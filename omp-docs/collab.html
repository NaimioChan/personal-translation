协作

邀请一位队友进入你正在进行的 omp 会话，安全地观看、输入提示词并协助引导工作。

协作针对的是在你已经打开的会话中共同工作。当队友应当看到完整上下文和实时进展，而不是收到截图或静态导出时，请使用它。主持端的 omp 始终是权威：模型和工具继续在主机上运行，而访客在自己的 omp 或浏览器中看到相同的对话记录和状态。

共享当前会话

在你想共享的交互式 omp 会话中运行：

/collab

omp 开始共享并显示：

  • 一条终端命令，例如 omp join "<room>.<secret>"，
  • 一个可点击的浏览器链接，
  • 该浏览器链接的二维码，以及
  • 一条提醒：这第一个链接允许访客向代理输入提示词。

把一个完整链接发给你的队友。终端形式和浏览器形式授予的权限相同。请让 omp 继续在主机上运行；那台机器会继续运行代理、模型请求和工具。

在主持期间再次运行 /collab 会重新打印完全控制链接和二维码。要查看谁已连接，请运行：

/collab status

参与者列表会标明主持端，并标出以只读方式加入的访客。

共享只读链接

在代码审查、演示，或任何应当只旁观而不引导工作的人面前，请使用只读链接：

/collab view

如有必要，这会开始共享；否则它会为已有的协作会话打印只读链接。旁观者可以看到此前的对话记录和实时更新，包括工具卡片和子代理对话记录，但无法输入提示词、中断、回应请求或控制子代理。

主持中的会话同时拥有完全控制链接和只读链接。你可以在不重启会话的情况下，给不同的人不同的访问权限：

/collab       # print the full-control link
/collab view  # print the view-only link

加入会话

任选以下方式。

从 omp 会话加入

把链接粘贴到交互式 TUI 中：

/join "<link>"

参与期间，你当前的本地会话会被搁置。当你离开时——或者主持端结束共享时——omp 会恢复你加入之前正在使用的会话。

你正在主持、或已经以访客身份连接时，无法加入其他会话。请先运行 /collab stop 或 /leave。

从新终端加入

直接在共享会话中启动 omp：

omp join "<link>"

omp join 需要交互式终端。请给链接加上引号，以免 shell 解释 # 之类的字符。

从浏览器加入

打开浏览器链接或扫描其二维码。无需安装 omp。页面会自动连接，并显示对话记录、流式输出、工具卡片、参与者和子代理。完全控制的浏览器链接还会启用输入框、中断按钮、子代理控制和主持端提问；只读链接会明确显示它是只读的。

加入后，omp 会先加载已有对话记录，再跟随实时活动。终端访客还会看到主持端的会话状态，包括工作目录、模型、上下文用量和成本，但不会切换到主持端的目录。

协同工作

访客的提示词在对话记录中会用其显示名标注。该名字只是对人的归属标识；它不是经过认证的身份，也不会作为指令传给模型。

当代理要求主持端选择一个选项或编辑文本时，每个已连接的完全控制访客都可能收到同样的请求。第一个回答或取消生效后，其余副本会被清除。

在终端里，完全控制访客可以按 Alt+A 打开 Agent Hub，检查主持端的子代理、读取它们的对话记录、给它们发消息、停止它们或恢复它们。这些操作会影响在主持端运行的工作。只读访客可以查看同样的子代理信息，但无法更改。

仅限主持端的命令始终留在主持端，包括 /model、/compact、/resume、/branch、! shell 命令、$ Python 和技能。终端访客仍可使用以下本地命令，而不会改变主持端会话：

访客本地命令用途
/dump, /export, /copy复制或导出访客可见的内容
/help, /hotkeys打开本地帮助
/theme, /settings更改访客机器上的设置；主持端不受影响
/collab显示访客的协作状态
/leave, /exit, /quit/leave 恢复之前的会话；/exit 和 /quit 关闭 omp

离开、停止与重新连接

访客用以下命令离开：

/leave

omp 关闭共享视图并恢复该访客之前的本地会话。离开不会停止主持端，也不会断开任何其他人。浏览器访客使用页面上的离开控件。

主持端用以下任一命令为所有人结束共享：

/collab stop

/leave

访客会看到会话已结束，终端访客会回到之前的本地会话。再次启动 /collab 会创建新链接；旧链接无法加入新房间。

短暂的网络或中继中断会自动重连。omp 会显示 reconnecting… 状态，并在连接恢复时重新同步共享会话。如果房间已消失、主持端已停止、密钥无效，或中继永久拒绝该连接，访客会话就会结束；如果主持端仍在共享，请向他们索取新链接。

权限与安全

协作链接是持有者密钥：任何拿到链接的人都获得该链接的权限。

  • 完全控制链接包含加密密钥和写入令牌。其持有者可以读取完整对话记录、提交会让主持端代理行动的提示词、中断工作、回应请求并控制子代理。
  • 只读链接包含加密密钥但不含写入令牌。其持有者可以读取同样可能敏感的会话历史，但无法引导它。
  • 有人使用有效链接时，没有基于账户的身份验证，也没有审批提示。参与者的显示名可以由参与者自己选择。

所有会话内容在到达中继之前就已用 AES-256-GCM 端到端加密。中继无法读取提示词、对话记录、工具细节或密钥。它可以观察到房间标识、连接数量、加密帧大小和有限的路由元数据。在浏览器链接中，房间链接位于 URL 片段里，而浏览器不会在 HTTP 请求中发送该片段。

中继本身并不会让完全控制访客变得安全。访客的提示词由主机上的代理在执行时按照主持端配置的工具与审批策略执行。共享之前，请检查对话记录中是否含有密钥，并确认主持端的权限是合适的。当某人只需要旁观时，默认发送只读链接；协作结束后，请停止共享。

中继配置

托管服务无需任何配置。默认情况下，/collab 使用 wss://my.omp.sh，推导出对应的浏览器界面，并把你的操作系统用户名用作参与者名称。

若只想临时改用其他中继，在开始共享时传入即可。不带协议的主机名会使用安全 WebSocket（wss://）：

/collab relay.example.com

要通过该中继以只读链接启动：

/collab view relay.example.com

若要持久设置，请使用 omp 中的 /settings，或运行：

omp config set collab.relayUrl wss://relay.example.com
omp config set collab.displayName "Ada"

用以下命令确认实际生效的值：

omp config get collab.relayUrl
omp config get collab.displayName

如果浏览器界面与中继分开托管，还要配置它的基地址：

omp config set collab.webUrl https://collab.example.com

collab.webUrl 必须是 http:// 或 https:// URL，且不带查询字符串或片段。非本地 URL 必须使用 HTTPS；纯 HTTP 仅在 localhost 下被接受。生成的浏览器链接仍指回所配置的中继。

设置默认值用途
collab.relayUrlwss://my.omp.sh当 /collab 没有中继参数时使用的中继
collab.webUrlempty浏览器界面基地址；为空时从 relay URL 推导
collab.displayNameempty参与者名称；为空时回退到操作系统用户名，再回退到 anonymous

中继 URL 可以使用 wss:// 或 https://；omp 会把两者都规范化为安全的中继连接。纯 ws:// 或 http:// 中继 URL 仅允许用于 localhost、127.0.0.1 或 ::1 开发端点。自定义端点必须实现 omp 协作中继服务；普通的 WebSocket 服务器并不够用。 omp 目前不发布可用于自建的生产级中继服务器或独立中继二进制文件。源码仓库中有一个仅支持 WebSocket 的本地开发替身，但它不提供浏览器客户端，也不能替代托管服务。

故障排查

你看到的现象该怎么做
No relay configured在 /settings 中设置 collab.relayUrl，运行 omp config set collab.relayUrl wss://…，或向 /collab 传入一个中继。
Stop hosting first运行 /collab stop，然后加入另一个会话。
Already in a collab session在加入另一个链接之前运行 /leave。
访客是只读的主持端共享的是 /collab view；只有当你应当引导会话时才索取完全控制链接。
浏览器链接能打开但连不上确认主持端仍在共享、使用当前完整链接，并检查自定义的 collab.webUrl 是否通过 HTTPS 提供 omp 浏览器客户端。
omp join requires an interactive terminal从 TTY 中运行它，或改为打开浏览器链接。
访客在某次响应期间加入，却漏掉了那次响应等待下一次更新。如果该响应在加入之后没有产生任何更新，那一次进行中的响应可能不会实时渲染；之后的对话记录和会话更新仍会同步。
