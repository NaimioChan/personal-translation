非茗的翻译文档库

记忆

把持久的偏好、决策与项目知识带入后续会话。记忆默认关闭；选择一个本地或远程后端，控制其作用域，并检查或清理它贡献的内容。

记忆让 omp 继续工作，而无需你重述持久事实，例如仓库约定、架构决策和审查偏好。它与上下文压缩不同：压缩缩短单个会话，而记忆可以影响未来的会话。

记忆默认关闭。如果你需要它，打开 /settings，选择 记忆 标签页，然后选择一个后端。可以先从 mnemopi 开始，它把可搜索的记忆存储在本机上；local 用于自动生成项目摘要；如果你已经运行 Hindsight 服务，则用 hindsight。

选择后端

后端适用场景存储与默认作用域重要取舍
off（默认）你不想要跨会话的知识。没有记忆存储。现有的会话对话记录不受影响；关闭记忆不会删除它们。
local你希望 omp 定期把过去已持久化的会话提炼为项目指引。本机上的生成文件，按工作目录隔离。它是一条批量摘要流水线，不是可搜索的存储。你无法审查或遗忘单条结构化事实。
mnemopi你想要由提示词驱动的记住、回忆与遗忘行为，且不需要记忆服务器。本地 SQLite 数据库；默认 per-project。数据库在本地，但默认的 smol LLM 模式可能把抽取工作发送给你配置的模型提供商。
hindsight你想要远程记忆库、共享基础设施，或 Hindsight 的合成与心智模型。你自己的 Hindsight 服务器；默认 per-project-tagged。自动留存默认开启，因此对话文本会离开本机。

从 shell 进行的最小持久化配置是：

# Pick exactly one
omp config set memory.backend local
omp config set memory.backend mnemopi
omp config set memory.backend hindsight

# Confirm the effective setting
omp config get memory.backend

/settings 会写入全局配置，并在保存时切换当前生效的后端。通过 shell 或 YAML 所做的更改对新的 omp 进程生效。若只想对一个仓库生效，把相同的键放进 <repo>/.omp/config.yml；项目设置会覆盖全局文件。路径与优先级见设置。

隐私、作用域与默认值

启用记忆会改变哪些内容得以持久化，并且取决于所选后端，还会决定哪些内容可能跨越网络边界。

  • 关闭意味着不做记忆处理。它不会禁用普通的会话持久化。记忆相关命令也不会擦除 ~/.omp/agent/sessions/ 下的文件；请通过会话单独管理这些文件。
  • Local 在本地存储生成的产物，默认位于 ~/.omp/agent/memories/<encoded-project>/ 下。它的抽取与合并流程使用你配置的模型角色，因此过去的会话文本仍可能被发送给该模型提供商。生成的输出会过滤常见的 token 与密钥模式，但不要有意让 omp 记住密钥。
  • Mnemopi 把它的 SQLite 记忆库存储在本地，默认位于 ~/.omp/agent/memories/mnemopi/ 下。本地嵌入可能会下载并运行一个嵌入模型。其默认的 llmMode: smol 使用你配置的在线 tiny/smol 模型进行 LLM 支持的抽取；如果你不希望有任何 LLM 参与的记忆处理，请使用 llmMode: none。
  • Hindsight 把持久记忆存储在配置的服务器上。在 autoRetain: true（默认值）下，omp 每三个用户轮次以及会话边界时发送用户与助手文本。它会省略工具调用、工具结果和思考块。回忆与合成查询也会发往该服务器。
  • 关闭某个后端不会删除它的存储。这使切换是可逆的，但当目标是彻底移除时，你必须单独清理或删除数据。

在积累敏感数据之前先选择作用域：

作用域MnemopiHindsight
global一个本地记忆库在所有项目中可见。一个远程记忆库在所有项目中可见。
per-project一个由绝对工作目录派生的隔离记忆库。这是默认值。每个仓库名（在 Git 之外则是 cwd 名）对应一个隔离记忆库。同一仓库的链接工作树共享主检出的名称。
per-project-tagged写入项目记忆库；回忆时会把它与共享的全局记忆库合并。把带项目标记的数据写入一个共享记忆库；回忆时把该项目的带标记记忆与未标记的全局记忆合并。这是默认值。

对于客户项目或其他严格边界，优先使用 per-project。per-project-tagged 很方便，但它会有意让未标记的全局知识与项目知识一起可见。

在对话中使用记忆

启用 Mnemopi 或 Hindsight 后，使用普通的提示词即可。你不需要了解 omp 是如何执行记忆操作的。

Remember that this repository uses pnpm and Node 22.

Before changing authentication, recall why we rejected session cookies.

What durable preferences have you learned about how I review pull requests?

Mnemopi 还可以编辑、遗忘或作废一条可编辑的记忆：

Forget the memory that says releases happen on Fridays; that policy was retired.

Update the stored release convention to say that releases happen after CI is green.

当描述可能匹配多条记录时，先让 omp 显示候选记忆再修改。Mnemopi 抽取出的事实表行是只读的；提示词应指明一条可编辑的记忆，或者在需要彻底移除时清空该作用域内的记忆库。Hindsight 不通过 omp 暴露单条记录的编辑能力；请使用 Hindsight 服务的 UI 做记录级审查或删除。

本地后端的工作方式不同。它会自动摘要符合条件的已持久化会话，并在启动时注入一个静态的记忆指引块。像“记住这个”这样的请求并不保证产生一次单独写入。它最好的用法是让反复出现的项目知识从已完成的工作中自然浮现。

回忆出或摘要出的记忆是背景上下文，不是指令。当它与你冲突时，当前提示词和当前仓库状态优先。

你可以检查和控制的内容

在会话中运行这些斜杠命令：

命令可见结果
/memory 或 /memory view打开当前注入的记忆载荷。出现空警告意味着后端已关闭、不可用，或尚未回忆/生成任何内容。
/memory stats在当前后端支持时显示后端统计信息。
/memory diagnose在支持时显示后端特有的诊断信息。
/memory enqueue请求当前后端执行更强的维护/留存动作；具体细节因后端而异，见下文。
/memory clear清理当前后端能够清理的内容。Hindsight 是一个重要的例外：远程记忆库不会被删除。

/memory reset 是 clear 的别名；/memory rebuild 是 enqueue 的别名。

enqueue 与 clear 的含义

后端/memory enqueue/memory clear
Local标记在下次启动时执行合并工作。它不会立刻重建指引面板。移除本项目生成的产物，并重置本地流水线共享的抽取/合并索引。它不会删除会话对话记录。
Mnemopi强制留存当前会话，清空待处理的抽取任务，并合并符合条件的工作记忆。新行要通过 Mnemopi 的年龄门槛后才会被提升（默认工作记忆生命周期为 24 小时，年龄门槛为 12 小时）。删除当前作用域的 SQLite 数据库以及 WAL/SHM 附属文件，然后重新启动一个空的后端。
Hindsight冲刷排队的写入，并强制留存当前会话。冲刷待处理的写入，然后只清空本会话的本地回忆状态。它不会删除服务器端的记忆或记忆库；请用 Hindsight UI 完成该操作。

检查本地生成的文件

本地后端把可读的生成产物保存在 ~/.omp/agent/memories/<encoded-project>/ 之下：

  • memory_summary.md — 由 /memory view 展示并在启动时注入的精简指引
  • MEMORY.md — 更长的合并后项目记忆
  • learned.md — 启用可选的自动学习后显式捕获的经验
  • skills/ — 生成的过程性操作手册

这些是生成的文件，而不是会话历史的来源。编辑它们不是一种持久的工作方式，因为后续的合并可能替换它们。请改为清理过期的输出，并排队一次重建。

管理 Hindsight 心智模型

Hindsight 心智模型是经过整理的摘要，例如用户偏好、项目约定和项目决策。它们默认启用并自动播种。在交互式 TUI 中，使用：

命令效果
/memory mm list列出当前记忆库中的模型。
/memory mm show <id>显示一个模型。
/memory mm refresh [id]刷新一个模型；未提供 id 时刷新所有自动刷新的模型。
/memory mm history <id>以 diff 形式显示该模型的修订历史。
/memory mm seed创建任何缺失的内置模型。
/memory mm delete <id>删除一个心智模型。这不会删除它的来源记忆。
/memory mm reload重新加载当前会话使用的心智模型块。

心智模型命令仅限 TUI，并且需要当前启用的后端是 Hindsight。它们不是 Mnemopi 的控制项。

配置 local 后端

~/.omp/agent/config.yml 中最小的全局 YAML：

memory:
  backend: local

该流水线在 omp 启动时于后台开始运行。它会跳过子代理以及未被持久化的会话。默认情况下，它忽略最近 12 小时内仍活跃的会话和早于 30 天的会话，因此刚启用的后端一开始可能显示空载荷。按会话的抽取使用 default 模型角色；合并使用 smol 及其回退。

设置默认值用途
memories.maxRolloutAgeDays30忽略早于该天数的会话。
memories.minRolloutIdleHours12忽略在此时长内仍有活动的会话。
memories.maxRolloutsPerStartup64一次启动最多处理的会话数。
memories.threadScanLimit300最多扫描的近期会话记录数。
memories.maxRawMemoriesForGlobal200传给合并步骤的已抽取会话记忆上限。
memories.stage1Concurrency8并发的按会话抽取任务数。
memories.stage1LeaseSeconds120抽取任务租约。
memories.stage1RetryDelaySeconds120抽取失败后重试前的延迟。
memories.phase2LeaseSeconds180合并任务租约。
memories.phase2RetryDelaySeconds180合并失败后重试前的延迟。
memories.phase2HeartbeatSeconds30合并租约的心跳间隔。
memories.rolloutPayloadPercent0.7会话载荷可用的模型上下文预算比例。
memories.phase1InputTokenLimit4000按会话抽取的输入上限。
memories.fallbackTokenLimit16000当模型没有声明有限的上下文窗口时使用的回退预算。
memories.summaryInjectionTokenLimit5000启动时注入的摘要与已捕获经验共用的大致上限。

可选的 autolearn.enabled: true 让 omp 把显式的经验捕获到 learned.md；它是实验性的，默认关闭。autolearn.autoContinue 默认也是 false，它控制 omp 在停止后是否运行一个私有的捕获轮次。

配置 Mnemopi

默认值已足以支撑一个项目隔离的本地记忆库：

memory:
  backend: mnemopi

一套偏向隐私、只用 FTS 并避免 LLM 抽取的配置是：

memory:
  backend: mnemopi
mnemopi:
  scoping: per-project
  noEmbeddings: true
  llmMode: none

配置 Hindsight

先运行一个可访问的 Hindsight 服务器。内置 URL 是 http://localhost:8888，因此本地无需认证的服务器只需要：

memory:
  backend: hindsight

对于 Hindsight Cloud 或需要认证的部署：

memory:
  backend: hindsight
hindsight:
  apiUrl: https://api.hindsight.vectorize.io
  scoping: per-project

尽可能把 token 放在文件之外：

export HINDSIGHT_API_TOKEN='replace-me'
omp

HINDSIGHT_* 环境变量会覆盖同名的 hindsight.* 设置。覆盖变量的名称与解析规则见环境变量。

故障排除

/memory view 在启用本地记忆后为空。本地记忆只处理已持久化的主会话，默认跳过最近 12 小时内仍活跃的会话，并且只在启动时执行维护。在存在符合条件的会话之后，运行 /memory enqueue，正常退出，然后再次启动 omp。同时确认 default 与 smol 模型角色拥有可用的凭据。

Mnemopi 已启用，但既不记住也不回忆。运行 /memory diagnose 和 /memory stats。启动是尽力而为的：数据库、嵌入模型或 LLM 初始化失败时，编码会话仍然可用，但记忆功能处于失效状态。可以尝试 mnemopi.noEmbeddings: true 来隔离嵌入问题，用 mnemopi.llmMode: none 来隔离 LLM 配置。

Hindsight 已启用，但什么都没出现。确认实际生效的后端与端点：

omp config get memory.backend
omp config get hindsight.apiUrl

然后运行 /memory diagnose。检查服务器是否可访问，以及 HINDSIGHT_API_TOKEN 或 hindsight.apiToken 是否有效。请求失败不会中止编码会话；需要后端日志时启用 hindsight.debug。

一个项目看到了另一个项目的知识。检查 mnemopi.scoping 或 hindsight.scoping。要隔离就切换到 per-project，然后单独清理旧的本地记忆库，或单独移除旧的 Hindsight 记忆库/数据；更改作用域不会抹去先前存储的知识。

记忆已经过时。让 omp 对照当前仓库核实它。对于 Mnemopi 的某条事实，要求更新或遗忘它。对于本地摘要，使用 /memory clear，随后运行 /memory enqueue 并在之后重启。对于 Hindsight，在 Hindsight 中移除或更正远程记录；/memory clear 只清空当前会话的本地回忆状态。

会话内的上下文管理见上下文压缩，配置位置、项目覆盖与优先级见设置。
