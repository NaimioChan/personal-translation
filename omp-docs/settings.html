设置

查看、修改、限定作用域并排查 omp 配置，无需猜测哪个值最终生效。

没有配置文件 omp 也能工作：已知设置会回退到内置默认值（部分可选值默认为未设置）。启动一个会话并运行 /settings，就能看到当前目录下的生效值、按名称搜索，并修改那些带交互控件的设置。面板会标记出与内置默认值不同的值。

面板会把改动保存到你当前活动的全局配置或命名配置档，并立即应用大部分 UI 与会话行为。用 Enter 或 Space 修改值，直接输入可在各标签页间搜索，按 Esc 关闭。如果需要精确重置、只改项目级设置，或某个设置未在面板中显示，请使用 omp config 或下文所述的 YAML。

全新安装时有几个有用的默认值：

  • 深色主题 titanium，浅色主题 light
  • 思考强度 high
  • 引导和后续消息按 one-at-a-time 送达
  • 对正在运行的轮次进行引导时立即打断
  • 压缩和自动图片缩放已启用
  • 命名模型角色的改动保存到全局（modelRoleStorage: global）
  • 工具审批模式为 yolo，除非启动模式或运行时标志覆盖它；修改策略前请先阅读工具审批

默认值会演进。omp config list 是你所运行版本中键与生效值的权威视图。

从 shell 查看、修改与重置

在你希望包含其项目设置的目录中运行这些命令：

omp config list                              # every effective setting, type, and allowed enum values
omp config list --json                       # machine-readable inventory
omp config get theme.dark                    # one effective value
omp config set theme.dark catppuccin-macchiato
omp config set compaction.enabled false
omp config reset theme.dark                  # write the built-in default to global config
omp config path                              # print the active agent directory

set 和 reset 写入的是当前配置档的全局配置，而不是项目文件。reset 写入的是 schema 默认值；它不会删除该键。如果你希望该键从其他层继承，请改为从 YAML 文件中移除它。

值按设置类型解析：

类型Shell 输入
布尔true / false、yes / no、on / off，或 1 / 0
数字一个有限数值
枚举omp config list 列出的某个确切值
数组JSON，例如 omp config set disabledProviders '["ollama"]'
记录JSON，例如 omp config set providers.maxInFlightRequests '{"anthropic":2}'
字符串剩余的参数文本，去除首尾空白

键必须是完整的点分路径：用 theme.dark，而不是 theme。未知的键和无效的 CLI 值会失败且不会被保存。人类可读的 config list 输出会遮蔽已配置的凭据；--json 会省略它们的值并标记为已遮蔽。config get 是对某个值的显式请求，因此不会遮蔽凭据。

文件与作用域

作用域位置用于如何写入
全局~/.omp/agent/config.yml你跨项目的常规默认值/settings、omp config set、omp config reset，或用编辑器
命名配置档~/.omp/profiles/<name>/agent/config.yml为工作/人格配置档隔离的设置、认证、会话与缓存在 omp --profile <name> 下运行或设置 OMP_PROFILE，然后使用同样的命令
项目<cwd>/.omp/config.yml可与项目共享的仓库专属覆盖编辑 YAML 文件；设置发现只检查当前目录，不检查祖先目录
配置覆盖层任何通过 --config 传入或在 PI_CONFIG_FILES 中列出的 YAML 文件临时、CI、密钥或实验专属的覆盖该进程的只读层；绝不复制进持久配置
运行时CLI 标志与特定功能的环境覆盖仅一次启动从不持久化

omp config path 打印的是当前活动的代理目录，因此打开文件时要自己追加 config.yml。已存在的 config.yaml 也会被接受并就地更新。PI_CODING_AGENT_DIR 会迁移默认配置档的代理目录；PI_CONFIG_DIR 改变常规的 .omp 根目录名。

命名配置档会取代普通的全局作用域，而不是继承其设置。若要在不进入会话的情况下查看某个配置档，请把配置档标志放在子命令之前：

omp --profile work config path
omp --profile work config list
omp --profile work config set theme.dark titanium

OMP_PROFILE 是持久化的环境变量等价物；PI_PROFILE 仍是旧版回退。快捷键单独存储，有自己的配置档继承规则；参见快捷键。

项目设置

在你启动 omp 的确切目录中创建 .omp/config.yml：

启用的兼容性提供商也可以从它们自己的格式贡献项目级设置。它们共享项目层；用 omp config get <key> 查看合并后的结果，用上下文文件控制发现来源。

# <repo>/.omp/config.yml
modelRoles:
  default: anthropic/claude-sonnet-4-5

disabledProviders:
  - ollama

compaction:
  enabled: true
  thresholdPercent: 80

omp config set 不会写入任意的项目设置。请直接编辑这个文件。唯一的交互式项目写入是在 modelRoleStorage 为 project 时进行的模型选择器角色分配；那里只会更新 modelRoles，缺失的项目角色仍会回退到全局配置档。

不要把凭据放进会提交的项目 YAML。优先使用已存储的登录凭据、环境变量、密钥与认证中所述的密钥引用，或未被跟踪的覆盖层。

一次性覆盖层

omp --config ./local/ci.yml "diagnose this failure"
omp --config ./base.yml --config ./experiment.yml "try this configuration"

覆盖层路径从工作目录解析，并会展开 ~。允许重复使用 --config；靠后的文件胜出。PI_CONFIG_FILES 接受平台路径列表（Unix 上为 :，Windows 上为 ;），并先加载这些文件，早于显式的 --config 文件。

覆盖层是严格的：文件缺失、YAML 格式错误，或文档顶层不是映射，都会中止启动。它们不会被隔离，也不会被静默忽略。

优先级与合并

从最低到最高优先级：

built-in defaults
  < active global/profile config
  < project config
  < PI_CONFIG_FILES overlays, in listed order
  < --config overlays, in command-line order
  < runtime flags and feature-specific environment overrides

运行时覆盖的例子包括模型角色标志，如 --model、--smol、--slow 和 --plan，审批标志，--hide-thinking、--advisor、--no-pty 以及 --api-key。环境变量并不是一个统一的设置层：每个负责的功能自行决定其变量是覆盖还是回退。参见环境变量。

映射会深度合并；标量和数组则替换：

# global
statusLine:
  preset: default
  transparent: false
disabledProviders: [anthropic, openai]

# project
statusLine:
  transparent: true
disabledProviders: [groq]

在项目内部，statusLine.preset 仍为 default，transparent 变为 true，而 disabledProviders 恰好是 [groq]。更高层的数组绝不会追加到更低层的数组。这条替换规则同样适用于 enabledModels、cycleOrder、extensions 以及所有其他数组设置。

校验、保存与重载

  • /settings 会把可选项限制在当前构建所支持的控件与取值范围内。它的改动会更新正在运行的会话，并在后台保存。
  • omp config set 会检查键是否存在，并在原子写入前解析布尔、数字、枚举、数组和记录。
  • 手工编辑的 YAML 文件根部必须是映射。YAML 解析并不保证能发现每个语义上错误的值，所以尽可能使用 /settings 或 omp config set，并用 omp config get <key> 检查结果。
  • 在可写的启动过程中，无效的持久全局或原生项目 YAML 会被移到原文件旁边，命名为 *.broken-<timestamp>-<pid>-<id>，随后启动失败并报告两个路径。修复或还原被移动的文件；omp 不会丢弃它。
  • 运行中的会话通常不会监视配置文件。/settings 的改动是实时的，但由另一个 omp config 进程或文本编辑器所做的改动，可靠生效的时机是下次启动。把会话移到另一个工作目录会重新加载该目录的项目层；如果模型/提供商发现已经初始化过，请重启。
  • 并发保存会在锁下重新读取文件，并保留无关的外部编辑。

没有通用的 /reload-settings 命令。/reload-plugins 刷新的是扩展与发现状态，而不是任意设置。

常用配方

设置模型角色

用 /settings 或模型选择器进行引导式选择，角色行为参见模型角色。当多个角色一起变动时，YAML 很有用：

modelRoles:
  default: anthropic/claude-sonnet-4-5
  smol: anthropic/claude-haiku-4-5
  slow: anthropic/claude-opus-4-6:high
  plan: openai/gpt-5.3-codex:high
  commit: anthropic/claude-haiku-4-5

运行 omp --list-models 可查看当前提供商和凭据下可用的模型。

修改队列行为

steeringMode: one-at-a-time  # or all
followUpMode: one-at-a-time  # or all
interruptMode: immediate     # or wait

关于引导与后续提示词的区别，参见使用 omp。

设置主题与终端行为

theme:
  dark: catppuccin-macchiato
  light: light
terminal:
  showImages: true
tui:
  hyperlinks: auto

内置与自定义配色参见主题。

限制某个仓库的提供商

# <repo>/.omp/config.yml
disabledProviders:
  - ollama
  - openrouter

这个项目数组会替换全局数组。提供商 id 与认证参见模型提供商。

配置安全敏感的功能

先从交互控件开始，然后遵循专门的指南，而不是盲目照抄一份宽泛的策略：

  • 工具权限策略：工具审批
  • 顾问审查：顾问模型
  • 桌面自动化：电脑控制
  • 安全审查：安全扫描
  • 提示词触发的模式：魔法关键词
  • 执行前的仓库遍历：Prewalk

配置压缩与记忆

compaction:
  enabled: true
  thresholdPercent: 80
memory:
  backend: off

压缩有多种策略、阈值和后台模式；参见上下文压缩。记忆后端与保留策略参见记忆。

排查问题

项目中的值没有生效

  1. 在包含 .omp/config.yml 的目录中运行 omp config get <key>。
  2. 确认项目文件位于进程的确切工作目录；omp 不会为原生项目设置搜索父目录。
  3. 检查是否有一个靠后的 --config 覆盖层、PI_CONFIG_FILES、CLI 标志或功能环境变量胜出。
  4. 记住项目中的数组会替换整个全局数组。
  5. 如果提供商/模型/工具发现已经初始化过，请重启。

omp config set 改错了文件

它始终写入当前活动的全局/配置档配置。运行 omp config path 找出那个代理目录。要做项目覆盖，请直接编辑 <repo>/.omp/config.yml。

omp config reset 似乎什么都没做

reset 会把内置默认值写入全局文件。项目、覆盖层或运行时的值仍可能胜出。用 omp config get <key> 查看，然后移除或修改更高层。若想继承而不是钉住全局默认值，请手动删除全局 YAML 中的该键。

启动时报告 YAML 损坏

阅读所报告的错误与备份路径。持久化的格式错误 YAML 会在启动停止前被移到唯一命名的 .broken-* 兄弟文件，保留原始内容。把该备份修复成映射，并还原为 config.yml。覆盖层的错误不会被移动；请就地修复该覆盖层。

键未知或值被拒绝

运行 omp config list，复制确切的点分键，并使用显示的某个枚举值。传给 set 的数组和记录必须是有效 JSON，尽管持久文件使用 YAML。

编辑在已有会话中不可见

单独的 shell 命令或编辑器不会把设置推送到已经运行的会话中。请启动一个新会话。如果你用的是 /settings，检查是否有项目、覆盖层或运行时覆盖的优先级高于你所修改的全局值。
