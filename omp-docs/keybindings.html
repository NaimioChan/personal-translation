快捷键

控制 omp 会话的快捷键、它们各自的作用范围，以及如何重新映射它们。

快捷键让你无需离开键盘就能发送或排队提示词、中断工作、在编辑器中移动，并打开常用的会话控件。先从下面这小组快捷键开始；忘记某个组合键时，用 /hotkeys 查询。

首次会话快捷键

按键作用
Enter发送提示词。omp 正在工作时，这会向当前轮次发送一条引导消息。
Shift+Enter、Ctrl+J 或 Alt+Enter插入换行而不发送。
Ctrl+Q 或 Ctrl+Enter将一条后续消息排队，等当前轮次结束后发送。
Escape关闭自动补全，或中断当前操作。
Ctrl+O展开或折叠工具输出。
Ctrl+R搜索提示词历史。
Ctrl+C清空输入框。在半秒内再按一次则退出。
Ctrl+D立即退出；非空的提示词会保存为可恢复的草稿。
Alt+A打开 Agent Hub。

查看当前生效的快捷键

在任意交互式会话中输入：

/hotkeys

生成的表格使用你所在平台的按键名称，并从当前生效的 keybindings.yml 解析应用层重新映射。例如，配置语法里写 alt 和 super 的地方，macOS 会显示为 Option 和 Cmd。

/hotkeys 是日常速查清单，不是完整的配置注册表。其中编辑器导航相关的行描述的是标准默认值，扩展添加的快捷键也不会追加到里面。重新映射编辑器或选择控件时，请使用下面的动作表。

快捷键在何处生效

当前获得焦点的界面决定一个按键的含义。在不同上下文中复用同一个按键是正常的：例如 Ctrl+O 在对话记录中展开工具输出，而在 /tree 中循环切换过滤器。

上下文控件
主提示词输入框应用动作（app.*）加上编辑器动作（tui.editor.* 和 tui.input.*）。
自动补全、历史与大多数选择器选择动作（tui.select.*）：方向键移动，PageUp/PageDown 翻页，Enter 确认，Escape 取消。
@ 文件选择器输入内容以模糊过滤项目文件，用 Up/Down 选择，用 Tab 接受，用 Escape 关闭。
计划审批Escape 取消审批并返回计划模式迭代。

全屏界面

这些页面会添加该界面特有的控件。它们的固定控件在 keybindings.yml 中不是独立的动作 ID；在标注的地方，可重新映射的选择与中断动作仍然生效。

界面控件
/treeUp/Down 移动；Alt+Up/Down 在用户轮次或助手轮次之间跳转；Left/Right 或 PageUp/PageDown 翻页；Home/End 跳到第一个/最后一个可见条目；Enter 选中；Shift+Enter 生成摘要并直接切换；Ctrl+O/Shift+Ctrl+O 循环切换过滤器；Escape 先清空搜索，然后关闭。
/extensionsTab/Shift+Tab 或 Left/Right 切换提供商标签页；方向键或 j/k 移动；Space 或 Enter 切换所选行；输入即过滤；Escape 先清空过滤，然后关闭；Ctrl+C 立即关闭。
/agentsTab/Shift+Tab 或 Left/Right 在作用域与列表之间切换；方向键移动；Enter 打开或激活；搜索为空时 Space 切换所选代理；输入即过滤；Ctrl+R 重新加载；Escape 先清空过滤，然后关闭。
Agent Hub方向键或 j/k 选择；Enter 打开一个代理；t 切换平铺/树形视图；在窄终端中 Tab 显示检查器；r 唤醒已停驻的代理；x 终止并释放代理；Escape 先关闭检查器，再关闭 Agent Hub。

重新映射快捷键

快捷键与主设置文件是分开的：

  • 默认配置文件：~/.omp/agent/keybindings.yml
  • 具名配置文件：~/.omp/profiles/<name>/agent/keybindings.yml
  • 自定义默认配置的代理目录：$PI_CODING_AGENT_DIR/keybindings.yml

具名配置会继承默认配置的绑定，然后逐个动作覆盖它们。配置文件和目录的配置方式见设置。

文件不存在就创建它。它是一个 YAML 映射，把精确的动作 ID 映射到单个组合键、组合键数组或空数组：

# ~/.omp/agent/keybindings.yml
app.model.cycleForward: f6
app.plan.toggle: f7
tui.editor.undo: [ctrl+-, ctrl+_]
app.history.search: []

重新映射会替换该动作的完整默认列表，而不是在默认列表上追加。想保留哪些默认值就重复写一遍。空数组会禁用该动作。

保存文件后重启 omp。运行 /hotkeys 可验证 app.model.cycleForward 这类应用动作；编辑器与选择器动作请直接按键验证，它们在 /hotkeys 中对应的行只是一份简明的默认值指南。

组合键语法

  • 组合键是用 + 连接的多个同时按下的键，例如 ctrl+p、alt+shift+p 或 ctrl+backspace。不支持多步按键序列。
  • 名称不区分大小写。在手写的配置文件中建议使用小写。
  • 修饰键是 ctrl、shift、alt 和 super。在 macOS 上，alt 表示 Option，super 表示 Command。
  • 基础键包括字母、数字、标点、方向键、home、end、pageUp、pageDown、backspace、delete、insert、enter、escape、tab、space，以及 f1 到 f12。
  • esc 可作为 escape 的别名接受；return 可作为 enter 的别名接受。
  • 避免在同一上下文中把同一个组合键分配给多个动作。哪个生效可能取决于当前获得焦点的界面。

加载时，旧版未限定命名空间的动作名会被迁移。旧版 keybindings.json 会被迁移为 keybindings.yml；keybindings.yaml 也可接受。新配置应使用 keybindings.yml 和本页中带命名空间的 ID。

平台与终端注意事项

  • macOS：即使 omp 显示 Option 和 Cmd，在 YAML 中也要写 alt 和 super。某些终端配置把 Option 用于字符组合，不会传递 Option+Up；此时使用 Shift+Up 这个出队回退方式。
  • Windows：Ctrl+Z 无法挂起 omp。Windows Terminal 不会传递独立的 Ctrl+Enter，所以请用 Ctrl+Q 发送后续消息。如果它捕获了 Ctrl+V，请用 Alt+V 粘贴剪贴板图片。
  • 换行：如果终端无法区分 Shift+Enter 和 Enter，请使用 Ctrl+J 或 Alt+Enter。
  • 终端自有的按键：你的终端、复用器、桌面环境或 shell 可能在 omp 收到之前就拦截某个组合键。请修改该终端绑定，或另选一个 omp 组合键。

故障排查

重新映射没有生效

  1. 确认你编辑的是当前配置的代理目录中的 keybindings.yml，而不是 config.yml。
  2. 确认动作 ID 与表格条目完全一致；动作 ID 区分大小写。
  3. 重启 omp。快捷键在交互式会话启动时加载。
  4. 检查 YAML 值是字符串、字符串数组或 []。
  5. 对应用动作运行 /hotkeys，或直接按键测试编辑器/选择器动作。

组合键仍然毫无反应

试试文档中给出的回退组合键。如果回退键有效，说明终端很可能吞掉了或规范化了原来的组合键。这种情况在 Ctrl+Enter、Shift+Enter、Option 组合键和剪贴板按键上很常见。

同时检查 keybindings.yml 其余部分是否也用了同一个组合键。在同一上下文中把它分配给两个动作会产生有歧义的重新映射。

按键执行了别的操作

检查当前获得焦点的界面。编辑器、选择器、/tree、/extensions、/agents 和 Agent Hub 的控件都是上下文相关的。按 Escape 关闭当前浮层，然后在主提示词输入框中重试该快捷键。常见快捷键的命令替代方案见斜杠命令。
