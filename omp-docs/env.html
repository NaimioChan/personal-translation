环境变量

环境变量适用于凭据、CI、单次 shell 覆盖，以及标准的云端或代理配置。本页列出 omp 支持的公开变量，并说明它们与 YAML 设置、CLI 标志的区别。

选择正确的配置方式

当某个值属于机器或进程、而不属于项目时，请使用环境变量：密钥、云凭据、代理、仅用于 CI 的值，或临时覆盖。例如：

export ANTHROPIC_API_KEY="sk-ant-..."
omp

如果只用于一次调用，请把赋值写在命令前面，而不是导出它：

PI_SLOW_MODEL="openai/gpt-5.5:high" omp

环境变量不是 YAML 设置，也不是 CLI 标志：

  • 需要持久、并应随其余配置一起审阅的 omp 行为，请使用 ~/.omp/agent/config.yml 或项目设置。
  • 需要为一次运行做明确选择时，请使用 omp 标志。当标志和环境变量控制同一个值时，标志优先；例如 --slow 优先于 PI_SLOW_MODEL。
  • 在 shell 或 .env 文件中使用本页的变量。不要把 export PI_FOO=... 写进 config.yml，也不要指望名为 PI_FOO 的 YAML 键能生效。

并不存在“环境变量永远压过 YAML”的通用规则。有些变量是回退值，另一些则明确覆盖对应的设置。下面每张表都会说明属于哪种行为。

当某一行写着 truthy 时，omp 共享的标志解析器接受 1、y、true、yes 或 on，包括按列出的大小写形式。部分子系统会归一化大小写，或要求某个确切值；那些行会明确写出。

对于支持交互式登录的提供商，/login 通常比把 OAuth token 放在 shell 启动文件里更安全。请把每个 API 密钥、token、cookie、客户端密钥和凭据文件都当作密钥处理。

omp 从哪里获取环境变量的值

启动时，omp 按以下顺序保留它找到的第一个非空值：

  1. 从启动 omp 的那个 shell 继承的环境。
  2. 启动目录下的 $PWD/.env。
  3. 当前代理的 .env：通常是 ~/.omp/agent/.env，命名 profile 则为 ~/.omp/profiles/<name>/agent/.env。
  4. 当前配置根目录的 .env：通常是 ~/.omp/.env，命名 profile 则为 ~/.omp/profiles/<name>/.env。
  5. ~/.env。

Bun 可能在 omp 运行前预加载它支持的启动目录文件——例如 .env.local、.env.<NODE_ENV> 和 .env.<NODE_ENV>.local。这样加载的值已经出现在继承的进程环境中，因此拥有第一个来源的优先级。

PI_CONFIG_DIR 改变 .omp 根目录的名称。PI_CODING_AGENT_DIR 改变默认 profile 的代理目录；命名 profile 会忽略它。

在解析后的 .env 文件内，OMP_FOO 键也会被复制到 PI_FOO，且复制出的值优先于同一文件中的 PI_FOO。这条兼容规则只适用于 .env 文件，不适用于从父 shell 继承的变量。

更改 .env 文件后请重启 omp。环境变量变更不会热重载。

.env 语法

名称必须匹配 [A-Za-z_][A-Za-z0-9_]*。允许空行和 # 注释；export 是可选的。接受单引号、双引号和反引号。

# ~/.omp/.env
export ANTHROPIC_API_KEY="sk-ant-..."
PI_SLOW_MODEL='anthropic/claude-opus-4-8:high'
PI_NOTIFICATIONS=off

OMP 自己的解析器会原样保留值。启动目录的 .env 可能在 omp 启动前由 Bun 加载，因此那里可能已经做过 Bun 支持的展开；不要指望其他 .env 文件里也会展开。

远程认证代理

这些变量选择远程凭据保险库，而不是本地凭据数据库。

变量可接受的值与默认含义
OMP_AUTH_BROKER_URL代理基地址。设置后即选中代理模式，且该值优先于 auth.broker.url。如果无法解析出任何 token，启动会失败，而不会回退到本地凭据。
OMP_AUTH_BROKER_TOKENBearer token。解析顺序为环境变量 → auth.broker.token → <config-root>/auth-broker.token。
OMP_AUTH_BROKER_SNAPSHOT_TTL_MS非负毫秒数；默认 3600000（1 小时）。0 禁用加密快照缓存的读取和写入。
OMP_AUTH_BROKER_SNAPSHOT_CACHE快照缓存路径；默认 ~/.omp/cache/auth-broker-snapshot.enc 或其 XDG 等价路径。
OMP_AUTH_BROKER_ACCOUNT_POOL_FILE把提供商 ID 映射到允许的代理 identityKey 数组的 JSON 文件。无效输入按失败关闭处理。缺失的提供商不受限制；[] 会隐藏该提供商的 OAuth 账户。
export OMP_AUTH_BROKER_URL="https://broker.example.net:8765"
export OMP_AUTH_BROKER_TOKEN="..."
omp

网络、代理与端点配置

出站代理

对于提供商请求，omp 先检查 NO_PROXY，然后按以下顺序解析代理：

  1. PI_PROXY_<PROVIDER>，其中提供商 ID 大写、标点变为 _，例如 PI_PROXY_GITHUB_COPILOT。
  2. PI_PROXY。
  3. HTTPS 和 WebSocket 使用 HTTPS_PROXY / https_proxy，HTTP 使用 HTTP_PROXY / http_proxy。
  4. ALL_PROXY / all_proxy。

NO_PROXY 和 no_proxy 包含常见的逗号分隔排除项。回环地址、链路本地地址和 RFC 1918 私有地址会绕过提供商代理。PI_PROXY 作用于整个进程，也覆盖登录、刷新、用量和发现调用；提供商专属变量只覆盖该提供商。

export PI_PROXY="http://127.0.0.1:7890"
export NO_PROXY="localhost,127.0.0.1,.internal.example"

故障排查

.env 中的值似乎被忽略了

  • 先检查启动时的 shell：已存在的非空值优先于任何 .env 文件。
  • 确认文件位于启动目录、当前 profile 目录、配置根目录或上面列出的主目录位置。
  • 重启 omp。这些值只在启动时加载一次。
  • 记住命名 profile 使用 ~/.omp/profiles/<name>/...，并忽略 PI_CODING_AGENT_DIR。

YAML 设置与环境变量不一致

阅读该变量对应的那一行。有些环境变量的值是明确的覆盖（PI_TINY_DEVICE、Hindsight 变量），有些是回退（LITELLM_BASE_URL），还有一些会被 CLI 标志取代（PI_SLOW_MODEL）。用 omp config get <setting> 查看 YAML；在 shell 中用 env | sort 查看继承的环境变量值。

认证仍然失败

对支持的 OAuth 提供商，优先使用 /login。否则请核对上面确切的提供商专属名称、去掉空白，并确认在需要提供商专属 token（如 COPILOT_GITHUB_TOKEN）的地方没有使用 GITHUB_TOKEN 这类通用密钥。

密钥被提交或打印出来了

立即吊销并轮换它。仅从最新文件中删除是不够的，因为它仍留在历史和日志里。不要让含凭据的 .env 文件进入版本控制，并限制其权限，例如 chmod 600 ~/.omp/.env。
