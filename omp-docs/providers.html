模型提供商

选择账户、API key、本地或自定义的模型路径；完成认证；然后选一个 omp 真正可用的模型。

选择适合的路径

提供商是账户或后端，例如 anthropic、openai-codex 或 ollama。模型以 provider/model-id 的形式选择。

对大多数人来说，最短的路径是：

  1. 启动 omp。
  2. 运行 /model。
  3. 选择一个提供商。没有凭据的提供商会显示为未配置；选中一个并按 Enter，若可用就会启动其登录流程。
  4. 登录完成后选择一个模型。

如果你已经清楚想怎样认证，就用这张表：

路径最适合第一步
OAuth 或账户登录浏览器、设备码和托管账户流程在 omp 中运行 /login，或用 /login openai-codex 直接跳到某个提供商
编程订阅ChatGPT Plus/Pro、Claude Pro/Max、Copilot 以及其他受支持的套餐使用套餐的提供商 ID，而不是厂商的 API 提供商 ID
API key按用量计费的 API、CI 和非交互式 shell导出该提供商的环境变量，然后启动 omp
本地引擎用 Ollama、llama.cpp 或 LM Studio 进行私有或可离线的推理启动引擎；omp 无需登录即可发现它
自定义端点团队网关、自托管 API 以及未内置的提供商把端点加到 ~/.omp/agent/models.yml

账户订阅与开发者 API 往往是不同的产品。例如 ChatGPT 凭据使用 openai-codex；openai 期望 OPENAI_API_KEY。Google 和 xAI 也有类似的区分。猜 ID 之前请先看提供商特定注意事项。

先把一条路径跑通

用 OAuth 或订阅登录

在交互式会话中：

/login openai-codex

按照 omp 显示的浏览器、设备码或粘贴码指示操作。在远程终端中，流程可能会要求你把最终的跳转 URL 或代码以 /login <value> 的形式粘贴回来。当某个提供商支持多个账户或工作区时，再次运行 /login <provider> 可以再添加一个；omp 可以在受管账户之间轮换。

然后验证并选择一个具体模型：

omp models openai-codex
omp --model openai-codex/gpt-5.5

omp models <provider> 只打印当前安装下可用的模型。如果示例中的模型已经变化，就从该输出里复制一个选择器。在已有会话中，改为运行 /model 或 /model provider/model-id。

用 /logout 选择要移除的凭据，或用 /logout <provider> 直接打开该提供商。

使用 API key

对于一次性启动或 CI 任务，把 key 放进进程环境：

OPENAI_API_KEY=sk-... omp --model openai/gpt-5.5

对于交互式配置，许多基于 key 的提供商也会出现在 /login 中；omp 会打开该提供商的 key 页面，询问 key，进行校验，并保存凭据。没有登录入口的提供商则使用其环境变量。

若想持久化一个环境变量而不写进 shell 启动文件，omp 会加载 .env 文件。已导出的进程值优先，其次是：

  1. <current-directory>/.env
  2. ~/.omp/agent/.env
  3. ~/.omp/.env
  4. ~/.env

不要提交包含密钥的项目 .env。参见环境变量了解每个提供商 key 的名称和完整的 .env 规则。

在开始长任务之前先验证这条路径：

omp models openai
omp --model openai/gpt-5.5 "Reply with the model provider and model ID you are using."

使用本地引擎

omp 会自动探测这些本地提供商：

提供商 ID默认端点覆盖方式
ollamahttp://127.0.0.1:11434OLLAMA_BASE_URL，其次是 OLLAMA_HOST
llama.cpphttp://127.0.0.1:8080LLAMA_CPP_BASE_URL
lm-studiohttp://127.0.0.1:1234/v1LM_STUDIO_BASE_URL

先启动引擎并在其中加载一个模型。默认的无密钥端点不需要登录或配置文件。然后问 omp 发现了什么：

omp models ollama

从输出中复制一个选择器：

omp --model ollama/model-id

如果引擎在另一台机器上，就设置它的 base-URL 环境变量。models.yml 中具有相同 ID 的显式提供商会取代自动发现。vllm 也是内置的提供商路径，但当它没有作为未认证的本地端点暴露时，需要自行配置或认证。

添加自定义提供商

对于兼容 OpenAI、兼容 Anthropic 或其他受支持的公共端点，使用 ~/.omp/agent/models.yml。这个最小示例从 MY_GATEWAY_API_KEY 读取 key：

providers:
  my-gateway:
    baseUrl: https://gateway.example.com/v1
    api: openai-completions
    apiKey: MY_GATEWAY_API_KEY
    models:
      - id: fast-chat
        name: Fast Chat
        contextWindow: 128000
        maxTokens: 8192

设置 key 并验证已加载的条目：

export MY_GATEWAY_API_KEY=...
omp models my-gateway
omp --model my-gateway/fast-chat

apiKey 会先按环境变量名解析，否则按字面文本处理。优先使用环境变量名，这样密钥就不会留在文件里。对于真正无密钥的端点，用 auth: none 代替 apiKey。

其他 wire API、模型发现、请求头、密钥命令、兼容性选项和模型覆盖，参见自定义模型与提供商。

模型如何变得可用

启动时，omp 按以下顺序组装模型注册表：

  1. 内置的提供商与已知模型；
  2. 来自 ~/.omp/agent/models.yml 或 models.yaml 的提供商覆盖与自定义模型；
  3. 受支持提供商和本地引擎的缓存或实时发现；
  4. 由已加载扩展注册的提供商与模型。

provider 和 id 都相同的自定义模型会取代内置条目。运行时发现可以更新某个提供商暴露的模型；模型覆盖会在此之后重新应用。

只有在以下条件下模型才可选择：

  • 其提供商不在生效的 disabledProviders 列表中；并且
  • 该提供商无密钥，或具有 omp 能解析的凭据。

有用的检查：

omp models                    # all currently available models
omp models find sonnet        # search provider, ID, selector, or display name
omp models refresh            # force fresh online discovery, then list

在 TUI 内，/model 会包含可用模型，并把目录中没有凭据的提供商显示为锁定状态。选中一个支持登录的锁定提供商会启动其设置。被禁用的提供商会省略。

对于初始选择，显式的 --model 优先。没有它时，omp 会依次考虑当前模型作用域、已保存的默认值、已知的提供商默认值，最后是第一个可用模型。当同一个模型 ID 存在于多条路径时，优先使用确切的 provider/model-id；裸 ID 和模糊的 --model 模式取决于可用目录与已配置的提供商顺序。持久默认值和任务专属的模型选择参见模型角色。

凭据优先级

当同一个提供商存在多份凭据时，omp 使用第一个适用的来源：

  1. 本进程的运行时 --api-key；
  2. models.yml 中的 providers.<id>.apiKey；
  3. 已存储的 OAuth 凭据，需要时刷新；
  4. 由 /login 存储的 API key；
  5. 提供商环境变量，包括从 .env 加载的值；
  6. 另一份已存储的 API key，例如由认证代理迁移的 key；
  7. 自定义提供商的回退解析器。

这意味着已存储的 OAuth 登录通常胜过环境中的 ANTHROPIC_API_KEY，而在 models.yml 中显式钉住的 key 又胜过 OAuth。若想同时保留账户访问和 API 访问，请让提供商 ID 彼此分开。

本地凭据通常位于 ~/.omp/agent/agent.db。配置了认证代理后，登录、登出、刷新和凭据读取都改用远程存储。存储、多账户、认证代理以及兼容提供商的认证网关参见密钥与认证。

排查问题

该提供商被锁定，或不在 omp models 中。检查其凭据，然后检查它是否被禁用：

omp config get disabledProviders

被禁用的提供商即使凭据有效也不可用。项目设置可以替换全局的 disabledProviders 数组；参见设置。

登录成功但模型列表是旧的。运行 omp models refresh，然后再次列出该提供商。动态目录可能因账户、工作区、区域或套餐而异。

用错了账户或 key。把你的来源与上面的凭据顺序对照。查找钉在 models.yml 中的 key、已存储的 OAuth 账户、已导出的变量，以及四个 .env 位置。用 /logout <provider> 移除受管账户。

自定义提供商被跳过。运行 omp models；校验错误会打印在列表之前。带显式模型的提供商需要 baseUrl、一个 api 值，以及 apiKey，除非它声明了 auth: none。

本地提供商没有返回模型。确认引擎正在生效的 base URL 上监听，并已加载模型。然后运行 omp models refresh。空的或不可达的本地端点会保持不可用。
