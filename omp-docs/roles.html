模型角色

把日常工作、快速的小任务、计划、视觉和子代理分别路由到合适的模型，而不必为每个请求手动挑模型。

按用途路由工作

模型角色让 omp 可以为不同类型的工作使用不同的模型。你可能会为主会话保留一个均衡的模型，为轻量工作使用更快的模型，为困难的计划或审查使用更强的推理模型。每个角色只需配置一次；使用该角色的功能会自动选用它。

你并不必在使用 omp 之前就配置角色。登录某个提供商后，omp 会自动为尚未分配的内置角色选择合适的可用模型。先使用默认值，然后只在需要可预期的质量、延迟、成本或提供商用量时才固定某个角色。

角色决定由哪个模型处理某类工作；代理还决定该工作者如何行事以及可以使用什么。在决定要改动哪一层时，参见代理与模型角色。

最快的分配方式：

  1. 输入 /model（或按 Alt+M）。
  2. 打开角色。
  3. 选择一个角色，挑选一个模型，并可选择其思考强度。
  4. 返回角色即可看到生效的分配。

大多数人只需要考虑这些角色：

角色何时配置它…
default你想为常规交互式工作选择模型。
smol你希望轻量工作偏向速度与成本。它通常也是Prewalk 的交接目标。
slow你希望困难的推理与审查使用更强的模型。
plan你希望计划模式使用专门的架构模型。
vision你的主模型无法查看图片，或者你想把图像分析路由到别处。

自动发生的部分

当 modelRoles 映射为空时，omp 会从可用且已认证的模型中解析角色。因此，专用功能无需完整的角色映射也能工作。

有几个默认行为值得了解：

  • default 是主会话模型。
  • 未分配的 smol、slow 和 designer 角色在 omp 寻找其他合适模型之前，可以先使用已配置的 default 模型。
  • 未分配的 tiny 工作会沿用 smol 所使用的快速模型偏好。
  • 未分配的 advisor 会寻找一个独立的强推理模型，而不是继承 default。顾问工作流见顾问模型。
  • 如果没有任何可用模型能满足某个角色，omp 会跳过该路由，或显示可据以行动的模型/认证错误，而不是悄悄使用未认证的提供商。

自动选择会随提供商、凭据或模型目录的变化而变化。请固定那些行为必须保持稳定的角色。

在模型中心分配角色

/model 和 Alt+M 会打开完整的模型中心。其中的角色视图是推荐的配置界面，因为它同时显示显式分配和自动选择。

  • 选择一个角色会打开可用的模型目录。
  • 选择一个模型即可挑选受支持的思考强度。
  • 清除显式分配会让该角色回到自动选择。
  • 该视图还管理 Ctrl+P 快速循环的顺序和重试回退链。
  • 被锁定的提供商会引导你去登录，而不是创建一条不可用的分配。

默认情况下，分配是全局的，保存在活动配置档的代理配置中（通常是 ~/.omp/agent/config.yml）。要允许按项目分配，请设置：

modelRoleStorage: project

之后模型中心会询问是把分配保存为全局还是保存到当前项目。项目级分配写入 .omp/config.yml；在那里缺失的角色会继续使用其全局分配。

在 YAML 中配置角色

最小的有用手动配置是在 ~/.omp/agent/config.yml 中写一个 modelRoles 映射：

modelRoles:
  default: anthropic/claude-sonnet-4-6
  smol: anthropic/claude-haiku-4-5
  slow: openai-codex/gpt-5.3-codex:high
  plan: anthropic/claude-opus-4-6:high

用 omp models find <name> 查找你安装中可用的选择器。显式的 provider/model-id 是最可预期的取值。思考后缀可以是 off、minimal、low、medium、high、xhigh、max 或 auto；不受支持的级别会被约束到所选模型支持的范围内。

角色取值还接受：

形式含义示例
模型选择器或模式选择匹配的模型。在长期配置中优先使用完整的、带提供商限定的选择器。google/gemini-3-pro
有序选择器从左到右依次尝试逗号分隔的选择器，使用第一个可用的匹配。anthropic/claude-sonnet-4-6,openai/gpt-5.4
角色别名复用另一个已配置的角色。@role 是规范写法；* 表示 @default。task: "@slow"
思考后缀为该角色固定或自动选择思考强度。openai-codex/gpt-5.3-codex:xhigh

pi/role 仍作为旧式角色别名被接受，但新配置应使用 @role。

为单次启动覆盖角色

启动标志和环境变量适用于实验或脚本。它们不会改写你已保存的角色分配。

目标Shell 标志环境变量优先级
活动主模型--model <selector>—启动标志
smol--smol <selector>PI_SMOL_MODEL标志，其次环境变量，再次配置/自动选择
slow--slow <selector>PI_SLOW_MODEL标志，其次环境变量，再次配置/自动选择
plan--plan <selector>PI_PLAN_MODEL标志，其次环境变量，再次配置/自动选择

例如：

omp --model @default --slow openai-codex/gpt-5.3-codex:xhigh
PI_SMOL_MODEL=anthropic/claude-haiku-4-5 omp

--model 选择的是该会话的活动模型；它不是持久的 modelRoles.default 分配。

在运行中的会话里切换与验证

操作结果
/model 或 /models打开持久的模型与角色中心。使用角色查看和编辑分配。
Alt+M打开同一个持久中心。
/switch 或 Alt+P仅为当前会话选择模型。它不会改变角色配置。
Ctrl+P在已配置的快速角色循环中向前切换。
Shift+Ctrl+P在已配置的快速角色循环中向后切换。

默认循环是 smol → default → slow。omp 会跳过没有可用分配的角色；如果只有一个角色模型可用，它会提示没有可切换的对象。循环切换改变的是当前会话的活动模型，而不是已保存的角色映射。

在角色视图中或用 cycleOrder 更改顺序：

cycleOrder:
  - default
  - slow
  - smol

完成分配后，重新打开 /model 并查看角色，以验证 omp 解析出的模型与思考强度。对于主会话，切换或循环之后状态行也会显示当前活动模型。

全部内置角色

角色路由给它的工作
default常规交互式工作以及主会话的默认模型。
smol快速、廉价的实用工作以及快速交接路径。
slow可以接受额外延迟的深入推理。
vision需要具备视觉能力的模型时进行图像查看。
plan计划模式的架构设计与审查。
designerdesigner 子代理。
commit生成提交信息；未分配时提交流程可以落到其他可用角色。
tiny非常小的在线分类、标题生成、记忆支持与语音清理；未分配时沿用 smol 的偏好。
task当代理没有请求其他模型时的通用子代理工作。
advisor顾问模型所使用的独立推理模型。

扩展和自编代理可以引入额外的角色名称。自定义角色在出现在 modelRoles、cycleOrder 或 modelTags 中时会在模型中心可见；要让工作真正路由到它，扩展或代理必须实际引用该角色。

添加重试回退模型

角色分配选择首选模型。重试回退链说明当某个符合条件的请求失败或配额状况使该模型不可用时，omp 可以转向哪里。

最简单的设置方式是在 /model → 角色中：在某个角色下添加回退行，或选择新建回退来保护某个特定模型或提供商。顺序很重要；omp 会从上到下尝试可用条目。

最小的 YAML 回退链如下：

retry:
  modelFallback: true
  fallbackChains:
    default:
      - openai/gpt-5.4
      - google/gemini-3-pro
  fallbackRevertPolicy: cooldown-expiry

default 链也会用于没有自己回退链的已配置角色。当某个角色需要不同的成本、能力或提供商边界时，为它单独提供列表：

retry:
  fallbackChains:
    default:
      - openai/gpt-5.4
    vision:
      - google/gemini-3-pro
    "google-antigravity/*":
      - google/*
      - google-vertex/*

回退链的键和条目比角色取值有更严格的语法：

语法作为键作为回退条目
角色名，例如 default 或 vision保护该角色所选的模型。不用作条目；请直接写模型名。
provider/model-id保护那个确切的活动模型，无论它由哪个角色选中。切换到那个确切的模型。允许带思考后缀。
provider/*保护来自该提供商的任何活动模型。保持当前模型 id，并通过指定的提供商尝试它。
provider/id-prefix/*保护该提供商侧前缀下匹配的 id。为 OpenRouter 这类路由型提供商给当前裸模型 id 重新加前缀。

在回退数组中请使用完整的、带提供商限定的选择器。每个回退项还需要可用的凭据和目录条目；不可用的候选项会被跳过。

设置默认值用途
modelRoles{}把角色名映射到模型选择。为空的内置角色会自动解析。
modelRoleStorageglobalglobal 把角色更改保存在活动配置档中；project 启用全局/项目选择以及 .omp/config.yml 覆盖。

重试回退设置

设置默认值用途
retry.modelFallbacktrue允许重试恢复时切换到已配置的回退模型。
retry.fallbackChains{}把角色、确切模型、提供商通配或带前缀的提供商通配映射到有序的回退选择器数组。
retry.fallbackRevertPolicycooldown-expirycooldown-expiry 在其抑制窗口结束后回到主模型；never 会一直停留在回退模型上，直到你手动切换。
retry.usageAwareFallbackfalse使用可靠的编码套餐配额报告，在触及硬性上限之前先在账户之间、再在已配置模型之间转移。普通 API key 配额不会被推断。
retry.usageReservePct10启用用量感知回退时，视为保留余量的编码套餐剩余百分比。
retry.usageReservePolicyconfirmconfirm 在交互式会话中询问（后台代理会自动回退），auto 总是选择下一个可用回退，fail-closed 既不使用保留配额也不使用回退。

配置优先级见设置，凭据与提供商特定的模型发现见模型提供商。

故障排查

某个角色解析出的模型与另一个角色相同

这可能是自动行为，尤其是未分配的 smol、slow 或 designer。如果你需要区分，请在 /model → 角色中显式分配该角色。

Ctrl+P 提示只有一个角色模型可用

打开 /model 并检查 cycleOrder 中列出的角色。至少为两个角色分配到可用且已认证的模型。快速循环会跳过缺失或不可用的分配；--models 只为某次启动限定模型目录，不会替换 cycleOrder。

某项更改在另一个项目中消失——或者到处都出现

检查 modelRoleStorage。为 global 时，模型中心的更改会跨项目生效。为 project 时，请检查角色视图是把分配保存到了项目还是全局；.omp/config.yml 只对该项目覆盖全局值。

omp 报告未知模型或缺少 API key

运行 omp models find <name> 并使用列出的 provider/model-id，然后用 /login 登录，或配置该提供商的凭据。如果某提供商刚刚发布了一个模型，请先运行 omp models refresh，再重新搜索。

回退从不执行

确认 retry.modelFallback 为 true，当前角色/模型有匹配且非空的回退链，并且至少有一个回退项拥有有效凭据。角色别名和模糊名称在 modelRoles 中很有用，但回退数组应使用具体的 provider/model-id 选择器或受支持的提供商通配。

回退执行了，但没有回到主模型

设置 retry.fallbackRevertPolicy: cooldown-expiry，以便在主模型的抑制窗口结束后返回。使用 never 时，请用 /switch、/model 或模型快捷键手动切换。

图像查看提示未配置视觉模型

把 modelRoles.vision 分配到一个目录条目支持图像输入的模型。仅在 vision 位置写一个纯文本模型并不会增加视觉能力。
