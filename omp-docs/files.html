非茗的翻译文档库

处理文件

让 omp 探索项目、解释或比较文件、从文档和压缩包中提取信息，以及做出精确的改动。它可以在你的本地工作区、受支持的 SSH 主机、网页、notebook、图片、数据库和常见压缩格式上工作。

当你希望 omp 理解真实项目上下文、而不是基于粘贴的片段工作时，请使用文件能力。把它指向一个目录或文件，描述你想要的结果，让它在动手修改之前先缩小搜索范围。

从一个问题开始

在你想让它检查的项目中启动 omp：

cd my-project
omp

然后用日常语言提问：

Find where refresh tokens are created. Explain the flow and cite the relevant files. Do not edit anything.

omp 会搜索工作区，打开相关部分，并报告它用到的路径。最后一句让这第一遍明确保持只读。等解释看起来正确后，再跟进一个有边界的改动：

Rename issueToken to mintToken across the implementation and its tests. Show me every changed file and run the focused tests.

改动直接发生在工作树中。在交互式对话记录里，omp 会显示受影响的路径和文本改动的彩色 diff；新建、移动和删除各有独立的状态行。展开一个结果可以查看大 diff 的更多内容。除非你要求，omp 不会创建 Git 提交。

你可以要求什么

目标示例请求
理解代码库“梳理从 POST /login 到数据库的请求路径。引用重要的文件和函数。”
查找文本或文件“找出所有提到旧主机的测试 fixture，包括 testdata/ 下被忽略的 fixture。”
比较版本或格式“按语义而不是键顺序比较这两个 JSON 文件，并总结行为上的差异。”
提取文档数据“从 vendor-proposal.xlsx 中提取定价表，并标出不一致的合计。”
检查压缩包“在 release.tar.zst 里找出生产配置，并与 config/production.yml 比较。”
处理 notebook“更新 analysis.ipynb 中的绘图单元格，为两个坐标轴都加上标签；其他单元格不要动。”
检查数据库“列出 cache.db 中的表，然后显示 sessions 表的 schema 和最新五行。不要修改它。”
查看图片“检查 screenshots/error-state.png，列出可见的错误文本和布局问题。”
使用远程主机“对 ssh://staging/etc/nginx/nginx.conf，解释其中的代理规则。不要改动远程文件。”
做有边界的改动“在 src/config.ts 中替换已废弃的端点，更新它的测试，并显示 diff。”

具体的路径、期望的结果，加上“不要编辑”“只改这些文件”或“保留原有格式”这样的边界，通常能得到最好的结果。

omp 能理解的数据

本地文件与目录

omp 可以浏览目录，检查文本、源代码、配置、日志和其他 UTF-8 文件。首次打开一个大型源文件时，它可能会使用结构化概览，展示声明而省略函数体。当你需要完整文本时，请要求确切的实现、引用的行或某个具名函数。

工作区发现默认遵循 .gitignore。如果答案存在于被忽略的构建产物、fixture、日志或 .env 文件中，请明确说明要包含哪个被忽略的路径。避免不必要地暴露密钥值；当变量名或结构足够时，就要求这些而不是内容。

目录列表有深度限制，宽泛的搜索也有上限，以免单个请求淹没会话。项目很大时，请按目录、扩展名、符号或日期缩小范围。

文档、notebook 与图片

omp 会从这些文档格式中提取可读内容：

  • PDF
  • Word .docx
  • PowerPoint .pptx
  • Excel .xlsx
  • EPUB

旧版 .doc、.ppt、.xls 和 .rtf 文件不会被自动转换。请先把它们转换成现代格式、PDF 或纯文本。

Jupyter .ipynb 文件会以可编辑的代码、Markdown 和 raw 单元格呈现，而不是原始 notebook JSON。修改单元格源码时，现有的 notebook 结构和单元格元数据会保留。受支持的图片可以内联查看；大于 20 MiB 的图片会被拒绝。

压缩包与压缩文件

omp 可以列出并检查成员，而不需要你先解开大多数常见压缩包。读取支持包括：

  • ZIP 以及基于 ZIP 的包，例如 JAR、APK 和 Python wheel
  • tar 归档，包括 gzip、bzip2、xz 和 zstd 变体
  • RAR、7z、ISO、CAB、Debian、RPM、CPIO、ar、静态库、LZH、ARJ 和 ASAR
  • 使用 gzip、bzip2、xz 或 zstd 的单个压缩流

压缩包的写入范围有意更窄。omp 可以修改基于 ZIP 的压缩包（.zip、.jar、.war、.ear、.apk）、.tar、.tar.gz/.tgz、.tar.zst 和 .asar 中的条目。其他压缩格式是只读的；如果必须修改，请解包后重新打包。把压缩包更新视为直接的写入操作，当压缩包尚未纳入版本控制时请保留备份。

SQLite 数据库

以 .sqlite、.sqlite3、.db 或 .db3 结尾的文件可以作为数据库来检查：omp 可以列出表、显示 schema、取回行，并回答有边界的查询式问题。它也可以插入一行，或按主键更新、删除某一行。当你只想分析时，请说明“只读”，并在请求写入前备份重要数据库。

网页、SSH 主机与 omp 资源

给 omp 一个 http:// 或 https:// URL，它会把页面的主要内容提取为干净的文本。这最适合文档和文章。如果页面依赖 JavaScript、认证或交互，请改为让 omp 在浏览器中打开它。

以 ssh:// 开头的路径可以访问已配置的远程 POSIX 主机。omp 可以列出远程目录、读取和搜索远程 UTF-8 文件，并写入远程文件。直接的远程读取上限为 1 MiB。主机必须已配置并验证，并且这个路径接口不支持 Windows SSH 目标；请改为在本地挂载，或使用显式的远程 shell 工作流。

omp 也可以跟随它自己的资源链接——例如缓存的 GitHub issue 和 pull request、会话产物、历史、记忆和计划文件。GitHub 资源见 GitHub。

文件改动时会发生什么

  1. omp 先检查再改动。 对普通的文本编辑，它用刚看到的内容来定位改动。如果另一个进程先改变了那段内容，omp 可以拒绝或恢复过期的目标，而不是盲目应用。
  2. 当你的策略要求时，写入之前会先审批。 被拒绝的审批会让目标保持原样。
  3. 结果立即可见。 文本编辑会显示 diff 和改动计数。新建、移动、删除、无变化的改动和错误会分别标注。
  4. 之后可能附带可选的语言反馈。 LSP 诊断和格式化取决于你的设置。它们不能替代你让 omp 运行的构建或测试命令。
  5. 工作树始终属于你。 用你平时的编辑器或 git diff 审阅，然后让 omp 修复任何意料之外的地方。

关于符号感知的重命名与诊断，见 代码智能。

安全与配置

默认审批模式是 Yolo，它允许读取、写入和命令执行，除非有按能力设定的策略覆盖它。若要让会话在工作区写入和命令之前暂停，请这样启动 omp：

omp --approval-mode always-ask

你可以在 /settings 的 Interaction → Approvals 下持久地更改这一点。“总是询问”会自动允许只读检查，并在写入和命令执行时请求确认。对于不能修改工作区的设计阶段，请使用 计划模式。

与文件相关的 LSP 控制在 /settings 的 Files → LSP 下。默认情况下，写入时格式化关闭，整文件写入后的诊断开启，增量编辑后的诊断关闭。如果你希望自动获得这些行为，请启用 Format on Write 或 Diagnostics on Edit，或者在改动后让 omp 运行特定的格式化器或检查。

对于敏感或高影响的工作：

  • 先以“只检查”开始，或使用计划模式。
  • 指明允许的文件和禁止涉及的领域。
  • 在改动压缩包、数据库或未纳入版本控制的远程文件之前，要求先备份。
  • 在要求提交之前，审阅显示的 diff 和 git diff。
  • 当密钥值不需要时，让它们远离提示词和 diff。

配置文件位置与优先级见 设置。

故障排查

问题该怎么办
omp 找不到本地文件检查路径相对于 omp 启动目录的位置。从项目根目录重新启动，或使用 omp --cwd /path/to/project。
结果中缺少某个被忽略的文件指明确切的被忽略目录或文件，并明确要求 omp 包含被忽略的内容。不要宽泛地包含密钥文件。
源文件看起来不完整omp 很可能返回的是结构化概览。要求给出具名函数的确切函数体、行范围或逐字内容。
结果在部分文件之后就停了按目录或文件类型缩小请求范围，或让 omp 从剩余的匹配项继续。
编辑因内容过期而被拒绝omp 检查之后，另一个进程改动了该文件。让 omp 重新打开当前文件，并基于新内容重试。
无法解码某个文档确认它是 PDF、.docx、.pptx、.xlsx 或 .epub；先转换旧版 Office 格式。
压缩包可以检查但不能修改它的格式是只读的。请解包并重新打包为受支持的 ZIP、tar 或 ASAR 格式。
SSH 路径失败确认普通 SSH 访问可用、该主机是 omp 已知的 POSIX 系统，并且目标为 UTF-8 且直接读取时不超过 1 MiB。
网页为空或不完整它很可能需要 JavaScript、登录或交互。让 omp 使用浏览器，并描述你想要的动作。
格式化或诊断没有运行要求确切的格式化器/检查，或在 /settings 的 Files → LSP 下启用相关选项。
