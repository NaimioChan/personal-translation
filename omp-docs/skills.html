技能

给 omp 一份针对某类可复用的工作手册，然后让它在相关时才加载这份指导。

技能改变omp 处理任务的方式：它为某个特定领域提供指令、约定和可选的配套文件。它本身不会增加权限，也不会增加可执行的工具。

要使用已安装的技能，直接从你真正想完成的任务开始：

Review this Postgres migration for locking and rollback risks.

在会话开始时，omp 会公布每个可用技能的名称和描述。当你的请求与某个描述匹配时，代理会先加载该技能的完整手册，再开始工作。正常使用时你不需要特殊语法。

查找并使用已安装的技能

在交互式 TUI 中运行：

/extensions

打开 Skills 可查看每个已发现技能的描述、状态、作用域、提供商和来源路径。选择一个技能并按 Space 或 Enter 来启用或禁用它。更改会被持久化；之后请运行 /reload-plugins，让当前会话刷新其技能和 /skill: 命令。

当你想要强制使用某个特定技能、而不是依赖匹配时，请显式调用它：

/skill:postgres Review migrations/042_add_status.sql for lock risk.

输入 /skill: 后，技能名称会出现在斜杠命令补全中。技能 token 也可以出现在普通文字里：

Review migrations/042_add_status.sql with /skill:postgres and propose a safer rollout.

显式调用默认可用。可以通过 skills.enableSkillCommands: false 将其禁用；自然的任务匹配仍然有效。隐藏的技能同样不参与自动匹配，但在启用技能命令时仍可通过 /skill:<name> 使用。

安装技能

一个独立技能就是一个包含 SKILL.md 的目录。把它复制到 omp 的原生位置之一：

~/.omp/agent/skills/<name>/SKILL.md   # user: every project
.omp/skills/<name>/SKILL.md           # project: this repository/tree

例如，为你自己安装一个已检出的技能，可以只有这么几步：

mkdir -p ~/.omp/agent/skills/postgres
cp ./postgres-skill/SKILL.md ~/.omp/agent/skills/postgres/SKILL.md

把手册引用的任何文件都放在同一个 postgres/ 目录中。发现只深入一层：skills/postgres/SKILL.md 会被找到，而 skills/databases/postgres/SKILL.md 不会。

技能也可以通过插件提供。浏览已配置的插件市场，然后以用户或项目作用域安装该插件：

omp plugin discover [marketplace]
omp plugin install --scope user name@marketplace
# or: omp plugin install --scope project name@marketplace

添加目录、查看包、固定版本、升级和卸载插件的方法见插件市场。在复制、安装、升级或编辑技能之后，请启动新会话或运行 /reload-plugins。与技能捆绑在一起的插件模块、钩子或工具仍可能需要完全重启。

作用域与信任

用户技能在每个项目中都可用。项目技能只有在 omp 从该项目树内启动时才会被发现；omp 也会沿父目录向上查找，直到仓库边界。这让项目技能适合仓库特定的工作流，但也意味着你打开的仓库可以贡献指令。

把技能当作代码对待：

  • 在启用之前检查 SKILL.md 以及它引用的脚本、模板和文件；
  • 检查 /extensions 中显示的来源，尤其是在新克隆的仓库里；
  • 当第三方技能只被一个项目需要时，以项目作用域安装它；
  • 记住手册可能会指示代理使用会话已有的权限运行命令。

同名技能不会合并。显式配置的自定义目录会覆盖默认发现位置。否则 omp 会保留优先级最高的提供商：原生 .omp、OMP/插件包、Claude、Agent/Codex 兼容目录、OpenCode、GitHub，最后是托管的自动学习技能。在被遍历的项目来源中，最近的目录优先。避免重名；/extensions 会显示哪一份副本生效、哪一份被遮蔽。

启用与筛选发现

当你需要临时的边界时，使用单次运行的标志：

omp --no-skills
omp --skills 'git-*,postgres'

--skills 接受以逗号分隔的 glob 模式，只保留匹配的名称。若要持久控制，请编辑 ~/.omp/agent/config.yml：

skills:
  enabled: true
  enableSkillCommands: true
  includeSkills:
    - "git-*"
    - postgres
  ignoredSkills:
    - "*-experimental"
  customDirectories:
    - ~/work/shared-skills

空的 includeSkills 列表会包含所有名称。ignoredSkills 会排除匹配的名称，即使它们也匹配允许列表。每个自定义目录中每个技能都必须占一个子目录，例如 ~/work/shared-skills/postgres/SKILL.md。

/extensions 中的开关会把单个被禁用的技能作为 skill:<name> 持久化到顶层 disabledExtensions 设置中。单个改动优先使用仪表板；等效的 YAML 是：

disabledExtensions:
  - skill:untrusted-skill

skills 下还有提供商专属开关：enablePiUser、enablePiProject、enableAgentsUser、enableAgentsProject、enableClaudeUser、enableClaudeProject 和 enableCodexUser。它们都默认为 true。

兼容位置

除 .omp 之外，omp 默认还会发现这些「每个技能一个目录」的布局：

作用域位置
用户~/.agent/skills/, ~/.agents/skills/, ~/.claude/skills/, ~/.codex/skills/, ~/.config/opencode/skills/
项目.agent/skills/, .agents/skills/, .claude/skills/, .codex/skills/, .opencode/skills/, .github/skills/
托管~/.omp/agent/managed-skills/

项目的 .agent、.agents 和 .claude 位置会在从工作目录向仓库根目录遍历时被发现。当多个兼容工具安装了同一个名称时，请使用 /extensions，而不要猜测。

创建最小的技能

在项目中创建 .omp/skills/release-check/SKILL.md：

---
description: Use when preparing or reviewing a release; verify versioning, changelog, build artifacts, and publication status.
---

# Release check

1. Identify the version and release tag.
2. Verify the changelog describes the shipped behavior.
3. Check the build artifacts before publishing.
4. Report blockers before changing a tag or publishing.

这就是一个完整的当前技能。目录名 release-check 会成为它的调用名，因此在运行 /reload-plugins 之后或在新会话中，可以用 /skill:release-check 请求它。

编写参考

Frontmatter

字段是否必需当前行为
description对于 .omp、自定义目录、插件和 GitHub 技能是必需的在正文加载之前显示，并用于判断技能是否适用。请写具体的任务动词、名词和范围。
name否覆盖用于匹配和 /skill:<name> 的目录名。除非兼容性要求覆盖，否则优先使用目录名。
hide否从自动技能列表中省略该技能，同时保留显式调用。
disable-model-invocation否与 Agent Skills 兼容的拼写，效果与 hide 相同。

虽然某些兼容格式接受 globs 或 alwaysApply 之类的字段，omp 目前并不用它们来选择或自动注入技能。请把触发条件写在 description 中。对于必须始终存在的指导，请改用上下文文件。

有用的描述会写明：

  • 动作：编写、审查、调试、迁移；
  • 对象：Postgres 迁移、快照测试、发布产物；
  • 需要时的边界：某个目录、文件类型或子系统。
description: Use when adding or reviewing Vitest tests in src/importer; covers fixtures, snapshots, and integration setup.

正文与配套文件

写直接的、可操作的指令。说明工作流何时适用、所需顺序、重要的安全边界，以及成功结果包含什么。把详细的参考资料、模板或脚本放在 SKILL.md 旁边，并用相对于技能目录的路径引用它们：

release-check/
├── SKILL.md
├── references/
│   └── registry-checks.md
└── scripts/
    └── verify-artifacts.sh

正文只在需要时加载，因此把冗长的参考材料移出始终可见的描述，可以让普通会话保持轻量。配套文件不会自动执行；手册必须说明何时以及如何使用它们。
