斜杠命令

本页是完整的会话内命令参考：语法、内置命令、子命令、别名、动态命令、优先级与重载行为。

运行命令

在主提示词编辑器中，输入/打开自动补全。继续输入以过滤，用方向键移动，按Tab或Enter接受补全。Escape关闭菜单。

最小的有用检查是：

/context

按Enter运行它。参数跟在命令之后，以空格分隔；命令族则先接受一个子命令：

/rename investigate checkout timeout
/usage reset active
/mcp test github

在下面的形式中，[value]是可选的，<value>是必需的，a|b表示从中选择一个。带引号的参数会把空格保留在一起。冒号可以把顶层命令与它的第一个参数分开，这就是/force write和/force:write都能用的原因。

没有顶层的/help内置命令。请通过/自动补全及其行内参数提示来学习命令。输入命令族加一个空格即可看到它的子命令。/mcp help、/ssh help和/marketplace help会打印各命令族专用的用法；/hotkeys显示键盘快捷键。无效参数也会打印可接受的形式。

本页描述的是交互式终端。命令只能从主会话编辑器运行，在子代理对话获得焦点时不能运行。协作期间，访客在本地只能运行/dump、/export、/copy、/hotkeys、/settings、/leave、/collab、/exit和/quit；其他所有斜杠命令都仅限主机。

内置命令

这些名称随核心注册表一同提供，优先于动态发现的命令。

模式、模型与轮次控制

命令可见效果与可用性
/settings打开设置菜单。
/setup [providers]
别名：/providers		打开提供商设置，用于登录提供商与网页搜索提供商。不接受其他子命令。
/plan [prompt]切换计划模式；行内提示词会立即开始规划。需要plan.enabled，不能在目标模式下启动，并且与 Vibe 模式互斥。见计划模式。
/plan-review重新打开最近一次计划审查。仅在计划模式激活时可用。
/vibe [prompt]切换只读的 Vibe 模式，并可选地用提示词启动它。它不能在计划模式或目标模式下启动。见Vibe 模式。
/goal [objective]未激活时打开目标编辑器，已激活时打开管理菜单；行内目标会直接启动一个目标。需要goal.enabled，并且不能在计划模式或 Vibe 模式下启动。见下面的子命令以及目标模式。
/guided-goal [rough objective]在聊天中开始一次访谈，然后根据结果配置目标模式。它受goal.enabled、计划模式与 Vibe 模式的约束，与/goal相同。
/loop [count|duration] [prompt]在每次让出控制权后切换是否自动重新提交。正整数限制迭代次数；时长接受紧凑或带空格的形式，例如90s、10 min或1h30m。纯文本是无界的行内提示词。再次运行/loop即可停止；Escape取消当前迭代。
/queue <message>在当前轮次让出后投递一条跟进消息；如果处于空闲状态，则立即开始。-> message和=> message是等价的编辑器简写。
/model
别名：/models		打开模型中心，用于选择角色与提供商。在 TUI 中该命令不接受模型 ID 参数。
/switch打开仅限会话的紧凑模型选择器，与Alt+P是同一操作；它不会持久化角色设置。
/fast [on|off|status]不带参数的形式切换优先服务（service_tier=priority用于 OpenAI，或为 Anthropic 使用快速速度）。对当前模型可能无法启用。toggle也被接受。
/extended-context [on|off|status]不带参数的形式切换持久化的高级长上下文设置；toggle也被接受。
/computer [on|off|status]不带参数的形式切换本会话的原生电脑控制工具。status会报告后端、权限、暴露情况与模型；在会话中可能无法启用。toggle也被接受。
/vision <on|off|auto|status>为inspect_image委派工具设置会话级覆盖。auto会遵循已配置的模式，并对具有原生图像输入的模型隐藏该委派。
/prewalk为下一次受 todo 门控的编辑或写入启用已认证的@smol角色，即使 omp 启动时没有带--prewalk。见Prewalk。
/advisor [on|off|status|dump [raw]|configure]不带参数的形式切换顾问；/advisor toggle等价。显式形式为/advisor on、/advisor off、/advisor status、/advisor dump [raw]和/advisor configure。dump会复制一份紧凑的对话记录，除非提供了raw；configure会打开 TUI 编辑器。已配置的顾问仍需要为advisor角色分配一个模型。见顾问模型。
/browser [headless|visible]不带参数的形式在无头与可见之间切换浏览器并重启它。需要browser.enabled。hidden表示无头；show和headful表示可见。
/force:<tool-name> [prompt]
也可写作/force <tool-name> [prompt]		为下一轮代理强制指定一个工具。行内提示词会立即开始该轮次；没有它时，下一条消息会使用该选择。工具必须处于活动状态。
/live启动由 Codex 支持的实时语音模式；再次运行以停止。仅限交互式 TUI。
/pause在下一个安全边界冻结主代理、子代理和顾问。进行中的调用会完成；Escape、Enter或Space恢复它们。

安全

/security需要security.enabled。不带参数的/security会列出已存储的扫描。该命令把本地扫描工作作为后台操作启动，因此请用status而不是在提示词处等待。云端形式还需要一个已存储的 OpenAI Codex OAuth 账户。扫描模型与产物见安全扫描。

形式效果
/security plan [options]创建一个不可变的计划，并打印其 ID 与指纹。选项：可重复的--path <path>、--exclude <path>和--knowledge-base <path>；--working-tree；--diff <base> <head>；--output <dir>；--archive-existing；--credential <id>。
/security scan [<plan-id>|options]启动一个已有的secplan_…，或从相同的选项创建计划并启动它。打印扫描 ID 与操作 ID。
/security status [operation-id]显示一个操作，或列出操作。
/security cancel <operation-id>请求取消正在运行的操作。
/security scans列出已存储的项目扫描。
/security show <scan-id|security://…>渲染一个扫描或其他安全资源。
/security import <sarif-file|bundle-directory>把 SARIF 或 Codex Security 包导入项目存储。
/security export <scan-id> --output <path> [--format bundle|sarif|report]写出规范包、SARIF 文档或报告。
/security validate <finding-uri>
或/security validate <scan-id> <finding-id>		启动一轮代理，用原生安全工具验证某一条发现。
/security compare <before-scan-id> <after-scan-id>打印发现谱系的比较数据。
/security disposition <scan-id> <finding-id> <open|false_positive|accepted_risk|fixed|wont_fix> [rationale]更新一条发现。除open之外的每个状态都需要理由。
/security cloud scans [--credential <id>]列出 Codex Security 云端配置。这个被接受的子命令目前未出现在嵌套自动补全中。
/security cloud start --repo-id <id> --repo-url <url> --environment <id> [--lookback <days|all>] [--credential <id>]启动云端扫描并消耗云端扫描额度。
/security cloud status <configuration-id> [--credential <id>]显示云端扫描统计。
/security cloud pull <configuration-id> [--credential <id>]把云端发现导入本地项目存储。

会话、历史与上下文维护

命令可见效果与可用性
/session [info]在 TUI 中打开当前会话信息。
/session delete删除当前已持久化的会话并返回选择器。流式输出期间或对内存会话不可用。
/session pin [account]把当前提供商固定到一个已存储的 OAuth 账户；不带账户时打开账户选择器。这与顶层的/pin不同。
/new在不删除当前会话的情况下开始一个新会话。
/fresh关闭提供商侧的流状态，并在不改变本地对话记录的情况下开始全新的提供商状态。流式输出期间不可用。
/clear就地清空对话上下文，同时保留会话。流式输出期间不可用。
/drop删除当前会话并开始一个新的。
/resume [session-id|@claude|@codex]打开本地会话选择器、打开 Claude/Codex 导入选择器，或恢复匹配的会话 ID。仅限交互式 TUI。
/pin [session-id]把当前或指定的会话在恢复列表顶部切换固定。
/rename <title>为当前会话设置用户指定的标题。
/move <path>把会话移动到另一个已存在的目录，重新加载目录作用域的设置与已发现的能力，并把该路径设为工作目录。流式输出期间不可用。
/add-dir <path>向本会话添加一个已存在的额外工作区根目录。流式输出期间不可用。
/remove-dir <path>移除一个额外的工作区根目录。工作目录本身不能被移除；请使用/move。
/dirs列出工作目录和每个额外的工作区根目录。
/tree打开就地会话树并切换到已存在的分支。
/branch选择一条较早的消息，并在同一个会话文件中创建另一个分支。
/fork选择一条较早的消息，并从中创建一个单独的会话文件。
/compact [focus]使用已配置的方法和可选的聚焦说明手动压缩上下文。见上下文压缩。
/compact soft [focus]在本次运行中强制使用当前模型生成一份本地摘要。
/compact remote [focus]尝试 OpenAI 兼容的服务器端压缩，然后回退到本地摘要。
/compact snapcompact把历史归档为高密度位图图像，而不使用 LLM 摘要；它拒绝聚焦文本。
/shake [elide|images|thinking]在不做摘要的情况下移除沉重的上下文。不带参数的形式/elide会剥离工具结果和大块内容；其他模式剥离图像或思考块。
/handoff [focus instructions]生成一份交接文档，并把它作为压缩条目提交到同一个会话中。需要会话处于空闲且消息足够；它不会自动结束轮次或创建新会话。见交接。
/btw <question>用当前上下文提出一个临时的附带问题；这次交流不会被加入已持久化的对话。
/tan <work>为附带工作启动一个完整的后台代理。仅限交互式 TUI。
/retry重试上一次失败的代理轮次。它仅在空闲时、且存在可重试的失败轮次时有效。
/omfg <complaint>把对反复出现行为的抱怨转换成 TTSR 规则。仅限交互式 TUI。
/cleanse [request] [--all]用加权并行子代理检测并修复项目诊断。仅限交互式 TUI。

内置工作流命令

有三个有用的命令不在核心注册表中提供，因此它们可以被覆盖：

命令来源与效果
/review [GitHub PR URL|pr://owner/repo/number] [instructions]内置的 TypeScript 命令。给出 PR 引用会直接开始该审查；否则 TUI 会提供基于基础分支、未提交改动、提交或自定义审查。见代码审查。
/green内置的 TypeScript 命令，展开为一个监视并修复 CI 直到当前分支变绿的工作流。
/init [request]内置的 Markdown 文件命令，展开为仓库初始化工作流。一个被发现且名为init的文件命令会替换它。

技能

当skills.enabled和skills.enableSkillCommands都开启时，每个被发现的技能都会以如下形式出现：

/skill:<name> [arguments]

该命令会在本轮次加载该技能的说明。技能命令是归属于用户的提示词，不是核心内置命令。用/extensions查看它们的来源与状态。见技能。

扩展与可执行命令

扩展可以注册带有自己的 UI 或程序逻辑的会话内命令。用户/项目的 TypeScript 命令模块从活动代理/配置目录下的commands/<name>/index.{ts,js,mjs,cjs}中发现，而 MCP 提示词命令由已连接的服务器添加为/<server>:<prompt>。内置名称是保留的。omp 内置的/review和/green是优先级最低的可执行命令；同名的用户或项目命令模块会替换内置的那个。见编写扩展。

文件斜杠命令

在被发现的commands/能力目录下的 Markdown 会变成/<filename>，并展开为一段提示词。原生位置是当前项目的.omp/commands/*.md和活动配置档代理的commands/*.md；兼容的 Claude Code、agent-dir、Codex、OpenCode 和已安装插件的提供方也会被发现。

对于重名的文件命令，优先级更高的能力提供方获胜。原生.omp命令拥有最高的提供方优先级，项目.omp/commands优先于活动配置档的用户目录。插件与兼容提供方次之。内置的/init仅在发现过程尚未占用init时使用。

提示词模板

Markdown 提示词模板也会以/<filename>的形式出现，但它们是独立的、最后兜底的展开系统。项目模板位于.omp/prompts/**/*.md；用户模板位于活动代理配置档的prompts/**/*.md。用户模板先于项目模板加载，因此用户模板会胜过同名的项目模板。参数与插值见提示词模板。

解析顺序

当同一个 token 存在于多个系统中时，omp 按以下顺序解析：

  1. 核心内置名称或别名；
  2. /skill:<name>；
  3. 扩展注册的命令；
  4. TypeScript 自定义命令，然后是 MCP 提示词命令；
  5. 被发现的 Markdown 文件斜杠命令；
  6. 提示词模板。

自动补全会省略已被占用的低优先级提示词模板。请使用有区分度的名称，而不要依赖遮蔽。

更改命令后重载

/reload-plugins会在当前 TUI 中刷新技能、Markdown 文件斜杠命令、任务代理定义、能力缓存和 MCP 连接。添加或更改提示词模板、可执行命令模块、扩展模块、钩子或自定义工具后，请重启 omp；这些已初始化的表面不会被完全就地重建。用/move移动会话会刷新目录作用域的能力，但新会话仍是加载已更改的提示词模板或可执行代码的可靠方式。

斜杠命令与魔法关键词

魔法关键词是提示词中的普通词语，会为该轮次添加隐藏的引导；它们不是/命令，也不会出现在命令自动补全中。同样，/review是内置工作流命令，而不是核心内置命令。关于各自专注的工作流，见代码审查、顾问模型、Vibe 模式、安全扫描和Prewalk；本页是清单与语法参考。
