插件

安装、检查、暂停、更新和移除可信的 omp 能力包，无需手动管理每一个文件。

插件以单个受管理单元的形式为 omp 增添能力。一个插件可以包含扩展代码、技能、斜杠命令、钩子、自定义工具、代理、规则、提示词，或 MCP/LSP/DAP 配置。当你想把一组相关行为一起安装和管理时，就使用它。

先看看已经安装了什么。在添加任何东西之前，检查它的发布者和来源：

omp plugin list
omp plugin install --dry-run '@scope/plugin@1.2.3'
omp plugin install '@scope/plugin@1.2.3'
omp plugin list

--dry-run 会预览 npm、Git 和本地路径安装，而不安装目标。它不适用于插件市场安装；对这类安装请在项目作用域中评估。安装成功会打印解析后的名称和版本。请启动新的 omp 会话以加载插件的全部行为，或参照重新加载活动会话。

插件是可信代码，不是沙箱。项目作用域限制了插件市场插件的发现位置；它并不限制该插件能读取、写入、执行或通过网络发送什么。

选择安装来源

omp plugin install 接受这些来源形式：

来源示例安装到何处
npm 包或版本omp plugin install '@scope/plugin@1.2.3'用户插件目录
Git 简写，可选固定版本omp plugin install 'github:org/repo#v1.4.0'用户插件目录
完整 Git URLomp plugin install 'https://github.com/org/repo.git#v1.4.0'用户插件目录
本地目录omp plugin install ./path/to/plugin以符号链接方式放入用户插件目录
插件市场条目omp plugin install --scope project plugin-name@marketplace-name默认用户作用域，或项目作用域

Git 简写还支持 gitlab:、bitbucket:、codeberg:、sourcehut: 和 srht:。完整的 HTTPS、SSH、git:// 和 git+… URL 都会被接受。包含 #、[ 或 ] 的来源请加引号，以免 shell 解释它们。

更短的 omp install <source> 命令是 omp plugin install 和 omp plugin link 的便捷封装。本页通篇使用 omp plugin … 形式，因为它暴露了完整的管理接口。

对于正在开发的本地插件，以下两种方式等价：

omp plugin install ./my-plugin
omp plugin link ./my-plugin

对源码的修改会通过符号链接立即可见，但已在运行的 omp 会话仍需重新加载或重启，之后每一项变更过的能力才会生效。

从插件市场安装

插件市场是插件的目录，本身不是插件。添加一个目录，检查其条目，然后用完整的 name@marketplace ID 安装某个条目：

omp plugin marketplace add anthropics/claude-plugins-official
omp plugin marketplace list
omp plugin discover claude-plugins-official
omp plugin install --scope project plugin-name@claude-plugins-official
omp plugin list

支持的目录来源包括：

  • GitHub 简写，例如 owner/repo
  • HTTP(S)、SSH 或 Git 仓库 URL
  • 以 .json 结尾的直接 HTTP(S) URL
  • 本地目录，例如 ./catalog、~/catalog 或 /absolute/catalog

Git 和本地目录使用 .omp-plugin/marketplace.json，找不到时回退到与 Claude Code 兼容的 .claude-plugin/marketplace.json。目录浏览、来源格式和发布参见插件市场。

用户作用域与项目作用域

作用域仅适用于插件市场安装：

  • --scope user 是默认值，使插件在所有项目中可用。
  • --scope project 会把它记录到最近的项目 .omp/plugins/installed_plugins.json，并使其在该项目中可用。
  • npm、Git 和链接的本地插件使用用户插件目录；对它们传入 --scope 会被忽略并给出警告。

已启用的项目安装会遮蔽具有相同 name@marketplace ID 的已启用用户安装。已禁用的项目安装不会隐藏已启用的用户安装。如果同一个插件在两个作用域中都安装了，升级、禁用、启用或卸载该副本时请传入 --scope user 或 --scope project。

项目作用域适合让某个项目的依赖集合保持独立。它不是安全边界：插件仍以与 omp 相同的操作系统权限运行。

检查、禁用与启用

在更改状态之前先列出内容，以便使用已安装的包名或完整插件市场 ID：

omp plugin list
omp plugin list --json

人类可读的列表会把 npm/link 插件与插件市场插件分开。它显示 npm/link 插件的版本、启用状态和可选特性；插件市场行则包含作用域，以及是否有项目副本遮蔽了用户副本。在会话内，/plugins 或 /plugins list 提供更简短的视图。

当你想停止加载某个插件，但不想删除其文件或设置时，请禁用它：

# npm, Git, or linked plugin; state is user-wide
omp plugin disable @scope/plugin
omp plugin enable @scope/plugin

# marketplace plugin
omp plugin disable --scope project plugin-name@marketplace-name
omp plugin enable --scope project plugin-name@marketplace-name

在交互式会话中，/plugins disable 和 /plugins enable 管理插件市场插件：

/plugins disable --scope project plugin-name@marketplace-name
/plugins enable --scope project plugin-name@marketplace-name

之后运行 /reload-plugins，或重启 omp。禁用会减少未来的加载；它无法撤销代码在当前进程中已执行的操作。

某些 npm/link 插件会声明可选特性。可以独立于整个插件的启用状态来检查和更改它们：

omp plugin features @scope/plugin
omp plugin features @scope/plugin --enable search,web
omp plugin features @scope/plugin --disable web
omp plugin features @scope/plugin --set search

安装时请给特性选择器加引号：

omp plugin install '@scope/plugin[search,web]'
omp plugin install '@scope/plugin[*]'
omp plugin install '@scope/plugin[]'

不带方括号时使用插件的默认值；[*] 启用所有已声明的特性，[] 不启用任何可选特性。

更新插件

更新行为取决于来源。

插件市场插件

刷新插件市场只更新其目录。升级是替换已安装插件代码的独立步骤：

omp plugin marketplace update marketplace-name
omp plugin upgrade --scope project plugin-name@marketplace-name

省略插件市场名称可刷新所有目录。在 omp plugin upgrade 中省略插件 ID 可升级所有已安装的插件市场插件：

omp plugin marketplace update
omp plugin upgrade

当某个插件市场插件在两个作用域中都存在时，省略 --scope 会升级两份副本。若某个条目失败，批量升级可能部分成功，因此请阅读每一条结果，并在之后运行 omp plugin list。

npm 和 Git 插件

对于 npm 或 Git 安装，没有通用的 omp plugin update 命令。请重新安装你打算运行的版本或引用：

omp plugin install '@scope/plugin@1.3.0'
omp plugin install 'github:org/repo#v1.5.0'

对于链接的本地插件，请自行更新其源码目录；符号链接无需重新安装。当可复现性重要时，请固定 npm 版本以及 Git 标签或提交。

移除插件

先预览移除，然后用 omp plugin list 显示的名称卸载：

omp plugin uninstall --dry-run @scope/plugin
omp plugin uninstall @scope/plugin

对于插件市场插件，请使用其完整 ID，并在必要时指定副本：

omp plugin uninstall --dry-run --scope project plugin-name@marketplace-name
omp plugin uninstall --scope project plugin-name@marketplace-name

卸载会移除该插件在所选作用域中的注册信息和已安装文件。移除插件市场目录则不同：它移除目录及其缓存，但不会卸载已经从它安装的插件。

omp plugin marketplace remove marketplace-name

移除可执行插件行为后，请重启 omp，或按下文所述重新加载活动会话。

重新加载活动会话

shell 命令会更改磁盘上的插件状态；它们不会重建已经在运行的 omp 进程。交互式插件市场变更还需要显式刷新。

运行：

/reload-plugins

这会刷新活动会话中的插件发现、技能、斜杠命令、代理定义、能力缓存和 MCP 连接。对于新安装或变更过的扩展模块、钩子或可执行自定义工具，请重启 omp，因为这些已初始化的运行时组件无法完全就地重建。有疑问时，重启。

检查健康状况与设置

如果某个插件已安装却不在 omp plugin list 中、加载失败，或指向已删除的本地路径，请先运行非破坏性的健康检查：

omp plugin doctor

阅读其检查结果后，可用 omp plugin doctor --fix 尝试修复。当另一个程序需要消费结果时，使用 --json。

插件可以声明带类型的设置。在设置某一项之前，先查看已声明的键：

omp plugin config list @scope/plugin
omp plugin config get @scope/plugin apiKey
omp plugin config set @scope/plugin apiKey value
omp plugin config delete @scope/plugin apiKey
omp plugin config validate

给 config list、get、set 或 delete 加上 -l 或 --local，可使用当前项目的设置覆盖。清单中标记为 secret 的设置会遮蔽其显示；这并不会把不受信任的插件变成可信代码。

信任清单

插件可以在 omp 的进程中运行扩展模块、在提示词和工具活动周围注册钩子、暴露可执行工具、启动 MCP/LSP/DAP 进程，并接收已配置的凭据。请把安装视为运行来自该来源的代码。

在安装或升级之前：

  1. 核实发布者、仓库，以及确切的 npm 版本、Git 引用或插件市场条目。
  2. 阅读扩展入口点、钩子、可执行工具/脚本，以及 MCP/LSP/DAP 配置。
  3. 审阅已安装版本与拟用版本之间的依赖和源码变更。
  4. 优先选用固定的 npm 版本、Git 标签、提交或插件市场版本。
  5. 在评估插件市场插件时，用项目作用域限制发现范围，但不要把它误当作沙箱。
  6. 禁用或卸载你不再信任的任何东西，然后重启 omp。

添加插件市场不会执行其中的插件，但目录决定了后续安装和升级从哪里获取代码。请同时信任目录维护者和每个插件来源。

插件、扩展与插件市场

术语它是什么用户如何管理它
插件可安装单元，能打包多个 omp 能力omp plugin install、list、disable、upgrade 和 uninstall
扩展向 omp 注册行为的运行时 TypeScript/JavaScript 代码为单个会话或从配置直接加载，或打包在插件中发布
插件市场为插件命名并指向其来源的目录omp plugin marketplace … 或 /marketplace …

插件不必包含扩展模块；它可以只包含技能或 MCP 配置这类声明式界面。反过来，你也可以直接加载扩展，而不把它作为受管理的插件安装。运行时 API 参见编写扩展。

面向插件作者

用户不应为了管理插件而理解清单文件。npm 或链接的 omp 包的作者在 package.json 的 omp 下列出运行时入口点（旧版的 pi 也被接受）：

{
  "name": "@acme/omp-review",
  "version": "1.0.0",
  "omp": {
    "extensions": ["./src/index.ts"]
  }
}

包也可以使用约定俗成的 skills/、commands/、hooks/、tools/、rules/、prompts/ 和 agents/ 目录，以及 .mcp.json 或 mcp.json。可选的 features 和带类型的 settings 属于 omp 清单，因为上面的管理命令会读取它们。公开扩展 API 参见编写扩展，目录清单参见插件市场。
