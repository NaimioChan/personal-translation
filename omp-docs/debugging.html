调试

让 omp 暂停一个真实的程序，检查它的实时状态，并解释它为什么与源码所暗示的行为不同。

用 omp 调试程序

当答案取决于运行时状态时使用调试器：某个值意外变化、某个分支只对一种输入成立、某个进程挂起，或多个线程相互干扰。omp 会说 Debug Adapter Protocol（DAP），因此它可以通过语言相关的调试适配器来启动或附加到程序、暂停它、检查栈帧与变量、单步执行并求值表达式。

最小的可用流程是：

  1. 为该语言安装适配器，并让其可执行文件对 omp 可用。
  2. 在项目目录中启动 omp。
  3. 用日常语言描述程序、停止点和你的问题。

例如，用 uv add --dev debugpy 安装 debugpy 之后：

Debug etl/transform.py with sample.csv. Break on line 58 when i == 3,
inspect the locals and running total, and explain where the bad value enters.

omp 会根据 .py 目标和 Python 项目标记选择 debugpy，启动脚本并驱动已暂停的进程。你不需要把请求翻译成 DAP 操作，也不需要自己管理栈帧标识符。

对于只需要读取定义、引用或类型的问题，请改用代码智能。调试会执行或附加到真实代码，并可能改变目标的状态。

哪些是自动完成的

调试器支持默认启用。可以在 shell 中确认该设置：

omp config get debug.enabled

对于启动操作，omp 只考虑已安装的适配器，然后用目标的文件扩展名和附近的项目标记（例如 pyproject.toml、go.mod、Cargo.toml、package.json 和 CMakeLists.txt）对它们排序。对于没有扩展名的原生可执行文件，它优先选择 GDB，然后是 LLDB。请求中点名的适配器会覆盖自动选择。

大多数内置启动配置会停在程序入口。这让 omp 有机会在继续执行之前安装你要求的断点。Go 还可以把包目录作为目标；其他适配器通常需要文件或可执行文件路径。

附加比启动更难自我描述。当可能存在歧义时，请指明适配器，并提供进程 ID 或目标暴露的主机与端口。

JavaScript 与 TypeScript

js-debug-adapter 是 omp 的适配器名称，不是 npm 包。不要运行 npm install -g js-debug-adapter。

下载 js-debug-dap-*.tar.gz 归档（来自 vscode-js-debug releases），并解压到服务器位于此处的位置：

~/.local/opt/js-debug/src/dapDebugServer.js

该路径会被自动发现。Neovim Mason 的安装也会在 $XDG_DATA_HOME/nvim/mason/packages/js-debug-adapter/js-debug/src/dapDebugServer.js（通常在 ~/.local/share 下）被发现。对于任何其他位置，请在启动 omp 之前导出该路径：

export JS_DEBUG_DAP_SERVER=/absolute/path/to/js-debug/src/dapDebugServer.js
omp

可用时 omp 用 node 运行该服务器，否则使用它的 Bun 宿主。

配置适配器

你通常不需要 DAP 配置文件。当适配器安装在 PATH 之外、其内置默认值与项目不匹配，或者你要添加 omp 尚不认识的适配器时，才需要添加一个。

项目特定配置使用 .omp/dap.json，个人默认值使用 ~/.omp/agent/dap.json。omp 启动目录下的 dap.json 优先级高于 .omp/dap.json。等价的 .dap.json、dap.yaml、.dap.yaml、dap.yml 和 .dap.yml 名称也被接受。所有适用文件中的适配器映射会被合并；工作区文件覆盖用户与插件的默认值。

覆盖内置适配器

覆盖项会与内置条目合并，所以只需写明要改的部分。下面这个项目级文件让 omp 使用项目的 Python 环境，同时保留 debugpy 的文件扩展名和根标记：

{
  "adapters": {
    "debugpy": {
      "command": ".venv/bin/python",
      "launchDefaults": {
        "justMyCode": true,
        "stopOnEntry": true
      }
    }
  }
}

像 .venv/bin/python 这样的相对命令会从调试工作目录解析。在 Windows 上，请使用适合该环境的解释器路径。

添加自定义适配器

自定义适配器需要一个命令，以及足够的匹配信息以供自动选择：

{
  "adapters": {
    "acme-jvm": {
      "command": "./tools/acme-debug-adapter",
      "args": ["--stdio"],
      "languages": ["java", "kotlin"],
      "fileTypes": [".java", ".kt", ".kts"],
      "rootMarkers": ["pom.xml", "build.gradle", "build.gradle.kts"],
      "launchDefaults": {
        "request": "launch",
        "stopOnEntry": true,
        "projectRoot": "."
      },
      "attachDefaults": {
        "request": "attach",
        "host": "127.0.0.1"
      }
    }
  }
}

launchDefaults 和 attachDefaults 是适配器特定的 DAP 参数。它们适合放置无法从提示词推断的设置，例如 JVM 主类、source map、justMyCode 或适配器特定的附加模式。运行时，你请求中的程序路径、工作目录、程序参数、PID、主机和端口优先于这些默认值。

让 omp 启动或附加

给 omp 具体的路径，并描述你想要的证据。启动目标是路径，不是 shell 命令；如有必要，请先让 omp 构建该目标。

Launch build/server with --config test/fixtures/dev.toml. Stop in parseConfig,
then show me the arguments and the first caller that supplied an empty path.

Debug the Go package in ./cmd/worker. Break when retryCount reaches 5 and
compare the current job with the previous stack frame.

Use lldb-dap to launch ./build/repro with arguments --seed 417. Stop at main,
then continue until decode_packet and inspect the packet header.

要附加到本地进程，请提供它的 PID：

Attach lldb-dap to PID 48120. Pause it, show all threads, and identify which
thread is holding the process in shutdown.

对于调试服务器，请同时提供端点和适配器：

Use debugpy to attach to 127.0.0.1:5678. When the request handler is reached,
inspect request.user and explain why authorization fails.

一个 omp 会话中只能有一个根调试会话处于活动状态。在启动或附加到其他目标之前，请让 omp 结束当前的调试会话。

暂停时你能看到什么

调试活动在对话记录中以 Debug 块显示。成功启动或附加后，该块会标明所选的适配器、状态、工作目录和程序。当执行暂停时，它还会显示停止原因、当前栈帧和源码位置，例如：

Adapter: debugpy
Status: stopped
Stop reason: breakpoint
Frame: transform_row
Location: /workspace/etl/transform.py:58:9

之后 omp 可以在单步或继续之前检查栈、线程、作用域、局部变量、嵌套值、目标输出和受支持的表达式。如果目标在请求超时内没有暂停，对话记录会说明它仍在运行；这不会被报告为崩溃。请让 omp 暂停它，或设置一个可达的断点并继续。

被暂停的进程确实处于暂停状态。在继续或终止之前，它可能停止处理请求或持有锁。在某些适配器中，表达式求值也可能调用代码或改变状态，所以当这一区别很重要时，请说“只检查，不求值表达式”。

故障排查

调试不可用

检查该功能开关，必要时启用它：

omp config get debug.enabled
omp config set debug.enabled true

更改启用的工具后，请启动一个新的 omp 会话。

omp 提示适配器不可用

在启动 omp 的同一个 shell 中验证该可执行文件。如果它安装在别处，请在启动 omp 前更新 PATH，或在 dap.json 中设置绝对 command。对于 debugpy，模块不存在时 python 也可能存在；请这样验证：

python -m debugpy --version

对于 JavaScript，请验证 JS_DEBUG_DAP_SERVER 或某个自动的 dapDebugServer.js 位置，而不是去找 js-debug-adapter 可执行文件。

选错了适配器

在请求中点名适配器。若要长期修复，请在项目 DAP 配置中更正它的 fileTypes 和 rootMarkers。文件扩展名应包含前导点，并按小写匹配。

目标路径被拒绝

请传入源文件或可执行文件路径，而不是把命令和标志写在一个字符串里。把程序参数单独放进请求中。目录目标需要适配器支持 acceptsDirectoryProgram: true；内置的 Delve 配置为 Go 包启用了这一点。

断点处于待定状态或从未命中

检查源码路径和行号是否属于目标实际加载的代码。用调试符号重新构建编译后的代码，如果单步行为误导请关闭优化，并验证生成的 JavaScript 的 source map 设置。条件表达式必须使用目标语言，并得到该适配器的支持。

附加失败

确认 PID 仍然存活，或主机与端口可达。然后明确点名预期的适配器。某些适配器需要额外字段，例如进程选择器或模式；请把这些适配器特定的值放进 attachDefaults。

omp 报告存在另一个活动会话

让它终止现有的调试会话，然后重试。启动或附加失败会被自动清理，但运行中或已暂停的会话会一直处于活动状态，直到调试工作结束。

DAP 适配器配置参考

字段必需含义
command是可执行文件名称或路径。相对路径从调试工作目录解析。
args否传给适配器进程的参数，而不是传给被调试程序的参数。
languages否与该适配器关联的语言元数据。
fileTypes否用于启动选择的小写扩展名，包含前导点。
rootMarkers否用于识别并排序匹配项目的文件或目录。
launchDefaults否适配器特定的参数，会在每次启动时于所请求的程序、工作目录和程序参数之前合并进去。
attachDefaults否适配器特定的参数，会在每次附加时于所请求的 PID、主机和端口之前合并进去。对于进程启动时已经附加的适配器，可以使用 skipAttachRequest: true。
connectMode否默认为 stdio；Delve 风格的适配器用 socket；本地 DAP 服务器用 tcp。在 tcp 模式下，args 中的 ${port} 会被替换为分配的端口。
acceptsDirectoryProgram否当适配器可以启动包或项目目录而不是文件时，设为 true。

外层的 adapters 对象是可选的：配置文件也可以直接包含适配器映射。没有可用 command 的无效新条目会被忽略；无效的部分覆盖不会抹掉它本要修改的内置适配器。
