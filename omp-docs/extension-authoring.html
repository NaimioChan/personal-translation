编写扩展

构建一个 TypeScript 或 JavaScript 包，用它添加工具、斜杠命令、事件行为以及其他 omp 能力，然后在本地加载它，或作为插件分发。

构建你的第一个扩展

扩展是一个 TypeScript 或 JavaScript 模块，omp 会把它加载进会话进程。当某项能力需要可执行行为时就用它：模型可以使用的工具、面向用户的斜杠命令、围绕工具调用的策略、自定义 UI，或者提供商集成。

可分发的扩展包还可以捆绑声明式能力，例如技能、提示词模板、规则、钩子、自定义工具和 MCP 服务器配置。扩展工厂与这些同级文件夹会一起被发现，所以用户只需安装一个包。

从两个文件开始。omp 直接运行 TypeScript，因此构建步骤是可选的。

hello-extension/
├── package.json
└── src/
    └── index.ts

{
  "name": "hello-extension",
  "version": "1.0.0",
  "type": "module",
  "files": ["src"],
  "omp": {
    "extensions": ["./src/index.ts"]
  }
}

omp.extensions 是一个数组，每个条目都相对于包的根目录。已安装插件的条目可以是 .ts、.js、.mjs 或 .cjs。较旧的 pi.extensions 字段仍然兼容，但新包应使用 omp.extensions。

把 omp 的包安装为开发依赖，以获得当前的 TypeScript 类型和编辑器补全：

cd hello-extension
bun add --dev @oh-my-pi/pi-coding-agent

现在创建 src/index.ts：

import type { ExtensionAPI } from "@oh-my-pi/pi-coding-agent";

export default function helloExtension(pi: ExtensionAPI) {
  const z = pi.zod;

  pi.on("session_start", (_event, ctx) => {
    ctx.ui.notify("hello-extension loaded", "info");
  });

  pi.registerCommand("hello", {
    description: "Greet someone",
    handler: async (args, ctx) => {
      const name = args.trim() || "there";
      ctx.ui.notify(`Hello, ${name}!`, "info");
    },
  });

  pi.registerTool({
    name: "greet_person",
    label: "Greet Person",
    description: "Create a short greeting for a person",
    parameters: z.object({
      name: z.string().describe("Person to greet"),
    }),
    approval: "read",
    async execute(_toolCallId, params) {
      return {
        content: [{ type: "text", text: `Hello, ${params.name}!` }],
        details: { name: params.name },
      };
    },
  });
}

默认导出就是公开的工厂契约：

export type ExtensionFactory = (
  pi: ExtensionAPI,
) => void | Promise<void>;

在工厂内部注册命令、工具、处理器、渲染器、标志和提供商。像 pi.sendMessage() 这样的运行时操作在工厂加载期间不可用；请稍后从事件处理器、命令处理器或工具执行中调用它们。

加载并测试它

在包含 hello-extension 的目录中，启动一个一次性开发会话：

omp --extension ./hello-extension
# -e is the short form

在 TUI 中：

  1. hello-extension loaded 通知确认工厂已运行。
  2. 输入 /hello Ada 测试面向用户的命令。
  3. 输入 “Use the greeting tool to greet Ada.”，通过普通提示词试用该工具。
  4. 打开 /extensions 查看发现到的能力条目及其启用状态。

扩展工厂在会话启动时初始化。修改 src/index.ts 后，请退出并启动新会话以加载新代码。

在开发期间保持启用

把该包链接进你的用户插件集合：

omp plugin link ./hello-extension
# Equivalent for a local path:
omp install ./hello-extension

本地安装是一个符号链接，所以下次 omp 启动时改动就在那里；它不会热重载正在运行的扩展工厂。用 omp plugin list 确认链接，用 omp plugin doctor 检查已安装插件的健康状况。

对于不想安装的包，改为把它的绝对路径加入用户配置：

# ~/.omp/agent/config.yml
extensions:
  - /absolute/path/to/hello-extension

配置中的相对路径是从 omp 启动的目录解析的，而不是从配置文件所在目录。项目专属配置应放在 <project>/.omp/config.yml。松散模块也可以直接放进 <project>/.omp/extensions/ 或 ~/.omp/agent/extensions/；自动目录扫描会发现 .ts 和 .js 文件，以及一层 index.ts 或 index.js 子目录。

捆绑更多能力

通过 --extension、extensions: 或插件管理器加载的包根目录，可以包含这些约定路径：

hello-extension/
├── package.json
├── src/index.ts
├── skills/release-notes/SKILL.md
├── commands/release.md
├── rules/commit-policy.md
├── prompts/review.md
├── hooks/
│   ├── pre/block-dangerous.ts
│   └── post/audit.ts
├── tools/
│   └── changelog/index.ts
└── .mcp.json
路径omp 会发现什么
skills/<name>/SKILL.md按需加载的技能
commands/*.md用户斜杠命令
rules/*.{md,mdc}项目或工作流规则
prompts/*.md提示词模板
hooks/pre/*, hooks/post/*工具调用前与调用后的钩子
tools/*以受支持的脚本、Markdown、JSON、TS 或 JS 格式编写的自定义工具
.mcp.json 或 mcp.jsonMCP 服务器定义

这些文件夹无需在 package.json 中声明任何字段。发布时请把它们加入包的 files 列表。各文件格式见技能、钩子、自定义工具和 MCP。

一个包可以暴露多个运行时工厂：

{
  "omp": {
    "extensions": ["./src/policy.ts", "./src/tools.ts"]
  }
}

只有当它们确实彼此独立时才使用多个条目。单个工厂就能注册全部公开扩展接口。

打包并分发

扩展运行时拥有与 omp 相同的文件系统、网络、环境和进程权限。它们不在沙箱中。请保持包可审计、避免不必要的依赖，并告知用户它需要哪些外部访问。

发布到 npm

确保 files 包含每个工厂和捆绑的能力目录，然后在发布前检查 tarball：

npm pack --dry-run
npm publish

用户按 npm 名称安装已发布的包：

omp install @acme/hello-extension

包管理器会安装其依赖，并从已发布的 package.json 中读取 omp.extensions。安装或升级扩展模块后，请启动新的 omp 会话。

从 Git 安装

公开仓库无需插件市场即可安装：

omp install github:acme/hello-extension#v1.0.0

为获得可复现的安装，请使用不可变的标签或提交。

通过插件市场发布

插件市场是一个包含 .omp-plugin/marketplace.json 的 Git 仓库。.claude-plugin/marketplace.json 是兼容 Claude Code 的回退位置。一个最小仓库可以把扩展放在 plugins/hello-extension/，并使用这样的目录清单：

{
  "name": "acme-extensions",
  "owner": { "name": "Acme" },
  "plugins": [
    {
      "name": "hello-extension",
      "description": "A greeting command and tool",
      "version": "1.0.0",
      "source": "./plugins/hello-extension",
      "category": "productivity"
    }
  ]
}

推送仓库后，用户运行：

omp plugin marketplace add acme/omp-extensions
omp plugin install hello-extension@acme-extensions

发布更新时，请给仓库打标签，按需更新目录清单中的版本与源固定信息，并让用户先运行 omp plugin marketplace update，再运行 omp plugin upgrade hello-extension@acme-extensions。目录清单的源格式、固定方式、作用域与更新行为见插件市场，安装与功能管理见插件。

公开扩展接口

已安装的 @oh-my-pi/pi-coding-agent 的 TypeScript 声明是签名规范的权威参考。从包根导入公开类型：

import type {
  ExtensionAPI,
  ExtensionContext,
  ExtensionCommandContext,
  ExtensionFactory,
  ToolDefinition,
} from "@oh-my-pi/pi-coding-agent";

ExtensionAPI

接口面公开成员
Schema 与宿主访问zod, arktype, typebox, logger, pi
事件on(event, handler)、共享的 events 总线
注册registerTool, registerCommand, registerShortcut, registerFlag, registerMessageRenderer, registerAssistantThinkingRenderer, registerComposerShape
提供商集成registerProvider, unregisterProvider
宿主文件系统回退registerFileWriteFallback, registerFileDeleteFallback

新的工具 schema 请使用 pi.zod 或 pi.arktype。pi.typebox 是为了兼容旧扩展而存在。

命令、快捷键与标志

pi.registerCommand("deploy", {
  description: "Deploy the current project",
  getArgumentCompletions: (prefix) => [
    { value: "staging", label: "staging" },
    { value: "production", label: "production" },
  ].filter((item) => item.value.startsWith(prefix)),
  handler: async (args, ctx) => {
    // args is the text after /deploy
  },
});

pi.registerShortcut("ctrl+shift+d", {
  description: "Open deployment controls",
  handler: async (ctx) => {
    ctx.ui.notify("Deployment controls", "info");
  },
});

pi.registerFlag("deployment-target", {
  description: "Default deployment target",
  type: "string",
  default: "staging",
});

命令名不得与内置斜杠命令冲突。快捷键使用快捷键中描述的同一套 ID；保留的终端组合键和核心组合键无法被替换。用 pi.getFlag("deployment-target") 读取已注册的标志。

工具

一个 ToolDefinition 需要 name、label、description、parameters，以及一个异步的 execute 函数。完整的可选接口面如下：

字段用途
hidden除非显式选中，否则排除该工具
defaultInactive注册它但初始不激活
loadMode默认是 "discoverable"；用 "essential" 让它保持在顶层
approval"read"、"write" 或 "exec"；默认为 "exec"
deferrable允许需要确认或丢弃的分阶段改动
strict选择加入或退出提供商的结构化输出语法
onSession在启动、切换、分叉、树导航或关闭时初始化或清理状态
renderCall, renderResult为自定义呈现提供 TUI 组件
mcpServerName, mcpToolName当该工具包装 MCP 时添加发现元数据

execute(toolCallId, params, signal, onUpdate, ctx) 返回一个代理工具结果，其中包含 content 数组和可选的带类型 details。请尊重 signal 以支持取消，并用 onUpdate 汇报有意义的流式进度。

运行时与命令上下文

每个事件处理器和工具都会收到 ExtensionContext。命令处理器会收到更大的 ExtensionCommandContext。

ExtensionContext 成员用途
cwd, mode, hasUI, ui当前目录与用户界面接口面
model, models, modelRegistry当前模型，以及只读的模型发现/解析
sessionManager只读的会话访问
getContextUsage(), getAsyncJobSnapshot()当前上下文与后台任务快照
isIdle(), hasPendingMessages(), abort(), shutdown()会话状态与生命周期控制
compact(), getSystemPrompt()上下文操作
memory已配置的结构化记忆运行时（如果可用）
setInterval, setTimeout, clearTimer受管理的后台回调
invokeTool替换同一个内置工具时，委托给原生实现
localProtocolOptions调用会话的本地协议映射（如果存在）
isProjectTrusted()兼容性检查；omp 目前信任已加载的项目输入

命令处理器还会额外收到 waitForIdle()、newSession()、switchSession()、branch()、navigateTree() 和 reload()。

ctx.ui 包含通知、选择/确认/输入对话框、编辑器访问、状态与小组件、页眉/页脚控制、主题、自定义 TUI 组件，以及自动补全注册。在依赖仅交互式可用的行为之前，请检查 ctx.hasUI 或 ctx.mode === "tui"；print 和 RPC 会话没有交互式终端。

请使用 ctx.setInterval() 和 ctx.setTimeout()，而不是裸定时器。受管理的回调会捕获抛出的错误、不会让进程保持存活，并在会话关闭时被清除。

用 pi.on(name, handler) 订阅。事件对象与允许的返回值会由事件名推断出来。

前置事件可以取消或替换其文档中说明的操作，tool_call 可以阻止一次调用，tool_result 可以替换其结果。请让 TypeScript 来约束确切的返回形状，而不是返回本属于其他事件的字段。

故障排查

包没有加载

  • 确认每个 omp.extensions 路径都存在，且相对于 package.json。
  • 确认入口默认导出的是一个函数，而不是一个已经创建好的对象。
  • 运行 omp --extension /absolute/path/to/package，以排除配置与工作目录的歧义。
  • 查看 /extensions 以及 ~/.omp/logs/ 下的结构化日志，了解该能力的发现状态。运行时工厂的导入错误会在 ~/.omp/logs/ 下的结构化日志中包含失败的路径。
  • 如果扩展导入了运行时依赖，请在加载它之前运行包管理器，并在 dependencies 中声明这些依赖，而不只是写在 devDependencies 里。

一个扩展失败不会阻止其他扩展路径加载。

它能加载，但某项能力缺失

  • 更改扩展工厂或安装包之后，重启 omp。
  • 确保捆绑的文件夹位于包根目录、与 package.json 同级，并且已包含在发布的 tarball 中。
  • 对于有变化的技能、斜杠命令和 MCP 服务器，使用 /reload-plugins。工具、钩子和扩展模块需要新会话。
  • 检查该项是否在 /extensions 中被禁用，或是否被配置中的 disabledExtensions 禁用。运行时工厂的 ID 是 extension-module:<filename>；index.ts 条目使用其父目录名。

在 TUI 之外它崩溃或行为不同

扩展在进程内运行且没有沙箱。请捕获你自己分离的 promise 中的失败，使用受管理的上下文定时器，遵守中止信号，并在 session_shutdown 时释放资源。用 ctx.mode === "tui" 保护自定义终端 UI，并在扩展也必须能在 print、RPC 或 ACP 会话中工作时提供非交互行为。
