交接

将漫长的工作会话变成聚焦的延续简报，同时留在当前会话中。

当对话积累了过多历史时，交接会为omp提供干净、面向任务的上下文。它会总结已完成的工作、重要决策和下一步行动，然后将该摘要压缩到当前会话中。

当你希望下一轮次从明确的检查点继续时运行：

/handoff

omp准备交接时，状态行显示Generating handoff… (esc to cancel)。成功后，对话会围绕handed-off分隔线重建，omp报告Context handed off and compacted in place。

尽管名称如此，/handoff不会创建、分叉或切换到另一个会话。你的会话ID、名称、分支和已保存的会话都保持不变。

交接还是压缩？

两个命令都会在原地减少模型的活动上下文，并保留对话最近的一段内容。根据你希望替代上下文强调的内容来选择。

选择适用需求结果
/handoff聚焦工作的延续简报：目标、进展、决策、约束和后续步骤omp生成该简报，将其用作较早上下文的摘要，并将此处标记为handed-off
/compact一般上下文缩减，或控制压缩方法，例如soft、remote或snapcompactomp使用选定的压缩方法，并标记相应的压缩点
两者都不选当前上下文仍然有用，且距离模型限制还有充足余量继续工作；自动上下文维护默认已启用

在改变工作阶段、长时间暂停后返回，或要保留精确的实现或调试检查点之前，使用/handoff。当优先事项只是释放上下文时，使用/compact。如果你确实需要单独的会话，请使用会话中介绍的会话控制。

聚焦延续内容

在命令后添加自然语言重点说明：

/handoff Focus on the migration plan, decisions already made, and callers that still need updating.

重点说明会改变简报强调的内容；它不会变成新的用户任务，也不会创建新会话。没有重点说明时，omp会从对话中选择重要的延续细节。

好的重点说明会指出必须在缩减后保留的工作：

/handoff Preserve the test failure, hypotheses ruled out, and the next two debugging steps.

/handoff Emphasize the approved API shape and unresolved compatibility risk.

运行命令前请等待当前响应完成。如果需要停止该响应，请先中止，然后输入/handoff。

屏幕上会发生什么变化

成功交接会改变后续模型轮次所使用的上下文：

  • 较早上下文会被生成的交接简报替换。
  • 最近消息保持原样。保留量由compaction.keepRecentTokens控制，默认值为20000。
  • 待办事项和其他实时会话界面会刷新。
  • 同一会话继续进行；不需要恢复或加载步骤。

默认情况下，交接前的历史会从实时对话记录中折叠，最近部分会出现在类似以下内容的分隔线之后：

──────── handed-off · 180K→24K · ctrl+o ────────

按Ctrl+O展开分隔线并阅读生成的简报。如果希望在压缩分隔线周围保留完整的已保存对话记录行内显示，请设置display.collapseCompacted: false。折叠影响显示，不影响持久化的会话历史。

你的下一条提示词可以立即继续工作：

Continue with the first remaining migration caller.

取消或从失败中恢复

按Esc取消（当Generating handoff…可见时）。omp显示Handoff cancelled，保持当前上下文不变，并让你留在同一会话中。

其他前置条件和错误同样不会造成破坏：

消息含义和下一步
Wait for the current response to finish or abort it before handing off.等待响应完成，或中止响应，然后重试。
Nothing to hand off (no messages yet)可供总结的消息少于两条。先继续对话。
Nothing to hand off (already compacted)没有剩余的较早上下文可供替换。继续工作后再试。
Compaction already in progress等待当前自动或手动压缩完成。
Handoff failed: No model selected for handoff选择模型，然后重试。
Handoff failed: No API key for …验证当前提供商身份，然后重试。
Handoff failed: …提供商或生成过程失败。原始上下文仍处于活动状态；解决报告的错误后重试。

生成的简报为空会被视为失败，而不是取消。omp会自动重试暂时性的提供商失败，但如果最终尝试失败，它会显示实际错误，不会提交不完整的交接。

自动交接

手动/handoff始终请求交接工作流；它不依赖是否启用自动压缩，也不依赖compaction.methodOrder。

要自动使用，请启用压缩，并将handoff放在有序回退列表的前面。默认顺序是：

remote → snapcompact → handoff → shake → soft

这意味着其他可用方法可能会先于交接运行。如果自动交接无法运行或失败，omp会尝试下一个已配置的方法。当输入已经溢出模型上下文时，omp通常会跳过发起新的交接请求，因为同样过大的输入无法被总结；不过，已经准备好的推测性交接仍可能被应用。

打开/settings并使用Context → Compaction，或在config.yml中添加全局或项目覆盖配置：

compaction:
  enabled: true
  methodOrder: [handoff, remote, snapcompact, shake, soft]
  handoffSaveToDisk: true

handoffSaveToDisk会在持久化会话的工件目录中添加带时间戳的handoff-*.md文件，仅限自动交接。手动/handoff会将结果存储为会话的压缩摘要，但不会写入额外的Markdown文件。

相关设置

设置默认值作用
compaction.enabledtrue启用自动上下文维护。它不会禁用手动/handoff。
compaction.methodOrder[remote, snapcompact, handoff, shake, soft]选择并排列自动维护方法。将handoff放在第一位即可优先使用它。
compaction.keepRecentTokens20000交接或压缩后按原文保留的最近上下文近似数量。
compaction.thresholdPercent-1自动维护阈值的百分比；-1使用基于预留量的默认值。
compaction.thresholdTokens-1自动维护的固定token限制；非默认值会覆盖百分比。
compaction.asyncEnabledtrue可以在阈值前不久准备由LLM支持的摘要，包括交接，以便快速应用。
compaction.handoffSaveToDiskfalse仅在持久化会话中为自动交接写入额外的Markdown工件。
display.collapseCompactedtrue在实时TUI中折叠被替换的历史；关闭它可保留完整对话记录的行内显示。

关于配置位置、作用域和优先级，请参阅设置。
