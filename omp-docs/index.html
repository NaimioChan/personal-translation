概览

把一个真实的软件任务带进你的终端。omp 可以检查仓库、修改代码、运行你的开发工具，并把工作保存在一个可恢复的会话里。

从一个真实任务开始

omp 是一个终端优先的编码代理，面向那些无法靠粘贴一段代码完成的工作。在项目里运行它，描述你想要的结果，它就能调查代码库、编辑文件、运行命令并解释结果，不必让你在编辑器、shell 和聊天窗口之间来回搬运上下文。

如果你是第一次使用，请从快速上手开始。它介绍了安装和提供商认证。然后打开一个项目并启动交互式会话：

cd path/to/your-project
omp

用日常语言给它一个具体的任务：

Find why the user-session test hangs, fix the root cause, run the smallest relevant test, and explain what changed.

omp 会流式输出它的响应，并以紧凑的卡片展示文件操作、命令和其他工作。按 Ctrl+O 展开卡片，查看它的完整输出或 diff。你可以继续追问、纠正方向，或按 Escape 停止当前轮次。

一个好的首个任务应该有明确的目标和验证方式。如果你只想要一个解释，就说“investigate, but do not edit”。对于庞大或有风险的改动，先进入计划模式，这样你能在动手实现前审阅方案。

为什么用 omp

软件工作很少止步于生成代码。一次有用的改动可能需要找到正确的文件、理解既有约定、安全地重命名符号、运行一个针对性的测试、检查正在运行的进程，或者核对一个拉取请求。omp 把这一整套循环放在同一个会话里，并使用你机器上已有的仓库和开发环境。

它很适合这样的开发者：

  • 更愿意在终端里指挥和审查工作；
  • 在既有的仓库里工作，上下文和验证都至关重要；
  • 想自己选择模型提供商，而不是被绑定在某一家上；
  • 今天需要一个简短的调查，明天需要一个可恢复、多步骤的改动；或者
  • 想要一套能从单个代理成长为计划、并行工作和共享会话的工作流。

omp 可以在你的环境中修改文件并运行命令，所以请像审查同事的改动那样审查它的工作，并在敏感项目中使用审批控制。提示词和相关上下文会发送给你选择的模型提供商；集成也可能联系它们各自对应的服务。

作为用户你会注意到什么

从请求到验证的同一个循环

提出你想要的结果，而不是把代码复制进浏览器。当任务需要时，omp 可以组合仓库搜索、编辑、命令、语言感知的代码智能、实时调试、浏览器操作和GitHub 上下文。它的工作始终在会话中可见。

由你选择模型

连接 API 密钥、OAuth、订阅、网关或本地提供商，然后为日常工作、快速任务、深度推理和规划分别选择模型。先从模型提供商开始；想调整路由或行为时使用设置。

可以离开再回来的工作

会话默认保存在本地。恢复以前的工作，在你想尝试不同方向又不想丢弃历史时分叉，或者当别人需要上下文时共享会话。用户侧的操作见会话。

先规划再实现

运行 /plan 进入一个单独的规划轮次，完善方案，并决定何时执行它。这适用于迁移、架构调整，以及操作顺序很重要的工作。见计划模式。

任务确实可以拆分时并行推进

让 omp 把任务中相互独立的部分委派给子代理，比如同时审计多个包。你可以在它们工作时观察进度并进行引导。见子代理与 Agent Hub。

一套可以扩展的工作流

项目规则和技能能让 omp 了解你的团队如何工作。内置能力不够时，扩展和MCP 服务器可以添加公共集成。

一条实用的学习路径

  1. 先让一条提示词跑通：快速上手涵盖安装、认证、终端配置和你的第一个会话。
  2. 学会交互操作：使用 omp介绍界面、编辑器、消息队列和单次执行模式。
  3. 保留有用的工作：会话涵盖恢复、分支、分叉、导出和共享。
  4. 按你的目标选择下一篇指南：
你想要……前往……
高效地控制正在运行的会话斜杠命令和快捷键
连接或更换模型模型提供商和设置
在动代码之前设计一个大型改动计划模式
调查符号、诊断或正在运行的进程代码智能和调试
拆分独立的工作或共享一个实时会话子代理与 Agent Hub和协作
在脚本或其他程序中使用 omp命令行参考、RPC 模式或SDK
添加团队指令或集成技能、MCP和编写扩展

不确定该走哪条路？完成快速上手，在一个你熟悉的仓库里跑一个小任务，然后继续看使用 omp。
