计划模式

在不修改项目的前提下探索一项改动，审阅提议的做法，然后精确选择 omp 应如何把它交给实现模型。

在 omp 动手之前先做计划

当难点在于决定改什么时，请使用计划模式：跨文件重构、陌生的代码库、带顺序约束的迁移，或是一份你想在实现前先审阅的设计。规划期间，omp 可以检查项目并验证假设，但它的规划轮次对你的工作树和系统是只读的。草稿会作为会话产物保留；未获批准就离开不会应用它。

从目标和那些会改变设计的约束开始：

/plan Replace the in-memory job queue with Postgres. Preserve the public API, include a rollback path, and call out every migration step.

你也可以不带提示词直接输入 /plan，或按默认的 Alt+Shift+P 组合键，然后输入你的请求。状态行会显示 Plan，omp 切换到配置的 plan 模型，下一轮会去探索并起草，而不是直接实现。

对于很小、已经很清楚的编辑，普通模式更快。规划会在执行开始前多消耗一个模型轮次和一部分上下文。

从请求到经过审阅的计划

  1. 描述结果。包含不可妥协的行为、相关的文件或系统，以及你将如何判断成功。
  2. 让 omp 去调查。它会阅读代码和其他可用来源，检查假设，并在不修改项目的情况下构建一份 Markdown 计划。
  3. 审阅草稿。计划就绪后，omp 会打开全屏的 Plan Review 界面。你也可以随时用 /plan-review 重新打开最新的草稿。
  4. 改进或批准。添加反馈、删除不需要的章节，或选择实现应如何继承这段规划对话。

有用的后续消息应当具体而非笼统：

Keep the database schema, but revise the rollout so old and new workers can run together for one deploy.

审阅与批准选项

批准选项同时控制执行和上下文。它不会改变已批准计划的内容。

选项会发生什么适用场景
批准并执行退出计划模式，开启一个全新会话，并把已批准的计划交给实现模型。先前的对话记录（包括规划讨论）不会带入新的上下文。计划本身是自包含的，或者你希望为实现留出最大的上下文空间。
批准并压缩上下文退出计划模式，把当前对话压缩成一份聚焦已批准计划的摘要，然后在当前会话中实现。部分探索过程有意义，但完整对话记录过于昂贵或会分散注意力。
批准并保留上下文退出计划模式，在完整保留规划对话的情况下于当前会话中实现。该选项会显示相对执行模型上下文窗口的大致用量。决策依赖那些没能写进计划的细节。
改进计划把你的审阅批注作为一次规划轮次发回。如果你没有添加批注，浮层会关闭，omp 会提示你输入一条后续消息。不会执行任何操作。做法、顺序或范围仍需要调整。
保存并退出提示输入目标位置，把计划写入那里，退出计划模式，并启动一个新的空白会话而不执行它。相对路径从当前工作目录解析。你想要一份可留存的计划，供之后的会话、审阅或交接使用。

仅当用量已超过执行模型上下文窗口的 95% 时，批准并保留上下文才不可用。此时请改选压缩上下文或全新执行。如果会话没有可用的上下文估算，该选项仍然可用，但不显示用量数字。

批准后会立即开始实现。如果会话还没有名字，omp 会从计划标题推导一个；你自己设置的名字会被保留。

选择实现模型

当至少有两个已配置的模型角色可用时，Plan Review 会在选项上方显示一个 continue with 选择器。它初始停在 default 角色。在操作区获得焦点时，用 Left/Right 在批准前选择另一个角色。此选择控制的是实现，而不是产出草稿的规划模型。

如果只解析出一个模型角色，选择器会隐藏，omp 会恢复进入计划模式之前活动的模型。

在 Plan Review 中操作

页脚始终显示当前聚焦区域中可用的操作。

操作结果
Up/Down, Enter选择并确认一项操作。
Tab / Shift+Tab在目录、计划正文和操作之间移动。
Page Up/Page Down, g/G在长计划中移动，或跳到其开头/结尾。
a为聚焦的章节或可见的计划行添加批注；这些批注会成为改进反馈。
d / Delete删除目录侧边栏中选中的章节。
u撤销最近一次章节编辑或批注。
c把当前计划复制到剪贴板。
你的外部编辑器快捷键在 $VISUAL 或 $EDITOR 中编辑计划。
Escape关闭审阅界面，但不批准也不离开计划模式。

只有在终端足够宽、且计划至少有两个标题时，目录侧边栏才会出现。因此在窄终端中，章节删除和章节级批注操作可能不可见；你仍然可以用普通的后续提示词来改进，或使用外部编辑器。

章节删除、撤销和外部编辑器的改动会随着你的操作更新会话草稿。Escape 只是关闭浮层，不会回滚这些编辑。运行 /plan-review 可以重新调出最新的计划草稿。查看快捷键以检查或修改计划开关和外部编辑器的组合键。

暂停、恢复或离开

/plan 是一个有状态的开关：

  1. 计划模式处于活动状态时，再次运行 /plan 即可不批准就离开。如果存在非空草稿，omp 会要求你确认。状态变为 Plan paused，普通工具和进入计划模式前的模型被恢复，不会执行任何操作。
  2. 暂停期间，运行 /plan <follow-up> 可重新进入计划模式并立即提交这条后续消息。
  3. 暂停期间，再次不带提示词运行 /plan，可完全关闭计划模式并清除暂停状态。

在 Plan Review 中按 Escape 则不同：它只关闭审阅界面。计划模式仍然活动，因此你可以继续讨论草稿，或用 /plan-review 重新打开它。

计划模式不能与目标模式或 Vibe 模式同时运行。进入计划模式前，请先退出处于活动或暂停状态的冲突模式。

规划模型与设置

计划模式默认启用，但不会自动启动。进入时它会把会话临时切换到 plan 角色，包括该角色配置的思考强度；离开时会恢复先前的模型，除非你在 Plan Review 中选择了实现角色。

在 config.yml 中的最小持久化配置是：

plan:
  enabled: true
  defaultOnStartup: false

modelRoles:
  plan: anthropic/claude-opus-4-5:high
设置或覆盖用途默认值
plan.enabled使 /plan 和计划模式可用。true
plan.defaultOnStartup让每个全新的交互式会话在计划模式下打开。已有的/恢复的对话不会被强制进入。false
modelRoles.plan规划时使用的持久模型和可选思考强度。未设置；omp 保持当前模型
omp --plan <model-id>为本次启动选择 plan 角色的模型。它不会进入计划模式；启动后请使用 /plan。—
PI_PLAN_MODEL=<model-id>为当前进程选择 plan 角色的模型。--plan 优先。—
cycleOrder 与 modelRoles决定审阅时 continue with 选择器提供的角色模型。smol, default, slow

如果在计划模式活动期间更改 plan 角色，omp 会在下一个安全的轮次边界应用新的角色模型。

限制与故障排查

  • Plan mode is disabled — 在当前生效的设置作用域中设置 plan.enabled: true，然后再次运行 /plan。
  • Exit goal mode first 或 Exit vibe mode first — 这些模式互斥。处于暂停状态的计划也必须完全关闭后才能进入目标模式。
  • No plan to review yet — 规划轮次还没有产出草稿。让 omp 完成计划，然后使用 /plan-review。
  • 保留上下文选项变灰 — 对话已超过执行模型上下文窗口的 95%。请改用压缩上下文或全新执行。
  • 批准后压缩被取消 — omp 会保留计划的批准状态，但不派发实现。再提交一个轮次即可从已批准的计划继续。
  • 外部编辑器没有打开 — 设置 $VISUAL 或 $EDITOR；否则就在 omp 中使用批注和后续提示词。
  • 启动时的计划模式在 --print 或 JSON 输出中不会激活 — plan.defaultOnStartup 仅适用于交互式运行，因为无头运行没有审阅界面。--plan-yolo 是单独的无头流程；它会自动批准，因此有意跳过上面记录的所有人工审阅选项。
  • 规划对 omp 是只读的，对你不是 — 你自己运行的 shell 命令仍然可以改变文件或系统状态。
