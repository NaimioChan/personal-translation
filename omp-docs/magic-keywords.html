魔法关键词

用一个精确的独立单词，让单条提示词转向更深入的推理，或转向协同的并行工作。

魔法关键词是可选的、仅作用于单轮的捷径。当你想让 omp 改变处理该提示词的方式，而不开启某个持久模式时，就在普通提示词中放一个被识别的独立单词。

先想清楚你需要什么行为：

ultrathink about the failure modes before changing this public API

orchestrate the migration across the server, client, and tests

workflowz perform an adversarial review of authentication, authorization, and session handling

这个词仍然是你可见消息的一部分。在终端编辑器中，输入框获得焦点时，omp 会用流动的渐变绘制被识别到的词；发送出去的消息则使用静态渐变。这只是一种识别辅助，并不确认该关键词的行为已启用，也不确认它所需的工具可用。

选择关键词

关键词何时使用……预期效果
ultrathink某个决策、诊断或有风险的改动值得格外谨慎地推理。omp 会采用谨慎的多步方法。如果自动思考已启用，该轮次还会使用当前模型支持的最高推理强度。
orchestrate一项较大的任务包含可以并行推进并从中获益的独立工作。omp 会界定任务范围，把合适的独立部分委派给子代理，整合结果并验证工作。
workflowz广泛调研、审查、迁移或对抗性分析能从明确、确定性的多代理工作流中获益。omp 会构建包含并行与分阶段子代理工作的结构化工作流，然后综合结果。

这些词引导执行方式；它们不保证某个特定答案，也不保证固定的工作代理数量。一个较小或高度耦合的请求可能几乎没有有用的并行工作。workflowz 是更明确的工作流构建选择；orchestrate 是通用的委派选择。

作用域：一条已提交的提示词

关键词只影响其提交的用户消息中包含该词的那一轮次。它不会成为会话状态，也不会延续到下一条提示词。

orchestrate inspect the three independent packages and fix their failing builds

编排请求适用于该轮次，包括 omp 为完成它而做的工作。之后的提示词，例如“Now update the release notes”，除非你再次加入关键词，否则按常规处理。一条提示词中的多个已启用关键词可以同时生效，但组合使用可能只增加成本而不改善结果；通常选择唯一最合适的那个。

精确匹配规则

匹配区分大小写，并且有意排除类代码的上下文。请以精确的小写拼写作为独立散文使用。

匹配：

Please ultrathink before choosing a migration strategy.
"orchestrate" the independent investigations.
Can you workflowz, then summarize the strongest evidence?

句子标点和引号可以紧贴该词。

不匹配：

Ultrathink about this                 # wrong case
orchestrated this migration           # part of another word
my_orchestrate_helper                 # identifier
orchestrate.ts                         # file name
foo::orchestrate                      # symbol reference
orchestrate()                          # call syntax
plans/orchestrate/checklist            # path
`workflowz` this review                # inline code

字母、数字、下划线、斜杠、反斜杠、连字符、文件扩展名后缀、:: 以及紧随其后的调用括号，都会把该词绑定为类代码 token。行内代码、围栏代码块，以及 HTML/XML 注释、标签或元素内部的出现会被忽略。这样你就可以讨论某个符号或粘贴代码，而不会意外改变该轮次的执行方式。

如果你需要提及该词而不激活它，请把它放进行内代码或围栏代码块，改变其大小写，或在提交前禁用该关键词。

前提条件与回退行为

  • ultrathink 不需要子代理工具。它的自动思考覆盖只在思考设为自动时才起作用；否则当前所选的思考强度保持不变。不同模型支持的推理强度不同，因此“最高”指当前模型所支持的最高档。
  • orchestrate 要求子代理任务能力处于启用状态。没有该能力时，不会添加任何编排行为；可见的提示词仍会正常提交。
  • workflowz 要求子代理任务能力和持久评估能力都处于启用状态。两者任一不可用，就不会添加任何工作流行为；可见的提示词仍会正常提交。

计划模式、工具配置或其他会话控件都可能使能力不可用。当 orchestrate 或 workflowz 看起来没有效果时，请检查 /tools。着色后的词仍可能出现，因为高亮识别文本与能力检查是相互独立的。

启用或禁用关键词

下面四项设置都默认为 true。在终端界面中打开 /settings，然后进入 Interaction → Magic Keywords。主 Magic Keywords 开关控制所有关键词；三个关键词开关分别控制它们。

你也可以在 shell 中做同样的修改：

# Disable all keyword behavior
omp config set magicKeywords.enabled false

# Disable one behavior while leaving the others available
omp config set magicKeywords.ultrathink false
omp config set magicKeywords.orchestrate false
omp config set magicKeywords.workflow false

# Re-enable them
omp config set magicKeywords.enabled true
omp config set magicKeywords.ultrathink true
omp config set magicKeywords.orchestrate true
omp config set magicKeywords.workflow true

尽管提示词中用的是 workflowz，设置名称却是 magicKeywords.workflow。运行 omp config list 并查看 magicKeywords.* 的值，以确认实际生效的配置。配置作用域与优先级见设置。

禁用全局开关会停止编辑器的动画，但被识别的词在编辑器和已发送消息中仍可能保持静态着色。各关键词开关不控制高亮。因此，请通过 /settings 或 omp config list 验证是否启用，而不要只看颜色。

成本与并行度

魔法关键词不会创建单独的计费模式，但会增加用量：

  • 当自动思考选择模型支持的最高强度时，ultrathink 可能消耗更多推理 token。
  • orchestrate 和 workflowz 可能同时运行多个子代理。并行执行可以缩短实际耗时，但每个工作代理都会占用模型和工具容量，因此总用量可能明显高于单代理轮次。
  • 工作代理更多并不自动更好。请给出独立的交付物、边界和具体的验收检查，这样并行工作才有用，而不是重复劳动。

用 /usage 或 omp stats 查看用量，而不要假定墙钟时间更短就一定成本更低。

故障排查

该词没有高亮

检查小写拼写及其前后边界。去掉代码格式、路径或扩展名、标识符字符、:: 或紧随其后的括号。高亮是终端界面的辅助特性；在一次性或协议输出中不要依赖它。

该词已高亮，但行为没有变化

检查 Interaction → Magic Keywords 或 omp config list。全局开关和对应的单关键词开关都必须开启。对于 orchestrate，请在 /tools 中确认任务能力；对于 workflowz，请确认任务能力和评估能力都已具备。仅凭高亮无法证明行为已被注入。

ultrathink 没有改变显示的思考强度

它的最高强度覆盖只在自动思考启用时生效，且受当前模型所支持档位的限制。若手动选择了思考强度，它仍会引导该轮次更谨慎，但不会替换该选择。

运行的代理过多，或用量高于预期

使用更窄的提示词、明确列出真正独立的切片，或对顺序执行或规模较小的工作干脆不加关键词。如果你希望这些词只作为普通散文出现，同时保留其他捷径，请禁用该关键词。
