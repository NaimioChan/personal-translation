ACP

在支持 ACP 的编辑器中运行完整的 omp 代理，并获得编辑器感知的文件、终端、会话控制和权限提示。

在编辑器中使用 omp

Agent Client Protocol（ACP）让编辑器可以托管 omp 会话，而无需嵌入 omp 或添加特定于编辑器的插件。当你想在代码旁边审阅变更、终端、审批和会话历史，同时让 omp 保留自己的模型、凭据、设置、扩展和技能时，请使用它。

编辑器会将 omp 作为子进程启动。你不需要在单独的终端中运行 ACP 服务器，也不需要把它连接到端口。

首先，确认 omp 在编辑器将使用的环境中可用：

command -v omp
omp --version

然后使用以下启动值配置 ACP 客户端：

字段值
命令omp
参数acp
传输stdio
会话目录打开的项目或工作区的绝对路径

omp --mode acp 等价，但客户端配置推荐使用 omp acp 这一写法。

连接 Zed

在 Zed 中运行 agent: open settings，打开 External Agents，选择 Add Agent → Add Custom Agent，然后添加：

{
  "agent_servers": {
    "Oh My Pi": {
      "type": "custom",
      "command": "omp",
      "args": ["acp"]
    }
  }
}

从 Agent Panel 启动一个新线程并选择 Oh My Pi。Zed 拥有线程 UI；omp 拥有代理、提供商连接和模型设置。

如果通过 GUI 启动的 Zed 找不到 omp，请将 "omp" 替换为 command -v omp 打印的绝对路径。对于环境不会继承 shell PATH 的其他客户端，也适用同一规则。

对于其他 ACP 客户端，请创建等价的自定义代理条目：用单个参数 acp 启动 omp，让 stdin 和 stdout 连接到 ACP 传输，并在创建会话时提供工作区的绝对路径。不要解析终端 UI 输出，也不要在没有 acp 的情况下启动 omp。

认证并启动线程

omp 会向每个 ACP 客户端声明使用现有本地凭据。这些是 omp 已可用的提供商密钥和 OAuth 会话；只为编辑器内置代理配置的凭据不会自动共享。

如果客户端提供在终端中设置 Oh My Pi，请选择它以打开 omp 的交互式提供商设置。否则：

  1. 在终端中运行 omp。
  2. 输入 /login 或 /login <provider> 并完成认证。
  3. 在编辑器中启动新的 ACP 线程。

关于凭据来源和优先级，参见模型提供商。连接后，使用编辑器的会话控制选择可用的模型和思考强度。模型列表反映了 omp 根据当前凭据和配置可以使用的内容。

现在像平常一样输入提示词，例如：

Rename issueToken to mintToken across this project, update every caller, and run the focused tests.

响应会流式传入编辑器。在功能完整的客户端中，omp 通过编辑器的文件系统桥接读取，通过编辑器写入，并在客户端终端中运行 shell 命令。这样可以让读取内容与打开的缓冲区保持一致，并让编辑器显示受影响的位置和命令输出。如果客户端不提供某项 ACP 能力，omp 会针对该能力回退到工作区文件系统或本地命令运行器。

会话控制

ACP 线程是普通的持久化 omp 会话。根据客户端 UI，你可以重新打开、恢复、分叉或关闭会话，并查看其保存的标题和工作目录。

标准会话控制包括：

  • 模式——默认或计划。plan.enabled 为 true 时可用计划模式，默认就是 true。
  • 模型——当前 omp 可用的任意模型。
  • 思考——关闭、自动，或所选模型支持的强度。

当你想在编辑前进行只读调查时，从客户端的模式控制中选择计划。omp 会呈现完成的计划供审批；关闭或拒绝该提示绝不会授予写入权限。/plan 是仅限 TUI 的命令，不是通过 ACP 进入计划模式的方式。工作流参见计划模式。

支持文本的斜杠命令会在客户端的命令菜单中公布。/login 和 /quit 等仅限 TUI 的命令会有意省略：认证和进程生命周期属于 ACP 宿主。

权限

ACP 会在以下操作之前增加编辑器侧的安全闸门：

  • shell 命令；
  • 删除文件；
  • 移动或重命名文件，包括较大编辑中包含的破坏性操作。

客户端可以提供允许一次、始终允许、拒绝和始终拒绝。一个“始终”选择只会针对当前会话和该操作类别缓存；它不是永久的全局设置。普通读取和非破坏性文件写入不会触发这个 ACP 专用闸门，但你的常规 omp 审批设置仍然适用。

被拒绝、取消或不受支持的权限请求会安全失败。omp 不会静默执行该操作。

对于可信的无人值守工作区，请在客户端启动参数中明确作出选择：

{
  "command": "omp",
  "args": ["acp", "--approval-mode", "yolo"]
}

这会跳过 omp 和客户端的权限提示，除非针对某个工具显式设置了 prompt 或 deny 策略。交互式编辑器使用时，请优先采用默认的提示式设置。持久的设置参见设置，包括 tools.approvalMode 和按工具设置的策略。

MCP 与编辑器能力

在 ACP 模式下，客户端拥有 MCP 服务器配置。omp 接受客户端在会话开始时传入的 stdio、HTTP 和 SSE MCP 服务器；对于该会话，它不会自动发现 omp 磁盘上的 MCP 配置。如果缺少 MCP 服务器，请在编辑器或 ACP 宿主中配置，然后启动或重新加载线程。

omp 还支持客户端提供的文本、图像和嵌入式上下文。你的编辑器是否暴露附件、会话导入、分叉、计划模式、终端或未保存缓冲区读取，取决于它实现的 ACP 能力和 UI。

疑难排查

omp acp 看起来挂起

手动运行时这是预期行为：进程正在等待 stdin 上的 ACP 消息，而 stdout 保留给协议使用。请配置编辑器来启动它。启动和传输诊断会写入 stderr，omp 日志位于 ~/.omp/logs/ 下。

在 Zed 中，运行 dev: open acp logs 检查连接的客户端一侧。

编辑器报告 command not found

在终端运行 command -v omp，并将那个绝对路径用作自定义代理的命令。GUI 应用经常会获得比交互式 shell 更小的 PATH。如果项目是远程的，请在 ACP 进程实际运行的环境中安装并认证 omp。

线程已连接，但没有模型可用

打开客户端提供的终端设置，或运行 omp 和 /login <provider>，不要在编辑器外完成。然后创建一个新线程。同时检查提供商凭据或环境变量对编辑器进程可见；编辑器原生的模型凭据不会自动配置 omp。

未保存的更改缺失，或终端在编辑器外打开

客户端可能没有公布 ACP 文件系统或终端支持。请更新或重新配置客户端。没有文件系统桥接时，请在要求 omp 检查之前保存缓冲区；没有终端桥接时，命令会使用 omp 的本地运行器。

权限提示始终无法完成

ACP 客户端必须呈现并回答权限请求。取消对话框，或使用无法回答请求的客户端，都会拒绝该操作。请使用当前版本的客户端，或有意配置审批策略，不要想当然地假设会获批。

缺少 MCP 工具

请在 ACP 客户端中配置 MCP 服务器，而不只是配置 omp 的本地 MCP 文件。启动新线程，以便客户端能在创建会话时传递服务器配置。

面向 ACP 客户端实现者

omp acp 通过换行分隔的 stdio 讲 ACP JSON-RPC。让 stdout 始终专用于协议，并从 stderr 读取诊断信息。客户端可以逐步集成：基本提示词处理首先可用，而文件系统访问、终端、权限对话框、图像、嵌入式上下文、MCP 服务器、会话历史、模式选择、模型选择和思考控制，会在客户端实现相应的公开 ACP 能力后出现。

该进程声明支持会话创建，以及列表、加载、恢复、分叉和关闭。消息 schema 请使用官方ACP 规范；omp 不要求客户端理解其内部工具或私有桥接负载。
