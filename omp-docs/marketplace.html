插件市场

添加你信任的插件目录，浏览其发布内容，并为一个项目或所有项目安装插件。

插件市场让你可以通过短名称安装插件，而不必自行管理每个插件的仓库。插件市场只是目录：它告诉 omp 存在哪些插件，以及它们的代码来自何处。

首先添加由你信任的发布者控制的目录，浏览其条目，并在评估期间以项目作用域安装一个插件：

/marketplace add anthropics/claude-plugins-official
/marketplace
/marketplace install --scope project <plugin>@claude-plugins-official

在交互式 TUI 中，/marketplace 会打开浏览器，显示插件名称、版本、描述及其插件市场。选择一个条目即可在默认的用户作用域安装；需要项目作用域时，请使用上面的显式安装命令。

选择并验证来源

omp 不会搜索中央商店，也不会认证插件市场发布者。/marketplace discover 只搜索你已经添加的目录。从插件发布者自己的网站或仓库获取来源，然后在添加前检查它：

  1. 确认仓库或域名属于预期的发布者。
  2. 检查 .omp-plugin/marketplace.json 或 .claude-plugin/marketplace.json。
  3. 跟随每个插件的 source；受信任的目录仍可能指向另一个仓库。
  4. 优先选择固定到已审查提交并带有 sha 的条目，而不是会移动的分支。

添加来源会获取并验证其目录，但不会安装插件。你可以随时列出已配置的来源，以发现意外或已重命名的来源：

/marketplace list

从 shell 执行：

omp plugin marketplace list

接受的来源形式如下：

来源示例omp 的处理方式
GitHub 简写owner/repo克隆 GitHub 仓库
Git URLhttps://github.com/org/repo、git@github.com:org/repo.git 或 ssh://…克隆仓库
直接目录 URLhttps://plugins.example/marketplace.json下载该 JSON 目录
本地目录./marketplace、~/marketplace 或绝对路径读取目录而不克隆它

Git 和本地来源必须包含 .omp-plugin/marketplace.json（首选），或兼容 Claude Code 的 .claude-plugin/marketplace.json 回退文件。直接目录 URL 不能使用相对插件来源，例如 "./plugins/linter"，因为没有附带的仓库树。

浏览并安装

添加来源后，可以打开 TUI 浏览器，或打印可用条目：

/marketplace
/marketplace discover
/marketplace discover claude-plugins-official

对应的 shell 命令是：

omp plugin discover
omp plugin discover claude-plugins-official

通过目录 ID name@marketplace 安装：

/marketplace install --scope project name@marketplace
/marketplace install --scope user name@marketplace

omp plugin install name@marketplace --scope project

默认作用域是 user。--force 会重新安装已有插件：

/marketplace install --force name@marketplace

对于 shell 命令，必须已经配置插件市场。否则，omp plugin install name@marketplace 可能会将参数解释为 npm 软件包和版本标签。运行 omp plugin marketplace list，并使用目录声明的 name，它可能与仓库名称不同。

更新、升级和移除

刷新插件市场和升级插件是两个独立的操作：

/marketplace update marketplace-name   # refresh one catalog
/marketplace update                    # refresh every catalog
/marketplace upgrade name@marketplace  # reinstall one plugin from its current entry
/marketplace upgrade                   # upgrade all eligible marketplace plugins

更新目录不会改变已安装的插件代码，升级则会改变。升级所有插件时，omp 会比较声明了 version 的条目；一个插件失败不会阻止其他插件，因此请检查报告的结果。

使用以下命令列出或移除已安装的插件：

/marketplace installed
/marketplace uninstall --scope project name@marketplace
/plugins list

在 TUI 中，不带 ID 的 /marketplace uninstall 会打开选择器。对应的 shell 命令是：

omp plugin list
omp plugin uninstall name@marketplace --scope project
omp plugin upgrade name@marketplace --scope project

只有决定如何处理其中已安装的插件后，才移除目录：

/marketplace remove marketplace-name

omp plugin marketplace remove marketplace-name

移除插件市场会删除其注册表条目和目录缓存，但不会卸载已从其中记录的插件。如果你不再信任或需要这些插件，请明确卸载它们。

作用域和启用状态

作用域可见性默认存储位置
user每个项目~/.omp/plugins/installed_plugins.json
project仅当前项目最近项目的 .omp/plugins/installed_plugins.json

启用的项目安装会遮蔽同一 name@marketplace 的用户安装。禁用的项目安装不会遮蔽用户副本。当一个插件安装在两个作用域时，请传入 --scope user 或 --scope project，以便对目标副本执行卸载、升级、启用或禁用。

/plugins disable --scope project name@marketplace
/plugins enable --scope project name@marketplace

omp plugin disable name@marketplace --scope project
omp plugin enable name@marketplace --scope project

项目作用域限制 omp 加载插件的位置；它不是安全沙箱。插件代码仍以与 omp 相同的操作系统权限运行。

在使用 omp 的 XDG 布局的系统上，用户注册表和缓存文件位于生效的 XDG 数据/缓存根目录下，而不是 ~/.omp。omp config init-xdg 会创建这些目录，但不会移动现有数据，也不会设置 XDG 环境变量。

重新加载当前会话

交互式 TUI 中的插件市场命令会更新磁盘状态并使发现缓存失效，但不会重建运行中会话的每个部分。

安装、升级、卸载、启用或禁用插件后，请运行：

/reload-plugins

这会刷新技能、斜杠命令、任务代理、能力发现和 MCP 服务器。当变更包含自定义工具、钩子或扩展模块时，请重启 omp 会话；这些已初始化的运行时界面不会由 /reload-plugins 完全重建。

Shell 命令会影响未来的会话。已经运行的会话仍需要执行上述重新加载或重启。

控制自动更新

默认情况下，marketplace.autoUpdate 是 notify。启动时 omp 会刷新过期目录并检查版本，但当前的 notify 模式只会在调试日志中报告可用性，不会显示 TUI 通知。如果这不是你想要的行为，请明确选择：

omp config get marketplace.autoUpdate
omp config set marketplace.autoUpdate off
omp config set marketplace.autoUpdate auto
值启动行为
off不检查插件市场插件
notify检查可用更新并写入调试日志；这是默认值
auto检查并自动升级可用插件

当你需要在每次代码变更运行前进行审查时，请使用 off，或手动执行 /marketplace update 加上 /marketplace upgrade。auto 允许发布者无需人工审批步骤即可交付更新的插件代码。

安全模型

插件市场和插件没有经过签名、沙箱隔离或 omp 的集中审查。安装插件可以添加技能和命令，也可以添加钩子、自定义工具、代理、MCP 或 LSP 服务器，以及扩展模块。这些界面可能运行进程、访问文件、发起网络请求，或在会话期间自动执行操作。

安装前：

  • 检查目录条目和解析后的插件来源；
  • 检查钩子、服务器命令、扩展模块和软件包安装脚本；
  • 根据你审查过的提交验证声明的 sha；
  • 使用项目作用域限制其他位置的意外加载，但不要将其视为权限边界；
  • 对于未来变更无法信任的来源，避免自动升级。

--force 只会重新安装插件，不会执行额外验证。

故障排除

来源添加成功，但没有插件出现

运行 /marketplace update <name>，然后运行 /marketplace discover <name>。目录顶层的 name 就是命令名称。即使目录的其他部分可用，无效的插件条目也会被跳过，因此请检查日志以及条目所需的 name 和 source 字段。

找不到目录

对于仓库或本地目录，请将目录放在仓库根目录的 .omp-plugin/marketplace.json 或 .claude-plugin/marketplace.json。相对本地路径必须加上 ./ 前缀；裸目录名不会被识别为本地来源。

看不到已安装的插件

运行 /marketplace installed 确认 ID 和作用域，然后运行 /reload-plugins。涉及工具、钩子或扩展模块时请重启会话。如果两个作用域包含相同 ID，/plugins list 会显示哪个副本处于活动状态或被遮蔽。

更新没有改变插件

/marketplace update 只会刷新目录。运行 /marketplace upgrade name@marketplace 更新已安装的代码，然后重新加载或重启会话。

发布插件市场

插件市场作者会发布一个包含目录和一个或多个可安装插件树的 Git 仓库：

my-marketplace/
  .omp-plugin/
    marketplace.json
  plugins/
    my-plugin/

对 omp 使用 .omp-plugin/marketplace.json。如果还需要兼容 Claude Code，则改用 .claude-plugin/marketplace.json；当缺少 .omp-plugin 目录时，omp 会读取它。

最小的有效目录如下：

{
  "name": "my-marketplace",
  "owner": { "name": "Your Name" },
  "plugins": [
    {
      "name": "my-plugin",
      "description": "What this plugin adds",
      "version": "1.0.0",
      "source": "./plugins/my-plugin"
    }
  ]
}

顶层必须有 name、owner.name 和 plugins。每个插件都需要 name 和 source。插件市场和插件名称必须以小写字母或数字开头和结尾，只能包含小写字母、数字、- 和 .，且最多 64 个字符。

相对来源必须以 ./ 开头，并保持在插件市场仓库内。外部插件可以使用带有可选 ref 和 sha 的 github、url 或 git-subdir 来源对象；请固定 sha 以实现可复现安装。目录解析器接受 npm 来源对象，但目前无法安装。

发布前在本地测试完全相同的使用者工作流：

/marketplace add ./my-marketplace
/marketplace discover my-marketplace
/marketplace install --scope project my-plugin@my-marketplace
/reload-plugins

然后推送仓库并分享其 owner/repo 简写。使用者可以检查该仓库、添加它，并按目录名称安装。
