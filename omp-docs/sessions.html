会话

你的工作会自动保存。按项目恢复它、拆分出一个实验，或者共享一份副本而不丢失原会话。

你的工作会自动保存

正常启动 omp 并开始工作：

cd ~/work/api
omp

没有 Save 命令。omp 会把完成的消息和工具活动记录在与工作目录关联的会话中。退出后，稍后这样回来：

cd ~/work/api
omp -c

-c 会在当前目录继续此终端的上一个会话。如果该终端记录的线索不可用，omp 会使用该目录中最近修改过的会话；如果不存在任何会话，则启动一个新会话。

保存会在条目完成时进行。仍在流式输出中的文本要等响应结束后才会提交，因此严重崩溃可能丢失末尾的部分响应，但会保留它之前已完成的工作。继续工作的安全方式参见崩溃恢复。

如果你完全不想保留本地会话记录，请用 omp --no-session 启动。该次运行无法作为已保存的会话来恢复、删除或分叉。显式导出或共享仍会创建或上传一份单独的副本。

开始、继续或选择会话

根据你已掌握的信息选择相应操作：

你想要操作
开始无关的新工作omp，或在 omp 内执行 /new
继续此终端在当前目录中最近的工作omp -c
从已保存的工作中选择omp -r，或在 omp 内执行 /resume
恢复一个已知会话omp -r <id-or-path>，或 /resume <id>
启动时总是继续最近的会话启用 Auto Resume（见 /settings），或运行 omp config set autoResume true

/new 会启动一个新的已保存会话，并让当前会话仍可在选择器中找到。它不同于 /clear——后者只重置模型当前的对话上下文，而保持同一会话。

使用会话选择器

在启动前运行 omp -r，或在 omp 打开时输入 /resume。选择器会从当前文件夹的会话开始。

  • 输入内容即可按标题、会话 ID、项目路径或对话文本搜索。搜索也能找到长会话深处的提示词。
  • 按 ↑/↓ 和 Enter 选择。
  • 按 Tab 在当前文件夹和所有项目之间切换。所有项目视图会显示每个会话的工作目录。
  • 固定（pin）的会话排在最前。interrupted、aborted 或 error 等状态文本有助于识别未完成的运行。
  • 按 Delete，或在搜索框为空时按 Backspace，可在确认后删除高亮的会话。

当你从另一个已存在的项目恢复会话时，omp 会切换到该会话记录的工作目录。如果记录的目录已不存在，交互式启动会询问是否将会话移动到你的当前目录。

用 /session info 查看当前会话的 ID 和文件路径。对于 -r、/resume、/pin 和 --fork，通常一个短的唯一 ID 前缀就足够了。

让已保存的工作容易找到

命名与固定

给重要的工作一个稳定的标题，而不是依赖它首条消息的预览：

/rename Streaming importer investigation
/pin

/pin 在当前会话上切换是否置顶于恢复列表。/pin <session-id> 在不打开另一个已保存会话的情况下切换它的固定状态。如果你把会话移动到另一个项目目录，固定状态会跟随该会话。

将会话移动到另一个项目

如果这段对话现在属于另一个检出或工作树，请移动它，而不是依赖所有项目选择器：

/move ../api-v2

目标必须是目录。omp 会移动已保存的会话及其产物，更新其工作目录，并使它能从目标项目的恢复列表中被发现。

删除

根据接下来应当发生什么来选择命令：

操作结果
在恢复选择器中删除删除高亮的会话及其产物
/session delete删除当前会话并返回选择器
/drop删除当前会话并立即启动一个新会话
/new保留当前会话并启动一个新会话

删除是破坏性的。如果你以后可能需要，请先导出或复制 /session info 显示的 JSONL 文件。

分支还是分叉？

两者都会保留你已有的对话，但它们以不同方式组织替代方案。

分支分叉
命令/branch/fork
保存形式同一会话中的另一条路径带新 ID 的新已保存会话
你要选择一条较早的用户消息，以便修改后重新发送当前状态；没有消息选择器
最适合探索应归入同一份标准历史中的替代方案有风险、一次性或可单独共享的一条工作线
回到原始版本在会话内使用 /tree用 /resume 选择父会话

/branch 会打开用户消息选择器。选择新方向应当开始的那条提示词；omp 会回退到它之前，并把该提示词放回编辑器，以便你修改。被放弃的后续内容仍留在同一会话中，可用 /tree 重新访问。

/fork 会把当前已保存的会话及其产物复制成一个新会话，然后在副本中继续。父会话保持不变，并单独出现在恢复选择器中。若要从更早的位置分叉，请先导航或分支到该位置，再运行 /fork。

在 shell 中，可以直接把已知的已保存会话分叉到当前项目：

omp --fork <session-id>
omp --fork ./received-session.jsonl

用 /tree 在一个会话内保留的多条路径之间切换。会话树解释了导航、标签、活动路径，以及分支和分叉究竟保留什么。

导出、共享与导入

导出一份本地审阅副本

/export 会写出一份自包含的 HTML 视图并在浏览器中打开：

/export
/export ./review/importer-session.html

无需打开交互式会话即可导出已有的 JSONL 文件：

omp --export ./session.jsonl ./session.html

HTML 用于阅读，不能用于恢复。它可能包含对话文本、工具输出、路径和模型上下文，因此请把它当作敏感内容。

共享加密链接

在会话中运行 /share，或从 shell 共享一个已有的已保存会话：

omp share <session-id-or-path>

默认流程在你的客户端中加密会话快照，并上传加密后的数据块。解密密钥位于 URL 片段中，不会发送到存储服务器。对已配置的密钥默认启用密文脱敏，但它不能替代你对自己所发送内容的审阅：任何拿到完整链接的人都能读取该快照。较大的共享内容可能会被裁剪以适应服务限制，而配置了自定义共享处理器时可能使用不同的目的地和隐私模型。

当另一个人需要一份关于当前状态和下一步的简明陈述时，请在共享前使用 /handoff [focus]。

继续一份可编辑的副本

共享链接或 HTML 导出无法再导入回活动会话。若要做可编辑的交接，请发送 /session info 报告的 JSONL 路径；接收者应把它分叉到自己的当前项目中：

cd ~/work/api
omp --fork ./received-session.jsonl

这会创建一个新的本地会话，并让收到的文件保持不变。omp -r ./received-session.jsonl 则会打开那个确切的文件，并在其记录的目录仍然存在时采用该目录。

omp 还可以把本地的 Claude Code 或 Codex 历史导入到一个全新的 omp 会话中：

omp --from-claude
omp --from-codex

每条命令都会打开一个针对来源的选择器。在已有 omp 会话中，/resume @claude 和 /resume @codex 会打开相同的导入选项。

对于需要公开的 JSONL 结构而非产品工作流的工具，参见会话格式。

配置档、位置与隐私

会话按两层划分作用域：

  1. 配置档。omp --profile work 使用隔离的设置、认证、缓存和会话。恢复选择器只能看到当前活动的配置档。
  2. 工作目录。在一个配置档内，omp 按项目对会话分组。选择器从当前文件夹分组开始；Tab 会显示该配置档的其他项目。

通常的默认配置档位置是 ~/.omp/agent/sessions/。命名配置档通常使用 ~/.omp/profiles/<name>/agent/sessions/。XDG 配置和目录覆盖可能改变这些路径，因此 /session info 是活动会话位置的权威来源。

当某次启动必须在特定目录中保存和查找会话时，请使用 --session-dir <path>。从该自定义位置恢复时，请复用同一个标志。若想在客户端、身份或工作上下文之间做持久隔离，请优先使用配置档；若只有一个对话属于另一个项目，请优先使用 /move。

已保存的 JSONL 文件和产物是本地的，但它们可能包含提示词、源码片段、工具结果、文件路径，以及命令打印出来的密钥。请像保护源代码和凭据一样保护会话目录。--no-session 会阻止生成会话记录，但不会撤销工具更改过的文件，也不会撤销你显式导出或共享的副本。

崩溃恢复

在终端断开、进程崩溃或强制重启之后：

  1. 回到同一个项目并运行 omp -c。
  2. 如果那不是正确的对话，运行 omp -r，输入一个有辨识度的短语，并检查标有 interrupted 的会话。
  3. 在发送下一条提示词之前，先阅读最后完成的几条消息以及任何待处理工具的警告。
  4. 在要求 omp 重复某条命令之前，先核实外部副作用。即使该命令更改了 omp 之外的某些内容，对话记录也可能显示工具结果从未被记录。

omp 会保留崩溃前已完成的条目，并忽略不完整的末尾记录。它不会凭空补出被中断的工具调用所缺失的结果，也不会补出流式响应中未保存的尾部内容。

疑难排查

选择器显示没有会话

  • 按 Tab；你可能只查看了当前文件夹。
  • 检查你是否和之前一样用同一个 --profile 启动。
  • 如果该会话使用了 --session-dir，请再次传入该目录。
  • 在离开会话前用 /session info 记录它的确切路径。

-c 打开了错误的工作

-c 优先选择与当前终端关联的最后一个会话，其次是该目录的最新会话。用 omp -r 做显式选择，或对你经常返回的会话使用 /rename 和 /pin。

找不到已知 ID

打开 omp -r，按 Tab，在所有项目视图中搜索。如果多个会话开头相同，请使用更长的 ID 前缀。配置档和自定义会话目录是分开的搜索作用域；请切换到原来的配置档，或传入原来的 --session-dir。

分叉或删除不可用

分叉需要持久化，因此请在不带 --no-session 的情况下重新启动。删除需要实际存在的已保存文件；一个全新的空会话可能还没有可删除的内容。在移动、删除或分叉之前，请等待流式响应结束，或先中止它。

项目目录被重命名或删除了

从交互式终端按 ID 恢复。对于记录的目录已不存在的会话，omp 会提供将其重新定位到当前目录的选项。对于存在但不同的项目，正常恢复它，并在你确实想重新分配时使用 /move <path>。

命令行标志列在命令行参考中，所有交互式命令列在斜杠命令中。
