目标模式

给 omp 一个持久目标，让它跨轮次持续工作，并用 token 预算和监督手段加以控制。

目标模式适用于那些一轮做不完、但有清晰终点的工作：全仓库范围的迁移、持续多轮测试并修复的循环，或者包含多个相互依赖步骤的发布清单。你只需说明一次目标；omp 会不断采取下一个有用的步骤，直到它验证工作已完成、你暂停或放弃该目标，或者预算阻止了进一步的工作。

从一个有边界、可测试的目标开始：

/goal Migrate the importer to streaming. Update every caller and user-facing documentation, preserve current error behavior, and finish only after the importer tests and typecheck pass.
/goal budget 200000

状态行会显示目标模式已激活，omp 会在每个有产出的轮次后继续工作，而不是等待下一次提示。请随时待命处理有风险的决策，在工作推进过程中审阅它，并用 /goal show 查看状态与用量。

token 预算是一条安全边界，而不是成功的定义。预算耗尽时，目标会变成 budget-limited，omp 会把已知的部分收尾。除非目标模式明确报告已完成，否则目标仍未完成。

选择合适的任务类型

目标模式在以下情况下效果很好：

  • 期望的最终状态和验证命令是已知的；
  • 推进过程可能需要大量编辑、工具运行或重试；
  • omp 能自行做出例行决策，不必每走一步都询问；以及
  • 你能事先表达安全边界。

对于应当在一轮内完成的聚焦改动，使用普通提示词。若你想在动手实现前先审阅方案，请使用计划模式。不要把目标无人值守地用于生产变更、破坏性操作、凭据相关的工作或有歧义的产品决策；请在目标中要求这些操作必须先获确认。

一个有力的目标会写明交付物、完成的证据，以及禁止的捷径。例如：

/goal Remove the legacy session API and migrate all callers. Keep the public behavior compatible, do not change the database schema, run the focused session tests and typecheck, and report any callers that cannot be migrated safely.

如果终点还不清楚，先让 omp 来访谈你：

/guided-goal I need to make authentication safer before launch

/guided-goal [rough objective] 会在普通聊天中提出澄清问题，把你的回答转成具体目标，然后启动目标模式。使用单纯的 /goal 时，省略目标即可打开多行编辑器。

监督进行中的目标

在交互式 TUI 中，活动目标会在短暂空闲后自动继续。输入提示词、附加图片或打断，都能让你在下一轮开始前取得控制权。你随时可以用一条普通消息引导工作：

Before continuing, keep the existing wire format and add a regression test for malformed frames.

用这些命令查看和控制当前会话的目标：

命令作用
/goal为活动或已暂停的目标打开管理菜单。若还没有目标，则打开目标编辑器。
/goal show显示目标、状态、已用与剩余 token，以及活跃时间。
/goal pause停止自动续跑，但保留会话中的目标与计量。
/goal resume恢复已暂停的目标，并安排下一次续跑。
/goal budget <N>设置一个正整数形式的总 token 预算。已有用量会被保留。
/goal budget off移除 token 上限。已有用量会被保留。
/goal set <objective>启动一个目标，或用新目标和全新的计数器替换活动目标。替换同时会清除旧预算。
/goal drop确认后永久停止当前目标。没有单独的 /goal stop 命令。

按 Esc 打断当前轮次。被中断的活动目标会保存为暂停状态，所以请检查未完成的工作，只在可以安全继续时才运行 /goal resume。

已暂停的目标必须先恢复才能更改预算。它也不能被静默覆盖：恢复它并用 /goal set …，或者在开始另一个目标之前先放弃它。

设置并解读预算

目标模式默认没有 token 上限。对于需要监督的工作，应在启动后尽快设置一个：

/goal budget 100000

N 是当前目标的总预算，而不是在其剩余额度上追加的数额。更改预算会保留累计用量。该计数包含输入 token、输出 token 和缓存写入 token；缓存读取 token 不计入。一轮可能在计量跟上之前越过确切边界，因此请把这个值当作护栏，而不是精确的硬停止点或支出限额。

当已用 token 达到上限时：

  1. 状态从 active 变为 budget-limited。
  2. omp 会发送一个收尾轮次，询问进展、剩余工作和阻碍，而不是开始更多实质工作。
  3. 自动续跑停止，但目标仍附属于该会话。

在做决定之前先检查状态：

/goal show

如果目标仍值得继续，就设置一个高于所显示用量的新总量，或者移除上限：

/goal budget 250000
# or
/goal budget off

这会让受预算限制的目标回到活动工作状态。如果你不想再做更多工作，用 /goal pause 把它保留到以后，或用 /goal drop 结束它。绝不要把 budget-limited、收尾回复、沉默或提供商错误解读为完成。

完成意味着什么

只有把每一项交付物都与当前仓库状态核对之后，目标模式才会要求 omp 收尾完成。成功时，你会看到 Goal mode completed，自动续跑结束，完成记录会把目标和累计用量写入会话历史。

这比仅仅走到某一轮末尾要更强，但它不能替代你的审阅。请阅读最终证据、检查重要改动，并运行任何需要人工授权的发布或生产检查。如果最终回复列出了剩余工作或阻碍，那么即使回复听起来像是结论，任务也并未完成。

持久化与恢复

随着工作推进，目标、状态、预算、token 用量和活跃时间都会随会话一起存储。压缩不会丢弃目标。在运行中的 TUI 里切走再切回同一会话，会保留活动目标；从冷启动重新打开已持久化的会话，会把活动目标恢复为暂停状态，这样它就不会无人值守地继续。请使用 /goal show，检查工作树，然后运行 /goal resume。

显式暂停的目标会一直保留在会话中，直到被恢复或被放弃。放弃会移除活动的目标记录，而累计用量仍留在会话日志中。完成会清除活动模式并写入一条完成记录。

当工作中途意外停止时，请使用这份恢复清单：

你看到的现象该怎么做
按 Esc、轮次被中断或重新打开会话后显示 paused检查未完成的改动与日志，然后运行 /goal resume。
budget-limited运行 /goal show；把总量提高到已用 token 之上，或使用 /goal budget off。
active，但没有自动的下一轮提交或清空输入框里等待的草稿/图片。如果上一次续跑没有产生可执行的进展，发送一条普通消息，例如“从最后一次已验证的步骤继续这个目标。”
反复出现提供商或命令失败暂停目标，修复凭据/环境或细化目标，然后恢复。只有在你确实想要全新的计数器时才放弃并重启。
提示“Exit plan mode first”或“Exit vibe mode first”先完成或退出该模式；计划模式、Vibe 模式和目标模式互斥。
提示“Goal mode is disabled”启用 goal.enabled，然后重试 /goal。

自动续跑目前是交互模式下的行为。循环模式也会接管自动提交，所以当你期望由目标驱动续跑时，不要把 /loop 与目标一起使用。

配置

无需任何配置：目标模式、其页脚状态和交互式续跑默认启用。可在设置 → 任务 → 模式中，或在 ~/.omp/agent/config.yml 中更改它们：

goal:
  enabled: true
  statusInFooter: true
  continuationModes:
    - interactive
设置默认值作用
goal.enabledtrue允许 /goal 和 /guided-goal 创建按会话的目标。
goal.statusInFootertrue在状态行中，于目标指示器旁显示目标的 token 用量。
goal.continuationModes["interactive"]在交互式 TUI 中启用轮次之间的自动续跑。移除 interactive 即改为需要手动提示。

从 shell 验证生效的取值：

omp config get goal.enabled
omp config get goal.statusInFooter
omp config get goal.continuationModes

文件优先级与配置命令见设置，完整命令索引见斜杠命令。
