GitHub

在 omp 提示词中审查 issue 与拉取请求、搜索 GitHub、安全地在 PR 上工作，并跟踪 Actions。

在提示词中处理 GitHub

用 omp 调查 issue、审查拉取请求、搜索仓库、创建或更新 PR 分支，并跟踪 GitHub Actions，无需把所有内容都复制到聊天中。omp 使用 GitHub CLI（gh），因此它看到的仓库和权限与你已登录的 GitHub 账户完全一致。

先安装并认证 gh，然后启用 GitHub 能力：

gh auth login
gh auth status
omp config set github.enabled true

你也可以在 omp 会话中打开 /settings，开启 Tools → Available Tools → GitHub CLI。github.enabled 默认关闭。如果已经在运行的会话中该能力仍不可用，请在启用后启动新会话。

然后直接说明你想要的结果：

审查 PR #482。总结行为变化，指出有风险的代码路径，并点出缺失的测试。不要检出或修改任何内容。

omp 会展示它读取到的 GitHub 数据、链接回源条目，并在执行 GitHub 操作前请求相应的审批。它不会在 ~/.omp 中另存一份 GitHub token；认证始终由 gh 管理。

常见工作流

当你希望简短的 issue 或 PR 编号指向某个仓库时，请在该仓库的检出目录中运行 omp，且其 origin 指向 GitHub。在检出目录之外，请在请求中写明仓库，例如 owner/repo。

调查 issue

让 omp 读取某个 issue 及其讨论，把它与代码关联起来，或与相关报告作比较：

读取 issue #731，在此检出中追踪受影响的代码，并解释最可能的根本原因。暂时不要修改文件。

查找 acme/payments 中最近两周更新过的未关闭 bug issue。合并重复项，并推荐影响最大的三个修复。

内置的 GitHub 能力可以读取和搜索 issue。它不提供专门的 issue 创建、编辑、评论或关闭操作。如果 omp 为这类写入提出一条独立的基于 shell 的 gh 命令，该命令受你常规的 shell 审批策略约束。

审查拉取请求

审查可以完全在远端进行：omp 读取 PR 元数据、讨论、变更文件列表，以及逐个文件的 diff 或完整 diff。

不检出地审查 PR #482。重点关注认证回归、不安全的错误处理，以及测试是否覆盖了失败路径。

比较 PR #482 和 #497。解释哪种方案更好地保留公共 API，以及原因。

对于其他仓库中的拉取请求，要明确写出：

审查 acme/widgets 的 PR 482，并总结尚未解决的审查意见。

在隔离的工作树中处理 PR

需要本地执行或修改时，让 omp 检出该 PR。GitHub 集成会创建一个专用 git 工作树，而不是切换或覆盖你当前的工作树。它会在结果中报告工作树路径。

在专用工作树中检出 acme/widgets 的 PR 482，运行针对性测试，修复失败的重定向测试，并把 diff 给我看。暂时不要提交或推送。

提交已批准的改动并推回 PR 482 的源分支，然后跟踪它的 CI。

PR 分支命名为 pr-<number>。工作树通常位于 ~/.omp/wt 下；OMP_WORKTREE_DIR 会覆盖该位置，其次是 worktree.base 设置。已存在的匹配工作树会被复用。如果本地已有 pr-<number> 分支指向不同的提交，检出会停止而不是重置该分支，除非你明确授权强制重置。

推送被有意限制：omp 只能对先前通过其 PR 检出工作流获得的分支使用 GitHub PR 推送工作流。这保留了 PR 头仓库、分支和 fork 元数据，并防止任意本地分支被误认为 PR 分支。当 PR 作者禁用了维护者编辑，或你的 GitHub 账户缺少权限时，推送仍可能失败。

打开拉取请求

在你审查并提交改动之后，让 omp 从当前分支创建一个 PR：

从当前分支向 main 创建草稿 PR。用提交内容填写标题和正文，添加 bug 标签，并请 octocat 审查。把 URL 给我。

或者自己提供措辞：

开一个标题为“Fix login redirect after SSO”的 PR，附上简明摘要和测试计划。目标分支为 main，并保持草稿状态。

创建 PR 属于远端写入，按常规审批策略需要执行审批。

搜索 GitHub

omp 可以搜索 issue、拉取请求、代码、提交和仓库。用自然语言说明范围和过滤条件；如果你已经熟悉 GitHub 搜索限定符，它们同样有用。

搜索此仓库中提及 token rotation 的未关闭 PR，创建时间晚于 2026-07-01。

在 acme 组织范围内搜索代码中调用 legacyAuthenticate( 的地方，并列出仓库和路径。

找出 acme 组织中上个月推送过、且提及 WebAuthn 的 Rust 仓库。

省略范围时，issue、PR、代码和提交搜索默认针对当前 GitHub 检出。仓库搜索是全局的，除非你的请求包含 org:、user: 或类似的 GitHub 限定符。搜索结果简明且有上限，因此请让 omp 缩小查询范围，而不要期望一份详尽的导出。

跟踪 GitHub Actions

让 omp 跟踪与当前 HEAD 关联的所有工作流运行，或给它一个运行 URL：

跟踪当前 HEAD 的 GitHub Actions。如果有 job 失败，总结失败原因，并告诉我完整日志保存在哪里。

跟踪 https://github.com/acme/widgets/actions/runs/123456789 直到它结束。

结果会随 job 运行而更新。失败的 job 会迅速报告并附上日志尾部；失败的完整 job 日志会保存为会话产物，并在响应中引用。跟踪当前提交时，omp 会等待所有已发现的工作流，并在宣布成功前额外检查一次，以免漏掉稍晚启动的工作流。

把 GitHub 引用粘贴到提示词中

pr:// 和 issue:// 是可选的、面向用户的引用。当单独一个编号会有歧义，或你希望看到特定视图时，把其中一个粘贴到提示词里。你不需要自己去调用读取文件的命令。

引用含义
issue://731当前检出所在 GitHub 仓库中的 issue 731，包含评论。
issue://acme/widgets/731完全限定的 issue。
issue://731?comments=0不含讨论串的 issue。
pr://482当前仓库中的 PR 482，包含评论和审查。
pr://acme/widgets/482完全限定的 PR。
pr://482/diff变更文件列表。
pr://482/diff/3该列表中第三个文件的 diff；索引从 1 开始。
pr://482/diff/all完整的统一 diff。
issue://?state=open&label=bug&limit=20当前仓库中最近的匹配 issue。
pr://acme/widgets?state=merged&author=octocat&limit=20指定仓库中匹配的 PR。

列表引用默认针对未关闭条目，返回 30 条结果。limit 必须为正数，上限为 100。issue 列表接受 open、closed 或 all；PR 列表还接受 merged。列表可按一个 author 和一个 label 过滤。

示例：

解释 pr://acme/widgets/482/diff/all 对用户可见的影响，并指出迁移风险。

针对当前代码分诊 issue://?state=open&label=regression&limit=20。

在交互式编辑器中输入独立的 #482 会同时提供 PR 和 issue 两个补全项，因为 GitHub 共用同一编号空间。输入 pr #482 或 issue #482 可限定补全类型。

这些引用通过 omp 的 GitHub 读取支持工作，不依赖更宽泛的 github.enabled 开关。它们仍要求 gh 已安装、已认证，并且能访问该仓库。

审批、隔离与缓存数据

GitHub 访问遵循三条明确的边界：

  • GitHub 权限：omp 只能访问当前 gh 账户能访问的内容。它无法绕过组织 SSO、仓库权限、分支保护或 fork 限制。
  • 操作审批：仓库读取、搜索和 Actions 跟踪请求读审批；PR 创建、检出和推送请求执行审批。当前生效的审批模式决定 omp 是否会暂停等待确认。
  • 本地隔离：PR 检出会创建或复用专用工作树。它不会在你当前的工作树中切换分支。检出会改变本地 git 状态；PR 创建和推送会改变 GitHub。

单个 issue 与 PR 视图以及 PR diff 默认缓存在 ~/.omp/cache/github-cache.db 中。缓存可能包含私有 issue 正文、评论、审查、审查评论和 diff。各行按当前 GitHub 凭据的指纹分隔，但该数据库仍是本地敏感数据，应像账户缓存的其他部分一样加以保护。

新鲜条目会在 5 分钟内复用。较旧的条目会在 omp 后台刷新的同时返回，超过 7 天的条目会被丢弃。要避免持久缓存 GitHub 视图：

omp config set github.cache.enabled false

设置参考

完成 gh 认证后默认值即可工作，只是必须启用更宽泛的 GitHub 能力。

设置默认值用途
github.enabledfalse启用 GitHub 仓库、文件、搜索、PR 工作树/推送/创建以及 Actions 工作流。
github.cache.enabledtrue在本地缓存渲染后的单 issue、单 PR 和 PR diff 视图。
github.cache.softTtlSec300在此期间内直接返回缓存视图，不进行网络刷新。
github.cache.hardTtlSec604800缓存视图保留的最长时长。
worktree.base未设置omp 托管工作树的基础目录；未设置时通常解析为 ~/.omp/wt。OMP_WORKTREE_DIR 优先级更高。

用 omp config get <setting> 查看实际生效的值，或参见设置了解配置文件与优先级。

故障排查

GitHub 工作流不可用。运行 gh --version。当 PATH 中找不到 gh 时不会暴露该能力。然后确认 omp config get github.enabled 输出 true；如果你是在会话开始后才启用它，请启动新的 omp 会话。

认证失败。运行 gh auth status，必要时再运行 gh auth login。对于私有或组织仓库，确认所选账户有访问权限，并且所需的 SSO 授权已生效。

omp 无法确定仓库。在带 GitHub 远端的 git 检出目录中启动 omp，或在请求中包含 owner/repo。涉及多个仓库时，优先使用完全限定的引用，例如 pr://acme/widgets/482。

PR 或 issue 视图看起来过时。视图可能来自本地缓存。通过 omp 进行的近期写入会使相关缓存视图失效，但在别处所做的更改最长可能保持 5 分钟软 TTL 的“新鲜”状态。刷新后重试、调低 github.cache.softTtlSec，或在每次读取都必须访问 GitHub 时禁用缓存。

PR 检出拒绝已存在的分支。本地 pr-<number> 分支已经指向别处。在授权强制重置之前，先让 omp 解释不匹配之处；如果该分支包含你需要的工作，就不要强制重置。

推送被拒绝。确认这个 PR 最初是 omp 检出到其专用工作树的、你的账户可以更新 PR 头分支、且允许 fork 维护者编辑。分支保护和必需的审查仍然适用。

没有出现 Actions 运行。确认提交已推送，且所请求的仓库和分支正确。如果你知道是哪个运行，请直接粘贴完整的 GitHub Actions URL，而不是让 omp 从本地 HEAD 推断。
