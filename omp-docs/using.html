使用 omp

完整跑一次交互式会话：写下请求、跟踪工作、回答决策、引导或停止它、审阅改动，并安全地恢复。

不带参数的 omp 会打开交互式终端界面。这是日常工作的常规场所：用普通语言描述期望结果，让 omp 检查并修改项目，审阅它做了什么，然后在同一个对话里继续打磨结果。

如果你刚看完快速上手，请先进入一个项目，然后发送一个范围明确的请求：

cd my-project
omp

Find the refresh-token race, fix only the implementation and its focused tests, show me the diff, and run those tests. Do not commit.

按 Enter。日常工作既不需要斜杠命令，也不需要特殊的提示词格式。

一项完整任务，逐轮推进

一次可靠的交互式任务通常遵循这样的循环：

  1. 说明结果与边界。指出 bug 或功能、重要路径、任何不能改动的东西，以及应当通过的检查。
  2. 让 omp 调查。它会叙述进展，并把每次读取、命令或改动作为卡片显示在对话记录中。
  3. 必要时介入。在它工作时发送引导消息、回答问题，或拒绝不安全的动作。
  4. 审阅证据。展开工具卡片与 diff。检查被改动的路径、命令退出状态、测试结果与最终解释。
  5. 在同一个会话里打磨。说明哪里不对或还剩什么：“保留公开签名”“补上缺失的边界情况”，或“把 cache.ts 的改动回退”。

omp 工作时，文件改动会直接应用到你的工作树。除非你要求提交，否则它们不会被提交。你的编辑器、git diff 和对话记录始终是最终的审阅界面。

读懂屏幕

具体的颜色和状态行布局取决于你的主题与设置，但交互式屏幕有三个工作区域：

对话记录（Transcript）

你的消息、助手文本与思考、通知、提问，以及工具卡片。新活动出现在底部。工具卡片显示某项动作是待处理、成功、失败还是被取消；编辑卡片包含受影响的路径和 diff 摘要。

输入框（Composer）

带边框的编辑器，你在这里写下一条提示词。自动补全、附件芯片、排队消息提示和临时对话框都出现在它周围。选择器或提问底部的提示行显示适用于该聚焦界面的按键。

状态行（Status line）

默认布局显示当前模型与思考强度、工作模式、路径、Git 状态、上下文用量、费用和会话名。窄终端会省略或缩短片段。Plan、Goal、Vibe、Loop、Fast、协作及相关状态会在相关时出现在这里。

状态行不是装饰：在断定 omp 位于错误目录、用了错误模型、被允许写入或上下文耗尽之前，先看它。它的预设与片段可在 /settings 中更改；完整参考见设置。

撰写、附加并提交

你希望……这样做
发送提示词按 Enter。
插入换行按 Shift+Enter、Ctrl+J 或 Alt+Enter。Windows Terminal 用户应优先使用 Alt+Enter。
提及一个项目文件输入 @，继续输入以进行模糊搜索，然后选择路径。omp 会把 @path 提及自动读入当前轮次。
补全路径输入相对、父级、主目录或绝对路径的一部分，并使用补全列表。Tab 接受高亮的补全项。
附加图片用 Ctrl+V 粘贴，或拖入、粘贴图片路径。输入框中的芯片会确认已粘贴的附件。你也可以提及 @path/to/image.png；omp 会随本轮读取该文件。
附加粘贴的文本正常粘贴即可。多行或大段粘贴可能折叠成一个带编号的粘贴芯片，让编辑器保持可读；删除该芯片即移除该附件。
在外部编辑长草稿按 Ctrl+G 打开 $VISUAL，回退到 $EDITOR，保存并关闭后把文本交回 omp。
找回较早的提示词按 Ctrl+R 搜索提示词历史。

你可以在一条提示词里组合散文、@file 提及、粘贴的文本和图片。说明每个附件是做什么用的；只有路径只提供上下文，不提供意图。例如：

Compare @src/auth/refresh.ts with @test/auth/refresh.test.ts. The attached screenshot is the production error. Fix the race without changing the token format, then run the focused test.

图片输入默认会被规范化并缩放。当当前模型无法直接接受图片时，omp 通常会请一个已配置的、具备视觉能力的模型给出描述。图片行为可配置：在 Model → Vision 与 Appearance → Images 下，位于 /settings 中。

跟踪工作并审阅卡片

工具卡片是你的提示词与最终答案之间的审计轨迹。先读标题：它标明动作、命令、路径或远程资源。然后检查它的状态与结果。

  • 按 Ctrl+O 展开或折叠工具输出。用于被截断的命令记录或完整的可见 diff。
  • 想要只看散文的视图时，按 Ctrl+Shift+O 隐藏或显示工具活动。
  • 卡片成功只表示该动作完成，并不表示整个任务正确。请单独检查最后的测试或验证卡片。
  • 失败或被取消的卡片仍是有用的证据。阅读错误，然后告诉 omp 是重试、换一种方法，还是停止。
  • 对于编辑，检查路径和增删行。如果作用域或行为不对，立即要求修正。

更深入的文件改动工作流程与安全设置，见处理文件。

回应审批与提问

如果你的审批模式或某个工具策略需要确认，omp 会在动作前暂停，并显示它想做什么。请阅读命令、目标、diff 预览和理由，而不是只看标题就批准。用在屏幕上显示的选择器按键，选择所提供的允许或拒绝选项。Escape 会取消该提示；取消不会被推断为批准。

当 omp 需要产品决策输入时，它可能显示一个提问对话框：

  • 用 Up/Down 移动，用 Enter 选择单个答案。
  • 对于多选问题，按 Space 切换选项，然后按 Enter 前进。
  • 用 Other 行输入自定义答案。当对话框提供解释性备注时，在某一行上按 n。
  • 对于多个问题，用 Tab、Shift+Tab 或 Left/Right 切换标签页；在最后一个标签页上审阅并提交。
  • 按 Escape 取消，而不是靠猜。之后你可以在输入框里说明缺失的约束。

默认的 Yolo 审批模式允许常规的读取、写入与执行动作，因此你可能看不到审批提示。当你想在写入和命令前得到确认时，请选择 Always ask（总是询问）：在 /settings 中它位于 Interaction → Approvals 下；也可以用 omp --approval-mode always-ask 启动。

引导、排队、停止与继续

omp 工作时你也可以输入。提交键决定这条消息是应影响当前轮次，还是应等待下一轮。

动作默认按键何时使用……
引导当前轮次Enter当前方法需要纠正：“不要改 schema”“使用现有的辅助函数”，或“调查完就停”。
排队一条后续消息Ctrl+Q 或 Ctrl+Enter当前任务应先完成：“在这之后，解释迁移风险。”
把排队的输入退回输入框Alt+Up 或 Shift+Up你排错了文本，或想编辑待发消息。
中断活动中的操作Escape某个轮次、本地 shell/Python 逃逸、重试或其他活动操作应当停止。
继续先前的意图发送 . 或 c你在合适的点中断了，并希望 omp 不必重述任务就继续。
重试上一次失败的助手轮次Alt+R提供商或轮次失败，且应再次尝试同一请求。

引导消息面向现在；后续消息面向代理交出结果之后。待发消息条显示已排队的内容。steeringMode、followUpMode 和 interruptMode 设置控制排队消息是一起排空还是一条一条来，以及引导是立即中断还是等待。

Escape 对焦点敏感。如果自动补全或选择器打开着，第一次按下会关掉那个界面。在主输入框中，它会中断活动工作。它不会退出 omp。在 Loop 模式中，它停止当前迭代，同时保持 Loop 开启；再次运行 /loop 可禁用 Loop。各模式的确切行为见运行模式。

选择模型与思考强度

先使用默认值，直到某项任务给了你改变它们的理由。当前选择始终显示在状态行中。

控件结果
/model 或 Alt+M打开模型中心，查看或更改持久的模型角色分配。
/switch 或 Alt+P为当前会话选择一个临时模型，而不改变已保存的角色分配。
Ctrl+P / Ctrl+Shift+P按配置的角色-模型顺序向前或向后循环。
Shift+Tab循环当前模型支持的思考强度，包括配置时的 Auto。
Ctrl+T显示或隐藏对话记录中的思考块。这改变可见性，不改变推理强度。

更高的思考强度可以改善困难推理，但通常会提高延迟和 token 用量。不支持可配置思考的模型会说明这一点，而不是改变。选中 Auto 时，轮次被分类后状态行会显示解析出的强度。

持久的角色分配、快速循环顺序与按会话覆盖，见模型角色。

交互式工作模式改变轮次的行为方式，而不是你与 omp 交谈的方式。有模式生效时，状态行会告诉你：

  • Plan 会探索并提出方案，在你批准前不改变工作树。见计划模式。
  • Goal、Vibe、Prewalk、Loop、Fast 及相关控件是专门的工作流。先从普通的交互轮次开始，再有意识地通过运行模式选用它们。
  • 如果 omp 意外拒绝编辑，或在轮次结束后仍继续推进，先检查模式片段。用它的斜杠命令离开或禁用该模式，而不是用重复的提示词硬顶。

自己运行本地命令

行首的逃逸符号会直接从输入框运行，不需要让模型选择或调用任何东西：

! git status
!! git diff --stat
$ print(2 + 2)
$$ import os; print(os.getcwd())
前缀行为
! command在你的用户 shell 中运行该命令，在 TUI 中流式显示结果，并把它纳入对话上下文。
!! command运行并显示它，但不把输出纳入模型上下文。
$ code在会话共享的 Python 内核中运行 Python，并把结果纳入上下文。$ 后必须有空格，因此像 $HOME 这样的散文仍是散文。
$$ code运行 Python 并显示它，但不把输出加入模型上下文。

按 Escape 取消正在运行的 shell 或 Python 逃逸。成功的 ! cd path 也会移动 omp 的交互式工作目录。这些命令以你的本地用户权限运行，可能立即改动文件；!! 和 $$ 只是把输出排除在模型上下文之外，并不是安全沙箱。

在不丢失工作的情况下在会话间移动

你不需要退出来改变对话状态：

命令用途
/tree移动到当前会话中较早的消息或另一个分支。当某个轮次跑偏时使用它。
/branch在同一个会话文件中，从较早的消息开始另一条线程。
/fork在尝试另一种方案前，把对话克隆到新的会话文件。
/resume打开本项目的会话选择器。
/new开始一个新会话，同时把当前会话保留在磁盘上。
/session info显示当前会话 id、路径、谱系与统计信息。
/compact当上下文计量很高时，摘要较早的活动上下文，同时保留可导航的历史。

树和会话选择器会显示各自的导航提示。Escape 先清除活动的搜索，然后关闭选择器。完整的创建分支、恢复、导出与交接行为见会话。

退出与恢复

使用 /exit、/quit、/q 或 Ctrl+D 有序退出。Ctrl+D 会保存非空的未发送草稿；恢复该会话时会还原一次。Ctrl+C 清空输入框，半秒内再按一次则退出，所以当你的意思是“离开并保留我的草稿”时，请优先用 Ctrl+D。

在同一个项目目录下，用下面的命令重启最近的会话：

omp -c

用 omp -r 打开项目会话选择器。这也是 SSH 或终端断连后的恢复路径；持久化的对话记录会被重放，包括仍在写入的进行中尾部。
