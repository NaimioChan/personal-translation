主题

预览内置配色，跟随终端的深色或浅色外观，或安装你自己的一份易读 JSON 主题。

主题控制 TUI 的文本、背景、边框、Markdown、语法高亮、diff、输入模式、状态行和符号。选择主题最快的方式是 /settings：打开 Appearance，然后选择 Dark Theme 或 Light Theme。在列表中移动会立即预览每个内置或已安装的主题。按 Enter 保留高亮的主题，或按 Escape 恢复之前的主题。

跟随终端外观

omp 没有一套固定的“系统”配色。它保留一个深色主题槽位和一个浅色主题槽位，然后使用与终端背景匹配的那个。默认值分别是深色背景用 titanium、浅色背景用 light。

在 /settings 中设置这两个槽位，或在当前代理配置中设置：

# ~/.omp/agent/config.yml
theme:
  dark: titanium
  light: light

omp 根据终端报告的 OSC 11 背景色判断槽位，其次看 COLORFGBG。在 macOS 上使用 Zellij 时，OSC 11 不可靠，它可以改用 macOS 外观。如果这些信息都不可用，它选择深色槽位。交互式 TUI 运行期间，外观变化会被重新评估。

内置列表包括 dark、light、titanium、面向终端的配色如 dark-terminal，以及许多命名的深色和浅色配色。请以 /settings 列表作为你所安装版本的权威目录，而不要从其他版本复制名称。

创建并安装自定义主题

自定义主题是当前代理目录中的一个 JSON 文件：

  • 默认 profile：~/.omp/agent/themes/<name>.json
  • 命名 profile：~/.omp/profiles/<profile>/agent/themes/<name>.json
  • 自定义代理目录：$PI_CODING_AGENT_DIR/themes/<name>.json

项目本地的主题文件不会被扫描。去掉 .json 的文件名就是选择时使用的名称；JSON 的 name 应使用相同的值。如果内置主题与自定义文件同名，内置主题优先。

文件格式与颜色值

name 和 colors 是必需的。vars、export 和 symbols 是可选的。

每种颜色可以是：

  • "#RRGGBB"，表示 RGB 颜色；
  • 0 到 255 的整数，表示 ANSI 256 色调色板索引；
  • vars 中某个条目的名称（引用可以嵌套）；或
  • ""，表示使用终端默认的前景或背景色。

缺失和循环的变量引用属于错误。十六进制颜色在支持的终端上以 truecolor 输出，否则转换为 256 色。数值始终指向终端的 256 色调色板，因此其确切外观取决于终端。内置的 dark-terminal 是一个有用的兼容性起点，而 "" 让终端自己决定基础前景或背景色。

下面所有 colors 键都是必需的，只有 thinkingMax 例外，它是可选的，并回退到 thinkingXhigh：

可选的导出与符号覆盖

HTML 导出的颜色可以单独提供：

"export": {
  "pageBg": "#0d1117",
  "cardBg": "#161b22",
  "infoBg": "#26364a"
}

如果没有提供，omp 会从主题推导导出背景色。symbols.preset 接受 unicode、nerd 或 ascii；Nerd 符号需要 Nerd Font。全局的 Symbol Preset 设置会覆盖主题的预设。高级主题还可以替换单个符号和 spinner 帧：

"symbols": {
  "preset": "ascii",
  "overrides": {
    "status.success": "OK",
    "nav.cursor": ">",
    "boxRound.topLeft": "+"
  },
  "spinnerFrames": {
    "status": [".", "o", "O", "o"],
    "activity": [".", "..", "..."]
  }
}

覆盖键使用 UI 符号词汇，包括 status.*、nav.*、tree.*、boxRound.*、boxSharp.*、sep.*、icon.*、thinking.*、md.*、lang.*、tab.* 和 tool.*。未知键会被忽略。spinnerFrames 也可以是一个非空字符串数组，同时应用到两个 spinner；在对象形式中，status 和 activity 各自可选，但至少必须存在一个且非空。

重新加载并检查可读性

一旦已安装的自定义主题在交互式会话中处于活动状态，omp 就会监视该文件。保存有效的 JSON 会在短暂防抖后重绘 TUI；没有重新加载命令。文件暂时缺失、格式错误或不完整时，屏幕上会保留最后一次成功加载的版本。修好后再次保存即可。内置主题是内嵌的，不会被监视。

在保留一个主题之前，请检查普通对话文本、选中行、Markdown 链接和代码、待处理/成功/出错的工具块、diff、语法、每个思考强度、bash 和 Python 模式，以及所有状态行分段。尤其要注意：

  • 保持前景/背景对比度高，包括弱化文本和选中行；
  • 让错误、警告和新增内容在亮度上、而不只是色相上可以区分；
  • 如果主题要分享出去，请同时试一下 truecolor 和 256 色终端；
  • 如果边框或图标字形渲染宽度不对，请选择 ascii；
  • 有用时启用 Color Blind Mode，它在 /settings 中提供：它会把十六进制的 toolDiffAdded 绿色向蓝色偏移；它不会重写调色板的其余部分。

故障排查

主题没有被列出。检查文件是否直接位于当前代理的 themes 目录内、是否以 .json 结尾，以及打开设置列表时它是否已经存在。项目的 .omp/themes 目录不是主题来源。

加载的是另一个主题。不要复用内置名称：内置主题优先。另外检查你是否在 omp 当前检测到浅色背景时改了深色槽位，或反之。

选择时报缺少颜色。自定义主题需要上面完整的 token 集合。只有 thinkingMax 是可选的。

选择时报颜色或变量无效。请使用 #RRGGBB、0–255、""，或一个可解析的 vars 名称。检查 JSON 语法、缺失的变量和引用循环。

启动时回退到 dark。配置的主题找不到或无法通过校验。修复选中的文件，或在 /settings 中选择一个内置主题；初始加载失败时会使用内置的 dark 作为回退。

保存后没有重绘。实时重载只监视当前活动的自定义文件。请先选中它，再保存有效的 JSON。如果编辑器临时替换或删除了该文件，请在最终文件存在后再保存一次。
