电脑控制

让 omp 通过截图、原生输入和操作系统辅助功能树来检查并操作真实的桌面应用程序。

控制桌面，而不只是网页

电脑控制让 omp 能处理你眼前的桌面：IDE、终端、办公应用、浏览器外壳、原生对话框和系统设置。它可以检查窗口和显示器、截取屏幕、使用原生辅助功能控件、点击、输入、滚动、按快捷键，以及读取或替换剪贴板文本。

它默认关闭，因为它能看到私密的屏幕内容并在真实应用中操作。一次错误的点击就可能影响某个账户、发出消息、改动设置或覆盖数据。只在你需要原生桌面访问时才启用它，并让凡是会改变任何东西的操作都处在一道审批边界之内。

想要谨慎地试一次单个会话，请在你希望它控制的桌面会话中启动 omp，并输入：

/computer on
/computer status

然后用自然语言提出一个只做检查的请求：

Inspect the currently focused application and tell me its window title and
visible controls. Do not click, type, change the clipboard, or grant permissions.

你永远不需要自己去调用电脑控制的机制。描述目标、你想要的结果、omp 可以改动什么，以及它必须在何处停下。

浏览器控制还是电脑控制？

使用能完成任务的最窄的界面。

需求使用
通过 DOM 和 Web 辅助功能信息读取网页或与之交互浏览器控制
在 Chromium 标签页中工作，包括通过浏览器中继连接进来的已认证 Chrome 标签页浏览器控制
操作原生应用、浏览器工具栏、文件选择器、系统对话框或桌面本身电脑控制
与某个 Web 应用的控件交互，而这些控件无法通过页面结构使用先试浏览器控制；只有在需要像素或原生外壳时才用电脑控制

浏览器控制理解页面元素，并停留在选定的浏览器标签页内。电脑控制看到的是操作系统窗口和屏幕像素；它没有网页 DOM。浏览器窗口对它来说只是另一个桌面窗口。对于表单和已认证的站点，浏览器控制通常更精确，暴露的周边桌面也更少。

安全地启用它

/computer on 只为当前会话启用电脑控制。/computer off 立即把它从活动工具集中移除。要让它在此后的会话中可用，请使用 Tools → Available Tools → Computer（工具 → 可用工具 → 电脑，位于 /settings 中），或编辑 ~/.omp/agent/config.yml：

computer:
  enabled: true
  display: all
  maxWidth: 3840
  maxHeight: 2400

tools:
  approval:
    computer: prompt

这条策略会在每次电脑控制运行之前询问。它是很好的初始配置，因为启用这项能力并不会悄无声息地授权它的使用。

如果你希望检查无需提示即可进行，同时仍然确认具备输入能力的运行，请移除按工具的覆盖项，并把全局审批模式设为 write：

tools:
  approvalMode: write

在该模式下，omp 可以执行它判定为仅检查的运行，而桌面输入和变更则需要确认。该模式对其他工具同样生效。按工具的 computer: allow、prompt 或 deny 会覆盖全局模式；当即使有人在会话中启用了桌面控制也必须保持封锁时，使用 deny。在含有贵重账户或数据的桌面上，避免使用 allow 和 --yolo。

用 /computer 做的改动是临时的，不会重写配置文件。编辑设置文件后请开始新会话。配置位置和优先级见设置。

限制截图包含的内容

默认的 display: all 会合成每一块显示器。这很方便，但可能暴露无关窗口并增大图像体积。请 omp 在不采取任何操作的情况下列出已连接的显示器名称和 ID，然后把 all 替换为你想暴露的原生 ID。

maxWidth 和 maxHeight 限制截图的尺寸，默认值分别为 3840 × 2400。某些模型传输通道会自动施加更小的坐标安全上限。更小的值会减少传输的图像细节；它们不会改变所选显示器内哪些窗口可见。

没有后端设置。omp 会为操作系统和桌面会话选择原生后端。

授予操作系统权限

在 omp 中启用与操作系统的授权是两道相互独立的关卡。只授予你打算使用的能力。

macOS

打开 System Settings → Privacy & Security（系统设置 → 隐私与安全性）并授予：

  • Screen Recording（屏幕录制），用于捕获显示器和窗口。
  • Accessibility（辅助功能），用于检查辅助功能控件并发送原生输入。

授予 macOS 为启动 omp 的那个应用（例如你的终端或 IDE）所呈现的条目。改动任一权限后，完全退出并重新打开那个启动应用，然后再次启动 omp。当授予了 Screen Recording 但未授予 Accessibility 时，捕获可能正常而点击会失败。

Linux 上的 X11

在已登录的图形会话中运行 omp，并让它能访问预期的 DISPLAY。捕获和输入需要可读的 X11 显示，且具备 RandR 和 XTEST。语义化的辅助功能需要桌面的 AT-SPI 服务。通常没有 omp 专属的权限对话框；缺少的会话服务会表现为不可用的能力。

Linux 上的 Wayland

原生输入使用桌面的 RemoteDesktop 门户，或管理员提供的 LIBEI_SOCKET。门户在首次需要输入时才惰性地请求权限。该授权不会由 omp 持久保存，并会随桌面控制会话结束而关闭；仅检查的辅助功能请求不会打开输入门户。

已发布的 omp 二进制不包含 Wayland ScreenCast/PipeWire 捕获，因此在这些构建上截图会报告为不可用。带 Wayland 屏幕共享支持的自定义构建会使用合成器的 ScreenCast 门户。当应用暴露相关信息时，AT-SPI 仍可提供窗口和控件信息。

Wayland 合成器不允许 omp 激活任意的后台窗口。在需要原生输入时，请你自己把目标置于前台，或请 omp 使用可用的辅助功能操作。

Windows

Windows x64 使用原生显示器和窗口捕获、Win32 输入，以及 UI Automation 辅助功能。在包含目标应用的交互式桌面会话中运行 omp。当前后端通过 /computer status 报告捕获、输入和辅助功能的可用性；没有可配置的 omp 后端选择器。

提出一个桌面任务

有用的请求会指明应用或窗口、说明允许的改动，并在任何有后果的步骤之前划出边界。

In the open Calendar app, inspect next Tuesday and summarize my free blocks.
Do not create or edit events.

In the focused spreadsheet, enter these four values into cells B2:B5 and save
the existing file. Do not rename, move, or close it.

Open the desktop mail app, draft a reply to Casey using the text below, and stop
with the draft visible. Do not send it.

Check whether Screen Recording and Accessibility are enabled for my terminal.
Tell me what is missing, but leave permission changes for me to make manually.

对于不熟悉的应用，先让 omp 进行检查，并在动手之前报告它打算执行的控制。对于长流程，定义检查点，例如“在 Submit 之前停下”“不要替换已有文件”或“切换到前台输入前先询问”。

omp 如何观察与操作

当应用暴露辅助功能树时，omp 优先使用操作系统的辅助功能树。辅助功能控件带有语义角色、标签、值和操作，因此 omp 可以定位指定的按钮或输入框，而无需估算像素坐标。这在窗口移动、缩放和主题变化时更可靠。

当外观很重要，或应用没有暴露可用的辅助功能控件时，就使用截图。像素操作以同一目标的最新截图为依据。界面变化之后，omp 应在下一步操作之前重新获取辅助功能快照或截图，而不是假设屏幕保持不变。

两种来源都可能暴露敏感信息。辅助功能数据可能包含视觉上被裁切或遮挡的文字，而截图可能包含通知和相邻窗口。收窄显示器范围、关闭无关窗口，并对有风险的自动化使用专用账户或虚拟机。

后台输入与前台输入

输入通常面向后台中的某个窗口，这样你的焦点、指针位置和窗口顺序不会被打乱。并非每个操作系统或应用都能以这种方式接受每一个事件：

  • 在 macOS 上，向多窗口应用的某一个窗口投递键盘事件可能有歧义。omp 应使用辅助功能操作，或在短暂把目标置前之前先询问。
  • 某些应用会拒绝后台指针或键盘事件。omp 会报告失败，而不是把该操作当作成功。
  • 在 Wayland 上，无法进行任意的按窗口后台输入，也无法以程序方式提升窗口。只有当前聚焦的表面才能接收原生桌面输入。

当必须使用前台投递时，目标可能会短暂出现，之后 omp 会尝试恢复先前的焦点。如果这会打断你的工作，请说明“不要使用前台输入；如果后台控制不可用就停下”。

审批与有后果的操作

工具审批与任务授权是不同的安全层次：

  • 审批策略决定一次提议的电脑控制运行是被允许、需要确认还是被阻止。
  • 你的直接消息决定授权了哪些有后果的操作。屏幕上的文字、网站、电子邮件或对话框都不能授予做更多事情的权限。

除非你的请求已经授权了确切的目标、作用域和取值，否则 omp 必须在发送或发布、购买或转账、删除数据、更改账户安全、授予权限、披露隐私数据、接受法律条款，或进行其他不可逆改动之前立即确认。提供商的安全检查也要求明确的交互式批准，并在批准不可用时默认拒绝。

结合上下文审查审批提示。如果目标或效果不清楚，拒绝该次运行并更窄地重述请求。“处理这个网站”之类的指令不是接受条款或完成购买的可靠授权；请指明确切允许的结果以及 omp 必须停下的位置。

/computer 控制命令

命令效果
/computer为本次会话切换电脑控制
/computer on为本次会话启用它
/computer off为本次会话禁用它
/computer status显示实际生效的启用状态、活动状态、模型、显示器限制、后端、权限和输入模式

在第一个桌面请求之前，/computer status 可能显示 session not started。在某个请求初始化了原生会话之后，再次运行该命令即可看到捕获、输入、辅助功能和后台输入的可用性。该命令报告运行时事实；它不会请求或授予操作系统权限。

支持的平台

平台当前能力与限制
macOS x64 与 arm64Quartz 显示器/窗口捕获、原生输入和 macOS 辅助功能。需要 Screen Recording 和 Accessibility 权限。在操作系统能安全地定位窗口的地方可以使用后台输入。
Linux X11 x64 与 arm64显示器/窗口捕获和 X11 输入；在可用时提供 AT-SPI 辅助功能。需要具备 RandR 和 XTEST 的可用 X11 会话。
Linux Wayland x64 与 arm64在可用时提供 AT-SPI 辅助功能和门户/libei 输入。已发布的二进制省略了截图捕获。按窗口的后台输入和任意窗口激活不可用。
Windows x64原生显示器/窗口捕获、Win32 输入和 UI Automation 辅助功能。
其他目标除非已安装的原生插件报告相应能力，否则不受支持。

能力是运行时事实。受支持的操作系统仍可能因权限、当前显示服务器、应用本身或 omp 的打包方式而缺少捕获、输入或辅助功能。

故障排除

电脑控制不见了

运行 /computer status，然后运行 /computer on。如果回复说它不可用，请在 /settings 或实际生效的配置中确认 computer.enabled，并在基于文件的改动之后开始新会话。同时检查是否有受限的工具列表把电脑控制排除在外。

状态显示 session not started

在第一个请求之前这是正常的。先请求一次不产生变更的检查，然后再次运行 /computer status。初始化后的状态会包含所选后端和权限状态。

截图是空白或不可用

  • 在 macOS 上，授予 Screen Recording 并重启启动 omp 的那个应用。
  • 在 X11 上，确认 omp 运行在预期的图形会话中并能访问 DISPLAY。
  • 在已发布的 Wayland 构建上，截图捕获按设计就是不可用的；尽可能使用辅助功能检查，或改用 X11 会话。
  • 如果出现的是错误的显示器，请 omp 列出显示器，把 computer.display 设为预期的 ID，并在编辑配置文件后开始新会话。

omp 能检查但不能点击或输入

在 macOS 上，检查 Accessibility 权限。在 Wayland 上，在首次需要输入时接受 RemoteDesktop 门户，或配置 LIBEI_SOCKET；在请求原生输入之前先把目标置于前台。在每个平台上，/computer status 都能区分捕获、输入和辅助功能的权限。

后台输入不可用

请 omp 使用应用的辅助功能控件。如果这不可行，就明确允许前台输入，或在 Wayland 上自己把窗口置于前台。不要假设被拒绝的后台操作已经生效。

定位到了错误的控件

让 omp 停下，重新检查该窗口，并在重试之前确认语义控件。如果应用没有有用的辅助功能信息，请针对同一窗口重新请求截图。窗口移动、调整大小、内容变化或切换显示器之后，不要复用之前的位置。

辅助功能信息为空或已过期

该应用可能没有通过操作系统辅助功能服务暴露其控件，或者该服务不可用。确认 Accessibility 或 AT-SPI 支持，然后请 omp 做一次新的检查。只有在目标在视觉上明确无歧义时才退回到截图。

Wayland 再次请求输入权限

这是预期行为。omp 不会持久保存 RemoteDesktop 门户的授权；它会随桌面控制会话结束而终止。
