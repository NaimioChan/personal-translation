MCP

通过 Model Context Protocol 服务器，把 omp 连接到外部服务和本地程序。

连接你的第一个服务器

当某个服务或工具已经发布了 MCP 服务器、而你想让 omp 与它协作时，就使用 MCP——例如搜索问题跟踪器、查询数据库，或使用当前项目之外的文件系统。你只需配置一次服务器，然后用日常语言提出工作请求。

最快的途径是 omp 内的引导式设置：

/mcp add

当在这个仓库中工作的每个人都应发现该服务器时选择 Project；当它只属于你时选择 User。设置完成后立即验证：

/mcp test filesystem

测试成功会显示服务器名称和版本、工具数量，以及最多十个工具名称。之后你就可以这样提问：

使用 filesystem MCP 服务器汇总我 Documents 文件夹中的 Markdown 文件。

你不需要用内部名称来指名 MCP 工具。

最小配置

对于本地服务器，在项目中创建 .omp/mcp.json。这个示例启动官方 filesystem 服务器，并只授予它访问一个目录的权限：

{
  "$schema": "https://raw.githubusercontent.com/can1357/oh-my-pi/main/packages/coding-agent/src/config/mcp-schema.json",
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/alice/Documents"
      ]
    }
  }
}

请把路径换成你机器上的绝对目录。省略 type 时，stdio 是默认传输方式。

如果你在 omp 运行时编辑该文件，请用以下命令应用并验证更改：

/mcp reload
/mcp list
/mcp test filesystem

/mcp list 会按来源对服务器分组，并显示每个服务器是已连接、正在连接、未激活、已禁用还是未连接。

omp 在哪里查找

你通常不需要复制已有的 MCP 配置。omp 会自动从 Claude Code、Codex、Gemini CLI、OpenCode、Cursor、Windsurf、VS Code、已安装的插件和扩展包中导入受支持的服务器定义。运行 /mcp list 可查看发现了什么，以及是哪份文件提供的。

对于由 omp 自己管理的配置，优先使用：

作用域文件用于
项目.omp/mcp.json由该仓库共享的服务器定义
用户~/.omp/agent/mcp.json默认配置文件中你个人的服务器
命名配置文件~/.omp/profiles/<name>/agent/mcp.json隔离在 omp --profile <name> 下的服务器
可移植回退项目根目录下的 mcp.json 或 .mcp.json与其他 MCP 客户端共享的最低优先级文件

项目 MCP 发现默认启用。遇到重复服务器时，先找到的定义生效；定义不会被合并。/mcp add、/mcp enable、/mcp disable 和 OAuth 命令只写入 omp 管理的文件，不会写入其他应用的配置。

传输方式

请选择服务器所发布的传输方式。以 /sse 结尾的 URL 本身并不会选定 SSE；对每个远程服务器都要显式设置 type。

传输方式必需字段何时使用
stdiocommand；可选 args、env、cwd一个本地可执行文件。type 可以省略。
httptype: "http"、url；可选 headers一个托管的 Streamable HTTP 服务器。新的远程集成请使用它。
ssetype: "sse"、url；可选 headers一个明确要求旧式传输的遗留 HTTP+SSE 服务器。

一条最小的 Streamable HTTP 配置项如下：

{
  "$schema": "https://raw.githubusercontent.com/can1357/oh-my-pi/main/packages/coding-agent/src/config/mcp-schema.json",
  "mcpServers": {
    "acme": {
      "type": "http",
      "url": "https://mcp.example.com/mcp"
    }
  }
}

一个服务器不能同时拥有 command 和 url。

认证与密钥

Bearer token 与 API key

本地进程的凭据放在 env 中，HTTP/SSE 的凭据放在 headers 中。请引用环境变量，而不是把密钥提交进仓库：

{
  "mcpServers": {
    "acme": {
      "type": "http",
      "url": "https://mcp.example.com/mcp",
      "headers": {
        "Authorization": "Bearer ${ACME_TOKEN}"
      }
    }
  }
}

omp 在加载文件时会展开服务器配置中的 ${VAR} 和 ${VAR:-default}。在 env 和 headers 中，如果整个值就是一个环境变量名，也会从进程环境中解析。以 ! 开头的值会运行其后的 shell 命令，并使用其去除首尾空白后的输出；只在你信任该命令时才这样做。

虽然 schema 接受 auth.type: "apikey"，但它不会获取并注入 API key。API key 请使用 env 或 headers。

OAuth

对于支持 OAuth 的 HTTP 或 SSE 服务器，请不写 token，改为运行：

/mcp reauth acme

omp 会打开授权流程，并把凭据存到当前配置文件的认证存储中（agent.db，或所配置的 auth broker），而不是存进 mcp.json。使用 /mcp unauth acme 移除它。如果提供商要求注册客户端，只需添加它要求的设置：

{
  "mcpServers": {
    "acme": {
      "type": "http",
      "url": "https://mcp.example.com/mcp",
      "oauth": {
        "clientId": "${ACME_CLIENT_ID}",
        "clientSecret": "${ACME_CLIENT_SECRET}"
      }
    }
  }
}

OAuth 凭据与当前配置文件和服务器 URL 绑定。同一配置文件可以在另一个检出目录中为同一 URL 复用该凭据。显式的 Authorization 标头优先于托管的 OAuth，因此在重新授权前请移除过期的标头。

检查与控制服务器

命令你会看到或改变什么
/mcp list已配置和已发现的服务器、来源文件、传输方式和连接状态
/mcp test <name>一次临时连接测试、服务器版本、工具数量，以及最多十个上游工具名称；按 Esc 取消
/mcp reload重新发现配置文件，并重建当前会话的 MCP 连接和工具
/mcp reconnect <name>重连一个已知服务器，而不重新发现每个配置文件
/mcp enable <name>启用一个服务器；对于导入的配置，会创建用户级覆盖
/mcp disable <name>按名称禁用一个服务器，包括从其他工具导入的服务器
/mcp reauth <name>替换当前配置文件的托管 OAuth 凭据
/mcp unauth <name>移除该托管 OAuth 凭据
/mcp resources列出已连接服务器提供的资源和资源模板
/mcp prompts列出已连接服务器提供的提示词及其斜杠命令名称
/mcp notifications显示通知支持情况、订阅，以及是否启用了更新注入
/mcp remove <name> [--scope project|user]删除 omp 管理的定义；project 是默认作用域
/mcp help显示当前命令参考

/tools 显示 omp 当前可见的所有工具。名称被转为小写并规范化为下划线之后，MCP 工具名会以 mcp__<server>_<tool> 形式出现。omp 可能会去掉重复的服务器前缀，或缩短过长的名称。这些名称帮助你识别某项能力来自哪里；请继续用自然语言提出工作请求。

已连接的服务器还可能发布提示词、资源和通知。/mcp prompts 会以 /server:prompt 的形式显示可调用的提示词命令。只有在启用 mcp.notifications 时，资源更新才会进入对话；默认关闭。

安全

把每个 MCP 定义都当作可执行的、可信的配置：

  • stdio 服务器会以你的用户权限运行其配置的命令。打开陌生仓库之前，请先检查项目的 MCP 文件。
  • 只授予最小的可用文件系统根目录、OAuth 作用域、数据库权限和 API 权限。
  • 远程服务器会收到每项请求操作所需的参数和数据。只使用你信任的端点和服务器包。
  • 绝不要提交 token 或客户端密钥。优先使用环境变量、可信的密钥命令或托管 OAuth。
  • 由于 OAuth 按 URL 绑定到配置文件，一个不可信的检出目录如果定义了相同 URL，就可能用上该配置文件已存储的凭据。对不可信项目请使用单独的配置文件。
  • 要禁用某个不想要的已发现服务器，请用 /mcp disable <name>，而不是编辑其他应用的配置。

故障排查

服务器没有出现在 /mcp list 中

检查 JSON 是否能解析，并且包含顶层 mcpServers 对象，然后运行 /mcp reload。用户级的 disabledServers 条目可能会隐藏该服务器。当 mcp.enableProjectConfig 为 false 时，项目来源也会被跳过。如果该名称存在于多个来源中，优先级更高的定义生效。

远程服务器报 stdio server requires "command"

添加 "type": "http"（遗留服务器则用 "sse"）。没有 type 时，omp 会假定为 stdio。

本地服务器连不上

运行 /mcp test <name>，并检查可执行文件是否已安装、cwd 是否存在、参数是否正确，以及所需环境变量对启动 omp 的进程是否可用。stdio 服务器必须把 stdout 保留给 MCP 协议消息；诊断日志请发送到 stderr。

服务器返回 401 或 403

对于托管 OAuth，请运行 /mcp reauth <name>。如有需要，先使用 /mcp unauth <name>。对于标头认证，请确认环境变量已设置，并移除任何会覆盖 OAuth 的过期显式 Authorization 标头。

连接超时

为每个服务器设置一个以毫秒计的更大 timeout，然后重新加载。默认是 30 秒；0 会禁用客户端侧的 MCP 超时。OMP_MCP_TIMEOUT_MS 会为整个进程覆盖所有按服务器的超时设置。

{
  "mcpServers": {
    "slow-server": {
      "type": "http",
      "url": "https://mcp.example.com/mcp",
      "timeout": 120000
    }
  }
}

遇到临时故障时使用 /mcp reconnect <name>。在更改文件之后，或发现本身就不正确时，使用 /mcp reload。

服务器字段参考

字段适用范围含义
enabled全部除非为 false，否则连接；用户的启用/禁用覆盖可以取代导入的定义
timeout全部请求超时，单位为毫秒；0 表示禁用
requestIdFormat全部默认为 "number"；仅对要求字符串 JSON-RPC ID 的服务器使用 "string"
commandstdio要启动的可执行文件
argsstdio参数数组，不经过 shell 解析
envstdio传给该进程的环境变量
cwdstdio该进程的工作目录
urlhttp、sse远程 MCP 端点
headershttp、sse请求标头，包括 token 认证
oauthhttp、sse用于授权的可选 clientId、clientSecret、redirectUri、callbackPort、callbackPath 和 prompt 设置
auth全部高级的已存储凭据元数据；通常由托管 OAuth 生成/解析，而不是手写

用户配置还可以包含 disabledServers 和 enabledServers 数组。拒绝列表享有最高优先级。

这些相关设置位于 ~/.omp/agent/config.yml（或当前配置文件的配置）中：

mcp:
  enableProjectConfig: true
  renderMarkdownResults: true
  notifications: false
  notificationDebounceMs: 500

以上是默认值。notificationDebounceMs 控制资源更新在进入对话之前会被合并多长时间。
