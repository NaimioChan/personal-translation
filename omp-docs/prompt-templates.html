提示词模板

把一份 Markdown 提示词变成可供你自己或某个项目复用的斜杠命令。

创建你的第一个模板

提示词模板会保存你反复使用的指令，并把它们暴露为一个斜杠命令。可以用它来做一致的审查清单、发布摘要、测试计划，或任何不需要自定义程序逻辑的任务。

在你想要使用该命令的项目中创建 .omp/prompts/review-change.md：

---
description: Review one area of this project for correctness
---

Review the code related to $1.

Focus on: $@[2:].

Report concrete findings first, with file and line references. Then list any
remaining risks or missing tests. Do not change files.

在该项目中启动一个新的 omp 会话，然后输入：

/review-change authentication "error handling and tests"

文件名会创建 /review-change 命令。omp 把 $1 展开为 authentication，把 $@[2:] 展开为 error handling and tests，并把生成的 Markdown 作为你的消息发送。description 会显示在 / 自动补全中该命令的旁边。

用 .omp/prompts/ 存放与项目共享的提示词。若想让命令在所有项目中可用，把同一个 Markdown 文件保存到 ~/.omp/agent/prompts/ 下。

传递参数

参数跟在命令名之后。空格和制表符分隔参数；配对的单引号或双引号会把文本保持在一起，并且引号字符本身会被去掉。

/review-change payments "retry behavior" tests
语法本例中的值
$1、$2、…payments、retry behavior、…
$@ 或 $ARGUMENTSpayments retry behavior tests
$@[2] 或 $@[2:]从第二个开始的所有参数：retry behavior tests
$@[2:1]从第二个开始的一个参数：retry behavior

索引从 1 开始。缺失的位置参数、越界的切片或非正的切片索引都会展开为空字符串。

参数解析器没有反斜杠转义语法。如果某个参数包含空格，请用另一种引号把它包起来，而不是试图转义外层引号。空的引号参数会被丢弃。

如果模板没有任何参数占位符，omp 不会丢弃你提供的文本。它会在空行之后把拼接好的参数追加到提示词末尾：

Summarize the requested part of this project.

调用 /summarize src/auth 会发送该模板，随后跟上 src/auth。

使用 Handlebars 插值

替换 $… 占位符之后，omp 会把结果作为 Handlebars 模板渲染。最有用的值是：

语法含义
{{arg 1}}第一个解析出的参数；arg 从 1 开始
{{arguments}} 或 {{ARGUMENTS}}所有解析出的参数，以空格拼接
{{args}}解析出的参数数组，适合用在块与 helper 中
{{default (arg 1) "current branch"}}第一个参数缺失时的回退值
{{#if args}}…{{else}}…{{/if}}根据是否提供了参数决定的条件内容

例如：

---
description: Draft a test plan for a feature
---

Draft a test plan for {{default (arg 1) "the current change"}}.
{{#if args}}
Additional context: {{arguments}}
{{/if}}

Shell 风格的替换先发生，Handlebars 渲染后发生。参数值中包含的 $1、$@ 或 $ARGUMENTS 不会被递归替换。使用任一风格行内参数占位符的模板也不会再收到自动追加的参数后缀。

对于普通的可复用提示词，优先使用 $1 和 $@ 形式：它们更短，也让调用方式容易理解。只有在你需要默认值或条件段落时才使用 Handlebars。

添加描述

在 omp 提示词模板的 YAML frontmatter 中，只有 description 有特殊含义：

---
description: Explain a failing test and propose the smallest fix
---

把 frontmatter 放在文件开头。如果缺少 description，omp 会在自动补全中使用第一行非空的正文，并截断到 60 个字符。命令名始终来自 Markdown 文件名；frontmatter 中的 name 字段不会重命名它。

发现与命名

在会话启动时，omp 会递归发现以下位置中的 Markdown 文件：

作用域目录自动补全来源标签
用户~/.omp/agent/prompts/**/*.md(user) 或 (user:subdirectory)
项目<working-directory>/.omp/prompts/**/*.md(project) 或 (project:subdirectory)

只有最终的文件名会成为命令名。.omp/prompts/frontend/review.md 和 .omp/prompts/backend/review.md 都定义 /review，而不是带命名空间的命令。即使你把文件组织进子目录，也要给每个模板一个唯一的文件名。

提示词模板是 Markdown 提示词，不是可执行的命令模块。如果某个命令需要运行自定义程序逻辑或显示自己的 UI，请改为构建一个扩展。

优先级

omp 先加载用户模板，再加载项目模板，并使用第一个匹配的名称。因此 ~/.omp/agent/prompts/review.md 会胜过 .omp/prompts/review.md。这与许多“项目覆盖用户”的配置系统不同，所以使用唯一名称是最安全的选择。

其他类型的斜杠命令会先于提示词模板解析。同名的内置命令、扩展命令、自定义命令、技能命令或基于文件的斜杠命令会胜出；与之冲突的提示词模板会从自动补全中省略。

编辑后重新加载

提示词模板在会话启动时读取。omp 不会监视这些文件，/reload-plugins 也不会重新加载它们。创建、重命名或编辑模板后，请退出并在预期的工作目录中启动一个新的 omp 会话。

故障排除

命令没有出现在自动补全中

  • 确认文件以 .md 结尾，并且位于当前工作目录的 .omp/prompts/ 下，或你的用户目录的 ~/.omp/agent/prompts/ 下。
  • 更改文件后启动一个新会话。
  • 检查是否有另一个同名文件名的模板。用户模板会胜过项目模板。
  • 试试更独特的文件名，以防某个内置、技能、扩展、自定义或基于文件的命令已经占用了该名称。
  • 检查会话日志中是否有提示词模板警告。无效的 YAML frontmatter 或不可读的文件会导致该模板无法加载。

参数展开不符合预期

  • 给包含空格的参数加引号：/review-change auth "error handling"。
  • 不要依赖引号参数内的反斜杠转义；它们会被按字面处理，而不是作为转义机制。
  • 记住 $@ 包含每一个参数，包括 $1。若只要剩余部分，请使用 $@[2:]。
  • 如果你需要控制参数出现的位置，就添加显式的占位符。没有占位符时，omp 会把它们追加到模板正文之后。

项目模板没有覆盖我的用户模板

这就是当前的优先级规则：用户模板先加载。重命名其中一个文件，或删除用户级的重复项，然后启动一个新会话。
