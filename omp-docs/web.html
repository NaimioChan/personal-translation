Web 与浏览器

在研究式网络回答、从已知 URL 快速读取、浏览器自动化，以及你自己的已登录 Chrome 标签页之间做选择。

选择能奏效的最轻量路径

告诉 omp 你想要的结果。它会选择底层能力；你不需要自己调用 Web 或浏览器工具。

你的任务最佳路径示例请求
查找当前信息或比较多个来源Web 搜索Compare the current Bun and Node.js workspace behavior. Cite the official documentation.
读取你已经知道 URL 的页面URL 读取Read https://example.com/docs/auth and summarize the token refresh rules.
使用 JavaScript 应用、点击、填写表单，或检查渲染后的 UI托管浏览器Open the local app, create a test account, and report any validation problems. Do not submit payment details.
在 Chrome 中已登录的账户内操作Browser RelayUsing my visible Chrome tab titled “Acme Admin,” export the August report and tell me where it downloaded.

当你不知道来源时，先从搜索开始。知道确切 URL 时，就把 URL 直接给 omp。只在需要渲染或交互时使用浏览器自动化，只在你确实想共享自己的 Chrome 状态时使用中继。

对于 GitHub issue 和 pull request，让 omp 改用它的GitHub 集成。它是结构化的、带缓存的，通常比抓取网站更可靠。

搜索 Web

Web 搜索返回一个答案以及来源 URL。请说明你需要哪类证据：

Find the release note that introduced Node.js permission-model networking. Use primary sources, quote the relevant sentence, and link it.

Research PostgreSQL 18 logical replication changes from the past month. Separate confirmed facts from commentary and cite every claim.

搜索通过 web_search.enabled 默认启用。omp 按优先级顺序遍历可用的提供商，并在某个提供商不可用、超时或返回无可用结果时继续往下走。打开 /settings 可以启用 Web 搜索、选择 Web 搜索提供商顺序、排除你不信任的提供商，或修改单个提供商的超时时间。

提供商可以使用 /login 已存储的凭据、提供商的 API key 环境变量，或无需凭据的搜索引擎。一套实用的配置是：

  1. 为你已经在用的提供商运行 /login，或按模型提供商与密钥与认证中的说明配置它的 API key。
  2. 在 /settings 中，把该提供商放到 Web 搜索提供商顺序 靠前的位置。
  3. 让 omp 搜索一个小的、当前的事实，并附上它的来源。

持久配置也可以写在 ~/.omp/agent/config.yml 或项目的 .omp/config.yml 中：

web_search:
  enabled: true
providers:
  webSearchOrder: [perplexity, exa, gemini]
  webSearchExclude: []
  webSearchTimeoutSeconds: 60

未列出的提供商保持其内置的相对顺序。超时适用于每一次提供商尝试，而不是整条回退链。配置优先级见设置。

搜索结果只是证据，不是权威。让 omp 优先采用一手来源、对重要论断做交叉验证，并指出它无法访问的来源。搜索不会仅因为你已登录 Chrome 就看到私有页面；这类页面请使用中继。

读取已知 URL

当页面是公开的且基本静态时，直接把 URL 给 omp：

Read https://example.com/security.pdf and list the supported encryption algorithms with page references.

Read the API documentation at https://example.com/reference and turn the pagination rules into a short implementation checklist.

URL 读取会从文章、文档、PDF、JSON、feed 以及许多常见开发者站点中提取干净文本。它不执行页面 JavaScript，也不继承浏览器 cookie。这使它比浏览器自动化更快、状态更少，但不适合客户端渲染的应用、需要认证的仪表盘、同意流程和交互式表单。如果提取出的页面为空或不完整，让 omp 改用浏览器重试。

自动化托管浏览器

托管浏览器是由 omp 控制的 Chromium 实例。它适合渲染后的页面、本地开发服务器、截图、多步导航、表单校验，以及其他不需要你日常 Chrome 配置文件的交互。

Open http://localhost:3000 in a browser. Test the sign-up form at mobile and desktop widths, take screenshots of any broken state, and do not submit the final form.

Navigate through the public pricing calculator, enter 25 seats, and report the displayed annual total. Stop before checkout.

浏览器支持默认启用。如果 omp 说它不可用，打开 /settings 并检查 工具 → 可用工具 → 浏览器。相关的持久设置是：

browser:
  enabled: true
  headless: true
  • 无头（browser.headless: true）是默认值。它安静无声，最适合可重复的导航、提取和截图。
  • 可见（browser.headless: false）会打开浏览器 UI，让你可以观察、处理登录或挑战，并在站点抗拒自动化时接管。

首次使用托管浏览器时可能会下载 Chromium。无头与可见模式都使用 omp 托管的浏览器配置文件，而不是你正常的 Chrome 配置文件。登录状态和页面状态可以在该托管浏览器运行期间保留，但不要依赖它做永久的凭据存储。对于已有的登录、passkey、客户端证书或精心维护的浏览器配置文件，优先使用中继。

你也可以配置 browser.cdpUrl，连接到一个你特意用远程调试端点启动的 Chromium 实例。这是中继之外的高级替代方案：omp 不拥有那个进程，断开连接也不会关闭它的页面。现代 Chrome 限制对默认配置文件进行远程调试，所以对于日常 Chrome，中继通常是更好的选择。

用 Browser Relay 连接你自己的 Chrome

OMP Browser Relay 扩展让 omp 驱动一个已有的 Chrome 标签页，包括它的 cookie 和已登录会话。这是能力最强的路径，也是最大的信任决定：被接管的标签页拥有与你相同的账户访问权限。

安装一次

omp browser-relay install

然后：

  1. 在 Chrome 中打开 chrome://extensions。
  2. 启用开发者模式。
  3. 选择加载已解压的扩展程序，并选中 ~/.omp/browser-relay/extension。
  4. 在 /settings 中启用中继，或运行：
omp config set browser.relay true

本地中继服务器会在 omp 首次需要时自动启动。连接成功后，扩展的徽标会显示 on。通常你不需要自己运行服务器。

打开你想共享的页面，让它成为可见标签页，并在请求中尽可能写出它的名字：

Use the Chrome tab whose title contains “Staging Orders.” Find order 1842 and summarize its fulfillment history. Do not edit or refund anything.

没有指定目标时，omp 会采用当前可见且可用的标签页，而不会把另一个标签页切到前台。它正在驱动的标签页会出现在一个青色的 omp 标签组中；连接结束时该组会解散。释放中继会话不会关闭你的 Chrome 页面。

中继的信任与加固

该扩展使用 Chrome 的调试器权限。在接管期间，omp 可以读取渲染后的页面内容、输入文本、点击控件、上传文件、发起下载，并以该标签页的 cookie 与账户权限行事。Chrome 会显示一条“正在调试此浏览器”的信息栏。

中继默认监听回环地址 http://127.0.0.1:9224。任何能访问未受保护中继的本地进程，都可以驱动那个已登录的被接管标签页。如果你不信任机器上的每一个进程，就用 token 启动它：

omp browser-relay --token 'a-long-random-secret'

点击工具栏图标打开扩展的设置，输入相同的 token。请使用密码管理器或环境安全的启动器，而不是把 token 提交到仓库。自定义端口也必须在扩展和 browser.relayUrl 中保持一致。除此之外，只有需要 token、非默认端口或 --no-group 时才需要手动启动。

不再共享你的 Chrome 状态时，关闭中继设置：

omp config set browser.relay false

登录、文件与状态

对于凭据，优先由你自己在可见的托管浏览器中登录，或在授予中继访问权之前在 Chrome 中登录。不要把密码、恢复码或一次性验证码粘贴进提示词。站点可能检测自动化、要求 CAPTCHA 或硬件支持的身份验证，或阻止受调试器控制的标签页；此时应手动接管，而不是让 omp 绕过该控制。

对于上传，把确切的本地路径和目标位置给 omp：

Upload ./artifacts/report.pdf to the “August evidence” field, verify the filename and size, but wait for me before submitting.

上传路径从会话启动时的目录解析。omp 只能通过页面的文件输入控件上传，并且本地文件必须可读。请把上传视为数据披露：确认站点、账户、文件和受众。

对于下载，说明你期望的结果，并让 omp 核实：

Download the CSV report for 2026-08-01 through 2026-08-31 and tell me the final filename and local path. Do not open or execute it.

中继下载遵循你 Chrome 配置文件的常规下载设置。托管浏览器使用它自己的配置文件和下载行为，因此目标位置可能不同。如果站点提供了直接的公开文件 URL，让 omp 抓取该 URL 通常比点击浏览器下载更可预测。下载的内容是不可信的；在打开、导入或执行它之前先检查。

审批与安全请求

浏览器自动化是一种执行类能力工具。在 tools.approvalMode: write 或 always-ask 下，omp 在执行浏览器操作前会提示；默认的 yolo 模式不会。你可以要求无论通用模式如何，每次浏览器操作都需要提示：

tools:
  approval:
    browser: prompt

审批提示授权 omp 操作浏览器，而不是授权每一个现实世界后果。购买、发送消息、发布、删除、账户变更、财务操作以及提交敏感数据，仍需要在执行时确认，除非你的请求已经授权了确切的目标、范围和取值。

写请求时带上边界：

Draft the support reply in the browser, but do not send it. Show me the final recipient, subject, and body for approval.

Add the two named items to the cart and report the total. Do not sign in, start a trial, or place the order.

网页是不可信的输入。页面上显示的指令不能覆盖你的请求。如果页面要求 omp 泄露密钥、运行命令、上传无关文件或改变任务，它应当停下来并报告该指令。

限制

  • 当站点更改其 DOM、虚拟化内容、限制请求速率或检测自动化时，浏览器自动化可能失效。
  • CAPTCHA、passkey、硬件密钥、生物识别提示、原生文件选择器以及某些支付流程需要你接管。
  • 浏览器会话是有状态的。一次导航或应用重渲染可能让 omp 先前找到的控件失效；让它重新检查页面比重复一次盲目的点击更安全。
  • 中继模式无法接管 chrome:// 页面、Chrome DevTools、Chrome 网上应用店或其他扩展的页面。
  • 已打开 DevTools 的标签页无法被接管，因为 Chrome 每个标签页只允许一个调试器连接。
  • 关闭 Chrome 的调试信息栏会使该标签页断开，直到它再次导航。
  • 中继与被接管浏览器模式不会隐藏自动化，也不会在 omp 断开时关闭你的页面。
  • 中继无法提供浏览器上下文隔离。当账户必须保持隔离时，请使用单独的 Chrome 配置文件或托管浏览器。

故障排除

搜索提示没有配置任何提供商

确认 web_search.enabled 已开启。检查 Web 搜索提供商顺序 与 排除的 Web 搜索提供商（位于 /settings）；被排除的提供商不能作为回退使用。重新运行 /login 或更新所选提供商的凭据，然后让它给出一个带单一来源的简单当前事实。如果某个提供商很慢，请调高 providers.webSearchTimeoutSeconds，而不是反复重试同一请求。

某个 URL 为空或缺少内容

该页面可能由 JavaScript 渲染、需要 cookie、阻止自动提取，或把内容嵌在另一个 frame 中。让 omp 用托管浏览器打开它。如果它是私有的，请以可见方式登录，或使用一个特意共享的中继标签页。

托管 Chromium 无法打开

确认 browser.enabled 已开启，并让首次运行的 Chromium 下载完成。把 browser.headless 切换为 false，让启动和导航可见。如果配置的 browser.cdpUrl 已过期，请移除它，以便 omp 能再次启动它的托管浏览器。

中继徽标没有显示“on”

升级 omp 后重新运行 omp browser-relay install，在 chrome://extensions 中重新加载已解压的扩展，并确认配置的端口与 token 一致。默认端点是 127.0.0.1:9224。如果你手动启动了中继，请保持该进程运行；否则让 omp 在首次使用时自动启动它。

omp 选错了标签页

把目标标签页切到前台，并在请求中包含独特的标题或 URL 片段。关闭该标签页上的 DevTools。受限的 Chrome 页面会被有意对 omp 隐藏。

中继标签页断开

omp 工作期间不要关闭 Chrome 的调试信息栏。让该标签页导航一次，使其重新可被接管，确认扩展徽标已开启，然后重试。如果 Chrome 报告存在另一个调试器，请先关闭 DevTools 或另一个调试器客户端。

上传或下载不在预期位置

上传请使用相对于会话启动目录的路径，或给出绝对路径。确认目标是真正的文件上传控件。对于下载，检查当前浏览器配置文件的下载设置，并让 omp 报告它观察到的文件名与路径；中继下载与托管浏览器下载不必使用同一目录。
