安全扫描

在后台执行一次明确限定范围、只读的安全审查，然后检查、验证、比较并导出其发现结果。

决定要审查的内容

当你想对仓库、敏感目录、未提交的工作树，或两个 Git 修订版本之间的变更进行以漏洞为重点的审查时，请使用 omp 原生安全扫描。它适用于发布前、身份验证或授权变更后、解析器和网络边界附近，或对高风险 diff 进行第二轮检查。它会寻找可信的攻击者可控路径及具体影响；它不是一般的风格审查、合规证书，也不能证明不存在漏洞。

安全扫描默认关闭，因为启用它可能会将仓库内容发送给当前模型背后的提供商，发起额外的模型请求，消耗配额，并生成可能包含敏感源代码细节的报告。仅为获准这样处理的仓库和提供商启用它。

最安全的首次运行方式是先制定范围狭窄且明确的计划，再单独启动：

/security plan --path src/auth --exclude src/auth/fixtures --knowledge-base SECURITY.md
/security scan secplan_…

第一条命令会检查并冻结范围，但不会开始模型审查。读取返回的计划 ID 和指纹，然后将该确切计划 ID 传给第二条命令。对于整个仓库的审查，/security scan 是单命令快捷方式：它会执行预检并立即启动。

你也可以用自然语言向 omp 提问，例如：“规划一次 OMP 原生的 src/auth 安全审查，排除生成的 fixtures，并在启动前停止。”当你需要确定性的计划、操作或扫描 ID 时，优先使用斜杠命令。

启用并登录

打开 /settings，进入 Tools → Available Tools → Security，然后将其启用。对于脚本化配置或下次启动时配置：

omp config set security.enabled true

对应的 ~/.omp/agent/config.yml 条目是：

security:
  enabled: true

原生预检还要求满足以下全部条件：

  • 在 Git 仓库内运行 omp；
  • 使用 /model 选择当前模型；
  • 为该模型的提供商保存 OAuth 登录信息。

来自环境、models.yml、--api-key 或通过登录流程保存的 API 密钥，不足以进行原生扫描。请选择支持 OAuth 的提供商路径，并使用 /login <provider>。例如，ChatGPT 订阅模型使用 openai-codex，而不是基于 API 密钥的 openai 路径。

当当前提供商存在多个 OAuth 账户时，请在规划前选择目标账户：

/session pin
/session pin 2

第一条命令列出当前提供商的账户；第二条命令将显示的账户编号固定到此会话。安全预检随后会固定底层持久凭据行及其账户或工作区身份。对于已经知道持久凭据 ID 的自动化流程，也可以使用 --credential ID 计划选项；它不是 /session pin 中显示的位置编号。

选择一个目标

所有 --path 和 --exclude 值都相对于 Git 仓库根目录，即使 omp 是从子目录启动的也是如此。需要指定多个路径时，可以重复任一选项。路径必须存在并解析到仓库内部；排除项优先于包含项。

意图命令审查内容
仓库快照/security plan整个当前仓库。这是默认模式。
一个或多个路径/security plan --path src/auth --path src/session仅指定的文件或目录，减去排除项。此模式至少需要一个 --path。
修订版本范围/security plan --diff origin/main HEAD解析后的基准到头部 Git diff，并针对解析后的头部执行临时分离工作树审查。
工作树/security plan --working-tree将当前工作树记录为工作树审查，包括范围内已跟踪和未跟踪的内容。这不是仅审查变更区块的 diff。

只能选择仓库、修订版本 diff 或工作树意图中的一种。--path 和 --exclude 可以缩小 diff 或工作树扫描的范围：

/security plan --diff v2.4.0 HEAD --path packages/server --exclude packages/server/generated
/security plan --working-tree --path src --exclude dist

仓库、路径和工作树计划会对范围内已跟踪及未跟踪文件的内容、可执行位、符号链接目标和当前 HEAD（或尚未创建提交的仓库状态）计算指纹。引用计划会将两个名称解析为提交 ID，并对其树 diff 计算指纹。因此，删除或更改文件会使旧计划过期，而不会悄悄改变其含义。

--path 和 --exclude 是审查和发布范围，而不是保密沙箱。原生审查者可以检查周围的仓库代码以验证控制流，引用审查也会接收 diff 上下文。不要从包含所选提供商无权处理的材料的工作树启动扫描。

添加指导并选择输出目录

重复使用 --knowledge-base FILE，将安全策略、威胁模型或架构说明固定到计划中。每个文件都从仓库根目录解析，并通过其规范路径、大小和 SHA-256 摘要固定。更改其中任何一项都需要新计划。也应将这些文件视为发送给提供商的扫描输入。

不使用 --output 时，omp 会在此项目的安全状态中分配唯一的私有目录。若要将初始结果包写入其他位置，请选择扫描仓库外的空目录：

/security plan --path src/auth --output /tmp/acme-auth-review

输出目录必须有已存在的父目录，具有规范的非符号链接身份，并且不能位于仓库内。除非明确允许归档，否则会拒绝非空目标：

/security plan --output /tmp/acme-review --archive-existing

扫描启动时，omp 会将现有目录重命名为相邻的 .archive-<scan-id> 路径，并创建新的目标目录。在 POSIX 系统上，生成的目录会强化为 0700，文件会强化为 0600。

预检会冻结的内容

/security plan 会持久化不可变计划，并返回其 ID 和指纹。它会固定：

  • 规范仓库根目录、目标类型、规范化的包含/排除范围以及目标快照；
  • 引用扫描的解析后基准提交和头部提交；
  • 当前提供商、模型、思考强度、确切 OAuth 凭据以及记录的账户/工作区身份；
  • 每个知识库文件的身份；
  • 输出和归档策略；
  • 相关安全设置和版本化的原生审查工作流。

只使用其 ID 启动现有计划：

/security scan secplan_…

启动时会重新计算指纹。如果代码、引用、范围输入、知识库、输出状态、设置或内置工作流发生变化，omp 会以计划过期错误拒绝启动。请再次运行 /security plan；不要尝试重用旧 ID。即使主会话后来更改模型，预检时选择的模型和账户仍会保持固定。

跟踪后台扫描

成功启动后会立即打印扫描 ID（secscan_…）和操作 ID。审查会作为可见的后台任务继续运行，因此主会话无需静默等待。进度依次经过：

queued → preparing → reviewing → publishing → completed

任务还会报告面向用户的里程碑，例如准备扫描、由安全工作者执行审查，以及发布发现数量。使用以下命令检查所有已知操作或某个确切操作：

/security status
/security status <operation-id>

操作快照包含其阶段、时间戳、计划和扫描 ID、当前发现数量，以及可用的会话文件或错误。其他终止阶段包括 partial、cancelled 和 failed。

使用以下命令取消原生后台工作：

/security cancel <operation-id>

取消是协作式的。成功的请求表示已请求停止，并不表示清理已经完成；请持续检查状态，直到它变为 cancelled。已完成或处于其他终止阶段的操作无法取消。

原生扫描会话仅限于只读仓库搜索、只读代码智能和捆绑的安全审查工作者。扩展、MCP 服务器、代理间聊天、shell 执行、模型回退和账户轮换在扫描期间均被禁用。它不会编辑被审查的源代码树。

检查发现和工件

结果按项目存储，不会在不同仓库之间全局混合。请从以下命令开始：

/security scans
/security show <scan-id>
/security show security://scans/<scan-id>/findings
/security show security://scans/<scan-id>/findings/<finding-id>

security:// 命名空间不可变且只读。/security show 可以呈现以下项目资源：

资源内容
security://scans/<scan-id>/manifest公开扫描清单和不可变计划。
security://scans/<scan-id>/findings发现 ID、严重性、标题和规则。
security://scans/<scan-id>/findings/<finding-id>位置、证据、修复建议和操作员处置。
security://scans/<scan-id>/coverage已审查表面、排除项、延期工作、开放问题和完整性。
security://scans/<scan-id>/report发布完成后的 Markdown 审查报告。
security://scans/<scan-id>/sarif可用时提供的 SARIF 2.1 结果。
security://scans/<scan-id>/provenance已删减的生成者和运行来源信息。

已完成的原生输出目录包含 scan.json、findings.json、report.md、results.sarif 和已删减的 provenance.json。规范项目存储仍是实时记录。后续验证或处置变更会更新该记录及其 SARIF，而不会更新原始 Markdown 叙述或已经写入的外部输出目录；需要最新工件时请再次导出。

验证并处置发现

验证和处置回答的是不同问题：

  • 验证询问技术主张是否可复现且与安全相关。/security validate 会要求当前 omp 会话检查所引用的源代码而不修改它，然后记录带有摘要和任何支持证据的 validated、rejected、partial 或 error。发现初始状态为 unvalidated。
  • 处置记录你的处理决定：open、false_positive、accepted_risk、fixed 或 wont_fix。

可以使用扫描/发现对，或确切的发现 URI 进行验证：

/security validate <scan-id> <finding-id>
/security validate security://scans/<scan-id>/findings/<finding-id>

将结果视为模型辅助验证，而不是自动批准。在接受重大结论前，请阅读所引用的代码和证据。

单独记录操作员决定：

/security disposition <scan-id> <finding-id> false_positive "Input cannot cross the authenticated boundary"
/security disposition <scan-id> <finding-id> accepted_risk "Mitigated by the isolated deployment profile"
/security disposition <scan-id> <finding-id> fixed "Patched and covered by the archive traversal regression test"
/security disposition <scan-id> <finding-id> open

每个非 open 处置都需要理由。将发现恢复为 open 会清除其先前的理由。

比较、导入和导出

修复后，在等效范围上再次运行扫描并比较其沿袭关系：

/security compare <before-scan-id> <after-scan-id>

结果会统计未改变、引入和已解决的发现，并标识其匹配 ID。后一次扫描必须为 completed；部分完成、已取消或失败的扫描不能证明先前的发现已经解决。在将结果作为发布门禁前，请同时比较覆盖范围和数量。

将 SARIF 文件或 Codex Security 结果包目录导入当前项目的规范存储：

/security import artifacts/results.sarif
/security import /tmp/codex-security-bundle

导入的路径和发现会根据当前仓库进行验证。使用 /security scans 列出新分配的扫描 ID。

将当前规范状态导出为 JSON 包、SARIF 或 Markdown 报告：

/security export <scan-id> --output artifacts/security-bundle.json --format bundle
/security export <scan-id> --output artifacts/results.sarif --format sarif
/security export <scan-id> --output artifacts/security-report.md --format report

bundle 是默认格式。当前导入命令接受 SARIF 文件和 Codex Security 结果包目录；它不会重新导入 omp 的单文件规范 JSON 导出。当扫描没有对应工件时，报告或 SARIF 导出会明确失败。导出的文件在 POSIX 上使用私有文件权限，但 omp 不会强化已有的父目录；请自行选择并保护目标位置。

原生审查与 Codex Security 云端服务

这是两个独立的产品，绝不会相互回退。

Omp 原生Codex Security 云端服务
执行受限的后台 omp 会话审查本地 Git 工作树或分离的引用目标。ChatGPT 的 Codex Security 控制平面扫描其配置的仓库和环境。
身份验证当前模型提供商的 OAuth，在预检时固定。一个 openai-codex ChatGPT OAuth 账户。这不是公开的 OpenAI API。
范围来自 /security plan 或 /security scan 的仓库/路径/引用/工作树选项。在云服务中配置的仓库、环境和回溯范围。
计费和配额请求计入所选模型/提供商账户。启动扫描会消耗账户单独的 Codex Security 云端扫描额度。
本地结果直接发布到 omp 的项目存储。只有在明确拉取并导入后才会变为本地结果。

云端控制是明确的：

/security cloud scans
/security cloud start --repo-id <repository-id> --repo-url https://github.com/owner/repo --environment <environment-id> --lookback 30
/security cloud status <configuration-id>
/security cloud pull <configuration-id>

使用 --lookback all 可进行无限回溯。只有在需要明确选择已知的 openai-codex 凭据时，才向云端命令添加 --credential <durable-id>。/security cloud scans 会列出所选账户可见的配置，包括仓库和环境 ID、状态、进度，以及服务报告的剩余额度。

云端拉取会获取带归属信息的发现，将其转换为 omp 的规范格式，生成报告和 SARIF，并存储一个已完成的导入扫描。除非当前 Git 项目具有 origin，且其规范化仓库身份与云端配置 URL 匹配，否则它会失败关闭。由于云端发现 API 不提供覆盖范围凭据，导入的云端覆盖范围会标记为 unknown。原生 /security cancel 不会取消云端工作；目前没有 /security cloud cancel 命令。

隐私、凭据和恢复

  • 提供商边界：原生审查会将提示词和检查过的仓库材料发送给当前模型的提供商。云端命令会将仓库配置发送给 ChatGPT 的 Codex Security 服务，由该服务执行远程扫描。请选择获准处理该仓库的账户和服务。
  • 凭据边界：计划存储一条 OAuth 行的引用及记录的身份，而不是轮换使用同级账户的许可。刷新会继续使用该行。如果凭据消失、身份改变、超过刷新期限，或固定的模型不可用，扫描会失败而不会回退。请登录或固定目标账户，选择可用模型，并创建新计划。
  • 工件边界：发现、报告、SARIF、覆盖范围和来源信息可能暴露路径、存在漏洞的流程及修复细节。默认状态和生成文件会使用严格的 POSIX 模式，但这不能替代加密存储、谨慎备份和访问控制。关闭功能不会删除已存储的扫描或导出文件。
  • 重启：进程重启无法恢复正在运行的原生审查。恢复时，omp 会将持久化的 planned 或 running 扫描记录标记为 failed 并附带中断错误，同时清理临时的引用 diff 工作树。检查 /security status 或 /security scans，然后创建并启动新计划。
  • 部分发布或发布失败：未完成规范发布的扫描会处于 partial；取消和执行错误会作为各自的终止记录存储。这类扫描可能没有报告或 SARIF。检查状态错误，修复身份验证、模型或输出条件，然后重新运行，不要将其作为解决证明进行比较。
  • 已完成但缺少外部文件：即使后续输出刷新失败，规范结果也可能已经安全地存储在项目中。使用 /security show 检查，并使用 /security export 写入新副本。

security.enabled 是当前唯一持久化的安全设置。目标、知识库、模型/账户选择和输出策略都属于计划。若不再希望使用 /security 和 security://，请在 /settings 中再次禁用该功能，或运行 omp config set security.enabled false；禁用可用性会保留现有数据。
