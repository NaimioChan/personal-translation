Prewalk

让一个能力强的模型调查并开始一项改动，然后把同一个会话交给更快或更便宜的模型来完成实现。

用力规划，用速度实现

Prewalk 是在一个普通 omp 会话内部进行的一次性模型交接。先用你信任的模型开始，由它理解陌生的仓库、识别风险并组织工作。一旦该模型已经列出待办清单并开始修改项目，omp 就会把当前会话切换到更快或更便宜的目标模型上继续实现。

一个有用的首次运行是：

omp --model @slow --prewalk-into @smol

然后照常描述完整的结果。对话、仓库上下文、待办事项和改动都留在同一个会话里；prewalk 改变的是做剩余工作的模型，而不是任务本身。

对于规划困难但执行例行的改动，这可以降低成本并减少延迟。这是一种权衡，而不是免费的质量提升：目标模型仍然必须理解规划者的待办事项、在实现暴露错误假设时随机应变、测试结果并完成收尾清理。当工作需要反复的设计决策、微妙的调试或高风险的编辑时，请全程使用一个能力强的模型。

启用它并选择目标

Prewalk 默认关闭。用 --prewalk 为某个新会话武装它：

omp --prewalk

这会使用分配给 smol 角色的模型。为了让选择可预期，请在 /model 的 Roles（角色）下分配该角色，或在 ~/.omp/agent/config.yml 中配置它：

modelRoles:
  smol: anthropic/claude-haiku-4-5

要为某一次启动选择不同的目标，请把角色别名或模型选择器传给 --prewalk-into。该标志同时会武装 prewalk，因此不需要再搭配 --prewalk。

omp --prewalk-into @smol
omp --prewalk-into openai/gpt-5-mini

当你需要一个稳定的精确选择时，使用完整的 provider/model-id。已配置的角色也可以带有思考强度，而模型选择器也可以包含它，例如 provider/model-id:medium。omp 使用与其他模型控制相同的角色和模型匹配规则来解析目标。

若要持久选择启用，请设置：

omp config set prewalk.enabled true

等价的 YAML 是：

prewalk:
  enabled: true

启用该设置后，每个全新会话都会被武装并以 @smol 为目标。用 --prewalk-into <model-or-role> 为某次启动覆盖该目标，或用 --no-prewalk 让某个特定会话保持在其起始模型上：

omp --no-prewalk

--no-prewalk 不能与 --prewalk 或 --prewalk-into 组合使用。持久设置不会自动武装一个被恢复的对话；如果你想在继续某个会话时进行交接，请显式传入 --prewalk。

识别这次交接

已武装的 prewalk 会让起始模型先调查并确立实现计划。当待办事项就绪时，第一次完成的文件编辑会启动交接。编辑本身由起始模型完成；目标模型接收同一个会话并从那里继续。

你会看到让生命周期变得明确的提示：

  • Armed（已武装） —— 指出已解析的目标，并说明 omp 正在等待待办清单和第一次编辑或写入。
  • Switched（已切换） —— 指出目标，并报告切换是在第一次编辑或写入之后发生的。
  • Nothing to switch（无需切换） —— 目标模型和思考强度已经与当前会话一致，因此 omp 会解除 prewalk 的武装，而不是执行一次空操作。

如果模型仍只是在阅读、搜索或讨论方案，交接就会等待。如果待办事项已就绪但尚未改动任何项目文件，它就保持武装状态。在待办事项不可用的配置中，第一次完成的文件编辑可以直接触发交接。

Prewalk 是一次性的。切换之后它不再处于武装状态，后续编辑也不会再引起模型变化。目标模型会成为当前会话剩余时间里的当前模型，但该切换不会重写你保存的模型角色设置。模型指示器和切换提示会显示当前哪个模型处于活动状态。

在活动会话中武装它

运行 /prewalk 即可武装一次交接，无需重启，也无需改动 prewalk.enabled：

/prewalk

该命令会解析 @smol、检查它是否可用，并在成功武装时显示目标。它不接受目标参数；如果你需要另一个目标，请在启动 omp 时使用 --prewalk-into。

如果 prewalk 已处于武装状态，/prewalk 会保留既有目标，而不是替换它。在一次交接发生之后，你可以用常规的模型控制选择另一个当前模型，并再次运行 /prewalk 来创建另一次一次性交接。

选择把模型质量花在哪里

好的 prewalk 目标应当已认证、快速、便宜，并且在任务所需的语言和工具上可靠。把预期的节省与修复糟糕实现的成本相比较：

工作形态建议选择
大范围调查，随后是重复的调用点更新强起始模型，快速目标
清晰计划，随后是例行测试或机械性编辑强起始模型，便宜目标
对安全敏感的迁移，或带有隐藏不变量的行为保持能力强的模型处于活动状态
每个结果都会改变下一个假设的调试通常跳过 prewalk
小而显眼的编辑直接在便宜的模型上开始；prewalk 帮助很小

更强的规划者应当留下具体、有顺序的待办事项，并以一次有代表性的编辑开头。如果目标模型经常不得不重新发现约束，就改用更强的目标，或者不要交接。

Prewalk 与子代理

本页描述的是主会话的交接。任务型子代理是一次独立的委派运行，有自己的上下文和模型选择；武装主会话并不意味着每个子代理都会 prewalk。只有在你使用委派代理、并希望在那些运行内部采用同样的先规划后切换模式时，才需要单独配置子代理的 prewalk。参见子代理与 Agent Hub。

故障排除

  • 启动时没有出现已武装的提示 —— 除非 prewalk.enabled 为 true，或启动参数包含 --prewalk 或 --prewalk-into，否则 prewalk 处于关闭状态。被恢复的会话不会从该设置继承自动武装；请显式传入该标志。
  • Warning: prewalk disabled — model … not found —— 目标角色或选择器未能解析。在 /model 中检查实际生效的 smol 分配，或使用 omp models find <name> 返回的完整选择器。
  • Warning: prewalk disabled — no API key for … —— 请对目标提供商进行认证，或选择一个提供商已配置好的模型。omp 会在 prewalk 未武装的情况下继续启动。
  • /prewalk 报告模型或 API 密钥错误 —— /prewalk 始终使用 @smol。修复该角色或其提供商凭据；要使用另一个目标，请用 --prewalk-into 重启。
  • 已武装但没有切换 —— 让起始模型完成调查、创建它的待办事项并开始第一次项目编辑。只读工作和讨论不会消耗这次交接。
  • 第一次编辑已发生但没有跟随切换 —— 检查该编辑是否失败、目标是否已经与当前模型和思考强度一致，或可见提示是否说明 prewalk 在解析目标期间被禁用。
  • /prewalk 说它已为另一个模型武装 —— 既有的那个一次性目标会被保留。让它完成交接，或用期望的 --prewalk-into 目标开始新会话。
  • 切换后质量下降 —— 选择更强的目标、分配更合适的思考强度，或对设计贯穿整个实现过程的任务使用 --no-prewalk。
