会话格式

解析、归档、迁移并检查 omp 保存的 JSONL 会话，而不把持久记录与运行时实时状态混为一谈。

omp 把会话保存为以换行分隔的 JSON（JSONL）：每个物理行一个 JSON 对象。你在审计对话、构建导出器、在机器之间移动会话，或恢复损坏的文件时，都可能遇到它。

最安全的第一步是只读检查。在 omp 数据目录下找到会话，然后在转换之前先复制 JSONL 文件：

find ~/.omp/agent/sessions -name '*.jsonl' -print
jq -c . ~/.omp/agent/sessions/<project>/<session>.jsonl

在默认安装中，根目录是 ~/.omp/agent/sessions。XDG 或 agent 目录配置可以重定位它。项目目录名属于实现细节；请发现文件，而不是构造它们的路径。常规交互式文件名形如 <filesystem-safe-timestamp>_<session-id>.jsonl。子代理会话则可能出现在父会话的兄弟产物目录之下。

把活动文件当作日志来对待：不加锁地读取它，容忍最后一行不完整，并在该轮次结束后重试那一行。要做持久归档或迁移时，请关闭拥有该文件的 omp 进程，并把 JSONL 连同 可移植性与脱敏 中描述的 blob 存储一起复制。不要在 omp 运行时就地编辑会话。尽管大多数记录都是追加的，omp 在迁移或维护期间可能重写文件，而它的定宽标题记录是有意就地更新的。

面向用户的恢复、分支和分享流程，参见会话。

物理文件布局

新写入的版本 3 文件通常按此顺序排列：

  1. 一条可选的定宽 title 记录（当前 omp 会写入它）；
  2. 恰好一个 session 头；
  3. 零个或多个树条目。

每个对象占据一行。空行或格式错误的行不属于该格式。omp 的读取器会跳过格式错误的记录，但一次可写的恢复之后可能重写文件并丢掉它们，因此请修复副本，而不要依赖这种恢复行为。

可变的标题记录

物理第一行是 256 个 UTF-8 字节，包含其换行符。填充位于 JSON 字符串内部，因此它仍然是有效的 JSON： 下面的 pad 值为了可读性已缩短。

{"type":"title","v":1,"title":"refactor importer","source":"user","updatedAt":"2026-05-14T10:14:22.000Z","pad":"                                  "}
字段类型含义
type"title"物理标题槽的判别符。
v1标题记录的格式版本，与会话 schema 版本相互独立。
titlestring当前标题；可以为空，也可能被截断以适配槽位。
source"auto" | "user"?由 omp 还是由用户选定。
updatedAtstringISO 8601 更新时间。
padstring用于把记录保持为恰好 256 字节的空格填充。忽略它。

旧版文件可以直接以 session 头开始。解析器应当同时通过 type: "title" 和 v: 1 识别标题记录，把它从逻辑条目流中移除，并把它的 title 与 source 覆盖到头部元数据上。不要假设第一个物理对象就是头部。

会话头（版本 3）

当前逻辑格式版本是 3。第一个逻辑对象是：

{"type":"session","version":3,"id":"019700f1-1a2b-7c3d-8e4f-aabbccddeeff","timestamp":"2026-05-14T10:12:03.000Z","cwd":"/Users/me/src/api","additionalDirectories":["/Users/me/src/shared"],"title":"refactor importer","titleSource":"user"}
字段类型含义
type"session"头部判别符。
versionnumber?Schema 版本。缺失表示版本 1；当前写入器会输出 3。
idstring会话标识。当前写入器使用 UUIDv7；请把它当作不透明值。
timestampstringISO 8601 创建时间。
cwdstring保存时的绝对主工作目录。
additionalDirectoriesstring[]?多根工作区中的绝对附加根目录。
titlestring?头部标题，在逻辑上会被已识别的物理标题记录覆盖。
titleSource"auto" | "user"?头部标题的来源。
parentSessionstring?仅表示谱系：完整分叉时为源会话 ID，把分支复制到新文件时为源 JSONL 路径。
previousSessionFilesstring[]?成功移动之后记录的先前绝对 JSONL 位置。
providerPromptCacheKeystring?不透明的提供商重放/缓存标识。保留它，但不要解释或生成它。

版本 1 没有 version，并且是线性的。加载它时会分配条目 ID 和父链接。版本 2 已经有树形封装；版本 3 在迁移期间重命名了旧的 hookMessage 角色。omp 会在内存中迁移较旧的文件，并可能在下次可写操作时重写它们。只有在你的集成无法保留未知数据时才拒绝未来版本；否则请保留未知字段和记录。

树条目封装与分支

头部之后的每个逻辑对象都是一个条目，共享以下通用封装：

字段类型含义
typestring条目判别符。
idstring条目标识。通常是 8 个字符的十六进制 ID，但冲突回退和导入数据意味着解析器必须把它当作不透明的非空字符串。
parentIdstring | null此分支上的前一个条目；null 表示一条根路径的起点。
timestampstringISO 8601 持久化时间。这与消息级时间戳不同，后者是 Unix 毫秒。

数组顺序是日志顺序，而不是扁平化后的对话。请构建 id → entry 映射，然后构建 parentId → children 映射。分支是从选定的叶子沿 parentId 走到 null 所得到的祖先链，再把结果反转。同一个父节点的多个子节点是兄弟分支。

文件不持久保存单独的活动叶子字段。加载时，omp 最初根据文件顺序中的最后一个逻辑条目推导叶子；交互式树导航只能在内存中选择不同的叶子。下一条追加的条目会以该选中的条目为父，然后成为最后一条记录。因此：

  • 不要仅凭时间戳推断当前分支；
  • 不要假设每条记录都属于同一份线性对话记录；
  • 检测重复 ID、缺失的父节点、自链接和更长的循环；
  • 往返转换时保留文件顺序，因为它提供了初始叶子。

parentSession 关联的是文件，而 parentId 关联的是一个文件内部的条目。两者都不保证所引用的来源仍然存在。

消息条目

消息条目封装一条持久的代理消息：

{"type":"message","id":"1f9d2a0b","parentId":null,"timestamp":"2026-05-14T10:12:05.000Z","message":{"role":"user","content":[{"type":"text","text":"refactor the importer to stream"}],"timestamp":1778753525000}}
{"type":"message","id":"1f9d2b0c","parentId":"1f9d2a0b","timestamp":"2026-05-14T10:12:06.000Z","message":{"role":"assistant","content":[{"type":"text","text":"Reading the file first."},{"type":"toolCall","id":"toolu_01","name":"read","arguments":{"path":"src/importer.ts"}}],"api":"anthropic-messages","provider":"anthropic","model":"claude-opus-4-6","usage":{"input":1200,"output":45,"cacheRead":0,"cacheWrite":0,"totalTokens":1245,"cost":{"input":0.01,"output":0.01,"cacheRead":0,"cacheWrite":0,"total":0.02}},"stopReason":"toolUse","timestamp":1778753526000}}
{"type":"message","id":"1f9d2c0d","parentId":"1f9d2b0c","timestamp":"2026-05-14T10:12:07.000Z","message":{"role":"toolResult","toolCallId":"toolu_01","toolName":"read","content":[{"type":"text","text":"file contents"}],"isError":false,"timestamp":1778753527000}}

消息角色

角色必需的结构常见的可选持久数据
usercontent: string | (text | image)[]、timestamp: numbersynthetic、steering、attribution、不透明的 providerPayload
developer与 user 相同的 content 和 timestamp 结构attribution、不透明的 providerPayload
assistantcontent: block[]、api、provider、model、usage、stopReason、timestamp: number响应/错误 ID 与详情、持续时间/TTFT、上下文快照、重试恢复、被禁用的特性、不透明的 providerPayload
toolResulttoolCallId、toolName、content: (text | image)[]、isError、timestamp: numberdetails、attribution、prunedAt、useless、提供商元数据

当前的 stopReason 取值是 stop、length、toolUse、error 和 aborted。assistant 的 usage、错误元数据、提供商负载、签名和工具 details 会随提供商和工具而演进。保留未知键；只需要对话记录的消费者可以忽略它们。

内容块

type使用位置核心字段
textuser、developer、assistant、工具结果text: string；可选的不透明 textSignature
imageuser、developer、assistant、工具结果data: string、mimeType: string；可选的 detail、提供商文件引用或 URL
thinkingassistantthinking: string；可选的不透明 thinkingSignature 和 itemId
redactedThinkingassistant不透明的 data: string
toolCallassistantid: string、name: string、arguments: object；可选的签名、意图、原始/提供商元数据
fallbackassistant提供商专属的 { from: { model }, to: { model } } 边界
anthropicServerToolassistant不透明、提供商原生的 block，为重放而保留

通过 message.toolCallId === block.id 把 toolResult 消息与 toolCall 块配对；在分支路径上，仅凭相邻关系是不够的。一个悬空的调用可能是一次实时调用、一个被中断的轮次，或一个其结果只存在于兄弟分支上的调用。

消息内容可能包含密钥、源码文本、命令输出、图像、签名推理和提供商重放负载。它不是经过脱敏的对话记录。

以下所有类型都包含通用树封装。

service_tier_changeserviceTier: object | null。保留提供商家族的映射；不要假设只有一个标量层级。
mode_changemode: string（none 表示退出某个模式），可选的模式专属 data。
compactionsummary、firstKeptEntryId、tokensBefore；可选的 shortSummary、tokensAfter、method、重放标记、details、preserveData、fromExtension、warning。它记录一次上下文重写；它不会删除较旧的日志条目。

有些条目会影响重建的模型上下文（message、压缩与分支摘要、重置、模式/模型/思考变化）；其他则是元数据。这种行为是运行时策略，并不承诺每个持久对象都会原样出现在可见的对话记录中。

扩展拥有的条目

扩展有两种公开的持久化形态：

{"type":"custom","id":"a1b2c3d4","parentId":"1f9d2c0d","timestamp":"2026-05-14T10:12:08.000Z","customType":"com.example.review-state","data":{"approved":true}}
{"type":"custom_message","id":"b2c3d4e5","parentId":"a1b2c3d4","timestamp":"2026-05-14T10:12:09.000Z","customType":"com.example.policy","content":"Use the approved migration plan.","display":true,"details":{"policyVersion":2},"attribution":"agent"}
  • custom 含有 customType: string 和可选的 JSON data。它持久保存扩展状态，不进入模型上下文。
  • custom_message 含有 customType、content: string | (text | image)[]、display: boolean、可选的 JSON details，以及可选的 attribution: "user" | "agent"。它确实参与模型上下文；display 控制 TUI 是否渲染它。

请为 customType 加命名空间（例如使用反向域名），在 data 或 details 内部为负载加版本，并容忍你不理解的版本。第三方解析器应当保留未知条目类型，而不是把当前的内置列表当作穷举。

持久化限制与附属 blob

JSONL 是持久的重放日志，并不总是运行时对象的逐字节转储：

  • 大多数超过 500,000 个字符的字符串会被截断，并附上一条持久化提示；
  • 签名/加密/提供商原生的重放块在截断会破坏重放时会保持完整；
  • 瞬态的 jsonlEvents 数据会被剥离；
  • 足够大的图像负载会从 image.data（以及某些嵌套图像字段）外置为 blob:sha256:<64-lowercase-hex> 引用。

Blob 字节存放在 omp blob 存储中，通常为 ~/.omp/agent/blobs/<sha256>。哈希基于原始二进制字节。因此，一份独立的 JSONL 副本即使能正确解析，也可能是不完整的。请保留整个 blob 存储，或复制每一个被引用的无扩展名哈希文件。遇到格式错误的 blob 引用时应当拒绝，而不是把它的后缀当作路径来解释。

可移植性与脱敏

要做一次忠实的迁移：

  1. 停止或分离正在写该会话的进程；
  2. 复制 JSONL，不改变记录顺序或不透明字段；
  3. 复制被引用的 blob；
  4. 决定 cwd、additionalDirectories、parentSession 和 previousSessionFiles 中的绝对路径是否需要重映射；
  5. 从新位置打开副本，并在删除来源之前核实其树结构。

文件名中的会话 ID 通常与 header.id 一致，但导入器应当做校验，而不是仅凭文件名推导身份。parentSession 和先前文件路径属于来源信息，移动之后可能仍是过期的。

在分享之前，请假设以下所有位置都可能存在敏感数据：

  • user/developer 消息、工具参数、工具结果和 custom 条目；
  • assistant 的思考、被脱敏/加密的块、提供商负载和错误文本；
  • session_init 的系统提示词和任务；
  • 绝对路径和标题；
  • 图像 blob 和提供商原生的文件/响应标识符；
  • credential_pin.hash，当它的输入可被猜出时是可关联的。

脱敏可能使签名推理、加密的重放历史、工具调用/结果配对、压缩引用或 blob 哈希失效。在不需要重放时，导出一份刻意有损的对话记录。如果重放很重要，就在副本上做结构性脱敏：保留 ID 和父链接，在适当处整对移除敏感的块，并预期提供商的缓存/重放元数据将变得不可用。

校验与故障排除

实用的校验器应当报告以下问题，而不是悄悄修复：

  1. 每个非空的物理行都是一个 JSON 对象；
  2. 可选的首个对象是有效的 title v1 记录；
  3. 第一个逻辑对象是 type: "session"，且 id 为字符串；
  4. 版本受支持（缺失即旧版 v1；当前为 3）；
  5. 之后的每个对象都有字符串 type、字符串 id、字符串 timestamp，以及为字符串或 null 的 parentId；
  6. 条目 ID 唯一，且每个非空父节点都能解析；
  7. 父节点遍历能够终止且没有循环；
  8. 被引用的 firstKeptEntryId、targetId 和工具调用 ID 在其语义要求之处能够解析；
  9. 每个规范 blob 引用都有对应的哈希文件；
  10. 最后一个逻辑记录被记为默认的恢复叶子。

有用的只读检查：

# Parse every physical record and show its discriminator.
jq -r '.type' session.jsonl

# Keep file order while inspecting tree links.
jq -c 'select(.id and has("parentId")) | {type,id,parentId,timestamp}' session.jsonl

# List external blob references conservatively.
grep -o 'blob:sha256:[a-f0-9]\{64\}' session.jsonl | sort -u

如果 jq 只在活动会话的最后一行失败，请等待写入者并重试。如果 omp 报告存在格式错误的记录，请保留原始文件、定位出错的物理行，并修复一份副本。如果会话打开在非预期的分支上，请检查最后一个逻辑条目及其祖先链。如果迁移后图像缺失，请恢复被引用的 blob 哈希。如果较旧的文件在恢复之后发生变化，那可能是正常的版本/标题槽迁移，而不是 JSONL 严格只追加的证据。

持久数据与运行时状态

会持久保存且可重建的：

  • 头部/工作区元数据和文件谱系；
  • 有序的条目树、消息、标签、重置边界、摘要和扩展记录；
  • 每个分支上记录的模型、模式、思考、层级、凭据亲和性、用量和提供商重放元数据；
  • 由最后一个逻辑记录隐含的默认叶子。

不作为稳定文件格式状态表示的：

  • 尚未引发追加的、交互式选中的叶子；
  • 进行中的流式增量、待执行的工具执行状态、队列、锁和打开的写入句柄；
  • 实际生成的模型上下文或可见的 TUI 对话记录（两者都按当前运行时策略重建）；
  • 实时的认证密钥、提供商连接、扩展代码、工具实现和当前配置；
  • 不透明提供商元数据在另一个账户、提供商或 omp 版本下仍然可用的保证。

集成应当解析持久的树和声明的负载、保留它们不理解的内容，并避免把保存的文件当作一个序列化的会话管理器进程。
