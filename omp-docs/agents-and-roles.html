代理与模型角色

选择执行工作的模型、选择该模型的路由槽位，以及决定工作如何完成的可复用专家。

模型、角色和代理配置的是不同的层：

层是什么何时修改
模型一个具体的 provider/model，例如 anthropic/claude-sonnet-4-5 或 openai/gpt-5.4。你想要不同的能力、延迟、价格、上下文大小或提供商凭据。
角色一个命名的路由槽位，例如 default、smol 或 slow，它会解析到一个模型。多个功能应跟随同一个模型选择，或你想在不逐个修改调用方的情况下更换它们的模型。
代理一个可复用的行为配置：名称、指令、允许的工具，以及可选的模型、prewalk 和顾问偏好。你想要一个可重复的专家，例如审查者、研究者或设计者——而不只是一个不同的模型。

代理可以指向角色，角色再指向模型。例如 reviewer 代理通常使用 @slow；修改 slow 角色会改变后续审查者运行所用的模型，而不改变审查者做什么。

一个简单的流程

  1. 进入 /model，打开 Roles，为你关心的常用槽位分配模型。先从 default、smol 和 slow 开始；其余的先留作自动，直到你需要可预测的路由。

  2. 进入 /agents 查看内置和自定义代理。选中一个即可看到它的来源、启用状态、生效模型、prewalk 选择和顾问选择。

  3. 用日常语言请 omp 按名称使用该专家：

    用 librarian 核实上游 API 的行为，然后总结来源证据。

    请 reviewer 检查当前改动是否正确。不要编辑文件。

    并行进行 UI 打磨和安全检查：让 designer 处理界面，让 security-reviewer 做只读审计。

  4. 在 Agent Hub 中监督该工作进程。查看它的活动与用量，打开它的对话记录，发送普通的后续消息，或在任务偏离时停止它。

你永远不需要描述 omp 内部的委派协议。说出结果和专家名称，加上范围或安全限制，让主会话去协调工作。

打开并浏览 Agent Hub

按 Alt+A 打开 Agent Hub。Ctrl+S 通过旧版的会话观察绑定打开同一个视图。

还有一个容易被忽略的导航手势：

  • 在空的主会话编辑器中，连按两次 ←。当前会话有可展示的工作进程时，Agent Hub 就会打开。
  • 当焦点位于某个工作进程时，让它自己的编辑器保持为空，连按两次 ← 即可回到主会话。

选中一个工作进程并按 Enter 打开它实时或已保存的对话记录。在那里发送消息会引导正在运行的工作进程，或向空闲的工作进程发送后续消息。Agent Hub 还会显示状态、解析后的模型、当前活动、血缘、token、请求、工具调用、活跃时间，以及可用时的实测成本。用 r 唤回一个已停放的工作进程，用 x 终止一个不应继续的工作进程。

状态、隔离、引导、限制以及完整的控制参考，参见子代理与 Agent Hub。

选择内置代理

这些代理随 omp 一起提供：

代理选择它的场景常规模型路径
scout快速、只读的仓库探索与精简的发现。@smol
designerUI/UX 实现、可访问性与视觉打磨。@designer
reviewer以证据为依据的正确性、质量与安全审查。@slow
security-reviewer只读的漏洞发现与安全分析。当前会话的模型回退
librarian对外部库与 API 进行经来源核实的研究。@smol
task具备全部可用能力的通用多步骤工作。@task
sonic几乎不需要推理的严格机械性编辑或数据收集。@smol

使用最窄的合适专家。只读代理在调查时更安全；没有专家适配时用 task；sonic 用于机械性工作，而不是含糊的设计或审查。打开 /agents 查看你这次安装中的生效定义，因为项目和用户代理可能添加名称或替换内置代理。

选择角色

内置角色既为代理也为产品功能做路由：

角色路由到它的工作
default常规交互式工作以及主会话的默认值。
smol快速、廉价的辅助性工作，以及通常的 prewalk 交接目标。
slow允许额外延迟时的深入推理与审查。
vision由具备视觉能力的模型进行图片检查。
plan计划模式的架构与审查。
designer内置的 designer 代理。
commit提交信息生成。
tiny非常小的后台任务，例如标题、记忆支持和语音清理。
task通用子代理工作。
advisor审查已选择加入的会话或工作进程的独立模型。

未分配的内置角色会从可用的已认证模型中自动解析。当你需要稳定的行为、成本或提供商选择时，在 /model 中分配角色。更改当前对话的活动模型不会改写已保存的角色分配。

模型角色页面涵盖自动选择、项目级存储、思考强度、快速循环、启动覆盖以及重试回退链。

代理如何获得它的模型

对于普通的命名工作进程，omp 按顺序尝试这些来源：

  1. 设置覆盖 —— task.agentModelOverrides.<agent-name>。
  2. 代理默认值 —— 代理的 model frontmatter，其中可以包含一个选择器或一个有序列表。
  3. 常规回退 —— 父会话的活动模型，然后是其已配置/默认的模型回退。

前两层中的选择器可以是具体的 provider/model，也可以是诸如 @slow 的角色别名。角色别名在启动时通过 modelRoles 展开。

若想在不复制或编辑其定义的情况下改道一个已有代理，请使用 task.agentModelOverrides。当多个代理或功能应当一起迁移时，在那里优先使用角色别名：

modelRoles:
  default: anthropic/claude-sonnet-4-5
  smol: openai/gpt-4.1-mini
  slow: openai/gpt-5.4:high
  review: openai/gpt-5.4:high

task:
  agentModelOverrides:
    reviewer: "@review"

在这种配置下，/model 控制由哪个具体模型填充 review，而 /agents 控制 reviewer 是否使用该角色。agentModelOverrides 下的具体模型会绕过代理 frontmatter 中的选择，并且在角色重新分配时不会随之变动。

用户与项目代理

自定义代理定义是带 YAML frontmatter 的 Markdown 文件：

  • 用户作用域：~/.omp/agent/agents/*.md 跨项目可用。
  • 项目作用域：.omp/agents/*.md 属于当前项目。

/agents 会把定义标记为 Project、User 或 Bundled。名称区分大小写。名称冲突时，项目定义胜过用户定义，自定义定义胜过内置定义。这样就能为某个仓库定制像 reviewer 这样的标准名称，但也可能解释为什么它在那个仓库里行为不同。

定义中与模型相关的部分可以保持很小：

---
name: release-auditor
description: Check release readiness and report concrete blockers.
tools: read, grep, glob, bash
model: "@slow"
prewalk: false
advisor: "@advisor"
---

Inspect the assigned release scope. Report evidence and blockers; do not edit files.

这里的 model 参与上面的优先级。prewalk 和 advisor 为该代理提供默认值；/agents 可以在不修改文件的情况下覆盖其中任意一项。用 New agent 在 /agents 中开始一个定义，或参阅编写子代理了解所有受支持的 frontmatter、工具限制、输出形状、技能加载与校验。

在 omp 运行期间编辑代理文件后，回到 /agents 并按 Ctrl+R 重新加载列表。

按代理设置的 prewalk 与顾问控制

在 /agents 中选中一个代理，可配置四个属性：启用、模型、prewalk 和顾问。

  • Prewalk 先让工作进程用其解析后的模型进行规划与早期实现，然后一次性交接给更快或更便宜的目标。on 使用 @smol；off 禁用它；模型或角色模式可选择另一个目标。
  • 顾问会把该工作进程与一个独立的审查模型配对。on 使用 @advisor；off 禁用它；模型或角色模式可选择另一个顾问。

对应的设置会覆盖代理 frontmatter，并可在 ~/.omp/agent/config.yml 中编辑：

task:
  agentPrewalk:
    task: "@smol"
    reviewer: "off"
  agentAdvisor:
    reviewer: "on"
    security-reviewer: "@slow"

更宽泛的默认值与限制请使用 /settings。Generic Task Prewalk 设置（task.prewalk）会影响内置的 task 代理；/agents 中按代理的选择仍然优先。这些系统的完整行为参见Prewalk、顾问模型和设置。

成本与排查问题

每个工作进程都是一个独立的模型会话。并行的工作进程会成倍增加提供商请求与 token 用量；顾问会加上它自己的审查调用，而 prewalk 可能在一个工作进程的生命周期内使用两个模型。当提供商提供足够数据时，Agent Hub 会报告实测用量与成本。先从最小可用的扇出开始，有意识地路由轻量工作，并及时停止过时的工作进程。

如果结果与预期不符：

  • 行为不对：在 /agents 中确认确切的代理名称与来源。某个项目定义可能遮蔽了用户或内置定义。
  • 模型不对：先在 /agents 中查看生效模型，然后按此顺序检查 task.agentModelOverrides、代理的 model frontmatter，以及 /model 中所引用的角色。同时确认所选提供商已通过认证。
  • 代理未知或被禁用：检查区分大小写的名称与启用状态，然后在文件改动后按 Ctrl+R。
  • Prewalk 或顾问没有启动：先检查按代理的覆盖，然后检查 frontmatter、角色分配、模型可用性与凭据。不可用的 prewalk 目标会被跳过，而不是让工作进程失败。
  • 连按两次左方向键没有反应：清空编辑器，并确认当前会话有可展示的工作进程。即使名册为空，Alt+A 也能打开 Agent Hub。
  • Hub 中没有显示工作进程：Agent Hub 的作用域是当前会话。回到或恢复启动该工作进程的那个会话。

要了解详尽行为，请继续阅读模型角色、子代理与 Agent Hub，以及编写子代理。
