会话树

回到之前的某个轮次，尝试另一条方向，同时保留原有对话可供访问。

只要你回到之前的某个点并以不同方式继续，对话就会变成一棵树。omp 会保留你已经走过的路径，并在旁边加上新的路径，所以做实验不需要删掉有用的工作。

最小的操作是：

/tree

用导航器选择你想从哪里继续。

读懂这棵树

/tree 打开一张全会话地图。各行由树线连接，同级的线表示从同一个点出发的不同后续路径。

  • 强调色圆点标记当前活动路径上的每一行。
  • 高亮的那一行是你正在考虑的点；在你按Enter之前它并不是活动路径。
  • 用户与助手的文本用于标识轮次。取决于筛选条件，工具活动和会话事件也可能出现。
  • 标签显示在其所在行之前，作用类似持久的书签。
  • 过深的缩进会用省略号压缩，以便消息文本仍然可读。

默认筛选偏向对话类条目。如果某个会话看起来异常稀疏，按Alt+A显示全部内容。输入消息、标签、角色或工具片段中的任意部分即可缩小地图范围。

• You: Investigate the failing build
  • Assistant: The failure starts in authentication
    ├─ • You: Patch the token refresh path
    │    • Assistant: Tests now pass
    └─ You: First check whether the cache is stale
         Assistant: The cache is healthy

在这里，圆点显示的是活动的 token 刷新路径。缓存检查仍然作为另一条分支存在。

从更早的轮次继续

要修改之前的某个请求而又不丢失它原本的结果：

  1. 运行/tree。
  2. 高亮更早的那条用户消息。
  3. 按Enter。
  4. omp 会移动到那条消息之前的位置，并把该消息——包括它的图片附件——恢复为可编辑的草稿。
  5. 修改草稿并提交。

提交会在旧路径旁边创建一条新的后续路径。原消息、它的回答以及其后的一切仍然可以在/tree里访问到。

如果改为选择某条助手回复，则会直接落到该回复之后，编辑器保持为空。你的下一个提示词就从那里继续。选择当前端点则只会关闭导航器，状态显示为“Already at this point”。

过去的交互式提问同样可以恢复：选择更早的一个ask回答会重新打开提问界面，新的回答会成为旧回答的兄弟节点。

从你离开的路径上带走有用的上下文

当branchSummary.enabled启用时，Enter会提供三个选项：

  • 不生成摘要——只带所选路径上的上下文继续。
  • 生成摘要——把你正在离开的那条路径生成的回顾带入新路径。
  • 用自定义提示词生成摘要——告诉 omp 这次回顾应当保留什么。

按Shift+Enter可以直接生成摘要并切换，而不打开该选项。回顾属于新路径；它不会替换或删除被放弃的路径。摘要生成过程中按Esc可取消并返回树中。

/tree、/branch还是/fork？

这些控制项保留的历史范围各不相同：

控制项结果最适合
/tree在当前会话文件内移动。你的下一次提交会添加一个文件内的替代路径，而所有已有路径仍留在同一棵树里。在保留一份可导航记录的前提下探索替代方案。
/branch遵循Double-Escape Action设置。在默认的Tree设置下，它打开与/tree相同的文件内导航器。把该动作设为Branch后，可选择一条更早的用户消息，并创建一个只包含该消息之前路径的独立会话；所选消息会作为草稿返回。决定 branch 命令是指文件内导航，还是从更早的决策点开一个干净会话。
/fork立即把当前会话——包括它当前的树和产物——克隆到一个新会话，然后切换到该克隆。它不会询问更早的轮次。在进行大范围或有风险的实验之前做一次完整检查点。

一条实用规则：想在同一个地图里比较路径时用/tree。要让/branch创建独立的前缀会话，打开/settings，进入Interaction → Input，把Double-Escape Action设为Branch。想要把当前所有内容完整复制成一份独立副本时用/fork。

该设置同时也决定了在空输入框中连按两次Esc会做什么：打开树、打开分支选择器，或者什么都不做。

/fork需要已持久化的会话，且在回复正在流式输出时无法运行。以--no-session启动的会话不可用。

导航操作

按键动作
↑ / ↓移动一行可见条目；到达两端后循环
Alt+↑ / Alt+↓跳到上一个或下一个用户/助手轮次
Page Up / Page Down 或 ← / →移动一页
Home / End跳到第一行或最后一行可见条目
输入搜索可见的树；Backspace删除搜索字符
Enter切换到高亮的点
Shift+Enter对将要离开的路径生成摘要，然后切换
Shift+L搜索为空时添加、编辑或清除标签
Ctrl+O向后循环筛选条件

如果预计会回到某个特定检查点，就在长时间实验之前加上标签。之后，Alt+L只显示带标签的条目。

持久化与压缩

已完成的轮次和所有分支都保存在会话日志中。普通的树导航不会重写或抹除更早的路径。

所选的会立即成为活动端点。你的下一次提交、一次分支摘要，或正常的会话退出记录，都会在该路径上写入一条记录，因此恢复时会沿着它走。如果 omp 在仅导航移动之后、还没来得及写入任何内容时被杀死，恢复时可能会回到日志中已经记录的上一个端点；重新打开/tree，再选择一次目标路径即可。

上下文压缩改变的是某条路径上发送给模型的上下文；它不会把树压平，也不会删除产生摘要的那些轮次。经过压缩点的路径使用该压缩后的上下文。导航到它之前的某个点，就可以从更早的上下文继续，其他分支也仍然可见。

分支摘要和压缩摘要解决的是不同的问题：

  • 分支摘要把有用信息带过你主动切换到另一条路径的那一刻。
  • 压缩摘要缩短一条活动路径，让对话能够在模型的上下文窗口内继续。

从错误的选择中恢复

如果你移动到了错误的点，不要重建对话：

  1. 再次运行/tree。
  2. 搜索有辨识度的文本，或按Alt+L找一个书签。
  3. 沿树线走到原路径的端点。
  4. 用Enter选中该端点。

原路径会重新变为活动路径。如果你已经在错误的路径上提交过，那些新工作同样会作为兄弟节点保留；返回不会删除任何一侧。

如果希望在实验之前有更强的边界，先用/fork。这样即使实验失败，你也可以通过/resume独立恢复原会话。
