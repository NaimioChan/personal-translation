SDK

把 omp 嵌入 Bun 应用，直接访问会话、事件、配置以及宿主自有的工具。

在你的应用中嵌入 omp

当你的宿主用 TypeScript 或 JavaScript 编写、运行在 Bun 上，并且希望与 omp 共享同一个进程时，就用 SDK。你得到的是与 CLI 相同的代理核心，但提示词的生命周期由你的应用掌控，你能接收流式事件，还能把普通函数暴露为代理工具。

如果需要其他语言、进程隔离或稳定的 JSON 边界，请改用RPC 模式。

1. 安装包

bun add @oh-my-pi/pi-coding-agent

SDK 要求 Bun 1.3.14 或更新版本。它不是 Node.js SDK。

发送由模型驱动的提示词之前，先认证一个提供商。最快的路径是运行omp，输入/login，完成提供商的流程。提供商 API 密钥环境变量同样可用；见模型提供商。

2. 运行一个会话

创建embed.ts：

import { createAgentSession } from "@oh-my-pi/pi-coding-agent";

const { session, modelFallbackMessage } = await createAgentSession({
  cwd: process.cwd(),
});

if (modelFallbackMessage) {
  process.stderr.write(`${modelFallbackMessage}\n`);
}

const unsubscribe = session.subscribe((event) => {
  if (
    event.type === "message_update" &&
    event.assistantMessageEvent.type === "text_delta"
  ) {
    process.stdout.write(event.assistantMessageEvent.delta);
  }
});

try {
  await session.prompt("Summarize this repository in three bullets.");
  process.stdout.write("\n");
} finally {
  unsubscribe();
  await session.dispose();
}

在 omp 应当处理的那个项目里运行它：

bun run embed.ts

文本通过message_update事件逐步到达。工具执行、历史更新、重试和压缩仍然是会话生命周期的一部分；prompt()会在所提交的轮次结束后完成。默认情况下，会话使用当前项目，并像 CLI 一样持久化历史。

默认值与配置

createAgentSession()遵循“省略则自动发现，提供则覆盖”的模式。不传任何选项时，它会发现你的 omp 凭据、设置、模型、扩展、技能、规则、项目上下文、提示词模板、斜杠命令、MCP 服务器和工具。MCP 与 LSP 集成默认启用。

这让最小的示例在既有的 omp 配置里就能用。嵌入方通常只覆盖那些需要自己掌控的部分：

选项何时使用
cwdomp 应当作用于宿主进程项目目录之外的某个目录。
sessionManager宿主需要临时历史、自定义会话位置、恢复或分叉行为。
model或modelPattern模型选择必须确定，而不是从设置中发现。
thinkingLevel宿主想要特定的推理强度选择，例如"medium"或"high"。
settings宿主需要隔离的覆盖值，而不是发现到的配置。
systemPrompt / appendSystemPrompt宿主需要替换或扩展渲染出的系统提示词。
toolNames / restrictToolNames宿主需要请求某些工具或强制一份允许清单。
customTools宿主把应用函数暴露给代理。
extensions / additionalExtensionPaths宿主提供内联或基于文件的扩展。
enableMCP / enableLsp宿主关闭其中某个自动发现的集成。
autoApprove宿主有意退出交互式工具审批。

临时会话与持久会话

默认的会话管理器把历史写入 omp 的会话存储。用于按请求划分的任务时，请使用内存管理器：

import {
  createAgentSession,
  SessionManager,
} from "@oh-my-pi/pi-coding-agent";

const { session } = await createAgentSession({
  sessionManager: SessionManager.inMemory(),
});

需要显式的文件支撑会话时，使用SessionManager.create(cwd)。同一个公开类还提供continueRecent(cwd)、list(cwd)、open(path)以及分叉辅助方法；见会话。

自行掌控模型与设置的选择

当宿主必须自己控制凭据、模型选择和设置、而不是依赖自动发现时，请使用包根导出的接口：

import {
  createAgentSession,
  discoverAuthStorage,
  ModelRegistry,
  SessionManager,
  Settings,
} from "@oh-my-pi/pi-coding-agent";

const authStorage = await discoverAuthStorage();
const modelRegistry = new ModelRegistry(authStorage);
await modelRegistry.refresh();

const model = modelRegistry.getAvailable()[0];
if (!model) {
  throw new Error("No authenticated model is available");
}

const settings = Settings.isolated({
  "compaction.enabled": true,
  "retry.enabled": true,
});

const { session } = await createAgentSession({
  authStorage,
  modelRegistry,
  model,
  settings,
  sessionManager: SessionManager.inMemory(),
  enableMCP: false,
});

同时传入authStorage和modelRegistry时，注册表必须是用同一个 auth-storage 实例创建的。常规的持久化配置及其优先级规则见设置。

进程级的默认AgentRegistry在每一代中只接纳一个顶层Main身份。如果你的应用并发运行多个独立的顶层会话，请给每个会话各自的agentRegistry: new AgentRegistry()。

把事件流进你的宿主

session.subscribe(listener)返回一个取消订阅函数。最有用的公开事件是：

事件宿主用途
message_update流式获取助手内容。assistantMessageEvent.type包括text_delta、thinking_delta、toolcall_start、toolcall_delta、toolcall_end、done和error。
message_start / message_end观察完整的用户、助手和工具结果消息。
tool_execution_start / _update / _end渲染工具进度。结束事件包含结果和可选的isError。
turn_start / turn_end界定一次助手回复及其工具结果。
agent_start / agent_end界定一次代理运行。如果agent_end.isTerminal === false，已排队的异步投递会让会话继续。
auto_compaction_start / _end显示自动的上下文维护。
auto_retry_start / _end显示提供商重试状态。
notice呈现来自会话的信息、警告或错误提示。

事件监听器是通知，不是背压机制：会话不会等待异步监听器。如果顺序重要，请自行把开销大的宿主工作排队。

添加一个宿主自有的工具

CustomTool是一个公开的回调契约。用包导出的z schema 构建器定义它的输入，并为模型返回文本或图片内容。最后的AbortSignal让会话取消能够到达你的 I/O。

import {
  createAgentSession,
  type CustomTool,
  z,
} from "@oh-my-pi/pi-coding-agent";

const lookupTicket: CustomTool = {
  name: "lookup_ticket",
  label: "Lookup ticket",
  description: "Fetch a support ticket by its public ticket ID.",
  parameters: z.object({ ticketId: z.string() }),

  async execute(_toolCallId, { ticketId }, _onUpdate, _context, signal) {
    try {
      const response = await fetch(
        `https://support.example.test/tickets/${encodeURIComponent(ticketId)}`,
        { signal },
      );

      if (!response.ok) {
        return {
          content: [{ type: "text", text: `Ticket lookup failed (${response.status}).` }],
          isError: true,
        };
      }

      const ticket = await response.json();
      return {
        content: [{ type: "text", text: JSON.stringify(ticket) }],
      };
    } catch (error) {
      if (signal?.aborted) throw error;
      return {
        content: [{ type: "text", text: `Ticket lookup failed: ${String(error)}` }],
        isError: true,
      };
    }
  },
};

const { session } = await createAgentSession({
  customTools: [lookupTicket],
});

工具 schema 校验的是形状，不是授权。请在宿主回调里强制租户边界、权限、速率限制和密钥处理。对于模型可以据以反应的预期失败，返回isError: true；抛出的错误只留给取消或意外故障。

toolNames用于请求工具，也能启用默认被禁用的工具，但它本身不是允许清单。要限制会话，请设置restrictToolNames: true。在受限会话中，只有以下三项都成立时，宿主工具才可用：

const { session } = await createAgentSession({
  customTools: [lookupTicket],
  toolNames: ["lookup_ticket"],
  restrictToolNames: true,
  allowRestrictedCustomTools: true,
});

要从自编写的包里加载可复用的工具、命令、钩子和 UI 集成，请使用编写扩展。

控制与清理会话

API行为
session.prompt(text, options?)提交一个提示词。只有当某条本地命令完全消费了该输入时才返回false；否则返回true。
session.steer(text)排队一条指引，在活动运行的下一个安全边界处打断它。
session.followUp(text)在当前运行本应停止之后，排队另一个用户轮次。
session.abort()取消活动工作，并等待代理进入空闲状态。
session.compact(instructions?)显式执行上下文压缩。
session.dispose()幂等地停止自有工作并释放会话资源。务必等待它完成。

在会话已经在流式输出时调用prompt()，需要streamingBehavior: "steer"或"followUp"；对大多数宿主来说，直接调用steer()或followUp()更清晰。

请在每个会话的整个生命周期外层套上try/finally。如果宿主有自己的异步关闭工作，请在第一个关闭用的await之前调用session.beginDispose()，完成宿主的清理，然后await session.dispose()。beginDispose()会关闭新工作的准入；它不能替代dispose()。

处理失败

请在 API 边界和事件边界两处都处理失败：

  • 用try/catch包住createAgentSession()和session.prompt()。配置无效、auth/model 接线不一致、所选模型缺失、API 密钥缺失，或会话正忙，都可能让调用被拒绝。
  • 在message_update中留意assistantMessageEvent.type === "error"，以捕获提供商侧的流式失败。其助手消息带有提供商的错误详情。
  • 留意tool_execution_end.isError，以捕获代理作为结果收到的工具失败。
  • 当恢复会话时无法使用其保存的模型、omp 改选了另一个模型时，请显示modelFallbackMessage。
  • 如果没有任何可用模型，请运行omp并使用/login，设置提供商的 API 密钥环境变量，或者传入显式配置的authStorage与modelRegistry。
  • 失败之后务必销毁会话；重复调用销毁是安全的。

SDK 还是 RPC？

选择最合适代价
SDKBun/TypeScript 宿主，工具用直接回调，可直接访问会话状态，集成开销最低omp 与你的进程、运行时、内存和故障边界共享
RPC任意语言，子进程或服务隔离，按换行分隔的 JSON 协议宿主必须管理进程与协议的生命周期

RPC 以omp --mode rpc启动，并通过 stdio 暴露会话事件。不要仅仅为了两次调用同一个进程就把 RPC 子进程放到 SDK 后面：进程内的 Bun 宿主选 SDK，真正需要语言/进程边界时选 RPC。
