工具索引

omp 能做什么、默认有哪些能力可用，以及在哪里开启或关闭能力与审批。

直接说明想要的结果

通常你不需要自己选择或调用工具。用日常语言告诉 omp 你想要什么：

Find where checkout retries are configured, change the default to three, and verify the behavior.

omp 会选择合适的搜索、编辑与执行能力。只有在你想要约束做法时才点名某种能力，例如“检查一下但不要运行它”“用浏览器，因为这个页面需要登录”，或“不要使用 shell”。

在会话中使用 /tools 查看当前模型和项目实际可用的能力。这是权威的实时视图：设置、已安装的程序、模型支持、任务深度、自定义工具和已连接的 MCP 服务器都会改变它。

控制可用的能力

  • 打开 /settings，使用 Tools → Available Tools 进行持久开关。相关控件也位于 Files、Shell、Memory 和 Tasks 之下。参见设置。
  • 用 omp --tools read,glob,grep 启动受限会话，或用 omp --no-tools 不加载任何内置能力。命令行限制只对该会话生效。
  • 用 omp --approval-mode always-ask、write 或 yolo 为会话设置审批模式。持久等价的配置是 tools.approvalMode，以及按能力配置的 tools.approval.<name> 策略（allow、prompt 或 deny）。参见工具审批。
  • tools.xdev 默认开启。它把不常用和动态发现的能力放在按需目录中，而不是预先加载所有描述。关闭它只改变呈现方式，不改变被允许的范围。

下面的审批类别描述潜在影响：

  • Read（读）在不有意改变状态的情况下检查状态。
  • Write（写）可以更改文件或持久用户数据。
  • Exec（执行）可以运行代码、控制进程、使用网络账户或操作应用程序。
  • Mixed（混合）取决于具体动作。例如 GitHub 读取属于 Read，而检出或推送属于 Exec。

内置审批模式目前默认为 yolo，会自动允许全部三个类别。如果你希望在 Write 和 Exec 动作前得到确认，请选择 always-ask，或用按能力的策略彻底禁止某项能力。项目、插件、自定义工具或 MCP 服务器仍然是必须信任的代码；审批提示不是沙箱。

读取文件与资源（read）解释文件或目录；从文档、笔记本、归档、图片、SQLite 数据库、受支持的内部 URL 和已知网页中提取文本。默认开启。读取网页还需要 fetch.enabled（默认开启）；SSH 和部分图片/PDF 处理会执行本地辅助程序。Read；部分远程/转换路径为 Exec处理文件
查找路径（glob）按名称或 glob 模式定位文件和目录。默认开启，由 glob.enabled 控制。Read处理文件
搜索内容（grep）用正则表达式和上下文搜索本地或受支持的远程内容。默认开启，由 grep.enabled 控制。Read；SSH 搜索为 Exec处理文件
结构化搜索代码（ast_grep）查找与空白和格式无关的语法形状。默认关闭；启用 astGrep.enabled。Read结构化编辑
使用语言智能（lsp）查找定义和引用、检查符号与诊断、应用代码动作，并执行语义重命名。默认开启，由 lsp.enabled 控制；相关语言服务器必须已安装或已配置。--no-lsp 可为单个会话禁用它。Mixed：检查为 Read；修复与重命名为 Write代码智能
理解图片（inspect_image）通过具备视觉能力的模型描述本地图片或回答关于它的问题。inspect_image.mode 默认为 auto：当前模型无法原生检查图片时才会暴露。可显式设为 on 或 off。需要有可用的视觉模型。Read设置
搜索实时网页（web_search）调研某个主题，返回带来源链接的最新结果。默认开启，由 web_search.enabled 控制；至少需要一个已配置的搜索提供商。ReadWeb 与浏览器
处理 GitHub（github）读取仓库、文件、issue、PR 和 diff；搜索 GitHub；检出 PR、推送改动并跟踪 Actions。默认关闭；启用 github.enabled。需要 gh CLI，私有或变更类操作还需要认证。Mixed：查看/搜索为 Read；检出、推送和其他账户操作为 ExecGitHub

调试程序（debug）启动或附加调试器、设置断点、单步执行，并检查线程、栈帧、作用域和变量。默认开启，由 debug.enabled 控制，但仅在存在合适的 DAP 适配器/配置时才会出现。Mixed：检查为 Read；启动与进程控制为 Exec调试
自动化浏览器（browser）打开交互式或重度依赖 JavaScript 的页面、使用已认证的标签页、填写表单、点击控件并截图。默认开启，由 browser.enabled 控制。omp 可以启动浏览器，或通过 CDP、浏览器中继或受支持的 cmux 界面附加；使用中继需要其浏览器扩展。ExecWeb 与浏览器
控制桌面（computer）检查屏幕和无障碍状态，然后用键盘和指针输入操作宿主应用。默认关闭；启用 computer.enabled。需要受支持的桌面辅助程序，以及操作系统的屏幕录制/辅助功能权限。Mixed：检查为 Read；输入为 Exec电脑控制
扫描安全问题（security_scan）规划并运行原生安全检查，查看已发布的发现。默认关闭；启用 security.enabled。各个扫描器可能需要各自安装的二进制文件或凭据。Exec安全扫描

生成语音（tts）用本地语音生成或已配置的语音提供商把文本转成音频文件。默认关闭；启用 speechgen.enabled。所选路径可能需要下载本地模型或提供商标据。Write设置

回答结构化问题（ask）当 omp 无法安全推断答案时，暂停下来询问选择、确认或缺失的细节。默认开启，由 ask.enabled 控制；通知和超时行为可配置。Read设置

面向结果的内置工作流

这些是用户入口，而不是通用工具，但它们可能代你使用上面多种能力。

工作流第一步作用了解更多
代码审查运行 /review，然后选择基线分支、未提交改动、某个提交、某个 PR 或自定义指令。把 diff 分发给多个审查代理，并返回按优先级排序的发现。代码审查
创建提交运行 omp commit；只想预览时加上 --dry-run。分析改动，提出约定式提交分组和变更日志更新，然后提交；推送需主动选择。创建提交
目标模式需要访谈式提问时运行 /guided-goal；目标已经明确时运行 /goal。跨轮次持续推进一个有预算的持久目标。它专用的辅助能力只在目标模式需要时出现。目标模式
计划模式在要求执行有风险或含糊的实现之前运行 /plan。把规划阶段限制为只读探索，并在执行前提交计划供审查。计划模式
Vibe 模式运行 /vibe [prompt] 直接启动持久的快速/优质工作会话。把主会话变成导演，负责启动、引导、验证并停止持久工作代理。Vibe 模式
自动研究把 autoresearch.sh 基准测试脚手架加入干净的 Git 工作树，然后运行 /autoresearch [goal]。在专用的 autoresearch/* 分支上反复运行由基准测试支撑的实验。部分重置/丢弃控件具有破坏性；请先查看仪表板和基线。运行模式

目标模式、子代理或某些模型系列使用的内部完成与推理辅助能力，有意不设为用户可选，也不会显示为可配置项。

添加能力

实时的 /tools 列表可能包含上述内置能力之外的内容：

来源如何变为可用信任与配置
自定义工具会话启动时，omp 会发现用户或项目编写的 JavaScript/TypeScript 工具。它们以你的用户身份运行。加载前请审查项目代码；参见自定义工具。
MCP 服务器已连接的服务器发布自己的工具和资源；默认允许发现项目中的 .mcp.json/mcp.json。服务器可能访问外部账户或执行本地代码。请通过MCP 配置并认证它。
扩展与插件受信任的扩展可以注册工具；插件可以把工具与命令、代理、规则或服务器配置打包在一起。启用前请检查源码和声明的内容；参见编写扩展和插件。
宿主应用SDK、RPC 和 ACP 宿主可以为其会话提供能力。可用性与审批由该宿主控制；参见SDK、RPC 模式和ACP。

报告能力问题

自动化工具 QA（xd://report_issue）默认开启，由 dev.autoqa 控制。当 omp 检测到与某项能力文档化契约相矛盾的行为时，它可以记录一份报告；首次报告会询问你是否同意分享。用 omp grievances 查看已记录的报告，并修改 Tools → Developer → Auto QA（在 /settings 中）来禁用报告。这条支持路径不会给 omp 另一种修改你项目的方式。

如果你预期中的能力缺失，请检查 /tools，然后检查上文对应的启用设置和前提条件。修改已发现的工具、扩展、插件或 MCP 配置后，请重启会话，以便重建实时目录。
