永久运行的装置

作者：Blair Neal

最近工作上我需要布置四个配置各不相同的装置，它们要全天候、每天 24 小时连续运行好几个月，尽量不出崩溃或故障，而且没人会去现场照看。这是很多媒体艺术家经常要做的事，而让东西长期稳定运行有许多不同的技巧和窍门，我想把自己的心得分享出来。很多任务都有别的做法，这只是其中一条路，所以也请在下方留言框里分享你在实践中总结的技巧。

为了找齐让一切持续运行、不出毛病所需的全部信息，我在好几个不同的地方做了好几次搜索。幸运的是，这次我打交道的装置在资源和复杂度上都比较轻，但有个安全网总归是最佳实践。

我通常是在全新的、没开箱的电脑上做这些，所以算是从零开始。我指出的很多东西默认设置都是相反的。

提示：如果你要弄多台电脑，先在其中的一台上完成这些准备步骤，然后把其它机器启动到目标磁盘模式，用 Carbon Copy Cloner 这类工具把第一台镜像到下一台，这样一切都会尽可能一致。

第 1 步：准备好软件和电脑

在构建你的软件或无论什么东西时，始终要把长期运行的装置放在心上。从一开始就规划好哪些东西需要由看管装置的人来调整（至少不要留到最后）。根据我的经验，尽可能保持简单，这样看管者就能方便地进入程序去修整或调整他们需要的东西，而不必打开 Xcode 编译，甚至不必退出你的应用。你现在为简化而花的时间，会在东西出故障时替你省下好几小时的远程调试。

你需要逐项关掉或禁用若干个自动设置，免得它们弹到你的应用上面。具体做法会因你运行的是 10.7、10.8、10.9、10.10 等等而有所不同。

Nick Hardeman 做了一个工具应用，可以在一个地方设置所有这些属性以及更多——点这里看看

在 System Preferences 中：

  • Desktop and Screensaver：禁用屏幕保护程序，把时间设为“Never”。我还建议把桌面背景改成黑色/你应用的截图/客户的 logo——你甚至可以让它们自动切换——记住：只要没人注意到，就不算坏 :)
  • Energy Saver：把 Display Sleep 和 Computer Sleep 都设为 Never。启用“Start up automatically after power failure”和“Restart automatically if the computer freezes”（这两项只在 10.7 及以后版本中可用）
  • Users and Groups：进入 Login Options（在挂锁上方），启用“Automatic Login”
  • Software update：禁用自动更新。
  • Sharing：如果你运行主机的电脑没有接显示器，或者放在不易接近的地方，别忘了打开 File sharing 和 Screen sharing。这样只要你在同一网络上，就能访问并控制这台电脑（如果你担心安全，这一项可选）。
  • Network：如果你不需要远程访问，或装置不需要联网，关掉 Wifi 不是个坏主意，这样“please select a wireless network”窗口就不会在你最意想不到的时候弹出来。你也可以关掉“在找不到合适的网络时询问是否加入新网络”的选项。
  • Bluetooth 如果在没有插鼠标或键盘的情况下运行，有时会冒出烦人的“Bluetooth keyboard/mouse setup”弹窗盖住你的应用。你可以在 Bluetooth Preferences 的高级设置里临时禁用这些。它在 10.6 中的位置见下图。
  • Security：我会确认“Disable Automatic Login”没有被勾选，以免重启时遇到意外。如果你真的很多疑，甚至可以关掉某些 Mac 上仍然存在、MacBook 上肯定有的 IR 遥控接收器。这能防止有人拿 Apple TV 遥控器“Front Row”你的装置。要禁用，进入 Security->General->Advanced（>10.8）并勾选“Disable remote control IR receiver”。
  • Notification Center：你可以完全禁用 Notification Center，也可以把“Do Not Disturb”设成基本上永久开启——用下图那样重叠的时间段来设置

你还可以在终端里运行下面这条命令，或者给 Problem Reporter 应用改名，来禁用“This Application Unexpectedly Quit”以及随之而来的错误报告：

sudo chmod 000 /System/Library/CoreServices/Problem\ Reporter.app

另一个用来修改某些 OSX .plist、禁用或启用某些东西的有用工具是 Tinkertool。你可以用它来禁用或启用 System Preferences 没有覆盖的某些项目。

我还会看看这个文件路径，你可以重命名这里的文件，在你使用的电脑上临时禁用它们：/System/Library/CoreServices

你可以把“Notification Center”改名为“Notification Center_DEACTIVATE”之类的名字（或者把它移走）——这样你就不会再收到任何讨厌的“贴心” Notification Center 弹窗了。

如有必要，你还可以用下面这条终端命令隐藏所有桌面图标：

defaults write com.apple.finder CreateDesktop -bool false

第 2 步：开机即进入你的软件

东西会被拔掉、会停电，不是每个人都有预算或空间装电池备份，等等等等。上面我讲了如何让一切在断电或卡死后自动重启，但你还需要让你的应用一开机就准备好，而不是把桌面敞开给好奇的眼睛。让应用自动加载的办法有很多——最简单的是用 OSX 自带的功能：在 System Preferences 的“Accounts”面板中选择“Login Items”，把你的应用拖进去，它就会在登录时自动打开。

Shell 脚本 + Cron Job 方法

（下面这个超级有用的技巧来自 Kyle McDonald）)

这个方法相对于 launchd 方法来说算是过时了——你可以用 Lingon 和 launchd 以和我们这里一样的方式运行 shell 脚本。Shell 脚本是你最好的朋友。借助下面的脚本和一个叫 CronniX 的应用（或者用 Lingon），你就能用一个 cronjob 来检查系统当前运行的进程列表。如果你的应用不在列表里，脚本就会重新打开它，否则什么都不做。你可以下载这个脚本，或者把下面的内容敲进文本编辑器，把 Twitter.app 换成你应用的名称和文件路径。别忘了 if 语句里的“.app”扩展名！：

\#!/bin/sh
	if [ $(ps ax | grep -v grep | grep "Twitter.app" | wc -l) -eq 0 ] then
	echo "Twitter not running. opening..."
	open /Applications/Twitter.app
	else
	echo "Twitter running" fi

把那个文件保存成类似“KeepOpen.sh”的名字，放在应用旁边或其它方便的地方。

创建好文件后，你需要让它可执行。为此，打开 Terminal，在新窗口里输入“chmod +x ”，然后输入你刚创建的 shell 脚本的路径（你可以把 shell 脚本拖进终端窗口，也可以手动输入）。看起来大概是这样：

4Evr-MacBook-Pro:~ Forever4Evr$ chmod +x /Users/Forever4Evr/Desktop/KeepOpen.sh

让它可执行之后，你就可以把它设为 cronjob 了。提示：要测试脚本，你可以把扩展名改成 KeepOpen.command，作为用 Terminal 打开它的替代方案，但效果是一样的。

Cronjob 就是设定好按定时器运行的低层系统任务。cronjob 的语法超出了本文的范围，但有很多网站可以查到。不过，CronniX 这个应用可以替你完成大量繁重的工作。

下载 CronniX 后，打开它并新建一个 cronjob。在打开的窗口里，于命令窗口中把你的 KeepOpen.sh 文件填进去，然后在 simple 标签页里把 minute、hour、month 等所有复选框都勾上。这就告诉任务要每分钟、每小时、每天、每月运行。如果你希望它运行得更少或频率不同，可以调整滑块。

现在只要点“New”，然后记得点“Save”把它保存进系统的 crontab。之后你只要等一分钟，它应该就会在每分钟整点打开你的应用。如果你还有别的事要做，也许可以把这一项留到最后 :)

如果发生了意外崩溃，这是个很棒的工具，因为应用离线的时间不会超过一分钟。

非 Cronjob——Shell 脚本方法

\#!/bin/bash

while true
do
#用 open 让它获得焦点
echo "Trying to open empty example"
open -a emptyExample
sleep 10
done

把这个敲进一个纯文本文档，保存成类似“KeepMyAppAlivePlz.command”的名字，然后用上面的 chmod 让文件可执行，再像上面那样把它放进你的 login items。这个脚本会持续尝试每隔 10ms 打开你的应用，但如果它已经打开了，操作系统知道不要再尝试打开第二次、第三次、第四次。

无论你是到现场还是远程检查装置，都记得查看 Console.app，看有没有什么错误在没人注意的时候冒出来。这不是给有 bug 的编程打包票的万灵药，只是个让一切运转顺畅的帮手。你能为“崩溃为什么发生”给自己留下记录的手段越多，你定位核心问题的速度就越快。

在需要点开奇怪的菜单、或按某种顺序发送按键这类更偏系统层的操作上，Applescript 也是一个非常可靠的选择。

第 4 步：定期重启

这一条更偏预防性，或者有点迷信，所以希望有人能指出它为什么确实是个好主意的具体理由。取决于你的应用以及它伸进系统多深，可能会有一些你没考虑到的内存泄漏或其它系统 bug。每天或每周重启一下，从系统层面来说能让一切保持整洁。

最简单的选择大概就是进入 System Preferences->Energy Saver，点击“Schedule…”，然后填入一些值——如果你需要在夜间之类的时候让电脑关机休息较长时间，以减轻它的压力。热量有时会造成些奇怪的问题，所以如果你有机会让电脑休息、又有时间测试，绝对值得一试……顺便还能省点电，挺好。

附加技巧：日志

如果你的装置要运行数周或数月，你可能会想要一种不必远程登录查看就能盯着它的办法。一个好办法是让系统里的某个东西把特定信息写进一个文本文件（放在同步的 Dropbox 里），或者更好的是写到一个你可以去查的网页服务器上。

根据你想了解装置状态的哪些方面，有几件事可以做。

有一条终端命令可以列出你电脑上当前运行的所有进程：

ps aux (or ps ax)

（关于 ps 命令的更多信息见这里））——此外，你还可以过滤这个列表，只返回你关心的应用：

ps aux | grep "TweetDeck"

这会返回类似这样的一行：

USER             PID  %CPU %MEM      VSZ    RSS   TT  STAT STARTED      TIME COMMAND
laser          71564   0.4  1.7  4010724 140544   ??  S    Sun03PM  14:23.76 /Applications/TweetDeck.app/Contents/MacOS/TweetDeck -psn_0_100544477
laser          95882   0.0  0.0  2432768    600 s000  S+   12:11PM   0:00.00 grep TweetDeck

现在你有了这些有用的信息：CPU 占用、内存占用（占总内存的百分比）、状态、启动时间、运行时长

剩下的就是把这个输出写进一个文本文件，可以用这样一行做到：

ps aux | grep 'TweetDeck' >> /Users/laser/Dropbox/InstallationLogs/BigImportantInstall/Number6ProcessLog.txt

这一行的意思基本上是——告诉我打开着的进程（px aux）——只给我含有“Tweetdeck”的那些行（grep Tweetdeck）——然后把它们追加到这个位置的文本文件里（>> path_to_text_file）

现在我们只需要把它做成一个可执行的 shell 脚本，并设为 launch daemon 或 cron job——参见上面第 3 步，了解如何用 Lingon 和 launchd 按固定间隔运行 shell 脚本。如果应用没在运行，它只会返回“grep YourAppName”这个进程，这其实是个值得记录的东西，因为如果应用没打开，你就不知道它已经停了多久（什么都不会被记录），但记录了 grep 进程至少能告诉你检查确实发生过。grep 还能更准确地告诉你它是什么时候检查的——另一个应用只会给你启动时间和运行时长。

我们再把这件事推进一步，假设你手上的 Triplehead2Go 显示适配器相当不靠谱，重启后不总能连上显示器或投影仪——或者某个投影仪自己关机了，把事情搅乱。那我们也可以把当前可用的分辨率记下来！在你自己终端里试试下面这一行：

system_profiler SPDisplaysDataType

这会返回已连接显示器的列表，以及一些关于它们的元数据，包括分辨率和名称。

假设你想确保始终运行在 3840×720 的分辨率……或者你想要一份分辨率变化的日志。你可以这样做：

system_profiler SPDisplaysDataType | grep Resolution

这会返回“Resolution: 3840×720”，你可以把它和上面的行结合起来，全部写进一个文本文件。所以，如果你想记录当前运行的进程和当前分辨率，你的 shell 脚本文件会是这样：

    \#!/bin/bash
ps aux | grep 'YourAppName' >> /Users/you/filepath/Install6ProcessLog.txt
system_profiler SPDisplaysDataType | grep Resolution >> /Users/you/Dropbox/Install6ProcessLog.txt

现在你可能兴奋起来了，还想按固定间隔截个全屏图，好确认没有你没看见的怪事发生……那你可以把这一行也加到上面：

screencapture ~/Desktop/$(date +%Y%m%d-%H%M%S).png

这会把截图保存到桌面（指定你自己的文件路径），文件名带格式化的日期和时间。你可能想每小时而不是每 5 分钟做一次，因为数据量很大，可能会给你的屏幕带来一些问题。和往常一样——部署前先测试！

加分项是做一个自动生成的表格和网页，把所有这些信息汇总成一个漂亮的视图，让你一眼就能查看所有装置。

如果进程记录器还不够，我们可以用在这个过程中的所学，实际搭建一套系统，在出问题时给你发邮件，这样你就不用手动检查了。这些都能用命令行和系统内置工具做到，只是设置稍微复杂一点。下面的内容会比较通用，你需要针对自己的具体情况做些调整。

首先你需要配置 postfix，这样才能方便地从终端发邮件——尽可能照着这里的说明做

如果你用的是 gmail 账号，你会这样做：

InstallationSupport@gmail.com

pass: yourpassword

文章里提到的 passwd 文件中的那一行会是：smtp.gmail.com:587 installationSupport@gmail.com:yourpassword

现在运行下面这条命令，给自己发一封测试邮件：echo "Hello" | mail -s "test" "InstallationSupport@gmail.com"

第二步是把这项在终端里发邮件的新能力，与一个检查应用是否还在运行的流程结合起来……下面这样的东西，结合你想做的事稍作调整就能用：

\#!/bin/sh
if [ $(ps ax | grep -v grep | grep "YourApp.app" | wc -l) -eq 0 ] ; #Replace YourApp.app with your own app's name
then
        SUBJECT="Shit broke"
        EMAIL="InstallationSupport" #this is the receiver
     EMAILMESSAGE="This could be for adding an attachment/logfile"
     echo "The program isn't open - trying to re-open">$SUBJECT
     date | mail -s "$SUBJECT" "$EMAIL"  "$EMAILMESSAGE"

        echo "YourApp not running. Opening..."

    open /Applications/YourApp.app #reopen the app - set this to an exact filepath
else
    echo "YourApp is running"
fi

现在你只需要照着上面第 3 步的说明，把这个 shell 脚本设置成由 launchd 运行——你可以每 5 分钟检查一次，并在它崩溃时收到邮件。你也可以改造那个 if 语句，在分辨率不对或出现其它进程状况时给你发邮件。
