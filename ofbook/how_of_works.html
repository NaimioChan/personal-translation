openFrameworks 如何工作

OF 代码中常见模式的简要说明

作者：Arturo Castro

openFrameworks 是一个开源 C++ 工具包，旨在通过提供简单直观的实验框架来协助创作过程。该工具包被设计成通用的黏合剂，把若干常用库包在一起。

openFrameworks 采用了几种模式，因此很容易理解事物如何运作。一旦你理解了这些模式是什么，使用 openFrameworks 中的任何功能都会更容易。

如果你是参与 OF 开发的程序员，这份文档对你也很有用，它能告诉你如何编写自己的类，使其行为与 openFrameworks 的其余部分保持一致。

setup、update、draw

openframeworks 中的大部分功能都按这种模式工作。每个示例的 ofApp 里也总有 setup、update 和 draw 方法。

setup()

setup 方法在应用开始时只被调用一次，用来初始化通常在 ofApp.h 中声明的其他对象或变量。

ofApp.h

ofVideoPlayer player;
int counter;

ofApp.cpp

void ofApp::setup(){
    player.loadMovie("movie.mov");
    counter = 0;
}

在 C++ 中初始化变量极其重要，因为默认情况下它们不会被初始化。例如，如果我们不写 counter = 0;，counter 可以是任意值。

update/draw()

update 和 draw 在一个无限循环中按这个顺序依次被调用，直到应用结束。

update 用于更新应用的状态，做需要的计算，并更新其他对象，比如视频播放器、采集设备，或我们可能在做的一些计算机视觉分析……

在 draw 中我们绘制到屏幕。

ofApp.h

float x;

ofApp.cpp

void ofApp::setup(){
    x = 0;
}

void ofApp::update(){
    x++;
}

void ofApp::draw(){
    ofDrawCircle(x,120,30);
}

会在 y=120 处画一个从屏幕左侧向右移动的圆。

类

openFrameworks 主要以类来组织。共有 3 类类：

工具类

这些是完成某件事的类，比如 ofVideoGrabber、ofVideoPlayer、ofSoundPlayer、ofImage……这些类大多按 setup/update/draw 模式工作。当然，对其中一些来说 draw 讲不通，例如 ofSoundPlayer 就没有 draw 方法。

这些类还遵循共享指针模式。也就是说，当它们被复制时，复制出来的实际上是所谓的浅拷贝。浅拷贝只是对对象的一个引用，而不是其内容的副本。

例如，如果你复制一个视频播放器，然后以某种方式修改副本，原对象也会被修改：

ofApp.h

ofVideoPlayer player;

ofApp.cpp

void ofApp::update(){
    ofVideoPlayer player2 = player;
    player2.setFrame(100);
}

会把 player 和 player2 的当前帧都设为 100，因为实际上 player 和 player2 都是对同一个对象的引用。

数据容器

这些类持有数据，并能对持有的数据做一些操作。例如 ofPixels 或 ofBuffer 这样的类。

这些类遵循 allocate/loadData 模式。allocate 在容器中预留内存，之后用 loadData 把数据放进去。这些函数的名字因类而异，但功能相同。复制这些类做的是深拷贝，也就是说副本是一个全新的对象，内容与原对象相同，因此修改副本不会碰到原对象。

ofApp.h

ofPixels pixels1, pixels2;
ofTexture tex1, tex2;

ofApp.cpp

void ofApp::setup(){
    pixels1.allocate(640,480,OF_IMAGE_COLOR);
    pixels1.set(0);
    pixels2 = pixels1;
    pixels2.setColor(10,10,ofColor(255,255,255));

    tex1.allocate(640,480,GL_RGB);
    tex2.allocate(640,480,GL_RGB);
    tex1.loadData(pixels1);
    tex2.loadData(pixels2);
}

void ofApp::draw(){
    tex1.draw(0,0);
    tex2.draw(660,0);
}

会在屏幕左侧画一幅全黑的图像，在右侧画一幅黑底、在 10,10 处有一个白色像素的图像。当我们调用 pixels2 = pixels1 时，pixels2 会按与 pixels1 相同的大小和通道数分配，pixels1 中的数据被复制到 pixels2。

GL 数据容器

GL 数据容器是数据容器的特例。功能与其他数据容器相当类似，同样遵循 allocate/loadData 模式。这类类有 ofTexture、ofFbo、ofVbo 或 ofVboMesh。它们都在 gl 文件夹里，不过 gl 文件夹里的东西并非都是数据容器，比如 ofShader 或 ofLight 就是 GL 工具类，行为通常与其他工具类完全一样。

GL 数据容器与其他数据容器的主要区别在于，GL 数据容器遵循浅拷贝模式。主要原因是性能：复制 GPU 中的资源通常很慢，所以默认不复制。

例如：

ofApp.h

ofTexture tex1, tex2;

ofApp.cpp

void ofApp::setup(){
    tex1.allocate(640,480,GL_RGB);
    ofPixels pixels;
    pixels.allocate(640,480,OF_IMAGE_COLOR);
    pixels.set(0);
    tex1.loadData(pixels);
    tex2 = tex1;
    pixels.setColor(10,10,ofColor(255,255,255));
    tex2.loadData(pixels);
}

void ofApp::draw(){
    tex1.draw(0,0);
    tex2.draw(660,0);
}

会在屏幕左侧和右侧都画出一个在 10,10 处有白色像素的黑色矩形。这是因为在这种情况下我们复制的是 GL 资源，而它实际上只是第一个纹理的纹理 ID 的一个引用，并非完整副本，所以修改它时也在修改原对象。

数据类型

这些是表示 openFrameworks 中类型的类，比如 ofRectangle、ofVec3f 或 ofMatrix4x4。

函数

openFrameworks 中有些功能通过普通 C 函数提供。这些通常是工具函数，比如 ofToString()、ofRandom()、ofDrawBitmapString()，以及 ofDrawCircle()、ofDrawRectangle() 这样的简单绘制函数。
