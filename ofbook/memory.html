C++ 中的内存

作者：Arturo Castro

正确地使用内存是使用 C++ 时最棘手的部分之一。它与其他语言（比如 Java、Python 以及任何“垃圾回收”语言）的主要区别在于，C++ 中我们可以显式地申请和释放内存，而在那些语言里，一个叫垃圾回收器的部件会替我们完成这些工作。

还有一处重要区别：C++ 中有两块不同的内存区域，堆和栈。如果你习惯了用 processing、Java 或 Python 等语言，那你通常只接触过堆内存。

稍后我们会看到它们的主要区别，但首先让我们看看内存是什么，以及我们在程序里创建变量时发生了什么。

计算机内存与变量

至少从较高层面理解计算机内存如何工作是有帮助的。

计算机有多种类型的内存，本节我们讨论的是 RAM（Random Access Memory，随机访问存储器）。计算机用它存放每时每刻正在执行的程序的指令，以及这些程序正在使用的数据。

你的计算机大概有 4GB 左右的 RAM，在 C++ 中我们能够访问其中的大部分，而访问的方式就是创建变量。内存以字节为单位划分，字节通常是我们在 C++ 应用里能使用的最小内存单位。每种数据类型，比如 char、int、float……都有不同的大小，都以字节计。这些大小可能因平台而异，但最常见的情况大致是：

  • char：1 字节
  • short：2 字节
  • int：4 字节
  • float 4 字节
  • double 8 字节

其他类型的大小可能随其内容而变化，比如数组或字符串。

例如，当我们创建一个这样的变量：

int i;

我们所做的是从这 4GB 中预留 4 个字节来存放一个 int。我们存的是 int 还是别的类型其实并不重要，int、char、float 或 string 的大小会不同，但内存的类型总是一样的。

在计算机内部，它并不把这块内存区域认作 i，而认作一个内存地址。内存地址只是一个数字，指向这 4GB 内存中的某个具体字节。

当我们写 int i 这样的变量时，我们是在告诉程序：预留 4 个字节的内存，把这 4 个字节中第一个字节的地址与变量名 i 关联起来，并把这块 4 字节内存中要存放的数据类型限定为 int。

内存地址通常用 十六进制 表示。在 C++ 中，你可以用 & 运算符取得变量的内存地址，像这样：

cout << &i << endl;

那个 cout 输出的就是我们刚创建的变量 i 的第一个字节的内存地址。

之后，当我们给这个变量赋值时，实际发生的是我们把值存进了刚才通过声明变量所预留的那块内存区域，所以当我们这样写：

i = 0;

我们的内存看起来会是这样：

组成 int 的这些字节在内存中的排列顺序取决于我们计算机的架构，你可能偶尔见过 小端序与大端序 这样的说法。这些术语指的是一个数据类型的字节在内存中的排列方式：最高有效字节在前还是在后。大多数时候我们并不需要了解这个顺序，不过多数现代计算机架构都使用小端序。

如果你用过一段时间 C++，很可能遇到过因为错误的内存访问导致的程序崩溃。通常你看到的提示大概是 “segmentation fault...”。这是什么意思？

在程序里创建变量时，即使在 C++ 中，出于安全原因你也无法访问计算机的全部内存。想象一下你的银行账户在浏览器里开着，如果任何程序都能访问计算机的所有内存，那么一个恶意程序就能直接读取浏览器的内存、拿到这些信息，甚至修改它。为了避免这种情况，操作系统会为每个程序分配若干块内存。你的应用启动时会被分配一个内存 segment。之后你创建变量时，如果这个 segment 里还有足够的内存，变量就建在那里。当这个 segment 里没有更多可用内存时，操作系统会给应用分配一个新的，应用随即开始使用它。如果你试图访问一个不属于分配给本应用的内存的地址，操作系统会直接杀掉这个应用，以避免潜在的安全风险。

这通常是怎么发生的呢？大多数时候你根本不会用地址的数字去访问内存，那为什么有时访问一个变量却得到 segmentation fault？多数情况下这是因为你访问的变量已经不存在了，通常是你保存了指向某块内存的指针，随后那块内存被释放或移到了别处。后面我们会更详细地讨论这一点。

栈变量，函数中的变量与对象中的变量

正如本章开头所说，C++ 中有两种内存：栈和堆。我们先讲栈，因为它是最容易使用的内存类型，也是你在 openFrameworks 中最常用到的。

当你在函数内部，或者类的 .h 文件中创建变量时，只要你没有使用指针和 new 关键字，用的就是栈这种内存。

它之所以叫栈，是因为它的组织方式就像一个 栈。当我们的应用调用一个函数时，内存中会有一块区域分配给那次函数 调用。只有那次特定的函数 调用，且仅限它，在它持续的这段时间内可以在这块区域创建变量。

这些变量在函数调用结束时就不再存在。所以比如你不能这样做：

void ofApp::setup(){
    int a = 0;
}

void ofApp::update(){
    a = 5; // 错误：a 在 setup 之外不存在
}

同样，既然说的是函数调用，你也不能把值存在一个栈变量里，并指望函数再次被调用时它还在。

一般来说，我们可以说变量存在于定义它的那个块中，C++ 中的块由变量被定义时所在的 {} 界定，所以比如下面这样也是不合法的：

for (int i=0;i<10;i++){
    int a = 5;
}
cout << a << endl; // 错误：a 在 for 的 {} 之外不存在

我们甚至可以这样写：

void ofApp::setup(){
   {
        int a = 0;
        // 对 a 做一些操作
   }

   {
        int a = 0;
        // 对 a 做一些操作
   }
}

这种做法不太常见，但有时会用来限定函数内一个变量的生存期，尤其是当这个变量是一个持有资源的对象、而我们只想在特定的时间段内持有这些资源时。

变量的生存期叫做 scope。

除了在函数内部创建变量，我们也可以在 .h 的类声明中创建变量，像这样：

class Ball{
public:
    void setup();

    float pos_x;
}

这类变量叫做 instance variables，因为我们类的每个实例或对象都会得到它的一份副本。它们的行为与函数中创建的栈变量大致相同：它们存在于定义它们的 {} 的生命周期内，在这里就是它们所属对象的 {}。

这些变量可以从类中的任何位置访问，所以当我们需要让数据能被这个类的对象中的任何函数访问时，就这样创建它们。

栈中的内存是有限的，具体大小取决于计算机的架构、操作系统，甚至我们使用的编译器。在某些系统上它甚至可以在应用运行期间被修改，不过大多数时候我们碰不到这个上限。

即使我们把所有变量都建在栈上，通常那些占用内存最多的对象，比如 vector，或者 openFrameworks 里的 ofPixels 之类，它们内部使用的大部分内存仍会建在堆上，而堆只受计算机可用内存总量的限制，所以我们不必担心。

接下来的小节我们会看到堆如何工作，以及使用堆或栈各有什么好处。

指针与引用

在讨论堆内存之前，我们先看看 C++ 中指针和引用如何工作，它们的语法是什么，以及我们创建一个指针或引用时内存里到底发生了什么。

如前所见，我们可以这样取得变量的地址：

cout << &i << endl;

这样得到的是该变量所用第一个字节的内存地址，与它的类型无关。当我们把这个内存地址存到另一个变量里，在 C++ 中我们称之为指针。语法是：

int i = 0;
int * p = &i;

内存里得到的东西大致是这样：

一个指针通常占 4 或 8 个字节（取决于我们是在 32 位还是 64 位应用中），这里只把它画成 1 个字节是为了便于理解，但如你所见，它只是另一个变量，只不过它装的不是值，而是一个指向某个值的内存地址。这就是它被称为指针的原因。

指针可以指向堆内存，也可以指向栈内存。

现在，我们来解释一件在 C++ 编程中非常重要、必须考虑的事。到目前为止我们看到，当我们这样声明一个变量时：

int i;

得到的内存布局是这样的：

如我们所见，那块内存区域里还没有值。在其他语言中，比如 processing，做这样的事：

int i;
println(i);

是非法的，编译器会告诉我们正在使用一个未初始化的变量。而在 C++ 中这完全合法，只是该变量的内容是未定义的。大多数情况下我们会得到 0，因为操作系统出于同样的安全原因会在把内存分配给我们的程序之前先清零。但如果我们复用了一块曾经分配过的内存，那么这块内存里可能是任何内容，程序的结果也就无法确定。

举例来说，如果我们有一个变量用来定义某个待绘制对象的位置，忘记初始化它就会导致该对象被画到任意位置。

大多数对象都有默认构造函数，会把值初始化为比如 0，所以对对象来说通常不必额外赋值。

那使用未初始化的指针会怎样？既然指针装的是一個内存地址，如果那块内存里的值指向了一个不属于我们程序的地址，而我们又试图读取或修改该地址上存放的值，操作系统就会用一个 segmentation fault 信号杀掉我们的应用。

回到指针，我们见过可以这样创建指针：

int i = 5;
int * p = &i;

现在，如果我们直接使用这个指针，就像这样；

cout << p <<< endl;

我们得到的是一个内存地址，而不是值 5。那么怎样才能访问指针所指向的值呢？我们可以使用 & 的反向运算符：& 给出变量的地址，* 给出某个内存地址所指向的值，所以我们可以这样做：

cout << *p << endl;

这样就会打印出值 5。我们也可以这样做：

int j = *p;
cout << j << endl;

同样会得到值 5，因为我们把 p 所指向的值复制到了 j 中。

这个 & 运算符被称为 引用运算符，因为它给出一个指向变量的引用，即它的内存地址。这个 * 运算符是它的反向操作，叫做 解引用运算符，它给出指针所指向的值：它对一个引用、一个内存地址做解引用，从而让我们访问其值而不是地址。

到目前为止，我们处理的都是原始类型，确切说是 int，但对任何其他原始类型，比如 float、short、char、unsigned int 等，行为都一样。事实上在 C++ 中，对对象的行为也是一样的。

比如你如果习惯 Java，可能已经注意到，在 Java 和 C++ 中这段代码：

int a = 5;
int b = a;
a = 7;
cout << "a: " << a << " b: " << b << endl;

行为相同（当然要把 cout 换成 Java 中对应的写法）。也就是说：a 最后会是 7，而 b 会是 5。使用对象时，C++ 的行为与 Java 不同。比如，假设我们有一个 Ball 类：

class Ball{
public:
    void setup();
    //...

    ofVec2f pos;
}

或者 processing 中类似的类；

class Ball{
    void setup();

    PVector pos;
}

如果在 C++ 中你这样做：

Ball b1;
b1.pos.set(20,20);
Ball b2;
b2 = b1;
b2.pos.set(30,30);

b1 的 pos 最后会是 20,20，b2 是 30,30；而如果在 java 中做等价的事，b1 和 b2 的位置都会是 30,30：

Ball b1 = new Ball();
b1.pos.set(20,20);
Ball b2;
b2 = b1;
b2.pos.set(30,30);

注意在 Java 的例子中，第一个 ball 我们用了 new，第二个没有，这是因为在 Java 中一切对象都是堆上的指针，所以当我们写 b2 = b1 时，实际上是把 b2 变成了指向 b1 的引用，之后修改 b2 时也就同时修改了 b1。

而在 C++ 中，当我们写 b2 = b1 时，实际上是把 b1 各变量的值复制进 b2，所以我们仍然有两个不同的变量，而不是一个引用。修改 b2 时，b1 保持不变。

在两种语言中，= 都表示把右侧的值复制到 = 左侧的变量中。区别在于，在 Java 中一个对象实际上是指向对象的指针，b1 或 b2 的内容不是对象本身而是它的内存地址；而在 C++ 中 b1 真正包含对象本身。

在 Java 和 C++ 中，内存大致会是这个样子：

如你所见，在 C++ 中对象在内存里就是它的所有成员变量一个接一个地排列。当我们把一个对象变量赋值为另一个对象时，C++ 默认会把整个对象复制到等号左侧。

那么，如果我们有一个这样的类会怎样：

class Particle{
public:
    void setup();
    //...

    ofVec2f pos;
    ParticleSystem * parent;
}

然后这样做：

Particle p1;
Particle p2;
ParticleSystem ps;

p1.pos.set(20,20);
p1.parent = &ps;
p2 = p1;

如前面一样，C++ 会把 p1 的内容复制到 p2。p1 的内容是一个 ofVec2f（由 x 和 y 两个 float 组成），然后是一个指向 ParticleSystem 的指针，被复制的就是这些：ParticleSystem 本身不会被复制，只复制指向它的指针，所以 p2 最后会拥有 p1 位置的副本和一个指向同一个 ParticleSystem 的指针，但我们只有一个粒子系统。

默认复制、以及对象可以存放在栈上而不是必然是指针，这些特性有其优点。例如在 C++ 中，像上一个例子那样用到的 particle 的 vector 或数组在内存中会是：

vector<Particle> particles;

在内存中所有粒子都是连续的，这一点（以及其他因素）使访问它们比用指针指向内存中不同位置更快。这也让把 C++ vector 转换成 openGL 内存结构更容易，不过那是另一章的话题。

除此之外，我们还需要注意 C++ 默认复制这一点，在把对象作为参数传给函数时尤其如此。例如这段：

void moveParticle(Particle p){
    p.x += 10;
    p.y += 10;
}

...

Particle p1;
moveParticle(p1);

是完全合法的代码，但不会有任何效果，因为函数收到的是 particle 的一份副本，修改的是这份副本而不是原来的对象。

我们可以这样做：

Particle moveParticle(Particle p){
    p.x += 10;
    p.y += 10;
    return p;
}
...

Particle p1;
p1 = moveParticle(p1);

这样我们把 particle 的副本传给函数，函数修改它的值并返回一个修改后的副本，我们再把它复制回 p1。注意到上一句里我们提了多少次“复制”了吗？编译器会把其中一些优化掉，对小型对象来说这样做完全没问题，但想象一下如果我们有类似这样的东西：

vector<Particle> moveParticles(vector<Particle> ps){
    for(int i=0;i<ps.size();i++){
        ps[i].x += 10;
        ps[i].y += 10;
    }
    return ps;
}
...

vector<Particle> ps;
...
ps = moveParticles(ps);

如果我们有一百万个粒子，那会慢得可怕。相对于 CPU，内存真的很慢，所以任何涉及复制内存或分配新内存的操作通常都应该避免。那么我们能做些什么来避免这些复制呢？

我们也可以用指针，对吧？

void moveParticle(Particle * p){
    p->x += 10;
    p->y += 10;
}
...

Particle p1;
moveParticle(&p1);

这里有件新东西：注意要引用指向对象的指针中的变量时，我们不用点号，而用 -> 运算符。每当我们想访问指向对象的指针中的某个变量时，不必像这样先解引用：

(*p).x +=10;

我们可以用 ->

p->x += 10;

这样就解决了问题：使用指针而不是传递对象的副本，我们传递的是对它的引用、它的内存地址，所以函数会真正修改原来的对象。

这样做的主要问题是语法有点怪，想象一下第二个例子——那个用 vector 的例子——如果传指针会写成什么样：

vector<Particle> moveParticles(vector<Particle> ps){
    for(int i=0;i<ps.size();i++){
        ps[i].pos.x += 10;
        ps[i].pos.y += 10;
    }
    return ps;
}
...

vector<Particle> ps;
...
ps = moveParticles(ps);

那么，函数会变成这样：

void moveParticles(vector<Particle> * ps){

问题在于现在我们无法用 [] 运算符访问 vector 中的元素，因为 ps 不再是一个 vector，而是一个指向 vector 的指针。更糟的是，这个

ps[i].x += 10;

居然能编译通过，但几乎肯定会造成内存访问错误，也就是 segmentation fault。ps 现在是一个指针，而在使用指针时 `[]' 的行为就像我们有一个 vector 数组一样！

我们会在讲内存结构的那一节更深入地解释这一点，但现在先看看如何传递一个不带指针语法的引用。在 C++ 中它叫做引用，看起来像：

void moveParticles(vector<Particle> & ps){
    for(int i=0;i<ps.size();i++){
        ps[i].pos.x += 10;
        ps[i].pos.y += 10;
    }
}

vector<Particle> ps;
...
moveParticles(ps);

现在我们传递的是对原对象的引用，但不必使用指针语法，仍然可以像普通对象一样使用它。

进阶说明：有时我们想用引用避免复制，但仍要确保接收对象的函数不会修改其内容，这种情况下建议使用 const，像这样：

ofVec2f averagePosition(const vector & ps){ ofVec2f average; for(int i=0;i<ps.size();i++){ average += ps[1].pos; } return average/float(ps.size()); } vector ps; ... ofVec2f averagePos = averagePosition(ps);

const 只是让变量无法被修改，即使它是引用也一样，同时它告诉任何使用该函数的人：他们可以把数据传进来而不会被改动；也让任何修改这个函数的人明白，将来它应当保持不变，输入——那个粒子系统——不应被修改。

在参数之外，引用还有一些特殊的性质。

首先，引用一旦创建，我们就不能修改它的内容，例如我们可以这样做：

ofVec2f & pos = p.pos;
pos.x = 5;

但试图改变引用本身，就像这样：

ofVec2f & pos = p.pos;
pos.x = 5;
pos = p2.pos;  // 错误：引用只能在声明时赋值

另外你也可以返回引用，但取决于这个引用指向什么，这可能是个坏主意：

ofVec2f & averagePosition(const vector<Particle> & ps){
    ofVec2f average;
    for(int i=0;i<ps.size();i++){
        average += ps[1].pos;
    }
    average/=float(ps.size());
    return average;
}

它其实能编译通过，但很可能在某个时候导致 segmentation fault，或者表面上能跑但调用这个函数时会得到奇怪的值。问题在于我们把这个变量 average 建在栈上，所以函数返回时它会从内存中被 删除，我们返回的引用将指向一块不再为 average 保留的内存区域，一旦它被覆盖，我们就会得到无效的值，或者得到一个指向不再属于我们程序的内存区域的指针。

这是 C++ 中最令人头疼的问题之一，叫做悬空指针，在这个例子里是悬空引用，它产生于我们拥有一个指针或引用，而它指向的内存区域后来以某种方式被释放了。

更现代的语言用不同的策略解决这个问题。例如 Java 不允许这种情况发生，因为对象只有在最后一个指向它的引用离开作用域后才会被删除；它使用所谓的垃圾回收器，不时遍历内存，寻找不再有引用指向的对象并删除它们。这解决了问题，但让人难以知道对象究竟何时会被真正删除。C++ 在其最新版本中，以及更现代的语言，试图用新的一类指针来解决，这类指针定义了对象的所有权，我们会在本章最后一节讨论它：智能指针。

堆中的变量

现在我们知道了指针的语法和语义，来看看如何使用堆。堆是一块属于整个应用的内存区域，任何函数都可以在这个空间里创建变量并与其他部分共享，要使用它我们需要一个新关键字 new：

Particle * p1 = new Particle;

如果你了解 processing 或 Java，这看起来有点像，对吧？确实，这和 Java 对象完全一样：当我们使用 new 时，我们把这个变量创建在堆上而不是栈上。new 返回一个指向堆中某个内存地址的指针，而在 C++ 中我们必须显式地说明用来存放它的变量 p1 是一个指针，方法是在声明中使用 *。

要访问指向对象的指针的变量或函数，如前所见，我们使用 -> 运算符，所以我们会这样写：

Particle * p1 = new Particle;
p1->pos.set(20,20);

或者：

Particle * p1 = new Particle;
p1->setup();

指针和任何变量一样，可以先声明而不初始化：

Particle * p1;
p1->setup() // 这能编译通过，但运行应用时会失败

我们可以把堆想象成某种全局内存，相对地栈则是局部内存。在栈中只有拥有它的那个块能访问它，而建在堆上的东西会活过创建它们的作用域，任何函数只要有指向它们的引用（指针）就能访问。例如：

Particle * createParticle(){
    return new Particle;
}

void modifyParticle(Particle * p){
    p->x += 10;
}

...

Particle * p = createParticle();
modifyParticle(p);

createParticle 在堆上创建了一个新的 Particle，所以即使 createParticle 结束了，那个 Particle 仍然存在。我们可以在函数外使用它，把指向它的引用传给其他函数……

那么我们怎么表示不再想用这个变量了？我们用 delete 关键字：

Particle * p1 = new Particle;
p1->setup();
...
delete p1;

使用堆时这一点很重要，如果忘了做，就会出现所谓的内存泄漏：这块内存不再被任何人引用，却继续留在堆里，使我们的应用随时间占用越来越多的内存，直到填满计算机所有可用内存：

void ofApp::draw(){
    Particle * p1 = new Particle;
    p1->setup();
    p1->draw();
}

每次我们调用 draw，都会创建一个新粒子，每次 draw 调用结束后我们就丢失了指向它的引用 *p1，但我们用 new 分配的内存在函数调用结束时并不会被释放，所以程序会慢慢占用越来越多的内存，你可以用系统监视器查看。

如前所述，栈内存是有限的，所以有时我们需要用堆。试图在栈上创建一百万个粒子很可能会造成栈溢出。不过总的来说，在 C++ 中大多数时候我们不需要直接使用堆。像 vector、ofPixels 这样的类和其他内存结构允许我们使用堆内存，但又保持栈的语义，例如这段：

void ofApp::draw(){
    vector<Particle> particles;
    for(int i=0; i<100; i++){
        particles.push_back(Particle())
        particles.back().setup();
        particles.back().draw();
    }
}

实际上用的是堆内存，因为 vector 内部就使用了堆，但 particles 变量一旦离开作用域——也就是当前这次 draw 调用结束时——vector 的析构函数会替我们释放那块内存。

内存结构、数组和 vector

数组是 C++ 中创建对象集合最简单的方式，和 C++ 中其他类型一样，它们也可以建在栈上或堆上。不过栈上的数组有一个限制：它们必须有一个预先定义的大小，需要在声明中指定，之后不能改变：

int arr[10];

和任何其他类型一样，前面的声明已经为 10 个 int 预留了内存，我们不需要用 new，而这块内存是未初始化的。要访问它们，如你从前面的章节可能知道的，直接这样做就行：

int arr[10];
arr[0] = 5;
int a = arr[0];

如果我们试着这样做：

int arr[10];
int a = arr[5];

a 的值将是未定义的，因为数组中的内存在创建时没有被初始化为任何值。另外如果我们试着这样做：

int arr[10];
int a = arr[25];

如果 arr + 25 处的内存地址超出了操作系统分配给我们的应用的内存范围，我们的应用很可能就会崩溃。

我们刚才说 arr + 25？这是什么意思？如前所见，一个变量只是内存中的某个位置，我们可以取得它的内存地址，也就是在内存中分配给该变量的第一个字节。数组也差不多，例如既然我们知道一个 int 在内存中占 4 个字节，那么 10 个 int 的数组将占 40 个字节，而且这些字节是连续的：

记住内存地址是用十六进制表示的，所以 40 == 0x0028。现在要取数组的地址，和其他变量一样我们可能会想用 & 运算符，确实可以这样做：

int arr[0];
int * a = &arr[0];

这给出数组第一个元素的地址，而它确实也就是数组的地址。但用数组时，同一个变量本身其实就是指针：

int arr[10];
int * a = &arr[0];
cout << "a: " << a << " arr: " << arr << endl;

对 a 和 arr 会打印出相同的值。所以数组只是一个指向某内存地址的指针，唯一的区别在于那个内存地址是一块预留内存的起始处，其大小足以容纳——在我们的例子里——10 个 int。所有这些 int 会一个接一个排列，所以当我们写 arr[5] 时，我们访问的只是数组所在内存地址加上 5 个 int 大小处的值。如果我们的数组从 0x0010 开始，而 int 占 4 bytes，那么 arr[5] 会是 16 （0x0010 的十进制） + 4 * 5 = 36，用十六进制表示就是 0x0024。我们实际上可以在代码里这样做：

int arr[10];
arr[5] = 20;
cout << "&arr[5]: " << &arr[5] << "arr+5: " << arr+5 << endl;
cout << "arr[5]: " << arr[5] << "*(arr+5): " << *(arr+5) << endl;

这确实很怪，大多数时候你不会用到，它叫做指针算术。第一个 cout 会打印数组中位置 5 那个 int 在内存中的地址：第一种情况用 & 运算符取得 arr[5] 的地址，第二种情况直接在 arr 的首地址上加 5，写成 arr+5。第二个 cout 打印该内存位置上的值，用 arr[5]，或者对地址 arr+5 用 * 运算符解引用。

注意，当我们给数组的地址加上 5 时，加的不是字节数，而是它所包含类型的大小（以字节计），在这个例子里 +5 实际意味着 +20 个字节。你可以这样验证：

int arr[10];
arr[5] = 7;
cout << "arr: " << arr << "arr+5: " << arr+5 << endl;

然后用计算器把这两个十六进制值相减。如果你试着在程序里这样减：

int arr[10];
arr[5] = 20;
cout << "arr: " << arr << "arr+5: " << arr+5 << endl;
cout << "(arr+5) - arr: " << (arr+5) - arr << endl;

你会再次得到 5，因为正如我们所说，指针算术是按类型大小而不是按字节来做的。

指针算术的语法有点复杂，而这部分的目的其实并不是讲指针算术本身，而是说明数组只是内存中一串挨着排的值，所以如果你没有完全理解这套语法也不用担心，这很可能是你不会用到的内容。同样重要的是要记住，数组变量本身就充当指针，所以当我们在不使用 [] 运算符的情况下引用它时，得到的是一个内存地址，而不是它包含的值。

到目前为止我们创建的数组都是建在栈上的，所以使用这种大数组时要小心，因为它可能带来问题。

堆上的数组和其他堆上的东西一样，用 new 来创建：

int arr[] = new int[10];

或者

int * arr = new int[10];

如你所见，这印证了我们前面说的：数组变量只是一个指针。当我们调用 new int[10] 时，它分配了存放 10 个整数的内存，并返回数组中第一个整数第一个字节的内存地址，我们可以像第二个例子那样把它保存在一个指针里，或者用 int arr[]，后者声明了一个大小未知的数组。

和其他建在堆上的变量一样，我们需要手动删除它，所以用完之后需要用 delete 来释放那块内存，对于堆上的数组，语法稍有特殊：

int arr[] = new int[10];
...
delete[] arr;

如果你在删除时忘了用 []，就只会释放第一个值，结果还是内存泄漏。

数组的语法还有一些问题，例如这个：

int arr[10];
int arrB[10];
arrB = arr;

会编译失败。而这个：

int arr[] = new int[10];
int arrB[] = new int[10];
arrB = arr;

其实能编译通过，但和其他变量一样，我们并没有把 arr 指向的值复制到 arrB，而是复制了内存地址。这样最终会有两个指针指向同一处内存，也就是我们创建 arr 时分配的那块，同时丢掉了初始化 arrB 时分配的内存。又是一处内存泄漏：执行 int arrB[] = new int[10]; 时分配的内存已经不再被任何变量引用，所以我们再也无法删除它。要复制数组，有一些 c（不是 C++）函数比如 memcpy，但它们的语法比较复杂，所以在 C++ 中推荐使用 vector。

C++ 的 vector 与数组非常相似，实际上它在内存中的布局和数组一样：它包含一串在内存中连续的值，而且总是分配在堆上。主要区别在于我们获得了更好的语法和 栈语义。要分配一个容纳 10 个 int 的 vector，我们可以这样做：

vector<int> vec(10);

我们甚至可以在初始化时给这 10 个 int 一个初始值，像这样：

vector<int> vec(10,0);

而比如把一个 vector 复制到另一个，会按预期工作：

vector<int> vec(10,0);
vector<int> vecB = vec;

会创建 vec 内容的一份副本到 vecB 中。另外，即使 vector 使用的内存在堆上，当一个 vector 离开作用域——也就是声明它的那个块结束时——vector 会被销毁，因为 vector 本身就建在栈上，所以离开作用域会触发它的析构函数，由它负责删除自己在堆上创建的内存：

void ofApp::update(){
    vector<int> vec(10);
    ...
}

这让 vector 比数组更容易使用，因为我们不必操心删除它们、产生悬空指针、内存泄漏……而且语法也更简单。

vector 还有更多特性，正确使用它们可能有些讲究，特别是在我们想为性能做优化或在多线程应用中使用它们时，但那不是本章的范围。你可以找到一些关于 vector 的教程，openFrameworks 站点上有一篇入门教程：vector 基础，还有一篇讲解了更进阶的概念 std::vector

其他内存结构：list 与 map

让对象在内存中一个接一个排列，大多数时候正是我们想要的：无论我们想顺序访问每一个还是随机访问任意一个，访问都很快，因为 vector 内部就是一个数组，访问它的第 20 个位置，只不过意味着内部取第一个位置的内存地址再加上 20。不过在某些情况下，vector 并不是最优的内存结构。例如，如果我们要频繁地在 vector 中间添加或删除元素，把 vector 想象成一条内存带，那就意味着我们需要把 vector 中后面的所有元素整体向右移一个位置，然后把新元素插入空出来的位置。内存中并不存在“移动”这回事，移动连续内存就意味着复制它，而如前所述，复制内存是相对较慢的操作。

有时如果内存不足以把元素整体右移一位（复制一份），vector 就需要把全部内容复制到一个新的内存位置。如果我们处理的是成千上万个元素并且非常频繁地这样做，比如每一帧都做，这真的会让性能大幅下降。

为了解决这个问题，还有别的内存结构，比如 list。在 list 中内存不是连续的，而是每个元素都有指向下一个和上一个元素的指针，所以插入一个元素只需要改动这些指针，让它们指向新加入的元素。在 list 中我们从不需要搬动元素，但它主要的缺点是元素在内存中不连续，访问会比 vector 稍慢；另外在某些场合无法使用它，比如向显卡上传数据时，显卡总是要求连续内存。

list 的另一个问题是，访问 list 中间的元素（即所谓随机访问）很慢，因为我们总得从头遍历整个 list 直到到达想要的元素。所以，当我们很少需要随机访问某个位置，而需要频繁在中间添加或删除元素时，才会使用 list。关于 list 语法的细节，可以查看 C++ 中 list 的文档

C++ 标准库和其他 C++ 库中还有多种内存结构，除了 vector 和 list，我们只再简单看一下 map。

有时我们不想按位置访问事物，也不想要一个有序的元素列表，而是想要类似索引或字典的东西，可以通过某个键来访问元素，这就是 map。在 map 中我们可以存储 (key,value) 对，并通过 key 查找 value。例如，假设我们有一组带名字的对象，如果这个名字对所有对象都是唯一的，我们就可以把它们存进 map，以便按名字查找：

map<string, NamedObject> objectsMap;

NamedObject o1;
o1.name = "object1";
objectsMap[o1.name] = o1;

之后我们就可以用它的名字查找那个对象，像这样：

objectsMap["object1"].doSomething();

不过要小心，如果这个对象之前不存在，使用 [] 运算符会创建一个新的。如果不确定，通常明智的做法是先查找它，只在它存在时才使用：

if(objectsMap.find("object1")!=objectsMap.end()){
    objectsMap["object1"].doSomething();
}

你可以在 C++ 中 map 的文档

智能指针

如前所述，传统的 C 指针——现在也叫 裸指针——有时会带来问题，最常见的是悬空指针：曾经大概有效、但现在指向无效内存位置的指针；试图解引用 NULL 指针；如果在丢失对该内存地址的引用之前没有释放内存，就可能造成内存泄漏……

智能指针试图通过在内存分配上加入我们一直称为栈语义的东西来解决这些问题，其正确的术语是 RAII：Resource Acquisition Is Initialization，意思是：在栈上创建一个对象时，就分配它之后要用的资源；当变量离开作用域而调用析构函数时，该对象的析构函数被触发，负责释放所有用到的资源。RAII 还有一些别的含义，但对本章来说这一点最重要。

智能指针用这项技术来避免我们在裸指针中见到的所有问题。它们还通过更明确地界定某块已分配内存或某个对象的所有者来做到这一点。到目前为止我们看到，分配在栈上的东西属于创建它们的函数或块，我们可以把它们的副本（或者在 C++11 及以后，把它们移动）作为返回值带出函数，但它们的所有权始终是清晰的。

然而对于堆内存，所有权就模糊得多，有人可能会像这样在堆上创建一个变量：

int * createFive(){
    int * a = new int;
    *a = 5;
    return a;
}

现在，当有人调用那个函数时，new int 的所有者是谁？事情还可能更复杂：如果我们把指向那块内存的指针传给另一个函数，甚至传给一个对象呢？

// ofApp.h
int * a;
SomeObject object;

// ofApp.cpp
void ofApp::setup(){
    a = createFive();
    object.setNumber(a);
}

现在那块内存的所有者是谁？ofApp？object？所有权决定了——除了别的之外——当内存不再使用时由谁负责删除它。现在 ofApp 和 object 都持有对它的引用，如果 ofApp 在 object 用完它之前就删除了它，object 可能试图访问它并让应用崩溃，或者反过来。在这个例子里，似乎 ofApp 负责删除比较合理，因为它同时知道 object 和指向 int 的指针 a，但如果我们把例子改成：

// ofApp.h
SomeObject object;

// ofApp.cpp
void ofApp::setup(){
    int * a = createFive();
    object.setNumber(a);
}

甚至这样：

// ofApp.h
SomeObject object;

// ofApp.cpp
void ofApp::setup(){
    object.setNumber(createFive());
}

现在 ofApp 已经不知道那块被分配的内存了，但两种情况都可能出现，所以我们实际上需要了解 object 实现的细节，才能知道是否需要保留那个变量的引用来稍后销毁它。这一点（以及其他类似的东西）破坏了封装，你可能在第 1 章了解过封装。我们不应该为了使用一个对象而去了解它内部如何工作。这让我们的代码逻辑变得非常复杂且容易出错。

智能指针通过明确界定谁拥有一个对象，并在所有者被销毁时自动删除已分配的内存来解决这个问题。有时我们需要在多个所有者之间共享一个对象。这种情况下我们有特殊的一类智能指针，叫做共享指针，它定义了共享所有权，只有当所有所有者都不再使用该变量时才释放已分配的内存。

我们只是简要地看一下，网上有大量关于如何使用智能指针及其语法的例子，最重要的是理解它们如何通过与裸指针对比、清晰地界定所有权来工作，以及它们解决了什么问题。

unique_ptr

顾名思义，unique_ptr 是一个为对象定义唯一所有权的指针，我们可以把它四处移动，在某个时刻持有它的对象或函数就是它的所有者，同一时间不能有超过一个有效引用，而当它离开作用域时，会自动删除我们可能分配过的内存。

要用 unique_ptr 分配内存，我们这样做：

void ofApp::setup(){
	unique_ptr<int> a(new int);
	*a = 5;
}

如你所见，一旦创建，它的语法和裸指针一样，我们可以用 * 运算符解引用它，访问或修改它的值；如果处理的是对象，像这样：

void ofApp::setup(){
	unique_ptr<Particle> p(new Particle);
	p->pos.set(20,20);
}

我们也可以用 -> 访问它的成员变量和函数。

当函数离开作用域时，由于 unique_ptr 是一个对象，它的析构函数会被调用，内部会对已分配的内存调用 delete，所以我们完全不需要对 unique_ptr 调用 delete。

现在假设我们想把一个 unique_ptr 移进 vector：

void ofApp::setup(){
	unique_ptr<int> a(new int);
	*a = 5;

	vector<unique_ptr<int> > v;
	v.push_back(a);  // 错误
}

那会产生一长串错误，视编译器而定，非常难懂。原因在于 a 仍然归 ofApp::setup 所有，所以我们不能把它放进 vector。我们可以做的是显式说明我们想把那个 unique_ptr 的所有权移进 vector，从而把它移进去：

void ofApp::setup(){
	unique_ptr<int> a(new int);
	*a = 5;

	vector<unique_ptr<int> > v;
	v.push_back(move(a));
}

还有一个 unique_ptr 解决不了的问题，我们仍然可以这样做：

void ofApp::setup(){
	unique_ptr<int> a(new int);
	*a = 5;

	vector<unique_ptr<int> > v;
	v.push_back(move(a));

	cout << *a << endl;
}

编译器不会在那里报错，但如果我们运行这个应用，它会崩溃，因为 a 已经不再归 ofApp::setup 所有了。必须显式使用 move 正是试图通过让语法更清晰来解决这个问题。用了 move 之后，我们就不能再使用那个变量了，只能通过 vector 访问它。更现代的语言如 Rust 完全解决了这个问题，它让编译器检测这类对已移动变量的使用并产生编译错误。C++ 大概在某个时候也会解决，但目前你需要小心，不要使用一个已被移动的变量。

shared_ptr

如前所见，有时唯一所有权并不够，有时我们需要在多个所有者之间共享一个对象，在 C++11 及以后，这通过 shared_ptr 解决。用法与 unique_ptr 非常相似，我们这样创建它：

void ofApp::setup(){
	shared_ptr<int> a(new int);
	*a = 5;

	vector<shared_ptr<int> > v;
	v.push_back(a);
}

区别在于现在 vector 和 ofApp::setup 都持有对该对象的引用，而这样做：

void ofApp::setup(){
	shared_ptr<int> a(new int);
	*a = 5;

	vector<shared_ptr<int> > v;
	v.push_back(a);

	cout << *a << endl;
}

完全没问题。shared_ptr 的工作方式是维护一个指向它的引用计数：每当我们复制它，就把计数加一；每当一个引用被销毁，就把引用计数减一。当引用计数降到 0 时，它释放已分配的内存。引用计数是原子地完成的，这意味着我们可以在多个线程之间共享一个 shared_ptr 而不会让计数出错。这并不意味着在多线程应用中访问所包含的数据是安全的，只是说如果我们把 shared_ptr 在不同的线程间传递，引用计数不会出错。
