数学：从一维到四维

作者：Omer Shapira

艺术家如何接近数学

数学在艺术里是件奇怪的东西。许多艺术家直接把它当作创作的灵感来源，从 Leonardo Da Vinci 的 Vitruvian Man，到 Escher 对数字场的不同视角，以及艺术中许多其他被突出、被当作主题的呈现。另一方面，数学也被视为给大多数艺术带来秩序的工具：音乐家虔诚地遵循 Chromatic Circles（它其实只是 12 阶循环群，\(\mathbb{Z}/12\mathbb{Z}\)），建筑师在谐波序列里创造节奏，\(\frac{1}{2^n}\) 或 \(\frac{1}{3^n}\)，产品设计师则训练自己的爱人半夜把他们叫醒、问他们关于黄金比例 The Golden Ratio 的问题，\(\frac{1 + \sqrt{5}}{2}\)（各位，真的，别这样）。但正如艺术家欣赏数学能带来的秩序很重要，观察数学内部包含的混沌要重要得多。

随机性、大规模的事件、不可预测性，这些数学概念直到不久之前都还无法被快速探索。仿真的概念——让一件事在受某些条件约束的前提下大规模地发生——正是计算机让人得以探索的东西。Benoît Mandelbrot 在 IBM 工作时，试图打印一个自重复复数序列的密度图——这件事若交给人的手和脑，永远也做不完——结果却让一项科学测量因其美学价值被重新挪用，成了我们今天所说的 Fractal Art。同样的结果——人们画出一幅图的速度可以快过他们思考的速度——催生了整个仿真艺术家族，比如由 Aristid Lindenmayer 构想、从 L-Systems 生成的树状结构，以及许许多多不同风味的计算机生成仿生制品。把这些东西称为 Art 是可以接受的，因为若让人以为数学家是在工作中有意做出这些，只会让观众困惑。

但只要你拿起这本书，任何读者就已经知道不该做这种区分。数学在艺术中无处不在，正如艺术在数学中无处不在。用画笔、钢笔或凿子时，我们都在借用大自然所做的苦工：它计算物理，为我们完美地渲染一切，而且全是实时的。在计算机的世界里，这些都不成立。像 L-Systems 这样的东西必须由人先造出来我们才能用，因为我们的手伸不进计算机里。只要你做的是数字艺术，数学就在某处发生着，不管你控制得住它还是控制不住。本章试图揭开图形编程这门黑魔法的一些基本内部构造。我希望这一章能写上五倍长，把那些真正漂亮的东西都塞进去，但那样这本书就重得没法塞进背包了。

一维：使用变化

让我们从数轴开始这段旅程。它是一段向正负两个方向都延伸到无穷的数字。假设我们是蚂蚁或微生物，能正好站在某个数值上，并通过朝那个方向行走抵达任何其他数值。这大致就是维度的定义：一个所有值都可达的无穷集合，其中任何一个值都能用一个数字描述。你马上就会看到，这些性质会带来相当多的可能性。

线性插值：ofLerp

float ofLerp(float start, float stop, float amt)

正如 Randall Munroe（xkcd 的作者）所说，如果你在页面上看到比 7 大的数字，那你做的就不是真正的数学。为了证明我们配得上这个说法，这一部分只涉及 0 到 1 之间的数字。

如果你已经做过一点基于时间或基于空间的工作，大概会注意到：你常常可以把作品里的元素描述为位于两个已知点之间的一条线上。时间线上的某一帧位于 00:00:00 与影片总时长之间的某个已知位置，滚动条指向页面开头与结尾之间的某个已知位置。这正是 lerp 所做的事。

用 lerp 函数，你可以取任意两个量——在我们的例子里是 start 和 stop——并用 0 到 1 之间的量（amt）找出它们之间的任意一点。说得啰嗦一点：\[\text{lerp}\left(a,b,t\right) = t\cdot b+\left(1-t\right)\cdot a\]

注：线性到底是什么意思？

工程师、程序员和说英语的人都喜欢把线性理解成任何你能放到一条线上的东西。而数学家要收拾前一类人制造的全部概念混乱，所以把它定义为任何你能放到一条从 (0,0) 出发的线上的东西。这背后有很好的理由，我们会在讨论线性代数时看到。现在，先这样理解：

一个线性变换接受任何在 0 点处取值为 0 的直线，并返回一条具有同样性质的直线，\[f\left(x\right)=ax\]。如果它在 \(x=0\) 处返回的直线值不为 0，\[f\left(x\right)=ax + b\]，那它就是仿射变换。

到这里你大概已经明白了，但还是值得重复一遍：这两种变换要么把线变成线，要么在某些退化情形下把线变成点。比如 \(f\left(x\right) = x^{2}\) 完全不是线性的。

练习：拯救 NASA 的火星着陆器

1999 年，一件工程杰作正在向火星做最后的接近。所有仪器都显示接近距离与速度相匹配，它马上就能抵达并做点科学了。但它却做了一件相当无礼的事：一头撞上了这颗红色星球。NASA 后来做的调查显示，在设计着陆器时，一个团队的测试设备设成了厘米，另一个团队设成了英寸。顺便说一句，这些都是真的。

帮 NASA 的团队协同工作：写一个把厘米换算成英寸的函数。供参考，\(1_{\text{in}} = 2.54_{\text{cm}}\)。用三个不同的真实世界数值检验你的结果。提示：先用纸笔求解，比用键盘容易得多。

仿射映射：ofMap

float ofMap(float value, float inputMin, float inputMax, float outputMin, float outputMax, bool clamp = false)

在上一段讨论中我们看到，借助 lerp，任意两点之间的值都可以被线性地当作 0 到 1 之间的值来寻址。这非常方便，也因此我们把大多数自定义的数值范围（比如 ofFloatColor）都建在 0 到 1 这个定义域上。

然而处理现实问题时，程序员会遇到一些数值区间，希望把它们映射到另一些区间，而两者都不限于 0 和 1。比如有人想把摄氏温度换算成华氏温度，光靠一个 lerp 是做不到的——我们关心的定义域并不在 0 和 1 之间。当然，这件事的做法里一定包含 lerp，只是需要一点帮助。

如果要用 lerp 函数，我们的目标是先把输入弄到 0 到 1 之间。做法是从输入 value 里减掉 inputMin，让它从 0 开始，再除以定义域的大小：\[x=\frac{\text{value}-\text{inputMin}}{\text{inputMax}-\text{inputMin}}\] 现在输入定义域已经被驯服到 0 到 1 之间，我们对输出做完全相反的事：ofMap(value, inputMin, inputMax, outputMin, outputMax) \[=\frac{\text{value}-\text{inputMin}}{\text{inputMax}-\text{inputMin}}\cdot\left(\text{outputMax}-\text{outputMin}\right)+\text{outputMin}\]

举个例子。假设我们拿到一份以华氏度为单位的数据集。华氏度把 0 定为盐水的冰点、100 定为某个有点不舒服的英国人的体温（啊？）。要用这份信息做任何事，我们得先把它换算成摄氏度，因为摄氏度至少在 0 和 100 上用的是同一种该死的物质™：水。现在我们知道水在 \(32_{\text{f}}\) 结冰、在 \(212_{\text{f}}\) 沸腾，于是我们有了完全相同的目标区间，接下来就该做映射了。这里我们用一个数组：

vector<float> farenheitValues;
// 我们跳过填充它们的代码，因为已经有人做过了
vector<float> celsiusValues; // 建立一个空的 C++ vector，它是一个动态数组
for (int i = 0 ; i < farenheitValues.size() ; ++i){
	celsiusValues.pushBack(ofMap(32, 212, 0, 100, farenheitValues[i]));
}

看看我们做了什么。我们取了一个 32 到 212 的数值区间（我们称之为定义域），把它转换成另一个 0 到 100 的区间（我们称之为值域）。这里有两点值得注意：

  • 在数学里，我们常用定义域和值域这两个词来表示起点和目标。使用这些术语可以引出另一个我们关心的概念：关注点分离。如果我们知道一个函数接受的每个输入都必定落在某个定义域内，我们就可以把它设计成保证输出落在某个值域内，并确保它不会失败。事实上，这就是函数的数学定义：

一个函数是一种数学对象，它把某个定义域中的每一个值映射到某个值域中唯一对应的值。

  • 我们把 32 到 212 这个区间定义为一条线上我们已知的两个点。实际温度的区间从 -459.67（绝对零度，华氏）到某个非常非常巨大的值（称为普朗克温度）——计算那个很不方便。所以我们没有选整个区间，而是把它已知的一段映射到值域中已知的一段。我们之所以可以用 ofMap() 来做这件事，是因为这个刻度是线性的。有些刻度不是线性的；比如声音测量中常用的分贝（\(\text{dB}\)），它是对数的，所以在 \(0_{\text{dB}}\) - \(6_{\text{dB}}\) 到 \(6_{\text{dB}}\)-\(15_{\text{dB}}\) 之间做换算不传达任何意义。

超越线性：变化的变化

到目前为止我们讨论的都是被绑在一条线上的变化。但在 Real Life™ 里，直线之外还有很多东西：首先，我们甚至没法用直线描述周期性事件。如果我们要描述吉他弦的振动[脚注：这个例子听起来有点老派。我当然是指「dubstep 乐器的抖动」]，或者台球被撞击后变化的速度，就得用到更高阶的变化。

在这段讨论里，我们会看到如何通过巧妙地使用 lerp 来描述更高阶的复杂度。你会发现某些类型的变化可以用这种方式复现（比如那颗台球）——而另一些运动，比如简谐运动，则需要另一套机制。请记住，这里有些代码只是概念性的，不一定高效。

二次与三次变化率

考虑这个函数：

float quadratic (float t){
	float a1 = ofLerp(t, 5, 8);
	float a2 = ofLerp(t, 2, 9);
	float b = ofLerp(t, a1, a2);
	return b;
	}

这个函数用一段定义好的区间和一个参数生成了 a1，然后用另一段定义好的区间和同一个参数生成了 a2。它们的结果看起来很出人意料：

[GRAPHIC：QuadraticSpline.pdf，待处理]

我们在这里做成了一件了不起的事。我们利用一个参数在两条固定直线上的变化方式，去控制第三条完全可移动的直线，并在 0 到 1 之间的每一个时间点上于其上画一个点。用数学的话说，它长这样：

\[\begin{aligned} \text{lerp}&\left(t,\text{lerp}\left(t,5,8\right),\,\text{lerp}\left(t,2,9\right)\right) =\\ \text{lerp}&\left(t,8\cdot t+5\cdot\left(1-t\right),9\cdot t+2\cdot\left(1-t\right)\right)\\ = &\left(9\cdot t+2\cdot\left(1-t\right)\right)\cdot t+\left(8\cdot t+5\cdot\left(1-t\right)\right)\cdot\left(1-t\right)\\ = &\left(9t^{2}+2t-2t^{2}\right)+\left(8t+5-5t\right)-\left(8t^{2}+5t-5t^{2}\right)\\ = &4t^{2}+5 \end{aligned}\]

这里发生了件有意思的事。不知不觉中，我们引入了第二阶复杂度，也就是二次的复杂度。说真的，再看它一眼，把整个过程画在纸上。这很了不起。

同样的操作可以用到第三阶：

float cubic (float t){
	float a1 = ofLerp(t, 5, 8);
	float a2 = ofLerp(t, 2, 9);
	float a3 = ofLerp(t, 3, -11);
	float a4 = ofLerp(t, -2, 4);
	float b1 = ofLerp(t, a1, a2);
	float b2 = ofLerp(t, a3, a4);
	float c = ofLerp(t, b1, b2);
	return c;
	}

我们跳过完整的推导，直接揭晓结果会以 \[at^{3} + bt^{2} + ct + d\] 的形式出现。看出规律了吗？最高的指数就是我们连续套用的 ofLerp 次数，也就是我们把 lerp 函数嵌套进自身的次数。

……以此类推

大学微积分里有一条普遍的见解：只要你拥有足够多的某种东西，你就能做任何事。于是很应景地，数学里有一个有趣的小想法：只要有足够多的这种嵌套控制点，我们就能逼近任何能想象出的曲线段。在这个想法最初的表述里（称为泰勒级数），只有当阶数（我们连续套用 lerp 的次数）接近无穷大时，我们才能得到好的逼近。

在计算机图形学里，你马上就会看到——3 就已经足够接近了。

样条

我们在上一节做的事其实相当了不起。我们搭起了一组点的支架，在它们之上又搭了一层把点成对控制的支架，如此继续，直到最后只剩一个参数 \(t\) 来控制它们全体，进而控制绘制的整个过程。在我们为这一切划定的定义域里，我们可以明确地把它变成一个物理比喻：比如一堆在某个点彼此相连、可以弯折的滑尺。然而，出于你马上会看到的理由，数学家往往不愿把多项式描述成一个物理比喻。

原因在于多项式一旦离开为它精心设置的控制点，会发生什么。在控制范围之外，每个多项式最终都会走向无穷——这是个很宽泛的说法，但对我们设计师来说，它意味着只要稍微超出范围，我们就需要多得多的纸，或者屏幕空间，或者毛线，或者蟑螂（真事）才能把它画出来。

在图中，我们取了同一个三次（3 阶）多项式的几段，把它们挪来挪去、按口味缩放，并在每个点上把它们全部加起来（我们称之为「混合」）。

得到的曲线无缝且易于处理。它还带有一些美妙的性质：这种曲线保证了连接两个相邻点所需的方向变化量最小，不会产生多余的运动。换句话说，它是光滑的。

这些性质让这种造曲线的方式在计算机图形学里相当流行，你可能会在不同名字下遇到它的变体，比如 Beziér Curves 或 Spline Curves。用 C++ 实现它的代码有点长、有点枯燥，所以本章不深入——不过如果你好奇，它和我们上面讨论的生成多项式的代码是一样的，只是多了很多 if 语句来检查 t 是否落在正确的区间里。

其他类型的变化

本章给出了一些通过连续使用线性变化所能达到的变化率的例子。但变化率的内容远不止这些，无法都塞进来——比如三角函数（正弦和余弦）只能用多项式去逼近，而要真正描述它们，我们得进入频率的讨论。变化这个主题太宽，没有任何一个数学分支专门处理它——它几乎涵盖了我能想到的所有分支。在 Sound 一章里，你会多学一点关于频率处理的内容。在那之前，你已经拥有了一套能做很多事的工具箱。

更多维度：一点线性代数

到目前为止，我们探索了几种改变数轴上发生的事情的思路。这很不错，但我们想知道怎么做图形，而图形不止一个维度。我们远古的数学家祖先（开玩笑的，最重要的数学家大多活不过 30 岁。没开玩笑）在处理形状与结构的空间时也遇到了同样的问题，于是发明了一些复杂的机械。这套机械的漂亮名字叫线性代数，它正好就是字面意思：用代数运算（主要是加和乘）来控制许多条线。

在这部分你会学到许多关于如何存储和操作多维信息的概念。之后你就能用这些信息，借助 OpenGL 控制实时的三维图形，并用你对几何的精通去打动异性（或同性）。

向量

你可能在讨论方向或位置时听说过向量，而在明白它两者都能表示之后，也许会有点困惑。关于 Vectors™ 的真相是：

一个向量只是一个数组，用来存放多份同一类型的信息。

说真的，就这么简单。别躲了。

这种简单也正是它们强大的地方。就像数字 5 可以用来描述五公里、12 减 7 的结果，或者罐子里饼干的数量——向量也一样。

至于把这个数学对象当作什么用，取决于使用者。向量 \[v=\left[\begin{array}{c}5\\-3\\1\end{array}\right]\] 可以表示空间中的一个点、一个运动物体的方向、施加在你游戏角色上的力，或者只是三个数字。而且和数字一样，加法和乘法这样的代数运算也可以用在向量上。

哦，但这里有个陷阱。你看，每个人都被教过 \(a + b\) 是什么意思。要继续讨论向量，我们得先定义它。

向量代数

一般地说，在处理非数字的数值结构的代数时，我们需要特别注意我们搅在一起的东西的类型。就向量而言，我们会区分逐分量运算和整体运算。

标量乘法

向量与标量的乘积定义为：

\[a\left[\begin{array}{c} x\\ y\\ z \end{array}\right]=\left[\begin{array}{c} ax\\ ay\\ az \end{array}\right]\]

这属于整体运算，因为整个向量都经历同一个操作。注意这个操作其实就是缩放。

ofVec3f a(1,2,3);
cout << ofToString( a * 2 ) << endl; 
// 输出 (2,4,6)

向量加法

向量相加很直接：这是一个逐分量运算：

\[\left[\begin{array}{c} x_{1}\\ y_{1}\\ z_{1} \end{array}\right]+\left[\begin{array}{c} x_{2}\\ y_{2}\\ z_{2} \end{array}\right]=\left[\begin{array}{c} x_{1}+x_{2}\\ y_{1}+y_{2}\\ z_{1}+z_{2} \end{array}\right]\]

ofVec3f a(10,20,30);
ofVec3f b(4,5,6);
cout << ofToString( a + b ) << endl; 
// 输出 (14,25,36)

注：C++ 运算符重载

正如我们得先定义标量与向量的乘积是什么意思，编程语言——它们在处理数学对象的抽象表示——也需要把这类运算的定义内建进来。C++ 对这类情况做了特别的照顾，用的特性叫运算符重载：把 * 运算定义成接受一个标量和一个向量，分别作为左手边和右手边的参数：

ofVec3f operator*( float f, const ofVec3f& vec ) {
    return ofVec3f( f*vec.x, f*vec.y, f*vec.z );
}

同样的定义也存在于，比如，两个 ofVec3f 实例之间：

ofVec3f ofVec3f::operator+( const ofVec3f& pnt ) const {
	return ofVec3f( x+pnt.x, y+pnt.y, z+pnt.z );
}

它自然地表征了向量加法的想法。

基本算术运算 +、-、*、/、+=、-=、*=、/= 在 ofVec2f、ofVec3f 和 ofVec4f 的各种组合之间，以及任何向量对象与标量之间都存在。凡是以 = 结尾的运算，都会用该运算修改左手边，且仅此而已。+、-、*、/ 这些运算则总是返回一个副本。

ofVec 各类型的源文件里有几个运算符重载做得极好的范例。建议去看看。

警告：重载运算符会让你瞎眼。程序员用运算符时并不检查它到底做了什么，所以糟糕的重载造成的 bug 要很久才能被抓到。如果表达式 a + b 返回的是引用而不是副本、返回 null 而不是值、或者修改了某个输入值——总有一天会有人用它，而那个人会哭很多天。除非这个运算符只做一件算术的事、且仅此一件，否则不要用别的含义去重载它。openFrameworks 也许有个功能，会在你写出愚蠢的运算符重载时替你发推。没人知道。

点之间的距离

float ofVec3f::distance( const ofVec3f& pnt) const
float ofVec3f::squareDistance( const ofVec3f& pnt ) const
float ofVec3f::length() const
float ofDist(float x1, float y1, float x2, float y2);
float ofDistSquared(float x1, float y1, float x2, float y2);

先从一个定义说起。你可能记得勾股定理，它说明了从点 \(a\) 到 \(b\) 之间线段的长度是多少：\[\text{Distance}\left(\left[\begin{array}{c} x_{a}\\ y_{a} \end{array}\right],\left[\begin{array}{c} x_{b}\\ y_{b} \end{array}\right]\right)=\sqrt{\left(x_{b}-x_{a}\right)^{2}+\left(y_{b}-y_{a}\right)^{2}}\]

好消息是：在三维里定义完全一样！只要加上 \(z\) 那一项。\[\text{Distance}\left(\left[\begin{array}{c} x_{a}\\ y_{a}\\ z_{a} \end{array}\right],\left[\begin{array}{c} x_{b}\\ y_{b}\\ z_{b} \end{array}\right]\right)=\sqrt{\left(x_{b}-x_{a}\right)^{2}+\left(y_{b}-y_{a}\right)^{2}+\left(z_{b}-z_{a}\right)^{2}}\]

于是向量的长度自然可以定义为向量与点 \(\left(0,0,0\right)\) 之间的距离：\[\text{Length}\left(\left[\begin{array}{c} x\\ y\\ z \end{array}\right]\right)=\sqrt{x^{2} + y^{2} + z^{2}}\]

而这正是你使用任何 ofVec 的 .length() 时得到的东西。

向量乘积：不止一种

所以你在把两个数相乘。简单吧？五百万零七乘以三等于某个你知道的东西。即使你需要计算器才能得出结果，你仍然知道它是一个数——向量就不是这样了。如果我们只是想把向量改变大小（就像我们对数字做的那样），我们把向量乘以一个标量，它就变长了。但把一个向量乘以另一个向量，在几何上到底是什么意思？

如果我们遵循我们建立的逐分量约定，会得到这样一个运算：

cout << ofToString(ofVec3f(1,2,3) * ofVec3f(1,2,3)) << endl;
// 输出 (1,4,9)

它也被称为哈达玛积。这很直观，但不太有用。它有用的一个场合是：我们想在每个维度上分别缩放某个东西。

下一节我们讲一些更有帮助的东西。

点积

float ofVec3f::dot( const ofVec3f& vec )

两个向量的点积，其定义乍看并不太清楚。一方面，这个运算可以定义为 \[v_{a}\bullet v_{b}=x_{a}\cdot x_{b}+y_{a}\cdot y_{b}+z_{a}\cdot z_{b}\]，这实现起来非常容易（事实上，显卡有专门的电路就干这个！）。另一方面，它也可以定义为 \[v_{a}\bullet v_{b}=\left\Vert v_{a}\right\Vert \cdot\left\Vert v_{b}\right\Vert \cdot\cos\theta\]，其中 \(\theta\) 是两个向量之间的夹角。你很快会看到，这是一个相当幸运的巧合。在此之前，先说说你应该怎么记住点积：

\(a\) 与 \(b\) 的点积，反映的是一个向量在另一个向量方向上的投影有多少。

等等。故事还没完。如你所见，\(\left\Vert v_{a}\right\Vert \cdot\left\Vert v_{b}\right\Vert\) 这部分在 \(\left\Vert v_{a}\right\Vert \cdot\left\Vert v_{b}\right\Vert \cdot\cos\theta\) 中，应该告诉你：两个向量的长度在决定最终结果的大小上各占一份，但在大多数实际场合，你用点积是为了确定某个向量的长度，或者向量之间的夹角。

这就是为什么点积是这样一个惊人的巧合：如果你知道 \(v_{a}\) 和 \(v_{b}\) 的长度，\(\cos\theta\) 就白送给你了。如果你知道 \(v_{a}\) 和 \(v_{b}\) 所在的平面、其中一个向量以及到另一个向量的夹角，你就能便宜地得到另一个，依此类推。在典型用法中，如果我们取两个长度都为 1 的向量（用数学的话说，归一化向量），点积 \(a⋅b\) 基本上就是它们夹角的余弦。这个由 \(\cos\theta\) 描述的关系，很容易理解为一种投影：想象从一个轴的上方打光，观察落在另一个轴上的影子。它有多长、朝哪个方向，与点积完全一致（事实上，大多数光照模型几乎一切地方都在用点积）。

例子：判断一个点在平面的上方还是下方

这是我们在三维图形里经常遇到的问题：给定一个点 \(p\) 和一个平面，我们需要判断这个点在平面的哪一侧。如果你想决定场景里不渲染什么以节省处理时间，这会非常有用。

描述一个平面有许多等价的方式。在这个场合最优雅的一种，是用平面的法线（垂直于平面两个轴的方向），我们把它记作向量 \(n\)，以及到原点的距离 \(d\)（注意，因为平面可以位于原点下方，这个距离可以是负数）。这是一个有效的定义：平面可以定义为世界上所有与法线构成垂直向量的点。

现在看数学：

如果点 \(p\) 在平面上。我们知道平面上的每条线都垂直于（与法线成 90 度角）法线。具体来说，每条把平面上某个点连到我们放置法线的那个点（它同样在平面上）的线都是如此，所以如果我们从这条线中取出方向向量，称它为 \(v\)，我们可以说：\[n∙v = \left\Vert n\right\Vert ⋅\left\Vert v\right\Vert ⋅\cos90^{\circ} = \left\Vert n\right\Vert ⋅\left\Vert v\right\Vert ⋅0 = 0\]。

如果点 \(p\) 不在平面上。那种情况下我们知道它肯定不与平面的法线 \(n\) 成 90 度角，因此点积 \(n\bullet v\) 不会为零。所以我们只需知道：它是投影到法线的正方向上，还是负方向上？为此，我们先找平面上的一点。这很容易，我们当初把平面定义成：沿法线 \(n\) 从原点 \(\left(0,0,0\right)\) 走一段长度 \(d\) 就能到达的地方。

因此点 \(q = d⋅n\) 肯定在平面上。

现在，我们从点 \(p\) 到那个点造一个向量：\(v = q - p\)。这个等式成立，是因为两个点相减得到它们之间的差，也就是从 \(p\) 指向 \(q\) 的方向。现在我们来计算：\[v∙n = v_{x}⋅n_{x}+v_{y}⋅n_{y}+v_{z}⋅n_{z}\]

  • 如果点积为正，法线与指向平面上某点的线方向相同，这意味着点 \(p\) 在平面的下方。
  • 如果点积为负，从该点指向平面的线必须往回走，因此该点在平面的上方。

代码如下：

// 我们为数值误差定义一个容差
float const EPSILON = 0.00001;

// 一个函数：如果点在平面下方返回 -1，
// 在平面上方返回 1，在平面上返回 0
int whichSide(ofVec3f planeNormal, float planeDistance, ofVec3f testPoint){
	ofVec3f directionToPlane = planeDistance * planeNormal - testPoint;
	float dot = directionToPlane.dot(planeNormal);
	if (abs(dot) < EPSILON){ // 检查点积是否非常接近零
		return 0;
	} else { // 否则返回它符号的相反数！
	return (dot < 0 ? 1 : -1);
	}
}

注意代码里我们必须照顾计算机的数值不精确性，给它一个容差来决定某个向量有时垂直于该法线。另一种做法是忽略这些情况，规定凡是 dot > 0 的都在平面下方。我更喜欢现在这样。

如这个例子所示，点积很神奇：仅仅知道坐标，我们就白得了关于向量之间夹角的洞见。

矩阵™

在计算机的世界里，程序要运转需要两样东西：算法和数据结构（它还需要 I/O，但我们谈的是计算，不是工程）。在三维数学的世界里也一样：我们把数据结构称为「向量」，把算法称为运算。

在为控制三维空间而建的重型机械的核心，矩阵只是一个数据结构，和向量一样。然而，施加在这个数据结构上的「算法」（在数学世界里叫运算）让它变得极其强大。我们在三维里关心的所有仿射运算都可以用矩阵的形式描述：平移、旋转、缩放、翻转、挤压、错切、投影等等，还有更多。记住它有个简单的办法：

一个矩阵是一种数学对象，它可以存放对点的一种几何变换。

记号约定：处理矩阵时，大多数作者习惯用小写字母标记向量，用大写字母标记矩阵。

单位矩阵

从最简单的情形开始。和数字一样，任何代数结构都有一个非常重要的性质：每个运算都有一个中性元素。比如在数字国里，任何 \(x\) 乘以 1 都返回 \(x\)，加 0 也一样。在矩阵国里，那个单位元素是一个对角线为 1、其余为零的矩阵。比如三维的单位矩阵是：

\[I_{3} = \left[\begin{array}{ccc} 1 & 0 & 0\\ 0 & 1 & 0\\ 0 & 0 & 1 \end{array}\right]\]

所以对任何矩阵 \(M\)，\[MI = IM = M\]。

注：你可能注意到我们现在对乘法的顺序非常小心，比如我们特意说明了 \(MI = IM\)。这是有充分理由的，几页之后你就会发现。

缩放

你可能记得，在缩放一个向量时（也就是空间中的点和/或速度、和/或力、和/或某个颜色的亮度值等等），我们可以选择用标量乘法均匀地缩放它：

ofVec3f v(1, 2, 3);
cout << ofToSting(v * 5) << endl; // 输出 (5, 10, 15)

或者，由于一个奇怪的语言设计选择，大多数图形应用允许你按分量进行非均匀缩放：

ofVec3f v1(1, 2, 3);
ofVec3f v2(10, 100, 1000);
cout << ofToString(v1 * v2) << endl // 输出 (10, 200, 3000)

为了终结这种疯狂，矩阵乘法里的缩放是有明确定义的[脚注：「有明确定义」不只是句恭维，它是一个数学术语，大意是说只要你遵守规则，计算就永远不会——可以这么说——崩掉：它永远不会产生超出你所定义形式的结果。比如除以零是无定义的，因此除法在包含零的实数定义域上没有明确定义。有人把这一环补上了，把除以零定义为恰好 \(\infty\)，于是对任何包含无穷的范围来说，除法都是有明确定义的。你在编程语言里会遇到同样的问题：有些运算会产生不兼容的结果。许多人批评 C++ 太经常允许这种事发生，而其他语言（比如 Haskell、Erlang 和 OCaml）更严格，只允许使用有明确定义的运算，于是编译器能抓住你的错误，而不是最终用户。]，在 openFrameworks 里（在数学里也是！）。它是这样的：矩阵 \(S\) 把 \(\left(x,y,z\right)^{T}\) 缩放为 \(\left(ax,by,cz\right)^{T}\)，其形式是：\[S\cdot \left[\begin{array}{c} x\\ y\\ z \end{array}\right]=\left[\begin{array}{ccc} a & 0 & 0\\ 0 & b & 0\\ 0 & 0 & c \end{array}\right] \cdot \left[\begin{array}{c} x\\ y\\ z \end{array}\right] = \left[\begin{array}{c} ax\\ by\\ cz \end{array}\right]\]

这背后有逻辑。回想一下，一个向量乘以一个矩阵，\(M\cdot v\) 就是一串点积：\[M\cdot v=\left[\begin{array}{c} M_{1}\\ M_{2}\\ M_{3} \end{array}\right]\cdot v=\left[\begin{array}{c} \begin{array}{c} M_{1}\cdot v\\ M_{2}\cdot v\\ M_{3}\cdot v \end{array}\end{array}\right]\]

所以，为了让这次乘法只影响 \(x\)，我们把向量的（矩阵的上行）\(M_{1}\) 调成除了与 \(x\) 相接处之外全为零：\[M_{1} = \left(a,0,0\right)\] 于是整个计算会是：

\[M\cdot v=\left[\begin{array}{c} M_{1}\\ M_{2}\\ M_{3} \end{array}\right]\cdot v= \left[\begin{array}{ccc} a & 0 & 0\\ M_{2,1} & M_{2,2} & M_{2,3}\\ M_{3,1} & M_{3,2} & M_{3,3} \end{array}\right]\cdot v=\left[\begin{array}{c} \begin{array}{c} a\cdot v_{x} + 0\cdot v_{y} + 0\cdot v_{z}\\ M_{2,1}\cdot v_{x} + M_{2,2}\cdot v_{y} + M_{2,3}\cdot v_{z}\\ M_{3,1}\cdot v_{x} + M_{3,2}\cdot v_{y} + M_{3,3}\cdot v_{z} \end{array}\end{array}\right]\] 让结果向量的 \(x\) 分量正好成为 \(a\cdot v_{x}\)，和承诺的一样。

那么任何矩阵 \(M\) 的标量乘法就变得很简单：它本质上就是右乘一个对角线上全是 \(a\) 的对角矩阵：\[a\cdot M = a \cdot I \cdot M\]

错切矩阵

像错切这样的奇怪运算，正是需要少一点直觉、多一点逻辑的地方。想到错切时，我们通常想象给某个维度（假设是 \(x\)）加上另一个维度（比如说 \(y\)）中某个量的一部分。假设那个比例是 \(0 < a \leq 1\)，就好像在说「我想把它轻轻推一下，它离地面越远推得越多」。在二维里做这件事的矩阵长这样：\[S = \left[\begin{array}{cc} 1 & a\\ 0 & 1 \end{array}\right]\] 看到我们做了什么吗？我们让结果的 \(x\) 值依赖于输入的 \(x\) 值（乘以 1），同时也轻微依赖输入的 \(y\)，而轻微到什么程度由 \(a\) 的大小决定：

\[S\cdot v = \left[\begin{array}{cc} 1 & a\\ 0 & 1 \end{array}\right] \left[\begin{array}{c} x\\ y\end{array}\right] = \left[\begin{array}{c} 1\cdot x + a\cdot y\\ 0\cdot x + 1 \cdot y\end{array}\right] = \left[\begin{array}{c} x + ay\\ y\end{array}\right]\]

挺妙的吧？试着记住这个技巧，因为当我们在第四维里搬动东西时会经常用到它。我一点也没开玩笑。

旋转矩阵

现在我们看到，矩阵国里的任何运算其实都可以表示成一组向量。我们也知道，向量的点积表达的是两个向量之间的夹角乘以它们的模长。一个略让人吃惊的事实是：这两条性质就足以描述任何旋转。

为了理解这最后一句，我们先解释旋转一个向量是怎么回事。取向量 \[v_0 = \left[\begin{array}{c} 1\\ 0 \end{array}\right]\] 我选了一个完全与 \(x\) 轴重合的向量。现在假设我们想把这个向量从原点出发旋转一个角度 \(\theta\)。利用我们关于单位圆的知识，可以把旋转后的向量描述为 \[v_{\theta}=\left[\begin{array}{c} \cos\theta\\ \sin\theta \end{array}\right]\]

现在我们为 \(x\) 轴找到了要去的地方。用同样的旋转，我们试着找出原来的 \(y\) 轴（向量 \(u_0 = \left[\begin{array}{c} 0\\1\end{array}\right]\)）去了哪里，只需要知道它们之间的夹角。幸运的是，我们都知道它是 90 度，或者用弧度说：\(\frac{\pi}{2}\)。那么它的新家就必须在距 x 轴（角度 0）\(\theta + \frac{\pi}{2}\) 的角度上：

\[u_{\theta}=\left[\begin{array}{c} \cos\left(\theta+\frac{\pi}{2}\right)\\ \sin\left(\theta+\frac{\pi}{2}\right) \end{array}\right] = \left[\begin{array}{c} -\sin\theta\\ \cos\theta \end{array}\right]\]

最后一个等式来自三角恒等式。

二维旋转矩阵

现在我们有了构造一个矩阵所需的全部信息，这个矩阵会移动这些向量

\[\left\{ \left[\begin{array}{c} 1\\ 0 \end{array}\right],\left[\begin{array}{c} 0\\ 1 \end{array}\right]\right\} to \left\{ \left[\begin{array}{c} \cos\theta\\ \sin\theta \end{array}\right],\left[\begin{array}{c} -\sin\theta\\ \cos\theta \end{array}\right]\right\} :\] \[R\left(\theta\right)= \begin{bmatrix} \cos \theta & -\sin \theta \\ \sin \theta & \cos \theta \end{bmatrix}\]

等等。看看我们做了什么：我们把源向量的目标位置作为列放进了矩阵，然后取矩阵结果的行来做旋转。为什么这么做？

回想一下，矩阵只是一叠点积。我们是怎么构造这些点积的？我们把所有应该影响结果那一项的元素，对齐到矩阵的同一行。这意味着，在考虑结果的 \(y\) 项时，我们的向量定义了：在结果运算中我们希望看到的、来自目标向量的\(y\) 分量的混合方式。这说得通：把构成矩阵的向量想成一个新的坐标系，而我们计算的，是「自然」坐标系如何投影到它们上面。

三维旋转矩阵

在 Flatland 里，Edwin A. Abbott 描述了一个二维生物无忧无虑、快乐地生活着的国度，直到其中一个遇上了三维的东西。他的心智被震住了——他很快明白了其中的含义；当他试图向生活在他世界里的其他正方形解释时，他们感到惊恐，把他当作异端放逐了。

三维里的旋转比二维旋转更难理解。情况多得多，而要理解非平凡的旋转，人必须真正从四维去看。这似乎惹恼了许多平时不在四维里思考的人。说了这么多，这一节也请留下来。

欧拉角

思考三维旋转最简单的方式，就是把它们想成一系列二维旋转。我们把这叫做嵌套一个维度。

在三维国里绕一个轴旋转的技巧，和在二维国里完全一样：要绕一个轴旋转，我们只需用一个二维旋转矩阵（想想看：绕一个轴的旋转此时还不依赖其他轴），再给它加一个中性的维度。下面是用单个旋转轴时，三维旋转矩阵的样子：

\[\begin{aligned} R_{x}(\theta) &= \begin{bmatrix} 1 & 0 & 0 \\ 0 & \cos \theta & -\sin \theta \\ 0 & \sin \theta & \cos \theta \\ \end{bmatrix}\\ R_{y}(\theta) &= \begin{bmatrix} \cos \theta & 0 & \sin \theta \\ 0 & 1 & 0 \\[3pt] -\sin \theta & 0 & \cos \theta \\ \end{bmatrix} \\ R_{z}(\theta) &= \begin{bmatrix} \cos \theta & -\sin \theta & 0 \\ \sin \theta & \cos \theta & 0\\ 0 & 0 & 1\\ \end{bmatrix} \end{aligned}\]

这确实是绕单个轴旋转的有效方法。研究这类旋转的著名数学家 Leonhard Euler 很早以前就指出：这种方法（后来以他命名）虽然适合绕单轴旋转，但要表述多轴旋转并不简单。要理解这一点，最容易的办法是拿一个魔方，先绕它的 \(x\) 维扭转，再绕它的 \(y\) 维扭转。记住那些独特的方块移到了哪里，复原，然后换成一先绕 \(y\) 再绕 \(x\) 试一次。结果会不一样！

注意到这一点，我们就知道在超过两维的空间里旋转东西时，不仅要知道旋转的角度，还要知道施加它们的顺序。旋转矩阵 \(R_{zx}\left(\theta\right) = R_{z}\left(\theta\right)⋅R_{x}\left(\theta\right)\) 和 \(R_{xz}\left(\theta\right) = R_{x}\left(\theta\right)⋅R_{z}\left(\theta\right)\) 并不相同。差异的原因会在下一节解释。

矩阵代数

本章介绍了一种和你以往习惯的不同的数学。但在引入一种用来做事的新东西的同时，我们也打开了许多未勘探的危险。注意我们总是按一定顺序把向量乘以矩阵：向量总是在矩阵之后，向量总是被转置，而任何施加到既有情形上的新运算，总是以一个位于我们结果左侧的矩阵出现。这一切都有个原因：交换律。

Commmumamitativiwha？

在中学代数里，我们习惯于认为 \(a\cdot b=b\cdot a\)。没理由不这么想：你拥有的铀棒数量乘以我拥有的受过特殊训练的猴子数量，无论乘法顺序如何，造成的伤亡数都一样。那是因为数量是可交换的，它们彼此施加运算的顺序无关紧要。

但在矩阵国里我们谈的不是我们数过的东西——而是运算，情况是这样的：

运算（比如旋转、平移和缩放）若以不同顺序施加，可能描述出不同的结果。

还有什么奇怪的？

没有了。我们仍然可以按任何我们想要的顺序乘矩阵和向量：\[M_{1}⋅M_{2}⋅v = \left(M_{1}⋅M_{2}\right)⋅v = M_{1}⋅\left(M_{2}⋅v\right)\] 只要不改变它们出现的顺序。这个性质叫结合律，它是描述几何运算的代数结构的定义性性质之一，数学家把这类结构称为群。交换律对群来说是个可选性质，它恰好在处理数字之间的运算时总是成立，这就是为什么从没人告诉过你需要它。这里有个教训：仿真把许多性质当作理所当然。有时问问为什么是好事。

「全栈」

平移矩阵

如果你还记得本章开头的注释，数学家在把东西称为线性时非常谨慎。在二维里，一个线性运算基本上只能做两件事：旋转和缩放（包括负缩放——「镜像」）。原因是，这些都是能在 n 维中对任何 n 维形状做的运算（在我们的例子里把 n 换成 3）。

如果整个形状神奇地抬起来、离开原点——那就没法用矩阵做到，因此它不是线性的。这给那些想用矩阵作为控制三维的代数系统的人带来了问题：现实里我们需要搬动一些东西。

齐次坐标：在四维里黑进三维

这个问题给 openFrameworks 社区带来了几百年的痛苦，直到 1827 年，一位叫 Möbius 的黑客给 ofMäth 的 SVN 仓库推了一个更新：用四维的矩阵来控制三维的形状。花招是这样的：一个三维运算可以描述成一个对第四维什么都不做的四维运算。写成矩阵，我们可以这样描述它：

\[A _{4\times 4} = \left[\begin{array}{ccc|c} a_{1,1} & a_{1,2} & a_{1,3} & 0\\ a_{2,1} & a_{2,2} & a_{2,3} & 0\\ a_{3,1} & a_{3,2} & a_{3,3} & 0\\ \hline 0 & 0 & 0 & 1 \end{array}\right]\]

我们已经知道，一维错切可以把该轴上的所有线沿某个方向移动而不影响其他维度，二维错切会对某个平面上的所有东西这么做，所以很容易想象三维错切会对嵌入在更高维空间里的三维空间这么做。Möbius 觉得这个特性很有用，他在 Tübingen 的两年一届 openFrämeworks 会议上提议，所有运算都在四维空间里进行，然后再投影回三维空间，像这样：

\[T = \left[\begin{array}{ccc|c} 1 & 0 & 0 & t_{x}\\ 0 & 1 & 0 & t_{y}\\ 0 & 0 & 1 & t_{z}\\ \hline 0 & 0 & 0 & 1 \end{array}\right]\]

三维变换向量 \(t\) 被放在第四维，它的第 4 项为 1（因为 1 对乘法是中性的）。新增的底行在 \(x,y,z\) 各项上为零，以避免干扰其他运算。看看一个向量乘以这个矩阵会发生什么：

\[T\cdot v = \left[\begin{array}{ccc|c} 1 & 0 & 0 & t_{x}\\ 0 & 1 & 0 & t_{y}\\ 0 & 0 & 1 & t_{z}\\ \hline 0 & 0 & 0 & 1 \end{array}\right]\cdot\left[\begin{array}{c} x\\ y\\ z\\ \hline 1 \end{array}\right]=\left[\begin{array}{c} x+t_{x}\\ y+t_{y}\\ z+t_{z}\\ \hline 1 \end{array}\right]\]

现在我们只需丢弃第四维，就得到了平移后的点。挺酷的吧？

注意，因为我们在 \(w\)（第 4）维放了 1，所有乘法运算都透明地穿过了那个分量。这个技巧成了大多数计算机几何系统的标准。Möbius 在这个理论里其实还有更多内容：如果我们把那个 1 换成别的东西，就能模拟向相机针孔的投影。本章不会涉及数学中这个迷人的部分，但等你用 OpenGL 搭建相机时，记得想起这个了不起的黑客手法。

SRT（缩放-旋转-平移）运算

现在我们定义了我们最喜欢用来描述空间中（大致）真实物体的运算。接下来花几段讲讲如何把所有运算组合起来。

如果你还记得，几何运算是不可交换的，意思是如果我们按某个特定顺序定义它们，改变顺序并不保证会给我们相似的结果。因此，在搭建图形系统时我们必须系统地保持警惕，这样才能实现「让这个地球绕它的轴转，它在阳光下泛着好看的光」这类人类想法，而不会不小心让太阳绕同一个轴转，造成一个非常令人困惑、非常短的一年。

我们保持警惕的方式，是为处理对象预先定好一个顺序。拿纸笔算一下，不用太久就能推出这个顺序：1. 修改缩放（如有必要，否则施加单位缩放）。2. 修改朝向（如有必要，否则施加单位旋转）。3. 修改位置（如有必要，否则施加单位平移）。

任何其他顺序都会造成奇怪的效果，比如东西一边长大一边绕着偏离的轴自转（如果你搞动画的话，就是锚点／枢轴）。这看起来像是常识，但 Ken Perlin 指出，这套体系成为三维的标准不过是在八十年代末。

这组运算叫 SRT，即缩放-旋转-平移，因为它可以用下面这个矩阵序列描述：\[T⋅R⋅S⋅v\] 其中最先发生的运算，是最靠近向量 \(v\) 的那个。

如果你还记得，我们可以把所有这些矩阵乘起来，得到代表整个运算的一个矩阵：\[M = T⋅R⋅S\]

我们把这个矩阵称为 \(M\)，因为它把我们给它的对象放到它们在模型中的位置上。每当你在某个对象上调用 ofTranslate()、ofRotate()、ofScale()（或等价物），该运算就施加到当前活动的模型矩阵上。每当你执行 ofPushMatrix()，该矩阵的一个副本就被存进矩阵栈，以便你在需要时回到它。而当需要时，你就用 ofPopMatrix()，它会让当前矩阵 \(M\) 被删除，并用矩阵栈顶的一个矩阵替换它。这就是关于矩阵的全部秘密。就这样。

quat.makeRotate(ofVec3f(1,0,0), ofVec3f(0,1,0));
ofVec3f myRotatedVector = quat * myUnrotatedVector;
cout << ofToString(myRotatedVector) << endl;
// 输出 (0,1,0)
