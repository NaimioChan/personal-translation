OpenFrameworks 在 iOS 设备上

简介

OpenFrameworks 的魅力在于它的跨平台特性：同一份代码可以跑在桌面和移动设备上，并得到相同的结果。

OpenFrameworks 对 iPhone 的支持始于最早期的 iPhone（iPhone 2 或 3——待核实！）发布的时候。OF 社区里一些聪明人意识到，iPhone 支持 OpenGL，而这恰好也是 OF 用来渲染图形的东西；更重要的是，C++ 代码可以和 Obj-C 代码混用。有了这两块关键的拼图，剩下的就是调整 OF 核心代码，开始支持 iOS 设备。ofxiPhone 就这样诞生了。

此后 Apple 又发布了 iPad 等一系列设备，ofxiPhone 这个名字就不那么准确了，最终改为 ofxiOS，即 OpenFrameworks 对所有 iOS 设备的支持。

Objective-C 入门

我们简单提到过 Objective-C，简称 Obj-C，有些人可能知道它是什么，有些人可能不知道。Obj-C 是 Apple 用于 OSX 和 iOS 系统的主要编程语言。Obj-C 同时还是 C 语言的超集，因此可以用 Obj-C 编译器编译 C 和 C++ 代码，也就是说可以把 OF 的 C++ 代码和原生 Obj-C 代码混在一起。

有些人这会儿可能正在绝望地长叹一口气，心想：“我才刚把 C++ 弄明白一点，现在又得学 Obj-C……搞什么啊？！”算你走运，OpenFrameworks 已经把苦活都干完了，把大部分 Obj-C 代码藏了起来，你不用操心。使用 OpenFrameworks 的 API，你可以访问大多数 iOS 设备功能，比如陀螺仪、加速度计或摄像头，一行 Obj-C 代码都不用写。但是，总有一天你会对 iOS 环境驾轻就熟，想访问某个非常具体的东西，具体到 OF 压根没考虑过替你封装。这种时候你就得戴上 Obj-C 的帽子，亲自动手了。

Obj-C 的语法乍看之下有点吓人。我第一次看到它时确实被吓得不轻。你可能还会注意到它异常地长，这是因为它非常显式：所有函数名都极具描述性，说明了它们所执行的功能，这些词加起来就很长。你也许会觉得用显式的语言干活更费时间，但事实恰恰相反，因为函数更容易找到，而且在 XCode 里你通常只要开始输入想找的函数，XCode 就会给出建议列表，并替你补全函数名。

Obj-C 类的结构

和 C++ 一样，Obj-C 里你的代码分成两个文件：头文件和实现文件。头文件仍然是 .h 扩展名，而实现文件是 .m 扩展名。下面是一个非常基础的例子，展示这两个文件长什么样。

我创建了一个叫 MyClass 的类，它继承 UIView 类。

在下面的头文件（.h）里，我们需要定义类的接口，写在 @interface 和 @end 标签之间。类接口定义实例变量和公开方法，但现在我们先让它空着。

@interface MyClass : NSObject {
    //
}

@end

实现文件（.m）是你为头文件中定义的方法编写实际代码的地方。你要做的第一件事是导入定义了结构的 MyClass.h 头文件，然后在 @implementation 和 @end 标签之间写你的实现。

#import "MyClass.h"

@implementation MyClass

@end

在 XCode 里新建 Obj-C 类

XCode 的好处是，你第一次创建类时它会替你生成类的基本结构，让编程更省事，你不必每次都把上面的代码结构敲一遍。打开 File 菜单，依次选择 New 和 File...，会弹出一个对话框，列出 XCode 能为你创建的所有文件。选择 Objective-C class，又会弹出一个对话框，让你给新类命名并指定它继承哪个 Subclass。MyClass 随后就会被自动生成，等着你往里填代码。

变量与方法

现在我们有了类的骨架，来给它加点方法和变量，让它真正能做点事。从简单的开始：假设 MyClass 里有两个字符串变量，一个存我的名，一个存我的姓。我们还需要一些方法，用来设置和读取类里的这些变量。

MyClass 的头文件（.h）现在长这样，

@interface MyClass : NSObject {
    NSString * firstName;
    NSString * lastName;
}

- (void)setFirstName:(NSString *)nameStr;
- (void)setLastName:(NSString *)nameStr;

- (NSString *)getFirstName;
- (NSString *)getLastName;

@end

在 MyClass 接口里，你现在能看到定义了两个 NSString 变量：firstName 和 lastName。NSString 是 Obj-C 里对应 C++ string 的类型。* 表示 firstName 和 lastName 是指向 NSString 对象的指针。在 Obj-C 里，所有实例变量默认都是私有的，也就是说你无法从类对象外部直接访问它们，所以需要创建存取方法（accessor）来设置和获取这些值。

我们来看看 Obj-C 里方法是怎么组织的，以 setFirstName 为例，

- (void)setFirstName:(NSString *)nameStr;

每个 Obj-C 方法前面第一样东西是一个减号 - 或一个加号 +。减号表示该方法是实例方法，加号表示该方法是类方法。接下来是方法的返回类型。在这个实例方法里我们是在设置名，不返回任何值，所以返回类型是 void。然后是方法名 setFirstName，再用冒号 : 分隔出我们传给方法的变量。这个例子里我们传入一个 nameStr 变量，并且必须指定该变量的类型，即 NSString。

现在我们在类接口里定义了变量和方法，来看看实现文件，我们的功能代码会放在那里。

#import "MyClass.h"

@implementation MyClass

- (void)setFirstName:(NSString *)nameStr {
    [firstName autorelease];
    firstName = [nameStr retain];
}

- (void)setLastName:(NSString *)nameStr {
    [lastName autorelease];
    lastName = [nameStr retain];
}

- (NSString *)getFirstName {
    return firstName;
}

- (NSString *)getLastName {
    return lastName;
}

@end

从结构上看，这些方法和类接口里的几乎一模一样，只是现在每个方法末尾都多了花括号 { 和 }，表示方法代码的开始和结束。两个 getter 方法（getFirstName 和 getLastName）非常直白，只是返回一个指向 NSString 变量的指针。setter 方法（setFirstName 和 setLastName）包含的代码更 Obj-C 特有，我们也是在里第一次接触到 Obj-C 的内存管理。

内存管理

我们来看看 setFirstName 方法里发生了什么。

[firstName autorelease];
firstName = [nameStr retain];

上面这些做的只是给 firstName 赋一个新的字符串值，但它同时确保在 retain 新值之前先释放旧值，以防内存泄漏。对对象调用 autorelease，就是告诉这个对象在不久的将来某个时刻、在它不再被使用时释放自己，通常是在方法末尾不再需要它的时候。接着我们需要 retain 新的字符串，你可以把它理解为把这个字符串绑定到 NSString * firstName 这个指针引用上。对象的 retain/release 是 Obj-C 内存管理系统的核心，这套机制叫作引用计数。

引用计数的基本理论是：每当对象被 retain，引用计数加 1；每当它被 release，引用计数减 1。当引用计数降回零时，对象就从内存中被释放。

创建 Obj-C 对象有几种方式，我们用 NSString 类来演示。下面是使用 alloc 方法创建 NSString 对象的代码示例。对 NSString 类调用 alloc 会返回一个新的 NSString 对象。这里有一点非常重要：用 alloc 创建对象时，它的引用计数就是 +1。也就是说，在背后 Obj-C 已经创建了一个新的字符串对象，并替我们对该对象调用了 retain。代码示例的最后一行用一段文字初始化这个字符串对象，文字是 \"I'm a string\"。

firstName = [NSString alloc];
[firstName initWithString:@"I'm a string"];

创建字符串的另一种方式是用下面代码示例里的 NSString 类方法。用类方法创建对象时，它处于 autorelease 状态，也就是说引用计数是 +1，但因为它被标记为 autorelease，如果没有被 retain，不久后就会从内存中释放。这就是为什么我们需要对这个新字符串对象调用 retain，好让我们能保住它的引用，在代码的其他地方使用。

firstName = [NSString stringWithString:@"I'm a string"];
[firstName retain];

Obj-C 内存管理的通则：如果你用 alloc 方法创建了对象，或者对某个对象调用了 retain，你就对那个对象负有责任，将来某个时候你必须 release 它。

入口与出口

了解了刚才讨论的一切，我们再来看一次 MyClass，这次它包含 init 和 dealloc 方法，也就是所有 Obj-C 对象的入口和出口。

#import "MyClass.h"

@implementation MyClass

- (id)init {
    self = [super init];
    if(self != nil) {
        firstName = [[NSString alloc] initWithString:@"Lukasz"];
        lastName = [[NSString alloc] initWithString:@"Karluk"];
    }
    return self;
}

- (void)dealloc {
    [firstName release];
    [lastName release];
    [super dealloc];
}

- (void)setFirstName:(NSString *)nameStr {
    [firstName autorelease];
    firstName = [nameStr retain];
}

- (void)setLastName:(NSString *)nameStr {
    [lastName autorelease];
    lastName = [nameStr retain];
}

- (NSString *)getFirstName {
    return firstName;
}

- (NSString *)getLastName {
    return lastName;
}

@end

init 和 dealloc 方法在每个 Obj-C 对象里都已经定义好了，所以我们是在扩展这些方法、覆盖它们的行为。init 方法是每个 Obj-C 对象上第一个被调用的方法，因此是初始化变量的理想位置。init 方法总是返回自身的一个引用，类型是 id，在 C++ 里相当于返回 void *。由于我们是在扩展 init 方法，必须确保先调用它的父类方法，否则对象无法正确初始化。然后我们确保 [super init] 被成功调用、没有出问题，再初始化变量 firstName 和 lastName。init 方法最后要做的一件事是返回自身的引用。

dealloc 方法在对象即将从内存中释放时被调用，因此是释放该对象持有的其他内存的最佳位置。firstName 和 lastName 对象被释放，最后一件要办的事是调用 [super dealloc] 方法，之后对象从内存中彻底移除。

属性

Obj-C 的好处之一是它尽可能提供语法糖，让编程快得多。在 MyClass 里，我们不得不为把 firstName 和 lastName 传入对象而写 getter 和 setter 方法。其实 Obj-C 里有一种快得多的方式声明 getter 和 setter，那就是属性（property）。属性是一种语法特性，可以自动声明 getter 和 setter 访问器。头文件里 @property 语法长这样，

@interface MyClass : NSObject {
    NSString * firstName;
    NSString * lastName;
}

@property (retain) NSString * firstName;
@property (retain) NSString * lastName;

@end

可以看到，我们丢掉了旧的 getter 和 setter 方法，换成了 @property 语法。在 @property 标签后面，我们还可以声明一些额外的 setter 属性，这里括号里写的是 retain。这意味着每次我们用 firstName 属性设置新值时，它都会自动 retain 新的 NSString，非常省事，也意味着我们用更少的代码得到同样的结果。

接下来进入实现文件，

#import "MyClass.h"

@implementation MyClass

@synthesize firstName;
@synthesize lastName;

- (id)init {
    self = [super init];
    if(self != nil) {
        self.firstName = [[[NSString alloc] initWithString:@"Lukasz"] autorelease];
        self.lastName = [[[NSString alloc] initWithString:@"Karluk"] autorelease];
    }
    return self;
}

- (void)dealloc {
    self.firstName = nil;
    self.lastName = nil;
    [super dealloc];
}

@end

在实现文件里我们要做的第一件事，是对头文件中声明的 @property 进行 @synthesize。@synthesize 告诉 Obj-C 编译器，为头文件里 @property 指令所定义的 getter 和 setter 方法生成实现。

现在我们可以通过 @property 指令创建的 getter 和 setter 方法访问 firstName 和 lastName 字符串对象了。这些方法是在内部生成的，我们实际上看不到它们，但每次写 self.firstName 或 self.lastName 时，我们就是在访问 getter 和 setter 方法。

在 init 方法里，有一处变化是：NSString 对象一创建就调用了 autorelease 方法。乍看之下这似乎不对，因为看起来我们创建了一个对象、retain 它、然后又 release 它，这会把引用计数降回零，意味着对象会被从内存中释放。但我们要意识到，我们用的是 @property 指令创建的 setter 方法，它会自动 retain 对象。这意味着最终的引用计数是 +1。

在 dealloc 方法里你会注意到，firstName 和 lastName 实际上并没有被 release，而是通过 @property 的 setter 设为 nil。在背后，当 setter 收到 nil 值时，它会先检查对象是否有效，如果有效就自动对对象调用 release，并通过把它设为 nil 来使对象失效。如果把这个逻辑写出来，就是下面这样，

if(firstName != nil) {
    [firstName release];
    firstName = nil;
}

属性确实需要一点时间才能习惯，但掌握之后，它是让编码更快、更灵活的强大工具。

委托

自动引用计数（ARC）

前面这些关于内存管理的内容可能挺沉重，所以你会高兴地知道，Obj-C 用自动引用计数（Automatic Reference Counting，ARC）让编程变简单了。ARC 替你完成所有内存管理工作，你不必再操心 retain 和 release 对象，一切都由编译器完成。ARC 的工作原理是在编译期检查你的代码，确保每个对象在被需要的时间里一直被 retain，同时也确保它在不再被使用后立刻被释放。

默认情况下，ofxiOS 的 XCode 项目里 ARC 是关闭的，但可以在项目的 Build Settings 里轻松打开。值得一提的是，即使可以打开 ARC，ofxiOS 的源文件仍然以非 ARC 方式编译。ARC 只应用于主 XCode 项目里的 Obj-C 文件。

打开 ARC 后，你可以指定哪些 Obj-C 类使用 ARC、哪些使用常规内存管理。你可以对该类使用 -fno-objc-arc 编译器标志来为某个特定的类关闭 ARC。

混用 Obj-C 与 C++（Objective-C++）

由于 Obj-C 和 C++ 都是 C 语言的子集，把两者混在一起是可行的。首先，在开始往 Obj-C 类里写 C++ 代码（或反过来）之前，你需要把实现文件的扩展名从 (*.m) 改成 (*.mm)。这让 XCode 编译器知道该文件是 Obj-C 和 C++ 的组合。

ofApp.mm 默认就已经这样设置好了，所以你可以在应用里开始使用 Obj-C 代码。一个例子是，你可能想用 UIKit 在 ofApp 之上添加某种用户界面。混用 Obj-C 和 C++ 有很多非常有用的可能性，本章后面会更详细地讲。

底层原理

UIKit 是所有 iOS 应用的中枢。它是一组类或一个框架，为创建和运行应用提供了标准化的结构。UIKit 提供了骨架结构，你可以把自己的应用代码插进去，它还让你能轻松接收系统事件，比如设备方向变化或内存警告——这只是众多例子中的两个。

UIKit 用 MVC（model-view-controller）设计模式来组织它的类。进入 iOS 编程后，你会发现 MVC 模式无处不在，尤其是在使用 UIViewController 时。MVC 把代码归入三类中的一类，让代码更易扩展、更易复用。

运行 iOS 应用时，它总是从 UIApplication 类开始，这个类监听系统事件并把它们传给应用代码做进一步处理。你第一个可以在里面写自己代码的类是 Application Delegate。App Delegate 负责创建和管理 UIWindow 以及根 UIViewController，这是 iOS 应用结构中两个非常重要的对象。UIWindow 的职责是协调并在屏幕上显示内容。至于 UIViewController，你可以把它看作一个单独的应用屏幕，按这个类比，根 UIViewController 可以看作应用的主屏幕。根 UIViewController 是最底层的视图控制器，你可以在它上面堆叠其他视图控制器，这就叫视图控制器栈。把一个 UIViewController 对象堆在另一个上面，一个应用就有了雏形。你现在有了几个带有不同 UIView 对象的屏幕，可以在它们之间导航。

（解释 UIView）

以上就是极度压缩的概述，只是触及 iOS 开发的表面。它的学习曲线可能非常陡峭，ofxiOS 正是来救场的：它像一部电梯，直接把你送到曲线顶端。ofxiOS 让你用 OpenFrameworks 开发原生 iOS 应用，而对 UIKit 或 Obj-C 一无所知也没关系。

ofxiOS 内部是一些扩展 UIKit 的类，它们负责创建 iOS 应用结构。三个核心类是：ofxiOSAppDelegate，扩展 application delegate；ofxiOSViewController，扩展 UIViewController，是 OF 应用的根视图控制器；以及 ofxiOSEAGLView，扩展 UIView，是 OpenGL 内容绘制到的视图。

ofxiOSAppDelegate 主要负责监听和处理全局事件，比如方向变化、内存警告，以及应用退出或进入后台状态的事件。ofxiOSAppDelegate 通知 ofApp 这些事件发生了，然后由程序员在 ofApp 里按自己的意愿处理。

ofxiOSViewController 就是 OF 的 UIViewController，顾名思义，它的主要职责是创建并控制 OF 的 UIView。它还负责处理方向变化，可以旋转 OF 应用以匹配设备上的方向变化。

ofxiOSEAGLView 就是 OF 的 UIView，显示所有 OF 渲染的内容。ofxiOSEAGLView 负责创建一个 ESRenderer，后者封装了底层 OpenGL 设置，使 OpenGL 图形可以渲染进 UIView。ofxiOSEAGLView 还监听触摸事件，把它们传给 ofApp 由程序员处理。

ofxiOSApp

打开一个空的 ofxiOS 项目时，你会立刻注意到 ofApp 头文件里有些不同。你会看到 ofApp 继承的是 ofxiOSApp，而不是运行桌面应用时见到的 ofBaseApp。这是因为 iOS 应用和桌面应用略有差别：桌面应用接收鼠标和键盘事件，而 iOS 应用接收触摸事件，还有方向事件和内存警告。为了处理这些新事件，必须在 ofxiOSApp 里定义新的方法，由 ofApp 继承。

void touchDown(ofTouchEventArgs & touch);
void touchMoved(ofTouchEventArgs & touch);
void touchUp(ofTouchEventArgs & touch);
void touchDoubleTap(ofTouchEventArgs & touch);
void touchCancelled(ofTouchEventArgs & touch);

触摸事件通过这些方法传给 ofApp。每个方法接收一个 ofTouchEventArgs 对象，里面包含触摸事件的所有信息，比如触摸 ID 以及触摸点在屏幕上的 x、y 坐标。

void lostFocus();
void gotFocus();

当应用从活跃状态变为非活跃状态（或反过来）时，焦点事件会传给 ofApp。gotFocus() 方法告诉 ofApp 应用已经变为活跃，这发生在应用首次启动时。lostFocus() 方法告诉 ofApp 应用已变为非活跃，这发生在电话或短信打断应用，或者用户退出应用时。

void gotMemoryWarning();

每个 iOS 应用运行时被分配到的内存是有限的。当应用超出分配的量，操作系统就会通过内存警告通知应用。内存警告通过 gotMemoryWarning() 方法传给 ofApp，此时应用需要释放一些内存，否则操作系统可能终止该应用。

void deviceOrientationChanged(int newOrientation);

每当设备方向改变，iOS 就会派发方向事件。方向事件通过 deviceOrientationChanged() 方法传给 ofApp。之后由用户自行决定如何处理这些方向变化。examples/ios/ 文件夹里的 iosOrientationExample 演示了方向事件可以怎么用。

媒体播放与采集

ofxiOS 支持中很大一块是媒体播放与采集。ofxiOS 对视频播放、声音播放、摄像头采集和声音输入都有良好支持。让这些功能得以实现的 Obj-C 代码都被封装和抽象了，普通 OF 用户可以在所有受支持的平台上以同样的方式继续使用 OF 的 API。

举例来说，假设你有一个非常简单的 ofApp 要播放视频。为此你会用 ofVideoPlayer 类，创建该类的一个对象实例，调用 loadMovie() 方法加载视频文件，然后调用 play() 方法开始播放。要在桌面 OF 应用或 iOS OF 应用上做到这一点，代码完全一样。因为我们用的是 ofVideoPlayer API，它在所有受支持的 OF 平台上都是通用的。不过这里要知道的是，尽管代码在不同平台上的工作方式相同，在 OSX 和 iOS（举例）上播放视频所用的实际代码是非常不同的。

ofxiOSVideoPlayer

ofxiOSVideoPlayer 是 ofxiOS 内部用于视频播放的视频播放器类。当你在 iOS 的 OF 项目里使用 ofVideoPlayer 时，实际用的就是 ofxiOSVideoPlayer。OF 会根据你使用的平台自动选择正确的视频播放器类。

演示 iOS 上视频播放器用法的 iOS 示例可以在 examples/ios/moviePlayerExample 文件夹里找到

查看 ofApp 头文件时你会注意到，我们用的是 ofxiOSVideoPlayer 类，而不是通用的 ofVideoPlayer 类。两者都能用，但用 ofxiOSVideoPlayer 大概更好。原因是 ofxiOSVideoPlayer 有一些 iOS 特有的额外方法，你可能想用也可能不想用，但有这个选项总是好的。

我们来过一遍一些基本功能。

加载和播放视频与使用 ofVideoPlayer 完全一样。

void ofApp::setup() {
	video.loadMovie("hands.m4v");
	video.play();
}

每一帧我们都需要更新视频播放器。

void ofApp::update(){
    video.update();
}

要把视频画到屏幕上，我们需要先取得视频纹理的引用，再对纹理对象调用 draw。

void ofApp::draw(){
    video.getTexture()->draw(0, 0);
}

现在说说那些 iOS 特有的额外方法。

如果你在 ofxiOSVideoPlayer 里翻一翻，会看到一个叫 getAVFoundationVideoPlayer() 的方法，它负责返回底层 AVFoundationVideoPlayer 的引用。AVFoundationVideoPlayer 是 iOS 视频播放器的 Obj-C 实现，位于 ofxiOSVideoPlayer 之下，几乎所有实际工作都由它完成。你可能想要访问 AVFoundationVideoPlayer 的原因有几种：你想直接和 Obj-C 代码打交道，以充分利用 iOS 视频播放器的特性；或者你想把视频显示在 UIView 里，而不是渲染到 OpenGL。

这里我们取得一个指向 AVFoundationVideoPlayer 的指针引用，而它恰好也继承自 UIView。这意味着我们可以把视频播放器加进 UIView 层级里，以原生方式显示视频。

AVFoundationVideoPlayer * avVideoPlayer;
avVideoPlayer = (AVFoundationVideoPlayer *)video.getAVFoundationVideoPlayer();
[avVideoPlayer setVideoPosition:CGPointMake(0, 240)];
[ofxiOSGetGLParentView() insertSubview:avVideoPlayer.playerView belowSubview:controls.view];
