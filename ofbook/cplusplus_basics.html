迭代

我大部分的绘画和油画创作都在九十年代中期，那时我是高中 AP 艺术课的学生，留着扎成马尾、侧面剃出阶梯的长黑发，戴着圆框眼镜，身上没有一件衣服不带 Liquitex Basics 丙烯颜料的溅点、甩痕、斑点和污渍。经济学课上我无聊到极点，摆弄着我的 TI-82 图形计算器，结果发现了某种让我心中灯泡一亮的东西。和我从小到大在家里见过的那些小计算器不同，TI-82 配了一本厚厚的说明书。在这本手册关于三角函数和其他枯燥遥远科学的章节之间，有一样东西抓住了我求知若渴的年轻眼睛：一个性感的黑白金字塔，里面无限嵌套着倒立的小金字塔，如图 1 所示。

这个分形，也就是著名的 Sierpinski 三角形，伴随着大约二十五条计算机指令，构成了完整的 SIERPINS 程序。我凑近看那些代码，看到几个数值运算——都不算高深，大部分是指令性词汇，比如“做这个”，或者“如果怎样，就做另一件事”。我把书上的代码敲进图形计算器，运行了程序。起初，LCD 面板上一片空白。慢慢地，几个随机像素这里那里变成黑色，还看不出任何规律。又过了几秒，画面逐渐填满，我已经能看到三角形的模糊轮廓。过了很长一段时间，我的计算器终于和书上的图片对上了。我的脑子彻底被震住了。有些事情说不通。是什么样的自然奇迹，让如此复杂的形式从这么少的指令里产生？屏幕上有六千多个像素，为什么仅仅二十五条指令就足以创造出这件惊人的、像生物一样的作品？这是谁的作品？我可以从中衍生出新作品吗？我很少见到如此之少的投入带来如此神奇的回报。我找到了我的新基础。我觉得有必要理解这个程序，因为（我认定）它很重要。我回到代码里，改了几个数字，然后再次运行程序。屏幕先是一片空白，然后画出了另一幅图，只是这一次偏向了左边，掉出了视口。我感到更有勇气了，于是试着改动其中一条英文指令，机器报错，没能运行。

图 2 所示的循环是一个无限重复的循环，我很荣幸已经执行了二十年，而且我仍然热爱我所做的事。每一个新循环都总能给我惊喜，因为我在追寻创造程序意味着什么，以及创造软件艺术意味着什么。迭代地演化一串计算机指令的过程，总是既带来同样多的逻辑挑战，也带来同样多的艺术回报。这些挑战中很少有无法解决的，尤其是当有其他人可以协作帮忙，或者把谜题拆成更小的谜题时。如果你已经在 Processing、JavaScript，甚至 HTML 加 CSS 这样的其他环境里写过代码，那么这第一个重要教训可能显得太显而易见了。

对于刚刚开始了解编写小程序意味着什么的人，理解代码编写过程的迭代性质很重要。图 3 的轶事说明了这个过程不是什么样的。你很少会把某些代码只往编辑器里敲一次，然后指望按下编译就能看到最终结果。程序从很小开始、带着大量错误（bug）、朝着期望结果或行为的目标缓慢演化，这是自然的，也是普遍被接受的。事实上这太常见了，以至于做出前面那种假设本身就是程序员不该犯的错误。甚至在更早的年代，程序还是手写在纸上的时候，作者仍然需要反复用眼睛盯着代码，才能找出错误；因此这个过程是迭代的。在学习 C++ 语言时，我会提供一些很小的代码示例，由你在自己的机器上编译。不正常的部分在于：把书上的代码敲进编辑器，（前提是你的手指不打滑）程序就神奇地跑起来了。我是故意去掉了排错体验，以便把 C++ 语言本身的内容单独隔出来。后面我们会把 调试（修复错误）这个日常任务当作一个独立主题来讨论。

关于字体排印的插曲

网页上的大多数字体是比例宽度，意思是字母宽度各不相同；眼睛读起来更舒服。字体也可以是等宽的，意思是所有字母（连 W 和小写 i 也一样）宽度相同。虽然这看起来有点好笑、有点古旧，像打字机，但它有重要用途。等宽字体把一段文本变成一种棋盘，就像国际象棋的格子或坐标纸。计算机编程代码通常用等宽字体呈现，因为它是一种 ASCII 艺术。缩进、空白字符和重复的模式都值得保留，也便于用眼睛对比。我认识的每一位写代码的人——除了艺术家 Jeremy Rotsztain——都用某种等宽字体写代码。一些字体建议是 Courier、Andale Mono、Monaco、Profont、Monofur、Proggy、Droid Sans Mono、Deja Vu Sans Mono、Consolas 和 Inconsolata。从现在起，你会看到字体切换成 this inline style……

注释

现在请按代码编辑器左上角的 Edit（图 7）。

你会看到编辑配置略有不同，但同样的模板代码在顶部仍然可以编辑。现在我们来改代码。找到第 5 行，那里写着：

// 你的代码写在这里 .

以双斜杠开头的一行叫作注释。你可以在里面写任何需要的东西，用自己能理解的方式给代码做标注。有时候把两条斜杠放在代码前面“注释掉代码”很有用，因为这样会让那段 C++ 代码失效，但又不删除它。C++ 的注释也可以跨多行，或者像标签一样插进去。开始和结束注释模式的语法不一样。/* and the */ 之间的一切都会变成注释：

/* 
这是一条多行注释。
仍处于注释模式。
*/

请删掉第 5 行的代码，换成下面这条语句：

cout << "Hello World" << endl;

这一行代码让计算机把 “Hello World” 说进一个隐含的文本空间，叫作 标准输出（也就是 stdout）。写程序时，可以放心地假定 stdout 是存在的。程序可以往里面“打印”文本。另外一些时候，stdout 只是你的编程环境里用来排错的一个窗格。

那对引号之间几乎可以放任何东西。被引号括起来的这串东西叫作一段 字符串。更准确地说，它是一个 c-string 字面量。本章后面会讲更多关于字符串的内容。代码里 cout << 这一块的意思是“把下面的东西以格式化的方式送到 stdout”。最后一块 << endl 的意思是“在 hello world 消息末尾加一个回车（行尾）字符”。最后，在这行代码的最末尾，你看到一个分号（;）。

在 C++ 里，分号就像句子末尾的句号。每条语句后面都必须写分号，通常是在代码行的末尾。如果你忘了写这个分号，编译就会失败。分号很有用，因为它们让多条语句可以共用一行，或者让一条语句占据好几行，从而让程序员在空白排版上灵活表达。加上分号，你就确保了编译器不会犯迷糊：你帮了它一把，告诉它语句在哪里结束。刚开始学 C 或 C++ 时，忘写分号是极其常见的错误，但代码要编译又非它不可。请格外小心，确保你的代码语句以分号结尾。

打字的时候，你可能注意到文字自己变成了多种颜色。这个好用的特性叫作 语法着色（或称语法高亮），它能潜移默化地提升你阅读代码、排查畸形语法和搜索的能力。每个工具都有自己的语法着色系统，所以如果你想改颜色，请记住这跟文字处理软件不是一回事——文字处理软件里的着色是你自己往文档里加的。代码编辑器不会允许我把 “TRON.TTF” 字体配上发光的青绿色，只用在 endl（意思是行尾）上。相反，我可以为整类语法选择一种特殊样式，只要代码属于那一类，它的所有部分都会以那种样式显示。在这个例子里，cout 和 endl 都被视为关键字，所以工具把它们着成黑色。如果这些东西在别处显示成别的颜色，请相信那就是和之前一样的代码，因为不同的代码编辑器提供不同的语法着色。整段代码现在应该长这样：

#include <iostream>
using namespace std;

int main(){
	cout << "Hello World" << endl;
	return 0;
}

超越 Hello World

既然已经下水试过了，我们回去分析代码的其他部分。第一行是一条 include 语句：

#include <iostream>

和 Java、CSS 里的 import 类似，#include 相当于告诉编译器：从名为 iostream.h1 的文件里剪下一些有用的代码，粘贴到文件中这个位置，这样你的新代码就可以依赖它的代码。在这个例子里，iostream.h 提供了 cout 和 endl 作为我可以在代码里使用的工具，只要写它们的名字就行。在 C++ 中，以 .h 结尾的文件名叫作头文件，里面装的代码会被包含进实际的 C++ 实现文件，而实现文件的文件名以 .cpp 结尾。C++ 内置了很多标准头文件，提供各种基础服务——事实上多到没法在这里一一列举。如果这还不够，给项目添加外部库并包含它的头文件也是很常见的做法。你也可以把自己写的头文件定义成代码的一部分，只是语法略有不同：

#include "MyCustomInclude.h"

在 openFrameworks 中，双引号用于包含不属于系统安装部分的头文件。

# 是怎么回事？

这说来话长，但值得从概念上理解。include 语句其实不是真正的 C++ 代码（注意它没有分号）。它属于一个完全独立的编译阶段，叫作 预处理器。它发生在你真正的程序指令被处理之前。它们是给代码编译器看的指令，而不是给编译后的计算机执行的指令。在这些 预处理器指令 前面用一个井号（pound/hash）符号，就能在文件里一眼认出它们，这样做也很有道理。应该把它们看成混在真正 C++ 代码里的另一种语言。C++ 的预处理器指令并不多——它们大多跟归拢其他代码有关。下面是一些你可能会见到的。

#define #elif #else #endif #error #if #ifdef #include #line #pragma #undef

我们来做个实验。在代码编辑器里，请把第 1 行的 include 指令注释掉，然后运行代码。要注释掉这一行代码，就在行首插入两条相邻的斜杠。

//#include <iostream>

语法着色会变成全绿，说明它现在只是一条注释。按右下角的大绿按钮运行代码，你会在输出面板里看到新东西。

prog.cpp: In function 'int main()':
prog.cpp:5:2: error: 'cout' was not declared in this scope
  cout << "Hello World" << endl;
  ^
prog.cpp:5:27: error: 'endl' was not declared in this scope
  cout << "Hello World" << endl;
                           ^

编译器发现了错误，没有运行程序。它转而试图帮你修好，向你显示它在哪儿卡住了。最前面的 prog.cpp：告诉你包含错误的文件。这里 ideone.com 把你的代码存成了那个默认文件名。接着是 In function 'int main()'：向你显示代码中包含错误的具体区段，这里是某个叫 main 的函数的花括号 { } 之间。（函数和花括号后面再说）。下一行我们看到 prog.cpp:5:2:。5 表示从文件顶部数第几行，2 表示从行首往右数第几个字符。再往下是 error: 'cout' was not declared in this scope。这是一条说明它认为代码哪里错了的消息。在这个例子里，它说得挺对。iostream.h 没了，因此没有 cout 提供给我们，所以当我们试图送出 “Hello World” 时，编译失败。接下来的两三行，你会看到包含错误 cout 的那行代码，下面还多了一个小小的向上的脱字符，它应该是一支指向代码中某个字符的箭头。在这个例子里，箭头应该落在 cout 里的 ‘c’ 下面。系统在用视觉方式告诉你哪个词元出了问题。接着又报了一个错误，这一次编译器抱怨没有 endl。当然，我们知道要修好这个错误，需要包含 <iostream>，那我们现在就来做。请取消第 1 行的注释，重新运行代码。

#include <iostream>

使用 openFrameworks 时，你可以选择不同的工具和平台。每一种展示错误的方式都不同。有时编辑器会弹出来，为你高亮代码，放一个错误气泡显示更多信息。另一些时候，编辑器什么也不显示，但编译输出会给出格式与上面类似的原始错误。虽然一次编译收到好几个错误有时也有用，但如果你集中精力理解和修复最先报告的那个错误，可以省下很多痛苦。修好最上面的错误之后，后面那些错误很可能就优雅地消失了，因为它们其实都被你的第一处修复覆盖了。把顶部那一行代码注释掉，我们造成了两个错误。

初识命名空间

继续看第 2 行，我们看到：

using namespace std;

假设你注册了一个社交网站，它让你挑一个用户名。我叫 Mx. Jetty Nimoy——用户名可能是 JNIMOY。我提交页面，它返回一个错误，说这个用户名已经被占了，我得换一个，因为我那位前任父亲 Joseph Nimoy 比我先注册，他占了 JNIMOY。所以我必须用中间名首字母 T，造一个唯一的用户名 JTNIMOY。我刚刚制造并解决了一次 命名空间冲突。命名空间是一组唯一的名字——其中没有重复。只要名字分属两个不同的命名空间，就允许出现相同的名字。命名空间帮程序员避免互相踩脚，防止彼此覆盖符号或霸占好名字。命名空间还提供了一套整洁的组织体系，帮我们找到想找的东西。在 openFrameworks 里，一切都以 of 开头……比如 ofSetBackground 和 ofGraphics。这是一种做命名空间隔离的技巧，因为其他程序员创建的名字不太可能以 of 开头。OpenGL 用的是同样的技巧。OpenGL API（应用程序编程接口）里的每个名字都以 gl 开头，比如 glBlendFunc 和 glPopMatrix。不过在 C++ 里，你不必给名字加严格的字符前缀，因为这门语言自带命名空间语法。第 2 行里，using namespace std; 是在告诉编译器：这个 .cpp 文件要使用 std 命名空间里的所有名字。剧透一下！那两个名字就是 cout 和 endl。现在我们来做个实验，把第 2 行注释掉，然后运行代码。你觉得编译器会返回什么样的错误？

/* using namespace std; */

错误和之前非常相似，都是找不到 cout 或 endl，但这一次消息列表里加上了建议的替代写法。

prog.cpp:5:2: note: suggested alternative:
In file included from prog.cpp:1:0:
/usr/include/c++/4.8/iostream:61:18: note:   'std::cout'
   extern ostream cout;  /// Linked to standard output
                  ^

编译器说：“嘿，我找过 cout 了，确实在文件包含的某个命名空间里找到了它。就是它，std::cout”，在这个例子里编译器是对的。它希望我们更明确地写出命名空间：cout 属于 std（standard），把它写在左边，用双冒号（::）连接。这有点像管我自己叫 Nimoy::Jetty。继续实验，把第 5 行改成给 cout 和 endl 加上显式命名空间。

std::cout << "Hello World" << std::endl;

运行代码，你会看到它编译得好好的，还成功打印出了 “Hello World”，尽管写着 using namespace std; 的那一行仍然被注释着。现在想象你在写一个程序，随机生成一首歌的歌词。显然你会大量使用 cout。要是每个 cout 前面都得敲一遍 std::，那就太烦了，而编程语言加入这类特性，原因之一就是为了减少打字。所以第 2 行 using namespace std; 虽然并非必需，但把它放在那里（连同其他 using namespace 语句）可以通过隐含上下文，让 C++ 代码既好写又好读。

假设我在曼哈顿参加一个拼字游戏派对，而我是唯一的 JT。轮到我玩的时候，大家直接叫我 JT 就行。但要是晚饭后 James Taylor（也叫 JT）加入进来，就有点混乱了，我们开始用名加姓来称呼这两位 Jetty 以示区分。在 C++ 里也一样。我是 Nimoy::JT，他是 Taylor::JT。有两个不同的 cout 名字没什么问题，一个来自 std 命名空间，另一个来自 improved 命名空间，只要两者都写明命名空间就行：std::cout 和 improved::cout。事实上，如果你不写，编译器就会抱怨。

等我介绍类的时候，你会看到更多双冒号语法（::）。

函数

继续，我们来看看第 4 行：

int main() {

这是第一段有开头也有结尾的代码，它把另一段代码“包”了起来。但更重要的是，一个函数代表了它内部包住的那些语句。这个 函数 的结尾就是第 7 行的右花括号：

}

在 C++ 里，我们把一组代码语句包在函数里，每个函数都可以看作更大程序里的一个小程序，就像图 9 的简化示意图那样。

这些函数每个都有名字，我们可以通过名字调用它。调用一个函数，就是执行该函数内部包含的那些代码语句。这样做最直接的好处是少打字，其他好处我们后面再谈。就像棋盘游戏，程序有一个起始位置。更准确地说，程序有一个编译器期待存在的入口点。那个入口点就是一个叫 main 的函数。你在 main 函数里写的代码是程序中最先执行的代码，因此它负责调用程序里的其他函数。那谁调用你的 main 函数呢？操作系统！我们来拆解这个示例里 main 函数的语法。再说一次，对你们这些 Processing 程序员来说，这都是老消息了。

定义函数时，第一个词元是声明的返回类型。函数可以选择返回一个值，就像问题的答案、难题的解、任务的结果，或某个过程的产物。在这个例子里，main 承诺返回一个 int，也就是 integer 类型，是一个没有小数部分的整数。下一个词元是我们函数的名字。系统期待 “main” 这个词全小写，但后面你会定义自己的函数，那时我们再讨论命名。接下来是一对圆括号。是的，里面什么都没有却要摆一对括号，看起来有点怪。后面我们会看到里面放什么——但函数的那对圆括号永远不能省，因为在某种意义上，它是提示人类“这是个函数”的主要线索。事实上，从现在起，当我用名字提到一个函数时，如果它不需要参数，我会在后面加上 ( )，例如 main()；如果它需要一个或多个参数，我会加上 (...)，例如 main(...)。

接着，我们看到一个左花括号。有时这个左花括号和前一个右括号在同一行，有时你会看到它单独占新的一行。这取决于写代码的人、项目或团队的个人风格——两种都可以。关于不同缩进风格的完整参考，见维基百科上关于缩进风格（Indent Style）的条目（http://en.wikipedia.org/wiki/Indent_style）。

在这个左花括号和右花括号之间，我们放入真正告诉计算机去做事情的代码语句。在这个例子里，我只有一条语句，就是必需的 return。如果一个函数的返回类型是 int，而你漏掉了它，编译器就会抱怨你违背了返回 int 的承诺。在这个例子里，操作系统把 0 解释为“没出问题”。就为了好玩，试试把 0 改成 1，然后运行代码，看看会怎样。

自定义函数

现在我们来定义自己的函数，并把它当作一个词语模板来用。把示例代码敲进编辑器并运行。

#include <iostream>
using namespace std;

void greet(string person){
	cout << "Hi there " << person << "." << endl;
}

int main() {
	greet("moon");
	greet("red balloon");
	greet("comb");
	greet("brush");
	greet("bowl full of mush");
	return 0;
}

输出显示的是一首熟悉的睡前故事。

Hi there moon.
Hi there red balloon.
Hi there comb.
Hi there brush.
Hi there bowl full of mush.

在这段新代码里，注意第二个函数 greet(...)，它看起来和 main() 一样，但又有所不同。它有同样的花括号来装代码块，但返回类型不同。它有同样的一对圆括号，但这次里面装了东西。那必需的 return 语句呢？当一个函数不返回任何东西时，用 void 关键字代替返回类型。所以既然 greet(...) 的返回类型是 void，你漏掉 return 编译器也不会抱怨。在圆括号里，你看到 string person。这是一个参数，是供函数使用的输入值。在这个例子里，它有点像查找替换。往下看 main()，我调用了 greet(...) 五次，每次都把不同的字符串放在引号里、放进圆括号之间。那些是实参。

顺便说一句，为了帮你从技术上分辨什么时候该叫它们实参（arguments）、什么时候该叫形参（parameters），看这个代码示例：


void myFunction(int parameter1, int parameter2){
	//todo: 代码
}

int main(){
	int argument1 = 4;
	int argument2 = 5;
	myFunction(argument1,argument2);
	return 0;
}

回到前面的例子，那五行代码都是函数调用。它们在告诉 greet(...) 去执行，并把那一个字符串实参传给它，好让它完成工作。那一个字符串实参通过名为 person 的形参，变成 greet(...) 内部代码可用的东西。要看事情发生的顺序，请看图 11。

图 11 里那条彩色的线，是一个想象中的播放头在执行时走过代码所画出的路径。我们从蓝色部分出发，穿过 main 入口点，然后遇到 greet(...)，跳转就发生在这里。当线变成绿色，它暂时逃出了 main()，以便跟着 greet(...) 走一会儿。大约在线变成黄色的地方，你会看到它执行完了 greet(...) 里包含的代码，做了第二次跳转（也就是返回），这次回到之前保存的位置，从那里继续执行下一条语句。这个例子里最明显的优势，就是把那条冗长的 cout 语句带来的复杂度，缩减成一次简单的 greet(...) 调用。如果我们必须调用 greet(...) 五次，把这段例行程序封装进一个函数就给了它便利的力量。假设你想把问候语从 “Good night” 改成 “Show's over ”。与其更新所有你复制粘贴过的代码行，你只需改那一个函数，函数的所有使用处就会随之同步改变行为。此外，代码会变得相当复杂。把它拆成小的例行程序，并在思考如何搭建更大的软件时把这些例行程序当作自己的定制积木，会有帮助。通过使用函数，你从必须事无巨细地表达系统每个细节中解放出来；因此函数是一种抽象，就像艺术中的抽象一样。这种抽象叫作复杂度的封装，因为它就像把那个又大又复杂的东西装进一个漂亮的小胶囊里，让那个又大又复杂的东西显得更小、更简单。这是个非常强大的想法——不只是在代码里。

变量（第一部分）

一个“东西”是一个“思”，是思想的一个单位

-- Alan Watts

请把下面这个程序输进 ideone 并运行。

#include <iostream>
using namespace std;

int main(){
	cout << "My friend is " << 42 << " years old." << endl;
	cout << "The answer to the life the universe and everything is " << 42 << "." << endl;
	cout << "That number plus 1 is " << (42+1) << "." << endl;
	return 0;
}

输出是这样的：

My friend is 42 years old.
The answer to the life the universe and everything is 42.
That number plus 1 is 43.

从前面一课我们知道，放进 << 运算符之间的东西会被格式化进 cout 对象，然后神奇地出现在输出控制台里。注意最后一行，我在圆括号之间放了一点简单的算术（42+1），它求值为 43。这在数学意义上叫作一个表达式。这三行代码都在讲数字 42 的某些事，所以它们都包含一个字面量整数。字面量值就是直接敲进代码里的内容；有人会说它是“硬接的”，因为这个值一旦和其他东西一起编译进去就固定了。

如果我想改那个数字，可以照我从文字处理软件里学到的做法，把 42 “查找替换”成新的值。那如果我在一个 3D 世界里有 100,000 个粒子呢？其中有些 42 需要改，但另一些 42 不该改。写代码时，事情会变得既沉重又复杂。变量最明显的用途是它是一种非常强大的查找替换机制，但你会看到变量的用处不止于此。那我们就在代码顶部声明一个整数，并用它代替那些字面量 42。

#include <iostream>
using namespace std;

int main(){
	
	int answer = 42;
	
	cout << "My friend is " << answer << " years old." << endl;
	cout << "The answer to the life the universe and everything is " << answer << "." << endl;
	cout << "That number plus 1 is " << (answer+1) << "." << endl;
	return 0;
}

现在我用上了变量 answer，只需要改代码里的那一个数字，它就会以 42 的形式出现在三个句子里。这比查找替换更优雅。图 18 展示了在同一行声明并初始化一个变量的语法解释。

也可以分两行来声明并初始化一个变量。那看起来像这样：

int answer;
answer = 42;

在这种情况下，你声明变量之后会有一小段时间，它的 answer 可能不可预测、有毛刺，因为在 C 里（不像 Java），新变量不会免费被设成零——这得你自己做。如果不做，变量就可能冒出不可预测的值——来自过去的计算机内存垃圾。所以，除非你打算做故障艺术（glitch art），请务必在声明变量时把它初始化为某个数字，哪怕那个数字是零。

给你的变量命名

注意下面那个箭头写着 “must be a valid name”。我们会发明新的名字，用来给命名空间、函数、变量，以及我们在代码里定义的其他构造（类、struct、enum，还有我还没教你的其他东西）命名。在代码里定义新标识符的规则很严格，有点像你在网站上选密码。

  • 你的标识符只能包含字母、数字和下划线。
  • 它不能以数字开头，但完全可以以下划线开头。
  • 名字不能和任何语言关键字相同（例如 void 这个词）

下面这些标识符是可以的。

a
A

_x_axis
perlin_noise_frequency
_         // a single underscore is fine
___       // several underscores are fine

命名约定

习惯与语言的差异，若目标相同、心怀坦荡，便算不得什么。

--Albus Dumbledore

标识符（包括变量）会用不同风格书写，以表明它们的各种属性，比如构造类型（变量、函数还是类？）、数据类型（整数还是字符串？）、作用域（全局还是局部？）、私有级别等等。你可能会看到一些标识符首字母大写并使用 CamelCase，另一些则保持全部 lower_case_using_underscores_to_separate_the_words。全局常量通常写成 ALL_CAPS_AND_UNDERSCORES 这样。另一种小写命名方式是从一个小写字母开始，然后 letterThenCamelCaseFromThere。你也可能见到混合体，比如 ClassName__functionName__variable_name。这些不同风格可以表示不同类别的标识符。

更执着的程序员有时会用那种被亲昵地叫作匈牙利命名法的做法，给标识符加上字符徽章来说明它的属性，但同时也降低了可读性，例如 dwLightYears 和 szLastName。命名约定并非一成不变，当然也不是编译器强制的。协作者通常需要就这些微妙的命名约定达成一致，以免互相搞混，而要与任何已定的约定保持一致，需要每个人的自律。代码里的命名约定这个话题，至今仍是开发者之间一场滑稽而激烈的争论，就像决定花括号放在哪一行、缩进用不用 tab 一样。跟编程中的许多事情一样，总有人会告诉你你做错了。那并不一定意味着你错了。

变量会变

我们管它们叫变量（variable），因为它们的值在运行时变化（vary）。它们最有用的形态就像一只桶，我们把东西（比如水）放进去好好保管。按通常的剧情发展，我们最后会回到桶边用掉一些水，或者往水里掺点化学品，或者再往桶里续些水，等等。变量就像一只空桶，你可以把东西放进去。图 19 展示了游戏 Minecraft 里的一只桶。

如果计算机程序像一个小小的大脑，那么变量就像一个基本的记忆单元。在我的速写本上记一条小笔记，就像把一个值存进变量以备后用。我们来看一个变量改变自身值的例子。

#include <iostream>
using namespace std;

int main(){
	int counter = 0;
	cout << counter;
	counter = 1;
	cout << counter;
	counter = 2;
	cout << counter;
	counter = 3;
	cout << counter;
	counter = 4;
	cout << counter;
	counter = 5;
	cout << counter;
	return 0;
}

输出应该是 012345。注意等号的用法。它和我们从算术里习惯的不一样。在传统语境里，单个等号意味着两边的表达式求值结果相同。在 C 里，那其实是双等号（==），我们后面会讲。单个等号的意思是“把右边的表达式解出来，把答案存进左边那个变量”。如果你以前没编过程，这需要一点时间适应。如果我是一个初学者（我内心的孩子永远都是），我大概会喜欢某种另类的语法来命令计算机把值存进变量。类似 3 => counter 那样的写法，见于 Princeton sound lab 的 ChucK 语言，或者更视觉化一点，就像我在图 20 里对 Minecraft 工作台的改造。

把变量名放在左边而不是右边，其实用起来好处很明显，因为表达式可以变得相当长！以 varname = 开头的一行，眼睛扫起来更容易，因为在你开始在等号后面敲出什么疯话之前，开头这两个符号的长度是固定的。

分析前面的代码示例，我们看到这个数字每次输出前都加了 1。我在反复地把字面量整数存进变量。既然编程语言懂基础算术，那我们试试下面这个改动：

#include <iostream>
using namespace std;

int main(){
	int counter = 0;
	cout << counter;
	counter = counter + 1;
	cout << counter;
	counter = counter + 1;
	cout << counter;
	counter = counter + 1;
	cout << counter;
	counter = counter + 1;
	cout << counter;
	counter = counter + 1;
	cout << counter;
	return 0;
}

输出应该仍然是 012345。通过写 counter = counter + 1，我把 counter 递增了 1。更具体地说，我在右边那个“加法”表达式里用了 counter，而它的结果（片刻之后）被存回 counter。这看起来有点好笑，因为它在两个不同时刻谈论 counter。这让我想起电影系列 Back to the Future，Marty McFly 在其中遇到了过去和未来的自己。见图 21。

天哪，这能把人看晕！但做过几次之后，你会发现它并不比你在那儿看到的复杂多少。这是科幻的一种高度实用的用法，而你大概并不是想挑战时空结构（除非你是 Kyle McDonald，或者是个 Haskell 程序员）。这里的要点是修改计算机内存里的内容，所以我们有了一条指令之前的 counter，就像我们去给桶里加水时，桶里可能已经有水了一样。图 22 展示了 bucket = bucket + water。

把变量加一，或者给变量加上某个值，在所有编程中其实都太常见了，以至于还有专门的语法糖。语法糖是为方便而加到编程语言里的冗余语法。它有助于减少打字，能提升理解度或表达力，而且（像糖一样）让程序员更开心。下面这些语句都是给 counter 加 1。

counter = counter + 1; // 原始写法
counter += 1;          // "给自身加上"，好处是少打字。
counter++;             // "给自身加 1"，好处是不用敲那个 1。
++counter;             // 与上面相同，但有个细微差别。

我们在程序里测试一下。

#include <iostream>
using namespace std;

int main(){
	int counter = 0;
	cout << counter;
	counter++;
	cout << counter;
	counter++;
	cout << counter;
	counter++;
	cout << counter;
	counter++;
	cout << counter;
	counter++;
	cout << counter;
	return 0;
}

是的，少打了很多字，而且还有很多办法写得更简洁。这里是一种。

#include <iostream>
using namespace std;

int main(){
	int counter = 0;
	cout << counter++;
	cout << counter++;
	cout << counter++;
	cout << counter++;
	cout << counter++;
	cout << counter++;
	return 0;
}

答案仍然是 012345。后缀自增运算符即使在变量置身表达式内部时，也会递增这个变量。现在我们试试前缀版本。

#include <iostream>
using namespace std;

int main(){
	int counter = 0;
	cout << ++counter;
	cout << ++counter;
	cout << ++counter;
	cout << ++counter;
	cout << ++counter;
	cout << ++counter;
	return 0;
}

如果你得到答案 123456，这没错！前缀自增运算符与它的后缀姊妹的差别正在于此。当 counter 初始化为 0 时，++counter 求值为 1，而 counter++ 仍然求值为 0（但会留下一个已递增的 counter 供后续使用）。下面例子的输出是 1112。

#include <iostream>
using namespace std;

int main(){
	int counter = 0;
	cout << ++counter; // 1：求值前自增
	cout << counter;   // 1：没有改变。
	cout << counter++; // 1：求值后自增
	cout << counter;   // 2：改变的证据。
	return 0;
}

为了算术上的完整性，我应该提一下还存在做减法的自减运算符（counter--）。另外，你可能已经猜到了，既然能写 counter + 1，C 编译器也能认出其他经典算术，比如 counter - 3（减法）、counter * 2（星号是乘法）、counter / 2（除法），以及用圆括号改写运算顺序，比如 (counter + 1) / 2 的求值结果和 counter + 1 / 2 不同。在变量前加负号也会正确取负，就好像它是从零里减出来的一样。C 在这套基础数学运算符之外还扩展了布尔逻辑和位操作；我会在变量第二部分介绍它们。

关于变量还有几样要点要学，但我们要拿目前学到的东西，以好玩的名义跑起来。同时，为你走到这里再鼓一次掌！你知道了变量是什么，也知道了如何对它们做基础算术。你还知道了 ++ 运算符放在变量名前面和后面时分别做什么。

C++ 语言之所以得名，是因为它是 C 语言加一。

结语

恭喜你读完了这篇 C++ 入门的最初几页。有了这些基础概念，你应该能够自己探索很远的路，但我得承认，这还不足以让你理解 ofBook 其余部分的代码示例。由于纸张资源有限，你在这里看到的是一个“预告”章节，真正的 C++ 语言入门必然要长得多。那一版章节变得太大了，如今已自成一部书——在网上可以读到未删节版，将来也可能作为 ofBook 的配套书出版。向非程序员教授 C++ 语言确实是个庞大的题目，没法有效地压缩到 35 页，更别说它后来长成的 100 多页了。如果你真心想深入 openFrameworks，我强烈建议你先停下来读完这一章的未删节版，再继续看 ofBook，这样你才能看懂自己在读什么。你可以在这里找到那些材料。

附言

在这里结束本章，绝不是想把 C++ 中重要的东西和不重要的东西分开。我们只是纸用完了。考虑到这篇 C++ 入门余下部分有多重要，并根据 ofZach 的教学经验，下面是你在未删节版里还能找到的一些内容：

  • 变量存在的时间长短不同——有些存在很久，有些只是你程序生命周期里的一小瞬。这个关于作用域的主题，在本书未删节版的 变量（第二部分） 一章里有讲。

  • 变量有数据类型。比如一个装数字，另一个装一些文本。更多内容在 基本类型 一章。

  • 需要重申的是，和 Processing 不同，变量不一定以零值开始。你必须用想要的值去初始化它们，否则你无法知道那里等着你的是什么。关于这个现象的更多讨论，你会在数组的入门部分找到。
