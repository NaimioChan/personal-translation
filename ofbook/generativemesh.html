基础：使用 ofMesh

网格是顶点的集合——也就是三维空间中的点——这些顶点可以用不同方式连接起来。由连接这些顶点形成的形状称为图元。图元是我们能组合成网格的最小构件。我们可以创建几种不同的图元：

  • 你可以选择不连接任何顶点，只把点作为图元来绘制。
  • 你可以选择把顶点两两连接，把线作为图元来绘制。
  • 你可以连接三个或四个（或更多）顶点，把三角形或四边形（或多边形）作为图元来绘制。

为了更具体一点，看看下面的网格。顶点是橙色的点。这些顶点按三点一组连接起来形成三角形图元，然后被涂成灰色。想深入了解的话，可以看 OpenGL 章节。

我们将专注于用点和线作为图元。先在屏幕上画点东西。创建网格时，你应该：

  1. 定义一个 ofMesh 变量。就叫它 mesh。
  2. 用 mesh.setMode(...) 指定网格用什么图元模式（点、线等）来连接顶点。我们将用点作为图元，所以应该使用 OF_PRIMITIVE_POINTS 模式。
  3. 用 mesh.addVertex(...) 添加一些顶点。顶点是一个 ofVec3f，如果你之前没用过这个类，可以看看文档页面上的示例。
  4. 用 mesh.draw() 绘制你的网格。

那就上代码吧！

在你的头文件（.h，例如 ofApp.h）中添加一个 mesh 变量：

class ofApp : public ofBaseApp{

    public:
        ofMesh mesh;
    // ……
    // 保留这里已有的其余代码。

把源文件（.cpp）里的 setup() 和 draw() 函数改成这样：

void ofApp::setup() {
    mesh.setMode(OF_PRIMITIVE_POINTS);

    ofVec3f top(100.0, 50.0, 0.0);
    ofVec3f left(50.0, 150.0, 0.0);
    ofVec3f right(150.0, 150.0, 0.0);

    mesh.addVertex(top);
    mesh.addVertex(left);
    mesh.addVertex(right);
}
void ofApp::draw() {
    ofBackground(0);
    mesh.draw();
}

白色太无聊？那你可以修改 setup 加点颜色：

void ofApp::setup() {
    mesh.setMode(OF_PRIMITIVE_POINTS);
    mesh.enableColors();

    ofVec3f top(100.0, 50.0, 0.0);
    ofVec3f left(50.0, 150.0, 0.0);
    ofVec3f right(150.0, 150.0, 0.0);

    mesh.addVertex(top);
    mesh.addColor(ofFloatColor(1.0, 0.0, 0.0)); // 红色

    mesh.addVertex(left);
    mesh.addColor(ofFloatColor(0.0, 1.0, 0.0)); // 绿色

    mesh.addVertex(right);
    mesh.addColor(ofFloatColor(1.0, 1.0, 0.0)); // 蓝色
}

我们先用 mesh.enableColors() 启用颜色。颜色默认就是启用的，但写上这一行是好习惯。然后可以用 mesh.addColor(...) 添加颜色。颜色用 ofFloatColor 指定，它和 ofColor 类似，只是红、绿、蓝和 alpha 通道用 0.0 到 1.0 之间的浮点数指定。（如果你想，你可以用 ofColor，因为网格会自动把它转换成 ofFloatColor。）我们添加的第一个颜色作用于第一个顶点，第二个颜色作用于第二个顶点，依此类推。

觉得我们的点很无聊？那就来点线。我们需要把图元模式改成线，但线图元有三种不同的选项。把 setup 函数的第一行依次改成下面这些，自己都试一遍：

    mesh.setMode(OF_PRIMITIVE_LINES);
    mesh.setMode(OF_PRIMITIVE_LINE_STRIP);
    mesh.setMode(OF_PRIMITIVE_LINE_LOOP);

mesh.setMode(...) 的每种模式从顶点生成线的方式都不同：

  • OF_PRIMITIVE_LINE 把每对顶点连成一条独立的线。如果你有一组顶点——V1、V2、V3、V4……——那么 V1 会连到 V2，V3 会连到 V4，依此类推。
  • OF_PRIMITIVE_LINE_STRIP 把每对顶点连成一组相连的线。V1 会连到 V2，V2 会连到 V3，依此类推。
  • OF_PRIMITIVE_LINE_LOOP 与 OF_PRIMITIVE_LINE_STRIP 相同，但还会把最后一个顶点连回第一个顶点。

只有 OF_PRIMITIVE_LINE_LOOP 勾勒出了完整的三角形。如果你想用 OF_PRIMITIVE_LINE 画出同样的三角形，可能会试着多添加一些顶点，像这样：

    mesh.addVertex(top);
    mesh.addVertex(left);
    mesh.addVertex(left);
    mesh.addVertex(right);
    mesh.addVertex(right);
    mesh.addVertex(top);

添加重复的顶点感觉太啰嗦了？那我们试试别的：

void ofApp::setup() {
    mesh.setMode(OF_PRIMITIVE_LINES);
    mesh.enableColors();
    mesh.enableIndices();

    ofVec3f top(100.0, 50.0, 0.0);
    ofVec3f left(50.0, 150.0, 0.0);
    ofVec3f right(150.0, 150.0, 0.0);

    mesh.addVertex(top);
    mesh.addColor(ofFloatColor(1.0, 0.0, 0.0));

    mesh.addVertex(left);
    mesh.addColor(ofFloatColor(0.0, 1.0, 0.0));

    mesh.addVertex(right);
    mesh.addColor(ofFloatColor(1.0, 1.0, 0.0));

    mesh.addIndex(0);
    mesh.addIndex(1);
    mesh.addIndex(1);
    mesh.addIndex(2);
    mesh.addIndex(2);
    mesh.addIndex(0);
}

索引增加了一层抽象。你添加到网格中的每个顶点都会被追加到一个大数组的末尾。也就是说，每个顶点都有一个编号，唯一地标识它在数组中的位置（也就是索引）。列表里有第 0 个顶点、第 1 个顶点、第 2 个顶点，等等。所以，你可以用索引号指向一个已有的顶点。

当你调用 mesh.enableIndices() 时，openFrameworks 会创建一个空的索引数组。当你使用 addIndex(...) 时，你是在往这个数组的末尾添加值。当网格即将被绘制到屏幕上时，openFrameworks 不会遍历顶点数组来创建图形图元，而是遍历你的索引数组来决定如何创建图元。

所以当我们的模式是 OF_PRIMITIVE_LINE、索引数组是 {0, 1, 1, 2, 2, 0} 时，第 0 个顶点与第 1 个顶点相连，第 1 个顶点与第 2 个顶点相连，第 2 个顶点与第 0 个顶点相连。为了画一个三角形要做这么多工作？没错。但索引这个概念强大且有用。

还有一点你可能注意到了——线的颜色。这是显卡上发生的一些魔法。你可以告诉它点 A 是红色、点 B 是蓝色，并且点 A 和 B 之间连一条线。然后显卡在屏幕上绘制构成这条线的像素时，会（线性地）在这些颜色之间插值。

作为读完整节的奖励：

我知道，这奖励不怎么样。但它确实展示了 OF_PRIMITIVE_LINES 能做、而另外两种线图元模式做不到的事——你可以画出彼此独立的线。我们会在下一节里用到这一点。

生成式网格：用图像驱动网格的创建

网格！你现在已经具备了开始创建“生成式”网格的基本材料。所谓生成式网格，就是一种把一组规则施加到某些数据上而生成的网格。

所以我们需要一些数据和一些规则。我们从 Hubble 望远镜拍的一张图里取一些“数据”：

新建一个名为 HubbleMesh 的 openFrameworks 项目。在该项目里创建 bin/data 目录（“bin”可能已经存在），把上面的图片保存为“stars.png”。（点击这里，然后右键图片并选择“图片另存为”。）

现在我们有了些色彩缤纷、像素感十足的素材，但该用什么规则把这些像素变成网格呢？我们可以从画点开始，逐步过渡到画线。我们的图像里有大量星星，那就在这些星星所在的位置创建一些顶点。做到这一步之后，我们就可以用线把相邻的顶点连起来，织出一张网。

先做第一件事，加载这张图。进入 main.cpp，把窗口尺寸改成你刚下载的图片的尺寸：

    ofSetupOpenGL(800,800,OF_WINDOW);

然后进入你的头文件（ofApp.h），添加：

    ofImage image;

最后进入源文件（ofApp.cpp）：

void ofApp::setup(){
    image.load("stars.png");
}

void ofApp::draw(){
    image.draw(0,0);
}

没有专门讲 ofImage 的章节，但你可以看看 openFrameworks 学习页面里的 Graphics 部分。

我们只需要用 load(...) 加载图像，并用 draw(0,0) 把它画在屏幕左上角。

很好！图像加载好了。现在我们要创建一个带顶点的网格。如果只想在星星所在的位置创建顶点，我们可以遍历像素、寻找“亮”的颜色。为此，我们需要用 image.getColor(x, y) 获取像素的颜色信息。我们要遍历图像中的像素并施加一个阈值，只在颜色强度大于我们设定的某个值的像素位置创建顶点。

给 ofApp.h 添加一个网格：

    ofMesh mesh;

并把这段加到 ofApp.cpp：

void ofApp::setup(){
    image.load("stars.png")

    mesh.setMode(OF_PRIMITIVE_POINTS);
    mesh.enableColors();

    float intensityThreshold = 150.0;
    int w = image.getWidth();
    int h = image.getHeight();
    for (int x=0; x<w; ++x) {
        for (int y=0; y<h; ++y) {
            ofColor c = image.getColor(x, y);
            float intensity = c.getLightness();
            if (intensity >= intensityThreshold) {
                ofVec3f pos(x, y, 0.0);
                mesh.addVertex(pos);
                // 调用 addColor(...) 时，网格会自动把
                // ofColor 转换成 ofFloatColor
                mesh.addColor(c);
            }
        }
    }
}
void ofApp::draw(){
    ofBackground(0,0,255);
    mesh.draw(); // 蓝色背景，方便看清网格
}

在那段代码里，我们创建了一个以点为图元的网格。然后我们遍历图像中的每个像素（用 getWidth() 和 getHeight()），并用 getLightness() 检查每个像素颜色的强度。如果强度超过了阈值，就在该像素的位置创建一个顶点，并用该像素的颜色给它着色。最后，我们在蓝色背景上绘制网格，这样就能看出图像中哪些像素被用来生成顶点。你可以调高或调低阈值，从而减少或增加顶点的数量。

我们用 ofBackgroundGradient 把这个背景换成更合适的样子……

void ofApp::draw(){
    ofColor centerColor = ofColor(85, 78, 68);
    ofColor edgeColor(0, 0, 0);
    ofBackgroundGradient(centerColor, edgeColor, OF_GRADIENT_CIRCULAR);
    mesh.draw();
}

马上就要进入线、线、线了！

我们的网格里有很多顶点。如果你愿意，可以用 getNumVertices() 查看数量：

// 阈值为 150 时，大约有 64,000 个顶点
cout << mesh.getNumVertices() << endl;

如果我们开始遍历这 64,000 个顶点、把每个顶点和附近的其他顶点连接起来，这个循环可能会花掉相当多的时间。加速图像处理的一种常见做法是缩小图像：

image.load("stars.png");
image.resize(200, 200);

然后，由于我们的图像像素与 openFrameworks 窗口像素不再一一对应，我们需要调整循环里的 pos 变量：

if (intensity >= intensityThreshold) {
    // 我们把图像缩小了 4 倍，所以需要把像素
    // 位置乘以 4，才能让网格覆盖 openFrameworks 窗口
    ofVec3f pos(x*4, y*4, 0.0);
    mesh.addVertex(pos);
    mesh.addColor(c);
}

现在顶点数量比较合理了（约 2000 个），我们可以开始把这些顶点连成线。如果只想连接彼此靠近的顶点，就需要遍历所有可能的顶点对，检查它们之间的距离是否小于某个值，如果是，就把它们连起来。

// 别忘了切换到线模式！
mesh.setMode(OF_PRIMITIVE_LINES);

// 这次我们要使用索引
mesh.enableIndices();

// ……
// 为清晰起见，省略了创建顶点的代码
// 但不要从你的文件里删掉它！

// 我们来加点线！
float connectionDistance = 30;
int numVerts = mesh.getNumVertices();
for (int a=0; a<numVerts; ++a) {
    ofVec3f verta = mesh.getVertex(a);
    for (int b=a+1; b<numVerts; ++b) {
        ofVec3f vertb = mesh.getVertex(b);
        float distance = verta.distance(vertb);
        if (distance <= connectionDistance) {
            // 在 OF_PRIMITIVE_LINES 中，每一对顶点或索引都会
            // 被连接起来形成一条线
            mesh.addIndex(a);
            mesh.addIndex(b);
        }
    }
}

你最终应该会得到类似这样的结果（如果代码在你机器上跑得太慢，试着调高 intensityThreshold 变量以减少顶点数量）：

我们再来看一遍那段代码：

  1. 我们需要取得所有不重复的顶点对。用 mesh.getVertex(...) 可以取得网格中第 a 个顶点的位置。然后用两个 for 循环就能取到每一对顶点。你可能会奇怪第二个循环为什么从 b=a+1 开始。连接两个顶点形成线时，顶点的顺序无关紧要，所以我们可以排除掉一大堆 b 的取值。
  2. 然后，我们需要求出这些顶点之间的距离。ofVec3f 正好有一个函数能做这件事：distance(...)。
  3. 如果两个顶点之间的距离小于 connectionDistance 设定的值，我们就需要在它们之间加一条线。加线其实就是把索引 a 和 b 添加到网格的索引数组里。

砰！生成式网格。我们再加两处调整，把它变成真正的 3D。首先，我们可以用某个像素颜色的饱和度来改变其对应顶点的 z 坐标。

if (intensity >= intensityThreshold) {
    float saturation = c.getSaturation();
    float z = ofMap(saturation, 0, 255, -100, 100);
    ofVec3f pos(x*4, y*4, z);
    mesh.addVertex(pos);
    mesh.addColor(c);
}

这段代码用 ofMap(...) 把更亮的颜色推向正 z 方向，把更白的颜色推向负 z 方向。ofMap 让我们可以把落在某个范围内的值（对我们来说是 0 到 255）映射到一个新的值范围（同样对我们来说是 -100 到 100）。

嗯……你的网格没怎么变？那现在该做本节最后一处调整了：加一个相机。

把这个加到你的头文件里：

		ofEasyCam easyCam;

然后修改你的 draw 函数：

void ofApp::draw(){
    ofColor centerColor = ofColor(85, 78, 68);
    ofColor edgeColor(0, 0, 0);
    ofBackgroundGradient(centerColor, edgeColor, OF_GRADIENT_CIRCULAR);

    easyCam.begin();
        ofPushMatrix();
            ofTranslate(-ofGetWidth()/2, -ofGetHeight()/2);
            mesh.draw();
        ofPopMatrix();
    easyCam.end();
}

ofEasyCam 是快速感受生成式网格中那难以捉摸的第三维的简便方法。OpenGL 章节会讲到相机、ofPushMatrix()、ofPopMatrix() 和 ofTranslate()。这段代码会把你的网格居中放在相机的视野里。现在你可以左键拖动来旋转了！右键拖动来缩放！

操纵：添加修改网格的效果

我们现在已经有一个网格感十足的网格了，那就继续给它加一些规则，让网格动起来。

抖动

这个网格看起来像显微镜下的东西，所以我们给顶点加一点“有机”的运动。在你的机器上，这个运动会比下面的 gif 快得多（浏览器会限制 gif 的最大帧率），但它能让你大致明白我们要做什么：

每一帧，我们都要把每个顶点移动一小段随机的距离。我们不用 ofRandom(...) 来位移顶点，而是用 ofSignedNoise(...)，它会生成一种叫做 Perlin 噪声的东西。可以看看 Daniel Shiffman 在他在线书籍的 1.6 Perlin Noise (A Smoother Approach) 一节中对 Perlin 噪声的描述。Perlin 噪声产生的随机值会随时间平滑变化。对比书中的 figure 1.5（显示连续的噪声值）和 figure 1.6（显示连续的随机值），你就能很好地理解随机值和 Perlin 噪声的区别。

用 ofRandom(...) 时，你指定一个取值范围，它返回该范围内的一个随机值。如果你连续调用它多次，每次（极大概率）都会得到一个新值。Perlin 噪声的工作方式略有不同。ofSignedNoise(...) 总是返回 -1.0 到 1.0 之间的值，但你仍然需要给函数传入一个输入。把 ofSignedNoise(...) 想成画在坐标纸上的曲线。你传入一个坐标、一个 x 值，它返回对应的 y 值。如果你多次调用 ofSignedNoise(3.0)，每次都会得到相同的值。

用 Perlin 噪声生成运动时，常见的做法是把当前时间作为输入（x 值）传进去。所以，为了位移顶点，我们要把时间（用 ofGetElapsedTimef() 获取）传给 ofSignedNoise，这样它给出的值就会随时间平滑变化。有一个需要注意的地方——我们希望各个顶点看起来是彼此独立地移动。如果在一帧里给每个顶点都传入相同的 time 给 ofSignedNoise，那所有顶点都会朝同一个方向移动。位移第一个顶点时用的时间必须与位移第二个顶点（以及第三个、第四个……）时不同。

我们直接进代码。把这个加到你的头文件里：

		vector<ofVec3f> offsets;

然后把下面两行加到你的 setup 函数里：

// 把这行加到代码里，显式地把帧率设为每秒 60 帧：
ofSetFrameRate(60);

// 为清晰起见省略了一些代码行，你仍应
// 把它们保留在本地版本里

for (int x=0; x<w; ++x) {
    for (int y=0; y<h; ++y) {
        ofColor c = image.getColor(x, y);
        float intensity = c.getLightness();
        if (intensity >= intensityThreshold) {
            float saturation = c.getSaturation();
            float z = ofMap(saturation, 0, 255, -100, 100);
            ofVec3f pos(x*4, y*4, z);
            mesh.addVertex(pos);
            mesh.addColor(c);

            // 再把这行加到已有的 for 循环里：
            // 它会创建一个带 3 个随机值的 ofVec3f，
            // 让我们可以独立地移动每个顶点的
            // x、y、z 坐标
            offsets.push_back(ofVec3f(ofRandom(0,100000), ofRandom(0,100000), ofRandom(0,100000)));
        }
    }
}

最后，把这些行加到你的 update 函数里：

int numVerts = mesh.getNumVertices();
for (int i=0; i<numVerts; ++i) {
    ofVec3f vert = mesh.getVertex(i);

    float time = ofGetElapsedTimef();
    float timeScale = 5.0;
    float displacementScale = 0.75;
    ofVec3f timeOffsets = offsets[i];

    // 使用 Perlin 噪声的典型模式会用到几个参数：
    // ofSignedNoise(time*timeScale+timeOffset)*displacementScale
    //     ofSignedNoise(time) 给出的噪声值会随时间
    //         平滑变化
    //     ofSignedNoise(time*timeScale) 让我们可以控制噪声的
    //         平滑程度（timeScale 越小，值越平滑）
    //     ofSignedNoise(time+timeOffset) 让我们可以用同一个 Perlin 噪声
    //         函数来控制多个对象，并让它们看起来像
    //         在各自独立地移动
    //     ofSignedNoise(time)*displacementScale 让我们可以把噪声的
    //         范围从 [-1, 1] 改成任意想要的值
    // 把所有这些参数组合起来，你就能很好地
    // 控制你的噪声

    vert.x += (ofSignedNoise(time*timeScale+timeOffsets.x)) * displacementScale;
    vert.y += (ofSignedNoise(time*timeScale+timeOffsets.y)) * displacementScale;
    vert.z += (ofSignedNoise(time*timeScale+timeOffsets.z)) * displacementScale;
    mesh.setVertex(i, vert);
}

在 setup 里我们做了两件新事情：

  1. 用 ofSetFrameRate() 指定程序最高 60 帧每秒。不做这个也能跑，但当你让东西随时间运动时，这么做很有用。
  2. 我们创建了一个叫 offsets 的变量。它是一个装随机值的 ofVec3f 的 vector。（参见 Introduction to Vectors 章节。）这些值让我们可以在 x、y、z 三个方向上随机移动每个顶点，并且看起来与其它顶点的移动相互独立。

然后，在 update 里：

  1. 我们用 mesh.getVertex(...) 取得某个顶点的位置，存进名为 vert 的变量里。
  2. 我们用 ofSignedNoise(...) 配合一组参数来移动 vert 的 x、y、z 值。
  3. 我们用 mesh.setVertex(...) 更新顶点的位置。

太好了！现在我们有了一个飘忽不定的网格。

绕轨

接下来，我们可以加一些旋转的轨道运动。毕竟这些原本就是星星，这么一来也挺贴切。

我们要用三角函数来实现轨道运动。如果想先打打基础，可以看看 The Nature of Code 的第 3 章。

先不管 z 维度，专注于 x 和 y 维度。如果我们想让一个点沿圆周绕行，可以利用角度、正弦和余弦来实现。看看关于极坐标的维基条目——特别是“在极坐标与笛卡尔坐标之间转换”那一节。

如果我们知道点距离中心多远，就可以用一个距离和一个角度（极坐标）来定义它在空间中的位置。我们可以拿这个距离和角度换算成 x、y 值（笛卡尔坐标）：

x = distance * cos(angle)
y = distance * sin(angle)

如果你想让那个点沿圆周摆动，只需要随时间不断增大角度，剩下的数学会处理好。

所以为了我们网格的目的，我们需要：

  1. 定义一个中心点，让顶点绕它旋转
  2. 计算各顶点所在位置的初始极坐标
  3. 随时间缓慢增大每个顶点极坐标的角度

我们在头文件里加一些新变量：

// 我们要用它们来开关轨道运动
ofMesh meshCopy;
bool orbiting;
float startOrbitTime;

// 这些变量用来存储每个顶点的极坐标
vector<float> distances;
vector<float> angles;
ofVec3f meshCentroid;

把这个加到你的 setup 函数末尾：

// 我们需要计算网格的中心点
// ofMesh 有一个名为 getCentroid() 的方法，它会
// 求出所有顶点的平均位置
//    http://en.wikipedia.org/wiki/Centroid
meshCentroid = mesh.getCentroid();

// 现在我们知道了质心，还需要知道每个顶点相对于
// 该中心点的极坐标（距离和角度）。
// 我们之前求过点之间的距离，但角度怎么办？
// 这时就该 atan2 出场了。atan2(y, x) 接收 x 和 y 值，返回
// 相对于原点 (0,0) 的角度。如果要求两点
// (x1, y1) 和 (x2, y2) 之间的角度，只需使用 atan2(y2-y1, x2-x1)。
for (int i=0; i<numVerts; ++i) {
    ofVec3f vert = mesh.getVertex(i);
    float distance = vert.distance(meshCentroid);
    float angle = atan2(vert.y-meshCentroid.y, vert.x-meshCentroid.x);
    distances.push_back(distance);
    angles.push_back(angle);
}

// 这些变量用来开关轨道运动
orbiting = false;
startOrbitTime = 0.0;
meshCopy = mesh; // 存一份网格副本，以便恢复原始状态

把这个加到你的 update 函数里：

if (orbiting) {
    int numVerts = mesh.getNumVertices();
    for (int i=0; i<numVerts; ++i) {
        ofVec3f vert = mesh.getVertex(i);
        float distance = distances[i];
        float angle = angles[i];
        float elapsedTime = ofGetElapsedTimef() - startOrbitTime;

        // 调整各轨道的速度，让靠近
        // 中心的比远处的转得更快
        float speed = ofMap(distance, 0, 200, 1, 0.25, true);

        // 要求出顶点的角度旋转量，我们用当前时间和
        // 起始角度
        float rotatedAngle = elapsedTime * speed + angle;

        // 记住，我们的距离是相对于网格质心
        // 计算的，所以需要把一切移回屏幕
        // 坐标，即加上质心的 x 和 y
        vert.x = distance * cos(rotatedAngle) + meshCentroid.x;
        vert.y = distance * sin(rotatedAngle) + meshCentroid.y;

        mesh.setVertex(i, vert);
    }
}

然后往你的 cpp 文件里加一个 keyPressed 函数：

void ofApp::keyPressed(int key){
	if (key == 'o') {
		orbiting = !orbiting; // 取反布尔值
		startOrbitTime = ofGetElapsedTimef();
		mesh = meshCopy; // 把网格恢复为原始值
	}
}

现在你应该可以用 'o' 键开关轨道运动了！

另外一点编程说明：变量 meshCopy 用作原始网格的备份副本，需要时可以重新载入。在 setup 函数里，当我们使用这一行时：

meshCopy = mesh;

我们创建了变量 mesh 的一个独立副本，并存进变量 meshCopy。在这种情形下，ofMesh 类提供的是所谓的深拷贝，所以如果我们改动 mesh 中的某些顶点，meshCopy 里的任何东西都不会变。只是要小心——并非所有对象默认都提供深拷贝！

放大

我们要加的最后一项调整给网格带来一点交互性。我们会加一个放大镜效果：

严格来说，叫它放大镜效果是用词不当。它其实基于光学中一种叫桶形畸变的现象。把它施加到网格上时，效果是这样的：

我们要做的是：

  1. 找到鼠标在屏幕上的位置。
  2. 找到从鼠标指向每个顶点的方向。
  3. 沿该方向把每个顶点从鼠标处推开。
    • 如果顶点离鼠标近，就推得远一些。
    • 如果顶点离鼠标远，就推得近一些。

这一项调整会用到一些向量运算，如果你觉得摸不着头脑，可以看看 Math 章节。上代码！

往你的头文件里加一个新变量：

		// 和绕轨调整一样，这让我们可以开关放大效果
		bool mouseDisplacement;

在 setup 函数末尾加一行：

    // 我们希望一开始不开启这个效果
    mouseDisplacement = false;

在 update 函数的开头加上这段代码：

if (mouseDisplacement) {
    // 获取鼠标位置——它必须相对于屏幕中心，
    // 因为 draw() 里有 ofTranslate() 命令
    ofVec3f mouse(mouseX, ofGetHeight()-mouseY, 0);

    // 遍历网格中的所有顶点，把它们推离
    // 鼠标
    for (int i=0; i<mesh.getNumVertices(); ++i) {
        ofVec3f vertex = meshCopy.getVertex(i);
        float distanceToMouse = mouse.distance(vertex);

        // 根据到鼠标的距离缩放位移量
        // 离鼠标越近，位移越小
        float displacement = ofMap(distanceToMouse, 0, 400, 300.0, 0, true);

        // 计算从鼠标指向当前顶点的方向
        ofVec3f direction = vertex - mouse;

        // 把方向归一化，使其长度为 1
        // 这样之后就能方便地改变向量的长度
        direction.normalize();

        // 把顶点沿远离鼠标的方向推开，推开的距离
        // 等于变量 displacement 的值
        ofVec3f displacedVertex = vertex + displacement*direction;
        mesh.setVertex(i, displacedVertex);
    }
}

最后，在 keyPressed 函数的开头加上这段代码：

if (key == 'm') {
    mouseDisplacement = !mouseDisplacement; // 取反布尔值
    mesh = meshCopy; // 恢复原始网格
}
