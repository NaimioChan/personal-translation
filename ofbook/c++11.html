C++ 11

作者：Elliot Woods

简介

C++ 是一门老语言。它从 1983 年就存在了。按今天的标准看，它常被视为陈旧、晦涩，也许干脆就是脱节了。与此相反，很多人认为它在性能和清晰度之间提供了最好的平衡，也有很多人用它是因为它强大的第三方库生态、设备支持以及普遍的接受度。就连新技术（比如 CUDA）也常常选用 C++ 作为它们的语言。

一些更现代的语言（比如 JavaScript 和 C#）让程序的运行方式与 C/C++ 大不相同。它们使用“虚拟机”的概念，而虚拟机与电路板上处理电子信号的那种计算机是完全不同的东西。虚拟机像真实机器一样接收并处理程序指令，但允许各种无法直接对应到硅电子器件的想法，比如动态类型和反射。虚拟机把处理器的种种限制从程序员的思考中抽离出去。

C/C++ 没有虚拟机，这（就目前而言）常常让它在性能上领先于这些较新的语言。它相当严格：你键入的指令在底层与物理处理器指令是一比一的对应关系。这给语言带来了一些不灵活之处，但也意味着代码既能被人自然理解，又能清晰地转换成机器码。

本章我们来看看 C++11 引入的一些新写法，它们既保留了这一承诺，又提供了书写代码的新方式。

auto

C++11 里最常用、也最简单的写法大概就是 auto。你会爱上它。而且过一两天，你大概就记不起没有它的日子了。看看下面这段……

ofRectangle myRectangle = ofGetCurrentViewport();
ofVec2f rectangleCenter = myRectangle.getCenter();
float rectangleCenterX = rectangleCenter.x;

这个代码块里我们声明了 3 个变量：

  • myRectangle
  • rectangleCenter
  • rectangleCenterX

每一行代码我们都在：

  1. 从右侧取一个变量，它具有某个确定的类型（分别是 ofRectangle、ofVec2f、float）
  2. 声明一个新变量，显式地写成与右侧值匹配的类型
  3. 把值赋给这个变量

对于 = 左右两侧，数据类型是相同的。由于 C++ 是严格类型的（例如返回 float 的函数永远返回 float），右侧的值不可能变成别的类型。编译器知道代码右侧会给出什么数据类型，例如它知道第 1 行里 = 右侧是一个 ofRectangle。所以，也许我们可以写成这样：

auto myRectangle = ofGetCurrentViewport();
auto rectangleCenter = myRectangle.getCenter();
auto rectangleCenterX = rectangleCenter.x;

这样编译器就能替我们做一部分编码工作。实际上，这正是 auto 特性提供的便利。这个代码块编译出的结果与第一个代码块完全相同。编译器注意到右侧是什么，然后在看到 auto 的地方替换成正确的类型。

这有什么好处

auto 能帮你省下敲键盘的力气。想象下面这段：

//.h
vector<shared_ptr<ofThread> > myVectorOfThreads;
//.cpp

// 旧写法
vector<shared_ptr<ofThread>>::iterator firstThreadIterator = this->myVectorOfThreads.begin();

// 新写法
auto firstThreadIterator = this->myVectorOfThreads.begin();

这能让代码更易读，但你也能以其他方式利用 auto。

例如，当你复用或复制变量时，可以一路使用 auto，这意味着你只需在开头定义一次想用的类型，而不必在代码的其他每处都写。比如在上面的 h 文件里，你可能想把 vector 换成 list，或者把 shared_ptr<ofThread> 换成 ofThread *。这些改动会自动传导到代码中所有用到 auto 的地方。挺妙吧？

注意这几点

auto 不是一种新类型

注意下面这样是不行的：

auto myRectangle = ofGetCurrentViewport();
myRectangle = "look mum! i'm a string!!"; // 编译错误！

记住 auto 本身不是一种类型，它不是能装下任何东西的魔法容器（像 C# 里的 var 或其他动态类型语言那样），它只是一个在编译期被替换掉的关键字，你可以想象编译器只是在那一行替你写上了合理的内容。在这个例子里，第一行确保了 myRectangle 是 ofRectangle，而你不能把 string 赋给 ofRectangle。

不能在函数参数里用 auto

因为 auto 必须由使用它的那行代码隐式确定，而这个决定是在编译期做出的，所以它不能做函数参数，我们来看看这意味着什么……

想象下面是合法的：（注意：它并不合法！）

float multiplyBy2(auto number) {
	return number * 2;
}

int firstNumber = 1;
float secondNumber = 2.0f;

cout << multiplyBy2(firstNumber) << endl;
cout << multiplyBy2(secondNumber) << endl;

如果这段代码合法，那么函数第一次被调用时 auto 意味着 int，第二次就意味着 float。所以“auto 这段文字在它出现的地方被替换成一个显式类型”这种说法就讲不通了。所以基本上你不能在函数参数里使用 auto（你也许该去看看 template，它会为这两种不同类型自动生成两份代码）。

不能用 auto 作函数返回类型

我不确定为什么，反正就是不行。按理说你应该可以，但就是不行，规则不是我定的……

const 与引用

我们来写个 const auto：

ofRectangle rectangle = ofGetCurrentViewport();
// 等同于
auto rectangle = ofGetCurrentViewport();

// 以及
const ofRectangle rectangle = ofGetCurrentViewport();
// 等同于
const auto rectangle = ofGetCurrentViewport();

接着看 auto &，在需要引用类型的时候用它。

float x = rectangle.x;
// 等同于
auto x = rectangle.x;

// 以及

float & x = rectangle.x;
// 等同于
auto & x = rectangle.x;

小结

  • 在变量声明里用 auto 省下敲键盘的力气
  • auto 取 = 赋值右侧的类型，并在编译期用该类型替换掉 auto 这段文字。
  • auto 不是能承载任何类型数据的魔法容器，它只是在编译期被替换成代码中隐含的类型
  • 你不能在函数参数、返回类型以及其他几处地方使用 auto。
  • 需要 const 类型就用 const auto，需要引用类型就用 auto &

for (thing : things)

看看下面这个常见写法：

vector<ofPixels> mySelfies;
/*
在这里拍几张照片，存进 mySelfies
*/

//哎哟，我的照片全是竖版
for(int i=0; i<mySelfies.size(); i++) {
	//把它们从横版旋转成竖版
	mySelfies[i].rotate90(1);
}

vector<ofxMySpace::Friend> myFriends = myspaceClient.getFriends();

//现在把它们发给我的所有好友
for(int i=0; i<myFriends.size(); i++) {
	if (myFriends[i].isOnline()) {
		for(int i=0; i<mySelfies.size(); i++) {
			myFriends[i].sendImage(mySelfies[i]);
		}
	}
}

我们总在写 for(int i=0; i<mySelfies.size(); i++) { 这样的东西，那看看能不能用 for thing in things 找到更简洁的写法，在 C++11 里我们可以写成 for (thing : things)……

vector<ofPixels> mySelfies;
/*
在这里拍几张好看的照片
*/

//哎哟，我的照片全是竖版
for(auto & mySelfie : mySelfies) {
	//把它们从横版旋转成竖版
	mySelfie.rotate90(1); // (1)
}

auto myFriends = myspaceClient.getFriends();

//现在把它们发给我的所有好友
for(auto & myFriend : myFriends) {
	if (myFriend.isOnline()) {
		for(auto & mySelfie : mySelfies) {
			myFriend.sendImage(mySelfie); // (2)
		}
	}
}

注意 for(thing : things) 和 auto 配合得天衣无缝。还要注意我用的是 auto &，因为：

  • 在 (1) 处我想能修改 vector 的内容，所以我需要指向 vector 元素的引用，而不是它的副本。
  • 在 (2) 处，用引用比用副本更合理，因为计算上更便宜，也意味着我不必为 ofxMySpace::Friend 分配新实例（它内部可能有许多复杂的分配，你并不想因为复制对象而重复一遍）。

小结

  • 使用 for(auto thing : vectorOfThings)
  • 这对所有 STL 容器都有效（vector、map、list、deque、set 等），在一些专用容器里也有效（比如 ofxGrayCode::DataSet）
  • 通常你会想用 for(auto & thing : vectorOfThings) 来使用引用而不是副本

override

override 节省你的时间，不是靠减少打字量，而是靠减少你处理 virtual 函数时挠头的次数。想象下面这段：

class BuildingProjectionMapper {
public:
//...
    virtual void mapTheNeoClassicalColumns();
//...
};

class AutoBuildingProjectionMapper : public BuildingProjectionMapper {
public:
	void mapTheNeoClassicalColums(); // 糟了，我把 column 拼错了
};

现在如果我实现 AutoBuildingProjectionMapper::mapTheNeoClassicalColums，它可能永远不会被调用，而我可能纳闷为什么我的函数调用全都被基类处理了。问题在于编译器从没告诉我，我试图覆盖的那个函数并不存在。这时 override 就来救场了。

class AutoBuildingProjectionMapper : public BuildingProjectionMapper {
public:
	void mapTheNeoClassicalColums() override;
};

这告诉编译器我打算覆盖一个 virtual 函数。这种情况下，编译器会告诉我并不存在名为 mapTheNeoClassicalColums 的 virtual 函数，因此我的 override 是有问题的。于是照着编译器的抱怨，我可以进去把拼写错误改掉。然后就能继续在市政图书馆外墙上做我的投影映射了。

当你修改基类时，这尤其有用：比如在 oF 0.9.0 里，许多基类发生了变化，通过在 addon 里使用 override，addon 作者会被硬性提醒自己的代码已经失效、需要更新。

小结

  • 当你打算覆盖基 class 里的 virtual 函数时，在派生类 h 文件的函数定义末尾加上关键字 override
  • 如果你的 override 无效，编译器会警告你，这也许能帮你省下大量找错误的时间

Lambda 函数

这个稍微复杂一点。它并非让代码写得更快或更安全，而是为你的代码设计方式增添了一种新特性。因此，我们先介绍它们的基本作用，然后做一些有意思的例子。

Lambda 函数在 JavaScript、C# 等现代语言里非常常见，用起来可以非常自由。它们看起来比实际更吓人，所以我建议先直接上手做几个例子。我们来写个简单的例子：

void normalFunction() {
	cout << "Heathcliff, it's me Cathy." << endl;
}

void main() {
	auto lambdaFunction = []() {
		cout << "So cold. Let me into your window." << endl;
	};
	normalFunction();
	lambdaFunction();
}

猜猜这里会发生什么：

Heathcliff, it's me Cathy.
So cold. Let me into your window.

所以 lambda 函数就像一个普通函数，但最大的区别在于：

  1. 函数定义在另一个函数的可执行代码内部（这个例子里 lambdaFunction 定义在 main 里）。
  2. 这个函数同时还是一个变量

第二点正是 lambda 函数真正的用武之地。因为我们可以传递它、存储它、丢弃它、复制它。我们来看个更具体的例子。

把 lambda 函数作为变量传递

当我们想把 lambda 函数作为变量传递时，需要引入一种能承载该数据的类型（因为我们不能在函数参数里或定义类成员时使用 auto）。能存储 lambda 函数的一个常见类型是 std::function<void()>。我明白 void() 乍看有点怪，但等后面多用一些 lambda 之后你就会明白。

class Graphic {
public:
    void draw() {
        whatToDraw();
    }

    std::function<void()> whatToDraw;
};

class ofApp : ofBaseApp {
/*
.. 那些常规内容
*/
protected:
	vector<Graphic> graphicElements;
};
void ofApp::setup() {
	Graphic circle;
	circle.whatToDraw = []() {
		ofDrawCircle(50,50,20);
	};
	this->graphicElements.push_back(circle);

	Graphic rectangle;
	rectangle.whatToDraw = []() {
		ofRect(50,50,200,200);
	};
	this->graphicElements.push_back(rectangle);
}

void ofApp::draw() {
	for(auto & graphic : this->graphicElements) {
		graphic.draw();
	}
}

我们本可以通过创建继承 Graphic 并覆盖 draw 函数的类来做这件事（比如 CircleGraphic 和 RectangleGraphic）。但这里我们没有定义新类，而是创建了 2 个 Graphic 实例，用 lambda 函数让它们包含不同的函数定义。这很方便，因为当我们只想改动类的少量功能时，新建类定义往往是件麻烦事。

参数、作用域与返回类型

那么怎么把变量传进函数、再取出结果？普通函数的常见做法是用函数参数把变量送进函数，用返回值把数值送出来。我们看看 lambda 里怎么做。

float multiplyByTwoFunction(float x) {
	return x * 2.0f;
}

void test() {
	auto multiplyByTwoLambda = [](float x) {
		return x * 2.0f;
	};

	cout << multiplyByTwoFunction(2.0f) << endl;
	cout << multiplyByTwoLambda(2.0f) << endl;
}

这当然会输出：

4
4

很好！但也得注意，因为这个函数现在有 float 返回类型和 float 参数，它与我们早先那个不带参数、返回 string 的 lambdaFunction 是不同类型的函数。注意，如果我们想把这个函数作为参数传递，需要这样做：

void performActionOnFloat(float & x, std::function<float(float)> action) {
	x = action(x);
}

具体来说，能承载 lambda 函数的类型是：

std::function<return type(arguments)>

你可以使用多个参数（就像普通函数那样）。

作用域

最后，我们常常需要为 lambda 函数引入一个“作用域”。作用域指函数外部哪些变量在函数内部可见。我们在 lambda 函数定义的 [] 之间定义作用域，例如：

float multiplier = 4.0f;
auto multiplyByOurMultiplier = [multiplier](float x) { // (1)
	return x * multiplier;
}
cout << multiplyByOurMultiplier(2.0f); // 输出 8

通过在 (1) 处 lambda 函数定义的 [] 里写上变量名 multiplier，现在我们就能在函数定义里使用变量 multiplier 了。放在那里非常顺手的一个东西是 [this]，它把 this 放进函数的作用域，也就是让当前类的所有成员在函数内部都可用。

你可以：* 往作用域里加多个变量，例如 [this, multiplier] * 以引用（而非副本）方式把变量加进作用域，例如：[&multiplier] * 用 [=]（在函数定义处复制变量）或 [&]（使用变量的引用）自动把你函数内部用到的变量加进作用域。

目前的小结

  • Lambda 函数让你能在代码里定义存放在变量中的函数
  • Lambda 函数可以在函数、类、存储变量和 vector 等之间传递。基本上，变量能做的任何事，lambda 函数都能做。
  • 你可以从 lambda 函数返回值，并为函数指定参数
  • 你可以用 [=]、[&]、[this]、[myVariableName]、[&myVariableName] 等来定义函数作用域内可用的内容。

工作线程示例

现在我们看个更深入的例子，了解怎样用 lambda 函数避免自己陷进泥潭。这个例子里有一个与相机设备通信的类。这台相机设备的特别之处在于：相机必须在它自己的线程里运行，所有对相机的操作都必须在该线程里执行。

假设我们的 ofApp 像这样：

class ofApp : public ofBaseApp {
	/*
	常规内容
	*/

	CameraClass camera;
	ofParameter<float> exposure;
}

class CameraClass : public ofThread {
protected:
	void threadedFunction() override {
		while (this->isCameraRunning()) {
			this->device.getFrame();
			this->pixelsLock.lock();
			this->pixels.setFromExternalPixels(this->device->getData(), 640, 480, 3);
			this->pixelsLock.unlock();
			// (1)
		}
	}

	CameraDriver device;
	ofPixels pixels;
	ofMutex pixelsLock;
}

现在如果我们想在 ofApp 里设置相机的曝光，就需要把这件事通知给 CameraClass，并让它在正确的线程里设置曝光（比如在 (1) 处，它发生在从相机抓取帧的间隙）。

一种做法是存一些数据，说明我们需要修改曝光、以及新的曝光值是多少。然后在 (1) 处检查这些数据，并写好相应的处理代码。问题是这样太繁琐，还会引入大量特殊情况（比如，如果某件事需要先读取增益再相应修改曝光呢？）。

一个巧妙的变通办法是用 lambda 函数来实现，例如：

class CameraClass : public ofThread {
protected:
	void threadedFunction() override {
		while (this->isCameraRunning()) {
			this->device.getFrame();
			this->pixelsLock.lock();
			this->pixels.setFromExternalPixels(this->device->getData(), 640, 480, 3);
			this->pixelsLock.unlock();

			this->actionsLock.lock();
			for(auto & action : this->actions) {
				action(this->device);
			}
			this->actions.clear();
			this->actionsLock.unlock();
		}
	}

	void performInThread(std::function<void(CameraDriver&)> action) {
		this->actionsLock.lock();
		this->actions.push_back(action);
		this->actionsLock.unlock();
	}

	CameraDriver device;
	ofPixels pixels;
	ofMutex pixelsLock;

	vector<std::function<void(CameraDriver&)> > actions;
	ofMutex actionsLock;
}
//ofApp 里的某个地方

this->camera->performInThread([this](CameraDriver & device) {
	device.setExposure(this->exposure);
});

这样指令就会被推入 CameraClass，于是在合适的时机，这个函数会在管理相机的线程内被调用，从 ofApp 取 this->exposure 变量，并对 CameraClass 中定义的 CameraDriver 生效。这一切都不必四处传递大量变量，方式还非常灵活。想了解它在 ofxMachineVision 中是如何实现的，可以看看 https://github.com/elliotwoods/ofxMachineVision/blob/master/src/ofxMachineVision/Utils/ActionQueueThread.cpp 里的 ofxMachineVision::Utils::ActionQueueThread。
