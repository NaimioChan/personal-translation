硬件

作者：Caitlin Morris 和 Pierre Proske

引言

本章介绍如何让 openFrameworks 走出计算机屏幕、进入物理世界。你究竟为什么想这么做呢？嗯，考虑到我们自己就是物理存在的生物，让软件去控制、感知和驱动现实世界中的东西会相当令人兴奋，也能创造出真正直击身体的体验。基于屏幕的作品可以很迷人，但实体装置因为更具可触性，有潜力带来更大的冲击。

有很多办法可以让你的 openFrameworks 应用离开个人电脑的框架，与外部世界交互。大体上这都涉及从 openFrameworks 到你决定接上的那块硬件的某种通信。基于计算机的通信方式（或协议）种类各异，但最常见的是所谓的“串口”（serial）通信，之所以这么叫，是因为发送的每一位数据都是一个接一个传输的（而不是多个位并行发送）。

我们要对接的第一种硬件是出色的 Arduino 原型平台。用 Arduino 自己的话说，它是一个“基于灵活、易用的硬件和软件的开源电子原型平台……面向艺术家、设计师、爱好者和任何有兴趣创造交互式对象或环境的人。”很容易看出，为什么对 openFrameworks 感兴趣和对 Arduino 感兴趣的人群有大量重叠！有了 Arduino，你可以很快让你的 openFrameworks 应用接上传感器（比如光传感器、距离传感器或其他获取环境输入的方式）、执行器（比如灯、电机和其他输出），并实现实时交互。你可以自由地走出像素的领域，进入物理世界。

本章假定你已经安装了 Arduino IDE，也装好了平时用来做 openFrameworks 的环境。如果没有，可以从 Arduino 网站（arduino.cc）或 Arduino 的 github（github.com/arduino）下载。

另外，跟着本章的例子做，需要你有几样基本硬件。你需要一块 Arduino（任何一代都行；Uno、Leonardo 或 Duemilanove 看起来会和本章的插图最像，但任何能通过 USB 连接的 Arduino 都完全没问题）和一根合适的 USB 线来连到计算机。

[** Callout - Leonardo 与早期开发板的不同之处在于它有内置的 USB 通信，不需要额外的处理器。这让 Leonardo 在连接的计算机上除了表现为虚拟串口，还能表现为鼠标和键盘。这让搭建交互式应用变得非常简单——在你的 openFrameworks 应用里，你只需要检测按键！ **]

串口通信入门

SERIAL：一个接一个

在最基本的语言学意义上，serial 指的是一个接一个到来的东西；这个词常用来形容杂志、犯罪和电视连续剧。这个含义在谈论串行数据时同样适用：“串口通信”意味着两个实体之间的所有信息都是按单个流、一次一份地发送的。一份数据，也就是一个位，只是一条二进制信息：你要么发 0，要么发 1。用数字电子学的术语，它们常被称为“高”和“低”；0 是低（就像关灯），1 是高（再打开）。8 个位（例如 01000001 这个流，代表字母 A）有时被打包在一起，构成一个字节。

串口通信其实是个非常宽泛的话题，串口协议有很多，包括 DMX（基于 RS-485）和 MIDI（以每秒 31,250 位的速率串行传输）这类视听协议，本章会简要涉及。最常见的串口协议叫 RS-232，计算机过去常配有 RS-232 串口（还记得吗？），但如今很少见了，这就是为什么涉及计算机的串口通信通常需要一根 RS-232 转 USB 的转接头（网上或本地电子商店都能买到）。

不过，如果你是连 Arduino，它在计算机上已经表现为一个虚拟串口，你只需要一根普通 USB 线（具体型号取决于你手上是哪种 Arduino）。Arduino 还自带一个库，负责读写计算机上出现的那个串口。此外，Arduino 有双向的 RS-232 串口，可以用来连接其他外部串口设备。简单说——Arduino 在串口通信方面装备齐全，替你做掉了大部分苦活！

注：扩充 Serial 库相关内容

Arduino 与你软件之间传输数据的速度以每秒位数（bps）衡量，这是个相当一目了然的单位。每秒位数通常称为波特率，会随应用而变。例如标准的 9600bps 波特率传数据比 115200 慢，但更快的波特率可能更容易出现字节错乱。

数字与模拟通信

在 Arduino 中使用 Serial monitor

Arduino IDE 内置一个 Serial monitor，能让你以指定的波特率“收听”串口上传来的数据。你可以在 Arduino 菜单栏的 Tools - Serial Monitor 下找到它，也可以点 IDE 顶部的“放大镜”图标。

在 Arduino sketch 里，在 setup() 函数中建立串口通信，并向 Serial monitor 打印一句简单的 “Hello world!”：

Serial.begin(9600);
Serial.println("Hello world!");

打开 Serial monitor，确认它的波特率与你的 sketch 一致（就是你写在 Serial.begin() 里的那个值）。注意 Arduino 上的 TX/RX 灯在 setup 时会闪一次——你可以按 Arduino 上的复位键（多数设备上都有）重新运行 setup，把这一点看得更清楚。Arduino 是通过串口发出打印的文本，Serial monitor 则接收到这些文本并打印出来给我们看。

当然，你也可以用 Serial monitor 来反映从连接到 Arduino 的设备传来的更有趣的数据。数字和模拟输入数据都可以打印到串口。

像按钮这种数字输入，或者只有开和关两个位置的开关，会以二进制值作为其状态。你可以跟着 Arduino 官方那个出色的教程走一遍把按钮接到 Arduino 的例子，教程在这里：

http://arduino.cc/en/tutorial/button

要把按钮的值打印到串口，先把 digitalRead 的返回值存进一个变量，再把这个变量打印到串口，做法和前面 “hello world!” 的例子一样。不过这里要在 loop() 函数里打印，而不是 setup()，这样值会持续更新，而不是只在复位时更新一次。

buttonState = digitalRead(buttonPin);
Serial.println( buttonState );

如果你觉得按钮的二元性太受限，也可以用模拟输入来读取，用上电位器、光敏电阻之类的元件，或者任何能提供非二值输入的传感器。

在标准 Arduino 上，模拟输入只能接在 A0-A5 引脚上。这些专用的模拟引脚带有一颗 ADC（模拟-数字转换器）芯片，能把电路返回的电压大小转换成 0 到 1023 之间的、数字可读的数值。

关于模拟输入的例子和教程有不少；这里有一个使用电位器的基础例子：

http://arduino.cc/en/Tutorial/AnalogInput

把输入的变量打印到 Serial monitor 的方法与数字输入相同，只是你要用 Arduino 的 analogRead() 函数而不是 digitalRead()：

sensorValue = analogRead(sensorPin);
Serial.println( sensorValue );

用串口在 arduino 与 openframeworks 之间通信

Arduino 用串口通信在硬件与 Serial monitor 之间通信，同样也可以用串口通信在 Arduino 板与任何正在运行的应用之间通信，包括 openFrameworks。用 openFrameworks 原生的 ofSerial 类就能相当简单地做到这一点。这个类会在指定的波特率和串口上建立一个串口监听器，让它能访问与 Arduino IDE 原生 Serial 库相同的流式数据。

openFrameworks 自带的 examples 中的 communications 文件夹里有一个注释详尽的好例子。让它跑起来所需的基本部件是：一个 Serial 对象、一个用于知道消息是否已发送的开关标记，以及一个存放所接收数据的数组。

把 FIRMATA 用作串口协议

虽然所有串口通信都可以手动处理，但你很快就会碰到能力上限——一旦你开始想寻址不同的设备或者有多个输入，就会陷入数据包管理的漩涡，更容易收到损坏的数据包或不准、错乱的数据。与其手动应付这些，不如用 Firmata，它是一个管理多条串口流的开源协议，简单得多。

OFARDUINO

ofArduino 是 openFrameworks 内置的 Arduino 通信类，基于 Firmata 协议。使用 ofArduino 的前提是 Arduino 上已经烧录了默认的 Firmata sketch。这个 sketch 位于 Arduino 的 examples 文件夹里，它让 Arduino 的所有引脚都能通过模拟和数字通信进行通信，也支持更具体的引脚寻址以控制舵机。

示例：把之前只用 Arduino 做过的 LED 闪烁 sketch 重做一遍，这次用 OF。

我们要做的基本流程是这样的：（缺图）

  • 创建一个 ofArduino 对象
  • 在正确的端口和波特率上连接到该 Arduino 对象
  • 设置一个事件监听器，用来判断我们是否成功连上了 Arduino
  • 设置一个用于通信的引脚，并指定该通信是模拟还是数字
  • 轮询串口上的数据
  • 向该引脚发送 HIGH 和 LOW（或模拟值）参数

创建一个 ofArduino 对象

第一步是把一个 ofArduino 对象加进项目的头文件（通常是 ofApp.h）。我把它叫做 myArduino。

void setup();
void update();
void draw();

ofArduino myArduino;

现在我们已经把 openFrameworks 原生 ofArduino 类的能力扩展到了自己的 sketch 里，可以操作 myArduino 这个对象了。

在正确的端口和波特率上连接到 Arduino 对象

在 ofApp.cpp 的 setup() 里，用 ofArduino 的 connect() 函数在合适的端口和波特率上建立连接。connect() 接受两个参数：第一个是串口名的 String，应当与你在 Arduino 应用里连接的串口名一致；第二个是波特率。Firmata 使用 57600 bps 的标准波特率。

myArduino.connect("/dev/tty.usbserial-a700fiyD", 57600);

设置一个事件监听器，用来判断我们是否成功连上了 Arduino

如果你只在 Arduino IDE 里工作，让某些函数（比如设置引脚模式）只在程序开始时被调用一次是很容易的——你只要在 setup() 里调用它们，并确信设备初始化时它们总会运行一次。但当你在和 openFrameworks 这类其他软件通信时，重要的是有一个检查机制，确保任何初始化函数只在连接建立之后才发生。openFrameworks 用 ofEventUtils 类让这件事更简单，它依靠默认的 ofAddListener() 和 ofRemoveListener() 函数来检查连接事件。

在 openFrameworks 应用里，我们会想创建一个 Arduino 专用的 setup() 函数，它只在串口连接建立后作为结果被调用一次。我们先在 ofApp.h 里声明这个函数：

void setupArduino(const int & version);

……然后在 ofApp.cpp 里调用它：

void ofApp::setupArduino(const int & version) {
    // Arduino 的初始化任务写在这里
}

传给函数的参数 const int & version，是我们即将建立的监听器给出的默认返回值——它总是以回传一个携带已连接固件版本号的参数来回应连接事件。这一行可以保持原样。

在 ofApp.cpp 的 setup() 里，用 ofAddListener() 创建一个监听器。ofAddListener() 是 ofEventUtils 的函数，接受这些参数（事件对象、回调对象、回调函数）。当事件对象发生（在这里，是 ofArduino 的 EInitialized 事件被触发）时，ofAddListener 告诉回调对象（这里是 ofApp 自身的指针，即 “this”）去执行我们在上一步创建的 setupArduino 函数。

cpp           ofAddListener(myArduino.EInitialized, this, &ofApp.setupArduino);

当 EInitialized 事件被触发时（也就是到 Arduino 的连接完成、Arduino 回传其固件版本信息时），监听器把我们送到回调函数，在这里就是 setupArduino()。

在 setupArduino() 里，我们可以移除监听器，因为我们已经知道连接建立了。ofRemoveListener() 接受的参数与其对应函数相同。

ofRemoveListener(myArduino.EInitialized, this, &ofApp.setupArduino);

设置一个用于通信的引脚，并指定该通信是模拟还是数字

现在该像在标准 Arduino 应用里那样对待我们的 Arduino 初始化函数了，设置好引脚和引脚模式。这里我把 Arduino 的 13 号引脚设为数字输出，为做一个基本的 LED 闪烁做准备。

myArduino.sendDigitalPinMode(13, ARD_OUTPUT);

其他引脚设置选项与标准 Arduino 引脚设置一致：

sendDigitalPinMode(PIN_NUMBER, ARD_INPUT) // 数字输入
sendAnalogPinMode(PIN_NUMBER, ARD_OUTPUT) // 模拟输出
sendAnalogPinMode(PIN_NUMBER, ARD_INPUT) // 模拟输入

轮询串口上的数据

为了持续用串口上的新信息更新，重要的是定期调用 ofArduino 的 update() 函数。可以把它放在 Arduino 专用的函数里，也可以直接从 ofApp::update() 调用：

myArduino.update();

就这样！现在你可以开始向 Arduino 的 13 号引脚发送数字信号了。

你能用来控制这个信号的触发方式有无数种：可以设一个定时器、把它接进游戏事件、用摄像头输入……可能性无穷无尽！这里，我要用上、下方向键来触发 13 号引脚的 LED 开和关。

因为我用键盘按键来控制，所以用 void ofApp::keyPressed (int key) 函数，不过你也可以把触发放在 draw() 或其他函数里，取决于你想要的效果。

void ofApp::keyPressed  (int key){
    switch (key) {
        case OF_KEY_UP:
            myArduino.sendDigital(13, ARD_HIGH);  // 打开 LED
            break;
	case OF_KEY_DOWN:
            ard.sendDigital(13, ARD_LOW); // 关闭 LED
            break;
        default:
            break;
    }
}

把各部分拼在一起后，运行应用，来回按上、下方向键，就能开关 Arduino 板载的 LED！你也可以在 13 号引脚上接一颗 3mm 或 5mm 的 LED，让效果更明显。记住 13 号引脚是 Arduino 上唯一自带电阻的引脚，所以如果你想在其他引脚上加 LED 或其他元件，就需要搭一个带电阻的完整电路，以免烧坏元件。

点灯——用 DMX 控制硬件

DMX（全称 Digital Multiplex），也叫 DMX512（512 指每路输出能容纳的通道数），是一个控制灯光和舞台设备的协议。它从 80 年代就存在了，有时被称为灯光界的 MIDI，因为它达成的结果相当类似——通过计算机对硬件进行排序和控制。DMX 可以用来控制从频闪灯到 RGB par 灯再到 LED 灯具的各种设备。只要硬件合适，甚至可以用脉冲宽度调制驱动 LED 灯带。通过定制的 openFrameworks 应用发送 DMX 的好处是，你可以借助 OF 提供的所有其他好东西把它整合起来，包括自定义 GUI、自定义排序算法、摄像头跟踪——随便你说。

DMX 协议概览

要发送 DMX，首先需要一个 DMX 转 USB 的控制接口。这是一个你需要购买的专用盒子，用来让计算机通过 USB 端口发送 DMX 数据。如果本地找不到，这些接口在网上很容易买到。你还需要一些 DMX 线缆，把接口和你要控制的 DMX 设备连起来。带 XLR 接头的麦克风线可以用来传 DMX 数据，不过 DMX 的官方标准是 5 芯线，而 XLR 只提供 3 芯。确实存在 5 芯与 3 芯之间的转接头，以备你需要混用。总之，用线缆把你的硬件接到 DMX 转 USB 设备上，按需安装驱动（取决于操作系统），就可以开始发送了。如前所述，控制器每路 DMX 输出最多能发送 512 个通道的 DMX 数据。在 DMX 术语中，每 512 个通道一组称为一个 “Universe”。在需要大量通道的复杂配置中，常会用到多个 DMX Universe。通常你不需要超过一个 universe，因为一盏彩色灯只会占用约 3 个通道（红、绿、蓝各一个）。

DMX 数据格式

一个 DMX 数据包，也就是每帧发给硬件的数据，由 512 个通道组成，每个通道发送一个 8 位值（即 0-255）。DMX 的一个古怪之处是通道编号从 1 开始，通道 0 是起始码而不是数据通道。这意味着，在建立一个数组来存放每帧的 DMX 数据时，你需要把它的大小设为 513 字节。在 openFrameworks 里我们几乎总是用 unsigned char 来表示一个字节，不过你也可以用其他类型来表示。

//设定数据结构
unsigned char dmxData[513];

// 把第一个值清零
dmxData[0] = 0;

// 通道从这里往上开始有效
dmxData[1] = 126;

围绕 DMX 涌现了不少 OF addon，在 ofxAddons.com 上搜一下就能找到最新的。通常这些 addon 已经把必要的数据结构（包括上面这个）都建好了，所以你除了把正确的数据送到正确的通道之外，什么都不用操心。最难的部分大概会是给你的控制器装驱动！

OF DMX 应用的结构

无论你用哪份代码、哪个 addon，发送 DMX 数据的方式都与下面这段伪代码非常相似（把注释替换成相应的代码）：

void ofApp::setup() {
    //连接你的 DMX 控制器
}

void ofApp::update() {

    //为 DMX 数据结构赋上相应的值

    //用新数据更新 DMX 控制器
}
