实验性游戏开发

作者：Phoenix Perry 与 Jane Friedhoff

附加编辑：Kayla Lewis

越来越多的游戏开发者正在转向 openFrameworks 这套创意编程工具包来开发游戏。与 Unity、GameMaker、Construct2 等平台不同，oF 并不是专为游戏开发者打造的。然而，oF 能移植到移动端、处理视频、使用摄像头输入、支持生成式图形，还能接入 Arduino、Kinect 等设备（以及其他特性），因此对那些希望快速做出引人入胜且独特的游戏的开发者来说，它成了一个非常有吸引力的选择。

用 openFrameworks 制作的流行游戏

本章将介绍如何在 openFrameworks 中开发游戏。我们会讲清一款游戏由哪些部分组成，以及如何编写一个简单的太空射击游戏。最后，我们会给游戏加一点实验性的 oF 花样：实现 OSC 功能，让你可以在玩家游玩的过程中实时改变游戏难度。

准备好了吗？开始吧！

游戏开发者究竟是怎么做游戏的？

有多少游戏开发者，就有多少种做游戏的方式。不过，很多开发者会遵循迭代流程：加入一个组件，测试；再加入一个组件，再测试；如此反复。无论在哪个平台上，这种方法都能让游戏开发者迅速判断最初的想法里哪些部分值得保留，并检验他们觉得可能有意思的新增内容，而不必浪费时间做出一个完整的游戏、事后却发现它并不吸引人。

这种迭代过程既可以在数字环境里进行，也可以在物理环境里进行。纸面原型就是用纸模型和替代物来测试机制与交互。这类纸面原型虽然未必看起来像最终的游戏，但搭起来很快，能让开发者比写代码更快地试验核心机制。例如，一款解谜游戏的棋盘和棋子，用纸和骰子搭出来，比用即使是最简单的移动应用实现还要快。同样，当开发者做数字原型（或者说用代码做原型）时，他们会先打磨游戏机制，让素材保持粗糙，直到接近完成。最后，开发者会进入漫长的调优过程——反复调整各种参数，直到手感恰到好处。

我们要用 openFrameworks 来玩这个流程的最后一步。在我们做的游戏里，不会固定使用一套每局都不变的参数。我们会用 openFrameworks 的 OSC 库，让我们能从另一台设备（比如智能手机或平板）无线通信，从而实时调整这些参数，为玩家提供量身定制的体验。

那么，OSC 到底是什么？

OSC（Open Sound Control）是作为 MIDI 的进阶方案出现的，所以我们先说说 MIDI。MIDI 是一种在设备之间收发信息的数据协议，这些设备通常是电子乐器。正是 MIDI 让键盘和鼓机之类的东西能同步触发。如果你听过流行音乐，你就听过 MIDI 在工作。

MIDI 有数据通道，你可以在通道上发送或接收单条消息，也就是事件。程序员可以把这些 MIDI 事件与电子乐器能执行的动作关联起来。例如，你可以把键盘设为在通道 1 上发送数据、在 MIDI 通道 2 上接收数据。更具体地说，你可以把某个特定的键（比如“a”键）编程为在通道 1 上发出一个 MIDI 事件。如果你的鼓机设为在通道 1 上接收，它就会收到这条消息并执行相应动作（比如发声）。这套系统相当酷，但受限于它预先定义且离散的消息类型。

随着时间推移，计算机和数据传输速度也在进步，于是有了 OSC。OSC 的设计目标是支持更具表现力的演奏数据，通过网络发送各种不同类型、灵活的消息。OSC 是 UDP（User Datagram Protocol）之上的一层薄封装，用户只要指定网络地址以及传入和传出的端口，就能通过网络发送信息。（UDP 在游戏里用得很多，而且完全可以在同一份代码里同时使用这两种协议，不会有任何问题。）

OSC 消息由以下部分组成：

  • 地址模式（address pattern）。这是一个分层的命名空间，看起来有点像 Unix 文件系统或 URL（例如 /Address1）。这些模式实际上可以是任何你想要的东西（例如 /EnemySpeed）——把它们当作你发送的内容的名字。
  • 类型标签字符串（Type tag string）。它只表示所发送数据的类型（例如 int、string）。
  • 参数（arguments）。实际传输的值（例如 6、"Hello world" 等）。

智能手机和平板上有很多不贵的应用，提供可定制的 GUI（带按钮、滑块等），用来发送不同种类的 MIDI 消息。下载一个（我们喜欢 TouchOSC），这样我们就有工具来发送消息了。想清楚这一点，我们就开始做游戏吧！

我们的基础游戏——以及如何让它不那么基础

openFrameworks 把 OSC 作为一个随附的 addon 来处理，所以第一步是运行 projectGenerator，创建一个带 OSC addon 的项目。（如果你还没读过关于 addon 的介绍，现在正好跳过去 [here] 看看！）启动 projectGenerator，然后在主菜单里点击“Addons”。会弹出窗口。选中 ofxOsc，然后点返回。这时在 Addons 一词旁边应该能看到 ofxOsc。按下“generate”。等它完成项目创建后，关闭生成器，用 Visual Studio 或 Xcode 打开项目。项目会创建在你的 myApps 文件夹里。现在打开它。

我们的游戏将包含：

  • 一个玩家，拥有屏幕上的位置、移动速度，以及一张代表它的图像
  • 一些敌人，拥有屏幕上的位置、移动速度（水平方向的值基于正弦波）、代表它们的一张图像，以及一个用来记录下次何时可以射击的间隔
  • 一个关卡控制器，拥有一个用来记录下一次应在何时生成敌人的间隔
  • 子弹（玩家和敌人的都有），拥有屏幕上的位置、代表它们的图像、一种记录它们来自哪一方（玩家还是敌人）的方式，以及速度
  • 奖励生命，拥有屏幕上的位置、代表它的一张图像，以及速度

把这些都列出来之后，我们用 OSC 来影响以下内容：

  • 敌人的水平移动——它们走的是更夸张的正弦曲线，还是更接近直线
  • 敌人射击的频率
  • 关卡控制器生成敌人的频率
  • 屏幕上是否有生命奖励

这三个参数能让开发者逐秒为正在玩这款游戏的人调整难度。

先从 ofApp 开始。有几样东西我们确定需要对应的类，所以为 Player、Bullet、Life、Enemy 和 LevelController 分别建立 .h 与 .cpp 文件。记得在每个类里 #include "ofMain.h"，并在 ofApp.h 里 include 每个类的 .h 文件。

玩家移动

很好！接下来看我们的玩家。玩家的类是这样的：

class Player {
public:
   ofPoint pos;
   float width, height, speed;
   int lives;

   bool is_left_pressed, is_right_pressed, is_down_pressed, is_up_pressed;

   void setup(ofImage * _img);
   void update();
   void draw();
   void shoot();

   void calculate_movement();

   bool check_can_shoot();

   ofImage * img;

};

一点点来看：

  • 玩家的位置会存在一个名为 pos 的 ofPoint 里。ofPoint 是很方便的数据类型，包含 x 和 y 值，让我们可以通过 pos.x 和 pos.y 访问玩家位置。
  • 玩家会有 width、height 和 speed 变量（前两个用于碰撞检测，最后一个用于移动）。
  • 玩家会有一个整数形式的生命值（因为 4.33333333333 条命没有任何意义）。
  • 玩家会用若干独立的布尔变量记录当前按下了哪些移动键。
  • 玩家会有 setup、update、draw、shoot 和 calculate_movement 方法。
  • 最后，玩家会有一个指向我们给它用的图像的指针。

你可能会想，为什么要用这么多布尔变量——为什么不直接检查哪些键被按下了？

问题在于，在 openFrameworks 里 keyPressed() 并不会返回当前所有被按住的键——只返回最后按下的那个键。也就是说，如果玩家同时按下上键和左键（想沿对角线移动），openFrameworks 只会报告其中一个键被按下。你可以把 keyPressed 的结果打印出来，亲眼看看这个现象。我们的规避办法是让玩家的移动基于前面写的那些布尔变量。如果玩家按下了某个键，对应布尔变量就为 true；如果松开，就为 false。这样，当玩家按下上键和左键时，在松开之前我们都会报告上和左为 true。

新的 keyPressed() 和 keyReleased() 函数是这样的：

//--------------------------------------------------------------
void ofApp::keyPressed(int key){
   if (game_state == "game") {
       if (key == OF_KEY_LEFT) {
           player_1.is_left_pressed = true;
       }

       if (key == OF_KEY_RIGHT) {
           player_1.is_right_pressed = true;
       }

       if (key == OF_KEY_UP) {
           player_1.is_up_pressed = true;
       }

       if (key == OF_KEY_DOWN) {
           player_1.is_down_pressed = true;
       }
   }

}
//--------------------------------------------------------------
void ofApp::keyReleased(int key){
   if (game_state == "start") {
       game_state = "game";
   } else if (game_state == "game") {
       if (key == OF_KEY_LEFT) {
           player_1.is_left_pressed = false;
       }

       if (key == OF_KEY_RIGHT) {
           player_1.is_right_pressed = false;
       }

       if (key == OF_KEY_UP) {
           player_1.is_up_pressed = false;
       }

       if (key == OF_KEY_DOWN) {
           player_1.is_down_pressed = false;
       }
   }
}

玩家子弹

接下来做子弹。为了能在屏幕上同时存在数量可变的子弹，我们需要在 ofApp.h 里加一个 vector<Bullet> bullets。再创建一个 void update_bullets() 函数，用来更新我们的子弹 vector（很快它还会触发子弹碰撞检测）。我们还希望玩家子弹和敌人子弹看起来不一样，所以在 ofApp.h 里加上 ofImage enemy_bullet_image 和 ofImage player_bullet_image。

子弹类和玩家类会很相似，有位置、速度、宽度、指向图像的指针，以及若干函数。最大的区别是子弹会记录自己来自哪一方（因为这会影响它能伤害谁、朝哪个方向移动）。

class Bullet {
public:
   ofPoint pos;
   float speed;
   float width;
   bool from_player;

   void setup(bool f_p, ofPoint p, float s, ofImage * bullet_image);
   void update();
   void draw();

   ofImage * img;
};

我们的 Bullet.cpp 会是这样：

void Bullet::setup(bool f_p, ofPoint p, float s, ofImage * bullet_image) {
   from_player = f_p;
   pos = p;
   speed = s + 3;
   img = bullet_image;
   width = img->width;

}
void Bullet::update() {
   if (from_player) {
       pos.y -= speed;
   } else {
       pos.y += speed;
   }
}
void Bullet::draw() {
   img->draw(pos.x - width/2, pos.y - width/2);

}

同样，这跟玩家的代码很像，但有两处不同：

  • 我们记录了子弹来自哪一方，并根据这个变量改变代码行为（这意味着我们可以把所有子弹放在同一个 vector 里）
  • 实例化子弹时，我们会读取射击者的位置以及射击者当前的速度（所以子弹总会比射出它的东西移动得更快）

现在子弹类实现好了，我们可以回到 ofApp::setup()，在加载 player_image 的代码下面加上 enemy_bullet_image.loadImage("enemy_bullet.png"); 和 player_bullet_image.loadImage("player_bullet.png");。 目前，我们的 update_bullets() 函数会调用每颗子弹的 update() 函数，同时清除朝任一方向飞出屏幕的子弹。

//--------------------------------------------------------------
void ofApp::update_bullets() {
   for (int i = 0; i < bullets.size(); i++) {
       bullets[i].update();
       if (bullets[i].pos.y - bullets[i].width/2 < 0 || bullets[i].pos.y + bullets[i].width/2 > ofGetHeight()) {
           bullets.erase(bullets.begin()+i);
       }
   }
   //稍后我们会在这里调用碰撞检测函数
}

现在 ofApp::update() 和 ofApp::draw() 会是这样：

//--------------------------------------------------------------
void ofApp::update(){
   if (game_state == "start") {

   } else if (game_state == "game") {
       player_1.update();
       update_bullets();
   }
}
//--------------------------------------------------------------
void ofApp::draw(){
   if (game_state == "start") {

   } else if (game_state == "game") {
       ofBackground(0,0,0);
       player_1.draw();

       for (int i = 0; i < bullets.size(); i++) {
           bullets[i].draw();
       }

}

加入敌人

接着做敌人。到这里流程应该已经很熟悉了。在 ofApp.h 里加上 ofImage enemy_image 和 vector<Enemy> enemies。另外，还要把 float max_enemy_amplitude 和 float max_enemy_shoot_interval 也加到 ofApp.h 里。这两个就是我们会用 OSC 影响的敌人参数。敌人类是这样的：

class Enemy {
public:
   ofPoint pos;
   float speed;
   float amplitude;
   float width;

   float start_shoot;
   float shoot_interval;

   void setup(float max_enemy_amplitude, float max_enemy_shoot_interval, ofImage * enemy_image);
   void update();
   void draw();
   bool time_to_shoot();

   ofImage * img;
};

敌人的水平移动会由喂给正弦波的值决定形状（稍后就能看到）。我们会记录振幅变量，让不同的敌人可以有不同的振幅。我们还要记录是否已经过了足够的时间让这个敌人再次射击，这用到了 start_shoot 和 shoot_interval 两个变量。这两个变量实际上会在 setup() 函数里设置。最后，我们会有一个布尔函数，告诉我们这个敌人本帧能否射击。我们的敌人类会是这样：

void Enemy::setup(float max_enemy_amplitude, float max_enemy_shoot_interval, ofImage * enemy_image) {
   pos.x = ofRandom(ofGetWidth());
   pos.y = 0;
   img = enemy_image;
   width = img->width;
   speed = ofRandom(2, 7);
   amplitude = ofRandom(max_enemy_amplitude);
   shoot_interval = ofRandom(0.5, max_enemy_shoot_interval);
   start_shoot = ofGetElapsedTimef();
}
void Enemy::update() {
   pos.y += speed;
   pos.x += amplitude * sin(ofGetElapsedTimef());
}
void Enemy::draw() {
   img->draw(pos.x - width/2, pos.y - width/2);
}
bool Enemy::time_to_shoot() {
   if (ofGetElapsedTimef() - start_shoot > shoot_interval) {
       start_shoot = ofGetElapsedTimef();
       return true;
   }
   return false;
}

在 update 里，我们用当前已流逝的时间（以帧计）得到一个不断增加的数值，喂给正弦函数，而正弦函数返回 -1 到 1 之间的值。我们把它乘以波的振幅，让这条曲线更夸张或更平缓。

在 time_to_shoot() 里，我们检查当前时间与该敌人上次射击时间的差是否大于它的射击间隔。如果是，就把 start_shoot 设为当前时间并返回 true；否则返回 false。接下来把敌人整合进 ofApp.cpp 的其余部分：

//--------------------------------------------------------------
void ofApp::setup(){
   game_state = "start";

   max_enemy_amplitude = 3.0;
   max_enemy_shoot_interval = 1.5;

   enemy_image.loadImage("enemy0.png");
   player_image.loadImage("player.png");
   enemy_bullet_image.loadImage("enemy_bullet.png");
   player_bullet_image.loadImage("player_bullet.png");

   player_1.setup(&player_image);
}
//--------------------------------------------------------------
void ofApp::update(){
   if (game_state == "start") {

   } else if (game_state == "game") {
       player_1.update();
       update_bullets();

       for (int i = 0; i < enemies.size(); i++) {
           enemies[i].update();
           if (enemies[i].time_to_shoot()) {
               Bullet b;
               b.setup(false, enemies[i].pos, enemies[i].speed, &enemy_bullet_image);
               bullets.push_back(b);
           }
       }
   } else if (game_state =="draw") {
   }
}
//--------------------------------------------------------------
void ofApp::draw(){
   if (game_state == "start") {
   } else if (game_state == "game") {
       ofBackground(0,0,0);
       player_1.draw();
       for (int i = 0; i < enemies.size(); i++) {
           enemies[i].draw();
       }
       for (int i = 0; i < bullets.size(); i++) {
           bullets[i].draw();
       }
   } else if (game_state == "end") {
   }
}

碰撞

来实现子弹碰撞检测。在 ofApp.h 里加上 void check_bullet_collisions()，然后写出下面的函数：

//--------------------------------------------------------------
void ofApp::check_bullet_collisions() {
   for (int i = 0; i < bullets.size(); i++) {
       if (bullets[i].from_player) {
           for (int e = enemies.size()-1; e >= 0; e--) {
               if (ofDist(bullets[i].pos.x, bullets[i].pos.y, enemies[e].pos.x, enemies[e].pos.y) < (enemies[e].width + bullets[i].width)/2) {
                   enemies.erase(enemies.begin()+e);
                   bullets.erase(bullets.begin()+i);
                   score+=10;
               }
           }
       } else {
           if (ofDist(bullets[i].pos.x, bullets[i].pos.y, player_1.pos.x, player_1.pos.y) < (bullets[i].width+player_1.width)/2) {
               bullets.erase(bullets.begin()+i);
               player_1.lives--;

               if (player_1.lives <= 0) {
                   game_state = "end";
               }
           }
       }
   }
}

            //当前设置，作为视觉反馈
            sendBack.addFloatArg(max_enemy_amplitude);
            sendBack.setAddress("/updatedVals/max_enemy_amplitude");
            sender.sendMessage(sendBack);

            cout << max_enemy_amplitude << endl;
        }

与此同时，我们也会把这些同样的值发回设备，这样就能看到游戏里的设置当前处在什么数值。[KL: 这句话也许可以更简洁，最好别以“at”结尾。] 这有两个好处。第一，你能在设备上看到当前变量值的视觉反馈。第二，如果你碰巧调出了游戏里手感合适的设置，可以在设备上截图。停止游戏后，回去把代码里的变量改成一致的数值，下次运行程序时就会以这些参数开始。

为了把当前运行游戏里的所有值打包并每帧发回设备，我们要创建一个 ofxOscMessage 类型的变量，名为 sendBack。当 ofxOscMessage m 的地址字符串匹配时，我们用对应的函数（这里通常是 addFloatArg）把参数复制到 sendBack，再用 setAddress 函数设置地址模式。最后，我们用内置的 sendMessage 函数把这条消息通过 OSC 发出去。

下面是加到 LiveTesting.cpp 文件里的完整代码

void LiveTesting::update()
{
    //我们简单的 while 循环，确保拿到所有消息
    while (receiver.hasWaitingMessages()) {

        //获取这条消息，它里面会包含我们所有的参数。
        //它是一个数据集合

        ofxOscMessage m;
        //把这条消息的引用传给接收器
        //也就是上面用 OSC addon 里的 getNextMessage 函数设置的那个。

        receiver.getNextMessage(&m);

        //这将是我们从游戏发回
        //到设备的消息，让它知道我们收到了什么值
        //并把该值回显给我们，好让我们知道我们
        //当前的游戏设置是多少。

        ofxOscMessage sendBack;

        //记住我们的地址标签是唯一的。
        //我们把 /game 标签设为根地址，每个 "/" 表示一个子标签。
        //如果这些字符串匹配，我们就知道进来的这条消息是我们的
        //振幅。

        if(m.getAddress() == "/game/max_enemy_amplitude")
        {

            //这一点很关键。
            //想跑通代码，每个类型都必须匹配。
            //我们知道消息数组里的第一个参数
            //在上面的 if 语句为真时会是 float。

            max_enemy_amplitude = m.getArgAsFloat(0);

            //现在我们打包一组数据，发回
            //到我们的设备。
           //sendBack 也是一个数据集合，我们
            //往里面添加参数。
            //把设置的振幅值加到消息里，然后继续。

            sendBack.addFloatArg(max_enemy_amplitude);
            sendBack.setAddress("/updatedVals/max_enemy_amplitude");
            sender.sendMessage(sendBack);

            cout << max_enemy_amplitude << endl;
        }

        else if (m.getAddress() == "/game/interval_time")
        {
            //这和上面完全一样。
            //我们只是在测试地址
            //标签是否等于这个值，如果是，就做完全相同
            //的流程：把游戏内的值设为该
   			//传入参数的值，并把 interval_time 发回我们的设备。

            interval_time = m.getArgAsInt32(0);

            //发送视觉反馈。  
            sendBack.addIntArg(interval_time);
            sendBack.setAddress("/updatedVals/interval");
            sender.sendMessage(sendBack);
        }
        else if (m.getAddress() == "/game/max_enemy_shoot_interval")
        {
            //同样是测试地址标签的流程
            max_enemy_shoot_interval = m.getArgAsFloat(0);

            //发送视觉反馈。
            sendBack.addFloatArg(max_enemy_shoot_interval);
            sendBack.setAddress("/updatedVals/max_enemy_shoot_interval");
            sender.sendMessage(sendBack);

        }
        else if (m.getAddress() == "/game/triggerBonus")
        {
            //最后收尾。这是最后一个测试。
            triggerBonus = m.getArgAsInt32(0);
            cout << triggerBonus << endl;
            //发送视觉反馈。
            sendBack.addIntArg(triggerBonus);
            sendBack.setAddress("/updatedVals/triggerBouns");
            sender.sendMessage(sendBack);


        }
    }
