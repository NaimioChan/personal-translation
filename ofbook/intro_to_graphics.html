如果你是跟着用ofSketch操作，那太好了！有几点需要注意。在ofSketch里写代码，和在Xcode、Code::Blocks等环境里略有不同。1）有几处会把变量加到所谓的头文件（.h）里。看到这类说明时，意思是你应该把变量放在ofSketch中setup()函数的上方。2）你会想用ofSetWindowShape(int width, int height)（放在setup()中）来控制应用窗口的大小。3）你写的一些应用会把图片保存到电脑上，可以在ofSketch文件夹里、路径ofSketch/data/Projects/YOUR_PROJECT_NAME/bin/data/下找到它们。

用基本图形做画笔

要制作画笔，我们需要先定义一些图形的基本构件。我们可以把2D图形函数分成两类：基本图形和自由形状。基本图形是矩形、圆、三角形和直线；自由形状是多边形和路径。本节我们专注于基本图形。

基本图形

在画任何图形之前，我们需要知道如何在屏幕上指定位置。计算机图形学使用笛卡尔坐标系。还记得数学课上的图1（左）吗？一对数值(x, y)告诉我们自己距离(0, 0)（也就是原点）有多远。计算机图形学基于同一套系统，但有两处不同。第一，(0, 0)是屏幕左上角的像素。第二，y轴是翻转的，正y方向位于原点下方，见图1（中）。

如果把这一套用到我屏幕的左上角（图1右），那正好是我的浏览器。我们可以看到像素，并在新的坐标系里确定它们的位置。左上角的像素是(0, 0)。蓝色日历图标（里面有白色“19”）的左上角像素是(58, 5)。

既然能描述位置了，我们就进入代码。新建一个openFrameworks项目，命名为“BasicShapes”（或者更有想象力的名字）。打开源文件ofApp.cpp，找到draw()函数。加入以下代码：

ofBackground(0);  // 用黑色清屏
ofSetColor(255);  // 把绘制颜色设为白色

// 画一些图形
ofDrawRectangle(50, 50, 100, 100); // 左上角在 (50, 50)，宽 100 x 高 100
ofDrawCircle(250, 100, 50); // 中心在 (250, 100)，半径 50
ofDrawEllipse(400, 100, 80, 100); // 中心在 (400 100)，宽 80 x 高 100
ofDrawTriangle(500, 150, 550, 50, 600, 150); // 三个角：(500, 150)、(550, 50)、(600, 150)
ofDrawLine(700, 50, 700, 150); // 从 (700, 50) 到 (700, 150) 的线段

运行代码后，我们看到黑色背景上的白色图形。成功了！每次draw()函数执行时，会发生三件事。第一，我们用ofBackground(...)画出纯黑背景来清屏。0代表一种灰度颜色，其中0是纯黑，而255是纯白。第二，我们用ofSetColor(...)指定绘制时使用的颜色。可以把这行代码理解为让openFrameworks拿出一支特定颜色的马克笔。我们绘制时就会一直用这个颜色，直到指定另一种颜色。第三，我们用ofDrawRectangle(...)、ofDrawCircle(...)、ofDrawEllipse(...)、ofDrawTriangle(...)和ofDrawLine(...)画出这些基本图形。看看示例里的注释，能更好地理解这些绘图函数的用法。这些函数还有别的用法，好奇的话可以查openFrameworks文档。

ofFill()和ofNoFill()在绘制填充图形和绘制轮廓之间切换。彩色马克笔的类比在这里不太适用，但概念仍然成立。ofFill()让openFrameworks绘制填充图形，直到另有指示。ofNoFill()做同样的事，只不过画的是轮廓。所以只要把draw()函数改成下面这样，我们就能在屏幕上画出两排图形（图2）——一排填充、一排轮廓：

ofFill(); // 如果省掉这行而保留 ofNoFill()，所有图形都会是轮廓！
// 画一些图形（代码略）

ofNoFill(); // 如果省掉这行而保留 ofFill()，所有图形都会是填充的！
// 画一些图形（代码略）

圆和椭圆看起来有点锯齿，可以用ofSetCircleResolution(...)来修正。圆和椭圆是把一系列点用直线连接起来画成的。仔细看图2里的圆，你能分辨出那20条细小的直线段——这就是默认的分辨率。试着把ofSetCircleResolution(50)放进setup()函数里。

构成轮廓的一条条线也会有锯齿。我们可以用一种叫抗锯齿的平滑技术来解决。这一般不用我们操心，因为近年版本的openFrameworks默认就会开启抗锯齿。如果没有开启，只要把ofEnableAntiAliasing()加到setup()里就行。（顺便记一下，为了省算力也可以把它关掉：ofDisableAntiAliasing()。）

从基本图形构建画笔

无聊的部分熬过去了，但既然能画一百万个矩形（图3），为什么只画一个？这基本上就是本节要做的事。我们会做出这样的画笔：每次按下鼠标左键，就撒出一团许多小图形。为了更有趣，还会掺入一些随机性。新建一个openFrameworks项目，叫“ShapeBrush”。

单矩形画笔：使用鼠标

我们先做一个简单的画笔，为后面的画笔打基础：按住鼠标时画一个矩形。开始之前，我们需要知道1）鼠标位置，2）鼠标左键是否按下。

关于1），可以用两个返回int变量的openFrameworks函数：ofGetMouseX()和ofGetMouseY()。我们会在draw()里使用它们。

关于2），可以用ofGetMousePressed(...)来判断鼠标左键是否按下。这个函数要求我们传入一个int，表示想查询的是哪个鼠标键。openFrameworks为此提供了一些“公共常量”：OF_MOUSE_BUTTON_LEFT、OF_MOUSE_BUTTON_MIDDLE和OF_MOUSE_BUTTON_RIGHT。这些公共常量其实就是int变量，不可修改，只要引入了openFrameworks，任何地方都能访问。所以ofGetMousePressed(OF_MOUSE_BUTTON_LEFT)在左键按下时返回true，否则返回false。

现在来加点图形。切到draw()函数，把这些新函数组合起来：

if (ofGetMousePressed(OF_MOUSE_BUTTON_LEFT)) {  // 如果按下了鼠标左键……
    ofSetColor(255);
    ofSetRectMode(OF_RECTMODE_CENTER);
    ofDrawRectangle(ofGetMouseX(), ofGetMouseY(), 50, 50);  // 在鼠标处画一个居中的 50 x 50 矩形
}

ofSetRectMode(...)让我们控制(x, y)在传入ofDrawRectangle(...)时如何用于绘制。默认情况下，它们被解释为左上角（OF_RECTMODE_CORNER）。就我们的目的而言，希望它表示中心（OF_RECTMODE_CENTER），这样矩形就会以鼠标为中心。

编译并运行。按下鼠标左键时，会在鼠标位置画出一个白色矩形……但它马上就消失了。默认情况下，每次draw()调用都会清屏。我们可以用ofSetBackgroundAuto(...)来改变这一点。传入false就关闭了自动清除背景。把下面几行加到setup()里：

ofSetBackgroundAuto(false);

// 我们仍然想在黑色背景上绘制，所以在用画笔画任何东西之前，
// 需要先把背景画出来
ofBackground(0);

第一个画笔完成了！接下来我们加点1）随机性和2）重复，让它更有意思。

随机性能让代码变得阴暗、神秘、难以预测。认识一下ofRandom(...)。它有两种用法：传入两个值ofRandom(float min, float max)，或者传入一个值ofRandom(float max)，此时最小值默认为0。函数返回min与max之间的随机值。我们可以用下面的写法给矩形颜色注入一点随机性（图4）：

float randomColor = ofRandom(50, 255);
ofSetColor(randomColor);  // 排除在黑色背景上看不见的深灰值（0 - 50）

最后给这个单矩形画笔加上按住右键擦除的功能，把以下代码加到draw()函数里：

if (ofGetMousePressed(OF_MOUSE_BUTTON_RIGHT)) {  // 如果按下了鼠标右键……
    ofBackground(0);  // 在屏幕上覆盖一层黑色背景
}

爆裂矩形画笔：生成随机爆发

画笔的基本框架已经有了，但我们不再于draw()里画一个矩形，而是画一簇随机矩形。我们会用for循环生成多个矩形，参数随机选取。哪些东西可以随机化？灰度颜色、宽度和高度都是容易想到的选项；还可以用一个小的正负值，让每个矩形相对鼠标位置偏移。把draw()改成这样：

if (ofGetMousePressed(OF_MOUSE_BUTTON_LEFT)) {  // 如果按下了鼠标左键……
    ofSetRectMode(OF_RECTMODE_CENTER);
    int numRects = 10;
    for (int r=0; r<numRects; r++) {
        ofSetColor(ofRandom(50, 255));
        float width = ofRandom(5, 20);
        float height = ofRandom(5, 20);
        float xOffset = ofRandom(-40, 40);
        float yOffset = ofRandom(-40, 40);
        ofDrawRectangle(ofGetMouseX()+xOffset, ofGetMouseY()+yOffset, width, height);
    }
}

不过！在运行之前，还要在setup()里再加一样东西：ofSetFrameRate(60)。帧率是我们程序的限速，即每秒帧数（fps）。update()和draw()每秒不会运行超过60次。（ofSketch用户——稍后我们会讲到update()。）注意：这是速度的上限，不是速度的下限——我们的代码可以跑得比60fps慢。我们设置帧率，是为了控制会画出多少矩形。如果按住鼠标时每帧画10个矩形，而我们知道draw()每秒最多被调用60次，那么每秒最多会生成600个矩形。

编译，运行。我们得到的是方形分布的随机矩形（图5左）。为什么不是圆形分布（图5右）？因为xOffset和yOffset可以是-40到40之间的任意值，想想当xOffset和yOffset取到最极端的值时会发生什么，也就是(xOffset, yOffset)取(-40, -40)、(40, -40)、(40, 40)和(-40, 40)这几种情况。

如果想在圆内取一个随机点，用角度来思考会更容易。想象我们站在圆心。先随机转一个角度（极角），再随机走一段距离（极径），最后就会落在圆内的随机位置（前提是我们没走太远、没有越过圆的边界）。我们刚刚是用极角和极径来描述一个点，而不是用(x, y)。我们刚刚是在用极坐标思考空间，而不是用笛卡尔坐标。

回到代码。计算偏移量时，我们先随机取一个方向（极角）和一段随机距离（极径），再把它们换算成笛卡尔坐标（见代码），作为xOffset和yOffset。我们在draw()里的循环会是这样：

for (int r=0; r<numRects; r++) {
    ofSetColor(ofRandom(50, 255));
    float width = ofRandom(5, 20);
    float height = ofRandom(5, 20);
    float distance = ofRandom(35);

    // 从极坐标转换为笛卡尔坐标的公式：
    //  x = cos(极角) * (极径)
    //  y = sin(极角) * (极径)

    // 要用 sin() 或 cos()，角度就必须是弧度，
    // 所以可以借助一个 openFrameworks 函数把度
    // 换算成弧度
    float angle = ofRandom(ofDegToRad(360.0));

    float xOffset = cos(angle) * distance;
    float yOffset = sin(angle) * distance;
    ofDrawRectangle(ofGetMouseX()+xOffset, ofGetMouseY()+yOffset, width, height);
}

发光圆形画笔：使用透明度与颜色

和矩形画笔不同，这次我们要把彩色、透明的圆一层层叠起来，做出发光的光晕。先画一个巨大的透明圆，再在它上面画一个略小的透明圆，然后重复、重复、重复。我们可以给ofSetColor(...)加上第二个参数——alpha通道（例如ofSetColor(255, 50)），取值范围从0（完全透明）到255（完全不透明）。

使用alpha之前，需要先开启所谓的“alpha混合”。透明会消耗算力，所以ofEnableAlphaBlending()和ofDisableAlphaBlending()让我们可以随时开关这种混合。这里需要它，所以在setup()中开启。

把if语句里检测鼠标左键的矩形画笔代码注释掉。现在可以开始写圆形画笔了。我们会像之前那样使用angle、distance、xOffset和yOffset这些代码。我们的for循环会从较大的半径开始，逐步把值递减到0。加入以下代码：

int maxRadius = 100;  // 调大可以让画笔更宽
int radiusStepSize = 5;  // 调小会画出更多圆（即画笔更不透明）
int alpha = 3;  // 调大可以让画笔更不透明
int maxOffsetDistance = 100;  // 调大可以让圆的分布范围更大
// 画越来越小的圆，并层层叠加（提高）不透明度
for (int radius=maxRadius; radius>0; radius-=radiusStepSize) {
    float angle = ofRandom(ofDegToRad(360.0));
    float distance = ofRandom(maxOffsetDistance);
    float xOffset = cos(angle) * distance;
    float yOffset = sin(angle) * distance;
    ofSetColor(255, alpha);
    ofDrawCircle(ofGetMouseX()+xOffset, ofGetMouseY()+yOffset, radius);
}

结果大致如图6，像一团发光的光，只是还没有颜色。厌倦了阴郁的灰色调？ofSetColor(...)除了灰度色彩模型，还可以使用红蓝绿（RGB）色彩模型。我们分别指定红、蓝、绿光的强度（0到255），例如ofSetColor(255, 0, 0)表示不透明的红色。也可以再加上alpha，例如ofSetColor(0, 0, 255, 10)表示透明的蓝色。动手把圆形画笔里的ofSetColor(...)改成一种漂亮的橙色：ofSetColor(255, 103, 0, alpha)。

还有另一种使用ofSetColor(...)的方式。认识一下ofColor，这是一个处理颜色的顺手类，可以做花哨的颜色运算（以及别的事）。下面是定义和修改颜色的一些例子：

ofColor myOrange(255, 132, 0); // 定义一个不透明的橙色——用 RGB 指定
ofColor myBlue(0, 0, 255, 50); // 定义一个透明的蓝色——用 RGBA 指定

// 可以这样访问红、绿、蓝和 alpha 通道：
ofColor myGreen(0, 0, 255, 255);
cout << "Red channel:" << myGreen.r << endl;
cout << "Green channel:" << myGreen.g << endl;
cout << "Blue channel:" << myGreen.b << endl;
cout << "Alpha channel:" << myGreen.a << endl;

// 也可以这样设置红、绿、蓝和 alpha 通道：
ofColor myYellow;
myYellow.r = 255;
myYellow.b = 0;
myYellow.g = 255;
myYellow.a = 255;

// 还可以使用 openFrameworks 提供的一些预定义颜色：
ofColor myAqua = ofColor::aqua;
ofColor myPurple = ofColor::plum;
// 完整的颜色列表见：http://openframeworks.cc/documentation/types/ofColor.html

如果我们想让画笔更“火”一点，就可以用橙色和红色之间的随机颜色来绘制。ofColor用所谓的“线性插值”来实现这种“中间态”，具体函数是getLerped(...)。getLerped(...)是ofColor的一个类方法，意思是如果有一个ofColor变量，就可以这样插值：myFirstColor.getLerped(mySecondColor, 0.3)。（关于类和方法的说明，见OOPS!一章。）我们传入两个参数：一个ofColor和一个float值，取值在0.0到1.0之间。函数返回一个新的ofColor，位于指定的两种颜色之间，而float决定新颜色有多接近我们的原色（这里是myFirstColor）。我们可以在draw()里这样用：

ofColor myOrange(255, 132, 0, alpha);
ofColor myRed(255, 6, 0, alpha);
ofColor inBetween = myOrange.getLerped(myRed, ofRandom(1.0));
ofSetColor(inBetween);

星形线条画笔：使用线性映射

那线条呢？我们来做一个画笔，画出从鼠标向外辐射的线，效果类似星号或闪烁的星星（图7）。把圆形画笔注释掉，加入：

int numLines = 30;
int minRadius = 25;
int maxRadius = 125;
for (int i=0; i<numLines; i++) {
    float angle = ofRandom(ofDegToRad(360.0));
    float distance = ofRandom(minRadius, maxRadius);
    float xOffset = cos(angle) * distance;
    float yOffset = sin(angle) * distance;
    float alpha = ofMap(distance, minRadius, maxRadius, 50, 0);  // 让较短的线更不透明
    ofSetColor(255, alpha);
    ofDrawLine(ofGetMouseX(), ofGetMouseY(), ofGetMouseX()+xOffset, ofGetMouseY()+yOffset);
}

我们用alpha做了什么？我们用ofMap(...)做了一次线性插值，类似getLerped(...)。ofMap(...)把一个数值区间映射到另一个区间——好比用麦克风录到的声音“响度”来决定屏幕上图形的颜色。为了得到“闪烁”效果，我们希望最短的线最不透明、较长的线最透明。ofMap(...)把某个区间里的值映射到另一个区间，写法是：ofMap(value, inputMin, inputMax, outputMin, outputMax)。我们告诉它：distance是一个value，位于minRadius和maxRadius之间；并且希望映射成这样——距离为125（maxRadius）时返回alpha值50，距离为25（minRadius）时返回alpha值0。

也可以用下面的写法改变线宽：ofSetLineWidth(ofRandom(1.0, 5.0))，但记住：如果在这个画笔里改了线宽，后面还得回到其他画笔里把线宽设回1.0。

逃逸三角形画笔：向量与旋转

第1节的最后一个画笔：三角形。我们会在鼠标位置周围画一堆朝外的三角形（图8左）。ofDrawTriangle(...)要求我们指定三角形的三个角，这意味着需要计算各个角的旋转，让三角形背离鼠标。有一个新类能让这套数学简单一些：ofVec2f。

我们之前定义点，一直是靠两个单独的变量：x和y。ofVec2f是一个2D向量，就我们的用途而言，可以把它当作2D空间里的一个点。ofVec2f让我们把x和y放进同一个变量（还能做一些顺手的数学运算）：

ofVec2f mousePos(ofGetMouseX(), ofGetMouseY());  // 定义一个新的 ofVec2f

// 可以这样访问 x 和 y 坐标：
cout << "Mouse X: " << mousePos.x << endl;
cout << "Mouse Y: " << mousePos.y << endl;

// 也可以这样修改坐标：
float xOffset = 10.0;
float yOffset = 30.0;
mousePos.x += xOffset;
mousePos.y += yOffset;

// 不过上面这些操作，也可以直接对两个向量做加减来完成
ofVec2f offset(10.0, 30.0);
mousePos += offset;

开始用它来搭三角形画笔。第一步，在鼠标光标处画一个三角形（图8右）。这一点后面会变得重要：我们的三角形从鼠标光标开始，指向右侧。把线条画笔注释掉，加入：

ofVec2f mousePos(ofGetMouseX(), ofGetMouseY());

// 在原点 (0,0) 定义一个指向右侧的三角形
ofVec2f p1(0, 25.0);
ofVec2f p2(100, 0);
ofVec2f p3(0, -25.0);

// 把三角形平移到鼠标位置
p1 += mousePos;
p2 += mousePos;
p3 += mousePos;

ofSetColor(255, 50);
ofDrawTriangle(p1, p2, p3);

运行看看效果。我们可以用ofVec2f的类方法rotate(...)来加旋转，写法如：myPoint.rotate(45.0)，其中myPoint会绕原点(0, 0)旋转45.0度。回到代码，在把三角形平移到鼠标位置之前加上这段：

// 让三角形的各个点绕原点旋转
float rotation = ofRandom(360); // rotate 函数用的是度！
p1.rotate(rotation);
p2.rotate(rotation);
p3.rotate(rotation);

画笔的效果大致如图8（左）。如果把这段旋转代码移到平移三角形位置之后，代码就没那么好用了，因为rotate(...)假定我们想绕原点旋转这个点。（文档里还介绍了另一种用法：rotate(...)可以绕任意点旋转。）最后一步，把之前画多个偏移图形的做法整合进来：

ofVec2f mousePos(ofGetMouseX(), ofGetMouseY());

int numTriangles = 10;
int minOffset = 5;
int maxOffset = 70;
int alpha = 150;
for (int t=0; t<numTriangles; t++) {
    float offsetDistance = ofRandom(minOffset, maxOffset);

    // 在原点 (0,0) 定义一个指向右侧的三角形（代码略）
    // 三角形尺寸比上一个画笔稍小——见源码

    // 旋转三角形（代码略）

    ofVec2f triangleOffset(offsetDistance, 0.0);
    triangleOffset.rotate(rotation);

    p1 += mousePos + triangleOffset;
    p2 += mousePos + triangleOffset;
    p3 += mousePos + triangleOffset;

    ofSetColor(255, alpha);
    ofDrawTriangle(p1, p2, p3);
}

现在我们用ofVec2f来表示偏移。我们从一个指向右侧的向量开始，这个方向也正是三角形初始朝向。当我们对两者施加相同的旋转，它们就保持同步（即都背离鼠标）。我们可以用triangleOffset.rotate(rotation+90)让它们失去同步，于是得到一团旋转的三角形。之后，我们还可以再次用ofRandom(...)和getLerped(...)加上颜色（图9），或者调整填充和线宽。

用自由形状做画笔

上一节我们是直接在屏幕上画。那时图形（笔触）以像素形式存储，因此用的是位图图形。正因如此，很难单独挑出、移动或擦除某一笔。这也意味着我们无法以别的分辨率重新渲染图形。相比之下，矢量图形把图形存储为一组几何对象，而不是像素值。这些对象在我们把它们“放”到屏幕之后，仍然可以被修改（擦除、移动、缩放等）。

本节我们会在openFrameworks里用自定义（“自由形状”）图形，做出一种矢量图形。我们会用一些结构（ofPolyline和vector<ofPolyline>），它们让我们能存储并绘制鼠标在屏幕上走过的路径。然后我们会拿这些路径做文章，做出不只是描摹光标轨迹的画笔。

polyline基础

新建一个项目，叫“Polylines”，然后和ofPolyline打个招呼。ofPolyline是一种数据结构，可以存储一系列有顺序的点，再把它们连接起来画成线。我们来看代码。在头文件里（准确说是在“ofApp.h”的“class ofApp”里）定义三个ofPolylines：

ofPolyline straightSegmentPolyline;
ofPolyline curvedSegmentPolyline;
ofPolyline closedShapePolyline;

我们可以在ofPolylines里填入点，代码写在setup()中：

straightSegmentPolyline.addVertex(100, 100);  // 添加一个新点：(100, 100)
straightSegmentPolyline.addVertex(150, 150);  // 添加一个新点：(150, 150)
straightSegmentPolyline.addVertex(200, 100);  // 以此类推……
straightSegmentPolyline.addVertex(250, 150);
straightSegmentPolyline.addVertex(300, 100);

curvedSegmentPolyline.curveTo(350, 100);  // 这些曲线是 Catmull-Rom 样条
curvedSegmentPolyline.curveTo(350, 100);  // 为控制点而必须重复的点
curvedSegmentPolyline.curveTo(400, 150);
curvedSegmentPolyline.curveTo(450, 100);
curvedSegmentPolyline.curveTo(500, 150);
curvedSegmentPolyline.curveTo(550, 100);
curvedSegmentPolyline.curveTo(550, 100);  // 为控制点而必须重复的点

closedShapePolyline.addVertex(600, 125);
closedShapePolyline.addVertex(700, 100);
closedShapePolyline.addVertex(800, 125);
closedShapePolyline.addVertex(700, 150);
closedShapePolyline.close();  // 连接第一个和最后一个顶点

现在可以在draw()函数里绘制polyline了：

ofBackground(0);
ofSetLineWidth(2.0);  // 线宽对 polyline 同样生效
ofSetColor(255,100,0);
straightSegmentPolyline.draw();  // 这就是绘制 polyline 的方式
curvedSegmentPolyline.draw();  // 挺简单吧？
closedShapePolyline.draw();

我们创建了三种不同类型的polyline（图11）。straightSegmentPolyline由一系列用直线连接的点组成。curvedSegmentPolyline用的是同样的点，但用曲线连接。生成的曲线是Catmull-Rom样条，它用四个点定义一段曲线：两个定义起点和终点，另两个控制点决定弯曲程度。正因为这些控制点，我们才需要把第一个和最后一个顶点各重复一次。最后，closedShapePolyline使用闭合的直线段，把第一个和最后一个顶点连接起来。

这种画法（相对于位图图形）的好处是polyline可修改。我们可以随时轻松地移动、添加、删除、缩放顶点。

Polyline笔：跟踪鼠标

我们用polyline来画笔触。新建项目“PolylineBrush”。按住鼠标左键时，我们会创建一个ofPolyline，并不断把它延伸到当前鼠标位置。我们会用一个bool来记录左键是否按下。如果按着，就把鼠标位置加到polyline里，但不是每一个鼠标位置都加，而是只加那些已经距离polyline最后一个点足够远的鼠标位置。

进入代码。在头文件里定义四个变量：

ofPolyline currentPolyline;
bool leftMouseButtonPressed;
ofVec2f lastPoint;
float minDistance;

初始化minDistance和leftMouseButtonPressed，都在setup()中完成：

minDistance = 10;
leftMouseButtonPressed = false;

接下来我们要用两个新函数——mousePressed(int x, int y, int button)和mouseReleased(int x, int y, int button)。它们默认已经内置在应用里。它们是事件处理函数：每次按下鼠标键，你写进mousePressed(...)的代码就会被调用。要注意的是，mousePressed(...)只在鼠标键刚按下时被调用。不管我们按住多久，这个函数都只调用一次。mouseReleased(...)同理。

这些函数带有几个变量x、y和button，让你能了解刚刚发生的这次鼠标事件的一些细节。x和y是光标在屏幕上的坐标，而button是一个int，代表被按下或松开的那个鼠标键。还记得OF_MOUSE_BUTTON_LEFT和OF_MOUSE_BUTTON_RIGHT这样的公共常量吗？要判断button是哪个键，我们就拿它和这些常量比较。

回到代码。如果你用的是project generator，这些鼠标函数就在.cpp文件里。如果你用的是ofSketch，可能看不到这些函数，但加上很容易。参考本节的ofSketch文件。在mousePressed(...)里，我们要开始一条polyline：

if (button == OF_MOUSE_BUTTON_LEFT) {
    leftMouseButtonPressed = true;
    currentPolyline.curveTo(x, y);  // 记住 x 和 y 是鼠标的位置
    currentPolyline.curveTo(x, y);  // 为第一个控制点而必须重复
    lastPoint.set(x, y);  // 一行代码设置 ofVec2f 的 x 和 y
}

在mouseReleased(...)里结束这条polyline：

if (button == OF_MOUSE_BUTTON_LEFT) {
    leftMouseButtonPressed = false;
    currentPolyline.curveTo(x, y); // 为最后一个控制点而必须重复
    currentPolyline.clear();  // 清除顶点，以便开始新的笔触
}

现在我们转到update()函数。对ofSketch用户来说，这是另一个默认函数，你的sketch里可能看不到它。它每帧被调用一次，专门用来做与绘制无关的事。加上它很容易——参考本节的ofSketch文件。

我们在update()里给polyline加点：

if (leftMouseButtonPressed) {
    ofPoint mousePos(ofGetMouseX(), ofGetMouseY());
    if (lastPoint.distance(mousePos) >= minDistance) {
        // a.distance(b) 计算点 a 与点 b 之间的欧氏距离，也就是
        // 两点之间直线段的长度。
        currentPolyline.curveTo(mousePos);
        lastPoint = mousePos;
    }
}

注意：只有当鼠标离开上次加入polyline的点超过一定阈值（minDistance）之后，才会加点。这里用的是distance(...)方法，属于ofVec2f。

剩下的就是在draw()里加上绘制polyline的代码，这样就有了一个基础的曲线polyline绘图程序。但我们还没法保存多条polyline，所以效果类似于Etch A Sketch玩具。我们只能画一条连续的线。为了能画多条互不相连的线，我们要请出vector。它和前面讲过的of2Vecf语境下的那类向量不是一回事。如果没接触过vector，可以看看站上的stl::vector基础教程。

在头文件里定义vector <ofPolyline> polylines。我们会用它保存polyline笔触。每画完一笔，就把这条polyline加进vector。所以，在mouseReleased(...)里的if语句中、currentPolyline.clear()之前，加上polylines.push_back(currentPolyline)。然后就可以这样绘制polyline：

ofBackground(0);
ofSetColor(255);  // 已保存的 polyline 用白色
for (int i=0; i<polylines.size(); i++) {
    ofPolyline polyline = polylines[i];
    polyline.draw();
}
ofSetColor(255,100,0);  // 正在画的 polyline 用橙色
currentPolyline.draw();

这样就有了一个简单的、类似钢笔的画笔，能跟踪鼠标，还能画出一个傻乎乎的笑脸（图12）。

Polyline画笔：点、法线与切线

基础绘制已经有了，现在来玩polyline的渲染方式。我们会画点、法线和切线。法线和切线是什么，稍后再说。先在我们polyline的顶点上画点（圆）。在for循环中、draw()里（在polyline.draw()之后）加上这段：

vector<glm::vec3> vertices = polyline.getVertices();
for (int vertexIndex=0; vertexIndex<vertices.size(); vertexIndex++) {
    glm::vec3 vertex = vertices[vertexIndex];  // glm::vec3 类似 ofVec2f，但多了第三个维度 z
    ofDrawCircle(vertex, 5);
}

getVertices()返回一个vector，其中包含glm::vec3对象——它们就是polyline的顶点。这基本上就是ofPolyline的本质：一组有序的glm::vec3对象（外加一些数学运算）。我们可以遍历vector的下标，取出每个顶点的位置，用它们来画圆。

注意：在较新版本中，openFrameworks已经不再沿用ofVec3f，转而使用新的内部数学库GLM。更多内容见这里。本章写于这次转变之前，某些地方仍在使用旧式的ofVec3f和ofVec2f。转变之后有些方法名变了，但在大多数能看到ofVec3f或ofVec2f的地方，都可以改用glm::vec3或glm::vec2。getVertices()就是默认必须使用新语法的位置之一。

运行后会发生什么？白线看起来变粗了。因为我们的polyline里塞满了顶点！每次调用curveTo(...)方法，都会额外创建20个顶点（默认值）。它们让曲线看起来更平滑。添加的顶点数量可用一个可选参数调整，即curveResolution，它在curveTo(...)里。我们不需要那么多顶点，但与其调低curveResolution，不如利用simplify(...)。

simplify(...)是一个方法，会删除polyline里的“重复”点。我们传入一个参数：tolerance，取值在0.0到1.0之间。tolerance描述的是点之间必须有多不相似，才算“足够独特”、不会被删除。tolerance越高，删掉的点越多。所以，在把polyline存进polylines这个vector之前，可以先简化它。在mouseReleased(...)里的if语句中（polylines.push_back(currentPolyline)之前），加上：currentPolyline.simplify(0.75)。现在应该能看到图13（左）那样的效果。

我们还可以用getPointAtPercent(...)沿polyline采样点，它接受一个float，取值在0.0到1.0之间，返回一个ofVec3f。在draw()函数里，把在每个顶点画圆的代码注释掉。在下面加上：

    for (int p=0; p<100; p+=10) {
        ofVec3f point = polyline.getPointAtPercent(p/100.0);  // 返回 polyline 上按百分比取到的点
        ofDrawCircle(point, 5);
    }

现在我们有了等距分布的点（图13右）。（注意线的末端没有画圆。）接下来试着做一种线宽会变化的笔触。为此需要用到法向量。图14展示了一些polyline上画出的法线——它们指向与polyline垂直的方向。想象在polyline上的每个点都画一条法线，就像图15那样。这就是给画笔增加“粗细”的一种办法。我们可以把draw()里画圆的代码注释掉，换成下面这几行：

    vector<glm::vec3> vertices = polyline.getVertices();
    float normalLength = 50;
    for (int vertexIndex=0; vertexIndex<vertices.size(); vertexIndex++) {
        glm::vec3 vertex = vertices[vertexIndex];  // 取出这个顶点
        glm::vec3 normal = polyline.getNormalAtIndex(vertexIndex) * normalLength;  // 缩放法线
        ofDrawLine(vertex-normal/2, vertex+normal/2);  // 让缩放后的法线以顶点为中心
    }

我们取到了ofPolyline中的所有顶点。但这里还用了getNormalAtIndex，它接受一个索引，返回一个glm::vec3，表示该索引处顶点的法向量。我们把这个法线缩放，然后以顶点为中心画出来。于是得到图14（左）那样的效果。不过我们也可以对法线进行采样，用的函数是getNormalAtIndexInterpolated(...)。所以把刚才的代码注释掉，试着沿polyline均匀采样法线：

float normalLength = 50;
for (int p=0; p<100; p+=10) {
    ofVec3f point = polyline.getPointAtPercent(p/100.0);
    float floatIndex = polyline.getIndexAtPercent(p/100.0);
    ofVec3f normal = polyline.getNormalAtIndexInterpolated(floatIndex) * normalLength;
    ofDrawLine(point-normal/2, point+normal/2);
}

我们又可以靠百分比拿到等距的点，但getNormalAtIndexInterpolated(...)要的是索引。具体说，它要的是一个floatIndex，这意味着我们可以传入1.5，polyline就会返回一条位于索引1与索引2正中位置的法线。所以需要把百分比p/100.0换算成floatIndex，用的是getIndexAtPercent(...)。做完这一步，就会得到图14（右）那样的效果。

现在可以把绘制中的法线数量加大。把循环的增量从p+=10改成p+=1，循环条件从p<100改成p<500，并把p/100.0这几行代码改成p/500.0。也许还想用半透明白来画这些法线，那就在循环前加上ofSetColor(255,100)。最后我们就能画出丝带般的线条，如图15。

我们刚给polyline加了点厚度。现在插一句切线——法线的“反面”。这些奇妙的东西与我们刚画的法线垂直。所以如果沿一条笔直的线画切线，基本上什么也看不到。有趣的部分出现在曲线上，我们来看看是什么效果。和之前一样：把上一段代码注释掉，加入下面的代码：

vector<glm::vec3> vertices = polyline.getVertices();
float tangentLength = 80;
for (int vertexIndex=0; vertexIndex<vertices.size(); vertexIndex++) {
    glm::vec3 vertex = vertices[vertexIndex];
    glm::vec3 tangent = polyline.getTangentAtIndex(vertexIndex) * tangentLength;
    ofDrawLine(vertex-tangent/2, vertex+tangent/2);
}

这段代码看着应该很眼熟，只有getTangentAtIndex(...)不同：它相当于getNormalAtIndex(...)，只不过用于切线。对于直线和弯曲不大的线，看不出什么；但弯曲剧烈的线会把切线显现出来，见图16（左）。

你肯定猜得到下一步……在等距的位置画一大堆切线（图16右）！这比听起来更有意思。getTangentAtIndexInterpolated(...)的用法和getNormalAtIndexInterpolated(...)一样。还是老规矩，把上一段代码注释掉，加入下面的代码：

ofSetColor(255, 50);
float tangentLength = 300;
for (int p=0; p<500; p+=1) {
    ofVec3f point = polyline.getPointAtPercent(p/500.0);
    float floatIndex = polyline.getIndexAtPercent(p/500.0);
    ofVec3f tangent = polyline.getTangentAtIndexInterpolated(floatIndex) * tangentLength;
    ofDrawLine(point-tangent/2, point+tangent/2);
}

矢量图形：保存快照（第2部分）

还记得我们用基本图形画笔画的画是怎么保存的吗——截屏。其实我们也可以把画保存成PDF。PDF把图形存储为一系列几何对象，而不是一系列像素值。所以，如果把polyline渲染成PDF，就能在矢量图形编辑器（比如Inkscape或Adobe Illustrator）里打开，用各种方式修改polyline。例如图17，我给polyline上了色、做了模糊，做出发光的效果。

有了PDF，还可以把polyline放大，做成巨幅的高分辨率印刷品。

要做到这些，我们需要用ofBeginSaveScreenAsPDF(...)和ofEndSaveScreenAsPDF()。调用ofBeginSaveScreenAsPDF(...)之后，后续的绘图命令都会输出到PDF，而不是画到屏幕上。ofBeginSaveScreenAsPDF(...)需要一个必填参数，即一个string，里面是想要保存的PDF文件名。（除非指定别的路径，PDF会保存到./bin/data/。）当我们调用ofEndSaveScreenAsPDF()时，PDF被保存，绘图命令重新输出到屏幕。

我们用上一节的polyline画笔代码来保存PDF。之前保存截图的做法是把ofSaveScreen()放进keyPressed(...)里。这里不能这么做，因为ofBeginSaveScreenAsPDF(...)和ofEndSaveScreenAsPDF()必须分别放在绘图代码的前面和后面。所以我们借助一个bool变量。在头文件（.h）里加上bool isSavingPDF，然后把源文件（.cpp）改成这样：

void ofApp::setup(){
    // 为清晰起见，setup 代码略……

    isSavingPDF = false;
}

void ofApp::draw(){
    // 如果 isSavingPDF 为 true（也就是按下了 s 键），那么
    // 位于 ofBeginSaveScreenAsPDF(...) 与 ofEndSaveScreenAsPDF() 之间的
    // 内容都会被保存到文件。
    if (isSavingPDF) {
        ofBeginSaveScreenAsPDF("savedScreenshot_"+ofGetTimestampString()+".pdf");
    }

    // 为清晰起见，绘图代码略……

    // 结束 PDF 保存，并把 isSavingPDF 标志重置为 false
    // 结束 PDF 会告诉 openFrameworks 恢复向屏幕绘制。
    if (isSavingPDF) {
        ofEndSaveScreenAsPDF();
        isSavingPDF = false;
    }
}

void ofApp::keyPressed(int key){
    if (key == 's') {
        // isSavingPDF 是一个标志，用来表示是否需要保存 PDF
        isSavingPDF = true;
    }
}

移动世界

我们做画笔做了很久，换个话题吧：移动世界。所谓世界，其实只是坐标系（不过那样说听起来更激动人心）。

每当我们调用绘图函数，比如ofDrawRectangle(...)，我们会传入一个x和y位置，告诉函数把图形画在哪里。我们知道(0,0)是窗口左上角的像素，正x方向向右穿过窗口，正y方向沿窗口向下（回想图1）。接下来我们要打破这个既有认知。

想象面前有一张方格纸。要在(5, 10)处画一个宽5格、高2格的黑色矩形，你会怎么做？大概会拿起黑笔，把手移到方格纸上的(5, 10)，然后开始涂格子。这很正常，但我们也可以让握笔的手不动，把纸向左移5格、向下移10格，然后再涂格子。听起来奇怪吧？其实这是个很有力的概念。在openFrameworks里，我们可以用ofTranslate(...)这样移动坐标系，还可以用ofRotate(...)和ofScale(...)旋转和缩放。我们先从平移开始，用火柴人铺满屏幕，然后再旋转、缩放，做出螺旋矩形。

平移：火柴人一家

ofTranslate先来。ofTranslate(...)接受x、y和一个可选的z参数，然后按这些值平移坐标系。为什么要这样做？新建一个项目，把下面的代码加到源文件（.cpp）的draw()函数里：

// 画火柴人一家
ofDrawCircle(30, 30, 30);
ofDrawRectangle(5, 70, 50, 100);
ofDrawCircle(95, 30, 30);
ofDrawRectangle(70, 70, 50, 100);
ofDrawCircle(45, 90, 15);
ofDrawRectangle(30, 110, 30, 60);
ofDrawCircle(80, 90, 15);
ofDrawRectangle(65, 110, 30, 60);

画一个白色背景，给图形上色。最后应该得到类似图18最左边部分的效果。

假如把图形的位置都算好之后，我们需要把它们画在屏幕上另一个位置，或者画出一整排副本呢？我们可以手动改掉所有位置，也可以用ofTranslate(...)移动坐标系，让坐标保持不变：

// 循环画出一排
for (int cols=0; cols<4; cols++) {

    // 画火柴人一家（代码略）

    ofTranslate(150, 0);
}

于是我们把原来的图形包进一个循环，配合ofTranslate(150, 0)，每执行一次就把坐标系向左移150像素。最后得到图18（左起第二个）。或者差不多是那样——图里的颜色我随机化了，每个家庭都不一样，对吧？

如果想摆出一整片家庭网格，就会遇到问题。画完第一排家庭后，坐标系已经左移了很远。为了开始画第二排而把坐标系向上移，结果会沿对角线一路画出屏幕。看起来就像图18（左起第三个）。

所以我们需要用ofPushMatrix()和ofPopMatrix()来重置坐标系。ofPushMatrix()保存当前坐标系，ofPopMatrix()则回到上一次保存的坐标系。这两个函数名字里有matrix，是因为openFrameworks把我们所有的旋转、平移、缩放合成为一个矩阵来保存。于是我们可以这样用：

    for (int rows=0; rows<10; rows++) {
        ofPushMatrix(); // 在水平平移之前，先保存当前坐标系

        // 为了让代码更易读，push 与 pop matrix 之间的代码通常要缩进

        // 循环画出一排（代码略）

        ofPopMatrix(); // 回到水平平移之前的坐标系
        ofTranslate(0, 200);
    }

这样就应该得到一片网格。见图18右。（我用了ofScale把许多家庭挤进一张图里。）或者如果你讨厌网格，我们也可以用随机的旋转和平移弄出一群乱糟糟的人，见图19。

旋转与缩放：螺旋矩形

接下来是ofScale(...)和ofRotate(...)！我们新建一个项目，通过旋转和缩放矩形做出图20那样的效果。

在了解ofRotate(...)之前，我们没法用ofDrawRectangle(...)画出旋转过的矩形。ofRotate(...)接受一个角度（单位为度），绕当前原点旋转坐标系。我们来试着画一个旋转矩形：

ofBackground(255);
ofPushMatrix();
    // 原来的矩形，蓝色
    ofSetColor(0, 0, 255);
    ofDrawRectangle(500, 200, 200, 200);

    // 旋转后的矩形，红色
    ofRotate(45);
    ofSetColor(255, 0, 0);
    ofDrawRectangle(500, 200, 200, 200);
ofPopMatrix();

嗯，不太对（图21左）。ofRotate(...)是绕当前原点即屏幕左上角旋转的。要在原地旋转，需要先用ofTranslate(...)把坐标系原点移到矩形上、再旋转。加上ofTranslate(500, 200)再旋转（图21，左起第二个）。现在我们是绕矩形的左上角旋转。要让矩形绕自身中心旋转，最简单的办法是用ofSetRectMode(OF_RECTMODE_CENTER)，把中心画在(500, 200)。这样做之后，终于得到图21（左起第三个）。

push、translate、rotate、pop——没问题。只剩ofScale(...)。它接受两个参数：x和y方向上想要的缩放（以及可选的z缩放）。把缩放应用到矩形上：

ofSetRectMode(OF_RECTMODE_CENTER);
ofBackground(255);

ofPushMatrix();
    // 原来的矩形，蓝色
    ofSetColor(0, 0, 255);
    ofDrawRectangle(500, 200, 200, 200);

    // 缩小后的矩形，红色
    ofTranslate(500, 200);
    ofScale(0.5, 0.5);  // 我们只在 x 和 y 方向上工作，所以 z 缩放保持默认值 (1.0)
    ofSetColor(255, 0, 0);
    ofDrawRectangle(0, 0, 200, 200);
ofPopMatrix();

我们会遇到和旋转、居中时一样的问题。解决办法也一样：先平移再缩放，并使用OF_RECTMODE_CENTER。缩放示例见图21（右）。

现在可以做出迷幻的矩形了。新建一个项目。思路很简单：在屏幕中心画一个矩形，缩放、旋转，再画一个矩形，重复、重复。把下面的代码加到draw()函数里：

ofBackground(255);

ofSetRectMode(OF_RECTMODE_CENTER);
ofSetColor(0);
ofNoFill();
ofPushMatrix();
    ofTranslate(ofGetWidth()/2, ofGetHeight()/2);  // 平移到屏幕中心
    for (int i=0; i<100; i++) {
        ofScale(1.1, 1.1);
        ofRotate(5);
        ofDrawRectangle(0, 0, 50, 50);
    }
ofPopMatrix();

就这样（图20）。我们可以玩缩放、旋转、矩形大小等等。三行代码就能让矩形活起来，随时间卷起又展开。把下面这几行放到ofRotate(5)的位置：

// 噪声这个主题足以在书里单独占一节
// 想看清楚可以先读 "The Nature of Code" 的 1.6 节
// http://natureofcode.com/book/introduction/
float time = ofGetElapsedTimef();
float timeScale = 0.5;
float noise = ofSignedNoise(time * timeScale) * 20.0;
ofRotate(noise);

接下来，如果关掉自动清屏、在每次绘制前先把屏幕部分擦掉，就能在旋转时产生视觉拖影（“拖尾效果”）。为此要在setup()里加几样东西：

ofSetBackgroundAuto(false);
ofEnableAlphaBlending(); // 记住：如果要用透明度，就得让 openFrameworks 知道
ofBackground(255);

把ofBackground(255)从draw()函数里删掉。然后，把它加到draw()函数的开头：

float clearAlpha = 100;
ofSetColor(255, clearAlpha);
ofSetRectMode(OF_RECTMODE_CORNER);
ofFill();
ofDrawRectangle(0, 0, ofGetWidth(), ofGetHeight());  // ofBackground 不支持 alpha，所以画一个透明矩形

挺催眠的吧？把clearAlpha调大，拖影就会减弱。把clearAlpha调小，拖影就会增强。

现在我们有两个参数能大幅改变螺旋的视觉体验，具体是：timeScale（噪声的）和clearAlpha（拖尾效果的）。我们不必手动改代码里的数值，可以在运行时用鼠标位置分别控制这两个值。水平位置调整clearAlpha，垂直位置调整timeScale。这种对参数设置的探索非常重要（尤其是在做生成式图形时），而如果只有一两个参数要试，用鼠标就很方便。

mouseMoved(int x, int y )会在鼠标每次移动时执行（限于我们这个应用内）。我们可以用这个函数来改参数。和mousePressed(...)一样，如果你用的是project generator，会在这个.cpp文件里和鼠标函数放在一起。如果你用的是ofSketch，可能看不到这个函数，但加上很容易。参考本节的ofSketch文件。

使用这个函数之前，需要让参数具有全局作用域。把局部定义timeScale和clearAlpha的代码从draw()里删掉，加到头文件。在setup()中分别初始化为100和0.5。然后把这些加进mouseMoved(...)：

clearAlpha = ofMap(x, 0, ofGetWidth(), 0, 255);  // 鼠标从左向右移动时，clearAlpha 从 0 变到 255
timeScale = ofMap(y, 0, ofGetHeight(), 0, 1);  // 鼠标从上向下移动时，timeScale 从 0 变到 1

最后一个扩展。我们可以让背景色和矩形颜色慢慢对调，把这行加到draw()的顶部：

ofColor darkColor(0,0,0,255);  // 不透明黑
ofColor lightColor(255,255,255,255);  // 不透明白
float time = ofGetElapsedTimef();  // 时间，单位为秒
float percent = ofMap(cos(time/2.0), -1, 1, 0, 1);  // 生成一个在 0 到 1 之间振荡的值
ofColor bgColor = darkColor;  // 用于清屏的透明矩形所用的颜色
bgColor.lerp(lightColor, percent);  // 这会“就地”修改颜色，详见文档页面
bgColor.a = clearAlpha;  // 我们初始的颜色是不透明的，但矩形需要透明
ofColor fgColor = lightColor;  // 矩形轮廓所用的颜色
fgColor.lerp(darkColor, percent);  // 就地修改颜色

现在把bgColor用在我们画在屏幕上的透明矩形上，把fgColor用在矩形轮廓上，就能得到图22。

  1. Pass in a third parameter, `z`, into `ofTranslate(...)` and `ofScale(...)` or rotate around the x and y axes with `ofRotate(...)`.

If you are using Windows, like me, that won't work for you, so try screen capture software (like fraps) or saving out a series of images using `ofSaveScreen(...)` and using them to create a GIF or movie with your preferred tools (Photoshop, [ffmpeg](https://ffmpeg.org/), [ImageMagick](http://imagemagick.org/) etc.)
