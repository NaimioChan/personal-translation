图像处理与计算机视觉

作者 Golan Levin
编辑 Brannon Dorsey

本章介绍在 openFrameworks 中操作和分析图像的一些基本技术。由于不可能全面覆盖这一领域，我们把讨论限定在图像与计算机内存的关系上，并完整走一遍背景减除的例子——这是在视频中检测人物的一种常用操作。本章不是计算机视觉的全面指南；关于这一点，我们向你推荐 Richard Szeliski 的 Computer Vision: Algorithms and Applications 或 Gary Bradski 的 Learning OpenCV 等优秀资源。

我们从“零开始”介绍这个主题，要学的东西很多，所以在动手之前，值得先确认一下是否已经有现成的工具恰好能做你想做的事。第一节会列出几个免费工具，它们把交互艺术与设计领域特别流行的一些视觉工作流整洁地封装了起来。

也许真有银弹

计算机视觉让你能够对图像、视频和摄像头画面中正在发生的事情做出判断。自己写视觉软件很有趣（也极具教育意义），但并不总是必须自己实现这些技术。许多最常见的计算机视觉工作流已经被封装成应用，它们能检测你想要的东西，并通过 OSC 把结果发送给你的 openFrameworks 应用！在深入本章之前，先想一想是否可以用这些省时的视觉工具之一搭一个原型。

TSPS（左）和 Community Core Vision（右）是功能丰富的工具包，用于完成交互装置中常见的计算机视觉任务。它们通过 OSC 发送分析结果的摘要，OSC 是媒体艺术中广泛使用的一种信号协议。

  • Toolkit for Sensing People in Spaces (TSPS)：用于在视频中跟踪人体的强大工具包。
  • Community Core Vision：另一个功能齐全的工具包，适用于多种跟踪任务。
  • FaceOSC：一个在视频中跟踪人脸（以及眼睛、鼻子等面部部件）并通过 OSC 发送这些数据的应用。
  • Reactivision TUIO：一个使用基准标记（fiducial marker）跟踪物体位置和朝向，并通过 OSC 发送这些数据的系统。
  • EyeOSC（.zip）：一个实验性的、基于摄像头的眼动追踪器，通过 OSC 发送观看者的注视点。
  • Synapse for Kinect：一个基于 Kinect 的骨骼跟踪器，带 OSC。
  • DesignIO kinectArmTracker：一个轻量的 OSC 应用，用 Kinect 跟踪手臂动作。
  • OCR-OSC 一个轻量的工具包，用于对视频流执行光学字符识别（OCR）。

本书游戏设计一章很好地概述了如何创建 openFrameworks 应用，来使用这类工具生成的 OSC 消息。当然，如果这些工具做不到你需要的，那就该开始读读……

图像处理的预备知识

数字图像的采集与数据结构

本章介绍操作栅格图像（并从中提取某些信息）的技术。这类图像有时也称为位图图像或像素图图像，不过我们统一用通用术语图像来指代任何由数字组成的数组（或缓冲区），这些数字表示一个矩形像素网格（“图像元素”）的颜色值。在 openFrameworks 中，这类缓冲区有多种形态，并被放在各种各样的便捷容器对象中使用（和管理），我们后面会看到。

加载与显示图像

图像处理始于，呃，一张图像。幸运的是，在 oF 中加载和显示图像非常简单。先从这张小小的、低分辨率（12x16 像素）的 Abraham Lincoln 灰度肖像开始：

下面是一个加载和显示图像的简单应用，与 oF 示例集中的 imageLoaderExample 非常相似。我们程序的头文件 ofApp.h 声明了一个 ofImage 对象的实例 myImage：

// 例 1：加载并显示一张图像。
// 这是 ofApp.h

#pragma once
#include "ofMain.h"

class ofApp : public ofBaseApp{
	public:
		void setup();
		void draw();
		
		// 在头文件（.h）里，我们声明一个 ofImage：
		ofImage myImage;
};

下面是完整的 ofApp.cpp 文件。Lincoln 图像从硬盘加载（一次，在 setup() 函数中），然后我们显示它（每秒多次，在 draw() 函数中）。从传给 loadImage() 函数的文件路径可以看出，程序假定图像 lincoln.png 位于与可执行文件同级的、名为 “data” 的目录中：

// 例 1：加载并显示一张图像。
// 这是 ofApp.cpp

#include "ofApp.h"

void ofApp::setup(){
	// 我们从 “data” 文件夹加载一张图像到 ofImage 中：
	myImage.load("lincoln.png");
	myImage.setImageType(OF_IMAGE_GRAYSCALE);
}

void ofApp::draw(){
	ofBackground(255);
	ofSetColor(255);

	// 我们取出 ofImage 的尺寸，并按 10 倍放大显示。
	int imgWidth = myImage.getWidth();
	int imgHeight = myImage.getHeight();
	myImage.draw(10, 10, imgWidth * 10, imgHeight * 10);
}

编译并运行上面的程序会显示下面的画布：这张（非常小的！）图像被放大 10 倍，其左上角被定位到像素位置 (10,10)。图像的定位和缩放由 myImage.draw() 命令完成。注意图像看起来“模糊”，因为默认情况下 openFrameworks 在显示放大图像时使用线性插值。

如果你是刚在 oF 中处理图像，有一点值得指出：尽可能避免在 draw() 或 update() 函数中加载图像。为什么呢？从磁盘读取数据是你能让计算机做的最慢的事情之一。很多情况下，你只需在程序首次初始化时（setup() 中）把所有需要的图像加载一次。相反，如果你在 draw() 循环里反复加载图像——同一张图像，一遍又一遍，每秒 60 次——那是在损害应用的性能，甚至可能危及你的硬盘。

图像（还）从哪来

在 openFrameworks 中，栅格图像可以来自多种来源，包括（但不限于）：

  • 图像文件（以 .JPEG、.PNG、.TIFF 或 .GIF 等常用格式存储），从硬盘加载并解压到 ofImage 中
  • 来自摄像头或其他摄像机的实时图像流（使用 ofVideoGrabber）
  • 从数字视频文件加载的帧序列（使用 ofVideoPlayer）
  • 从屏幕上已经显示的内容中抓取的像素缓冲区，用 ofImage::grabScreen() 捕获
  • 生成的计算机图形渲染结果，或许来自 ofFBO，或存放在 ofPixels 或 ofTexture 对象中
  • 来自更专业的摄像机的实时视频，例如 1394b Firewire 摄像机（通过 ofxLibdc）、网络以太网摄像机（通过 ofxIpCamera）、Canon 单反（使用 ofxCanonEOS），或借助 ofxQTKitVideoGrabber、ofxRPiCameraVideoGrabber 等各种社区贡献的 addon。
  • 或者更奇特的，深度图像，其中像素值表示距离而不是颜色。深度图像可以用特殊摄像机（例如通过 ofxKinect addon 使用 Microsoft Kinect）从真实场景捕获，也可以用（比如）ofFBO::getDepthTexture() 从 CGI 场景中提取。

用 Microsoft Kinect 同时捕获的一张深度图像（左）和对应的 RGB 彩色图像（右）。在深度图像中，像素的亮度表示它到摄像机的距离。（注意这两张以原始状态呈现的图像尚未相互“标定”，也就是说，像素的颜色与其对应深度之间还没有精确的逐像素对应关系。）

顺带一提，oF 让直接从互联网加载图像变得很容易：把 URL 作为文件名参数传入即可，例如

myImage.load("http://en.wikipedia.org/wiki/File:Example.jpg");

请记住，这样做会同步加载远程存储的图像，也就是说程序在等待所有数据从网络下载完成期间会“阻塞”（或冻结）。为了更好的用户体验，你也可以改为异步加载互联网图像（在后台线程中），具体做法是使用 ofLoadURLAsync() 提供的响应；示例实现可以在 openFrameworks 的 imageLoaderWebExample 图形示例中找到（也可以看看 threadedImageLoaderExample）。既然能加载互联网上的图像，你就可以以计算的方式，用有趣的 API（比如 Temboo、Instagram 或 Flickr 的）获取图像，或从实时路况摄像头之类的动态在线来源获取。

采集并显示摄像头图像

从实时摄像头或数字影片文件采集视频流的过程并不比加载 ofImage 更难。主要的概念差异在于，ofVideoGrabber 或 ofVideoPlayer 对象中的图像数据会持续刷新，通常约每秒 30 次（或按素材的帧率）。每次你让这个对象把数据渲染到屏幕（如下面的 myVideoGrabber.draw()），像素中都会包含刚更新的值。

下面的程序（在 oF 的 videoGrabberExample 中有更完整的版本）展示了基本流程。在下面的示例中，为了增加点乐趣，我们还取出包含 ofVideoGrabber 像素的数据缓冲区，然后用算术方式“反转”这些数据（生成一张“照片底片”），并用 ofTexture 显示出来。

我们应用的头文件声明了一个 ofVideoGrabber，用来从计算机的默认摄像头采集视频数据。我们还声明了一个 unsigned char 缓冲区来存放反转后的视频帧，以及用来显示它的 ofTexture：

// 例 2. 一个采集、显示，
// 并反转摄像头实时视频的应用。
// 这是 ofApp.h

#pragma once
#include "ofMain.h"

class ofApp : public ofBaseApp{
	public:
	
		void setup();
		void update();
		void draw();

		ofVideoGrabber myVideoGrabber;
		ofTexture myTexture;

		unsigned char* invertedVideoData;
		int camWidth;
		int camHeight;
};

unsigned char* 这个声明看起来陌生吗？认清并理解它非常重要，因为这几乎是存储和交换图像数据的通用方式。unsigned 关键字表示描述图像颜色的值全部是正数。char 表示每个像素的每个颜色分量都存储在一个 8 位数字中——一个字节，取值范围 0 到 255——很多年里 character（字符）也是用这个数据类型存储的。而星号（*）表示这个变量命名的数据不只是一个 unsigned char，而是一个 unsigned char 的数组（更准确地说，是指向一个 unsigned char 缓冲区的指针）。关于这类数据类型的更多信息，见 Memory in C++ 一章。

下面示例 2 是抓取摄像头的 .cpp 文件的完整代码。如你所料，ofVideoGrabber 对象还提供许多此处未展示的方法和设置。它们让你可以列出并选择可用的摄像设备；设置采集尺寸和帧率；以及（取决于硬件和驱动）调整摄像机曝光和对比度等参数。

注意该示例把繁重的计算放在 update() 方法中，把图形渲染放在 draw() 中。这是推荐的组织代码的模式。

// 例 2. 一个采集、反转，
// 并显示摄像头实时视频的应用。
// 这是 ofApp.cpp

#include "ofApp.h"

void ofApp::setup(){

	// 设置采集尺寸为 320x240，这是常见的视频尺寸。
	camWidth = 320;
	camHeight = 240;

	// 为默认摄像头打开一个 ofVideoGrabber
	myVideoGrabber.initGrabber (camWidth,camHeight);

	// 创建资源，用来存储并显示数据的另一份副本
	invertedVideoData = new unsigned char [camWidth * camHeight * 3];
	myTexture.allocate (camWidth,camHeight, GL_RGB);
}

void ofApp::update(){

	// 让 grabber 刷新它的数据。
	myVideoGrabber.update();

	// 如果 grabber 确实有新数据，
	if(myVideoGrabber.isFrameNew()){

		// 取得指向 grabber 图像数据的指针。
		unsigned char* pixelData = myVideoGrabber.getPixels().getData();
		
		// 算出要检查的总字节数。
		// 这是图像的宽度乘以高度，
		// 再乘以 3 —— 因为每个像素需要 3 个字节
		// 来存储它的 R、G、B 三个颜色分量。
		int nTotalBytes = camWidth * camHeight * 3;
		
		// 对 RGB 图像数据的每一个字节，
		for(int i=0; i<nTotalBytes; i++){

			// pixelData[i] 是图像的第 i 个字节；
			// 用 255 减去它，得到“照片底片”
			invertedVideoData[i] = 255 - pixelData[i];
		}

		// 现在把反转后的数据存进一个 ofTexture
		myTexture.loadData (invertedVideoData, camWidth,camHeight, GL_RGB);
	}
}

void ofApp::draw(){
	ofBackground(100,100,100);
	ofSetColor(255,255,255);

	// 绘制 grabber，并在它旁边绘制 ofTexture 的“底片”。
	myVideoGrabber.draw(10,10);
	myTexture.draw(340, 10);
}

理解像素数据如何存储在计算机内存中很重要。每个像素都有一个地址，用一个数字表示（从零开始计数）：

观察内存中一维的数值列表如何被排列成二维像素网格的连续行，反之亦然。

你经常需要确定某个像素 (x,y) 在存储于 unsigned char* 缓冲区中的图像里的数组下标。这个小任务出现得足够频繁，值得把下面的模式记牢：

// 已知：
// unsigned char *buffer，一个存放单通道图像的数组
// int x，查询像素的水平坐标（列）
// int y，查询像素的垂直坐标（行）
// int imgWidth，图像的宽度

int arrayIndex = y*imgWidth + x;

// 现在你可以读取 (x,y) 位置的值，例如：
unsigned char pixelValueAtXY = buffer[arrayIndex];

// 你也可以写入该位置的值，例如：
buffer[arrayIndex] = pixelValueAtXY;

同样，你也可以根据给定的数组下标求出像素的 x 和 y 坐标：

// 已知：
// 一张单通道（如灰度）图像
// int arrayIndex，该图像像素数组中的一个下标
// int imgWidth，图像的宽度

int y = arrayIndex / imgWidth; // 注意，这是整数除法！
int x = arrayIndex % imgWidth; // 友好的取模运算符。

底层与高层像素访问方法

大多数时候，你会处理存放在更高层容器对象（如 ofImage）中的图像数据。从这类容器中获取像素数据值有两种方式。“底层”方法是向图像索取指向其原始 unsigned char 像素数据数组的指针，用 .getPixels()，然后从这个数组中取出想要的值。这涉及一些用上面描述的模式进行的数组下标计算。（顺带一提，大多数其他 openFrameworks 图像容器，比如 ofVideoGrabber，都支持这样的 .getPixels() 函数。）

int arrayIndex = (y * imgWidth) + x;
unsigned char* myImagePixelBuffer = myImage.getPixels().getData();
unsigned char pixelValueAtXY = myImagePixelBuffer[arrayIndex];

第二种方法是一个高层函数，返回给定像素位置上存储的颜色：

ofColor colorAtXY = myImage.getColor(x, y);
float brightnessOfColorAtXY = colorAtXY.getBrightness();

寻找图像中最亮的像素

用现在掌握的知识，我们可以写一个简单程序来定位图像中最亮的像素。艺术家团体 Graffiti Research Lab（GRL）在他们为 2007 年项目 L.A.S.E.R Tag 构建的 openFrameworks 应用里，把这一基本概念用出了极佳的艺术效果。L.A.S.E.R Tag 的概念是让人们用激光笔在大型建筑立面上绘制投影涂鸦。激光笔的亮点由类似下面所示的代码跟踪，并作为创作交互式投影图形的基础。

我们应用的 .h 文件加载了一张 ofImage（laserTagImage），内容是有人把激光指向建筑。（在真实应用中用的是实时摄像头。）

// 例 3. 寻找图像中最亮的像素
// 这是 ofApp.h

#pragma once
#include "ofMain.h"

class ofApp : public ofBaseApp{
	public:
		void setup();
		void draw();
		
		// 最终会把这个 ofImage 换成实时视频
		ofImage laserTagImage;
};

下面是 .cpp 文件：

// 例 3. 寻找图像中最亮的像素
// 这是 ofApp.cpp

#include "ofApp.h"

//---------------------
void ofApp::setup(){
	laserTagImage.load("images/laser_tag.jpg");
}

//---------------------
void ofApp::draw(){
	ofBackground(255);

	int w = laserTagImage.getWidth();
	int h = laserTagImage.getHeight();

	float maxBrightness = 0; // 这些用于搜索
	int maxBrightnessX = 0; // 最亮的位置
	int maxBrightnessY = 0;

	// 逐个检查每个像素。如果它比之前见过的
	// 任何像素都亮，就记下它的亮度和坐标。
	// 检查完所有像素后，我们就知道哪个最亮了！
	for(int y=0; y<h; y++) {
		for(int x=0; x<w; x++) {
			ofColor colorAtXY = laserTagImage.getColor(x, y);
			float brightnessOfColorAtXY = colorAtXY.getBrightness();
			if(brightnessOfColorAtXY > maxBrightness){
				maxBrightness = brightnessOfColorAtXY;
				maxBrightnessX = x;
				maxBrightnessY = y;
			}
		}
	}

	// 绘制图像。
	ofSetColor (255);
	laserTagImage.draw(0,0);

	// 在最亮的位置画一个圆。
	ofNoFill();
	ofDrawEllipse (maxBrightnessX, maxBrightnessY, 40,40);
}

我们的小应用定位激光的亮点（幸运的是，它是场景中最亮的部分），并在它周围画一个圆。要复现 L.A.S.E.R Tag，我们会存储这些点的位置并渲染一条适合投影的浅色拖尾。当然，既然知道了最亮（或最暗）点在哪，我们就能开发许多其他有趣的应用，比如太阳跟踪器、乌龟跟踪器……

能定位图像中最亮的像素还有别的用途。例如在深度图像（比如 Kinect 传感器产生的）中，最亮的像素对应最靠前的点——也就是离摄像机最近的物体。如果你在做跟踪用户手部的交互装置，这可能非常有用。

深度图像中最亮的像素对应离摄像机最近的物体。在这里所示的配置中，“最近点”几乎肯定是用户的手。

不出所料，跟踪不止一个亮点需要更复杂的处理方式。如果你能设计和控制跟踪环境，一种简单而有效的方法是最多跟踪三个物体：在场景中搜索最红、最绿和最蓝的像素。Zachary Lieberman 在他与字体设计师 Pierre & Damien 等人合作的 IQ Font 中使用了类似的技术，通过跟踪一辆做了特殊标记的跑车的运动来生成字形。

更一般地，你可以构建一个跟踪特定颜色（单个）亮点的系统。一个非常简单的方法，是找出在“RGB 空间”中颜色与目标颜色欧氏距离最短的像素。下面是一段展示这一点的代码片段。

// 用于跟踪某个目标颜色亮点的代码片段。
// 我们的目标颜色是 CSS LightPink：#FFB6C1 或 (255, 182, 193)
float rTarget = 255; 
float gTarget = 182;
float bTarget = 193; 

// 这些用于搜索颜色最接近
// 目标颜色的那个像素的位置。
float leastDistanceSoFar = 255; 
int xOfPixelWithClosestColor = 0; 
int yOfPixelWithClosestColor = 0;

for (int y=0; y<h; y++) {
	for (int x=0; x<w; x++) {
	
		// 从 myVideoGrabber（或其他图像来源）中
		// 取出 (x,y) 处像素的颜色分量
		ofColor colorAtXY = myVideoGrabber.getColor(x, y);
		float rAtXY = colorAtXY.r; 
		float gAtXY = colorAtXY.g; 
		float bAtXY = colorAtXY.b;
		
		// 计算这些 (r,g,b) 值
		// 与目标颜色 (r,g,b) 值之间的差
		float rDif = rAtXY - rTarget; // 红色的差
		float gDif = gAtXY - gTarget; // 绿色的差
		float bDif = bAtXY - bTarget; // 蓝色的差
		
		// 勾股定理给出欧氏距离。
		float colorDistance = 
			sqrt (rDif*rDif + gDif*gDif + bDif*bDif); 
			
		if(colorDistance < leastDistanceSoFar){
			leastDistanceSoFar = colorDistance;
			xOfPixelWithClosestColor = x;
			yOfPixelWithClosestColor = y;
		}
	}
}

// 到这里，我们就知道了颜色最接近
// 目标颜色的那个像素的位置：
// (xOfPixelWithClosestColor, yOfPixelWithClosestColor)

这种技术常与“吸管式”交互配合使用——用户（通过点击）交互地选取目标颜色。注意还有更精细的“颜色距离”度量方式，例如 CIE76 色彩空间中的 Delta-E 计算，它们对光照变化稳健得多，也更符合人类色彩感知的基础。

三通道（RGB）图像。

我们的 Lincoln 肖像图像是 8 位、1 通道的“灰度”图像。每个像素用一个圆整数（技术上讲是 unsigned char）表示单个亮度值。但其他数据类型和格式也是可能的。

例如，彩色图像通常用 8 位、3 通道图像表示。在这种情况下，每个像素汇集了 3 个字节的信息：红、绿、蓝强度各一个字节。在计算机内存中，这些值通常按 R-G-B 交错存放。如你所见，RGB 彩色图像必然包含三倍的数据量。

非常仔细地看看你的 LCD 屏幕，你会看到这种数据存储方式直接源于显示器荧光体的布局：

由于颜色数据是交错的，访问包含 RGB 数据的缓冲区中的像素值会稍微复杂一点。下面是如何取出给定 (x,y) 位置上 RGB 像素的红、绿、蓝各分量的值：

// 用于访问 RGB 彩色图像中给定 (x,y)
// 位置处颜色的代码片段。

// 已知：
// unsigned char *buffer，一个存放 RGB 图像的数组
//（假定数据按 RGB 顺序交错！）
// int x，查询像素的水平坐标（列）
// int y，查询像素的垂直坐标（行）
// int imgWidth，图像的宽度

int rArrayIndex = (y*imgWidth*3) + (x*3);
int gArrayIndex = (y*imgWidth*3) + (x*3) + 1;
int bArrayIndex = (y*imgWidth*3) + (x*3) + 2;

// 现在你可以读取和写入 (x,y) 位置的值，例如：
unsigned char redValueAtXY   = buffer[rArrayIndex];
unsigned char greenValueAtXY = buffer[gArrayIndex];
unsigned char blueValueAtXY  = buffer[bArrayIndex];

这就是我们先前用来从单色图像取像素值的基本 index = y*width + x 模式的三通道“RGB 版本”。

注意你偶尔会遇到以不同顺序（如 BGR）提供 RGB 字节的外部库或成像硬件。

图像格式的种类

8 位 1 通道（灰度）和 8 位 3 通道（RGB）图像是你最常见的图像格式。不过在广阔的图像处理算法世界里，你最终会遇到各种奇特的图像类型，包括：- 8 位调色板图像，每个像素存储一个指向（最多）256 种颜色的数组的下标；- 16 位（unsigned short）图像，每个通道用两个字节存储每个像素的每个颜色值，数值范围 0-65535；- 32 位（float）图像，每个颜色通道的数据用浮点数表示。

举个实际例子，再想想 Microsoft 广受欢迎的 Kinect 传感器：其 XBox 360 版本产生的深度图像值范围是 0 到 1090。显然这比图像数据中常见的 8 位值范围（0 到 255）更宽；实际上大约是 11 位分辨率。为适应这一点，ofxKinect addon 使用 16 位图像来存储这些信息而不损失精度。同样，要计算高质量的视频合成，32 位浮点的精度几乎是必需的。

你还会遇到：

  • 2 通道图像（常用于亮度加透明度）；
  • 3 通道图像（一般用于 RGB 数据，但偶尔也用于存储其他色彩空间中的图像，如 HSB 或 YUV）；
  • 4 通道图像（常用于 RGBA 图像，偶尔用于 CMYK）；
  • Bayer 图像，其 RGB 颜色通道不是 R-G-B-R-G-B-R-G-B…… 交错，而是呈现独特的棋盘格图案。

还有更奇特的。例如 来自 Landsat 8 卫星的“高光谱”影像有 11 个通道，包括紫外线、近红外和热（远）红外波段！

oF 图像容器的种类（数据结构）

图像格式的区别在于它们表示的图像数据种类（如 8 位灰度影像与 RGB 图像），而图像容器类则是库相关的数据结构，让图像数据能以不同方式和在不同场景下被使用（采集、显示、操作、分析和/或存储）。你在 openFrameworks 中可能遇到的较常见容器有：

  • unsigned char* 一个 unsigned char 数组，这是存储像素数据缓冲区的原始、老派、C 风格格式。它并不很“智能”——没有专门管理图像数据的功能或元数据——但常用于在不同库之间交换数据。许多图像处理教材都假定你的数据以这种方式存储。
  • ofPixels 这是 openFrameworks 的像素数据容器，存在于每个 ofImage 以及 ofVideoGrabber 等其他类内部。它是对缓冲区的封装，包含宽高等额外信息。
  • ofImage ofImage 是 openFrameworks 中用于加载、保存和显示静态图像的最常用对象。把文件加载进 ofImage 会分配一个内部 ofPixels 对象来存储图像数据。ofImage 对象不只是容器，还包含用于把像素数据显示到屏幕的内部方法和对象（如 ofTexture）。
  • ofxCvImage 这是 openFrameworks 的 ofxOpenCV addon 使用的图像数据容器，支持来自流行 OpenCV 库的一系列功能，用于滤波、阈值化和其他图像操作。
  • ofTexture 这个容器把图像数据存储在计算机显卡（GPU）的纹理内存中。许多其他类，包括 ofImage、ofxCvImage、ofVideoPlayer、ofVideoGrabber、ofFbo 和 ofKinect，都持有一个内部 ofTexture 对象来把数据渲染到屏幕。
  • ofFBO 这是 GPU 的“帧缓冲对象”，是纹理和可选深度缓冲区的容器。可以粗略地把它理解为另一个渲染器——一块可以画 3D 或 2D 场景的画布——其产生的像素本身可以当作图像处理。归根结底，ofFBO 是存储在显卡上、代表一次渲染绘制过程的对象。
  • cv::Mat 这是 OpenCV 用来存储图像信息的数据结构。openFrameworks 中不使用它，但如果你大量使用 OpenCV，就会经常发现自己在这个格式中放入和取出数据。
  • IplImage 这是一个较老的数据容器（来自 Intel Image Processing Library），与 OpenCV 配合良好。注意通常你不必操心 IplImage，除非（或直到）你要用 OpenCV 做复杂得多的事情；ofxCvImage 应该提供了把数据取进取出的全部手段。

openFrameworks 的设计者（以及 ofxOpenCV、Kyle McDonald 的 ofxCv 等图像处理 addon）尽可能提供了简单的运算符，方便在这些容器之间交换数据。

上图展示了你可能见到的两种最常见 oF 图像格式的简化表示。左侧是一个 ofImage，其核心是一个 unsigned char 数组。一个 ofPixels 对象封装了这个数组，并附带一些有用的描述性元数据，如宽、高和格式（RGB、RGBA 等）。ofImage 再把这个 ofPixels 对象与一个 ofTexture 封装在一起，后者提供把图像渲染到屏幕的功能。右侧的 ofxCvImage 非常相似，但把图像数据存储在 IplImage 中。所有这些类都提供多种方法把图像数据移入移出。

需要指出的是，图像数据可能存储在计算机内存中非常不同的位置。老式的 unsigned char，以及 ofPixels 和 ofxCvImage 等容器类中的图像数据，存放在计算机的主 RAM 中；这便于 CPU 进行图像处理操作。相反，如上所述，ofTexture 类把数据存储在 GPU 内存中，这对于快速渲染到屏幕最为理想。同样值得知道的是，在 CPU 和 GPU 之间来回搬运图像数据通常会有性能损失，例如 ofImage::grabScreen() 方法从 GPU 捕获屏幕的一部分并存到 ofImage 中，或者 ofTexture::readToPixels() 和 ofFBO::readToPixels() 方法把图像数据复制到 ofPixels。

RGB 到灰度的转换及其在计算机视觉中的作用

许多计算机视觉算法（虽非全部）通常在单通道（即灰度或单色）图像上执行。无论你的项目在某个环节是否使用彩色图像，你几乎肯定仍会用灰度像素数据来表示和存储图像处理链中的许多中间结果。简单的事实是：尽可能使用单通道图像缓冲区可以显著提升图像处理例程的速度，因为它同时减少了计算次数和处理数据所需的内存量。

例如，如果你在计算一个代表用户身体位置的“团块（blob）”，通常把这个团块存储在单通道图像中；一般情况下，值为 255（白）的像素标记前景团块，值为 0（黑）的像素是背景。同样，如果你用一张特殊图像表示视频帧不同部分的运动量，把这一信息存在灰度图像中就足够了（0 表示静止，255 表示大量运动）。这些操作我们会在后面的小节中更多讨论；现在，这条经验法则足矣：如果你用像素缓冲区存储和表示一个一维量，就用单通道图像缓冲区。因此，除另有说明外，本章所有示例都假定你处理的是单色图像。

假设你的原始数据是彩色视频（摄像头常见的情况）。对许多图像处理和计算机视觉应用来说，第一步就是把它转换成单色。视应用而定，你要么直接把彩色数据覆盖成灰度，要么创建一份灰度副本供后续处理使用。

把彩色图像转换为灰度最简单的方法，是修改其数据、把 openFrameworks 图像类型改为 OF_IMAGE_GRAYSCALE。注意这会导致图像重新分配、任何 ofTexture 被更新，所以如果频繁执行，代价可能很高。它也是一种“破坏性操作”，因为转换中图像的原始颜色信息会丢失。

ofImage myImage; 
myImage.load("colorful.jpg"); // 加载一张彩色图像。
myImage.setImageType (OF_IMAGE_GRAYSCALE); // 噗！现在它变成灰度了。

ofxOpenCV addon 库提供了多种把彩色影像转换为灰度的方法。例如 convertToGrayscalePlanarImage() 和 setFromColorImage() 函数会从存放在 ofxCvColorImage 中的彩色图像数据创建或设置 ofxCvGrayscaleImage。但最简单的方法是直接把灰度版本从彩色版本赋值过去；addon 会替你完成转换：

// 给定一个已填入 RGB 数据的彩色 ofxOpenCv 图像：
// ofxCvColorImage kittenCvImgColor; 

// 再给定一个已声明的 ofxCvGrayscaleImage：
ofxCvGrayscaleImage kittenCvImgGray;
	
// 彩色到灰度的转换就由这次赋值完成。
// 注意：这里用到了「运算符重载」，用于自定义
// ofxOpenCV 图像上 '=' 运算符的含义。
kittenCvImgGray = kittenCvImgColor;

尽管 oF 提供了上述把彩色图像转为灰度的工具，仍值得花点时间理解转换过程的细微之处。有三种常见的转换技术：

  • 只提取 R、G、B 中的一个颜色通道，作为图像亮度的替代。例如，可以只取绿色值作为图像亮度的近似，丢弃红、蓝数据。对于字节按 R-G-B 交错的典型彩色图像，这可以通过每隔 3 个字节取一个来实现。这种方法计算快，但在感知上不准确，对自然场景图像往往产生更多噪声。
  • 对 R、G、B 三个颜色通道取平均。一种较慢但在感知上更准确的方法，把亮度（常写作 Y）近似为每个像素红、绿、蓝值的直接平均：Y = (R+G+B)/3;。这不仅在整个可见光谱上更好地表示图像亮度，还削弱了任一颜色通道中噪声的影响。
  • 用色度系数计算亮度。从彩色图像计算灰度最符合人眼感知的方法，是对 RGB 颜色数据做特殊加权的“色度”平均。这些方法计算成本略高，因为每个颜色通道都必须乘以自己的感知权重系数。CCIR 601 成像规范（用于 OpenCV 的 cvtColor 函数，而该函数又被 ofxOpenCV addon 使用）采用公式 Y = 0.299*R + 0.587*G + 0.114*B（并进一步假定 RGB 值已做 gamma 校正）。据 Wikipedia 所述，“这些系数代表了典型三色视觉人类所测得的强度感知；特别地，人眼对绿色最敏感，对蓝色最不敏感。”

下面是一段用 C/C++“从零”写的彩色转灰度代码，使用上述平均法。这段代码也更为一般地展示了如何基于 3 通道图像逐像素计算 1 通道图像。

// 把彩色转换为灰度的代码片段（“从零”实现）

// 加载一张彩色图像，取它的尺寸，
// 并取得指向其像素数据的指针。
ofImage myImage; 
myImage.load ("colorful.jpg");
int imageWidth = myImage.getWidth();
int imageHeight = myImage.getHeight();
unsigned char* rgbPixelData = myImage.getPixels().getData(); 

// 为存放灰度版本分配内存。
// 因为只有 1 个通道的数据，所以就是 w*h。
int nBytesGrayscale = imageWidth * imageHeight; 
unsigned char* grayPixelData = new unsigned char [nBytesGrayscale];

// 对灰度目标图像中的每个像素，
for(int indexGray=0; indexGray<nBytesGrayscale; indexGray++){

	// 计算彩色图像中对应像素的下标，
	// 记住它的数据量是灰度图像的三倍。
	int indexColor = (indexGray * 3); 

	// 取出该彩色像素的红、绿、蓝字节。
	unsigned char R = rgbPixelData[indexColor  ]; 
	unsigned char G = rgbPixelData[indexColor+1]; 
	unsigned char B = rgbPixelData[indexColor+2]; 
	
	// 计算并赋值亮度（这里是 R、G、B 的平均值）。
	// 或者，你也可以使用色度系数。
	unsigned char Y = (R+G+B)/3; 
	grayPixelData[indexGray] = Y;
}

图像的点处理操作

本节讨论的图像处理操作，是后续大量分析与决策的前置步骤。我们特别来看点处理操作，即图像算术与阈值化。

我们从图像算术开始，它是计算机视觉工作流的核心部分。这些就是我们都知道的基本数学运算——加、减、乘、除——只不过作用在图像上。开发者不断使用这类操作，原因多种多样。

与常数的图像算术

图像算术中最简单的操作之一，是用一个常数变换图像中的值。下面的例子中，我们给一张 8 位单色图像加上常数 10。注意这个值是逐像素相加的：结果目标图像中的每个像素所存的数，比源图像中对应像素多 10（即亮 10 个灰度级）。因为每个像素都被孤立处理、不考虑邻居，这类图像算术有时称为点处理。

加常数使图像整体变亮，减常数使它整体变暗。

下面的代码中，我们通过直接操作像素缓冲区的内容“从零”实现点处理。虽然实际的计算机视觉项目常用更高层的库（如 OpenCV）来完成，我们这样做是为了展示底层发生了什么。

// 例 4：给图像加一个常数值。
// 这是“从零”实现的，不用 OpenCV。
// 这是 ofApp.h

#pragma once
#include "ofMain.h"

class ofApp : public ofBaseApp{
	public:
	void setup();
	void draw();
	
	ofImage lincolnOfImageSrc; // 源图像
	ofImage lincolnOfImageDst; // 目标图像
};
// 例 4. 给图像加一个常数值。
// 这是 ofApp.cpp
#include "ofApp.h"

void ofApp::setup(){
	
	// 加载图像，并确保我们在单色模式下工作。
	// 这是我们的源（“src”）图像。
	lincolnOfImageSrc.load("images/lincoln_120x160.png");
	lincolnOfImageSrc.setImageType(OF_IMAGE_GRAYSCALE);
	
	// 构造并分配一张尺寸相同的新图像。
	// 它将存放我们的目标（“dst”）图像。
	int imgW = lincolnOfImageSrc.getWidth();
	int imgH = lincolnOfImageSrc.getHeight();
	lincolnOfImageDst.allocate(imgW, imgH, OF_IMAGE_GRAYSCALE);
	
	// 取得两张图像像素缓冲区的指针。
	// 这些图像用 8 位 unsigned char 存储灰度值。
	// 注意 'src' 和 'dst' 的命名约定 —— 这非常常见。
	unsigned char* srcArray = lincolnOfImageSrc.getPixels().getData();
	unsigned char* dstArray = lincolnOfImageDst.getPixels().getData();
	
	// 遍历目标图像的所有像素。
	// 每个目标像素将比对应的源像素
	// 亮 10 个灰度级。
	int nPixels = imgW * imgH; 
	for(int i=0; i<nPixels; i++) {
		unsigned char srcValue = srcArray[i];
		dstArray[i] = srcValue + 10; 
	}
	
	// 别忘了这一步！
	// 我们告诉 ofImage 从我们已修改的像素缓冲区（在 CPU 上）
	// 刷新它的纹理（存储在 GPU 上）。
	lincolnOfImageDst.update();
}

//---------------------
void ofApp::draw(){
	ofBackground(255);
	ofSetColor(255);

	lincolnOfImageSrc.draw ( 20,20, 120,160);
	lincolnOfImageDst.draw (160,20, 120,160);
}

关于整数溢出的警告

图像算术很简单！但当算术运算作用到像素中存储的值上时，有一个潜伏的危险：整数溢出。

想想给上图底行那个特别标记的像素加 10 会发生什么。它的初始值是 251——但 unsigned char 能存的最大数是 255！结果值该是多少？更一般地，如果我们试图赋一个大到无法用像素数据类型表示的像素值，会发生什么？

答案是：这取决于你用的是什么库或编程技巧，而且可能带来非常重大的后果！一些图像处理库（如 OpenCV）会把所有算术钳制或约束在数据的期望范围内；因此给 251 加 10 会得到封顶的 255（这种方案有时称为“饱和”）。在其他情况下，比如上面直接编辑 unsigned char 的代码，我们就有数据“翻转”的风险，像汽车里程表一样越过零回绕。由于无法进位，只有最低有效位被保留。在 unsigned char 的世界里，251 加 10 等于…… 6！

整数溢出的危害在下图中一目了然。我用上面的代码把 Abraham Lincoln 的源图像调亮：给所有像素值加一个常数。由于没有任何预防措施，许多浅色像素“回绕”变成了深色。

在上面的例子中，可以在赋值新像素值之前，先把相加的数提升为整数并加入饱和约束，来避免整数溢出：

// 'min' 防止数值超过 255，避免溢出。
dstArray[index] = min(255, (int)srcValue + 10);

整数溢出也可能给其他算术操作带来问题，比如乘法和减法（当值变为负数时）。

两幅图像之间的算术：绝对差分

图像算术在作用于两幅图像时特别有用。如你所料，可以把两幅图像相加、相乘、从一幅中减去另一幅、用一幅除以另一幅。对两幅图像执行算术操作（如加法）时，操作是“逐像素”进行的：图像 A 的第一个像素与图像 B 的第一个像素相加，A 的第二个与 B 的第二个相加，依此类推。为便于讨论，我们假定 A 和 B 都是单色且尺寸相同。

在计算机视觉程序中，我们常常需要判断哪些像素代表感兴趣的东西、哪些不代表。构建这类判别器的关键是阈值化操作。

阈值化提出一个逐像素的条件测试——也就是说，它会问“if”源图像中每个像素 (x,y) 中存储的值是否满足某个准则。作为回报，阈值化产生一幅目标图像，表示原图对应像素中该准则（不）满足的位置和方式。如前面所说，满足准则的像素按惯例赋为 255（白），不满足的赋为 0（黑）。我们还会看到，这种阈值化产生的白色团块非常适合由轮廓跟踪器做进一步分析。

一个完整的工作流：背景减除

现在我们已经具备理解和实现计算机视觉中一个流行且广泛使用的工作流所需的全部零件：从背景减除中提取轮廓并跟踪团块。这个工作流产生一组 (x,y) 点，表示（例如）进入摄像头视野的人体轮廓。

本节我们将围绕标准的 openFrameworks opencvExample 展开讨论，它位于 openFrameworks 安装目录的 examples/addons/opencvExample 中。编译并运行这个示例，你会看到一只手投下阴影的视频——并在窗口右下角看到这只手的轮廓，渲染成青色折线。这条折线就是我们的战利品：用它我们可以获得关于来访者的各种信息。那么我们是怎么走到这一步的？

下面的代码是标准 opencvExample 的略微简化版本；例如我们省略了一些 UI 功能，也省略了前面提到的、用于在实时视频源和存储的视频文件之间切换的 #define _USE_LIVE_VIDEO。

在接下来的讨论中，我们把内部机制分成五步，并讨论它们如何执行和显示：

  1. 视频采集
  2. 彩色转灰度
  3. 存储“背景图像”
  4. 阈值化绝对差分
  5. 轮廓跟踪

// 这是 ofApp.h

#include "ofMain.h"
#include "ofxOpenCv.h"

class ofApp : public ofBaseApp{
	public:
		void setup();
		void update();
		void draw();
		void keyPressed(int key);

		ofxCvGrayscaleImage 	grayBg;

		ofxCvContourFinder		contourFinder;

		int						thresholdValue;
		bool					bLearnBackground;
};
// 例 7：背景减除
// 这是 ofApp.cpp
#include "ofApp.h"

//---------------------
void ofApp::setup(){
	vidPlayer.load("fingers.mov");
	vidPlayer.play();

	colorImg.allocate(320,240);
	grayImage.allocate(320,240);
	grayBg.allocate(320,240);
	grayDiff.allocate(320,240);

	bLearnBackground = true;
	thresholdValue = 80;
}

//---------------------
void ofApp::update(){
	
	// 让视频播放器更新自己。
	vidPlayer.update();
	
	if (vidPlayer.isFrameNew()){ // 如果有新数据……
		
		// 把视频播放器的数据复制进一个 ofxCvColorImage
		colorImg.setFromPixels(vidPlayer.getPixels());
		
		// 在 grayImage 中生成 colorImg 的灰度版本
		grayImage = colorImg;
		
		// 如果该学习背景了；
		// 就把 grayImage 的数据复制进 grayBg
		if (bLearnBackground == true){
			grayBg = grayImage; // 注意：这是“运算符重载”
			bLearnBackground = false; // 锁存：只学一次。
		}

		// 取差值
		// 背景图像与输入图像之间差值的绝对值。
		grayDiff.absDiff(grayBg, grayImage);

		grayDiff.threshold(thresholdValue);

		// “Find holes” 为 true，所以我们也会得到内部轮廓。
		contourFinder.findContours(grayDiff, 20, 25000, 10, true);
	}
}

}

第 1 步：视频采集。
屏幕显示区的左上角是未经修改的原始视频：一只手正在投下阴影。虽然不太明显，但这其实是彩色视频，只不过恰好呈现的是近乎黑白的场景。

在 setup() 中，我们初始化一些全局作用域的变量（在 ofApp.h 中声明），并为多个全局作用域的 ofxCvImage 图像缓冲区分配所需内存。我们还把手的视频从其源文件加载进 vidPlayer，这是 ofVideoPlayer 的一个全局作用域实例。

在计算机视觉工作流中，维护大量图像缓冲区相当常见，每个都存储图像处理链中的一个中间状态。为获得最佳性能，最好只在 setup() 中 allocate() 它们一次；否则为这些图像保留内存的操作会影响帧率。

这里的 colorImg 缓冲区（一个 ofxCvColorImage）存放来自 vidPlayer 的未修改彩色数据；每当播放器有新的一帧数据，colorImg 就会在 update() 中收到一份副本。注意从 vidPlayer 取出数据再赋给 colorImg 的那几行命令：

colorImg.setFromPixels(vidPlayer.getPixels());

在 opencvExample 的完整代码中（此处未展示），ofApp.h 顶部附近的 #define 允许你把 ofVideoPlayer 换成 ofVideoGrabber——一个实时摄像头。

第 2 步：彩色转灰度。
窗口右上角是同一段视频转换成的灰度版本。它存放在 grayImage 对象中，这是 ofxCvGrayscaleImage 的一个实例。

灰度转换很容易被忽略；它是在赋值 grayImage = colorImg; 中通过 = 号的运算符重载隐式完成的。opencvExample 中后续所有图像处理都用灰度（而非彩色）图像完成。

第 3 步：存储“背景图像”。
屏幕中左部是背景图像的视图。这是视频刚开始播放时、在手进入画面前捕获一次的场景灰度图像。

背景图像 grayBg 存储第一个有效的视频帧；这由 grayBg = grayImage; 一行完成。一个布尔锁存变量（bLearnBackground）防止它在后续帧上反复执行。不过，如果用户按键，这个锁存会被重置。

系统在你主体（如手）离开画面时“学习背景”，这一点绝对关键。否则，你的主体将无法被正确检测！

第 4 步：阈值化绝对差分。
4. 屏幕中右部显示的是当前帧与背景帧之间的阈值化绝对差分图像。白色像素代表与背景差异显著的区域：那只手！

绝对差分与阈值化分两步操作完成，代码如下。absDiff() 操作计算 grayBg 与 grayImage（存放当前帧）之间的绝对差，并把结果放入 grayDiff。

随后的阈值化操作确保这幅图像被二值化，即其像素值只能是黑（0）或白（255）。阈值化以原地操作的方式作用于 grayDiff，也就是说 grayDiff 图像会被它自己的阈值化版本覆盖。

变量 thresholdValue 设为 80，意味着一个像素必须与背景相差至少 80 个灰度级，才会被视为前景。在官方示例中，按键允许用户调整这个数值。

// 取差值
// 背景图像与输入图像之间差值的绝对值。
grayDiff.absDiff(grayBg, grayImage);

// 对差分图像执行原地阈值化。
grayDiff.threshold(thresholdValue);

这个例子用阈值化把暗色物体从浅色背景中区分出来。但值得指出，阈值化可以应用于任何亮度量化了某个感兴趣变量的图像。

如果你用的是摄像头而不是随附的“fingers.mov”演示视频，请注意自动增益控制有时会干扰背景减除。你可能需要提高阈值，或者使用更精细的背景减除技术。

第 5 步：轮廓跟踪。
5. 最后几步显示在屏幕右下角。这里，ofxCvContourFinder 被指派在二值化图像中 findContours()。它先找出连续的白色像素团块，再把这些团块的轮廓跟踪成由 (x,y) 点构成的 ofxCvBlob 外形。

在内部，ofxCvContourFinder 首先执行一个基于像素的操作，称为连通分量标记，把连续区域标识为带唯一标签的团块。它接着提取每个团块的边界，把它存入 ofPolyline，用的是所谓的链码算法。

帧差分

与背景减除密切相关的是帧差分。如果说背景减除适合检测存在（比较有人进入某场景前后的画面），那么帧差分适合检测运动。

背景减除与帧差分的区别可以这样描述：

  • 背景减除把当前帧与先前存储的背景图像比较
  • 帧差分把当前帧与紧邻的上一帧视频比较。

与背景减除一样，习惯上会对差分图像做阈值化，以区分信号与噪声。用帧差分可以量化场景中有多少运动。做法是统计阈值化差分图像中的白色像素数量。

实践中，背景减除和帧差分经常一起使用。例如，背景减除可以告诉我们房间里有人，而帧差分可以告诉我们他们活动的程度。在一个兼顾两者优点的常见方案中，把运动检测（来自帧差分）与存在检测（来自背景减除）结合起来可以构建一个通用检测器。一个简单的技巧是对两者结果取加权平均，并以此作为进一步阈值化的基础。

轮廓游戏

团块轮廓是一种基于矢量的表示，由一系列 (x,y) 点构成。一旦得到轮廓，就可以用它做各种有趣的几何游戏。

Cyril Diagne 的下面这个项目是一个很好的例子：身体的轮廓由 ofxTriangle 三角化，然后用 ofxBox2D 作为模拟物理交互的基础。Diagne 项目的用户可以用自己的剪影“接住”弹跳的圆形“球”。

ofxCvContourFinder::findContours() 函数的一个标志参数允许你专门搜索内部轮廓，也称为负空间。Philip Worthington 的 Shadow Monsters 是一件很好地运用了这一点的交互艺术作品，它把内部轮廓解释为活蹦乱跳的动画眼球的边界。

轮廓游戏的原始杰作是 Myron Krueger 的里程碑式交互作品 Videoplace，它在 1970 年至 1989 年间持续开发，并于 1974 年首次公开展出。Videoplace 项目包含至少二十多个极具创造力的场景，全面探索了基于摄像机的全身交互与虚拟图形的设计空间——包括远程临场应用，以及（如这里展示的“Critter”场景）与动画人造生物的交互。

下面快速列出一些用从团块中提取的轮廓可以做的有趣而强大的事情：

  • 团块的轮廓表示为 ofPolyline，可以用 ofPolyline::getSmoothed() 平滑和简化。试着做极端平滑，得到捕获几何形状的超强滤波版本。
  • 如果轮廓里的点太多（或太少），可以考虑用 ofPolyline::getResampledBySpacing() 或 getResampledByCount() 来减少（或增加）点数。
  • ofPolyline 提供计算轮廓面积、周长、质心和包围盒的方法；可以考虑把它们映射到视听属性或其他交互属性上。例如，你可以把形状的面积映射到它的质量（在物理模拟中），或映射到它的颜色。
  • 通过搜索轮廓中局部曲率高的点，可以识别形状上的“特殊”点（比如方形的角，或手上伸出的指尖）。ofPolyline::getAngleAtIndex() 函数对此有帮助。
  • 形状度量的数学可以为轮廓分析乃至识别提供强大工具。一种简单的形状度量是长宽比，即形状宽度与高度之比。另一种优雅的形状度量是紧凑度（也称等周比），即形状周长的平方与面积之比。你可以用这些度量来区分（例如）动物或数字的纸板剪影。
  • ofxCvContourFinder 分配给团块的 ID 编号（数组下标）取决于团块的大小和位置。如果你需要跟踪多个位置和面积随时间变化的团块，请看 example-contours-tracking 示例，它来自 Kyle McDonald 的 addon ofxCv。

清理阈值化图像：腐蚀与膨胀

有时阈值化会留下噪声，表现为破碎的团块或多余的斑点。如果调整阈值解决不了这个问题，你肯定想了解腐蚀和膨胀，它们是用于二值化图像的形态学算子。简单地说，

  • 腐蚀会从场景中每个团块上去掉一层像素。
  • 膨胀会给场景中每个团块加上一层像素。

其他有助于去除噪声的操作是 ofxCvImage::blur() 和 ofxCvImage:: blurGaussian()。它们应该在阈值化操作之前应用，而不是之后。

自动阈值化与动态阈值化

有时很难预先知道阈值到底该是多少。摄像机状态会变，光照条件会变，场景条件会变；这些都会影响我们希望用来区分明暗的那个值。

为解决这个问题，你可以把它做成手动调整的设置，就像我们在（上面的）示例 6 中用 mouseX 作阈值那样。但也有一些自动阈值化技术，可以基于图像的亮度直方图计算“理想”阈值。这类技术有几十种，包括 Otsu 法、高斯混合建模、IsoData 阈值化和最大熵阈值化。想全面了解这类技术，可以看看 ImageJ，这是美国国立卫生研究院出品的开源（Java）计算机视觉工具包。

下面是 Isodata 方法的代码，它是自动计算理想阈值的较简单（也较短）的方法之一。注意该函数以图像的直方图为输入：一个含 256 个整数的数组，记录每个灰度级上有多少像素被着成该灰度级。

/*
From: http://www.ph.tn.tudelft.nl/Courses/FIP/frames/fip-Segmenta.html
这种迭代式阈值选取技术由
Ridler 和 Calvard 提出。直方图最初被分成两部分，
使用一个起始阈值，例如 th0 = 127，即 8 位图像
最大动态范围的一半。前景像素对应的灰度值的
样本均值 (mf,0)，以及背景像素对应的灰度值的
样本均值 (mb,0) 都计算出来。
新的阈值 th1 现在取这两个
样本均值的平均。基于新阈值重复这一过程，
直到阈值不再发生变化。

输入：imageHistogram，一个含 256 个整数的数组，每个元素表示
具有该特定灰度级的像素数量。例如，
imageHistogram[56] 包含灰度级为 56 的像素个数。
输出：一个整数（0-255 之间），表示理想阈值。
*/

int ofApp::getThresholdIsodata (int *imageHistogram){
	int theThreshold = 127; // 我们的输出
	
	if (input != NULL){ // 健全性检查
		int thresh = theThreshold;
		int tnew = thresh;
		int thr  = 0;
		int sum  = 0;
		int mean1, mean2;
		int ntries = 0;
		
		do {
			thr = tnew;
			sum = mean1 = mean2 = 0;

			for (int i=0; i<thr; i++){
				mean1 += (imageHistogram[i] * i);
				sum   += (imageHistogram[i]);
			}     
			if (sum != 0){ mean1 = mean1 / sum;}

			sum = 0;
			for (int i=thr; i<255; i++){
				mean2 += (imageHistogram[i] * i);
				sum   += (imageHistogram[i]);
			}

			if (sum != 0){ mean2 = mean2 / sum;}
			tnew = (mean1 + mean2) / 2;
			ntries++;

		} while ((tnew != thr) && (ntries < 64));
		theThreshold = tnew;
	}
	return theThreshold;
}

ROI 处理

许多图像处理和计算机视觉操作可以通过只在主图像的一个子区域内计算来提速，这个子区域称为感兴趣区域，即 ROI。

相关的函数是 ofxCvImage::setROI()，它设置图像中的 ROI。感兴趣区域（Region of Interest）是图像中的一个矩形区域，用于分割出物体以便进一步处理。一旦定义了 ROI，OpenCV 函数就会只作用于该 ROI，从而减少操作要检查和修改的像素数量。

一台狭缝扫描仪。

狭缝扫描——一种时空成像或“时间-空间成像”——二十多年来一直是交互视频艺术中的常见手法。一些最受尊敬的新媒体艺术先驱（Toshio Iwai、Paul de Marinis、Steina Vasulka）以及几十位其他备受推崇的实践者都做过交互式狭缝扫描仪。这个前提至今仍是一个开放式的形式，似乎有着无穷的实验空间，其可能性远未穷尽。它也是管理图像数据的一次好练习，特别是在提取和复制图像子区域方面。

在数字狭缝扫描中，从一系列视频帧中抽取细条，拼接成一幅新图像。结果是一幅简洁地揭示视频或摄像头流中运动历史的图像。例如 Danny Rozin 的 Time Scan Mirror（2004）中，图像由从每一帧输入视频中心提取的细竖直像素条并排放置而成。这样的狭缝扫描仪用不到 20 行代码就能做出来——试试吧！

临摹 Utterback & Achituv（1999）的 Text Rain。

Camille Utterback 与 Romy Achituv 的 Text Rain 是如今已成为经典的交互艺术作品，虚拟字母仿佛“落”在观众的“剪影”上。Utterback 写道：“在 Text Rain 装置中，参与者在巨大的投影屏前站立或移动。屏幕上他们看到自己黑白的镜像视频投影，与下坠字母的彩色动画合成在一起。像雨或雪一样，字母似乎落在参与者的头和手臂上。字母会响应参与者的动作，可以被接住、举起，然后再任其落下。下落的文字会‘落’在任何比某个阈值更暗的东西上，一旦那个障碍移开就会继续‘下落’。”

Text Rain 大约 30 行代码就能实现，涉及本章讨论过的许多主题，例如获取给定位置上像素的亮度。它也是一个理想的项目，可以用来确认你懂得如何创建对象（存储下落粒子的位置和字母）以及对象数组。
