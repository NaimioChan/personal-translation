MIDI

Tidal 可以发送和接收 MIDI 消息。你可以与外部合成器和硬件通信，并从你的控制器接收数据。所有映射都直接通过语言完成，方式直观。

SuperDirt MIDI

前提条件

前提条件是需要较新版本的 Tidal 和 SuperDirt：

  • 升级到最新的 Tidal（本文假定版本为 0.9.10 或更高）
  • 确保你拥有最新的 SuperDirt quark。卸载后重新安装 SuperDirt quark 可能是最简单的做法。有关如何更新 Quarks 的详细信息，参见这个页面。

初始化

首先，你要在 SuperCollider 中开始。像平常一样启动 SuperDirt。然后，在 SuperCollider 中执行以下代码：

MIDIClient.init;

此时你应该会在 SuperCollider 的 post 窗口中看到系统 MIDI 设备的列表。输出大致如下：

MIDI Sources:
	MIDIEndPoint("LoopBe Internal MIDI", "LoopBe Internal MIDI")
	MIDIEndPoint("Focusrite USB MIDI", "Focusrite USB MIDI")
MIDI Destinations:
	MIDIEndPoint("Microsoft GS Wavetable Synth", "Microsoft GS Wavetable Synth")
	MIDIEndPoint("LoopBe Internal MIDI", "LoopBe Internal MIDI")
	MIDIEndPoint("Focusrite USB MIDI", "Focusrite USB MIDI")

请注意，这些 MIDI 设备的名字由两部分组成。下一步你需要同时用到这两部分，即真正连接到 MIDI 设备。执行下面这行：

~midiOut = MIDIOut.newByName("Focusrite USB MIDI", "Focusrite USB MIDI"); // 在这里替换成你自己的设备

上面我们把设备的引用存储到了一个名为 ~midiOut 的变量中。

最后，在 Tidal 中定义你将用来控制这个设备的「合成器」的名字。下面我们把它叫做 mydevice。执行下面这行：

~dirt.soundLibrary.addMIDI(\mydevice, ~midiOut);

可选地，你可以为设备定义一个延迟值：

~midiOut.latency = 0.45;

初始化到此完成。此时你应该已经在 SuperDirt 中连接好了一台 MIDI 设备，作为一个名为 mydevice 的合成器运行。

在 Tidal 中使用

音符 pattern

现在我们可以开始编写一些 Tidal pattern来控制 MIDI 设备了。先给它发送一个简单的音符 pattern：

d1 $ n "0 2 4 7" # s "mydevice"

这应该会播放一个简单的四音符 pattern。注意我们只是用合成器名 mydevice 来向 MIDI 设备发送音符。

你也可以使用音名加八度的记法：

d1 $ n "c4 d4 e5 g3" # s "mydevice"

除了用 n 或 note 传递 MIDI 音符之外，还可以使用 midinote 函数：

Type: midinote :: Pattern Note -> ControlPattern

唯一的区别是，用 midinote 时音符以数字表示，范围从 0（C(-1)）到 127（G9）。在 Tidal Cycles 中，音符 0 是 C5，而在 MIDI 中 C5 是音符 60，所以只要对音符值加减 60 就能在两套体系之间轻松换算。

上面的最后一个例子可以改写为：

d1 $ midinote "48 50 64 42" # s "mydevice"

MIDI 通道

使用函数 midichan 来设置 MIDI 通道。

Type: midichan :: Pattern Double -> ControlPattern

默认 MIDI 通道是 1。SuperDirt 的 MIDI 通道从零开始编号，所以 MIDI 通道 1 是 midichan 0：

d1 $ note "0 2 4 7" # s "mydevice" # midichan 0

如果你的合成器监听的是别的通道，比如 MIDI 通道 5，那就用 midichan 4：

d1 $ note "0 2 4 7" # s "mydevice" # midichan 4

注意 midichan 接受数字 pattern，所以你可以用 pattern 在不同的 MIDI 通道上演奏：

d1 $ note "0 2 4 7" # s "mydevice" # midichan "0 4"

上面的 pattern 在第 1 通道演奏音符「0 2」，在第 5 通道演奏「4 7」。

CC 参数

要向合成器发送 CC 参数，在新的 SuperDirt MIDI 中最好的方式是使用另一个 Tidal pattern。创建这个 pattern 要用到两个新的 SuperDirt MIDI 参数：

  • ccn：你想控制的 CC 参数编号：ccn 30
  • ccv：发送给 CC 参数的值，范围从 0 到 127：ccv 64
Type: ccn :: Pattern Double -> ControlPattern
Type: ccv :: Pattern Double -> ControlPattern

下面是一个完整的例子，向 CC 参数 30 发送值 64：

d2 $ ccv 64 # ccn 30 # s "mydevice"

当然你也可以用 midichan 指定 MIDI 通道：

d2 $ ccv 64 # ccn 30 # s "mydevice" # midichan 4

你可以指定 CC 值的 pattern：

d2 $ ccv "20 40 60 80 100" # ccn 30 # s "mydevice"

d2 $ ccn "30*4" # ccv (range 20 100 $ slow 30 sine) # s "mydevice"

注意，使用 # 时在这种情形下最左边的 pattern 决定节奏。

如果你的设备上有某个功能监听特定的 CC 编号，你可以给它起一个友好的名字：

let ringMod = 30
d2 $ ccv "0 20 50 60" # ccn ringMod # s "mydevice"

如果你想同时控制多个 CC 参数，stack（函数 stack）很好用：

d2 $ fast 8 $ stack [
  ccn 30 # ccv (range 0 127 $ slow 30 sine),
  ccn 31 # ccv "[0 70 30 110]/3",
  ccn 32 # ccv 10
  ] # s "mydevice"

每个设备都有自己的 MIDI 映射表，但有一些 CC 编号是标准的，在大多数设备上应当表现一致：

CC 编号功能
1调制轮
2呼吸控制器
7音量
10声像
11表情踏板
64延音踏板（<=63 关，>=64 开）
 
Type: cc :: Pattern String -> ControlPattern

还有函数 cc，它允许我们在一个字符串里同时传入编号和值：

d2 $ cc "64:30" # s "mydevice" # midichan 4

力度

音高调制

音高调制可以用 midibend 函数控制。

Type: midibend :: Pattern Double -> ControlPattern

注意，通常音高轮发送的数字在 -8192 到 8191 之间，但这里所有数字都是正数，所以范围是从 0 到 16383，其中 8192 是中间的中性点。

你可以用多种方式模拟音高轮的移动。

假设你的设备名为 mydevice，并在通道 5 上接收 MIDI 消息，在这个例子里，声音会从一个 C 音开始，逐渐升高音高，直到音高弯音（pitch bend）调制的极限：

d1 $ stack [
  midibend (segment 128 $ range 8193 16383 $ saw),
  note "c"
  ] # s "mydevice" # midichan 4

现在，我们从音高弯音调制的最小值开始，快速移动到中性点，并在该点保持音高直到本循环结束：

d1 $ stack [
  midibend (smooth "0@2 8193@10 8193@0.1"),
  note "c"
  ] # s "mydevice" # midichan 4

触后（Aftertouch）

触后用于修饰一个已经在发声的音色的性质，通常是通过在 MIDI 控制器键盘的琴键上施加或多或少压力来实现的。

要向设备传递触后 MIDI 消息，使用函数 miditouch。

Type: miditouch :: Pattern Double -> ControlPattern

触后的范围是从 0 到 127，默认值为 0。

d1 $ stack [
  miditouch (segment 128 $ fast 4 $ range 0 64 $ sine),
  note "c"
  ] # s "mydevice" # midichan 4

在这个例子里，一旦音符开始发声，我们就把触后从 0 调到 64 再调回来，在一个循环中往复多次，就像我们在 MIDI 控制器上按压 C 键那样。

调制轮

没有专门用于发送调制轮消息的函数，但 CC 1 用于调制轮，所以我们可以用它：

d1 $ stack [
  ccv (segment 128 $ range 0 128 $ sine) # ccn 1,
  note "c"
  ] # s "mydevice" # midichan 4

这里，我们在循环开始时把调制轮设为 0，升到最大值，再降到最小值，并在循环结束时回到 0。

程序变换（Program change）

程序变换消息可以用 progNum 函数发送。

Type: progNum :: Pattern Double -> ControlPattern

如果你把设备命名为 mydevice，并且它通过 MIDI 通道 14 接收程序变换消息，你可以发出如下命令来改变它的程序/pattern：

once $ s "mydevice" # progNum 10 # midichan 13

NRPN 参数

要发送 NRPN 参数，使用函数 nrpnn 和 nrpnv。

Type: nrpnn :: Pattern Int -> ControlPattern
Type: nrpnv :: Pattern Int -> ControlPattern

NRPN 编号由两个字节组成：MSB（最高有效字节）和 LSB（最低有效字节）。使用 nrpnn 时，你要把这两个字节写成一个数字。要算出所需的数字，需将第一个字节（MSB）乘以 128，再加上第二个字节（LSB）。例如，如果设备手册说混响发送（reverb send）由 NRPN MSB 2 和 NRPN LSB 6（即 2:6）设置，你就需要给 nrpnn 传入 2*128+6=262。

NRPN 值同样有两个字节，因此比 CC 消息有更高的精度。nrpnv 的有效范围是从 0 到 16384。不过要注意，许多设备会直接忽略这个额外的精度。

d2 $ nrpnn (2*128+6) # nrpnv 14000 # s "mydevice" # midichan 12

nrpnn 和 nrpnv 都是可以用 pattern 表示的，但注意它们的参数类型是 Pattern Int，所以你必须确保传给它们的是 Int 而不是 Double：

d2 $ nrpnv (segment 32 $ floor <$> range 0 16000 sine) # nrpnn (1*128+29) # s "mydevice" # midichan 4

sine 给我们的是 Double，所以我们需要在喂给 nrpnv 之前把它们转换成 Int。我们用 floor 来做这件事——它是一个把数字向下取整的 Haskell 函数——而 <$> 会把一个函数（此处是 floor）应用到一个集合中的所有元素上。

Type: nrpn :: Pattern String -> ControlPattern

还有函数 nrpn，它允许我们在一个字符串里同时传入编号和值：

d2 $ nrpn "262:14000" # s "mydevice" # midichan 12

Tidal-Midi

较旧的 tidal-midi Haskell 模块目前无法使用（虽然它将来可能会回归）。请使用其他现有方案。

同步 MIDI 时钟

向设备发送 MIDI 时钟事件以在设备之间同步速度，往往很重要。 Tidal 无法将其速度同步到它接收到的 MIDI 时钟事件，但它可以作为 MIDI 时钟源。 下面的小节展示两种发送跟随 Tidal 速度的 MIDI 时钟事件的方案。

使用 Link 协议同步 MIDI 时钟

从 1.9 版本起，Tidal 使用 Link 协议来调度事件。 Link 是一项在多个应用程序之间同步音乐节拍、速度和相位的技术。它最初由一家名为 Ableton 的公司开发，但它是开源的，如今已在大量音乐软件中实现。 我们可以用 Link 把 Tidal 与一个充当 MIDI 时钟源的独立程序同步起来。

这是发送 MIDI 时钟事件的首选方法，因为它简单、高效、稳定，而且比通过 Tidal 同步 MIDI 时钟的怪癖更少。

用 Ableton Live 作为 MIDI 时钟源

Ableton Live 可以通过 Link 与 Tidal 同步，同时发送 MIDI 时钟消息。

要做到这一点，请同时遵循以下两条说明：

  • 在 Ableton Live 中开启 Link 同步。参见Synchronizing via Link。
  • 在 Live 的 Link/Tempo/MIDI 偏好设置中把该 MIDI 设备开启为同步目标。参见Synchronizing External MIDI Devices to Live。

用 SuperCollider 作为 MIDI 时钟源

我们可以用 Link 把 Tidal 与 SuperCollider 同步，并设置 SuperCollider 发送 MIDI 时钟事件。这个方法的灵感来自 jamshark70 的帖子。它需要用一个新类 LinkToMidiClock 来扩展 SuperCollider。

首先决定这个 SuperCollider 类是只对你自己的用户账户可用，还是对机器上的所有用户可用。然后在 SuperCollider 中运行下面其中一行，找到对应的扩展目录：

Platform.userExtensionDir;   // 仅对你自己的用户账户可用的扩展
Platform.systemExtensionDir; // 对机器上所有用户可用的扩展

在选定的扩展目录中创建一个文件 LinkToMidiClock.sc，并以下面的内容保存：

LinkToMidiClock {
	var <midiOut, <linkClock, routine, <isPlaying = false, d;

	*new { arg midiOut, linkClock;
		^super.newCopyArgs(midiOut, linkClock)
	}

	start {
		if(isPlaying,{
			"Can't start. LinkToMidiClock is already playing".inform;
		},{
			isPlaying = true;
			d = 1/24;
			routine = Routine {
				midiOut.start;
				loop {
					23.do { |i|
						midiOut.midiClock;
						d.wait;
					};
					midiOut.midiClock;
					(thisThread.clock.beats.ceil - thisThread.beats).wait;
				}
			}.play(linkClock, [linkClock.quantum, 0]);
		});
	}

	stop {
		if(isPlaying,{
			isPlaying = false;
			midiOut.stop;
			routine.stop;
		},{
			"Can't stop. LinkToMidiClock is not playing".inform;
		})
	}
}

重启 SuperCollider，或使用 Language > Recompile Class Library。

现在我们可以按照初始化指南操作。在下面的例子里，我们将使用初始化得到的名为 ~midiOut 的 MIDI 设备变量。

MIDI 设备初始化完成后，在 SuperCollider 中创建一个 LinkClock。

~lc = LinkClock.new.latency_(Server.default.latency);

你可以通过检查 Link 对端的数量，确认 Tidal 和 SuperCollider 已经通过 Link 连接：

~lc.numPeers; '0 means no connection, 1 means connection

然后，创建一个连接到 MIDI 设备 ~midiOut 和 LinkClock ~lc 的 LinkToMidiClock。

~ltmc = LinkToMidiClock(~midiOut, ~lc);

在我们告诉它开始之后，MIDI 时钟事件就会被持续发送，直到我们让它停止。

~ltmc.start;
~ltmc.stop;

注意：如果 SuperCollider 和 Tidal 无法通过 Link 连接，可以试着在创建 LinkClock 之前、启动 SuperDirt 之后再启动 Tidal。或者，试着在启动 Tidal 之前先创建 LinkClock。据一些个案反馈，这样做在某些情况下奏效。请在TidalCycles 1.9.0 版发布公告帖中报告你的发现。

有关 Tidal 与 Link 集成的更多细节，参见多人使用 Tidal。

通过 Tidal 同步 MIDI 时钟

我们也可以改用 Tidal 和 SuperDirt MIDI 来发送 MIDI 时钟事件。好处是在较旧版本的 Tidal 上也能使用，但方法稍微复杂一些。

按照初始化指南设置好 SuperDirt MIDI。

完成后，你就可以开始发送 MIDI 时钟消息了，每个循环 48 条，像这样：

p "midiclock" $ midicmd "midiClock*48" # s "mydevice"

你的 MIDI 设备应当会把自己的 BPM 调整到 Tidal 的 cps。接着最好像这样发送一条 stop 消息：

once $ midicmd "stop" # s "mydevice"

然后最后发送一条 start 消息，在正确的时机启动 MIDI 时钟。下面这条每隔四个循环发送一次 start 消息：

p "midictl" $ midicmd "start/4" # s "mydevice"

一切启动并同步之后，最好停止发送 start 消息，以免出现毛刺：

p "midictl" $ silence

但此时如果你执行 hush，midiclock 会和其他所有 pattern 一起停止。为避免这种情况，你可以用另一个版本的 hush 函数覆盖它，只静默特定的 pattern：

let hush = mapM_ ($ silence) [d1,d2,d3,d4,d5,d6,d7,d8,d9,d10,d11,d12,d13,d14,d15,d16]

你很可能会发现 SuperDirt 和你的 MIDI 设备的正拍并不对齐。作为起点，把 SuperCollider 中的 MIDI 延迟设为 0：

~midiOut.latency = 0;

确保 MIDI 一侧的任何偏移也设为 0，然后逐步调整其中之一，直到两者对齐。如果你在改变 cps 后它们仍保持对齐，那就大功告成了！

控制器输入

Tidal 1.0.0 现在支持外部输入，使用的是 OSC 协议。下面是一份让它跑起来的快速指南，包括用一个简单的「桥接器」让 MIDI 输入工作。

设置

要使用 MIDI，你不必太操心 OSC 的映射。不过，你确实需要运行某个东西来把 MIDI 转换成 OSC（Tidal 监听的是 OSC 消息）。下面介绍如何用 SuperCollider 做到这一点。首先，在 Tidal 和 SuperDirt 已经运行的情况下，在 SuperCollider 中运行以下代码块：

// 执行下面的代码块，开始 MIDI -> OSC 的映射。
(
var on, off, cc;
var osc;

osc = NetAddr.new("127.0.0.1", 6010);

MIDIClient.init;
MIDIIn.connectAll;

on = MIDIFunc.noteOn({ |val, num, chan, src|
	osc.sendMsg("/ctrl", num.asString, val/127);
});

off = MIDIFunc.noteOff({ |val, num, chan, src|
	osc.sendMsg("/ctrl", num.asString, 0);
});

cc = MIDIFunc.cc({ |val, num, chan, src|
	osc.sendMsg("/ctrl", num.asString, val/127);
});

if (~stopMidiToOsc != nil, {
	~stopMidiToOsc.value;
});

~stopMidiToOsc = {
	on.free;
	off.free;
	cc.free;
};
)

// 执行下面这行来停止它。
~stopMidiToOsc.value;

用法

之后你应该就能运行诸如下面这样的 pattern，它使用 CC 值 12：

d1 $ sound "bd" # speed (cF 1 "12")

如果你想在 pattern 构成语句中使用 MIDI，先把输入 segment 一下可能会有帮助，因为来自 MIDI 设备的原始 pattern 分辨率非常高。这个例子每个循环只取一个值，并用 range 函数重新映射：

d1 $ sound "amencutup" + n (run (segment 1 $ range 1 16 $ cN 0 "32" ))

重命名 MIDI 音符

假设你有一台 MIDI 鼓机，底鼓在 MIDI 音符 231 上，而你不想每次都写 231，你可以这样做：

s2n :: String -> Note
s2n "BD" = 231
s2n _ = 0

d1 $ n (s2n <$> "BD*4") # sound "tr8" # midichan 9

另一种做法是使用 inhabit，你传入一个名字和 pattern 的列表，像这样：

let drum pat = sound (inhabit [("bd", "231"), ("sd", "232")] pat)
d1 $ drum "bd sd" # midichan 9

你还可以把 MIDI 通道也藏进去，这样就不用每次都输入它：

let drum pat = sound (inhabit [("bd", "231"), ("sd", "232")] pat) # midichan 9

d1 $ drum "bd sd"
d2 $ drum "bd*3 sd*2"

注意 232 那部分是一个 pattern，所以你可以让一个名字触发多个事件，例如：

let drum pat = sound (inhabit [("bd", "231"), ("rush", "232*8"), ("sd", "232")] pat) # midichan 9

d1 $ drum "bd sd rush"

使用 Pure Data 的替代方案

如果你在用 SuperDirt，上面的 SuperCollider 说明是最方便的，但作为替代，你也可以用 Pure Data 把 midi 转换成 OSC。你可以从这里获取 puredata（推荐 vanilla 版本）。然后，下载这个文件。接着，启动 Tidal，在 Pure Data 中打开该文件，并在 Pure Data 中配置好你的 MIDI 设备，事情应该就开始工作了。
