打得快，打得准

简介

现场编码的核心就是……在键盘上敲代码。不过这可不是通常的编码体验。你需要快、需要反应敏捷，还需要打得准、避免出错。现场编码时，尤其是在舞台上，你可能会想避免卡壳或打错。实际上，稍加练习之后，代码编辑器就会像一件乐器。危险无处不在，尤其是你的指尖。现场编码时打得又快又准很重要，因为它能帮你保持在即兴的流动之中，并避免许多原本可能遇到的危险。当然，没有人是完美的，出错也是演出的一部分。

编码活动也涉及操作源代码，包括相当多的复制/剪切/粘贴类操作。你可能还想学会如何快速从一个词跳到另一个词，或者如何在多个文本文件之间高效切换。代码编辑器可以帮你做很多事情：插入代码片段、补全代码、建议语句等等……

本页会给你一系列在电脑键盘上打得更好的建议。页面分为多个小节，每一节处理文本输入或文本操作的一个方面。

打字：速度、准确度与耐力

速度与准确度

  • 有很多网站可以训练你的速度和准确度，通常是随机词序列。Monkeytype 是一个不错的轻量级选择，无需订阅。
    • 如果你想/需要学习另一种键盘布局，这些网站非常好用。
    • 注意符号。尽量加入符号练习，因为编码全是语法和古怪的运算符。
    • 放松点。打字一点也不自然，练习太多或姿势不对都可能伤到自己。
    • 为了快而快并不明智。追求准确反而会更快。尽量别出错。

耐力

  • 你可以边读边打来训练耐力。可以是一本书或任何东西。Typelit 让你在抄写经典文学的同时训练耐力和准确度。
    • 别追求快，而要追求稳定。
    • 你的阅读速度可能比打字快。这种挫败感会促使你打得更起劲！

国际键盘

  • QWERTY 在编程世界里是王者。编程语言的设计（往往是无意的）大多围绕这种键盘布局。有些国际键盘布局不太适合编码。一些国家把 QWERTY 布局当作了*事实*标准。他们真幸运。
  • 愿意保留自己习惯的编码者也可以找到替代键盘布局。这些布局往往是为程序员设计的，符号、变音符号和符号记号的位置安排很有逻辑。我现在就是用 AZERTY-AFNOR 键盘打这段文字的，对一个法国人来说相当好用。
  • 学习一种键盘布局又快又简单。每天尽量多练，直到恢复你平时的速度。凡涉及肌肉记忆的东西，人通常都学得很快。

代码编辑器

从无模式编辑器到模式编辑器

它们是什么？

  • 默认情况下，人们习惯于*无模式*文本编辑器（如 Word、Notepad 等）。按下一个键，就会在当前行输入对应的符号。这对 90% 以上的用例已经够用，人们一般也期望这样用键盘输入文字。大多数人也是这样编码的，把文本输入、各种组合键和鼠标移动巧妙地结合起来。
  • *模式*编辑器（如 Vim）使用另一套系统。键盘有不同的模式：INSERT、VISUAL、NORMAL 等。VISUAL pattern 会重新映射键盘以加快文本选择，INSERT 的行为几乎和*无模式*文本输入一样，NORMAL 则把各种命令映射到你的手指下，等等。*模式*编辑器出了名的难学，但一旦学会，它们就会成为你的第二天性，以至于很难再回到普通的文本输入方式。
    • Vim 和 Emacs 天生可扩展。你可以编写自己的函数或添加插件。
    • Vim 和 Emacs 是以键盘为中心的编辑器。你几乎不需要离开键盘去做别的事。键盘成为与你的计算机进行输入和对话的核心方式。
    • *模式*编辑器在编程世界里很常见，因为文本操作能力在那里很重要。它们非常适合现场编码。

为什么？

  • *模式*编辑器能给你文本编辑的超能力：轻松的代码导航、与终端的集成、宏、可扩展性。
  • 以键盘为中心：一切用键盘完成。界面统一。

代码补全

什么时候不用补全？

  • 即使是最基础的事情，培养肌肉记忆也很重要：创建 pattern、用 mini-notation 语法书写等等。书写 Tidal pattern 可以变成一项近乎自动、无需思考的任务。这样你就可以专注于音乐层面了。
  • 如果你已经习惯了补全，不用补全可能是一种挑战，会迫使你去写一些还没探索过的新东西。
