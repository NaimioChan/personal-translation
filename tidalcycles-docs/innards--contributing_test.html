贡献测试

单元测试是一小段一小段的代码，用来检查某个函数是否按预期工作。你可能出于以下一个或多个原因想贡献一个测试：

  • 以清晰的方式演示一个 bug 或其他意外行为
  • 解释一个新功能是如何工作的
  • 因为你很喜欢某个功能，不希望它将来被破坏
  • 总体上帮助 Tidal 变得更健壮

测试模块

你可以在这里浏览已有的测试模块。

测试模块以它们所测试的模块命名，例如 /test/Sound/Tidal/UITest.hs 包含针对 Sound.Tidal.UITest 的测试。下面是该文件中的一个示例：

describe "euclidFull" $ do
  it "can match against silence" $ do
    compareP (Arc 0 1)
      (euclidFull 3 8 "bd" silence)
      ("bd(3,8)" :: Pattern String)

这个测试验证当 euclidFull 的第四个参数是 silence 时它仍能正常工作。这里曾有过一个 bug，它的存在意味着如果这个 bug 再次出现，我们就会知道。

compareP 用于比较两个 pattern。它接受三个参数——一个带有起止时间的 Arc——在本例中是 0 和 1，意味着第一个循环（即时间位置 0 到 1 之间）中的所有事件都会被比较。然后是待比较的两个 pattern。

你还会看到 comparePD——末尾的 'D' 代表 defragment（碎片整理）。有些情况下一个函数事件会被拆成两部分，comparePD 会简单地把这类事件重新拼合起来，再比较两个 pattern。

贡献测试

要贡献一个测试，你需要 fork Tidal 项目。如果你还没有 Codeberg 账号，需要先注册一个（免费的！），然后前往 Tidal 并点击 fork 按钮。

完成之后，你需要把新的 fork clone 到你的电脑上，并将该文件夹设为当前工作目录。你可以用下面的命令做到这一点，注意把其中的 "<your username>" 换成你在 GitHub 上的用户名。

git clone https://codeberg.org/<your username>/Tidal/
cd Tidal

运行测试

在做任何其他事情之前，最好先跑一遍测试，确认一切顺利完成。你可以用下面的命令：

cabal test

编写并提交你的测试

现在是时候为你的测试创建一个 'branch'（分支），然后以 pull request 的形式把它发给 Tidal 的维护者了。这是一般的开发流程，具体我们就交给这份实用指南吧。你可以从第 3 步开始——"create a branch"。
