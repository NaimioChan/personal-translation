多人使用 Tidal

有多种方式可以和朋友们一起使用 Tidal。

共享编辑器

Troop

Troop 的作者 Ryan Kirkbride（Qirky）将它描述为*“一个实时协作工具，让多台电脑能够在同一份文档里进行集体现场编码。”* Troop 是一个预配置好的文本编辑器，用于在网络上的协作现场编码。Troop 用 Python 3 编写。你需要为自己的操作系统/发行版安装 Python 和 tkinter。Linux 用户可能还需要安装一些额外的依赖，但过程应该很简单。

请注意，要在你的电脑上使用 Troop，你还需要安装 SuperCollider 和 Tidal Cycles。

关于安装/配置流程，请参阅 GitHub 仓库上的 README。

Extramuros

Extramuros 由 David Ogborn（dktr0）编写，是一个经过优化的现场编码协作环境。文本编辑器本身嵌入在网页浏览器里。一台服务器接收来自所有用户的代码/数据，并连接到解释器。编辑器可以划分为多个区域，每个区域各有一个解释器。请前往 GitHub 仓库页面了解安装/配置流程。

Estuary

Estuary 同样由 David Ogborn（dktr0）编写，是一个协作式现场编码环境，其中一些组件取自 Extramuros 并做了扩展。Estuary 内嵌了 minitidal——Tidal Cycles 的一个子集，可以直接在网页浏览器里运行（包括声音！）。无需安装任何东西。

为了获得更好的使用体验，强烈推荐使用 Chrome 或 Chromium。

Estuary 在线版

McMaster 大学的研究小组（即该项目背后的团队）的服务器上有一个全天候运行的服务器。这意味着你无需安装任何东西，就能和朋友们在线体验 Tidal Cycles！

网络速度共享

网络速度共享是将 Tidal 与运行在不同电脑上的其他实例同步的一种方式。这种方式比上面描述的更复杂、更"动手"。它可能更适合更进阶/更有技术功底的用户。

注意：自 Tidal 1.9 起，此方法已不可用。请考虑改用 Native Link Protocol 同步。

1) 同步电脑时钟

确保所有电脑的系统时钟已经同步。可以通过系统设置让电脑*与网络时钟同步*来实现，但这并不理想。其底层使用的是 ntpd，它是为通过互联网慢慢把多台电脑带入同步状态而设计的，而不是用于让局域网内的电脑快速同步。

更推荐使用 ptpd。

ptpd 仅支持 Linux 和 MacOS。

2) 在你的电脑上启动 Tidal

指定一台电脑作为 clock server（时钟服务器），并在那里启动 Tidal。你需要知道这台电脑在局域网中的网络地址。你应该可以在系统设置里找到它。

3) 将其他电脑同步到时钟服务器

在其他电脑上修改你的 Tidal 启动配置，把 cTempoAddr 选项设置为时钟服务器的 IP 地址。例如，如果时钟服务器的 IP 地址是 '192.168.0.10'，你的 startTidal 一行会像这样：

tidal <- startTidal (superdirtTarget {oLatency = 0.02}) (defaultConfig {cFrameTimespan = 1/20, cTempoAddr = "192.168.0.10"})

4) 设置 CPS

在其中一台电脑上使用 setcps，即可让所有电脑同步（例如 setcps 1.1）。

5) 调整延迟

你可能会发现各台电脑仍然"错相"：以相同的 cps 运行，但存在偏移。把 cps 设低（例如 setcps 0.25），在时钟服务器和另一台电脑上各运行一个简单的 pattern（d1 $ s "cp"），然后用 nudge 找出偏移量（d1 $ s "cp" # nudge 0.05）。

一旦找到正确的偏移量，就可以把它加进配置中的 oLatency 值，使其永久生效。只要使用的音频设备等保持不变，就不必再调整了。

如果你发现需要向后 nudge（例如 d1 $ s "cp" # nudge (-0.05)），这只在一定范围内可行。这种情况下更好的做法是给时钟服务器增加延迟。

Link 协议同步

Link 是一个用于同步音乐设备的协议，软件或硬件皆可。Link 会把局域网上发现的所有设备同步到一起。时序和速度由所有客户端共享。它最初由一家名为 Ableton 的音乐软件公司创建，但他们将它分享给了开源社区，使用它不需要安装他们的任何软件。

Native Link 协议同步

Tidal 1.9 版本直接集成了 Ableton Link。1.9 中 Link 同步默认启用，Tidal 会自动连接同一局域网内其他兼容 Link 的应用程序，包括其他 Tidal 实例。Tidal 1.10 版本默认*禁用*了 link 协议。要启用它，请取消注释 bootTidal.hs 中带有 streamEnableLink tidal 的那一行。

调整 Quantum 与每拍循环数

除了对齐节拍，Link 还会对齐小节/循环边界。引用 Link 文档中关于相位同步的说明："为了实现所需的小节和循环对齐，应用程序向 Link 提供一个 quantum（量子）值，以节拍为单位指定所需的相位同步单元。Link 保证拥有相同 quantum 值的会话参与者会相位对齐，也就是说，如果两个参与者的 quantum 是 4 拍，一方的第 3 拍可以对应另一方的第 11 拍，但不能对应第 12 拍。"

Quantum 可以在 Tidal 启动配置中通过 cQuantum 选项设置。cQuantum 的默认值是 4。

除了 quantum，Tidal 还允许你配置每个循环应包含的节拍数。这通过 cBeatsPerCycle 选项完成。默认值为 4。此时，BPM（每分钟节拍数）为 120 对应的 CPS（每秒循环数）为 120 / 60 / 4。有关 BPM 与 CPS 之间换算的更多信息，请参阅入门教程。

cQuantum 和 cBeatsPerCycle 可以任意组合使用，但某些组合可能产生不符合直觉的结果。我们建议从 cQuantum = cBeatsPerCycle 开始，但也欢迎分享你的实验发现！

示例：

tidal <- startTidal superdirtTarget (defaultConfig {cQuantum = 3, cBeatsPerCycle = 3})

调整延迟

你可能会发现，即便速度已经同步，事件之间仍不完全对齐。这是因为 Ableton Link 并不了解不同设备或软件的延迟。

Link 使用共享时间线的概念，时间戳对应声音应当到达扬声器的时间。但它并不知道声音应该提前多久发出，才能准时到达扬声器。不同设备或软件有不同的延迟，因此我们需要对此进行调整。How to adjust sync when using Link 一文说："有时播放可能会有轻微偏移，这通常是由于设备间播放延迟不同造成的。"

如何调整延迟

调整延迟的第一步是找出需要调整多少。把 cps 设低，例如：

setcps 0.25

运行一个简单的 pattern，例如：

d1 $ s "cp"

使用 nudge 找出偏移量：

d1 $ s "cp" # nudge 0.05

一旦找到正确的偏移量，就可以从配置中的 oLatency 值里减去它，使其永久生效。只要使用的音频设备等保持不变，就不必再调整了。我们需要用减法，因为 nudge 把事件在时间上向后移，而 oLatency 把事件在时间上向前移。

你可能需要向后 nudge，例如：

d1 $ s "cp" # nudge (-0.05)

这相当于增大 oLatency。当向后 nudge 很多，或 olatency 非常大时，Tidal 可能会开始过晚地处理事件。可以通过调整配置中的 cProcessAhead 来避免。

禁用 Link 同步

可以把 Tidal 配置为不与其他 Link 会话同步。

修改你的 Tidal 启动配置，把 cEnableLink 选项设为 False。例如，你的 startTidal 一行会像这样：

tidal <- startTidal superdirtTarget (defaultConfig {cEnableLink = False})

Tidal 实例不会自动拥有相同的循环数

Link 不会在会话参与者之间对齐节拍/循环值。引用 Link 文档："例如，一方时间线上的第 1 拍可能对应另一方的第 3 拍或第 4 拍，但不能对应第 3.5 拍"。如果希望循环对齐，请在每个 Tidal 实例中同时执行 resetcycles。

更多讨论请参见 Automatic alignment of cycles in Link sessions - issue #936。

使用 Carabiner 进行 Link 协议同步

Tidal 1.0.11 和 1.8 版本通过 Carabiner 支持与 Link 的初步集成。

要与 Link 协议同步，请按以下步骤操作：

  1. 下载并运行 Carabiner，它是 Link 协议与 Tidal 这类软件之间的桥梁。如果你用的是 Mac OS X、Windows x64、Linux x64 或 Raspberry Pi 系统，可以从 Carabiner 的 releases 页面下载可执行文件。其他用户可以在这里找到编译说明。
  2. 手边准备好另一个你想与之同步的兼容 Link 的应用程序。
  3. 在编辑器中启动 Tidal，运行以下代码连接到 carabiner：
sock <- carabiner tidal 4 (-0.14)
  1. 运行一个 Tidal pattern（例如 d1 $ (sound "cp bd bd bd")），在另一个兼容 Link 的应用程序里改变 BPM，看看是否生效。

目前要从 Tidal 改变 BPM，你必须运行诸如 sendMsg sock "bpm 155" 的命令。

ESPGrid 速度共享

EspGrid 是一个与语言无关的独立开源软件，用于在电子合奏中共享速度等内容。该软件可在 dktr0 的网站上获取。它的设计使得在一处改变速度，所有实例的速度都会改变。每一处改动都会反映到所有地方。

注意：Tidal 1.9 起改用 Link 来调度事件，ESPGrid 集成已被移除。

1) 启动 EspGrid/espgridd

安装、启动和配置 EspGrid/espgridd 的详细说明见上面提到的链接。

2) 启动 Tidal 和 SuperDirt

照常启动 Tidal。

3) 与 EspGrid 同步

只需在编辑器会话中执行 espgrid tidal。

4) 改变速度

你可以用 cpsEsp 0.5、cpsEsp 0.75 等为所有同步到 EspGrid 的人改变速度。如果其他人改变了速度（包括通过 OSX 图形界面程序 EspGrid、SuperCollider quarks 等），你的速度也应随之改变。

CPS 与 BPM

目前你在 Tidal 里调整 cps，还无法让 link 网络中的 BPM 随之改变——这一点很快会修复。你可以调整启动命令：

sock <- carabiner tidal 4 (-0.14)

目前你在 Tidal 里调整 cps，还无法让 link 网络中的 bpm 随之改变——这一点很快会修复。

理解 Link 命令

让我们仔细看看这行晦涩的代码：

sock <- carabiner tidal 4 (-0.14)
  • 4：每个循环的节拍数。用于在 link 的每分钟节拍数与 Tidal 的每秒循环数之间换算。你可能更想要 2（如果跳华尔兹则可以是 3）。
  • -0.14：让 Tidal 相位对齐的延迟时间调整。你可能需要微调它，才能完全对准。

每次调整这些数字后，你都必须重启 Tidal。可以通过重启文本编辑器来完成。将来会更易于配置。
