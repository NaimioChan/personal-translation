Windows 故障排除

  • Haskell：ghc 9.6.1 版本的问题已解决。
  • Haskell：有了新的 network 包（`network-3.1.2.9`）。使用最新的 ghc/cabal 版本时会自动安装它。
  • 针对 choco 安装期间 SuperDirt 安装卡住的问题，新增了一个故障排除步骤。
  • choco 安装出问题后的清理方法，参见 Windows Chocolatey 清理。

Haskell ghci 版本问题

Haskell 安装方式 - choco 对比 ghcup
如果你遇到了 Haskell 相关的问题，重要的是弄清你当初用的是哪种安装方式（choco 还是 ghcup）。你还需要决定是继续用 choco 解决安装问题，还是切换到 ghcup——Haskell 的原生安装器。如果你切换到 ghcup，应当考虑从 choco 中移除相关组件，并从一个干净的系统重新开始。

9.6.1 版本现已与 Tidal 兼容。要获得正确版本的 network 包 `network-3.1.2.9`，现在必须使用 Cabal `3.10.1.0`。在 Windows 上，这些是推荐版本：

  • ghci 9.6.1
  • cabal 3.10.1.0

用 choco 升级版本时，先卸载 ghc/cabal，然后用精确版本参数安装：

choco uninstall ghc
choco uninstall cabal
choco install ghc --version=9.6.1
choco install cabal --version=3.10.1.0

用 ghcup 更改版本：
（如果你没有 ghcup，参见 Haskell ghcup 安装。）

ghcup install ghc 9.6.1
ghcup install cabal 3.10.1.0
ghcup set ghc 9.6.1
ghcup set cabal 3.10.1.0
  • 在安装/重装 Tidal 包之前，建议删除你本地的 ghc 和 cabal 目录。它们通常在你的用户 `\AppData\Roaming` 目录下，但也可能在 `\AppData\` 下的其他目录中。
C:\Users\<yourUser>\AppData\Roaming\ghc\
C:\Users\<yourUser>\AppData\Roaming\cabal\
C:\Users\<yourUser>\AppData\Local\ghc\
C:\Users\<yourUser>\AppData\Local\cabal\
  • 现在运行 Tidal 包的安装命令：
cabal update
cabal v1-install tidal

删除本地 ghc/cabal 目录然后运行 Tidal cabal 命令，是应对任何 Tidal 安装失败问题的标准做法。

choco 安装期间 SuperDirt 安装卡住

SuperDirt 是通过一条在 SuperCollider 中运行的命令安装的。有时安装过程没有正常完成，choco 安装器便不再继续。这很可能是由 SuperCollider 中的残留进程造成的。你可以在 Windows 任务管理器中结束该进程来解决。

如果你看到安装过程停在以下消息处，并且长时间（> 5 分钟以上）没有任何后续动静，它很可能卡住了：

...
SuperDirt installed
** Downloading samples ** - please be patient, this may take a while.
Installing Dirt-Samples
Dirt-Samples installed
SuperDirt installation complete!
Booting server 'localhost' on address 127.0.0.1:57110.
cleaning up OSC

解决步骤：
- 启动 Windows 任务管理器
- 找到残留的 SuperCollider 进程（sclang 或 scide.exe）
- 选中该任务并点击 “End task” 按钮
- 更准确的做法是，用 “More details” 查看所有正在运行的进程。
- 找到与 SuperCollider 关联的残留进程并选择 “End task”
- 这应该能让 choco 安装过程继续进行

Tidal 包安装期间 network-3.1.2.8 报错

failed to install network-3.1.2.8
package has a ./configure script. If on windows, this requires a unix compatibility
toolchain such as MinGW+MSYS or Cygwin.

这个错误说明你没有当前版本的 network 包。 不必安装 Cygwin，从 `choco` 或 `ghcup` 安装 Haskell 时都会安装 `msys2`，它提供 Unix shell。缺的是 `cabal` 找不到它，所以你需要修正你的 `$PATH`。

解决步骤：

  • 首先：按上面的步骤确保你的 ghc 和 cabal 版本正确。注意 `cabal 3.8.1.0` 会安装错误版本的 network 包，无法解决这个错误。你需要 `cabal 3.10.1.0`
  • 删除你本地的 `ghc` 和 `cabal` 目录（见上文）。
  • 再次安装 `tidal` 包（见上文）。
  • 如果问题依旧，可能是你的 `$PATH` 环境变量有问题。
  • choco：把这些值加入你的系统 PATH 环境变量，路径要使用你的 `ghc` 版本：
C:\tools\ghc-\<version>\mingw\bin
# 示例：C:\tools\ghc-9.4.4\mingw\bin
C:\tools\msys64\usr\bin
  • ghcup：把这些值加入你的系统 PATH 环境变量：
C:\ghcup\ghc\\<version>\mingw\bin
# 示例：C:\ghcup\ghc\9.4.4\mingw\bin
C:\ghcup\msys64\usr\bin
  • 退出并以管理员身份重新启动 powershell
    不要跳过这一步——它确保你的新 `$PATH` 设置生效。
  • 按上文所述步骤删除你本地的 `ghc` 和 `cabal` 目录，然后重新运行安装 Tidal 的命令。

Tidal 包安装的其他包错误

有时从 `cabal` 安装 Tidal 包会因多个错误而失败。如果这些错误与 `network-*` 包有关，你多半可以通过检查以下各项来解决。如果你的错误不涉及 `network-*` 包，首先要做的是清空已安装的包并重新运行安装命令（见上文）。

其他需要检查的事项：

  • 务必清空你本地 `%APPDATA%` 中所有的 ghc/cabal 目录。（见上文）
  • 如果你同时用 `choco` 和 `ghcup` 安装过 Haskell 组件，这可能会引发问题。
  • 检查你的环境变量，以管理员身份重启 PowerShell（或你惯用的终端模拟器），然后重启电脑。
  • 如果你已装有 Cygwin 或其他 POSIX 兼容层，可能需要暂时把它从 $PATH 中移除，`cabal` 才能在安装期间成功配置 `network-*`。

是否已安装 Haskell？

打开一个终端窗口，输入：

ghci

你应该会看到类似这样的内容：

GHCi, version 8.6.3: http://www.haskell.org/ghc/  :? for help
Prelude>

如果你没有看到类似上面的内容，那你可能需要安装 Haskell。你看到的版本号很可能不同，不必担心。截至撰写本文时，Tidal 已测试到最早 7.10.3 的版本。

想了解更多信息，请回到 Windows 安装页面查阅。

是否已安装 Tidal 库？

保持那个 ghci 窗口打开，输入（或粘贴）：

import Sound.Tidal.Context

现在你应该会看到类似这样的内容：

GHCi, version 9.4.4: http://www.haskell.org/ghc/  :? for help
Prelude> import Sound.Tidal.Context
Prelude Sound.Tidal.Context>

如果你看到的却是类似这样的错误消息：

<no location info>: error:
  Could not find module ‘Sound.Tidal.Context’

这表示 Tidal 库尚未安装。要安装它，请打开一个新的终端窗口并输入：

cabal update
cabal v1-install tidal

你可以忽略关于 “legacy v1 style” 的警告。

如果你仍然看到错误消息，请确认你已安装 Full 版 Haskell Platform，然后重试。如果仍然不行，请到某个社区页面寻求帮助。

SuperDirt 是否正常？

CLASS Not Found

如果你看到如下错误：

ERROR: Class not defined.

这表示 SuperDirt 尚未安装。运行以下命令来安装：

 include("SuperDirt")

如果安装失败，请确认你已安装 `git` 命令。可以在命令提示符下运行 `git --version` 来检查。如果找不到该命令，请查看安装页面了解如何安装 Git。安装好之后，需要先重启 SuperCollider 再重试。

对于刚安装 SuperCollider 的用户，在运行 `include("SuperDirt")` 之前先重启它也可能解决这个错误。

Could not bind to requested port

如果你看到类似这样的错误：

Could not bind to requested port. This may mean it is in use already by another application.
ERROR: Could not open UDP port 57120

这很可能表示有残留的 SuperCollider 进程在运行，占用了网络端口。关闭 SuperCollider，并在任务管理器中强制退出 `sclang` 和 `scserver`。如果还不行，重启一次电脑即可清除它们。

为什么什么都听不到？

缺少采样

Tidal Cycles 安装时附带了一个庞大的默认音频采样音色库。下载有时会失败，导致你没有任何声音可播放。如果一切看起来都正常，但并非所有声音都能播放，那么很可能是下载 Tidal 音色库的过程中途失败了。

你可以通过 SuperCollider 菜单找到 `Dirt-Samples` 文件夹来修复：打开 `File > Open user Support directory`（顶部菜单）。找到 `downloaded-quarks`，然后再找到 `Dirt-Samples` 文件夹。你很可能会发现其中许多文件夹缺失或为空。你可以从这个链接下载缺失的采样并放到这里。

音频配置

问题也可能出在你的声音系统上。检查所有设备是否连接正确，检查你是否选择了正确的音频接口，以及音量是否已调高。如果你还是听不到任何声音，那问题可能出在别处。

用 'stack' 而非 'cabal' 安装

如果 Tidal Haskell 库在用 `cabal` 安装时遇到顽固的问题，特别是出现与 'network' 库相关的错误，那么改用 `stack` 安装即可解决。

只需在终端窗口中运行以下命令：

stack install tidal

完成后，你只需让编辑器插件使用 通过 `stack` 安装的 Tidal。在 Atom 中，找到 Tidal Cycles 包的设置，把 `ghci path` 设置为：

stack exec --package tidal -- ghci

重启 Atom**，一切应该就正常了。
