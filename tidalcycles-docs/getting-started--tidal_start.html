启动 Tidal

Tidal Cycles 并不是一个庞大的单体软件。最好把它理解为多个组件之间的互联：

  1. 一个 pattern 库
    • (1) 你的文本编辑器
    • (2) 解释器（Haskell）
  2. 一个音频引擎
    • (1) SuperDirt，负责接收消息并把它们变成声音。
    • (2) SuperCollider，负责把声音发送出去。

启动 Tidal

启动 Tidal 总是分为两步：

  1. 启动 SuperCollider，然后在其中启动 SuperDirt。
  2. 从你的文本编辑器启动 Tidal Cycles。

本页将解释如何做到这一点，还会教你把这些任务自动化，这样你就不必一次又一次地重复设置环节 🙂。

启动 SuperCollider 和 SuperDirt

通过 IDE

使用下面这行简单的代码，就可以用默认设置启动 SuperDirt：

SuperDirt.start;

选中编辑器中的文字并按 Ctrl+Enter（Linux 与 Windows）或 Command+Enter（macOS）来运行代码。几秒钟后你应该会在日志中看到下面这一行：

SuperDirt: listening to Tidal on port 57120

现在你可以从文本编辑器启动 Tidal Cycles，开始做音乐了。

这一步经常会失败！你可能会得到一长串错误，其中包括

ERROR: No more buffer numbers -- free some buffers before allocating more.

更多信息请参见下文的自定义 SuperCollider 服务器选项。

自定义 SuperCollider 服务器选项

默认设置可能不足以应对更大的采样集合，比如默认的 Dirt-Samples。此外，你可能想指定加载更多（或更少）的采样，或者微调内存、延迟等其他设置。

SuperDirt 仓库中的启动脚本可以作为起点。脚本也在下面展示了出来，但链接中的版本可能更新。

要运行代码，把光标放在最外层括号之间的任意位置，然后按 Ctrl+Enter（Linux 与 Windows）或 Command+Enter（macOS）。

/*
This is an example startup file.
If you want to modify it, best copy it elsewhere to keep the git repository clean.

You can then load it by calling
"path/to/my/superdirt_startup.scd".load
from the supercollider startup file

The supercollider startup file is to be found in
Platform.userAppSupportDir +/+ "startup.scd",
or via the menu File > Open startup file
*/


(
s.reboot { // 服务器选项只会在重启时更新
	// 配置声音服务器：这里可以添加针对特定硬件的选项
	// 参见 http://doc.sccode.org/Classes/ServerOptions.html
	s.options.numBuffers = 1024 * 256; // 如果需要加载更多采样就调大这个值
	s.options.memSize = 8192 * 32; // 如果出现 "alloc failed" 消息就调大这个值
	s.options.numWireBufs = 2048; // 如果出现 "exceeded number of interconnect buffers" 消息就调大这个值
	s.options.maxNodes = 1024 * 32; // 如果出现掉音和 "too many nodes" 消息就调大这个值
	s.options.numOutputBusChannels = 2; // 如有必要，设为你的硬件输出通道数
	s.options.numInputBusChannels = 2; // 如有必要，设为你的硬件输入通道数
	// 启动服务器并启动 SuperDirt
	s.waitForBoot {
		~dirt.stop; // 停掉旧实例，避免重复的 dirt（如果它是 nil，这一步什么也不会做）
		~dirt = SuperDirt(2, s); // 两个输出通道，如果想在更多通道间做声像就调大
		~dirt.loadSoundFiles;   // 加载采样（路径中可以包含通配符）
		// 例如：~dirt.loadSoundFiles("/Users/myUserName/Dirt/samples/*");
		// s.sync; // 可选：等待采样读取完成
		~dirt.start(57120, 0 ! 12);   // 在端口 57120 上开始监听，创建两条总线，各把音频发送到通道 0
		SuperDirt.default = ~dirt; // 让这个实例在 sclang 中可用（可选）

		// 可选，为了在 sclang 中方便访问：
		(
			~d1 = ~dirt.orbits[0]; ~d2 = ~dirt.orbits[1]; ~d3 = ~dirt.orbits[2];
			~d4 = ~dirt.orbits[3]; ~d5 = ~dirt.orbits[4]; ~d6 = ~dirt.orbits[5];
			~d7 = ~dirt.orbits[6]; ~d8 = ~dirt.orbits[7]; ~d9 = ~dirt.orbits[8];
			~d10 = ~dirt.orbits[9]; ~d11 = ~dirt.orbits[10]; ~d12 = ~dirt.orbits[11];
		);

		// 直接在下面、在你自己的这份文件副本里，可以添加你想在启动时调用的更多代码
		// 这可以确保服务器和 ~dirt 在运行
		// 你可以把它独立出来，通过 "path/to/my/file.scd".load
		// 以及按需注释掉不同的 load 语句，更方便地在不同设置之间切换
		// ...

	};

	s.latency = 0.3; // 如果出现 "late" 消息就调大这个值


};
);

如你所见，这个脚本还展示了如何加载自定义音频采样，以及如何处理多声道声音。

使用这段代码时，你不应再运行 SuperDirt.start。脚本已经负责启动 SuperDirt 了。

每次 SuperCollider 启动时自动启动 SuperDirt

打开 SuperCollider。点击 File > Open startup file。把自定义 SuperCollider 服务器选项中的代码粘贴到刚出现的新缓冲区里。

保存文件，瞧！只要程序一启动，SuperCollider 就会始终启动 SuperDirt。

通过命令行（适合有经验的用户）

或者，你也可以从终端启动 sclang 来获得交互式提示符，而不必启动 SuperCollider IDE。

启动 Tidal Cycles

我们先假设你目前使用的是 Pulsar 编辑器（即之前的 Atom）。有关你选择的文本编辑器的具体说明，请查看侧边栏中的 Get a Text Editor 子菜单，里面有更详细的说明。

  1. 启动 Pulsar
  2. 新建一个文件，并以 .tidal 结尾的文件名保存（例如 test.tidal）。
  3. 打开 Packages 菜单，选择 TidalCycles -> Boot Tidal Cycles。窗口底部会打开一个小窗口，其中包含 t> 提示符（并且但愿没有任何错误消息）。

来试试吧！在文本编辑器中输入下面的 pattern，然后按 Shift+Enter 求值（Ctrl+Enter 会求值多行）：

d1 $ sound "bd sn"

如果你听到了声音，恭喜 👍！

如果遇到问题，欢迎在论坛或 Discord 群组提问和分享问题。一定是你的 Tidal 系统有配置错误或缺了什么东西！

继续探索

与自由软件的常见情况一样，构成 Tidal Cycles 系统的各个组件都有其他选择。Pulsar 和 SuperDirt 也许就足够你用了，但还有其他编辑器和合成器可供使用。请查看侧边栏了解这些替代方案。
