问：如何确保「处理」与「用户界面」之间的通信？

我们用「处理」一词指实现 Vst:: IAudioProcessor 接口的代码，用「用户界面」指实现 Vst:: IEditController 接口的编辑器组件。

如果需要把任何参数变更传达到用户界面，例如电平表变化和峰值，就需要把该参数定义为导出类型。该参数随后会关联一个 ID。在 process 函数中，你可以通过 outputParameterChanges（来自 ProcessData）把变更通知宿主。你把该参数（ID）加入一个列表，宿主会用它在正确的时刻把变更送回用户界面。

如果需要交换的不只是参数变更，例如 速度、采样率、FFT、音高分析 或处理产生的任何其他数据，你可以使用 Vst:: IMessage 接口（参见 AGain 示例）。不过要小心，应从「timer」线程发送数据，而不是直接在 process 函数中发送，例如在「process」调用中发送。

参见 组件之间的通信。

问：宿主如何把自动化数据发送给我的 VST 3 插件？

自动化数据会作为传给 Vst:: IAudioProcessor::process（processData）方法的数据的一部分，发送到音频处理方法。

IAudioProcessor::process (processData)
{
    IParameterChanges* paramChanges = processData.inputParameterChanges;
    //...
}

自动化数据以参数变更列表的形式传输。该列表始终包含足够的信息，能够以逐采样精确的方式还原宿主的原始自动化曲线。请查看 AGain 示例，了解如何实现。

另请参见 参数与自动化。

问：如何向宿主报告插件有了新的参数标题？

由于加载预设或用户交互，插件可能改变其参数名称（标题）（但不改变其数量或 ID）。为把这一变更通知宿主，插件应通过 editController 的组件处理器调用 restartComponent 函数，并带上标志 kParamTitlesChanged：

componentHandler->restartComponent (kParamTitlesChanged);

宿主将重新扫描参数列表并更新标题。

ⓘ 注意
使用标志 kParamValuesChanged 时只会更新参数值。

问：如何从宿主接收 MIDI 控制器？

MIDI 控制器不会直接传给 VST 组件。MIDI 作为硬件协议，有一些限制在软件中可以避免。尤其是控制器数据，其语义往往不清楚且常被忽略。此外，它们会干扰常规的参数自动化，而宿主在直接传递 MIDI 控制器时并不清楚插件内部发生了什么。

因此，任何由 MIDI 控制器控制的功能都必须导出为常规参数。宿主会用这个接口转换传入的 MIDI 控制器数据，并以普通参数变更的形式传输。这样宿主就能像对待其他参数一样对它们进行自动化。

为把这种 MIDI CC 到插件参数的映射通知宿主，插件应实现 Vst:: IMidiMapping 接口。如果映射发生变化，插件应调用 Vst:: IComponentHandler::restartComponent（kMidiCCAssignmentChanged）把这一变更通知宿主。

问：如果宿主不进行处理，我的参数变更（来自 UI 交互）如何发送给处理器？

当用户操作在插件 UI 中改变参数时，插件通过 performEdit 把该变更发送给宿主（不要忘记调用 beginEdit 和 endEdit），随后由宿主负责把这个参数变更传递到处理器部分：

  • 如果音频引擎正在运行（播放），这将在下一次可用的 process 调用中完成。
  • 如果音频引擎未运行且插件已激活（启用），宿主必须通过 process 调用（音频缓冲区设为 nullptr）把参数变更发送给处理器，以此定期 flush 参数变更。此时插件应只更新参数变更，不处理任何音频。宿主支持这种 flush 机制至关重要；否则，在插件状态（项目/预设）时，宿主将得不到正确的更新状态。
