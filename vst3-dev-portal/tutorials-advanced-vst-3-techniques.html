第 1 部分：逐采样精确的参数处理

我们先来看这个 process 函数：

void MyEffect::process (ProcessData& data)
{
    handleParameterChanges (data.inputParameterChanges);

    // 取出本块的增益值
    ParamValue gain = gainParameter.getValue ();

    // 处理音频
    AudioBusBuffers* inputs = data.inputs;
    AudioBusBuffers* outputs = data.outputs;
    for (auto channelIndex = 0; channelIndex < inputs[0].numChannels; ++channelIndex)
    {
        for (auto sampleIndex = 0; sampleIndex < data.numSamples; ++sampleIndex)
        {
            auto sample = inputs[0].channelBuffers32[channelIndex][sampleIndex];
            outputs[0].channelBuffers32[channelIndex][sampleIndex] = sample * gain;
        }
    }
}

这很直接也很简单：我们在 handleParameterChanges 函数中处理参数变更，稍后就会看到这个函数。然后我们取出最后一个增益参数值，遍历输入缓冲区，把其中的采样复制到输出缓冲区，再乘上 gain 系数。

如果我们看一下 handleParameterChanges 函数：

void MyEffect::handleParameterChanges (IParameterChanges*changes)
{
    if (!changes)
        return;
    int32 changeCount = changes->getParameterCount ();
    for (auto i = 0; i < changeCount; ++i)
    {
        if (auto queue = changes->getParameterData (i))
        {
            auto paramID = queue->getParameterId ();
            if (paramID == ParameterID::Gain)
            {
                int32 pointCount = queue->getPointCount ();
                if (pointCount > 0)
                {
                    int32 sampleOffset;
                    ParamValue value;
                    if (queue->getPoint (pointCount - 1, sampleOffset, value) == kResultTrue)
                        gainParameter.setValue (value);
                }
            }
        }
    }
}

可以看到，Gain 参数只使用最后一个点作为增益值。

如果我们现在想使用 Gain 参数的所有点，可以使用 SDK 中的两个工具类。

第一个是 ProcessDataSlicer，它把音频块切分成更小的片段。

void MyEffect::process (ProcessData& data)
{
    handleParameterChanges (data.inputParameterChanges);

    ProcessDataSlicer slicer (8);
    
    auto doProcessing = [this] (ProcessData& data) {
        // 取出本块的增益值
        ParamValue gain = gainParameter.getValue ();

        // 处理音频
        AudioBusBuffers* inputs = data.inputs;
        AudioBusBuffers* outputs = data.outputs;
        for (auto channelIndex = 0; channelIndex < inputs[0].numChannels; ++channelIndex)
        {
            for (auto sampleIndex = 0; sampleIndex < data.numSamples; ++sampleIndex)
            {
                auto sample = inputs[0].channelBuffers32[channelIndex][sampleIndex];
                outputs[0].channelBuffers32[channelIndex][sampleIndex] = sample * gain;
            }
        }
    }
    
    slicer.process<SymbolicSampleSizes::kSample32> (data, doProcessing);
}

如你所见，我们把算法部分移到了 lambda doProcessing 中，并把它传给 slicer.process。现在这个 lambda 会被多次调用，每次最多处理 8 个采样，直到整个缓冲区处理完毕。这还不能带来更好的参数分辨率，但我们现在可以用第二个工具类来处理这件事。

首先，我们来看一下 gainParameter 变量的类型，因为它就是我们的下一个工具类：

SampleAccurate::Parameter gainParameter;

我们必须把 handleParameterChanges 函数改成：

void MyEffect::handleParameterChanges (IParameterChanges*inputParameterChanges)
{
    int32 changeCount = inputParameterChanges->getParameterCount ();
    for (auto i = 0; i < changeCount; ++i)
    {
        if (auto queue = changes->getParameterData (i))
        {
            auto paramID = queue->getParameterId ();
            if (paramID == ParameterID::Gain)
            {
                gainParameter.beginChanges (queue);
            }
        }
    }
    
}

以便把参数变更的处理委托给 gainParameter 对象。

现在我们只需要在 process lambda 中再做一点小改动，就能使用近乎逐采样精确的 gain 值。我们必须调用 gainParameter 对象来推进参数值：

auto doProcessing = [this] (ProcessData& data) {
    // 取出本块的增益值
    ParamValue gain = gainParameter.advance (data.numSamples);

    // 处理音频
    AudioBusBuffers* inputs = data.inputs;
    AudioBusBuffers* outputs = data.outputs;
    for (auto channelIndex = 0; channelIndex < inputs[0].numChannels; ++channelIndex)
    {
        for (auto sampleIndex = 0; sampleIndex < data.numSamples; ++sampleIndex)
        {
            auto sample = inputs[0].channelBuffers32[channelIndex][sampleIndex];
            outputs[0].channelBuffers32[channelIndex][sampleIndex] = sample * gain;
        }
    }
}

最后，我们必须在 process 函数末尾对 gainParameter 做一些清理，即调用 gainParameter.endChanges。

void MyEffect::process (ProcessData& data)
{
    handleParameterChanges (data.inputParameterChanges);

    ProcessDataSlicer slicer (8);
    
    auto doProcessing = [this] (ProcessData& data) {
        // 取出本块的增益值
        ParamValue gain = gainParameter.advance (data.numSamples);

        // 处理音频
        AudioBusBuffers* inputs = data.inputs;
        AudioBusBuffers* outputs = data.outputs;
        for (auto channelIndex = 0; channelIndex < inputs[0].numChannels; ++channelIndex)
        {
            for (auto sampleIndex = 0; sampleIndex < data.numSamples; ++sampleIndex)
            {
                auto sample = inputs[0].channelBuffers32[channelIndex][sampleIndex];
                outputs[0].channelBuffers32[channelIndex][sampleIndex] = sample * gain;
            }
        }
    }
    
    slicer.process<SymbolicSampleSizes::kSample32> (data, doProcessing);
    
    gainParameter.endChanges ();
}

现在，这个示例已经支持近乎逐采样精确的参数变更。每隔 8 个采样，gain 参数就会更新为正确的值。

要做到 100% 逐采样精确非常简单，请查看 SDK 中的 AGain Sample Accurate 示例。

第 2 部分：添加 32 位和 64 位音频处理

该示例目前只支持 32 位处理。现在我们要添加 64 位处理。

你可能已经注意到，ProcessDataSlicer 的 process 函数使用了一个模板参数。这个模板参数 SampleSize 定义了 ProcessData 结构中音频缓冲区的位深。目前它被硬编码为 SymbolicSampleSizes::kSample32。

为了支持 SymbolicSampleSizes::kSample64，我们只需要对代码做几处改动。首先，我们通过为效果器引入一个新的模板方法来改造算法部分：

template <SymbolicSampleSizes SampleSize>
void MyEffect::process (ProcessData& data)
{
}

我们基本上只是把代码从原来的 process 方法移到这个方法中，参数变更处理那部分代码除外：

template <SymbolicSampleSizes SampleSize>
void MyEffect::process (ProcessData& data)
{
    ProcessDataSlicer slicer (8);
    
    auto doProcessing = [this] (ProcessData& data) {
        // 取出本块的增益值
        ParamValue gain = gainParameter.advance (data.numSamples);

        // 处理音频
        AudioBusBuffers* inputs = data.inputs;
        AudioBusBuffers* outputs = data.outputs;
        for (auto channelIndex = 0; channelIndex < inputs[0].numChannels; ++channelIndex)
        {
            for (auto sampleIndex = 0; sampleIndex < data.numSamples; ++sampleIndex)
            {
                auto sample = inputs[0].channelBuffers32[channelIndex][sampleIndex];
                outputs[0].channelBuffers32[channelIndex][sampleIndex] = sample * gain;
            }
        }
    }
    
    slicer.process<SampleSize> (data, doProcessing);
}

我们只是把 ProcessDataSlicer 的 process 方法的模板参数 SampleSize 改成与我们自己的 process 函数相同的模板参数。

这样还不能正确工作，因为我们在 doProcessing lambda 中仍然使用 32 位音频缓冲区。为了解决这个问题，我们必须再引入两个模板函数 getChannelBuffers，它们会根据 SampleSize 模板参数选择正确的音频缓冲区，该参数可以是 SymbolicSampleSizes::kSample32 或 SymbolicSampleSizes::kSample64：

template <SymbolicSampleSizes SampleSize,
        typename std::enable_if<SampleSize == SymbolicSampleSizes::kSample32>::type* = nullptr>
inline Sample32** getChannelBuffers (AudioBusBuffers& buffer)
{
    return buffer.channelBuffers32;
}

template <SymbolicSampleSizes SampleSize,
        typename std::enable_if<SampleSize == SymbolicSampleSizes::kSample64>::type* = nullptr>
inline Sample64** getChannelBuffers (AudioBusBuffers& buffer)
{
    return buffer.channelBuffers64;
}

现在我们可以修改 doProcessing 算法，改用这些函数：

template <SymbolicSampleSizes SampleSize>
void MyEffect::process (ProcessData& data)
{
    ProcessDataSlicer slicer (8);
    
    auto doProcessing = [this] (ProcessData& data) {
        // 取出本块的增益值
        ParamValue gain = gainParameter.advance (data.numSamples);

        // 处理音频
        AudioBusBuffers* inputs = data.inputs;
        AudioBusBuffers* outputs = data.outputs;
        for (auto channelIndex = 0; channelIndex < inputs[0].numChannels; ++channelIndex)
        {
            auto inputBuffers = getChannelBuffers<SampleSize> (inputs[0])[channelIndex];
            auto outputBuffers = getChannelBuffers<SampleSize> (outputs[0])[channelIndex];
            for (auto sampleIndex = 0; sampleIndex < data.numSamples; ++sampleIndex)
            {
                auto sample = inputBuffers[sampleIndex];
                outputBuffers[sampleIndex] = sample * gain;
            }
        }
    };
    
    slicer.process<SampleSize> (data, doProcessing);
}

作为最后一步，我们现在需要从普通的 process 函数中调用模板化的 process<...> 函数：

void MyEffect::process (ProcessData& data)
{
    handleParameterChanges (data.inputParameterChanges);

    if (processSetup.symbolicSampleSize == SymbolicSampleSizes::kSample32)
        process<SymbolicSampleSizes::kSample32> (data);
    else
        process<SymbolicSampleSizes::kSample64> (data);
    
    gainParameter.endChanges ();
}

根据 processSetup.symbolicSampleSize，我们或者调用 32 位的 process 函数，或者调用 64 位的 process 函数。

我们只需要告知宿主我们可以处理 64 位：

tresult PLUGIN_API MyEffect::canProcessSampleSize (int32symbolicSampleSize)
{
    return (symbolicSampleSize == SymbolicSampleSizes::kSample32 ||
            symbolicSampleSize == SymbolicSampleSizes::kSample64) ?
            kResultTrue :
            kResultFalse;
}

现在我们既有逐采样精确的参数变更，也有 32 位和 64 位音频处理。

第 3 部分：线程安全的状态变更

这个领域的一个常见问题是：来自预设或 DAW 工程的插件状态是由宿主在非实时线程中设置的。

如果我们想改变内部数据模型来使用这个状态，就必须把这个状态传递到实时线程。这应当以实时线程安全的方式完成。否则模型可能无法反映正确的状态，因为在实时线程中分派的参数变更和在另一个线程中设置的状态数据最终会处于未定义状态。

对于这种情况，我们还有另一个工具类：RTTransferT

这个类需要一个描述状态数据的模板参数 StateModel。我们创建一个简单的结构体作为数据模型：

struct StateModel
{
    double gain;
};

using RTTransfer = RTTransferT<StateModel>;

我们现在把 RTTransfer 用作 MyEffect 类的成员：

class MyEffect : ....
{
    RTTransfer stateTransfer;
};

如果我们现在从宿主收到一个新的 state，就创建一个 newStateModel，把 stateGain 值写入 model->gain，并把它传给工具类 stateTransfer：

tresult PLUGIN_API MyEffect::setState (IBStream* state)
{
    double stateGain = ... // 从状态流中读出该值
    
    StateModel model = std::make_unique<StateModel> ();
    model->gain = stateGain;
    
    stateTransfer.transferObject_ui (std::move (model));
    
    return kResultTrue;
}

要把 stateModel 送入我们的实时线程，我们必须按以下方式修改 process 函数：

void MyEffect::process (ProcessData& data)
{
    stateTransfer.accessTransferObject_rt ([this] (const auto& stateModel) {
        gainParameter.setValue (stateModel.gain);
    });
    
    handleParameterChanges (data.inputParameterChanges);

    if (processSetup.symbolicSampleSize == SymbolicSampleSizes::kSample32)
        process<SymbolicSampleSizes::kSample32> (data);
    else
        process<SymbolicSampleSizes::kSample64> (data);
    
    gainParameter.endChanges ();
    return kResultTrue;
}

accessTransferObject_rt 函数会检查是否有新的模型状态。如果有，它就会调用 lambda，然后我们就可以把 gainParameter 设置为 stateModel.gain 的值。

为了释放 stateTransfer 对象中的内存，我们必须调用它的 clear_ui 方法。在这种只有一个 double 作为状态模型的情况下，把它保留到设置下一个状态或效果器终止为止是没有问题的。所以我们只需把它加到插件的 terminate 方法中：

tresult PLUGIN_API MyEffect::terminate ()
{
    stateTransfer.clear_ui ();
    return AudioEffect::terminate ();
}

如果模型数据占用更多内存，并且你想提前释放它，可以使用定时器或类似机制，在 setState 方法被调用后稍晚一点调用 clear_ui 方法。但这不属于本教程的范围。

如果你想使用这些工具类，可以在 SDK 的以下位置找到它们：
