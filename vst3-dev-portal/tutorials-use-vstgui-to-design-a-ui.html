目标

本教程讲解如何使用 VSTGUI。VSTGUI 附带一个 WYSIWYG 编辑器，可让你为插件创建出色的用户界面。

第 1 部分：准备工作

如果你用 VST 3 Project Generator 创建了工程并勾选了「Use VSTGUI」，可以直接跳到本教程的第 2 部分。

在使用内联 UI 编辑器之前，必须确保你以 Vst::EditController 类作为自己编辑控制器的基类，并且参数使用的是 Vst::Parameter 类或其任何子类。否则内联 UI 编辑器无法正常工作。

接下来必须把 vstgui 添加到工程中。对于使用 cmake 的用户，只需把 vstgui_support 库加到目标上：

target_link_libraries(${target} PRIVATE vstgui_support)

如果不使用 cmake，就必须手动把以下源文件加入工程：

  • vstgui/vstgui_[ios/mac/linux/win32].[cpp/mm]
  • vstgui/vstgui_uidescription.cpp
  • vstgui/plugin-bindings/vst3editor.cpp

之后必须修改工程设置，为调试构建添加一个预处理器定义：

  • VSTGUI_LIVE_EDITING=1

使用 cmake 的话，大致是这样：

target_compile_definitions(${target} PUBLIC$<$<CONFIG:Debug>:VSTGUI_LIVE_EDITING=1>)

最后，必须修改编辑控制器类，覆写 createView() 方法：

#include "vstgui/plugin-bindings/vst3editor.h"

IPlugView* PLUGIN_API MyEditController::createView (FIDStringname)
{
    if (strcmp (name, ViewType::kEditor) == 0)
    {
        return new VSTGUI::VST3Editor (this, "view", "myEditor.uidesc");
    }
    return 0;
}

同时要确保包含 vst3editor.h 头文件。

现在可以构建插件，并启动你常用的 VST 3 宿主来开始设计用户界面了。

第 2 部分：打开 VSTGUI/WYSWYG 编辑器

如果此时在宿主中打开插件 UI，你会看到一个空白的编辑器。要进入 UI 编辑器，右键点击它并选择「Open UIDescription Editor」。

完成最初的编辑后，你必须把保存的 uidesc 文件加入工程（如果你使用了 VST 3 Project Generator，这一步已经完成）。同时还要确保在修改 uidesc 文件后始终重新构建工程。

第 3 部分：参数绑定

如果你使用了 VST SDK 提供的 Parameter 类，编辑器控件与 VST 编辑控制器中的参数之间就会自动建立参数绑定。

你唯一需要做的是在 Tags 编辑器中把参数的 ID 声明为 tag（或使用工具栏 Edit 菜单中的「Sync Parameter Tags」命令），并把控件的 tag 设置为这些 ID。这样当用户操作控件时，你的 VST 编辑控制器就会收到 beginEdit(...)/performEdit(...)/endEdit(...) 调用。如果宿主对参数做了自动化，控件也会反映这些变化。

此外，你还可以修改 VST 编辑控制器，在 getParameterObject(int32 paramID) 方法中返回仅供 UI 使用的特定参数对象，而这些对象并不是 VST 音频处理器的参数。这样就可以存储视图设置（例如用户关闭编辑器时打开的是哪个选项卡，以便用户再次打开编辑器时恢复）。关于其工作方式，可以查看附带的「uidescription test」工程源码以了解更多信息。

第 4 部分：创建自定义视图

如果需要创建自定义视图，可以在编辑控制器类中实现 VSTGUI::VST3EditorDelegate 接口。如果你在某个视图中设置了「custom-view-name」属性，就会调用 createCustomView 方法。

使用自有视图的另一种方式是在运行时用 UIViewFactory 注册它们。这种方式工作量更大，但优点是视图会像内置视图一样出现在列表中，并且修改属性可即时生效。参见 VSTGUI::IViewCreator。
