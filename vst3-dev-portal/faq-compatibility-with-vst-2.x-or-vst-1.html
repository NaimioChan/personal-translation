问：如何把我的插件从 VST 2 版本更新为 VST 3 版本，并确保 Cubase 加载新版本而不是旧版本？

你必须为 kVstAudioEffectClass 与 kVstComponentControllerClass 组件提供特殊的 UID，依据其 VST 2 UniqueID（4 个字符）及其插件名称，方式如下：

static void convertVST2UID_To_FUID (FUID& newOne, int32 myVST2UID_4Chars, const char* pluginName, bool forControllerUID = false)
{
    char uidString[33];
 
    int32 vstfxid;
    if (forControllerUID)
        vstfxid = (('V' << 16) | ('S' << 8) | 'E');
    else
        vstfxid = (('V' << 16) | ('S' << 8) | 'T');
 
    char vstfxidStr[7] = {0};
    sprintf (vstfxidStr, "%06X", vstfxid);
 
    char uidStr[9] = {0};
    sprintf (uidStr, "%08X", myVST2UID_4Chars);
 
    strcpy (uidString, vstfxidStr);
    strcat (uidString, uidStr);
 
    char nameidStr[3] = {0};
    size_t len = strlen (pluginName);
 
    // !!!pluginName 必须为小写!!!!
    for (uint16 i = 0; i <= 8; i++)
    {
        uint8 c = i < len ? pluginName[i] : 0;
        sprintf (nameidStr, "%02X", c);
        strcat (uidString, nameidStr);
    }
    newOne.fromString (uidString);
}

注意，如果你在开发新插件，并且使用 SDK 中包含的 VST 2 包装层，就无需使用 convertVST2UID_To_FUID，一个 VST 2 专用的厂商调用允许宿主（Steinberg 宿主自 Cubase 4.0 起）从 VST 2 版本获取 VST 3 UID。

问：如何支持用 VST 2 版本插件保存的项目？

宿主会以完整的 FXB/FXP 流调用 Vst:: IComponent::setState() 与 Vst:: IEditController::setComponentState()。你必须从中提取旧状态，为此 SDK 提供了辅助函数 VST3::tryVst2StateLoad。

以下是当 VST 3 插件在 Steinberg 音序器项目中替代 VST 2 插件时，需要在 VST 3 版本中添加的代码：

#include "public.sdk/source/vst/utility/vst2persistence.h"
 
//------------------------------------------------------------------------
tresult PLUGIN_API MyVST3Effect::setState (IBStream* state)
{
    if (auto vst2State = VST3::tryVst2StateLoad (*state))
    {
        if ((vst2State->programs.empty ()) ||
            (static_cast<int32_t> (vst2State->programs.size ()) <= vst2State->currentProgram))
            return kResultFalse;
 
        //....
    }
    return kResultFalse;
}

完整示例源代码可查看函数：
tresult PLUGIN_API Processor::setState (IBStream state)*，它位于文件 public.sdk/samples/vst/mda-vst3/source/mdaBaseProcessor.cpp 中

为了兼容自动化，你必须确保 VST 3 的参数 ID 与其在 VST 2 中关联参数的索引值相同。只有满足这个条件，宿主才能回放自动化。参数值在 VST 2 和 VST 3 中含义相同。

问：我已经发布了一个 VST 3 插件，其 UID 与其 VST 2 对应版本不同。如何声明该 VST 3 插件可以替代其 VST 2 插件对应版本？

你可以使用 moduleinfo.json 文件的 compatibility 数组。在那里，把你 VST 3 音频效果器类的 UID 作为 “New” UID，并把你 VST 2 插件的 UID 放入 “Old” 数组。

如果无法使用 moduleinfo.json 文件，你可以创建一个实现 Vst:: IPluginCompatibility 接口的类，并通过插件工厂把它提供给宿主。

问：在 VST 2 中，编辑器可以直接访问处理部分（名为 effect）。在 VST 3 中如何做到这一点？

你不能这样做，更重要的是不得这样做。处理部分与用户界面部分通过消息系统通信。
详情参见 问：应如何在「处理」与「用户界面」之间通信？。

问：VST 3 是否实现了 VST 2 中已知的 beginEdit 与 endEdit 之类的方法？

是，而且支持这一点对自动化至关重要。详情请参见 参数与自动化

问：VST 3 是否包含像 VST 2 的 processVariableIo 那样的可变输入/输出处理？

在 3.1.0 版本中还没有，我们计划以后朝这个方向做些什么。（注意：这种 variableIO 处理例如是用于时间伸缩插件的。）

问：与 VST 2 的 kPlugCategOfflineProcess 等价的是什么？

VST 3 不像 VST 2 那样支持离线处理（该接口专供 WaveLab 使用）。但可以在离线上下文中使用 VST 3 插件（这意味着 process 函数可以比实时更快地被调用：例如在导出或批处理期间）。如果插件不支持快于实时，就应把 kOnlyRealTime 加入其类别。
