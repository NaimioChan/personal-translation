引言

VST 3 插件不再局限于固定数量的输入和输出，其 I/O 配置可以动态适应通道配置。侧链也很容易实现。这包括在加载后停用未使用的总线，以及在需要时重新激活它们的可能性。这样可以让混音器更整洁，并进一步帮助降低 CPU 负载。

可以把总线理解为归于一体的一组「数据通道」：

  • 它描述插件的数据输入（kInput）或数据输出（kOutput）。
  • 支持 2 种总线类型：kAudio 和 kEvent
  • 一个 VST 组件可以定义任意所需数量的总线。
  • 一个总线可以定义为主总线（kMain）或用于侧链的辅助总线（kAux）（在导出的总线列表中，kMain 总线必须位于任何其他 kAux 总线之前）
  • 能够处理多个总线的宿主允许用户激活总线，而这些总线最初全部处于未激活状态。

多个输入或输出总线

插件可能有各种理由定义多个事件输入总线，例如：

  • 对于支持同时加载超过 16 个子乐器的复杂多音色乐器，从宿主视角在其输入中加入某种结构（模拟若干个「MIDI 端口」及其子 MIDI 通道）
  • 或者不同的输入含义，它们在宿主中可以清楚地区分和选择：
    • 一个输入用于演奏事件
    • 一个输入用于调制事件

插件可能有各种理由定义多个事件输出总线，例如：

  • 一个主事件输出用于来自 UI 的演奏事件，另一个事件输出用于琶音器内部生成的事件。

插件可以决定导出多于一个音频输入，方法是添加第二个音频输入（侧链，见下文）或更多。

多个音频输出的典型用例是乐器插件，例如：

  • 一个主音频输出，以及若干用于 FX 返回或 FX 发送的辅助音频输出。
  • 每个内部加载的乐器各有一个主音频输出。

示例

//------------------------------------------------------------------------
tresult PLUGIN_API MyPlugin::initialize (FUnknown* context)
{
    //---总是初始化父类-------
    tresult result = AudioEffect::initialize (context);
    // 如果一切正常，继续
    if (result != kResultOk)
    {
        return result;
    }

    //---创建音频输入/输出总线------
    // 我们需要一个立体声输入和一个立体声输出
    addAudioInput (STR16 ("Stereo In"), SpeakerArr::kStereo, kMain, BusInfo::kDefaultActive);
    addAudioOutput (STR16 ("Stereo Out"), SpeakerArr::kStereo, kMain, BusInfo::kDefaultActive);

    //---创建主事件输入总线（1 个只有 16 个通道的总线）------
    addEventInput (STR16 ("Event In"), 16, kMain, BusInfo::kDefaultActive);

    //---创建辅助事件输入总线（1 个只有 1 个通道的总线）------
    addEventInput (STR16 ("Mod In"), 1, kAux, 0); // 不希望默认激活

    //---创建事件输出总线（1 个只有 1 个通道的总线）------
    addEventOutput (STR16 ("Arpeggiator"), 1, kAux, 0); // 不希望默认激活

    return kResultOk;
}

总线的信息

为了获取插件导出的总线数量与相关信息，宿主使用 Vst:: IComponent 接口的以下函数：

/** 在插件初始化之后调用。 */
virtual int32 PLUGIN_API getBusCount (MediaType type, BusDirection dir) = 0;
 
/** 在插件初始化之后调用。 */
virtual tresult PLUGIN_API getBusInfo (MediaType type, BusDirection dir, int32 index, BusInfo& bus /*out*/) = 0;

BusInfo 包含如下信息：

  • 名称，
  • 通道数量，
  • ...
  • 以及一些用于表示以下含义的标志：
    • kDefaultActive：该总线应在实例化时由宿主默认激活（会请求调用 activateBus）。默认情况下总线是未激活的。注意，如果宿主之后向用户提供激活/停用总线的功能，它可能不遵循此 kDefaultActive 标志，并在实例化时让某些总线保持未激活状态。
    • kIsControlVoltage：该总线不包含普通音频数据，而是包含按采样率进行控制变更所用的数据。
      • 数据格式与音频数据相同，为 [-1.0, 1.0]。
      • 宿主必须防止意外路由到扬声器，以避免造成损坏。
      • 仅对音频媒体类型的总线有效。

总线的激活

总线的动态使用由宿主通过激活和停用总线来处理。所有总线最初都是未激活的。

插件必须定义其中哪些总线在插件实例化后默认激活，这只是一个愿望，宿主可以不予遵循，例如只激活第一个总线。

// 这里希望默认激活（但不保证）
addAudioInput (STR16 ("SideChain"), SpeakerArr::kStereo, kAux, BusInfo::kDefaultActive);

为了能够使用，每个输入总线和每个输出总线都必须被激活，这由宿主通过插件实现的接口（Vst:: IComponent）完成：

//------------------------------------------------------------------------
tresult PLUGIN_API Component::activateBus (MediaType type, BusDirection dir, int32 index, TBool state)
{
    // ...

已停用的总线不需要由插件处理，这有助于降低 CPU 负载。

什么是侧链？

在音频应用中，某些插件允许向插件提供第二路信号，并将其作为一个或多个处理参数的控制器。这样的信号通常称为侧链信号或侧链输入。

示例：

如果录制的底鼓被认为演奏得很好，但贝斯手部分的录音显示他经常略微抢在底鼓之前，那么对贝斯部分带「门控」功能的插件可以把底鼓信号用作侧链，将贝斯部分精确地「修剪」到与底鼓一致。

另一种应用是，当另一路信号（例如人声）达到某一电平时，自动降低音乐背景的电平。这种情况下会使用带「闪避」功能的插件——当人声信号送入侧链输入时，主音乐信号被衰减。

延迟的混合参数可以由侧链输入信号控制——使延迟信号量正比于另一路信号的电平。

侧链可以用作额外的调制源，而不是周期性的调制形式。从插件的角度看，侧链输入和/或输出是额外的输入和输出，可由宿主启用或禁用。

宿主（如果支持）会向用户提供一种方式，把某些信号通路路由到这些侧链输入，或从侧链输出路由到其他信号输入。

如何在插件中实现侧链通路？

在 AudioEffect::initialize (FUnknown* context) 中，必须添加插件所需的总线和扬声器配置。例如，如果你的插件处理一个输入总线和一个输出总线，且两者都是立体声，相应的代码片段如下所示：

addAudioInput (USTRING ("Stereo In"), SpeakerArr::kStereo);
addAudioOutput (USTRING ("Stereo Out"), SpeakerArr::kStereo);
 
// 此外，添加一个立体声侧链总线的方式如下：
addAudioInput (USTRING ("Aux In"), SpeakerArr::kStereo, kAux, 0); // 这里的 0 表示不希望默认激活

音频总线的通道配置

每个音频总线都有其通道配置，即一个扬声器布置：

立体声（L+R）

const SpeakerArrangement kStereo = kSpeakerL | kSpeakerR;

不同扬声器是如何定位的？

以下是主要已定义扬声器位置的概览（参见 enum Speakers 和 namespace SpeakerArr）。SpeakerArrangement 是扬声器的位集组合。

例如：

const SpeakerArrangement kStereo = kSpeakerL | kSpeakerR; // => 十六进制表示为 0x03，二进制表示为 0011。

我的插件能够处理所有可能的通道配置

添加总线时，我应选择哪种扬声器布置？

选择你的插件最可能被使用的配置。对于 5.1 环绕声设置，那就是：

addAudioInput (USTRING ("Surround In"), SpeakerArr::k51);
addAudioOutput (USTRING ("Surround Out"), SpeakerArr::k51);

但当宿主调用 Vst:: IAudioProcessor::setBusArrangements 时，宿主是在告知插件它被选择所在轨道的当前扬声器布置。如果你接受该布置，应返回 kResultOk；如果不接受，则返回 kResultFalse。

ⓘ注意
如果你拒绝 Vst:: IAudioProcessor::setBusArrangements 并返回 kResultFalse，宿主会调用 Vst:: IAudioProcessor::getBusArrangement，此时你有机会把参数 'arrangement' 设为你的插件对该给定总线所接受的扬声器布置的值。

随后宿主可以用插件所希望的布置重新调用 Vst:: IAudioProcessor::setBusArrangements，这时插件应返回 kResultOk。

FX 插件的扬声器布置设置是如何处理的？

在插件实例化之后，宿主会以默认配置（取决于当前通道配置）调用 Vst:: IAudioProcessor::setBusArrangements；如果插件接受（通过返回 kResultOK），就继续使用该配置。如果不接受（通过返回 kResultFalse），宿主会调用 Vst:: IAudioProcessor::getBusArrangement（针对输入和输出）询问插件所希望的布置，然后以最终希望的布置重新调用 Vst:: IAudioProcessor::setBusArrangements。参见总线布置设置序列工作流程。

// 示例：仅支持对称输入-输出布置的插件：

host -> plug-in: setBusArrangements (monoIN, stereoOUT)
plug-in return: kResultFalse
host -> plug-in: getBusArrangement (IN) => return Stereo;
host -> plug-in: getBusArrangement (OUT) => return Stereo;
host -> plug-in: setBusArrangements (stereoIN, stereoOUT)
plug-in return: kResultOk

// 示例：仅支持非对称输入-输出布置（单声道->立体声）的插件：

host -> plug-in: setBusArrangements (stereoIN, stereoOUT)
plug-in return: kResultFalse
host -> plug-in: getBusArrangement (IN) => return Mono;
host -> plug-in: getBusArrangement (OUT) => return Stereo;
host -> plug-in: setBusArrangements (MonoIN, stereoOUT)
plug-in return: kResultOk

// 示例：仅支持非对称输入-输出布置（单声道-> 立体声直至 5.1）的插件：

host -> plug-in: setBusArrangements (5.1IN, 5.1OUT)
plug-in return: kResultFalse
host -> plug-in: getBusArrangement (IN) => return Mono;
host -> plug-in: getBusArrangement (OUT) => return 5.1;
host -> plug-in: setBusArrangements (MonoIN, 5.1OUT)
plug-in return: kResultOk

// 宿主 -> 插件：setBusArrangements (QuadroIN, QuadroOUT)

plug-in return: kResultFalse
host -> plug-in: getBusArrangement (IN) => return Mono;
host -> plug-in: getBusArrangement (OUT) => return Quadro;
host -> plug-in: setBusArrangements (MonoIN, QuadroOUT)
plug-in return: kResultOk

// 示例：仅支持对称输入-输出布置、且侧链输入始终为单声道的插件：

host -> plug-in: getBusArrangements (IN) => Input Main:Mono / Input Side-chain:Mono
host -> plug-in: getBusArrangements (OUT) => Output: mono
host -> plug-in: setBusArrangements (Input Main:stereo / Input Side-chain:Mono, Output: stereo)
plug-in return: kResultTrue

or
host -> plug-in: getBusArrangements (IN) => Input Main:Mono / Input Side-chain:Mono
host -> plug-in: getBusArrangements (OUT) => Output: mono
host -> plug-in: setBusArrangements (Input Main:stereo / Input Side-chain:stereo, Output: stereo)
plug-in return: kResultFalse // 因为我们希望侧链为单声道
host -> plug-in: getBusArrangement (IN) => return Input Main:stereo / Input Side-chain:mono;
host -> plug-in: getBusArrangement (OUT) => return Stereo;
host -> plug-in: setBusArrangements (Input Main:stereo / Input Side-chain:mono, Output: stereo)
plug-in return: kResultOk

// 示例：仅支持对称输入-输出布置、且侧链输入跟随主输入布置的插件：

host -> plug-in: getBusArrangements (IN) => Input Main:Mono / Input Side-chain:Mono
host -> plug-in: getBusArrangements (OUT) => Output: mono
host -> plug-in: setBusArrangements (Input Main:stereo / Input Side-chain:Mono, Output: stereo)
plug-in return: kResultFalse // 因为我们希望主输入和侧链使用相同的布置
host -> plug-in: getBusArrangement (IN) => return Input Main:stereo / Input Side-chain:stereo;
host -> plug-in: getBusArrangement (OUT) => return Stereo;
host -> plug-in: setBusArrangements (Input Main:stereo / Input Side-chain:stereo, Output: stereo)
plug-in return: kResultOk

如何向宿主报告插件的布置已更改？

在加载预设或用户交互时，插件希望更改其 IO 配置。这种情况下，插件应从 editController 调用其组件处理器，并带上 kIoChanged 标志：

componentHandler->restartComponent (kIoChanged);

宿主会调用 Vst:: IAudioProcessor::getBusArrangement（针对输入和输出）以检查新请求的布置，然后宿主会调用 Vst:: IAudioProcessor::setBusArrangements（在挂起状态下调用：setActive (false)）以确认所请求的布置。

我的插件是单声道输入、立体声输出。VST 3 如何处理这种情况？

有以下两种方式可以这样实例化插件：

  • 方式 1

在 AudioEffect::initialize (FUnknown* context) 中添加一个单声道总线和一个立体声总线。

//---------------------------------------------------------------
tresult PLUGIN_API AGain::initialize (FUnknown* context)
{
    //---总是初始化父类-------
    tresult result = AudioEffect::initialize (context);
    // 如果一切正常，继续
    if (result != kResultOk)
    {
        return result;
    }

    addAudioInput (USTRING ("Mono In"), SpeakerArr::kMono);
    addAudioOutput (USTRING ("Stereo Out"), SpeakerArr::kStereo);
    //...

当宿主为 Cubase/Nuendo 时，插件在插入立体声轨道后会得到立体声输入信号的左声道作为其单声道输入。你可以从这个信号创建立体声输出信号。

  • 方式 2

在 AudioEffect::initialize (FUnknown* context) 中添加一个立体声输入总线和一个立体声输出总线。

//---------------------------------------------------------------
tresult PLUGIN_API AGain::initialize (FUnknown* context)
{
    //---总是初始化父类-------
    tresult result = AudioEffect::initialize (context);
    // 如果一切正常，继续
    if (result != kResultOk)
    {
        return result;
    }

    addAudioInput (USTRING ("Stereo In"), SpeakerArr::kStereo);
    addAudioOutput (USTRING ("Stereo Out"), SpeakerArr::kStereo);
    //...

处理时，你的插件算法只取左声道，或者把左、右声道的样本相加来创建新的单声道输入信号。
