目标

本教程讲解如何将 cmake 与 VST SDK 一起使用。

用于构建 VST 3 插件的 CMake

SDK 提供了一组 cmake 文件，让你可以编译随附的示例并开发新的插件。

  • 从以下地址下载 cmake：https://cmake.org，或使用适用于你的操作系统的包管理器（参见 如何为 VST 3 配置系统）。
  • 你可以使用命令行或 cmake 编辑器（cmake-gui）。

Windows 的命令行

构建 Microsoft Studio 17 2022 解决方案的示例：

// 进入你解压 VST SDK 的文件夹
mkdir build
cd build
cmake.exe -G "Visual Studio 18 2026" -A x64 "..\vst3sdk"
// 或者不使用符号链接
cmake.exe -G "Visual Studio 18 2026" -A x64 "..\vst3sdk" -DSMTG_CREATE_PLUGIN_LINK=0

// 或者使用符号链接但采用用户位置（默认启用），它不需要管理员权限
cmake.exe -G "Visual Studio 18 2026" -A x64 "..\vst3sdk" -DSMTG_PLUGIN_TARGET_USER_PROGRAM_FILES_COMMON=1

// 注意：你可以在 cmake 在线文档中找到不同 Visual Studio 生成器的字符串定义

macOS 的命令行

构建 Xcode 工程的示例：

// 进入你解压 VST SDK 的文件夹
mkdir build
cd build
/Applications/CMake.app/Content/bin/cmake -G"Xcode" "../vst3sdk"

在 Linux 上使用 QtCreator

你可以使用 QtCreator 2.3.1（或更高版本）

  • 启动 QtCreator 2.3.2
  • 打开位于 VST3_SDK 文件夹顶层的 CMakeLists.txt
  • 点击菜单 Build->Run CMake

使用 cmake-gui

  • 启动 CMake（cmake-gui）应用
  • 将 Where is the source code 设为 VST3_SDK 文件夹的位置
  • 将 Where to build the binaries 设为你选择的构建文件夹
  • 点击 Configure
  • 点击 Generate 创建工程/解决方案

Windows 上 cmakegui 应用的示例

  • 使用 cmake 命令行编译
cd build
cmake --build
  • 使用 cmake 选择特定的编译器（Linux 上的命令行）
cmake -DCMAKE_C_COMPILER=/usr/bin/clang-DCMAKE_CXX_COMPILER=/usr/bin/clang++

// 或者

cmake -DCMAKE_C_COMPILER=/usr/bin/gcc-DCMAKE_CXX_COMPILER=/usr/bin/g++

可用的 SMTG cmake 选项

  • SMTG_AAX_SDK_PATH：在这里可以定义 AAX SDK 的位置（如需要）
  • SMTG_ADD_VST3_UTILITIES：构建 VST 实用工具（默认 ON）
  • SMTG_CREATE_MODULE_INFO：创建 moduleinfo.json 文件（默认 ON）
  • SMTG_CUSTOM_BINARY_LOCATION：自定义二进制文件的输出位置
  • SMTG_CXX_STANDARD：插件使用的 C++ 标准版本：14、17、20、23
  • SMTG_ENABLE_ADDRESS_SANITIZER：启用 Address Sanitizer（默认 OFF）
  • SMTG_ENABLE_TARGET_VARS_LOG：启用以记录用于调试的目标变量（自 3.6.11 起新增！）（默认 OFF）
  • SMTG_ENABLE_VST3_HOSTING_EXAMPLES：启用 VST 3 宿主示例（默认 ON）
  • SMTG_ENABLE_VST3_PLUGIN_EXAMPLES：启用 VST 3 插件示例（默认 ON）
  • SMTG_ENABLE_VSTGUI_SUPPORT：启用 VSTGUI 支持（默认 ON）
  • SMTG_MDA_VST3_VST2_COMPATIBLE：将 MDA 示例构建为其 VST 2 对应版本的替代品（默认 ON）
  • SMTG_PLUGIN_TARGET_USER_PATH：在这里可以重新定义 VST 3 插件文件夹
  • SMTG_RENAME_ASSERT：将 ASSERT 重命名为 SMTG_ASSERT，以避免与第三方库冲突（默认 ON）
  • SMTG_RUN_VST_VALIDATOR：每次构建 VST 3 插件时运行 VST 校验器（默认 ON）

Windows 特有

  • SMTG_CREATE_BUNDLE_FOR_WINDOWS：在 Windows 上为 VST 3 插件创建 bundle（自 3.6.10 起新增！）（默认 ON）
  • SMTG_CREATE_PLUGIN_LINK：在 ${VST3_FOLDER_NAME} 文件夹中为每个 VST 3 插件创建符号链接（你需要拥有 Windows 管理员权限，或修改本地组策略以允许创建符号链接）（默认 ON）
  • SMTG_PLUGIN_TARGET_USER_PROGRAM_FILES_COMMON：使用 FOLDERID_UserProgramFilesCommon 作为 VST 3 目标路径（默认 ON）
  • SMTG_USE_STATIC_CRT：在 Windows 上使用静态 CRuntime（选项 /MT）（默认 OFF：使用 /MD）

macOS/iOS 特有

  • SMTG_AUDIOUNIT_SDK_PATH：AudioUnit SDK 的路径
  • SMTG_BUILD_INTERAPPAUDIO：启用构建 iOS InterAppAudio 示例（已弃用）（默认 OFF）
  • SMTG_BUILD_UNIVERSAL_BINARY：构建通用二进制文件（32 位和 64 位）
  • SMTG_CODE_SIGN_IDENTITY_IOS：iOS 代码签名标识
  • SMTG_CODE_SIGN_IDENTITY_MAC：macOS 代码签名标识
  • SMTG_COREAUDIO_SDK_PATH：在这里可以定义 COREAUDIO SDK 的位置
  • SMTG_DISABLE_CODE_SIGNING：禁用所有代码签名（默认 OFF）
  • SMTG_ENABLE_IOS_TARGETS：启用构建 iOS 目标（默认 OFF）
  • SMTG_IOS_DEVELOPMENT_TEAM：构建适用于 iOS 的 InterAppAudio（已弃用）和 AUv3 示例所需
  • SMTG_VSTSDK_GENERATE_MACOS_IOS_COLLECTION_TARGETS：创建 macOS 和 iOS 集合目标（默认 OFF）
  • SMTG_XCODE_MANUAL_CODE_SIGN_STYLE：手动 Xcode 签名样式（默认 OFF）
  • SMTG_XCODE_OTHER_CODE_SIGNING_FLAGS：其他代码签名标志 [Xcode]（默认 --timestamp）

Linux 特有

  • SMTG_ENABLE_WAYLAND_SUPPORT：启用 Wayland 支持（默认 OFF）

使用你的 IDE 编译示例

  • 解决方案/工程（vstsdk.sln/vstsdk.xcodeproj）生成在 "build" 文件夹中。
  • 创建的插件位于 "build" 文件夹中，在 /VST3/Release 或 /VST3/Debug 子文件夹下。
  • 为了让 DAW 找到这些插件，你必须创建从官方 VST 3 位置 指向它们的链接。
