问：音频处理旁通如何工作？

为了实现音频处理旁通，插件可以导出一个额外且专门标记了 kIsBypass 属性的参数。当用户在宿主中启用插件旁通时，就像所有参数变更一样，该变更会作为传给 Vst:: IAudioProcessor::process 方法的参数数据的一部分被发送。

旁通功能的实现完全由插件负责：

Vst:: IAudioProcessor::process 方法仍会继续被调用。插件必须自行处理无爆音的切换（渐变/淡入/淡出、并行处理或算法切换）；如果插件有延迟，还必须提供延迟动作，并确保输出缓冲区提供输入缓冲区的副本（可能带延迟）。当指针相同且插件没有延迟时，无需把输入缓冲区复制到输出缓冲区！

插件可以选择像处理其他参数一样，以逐采样精确（使用参数变更的 sampleOffset）或基于音频块（音频块长度过大 > 1024 时不推荐）的方式处理旁通。

旁通期间 process 仍会被调用，但若由于某种原因没有调用，宿主可能会发起一次 flush（使用带空音频缓冲区的 process 调用）。

ⓘ 注意
插件需要像其他参数一样，把旁通参数保存在其状态中。

问：如果关联的总线已停用，宿主还必须提供有效的已初始化音频缓冲区吗？

在正确实现的宿主中，如果宿主中存在某个输入或输出总线，而它与插件断开连接，插件将收到断开连接的信息（总线激活）。

此外，输入总线已断开的插件会继续收到默认的静音缓冲区；同样，输出总线已断开的插件，如果其后还有已激活的总线，会继续收到默认的 nirvana 缓冲区。当这些停用的总线是最后的总线（输入或输出）时，宿主无需提供关联的 AudioBusBuffers，此时插件应检查 numInputs 与 numOutputs，并且不处理这些总线。

下表显示了缓冲区是否可用，取决于哪些总线被激活：

问：插件处理期间最大采样块大小会改变吗？

最大采样块大小（maxSamplesPerBlock）可以在插件生命周期内改变，但音频组件处于活动状态时不行。因此，插件处于活动状态时，最大采样块大小（maxSamplesPerBlock）绝不能在处理调用期间或调用之间改变。

如果宿主改变了最大采样块大小，它会专门调用以下序列：

Vst::IAudioProcessor::process (...);
Vst::IAudioProcessor::setProcessing (false);
Vst::IAudioProcessor::setActive (false);

Vst::IAudioProcessor::setupProcessing (...);

Vst::IAudioProcessor::setActive (true);
Vst::IAudioProcessor::setProcessing (true);
Vst::IAudioProcessor::process (...);

注意，ProcessData->numSamples 表示一次 process 调用中使用了多少个采样，它可以逐次调用变化，但绝不会大于 maxSamplesPerBlock。

问：插件处理期间采样率会改变吗？

不会。与 问：插件处理期间最大采样块大小会改变吗？ 相同。

问：宿主可以在没有音频缓冲区的情况下调用 process 函数吗？

可以，宿主可以在没有缓冲区的情况下调用 Vst:: IAudioProcessor::process（numInputs 与 numOutputs 置零），以便 flush 参数（从宿主到插件）。

问：如何向宿主报告插件延迟已改变？

插件应通过 editController 调用其组件处理器的 restartComponent 函数，并带上标志 kLatencyChanged：

componentHandler->restartComponent (kLatencyChanged);

宿主将调用 Vst:: IAudioProcessor::getLatencySamples() 以检查新的延迟，并在支持时调整其延迟补偿。

问：Vst:: IAudioProcessor::setProcessing 可以在没有任何 Vst:: IAudioProcessor::process 调用的情况下被调用吗？

可以，这取决于 DAW 如何支持其处理，以下调用序列是合法的：

Vst::IAudioProcessor::process (...);
Vst::IAudioProcessor::setProcessing (false);
Vst::IAudioProcessor::setProcessing (true);
// 此处没有调用 process，DAW 中间可能发生了某些事情
Vst::IAudioProcessor::setProcessing (false);
Vst::IAudioProcessor::setProcessing (true);
Vst::IAudioProcessor::process (...);

问：如何确保插件始终被处理？

如果你的插件始终产生声音而不需要任何音频输入，可以把类别 “Generator” 添加到 subCategories（例如使用 kFxGenerator），或者在函数 Vst:: IAudioProcessor::getTailSamples 中返回 kInfiniteTail

问：可以在处理期间调用 IComponent::getState()/setState() 吗？

可以，当插件在实时上下文中使用时，setState 与 getState 通常从 UI 线程 调用；在离线上下文中，set/getState 可以在与 process 调用相同的线程中调用。关于在哪种状态下会调用哪些接口的更多信息，请查看工作流程图「音频处理器调用序列」。

问：如何告知插件它当前正在离线处理中被处理？

当插件在离线处理上下文中使用（例如 Cubase 9.5/Nuendo 8 的功能：直接离线处理）时，其组件会以 Vst:: IComponent::setIoMode（Vst::kOfflineProcessing）初始化（参见 The Simple Mode）。离线处理模式（在 process 调用中传入）用于以下情况：

  • 用户导出音频（缩混）
  • 直接离线处理功能

通过 Vst:: IComponent::setIoMode（Vst::kOfflineProcessing），你可以区分导出与 DOP（直接离线处理）。

自 Cubase 9.5 起支持直接离线处理

问：在实时 process 函数中不应调用什么？

一个良好的做法是避免在这个关键的实时 process 中调用任何库函数。如果必须使用，请检查它们是否为实时操作而设计，且不包含任何加锁机制。避免任何文件系统访问、网络和 UI 调用、内存分配与释放；使用可能在后台分配内存的 STL 容器时要小心，优先使用非阻塞内存池之类的模式，并把需要内存/文件/网络访问的任务交给 UI/定时器线程处理。也请查看 音频处理器调用序列。
