介绍 VST 3 中如何处理预设与程序列表。

预设格式的定义请参见 VST 3 位置 / 格式。

简单插件

对于简单插件，预设的数据不过就是它的状态。在这种情况下：

  • 为插件管理预设处理是宿主的任务。

  • 插件本身完全不需要在其 GUI 中提供任何加载预设的手段，也不需要定义任何程序列表。

  • 工厂预设必须作为文件安装到所需的位置（见 预设位置）。

宿主必须提供用于加载和保存预设文件的 GUI。这些文件包含插件通过 Vst:: IComponent::getState 填入流中的数据。VST 3 在 OS 文件系统中定义了专门的位置（见 预设位置），因此宿主不需要显示文件选择对话框。它知道在哪里查找特定插件的预设文件，以及在哪里创建它们。因此它可以创建一个用于选择预设的弹出列表，或任何其他它选定的 GUI。加载预设后，宿主负责（从控制器部分）重新扫描参数值。因此，控制器必须确保在加载预设时获得正确的参数状态（这是通过 Vst:: IEditController::setComponentState 完成的）。

另见 组件之间的通信 和 持久化。

程序列表

如果插件使用大量程序，而这些程序需要某种缓存或需要预加载，那么使用预设文件可能不是足够的选择。在这种情况下，插件可以定义程序列表。为此，编辑控制器必须通过接口 Vst:: IUnitInfo 进行扩展。

  • 如果插件定义的程序列表用作工厂预设池，则不得允许用户通过参数编辑的方式更改这些预设。相反，它应把相应的数据加载到某种工作内存中，并把可能的修改存储为组件状态。此外，可以允许用户把修改存储为预设文件。

  • 如果插件定义的程序列表用作初始处于「空」状态的用户预设池，则可以直接对列表项应用修改。只有在程序确实需要大量资源、必须缓存才能实现快速程序切换时（基于采样的插件就是很好的例子），才应选择这种使用程序列表的方式。

  • 插件可以提供用于选择程序的 GUI，但它必须使宿主也能显示列表和所选程序。所选程序在列表中的索引必须作为程序选择参数导出。（Vst:: ParameterInfo::kIsProgramChange）

  • 插件可以允许宿主读写列表项的程序数据。为此，插件必须实现 Vst:: IProgramListData 接口，作为组件部分的扩展。

程序列表的结构

所有程序始终以平面列表的形式传输给宿主。但插件可以为列表中的每个程序分配若干属性。这使宿主能够以非常灵活的方式组织和筛选它们。属性值通过 Vst:: IUnitInfo::getProgramInfo 查询。可能的属性标识符定义在命名空间 Vst::PresetAttributes 中。例如，指定程序类别的属性标识符是 Vst::PresetAttributes::kInstrument。尽管名称暗示它只应用于乐器，但它可以用于任何类型的音频插件。例如，某个程序的乐器类别值为「Piano」。但也可以指定像「Acoustic Piano」这样的子类别。在这种情况下，字符串需要按以下方式串联：
「Piano|Acoustic Piano」。例如，这使宿主能够在类别树视图中组织预设。

音高名称

音高名称旨在用于鼓组程序，其中不同的鼓声通过音符音高来寻址。例如，为了在鼓编辑器中显示某个音高所对应鼓乐器的名称，宿主会调用 Vst:: IUnitInfo::hasProgramPitchNames 来确定是否支持音高名称，并调用 Vst:: IUnitInfo::getProgramPitchName 来查询单个音符的音高名称。

另见 VST 3 单位多音色程序列表，并查看 pitchnames VST 3 插件示例。
