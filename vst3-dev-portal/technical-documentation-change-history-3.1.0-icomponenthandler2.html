引言

改进插件在宿主中的集成（脏状态、请求打开编辑器、组编辑）。

为编辑控制器扩展的宿主回调接口 Vst:: IComponentHandler2。

  • [host imp]
  • [扩展 Vst:: IComponentHandler]
  • [发布于：3.1.0]
  • [optional]

脏状态支持

这使插件能够告知宿主其内部状态是否为脏状态。如果设为 true，意味着在保存之后又发生了进一步更改（除参数更改之外）。这种情况下，宿主应在退出前保存。

void MyPluginController::informHostAboutMyDirtyState (bool dirty)
{
    if (auto componentHandler2 = Steinberg::U::cast<IComponentHandler2> (componentHandler))
        componentHandler2->setDirty (dirty);
}

打开编辑器请求支持

请求宿主在下次可能时打开插件的编辑器。你应使用此方式，而不是显示警告框并阻塞程序流程（尤其是在加载项目时）。

void MyPluginController::requestHostToOpenEditor()
{
    if (auto componentHandler2 = Steinberg::U::cast<IComponentHandler2> (componentHandler))
        componentHandler2->requestOpenEditor ();
}

UI 组编辑

这部分处理来自插件 UI 的参数组编辑。它封装了一组：

  • Vst:: IComponentHandler::beginEdit
  • Vst:: IComponentHandler::performEdit
  • Vst:: IComponentHandler::endEdit

函数（参见 Vst:: IComponentHandler），在写入自动化时它们应在宿主中使用相同的时间戳，从而可以更好地同步一次性发生的多个参数更改。

不同用例的示例

//--------------------------------------
// 我们在 editcontroller 中...
// 对于多个开关按钮的情况（关联的 ParamID 为 1 和 3）
// 鼠标按下时：
hostHandler2->startGroupEdit ();
hostHandler->beginEdit (1);
hostHandler->beginEdit (3);
hostHandler->performEdit (1, 1.0);
hostHandler->performEdit (3, 0.0); // 例如与 paramID 1 相反
//....
// 鼠标松开时：
hostHandler->endEdit (1);
hostHandler->endEdit (3);
hostHandler2->finishGroupEdit ();
//....
//....
//--------------------------------------
// 对于多个推子的情况（关联的 ParamID 为 1 和 3）
// 鼠标按下时：
hostHandler2->startGroupEdit ();
hostHandler->beginEdit (1);
hostHandler->beginEdit (3);
hostHandler2->finishGroupEdit ();
//....
// 鼠标移动时：
hostHandler2->startGroupEdit ();
hostHandler->performEdit (1, x); // x 是所需的值
hostHandler->performEdit (3, x);
hostHandler2->finishGroupEdit ();
//....
// 鼠标松开时：
hostHandler2->startGroupEdit ();
hostHandler->endEdit (1);
hostHandler->endEdit (3);
hostHandler2->finishGroupEdit ();

另见 Vst:: IComponentHandler、Vst:: IEditController。
