目标

这里可以找到一些关于如何为已有 VST 2 版本的插件编写 VST 3 版本的信息。本指南有助于确保宿主用你的插件的新 VST 3 版本正确替换旧的 VST 2 版本。

对 VST 3 宿主来说，关键信息是（处理器）插件的 UID。凭借这一信息，它就能找到要使用的正确 VST 3 版本。

可能有两种情况：插件的 VST 3 与 VST 2 版本具有相同的 UID，或者不具有相同的 UID。

插件的 VST 2 与 VST 3 版本具有相同的 UID

可以把 VST 2 版本生成的 UID 复用于 VST 3 插件（基于 4 个字符加上其名称），这在大多数 VST 3 宿主上应当可行。请查看用于生成 VST 3 UID 的函数（输入为 VST 2 UID）这里，并把该值复用为 VST 3 插件的 UID（处理器组件 UID）。

插件的 VST 2 与 VST 3 版本不具有相同的 UID

对于这种用例，从 VST SDK 3.7.5 版起，VST 3 插件有两种方式告知宿主它可以替换哪个 VST 2 插件：

使用 moduleinfo.json 文件

Compatibility json 数组位于 moduleinfo.json 中，它可以列出可被 VST 3 插件替换的 UID。

使用 IPluginCompatibility 接口

插件应实现该接口（pluginterfaces/base/iplugincompatibility.h），条件是 moduleinfo.json 文件无法使用（例如没有可用的 bundle 时）。请查看这里。

预设/工程兼容性 VST 2 <-> VST 3

请查看这里的常见问题，其中展示了如何使用辅助函数 VST3::tryVst2StateLoad 把 VST 2 状态读入 VST 3 插件。

可以为 VST 2 向后兼容写回，方法是使用辅助函数 VST3::writeVst2State（public.sdk/source/vst/utility/vst2persistence.h）。

参数兼容性

VST 2 使用索引来标识参数，而 VST 3 使用 ID。为确保兼容性，VST 3 参数的 ID 应保持与 VST 2 索引值相同（从 0 开始）。

如果无法保持索引与 ID 相同，可以使用 3.7.11 版新增的 VST 3 API IRemapParamID，在旧插件（VST 3 或 VST2）与较新插件之间重映射参数。

如果参数范围或行为没有改变，宿主中先前的参数自动化应当能正确回放。

如果你改变了参数的含义（范围、从归一值到普通值的转换），建议为该参数创建新的 ID。

你可以在 VST 3 插件中使用 Unit 为参数添加结构。
