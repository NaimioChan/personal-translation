问：我需要把现有的基于 VST 3 的产品更新到 MIT 许可证吗？

  • 不需要。现有产品可以继续使用你当前的许可证。

问：我可以切换到 MIT 许可证吗？

  • 可以。只需使用以 MIT License 许可的 VST SDK 版本，并遵守其条款。

问：在 MIT 许可证下，我必须公开源代码吗？

  • 不必。MIT License 不要求你公开源代码。
  • 唯一的义务是：你必须在代码的所有副本或重要部分中包含原始版权声明和 MIT license 文本。
  • 换句话说：你可以在 MIT license 下许可你的项目，而无需公开源代码。只有在分享或分发软件时，你才需要提供许可证和版权声明。

问：我想在 GitHub 或类似平台上分享我的 VST 3 插件/宿主的源代码。

  • 可以。由于 VST SDK 采用 MIT License，你可以自由地在 GitHub 等平台上分享包含或引用 VST SDK 的插件或宿主源代码。你也可以以二进制形式分发你的插件/宿主。

ⓘ 注意：遵循 Steinberg VST 使用准则 被视为最佳实践，但它是可选的。

问：我想以免费软件/共享软件的形式分发我的 VST 3 插件/宿主，或仅以二进制形式出售它。

  • 可以。MIT License 允许你以免费软件、共享软件或付费版本的形式，以二进制形式分发或出售你的插件/宿主。

ⓘ 注意：遵循 Steinberg VST 使用准则 被视为最佳实践，但它是可选的。

问：我想改造 VST SDK 的源代码以满足我的 VST 3 插件/宿主的需求。

  • 可以。在 MIT License 下，你可以自由地改造和修改 VST SDK 源代码以满足你的特定需求。
  • 如果你认为你的改动应当纳入 SDK，请联系我们（使用 sdk.steinberg.net）。

问：我可以复用他人分发的修改版 VST SDK 吗？

  • 可以。MIT License 允许复用修改版的 SDK。

问：我想以二进制形式出售基于第三方 SDK（如 JUCE）的 VST 3 插件/宿主。

  • 可以。即使基于第三方 SDK，你也可以以二进制形式分发或出售你的插件/宿主。

ⓘ 注意：遵循 Steinberg VST 使用准则 被视为最佳实践，但它是可选的。

问：我想以二进制形式分发基于第三方 SDK（如使用 GPLv3 许可证的 JUCE）的 VST 3 插件/宿主。

  • 可以，MIT license 与 GPLv3 兼容。

ⓘ 注意：遵循 Steinberg VST 使用准则 被视为最佳实践，但它是可选的。

VST 2 专属内容

问：我想在 GitHub 或其他基于 Web 的交流平台上分享我的 VST 2 插件/宿主的源代码。

  • 这是允许的，但务必不要包含 Steinberg 的 VST 2 文件，例如 aeffect.h 和 aeffectx.h。这些文件采用不同的许可证，不允许再分发！

问：我是开发者/公司，我想以二进制形式开发和分发 VST 2 插件和/或宿主。

  • 如果你已签署 VST 2 许可协议（2018 年 10 月之前），则可以。
  • 如果没有，则不允许分发！
  • 参见此处！
