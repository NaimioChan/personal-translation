主组件

本教程介绍如何通过创建主内容组件，向应用程序窗口添加图形内容。这对于在窗口中向用户显示内容非常重要。

难度：初级
平台：Windows、macOS、Linux
类：DocumentWindow, Component, Graphics

准备工作

启动 Projucer，创建一个名为 MainComponentTutorial 的新 GUI 应用项目。在 Files to Auto-Generate: 字段中，确保选中 Create a Main.cpp file only。

如果这一步需要帮助，请参阅教程：Projucer 第 1 部分：Projucer 入门。

修改 MainComponentTutorialApplication 类，在其中加入下面的 MainWindow 类：

//==============================================================================
class MainComponentTutorialApplication : public juce::JUCEApplication
{
public:
    //...
    //==============================================================================
    class MainWindow : public juce::DocumentWindow
    {
    public:
        MainWindow (juce::String name) : DocumentWindow (name,
                                             juce::Colours::lightgrey,
                                             DocumentWindow::allButtons)
        {
            setUsingNativeTitleBar (true);
            centreWithSize (300, 200);
            setVisible (true);
        }
        void closeButtonPressed() override
        {
            JUCEApplication::getInstance()->systemRequestedQuit();
        }
    private:
        JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR (MainWindow)
    };
private:
    std::unique_ptr<MainWindow> mainWindow;
};

在 initialise() 函数中添加下面这行：

void initialise (const juce::String& commandLine) override
{
    mainWindow.reset (new MainWindow (getApplicationName()));
}

最后，在 shutdown() 函数中添加下面这行：

void shutdown() override
{
    mainWindow = nullptr;
}

简介

在上一篇教程（教程：应用程序窗口）中，我们介绍了主窗口，它充当应用程序图形界面的框架。在本教程中，我们将创建一个主内容组件，它是显示应用界面内容的对象。主内容组件对每个 JUCE 应用都是必不可少的对象。

如果你用 The Projucer 创建新的 GUI 应用，它会自动为你生成一个主内容组件。不过，熟悉这个概念并理解 JUCE 应用结构的一个好方法，是自己创建这样一个主内容组件。这就是我们在本教程中要做的事。

在你的 IDE 中打开教程项目。我们从上一篇教程结束的地方继续：一个空的应用程序窗口。在 Main.cpp 文件中，我们有一个 MainWindow 类。上一篇教程（教程：应用程序窗口）中我们已经学会了如何使用它。现在，我们要往这个窗口里填充内容！

不过，在做这件事之前，我们先进一步探讨一下组件的概念。

Component 类

JUCE 所有图形界面最重要的基类是 Component 类。在 JUCE 中，GUI 几乎所有可见元素——无论是按钮、滑块还是文本字段——都是组件，都派生自这个类。在 JUCE 中编写这类应用的方法是创建一个主组件，它由主应用程序窗口拥有，是窗口的内容。然后所有其他组件都成为这个主组件的子组件（参见教程：父组件和子组件）。我们的 MainWindow 所派生的 DocumentWindow 类包含必要的功能，以确保主窗口正确显示其内容（包括主组件及其子组件）。

请记住：JUCE 中的所有图形元素都派生自 Component 类。要构建 GUI，需要把不同的组件按父组件和子组件的嵌套层级排列。最顶层的组件称为主内容组件。详见教程：父组件和子组件。

添加主组件类

创建新的源文件

现在来创建我们的主组件类。为此，我们需要创建新的文件，用来存放这个类的源代码。回到 The Projucer 并在其中打开教程项目。在左侧，确保 Files 浏览器处于打开状态。然后右键单击 Source 组（这是新 C++ 源文件应该始终放入的文件组），选择 Add new Component class (split between CPP & header)..。The Projucer 会询问如何命名新的 Component 子类。在对话框中输入 MainComponent，然后单击 Create Files。你会看到 The Projucer 创建了两个新文件：MainComponent.cpp 和 MainComponent.h。现在保存项目，并在你的 IDE 中再次打开它。你现在也应该能在那里看到新文件。The Projucer 已经为新组件类自动创建了一些代码，我们将在下一节中查看。

请记住：如果创建新类，应把它们放在各自的文件中，文件名与类名一致。始终使用 The Projucer 创建新文件；绝不要在 IDE 中创建（否则下次保存项目时 The Projucer 会覆盖这些更改）。

新的组件类

如你所见，The Projucer 自动让新类派生自 Component 类，并添加了下面的类声明：

class MainComponent : public juce::Component
{
public:
    MainComponent();
    ~MainComponent();
    void paint (juce::Graphics&) override;
    void resized() override;
private:
    JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR (MainComponent)
};

Component 基类有两个重要的虚成员函数，任何派生自它的类都应重写这两个函数。The Projucer 已经为你创建了这两个重写：

  • Component::paint()：这个成员函数决定你的组件应如何在屏幕上绘制，每个组件类都应实现它。
  • Component::resized()：这个成员函数决定组件被调整大小时应发生什么，每个组件类都应实现它（除非你确定这个组件在你的应用中永远不会可调整大小）。

对于类中所有要重写基类函数的方法，始终添加 override 关键字。这可以防止应用中出现意外错误，也是 JUCE 编码标准的一部分。

实现 paint 函数

paint() 函数决定 Component 对象如何渲染到屏幕上。我们就在这里为 MainComponent 类添加自定义外观。

The Projucer 自动添加了一些演示代码。让我们把自己的代码放进 paint() 函数。

void MainComponent::paint (juce::Graphics& g)
{
    g.fillAll (juce::Colours::lightblue);
    g.setColour (juce::Colours::darkblue);
    g.setFont (20.0f);
    g.drawText ("Hello, World!", getLocalBounds(), juce::Justification::centred, true);
}

我们不必过多深入这段代码的细节。下一篇教程（教程：Graphics 类）中我们会进一步了解这里用到的函数（以及更多内容）。现在你大概能猜到，这段演示代码用浅蓝色背景填充组件，然后在组件中央用蓝色字体渲染文本 Hello, World!。这里的关键是，所有决定 MainComponent 对象外观的代码都写在这个 paint() 函数里。

让主组件可见

现在编译并运行代码。你会发现，看到的仍然是空白的应用程序窗口，而不是蓝色背景和文本。为什么会这样？

原因是我们没有告诉 MainWindow 对象现在应该显示一些内容。首先需要包含头文件，让 MainWindow 类知道 MainComponent 类。在 Main.cpp 文件顶部、现有 include 的下面添加以下 include：

#include "MainComponent.h"

下一步是创建一个 MainComponent 对象，并将它添加为主窗口的内容。我们可以通过调用 DocumentWindow::setContentOwned() 函数来实现。

「Owned」意味着 MainWindow 对象现在负责 MainComponent 对象的生命周期，并在自己的析构函数被调用时自动销毁它。

在 MainWindow 类的构造函数中添加下面这行：

setContentOwned (new MainComponent(), true);

使 MainWindow 构造函数看起来像这样：

MainWindow (juce::String name) : DocumentWindow (name,
                                     juce::Colours::lightgrey,
                                     DocumentWindow::allButtons)
{
    setUsingNativeTitleBar (true);
    setContentOwned (new MainComponent(), true);
    centreWithSize (getWidth(), getHeight());
    setVisible (true);
}

注意我们还改动了另一个细节：Component::centreWithSize() 函数的参数也变了。现在我们不再显式设置 MainWindow 对象的大小，而是让它根据内容来确定大小：

centreWithSize (getWidth(), getHeight());

不过，要让这一点生效，MainComponent 对象需要在调用 centreWithSize() 函数之前就设置好大小。如果没有设置，主窗口就不知道合适的窗口大小是多少（运行时会触发断言失败）。下一节说明如何做到这一点。

设置组件的大小

原则上，有两种方法设置 Component 对象的大小。可以在组件自身的构造函数中设置大小，也可以在其父组件的构造函数中设置大小。对于主组件，我们通常在组件自身中设置大小。在 MainComponent 类的构造函数中添加下面这行：

setSize (400, 300);

（当然，如果需要，你也可以选择其他大小。）

请记住：始终设置组件的大小。省略这一步是 JUCE 中非常常见的错误来源。

这就是为什么 MainWindow 类中对 Component::getWidth() 和 Component::getHeight() 函数的调用能够确定窗口大小，从而以正确的大小显示主组件。MainComponent 对象的大小在它自己的构造函数中设置，早于 MainWindow 对象被定位和设置大小。

现在所有必要的部分都到位了。如果现在编译并运行应用，你应该能看到主组件正确地绘制到应用程序窗口中：

练习：弄清 setContentOwned() 函数的第二个参数（我们在这里设为 true）的含义，以及改变它后行为如何变化。提示：查看 ResizableWindow::setContentOwned() 函数的文档。

实现 resize 函数

现在我们已经介绍了 paint() 函数，接下来看看如何让 MainComponent 类对调整大小作出反应。

首先，我们需要告诉主窗口它应该可调整大小。如果记不清怎么做，请参阅教程：应用程序窗口。

现在编译并运行应用，用鼠标调整窗口大小。你会看到 MainComponent 对象会自动调整自身大小以适配主窗口的大小——实现这一点的所有必要代码已经在 Component 基类中为你写好了。

但如果你希望在每次组件被调整大小时执行一些自定义工作呢？也许它有子组件，需要根据主组件的大小以不同方式布局。在我们这个简单的演示应用中，让我们更改主组件内的文本，使其显示组件的当前大小。

调整组件大小时需要完成或更新的任何事情，都放在组件的 resized() 函数中。目前这个函数是空的。让我们在这里添加我们的功能。

Component::resized() 函数会在任何导致组件大小变化的事情发生时自动调用。绝不要自己调用这个函数！

目前组件内显示的文本是在 paint() 函数中以字面字符串「Hello, World!」给出的。让我们通过给 MainComponent 类引入一个新的成员变量来改变这一点。始终为变量取描述性强、能揭示意图的名称是一种好做法。这能让代码更易读易懂，并减少额外的代码注释。我们希望新变量以字符串形式表示主组件的当前大小，所以就叫它 currentSizeAsString。

成员变量总是在类的私有部分声明：

class MainComponent : public juce::Component
{
    // ...
private:
    juce::String currentSizeAsString;
    // ...
};

现在来实现 currentSizeAsString 对象所需的行为。要做两件事：

  • currentSizeAsString 对象的内容应渲染到屏幕上。
  • currentSizeAsString 对象应在主组件大小变化时更新自身。

实现第一部分应该相当简单：在 paint() 函数中调用 g.drawText() 函数的地方，把那里的字面字符串直接替换为 currentSizeAsString 对象：

void MainComponent::paint (juce::Graphics& g)
{
    //...
    g.drawText (currentSizeAsString, getLocalBounds(), juce::Justification::centred, true);
}

第二部分更有意思。我们已经知道，每次调整大小时都会调用 resized() 函数。所以就在那里更新 currentSizeAsString 对象的值：

void MainComponent::resized()
{
    currentSizeAsString = juce::String (getWidth()) + " x " + juce::String (getHeight());
}

Component::getWidth() 和 Component::getHeight() 是方便的函数，让你可以查询组件的当前大小。我们还需要把这些整数转换为 String 对象。（你可以在以后的教程中进一步了解如何使用 String 类。）

如果现在编译并运行应用，你会看到它始终显示当前大小：

这里可以得出两个有意思的观察结果。第一，显示会自动更新——resized() 函数被调用后，paint() 函数会自动被调用。第二，应用启动时大小就已经正确显示，甚至在你第一次亲自调整窗口大小之前也是如此。记住，只要任何东西改变了组件的大小，resized() 函数就会被调用。这包括应用启动后第一次设置组件大小以及绘制组件的时候。

小结

本教程讲解了主组件的概念、如何向应用添加主组件，以及如何实现 paint() 和 resized() 函数。读完本教程后，你应熟悉以下要点：

  • 每个 JUCE 应用程序窗口都有一个主组件。它是构成应用 GUI 的所有其他组件的父组件。
  • 每个组件（包括主组件）都有两个需要重写的重要函数：paint() 和 resized()。
  • 在 paint() 函数中，应添加把组件渲染到屏幕上的代码。
  • 如果组件需要特殊行为以响应大小变化，应实现 resized() 函数。
  • paint() 和 resized() 函数是回调函数，会在需要时自动调用。
  • 不要忘记设置主组件的大小，并将它添加到主窗口以使其可见。
