保存与加载插件状态

自动管理你的插件参数。存储和访问参数变得轻而易举，尤其是让构建有效的用户界面容易得多。

难度：中级
平台：Windows、macOS、Linux
类：AudioProcessorValueTreeState、ValueTree、XmlElement

入门

在此处下载本教程的演示项目：PIP | ZIP 。解压该项目，并在 Projucer 中打开第一个头文件。

如果你在这一步需要帮助，请参阅教程：Projucer 第 1 部分：Projucer 入门。

你还应该知道如何使用 JUCE 构建音频插件，并将其加载到你偏好的音频宿主（例如数字音频工作站）中。入门介绍请参阅教程：创建基本的音频/MIDI 插件，第 1 部分：设置。理想情况下，你还应该阅读教程：添加插件参数，作为音频处理器参数的入门。

演示项目

演示项目大致基于 JUCE/examples/Plugins 目录中的 GainPlugin 项目。该插件使用单个参数改变输入信号的增益。除此之外，它还有一个相位反转*参数，用于反转输入信号的相位。

增益处理器

TutorialProcessor 类中的大部分代码与使用 Audio Plug-In 项目模板时 Projucer 生成的代码相同。为简单起见，我们将处理器代码打包到单个 .h 文件中，而不是拆分到 .cpp 和 .h 文件中。处理器的编辑器位于 GenericEditor 类中。

使用 AudioProcessorValueTreeState 类管理插件参数有几个优点：

  • ValueTree 类本身提供撤销支持。
  • ValueTree 对象已经支持序列化和反序列化（到 XML）。
  • ValueTree 对象可以附加监听器。这意味着 AudioProcessorValueTreeState 类几乎可以自动连接到滑块和按钮，以线程安全的方式让 UI 和处理器状态保持同步。

要使用 AudioProcessorValueTreeState 对象，你可以在处理器类中存储一个：

private:
//==============================================================================
juce::AudioProcessorValueTreeState parameters;

你可以将 AudioProcessorValueTreeState 对象存储在其他地方，但必须注意每个 AudioProcessorValueTreeState 对象必须：

  • 只附加到一个处理器；并且
  • 与处理器具有相同的生命周期（因为它们之间会相互依赖）。

将 AudioProcessorValueTreeState 对象存储在处理器类中，可以更容易地确保满足这些要求。

AudioProcessorValueTreeState 构造函数需要一个对其将要附加到的 AudioProcessor 子类的引用、一个指向 UndoManager 对象的指针、一个 Identifier 用于标识 ValueTree，以及一个包含要管理的参数的 AudioProcessorValueTreeState::ParameterLayout。

AudioProcessorValueTreeState (AudioProcessor& processorToConnectTo,
    UndoManager* undoManagerToUse,
    const juce::Identifier& valueTreeType,
    ParameterLayout parameterLayout);

在这个例子中，我们将为 UndoManager 对象使用 nullptr 值，因为本教程不会实现撤销支持。nullptr 值表示我们不想使用撤销支持。

配置参数

AudioProcessorValueTreeState::ParameterLayout 参数（即 AudioProcessorValueTreeState 的参数）包含我们插件的参数。AudioProcessorValueTreeState 可以管理任何派生自 RangedAudioParameter 的参数，并且 AudioProcessorValueTreeState::ParameterLayout 构造函数可以接受数量可变的 RangedAudioParameter 子类，或包含 RangedAudioParameters 的 AudioProcessorParameterGroups。

参数和组使用 std::unique_ptr 传递，因为 APVTS 将取得参数和组的所有权。

JUCE 内置的参数类型，也就是我们在教程：添加插件参数中使用过的那些，都是 RangedAudioParameter 的子类，因此我们在这里也可以使用它们。

TutorialProcessor()
    : parameters (*this, nullptr, juce::Identifier ("APVTSTutorial"),
          {
              std::make_unique<juce::AudioParameterFloat> ("gain", // parameterID
                  "Gain", // parameter name
                  0.0f, // minimum value
                  1.0f, // maximum value
                  0.5f), // default value
              std::make_unique<juce::AudioParameterBool> ("invertPhase", // parameterID
                  "Invert Phase", // parameter name
                  false) // default value
          })
{

将参数添加到 AudioProcessorValueTreeState 也会自动将它们添加到所附加的 AudioProcessor 中。

参数 ID应该是该参数的唯一标识符。可以把它想成变量名；它可以包含字母数字字符和下划线，但不能包含空格。参数名称是将显示在屏幕上的名称。

执行增益处理

为帮助避免信号中出现咔嗒声，我们对增益变化和信号相位变化进行平滑处理。为此，我们在处理器中存储先前计算出的增益值 [1]：

private:
//==============================================================================
juce::AudioProcessorValueTreeState parameters;
float previousGain; // [1]
std::atomic<float>* phaseParameter = nullptr;
std::atomic<float>* gainParameter = nullptr;
//==============================================================================
JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR (TutorialProcessor)
};

我们还在构造函数末尾存储指向参数的指针，以便之后对它们解引用：

phaseParameter = parameters.getRawParameterValue ("invertPhase");
gainParameter = parameters.getRawParameterValue ("gain");

这些变化在 TutorialProcessor::prepareToPlay() 函数中初始化：

void prepareToPlay (double, int) override
{
    auto phase = *phaseParameter < 0.5f ? 1.0f : -1.0f;
    previousGain = *gainParameter * phase;
}

这里我们计算相位反转因子（+1 或 -1），并将其乘以增益，为第一次处理回调做好准备。你可以看到，我们使用 AudioProcessorValueTreeState::getRawParameterValue() 函数获取指向表示参数值的 float 的指针。我们对其解引用来获取实际值。处理在 TutorialProcessor::processBlock() 函数中执行：

void processBlock (juce::AudioSampleBuffer& buffer, juce::MidiBuffer&) override
{
    auto phase = *phaseParameter < 0.5f ? 1.0f : -1.0f;
    auto currentGain = *gainParameter * phase;
    if (juce::approximatelyEqual (currentGain, previousGain))
    {
        buffer.applyGain (currentGain);
    }
    else
    {
        buffer.applyGainRamp (0, buffer.getNumSamples(), previousGain, currentGain);
        previousGain = currentGain;
    }
}

你可以看到，如果值没有变化，我们只需应用一个恒定增益。如果值发生了变化，我们就应用增益渐变，然后更新 previousGain 值以供下次使用。

存储与读取参数

除了提供处理音频的例程之外，你还需要提供将插件的整个状态存储到内存块中以及从中读取的方法。这应包括所有参数的当前值，但如有需要也可以包含其他状态信息（例如，如果你的插件要处理文件，它可能会存储文件路径）。

使用 AudioProcessorValueTreeState 对象存储插件状态使这件事变得非常简单，因为 ValueTree 对象可以轻松地与 XML 相互转换。

AudioProcessor::getStateInformation() 回调要求你的插件将其状态存储到 MemoryBlock 对象中。要通过 ValueTree 对象以 XML 完成这件事，代码很简单：

void getStateInformation (juce::MemoryBlock& destData) override
{
    auto state = parameters.copyState();
    std::unique_ptr<juce::XmlElement> xml (state.createXml());
    copyXmlToBinary (*xml, destData);
}

所创建的 XmlElement 对象的标签名将是“APVTSTutorial”，也就是我们之前用来初始化 ValueTree 对象的名称。

从 XML 恢复状态几乎同样简单：

void setStateInformation (const void* data, int sizeInBytes) override
{
    std::unique_ptr<juce::XmlElement> xmlState (getXmlFromBinary (data, sizeInBytes));
    if (xmlState.get() != nullptr)
        if (xmlState->hasTagName (parameters.state.getType()))
            parameters.replaceState (juce::ValueTree::fromXml (*xmlState));
}

这里我们加入了一些错误检查以确保安全。我们还通过检查 XML 元素的标签名，确认 ValueTree 生成的 XML 与插件所需的 ValueTree 类型一致。

增益编辑器

看看项目中的 GenericEditor 类。你可能注意到 GenericEditor 类的声明非常简单：

class GenericEditor : public juce::AudioProcessorEditor
{
public:

你可能以为我们需要继承 Slider::Listener 类和 Button::Listener 类，才能响应滑块和按钮的交互。但这同样是使用 AudioProcessorValueTreeState 类的好处之一。我们可以改用 AudioProcessorValueTreeState 类中的附加类。

组件附加

实际上，由于这些类的名称可能变得非常长，我们为我们需要的每个附加类都包含了一个 typedef：

typedef juce::AudioProcessorValueTreeState::SliderAttachment SliderAttachment;
typedef juce::AudioProcessorValueTreeState::ButtonAttachment ButtonAttachment;

我们的 GenericEditor 类包含若干成员，包括一个滑块、一个切换按钮，以及其中一些附加对象：

private:
    juce::AudioProcessorValueTreeState& valueTreeState;
    juce::Label gainLabel;
    juce::Slider gainSlider;
    std::unique_ptr<SliderAttachment> gainAttachment;
    juce::ToggleButton invertButton;
    std::unique_ptr<ButtonAttachment> invertAttachment;
};

我们还需要引用 AudioProcessorValueTreeState 对象，因此我们也保留了对它的引用。

我们的 GenericEditor 类的构造函数会设置这些对象：

GenericEditor (juce::AudioProcessor& parent, juce::AudioProcessorValueTreeState& vts)
    : AudioProcessorEditor (parent),
      valueTreeState (vts)
{
    gainLabel.setText ("Gain", juce::dontSendNotification);
    addAndMakeVisible (gainLabel);
    addAndMakeVisible (gainSlider);
    gainAttachment.reset (new SliderAttachment (valueTreeState, "gain", gainSlider));
    invertButton.setButtonText ("Invert Phase");
    addAndMakeVisible (invertButton);
    invertAttachment.reset (new ButtonAttachment (valueTreeState, "invertPhase", invertButton));
    setSize (paramSliderWidth + paramLabelWidth, juce::jmax (100, paramControlHeight * 2));
}

它由我们处理器的 TutorialProcessor::createEditor() 函数调用：

juce::AudioProcessorEditor* createEditor() override { return new GenericEditor (*this, parameters); }

你可能注意到，我们甚至不需要设置滑块的取值范围。这是由 SliderAttachment 类自动完成的。我们只需将 AudioProcessorValueTreeState、参数 ID以及它应附加到的 Slider 对象传给附加对象的构造函数。

我们仍然保留 Slider 对象的所有权。你应确保附加类与 Slider 对象具有相同的生命周期。

ButtonAttachment 类仍然需要我们提供按钮名称。（而 AudioProcessorValueTreeState::ComboBoxAttachment 类可以附加到 ComboBox 对象，它需要我们手动填充 ComboBox。）

练习：将插件改为仅支持 2 声道主总线，并添加一个声道交换参数，用于可选地交换左右声道。——仍然使用仅支持 2 声道的插件，添加一个平衡参数来平衡左右声道的电平。

以编程方式添加参数

你也可以通过调用 add，以编程方式向 AudioProcessorValueTreeState 添加参数（或 AudioProcessorParameterGroups）。下面展示了如何做到这一点的一个示例：

juce::AudioProcessorValueTreeState::ParameterLayout createParameterLayout()
{
    juce::AudioProcessorValueTreeState::ParameterLayout params;
    for (int i = 1; i < 9; ++i)
        params.add (std::make_unique<AudioParameterInt> (String (i), String (i), 0, i, 0));
    return params;
}
YourAudioProcessor()
    : parameters (*this, nullptr, "PARAMETERS", createParameterLayout())

已弃用的方法

在 JUCE 5.4 版本之前，向 AudioProcessorValueTreeState 添加参数的唯一方法是使用现已弃用的 createAndAddParameter 方法，它带有许多函数参数。

以前看起来像这样的代码

createAndAddParameter (paramID1, paramName1, ...);

可以重写为

using Parameter = juce::AudioProcessorValueTreeState::Parameter;
createAndAddParameter (std::make_unique<Parameter> (paramID1, paramName1, ...));

但使用本教程中介绍的新 AudioProcessorValueTreeState 构造函数是更好的方法：

using Parameter = AudioProcessorValueTreeState::Parameter;
YourAudioProcessor()
    : apvts (*this, nullptr, "PARAMETERS", { std::make_unique<Parameter> (paramID1, paramName1, ...), std::make_unique<Parameter> (paramID2, paramName2, ...), ... })

总结

在本教程中，我们介绍了 AudioProcessorValueTreeState 类，并展示了它如何帮助你：

  • 管理你的插件参数。
