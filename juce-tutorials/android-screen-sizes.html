管理 Android 屏幕尺寸

为不同的屏幕尺寸构建应用程序。Android 上有许多可用的屏幕尺寸，本教程探讨一些应对策略。

难度：中级
平台：Android、macOS、Windows 类：Desktop、AffineTransform、TabbedComponent

入门

本教程演示了使用 JUCE 在 Android 平台上管理不同屏幕尺寸的几种策略。本教程配有多个演示项目。这些项目的下载链接在本教程的相关章节中提供。

如果你在这些章节中需要这一步的帮助，请参阅 教程：Projucer 第 1 部分：Projucer 入门。

演示项目

本教程提供的演示项目展示了使用 JUCE 在 Android 平台上管理不同屏幕尺寸的几种不同方法。大体上，这些方法是：

  • 在主组件内调整子组件的大小。
  • 使用变换调整主组件的大小。
  • 为不同方向设计不同的组件布局。
  • 为不同尺寸设计不同的组件布局。

Android 屏幕尺寸

特别是对于期望全屏运行的设备（例如移动设备），要设计出在所有屏幕尺寸和各种设备方向上都有效的用户界面是一项挑战。在存在众多可能屏幕尺寸和分辨率的 Android 平台上，这尤其具有挑战性。这里主要有三个问题：

  • 物理尺寸：以标准计量单位衡量的屏幕物理尺寸（常用度量是屏幕对角线长度，以英寸为单位）。
  • 分辨率：以像素衡量的屏幕分辨率。
  • 方向：设备方向，即横向或纵向。

物理尺寸与分辨率之间的关系很重要。在考虑高分辨率屏幕时尤为重要，因为其物理像素比标准分辨率屏幕更小、排列更密集。特定的屏幕物理尺寸与其分辨率的组合决定了屏幕的每英寸点数（DPI）。这与屏幕的像素密度相关。它表示在每个维度上，相对于标准密度屏幕上的一个像素，有多少个物理像素占据一个“软件”像素的空间。

对某些应用程序而言，物理尺寸最为重要。例如，应用程序使用包含精细手指动作的复杂交互时就是如此。在这种情况下，屏幕尺寸和典型用户的手部尺寸都很重要。在其他应用程序中，屏幕的 DPI 更为重要。例如，在更高的 DPI 下，使用较小的字号文本仍可保持可读。但如果按文本在屏幕上的物理尺寸来衡量，其可读性是有极限的。设计应用程序时，你有时需要同时考虑物理尺寸和分辨率（因此也包括 DPI）。

默认情况下，JUCE 会根据屏幕的像素密度缩放其坐标系。这意味着在高密度屏幕上绘制的图形和文本，其物理尺寸应与在标准密度屏幕上大致相同。在 JUCE 中，你可以通过 Desktop 类访问特定显示器的信息。在这里你可以找到可用的显示器，以及哪一个被标记为“主显示器”（尤其是在有多个显示器时）。

遗憾的是，JUCE 能获取到的用于得到显示器 DPI 的值只是一个近似值（因为并非所有屏幕设备都能正确报告该信息）。这意味着我们无法准确测量用户屏幕的物理尺寸。但 Desktop 类提供的信息足以作为参考，用来根据应用程序的需求缩放用户界面。

在接下来的每个示例中，我们都使用一个名为 ResizingComp 的子组件，它由父组件（MainContentComponent）管理和调整大小。

如果你在 macOS 或 Windows 上测试这些项目，你将能够动态调整主窗口的宽度和高度。虽然这在某种程度上可行，但除测试目的外，这并不是这些项目的设计特性。这些项目被设计为预期尺寸变化不频繁。例如，应用程序启动时的一次性设置，或用户旋转 Android 设备时。

组件数组

为了在 ResizingComp 类中存储按钮和滑块，我们使用 OwnedArray 模板类（这意味着这些子组件会在 ResizingComp 析构函数中自动删除）。首先，在 ResizingComp 构造函数中，我们构建一个 Colour 对象数组。它们用于设置按钮、滑块拇指和滑块轨道的颜色：

ResizingComp()
{
    juce::Array<juce::Colour> colours { juce::Colour (0xffb3c3Da), juce::Colour (0xff5973b8), juce::Colour (0xffd65667), juce::Colour (0xffd99154), juce::Colour (0xffe5ad6c), juce::Colour (0xffecc664), juce::Colour (0xffefe369), juce::Colour (0xffdddB74) };

这些恰好是 JUCE 标志中的颜色！

然后我们使用 for() 循环来分配并配置多个按钮：

for (auto i = 0; i < 6; ++i)
{
    auto* button = buttons.add (new juce::TextButton (juce::String ("Button ") + juce::String (i + 1)));
    addAndMakeVisible (button);
    button->setColour (juce::TextButton::buttonColourId,
        colours.getUnchecked (i % colours.size()));
}

滑块的设置类似（不过我们利用颜色数组打乱了颜色选择，以保持有趣）。

for (auto i = 0; i < 6; ++i)
{
    auto* slider = sliders.add (new juce::Slider());
    addAndMakeVisible (slider);
    slider->setColour (juce::Slider::thumbColourId,
        colours.getUnchecked ((buttons.size() + i) % colours.size()));
    slider->setColour (juce::Slider::backgroundColourId,
        colours.getUnchecked ((buttons.size() + i + 2) % colours.size()).withAlpha (0.4f));
    slider->setColour (juce::Slider::trackColourId,
        colours.getUnchecked ((buttons.size() + i + 2) % colours.size()));
    slider->setColour (juce::Slider::textBoxTextColourId, juce::Colours::black);
}

使用自定义滑块拇指尺寸

为了在触摸屏界面上更易用，滑块拇指已作定制，使其通常大于标准尺寸。为此，我们添加了 LookAndFeel_V4 的一个子类，并重写了 LookAndFeel::getSliderThumbRadius() 函数。

class CustomLookAndFeel : public juce::LookAndFeel_V4
{
public:
    int getSliderThumbRadius (juce::Slider& slider) override
    {
        return juce::jmin (slider.getWidth(), slider.getHeight()) / 2;
    }
};

我们将该类的一个实例添加为 ResizingComp 类的成员：

juce::OwnedArray<juce::Button> buttons;
juce::OwnedArray<juce::Slider> sliders;
CustomLookAndFeel lf;
};

并在 ResizingComp 构造函数的末尾，将其设置为此组件及其所有子组件的观感。

setLookAndFeel (&lf);

在 ResizingComp 析构函数中，我们将其设置为 nullptr。

~ResizingComp() override
{
    setLookAndFeel (nullptr);
}

调整按钮和滑块的大小

在 ResizingComp::resized() 函数中，我们遍历按钮数组和滑块数组并设置它们的边界：

void resized() override
{
    auto space = 8;
    auto widgetHeight = (getHeight() - space) / (buttons.size() + sliders.size()) - space;
    for (auto* button : buttons)
        button->setBounds (space, space + (widgetHeight + space) * buttons.indexOf (button), getWidth() - space - space, widgetHeight);
    for (auto* slider : sliders)
        slider->setBounds (space, space + (widgetHeight + space) * (sliders.indexOf (slider) + buttons.size()), getWidth() - space - space, widgetHeight);
}

这里我们使用一个常量值（8）来分隔组件。然后我们根据可用高度和“控件”（按钮与滑块）的数量计算“控件高度”。

如果屏幕尺寸太小，界面会变得无法使用、无法阅读，如下方截图所示：

使用变换调整主组件的大小

在此处下载本节演示项目：PIP | ZIP。解压项目并在 Projucer 中打开第一个头文件。

这个示例采用了另一种方式来替代调整子组件大小。取而代之的是，ResizingComp 组件被设为标称尺寸（480 × 640 像素），然后 MainContentComponent 对象应用仿射变换将其放大或缩小以匹配屏幕尺寸。此过程保持相同的宽高比（在滑块和按钮的侧边或上下留出空白）。ResizingComp 类的代码与简单调整示例相同。但在 MainContentComponent::resized() 函数中，我们先设置 ResizingComp 组件的尺寸，然后计算所需的变换：

void resized() override
{
    auto contentWidth = 480;
    auto contentHeight = 640;
    auto scaleX = (float) getWidth() / static_cast<float> (contentWidth);
    auto scaleY = (float) getHeight() / static_cast<float> (contentHeight);
    auto scale = juce::jmin (scaleX, scaleY);
    resizingComp->setTransform (juce::AffineTransform::scale (scale, scale));
    resizingComp->centreWithSize (contentWidth, contentHeight);
}

这段代码计算标称尺寸与屏幕实际尺寸（以软件像素计）之间的比例。然后选择其中较小的比例，以保持宽高比，同时让所有内容都留在屏幕上。接着我们使用 AffineTransform::scale() 函数创建 AffineTransform 类的实例，并让缩放变换以屏幕中心为中心。该变换通过 Component::setTransform() 函数应用到组件上。结果与简单调整方法相当不同。

对组件应用变换不仅会改变用户界面的绘制，还会改变触摸（以及鼠标）活动的位置。

为不同方向设计不同的布局

在此处下载本节演示项目：PIP | ZIP。解压项目并在 Projucer 中打开第一个头文件。

这个示例探讨一种根据屏幕（或设备）方向显示不同布局的方法。Desktop::getCurrentOrientation() 函数提供了访问设备方向的方式。实际上，有四种可能的方向：

  • 正向（纵向）。
  • 倒置（纵向旋转 180 度）。
  • 设备顺时针旋转 90 度（横向的一种）。
  • 设备逆时针旋转 90 度（横向的另一种）。

为简单起见，在本教程中，我们将纵向视为高度大于宽度的屏幕（并将横向视为宽度大于高度的屏幕）。

这个示例使用我们之前看到的相同技术，通过变换来缩放用户界面。不同之处在于，这个 ResizingComp 类根据方向使用不同的布局，而 MainContentComponent 类有两个标称尺寸（一个用于横向，一个用于纵向）。方向在 MainContentComponent::resized() 函数中确定：

void resized() override
{
    auto isLandscape = getWidth() > getHeight();
    auto contentWidth = isLandscape ? 640 : 480;
    auto contentHeight = isLandscape ? 480 : 640;

然后，在 ResizingComp::resized() 函数中，我们根据方向从两个调整尺寸函数中选择：

void resized() override
{
    if (getHeight() > getWidth())
        resizedPortrait();
    else
        resizedLandscape();
}

resizedPortrait() 和 resizedLandscape() 函数随后使用不同的运算来布局按钮和滑块。

使用横向时，按钮和滑块显示为两列而不是一列。如下方截图所示：

练习：修改代码，使用 Desktop::getCurrentOrientation() 函数来确定屏幕方向，而不是比较屏幕的宽度和高度。

为不同屏幕尺寸设计不同的布局

在此处下载本节演示项目：PIP | ZIP。解压项目并在 Projucer 中打开第一个头文件。

最后一个示例为不同的屏幕方向和屏幕尺寸使用不同的布局。如果你想为不同屏幕方向使用完全不同的布局，甚至为 Android 手机和平板电脑制作通用应用程序，这类技术可能特别有用。这里采用的方法是：如果组件无法容纳在单页上，就使用 TabbedComponent 类将组件分页排列。

与前面三个项目相比，这个项目中 ResizingComp 类的职责略有变化。特别是，我们不再将按钮和滑块作为直接子组件添加。注意下面构造函数代码中缺少对 Component::addAndMakeVisible() 函数的调用：

ResizingComp()
{
    juce::Array<juce::Colour> colours { juce::Colour (0xffb3c3Da), juce::Colour (0xff5973b8), juce::Colour (0xffd65667), juce::Colour (0xffd99154), juce::Colour (0xffe5ad6c), juce::Colour (0xffecc664), juce::Colour (0xffefe369), juce::Colour (0xffdddB74) };
    for (auto i = 0; i < 6; ++i)
    {
        auto* button = buttons.add (new juce::TextButton (juce::String ("Button ") + juce::String (i + 1)));
        button->setColour (juce::TextButton::buttonColourId,
            colours.getUnchecked (i % colours.size()));
    }
    for (auto i = 0; i < 6; ++i)
    {
        auto* slider = sliders.add (new juce::Slider());
        slider->setColour (juce::Slider::thumbColourId,
            colours.getUnchecked ((buttons.size() + i) % colours.size()));
        slider->setColour (juce::Slider::backgroundColourId,
            colours.getUnchecked ((buttons.size() + i + 2) % colours.size()).withAlpha (0.4f));
        slider->setColour (juce::Slider::trackColourId,
            colours.getUnchecked ((buttons.size() + i + 2) % colours.size()));
        slider->setColour (juce::Slider::textBoxTextColourId, juce::Colours::black);
    }
    setLookAndFeel (&lf);
}

ResizingComp 类管理按钮和滑块的生命周期，但在组件层级上，它们被添加到另一个名为 ComponentHolder 的组件类的一个或多个实例中。

布局组件

ComponentHolder 类持有一个 Component 指针数组，并根据方向将组件布局为一列或两列。（实现这种布局的技术在之前讨论不同屏幕方向时已经介绍过。）只有一个函数——（ComponentHolder::addComp()——用于添加组件，它将组件加入内部数组并调用 Component::addAndMakeVisible()：

void addComp (Component* comp)
{
    comps.add (comp);
    addAndMakeVisible (comp);
}

这些布局函数——ResizingComp::resizedPortrait() 和 ResizingComp::resizedLandscape()——应该看起来很熟悉。不过它们需要略有不同，因为我们不再有独立的滑块数组和按钮数组：

void resizedPortrait()
{
    auto space = 8;
    auto widgetHeight = (getHeight() - space) / comps.size() - space;
    for (auto* comp : comps)
        comp->setBounds (space, space + (widgetHeight + space) * comps.indexOf (comp), getWidth() - space - space, widgetHeight);
}
void resizedLandscape()
{
    auto space = 8;
    auto halfComps = comps.size() / 2;
    auto widgetHeight = (getHeight() - space) / halfComps - space;
    for (auto* comp : comps)
    {
        auto index = comps.indexOf (comp);
        if (index < halfComps)
        {
            comp->setBounds (space, space + (widgetHeight + space) * index, getWidth() / 2 - space - space, widgetHeight);
        }
        else
        {
            comp->setBounds (getWidth() / 2 + space, space + (widgetHeight + space) * (index - halfComps), getWidth() / 2 - space - space, widgetHeight);
        }
    }
}

选择单页或多页

如果屏幕尺寸较大，则只创建一个这样的 ComponentHolder 组件，并将所有按钮和滑块添加到其中。如果屏幕尺寸较小，ResizingComp 类会使用一个 TabbedComponent 对象，并添加两个 ComponentHolder 类的实例来构成 TabbedComponent 的标签页。使用单页还是多页的决定由 ResizingComp 类在 ResizingComp::resized() 函数中管理。

void resized() override
{
    if (holder.get() != nullptr)
    {
        removeChildComponent (holder.get());
        holder.reset();
    }
    auto minimumDimension = juce::jmin (getWidth(), getHeight());
    if (minimumDimension >= 480)
        layoutSinglePage();
    else
        layoutTabs();
}

可以看到，我们将“大”屏幕定义为某个维度大于或等于 480 软件像素的屏幕。当然，你可以为你的应用程序选择不同的值。ResizingComp::layoutSinglePage() 函数很直接：

void layoutSinglePage()
{
    holder.reset (new ComponentHolder());
    for (auto* button : buttons)
        dynamic_cast<ComponentHolder*> (holder.get())->addComp (button);
    for (auto* slider : sliders)
        dynamic_cast<ComponentHolder*> (holder.get())->addComp (slider);
    addAndMakeVisible (holder.get());
    holder->setBounds (getLocalBounds());
}

可以看到，我们将所有按钮和滑块添加到 ComponentHolder 实例，并将其作为 ResizingComp 对象的子组件添加。ResizingComp::layoutTabs() 函数只是稍微复杂一点：

void layoutTabs()
{
    auto orientation = getWidth() < getHeight() ? juce::TabbedButtonBar::TabsAtBottom
                                                : juce::TabbedButtonBar::TabsAtLeft;
    holder.reset (new juce::TabbedComponent (orientation)); // [1]
    addAndMakeVisible (holder.get()); // [2]
    auto* buttonTab = new ComponentHolder(); // [3]
    auto* sliderTab = new ComponentHolder();
    dynamic_cast<juce::TabbedComponent*> (holder.get())->addTab ("Buttons", juce::Colours::white, buttonTab, true); // [4]
    dynamic_cast<juce::TabbedComponent*> (holder.get())->addTab ("Sliders", juce::Colours::white, sliderTab, true);
    for (auto* button : buttons) // [5]
        buttonTab->addComp (button);
    for (auto* slider : sliders) // [6]
        sliderTab->addComp (slider);
    holder->setBounds (getLocalBounds()); // [7]
}
  • [1]：我们创建 TabbedComponent 对象，并使用屏幕方向将其存储到 holder 成员中，以确定标签按钮的位置。
  • [2]：我们将 TabbedComponent 对象添加为子组件。
  • [3]：我们创建 ComponentHolder 对象。
  • [4]：我们将它们作为标签页添加到 TabbedComponent 对象（最后的 true 参数告诉 TabbedComponent 对象，它们可以在不再需要时删除 ComponentHolder 对象）。
  • [5]：我们将按钮添加到“Buttons”标签页。
  • [6]：并将滑块添加到“Sliders”标签页。
  • [7]：我们设置 TabbedComponent 对象的尺寸，使其填满 ResizingComp 对象的边界。
