Projucer 第 3 部分：选择合适的 Projucer 模板

一开始为你的应用选择合适的模板可能并不容易，而从起步就继承正确的类，能极大提升开发效率。在本教程中，我们将探索 Projucer 提供的各种模板项目，以及在构思应用时应当关注的主要类。

难度：初级
平台：Windows、macOS、Linux、iOS、Android
类：JUCEApplication、Component、AudioAppComponent、AnimatedAppComponent、OpenGLAppComponent、AudioProcessor、AudioProcessorEditor

准备工作

请确保你熟悉 Projucer，并对 Projucer 项目的结构有基本了解。

如果你在这一步需要帮助，请参阅教程：Projucer 第 1 部分：Projucer 入门。

合适的项目用合适的模板

取决于你正在开发的项目，你可能想从 Projucer 向导中选择不同的模板项目。下面的流程图提供了一份可视化的问卷，帮助你为项目选出最合适的模板：

你可以直接跳转到相应的项目类型，也可以继续阅读，了解 JUCE 项目的结构说明。

GUI 项目

所有 GUI 项目模板都会为你提供源文件，帮助你开始开发。由于应用需要显示图形用户界面，模板会为你提供一个 Main.cpp 文件，其中已经创建了一个派生自 JUCEApplication 的类。

JUCEApplication 类是一个抽象基类，为你的应用提供启动和关闭功能。Main.cpp 文件还会创建承载 GUI 的应用窗口。

GUI 应用

GUI 应用项目是所有 GUI 项目中最通用的一种，除了 Main.cpp 文件之外，它还会创建一个派生自 Component 类的 MainComponent 类。

Component 类是 JUCE 中所有用户界面对象的基类。你所有的 GUI 元素都应当在 MainComponent 类中定义和放置。

创建 GUI 应用项目后，你会在源文件夹中找到以下文件：

  • Main.cpp：派生自 JUCEApplication 类，为你的应用和窗口提供初始化代码。
  • MainComponent.h：MainComponent 的头文件，该类派生自 Component 类。
  • MainComponent.cpp：MainComponent 的实现文件，该类派生自 Component 类。

当你确定应用需要 GUI，但对其具体功能还不确定、或者需要保持灵活性时，就使用这种项目类型。

关于 GUI 应用项目的更多细节，请参阅教程教程：应用窗口以获取更多信息。

音频应用

音频应用与 GUI 应用类似，但 MainComponent 不再派生自 Component 类，而是派生自 AudioAppComponent 类。

AudioAppComponent 类是一个抽象基类，它把 Component 与 AudioSource 的功能结合在一起，为处理音频输入/输出提供了一个便捷的起点。

创建音频应用项目后，你会在源文件夹中找到以下文件：

  • Main.cpp：派生自 JUCEApplication 类，为你的应用和窗口提供初始化代码。
  • MainComponent.cpp：MainComponent 的头文件和实现文件，该类派生自 AudioAppComponent 类。

当你需要音频输入/输出功能，同时应用还要有 GUI 时，就使用这种项目类型。

关于音频应用项目的更多细节，请参阅教程教程：构建白噪声发生器以获取更多信息。

动画应用

动画应用与 GUI 应用类似，但 MainComponent 不再派生自 Component 类，而是派生自 AnimatedAppComponent 类。

AnimatedAppComponent 类是一个抽象基类，它把 Component 与 Timer 的功能结合在一起，为显示动画提供了一个便捷的起点。

创建动画应用项目后，你会在源文件夹中找到以下文件：

  • Main.cpp：派生自 JUCEApplication 类，为你的应用和窗口提供初始化代码。
  • MainComponent.cpp：MainComponent 的头文件和实现文件，该类派生自 AnimatedAppComponent 类。

当你想在应用的 GUI 中创建简单动画时，就使用这种项目类型。

关于动画应用项目的更多细节，请参阅教程教程：为几何图形添加动画以获取更多信息。

OpenGL 应用

OpenGL 应用与 GUI 应用类似，但 MainComponent 不再派生自 Component 类，而是派生自 OpenGLAppComponent 类。

OpenGLAppComponent 类是一个抽象基类，它把 Component 与 OpenGLRenderer 的功能结合在一起，为渲染复杂图形提供了一个便捷的起点。

创建 OpenGL 应用项目后，你会在源文件夹中找到以下文件：

  • Main.cpp：派生自 JUCEApplication 类，为你的应用和窗口提供初始化代码。
  • MainComponent.cpp：MainComponent 的头文件和实现文件，该类派生自 OpenGLAppComponent 类。

当你想在应用的 GUI 中使用 OpenGL 渲染复杂的图形元素时，就使用这种项目类型。

关于 OpenGL 应用项目的更多细节，请参阅教程教程：构建 OpenGL 应用以获取更多信息。

命令行项目

控制台应用

创建控制台应用项目后，你会在源文件夹中找到以下文件：

  • Main.cpp：提供 C 风格的 main() 函数，让你的应用能携带相应的命令行参数运行。

当二进制文件在命令行中执行时，将会调用以下函数：

int main (int argc, char* argv[])
{
    // ..your code goes here!
    return 0;
}

这种项目类型不会在 Main.cpp 文件中创建任何类，也不会继承任何基类，但会创建一个 .jucer 文件和一个 JUCE 库代码文件夹，以及你在创建项目时选择的所有导出器。

当你的应用不需要 GUI，并且希望在命令行控制台中运行时，就使用这种项目类型。

插件项目

音频插件

与 Projucer 提供的其他模板项目相比，音频插件项目的结构完全不同，它会创建一个 AudioProcessor 和一个 AudioProcessorEditor。

AudioProcessor 类是一个抽象基类，负责音频插件的音频处理。它代表已加载插件的一个实例，并被 VST、AU、RTAS 和 AAX 等各种插件格式所封装。

AudioProcessorEditor 类是派生自 Component 类的基类，承载音频插件的 GUI 功能。

创建音频插件项目后，你会在源文件夹中找到以下文件：

  • PluginProcessor.h：PluginProcessor 的头文件，该类派生自 AudioProcessor 类。
  • PluginProcessor.cpp：PluginProcessor 的实现文件，该类派生自 AudioProcessor 类。
  • PluginEditor.h：PluginEditor 的头文件，该类派生自 AudioProcessorEditor 类。
  • PluginEditor.cpp：PluginEditor 的实现文件，该类派生自 AudioProcessorEditor 类。

当你想创建一个可以托管在 DAW 中的插件，或者一个带 GUI 的独立应用时，就使用这种项目类型。

关于音频插件项目的更多细节，请参阅教程教程：创建一个基础音频/MIDI 插件，第 1 部分：项目搭建以获取更多信息。

库项目

静态/动态库

如果你感兴趣的是创建一个供其他项目使用的库，Projucer 提供了创建静态库和动态库的选项。

这种项目类型不会创建任何源文件，但会创建一个 .jucer 文件和一个 JUCE 库代码文件夹，以及你在创建项目时选择的所有导出器。

之后你可以随意添加文件，并且随时都能方便地访问 JUCE 模块。
