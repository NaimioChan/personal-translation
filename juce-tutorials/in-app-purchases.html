桌面与移动设备上的应用内购买

在你的桌面和移动应用程序中销售消耗型与非消耗型应用内购买。了解如何在 macOS/iOS 和 Android 设备上设置并处理 IAP 产品的支付。

难度：高级
平台：macOS、iOS、Android
类：InAppPurchases::Listener、SoundPlayer、AsyncUpdater、ListBoxModel

本项目在 macOS/iOS 上需要 Apple Developer 和 iTunes Connect 账户，在 Android 上需要 Google Play Developer 账户。如果你需要这方面的帮助，请按照 Apple Developer、iTunes Connect 和 Google Play Developer 网站上的说明开通这些账户。

本项目还需要实体设备来测试应用内购买，因为模拟器不支持 IAP 测试。请确保你已准备好一台设备。

购买类型

应用内购买可用于直接在应用内向客户提供额外内容和功能。它们可以是高级功能、专属项目，甚至订阅。一般来说，所有相关平台上主要有四种购买类型：

  • 消耗型：可多次使用和购买的计数型项目。
  • 非消耗型：一次性购买，永久解锁应用的功能。
  • 自动续期订阅：定期更新内容，按周期持续，直到取消。
  • 非续期订阅：限时内容，需要手动续订。

在本教程中，我们将实现非消耗型应用内购买。

项目结构

该项目使用以下类来构建，以处理应用程序的不同部分：

  • MainContentComponent：在屏幕上布局 GUI 组件，并处理点击播放/停止按钮时声音文件的播放。
  • PhraseModel：ListBoxModel，用于描述可使用已购买语音播放的可用短语。
  • VoiceModel：ListBoxModel，用于描述可购买并用于播放短语的可用语音。
  • VoiceRow：为 VoiceModel 类定制的行 Component，用于显示特定语音条目的图片和信息。
  • VoicePurchases：用于管理 VoiceProduct 购买的类，负责处理购买并封装 InAppPurchases 实例。
  • VoiceProduct：用于描述单个可购买产品的结构体，包含价格、名称以及是否曾购买等信息。

可以看到，它大致遵循 MVC 设计模式，将应用程序功能分离到不同的类中。

VoiceProduct 结构体包含非消耗型产品所需的有用信息，即以下变量：

  • const char* identifier：由 iTunes Connect 和 Google Play 引用的唯一标识符。
  • const char* humanReadable：标识符的易读版本，用于在应用中显示。
  • bool isPurchased：登录用户此前是否已购买该项目。
  • bool priceIsKnown：价格是否已加载并获取以便显示。
  • bool purchaseInProgress：用户是否已发起目前正在进行的购买。
  • String purchasePrice：以本地货币显示产品价格的本地化字符串。

练习：消耗型购买需要我们提供哪类信息？订阅呢？思考应添加或移除哪些内容。

int findVoiceIndexFromIdentifier (juce::String identifier) const
{
    identifier = identifier.toLowerCase();
    for (auto i = 0; i < voiceProducts.size(); ++i)
        if (juce::String (voiceProducts.getReference (i).identifier) == identifier)
            return i;
    return -1;
}

检索购买

本节仅在实体设备上有效。不要在模拟器上尝试，因为它无法正常运行。

处理应用内购买时，应用程序应首先检查用户登录时的以往购买记录。作为客户，最令人沮丧的事情之一就是丢失在另一台设备或同一应用先前版本上所做的购买。因此，我们要确保应用启动时尽快让用户看到更新后的产品页面视图。

首先，在 VoicePurchases 类中创建额外的私有变量，用于存储应用的临时状态 [1]：

juce::Array<VoiceProduct> voiceProducts;

我们还需要一个名为 getPurchase() 的新辅助函数，用于根据索引检索 VoiceProduct。在这个函数中，我们还插入了在该函数首次被调用时执行的初始化代码：

  • [4]：然后我们可以调用 restoreProductsBoughtList() 函数来触发恢复过程，并等待随后的回调。
  • [5]：最后返回指定索引处的 VoiceProduct。作为该函数的正常行为，这一行每次都会被调用。

由于 VoicePurchases 类在上述函数首次被调用时会注册为监听器，我们需要确保在该类销毁时取消注册。在类析构函数中将该类作为 InAppPurchases 监听器移除：

void purchasesListRestored (const juce::Array<PurchaseInfo>& infos, bool success, const juce::String&) override

            for (const auto& productId : info.purchase.productIds)
            {
                auto idx = findVoiceIndexFromIdentifier (productId); // [6]
                if (juce::isPositiveAndBelow (idx, voiceProducts.size()))
                {

                    voiceProduct.isPurchased = true;

        guiUpdater.triggerAsyncUpdate();

我们尚未在应用中实现购买行为，现在来实现它。在 VoicePurchases 类中实现一个公有函数 purchaseVoice()，将请求转发给 InAppPurchases 实例：

void purchaseVoice (int voiceIndex)
{
    if (havePricesBeenFetched && juce::isPositiveAndBelow (voiceIndex, voiceProducts.size()))
    {
        auto& product = voiceProducts.getReference (voiceIndex); // [1]
        if (!product.isPurchased)
        {
            purchaseInProgress = true;
            product.purchaseInProgress = true; // [2]
            juce::InAppPurchases::getInstance()->purchaseProduct (product.identifier); // [3]
  • [1]：首先检查在使用索引检索 VoiceProduct 之前是否已获取价格。
  • [2]：如果该产品此前未被购买，则通过设置相应变量进入购买状态。
  • [3]：现在我们可以通过指定正确的标识符，安全地请求 InAppPurchases 实例购买该产品。

购买结束并收到响应后，这会触发来自服务器的回调。我们在此实现 productPurchaseFinished() 回调：

void productPurchaseFinished (const PurchaseInfo& info, bool success, const juce::String&) override
{
    purchaseInProgress = false;
    for (const auto& productId : info.purchase.productIds)
    {
        auto idx = findVoiceIndexFromIdentifier (productId); // [4]
        if (juce::isPositiveAndBelow (idx, voiceProducts.size()))
        {
            auto& voiceProduct = voiceProducts.getReference (idx); // [5]
            voiceProduct.isPurchased = success;
            voiceProduct.purchaseInProgress = false;
        }
        else
        {
            // On failure Play Store will not tell us which purchase failed
            for (auto& voiceProduct : voiceProducts)
                voiceProduct.purchaseInProgress = false;
        }
    }
    guiUpdater.triggerAsyncUpdate();
}

使用与之前相同的辅助函数，从其标识符获取 VoiceProduct 索引 [4]，并根据购买是否成功在相应对象上设置适当的变量并退出购买状态 [5]。

处理异步更新

由于购买以及与 IAP 服务器的同步在单独的线程上执行，我们需要以异步方式处理响应。在 MainContentComponent 类中，我们继承 AsyncUpdater 类 [1]，并将该类的引用传递给 VoicePurchases 实例 [2]：

class MainContentComponent : public juce::Component,

播放声音

当用户点击播放按钮时，我们需要触发正确的音频文件，用正确的语音和短语播放。音频文件以二进制资源形式存储，命名约定为语音名称加上与短语编号相关的索引。在 MainContentComponent 类中，我们按如下方式处理该行为：

void playStopPhrase()
{
    juce::MemoryOutputStream resourceName;
    auto idx = voiceListBox.getSelectedRow(); // [1]
    if (juce::isPositiveAndBelow (idx, soundNames.size()))
    {
        resourceName << soundNames[idx] << phraseListBox.getSelectedRow() << ".ogg"; // [2]
        auto dir = juce::File::getCurrentWorkingDirectory();
        int numTries = 0;
        while (!dir.getChildFile ("Resources").exists() && numTries++ < 15)
            dir = dir.getParentDirectory();
        auto file = dir.getChildFile ("Resources").getChildFile ("Sounds").getChildFile (resourceName.toString().toRawUTF8());
        if (file.exists())
            player.play (file); // [3]
    }
}
  • [1]：首先获取语音表中选中行的索引，并检查该索引相对于音频文件数组是否有效。
  • [2]：接着使用 MemoryOutputStream 对象和上述命名约定构造正确的文件名。
  • [3]：最后，根据先前构造的文件名检查音频文件能否加载，并使用相应文件调用 SoundPlayer 的 play() 函数。

现在按下播放按钮时，你应该能听到用相应语音朗读的短语。
