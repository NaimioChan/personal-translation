理解 MPE 区域

了解区域的概念，以及 MPE 标准中定义的区域布局约定。把你的 MPE 合成器连接到兼容 MPE 的设备。

难度：中级
平台：Windows、macOS、Linux
类：MPEZoneLayout、MPEZoneLayout::Zone、MPEMessages、MPESynthesiser

MPE 规范

在入门教程教程：构建多复音合成器（MPE）中，我们通过使用传统模式绕过标准的 MPE 配置流程，轻松实现了一个兼容 MPE 的合成器。在本教程中，我们按照最新 MPE 标准描述的流程来配置合成器。

合成器能否判断我们是否工作在 MPE 模式下，取决于 MPE 区域这一概念。如果使用 MPE 配置消息（MCM）定义了至少一个区域，我们就处于 MPE 模式。反之，如果没有定义任何区域，MPE 模式就是关闭的。那么，区域是什么？

MPE 区域

区域这一概念是 MPE 特有的术语，描述一组连续的 MIDI 通道，由一个主控通道和一个或多个成员通道组成。

主控通道接收作用于整个区域的消息，而成员通道接收只作用于单个音符的消息。

在 MPE 中，最多可以有两个区域，分别定义为低音区和高音区。

  • 低音区：通道 1 作为主控通道，一个或多个成员通道从通道 2 开始向上递增分配。
  • 高音区：通道 16 作为主控通道，一个或多个成员通道从通道 15 开始向下递减分配。

一个成员通道同一时间只能属于一个区域，并且最近的 MCM 优先于之前的。

例如，我们可以让低音区包含通道 2 到 10，高音区包含通道 11 到 15。

另外，我们也可以只使用单个区域，即只用低音区或高音区。不过，建议默认使用低音区。在单区域情形下，剩下未使用的主控通道可以作为另一个区域的成员通道使用，从而最多得到 15 个成员通道。

向区域的主控通道发送一个不含任何成员通道的 MCM，即可关闭该 MPE 区域；因此当所有区域都为空时，MPE 模式也就关闭了。

在 JUCE 中，区域的实现封装在 MPEZoneLayout::Zone 结构体中，不同的区域配置可以通过 MPEZoneLayout 类定义。

区域是一种有用的手段，可以只用一个 MPE 控制器就提供不同的音色特征，并且便于通过主控通道在一组组通道之间传播 MIDI 消息。

MIDI 模式

MPE 主要支持两种 MIDI 模式：MIDI 模式 3 和模式 4。

  • MIDI 模式 3（复音模式）：在复音模式下，单个 MIDI 通道可以同时容纳多个音符，但通道消息会影响该通道上所有正在发声的音符。创建新的 MIDI 音符时，控制器会尽可能把它分配到空通道，否则分配到已有活动音符的通道。
  • MIDI 模式 4（单音模式）：在单音模式下，单个 MIDI 通道只能容纳一个音符；创建新的 MIDI 音符时，如果其他通道已满，控制器会覆盖已有的活动音符。

MPE 设计上使用 MIDI 模式 3（复音模式）才能正常工作，但仍可以使用 MIDI 模式 4（单音模式）。

音符级消息与区域级消息

根据 MIDI 消息是在主控通道还是成员通道上发送，我们分别称它们为区域级消息或音符级消息。有些消息既可以发送到区域内的主控通道，也可以发送到成员通道。出现这种情况时，接收方合成器必须以适当方式合并这两部分信息。

必须作为区域级发送的消息如下：

  • CC #1、#33：调制的控制变化。该 CC 可以在音符级发送，但会被忽略。
  • CC #7、#39：音量的控制变化。该 CC 可以在音符级发送，但会被忽略。
  • CC #64：制音踏板的控制变化。该 CC 可以在音符级发送，但会被忽略。
  • CC #120：关闭所有声音的控制变化。该 CC 可以在音符级发送，但会被忽略。
  • CC #127：重置所有控制器的控制变化。该 CC 只能在区域级发送。
  • 复音键压力：PKP 是 MPE 规范的一项未来扩展，在主控通道上发送。
  • MPE 配置（MCM）：MCM 在主控通道上发送，用于按前面所述进行配置。

既可以作为区域级、也可以作为音符级发送的消息如下：

  • 弯音：第一维度的控制变化，也称为滑音。弯音信息如果在两个消息级别都收到，必须合并。
  • 通道压力：第二维度的控制变化，也称为按压。通道压力信息如果在两个消息级别都收到，必须合并。
  • 音色（CC #74）：第三维度的控制变化，也称为滑动。音色信息如果在两个消息级别都收到，必须合并。
  • 弯音灵敏度：用于更改弯音灵敏度的控制变化；作为音符级使用时，应发送到所有成员通道。
  • 音色切换/音色库选择：音色切换在主控通道上发送，但在 MIDI 模式 4 下则在成员通道上发送。

通常作为音符级发送的消息如下：

  • 音符开/关：音符开和音符关消息应在相应的成员通道上发送，但为了向后兼容也允许在主控通道上发送。
  • MIDI 模式（CC #126、#127）：用于在 MIDI 模式 3 和 4 之间切换的控制变化，发送到编号最低的成员通道。

记住这些消息级别很重要，因为它们会影响你在合成器中定义区域时的设计决策。

配置区域

如果不使用教程：构建多复音合成器（MPE）中实现的传统模式，那么在我们配置至少一个区域之前，合成器不会输出任何声音。

在 MPESetupComponent 类中，我们用 lambda 函数添加了三个按钮回调，用于创建和删除区域。我们可以创建低音区和高音区，也可以清除区域布局中的所有区域。

MPESetupComponent()
{
    addAndMakeVisible (isLowerZoneButton);
    isLowerZoneButton.setToggleState (true, juce::NotificationType::dontSendNotification);
addAndMakeVisible (setZoneButton);
setZoneButton.onClick = [this] { setZoneButtonClicked(); };
addAndMakeVisible (clearAllZonesButton);
clearAllZonesButton.onClick = [this] { clearAllZonesButtonClicked(); };

当用户决定设置区域时，会调用如下定义的 setZoneButtonClicked() 函数：

void setZoneButtonClicked()
{
    auto isLowerZone = isLowerZoneButton.getToggleState();
    auto numMemberChannels = memberChannels.getText().getIntValue();
    auto perNotePb = notePitchbendRange.getText().getIntValue();
    auto masterPb = masterPitchbendRange.getText().getIntValue();
    if (isLowerZone)
        zoneLayout.setLowerZone (numMemberChannels, perNotePb, masterPb);
    else
        zoneLayout.setUpperZone (numMemberChannels, perNotePb, masterPb);
    listeners.call ([&] (Listener& l) { l.zoneChanged (isLowerZone, numMemberChannels, perNotePb, masterPb); });
}

我们首先创建新的局部变量，保存低音区/高音区的选择、成员通道数量、区域级弯音和音符级弯音。然后我们在 MPEZoneLayout 对象中设置区域，方法是调用相应的 setLowerZone() 或 setUpperZone() 函数。

要处理清除区域时的回调，我们只需调用 clearAllZones() 函数，它会从 MPEZoneLayout 对象中移除所有区域，如下所示：

void clearAllZonesButtonClicked()
{
    zoneLayout.clearAllZones();
    listeners.call ([] (Listener& l) { l.allZonesCleared(); });
}

配置合成器

由于 MPESetupComponent 类充当广播器，我们可以在 MainComponent 类中注册为监听器，以便在区域布局变化时收到回调。

class MainComponent : public juce::Component,
                      private juce::AudioIODeviceCallback,
                      private juce::MidiInputCallback,
                      private MPESetupComponent::Listener
{
public:

然后我们可以覆盖相应的函数，据此配置合成器。

在 zoneChanged() 回调中，我们把新建的区域设置到 MPEZoneLayout 成员变量 [1] 中。然后我们可以把 MPEZoneLayout 对象传给 MPESynthesiser，方法是在它上面调用 setZoneLayout() [2]：

void zoneChanged (bool isLowerZone, int numMemberChannels, int perNotePitchbendRange, int masterPitchbendRange) override
{
    auto* midiOutput = audioDeviceManager.getDefaultMidiOutput();
    if (midiOutput != nullptr)
    {
        if (isLowerZone)
            midiOutput->sendBlockOfMessagesNow (juce::MPEMessages::setLowerZone (numMemberChannels, perNotePitchbendRange, masterPitchbendRange));
        else
            midiOutput->sendBlockOfMessagesNow (juce::MPEMessages::setUpperZone (numMemberChannels, perNotePitchbendRange, masterPitchbendRange));
    }
    if (isLowerZone)
        zoneLayout.setLowerZone (numMemberChannels, perNotePitchbendRange, masterPitchbendRange);
    else
        zoneLayout.setUpperZone (numMemberChannels, perNotePitchbendRange, masterPitchbendRange);
    visualiserInstrument.setZoneLayout (zoneLayout);
    synth.setZoneLayout (zoneLayout);
    colourPicker.setZoneLayout (zoneLayout);
}

在 allZonesCleared() 回调中，我们清空 MPEZoneLayout 成员变量 [3] 中的所有区域。然后同样可以在 MPESynthesiser 上调用 setZoneLayout()，把 MPEZoneLayout 对象传给它 [4]：

void allZonesCleared() override
{
    auto* midiOutput = audioDeviceManager.getDefaultMidiOutput();
    if (midiOutput != nullptr)
        midiOutput->sendBlockOfMessagesNow (juce::MPEMessages::clearAllZones());
    zoneLayout.clearAllZones();
    visualiserInstrument.setZoneLayout (zoneLayout);
    synth.setZoneLayout (zoneLayout);
    colourPicker.setZoneLayout (zoneLayout);
}

当 MPESynthesiserVoice 对象的数量被修改时，我们会收到 numberOfVoicesChanged() 回调，它让我们可以分别在 MPESynthesiser 对象上使用 reduceNumVoices() 和 addVoice() 函数来移除或添加声部：

void numberOfVoicesChanged (int numberOfVoices) override
{
    if (numberOfVoices < synth.getNumVoices())
        synth.reduceNumVoices (numberOfVoices);
    else
        while (synth.getNumVoices() < numberOfVoices)
            synth.addVoice (new MPEDemoSynthVoice());
}
