使用 AudioSampleBuffer 类循环播放音频（进阶）

本教程展示如何使用线程安全的技术播放并循环存储在 AudioSampleBuffer 对象中的音频。同时还介绍了一种在后台线程加载音频数据的技术。

难度：高级
平台：Windows、macOS、Linux
类：ReferenceCountedObject, ReferenceCountedArray, Thread, AudioBuffer

入门

本教程接续教程：使用 AudioSampleBuffer 类循环播放音频。如果你还没有读过，应该先阅读那篇教程。

在此处下载本教程的演示项目：PIP | ZIP 。解压项目并在 Projucer 中打开第一个头文件。

如果你在这一步需要帮助，请参阅教程：Projucer 第 1 部分：Projucer 入门。

演示项目

演示项目实现了与教程：使用 AudioSampleBuffer 类循环播放音频中演示项目类似的行为。它允许用户打开一个音频文件，将其加载到缓冲区并循环播放。本教程的一个主要区别是音频系统保持运行，而不是每次浏览文件时都关闭它。这是通过使用一些有用的类以线程安全的方式在线程之间通信来实现的。

线程安全的技术

你应该还记得在教程：使用 AudioSampleBuffer 类循环播放音频中，我们如何解决音频线程和消息线程访问可能不完整或已损坏数据的潜在问题。就在浏览文件之前，我们关闭音频系统。然后，一旦选择了文件，我们打开文件并重启音频系统。在真实应用中，这显然是一种不切实际且笨拙的方法！

引用计数对象

ReferenceCountedObject 类是在线程之间传递消息和数据的有用工具。这里，我们把 AudioSampleBuffer 对象和播放位置存储在一个 ReferenceCountedObject 类中。为了便于调试，也为了帮助说明该类如何工作，我们还包含了一个 name 成员（尽管严格来说这并不是该类运作所必需的）：

class ReferenceCountedBuffer : public juce::ReferenceCountedObject
{
public:
    typedef juce::ReferenceCountedObjectPtr<ReferenceCountedBuffer> Ptr;
    ReferenceCountedBuffer (const juce::String& nameToUse,
        int numChannels,
        int numSamples)
        : name (nameToUse),
          buffer (numChannels, numSamples)
    {
        DBG (juce::String ("Buffer named '") + name + "' constructed. numChannels = " + juce::String (numChannels) + ", numSamples = " + juce::String (numSamples));
    }
    ~ReferenceCountedBuffer()
    {
        DBG (juce::String ("Buffer named '") + name + "' destroyed");
    }
    juce::AudioSampleBuffer* getAudioSampleBuffer()
    {
        return &buffer;
    }
    int position = 0;
private:
    juce::String name;
    juce::AudioSampleBuffer buffer;
    JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR (ReferenceCountedBuffer)
};

类顶部的 typedef 是实现 ReferenceCountedObject 子类的重要部分。我们不是把 ReferenceCountedBuffer 对象存储在裸指针中，而是存储在 ReferenceCountedBuffer::Ptr 类型中。正是它管理对象的引用计数（按需递增和递减）及其生命周期（引用计数归零时删除对象）。我们还可以使用 ReferenceCountedArray 类存储一个 ReferenceCountedBuffer 对象数组。

在我们的 MainContentComponent 类中，我们既存储了一个数组，也存储了一个实例：

juce::SpinLock mutex;
juce::ReferenceCountedArray<ReferenceCountedBuffer> buffers;
ReferenceCountedBuffer::Ptr currentBuffer;

buffers 成员在数组中保留我们的缓冲区，直到我们完全确定音频线程不再需要它们。currentBuffer 成员保存当前选中的缓冲区。

实现后台线程

我们的 MainContentComponent 类继承自 Thread 类：

class MainContentComponent : public juce::AudioAppComponent,
                             private juce::Thread
{
public:

它用于实现我们的后台线程。我们重写的 Thread::run() 函数如下：

void run() override
{
    while (!threadShouldExit())
    {
        checkForBuffersToFree();
        wait (500);
    }
}

这里我们检查是否有需要释放的缓冲区，然后线程等待 500ms 或被唤醒（使用 Thread::notify() 函数）。本质上，这意味着检查至少每 500ms 发生一次。checkForBuffersToFree() 函数会搜索我们的 buffers 数组，看看是否有缓冲区可以释放：

void checkForBuffersToFree()
{
    for (auto i = buffers.size(); --i >= 0;) // [1]
    {
        ReferenceCountedBuffer::Ptr buffer (buffers.getUnchecked (i)); // [2]
        if (buffer->getReferenceCount() == 2) // [3]
            buffers.remove (i);
    }
}
  • [1]：在这些情况下，记住要反向遍历数组是很有用的。如果我们在遍历数组时删除元素，就更容易避免破坏数组索引访问。
  • [2]：这会保留指定索引处缓冲区的一份副本。
  • [3]：如果此时引用计数等于 2，我们就知道音频线程不可能正在使用该缓冲区，可以将其从数组中移除。这两个引用中的一个在 buffers 中，另一个在局部 buffer 变量中。被移除的缓冲区会在 buffer 变量离开作用域时自行删除（因为这将是最后一个剩余的引用）。

当然，我们需要在应用启动时启动线程，这在 MainContentComponent 构造函数中完成：

startThread();
}

打开文件

我们的 openButtonClicked() 函数与教程：使用 AudioSampleBuffer 类循环播放音频中的 openButtonClicked() 函数类似，只有一些细微差别：

void openButtonClicked()
{
    chooser = std::make_unique<juce::FileChooser> ("Select a Wave file shorter than 2 seconds to play...",
        juce::File {},
        "*.wav");
    auto chooserFlags = juce::FileBrowserComponent::openMode
                        | juce::FileBrowserComponent::canSelectFiles;
    chooser->launchAsync (chooserFlags, [this] (const juce::FileChooser& fc) {
        auto file = fc.getResult();
        if (file == juce::File {})
            return;
        std::unique_ptr<juce::AudioFormatReader> reader (formatManager.createReaderFor (file));
        if (reader != nullptr)
        {
            auto duration = (float) reader->lengthInSamples / reader->sampleRate;
            if (duration < 2)
            {
                ReferenceCountedBuffer::Ptr newBuffer = new ReferenceCountedBuffer (file.getFileName(),
                    (int) reader->numChannels,
                    (int) reader->lengthInSamples);
                reader->read (newBuffer->getAudioSampleBuffer(), 0, (int) reader->lengthInSamples, 0, true, true);
                {
                    const juce::SpinLock::ScopedLockType lock (mutex);
                    currentBuffer = newBuffer;
                }
                buffers.add (newBuffer);
            }
            else
            {
                // handle the error that the file is 2 seconds or longer..
            }
        }
    });
}

以下是差别：

  • 分配 ReferenceCountedBuffer 类的新实例。
  • 把音频数据读入它所包含的 AudioSampleBuffer 对象。
  • 使其成为当前缓冲区。
  • 将其添加到我们的缓冲区数组。

要清除当前缓冲区，我们只需把它的值设为 nullptr ：

void clearButtonClicked()
{
    const juce::SpinLock::ScopedLockType lock (mutex);
    currentBuffer = nullptr;
}

播放缓冲区

我们的 getNextAudioBlock() 函数与教程：使用 AudioSampleBuffer 类循环播放音频中的 getNextAudioBlock() 函数类似，只是我们需要访问当前的 ReferenceCountedBuffer 对象及其包含的 AudioSampleBuffer 对象。

void getNextAudioBlock (const juce::AudioSourceChannelInfo& bufferToFill) override
{
    auto retainedCurrentBuffer = [&]() -> ReferenceCountedBuffer::Ptr // [4]
    {
        const juce::SpinLock::ScopedTryLockType lock (mutex);
        if (lock.isLocked())
            return currentBuffer;
        return nullptr;
    }();
    if (retainedCurrentBuffer == nullptr) // [5]
    {
        bufferToFill.clearActiveBufferRegion();
        return;
    }
    auto* currentAudioSampleBuffer = retainedCurrentBuffer->getAudioSampleBuffer(); // [6]
    auto position = retainedCurrentBuffer->position; // [7]
    auto numInputChannels = currentAudioSampleBuffer->getNumChannels();
    auto numOutputChannels = bufferToFill.buffer->getNumChannels();
    auto outputSamplesRemaining = bufferToFill.numSamples;
    auto outputSamplesOffset = 0;
    while (outputSamplesRemaining > 0)
    {
        auto bufferSamplesRemaining = currentAudioSampleBuffer->getNumSamples() - position;
        auto samplesThisTime = juce::jmin (outputSamplesRemaining, bufferSamplesRemaining);
        for (auto channel = 0; channel < numOutputChannels; ++channel)
        {
            bufferToFill.buffer->copyFrom (channel,
                bufferToFill.startSample + outputSamplesOffset,
                *currentAudioSampleBuffer,
                channel % numInputChannels,
                position,
                samplesThisTime);
        }
        outputSamplesRemaining -= samplesThisTime;
        outputSamplesOffset += samplesThisTime;
        position += samplesThisTime;
        if (position == currentAudioSampleBuffer->getNumSamples())
            position = 0;
    }
    retainedCurrentBuffer->position = position; // [8]
}

重要的变化是：

  • [4]：我们保留 currentBuffer 成员的一份副本。在这个函数中此点之后，currentBuffer 成员是否在另一个线程上被改变就无关紧要了，因为我们已经取得了本地副本。注意我们这里使用尝试锁定，这样在另一个线程正在修改 currentBuffer 时，音频线程不会卡在等待访问它上。
  • [5]：如果我们取得副本时 currentBuffer 成员为空，我们输出静音。
  • [6]：我们访问 ReferenceCountedBuffer 对象内的 AudioSampleBuffer 对象。
  • [7]：我们获取缓冲区的当前播放位置。
  • [8]：修改当前播放位置后，我们把它存回 ReferenceCountedBuffer 对象。

该算法确保 ReferenceCountedBuffer 对象不会在音频线程上被删除。在音频线程上分配或释放内存不是好主意。ReferenceCountedBuffer 对象只会在我们的后台线程上被删除。

在后台线程读取音频

我们的应用仍然在消息线程上读取音频数据。这并不理想，因为这会阻塞消息线程，而大文件可能需要一些时间才能加载。事实上，我们也可以使用后台线程来执行这项任务。

将文件路径传递给后台线程

首先，向 MainContentComponent 类添加以下成员：

juce::CriticalSection pathMutex;
juce::String chosenPath;

现在修改 openButtonClicked() 函数，把文件的完整路径交换到这个成员中。交换字符串在技术上不是线程安全的，所以我们还需要加锁，以确保在这个线程使用 chosenPath 时没有其他线程试图修改它。

void openButtonClicked()
{
    chooser = std::make_unique<juce::FileChooser> ("Select a Wave file shorter than 2 seconds to play...",
        juce::File {},
        "*.wav");
    auto chooserFlags = juce::FileBrowserComponent::openMode
                        | juce::FileBrowserComponent::canSelectFiles;
    chooser->launchAsync (chooserFlags, [this] (const juce::FileChooser& fc) {
        auto file = fc.getResult();
        if (file == juce::File {})
            return;
        auto path = file.getFullPathName();
        {
            const juce::ScopedLock lock (pathMutex);
            chosenPath.swapWith (path);
        }
        notify();
    });
}

这里我们还唤醒后台线程，因为我们将要在后台线程上调用函数来打开文件。

从后台线程访问路径

我们的 run() 函数应更新如下：

void run() override
{
    while (!threadShouldExit())
    {
        checkForPathToOpen();
        checkForBuffersToFree();
        wait (500);
    }
}

checkForPathToOpen() 函数通过把 chosenPath 成员交换到局部变量来检查它。同样，交换不是线程安全的，因此在访问 chosenPath 之前我们必须加锁。

void checkForPathToOpen()
{
    juce::String pathToOpen;
    {
        const juce::ScopedLock lock (pathMutex);
        pathToOpen.swapWith (chosenPath);
    }
    if (pathToOpen.isNotEmpty())
    {
        juce::File file (pathToOpen);
        std::unique_ptr<juce::AudioFormatReader> reader (formatManager.createReaderFor (file));
        if (reader.get() != nullptr)
        {
            auto duration = (float) reader->lengthInSamples / reader->sampleRate;
            if (duration < 2)
            {
                ReferenceCountedBuffer::Ptr newBuffer = new ReferenceCountedBuffer (file.getFileName(),
                    (int) reader->numChannels,
                    (int) reader->lengthInSamples);
                reader->read (newBuffer->getAudioSampleBuffer(), 0, (int) reader->lengthInSamples, 0, true, true);
                {
                    const juce::SpinLock::ScopedLockType lock (mutex);
                    currentBuffer = newBuffer;
                }
                buffers.add (newBuffer);
            }
            else
            {
                // handle the error that the file is 2 seconds or longer..
            }
        }
    }
}

如果 pathToOpen 变量是空字符串，我们就知道没有新文件要打开。这个函数中其余代码对你来说应该很熟悉。

再次运行应用，它应该仍能正常工作。
