为插件配置正确的总线布局

学习如何为多种配置情况配置和限制插件中的总线布局。使用 Apple Logic Pro 中提供的 auval 工具检查你的 AU 插件的总线安排。

难度：初级
平台：Windows、macOS、Linux 插件格式：VST、VST3、AU、Standalone
类：AudioProcessor::BusesLayout、AudioProcessor::BusesProperties、AudioChannelSet、AudioProcessor

入门

要学习本教程，请确保你已打开一个插件项目，或者在 Projucer 中新建一个 Audio Plugin 项目。

如果你在这一步需要帮助，请参阅教程：创建基本的音频/MIDI 插件，第 1 部分：设置。

要构建 AudioUnit 插件并使用 auval 工具测试它，你需要在 macOS 上构建，并安装 Logic Pro X。

简介

JUCE 中的 AudioProcessor 类接收若干输入通道，处理输入的数据，然后将结果提供给若干输出通道，如下图所示：

对于许多类型的音频处理器来说，这就足够了。然而，你常常希望将这些单独的通道表示为一个组，以便于宿主与处理器之间的通信。例如，前四个输入通道可以用作主通道，后两个输入通道可以用作侧链，如下所示：

上图中的黄色箭头称为总线。因此，总线是一组通道，它们通常在插件内部共享相同的信号路径，例如主音频信号路径或侧链信号路径。在 JUCE 中，每条总线都有一个名称，以便你可以识别它在插件中的具体用途。

在几乎每个 DAW 中，第一条输入总线或第一条输出总线被称为主总线。在 JUCE 中，你有时会看到注释或方法名提及主总线，它其实就是第一条输入或输出总线。

然而，仅仅对音频处理器的输入和输出通道进行分组并为这些组命名是不够的。你还需要传达每条总线内每个通道的空间位置信息。例如，你可以将总线配置为立体声总线（左、右）、四声道总线（左、右、左环绕、右环绕）或单声道总线（中置）等。在 JUCE 中，每条总线都被分配一个 AudioChannelSet，用于描述这些通道组的空间位置（例如：AudioChannelSet::mono()、AudioChannelSet::stereo()、AudioChannelSet::quadraphonic()）。

需要注意的是，每条总线的 AudioChannelSet 在插件的整个生命周期内并不是固定的。DAW 可能随时为某条特定总线请求不同的 AudioChannelSet，例如当 DAW 用户将侧链源从单声道切换为立体声时。为实现这一点，JUCE 支持一个回调，用于向插件查询每条总线支持哪些 AudioChannelSet 对象。

有一个特殊的 AudioChannelSet 名为 AudioChannelSet::disabled()，它不包含任何通道。这个 AudioChannelSet 用于表示某条总线当前未被使用，例如在 DAW 中未连接侧链时。

总之，要在任意时刻传达插件每个通道的信息，DAW 和插件必须：

  • 交换关于通道如何分组为总线的信息。
  • 交换关于每条总线的名称和当前 AudioChannelSet 的信息。
  • 协商每条总线支持哪些 AudioChannelSet 对象。

让我们从插件开发者的角度开始，探讨如何将这些信息传达给宿主。

分配 BusesProperties

在编写插件时，我们首先关注前两点（将通道分组并命名到总线中，以及为每条总线选择一个 AudioChannelSet）。这些信息通过将一个 AudioProcessor::BusesProperties 实例传递给 AudioProcessor 的构造函数来传达给 DAW，如下所示：

ExampleAudioProcessor()
    : AudioProcessor (BusesProperties().withInput ("Input", juce::AudioChannelSet::stereo(), true).withOutput ("Output", juce::AudioChannelSet::stereo(), true))
{
    //...

上面的代码告知 DAW，该插件有两条总线：一条名为“Input”的输入总线和一条名为“Output”的输出总线。withInput() 和 withOutput() 函数中的第二个参数描述相应总线的初始 AudioChannelSet。重要的是要记住，DAW 可以随时改变这一点。第三个参数指示该总线最初是启用还是禁用。由于这两条总线都是主总线，禁用它们没有多大意义。

前面的示例通常用于效果插件。然而，合成器插件通常只有一条输出总线，因此构造函数看起来会是这样：

ExampleAudioProcessor()
    : AudioProcessor (BusesProperties().withOutput ("Output", juce::AudioChannelSet::stereo(), true))
{
    //...

JUCE 支持的另一类插件是 MIDI 效果插件。由于它们只处理 MIDI，因此完全没有音频总线：

ExampleAudioProcessor()
    : AudioProcessor (BusesProperties())
{
    //...

不要将上面的构造函数代码与调用默认 AudioProcessor 构造函数混淆。为向后兼容，默认构造函数会创建一个插件，其中包含一条最初被禁用、名为“Input”的输入总线和一条最初被禁用、名为“Output”的输出总线——两者都是 AudioChannelSet::stereo()。

配置 BusesLayout

现在唯一需要做的步骤是配置某条总线支持的 AudioChannelSet 对象，因为 DAW 可能希望随时更改构造函数中提供的初始 AudioChannelSet。需要注意的是，插件无法主动更改自己的布局：插件是被动的，始终“受制于”宿主。它只能拒绝或接受所请求的 AudioChannelSet 配置。

为此，插件需要重写 AudioProcessor::isBusesLayoutSupported() 回调。该回调接受单个 BusesLayout 参数，它实际上就是插件每条总线对应一个 AudioChannelSet 对象的数组。

受支持的输入和输出总线数组中的元素数量，将始终与你在 AudioProcessor 构造函数中指定的总线数量一致。

在你的 AudioProcessor::isBusesLayoutSupported() 回调中，你需要返回给定的 BusesLayout 是否受支持。例如，默认回调是接受 DAW 请求的任何 BusesLayout，如下所示：

bool isBusesLayoutSupported (const BusesLayout& layouts) const
{
    return true;
}

大多数效果插件只有一条主输入总线和一条主输出总线。通常，它们要求输入侧和输出侧的 AudioChannelSet 相同，如下所示：

bool isBusesLayoutSupported (const BusesLayout& layouts) const
{
    return layouts.getMainInputChannelSet() == layouts.getMainOutputChannelSet();
}

请记住，有一个特殊的 AudioChannelSet 名为 AudioChannelSet::disabled()，它表示某条总线被禁用。大多数效果插件不希望其主总线被禁用，因此我们可以在回调中加入这样的检查：

bool isBusesLayoutSupported (const BusesLayout& layouts) const
{
    if (layouts.getMainInputChannelSet() == juce::AudioChannelSet::disabled()
        || layouts.getMainOutputChannelSet() == juce::AudioChannelSet::disabled())
        return false;
    return layouts.getMainInputChannelSet() == layouts.getMainOutputChannelSet();
}

假设该插件只能处理单声道到单声道或立体声到立体声的配置。上面代码的最后一行已经检查了输入和输出布局必须相同，因此我们只需对输入或输出总线做前面的检查即可，如下所示：

bool isBusesLayoutSupported (const BusesLayout& layouts) const
{
    if (layouts.getMainInputChannelSet() == juce::AudioChannelSet::disabled()
        || layouts.getMainOutputChannelSet() == juce::AudioChannelSet::disabled())
        return false;
    if (layouts.getMainOutputChannelSet() != juce::AudioChannelSet::mono()
        && layouts.getMainOutputChannelSet() != juce::AudioChannelSet::stereo())
        return false;
    return layouts.getMainInputChannelSet() == layouts.getMainOutputChannelSet();
}

测试 BusesLayout

我们在插件中支持的总线布局配置可以使用不同的工具来测试，因为很容易忽略 isBusesLayoutSupported() 函数中所定义布局的边界情况。

在本教程中，我们提供两种方案：Apple Logic Pro 中包含的 auval 工具，用于测试和验证 AudioUnits；以及 JUCE 中包含的 Audio Plugin Host，它支持 VST 和 AU 插件。

使用 auval 工具测试

本节介绍的工具仅在 macOS 上可用于 AudioUnits。

auval 工具会在 AudioUnits 被加载到 Apple 的插件宿主（如 Logic Pro X 和 Final Cut Pro X）之前对其进行验证。它会对你的插件执行各种有用的测试，但就本教程而言，我们重点关注总线布局测试。

在 Logic Pro X 中，可以通过依次进入 Logic Pro X > Preferences > Plug-in Manager… 并点击 Reset & Rescan Selection 来调用验证，从而访问 auval 工具，如下所示：

不过，我们也可以通过命令行这样调用它：

auval - v aufx Test Manu

使用插件宿主测试

另一个有用的工具是 JUCE 附带的 Audio Plugin Host，它位于库的 JUCE/examples 文件夹中。该工具允许你通过在运行时更改总线布局来测试 VST 和 AU 插件。

如果你需要关于构建和使用 Audio Plugin Host 的帮助，请参阅教程：创建基本的音频/MIDI 插件，第 1 部分：设置以获取详细说明。

打开 Audio Plugin Host，并加载一个你想测试的插件实例。如果你右键点击该插件并选择 Configure Audio I/O ，应该会看到以下窗口出现：

在这里，如果你的插件允许，你可以添加或移除输入或输出总线，更改所选总线的通道集，并按需启用或禁用总线。

请注意，当你第一次加载插件时，可以看到输入和输出引脚显示的是在 AudioProcessor 构造函数中设置的默认 BusesLayout 配置。

练习：尝试不同的总线布局，并在 auval 工具和 Audio Plugin Host 中检查插件的行为。

总结

阅读本教程后，你应该能够：

  • 用不同的通道集定义输入、输出和侧链总线。
  • 为你的插件类型配置偏好的总线布局。
  • 使用 auval 工具检查 AudioUnits 的总线安排配置。
  • 在 JUCE 音频插件宿主中分配不同的总线属性。
