ValueTree 类

了解如何使用 ValueTree 类在你的应用程序中高效地管理数据。

难度：中级
平台：Windows、macOS、Linux、iOS、Android
类：ValueTree、var、Identifier

简介

ValueTree 类是 JUCE 的秘密武器。它能够大幅简化应用程序内部的复杂性，把传统上被动的数据模型转变为运行时操作的积极参与者。它处理了开发中一些较为繁琐的方面，例如让数据与 GUI 对接、为数据修改提供自动撤销与重做，以及为你的数据提供通用容器。它天生可序列化，使导出和导入过程非常直接。

你可能对它们并不了解，或者只是没有意识到它们的潜力。本指南旨在涵盖使用它们所需的全部知识。

三个核心类

ValueTree 类实际上是一个组合体，在使用它们时，你总是会与至少三个重要的类打交道。这三个类是 ValueTree 类本身、var 类和 Identifier 类。使用 ValueTree 对象做任何有意义的事情都不可能不遇到它们，因此了解应该怎样（以及为何）使用它们是很有用的。所以，在我们讨论操作这类数据的实际细节之前，你应该先熟悉以下内容：

ValueTree 类概览

ValueTree 类是终极容器类，能够容纳任何类型的信息。虽然这可能是该类型显而易见的职责，但它还有许多其他方面，使其超越了单纯的结构性职责。

数据存储

ValueTree 对象是一个灵活的多用途数据对象。它有一个基本的类型名，并且可以容纳任意一组具名属性。它就像一种通用结构体；你不需要定义它应该容纳什么（或多少）数据，只需在运行时按需使用即可。

为了便于说明，一个对象（此处以伪数据形式展示）可能包含以下信息：

Pet
Name = "Fluffmuff"
Animal = "Cat"
Size = 2.4

顾名思义，ValueTree 对象也可以充当树结构中的一个节点。除了具名属性之外，它还可以包含任意数量的子节点（并且它本身也可以被添加到父节点中）。

Pet
Name = "Fluffmuff"
Animal = "Cat"
Size = 2.4
Accessories
Collar
Colour = "Pink"
Camera
HasFlash = false
Capacity = 32

这些结构与 XML 格式中形成的结构非常相似；单个 ValueTree 节点非常像 XmlElement 对象，具有名称、属性和子节点。最大的区别在于，属性以真正的带类型数据存储，而不是 XML 格式那种一切皆文本的表示方式。这意味着它们可以容纳更复杂的数据类型、更高效地访问数据，并且总体上更适合用于数据模型（而不仅仅是序列化）。事实上，可以从任何给定的 ValueTree 节点自动生成 XML 文本（或一种特殊的二进制格式），之后再恢复该结构。

引用计数

每个节点都进行引用计数，因此其生命周期很容易管理。数据本身实际上存储在一个隐藏的共享实例中，ValueTree 类只是它的一个轻量级、保持引用的包装接口。

你可以按值快速地传递它们，而不必直接使用指针；从函数返回 ValueTree 对象不会复制任何数据，只复制一个引用，因此这使你的接口既简单又安全。

你永远不必担心自己删除它们；一旦你在任何地方都不再使用某个对象，它就会被自动销毁。这也意味着节点数据永远不会在你仍可能使用它的时候被意外删除，这对于确保异步 UI 永远不会遇到悬空指针尤其方便。

简单的接口

它有一个简单、通用的接口来操作其属性和子节点。由于它是通用的，因此无论内容是什么类型或如何组织，都可以用单一的接口来访问。使用通用的 var 类作为共同的属性类型，它可以接受多种输入。使用 Identifier 类按名称存储和检索这些属性，它提供了一种直观的方式来组织你的数据。

撤销与重做

由于拥有如此简洁的一组控制手段，它能够提供内置的撤销支持；所有修改内容的函数都内置了预定义的可撤销动作，因此你只需提供一个 UndoManager 对象，就能在应用程序中提供此类功能。如果你还没有被说服，这就是在数据模型中使用 ValueTree 对象的一个非常有说服力的理由。

通知

另一个非常强大的特性是 ValueTree 在内容变化时能够发送通知；这带来了巨大的实际简化，尤其是在保持 UI 同步更新方面。例如，用于显示某个节点内容的 Component 对象，只要发现数据被编辑就可以简单地刷新自身——你只需将其实现为 ValueTree::Listener 的子类。

小结

ValueTree 类就像是应用程序数据模型的某种神奇类，毫不费力地提供了丰富的功能，简化了应用程序内部各部分的衔接方式。

var 类概览

var 类是一个通用的变体类，用于容纳各种类型的数据。它的功能使其适合表示 JSON 数据结构。

传统上，你必须预先决定代码中任何给定变量可以存储什么类型的数据（例如，如果你想保存一个整数，你会选择 int，而这个变量就只能用于此目的）。然而，如果你使用 var，就不必做出这样的决定，因为它兼容多种类型。

它就像一个通用的变色龙变量，能够表示基本的数值（int 或 double）、文本（String 对象）和 bool 值，以及 void 状态（因为 0 或 false 在概念上可能不同于什么都没有）。它们还可以保存指向任何派生自 ReferenceCountedObject 类的对象的指针（该类可以包含你能想象到的任何复杂数据）。如果这还不够，单个 var 对象还可以用作多个 var 对象的数组！

这种多用途性使其非常适合用于通用容器（例如 ValueTree 类），让其接口可以不必关心你给它（或期望从它那里得到）的是什么类型，只要能用 var 容纳即可。基本类型有隐式转换（以及重载的赋值运算符），使代码中的交互变得简单。你甚至可以自动返回其当前值的字符串表示（包括非文本类型）。这些便利唯一不完全适用的地方，是 var 对象持有 ReferenceCountedObject 对象时。由于这些是未知类型，你必须自己进行转换（可以安全地使用 dynamic_cast，因为如果类型不正确，它会返回 nullptr）。

在 ValueTree 对象中，所有属性都以 var 对象的形式保存。通过选择这个多用途类作为属性类型，就可以用同一组函数来访问它们，无论它们是什么。你不需要为 int 值使用一个函数、为文本使用另一个函数；所有这类函数都可以通过处理 var 对象来统一。

Identifier 类概览

这个类旨在作为一种人类可读的键，用于标识数据。

本质上，Identifier 对象就是一个字符串。你可以从 String 对象赋值给它，也可以将其内容作为 String 对象获取。在 ValueTree 类的上下文中，它既用于指定节点的类型名，也用于唯一地标记每个属性。

为什么不直接使用 String 类？

使用专门的类而不是通用 String 类有两个主要原因。

  • 它可以强制限定字符集：首先，这个类对可构成有效键的字符施加了限制；它只允许字母数字字符和特殊字符 _-:#$%。这听起来可能有点糟糕，但它使得与其他具有相同限制的系统（例如 XML 格式和脚本）保持兼容成为可能。
  • 它可以针对用途进行优化：第二个（也是最重要的）原因源于我们想要如何使用它们。它们的作用是作为键，从任意大小的列表中标识单个条目，因此对它们执行的最常见操作是比较。然而，String 对象的比较可能相当慢。我们实际上必须检查文本，只有当我们找到第一个不同的字符时，才能确定两个 String 对象不相同。对于大部分相同的字符串，我们可能最终要检查大部分字母（而完全匹配的字符串则要测试其所有字符）。对于单次比较，这或许可以接受，但当你想把一个字符串与一个列表进行比较时（就像我们把它用作键时那样），整件事可能会花费很长时间。

通过使用专门的类，我们可以确保它经过优化以支持快速比较。由于这种优化（以及受限的字符集），它们不适合用于一般文本处理，但它们非常适合将类字符串数据用作键。

为什么它们的比较可以更快？

了解 Identifier 类的优化是很有用的。一方面，它会让你放心，代码并不是在每次测试时都偷偷检查所有字符。但更重要的是，与许多优化一样，这涉及一定的代价，了解代价在哪里有助于你避免它成为问题。

完全可以在不了解这些内容的情况下使用 Identifier，但如果你了解，就能更好地理解权衡发生在哪里。

这种优化的细节很可能会改变（这是类的次要知识），但它对你的实现所产生的影响不太可能改变。

String 比较中的一个特例

要知道两个 String 对象相同，你实际上必须做的是证明它们没有不同。碰巧的是，String 类持有引用计数的文本，因此两个 String 对象有可能实际上指向同一份数据；如果是这种情况，我们可以立刻发现（因为它们都会持有相同的地址）。

这些特例要快得多，但 String 类只有在它们发生时才能加以利用。当地址不相同时，并不能证明它们的内容不等价，因此我们仍然必须检查字符。

利用这个特例

Identifier 类利用了这一行为，使得我们实际上可以保证所有等价的 Identifier 对象始终指向同一份数据。由于它们的优化方式，不同内存地址上永远不会存在逐字符匹配的不同 Identifier 对象。这意味着相同字符串的这个特例成为了等价的唯一方式，因此证明它们不同就如同发现它们持有不同地址一样简单。

然而这并不是魔法，代价只是被转移到了别处。

为了强制实现这一行为，所有 Identifier 对象共享一个单一的、隐藏的全局唯一字符串池。运行时使用的每个 Identifier 对象所持有的字符串都存储在这个池中。当一个 Identifier 对象由 String 对象赋值而来时，会检查池中是否已经包含等价的副本。如果包含，就会改用那个副本；如果不包含，则添加新的 String 对象，供下一个 Identifier 对象查找。

代价

因此，Identifier 对象由 String 对象实例化，是其操作中最昂贵的部分。一旦某个对象存在，如果你总是从它复制，就再也不必为此付出代价。有时这是不可避免的（特别是当你获取 Identifier 对象，来源是输入或保存在普通 String 对象中的数据时），但这比比较它们的情况要少见得多。每次你从裸 String 对象（无论是来自数据，还是代码中的字面量）赋值时，都需要进行池检查以强制实施优化。如果你改为从另一个已有的 Identifier 对象赋值，则可以保证这样的检查已经完成。

如何将代价降到最低

一个好的策略是在启动时初始化一些易于访问的 Identifier 实例。之后在你的代码中，可以使用它们代替字面字符串，这样就不会再因它们而产生任何查找开销。你可以把它们放在全局可访问的命名空间中，使用文件静态实例，甚至使用静态类成员来帮助组织它们。

ValueTree 类的基本用法

除了 var 和 Identifier 类之外，实际上还有许多其他类会与 ValueTree 对象一起使用，我们稍后会看到。然而，这些类是 ValueTree 类中大多数基本操作所必需的。

一旦你了解了这三个核心类，就应该可以继续学习基础内容了。

这是一份基础指南，介绍了 ValueTree 类的所有核心基本函数。它涵盖了你在代码中开始使用它们所需的全部功能。

创建 ValueTree 对象

你可以简单地在栈上（或作为类的成员）创建一个对象来使用 ValueTree 对象。

无效的 ValueTree 对象

ValueTree 对象默认是无效的。也就是说，一个 ValueTree 对象若以默认构造函数初始化，将完全没有数据。除非你显式地用 Identifier（或一个已有的有效 ValueTree 对象）初始化它，否则它不持有任何内容；它只是一个空壳。

juce::ValueTree myNode; // this object is invalid - it does not hold any node data

这类似于空指针（事实上，在内部它正是如此），但没有任何固有的危险。在它被赋予有效节点之前，它不指向任何东西。这里的主要区别在于，接口函数仍然可以使用，尽管基本上没有任何效果（因为没有什么可操作的）。

虽然在无效节点上「意外」调用访问函数是安全的，但这并不会让你走得更远！

如何检查节点是否无效

在代码中，你可以调用成员函数 ValueTree::isValid() 来查明 ValueTree 是否为空：

if (myNode.isValid())
{
    // This will not be reached for an invalid node
}

有效的 ValueTree 对象

创建有效 ValueTree 对象的主要方式是用一个有效的 Identifier 对象进行初始化。它用于为新节点命名，并代表节点的类型。

static juce::Identifier myNodeType ("MyNode"); // pre-create an Identifier
juce::ValueTree myNode (myNodeType); // This is a valid node, of type "MyNode"

你可以使用字符串字面量来代替显式提供 Identifier 对象，但更好的做法是尽可能使用已有的 Identifier 实例。（更多信息请参阅 Identifier 类概览。）

通过要求有效节点必须具有类型，我们有了一种机制来表明它应该包含何种数据。反过来，当面对一个 ValueTree 对象时（例如作为传递给函数的参数），你可以检查它的类型——使用 ValueTree::getType() 函数——以确定你可能会在其中找到什么。

void foo (const juce::ValueTree& someNode)
{
    if (someNode.getType() == myNodeType)
    {
        // This would be hit for nodes created as “MyNode”
    }
}

节点一旦创建，就不能更改其类型。这是有意为之，因为这类信息并不是对象的属性，而是对象的根本本质。

共享有效的 ValueTree 对象

ValueTree 可以被初始化的第三种方式是通过拷贝构造函数，提供一个已有的 ValueTree 对象。

[1] : juce::ValueTree myNode (myNodeType); // creates a new node of type "MyNode"
[2] : juce::ValueTree sameNode (myNode); // This object points to the same data as myNode

这会产生一个与已有对象指向同一份节点数据的对象。

重要的是要理解，这里除了引用之外没有复制任何东西；两个对象都附加到原始节点数据的同一个底层实例上。对其中任何一个所做的更改（如果共享节点有效）在检查另一个时都能看到。

你可以使用赋值运算符达到同样的结果（共享节点数据）。

[3] : juce::ValueTree otherNode (myNodeType); // This creates a second (new) "MyNode" node...
[4] : otherNode = sameNode; // ...but the object now points to the first instance

这里有一个问题：

当我们在第 [4] 行替换第 [3] 行创建的节点实例时，它会发生什么？

到最后，三个变量都指向同一个初始实例。不再有任何 ValueTree 对象引用第二个实例，因此它被销毁了。

每当 ValueTree 对象被重新赋值（或离开作用域）时，它原本指向的底层数据就会失去一个引用。如果该数据没有保存在其他地方，它就会被自动销毁。这听起来可能很吓人，仿佛你可能处在一个数据随时会自毁的世界里；但在现实中，你几乎不可能意外丢失节点！这是一个非常健壮的系统。此外，如果数据很重要，你很可能发现自己实际上已经把它保存在某处了；这已经直观得不能再直观了。

这也意味着你需要在音频回调这类实时代码中格外小心。在音频回调中重新赋值 ValueTree 对象，如果不再有对先前赋值数据的引用，可能会意外触发 delete 运算符。

关于 UndoManager 类的说明

ValueTree 类中的所有访问函数都知道如何使用 UndoManager 对象。它们已预先准备好合适的 UndoableAction 对象；你只需在调用时提供一个指向 UndoManager 对象的指针，一条可操作的、可撤销的修改记录就会自动添加到其中。

管理这一点不需要了解太多，但我们会在教程：将 UndoManager 与 ValueTree 配合使用中更详细地介绍。

目前，我们将通过提供 nullptr 值来使用这些函数，而不必费心保存历史记录。我们默认认为，在描述这些修改函数时，必须至少给它们一个指向 UndoManager 对象的空指针；当然，示例中会看到 nullptr 值。

作为 Listener 接收通知

注册为 ValueTree 的监听器，使我们能够在数据发生变化时同步收到通知。监听器的指针保存在 ValueTree 实例中，因此通常最好在注册之前先拷贝一份 ValueTree，如下所示：

struct ExampleListener : public juce::ValueTree::Listener
{
    ExampleListener (juce::ValueTree v)
        : tree (v)
    {
        tree.addListener (this);
    }
    juce::ValueTree tree;
};

然后，我们可以根据希望收到通知的行为，实现以下回调函数：

  • valueTreePropertyChanged()：当 ValueTree 或其任何子节点发生属性更改时调用。
  • valueTreeChildAdded()：当有子节点被添加到 ValueTree 或其任何子节点时调用。
  • valueTreeChildRemoved()：当有子节点从 ValueTree 或其任何子节点中移除时调用。
  • valueTreeChildOrderChanged()：当有子节点在 ValueTree 或其任何子节点中重新排序时调用。
  • valueTreeParentChanged()：当 ValueTree 被添加到父节点或从父节点中移除时调用。

回调会在树层级中向上传播，因此父节点的监听器也会收到来自子节点的属性更改回调，所以应该检查类型和属性名。

由于回调是同步的，对于任何对时间敏感的应用，你应该使用 AsyncUpdater 来处理属性更改。

基本的属性访问

设置属性

ValueTree::setProperty() 函数是在有效节点上设置属性的一种直接方式。你必须提供一个 Identifier 对象来指定要设置的属性名，以及一个 var 值作为其取值：

static juce::Identifier propertyName ("name");
myNode.setProperty (propertyName, "Fluffmuff", nullptr);

获取属性

获取属性有两种基本方式。无论采用哪种方式，都必须提供一个 Identifier 来指定你要请求的具名属性。

使用 ValueTree::getProperty() 函数：

juce::String name (myNode.getProperty (propertyName));

或者使用下标运算符（即 [ValueTree::operator[](https://docs.juce.com/master/classValueTree.html#a6cf8b3f5eac2d14f1323f5fe0f228a71 “返回具名属性的值。”) 函数）：

name = myNode[propertyName];

上面两行都把相同的结果存入 name 变量。请记住，这些属性可以保存任何受支持的 var 类型。因此，以下代码也是有效的：

static juce::Identifier propertySize ("size");
myNode.setProperty (propertySize, 2.4, nullptr);
double size = myNode[propertySize];

这里，属性以同样的方式用 double 值设置，并且很容易以同样的方式读回。也可以用不同类型的值替换已有的属性。

如果你只想在 ValueTree 节点中存储单个值（没有更复杂的内容），那么你已经掌握了入门所需的知识！

了解属性的情况

如果你使用结构体，就只能直接设置或获取这些成员变量。而对于 ValueTree 节点，你还可以（在运行时）查明有哪些变量。

ValueTree::getNumProperties() 函数告诉你一个节点有多少个属性：

int numProperties = myNode.getNumProperties();

ValueTree::getPropertyName() 函数返回一个 Identifier 对象，给出指定位置处属性的名称。将其与 ValueTree::getNumProperties() 函数结合使用，就可以在事先不知道属性是什么的情况下遍历它们。

for (int i = 0; i < numProperties; ++i)
{
    juce::Identifier name (myNode.getPropertyName (i));
    // …
}

ValueTree::hasProperty() 函数只是告诉你某个节点是否设置了特定的具名属性：

if (myNode.hasProperty (nameProperty))
{
    // property was found
}

这些函数支持所谓的反射，即你的程序能够检查对象的性质。当面对一个要处理的对象时，你的代码不一定需要定义（例如类头文件）就能使用它；你可以检查它有哪些成员，并在合适时使用它们。

基本的子节点访问

如果你想创建更复杂的结构，就会希望开始将这些对象用作层级结构中的节点。

添加子节点

虽然一个节点可以附加一组属性，但它也可以包含若干子节点，很像一个数组。

如果我们有一个希望作为子节点添加的节点，只需在要添加到的节点上调用 ValueTree::addChild () 函数。我们自然会传入新的子节点，但还必须指定它应该放在哪里。如果你不需要将它插入到任何特定位置，可以指定 -1，直接将它放在末尾。

juce::ValueTree childNode (myNodeType);
myNode.addChild (childNode, -1, nullptr);

这里，childNode 节点中保存的数据归属于 myNode 中保存的数据。

注意，这种归属关系也是一种额外的引用。如果我们重新赋值 childNode 变量，现有的数据不会丢失。

childNode = juce::ValueTree (myNodeType);
myNode.addChild (childNode, -1, nullptr);

虽然我们的直接作用域中可能不再有任何 ValueTree 对象直接指向那个实例，但它仍会在原始节点中保持存活。

获取子节点

有多种方式可以获取子节点。对于任何给定任务应该选择哪一种，取决于你所选结构的组织方式。

对于所有这些方式，任何不对应于子节点的请求都会返回一个无效对象。

ValueTree::getChild() 函数返回当前位于节点内部列表中指定位置的子节点。如果你总是将它们添加到末尾，那么 0 就对应你放入的第一个：

childNode = myNode.getChild (0);

ValueTree::getChildWithName() 函数返回第一个以指定名称标识符作为节点类型的子节点：

childNode = myNode.getChildWithName (myNodeType);

ValueTree::getChildWithProperty() 函数返回第一个具名属性被设置为指定值的子节点：

childNode = myNode.getChildWithProperty (nameProperty, "Fluffmuff");

最后两个函数，以及你需要的任何其他此类方法，当然都可以用第一个函数来编写；很容易编写自己的函数来按其他条件获取子节点（例如，同时匹配节点类型和属性值）。

你还可以使用 ValueTree::getParent() 函数获取任何给定节点的当前所有者：

ValueTree parent (childNode.getParent());
