处理 MIDI 事件

本教程演示如何处理 MIDI 输入事件。除了处理来自外部源的 MIDI 数据，还会介绍一个屏幕键盘组件。

难度：中级
平台：Windows、macOS、Linux
类：AudioDeviceManager、MidiMessage、MidiInputCallback、ComboBox、MidiKeyboardComponent、MidiKeyboardState、CallbackMessage、ScopedValueSetter

准备工作

在此处下载本教程的演示项目：PIP | ZIP 。解压项目，在 Projucer 中打开第一个头文件。

如果你在这一步需要帮助，参见教程：Projucer 第 1 部分：Projucer 入门。

理想情况下，你的电脑上应连接一个外部 MIDI 源。如果没有，某种虚拟 MIDI 源（在电脑上创建虚拟 MIDI 端口）也会有帮助。

MIDI 输入

本教程演示如何在基础应用程序中处理 MIDI 输入。JUCE 让查找已连接的硬件 MIDI 接口列表变得很容易。它还提供了 MidiKeyboardComponent 类，让你可以显示一个屏幕键盘。首先，看看 MainContentComponent 类中的成员变量：

juce::AudioDeviceManager deviceManager; // [1]
juce::ComboBox midiInputList; // [2]
juce::Label midiInputListLabel;
int lastInputIndex = 0; // [3]
bool isAddingFromMidiInput = false; // [4]
juce::MidiKeyboardState keyboardState; // [5]
juce::MidiKeyboardComponent keyboardComponent; // [6]
juce::TextEditor midiMessagesBox;
double startTime;
  • [1]：我们使用 AudioDeviceManager 类查找哪些 MIDI 输入设备已启用。
  • [2]：我们在这个组合框中显示 MIDI 输入设备的名称，供用户选择。
  • [3]：当用户选择另一个输入时，用它注销之前选中的 MIDI 输入。
  • [4]：这个标志用于表示 MIDI 数据来自外部源，而不是在屏幕键盘上的鼠标点击。
  • [5]：MidiKeyboardState 类跟踪当前按下了哪些 MIDI 键。
  • [6]：这是屏幕键盘组件。

在 MainContentComponent 构造函数中，我们初始化 [3]、[4] 和 [6]。我们还记录了应用程序的启动时间，以便相对于它显示 MIDI 数据的时间戳。

MainContentComponent()
    : keyboardComponent (keyboardState, juce::MidiKeyboardComponent::horizontalKeyboard),
      startTime (juce::Time::getMillisecondCounterHiRes() * 0.001)
{

我们必须传入一个 MidiKeyboardState 对象来初始化 MidiKeyboardComponent 对象。而且，由于这些是静态分配的对象，MidiKeyboardState 必须列在成员变量的前面。

MIDI 输入列表

包含 MIDI 输入列表的组合框，是通过 MidiInput 类使用 MidiInput::getDevices() 函数获取连接到电脑的 MIDI 输入列表来填充的：

addAndMakeVisible (midiInputList);
midiInputList.setTextWhenNoChoicesAvailable ("No MIDI Inputs Enabled");
auto midiInputs = juce::MidiInput::getAvailableDevices();
juce::StringArray midiInputNames;
for (auto input : midiInputs)
    midiInputNames.add (input.name);
midiInputList.addItemList (midiInputNames, 1);
midiInputList.onChange = [this] { setMidiInput (midiInputList.getSelectedItemIndex()); };
// find the first enabled device and use that by default
for (auto input : midiInputs)
{
    if (deviceManager.isMidiInputDeviceEnabled (input.identifier))
    {
        setMidiInput (midiInputs.indexOf (input));
        break;
    }
}
// if no enabled devices were found just use the first one in the list
if (midiInputList.getSelectedId() == 0)
    setMidiInput (0);

如果用户更改了选中的 MIDI 输入，赋给 ComboBox::onChange 辅助对象的 lambda 函数就会被调用：

midiInputList.onChange = [this] { setMidiInput (midiInputList.getSelectedItemIndex()); };

setMidiInput() 函数让应用程序开始监听选中的设备。如果该设备当前处于禁用状态，它还会启用该设备：

void setMidiInput (int index)
{
    auto list = juce::MidiInput::getAvailableDevices();
    deviceManager.removeMidiInputDeviceCallback (list[lastInputIndex].identifier, this);
    auto newInput = list[index];
    if (!deviceManager.isMidiInputDeviceEnabled (newInput.identifier))
        deviceManager.setMidiInputDeviceEnabled (newInput.identifier, true);
    deviceManager.addMidiInputDeviceCallback (newInput.identifier, this);
    midiInputList.setSelectedId (index + 1, juce::dontSendNotification);
    lastInputIndex = index;
}

处理外部 MIDI 输入

我们实现 MidiInputCallback::handleIncomingMidiMessage() 纯虚函数。它会更新键盘状态（进而更新 MidiKeyboardComponent 对象）：

void handleIncomingMidiMessage (juce::MidiInput* source, const juce::MidiMessage& message) override
{
    const juce::ScopedValueSetter<bool> scopedInputFlag (isAddingFromMidiInput, true);
    keyboardState.processNextMidiEvent (message);
    postMessageToList (message, source->getName());
}

注意，scopedInputFlag 变量使用了 ScopedValueSetter 类。它会做以下几件事：

  • 保存 isAddingFromMidiInput 成员的当前状态。
  • 把 isAddingFromMidiInput 成员设为 true。
  • 函数退出时，把 isAddingFromMidiInput 成员恢复为函数开始时的状态。

MIDI 键盘状态与组件

在 MainContentComponent 构造函数中，MidiKeyboardComponent 对象被添加到父组件 MainContentComponent 中并设为可见。我们还监听了 MidiKeyboardState 对象（不是组件）：

addAndMakeVisible (keyboardComponent);
keyboardState.addListener (this);

MidiKeyboardStateListener 类有两个必须实现的纯虚函数，即 MidiKeyboardStateListener::handleNoteOn() 和 MidiKeyboardStateListener::handleNoteOff() 函数。

void handleNoteOn (juce::MidiKeyboardState*, int midiChannel, int midiNoteNumber, float velocity) override
{
    if (!isAddingFromMidiInput)
    {
        auto m = juce::MidiMessage::noteOn (midiChannel, midiNoteNumber, velocity);
        m.setTimeStamp (juce::Time::getMillisecondCounterHiRes() * 0.001);
        postMessageToList (m, "On-Screen Keyboard");
    }
}
void handleNoteOff (juce::MidiKeyboardState*, int midiChannel, int midiNoteNumber, float /*velocity*/) override
{
    if (!isAddingFromMidiInput)
    {
        auto m = juce::MidiMessage::noteOff (midiChannel, midiNoteNumber);
        m.setTimeStamp (juce::Time::getMillisecondCounterHiRes() * 0.001);
        postMessageToList (m, "On-Screen Keyboard");
    }
}

这里可以看到 isAddingFromMidiInput 成员的用法。它防止从硬件输入到达的事件被重复投递到我们的列表。

把消息投递到列表

postMessageToList() 函数乍看之下可能有点不寻常：

void postMessageToList (const juce::MidiMessage& message, const juce::String& source)
{
    (new IncomingMessageCallback (this, message, source))->post();
}

IncomingMessageCallback 类是 CallbackMessage 类的子类。我们必须使用它，因为无法确定 postMessageToList() 函数会从哪个线程被调用。如果用户点击 MidiKeyboardComponent 对象，它会从消息线程被调用。但如果数据来自外部 MIDI 源，它就会从后台 MIDI 线程（可能是操作系统线程）被调用。

CallbackMessage 类提供了一种在消息线程上调用函数的方式。CallbackMessage 类是一种 ReferenceCountedObject 类。这就是为什么我们（表面上）不需要把 IncomingMessageCallback 对象保存在任何地方。实际上，IncomingMessageCallback::post() 函数（也就是 MessageManager::MessageBase::post() 函数）会把该对象添加到一个由 MessageManager 类处理的队列中。MessageManager 类最终会在队列中找到这个对象，并在消息线程上调用 IncomingMessageCallback::messageCallback() 函数。该函数被调用后，IncomingMessageCallback 对象就会被删除。因此，这个对象的生命周期（几乎）是自动管理的。

之所以确实需要这样做，只是因为我们得把数据发送到消息线程。在 MIDI 应用程序中，某种线程间通信很可能是必需的，但具体实现取决于实际情况。

显示消息

addMessageToList() 和 getMidiMessageDescription() 函数与教程：创建 MIDI 数据中的同名函数非常相似。主要区别在于我们记录了 MIDI 消息的来源 [7]（哪个硬件输入，或屏幕键盘）：

void addMessageToList (const juce::MidiMessage& message, const juce::String& source)
{
    auto time = message.getTimeStamp() - startTime;
    auto hours = ((int) (time / 3600.0)) % 24;
    auto minutes = ((int) (time / 60.0)) % 60;
    auto seconds = ((int) time) % 60;
    auto millis = ((int) (time * 1000.0)) % 1000;
    auto timecode = juce::String::formatted ("%02d:%02d:%02d.%03d",
        hours,
        minutes,
        seconds,
        millis);
    auto description = getMidiMessageDescription (message);
    juce::String midiMessageString (timecode + " - " + description + " (" + source + ")"); // [7]
    logMessage (midiMessageString);
}

练习：在用户界面中添加一些滑块，用于发送并响应调制轮（CC1）和弯音轮之类的消息。

小结

本教程介绍了一些用于处理和显示 MIDI 输入事件的类。具体来说，你应该能够：

  • 列出可用的 MIDI 输入设备。
  • 创建 MIDI 输入设备菜单。
  • 监听到达硬件输入的 MIDI。
  • 使用 MidiKeyboardComponent 类显示 MIDI 音符数据。
  • 使用 CallbackMessage 类把来自其他线程的消息投递到消息线程上处理。
