打包应用或插件以供分发

学习如何为在各类市场上分发你的音频应用或插件做好准备。为不同操作系统平台上的所有插件格式创建安装程序。

难度：高级
平台：Windows、macOS
插件格式：VST、VST3、AU、AUv3、RTAS、AAX

简介

你刚刚实现了一个完美的插件，在所有包装器上都无缺陷，并且做到了尽可能好的优化，但到了分发这件杰作的时候却不知道从何下手？

那么本教程就是为你准备的！当你需要把应用安装到众多平台上用户的系统中时，为分发做准备可能会相当令人望而生畏。市场对其审核流程的要求越来越严格，一点小小的疏忽就可能导致你的二进制文件被重新提交。

在本教程中，我们首先会了解插件的安装位置，然后着手为 Mac 和 Windows 创建安装程序，最后以市场提交的最佳实践作结。

为了充分利用本教程，请准备好已构建的插件和二进制文件以便打包。

安装位置

安装插件不过是将插件复制到用户机器上正确文件夹位置的一个简单步骤。

分发插件时，了解各种插件包装器的安装位置非常重要。下表列出了根据目标操作系统，你的安装程序必须将文件复制到的目录：

Mac 安装目录

插件类型 目录类型 路径
VST 用户 ~/Library/Audio/Plug-Ins/VST
VST 系统 /Library/Audio/Plug-Ins/VST
VST3 用户 ~/Library/Audio/Plug-Ins/VST3
VST3 系统 /Library/Audio/Plug-Ins/VST3
AU 用户 ~/Library/Audio/Plug-Ins/Components
AU 系统 /Library/Audio/Plug-Ins/Components
RTAS 系统 /Library/Application Support/Digidesign/Plug-Ins
AAX 系统 /Library/Application Support/Avid/Audio/Plug-Ins

Windows 安装目录

插件类型 目录类型 路径
VST 共享 C:\Program Files\VstPlugins
VST 共享 C:\Program Files\Steinberg\VstPlugins
VST 共享 C:\Program Files\Common Files\VST2
VST 共享 C:\Program Files\Common Files\SteinbergVST2
VST3 共享 C:\Program Files\Common Files\VST3
RTAS 共享 C:\Program Files\Common Files\Digidesign\DAE\Plug-Ins
AAX 共享 C:\Program Files\Common Files\AvidAudio\Plug-Ins

在 64 位系统上安装 32 位插件时，请在“Program Files”文件夹后添加“(x86)”后缀。

通常建议将插件安装到系统文件夹或“Common Files”目录，因为大多数插件制造商都会把插件安装在那里，这样做的好处是系统中的所有用户都能使用你的插件。不过，执行安装需要管理员权限。

对于 AUv3 和 AAX 等某些插件格式，安装过程还需要代码签名和证书等额外步骤才能成功。

Mac 安装程序

如果你只对 Windows 分发感兴趣，请跳到下一节“Windows 安装程序”。

虽然手动创建安装程序是可行的，但市面上有许多工具可以轻松为你完成这项任务。其中一个例子是免费软件 Packages，我们将在本节中使用它来创建 Mac 安装程序。

接下来，在左侧面板中选择每个软件包，为其分配一个唯一标识符，例如“com.yourcompany.pkg.format”，并确保勾选“Require admin password for installation”复选框。（这是将插件安装到系统文件夹而不是用户目录所必需的。）

现在我们来定制安装过程中显示的消息：从左侧面板中选择 Project 项，然后选择 Presentation 标签页，如下所示：

在此屏幕中，你可以指定一个文本文件的位置，该文件将用于在安装程序的介绍屏幕上显示自定义消息。点击 + 号在右侧表格中添加一项，然后选择 Choose… 指定文本文件的位置。请确保将文本文件复制到项目文件夹中以便于引用。你可以点击预览界面上的相应标签，对“Read Me”和“License”步骤重复此过程。

创建磁盘映像

为了向用户提供更全面、更可定制的下载包，通常最佳实践是从上一步创建的 .pkg 文件创建一个磁盘映像或 .dmg 文件。我们可以使用 Applications/Utilities 文件夹中的 Mac 内置应用程序 Disk Utility 轻松完成。

在 .pkg 文件准备就绪后，创建一个文件夹，放入该 .pkg 文件以及你希望包含的任何其他文档，例如“License”或“Read Me”文件。此文件夹将用于创建磁盘映像，并作为解包后显示的内容。

启动 Disk Utility，从菜单项中导航到 File > New Image > Image from Folder…，然后选择你刚刚创建的文件夹。

将新磁盘映像保存为 .dmg 扩展名，并在 Image Format 字段中选择“read/write”选项。点击 Save 后，这应该会生成一个可修改的磁盘映像，我们可以在下一步中对其进行定制。打开新创建的磁盘映像，你应该会看到用于创建它的文件夹的内容。然后你可以移动其中的项目，也可以选择背景图像：从菜单项中导航到 View > Show View Options 打开 Finder 视图选项。

当你对磁盘映像的外观满意后，只需推出该映像，更改会自动保存。回到 Disk Utility，导航到 Images > Convert… 并选择该 .dmg 文件。通过附加 .dmg 扩展名，为其指定你希望用户看到的最终名称，并在 Image Format 字段中选择“read-only”选项。

点击 Convert，你就会得到最终的磁盘映像，可以放心地分发给客户。

创建拖放式安装程序

除了创建 .pkg 分发包并让安装程序执行插件安装的所有复制/粘贴操作之外，我们还可以创建一种更简单的磁盘映像，让用户参与得更多一些。这种方法更容易出错，因为安装实际上是由用户完成的，但它对安装位置提供了更多控制。

拖放式安装程序的工作方式是：向用户呈现系统上安装位置的文件夹替身，并邀请用户通过这些替身将插件拖放到相应的文件夹中。

要创建这种磁盘映像，请按照上一节所述的相同步骤，创建一个包含所有必要插件的文件夹的磁盘映像。然后像之前一样打开该磁盘映像以定制其外观。

现在，在你的系统上导航到你所支持的插件格式的所需插件安装位置（可参考教程开头的表格），选择该文件夹，然后从菜单项中导航到 File > Make Alias 创建替身。新创建的替身随后可以移动到磁盘映像中，而该文件夹仍将指向系统中的位置。

现在用户只需将插件拖放到磁盘映像窗口中的替身上即可完成安装。

本教程这一部分中说明的所有步骤同样适用于打包应用程序。

Windows 安装程序

如果你只对 Mac 分发感兴趣，请参阅上一节“Mac 安装程序”。

手动创建安装程序可能很繁琐，但幸运的是，市面上有许多工具可以轻松为你完成这项任务。其中一个例子是免费软件 Inno Setup，我们将在本节中使用它来创建 Windows 安装程序。

从网站安装该软件并启动应用程序。你应该会看到一个带有代码编辑器的窗口，我们可以在其中编写自己的安装脚本。

一个用于在 Windows 上安装 VST/VST3/RTAS/AAX 插件的 Inno Setup 脚本或 .iss 文件示例大致如下：

[Setup]
AppName=TestPlugin
AppVersion=1.0.0
DefaultDirName={cf}
DefaultGroupName=TestPlugin
OutputBaseFilename=TestPlugin-windows
[Files]
Source: "TestPlugin.dll"; DestDir: "{app}\Steinberg\VST2"
Source: "TestPlugin.vst3"; DestDir: "{app}\Steinberg\VST3"
Source: "TestPlugin.dpm"; DestDir: "{app}\Digidesign\DAE\Plug-Ins"
Source: "TestPlugin.aaxplugin*"; DestDir: "{app}\Avid\Audio\Plug-Ins\TestPlugin.aaxplugin"; Flags: recursesubdirs

这里我们在脚本的 [Setup] 部分设置通用属性，并在 [Files] 部分指定要复制到特定文件夹的插件。

此语法格式中提供了某些常用 Windows 路径位置的快捷方式，方法是用花括号括起所需的变量。

  • {pf}：位于 C:\Program Files 的“Program Files”的快捷方式。
  • {cf}：位于 C:\Program FilesCommon Files 的“Common Files”的快捷方式。
  • {app}：用户在安装过程中选择的目标应用程序目录的快捷方式。

为了指定默认安装目录，我们将 DefaultDirName 变量设置为“Common Files”目录，但用户仍然可以选择将插件安装到其他地方，如下面运行安装程序时所示：

要指示安装程序将每种插件格式复制到正确的目录，请在 [Files] 部分以单独行的形式，将工作目录中的源文件指定为 Source，将所需的安装位置指定为 DestDir。

请注意，与其他插件格式不同，AAX 插件是作为文件夹打包的，因此必须设置 recursesubdirs 标志，以指示复制该目录中的所有内容。

当你对脚本配置满意后，点击 Build > Compile 创建安装程序。这将在工作目录中默认名为 Output 的目录中生成一个 Setup 应用程序。该安装程序的名称将取自脚本 [Setup] 部分的 OutputBaseFilename 变量。

要在 Inno Setup 中直接测试安装程序，请在编译成功后点击 Run > Run 启动刚刚生成的安装程序。

运行时库链接

由于 Windows 10 的一次近期更新，运行时库的静态链接已被弃用，建议改用动态链接。

为 Windows 构建插件时，JUCE 默认会选择动态链接运行时库。这个通用运行时现在是 Windows 10 系统核心的一部分，因此如果你的插件只面向 Windows 10 用户，就不应该遇到任何问题。然而，对于 8.1 到 Vista 之间的 Windows 版本，客户的电脑上有可能没有安装通用运行时库，插件将无法正常工作。

为解决此问题，你可以提示用户自行通过 Windows Update 安装通用运行时，或者提供一个安装程序，让它随插件一起下载并安装。另一种选择是使用静态链接构建插件，但不建议这样做，因为 Windows 会将可加载到 DAW 中的插件数量限制为 64 个。

市场提交

根据你想要分发应用的商店不同，存在不同类型的要求。不过，有一些通用准则可以帮助你加快在大多数商店的审核流程，包括：

  • 提交在即使最冷门的使用场景下也不出现任何崩溃或缺陷的应用程序。
  • 为你的应用程序撰写准确的描述，精确反映其功能。
  • 为应用程序所需的所有权限和授权提供说明，例如麦克风和摄像头访问权限。
