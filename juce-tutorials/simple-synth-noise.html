构建白噪声发生器

本教程介绍简单的合成与音频输出。这是理解 JUCE 中音频应用（以及插件）概念的关键。

难度：中级
平台：Windows、macOS、Linux
类：AudioAppComponent, AudioSourceChannelInfo, AudioBuffer, Random

准备工作

在这里下载本教程的演示项目：PIP | ZIP。解压项目，并在 Projucer 中打开第一个头文件。

如果这一步需要帮助，请参阅教程：Projucer 第 1 部分：Projucer 入门。

本教程假定你熟悉数字音频的基本原理。特别是，你应该了解音频信号如何用采样来表示。你还应该熟悉这一语境下的采样率概念（你可能把它称为取样率、采样频率或其他类似术语）。

演示项目

演示项目是使用 The Projucer 的 Audio Application 模板创建的。

对于你自己在 JUCE 中的音频应用来说，这是一个有用的起点。演示项目合成白噪声，并通过目标设备的默认音频硬件播放。

Audio Application 模板

本教程只实现音频输出。音频输入以及对音频输入数据的实时处理在其他教程中探讨。Audio Application 模板与 GUI Application 模板非常相似，区别在于：

  • MainContentComponent 类继承自 AudioAppComponent 类，而不是 Component 类。
  • 除了默认添加到项目中的其他音频相关模块之外，项目中还会添加 juce_audio_utils 模块。

Audio Application 模板可用于简单的应用，例如这里给出的示例。它也可以扩展到更复杂的应用，基本上任何需要直接与目标设备音频硬件交互的应用都可以。使用 JUCE 创建音频插件在其他教程中探讨。

音频应用的生命周期

AudioAppComponent 类是一个抽象基类，它有三个纯虚函数，代表我们音频应用的生命周期，我们必须在派生类中实现它们：

  • AudioAppComponent::prepareToPlay()：在音频处理开始之前调用。
  • AudioAppComponent::releaseResources()：音频处理结束时调用。
  • AudioAppComponent::getNextAudioBlock()：每次音频硬件需要新的音频数据块时调用。

在这三个函数中，最重要的也许是 AudioAppComponent::getNextAudioBlock()，因为你的 JUCE 音频应用就在这里生成或处理音频。要理解它的工作原理，我们需要稍微了解现代计算机如何生成音频。音频硬件每秒需要为每个声道生成一定数量的采样。CD 音质的采样率是 44.1kHz，这意味着每秒每个声道需要向音频硬件发送 44100 个采样用于播放。采样并不是一次一个地传给音频硬件，而是放在包含一定数量采样的缓冲区（或块）中传递。例如，在 44.1kHz、块大小为 441 的情况下，我们的 AudioAppComponent::getNextAudioBlock() 函数每秒会被调用 100 次。

上面使用 441 个采样的缓冲区大小，只是为了让讲解中的算术更简单。在实践中，441 这样的缓冲区大小并不常见。硬件缓冲区大小几乎肯定是偶数，而且往往取 2 的幂（256、512、1024 等）。重要的是，你的应用要准备好处理任何缓冲区大小。关于采样率和缓冲区大小设置的更多信息，参见教程：AudioDeviceManager 类。

本质上，我们的 AudioAppComponent::getNextAudioBlock() 是在为音频硬件的音频回调提供服务。需要注意，这个函数会从另一个线程（大多数情况下是音频线程）调用。

为了让我们的 JUCE 音频应用正常工作，还有两个重要的函数。这一次我们需要调用它们，而不是实现它们：

  • AudioAppComponent::setAudioChannels()：我们必须调用它来注册所需的输入和输出声道数。通常我们在构造函数中这样做。这个函数进而会触发应用中音频处理的启动。
  • AudioAppComponent::shutdownAudio()：我们必须调用它来关闭音频系统。通常我们在析构函数中这样做。

初始化音频应用

现在，我们通过更详细地考察音频应用的生命周期，来探讨这个简单的噪声发生器实现。构造函数需要设置 Component 对象的大小（参见教程：主组件）。我们还需要初始化至少一个音频输出：

MainContentComponent()
{
    setSize (800, 600);
    setAudioChannels (0, 2); // no inputs, two outputs
}

如上所述，调用 AudioAppComponent::setAudioChannels() 函数会触发音频系统启动。特别是，它会调用 prepareToPlay() 函数：

void prepareToPlay (int samplesPerBlockExpected, double sampleRate) override
{
    juce::String message;
    message << "Preparing to play audio...\n";
    message << " samplesPerBlockExpected = " << samplesPerBlockExpected << "\n";
    message << " sampleRate = " << sampleRate;
    juce::Logger::getCurrentLogger()->writeToLog (message);
}

在这个例子中，我们其实不需要在这里做任何事，但因为它是一个纯虚函数，我们必须至少实现一个空函数。这里我们记录一些此时可以获得的、关于目标设备音频系统的有用信息。samplesPerBlockExpected 参数顾名思义，就是当 getNextAudioBlock() 函数每次请求一块音频时，我们预期会被要求提供的音频缓冲区大小（以采样为单位）。这个缓冲区大小在不同回调之间可能变化，但它是一个很好的参考。sampleRate 参数告诉我们硬件当前的采样率。如果我们做的是与频率相关的事情，比如合成音调（参见教程：构建正弦波合成器）或使用均衡，就会需要这个参数。如果使用延迟效果，我们也需要知道采样率。而生成噪声不需要这些信息。

生成音频数据

调用 prepareToPlay() 函数之后不久，音频线程就会开始通过 AudioAppComponent::getNextAudioBlock() 函数请求音频块。这个函数接收一个 bufferToFill 参数，它是一个 AudioSourceChannelInfo 结构体。AudioSourceChannelInfo 结构体包含一个多声道的音频采样缓冲区。它还包含两个整数值，用于指定本次调用应处理该缓冲区的哪个区域。更详细地说，AudioSourceChannelInfo 包含以下成员：

  • AudioSampleBuffer* buffer：AudioSampleBuffer 对象是一个多声道音频数据缓冲区，本质上是一个由 float 值构成的多维数组。当 getNextAudioBlock() 函数被调用时，这个缓冲区中包含着来自目标设备音频输入的任何音频数据（如果我们请求了音频输入）。当 getNextAudioBlock() 函数返回时，我们必须已经把缓冲区中相关部分填入了想要播放的音频。
  • int startSample：这是缓冲区中的采样索引，getNextAudioBlock() 函数应从该位置开始读取或写入音频。
  • int numSamples：这是缓冲区中应读取或写入的采样数量。

以浮点值存储的音频数据非常直观。音频信号的每个采样都存储为一个标称范围在 ±1.0 之间的值。

像这样峰值电平为 ±1.0 时，输出会非常响。事实上，这是音频系统在不发生削波的情况下能产生的最大音量。通常，我们需要输出的音频不应超过这个 ±1.0 的上限（不过中间处理阶段超出该上限也没问题，只要最终输出更低即可）。

AudioSampleBuffer 类

虽然 AudioSampleBuffer 类（从最基本的层面看）只是一个由 float 值构成的多声道数组，但它提供了一组处理音频数据的有用函数。其中许多函数会在后续教程中介绍，这里我们用到以下函数：

  • AudioSampleBuffer::getNumChannels()：它返回缓冲区中存储的音频声道数。在这里，该值应与我们之前调用 AudioAppComponent::setAudioChannels() 函数时请求的输出声道数一致。（该值始终是输入声道数与输出声道数中的较大者。）
  • AudioSampleBuffer::getWritePointer()：它返回指向特定采样偏移处 float 值缓冲区的指针。

要让这个简单的应用生成白噪声，我们需要用随机值填充缓冲区中请求的部分。为此，我们可以遍历缓冲区中的各个声道，找到该声道在缓冲区中的起始采样，然后把所需数量的采样写入缓冲区：

void getNextAudioBlock (const juce::AudioSourceChannelInfo& bufferToFill) override
{
    for (auto channel = 0; channel < bufferToFill.buffer->getNumChannels(); ++channel)
    {
        // Get a pointer to the start sample in the buffer for this audio output channel
        auto* buffer = bufferToFill.buffer->getWritePointer (channel, bufferToFill.startSample);
        // Fill the required number of samples with noise between -0.125 and +0.125
        for (auto sample = 0; sample < bufferToFill.numSamples; ++sample)
            buffer[sample] = random.nextFloat() * 0.25f - 0.125f;
    }
}

使用 Random 类生成白噪声

这里我们使用 Random 类来生成随机值（参见教程：Random 类）。要生成白噪声，我们需要生成围绕零均匀分布的随机数。这里我们生成 -0.125 到 +0.125 之间的随机值：先调用 Random::nextFloat() 函数，它生成 0 到 1 之间的值；然后把结果乘以 0.25 并减去 0.125。（关于这一过程的更多信息，参见教程：控制音频电平。）注意我们没有使用 Random::getSystemRandom() 函数获取共享的系统 Random 对象，就像其他教程（教程：Random 类）那样。这是因为我们是在音频线程上调用 Random::nextFloat() 函数。我们需要创建自己的 Random 对象，否则这些值可能会被使用该共享 Random 对象的其他线程破坏。为此，一个 Random 类的实例被添加到我们的 MainContentComponent 类中：

private:
juce::Random random;
JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR (MainContentComponent)
};

关闭音频应用

应用关闭时会调用析构函数。此时我们应该调用 AudioAppComponent::shutdownAudio() 函数：

~MainContentComponent() override
{
    shutdownAudio();
}

调用 AudioAppComponent::shutdownAudio() 函数会进而导致 AudioAppComponent::releaseResources() 函数被调用。如果我们在音频处理运行期间分配了资源（例如分配了内存或打开了某些文件），这里是释放资源的好地方。在这个例子中，我们不需要任何额外资源，只用一条简单的消息记录该函数调用：

void releaseResources() override
{
    juce::Logger::getCurrentLogger()->writeToLog ("Releasing audio resources");
}

练习：尝试更改音频输出的数量。注意单声道噪声听起来与立体声噪声有细微差别。如果你有多声道声卡，也许能生成两个以上声道的噪声。你还可以尝试更改生成噪声的电平。例如，要生成电平为 0.1 的噪声，需要把随机生成的值乘以 0.2 再减去 0.1。
