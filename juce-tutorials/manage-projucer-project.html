Projucer 第 2 部分：管理 Projucer 项目

在教程：Projucer 第 1 部分：Projucer 入门中，你学习了如何创建新的 JUCE 项目、将其导出到本地 IDE，并开始编写代码。然而，Projucer 的作用远不止于此——它还是一个非常强大的跨平台工具，可以管理项目的所有设置、添加源文件等等。在开发 JUCE 应用的过程中，Projucer 将始终陪伴你。本教程将带你概览其中一些核心功能。

难度：初级
平台：Windows、macOS、Linux、iOS、Android

准备工作

创建一个新的 JUCE 项目，并在 Projucer 中打开它。具体操作在教程：Projucer 第 1 部分：Projucer 入门中已有说明。

管理你的项目

接下来我们看看 Projucer 中最核心的一些功能，在开发 JUCE 应用的过程中你会经常用到它们。

添加和编辑源文件

Projucer 提供了文件浏览器和一个基础的 C++ 源文件代码编辑器，位于左侧的 File 浏览器标签页下。它看起来是这样的：

借助 Projucer，你可以向项目中添加新的源文件，删除或重命名已有的源文件，还可以将文件组织到分组中。要做到这些（以及访问其他功能），点击左侧文件浏览器标签页中的「+」符号，或者右键点击文件或分组，然后从弹出菜单中选择你想做的操作。

分组并不等同于文件夹。如果你在 Projucer 的某个分组中创建文件，系统还会询问你要把文件保存到哪个文件夹。这样一来，文件夹结构就可以与分组结构不同。不过，强烈建议并且也是良好实践的做法，是让分组遵循文件夹的结构和名称。

如果你改动了文件结构，随后保存项目，这些改动会反映到所有已导出的本地 IDE 项目中。这样，你就可以轻松地让项目文件结构在你开发的所有平台上保持一致。

绝不要在本地 IDE（例如 Xcode、Visual Studio）中为 JUCE 项目添加、重命名或删除源文件。下次你在 Projucer 中保存项目时，这些改动会被覆盖（Projucer 每次保存都会重新生成本地 IDE 项目）。请始终使用 Projucer 本身来完成这类改动。

当你在文件浏览器中选中某个文件时，Projucer 的代码编辑器就会出现。如果只是对代码做一些快速修改，你无需启动本地 IDE，直接在 Projucer 中修改并保存即可。

管理 JUCE 模块

JUCE 库代码被组织成不同的模块。默认情况下，你的项目类型所需的所有模块都已添加。

大多数 JUCE 模块需要依赖其他 JUCE 模块才能正确编译。如果你删除了项目里其他模块所依赖的某个模块，Projucer 会用红色高亮显示这些已经「损坏」的模块。此时你必须删除这些「损坏」的模块，或者补上缺失的模块。

如果你点击 Modules 标签页中的设置图标，就会打开模块设置页面。它提供了当前使用的所有模块的概览，并允许你设置这些模块的路径。若要一次性修改所有模块的路径，请把正确的路径填入其中一个模块，选中它，然后点击 Set paths for all modules…。

另一种方式是使用模块的全局搜索路径，点击 Enable/disable global path for modules… 即可。要设置全局搜索路径，在 macOS 上请转到菜单项 Projucer > Global Search Paths，在 Windows 和 Linux 上请转到 File > Global Search Paths。

如果你在浏览器中点击某个单独的模块，就可以访问该模块专属的设置和属性。在那里你可以查看特定模块的版本和许可证，并设置该模块所使用的 SDK、外部库等附加依赖项的路径。通常默认设置就足够好用，你很少需要进入这个页面。

导出目标、配置和构建设置

你之前创建的各种导出器目标（Xcode、Visual Studio 等等）可以在 Exporters 标签页中找到。如果你在浏览器中点击它们，就可以访问该导出目标的构建设置。这里是你指定额外的编译器与链接器标志以及其他平台专属构建设置的地方。

要为额外的 IDE 和平台创建新的导出目标，点击「+」符号即可。你随时都可以这样做。例如，如果你最初为 Windows 和 OSX 创建了 JUCE 应用，后来决定还要支持 Linux，也可以轻松做到。

你也可以右键点击导出目标，选择 Delete this exporter 来删除它。

Projucer 会为每个导出目标创建构建配置，你的本地 IDE 将使用这些配置来实际编译和运行应用。默认情况下，每个导出目标都会添加 Debug 和 Release 两个配置。点击这些配置，你就可以访问该配置对应的平台专属构建设置：

你也可以添加额外的配置。例如，对于 Visual Studio 导出目标，Projucer 添加的是使用 64 位的 Debug 和 Release 配置。不过，你可能还想为 Windows 应用添加 32 位支持。为此，你可以复制现有的两个配置（右键点击配置并选择 Create a copy of this configuration），把副本分别重命名为 Debug32 和 Release32，然后在这两个配置中把构建设置 Architecture 从 64 位改为 32 位。

小结

读完本教程后，你应该能够：

  • 使用 Projucer 编辑源文件并管理 JUCE 模块。
  • 配置应用的构建设置。
  • 创建新的导出目标和构建配置。
