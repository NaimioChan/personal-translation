使用分贝控制音频电平

本教程介绍如何通过分贝刻度处理音频以改变其输出电平。在音频应用中，这是向用户呈现音频电平值更常见的方式。

难度：中级
平台：Windows、macOS、Linux
类：Decibels, Slider, String

准备工作

在此处下载本教程的演示项目：PIP | ZIP。解压该项目，并在 Projucer 中打开第一个头文件。

如果你需要这一步的帮助，请参阅教程：Projucer 第 1 部分：Projucer 入门。

本教程承接教程：控制音频电平。在继续之前，你应该已经学习过该教程。

演示项目

与教程：控制音频电平的演示项目类似，本教程的演示项目呈现的窗口中也只有一个滑块。这一次，滑块的值用分贝表示。这个分贝值需要在用于音频处理算法之前转换为线性增益值。大多数音频应用都用分贝向用户表示增益，因为在对数值进行变化（或比较）时，这通常感觉更自然。演示项目的用户界面如下图所示。

创建自定义滑块

注意这一次滑块旁边显示的文本不仅显示分贝值，还显示后缀“dB”。这是通过创建一个继承自Slider类的自定义滑块类 DecibelSlider 实现的。在这个自定义滑块类中，文本框界面被定制为以分贝显示数值。虽然可以为Slider对象文本框中显示的文本添加后缀，只需使用 Slider::setTextValueSuffix() 函数，但我们还需要另一项定制。那就是定制数值的转换方式，以便在电平降得很低时显示 -INF dB。

INF 指无穷大（infinity），在我们的应用中 -INF dB 被当作静音处理。

Decibels 类

Decibels类包含若干静态函数，用于在分贝值与线性增益之间转换。它还提供了一种把分贝值转换为String对象的简便方法。例如，我们重写虚函数 Slider::getTextFromValue()，在其中使用 Decibels::toString() 函数（在 DecibelSlider 类中），如下所示：

juce::String getTextFromValue (double value) override
{
    return juce::Decibels::toString (value);
}

这使我们的 DecibelSlider 类能够针对给定的滑块值，在其文本框中显示合适的文本。

Decibels类没有把String对象转换回分贝值的函数，所以我们需要自己写一个。这里我们重写 Slider::getValueFromText() 虚函数（同样在 DecibelSlider 类中）：

double getValueFromText (const juce::String& text) override
{
    auto minusInfinitydB = -100.0;
    auto decibelText = text.upToFirstOccurrenceOf ("dB", false, false).trim(); // [1]
    return decibelText.equalsIgnoreCase ("-INF") ? minusInfinitydB
                                                 : decibelText.getDoubleValue(); // [2]
}

这使用户能够在文本框中输入数值，并让该数值经过检查后转换为滑块的合法值。为此我们：

  • [1]：从文本中去掉“dB”后缀（如果存在），并修剪文本以删除开头和结尾的空白字符（使用 String::trim() 函数）。
  • [2]：检查剩余文本是否为“-INF”，若是则返回 -100（这是分贝中 -INF dB 的默认值，Decibels类就使用这个值，相关讨论见本教程的“说明”部分）。否则把剩余文本转换为 double 值并返回。

使用滑块的值

在教程：控制音频电平中，我们直接在 getNextAudioBlock() 函数里访问滑块的值。由于从分贝到线性增益的转换涉及一些可能很耗 CPU 的运算，最好避免过于频繁地执行转换，尤其是在音频线程上。在本教程的演示项目中，我们有一个 float 成员 level 存放在 MainContentComponent 类中，并在滑块变化时通过监听器更新这个值。

我们在构造函数中把 level 成员初始化为零，并把它转换为分贝（使用 Decibels::gainToDecibels() 函数），从而（使用 Slider::setValue() 函数）给滑块一个初始位置，如下所示：

MainContentComponent()
{
decibelSlider.setValue (juce::Decibels::gainToDecibels (level));
decibelLabel.setText ("Noise Level in dB", juce::dontSendNotification);

把分贝转换为线性增益

在 Slider::onValueChange 辅助对象的 lambda 函数中，我们执行从滑块所用的分贝刻度到音频处理所需的线性增益值的转换：

decibelSlider.onValueChange = [this] { level = juce::Decibels::decibelsToGain ((float) decibelSlider.getValue()); };

当我们在构造函数中用 Slider::setValue() 函数首次设置滑块的值时，这个函数会被调用。它会在值变化时调用赋给 Slider::onValueChange 辅助对象的 lambda 函数，我们的 level 成员就会被正确设置。

练习：向 MainContentComponent 类再添加一个Label对象，用于显示线性增益值。——向 MainContentComponent 类再添加一个Slider对象，显示线性增益值，使用户能够用任一个滑块查看和指定噪声电平。移动任一个滑块时，两个滑块都应正确更新。（不同单位之间转换的简单示例参见教程：Slider 类。）

处理音频

在 MainContentComponent::getNextAudioBlock() 中，我们处理音频：

void getNextAudioBlock (const juce::AudioSourceChannelInfo& bufferToFill) override
{
    auto currentLevel = level;
    auto levelScale = currentLevel * 2.0f;
    for (auto channel = 0; channel < bufferToFill.buffer->getNumChannels(); ++channel)
    {
        auto* buffer = bufferToFill.buffer->getWritePointer (channel, bufferToFill.startSample);
        for (auto sample = 0; sample < bufferToFill.numSamples; ++sample)
            buffer[sample] = random.nextFloat() * levelScale - currentLevel;
    }
}

注意，这与教程：控制音频电平中的 getNextAudioBlock() 函数几乎相同，只是我们先取一份 level 值的函数局部副本，然后像之前那样计算 levelScale 值。

这种方法的问题

这种方法的一个问题是，level 变量可能在音频线程执行期间突然改变值（在这里是指两次 getNextAudioBlock 调用之间）。这类变化通常会引入音频瑕疵，例如可听见的爆裂声。为避免这种情况，在实际的合成器中，我们希望 level 值能够平滑变化。实现这一点的技巧在其他教程中探讨（参见教程：构建正弦波合成器）。

另一个问题与线程安全有关。在一个线程（GUI 线程）中写入像 level 这样的成员变量，同时从另一个线程（音频线程）读取同一个值，如果不进行线程同步（无论是通过临界区还是使用原子操作），在 C++ 中严格来说属于未定义行为。这些问题超出了本教程的范围，将在以后的教程中讨论。在这个特定情况下，我们不必过于担心，因为在典型的架构（x86、x86_64、ARM）上，读写单个 float 是原子操作：读写不会相互交错，通常是安全的。

再进一步想，可能会想通过把 levelScale 也变成成员变量来进一步优化代码（这样就不必在每次调用 getNextAudioBlock() 函数时计算它）。但这样一来，这两个成员变量就不再作为单个原子操作更新了。当然，对此也有解决办法，但这超出了本教程的范围。

说明

本教程演示项目中的代码假设我们希望把 -100 dB 或更低的值视为 -INF dB（即线性增益值为零）。这个 -100 dB 是Decibels类使用的默认值，但你可以在它的计算中覆盖这个值。方法是向Decibels类中的每个函数提供一个额外参数，指定哪个值应被视为 -INF dB。例如，要在 MainContentComponent 构造函数中更新滑块值时把 -96 dB（及以下）视为 -INF dB，我们可以这样做：

decibelSlider.setValue (juce::Decibels::gainToDecibels (level, -96.0f));

当然，我们需要确保应用的所有部分对 -INF dB 使用相同的值。演示项目的代码有一个潜在问题，因为 -100.0 被硬编码在我们的 DecibelSlider::getValueFromText() 函数中。如果Decibels类（因某种原因）改变了它的默认值，我们的代码就会失效。不幸的是，这个默认值是Decibels类的私有成员，因此我们无法向Decibels类查询它的默认值。相反，我们需要指定自己的默认值，并在各处统一使用它。

练习：修改演示项目，把 -INF 的自定义默认值指定为 -96 dB。你需要同时更新 DecibelSlider 类和 MainContentComponent 类。
