构建多复音合成器（MPE）

了解 MPE 标准的基础知识，以及如何实现支持 MPE 的合成器。把你的应用程序连接到 ROLI Seaboard Rise 吧！

难度：中级
平台：Windows、macOS、Linux
类：MPESynthesiser、MPEInstrument、MPENote、MPEValue、SmoothedValue

准备工作

在此处下载本教程的演示项目：PIP | ZIP 。解压项目，在 Projucer 中打开第一个头文件。

如果你在这一步需要帮助，参见教程：Projucer 第 1 部分：Projucer 入门。

建议先阅读教程：构建一个 MIDI 合成器，因为本教程多处会以它作为参照。

演示项目

演示项目是 JUCE/examples 目录中 MPEDemo 项目的简化版本。为了充分学习本教程，你需要一个兼容 MPE 的控制器。MPE 代表 MIDI 复音表情（MIDI Polyphonic Expression），这是一项新规范，用于在音频产品之间传递多维数据。

这类兼容 MPE 的设备包括 ROLI 自家的 Seaboard 系列（例如 Seaboard RISE ）。

除非你的控制器发送 MIDI 通道压力和连续控制器 74（音色）的方式与 Seaboard RISE 相同，否则合成器的声音可能会非常轻。

你需要启用其中一个 MIDI 输入（这里可以看到 Seaboard RISE 作为选项出现）。

可视化器

在兼容 MPE 的设备上演奏的任何音符都会在窗口下半部分可视化。如下图所示：

MPE 的一个关键特性是：每个新的 MIDI 音符事件都会被分配自己的 MIDI 通道，而不是把某个控制器键盘的所有音符都分配到同一个 MIDI 通道。这样，每个音符都可以通过控制变化消息、弯音消息等独立控制。在 JUCE 对 MPE 的实现中，正在发声的音符由 MPENote 对象表示。MPENote 对象封装以下数据：

  • 音符的 MIDI 通道。
  • 音符的初始 MIDI 音高值。
  • 音符开力度（或击打）。
  • 音符的弯音值：由该音符的 MIDI 通道上收到的 MIDI 弯音消息得出。
  • 音符的压力值：由该音符的 MIDI 通道上收到的 MIDI 通道压力消息得出。
  • 音符的音色：通常由该音符的 MIDI 通道上控制器 74 的控制器消息得出。
  • 音符关力度（或抬起）：只有在收到音符关事件之后、且发声尚未结束时才有效。

在没有音符发声时，可以看到可视化器呈现的是传统 MIDI 键盘布局。在演示应用程序中，每个音符在可视化器中这样表示：

  • 灰色实心圆表示音符开力度（力度越大，圆越大）。
  • 音符的 MIDI 通道显示在圆内「+」符号的上方；
  • 初始 MIDI 音名显示在「+」符号的下方。
  • 叠加的白色圆表示该音符当前的压力（同样，压力越大，圆越大）。
  • 音符的水平位置由原始音符以及施加到该音符上的弯音决定。
  • 音符的垂直位置由该音符的音色参数决定（来自该音符 MIDI 通道上的 MIDI 控制器 74）。

其他设置

在深入探讨本应用程序所演示的 MPE 规范的其他方面之前，先看看我们的应用程序用到的其他一些内容。

首先，我们的 MainComponent 类继承自 AudioIODeviceCallback [1] 和 MidiInputCallback [2] 类：

class MainComponent : public juce::Component,
                      private juce::AudioIODeviceCallback, // [1]
                      private juce::MidiInputCallback // [2]
{
public:

MainComponent 类中还有一些重要的成员：

juce::AudioDeviceManager audioDeviceManager; // [3]
juce::AudioDeviceSelectorComponent audioSetupComp; // [4]
Visualiser visualiserComp;
juce::Viewport visualiserViewport;
juce::MPEInstrument visualiserInstrument;
juce::MPESynthesiser synth;
juce::MidiMessageCollector midiCollector; // [5]
JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR (MainComponent)
};

AudioDeviceManager [3] 类负责电脑上的音频和 MIDI 配置，而 AudioDeviceSelectorComponent [4] 类让我们可以通过图形用户界面进行配置（参见教程：AudioDeviceManager 类）。MidiMessageCollector [5] 类让我们可以在音频回调中轻松地把消息收集成带时间戳的 MIDI 消息块（参见教程：构建一个 MIDI 合成器）。

重要的是 AudioDeviceManager 对象要列在最前面，因为我们要把它传给 AudioDeviceSelectorComponent 对象的构造函数：

MainComponent()
    : audioSetupComp (audioDeviceManager, 0, 0, 0, 256,
          true, // showMidiInputOptions must be true
          true,
          true,
          false)

注意传给 AudioDeviceSelectorComponent 构造函数的另一个重要参数：showMidiInputOptions 必须为 true，才会显示可用的 MIDI 输入。

我们设置 AudioDeviceManager 对象的方式与教程：AudioDeviceManager 类类似，但还需要添加一个 MIDI 输入回调 [6]：

audioDeviceManager.initialise (0, 2, nullptr, true, {}, nullptr);
audioDeviceManager.addMidiInputDeviceCallback ({}, this); // [6]
audioDeviceManager.addAudioCallback (this);

MIDI 输入回调

当从用户界面中任一活动的 MIDI 输入收到每条 MIDI 消息时，都会调用 handleIncomingMidiMessage()：

void handleIncomingMidiMessage (juce::MidiInput* /*source*/,
    const juce::MidiMessage& message) override
{
    visualiserInstrument.processNextMidiEvent (message);
    midiCollector.addMessageToQueue (message);
}

这里我们把每条 MIDI 消息同时传给两者：

  • 我们的 visualiserInstrument 成员——用于驱动可视化器显示；以及
  • midiCollector 成员——它再把消息在音频回调中传给合成器。

音频回调

在任何音频回调发生之前，我们需要在 audioDeviceAboutToStart() 函数中告知 synth 和 midiCollector 成员设备的采样率：

void audioDeviceAboutToStart (juce::AudioIODevice* device) override
{
    auto sampleRate = device->getCurrentSampleRate();
    midiCollector.reset (sampleRate);
    synth.setCurrentPlaybackSampleRate (sampleRate);
}

audioDeviceIOCallbackWithContext() 函数看起来没有做任何 MPE 特有的工作：

void audioDeviceIOCallbackWithContext (const float* const* /*inputChannelData*/,
    int /*numInputChannels*/,
    float* const* outputChannelData,
    int numOutputChannels,
    int numSamples,
    const juce::AudioIODeviceCallbackContext& /*context*/) override
{
    // make buffer
    juce::AudioBuffer<float> buffer (outputChannelData, numOutputChannels, numSamples);
    // clear it to silence
    buffer.clear();
    juce::MidiBuffer incomingMidi;
    // get the MIDI messages for this audio block
    midiCollector.removeNextBlockOfMessages (incomingMidi, numSamples);
    // synthesise the block
    synth.renderNextBlock (buffer, incomingMidi, 0, numSamples);
}

事实上，这与教程：构建一个 MIDI 合成器中的 SynthAudioSource::getNextAudioBlock() 函数相当相似。

MPE 核心类

所有 MPE 特有的处理都由 MPE 类完成：MPEInstrument、MPESynthesiser、MPESynthesiserVoice、MPEValue 和 MPENote（前面已经提到过）。

MPEInstrument 类

MPEInstrument 类按照 MPE 规范维护当前正在发声的音符状态。MPEInstrument 对象可以挂接一个或多个监听器，并能在音符发生变化时广播这些变化。你只需把 MIDI 数据喂给 MPEInstrument 对象，其余它都会处理。

在 MainComponent 构造函数中，我们把 MPEInstrument 配置为传统模式，并把默认弯音范围设为 24 个半音：

visualiserInstrument.enableLegacyMode (24);

这个特殊模式用于向后兼容非 MPE 的 MIDI 设备，此时乐器会忽略当前的 MPE 区域布局。

参见教程：理解 MPE 区域，了解使用区域和区域布局的更灵活方法。

在 MainComponent::handleIncomingMidiMessage() 函数中，我们把 MIDI 消息传给 visualiserInstrument 对象：

visualiserInstrument.processNextMidiEvent (message);

在这个例子中，我们直接使用 MPEInstrument 对象，因为需要它来更新可视化器显示。就音频合成而言，我们不需要再创建一个单独的 MPEInstrument 对象。MPESynthesiser 对象内部包含一个 MPEInstrument 对象，用来驱动合成器。

MPESynthesiser 类

我们把 MPESynthesiser 设置为与 visualiserInstrument 对象相同的配置（传统模式，弯音范围 24 个半音）：

synth.enableLegacyMode (24);
synth.setVoiceStealingEnabled (false);

MPESynthesiser 类也可以替我们处理声部抢占，但正如这里所示，我们把它关掉了。启用声部抢占后，如果合成器的声部用尽又需要演奏另一个音符，它会尝试接管一个已有的声部。

正如我们在 MainComponent::audioDeviceAboutToStart() 函数中已经看到的，需要设置 MPESynthesiser 对象的采样率才能正常工作：

synth.setCurrentPlaybackSampleRate (sampleRate);

也正如我们在 MainComponent::audioDeviceIOCallback() 函数中已经看到的，我们只需传给它一个 MidiBuffer 对象，其中包含我们希望它用于执行合成操作的消息：

synth.renderNextBlock (buffer, incomingMidi, 0, numSamples);

MPESynthesiserVoice 类

通常可以直接使用 MPESynthesiser 和 MPEInstrument 类本身（不过如果你需要覆盖某些行为，这两个类都可以作为基类）。要使用 MPESynthesiser 类，你必须覆盖的最重要的类是 MPESynthesiserVoice 类。它实际上负责从合成器的各声部生成音频信号。

这类似于配合 Synthesiser 类使用的 SynthesiserVoice 类，但它经过定制以实现 MPE 规范。参见教程：构建一个 MIDI 合成器。

我们的声部类代码位于演示项目的 MPEDemoSynthVoice 类中。这里我们让 MPEDemoSynthVoice 类继承自 MPESynthesiserVoice 类：

class MPEDemoSynthVoice : public juce::MPESynthesiserVoice
{

我们有一些成员变量，用于跟踪控制所生成音调的电平、音色和频率的值。特别是，我们使用了 SmoothedValue 类，它非常适合平滑信号中原本会由数值变化引起的不连续（参见教程：构建一个正弦波合成器）。

juce::SmoothedValue<double> level, timbre, frequency;
double phase = 0.0;
double phaseDelta = 0.0;
double tailOff = 0.0;
// some useful constants
static constexpr auto maxLevel = 0.05;
static constexpr auto maxLevelDb = 31.0;
static constexpr auto smoothingLengthInSeconds = 0.01;
};

启动与停止声部

使用 MPESynthesiserVoice 类的关键在于访问其 MPESynthesiserVoice::currentlyPlayingNote（受保护）MPENote 成员，从而在各个回调中获取关于该音符的控制信息。例如，我们这样覆盖 MPESynthesiserVoice::noteStarted() 函数：

void noteStarted() override
{
    jassert (currentlyPlayingNote.isValid());
    jassert (currentlyPlayingNote.keyState == juce::MPENote::keyDown
             || currentlyPlayingNote.keyState == juce::MPENote::keyDownAndSustained);
    // get data from the current MPENote
    level.setTargetValue (currentlyPlayingNote.pressure.asUnsignedFloat());
    frequency.setTargetValue (currentlyPlayingNote.getFrequencyInHertz());
    timbre.setTargetValue (currentlyPlayingNote.timbre.asUnsignedFloat());
    phase = 0.0;
    auto cyclesPerSample = frequency.getNextValue() / currentSampleRate;
    phaseDelta = 2.0 * juce::MathConstants<double>::pi * cyclesPerSample;
    tailOff = 0.0;
}

以下「五个维度」以 MPEValue 对象的形式存储在 MPENote 对象中：

  • 音符开力度：存放在 [MPENote::noteOnVelocity](structMPENote.html#a9322650db7f2e76cec724746d1a75c1a “音符开的力度（「击打」）。”) 成员中
  • 弯音：存放在 MPENote::pitchbend 成员中
  • 压力：存放在 MPENote::pressure 成员中
  • 音色：存放在 MPENote::timbre 成员中
  • 音符关力度：存放在 [MPENote::noteOffVelocity](structMPENote.html#a9e46888c40a2d3eaf4b8c5129b21de6e “收到音符关之后，音符的释放力度（「抬起」）。”) 成员中

MPEValue 对象让从 7 位或 14 位 MIDI 值源创建值变得容易，也便于把这些值获取为 0..1 或 -1..+1 范围内的浮点值。

MPEValue 类内部以 14 位范围存储该值。

MainComponent::noteStopped() 函数会触发音符包络的「释放」（或者按请求立即停止）：

void noteStopped (bool allowTailOff) override
{
    jassert (currentlyPlayingNote.keyState == juce::MPENote::off);
    if (allowTailOff)
    {
        // start a tail-off by setting this flag. The render callback will pick up on
        // this and do a fade out, calling clearCurrentNote() when it's finished.
        if (tailOff == 0.0) // we only need to begin a tail-off if it's not already doing so - the
            // stopNote method could be called more than once.
            tailOff = 1.0;
    }
    else
    {
        // we're being told to stop playing immediately, so reset everything..
        clearCurrentNote();
        phaseDelta = 0.0;
    }
}

SineWaveVoice::stopNote() 函数与教程：构建一个 MIDI 合成器中的对应函数非常相似。这里没有任何 MPE 特有的内容。

练习：修改 MainComponent::noteStopped() 函数，让音符关力度（抬起）可以影响音符的释放速率。抬起越快，释放时间应越短。

参数变化

有一些回调会在该音符的压力、弯音或音色发生变化时通知我们：

void notePressureChanged() override
{
    level.setTargetValue (currentlyPlayingNote.pressure.asUnsignedFloat());
}
void notePitchbendChanged() override
{
    frequency.setTargetValue (currentlyPlayingNote.getFrequencyInHertz());
}
void noteTimbreChanged() override
{
    timbre.setTargetValue (currentlyPlayingNote.timbre.asUnsignedFloat());
}

同样，我们访问 MPESynthesiserVoice::currentlyPlayingNote 成员来获取这些参数各自当前的值。

生成音频

MainComponent::renderNextBlock() 实际生成音频信号，把这个声部的信号混合到传入的缓冲区中：

void renderNextBlock (juce::AudioBuffer<float>& outputBuffer,
    int startSample,
    int numSamples) override
{
    if (phaseDelta != 0.0)
    {
        if (tailOff > 0.0)
        {
            while (--numSamples >= 0)
            {
                auto currentSample = getNextSample() * (float) tailOff;
                for (auto i = outputBuffer.getNumChannels(); --i >= 0;)
                    outputBuffer.addSample (i, startSample, currentSample);
                ++startSample;
                tailOff *= 0.99;
                if (tailOff <= 0.005)
                {
                    clearCurrentNote();
                    phaseDelta = 0.0;
                    break;
                }
            }
        }
        else
        {
            while (--numSamples >= 0)
            {
                auto currentSample = getNextSample();
                for (auto i = outputBuffer.getNumChannels(); --i >= 0;)
                    outputBuffer.addSample (i, startSample, currentSample);
                ++startSample;
            }
        }
    }
}

它调用 MainComponent::getNextSample() 生成波形：

float getNextSample() noexcept
{
    auto levelDb = (level.getNextValue() - 1.0) * maxLevelDb;
    auto amplitude = std::pow (10.0f, 0.05f * levelDb) * maxLevel;
    // timbre is used to blend between a sine and a square.
    auto f1 = std::sin (phase);
    auto f2 = std::copysign (1.0, f1);
    auto a2 = timbre.getNextValue();
    auto a1 = 1.0 - a2;
    auto nextSample = float (amplitude * ((a1 * f1) + (a2 * f2)));
    auto cyclesPerSample = frequency.getNextValue() / currentSampleRate;
    phaseDelta = 2.0 * juce::MathConstants<double>::pi * cyclesPerSample;
    phase = std::fmod (phase + phaseDelta, 2.0 * juce::MathConstants<double>::pi);
    return nextSample;
}

endcode

它只是根据音色参数的值，在正弦波和（未限带的）方波之间交叉淡化。

练习：修改 MPEDemoSynthVoice 类，使其响应音色参数，在两个相差一个八度的正弦波之间交叉淡化。

小结

本教程介绍了 JUCE 中一些基于 MPE 的类。现在你应该知道：

  • MPE 是什么。
  • 兼容 MPE 的设备会把每个音符分配到各自的 MIDI 通道。
  • MPENote 类如何存储音符的信息，包括其 MIDI 通道、原始音符编号、力度、弯音等。
  • MPEInstrument 类维护当前正在发声的音符状态。
  • MPESynthesiser 类内部包含一个 MPEInstrument 对象，用来驱动合成器。
  • 你必须实现一个继承自 MPESynthesiserVoice 类的类，来实现合成器的音频代码。
