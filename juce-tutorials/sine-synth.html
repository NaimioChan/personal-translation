构建正弦波合成器

本教程介绍简单的正弦波合成。我们展示如何管理正弦波振荡器的状态，以及如何把数据写入音频输出。

难度：中级
平台：Windows、macOS、Linux
类：AudioAppComponent, Slider, MathConstants

准备工作

本教程承接教程：控制音频电平，你应该先阅读并理解该教程。

在此处下载本教程的演示项目：PIP | ZIP。解压该项目，并在 Projucer 中打开第一个头文件。

如果你需要这一步的帮助，请参阅教程：Projucer 第 1 部分：Projucer 入门。

演示项目

演示项目基于 Projucer 的 Audio Application 模板。它向用户呈现一个滑块，用于控制正弦波的频率。

生成正弦波

本教程使用标准库函数 std::sin() 合成正弦波。为了使用它，我们需要为正弦波生成维护状态，即存储当前的相位角，以及每输出一个采样时相位角需要增加的量。每个采样的这个变化量（“delta”）的大小取决于输出的采样率以及我们要生成的正弦波频率。

大多数合成器应用和插件很可能不会使用 std::sin() 函数，因为它大概不是最高效的技术。通常会用波表，参见教程：波表合成。波表还允许使用正弦波以外的波形。

维护状态

在 MainContentComponent 类中，我们存储三个 double 成员 [1]：

double currentSampleRate = 0.0, currentAngle = 0.0, angleDelta = 0.0; // [1]

我们有一个简单的函数来更新 angleDelta 成员：

void updateAngleDelta()
{
    auto cyclesPerSample = frequencySlider.getValue() / currentSampleRate; // [2]
    angleDelta = cyclesPerSample * 2.0 * juce::MathConstants<double>::pi; // [3]
}
  • [2]：首先，我们计算每输出一个采样需要完成多少个周期。
  • [3]：然后把它乘以一个完整正弦波周期的长度，即 2pi 弧度。

在这个函数能正确工作之前，我们需要知道输出的采样率。这是因为我们需要知道采样的生成频率，以便确定每个采样所需的变化量。采样率通过 AudioAppComponent::prepareToPlay() 回调函数传给我们：

void prepareToPlay (int, double sampleRate) override
{
    currentSampleRate = sampleRate;
    updateAngleDelta();
}

这里我们保存采样率值的一份副本，并在一开始调用 updateAngleDelta() 函数。

使用滑块的值

当应用运行时移动滑块，我们需要再次更新 angleDelta 成员：

frequencySlider.onValueChange = [this] {
    if (currentSampleRate > 0.0)
        updateAngleDelta();
};

这里我们先检查采样率是否有效，然后再调用 updateAngleDelta() 函数。

输出音频

在 getNextAudioBlock() 回调中，我们需要生成实际的正弦波并把它写入输出：

void getNextAudioBlock (const juce::AudioSourceChannelInfo& bufferToFill) override
{
    auto level = 0.125f;
    auto* leftBuffer = bufferToFill.buffer->getWritePointer (0, bufferToFill.startSample);
    auto* rightBuffer = bufferToFill.buffer->getWritePointer (1, bufferToFill.startSample);
    for (auto sample = 0; sample < bufferToFill.numSamples; ++sample)
    {
        auto currentSample = (float) std::sin (currentAngle);
        currentAngle += angleDelta;
        leftBuffer[sample] = currentSample * level;
        rightBuffer[sample] = currentSample * level;
    }
}

对于每个输出采样，我们计算当前角度的正弦函数，然后为下一个采样递增角度。注意我们把电平降到 0.125，因为满幅正弦波会非常响！我们本可以（也许应该）在当前角度值达到 2pi 时把它回绕到零。由于更大的值仍然返回有效结果，我们实际上可以避免这个计算。我们会得到类似下图所示的结果：

滑块的配置

你可能已经注意到滑块的值是非线性变化的（如果没有注意到，你现在就应该试一下）。事实上，这些变化是对数的。这使我们对较小的值有更高的分辨率，对较大的值有较低的分辨率。在控制频率值时，这通常是合适的（因为在音乐上，我们听到的是频率之间比值的相等变化，而不是相等的线性变化）。这是通过 Slider::setSkewFactorFromMidPoint() 函数配置的 [4]。我们的滑块范围设为 50..5000，因此把滑块轨道的中心设为代表 500，就意味着滑块最小值到中心、中心到滑块最大值之间是相等的音乐音程：

MainContentComponent()
{
    addAndMakeVisible (frequencySlider);
    frequencySlider.setRange (50.0, 5000.0);
    frequencySlider.setSkewFactorFromMidPoint (500.0); // [4]

滑块的偏斜因子可以直接用 Slider::setSkewFactor() 函数设置，不过通常更容易考虑你希望在中间点得到什么值。

练习：向应用再添加一个滑块，用于控制正弦波的电平。注意让电平远低于 1.0——最大值取 0.25 应该没问题。

平滑频率变化

你可能会注意到——尤其是在较高频率时——移动滑块会产生一些可听见、而且多半是不想要的瑕疵。这是因为滑块实际上是以离散的步进变化的，而快速移动滑块时这些步进相当大。除此之外，滑块频率只在每个音频块更新一次，因此这些变化的具体影响取决于硬件的块大小。

用于平滑的状态成员

让我们给类添加两个成员，一个存储当前用于合成的频率，另一个是用户通过移动滑块请求的目标频率。然后我们可以在这两个值之间较缓慢地渐变，以消除瑕疵：

double currentFrequency = 500.0, targetFrequency = 500.0; // [5]

我们同时初始化这两个值 [5]。我们还可以把滑块初始化为相同的值 [6]：

MainContentComponent()
{
    addAndMakeVisible (frequencySlider);
    frequencySlider.setRange (50.0, 5000.0);
    frequencySlider.setSkewFactorFromMidPoint (500.0);
    frequencySlider.setValue (currentFrequency, juce::dontSendNotification); // [6]

更新合成代码

这个算法工作方式的关键在于检查当前值和目标值是否相同。如果相同，我们就可以直接使用原来的代码，因为 angleDelta 成员不需要改变。如果当前值和目标值不同，那么我们就需要在每个采样更新 angleDelta 成员，同时让当前值逐渐接近目标值。

在这个示例中，我们只是把输出缓冲区中的采样数作为渐变的持续时间。这意味着在缓冲区尺寸很小时，你可能仍会听到瑕疵。

void getNextAudioBlock (const juce::AudioSourceChannelInfo& bufferToFill) override
{
    auto level = 0.125f;
    auto* leftBuffer = bufferToFill.buffer->getWritePointer (0, bufferToFill.startSample);
    auto* rightBuffer = bufferToFill.buffer->getWritePointer (1, bufferToFill.startSample);
    auto localTargetFrequency = targetFrequency;
    if (!juce::approximatelyEqual (localTargetFrequency, currentFrequency)) // [7]
    {
        auto frequencyIncrement = (localTargetFrequency - currentFrequency) / bufferToFill.numSamples; // [8]
        for (auto sample = 0; sample < bufferToFill.numSamples; ++sample)
        {
            auto currentSample = (float) std::sin (currentAngle);
            currentFrequency += frequencyIncrement; // [9]
            updateAngleDelta(); // [10]
            currentAngle += angleDelta;
            leftBuffer[sample] = currentSample * level;
            rightBuffer[sample] = currentSample * level;
        }
        currentFrequency = localTargetFrequency;
    }
    else // [11]
    {
        for (auto sample = 0; sample < bufferToFill.numSamples; ++sample)
        {
            auto currentSample = (float) std::sin (currentAngle);
            currentAngle += angleDelta;
            leftBuffer[sample] = currentSample * level;
            rightBuffer[sample] = currentSample * level;
        }
    }
}
  • [7]：检查我们的目标值是否与当前值不同。注意我们取了目标值的局部副本，以防在这个函数运行期间滑块在消息线程上改变了该值。
  • [8]：计算每个采样所需的增量。
  • [9]：递增当前频率。
  • [10]：基于这个新频率更新 deltaAngle 成员。
  • [11]：否则就直接使用原来的代码。

这段代码的形式采用了 DSP 代码的典型模式。我们尽可能避免在内层 for() 循环中使用条件语句。取而代之的是，把条件测试放在循环之外，并根据参数是否在变化使用两个不同但相当相似的循环。

最后，我们需要更新 Slider::onValueChange 辅助对象，使它只更新目标值：

frequencySlider.onValueChange = [this] { targetFrequency = frequencySlider.getValue(); };

就是这样！现在试试看，移动滑块产生的瑕疵应该已经消除了。

练习：为你之前在练习中添加的电平滑块控件也加上平滑处理。

说明

  • 不把相位角回绕到 2pi 可能并非在所有情况下都理想。如果使用 float 而不是 double 变量，那么当前角度值变得很大时，计算会出现一些不精确。通过在 2pi 处不回绕相位，std::sin() 函数的表现与简单的波表技术相比相当不错。相关探讨参见教程：波表合成。
