构建音频播放器

本教程介绍如何打开和播放声音文件。其中包括 JUCE 中一些处理声音文件的重要类。

难度：中级
平台：Windows、macOS、Linux
类：AudioFormatManager, AudioFormatReader, AudioFormatReaderSource, AudioTransportSource, FileChooser, ChangeListener, File, FileChooser

入门

在此处下载本教程的演示项目：PIP | ZIP 。解压项目并在 Projucer 中打开第一个头文件。

如果你在这一步需要帮助，请参阅教程：Projucer 第 1 部分：Projucer 入门。

演示项目

演示项目呈现一个三按钮界面，用于控制声音文件的播放。这三个按钮是：

  • 一个按钮，向用户显示文件选择器，供其选择声音文件。
  • 一个用于播放声音的按钮。
  • 一个用于停止声音的按钮。

有用的类

AudioSource 类

虽然我们可以在 Audio Application 模板的 getNextAudioBlock() 中逐个采样地生成音频，但也有一些内置工具可用于生成和处理音频。这些工具让我们能够把高层构建块连接起来，构成强大的音频应用，而无需在应用代码中处理每一个音频采样（JUCE 会替我们完成这件事）。这些构建块基于 AudioSource 类。事实上，如果你跟随过任何基于 AudioAppComponent 类的教程——例如教程：构建白噪声发生器——那么你已经在使用 AudioSource 类了。AudioAppComponent 类本身继承自 AudioSource 类，并且重要的是，它包含一个 AudioSourcePlayer 对象，在 AudioAppComponent 与音频硬件设备之间流式传输音频。我们可以直接在 getNextAudioBlock() 函数中生成音频采样，但也可以把多个 AudioSource 对象串联起来，形成一系列处理。本教程就利用了这项特性。

音频格式

JUCE 提供了许多用于读写多种格式声音文件的工具。本教程中我们使用了其中几个，具体来说用到以下类：

  • AudioFormatManager：该类包含一个音频格式列表（例如 WAV、AIFF、Ogg Vorbis 等），并可以创建合适的对象来从这些格式中读取音频数据。
  • AudioFormatReader：该类处理音频文件上的底层文件读取操作，让我们能以一致的格式读取音频（通常这意味着 float 值数组）。当要求 AudioFormatManager 对象打开某个文件时，它会创建该类的实例。
  • AudioFormatReaderSource：它是 AudioSource 类的子类。它可以从 AudioFormatReader 对象读取音频数据，并通过其 getNextAudioBlock() 函数渲染音频。
  • AudioTransportSource：该类是 AudioSource 类的另一个子类。它可以控制 AudioFormatReaderSource 对象的播放。这种控制包括启动和停止 AudioFormatReaderSource 对象的播放。它还可以执行采样率转换，并且如果我们需要，它可以提前缓冲音频。

整合起来

现在我们将把这些类与合适的用户界面类结合起来，制作我们的声音文件播放应用。此时思考一下播放音频文件的各个阶段——或者说传输状态——是很有用的。音频文件加载后，我们可以考虑以下四种可能的状态：

  • 已停止：音频播放已停止，随时可以开始。
  • 正在启动：音频播放尚未开始，但已经收到开始的指令。
  • 正在播放：音频正在播放。
  • 正在停止：音频正在播放，但播放已经收到停止的指令，之后它将回到已停止状态。

为了表示这些状态，我们在 MainContentComponent 类中创建一个 enum：

enum TransportState {
    Stopped,
    Starting,
    Playing,
    Stopping
};

初始化界面

在 MainContentComponent 类的构造函数中，我们配置这三个按钮：

MainContentComponent()
    : state (Stopped)
{
    addAndMakeVisible (&openButton);
    openButton.setButtonText ("Open...");
    openButton.onClick = [this] { openButtonClicked(); };
    addAndMakeVisible (&playButton);
    playButton.setButtonText ("Play");
    playButton.onClick = [this] { playButtonClicked(); };
    playButton.setColour (juce::TextButton::buttonColourId, juce::Colours::green);
    playButton.setEnabled (false);
    addAndMakeVisible (&stopButton);
    stopButton.setButtonText ("Stop");
    stopButton.onClick = [this] { stopButtonClicked(); };
    stopButton.setColour (juce::TextButton::buttonColourId, juce::Colours::red);
    stopButton.setEnabled (false);

特别注意，我们最初禁用了播放和停止按钮。一旦加载了有效文件，播放按钮就会被启用。可以看到，我们为这三个按钮的 Button::onClick 辅助对象分别指定了一个 lambda 函数（参见教程：监听器与广播器）。我们还在构造函数的初始化列表中初始化了传输状态。

其他初始化

除了三个 TextButton 对象之外，我们的 MainContentComponent 类还有四个其他成员：

juce::AudioFormatManager formatManager;
std::unique_ptr<juce::AudioFormatReaderSource> readerSource;
juce::AudioTransportSource transportSource;
TransportState state;

这里我们看到前面提到的 AudioFormatManager、AudioFormatReaderSource 和 AudioTransportSource 类。

在 MainContentComponent 构造函数中，我们需要初始化 AudioFormatManager 对象，以注册一组标准格式 [1]：

formatManager.registerBasicFormats(); // [1]

至少，这会使 AudioFormatManager 对象能够为 WAV 和 AIFF 格式创建读取器。其他格式是否可用取决于平台以及 Projucer 项目中 juce_audio_formats 模块所启用的选项，如下面的截图所示：

在 MainContentComponent 构造函数中，我们还将 MainContentComponent 对象作为监听器 [2] 添加到 AudioTransportSource 对象，以便能够响应其状态的变化（例如当它停止时）：

transportSource.addChangeListener (this); // [2]

在这种情况下，函数名是 addChangeListener()，而不是像 JUCE 中许多其他监听器类那样简单地叫 addListener()。

响应 AudioTransportSource 的变化

当传输的变化被报告时，changeListenerCallback() 函数会被调用。它会在消息线程上异步调用：

void changeListenerCallback (juce::ChangeBroadcaster* source) override
{
    if (source == &transportSource)
    {
        if (transportSource.isPlaying())
            changeState (Playing);
        else
            changeState (Stopped);
    }
}

可以看到，这里只是调用了一个成员函数 changeState() 。

改变状态

传输状态的改变被集中到这个单一函数 changeState() 中。这有助于把所有相关逻辑保存在一个地方。该函数更新 state 成员，并触发在此新状态下需要发生的对其他对象的任何更改。

更有经验的读者可能希望使用状态设计模式，作为组织这段代码的另一种方式。

void changeState (TransportState newState)
{
    if (state != newState)
    {
        state = newState;
        switch (state)
        {
            case Stopped: // [3]
                stopButton.setEnabled (false);
                playButton.setEnabled (true);
                transportSource.setPosition (0.0);
                break;
            case Starting: // [4]
                playButton.setEnabled (false);
                transportSource.start();
                break;
            case Playing: // [5]
                stopButton.setEnabled (true);
                break;
            case Stopping: // [6]
                transportSource.stop();
                break;
        }
    }
}
  • [3]：当传输回到已停止状态时，它禁用停止按钮，启用播放按钮，并将传输位置重置回文件开头。
  • [4]：正在启动状态由用户点击播放按钮触发，这会告诉 AudioTransportSource 对象开始播放。此时我们也会禁用播放按钮。
  • [5]：正在播放状态由 AudioTransportSource 对象通过 changeListenerCallback() 函数报告变化而触发。这里我们启用停止按钮。
  • [6]：正在停止状态由用户点击停止按钮触发，因此我们告诉 AudioTransportSource 对象停止。

处理音频

这个演示项目中的音频处理非常直接：我们只是把处理交给 AudioTransportSource 对象，把经由 AudioAppComponent 类传给我们的 AudioSourceChannelInfo 结构体传递给它：

void getNextAudioBlock (const juce::AudioSourceChannelInfo& bufferToFill) override
{
    if (readerSource.get() == nullptr)
    {
        bufferToFill.clearActiveBufferRegion();
        return;
    }
    transportSource.getNextAudioBlock (bufferToFill);
}

注意，我们先检查是否存在有效的 AudioFormatReaderSource 对象，如果没有，就简单地把输出置零（使用便捷的 AudioSourceChannelInfo::clearActiveBufferRegion() 函数）。AudioFormatReaderSource 成员存储在 std::unique_ptr 对象中，因为我们需要根据用户的操作动态创建这些对象。这也让我们可以针对无效对象检查 nullptr。

我们还需要记得将 prepareToPlay() 回调传递给正在使用的任何其他 AudioSource 对象：

void prepareToPlay (int samplesPerBlockExpected, double sampleRate) override
{
    transportSource.prepareToPlay (samplesPerBlockExpected, sampleRate);
}

以及 releaseResources() 回调：

void releaseResources() override
{
    transportSource.releaseResources();
}

打开文件

要打开文件，我们响应打开…按钮的点击，弹出一个 FileChooser 对象：

void openButtonClicked()
{
    chooser = std::make_unique<juce::FileChooser> ("Select a Wave file to play...",
        juce::File {},
        "*.wav"); // [7]
    auto chooserFlags = juce::FileBrowserComponent::openMode
                        | juce::FileBrowserComponent::canSelectFiles;
    chooser->launchAsync (chooserFlags, [this] (const juce::FileChooser& fc) // [8]
        {
            auto file = fc.getResult();
            if (file != juce::File {}) // [9]
            {
                auto* reader = formatManager.createReaderFor (file); // [10]
                if (reader != nullptr)
                {
                    auto newSource = std::make_unique<juce::AudioFormatReaderSource> (reader, true); // [11]
                    transportSource.setSource (newSource.get(), 0, nullptr, reader->sampleRate); // [12]
                    playButton.setEnabled (true); // [13]
                    readerSource.reset (newSource.release()); // [14]
                }
            }
        });
}
  • [7]：创建 FileChooser 对象，带一条简短消息，并只允许用户选择 .wav 文件。
  • [8]：弹出 FileChooser 对象。
  • [9]：如果用户确实选择了文件（而不是取消），if() 就会成立
  • [10]：使用 AudioFormatManager::createReaderFor() 函数尝试为该文件创建读取器。如果失败（例如该文件不是 AudioFormatManager 对象能够处理的音频格式），它将返回 nullptr 值。
  • [11]：我们使用刚刚创建的读取器创建一个新的 AudioFormatReaderSource 对象。第二个参数 true 表示我们希望 AudioFormatReaderSource 对象管理 AudioFormatReader 对象，并在不再需要时删除它。我们将 AudioFormatReaderSource 对象存储在一个临时的 std::unique_ptr 对象中，以避免在后续打开文件的命令中过早删除先前分配的 AudioFormatReaderSource。
  • [12]：AudioFormatReaderSource 对象被连接到我们在 getNextAudioBlock() 函数中使用的 AudioTransportSource 对象。如果文件的采样率与硬件采样率不匹配，我们就将其作为第四个参数传入，该值从 AudioFormatReader 对象获取。有关第二和第三个参数的更多信息，请参见注释。AudioTransportSource 源将处理任何必要的采样率转换。
  • [13]：播放按钮被启用，以便用户可以点击它。
  • [14]：由于 AudioTransportSource 现在应该在使用我们新分配的 AudioFormatReaderSource 对象，我们可以安全地将该 AudioFormatReaderSource 对象存储到 readerSource 成员中。（如上面的处理音频所述。）为此，我们必须使用 std::unique_ptr::release() 从局部 newSource 变量转移所有权。

将新分配的 AudioFormatReaderSource 对象存储在临时的 std::unique_ptr 对象中还有一个额外好处：异常安全。在调用 AudioTransportSource::setSource() 期间可能抛出异常，此时 std::unique_ptr 对象会删除不再需要的 AudioFormatReaderSource 对象。如果此时使用裸指针来存储 AudioFormatReaderSource 对象，那么一旦抛出异常，指针就会悬空，可能造成内存泄漏。

播放和停止文件

由于我们已经设置好了实际播放文件的代码，只需用适当的参数调用 changeState() 函数即可播放文件。点击播放按钮时，我们执行以下操作：

void playButtonClicked()
{
    changeState (Starting);
}

停止文件同样直接，点击停止按钮时：

void stopButtonClicked()
{
    changeState (Stopping);
}

练习：在创建 FileChooser 对象时更改第三个参数（filePatternsAllowed ），让应用也能加载 AIFF 文件。文件模式可以用分号分隔，因此应为 "*.wav;*.aif;*.aiff"，以支持该格式的两种常见文件扩展名。

添加暂停功能

现在我们逐步为应用添加暂停功能。这里我们让播放按钮在文件播放时变成暂停按钮（而不只是禁用它）。我们还会让停止按钮在声音文件暂停时变成归零按钮。

首先，我们需要向 TransportState 枚举添加两个状态正在暂停和已暂停：

enum TransportState {
    Stopped,
    Starting,
    Playing,
    Pausing,
    Paused,
    Stopping
};

我们的 changeState() 函数需要处理这两个新状态，其他状态的代码也需要更新：

void changeState (TransportState newState)
{
    if (state != newState)
    {
        state = newState;
        switch (state)
        {
            case Stopped:
                playButton.setButtonText ("Play");
                stopButton.setButtonText ("Stop");
                stopButton.setEnabled (false);
                transportSource.setPosition (0.0);
                break;
            case Starting:
                transportSource.start();
                break;
            case Playing:
                playButton.setButtonText ("Pause");
                stopButton.setButtonText ("Stop");
                stopButton.setEnabled (true);
                break;
            case Pausing:
                transportSource.stop();
                break;
            case Paused:
                playButton.setButtonText ("Resume");
                stopButton.setButtonText ("Return to Zero");
                break;
            case Stopping:
                transportSource.stop();
                break;
        }
    }
}

我们在各个状态下适当地启用和禁用按钮，并正确更新按钮文字。

注意，在正在暂停状态下被要求暂停时，我们实际上是停止传输。在 changeListenerCallback() 函数中，我们需要修改逻辑，根据请求是暂停还是停止来进入正确的状态：

void changeListenerCallback (juce::ChangeBroadcaster* source) override
{
    if (source == &transportSource)
    {
        if (transportSource.isPlaying())
            changeState (Playing);
        else if ((state == Stopping) || (state == Playing))
            changeState (Stopped);
        else if (Pausing == state)
            changeState (Paused);
    }
}

我们需要修改点击播放按钮时的代码：

void playButtonClicked()
{
    if ((state == Stopped) || (state == Paused))
        changeState (Starting);
    else if (state == Playing)
        changeState (Pausing);
}

以及点击停止按钮时：

void stopButtonClicked()
{
    if (state == Paused)
        changeState (Stopped);
    else
        changeState (Stopping);
}

就是这样：现在你应该能够构建并运行该应用了。

这个修改版本应用的源代码可以在演示项目的 PlayingSoundFilesTutorial_02.h 文件中找到。

练习：向界面添加一个 Label 对象，显示 AudioTransportSource 对象的当前时间位置。你可以使用 AudioTransportSource::getCurrentPosition() 函数获取该位置。你还需要让 MainContentComponent 类继承 Timer 类，并在 timerCallback() 函数中执行周期性更新来刷新标签。你甚至可以使用 RelativeTime 类，把以秒为单位的原始时间转换成由分、秒和毫秒组成的更有用的格式。

该练习的源代码可以在演示项目的 PlayingSoundFilesTutorial_03.h 文件中找到。

小结

本教程介绍了声音文件的读取和播放。具体来说，我们涵盖了以下内容：

  • 使用 AudioFormatManager 类为常见音频格式创建 AudioFormatReader 对象。
  • 使用各种 AudioSource 类并将它们连接在一起。具体来说：
    • 用于从 AudioFormatReader 对象读取和播放音频的 AudioFormatReaderSource 类；以及
    • 用于控制 AudioFormatReaderSource 对象播放的 AudioTransportSource 类。
  • 我们还了解了一种管理音频文件播放状态的方法。

注释

AudioTransportSource::setSource() 函数的第二和第三个参数让你可以控制后台线程上的预读缓冲。第二个参数是要使用的缓冲区大小，第三个参数是指向 TimeSliceThread 对象的指针，用于后台处理。在这个例子中，我们使用零缓冲区大小，线程对象使用 nullptr 值，这是默认值。
