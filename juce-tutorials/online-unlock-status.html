通过在线注册解锁插件

通过锁定应用和插件的访问权限直到获得授权，提升它们的安全性。学习如何为用户提供一种机制，通过在线注册密钥来解锁你的插件。

难度：高级
平台：Windows、macOS、Linux
类：OnlineUnlockStatus、OnlineUnlockForm、KeyGeneration、RSAKey、TracktionMarketplaceStatus

本教程假定你具备RSA密码学、证书、网络协议和PHP语法的基本知识。

入门

在此处下载本教程的演示项目：PIP | ZIP。解压该项目，并在Projucer中打开第一个头文件。

如果你需要这一步的帮助，请参阅教程：Projucer第1部分：Projucer入门。

演示项目

演示项目展示了一个非常简单的界面，其中有两个按钮，其中一个用于通过注册解锁对另一个按钮的访问。当按下“Unlock”按钮时，会打开一个注册表单，以便用户输入凭据。目前，在我们开始实现后端服务器之前，注册过程会失败。

在成功实现并授权应用之后，你应该会在本教程结束时看到应用如下的已解锁状态。

简介

作为插件制造商，插件被黑客破解、甚至未经你同意就被免费传播，有时会令人沮丧。尽管要让应用完全抵御此类威胁可能很困难，但仍有办法让黑客的这一过程变得更加繁琐。有时你可能想为用户提供试用期，让他们在决定购买之前试用产品，或者为免费版用户限制某些功能。

根据制造商的不同，改善插件安全性的方法也各不相同：有些可能使用第三方授权方案，例如PACE的iLok，它需要一根物理USB加密狗来携带许可证；或者使用专有系统，通过将凭据与远程Web服务器上的数据库进行比对来授权用户。

在本教程中，我们来看第二种方法：通过Web服务器授权来注册插件。这种方法的优点是它既能在线工作，也能离线工作，而且不需要物理设备来完成注册。然而，由于插件会在机器上注册一段时间，与PACE那种每次插件启动都需要授权的方案相比，这种技术更容易受到破解。

那么服务器授权是如何工作的呢？如果机器连接到互联网，我们可以执行所谓的在线授权：插件通过安全连接发送用户凭据，并向服务器查询许可证密钥。如果用户确实被验证已购买该产品，服务器会将一个密钥文件发送回机器，插件便可解锁。另一方面，如果机器处于离线状态，用户仍然可以通过另一台联网的计算机从Web服务器下载密钥文件，然后将该密钥文件复制并通过加载到插件中应用到离线机器。

RSA加密

现在我们来简单谈谈密码学。我们如何确保信息在双方之间传输时不被篡改？我们使用一种广泛使用的安全加密算法RSA来确保这一点。RSA的原理是使用质数创建一对密钥，其中一个是公钥，另一个是私钥。公钥可以公开共享，用于加密消息。私钥由接收方保密保存，用于解密消息。

由于RSA的设计方式，只有私钥所有者才能解密由匹配密钥对中对应公钥加密的消息。这个场景可以用下图来描述：Bob知道公钥，Alice拥有私钥，Eve是试图拦截消息的第三方：

在上述情况中，Eve无法读取Bob的消息，因为她没有用于解密消息的私钥。她仍然可以使用公钥向Alice发送加密消息，但这对于想要拦截Bob消息的Eve来说毫无用处。这通常是RSA最常见的用例，即某一方想要发送秘密消息，但这并不是RSA在插件注册过程中的使用方式。

用于插件认证的RSA还有一种替代场景，即使用私钥加密消息，使用公钥解密。这个场景可以用下图来描述：Bob是安装了插件的机器，Alice是用于注册的认证Web服务器，Eve是试图入侵插件的第三方：

在这种情况下，任何拥有公钥的人都可以解密由Alice用私钥加密的消息，包括Bob和Eve。然而，如果Eve试图在没有匹配密钥对中对应私钥的情况下向Bob发送加密消息，Bob将能够通过用公钥解密来检查消息的真实性。然后他可以验证结果确实是有效的，因为数据会包含乱码，因此Eve无法冒充Alice。

与此类似，插件认证可以简单地通过检查服务器发送的消息是否有效来完成，前提是服务器仅在凭据与数据库匹配时才发送响应。幸运的是，所有这些加密和解密过程都由JUCE库通过KeyGeneration和RSAKey等类为我们处理好了。

现在我们已经理解了RSA加密的工作原理，让我们开始在演示项目中实现注册机制。

实现marketplace状态

为了方便在机器上使用应用的客户端与授权应用的注册服务器之间进行通信，JUCE库提供了一个充当接口的基类，称为OnlineUnlockStatus类。该类为管理应用所安装的当前机器的注册状态提供了基础。

实现特定商店marketplace的第一步是从OnlineUnlockStatus类继承，TracktionMarketplaceStatus类中描述了如何实现这个子类的示例。由于该实现是专门为Tracktion marketplace设计的，我们需要创建自己的独立子类，但我们会借用处理服务器响应的代码，因为这部分可以保持完全相同。

我们先来看看TutorialMarketplaceStatus类的实现，它派生自OnlineUnlockStatus类。请注意，为简单起见，readReplyFromWebserver()和userCancelled()函数是从TracktionMarketplaceStatus实现中复制的。

现在需要填充基类中其余的虚函数，以完成我们自己的marketplace实现。

在getProductID()函数中插入你应用的产品ID，并确保该ID稍后与服务器上的产品ID匹配：

juce::String getProductID() override
{
    return "TestApp";
}

下面的doesProductIDMatch()函数应验证服务器发送的ID是否与上一步插入的产品ID匹配：

bool doesProductIDMatch (const juce::String& returnedIDFromServer) override
{
    return getProductID() == returnedIDFromServer;
}

接下来，在getWebsiteName()函数中插入你网站的名称。此信息仅用于在联系服务器时向用户显示域名。

juce::String getWebsiteName() override
{
    return "juce.com";
}

下一个函数很重要，因为这是在尝试授权应用时要联系的地址，它应指向marketplace服务器。就本教程而言，我们指向“localhost”或“127.0.0.1”IP地址，因为测试服务器将在我们的机器上本地运行。它指向的页面以PHP扩展名结尾，因为为简单起见，服务器将使用PHP语言。

juce::URL getServerAuthenticationURL() override
{
    return juce::URL ("https://localhost:8443/auth.php");
}

请注意，与服务器通信所使用的协议必须是HTTPS，因为认证过程只能通过安全连接进行。8443端口反映了这一选择，它表示默认的SSL端口。

当注册过程开始时，客户端应用将使用用户提供的凭据请求认证，服务器将回复一条加密消息。这条包含解锁应用密钥文件的消息，只能使用与服务器端加密消息所用RSA私钥相对应的RSA公钥来解密。

getPublicKey()函数必须返回这个公钥，并将在本教程后面的密钥生成步骤中填写。先按如下方式准备好该函数，暂时将字段留空：

juce::RSAKey getPublicKey() override
{
    return juce::RSAKey ("INSERT_PUBLIC_KEY_HERE");
}

TutorialMarketplaceStatus类现在拥有了与marketplace服务器通信并获取密钥所需的全部信息。

提供注册表单

有几种方式可以显示注册表单供用户在应用或插件中填写。我们既可以在界面上覆盖一个常规的Component，也可以在主窗口上方弹出一个DialogWindow。在开发插件时强烈不建议使用后一种方式，因为这会在验证插件时冻结简单的扫描例程，而且如果DAW在注册窗口仍然活动时关闭插件，也会引起问题。

因此在本节中，我们选择前一种方式，以确保同时兼容应用和插件。为了简化实现注册用户界面的过程，JUCE库提供了OnlineUnlockForm类，它显示电子邮件和密码两个字段，并与OnlineUnlockStatus类配合提供无缝的注册实现。

创建一个名为TutorialUnlockForm的类，并按如下方式派生自OnlineUnlockForm：

class TutorialUnlockForm : public juce::OnlineUnlockForm
{
public:
    TutorialUnlockForm (TutorialMarketplaceStatus& status)
        : OnlineUnlockForm (status, "Please provide your email and password.")
    {
    }

在这里我们还传入了对上一节实现的TutorialMarketplaceStatus类的引用，并在类构造函数中提供一条描述性消息来指示用户。

在MainContentComponent中，声明三个私有成员变量，分别是一个TutorialMarketplaceStatus实例和一个TutorialUnlockForm对象，以及一个用于存储应用是否已解锁的布尔值。

TutorialMarketplaceStatus marketplaceStatus;
TutorialUnlockForm unlockForm;
bool isUnlocked = false;
JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR (MainContentComponent)
};

修改构造函数，通过传入TutorialMarketplaceStatus对象来初始化TutorialUnlockForm，并将该表单作为子Component添加，如下所示：

class MainContentComponent : public juce::Component,
                             private juce::Timer
{
public:
    //==============================================================================
    MainContentComponent()
        : unlockForm (marketplaceStatus)
    {
addChildComponent (unlockForm);
setSize (400, 250);
startTimer (100);
}

请注意，这里我们还继承自Timer类并调用startTimer()函数，稍后将用它来检查应用是否已解锁。

在resized()方法中，通过调用centreWithSize()函数将表单的尺寸设置为覆盖界面的大部分区域，如下所示：

void resized() override
{
    unlockForm.centreWithSize (300, 200);

showForm()辅助函数将在用户按下“Unlock”按钮时被调用。由于该Component只是通过addChildComponent()函数而不是addAndMakeVisible()添加的，表单默认是隐藏的，因此这里只需调用setVisible()来显示表单：

void showForm()
{
    unlockForm.setVisible (true);
}

当注册过程被取消或成功时，需要关闭表单，OnlineUnlockForm类会自动调用dismiss()回调来完成这件事。在TutorialUnlockForm声明中重写此函数，只需调用setVisible()来隐藏该Component：

void dismiss() override
{
    setVisible (false);
}
};

正如之前在MainContentComponent的构造函数中所见，启动了一个定时器，用于在timerCallback()函数中定期检查应用是否已成功解锁：

void timerCallback() override
{
    if (!isUnlocked && marketplaceStatus.isUnlocked())
    {
        isUnlocked = true;
        unlockApp();
    }
}

这里我们用isUnlocked局部变量检查应用是否仍处于锁定状态，如果是，则通过isUnlocked()函数询问OnlineUnlockStatus实例应用是否仍被锁定。如果应用已获得授权，我们就切换该局部变量以防止后续迭代，并调用下面的unlockApp()辅助函数：

void unlockApp()
{
    secretButton.setEnabled (true);
    unlockButton.setEnabled (false);
    unlockLabel.setText ("Status: Unlocked", juce::dontSendNotification);
    unlockLabel.setColour (juce::Label::textColourId, juce::Colours::green);
}

该函数只是启用访问秘密功能的按钮，禁用解锁应用的按钮，同时显示新的授权状态。

最后，当用户点击秘密功能按钮时会调用checkFeature()函数，模拟已解锁应用的行为：

void checkFeature()
{
    if (marketplaceStatus.isUnlocked())
        DBG ("App unlocked!");
    else
        DBG ("Beware of hackers!");
}

这个函数很重要，因为它为我们的应用提供了另一层安全保护。请注意，该函数会再次通过OnlineUnlockStatus实例检查应用是否仍处于解锁状态。这样做的原因是，黑客不仅需要破解这个函数才能解锁应用，还需要替换你应用代码中该函数的所有实例，才能完全突破应用的受限功能。

因此，建议在代码中尽可能多的地方检查应用的授权状态，以提供更健壮的安全机制。

现在如果我们运行应用，就可以显示注册表单了。

搭建后端服务器

本节介绍在macOS和Windows上使用PHP搭建本地测试服务器的步骤，但你可以随意使用任何类型的后端服务器，无论是Java、Ruby还是Python等等……

由于OnlineUnlockStatus类以XML格式处理来自服务器的回复，我们必须使用PHP提供XML响应。应用会将凭据发送到我们TutorialMarketplaceStatus实现的getServerAuthenticationURL()函数中提供的URL，该URL在本教程第一节中定义为“https://localhost:8443/auth.php”。

因此，让我们看看演示项目Resources文件夹中提供的auth.php文件，并研究响应是如何用PHP编写的：

<?php
function sendResponse() // [1]
{
    $response = '<?xml version="1.0" encoding="utf-8"?>'; // [2]
    if ($_POST['email'] === 'test@example.com' and $_POST['pw'] === 'test') // [3] {
        $response .=
            '<MESSAGE message="Thanks for registering our product!"><KEY>INSERT_KEY_HERE</KEY></MESSAGE>';
    } else {
        $response .=
            '<ERROR error="Sorry, we were not able to authorise your request. Please provide a valid email address and password."></ERROR>';
    }
    return $response;
}
header('Content-type: text/xml; charset=utf-8'); // [4]
echo sendResponse();
?>
  • [1]：我们首先定义一个名为sendResponse()的函数，稍后将调用它来显示XML内容。
  • [2]：然后我们通过将元数据头赋值给一个本地PHP变量来准备一个XML文档。
  • [3]：接下来，我们通过比较通过POST收到的测试电子邮件和密码字符串，检查凭据是否与测试用户相对应。如果凭据匹配，我们就追加成功消息以及一个加密的密钥文件（我们将在下一节中插入）。否则，我们追加一条错误消息，说明授权失败的原因。
  • [4]：最后，我们设置响应头以指示内容是XML格式，并使用echo函数发送响应。

此时，如果我们决定在本地运行服务器并尝试从应用联系授权服务器，我们会收到一条安全警告，告诉我们连接不是私密或安全的。为了让OnlineUnlockStatus实例安全地发送凭据，我们需要使用SSL通过HTTPS协议创建安全连接。

为了在本地进行测试，我们可以创建一个自签名证书，并使用隧道通过HTTPS访问底层不安全的HTTP协议。

确保你的计算机上安装了OpenSSL、PHP和“stunnel”以测试后端服务器。OpenSSL是生成自签名证书所必需的，PHP提供了一个可以在你机器上本地运行的内置Web服务器，而“stunnel”允许你将安全连接隧道到其中。

导航到项目的Resources文件夹，并在终端中运行以下命令创建自签名证书：

// Creates an RSA key and certificate pair.
// macOS
openssl req -new -newkey rsa:4096 -x509 -nodes -sha256 -days 365 -keyout stunnel.key -out stunnel.cert
// Windows
C:\path-to-openssl\openssl req -new -newkey rsa:4096 -x509 -nodes -sha256 -days 365 -keyout stunnel.key -out stunnel.cert

当提示你提供证书信息时，除了通用名称（CN）条目外，跳过所有字段，在该条目中应输入“localhost”。

确保域名没有拼写错误，因为这会在连接服务器时引起问题。

这将使用SHA-256哈希算法和一年的有效期，创建两个文件，构成一对RSA 4096位密钥和证书。X.509标准表示我们感兴趣的自签名策略。为简单起见，我们将生成的密钥和证书文件合并为一个PEM文件，如下所示：

// Combines the key and certificate into a PEM file.
// macOS
cat stunnel.key stunnel.cert > stunnel.pem
// Windows
type stunnel.key stunnel.cert > stunnel.pem

在macOS上，双击Finder中的PEM文件，将证书添加到你的钥匙串。这将打开位于Applications/Utilities文件夹中的Keychain Access应用。在列表中双击新添加的证书以打开详细视图，并展开Trust视图。选择“Always Trust”选项，以允许你的mac当前用户账号信任该证书，如下所示：

在Windows上，在Run提示符中输入“MMC”打开Microsoft Management Console，导航到File > Add Snap-in…并选择“Certificates”。点击Add为当前用户添加证书，然后点击OK完成。

然后，通过导航到左侧面板中的相应文件夹，并从菜单中选择Action > All Tasks > Import…，将自签名证书导入Trusted Root Certification Authorities > Certificates。你将被引导完成定位证书的步骤，此时应选择扩展名为.cert的文件，因为这是MMC接受的格式。

不要在实际应用中使用自签名证书或隧道，因为这被认为不如CA签名的证书安全。此方法仅用于演示目的。

接下来，让我们通过打开演示项目Resources文件夹中提供的stunnel.conf文件来配置隧道协议：

[https]
accept = 8443
connect = 8080
cert = stunnel.pem
TIMEOUTclose = 0

这里我们定义了用于连接的传入和传出端口，以及上一步创建的用于保护链路的证书文件。应用将尝试连接到8443端口，隧道将链接到PHP服务器运行的8080端口。

我们最终可以通过导航到Resources目录并在终端中运行以下命令来启动服务器：

// Starts the built in PHP web server and tunnels a secure connection.
// macOS
php -S localhost:8080 & stunnel stunnel.conf
// Windows
C:\path-to-php\php -S 127.0.0.1:8080 & C:\path-to-stunnel\stunnel stunnel.conf

这将启动本地服务器到8080端口，并将连接隧道到8443端口，供应用安全访问。在你喜欢的浏览器中打开认证URL“https://localhost:8443/auth.php”，以检查服务器是否正在运行。你应该会看到auth.php文件中声明的错误消息，形式为XML响应。

如果一切正常，启动应用并通过提交任意电子邮件和密码组合尝试授权。你收到的错误消息应与之前的尝试不同，并且应与浏览器中显示的消息一致，如下所示：

这意味着应用已成功联系服务器并处理响应，但我们仍然需要生成并发送正确的密钥文件来解锁应用。

通过按键盘上的“Ctrl+C”停止服务器，或运行以下命令停止服务器和隧道：

// Windows
taskkill /f /im php.exe & taskkill /f /im stunnel.exe

生成安全密钥

让我们来看看作为最后一步的生成安全密钥。

你会在项目的Resources文件夹中找到一个名为KeyGenerator的辅助控制台应用，它将生成一个RSA密钥对，用于认证此应用。每个应用或插件只需生成一次密钥，因为这些密钥可以在项目的整个生命周期内保持不变（除非私钥以某种方式泄露，这种情况下必须创建新的密钥对）。

如果我们看看KeyGenerator应用的main()函数，可以看到它所做的就是用256位的密钥长度调用RSAKey类的createKeyPair()函数，并将结果打印到屏幕上：

juce::RSAKey publicKey;
juce::RSAKey privateKey;
juce::RSAKey::createKeyPair (publicKey, privateKey, 256);
std::cout << "Public Key: " << publicKey.toString() << std::endl
          << "Private Key: " << privateKey.toString() << std::endl
          << std::endl;

构建KeyGenerator应用并运行以下命令以获取密钥：

// Run the program and copy the keys.
// macOS
./KeyGenerator
// Windows
KeyGenerator.exe

将上一步中的公钥复制并粘贴到TutorialMarketplaceStatus类的getPublicKey()函数中：

return juce::RSAKey ("INSERT_PUBLIC_KEY_HERE");

只要消息是真实的并且是使用匹配的私钥加密的，这将允许应用解密来自服务器的消息。

为了让服务器在应用请求时生成真实的密钥文件，它必须拥有上一步生成的私钥来加密消息。在实际生产场景中，密钥生成步骤必须以编程方式在服务器上完成，但就本教程而言，我们将手动执行此步骤，并将密钥文件复制粘贴到PHP脚本中。

再次导航到Resources文件夹，找到另一个名为Unlocker的辅助控制台应用。它将通过调用KeyGeneration类的generateKeyFile()函数来创建解锁应用所需的密钥文件：

// args[0]: app-name
// args[1]: user-email
// args[2]: username
// args[3]: machine-numbers
// args[4]: private-key
std::cout << juce::KeyGeneration::generateKeyFile (args[0], args[1], args[2], args[3], juce::RSAKey (args[4])) << std::endl;

该函数接受应用名称、用户电子邮件和用户名、被授权使用的机器ID以及用于加密消息的RSA私钥作为参数。你可以在运行演示项目时通过检查尝试注册时的调试器日志找到对应的机器ID。
