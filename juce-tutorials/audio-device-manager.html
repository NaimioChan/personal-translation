AudioDeviceManager 类

本教程介绍 AudioDeviceManager 类，它用于在所有平台上管理音频设备。借助它，你可以配置设备的采样率、输入和输出数量等设置。

难度：中级
平台：Windows、macOS、Linux、iOS、Android
类：AudioDeviceManager, AudioDeviceSelectorComponent, ChangeListener, BigInteger

准备工作

本教程假定你已经基本掌握如何使用 AudioAppComponent 类进行音频输入和输出（参见教程：处理音频输入）。它还假定你熟悉基本的 GUI 布局技巧（参见教程：父组件与子组件）。

在这里下载本教程的演示项目：PIP | ZIP。解压项目，并在 Projucer 中打开第一个头文件。

如果这一步需要帮助，请参阅教程：Projucer 第 1 部分：Projucer 入门。

演示项目

演示项目基于 Projucer 的 Audio Application 模板。它呈现一个 AudioDeviceSelectorComponent 对象，让你可以配置音频设备设置。演示项目还提供一个简单的文本控制台，用于报告当前的音频设备设置。应用还会显示其音频处理部分的当前 CPU 占用率。

这里给出的代码与 JUCE Demo 中的 AudioSettingsDemo 大体相似。主要区别在于生成的音频与教程：处理音频输入中的相同（它用白噪声对音频输入进行环形调制）。

音频设备

JUCE 在所有受支持的平台上提供了一致的音频设备访问方式。虽然这里提供的演示应用可能只能部署到桌面平台，但这仅仅是因为 GUI 布局的限制。音频在移动平台上同样可以无缝工作。

在 Audio Application 模板中，AudioAppComponent 类会实例化一个 AudioDeviceManager 对象 deviceManager——它是公有成员，因此可以从你的子类中访问。AudioAppComponent 类还会对这个 AudioDeviceManager 对象做一些基本初始化——这在你调用 AudioAppComponent::setAudioChannels() 时发生。

除非另有覆盖，AudioDeviceManager 类会尝试使用默认音频设备。这可以在代码中配置，也可以通过这里展示的 AudioDeviceSelectorComponent 配置。设备设置和偏好可以在应用后续启动时保存和恢复。如果首选设备不再可用（例如上次启动后外部音频设备被拔掉），AudioDeviceManager 类在这种情况下还可以回退到默认设备。

AudioDeviceManager 类也是传入 MIDI 消息的枢纽。其他教程对此有所探讨（参见教程：处理 MIDI 事件）。

AudioDeviceManager 类可以广播其设置的变更，因为它继承自 ChangeBroadcaster 类。每当我们的 AudioDeviceManager 对象发生变更时，组件的右侧就会发布一些重要的音频设备设置。

AudioDeviceSelectorComponent 类

AudioDeviceSelectorComponent 类提供了一种在所有平台上配置音频设备的便捷方式。如上所述，它在演示项目的用户界面右侧显示。构造 AudioDeviceSelectorComponent 对象时，我们把希望它控制的 AudioDeviceManager 对象传给它，同时传入若干其他选项，包括要支持的声道数（更多信息参见 AudioDeviceSelectorComponent 类的构造函数）。这里我们创建 AudioDeviceSelectorComponent 对象时，传入的是 AudioDeviceManager 对象，它是 AudioAppComponent 的成员，允许最多 256 个输入和输出声道，隐藏 MIDI 配置，并把我们的声道显示为单声道而不是立体声对：

MainContentComponent()
    : audioSetupComp (deviceManager,
          0, // minimum input channels
          256, // maximum input channels
          0, // minimum output channels
          256, // maximum output channels
          false, // ability to select midi inputs
          false, // ability to select midi output device
          false, // treat channels as stereo pairs
          false) // hide advanced options
{

我们的界面配置为可以控制：

  • 选择输出设备。
  • 选择输入设备。
  • 启用和禁用输入、输出声道。
  • 选择采样率（设备支持的采样率）。
  • 选择音频缓冲区大小（块大小）。

你应该会注意到，当我们更改其中任何一项设置时，界面右侧的小控制台窗口就会发布一份新的数据列表。这是因为 AudioDeviceManager 类是一种 ChangeBroadcaster 类。

在 changeListenerCallback() 函数中，我们调用 dumpDeviceInfo() 函数，它访问 AudioDeviceManager 对象以获取当前音频设备。然后我们获取该设备的各项信息：

void dumpDeviceInfo()
{
    logMessage ("--------------------------------------");
    logMessage ("Current audio device type: " + (deviceManager.getCurrentDeviceTypeObject() != nullptr ? deviceManager.getCurrentDeviceTypeObject()->getTypeName() : "<none>"));
    if (auto* device = deviceManager.getCurrentAudioDevice())
    {
        logMessage ("Current audio device: " + device->getName().quoted());
        logMessage ("Sample rate: " + juce::String (device->getCurrentSampleRate()) + " Hz");
        logMessage ("Block size: " + juce::String (device->getCurrentBufferSizeSamples()) + " samples");
        logMessage ("Bit depth: " + juce::String (device->getCurrentBitDepth()));
        logMessage ("Input channel names: " + device->getInputChannelNames().joinIntoString (", "));
        logMessage ("Active input channels: " + getListOfActiveBits (device->getActiveInputChannels()));
        logMessage ("Output channel names: " + device->getOutputChannelNames().joinIntoString (", "));
        logMessage ("Active output channels: " + getListOfActiveBits (device->getActiveOutputChannels()));
    }
    else
    {
        logMessage ("No audio device open");
    }
}

我们用 getListOfActiveBits() 函数，把表示活动声道列表的 BigInteger 对象（以位掩码形式）转换成 String 对象。BigInteger 对象被当作位掩码使用，类似于 std::bitset 或 std::vector<bool>。这里，组成 BigInteger 值的各个位用 0（非活动）或 1（活动）表示声道。参见教程：BigInteger 类，了解可对 BigInteger 对象执行的其他操作。

在实际应用中响应这类变更非常有用，因为我们常常需要知道应用可用的声道数何时发生变化。通常，对采样率和其他音频参数的变化做出恰当响应也很重要。

练习：尝试为 AudioDeviceSelectorComponent 类的构造函数设置不同的参数——如果你有多声道声卡，可以借此限制应用能访问的声道数，这会特别有用。你还可以看看如何把成对的声道视为立体声对。

AudioDeviceSelectorComponent 类还包含一个 Test 按钮。它会从设备输出播放一个正弦音，方便用户测试目标设备上的音频输出是否正常。

CPU 占用率

我们通过调用 AudioDeviceManager::getCpuUsage() 函数获取应用音频处理部分的 CPU 占用率。在 MainContentComponent 类中，我们继承 Timer 类，并启动定时器使其每 50 毫秒触发一次。在 timerCallback() 函数中，我们从 AudioDeviceManager 对象获取 CPU 占用率。该值以百分比形式（保留六位小数）显示在 Label 对象中：

void timerCallback() override
{
    auto cpu = deviceManager.getCpuUsage() * 100;
    cpuUsageText.setText (juce::String (cpu, 6) + " %", juce::dontSendNotification);
}

由于这个特定应用所做的音频处理非常少，CPU 占用率可能很低——在许多目标设备上大概低于 1%。不过，你可以尝试不同的设置组合，观察不同采样率和缓冲区大小对 CPU 负载的影响。一般来说，采样率越高、缓冲区越小，占用的 CPU 越多。

小结

本教程介绍了 AudioDeviceManager 类的一些特性以及音频设备的总体情况。现在你应该知道如何：

  • 使用 Audio Application 模板，访问 AudioDeviceManager 对象，它位于 AudioAppComponent 对象中。
  • 创建 AudioDeviceSelectorComponent 对象来控制 AudioDeviceManager 对象。
  • 响应音频设备的变更。
  • 访问音频设备中有用的设置，例如采样率和可用声道数。
