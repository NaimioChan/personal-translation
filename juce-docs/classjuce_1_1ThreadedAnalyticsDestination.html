juce::ThreadedAnalyticsDestination 类参考

详细说明

在专用线程上分派分析事件的基类。

本类特别适合在不阻塞消息线程的情况下把分析事件发送到 Web 服务器。它还能保存（并恢复）未能分派的事件，因此在没有网络连接或有其他原因导致记录失败时不会丢失信息。

调用 startAnalyticsThread 之后，logBatchedEvents 方法会按 setBatchPeriod 设定的周期在分析线程上被定时调用。事件在这里被分组成批次，最大批大小由 getMaximumBatchSize 的实现决定。

一定要在子类的析构函数中（或在此之前）调用 stopAnalyticsThread，给分析线程留出关闭时间。调用 stopAnalyticsThread 会进而调用 stopLoggingEvents，你应当用它终止当前正在运行的 logBatchedEvents 调用。

logBatchedEvents()

virtual bool juce::ThreadedAnalyticsDestination::logBatchedEvents (const Array < AnalyticsEvent > & events) pure virtual

此方法会在分析线程上被定时调用。

如果此方法返回 false，那么本函数的下一次调用会包含上一次调用中的同样事件，外加两次调用之间新产生的事件。事件顺序不会改变。这样你可以一直重试记录，直到成功为止。

参数
events要记录的事件列表
返回
事件是否记录成功

stopLoggingEvents()

virtual void juce::ThreadedAnalyticsDestination::stopLoggingEvents () pure virtual

你必须始终在子类的析构函数中（或在此之前）调用 stopAnalyticsThread，给分析线程留出关闭时间。

调用 stopAnalyticsThread 会触发对本方法的调用。此时可以保证 logBatchedEvents 已经最后一次被调用，你应当确保当前的 logBatchedEvents 调用尽快结束。本方法以及随后的 saveUnloggedEvents 调用都必须在传给 stopAnalyticsThread 的超时时间内完成。

在通常用法中，stopLoggingEvents 会在消息线程上由 ThreadedAnalyticsDestination 子类的析构函数调用，并且必须让运行在分析线程上的 logBatchedEvents 方法停下来。

stopAnalyticsThread()

void juce::ThreadedAnalyticsDestination::stopAnalyticsThread (int timeoutMilliseconds) protected

触发分析线程关闭。

你必须在子类的析构函数中（或在此之前）调用此方法，给分析线程留出关闭时间。

此方法会调用 stopLoggingEvents，你应当确保分析线程和 saveUnloggedEvents 调用都能在给定的超时时间内结束。这个超时很重要，因为在 iOS 这类平台上，应用关闭耗时过长会被系统杀掉。

参数
timeoutMilliseconds分析线程被强制终止前的毫秒数
