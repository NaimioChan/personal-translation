prepareToPlay()

void juce::IIRFilterAudioSource::prepareToPlay (int samplesPerBlockExpected, double sampleRate) override virtual

通知源为播放做准备。

AudioSource 有两种状态：prepared 和 unprepared。

在调用 getNextAudioBlock() 之前，保证至少会对 'unprepared' 的源调用一次 prepareToPlay() 方法，使其进入 'prepared' 状态。此回调允许源初始化播放时可能需要的任何资源。

播放结束后，会调用 releaseResources() 方法将流恢复为 'unprepared' 状态。

注意，此方法可能被连续调用多次而没有对应的 releaseResources() 调用，因此请确保你的代码足够健壮，能够处理这种情况。

参数
samplesPerBlockExpected每次调用源的 getNextAudioBlock() 方法时，源预期要提供的采样数。此数值可能略有变化，因为它取决于音频硬件回调，而这些回调不保证总是使用固定的块大小，因此源应能应对小幅变化。
sampleRate输出将使用的采样率——音调发生器等源需要此信息。

releaseResources()

void juce::IIRFilterAudioSource::releaseResources () override virtual

允许源在播放停止后释放不再需要的任何资源。

当源不再会调用其 getNextAudioBlock() 方法时会调用此方法，因此它应释放 prepareToPlay() 调用期间可能分配的备用内存等资源。

注意，无法保证 releaseResources() 之前确实调用过 prepareToPlay()，而且它可能被连续调用多次，因此请确保你的代码足够健壮，不要对调用时机做任何假设。

getNextAudioBlock()

void juce::IIRFilterAudioSource::getNextAudioBlock (const AudioSourceChannelInfo & bufferToFill) override virtual

反复调用以获取后续的音频数据块。

调用 prepareToPlay() 方法之后，每当音频播放硬件（或音频数据要去的其他任何目标）需要下一块数据时，都会进行此回调。

它通常会在高优先级系统线程上调用，甚至可能在中断中调用，因此注意不要在这里做太多工作，否则会导致音频故障！
