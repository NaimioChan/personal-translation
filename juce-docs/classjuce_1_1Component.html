void juce::Component::grabKeyboardFocus ()

尝试将键盘焦点给予此组件。

当用户点击组件或调用其 grabKeyboardFocus() 方法时，会使用以下流程来确定哪个组件应获得焦点：

runModalLoop()

int juce::Component::runModalLoop ()

以模态方式运行组件，等待循环终止。

此方法首先使组件可见，将其带到前面并给予键盘焦点。

然后它运行一个循环，从系统消息队列分派消息，但阻止所有鼠标或键盘消息到达此组件及其子组件之外的任何组件。

此循环持续到调用组件的 exitModalState() 方法（或组件被删除）为止，然后此方法返回，返回传给 exitModalState() 的值。

注意，你绝不应使用此方法！模态循环是一种危险的构造，因为其分派的事件期间发生的事情可能影响栈上某处正在使用的对象状态，因此当循环结束、栈展开时，可能会发生可怕的问题。这在插件中尤其糟糕，宿主可能选择在 runModalLoop() 期间删除插件，这样当它返回时，整个 DLL 可能已从内存中卸载！此外，某些 OS 故意使模态循环无法运行（例如 Android），因此在某些平台上此方法甚至不存在。

createAccessibilityHandler()

virtual std::unique_ptr< AccessibilityHandler > juce::Component::createAccessibilityHandler () virtual

重写此方法可为该组件返回自定义的 AccessibilityHandler。

默认实现创建并返回一个角色未指定的 AccessibilityHandler 对象，这意味着它对无障碍客户端可见，但没有特定角色、操作回调或接口。要控制无障碍客户端如何查看和交互你的组件子类 AccessibilityHandler，请实现所需行为，并在组件子类中从此方法返回它的实例。

你在此处返回的无障碍处理器保证在其 Component 之前被销毁，因此如有必要，在 AccessibilityHandler 中保存并使用指回 Component 的引用是安全的。

此函数很少应被直接调用。如果你需要查询组件的无障碍处理器，通常最好调用 getAccessibilityHandler()。此规则的例外是 createAccessibilityHandler() 的派生实现，它们可能会发现调用基类实现、然后包装或修改结果很有用。
