juce::PushNotifications 类参考

详细说明

负责推送通知功能的单例类。

同时支持远程和本地通知。要获取通知信息，请在应用启动时注册监听器。最好尽早注册监听器，因为你的应用也可能是通过推送通知启动的。

要发送本地通知，请创建一个 Notification 实例，填入必要字段并调用 PushNotifications::sendLocalNotification()。接收本地或远程通知时，检查 Notification 的字段以获取通知详情。请注意，接收远程通知时某些字段将不可用。

成员函数

requestPermissionsWithSettings()

void juce::PushNotifications::requestPermissionsWithSettings (const Settings & settings)

使用提供的设置在当前设备上初始化推送通知。

在应用启动时调用此方法；在 iOS 上首次启动应用时，会向用户显示权限请求对话框，以授予推送通知权限。用户作出回应后，将调用 Listener::notificationSettingsReceived()，以便你检查实际授予了哪些权限。在之后的每次启动时也会调用该监听器回调（前提是你在上次应用运行时调用过 requestPermissionsWithSettings()）。这样你就可以检查当前的推送通知权限。

注意，设置目前仅在 iOS 上使用。在其他平台上调用时，Listener::notificationSettingsReceived() 中将收到不带类别、所有 allow* 标志均为 true 的 Settings。

你也可以调用 requestSettingsUsed() 来显式请求当前设置。

requestSettingsUsed()

void juce::PushNotifications::requestSettingsUsed ()

发送异步请求，以获取当前正在使用的设置。

这些可以与 requestPermissionsWithSettings() 中使用的完全相同，但取决于用户随后在操作系统设置中的更改，实际当前设置可能不同（例如用户后来可能决定禁用声音）。

注意，设置目前仅在 iOS 上使用，在 OSX 上部分使用。

在 OSX 上，只使用 allow* 标志，并且它们仅指远程通知。对于本地通知，请参阅系统偏好设置。

在其他平台上调用此函数时，Listener::notificationSettingsReceived() 中将收到不带类别、所有 allow* 标志均为 true 的 Settings。

sendUpstreamMessage()

void juce::PushNotifications::sendUpstreamMessage (const String & serverSenderId, const String & collapseKey, const String & messageId, const String & messageType, int timeToLive, const StringPairArray & additionalData)

仅 Android：向你的应用服务器发送上行消息。

服务器必须实现 XMPP Connection Server 协议（请参阅 Firebase 文档）。

参数
serverSenderId表示发送方。查阅你的 Firebase 项目设置以获取 sender id。
collapseKey具有相同 collapse key 且尚未送达的远程消息将合并为一条，最新的消息会替换之前的所有消息。注意，同时使用的 collapse key 可能存在最大数量限制，超过该限制（请参阅 Firebase 文档）时，无法保证服务器会使用哪些 key。
messageId唯一的消息 ID。用于错误回调和调试。
messageTypeMessage 类型。
timeToLiveTTL，以秒为单位。如果为 0，将立即尝试发送消息，如果设备未连接则丢弃该消息。否则，消息将在指定期间内排队。
additionalData键值对集合，用作消息的附加数据。
