juce::ImagePixelDataBackupExtensions 类参考

详细说明

此接口上的方法允许 ImagePixelData 的使用者查询和控制从图形内存到主内存的自动备份过程（如果此机制适用且受支持）。

某些图像类型（Direct2D、OpenGL）由位于图形内存中的纹理支撑。这类纹理显示很快，但如果图形设备消失，它们就会丢失。

通常会在主内存中保留一份纹理的备份，这样即使图形设备消失，图像仍然可用。虽然这带来了程序能自动应对图形设备消失的好处，但也带来一些性能开销，因为每次修改后都必须将纹理内容复制回主内存。

对于性能敏感的应用，禁用自动同步行为、改为手动同步可能更有利，这可以用此类型的方法实现。

下表说明了如何解读此类型成员函数的结果。

needsBackup() | canBackup() | 含义

true | true | 图像的主内存副本已过期，但图形内存中有一份最新的副本 | | true | false | 虽然主内存已过期，但图形内存中图像的最新副本已丢失 | | false | true | 主内存与图形内存同步；图形内存仍然可用； | | false | false | 主内存中有一份最新的图像副本，但图形内存中图像的最新副本已丢失

成员函数

setBackupEnabled()

virtual void juce::ImagePixelDataBackupExtensions::setBackupEnabled (bool) pure virtual

向此函数传入 false 可以禁用自动图像备份机制，传入 true 可以启用。

如果你为某个图像禁用了自动备份，请务必测试在图形设备断开时你的软件行为是否符合预期。在 Windows 上测试这一点的一个简单方法是，通过远程桌面会话运行你的程序，并在图像显示期间结束并重新启动该会话。

此标志最有用的最常见场景是绘制一次性图像。例如，对于投影或其他效果，每次 paint 调用可能会执行以下一系列步骤：

  • 创建一条与带阴影组件的轮廓匹配的路径
  • 将路径绘制到临时图像中
  • 模糊该临时图像
  • 将临时图像绘制到其他某个上下文
  • （销毁临时图像）

在这种情况下，图像被创建、修改、使用并迅速销毁，无需保留图像的弹性备份，因此在构造图像后调用 setBackupEnabled(false) 是合理的。

backupNow()

virtual bool juce::ImagePixelDataBackupExtensions::backupNow () pure virtual

此函数会尝试通过从图形内存复制到主内存，使图像在图形设备断开时不受影响。

默认情况下备份会自动进行，因此除非已为此图像禁用自动备份，否则无需调用此函数。

如果图形设备在其内存被读取之前消失，刷新可能会失败。如果 needsBackup() 返回 false，那么 backupNow() 将总是直接返回 true 而不做任何工作。

返回
如果图像的主内存副本是最新的则为 true，否则为 false。
