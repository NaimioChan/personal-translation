juce::AccessibilityHandler 类参考

详细说明

无障碍 Component 的基类。

此类封装一个 Component，并提供一些方法，让无障碍客户端（例如 macOS 上的 VoiceOver 或 Windows 上的讲述人）能够控制它。

它处理层次结构导航、属性、状态以及各种接口。

AnnouncementPriority

enum class juce::AccessibilityHandler::AnnouncementPriority strong

一个优先级，可帮助无障碍客户端决定如何处理播报请求。

它具体控制什么取决于平台，但一般来说，低优先级公告会在屏幕阅读器空闲时朗读，而高优先级公告会打断当前的语音。

构造函数与析构函数

AccessibilityHandler()

juce::AccessibilityHandler::AccessibilityHandler (Component & componentToWrap, AccessibilityRole accessibilityRole, AccessibilityActions actions = {}, Interfaces interfaces = {})

构造函数。

这会创建一个 AccessibilityHandler，它封装所提供的 Component 并使其对无障碍客户端可见。你还必须从 AccessibilityRole 列表中为 UI 元素指定一个最能描述它的角色。

要让用户能够与 UI 元素交互，你应通过 accessibilityActions 参数提供受支持的操作集合及相应的回调。

对于支持更复杂交互的 UI 元素，应按需实现 value、text、table 和 cell 接口，并把它们作为此构造函数的最后一个参数传入。有关这些类所表示的控制类型以及需要实现哪些方法，请参阅它们的文档。

被以下对象引用： AccessibilityNativeHandle、getChildAt()、getChildFocus()、getChildren()、getParent()、isParentOf()。

getTitle()

virtual String juce::AccessibilityHandler::getTitle () const inline virtual

UI 元素的标题。

这会被系统朗读出来，应保持简洁，最好与 UI 元素可见的标题一致（如果有）。例如，这可能是按钮的文本或一个简单标签。

默认实现会调用 Component::getTitle()，但如果需要，你可以重写它来返回不同的字符串。

如果既未提供名称也未提供描述，该 UI 元素可能会被无障碍客户端忽略。

这必须是本地化字符串。

postSystemNotification()

void juce::AccessibilityHandler::postSystemNotification (const String & notificationTitle, const String & notificationBody) static

发布一条本地系统通知。

要让它产生任何效果，必须满足以下条件。

  • 构建时：
    • 项目中必须包含 juce_gui_extra 模块。
    • 必须通过设置预处理器定义 JUCE_PUSH_NOTIFICATIONS=1 来启用推送通知
  • 运行时：
    • 必须有一个无障碍客户端（讲述人、VoiceOver 等）处于活动状态。

此外，在 Android 上通知需要图标。必须在 Projucer 的 "Extra Android Raw Resources" 设置中，添加名为 "accessibilitynotificationicon" 的图标文件路径来指定它。

在 macOS、iOS 和 Android 上，这会使用推送通知客户端。在 Windows 上，这会创建一个系统托盘图标来发布通知。

参数
notificationTitle通知的标题
notificationBody通知的主体文本
