juce::PluginDirectoryScanner 类参考

详细说明

扫描目录中的插件，并把它们添加到 KnownPluginList。

要使用其中之一，请创建它并反复调用 scanNextFile()，直到它返回 false。

构造函数与析构函数

PluginDirectoryScanner()

juce::PluginDirectoryScanner::PluginDirectoryScanner (KnownPluginList & listToAddResultsTo, AudioPluginFormat & formatToLookFor, FileSearchPath directoriesToSearch, bool searchRecursively, const File & deadMansPedalFile, bool allowPluginsWhichRequireAsynchronousInstantiation = false)

创建一个扫描器。

参数
listToAddResultsTo新类型将被添加到这个对象中。
formatToLookFor这是你想要查找的格式类型
directoriesToSearch要搜索的路径
searchRecursively为 true 时递归搜索
deadMansPedalFile如果不是 File()，则它将被用作文件，用来存储初始化期间崩溃的任何插件的名称。如果其中列出了任何插件，那么在所有其它可能的文件都尝试过之后，这些插件总会被扫描——这样，即使你的路径里有几个不靠谱的插件，几次重新扫描仍能设法找到所有正常的插件。最好在用户的应用数据目录中选择一个文件（与你应用的设置文件放在一起）。它使用的文件格式就是失败模块的文件名列表。
allowPluginsWhichRequireAsynchronousInstantiation如果此项为 false，则扫描器将排除插件的异步创建——例如 AUv3 插件。

scanNextFile()

bool juce::PluginDirectoryScanner::scanNextFile (bool dontRescanIfAlreadyInList, String & nameOfPluginBeingScanned)

尝试下一个看起来像插件的文件。

如果 dontRescanIfAlreadyInList 为 true，则只有当文件不在列表中，或文件的修改时间自列表创建以来已发生变化时，才会加载并重新测试该文件。如果 dontRescanIfAlreadyInList 为 false，则该文件总会被重新加载并测试。nameOfPluginBeingScanned 会在扫描开始前更新为正在扫描的插件名称。

当没有更多文件可尝试时返回 false。
