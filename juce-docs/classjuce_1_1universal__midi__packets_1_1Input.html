juce::universal_midi_packets::Input 类参考

详细说明

一个输入（从 JUCE 项目的角度看），用于接收端点发送的消息。

Input 在概念上类似于 unique_ptr，因为它是可为空的、仅可移动的类型。你可以通过调用 isAlive() 检查实例是否为空。对于当前已连接的 Input，isAlive() 将返回 true，否则返回 false。特别地，对于默认构造的 Input，isAlive() 将返回 false。如果 isAlive() 返回 false，你应避免调用其它成员函数：虽然这不会导致未定义行为，但在此状态下没有任何函数会产生有用的结果。

如果连接到 Input 的设备变得不可用（例如被拔出或蓝牙连接断开），Input 会将自身置空，对 isAlive() 的调用将返回 false。你可以通过调用 addDisconnectionListener() 注册回调来处理此事件。

需要特别留意的一个陷阱是：对默认构造的 Input 或 isAlive() 返回 false 的其它 Input 调用 addConsumer()、removeConsumer()、addDisconnectionListener() 和 removeDisconnectionListener()。这不会产生任何效果。相反，如果你想向 Input 附加监听器，应使用 Session::connectInput() 创建一个 Input，并确保该 Input 上的 isAlive() 返回 true 之后再附加监听器。

addConsumer()

void juce::universal_midi_packets::Input::addConsumer (Consumer & r)

附加一个接收者，它将从此输入接收 MIDI 消息。

传入消息将被转换为打开 Input 时请求的协议。

如果在此函数被调用时 isAlive() 返回 false，则此函数不会产生任何效果。这通常发生在尝试向默认构造的 Input 添加监听器时，或者输入设备已断开连接时。

在消费者回调内部添加或移除消费者是错误的。这会导致死锁，所以务必小心！

你只应在主线程上添加和移除消费者。

对 Consumer::consume() 的调用将发生在单独的线程上，通常具有高优先级甚至实时优先级。
