juce::AudioProcessorPlayer 类参考

详细说明

一个 AudioIODeviceCallback 对象，通过 AudioProcessor 流式传输音频。

要使用其中之一，只需将其设为你的 AudioIODevice 所使用的回调，并通过调用 setProcessor() 给它一个要使用的处理器。

它也是一个 MidiInputCallback，因此你可以将其同时连接到音频和 midi 输入，以将两个流都送入处理器。要为处理器设置 MidiOutput，请使用 setMidiOutput() 方法。

另见
AudioProcessor, AudioProcessorGraph

setDoublePrecisionProcessing()

void juce::AudioProcessorPlayer::setDoublePrecisionProcessing (bool doublePrecision)

在双精度和单精度浮点处理之间切换。

音频 IO 回调仍将以单精度浮点运行，但如果 AudioProcessor 支持，所有内部处理（包括 AudioProcessor）都将以双精度浮点处理（见 AudioProcessor::supportsDoublePrecisionProcessing()）。否则，无论参数 doublePrecision 如何，处理都将保持单精度。

audioDeviceIOCallbackWithContext()

void juce::AudioProcessorPlayer::audioDeviceIOCallbackWithContext (const float *const * inputChannelData, int numInputChannels, float *const * outputChannelData, int numOutputChannels, int numSamples, const AudioIODeviceCallbackContext & context) override virtual

处理传入和传出的一个音频数据块。

子类的实现应按其需要使用传入音频，并且必须在返回前用下一个输出数据块填满所有输出通道。

通道数据的排列所用数组索引与 AudioIODevice::getOutputChannelNames() 返回的通道名称数组相同，但那些未在 AudioIODevice::open() 中指定的通道，其关联通道指针将为 nullptr，因此记得检查这一点。

参数
inputChannelData一组包含每个传入通道音频数据的数组 - 该数据在函数返回前有效。设备打开时启用的每个输入通道都会有一路数据（见 AudioIODevice::open()）
numInputChannelsinputChannelData 数组中通道数据指针的数量。
outputChannelData一组需要用要发送到设备各输出通道的数据填充的数组。设备打开时启用的每个输出通道都会有一路数据（见 AudioIODevice::open()）数组的初始内容未定义，因此如果输出是静音，回调函数必须将所有通道填充为零。不这样做可能会产生相当难听的声音！
numOutputChannelsoutputChannelData 数组中通道数据指针的数量。
numSamples输入和输出数组中每个通道的采样数。采样数取决于音频设备的缓冲区大小，并且通常会保持不变，但这并非保证。例如在 Android 上，在支持该功能的设备上，Android 会把你的音频处理切分成若干个更小的回调以确保更高的音频性能。因此请确保你的代码能应对从一个回调到下一个回调的合理缓冲区大小变化。
context可能传递给 AudioIODeviceCallback 的附加信息。

audioDeviceAboutToStart()

void juce::AudioProcessorPlayer::audioDeviceAboutToStart (AudioIODevice * device) override virtual

调用以指示设备即将开始回调。

这将在音频回调开始之前被调用，无论是在此回调刚被添加到音频设备时，还是在因采样率或块大小变化而重启设备之后。

你可以借此机会，通过对传入的指针调用 AudioIODevice::getCurrentSampleRate() 和 AudioIODevice::getCurrentBufferSizeSamples()，查明设备将使用的采样率和块大小。

参数
device将用于驱动回调的音频 IO 设备。注意，如果你要保存此指针，它只在下次调用 audioDeviceStopped 之前有效。

handleIncomingMidiMessage()

void juce::AudioProcessorPlayer::handleIncomingMidiMessage (MidiInput * source, const MidiMessage & message) override virtual

接收传入的消息。

当 MIDI 事件到达时，MidiInput 对象会调用此方法。它会在高优先级系统线程上被调用，因此避免在这里做耗时的事情，也避免任何 UI 调用。你可能会发现 MidiBuffer 类有助于将传入消息排队以便稍后使用。

参数
source生成该消息的 MidiInput 对象
message传入的消息。消息的时间戳被设为等同于（Time::getMillisecondCounter() / 1000.0）的值，以指明消息到达的时间
