userArea

Rectangle <int> juce::Displays::Display::userArea

userBounds

Rectangle <float> juce::Displays::Display::userBounds

此显示器未被任务栏、菜单栏等依赖于操作系统的对象覆盖的总区域（逻辑像素）。

在移动端（iOS、Android）上，系统 UI 会尽可能透明，JUCE 应用可能绘制在这些栏后面。因此，在这些平台上，userBounds not 受系统 UI 限制。相反，显示器可能被遮挡的区域可以通过查询 safeAreaInsets 和 keyboardInsets 找到。

支持多窗口的移动平台（例如 Android 分屏）将在此返回当前可供应用使用的屏幕区域。结果区域可能明显小于整个屏幕区域，但可能与系统装饰重叠。

被以下对象引用： juce::StandaloneFilterWindow::StandaloneFilterWindow()。

safeAreaInsets

BorderSize <int> juce::Displays::Display::safeAreaInsets

表示此显示器中无法用于显示内容的区域（逻辑像素）。

这些 insets 相对于 userArea 应用。

在移动设备上，这可能是显示器开孔和刘海覆盖的区域，在这些地方你仍想绘制背景，但不应放置重要内容。

注意，这些 insets 可能随系统当前状态而变化。举个简单的例子，进入/退出 kiosk 模式可能导致系统 UI 可见性改变，从而影响安全区域。更复杂的例子是 Android 上的分屏状态，占据屏幕顶部的 activity 很可能有状态栏 insets 但没有导航栏 insets，而底部的 activity 可能有导航 insets 但没有状态 insets。

屏幕旋转也可能导致内边距发生变化，因为这会使任何物理屏幕切口随之旋转，还可能引起系统 UI 元素重新定位。

keyboardInsets

BorderSize <int> juce::Displays::Display::keyboardInsets

表示此显示器中被屏幕键盘遮挡的区域（逻辑像素）。

目前仅在 iOS 以及 Android 11+ 上受支持。

此方法仅在键盘处于“停靠”模式时返回键盘的边界。如果键盘是浮动的（例如在 iPad 上使用分屏键盘模式），则不会报告任何内边距。

scale

double juce::Displays::Display::scale

此显示器的缩放因子。

对于更高分辨率的显示器，或设置了用户自定义缩放系数的显示器，该值可能不是 1.0。

该值用于在物理像素与逻辑像素之间进行转换。例如，大小为 10x10 的 Component 在缩放系数为 2.0 的显示器上将使用 20x20 个物理像素。

dpi

double juce::Displays::Display::dpi

显示器的 DPI。

这是每英寸的物理像素数。要得到每英寸的逻辑像素数，请将此值除以 Display::scale 值。

std::optional<double> juce::Displays::Display::verticalFrequencyHz
