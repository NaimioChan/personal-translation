juce::midi_ci::PropertyHost 类参考

详细说明

作为 ResponderListener 使用时，此类的实例可以对远程设备发起的属性事务组织合适的回复。

PropertyHost 实例还包含用于通知远程设备本地属性状态变化的方法。

sendSubscriptionUpdate()

std::optional< RequestKey > juce::midi_ci::PropertyHost::sendSubscriptionUpdate (MUID device, const PropertySubscriptionHeader & header, Span < const std::byte > body, std::function< void(const PropertyExchangeResult &)> callback)

作为订阅响应者时，从设备发送一条 Subscription 消息。

当所订阅的属性以远程设备不知道的方式被修改时，你应对所有已注册的订阅者调用此函数（如果是远程设备请求属性更新，那么在相应地修改属性后无需发送订阅更新）。

你not尝试用此函数在另一台设备上启动新订阅。有效的订阅命令有 full、partial 和 notify。这些命令的预期用途请查阅属性交换规范。

要终止由远程设备发起的订阅，请使用 terminateSubscription()。

远程设备确认收到订阅更新后，将调用所给回调。如果你的应用状态发生变化，不再需要响应/等待确认，可以把请求键传给 Device::abortPropertyRequest()。

terminateSubscription()

void juce::midi_ci::PropertyHost::terminateSubscription (MUID device, const String & subscribeId)

终止由远程设备启动的订阅。

如果你的应用带有可添加和移除的属性，这可能有用 —— 你可以在移除这些属性之前终止对它们的订阅。

findSubscriptionsForDevice()

std::set< Subscription > juce::midi_ci::PropertyHost::findSubscriptionsForDevice (MUID device) const

返回已订阅资源的集合。

此集合包含给定设备的所有活动 subscriptionID，以及这些 subscriptionID 所指的资源。

返回由其他设备发起但尚未完成的事务数量，这通常是因为请求被拆成了多条消息。

tryRespond()

bool juce::midi_ci::PropertyHost::tryRespond (ResponderOutput & output, const Message::Parsed & message) override virtual

如果消息处理成功且已发出响应，则返回 true。

否则返回 false，以便必要时让其他 ResponderDelegate 尝试处理该消息。
