juce::Thread 类参考

详细说明

封装一个线程。

子类从 Thread 派生并实现 run() 方法，在其中完成自己的工作。然后可以用 startThread() 或 startRealtimeThread() 方法启动线程，并用各种其他方法进行控制。

此类还包含一些与线程相关的静态方法，例如 sleep()、yield()、getCurrentThreadId() 等。

另见
CriticalSection, WaitableEvent, Process, ThreadWithProgressWindow, MessageManagerLock

startThread() [1/2]

bool juce::Thread::startThread ()

尝试以默认（'Priority::normal'）优先级启动新线程。

这会使线程的 run() 方法由一个新线程调用。如果此线程已在运行，startThread() 不会做任何事。

如果无法以请求的优先级创建线程，将返回 false，并且不会调用 Thread::run()。Android 平台是个例外，它总是启动线程并在创建后尝试升级线程。

返回
如果线程成功启动则为 true。如果不成功则为 false。

stopThread() [2/3]

bool juce::Thread::stopThread (Seconds timeOut)

尝试停止线程运行。

此方法会使 threadShouldExit() 方法返回 true，并在该线程当前处于等待状态时调用 notify()。

但愿线程随后会通过干净退出对此作出响应，而 stopThread 方法将等待给定的时间段以便其发生。

如果线程卡住并在超时后仍未响应，它会被强制杀死，这是非常糟糕的事情，因为它可能仍持有程序其它部分所需的锁等。

因此，与 stopThread (int) 不同，只支持正的超时值，其他任何值都会触发断言。要无限期等待，请不带参数调用 stopThread()。

参数
timeOut在强制杀死线程之前等待其结束的最长时间。必须为正。
返回
如果线程在超时前干净停止则为 true，如果不得不强制杀死则为 false。
另见
signalThreadShouldExit, threadShouldExit, waitForThreadToExit, isThreadRunning

bool juce::Thread::launch (std::function< void()> functionToRun) static

这将启动一个 Thread 对象，它调用该函数然后退出。请记住，启动和停止线程是相当重量级的操作，因此如果你要启动大量简短的后台任务，可能更愿意使用 ThreadPool。

initialiseJUCE()

void juce::Thread::initialiseJUCE (void * jniEnv, void * jContext) static

为不是由 Projucer 创建的项目初始化 JUCE 子系统。

在 Android 上，JUCE 在使用前需要初始化一次。Projucer 会自动生成必要的 java 代码来完成此操作。但是，如果你在没有 Projucer 的情况下使用 JUCE，或正在创建一个用 JUCE 制作、打算用于非 JUCE apk 的库，那么你必须在 apk 启动时手动调用此方法一次。

你可以从 C++ 调用此方法，或直接通过调用以下 java 方法从 java 调用：

com.rmsl.juce.Java.initialiseJUCE (myContext);

注意，上述 java 方法仅在由 Projucer 创建的 Android Studio 项目中可用。如果你需要从其他类型的项目中调用它，则需将以下 java 文件添加到你的项目中：

package com.rmsl.juce;

public class Java
{
 static { System.loadLibrary ("juce_jni"); }
 public native static void initialiseJUCE (Context context);
}
参数
jniEnv这是指向 JNI 的 JNIEnv 变量的指针。任何从 Java 到 C++ 的回调都会将其作为第一个参数传入。
jContext这是一个指向你的 app/service/receiver/provider 的 Context 的 jobject。JUCE 的许多内部函数都需要它。
