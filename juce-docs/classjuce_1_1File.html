juce::File 类参考

详细说明

表示本地文件或目录。

此类封装文件或目录的绝对路径名，并提供查询文件信息及更改其属性的方法。

要读写文件，有返回输入流或输出流的方法。

另见
FileInputStream, FileOutputStream

TypesOfFileToFind

enum juce::File::TypesOfFileToFind

用于文件搜索，以指定应返回文件、目录还是两者。

枚举值
findDirectories 

使用此标志表示你想查找目录。

findFiles 

使用此标志表示你想查找文件。

findFilesAndDirectories 

使用此标志表示你想同时查找文件和目录。

ignoreHiddenFiles

FollowSymlinks

enum class juce::File::FollowSymlinks strong
枚举值
no 

请求文件系统遍历不跟随任何符号链接。

noCycles 

请求文件系统遍历可以跟随符号链接，但应尝试跳过任何可能导致循环的指向目录的符号链接。

yes 

请求文件系统遍历跟随所有符号链接。

请谨慎使用，因为如果文件系统包含由符号链接导致的循环，这可能产生不一致的结果或无法终止。

SpecialLocationType

enum juce::File::SpecialLocationType

一组可传递给 getSpecialLocation() 方法的位置类型。

枚举值
userHomeDirectory 

用户的主文件夹。

这与使用 File ("~") 相同。

userDocumentsDirectory 

用户的默认文档文件夹。

在 Windows 上，这可能是用户的 "My Documents" 文件夹。在 Mac 上则是其 "Documents" 文件夹。Linux 通常没有这样的文件夹，因此可能只返回其主文件夹。

userDesktopDirectory 

包含用户桌面对象的文件夹。

userMusicDirectory 

用户最可能存放音乐文件的位置。

userMoviesDirectory 

用户最可能存放电影文件的位置。

userPicturesDirectory 

用户最可能存放图片文件的位置。

userApplicationDataDirectory 

应用程序存储其持久化的用户特定设置的文件夹。

在 Windows 上，这可能是 "\Documents and Settings\username\Application Data"。在 Mac 上，可能是 "~/Library"。如果你要在此存储设置，务必创建自己的子文件夹来存放，以免弄乱。在 GNU/Linux 上它是 "~/.config"，使用前你可能需要创建该目录。

commonApplicationDataDirectory 

与 userApplicationDataDirectory 文件夹等价，但由计算机的所有用户共享，而不仅是当前用户。

在 Mac 上它是 "/Library"，在 Windows 上可能类似于 "\Documents and Settings\All Users\Application Data"。

在 GNU/Linux 上它是 "/opt"。

视配置而定，此文件夹可能是只读的。

commonDocumentsDirectory 

存放由机器所有用户共享的文档的位置。

在 Windows 上这可能是 "C:\Users\Public\Documents" 之类的位置，在 OSX 上则是 "/Users/Shared" 之类。不过其他操作系统可能没有这种概念，因此要小心。

tempDirectory 

应用于临时文件的文件夹。

完成后务必删除它们，以保持用户计算机整洁！

currentExecutableFile 

返回此应用程序的可执行文件。

如果作为插件或 DLL 运行，这将（在可能的情况下）是 DLL 而不是宿主应用。

在 Mac 上，这将返回 unix 二进制文件，而不是包文件夹——后者请参见 currentApplicationFile。

另见 invokedExecutableFile，它类似，但如果 exe 是从文件链接启动的，invokedExecutableFile 将返回链接的名称。

currentApplicationFile 

返回此应用程序的位置。

如果作为插件或 DLL 运行，这将（在可能的情况下）是 DLL 而不是宿主应用。

在 Mac 上，这将返回包文件夹（如果它在包中），而不是其中的 unix 二进制文件——请与 currentExecutableFile 比较。

invokedExecutableFile 

返回被调用来启动此可执行文件的文件。

如果应用是从例如链接启动的，这可能与 currentExecutableFile 不同——这将返回所用链接的名称，而 currentExecutableFile 将返回目标可执行文件的实际位置。

hostApplicationPath 

在插件中，这将返回宿主可执行文件的路径。

windowsSystemDirectory 

在 Windows 机器上，返回 Windows/System32 文件夹的位置。

globalApplicationsDirectory 

应用程序通常安装到的目录。

因此在 Windows 上，这可能是 "C:\Program Files"，在 Mac 上是 "/Applications"，在 linux 上是 "/usr"。

globalApplicationsDirectoryX86 

在 Windows 机器上，返回 32 位应用程序通常安装到的目录。

在 64 位机器上，这可能是 "C:\Program Files (x86)"，而在 32 位机器上，这将与 globalApplicationsDirectory 一致，类似于 "C:\Program Files"。

另见
globalApplicationsDirectory
windowsLocalAppData 

在 Windows 机器上返回 LOCALAPPDATA% 文件夹。

windowsProgramFilesCommon 

在 Windows 机器上返回 COMMONPROGRAMFILES% 文件夹。

getFileName()

String juce::File::getFileName () const

返回路径名的最后一段。

仅返回路径的最后一部分——例如，如果完整路径是 "/moose/fish/foo.txt"，这将返回 "foo.txt"。

对于目录，它返回路径的最后一部分——例如对于目录 "/moose/fish"，它将返回 "fish"。

如果文件名以点开头，它将返回整个文件名，例如对于 "/moose/.fish"，它将返回 ".fish"

另见
getFullPathName, getFileNameWithoutExtension

getRelativePathFrom()

String juce::File::getRelativePathFrom (const File & directoryToBeRelativeTo) const

创建相对于给定目录引用某文件的相对路径。
