成员函数

newOpenGLContextCreated()

virtual void juce::OpenGLRenderer::newOpenGLContextCreated () pure virtual

当新 GL 上下文已创建时调用。

你可以借此机会创建纹理、着色器等。调用此方法时，新的 GL 上下文将处于活动状态。注意此回调在后台线程上进行，因此请确保你的实现是线程安全的。

renderOpenGL()

virtual void juce::OpenGLRenderer::renderOpenGL () pure virtual

当你应渲染下一个 OpenGL 帧时调用。

注意此回调在后台线程上进行。

如果上下文附加到某个组件以进行组件渲染，那么在此回调进行时 MessageManager 将处于锁定状态。

如果没有进行组件渲染，则 MessageManager 不会被锁定，你需要确保代码与 GUI 类的任何交互都是线程安全的。

有关如何触发渲染回调的信息，参见 OpenGLContext::triggerRepaint() 和 OpenGLContext::setContinuousRepainting()。

重要：切勿在此函数内获取 MessageManagerLock！在 macOS 上，OpenGL 上下文将在本次调用期间被锁定。主线程也可能随时尝试与 OpenGL 上下文交互，这同样需要锁定 OpenGL 上下文。因此，在 renderOpenGL() 内获取 MessageManagerLock 可能导致层级死锁。

openGLContextClosing()

virtual void juce::OpenGLRenderer::openGLContextClosing () pure virtual

当当前 OpenGL 上下文即将关闭时调用。

你可以借此机会释放自己创建的任何 GL 资源。

注意此回调在后台线程上进行，因此请确保你的实现是线程安全的。

（另请注意，在 Android 上此回调不会发生，因为目前无法实现它。）
