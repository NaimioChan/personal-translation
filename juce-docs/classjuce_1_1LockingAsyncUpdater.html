juce::LockingAsyncUpdater 类参考

详细说明

有点类似 AsyncUpdater，但保证在 cancelPendingUpdate() 返回之后，直到再次调用 triggerAsyncUpdate() 之前异步函数都不会被调用。

对于编写具备异步行为、但仍能安全地从后台线程销毁的类来说，这是一个重要的保证。

注意，此类型的所有成员函数都有可能阻塞，因此该类不适合用于从实时线程广播变更。

LockingAsyncUpdater() [1/2]

juce::LockingAsyncUpdater::LockingAsyncUpdater (std::function< void()> callbackToUse) explicit

创建一个 LockingAsyncUpdater 对象，它在被触发时会在主线程上调用所提供的回调。

注意，LockingAsyncUpdater 在调用所提供的回调之前会获取内部互斥量。因此，为避免死锁，你应（理想情况下）确保 callbackToUse 内部不获取任何锁。如果确实需要在回调内加锁，请确保在调用任何 LockingAsyncUpdater 成员函数时不要持有同一把锁。

被以下对象引用： isUpdatePending()、LockingAsyncUpdater()、operator=()。

triggerAsyncUpdate()

void juce::LockingAsyncUpdater::triggerAsyncUpdate ()

使回调在稍后时间触发。

此方法会快速返回，随后 impl 线程会尽快回调 handleAsyncUpdate() 方法。

如果某个更新回调已处于待处理状态但尚未开始执行，调用此方法不会有任何效果。

从任何线程调用此方法都是线程安全的，但要小心从实时（例如音频）线程调用，因为它会无条件地锁定一个互斥量。这可能会阻塞，例如在异步回调正在主线程执行时从后台线程调用它。

cancelPendingUpdate()

void juce::LockingAsyncUpdater::cancelPendingUpdate () noexcept

这将停止任何待处理的更新发生。

如果另一个线程上的回调已在执行，此方法会一直阻塞到该回调结束后才返回。

handleUpdateNowIfNeeded()

void juce::LockingAsyncUpdater::handleUpdateNowIfNeeded ()

如果已触发更新且正在等待处理，这将同步调用它。

可以把它当作一种「刷新」操作——如果有待处理的更新，handleAsyncUpdate() 方法会立即被调用；如果没有待处理的更新，则什么也不做。

因为它可能调用回调，该方法只能在主事件线程上调用。
