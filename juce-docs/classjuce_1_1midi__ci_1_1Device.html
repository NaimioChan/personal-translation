juce::midi_ci::Device 类参考

详细说明

此类型的实例负责解析和解释收到的 MIDI-CI 消息，并向其他设备发送 MIDI-CI 消息。

每个 Device 既可作为消息的目标，也可作为消息的源头，用于检查/配置其他设备。

Device 的成员函数通常用于检查其他设备。以 send 开头的成员函数用于向其他设备发送或请求信息；当 Device 收到响应时，已注册的 DeviceListener 会收到通知，随后可用名称匹配 get.*ForMuid 的成员函数获取查询结果。

如果 Device 没有本地 profile 或属性，则所有收到的消息都会用构造时提供的信息自动生成响应。

如果 Device 带有 profile 或属性，则你应视情况实现 ProfileDelegate 和/或 PropertyDelegate，并在构造时传入该 delegate。当远程设备向本地设备发出请求（例如启用/禁用 profile，或设置/获取属性数据）时，每个 Delegate 都会收到回调。

有时本地设备在更新其 profile 或属性状态时必须发送通知，例如添加 profile 时，或所订阅的属性发生变化时。发送这些通知的方法位于 ProfileHost 和 PropertyHost 类上。

processMessage()

void juce::midi_ci::Device::processMessage (ump::BytesOnGroup) override virtual

应把任何需要由该设备处理的消息都传给此函数。

只应向它传入完整的 CI 消息 —— 你可能会发现 Extractor 类有助于解析 Universal MIDI Packet 流并提取其中的 CI 消息。注意，此函数 not 会与此类的其他成员函数进行同步。这意味着，如果其他线程有可能同时在同一实例上调用其他成员函数，你就绝不能直接从 MIDI 输入线程调用它。最简单的做法大概是把所有消息都送到主线程，并把与 Device 的交互限制在该线程中。

sendProfileEnablement()

void juce::midi_ci::Device::sendProfileEnablement (MUID muid, ChannelInGroup address, Profile profile, int numChannels)

启用或禁用某个 profile。

传入 0 或负数以禁用该 profile，传入正数以启用它。

组/块 profile 也是如此。如果请求寻址到组/块，则正数会导致发送 profile on 消息，非正数会导致发送 profile off 消息。对于寻址到组/块的消息，所发消息的通道计数始终为零，无论 numChannels 参数的值如何。
