juce::dsp::Convolution 类参考

详细说明

使用 JUCE 的 FFT 类在频域中对输入信号与脉冲响应进行立体声分块卷积。

该类提供了一些线程安全的函数，可在运行时从音频文件或内存加载脉冲响应，而不会产生明显伪影，并在必要时进行重采样和裁剪。

该类执行的处理等同于 FIRFilter 类中进行的时域卷积，其中 FIRFilter::Coefficients 对象以脉冲响应的采样作为其系数。不过一般来说，当脉冲响应的长度为 64 个采样或更大时，进行频域卷积会更高效。

注意：该类默认使用零延迟和均匀分块算法。如果脉冲响应尺寸较大，或该算法过于消耗 CPU，可以使用固定延迟版本的算法，或简单的非均匀分块卷积算法。

线程：交错调用该类的方法是不安全的。如果你需要在处理过程中加载新的脉冲响应，load() 调用必须与 process() 调用同步，这实际上意味着要从音频线程发起 load() 调用。loadImpulseResponse() 函数是 are 无等待的，因此适合在实时环境中使用。

成员函数

prepare()

void juce::dsp::Convolution::prepare (const ProcessSpec &)

必须在首次调用 process 之前调用。

一般来说，调用 loadImpulseResponse() 会异步加载脉冲响应（IR）。IR 在完全加载并处理完成后才会生效，这可能需要一些时间。

调用 prepare() 可确保最近一次调用 loadImpulseResponse() 时提供的 IR 已完全初始化。该 IR 随后将在下一次调用 process() 时生效。如果必须在首次 process() 调用期间就有特定的 IR 生效，建议调用 loadImpulseResponse() before prepare()。

引用了 prepare()。

被以下对象引用： getLatency()、prepare()。

loadImpulseResponse() [1/3]

void juce::dsp::Convolution::loadImpulseResponse (const void * sourceData, size_t sourceDataSize, Stereo isStereo, Trim requiresTrimming, size_t size, Normalise requiresNormalisation = Normalise::yes)

该函数从内存中加载脉冲响应音频文件，该文件是通过 Projucer 以二进制数据形式添加到 JUCE 项目中的。

它可以加载 JUCE 中注册的任何音频格式，并在需要时执行一些重采样和预处理。

注意：不要对 float 采样使用该函数，因为数据应为二进制格式的音频文件。请确保原始数据在 Convolution 对象的整个生命周期内保持不变，因为该函数返回后加载过程将在后台线程中进行。

参数
sourceData用作流数据源的数据块
sourceDataSize源数据块中的字节数
isStereo选择立体声或单声道
requiresTrimming可选地裁剪脉冲响应的开头和结尾
size加载后脉冲响应的预期尺寸，可设为 0 以请求原始脉冲响应尺寸
requiresNormalisation可选地归一化脉冲响应的幅度

引用了 prepare()。

loadImpulseResponse() [3/3]

void juce::dsp::Convolution::loadImpulseResponse (AudioBuffer < float > && buffer, double bufferSampleRate, Stereo isStereo, Trim requiresTrimming, Normalise requiresNormalisation)

该函数从音频缓冲区加载脉冲响应。

为避免在音频线程上进行内存分配，该函数会取得传入缓冲区的所有权。

如果在处理过程中调用此函数，请确保缓冲区不是在音频线程上分配的（小心意外的拷贝！）。如果需要传递任意/生成的缓冲区，建议在单独的线程上创建这些缓冲区，并使用某种无等待构造（无锁队列或 SpinLock/GenericScopedTryLock 组合）将所有权转移到音频线程，而不进行分配。

参数
buffer要使用的 AudioBuffer
bufferSampleRateAudioBuffer 中数据的 sampleRate
isStereo选择立体声或单声道
requiresTrimming可选地裁剪脉冲响应的开头和结尾
requiresNormalisation可选地归一化脉冲响应的幅度
