read() [2/3]

bool juce::AudioFormatReader::read (int *const * destChannels, int numDestChannels, int64 startSampleInSource, int numSamplesToRead, bool fillLeftoverChannelsWithCopies)

从流中读取采样。

参数
destChannels一个缓冲区数组，各通道的采样数据将写入其中。如果格式为定点格式，无论源的位深如何，每个通道都将写为使用完整范围 -0x80000000 到 0x7fffffff 的 32 位有符号整数数组。如果是浮点格式，你应将结果数组强制转换为 (float**)，以获取数值（范围在 -1.0 到 1.0 或更大）。如果是立体声格式，则 destChannels[0] 为左通道数据，destChannels[1] 为右通道。numDestChannels 参数表示该数组包含多少个指针，但如果你不想读取某些通道的数据，其中一些指针可以为 null
numDestChannelsdestChannels 数组中的数组元素数量
startSampleInSource在音频文件或流中读取采样的位置，以距流起始位置的采样数表示。超出可用数据起点或终点范围也没关系——任何超出范围的采样都将以零返回。
numSamplesToRead要读取的采样数。如果该值大于文件或流所包含的采样数，结果将用零填充
fillLeftoverChannelsWithCopies如果为 true，表示当你传入的某些通道没有可用源数据时，应使用有效源通道的副本填充它们。例如，如果你正在读取单声道文件并向此方法传入 2 个通道，那么当 fillLeftoverChannelsWithCopies 为 true 时，两个目标通道都将填充该文件单一通道的相同数据。如果 fillLeftoverChannelsWithCopies 为 false，则只有第一个通道会填充文件内容，第二个通道将被清零。如果通道很多，例如你尝试从立体声文件中读取 4 个通道，那么最后 3 个通道最终都会得到同一数据的副本。
返回
操作成功返回 true，出错则返回 false。注意，读取超出流范围的数据段不算错误——读取器只需为这些区域返回零

searchForLevel()

int64 juce::AudioFormatReader::searchForLevel (int64 startSample, int64 numSamplesToSearch, double magnitudeRangeMinimum, double magnitudeRangeMaximum, int minimumConsecutiveSamples)

扫描源，查找幅度处于指定范围内的采样。

这会从源中向前或向后读取两个采样位置之间的数据，直到找到一个幅度位于两个指定电平之间的采样。

如果找到合适的采样，则返回其位置；否则返回 -1。

还有一个 minimumConsecutiveSamples 设置，可在搜索连续采样范围时帮助避开尖峰或过零点

参数
startSample要查看的第一个采样
numSamplesToSearch要扫描的采样数。如果该值为负数，搜索将向后进行
magnitudeRangeMinimum被视为命中的最低幅度（含），从 0 到 1.0
magnitudeRangeMaximum被视为命中的最高幅度（含），从 0 到 1.0
minimumConsecutiveSamples如果该值 > 0，方法将只查找这样一段连续采样：其数量为指定值，且全部位于目标范围内。找到这样一段序列时，返回它找到的第一个在范围内采样的位置（即向前扫描时最早的那个，向后扫描时最晚的那个）
