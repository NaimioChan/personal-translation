juce::ResizableBorderComponent 类参考

详细说明

拖动时会调整其父组件尺寸的组件。

此组件在组件边缘形成边框，允许通过拖动边缘或角来调整其尺寸——就像在 MSWindows 或 Linux 中调整窗口大小一样。

要使用它，只需将其添加到组件中，使其填满整个父组件（有一个鼠标命中测试只捕获落在组件边缘附近的鼠标事件，因此甚至可以把它放在你使用的任何其他组件之上）。请确保在父组件尺寸每次变化时重新缩放 resizer 组件以填满父组件。

paint()

void juce::ResizableBorderComponent::paint (Graphics & g) override protected virtual

组件可以重写此方法以绘制其内容。

当组件的某个区域需要重绘时会调用 paint() 方法，原因可能是组件的 repaint() 方法被调用，或者屏幕上发生了某些情况导致窗口的某一部分需要重绘。

任何子组件都会绘制在此方法绘制的内容之上。如果你需要绘制在子组件上方，也可以实现 paintOverChildren() 方法来实现。

如果你想让组件重绘自身，这是异步完成的——调用 repaint() 方法会将组件的某个区域标记为“脏”，稍后消息线程会自动调用 paint() 方法来绘制任何需要刷新的部分。在 JUCE（以及几乎所有现代界面框架）中，你永远不会同步重绘。

你应该永远不需要直接调用此方法——要对组件进行快照，可以使用 createComponentSnapshot() 或 paintEntireComponent()。

参数
g执行绘制操作时必须使用的图形上下文。

hitTest()

bool juce::ResizableBorderComponent::hitTest (int x, int y) override protected virtual

测试给定点是否位于组件内。

重写此方法可以让你创建只在用户定义区域内拦截鼠标点击的组件。

调用此方法以查明特定 x、y 坐标是否被视为在组件内部，contains() 和 getComponentAt() 等方法用它来确定鼠标点击在哪个组件上。

具有自定义形状的组件可能想重写它来执行更复杂的命中测试。

此方法的默认实现返回 'client' 或 'none'，取决于通过调用 setInterceptsMouseClicks() 设置的值（'client' 是默认返回值）。

注意，命中测试区域与组件各区域绘制的不透明度无关。

应用程序绝不应直接调用 hitTest() —— 而应使用 contains() 方法，因为它还会检测父组件的遮挡。

注意，对于桌面上的组件，此方法将被忽略，因为并非在所有平台上都能实现此行为。

参数
x要测试的 x 坐标，相对于此组件的左边缘。该值保证大于或等于零，且小于组件宽度
y要测试的 y 坐标，相对于此组件的上边缘。该值保证大于或等于零，且小于组件高度
返回
如果点击被视为在组件内部则为 true
另见
setInterceptsMouseClicks, contains
