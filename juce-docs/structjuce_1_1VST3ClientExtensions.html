juce::VST3ClientExtensions 结构体参考

详细说明

允许 AudioProcessor 实现扩展的 VST3 特定功能的接口。

要使用此类，请创建一个继承自它的对象，实现这些方法，然后在你的 AudioProcessor::getVST3ClientExtensions() 方法中返回指向该对象的指针。

另见
AudioProcessor, AAXClientExtensions, VST2ClientExtensions

getPluginHasMainInput()

virtual bool juce::VST3ClientExtensions::getPluginHasMainInput () const inline virtual

将调用此函数以检查第一个输入总线应指定为 "kMain" 还是 "kAux"。

如果第一个总线应为 kMain，则返回 true；如果该总线应为 kAux，则返回 false。

所有其他输入总线将始终指定为 kAux。

getCompatibleParameterIds()

virtual std::map< uint32_t, String > juce::VST3ClientExtensions::getCompatibleParameterIds (const VST3Interface::Id & compatibleClass) const virtual

此函数应返回 VST3 参数 ID 与它们所映射到的 JUCE 参数之间的映射。

此信息用于实现 IRemapParamID 接口。当会话是使用具有不同参数 ID 的兼容插件保存时，宿主可以用它来保留自动化数据。

并非所有宿主都会考虑此信息。因此，参数 ID 应在插件版本之间保持不变。对于从 VST2 迁移到 VST3 的 JUCE 插件，实现这一点的最佳方法是启用 JUCE_FORCE_LEGACY_PARAM_IDS。但是，如果插件已经在未启用此标志的情况下发布，则此方法提供了一种不会造成进一步兼容性问题的替代方案。

映射中的键是一个整数，可以表示 VST3 参数标识符（Vst::ParamID）或 VST2 参数索引。你应为兼容插件中的每个参数 ID 都包含一个映射条目。对于 VST2 或 JUCE 插件，这些 ID 可以通过以下方式确定。

  • 如果满足以下任一条件，请使用参数索引：
    • InterfaceId 参数指向兼容的 VST2 插件，或
    • InterfaceId 参数指向启用了 JUCE_FORCE_LEGACY_PARAM_IDS 的 JUCE VST3 插件，或
    • InterfaceId 参数指向 JUCE 插件，但兼容插件中的参数不继承自 HostedAudioProcessorParameter（这种情况不太可能）。
  • 否则，对于禁用了 JUCE_FORCE_LEGACY_PARAM_IDS 且兼容参数派生自 HostedAudioProcessorParameter 的 JUCE VST3 插件，请使用 convertJuceParameterId()。
  • 对于非 JUCE 的 VST3，请使用兼容 VST3 导出的 Vst::ParamID。

映射中的值是要映射到的参数的 JUCE 参数 ID，或空字符串表示没有要映射到的参数。如果参数不继承自 HostedAudioProcessorParameter，则其 ID 将是参数字符串形式的索引，例如 "1"。否则，始终使用实际参数 ID（即使启用了 JUCE_FORCE_LEGACY_PARAM_IDS）。

在极不可能的情况下，如果两个插件共享相同的插件 ID，且两者都有共享相同参数 ID 的不同参数，则可能可以在 setStateInformation() 期间确定正在加载哪个版本的插件。此方法将始终在 setStateInformation() 之后调用，以便在查询时提供具有正确映射的映射表。

以下示例展示了在启用 JUCE_VST3_CAN_REPLACE_VST2 但禁用 JUCE_FORCE_LEGACY_PARAM_IDS 的 JUCE VST3 插件中，你可以如何实现此函数。

std::map<uint32_t, String> getCompatibleParameterIds (const InterfaceId&) const override
{
 return { { 0, "Frequency" },
             { 1, "CutOff" },
             { 2, "Gain" },
             { 3, "Bypass" } };
}
参数
compatibleClass插件标识符，可以是当前插件的标识符，也可以是 JUCE_VST3_COMPATIBLE_CLASSES 中列出的某个插件的标识符。此参数允许实现为每个兼容类返回不同的参数映射。使用 VST3Interface::jucePluginId() 和 VST3Interface::vst2PluginId() 确定 JUCE 插件使用的类 ID。设置 JUCE_VST3_CAN_REPLACE_VST2 时，表示插件 VST2 版本的 ID 将与其替代的 VST3 的 ID 匹配。在这种情况下，假设 VST2 参数索引与 VST3 ParamID 之间没有冲突，你应仅在返回的映射中包含 VST2 映射。在极不可能发生冲突的情况下，你应检查最近传给 setStateInformation() 的状态，以确定宿主是否正在加载需要参数重映射的 VST2 状态。如果你确定不需要重映射，可以返回空映射来表示这一点。
返回
一个映射，其中每个键是兼容插件中的 VST3 参数 ID，值是当前插件中应映射到的唯一 JUCE 参数 ID。

convertJuceParameterId()

uint32_t juce::VST3ClientExtensions::convertJuceParameterId (const String & parameterId, bool studioOneCompatible = true) static

返回针对给定 JUCE 参数所报告的 VST3 兼容参数 ID。

在内部，JUCE 将使用此方法确定 HostedAudioProcessorParameter 的 Vst::ParamID，除非启用了 JUCE_FORCE_LEGACY_PARAM_IDS，此时它将使用参数索引。
