juce::Typeface 类参考

详细说明

typeface 表示一种与尺寸无关的字体。

此基类是抽象的，但调用 createSystemTypefaceFor() 会返回一个可用的平台相关子类。

通常你永远不需要直接处理 Typeface 对象——Font 类已经完成了渲染文本通常需要的一切。

成员枚举

ColourGlyphFormat

enum juce::Typeface::ColourGlyphFormat

特定 typeface 可能实现的彩色字形格式种类。

大多数 typeface 是单色的，不支持任何彩色格式。Emoji 字体通常会实现一种或多种彩色字体格式。

目前 JUCE 只能渲染位图和 COLRv0 字体。如果你允许用户自定义字体，可能希望隐藏或以其他方式阻止用户选择使用不受支持彩色格式的字体。

枚举值
colourGlyphFormatBitmap 

该 typeface 包含以位图（通常是 PNG）表示的字形。

colourGlyphFormatSvg 

该 typeface 包含以 SVG 表示的字形。

colourGlyphFormatCOLRv0 

该 typeface 使用 COLRv0 格式，支持纯色。

colourGlyphFormatCOLRv1 

该 typeface 使用 COLRv1 格式，支持渐变和混合模式。

getColourGlyphFormats()

int juce::Typeface::getColourGlyphFormats () const

返回一个 int，其置位表示该 typeface 中包含的彩色字形格式。

如果该 typeface 没有彩色字形，则不会置位任何位。否则会按彩色字形信息的格式置位一个或多个位。你可以用 ColourGlyphFormat 枚举的成员做按位与运算，来判断是否支持某种特定格式。

const auto isMonochrome   = typeface->getColourGlyphFormats() == 0;
const auto isSvg          = (typeface->getColourGlyphFormats() & Typeface::colourGlyphFormatSvg) != 0;
const auto isSimpleColour = (typeface->getColourGlyphFormats() & (Typeface::colourGlyphFormatBitmap | Typeface::colourGlyphFormatCOLRv0)) != 0;

createSystemFallback()

virtual Typeface::Ptr juce::Typeface::createSystemFallback (const String & text, const String & language) const pure virtual

尝试找到一个风格相似、且能够显示所请求字符串的字体。

这使用系统设施，因此结果会因操作系统和已安装字体而异。如果你的应用必须在所有平台上使用相同的字体，那你大概不应使用此函数的结果。

注意，它接受 string 而不是单个码位，因为操作系统在选择合适的字体时可能考虑组合标记和变体选择符。举例来说，许多字体都包含笑脸 emoji 的 'text'/'outline' 版本。在 macOS 上，如果只传入笑脸 emoji 的码位，可能返回 Helvetica；但如果在 emoji 码位后跟随 variation-selector-16 码位，则会返回 emoji 字体。

要指定你自己的回退字体：

  • 确保你首选的字体覆盖你可能需要显示的所有语言/文字/码位
  • 把字体打包到你的产品中，例如作为二进制数据，并在产品启动时注册它们
  • 使用 Font::setPreferredFallbackFamilies() 来指定在向系统请求回退字体之前应先使用打包的字体
参数
text返回的字体通常能够显示此字符串中的大多数码位
language包含此码位的文本的 BCP 47 语言代码
返回
如果无法创建回退字体，则为 nullptr

cloneWithVariableSettings()

virtual Typeface::Ptr juce::Typeface::cloneWithVariableSettings (Span < const FontVariableSetting > settings) const nodiscard pure virtual

创建并返回此 typeface 的副本，并按指定的可变字体设置对其进行配置。

可变字体（也称为 OpenType Font Variations）允许单个字体文件在一个或多个轴上包含多种设计变体，例如字重、宽度、倾斜、光学尺寸以及字体设计师定义的自定义轴。此方法创建一个新的 typeface 实例，并应用指定的轴值。应用于原始 typeface 的任何可变设置在返回的实例中都会被替换。

此方法不检查也不缓存 typeface，用相同设置调用两次会返回两个不同的指针。

参数
settings要应用的可变设置，用于配置新的 typeface 实例。
返回
一个唯一的 Typeface::Ptr；如果此 typeface 不是可变 typeface，则为 nullptr。
另见
getSupportedVariables, getRangeForVariable, getDefaultValueForVariable

findSystemTypeface()

Typeface::Ptr juce::Typeface::findSystemTypeface () static

返回系统的默认 UI 字体。

这会因平台而异。

在 Linux/fontconfig 上，它返回映射到名称 "system-ui" 的 typeface，如果不存在此类字体则返回 nullptr。

在 Windows 上，它使用键 SPI_GETNONCLIENTMETRICS 查询 SystemParametersInfo，并返回得到的 lfMessageFont；如果找不到该字体则返回 nullptr。

在 macOS 和 iOS 上，它返回对 kCTFontUIFontSystem 类型调用 CTFontCreateUIFontForLanguage() 的结果。

在 Android 29+ 上，它会使用 AFontMatcher 返回 "system-ui" 字体。在更早的 Android 版本上，它会尝试返回 Roboto 字体。

注意：系统 typeface 的度量可能与 JUCE 通常选作默认字体的 sans-serif 字体的度量有很大差异。这在 Windows 上尤其明显：对于 Segoe UI（Windows 的系统 typeface），ascender 与 descender 之和略大于字体的 em 尺寸；而对于 Verdana（JUCE 在 Windows 上的默认 sans-serif 字体），ascender 与 descender 之和更接近 em 尺寸。当通过 FontOptions::withHeight() 或 Font::setHeight() 设置字体大小时，JUCE 会根据 ascender 与 descender 之和来缩放字体，因此切换到 Segoe UI 可能导致文本渲染出来的尺寸比使用 Verdana 时小得多。使用 FontOptions::withFontHeight() 和 Font::setPointHeight() 以点为单位设置字体大小，可能会得到更好的结果。使用点时，Segoe UI 渲染出来仍比 Verdana 略小，但差异没那么明显。

getNamedInstanceConfiguration() [1/2]

Span < const FontVariableSetting > juce::Typeface::getNamedInstanceConfiguration (StringRef instanceName) const & nodiscard

返回特定命名实例的可变字体轴设置。

许多可变字体包含预定义的命名实例，代表常见的设计变体，例如 "Bold"、"Light"、"Condensed" 等。每个命名实例是一组轴值，它们共同定义一种特定风格。

Named 实例提供了一种便捷方式来访问常用的变体，而无需了解具体的轴值。
