juce::ChildProcessCoordinator 类参考

详细说明

在协调器/工作器成对的已连接进程中充当协调器。

ChildProcessWorker 和 ChildProcessCoordinator 类使应用可以轻松创建子进程，并管理双向消息连接来控制它。

要使用该系统，你需要创建 ChildProcessWorker 和 ChildProcessCoordinator 的子类。当你希望协调器进程启动工作器时，只需调用 launchWorkerProcess()，它将尝试启动你指定的可执行文件（可能是同一个 exe），并假设它已设置为正确解析命令行参数（见 ChildProcessWorker），则会创建双向连接。

juce 演示应用中有该类实际运行的良好示例。

launchWorkerProcess()

bool juce::ChildProcessCoordinator::launchWorkerProcess (const File & executableToLaunch, const String & commandLineUniqueID, int timeoutMs = 0, int streamFlags = ChildProcess::wantStdOut | ChildProcess::wantStdErr)

尝试启动并连接到工作器进程。

这将启动给定的可执行文件，并基于 commandLineUniqueID 字符串向它传递一个特殊的命令行参数；该字符串必须是标识你的应用的简短字母数字字符串（不能有空格！）。被启动的 exe 必须在其启动代码中调用 ChildProcessWorker::initialiseFromCommandLine() 作为响应，并且必须使用与 commandLineUniqueID 匹配的 ID。

timeoutMs 参数让你指定子进程在不发送 ping 的情况下可以持续多久，之后即认为它已死亡，并将调用 handleConnectionLost()。将该超时设为 <= 0 将使用默认值。

如果这一切都正常，该方法返回 true，你就可以开始与工作器进程收发消息。

如果子进程已在运行，这将调用 killWorkerProcess() 并启动一个新的。

引用了 juce::ChildProcess::wantStdErr、juce::ChildProcess::wantStdOut。

被以下对象引用： launchSlaveProcess()。
