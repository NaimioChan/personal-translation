juce::InterprocessConnection 类参考

详细说明

管理到另一个进程的简单双向消息连接，使用套接字或命名管道作为传输介质。

要连接到正在等待的套接字或已打开的管道，请使用 connectToSocket() 或 connectToPipe() 方法。如果成功，就可以向另一端发送消息，传入消息将导致通过 messageReceived() 方法回调。

要打开管道并等待另一个客户端连接到它，请使用 createPipe() 方法。

要作为套接字服务器并为某个或多个客户端创建连接，请参见 InterprocessConnectionServer 类。

重要说明：你的派生 Connection 类must在其析构函数中调用 disconnect，以便在类销毁之前取消任何待处理的消息。

另见
InterprocessConnectionServer、Socket、NamedPipe

InterprocessConnection()

juce::InterprocessConnection::InterprocessConnection (bool callbacksOnMessageThread = true, uint32 magicMessageHeaderNumber = 0xf2b49e2c)

创建一个连接。

连接是手动创建的，通过 connectToSocket() 或 connectToPipe() 方法连接；或者当客户端想要连接时，由 InterprocessConnectionServer 自动创建。

参数
callbacksOnMessageThread如果为 true，对 connectionMade()、connectionLost() 和 messageReceived() 方法的回调将始终使用消息线程；如果为 false，这些回调将立即在连接自身的线程上调用。
magicMessageHeaderNumber用于在头部中检查所收发数据块有效性的魔数。可以是任何数字，但发送方和接收方显然必须使用匹配的值，否则它们无法识别彼此。

connectToPipe()

bool juce::InterprocessConnection::connectToPipe (const String & pipeName, int pipeReceiveMessageTimeoutMs)

尝试将该对象连接到现有的命名管道。

为此，同一台计算机上的另一个进程必须已经打开了 InterprocessConnection 对象并使用 createPipe() 创建了一个管道供其连接。

参数
pipeName管道使用的名称——应为你的应用独有
pipeReceiveMessageTimeoutMs读写管道时使用的超时时长，或 -1 表示无限超时。
返回
如果连接成功，则为 true。

createPipe()

bool juce::InterprocessConnection::createPipe (const String & pipeName, int pipeReceiveMessageTimeoutMs, bool mustNotExist = false)

尝试创建一个新管道供其他进程连接。

这将创建具有给定名称的管道，以便其他进程可以使用 connectToPipe() 连接到另一端。

参数
pipeName管道使用的名称——应为你的应用独有
pipeReceiveMessageTimeoutMs读写管道时使用的超时时长，或 -1 表示无限超时
mustNotExist如果设为 true，当管道已存在时该方法将失败
返回
如果管道已创建则为 true，如果失败则为 false（例如另一个进程已在使用该管道）
