juce::ARADocumentControllerSpecialisation 类参考

详细说明

此类包含 JUCE 提供的 ARA 文档控制器实现的自定义点。

每个启用 ARA 的插件都必须提供自己的文档控制器实现。为此，请从此类继承，并按需重写其受保护的方法。然后你需要在模块的某处实现一个名为 createARAFactory() 的全局函数。该函数必须返回一个 ARAFactory*，它会使用你的特化来实例化文档控制器对象。ARADocumentControllerSpecialisation 中有辅助函数，因此 createARAFactory() 的实现始终可以是一行简单的代码。例如

class MyDocumentController : public ARADocumentControllerSpecialisation
{
 //...
};

const ARA::ARAFactory* JUCE_CALLTYPE createARAFactory()
{
 return juce::ARADocumentControllerSpecialisation::createARAFactory<MyDocumentController>();
}

大多数成员函数都有默认实现，因此你可以逐步构建所需的功能集。此类的受保护函数分为三个不同的组：

  • 交互式编辑与播放，
  • 由插件提供、供宿主使用的分析功能，以及
  • 维护 ARA 模型图。

除了纯虚函数之外，如果你希望插件能发出任何声音，至少应重写 doCreatePlaybackRenderer()。此函数属于第一组。

如果你的插件具备分析能力并希望允许宿主访问这些能力，则应重写第二组中的函数。

ARA 模型对象类的默认实现——即 ARADocument、ARAMusicalContext、ARARegionSequence、ARAAudioSource、ARAAudioModification、ARAPlaybackRegion——应足以维护 ARA 模型图的表示，因此重写模型对象创建函数（例如 doCreateMusicalContext()）被视为高级用法。因此，无需重写第三组中的函数，你也能完成很多工作。

为了对各种 ARA 状态变化做出反应，你可以重写 ARADocumentControllerSpecialisation 继承的任何 ARA 模型对象监听器函数。此类监听器函数可以附加到某个特定的模型对象实例，但 ARADocumentControllerSpecialisation 中的监听器函数会响应所有模型对象实例的事件。
