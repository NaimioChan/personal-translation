juce::MPESynthesiserBase 结构体参考

详细说明

从此类派生，可创建一个支持 MPE 的基本音频发生器。

实现 MPEInstrument::Listener 的回调（noteAdded、notePressureChanged 等），让你的音频发生器知道 MPE 音符被触发、调制或释放。在这些回调中做什么，以及它如何影响你的音频发生器，完全由你决定！

该类在内部使用一个 MPEInstrument 实例来处理 MPE 音符状态逻辑。

该类是 MPE 乐器的非常底层的基类。如果你需要更完善的功能，请看 MPESynthesiser。该类通过添加可演奏音符的声部概念、声部抢占算法以及更多内容来扩展 MPESynthesiserBase。

renderNextBlock()

template<typename floatType> void juce::MPESynthesiserBase::renderNextBlock (AudioBuffer < floatType > & outputAudio, const MidiBuffer & inputMidi, int startSample, int numSamples)

创建下一块音频输出。

调用此方法即可发声。它会将 AudioBuffer 按 MIDI 缓冲区中的事件切分成多个 subBlock 片段，然后对每个片段调用 renderNextSubBlock。其间你会收到 noteAdded/Changed/Finished 调用，你可以在那里更新音频渲染所依赖的音符参数。

参数

inputMidi要处理的 MIDI 事件
startSample两个缓冲区中要处理的第一个采样
numSamples要处理的采样数

handleMidiEvent()

virtual void juce::MPESynthesiserBase::handleMidiEvent (const MidiMessage &) virtual

处理传入的 MIDI 事件（由 renderNextBlock 调用）。

此处提供的默认实现只是把所有内容转发给 MPEInstrument::processNextMidiEvent，在那里用于更新 MPE 音符、区域等。与 MPE 无关的 MIDI 消息会被忽略。

如果你需要在 MPE 之上做自定义 MIDI 处理，可以重写此方法。MPESynthesiser 类重写它以实现对 MIDI 程序变更和非 MPE 相关 MIDI 控制器消息的回调。

在以下类中重新实现： juce::MPESynthesiser。

setMinimumRenderingSubdivisionSize()

void juce::MPESynthesiserBase::setMinimumRenderingSubdivisionSize (int numSamples, bool shouldBeStrict = false) noexcept

设置渲染时音频子块可被划分的最小尺寸限制。

渲染时，传入 renderNextBlock() 的音频块会被切分为位于所有传入 MIDI 消息之间的更小块，正是这些更小的子块通过多次调用 renderVoices() 来渲染。

显然，在每个采样上都有 MIDI 消息的极端情况下，renderVoices() 可能每个采样被调用一次，导致性能很差，因此此设置允许你为块大小设置下限。

默认设置为 32，这意味着 MIDI 消息的精度约为 < 1ms，对大多数用途来说应该够了，但你可能想为你的合成器增大或减小该值。

如果 shouldBeStrict 为 true，音频子块将严格永远不会小于 numSamples。

如果 shouldBeStrict 为 false（默认），则允许缓冲区中的第一个音频子块更小，以确保缓冲区中的第一个 MIDI 事件始终是采样精确的（这有时有助于避免量化或相位问题）。

参数
