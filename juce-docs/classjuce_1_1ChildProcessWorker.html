juce::ChildProcessWorker 类参考

详细说明

在协调器/工作器成对的已连接进程中充当工作器端。

ChildProcessWorker 和 ChildProcessCoordinator 类使应用可以轻松创建子进程，并管理双向消息连接来控制它。

要使用该系统，你需要创建 ChildProcessWorker 和 ChildProcessCoordinator 的子类。要实例化 ChildProcessWorker 对象，你必须在 main() 或 JUCEApplication::initialise() 函数中添加一些代码，调用 initialiseFromCommandLine() 方法检查应用的命令行参数，以确定它是否正作为子进程被启动。如果返回 true，则允许工作器进程运行，并且每当有消息到达时会调用其 handleMessageFromCoordinator() 方法。

juce 演示应用中有该类实际运行的良好示例。

成员函数

initialiseFromCommandLine()

bool juce::ChildProcessWorker::initialiseFromCommandLine (const String & commandLine, const String & commandLineUniqueID, int timeoutMs = 0)

这会检查一些命令行参数，看它们是否由 ChildProcessCoordinator::launchWorkerProcess() 生成，如果是，则连接到该协调器进程。

在可作为子进程使用的 exe 中，你应在 main() 或 JUCEApplication::initialise() 中添加一些代码来调用该方法。

commandLineUniqueID 应为简短的字母数字标识符（不能有空格！），并与传给 ChildProcessCoordinator::launchWorkerProcess() 的字符串匹配。

timeoutMs 参数让你指定子进程在未收到协调器 ping 的情况下可以运行多久，之后即认为协调器已死亡，并将调用 handleConnectionLost()。将该超时设为 <= 0 将使用默认值。

如果命令行匹配且连接成功建立，则返回 true。

handleMessageFromCoordinator()

virtual void juce::ChildProcessWorker::handleMessageFromCoordinator (const MemoryBlock & mb) virtual

将调用此方法来投递来自协调器进程的消息。

该调用很可能在后台线程上进行，所以要注意线程安全！你可能想通过 sendMessageToCoordinator() 回发消息来响应

handleConnectionLost()

virtual void juce::ChildProcessWorker::handleConnectionLost () virtual

当与协调器进程的连接丢失时，将调用此方法。

该调用可能来自任何线程（包括消息线程）。通常，如果你的进程只是作为工作器存在，那么在此发生时你可能应该退出。

sendMessageToCoordinator()

bool juce::ChildProcessWorker::sendMessageToCoordinator (const MemoryBlock &)

尝试向协调器进程发送消息。

如果消息已发送，则返回 true，但不会检查它是否真的在另一端被投递。如果成功，数据将出现在对你的 ChildProcessCoordinator::handleMessageFromWorker() 的调用中。
