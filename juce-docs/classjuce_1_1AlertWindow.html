juce::AlertWindow 类参考

详细说明

显示消息并带有按钮供用户响应的窗口。

对于只有几个按钮的简单对话框，有一些用于运行它们的静态方法。

对于更复杂的对话框，可以创建一个 AlertWindow，然后向其中添加按钮和组件，并用其 enterModalState() 方法显示它。返回给 ModalComponentManager::Callback 的值表示用户按下了哪个按钮来关闭该框。

另见
ThreadWithProgressWindow, Component::enterModalState

如果未定义 JUCE_MODAL_LOOPS_PERMITTED，或 callback 参数非空，此函数将立即返回。作为 callback 参数传入的对象会异步收到警告窗口的结果。否则，如果定义了 JUCE_MODAL_LOOPS_PERMITTED 且 callback 参数为空，该框以模态方式显示，方法会阻塞直到用户点击按钮（或按下 escape 或 return 键）。这种操作方式可能引发问题，尤其是在插件中，因此不推荐使用。

message在标题下方显示的更长、更具描述性的消息

button2Text第二个按钮中要显示的文本 —— 如果该字符串为空，将使用默认字符串 "cancel"（或其本地化版本）。

createAccessibilityHandler()

std::unique_ptr< AccessibilityHandler > juce::AlertWindow::createAccessibilityHandler () override virtual

重写此方法可为该组件返回自定义的 AccessibilityHandler。

默认实现创建并返回一个角色未指定的 AccessibilityHandler 对象，这意味着它对无障碍客户端可见，但没有特定角色、操作回调或接口。要控制无障碍客户端如何查看和交互你的组件子类 AccessibilityHandler，请实现所需行为，并在组件子类中从此方法返回它的实例。

你在此处返回的无障碍处理器保证在其 Component 之前被销毁，因此如有必要，在 AccessibilityHandler 中保存并使用指回 Component 的引用是安全的。

此函数很少应被直接调用。如果你需要查询组件的无障碍处理器，通常最好调用 getAccessibilityHandler()。此规则的例外是 createAccessibilityHandler() 的派生实现，它们可能会发现调用基类实现、然后包装或修改结果很有用。

另见
getAccessibilityHandler

paint()

void juce::AlertWindow::paint (Graphics & g) override protected virtual

组件可以重写此方法以绘制其内容。

当组件的某个区域需要重绘时会调用 paint() 方法，原因可能是组件的 repaint() 方法被调用，或者屏幕上发生了某些情况导致窗口的某一部分需要重绘。

任何子组件都会绘制在此方法绘制的内容之上。如果你需要绘制在子组件上方，也可以实现 paintOverChildren() 方法来实现。

如果你想让组件重绘自身，这是异步完成的——调用 repaint() 方法会将组件的某个区域标记为“脏”，稍后消息线程会自动调用 paint() 方法来绘制任何需要刷新的部分。在 JUCE（以及几乎所有现代界面框架）中，你永远不会同步重绘。

你应该永远不需要直接调用此方法——要对组件进行快照，可以使用 createComponentSnapshot() 或 paintEntireComponent()。

参数
g执行绘制操作时必须使用的图形上下文。
另见
repaint, paintOverChildren, Graphics

keyPressed()

bool juce::AlertWindow::keyPressed (const KeyPress & key) override protected virtual

按下按键时调用。

当某个键被按下时，拥有键盘焦点的组件将调用此方法。请记住，只有使用组件的 setWantsKeyboardFocus() 方法启用后，组件才会获得焦点。

如果你的实现返回 true，事件将被消费，不会传递给任何其他监听器。如果返回 false，该键将传递给向此组件注册的任何 KeyListener。一旦其中一个返回 true，过程就会停止；但如果它们全部返回 false，事件将向上传递给此组件的父组件，依此类推。

此方法的默认实现什么都不做并返回 false。
