juce::ApplicationCommandManager 类参考

详细说明

其中一个对象持有应用可执行的所有命令的列表，并在需要时分发这些命令。

应用程序命令是触发应用中操作的好方法，例如 "Quit"、"Copy"、"Paste" 等。菜单、按钮和按键都可以被赋予命令以自动调用，这意味着你不必手动处理菜单或按钮点击的结果。命令被分发给 ApplicationCommandTarget 对象，由它们选择要处理哪些事件。

这种架构还允许嵌套的 ApplicationCommandTargets，例如你可以有两个不同的对象，一个在另一个内部，二者都能响应 "delete" 命令。根据哪个拥有焦点，命令将被发送到合适的位置，无论它是由菜单、按键还是其他方式触发的。

要设置应用以使用命令，你需要执行以下操作：

  • 创建一个全局的 ApplicationCommandManager 来保存所有可能命令的列表。（它还会为这些命令管理一组键映射）。
  • 让你的某些 UI 组件（或其他对象）继承自 ApplicationCommandTarget。这允许该对象提供它能执行的命令列表并处理它们。
  • 使用 ApplicationCommandManager::registerAllCommandsForTarget() 或 ApplicationCommandManager::registerCommand() 注册每种命令。
  • 如果你希望按键触发命令，请使用 ApplicationCommandManager::getKeyMappings() 方法访问键映射器对象，你需要在所使用的任何顶层组件中将其注册为按键监听器。有关设置的更多帮助，请参阅 KeyPressMappingSet 类。
  • 使用 PopupMenu::addCommandItem() 或 Button::setCommandToTrigger() 等方法使这些命令被自动调用。
  • 你的代码可以使用 ApplicationCommandManager::invokeDirectly() 直接调用命令。

当命令被调用时，ApplicationCommandManager 会尝试选择最佳的 ApplicationCommandTarget 来接收指定命令。为此，它会利用当前键盘焦点查看哪个组件可能感兴趣，并在组件层次结构中搜索那些还实现了 ApplicationCommandTarget 接口的组件。如果某个 ApplicationCommandTarget 对正在调用的命令不感兴趣，就会尝试链上的下一个（参见 ApplicationCommandTarget::getNextCommandTarget() 方法），依此类推，直到 ApplicationCommandTarget::getNextCommandTarget() 返回 nullptr。此时如果命令仍未被执行，它会被传递给当前的 JUCEApplication 对象（它本身就是一个 ApplicationCommandTarget）。

要对选择哪个 ApplicationCommandTarget 来调用命令施加自定义控制，你可以重写 ApplicationCommandManager::getFirstCommandTarget() 方法并自行选择对象。

commandStatusChanged()

void juce::ApplicationCommandManager::commandStatusChanged ()

应调用此方法以告知管理器，其某个已注册命令的激活状态可能已改变。

由于命令管理器只能通过查询当前 ApplicationCommandTarget 来了解命令是激活还是非激活，此方法用于告知它情况可能已改变。它使按钮等能够更新其启用状态等。

此方法会对任何已注册的监听器异步调用 ApplicationCommandManagerListener::applicationCommandListChanged()。

invoke()

bool juce::ApplicationCommandManager::invoke (const ApplicationCommandTarget::InvocationInfo & invocationInfo, bool asynchronously)

将命令发送给默认目标。

这会使用 getFirstCommandTarget() 选择目标，并使用 ApplicationCommandTarget::invoke() 方法将指定命令发送给它。这意味着如果第一个目标无法处理该命令，它会被传递给链上更靠后的目标（更多信息参见 ApplicationCommandTarget::invoke()）。

参数
invocationInfo必须正确填写，描述调用的上下文。
asynchronously如果为 false，命令将在此方法返回前执行。如果为 true，则发布一条消息，使命令稍后在消息线程上执行，此方法立即返回。

getFirstCommandTarget()

virtual ApplicationCommandTarget * juce::ApplicationCommandManager::getFirstCommandTarget (CommandID commandID) virtual

选择命令应发送到的 ApplicationCommandTarget。

每当管理器需要知道命令应发送到哪个目标时，它会调用此方法来确定第一个要尝试的目标。

默认情况下，此方法返回通过调用 setFirstCommandTarget() 设置的目标。如果未设置目标，则返回 findDefaultComponentTarget() 的结果。

如果你需要确保所有命令都经由自己的自定义目标，可以使用 setFirstCommandTarget() 指定单个目标，或者在需要更复杂的选择逻辑时重写此方法。

如果没有可用目标，可能返回 nullptr。

另见
getTargetForCommand, invoke, invokeDirectly

setFirstCommandTarget()

void juce::ApplicationCommandManager::setFirstCommandTarget (ApplicationCommandTarget * newTarget) noexcept

getTargetForCommand()

ApplicationCommandTarget * juce::ApplicationCommandManager::getTargetForCommand (CommandID commandID, ApplicationCommandInfo & upToDateInfo)

尝试找到用于执行给定命令的最佳目标。

这会调用 getFirstCommandTarget() 查找首选目标，并检查该目标能否处理给定命令。如果不能，则使用 ApplicationCommandTarget::getNextCommandTarget() 查找下一个要尝试的目标，依此类推，直到没有可用目标。

如果找不到能执行该命令的目标，此方法将返回 nullptr。

如果找到目标，则会让该目标填充 upToDateInfo 结构，包含该命令的最新信息，以便调用者了解命令是否被禁用、是否勾选等。
