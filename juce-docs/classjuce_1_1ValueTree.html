详细说明

一个功能强大的树结构，可用于保存自由形式的数据，并能自行处理撤销和重做行为。

ValueTree 包含以 var 对象形式存在的命名属性列表，还包含任意数量的子树。

在栈上创建 ValueTree 对象，不要害怕复制它们，因为它们只是对共享数据容器的轻量引用。创建另一个 ValueTree 的副本只是创建对同一底层对象的新引用——要制作树的独立深拷贝，你应显式调用 createCopy()。

每个 ValueTree 都有一个类型名称，这与 XmlElement 有标签名的方式非常相似，且 ValueTree 的结构很大部分与 XmlElement 树类似。你可以在 ValueTree 与 XmlElement 之间相互转换，只要 XML 不含文本元素，转换就能良好进行，是一种很好的序列化格式。它们也可以序列化为二进制格式，速度非常快且紧凑。

所有更改数据的方法都接受一个可选的 UndoManager，用于跟踪对对象的任何更改。为此，你必须小心地始终对树内任何子树的所有操作使用同一个 UndoManager。

ValueTree 同一时间只能是一个父级的子级，因此如果你要将其从一棵树移到另一棵树，务必在添加之前先将其移除。这也可能打乱你的撤销/重做链，所以要小心！在调试构建中，如果你尝试做任何危险操作，应该会触发断言，但仍有很多方式可能出错。

注意，虽然树中的子级有固定顺序，但属性不保证以任何特定顺序存储，因此不要期望属性的索引会对应属性的添加顺序，也不要期望在其他属性添加或移除时它保持不变。

可以向 ValueTree 添加监听器，以便在属性更改以及子树添加或移除时收到通知。

    },
    { "Group", {{ "name", "Other Controls" }},
      {
        { "Parameter", {{ "id", "drywet" }, { "value", 0.5 }}},

  }

addListener()

void juce::ValueTree::addListener (Listener * listener)

添加监听器，在此树以某种方式更改时接收回调。

监听器添加到此特定的 ValueTree 对象，而不是它所引用的共享对象。当此对象被删除时，所有监听器都会丢失，即使对同一 ValueTree 的其他引用仍然存在。如果你使用 operator= 使此对象引用不同的 ValueTree，任何监听器将改为监听新树的更改，而不再监听旧树。

添加监听器时，请确保将其添加到在你需要监听器期间一直存在的 ValueTree 实例上。一般来说，你绝不会想把监听器添加到局部的、基于栈的 ValueTree 上，而通常会添加到成员变量上。

sort()

template<typename ElementComparator> void juce::ValueTree::sort (ElementComparator & comparator, UndoManager * undoManager, bool retainOrderOfEquivalentItems) inline

此方法使用比较器对象对树的子级进行排序。

所提供的对象必须具有以下形式的方法：

int compareElements (const ValueTree& first, const ValueTree& second);

……并且此方法必须返回：

  • 如果第一个先于第二个，则返回值 < 0
  • 如果两个对象等价，则返回值 0
  • 如果第二个先于第一个，则返回值 > 0

为提高性能，compareElements() 方法可以声明为 static 或 const。

参数
comparator用于比较元素的比较器。
undoManager用于存储更改的可选 UndoManager
retainOrderOfEquivalentItems如果为 true，则比较器认为等价的项将保持它们当前在数组中出现的顺序。这执行起来较慢，但在某些情况下可能很重要。如果为 false，则使用更快的算法，但等价元素可能被重排。
