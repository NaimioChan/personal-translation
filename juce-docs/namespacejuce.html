自动解锁并重新锁定 CriticalSection 对象。

这与 ScopedLock 对象相反——它不在对象生命期内锁定临界区，而是将其解锁。

 // ...and now unlocked...
            }

        }

    }
};

当你需要遍历某个范围，同时还要查询每个项在范围中的位置时，这很有用。

一个简单的用法可能如下所示：

std::list<int> elements { 10, 20, 30, 40, 50 };

for (const auto pair : enumerate (elements))
    std::cout << pair.index << ' ' << pair.value << ' ';

// output: 0 10 1 20 2 30 3 40 4 50

你也可以使用结构化绑定来简洁地解构每个 Enumerated 实例：

for (const auto [index, value] : enumerate (elements))
    std::cout << index << ' ' << value << ' ';

注意，Enumerated 实例是按值返回的。这是因为每个 Enumerated 实例都是在解引用迭代器时按需创建的。因此，下面这种写法会产生悬垂引用，并且很可能会触发编译器警告：

// BAD IDEA: creating a reference to a temporary Enumerated instance
for (auto& [index, value] : enumerate (elements))
    ...

Enumerated 的 'value' 成员会自动采用与被包装迭代器解引用相同的类型，通常是对容器中元素的引用。在下面的代码片段中，'[index, value]' 的类型是 'const Enumerated<ptrdiff_t, int&>'，'index' 的类型是 'ptrdiff_t'，'value' 的类型是 'int&'。

std::vector<int> elements { 10, 20, 30, 40, 50 };
for (const auto [index, value] : enumerate (elements))
    ...

默认情况下，pair.value 的常量性会与传给 enumerate 的范围的常量性一致。如果你向 enumerate 传入可变的左值引用，那么每个值也是可变的。如果你向 enumerate 传入常量左值引用，那么每个值都是 const 的。如果你知道不需要遍历的元素可变，最好在传给 enumerate 之前用 std::as_const 包装该范围：

for (const auto [index, value] : enumerate (std::as_const (elements)))
{
 // value is immutable here
}
