juce::HighResolutionTimer 类参考

详细说明

高精度周期定时器。

这提供精确定时的规律回调。与普通 Timer 类不同，它使用专用线程而非消息线程，因此更稳定、更精确。

你只应在确实需要精度的场合使用此类，因为与非常轻量、开销低的普通 Timer 类不同，HighResolutionTimer 将使用多得多的资源，并且需要考虑线程安全。

成员函数

hiResTimerCallback()

virtual void juce::HighResolutionTimer::hiResTimerCallback () pure virtual

实际会被定期调用的用户自定义回调例程。

这将在专用定时器线程上被调用，因此务必确保你的实现是线程安全的！

在某些平台上，专用定时器线程可能与其他 HighResolutionTimer 共享，因此尽量尽快完成此回调中的任何工作。

在此回调中调用 startTimer() 或 stopTimer() 来更改后续间隔是完全可以的。不过，如果你在回调中调用 stopTimer()，仍最好在析构函数中调用 stopTimer()，以避免数据竞争。

startTimer()

void juce::HighResolutionTimer::startTimer (int intervalInMilliseconds)

启动定时器并设置所需间隔长度。

如果定时器已启动，这将重置定时器，因此调用此方法与下一次定时器回调之间的时间将不少于传入的间隔长度。

在异常情况下，专用定时器线程可能不会启动，如果这对你的用例是潜在问题，你可以调用 isTimerRunning() 确认定时器是否实际启动。

在 Windows 上，底层 API 只允许同一进程中同时运行 16 个高精度定时器。超过此限制时将使用后备定时器，但精度可能显著降低。这对插件尤其重要，因为同一宿主进程中的其他插件可能已有定时器在运行。为避免问题，尽量使用最少的高精度定时器。例如，考虑使用 SharedResourcePointer，以便同一进程中运行的同一插件的所有实例共享单个 HighResolutionTimer 实例。

参数
intervalInMilliseconds要使用的间隔（零或更小的值将停止定时器）

stopTimer()

void juce::HighResolutionTimer::stopTimer ()

停止定时器。

此方法可能阻塞，等待待处理的回调完成。一旦返回，将不再有回调。如果从定时器自身线程调用它，它将在当前回调返回后取消定时器。

为防止数据竞争，通常最好在派生类的析构函数中调用此方法，即使在 hiResTimerCallback() 中已调用了 stopTimer()。
