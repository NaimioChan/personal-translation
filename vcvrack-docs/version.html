版本管理

ABI（应用二进制接口）是一份机器可读的符号清单（函数、全局变量和类），计算机只能以特定方式调用、访问和使用它们。 API（应用编程接口）由 C 和 C++ 头文件（.h/.hpp）组成，它们定义了编译器可以如何使用该 ABI。

版本字符串的结构为 vMAJOR.MINOR.REVISION，大致遵循语义化版本标准。

Rack 可以视为供插件使用的库。应用语义化版本，这意味着：

  • Rack 的主版本更新会带来不兼容的插件 API 与 ABI 变更。
  • Rack 的次版本更新会向插件 API 与 ABI 添加（但不删除或修改）符号，使 Rack 对针对较旧次版本 Rack 编译的插件保持向后兼容，但对针对较新次版本 Rack 编译的插件不向前兼容。建议用户在更新插件之前先更新 Rack，以确保所有插件都能加载。
  • Rack 的修订版本更新不修改符号，只以兼容的方式改变功能并修复 bug。

Rack 插件可以视为链接到 Rack 库的应用程序。这意味着：

  • 插件的主版本必须与 Rack 的主版本匹配，才能被 Rack 加载。要让插件可用于新的 Rack 主版本，必须更新插件源码并针对新的 Rack SDK 重新编译。
  • 插件的次版本更新意味着添加了新功能或新模块。
  • 插件的修订版本更新意味着修复了 bug 或调整了现有行为。

对用户来说最重要的一点是：Rack 只会加载主版本（vX.*）与之匹配的插件。

Git 分支与标签

在 Rack 的 git 仓库中，每个主版本都有自己的分支，标记为 v1、v2 等。

没有 master 分支。 GitHub 上的默认分支是 vcvrack.com 上列出的 Rack 最新发布版的主版本。 要更新源码树的主版本，只需检出它的分支。 除非你知道如何完整清理带子模块的 git 树，否则不建议通过检出分支来升级 Rack 的主版本。

当 Rack 的任何版本发布时，该构建的提交会用其完整版本名打上标签（例如 v1.0.0）。 不过，这只用于提供信息。 不支持从分支的“分离头指针”（detached heads）构建，因为自发布日期过去一段时间后，依赖 URL 及其他问题可能需要修复。
