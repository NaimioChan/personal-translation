数字信号处理

数字信号处理（DSP）是关于在时间与空间上对连续信号进行离散化的数学与编程领域。 它的众多应用之一是从虚拟/数字模块化合成器生成并处理音频。

信号

信号是定义在时间连续统上的幅度（电压、声压级等）的函数 x(t):R→Rx(t): \mathbb{R} \rightarrow \mathbb{R}，而序列是仅定义在整数点上的函数 x(n):Z→Rx(n): \mathbb{Z} \rightarrow \mathbb{R}，通常写作 xnx_n。 换言之，信号是具有无限时间细节的无限长数值连续统，而序列是时间上等间距孤立点处样本的无限长流。

模拟硬件产生并处理信号，而数字算法处理样本序列（通常称为数字信号）。

傅里叶分析

在 DSP 中你经常会遇到以频率 ff 重复的周期信号，比如循环波形。 周期信号由多个谐波（平移的余弦波）组成，其频率为 fkfk，其中 k=1,2,3,…k = 1, 2, 3, \ldots。 事实上，一个周期信号可以由其所有谐波的幅度和相位定义。 为简化起见，若 x(t)x(t) 是周期为 f=1f=1 的周期信号，则 x(t)=A0+∑k=1∞Akcos⁡(2πkt+ϕk)x(t) = A_0 + \sum_{k=1}^\infty A_k \cos \left( 2\pi k t + \phi_k \right) 其中 A0A_0 是直流分量（信号相对零点的平均偏移），AkA_k 是谐波 kk 的幅度，ϕk\phi_k 是其角相位。 求和中的每一项都是简谐信号，叠加起来即可重建原信号。

事实证明，不仅周期信号，所有信号都有唯一的平移余弦分解。 不过，此时不是整数谐波，而必须考虑所有频率 ff；不是离散求和，而必须对实数频率的所有平移余弦积分。 此外，把幅度和相位合并为单个复值分量 X(f)=A(f)eiϕ(f)X(f) = A(f) e^{i \phi(f)} 更为方便。 经过这些修改，分解变为 x(t)=∫−∞∞X(f)e2πitfdfx(t) = \int_{-\infty}^\infty X(f) e^{2\pi i t f} df X(f)X(f) 分量可用下式计算 X(f)=∫−∞∞x(t)e−2πitfdtX(f) = \int_{-\infty}^\infty x(t) e^{-2\pi i t f} dt 这被称为傅里叶变换。

对于周期为 NN 的数字周期信号，无法表示高于 N/2N/2 的谐波，因此其分解被截断。 xk=∑n=0N/2Xne2πikn/Nx_k = \sum_{n=0}^{N/2} X_n e^{2\pi i kn / N} 其逆变换为 Xn=∑k=0Nxke−2πikn/NX_n = \sum_{k=0}^{N} x_k e^{-2\pi i kn / N} 由于序列 xkx_k 为实值，各分量 XnX_n 关于 N/2N/2 共轭对称，即 Xn=XN−n∗X_n = X_{N-n}^\ast，因此我们有 N/2+1N/2 + 1 个唯一的谐波分量。 这就是（实数）离散傅里叶变换（DFT）。

快速傅里叶变换（FFT）是一种令人惊讶的方法：它使用递归的动态规划算法，计算 NN 个样本块的 DFT 只需 O(Nlog⁡N)O(N \log N) 步而非 DFT 的 O(N2)O(N^2) 步，同时比朴素求和具有更好的数值稳定性。 这使得 DFT 在处理样本块时能够用于高性能 DSP。 块尺寸越大，每样本所需的平均步数越少。 FFT 算法存在于许多库中，比如 VCV Rack 自身使用的 pffft。

采样

奈奎斯特–香农采样定理指出，不含高于采样率一半 fsrf_{sr} 的频率成分的信号，可以被采样并重建而不丢失信息。 换言之，如果你对信号进行带限（用在 fsr/2f_{sr}/2 处的砖墙低通滤波器），并在 fsrf_{sr} 处采样点，那么就能通过寻找唯一一条经过所有点且不含高于 fsr/2f_{sr}/2 的频率成分的信号来重建该带限信号。

在实践中，模数转换器（ADC）会施加一个近似的砖墙低通滤波器，以从信号中去除高于 fsr/2f_{sr}/2 的频率。 信号在采样时间 1/fsr1/f_{sr} 的一小部分内被积分，以获得某一时间点幅度的近似值，该测量值被量化到最接近的数字值。

数模转换器（DAC）将数字值转换为幅度，并在采样时间的一小部分内保持该值。 随后施加重建滤波器，产生接近原始带限信号的信号。 高质量的 ADC 可能在重建之前包含数字上采样。 也可以使用抖动，但对于高于 16 的位深来说大多没有必要。

当然，这些步骤中的每一步也可能引入噪声。 幸运的是，现代 DAC 和 ADC 每片仅需 2-5 美元，就能以超出人类辨识范围的程度对信号进行数字化和重建，其信噪比（SNR）和总谐波失真（THD）低于 -90dBr。

混叠

奈奎斯特–香农采样定理要求原始信号在数字化之前在 fsr/2f_{sr}/2 处带限。 如果不是这样，重建将得到完全不同的信号，这通常听起来刺耳，并与低质量 DSP 相关联。

考虑红色的高频正弦波。 如果每整数点采样一次，其唯一的重建是蓝色的信号，它与原信号的谐波内容完全不同。 如果正确地进行了带限，原信号应当为零（静音），因此重建结果也应当为零。

由带限不连续性产生的曲线被称为吉布斯现象。 试图对锯齿波或方波中的跳变建模的 DSP 算法必须包含这一效应，例如为每个不连续点插入 minBLEP 或 polyBLEP 信号。 否则，更高次谐波——如上文的高频正弦波——将污染 fsr/2f_{sr}/2 以下的频谱。

即使是不含不连续点的信号，比如谐波幅度为 (−1)k/k2(-1)^k / k^2 的三角波，也必须正确地带限，否则会发生混叠。 一种可行的方法是利用三角波是积分后的方波，而积分器不过是一个具有每十倍频 -20dB 斜率的滤波器。 由于线性滤波器可交换，带限的积分方波就是积分后的带限方波。

最通用的方法是在高采样率下生成样本，施加 FIR 或多相滤波器，再按整数因子降采样（即抽取）。

对于更具体的应用，某些情形下存在更先进的技术。 许多处理过程都需要抗混叠，包括波形生成、波形整形、失真、饱和，以及通常所有的非线性处理。 而对混响、线性滤波器、正弦信号在音频速率下的 FM（这正是 80 年代原始数字芯片能够听起来相当不错的原因）、信号相加以及大多数其他线性处理，则有时不需要。

线性滤波器

线性滤波器是一种根据信号频率成分施加增益的运算，定义为 Y(s)=H(s)X(s)Y(s) = H(s) X(s) 其中 s=iωs = i \omega 是复角频率，XX 和 YY 分别是输入信号 x(t)x(t) 和输出信号 y(t)y(t) 的拉普拉斯变换，而 H(s)H(s) 是滤波器的传递函数，定义了它的特性。 注意这里不使用傅里叶变换，因为需要考虑时间因果性，即我们并不知道信号的未来。 该滤波器之所以是“线性”的，是因为两个信号之和经过滤波的结果等于两个信号分别滤波后之和。

H(iω)H(i \omega) 的对数-对数图称为波特图。

为了能够利用各种数学工具，传递函数通常写成关于 s−1s^{-1} 的有理函数 H(s)=∑p=0Pbps−p∑q=0Qaqs−qH(s) = \frac{\sum_{p=0}^P b_p s^{-p}}{\sum_{q=0}^Q a_q s^{-q}} 其中 aqa_q 和 bpb_p 称为模拟滤波器系数。 只要分子和分母多项式的阶数 PP 和 QQ 足够高，你就能逼近合成中见到的大多数线性模拟滤波器。

要在数字上实现一个传递函数，可将 zz 定义为把样本 xnx_n 变换为其后一个样本的算子，即 xn+1=z[xn]x_{n+1} = z[x_n]。 我们实际上可以把它写成一个关于 ss 和采样时间 T=1/fsrT = 1/f_{sr} 的变量。 （考虑角频率为 ω\omega 的正弦波。zz 算子对其相位的平移，相当于延迟 TT 时间。） z=esTz = e^{sT}

它的一阶近似是 z=esT/2e−sT/2≈1+sT/21−sT/2z = \frac{e^{sT/2}}{e^{-sT/2}} \approx \frac{1 + sT/2}{1 - sT/2} 其逆为 s=1Tln⁡z≈2T1−z−11+z−1s = \frac{1}{T} \ln{z} \approx \frac{2}{T} \frac{1 - z^{-1}}{1 + z^{-1}}

这被称为双线性变换。 在数字形式下，有理传递函数写为 H(z)=∑n=0Nbnz−n∑m=0Mamz−mH(z) = \frac{\sum_{n=0}^N b_n z^{-n}}{\sum_{m=0}^M a_m z^{-m}} 注意阶数 NN 和 MM 未必等于模拟形式的阶数 PP 和 QQ，我们得到一组新的数 ama_m 和 bnb_n，称为数字滤波器系数。

滤波器的零点是使分子为零的非零 zz 值，极点是使分母为零的非零 zz 值。 一个线性滤波器是稳定的（其冲激响应收敛到 0），当且仅当所有极点严格位于复平面单位圆内，即 ∣z∣<1|z| < 1。

IIR 滤波器

无限冲激响应（IIR）滤波器是一种实现所有可能有理传递函数的数字滤波器。 将上文有理 H(z)H(z) 定义的分母在两边相乘，并作用于输入 xkx_k 和输出 yky_k，我们得到差分关系 ∑m=0Mamyk−m=∑n=0Nbnxk−n\sum_{m=0}^M a_m y_{k-m} = \sum_{n=0}^N b_n x_{k-n} 通常将 a0a_0 归一化为 1，于是 yky_k 可以显式写出。 yk=∑n=0Nbnxk−n−∑m=1Mamyk−my_k = \sum_{n=0}^N b_n x_{k-n} - \sum_{m=1}^M a_m y_{k-m} 这一迭代过程可以对每个样本进行计算

当 N,M=2N, M = 2 时，这就是双二阶滤波器，它非常快、数值稳定（假设传递函数本身数学上稳定），而且音质相当不错。

FIR 滤波器

有限冲激响应（FIR）滤波器是 IIR 滤波器在 M=0M = 0 时的特例（传递函数分母为 1）。对于输入和输出信号，差分关系为 yk=∑n=0Nbnxk−ny_k = \sum_{n=0}^N b_n x_{k-n} 它们在计算上直截了当，并且由于没有极点而总是稳定的。

长 FIR 滤波器（N≥128N \geq 128），比如 FIR 混响（是的，它们就是线性滤波器），可以通过 FFT 来优化。 注意上式是向量 yy 与 bb 的卷积，而根据卷积定理， y∗b=F−1{F{y}⋅F{b}}y \ast b = \mathcal{F}^{-1} \{ \mathcal{F}\{y\} \cdot \mathcal{F}\{b\} \} 其中 ⋅\cdot 表示逐元素相乘。

上文的朴素 FIR 公式每样本需要 O(N)O(N) 次计算，而 FFT FIR 方法在处理样本块时每样本平均只需 O(log⁡N)O(\log N) 次计算（块长为 NN 个样本）。 FFT FIR 方法的一个缺点是，在能够确定任何输出之前，信号必须延迟 NN 个样本。 你可以用重叠相加或重叠保留方法把朴素方法与 FFT 方法结合成混合方案，从而处理尺寸为 M<NM < N 的较小块，代价是每样本平均计算量略差，为 O((N/M)log⁡M)O((N/M) \log M)。

冲激响应

有时我们需要模拟非有理传递函数。 考虑一般的传递函数 H(f)H(f)，为简单起见写成关于 ff 而非 ss 的形式。 我们最初对输入 x(t)x(t) 和输出 y(t)y(t) 的传递函数定义是 Y(f)=H(f)X(f)Y(f) = H(f) X(f) 再次应用卷积定理，得到 y(t)=(h∗x)(t)=∫−∞∞h(τ)x(t−τ)dτy(t) = (h \ast x)(t) = \int_{-\infty}^\infty h(\tau) x(t - \tau) d\tau 其中 h(t)h(t) 是我们滤波器的冲激响应。

信号 h(t)h(t) 是δ 函数经过我们滤波器的结果，因为 δ(t)\delta(t) 是卷积的“单位”函数，即 h(t)=(h∗δ)(t)h(t) = (h \ast \delta)(t)。 在大教堂中拍手或挤破气球（两者都是 δ\delta 的良好近似）会产生非常复杂的冲激响应，它可以被记录为 h(t)h(t)，并在 FIR 滤波器算法中处理，从而重现任意声音，仿佛它们是在那座大教堂中演奏的。

电路建模

虽然并不直接属于 DSP 领域，但模拟电路建模对于用数字算法模拟模拟信号处理器的声音和行为是必要的。 电路建模算法不是评估某一信号处理概念的理论模型，而是模拟物理电子器件（其本身可能就是为了近似某个信号处理概念而构建的）的电压状态。 电路的每个元件都可以按期望的细节程度（无论多粗或多细）来建模，当然要在复杂度和计算时间上做权衡。

在尝试对电路建模之前，最好先画出原理图并理解它在模拟域中如何工作。 这样你就能轻松地略去电路中那些对声音特性毫无贡献、却会给建模过程增加不必要工作的大片部分。

常微分方程的数值方法

常微分方程（ODE）系统是形如下的向量方程 x⃗′(t)=f(t,x⃗).\vec{x}'(t) = f(t, \vec{x}). 像 x′′(t)=−x(t)x''(t) = -x(t) 这样的高阶 ODE 可以通过定义中间变量如 x1=x′x_1 = x' 并写成如下形式来支持

[xx1]′(t)=[x1−x]. \begin{bmatrix} x \\ x_1 \end{bmatrix}'(t) = \begin{bmatrix} x_1 \\ -x \end{bmatrix}.

数值方法的研究处理这一一般系统的计算求解。 尽管这是一个庞大的领域，但由于 CPU 的严格限制以及对解精度的宽容，音频合成通常只需学到基础即可。

最简单的计算方法是前向欧拉法。 若状态 x⃗\vec{x} 在时刻 tt 已知，而你想近似未来时刻 Δt\Delta t 的状态，令 x⃗(t+Δt)→x⃗(t)+Δtf(t,x⃗).\vec{x}(t + \Delta t) \rightarrow \vec{x}(t) + \Delta t f(t, \vec{x}). 迭代这一近似即可获得更多点。 它是一阶方法，因此误差与 Δt\Delta t 成正比。 龙格-库塔方法是常用的高阶近似，代价是每个时间步需要多计算 f⃗(t,x⃗)\vec{f}(t, \vec{x}) 次。 例如，四阶 RK4 方法的误差与 (Δt)4(\Delta t)^4 成正比，因此相比前向欧拉法，在更小的时间步下误差会显著降低。

优化

在代码中实现一个想法之后，你可能发现它的运行时间太高，减少了可同时运行的实例数量，或增加了 CPU 占用和笔记本电脑风扇转速。 有几种方法可以提升代码的性能，下面按重要性排序列出。

性能剖析

缺乏经验的程序员通常在写代码时就花大量时间关注其性能。 这被称为过早优化，可能使开发时间成倍增加。 事实上， “过早优化是编程中一切邪恶（或至少大部分邪恶）的根源”——Donald Knuth，作为艺术的计算机编程（1974）。

我要再提出一个论断：无论程序多么复杂，通常都存在一个单一的、很小的瓶颈。 它可能是 FFT，也可能是对 sin() 这类超越函数的求值。 如果某个瓶颈占总运行时间的 90%，那么优化其他代码最多只能带来 10% 的运行时间缩减。 我的建议是优化瓶颈，其他一概不管。

即使是顶尖的编程专家，也很难猜出代码的哪一部分是瓶颈，因为由于编译器优化和硬件实现的极端复杂性，结果可能完全出人意料。 你必须对代码进行性能剖析才能正确回答这个问题。

可用的剖析器有很多。

  • Linux 上的 perf。用 perf record --call-graph dwarf -o perf.data ./myprogram 启动。
  • Hotspot 用于可视化 perf 输出，它本身不是剖析器。
  • gperftools
  • gprof
  • Valgrind 用于内存、缓存、分支预测和调用图剖析。

测得的剖析数据可以用你喜欢的剖析可视化软件生成火焰图来查看。 每个方块代表调用树中的一个函数，其宽度与该函数的运行时间成正比，因此你可以很容易地发现瓶颈。

数学优化

如果代码的瓶颈是某个数学概念的求值，那么仅仅换用另一种数学方法，就可能获得 10,000 倍甚至更高的巨大加速。 如果彻底更换方法不可行（也许你已经在用已知最好的算法），仍然可以通过一套技巧获得加速。

  • 把频繁重复求值的值存入变量，使其只求值一次。
  • 把代价高的函数移到查找表中。
  • 用多项式或有理函数近似函数，使用秦九韶法（Horner 法）、Estrin 方案和/或帕德近似。
  • 重排嵌套的 for 循环，以“转置”算法。

记住，在任何可能提升性能的改动前后都要对代码进行性能剖析，否则很容易自欺欺人地认为某种方法更快。

向量指令

2000 年，AMD 发布了 AMD64 处理器指令集，提供 64 位宽寄存器以及对现有 x86 指令集的若干扩展。 Intel 随后在 2004 年于代号 Nocona 的 Xeon 多核处理器系列中采用了该指令集，并称之为 Intel 64。 现在大多数人称这一架构为 x86_64，或者含义略显含糊的“64 位”。

这一架构最重要的新增内容是单指令多数据（SIMD）扩展，它允许把多个值放入一个寄存器向量中，并以与处理单个值相近的周期数进行处理（求和、相乘等）。 由于晶体管尺寸已接近极限，时钟频率的提升正在放缓（目前桌面 CPU 约为 3GHz），这些扩展对于对抗这一趋势是必要的；因此未能利用这些特性可能会让你的代码以 2004 年以前的速度运行。 以下是几个重要的扩展及其首次引入 CPU 的日期。

  • MMX（1996）用于处理最多 64 位的打包整数。
  • SSE（1999）用于处理最多 128 位的打包浮点数和整数。
  • SSE2（2001）扩展 SSE 功能并完全取代 MMX。
  • SSE3（2004）略微扩展 SSE2 功能。
  • SSE4（2006）扩展 SSE3 功能。
  • AVX（2008）用于处理最多 256 位的浮点数。
  • FMA（2011）用于对最多 256 位的浮点数计算 ab+cab+c。
  • AVX-512（2015）用于处理最多 512 位的浮点数。

你可以通过 Intel Intrinsics Guide，或者完整的 Intel 软件开发手册和 AMD 编程参考，查看这些扩展提供了哪些指令。

幸运的是，在 GCC/Clang 上使用 -march=nehalem 或 -march=native 这类选项时，只要代码的写法允许向量化，编译器就能发出优化指令来利用一组允许的扩展。 如果优化后的代码不令人满意，而你想自己编写这些指令，请参阅 GCC 手册中的 x86 内建函数。 记住，你目标的一部分 CPU 可能不支持 SSE4 或 AVX 这类现代扩展，因此可以在运行时用 GCC 的 __builtin_cpu_supports 检查支持情况，必要时分支到回退实现。 通常更倾向于对指令使用更通用的 _mm_add_ps 之类函数名，而不是 GCC 的 __builtin_ia32_addps 之类名称，因此 GCC 提供了一个头文件 x86intrin.h 来提供这些别名。
