模块配置

用 config(numParams, numInputs, numOutputs, numLights) 配置好 Module 子类之后，就可以在 Module 的构造函数中配置每个组件的标签与行为。

输入、输出与灯

用 configInput()、configOutput() 和 configLight() 为输入、输出和灯的提示框添加标签。 例如：

configInput(PITCH_INPUT, "Pitch (1V/octave)");
configOutput(SINE_OUTPUT, "Sine");
configLight(PHASE_LIGHT, "Phase");

提示框会自动追加 "input"、"output" 和 "light" 字样，因此不要在标签字符串中包含它们。

灯的提示框通常没有必要，因此建议仅在灯的含义不明显时才添加。

参数

configParam() 方法设置参数的范围、默认值、标签、单位和显示刻度。 以下是几个示例。

// 旋钮：最小值（拧到最左）为 0，最大值（拧到最右）为 1，默认（初始）值为 0.5。
configParam(SIMPLE_PARAM, 0.f, 1.f, 0.5f, "Simple");

// 单位标签，用于在提示框中显示 "10 V" 或 "0 V" 这样的字符串。
// 建议在前面加一个空格，把数字与单位分开。
configParam(OFFSET_PARAM, -10.f, 10.f, 0.f, "Offset", " V");

// 把显示值乘以 100，并追加百分号。
configParam(PERCENT_PARAM, -1.f, 1.f, 0.f, "Percent", "%", 0.f, 100.f);

// 在值为 0 时显示 "261.62 Hz"，即中央 C。
// 1V/倍频程使用以 2 为底的指数。
configParam(PITCH_PARAM, -5.f, 5.f, 0.f, "Pitch (1V/octave)", " Hz", 2, dsp::FREQ_C4);

// 值 0 显示 "-inf dB"，值 2 显示 "6.02 dB"，值 1 为默认的 "0 dB"。
// 使用以 10 为底的对数（用 -10 编码），乘数为 20 dB。
configParam(GAIN_PARAM, 0.f, 2.f, 1.f, "Gain", " dB", -10, 20);

configSwitch() 方法适用于为每个值显示标签的多模式开关。 用户可以通过右键单击开关直接选择每个选项。

// 三档开关（取值 0 到 2），默认 "Hi-fi"。
configSwitch(QUALITY_PARAM, 0.f, 2.f, 0.f, "Quality", {"Hi-fi", "Mid-fi", "Lo-fi"});

configButton() 与 configSwitch() 类似，但没有标签，范围为 0 到 1，默认值为 0。 这适用于瞬态开关。

configButton(GATE_PARAM, "Gate");

如果需要在提示框中传达额外信息，可以选择为任意组件添加一行描述。

getParamQuantity(SEND_PARAM)->description = "Pre-fader";
getOutputInfo(PINK_NOISE_OUTPUT)->description = "-3 dB/octave power density";

旁通

用户可以通过模块的上下文菜单或快捷键旁通模块，这会禁用模块的 DSP 处理，并可选择将某些输入直接路由到某些输出，就像在它们之间接上了跳线。 你（模块开发者）可以用 configBypass() 配置这些旁通路由。

只有当模块对输入信号施加效果并将其传递到输出时，才应为端口配置旁通路由。 例如：

  • 音频输入 → 低通滤波器输出
  • CV 输入 → 反相 CV 输出
  • 门信号输入 → 延迟门信号输出

以下路由在旁通时则不适用：

  • 音高 CV 输入 → 正弦音频输出。信号类型不相关，用户也不想听音高 CV 信号。
  • 通道 1 输入 → 混音器输出。混音器不是效果器，用户很可能想静音混音器输出，而不是将所有通道单位增益混合。
  • 时钟输入 → 音序器触发输出。用户很可能想静音所有触发输出，而不是每个时钟步都产生一个触发。

除这些例子外，旁通路由可能带有主观性，因此请考虑用户最期望、最不意外的旁通行为。

以下示例在模块被旁通时，将两个立体声输入分别路由到对应的立体声输出。

configBypass(LEFT_INPUT, LEFT_OUTPUT);
configBypass(RIGHT_INPUT, RIGHT_OUTPUT);

覆写 processBypass() 可以实现更复杂的旁通路由，它与 process() 相同，但在模块被旁通时调用。

为扩展上述示例，你可能想实现左到右归一化，而这无法用 configBypass() 实现。

struct MyModule : Module {
	...

	void processBypass(const ProcessArgs& args) override {
		// 注意：不支持复音
		float left = getInput(LEFT_INPUT).getVoltage();
		// 若右输入未连接，则把左输入路由到右输出
		float right = getInput(RIGHT_INPUT).isConnected() ? getInput(RIGHT_INPUT).getVoltage() : left;
		getOutput(LEFT_OUTPUT).setVoltage(left);
		getOutput(RIGHT_OUTPUT).setVoltage(right);
	}
};

模块事件

有时你需要处理模块上发生的特定事件，例如用户重置或随机化模块，或引擎采样率发生变化。 覆写相应的 Module::on*() 方法，并记得调用父类的方法，除非你想替换其默认行为。 例如：

struct MyModule : Module {
	...

	void onReset(const ResetEvent& e) override {
		// 重置所有参数
		Module::onReset(e);
		// 重置自定义状态变量
		...
	}

	void onRandomize(const ResetEvent& e) override {
		// 随机化所有参数
		Module::onRandomize(e);

		// 或者删掉上面这行，自己随机化参数。
		params[MY_PARAM].setValue(random::uniform());

		// 随机化自定义状态变量
		...
	}

	void onSampleRateChange(const SampleRateChangeEvent& e) override {
		Module::onSampleRateChange(e);
		// 更改自定义状态变量的采样率
		...
	}
};

线程安全说明：尽管事件、process() 以及 dataToJson()/dataFromJson() 等 Module 方法可能由不同线程调用，但它们是互斥的，即 Rack 从不会同时从多个线程调用任何 Module 方法。

数据序列化

当用户关闭 VCV Rack 或保存 patch 时，所有模块的状态都会保存到文件。 Rack 会自动保存所有参数（如旋钮、滑块和开关）的值，但如果你在 Module 实例变量中存储额外的状态数据，就必须自己编写代码来保存/加载这些数据。

JSON

通过在 Module 子类中覆写 dataToJson() 和 dataFromJson() 方法，可以在 JSON 对象中存储和读取自定义数据。 例如，如果你的模块使用 int mode 实例变量，以下代码可以保存/加载它。

struct MyModule : Module {
	...

	json_t* dataToJson() override {
		json_t* rootJ = json_object();
		json_object_set_new(rootJ, "mode", json_integer(mode));
		return rootJ;
	}

	void dataFromJson(json_t* rootJ) override {
		json_t* modeJ = json_object_get(rootJ, "mode");
		if (modeJ)
			mode = json_integer_value(modeJ);
	}
};

使用 Jansson 库，JSON 可以存储/读取多种 C++ 数据类型：

  • bool：json_boolean() / json_boolean_value()
  • const char*：json_string() / json_string_value()
  • int64_t：json_integer() / json_integer_value()
  • double：json_real() / json_number_value() 注意：不推荐使用 json_real_value()，因为它无法解析整数值。
  • 数组：json_array() 和 json_array_set_new() / json_array_foreach()
  • 以字符串为键的对象：json_object() 和 json_object_set_new() / json_object_foreach()

Patch 存储

如果你的模块需要保存/加载大量数据（约 >100 kB），JSON 序列化在自动保存时（默认每 15 秒）可能会阻塞主线程。 为解决这个问题，模块实例可以请求拥有自己的按 patch 存储目录，在其中创建任意大小的文件（甚至数 GB 的录音），并随时读写。 当用户保存 patch 时，VCV Rack 会将所有模块的 patch 存储压缩到单个 .vcv 文件中。

模块可以用 createPatchStorageDirectory() 方法创建其 patch 存储目录，并使用返回值构建文件路径。 通常只需在保存 patch 或模块添加到机架时保存/加载文件。 例如：

struct MyModule : Module {
	...

	void onAdd(const AddEvent& e) override {
		std::string path = system::join(getPatchStorageDirectory(), "recording.wav");
		// 从文件加载。如果模块刚创建，文件可能并不存在。
		...
	}

	void onSave(const SaveEvent& e) override {
		std::string path = system::join(createPatchStorageDirectory(), "recording.wav");
		// 保存到文件。
		...
	}
};

可以在 Module::process() 中访问 patch 文件，但这样做可能阻塞 DSP 线程，导致音频卡顿。 建议只在模块事件方法或自己的 worker 线程中访问它们。

插件设置

如果你的插件需要保存/加载插件级数据（如设置），可以在 plugin.cpp 文件中实现 settingsToJson() 和 settingsFromJson()。 该 JSON 对象存储在 <Rack user folder>/settings.json 中，并在退出时以及定期（默认每 15 秒）自动保存。

例如，要保存 int theme 全局变量，将以下代码添加到 plugin.cpp 的根作用域。

json_t* settingsToJson() {
	json_t* rootJ = json_object();
	json_object_set_new(rootJ, "theme", json_integer(theme));
	return rootJ;
}

void settingsFromJson(json_t* rootJ) {
	json_t* themeJ = json_object_get(rootJ, "theme");
	if (themeJ)
		theme = json_integer_value(themeJ);
}

上下文菜单

当用户右键单击模块面板时，会弹出上下文菜单，包含 "Initialize"、"Randomize"、"Delete" 等熟悉操作。 你可以在末尾添加自定义菜单项，以提供面板上没有的设置。

要将菜单项追加到模块的上下文菜单，请覆写 ModuleWidget::appendContextMenu()。 用 create*() 辅助函数创建具体的菜单项，并用 menu->addChild() 将它们添加到菜单。

以下代码示例演示了可追加到模块上下文菜单的大多数菜单项类型。 要在菜单项被点击或展开时运行自定义代码，请使用按值捕获变量的 lambda：[=]() {...}。

struct MyModuleWidget : ModuleWidget {
	...

	void appendContextMenu(Menu* menu) override {
		MyModule* module = getModule<MyModule>();

		menu->addChild(new MenuSeparator);

		menu->addChild(createMenuLabel("Editor settings"));

		menu->addChild(createMenuItem("Load sample", "kick.wav",
			[=]() {
				module->loadSample();
			}
		));

		// 控制 bool 型的 Module::loop
		menu->addChild(createBoolPtrMenuItem("Loop", "", &module->loop));

		menu->addChild(createSubmenuItem("Edit", "",
			[=](Menu* menu) {
				menu->addChild(createMenuItem("Copy", "", [=]() {copy();}));
				menu->addChild(createMenuItem("Paste", "", [=]() {paste();}));
			}
		));

		// 控制 int 型的 Module::mode
		menu->addChild(createIndexPtrSubmenuItem("Mode",
			{"Hi-fi", "Mid-fi", "Lo-fi"},
			&module->mode
		));
	}
};

建议先添加一个 MenuSeparator，以便在视觉上将自定义菜单项与常见菜单项分开。

扩展模块

一些 Eurorack 硬件模块可以通过面板后的总线电缆与相邻模块通信。 这可用于通过额外的端口和参数扩展模块的功能。

同样，在 VCV Rack 中，模块可以直接与紧贴其左侧或右侧的模块通信。 例如，Grayscale Permutation 可以将其门信息发送给 Grayscale Variant 以生成 CV 信号（如图）。

要从主 Module 访问相邻模块，必须检查其是否存在及其型号。 确认后，就可以在主模块中实现其完整的 DSP 算法。 在此例中，当 MyExpander 模块与主模块右侧相接时，我们访问它。

Module* rightModule = getRightExpander().module;
if (rightModule && rightModule->getModel() == modelMyExpander) {
	// 现在可以确定 rightModule 就是 MyExpander。
	// 我们可以处理它的参数、端口和灯。
	float in = rightModule->getInput(MyExpander::AUDIO_INPUT).getVoltage();
	float gain = rightModule->getParam(MyExpander::GAIN_PARAM).getValue();
	rightModule->getOutput(MyExpander::AUDIO_OUTPUT).setVoltage(in * gain);
}

扩展模块可以覆写 onExpanderChange()，在断开连接时清除其输出和灯。

消息

你可能更希望 MyExpander 拥有自己独立的 process() 方法。 然而，如果任一模块试图直接访问另一模块的实例变量，其 process() 调用可能发生在另一模块 process() 调用之前、之后或期间（若启用多线程）。 这可能导致延迟不一致（0 或 1 个引擎帧）或读取到损坏的数据。

解决方案是使用扩展模块"消息"，它是二进制数据的双缓冲。 这确保数据始终以 1 个引擎帧的延迟共享。

要从主模块向扩展模块发送数据（如 float 或结构体），在扩展模块中添加两份副本，并将其地址指定为扩展模块的消息缓冲区。

struct MyExpander : Module {
	...
	float value[2] = {};

	MyExpander() {
		...
		getLeftExpander().producerMessage = &value[0];
		getLeftExpander().consumerMessage = &value[1];
	}
};

然后在主模块中，在需要时发送生产者消息。

Module* rightModule = getRightExpander().module;
if (rightModule && rightModule->getModel() == modelMyExpander) {
	// 取出生产者消息，并转换成正确的指针类型。
	float* value = (float*) rightModule->getLeftExpander().producerMessage;

	// 写入缓冲区
	*value = 42.f;

	// 请求 Rack 引擎在下一个引擎帧翻转双缓冲。
	rightModule->getLeftExpander().requestMessageFlip();
}

在 Rack 的下一个引擎帧，MyExpander 的生产者与消费者消息指针将交换，因此先前产生的值可供扩展模块的 process() 方法消费。

float* value = (float*) getLeftExpander().consumerMessage;

现在你可以读取缓冲区，以处理 MyExpander 的输出或灯。

深色面板

自 Rack 2.4 起，用户可以通过启用 "View > Use dark panels if available" 请求模块使用深色主题面板。

要提供深色面板主题，为 createPanel() 添加第二个参数，指向深色 SVG 文件的路径。

setPanel(createPanel(
	asset::plugin(pluginInstance, "res/VCO.svg"),
	asset::plugin(pluginInstance, "res/VCO-dark.svg")
));

可以选择用 ThemedScrew 替换 ScrewSilver，用 ThemedPJ301MPort 替换 PJ301MPort，以更好地匹配面板。

对于自定义深色控件，可以子类化 ThemedSvgScrew 或 ThemedSvgPort。 也可以在自定义代码中读取 bool settings::preferDarkPanel 的值。

如果你的面板已经是深色主题，可以忽略此功能，或将浅色主题面板作为默认。

自定义控件

一些模块包含显示波形、可视化或其他动态元素的显示屏。 你可以通过子类化 Widget 并覆写其 draw() 方法来创建这些显示屏。 形状、线条、颜色和文本可以使用 NanoVG API 绘制。

以下代码示例演示向 args.vg 变量访问的 NanoVG 上下文绘制。

struct MyWidget : Widget {
	void draw(const DrawArgs& args) override {
		// 按此控件的尺寸绘制一个黄色矩形
		nvgFillColor(args.vg, nvgRGBf(1.0, 1.0, 0.0));
		nvgBeginPath(args.vg);
		nvgRect(args.vg, 0.0, 0.0, box.size.x, box.size.y);
		nvgFill(args.vg);

		// 绘制一个蓝色描边的三角形
		nvgStrokeColor(args.vg, nvgRGBf(1.0, 0.0, 0.0));
		nvgStrokeWidth(args.vg, 5.0);
		nvgLineJoin(args.vg, NVG_MITER);
		nvgBeginPath(args.vg);
		nvgMoveTo(args.vg, 10.0, 90.0);
		nvgLineTo(args.vg, 90.0, 90.0);
		nvgLineTo(args.vg, 50.0, 10.0);
		nvgClosePath(args.vg);
		nvgStroke(args.vg);

		// 绘制一个蓝色圆
		nvgFillColor(args.vg, nvgRGBf(0.0, 0.0, 1.0));
		nvgBeginPath(args.vg);
		nvgCircle(args.vg, 70.0, 50.0, 20.0);
		nvgFill(args.vg);
	}
};

将控件添加到 ModuleWidget 构造函数中。

MyWidget* myWidget = createWidget<MyWidget>(Vec(20, 20));
myWidget->setSize(Vec(100, 100));
addChild(myWidget);

VCV 模块如 VCV Scope 和 VCV ADSR EG 使用 LedDisplay 的子类而不是 Widget，以便为其类 LED 屏幕的显示屏提供更美观、更一致的起点。

文本

静态文本可以直接写在 SVG 模块面板上，但有时需要在自定义控件上显示动态文本。 例如，信号测量模块可以显示每秒更新的电压值。

VCV Rack 包含若干字体，其路径可通过 asset::system("res/fonts/...") 获取。 或者，你可以用 asset::plugin(pluginInstance, "res/...") 包含并使用自己的 TTF 字体。

要在 Widget 的 draw() 方法中渲染文本，每帧从 Rack 的缓存中加载字体，并使用 NanoVG 设置位置、大小、对齐方式等并绘制文本。

void draw(const DrawArgs& args) override {
	// 从缓存加载字体
	std::string fontPath = asset::plugin(pluginInstance, "res/MyFont.ttf");
	std::shared_ptr<Font> font = APP->window->loadFont(fontPath);
	// 字体加载失败时不要绘制文本
	if (font) {
		// 选择字体句柄
		nvgFontFaceId(args.vg, font->handle);
		// 设置字号与对齐
		nvgFontSize(args.vg, 16.0);
		nvgTextAlign(args.vg, NVG_ALIGN_LEFT | NVG_ALIGN_BASELINE);

		// 生成你的文本
		float voltage = 42.f;
		std::string text = string::f("%6.2f V", voltage);
		// 在某个位置绘制文本
		nvgText(args.vg, 100.0, 100.0, text.c_str(), NULL);
	}
}

避免在 Widget 中跨多帧存储 Font 实例，因为它们与 Rack 的 Window 对象绑定，而该对象可能被销毁并重新创建。

自发光图层

Rack 的"房间"亮度可以在 "View" 菜单中调低，只显示灯等自发光对象。 这些对象通过覆写 drawLayer() 方法绘制在图层 1 上。

void drawLayer(const DrawArgs& args, int layer) override {
	if (layer == 1) {
		// 在这里调用 NanoVG 函数，把图形绘制到自发光图层上。
		...
	}
	// 记得调用父类的方法。
	Widget::drawLayer(args, layer);
}

帧缓冲

VCV Rack 每个屏幕帧都会调用 Widget::draw() 方法，因此包含大量路径和文本的复杂控件会消耗大量 CPU/GPU。 如果你的自定义控件不需要每帧重绘，可以用 GPU 帧缓冲缓存其光栅化结果。

为此，将控件放入 FramebufferWidget 中。

FramebufferWidget* myWidgetFb = new FramebufferWidget;
addChild(myWidgetFb);

MyWidget* myWidget = createWidget<MyWidget>(Vec(20, 20));
myWidget->setSize(Vec(100, 100));
myWidgetFb->addChild(myWidget);

然后在需要重绘子控件时，将帧缓冲标记为"脏"。

myWidgetFb->setDirty();

（或者，分发一个 DirtyEvent。）

常见模式是让自定义控件创建自己的子 FramebufferWidget，其中包含其他自定义控件。 顶层控件管理帧缓冲，在子控件需要重绘时将其标记为脏。

复音

VCV Rack 中的电缆可以是复音的，最多承载 16 路电压信号。 要支持复音，模块的 process() 代码必须从输入端口读取每个通道，并向输出端口写入每个通道。 参见 VCV 复音标准，了解处理复音电缆的正确行为。

要为教程中的"正弦振荡器"示例添加复音支持，将所有 DSP 状态变量改为 16 元素数组。

// 把所有相位初始化为 0。
float phase[16] = {};

然后将 process() 方法重写为遍历每个通道。

void process(const ProcessArgs &args) override {
	// 从"主"输入获取所需的通道数。
	// 若该输入未连接，getChannels() 返回 0，但我们仍应产生 1 个通道的输出。
	int channels = std::max(1, inputs[PITCH_INPUT].getChannels());

	// 遍历每个活动通道。
	for (int c = 0; c < channels; c++) {
		float pitch = params[PITCH_PARAM].getValue();
		// 使用 getPolyVoltage(c)，这样单音输入会作用于所有通道。
		pitch += inputs[PITCH_INPUT].getPolyVoltage(c);
		float freq = dsp::FREQ_C4 * std::pow(2.f, pitch);

		phase[c] += freq * args.sampleTime;
		if (phase[c] >= 1.f)
			phase[c] -= 1.f;

		float sine = std::sin(2.f * M_PI * phase);
		// 通过第二个参数设置第 c 个通道。
		outputs[SINE_OUTPUT].setVoltage(5.f * sine, c);
	}

	// 设置每个输出的通道数。
	outputs[SINE_OUTPUT].setChannels(channels);
}

提示：如果模块使用多个实例变量，可以将每个通道的状态组织为结构体数组。

struct OscillatorEngine {
	float phase = 0.f;
};
OscillatorEngine engines[16];

然后可以在 for 循环中用以下方式访问每个引擎：

OscillatorEngine& engine = engines[c];
engine.phase = ...

SIMD 库

现代 CPU 能够使用 SIMD（单指令多数据）指令集，用一条指令操作多个值。 例如，与其用 4 条顺序指令执行

a[0] += 1;
a[1] += 1;
a[2] += 1;
a[3] += 1;

不如使用一条 4 元素 SIMD 指令并行完成所有操作，因此在受 CPU 限制的算法中可预期约 4 倍的性能提升。 （实际加速通常更小，原因包括内存瓶颈、指令吞吐瓶颈、阿姆达尔定律等。）

x64 上的 VCV Rack 最高支持 SSE4.2 扩展，可对 32 位浮点或整数的 4 元素向量进行操作。 Rack 的 SIMD 库包含 simd::float_4 和 simd::int32_4 数据类型，其行为类似 float 和 int32_t 值的 4 元素数组。 不过，你可以用 + - * / += -= *= /= 等运算符将这些数组当作单个（标量）值处理。 sin()、exp() 和 floor() 等若干数学函数也可用于 float_4。

可以用索引表示法 a[i] 访问 SIMD 数组元素，但频繁这样做会抵消 SIMD 的优势。 性能会降到与串行非 SIMD 代码一样慢。

我们可以用 SIMD 类型重写上一节的"正弦振荡器"示例。 用 4 个 float_4 值代替 16 个 float 值。

using simd::float_4;
float_4 phase[4] = {};

然后将循环重写为一次处理 4 个通道。

void process(const ProcessArgs &args) override {
	int channels = std::max(1, inputs[PITCH_INPUT].getChannels());

	// 每次遍历 4 个通道组成的向量，而不是一次一个通道。
	for (int c = 0; c < channels; c += 4) {
		float_4 pitch = params[PITCH_PARAM].getValue();
		// 从通道 c 开始取出 4 个电压组成的向量。
		pitch += inputs[PITCH_INPUT].getPolyVoltageSimd<float_4>(c);
		// 使用 simd:: 命名空间下的数学函数，而不是 std:: 的。
		float_t freq = dsp::FREQ_C4 * simd::pow(2.f, pitch);

		// 大多数算术运算符都为 float_4 类型做了重载。
		// 这里把一个 float_4 与一个浮点标量相乘。
		phase[c / 4] += freq * args.sampleTime;
		// 不能对 SIMD 元素做分支，否则会失去它们的性能优势。
		// 取而代之，想办法在不分支的前提下得到相同结果。
		phase[c / 4] -= simd::trunc(phase[c / 4]);

		float_4 sine = simd::sin(2.f * M_PI * phase);
		outputs[SINE_OUTPUT].setVoltageSimd(5.f * sine, c);
	}

	// 设置每个输出的通道数。
	outputs[SINE_OUTPUT].setChannels(channels);
}

虽然跨多个复音通道的 SIMD 并行化是常见做法，你也可以对单个通道内的计算应用并行化。 卷积、滤波器和立体声/四声道处理都能从 SIMD 优化中受益。

DSP 库

Rack 的 API 包含若干 DSP 头文件，例如：

  • 常用函数与常量
  • 触发检测器、脉冲发生器等数字工具
  • 常用数学函数的快速近似
  • FFT（快速傅里叶变换）
  • 采样率转换器
  • ODE（常微分方程）求解器
  • 常用滤波器处理器

为进一步优化上面的"正弦振荡器"示例，我们可以将 simd::pow(2.f, pitch) 替换为 dsp::exp2_taylor5(pitch)，它以足够的精度近似 2x2^x，可用于电压到频率转换而无听感误差。
