构建

搭建开发环境

在构建 Rack 或 Rack 插件之前，你必须安装由系统包管理器提供的构建依赖。 Rack 自身的依赖（GLEW、glfw 等）不需要安装在你的系统上，因为构建过程中会在本地编译特定版本。 不过，你需要合适的工具来构建 Rack 及这些依赖。

Windows

如果你正在运行杀毒软件，请将其禁用，否则它可能干扰构建过程，或使构建变得非常缓慢。

安装 MSYS2，并从开始菜单启动 MinGW 64 位 shell，而不是默认的 MSYS shell。 先更新包管理器本身：

pacman -Syu

然后重启 shell 并安装软件包。

pacman -Syu git wget make tar unzip zip mingw-w64-x86_64-gcc mingw-w64-x86_64-gdb mingw-w64-x86_64-cmake autoconf automake libtool jq python zstd mingw-w64-x86_64-pkgconf

Mac

安装 Homebrew，并安装构建依赖。

brew install git wget cmake autoconf automake libtool jq python zstd pkg-config

Linux

在 Ubuntu 16.04+ 上：

sudo apt install unzip git gdb curl cmake libx11-dev libglu1-mesa-dev libxrandr-dev libxinerama-dev libxcursor-dev libxi-dev zlib1g-dev libasound2-dev libgtk2.0-dev libgtk-3-dev libjack-jackd2-dev jq zstd libpulse-dev pkg-config autoconf libtool

在 Arch Linux 上：

pacman -S git wget gcc gdb make cmake tar unzip zip curl jq python zstd libpulse pkgconf

构建 Rack

如果你使用 Rack SDK，构建插件时无需构建 Rack。

用 git clone https://github.com/VCVRack/Rack.git 克隆此仓库，并 cd Rack。 请确保绝对路径中不含空格，因为这会破坏基于 Makefile 的构建系统。

克隆子模块。

git submodule update --init --recursive

在本地构建依赖。 你可以在 make 命令中加入 -j4（或你的逻辑核心数）来并行构建。 这可能需要 15-60 分钟。

make dep

构建 Rack。 这可能需要 1-5 分钟。

make

运行 Rack。

make run

构建 Rack 插件

完成搭建开发环境一节。

插件可以通过三种方式构建：

  • 下载 VCV Rack 和 Rack SDK（Windows x64 / Mac x64 / Mac ARM64 / Linux x64），然后从任意文件夹构建插件。（最简单、最快捷。）
  • 从源码构建 Rack，并在 plugins/ 文件夹中构建插件。（推荐高级开发者使用。）
  • 使用 VCV Rack Plugin Toolchain 以一条命令为所有架构构建。支持原生（Linux）或 Docker（Linux、Mac、Windows）。建议 15 GB 磁盘空间、8 GB 内存。

下载或克隆插件源代码，例如

git clone https://github.com/VCVRack/Fundamental.git

克隆该 git 仓库的子模块。

cd Fundamental
git submodule update --init --recursive

如果使用 Rack SDK，请解压它，并通过运行 export RACK_DIR=<Rack SDK dir> 设置 RACK_DIR 环境变量。

构建插件依赖。（大多数插件不需要此步骤。）

make dep

构建插件。

make

创建可分发的插件包。

make dist

你的包会生成在 dist/<slug>-<version>-<os>-<cpu>.vcvplugin。

或者，你也可以用一步完成构建、打包并把插件安装到你的 Rack 用户文件夹。

make install
