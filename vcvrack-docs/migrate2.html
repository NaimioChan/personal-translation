将 v1 插件迁移到 v2

VCV Rack 2 的 API 在设计上几乎与 v1 插件保持向后兼容。 这意味着 90% 的插件只需要更新版本号并重新编译（改 1 行，15 秒的工作量）。

对于另外 10% 使用了高级或尚不稳定 API 特性的插件，升级到 v2 同样简单，只需按下面几步做查找替换即可。

此外，Rack 2 还提供了一些新的可选增强特性，插件开发者可以用它们提升插件的易用性，详见第 3 节。

1.1) 把 plugin.json 的版本字符串更新为 v2

插件的主版本号（MAJOR.MINOR.REVISION）必须与 Rack 的主版本号一致，因此请把插件的 plugin.json 清单中的版本号改为 2。 例如，把

{
  "slug": "Fundamental",
  "version": "1.2.3",
  ...

改为

{
  "slug": "Fundamental",
  "version": "2.0.0",
  ...

如果愿意，次版本号和修订号可以保持不变，例如 2.2.3。

下载最新的 Rack 2 SDK。 清理并编译插件。

export RACK_DIR=/path/to/Rack-SDK
make clean
make dist

如果插件编译成功，可以直接跳到可能出现的运行时 bug。 如果编译失败，请继续阅读，以解决可能的错误或警告。

1.2) ParamWidget::paramQuantity 已由 getParamQuantity() 取代

如果你的 ParamWidget 方法使用了 paramQuantity 成员变量，请改用对应的 getter 方法，或在方法开头加上这一行。

ParamQuantity* paramQuantity = getParamQuantity();

1.3) 已移除 ParamWidget::reset() 与 ParamWidget::randomize()

如果你希望在用户重置/随机化模块时，禁止某个特定参数被重置或随机化，请在 Module 构造函数中设置这些属性。

getParamQuantity(MY_PARAM)->resetEnabled = false;
getParamQuantity(MY_PARAM)->randomizeEnabled = false;

另一种做法是在 Module 类中重写下列方法，为所有参数和内部状态实现自定义行为。

void onReset(const ResetEvent& e) override {
	params[MY_PARAM].setValue(0.f);
	// ...

	// 如需包含默认行为，请调用父类方法
	// Module::onReset(e);
}

void onRandomize(const RandomizeEvent& e) override {
	params[MY_PARAM].setValue(random::uniform());
	// ...

	// 如需包含默认行为，请调用父类方法
	// Module::onRandomize(e);
}

如果你的插件仍然有构建错误，请在 VCV 开发者论坛发帖，或联系 VCV 支持，描述你的构建错误。

2) 可能出现的运行时 bug

测试时你可能会遇到以下问题。

2.1) 不要跨帧保存 Font 与 Image 引用

Rack 的 DAW 插件版本在插件编辑器窗口每次关闭后重新打开时，都会使用不同的 OpenGL 上下文。 这意味着，如果你在控件的构造函数中用 font = APP->window->loadFont(...) 或 image = APP->window->loadImage(...) 加载并保存了 Font 或 Image，那么窗口之后重新打开时，它的 OpenGL 引用就会失效。

正确的做法是只保存路径，并在 draw() 中每一帧重新获取字体/图像。示例：

void draw(const DrawArgs& args) override {
	std::shared_ptr<Font> font = APP->window->loadFont(fontPath);
	if (font) {
		nvgFontFaceId(args.vg, font->handle);
		...
	}
}

loadFont() 和 loadImage() 会按路径缓存字体/图像，因此该操作可以高效地在 draw() 中每帧调用。

3) v2 API 新增的可选特性

以下 Rack 2 的新 API 特性并非必需，但可以提升模块的易用性。

3.1) 为 Port 与 Light 添加标签

为端口和灯添加名称，它们会显示在工具提示中。

例如，在 Module 构造函数中：

configInput(PITCH_INPUT, "1V/oct pitch");
configOutput(SIN_OUTPUT, "Sine");
configLight(PHASE_LIGHT, "Phase");

3.2) 视情况用 configButton() 或 configSwitch() 替换 configParam()

对于瞬时按钮（momentary button）和多状态开关，向用户显示一个实数参数并没有太大意义。

此时应使用 configButton() 隐藏右键菜单中的数值输入框，或用 configSwitch() 提供一组选项。

configButton(TAP_PARAM);
configSwitch(SYNC_PARAM, 0, 1, 0, "Sync mode", {"Soft", "Hard"});

3.3) 添加旁通路由

如果模块被用户旁通（通过右键菜单或快捷键），你可以把某些输入直接路由到输出，跳过所有处理。 这对滤波器或混响，甚至分频器或量化器都很合理，但对 VCO 不合理，因为 VCO 是产生信号而不是处理信号。

例如，在 Module 构造函数中：

configBypass(LEFT_INPUT, LEFT_OUTPUT);
configBypass(RIGHT_INPUT, RIGHT_OUTPUT);

另一种做法是重写 Module::processBypass() 来实现自定义的旁通行为。

3.4) 把大数据存放在模块的 patch storage 目录

不要在 toJson/fromJson() 方法中序列化大（>100 KB）缓冲区，那可能会让 UI 卡顿；请改为读写 createPatchStorageDirectory() 和 getPatchStorageDirectory() 返回的目录。

示例：

void onAdd(const AddEvent& e) override {
	std::string path = system::join(createPatchStorageDirectory(), "wavetable.wav");
	// 读取文件...
}

void onSave(const SaveEvent& e) override {
	std::string path = system::join(createPatchStorageDirectory(), "wavetable.wav");
	// 写入文件...
}

注意：不能在 Module 构造函数中调用这些方法，因为此时模块尚未加入 Engine。

3.5) 以全亮度绘制自定义的类灯控件

Rack 2 允许用户降低机架的亮度，同时让灯保持全亮度。

如果你的自定义控件应当发光，请重写 Widget::drawLayer()，并在 layer 1 上绘制：

void drawLayer(const DrawArgs& args, int layer) override {
	if (layer == 1) {
		...
	}
	Widget::drawLayer(args, layer);
}
