复音

VCV Rack 支持复音线缆，最多可承载 16 个通道的电压（音频、CV、门限等）。 为了与普通单音线缆区分，复音线缆显示得更粗，并且可以包含 2 到 16 之间的任意通道数。

若没有复音线缆，连接复音合成器的 patch 会非常繁琐，而且需要支持的声部越多，难度就越大。 要同时演奏最多 NN 个声部，你就得创建 NN 个相同的 VCO、VCF、VCA 等，在它们之间连接 NN 组线缆，然后把它们的 NN 个输出单位增益混合成单个信号。 但有了复音线缆，你只需连接一组模块，然后配置一个“源”模块来产生复音输出即可。

示例

在下图截屏中，MIDI-CV 被配置为产生 8 个通道：右键单击它的面板，选择 “Polyphonic channels” 的数量，并可选择 “Polyphony mode” 来指定 MIDI 音符如何分配到各复音通道。 它的 V/OCT 和 GATE 端口随即成为复音输出，其信号可通过复音线缆送往其他复音模块。

模块必须专门开发以支持复音，才能处理复音线缆。 这类模块会标有 “Polyphonic” 标签。

有些模块只在用户配置后才产生复音信号，比如上面介绍的 MIDI-CV。 另一些模块则在有复音线缆接入其某个输入时才产生复音输出。 在此例中，VCO-1 会在其 SINE 输出上产生复音音频信号，因为来自 MIDI-CV’s V/OCT 输出的复音音高信号接入了 VCO-1’s 的 V/OCT 输入。 这意味着，只要你注意在 patch 中只使用带 “Polyphonic” 标签的模块，就能通过配置单个模块（例如 MIDI-CV）让整个 patch 启用复音。 其余模块会从复音源开始，以“连锁反应”的方式变成复音。

有助于理解和使用 Rack 复音功能的有用工具模块包括：VCV Split，用于把复音信号拆分为多个单音信号；VCV Merge，用于把多个单音信号合并为复音信号；VCV Sum，用于对复音信号中的所有通道做单位增益混合；以及 VCV Viz，用于可视化复音信号中的各个通道。 像 VCV Scope 这样的模块也可用来分别显示每个通道。

技术细节

在 Rack 中，单音线缆实际上只是复音线缆的特例，仅含 1 个通道。 这意味着 Rack 里只有一种线缆：复音线缆。

零通道线缆也是可能的，它会让模块认为该线缆未被连接。 当某个模块有特定的未连接行为、而你并不想真的拔掉线缆时，这会很有用。 模块甚至可以自动化其输出的通道数，从而在逻辑上连接或断开线缆。 例如，第三方模块 Sapphire Moots 在收到触发时会在 1 通道与 0 通道输出之间切换。

支持复音的模块，性能几乎总是优于使用多个单音模块副本，通常可高出 4 倍（CPU 占用仅为 25%）。 这是因为复音模块通常使用 SIMD 指令编写，和/或利用编译器的自动向量化，从而让 CPU 在同一核心上同时处理 4 个通道（借助 SSE）。

其他用途

尽管名称如此，复音线缆并不限于制作复音合成器 patch。 其他一些假设性用途包括：

  • 使用 2 通道复音线缆进行立体声编码
  • 环绕声
  • 高保真度立体声响复制（ambisonics）。三阶 ambisonics 恰好需要 16 个通道，因此 Rack 的复音线缆是传输 ambisonics 信号的理想媒介。
  • 自定义数字多通道总线协议
  • 以高于 Rack 引擎运行采样率的速率传输信号。这或许能实现低 CPU 占用的视频合成。
  • 使用 VCV Merge 和 VCV Split 把最多 16 个单音信号“瞬移”到 patch 的其他位置，以减少线缆杂乱。 这一概念类似于 Doepfer A-180-9 Multicore 这个 Eurorack 模块，它（滥）用 RJ45（以太网）线缆来传输模拟信号。
