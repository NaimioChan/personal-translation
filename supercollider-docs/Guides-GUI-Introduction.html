GUI 简介

编写图形用户界面代码的入门介绍

注意： 为避免混淆，我们先从一个重要的历史说明开始。SuperCollider 曾经有一个相当糟糕的 GUI 类系统，涉及诸如 SCWindow 之类依赖于平台的类。该系统在 3.7 中已随统一的 Qt GUI 完全消失。在某些 SuperCollider 帮助文件和 quark 中，你仍会看到旧 GUI 类的残余。我们仍在更新所有帮助文件。如果你在某个 quark 中遇到此类旧类，可以通过通知该 quark 作者来为公众做一件好事。

基本元素：窗口、视图和容器

GUI 最基本的元素是窗口。它在屏幕上占据一个矩形区域，其他 GUI 元素在其中显示。它通常带有一个栏，用于显示窗口标题，并允许通过其显示的控件或通过鼠标和键盘交互来移动窗口、调整窗口大小和关闭窗口。其中一些方面可以在 SuperCollider GUI 代码中控制，不过与窗口交互的具体方式及视觉呈现方式在很大程度上取决于平台。

Window 中包含的 GUI 元素称为视图。它们都继承自基本的 View 类。视图占据窗口的一个矩形区域，并在其中绘制自身以显示某些数据，或指示用户与程序之间的某种交互模式。视图接收用户产生的键盘和鼠标事件，并通过控制程序的行为来响应这些事件。它们还显示有关程序状态及其所操作数据的信息。

还有一些特殊类型的视图可以包含其他视图，因此被称为容器，例如 CompositeView。它们允许以分层方式组织 GUI。容器视图被称为它所包含视图的父视图，而后者则被称为它的子视图。分层组织方式可以轻松地更改容器内所有视图的各个方面：如果父视图被隐藏，那么所有子视图也会被隐藏；如果父视图被移动，那么它们也会随之移动。子视图的定位使用相对于其父视图的坐标。

注意： 在许多方面，Window 也被视为其所包含视图的父级，并且可以在代码中从功能上占据与容器视图相同的位置，尽管并非在所有情况下都是如此。创建 Window 时，它会隐式创建一个占据其整个空间的容器视图。当以 Window 作为父级创建视图时，该视图实际上会成为该容器的子级。有关详细信息，请参见 Window 的 view 方法和 View 的构造函数。

注意： 在 Qt GUI 中，窗口、视图和容器之间没有区别。View 类本身的实例可以直接显示在屏幕上，并且可以包含其他视图，因此这同样适用于其所有子类。在其他 GUI 工具包中特定于 Window 和容器的大多数方法，在 Qt 中由所有视图共享。

以下示例展示了一个包含 Button、Slider 以及位于 CompositeView 中的一组 StaticText 视图的窗口。点击按钮时，CompositeView 的可见性会被切换，而与 Slider 交互则会将 CompositeView（以及其所有内容）沿水平方向移动。

w = Window.new("GUI Introduction", Rect(200,200,255,100));
b = Button.new(w,Rect(10,0,80,30)).states_([["Hide"],["Show"]]);
l = Slider.new(w,Rect(95,0,150,30));
c = CompositeView.new(w,Rect(20,35,100,60));
StaticText.new(c,Rect(0,0,80,30)).string_("Hello");
StaticText.new(c,Rect(20,30,80,30)).string_("World!");
b.action = { c.visible = b.value.asBoolean.not };
l.action = { c.bounds = Rect( l.value * 150 + 20, 35, 100, 100 ) };
w.front;

视图的自动定位与调整大小

作为在代码中显式指定所有视图尺寸和位置的一种便捷替代方案，SuperCollider 允许在视图创建时以及窗口调整大小时动态地实现视图之间以及视图与窗口大小之间的自动定位和调整大小。为此有多种机制。

视图的调整大小选项

当父视图调整大小时，视图可以自动调整大小或移动，共有九种不同的方式定义视图各边缘如何随父视图边缘移动。相关文档请参阅视图的 resize 方法和 Resize behaviour 文档。

w = Window.new("GUI Introduction", Rect(200,200,200,200));
TextField.new(w,Rect(0,0,200,30)).resize_(2);
Slider.new(w,Rect(0,30,30,170)).resize_(4);
TextView.new(w,Rect(30,30,170,170)).resize_(5);
w.front;

Decorators

装饰器是可分配给容器视图的对象，用于承担定位容器子视图的任务（目前只存在一种：FlowLayout）。将装饰器分配给容器后，作为其子视图创建的视图将自动按特定模式定位。详情请参阅 FlowLayout 的文档。

w = Window.new("GUI Introduction", Rect(200,200,320,320)).front;
// 注意 FlowLayout 引用的是 w.view，即容器视图
// 它会随窗口自动创建并占据其整个空间
w.view.decorator = FlowLayout(w.view.bounds);
14.do{ Slider(w, 150@20) };

Layouts

布局类构成一个复杂系统的一部分，用于管理视图的位置和大小。使用布局时，只需指定视图在某种组织模式内的关系，其精确位置和大小会根据其类型（所显示的内容和提供的交互类型）自动推导，并符合良好的 GUI 可用性原则。布局还会动态地定位和调整视图大小，每当其父级被调整大小或其内容发生变化时都会如此。

详细说明请参见 布局管理 指南。

注意： 布局目前仅在 Qt GUI 中实现。以下示例在其他 GUI 工具包中无法运行。w = Window.new("GUI Introduction").layout_( VLayout( HLayout( Button(), TextField(), Button() ), TextView() ) ).front;

注意： 布局与装饰器不兼容，并且会忽略视图大小调整选项。组合布局和装饰器的效果未定义。

自定义外观

视图提供多种自定义外观的方式。其范围从装饰性地更改它们绘制自身所用的颜色，到控制它们显示各种数据的方式。

Colors

在 GUI 代码中，颜色由 Color 类表示。

一种可以自定义的典型颜色是背景色——可将选定的颜色应用于某个视图被视为背景的部分。显示文本的视图通常也允许自定义其颜色。

自定义颜色可以与视图或其所显示数据的不同变化状态相关联，例如：Button 允许为其每个状态分别关联背景色和文本色，因此点击时会随状态一起切换颜色；ListView 允许为其每个项设置不同的背景色，还可以设置仅应用于当前选中项的特殊背景色和文本色。

每当你执行以下示例时，随机颜色将被应用到视图的不同方面：

(
w = Window("GUI Introduction").background_(Color.rand).front;
b = Button(w, Rect(10,10,100,30)).states_([
    ["One",Color.rand,Color.rand],
    ["Two",Color.rand,Color.rand],
    ["Three",Color.rand,Color.rand]
]);
l = ListView.new(w, Rect(10,50,200,100))
    .items_(["One","Two","Three"])
    .colors_([Color.rand,Color.rand,Color.rand])
    .hiliteColor_(Color.blue)
    .selectedStringColor_(Color.white);
r = Slider(w, Rect(10, 160, 200, 20))
    .knobColor_(Color.rand)
    .background_(Color.rand);
)

Palette

在 Qt GUI 中，用于绘制视图的完整颜色集合由调色板表示（参见 QPalette 类）。使用调色板，你可以一次性定义整个 GUI 的（大部分）外观。

在下面的示例中，点击按钮将在两个调色板之间切换。但请注意，赋给第一个 Button 状态的颜色将覆盖调色板中定义的红色，并且各个 ListView 项的颜色不受调色板控制。

(
x = QPalette.auto(Color.red(0.8), Color.red(0.5));
y = QPalette.auto(Color.cyan(1.4), Color.cyan(1.8));
p = QtGUI.palette;
QtGUI.palette = x;
w = Window.new("GUI Introduction").front;
w.onClose = {QtGUI.palette = p};
Button.new(w, Rect(10,10,100,30)).states_([
    ["Red", Color.black, Color.grey(0.7)],
    ["Cyan"]
]).action_({ |b| QtGUI.palette = if(b.value == 0){x}{y} });
ListView.new(w, Rect(10,50,200,100))
    .items_(["One","Two","Three"])
    .colors_([Color.grey(0.4),Color.grey(0.5),Color.grey(0.6)]);
Slider(w, Rect(10, 160, 200, 20));
RangeSlider(w, Rect(10, 190, 200, 20));
)

Fonts

显示文本的视图通常允许你为其指定自定义字体。字体由 Font 类表示，该类还可查询通常使用的默认字体，以及专门用于 "serif"、"sans-serif" 和 "monospace" 字体类型的默认字体。它还可查询系统上所有可用的字体。

(
w = Window.new("GUI Introduction",Rect(200,200,200,70)).front;
a = [Font.defaultMonoFace, Font.defaultSansFace, Font.defaultSerifFace];
b = Button.new(w,Rect(10,10,180,50))
    .states_([["Monospace"],["Sans serif"],["Serif"]])
    .font_(a[0])
    .action_({|b| b.font = a[b.value]});
)

其他视觉属性

复杂视图可能有许多其他方式来定制它们显示相同数据的方式。MultiSliderView 和 EnvelopeView 就是很好的例子。

动作与钩子：让那个按钮做点什么！

视图和窗口可以被赋予 action，当用户交互导致特定事件发生时，它们将执行该动作。从技术上讲，动作可以是任何对象，当相关事件发生时，将调用其 value 方法。例如，将 Function 赋为动作很有用，这允许人们定义任意一段代码来响应 GUI 事件。

也可以将对象赋予视图和窗口，以便在并非由用户交互直接引发、但能传达有关视图操作及其所处状态的有用信息的事件上进行求值。在这种情况下，它们通常有别于动作，而被称为 钩子。

这里，我们将概述不同种类的动作与钩子。关于如何赋值和使用它们的精确说明，参见 View: Actions in general 及后续章节。

默认动作

视图通常可以通过其 action 设置方法指定默认动作，当视图的主要交互方式被触发时会执行该动作。例如，Button 的默认动作在点击时发生，Slider 的默认动作在其手柄被移动时发生。

在下面的示例中，按下按钮将打开一个完全相同的窗口，但位置不同。

~makeWindow = { var w;
    w = Window.new("Evader",Rect(500.rand + 100, 500.rand + 100, 200,50)).front;
    Button.new(w,Rect(10,10,180,30)).states_([["Evade"]]).action_(~makeWindow);
};
~makeWindow.value;

键盘和鼠标操作

所有视图都可以为特定的鼠标和键盘事件分配动作，无论这些事件对视图可能有什么其他影响，也无论视图可能在这些事件上触发什么其他专门的动作或钩子。

你可以为鼠标事件分配动作，这些事件在鼠标指针进入视图空间、在视图上移动以及按下或松开鼠标按钮时生成。

详情请参见 View: Mouse actions。

在以下示例中，StaticText 将报告 Button 是被按下还是被释放。

w = Window.new(bounds:Rect(200,200,200,50)).front;
b = Button.new(w,Rect(10,10,80,30)).states_([["Off"],["On"]]);
t = StaticText(w,Rect(100,10,90,30)).string_("Button released");
b.mouseDownAction = { t.string = "Button pressed" };
b.mouseUpAction = { t.string = "Button released" };

你可以为键盘事件分配动作，每当视图具有键盘焦点时按下或释放按键都会生成这些事件。键盘焦点是视图的一种状态，在此状态下视图具有响应键盘事件的独占优先权。具有键盘焦点的视图通常会以某种方式在视觉上加以表明。在大多数平台上，按下 Tab 键会在活动窗口的各视图之间切换键盘焦点，而单击某个视图会使其获得焦点。

详情参见 View: Key actions。

在以下示例中，向任意 TextField 输入文本都会改变下方矩形的颜色，每个 TextField 对应一种不同的颜色。

w = Window.new(bounds:Rect(200,200,200,100)).front;
x = TextField(w,Rect(10,10,80,30));
y = TextField(w,Rect(110,10,80,30));
t = StaticText(w,Rect(10,40,180,50));
~reset = {t.background = Color.red};
x.keyDownAction = {t.background = Color.green};
x.keyUpAction = ~reset;
y.keyDownAction = {t.background = Color.blue};
y.keyUpAction = ~reset;
~reset.value;

如果某个按键或鼠标事件未被其发生的视图处理，它可能会传播到父视图，并触发父视图的动作。详细说明请参见 View: Key and mouse event processing。

拖放操作

当在视图上按下鼠标按钮并同时按住 Cmd（macOS）或 Ctrl（其他操作系统）键，再按住按钮移动鼠标指针时，如果该视图支持，就会启动一次拖放操作。大多数视图在尝试拖动时都有一个默认导出的对象。对于 Slider，它是其值；对于 List，它是当前选中项的数值索引，等等。可以说被导出的对象正在被拖动。当拖动手势在另一个视图上释放鼠标按钮而结束时，可以说被拖动的对象被放下到了另一个视图上。视图可以以不同方式响应被放到其上的各种对象。

可以通过分配自定义拖放动作，来自定义视图被拖动时导出什么对象，以及视图如何响应被拖放的对象。

详情参见 View: Drag and drop。

(
    w = Window.new.front;
    a = Button(w, Rect(10, 10, 200, 20)).states_([["Hi There!"]]);
    a.beginDragAction = { a.dragLabel ="I'm dragging: \""++ a.states[0][0]++"\""; a.states[0][0] };
    DragSink(w,Rect(10,40,200,20)).align_(\center).string="Cmd-drag from Button to here";
)

其他专用操作

某些视图可以为其与用户交互模式特定的其他事件分配动作，建议查阅其文档以了解。

Hooks

钩子（hook）是各种表示 GUI 元素重要状态变化的事件。技术上它们的用法与 action 相同，但被区分开来，以表示不是用户直接交互产生的事件。用于分配钩子的 GUI 类方法通常以 "on" 为前缀。（你也会在其它 SuperCollider 类的方法中发现这种命名模式，它们具有相同意义上的钩子）。

例如，每个视图以及 Window 都具有的一个钩子是 onClose，它在窗口关闭或视图被移除时触发。其他钩子例如存在于 Window 成为或不再成为活动窗口的情况下。

自定义视图

UserView 是一个视图，它本身只负责显示而不做任何事，但允许你定义它如何绘制，并且你可以用鼠标、键盘以及拖放操作来定义它的全部行为。关于所有这些方面的文档，请参阅 UserView、View 和 Pen。不过，下面的说明将演示设计自定义视图的基本技术。

你将使用 Pen 类来绘制视图。Pen 是一个强大的类，允许你使用简单的视觉图元（如线、弧、曲线、矩形、椭圆等）进行算法绘制，并用颜色和渐变填充形状。

注意： 旧教程可能会建议子类化 UserView。不要这样做。使用组合，而非继承。将 UserView 作为自定义视图类的一个属性。

创建自定义视图涉及以下步骤：

  1. 创建用户视图
  2. 定义绘制函数
  3. 定义默认操作
  4. 定义鼠标动作
  5. 定义按键动作
  6. 定义拖放操作

你可以省略不需要的步骤。

(
var value = 0.5;
w = Window.new.front;

// (1) 创建一个 UserView
v = UserView(w,Rect(50,50,200,20));

// (2) 使用 Pen 定义一个绘图函数
v.drawFunc = {
    // 绘制填充
    Pen.fillColor = Color.grey;
    Pen.addRect(Rect(0,0, v.bounds.width*value,v.bounds.height));
    Pen.fill;
    // 绘制三角形
    Pen.fillColor = Color.red;
    Pen.moveTo(((v.bounds.width*value)-5) @ v.bounds.height);
    Pen.lineTo(((v.bounds.width*value)+5) @ v.bounds.height);
    Pen.lineTo(((v.bounds.width*value)) @ (v.bounds.height/2));
    Pen.lineTo(((v.bounds.width*value)-5) @ v.bounds.height);
    Pen.fill;
    // 绘制框架
    Pen.strokeColor = Color.black;
    Pen.addRect(Rect(0,0, v.bounds.width,v.bounds.height));
    Pen.stroke;
};

// (3) 设置默认动作
v.action = {value.postln; v.refresh};

// (4) 定义鼠标动作
v.mouseDownAction = { arg view, x = 0.5,y, m;
    //m.postln;
    ([256, 0].includes(m)).if{ // 限制为无修饰键
    value = (x).linlin(0,v.bounds.width,0,1); v.doAction};
};

v.mouseMoveAction = v.mouseDownAction;

// (5)（可选）定义按键动作
v.keyDownAction = { arg view, char, modifiers, unicode,keycode;
    if (unicode == 16rF700, { value = (value+0.1).clip(0,1) });
    if (unicode == 16rF703, { value = (value+0.1).clip(0,1) });
    if (unicode == 16rF701, { value = (value-0.1).clip(0,1) });
    if (unicode == 16rF702, { value = (value-0.1).clip(0,1) });
    v.doAction;
};

// (6)（可选）定义拖放行为
v.beginDragAction = {value}; // 拖动什么
v.canReceiveDragHandler = {View.currentDrag.isNumber}; // 接收什么
v.receiveDragHandler = {value = View.currentDrag; v.doAction }; // 接收时做什么


// 仅用于测试拖放
Slider(w,Rect(50,100,200,20));

StaticText(w,Rect(50,150,350,50)).string_("To Test Drag and Drop,\nHold down Cmd (Ctl) Key");

)

注意：GUI 与定时

警告： 使用 GUI 系统的代码的执行仅限于主应用程序上下文。在 SuperCollider 中，代码有许多方式可以在与主上下文并行运行的其他上下文中执行，而在这些上下文中不允许与 GUI 对象交互。这包括：在 SystemClock 和 TempoClock 上调度的代码，以及为响应 OSC 消息而执行的代码

如果你在上述上下文中尝试与 GUI 对象交互，将抛出错误。

因此，如果你想使用 Function、Routine、Task 和其他类似对象来调度与 GUI 元素交互的代码，你必须使用 AppClock 来这样做，因为调度在 AppClock 上的代码是在主应用程序上下文中执行的。你当然也可以在其他上下文中执行的代码里将 GUI 代码重新调度到 AppClock，而 'defer' 机制是这种做法的一种便捷简写。

在 AppClock 上调度 GUI 代码的示例：

w=Window.new.front;
Routine{
    20.do{
    w.bounds=Rect(200.rand, 200+200.rand, 300,300);
    0.1.wait;
    };
    w.close;
}.play(AppClock)

使用 SystemClock 结合 defer 机制的相同做法：

w=Window.new.front;
Routine{
    20.do{
    {w.bounds=Rect(200.rand, 200+200.rand, 300,300) }.defer; // 你必须延迟执行此操作
    0.1.wait;
    };
    {w.close}.defer; // 你必须延迟执行此操作
}.play(SystemClock)

如上所述，在直接响应 OSC 消息执行的代码中（这包括提供给各种 OSC 响应者类的函数）也不允许使用 GUI 系统。上述相同的解决方案同样适用。
