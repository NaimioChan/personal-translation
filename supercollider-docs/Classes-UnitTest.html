UnitTest

一个用于对类进行程序化测试的类

Object

另请参阅：UnitTestResult、UnitTestScript

子类：UnitTestScript

说明

为了确保方法正常工作，可以实现一个测试来保证正确的行为。

编写测试以阐明对象应如何响应是一种常见做法，从长远来看还能避免不一致。测试始终是 UnitTest 的子类，至少实现一个以 test_ 开头的方法。

当运行一个类的所有测试时（参见 *run），每个测试方法都在该类的单独实例中调用。因此，测试方法互不干扰。

注意： Common 库类的单元测试保存在 SuperCollider 源码的 testsuite/classlibrary 目录中。要安装，请下载源码，并将该目录添加到你的 sclang_conf.yaml 中，可以通过编辑该文件或通过 ScIDE 首选项来完成。

UnitTest.reportPasses

UnitTest.reportPasses = value

访问器，控制是否报告通过的测试。默认为 true。另请参见 *passVerbosity，它控制当此项设置为 true 时，通过的测试报告多少细节。

参数：

(value)

应为 true 或 false。

UnitTest.passVerbosity

UnitTest.passVerbosity = value

控制是否为通过的测试报告额外细节的访问器。

默认值为 UnitTest.full，以便报告所有细节；然而，这种行为对某些人来说可能过于冗长，对他们来说，只需看到测试通过而不需要看到细节就足够了。如果设置为 UnitTest.brief，并且 *reportPasses为 true，将通过会被报告，但不包含断言可能提供的任何额外细节。

参数：

(value)

应为 UnitTest.full 或 UnitTest.brief。

UnitTest.run(reset: true, report: true)

运行所有名称以 test_ 开头的方法。

TestUnitTest.new.run;

参数：

reset

如果为 true，则首先在该类上运行 *reset。

report

如果为 true，则输出测试结果。

UnitTest.runTest(methodName)

运行单个测试方法。

UnitTest.reset;
UnitTest.runTest("TestUnitTest:test_assert");

参数：

methodName

一个 String，引用类及其内部的测试方法，例如 "TestPolyPlayerPool:test_prepareChildrenToBundle"。

UnitTest.runAll

运行整个测试套件。由于此方法针对整个测试套件，因此只应在 UnitTest 上调用。在它的任何子类上调用都会导致抛出 Error。

UnitTest.reset;

.runTestMethod(method, report: true)

运行此类中的单个测试方法

TestUnitTest.new.runTestMethod(TestUnitTest.findMethod(\test_assert));

参数：

method

要运行的方法

report

返回值：

（在此处描述返回值）

.assert(boolean, message, report: true, onFailure, details)

断言一个表达式必须为真。

this.assert(2 == 2, "passes");
this.assert(2 == 2.00001, "fails");

参数：

boolean

一个布尔值，其中 true 表示测试通过。

message

描述断言目的的消息，例如 "foo should be less than bar"。当 report 为 true 时发布。

report

如果为 true，报告测试结果。

onFailure

如果不是 nil，失败会停止测试并求值此函数。

details

一些可选的额外细节，除非请求简要报告（参见 *passVerbosity），否则这些细节将传递给报告框架以供显示。

.assertEquals(a, b, message: "", report: true, onFailure)

断言表达式 a 等于值 b，其中相等性根据 a 对 == 的实现来确定。

自动将相等性检查的详细信息传递给报告框架，如果断言失败，将显示这些信息，并且如果断言通过且 *reportPasses 为 true 且 *passVerbosity 未设置为 UnitTest.brief，也会显示。

this.assertEquals(2 + 2, 4, "passes");
this.assertEquals(2 + 2, 5, "fails");

参数：

a

实验产生的值

b

期望值

message

描述断言目的的消息，例如 "Adding two numbers should return their sum."。若 report 为 true 则发布。

report

如果 true（默认值为 true），则报告测试结果。

onFailure

如果不是 nil，失败会停止测试并求值此函数。

.assertFloatEquals(a, b, message: "", within: 0.0001, report: true, onFailure)

断言返回浮点数的表达式 a 在给定范围（within）内与 b 相等。

自动将相等性检查的详细信息传递给报告框架，如果断言失败，将显示这些信息，并且如果断言通过且 *reportPasses 为 true 且 *passVerbosity 未设置为 UnitTest.brief，也会显示。

this.assertFloatEquals(2, 2.0001, "Pass since 2 is close enough to 2.0001.", 0.001);
this.assertFloatEquals(2, 2.0001, "Fail since 2 isn't close enough to 2.0001.", 0.0001);

参数：

a

实验产生的 float 值

b

预期的浮点值

message

描述断言目的的消息，例如 "Adding two numbers should return their sum."。若 report 为 true 则发布。

within

a 必须处于 b 的范围之内，测试才能通过。

report

如果 true（默认值为 true），则报告测试结果。

onFailure

如果不是 nil，失败会停止测试并求值此函数。

.assertArrayFloatEquals(a, b, message: "", within: 0.0001, report: true, onFailure)

确保两个浮点数数组 a 和 b 在给定范围（within）内相等。

this.assertArrayFloatEquals([2, 3] + 0.0001, [2, 3], "Pass since pairs of floats are close enough", 0.001);
this.assertArrayFloatEquals([2, 3.0001], [2, 3], "Fail since pairs of floats aren't both close enough", 0.0001);

参数：

a

实验产生的值，是一个由浮点数组成的 Array

b

预期的浮点值 Array

message

描述断言目的的消息，例如 "Arrays foo and bar should be equal."。若 report 为 true 则发布。

within

每个 a 中的元素与 b 中对应元素的差异所允许的范围，以使测试通过。

report

如果 true（默认值为 true），则报告测试结果。

onFailure

如果不是 nil，失败会停止测试并求值此函数。

.ifAsserts(boolean, message, ifPassedFunc, ifFailedFunc, report: true)

仅当它通过时，或仅当它失败时，才做进一步断言。

(
a = UnitTest.new;
a.ifAsserts(2 == 3, "yes", { a.assert(2 == 4) }, { a.assert(1 == 1, "but this is correct") });
)

.assertException(func, errorClass, message, report: true, onFailure, details)

确保抛出特定的 Exception 或 Error。

参数：

func

在此函数中传入预期会抛出错误的代码。

errorClass

错误应属于的类或类名。

message

描述断言目的的消息。

report

如果 true（默认值为 true），则报告测试结果。

onFailure

如果不是 nil，失败会停止测试并求值此函数。

details

一些可选的额外细节，除非请求简要报告（参见 *passVerbosity），否则这些细节将传递给报告框架以供显示。

.assertNoException(func, message, report: true, onFailure, details)

确保特定的 Exception 或 Error 不会被抛出。有关参数，请参见 -assertException。

.wait(predicate, failureMessage: "", maxTime: 10.0)

等待谓词函数返回 true。超过 maxTime 后视为测试失败。仅在测试（或例程）内有效。

注意： 最好在测试中避免使用此方法。更好的选项请参见 CondVar: -waitFor。

(
{
    s.reboot;
    UnitTest.new.wait({ s.serverRunning }, "server failed to boot in time", 2);
}.fork
)

.bootServer(server)

等待服务器启动后再继续。仅在测试（或例程）中有效。

如果已启动，则执行 freeAll 并创建新的分配器。

(
{
    UnitTest.new.bootServer(s);
}.fork
)

.debug(text)

提供一些与当前正在运行的测试用例相关的调试信息。这些信息将显示在可能通过 -passed 和 -failed 的 details 参数显示的任何详细信息之前。

参数：

text

调试文本。

讨论：

test_myMethod {
    var obj = MyClass.new;
    this.debug("obj has color" + obj.color);
    this.assert(2 + 2, 5);
}

将导致：

FAIL: a TestMyClass: test_myMethod
obj has color red
Is:
         4
Should be:
         5

.passed(method, message, report: true, details)

注册一个通过的测试。

参数：

method

测试通过所在的方法名。

message

描述断言目的的消息，例如 "foo should be less than bar"。如果 report 和 *reportPasses 均不为 false，则会发布该消息。

report

如果为 true 且 *reportPasses 为 true，则报告测试的结果。

details

一些可选的额外细节，当 *reportPasses 为 true 且 *passVerbosity 未设置为 UnitTest.brief 时显示。

讨论：

this.passed(message: "this passed");

.failed(method, message, report: true, details)

注册一个测试失败。

参数：

method

测试失败所在的方法名。

message

描述断言目的的消息，例如 "foo should be less than bar"。当 report 为 true 时发布。

report

若为 true 则报告测试结果。

details

一些可选的额外细节，当 report 为 true 时显示。

讨论：

this.failed(message: "this failed");

示例

通过继承 UnitTest 并定义名称以 test_ 开头的方法来编写测试。每个测试方法都将从该子类的一个新实例中调用。

如果你在测试类中实现 setUp 和 tearDown 方法，它们将在每个测试之前和之后被调用。这有助于消除重复代码，并通过确保所有测试都在相同的条件下运行，使测试更易于维护。

TestYourClass : UnitTest {
    setUp {
        // 这将在每个测试之前被调用
    }
    tearDown {
        // 这将在每个测试后调用
    }

    test_yourMethod {
        // 所有名称以 "test_" 开头的方法都将被运行
        var synth;

        this.assert(6 == 6, "6 should equal 6");

        this.assertEquals(9, 9, "9 should equal 9");

        this.assertFloatEquals(4.0, 1.0 * 4.0 / 4.0 * 4.0,
            "floating point math should be close to equal");

        // 我们在一个 Routine 内部，可以等待
        1.0.wait;

        // 这将等待服务器启动
        // 如果服务器已经启动，它将释放所有节点
        // 并创建新的分配器，给你一个干净的状态
        this.bootServer;

        synth = { SinOsc.ar / 10 }.play;
        synth.register; 

        // 将等待直到条件为真
        // 10 秒后将被视为失败
        this.wait({ synth.isPlaying }, "waiting for synth to play", 10);
    }
}
