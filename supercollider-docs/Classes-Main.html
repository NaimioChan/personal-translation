Main

Process 的具体实例

Process : Object

另请参阅：StartUp

说明

Main 是 Process（虚拟机和解释器的运行时环境）的具体实例。Main 重写了 Process 的一些方法。有两个值得关注的方法。一个名为 startup，在类库编译完成后被调用。另一个名为 shutdown，在类库重新编译时被调用。

thisProcess

Main 的单例实例可通过特殊关键字 thisProcess 获取。例如，要查明你所在的平台：

thisProcess.platform;    // --> 例如 "an OSXPlatform"、"a LinuxPlatform"、...

类方法

SuperCollider 版本

这些类方法会告诉你正在运行的 SuperCollider 版本，以及该版本是否符合你要求的最低/最高设置：

Main.version

返回值：

当前版本，以人类可读字符串表示

Main.versionAtLeast(maj, min, patch)

如果我们运行的版本为 maj.min.patch 或更新版本，则返回 true，否则返回 false。如果 min 和/或 patch 为 nil，则将其视为通配符。版本中的 tweak 部分被完全忽略。

参数：

maj

作为 Integer 的主版本号。

min

次版本号，为 Integer，或 nil。

patch

补丁版本号，为 Integer，或 nil。

Main.versionAtLeast(3, 10, 4);

Main.versionAtMost(maj, min, patch)

如果我们运行的版本为 maj.min.patch 或更旧版本，则返回 true，否则返回 false。如果 min 和/或 patch 为 nil，则将其视为通配符。版本中的 tweak 部分被完全忽略。

参数：

maj

作为 Integer 的主版本号。

min

次版本号，为 Integer，或 nil。

patch

补丁版本号，为 Integer，或 nil。

Main.versionAtMost(3, 13, 9);

Main.scVersionMajor

返回值：

作为 Integer 的主版本号

Main.scVersionMinor

返回值：

作为 Integer 的次版本号

Main.scVersionPatch

返回值：

作为 Integer 的补丁版本号

Main.scVersionTweak

"tweak" 版本通常仅用于区分 SC 的预发布版本与正式版本。它可能为空。

返回值：

以字符串形式调整版本

Main.scVersionPostfix

来自扩展 /usr/local/share/SuperCollider/SCClassLibrary/deprecated/3.10/Main.sc

已弃用。请改用 scVersionPatch 和 scVersionTweak。

实例方法

.startup

在类库编译完成后调用。

讨论：

这会调用父类的 startup，其作用包括初始化 AppClock 和顶层 Environment。

Main 的启动过程随后将 Server.default 存入解释器变量 s，设置平台默认的 GUI 套件，调用特定于 Platform 的启动方法（例如，OSXPlatform 的启动会打开服务器窗口），最后调用 StartUp.run。

要添加你自己的启动功能，你可以编辑特殊的启动文件（在 Sclang Startup File 中讨论），或使用 StartUp 帮助文件中讨论的 StartUp.add。

.shutdown

在 SuperCollider 退出后或类库即将重新编译时调用。

讨论：

这将退出所有音频 Server 实例，执行平台特定的关闭（例如释放 HID 子系统），最后调用 Process 的 shutdown 方法，从而依次调用 UI.shutdown、NetAddr.disconnectAll、File.closeAll 和 Archive.write。要注册你自己的关闭代码，请使用如下调用：

ShutDown.add({ "Good bye!!".postln });

.run

重写此方法以执行任意所需操作，例如向类库中添加如下类扩展文件：

+ Main {
    run { "myPatch.rtf".load }
}

参数：

(newFunc)

要设置的 Function 或类似对象。求值时，该函数会接收参数 time、replyAddr 和 message，分别对应消息发送的时间、发送者的 NetAddr，以及消息本身（以 Array 形式）。

.addOSCRecvFunc(func)

注册一个 Function，每当 SuperCollider 语言（客户端）接收到 OSC 消息时求值。这不会覆盖任何先前注册的函数。

参数：

func

要添加的 Function 或类似对象。求值时，此函数将接收 msg、time、replyAddr 和 recvPort 参数，分别对应消息本身（作为 Array）、消息发送时间、发送者的 NetAddr，以及接收消息的端口。请注意，此顺序与已废弃方法 -recvOSCfunc 所使用的顺序不同。

// 打印所有传入流量，除了服务器状态消息
// 基本上与 OSCFunc.trace 相同
(
f = { |msg, time, replyAddr, recvPort|
    if(msg[0] != '/status.reply') {
        "At time %s received message % from % on port%\n".postf(time, msg, replyAddr, recvPort)
    }
};
thisProcess.addOSCRecvFunc(f);
);

// 停止发送。
thisProcess.removeOSCRecvFunc(f);

.removeOSCRecvFunc(func)

从每当 SuperCollider 语言（客户端）接收到 OSC 消息时被求值的函数列表中移除一个 Function。其他已注册的函数将保持不变。

参数：

func

要移除的 Function 或类似对象。

.replaceOSCRecvFunc(func, newFunc)

用另一个 Function 替换列表中每当 SuperCollider 语言（客户端）接收到 OSC 消息时求值的函数。其他已注册的函数将保持不变。

参数：

func

要被替换的 Function 或类似对象。

newFunc

用于替换正在被移除的函数的 Function 或类似对象。求值时，该函数将传入参数 time、replyAddr、recvPort 和 message，分别对应消息发送的时间、发送者的 NetAddr、接收消息的端口，以及消息本身（作为 Array）。

.openUDPPort(portNum, type: 'osc')

尝试打开一个新的 UDP 端口以接收 OSC 通信。如果另一个应用程序已绑定到所请求的端口，此操作将失败。一旦打开，端口将保持绑定状态，直到重新编译 SC。

如果端口已由 SC 打开，则直接返回 true，而不再次尝试打开端口。

参数：

portNum

一个 Integer，表示尝试绑定的端口。

type

一个 Symbol，取值为 \osc 或 \raw，指示期望接收的消息类型。\osc 将在 Main:recvOSCmessage 处接收回调，\raw 将在 Main:recvRawMessage 处接收回调。

返回值：

一个 Boolean，指示尝试是否成功。

thisProcess.openUDPPort(3000); // 将返回 true 或 false。
thisProcess.openPorts; // 返回所有打开的端口

.openPorts

获取所有活动 UDP 端口的集合，包括主 sclang 端口 NetAddr.langPort。

返回值：

一个 Set。

.pid

返回值：

该进程的操作系统 pid（进程 ID）。

.recompile

重新编译类库。

.platform

获取当前 Platform

.argv

获取传递给 sclang 的命令行参数。
