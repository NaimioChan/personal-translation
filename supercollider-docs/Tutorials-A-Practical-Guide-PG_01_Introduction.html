模式实现的细节，以及编写新模式类的指导

为什么用模式？

模式描述计算过程，而不必明确写出每一个步骤。它们是计算任务的一种更高层级的表示。虽然模式并非理想地适用于每一种计算类型，但在适用时，它们使用户无需操心过程的每一个细节。使用模式，人们编写的是应该发生什么，而不是如何去完成它。

在 SuperCollider 中，模式最适合需要生成信息序列或流的任务。这些信息通常是数字，但也不一定——模式可以生成任何类型的对象。

举个简单的例子，让我们从 0 开始向上计数。我们不知道需要数到多高；我们只知道每次请求值时，都应该得到一个持续递增的序列。

将所有内容写出来，看起来是这样的。使用 Routine 是因为这是一个控制结构，它可以中断正在做的事情并记住它进行到了哪里，以便能够在那个确切的位置继续。你可以从中获取一些数字，稍后再调用它，它会从最后返回的数字继续计数。（这是 Stream 的一个例子。你可以在 Understanding Streams, Patterns and Events - Part 1 中找到更多关于 Stream 的内容。）

a = Routine {
    var    i = 0;
    loop {
        i.yield;
        i = i + 1;
    };
};

a.nextN(10);

SuperCollider 的内置控制结构允许进行一些简化。

a = Routine {
    (0..).do { |i|
        i.yield;
    };
};

a.nextN(10);

但若能直接说“给我一个从 0 开始、每次递增 1 的无限数列”岂不是更好？使用 Pseries 就能做到。（此处为清晰起见使用了参数的关键字寻址，但 start、step 和 length 均可省略。）

a = Pseries(start: 0, step: 1, length: inf).asStream;

a.nextN(10);

模式表示法有哪些优点？

  • 它更短。
  • 它已经过测试并且可以正常工作。你无需调试 Pseries 的工作方式（而如果编写 Routine，则可能出错，然后还得去查找错误。）
  • 使用例程时——尤其是如果例程很复杂——你以后回看代码时必须自己去解读它。而模式直接在代码中说明了用途。

有哪些缺点？

  • 模式是一套需要学习的新词汇。在你掌握足够多的模式之前，很难信任它们。这就是本指南的目的！
  • 如果没有完全符合需求的模式，那么可能需要一些创造力才能将模式组合成新的设计。（自定义行为始终可以使用 Prout 编写。）

使用模式进行排序可能看起来像高级用法，但在许多情况下，它们比逐步写出的等效代码更简单。它们可以作为新用户和高级用户的桥梁，以更直接的方式表达音乐构想，而无需显式写出过多的连接结构。

学习一门新语言的第一步是词汇，因此下一章将集中介绍用于生成几乎各类数据流的基础模式。

模式与流

在整个讨论中需要牢记的一个重要背景是模式与流之间的区别。用最一般的话来说：

模式定义行为；流执行行为。

模式就像建筑的蓝图，展示了所有部件如何组合在一起。直到承包商按照图纸施工，建筑才存在。当从模式创建流时，流会遵循模式蓝图中规划的方案。将图纸转化为现实结果不会以任何方式改变蓝图，但为了得到结果，流必须经历不同的状态。

模式应当描述行为，一般而言，对模式求值（通过流的方式）不应改变 Pattern 对象本身的任何内容。用计算机科学术语来说，模式是无状态的；其定义不随时间改变。流负责记录我们在模式求值过程中所处的位置。

这解释了模式中一个容易出现的“陷阱”——忘记把模式转换为流就得不到预期的结果。由于模式没有当前状态的概念，对它调用 next 是没有意义的，因此 next 所做的事与它对大多数对象所做的一样：返回接收者对象本身。方法 asStream 会创建符合该模式规范的流，对流调用 next 会推进到它的下一个状态并返回新的值。

p = Pseries(0, 1, 10);
p.next;    // 始终返回 Pseries，而不是实际数字

q = p.asStream;
q.next;    // 反复调用此方法会得到期望的递增整数

这种严格的职责划分有实际的好处。由于流不修改原始模式，因此可以从同一个蓝图创建任意数量的流。所有这些流都维护各自独立的状态，并且可以并发运行而互不干扰。

r = p.asStream;
r.next;    // 从零开始，尽管 q 已经给出了一些数字

q.next;    // 从 q 离开的地方继续，从 r 获取值不会产生影响

[q.next, r.next]    // 等等……

在我们进入下一个主题时请记住这些要点：从模式中获取基本类型的数据（确定性的和随机的）。
