SynthDefs

使用 SynthDef 类来构建将在服务器上运行的 Synth 的引擎。这些引擎可以保存到磁盘并重复使用，类似于商业硬件和软件合成器上的预设。

当在客户端程序中以代码形式书写时，引擎有两个基本部分：一个名称和一个函数。在 SuperCollider 的术语中，该函数称为 ugenGraphFunc。

术语 ugenGraphFunc 源自图（graph）的概念，图是 SuperCollider 用来组织 unit generator 的数据结构。SuperCollider 会根据它在你的函数中找到的代码为你构建图，这意味着你不必了解图如何工作，甚至不必知道它的存在。

如果你想了解更多关于图的信息，请访问 Wikipedia：

http://en.wikipedia.org/wiki/Graph_(data_structure)

或者，转到

http://www.nist.gov/dads/HTML/graph.html

Template

下面是一个 synthdef 的模板，展示它由一个名称和一个 ugenGraphFunc 组成

SynthDef(
    "aSynthDef",                // 第一个参数是名称
    { .... i am a ugenGraphFunc ... }    // 第二个参数是 ugenGraphFunc
)

要使模板可用

  1. 将代码放入 ugenGraphFunc
  2. 向 synthdef 发送 .load 消息
(
SynthDef(
    "aSynthDef",                 // synthdef 的名称
    {                     // 带有实际代码的 ugenGraphFunc
        arg freq;
        Out.ar(
            0,
            SinOsc.ar(freq, 0, 0.1)
        )
    }
).load(s);
)

.load 消息和变量 's'

.load 消息将 synthdef 写入磁盘，同时也将它们发送到默认服务器。默认服务器由 SuperCollider 在启动时定义（为 localhost 服务器），此时它也被赋值给变量 's'。

.send 消息与远程服务器

另一方面，.send 消息，

SynthDef( .... ).send(s);

而不是 .load 消息

SynthDef( .... ).load(s);

是将 synthdef 发送到服务器的另一种方式。与 .load 消息不同，.send 消息不会先将 synthdef 写入磁盘，而是直接将 synthdef 传输到服务器。因此，当你想在一台计算机上定义 synthdef 但将其发送到另一台计算机时，应使用此消息。

(
var aServer;
aServer =
    Server(
        "aRemoteServerOnAnotherMachine",
        NetAddr("... an ip # ...", 57110)    // 另一台计算机上的服务器
    );
SynthDef( .... ).send(aServer);
)

注意： 自本教程编写以来，SynthDef 又添加了另一个通用方法。它叫做 .add，将成为替代 .load 和 .send 的新推荐标准。

SynthDef 浏览器

使用 synthdef 浏览器检查已写入磁盘的 synthdef。

(
// 一个合成器定义浏览器
SynthDescLib.global.read;
SynthDescLib.global.browse;
)

中间的框（顶行）显示 synthdef 的名称。选中每个名称时，其他框会显示某个特定 synthdef 的 ugens、controls 以及输入和输出。

标记为“SynthDef controls”的框很有用，因为它显示了可以传递给给定 synthdef 的参数。

浏览器显示，上面定义的 SynthDef——“aSynthDef”——由四个 UGen、一个 control、无输入和一个输出组成。这四个 UGen 包括 Control、SinOsc、BinaryOpUGen 和 Out 类的实例。

唯一的控件是 "freq"。控件是合成器在创建时或它在服务器上存在期间的任何时刻都可以使用的参数。浏览器还显示 "aSynth" 没有输入（这意味着它不使用来自音频总线或控制总线的数据），并且它向一条音频总线发送一个声道的音频。
