同步与异步执行

同时同步和异步执行的问题

使用 SuperCollider 这样的程序会引入许多关于时序和执行顺序的问题。实时音频合成要求按一定的速率和时间表计算并播放采样，以避免丢音、故障等。其他任务，例如将采样加载到内存中，可能花费任意长的时间，并且可能不需要在确定的时间范围内完成。这就是同步任务与异步任务的区别。

当同步任务依赖于异步任务的完成时，可能会出现问题。例如尝试播放一个可能尚未完全加载的样本。

在 SC2 中，处理这一点相对简单。在合成期间，即在 Synth.play 的作用域内，调度同步任务。异步任务按顺序在合成之外执行。因此，人们会首先创建缓冲区，将采样加载到其中，然后开始合成并播放它们。解释器确保只有在必要的前一步骤完成后才执行每一步。

在 SC3 中，语言与 synth 应用的分离带来一个问题：一侧如何知道另一侧已经完成了必要的任务，换言之，左手如何知道右手是否已经完成？新架构带来的灵活性引入了另一层复杂性，也对用户提出了额外的要求。

处理此问题的一种简单方法是以块为单位执行代码。例如，在以下代码中，每个代码块或每行代码都依赖于前一块或前一行完成。

// 一次执行一个

// 启动服务器
s.boot;

// 编译一个 SynthDef 并将其写入磁盘
(
SynthDef("Help-SynthDef", { arg out = 0;
     Out.ar(out, PinkNoise.ar(0.1))
}).writeDefFile;
)

// 将其加载到服务器
s.loadSynthDef("Help-SynthDef");

// 用它创建一个 Synth
x = Synth.new("Help-SynthDef", s);

// 在服务器上释放该节点
x.free;

// 允许客户端 Synth 对象被垃圾回收
x = nil;

在前面的示例中，有必要使用解释器变量（在编译时声明的变量 a-z），以便在后续的代码块或代码行中引用先前创建的对象。如果在一个代码块内声明了变量（即 var mySynth;），那么它只会在该作用域内持续存在。（更多细节请参阅帮助文件 Scoping and Closure。）

这种一次执行一行或一块代码的工作方式可以非常动态和灵活，在演出情境中尤其有用，特别是在即兴时。但它确实带来了作用域和持久性的问题。另一种允许使用更具描述性变量名的方法是使用环境变量（即以 ~ 开头的名字，例如 ~mysynth;，详情参见 Environment 帮助文件）。然而，在两种方法中，你都需要负责确保对象和节点在不再需要时不会继续存在。

(
SynthDef("Help-SynthDef", { arg out = 0;
    Out.ar(out, PinkNoise.ar(0.1))
}).send(s);
)

// 创建一个 Synth 并将其分配给环境变量
~mysynth = Synth.new("Help-SynthDef", s);

// 释放 synth
~mysynth.free;

// 但你仍然有一个 Synth 对象
~mysynth.postln;

// 所以把它从 Environment 中移除，这样 Synth 就会被垃圾回收
currentEnvironment.removeAt(\mysynth);

但如果你想要一个包含若干同步和异步任务的代码块呢？以下代码会导致错误，因为服务器所需的 SynthDef 尚未被接收。

// 一次性完成所有这些会产生错误 "FAILURE /s_new SynthDef not found"
(
var name;
name = "Rand-SynthDef" ++ 400.0.rand; // 使用随机名称以确保它尚未被加载

SynthDef(name, { arg out=0;
    Out.ar(out, PinkNoise.ar(0.1))
}).send(s);

Synth.new(name, s);
)

一种粗糙的解决方案是使用时钟，将依赖代码安排在看似足够的延迟之后执行。

// 这个可以工作，因为定义先到达服务器应用
(
var name;
name = "Rand-SynthDef" ++ 400.0.rand;

SynthDef(name, { arg out = 0;
    Out.ar(out, PinkNoise.ar(0.1))
}).send(s);

SystemClock.sched(0.05, {Synth.new(name, s);}); // 在 0.05 秒后创建一个 Synth
)

尽管这样可行，但并不是很优雅或高效。更好的做法是让下一件事在前一件事完成后立即执行。为了探究这一点，我们将看一个已经实现的示例。

你可能已经意识到，上面第一个示例是不必要的复杂。SynthDef-play 只需按一次回车键，就能一次性完成所有这些编译、发送以及 Synth 的创建。

// 一次性全部
(
SynthDef("Help-SynthDef", { arg out = 0;
    Out.ar(out, PinkNoise.ar(0.1))
}).play(s);
)

让我们看一下 SynthDef-play 的方法定义，看看它做了什么。

    play { arg target,args,addAction=\addToTail;
        var synth, msg;
        target = target.asTarget;

        synth = Synth.basicNew(name,target.server); // 创建一个 Synth，但不是 synth 节点
        msg = synth.newMsg(target, addAction, args);// 创建一个将添加 synth 节点的消息
        this.send(target.server, msg); // ** 发送 def，并将该消息作为完成消息
        ^synth // 返回 Synth 对象
    }

如果你不习惯钻研类定义，这可能看起来有点复杂，但重要的是 this.send(target.server, msg); 的第二个参数。这个参数是一个完成消息，它是服务器在发送动作完成后将执行的消息。在本例中，它表示在服务器上创建一个合成器节点，该节点对应于我已经创建的 Synth 对象，且仅当 def 已被发送到服务器应用程序时才会执行。（有关消息传递的详细信息，请参阅帮助文件 Server Command Reference。）

SC 中的许多方法都可以包含完成消息。这里我们可以使用 SynthDef-send 来完成与 SynthDef-play 相同的事情：

// 编译、发送并开始播放
(
SynthDef("Help-SynthDef", { arg out=0;
    Out.ar(out, PinkNoise.ar(0.1))
}).send(s, ["s_new", "Help-SynthDef", x = s.nextNodeID]);
// 这是 'messaging' 风格，见下文
)
s.sendMsg("n_free", x);

完成消息需要是一条 OSC 消息，但它也可以是一些在被求值时返回该消息的代码：

// 解释一些代码以返回完成消息。需要 .value。
// 这和前面的示例本质上与 SynthDef.play 相同
(
SynthDef("Help-SynthDef", { arg out=0;
    Out.ar(out, PinkNoise.ar(0.1))
}).send(s, {x = Synth.basicNew("Help-SynthDef"); x.newMsg; }.value); // 'object' 风格
)
x.free;

如果你更喜欢以“消息传递”风格工作，这非常简单。如果你更喜欢以“对象”风格工作，你可以对对象使用 newMsg、setMsg 等命令来创建相应的服务器消息。前面两个示例展示了这种差别。更多细节请参阅 Node Messaging 帮助文件。

对于 Buffer 对象，可以将函数用作完成消息。它将被求值，并将 Buffer 对象作为参数传入。这将在 Buffer 对象创建之后、消息发送到服务器之前发生。它还可以返回一条有效的 OSC 消息，供服务器在完成时执行。

(
SynthDef("help-Buffer",{ arg out=0, bufnum;
    Out.ar(
        out,
        PlayBuf.ar(1,bufnum,BufRateScale.kr(bufnum))
    )
}).load(s);

y = Synth.basicNew("help-Buffer"); // 尚未发送

b = Buffer.read(s, ExampleFiles.child, action: { arg buffer;
       // synth 发送其 s_new 消息以跟随
       // 在缓冲区读取完成后
       s.sendBundle(nil, y.newMsg(s,[\bufnum,buffer],\addToTail));
   }
);
)

// 完成后……
y.free;
b.free;

完成消息的主要目的是为服务器提供可在完成时立即执行的 OSC 消息。对于 Buffer，以下两者本质上没有区别：

(
b = Buffer.alloc(s, 44100,
    completionMessage: { arg buffer; ("bufnum:" + buffer).postln; }
);
)

// 这等同于上述内容
(
b = Buffer.alloc(s, 44100);
("bufnum:" + b).postln;
)

还可以用 OSCFunc 响应 'done' 消息（或任何其他消息）来求值一个函数。详见其帮助文件。

(
SynthDef("help-SendTrig",{
    SendTrig.kr(Dust.kr(1.0), 0, 0.9);
}).send(s);

// 注册以接收此消息
a = OSCFunc({ arg msg, time;
    ("This is the done message for the SynthDef.send:" + [time, msg]).postln;
}, '/done').oneShot; // 完成后自动移除我

b = OSCFunc({ arg msg, time;
    [time, msg].postln;
}, '/tr');
c = OSCFunc({ arg msg;
    "this is another call".postln;
}, '/tr');
)

x = Synth.new("help-SendTrig");
b.free;
c.free;
a.free;
