列表推导

列表推导式和生成器表达式

Introduction

列表推导式是函数式编程语言（如 Miranda、Haskell 和 Erlang）的一种语法特性，后来被引入到 Python 中。你可以在网上搜索“list comprehensions”或“generator expressions”以了解更多。基本上，列表推导式用于获取某个问题的一系列解。

在 SC 中，这些只是一个更长表达式的语法宏。将其读作 “对 1..5 中的 x、1..x 中的 y，满足 x+y 为素数，取所有 [x,y]”：

all {:[x,y], x <- (1..5), y <- (1..x), (x+y).isPrime }

returns:

[ [ 1, 1 ], [ 2, 1 ], [ 3, 2 ], [ 4, 1 ], [ 4, 3 ], [ 5, 2 ] ]

上面的列表推导式等价于以下代码：

all(Routine.new({ (1..5).do {|x| (1..x).do {|y| if ((x+y).isPrime) {[x,y].yield} }}}));

……但比把它完整写出来要简洁得多，也更容易记住。

在列表推导编译器中，像 (1..5) 和 (1..x) 这样的简单序列被当作特殊情况处理，并实现为循环而不是创建集合。

SC 中的列表推导实际上是一个 Routine。你可以使用 all 消息将 Routine 的所有结果收集到一个列表中。

几个示例

all {: x/(x+1), x <- (1..5) }

[ 0.5, 0.66666666666667, 0.75, 0.8, 0.83333333333333 ]
all {:[x,y], x <- (1..3), y <- [\a,\b,\c] }

[ [ 1, a ], [ 1, b ], [ 1, c ], [ 2, a ], [ 2, b ], [ 2, c ], [ 3, a ], [ 3, b ], [ 3, c ] ]
all {:[x,y], x <- (0..3), y <- (x..0) }

[ [ 0, 0 ], [ 1, 1 ], [ 1, 0 ], [ 2, 2 ], [ 2, 1 ], [ 2, 0 ], [ 3, 3 ], [ 3, 2 ], [ 3, 1 ], [ 3, 0 ] ]
all {:y, x <- (1..4), y <- (x..1) }

[ 1, 2, 1, 3, 2, 1, 4, 3, 2, 1 ]
(
var intervals;
// 一个用于生成和弦排列中所有音符对之间音程的函数
intervals = {|chord|
    all {: chord[i+gap] - chord[i],
        gap <- (1 .. chord.lastIndex),
        i <- (0 .. chord.lastIndex - gap)
    }
};

intervals.([0,4,7,10]).postln;
intervals.([0,1,3,7]).postln;
)

[ 4, 3, 3, 7, 6, 10 ]
[ 1, 2, 4, 3, 6, 7 ]
all {:[y, z], x<-(0..30), var y = x.nthPrime, var z = 2 ** y - 1, z.asInteger.isPrime.not  }
[ [ 11, 2047 ], [ 23, 8388607 ], [ 29, 536870911 ] ] // 不是素数的梅森数

限定子句

列表推导式以 {: 开头，包含一个主体，其后是以逗号分隔的若干限定子句。

{: body , qualifiers }

有几种类型的限定子句可以出现在主体之后。

生成器子句

基本子句是生成器子句。其语法为

name <- expr

表达式应该是能够对 'do' 做出有意义响应的对象，例如集合或流。name 依次取表达式的每个值。name 是一个局部变量，其作用域延伸到右侧的所有子句。name 在主体中也处于作用域内。

all {: x, x <- (1..3) }

[ 1, 2, 3 ]
all {: x, x <- [\a, \b, \c] }

[ a, b, c ]
all {: x, x <- (1!3)++(2!2)++3 }

[ 1, 1, 1, 2, 2, 3 ]

多个生成器的作用类似于嵌套循环。

all {: [x,y], x <- (1..2), y <- (10,20..30) }

[ [ 1, 10 ], [ 1, 20 ], [ 1, 30 ], [ 2, 10 ], [ 2, 20 ], [ 2, 30 ] ]

生成器可以依赖先前的值。

all {: x, x <- (1..3), y <- (1..x) }

[ 1, 2, 2, 3, 3, 3 ]
all {: x, x <- (1..3), y <- (1..4-x) }

[ 1, 1, 1, 2, 2, 3 ]

守卫子句

守卫子句只是一个表达式。它应返回一个布尔值。

expr

guard 充当结果的过滤器并约束搜索。

all {: x, x <- (0..10), x.odd }

[ 1, 3, 5, 7, 9 ]

x.odd 是守卫条件，会使所有偶数被跳过。

all {: x, x <- (0..30), (x % 5 == 0) || x.isPowerOfTwo }

[ 0, 1, 2, 4, 5, 8, 10, 15, 16, 20, 25, 30 ]

你可以有多个守卫。

all {: [x,y], x <- (0..10), (x % 5 == 0) || x.isPowerOfTwo, y <- (1..2), (x+y).even }

[ [ 0, 2 ], [ 1, 1 ], [ 2, 2 ], [ 4, 2 ], [ 5, 1 ], [ 8, 2 ], [ 10, 2 ] ]

var 子句

var 子句允许你创建一个新的变量绑定，以便在表达式中使用。该名称的作用域延伸到右侧的所有子句以及主体中。

var name = expr

与生成器子句不同，名称绑定到单个值，不会迭代。

all {: z, x <- (1..20), var z = (x*x-x) div: 2, z.odd }

[ 1, 3, 15, 21, 45, 55, 91, 105, 153, 171 ]

副作用子句

此子句允许你插入代码以执行某些副作用，例如打印。

\:: expr
all {: z, x <- (1..20), var z = (x*x-x) div: 2, :: [x,z].postln, z.even }

终止子句

终止子句用于停止进一步搜索结果。一旦表达式变为 false，例程便停止。

:while expr

使用守卫

all {: z, x <- (1..20), var z = (x*x-x) div: 2,  :: [x,z].postln, z < 50 }

使用终止子句。这个会停止搜索，因此比上面的做法工作量更少。

all {: z, x <- (1..20), var z = (x*x-x) div: 2,  :: [x,z].postln, :while z < 50 }

约束搜索

列表推导可以解决像这样的受约束组合问题：

Baker、Cooper、Fletcher、Miller 和 Smith 住在一栋只有五层的公寓楼的不同楼层。Baker 不住在顶层。Cooper 不住在底层。Fletcher 既不住在顶层也不住在底层。Miller 住的楼层比 Cooper 高。Smith 不住在与 Fletcher 相邻的楼层。Fletcher 不住在与 Cooper 相邻的楼层。每个人住在哪里？

(
z = {: [baker, cooper, fletcher, miller, smith] ,
    var floors = (1..5),
    baker <- floors,  baker != 5,  // Baker 不住在顶层。
    // 从列表中移除 baker's floor。
    // var 会创建一个新作用域，因此左侧的 'floors' 是一个新绑定。
    var floors = floors.removing(baker),
    cooper <- floors, cooper != 1, // Cooper 不住在底层。
    var floors = floors.removing(cooper), // 从列表中移除 cooper 的地板。
    fletcher <- floors, (fletcher != 5) && (fletcher != 1) // Fletcher 既不住在顶层也不住在底层。
        && (absdif(fletcher, cooper) > 1), // Fletcher 不住在 Cooper 的相邻楼层。
    var floors = floors.removing(fletcher), // 移除 fletcher 的下限
    miller <- floors, miller > cooper, // Miller 住在比 Cooper 更高的楼层。
    var floors = floors.removing(miller), // 移除 Miller 的地板
    smith <- floors, absdif(fletcher, smith) > 1  // Smith 不住在 Fletcher 的相邻楼层。
};
)

z.next; // [3, 2, 4, 5, 1 ]
z.next; // nil。只有一种解

组合问题可能需要运行很长时间。你可以重新排列上面的测试以使其运行得更快。通常你希望先搜索约束最多的变量。上面约束最多的人是 fletcher，所以应该先搜索他们，然后是 cooper，等等。

Grammar

以下是 SC 中列表推导式的 BNF 语法。

[ ] - optional
{ } - zero or more

<list_compre> ::= "{:" <body> ',' <qualifiers> "}"

<body> ::= <exprseq>

<exprseq> ::= <expr> { ";" <expr> }

<qualifiers> ::= <qualifier> { ',' <qualifiers> }

<qualifier> ::= <generator> | <guard> | <binding> | <side_effect> | <termination>

<generator> ::= <name> "<-" <exprseq>

<guard> ::= <exprseq>

<binding> ::= "var" <name> "=" <exprseq>

<side_effect> ::= "::" <exprseq>

<termination> ::= ":while" <exprseq>

代码生成

对于上述每个子句，以下是代码的生成方式。主体作为最内层的限定符。理解这些转换，你就能更好地理解列表推导式中的作用域和控制流是如何工作的。

generator
expr.do {|name| ..next qualifier.. }
guard
if (expr) { ..next qualifier.. }
binding
{|name| ..next qualifier.. }.value(expr)
副作用
expr ; ..next qualifier..
termination
if (expr) { ..next qualifier.. }{ nil.alwaysYield }
