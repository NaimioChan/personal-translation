Task

一个可暂停的进程

PauseStream : Stream : AbstractFunction : Object

另请参阅：Routine

说明

Task 是一个可暂停的进程。它通过将 PauseStream 包装在 Routine 周围来实现。它的大多数方法（start、stop、reset）继承自 PauseStream。

Task 的用途是将 Routine 的执行状态与其运行状态（即，它是否被调度在某个时钟上，或者是否暂停在某个 CondVar 中）分离开来。如果你预计该过程需要在保持执行流的同时多次启动、停止或恢复，请使用 Task。（这意味着 Task 与 Routine 并非 100% 可以互换——在许多用途中，应优先使用 Task 而非 Routine。）

请注意，停止任务并快速重新启动它可能会产生令人惊讶的结果（参见下面的示例），但这是必要的，以防止任务在快速连续启动和/或停止时变得不稳定。（例程确实允许快速的停止-重置-播放循环，但它们没有机制来防止这种情况下时序被破坏，也就是说 Routine 在这方面更为脆弱。）如果你需要在保持时序的同时快速启动和停止，更好的方法是将子 Routine 换到 PauseStream 的新实例上。

类方法

Task.new(func, clock)

参数：

func

一个要被求值的 Function。

clock

用于播放 Routine 的 Clock。如果你不提供 Clock，默认是 TempoClock 的实例。请记住，调用 Cocoa 原语的方法（即 GUI 函数）必须在 AppClock 中播放。

实例方法

.play(argClock, doReset: false, quant)

来自父类：PauseStream

参数：

argClock

（可选）覆盖 Task.new 中分配的时钟。

doReset

如果为 true，任务将从头开始。默认值为 false（任务将从上次停止处继续）。

quant

参见 Quant 帮助文件。

其他控制方法

.start(argClock, quant)

来自父类：PauseStream

从头重新启动任务。

.resume(argClock, quant)

来自父类：PauseStream

从任务中断处恢复。

.pause

来自父类：PauseStream

立即停止播放。

.stop

来自父类：PauseStream

立即停止播放。（暂停和停止具有相同的实现。）

.reset

来自父类：PauseStream

将流设置为下次播放时从头重新开始。

.reschedule(argClock, quant)

来自父类：PauseStream

在不停止的情况下，将 Task 切换到不同的时钟或不同的时间。完整文档请参见 Routine: -reschedule。

注意： 如果你想要在 Task 自身内部重新调度 Task，thisThread.reschedule(...) 将无法工作，因为 thisThread 指的是受 Task 控制的 Routine，而不是 Task 本身（而 Routine 是直接在时钟上播放的）。你必须改用 thisThread.threadPlayer.reschedule(...)。

Notifications

其他对象可能需要感知 task 状态的变化。以下通知会广播给注册到 Task 对象上的依赖对象。

  • \userPlayed - 在用户调用 play、start 或 resume 时发送。
  • \playing - 在任务开始于时钟上播放时发送（对应于 quant）。
  • \userStopped - 在用户调用 pause 或 stop 时发送。
  • \stopped - 在任务最终从时钟移除时发送（这是如果任务未被停止，下一个事件本应发生的时间）。如果任务函数自行完成，则发送此通知，而不会事先发送 'userStopped'。

示例

如果过快停止并启动任务会发生什么？

(
t = Task({
    50.do({ |i|
        i.squared.postln;
        0.5.wait;
    });
});
)

t.start;
t.pause;
t.resume;
t.reset;
t.stop;

// 此处出现意外行为
(
t = Task({
    ["go", thisThread.clock.beats].postln;
    inf.do({ |i|
        2.wait;
        ["wake up", i].postln;
    });
});

fork {
    t.start;
    0.1.wait;
    t.stop;
    0.1.wait;
    t.start;
    6.wait;
    t.stop;
};
)

[go, 1702.114411906]
[go, 1704.114411906]

基于所派生的线程，你会预期第二行“go”输出在第一个之后 0.2 秒出现，但实际上它在两秒之后才出现（与任务在迭代之间等待的时间相同）。这是因为任务不得在时钟上多次调度自己。当任务被停止时，它会保持已调度状态，直到再次唤醒（基于其等待时间）。如果在此间隔期间重新启动该任务，调度器队列中就会有两个对该任务的引用——这种情况除了用 command-period 停止一切之外无法恢复。

对于上述情况，你可以通过手动将 Routine 包装在 PauseStream 中来获得完全稳定的计时。注意，start 会隐式地将 routine 重置到开头；改用 play 只会改变计时，而不会中断 routine 的流程。

(
r = Routine({
    ["go", thisThread.clock.beats].postln;
    inf.do({ |i|
        2.wait;
        ["wake up", i].postln;
    });
});

fork {
    t = PauseStream(r);
    t.start;  // 打印 "go..."
    0.1.wait;
    t.stop;   // 但在循环打印之前停止
    0.1.wait;
    t = PauseStream(r);
    t.start;  // 打印 "go..."
    6.wait;   // 允许循环运行 2 个周期
    t.stop;
};
)
