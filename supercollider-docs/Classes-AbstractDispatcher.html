AbstractDispatcher

将传入的消息分派给 Functions

Object

另请参见：AbstractWrappingDispatcher、OSCMessageDispatcher、OSCMessagePatternDispatcher、MIDIMessageDispatcher、OSCFunc、OSCdef、MIDIFunc、MIDIdef、AbstractResponderFunc

子类：AbstractWrappingDispatcher

说明

AbstractDispatcher 的实例将传入消息（例如 MIDI、OSC）分发给已注册的 AbstractResponderFunc 实例。每种消息类型都会有一个默认分发器，但也可以为每种类型设置多个分发器，以便为 ResponderFunc 组实现自定义分发。（这方面主要的例子是使用 OSCMessagePatternDispatcher 进行 OSC 模式匹配。）通常用户不需要直接访问分发器实例。

分派器必须在适当的中心位置注册（例如，OSC 消息在 Main:recvOSCfunc 处注册）。在这一角色中，它们的接口模仿 Function 和 FunctionList。

类方法

AbstractDispatcher.all

获取所有当前活动调度器的集合。

返回值：

一个 IdentitySet。

AbstractDispatcher.new

创建一个新的调度器。

返回值：

一个新实例。

实例方法

.add(funcProxy)

向此分派器添加一个响应函数。子类应重写此方法以执行任何必要的记录工作。通常此方法应将此分派器添加为响应函数的依赖对象，以便它能响应任何变化。

参数：

funcProxy

要添加的 AbstractResponderFunc 子类的实例。

.remove(funcProxy)

从此调度器中移除一个响应函数。

参数：

funcProxy

要移除的 AbstractResponderFunc 子类的实例。

.value

评估传入消息以查看是否匹配。子类应重写此消息以接收适当的参数。如果找到匹配的响应函数，此方法应调用其 value，并传入该消息。

.valueArray(args)

与上面的 -value 相同，但参数以单个 Array 传入。需要此方法是为了让子类能够在中心消息注册点（如 Main:recvOSCMessage）的 FunctionList 中工作。

参数：

args

一个包含消息及相应参数的 Array。

.register

将此分派器注册到适当的中心点（例如 Main:recvOSCfunc）以接收其消息类型。子类应注意不要覆盖任何其他已注册的对象。（因此，例如对于 OSC 消息，应使用 Main:addOSCFunc 而不是 Main:recvOSCfunc_。）一般来说，分派器应在添加响应函数时根据需要自动注册自身。

.unregister

从适当的中央注册点移除此 dispatcher，即停用它。一般来说，dispatcher 应在移除其最后一个 responder 函数时自动注销自身。

.free

-unregister 注销此调度器并将其从 *all 中移除。此后该调度器应被丢弃。

.typeKey

子类应重写此方法，以返回一个表明此分派器响应何种消息类型的键，例如 'OSC matched' 或 'MIDI control'。

返回值：

一个 Symbol。

.update

当调度器的响应函数通过标准依赖机制表明它们已改变时，子类应重写此方法以执行任何必要的更新。默认实现不做任何事。
