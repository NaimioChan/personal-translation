GUI：你可能想了解的事项

关于 SuperCollider 的 GUI 系统，你可能想了解的一些杂项内容。

GUI 教程

此帮助文件是 GUI 教程 的一部分。

渲染并不总是可用

SuperCollider 提供了一些有用的类来自动化处理过程。其中一些与 Clock 相关联：主要是 Routine 和 Task。

在时钟相关线程的上下文中，Qt 渲染系统不可用。换句话说，你无法在 Routine 或 Task 中“直接”修改控件。

取而代之的是，你需要通过将其封装在一个延迟函数中来推迟修改，该函数将在 SuperCollider 恢复其主上下文后执行，参见 Function: -defer。否则会导致程序崩溃：

(
var win = Window();
var slider= Slider();
var value = 0;

var routine = Routine({
    loop {
        value = 101.rand / 100;
        // 在 routine 中与 widget 交互：
        // 指令必须嵌套在函数中，并延迟执行
        { slider.value_(value); }.defer;
        0.5.wait;
    };
}).play;

win.layout_(
    VLayout()
    .add(slider)
);

CmdPeriod.doOnce({
    routine.stop;
    win.close;
});

win.front;
)

Qt 限制

这一说明主要涉及调试和理解问题。由于 Qt 是集成在 SuperCollider 内的第三方库，它的一些限制与 SuperCollider 本身无关。

举例来说，在撰写本文时，Qt 的 QImage 有严格的像素限制，不能超过 32767x32767 像素。这个“问题”仅与 Qt 相关，记录在 Qt 的源码/论坛中，而不在 SuperCollider 的源码/论坛中。换言之，在 SuperCollider 环境中使用 Qt 时，也可能需要直接使用 Qt 的文档。

Pen 的使用与资源管理

Pen 类允许用户为 View 定义自定义的 drawFunc。

Pen 的使用是一个两步过程：用户首先“描述”想要绘制的形状（使用 fillRect 或 lineTo 等方法），然后渲染该形状，使用 fill、stroke 或 fillStroke。

取决于硬件，在绘制非常复杂的形状时（例如一百万条线），可能会出现一些问题：

绘制指令会被缓存，直到被绘制为止。这意味着在调用 stroke 之前调用 lineTo 一百万次，可能会在 stroke 指令实际执行并释放缓存的指令之前耗尽计算机的 RAM。

另一方面，连续调用 lineTo 然后 stroke 一百万次可能在时间上效率低下，因为多个 lineTo 本可以在绘制到屏幕之前被组合在一起。

在这种情况下，最佳解决方案是测试多种配置，以最有效的方式平衡 RAM/CPU 使用率。
