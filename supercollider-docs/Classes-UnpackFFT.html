UnpackFFT

将 FFT 链解包为独立的 demand-rate FFT bin 流

MultiOutUGen : UGen : AbstractFunction : Object

另请参阅：PackFFT、Unpack1FFT

说明

接收一个 FFT 链，将幅度和相位数据分离为各自独立的按需速率流，以便进行算术运算等。

从技术上讲，这是一个 demand-rate UGen。实际的“需求”通常由图中稍后的 PackFFT 创建，它按顺序请求这些值以重新打包数据。这允许在此期间进行处理。

另请参见 PV_ChainUGen: -pvcollect、PV_ChainUGen: -pvcalc 和 PV_ChainUGen: -pvcalc2，它们提供了在频域中处理音频的便捷方式。pvcollect 的帮助文档中包含关于效率考量的说明。

类方法

UnpackFFT.new(chain, bufsize, frombin: 0, tobin)

参数：

chain

FFT 链

bufsize

FFT 缓冲区大小

frombin

将分析限制在感兴趣的频段

tobin

将分析限制在感兴趣的频段

返回值：

从 DC 到 Nyquist 的列表：[mag[0], phase[0], mag[1], phase[1], ... mag[nyquist], phase[nyquist]].

讨论：

注意，你必须事先确定 FFT 缓冲区大小，因为这决定了该 UGen 将输出多少个值。

#magsphases = UnpackFFT(chain, bufsize)

实例方法

示例

// 这个只是拖出各种值并打印出来 - 有点无意义！
(
{
    var sig, chain, stream, windowStarts, fftSize;
    fftSize = 1024;

    sig = SinOsc.ar(LFDNoise3.kr(LFNoise0.kr(1) * 40 + 60) * 700 + 800);
    chain = FFT(LocalBuf(1, fftSize), sig);

    // 窗口起点由离开 -1 底线的信号指示
    windowStarts = chain > -1;

    // 使用 frombin 与 tobin 参数会高效得多，可将分析限制在感兴趣的 bin 上
    stream = UnpackFFT(chain, fftSize, frombin: 0, tobin: 4);

    // 从解包器请求一些数据。
    // 注意：目前，Demand.kr 无法处理超过 32 个输入，
    // 因此必须使用 frombin 和 tobin 来限制 bin 的数量。

    Demand.kr(windowStarts, 0, stream).collect { |anunp, index|
        var label = if(index.even) { "Magnitude" } { "Phase" };
        label = label + (index / 2).floor;
        anunp.poll(windowStarts, label)
    };

    sig * 0.05
}.play
)

// 简单的频域操作，对幅度和相位都取平方根。
(
x = {
    var sig, chain, magsphases, b;
    b = LocalBuf(1, 1024);
    sig = SinOsc.ar(LFDNoise3.kr(LFNoise0.kr(1) * 40 + 60) * 700 + 800);
    chain = FFT(b, sig);
    magsphases = UnpackFFT(chain, b.numFrames);
    magsphases = magsphases.collect(_.sqrt);
    chain = PackFFT(chain, b.numFrames, magsphases);
    IFFT(chain) * 0.1
}.play
)
