编写类

编写 SuperCollider 类

另请参阅：Classes、Class、Object

SuperCollider 遵循纯面向对象范式。它不是建立在数据类型之上，而是建立在对象之上，对象对消息作出响应。类是一个对象，它保存着关于其对象（实例）如何响应此类消息的信息。编写一个类就是给出这种行为的定义。

这是编写类时所用惯用法的概述。它不是关于编写相互关联的类体系的教程。它概述了一些典型的表达式。另请参见：Introduction to Objects、Messages 和 Classes。

此外还有当前完整类树的概览。

注意： 类定义在你启动 SuperCollider 或“重新编译类库”时被静态编译。这意味着类定义必须保存到扩展名为 .sc 的文件中，放在 SuperCollider 查找类的磁盘位置。一般不建议保存到主类库（SCClassLibrary）中。最好使用用户或系统扩展目录。Platform.userExtensionDir; // 仅对你的用户账户可用的扩展 Platform.systemExtensionDir; // 对机器上所有用户可用的扩展 无法在解释器窗口中输入类定义并执行它。

Inheriting

为了避免多次编写相同的代码，类可以从其父类继承实现。

MyClass : SomeSuperclass {

}

未指定父类时，默认采用 Object 作为父类。

MyClass { // : 隐含 Object

}

这就是为什么在上面的例子中，消息 new 可以在类中未显式定义的情况下被调用。

Methods

实例方法

每个对象实例都响应其实例方法。实例方法在对象的本地上下文中调用。在实例方法内部，关键字 this 指代实例本身。

MyClass {

    instanceMethod { | argument |
        this.anotherInstanceMethod(argument)
    }

    anotherInstanceMethod { | argument |
        "hello instance".postln
    }
}

然后可以按如下方式使用：

a = MyClass.new // 返回一个新实例
a.instanceMethod // 输出 "hello instance"

要从方法中返回，请使用 ^（脱字符）。也可以有多个退出点。如果未指定 ^，方法将返回实例（对于类方法，则返回该类）。SuperCollider 中不存在返回 void 的概念。

MyClass {
    someMethod {
        ^returnObject
    }

    someOtherMethod { | aBoolean |
        if(aBoolean) {
            ^someObject
        } {
            ^someOtherObject
        }
    }

}

类方法

对象的类方法与其实例方法定义在一起。它们在方法名前用星号（*）标示。

类本身就是一个对象。它就是其所有实例共有的东西。类方法是该对象所属类的方法。这就是为什么在类方法中，关键字 this 指代该类。

MyClass {
    *classMethod { | argument |
        this.anotherClassMethod(argument)
    }

    *anotherClassMethod { | argument |
        "hello class".postln
    }

}

然后可以按如下方式使用：

MyClass.classMethod // 输出 "hello class"

重写方法（重载）

要改变从父类继承的行为，可以重写方法。注意，对象总是先查找它自己定义的方法，然后再到父类中查找。这里 MyClass.value(2) 将返回 6，而不是 4：

SomeSuperclass {
    calculate { |in| ^in * 2 }
    value { |in| ^this.calculate(in) }
}

MyClass : SomeSuperclass {
    calculate { |in| ^in * 3 }
}

关键字 super 可用于调用父类上的方法

SomeSuperclass {

    value {
        ^100.rand
    }
}

MyClass : SomeSuperclass {

    value {
        ^super.value * 2
    }
}

Instances

Object.new 会返回一个新对象。重写类方法 .new 时，你必须调用父类，父类又会调用其父类，直到调用 Object.new，实际创建对象并为其分配内存。

MyClass {
    // 这是一个普通的构造函数方法。
    *new { ^super.new }
}

在这种情况下请注意，super.new 会在父类上调用方法 new 并返回一个新对象。

实例变量与初始化逻辑

实例可以有关联的变量——在其他语言中称为成员。

Foo {
    var a, b, c; // 实例变量。
}

这些可以通过两种方式赋值。通过 newCopyArgs 或通过 init 方法。推荐使用前者，并首先讨论。

可以不调用 new 方法，而是调用 Object: *newCopyArgs 来初始化成员。

下面的代码允许调用处决定 c 的初始值，并将 a 默认为 10、b 默认为 20。

Foo {
    var a, b, c;
    *new { |myC| ^super.newCopyArgs(a: 10, b: 20, c: myC) }
}

如果需要在赋值前准备参数的初始化逻辑，理想情况下应将其放在调用 super.newCopyArgs 之前。这样最终对象就永远不会处于无效状态——另一种做法是使用 init 方法，稍后将展示。

然而，当存在类的层次结构时，newCopyArgs 要求所有基类的参数按照它们定义的顺序传入。这使得更改基类变得困难。下面是一种利用可变关键字参数 Functions: Variable Arguments 和 Object: -superPerformArgs 来缓解此问题的方法。

Base {
    var <>a, <>b;
    *new { |a, b ...args, kwargs|
        ^super.superPerformArgs(\newCopyArgs, [a, b] ++ args, kwargs);
    }
}

Derived : Base {
    var <>c;
    *new { |a, b, c ...args, kwargs|
        ^super.superPerformArgs(\new, [a, b, c] ++ args, kwargs)
    }
}

调用 Derived(1, 2, 3) 会将 a 设为 1，b 设为 2，c 设为 3。以下是一些更多示例：

Derived(c: 10) // a: nil, b: nil, c: 10
Derived(1, 2, c: 10) // a: 1, b: 2, c: 10
Derived(d: 10) // 如果 'd' 存在于层级中的某个位置，它就会被赋值为 10。

虽然这种方法可能看起来复杂，但其好处在于，新的实例变量可以添加到任一 类 中，并且你始终能明确自己打算赋值给哪一个。

如果将来希望移除基类的实例变量，那么要求只使用关键字参数是好的做法。这可以通过移除具名参数并在 args 非空时抛出错误来实现。这样做的一个缺点是 IDE 中的自动补全将无法工作。

Foo {
    *new { |... args, kwargs| 
        if(args.empty.not) { Error().throw };
        ^super.superPerformArgs(\newCopyArgs, #[], kwargs);
    }
}

另一个好处是实例永远不会处于不完整状态：要么所有实例成员都已赋值，要么该对象不存在。

缺点出现在你拥有复杂的初始化逻辑时，其中 Derived 中的参数需要了解 Base 中的参数。在 SuperCollider 中，传统上通过如下所示的 init 方法来解决，尽管对于复杂情况也可以考虑使用“构建器”模式。

Base {
    var a, b;
    *new {|a, b| ^super.new.init(a, b) }
    init {|newA, newB|
        // 初始化逻辑放在这里。
        a = newA;
        b = newB;
    }
}

这样可行，但在继承链中会变得更复杂。

Base {
    var a, b;
    *new {|a, b| ^super.new.init(a, b) }
    init {|newA, newB|
        // 初始化逻辑放在这里。
        a = newA;
        b = newB;
    }
}

Derived : Base {
    var c;
    *new { |a, b, c| ^super.new.derivedInit(a, b, c) }
    derivedInit { |newA, newB, newC|
        // 使用所有参数进行初始化
        this.init(newA, newB) // 调用 Base.init
        c = newC; // 赋值给 Derived 的 c
    }
}

警告： 如果 Base 和 Derived 类都定义了 init 方法，Derived 类将覆盖 Base 的实现，这意味着将不再可能调用该实现。在这种情况下，应使用像 myclassInit 这样的唯一方法名，或者更好的是，使用能表明执行何种初始化的专门名称。

虽然 init 模式最为灵活，但必须小心：在 init 函数内部，实例处于不完整状态，其他方法可能无法按预期工作；例如，当与线程和异步执行结合时（例如与服务器交互时），这可能会变得令人困惑。

类实例

类变量可在类方法以及任何实例方法中访问。

MyClass {
    classvar myClassvar;

    instanceMethod {
        ^myClassvar
    }
}

类级别的初始化（例如设置 classvar）可以通过重载 Class: *initClass 方法来实现。

MyClass {
    classvar myClassvar;

    *initClass {
        myClassvar = IdentityDictionary.new;
    }
}

继承的替代方案

过度依赖继承通常是一种设计缺陷。继承主要是组织代码的一种方式，不应被误认为是对象的分类。两个对象可能以不同方式响应同一消息（多态），并且对象会将其控制权委托给其实例变量中持有的其他对象（对象组合）。

Polymorphism

另请参阅：Polymorphism

两个完全不相关的对象可以响应相同的消息，因此可以在同一段代码中一起使用。例如，Function 和 Event 除了通用类 Object 之外没有共同的父类。但两者都响应消息 play。你可以不必继承所有方法，而只需在你的类中实现其中一些相同的方法。

MyClass {
    var count = 0;
    value {
        ^count = count + 1
    }
}
// 此类的对象会响应消息 "value"，就像函数一样。
a = MyClass.new;
a.value; // 返回 1

对象组合

对象常常将控制权交给其实例变量中的某个对象。因为这些对象可以是任意类型，所以这是实现各种功能的一种非常灵活的方式。例如，Button 有一个 action 实例变量，它可以保存任何响应 value 消息的对象。

MyClass {
    var action;
    *new { |action|
        ^super.newCopyArgs(action)
    }
    value { |x|
        action.value(x);
    }
}

// 取决于 "action" 是什么，此类的对象会表现不同
a = MyClass({ "hello." });
b = MyClass({ |i| log2(i) * sin(i * pi) });
a.value(8);
b.value(8);

通常，像上面 action 这样的变量会填入属于 MyClass 的自定义对象。因此，人们会编写许多小型类，以便能够以这种方式很好地组合使用。这被称为“可插拔行为”。

Variables

直接初始化变量

在变量声明中，可以直接初始化变量。只有 Literals 可以用于以这种方式初始化变量。这意味着无法进行链式赋值（例如 var x = 9; var y = x + 1）。

MyClass {
    classvar all = #[];
    var x = 8;
    var y = #[1, 2, 3];
}

变量作用域

实例变量可以从该类的所有实例方法及其子类访问。相比之下，类变量可以从该类的所有类方法和实例方法及其子类访问。实例变量将遮蔽同名的类变量。

MyClass {
    classvar x = 0, y = 1;
    var x = 1;

    *returnX { ^x } // 返回 0
    returnX { ^x } // 返回 1
    returnXY { ^x + y } // 返回 2
}

子类可以覆盖类变量声明（但不能覆盖实例变量）。此时超类的类变量在子类中不再可访问。

SomeSuperclass {
    classvar x = 0;

    returnX { ^x }
    returnXHere { ^x }
}

MyClass : SomeSuperclass {
    classvar x = 1;

    returnXHere { ^x }
}

// SomeSuperclass.returnXHere 返回 0
// MyClass.returnXHere 返回 1
// MyClass.returnX 返回 0

Getter 与 Setter

SuperCollider 要求变量不可在类或实例之外访问。必须添加一个方法以显式提供访问：

MyClass : SomeSuperclass {
    var myVariable;

    variable {
        ^myVariable
    }

    variable_ { | newValue |
        myVariable = newValue;
    }
}

这些被称为 getter 和 setter 方法。SuperCollider 允许通过添加 < 或 > 来轻松添加这些方法。

MyClass {
    var <getMe, >setMe, <>getMeOrSetMe;
}

这提供了以下方法：

someObject.getMe;
someObject.setMe_(value);

它还允许我们说：

someObject.setMe = value;

someObject.getMeOrSetMe_(5);
someObject.getMeOrSetMe;

以这种方式创建的 getter 或 setter 方法可以在子类中通过显式定义该方法来覆盖。为了一致地支持两种表达方式，setter 方法应只接收一个参数。例如

MyClass {

    variable_ { | newValue |
        variable = newValue.clip(minval,maxval);
    }

}

设置方法应始终返回接收者。这使我们能够确信可以链接多个设置方法。

Constants

常量是变量，嗯，它们不会变化。它们只能在初始时被赋值。

MyClass {
    const <zero = 0;
}

MyClass.zero // 返回 0

外部方法文件

方法可以添加到单独文件中的类里。这相当于 Objective-C 中的 Category。按照惯例，文件名以小写字母开头：即这些方法所支持的方法或特性的名称。

+ Class {

    newMethod {

    }

    *newClassMethod {

    }

}

槽类

用 [slot] 定义的类可以使用语法 myClass[...]，这会调用 myClass.new，然后对尖括号中的每一项调用 this.add(each)。

MyClass[] {
    var <allOfThem;
    add { |item|
        allOfThem = allOfThem.add(item)
    }
}

a = MyClass[1, 2, 3];
a.allOfThem; // [1, 2, 3]

打印为字符串

向 post 窗口打印自定义消息

默认情况下，当对某个类实例调用 postln 时，会在 post 窗口中打印该类的名称。当对类实例调用 postln 或 asString 时，该类随后会调用 printOn，而后者默认仅返回对象的类名。应重写该方法以获得更有用的信息。

MyTestPoint {
    var <x, <y;

    *new { |x, y|
        ^super.newCopyArgs(x, y)
    }

    printOn { | stream |
        stream << "MyTestPoint( " << x << ", " << y << " )";
    }
}
a = MyTestPoint(2, 3)

定义自定义 asCompileString 行为

调用 asCompileString 应返回一个字符串，对该字符串求值会创建该类的完全相同的实例。要定义自定义行为，应重写 storeOn 或 storeArgs。storeOn 方法应返回一个字符串，对其求值会创建当前对象的实例。storeArgs 方法应返回一个数组，其中包含要传递给 TheClass.new 的参数。在大多数情况下，可以使用此方法代替 storeOn。

// either
MyTestPoint {
    var <x, <y;

    *new { |x, y|
        ^super.newCopyArgs(x,y)
    }

    storeOn { | stream |
        // 注意 <<< 代表 storeOn，而 << 代表 printOn。
        // 我们希望 x 和 y 被完整表示
        stream << "MyTestPoint.new(" <<< x << ", " <<< y << ")"
    }
}

// or
MyTestPoint {
    var <x, <y;

    *new { |x, y|
        ^super.newCopyArgs(x,y)
    }

    storeArgs { | stream |
        ^[x, y]
    }
}
MyTestPoint(2, 3).asCompileString;

私有方法

私有方法带有前缀 pr 标记，例如 prBundleSize。这只是一个命名约定；该消息仍然可以从任何地方调用。建议遵循约定，只从定义私有方法的类内部调用它们。

捕获未定义的方法调用

当收到一条未定义的消息时，接收者会调用方法 doesNotUnderstand。通常这会抛出错误。通过重写 doesNotUnderstand，可以捕获这些调用并加以利用。示例请参见 IdentityDictionary 的类定义。

MyClass {

    doesNotUnderstand { | selector... args, kwargs |
        (this.class ++ " does not understand method " ++ selector);

        if(UGen.findRespondingMethodFor(selector).notNil) {
            "But UGen understands this method".postln
        };
    }
}
a = MyClass();
a.someMethodThatDoesNotExist
