编写原语

编写原语

尽管 SuperCollider 的许多功能是在 SuperCollider 语言本身中实现的，但出于效率考虑，某些功能是在称为 "primitives" 的 "后端" C++ 函数中实现的。本文档为 SC 开发社区的成员提供关于编写 primitive 的指导。

Example

SuperCollider 代码

原语调用以下划线开头，例如 _myPrimitiveName。下面是一个在 SC 类中调用原语的示例：

Cocoa {
    prGetPathsDialog { arg returnSlot;
        _Cocoa_GetPathsDialog
        ^this.primitiveFailed
    }
}

在上面的示例中，原语在 _Cocoa_GetPathsDialog 处被分派。如果成功，它将返回而不执行其下方的代码。原语函数（见下文）返回一个整数，应为 PyrErrors.h 文件中定义的值之一：

enum { // 原始错误
    errReturn = -1,    // 并不是真正的错误.. 原语执行了非局部返回
    errNone,
    errFailed = 5000,
    errBadPrimitive,
    errWrongType,
    errIndexNotAnInteger,
    errIndexOutOfRange,
    errImmutableObject,
    errNotAnIndexableObject,
    errStackOverflow,
    errOutOfMemory,
    errCantCallOS,
    errException,

    errPropertyNotFound = 6000,

    errLastError
};

如果你的原语除了 errNone 之外还可以返回任何值，那么你需要在该原语调用之后提供处理代码。大多数情况下这将是 ^this.primitiveFailed。这将抛出一个 Error，向用户提供出错原因的信息。

在某些情况下，你可能希望执行回退的 SC 代码，而不是抛出 Error。例如，当某个原语提供了某个方法的优化版本、但该版本并非在所有实例中都可用时，这会很有用。以下是一个实现示例：

flop {
    _ArrayMultiChannelExpand
    ^super.flop // 如果原语失败，则执行此代码
}

请注意，返回除 errNone 之外的任何值都将导致执行 SC 方法时忽略原语调用。因此，如果你需要在调用原语之前在 SC 中做一些准备工作，最佳实践是在单独的方法中进行，以避免重复。例如：

// 在此进行初始化工作
openUDPPort {|portNum|
    var result;
    if(openPorts.includes(portNum), {^true});
    result = this.prOpenUDPPort(portNum);
    if(result, { openPorts = openPorts.add(portNum); });
    ^result;
}

// 此方法仅调用原语，并抛出任何原语错误
prOpenUDPPort {|portNum|
    _OpenUDPPort
    ^this.primitiveFailed;
}

定义你的原语

在你的原语源代码中定义原语：

void initCocoaFilePrimitives()
{
    int base, index;

    base = nextPrimitiveIndex();
    index = 0;

    definePrimitive(base, index++, "_Cocoa_GetPathsDialog", prGetPathsDialog, 2, 0);
    // 可以继续添加更多原语...
    //definePrimitive(base, index++, "_Cocoa_SaveAsPlist", prSaveAsPlist, 3, 0);
}

以下是 definePrimitive 的原型：

int definePrimitive(int base, int index, char *name, PrimitiveHandler handler, int numArgs, int varArgs);

numArgs 是传入调用该原语的 SuperCollider 方法的参数数量，再加一以包含作为第一个参数传入的接收者。

编写你的原始 UGen

g->sp 是栈顶，也是最后压入的参数。g->sp - inNumArgsPushed + 1 是接收者，也是结果存放的位置。

在此示例中，numArgsPushed 将为 2（如 definePrimitive 中所指定）

int prGetPathsDialog(struct VMGlobals *g, int numArgsPushed)
{
    if (!g->canCallOS) return errCantCallOS; //如果它是延迟的，这有关系吗？

    PyrSlot *receiver = g->sp - 1; // 一个 Cocoa 实例
    PyrSlot *array = g->sp; // 一个数组

    // ...  主体

    return errNone;
}

此示例没有设置接收者，因此原语返回未改变的原始接收者（仍然是 Cocoa 的实例）。或者将对象设置在 receiver，它同样位于 (g->sp - numArgsPushed + 1)。

Guidelines

在 primitive 中创建对象，以及 GC 安全性

SuperCollider 使用垃圾回收器来按需管理内存分配和回收。1 为了满足良好实时性能的要求，每次创建对象时可能会触发少量且有界的垃圾回收。这包括增量检查所有对象并确定它们是否可达（见下文）。不可达对象的内存可能会被重新分配给新对象。

以下几点对于理解 GC 如何工作以及如何避免 bug 很重要：

  • 如果一个对象具有以下条件，则它是可达的

    • 已存储在栈上，或
    • 已存储在 sclang 变量、类变量或
    • 已被存储在满足上述条件之一的其他对象中

  • GC 将对象标记为以下之一：

    • 白色 - 待检查
    • 灰色 - 可达，但包含的对象本身尚未被完全检查并标记为灰色或黑色
    • 黑色——可达，且其中包含的所有对象均已完全检查
    • Free - 不可达；内存可供重用
  • 如果触发，垃圾回收将在分配新对象之前发生。
  • 新创建的对象将被标记为白色（待检查）。

SC 提供了若干创建新对象的函数，包括 instantiateObject、newPyrObject、newPyrString 和 newPyrArray。在调用任何此类函数之前，至关重要的是让所有先前创建的对象都保持可达。如果没有这样做，这些对象就可能被标记为 free。由于已释放对象的内存可能不会被立即重用，问题可能不会在你的原语被调用时出现，从而导致极难发现的缺陷。

另外，大多数对象创建函数都包含一个 bool runGC 参数。如果将其设为 false，就能保证垃圾回收器不会在这次分配上运行。虽然这并不理想（因为最好尽可能分摊 GC 活动），但此选项是安全的，因为任何先前创建的对象的状​​态都不会被改变。

以下两个示例都是安全的：

使新创建的对象可达：
PyrSlot *arg = g->sp;
PyrObject *array1 = newPyrArray(g->gc, 2, 0, true); // runGC = true
SetObject(arg, array1); // 使该数组在栈上可达
PyrObject *array2 = newPyrArray(g->gc, 2, 0, true);
...
将 runGC 设为 false：
PyrSlot *arg = g->sp;
// runGC = true
PyrObject *array1 = newPyrArray(g->gc, 2, 0, true);
// runGC = false 因此不会触发 GC，并且 array1 无法被释放
PyrObject *array2 = newPyrArray(g->gc, 2, 0, false);
...

一个注意事项：在通过将新对象存储在栈上来使其可达时，你必须确保不会覆盖之后在该原语中需要的对象。如果这样做了，接收者可能会在未来的任何分配中被回收。一种解决方案是将对象压入栈，完成后再将其弹出，例如：

PyrSlot *receiver = g->sp;    // 获取接收者
PyrObject *result = newPyrArray(g->gc, 2, 0, true); // 创建空数组 `result`

// 为确保 `result` 和接收者都可访问，
//    将 `result` 数组压入栈：
++g->sp;                      // 推进栈指针
SetObject(g->sp, result);     // 设置 `result`

// 进一步分配，利用接收者来填充 `result`
(...)

--g->sp;                      // 将栈指针弹回接收者槽位
SetObject(receiver, result);  // 将 `result` 设置为接收者槽位

prArrayMultiChanExpand 在 lang/LangPrimSource/PyrListPrim.cpp 中给出了这种方法的示例。将 runGC 设置为 false 是另一种可能的解决方案。

同样，在编写自身会创建新对象的工具函数时必须小心，因为这可能以某种不透明的方式发生，而且调用上下文可能未知。可能递归调用自身的函数也需要特别注意。在这种情况下，将 runGC 设为 false 可能是最安全的选择，或者包含一个 runGC 参数，使 GC 行为显式化。MsgToInt8Array 就是这样一个函数的例子。

static PyrInt8Array* MsgToInt8Array ( sc_msg_iter& msg, bool runGC )
{
    int size = msg.getbsize() ;
    VMGlobals *g = gMainVMGlobals ;
    PyrInt8Array *obj = newPyrInt8Array ( g->gc , size , 0 , runGC ) ;
    obj->size = size ;
    msg.getb ( (char *)obj->b , obj->size ) ;
    return obj ;
}

将对象设置到另一个对象的内部槽中（例如使用 SetObject 或 slotCopy）也需要小心。如果父对象是黑色的（可达且已检查），则需要将这一变更通知 GC。因此，在使用这些方法之一后，通常必须调用 g->gc->GCWrite(parentObject, childObject)。此规则的唯一例外是父对象已知为白色（未检查）的情况。在以下情况下为真：

  • 它是最后创建的对象，或者
  • 任何随后创建的对象都以 runGC = false 分配（即 GC 不可能在此期间运行过），并且
  • 尚未对其调用 GCWrite

以下两个示例都是安全的：

运行 GCWrite，因为父级可能不是白色：
PyrSlot *arg = g->sp;
PyrObject *array = newPyrArray(g->gc, 2, 0, true); // runGC = true
SetObject(arg, array); // 使该数组在栈上可达
PyrObject *str = newPyrString(g->gc, "Hello", 0, true); // runGC = true
SetObject(array->slots, str);
// 我们必须调用 GCWrite，因为数组可能不是白色的
g->gc->GCWrite(array, str);
...
我们知道父元素是白色的：
PyrObject *array = newPyrArray(g->gc, 2, 0, true); // runGC = true
PyrObject *str = newPyrString(g->gc, "Hello", 0, false); // runGC = false
SetObject(array->slots, str);
// 我们不需要 GCWrite，因为数组必须仍然是白色的
...

如果你知道子对象仍然是白色的，那么可以用 GCWriteNew 代替 GCWrite。如果自子对象创建以来 GC 尚未触发，并且你之前没有对它调用过 GCWrite，那么该子对象仍将是白色的。

如果将对象放入另一个对象中修改了其大小（例如，向数组中添加一个对象），你必须通过 parent->size = newSize 正确调整其大小。这一操作以及调用 GCWrite（如有必要）都应在进行任何进一步的对象分配之前完成。最佳实践是尽可能立即执行它们。

这是安全的：
PyrSlot *arg = g->sp;
int size = 10;
PyrObject *array = newPyrArray(g->gc, size, 0, true); // runGC = true
SetObject(arg, array);
for(i=0; i<numLists; ++i) {
  PyrObject *str = newPyrString(g->gc, "Hello", 0, true); // runGC = true
  SetObject(array->slots + i, str);
  // str 必须仍为白色，这样我们才能使用 GCWriteNew
  g->gc->GCWriteNew(array, str);
  // 立即增加大小
  //以便在下一次分配时准确
  array->size++;
}
...
这不安全：
PyrSlot *arg = g->sp;
int size = 10;
PyrObject *array = newPyrArray(g->gc, size, 0, true); // runGC = true
// 在此处将 size 设为最终值意味着
// 它在下次分配时*不*准确
array->size = size;
SetObject(arg, array);
for(i=0; i<numLists; ++i) {
  PyrObject *str = newPyrString(g->gc, "Hello", 0, true); // runGC = true
  SetObject(array->slots + i, str);
  g->gc->GCWriteNew(array, str);
}
...

尽可能避免在原语中创建对象是一种良好的实践。如果你传入一个在 SC 代码中创建的对象并在原语中填充其槽位，原语的编写和调试会简单得多。

注意： 总而言之，在调用任何可能分配内存的函数（如 newPyr*）之前，你必须确保满足以下条件：先前创建的所有对象必须可到达，即它们必须存在于 g->sp 栈上（注意不要覆盖之后会用到的对象），或存在于语言端变量或类变量中，或存在于满足这些条件的另一个对象的槽中。如果某个对象（ child ）被放入了另一个对象（ parent ）的槽中，则之后你必须调用过 g->gc->GCWrite(parent, child)，除非你知道父对象仍是白色（未检查），或者如果你也知道子对象是白色，则调用 GCWriteNew，并将 parent->size 设置为正确的值

以下是一个完整原语可能的样子示例：

int prMyPrimitive(struct VMGlobals* g, int numArgsPushed)
{
    PyrSlot *arg = g->sp;
    float number;
    int err;

    err = slotFloatVal(arg, &number); // 获取一个浮点参数
    if(err) return err;

    PyrObject *array = newPyrArray(g->gc, 2, 0, true);
    // 创建时 array->size = 0；最大大小为 2
    SetObject(arg, array); // 返回值

    // 注意：数组现在可以在栈上访问，因为 arg 指向 g->sp

    PyrObject *str1 = newPyrString(g->gc, "Hello", 0, true);
    SetObject(array->slots, str1);
    array->size++; // 立即增加数组的大小
    // 数组可能不是白色，因此调用 GCWrite
    // 但我们知道 str 是白色，所以可以改用 GCWriteNew
    g->gc->GCWriteNew(array, str1);

    // 注意：str1 现在在 array 中可达，而 array 在栈上可达

    SetFloat(array->slots+1, number);
    array->size++;
    // 浮点数不是分配的对象，因此这里不需要特殊处理

    return errNone;
}

如果我们把 SetObject(arg, array); 放在这个函数的末尾，那么在调用 array 时 newPyrString 将不会可到达，因此可能被标记为 free，从而导致难以追踪的错误。

警告： 除非你能绝对保证 PyrObject 不会被垃圾回收，否则不要将指向它的指针存储在 C/C++ 变量中。例如，File 和 SCWindow 类通过将对象存储在 classvar 中的数组里来实现这一点。该对象必须留在该数组中，直到没有 C 对象引用它为止。未能遵守上述两点可能会导致非常难以发现的 bug。

类型安全

由于 SC 是动态类型的，你不能依赖任何参数是你期望的类。你应该检查每个参数以确保它是正确的类型。

其中一种方法是使用 isKindOfSlot。如果你只想要一个数值，可以使用 slotIntVal、slotFloatVal 或 slotDoubleVal，如果值不是数值类型，它们将返回错误。类似地还有 slotStringVal。

可以安全地假设接收者类型正确，因为这是由方法分派机制保证的。

FAQ

现在我把要返回的东西放在哪里？

将返回值存储到 g->sp - inNumArgsPushed + 1。（在大多数原语中，这由变量 a 引用。）

[1] - 某些 SC 语言对象，例如数字、布尔类型、字符和符号，直接存储在 PyrSlot 中，不需要分配内存。（符号是一个特例：存储的是对全局符号表中某个位置的引用，每个已定义的符号都永久存储在那里。）
