SCViewHolder

这不是对 (Q/SC)View 进行子类化，而是一个持有该 View 的代理/适配器对象

参见：View

说明

在编写 GUI 控件时，有时不希望将视图类作为子类。更可取的做法是编写一个行为类似 View 的类，并在通常使用 View 的地方使用它，但它并不是 View 类的直接子类。

在 View 的层级结构中，无法对 View 类进行子类化，因为在底层，View 子类与其配对的 C++ 类之间始终存在严格的关系。C++ 类创建实际的视图，而 SC 类是该 C++ 对象的接口。

在 Qt 中有更多一些灵活性。

但不继承自某个特定视图还有其他原因：你的控件可能不是单个视图，这种情况下你会想放置一个 CompositeView，然后在其内部放置子视图。这些视图共同构成你的控件所管理的内容。在这种情况下可以使用 SCViewHolder，它会将顶层 CompositeView 设为其主视图。

尽管它仍被称为 "SC"ViewHolder，但实际上它是跨平台的，因为它不绘制视图，只是持有它们。

另一个可能的名称是 ViewAdapter 或 PseudoView。它最初称为 SCViewAdapter。

这里大多数标准视图方法只是委托给代理视图。这使得 ViewHolder 的行为和表现都像 View 一样。

视图持有者无法理解的消息会被转发给被代理的视图。

历史说明：此类最初位于 cruciallib 中。ObjectGui 是此类的子类。

.doesNotUnderstand

视图持有者无法理解的消息会转发给被代理的视图。因此，当解释器被要求向视图持有者对象发送消息而该消息无法被理解时，它会调用 doesNotUnderstand

参数：

selector

未被理解的消息

... args

所提供的参数

返回值：

在被代理的视图上调用该方法的结果

.viewDidClose

取消设置视图变量。视图关闭（从窗口中移除）后，对视图持有者的所有调用都将失败，而且应该失败，因为视图已不存在。如果不确定，可以检查 viewHolder.isClosed
