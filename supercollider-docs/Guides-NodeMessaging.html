节点消息传递

使用 OSC 向节点发送消息

Introduction

在 sc-lang 内，向服务器发送命令最直接、最快的方式是向 Server 对象发送消息。如果你在 shell 中，可以使用 sendOSC（可从 CNMAT 获取）。

此消息传递方案在以下内容中有详细说明：

  • 服务器架构
  • 服务器命令参考
  • 服务器教程

消息传递节点

在服务器上创建节点（synth 和组）时，我们唯一需要知道的是 nodeID 和服务器（准确地说，是它的地址）。

为了与 synth 通信，需要发送带有其 nodeID 的消息。如果你不打算在节点创建之后与其通信（并且该节点会在没有外部消息的情况下自行结束），则可以将节点 id 设置为 -1，这在服务器中相当于 nil。

一旦你想要传递对某个节点的引用，并考虑到你可能不只有一个服务器，创建一个 Synth 或 Group 对象可能会很有用。这些对象也会响应消息，在需要时可用于获取服务器端节点的状态。

有关节点对象的更详细帮助文件，请参阅 Node、Synth 和 Group 帮助。

等价于

n = s.nextNodeID;
s.sendMsg("/s_new", "default", n);
s.sendMsg("/n_free", n);

is

n = Synth("default");
n.free;

在传递参数时：

n = s.nextNodeID;
s.sendMsg("/s_new", "default", n, 0, 0, "freq", 850);
s.sendMsg("/n_set", n, "freq", 500);
s.sendMsg("/n_free", n);

它是

n = Synth("default", [\freq, 850]);
n.set(\freq, 500)
n.free;

注意可以使用 Symbol 代替 String：

n = s.nextNodeID;
s.sendMsg(\s_new, \default, n, 0, 0, \freq, 850);
s.sendMsg(\n_set, n, \freq, 500);
s.sendMsg(\n_free, n);

and:

n = Synth(\default, [\freq, 850]);
n.set(\freq, 500)
n.free;

关于应当使用节点对象还是直接使用消息，这个问题的答案在一定程度上取决于上下文，在一定程度上也属于个人偏好。

节点对象的封装带来了一定的泛化能力，这意味着其他复合对象可以响应相同的消息，从而利用多态性。它们还提供了一定程度的便利，例如跟踪索引和 ID 等。

在某些情况下，例如对于颗粒合成，建议直接使用消息，因为节点对象无法带来任何好处（即无需向它们发送消息），而且它们会增加客户端的 CPU 负载。

(
SynthDef("grain", {
    Out.ar(0, Line.kr(0.1, 0, 0.01, doneAction: Done.freeSelf) * FSinOsc.ar(12000))
}).send(s);
)

(
Routine({
    20.do({
        s.sendMsg("/s_new", "grain", -1);
        0.01.wait;
    })
}).play;
)

在需要跟踪 synth 状态的情况下，建议使用节点对象并将其注册到 NodeWatcher。（参见帮助文件）

除了这类情况之外，使用消息加数值型全局表示的组合，还是使用对象表示，取决于个人偏好。两者可以混用，而且在使用消息风格时也能获得对象风格的某些优势。例如 Server.nextNodeID 允许以消息风格使用动态分配的 ID。笼统地说，大概可以认为对象风格更方便，但消息风格更高效，因为减少了客户端 CPU 负载。

注意： 重要：如果你希望拥有 default_group 的功能（例如无问题地使用 Server 的 record 和 scope 功能），你应将 ID 1（即 default_group）视为节点树的根，而不是 ID 0（即 RootNode）。详见 default_group。

请注意，Function-play 和 SynthDef-play 会返回一个 synth 对象，可用于向其发送消息。

x = { arg freq=1000; Ringz.ar(Crackle.ar(1.95, 0.1), freq, 0.05) }.play(s);
x.set(\freq, 1500);
x.free;

节点消息中的参数列表

若干节点消息接受值列表，用于映射到 Synth 节点的控制上，正如前面已经给出的一些示例中那样：

s.sendMsg(\s_new, \default, n, 0, 0, \freq, 850);
n = Synth(\default, [\freq, 850]);

参数列表通常以交替对的形式出现，控制标识符位于值之前。通常控制标识符是一个名称，如上所示，但它也可以是一个整数索引。（使用整数对服务器来说稍快一些，但会使代码更难阅读，并且如果 SynthDef 结构发生变化，可能会引入错误。）了解控制索引的一种方法是将 SynthDef .add 到 SynthDescLib 中，然后从 SynthDesc 获取所有控制的列表。

    (
        SynthDef(\controlList, { |out = 0, freq = 440, amp = 0.1, detune = #[0.999, 1.001], gate = 1|
            var    sig = Mix(Saw.ar(freq * (detune ++ [1]), amp)),
            env = EnvGen.kr(Env.adsr, gate, doneAction: Done.freeSelf);
            Out.ar(out, (sig * env) ! 2);
        }).add;

        SynthDescLib.global[\controlList]
    )

Prints:

SynthDesc 'controlList'
Controls:
ControlName  P 0 freq control 440
ControlName  P 1 amp control 0.10000000149012
ControlName  P 2 detune control 0.9990000128746
ControlName  P 3 ? control 1.00100004673
ControlName  P 4 gate control 1
ControlName  P 5 out control 0
   O audio 0 2

该列表显示 'freq' 控制的索引为 0，'amp' 为 1，依此类推。Detune 被定义为“数组参数”，占据索引 2-3。

拥有大量控制参数的 SynthDef 可能需要额外一点代码才能打印完整列表。

SynthDescLib.global[\controlList].controls.do(_.postln); ""

在 SuperCollider 3.3 之前，按名称设置数组参数的唯一方法是使用 n_setn（或 Node 的 setn 方法）。从 3.3 版本开始，数组参数可以透明地包含在 s_new 或 n_set 消息中。

消息传递风格

注意列表中用于界定数组的字符 $[ 和 $]：

n = s.nextNodeID;
s.sendMsg(\s_new, \controlList, n, 0, 0, \detune, $[, 0.95, 1.005, $], \freq, 220);
s.sendMsg(\n_set, n, \gate, 0);

对象风格

Node 对象会自动为你插入 $[ 和 $]：

n = Synth(\controlList, [\detune, [0.95, 1.005], \freq, 220]);
n.set(\detune, [0.99, 1.01]);
n.release;

事件样式

在事件中为某个参数提供数组已经有另一种含义：多通道扩展，即为数组中的每个元素创建一个单独的节点。如果数组的所有元素都应发送到同一个节点，则应将数组参数再包裹在一层数组中：

(instrument: \controlList, freq: 220, detune: [[0.95, 1.005]], sustain: 2).play;
