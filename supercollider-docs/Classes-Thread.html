Thread

代码求值的上下文

Stream : AbstractFunction : Object

另请参阅：Routine

子类：Routine

说明

注意： SuperCollider 的 Thread 不是操作系统线程。尽管它们在概念上有一些相似之处，但二者并不对应。

Thread 表示代码运行所在的上下文。也可以说代码“在 Thread 上”运行。Thread 记录代码执行的状态，因此支持代码在任何时候被挂起，然后在暂停处恢复。这时就称 Thread 本身被挂起和恢复。

总是有一个 main Thread 属于 Process——它是运行顶层代码的 Thread。另一个 Thread 可以使用 Thread 的子类 Routine 的实例来启动，该实例将在一个由其自身提供的上下文中运行一个 Function（实例化 Thread 类本身没有用处）。

当 Thread 上的代码启动或恢复另一个 Thread（Routine）时，前一个 Thread 成为后者的父，后者成为其子。父 Thread 的执行会被阻塞，直到子 Thread 结束或被挂起，此时父 Thread 继续执行。当前 Thread 可通过 thisThread 访问，而 Thread 的父可通过 -parent 访问。

一个 Thread 具有

  • 关联的逻辑时间
  • 一个关联的 Clock
  • 自己的 随机数种子
  • 自己的异常处理器

thisThread

全局伪变量 thisThread 始终表示当前 Thread，即当前代码运行所在的上下文。它可以是主 Thread，也可以是运行当前代码的 Routine。

参见：Clock: Scheduling and Threads。

// example
thisThread.beats;
thisThread.seconds;
thisThread.clock;

类方法

Thread.new(func, stackSize: 512)

创建一个 Thread 实例，将包含要运行代码的 Function 传递给它。

注意： 实例化 Thread 没有好的用途，因为该类不提供启动所给 Function 的方法。请改用 Thread 的子类 Routine。此构造函数的唯一用途是供 Routine 在其自身的构造函数中调用它。

参数：

func

一个包含供 Thread 运行的代码的 Function。

stackSize

调用栈大小（一个 Integer）。

实例方法

.parent

启动或恢复此 Thread 的父 Thread。

讨论：

父 Thread 的执行会被阻塞，直到子 Thread 结束或被挂起。

当子 Thread 启动或恢复时，它会从父级继承某些方面：

  • 关联的 Clock
  • 关联的逻辑时间

.beats

.beats = inBeats

获取或设置 Thread 当前的逻辑时间，单位为拍。这通常与以秒为单位的时间相同，除非该 Thread 的 clock 是 TempoClock，且该时钟的 tempo 不为 1。

设置 beats 也会将 -seconds 设置为 thisThread.clock.beats2secs(beats)。

讨论：

逻辑时间有几种来源：

  • 当从代码编辑器、命令行运行代码，或响应 OSC 和 MIDI 消息时，主 Thread 的逻辑时间被设置为当前的物理时间（参见 Process: *elapsedTime）。
  • 当 调度 在 Clock 上的代码运行时，主线程 的逻辑时间会被设置为该代码被调度的时间。
  • 子线程继承其父级的逻辑时间——每当线程（Routine）启动或恢复时，其逻辑时间被设置为父线程的逻辑时间。

不过，Thread 的逻辑时间也可以手动设置（使用此方法或 -seconds）。改变当前 Thread 的时间，可能有助于操控那些使用当前逻辑时间进行操作的流的行为（例如由 Pstep 和 Pseg 模式创建的流）。由于逻辑时间继承，这会影响当前 Thread 内运行的所有代码，以及任何子 Thread。但请注意，改变另一个 Thread 的时间不会有任何效果，因为该 Thread 一旦运行，其时间就会被继承覆盖；同样，对当前 Thread 时间的任何更改，也只在 Thread 被挂起（它 yields）并再次恢复之前有效。

参见：Clock: Scheduling and Threads。

.seconds

.seconds = inSeconds

获取或设置 Thread 的当前逻辑时间（以秒为单位）。

设置 seconds 也会将 -beats 设置为 thisThread.clock.secs2beats(seconds)。

关于线程和逻辑时间的一般性讨论，请参见 -beats。

.clock

.clock = inClock

获取或设置 Thread 关联的 Clock。

讨论：

Clock 与 Thread 关联的方式有几种：

  • 当代码从代码编辑器、命令行或响应 OSC 和 MIDI 消息运行时，主线程的时钟被设置为 SystemClock。
  • 当代码在 Clock 上被调度运行时，该 clock 成为 main Thread 的 clock。
  • 子线程继承其父线程关联的时钟。

Thread 关联的时钟也可以通过此方法手动设置。设置当前 Thread 的时钟有助于操纵该 Thread 或其子 Thread 的后续行为，但由于时钟继承，下次该 Thread 恢复时时钟将被重置。出于同样的原因，设置另一个 Thread 的时钟对其上运行的代码没有影响。

参见：Clock: Scheduling and Threads。

.deferAwayFrom(func, delta: 0)

执行给定的函数，保证它不会在 this 所在的线程上执行。即：

  • 如果 delta > 0（函数应稍后求值），则延迟到 AppClock。
  • 如果 delta <= 0（立即执行），当 thisThread 与接收此方法调用的线程匹配时，交给 AppClock。否则，直接对函数调用 Function: -value。

此方法接口设计用于函数调用语法，例如 deferAwayFrom(aThread) { ... function body ... }。

参数：

func

要求值的函数。不会向它传递任何参数值。

delta

以秒为单位的时间增量。通常将使用默认值 0。

.isPlaying

若正在播放则为 true。

另见：Random Seed

.randSeed = seed

使用单个整数设置随机数生成器种子。

讨论：

Example:

g = thisThread.randSeed = 4;
10.do{ 1.0.rand2.postln };

.randData

.randData = data

获取或设置定义随机数生成器内部基的三个整数数组。你可以用它来得到完全相同的随机数序列，它为生成音乐的自动重放提供了一种机制。

讨论：

Example:

g = thisThread.randData;
10.do{ 1.0.rand2.postln };
// 每次重置种子时，随机数生成应给出相同的序列
thisThread.randData_(Int32Array[-662787342, 1546785953, 1661466823]);
10.do{ 1.0.rand2.postln };
