模式指南 060：滤波模式

修改其他模式行为的模式概述

另请参见：Pattern Guide 05: Math on Patterns、Pattern Guide 06a: Repetition Constraint Patterns

滤波模式

正如滤波 UGen 会修改输入信号一样，滤波模式会修改来自模式的数值流。

我们已经见过一些修改值流的操作：数学运算符（呈现为 Punop、Pbinop 或 Pnaryop 模式）以及某些集合方法（主要是 collect、select 和 reject）。过滤模式类还能做一些其他令人惊讶且有用的事情。

所有滤波模式都至少接收一个源模式，提供要被滤波的值/事件。有些滤波模式是为值模式设计的，另一些则用于事件模式。还有少数模式对单个值和事件同样适用。

以下是一个分类概览。更多细节请参阅各个分类文档。

重复与约束模式

Pattern Guide 06a: Repetition Constraint Patterns

Pclutch(pattern, connected)

如果所连接的模式为 true，Pclutch 返回模式的下一个值。如果 connected 为 false，则重复先前的模式值。它就像汽车里的离合器：接合时，模式向前推进；断开时，它停留在原处。

Pn(pattern, repeats)

将源模式重复 times 次：简单重复。这也适用于单个值：Pn(1, 5) 输出数字 1 五次。

Pdup(n, pattern)

n 和 pattern 都是模式。pattern 中的每个值重复 n 次。如果 n 是一个模式，每个值可以重复不同的次数。

Psubdivide(n, pattern)

与 Pdup 类似，不同的是模式值被除以重复次数（这样重复周期的总时间就是源模式的 duration 值）。

Pfin(count, pattern)

从源模式中精确返回 count 个值，然后停止。

Pconst(sum, pattern, tolerance)

输出数字，直到总和达到预定义的限制。最后一个输出值会被调整，使总和恰好等于该限制。

Pfindur(dur, pattern, tolerance)

类似 Pconst，但将“约束”行为应用于事件的节奏值。源模式会运行到指定的时长，然后停止。如果你知道某个音乐行为应持续多长时间，但不知道填满该时间所需的事件数量，这会非常有用。

Psync(pattern, quant, maxdur, tolerance)

与 Pfindur 类似，但没有固定的时长限制。相反，它会一直播放，直到达到 maxdur（此时其行为与 Pfindur 相同，会调整最后一个事件使总时长与 maxdur 匹配），或者模式提前停止且最后一个事件被向上取整到 quant 的下一个整数倍。

基于时间的模式

Pattern Guide 06b：基于时间的模式

Ptime(repeats)

返回自嵌入以来经过的时间量。

Pstep(levels, durs, repeats)

为其对应的时长重复一个电平值，然后移动到下一个。

Pseg(levels, durs, curves, repeats)

与 Pstep 类似，但会插值到下一个值，而不是在持续时间结束时突然跳变。默认情况下插值是线性的，但可以使用任何包络段曲线。levels、durs 和 curves 应为模式。相关：将 Env 用作模式。

向事件模式中添加值（或者说，“模式组合”）

模式指南 06c：模式的组合

Pbindf(pattern, pairs)

将新的键值对添加到已有的 Pbind 风格模式上。

Pchain(patterns)

链将 Pbind 风格的模式串联在一起，使它们所有的键值对都进入同一个事件。

并行化事件模式

模式指南 06d：并行模式

Ppar(list, repeats)

同时启动列表中每个事件模式。当最后一个结束时，Ppar 也会停止。如果 repeats > 1，所有子模式将从头重新开始。

Ptpar(list, repeats)

这里，列表由 [timeOffset0, pattern0, timeOffset1, pattern1...] 组成。每个模式在其时间偏移所给定的拍数之后开始。这些模式可以相对于彼此在不同的时间开始。

Pgpar(list, repeats)

类似 Ppar，但它为每个子模式创建一个单独的组。

Pgtpar(list, repeats)

这应该类似于 Ptpar，为子模式设置单独的组，但该类目前是损坏的。

Pspawner(routineFunc)

该函数用于创建例程。一个 Spawner 对象被传入此例程，该对象用于向并行流添加流或从中移除流。新模式可以按顺序或并行添加。

Pspawn(pattern, spawnProtoEvent)

支持 Pspawner 的大部分功能，但使用模式来控制 Spawner 对象，而不是例程函数。

语言控制方法

模式指南 06e：语言控制

有些模式模仿语言风格的控制方法：条件分支（Pif）、循环（Pwhile）和错误清理（Pprotect）。

Pif(condition, iftrue, iffalse, default)

评估一个模式条件，该条件返回 true 或 false。然后，从 true 或 false 分支中取出一个值，再返回去重新评估该条件。当 true 或 false 分支停止产生值（返回 nil）时，默认值或模式就会起作用。如果未给出默认值，则 Pif 在任一分支返回 nil 时把控制权交还给父级。

Pseed(randSeed, pattern)

随机数生成器依赖于种子值；设置特定的种子会产生可重复的伪随机数流。Pseed 在嵌入 pattern 之前设置随机种子，从而有效地在 pattern 开始时重新启动随机数生成器。

Pprotect(pattern, func)

与 protect 错误处理方法类似，如果在从模式获取下一个值时发生错误，该函数将在错误中断执行之前被求值。

Ptrace(pattern, key, printStream, prefix)

为进行调试，Ptrace 会打印每个返回值。你的模式真的在做你认为的事情吗？这会告诉你。Ptrace 由 trace 消息自动创建：aPattern.trace(key, printStream, prefix) --> Ptrace(aPattern, key, printStream, prefix)。

Pwhile(func, pattern)

与 while 类似，只要函数求值为 true，模式就会被嵌入。该函数在开始时检查一次，之后在模式结束时检查。如果它应用于无限模式，则不会循环，因为该模式永远不会交还控制权。

服务器控制方法

模式指南 06f：服务器控制

Pbus(pattern, dur, fadeTime, numChannels, rate)

为模式所演奏的 synth 创建一个私有组和总线。当模式停止时，组和总线会被释放。适用于隔离不同模式的信号。

Pgroup(pattern)

为模式的 Synth 创建一个私有组（不含私有总线）。

Pfx(pattern, fxname, pairs)
Pfxb(pattern, fxname, pairs)

这两个模式都在目标组的尾部播放一个效果 Synth。这个 Synth 应从 out 参数所标识的总线读取，并使用 ReplaceOut 或 XOut 将处理后的信号写入同一总线。Pfx 使用传入事件中指定的任意总线和组。Pfxb 则为效果和模式分配单独的总线和组。

Pproto(makeFunction, pattern, cleanupFunc)

在服务器上分配资源，并将对这些资源的引用添加到用于播放模式的事件原型中。当模式停止（或被停止）时，这些资源可以被自动移除。

数据共享

Pattern Guide 06g: Data Sharing

Pkey(key)

读取输入事件中的键，使先前计算的值可供其他流使用。

Penvir(envir, pattern, independent)

在给定环境中运行该模式。

Pfset(func, pattern)

在从给定模式中获取每个结果事件之前，将默认值赋入输入事件。

Plambda(pattern, scope)

创建一个“函数作用域”，使用 Plet 向其中赋值，并通过 Pget 从中取值。Pget 有点类似 Pkey，不同之处在于其作用域严格为内部，对调用者不可见。使用 Pkey 时，源值仍保留在返回给调用者的事件中。
