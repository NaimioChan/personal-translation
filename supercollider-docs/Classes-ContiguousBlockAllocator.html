ContiguousBlockAllocator

以便更好地处理动态分配

Object

参见：Server、PowerOfTwoAllocator、Multi-client Setups

说明

服务器中用于分配总线编号和缓冲区编号的默认分配器。与其前身 PowerOfTwoAllocator 相比，它可以在其范围的开始处保留一块编号，并且可以偏移其整个编号范围以支持多个 clientID。

类方法

ContiguousBlockAllocator.new(size, pos: 0, addrOffset: 0)

创建一个具有 size 个槽位的新分配器。你可以屏蔽掉前 pos 个槽位（服务器的 audioBusAllocator 这样做是为了预留硬件输入和输出总线）。

实例方法

公共接口

.alloc(n: 1)

返回宽度为 n 个槽位的空闲块的起始索引。默认为 1 个槽位。

请注意，返回的地址不保证是能满足所请求大小的最低可能地址。不过它应当与先前分配的块相邻（以最小化地址空间的碎片化）。

.free(address)

释放先前从 address 开始分配的块。

.reserve(address, size: 1, warn: true)

将特定范围的地址标记为已使用，以便 alloc 方法不会返回该范围内的任何地址。

.findAvailable(n)

给定所需块的整数宽度，查找并返回一个 ContiguousBlock 对象，其 start 为该块的起始地址，其 size 为该宽度。此方法仅查询分配器；它不会改变状态。如果你通过 findAvailable 获得了一个地址，则无法保证后续调用不会返回相同的地址。因此，一般来说应使用 -alloc 来请求地址。（alloc 会调用 findAvailable，然后调用 reserve。）

此方法可以被视为“半私有”：它对查询可能有用，但一般来说，你可以从 -alloc、-free 和 -reserve 获取你所需的一切。

状态与调试

你可以查询这些状态变量，但不建议在公共接口之外更改它们。

.debug(text)

发布分配器的内部状态以供调试。

.size

它可以分配的 id 编号数量。

.pos

分配器为保留块（例如用于硬件输入和输出总线）提供的偏移量。

.addrOffset

分配器地址范围的偏移量，用于容纳多个 clientID。

.top

最后一个空块的地址。

示例

c = ContiguousBlockAllocator(10);
c.alloc(5);  // 0 = 第一个可用
c.alloc(2);  // 5
c.alloc(4);  // nil —— 没有可用的 4 块

c.free(1);  // no-op：1 处没有任何内容需要释放

c.free(0);

c.alloc(3);  // 0：先尝试复用之前释放的空间

c.alloc(3);  // 7


// 邻接
c = ContiguousBlockAllocator(24);

// 每 4 个保留一个
(0, 4 .. 23).do { |i| c.reserve(i) };

10.do { c.findAvailable(1).postln };

在第二个示例的最后一行中，findAvailable 可能定位到索引 1、5、9、13 或 17 中的任意一个。（在其它空白区域找不到合适块之前，不会使用 21。）如果你分配单个地址，那么大小为三的空闲块将始终缩减为大小为二的空闲块（而不是将空闲空间对半分割并得到两个大小为单地址的空闲块）。

令人意外的是，该算法并不偏向较低索引的块；但如果两个地址 A 和 B 之前已被使用并释放，若 A < B，则没有内在理由偏好 A。
