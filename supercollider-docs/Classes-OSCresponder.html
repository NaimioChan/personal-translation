OSCresponder

客户端网络响应器

Object

参见：OSCFunc、OSCdef、OSC Communication、OSCresponderNode、NetAddr

子类：OSCMultiResponder、OSCpathResponder、OSCresponderNode

注意： 此类已废弃，并将在 SC 的未来版本中移除。请改用 OSCFunc 和 OSCdef。它们比旧版响应器类更快、更安全，参数顺序更合理，并且支持模式匹配和自定义监听端口。使用旧版类 OSCresponder、OSCresponderNode 和 OSCpathResponder 可能不安全，因为用户代码和类代码中的响应器可能会意外地相互覆盖。

注册一个函数，在从特定 OSC 地址接收到特定命令时被调用。

其他向 SuperCollider 发送消息的应用程序应区分发送给服务器还是发送给语言的消息。服务器消息记录在 Server Command Reference 中，应发送到服务器的端口 - s.addr.port - 默认值为 57110。发送到服务器的消息不会被语言中的任何 OSCresponder 处理。

应由 OSCresponder 处理的外部客户端消息必须发送到语言端口，默认情况下为 57120。使用 NetAddr.langPort 来确认 SuperCollider 语言正在监听哪个端口。

更多细节参见 OSC Communication。

注意： 强烈建议使用 OSCresponderNode 或 OSCpathResponder 代替直接使用 OSCresponder。OSCresponder 之间可能相互覆盖，但具有相同地址和命令名的 OSCresponderNode 可以和平共存。

类方法

OSCresponder.new(addr, cmdName, action)

参数：

addr

响应者接收来自的地址（一个 NetAddr 实例，例如 Server.default.addr）。地址为 nil 将响应来自任何地方的消息。端口为 nil 的地址将响应来自该特定 IP 的任何端口的消息。

cmdName

一个 OSC 命令，例如 '/done'。

action

一个 Function，当从 addr 收到该名称的 cmd 时将被求值。参数：time、theResponder、message、addr

注意： OSCresponder 在系统进程中求值其函数。为了访问应用进程（例如进行 GUI 访问），请在动作函数内使用 { ... }.defer;，例如：{ |time, resp, msg| { gui.value_(msg[3]) }.defer }
