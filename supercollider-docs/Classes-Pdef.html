Pdef

流引用定义

EventPatternProxy : TaskProxy : PatternProxy : Pattern : AbstractFunction : Object

参见：Pdefn、PdefGui

子类：Pbindef

说明

Pdef 按键注册模式。对已注册模式的所有访问都通过该键经由 Pdef 类进行。已注册的模式可以在运行时被替换。旧模式与其替换者可以自动交叉淡化，替换时间可以被量化。

Pdef 是一个类，它为其父类 EventPatternProxy 提供接口，保持对可在播放时替换的流的引用。一个模式可以在不同地方的许多流中使用。模式定义的更改会传播到所有流。

Pdef 和 Pdefn 使用各自独立的全局集合。

Pdef(key)    // 返回该实例
Pdef(key, pat)    // 存储该模式并返回实例，与 Tdef 和 Ndef 类似。

它可用于全局存储事件模式。对此全局库的更改会立即生效。

对于非事件模式，则使用 Pdefn 代替。Pdef 的另一种用法另请参见 recursive_phrasing。所有当前 Pdef 的图形化概览：PdefAllGui。概览：JITLib。

第一个示例

s.boot;

Pdef(\x, Pbind(\note, Pbrown(0, 6, 0.1, inf)));
Pdef(\x).quant = 0; // 无需等待。
Pbindf(Pdef(\x), \dur, 0.03).play;
Pbindf(Pdef(\x), \dur, 0.1, \ctranspose, 15).play;
Pbindf(Pdef(\x), \dur, 0.3, \ctranspose, 2).play;
// 现在更改定义
Pdef(\x, Pbind(\note, Pseq([0, 3, 5, 7, 9, 11], inf)));
Pdef(\x, Pbind(\freq, Pseq([1000, 1923, 245.2, 1718] / 1.2 + 0.1, inf)));

类方法

Pdef.all

Pdef.all = value

一个包含所有代理的全局 IdentityDictionary。

Creation

Pdef.new(key, item)

将模式存储在键下的全局字典中，用新模式替换其模式。如果模式是一个函数，Pdef 会在内部创建一个 PlazyEnvir，它会动态创建从该函数返回的模式，并应用来自 inevent 的参数。

使用 *new(key) 可以访问该键处的模式（如果未给出，则创建一个默认的静音事件）

参数：

key

代理的标识符。通常它是一个 Symbol。该键会透明地访问全局 IdentityDictionary。

item

用于（重新）定义代理源的对象。如果为 nil，则返回未经修改的代理。

(
SynthDef(\Pdefhelp, { |out, freq, sustain = 1, amp = 1, pan|
    var env = EnvGen.kr(Env.perc(0.01, sustain), 1, doneAction: Done.freeSelf);
    Out.ar(out, Pan2.ar(SinOsc.ar(freq, 0.5pi, amp * env), pan));
}).add;
)

// 作为参数的事件模式
Pdef(\x, Pbind(\instrument, \Pdefhelp, \note, Pbrown(0, 6, 0.1, inf), \dur, 0.2));
Pdef(\x); // 省略第二个参数，我们可以访问代理
Pdef(\x).play; // ... 播放一个事件流
Pdef(\x).source.postcs; // ... 并检查事件模式本身。


// 函数作为参数，每次调用时创建一个新模式
Pdef(\x, { Pbind(\note, Pseries(10.rand, 5.rand, 8.rand + 1), \dur, 1 / (8.rand + 1)) });
Pn(Pdef(\x)).play;

// 该函数在传入事件中作为当前环境被调用，因此可以传递参数：
Pdef(\stut, { Pdup(~dup ? 1, ~pattern) });
Pdef(\x, Pbind(\instrument, \Pdefhelp, \note, Pseq([0, 4, 7, 3, 0, 1, 0], inf)));
Pdef(\y, Pdef(\stut) <> (pattern: Pdef(\x), dup: Pseq([2, 2, 4, 3], inf)) <> (dur: 0.1, legato: 0.2)).play;

来自父类：PatternProxy

Pdef.clear

实例方法

更改定义 / 设置源

一个模式可以在不同位置拥有多个流。Pdef 中模式定义的更改会传播到所有流。更改不必是立即的——有一种方案可以安排更改何时生效：一个 quant 和 clock（与其他地方一样）以及一个 condition。

.clock

.clock = value

来自父类：PatternProxy

获取或设置实例的默认时钟，在没有指定其他时钟时由 -play 使用。默认为 TempoClock.default。

.quant

.quant = val

来自父类：PatternProxy

设置用于节拍精确调度的量化时间。

参数：

val

可以是数组 [quant, phase, timingOffset, outset]，或仅 [quant, phase] 等。

.condition

.condition = value

来自父类：PatternProxy

提供在插入新模式时切换模式的条件。流值和计数值会被传入该函数。

.count(n: 1)

来自父类：PatternProxy

创建并更新条件，该条件简单地计数到 n，然后切换模式

.reset

来自父类：PatternProxy

立即切换模式（可通过此方式消除卡住的条件）。

.fadeTime

.fadeTime = value

来自父类：EventPatternProxy

当所使用的 synthdef 包含 \amp 控制时，模式将在此时间（以拍为单位）内通过将前一个与新的进行交叉淡化来替换。

.envir

.envir = dict

来自父类：PatternProxy

设置 Pdef 的事件。它用于在传入流被传递给源模式之前对其进行过滤。这类似于 NodeProxy: -nodeMap。首次设置时，模式会被重建。

.set( ... args)

来自父类：PatternProxy

设置默认事件中的参数。如果没有默认事件，则创建它并重建模式。

.map( ... args)

将 Pdefn 映射到事件中的键。

.clear

来自父类：PatternProxy

将源设为 nil

.endless(default)

来自父类：PatternProxy

返回一个 Prout，它无限地播放该代理，将 nil 替换为 default 值（静默事件）。这允许创建一直空闲的流，直到插入新模式为止。

Pdef 作为流引用

单个 Pdef 可以作为多个流的定义。这些方法展示了如何从一个实例派生出独立的流。即使它们在不同的上下文中运行，它们的定义仍然可以被更改。

.fork(argClock, quant, protoEvent)

来自父类：EventPatternProxy

并行播放一个独立的流。

参数：

argClock

运行子流所用的时钟。

quant

可以是一个 [quant, phase, offset] 数组，或一个 Quant 值。

protoEvent

传入一个事件，供子流使用

返回值：

一个 EventStreamPlayer。

.embed(val)

来自父类：PatternProxy

将一个值（通常是 Event）传入模式 inval，并将 Pdef 嵌入到流中。

.embedInStream(inval, embed: true, default)

来自父类：EventPatternProxy

就像任何模式一样，它嵌入到流中

作为 EventStreamPlayer 的 Pdef

对于现场编程，每个 Pdef 还可以控制一个实例，该实例从中播放一个流。这是一个 EventStreamPlayer，可通过实例变量 -player 访问。

.play(argClock, protoEvent, quant, doReset: false)

来自父类：EventPatternProxy

启动 Pdef 并创建一个播放器。（参见：EventPatternProxy: -play）

.stop

来自父类：TaskProxy

停止播放器

.player

来自父类：TaskProxy

返回当前的演奏者（如果 Pdef 仅用于其他流中，则为 nil）

.pause

来自父类：TaskProxy

.resume(clock, quant)

来自父类：TaskProxy

.reset

来自父类：PatternProxy

在 player 上执行此方法。

.isPlaying

来自父类：TaskProxy

如果 player 正在运行则返回 true。如果某个 Pdef 正在播放且其流结束，它将会安排一个流来播放，一旦有新的流被分配给它。如果它被 stop 停止，则不会如此。

Recursion

Pdef 可以递归使用，条件是流调用结构允许这样做。像下面这样的结构可以工作：

Pdef(\x, Pseq([Pbind(\instrument, \gpdef), Pdef(\x)], inf));
Pdef(\x).play;

但以下代码会崩溃，因为 .embedInStream 被无限制地递归调用：

// Pdef(\y, Pseq([Pdef(\y), Pbind(\instrument, \gpdef)], inf));

量化与起始偏移

当量化到较多的拍数时，如果需要等待下一拍，变化会变得非常缓慢。提供 outset 量化值是一种让变化看起来如同已经在之前的网格点上完成的方法。流会被快进到相对于量化网格的当前位置。提供大于零的数值时，下一个可能的量化点会被用作 outset。

例如，如果 quant 为 32，并且在更改模式时刚刚错过了第一拍，则必须等待 32 拍才会发生更改。使用 outset 为 1，则假定你已经在第一拍更改了模式，流会被快进到你若已更改时现在所处的时间。新模式会在下一拍插入（outset = 1）。

quant 可以是：[quant, phase, timingOffset, outset]

注意： 如果模式非常复杂/快速或 quant 很长，这种快进可能会产生 CPU 峰值。这很难避免，因此只能将其考虑在内。

(
Pdef(\x).quant_([8, 0, 0, 1]);
Pdef(\y).quant_([8, 0.5, 0, 1]); // 相位：半拍
Pdef(\x).play;
Pdef(\y).play;
)

Pdef(\x, Pbind(\degree, Pseq((0..7)+2, inf)));
Pdef(\y, Pbind(\degree, Pseq((0..7)-2, inf)));
Pdef(\x, Pbind(\degree, Pseq((0..7)+2, inf), \dur, 0.5));
Pdef(\y, Pbind(\degree, Pseq((0..7).scramble-2, inf), \dur, 0.25, \legato, 0.3));
Pdef(\x, Pbind(\degree, Pseq((0..7), inf)));

Pdef(\x, Pbind(\degree, Pseq([0, 2, 2, 4, 0, 4, 0, 4], inf), \dur, 1));

更新条件

为了能够在某个 -condition 下切换到新的模式，可以将实例变量 condition 设置为一个返回布尔值的函数。值和计数索引会被传递给该函数。该条件始终对下一个插入的模式有效。对于卡住的条件，可以使用 -reset 消息。

由于向上计数（例如 "每第 n 个事件，可以发生一次交换"）是一项常见任务，因此有一个专门的方法，称为 -count(n)。

Pdef(\x).play;
Pdef(\x).quant = 0; // 这里不需要量化。
Pdef(\x, Pbind(\degree, Pseq((0..5), inf), \dur, 0.3)).condition_({ |val, i| i.postln % 6 == 0 });
Pdef(\x, Pbind(\degree, Pseq((0..7) + 5.rand, inf), \dur, 0.3)).condition_({ |val, i| (i % 8).postln == 0 });

// 上述内容等价于：
Pdef(\x, Pbind(\degree, Pseq((0..7) + 5.rand, inf), \dur, 0.3)).count(8);

// 传入的值就是事件，因此可以依据事件字段做出决策

reset

// 重置以立即更改：
Pdef(\x).reset;
