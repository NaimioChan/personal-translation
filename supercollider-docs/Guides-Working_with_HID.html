使用 HID

使用 HID 设备进行控制输入的指南

另请参阅：HID、HIDFunc

Introduction

人机接口设备可用作制作音乐的控制器。HID 和 HIDFunc 类以简单透明的方式为你提供对它们的访问。

这一 SuperCollider 的 HID 访问实现的开发由 SuperCollider 社区和 BEK，Bergen Elektronisk Kunst，挪威卑尔根资助，http://www.bek.no

什么是 HID 设备？

HID 代表 Human Input Device，因此从某种意义上说，HID 设备就是指 Human Input Device 设备。另一个混淆之处在于，HID 不仅仅是输入设备，它们还可以具有输出，例如指示 CapsLock 或 NumLock 是否开启的 LED，或游戏设备中的力反馈（或振动）。

如今大多数 HID 使用 USB 连接到计算机，尽管有些 HID 改用 BlueTooth（但并非所有 BlueTooth HID 都遵循标准协议，最值得注意的是 WiiMote 就不遵循）。SuperCollider 提供访问 HID 的手段，前提是它们遵循为其制定的标准协议。在实现中，我们尽量使 HID 的使用尽可能跨平台兼容，这样你在迁移到另一个平台（例如从 macOS 到 Linux，以及反之）时无需更改代码。然而，某些 HID 可能使用特殊的驱动软件，从而使这变得不可能。其他不兼容性可能源于以下事实：尽管在设备层面存在标准化，但不同操作系统随后提供的软件接口各不相同，因此在某种程度上，我们不得不逆向工程操作系统引入的差异。

注意： Windows 的后端尚未完成，因此 HID 在 Windows 上尚不可用。

常规工作流程

使用 HID 设备的一般工作流程是：

  • 查找连接到计算机的设备
  • 打开你想要使用的设备
  • 并为设备具有的不同控件分配函数

当你想使用 HID 时，最初会想探索设备并了解其功能，然后编写一些代码，以便每次开始使用你的乐器时都能复用。

探索 HID

以下是一个简短示例，说明如何探查连接了哪些 HID，以及它们会产生什么输入：

查找可用设备：

HID.findAvailable;

打印可用设备的可读列表：

HID.postAvailable;

打开特定设备：

~myhid = HID.open( 1103, 53251 );

打印所有 HID 输出：

HID.debug = true;

或者（差异见下文），

HIDFunc.trace( true );

findAvailable 方法会检查哪些设备连接到计算机，并获取它们的基本信息。使用 postAvailable 方法，设备列表随后会以可读列表的形式打印到 post 窗口，第一列给出设备列表中的索引，第二列列出设备的各种属性。这些属性可用于打开特定设备。

要打开设备，有多种方法可用：

  • 使用设备列表中的索引，例如：HID.openAt( 0 );
  • 使用操作系统中的路径，例如：HID.openPath( "/dev/hidraw4" );
  • 使用设备的 vendor id 和 product id，以及可选的路径，例如：HID.open( 1103, 53251 );

最后一个（如果未给出路径）是跨平台兼容的。供应商 ID 和产品 ID 由设备报告给操作系统，因此始终相同。这些数字对于该设备类型是唯一的（例如，任何 Nintendo Switch Pro Controller 都具有相同的数字）。如果你使用多个相同设备，你可能需要调整设置，同时使用路径，以便能够识别你打开的是哪个设备。

注意： 如果你在打开设备时遇到问题，例如收到消息 ERROR: HID: Could not open device，请检查 HID permissions

注意： 在 macOS 上，笔记本电脑的内置设备有些混乱——它们会多次出现且没有唯一路径，这使得打开其中某个特定设备变得困难。

你随时可以检查 SuperCollider 已经打开了哪些设备，使用

HID.openDevices;

探索 HID 控制数据

如果你已启用 HID 输入数据的调试，并移动设备上的某个控件，你将得到类似下面的输出：

HID Element Data:
    devid: 0, elid: 18
    element:      page: 1    usage: 53
    array value: 0,     raw value: 128,    physical value: 128,    value: 0.50196081399918

元素是 HID 中一个元素的名称，它可以代表例如操纵杆的 x 轴，或键盘上按下的第一个键。

devid 是打开设备字典（HID.openDevices;）中的索引，元素 id（elid）是设备元素数组中的索引。此索引可能因操作系统而异，因此它主要仅在内部使用。

元素的page和usage是用于查找元素功能的查找索引。这些查找索引是标准化的，并且有可用的表格来查询控件的名称。

原始值是传入时的值——它没有经过任何缩放。值则根据设备报告的逻辑最小值和最大值缩放到 0 到 1 之间。

array value 仅对能够表示多种用途的元素有意义，例如来自键盘的元素。在这种情况下，它表示按下的是哪个键，将此数字与该元素的 usage 相加，即可得知该键具有哪种功能。

使用调试方法 HIDFunc.trace( true )，数据将以不同方式打印：

HID Element Data:    devid: 0, elid: 18
    device:     a HIDInfo(Thrustmaster, Run'N' Drive, IDs:1103, 53251, /dev/hidraw4, , 258, 0),     page: 1     usage: 5
    element:    a HIDElement(18: type: 2, usage: 1, 53)
                page: 1    usage: 53    raw value: 128,    value: 0.50196081399918

再次关闭调试：

  • HIDFunc.trace( false )
  • HID.debug_( false )

除了查看传入的数据，我们还可以检查设备具有哪些元素，使用

  • ~myhid.postElements
  • ~myhid.postInputElements
  • ~myhid.postOutputElements

或检查哪些用法可用：~myhid.postUsages

这些将发布每个元素的详细信息：

HID Element: 18, type: 1, 2, usage page: 1, usage index: 53
    Description: GenericDesktop, Rz, input,
    [ Data, Variable, Absolute, NoWrap, Linear, PreferredState, NoNullPosition, NonVolatile, BitField ]
    Usage range: [ -1, -1 ]
    Logical range: [ 0, 255 ]
    Physical range: [ 0, 255 ], Unit: 0, Exponent: 0
    Report ID: 0, size 8, index 5

type 是一个数值索引，指示它是输入、输出还是特性元素，第二个指示其他属性。在描述中，页面和用途通过表查找进行转换，类型指示也会被转换为可理解的内容。

使用范围对键盘来说同样重要，逻辑范围和物理范围给出了值的变化范围。报告 ID、大小和索引提供了关于数据如何传入的低层信息。

为 HID 控制数据分配动作

每当来自已打开的 HID 设备的数据到达时，会触发两种类型的动作。一个针对传入的元素数据的动作，以及一个针对设备的动作，表示其中一个元素发生了改变。在大多数情况下你会想使用第一个动作；只有在解析元素数据的顺序很重要的情况下，你可能想使用第二种类型——例如在处理对时间要求非常精确的按钮按下组合时。

可以在三个层级上设置动作：

  • 在全局级别——对任何 HID 设备、任何元素调用
  • 在设备层面——针对特定设备、对任意元素调用
  • 在元素级别——针对特定设备的特定元素调用

或者，你也可以使用 HIDFunc 接口，它允许根据多个设备的使用情况来过滤事件。

全局层级

HID.action = { |value, rawValue, usage, page, elid, element, devid, device | "HID global action: ".post; [value, rawValue, usage, page, elid, element, devid, device].postln; };

设备层级

~myhid.action = { | value, physValue, rawValue, arrayValue, usage, page, elid | "HID device action: ".post; [value, physValue, rawValue, arrayValue, usage, page, elid].postln; };

元素层级

~myhid.elements.at(18).action = { |value,element| "HID element action: ".post; [value,element].postln; };

使用 HIDFunc

HIDFunc.usage( { |value, rawValue, usage, page, elid, ele, devid, device, key| "HIDFunc.usage action: ".post; [value, rawValue, usage, page, elid, ele, devid, device, key].postln; }, \Rz );

使用 HIDdef

HIDdef.usage( \myRz, { |value, rawValue, usage, page, elid, ele, devid, device, key| "HIDdef.usage action: ".post; [value, rawValue, usage, page, elid, ele, devid, device, key].postln; }, \Rz );

HIDFunc 和 HIDdef 选项提供了最灵活的控制，其用法类似于 MIDIFunc 和 MIDIdef 以及 OSCFunc 和 OSCdef。

其优点在于你可以只针对特定类型的控制器进行过滤，因此可以轻松地用类似类型的游戏控制器替换你的游戏控制器。

让我们再次关闭设备：

~myhid.close;

一个简单示例

HID.findAvailable; // 检查连接了哪些设备
~myhid = HID.open( 1103, 53251 ); // 打开 Run'N' Drive 游戏控制器

s.boot; // 启动服务器

Ndef( \sinewave, { |freq=500, amp=0.1| SinOsc.ar( freq, 0, amp * 0.2 ) } );
Ndef( \sinewave ).play;

~freqRange = [500, 5000, \exponential].asSpec; // 创建一个频率范围

HIDdef.usage( \freq, { |value| Ndef( \sinewave ).set( \freq, ~freqRange.map( value ) ); }, \X );
HIDdef.usage( \amp, { |value| Ndef( \sinewave ).set( \amp, value ); }, \Y );

在设备分离后再次自动查找设备

(
Tdef( 'tryOpenHID' , {
   var keepLooking = true;
   while ( { keepLooking } ){
      if ( ~myhid.notNil ){
         if ( ~myhid.isOpen ){
            keepLooking = false;
         }
      };
      if ( keepLooking ){
         HID.findAvailable;
         if ( HID.findBy(1103, 53251).size > 0 ){
            ~myhid = HID.open( 1103, 53251 );
            if ( ~myhid.notNil ){
               ~myhid.closeAction = {
                    "device closed".postln;
                    Tdef( \tryOpenHID ).reset.play;
               };
               keepLooking = false;
            }{
               3.0.wait;
            };
         }{
            3.0.wait;
         }
      }
   }
} );
);
Tdef( 'tryOpenHID' ).play;
