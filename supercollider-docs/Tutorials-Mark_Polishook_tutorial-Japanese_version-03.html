SynthDefsには2つの重要な部分がある

SynthDefs 是 SuperCollider 中用于创建合成器引擎的类。

SynthDefsには2つの重要な部分があります。それは、名前と関数です。SuperColliderの用語では、関数はしばしばugenGraphFuncと呼ばれます。

////////////////////////////////////////////////////////////////////////////////////////////////////

ugenGraphFunc 一词来源于这样一种想法：以图这种数据结构的形式来描述单元生成器的函数。SuperCollider 根据它在函数中找到的代码生成图。这实际上意味着，在使用图时，无需了解图这一概念是如何工作的。

然而，为了进一步说明有关图的背景，引用http://www.nist.gov/dads/HTML/graph.html 中关于图的讨论。

「グラフはロードマップの様なものです。都市は頂点です。都市から都市への道路はエッジです。（道路のジャンクションや分岐はどうでしょう？ジャンクションもまた頂点と見なすことができます。もしそれらを頂点としてカウントしたくないのであれば、道路は２つ以上の都市を結ぶでしょう。つまり、厳密にいえば、ハイパーグループにはハイパーエッジがあるのです。もしそれぞれの１組の都市の間に１本以上の道路を許可したいのであれば、代わりにマルチグラフがあります。これはあなたがどのように定義したいのか次第です）。

グラフに関する他の考え方とは、線によって接続された点の集まりというものです。かなり昔に数学者は普通の人々に話しかけるのを辞めてしまったため、グラフの中の点は頂点と呼ばれ、点に接続された線はエッジと呼ばれます。重要なのはエッジと頂点、つまり、点とそれらの間の接続です。与えられた点の位置や与えられた線の真直度は問題ではありません。かくして、点はどこにもなることができ、それらをつなぐ線は無限に伸縮性があります。さらに、数学的なグラフは、比較表や、xとy軸のある図や、株価のレポートのくねった線ではありません。グラフとは単純に点とそれらの間の線なのです。すみません、頂点とエッジです。」

// synthdefのテンプレート ... 疑似コードを含む
SynthDef(
    "i am a synthdef",            // 第１アーギュメントは名前
    { .... i am a ugenGraphFunc ... }    // 第２アーギュメントはUGen
)

以下几行代码展示了实际的 SuperCollider 代码模板。synthdef 的第一个参数是名称，第二个参数是函数。

(
SynthDef(
    "aSynthDef",                 // SynthDefの名前
    {                     // ugenGraphFunc
        arg freq;
        Out.ar(
            0,
            SinOsc.ar(freq, 0, 0.1)
        )
    }
).load(s);
)

SynthDefブラウザー

通常，ugenGraphFunc 包含两三个重要的组件。这些组件包括 ugen（单元发生器）、control（控制）、input（输入）以及 output（输出）。

ブラウザー・ウィンドウでそのようなことを見るためには、次のコードを実行してみて下さい。

(
SynthDescLib.global.read;
SynthDescLib.global.browse;
)

这段代码创建的浏览器窗口包含六个框，显示所有先前定义的 SynthDef 的名称。选择每个名称，即可显示与其关联的 ugenGraphFunc ugen、control、input 和 output。

预先定义的 SynthDef 是指之前发送过 .load 消息的 SynthDef。因此，SuperCollider 会在启动时加载预先加载的 SynthDef。

通过 .load 消息，SynthDef 被写入磁盘并发送到活动服务器。相比之下，.send 消息通过网络将 SynthDef 发送到服务器，而无需先将定义写入磁盘。

新闻快讯！：最近定义了新消息 .store。.store 消息有时比 .load 或 .send 更可取。除了将 SynthDef 写入磁盘之外，还将其放入可由 SynthDef 浏览器窗口和/或模式类访问的库中。

////////////////////////////////////////////////////////////////////////////////////////////////////

ugenGraphFuncのコンポーネント

SynthDef 浏览器显示已定义的 SynthDef。刚才的「aSynthDef」由 4 个 ugen 组成。它包含 1 个 control。它没有 input。并且它有 1 个 output。

如浏览器中所显示，这 4 个 ugen 分别包含 Control、SinOsc、BinaryOpUGen 和 Out 的实例。在此例中，为使该 SynthDef 完全可用，SuperCollider 会安装 Control 和 BinaryOpUGen 的实例。其他所有 ugen 仅在指定时才会存在。

该 SynthDef 的一个控制是「freq」，它是一个在创建合成器时、或只要它在服务器上时随时都可使用的参数。浏览器显示「aSynth」没有输入。这意味着该 SynthDef 未使用 In 类的实例。

浏览器还表明，此 SynthDef 指定了到通道 0 的单通道输出。

请试着调查浏览器中显示的其他 SynthDef 是如何构建的。
