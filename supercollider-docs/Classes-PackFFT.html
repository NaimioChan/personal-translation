PackFFT

将独立的需求速率 FFT 频段流打包到 FFT 链缓冲区中

PV_ChainUGen : WidthFirstUGen : UGen : AbstractFunction : Object

参见：UnpackFFT

说明

接收一个幅度和相位数组，并将它们打包进 FFT 缓冲区，以便使用 IFFT 变换回时域音频。

大多数人不需要直接使用它——而应使用 PV_ChainUGen 基类中的 pvcollect、pvcalc 或 pvcalc2 方法。

类方法

PackFFT.new(chain, bufsize, magsphases, frombin: 0, tobin, zeroothers: 0)

参数：

chain

FFT 链

bufsize

FFT 缓冲区大小

magsphases

输入数据应为一个扁平数组，按升序包含所有 bin 的幅度和相位。例如 [mag0, phase0, mag1, phase1, mag2, phase2, ... magN, phaseN] 此输入通常为 demand-rate。

frombin

限制频带

tobin

限制频带

zeroothers

设为 1 以将受限频带外的所有幅度置零

讨论：

从技术上讲，这与 Demand 或 Duty 类似，因为它会调用图中更上层的 demand-rate UGen 来处理这些值，最终调用 UnpackFFT。在大多数情况下，这个过程的两端必须看到同一条链……！否则行为就是未定义的，而且谁知道呢，可能还会令人不快。

可选参数：frombin 和 tobin 允许你仅将提供的数据填充到 FFT 频段的一个子集（即单个限定的频带），如果这样做，你还可以选择将 zeroothers 设为 1，以将该频带之外的所有幅度归零（否则它们保持不变）。

示例

这里有一个不寻常的例子，它使用 PackFFT 而不先使用 UnpackFFT——本质上是从零开始创建我们的 FFT 数据。

// 提醒：这不是预期的典型用法！不过这样做也可以。
(
x = {
    var mags, phases, chain, sig;
    // 创建简单的起伏幅度
    mags = { FSinOsc.kr(ExpRand(0.1, 1)).range(0, 1) }.dup(100);
    // 然后给它们一个 "rolloff"，让声音不那么难听
    mags = mags  * ((1, 0.99 .. 0.01).squared);
    // 让我们以不同速率开启和关闭这些频段，我*确信*那听起来会很有趣
    mags = mags * { LFPulse.kr(2 ** IRand(-3, 5)).range(0, 1) }.dup(100);
    // 暂时忽略相位
    phases = 0.dup(100);
    // 我们需要创建一个 FFT 链来输入我们的数据。
    // 最简单的方法是对某个信号做 FFT，然后将其忽略！
    chain = FFT(LocalBuf(512), FSinOsc.ar);
    // 现在我们可以进行打包
    chain = PackFFT(chain, 512, [mags, phases].flop.flatten, 0, 99, 1);
    sig = IFFT(chain);
    sig.dup
}.play
)
x.free;
