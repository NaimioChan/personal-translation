LinkClock

与 Ableton Link 同步的调度器

参见：TempoClock

说明

LinkClock 是一种基于 TempoClock 的时钟，它依赖于 Ableton Link，这是一种在本地网络上同步相位（小节内的节拍）和速度的协议。

链接行为

Link 尽可能在同步的同时，允许应用程序按自己的节奏运行：

  • 速度：任何应用程序都可以随时改变速度。
  • Beat：整数拍应在所有应用程序中同时发声。
  • 相位（类似于 SuperCollider 的 TempoClock: -beatInBar）：一个 peer 中的强拍应对应其他 peer 中的强拍。

Link 不会同步精确的拍数。两个加入同一 Link 会话的 SuperCollider 对等端，在 4/4 拍中，可能分别位于第 4 拍和第 16 拍（它们都是小节线），但它们不应位于第 4.0 拍和第 19.0 拍。

许多启用 Link 的应用程序（DAW）可以启动和停止整个时间线。SuperCollider 的时钟不会停止。DAW 在开始播放时，应锁定到 SuperCollider 在小节内的相位。你可以注册函数来响应其他对等端的启动或停止。（SuperCollider 并不知道是哪个其他对等端启动或停止了。）

Latency

Link 协调给定节拍的发声时间。

所有音频应用程序都必须提前准备好事件和音频处理，以便信号能在正确的时间到达音频接口。SuperCollider 为此使用 OSC 时间戳，根据当前时间（以秒为单位）加上一个 latency 偏移量来计算时间戳。

因此，为了与其他应用程序协调，LinkClock 必须以相同的固定偏移量比期望的发声时间更早运行。也就是说，它应具有与服务器相同的（正）延迟偏移：

t = LinkClock.new.latency_(Server.default.latency);

之后，服务器消息应以相同的延迟量发送。由模式生成的事件会自动应用服务器对象的延迟。对于其他消息，请使用 Server: -makeBundle。

在延迟为正的情况下，如果检查 t.beats，它会显得比其他应用中显示的节拍更晚。这是正常的。SuperCollider 中的时钟必须提前运行，事件才能准时发声。

（由于时钟和服务器有独立的延迟设置，因此可以相对于其他应用程序调整时序。例如，如果你发现 SuperCollider 的声音稍晚，可以略微增加 LinkClock 的延迟，使时钟提前，而不影响消息传递延迟。理想情况下这应该没有必要，但应用程序之间的协调可能很棘手。）

这确实会对速度变化产生影响。SuperCollider 只有在其他对等端发送速度变化之后才会接收到它们，这对我们的时钟来说可能稍晚。在实践中，这意味着落在延迟间隙内的事件可能会稍微不同步，但同步应该会很快恢复。（因此，Link 并不适合涉及频繁速度或拍号变化的音乐。）

beatsPerBar 与 quantum

对于每一个时刻，Ableton Link 都知道拍子、以秒计的时间以及相位。相位是相对于量子来度量的。共享相同量子的 Link 对等端将同步小节线。

例如，假设 quantum = 4。Peer A 当前位于第 33 拍。Peer B 加入网络。Peer A 的上一个小节线是第 32 拍，因此 phase = 1。Peer B 的拍计数器应调整为具有相同的相位：在实践中，它将从 -3 开始。

小节线（同步）

如果你改变 quantum，Link 不保证拍子会保持相同的时长。拍子可能变短或变长，以尝试保持相位同步。

因此，你不应在演出过程中更改 quantum。Ableton 建议在开始前设置好 quantum。之后，你可以根据需要更改 SuperCollider 的 beatsPerBar，而无需更改 quantum，从而使 Link 的相位参考保持一致。

SuperCollider 对等端可以选择通过 LinkClock: -enableMeterSync 来同步小节线和所有拍号变化。这与 Link 的 quantum 无关，并且可以安全地在演出中途使用。参见 MeterSync。

Notifications

LinkClock 的状态可能会被其他已连接的 Link 对等节点更改。LinkClock 使用依赖通知将新状态转发给其他感兴趣的对象。

Notification

Event

\tempo

速度已改变

\meter

时钟的 beatsPerBar 已更改

\linkStart

外部对等端开始播放

\linkStop

外部对等端停止播放

\numPeers

连接的节点数量发生变化

\resynced

在 -enableMeterSync 之后，每当 MeterSync 的 -resyncMeter 调用成功完成时，都会发送一个 \resynced 通知。传递一个 Boolean 参数：如果找到了其他 SuperCollider 对等节点则为 true，否则为 false。

（请注意，Link 不会在对等端之间同步节拍；此通知继承自 TempoClock。LinkClock: -isSyncingMeter 是 SuperCollider 特有的同步节拍方式；它不属于 Link 协议。）

注册接收通知最方便的方式是使用 SimpleController。参见下面的示例。

类方法

.new

创建一个新的 LinkClock 实例。

参数：

tempo

初始 tempo。默认为 1。

beats

以拍为单位的时间，对应于参考时间。默认为 0。

seconds

参考时间，以秒为单位。参见 TempoClock: *new。

queueSize

调度队列的存储大小。参见 TempoClock: *new。

讨论：

如果在本地网络上发现了现有的 Link 会话，对象会连接到该会话并使用其属性：tempo 参数会被丢弃，转而使用会话的速度，而 beat 参数会被调整，以确保所有对等端之间正确的节拍和相位同步。如果 SuperCollider 是第一个加入的，则会在本地创建一个新的 Link 会话，并使用构造函数的参数进行初始化。

.newFromTempoClock

创建一个从 TempoClock 派生的 LinkClock 新实例。

参数：

clock

用于创建 LinkClock 的 TempoClock。

讨论：

LinkClock 的 tempo、beats、seconds 和 beatsPerBar 值被设置为 TempoClock 的对应值。随后 TempoClock 被停止，它的所有任务都由新创建的 LinkClock 重新调度，因此它们现在与 Link 会话同步。

实例方法

.latency

获取或设置 LinkClock 应考虑的 OSC 消息延迟秒数。通常，应将其设置为与服务器对象的延迟相匹配。

参数：

lat

一个 Float。

.tempo

在当前逻辑时间设置或获取当前会话速度。注意，速度可能随时被另一个对等端改变；在这种情况下，LinkClock 会广播一个 \tempo 通知（参见 LinkClock: Notifications）。

.beats

设置或获取以拍为单位的当前逻辑时间。如果你尝试设置拍数，Link 可能会调整你给定的值，以与其他 peer 保持同步。

.numPeers

获取连接到当前 Link 会话的对等节点数量。当对等节点加入或离开会话时，LinkClock 会广播一个 \numPeers 通知（参见 LinkClock: Notifications）。

.quantum

获取或设置 Link 的内部 quantum（见上文 beatsPerBar and quantum）。通常应在演出开始时进行此操作，或者完全不进行。在演出期间更改 quantum 是有风险的。局部更改拍号的方式与 TempoClock 中相同：TempoClock: -beatsPerBar。

参数：

quantum

一个 Integer 或 Float。

.enableMeterSync

通过在内部创建 MeterSync 对象来激活 SuperCollider 小节线同步。（如果已启用，则不会创建新对象。）

参数：

id

可选：一个整数 ID，唯一标识此实例。如果未提供，将随机选择一个。

ports

可选：一个端口号数组，小节线同步消息将被发送到这些端口。

返回值：

该 LinkClock 实例（用于支持链式配置方法，例如 l = LinkClock.new.latency_(s.latency).enableMeterSync，在这种情况下你希望 l 是时钟对象）。要访问 MeterSync 对象，请使用 -getMeterSync。

.disableMeterSync

移除所有小节线同步对象。

.isSyncingMeter

返回值：

一个布尔值，如果小节线同步处于活动状态则为 true，否则为 false。（如果你独立创建小节线同步对象，此答案可能不正确。）

.getMeterSync

返回值：

先前由 -enableMeterSync 创建的 MeterSync 对象。

注意： 尽管冗余且不推荐，但可以通过执行 clock.enableMeterSync 和 m = SCClockMeterSync(clock) 来创建多个小节线同步对象。getMeterSync 仅能访问由 clock.enableMeterSync 创建的对象。因此，建议在所有情况下都使用 clock.enableMeterSync。

示例

(
s.waitForBoot({
    SynthDef(\click, { |freq = 400, amp = 0.2|
        var sig = SinOsc.ar(freq, 0.5pi) *
            Env.perc(0.001, 0.06).ar(Done.freeSelf, levelScale: amp);
        OffsetOut.ar(0, sig.dup)
    }).add;
});
)

// 创建一个同步时钟
l = LinkClock(1).latency_(Server.default.latency);

// 用于监视状态的 GUI
(
var win = Window("LinkClock", Rect(200, 200, 500, 100)).front,
peersBox, tempoBox, barsBox, beatsBox,
font = Font.default.copy.size_(32),
boldFont = font.boldVariant,
controller, task;

win.layout = HLayout(
    StaticText().font_(font).string_("Peers:"),
    peersBox = NumberBox().font_(boldFont).align_(\center).fixedWidth_(80),
    StaticText().font_(font).string_("Tempo:"),
    tempoBox = NumberBox().font_(boldFont).align_(\center).fixedWidth_(120),
    StaticText().font_(font).string_("Now:"),
    barsBox = NumberBox().font_(boldFont).align_(\center).fixedWidth_(80),
    beatsBox = NumberBox().font_(boldFont).align_(\center).fixedWidth_(80)
);

[peersBox, barsBox, beatsBox].do { |view| view.enabled_(false) };

tempoBox.action = { |view| l.tempo = view.value / 60 };
tempoBox.value = l.tempo * 60;
peersBox.value = l.numPeers;

task = Routine {
    var bars, beats;
    loop {
        bars = l.bar;
        beats = l.beatInBar;
        {
            barsBox.value = bars;
            beatsBox.value = beats;
        }.defer(l.latency);
        1.0.wait;
    }
}.play(l, quant: 1);

controller = SimpleController(l)
.put(\tempo, {
    defer { tempoBox.value = l.tempo * 60 }
})
.put(\numPeers, {
    defer { peersBox.value = l.numPeers }
})
.put(\stop, { defer { win.close } });

win.onClose = { task.stop; controller.remove };
)

// 现在使用 Ableton Link 启动一个程序来测试同步

// pattern 会自动应用服务器延迟，
// 因此这里应该是同步的
p = Pbind(\instrument, \click, \freq, Pseq([900, Pn(400, 3)], inf)).play(l, quant: 4);

// 在 Task 中, 你需要自行处理延迟:
(
r = Task {
    loop {
        s.makeBundle(s.latency, {
            Synth(\click, [freq: exprand(500, 1200)])
        });
        1.wait;
    }
}.play(l, quant: 4);
)

// 在另一个应用程序中更改速度应该会影响 SC 中的速度
// 在 SC 中更改速度应该会影响每个连接的应用程序
l.tempo = 90/60;

// 开始/停止通知
// 远程对等端应启用开始/停止同步
(
q = nil;
c = SimpleController(l)
.put(\linkStart, {
    if(q.isNil) {
        q = Pbind(
            \degree, Pn(Pseries(0, 1, 8), inf),
            \dur, 0.25
        ).play(l, quant: -1);
    }
})
.put(\linkStop, {
    q.stop;
    q = nil;
})
.put(\stop, { c.remove });  // 如果时钟停止则清理
)

p.stop;
r.stop;
l.stop;
