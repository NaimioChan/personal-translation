Pitch

自相关音高跟踪器

MultiOutUGen : UGen : AbstractFunction : Object

说明

这是比 ZeroCrossing 更好的音高跟踪器，但消耗更多 CPU。对于大多数用途，可以使用默认设置，只需提供 in。Pitch 返回两个值（通过由 OutputProxy 组成的 Array，参见 OutputProxy 帮助文件），一个是 freq，即音高估计值，另一个是 hasFreq，表示是否找到了音高。某些元音仍然有问题，例如介于低音短 'a' 音（如 'sat' 中）和长 'i' 音（如 'fire' 中）之间的张大嘴声音，包含足够的泛音能量，会干扰该算法。

类方法

参数：

in

initFreq

minFreq

maxFreq

execFreq

maxBinsPerOctave

median

ampThreshold

peakThreshold

讨论：

音高跟踪器以 execFreq 指定的速率（单位为 cps）周期性执行。execFreq 被限制在 minFreq 和 maxFreq 之间。首先，它检测输入峰峰值幅度是否高于 ampThreshold。如果不是，则不执行音高估计，hasFreq 被设为零，freq 保持其先前的值。它对输入执行自相关，并寻找零延迟附近峰值之后的第一个峰值，该峰值要高于零延迟处峰值幅度的 peakThreshold 倍。

如果 clar 参数大于零（默认值为零），则 hasFreq 会给出额外细节。当检测到音高时，它不再是简单的 1，而是在零到一范围内的“清晰度”度量。（技术上，它是自相关峰值的高度除以零延迟峰值的高度后的归一化值。）因此，它给出了有音高信号的一种“纯度”度量。

使用一半的 peakThreshold 可以很好地消除泛音，而找到高于该阈值的第一个峰值（而不是绝对最大峰值）可以很好地消除实际上是波形多个周期的估计值。

自相关首先使用最多 maxBinsPerOctave 个延迟进行粗略计算，直到定位到峰值。然后执行精细分辨率搜索，直到找到峰值。（注意 maxBinsPerOctave 不影响最终的音高分辨率；精细分辨率搜索总是会执行。将 maxBinsPerOctave 设置得更大将使粗略搜索耗时更长，将其设置得更小将使精细搜索耗时更长。）

峰值周围的三个值用于求出音高的分数延迟值。如果音高频率高于 maxFreq，或者在 minFreq 以上没有找到峰值，则将 hasFreq 设为零，并将 freq 保持为其先前的值。

可以在输出估计上放置一个长度为 median 的中值滤波器，从而消除离群值和抖动。然而，这会为新音高的音高估计增加延迟，因为中值滤波器必须有一半被新值填充后，新值才会成为中值。如果 median 设为一，则等同于没有滤波器，这也是默认值。

当找到范围内峰值时，将其插入中值滤波器，从中值滤波器中读出新的音高并作为 freq 输出，同时将 hasFreq 设为 1。

可以通过整数因子 downSample 对输入信号进行降采样，以减少 CPU 开销。这也会降低音高分辨率。

在 Pitch 首次找到音高之前，它将输出 initFreq。

这些设置都不是时变的。

实例方法

示例

// （使用耳机！）

(
    SynthDef("pitchFollow1", { |out|
        var in, amp, freq, hasFreq, sound;
        in = Mix.new(SoundIn.ar([0, 1]));
        amp = Amplitude.kr(in, 0.05, 0.05);
        # freq, hasFreq = Pitch.kr(in, ampThreshold: 0.02, median: 7);
        // freq = Lag.kr(freq.cpsmidi.round(1).midicps, 0.05);
        sound = Mix.new(VarSaw.ar(freq * [0.5, 1, 2], 0, LFNoise1.kr(0.3, 0.1, 0.1), amp));
        6.do {
            sound = AllpassN.ar(sound, 0.040, [0.040.rand, 0.040.rand], 2)
        };
        Out.ar(out, sound);
    }).play
)
(
    SynthDef("pitchFollow2", { |out|
        var in, amp, freq, hasFreq, sound;
        in = Mix.new(SoundIn.ar([0, 1]));
        amp = Amplitude.kr(in, 0.05, 0.05);
        # freq, hasFreq = Pitch.kr(in, ampThreshold: 0.02, median: 7);
        sound = CombC.ar(LPF.ar(in, 1000), 0.1, (2 * freq + 10).reciprocal, -6).distort * 0.05;
        6.do({
            sound = AllpassN.ar(sound, 0.040, [0.040.rand, 0.040.rand], 2)
        });
        Out.ar(out, sound);
    }).play(s);
)

/*

RM octaver

inSignal is RingModulated by a sinusoidal tone with half frequency.
The resulting spectrum is given by all the components of inSignal with
half freqs.
This means that the new spectrum is a one 8ve below version of the input signal's one,
with only odd partials.
As a consequence, if inSignal is added again, even partials are
recovered.

See:
Miller Puckette, The Theory and Technique of Electronic Music, p. 126
http://crca.ucsd.edu/~msp/techniques/latest/book.pdf
http://crca.ucsd.edu/~msp/techniques/latest/book-html/node77.html#sect5.ringmod

andreavalle

*/

(
    SynthDef(\RmOctaver, { |out|
        var in, freq, hasFreq;
        in = SoundIn.ar(0);
        # freq, hasFreq = Pitch.kr(in);
        Out.ar(out, SinOsc.ar(freq: freq * 0.5) * in + in);
    }).add;
)

Synth.new(\RmOctaver);
