時間ベースのフィルター

Delay、Comb 和 Allpass 等 UGen 生成基于时间的特效。这适合制作混响等赋予空间或位置感的特效。

////////////////////////////////////////////////////////////////////////////////////////////////////

// 两个 SynthDef。第一个 SynthDef 生成颗粒，第二个 SynthDef 延迟它们
//  生成颗粒的 SynthDef 是左声道
// 延迟颗粒的 SynthDef 是右声道
(
SynthDef("someGrains", { arg centerFreq = 777, freqDev = 200, grainFreq = 2;
    var gate;
    gate = Impulse.kr(grainFreq);
    Out.ar(
        0,
        SinOsc.ar(
            LFNoise0.kr(4, freqDev, centerFreq),
            0,
            EnvGen.kr(Env.sine(0.1), gate, 0.1)
        )
    )
}).add;

SynthDef("aDelay", { arg delay = 0.25;
    Out.ar(
        1,
        DelayN.ar(
            In.ar(0, 1),
            delay,
            delay
        )
    )
}).add;
)

// グレインをテストして ... オフにしなさい
// 全て左チャンネルだけ ... グッド！
Synth("someGrains");


// ２つのグループを作成。第1はソース、第2はエフェクト。
(
~source = Group.head(s);
~effects = Group.tail(s);
)

// グレインをディレイに配置する ... ソースは左でディレイをかけられたソースは右
(
Synth.head(~source, "someGrains");
Synth.head(~effects, "aDelay");
)

フィードバック・フィルター

Comb 和 Allpass 滤波器是 UGen 将自己的输出反馈到输入的示例。与 Comb 滤波器相比，Allpass 滤波器通常听起来没有太大区别。然而，Allpass 滤波器会改变通过它的信号的相位。因此，在 UGen 网络中使用它时很方便。

// インターナル・サーバーを起動！！
// 最初はCombフィルターで次がAllpassフィルター（パラメータは同じ）。両者を比較せよ。
(
{
    CombN.ar(
        SinOsc.ar(500.rrand(1000), 0, 0.2) * Line.kr(1, 0, 0.1),
        0.3,
        0.25,
        6
    )
}.scope;
)

// 前の例とそんなに大きな違いは無い
(
{
    AllpassN.ar(
        SinOsc.ar(500.rrand(1000), 0, 0.2) * Line.kr(1, 0, 0.1),
        0.3,
        0.25,
        6
    )
}.scope;
)

// 最初はCombフィルターで次がAllpassフィルター（パラメータは同じ）。両者を比較せよ。
// ２つの例はもっと短いディレイ・タイムを持つ ... 0.1秒
(
{
    CombN.ar(
        SinOsc.ar(500.rrand(1000), 0, 0.2) * Line.kr(1, 0, 0.1),
        0.1,
        0.025,
        6
    )
}.scope;
)

// ディレイ・タイムを短くすると、allpassフィルターはcombフィルターよりより広がって聞こえるようになる
(
{
    AllpassN.ar(
        SinOsc.ar(500.rrand(1000), 0, 0.2) * Line.kr(1, 0, 0.1),
        0.1,
        0.025,
        6
    )
}.scope
)

リバーブレーション

以下示例由 James McCartney 编写，做了如下修改：使用 .scope 而不是 .play，并且变量在函数内部声明。此示例来自 SuperCollider 2 发行版中的部分文档 01 Why SuperCollider。

这实际上是 Schroeder 混响的一种实现，信号通过并联的 Comb 滤波器组，再经过几个串联的 Allpass 滤波器。

(
{
var s, z, y;
    // ランダムな10ボイス分のサイン波のパーカッション・サウンド：
s = Mix.ar(Array.fill(10, { Resonz.ar(Dust.ar(0.2, 50), 200 + 3000.0.rand, 0.003)}) );
    // リバーブのプリ・ディレイ・タイム：
z = DelayN.ar(s, 0.048);
    // 並列に7つの長さを変調されたcombによるディレイ：
y = Mix.ar(Array.fill(7,{ CombL.ar(z, 0.1, LFNoise1.kr(0.1.rand, 0.04, 0.05), 15) }));
    // 4つのallpassによるディレイの２つの並列したチェーン（合計8個）：
4.do({ y = AllpassN.ar(y, 0.050, [0.050.rand, 0.050.rand], 1) });
    // オリジナルのサウンドをリバーブに加えてそれを再生：
s+(0.2*y)
}.scope
)

コンポーネント

以下示例展示了如何将 01 Why SuperCollider 文档中刚刚描述的合成过程拆分为小而简单的部分。它还展示了如何并行滤波信号（参见 "combs" 的 SynthDef）以及如何串联滤波信号（参见 "allpass" 的 SynthDef）。此示例还演示了如何在每次合成器运行时使用随机生成的控制值。

这个例子还说明了，为方便起见，如何将多声道音频扩展到任意数量的总线上。也就是说，虽然跨总线扩展音频的总线分配在 SynthDef 中是固定的，但可以轻松地将其分配到控件上。

前の例をより小さな部分に分解することのアドバンテージは、オーディオ・バスに送られる最初の要素にならなければならない、ソースのオーディオを除いて、残りの部分は任意の順序に組み替え直すことができるということです。

(
SynthDef("filteredDust", {
    Out.ar(
        2,
        Mix.arFill(10, { Resonz.ar(Dust.ar(0.2, 50), Rand(200, 3200), 0.003) })
    )
}).add;

SynthDef("preDelay", {
    Out.ar(
        4,
        DelayN.ar(In.ar(2, 1), 0.048, 0.048)
    )
}).add;

SynthDef("combs", {
    Out.ar(
        6,
        Mix.arFill(7, { CombL.ar(In.ar(4, 1), 0.1, LFNoise1.kr(Rand(0, 0.1), 0.04, 0.05), 15) })
    )
}).add;

SynthDef("allpass", { arg gain = 0.2;
    var source;
    source = In.ar(6, 1);
    4.do({ source = AllpassN.ar(source, 0.050, [Rand(0, 0.05), Rand(0, 0.05)], 1) });
    Out.ar(
        8,
        source * gain
    )
}).add;

SynthDef("theMixer", { arg gain = 1;
    Out.ar(
        0,
        Mix.ar([In.ar(2, 1), In.ar(8, 2)]) * gain
    )
}).add;
)

// それぞれの行が実行されると、それぞれは最後のノードになる。結果は、"filteredDust"が最初のノードになり、
// "theMixer"が最後のノードになる。これは我々が望んだ通りである。
(
Synth.tail(s, "filteredDust");
Synth.tail(s, "preDelay");
Synth.tail(s, "combs");
Synth.tail(s, "allpass");
Synth.tail(s, "theMixer");
)

////////////////////////////////////////////////////////////////////////////////////////////////////

または、グループを使って前の例のシンセの実行の順序をコントロールします。

(
~source = Group.tail(s);
~proc1 = Group.tail(s);
~proc2 = Group.tail(s);
~proc3 = Group.tail(s);
~final = Group.tail(s);
)

// 以下のノードは、上で並べた通りに、グループにアサインされる
// それゆえ、これらは正しい順序で実行される
(
Synth.head(~final, "theMixer");
Synth.head(~proc3, "allpass");
Synth.head(~proc2, "combs");
Synth.head(~proc1, "preDelay");
Synth.head(~source, "filteredDust");
)

上に示した様に正しい順序にグループを配置することはそれにアサインされるシンセもまた正しい順序になるということを保証します。

作为背景参考，下面是 SuperCollider 2 发行版中 01 为什么选择 SuperCollider 文档（作者 James McCartney）的完整文本。

为什么是 SuperCollider 2.0？

SuperCollider 2.0 版是一门新的编程语言。为什么要发明一门新语言而不使用现有语言？ 计算机音乐作曲是一个规格说明问题。声音合成与声音的作曲都是复杂问题，需要一门具有高度表达力的语言来应对这种复杂性。实时信号处理是一个需要高效实现且操作时间有界的问题。当时没有一门语言能结合我进行数字音乐合成所想要和需要的各项特性。SuperCollider 语言最像 Smalltalk。一切都是对象。它具有类对象、方法、动态类型、完整闭包、默认参数、变长参数列表、多重赋值等特性。其实现提供了快速、常数时间的方法查找、实时垃圾回收，以及大多数函数上下文的栈分配，同时保持完整的闭包语义。SuperCollider 虚拟机的设计使其能够在中断级别运行。当时没有其他现成可用的语言既具备高级特性、实时性，又能够在中断级别运行。

SuperCollider 1.0 版本被完全重写，使其既更具表达力又更高效。这要求根据第一版的经验重新思考实现方式。我认为新版本从这种重新思考中获益良多。它并非只是功能更多的 1.0 版本。

为什么使用基于文本的语言而不是图形语言？对此至少有两个答案。动态性：大多数图形化合成环境使用静态分配的 unit generator。在 SuperCollider 中，用户可以创建动态地、以嵌套方式产生事件的结构。Patch 可以动态构建，并且不仅可以通过来自静态乐谱的浮点数进行参数化，还可以通过其他 unit generator 图进行参数化。或者你可以即时地以算法方式构建 patch。这种流动性在具有静态分配 unit generator 的语言中是不可能的。简洁性：在 SuperCollider 中，patch 中的对称性可以通过多通道扩展或程序化 patch 构建来利用。例如，下面这个简短的程序生成了一个包含 49 个 unit generator 的 patch。在图形程序中，这可能需要大量的时间和空间来连接。另一个优点是，下面 patch 的大小可以通过仅更改几个常量来轻松扩展或收缩。

(
{
    // 10 个声部的随机正弦打击乐声音：
s = Mix.ar(Array.fill(10, { Resonz.ar(Dust.ar(0.2, 50), 200 + 3000.0.rand, 0.003)}) );
    // 混响预延迟时间：
z = DelayN.ar(s, 0.048);
    // 7 个长度调制的梳状延迟并行：
y = Mix.ar(Array.fill(7,{ CombL.ar(z, 0.1, LFNoise1.kr(0.1.rand, 0.04, 0.05), 15) }));
    // 两条并行的 4 个 allpass 延迟链（共 8 个）：
4.do({ y = AllpassN.ar(y, 0.050, [0.050.rand, 0.050.rand], 1) });
    // 将原始声音添加到混响中并播放：
s+(0.2*y)
}.play )

图形化合成环境正变得随处可见。似乎每个月都会有一个新的环境发布。它们中没有一个具备 SuperCollider 完整编程环境那样的动态灵活性。翻一翻 SuperCollider 的帮助文件和示例，你自己看看就知道了。
