Onsets

起始检测器

UGen : AbstractFunction : Object

另请参见：BeatTrack、Loudness、MFCC、Pitch、KeyTrack

说明

用于音乐音频信号的起始检测器 - 检测音符/鼓点等的起始。输出一个控制速率触发信号，检测到起始时为 1，否则为 0。

有关所有涉及的过程、不同的起始检测函数及其评估的更多详细信息，请参阅：

D. Stowell 和 M. D. Plumbley。用于改进实时音频起音检测的自适应白化。Proceedings of the International Computer Music Conference (ICMC2007)，丹麦哥本哈根，2007 年 8 月。参见 http://c4dm.eecs.qmul.ac.uk/papers/2007/StowellPlumbley07-icmc.pdf

类方法

Onsets.kr(chain, threshold: 0.5, odftype: 'rcomplex', relaxtime: 1, floor: 0.1, mingap: 10, medianspan: 11, whtype: 1, rawodf: 0)

参数：

chain

一个 FFT 链。

threshold

检测阈值，通常在 0 到 1 之间，尽管在极少数情况下你可能会发现超出此范围的值也有用。

odftype

选择使用哪个起始检测函数。多数情况下默认值即可。更多选项列于下文。

其余参数都是调整因子，将在下面的高级功能部分中说明：

relaxtime

floor

mingap

medianspan

whtype

rawodf

讨论：

以下选项可用于 odftype：

\power

通常没问题，适合打击类输入，而且非常高效

\magsum

通常没问题，适合打击类输入，而且非常高效

\complex

总体表现很好，但更消耗 CPU

\rcomplex

通常表现非常好，且比 \complex 略更高效

\phase

通常效果良好，尤其适用于有调性输入，效率中等

\wphase

通常非常好，尤其对于有调性输入，中等效率

\mkl

通常非常好，中等效率，与其他方法相当不同

对于 FFT 链，通常应使用 512 或 1024 的帧大小（在 44.1 kHz 采样率下）以及 50% 的跳跃大小（这是 SC 中的默认设置）。对于不同的采样率，请选择能够覆盖相似时间跨度（约 10 到 20 ms）的 FFT 大小。

起始检测应能很好地适用于一般的单声道和多声道音频信号。起始检测纯粹基于信号分析，不使用任何诸如速度之类的“自上而下”的推断。

应该选择哪种起音检测函数？差异并不大，所以我建议你坚持使用默认的 \rcomplex，除非你发现它存在特定问题。然后可以尝试 \wphase。\mkl 类型与其他类型略有不同，所以也许也可以试试。它们都具有略微不同的特性，在测试中表现出相似的质量水平。

高级特性

还有更多选项可用，如果你愿意可以自行探索。它们是一些调节起音检测器行为的数字：

  • relaxtime 和 floor 是所用白化过程的参数，白化过程是对 FFT 信号的一种归一化。（注意：在 \mkl 模式下不使用这些参数。）

    • relaxtime 指定归一化“遗忘”最近一次起音所需的时间（以秒为单位）。如果你发现过多的重复触发（例如某个音符不均匀地衰减），那么你可能希望增大此值。
    • floor 是一个下限，与“声音预期能安静到什么程度而不至于变得与噪声无法区分”这一理念相关联。对于一些动态范围宽广、录制干净的古典音乐，我发现将其一直降到 0.000001 会很有帮助。
  • mingap 指定起音检测之间的最小间隔（以 FFT 帧为单位），这是一种防止重复检测过多的暴力方法。
  • medianspan 指定用于在触发前平滑检测函数的中值窗口大小（以 FFT 帧为单位）。

实例方法

示例

////////////////////////////////////////////////////////////////////////////////////////////////
// 移动鼠标以改变阈值
(
x = {
    var sig, chain, onsets, pips;

    // 一个简单的生成式信号
    sig = LPF.ar(Pulse.ar(TIRand.kr(63, 75, Impulse.kr(2)).midicps), LFNoise2.kr(0.5).exprange(100, 10000)) * Saw.ar(2).range(0, 1);
    // 或者，取消注释这一行，如果你想在以下代码中播放缓冲区：
    // sig = PlayBuf.ar(1, d, BufRateScale.kr(d), loop: 1);

    chain = FFT(LocalBuf(512), sig);

    onsets = Onsets.kr(chain, MouseX.kr(0, 1), \rcomplex);

    // 每当检测到起音时，你都会听到打击性的"嘀嗒"声
    pips = WhiteNoise.ar(EnvGen.kr(Env.perc(0.001, 0.1, 0.2), onsets));
    Pan2.ar(sig, -0.75, 0.2) + Pan2.ar(pips, 0.75, 1)
}.play;
)
x.free; // 释放合成器

////////////////////////////////////////////////////////////////////////////////////////////////
// Or we could expand this multichannel, run a series of different thresholds at the same time,
// to sonify the effect of the threshold value.
// A little hard to listen to at first: try and identify a pitch at which the best sort of
// detection is happening.
// You'll hear "bobbling" at low pitches where the threshold is definitely too low.

(
var threshes = (0.1, 0.2 .. 1);
x = {
    var sig, chain, onsets, pips;

    // 一个简单的生成式信号
    sig = LPF.ar(Pulse.ar(TIRand.kr(63, 75, Impulse.kr(2)).midicps), LFNoise2.kr(0.5).exprange(100, 10000)) * Saw.ar(2).range(0, 1);
    // 或者，取消注释这一行，如果你想在以下代码中播放缓冲区：
    // sig = PlayBuf.ar(1, d, BufRateScale.kr(d), loop: 1);

    chain = FFT(LocalBuf(512), sig);

    onsets = Onsets.kr(chain, threshes, \rcomplex);

    // 以各种音高生成短促音
    pips = SinOsc.ar((threshes).linexp(0, 1, 440, 3520), 0, EnvGen.kr(Env.perc(0.001, 0.1, 0.5), onsets)).mean;
    Pan2.ar(sig, -0.75, 0.2) + Pan2.ar(pips, 0.75, 1)
}.play;
)

x.free; // 释放合成器
[b, d].do(_.free); // 释放缓冲区
