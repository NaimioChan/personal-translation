音频设备选择

用于进行音频设备选择的参考

另请参见：Server、ServerOptions

本参考提供有关音频设备选择的信息，包括平台特定的细节。

可以通过 ServerOptions 的实例选择特定设备。要访问默认服务器的 ServerOptions 实例，可以使用 Server.default.options。ServerOptions 还允许你指定设备的其他重要参数——采样率和硬件缓冲区大小。

注意： 设备选择在服务器（重新）启动之前不会生效。

macOS

默认情况下，服务器将启动到系统的默认音频设备。如果你想明确告诉服务器使用内置声卡，需要同时指定输入和输出设备。以下示例来自一台 MacBook Pro：

Server.default.options.inDevice_("Built-in Microph");
Server.default.options.outDevice_("Built-in Output");

在使用专用音频接口的情况下，你可能需要指定单个设备，例如

Server.default.options.device_("MOTU 828");

在 Windows 和 macOS 上，你可以在不启动服务器的情况下以编程方式获取可用音频设备列表：

ServerOptions.devices; // 所有设备
ServerOptions.inDevices; // 输入设备
ServerOptions.outDevices; // 输出设备

采样率不匹配

服务器可能启动失败的一个原因，是输入和输出设备的采样率不匹配，当对输入和输出使用不同的设备时（例如使用 Mac 的内置声卡时），就可能出现这种情况。如果服务器因采样率不匹配而启动失败，将会相应地发布一条错误信息。

你应将输入和输出设备的采样率设为相同的值。你可以在 Audio MIDI Setup 中完成此操作：

"open -a 'Audio MIDI Setup'".unixCmd; // 执行此操作以启动它

聚合设备

有时你可能想使用多个设备进行输入或输出。macOS 提供了一种将多个物理设备组合成一个虚拟聚集设备的方法。要创建一个聚集设备，你必须打开 Audio MIDI Setup 应用程序（位于 /Applications/Utilities 中）。你应当从具有管理员权限的用户账户执行此操作。

"open -a 'Audio MIDI Setup'".unixCmd; // 执行此操作以启动它
  • 在 Audio Devices 窗口中点击左下角的加号按钮，然后选择 Create Aggregate Device。
  • 如果愿意，你可以将其名称改为某个特定的名称，例如 "InternalAndMOTU"。
  • 查看右侧的 Use 列，了解要组合的设备。

现在你需要告诉 SuperCollider 使用你的新聚合设备。

Server.default.options.device = "Aggregate Device"; //或你在上一步中指定的名称

重启服务器（Server.default.reboot）后，你应该会在后置窗口中看到它现在使用聚合设备而不是系统默认设备：

[...]
"Aggregate Device" Input Device
[...]
"Aggregate Device" Output Device

请注意，当你通过 SuperCollider 的 ServerOptions 指定声音设备时，无需将该聚合设备用作系统的默认设备。

Linux

在 Linux 上，SuperCollider 默认使用 JACK，音频设备的选择由 JACK 服务器管理。ServerOptions 无法覆盖 JACK 对音频硬件的选择。

使用 JACK 服务器进行设置

SuperCollider 服务器被视为一个 JACK 客户端。在以下章节中，术语客户端将从 JACK 的角度指代 SuperCollider 服务器。

当服务器编译为使用 JACK 作为音频后端时，ServerOption 的 device 可用于两种方式：将客户端名称设置为向 JACK 注册：

Server.default.options.device = "my_synth";

使用特定的 JACK 服务器，并设置客户端名称：

Server.default.options.device = "JACKServerName:scsynthName";

设备为 nil 等效于 Server.default.options.device = "default:SuperCollider";

Jack 环境变量

JACK 连接可通过环境变量 SC_JACK_DEFAULT_INPUTS 和 SC_JACK_DEFAULT_OUTPUTS 进行配置。这些变量允许 SuperCollider 检测系统对进出 scsynth 服务器的 Jack 输入的偏好设置。

这些变量写为一个字符串，用于指定另一个 jack 客户端，或以逗号分隔的 jack 端口列表（格式为字符串）。

SuperCollider 语言客户端默认将这些环境变量设置为 "system"，因此从 SC 语言启动的服务器默认会连接。

如果这些没有设置，服务器将不会自动连接到任何 JACK 端口。你可以手动连接它们，也可以通过执行 jack_connect / jack_disconnect shell 命令（String: -unixCmd）来连接。因此，从命令行启动的服务器不会自动连接，除非你在同一终端会话或 shell 配置文件（见下文）中设置这些变量。

这是从 SuperCollider 脚本内部更改 SuperCollider 的 Jack 环境变量的推荐方式：

// 使用 system 将第一个连接到输入通道
"SC_JACK_DEFAULT_INPUTS".setenv("system:capture_1,system:capture_2");

// 用 system 连接所有输出通道
"SC_JACK_DEFAULT_OUTPUTS".setenv("system");

作为替代方案，也可以通过在 .bash_profile、.zsh_profile 或 shell 的类似启动文件中设置以下环境变量来更改这些设置：

export SC_JACK_DEFAULT_INPUTS="system"
export SC_JACK_DEFAULT_OUTPUTS="system"

要从语言端禁用自动连接：

"SC_JACK_DEFAULT_INPUTS".unsetenv;
"SC_JACK_DEFAULT_OUTPUTS".unsetenv;

Windows

默认情况下，服务器将使用 WASAPI 驱动启动到系统的默认音频设备。

在 Windows 上有多种音频驱动 API（例如 MME、WASAPI、ASIO 等）可用于与音频设备通信。API（列在设备名称之前）在输入和输出之间必须匹配，例如：

o = Server.default.options;
o.inDevice_("Windows WASAPI : Microphone");
o.outDevice_("Windows WASAPI : Speakers");
Server.default.reboot;

你可以在不启动服务器的情况下以编程方式获取可用音频设备列表：

ServerOptions.devices; // 所有设备
ServerOptions.inDevices; // 输入设备
ServerOptions.outDevices; // 输出设备

Windows 支持部分设备名称匹配（但 macOS 不支持）。

注意： 将 sampleRate（例如 Server.default.options.sampleRate）留为 nil 对于 ASIO 设备，很可能导致硬件被设置为以 44100 Hz 运行。

选择设备和 API

  • 如果你需要指定设备，则必须同时为输入和输出指定（同时设置 .inDevice 和 .outDevice），除非你使用 ASIO
  • 输入和输出设备都需要使用相同的 API（列在名称之前，例如 MME、WDM-KS 等）。
  • 输入和输出设备应使用相同的采样率（尽管某些 API 可能提供重采样）。这可以在 Windows 的音频控制面板中设置。

以下列表提供了不同 API 的基本参考。最推荐的 API 列在最前面。

可用 API 列表

ASIO
  • 最大通道数：支持任意数量的输入/输出通道，由硬件提供
  • 典型延迟：低
  • 注意事项：专用 ASIO 驱动需要由音频设备制造商提供；这对大多数（半）专业接口来说是常见的，但对内置声卡则不一定。
  • 更多信息： 专为专业音频设备设计；对采样率和硬件缓冲区大小的控制通常由驱动的控制面板提供（即无法由 SuperCollider 设置）；ASIO 代表 Audio Stream Input/Output，由 Steinberg 开发
WASAPI
  • 最大通道数：通常仅支持单声道或立体声；超过 2 个通道的设备可能会被表示为多个立体声对
  • 典型延迟：低
  • 注意事项：默认启用重采样，因此 SuperCollider 可以以不同于硬件的采样率运行，其他应用程序也可以共享同一设备
  • 更多信息： WASAPI 代表 Windows Audio Session API，是最现代的 Windows 音频 API
WDM-KS
  • 最大通道数：通常仅支持单声道或立体声；超过 2 个通道的设备可能会被表示为多个立体声对
  • 典型延迟：低
  • 注意事项：在某些系统上，使用此 API 时 SuperCollider 会阻止其他应用程序使用音频设备
  • 更多信息：WDM-KS 代表 Windows Driver Model Kernel Streaming。它是第一个提供合理低延迟的原生 Windows API
DirectSound
  • 最大通道数：通常仅支持单声道或立体声；超过 2 个通道的设备可能会被表示为多个立体声对
  • 典型延迟：中等/高
  • 注意事项：这是一个较旧的 API，通常比更新的 API 性能更差
  • 更多信息：DirectSound 是 DirectX 的一部分，最初是考虑到游戏音频而创建的
MME
  • 最大通道数：通常仅支持单声道或立体声；超过 2 个通道的设备可能会被表示为多个立体声对
  • 典型延迟：高
  • 注意事项：它是此列表中最古老的 API；如果用户未指定要使用哪个设备，则默认选择它
  • 更多信息： 此 API 可能开箱即用，但选择更新的 API 通常会提供更好的性能；MME 代表 Multimedia Extension（用于 Windows 3.0）

如果 ASIO 驱动可用，它很可能是确保低输入/输出延迟的最佳选择。ASIO 驱动通常通过单个设备同时提供输入和输出。

注意： 在 Windows 上，ASIO 驱动程序很可能是多声道操作的唯一选项（允许同时使用超过 2 个输入/输出）。

o = Server.default.options;
o.device = "ASIO : UMC ASIO Driver";
Server.default.reboot;

ASIO4ALL

如果你使用的是内置声卡或没有附带 ASIO 驱动的设备，另一种选择是使用 ASIO4ALL。它是一个虚拟 ASIO 驱动，使用 Windows 原生 API 与声卡通信。它可能为内置声卡提供更好的性能，并且应允许此类设备进行多通道操作（如果硬件支持）。使用网络搜索引擎查找下载链接。

注意： ASIO4ALL 通常不会比专用的 ASIO 驱动提供更好的性能。

安装 ASIO4ALL 后，可以按如下方式选择它（在服务器启动时于 post 窗口中确认）：

Server.default.options.device = "ASIO : ASIO4ALL v2";
