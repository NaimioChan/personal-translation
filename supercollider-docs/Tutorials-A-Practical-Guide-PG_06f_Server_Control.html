模式指南 06f：服务器控制

管理服务器端资源的模式

另请参见：Pattern Guide 06e: Language Control、Pattern Guide 06g: Data Sharing

服务器控制方法

少数滤波器模式可以在私有总线和/或组上隔离信号，并且还能应用效果 synth。一个很好的特性是，模式开始时分配的资源会在结束时被移除。这对效果特别有用，因为你不希望留下大量效果 synth 占用 CPU 却不处理音频。

Pbus(pattern, dur, fadeTime, numChannels, rate)

为模式所演奏的 synth 创建一个私有组和总线。当模式停止时，组和总线会被释放。适用于隔离不同模式的信号。

Pgroup(pattern)

为模式的 Synth 创建一个私有组（不含私有总线）。

Pfx(pattern, fxname, pairs)
Pfxb(pattern, fxname, pairs)

这两个模式都在目标组的尾部播放一个效果 Synth。这个 Synth 应从 out 参数所标识的总线读取，并使用 ReplaceOut 或 XOut 将处理后的信号写入同一总线。Pfx 使用传入事件中指定的任意总线和组。Pfxb 则为效果和模式分配单独的总线和组。

在信号路由和效果管理方面也有许多排列组合，此处无法深入讨论。一些主要场景包括：

  • 应当分别应用的独立效果：模式与效果应隔离在不同的总线上。Pfxb 会自动处理这种隔离：像 Pfxb(Pbind(...), \fxname, \effectargName, value, \name, value...) 这样的两个模式会在不同的总线上播放，它们的信号不会相互干扰。
  • 应当以链式方式应用的效果：两个效果应使用同一总线，并且效果模式应嵌套以将它们串联起来。最外层的效果应使用 Pfxb 为该信号链分配独立的组和总线；内层效果应使用 Pfx 复用已有的总线。
Pfxb(
    Pfx(
        (event pattern here),
        \synthDefNameOfFirstEffectInChain,
        (argument list for the first effect),
    )
    \synthDefNameOfSecondEffectInChain,
    (argument list for the second effect)
).play;

通过嵌套以及使用 Ppar 及其同类并行化 Pfx 或 Pfxb 模式，可以实现更复杂的编排。

此示例使用 Pfxb 在不同总线上分离一对独立发声的模式，并将两个信号的流分别通过独立的音量控制。为示例起见，音量效果合成器被刻意保持简单，但它当然可以执行你想要的任何类型的信号处理。

起初为效果使用门控包络可能看起来有些奇怪，但这对于保持信号的完整性很重要。如果没有门控，效果 synth 将被 n_free（粗暴地切断），很可能在源模式播放的节点完成之前。在这种情况下，它会在结束时产生突然、短暂的音量跳变。门控与包络中一秒的释放相结合，使效果 synth 保持足够长的时间，以便其源 synth 先变为静音。

请记住，由模式创建的流不会暴露其内部结构。这意味着你无法直接调整效果 Synth 的参数，因为你无从得知它的节点 ID。示例通过为振幅值分配几个控制总线，并将音量 Synth 映射到这些控制总线来解决此问题。这样，小型 GUI 只需更新控制总线的值即可。

// 演示 Pfxb 如何隔离不同总线上的信号
// 此处的 fx synth 是一个简单的音量控制
// 但它可以更复杂

(
SynthDef(\volumeCtl, { |out, amp = 1, gate = 1|
    var    sig = In.ar(out, 2) * amp;
    sig = sig * EnvGen.kr(Env(#[1, 1, 0], #[1, 1], -3, releaseNode: 1), gate, doneAction: Done.freeSelf);
    ReplaceOut.ar(out, sig)
}).add;

~vbus1 = Bus.control(s, 1).set(0.5);
~vbus2 = Bus.control(s, 1).set(0.5);

~window = Window.new("mixers", Rect(10, 100, 320, 60));
~window.view.decorator = FlowLayout(~window.view.bounds, 2@2);
EZSlider(~window, 310@20, "low part", \amp, { |ez| ~vbus1.set(ez.value) }, 0.5);
~window.view.decorator.nextLine;
EZSlider(~window, 310@20, "high part", \amp, { |ez| ~vbus2.set(ez.value) }, 0.5);
~window.front.onClose_({ ~vbus1.free; ~vbus2.free });
)

(
p = Ppar([
    Pfxb(Pbind(
        \degree, Pseq([0, 7, 4, 3, 9, 5, 1, 4], inf),
        \octave, 4,
        \dur, 0.5
    ), \volumeCtl, \amp, ~vbus1.asMap),    // 在此映射到控制总线
    Pfxb(Pbind(
        \degree, Pwhite(0, 11, inf),
        \dur, 0.25
    ), \volumeCtl, \amp, ~vbus2.asMap)    // ……以及这里
]).play;
)

p.stop;

第三方扩展提醒：Pfx 及其同类基于这样一种理念：信号路由安排应当按需创建（当其子模式正在播放时），并在模式结束时立即移除。另一种方法是将信号路由和效果视为持久性基础设施，由用户控制创建和销毁（而非由模式控制）。JITLib 的 proxy 系统为此提供了一些支持。MixerChannels（在 ddwMixerChannel quark 中）是一种更显式的方式。任何模式都可以在 MixerChannel 上播放：aMixer.play(aPattern)。

Pproto：在模式持续期间分配其他资源

也可以在准备运行 Pbind 风格模式的过程中加载声音文件或波表缓冲区，或播放 synth。当 Pbind 停止时，这些资源会自动从服务器中移除。

实现这一点的机制与 SuperCollider 中使用服务器的大多数其他协议有些不同。为了创建资源，Pproto 接受一个函数，其中包含一个或多个 Event 对象，这些对象包含创建资源的指令。这些事件应使用特定的事件类型，详见 Pproto 的帮助文件。该模式能够清理资源，因为每个事件都有一个关联的清理动作（参见带有 cleanup 类的事件类型）。因此，Pproto 只需记住代表资源的事件，并在最后执行它们的清理动作。

Pproto 帮助文件中有几个值得阅读的复杂示例。这里只是一个简单案例：加载标准的 ExampleFiles.child 声音文件，并播放其中的片段。

(
SynthDef(\playbuf, { |bufnum, start, dur = 1, amp = 0.2, out|
    var    sig = PlayBuf.ar(1, bufnum, BufRateScale.ir(bufnum), 0, start);
    sig = sig * amp * EnvGen.kr(Env.linen(0.01, dur, 0.01), doneAction: Done.freeSelf);
    Out.ar(out, sig ! 2)
}).add;
)

(
TempoClock.default.tempo = 1;
p = Pproto({
    ~buf = (type: \allocRead, path: ExampleFiles.child).yield;
}, Pbind(
    \instrument, \playbuf,
        // 通过 Pkey 访问 protoevent 中的资源
    \bufnum, Pkey(\buf),
    \dur, Pwhite(1, 4, inf) * 0.25,
        // Pwhite 的上限基于 duration
        // 因此 start + (dur * samplerate) 永远不会超出 buffer 的末尾
    \start, Pwhite(0, 188893 - (Pkey(\dur) * 44100), inf)
)).play;
)

// 显示分配的缓冲区编号（'true' 表示 ContiguousBlock）
s.bufferAllocator.debug;

p.stop;

s.bufferAllocator.debug;    // 停止后，缓冲区就没了
