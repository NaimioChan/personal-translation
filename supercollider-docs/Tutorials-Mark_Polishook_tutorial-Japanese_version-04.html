ユニット・ジェネレータのコントロール のレート

你会注意到，一些 SuperCollider 的 ugen 后面跟着 .ar 消息。例如，如下所示

SinOsc.kr

というものもあれば、他のugenは、次の様に.arメッセージを使うということもあります。

SinOsc.ar

音频速率

带有 .ar 消息的 ugen 以音频速率运行。默认情况下，每秒 44,100 个采样。

SinOsc.ar(440, 0, 1);

只要它是可听音频链的一部分，就向单元生成器发送 .ar 消息。

控制率

コントロール・レート

以 .kr 消息结尾的 ugen 以控制速率运行。默认情况下，控制速率的 ugen 每生成 64 个采样（由音频速率的 ugen 生成）才生成一次。

SinOsc.kr(440, 0, 1);

只有当你想把单元生成器用作调制器，即用于塑造或控制音频信号时，才向单元生成器发送 .kr 消息。

与音频速率相比，控制速率信号的计算负载更低。当用于调制音频速率 UGen 的参数时，尽管变化速率不同，听起来仍几乎平滑。

////////////////////////////////////////////////////////////////////////////////////////////////////

这是一个 UGen 以音频速率运行、其他 UGen 以控制速率运行的示例。

(
SynthDef("anExample", {
    Out.ar(
        0,
        SinOsc.ar(
            [440, 443] + SinOsc.kr([7, 8], 0, 7), // コントロール・レートはCPUサイクルをセーブする
            0,
            0.2
        )
    )
}).add;
)

Synth("anExample")

以控制速率运行的此 SinOsc——SinOsc.kr([7, 8], 0, 7)——的实例，会调制以音频速率听到的 SinOsc 的频率。

////////////////////////////////////////////////////////////////////////////////////////////////////

未来，随着计算机速度的不断提升（除非完全废除），区分使用音频速率和控制速率的必要性将会降低。通过以控制速率使用 ugen，在不需要像以音频速率生成数据那样严格的情况下，可以降低处理负载。
