服务器命令参考

SuperCollider 服务器 Synth 引擎命令参考

以下是所有服务器命令及其参数的列表。

每个命令都有一个命令编号，可以以 32 位整数而非 OSC 风格字符串的形式发送到服务器。命令编号列于本文档末尾。

如果命令的描述中包含 Asynchronous 一词，则该命令将被传递到后台线程完成，以免占用音频合成线程的 CPU 时间。所有异步命令在完成时都会向客户端发送回复。许多异步命令可以包含一个在完成时执行的 OSC 消息或 bundle。例如。

    ["/d_load", "synthdefs/void.scsyndef",
        ["/s_new", "void", 1001, 1, 0] // 完成消息
    ]

顶层命令

/notify

int

如果第一个参数为 1，服务器将记住你的返回地址并向你发送通知；如果为 0，服务器将停止发送通知。

Asynchronous.

完成后向发送者回复 /done /notify clientID [maxLogins]。如果此客户端之前已注册过通知，这可能就是同一个 ID。否则将是一个新的 ID。客户端可以在多客户端场景中使用此 ID，以避免在分配节点 ID、总线索引和缓冲区编号等资源时发生冲突。仅当此命令中提供了 client ID 参数时才会返回 maxLogins。supernova 不支持 maxLogins。

/clearSched

/error

启用/禁用错误消息发布。

int

mode

打开或关闭发送到 SuperCollider 后置窗口的错误消息。当发送的消息（例如 /n_free）失败并不一定表示出错时，这很有用。

mode 的取值如下：

0

关闭错误发布，直到下一条 ['/error', 1] 消息。

1

开启错误发布。

为了方便客户端方法，你还可以临时抑制错误，作用范围限于单个 bundle。

-1

在 bundle 中局部关闭——错误发布在下一个消息或 bundle 时会恢复为“永久”设置。

-2

在 bundle 中本地开启。

这些“临时”状态会在单个 bundle 内累积——因此，如果你有嵌套调用的方法使用了 bundle 局部错误抑制，那么错误发布将保持关闭，直到所有层都被解开。如果你在自我打包的方法中使用了 ['/error', -1]，你应该始终用 ['/error', -2] 来关闭它，以便后续打包的消息能够采用正确的错误发布状态。然而，即使没有这样做，下一个接收到的 bundle 或消息也会以标准的错误发布状态开始，该状态由模式 0 或 1 设定。

临时错误抑制可能并非在所有情况下都影响异步命令。

/version

查询 SuperCollider 版本。向发送者回复以下消息：

/version.reply

string

程序名称。可以是 "scsynth" 或 "supernova"。

int

主版本号。等同于 sclang 的 Main.scVersionMajor。

int

次版本号。等同于 sclang 的 Main.scVersionMinor。

string

Patch 版本名称。等同于 sclang 代码 "." ++ Main.scVersionPatch ++ Main.scVersionTweak。

string

Git 分支或标签名。

string

提交哈希的前七个十六进制数字。

标准的可读版本字符串可以通过拼接 major_version ++ "." ++ minor_version ++ patch_version 来构造。由于 sclang 用户可以通过上述方法轻松获取版本信息，因此此命令主要对其他客户端有用。

如果用户 fork 了 SC，git 分支/标签名和提交哈希可以是任何内容，因此它们只应用于显示和用户界面目的。

Synth 命令

/s_new

创建一个新的 synth。

string

synth ID

添加动作（0、1、2、3 或 4，见下文）

int

添加目标 ID

N *

int 或 string

控制索引或名称

float 或 int 或 string

浮点和整数参数被解释为控制值。由字母 'c' 或 'a'（分别代表 control 或 audio）后跟总线索引组成的符号参数。

int 或 string

控制索引或名称

float 或 int 或 string

浮点和整数参数被解释为控制值。由字母 'c' 或 'a'（分别代表 control 或 audio）后跟总线索引组成的符号参数。

根据 synth 定义创建一个新的 synth，为其指定一个 ID，并将其添加到节点树中。根据 add action 参数的不同，有四种将节点添加到树中的方式，其定义如下：

添加动作：

0

将新节点添加到由 add target ID 指定的组的头部。

1

将新节点添加到由 add target ID 指定的组的尾部。

2

将新节点添加到由添加目标 ID 指定的节点之前。

3

将新节点紧接在由 add target ID 指定的节点之后添加。

4

新节点替换由 add 目标 ID 指定的节点。目标节点被释放。

可以在创建 synth 时设置控件。控制参数与 n_set 命令所用的参数相同。

如果发送带有 synth ID 为 -1 的 /s_new，那么服务器将为你生成一个 ID。服务器保留所有负 ID。由于你不知道该 ID 是什么，之后便无法直接与该节点通信。因此，这对于持续时间有限且从参数和总线或发送到其组的消息中获取所需控制信息的节点很有用。此外，当该节点状态发生变化时不会发送通知，例如 /go、/end、/on、/off。

如果你为任何其他命令（例如 /n_map）使用节点 ID -1，则它指的是由 /s_new 最近创建的节点（无论是否为自动生成的 ID）。这就是你映射具有自动生成 ID 的节点控件的方式。在多客户端情况下，要确定 -1 指的是哪个节点，唯一的方法是将这些消息放入一个 bundle 中。

此消息现在支持 OSC 消息的控制/值组件中的数组类型标记（$[ 和 $]）。数组控制值以 n_setn 的方式应用（即，从索引或命名控制开始按顺序应用）。参见 Node Messaging 帮助文件。
