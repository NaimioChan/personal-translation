SynthDesc

synth 定义的描述

Object

参见：SynthDef、Synth

说明

包含对 SynthDef 的描述，包括其名称、控制名称和默认值。还存储关于其输出和输入的信息，以及它是否具有 gate 控制。

事件流系统需要 SynthDesc，因此在使用 Pbind 时，乐器的默认参数派生自 SynthDesc。

Creation

SynthDesc 由 SynthDescLib 通过读取已编译的 synth def 文件创建。

SynthDescLib.global.read("synthdefs/default.scsyndef");
SynthDescLib.global.synthDescs.at(\default)
SynthDescLib.global.at(\default) // 快捷键，与上一行相同

aSynthDef.store 和 aSynthDef.add 也会在全局库中创建一个 synthDesc。

.store

将 synthdef 文件保存到磁盘（类似 .load）；

.add

完全在内存中创建 synthDesc，并将 synthdef 发送到已注册的服务器。

(
SynthDef("test", { |out, freq, xFade|
    XOut.ar(out, xFade, SinOsc.ar(freq))
}).store
);

浏览 SynthDesc 的属性：

SynthDescLib.global.browse;

类方法

SynthDesc.read(path, keepDefs: false, dict)

将某个路径中的所有 synthDescs 添加到字典中。你不应使用此方法或 *readFile 将 SynthDesc 读入 SynthDescLib。请改用 SynthDescLib: read 或 SynthDescLib: readStream。

SynthDesc 与 SynthDef 元数据

与 SynthDef 关联的元数据由一个 Event（一种语法上更简短的身份字典形式）组成，其中包含对客户端有用且无法从二进制 .scsyndef 流中推断出的 SynthDef 信息。

例如，通过在事件的 'specs' 键下列出参数名和 ControlSpec，客户端可以使用这些 spec 构建一个 GUI，从而以合理的范围映射控制 SynthDef 的所有输入。（SynthDescLib 浏览器中的 "window" 按钮正是这样做的——元数据中列出的任何 ControlSpec 都会被用于对应 synth 输入的滑块。）

目前仅保留 'specs' 键。其他键可按特定应用的需要使用。随着 SynthDef 元数据的使用不断发展，其他键可能会被标准化。

创建与访问

元数据在创建 SynthDef 时指定。如果该 SynthDef 被 .store（或 .add）到 SynthDescLib 中，元数据也会成为 SynthDesc 的一部分。此后，可以通过 SynthDescLib 访问元数据：

SynthDescLib.global[\synthDefName].metadata

持久化与元数据插件

使用 .store 将 SynthDef 存入库中会将 SynthDef 持久化到磁盘。通过使用相应的元数据插件类，元数据也可以同时被持久化。该插件负责将一个单独的元数据文件写入 synthdefs 目录，并在使用 SynthDesc.read 或 SynthDescLib.global.read 为 .scsyndef 文件创建 SynthDesc 时同时读回该文件。

当前可用的插件有：

AbstractMDPlugin

一个虚拟插件，不写入任何元数据，这样对元数据不感兴趣的用户就不会在 synthdefs 目录中发现多余的文件。

TextArchiveMDPlugin

将元数据写为 SuperCollider 文本归档——metadata.writeArchive(path)。这是默认值。仅当 SynthDef 包含元数据时才写入元数据。

其他插件可在以后编写，以支持使用 JSON（JavaScript Object Notation）或 XML 等格式与其他语言中的应用程序共享元数据。

你可以如下方式指定一个全局默认元数据插件：

SynthDesc.mdPlugin = ... plug-in class name ...;

使用 SynthDef().load(server) 时不会写入元数据。这是因为 SynthDesc 的存在是为了向客户端描述 SynthDef，而 SynthDef 实际上只是为服务器创建 UGen 图的一种抽象。使用 SynthDef().add 时也不会写入元数据，因为在正常情况下，不会持久化任何内容到磁盘。（如果 SynthDef 非常大且需要磁盘文件，那么元数据将随 .scsyndef 文件一起持久化。）

自动填充

你可以编写一个函数，根据 SynthDesc 对象自动填充元数据条目。该函数在从磁盘读取 SynthDesc 时、使用 .add 时以及写入元数据文件之前（在 .store 中）执行。

SynthDesc.populateMetadataFunc = { |synthdesc|
    ... do work here ...
};

Synchronization

每当写入 .scsyndef 文件时，任何现有的元数据文件都会被删除，以免新的 .scsyndef 文件在磁盘上存在时带有过期的元数据。

Reading

读取 SynthDesc 时，将检查元数据文件并读取其中一个，无论其格式如何。（即使默认的 SynthDesc.mdPlugin 与磁盘上的文件格式不同，磁盘文件仍会使用相应的插件来读取。）

同一时间应只有一个元数据文件。然而，在发生冲突的情况下，默认的 SynthDesc.mdPlugin 将被优先使用。文件扩展名标识其格式。

元数据示例

s.boot;

d = SynthDef(\mdDemo, { |out, freq, cutoff, volume, gate = 1|
    var    sig = LPF.ar(Saw.ar(freq, volume), cutoff),
        env = EnvGen.kr(Env.adsr, gate, doneAction: Done.freeSelf);
    Out.ar(out, (sig * env) ! 2)
}).add;

SynthDescLib.global[\mdDemo].makeWindow;

// 在生成的窗口中注意，Freq 有滑块，但 Cutoff 和 Volume 没有。
// 这是因为参数名 'cutoff' 和 'volume' 没有全局规格。


// 相同的 SynthDef，但添加了元数据
// \freq 和 \amp 存在于全局 ControlSpec 集合中 -- Spec.specs
// 它们通过 .asSpec 被转换为真正的 ControlSpec

d = SynthDef(\mdDemo, { |out, freq, cutoff, volume, gate = 1|
    var    sig = LPF.ar(Saw.ar(freq, volume), cutoff),
        env = EnvGen.kr(Env.adsr, gate, doneAction: Done.freeSelf);
    Out.ar(out, (sig * env) ! 2)
}, metadata: (specs: (cutoff: \freq, volume: \amp))).add;

SynthDescLib.global[\mdDemo].makeWindow;

// 现在 cutoff 有一个用于频率的滑块，volume 有振幅缩放


// 将 SynthDef 连同元数据一起存储
d.store(mdPlugin: TextArchiveMDPlugin);

"ls %mdDemo.*".format(SynthDef.synthDefDir.escapeChar($ )).unixCmd;

// 除了 .scsyndef，还有 .txarcmeta —— "text archive metadata"

// 从磁盘为其加载一个全新的 SynthDesc
// SynthDesc.read 接口有点奇怪——e 将是一个保存 SynthDesc 的字典
e = SynthDesc.read(SynthDef.synthDefDir ++ "mdDemo.scsyndef");

// 已成功从磁盘读取元数据！
// 你甚至可以在重新编译后执行上述操作，而 MD 仍会存在
e[\mdDemo].metadata

e[\mdDemo].makeWindow;
