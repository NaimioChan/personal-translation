11. 总线

SuperCollider 入门

另请参阅：00. Getting Started With SC

现在再稍微多谈一些服务器上的总线。总线的命名源自模拟调音台上的总线或发送，用途类似：将信号从一个地方路由到另一个地方。在 SC 中，这意味着将信号发送到音频硬件或从音频硬件接收，或在不同的 synth 之间传输。总线有两种类型：音频速率和控制速率。你可能已经猜到，前者路由音频速率信号，后者路由控制速率信号。

控制速率总线相当容易理解。每个总线都有一个索引号，从 0 开始。

音频速率总线类似，但需要稍微多一些解释。服务器应用会有一定数量的输出和输入通道。它们对应前几个音频总线，输出位于输入之前。

例如，如果我们设想一个具有两个输出通道和两个输入通道的服务器（即立体声输入和输出），那么前两个音频总线（索引 0 和索引 1）将是输出，紧随其后的两个（索引 2 和索引 3）将是输入。将音频写入其中一个输出总线会使声音从你的扬声器播放出来，而从输入总线读取音频则会将声音输入 SC，用于录音和处理等用途（前提是你有麦克风之类的音源连接到计算机或音频接口的输入端）。

剩余的音频总线将是“私有”的。它们仅用于在各种 synth 之间发送音频和控制信号。将音频发送到私有总线不会从你的扬声器发出声音，除非你之后将其重新路由到某个输出总线。这些“私有”总线常用于“效果发送”之类的事情，即需要在到达扬声器之前进行进一步处理的内容。

可用的控制总线和音频总线的数量，以及输入和输出通道的数量，都在服务器应用启动时设定。（有关如何设置输入和输出通道数以及总线数的信息，请参见 ServerOptions。）

写入总线或从总线读取

我们已经见过 Out.ar，它允许你将音频写入（即播放输出到）总线。回想一下它有两个参数——一个索引和一个输出——输出可以是 UGen 的数组（即多通道输出）或单个 UGen。

要从总线读取信号，你需要使用另一个 UGen：In。In 的 'ar' 方法同样接受两个参数：一个索引，以及要读取的通道数。如果通道数大于一，那么 In 的输出将是一个数组。请执行以下示例，并观察 post 窗口：

In.ar(0, 1); // 这将返回 'an OutputProxy'
In.ar(0, 4); // 这将返回一个包含 4 个 OutputProxy 的数组

OutputProxy 是一种特殊的 UGen，它充当某个信号的占位符，该信号将在 synth 运行时存在。你很可能永远不需要直接处理它，所以不必担心。只需了解它们是什么，以便在 post 窗口和其他地方看到它们时能够识别。

In 和 Out 也有 'kr' 方法，它们会从控制速率总线读取控制速率信号并向其写入。请注意，Out.kr 会将音频速率信号转换为控制速率（这称为“降采样”），但反之不成立：Out.ar 需要音频速率信号作为其第二个参数。

// 这会抛出一个错误。不能把控制速率信号写入音频速率总线
{ |out| Out.ar(out, SinOsc.kr) }.play;

// 这将正常工作，因为音频速率信号被降采样到控制速率
{ |out| Out.kr(out, SinOsc.ar) }.scope;

（不过，这一限制并非所有音频速率 UGen 都适用，大多数 UGen 会为部分或全部参数接受控制速率信号。一些 UGen 甚至会在需要时把控制速率输入转换为音频速率，通过一种称为插值的过程填充额外的值。）

你会注意到，当多个 Synth 写入同一总线时，它们的输出会被求和（即混合）。

(
SynthDef("tutorial-args", { arg freq = 440, out = 0;
    Out.ar(out, SinOsc.ar(freq, 0, 0.2));
}).add;
)
// 两者都写入总线 1，它们的输出会被混合
x = Synth("tutorial-args", ["out", 1, "freq", 660]);
y = Synth("tutorial-args", ["out", 1, "freq", 770]);

创建 Bus 对象

有一个方便的客户端对象可以表示服务器总线：Bus。既然你所需要的只是一个 In 或 Out UGen 和一个用于写入总线的索引，你可能会想，为什么需要一个功能完备的 Bus 对象呢。嗯，大多数时候你并不需要，特别是如果你只是在进行音频的输入和输出。但 Bus 确实提供了一些有用的功能。我们稍后会讲到这些，但首先让我们看看如何创建一个 Bus。

正如许多 UGen 具有 ar 和 kr 方法一样，Bus 有两个常用的创建方法：Bus-audio 和 Bus-control。它们各接受两个参数：一个 Server 对象和通道数。

b = Bus.control(s, 2); // 获取一个双声道控制总线
c = Bus.audio(s);     // 获取一个单声道私有音频总线（默认为一个）

你可能会疑惑什么是“双声道”总线，因为我们之前没有提到过这些。你应当回想一下，当 Out 的第二个参数是一个数组时，它会将该数组的各声道写入连续的总线。回想一下 10. SynthDefs and Synths 中的这个例子：

(
SynthDef.new("tutorial-SinOsc-stereo", { |out|
    var outArray;
    outArray = [SinOsc.ar(440, 0, 0.2), SinOsc.ar(442, 0, 0.2)];
    Out.ar(out, outArray); // 写入总线 0 和 1
}).play;
)

实际情况是并不存在真正意义上的多通道总线，但 Bus 对象能够表示一串索引连续的总线。它们把服务器端的若干相邻总线封装进单个 Bus 对象，让你可以把它们当作一个组来处理。这用起来相当方便。

当使用所谓的“私有”总线时（即除输入和输出通道之外的任何总线；所有控制总线都是“私有”的），你通常希望确保该总线只用于你确切需要的事情。毕竟重点在于保持事物相互分离。你可以通过仔细考虑使用哪些索引来做到这一点，但 Bus 允许自动完成这件事。每个 Server 对象都有一个总线分配器，当你创建 Bus 对象时，它会保留那些私有索引，并且在释放之前不会再次分配它们。你可以使用 Bus 的 'index' 方法查出其索引。不过通常你无需存储这个值，因为 Bus 的实例可以直接作为 UGen 输入或 Synth 参数传入。

s.reboot; // 这会重启服务器，从而重置总线分配器

b = Bus.control(s, 2);    // 一个 2 声道控制总线
b.index;         // 这应该为零
b.numChannels         // Bus 也有一个 numChannels 方法
c = Bus.control(s);
c.numChannels;        // 默认通道数为 1
c.index;        // 注意这是 2；b 使用 0 和 1

因此，通过使用 Bus 对象来表示相邻的总线，你可以保证不会发生冲突。由于索引是动态分配的，你可以在代码中更改 Bus 的通道数（例如因为你现在需要路由一个多通道信号），并且仍然保证安全。如果你只是通过使用索引编号来“硬分配”总线，你可能不得不调整所有索引以便为额外的相邻通道腾出空间，因为索引必须是连续的！这是对象能力的一个很好的例子：通过封装索引分配之类的内容，并提供一层抽象，它们可以让你的代码更加灵活。

可以通过调用 Bus 的 'free' 方法来释放它使用的索引。这会允许这些索引被重新分配。

b = Bus.control(s, 2);
b.free; // 释放索引。之后你不能再使用这个 Bus 对象

请注意，这实际上并不会使服务器上的总线消失，它仍然存在。'free' 只是让分配器知道你暂时不再使用这条总线，它可以自由地重新分配其索引。

下面是在使用私有音频速率总线时的另一个优势。如上所述，前几个总线是输出和输入通道。因此，如果我们想使用第一个私有总线，只需将它们相加即可，对吧？考虑我们的服务器应用程序具有 2 个输出和 2 个输入通道的情况。第一个私有音频总线的索引是 4。（0、1、2、3……4！）因此我们编写代码，并将相应的 Out UGen 的索引参数设为 4。

但是，如果我们后来决定将输出通道数改为 6，会发生什么？现在，之前写入我们私有总线的所有内容都会从某个输出通道输出！服务器的音频总线分配器只会分配私有索引，因此当你更改输入或输出通道数时，在你执行代码时它会将这一点考虑在内。这同样让你的代码更加灵活。

总线实战

因此这里有两个使用总线的示例。第一个使用控制速率总线。

(
SynthDef("tutorial-Infreq", { arg bus, freqOffset = 0, out;
    // 这会把 freqOffset 加到从 bus 中读到的任何值上
    Out.ar(out, SinOsc.ar(In.kr(bus) + freqOffset, 0, 0.5));
}).add;

SynthDef("tutorial-Outfreq", { arg freq = 400, bus;
    Out.kr(bus, SinOsc.kr(1, 0, freq/40, freq));
}).add;

b = Bus.control(s,1);
)

(
x = Synth.new("tutorial-Outfreq", [\bus, b]);
y = Synth.after(x, "tutorial-Infreq", [\bus, b]);
z = Synth.after(x, "tutorial-Infreq", [\bus, b, \freqOffset, 200]);
)
x.free; y.free; z.free; b.free;

y 和 z 都从同一个总线读取。后者只是通过给频率控制信号加上一个常量值 200 来修改它。这比使用两个单独的控制振荡器来控制频率更高效。这种将各个 synth 连接在一起、每个 synth 在更大过程中执行不同任务的策略，在 SC 中非常有效。

现在来看一个使用音频总线的示例。这是我们目前见过的最复杂的示例，但应该能让你了解如何开始将我们学到的所有内容组合起来。下面的代码将使用两个 Synth 作为源，一个产生 PinkNoise 的脉冲（一种在高频处能量低于低频处的 Noise），另一个产生正弦波的脉冲。这些脉冲使用 UGen Impulse 和 Decay2 创建。然后通过一串 AllpassC（一种延迟）对它们进行混响处理。

注意下面的构造 16.do({ ... })。它通过将函数求值 16 次来构建链条。这是一种非常强大且灵活的技术，因为只需改变数字，我就能改变求值的次数。有关 Integer-do 的更多信息，请参见 Integer。

(
// arg direct 将控制直接信号与处理信号的比例
SynthDef("tutorial-DecayPink", { arg outBus = 0, effectBus, direct = 0.5;
    var source;
    // 衰减的 PinkNoise 脉冲。稍后我们会添加混响。
    source = Decay2.ar(Impulse.ar(1, 0.25), 0.01, 0.2, PinkNoise.ar);
    // 这将是我们的主输出
    Out.ar(outBus, source * direct);
    // 这将是我们的效果输出
    Out.ar(effectBus, source * (1 - direct));
}).add;

SynthDef("tutorial-DecaySin", { arg outBus = 0, effectBus, direct = 0.5;
    var source;
    // 调制正弦波的衰减脉冲。我们稍后会添加混响。
    source = Decay2.ar(Impulse.ar(0.3, 0.25), 0.3, 1, SinOsc.ar(SinOsc.kr(0.2, 0, 110, 440)));
    // 这将是我们的主输出
    Out.ar(outBus, source * direct);
    // 这将是我们的效果输出
    Out.ar(effectBus, source * (1 - direct));
}).add;

SynthDef("tutorial-Reverb", { arg outBus = 0, inBus;
    var input;
    input = In.ar(inBus, 1);

    // 一个低成本的混响
    // aNumber.do 会将其函数参数求值相应次数
    // {}.dup(n) 会将函数求值 n 次，并返回结果的 Array
    // n 的默认值为 2，因此这会产生立体声混响
    16.do({ input = AllpassC.ar(input, 0.04, { Rand(0.001,0.04) }.dup, 3)});

    Out.ar(outBus, input);
}).add;

b = Bus.audio(s,1); // 这将是我们的效果总线
)

(
x = Synth.new("tutorial-Reverb", [\inBus, b]);
y = Synth.before(x, "tutorial-DecayPink", [\effectBus, b]);
z = Synth.before(x, "tutorial-DecaySin", [\effectBus, b, \outBus, 1]);
)

// 改变干湿平衡
y.set(\direct, 1); // 仅直接 PinkNoise
z.set(\direct, 1); // 仅直接正弦波
y.set(\direct, 0); // 只有经过混响的 PinkNoise
z.set(\direct, 0); // 只有经过混响的 Sine 波
x.free; y.free; z.free; b.free;

请注意，我们可以轻松地让更多的源 synth 由单个混响 synth 处理。如果把混响内建到源 synth 中，我们就会重复劳动。但通过使用私有总线，我们能够更高效。

控制总线的更多乐趣

控制速率总线还有一些其他强大的用途。例如，您可以将运行中的 synth 的任意参数映射为从控制总线读取。这意味着您不再需要 In UGen。您还可以用 Bus 的 'set' 方法向控制总线写入常量值，并用其 'get' 方法轮询取值。

(
// 创建两个控制速率总线并将其值设置为 880 和 884。
b = Bus.control(s, 1); b.set(880);
c = Bus.control(s, 1); c.set(884);
// 并创建一个带两个频率参数的 synth
x = SynthDef("tutorial-map", { arg freq1 = 440, freq2 = 440, out;
    Out.ar(out, SinOsc.ar([freq1, freq2], 0, 0.1));
}).play(s);
)
// 现在将 freq1 和 freq2 映射为从两个总线读取
x.map(\freq1, b, \freq2, c);

// 现在创建一个 Synth 写入其中一个总线
y = {Out.kr(b, SinOsc.kr(1, 0, 50, 880))}.play(addAction: \addToHead);

// 释放 y，而 b 保留其最后一个值
y.free;

// 使用 Bus-get 查看该值是什么。观察 post 窗口
b.get({ arg val; val.postln; f = val; });

// 设置 freq2，这会将其从 c 中“取消映射”
x.set(\freq2, f / 2);

// freq2 不再被映射，因此将 c 设为不同的值没有效果
c.set(200);

x.free; b.free; c.free;

请注意，与音频速率总线不同，控制速率总线会保持其最后一个值，直到写入新值。

还要注意，Bus-get 接受一个 Function（称为 action function）作为参数。这是因为服务器获取回复并将其发送回来需要少量时间。该函数以值（对于多声道总线而言，则是值的数组）作为参数传入，让你在值返回后可以对其进行处理。

事物需要少量时间来响应（通常称为延迟）这一概念对理解来说相当重要。SC 中还有许多其他方法也以这种方式运作，如果不小心可能会给你带来问题。为了说明这一点，请考虑下面的例子。

// 创建一个 Bus 对象并设置其值
b = Bus.control(s, 1); b.set(880);

// 整体执行这段代码
(
f = nil; // 只是为了确保
b.get({ arg val; f = val; });
f.postln;
)

// f 等于 nil，但再试一次就和我们预期的一样了！
f.postln;

那么为什么第一次 f 是 nil，而第二次却不是呢？语言应用程序中执行你代码的部分（称为解释器）会在你要求时以尽可能快的速度执行你告诉它的操作。因此，在上面括号之间的代码块中，它向服务器发送 'get' 消息，安排 Function 在收到回复时执行，然后继续打印 f。由于它尚未收到回复，所以第一次打印时 f 仍然是 nil。

服务器发送回复只需极短的时间，因此当我们执行到最后一行代码时，f 已如预期被设为 880。在前一个例子中这不成问题，因为我们一次只执行一行。但有些情况下你需要把若干操作作为一个块来执行，这时动作函数技巧就非常有用。

让一切按正确顺序进行

在上面的示例中，你可能对 Synth.after、addAction: \addToHead 之类的内容感到疑惑。在每个周期（即计算一个采样块的时段）中，服务器会按照其运行中 synth 的列表顺序，以特定的顺序进行计算。

它从其列表中的第一个 synth 开始，为其第一个 UGen 计算一个块的采样。然后它以此为基础，依次为其余每个 UGen 计算一个块的采样（其中任何一个 UGen 都可能将较早的 UGen 的输出作为输入）。视情况而定，该 synth 的输出被写入一个总线或多个总线。然后服务器继续处理其列表中的下一个 synth，重复该过程，直到所有正在运行的 synth 都计算完一个块的采样。此时，服务器可以进入下一个周期。

需要理解的关键点是，作为一般规则，当你使用总线将各个 Synth 连接在一起时，重要的是向总线写入信号的 Synth 在服务器顺序中要早于从这些总线读取信号的 Synth。例如，在上面的音频总线示例中，'reverb' Synth 必须在其处理的噪声和正弦波 Synth 之后计算。

这是一个复杂的话题，并且存在一些例外，但你应该意识到，在连接 synth 时，顺序至关重要。文件 Order of execution 更详细地介绍了这一主题。

Synth-new 有两个参数，允许你指定 synth 添加在顺序中的哪个位置。第一个是 target，第二个是 addAction。后者指定新 synth 相对于 target 的位置。

x = Synth("default", [\freq, 300]);
// 在 x 之后立即添加第二个合成器
y = Synth("default", [\freq, 450], x, \addAfter);
x.free; y.free;

目标可以是另一个 Synth（或其他一些对象；稍后会详细介绍），而 addAction 是一个符号。有关可能的 addAction 的完整列表，请参见 Synth。

像 Synth-after 这样的方法只是做同样事情的便捷方式，区别在于它们将目标作为第一个参数。

// 这两行代码是等价的
y = Synth.new("default", [\freq, 450], x, \addAfter);
y = Synth.after(x, "default", [\freq, 450]);

更多信息请参见：

Bus、In、OutputProxy、执行顺序、Synth

建议练习

尝试使用音频总线和控制总线将不同的 Synth 相互连接。这样做时，请注意它们在服务器上的顺序。
