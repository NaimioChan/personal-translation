Introduction

SuperCollider 3 Synth Server 是一个简单但强大的合成引擎。合成运行时，可以创建、销毁新模块并重新连接它们，可以创建和重新分配采样缓冲区。效果处理过程可以被创建并在预定时间动态接入信号流中。所有运行中的模块都按照定义执行顺序的节点树进行排序。模块之间的连接通过全局音频总线和控制总线完成。

所有命令都通过 TCP 或 UDP 接收，使用简化版的 Open Sound Control（OSC）。Synth 服务器及其客户端可以位于同一台机器上，也可以跨网络。Synth 服务器不发送或接收 MIDI。预期由客户端发送所有控制命令。如果需要 MIDI，则由客户端负责接收它并将其转换为适合 Synth 引擎的 OSC 命令。

Synth 定义存储在由 SuperCollider 语言应用程序生成的文件中。Unit generator 定义是 Mach-O 捆绑包（不要与 CFBundle 混淆）。Unit generator API 是一个简单的 C 接口。

主要设计概念

Node

Node 是由 synth 引擎运行的节点树中可寻址的节点。它有两种类型：Synth 和 Group。树定义了所有 Synth 的执行顺序。所有节点都有一个整数 ID。

Group

组是由节点组成的集合，以链表形式表示。新节点可以添加到组的头部或尾部。组内的节点可以一起控制。组内的节点既可以是 Synth，也可以是其他组。启动时存在一个 ID 为 0 的顶层组，它定义了树的根。如果服务器是从 SCLang 内部启动的（而非从命令行启动），则还会存在一个 ID 为 1 的“默认组”，它是所有新节点的默认目标。更多信息请参见 RootNode 和 Default Group。

Synth

Synth 是一组一起运行的 unit generator 的集合。可以通过向合成引擎发送命令来寻址和控制它们。它们读取输入，并将输出写入全局音频总线和控制总线。Synth 可以拥有自己的本地控制，通过向服务器发送命令来设置。

Synth 定义

Synth 由 Synth Definition 创建。Synth Definition 文件由 SuperCollider 语言应用程序创建，并被加载到 synth 服务器中。Synth Definition 通过名称来引用。

音频总线

Synth 通过一个单一的全局音频总线数组相互发送音频信号。音频总线由从零开始的整数索引。使用总线而不是将 synth 直接相互连接，允许 synth 将自身连接到其他 synth 的共同体中，而无需具体了解它们。编号最低的总线被写入音频硬件输出。紧跟在输出总线之后的是输入总线，从音频硬件输入读取。定义为输入和输出的总线通道数量不必与硬件匹配。

控制总线

Synth 可以通过一个单一的控制总线全局数组相互发送控制信号。总线使用从零开始的整数进行索引。

Buffers

缓冲区是 32 位浮点值的数组，附带一个小的描述性头部。缓冲区存储在一个全局数组中，由从零开始的整数索引。在合成运行期间，缓冲区可以被安全地分配、加载和释放，即使 unit generator 正在使用它们。缓冲区用于波表、采样缓冲区、延迟线、包络，或任何其他可以使用浮点值数组的需求。声音文件可以被加载到缓冲区中或从缓冲区写出。

单元生成器定义

Unit Generator Definitions 是程序启动时自动加载的插件。它们是二进制代码库，被 Synths 用作构建块来构建合成算法。Unit Generator Definitions 的名称与构建 Synth Definitions 时使用的 SuperCollider 语言类的名称相匹配。

命令行参数

必须提供 -u 或 -t 之一。两者均可提供。

-u udp-port-number

端口号 0-65535。

-t tcp-port-number

端口号 0-65535

-v 详细程度

控制服务器消息的详细程度。值为 0 是正常行为。-1 抑制信息性消息。-2 抑制信息性消息和许多错误消息，以及来自 Poll 的消息。默认值为 0。

-a num-audio-bus-channels

音频总线通道数（默认 = 1024）。为音频总线分配的空间为：(numchannels * (blocksize + 1) * 4)

-i num-input-bus-channels

音频输入总线通道数（默认 = 8）

-o num-output-bus-channels

音频输出总线通道数（默认 = 8）

-c num-control-bus-channels

控制总线通道数（默认 = 16384）。为控制总线分配的空间为：(numchannels * 8)

-b num-buffers

采样缓冲区数量（默认 = 1024）

-n 最大节点数

最大节点数（默认 = 1024）

-d max-synth-defs

合成器定义的最大数量（默认 = 1024）

-D 1 或 0

如果为零，则合成器定义在启动时不会被加载。（默认值 = 1）

-z block-size

一个控制周期内的采样数。（默认值 = 64）

-Z preferred-hardware-buffer-size

如果非零，它将尝试设置硬件缓冲区帧大小。（默认值 = 0）

-S 首选采样率

若非零，将尝试设置硬件采样率。（默认值 = 0）

-m 实时内存大小

实时内存的千字节数。此内存用于分配 Synth 以及 unit generator 自身分配的任何内存。（默认值 = 8192）

-r random-number-generators

可设置种子的随机数生成器的数量。（默认 = 64）

-w max-interconnect-buffers

为用于互连单元发生器的缓冲区分配的最大缓冲区数量。它设定了可在运行时加载的 synth def 的复杂度上限。如果在启动时加载了更复杂的 synth-def，此值将增加，但一旦合成开始便无法再增加。（默认值 = 64）

-l max-logins

存储的命名返回地址的最大数量（默认 = 64）。也是接受的 TCP 连接的最大数量

-p session-password

使用 TCP 时，会话密码必须是发送的第一条命令。默认没有密码。UDP 端口从不要求密码，因此如果需要密码保护，请使用 TCP。

-H device-name-H input-device-name output-device-name

硬件 I/O 设备的名称。如果未提供，则使用默认设备。更多详情请参阅音频设备选择。

注意： 要仅指定输入设备并使用默认输出设备，或仅指定输出设备并使用默认输入设备，请使用空字符串：'-H "" output-device-name' 或 '-H input-device-name ""'

-I input-streams-enable-string

允许关闭设备上你不感兴趣的输入流。例如，如果字符串为 01100，则仅启用设备上的第二个和第三个输入流。关闭流可以减少 CPU 负载。

-O output-streams-enable-string

允许关闭设备上你不感兴趣的输出流。例如，如果字符串为 11000，则设备上只有前两个输出流会被启用。关闭流可以减少 CPU 负载。

-N cmd-filename input-filename output-filename sample-rate header-format sample-format

以非实时模式运行。

cmd-filename 应是一个文件，其中包含按时间升序排列的 OSC 包。如果 cmd-filename 为下划线字符 _，则 OSC 将从标准输入流式读取。

音频输入将取自 input-filename。如果 input-filename 是下划线字符 _，则不会读取任何输入文件。

输出将被写入 output-filename。

输出文件的采样率由 sample-rate 指定。输出文件的 header-format 应为以下之一：AIFF、WAVE、NeXT。输出文件的 sample-format 应为以下之一：int16、int24、int32、float、double。输出文件中的通道数由 -o 参数指定。

Example

scsynth -u 57117 >synth_log &

    Accept commands via UDP on port 57117.
    Send output to file "synth_log"
    Run asynchronously: &.

scsynth -N score.osc _ out.aiff 48000 AIFF int24

    Run in non real time mode with command file score.osc,
    no input file, and output file named out.aiff.
    Sample rate is 48000. Output file header format is aiff,
    sample format is 24 bit integer.

消息的二进制格式

消息的格式与 Open Sound Control 消息类似，区别在于不对命令名进行模式匹配。当通过 TCP 流式传输时，每条消息前都有一个 32 位整数，给出该消息的字节长度。UDP 数据报已经包含此长度信息。

Types

所有值均采用网络字节序。

long

一个 64 位整数。仅用于时间戳。

int

一个 32 位整数。

float

一个 32 位单精度浮点数。

double

一个 64 位双精度浮点数。

string

一个 OSC 格式字符串：8 位 ASCII 字符，零填充至 4 字节的倍数。

bytes

一个数据缓冲区，前面有一个 32 位长度字段，并填充到 4 字节的倍数。

Tags

命令参数具有单字符标签，这些标签出现在标签字符串中以标识其类型。

'i'

一个 int

'f'

一个 float

's'

一个字符串

'b'

bytes

'd'

一个 double

't'

一个时间戳

Command

一个 Command 由以下部分组成：

string

命令名称。参见下面的命令参考。

string

一个字符串，其中的标签由后续参数的类型定义。标签字符串以逗号 ',' 字符开头。

...

类型为 int、float、string 或 bytes 的参数的任意组合。

Bundle

一个 Bundle 由以下部分组成：

时间戳

long。时间戳采用 Open Sound Control 定义的相同格式：高 32 位表示自 1900 年起的秒数，低 32 位表示一秒的 32 位小数部分。

...

一系列 Command，每个前面都有一个 32 位整数表示的字节长度。

Message

一个 Message 由以下部分组成：

使用 UDP
  • 一个 Bundle 或一个 Command。
使用 TCP
  • int32 - 后续消息的字节长度。
  • 一个 Bundle 或一个 Command。

Glossary

buffer

一个头部和浮点采样数据数组。缓冲区用于声音文件、延迟线、全局控制数组以及合成器间补丁点数组。

group

一个节点的链表。组提供了同时控制许多节点执行的方式。组是一种节点。

MIDI

一种在合成器之间发送音乐控制数据的协议。

node

对象树中的一个对象，由 synth 引擎按深度优先遍历顺序执行。节点有两种类型：synth 和组。

Open Sound Control

由 UCBerkeley 的 CNMAT 定义的一种用于控制合成器的协议。参见 http://cnmat.cnmat.berkeley.edu/OSC/ 。

OSC

参见 Open Sound Control。

synth

一个声音处理模块。类似于其他系统中的“voice”。Synth 通过编号来引用。

synth 定义

用于创建新 synth 的定义。类似于其他系统中的“instrument”。

TCP

一种用于通过网络流式传输数据的协议。

UDP

一种用于在网络上发送数据报的协议。
