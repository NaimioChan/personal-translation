gui

gui 消息在 SC 中很常用。它起源于 crucial 库，在那里它被用作模型-视图-控制器系统的一部分，以创建 ObjectGui 或 ObjectGui 子类。

.gui 的实现和接受的参数各不相同。本帮助文件解释了 Object 的默认行为，因而也解释了所有未实现自己的 .gui 方法的 Object 子类的默认行为。本帮助文件和实现均来自最初的 crucial 库。

任何对象都可以创建 GUI，尽管这是一个非常简单的 GUI，只是在一个视图上显示该对象的字符串表示：

nil.gui;
"2".gui;
2.gui;
[1,nil,"tree"].gui;

这意味着任何对象都可以被 .gui(ed)，而无需确切知道该对象是什么。其目的与 .asString 完全相同，后者用于将对象的表示形式发布到 post 窗口。

参数约定

crucial 库中所述的约定是，.gui 方法应像 View 一样接受 parent 和 bounds 作为其参数。

thing.gui(parent,bounds);
// 或使用可选的附加参数：
things.gui(parent,bounds,arg1,arg2,...argN)

许多编写自己的 .gui 方法的人并没有遵循这一约定（也许他们称之为 .gui 而不是 .makeView 或 .makeWindow，是因为他们喜欢 .gui 简短易输入）

这是 Object 的默认实现，因此也是所有未编写显式 .gui 方法的子类的实现

parent
  • 一个 Window，
  • 一个 FlowView
  • CompositeVIew
  • HLayoutView
  • VLayoutView
  • nil（将创建一个带有 FlowView 的 Window）
bounds
  • 任何响应 asRect: 的对象：
  • Nil - gui 将使用其自身的默认尺寸
  • Point - width @ height

通常不指定边界（bounds）。对象的 gui 类首先添加一个容器，将其内容布局在该容器内，然后收缩容器以适应内容。如果确实指定了边界，容器将被设置为该精确大小。

将视图添加到父视图（窗口）

(
    f = FlowView.new;
    nil.gui(f);
    "2".gui(f);
    2.gui(f);
)

guiClass

每个类都可以指定一个关联的 guiClass，它是 ObjectGui 的子类。编写有用的子类是 ObjectGui 系统的目的所在，在 crucial 库中可以找到许多这样的子类。

指定 guiClass 的示例：

    Object-guiClass {  ^ObjectGui }
    Server-guiClass {  ^ServerGui }
    AbstractPlayer-guiClass { ^AbstractPlayerGui }
    Patch-guiClass { ^PatchGui }

对于任何合适的类，都会实现一个单独的 gui 类，通常从其父类的 gui 类继承大部分行为。

参见 ObjectGui
