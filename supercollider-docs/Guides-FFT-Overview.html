FFT 概述

快速傅里叶变换（FFT）UGen 概述

另请参阅：FFT、IFFT

FFT 与 IFFT

SuperCollider 实现了若干支持基于快速傅里叶变换（FFT）处理的 UGen。其中最基本的是 FFT 和 IFFT（逆 FFT），它们在时域和频域之间转换数据：

chain = FFT(buffer, input)
output = IFFT(chain)

FFT 需要一个 Buffer 或 LocalBuf。缓冲区的大小必须对应 2 的幂，并且还必须是服务器当前块大小的倍数。窗口大小等同于缓冲区大小，窗口重叠默认为 2（hop = 0.5）。FFT 和 IFFT 默认都使用正弦窗口。它们的组合有效地成为汉宁窗（即升正弦，也就是正弦的平方）。

FFT UGen 如何通信

FFT 以以下格式将频谱数据存储在缓冲区中：

DC

nyquist

real 1f

imag 1f

real 2f

imag 2f

...

实部 (N-1)f

虚部 (N-1)f

其中 f 是对应于窗口大小的频率，N 是窗口大小 / 2。

FFT UGen 返回的信号（通常称为 chain）恒为 -1，仅当新的 FFT 窗口开始时，该信号才等于缓冲区编号。后续的 FFT UGen 正是通过这种方式写入该缓冲区，并知道何时进行写入。FFT 信息并不在 chain 信号中，而是在缓冲区中。

// FFT 返回信号为 -1，并且对于每个起始窗口，
// 它是 FFT 缓冲区编号

b = Buffer.alloc(s, 512); // 分配 FFT 缓冲区
b.bufnum; // 注意缓冲区编号

(
var dt = s.options.blockSize / s.sampleRate * 16; // 绘制 16 个块
var min = -2, max = b.bufnum + 4;
// 输入是 SoundIn，但我们看不到这个信号
{ FFT(b, SoundIn.ar) }.plot(dt, minval:min, maxval:max).plotMode_(\steps);
)

b.free; // 再次释放缓冲区

相位声码器 UGen 与频谱处理

在 FFT 与 IFFT 之间，可以将多个 Phase Vocoder UGen（即 PV_...）串联起来，以便在重新转换之前对频谱数据块进行操作。缓冲适量音频、加窗、转换、重叠相加等过程都会自动处理。

有关 UGen 的列表，参见 标准库中的 PV 和 FFT UGen。

(
{
  var in, chain;
    in = WhiteNoise.ar(0.8);
    chain = FFT(LocalBuf(2048), in); // 编码到频域
    chain = PV_RandComb(chain, 0.95, Impulse.kr(0.4)); // process
    IFFT(chain) // 解码到时域
}.play;
)

为了对多声道输入信号展开 PV UGen，必须提供合适的缓冲区数组（而不是多声道缓冲区）：

(
{
  var in, chain;
    in = Ringz.ar(Impulse.ar([2, 3]), [700, 800], 0.1) * 5; // 立体声输入
    chain = FFT({ LocalBuf(2048) } ! 2, in); // 两个本地缓冲区的数组
    chain = PV_RandComb(chain, 0.95, Impulse.kr(0.4));
    IFFT(chain) // 返回立体声输出
}.play;
)

更多示例，请参见 Multichannel Expansion with FFT UGens

并行 FFT 链

PV UGen 将其输出数据原地写入，即写回它们读取的同一缓冲区。需要两个缓冲区的 PV UGen 将其数据写入第一个缓冲区，通常称为 'bufferA'。

(
{
  var inA, chainA, inB, chainB, chain;
    inA = LFSaw.ar(MouseY.kr(100, 1000, 1), 0, 0.2);
    inB = Ringz.ar(Impulse.ar(MouseX.kr(1, 100, 1)), 700, 0.5);
    // 创建两条并行链
    chainA = FFT(LocalBuf(2048), inA);
    chainB = FFT(LocalBuf(2048), inB);
    chain = PV_MagMul(chainA, chainB); // 写入 bufferA
    IFFT(chain) * 0.1
}.play;
)

d.free;

一个使用声音文件的类似示例：

// 将声音文件读入缓冲区
d = Buffer.read(s, ExampleFiles.child);

(
{
  var inA, chainA, inB, chainB, chain;
    inA = LFSaw.ar(100, 0, 0.2);
    inB = PlayBuf.ar(1, d, BufRateScale.kr(d), loop: 1);
    chainA = FFT(LocalBuf(2048), inA);
    chainB = FFT(LocalBuf(2048), inB);
    chain = PV_MagMul(chainA, chainB); // 写入 bufferA
    IFFT(chain) * 0.1
}.play;
)

d.free;

复制 FFT 链

因为每个 PV UGen 都会覆盖前一个的输出，所以有必要在链中的所需位置将数据复制到额外的缓冲区，以便在不使用多个 FFT UGen 的情况下对输入进行并行处理。PV_Copy 可以实现这一点。

注意： 自 SC 3.7 起，PV_Copy 的实例会在需要时自动添加以支持并行处理。显式使用 PV_Copy 的现有代码应继续正常工作。

(
{
    var in, in2, chainA, chainB, chainC;
    var mod = LFNoise2.kr(2);
    in = Blip.ar(mod.exprange(4000, 2), 231);
    in2 = SinOsc.ar(mod.exprange(200, 4000));
    chainA = FFT(LocalBuf(2048), in);
    chainB = FFT(LocalBuf(2048), in2);
    chainC = PV_Copy(chainA, LocalBuf(2048));
    chainB = PV_MagMul(chainB, chainC);
    XFade2.ar(
        IFFT(chainA) * 0.4,
        IFFT(chainB) * 0.1,
        MouseX.kr(-1, 1)
    );
}.play
)

PV 处理也可以共享单个 FFT UGen 来并行处理信号。在以下示例中，'chain0' 和 'chain1' 共享同一个 FFT UGen。SuperCollider 会自动将 'chain' 中的 FFT 数据复制到 Synth 内部的隐藏 LocalBuf 中。在以下示例中，如果 PV_PhaseShift UGen 直接作用于 chainA，那么两个 IFFT 单元将产生相同的信号，相加时会相互增强。相反，声音几乎静音——这证明 chainB 位于不同的缓冲区中，即使函数没有显式创建它。

(
x = { var inA, chainA, chainB;
    inA = LFClipNoise.ar(100);
    chainA = FFT(LocalBuf(2048, 1), inA);
    chainB = PV_PhaseShift(chainA, pi);
    // 半圆相移应产生一个反相信号
    // 在实践中，超低频会溜过去
    // 但你在这里不会听到太多
    IFFT(chainA) + IFFT(chainB);
}.play;
)

绘制幅度

请注意，PV UGen 会根据需要在笛卡尔（复数）表示和极坐标表示之间进行转换，因此在使用多个 PV UGen 时，可能无法知道在任意给定时刻这些值会以哪种形式存在。FFT 产生复数输出（见上文）。然而，以下代码会返回一个可靠的幅度图：

c = Buffer.alloc(s,2048,1);

(
x = { var in, chain, chainB, chainC;
    in = WhiteNoise.ar;
    chain = FFT(c, in);
    0.01 * Pan2.ar(IFFT(chain));
}.play(s);
)

(
Routine({
    3.do{arg i;
        c.getToFloatArray(action: { arg array;
            var z, x;
            z = array.clump(2).flop;
            // 初始时数据为复数形式
            z = [Signal.newFrom(z[0]), Signal.newFrom(z[1])];
            x = Complex(z[0], z[1]);

            { x.magnitude.plot('Initial', Rect(200, 600-(200*i), 700, 200)) }.defer
        });
        0.1.wait;
}}).play
)

x.free;

UGen 访问 FFT 数据

可以直接在 synth 图中操作 FFT 数据（如果尚无现成的 PV UGen 能满足需求），使用 pvcalc、pvcalc2、pvcollect 方法即可。下面这个例子使用 SequenceableCollection: -clump 和 SequenceableCollection: -flop 方法重新排列频谱 bin 的顺序：

c = Buffer.read(s, ExampleFiles.child);

(
x = {
    var in, numFrames=2048, chain, v;
    in = PlayBuf.ar(1, c, loop: 1);
    chain = FFT(LocalBuf(numFrames), in);

    chain = chain.pvcalc(numFrames, {|mags, phases|
        /* 调整 mags 和 phases，然后返回它们 */
        [mags, phases].flop.clump(2).flop.flatten
    }, tobin: 250);

    0.5 * IFFT(chain).dup
}.play;
)
x.free; c.free;

使用 FFT UGens 的多通道扩展

将多声道展开与 FFT UGen 一起使用时必须小心，因为它们需要独立的缓冲区。像这样的代码可能具有欺骗性：

chain = FFT(bufnum, { WhiteNoise.ar(0.2) }.dup);

上述方法看起来可能有效，但实际上无效。它确实会产生两个 FFT UGen，但由于它们都写入同一个缓冲区，第二个只会覆盖第一个的数据，从而浪费 CPU 且毫无效果。

在使用 FFT UGen 进行多通道扩展时，有必要确保每个 UGen 写入不同的缓冲区。以下是一种实现方式的示例：

(
SynthDef("help-multichannel FFT", { |out=0| // bufnum 是一个数组
    var in, chain;
    in = [SinOsc.ar(200, 0, 0.2), WhiteNoise.ar(0.2)];
    chain = FFT(LocalBuf([2048, 2048]), in); // 每个 FFT 都有不同的缓冲区
    // 现在我们可以像平常一样进行多声道扩展
    chain = PV_BrickWall(chain, SinOsc.kr(-0.1));

    Out.ar(out, IFFT(chain));
}).play;
)

// 或使用全局缓冲区

b = { Buffer.alloc(s, 2048, 1) }.dup;

(
SynthDef("help-multichannel FFT", { |out=0, bufnum= #[0, 1]| // bufnum 是一个数组
    var in, chain;
    in = [SinOsc.ar(200, 0, 0.2), WhiteNoise.ar(0.2)];
    chain = FFT(bufnum, in); // 每个 FFT 都有不同的缓冲区
    // 现在我们可以像平常一样进行多声道扩展
    chain = PV_BrickWall(chain, SinOsc.kr(-0.1));

    Out.ar(out, IFFT(chain));
}).play(s,[\bufnum, b]);
)

b.free;

请注意，对 UGen 调用 dup 只是对该 UGen 的引用，因为 UGen 定义的 -copy 只是返回接收者。（更多细节请参阅 UGen。）

a = SinOsc.ar;
a.dup[1] === a

true

形如 IFFT(chain).dup 的代码遍布于 PV 帮助文件中，它只是一种将单声道信号复制为立体声的便捷方式，无需进行额外计算。

另请参见 Multichannel Expansion。
