Process

虚拟机和解释器的运行时环境。

Object

子类：Main

说明

Process 是虚拟机和解释器的运行时环境。它有一个名为 Main 的子类，你应该在该子类中重写 Process 的方法。有两个值得关注的方法：一个名为 startup，在类库编译完成后调用；另一个名为 run，当用户选择 Run 菜单命令时调用。

类方法

Process.tailCallOptimize

Process.tailCallOptimize = bool

获取或设置尾调用优化。默认开启。将其设置为 false 有助于调试，因为错误回溯中会包含中间层级。

实例方法

.nowExecutingPath

.nowExecutingPath = value

用法：thisProcess.nowExecutingPath

返回包含当前在解释器中交互式执行的代码的文件的完整路径。通常这是当前文档。如果代码块使用 String: -load 或 String: -loadPaths 执行磁盘上的另一个文件，则 nowExecutingPath 将是所执行文件的位置。

nowExecutingPath 仅对交互式代码有效，即带有 .scd 扩展名的代码文件。它不适用于类定义（.sc）。对此，请使用 thisMethod.filenameSymbol 或 this.class.filenameSymbol。

此方法在 SuperCollider IDE、仅限 macOS 的 SuperCollider.app 以及 scel（SuperCollider-Emacs-Lisp）环境中受支持。在其他编辑器环境中，它将返回 nil。

警告： nowExecutingPath 有一个对应的设置方法 nowExecutingPath_，仅供解释器内部使用。不要调用该设置方法！

.startup

在类库编译完成后调用。在类 Main 中重写此方法以执行所需操作。

.run

当用户选择 Run 菜单命令时调用。在类 Main 中重写此方法以执行所需操作。

.mainThread

顶层 Thread，即所有其他 Thread 的父。此 Thread 实例始终存在，并在 SuperCollider 启动时随 Process 一起创建。

讨论：

所有 SuperCollider 代码最初都在主 Thread 的上下文中运行：

  • 在代码编辑器中求值的代码
  • 在命令行上求值的代码
  • 调度在任何 Clock 上的任务
  • 响应传入的 OSC 和 MIDI 消息而求值的函数

这意味着 thisThread 最初总是指向主线程。然而，当某些代码启动一个 Routine 时，该 Routine 成为当前线程，而主线程作为其父线程。
