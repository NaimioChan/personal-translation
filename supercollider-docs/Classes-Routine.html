Routine

可以在中间返回，然后从离开处继续执行的函数

Thread : Stream : AbstractFunction : Object

参见：Stream

子类：FuncStreamAsRoutine

说明

例程运行一个 Function，并允许它在中间挂起，然后在离开处再次恢复。此功能由其父类 Thread 提供支持。实际上，例程可用于实现协程，就像 Scheme 和其他一些语言中的那样。

Routine 在首次调用 -next 时被启动，此时将从头开始运行该 Function。当它“yield”时（在 Function 内使用 Object: -yield）被挂起，然后再次使用 -next 时被恢复。当 Function 返回时，Routine 被视为停止，此后调用 -next 将不起作用——除非使用 -reset 将该 Routine 重置，这会将该 Function 倒回到开头。你可以在 Function 返回之前使用 -stop 停止一个 Routine。

当一个例程被调度到时钟上时（例如使用-play），它将在预定的时间启动或恢复。例程产生的值将作为重新调度该例程的时间差。（参见-awake）。

由于 Routine 继承自 Thread，它有自己的关联逻辑时间等。当 Routine 启动或恢复时，它成为当前线程。

Routine 也继承自 Stream，因此共享其使用数学运算进行组合和“过滤”的能力。

类方法

Routine.new(func, stackSize: 512)

来自父类：Thread

创建一个 Routine 实例，将带有要运行代码的 Function 传递给它。

参数：

func

一个包含供 Thread 运行的代码的 Function。

stackSize

调用栈大小（一个 Integer）。

讨论：

a = Routine.new({ 1.yield; 2.yield });
a.next.postln;
a.next.postln;
a.next.postln;

Function 类提供了自己的快捷方法 r，它调用 Routine.new，因此也可以写成：

a = r { 1.yield; 2.yield };

实例方法

.next(inval)

此方法根据例程的状态执行不同操作：

  • 启动该例程（如果尚未启动或已被 reset），即从头运行其函数，并传入 inval 参数。
  • 如果 Routine 已被挂起（它已 yield），则恢复它；即从在某个 Object 上调用 yield 的位置恢复其 Function，并将 inval 参数作为 yield 的返回值传入。
  • 如果例程已停止（因为其函数已返回，或已调用 -stop），则不做任何操作。

thisThread：由于 Routine 继承自 Thread，它在启动或恢复时会成为当前线程；即在 Routine 函数中使用的 thisThread 将返回该 Routine。

时间：就在调用 next 之前，thisThread 指向另一个例程或顶层线程。在 next 调用期间，它成为父线程（参见 Thread: -parent）。随后 next 在父线程的时钟上、以父线程的逻辑时间进行求值。

next 的同义词是 -value 和 -resume。

返回值：

  • 要么是 Routine 所 yield 的值（即在 Routine 函数内部调用 yield 的对象），
  • ...或 nil，如果例程已停止。

讨论：

当通过调用此方法（或其同义词之一）启动一个 Routine 时，该方法的参数会作为 Routine Function 的参数传入：

Routine { |inval|
    inval.postln;
}.value("hello routine");

在例程已经产出之后（它已在其函数中对某个对象调用 yield 的位置处被挂起），调用此方法（或其同义词）会恢复执行该函数，而此方法的参数将成为 yield 的返回值。要在函数内部访问该值，你必须将其赋给一个变量——通常，会复用函数的参数：

(
r = Routine { |inval|
    inval.postln;
    inval = 123.yield;
    inval.postln;
}
)

r.value("hello routine");
r.value("goodbye routine");

通常，一个 Routine 会多次 yield，每次 yield 的结果都会被重新赋值给其 Function 的参数。

(
r = Routine { |inval|
    inval.postln; // 启动时输出传入的值。
    5.do { |i|
        inval = (i + 10).yield;
        inval.postln; // 恢复时输出传入的值。
    }
}
)
(
5.do {
    r.value("hello routine").postln; // 打印 Routine 产生的值。
}
)

.value(inval)

等价于 -next。

.resume(inval)

等价于 -next。

.stop

相当于 Routine 函数执行到末尾或返回：此后，该 Routine 将不再运行（-next 方法没有效果并返回 nil），除非调用 -reset。

.reset

使得下次调用 -next 时，例程从头开始。

讨论：

如果一个 Routine 被停止（其 Function 已返回或已调用 -stop），它将永远不会再次运行（-next 方法没有效果并返回 nil），除非调用此方法。

Routine 无法重置自身，除非调用 Object: -yieldAndReset。

参见：Object: -yield、Object: -alwaysYield

.play(clock, quant)

来自父类：Stream

在指定的 Clock 上调度该 Routine，时间由 quant 指定。到了该时间，Routine 会被唤醒（通过调用 Routine: -awake），设置时钟和时间并对 Routine 求值。如果 Routine 产生一个数字，该数字对应的拍数会被加到当前时间上，并重新调度该 Routine。（此行为与调度 Stream 或 Function 兼容。）

参数：

clock

一个 Clock，默认是 TempoClock

quant

参见 Quant 帮助文件

讨论：

在例程中使用 Object: -idle，在此时间结束之前返回各值。时间相对于该线程的时钟来计量。

// 持续 6 秒，返回 200，然后继续
(
r = Routine {
        199.yield;
        189.yield;
        200.idle(6);
        199.yield;
        189.yield;
};

fork {
    loop {
        r.value.postln;
        1.wait;
    }
}
);

// 该值也可以是流或函数
(
r = Routine {
        199.yield;
        189.yield;
        Routine { 100.do { |i| i.yield } }.idle(6);
        199.yield;
        189.yield;
};

fork {
    loop {
        r.value.postln;
        1.wait;
    }
}
);

.reschedule(argClock, quant)

如果某个 Routine 当前已被调度到某个时钟上，它将预期在特定时间、特定时钟上“唤醒”。reschedule 允许你切换到不同的时钟或更晚的时间。

参数：

argClock

用于运行该 Routine 的新时钟。如果为 nil，则不会更改该 routine 的时钟。（注意：目前与 AppClock 不兼容；重新调度依赖于方法 schedAbs，而 AppClock 未实现该方法。）

quant

一个量化说明符，标识一个晚于下一个已调度时间的时间。若为 nil，则使用 nextBeat 的当前值。

讨论：

  • 重新调度到不同的时钟在秒的层面上是连续的，但在拍的层面上不一定连续。基于时间的模式（例如 Pseg，或将 Env 用作流）可能不会连续遵循包络形状。（Pseg 和 Env-as-stream 以正在播放的时钟上的拍来度量时间。在正常使用中，时钟从不改变，因此时间会单调地推进并穿过包络的断点。如果线程被重新调度到不同的时钟，拍值在新时钟上极不可能相同，因此包络会在时间上向前或向后跳跃。）

    切换时钟时，reschedule 会首先根据给定的 quant 以拍为单位计算出新的“唤醒”时间。然后将该 beats 值转换为同一时刻下新时钟的 beats 值。如果旧时钟的速度为 1，且 Routine 正在等待 1 拍，则下一次“唤醒”应在一秒后发生。在不带 quant 的情况下重新调度时，下一次“唤醒”仍然会在一秒后发生——但 beats 值会针对新时钟进行调整。

  • 目前 quant 会被解析为比该 Routine 当前的 nextBeat 更晚的时间。如果你试图强制将其提前，则很可能会出现某种不连续。这是因为 Routine 在正常唤醒之前无法重新调度。变通方法是把该 Routine 切换到另一个 Task 包装器中。
  • 目前例程必须正在播放（已在某个时钟上调度）。这是因为交接给新时钟或新时间发生在该线程的"唤醒"过程中。若例程未在播放，则它不会唤醒，什么也不会发生。
// 重新调度到不同的时钟，时间相同
c = TempoClock.new;

(
t = Routine {
    var lastSeconds = thisThread.seconds;
    loop {
        1.0.wait;
        [thisThread.beats, thisThread.seconds - lastSeconds].postln;
        lastSeconds = thisThread.seconds;
    }
}.play;
)

t.reschedule(c);  // 整个过程中秒数增量为 1.0

t.stop;

// 重新调度到更晚的时间，同一时钟
(
t = Routine {
    var lastSeconds = thisThread.seconds;
    loop {
        1.0.wait;
        [thisThread.beats, thisThread.seconds - lastSeconds].postln;
        lastSeconds = thisThread.seconds;
    }
}.play;
)

t.reschedule(quant: 1);

t.stop;

// 重新调度到更早的时间（变通方法，唯一可行的方式）
// 要求你从 PauseStream 开始！
// 如果 't' 最初是 Routine，则这不起作用。
(
t = PauseStream(Routine {
    var lastSeconds = thisThread.seconds;
    loop {
        1.0.wait;
        [thisThread.beats, thisThread.seconds - lastSeconds].postln;
        lastSeconds = thisThread.seconds;
    }
}).play;
)

// 稍后短于 1 拍
(
u = PauseStream(t.stream);
TempoClock.schedAbs(t.nextBeat.trunc, u.refresh);
t.stop;
)

u.stop;

.awake(inBeats, inSeconds, inClock)

此方法由 Clock 在其调度时间到达时调用，该 Clock 是例程被调度所在的时钟。它会调用 -next，并将以拍为单位的调度时间作为参数传入。next 返回的值（即例程所产出的值）将依次由该方法返回，从而决定例程下一次被重新调度的时间。

参数：

inBeats

调度时间，以拍为单位。这等于当前逻辑时间（Thread: -beats）。

inSeconds

调度时间，以秒为单位。它等于当前逻辑时间（Thread: -seconds）。

inClock

唤醒例程的时钟。

.p

将例程转换为模式（的子类）。

返回值：

一个 Prout，它（响应 asStream）充当原始例程（p 的接收者）的独立副本的生成器。

讨论：

任何 Pattern 的子类在响应 asStream 时都返回一个 Stream。然而，返回的 Stream 的确切子类取决于 Pattern 的类。特别地，Prout 在响应 asStream 时返回一个 Routine。因此，制作 Routine 独立副本的一种方法是，用方法 p 从它创建一个 Prout，然后从这个 Prout 创建一个新的 Routine。在紧接着的下面示例中，这第二步通过调用 asStream 显式完成，但在向其他 Pattern 传递参数的上下文中，后一步通常会自动发生，如后续示例所示。

(
r = Routine { "hi".yield; "bye".yield };
r.next.postln;    // "hi" posted

q = r.p.asStream; // 或者直接：r.p.iter
q.next.postln;    // "hi" 再次

r.next.postln;    // "bye" 因为 r 保留了自己的状态，独立于 q
)

注意： 由 .p.asStream 生成的新例程会从头运行原例程的函数。不会复制原例程的内部状态，只会复制其函数。相关地，Routine.copy（继承自 Thread）不会创建新的独立例程，只会返回接收者。

Routine 方法 p 在将返回 Routine 的表达式的结果作为 Pattern 的参数使用的上下文中最为有用，此时意图是将 Routine 的结果用作模式，即多次出现时彼此独立运行。

(
r = (:2..5); // 一个 seriesIter Routine
Ptuple([r, r]).asStream.all.postln; // posts [[2, 3], [4, 5]]
r.next.postln; // nil

p = r.p; // 从 r 创建一个 Pattern；r 已经结束也没关系
Ptuple([p, p]).asStream.all.postln;
// posts [[2, 2], [3, 3], [4, 4], [5, 5]]

// 显然，显式地把同一个以 Routine 为值的子表达式写两次
// 也会创建各自独立的 Routine。
Ptuple([(:2..5), (:2..5)]).asStream.all.postln;
// posts [[2, 2], [3, 3], [4, 4], [5, 5]]
)

在以下示例中，在 Pseq 中直接两次重用同一个 Routine 对象无法复制其输出，因为第一次嵌入已完全消耗了该例程的（非 nil）输出。

(
r = (:2..6);
Pseq([r, r]).asStream.all.postln;
// [2, 3, 4, 5, 6]

p = r.p;
Pseq([p, p]).asStream.all.postln;
// [2, 3, 4, 5, 6, 2, 3, 4, 5, 6]

Pseq([(:2..6), (:2..6)]).asStream.all.postln;
// [2, 3, 4, 5, 6, 2, 3, 4, 5, 6]
)

可访问的实例变量

Routine 继承自 Thread，这允许访问它的一些状态：

(
r = Routine { |inval|
    loop {
        // thisThread 指该 routine。
        postf("beats: % seconds: % time: % \n",
            thisThread.beats, thisThread.seconds, Main.elapsedTime
        );
        1.0.yield;

    }
}.play;
)

r.stop;
r.beats;
r.seconds;
r.clock;

.beats

.beats = inBeats

来自父类：Thread

返回值：

例程的已用拍数（逻辑时间）。当例程未运行时，拍数不会推进。

.seconds

.seconds = inSeconds

来自父类：Thread

返回值：

例程已流逝的秒数（逻辑时间）。当例程未播放时，秒数不前进，它是转换后的拍值。

.clock

.clock = inClock

来自父类：Thread

返回值：

线程的时钟。若尚未播放，则为 SystemClock。

var r, outval;
r = Routine.new({ |inval|
    ("->inval was " ++ inval).postln;

});

outval = r.next('a');
("<-outval was " ++ outval).postln;
outval = r.next('b');
("<-outval was " ++ outval).postln;
r.reset; "reset".postln;
outval = r.next('c');
("<-outval was " ++ outval).postln;
outval = r.next('d');
("<-outval was " ++ outval).postln;
outval = r.next('e');
("<-outval was " ++ outval).postln;
outval = r.next('f');
("<-outval was " ++ outval).postln;
)

(
var r;
r = Routine {
    10.do({ |a|
        a.postln;
        // 通常你会看到 Wait 被用来暂停一个例程
        // 这里在每个数字之间等待一秒
        1.wait;
    });

    0.5.wait;
    "done".postln;
}.play;
)

var r;
r = Routine {
    var times = { rrand(1.0, 10.0) }.dup(10) + thisThread.beats;
    times = times.sort;
    times.do({ |a|
        waitUntil(a);
        a.postln;
    });
    // 说完之前等待半秒
    0.5.wait;
    "done".postln;
}.play;

// 使用 Routine 动态设置按钮状态。
(
var update, w, b;
w = Window.new("State Window", Rect(150, Window.screenBounds.height - 140, 380, 60));

// 设置按钮标签的便捷方法
update = {
    |but, string| but.states = [[string.asString, Color.black, Color.red]];
    but.refresh;
};

b = Button(w, Rect(10, 10, 360, 40));
b.font_(Font("Impact", 24));

update.value(b, "there is only one state");

// 如果某个动作在每次被调用时都应执行不同的操作，那么 routine 就是
// 正确的选择。这比在外部创建变量并在动作函数中设置它们、
// 以便在动作之间保持状态要好

b.action_(Routine { |butt|
    rrand(15, 45).do { |i|
        update.value(butt, "%. there is still only 1 state".format(i + 2));
        0.yield; // 在此停止
    };
    w.close;
});

w.front;
)
// 使用 Pen 在窗口中动态绘制
(
var w, much = 0.02, string, synth;

w = Window.new("swing", Rect(100, 100, 300, 500)).front;
w.view.background_(Color.new255(153, 255, 102).vary);

string = "swing ".dup(24).join;

w.drawFunc = Routine {
    var i = 0;
    var size = 40;
    var func = { |i, j| sin(i * 0.07 + (j * 0.0023) + 1.5pi) * much + 1 };
    var scale;
    Pen.font = Font("Helvetica-Bold", 40);
    loop {
        i = i + 1;
        string.do {    |char, j|

            scale = func.value(i, j).dup(6);

            Pen.fillColor = Color.new255(0, 120, 120).vary;
            Pen.matrix = scale * #[1, 0, 0, 1, 1, 0];
            Pen.stringAtPoint(char.asString,
                ((size * (j % 9)) - 10) @ (size * (j div: 9))
            );
        };
        0.yield // 停在这里，返回一些不重要的东西
    }
};

fork { while { w.isClosed.not } { defer { w.refresh }; 0.04.wait } };

w.front;

)
