Server

表示服务器应用程序的对象

Object

另请参阅：Server Guide、Multi-client Setups、ServerOptions、Server Architecture、Server Command Reference、ServerStatusWatcher、Audio device selection

子类：ScoreStreamPlayer

说明

Server 对象是服务器应用程序的表示。它用于从 SuperCollider 语言中控制 scsynth（或 supernova）。（有关两者区别的更多细节，请参阅 Server Guide 以及 Client vs Server。）它转发 OSC 消息，并拥有若干分配器，用于跟踪节点、总线和缓冲区的 ID。

由 Server 对象表示的服务器应用程序可能运行在与 sclang 相同的机器上，也可能运行在远程机器上。

服务器的大多数选项均通过其 ServerOptions 实例进行控制。更多细节请参阅 ServerOptions 帮助文件。

服务器还持有一个 Recorder 实例（用于将输出录制到文件）和一个 Volume（主输出电平）。

注意： 默认情况下，始终有一个默认服务器，它存储在解释器变量 's' 中。例如，你可以通过调用 s.boot 来启动默认服务器

s.boot;
{ SinOsc.ar * 0.1 }.play(s); // 在服务器上播放合成器

服务器应用程序可能处于三种不同状态：运行中、未运行或无响应（例如在从磁盘加载大文件时）。

s.serverRunning // 如果为真则返回 true

注意： 如果收到消息 "Mismatched sample rates are not supported."，以下步骤可能会有帮助：1. 将设备设置为所需的采样率 2. 在服务器的启动信息中检查设备名称 3. 同时设置采样率和设备（s.options.sampleRate = …; s.options.device = "…"）4. 重启服务器："s.reboot"

关于常见服务器问题的一些见解可以在 FAQ 服务器问题 中找到

类方法

Server.new(name, addr, options, clientID)

创建一个新的 Server 实例。

参数：

name

一个符号；每个 Server 对象以其名称存储在一个全局类变量中。

addr

一个可选的 NetAddr 实例，提供主机和端口。默认是使用端口 57110 的本机地址，与本地服务器相同。

options

可选的 ServerOptions 实例。如果为 nil，将使用默认值创建一个 ServerOptions 实例。

clientID

一个整数。在多客户端环境中，可以为每个客户端分别指定用于节点、缓冲区或总线的范围。在正常使用中，当客户端注册通知时，服务器会自动提供一个 ID，因此你无需在此处提供。注意：在多客户端环境中，你需要将 ServerOptions: -maxLogins 设置为至少等于你希望允许的客户端数量。每个客户端上的服务器实例中的该设置必须相同。

Server.remote(name, addr, options, clientID)

创建一个新的 Server 实例，对应运行于另一台机器上的服务器应用。此方法假定远程应用已启动并立即开始监听。对于用此方法创建的实例，不应调用 -boot。Server Guide 和 Multi-client Setups 包含有关此用法和多客户端用法的更多信息。

参数：

name

一个符号；每个 Server 对象以其名称存储在一个全局类变量中。

addr

一个可选的 NetAddr 实例，提供远程机器的 IP 地址以及应用正在监听的端口。

options

可选的 ServerOptions 实例。如果为 nil，将使用默认值创建一个 ServerOptions 实例。

注意： 要启用远程连接，你需要更改选项 ServerOptions: -bindAddress，因为默认值只允许来自本机的连接。s.options.bindAddress = "0.0.0.0" 将允许来自任何地址的连接。

clientID

一个整数。在多客户端环境中，可以为每个客户端分别指定用于节点、缓冲区或总线的范围。在正常使用中，当客户端注册通知时，服务器会自动提供一个 ID，因此你无需在此处提供。注意：在多客户端环境中，你需要将 ServerOptions: -maxLogins 设置为至少等于你希望允许的客户端数量。每个客户端上的服务器实例中的该设置必须相同。

// 用法示例：
// 在运行服务器的机器上
(
s.options.bindAddress = "0.0.0.0"; // 允许来自任何地址的连接
s.options.maxLogins = 2; // 设置为正确的客户端数量
s.boot;
)

// 在远程机器上连接到服务器
(
o = ServerOptions.new;
o.maxLogins = 2;
t = Server.remote(\remote, NetAddr("192.168.0.130", 57110), o); // 设置为正确的地址和端口
// 关于返回的客户端 ID 的信息应发布在 post 窗口中
t.makeWindow; // 创建一个用于监视的窗口
)

// 如果你想使用远程服务器而无需显式地将其传递给例如 Synth 或 Function -play，请将其设为默认服务器：
//Server.default = t;

//否则，在远程服务器上发出一些声音 
{Resonz.ar(Saw.ar([100,101]), Line.kr(100,5000,10, doneAction: 2),mul: -12.dbamp)}.play(target: t); //使用 target 指定远程服务器

实例方法

.sendMsg( ... msg)

向服务器发送 OSC 消息。

讨论：

s.sendMsg("/s_new", "default", s.nextNodeID, 0, 1);

.sendBundle(time ... msgs)

向服务器发送一个 OSC-bundle。

讨论：

由于网络性能可能不规则，时间允许 bundle 在未来的指定时间点被求值。因此所有消息相对彼此是同步的，但被一个恒定偏移量延迟。如果这样的 bundle 迟到，服务器会回复一条 late 消息，但仍然会对其求值。

s.sendBundle(0.2, ["/s_new", "default", x = s.nextNodeID, 0, 1], ["/n_set", x, "freq", 500]);

.sendRaw(rawArray)

.listSendMsg(msg)

与 sendMsg 相同，但以数组作为参数。

.listSendBundle(time, msgs)

与 sendBundle 相同，但接受数组作为参数。

讨论：

这允许你将消息收集到数组中，然后再发送它们。

s.listSendBundle(0.2, [["/s_new", "default", x = s.nextNodeID, 0, 1],
    ["/n_set", x, "freq", 600]]);

.sendSynthDef(name, dir)

将写入本地目录中的 synthDef 发送到服务器

.loadSynthDef(name, completionMsg, dir)

加载位于远程目录中的 synthDef

.loadDirectory(dir, completionMsg)

加载目录 dir 中的所有 SynthDef。

参数：

dir

一个有效的路径 String。

completionMsg

.nextNodeID

获取唯一的 nodeID。

.nextPermNodeID

获取一个永久节点 ID。此节点 ID 位于保留范围内，并将一直保留，直到你显式释放它。

.freePermNodeID(id)

释放一个永久节点 ID 以便后续复用。

.wait(responseName)

可在 Routine 中使用，以等待服务器回复

.waitForBoot(onComplete, limit: 100, onFailure, clock)

服务器一启动就立即求值 "onComplete"。如果服务器尚未运行或启动，此方法会为你启动服务器。如果服务器已在运行，"onComplete" 会立即执行。

参数：

onComplete

在服务器成功启动后求值的函数。

limit

检查成功启动的次数。（每秒 5 次）

onFailure

在服务器启动失败后求值的函数。如果未提供 onFailure，则会发布错误消息。提供函数会抑制错误消息。如果你想要提供函数并打印正常的错误消息，请确保你的函数返回 "false"，例如 s.waitForBoot(onFailure: { ... custom action...; false })。

clock

默认的 Clock 是 AppClock。如果时间精度很重要，请使用 SystemClock 或 TempoClock。

讨论：

请参阅 -doWhenBooted 的讨论。

.doWhenBooted(onComplete, limit: 100, onFailure, clock)

服务器一启动就求值 "onComplete"。此方法假定服务器是通过单独的 boot 调用显式启动的。如果服务器已在运行，则立即执行 "onComplete"。

参数：

onComplete

在服务器成功启动后求值的函数。

limit

检查成功启动的次数。

onFailure

服务器启动失败后要执行的函数。如果未提供 onFailure，则会发布错误消息。提供函数会抑制错误消息。如果你想提供函数并打印常规错误消息，请确保你的函数返回 "false"，例如 s.doWhenBooted(onFailure: { ... custom action...; false })。

clock

默认的 Clock 是 AppClock。如果时间精度很重要，请使用 SystemClock 或 TempoClock。

讨论：

要以精确的时间控制进行播放，第四个参数 clock 应设置为精确的时钟（见上文），然后应将 GUI 类包装在 defer { ... } 中。

(
t = TempoClock;
t.tempo = 1;

s.waitForBoot({
    var win, routine;
    defer {
        win = Window();
        win.background_(Color.grey(0, 0)).onClose_{ routine.stop }.front;
    };
    routine = fork {
        9.do { |i|
            1.wait;
            { win.background_(Color.rand) }.defer;
            i = if (i % 4 == 0) { 93 } { 81 };
            x = {
                SinOsc.ar(i.midicps) * Env.perc.ar(Done.freeSelf) * [0.1, -0.1]
            }.play
        };
        defer { win.close }
    }
}, clock: t)
)

t.tempo = 30/60

.boot(startAliveThread: true, recover: false, onFailure)

启动远程服务器，创建新的分配器。

参数：

startAliveThread

如果为 true，则启动一个 Routine，每隔一段时间向服务器发送一条 /status 消息。消息之间的间隔由 theServer.aliveThreadPeriod = (seconds) 设置。默认周期为 0.7。如果为 false，则不会发送 /status，服务器的窗口也不会更新。

recover

如果为 true，则为服务器创建新的节点 ID 分配器，但使用旧的缓冲区和总线分配器。如果服务器进程实际上没有停止，这会很有用。在正常使用中，应使用默认值 "false"。

onFailure

在此方法中，onFailure 参数仅供内部使用。如果你希望在服务器启动或启动失败时执行特定操作，建议使用 -waitForBoot 或 -doWhenBooted。

讨论：

你无法在远程机器上启动服务器应用，但可以通过调用此消息来初始化分配器。

.quit(onComplete, onFailure, watchShutDown: true)

退出服务器应用程序

注意： 如果调用此方法时服务器无响应，将强制其立即退出。

参数：

onComplete

在退出完成后被调用的函数。

onFailure

在退出失败时被调用的函数。

watchShutDown

一个布尔值，告诉服务器是否在关闭期间监视状态。

.reboot(func, onFailure)

退出并重启服务器应用程序

参数：

func

在退出与（重新）启动之间被调用的函数。

onFailure

在退出失败时被调用的函数。

.freeAll

释放此服务器中的所有节点

.status

查询服务器状态

.notify

.notify = flag

服务器会发送通知，例如某个节点被创建时、来自 SendTrig 的 'tr' 消息，或 /done 动作。若 flag 设为 false，这些消息将不会发送到此客户端。默认值为 true。若为 true，服务器将回复一个 clientID（仅 scsynth），这在多客户端场景中很有用。若该 ID 与之前收到的任何 ID 不同，将创建新的分配器。更多信息参见 Local vs. Remote Servers, Multi-client Configurations。

.ping(n: 1, wait: 0.1, func)

测量服务器和客户端之间的时间，该时间可能会有所不同。在评估 func 时，它会被执行 n 次，并传入由此得到的最大值。

.options

.options = value

获取或设置此 Server 的 ServerOptions 对象。对选项的更改仅在服务器重启后才会生效。

.defaultGroup

返回此服务器上对应此客户端 ID 的默认组。此对象与 server.defaultGroups[server.clientID] 相同。

.defaultGroups

返回一个数组，将客户端 ID 映射到其关联的默认组（作为 Group 对象）。

.volume

.volume = newVolume

获取一个在默认组之后运行的 Volume 实例，或将服务器的输出音量设置为 level。Level 单位为 db。

.mute

静音服务器的输出。也可以从服务器窗口用 'm' 键切换。

.unmute

取消服务器静音。也可以在 Server 窗口中用 'm' 键切换。

.reorder(nodeList, target, addAction: 'addToHead')

将 nodeList 中的节点移动到由 target 和 addAction 指定的位置，并按 nodeList 指示的顺序放置它们。

讨论：

任何已经释放的节点都将被跳过。为 target 和 addAction 传入 nil 将导致位置为默认组的头部。

g = Group.new;
x = Array.fill(5, { Synth(\default) });
s.queryAllNodes;
s.reorder(x, g, \addToTail);
s.queryAllNodes;

.inputBus

返回一个表示输入音频总线的 Bus 对象。

.outputBus

返回一个表示输出音频总线的 Bus 对象。

将此服务器当前节点树的表示发布到 post 窗口。有关图形化变体，请参见 -plotTree。

.rtMemoryStatus(action)

向服务器查询当前空闲的实时内存量

参数：

一个在服务器响应时被求值的 Function，当前空闲 RT 内存量和最大连续块大小（均以字节为单位）作为参数传入。默认动作会打印一条消息。

.peakCPU

.avgCPU

获取 CPU 使用的峰值和平均值。

.latency

.latency = value

服务器的当前延迟。详情请参阅 Scheduling and Server timing。

.sampleRate

一个整数，表示服务器的标称采样率；换句话说，即服务器启动时请求的采样率。

.actualSampleRate

一个浮点数，表示当前的硬件采样率，该值可能会漂移。

.numSynths

获取正在运行的 Synth 数量。

.numGroups

获取 Group 的数量。

.numUGens

获取正在运行的 UGen 数量。

.numSynthDefs

获取已加载的 SynthDef 定义数量。

.pid

获取正在运行的服务器的进程 ID（如果不是内部服务器）。

.addr

.addr = netAddr

服务器的网络地址，为一个NetAddr。

.maxNumClients

如果已知，服务器上允许的最大客户端数。否则，为 ServerOptions: -maxLogins 的值，即服务器启动后将请求的值。在 -serverRunning 为 true 之前，此数字不保证正确。

.clientID

.clientID = val

getter 返回此客户端在远程进程上的客户端 ID。在服务器运行之前为 nil。

此设置器尝试为远程服务器进程设置此客户端的客户端 ID。输入无效或服务器正在运行时会失败。有效输入在 [0..(this.maxNumClients-1)] 范围内。

.hasShmInterface

如果 ServerShmInterface 可用，则返回 true。另请参见 Bus: Synchronous Control Bus Methods。共享内存接口在服务器首次启动后初始化。

警告： 目前，共享内存接口将服务器端口视为唯一标识符。在极少数情况下，当同一台机器上运行多个服务器并监听同一端口时，这会导致其中一个服务器的共享内存接口被另一个覆盖。

.serverBooting

如果服务器正在启动则为 true，否则为 false。

.hasBooted

如果服务器已启动，则为 true。不保证服务器具有正确的 clientID，也不保证 ServerTree 中的操作已经运行。

.serverRunning

仅当服务器完全就绪时为 true。服务器完全就绪的条件是：已启动、收到对 /notify 命令的回复、已获得客户端 ID，并且 ServerTree 已运行。

.unresponsive

如果服务器无响应则为 true（具体来说，是在 ServerOptions: -pingsBeforeConsideredDead 次 ping 尝试后仍未响应）；否则为 false。

.isLocal

如果服务器与 sclang 运行在同一台机器上则为 true，否则为 false。

.remoteControlled

.remoteControlled = value

如果服务器不受其运行所在机器的控制，则为 true，否则为 false。除非显式设置，否则该值与 isLocal 相同。

.userSpecifiedClientID

来自扩展 /usr/local/share/SuperCollider/SCClassLibrary/deprecated/3.10/deprecated-3.10.sc

在 3.9 中已弃用。返回 false。现在可以在服务器关闭时设置 Server:clientID，并且在服务器运行时会被锁定。因此，userSpecifiedClientID 在内部不再需要，且毫无意义。

消息捆绑

服务器提供对消息自动打包的支持。这在对象风格中非常方便，并确保同步执行。另请参见 Bundled Server Messages

.makeBundle(time, func, bundle)

对函数 func 求值，其生成的所有 OSC 消息都会被延迟并添加到一个 bundle 中。

参数：

time

如果设置为 nil 或一个数字，则捆绑包将在相应的延迟秒数后自动发送并执行。如果 time 设置为 false，则不会发送该捆绑包。

func

要求值的函数。

bundle

允许你传入一个已存在的 bundle 并继续向其添加内容。

返回值：

该 bundle，以便在需要时进一步使用。

讨论：

在 func 内部调用 sync 将拆分捆绑包并等待异步操作完成后再继续。

如果在求值 func 时遇到错误，此方法将抛出一个 Error 并停止消息延迟。

s.boot;
(
// 向服务器发送合成器定义
SynthDef("tpulse", { |out = 0, freq = 700, sawFreq = 440.0|
    Out.ar(out, SyncSaw.ar(freq, sawFreq, 0.1))
}).add;
)

// 函数中包含的所有在下面生成的 OSC 命令都将被添加到一个 bundle 中
// 并在 2 秒后同时执行。
(
s.makeBundle(2.0, {
    x = Synth.new("tpulse");
    a = Bus.control.set(440);
    x.map(\freq, a);
});
)
x.free;

// 不要发送
(
b = s.makeBundle(false, {
    x = { PinkNoise.ar(0.1) * In.kr(0, 1) }.play;
});
)
// 现在将 b 作为预先存在的 bundle 传递，并同步启动两个合成器
(
s.makeBundle(nil, { // nil 会尽快执行
    y = { SinOsc.kr(0.2).abs }.play(x, 0, 0, \addBefore); // 正弦包络
}, b);
)
x.free; y.free;

// 抛出一个错误
(
try {
    s.makeBundle(nil, {
        s.farkermartin;
    });
} { |error|
    ("Look Ma, normal operations resume even though:\n" + error.errorString).postln;
    x = { FSinOsc.ar(440, 0, 0.2) }.play; // 这可以正常工作
}
)
x.free;

// 使用同步
(
s.makeBundle(nil, {
    b = Buffer.read(s, ExampleFiles.child);
    s.sync; // 等待加载完成，然后发送 bundle 的其余部分
    x = { PlayBuf.ar(1, b) * 0.5 }.play;
});
)
x.free; b.free;

讨论：

(

    s.sync;
    a.set(\freq, 400);
}
)

.plotTree: METHOD NOT FOUND!

以图形格式绘制节点/组树，类似于 -queryAllNodes。这会创建一个包含 NodeTreeView 的单例窗口。

注意： 若要在每个 Server 实例或工作区中使用多个 NodeTreeView 实例，请参阅 NodeTreeView 文档中的示例。

此方法返回一个 NodeTreeView 的实例，也可以经由 -nodeTreeView 方法访问。在 3.14 版本之前，此方法返回 Server 自身的实例。

// 启动 SuperCollider 服务器：
s.boot;

// 打开一个 NodeTreeView 窗口，默认刷新率为每 0.5 秒一次：
s.plotTree;

// 关闭它：
s.nodeTreeView.close;
s.plotTree;

// 定义并播放一个重复模式，每 0.4 秒生成一个新的 synth：
x = Pn((dur: 0.4, midinote: 69, amp: 0.1)).play;

/*
NodeTreeView 窗口动态显示活动的 synth 节点。
初始时它显示第一个节点，之后每次刷新时，它保留之前的节点并添加一个新的。
这导致每个间隔会显示一到两个后续节点。
*/

// 停止更新 plotTree：
s.nodeTreeView.stop;

// 开始更新 plotTree：
s.nodeTreeView.start;

// 停止 pattern 的播放：
x.stop;

s.nodeTreeView.close;

参数：

interval

轮询间隔。

(
s.waitForBoot {
    // 打开一个刷新率为 2 秒的 plotTree 窗口：
    s.plotTree(2);

    // 定义并播放一个重复模式，每 0.5 秒生成一个新的 synth：
    x = Pn((dur: 0.5, midinote: 69, amp: 0.1)).play;

    /*
    由于 plotTree 窗口每 2 秒刷新一次，
    只显示最近的节点，
    第一个节点将在 2 秒延迟后出现（即四个音符播放之后），
    也就是说只有每第四个合成器节点可见。
    */

    5.wait; // 等待 5 秒。

    x.stop; // 停止模式的播放

    2.wait; // 等待 2 秒。

    s.nodeTreeView.close; // 关闭 plotTree 窗口
}
)

bounds

录制支持

以下方法供便捷使用。若要以采样精确的开始和停止时间进行录制，你应自行创建节点。更多信息请参见 DiskOut 帮助文件。关于非实时录制，请参见 Non-Realtime Synthesis (NRT) 帮助文件。

此功能也可通过服务器窗口上的录制按钮使用。按一次会调用 record，再按一次会调用 stopRecording（见下文）。这样做时，创建的文件将位于你的 recordings 文件夹中，并以当前日期和时间命名。recordings 文件夹的默认位置因平台而异，但始终存储在 thisProcess.platform.recordingsDir 中。设置此变量可更改默认位置。

注意： record 会在服务器的默认组之后创建录音 Synth，并使用 In.ar。因此，如果你在录音 Synth 之后添加节点，它们的输出将不会被捕获。为避免这种情况，可以使用 Node 对象（它们将默认节点作为目标），或者（在使用消息传递风格时）使用目标 nodeID 为 1.s.sendMsg("/s_new", "default", s.nextNodeID, 1, 1);

关于此主题的更多细节，请参见 Order of execution、Default Group 和 Node Messaging。

有关各种样本格式和头格式的信息，请参见 SoundFile。并非所有样本格式和头格式都相互兼容。请注意，输出文件的采样率将与服务器应用的采样率相同。这可以通过服务器的 ServerOptions 进行设置。

Example:

s.boot; // 启动服务器

// 要录制的内容
(
SynthDef("bubbles", { |out|
    var f, sound;
    f = LFSaw.kr(0.4, 0, 24, LFSaw.kr([8, 7.23], 0, 3, 80)).midicps; // 滑音函数
    sound = CombN.ar(SinOsc.ar(f, 0, 0.04), 0.2, 0.2, 4); // 回声正弦波
    Out.ar(out, sound);
}).add;
)

x = Synth.new("bubbles");

s.prepareForRecord; // 如果你想在精确的时间点开始录音，必须先调用这个。

s.record;

s.pauseRecording; // 可暂停

s.record // start again

s.stopRecording; // 这会关闭文件并释放 buffer 录音节点等

x.free; // 停止合成器

// 查看你的录音文件夹，你会找到一个以该日期和时间命名的文件

录制通过 Recorder 完成——一个服务器隐式持有一个实例。

.prepareForRecord(path, numChannels)

为录制服务器输出分配必要的缓冲区等。（参见下方的 record。）

参数：

path

一个 String，表示输出文件的路径和名称。如果目录不存在，将为你创建。（但请注意，如果因任何原因创建失败，录制也会失败。）

numChannels

一个 String，表示要录制的输出声道数。

讨论：

如果你不指定路径，则会在你的录音文件夹中创建一个文件（参见上面关于此的说明），名为 SC_thisDateAndTime。对文件头或采样格式的更改，或对声道数的更改，必须在调用此方法之前完成。

.record(path, bus, numChannels, node, duration)

开始或恢复录制输出。

参数：

path

这是可选的，会被传递给 prepareForRecord（见上）。

bus

要录制到的总线 - 默认为 0

numChannels

要录制的通道数——默认为 2

node

要录制的节点——默认为服务器根节点

duration

录制时长 — 默认为 inf

讨论：

如果你尚未先调用 prepareForRecord（见上文），则会为你调用它（但这会使真正开始录制前略有延迟）。

.pauseRecording

暂停录制。可通过再次执行 record 来恢复。

.stopRecording

停止录制，关闭文件，并释放相关资源。

讨论：

录制完成后必须调用此方法，否则输出文件将无法使用。录制时按 Cmd-. 具有相同的效果。

.recChannels

.recChannels = n

获取/设置要录制的通道数（int）。默认设置为 2（立体声），但可以增大以录制具有更多通道的声音文件。必须在 prepareForRecord 之前调用。

.recHeaderFormat

.recHeaderFormat = string

获取/设置输出文件的头部格式（字符串）。默认值为 "wav"。必须在 prepareForRecord 之前调用。

.recSampleFormat

.recSampleFormat = string

获取/设置输出文件的采样格式（字符串）。默认为 "float"（32 位）。常见选项包括用于 24 位音频的 "int24" 和用于 16 位音频的 "int16"。必须在 prepareForRecord 之前调用。

.recBufSize

.recBufSize = n

获取/设置用于 DiskOut UGen 的 Buffer 的大小。该值必须是 2 的幂。默认值为 sampleRate.nextPowerOfTwo，或比一秒更长的第一个 2 的幂的采样数。必须在 prepareForRecord 之前调用。

异步命令

服务器支持等待异步 OSC 命令（例如读取或写入声音文件）的完成。注意：以下方法必须从正在运行的 Routine 内部调用。显式传入 Condition 可以让多个元素依赖不同的条件。下面的示例应该能清楚地说明这一切是如何工作的。

.bootSync(condition)

启动服务器并等到启动完成后再恢复线程。

参数：

condition

一个可选的 Condition 实例，用于对其实施求值。

.sendMsgSync(condition ... args)

向服务器发送以下消息，并等待其完成后再恢复线程。

参数：

condition

一个可选的 Condition 实例，用于对其实施求值。

... args

一条或多条有效的 OSC 消息。

.sync(condition, bundles, latency)

向服务器发送 /sync 消息，当所有待处理的异步命令完成时，服务器将回复 /synced 消息。

参数：

condition

一个可选的 Condition 实例，用于对其实施求值。

bundles

一条或多条 OSC 消息，它们将在 sync 消息之前捆绑发送（从而确保它们先于 /sync 消息到达）。

latency

允许该消息在未来的特定时间点求值。

讨论：

在广域网上的 UDP 下，这可能比 sendMsgSync 稍微不安全一些，因为数据包可能乱序到达，但在本地网络上应该没问题。在 TCP 下，这应该始终是安全的。

(
Routine.run {
    var c;

    // 创建一个条件变量来控制 Routine 的执行
    c = Condition.new;

    s.bootSync(c);
    \BOOTED.postln;

    s.sendMsgSync(c, "/b_alloc", 0, 44100, 2);
    s.sendMsgSync(c, "/b_alloc", 1, 44100, 2);
    s.sendMsgSync(c, "/b_alloc", 2, 44100, 2);
    \b_alloc_DONE.postln;
};
)
