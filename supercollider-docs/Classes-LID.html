LID

Linux 输入设备

Object

另请参阅：HID、LIDInfo、LIDSlot、LIDGui

说明

该类提供了一种访问 Linux 输入层设备的方式，该层支持许多输入设备（鼠标、键盘、操纵杆、游戏手柄、数位板）和总线（串行、PS/2、USB）。

注意： 对于外部 HID 设备，建议使用 HID 接口，如 Working with HID 中所述，因为它能确保你的代码具有跨平台兼容性。只有在原始 HID 接口因设备需要特殊驱动程序（且该驱动程序在内核中提供）而无法访问的情况下，或者在你想要访问内部设备的情况下，才应使用该类。

注意：如果你在打开设备时遇到问题，例如收到消息 ERROR: LID: Could not open device，请检查 LID permissions

第一个示例：

LID.findAvailable;
LID.postAvailable; // 选择你想打开的那个，并在下一行填写 vendor 和 product id：
d = LID.open(2, 10); // trackpoint

d.postInfo;
d.postSlots;

d.debug_(true); // 稍微晃动一下，看看传入的数据

d.debug_(false);

// 创建一个 GUI：
d.makeGui;

// 关闭设备（如果你想执行本类中后续的示例，请先不要这样做）
d.close;

类方法

查找设备

查找设备的示例：

LID.findAvailable;

LID.available;

LID.postAvailable;

// 找到你想要的那个并找到它：

LID.findBy(2, 10) // 按供应商和产品

LID.findAvailable(name)

查询操作系统，确定哪些 LID 设备已连接到系统并可以访问。使用 LID 时，这是你需要执行的第一个方法，之后才能访问任何设备。

参数：

name

要查找的基本路径，默认是 "event"。另请参见 deviceRoot。

返回值：

可用设备的 IdentityDictionary

LID.deviceRoot

LID.deviceRoot = value

这是查找设备的基础路径。默认情况下为："/dev/input"。使用 findAvailable 时，会用传入的 name 扩展该路径，其默认值为 "event"。因此，默认情况下我们查找匹配路径 "/dev/input/event*" 的设备。

请参阅下文 使用替代 deviceRoot 打开设备

LID.available

一个可用设备的字典，或者更确切地说，是 LIDInfo 实例中关于它们的信息，由方法 findAvailable 填充

返回值：

一个 IdentityDictionary

LID.postAvailable

列出可用 LID 设备及其属性的人类可读列表（另见 LIDInfo）

LID.findBy(vendorID, productID, path, version, physical, unique)

通过指定设备的一个或多个特征，在可用设备字典中查找设备

参数：

vendorID

设备的供应商 ID，这是由设备自身编码的数字。

productID

设备的 product ID，这是由设备自身编码的数字。

path

设备的路径，这是由操作系统定义的路径。

version

设备的版本。

physical

设备的物理位置，这是由操作系统定义的路径。

unique

设备的唯一标识符，由操作系统定义。

返回值：

一个与搜索查询匹配的设备的 IdentityDictionary，如果未提供参数则为 nil

LID.findBy(2); // 按 vendorID
LID.findBy(2, 10) // 按供应商和产品
LID.findBy(productID: 10);
LID.findBy(path: "/dev/input/event4");
LID.findBy(version: 0);
LID.findBy(physical: 'synaptics-pt/serio0/input0')
LID.findBy(physical: "synaptics-pt/serio0/input0") // 参数被转换为 symbol 以进行检查
LID.findBy(unique: '')
LID.findBy(unique: "") // 参数被转换为 symbol 以进行检查

// 使用所有可能的参数：
LID.findBy(2, 10, "/dev/input/event4", 0x0000, 'synaptics-pt/serio0/input0')

打开设备

LID.open(vendorID, productID, path, version, physical, unique)

使用给定的 vendorID 和 product ID 打开设备。参数说明请参见 *findBy。该方法将调用 findBy 方法，并使用第一个可用的结果作为要打开的设备。

返回值：

LID 设备——一个 LID 的实例。

LID.new(path)

与 LID.openPath 相同。

LID.openPath(path)

使用设备在操作系统中的路径打开设备。

参数：

path

操作系统中的路径，例如 "/dev/input/event4"

返回值：

LID 设备——一个 LID 的实例。

LID.openAt(index)

使用设备在可用设备字典中的索引打开设备

参数：

index

可用设备字典中的索引

返回值：

LID 设备——一个 LID 的实例。

LID.openDevices

已打开设备的字典

返回值：

一个 IdentityDictionary

向 LID 事件添加函数

每当来自已打开的 LID 设备的数据到达时，会触发两种类型的动作。一个针对传入的元素数据的动作，以及一个针对设备的动作，表示其中一个元素发生了改变。在大多数情况下你会想使用第一个动作；只有在解析元素数据的顺序很重要的情况下，你可能想使用第二种类型——例如在处理对时间要求非常精确的按钮按下组合时。

可以在三个层级上设置动作：

  • 在全局级别——对任何 LID 设备、任何槽位调用
  • 在设备级别 - 针对特定设备调用，适用于任何槽位
  • 在槽位级别——针对特定设备的特定元素调用

LID.debug

LID.debug = onoff: true

当设置为 true 时，来自任何已打开 LID 设备的传入数据将被打印到 post 窗口。

LID.action

LID.action = function

设置或获取在从任何设备接收元素数据时要执行的动作。该函数将被传递以下参数：值（映射在 0 和 1 之间）、原始值、元素用途页、元素用途、元素 id、设备 id、设备（一个 LID 的实例）。

参数：

function

从设备接收元素数据时要执行的函数

LID.addRecvFunc(function)

向内部的 FunctionList 添加一个函数，每当来自已打开设备的元素数据到达时都会对该函数求值。传递给该函数的参数如上文所定义。如果你想要从自己编写的类向 LID 函数添加操作，同时仍保留从用户代码即时添加操作的选项，请使用此方法。

参数：

function

要添加到列表中的函数。

LID.removeRecvFunc(function)

向内部 FunctionList 添加一个函数，每当设备有数据传入时都会对其进行求值。

参数：

function

要从列表中移除的函数，这必须是对最初添加到列表中的 Function 的引用

管理 LID 子系统

以下方法在内部用于初始化和终结 LID 子系统，但在少数情况下你可能希望手动管理这些方法。

LID.initializeLID

初始化 LID 子系统，该方法在调用 findAvailable 方法时会被自动调用。

LID.running

指示 LID 子系统是否正在运行。

LID.closeAll

如果在 LID 子系统已初始化的情况下，此方法会在关闭时自动调用。为节省系统资源，也可以手动停止它。此方法将关闭所有已打开的 LID 设备。

为设备创建规格

设备规格是事件代码与符号控制名之间的映射。新规格可以通过 LID>>*register 添加到 LID.specs。

// 为 Logitech 轨迹球添加一个鼠标设备规格
LID.register('Logitech Trackball', LID.mouseDeviceSpec);

// 为 Logitech 游戏手柄添加自定义设备规格
(
LID.register('Logitech WingMan RumblePad', (
    // key
    rumble: #[0x0001, 0x0102],    // 隆隆声（切换 ff）
    mode: #[0x0001, 0x0103],    // 模式（切换 h 和 l）
    a: #[0x0001, 0x0120],        // 按钮 a
    b: #[0x0001, 0x0121],        // 按钮 b
    c: #[0x0001, 0x0122],        // 按钮 c
    x: #[0x0001, 0x0123],        // 按钮 x
    y: #[0x0001, 0x0124],        // 按钮 y
    z: #[0x0001, 0x0125],        // 按钮 z
    l: #[0x0001, 0x0126],        // 左前按钮
    r: #[0x0001, 0x0127],        // 右前按钮
    s: #[0x0001, 0x0128],        // 按钮 s
    // abs
    lx: #[0x0003, 0x0000],        // 左摇杆 x
    ly: #[0x0003, 0x0001],        // 左摇杆 y
    rx: #[0x0003, 0x0005],        // 右摇杆 x
    ry: #[0x0003, 0x0006],        // 右摇杆 y
    hx: #[0x0003, 0x0010],        // hat x
    hy: #[0x0003, 0x0011],        // hat y
    slider: #[0x0003, 0x0002]    // slider
));
)

LID.register(name, spec)

这将为指定设备注册 spec。如果该设备已打开且之前未使用该 spec，它将使用此 spec。另请参见 LID: *specs。

参数：

name

要为其注册的设备名称。

spec

要添加的 spec。这应该是一个 IdentityDictionary。

LID.specs

返回已注册的 specs。

LID.mouseDeviceSpec

返回鼠标设备的默认规范；任何鼠标、轨迹球、触控板或指点杆都应能使用此规范。

LID.keyboardDeviceSpec

返回键盘设备的默认规格；任何键盘或数字小键盘都应能使用此规格。

实例方法

.close

关闭 LID 设备，关闭设备是异步的。你可以设置一个 closeAction（见下文），它将在设备关闭时执行。

.isOpen

如果设备已打开则返回 true，如果设备已关闭则返回 false。

d.isOpen;
d.close;
d.isOpen;

发布关于该设备的可读信息

.postInfo

以人类可读的格式输出此设备的 LIDInfo。另请参见 LIDInfo。

.postSlots

以人类可读格式发布关于此设备所有槽的信息

.dumpCaps

以人类可读格式列出可用能力

.makeGui: METHOD NOT FOUND!

为该设备创建一个 LIDGui。

访问槽

设备能力以事件类型和事件代码映射的形式报告。事件类型和事件代码常量可在 /usr/include/linux/input.h 中找到。

.slot(evtType, evtCode)

通过其 evtType 和 evtCode 访问一个槽。另见 LIDSlot

参数：

evtType

用于访问该槽的 eventType。

evtCode

用于访问该槽的 eventCode。

.at(controlName)

如果为此设备定义了 spec，则可以使用 controlName 查找槽位。

.spec(forceLookup: false)

将槽标签映射到槽索引的 IdentityDictionary。

参数：

forceLookup

如果设置为 true，将强制使用此设备注册的规格重新初始化字典。

为设备添加功能

.debug

.debug = onoff

设为 true 时，来自此 LID 设备的传入数据将输出到 post 窗口。

d.debug_(true);
d.debug_(false);

.closeAction

.closeAction = value

设备关闭时要执行的函数。

d.closeAction_({ "hey, I got closed!".postln });
d.close;

.action

.action = value

设置或获取接收到设备数据时要执行的动作。该函数将接收 evtType、evtCode、值（根据该槽的 spec 映射）以及原始值作为参数。

d.action_({ |...args| ("my action" + args).postln });
d.action_(nil);

设备的属性

.slots

一个 IdentityDictionary，保存设备的所有槽位，即控件

.path

获取此设备的路径

d.path;

.info

获取此设备的 LIDInfo

d.info;

.vendor

获取此设备的供应商 id

d.vendor;

.product

获取此设备的产品 id

d.product;

.caps

可用功能的列表。

抓取设备

在拥有适当权限的情况下，可以抓取设备以防止其在其他应用程序（包括 X）中使用。抓取鼠标或键盘时要小心，因为之后你将无法再将它们用于正常交互（例如输入代码或移动鼠标指针）！

d[\b].action = { d.ungrab };
d.grab;

d.isGrabbed;

.grab(flag: true)

独占获取供 SC 使用的设备。

.ungrab

释放设备，使其不再专供 SC 使用。

.isGrabbed

检查设备是否被占用。

示例

查找并打开设备

LID.findAvailable;
LID.postAvailable; // 选择你想打开的那个，并在下一行填写 vendor 和 product id：
d = LID.open(2, 10); // trackpoint

d.postInfo;
d.postSlots;

d.debug_(true); // 稍微晃动一下，看看传入的数据
d.debug_(false);

事件动作（原始事件）

设备的 'action' 实例变量可用于事件通知。它会被传入事件类型、代码和当前值。

(
d.action = { |evtType, evtCode, evtValue|
    [evtType.asHexString(4), evtCode.asHexString(4), evtValue].postln
}
)

d.action = nil;

如果设备被移除，LID 会检测到并关闭该设备。它将执行 closeAction，该动作可由用户定义：

d.closeAction = { "device was detached".postln };

事件动作（原始槽事件）

当 'action' 为 nil 时，动作可以绑定到特定事件。

(
d.slot(0x0002, 0x0001).action = { |slot|
    [slot.type.asHexString(4), slot.code.asHexString(4), slot.value].postln;
}
)

相对槽可以有 deltaActions：

(
d.slot(0x0002, 0x0001).deltaAction = { |slot|
    [slot.type.asHexString(4), slot.code.asHexString(4), slot.delta].postln;
}
)

事件动作（符号槽事件）

当为给定设备名称注册了设备规格后，可以使用符号控制名称来分配槽位动作。

    d[\x].action = { |slot| [\x, slot.value].postln };

LED's

有些设备具有可打开和关闭的 LED。这些在 d.caps 中显示为类型 0x0011 的事件

d = LID("/dev/input/event0");
// LED 可以点亮：
d.setLEDState(0x0, 1)
// （LED 0x0 在任何键盘上都应可用）
// 然后关闭：
d.setLEDState(0x0, 0)
d.close;

// setLEDState(evtCode, evtValue)：值应为 1 或 0

关闭设备

d.close;
LID.closeAll;

使用替代的 deviceRoot 打开设备

输入设备通过设备节点访问，通常为 /dev/input/event[0-9]。使用 udev 等用户空间守护进程时，可以为设备分配有意义的名称。

原始设备名称：

d = LID("/dev/input/event4");

符号设备名

d = LID("/dev/input/trackball");

相对于 LID.deviceRoot 的设备名称

d = LID("gamepad");

构建一个可用设备的列表：

LID.findAvailable;

buildDeviceList 会在 LID.deviceRoot+"/event" 中构建设备表，尝试打开找到的所有设备，查找其名称，然后再次关闭它们。结果会被返回，之后可通过 LID.deviceList 访问。你可以通过传入参数来查询除 "/event" 之外的其他名称。（搜索方式为：LID.deviceRoot++"/"++name++"*"）

LID.findAvailable("mouse");

注意： 这很可能给出设备无法打开的信息，因为 "mouse" 使用了另一个接口（当然你也可以通过 "event" 接口访问鼠标）

注意： 如果你完全无法打开设备，请查阅帮助文件：LID permissions
