Environment

一个可作为函数“命名空间”的字典

IdentityDictionary : Dictionary : Set : Collection : Object

另请参阅：Event、IdentityDictionary

子类：Event

说明

Environment 是一个 IdentityDictionary，具有额外特性，使其能充当一个“命名空间”，在其中可以定义和/或求值函数。

类方法

Environment.stack

Environment.stack = value

维护一个由 *push 和 *pop 访问的 Environments 栈。

Environment.make(function)

创建一个新的 Environment 并发送 make 消息。

Environment.use(function)

创建一个新的 Environment 并发送 use 消息。

Environment.push(envir)

将 currentEnvironment 保存到栈上。

Environment.pop

从栈中恢复 currentEnvironment。

实例方法

.make(function)

在环境中评估该函数，并返回该环境。

.use(function)

在该环境中计算该函数，返回该函数的返回值。

.push

将接收者保存到栈上。

.pop

从栈中恢复 currentEnvironment。

.linkDoc(doc)

将环境链接到当前文档，使其仅在一个文档处于焦点时作为 currentEnvironment。参见：Document: -envir

参数：

doc

要链接到的文档，默认为当前文档（Document: *current）。如果该文档具有焦点或未给出文档，则立即压入环境。

.unlinkDoc(doc)

将环境取消链接到当前文档，使其仅当某个文档处于焦点时才作为 currentEnvironment。参见：Document: -envir

参数：

doc

要从中取消链接的文档，默认为当前文档（Document: *current）。如果该文档具有焦点或未指定文档，则立即弹出环境。

未文档化的实例方法

.composeEvents(event)

.eventAt(key)

伪变量（全局变量）

这些不是方法，而是全局变量。

警告： 一般来说，你不应直接操作这些变量。而应使用 -use、-push 和 *pop 方法。

currentEnvironment

确定由 "~" 语法、valueEnvir 和 valueArrayEnvir 所使用的环境

topEnvironment

currentEnvironment 的初始值。放在此处的 ~environmentVariables 可用作“全局变量”，只要 topEnvironment 保持为 currentEnvironment。

~abc = 10;  // 环境变量（作用类似于全局变量）

currentEnvironment;  // abc 在那里
topEnvironment;  // 而这里，因为……

// 它们是完全相同的环境
currentEnvironment === topEnvironment;

// 一个独立的环境
e = Environment.make { ~def = 20 };

e.push;  // 使 'e' 成为 currentEnvironment

~abc  // 现在为 nil，因为……

currentEnvironment;  // 这是 'e' 且仅包含 ~def
topEnvironment;  // 仍有 ~abc

e.pop;  // 返回到之前的 currentEnvironment

~abc  // 它回来了！

因此，~abc 并非真正的全局变量，因为如果其环境不是当前环境，它就无法访问。

相关消息

valueEnvir(arg1, arg2...)

求值一个函数，在 currentEnvironment 中查找未指定的参数

valueArrayEnvir(argArray)

与 valueEnvir 相同，但参数以数组形式传入

Overview

topEnvironment、currentEnvironment、make 及用法

当 SuperCollider 启动时，它会创建一个 Environment，并将其存储到伪变量 topEnvironment 和 currentEnvironment 中。topEnvironment 提供了一组可全局访问的命名值，类似于 Interpreter 变量 a、b、c、……。

编译器提供了快捷语法，其中 ~ 是 currentEnvironment 的占位符。这使得表达式 ~myvariable; 等价于 currentEnvironment.at(\myvariable);，表达式 ~myvariable = 888; 等价于 currentEnvironment.put(\myvariable, 888);

消息 *make(function) 和 *use(function) 用接收者替换 currentEnvironment。消息 *make 旨在初始化 Environment 时使用，因此它返回 Environment。消息 *use 用于在 Environment 中求值函数，因此它返回该函数的返回值。

例如

(
a = Environment.make({
    ~a = 100;
    ~b = 200;
    ~c = 300;
});
a.postln;
)

创建一个环境，而

a.use({
    ~a + ~b + ~c
}).postln;

在该环境中求值该函数。

valueEnvir 与 valueArrayEnvir

当使用 valueEnvir 和 valueArrayEnvir 对 Function 求值时，未指定的参数会在当前 Environment 中查找。如果在 Environment 中找不到该参数，则使用其默认值。

(
var f;

// 定义一个函数
f = { |x, y, z| [x, y, z].postln };

Environment.use({
    ~x = 7;
    ~y = 8;
    ~z = 9;

    f.valueEnvir(1, 2, 3);    // 所有值均已提供
    f.valueEnvir(1, 2);    // z 在当前 Environment 中查找
    f.valueEnvir(1);    // y 和 z 在当前 Environment 中查找
    f.valueEnvir;        // 所有参数都在当前 Environment 中查找
    f.valueEnvir(z: 1);    // x 和 y 在当前 Environment 中查找
});
)

下面说明如何将此与乐器函数一起使用。环境允许你定义乐器，而无需担心参数顺序冲突。尽管下面三个函数的 freq、amp 和 pan 参数的声明顺序不同，但这没有关系，因为 valueEnvir 会在环境中查找它们。

s.boot;

(
var orc;
orc = Environment.make {
    ~a = { |freq, amp, pan|
        Pan2.ar(SinOsc.ar(freq), pan, amp);
    };
    ~b = { |amp, pan, freq|
        Pan2.ar(RLPF.ar(Saw.ar(freq), freq * 6, 0.1), pan, amp);
    };
    ~c = { |pan, freq, amp|
        Pan2.ar(Resonz.ar(GrayNoise.ar, freq * 2, 0.1), pan, amp * 2);
    };
    ~orc = [~a, ~b, ~c];
};
// 'reverb'
{ var in; in = In.ar(0, 2); CombN.ar(in, 0.2, 0.2, 3, 1, in) }.play(addAction: \addToTail);

{ loop({
    orc.use({
            // 在环境中设置值
        ~freq = exprand(80, 600);
        ~amp = 0.1;
        ~pan = 1.0.rand2;

            // 调用一个随机选择的乐器函数
            // 使用环境中的值

         x = { ~orc.choose.valueEnvir }.play(fadeTime: 0.2, addAction: \addToHead);
         0.2.wait;
         x.release(0.2);
    });
}) }.fork;

)

环境与异步函数

函数中声明的局部变量，以及类和实例变量，都使用词法作用域。也就是说，理解它们的上下文取决于编译期间读取声明的位置。异步函数——任何会在当前执行流之外（晚于当前执行流）执行的函数——会携带其词法作用域变量。

f = { var a = "got it"; { a.postln }.defer(0.5) };
f.value;

异步函数包括任何已调度函数、与 OSCFunc、MIDIFunc、HID 关联的响应函数或 GUI 动作函数，或用于服务器消息传递的动作（例如 Buffer.read、Buffer 或 Bus 的 .get 等）。

环境变量具有动态作用域；它们从当前的环境读取，无论该环境在声明函数时是否为当前环境。例如，以下代码会失败，因为当延迟函数唤醒时 e 已不再是当前环境。

e = (a: "got it", f: { { ~a.postln }.defer(0.5) });
e.use { e.f };

Function 的 inEnvir 方法将函数附加到特定环境。如果未指定环境，则执行 inEnvir 时的当前环境为默认值。

e = (a: "got it", f: { { ~a.postln }.inEnvir.defer(0.5) });
e.use { e.f };

将环境用作对象原型

Environment 的 know 变量保存一个 Boolean 值，控制该 Environment 是否可用作对象原型。如果 know 为 true，那么发送给 Environment 的任何它尚不理解的消息都会被转发给 Environment 中的项。（如果为 false，则无法理解的消息会产生标准的“does not understand”错误消息。）

默认情况下，对于 Environment，know 为 false，对于 Event 为 true。

e = Environment[
    'someVariable' -> 5,
    'printMe' -> { |self, string| string.postln }
];

e.know = true;

更常见的情况是，使用事件来定义此类原型，因为语法更简单。

e = (someVariable: 5, printMe: { |self, string| string.postln });

对象原型在 Environment 中查找方法选择器以决定要做什么。

大多数对象会被直接返回——对于任何其他对象，该方法调用都表现得像 getter。

e.someVariable;
// 与……相同
e.at('someVariable');
e['someVariable'];

如果选择器是 setter，例如 someVariable_(value) 或 someVariable = value，则新值会被放入 Environment。

e.someVariable = 10;
// 与……相同
e.put('someVariable', 10);

如果 Environment 项是一个函数，则将其视作方法定义进行求值。传入该函数的第一个参数是持有该函数的 Environment；方法调用的参数作为第二个、第三个等参数传入该函数。

e.printMe("Oh hai wrldz");
// 与……相同
e['printMe'].value(e, "Oh hai wrldz");

该函数可以使用第一个函数参数访问 Environment 中的对象。

e.mul2 = { |z| z.someVariable * 2 };
e.mul2;

函数内的环境变量会引用当前活动的环境——而不是被寻址的 Environment。这是为了让对象原型能够与 currentEnvironment 交互。

e.mul2 = { |z| ~someVariable * 2 };
// 这会抛出错误，因为当前环境中的 ~someVariable 为 nil
e.mul2;

如果希望使用环境变量语法访问环境中的对象，请在函数内 'use' 该环境。

e.mul2 = { |z| z.use { ~someVariable * 2 } };
e.mul2;

注意： 注意避免使用在 environment（或 event）的任何父类中已定义的方法名。对象原型通过捕获尚未定义为类库方法的 method selector 来工作。使用诸如 'stop' 或 'reset' 之类的通用 method selector 会导致相应的类库方法响应，而 environment 中的条目将永远不会被检查。使用 setter —— name_() 或 .name = ... —— 向 environment 中赋值时，如果该名称已在类库中定义，则会发布一条警告消息。e.reset = { "My reset function".postln }; // 输出：WARNING: 'reset' exists a method name, so you can't use it as pseudo-method. // 这不会执行上面的 reset 函数 // 因为 Object:reset 会响应 e.reset;
