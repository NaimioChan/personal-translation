Unit Generator 与 Synth

一些基本概念的介绍

unit generator 是处理或生成声音的对象。unit generator 有许多类，它们都派生自类 UGen。

SuperCollider 中的单元生成器可以有多个输入，但始终只有一个输出。那些自然会有多个输出的单元生成器类（例如声像器）在实例化时会返回一个单元生成器数组。每个单元生成器只有一个输出的约定允许通过使用单元生成器数组来实现多通道。（更多细节见 多通道扩展。）

实例化。音频速率、控制速率

通过向 unit generator 的类对象发送 'ar' 或 'kr' 消息来创建 unit generator。'ar' 消息创建一个以音频速率运行的 unit generator。'kr' 消息创建一个以控制速率运行的 unit generator。控制速率 unit generator 用于低频或缓慢变化的控制信号。控制速率 unit generator 每个控制周期只产生一个采样，因此比音频速率 unit generator 消耗更少的处理能力。

单位生成器的输入参数在该类的文档中给出。

FSinOsc.ar(800, 0.0, 0.2); // 在 800 Hz 处创建一个正弦振荡器，相位 0.0，振幅 0.2

单元发生器的信号输入可以是其他单元发生器、标量，或单元发生器与标量的数组。

SynthDef 与 Synth

要播放一个 unit generator，需要将它编译进一个 SynthDef，并在服务器上通过 Synth 播放它。synth 节点是一个或多个一起执行的 unit generator 的容器。SynthDef 就像是一种用于在服务器上创建 synth 节点的模式。

s.boot; // 启动服务器

// 编译并发送此 def
SynthDef.new("FSinOsc-test", { Out.ar(0, FSinOsc.ar(800, 0, 0.2)) }).send(s); // 输出通道 0

// 现在创建一个 Synth 对象，它代表服务器上的一个 synth 节点
x = Synth.new("FSinOsc-test");

// 释放 synth
x.free;

上面创建的 synth 节点也可以使用“消息风格”来创建，从而节省客户端 Synth 对象的开销：

n = s.nextNodeID;
s.sendMsg("/s_new", "FSinOsc-test", n);
s.sendMsg("/n_free", n);

因为任何表达式都会返回它的值，为方便起见，我们可以把上面两行嵌套起来。（详见 Expression Sequence。）

s.sendMsg("/s_new", "FSinOsc-test", n = s.nextNodeID;);
s.sendMsg("/n_free", n);

理解客户端 Synth、Group、Buffer 和 Bus 对象底层的消息结构非常重要且有用。有关更多细节，请参见 Node Messaging、Server Tutorial 和 Client vs Server。

为方便起见，类 Function 的 'play' 方法会编译一个 SynthDef，并为你使用该函数创建并播放一个 synth。使用此方法时，如果你没有显式创建，系统会为你创建一个 Out ugen。

{ FSinOsc.ar(800, 0, 0.2) }.play; // 创建一个 800 Hz 的正弦振荡器并播放

构建音色

你可以对单位生成器进行数学运算，结果将是另一个单位生成器。对单位生成器进行数学运算本身并不进行任何信号计算——它是在构建单位生成器网络，这些网络将在 Synth 中播放时执行。这是需要理解的关键：合成网络，换言之信号流图，是通过执行单位生成器的表达式创建的。以下表达式创建一个流图，其根是一个执行 '+' 操作的 BinaryOpUGen 实例。它的输入是 FSinOsc 和 BrownNoise 单位生成器。

FSinOsc.ar(800, 0.0, 0.2) + BrownNoise.ar(0.2); // 按回车并查看 post 窗口

{FSinOsc.ar(800, 0.0, 0.2) + BrownNoise.ar(0.2)}.play; // play it
