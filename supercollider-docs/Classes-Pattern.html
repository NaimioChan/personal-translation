说明

模式与流

Pattern 是一个抽象类，是 Patterns 库的基础。这些类构成了一种丰富而简洁的音乐记谱语言。名为 Understanding Streams, Patterns and Events - Part 1 的一系列帮助文件提供了详细介绍。这里尝试进行更简短的描述。

Stream 是一个响应 next、reset 和 embedInStream 的对象。流表示通过消息 next 一次获取一个值的序列。一条 reset 消息会使流重新开始（许多流实际上会自我重复，但并非所有流都如此）。如果流用完了值，则它对 next 的响应为 nil。消息 embedInStream 允许一个流定义让另一个流“接管”该流的控制权。所有对象都响应 next 和 reset，其中大多数对象在响应 next 时返回自身。因此，数字 7 定义了一个产生无限个 7 序列的 Stream。大多数对象响应 embedInStream 时返回一个只返回该对象一次的 singleton Stream。

Pattern 是一个响应 asStream 和 embedInStream 的对象。Pattern 定义了 Stream 的行为，并在收到 asStream 消息时创建这样的流。Pattern 与 Stream 之间的区别类似于乐谱与该乐谱的演奏之间的区别，或类与该类的实例之间的区别。所有对象都响应此接口，大多数通过返回自身来响应。因此大多数对象都是模式，它们定义的流是该对象的无限序列，并嵌入为该对象只返回一次的单独流。

模式是依据其他模式而非具体值来定义的。这允许在模式定义中的任何位置用一个任意复杂的模式替换单个值。将流的定义与模式进行比较，有助于说明模式的实用性。

示例 1 - Pseq 与 Routine

Pattern 类 Pseq(array, repetitions) 定义了一个 Pattern，它将创建一个迭代数组的 Stream。类 Routine(func, stackSize) 定义了单个 Stream，在该流中运行的函数被定义为执行数组迭代。

下面使用 Pseq 和 asStream 消息创建了一个流，并直接使用 Routine 创建了一个相同的流。

// Routine 与 Pattern 对比
(
    a = [-100, 00, 300, 400];            // 要迭代的数组

    p = Pseq(a);                    // 创建 Pattern
    q = p.asStream;                    // 让 Pattern 生成一个 Stream
    r = Routine({ a.do({ |v| v.yield }) }) ;    // 直接创建 Stream

    5.do({ Post << Char.tab << r.next << " " << q.next << Char.nl });
)

示例 2 - 嵌套模式

在示例 1 中，使用 Pseq 和 Routine 差别不大。但 Pseq 实际上会把它的数组作为要嵌入的模式集合来迭代，允许另一个 Pseq 替换数组中的任意值。另一方面，Routine 则必须完全重新定义。

(
    var routinesA;
    a = [3, Pseq([-100, 00, 300, 400]), Pseq([-100, 00, 300, 400].reverse)];
    routinesA = [[3], [-100, 00, 300, 400], [-100, 00, 300, 400].reverse];
    p = Pseq(a);
    q = p.asStream;

    r = Routine({
        routinesA.do({ |v|
            v.do({ |i| i.yield })
        }) ;
    });
    10.do({ Post << Char.tab << r.next << " " << q.next << Char.nl });
)

示例 3 - Stream-embedInStream

消息 embedInStream 正是让模式能够实现这种嵌套的机制。大多数对象（例如下面的数字 3）对 embedInStream 的响应是让自身产出一次然后返回。流对 embedInStream 的响应是迭代自身直至完成，实际上在那个时间段内“接管”了调用它的流。

例程可以简单地通过将 yield 的调用替换为 embedInStream 的调用来执行模式。

(
    a = [3, Pseq([-100, 00, 300, 400]), Pseq([-100, 00, 300, 400].reverse)];

    r = Routine({ a.do({ |v| v.embedInStream }) }) ;
    p = Pseq(a);
    q = p.asStream;
    10.do({ Post << Char.tab << r.next << " " << q.next << Char.nl });
)

当然，不使用 Pseq 就没有简洁的方式来定义这个流。

注意： 出于效率考虑，embedInStream 的实现假定它是在一个 Routine 中被调用的。因此，embedInStream 绝不应在定义 FuncStream 或 Pfunc（创建 FuncStream 的模式）的函数内部被调用。

事件模式

Event 是带有 'play' 方法的 Environment。通常，Event 由一组键/值对组成，这些键/值对决定 play 方法实际做什么。值可以是任何对象，包括根据其他命名属性定义的函数。改变这些值可以产生一连串声音，有时被称为“音乐”…… 模式 Pbind 将特定模式与特定名称连接起来。详情请查阅其帮助页面。

播放事件模式

-play 方法并不返回模式本身。相反，它返回实际运行该模式的 EventStreamPlayer 对象。控制指令——停止、暂停、恢复、播放、重置——应发送给该 EventStreamPlayer。（同一个模式可以使用不同的 EventStreamPlayer 同时播放多次。）

p = Pbind(...);
p.play;
p.stop;    // 不会停止，因为 p 并不是实际正在播放的 EventStreamPlayer

p = Pbind(...).play;
p.stop;    // 确实会停止，因为 p 是 EventStreamPlayer

录制事件模式

模式可以实时或非实时录制。实时录制请参见方法 -record。

关于非实时录制，请参阅 Score 帮助文件，尤其是“从模式创建 Score”。这可能很棘手，因为 NRT 录制会启动一个新的服务器实例。该服务器实例不知道加载到你可能一直用于测试的实时服务器中的缓冲区或其他资源。模式负责（重新）加载任何资源（缓冲区、效果等）。Pfset 或 Pproto 可能有用。

类方法

实例方法

.asStream

从此模式返回一个 Stream。一个模式可用于生成任意数量的独立流。

a = Pgeom(1, Pwhite(1.01, 1.2), inf);
b = a.asStream; c = a.asStream;

b.next;
b.next;
b.next;

c.next; // c 独立于 b
c.next;

.embedInStream(inval)

给定一个 Stream（例如 Routine），在继续之前从此模式中产出所有值。一个模式可用于为任意数量的独立流产生值。

参数：

inval

inval 被传入所有子流，可用于从外部控制它们的行为。

a = Pgeom(1, Pwhite(1.01, 1.2), 5);
r = Routine { 2.yield; 3.yield; a.embedInStream; 7.yield };
r.nextN(12); // 来自 r 的下 12 个值

.play(clock, protoEvent, quant)

参数：

clock

将运行该模式的节拍时钟。如果省略，则使用 TempoClock.default。

protoEvent

将在每次迭代时馈入模式流的事件原型。如果省略，则使用 event.default。

quant

参见 Quant 帮助文件。

.record(path, headerFormat, sampleFormat, numChannels: 2, dur, fadeTime: 0.2, clock, protoEvent, server, out: 0, outNumChannels)

打开一个磁盘文件用于录音，并将该模式播放到其中。

参数：

path

录制文件的磁盘位置。如果未指定，会为你生成一个文件名并放在默认录音目录中：thisProcess.platform.recordingsDir。

headerFormat

文件格式，默认为 Server: -recHeaderFormat —— 关于支持的头部和采样格式，参见 SoundFile。

sampleFormat

采样格式，默认为 Server: -recSampleFormat。

numChannels

要录制的通道数，默认为 2。

dur

在停止之前运行模式多长时间。如果为 nil（默认值），模式将自行运行直至结束；然后停止录制。或者，使用 cmd-period 停止录制。如果给定一个数字，模式将运行该数量的拍，然后停止（使用 Pfindur），同时结束录制。

fadeTime

在最后一个事件之后，停止录音前允许的拍数。默认值 = 0.2。

clock

用于播放的时钟。如果未另行指定，则使用 TempoClock.default。

protoEvent

用于播放的事件原型。如果未另行指定，则回退到 Event.default。

server

用于播放和录制的服务器。未另行指定时为 Server.default。

out

录制时用于试听模式的输出总线，默认值 = 0。

outNumChannels

录制器回放的输出通道数。如果大于 numChannels，outNumChannels 将回绕。

// Pfset(function, pattern)
// function 构造一个事件，该事件被传递给 pattern.asStream

Pfset({ ~freq = Pseq([500, 600, 700], 2).asStream }, q).play;

// Pset(name, valPattern, pattern)
// 逐个事件地设置事件的一个字段（Pmul、Padd 类似）

Pset(\freq, Pseq([500, 600, 700], 2), q).play;

// Psetp(name, valPattern, pattern)
// 在 pattern 的每次迭代时设置一次（Pmulp、Paddp 类似）

Psetp(\legato, Pseq([0.01, 1.1], inf), r).play;

r = Psetpre(\freq, Pseq([500, 600, 700], 2), q);

Psetp(\legato, Pseq([0.01, 1.1], inf), r).play;

r = Psetpre(\freq, Pseq([500, 600, 700], 2), q);

Pstretchp(Pn(Env([0.5, 2, 0.5], [10, 10])), r).play;

// 以强制重复伪随机模式

// Prout(function) - 退出时，该函数必须返回 yield 最后返回的值
// （否则该模式无法被其他模式可靠地操作）

Prout({ |inval|
    inval = p.embedInStream(inval);
    inval = Event.silent(4).yield;
    inval = q.embedInStream(inval);
    inval = r.embedInStream(inval);
    inval;
}).play

// Pfunc(function) - 该函数不应调用 embedInStream，请改用 Prout。

Pn(Pbindf(q, \legato, Pfunc({ |inval| if (inval.at(\degree) == 5) { 4 } { 0.2 } }))).play
