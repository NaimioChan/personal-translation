前面的章节展示了如何使用流和模式来一次为单个参数生成复杂的值序列。

本节涵盖环境与事件，它们用于为模式构建一个符号事件框架，让你能用模式控制作曲的各个方面。

Environment

Environment 是一个将 Symbol 映射到值的 IdentityDictionary。始终存在一个当前 Environment，它存储在 Object 类的 currentEnvironment 类变量中。

符号和值对可以按如下方式放入当前 Environment：

currentEnvironment.put(\myvariable, 999);

并按如下方式从当前 Environment 中获取：

currentEnvironment.at(\myvariable).postln;

编译器为上述两种构造提供了简写形式。

~myvariable = 888;

等价于：

currentEnvironment.put(\myvariable, 888);

and:

~myvariable.postln;

等价于：

currentEnvironment.at(\myvariable).postln;

创建一个环境

Environment 有一个类方法 make，可用于创建 Environment 并为其填充值。make 的作用是临时用一个新的 Environment 替换当前的 Environment，调用你的函数在其中填充值，然后恢复之前的当前 Environment，并返回新的那个。

(
var a;
a = Environment.make({
    ~a = 100;
    ~b = 200;
    ~c = 300;
});
a.postln;
)

使用环境

实例方法 use 可以让你用一个自己创建的 Environment 临时替换当前的 Environment。use 方法返回你的函数的结果，而不是像 make 那样返回 Environment。

(
var a;
a = Environment.make({
    ~a = 10;
    ~b = 200;
    ~c = 3000;
});
a.use({
    ~a + ~b + ~c
}).postln;
)

还有一个 use 类方法，用于你想直接从 Environment 创建并使用结果的情况。

(
var a;
a = Environment.use({
    ~a = 10;
    ~b = 200;
    ~c = 3000;
    ~a + ~b + ~c
}).postln;
)

从当前环境调用带参数的函数

可以调用一个 Function 并让它从当前 Environment 中查找任何未指定的参数值。这是通过 valueEnvir 和 valueArrayEnvir 方法完成的。对于任何未指定的参数值，这些方法将在当前 Environment 中查找与参数同名的符号。如果未找到该参数，则使用函数为该参数定义的默认值。

(
var f;

// 定义一个函数
f = { arg x, y, z; [x, y, z].postln; };

Environment.use({
    ~x = 7;
    ~y = 8;
    ~z = 9;

    f.valueEnvir(1, 2, 3);    // 所有值均已提供
    f.valueEnvir(1, 2);    // z 在当前 Environment 中查找
    f.valueEnvir(1);    // y 和 z 在当前 Environment 中查找
    f.valueEnvir;        // 所有参数都在当前 Environment 中查找
    f.valueEnvir(z: 1);    // x 和 y 在当前 Environment 中查找
});
)

下面是一个有些刻意构造的示例，说明如何使用 Environment 来制造 SynthDefs。尽管下面三个函数的 freq、amp 和 pan 参数以不同的顺序声明，但这并不重要，因为 valueEnvir 会在环境中查找它们。

(
var a, b, c, n;

n = 40;
a = { arg freq, amp, pan;
    Pan2.ar(SinOsc.ar(freq), pan, amp);
};
b = { arg amp, pan, freq;
    Pan2.ar(RLPF.ar(Saw.ar(freq), freq * 6, 0.1), pan, amp);
};
c = { arg pan, freq, amp;
    Pan2.ar(Resonz.ar(GrayNoise.ar, freq * 2, 0.1), pan, amp * 2);
};

Task({
    n.do({ arg i;
        SynthDef("Help-SPE4-EnvirDef-" ++ i.asString, { |out|
            var sound;
            Environment.use({
                    // 在环境中设置值
                ~freq = exprand(80, 600);
                ~amp = 0.1 + 0.3.rand;
                ~pan = 1.0.rand2;

                    // 调用一个随机选择的乐器函数
                    // 使用环境中的值
                sound = [a,b,c].choose.valueEnvir;
            });
            sound = CombC.ar(sound, 0.2, 0.2, 3, 1, out);
            sound = sound * EnvGen.kr(
                Env.sine, doneAction: Done.freeSelf, timeScale: 1.0 + 6.0.rand, levelScale: 0.3
            );
            Out.ar(out, sound);
        }).send(s);
        0.02.wait;
    });
    loop({
        Synth( "Help-SPE4-EnvirDef-" ++ n.rand.asString );
        (0.5 + 2.0.rand).wait;
    });
}).play;
)

Event

类 Event 是 Environment 的子类。事件是将代表音乐事件参数名称的 Symbol 映射到其值的映射。这让你可以将任何想要的信息放入事件中。

类获取方法 default 检索默认的原型事件，该事件已用许多有用参数的值进行了初始化。它只代表一种可能的事件模型。你可以自由创建自己的事件模型，但最好先理解所提供的这一个，以便了解可以做什么。

原型事件是一个默认事件，它将被模式返回的流所变换。由事件模式产生的组合完全是由对单个 protoEvent 的副本进行变换而创建的。

值模式、事件模式和 Pbind

第 2 部分和第 3 部分讨论的模式被称为“值模式”，因为它们的流在每次调用 next 时返回单个值。这里我们介绍“事件模式”，它在转换为流后，每次调用 next 时返回一个 Event。

类 Pbind 在值模式与事件模式之间架起桥梁。它将每个事件中的符号绑定到从模式获得的值。Pbind 以成对形式接收参数，每对中的第一个是 Symbol，第二个是值 Pattern。任何对象都可以充当 Pattern，因此你可以使用常量作为模式（参见下面示例中的 \amp）。

当其流中的第一个结束时，Pbind 流返回 nil。

Pbind( \freq, Pseq([440,880]) ).play

通过向模式发送 asStream 消息，会为其创建一个事件流。Pbind 所做的是产生一个流，将其符号对应的值放入事件中，可能覆盖这些符号之前的绑定：

t = Pbind( \freq, Pseq([440,880]) ).asStream;
t.next(Event.default);
t.next(Event.default);
t.next(Event.default);

调用 Pattern: -play 时，会自动生成一个 EventStreamPlayer，它负责调度以及将 protoEvent 传递到事件流中。

EventStreamPlayer

类 EventStreamPlayer 是 PauseStream 的子类。PauseStream 只是一个流的包装器，允许播放、停止、启动它等……

EventStreamPlayers 使用 Pbind-asStream 返回的事件流以及 protoEvent 来初始化。EventStreamPlayer 在每次对 Pbind 流调用 next 时传入一个 protoEvent。Pbind 流会复制该事件，以便沿着模式流树向下和向上传递，使每个流都能修改它。

EventStreamPlayer 本身就是一个流，它返回标量（数字），时钟用这些标量来调度其下一次调用。每次时钟调用 EventStreamPlayer-next 时，播放器都会在 Pbind 流遍历返回 Event 之后，通过查询该 Event 来获取其 delta 值。

SC3 中的变化

在 SC2 中，你在 Pattern 上调用 asEventStream，会得到一个实际返回事件的流。

在 SC3 中，如果你想要一个真正的事件流，可以在 Event Pattern 上调用 asStream。这将给你一个事件流，然后你可以用它来初始化一个 EventStreamPlayer 对象。不过你不需要担心这一点，因为这通常会在 Pattern 的 play 方法中为你完成。另一个变化是，你不通过 asStream 方法传入你的 protoEvent。它由 EventStreamPlayer 在每次调用流的 next 时为你传入。

在这里你可以看到从 Pbind 返回的流是什么样子。

(
var pattern, stream;

    // 将 Symbol xyz 绑定到从 pattern 获得的值
pattern = Pbind(
    \xyz, Pseq([1, 2, 3])
);

    // 为 Pbind 模式创建一个事件流。
stream = pattern.asStream;

    // 事件流需要一个原型事件作为输入。
    // 此示例使用一个空 Event 作为原型
4.do({ stream.next(Event.new).postln; });
)

这是一个包含更多绑定的示例。

stream = pattern.asStream;
