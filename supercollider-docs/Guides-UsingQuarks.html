使用 Quarks

Quarks 指南

参见：Quarks、Quark、Git

Quark 是 SuperCollider 代码包，包含类、扩展方法、文档和服务器 UGen 插件。Quarks 类负责管理这些包的下载以及安装或卸载。

警告： 随着个人用户或团体为不同目的开发各自的 Quark，安装多个包可能会因彼此冲突而导致问题。因此，我们建议你只选择并安装你需要的包。一次安装一个 Quark 包也可能会有帮助，这样在出现问题时应该更容易排查。

注意： 如果你难以找到所需的 Quarks 包，你可能会发现以下百科中的 Quarks 包信息很有用：https://baryon.supercollider.online

初步阶段

Quarks 安装依赖 git 版本控制软件。详细安装说明见 https://git-scm.com。

  • Windows 用户可以从 https://git-scm.com/download/win 下载并安装适合其环境的安装文件。
  • Linux 用户可以从 https://git-scm.com/download/linux 复制适合自己环境的终端命令，并在终端窗口中运行它们。
  • 对于 Mac 用户，我们建议从 Homebrew 安装 git，具体说明见 https://git-scm.com/download/mac。如果你不确定是否已安装 Homebrew，请先按照安装 Homebrew 的说明操作。如果弹出窗口要求你安装“Xcode Command Line Tools”，你可能也需要安装它。

安装/卸载/更新 quark

使用 GUI

你可以使用界面安装 Quark：

Quarks.gui

这里提供了许多社区贡献的包，其中大部分托管在 github 上。

你还可以添加额外的文件夹，用于存放你自己开发的 quark，或你 fork 或下载的 quark。这些文件夹也会作为安装选项显示在 GUI 中。

// 将此放入你的 startup.scd
Quarks.addFolder("~/supercollider/quarks");

按名称

你可以按名称（卸载）安装 Quark：

Quarks.install("MathLib");
Quarks.uninstall("MathLib");

通过 git URL

Quarks.install("https://github.com/supercollider-quarks/MathLib.git");
// 卸载它
Quarks.uninstall("https://github.com/supercollider-quarks/MathLib.git");

从本地文件夹

并且你可以安装任何本地文件夹：

// 添加你自己的类
Quarks.install("~/supercollider/quarks/my-thing");
// 安装你下载并想尝试的东西
Quarks.install("~/Downloads/something-i-found");

你还可以添加一个文件夹来存放你的开发 quarks（你自己的以及你 fork 的内容）：

Quarks.addFolder("~/supercollider/quarks");

现在该文件夹中的每个 quark 都会出现在 GUI 中，供你安装/卸载。

如果你希望能够卸载本地 quark，但仍然在 GUI 中看到它们，强烈建议将本地 quark 目录收集到一个单一的主目录下。然后，使用 Quarks: *addFolder 添加该主目录。addFolder 不会添加单个 quark 目录。

重新编译类库

安装或卸载后，你需要 Language > Recompile Class Library

如果你弄得有点乱：

// 移除所有内容
Quarks.clear

Internals

安装时会通过 git 克隆到：

Quarks.folder;
// 打开文件夹并查看
Quarks.openFolder;

并且此路径会被添加到 LanguageConfig 的 includePaths 中，以便在你重新编译库时这些类位于 SuperCollider 的类路径中。

你可以通过 Preferences > Interpreter > Include Paths 查看并编辑当前的包含路径。

LanguageConfig.includePaths

你也可以在文件 sclang_config.yaml 中查看或编辑这些设置

解决冲突

SuperCollider 不允许重复的类定义，如果你不小心安装了冲突的包，将无法编译。

Quarks 界面只有在 SuperCollider 已编译并运行的情况下才能工作，因此如果出现问题，你必须手动修复。

如果你使用的是 SC IDE，请打开 Preferences > Interpreter 并从 Include Paths 中移除这些路径。

你也可以手动编辑 sclang_config.yaml

更新 Quarks

你可以通过求值以下代码来更新所有已安装的 Quarks：

Quarks.all.do{ |quark| quark.update() };

或在求值以下代码后按下“检查更新”按钮：

Quarks.gui

保存和加载 Quarks 集合

为了使项目工作更简单，你可以将当前安装的 Quarks 保存到 quarks.txt 文件，并在之后从该文件重新加载。这类似于 LanguageConfig 所做的，但它还会在需要时下载 Quarks 并安装所有依赖项。

这对项目非常有用，因为你可以固定项目所依赖的每个 Quark 的确切版本，并且即使在多年以后，也应当能够精确地重新加载它们。

// 保存你当前的状态
Quarks.save("~/supercollider/quarks.txt");
// 稍后重新加载
Quarks.load("~/supercollider/quarks.txt");

这会同时保存你拥有哪些 quark 以及它们所处的 git 修订版本。如果其中一个 quark 有未提交的更改，则会警告该 quark 处于 dirty 状态。

保存格式使用 git 标签来指定修订版本，当标签不可用时回退到指定修订版本的完整 sha 哈希。在 git 术语中，这称为 refspec。

如果你安装了不在 git 源代码管理下的本地路径（你自己的作品或下载的内容），那么这些路径将保存时不带任何版本或 refspec。

文件格式如下所示：

https://github.com/author/quarkname@tags/4.1.4
https://github.com/supercollider-quarks/ddwCommon@8ae156b460dcb08285013265cf3a1c7172bba665
~/supercollider/quarks/my-thing

注意，在此例中 `quarkname` 被检出到标签 4.1.4，而 `ddwCommon` 不在任何标签上，因此 refspec 是 SHA 哈希。在这两种情况下，这都会得到精确的引用。`~/supercollider/quarks/my-thing` 不是 git 仓库，因此它最多只能指定路径。

即使某个 quark 是通过目录按名称安装的，也会保存完整的仓库 URL，以确保引用始终不变（directory.txt 可能被编辑、URL 可能被更改，从而可能指向不同的源代码）。

任何不受 git 源代码控制的包都通过路径指定，路径简写为相对于 quark 文件、主目录或绝对路径的最合理形式。它们没有版本或 refspec。

制作你自己的 Quark

包是存储工作的自然方式。

将任何源代码文件夹安装为 Quark：

Quarks.install("~/path/to/my-quark")

或者创建一个用于开发工作的文件夹，并将其添加到附加文件夹中：

Quarks.addFolder("~/supercollider/quarks");

现在你可以从本地文件夹（卸载）安装自己的包。

使用 git 管理代码是可选的，但你应该尽早考虑使用它。即使你不打算与任何人共享代码，git 也提供了备份系统，并且在你破坏某些东西时能充当时间机器。

# in the terminal, its easy as this:
git init

Bitbucket 提供私有仓库的免费托管，你也可以在任何具有 SSH 访问权限的机器上搭建自己的 git 托管服务。但你甚至不需要外部托管的仓库就可以使用 git。

硬盘会损坏，备份会失败，人们会犯错。如果你在 bitbucket 上保留一份副本，你的工作就会安全得多。

发布 Quark

创建一个 git 仓库并将其推送到 github、gitlab、bitbucket 或任何可公开访问的 git 主机。

请务必为你的发布打上标签。标签的名称应当是对应的发布版本。强烈建议使用 语义化版本（例如 "v1.0.1"）。这样 Quarks 系统就能列出可用的版本，并允许用户选择要检出（checkout）的版本。版本标签还允许其他 quark 开发者将他们的依赖固定到特定的发布版本。

你可以通过将名称和 git URL 添加到以下文件，来将你的 quark 添加到 Community Quark Directory：

https://github.com/supercollider-quarks/quarks/blob/master/directory.txt

只需点击 edit，添加你的 quark 信息，然后提交一个 pull request。以下是 Quark 目录中条目应呈现的样子示例：

quarkname=https://github.com/author/quarkname

从 SVN 迁移的 Quarks

我（felix）将旧的 SVN 仓库迁移到了 github，并保留了所有提交记录和作者信息。你可能会在以下 quark 之一中找到你以前的工作：

https://github.com/supercollider-quarks

请联系我将所有权转移到你自己的 github 账户。你也可以直接 fork 那里的任何仓库，或者如果你已经把代码移到了 github，那么只需编辑该目录以指向你偏好的较新版本。

名称中包含空格的 Quarks 必须移除这些空格。嵌套在其他 Quarks（dewdrop_lib）内部的 Quarks 现在已取消嵌套。

git 分支

发布版本通过 git 标签指定，该标签指向一个特定的提交，无论它位于哪个分支。默认分支是 master，但分支实际上并不重要，只有标签重要。如果你没有为特定发布版本打标签，则 Quarks 将获取 master 分支。

Quark 文件

quark 文件是一个 SuperCollider 代码文件，包含作者、版本、版权和依赖信息。它是可选的，但推荐提供。没有任何字段是必填的，你可以包含任何自定义字段。

最重要的特性是指定依赖、版本、摘要以及指定帮助文件。

它类似于 npm（JavaScript 包管理器）中的 package.json 文件，或 Bower（Web/前端包管理器）的 bower.json。

文件名是 quark 的名称后跟 .quark 扩展名：

{quark name}.quark

并且是一个返回 IdentityDictionary 的 SuperCollider 文件

(
  name: "DemonWidgets",
  summary: "Widgets, gadgets and arcane devices for summoning demons.",
  version: "1.0.0",
  schelp: "DemonWidgets",
  dependencies: ["Bjorklund", "Canvas3D", "cruciallib@tags/4.1.4"],
  license: "GPL",
  copyright: "Frank Furter, Dr.-Ing. 2015"
)

公共字段

  • name
  • summary
  • author
  • copyright
  • license - 默认为 GPL
  • version - 首选 semver 兼容字符串，例如 "1.0.0"
  • schelp - 主帮助文件的标题
  • url - 主页，默认为 github/bitbucket url
  • dependencies - 见下文
  • isCompatible - 一个返回布尔值的函数。可以检查类、特性、版本号的存在性。
  • organization
  • country
  • since
  • ext_dependency - 描述外部软件的文本，如 "PD" 或 "processing"
  • preInstall - 一个函数 / 钩子，将在安装之前被调用 - 参见 Using Quarks: Hooks

dependencies 是一个 Quarks 或 git url 的列表，可带有可选的 @refspec

Bjorklund
cruciallib@tags/4.1.4

Hooks

注意： 在 SuperCollider 3.13 中引入，因此仅当运行至少此版本时才可用。

可以在安装或更新过程的特定时间点运行定义在 .quark 文件中的函数，即所谓的“钩子”。

这可用于设置或删除某些目录结构、检查硬件等。

执行时，钩子函数将作为第一个参数被处理为 Quark: -data，即解析后的 .quark 文件（作为 Event）。

以下钩子可用，并将由 Quark: -runHook 执行

\preInstall

将在 Quarks: *link 之前执行

\postInstall

将在 Quarks: *link 之后执行

\preUpdate

将在 Git: -pull 之前执行

执行时，它将具有 .quark 文件的旧状态

\postUpdate

将在 Git: -pull 之后执行

执行后，这将具有 .quark 文件的新更新状态

\preUninstall

将在 Quarks: *unlink 之前执行

\postUninstall

将在 Quarks: *unlink 之后执行

为 Quark 创建包含采样的目录的示例可能如下

(
  name: "DemonWidgets",
  // ...
  preInstall: {|data|
    File.mkdir("~/samples/%".format(data[\name]));
  },
  postUninstall: {
    "Samples at '~/samples/DomenWidgets' must be deleted manually".warn;
  },
)

已弃用/忽略的字段

path 曾用于 SVN

helpdoc 指定 Quark 中的一个 html 帮助文件。它仍能正常工作并加载该帮助文件，但更推荐使用 schelp。

向 quark 贡献修复

最佳实践是将 quark 克隆到你进行开发工作的文件夹中。创建一个 ~/supercollider/quarks（或任何你想要的路径），并将其添加到 Quarks 文件夹中：

Quarks.addFolder("~/supercollider/quarks");

将 quark git clone 到该文件夹中。你可以在那里进行开发工作 / 修改，并向仓库所有者提交 pull request。

有一个对处理 github 仓库非常有用的 git 扩展，是 https://hub.github.com

如果你使用 Quarks.gui，现在你应该能够同时看到下载版本的 quark 和你自己克隆的版本。

离线使用

Quarks 即使离线也应可用。目录会被缓存，每四小时刷新一次。克隆的 quark 可以在无需联网的情况下切换版本。

你可以下载所有 quarks 的压缩发布包：

https://github.com/supercollider-quarks/quarks/releases
