BeatTrack2

模板匹配节拍跟踪器

MultiOutUGen : UGen : AbstractFunction : Object

另请参阅：BeatTrack

说明

这个节拍跟踪器1基于对特征流穷举测试特定的模板模式；测试每 0.5 秒进行一次。两个基本模板是 16 分音符的直拍（groove = 0）和摇摆三连音（groove = 1）模式；该模式会在对应于 60 到 180 bpm 速度的缩放比例下进行尝试。这是节拍跟踪的互相关方法。对检测到的最佳速度进行多数投票，但这必须经过相位估计后的一致性检查来确认。这种一致性检查有助于避免估计值剧烈波动，但代价是额外半秒的延迟。因此，默认设置下节拍跟踪器的延迟至少为 2.5 秒；由于基于块的计算分摊，对于 2.0 秒的时间窗口，实际延迟约为 2.8 秒。

该节拍跟踪器旨在灵活满足用户需求；你可以尝试不同的窗口大小、速度权重和特征组合。然而，其稳定性和有效性无法保证，你需要针对特定情况探索这些参数。

类方法

BeatTrack2.kr(busindex, numfeatures, windowsize: 2.0, phaseaccuracy: 0.02, lock: 0, weightingscheme)

参数：

busindex

[sk] 要跟踪的音频输入，已分析为 N 个特征，通过一个控制总线号传入，从该总线号获取连续的流。

numfeatures

[s] 提供了多少个特性（即多少个控制总线）

windowsize

[s] 所需时间窗口的大小（2.0 到 3.0 秒模拟人类时间窗口）。你可以使用更长的值以换取估计的稳定性，但会牺牲响应性。

phaseaccuracy

[s] 与要测试多少个不同相位有关。在默认情况下，对于 60bpm 会尝试 50 个以 phaseaccuracy 秒为间隔的不同相位；对于 180 bpm 会尝试 16 个。较大的 phaseaccuracy 意味着更多测试和更高的 CPU 开销。

lock

[sk] 如果此参数大于 0.5，跟踪器将锁定在其当前周期性上并从当前相位继续。虽然它会更新模型的相位和周期，但在 lock 回到 0.5 以下之前，这不会反映在输出中。

weightingscheme

[s] 使用 (-2.5) 表示速度的平坦加权，(-1.5) 表示基于所测试事件数的补偿加权（因为不同周期允许时间窗口内不同数量的事件），否则使用从 0 向上的 bufnum 来传递包含 120 个单独速度权重的数组；速度从 60 到 179 bpm，步长为 1 bpm，因此你必须有一个包含 120 个值的缓冲区。

返回值：

六个 k-rate 输出：

#beattick, eighthtick, groovetick, tempo, phase, groove = BeatTrack2.kr(busindex, numfeatures)

实例方法

示例

// 你应该加载一些有用的东西来进行测试，比如一首一分钟的流行歌曲
b = Buffer.read(s, ExampleFiles.child);

// 高度依赖具体特性
(
SynthDef(\help_beattrack2_1, { |out, vol = 1.0, beepvol = 1.0, lock = 0, bufnum|
    var in, kbus;
    var trackb, trackh, trackq, tempo, phase, period, groove;
    var bsound, hsound, qsound, beep;
    var fft;
    var feature1, feature2, feature3;

    in = PlayBuf.ar(1, bufnum, BufRateScale.kr(bufnum), 1, 0, 1);
    // in = SoundIn.ar(0);

    // 创建一些特征
    fft = FFT(LocalBuf(1024), in); // 对于采样率 44100 和 48000
    // fft = FFT(LocalBuf(2048), in); // 适用于采样率 88200 和 96000

    feature1 = RunningSum.rms(in, 64);
    feature2 = MFCC.kr(fft, 2); // 两个系数
    feature3 = A2K.kr(LPF.ar(in, 1000));

    kbus = Out.kr(0, [feature1, feature3] ++ feature2);

    // 查看四个特征
    #trackb, trackh, trackq, tempo, phase, period, groove = BeatTrack2.kr(0, 4, 2.0, 0.02, lock, -2.5);

    beep = SinOsc.ar(1000, 0.0, Decay.kr(trackb, 0.1));
    beep = Pan2.ar((vol * in) + (beepvol * beep), 0.0);
    Out.ar(out, beep);
}).add;
)

a = Synth(\help_beattrack2_1, [\bufnum, b]);
a.set(\vol, 0.0);
a.set(\vol, 1.0);

a.set(\beepvol, 1.0);
a.set(\beepvol, 0.0);

a.set(\lock, 1); // 从当前相位/周期解刚性固定它
a.set(\lock, 0); // 取消固定，回到跟踪

a.free;
// 同样的事情，尝试使用 Onsets UGen 的原始输出

// 在自有权重方案中偏好更高的速度
(
c = Array.fill(120, { |i| 0.5 + (0.5 * (i / 120)) });
e = Buffer.sendCollection(s, c, 1);

// 跟踪音频输入（尝试拍一段节拍或做口技，但请允许最多 6 秒的跟踪启动时间），并以四分音符、八分音符和十六分音符的间隔生成内容
(
SynthDef(\help_beattrack2_2, { |out|
    var trackb, trackh, trackq, tempo;
    var source, kbus;
    var bsound, hsound, qsound;

    source = SoundIn.ar(0);

    // 通过 kr 从 ar 自动降采样
    kbus = Out.kr(0, LPF.ar(source, 1000)); // ([feature1, feature3]++feature2);

    #trackb, trackh, trackq, tempo = BeatTrack2.kr(0, 1, weightingscheme: e.bufnum);

    bsound = Pan2.ar(LPF.ar(WhiteNoise.ar * (Decay.kr(trackb, 0.05)), 1000), 0.0);
    hsound = Pan2.ar(BPF.ar(WhiteNoise.ar * (Decay.kr(trackh, 0.05)), 3000, 0.66), -0.5);
    qsound = Pan2.ar(HPF.ar(WhiteNoise.ar * (Decay.kr(trackq, 0.05)), 5000), 0.5);

    Out.ar(out, source + bsound + hsound + qsound);
}).play;
)
// 几何速度放置与线性非常相似，而线性在查找倍速和半速的相关速度时更容易处理
(
var startbps = 1, endbps = 3;
var numtempi = 100;
var ratio, tempi, periods;

ratio = (endbps / startbps) ** (numtempi-1).reciprocal;

tempi = Array.geom(numtempi, startbps, ratio);

periods = tempi.reciprocal;

Post << (tempi*60) << nl;
Post << periods << nl;
)

// 创建线性周期
Post << ((Array.series(120, 1, 2/120)).reciprocal) << nl;

// 速度权重
 Post << (Array.fill(120, { |i|  0.2*((1.0- ((abs(i-60))/60.0))**0.5) + 0.8 })) << nl;
