MeterSync

同步 SuperCollider LinkClock 对等体的小节线

Object

参见：LinkClock

说明

此类在 Ableton Link 协议之外实现了额外的网络消息传递，以确保 SuperCollider LinkClock 对等端与其他 LinkClock 对等端遵循相同的节拍（beatsPerBar）和小节线。

该类，或相关方法 LinkClock: -enableMeterSync 和 LinkClock: -disableMeterSync，应用于所有已链接的机器都应遵循同一拍号并且拍号在演出过程中会发生变化的演出场合。

如果拍号不会改变（典型用例是始终为 4/4 拍），那么只需在所有对等端上设置 myLinkClock.quantum = beatsPerBar。（参见 LinkClock: -quantum。）

理论上，MeterSync 可与任何响应 beatsPerBar、beatInBar 和 baseBarBeats 方法的 SuperCollider 时钟一起使用。目前仅在 LinkClock 上测试过。与 TempoClock 一起使用没有意义，因为 TempoClock 不会做任何事情来将其节拍与任何其他机器同步。

注意： 此类仅考虑 SuperCollider LinkClock 对等体的小节线位置！其他支持 Link 的应用程序不实现此协议。

Background

SuperCollider 使用两个数字定义 meter：

TempoClock: -beatsPerBar

一小节包含多少拍（4 = 4/4 拍，3 = 3/4 拍）。

TempoClock: -baseBarBeat

节拍器最后改变时的拍值。

例如，如果一个时钟运行四小节 4/4 拍，然后切换到 3/4 拍，则小节线不是 3 的倍数。拍号在第 16 拍改变，因此新的小节线将是 16 + (3 * n)（n 是整数）。此时，beatsPerBar = 3 且 baseBarBeat = 16。

Ableton Link 维护一个量子，它类似于 TempoClock: -beatsPerBar。如果所有对等方遵循相同的拍号并具有相同的量子，则 Link 本身会同步小节线。（因此，在始终使用一致拍号的常规用例中，完全不需要使用 MeterSync。）

然而，在更改 Link 量子时，Link 并不保证拍值会一致地递增。设置量子应在演出开始前完成，而不是在演出过程中进行。

SuperCollider 可以独立于 Link quantum 更改其 beatsPerBar。但是，在这种情况下，各对等端之间的小节线可能无法同步。

MeterSync 通过查询其他 SuperCollider Link 对等端的当前节拍位置来解决此问题。如果本地机器与其他对等端不同，则本地机器会调整其 baseBarBeat，以与其他对等端保持节拍同步。（拍数照常推进；只有小节线位置会被调整。）

类方法

MeterSync.new(clock, id, ports)

返回一个与特定时钟对象关联的新实例。

参数：

clock

此实例控制的时钟。

id

可选。一个整数，用于唯一标识此实例。如果未提供，将随机选择一个整数。

ports

可选。一个端口号数组，同步消息将被发送到这些端口。（sclang 实例通常使用端口 57120，但如果该端口已被占用，它们会依次尝试 57121 等。此处的默认值是尝试 57120-57127 中的全部端口。）

实例方法

.free

释放此实例，并禁用关联时钟的度量同步。

.resyncMeter(round, verbose: true)

调整时钟的小节线位置，以与网络上的其他 SuperCollider 对等端匹配。

参数：

round

可选。强制指定特定的细分：round = 1 假定四分音符作为度量基础；round = 0.5 假定八分音符（例如 5/8 拍）。如果未提供，将根据来自其他对等方传入的 beatsPerBar 值计算。

verbose

布尔值。如果为 false，则抑制信息消息。

返回值：

该实例。

.queryMeter(action, timeout: 0.2)

从其他对等方查询节拍信息，并收集结果。通常，你不需要调用此方法。它提供给你，以便在你想验证同步或实现自定义行为时使用。

参数：

action

在获得结果后要执行的函数。结果作为参数传递给此函数：一个包含以下内容的 Event 的 List：

  • id：远程对等方的 ID（整数）。
  • beats：应答时远程时钟的节拍数。
  • beatsPerBar：远端时钟的拍号。
  • baseBarBeat：远程时钟的节拍基准。
  • beatInBar：远程时钟在小节内的节拍位置。
  • queriedAtBeat：查询时钟的查询时间，以拍为单位。
  • syncMeter：布尔值。如果为 true，则远程时钟正在同步小节线。如果为 false，则远程时钟有一个应答的 MeterSync 对象，但它已被禁用。

timeout

Float。等待回复的秒数。（它将始终等待整个超时时间。LinkClock 知道它的 LinkClock: -numPeers，但只有 SuperCollider 对等端会回答查询，并且无法知道有多少对等端是 SuperCollider。）

返回值：

该实例。回复是异步的；使用 action 函数来响应。

.id

获取唯一标识此实例的整数 ID。该 ID 在初始化时设置（LinkClock: -enableMeterSync 或 *new）。要更改它，请释放当前实例并创建一个新实例。

.ports

获取将发送同步消息的端口数组。这些端口在初始化时设置（LinkClock: -enableMeterSync 或 *new）。要更改它们，请释放当前实例并创建一个新实例。

返回值：

一个整数端口号组成的数组。

.adjustMeterBase(localBeats, remoteBeats, round: 1)

一个便捷方法，在给定本地节拍位置和远程节拍位置的情况下调整时钟的 baseBarBeat。通常你不需要调用此方法。它适用于你自己分析 MeterSync: -queryMeter 结果并希望以自己的方式调整小节线的情况。

参数：

localBeats

本地时钟的拍数。通常这应源自 result[index][\queriedAtBeat]（其中 result 来自 MeterSync: -queryMeter）。强烈建议使用它而不是 clock.beats，因为查询时间不会加上超时时间。

remoteBeats

本地时钟的拍数。通常应从 result[index][\beats] 推导得出。

round

可选。强制指定细分：round = 1（默认值）假定四分音符为度量基准；round = 0.5 假定八分音符（例如 5/8 拍）。

返回值：

该实例。

// You *may* do something like this optionally,
// if something went wrong.
// Normally you should just call 'resyncMeter'
// and it's all done for you.

l = LinkClock.new.latency_(s.latency);
m = MeterSync(l);

(
m.queryMeter({ |result|
    result.postln;
    m.adjustMeterBase(result[0][\queriedAtBeat], result[0][\beatInBar]);
});
)

l.stop;  // 自动清理 'm'

.enabled

.enabled = bool

启用或禁用节拍器同步。如果禁用，此实例将不再响应来自对等节点的节拍器变更。它仍会响应 queryMeter，并在回复中包含 'syncMeter': false（因此你可以相应地过滤 queryMeter 的结果）。

参数：

bool

true = 启用，false = 禁用。

返回值：

Boolean.

.clock

.clock =

返回由该实例控制的时钟。

注意： 你无法更改关联的时钟对象。应改为 MeterSync: -free 此实例，并为另一个时钟创建新实例。

.repeats

.repeats = value

获取或设置 OSC 消息的重复次数。

UDP 不检测消息传递失败；因此消息可能会丢失。如果发生这种情况，LinkClock 对等体可能无法正确同步，且 -resyncMeter 可能无法恢复。为防止此问题，同步消息会发送 'repeats' 次。默认值为 4。

.delta

.delta = value

获取或设置 OSC 消息重复之间的秒数。

示例

l = LinkClock.new.latency_(s.latency).enableMeterSync;

// 如果节拍器失步，尝试重新同步：
l.getMeterSync.resyncMeter;

// 其他时钟的时基是什么？
l.getMeterSync.queryMeter({ |result|
    result.do { |row| row.postln };
});

// 我想要不同的 ID 和/或端口：先释放，再重建
l.disableMeterSync;
l.enableMeterSync(1000, (57120..57135));
