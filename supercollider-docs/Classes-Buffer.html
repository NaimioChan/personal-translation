Buffer

服务器上缓冲区的客户端表示

Object

另请参见：ExampleFiles

说明

Buffer 对象是服务器端缓冲区的客户端侧抽象。（SuperCollider 的服务器-客户端架构是使用 Buffer 对象时常见的困惑来源，因此请参阅 Client vs Server。）

缓冲区最常用于保存采样的音频，例如加载到内存中的声音文件，但也可以用于保存其他类型的数据。从技术上讲，服务器上的缓冲区是一个全局可用的、多声道 32 位浮点数数组。它还具有关联的采样率，以 64 位浮点数表示，单位为赫兹。

Buffer 类封装了大量与服务器端缓冲区相关的常见任务、OSC 消息和功能——请参阅本文档后面的示例，了解使用 Buffer 进行声音播放和录音的许多示例。

缓冲区通常与 PlayBuf、RecordBuf、DiskIn、DiskOut、BufWr、BufRd 以及其他 UGen 一起使用。（更多示例请参见它们各自的帮助文件。）即使正在被访问，缓冲区也可以被释放或修改。一些技术细节请参见 服务器架构。

不应在 SynthDef 中创建或修改缓冲区对象。如有需要，参见 LocalBuf。

缓冲区编号与分配

尽管服务器上的缓冲区数量在服务器启动时设定，但在它们能够保存值之前，仍必须在服务器应用内部分配内存。（启动时所有缓冲区的大小均为 0。）

Server 端缓冲区通过编号标识，从 0 开始。使用 Buffer 对象时，缓冲区编号会从 Server 的 bufferAllocator 自动分配。当你在 Buffer 对象上调用 .free 时，它会释放服务器上该缓冲区的内存，并释放缓冲区编号以供将来重新分配。有关设置可用缓冲区数量的详细信息，请参见 ServerOptions。

通常你不需要提供缓冲区编号（参见 Buffer: *alloc）。只有在你确信自己清楚在做什么时才应该这样做。同样，在正常使用中你也不需要访问缓冲区编号，因为 Buffer 的实例可以直接用作 UGen 输入或 Synth 参数。

多通道缓冲区

多声道缓冲区会交错存储其数据。因此，使用诸如 set, setn, get, getn 等方法按索引请求或设置值时，实际可用的值数量等于 numFrames * numChannels。索引从 0 开始，一直到 (numFrames * numChannels) - 1。例如，在两声道缓冲区中，索引 0 将是第一个声道的第一个值，索引 1 将是第二个声道的第一个值，索引 2 将是第一个声道的第二个值，依此类推。

在某些情况下，使用多个单声道缓冲区比使用单个多声道缓冲区更简单。

完成消息与动作函数

许多缓冲区操作（例如读取和写入文件）是异步的，这意味着它们将花费任意长的时间来完成。异步命令被传递给服务器上的后台线程，以免占用音频合成线程的 CPU 时间。由于它们可能持续任意长的时间，因此能够指定在完成时立即执行的其它操作会很方便。Buffer 的各种方法以两种方式实现了这一能力：完成消息和动作函数。

完成消息是包含在发送给服务器的消息中的第二条 OSC 命令。（关于 OSC 消息的讨论见 Node Messaging。）服务器在完成第一条命令后会立即执行它。动作函数是一个 Function，当客户端收到服务器发来的相应回复、表明前一条命令已完成时，它会被求值。因此，动作函数本质上比完成消息更灵活，但由于消息传递会带来少量额外延迟，效率略低。动作函数在被求值时会将 Buffer 对象作为参数传入。

对于带有完成消息的 Buffer 方法，也可以传入一个返回 OSC 消息的函数。与 action 函数一样，该函数会将 Buffer 作为参数传入。然而重要的是要理解，该函数将在 Buffer 对象创建之后（以便其 bufnum 和其他细节可访问），但在相应消息发送到服务器之前被求值。

Bundling

下面的许多方法有两个版本：常规版本会立即将对应消息发送到服务器，另一个版本则将消息返回为 Array，以便加入 bundle。也可以利用 Server 的自动打包功能捕获常规方法生成的消息。详情请参阅 Server 和 Bundled Server Messages。

服务器消息数据类型

服务器要求 numFrames、numChannels 以及 get/set 索引参数为整数。为方便起见，用于构造服务器消息的 Buffer 方法（方法名以 'Msg' 结尾）会将这些参数的浮点数转换为整数。手动构造消息的用户应注意这些数据类型。

类方法

使用立即内存分配创建

Buffer.alloc(server, numFrames, numChannels: 1, completionMessage, bufnum, sampleRate)

创建一个 Buffer 并返回，同时在服务器上立即分配所需的内存。缓冲区的值将被初始化为 0.0。

参数：

server

用于分配缓冲区的服务器。默认为默认服务器。

numFrames

要分配的帧数。实际内存使用量将对应于 numFrames * numChannels。（浮点值会被截断为整数。）

numChannels

Buffer 的通道数。默认值为 1。（浮点值会被截断为整数。）

completionMessage

一个有效的 OSC 消息或一个将返回该消息的 Function。当求值时，此 Buffer 将作为参数传递给 Function。

bufnum

一个显式指定的缓冲区编号。提供编号会绕过服务器的缓冲区分配器，这可能导致冲突。最佳实践是不设置此项，让缓冲区编号分配器选择下一个可用的 bufnum。

sampleRate

缓冲区的采样率。默认值为服务器的采样率。0 或 nil 将重置为服务器的采样率。

讨论：

// 分配 8 秒立体声缓冲区
s.boot;
b = Buffer.alloc(s, s.sampleRate * 8.0, 2);
b.free;

Buffer.allocConsecutive(numBufs: 1, server, numFrames, numChannels: 1, completionMessage, bufnum, sampleRate)

分配一段连续编号的缓冲区范围，供像 VOsc 和 VOsc3 这样需要连续缓冲区块的 UGen 使用，并返回相应 Buffer 对象的数组。

参数：

numBufs

要分配的连续索引缓冲区的数量。

server

用于分配缓冲区的服务器。默认为默认服务器。

numFrames

每个缓冲区中要分配的帧数。实际内存使用量将对应于 numFrames * numChannels。（浮点值会被截断为整数。）

numChannels

每个缓冲区的通道数。默认为 1。（浮点值会被截断为整数。）

completionMessage

一个有效的 OSC 消息，或一个将返回该消息的 Function。求值时，将把每个 Buffer 及其在数组中的索引作为参数传递给 Function。

bufnum

一个显式指定的缓冲区编号。提供编号会绕过服务器的缓冲区分配器，这可能导致冲突。最佳实践是不设置此项，让缓冲区编号分配器选择下一个可用的 bufnum。

sampleRate

缓冲区的采样率。默认为服务器的采样率。

讨论：

注意：你必须将 Buffers 数组当作一个组来处理。单独释放它们或重用它们可能会导致分配错误。你应该用 do 遍历该数组，一次性释放数组中的所有 Buffers。

s.boot;
// 分配一个 Buffer 数组并用不同的谐波填充它们
(
b = Buffer.allocConsecutive(8, s, 4096, 1, { |buf, i|
    buf.sine1Msg((1 .. ((i + 1) * 6)).reciprocal) // 完成消息
});

a = { VOsc.ar(SinOsc.kr(0.5, 0).range(b.first.bufnum + 0.1, b.last.bufnum - 0.1),
    [440, 441], 0, 0.2) }.play;
)
a.free;

// 遍历该数组并释放它
b.do(_.free);

Buffer.read(server, path, startFrame: 0, numFrames: -1, action, bufnum)

分配一个缓冲区并立即将声音文件读入其中。此方法会发送一条查询消息作为完成消息，以便 Buffer 的实例变量自动更新。

参数：

server

用于分配缓冲区的服务器。

path

一个 String，表示要读取的声音文件的路径。

startFrame

要读取的声音文件的第一帧。默认值为 0，即文件的开头。

numFrames

要读取的帧数。默认值为 -1，将读取整个文件。

action

一个 Function，在文件读取完成且此 Buffer 的实例变量已更新后求值。该函数将把此 Buffer 作为参数传入。

bufnum

一个显式指定的缓冲区编号。提供编号会绕过服务器的缓冲区分配器，这可能导致冲突。最佳实践是不设置此项，让缓冲区编号分配器选择下一个可用的 bufnum。

讨论：

注意：不能指望缓冲区的实例变量会立即更新，因为其中涉及少量延迟。收到查询回复时会求值 action，因此在需要访问实例变量的情况下请使用它。

// 从磁盘读取声音文件到缓冲区
s.boot;
// ExampleFiles 帮助定位示例中使用的音频文件
p = ExampleFiles.child;
// 查看路径以了解位置和路径的格式
p.postln;
// 读取文件
b = Buffer.read(s, p);

// 现在播放它
(
x = SynthDef(\help_Buffer, { |out = 0, bufnum|
    Out.ar(out,
        PlayBuf.ar(1, bufnum, BufRateScale.kr(bufnum))
    )
}).play(s, [\bufnum, b]);
)
x.free; b.free;

// 带有一个 action 函数
// 注意这些变量不会立即更新
(
b = Buffer.read(s, p, action: { |buffer|
    ("After update:" + buffer.numFrames).postln;
    x = { PlayBuf.ar(1, buffer, BufRateScale.kr(buffer)) }.play;
});
("Before update:" + b.numFrames).postln;
)
x.free; b.free;

Buffer.readChannel(server, path, startFrame: 0, numFrames: -1, channels, action, bufnum)

与上面的 *read 相同，但接受一个要读取的通道索引 Array，从而只读取选定的通道。

参数：

用于分配缓冲区的服务器。

path

一个 String，表示要读取的声音文件的路径。

startFrame

要读取的声音文件的第一帧。默认值为 0，即文件的开头。

numFrames

要读取的帧数。默认值为 -1，将读取整个文件。

channels

要从声音文件中读取的声道数组。索引从零开始。这些声道将按提供的顺序读取。

action

一个 Function，在文件读取完成且此 Buffer 的实例变量已更新后求值。该函数将把此 Buffer 作为参数传入。

bufnum

一个显式指定的缓冲区编号。提供编号会绕过服务器的缓冲区分配器，这可能导致冲突。最佳实践是不设置此项，让缓冲区编号分配器选择下一个可用的 bufnum。

讨论：

s.boot;
// 首先进行一次标准读取，以便我们查看文件中的内容
b = Buffer.read(s, ExampleFiles.sinedPink);
// ExampleFiles.sinedPink 包含左侧的 SinOsc 和右侧的 PinkNoise
b.plot;
b.free;

// 现在只保留正弦波
b = Buffer.readChannel(s, ExampleFiles.sinedPink, channels: [0]);
b.plot;
b.free;

// 现在只保留粉红噪声
b = Buffer.readChannel(s, ExampleFiles.sinedPink, channels: [1]);
b.plot;
b.free;

// 现在反转通道顺序
b = Buffer.readChannel(s, ExampleFiles.sinedPink, channels: [1, 0]);
b.plot;
b.free;

Buffer.readNoUpdate(server, path, startFrame: 0, numFrames: -1, bufnum, completionMessage)

与上面的 *read 相同，但不会自动更新实例变量。调用 updateInfo（见下文）来更新这些变量。

参数：

server

用于分配缓冲区的服务器。

path

一个 String，表示要读取的声音文件的路径。

startFrame

要读取的声音文件的第一帧。默认值为 0，即文件的开头。

numFrames

要读取的帧数。默认值为 -1，将读取整个文件。

bufnum

一个显式指定的缓冲区编号。提供编号会绕过服务器的缓冲区分配器，这可能导致冲突。最佳实践是不设置此项，让缓冲区编号分配器选择下一个可用的 bufnum。

completionMessage

一个有效的 OSC 消息或一个将返回该消息的 Function。当求值时，此 Buffer 将作为参数传递给 Function。

讨论：

// 带有完成消息
s.boot;
(
SynthDef(\help_Buffer, { |out = 0, bufnum|
    Out.ar(out,
        PlayBuf.ar(1, bufnum, BufRateScale.kr(bufnum))
    )
}).add;

y = Synth.basicNew(\help_Buffer); // 尚未发送
b = Buffer.readNoUpdate(s, ExampleFiles.child,
    completionMessage: { |buffer|
        // synth 将其 s_new 消息添加为
        // 在缓冲区读取完成后跟随
        y.newMsg(s, [\bufnum, buffer], \addToTail)
    });
)
// 音符变量不准确
b.numFrames; // nil
b.updateInfo;
b.numFrames; // 188893
// 完成后……
y.free;
b.free;

Buffer.cueSoundFile(server, path, startFrame: 0, numChannels: 2, bufferSize: 32768, completionMessage)

分配一个缓冲区并预加载声音文件，以便使用 DiskIn 进行流式播放。

参数：

server

用于分配缓冲区的服务器。

path

一个 String，表示要读取的声音文件的路径。

startFrame

DiskIn 开始播放时声音文件的帧位置。

numChannels

声音文件中的通道数。

bufferSize

这必须是（2 * 服务器块大小）的倍数。32768 是默认值，适用于大多数情况。

completionMessage

一个有效的 OSC 消息或一个将返回该消息的 Function。当求值时，此 Buffer 将作为参数传递给 Function。

讨论：

s.boot;
(
SynthDef(\help_Buffer_cue, { |out = 0, bufnum|
    Out.ar(out,
        DiskIn.ar(1, bufnum)
    )
}).add;
)

(
s.makeBundle(nil, {
    b = Buffer.cueSoundFile(s, ExampleFiles.child, 0, 1);
    y = Synth(\help_Buffer_cue, [\bufnum, b], s);
});
)
b.free; y.free;

Buffer.loadCollection(server, collection, numChannels: 1, action)

将大型集合加载到服务器上的缓冲区中。返回一个 Buffer 对象。

参数：

server

用于创建缓冲区的服务器。

collection

Collection 的一个子类（即 Array），仅包含浮点数和整数。多维数组将无法使用。

numChannels

缓冲区应具有的通道数。注意，缓冲区会对多通道数据进行交织。如有需要，你需自行提供交织后的集合。多维数组不可用。

action

一个 Function，在文件读取完成且此 Buffer 的实例变量已更新后求值。该函数将把此 Buffer 作为参数传入。

讨论：

这是通过将集合写入 SoundFile 并从那里加载来实现的。因此，此方法仅适用于本地机器上的服务器。对于远程服务器，请使用下面的 sendCollection。文件在加载后会自动删除。这允许比下面的 setn 更大的集合，并且通常是将大型集合放入缓冲区的最安全方式。缓冲区的采样率将是在其上创建它的服务器的采样率。

s.boot;
(
a = FloatArray.fill(44100 * 5.0, { 1.0.rand2 }); // 5 秒的噪声
b = Buffer.loadCollection(s, a);
)

// test it
b.get(20000, { |msg| (msg == a[20000]).postln });

// play it
x = { PlayBuf.ar(1, b, BufRateScale.kr(b), loop: 0) * 0.5 }.play;
b.free; x.free;

// 交错一个多维数组
(
l = Signal.sineFill(16384, Array.fill(200, { 0 }).add(1));
r = Array.fill(16384, { 1.0.rand2 });
m = [Array.newFrom(l), r]; // 一个多维数组
m = m.lace(32768); // 交错两个集合
b = Buffer.loadCollection(s, m, 2, { |buf|
    x = { PlayBuf.ar(2, buf, BufRateScale.kr(buf), loop: 1) * 0.5 }.play;
});
)
b.plot;
x.free; b.free;

Buffer.sendCollection(server, collection, numChannels: 1, wait: -1, action)

使用多个 setn 消息将一个大集合流入服务器上的缓冲区。返回一个 Buffer 对象。

参数：

server

用于创建缓冲区的服务器。

collection

Collection 的一个子类（即 Array），仅包含浮点数和整数。多维数组将无法使用。

numChannels

缓冲区应具有的通道数。请注意，缓冲区会交错存储多通道数据。如有需要，你有责任提供一个交错集合。多维数组将无法使用。请参阅上方 *loadCollection 中的示例，了解如何操作。

wait

发送 setn 消息之间的可选等待时间。在高流量情况下，将其设置为大于零的值可能更安全，零是默认值。

action

一个 Function，在文件读取完成且此 Buffer 的实例变量已更新后求值。该函数将把此 Buffer 作为参数传入。

讨论：

这允许使用比下面介绍的 setn 更大的集合。这不如上面的 *loadCollection 安全，但可以用于远程机器上的服务器。缓冲区的采样率将是创建它的服务器的采样率。

s.boot;
(
a = Array.fill(2000000, { rrand(0.0, 1.0) }); // 一个大型集合
b = Buffer.sendCollection(s, a, 1, 0, { |buf| "finished".postln });
)
b.get(1999999, { |msg| (msg == a[1999999]).postln });
b.free;

不进行立即内存分配的创建

Buffer.new(server, numFrames, numChannels, bufnum, sampleRate)

创建一个新的 Buffer 对象并返回它，而不会立即在服务器上分配相应的内存。将此与 'message' 方法结合使用，可以灵活地处理 bundle。

参数：

server

用于分配缓冲区的服务器。默认为默认服务器。

numFrames

要分配的帧数。实际内存使用量将对应于 numFrames * numChannels。

numChannels

Buffer 的声道数。默认值为 1。

bufnum

一个显式指定的缓冲区编号。提供编号会绕过服务器的缓冲区分配器，这可能导致冲突。最佳实践是不设置此项，让缓冲区编号分配器选择下一个可用的 bufnum。

sampleRate

缓冲区的采样率。默认为服务器的采样率。

讨论：

s.boot;
b = Buffer.new(s, 44100 * 8.0, 2);
c = Buffer.new(s, 44100 * 4.0, 2);
b.query; // numFrames = 0
s.sendBundle(nil, b.allocMsg, c.allocMsg); // 同时发送两者
b.query; // 现在正确了
c.query;
b.free; c.free;

已缓存的缓冲区

为协助缓冲区信息的自动更新（参见 updateInfo 和 read），缓冲区对象被缓存在与承载这些缓冲区的 Server 对象关联的集合中。释放缓冲区会将其从缓存中移除；退出服务器会清除所有缓存的缓冲区。（如果服务器意外崩溃，也会发生这种情况。）

你可以使用以下方法访问缓存的缓冲区。

通过服务器对象访问它们可能更简单：

myServer.cachedBufferAt(bufnum)
myServer.cachedBuffersDo(func)

b = Buffer.alloc(s, 2048, 1);
Buffer.cachedBufferAt(s, 0);    // 假设 b 的 bufnum 为 0
s.cachedBufferAt(0);            // 相同结果
s.cachedBuffersDo({ |buf| buf.postln });

Buffer.cachedBufferAt(server, bufnum)

通过编号访问缓冲区。

Buffer.cachedBuffersDo(server, func)

遍历所有已缓存的缓冲区。遍历不按任何顺序进行，但会触及所有缓冲区。

讨论：

注意，多声道缓冲区会交错存储其采样数据，因此实际可用的值数量等于 numFrames * numChannels。如有需要，你负责将 values 中的数据交错排列。多维数组将无法使用。索引从 0 开始。

s.boot;
b = Buffer.alloc(s, 16);
b.setn(0, Array.fill(16, { rrand(0, 1) }));
b.getn(0, b.numFrames, { |msg| msg.postln });
b.setn(0, [1, 2, 3], 4, [1, 2, 3]);
b.getn(0, b.numFrames, { |msg| msg.postln });
b.free;

.loadCollection(collection, startFrame: 0, action)

将大型集合加载到此缓冲区中。这是通过将集合写入 SoundFile 并从那里加载来完成的。因此，此方法仅适用于你本地机器上的服务器。对于远程服务器，请使用下面的 sendCollection。加载后文件会自动删除。

参数：

collection

Collection 的一个子类（即 Array），仅包含浮点数和整数。多维数组将无法使用。

startFrame

开始加载集合的帧索引。默认值为 0，即缓冲区的起始位置。

action

一个 Function，在文件读取完成且此 Buffer 的实例变量已更新后求值。该函数将把此 Buffer 作为参数传入。

讨论：

这允许比上面的 setn 更大的集合，并且通常是将大集合放入缓冲区的最安全方式。缓冲区的采样率将是创建它的服务器的采样率。通道数和帧数将在分配缓冲区时确定。你有责任确保集合的大小不大于 numFrames，并在需要时对任何数据进行交错。

s.boot;
(
v = Signal.sineFill(128, 1.0 / [1, 2, 3, 4, 5, 6]);
b = Buffer.alloc(s, 128);
)
(
b.loadCollection(v, action: { |buf|
    x = { PlayBuf.ar(buf.numChannels, buf, BufRateScale.kr(buf), loop: 1)
        * 0.2 }.play;
});
)
x.free; b.free;

// 交错一个多维数组
(
l = Signal.sineFill(16384, Array.fill(200, { 0 }).add(1));
r = Array.fill(16384, { 1.0.rand2 });
m = [Array.newFrom(l), r]; // 一个多维数组
m = m.lace(32768); // 交错两个集合
b = Buffer.alloc(s, 16384, 2);
)
(
b.loadCollection(m, 0, { |buf|
    x = { PlayBuf.ar(2, buf, BufRateScale.kr(buf), loop: 1) * 0.5 }.play;
});
)
b.plot;
x.free; b.free;

使用一系列 getn 消息将缓冲区流式传输到客户端，并将结果放入 FloatArray。

开始写入时在缓冲区中的索引。默认为 0。（浮点值会被截断为整数。）

要获取的值的数量。默认值为 -1，表示从 index 获取到缓冲区末尾。（浮点值会被截断为整数。）

发送 getn 消息之间等待的时间量，以秒为单位。较长的等待时间更安全。默认值为 0.01 秒，在正常情况下似乎可靠。不建议设置为 0。

一个 Function，会将得到的 FloatArray 作为参数传入，并在收到所有回复后求值。

讨论：

这比 loadToFloatArray 风险更大，但确实可用于远程机器上的服务器。在高流量情况下，数据可能会丢失。如果该方法在超时前未收到其全部回复，它将发布一条警告，说明该方法已失败。一般来说，应尽可能改用 loadToFloatArray。

s.boot;
b = Buffer.read(s, ExampleFiles.child);
// 类似 Buffer.plot
b.getToFloatArray(wait: 0.01, action: { |array { array.plot }.defer; "done".postln });

从索引 srcStartAt 开始，从本缓冲区复制 numSamples 个样本到目标缓冲区 buf 中从 dstStartAt 开始的位置。如果 numSamples 为负，则复制尽可能多的样本。默认从源中的 0 开始，并从目标中的 0 开始复制尽可能多的样本。（srcStartAt、numSamples 和 dstStartAt 的浮点值会被截断为整数。）

讨论：

注意：此方法过去称为 copy，但这与用于对象复制的方法冲突。因此 Buffer:copy 现在旨在创建客户端侧 Buffer 对象的副本。将其用于在服务器上复制缓冲区数据的用法已弃用。如果你看到弃用警告，数据仍会在服务器上被复制，你的代码仍可正常工作，但你应更新代码以使用新的方法名。

s.boot;
(
SynthDef(\help_Buffer_copy, { |out = 0, buf|
    Line.ar(0, 0, dur: BufDur.kr(buf), doneAction: Done.freeSelf);
    Out.ar(out, PlayBuf.ar(1, buf));
}).add;
)

(
b = Buffer.read(s, ExampleFiles.child);
c = Buffer.alloc(s, 120000);
)

Synth(\help_Buffer_copy, [\buf, b]);

// 复制整个缓冲区
b.copyData(c);
Synth(\help_Buffer_copy, [\buf, c]);

// 复制一些样本
c.zero;
b.copyData(c, numSamples: 4410);
Synth(\help_Buffer_copy, [\buf, c]);

// 缓冲区 "compositing"
c.zero;
b.copyData(c, numSamples: 4410);
b.copyData(c, dstStartAt: 4410, numSamples: 15500);
Synth(\help_Buffer_copy, [\buf, c]);

b.free;
c.free;

.query(action)

向服务器发送 \b_query 消息，服务器会返回以下内容：OSC 地址模式（/b_info）、服务器端缓冲区表示的 bufnum、numFrames、numChannels 和 sampleRate。这些值会按顺序传给 action 函数，默认情况下为：

action: { |oscAddrPattern, bufnum, numFrames, numChannels, sampleRate|
    postf("bufnum: %\nnumFrames: %\nnumChannels: %\nsampleRate: %\n",
        bufnum, numFrames, numChannels, sampleRate
    );
}

它会发布缓冲区的属性。

警告： 调用 query 将更新 Buffer 实例变量 numFrames、numChannels 和 sampleRate。这是存储在 serverCaches 中缓冲条目里的 OSC 响应器动作的副作用。

参数：

action

一个可选的 Function，会以上面列出的缓冲区属性作为参数被调用，替代默认的 action。

.updateInfo(action)

向服务器发送 b_query 消息，请求该缓冲区的描述。收到回复后，该 Buffer 的实例变量会自动更新。

参数：

action

一个 Function，在文件读取完成且此 Buffer 的实例变量已更新后求值。该函数将把此 Buffer 作为参数传入。

讨论：

s.boot;
b = Buffer.readNoUpdate(s, ExampleFiles.child);
b.numFrames; // 显示 nil
b.updateInfo({ |buf| buf.numFrames.postln }); // 现在已更新
b.free;

一个包含各分音振幅的数组。其项数应与 freqs 相同。

.cheby(amps, normalize: true, asWavetable: true, clearFirst: true)

.chebyMsg(amps, normalize: true, asWavetable: true, clearFirst: true)

用一系列 Chebyshev 多项式填充此缓冲区，其定义如下：cheby(n) = amplitude * cos(n * acos(x))。为消除用作波形整形器时的直流偏移，波表会进行偏移，使中心值为零。

类似的功能可在 Signal.chebyFill 和 Wavetable.chebyFill 中找到。如果你需要不包含偏移补偿的 Chebyshev 多项式，建议使用其中之一。

参数：

amps

一个包含各次谐波幅度的数组。第一个浮点值指定 n = 1 的幅度，第二个浮点值指定 n = 2 的幅度，依此类推。

normalize

一个 Boolean，指示是否将缓冲区归一化到峰值为 1.0。默认为 true。

asWavetable

一个布尔值，指示是否以波表格式写入缓冲区，以便可以通过插值振荡器读取。默认为 true。

clearFirst

一个 Boolean，指示写入前是否清空缓冲区。默认为 true。

讨论：

注意： 在之前的版本中，偏移处理（以确保中心值为零）的执行方式不正确。此问题已在 3.7 版本中修复，因此任何可能依赖（错误）行为的代码都可能需要修改。如果将 Chebyshev 缓冲区用作波形整形器，最简单的修复方法是将 Shaper 包装在 LeakDC UGen 中。

s.boot;
b = Buffer.alloc(s, 512, 1, { |buf| buf.chebyMsg([1, 0, 1, 1, 0, 1]) });
(
x = {
    Shaper.ar(
        b,
        SinOsc.ar(300, 0, Line.kr(0, 1, 6)),
        0.5
    )
}.play;
)
x.free; b.free;
