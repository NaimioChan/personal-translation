向后兼容性

提高与 SC2 代码向后兼容性的类和方法

有一些类和方法的添加是为了兼容 SC2 代码。其中最值得注意的是 Synth.play，它基本上是 Function.play 的封装。

{ SinOsc.ar(440, 0, 0.5) }.play; // 创建一个任意命名的 SynthDef 以及一个用于演奏它的 Synth
Synth.play({ SinOsc.ar(440, 0, 0.5) }); // 在 SC3 中只是 Function.play 的包装，参数更少

这两者都会在默认服务器上创建 synth 节点。请注意，两者都不需要使用 Out.ar UGen；它们只是输出到第一个音频总线。不过，可以向 Function.play 添加一个 Out 来指定输出。

Synth.play({ Out.ar(1, SinOsc.ar(440, 0, 0.5)) });

通常，在使用这段代码时应当注意这一区别。当复制此类代码以便与其他 SC3 类一起复用（例如在可复用的 SynthDef 中）时，通常需要添加一个 Out.ar。尽管这些方法在快速测试时很有用，但通常不如 SynthDef.play，因为后者更直接、无需修改即可通用复用、具有更大的通用灵活性，且开销略低。（虽然在大多数情况下这一点微不足道，但在创建大量 def 或节点时可能就有影响。）

与 SynthDef.play 类似，Function.play 返回一个 Synth 对象，之后可以对其发送消息等。然而，由于 Function.play 创建的是一个名称任意的 SynthDef，因此无法复用生成的 def，至少在不从 post 窗口读取其名称、或从 Synth 对象获取其名称的情况下无法复用。

//以下示例在功能上是等价的
x = { arg freq = 440; Out.ar(1, SinOsc.ar(freq, 0, 0.5)) }.play(fadeTime: 0);
x.set(\freq, 880);        // 你可以设置参数
y = Synth.new(x.defName);    // 从 x 获取任意 defname
x.free;
y.free;

x = SynthDef("backcompat-sine", { arg freq = 440; Out.ar(1, SinOsc.ar(freq, 0, 0.5)) }).play;
x.set(\freq, 880);
y = Synth.new("backcompat-sine");
x.free;
y.free;

Function.play 总体上优于其在 SC2 中的对应方法以及 Synth.play。它具有许多重要特性，例如能够以参数形式指定输出总线和淡入淡出时间。请参阅 Function 帮助文件以获取更深入的讨论。
