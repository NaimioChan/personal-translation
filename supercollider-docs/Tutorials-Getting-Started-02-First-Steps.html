Hello World, I'm SuperCollider

在学习一门新的编程语言时，传统上会从一个名为“Hello World”的简单程序开始。这不过就是让程序把文本“Hello World!”打印到……嗯，打印到任何它打印文本的地方。在 SC 中，那是一个叫做 post window 的地方。post window 就是你第一次启动 SC 时打开的那个窗口，里面会打印出一堆东西，看起来像这样：

init_OSC
compiling class library..
    NumPrimitives = 587
    compiling dir: '/Applications/SC3/SCClassLibrary'
    pass 1 done
    Method Table Size 3764776 bytes
    Number of Method Selectors 3184
    Number of Classes 1814
    Number of Symbols 7595
    Byte Code Size 180973
    compiled 296 files in 1.34 seconds
compile done
RESULT = 256
Class tree inited in 0.14 seconds

现在不必太在意这一切意味着什么，只需记住这是 SC 向你发送信息的地方。这也是我们获取 Hello World 程序结果的地方，你可以在下面看到：

"Hello World!".postln;

要执行它，只需点击将光标放在代码同一行的某个位置，然后按 Shift-Enter（macOS 上为 Shift-Return）。现在试试看。

如果一切顺利，你应该会在 post 窗口中看到这些内容。

Hello World!
-> Hello World!

或者，你也可以先选中要执行的代码（点击并拖动文本直到其高亮），然后按 Ctrl-Enter（macOS 上为 Cmd-Return）。现在试一试。

现在让我们更仔细地看看这段代码。第一部分 "Hello World!" 是一种 Object，称为 String。对象基本上只是在计算机中表示某种事物的一种方式，例如一段文本或一个振荡器，它允许你控制它并向它发送消息。关于这一点稍后再详述，现在只需理解 String 是表示一段文本的一种方式。

第二部分 .postln; 表示“将我（或关于我的有意义的描述）打印到 post 窗口。”记住 postln，它是你的朋友。你几乎可以对 SC 中的任何东西应用它，并得到有意义的结果。这在追踪代码中的 bug 时非常方便。

为什么打印了两次？嗯，当你在 SC 中执行代码时，它总是会打印最后一段代码（最后一条语句）的结果。所以它首先打印是因为我们明确让它打印，然后它打印这个操作的结果，而在这种情况下结果恰好相同。

所以在当前这个例子中，我们其实并不需要 postln 部分。但在下面的例子中我们就需要了。通过点击并拖动选中两行文本，然后执行，即按 Ctrl-Enter（macOS 上为 Cmd-Return）。

"Hello there, I'm SuperCollider!".postln;
"Hello World!".postln;

如果没有显式的 postln，第一行 'Hello there, I'm SuperCollider!' 就不会被打印出来。

一般来说，当你需要同时执行多行代码时，它们会被括号包围，如下面的示例所示。你可以将光标放在该区域内的任意位置（在 macOS 上或放在括号所在行），然后双击并按 Ctrl-Enter 或 Shift-Enter（在 macOS 上为 Cmd-Return 或 Shift-Return）——这会选中整个区域并执行它。请在下面的示例中试一试。

(
"Call me,".postln;
"Ishmael.".postln;
)

在所有系统中，双击一对包围的括号内部可能无法选中整个区域，尤其是在现代 Mac 上并非如此。在某些系统上，它可能只会选中双击的那个词。因此，养成坚持使用某种特定技巧的习惯可能更好。例如，无论使用哪种选择技巧，始终先检查是否已选中所有预期代码，然后再按 Ctrl-Enter 或 Shift-Enter（macOS 上为 Cmd-Return 或 Shift-Enter）。然后坚持使用最适合你的技巧。尝试此操作以了解你的系统的行为。

当代码没有被括号包围时，通常意图是逐行执行。你可以将光标放在代码行的任意位置，然后按 Ctrl-Enter 或 Shift-Enter（macOS 上为 Cmd-Return 或 Shift-Return）——这会选中整行并执行它。

请注意，代码块中的每一行都以分号结尾。这在执行多行代码时非常重要。试试执行以下几乎完全相同代码的变体，看看会发生什么。

(
"Call me?".postln
"Ishmael.".postln;
)

执行上面的代码会导致“Parse Error（解析错误）”。出现这类错误时，错误信息中的点会标示出 SC 遇到问题的地方。这里问题就发生在 "Ishmael." 之后。

ERROR: syntax error, unexpected STRING, expecting DOTDOT or ':' or ',' or ')'
in interpreted text
line 3 char 10:

"Ishmael.".postln;
^^^^^^^^^
)

通常问题实际上发生在稍早一点的地方，所以那才是你应该查看的地方。在本例中，是上一行末尾缺少分号。请注意，每行代码通常以分号结尾。这就是在 SC 中分隔代码行的方式。由于两行之间没有分号，我们才得到了错误。

另请注意，在最后一段代码的末尾多写一个分号并无妨碍，SC 出于方便考虑也容忍这种做法。

关于 post 窗口还有几点补充。能够看到它非常有用，但有时它可能会被其他窗口遮挡。你可以随时按 Cmd-\ 将其带到前面。

其他时候，后窗会充满文本且难以阅读。你可以随时按 Ctrl-Shift-P（macOS 上为 Cmd-Shift-P）来清空它。

SuperCollider 眼中的世界

SuperCollider 实际上由三个程序组成：

  • 你正在查看的文本编辑器（也称为 IDE 或集成开发环境），
  • 语言（sclang 或 "client" 应用），
  • 以及服务器，它执行实际的合成与音频计算。

sclang 部分是一门成熟的编程语言，具有构建 GUI（图形用户界面）的优秀特性；服务器部分则是一个精简、高效、轻量的 UNIX 命令行应用（意味着它运行时没有任何 GUI 表示）。

它们通过一种叫做 OSC（Open Sound Control）的协议进行通信，传输层可使用 UDP（User Datagram Protocol）或 TCP（Transmission Control Protocol），这两种网络协议也用于互联网。由于客户端和服务器以这种方式通信，更高级的项目可能出于性能考虑将它们运行在不同的计算机上。事实上，它们甚至可能运行在世界不同的地方！然而，这两个应用程序使用常见互联网协议进行通信，并不意味着它们必须连接到互联网或位于不同的计算机上。大多数情况下，它们会运行在同一台计算机上，而“网络”方面对你来说相对透明。尤其是在你刚开始学习的时候。

你只能通过网络使用 OSC 消息与服务器通信，但幸运的是，语言应用拥有许多强大的对象，它们代表服务器上的各种事物，并让你能够轻松而优雅地控制它们。理解其确切工作方式对于在 SC 中高效工作至关重要，因此我们将对此进行一定深度的讨论。

但首先让我们找点乐子，发出一些声音！

建议练习

按 Ctrl-N（macOS 上为 Cmd-N）打开新标签页或窗口，或从 File 菜单中选择“New”。为文档指定一个名称（如“My first SC code.scd”）并保存。注意，包含 SC 代码的文件应始终使用扩展名“.scd”。使用 Ctrl-C 和 Ctrl-V（macOS 上为 Cmd-C 和 Cmd-V）将上面的部分代码示例复制并粘贴到新文档中，或使用 Edit 菜单中的复制和粘贴项。

SC 允许你编辑帮助文件和文档，因此最好在修改前先复制文本，以免意外保存了被改动的帮助文件！
