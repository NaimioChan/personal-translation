Quant

封装与 EventStreamPlayer 和 TempoClock 相关的量化问题

Object

说明

表示 Routine、Task 和 Pattern 的标准调度模型。Quant 对象存储用于计算 Routine/Task/Pattern 在指定 TempoClock 上开始播放的精确时间所需的参数。

标准调度模型使用 quant 和 phase 来确定开始时间。它们以 TempoClock 的 baseBarBeat 为参照进行求值，该值通常为零，但当你使用时钟的 setMeterAtBeat 方法改变时钟的拍号时会更新。因此，即使在拍号改变之后，调度仍然有意义。有关其时间表示的详细信息，请参阅 TempoClock 帮助文件。

类方法

Quant.new(quant: 0, phase, timingOffset)

显式创建一个 Quant 实例，该实例可以被使用和复用。phase 和 offset 可以为 nil，此时它们被视为 0。如果 quant 为 nil，则会在当前时间精确调度。

未文档化的类方法

Quant.default

Quant.default = quant

实例方法

.quant

.quant = value

量化粒度。例程将在 baseBarBeat 之后的该数字的下一个整数倍处开始。若为负值，则表示要在未来安排的小节数（小节长度取自时钟的 beatsPerBar 变量）。

.phase

.phase = value

一个偏移量，用于将调度时间推入小节中间。+1 表示晚一拍，-1 表示早一拍。负的相位是合法的，但它可能导致调度时间晚于当前时间，这种情况下调度将不正确。你需要自行考虑这一点。

.timingOffset

.timingOffset = value

仅用于模式——这使得模式可以在时钟上略微提前于其发声时间运行，从而让你控制线程的执行顺序。

未文档化的实例方法

.asQuant

.nextTimeOnGrid(clock, referenceBeat)

示例

quant = 1

调度到下一个整拍

quant = 4, phase = -1

到下一个 4/4 小节线的一拍弱起

假设时钟的拍号为 3/4，持续 3 小节（从 0 开始）。那么：

quant = 3, phase = 1

将安排在 1、4 或 7 拍

在此期间，执行 clock.setMeterAtBeat(4, 9)。然后：

quant = 4, phase = 0

将安排在 9、13、17、21 等拍上

每个时间点都可以通过这种方式被精确识别，并且可以很容易地关联回西方的节拍或拍号概念。

自动实例化

某些对象在与 Routine: -play、Task: -play 或 Pattern: -play 一起使用时，会将自身转换为 Quant 对象。

SimpleNumber

4.0 --> Quant(4.0, nil, nil)

Array

[4.0, 1.0] --> Quant(4.0, 1.0, nil)

[4.0, 1.0, 0.1] --> Quant(4.0, 1.0, 0.1)

Nil

nil --> Quant(nil, nil, nil)

这简化了语法：

Routine({ ... }).play(quant: 4.0):: vs. code::Routine({ ... }).play(quant: Quant(4.0))

模式中的时间偏移

在某些情况下，你可能希望两个同时发声的模式按特定顺序求值——例如，第二个模式可能依赖于第一个模式计算出的数据。如果它们在时钟上被调度到完全相同的时间，你就无法控制执行顺序：第二个模式可能先求值，在这种情况下，它就会使用本应先行运行的模式所留下的过期数据。

定时偏移是一个正数，通常很小，它会将调度时间略微提前，从而保证具有较大定时偏移的模式会先于其他模式执行。定时偏移值保存在事件原型中，事件原型随后将其消息延迟恰好该数量的拍发送到服务器。

两个以相同 quant 和相位调度但具有不同时间偏移的模式，应该听起来完全同步。

(
// 时间偏移 = 0
p = Pbind(\freq, 440, \pan, -1, \delta, 1.0, \sustain, 0.1).play(quant: [2, 0, 0]);
// 时间偏移量 = 0.1
q = Pbind(\freq, 880, \pan, 1, \delta, 0.5, \sustain, 0.1).play(quant: [2, 0, 0.1]);
)

// p 的 nextBeat 是 x.0 —— q 的是 x.4 或 x.9（例如，一拍的一半减去 0.1）
[p.nextBeat, q.nextBeat]

p.stop; q.stop;

可扩展性：添加自定义调度模型

虽然标准调度模型对大多数用途应该足够，但使用对象封装调度细节的意义在于，你可以使用不同的对象以不同方式调度 Routine 或 Pattern。（用户并非在所有情况下都必须使用标准调度模型。）

如果这是你预期会经常使用的调度方式，可以创建 Quant 的子类并实现以下方法：

*new(...)：创建一个新实例，使用你需要的任意参数

nextTimeOnGrid(clock)：计算时钟上的精确拍数

你的类还应具有 asQuant、offset 和 offset_ 方法。如果你的类是 Quant 的子类，它将自动继承这些方法。

你也可以使用 Event 进行一次性调度。它至少应包含 nextTimeOnGrid 条目，这通常是一个接受参数 "self" 和 "clock" 的函数，返回绝对调度时间。该计算所需的任何其他值也应出现在 Event 中。

// 在下一个整数之后调度一个随机拍数
Pfuncn({ thisThread.clock.beats.debug("scheduled for"); nil }, 1)
    .play(quant: (
        nextTimeOnGrid: { |self, clock|
            clock.beats.roundUp(1).debug("clock beats") + rrand(self.lo, self.hi).debug("rand")
        },
        lo: 0, hi: 4
    ));
