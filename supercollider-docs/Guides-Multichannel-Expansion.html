多声道扩展

解释多通道扩展与表示

将多个通道作为数组

多个音频通道表示为 Array。

s.boot;
// 一个声道
{ Blip.ar(800,4,0.1) }.play;

// 两个声道
{ [ Blip.ar(800,4,0.1), WhiteNoise.ar(0.1) ] }.play;

每个输出声道会输出到不同的扬声器，因此对于立体声输出，这里的上限是 2。如果你有受支持的多声道音频接口或声卡，则可以输出该声卡支持的所有声道数。

所有 UGen 都只有一个输出。这种统一性便于使用数组操作来处理多通道结构。

为了实现多通道输出，UGen 会为每个输出创建一个单独的 UGen，称为 OutputProxy。OutputProxy 只是多通道 UGen 输出的占位符。OutputProxy 是在内部创建的，你永远不需要自己创建它们，但了解它们的存在是好的，这样当你遇到它们时就知道它们是什么。

// 查看 Pan2 的输出：
Pan2.ar(PinkNoise.ar(0.1), FSinOsc.kr(3)).dump;

play({ Pan2.ar(PinkNoise.ar(0.1), FSinOsc.kr(1)); });

多通道扩展

当把一个 Array 作为输入提供给一个 unit generator 时，会导致生成一个由该 unit generator 的多个副本组成的数组，每个副本使用输入数组中的不同值。这称为多通道扩展。除了少数特殊的 unit generator 外，所有 unit generator 都会执行多通道扩展。只有 Arrays 会被扩展，没有其他类型的 Collection，甚至 Array 的子类也不会。

{ Blip.ar(500,8,0.1) }.play // 一个声道

// freq 输入中的数组会导致创建一个包含 2 个 Blip 的 Array：
{ Blip.ar([499,600],8,0.1) }.play // 两个声道

Blip.ar(500,8,0.1).postln // 创建了一个单元生成器。

Blip.ar([500,601],8,0.1).postln // 创建了两个 unit generator。

多通道扩展会通过表达式图传播。当以输入数组调用 unit generator 构造函数时，它会返回一个实例数组。如果该数组作为另一个构造函数的输入，则又会创建一个数组，依此类推。

{ RLPF.ar(Saw.ar([100,250],0.05), XLine.kr(8000,400,5), 0.05) }.play;

// Saw 的频率输入数组 [100,250] 会使 Saw.ar 返回
// 两个 Saw 组成的数组，该数组又使 RLPF.ar 创建两个 RLPF。
// 两个 RLPF 共享同一个 XLine 实例。

当构造函数由两个或多个数组参数化时，创建的通道数等于最长的数组，参数从各数组中并行提取。较短的数组将回绕。

例如，以下内容：

Pulse.ar([400, 500, 600],[0.5, 0.1], 0.2)

等价于：

[ Pulse.ar(400,0.5,0.2), Pulse.ar(500,0.1,0.2), Pulse.ar(600,0.5,0.2) ]

下面给出一个基于上述 Saw 示例的更复杂的例子。在这个例子中，XLine 被扩展为两个实例，一个从 8000 Hz 到 400 Hz，另一个朝相反方向从 500 Hz 到 7000 Hz。这两个 XLine 与两个 Saw 振荡器“配对”，用于为两份 RLPF 提供参数。因此，在左声道上，一个 100 Hz 的 Saw 被从 8000 Hz 到 400 Hz 滤波，而在右声道上，一个 250 Hz 的 Saw 被从 500 Hz 到 7000 Hz 滤波。

{ RLPF.ar(Saw.ar([100,250],0.05), XLine.kr([8000,500],[400,7000],5), 0.05) }.play;

展开方法与运算符

许多运算符和方法也会进行多通道扩展。例如所有常见数学运算符：

{ Saw.ar([100,250]) * [0.5,0.8] }.play;
{ Saw.ar(LFNoise1.kr(1).range(0,100) + [100,250]) }.play;

还有各种 UGen 便捷函数，如 .clip2、.lag 和 .range：

{ Saw.ar(LFNoise1.kr(1).range(100,[200,300])) }.play;
{ Saw.ar(LFPulse.kr(1).range(100,[200,300]).lag([0.1,0.2])) }.play;

扩展由在 SequenceableCollection 中定义的包装方法处理。

你可以使用 Object: -multiChannelPerform 对任何类型的任何方法进行多通道扩展：

["foo","bar"].multiChannelPerform(\toUpper);

较短的数组会回绕：

["foo","bar","zoo"].multiChannelPerform('++', ["l","ba"])

使用 flop 和 flop1 进行多通道扩展

方法 flop 交换列与行，从而可推导出一系列参数集合：

(
SynthDef("help_multichannel", { |out=0, freq=440, mod=0.1, modrange=20|
    Out.ar(out,
        SinOsc.ar(
            LFPar.kr(mod, 0, modrange) + freq
        ) * EnvGate(0.1)
    )
}).add;
)
(
var freq, mod, modrange;

freq = Array.exprand(8, 400, 5000);
mod = Array.exprand(8, 0.1, 2);
modrange = Array.rand(8, 0.1, 40);

fork {
    [\freq, freq, \mod, mod, \modrange, modrange].flop.do { |args|
        args.postln;
        Synth("help_multichannel", args);
        0.3.wait;
    }
};
)

类似地，Function:flop 和 Function:flop1 返回一个未求值的函数，求值时会展开为其参数。

// if 的多通道扩展，这里用于防止除以零。
// flop 总是返回一个数组
f = { |a, b| if(b != 0) { a / b } { 0 } }.flop;
f.value([1, 2, 3, 4], [0, 10, 1000]); //  -> [ 0, 0.2, 0.003, 0 ]
f.value(2, 4); // [ 0.5 ]（始终返回一个数组）

// if 的多通道扩展，此处用于防止除以零
// flop1 仅在参数包含数组时返回数组
f = { |a, b| if(b != 0) { a / b } { 0 } }.flop1;
f.value([1, 2, 3, 4], [0, 10, 1000]); //  -> [ 0, 0.2, 0.003, 0 ]
f.value([2], 4); // -> [0.5]
f.value(2, 4); // -> 0.5
// 多通道扩展一个 fork 出 task 的函数
(
SynthDef(\blip, { |out, freq|
    Out.ar(out,
        Line.ar(0.1, 0, 0.05, 1, 0, 2) * Pulse.ar(freq * [1, 1.02])
    )
}).add;

a = { |dur=1, x=1, n=10, freq=400|
    fork {
        n.do {
            if(x.coin) { Synth(\blip, [\freq, freq]) };
            (dur / n).wait;
        }
    }
}.flop;
)

a.value(5, [0.3, 0.3, 0.2], [12, 32, 64], [1000, 710, 700]);

模式中的多声道扩展

多通道扩展并不完全遵循人们从前述内容中可能预期的方案。例如，以下代码无法正确进行多通道扩展：

(
SynthDef(\help_multichannel, { |out=0, freq=#[342, 145]|
    var env = EnvGate.new;
    Out.ar(out, [SinOsc.ar(freq[0]), Saw.ar(freq[1])] * env * 0.2)
}).add
)

// 未按预期工作
// 只有左声道的 freq 被正确设置
(
a = Pbind(
    \instrument, \help_multichannel,
    \freq, Pseq([[342, 145], [187, 564], [234, 135]], inf),
    \dur, 0.5
).play;
)

而是将数组参数包裹在额外的一对方括号中：

a.stop;

// 两个通道的频率均按预期设置
(
a = Pbind(
    \instrument, \help_multichannel,
    \freq, Pseq([[[342, 145]], [[187, 564]], [[234, 135]]], inf),
    \dur, 0.5
).play;
)

在底层，这是 .flop 如何准备给定参数以传递给 Synth 的结果：

// 单方括号
[\freq, [342, 145]].flop
// --> [ [ freq, 342 ], [ freq, 145 ] ]

// 双方括号
[\freq, [[342, 145]]].flop
// --> [ [ freq, [ 342, 145 ] ] ]

Pitfalls

有些 UGen 会从单声道输入创建立体声输出，在多声道扩展方面的行为可能与预期不符。

例如，Pan2：

{ Pan2.ar(SinOsc.ar([500,600]),[-0.5,0.5]) }.play;

这里的预期可能是两个正弦波会得到各自独立的声像位置。确实如此，但 Pan2 会展开为嵌套在外层数组中的两个立体声 UGen，从而总共产生四个输出通道。play 会为它们各添加一个 Out UGen，导致两个 Pan2 都写入同一个输出总线：

Pan2.ar(SinOsc.ar([500,600]),[-0.5,0.5])

// 打印：
// [ [ an OutputProxy, an OutputProxy ], [ an OutputProxy, an OutputProxy ] ]

在这种情况下，解决方案很简单，就是将嵌套的四个声道求和为单个立体声声道：

{ Pan2.ar(SinOsc.ar([500,600]),[-0.5,0.5]).sum }.play;

如果我们查看上面代码生成的 UGen 图，可以看到它是正确的。两个 Pan2 混合在一起，产生单个立体声输出：

{ Pan2.ar(SinOsc.ar([500,600]),[-0.5,0.5]).sum }.asSynthDef.dumpUGens

// 输出：
// [ 0_Control, scalar, nil ]
// [ 1_SinOsc, audio, [ 500, 0 ] ]
// [ 2_Pan2, audio, [ 1_SinOsc, -0.5, 1 ] ]
// [ 3_SinOsc, audio, [ 600, 0 ] ]
// [ 4_Pan2, audio, [ 3_SinOsc, 0.5, 1 ] ]
// [ 5_+, audio, [ 2_Pan2[0], 4_Pan2[0] ] ]
// [ 6_+, audio, [ 2_Pan2[1], 4_Pan2[1] ] ]
// [ 7_Out, audio, [ 0_Control[0], 5_+, 6_+ ] ]

保护数组免受扩展

某些 UGen，例如 Klank，需要以数组作为输入。由于所有数组都会被展开，你需要用 Ref 对象来保护某些数组。Ref 实例是一个带有名为 'value' 的单个槽的对象，用作对象的容器。Ref.new(object) 是创建 Ref 的一种方式，但还有一种语法捷径。反引号 ` 是一个一元运算符，等价于调用 Ref.new(something)。因此，要保护作为 Klank 或类似 UGen 输入的数组，你可以这样写：

Klank.ar(`[[400,500,600],[1,2,1]], z)

你仍然可以通过给它一个由 Ref 包装的数组组成的数组来创建多个 Klank。

Klank.ar([ `[[400,500,600],[1,2,1]],  `[[700,800,900],[1,2,1]] ], z)

等价于：

[ Klank.ar(`[[400,500,600],[1,2,1]], z),  Klank.ar(`[[700,800,900],[1,2,1]], z)]

当传递给 Klank 时，也是 Refs 的多通道扩展：

Klank.ar(`[[[400,500,600], [700,800,900]],[1,2,1]], z)

，它等价于：

[ Klank.ar(`[[400,500,600],[1,2,1]], z),  Klank.ar(`[[700,800,900],[1,2,1]], z)]

使用 Mix 减少声道扩展

Mix 对象提供了将多通道数组缩减为单通道的手段。

Mix.new([a, b, c]) // 通道数组

or

[a, b, c].sum

等价于：

a + b + c  // 混合为一个

Mix 比使用 + 更高效，因为它可以一次执行多次加法。但主要优势在于它可以处理通道数任意或在运行时确定的情况。

// Pulse 的三个通道被混合到一个通道
{ Mix.new(  Pulse.ar([400, 501, 600], [0.5, 0.1], 0.1) ) }.play

Mix 的多通道扩展方式不同。Mix 接收一个数组作为输入（且该数组未被 Ref 保护）。这个数组不会导致 Mix 被复制。数组的所有元素在单个 Mix 对象中混合在一起。另一方面，如果该数组包含一个或多个数组，则会在下一层执行多通道扩展。这允许你混合立体声（双元素）数组组成的数组，从而得到一个双通道数组。例如：

Mix.new( [ [a, b], [c, d], [e, f] ] ) // 输入是立体声对组成的数组

等价于：

// 混合为单个立体声对
[ Mix.new( [a, c, e] ), Mix.new( [b, d, f] ) ]

目前它不是递归的。你不能对数组的数组的数组使用 Mix。

以下是最后一个示例，演示多通道扩展和 Mix。通过更改变量 'n'，你可以更改 patch 中的声部数量。你的机器能处理多少个声部？

(
{
    var n;
    n = 8; // 'voices' 的数量
    Mix.new( // 将所有立体声对混合为单声道。
        Pan2.ar( // 将声音声像定位到立体声位置
            CombL.ar( // 用作弦共振器的梳状滤波器
                Dust.ar( // 随机脉冲作为激励函数
                    // 一个数组，用于让 Dust 扩展到 n 个通道
                    // 1 表示平均每秒一个脉冲
                    Array.fill(n, 1),
                    0.3 // 振幅
                ),
                0.01, // 最大延迟时间（秒）
                // 为每个 'string' 生成不同随机长度的数组
                Array.fill(n, {0.004.rand+0.0003}),
                4 // 衰减时间（秒）
            ),
            Array.fill(n,{1.0.rand2}) // 为每个声音分配不同的声像位置
        )
    )
}.play;
)
