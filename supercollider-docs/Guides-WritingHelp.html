编写帮助

开始编写帮助文档

参见：SCDoc Syntax、SCDoc

编写新的帮助文档

最简单的方法是查看现有的帮助文件或类文档，并阅读本文档和 SCDoc Syntax

注意： 帮助文件应使用 UTF-8 编码！

所有用于文档元数据的标签都应放在文档源文件的顶部，位于任何章节或其他文本之前。参见 SCDoc Syntax: Header tags

在头部中，必须指定标题、摘要和类别部分。

示例头部：

title:: My help file
summary:: A short single-line summary of what this is
categories:: Language>Conditionals, SomeOtherCategory
related:: Reference/FooBar

在章节和小节中使用常规文本，在列表、表格、树、图像、链接等中可使用其他标签。标签参考参见 SCDoc Syntax。

section:: Introduction

This is a nice document...
blah blah blah..

subsection:: Details

Some details..

为新类编写文档

当你导航到一个未文档化的类时，它会包含一个 schelp 模板，你可以填写该模板并保存到 HelpSource/Classes/ClassName.schelp。

所有未文档化的类可在此处查看：Browse: Undocumented classes（自动生成）。

目录布局

帮助系统根据文档类型使用 HelpSource 下的不同文件夹：

HelpSource
Classes

类引用，文件必须以类名命名。

Reference

其他参考文档。

Tutorials

是的，教程。

Guides

解释内容但并非真正教程的指南。

Overviews

其他文档的概览，这些大多是自动生成的。

Other

不适合放入任何其他目录的内容。

注意： 将文档放在正确的文件夹中很重要。对于 Classes 而言，这是必须的！

所有 .schelp 文件都将被解析并渲染到帮助目标目录中相同的目录结构下。任何其他文件，如图片或现成的 HTML 文件，都将被直接复制。

类参考

类参考具有一些特殊标签和更严格的结构。普通文本应写在特殊的顶层节 DESCRIPTION、CLASSMETHODS、INSTANCEMETHODS 和 EXAMPLES 内部。

在上述每个顶层节下均可使用命名的子节。

也可以使用命名小节，但它们会被放在上述所有顶层小节之后。

方法与参数

方法的文档记录方式如下：

  • method:: name(s)

    • 方法的简短描述。

    • argument:: name1

      • 参数描述

    • argument:: name2

      • 另一个参数的描述。

    • returns::

      • 返回值的描述

    • discussion::

      • 可选的讨论与示例代码

注意： 不要在 method 标签中列出参数，只列出方法名

方法描述之后是参数，写作 argument:: name，其中 name 是可选的，如果未给出则会自动填充。如果给出，它必须与方法实际的参数名匹配。每个参数行之后是该参数的描述。

有一个可选的 returns:: 标签，可用于描述方法的返回值。

如果需要更长的讨论，请使用 discussion:: 标签。这是插入示例代码等内容的好地方。

Setter 会自动处理。在记录 setter/getter 时，只使用 getter 名称（不带下划线），并将 setter 和 getter 作为单个属性来描述，例如：

method:: helpSourceDir
set or get the help source directory

方法会自动获得一个锚点名称，类方法前缀为 *，实例方法前缀为 -。例如，要链接到 foo 类方法，请使用 link::#*foo::。

method:: 标签也可用于普通文档中，此时应该带有参数名。这对于在特定类文档之外记录常见接口很有用，例如 plot。这些方法的锚点前缀为点（.）而不是 * 或 -。

当多个方法具有相同的签名（如 ugen 中的 ar 和 kr）时，它们应全部列在一个方法标签中。

SCDoc 会为所有未文档化的方法生成文档。要忽略私有方法，请将它们添加到 private:: 标签中，其工作方式与方法标签相同，但没有节正文。

扩展可以向现有类的文档添加方法，参见下文的 Extensions 部分。

从其他类复制方法

你可以使用 copymethod:: ClassName, methodName 将另一个帮助文件中某个方法的文档复制到此帮助文件。

methodName 对于类方法必须加上 *（星号）前缀，对于实例方法必须加上 -（短横线）前缀。

重定向类

有些类使用 *doesNotUnderstand 技巧来重定向到另一个实现类。要为这类类编写文档，需要在头部添加此标签：

redirect:: implClass

其中 implClass 是保存实现类的类变量的名称。

Example

LFPulse UGen 文档的示例，保存到 HelpSource/Classes/LFPulse.schelp

TITLE:: LFPulse
summary:: pulse oscillator
categories:: UGens>Generators>Deterministic, UGens>Oscillators
related:: Classes/LFSaw

DESCRIPTION::
A non-band-limited pulse oscillator. Outputs a high value of one and a low value of zero.

CLASSMETHODS::
private:: categories

METHOD:: ar, kr

argument::freq
frequency in Hertz

argument::iphase
initial phase offset in cycles ( 0..1 )

argument::width
pulse width duty cycle from zero to one.

returns::
An UGen.

EXAMPLES::

a plot:
code:: { LFPulse.ar(Line.kr(100, 800, 0.1)) }.plot(0.1); ::

50 Hz wave:
code:: { LFPulse.ar(50) * 0.1 }.play; ::

Categories

尝试为你正在编写或转换的文档找到合适的类别。如果已存在合适的类别，就应使用它。参见文档浏览器（自动生成）以查看现有类别。

对于 UGen，应使用现有的类别，如 UGens>Filter>Nonlinear。可这样查看当前类别：

Ball.categories

文档可以存在于多个分类中，也可以具有层级分类，例如 Sequencing>Patterns。

跨文档链接

要链接另一个文档，请使用 link::Path/To/Document::，其中路径相对于 SCDoc: *helpTargetDir，且文档文件名不带扩展名。示例：

Also take a look at link::Classes/SinOsc:: and link::Reference/Literals::

Methods

要链接到特定的类方法，请追加 #*methodName；要链接到实例方法，请追加 #-methodName：

Also take a look at the play method of link::Classes/Function#-play::

这将渲染为 Function: -play

对于在 instancemethods 或 classmethods 之外文档化的通用方法（如通用的 play 文档），请使用点（.）作为前缀，而不是 * 或 -。

特殊的 Methods 概览是动态的，允许通过追加 #name 来显示特定方法，其中 name 是方法名：

For all implementations of play, see link::Overviews/Methods#play::

使文档可被搜索找到

Search 页面可以匹配文档标题/文件名、摘要、非私有方法和分类。如果你提到了某些内容应该在搜索中匹配但不属于上述类型，可以用 keyword 标签显式添加：

keyword:: someKeyWords

Extensions

Quarks 与扩展

每个扩展都应拥有自己的 HelpSource 文件夹，其中包含应被纳入帮助系统的文件。

示例文件布局：

MyQuark/HelpSource/Classes/MyClass1.schelp
MyQuark/HelpSource/Classes/MyClass2.schelp
MyQuark/HelpSource/Guides/MyGuide.schelp
MyQuark/HelpSource/Guides/MyPicture.png
MyQuark/MyClass1.sc
MyQuark/MyClass2.sc

注意： quark 中包含的所有帮助文件都会自动添加分类 "Quarks>NameOfQuark"，因此你不应自行添加。这使得浏览某个特定 quark 的全部文档变得容易。

如果你想为 quark 设置主帮助文件，请在 Quark 目录文件中将 \schelp 设置为帮助文件相对于 HelpSource 的路径，并且不带 .schelp 扩展名。示例：\schelp: "Guides/MyGuide"

方法扩展

为现有类添加方法的扩展应将这些方法记录在 Classes/TheClass.ext.schelp 中，只包含相关部分（不要标题、摘要、类别等）。

示例：Classes/String.ext.schelp

INSTANCEMETHODS::

subsection:: Extensions by SCDoc

method:: stripWhiteSpace
strips whitespace at the beginning and end of the string
returns:: the stripped string

内容被插入到正确的位置（节、小节等）。它适用于所有类型的节，例如可以向 DESCRIPTION:: 添加一个包含附加信息的小节，或添加另一个顶级节等。

Links

URL 会被自动转换为链接。

link:: 标签用于文档之间的交叉引用。它使用简单的命名空间，例如：

See also link::Classes/SinOsc:: for a nice oscillator.
Or take a look at link::Browse#UGens:: for a full list.
The link::Overviews/Methods#play#play method:: is often very useful.

可以使用 anchor::name:: 手动插入锚点，并像这样引用：

link::Foo/Bar#hello::

或跳转到本文档中的锚点：

link::#hello::

所有章节都会自动获得锚点名称。

所有方法都会获得锚点名称，类方法以 * 为前缀，实例方法以 - 为前缀。

可以使用另一个 # 字符来更改链接的渲染文本：

Also see link::Classes/SinOsc##a nice oscillator::

指向特定方法的链接：

Take a look at link::Classes/SinOsc#*ar:: and link::Classes/Function#-play::

渲染为：SinOsc: *ar 和 Function: -play

Methods 概览是动态的，允许通过将方法名用作锚点来显示特定方法，例如获取所有实现 play 的类的列表：

All classes implementing code::play:: can be seen link::Overviews/Methods#play#here::.

渲染为：所有实现了 play 的类可以在此处看到。

Browse 页面也是动态的，并且可以将类别树作为锚点名称：

For more filters, see link::Browse#UGens>Filters::

渲染为：更多过滤器，请参见 Browse: UGens>Filters

参与文档贡献

为文档做贡献的最简单方式是：

1. Fork SuperCollider 仓库 https://github.com/supercollider/supercollider

2. 克隆你的仓库

    git clone --recursive https://github.com/{your_username}/supercollider.git

3. 为文档更新创建一个分支

    git checkout -b doc_updates

4. 进行更新，提交更改并推送到 github

    git push origin -u doc_updates

5. 通过 github 提交你的 pull request，从你的分支 doc_updates 到 SuperCollider develop

处理旧版文档

以下是一些关于处理以旧格式或语法编写的文档的信息。

SC 3.5.2 中的新特性

SCDoc 在 3.5.2 中被重写，解析器用 C++ 实现，以提升速度和稳定性。语法变得更加严格，如果文档中存在错误，解析器现在会抛出错误或警告。

需要记住的一些重要更改：

  • 链接到章节不再使用 lower_case_and_underscored 形式的锚点，而是使用精确的章节标题。示例：link::#Language-side news:: 渲染为：Language-side news
  • 如果你添加了新文档或其他文件，并希望在帮助中看到变化，请运行 SCDoc.indexAllDocuments。如果你只是修改了某个文档并想看到更改，只需在浏览器中按 Reload，SCDoc 会自动检测并重新索引。
  • CLASS:: 标签已弃用，类参考文档也只需改用 TITLE:: 即可。
  • 现在 ARGUMENT:: 标签的参数名是可选的。如果未给出，SCDoc 将自动填充真实的参数名。

转换旧帮助文件

对此没有自动化流程，但对大多数帮助文件来说，手动完成非常简单：

  1. 在网页浏览器中打开旧帮助文件
  2. 复制文本并将其插入到新的文本文件：FileName.schelp
  3. 添加适当的标签，如 title、sections 等。（见下文）
  4. 根据文档类型将文件保存到 HelpSource 下正确的子目录中（参见下面的 目录布局）

  5. 检查它是否渲染正常。你可以运行 SCDoc.indexAllDocuments（方法文档链接：SCDoc: *indexAllDocuments），让 SCDoc 检测到新文件并将其添加到文档索引中。

    如果文件已经存在并且你想查看更改，只需在帮助浏览器中按 Reload，SCDoc 将重新渲染它。
