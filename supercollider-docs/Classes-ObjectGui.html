ObjectGui

MVC 架构的控制器类，所有 XYZGui 类的父类

参见：gui

说明

在 MVC 架构中，这是 Controller，它创建用于操作 Model 属性的 View，并接收来自 View 的消息，将变更施加到 Model 上。

每个类通过 guiClass 方法指定其 Gui 类。

Object 的默认 guiClass 是 ObjectGui。因此，如果一个类根本没有实现 guiClass，那么至少有一个默认的 ObjectGui 会显示其名称。

许多子类重写 guiClass 方法以指定不同的类，即 ObjectGui 的一个子类。

这是最简单的显示方式，只是对象的 asString。

在你的模型上调用 .gui 方法：

// 标准用法
theModel.gui(parent, bounds)

// 这会产生以下步骤：
guiClass = theModel.guiClass;
gui = guiClass.new(theModel);
gui.gui(parent, bounds);

除了这些步骤之外，还会管理 model/gui 依赖关系、管理默认值（nil 父级或 nil 边界），并且当窗口或父视图关闭时，依赖关系会被安全管理。

类方法

.new

创建一个 gui 控制器对象，但尚未创建视图 / 窗口。调用 .gui 来创建视图。

参数：

model

模型是 GUI 作为其图形界面的对象。

返回值：

ObjectGui 或子类对象

实例方法

.guiBody

在实现子类时，这是主要且通常唯一需要实现的方法。ObjectGui 父类负责设置所有窗口和依赖关系，然后 guiBody 方法向布局中添加视图。在 ObjectGui 子类中声明用于存储控件（以便之后更新）的实例变量是正常的做法。

参数：

layout

通常是一个 FlowView：一个带有 FlowLayout 的父视图，用于添加视图。

bounds

nil 或 Rect。

... args

此处可以传递更多参数。

返回值：

this

.update

当模型发生变化并调用 .changed 方法时，会在包括此 gui 对象在内的所有依赖对象上调用 .update。更新你放置在 guiBody 中的视图。

参数：

theChanged

模型。在你的 gui 类中，模型已经位于实例变量 'model' 中。

theChanger

取决于 .changed 的调用约定。如果某个对象调用了 someModel.changed(this)，那么它就是将自己作为 changer 提供，并会在此处被传递。有时会使用一个标志：someModel.changed('points')，而 gui 可能了解并参与该约定。有时不传入 changer。

.gui

创建视图 / 窗口的标准方法。通常你会调用 yourModel.gui(parent, bounds)，这会创建 gui（相关 ObjectGui 子类的），然后调用 theObjectGui.gui(parent, bounds)，并转发参数。因此，这个方法就是接收来自最初对 yourModel.gui(parent, bounds) 调用所转发的 (parent, bounds) 的方法。通常你不会手动调用它，并且会避免重新实现它。

参数：

parent

父视图：nil、一个 Window、一个 FlowView 或任何其他可用的容器视图。

bounds

nil 或一个 Rect。默认值 nil 会将完整的边界提供给 guiBody 方法，然后随后将视图尺寸收缩为实际添加内容的精确尺寸。

... args

更多参数可以传入 theModel.gui(parent, bounds, anArg, moreArg)，并会被转发给 guiBody。

返回值：

this

.guify

这会将提供的父视图和边界转换为窗口上可用的父容器视图。如有需要，它会创建一个窗口。

参数：

parent

父视图或 nil

bounds

所需边界或 nil

title

正在创建新窗口时的窗口标题。如果存在父视图，则忽略 title。

返回值：

转换后的父级

.model

设置一个新模型。这允许使用单个 gui 并动态换入同一类的不同模型。旧模型将 gui 作为依赖项释放，新模型将 gui 添加为依赖项。然后更新视图。

参数：

newModel

新对象

返回值：

(returnvalue)

.dragSource

writeName 的默认实现会在 gui 上放置一个可拖拽的名牌。此方法是该 dragSource 对象的访问器。

返回值：

一个 GUi.dragSource

.viewDidClose

当父视图关闭时调用此方法。它会释放依赖对象。

返回值：

this

.background

每个 ObjectGui 子类都可以实现一个默认背景色。

返回值：

一个颜色

.writeName

ObjectGui 默认会创建一个带有模型名称的名牌。如果需要不同的名称样式或不需要名牌，请在子类中实现此方法。注意：这在不久的将来可能会改变。因此许多类重写此方法以关闭名称。

参数：

layout

放置铭牌的布局。可能与被传递给 guiBody 的布局相同

.prWriteName

默认的 writeName 实现。如果你主要实现 writeName 以自定义显示的名称或向该区域添加其他项，可以在子类中调用此方法。

参数：

layout

布局

name

要显示的字符串

示例

YourSimpleGuiClass : ObjectGui {

    guiBody { |layout|
    
        // 我们引用该模型并
        // 访问其变量 howFast。
        // 如果它是一个简单的数字，它将使用
        // 默认的 ObjectGui 类显示，该类
        // 会简单地将其值显示为字符串。
        model.howFast.gui(layout);
    }
}


// 更复杂
YourGuiClass : ObjectGui {
    
    var numberEditor;
    
    // 例如
    guiBody { |layout|
        var r;
        // 你为其创建 GUI 的对象被称为模型
        
        // 在屏幕上显示一些参数。
        // 这里我们假设 someParam 具有
        //  一个合适的已实现的 GUI 类，
        // 或者默认的 ObjectGui 已足够。
        model.someParam.gui(layout);
        
        // 使用非 'gui' 对象
        r = layout.layRight(300, 300); // 为自己分配一些空间
        Button(layout.win, r)
            .action_({ |butt|
                model.goApeShit;
            });
        
        // 注意：NumberEditor 是一个 cruciallib 类
        // 它本身是一个模型（它是一个值的编辑器）
        // 并且拥有自己的 GUI 类，用于创建和管理 NumberBox 视图
        numberEditor = NumberEditor(model.howFast, [0, 100])
            .action_({ |val|
                model.howFast = val;
                model.changed(this);
                // 告诉模型此 GUI 已更改了它
            });
        numberEditor.gui(layout);
    }
    
    // 你的 gui 对象在任何时候 .changed 消息
    // 被发送到你的模型时都会调用 update
    update { |changed, changer|
    
        if(changer !== this, {
            /* 如果正是这个 GUI 对象通过 numberEditor 改变了值，
                那我们已经有了正确的显示，
                不需要浪费 CPU 去更新它。
                如果其他人对模型做了任何改动，
                我们会在这里自行更新。
            */
            numberEditor.value = model.howFast;
            /*
                注意 
                    numberEditor.value = model.howFast;
                是被动的，不会触发 numberEditor 的 action。    

                numberEditor.activeValue = model.howFast
                则会同时触发 action，导致一个循环，
                很可能让你的机器崩溃。
            */
        }
    }

}
