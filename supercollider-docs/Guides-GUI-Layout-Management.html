布局管理

使用布局类管理父视图内子视图的分布

另请参见：LineLayout、HLayout、VLayout、GridLayout、StackLayout

布局的作用是将安装布局的视图所获得的空间量分配给该视图的子级。Layout 的每个子类都有特定的空间分配模式（一条线、一个二维网格等）。详见其文档。

布局被安装到视图上，用于管理视图所占用的空间，并在其子视图之间分配空间。这些子视图又可以安装其他布局，管理分配给它们的空间。但布局也可以直接管理其他布局——一个布局可以直接占据另一个布局分配模式中的一个位置。因此，布局操作的基本单元被抽象地称为 item，它可以是视图，也可以是另一个布局。

注意： 虽然布局可以自行构成层次结构，但就视图层次而言，由这些布局管理的所有视图都是安装顶层布局的视图的直接子视图。

以下示例展示了一个 VLayout，将一系列 TextField 组织成垂直线，其最后一项是一个 HLayout，将一系列 Button 组织成水平线。

(
w = Window(bounds:Rect(200,200,200,200)).layout_(
    VLayout(
        TextField(), TextField(), TextField(),
        HLayout( Button(), Button(), Button() )
    )
).front;
)

布局如何完成其工作

布局通过在父视图中调整项的大小并移动它们，以形成特定的分布模式来发挥作用，这遵循各项自身的大小偏好与约束，并符合使 GUI 实用的常识。

为了解释布局如何运作，我们先来看看视图的固有尺寸偏好和约束：

固有视图尺寸

每个视图本质上都有一个首选尺寸和一个最小尺寸，分别由 View: -sizeHint 和 View: -minSizeHint 返回。首选尺寸是适合视图舒适地绘制自身、显示其内容并允许交互的尺寸，而最小尺寸是视图正确绘制自身（包括其内容）所需的绝对最小尺寸。当视图的内容发生变化时，两者都可能改变；例如，大多数显示某些文本的视图在文本改变时会报告不同的 sizeHint（除非文本是可滚动的）。

如果在构造时省略了 'bounds' 参数，视图会在构造时采用其首选大小。然而，通常无法在构造时设置视图上的文本，因此它自动获得的大小不会反映构造之后对文本所做的更改。你可以通过在设置文本后将视图调整为其 sizeHint 来补救这一点——但布局的目的（下文将解释）正是为了自动为你完成这一操作。以下是手动使用 sizeHint 的示例：

// 创建一个带 StaticText 的 Window
(
w=Window().alwaysOnTop_(true);
t=StaticText(w);
w.front;
)

// 尚未设置文本。发布 StaticText 的 sizeHint：
t.sizeHint

// 设置文本，并再次发布 sizeHint：
t.string_("This is a looooooong text");
t.sizeHint

// 将大小调整为 sizeHint：
t.bounds = t.bounds.size_(t.sizeHint);

// 现在你可以看到整个文本

正如它们的名称所示，sizeHint 和 minSizeHint 只是提示，并不阻止设置不同的大小。不过，你可以使用 View: -minSize、View: -maxSize 及类似方法设置大小的硬性限制：

x=View(bounds:Rect(30,30,100,100)).alwaysOnTop_(true).front;

// 设置最小尺寸限制：
x.minSize = Size(200,200);

// 视图自动调整到了最小尺寸。
// 现在试着把它缩回去：
x.resizeTo(100,100);

// 该视图不允许小于 minSize 的尺寸。

自动和动态的空间分布

布局会自动在其各项之间分配空间，可能按不相等的部分分配，这取决于上述视图的固有偏好和约束。此外，视图对于自身是更受益于被水平或垂直扩展，还是更倾向于在某个方向上保持固定大小，也有各自的固有偏好。布局也会考虑这一点。

布局是动态工作的，这意味着每当空间量发生变化（安装它的视图或父布局被调整大小）、每当条目被添加或移除，以及每当条目的大小约束和偏好发生改变时，布局都会重新分配空间。后者可能发生的情况例如：影响视图外观的属性被改变时。

布局将影响沿布局层级向上的空间分配——它将根据其分布模式以及其各项约束和偏好之和，定义自身的约束和偏好。最终，这意味着用户调整窗口大小的能力将受到基于窗口内容所确定的大小约束的限制。

例如：在一个包含 Button 和 TextField 的 HLayout（一种将项目按水平线排列的布局）中，Button 会根据其显示的文本获得固定的宽度，而 TextField 则会获得剩余的所有宽度。下面示例代码中的另一个 Button 将占据窗口的全部宽度，因为没有其他项目竞争该特定空间。请注意，Button 和 TextField 都具有固有固定的高度，因此它们在调整窗口大小时高度永远不会改变。尺寸约束还限制了窗口可调整到的最小尺寸。

(
w = Window.new(bounds:Rect(100,100,300,80)).layout_(
    VLayout (
        HLayout(
            Button().states_([["Super"]]),
            TextField().string_("Collider")
        ),
        Button().states_([["SuperCollider"]])
    )
).front;
)

用户自定义

拉伸因子

布局通常允许用户通过为布局分布模式的项或方面分配伸缩因子，来覆盖其默认的分布策略。

(
w = Window.new(bounds:Rect(100,100,400,80)).layout_(
    HLayout(
        [Button().states_([["Super"]]), stretch:1],
        TextField().string_("Collider")
    )
).front;
)

尺寸约束

用户可以通过对视图尺寸设置硬性限制（如上所述）来覆盖视图的固有尺寸约束和偏好，布局会将这些考虑在内。

(
w = Window.new(bounds:Rect(100,100,300,300)).layout_(
    VLayout(
        TextField().string_("Super").minHeight_(80),
        TextField().string_("Collider").maxWidth_(150)
    )
).front;
)

视图的最小尺寸对于默认没有最小尺寸的 UserView 尤为重要。在示例中，第一个 UserView 是不可见的。

(
w = Window.new(bounds:Rect(100,100,200,200)).layout_(
    VLayout(
        UserView.new.background_(Color.rand),
        TextField().string_("Super").maxWidth_(100),
        UserView.new.background_(Color.rand).minSize_(200@200),
        TextField().string_("Collider").maxWidth_(100)
    )
).front;
)

Alignment

布局层级中所有项的大小约束和偏好的组合，可能导致分配给某项的空间大于其自身约束所允许的大小。在这种情况下，该项只会增长到其最大允许大小，而用户在额外可用空间内的位置可通过为该项指定对齐方式来控制。

(
w = Window.new.layout_(
    HLayout(
        [Button.new.states_([["Super"]]), align:\bottom],
        TextView(),
        [Button.new.states_([["Collider"]]), align:\top]
    )
).front;
)

视图与布局的层级结构

从布局安装到某视图上的那一刻起，它就开始作用于该视图所占据的空间。然而，它不会自动影响在布局之前已创建的子视图。要让视图由布局管理，它们必须在布局安装到某视图之后作为该视图的子视图创建，或者必须通过布局的构造函数或为此目的提供的实例方法显式插入到布局中。

使用父级构建的视图

当创建一个视图并指定另一个视图作为其父视图时，它会隐式地受父视图布局的管理——它会以某种默认方式插入到布局中。然而，像 GridLayout 这样的布局具有复杂的空间分配模式，因此你需要使用它们专用的方法来精确指定视图将占据布局分配模式中的哪个位置。

显式插入到布局中的视图

视图也可以在未给定父视图的情况下构造；在通过布局的构造函数或实例方法将其显式插入布局后，它将自动成为该布局所在（或将安装于其上的）视图的子视图。如果该布局直接位于另一个布局中，则视图将成为最顶层布局所安装于其上的视图的子视图。
