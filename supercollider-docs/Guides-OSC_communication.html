OSC 通信

OSC 网络通信

参见：NetAddr、OSCFunc

程序之间的 OSC 通信通常用于从一个应用程序向另一个应用程序发送消息，这些应用程序可能运行在不同的计算机上。在 SuperCollider 中，这种通信通过创建目标应用程序的 NetAddr 并创建一个 OSCFunc 来监听另一个应用程序来实现。OSC 的底层协议是 UDP 或 TCP。

向另一个应用程序发送 OSC

要与另一个应用程序建立通信，你需要知道该应用程序在哪个端口上监听。例如，如果一个应用程序在端口 7771 上监听，我们可以创建一个 NetAddr 并向它发送消息：

b = NetAddr.new("127.0.0.1", 7771);    // 创建 NetAddr
b.sendMsg("/hello", "there");    // 向应用程序发送消息 "hello"，参数为 "there"

从另一个应用程序接收 OSC

要监听另一个应用程序，该应用程序需要向 SuperCollider 正在监听的端口发送消息。通常默认端口是 57120，但如果 SC 启动时该端口已被占用，则可能是其他端口。当前默认端口可通过以下方式获取

NetAddr.langPort;    // 获取 SC 当前监听的端口

或者你可以同时获取 IP 和端口：

NetAddr.localAddr    // 获取当前 IP 和端口

你可以使用 Main: -openUDPPort 打开额外的端口。它会返回一个 Boolean，指示 SC 是否成功打开了新端口。或者，你也可以直接将自定义端口作为 recvPort 参数传给 OSCFunc，如果该端口尚未打开，它会自动打开。

thisProcess.openUDPPort(1121); // 尝试打开 1121
thisProcess.openPorts; // 列出所有打开的端口

要监听传入的消息，需要在 SuperCollider 中创建一个 OSCFunc。如果发送应用程序具有固定的发送端口，你可以将 OSCFunc 设置为仅监听来自该 IP 和端口的消息：

n = NetAddr.new("127.0.0.1", 7771);    // 创建 NetAddr
// 创建 OSCFunc
o = OSCFunc({ arg msg, time, addr, recvPort; [msg, time, addr, recvPort].postln; }, '/goodbye', n);
o.free;    // 完成后移除该 OSCFunc。

注意： 上面的端口 7771 是另一个应用程序发送来源端口，而不是 SC 接收数据的端口。如果你想在 NetAddr.langPort 以外的端口接收数据，请参见 OSCFunc: *new 中的 recvPort 参数。

从正在从可变端口发送的应用程序接收

有些应用程序（尤其是 Pd 和 Max）不会从固定端口发送消息，而是每次发送消息时使用不同的端口，或者每次补丁启动时随机选择一个端口。在这种情况下，需要设置 OSCFunc，使其监听来自任何地方的消息。你可以通过将 srcID 参数传入 nil 来实现。

o = OSCFunc({ arg msg, time, addr, recvPort; [msg, time, addr, recvPort].postln; }, '/goodbye'); // 创建 OSCFunc
o.free;    // 完成后移除该 OSCFunc。

测试传入流量

OSCFunc 有一个便捷方法 OSCFunc: *trace，它会发布所有传入的 OSC 消息：

OSCFunc.trace(true); // 开启 posting
OSCFunc.trace(false); // 关闭发布

自定义 OSC 消息处理

所有传入的 OSC 消息都会调用 Main 中的消息 recvOSCmessage。如有需要，可以向 Main 的 recvOSCFunc 变量添加自定义的 Function 或其它对象。虽然可以直接使用相应的 setter 来完成，但最好使用 Main: -addOSCRecvFunc 和 Main: -removeOSCRecvFunc，以避免覆盖类代码可能已添加的任何其它函数。

// 此示例基本上类似于 OSCFunc.trace，但会过滤掉
// /status.reply 消息
(
f = { |msg, time, addr|
    if(msg[0] != '/status.reply') {
        "time: % sender: %\nmessage: %\n".postf(time, addr, msg);
    }
};
thisProcess.addOSCRecvFunc(f);
);

// 停止发送。
thisProcess.removeOSCRecvFunc(f);

OSC 类型标签与 sclang

入站 OSC 消息必须带有类型标签，否则将抛出错误。

支持以下出站转换：

  • 整数变为 "i"。OSC 和 sclang 都使用 32 位有符号整数。
  • 布尔值变为 "i"，true 转换为 1，false 转换为 0。
  • Nil 变为 "i"，转换为值 0。
  • 浮点数变为 "f"（32 位浮点数）。sclang 的浮点数是 64 位的，因此转换为 OSC 时会有精度损失。
  • 字符串和符号变为 "s"（字符串）。
  • Int8Array 变为 "b"（blob）。
  • Char 作为原始类型标签添加，不向 OSC 包附加任何数据。这用于发送 $N（nil）、$T（true）、$F（false）、$I（infinity/impulse）。请小心处理——如果目标实体不认为该标签消耗零字节，则 OSC 消息的剩余部分可能会被破坏！

如果将 NetAddr.useDoubles 设置为 true，那么在出站消息中，sclang 将使用 "d"（双精度）类型标签而非 "f"。OSC 双精度数为 64 位。你需要自行确保接收者能够理解 "d"。

支持以下入站类型标签：

  • "i"（32 位有符号整数）变为 Integer
  • "f"（32 位浮点数）变为 Float
  • "s"（字符串）变为 Symbol
  • "b"（blob）和 "m"（4 字节 MIDI 消息）变为 Int8Array
  • "d"（64 位浮点数）变为 Float
  • "T"（真）和 "F"（假）变为布尔值
  • "I"（无穷/冲激）变为 +inf
  • "N"（nil）变为 nil
  • "t"（64 位大端定点时间标签）变为 Float
  • "c"（字符）变为 Char

不支持 "r"（RGBA 颜色）、"S"（符号）以及 "[" 和 "]"（数组开始和结束）。

如果遇到无法识别的标签，sclang 会将这个无法识别的标签转换为一个 Char 对象，并将其添加到 OSC 消息中。然后它会像读取字符串一样在 OSC 消息中向前跳过——它寻找下一个空字节，然后跳过 0-3 个字节以实现 4 字节对齐。
