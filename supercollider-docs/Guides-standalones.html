制作独立应用程序

通过“导出”现有 SuperCollider 应用配置和项目来制作基于 SuperCollider 的应用程序的指南。

注意： 独立应用程序的概念主要与 macOS 相关。在 Linux 上，Miguel Negrão 和 Fredrik Olofsson 创建了类似的方式，将 SC3 的各个版本打包成独立的设置。

Introduction

SuperCollider 3.6 及更早版本支持 macOS Cocoa 界面，以及一个特殊的 XCode 项目，它允许非常灵活的界面设计，包括移除和添加菜单。自 3.7 起，SuperCollider 仅使用 Qt，并且（现已过时的）独立 XCode 项目已在 3.9 中移除。虽然当前的 Qt 实现目前灵活性较低，但仍可使用此处提供的脚本（或类似脚本）用它创建有用的独立应用程序。

人们可以将演出设置、装置作品、软件合成乐器、复杂声音生成器和其他项目打包成完全独立的 SuperCollider.app 副本，包括 IDE，以及（如果需要）帮助系统。自定义界面可以让这类应用易于被受众使用，而这些受众无需知道如何安装 SuperCollider、运行 SuperCollider 代码，甚至无需知道涉及 SuperCollider。这对于向公众分发应用程序，或创建供自己使用的专用应用程序很有用。有一个重要的限制：整个应用程序必须是开源的，并符合 GNU 通用公共许可证。

在 macOS 上，应用程序是带有 ".app" 扩展名的特殊目录，称为包。SuperCollider 的独立应用程序就是这样一种包，其中包含你的 SuperCollider 代码，以及一份重命名后的 SuperCollider 副本，用于运行你的代码。

实用指南

（作者 Alberto de Campo，2017）

本指南用于导出现有 SC3 设置的副本，至少适用于两种场景：

  • 为非专业用户冻结基于 SC 的配置，例如在博物馆中运行的装置作品，其应尽可能便于移动且自包含。
  • 复制一个作品或演出设置的配置，作为备份或安全副本，为熟练用户保留很大的灵活性。

在 3.6 之前的版本中，可以用 SC 创建更复杂的面向用户的应用，而且有不少人正在为 SC 开发附加功能，以再次提供类似的灵活性。

注意： 制作独立应用已知可用的版本：SC3.8.0、来自分支 [2a105f1] 的 SC3.9dev"https://supercollider.github.io/download".openOS；自行构建的 SC 版本可能会假设其 Platform.userAppSupportDir 被称作 .../SuperCollider/，而不是新制作应用的名称。

本指南的工作方式

本指南是一组脚本，可通过几个基本步骤创建基于 SuperCollider 的独立应用：

  1. 复制打开的 SuperCollider.app 或基于 SC3 的独立应用。
  2. 修正副本的 info 文件，使其使用自己的 userAppSupportDir

  3. 测试 Platform.userAppSupportDir 在新应用中是否独立！

    ... 然后开始针对具体项目进行适配：...

  4. 将活动的 quark 和扩展转移到新应用
  5. 将所用的项目文件夹复制到新应用
  6. 为其创建一个内部 startupFile
  7. 测试并调整，直到它实现你想要的功能

准备工作

  • 确保你的系统已准备好并安装了所有所需的 quark，且有一个可用的启动文件。（可以是非常简单的测试设置）
  • 阅读每一节，然后尝试一次性求值；若出现问题，再逐行求值，并告诉我哪里出现了哪些问题
  • 当你到达唤醒之吻时，分享并享受吧！

命名、复制并修复新应用

// 准备时，请在 Preferences->Interpreter 中检查您当前的配置：
// 您应该使用内部的 SCClassLibrary 和 HelpSource，
// 而不是外部 git 仓库！
// 要测试导出扩展，最好安装一些 quarks
// 或其他扩展，如 includePaths 中所示。

// 0 - 定义新应用的名称和位置 + 辅助函数
(
// 为新应用定义名称及其位置：
~newAppName = "StehAllein";
~newAppLocation = "~/Desktop".standardizePath;

// --- 此行以下无需更改 --- \\
// 一些辅助函数
~readText = { |path| File.readAllString(path); };
~writeText = { |path, string| File(path, "w").write(string).close; };
~copyFolder = { |orig, dest|
    var str = "cp -ir" + quote(orig) + quote(dest);
    str.postcs;
    unixCmd(str);
};

// 创建一些所需的路径和文件夹
~pathToThisApp = Platform.resourceDir.dirname.dirname;
~thisAppName = ~pathToThisApp.basename.splitext.first;
~pathToNewApp = ~newAppLocation +/+ ~newAppName ++ ".app";
~newAppResDir = ~pathToNewApp +/+ "Contents/Resources";
~newAppSupportDir = Platform.userConfigDir.dirname +/+ ~newAppName;
);


(
// 1. 用 newAppName 复制 thisApp：
// 在慢速硬盘上可能需要一段时间。
// 等待 RESULT = 0 出现！

if (File.exists(~pathToNewApp).not) {
    ~copyFolder.(~pathToThisApp, ~pathToNewApp);
    File.mkdir(~newAppSupportDir);
} { warn("supportDir % already exists.".format(~pathToNewApp)) };
);

(
// 2. 新应用中的修正：
// a. 通过替换名称来修复 Info.plist 文件：
~infoPlistPath = ~pathToNewApp +/+ "Contents/Info.plist";
// 获取其字符串，替换 SC 名称，再次写入
~infoString = ~readText.(~infoPlistPath);
~executableIndex = ~infoString.find("<key>CFBundleExecutable</key>");
~nameToReplace = ~infoString.copyRange(
    ~infoString.find("<string>", offset: ~executableIndex) + 8,
    ~infoString.find("</string>", offset: ~executableIndex) - 1
);

"replacing bundleName % in plist file at these locations: "
.postf(~nameToReplace.cs);
~foundNameLocs = ~infoString.findAll(~nameToReplace).postln;

~newInfoString = ~infoString.replace(~nameToReplace, ~newAppName );
~writeText.(~infoPlistPath, ~newInfoString);
// ~readText.(~infoPlistPath);

// b. 重命名二进制文件：
"renaming macos binary to: ".post;
// 新应用中的修复 - 2. 重命名应用文件夹内的二进制文件
unixCmd("mv -i"
    + quote(~pathToNewApp +/+ "Contents/MacOS/" +/+ ~nameToReplace)
    + quote(~pathToNewApp +/+ "Contents/MacOS/" ++ ~newAppName).postln
);
);


// 3. *** 第一次唤醒之吻的时间 *** //
unixCmd("open" + ~pathToNewApp);

// ... 以及独立性测试：
// 在新应用中，运行此代码：
Platform.userAppSupportDir.postcs;

注意： 这应当以 ~newAppName 结尾！如果它含有原始的 ~thisAppName（即你最初使用的名称，例如 ~/././SuperCollider），新应用将不会干扰 SuperCollider！因此，请再次删除该应用，并使用推荐的 SC3 版本重新开始（参见顶部的已测试列表）！

对项目的适配

退出新的独立应用，回到起始应用以执行：

  • 4. 覆盖 .startupFiles 以查看应用文件夹内部
  • 5. 为新应用创建演示项目文件夹和 loadfile
  • 6. 创建一个启动文件，用于加载项目的加载文件
  • 7. 将活动 quark 和扩展迁移到新应用
  • 8. 用你的文件、脚本等替换/填充项目文件夹
(
// 4. 编写一个类扩展文件，在应用中查找 startupFile，
// 在 Platform.resourceDir 中查找以实现自包含。
~overDir = ~newAppResDir +/+ "SCClassLibrary/SystemOverwrites";
File.mkdir(~overDir);
~writeText.value(~overDir +/+ "extModStartupFile.sc",
    "+ OSXPlatform {
    startupFiles {
        ^[Platform.resourceDir +/+ \"startup.scd\"];
    }
}
"
);
~overDir.openOS;
)

(
// 5. 编写一个基本的启动文件：
~startupCode =
"// basic example startup file for osx standalone.
// 避免与默认 SC 服务器冲突
s.addr.port = 57105;

// 启动服务器并播放一小段声音
s.waitForBoot {
    {
        Line.kr(1, 0, 10, doneAction: 2) * SinOsc.ar(1000)
        * EnvGen.ar(Env.perc(0.01, 0.25), Impulse.kr(2, [0, 0.5]), 0.1)

    }.play;
};
";
~writeText.(~newAppResDir +/+ "startup.scd", ~startupCode);
(~newAppResDir +/+ "startup.scd").openOS;
)

// *** 是时候来个第二次唤醒之吻了 *** //
// 应运行启动文件并播放声音：
unixCmd("open" + ~pathToNewApp);


// 6. 对于较大的项目：
//    创建一个示例项目文件夹，其中包含一个 loadfile，
//    以及一个指向该 loadfile 的启动文件。
(
~projDirName = ~newAppName ++ "_files";
~projDir = ~newAppResDir +/+ ~projDirName;
File.mkdir(~projDir);
~projDir.openOS;

~loadFileCode =
"\"*** startup file for % loading.\".postln;
\"*** My Platform.userAppSupportDir is: \".postln;
Platform.userAppSupportDir.postcs;
thisProcess.nowExecutingPath.openOS;

// 如有需要，在此处配置服务器选项：
s.options.memSize = 8192 * 16;
// 将服务器端口移离默认值（57110）
// 以避免与 SuperCollider 本身产生干扰/冲突：
s.addr.port = 57105;

s.waitForBoot {
    \"*** server booted, plays ping.\".postln;
    Env.perc.test;

    \"*** loading files next ? \".postln;
    // 把你的加载序列放在这里：
    // \"loadX.scd\".loadRelative;
    // s.sync; // 例如在加载缓冲区时
     // 1.wait;
     // \"loadY.scd\".loadRelative;
};"
.format(~newAppName);

~loadfilepath = ~projDir +/+ "00_loadMe.scd";
~writeText.value(~loadfilepath, ~loadFileCode);
~loadfilepath.openOS;


// 编写一个指向加载文件的启动文件：
~startupCode =
"// example startup file for osx standalone.
// 在此项目文件夹中运行 loadfile：
%.loadRelative;
".format((~projDirName +/+ ~loadfilepath.basename).cs);

~writeText.(~newAppResDir +/+ "startup.scd", ~startupCode);
(~newAppResDir +/+ "startup.scd").openOS;
)

// *** 第三次唤醒之吻的时间 *** //
unixCmd("open" + ~pathToNewApp);

// 这应该会打开新的应用，以及它的 loadfile！


// 7. 在新应用内创建一个内部扩展文件夹，
// 并将所有当前活动的 includePaths 复制到那里：
(
~newAppQuarksDir = ~newAppResDir +/+ "InternalExtensions";

// 将我当前 quarks includePaths 中的所有文件夹
// 复制到 Resources/SCClassLibrary 以冻结它们：
File.mkdir(~newAppQuarksDir);

~pathsToCopy = LanguageConfig.includePaths.reject { |path|
    ["SCClassLibrary", "HelpSource"].includesEqual(path.basename)
};

~pathsToCopy.collect(_.basename).sort.printcsAll;

if (~newAppQuarksDir.pathMatch.notEmpty) {
    "/*** copying Quarks : ***/".postln;
    ~pathsToCopy.do { |path|
        unixCmd(
            "cd" + quote(~newAppQuarksDir) ++ ";" ++
            " cp -ir" + quote(path).postln + ".");
    };
};
"";
)
// 现在新的应用文件夹包含了所有的 quark：
~newAppQuarksDir.openOS;

// 打开新应用：
unixCmd("open" + ~pathToNewApp);

// 并且在新应用中，运行此命令以创建一个自包含的启动配置文件：
(
// 使用内部扩展——移动应用时请重复此操作！
LanguageConfig.addIncludePath(Platform.resourceDir +/+ "InternalExtensions");
// 排除默认值
LanguageConfig.addExcludePath(Platform.userExtensionDir);
LanguageConfig.addExcludePath(Platform.systemExtensionDir);
LanguageConfig.store;

// 检查内部路径是否已正确存储：
LanguageConfig.includePaths.last;
// 这不应为空：
LanguageConfig.includePaths.last.pathMatch.postln;
)

// 仍在新应用中，现在重启解释器！
// - 添加的 quarks 现在应该已经存在。

注意： 你可以使用 Standalone quark 来确保应用保持关闭状态、继续使用其 InternalExtensions 目录，并继续忽略其 userExtensionDir 或 systemExtensionDir 中的任何内容。

// 在新应用中，执行：
Quarks.install("https://github.com/adcxyz/Standalone");
// 重启解释器，然后执行
Standalone.activate;
// 再次重启解释器，就完成了。


// 8. 现在，将你的项目文件放入项目文件夹，
// 调整加载顺序，
// 并测试直到一切完美运行……

// 分享并享受你的专属独立应用吧！
