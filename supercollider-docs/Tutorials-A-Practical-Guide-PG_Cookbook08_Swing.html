模式指南食谱 08：摇摆

将等分节奏转换为摇摆音符的滤波器模式

另请参见：Pattern Guide Cookbook 07: Rhythmic Variations、Pattern Guide Reference 01: Pattern Internals

将等分转换为“摇摆”

大多数 MIDI 音序器都有“摇摆”（swing）功能，它会根据音符的节拍位置以不同方式处理其时序。位于较强节拍位置的音符按时播放；位于较弱位置的音符则延迟某一拍的一部分。

在 SuperCollider 模式中，用等长的音符时值来表达节奏更为方便。为了模拟传统音序器的摇摆量化行为，拥有一种修改模式输出事件的方法会很有帮助，使节拍上较弱的音符发声稍晚，而无需原始模式了解音符的节拍位置。

Requirements

参数：基本节奏值

你应该能够对节拍的任何细分进行摇摆：八分音符、十六分音符、四分音符。如果这是 0.5（八分音符），那么四分音符将保持不变地播放。

参数：Swing 量

基本节奏中用于延迟较弱音符的比例。实际的延迟时间将是 base_value * swing_amount。

弱位音符

起音需要被后移，使用事件的 timingOffset（参见 Pattern Guide 08: Event Types and Parameters: Timing control）。此外，如果下一个音符处于更强的位置，则此音符需要相应缩短相同的量。

位置更强的音符

起音不会被移动时间；但是，如果下一个音符处于较弱的位置，则此音符需要稍微长一些，以补偿音符起始之间的额外时间。

非二倍细分

Swing 通常假定一拍会被分成两个音符。用相同的算法处理三连音、五连音或其他划分会产生令人困惑的节奏。因此，我们可能还需要一个参数 swingThreshold，用于对距离基础节奏值太远的音符禁用 swing。

Implementation

Pchain 将一个模式应用于另一个模式的结果。因此，如果我们能编写一个模式来修改来自源的事件，Pchain 将是组合它们的一种简便方法。

上述参数应在源模式中提供。或者，它们可以作为事件提供在 Pchain 的输入列表末尾。（Pchain 遵循函数组合的模型，以逆序求值其模式。参见 Pattern Guide 06c: Composition of Patterns。）

那么……深呼吸……

(
~swingify = Prout({ |ev|
    var now, nextTime = 0, thisShouldSwing, nextShouldSwing = false, adjust;
    while { ev.notNil } {
        // 当前时间就是上一次的“下一个”
        now = nextTime;
        nextTime = now + ev.delta;
        thisShouldSwing = nextShouldSwing;
        nextShouldSwing = ((nextTime absdif: nextTime.round(ev[\swingBase])) <= (ev[\swingThreshold] ? 0)) and: {
            (nextTime / ev[\swingBase]).round.asInteger.odd
        };
        adjust = ev[\swingBase] * ev[\swingAmount];
        // 这里的奇数表示我们处于弱拍上
        if(thisShouldSwing) {
            ev[\timingOffset] = (ev[\timingOffset] ? 0) + adjust;
            // 如果下一个音符不会摇摆，则此音符需要缩短
            if(nextShouldSwing.not) {
                ev[\sustain] = ev.use { ~sustain.value } - adjust;
            };
        } {
            // 如果下一个音符将摇摆，这个音符需要延长
            if(nextShouldSwing) {
                ev[\sustain] = ev.use { ~sustain.value } + adjust;
            };
        };
        ev = ev.yield;
    };
});
)

示例

p = Pbind(\degree, Pseries(0, 1, 8), \dur, 0.25);

p.play;  // 直连 16 分音符

// swingBase: 0.25：每隔一个 16 分音符被延迟
// swingAmount: 1/3：弱拍音符将被延迟 1/3 个 16 分音符
Pchain(~swingify, p, (swingBase: 0.25, swingAmount: 1/3)).play;

// 音符时值 = 两倍 swingBase，无摇摆（正确）
Pchain(~swingify, Pstretch(2, p), (swingBase: 0.25, swingAmount: 1/3)).play;

// 聆听不同摇摆量的结果
(
Ppar([
    // 16 分音符的 60%
    Pchain(~swingify, p, (swingBase: 0.25, swingAmount: 0.6, pan: -1)),
    // 16 分音符的 20%
    Pchain(~swingify, p, (swingBase: 0.25, swingAmount: 0.2, pan: 1, octave: 6))
]).play;
)

q = Ppar([

Swing 不应应用于三连音。注意，节奏值 1/6 会引入浮点舍入误差，因此我们需要略微提高阈值。(1/6)+(1/6)+(1/6) 与八分音符的偏差在 0.05 以内，但 1/6 不是，从而使三连音音符原样通过。

// 摇摆阈值：加入几个三连音
(
Pchain(
    ~swingify,
    Pbind(
        \degree, Pseries(-7, 1, 15),
        \dur, Pwrand([Pn(0.25, 2), Pn(1/6, 3)], [0.7, 0.3], inf)
    ),
    (swingBase: 0.25, swingAmount: 0.2, swingThreshold: 0.05)
).play;
)

Explanation

如上所述，有两个因素决定该音符是否应被延迟：

它是否足够接近基础节奏网格？

将当前时间舍入到网格上，实际时间与舍入后时间的差值必须小于阈值：(now absdif: now.round(ev[\swingBase])) <= (ev[\swingThreshold] ? 0)。

它是否处于较弱的节拍位置？

除以基准值后，较强位置得到偶数，较弱位置得到奇数：(now / ev[\swingBase]).round.asInteger.odd。

还有一点小优化的空间。在前一个事件中，我们决定了下一个事件是否需要 swing。现在，在当前事件中，我们正在处理曾经的“下一个”。因此我们可以直接复制上次的 nextShouldSwing 旧值，而不必重新进行计算。（注意这要求开始时 nextShouldSwing = false——因为第一个事件的 now 始终为 0，因此永远不可能 swing。）

yield 是个有点奇特的的方法。它不会立即返回结果，而是把让出的值传递给那个对流调用 next 的代码块，然后暂停。之后，下一次调用 next 时，yield 方法返回，其值取自 next 的参数。在这里，该值就是当前正在处理的事件，所以我们需要将它重新赋值给 ev，然后循环回去。

这是在例程中处理来自 next 的输入值的正常、正确方式。

        ev = ev.yield;
