HID

该类提供对人类输入设备的访问，简称 HID，例如操纵杆、游戏手柄、鼠标、键盘等。

Object

参见：HIDFunc、Working with HID、HIDElement、HIDCollection、HIDUsage、HIDInfo

说明

人类输入设备可用作制作音乐的控制器。此类以简单透明的方式为你提供对它们的访问。

这一 SuperCollider 的 HID 访问实现的开发由 SuperCollider 社区和 BEK，Bergen Elektronisk Kunst，挪威卑尔根资助，http://www.bek.no

Introduction

通常，使用人体输入设备遵循以下方案：

查找可用设备：

HID.findAvailable;

打印可用设备的可读列表：

HID.postAvailable;

打开特定设备：

~myhid = HID.open(1103, 53251);

为特定元素设置动作：

~myhid.elements[1].action = { |...args| args.postln };

完整介绍请参阅 Working with HID。

类方法

查找设备

HID.findAvailable

查询操作系统中有哪些 HID 设备已连接到系统并可以访问。使用 HID 时，这是你需要执行的第一个方法，之后才能访问任何设备。

返回值：

可用设备的 IdentityDictionary

HID.available

可用设备的字典，或者更确切地说，是 HIDInfo 实例中关于它们的信息，由 findAvailable 方法填充

返回值：

一个 IdentityDictionary

HID.postAvailable

列出可用 HID 设备及其属性的人类可读列表（另见 HIDInfo）

HID.findBy(vendorID, productID, path, serial, releaseNumber)

通过指定设备的一个或多个特征，在可用设备字典中查找设备

参数：

vendorID

设备的供应商 ID，这是由设备自身编码的数字，并且在各个平台上保持一致。

productID

设备的 product ID，这是由设备本身编码的数字，且在各平台上保持一致。

path

设备的路径，这是由操作系统定义的路径，因此在不同平台上并不相同，但它是区分具有相同供应商 ID 和产品 ID 的设备所必需的。

serial

设备的序列号。这取决于操作系统，例如在 Linux 上不会设置。

releaseNumber

设备的发布编号，这是由设备自身编码的数字，在各平台上相同。

返回值：

一个与搜索查询匹配的设备的 IdentityDictionary，如果未提供参数则为 nil

HID.availableUsages

来自所有 HID 的可用用途字典，在设备打开和关闭时自动填充。

返回值：

一个 IdentityDictionary

HID.postAvailableUsages

发布可用 HID 用法及其属性的可读列表（另请参见 HIDElement 和 HIDUsage）

打开设备

HID.open(vendorID, productID, path)

使用给定的 vendorID、产品 ID 以及可选的路径打开设备。

参数：

vendorID

设备的供应商 ID

productID

设备的 product ID

path

（可选）操作系统中的路径，例如 Linux 上的 "/dev/hidraw0"。如果未指定，该方法将在设备列表中查找匹配的设备，并打开找到的第一个匹配项。

返回值：

HID 设备 - HID 的一个实例。

HID.new( ... args)

与 HID.open 相同

HID.openPath(path)

使用设备在操作系统中的路径打开设备

参数：

path

操作系统中的路径，例如 Linux 上的 "/dev/hidraw0"

返回值：

HID 设备 - HID 的一个实例。

HID.openAt(index)

使用设备在可用设备字典中的索引打开设备

参数：

index

可用设备字典中的索引

返回值：

HID 设备 - HID 的一个实例。

HID.openDevices

已打开设备的字典

返回值：

一个 IdentityDictionary

向 HID 事件添加函数

每当来自已打开的 HID 设备的数据到达时，会触发两种类型的动作。一个针对传入的元素数据的动作，以及一个针对设备的动作，表示其中一个元素发生了改变。在大多数情况下你会想使用第一个动作；只有在解析元素数据的顺序很重要的情况下，你可能想使用第二种类型——例如在处理对时间要求非常精确的按钮按下组合时。

可以在三个层级上设置动作：

  • 在全局级别——对任何 HID 设备、任何元素调用
  • 在设备层面——针对特定设备、对任意元素调用
  • 在元素级别——针对特定设备的特定元素调用

或者，你也可以使用 HIDFunc 接口。

HID.debug

HID.debug = value

当设置为 true 时，来自任何已打开 HID 设备的传入数据将被打印到 post 窗口。

HID.action

HID.action = function

设置或获取在从设备接收元素数据时要执行的动作。该函数将被传递以下参数：值（映射在 0 和 1 之间）、原始值、元素用途页、元素用途、元素 id、设备 id、设备（一个 HID 的实例）。

参数：

function

从设备接收元素数据时要执行的函数

HID.addRecvFunc(function)

向内部的 FunctionList 添加一个函数，每当来自已打开设备的元素数据到达时都会对该函数求值。传递给该函数的参数如上文所定义。如果你想要从自己编写的类向 HID 函数添加操作，同时仍保留从用户代码即时添加操作的选项，请使用此方法。

参数：

function

要添加到列表中的函数。

HID.removeRecvFunc(function)

向内部 FunctionList 添加一个函数，每当设备有数据传入时都会对其进行求值。

参数：

function

要从列表中移除的函数，这必须是对最初添加到列表中的 Function 的引用

HID.deviceAction = function

设置一个动作或函数，每当任何设备的元素发生更新时执行。

参数：

function

接收到来自设备的数据时要执行的函数

HID.addDevFunc(function)

向内部 FunctionList 添加一个函数，当有数据从设备传入时该函数将被求值。

参数：

function

接收到来自设备的数据时要执行的函数

HID.removeDevFunc(function)

向内部 FunctionList 添加一个函数，每当设备有数据传入时都会对其进行求值。

参数：

function

要从列表中移除的函数，这必须是对最初添加到列表中的 Function 的引用

管理 HID 子系统

以下方法在内部用于初始化和终结 HID 子系统，但在少数情况下你可能希望手动管理这些方法。

HID.initializeHID

初始化 HID 子系统，该方法在调用 findAvailable 方法时会被自动调用。

HID.running

指示 HID 子系统是否正在运行。

HID.closeAll

如果在 Shutdown 时 HID 子系统已初始化，此方法会被自动调用。为了节省系统资源，可以手动停止它。此方法将关闭所有已打开的 HID 设备。

实例方法

.elements

一个 IdentityDictionary，保存该设备的所有元素，即控件

.findElementWithUsage(elUsage, elUsagePage)

查找具有特定 usage 和 usagePage 的所有元素。

参数：

elUsage

元素的使用索引

elUsagePage

元素的使用页面

返回值：

包含所找到元素的数组

.getElementWithID(elid)

获取具有给定索引的元素

参数：

elid

元素的索引

返回值：

HIDElement

.close

关闭 HID 设备，关闭设备是异步的。你可以设置一个 closeAction（见下文），它将在设备关闭时执行。

.isOpen

如果设备已打开则返回 true，如果设备已关闭则返回 false。

返回：一个布尔值

.collections

一个 IdentityDictionary，保存设备的所有集合，即控件组

为设备添加功能

.debug

.debug = value

参数：

(function)

.deviceAction

.deviceAction = value

参数：

发布关于该设备的可读信息

.postInfo

以人类可读的格式发布此设备的 HIDInfo

.postCollections

以人类可读的格式发布关于此设备所有集合的信息

.postElements

以人类可读的格式发布此设备所有元素的信息

.postInputElements

以人类可读的格式发布关于此设备所有输入元素的信息

.postOutputElements

以人类可读的格式发布关于此设备所有输出元素的信息

以人类可读的格式发布有关此设备所有用途的信息

设备的属性

.info

获取此设备的 HIDInfo

返回值：

HIDInfo 的一个实例

.usage(collectionID: 0)

获取此设备某个集合的使用索引，或设备的主动使用（如果无参数调用）。

参数：

collectionID

要检索其用法的集合。默认值为 0，应定义该设备的主要用法。

返回值：

此设备的使用索引

.usageName(collectionID: 0)

获取此设备集合的使用名称，或设备的主用途（如果调用时没有参数）。该名称是按用途索引从标准化 HID 用途表中查找的。

参数：

collectionID

要检索其用法的集合。默认值为 0，应定义该设备的主要用法。

返回值：

此设备的使用名称

.usagePage(collectionID: 0)

获取此设备的一个集合的 usage page 索引，或设备的主页面（如果不带参数调用）。名称通过 usage page 索引从标准化的 HID usage 表中查找。

参数：

collectionID

要检索其 usage page 的集合。默认值为 0，它应定义设备的主要用途。

返回值：

此设备的用途页索引

.pageName(collectionID: 0)

获取此设备某个集合的页面名称，或设备的首页面（如果调用时无参数）。该名称使用 usage page 索引从标准化 HID 用途表中查找。

参数：

collectionID

要检索用法页名称的集合。默认值为 0，应定义设备的主要用法。

返回值：

此设备的 usage page 名称

.vendor

获取此设备的供应商 id

返回值：

供应商 id

.product

获取此设备的产品 id

返回值：

产品 ID

.usages

检索该设备各元素的使用情况。

返回值：

一个 IdentityDictionary，以用途为键，以元素列表为对应的元素

示例

HID.findAvailable; // 检查连接了哪些设备
~myhid = HID.open(1103, 53251); // 打开 Run'N' Drive 游戏控制器

s.boot; // 启动服务器

Ndef(\sinewave, { |freq = 500, amp = 0.1| SinOsc.ar(freq, 0, amp * 0.2) });
Ndef(\sinewave).play;

~freqRange = [500, 5000, \exponential].asSpec; // 创建一个频率范围

HIDdef.usage(\freq, { |value| Ndef(\sinewave).set(\freq, ~freqRange.map(value)) }, \X);
HIDdef.usage(\amp, { |value| Ndef(\sinewave).set(\amp, value) }, \Y);
