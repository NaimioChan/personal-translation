Interpreter

解释器定义了一个上下文，在其中编译和执行交互式命令。

Object

另请参见：如何使用解释器

说明

解释器是一个在运行时处理代码翻译和执行的对象。它负责运行任何程序代码并为其定义上下文。

(
a = 5 + 7;
this.cmdLine.postln;
)

类方法

实例方法

Accessing

在解释器中，this 指解释器本身，例如：this.postln

解释器定义了全局变量（a … z），可用于交互式编程。除这些单字母变量（“解释器变量”）外，所有变量都必须用关键字 var 定义（参见：Assignment Statements 以及 Scoping and Closure）。

// 典型用法
a = 4;
b = 3;
b = b + a;

// 某个声音
a = Synth(\default);
g = fork { loop { 0.1.wait; a.set(\freq, 200 + 20.0.rand2.postln) } };
g.stop; a.free;

// 所有变量的概览
this.inspect;

注意： 使用这些变量时需要格外小心——由于它们是全局的，会一直保留在内存中，一段代码可能会干扰另一段代码。按照惯例，变量 s 绑定到默认服务器（Server），不应更改。

.clearAll

将变量 a 到 z 的值设为 nil。

x = 123;
x.postln;
this.clearAll;
x.postln;

编译并解释

.interpret(string ... args)

编译并执行一个字符串。

this.interpret("(123 + 4000).postln");

.interpretPrint(string ... args)

编译并执行一个 String，并打印结果。

this.interpretPrint("123 + 4000");

.compile(string)

编译一个 String 并返回一个 Function。

(
z = this.compile("(123 + 4000).postln");
z.postln;
z.value;
)

.compileFile(pathName)

读取 pathName 处的文件，编译它并返回一个 Function。该文件自然必须包含有效的 SuperCollider 表达式。这将不会编译类定义，只编译表达式。

.executeFile(pathName ... args)

读取 pathName 处的文件，编译并执行它，返回结果。自然，该文件必须包含有效的 SuperCollider 表达式。这不会编译类定义，只编译表达式。

.cmdLine

.cmdLine = value

返回先前解释执行的代码。

1 + 2;
this.cmdLine

.codeDump

.codeDump = value

此解释器变量可以设置为使用任何成功编译的代码来求值函数。例如参见 History 类。

a = []; // 存储所有在 a 中评估的代码
this.codeDump = { |code| a = a.add(code) };
1 + 3;
f = { "hallo" };
a.postcs;
codeDump = nil; // 重置为 nil。

.preProcessor

.preProcessor = value

若将其设为一个函数，则所有交互式执行的代码都会在解析和解释之前经由该函数处理。这主要用于开发基于 SuperCollider 编辑环境的领域特定 live coding 语言。

此函数由 Interpreter: -interpretPrintCmdLine 调用，带有两个参数：代码字符串和解释器本身。

// 虽然有点傻但很简单：为每个 SinOsc 理解一个 Saw
this.preProcessor = { |code| code.replace("SinOsc", "Saw") };

{ SinOsc.ar(200) * 0.1 }.play;

preProcessor = nil; // 重置为 nil。
