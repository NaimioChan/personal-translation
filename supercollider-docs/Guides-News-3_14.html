3.14 中的新特性

SC 3.14 中的新闻摘要

值得注意的变更与新增

以下是 SC 3.14 中变更的要点。详情参见下文各节。

  • Sclang 函数现在支持通过 { |...args, kwargs| kwargs }. 收集任意关键字参数。
  • 修复了多个 UGens 的初始化采样。
  • 文档现在也可以像 IDE 一样应用主题。
  • 由于更新了捆绑的 boost 库，在 SuperCollider 3.13 下可用的 FluCoMa UGen 不再与 3.14 兼容！请访问 https://github.com/flucoma/flucoma-sc 查看兼容版本。
  • 尽管这些并非那么多面向用户的变化，但进行了无数结构性升级：我们迁移到了 qt6，添加并改进了测试，更新了第三方库，针对最新的构建工具更新了构建系统，并采用了新的开发组织结构。

对 UGen 的更改（可能影响其输出值）现已详细记录在单独文档中：UGen Changelog。

破坏性变更

  • Phasor：修复初始化采样：不再忽略第一个采样上的 trig。如果代码依赖于这一缺陷，行为可能会发生改变。作者 @elgiano，见 https://github.com/supercollider/supercollider/pull/6833
  • 修复 mod 仅对负整数取模的问题。方法 modSeaside 可用于恢复原始行为，如此命名是出于不那么显而易见的原因，作者为 @passyur 和 @telephon https://github.com/supercollider/supercollider/pull/6699
  • Splay 和 SplayAz 的电平补偿已修复并变得更加灵活，这可能会改变整体电平分布，由 @adcxyz 完成 https://github.com/supercollider/supercollider/pull/6804.
  • 显式地将 SetResetFF 标记为单极性，这会在使用 range 时改变输出电平——例如，如果你使用了 .range(0, 1)，迄今为止它一直假定为双极性默认值并返回 [0.5, 1] 的范围。）由 @capital-G 在 https://github.com/supercollider/supercollider/pull/6023 中提交
  • Set.remove 现在返回被移除的项，由 @JordanHendersonMusic 在 https://github.com/supercollider/supercollider/pull/6409 中实现

  • 修复 Dictionary 的 trueAt，作者 @telephon，见 https://github.com/supercollider/supercollider/pull/6001，以及 @mtmccrea，见 https://github.com/supercollider/supercollider/pull/6335。这会将行为改变如下：

General

Added

到目前为止，额外的函数参数和方法参数可以通过如下语法捕获到数组中：f = { |a, b ... args| args }; f.(1,2,3,4) // returns [3, 4]。之前无法使用除显式给出的关键字（此处为 a 和 b）之外的其他关键字。现在还可以通过如下语法捕获任意关键字参数：f = { |a, b ... args, kwargs| kwargs }; f.(x:3, y:4) // returns [\x, 3, \y, 4]。

新的关键字参数 capture 由 @JordanHendersonMusic 在 https://github.com/supercollider/supercollider/pull/6339 中实现，与 @telephon 和 @capital-G 合作完成。

此更改使许多新功能成为可能，例如

  • performList、functionPerformList、superPerform、tryPerform、doesNotUnderstand 现在接受 kwargs。这使得消息转发更加灵活和完整。
  • 需要一个新的 superPerformArgs 方法来避免将关键字参数向上传递给父类时出现无限循环，由 @JordanHendersonMusic 在 https://github.com/supercollider/supercollider/pull/6568 中完成
  • *newCopyArgs 中的关键字允许在具有许多实例变量的类中编写更简洁的构造函数，现在你可以编写像 ^super.newCopyArgs(freq:440) 这样的表达式，由 @JordanHendersonMusic 贡献于 https://github.com/supercollider/supercollider/pull/6398
  • 关键字参数现在可用于组合函数和高阶函数（Maybe、CallOnce、UnaryOpFunction、BinaryOpFunction、NaryOpFunction、FunctionList、UnaryOpFunctionProxy、BinaryOpFunctionProxy、NAryOpFunctionProxy），因此例如你可以写 f = { |x, y = 1| x + y } * { |x, y = 2| x ** y }; f.(x:2, y:6)，由 @telephon 提交于 https://github.com/supercollider/supercollider/pull/6786
  • 为所有对象新增一个方法，显式地将关键字参数作为列表传递：performArgs(selector, args, kwargs)
  • FunctionDef 上用于查明其参数形式的方法：varArgsValue、hasVarArgs、hasKwArgs。
  • 现在向 Scale 和 Tuning 选择器传递参数可以正常工作：Scale.ionian(tuning:Tuning.kirnberger)（这是最初要解决的问题）。
  • 对象原型：IdentityDictionary 中的伪方法接受关键字参数并正确传递它们。因此现在可以这样写：u = (dive:{|self, speed, depth| ... }); u.dive(depth: -5)
  • DoesNotUnderstandError 会提示关键字参数的相关信息。
  • 让 Pbind 支持 kwargs（这种语法现在可用：Pbind(note: Pseq([-3, -2, 0, 1, 6, 13]), dur: 0.05, amp: 0.1).play），由 @JordanHendersonMusic 和 @telephon 提交于 https://github.com/supercollider/supercollider/pull/6530
