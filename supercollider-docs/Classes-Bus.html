Bus

服务器上总线的表示

Object

另请参阅：Server

说明

服务器上音频总线或控制总线的客户端表示。封装了 Bus 可以接收的所有 OSC 消息。管理总线索引的分配与释放，因此你无需担心冲突。控制总线、音频总线以及输入和输出总线的数量是固定的，在服务器启动后无法更改。

更多信息请参见 Client vs Server 和 Server Architecture。

请注意，使用 Bus 类来分配多通道总线并不会“创建”多通道总线，而只是通过该总线所属的 Server 对象的总线分配器保留一系列相邻的总线索引。abus.index 仅返回这些索引中的第一个。当将 Bus 与 In 或 Out UGen 一起使用时，没有什么能阻止你从更大的范围读取或写入，或硬编码到已分配的总线。你需要负责确保通道数匹配且不存在冲突。

不应在 SynthDef 内创建或修改 Bus 对象。

注意： 最低的 n 个总线索引保留给硬件输出和输入，其中 n = server.options.numOutputBusChannels + server.options.numInputBusChannels 硬件输出总线0 .. (numOutputBusChannels - 1)硬件输入总线numOutputBusChannels .. (numOutputBusChannels + numInputBusChannels - 1)第一个私有总线索引numOutputBusChannels + numInputBusChannels 不要尝试将硬件 I/O 总线用作私有总线。

类方法

Bus.control(server, numChannels: 1)

在服务器上分配一个控制总线。

参数：

server

Server。默认为 Server.default。

numChannels

要分配的通道数

Bus.audio(server, numChannels: 1)

在服务器上分配一个私有音频总线。

参数：

server

Server。默认为 Server.default。

numChannels

要分配的通道数

Bus.alloc(rate, server, numChannels: 1)

分配一个由 rate 指定速率的 bus。

参数：

rate

速率符号：\control 或 \audio

server

Server。默认为 Server.default。

numChannels

要分配的通道数

Bus.new(rate: 'audio', index: 0, numChannels: 2, server)

此方法不分配总线索引，而是假定你已经分配了相应的总线索引，并且可以自行提供。

讨论：

可以通过最低的索引来访问硬件 I/O 总线（请参阅 Description 部分中的Note）：

  • 硬件输出总线的前两个通道：

    a = Bus(\audio, 0, 2)

  • 硬件输入总线的第一个通道，如果硬件输出通道设置为 2：

    b = Bus(\audio, 2, 1)

Bus.newFrom(bus, offset, numChannels: 1)

此方法创建一个新总线，它是该总线的子集。新总线将与输入总线的速率相同。offset 是给定总线中的索引。numChannels 是期望的通道数。如果 offset 与 numChannels 的组合超出输入总线的范围，则会抛出错误。

实例方法

.index

获取 Bus 的索引。通常你不需要这样做，因为 Bus 的实例可以直接作为 UGen 输入或 Synth 参数传递。

.free(clear: false)

将这些总线索引归还给服务器的总线分配器，以便它们可以被重新分配。

.rate

获取 Bus 的速率。这是一个符号，可以是 \control 或 \audio。

.numChannels

获取 Bus 的通道数。

.server

获取 Bus 的服务器对象。

.asMap

返回值：

一个符号，由字母 'c' 或 'a'（分别表示控制或音频）后跟总线的索引组成。这可用于在设置 synth 节点的控制输入时，将输入映射到控制总线。

讨论：

关于将控件映射到总线的更多信息，请参见 Node 帮助文件。

(
a = Bus.control(s, 1).set(440);
b = Bus.control(s, 1).set(0.01);
)
(
SynthDef(\rlpf, { |out, ffreq, rq|
    Out.ar(out, RLPF.ar(WhiteNoise.ar(0.2), ffreq, rq))
}).play(s, [\ffreq, a.asMap, \rq, b.asMap]);
)

.subBus(offset, numChannels: 1)

获取一个作为此总线子集的新 Bus（参见 newFrom）。

异步控制总线方法

以下命令仅适用于控制总线且为异步操作。如需同步访问控制总线，请参阅 同步控制总线方法。

.value

.value = value

来自父类：Object

将所有声道设置为该浮点值。此命令是异步的。

.set( ... values)

控制总线每个通道的值列表。提供的值列表不应超过通道数。此命令是异步的。

.setn(values)

类似 set，但接受数组作为参数。

.get(action)

获取此控制总线的当前值。此命令是异步的。

参数：

action

一个函数，当服务器响应时会被求值，并将总线的当前值作为参数传入。对于单通道总线，这将是一个浮点数；对于多通道总线，则是一个浮点数数组。默认动作会发布总线值。

.getn(count, action)

获取此控制总线的当前值。此命令是异步的。

参数：

count

要读取的通道数，从此总线的第一个通道开始。

action

一个函数，当服务器响应时会被求值，当前总线值以数组形式作为参数传入。

同步控制总线方法

对控制总线的同步访问仅适用于具有共享内存接口的服务器。你可以使用 hasShmInterface 检查服务器是否提供这些方法。

注意： 在 3.5 之前，内部服务器可通过共享控制总线和 SharedIn 与 SharedOut 控制。这些类已废弃，将被移除。

.getSynchronous

获取此控制总线的当前值。此命令是同步的。

返回值：

控制总线的值。

.getnSynchronous(count)

获取此控制总线的当前值。此命令是同步的。

参数：

count

要读取的通道数，从此总线的第一个通道开始。

返回值：

值的数组。

.setSynchronous( ... values)

控制总线每个通道的值列表。提供的值列表不应大于通道数。此命令是同步的。

.setnSynchronous(values)

与 setSynchronous 相同，但接受一个数组作为参数。

多通道总线的便利方法

.setAt(offset ... values)

从 offset 开始设置总线值。异步。

.setnAt(offset, values)

将总线设置为所提供的值列表。异步。

.setPairs( ... pairs)

通过索引、值、... 成对设置总线值，异步

像 UGen 一样使用总线

.kr(numChannels, offset: 0)

.ar(numChannels, offset: 0)

像 UGen 一样使用总线。numChannels 和 offset 参数可用于获取总线的一个子集。

讨论：

默认情况下，使用所有总线通道。例如，在 8 通道总线中，

  • b.kr 将返回一个 In ugen，从总线的全部 8 个通道读取；
  • b.kr(4) 将返回前四个声道，并且
  • b.kr(2, 5) 将返回两个声道，从该总线索引为 5 和 6 的声道开始。

OSC Bundle 方法

.getMsg

返回一个类型为 /c_get 的 msg，用于 osc 束。

.getnMsg(count)

返回一个类型为 /c_getn 的消息，用于 osc 数据包。

参数：

count

要读取的通道数，从该总线的第一个通道开始。默认值为该总线的 numChannels。

.setMsg( ... values)

返回一个类型为 /c_set 的 msg，用于 osc 束。

.setnMsg(values)

返回一个类型为 /c_setn 的消息，用于 osc 数据包。

参数：

values

一个值的数组，这些值将被设置到相邻的通道上，从此总线的第一个通道开始。

.fillMsg(value)

返回一个类型为 /c_fill 的消息，用于 osc 数据包。

参数：

value

此总线的通道将被设置成的值。

用示波器监视

.scope: METHOD NOT FOUND!

a = { SinOsc.ar([330, 440], 0, 0.4) }.play(s, b) // 如果你只有两个声道，就不会听到这个
b.scope

a.free;
b.free;

Bela

.belaScope(scopeChannel)

来自扩展 /usr/local/share/SuperCollider/SCClassLibrary/Common/Audio/Bela/BelaScope.sc

将此总线的所有通道作用域到 Bela 的示波器（所需设置请参见 BelaScope）。要求此总线位于运行于 Bela 上的服务器上，因而该服务器能够使用 BelaScope。

参数：

scopeChannel

Bela 示波器开始进行示波显示的通道。这必须是一个非负数，且在示波开始后无法更改。

返回值：

一个 Synth，将此总线链接到 BelaScope 的总线。

示例

s.boot;

(
// 可以用来玩的东西
SynthDef(\help_Bus, { |out = 0, ffreq = 100|
    var x;
    x = RLPF.ar(LFPulse.ar(SinOsc.kr(0.2, 0, 10, 21), [0, 0.1], 0.1),
            ffreq, 0.1)
            .clip2(0.4);
    Out.ar(out, x);
}).add;

)

x = Synth(\help_Bus);

// 获取总线
b = Bus.control(s);

// map the synth's second input (ffreq) to read
// from the bus' output index
x.map(1, b);

// 通过设置总线的值，你向总线的每个声道发送 /c_fill 消息，
// 将其设置为提供的浮点值
b.value = 100;
b.value = 1000;
b.value = 30;

// 由于这是单声道总线，效果相同
b.set(300);
b.numChannels.postln;

// 多声道：b.set(300, 350);
// 获取当前值。这是异步操作，因此不能指望它立即发生。
(
a = "waiting";
b.get({ |value| a = value; ("after the server responds a is set to:" + a).postln });
("a is now:" + a).postln;
)

x.free;

    // 总线也可以像 UGen 一样与 kr 或 ar 一起使用：
(

SynthDef(\help_Bus, { |out|
    var ffreq = b.kr;
    Out.ar(out,
        RLPF.ar(
            LFPulse.ar(SinOsc.kr(0.2, 0, 10, 21), [0, 0.1], 0.1),
            ffreq, 0.1
        ).clip2(0.4)
    );
}).play;
)

b.free; // 释放它以便可以重新分配！


// 使用并设置多声道总线：

(
b = Bus.control(s, 4);

x = SynthDef(\helpBusMulti, { |out|
    var freqs = b.kr;
    Out.ar(out, Splay.ar(SinOsc.ar(freqs) * Decay2.ar(Dust.ar(10 ! 4), 0.001, 0.1)) * 0.5);
}).play;
)

    // 设置从索引 0 开始的 bus：
    // 这些方法都不会检查索引是否保持
    // 在 bus 的范围内。

b.set(234, 345, 456, 567);
b.getn;
b.setn([100, 200, 300, 400]);
b.getn;

    // 获取各个独立通道
b.setAt(3, 500);
b.getn;
b.setAt(1, 300, 400);
b.getn;
b.setnAt(1, [250, 350]);
b.getn;
    // 通过成对的 index、value 设置……
b.setPairs(3, 600, 0, 200);
b.getn;

b.set(300, 500, 700, 900);

(    // 只获取前 2 个声道
x = SynthDef(\helpBusMulti, { |out|
    Out.ar(out, SinOsc.ar(b.kr(2)) * 0.2)
}).play;
)
b.set(300, 303);
x.free;

(    // 只是 channels[[2, 3]]；
y = SynthDef(\helpBusMulti, { |out|
    Out.ar(out, LFNoise2.ar(b.kr(2, 2)) * 0.2);
}).play;
)
b.setAt(2, 1200);
b.setAt(3, 2400);

y.free;
b.free;
