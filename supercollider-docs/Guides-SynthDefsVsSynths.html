SynthDef 与 Synth 的对比

使用预编译的 SynthDef，而非始终即时编译

在 SC2 中，Synth.play 是编译 ugenGraphFunc 并播放它的标准方式。每次执行 Synth.play，或生成一个新事件时，该函数都会被重新编译。另一方面，SC3 利用了所谓的 SynthDef。SynthDef 接受一个 ugenGraphFunc，并将其编译为一种服务器应用能够理解的字节码（类似于 Java 字节码）。服务器读取 SynthDef 并基于它创建一个 synth 节点。

SynthDef 可以预编译并保存到磁盘。任何保存在 synthdefs/ 目录中（或环境变量 SC_SYNTHDEF_PATH 所设置的任何目录中）的 def，都会在本地 Server 启动时被加载到内存中。如果新 Synth 中使用的 def 已经编译并加载，那么创建新 Synth 时的 CPU 峰值会比 SC2 中少得多。

SynthDef 也可以被编译并加载到服务器中，而无需将它们写入磁盘。这可以在演出过程中完成。

这样做的缺点是，预编译的 SynthDef 缺少了一些编程灵活性，而这是 SC2 的一大优势。不过，通过设置和更改参数（这些参数是你内建在 ugenGraphFunc 中的），以及通过 Rand 和 TRand 等新的 UGen，大部分灵活性得以恢复。

在需要最大灵活性时，仍然可以即时编译并发送 SynthDef，不过这会带来类似 SC2 的 CPU 尖峰以及少量消息延迟。

重要的是要理解，创建和发送 SynthDef 是异步的。这意味着无法精确确定编译并发送一个 SynthDef 需要多长时间，因而也无法确定它何时可用于创建新的 Synth。一个简单的解决办法是将代码分块执行，一次选择一块。更复杂的方法是使用完成消息。SynthDef.play 会为你处理这一点，并返回一个 Synth 对象，之后你可以对它进行操作。参见下面的示例

另一个重要的区别是 SC2 中的 Synth 与 SC3 中的 Synth。后者是一个客户端对象，表示服务器上的一个 synth 节点。尽管它具有一些相同的方法，但它的工作方式并不相同。在 SC3 中没有顶层的 Synth，所有调度和其他 Synth 的创建都发生在其中。只有表示服务器上 synth 节点的 Synth 对象。这些对象可以在任何时间、任何作用域内创建。

示例

s.boot;

// 编译一个 SynthDef 并将其写入磁盘
(
SynthDef("Help-SynthDef", { arg out = 0;
    Out.ar(out, PinkNoise.ar(0.1))
}).writeDefFile;
)

// 编译、写入并加载到服务器
(
SynthDef("Help-SynthDef", { arg out = 0;
    Out.ar(out, PinkNoise.ar(0.1))
}).load(s);
)

// 将其加载到服务器而不写入磁盘
(
SynthDef("Help-SynthDef", { arg out = 0;
    Out.ar(out, PinkNoise.ar(0.1))
}).send(s);
)

// 用它创建一个 Synth
x = Synth.new("Help-SynthDef", s);
x.free;

// 用于编译并写入 SynthDef，然后在完成后在 Synth 中播放它的简写方法。
// 看起来很熟悉？
(
x = SynthDef("Help-SynthDef", { arg out = 0;
    Out.ar(out, PinkNoise.ar(0.1))
}).play(s);
)
// 以上仅在 def 已发送到服务器后才启动新的 Synth。
// 注意 SynthDef.play 返回一个 Synth 对象！

x.set(\out, 1); // 更改其中一个参数
x.free;

// 带有参数的 SynthDef，该参数会在每次创建新 Synth 时随机确定
// （多试几次以听出差异）
(
SynthDef("help-RandFreq", { arg out = 0;
    Out.ar(
        out,
        FSinOsc.ar(
            Rand(200.0, 400.0), // 频率在 200 到 400 Hz 之间
            0, Line.kr(0.2, 0, 1, doneAction: Done.freeSelf)
        )
    )
}).play(s);
)
