MIDIOut

发送 MIDI 消息

Object

参见：MIDIClient、MIDIIn、MIDI、Using MIDI

说明

MIDIOut 绑定到由操作系统定义的特定 MIDIEndPoint。

Linux 用户，或任何需要与 Linux 跨平台兼容的用户，应仔细阅读Linux 专属：连接和断开端口。

类方法

MIDIOut.new(port, uid)

创建一个新的 MIDIOut 实例。请注意，此方法在 Linux 上跨平台使用时并不安全，因为 port 参数的含义有所不同。详情请参见 Linux 专用：连接和断开端口。

参数：

port

macOS、Windows

MIDIEndPoint 在 MIDIClient.destinations 数组中的索引。

Linux

输出端口号。MIDIEndPoint("SuperCollider", "out0") 是端口 0；"out1" 是端口 1。在 Linux 中，此参数与 MIDIClient.destinations 完全无关。

uid

macOS / Windows

uid 是可选的；如果指定，它应该是该端口的 uid，即 MIDIClient.destinations[port].uid。如果你不提供 uid，正确的 uid 会为你填入（更简单）。

Linux

如下所述，使用 uid 是可选的。

MIDIOut.newByName(deviceName, portName, dieIfNotFound: true)

通过 MIDIClient.destinations 数组中查找到的名称来搜索 MIDI 输出设备。这比依赖索引更安全，因为索引会随着工作室设置的变化而改变。它也与 Linux 兼容。

// 列出已连接的输出端口及其名称：
MIDIClient.init;
MIDIClient.destinations;

MIDIOut.findPort(deviceName, portName)

按名称搜索已连接的 MIDIEndPoint。

// 列出已连接的输出端口及其名称：
MIDIClient.init;
MIDIClient.destinations;

MIDIOut.connect(outport: 0, device: 0)

来自扩展 /usr/local/share/SuperCollider/SCClassLibrary/Platform/linux/SystemOverwrites/extMIDIOut.sc

MIDIOut.disconnect(outport: 0, device: 0)

来自扩展 /usr/local/share/SuperCollider/SCClassLibrary/Platform/linux/SystemOverwrites/extMIDIOut.sc

仅限 Linux。MacOS 无需连接。在 Linux 上这是一个可选功能（见下文）。

实例方法

.sysex(packet)

向设备发送以 Int8Array 表示的 sysex 命令。

注意： 方法调用应包含完整的 sysex 消息。换句话说，它应以 0xF0（240 或 -16）开头，并以 0xF7（247 或 -9）结尾。

参数：

packet

要发送的数据字节的 Int8Array。

m = MIDIOut(0);

m.sysex(Int8Array[0xF0, 1, 2, 3, 0xF7]);  // OK!

m.sysex(Int8Array[1, 2, 3]);  // not OK

.latency

.latency = value

这设置 MIDI 事件发送的延迟时间。默认情况下，该值设为 0.2，以便与 Server.latency 保持一致。

注意： 在 Linux 上，对于某些 Linux 内核，如果延迟大于 0，似乎存在 ALSA 或内核 bug。如果 MIDIOut 似乎无法工作，请将延迟设为 0。

示例

MIDIClient.init;

m = MIDIOut(0);  // Linux 用户：MIDIOut(0, MIDIClient.destinations[0].uid)
m.noteOn(16, 60, 60);
m.noteOn(16, 61, 60);
m.noteOff(16, 61, 60);
m.allNotesOff(16);


MIDIIn.connect; // 1 端口 MIDI 接口
MIDIIn.sysex = { |uid, packet| [uid, packet].postln };
MIDIIn.sysrt = { |src, chan, val|  [src, chan, val].postln };
MIDIIn.smpte = { |src, chan, val|  [src, chan, val].postln };

m.sysex(Int8Array[0xF0, 0, 0, 27, 11, 0, 0xF7])

m.smpte(24, 16)
m.midiClock
m.start
m.continue
m.stop

使用模式发送 MIDI 事件

MIDIClient.init;
m = MIDIOut(0);  // Linux 用户：MIDIOut(0, MIDIClient.destinations[0].uid)

a = Pbind(\degree, Prand([1, 2, 3, [0, 5]], inf), \bend, Pwhite(0, 76, inf));


// 将一个 MIDI 事件链接到 pattern 中并播放（参见 Pchain）

(a <> (type: \midi, midiout: m)).play;

有关 'midi' 事件类型支持的 midi 命令列表，请参见 Pattern Guide 08: Event Types and Parameters: MIDI output。

Linux 特定：连接和断开端口

在 Linux 中，MIDIOut 的架构与其他操作系统不同。

在 macOS 和 Windows 中，MIDIOut 实例绑定到特定的目标 MIDI 设备。

Linux 中的 SuperCollider 使用 ALSA MIDI 层。ALSA MIDI 应用程序通过“虚拟输出端口”发送消息，该端口是 MIDIClient.sources 的成员之一。

MIDIClient.init;
MIDI Sources:
    MIDIEndPoint("System", "Timer")
    MIDIEndPoint("System", "Announce")
    MIDIEndPoint("Midi Through", "Midi Through Port-0")
    MIDIEndPoint("SuperCollider", "out0")
    MIDIEndPoint("SuperCollider", "out1")

此时，创建 MIDIOut(0) 会告知 SuperCollider，此 MIDIOut 对象应将消息定向到 MIDIEndPoint("SuperCollider", "out0")。（如果你以为 SuperCollider 是在向这个 MIDI 源发送消息，就会觉得这很奇怪。更准确的理解是，SuperCollider 是通过这个端口发送消息。因此，这个端口是系统其余部分的源。）

因此，MIDIOut(0) 对象默认不会到达任何目的地。用户需要使用 Qjackctl 等图形工具，或通过 MIDIOut 的 connect 方法，将目标设备连接到虚拟源端口。

m = MIDIOut(0);  // 使用虚拟源端口 "out0"
m.connect(1);  // 连接到 MIDIClient.destinations[1]

警告： MIDIOut: *new 的 port 参数在 Linux 上的含义与在 macOS 和 Windows 上完全不同。如果用户代码调用此方法并且需要跨平台兼容性，则用户有责任单独处理 Linux。用户代码可以使用 thisProcess.platform.name 检查平台（它返回 \osx、\linux 或 \windows 之一）。或者，为了兼容性，改用 *newByName。

MIDIOut: *new 还可以选择接受第二个参数，用于指定 MIDI 目标设备的 uid。如果 uid 非零，则：1/ 忽略 ALSA MIDI 跳线盘中的所有连接，并且 2/ 单条消息将直接发送到指定的设备。

MIDIOut: *newByName 按名称定位设备，并在新的 MIDIOut 对象中填充 uid。成功完成后，使用此方法创建的 MIDIOut 对象将具有非零 uid。

注意： 非零的 uid（无论是在 MIDIOut.new 中指定、由 MIDIOut.newByName 找到，还是稍后手动设置）不会创建或使用任何 ALSA MIDI 连接。它根本不是一种“连接”；而是一个参数，使传出的 MIDI 消息绕过 ALSA MIDI 连接，直接发送到某个特定设备。由于它不是连接，因此在 MIDI patchbay 界面中没有任何可显示的内容；用户不应期望看到这些 MIDIOut 对象的连接。另外，由于 uid 会绕过 patchbay 连接，同时指定 uid 并使用 .connect 是没有意义的。单个 MIDIOut 对象不应同时做这两件事。（这不会破坏任何东西，但 patchbay 连接会被忽略。）

Compatibility

  • MIDIOut.newByName("device", "port") -- 应在所有系统上兼容。
  • MIDIOut(index) -- macOS、Windows（index 是设备在 MIDIClient.destinations 中的索引）。注意，这种用法不兼容 Linux！macOS 和 Windows 用户不应期望 Linux 用户能够运行这种风格的连接。
  • MIDIOut(0, MIDIClient.destinations[index].uid) —— 仅限 Linux（index 是该设备在 MIDIClient.destinations 中的索引）。

macOS 特定：向其他应用程序发送 MIDI

打开 Audio MIDI Setup 应用程序。双击 IAC Driver 并勾选 "device is online"。

reinitialize:

MIDIClient.init(numIns, numOuts)

IAC 总线现在将出现在 MIDIClient.destinations 中。它将出现在首位，这意味着你编写的任何将第一个物理总线寻址为 0 的代码现在都需要修改。

因此，通过名称查找端口总是更安全：

MIDIOut.newByName("RemoteSL IN", "Port 1");

IAC 总线现在也会出现在其他应用程序中。

Sysex 示例

一份 machinedrum 手册说 sysex 命令应当像这样格式化……

$f0,$00,$20,$3c,$02,$00,command,...,$f7

而要设置速度，machinedrum 期望这条命令……

$61 | Set tempo ID
%0aaaaaaa | Upper bits
%0bbbbbbb | Lower bits
$f7 | SYSEX end
Note: Tempo = %aaaaaaabbbbbbb / 24, max 300 BPM, min 30 BPM

因此，要从 SuperCollider 向此 machinedrum 创建并发送有效的设置速度 sysex 命令，请执行……

MIDIClient.init;
m = MIDIOut(0);  // Linux 用户：MIDIOut(0, MIDIClient.destinations[0].uid)
m.sysex(Int8Array[0xf0, 0x00, 0x20, 0x3c, 0x02, 0x00, 0x61, 21, 54, 0xf7]);

这会将速度设置为 114.23 bpm。可以像这样计算高 7 位和低 7 位的值...

(
var bpm, val, upper, lower;
bpm = 114.23;
val = (bpm*24).round.asInteger;
upper = val&2r11111110000000>>7;
lower = val&2r00000001111111;
[upper, lower].postln;
)

其中结果 21 和 54 与二进制表示法中的 2r0010101 和 2r0110110 相同。
