Exception

根错误类

Object

子类：Error

说明

SuperCollider 错误处理机制的根。

Exception 是一个抽象类，定义了基本的错误行为。该类不直接在 SuperCollider 中使用。用户可以创建 Exception 的子类来标识特定类型的失败条件。

内置的异常类型实际上是 Error 的子类——其层次结构参见它的帮助文件。

注意： 你不应从 try 或 protect 函数内部返回 ^，它无法被捕获。在被接收者调用的方法中返回是可以的。

背景：通用异常处理

异常是指任何中断程序正常执行流的事件。实际上，异常和错误之间并没有太大区别；在 SuperCollider 中，我们倾向于在其他面向对象语言（Java、C++）会一致使用异常的地方使用错误这一说法。

如果一段代码遇到意外情况，它会创建一个异常对象来保存关于该错误情况的信息，然后“抛出”该对象。随后，解释器会向前回溯所有之前的栈帧，寻找将“捕获”该异常的异常处理器。异常处理器可以采取另一条路径来解决故障并正常继续；如果无法做到，它可以重新将异常抛回前一个栈帧。从未被捕获的异常会导致执行中止。在 SuperCollider 中，这会产生标准错误转储（详情参见 Understanding-Errors 帮助文件）；在 C++ 或 Java 中，后果是灾难性的，会导致整个程序崩溃。

其他语言中异常处理的常见语法是：

try { ...code... }
catch { ...exception handler... }

特定语言可能有其他变体。SuperCollider 编译器没有为「catch」关键字留出空间，因此语法更简单：

try { ...code... } { ...exception handler... };

使用 "try" 时，如果错误无法处理，必须显式重新抛出错误：

try { ...code... } { |error|
    if(test: can I handle the error?) {
        handle gracefully
    } { error.throw }
};

SuperCollider 包含一个借自 Scheme 的变体，其中异常总是致命的，但之前的代码可能已经分配了一些资源，需要在报告错误之前释放。例如，你可能打开了一个文件并对其进行一些处理，而处理过程中可能遇到错误。良好的做法是在错误停止之前关闭文件，你可以这样实现：

file = File(path, "r");
protect {
    work with the file here, which might cause an error
} {
    file.close;
};

使用“protect”时，即使没有错误，第二个函数也会执行，并且任何错误都会沿调用链向上传递。

在 Java 中，你可以捕获特定类的异常。你可以用以下结构模拟这种用法：

// Java 风格

try { }
catch { FileNotFoundException e } { console.printLine("File not found: " + e.path) }
catch { EmptyFileException e } { console.printLine("File is empty: " + e.path) };

// SuperCollider 风格（假设性的；这些具体异常在主库中不存在

try { } { |error|
    switch(error.species.name)
        { 'FileNotFoundException' } { postln("File not found:" + e.path) }
        { 'EmptyFileException' } { postln("File is empty:" + e.path) }
            // 默认条件：未处理的异常，重新抛出
        { error.throw }
}

下面是一个从写入不可变数组失败中恢复的例子，方法是在数组的副本上重新尝试写入。

(
~inPlaceSub = { |array, find, replace|
    array.do({ |item, i|
        if(item == find) { array[i] = replace };
    });
};

~trySub = { |array, find, replace|
    try {
        ~inPlaceSub.(array, find, replace)
    } { |error|
        switch(error.species.name)
            { 'PrimitiveFailedError' } {
                if(error.what.find("immutable").notNil) {
                    "caught ImmutableError".postln;
                    ~inPlaceSub.(array.copy, find, replace)
                } { "unknown primitive exception".postln; error.throw }
            }
                // 默认情况：未处理的异常，应终止以便重新抛出错误
            { "unknown exception".postln; error.throw }
    };
};
)

// 传入一个可变数组，可以
~trySub.((0..9), 9, 19);

// 传入字面量数组，Immutable 异常被捕获并处理
~trySub.(#[0, 1, 2, 3, 4, 5], 5, 6);

// 传入一个无意义的值，其他异常会被重新抛出
~trySub.(10, 5, 6);
