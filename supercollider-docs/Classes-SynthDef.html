SynthDef

Synth 定义的客户端表示

Object

另请参阅：Synth、Synth Definition File Format、SynthDesc

子类：ProxySynthDef、SynthDefOld

说明

服务器应用程序使用合成器定义作为创建 Synth 节点的模板。（诸如 Function: -play 之类的方法只是便捷方式，它们会自动创建这样的定义。）SynthDef 类封装了给定定义的客户端表示，并提供用于创建新定义、将其写入磁盘以及将其流式传输到服务器的方法。

SynthDef 是 SC 中较复杂的类之一，对其进行详尽解释超出了本文档的范围。因此，本文档底部的示例以及可从 Help 访问的各种教程中的示例，对于阐明其使用的某些方面可能是必要的。

关于常见 SynthDef 问题的一些见解可在 FAQ SynthDef Issues 中找到

UGen 图函数与特殊参数形式

def 的核心是其单位生成器图函数。这是一个 Function 实例，它详细描述了 def 的单位生成器如何互连、其输入和输出，以及哪些参数可供外部控制。在基于该 def 的 synth 中，函数的参数将变为 Control 的实例。这些可以有默认值，也可以在创建 synth 时设置。创建后，它们将可通过 Node 的 set 和 setn 方法，或 n_set 和 n_setn OSC 消息进行控制。

有四种特殊类型的参数，它们的处理方式不同：

音频速率

以 "a_" 开头的参数（例如 a_input），或在 def 的 rates 参数中指定为 \ar 的参数（见下文），在用 /n_mapa 映射到音频速率总线时，将能够读取该总线。

初始速率

以 "i_" 开头的参数（例如 i_freq），或在 def 的 rates 参数中指定为 \ir 的参数（见下文），将是静态且不可调制的。它们不会响应 /n_set 或 /n_map。这在 CPU 开销上比普通参数略为高效。

触发速率

以 "t_" 开头的参数（例如 t_trig），或在 def 的 rates 参数中指定为 \tr 的参数（见下文），会创建为 TrigControl。设置该参数时会在设定值处产生一个控制速率脉冲。这对于触发器很有用。

字面量数组

以字面数组作为默认值的参数（参见 Literals）会产生多通道控件，可通过 Node: -setn 或 /n_setn 作为一组进行设置。

有关其工作原理的更多细节，请参见下面的示例。

某些参数名（例如用于指定输出总线的 'out'）使用得如此普遍，以至于采用它们可以说构成了“良好风格”。其中之一是用于控制 EnvGen 的 gate 输入的 'gate'，值得特别提及，因为它允许使用 Node 的 release 方法。示例和更多细节请参见 Node。

数组化控件

在某些情况下，将一组值发送到单个控制名称会很有用，例如 aSynth.set(\freqs, [300, 400, 500])，或者在实例化 Synth 时传递包络。这要求在 SynthDef 中定义一个数组控制。

有两种定义数组化控件的方式：

  1. NamedControl —— 推荐使用，以获得灵活性和清晰性。
  2. 字面量数组（如上所述）。

NamedControl 可以接受在代码中确定的默认值。例如，传入一个包络时，每个断点需要四个值。通过编写 NamedControl.kr(\env, Env.newClear(numSegments: 8).asArray)，可以轻松地为数组化控件创建模板。

对于所有默认值都事先已知的非常小的数组，字面量数组可能更为方便。

一般来说，在大多数情况下，对数组化控件使用 NamedControl 可能更简单。

参见 Array Arguments 下的示例。

静态元素与动态元素

重要的是要理解，尽管单个 def 可以通过其参数等提供极大的灵活性，但它仍然是一个静态实体。def 的 UGen 图函数（以及其中的 SC 代码）仅在创建 def 时求值。因此，像 while、do、collect 等语句在 def 用于创建 Synth 时将不再产生任何效果，并且重要的是要理解，UGen 图函数不应像语言中的函数那样设计，因为语言中的函数多次求值可以产生不同的结果。它将被求值一次且仅一次。

注意： 当接收者为 UGen 时，if 实现为线性信号交叉淡化

不过，还有其他方法可以实现类似的结果，通常使用 Rand 等 UGen。例如，下面的 def 会有一个随机生成的频率，基于它的每个 Synth 都会使用相同的频率：

(
SynthDef(\help_notRand, { |out|
    Out.ar(out,
        SinOsc.ar(rrand(400, 800), 0, 0.2) * Line.kr(1, 0, 1, doneAction: Done.freeSelf)
    )
}).add;
)
a = Synth(\help_notRand);
b = Synth(\help_notRand); // 与以下相同的频率

另一方面，这个将为每个创建的 Synth 使用不同的随机频率：

(
SynthDef(\help_isRand, { |out|
    Out.ar(out,
        SinOsc.ar(Rand(400, 800), 0, 0.2) * Line.kr(1, 0, 1, doneAction: Done.freeSelf)
    )
}).add;
)
a = Synth(\help_isRand);
b = Synth(\help_isRand); // 一个不同的随机选择的频率

类方法

SynthDef.new(name, ugenGraphFunc, rates, prependArgs, variants, metadata)

创建一个 SynthDef 实例，求值 ugenGraphFunc 并构建 ugenGraph。

参数：

name

一个 String 或 Symbol（即 "name" 或 \name）。此名称将用于在基于 SynthDef 创建 Synth 时引用该 SynthDef，并且应当是唯一的。

ugenGraphFunc

一个 Function 实例，用于指定该 def 的 UGen 如何互连。有关如何指定 Function 参数的信息，请参阅上面的讨论。

rates

一个可选的数组，用于指定 ugenGraphFunc 各参数的规格说明。其顺序与参数顺序相对应。有关这些规格说明的用法，请参阅下面的示例。

一个规格可以是：

nil/zero

创建一个标准的控制率 Control。

\ar

会创建一个音频速率 AudioControl。

一个 float

该 Control 将具有指定时间的滞后。这可用于在不同值之间创建平滑过渡。t_ 和 i_ 参数不能滞后。

\ir

Control 只能在创建时设置（“初始速率”）。参见上文讨论。

\tr

该 Control 用作触发器。参见上文讨论。

prependArgs

一个可选的 Array，包含在 ugenGraphFunc 求值时作为其第一批参数传入的对象。以这种方式接收值的参数不会转换为 Control 的实例。有关如何使用它的示例，请参见下面的 wrap 示例。

variants

一个可选的 Event，包含默认的参数设置。这些设置可以覆盖 ugenGraphFunc 中指定的默认值。创建 Synth 时，可以通过以 'name.variant' 或 "name.variant" 形式附加 defName 参数来请求变体。参见下面的示例。

metadata

一个可选的 Event，包含与客户端中使用该 SynthDef 相关的额外用户自定义信息。SynthDef 本身会被发送到服务器进行音频渲染；元数据严格来说是客户端的描述性信息。目前，事件中的 'specs' 键保留用于与 SynthDef 参数关联的 ControlSpec（这对于自动构建 GUI 很有用）。元数据可以持久化到磁盘，并作为 SynthDesc 的一部分自动加载。有关更多详细信息，请参阅 SynthDesc 帮助文件。

SynthDef.wrap(func, rates, prependArgs)

将函数包裹在封闭的 synthdef 中。

讨论：

被包装函数的参数会自动提升为 SynthDef 控件，所用规则与主 UGen 函数的参数相同。一个非常简单的示例：

d = SynthDef(\demoWrapping, { |out|
    Out.ar(out, SynthDef.wrap({ |freq| SinOsc.ar(freq) }))
});

d.allControlNames;

打印：[ControlName P 0 out control 0, ControlName P 1 freq control 0]。

外部函数声明了参数 'out'，而被包装的函数以 'freq' 作为其参数。生成的 SynthDef 将这两个参数都作为控制，完全就像外层函数将两者都包含为参数一样。

rates 数组的行为如前所述。PrependArgs 允许将值或单元生成器从外围的 SynthDef 上下文传入内部函数。任何接收 prependArg 值（包括 nil）的内部函数参数都将使用该值，从而抑制为该参数创建控件。下面更长的示例演示了这种技术。

这对于批量生成 SynthDef 非常有用，这些 SynthDef 具有共同的“外壳”定义特性，例如包络或触发机制，适用于不同的 unit generator 子图。共同特性只需编写一次；SynthDef 之间不同的 UGen 插入到支撑架构中。

SynthDef.synthDefDir

SynthDef.synthDefDir = dir

获取或设置写入 defs 的默认目录。

SynthDef.removeAt(name, libname: 'global')

从名为 libname 的 SynthDescLib 及其服务器中移除 synthdef name。

SynthDef.writeOnce(name, func, rates, prependArgs, variants, dir, metadata, mdPlugin)

创建一个新的 SynthDef。仅当同名 def 文件尚不存在时，才会将其写入磁盘。注意，这不会检查差异，因此你需要删除 defFile 才能让它重新构建。dir 的默认值是使用 SynthDef.synthDefDir 指定的路径。

警告： SynthDef.writeOnce 是一个遗留方法。它的主要用途是提高 quark 中 SynthDef 的效率，但这已被 SynthDescLib 取代。由于完全不受更改影响，它可能导致难以诊断的 bug（例如 quark 已是 1.1 版，但其中的 SynthDef 仍停留在 1.0 版）。Quark 开发者现在应改用 -add。例外是极大的 SynthDef，此时你可以在 -writeDefFile 和此方法之间选择。即便如此，writeOnce 所节省的效率仅在于磁盘 I/O——两种方法在每次运行时都会构建 SynthDef。

SynthDef.warnAboutLargeSynthDefs

SynthDef.warnAboutLargeSynthDefs = value

当一个 SynthDef 过大而无法通过标准 OSC 消息发送到本地服务器时，它会被写入磁盘，服务器则改为从磁盘加载它。如果 warnAboutLargeSynthDefs 设置为 true，则会警告正在发生这种情况。对于远程服务器，始终会有警告。

实例方法

.add(libname, completionMsg, keepDef: true)

将 synthdef 添加到由 libname 指定的 SynthDescLib，并将其发送到该库的服务器。不会写入 defFile；所有操作都在内存中进行。

讨论：

使用此方法后，synthdef 可以像在 store() 中那样用于事件流，但不会在磁盘上留下永久文件。调用此方法会向库可能拥有的任何依赖者触发一个带有 \synthDescAdded 键的更新消息。这可用于在每次添加 def/desc 时触发额外的行为。参见 Object: Dependancy。

可以通过 SynthDescLib.global.addServer(server) 添加服务器。

请注意，此方法不存在 "dir" 和 "mdPlugin" 参数。由于不写入文件，因此无需指定目录或写入元数据文件。

(
SynthDef(\help_synth, { |out, freq = 800, sustain = 1, amp = 0.1|
    Out.ar(out,
        SinOsc.ar(freq, 0, 0.2) * Line.kr(amp, 0, sustain, doneAction: Done.freeSelf)
    )
}).add;
)

.name

.name = value

返回此 def 的名称。

.func

.func = value

返回此 def 的 ugenGraphFunc。

.variants

.variants = value

返回一个包含此 def 各变体的 Event。

.allControlNames

.allControlNames = value

一个数组，包含各个控制的 ControlName。

.specs

一个 SynthDef 的 Dictionary，包含 ControlSpec。等价于：d.metadata[\specs]

特殊用途方法

（大多数情况下，推荐使用 add 方法）

.writeDefFile(dir, overwrite: true, mdPlugin)

将该 def 以服务器可读的形式写入名为 name.scsyndef 的文件中。dir 的默认值为 synthdefs/。存储在默认目录中的 def 将在本地和内部服务器启动时被自动加载。

.load(server, completionMsg, dir)

写入 defFile 并向服务器发送消息以加载此文件。当此异步命令完成时，completionMessage（一个有效的 OSC 消息）会立即由服务器执行。dir 的默认值为 synthdefs/。

.send(server, completionMsg)

编译该 def 并发送到服务器而不写入磁盘（从而避免烦人的 SynthDef 堆积）。当这个异步命令完成时，completionMessage（一个有效的 OSC 消息）立即由服务器执行。

.store(libname: 'global', dir, completionMsg, mdPlugin)

写入 defFile 并将其存储到由 libname 指定的 SynthDescLib 中，然后向该库的服务器发送消息以加载此文件。当此异步命令完成时，completionMessage（一个有效的 OSC 消息）会立即由服务器执行。libname 的默认值为 \global，dir 的默认值为 synthdefs/。这是将 def 与事件流系统一起使用所必需的。参见 Streams and Pattern。

参数：

libname

SynthDescLib 的名称

dir

completionMsg

mdPlugin

（可选）用于持久化元数据的元数据插件类。如果未提供，则使用默认插件。详情请参见 SynthDesc 帮助文件。

.play(target, args, addAction: 'addToHead')

一个便捷方法，它编译该 def 并将其发送到 target 的服务器。当此异步命令完成时，它会使用 Array args 中指定的参数值，根据此定义创建一个 synth。有关有效 addActions 的列表，请参见 Synth。默认为 \addToHead。

返回值：

对应的 Synth 对象。

示例

Basic

// 注意，SynthDef(...) 和 Synth(...) 这类构造是 SynthDef.new(...) 等的简写。
// 使用 SynthDef 时，通常会将它与结果实例上的调用链接起来，
// 例如 SynthDef(...).add 或 SynthDef(...).play

// 创建一个简单的 def 并发送到服务器

s.boot;
SynthDef(\SimpleSine, { |freq = 440, out| Out.ar(out, SinOsc.ar(freq, 0, 0.2)) }).add;

// 以上内容本质上等同于以下内容：
d = SynthDef(\SimpleSine, { |freq = 440, out| Out.ar(out, SinOsc.ar(freq, 0, 0.2)) });
d.add;

// 现在用它创建一个 synth，freq 使用默认值，然后再创建另一个使用不同值的
x = Synth(\SimpleSine);
y = Synth(\SimpleSine, [\freq, 660]);

// 现在更改 x 的 freq 值
x.set(\freq, 880);

x.free; y.free;

// 使用便捷方法 play
x = SynthDef(\SimpleSine, { |freq = 440, out| Out.ar(out, SinOsc.ar(freq, 0, 0.2)) }).play
x.free;

参数速率

(
SynthDef(\trigTest1, { |out, t_trig = 0, freq = 440| // t_trig 创建一个 TrigControl
    Out.ar(out, SinOsc.ar(freq+[0, 1], 0, Decay2.kr(t_trig, 0.005, 1.0)));
}, [0, 0, 4]        // 将 freq 延迟 4 秒（第二个参数），但不延迟 t_trig（反正也不会生效）
).add;
)

y = Synth(\trigTest1);
y.set(\t_trig, 1); // 你可以多次这样做
y.set(\t_trig, 1, \freq, 220); // 听听频率是如何滞后的
y.free;

// 带有默认 \note 事件类型的 Pbind 和 Pmono 使用自动生成的
// 函数来查找参数值。该函数将事件中的 \trig
// 转换为合成器中的 \t_trig。
(
Pmono(\trigTest1, *[
    trig: Prand([0, 1], inf), // 对于随机触发，使用 trig，而非 t_trig
    freq: Pwhite(lo: 220, hi: 440, length: 10),
    dur: 1
]).play;
)

// 注意：使用事件类型 \set 时没有自动转换，所以那种情况下
// 你应该使用 t_trig。
y = Synth(\trigTest1);
(
Pbind(*[
    type: \set,
    id: y.nodeID,
  args: #[\t_trig],
    t_trig: Prand([0, 1], 8)
]).play;
)
y.free;

// 第二个版本通过在 rates 数组中指定，使 trig 成为 \tr 参数。
(
SynthDef(\trigTest2, { |out, trig = 0, freq = 440|
    Out.ar(out, SinOsc.ar(freq+[0, 1], 0, Decay2.kr(trig, 0.005, 1.0)));
    }, [0, \tr, 4]        // 对 freq 应用滞后（滞后时间：4 秒），\tr 为触发创建一个 TrigControl
).add;
)

// 还有一种使用 NamedControls 编写同样内容的不同方式
(
SynthDef(\trigTest2, { |out|
    Out.ar(out, SinOsc.ar(\freq.kr(440, 4) + [0, 1], 0, Decay2.kr(\trig.tr, 0.005, 1.0)));
}).add;
)

// 使用第二个版本，创建一个合成器
z = Synth(\trigTest2);

// 现在触发 decay 包络
z.set(\trig, 1);                 // 你可以多次这样做
z.set(\trig, 1, \freq, 220);     // 听听频率是如何滞后的
z.set(\trig, 1, \freq, 880);
z.free; // 释放 synth

// 在 Pbind 和 Pmono 中使用 trig
(
Pmono(\trigTest2, *[
    trig: Prand([0, 1], inf), // 对于随机触发，使用 trig，而非 t_trig
    freq: Pwhite(lo: 220, hi: 440, length: 10),
    dur: 1
]).play;
)

Variants

// 创建一个带有一些变体的 def
(
SynthDef(\vartest, { |out, freq = 440, amp = 0.2, a = 0.01, r = 1|
    // 带有 doneAction: Done.freeSelf 的 EnvGen 会在完成后自动释放 synth
    Out.ar(out, SinOsc.ar(freq, 0, EnvGen.kr(Env.perc(a, r, amp), doneAction: Done.freeSelf)));
}, variants: (alpha: [a: 0.5, r: 0.5], beta: [a: 3, r: 0.01], gamma: [a: 0.01, r: 4])
).add;
)

// 现在创建一些 synth。首先使用 arg 默认值
Synth(\vartest);

// 现在 variant 是默认值
Synth('vartest.alpha');
Synth('vartest.beta');
Synth('vartest.gamma');

// 覆盖一个变体
Synth('vartest.alpha', [\release, 3, \freq, 660]);

数组参数

// freqs 被定义为一个数组化控制。这会创建一个同样大小的多通道 Control。
(
SynthDef(\arrayarg, { |out, amp = 0.1, gate = 1|
    var env, sines;
    var freqs = NamedControl.kr(\freqs, [300, 400, 500, 600]);
    env = Linen.kr(gate, 0.1, 1, 1, 2) * amp;
    sines = SinOsc.ar(freqs +.t [0, 0.5]).cubed.sum; // 4 个振荡器的混合
    Out.ar(out, sines * env);
}, [0, 0.1, 0]).add;
)

x = Synth(\arrayarg);
x.setn(\freqs, [440, 441, 442, 443]);

// 数组边界之外的值会被忽略——
// 0 被丢弃
x.setn(\freqs, [300, 400, 500, 600, 0]);

x.release;

// McCartney 先生更复杂的示例
(
fork {
    z = Synth(\arrayarg);

    2.wait;
    10.do {
        z.setn(\freqs, { exprand(200, 800.0) } ! 4);
        (2 ** (0..3).choose * 0.2).wait;
    };

    z.set(\amp, -40.dbamp);

    10.do {
        z.setn(\freqs, { exprand(200, 800.0) } ! 4);
        (2 ** (0..3).choose * 0.2).wait;
    };
    2.wait;

    z.release;
};
)

包装示例：效果定义的 'factory' 生产

// 下面的 makeEffect 函数将一个更简单的函数包装在自身内部，并提供
// 淡入淡出到效果中（这样你可以添加它而不产生咔嗒声）、对湿声
// 和干声混合的控制等。
// 这种功能对各种效果都有用，而 SynthDef-wrap
// 让你可以复用这些公共代码。
(
// 基本包装器
~makeEffect = { |name, func, lags, numChannels = 2|

    SynthDef(name, { |i_bus = 0, gate = 1, wet = 1|
        var in, sound, env, lfo;
        in = In.ar(i_bus, numChannels);
        env = Linen.kr(gate, 2, 1, 2, 2); // 效果淡入

        // 调用被包装的函数。in 和 env 参数会作为
        // 前两个参数（prependArgs）传递给该函数。
        // 被包装函数的任何其他参数将成为 Controls。
        sound = SynthDef.wrap(func, lags, [in, env]);

        XOut.ar(i_bus, wet * env, sound);
    }, [0, 0, 0.1]).add;

};
)

// 现在制作一个哇音
(
~makeEffect.value(\wah, { |in, env, rate = 0.7, ffreq = 1200, depth = 0.8, rq = 0.1|
    // in 和 env 来自 wrapper。其余是 controls
     var lfo;
    lfo = LFNoise1.kr(rate, depth * ffreq, ffreq);
    RLPF.ar(in, lfo, rq, 10).distort * 0.15;
},
[0.1, 0.1, 0.1, 0.1], // 速率 ffreq、depth 和 rq 的滞后
2    // numChannels
);
)

// 现在做一个简单的混响
(
~makeEffect.value(\reverb, { |in, env|
    // in 和 env 来自包装器。
    var input;
    input = in;
    16.do({ input = AllpassC.ar(input, 0.04, Rand(0.001, 0.04), 3) });
    input
},
nil, // 无滞后
2    // numChannels
);
)

// 要处理的内容
x = { { Decay2.ar(Dust2.ar(3), mul: PinkNoise.ar(0.2)) } ! 2 }.play;

y = Synth.tail(s, \wah);
z = Synth.tail(s, \reverb, [\wet, 0.5]);

// 我们使用了一个名为 gate 的参数，因此 Node-release 可以淡出效果
y.release;

// 把门限设为零也会得到相同结果
z.set(\gate, 0);

x.free;

常见参数名：out 和 gate

// 名为 'out' 和 'gate' 的参数通常分别用于指定输出总线和
// EnvGen 门控。虽然不是必需的，但使用它们有助于保持一致
// 和可互换性。'gate' 尤其有用，因为它允许使用 Node 的 release
// 方法。
(
SynthDef(\synthDefTest, { |out, gate = 1, freq = 440|
    // doneAction: Done.freeSelf 在 EnvGen 结束时释放该 synth
    Out.ar(out, SinOsc.ar(freq) * EnvGen.kr(Env.asr(0.1, 0.3, 1.3), gate, doneAction: Done.freeSelf));
}).store; // 使用 store 以兼容下面的模式示例
)

x = Synth(\synthDefTest, [\out, 0]); // 通过硬件输出总线 0 播放（参见 Out.help）
x.release; // 释放并释放合成器（如果 doneAction > 2；参见 EnvGen）

// 等价于：

x = Synth(\synthDefTest); // 如果没有给出默认参数，out 默认为零。
x.set(\gate, 0);

// 如果值为负数，它会覆盖释放时间，变为 -1 - gate
x = Synth(\synthDefTest);
x.set(\gate, -5); // 4 秒释音

// 等价于：
x = Synth(\synthDefTest);
x.release(4);

// 如果 out 参数以标准方式使用，则无需了解 synth def 即可随时更改它
x = Synth(\synthDefTest, [\out, 0]);
x.set(\out, 1); // 通过通道 1 播放
x.release;

// 另一个好例子是 patterns，它可以使用 gate 来释放音符
(
Pbind(
    \instrument, \synthDefTest,
    \freq, Pseq([500, 600, Prand([200, 456, 345], 1)], inf),
    \legato, Pseq([1.5, 0.2], inf),
    \dur, 0.4,
    \out, Pseq([0, 1], inf)
).play;
)

内联 ControlSpec 定义

有时，在 SynthDef 中使用参数的位置直接为其指定 ControlSpec 比在其他地方指定更清晰。可以在构造 NamedControl 时设置 spec，也可以将其作为 SynthDef 参数的属性来设置。

(
~def = SynthDef(\argumentExample, { |freq, amp|
    var sig;
    freq.spec = ControlSpec(20, 20000, \exp);
    amp.spec = ControlSpec(0, 1);
    sig = SinOsc.ar(freq, 0, amp);
    Out.ar(0, sig);
});
~def.specs.freq.postln;
~def.specs.amp.postln;
)

(
~def = SynthDef(\argumentExample, {
    var sig;
    sig = SinOsc.ar(
        \freq.kr(spec: ControlSpec(20, 20000)),
        0,
        \amp.kr(spec: ControlSpec(0, 1));
    );
    Out.ar(0, sig);
});
~def.specs.freq.postln;
~def.specs.amp.postln;
)
