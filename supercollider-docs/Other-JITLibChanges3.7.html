3.7 中的 JITLib 变更

JITLib 的更改日志

Overview

总体而言，此版本的改动旨在强化代理作为真正占位符的理念，使其在许多方面表现得与源对象一样：

  • 模式代理现在的行为应更接近其源模式
  • 节点代理可以根据源 UGen 函数的大小调整其通道数，如果你允许它们这样做

这增加了一点复杂性，但出于各种原因，其他方面可以简化，从而类更少、代码更易读。系统更容易从故障中恢复。一些鲜为人知（或未知）的 bug 也被修复了。

由于代码的许多部分已被修改，其中可能仍存在 bug。下面你会找到一长串（手动）测试，这些测试也应能稍微揭示出你可以对该系统有何期待。

已更改的类：

  • NodeProxy、BusPlug、Ndef
  • PatternProxy、Pdefn、EventPatternProxy、Pdef、ProxySpace
  • Monitor、NodeMap

注意： 示例使用 Ndef 给出，但同样适用于 ProxySpace 和 NodeProxy：Ndef(\x, 5); 与 ProxySpace 中的 ~x = 5; 相同。

行为方面最大的变化之一可能是节点代理的弹性重塑（参见：NodeProxy 弹性行为设置）。默认情况下它是关闭的。如果你想将其作为默认设置进行测试，可以将以下内容添加到启动文件中：

BusPlug.defaultReshaping = \elastic;

行为变更

模式代理（Pdef/Pdefn/Tdef 及各自的父类）中的变更

  • 当代理的源是非流/非模式对象时，每个流只返回该对象一次（默认不循环）
  • 在模式系统中，非模式对象的角色是模糊的：在某些情况下，当作为模式的输入使用时，它会无休止地返回自身（例如在 Pbind 的值中）。在其他情况下（例如作为 Pseq 列表的元素），它们只被使用一次，然后让位给下一个元素。模式代理实际上应根据其输入表现出相同的行为。这意味着 asStream 和 embedInStream 必须稍作不同的实现：现在所有模式代理对 asStream 和 embedInStream 的行为都与其各自的源对象相同。例如 Pdefn(\x, 800); Pbindef(\freq, Pdefn(\x)) 将循环 800，而 Pseq([Pdefn(\x), 900]) 将先返回 800，然后返回 900。

节点代理（NodeProxy、Ndef、BusPlug）中的变更

  • controls 现在在创建 synth 时设置，而不是在额外的 set 消息中设置。这意味着 i-rate controls 可以在 nodemap 中设置。
  • send 和 spawn 的 extraArgs 现在会覆盖每个 synth 现有的 nodeMap 设置
  • 当把节点代理的源设为一个数字或一个数字数组时，总线由一个预编译的 synth def 设置，这比构建一个要高效和一致得多。这意味着现在可以放心地以更高频率将源设为一个数字/数组（例如 Ndef(\x, [100, 200])）。
  • 由于实现原因，现在无法再在单个节点代理中累加数字。一个槽位会覆盖下一个槽位。例如 Ndef(\x)[0] = 100; Ndef(\x)[1] = 200; 的输出将是 200，而不是（像以前那样）300。
  • play（Monitor）现在可以从任意数量的声道映射到任意数量的声道
  • play 和 playN (Monitor) 之前传递的参数会被保留，并且可以被新参数部分覆盖（消息 clear 会移除它们）。
  • nodeProxy.value(n)（例如 SinOsc.ar(Ndef(\x)）将保持代理已有的速率）。
  • 使用 x.ar(n) 和 x.kr(n) 时，当 n 为 nil 会自动扩展。如果给出了 n，则保持固定。
  • nodeProxy.ar(n) / nodeProxy.kr(n) 如果未给出 n，它们现在将始终返回一个数组；如果没有给出输入，nodeProxy.value(x) 返回一个数组。这是为了保持普遍一致性：少数 UGen 期望以数组作为输入，而代理的 numChannels 现在可能会变化，因此必须对此加以指定。要得到一个 UGen 而非数组，请分别使用 nodeProxy.ar(1) 或 nodeProxy.kr(1)。
  • 与之前不同，x.ar(n, offset) 现在会环绕可用的 proxy 总线通道。还有第三个参数（wrap），当设为 false 时会改为裁剪。
  • ar/kr 新增了第三个参数 clip：x.ar(n, offset, clip)。将其设为 \wrap 时，会通过环绕来扩展现有通道的输出尺寸（默认值为 \wrap）。如果你希望通过重复最后一个值来保持在范围内，请将其设为 \clip。
  • InBus 现在在多通道扩展方面更加灵活和合理，并且有了一份帮助文档

新功能

  • 消息 NodeProxy: -mold 允许在运行时改变代理的通道数和速率。代理的子节点会被自动重新映射，源和监视器都会在各自对应的状态之间交叉淡化。
  • 注意，重建子项时，父项的时间设置（clock、quant 和 fadeTime）会用于所有其他项。如果需要相关 proxy 拥有不同的时间基准，mold 不会保留它们的时间设置。这种情况下，应将 mold 后 proxy 的 quant 设置为两个 quant 的最小公倍数。
  • 现在可以直接将 NodeMap 用作 Synth 对象中的参数。
  • NodeProxy 可以直接作为 Synth 的参数使用，它会返回其总线索引，或通过 asMap 返回其总线映射参数。请注意，当允许重排时，synth 不会自动更新。你可以注册对 \bus 的依赖。
  • 节点代理和模式代理现在可以复制：这会复制隐藏的内部状态以使副本独立，但会保留对源对象的引用。在 NodeProxy 中，已渲染的 SynthDef 会被缓存，因此复制效率很高。ProxySpace 或 LazyEnvir 可以被复制，然后独立修改。

NodeProxy 弹性行为设置

  • NodeProxy 现在能够根据其源进行重塑。这样做时，它会递归更新所有依赖于它的其他 node proxy。源和监听都会在各自状态之间交叉淡化。

  • 重塑可以在三个层级上设置：

    • 作为全局默认值，例如：BusPlug.defaultReshaping = \elastic。
    • 对于 ProxySpace，例如：p = ProxySpace.push; p.reshaping = \elastic。
    • 对于单个 NodeProxy/BusPlug，例如：Ndef(\x).reshaping = \elastic。
  • 默认情况下，重塑为 nil（不自动重塑）。除此之外，目前还有 \elastic：既可收缩也可增长，并改变速率；以及 \expanding：仅增长，但也会调整速率。

一些细微更改

  • 空函数 / 或返回 nil 的函数传给节点代理不会失败，而只是播放一个没有输出的 synth
  • 尝试播放控制速率代理时，仅发出警告而不抛出错误
  • 代理的源在插入时构建，而不仅仅在服务器运行时构建。这允许独立于服务器运行状态了解其通道数。
  • 总线在 fadeTime 之后被释放，以避免过早重用。
  • proxy 被传入由事件流产生的事件中（~proxy）。

实现变更

  • NodeProxy 和 BusPlug 的代码已经过重构，使其更易阅读且行为更一致（见下文）。
  • NodeMap 现在只是一个 Dictionary（NodeMapSetting 类已被移除）。你可以将 NodeMap 用于多种用途。
  • 节点代理会跟踪任何使用其输出的其他节点代理，以便在总线发生变化时重建它们（“子节点”）。
  • 一些方法，如 setSourceLikeInPbind 和 prFadeTime，已不再需要。

已修复的 Bug

  • 当 quant 不为 nil 时，Pattern Proxies 有时无法正确嵌入（已修复）
  • 当节点代理彼此启动时，它们之间的节点顺序是错误的（已修复）
  • 一次多次设置 NodeProxy 的源时未能释放相应的 synth（已修复）
  • 在 NodeProxy 中使用依赖组的事件模式（如 Pfxb）会将它们分配到错误的组（已修复）
  • Pdef 中的清理有时不生效。修复了问题 #107。
