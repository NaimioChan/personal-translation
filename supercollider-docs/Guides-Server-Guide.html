服务器指南

在不同情况下使用 Server 对象

另请参阅：Server、ServerOptions、Server Architecture、Server Command Reference、Multi-client Setups

说明

Server 对象是服务器应用程序的客户端侧表示，用于从 SuperCollider 语言应用程序控制该应用程序。（有关这种区别的更多细节，请参见 Client vs Server。）它转发 OSC 消息，并拥有若干分配器，用于跟踪节点、总线和缓冲区的 ID。

服务器应用程序是一个命令行程序，因此除 OSC 消息外，所有命令都是 UNIX 命令。

由 Server 对象表示的服务器应用程序可能运行在与客户端相同的机器上（与语言应用程序处于相同的地址空间，或分开运行；见下文），也可能运行在远程机器上。

服务器的大部分选项都通过其 ServerOptions 实例进行控制。有关详细信息，请参阅 ServerOptions 帮助文件。

Paths

在本地机器上运行的服务器应用有两个 UNIX 环境变量：SC_SYNTHDEF_PATH 和 SC_PLUGIN_PATH。它们指示启动时加载的 synthdef 和 ugen 插件所在的目录。这些目录是在硬编码的默认 synthdef/ 和 plugin/ 目录之外的额外目录。

这些可以在 SC 内使用类 String 的 getenv 和 setenv 方法进行设置。

// 当本地服务器启动时，将加载此目录中的所有定义
"SC_SYNTHDEF_PATH".setenv("~/scwork/".standardizePath);
"echo $SC_SYNTHDEF_PATH".unixCmd;

默认组

当 Server 启动时，会有一个 ID 为 0 的顶层组，它定义了节点树的根。（这由 Group 的子类 RootNode 表示。）如果服务器应用是从 SCLang 内部启动的（而非从命令行启动），则启动后会自动调用方法 initTree。这还会创建一个 ID 为 1 的 Default Group，它是使用对象风格时所有 Node 的默认组。这提供了一个可预测的基本节点树，使得 Server-scope、Server-record 等方法可以在不遇到执行顺序问题的情况下正常工作。

默认组是持久的，即它会在重启、按 cmd-. 等操作之后被重新创建。更多信息请参见 RootNode 和 Default Group。

注意： 如果服务器是从命令行启动的，那么如果你需要默认组，则必须手动调用 initTree 来初始化它。请参见下面的 initTree。

本地与内部

一般来说，在单机工作时，可能会使用启动时创建并存储在类变量 *local 和 *internal 中的两个 Server 对象之一。在 SuperCollider.app（OSX）中，会创建两个 GUI 窗口来控制它们。使用 -makeGui 手动创建 GUI 窗口。

两者的区别在于：本地服务器作为独立应用程序运行，拥有自己的地址空间；而内部服务器与语言/客户端应用程序运行在同一空间内。

本地服务器和内部服务器都支持作用域和同步总线访问。

本地服务器以及运行在你本地机器上的任何其他服务器应用有一个优势：如果语言应用崩溃，它（因而可能还有你的作品）将继续运行。因此这是一种本质上更稳健的配置。但要注意，即使服务器上的 synth 继续运行，如果语言应用崩溃，任何语言侧的排序和控制都将终止。

目前，使用内部服务器通常没有好处，但为了向后兼容，它仍然保留。

默认服务器

始终存在一个默认服务器，它存储在类变量 default 中。任何未指定目标而创建的 Synth 或 Group 都将在默认服务器上创建。在启动时，它被设置为本地服务器（见上文），但可以设置为任意服务器。

本地与远程服务器，多客户端配置

大多数情况下，用户使用的服务器应用与 SC 语言客户端运行在同一台机器上。只要知道服务器的 IP 地址和端口，就可以通过网络使用运行在不同机器上的服务器。*remote 方法提供了一种便捷的方式来实现这一点。

注意： 要启用远程连接，你需要修改服务器的 ServerOptions 中的 ServerOptions: -bindAddress，因为默认值只允许来自本机的连接。s.options.bindAddress = "0.0.0.0" 将允许来自任何地址的连接。

这种方法的一个常见变体是多个客户端使用同一个服务器。如果你希望这样做，需要将服务器的 ServerOptions: -maxLogins 设置为至少等于你希望允许的客户端数量。当客户端注册 notifications 时，服务器会提供一个客户端 ID。这还会配置分配器，以避免在分配 Nodes、Buffers 或 Busses 时发生冲突。更多信息请参见 Multi-client Setups。

为了使用 tcp 连接远程服务器，应首先使用 -t 选项启动远程服务器，例如如下所示：

// 在运行服务器的机器上
(
s.options.protocol = \tcp; // 设置为使用 tcp
s.options.bindAddress = "0.0.0.0"; // 允许来自任何地址的连接
s.options.maxLogins = 2; // 设置为正确的客户端数量
s.boot;
)

然后运行以下代码：

// 在远程机器上连接到服务器
(
o = ServerOptions.new;
o.protocol_(\tcp);
t = Server.remote(\remote, NetAddr("192.168.0.130", 57110), o); // 设置为正确的地址和端口
t.addr.connect;
t.startAliveThread( 0 );
t.doWhenBooted({ "remote tcp server started".postln; t.notify; t.initTree });
)
