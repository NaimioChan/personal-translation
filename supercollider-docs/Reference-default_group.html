默认组

sclang 中自动创建的 Group

另请参见：Group、RootNode、Node、Node Messaging、Order of execution

  • 根节点（id:0）

    • 默认组（id:1）

当服务器启动时，存在一个 ID 为 0 的顶层组，它定义了树的根。这由 Group 的一个子类表示：RootNode。

与根组分开的是 sclang 的“默认组”概念，它在服务器启动时自动创建。你可以通过方法 Server: -defaultGroup 访问它。此组是所有节点的默认外层组，即如果你不指定，得到的就是它。一般来说，你应该在服务器的默认组内创建新节点，而不是在其 RootNode 内。在单客户端设置中，默认组的 ID 将为 1。

请记住，默认组是客户端侧的概念，如果你从命令行或 NRT 模式运行 scsynth，或开发替代客户端，则需要自行创建它们。1

这是在对象风格下所有 Node 的默认目标，如果你将一个 Server 作为目标提供，得到的就是它。如果你不指定目标或传入 nil，你将得到默认 Server 的默认组。

s.boot;
a = Synth.new(\default); // 在默认 Server 的默认组中创建一个 synth
a.group; // 注意 Group ID
a.group == Server.default.defaultGroup;
// -> true

默认组有一个重要用途：它提供了一个可预测的基本节点树，使得诸如 Server-scope、Server-record 等方法能够在不会遇到执行顺序问题的情况下正常工作。在下面的示例中，作用域节点将位于默认组之后。

s.boot;

{ SinOsc.ar(mul: 0.2) }.scope(1);

// 观察 post 窗口；
s.queryAllNodes;

// 我们的 SinOsc synth 位于默认组（ID 1）中
// scope 节点在默认组之后，所以没有问题

s.quit;

注意默认组是持久存在的：它在 Server 的 initTree 方法中创建（与存储在其 tree 实例变量中的任何代码一起执行；详情参见 Server），并在重启后、按下 Cmd-. 后以及所有节点被释放后重新创建。使用 osc 消息时，这意味着 id 为 1 的目标节点始终可以使用：

s.sendMsg("/s_new", "snd", 1832,0,1); // 添加到组 1 的头部

默认组可以被专门释放，但通常没有理由去这样做。

一般来说，应将节点添加到默认组而不是 RootNode，除非有特定理由需要这样做（例如添加一些新的功能，比如录音和示波，这些功能依赖于可预测的基本节点顺序）。使用对象风格时，默认组是所有新节点的默认目标，因此除非明确指定，节点通常不会被添加到 RootNode。当然可以这样做，但只有在充分理解相关问题的情况下才应这样做。

例如，如果将 'effects' synth 放在默认组之后，并调用 Server-record 或 Server-scope，则生成的录音或示波器 synth 可能顺序不正确：

  • 默认组

    • 源 synth1
    • 源 synth2
  • 录制 synth
  • 效果 synth

在上面的示例中，录音 synth 可能无法捕获效果 synth 的输出，因为它在节点顺序中靠后。

在这种情况下，更好的方法是在默认组内创建一个组，并将效果 synth 放在该组之后。

  • 默认组

    • 源组

      • 源 synth1
      • 源 synth2
    • 效果 synth
  • 录制 synth

多客户端设置中的默认组

更多信息请参见 多客户端设置。

默认组机制也用于在多客户端设置中分隔客户端。每个向服务器注册的客户端都有自己独立的默认组。属于一个客户端的所有节点都在其默认组中，并且可以被专门寻址。

这默认使节点保持清晰分离，但客户端也知道所有其他客户端的默认组。这可以通过方法 Server: -defaultGroups 访问，它是一个将客户端 ID 映射到默认组的数组。

[1] - 从命令行启动服务器时，你可以手动创建默认组：s.initTree;
