第 5 章　实现改进的 Perlin 噪声

Ken Perlin
New York University

本章着重讲我在设计新版改进 Noise 函数时所做的决定。我重新设计它出于三个原因：（1）让 Noise 更适合逐步迁移到硬件；（2）在若干重要方面改善 Noise 函数的视觉特性；（3）推出一个单一的标准版本，在所有硬件和软件平台上返回相同的值。

本章结构如下：先描述 Noise 函数本身的目标，简要回顾最初的实现；然后讲述我在实现改进版 Noise 时所做的具体选择，用以提高质量、减少视觉瑕疵；最后讨论逐步迁移到硬件需要什么。目标是让 Noise 能用越来越少的指令实现，因为一代代 GPU 都在朝着更强的指令集演进。

5.1 Noise 函数

Noise 函数的用途，是在 R3（三维空间）上提供一个高效实现、可重复的伪随机信号，它是带限的（大部分能量集中在某个空间频率附近），并且在视觉上是各向同性的（统计上旋转不变）。

总体思路是造出与「完全随机的信号（即白噪声）经过低通滤波、去掉所有高空间频率」相同的效果。一个例子是沙丘上缓缓起伏的丘与谷，如图 5-1 所示。

5.2 最初的实现

最初的实现在 1983 年首次使用，1985 年首次发表（Perlin 1985），它用如下算法定义任意点（x、y、z）处的 Noise：

  1. 在空间中每个整数坐标点（i, j、k）处，赋予零值和一个由（i、j、k）哈希得到的伪随机梯度。
  2. 把（x、y、z）的坐标表示为整数值加小数余数：（x、y、z）=（i + u、j + v、k + w）。考虑包围该点的单位立方体的八个角：（i、j、k）、（i + 1、j、k）、……（i + 1、j + 1、k + 1）。
  3. 用一条 Hermite 样条拟合这八个点，并以 u 、 v 、 w 为插值参数，在 ( x , y , z ) 处对该样条求值。若用查表预先定义 Hermite 三次混合函数 3 t 2 - 2 t 2 ，那么这次插值只需要七次标量线性插值：例如在 x 方向做四次，接着在 y 方向做两次，最后在 z 方向做一次，如图 5-2 所示。

这种做法效果尚可。Noise 函数的一个二维切片看起来如图 5-3。

5.3 最初实现的缺陷

遗憾的是，Noise 有以下缺陷：

  • 各维所选用的插值函数是 3t 2 - 2t 3，它的二阶导数含非零值。这在求噪声导数时会造成视觉瑕疵，例如做凹凸贴图时。
  • 由 ( i , j , k ) 处的梯度做散列，得到的是对散布在三维球面上的 256 个梯度向量所构成伪随机集合的一次查表；这一分布的不规则性会在所得噪声函数中产生不需要的高频成分。参见图 5-4。

回过头看，我意识到应该在选取伪随机梯度方向的预处理步骤中应用一种松弛算法，让这些点在球面上互相排斥，形成更均匀、类泊松的分布，这样本可以减少不必要的高空间频率，得到如图 5-5 所示的结果。

最近我意识到，如此多不同的梯度方向在视觉上根本没有必要。更重要的是梯度方向具有均匀的统计分布，而非数量众多的不同梯度方向。这与知觉研究一致：人类的预注意视觉对纹理特征朝向的统计异常高度敏感，却对朝向的粒度相对不敏感，因为我们的低级视觉系统会把足够密集的一组离散朝向转换成等效的连续信号（Grill Spector et al. 1995）。人类视觉系统在非常早期的阶段就完成了这种转换，远低于意识觉察的阈值。

只要 Noise 实现具有统计上均匀的梯度方向分布，构建生成复杂外观纹理的过程化表达式就相当直接。例如图 5-6 展示了由 Noise 构建的四个复杂度依次递增的纹理表达式。

5.4 对 Noise 的改进

对 Noise 函数的改进集中在两个具体方面：插值函数的性质，以及伪随机梯度场的性质。

如我在 Perlin 2002 中所讨论的，改进插值函数的关键就是去掉二阶不连续。原来选用三次插值函数 3t 2 - 2t 3，是因为它在 t = 0 和 t = 1 处的导数都为零。遗憾的是它的二阶导数是 6 - 12t，在 t = 0 和 t = 1 处都不为零。这让 Noise 用于凹凸贴图时出现瑕疵。由于光照作用于凹凸贴图表面的效果随对应高度函数的导数变化，二阶导数的不连续就会显现出来。

改用五次插值函数解决了这个问题：6t 5 - 15t 4 + 10t 3，它在 t = 0 和 t = 1 处的一阶和二阶导数都为零。

两种插值函数的差别可在图 5-7 中看到。绿色曲线是原来的三次插值函数，它在 t = 0 和 t = 1 处有二阶不连续。蓝色曲线是新的五阶插值函数，它在 t = 0 和 t = 1 处没有二阶不连续的问题。

图形加速器的一个好处是，你可以通过一维纹理查找表来做一维插值。采用这种做法时，做更高阶插值没有额外开销。实践中我发现 256 的纹理表长度足够，16 位精度也足够。甚至半精度浮点（fp16）的 10 位尾数也够用。

图 5-8 展示了 Noise 置换后的超二次曲面的两种渲染。左边用原来的三次插值函数，右边用更新的五阶插值函数。视觉改善表现为形状正面上类似 4x4 网格的瑕疵减少了。

另一项改进是把 256 个伪随机梯度换成仅 12 个，它们是以原点为中心的立方体的各边中点：(0, ±1, ±1)、(±1, 0, ±1) 和 (±1, ±1, 0)。这让分布不再那么「斑驳」，对比图 5-9 中新旧两种 Noise 实现所得平面切片的并列比较即可看出。

之所以有此改善，是因为这 12 个梯度方向中没有任何一个与别的过于接近，因此它们绝不会挤得太紧。正是相邻梯度这种不必要的聚集，造成原版 Noise 实现中部分区域呈现斑驳外观。

这种做法还有一个好处：可以省去许多与求梯度函数相关的乘法，因为（x、y、z）与比如 (1, 1, 0) 的内积可以简单地算作 x + y。

为了让哈希到这组梯度的过程与尽可能快的硬件实现相容，实际定义了 16 个梯度，这样哈希函数直接返回一个 4 位随机值即可。多出的四个梯度只是重复 (1, 1, 0)、(-1, 1, 0)、(0, -1, 1) 和 (0, -1, -1)。

5.5 如何在像素着色器中做出好的伪噪声

若能完全在像素着色器里实现某种合理的体积噪声图元，那会很好，但直白的实现要花不少指令。我们怎样利用当今像素着色器的能力，用极少的指令实现 Noise 的某种合理近似？假定我们愿意使用分段三线性插值而非更高阶的多项式插值（因为当今 GPU 对三线性插值提供直接的硬件加速），并且愿意容忍使用三线性插值所带来的小幅梯度不连续。

一种解法是把整块噪声体放进一张三线性插值的纹理。遗憾的是这非常耗空间。例如，一个立方体从 (0, 0, 0) 采样到 (72, 72, 72)，每线性单位距离三个采样、再加一个末端采样，即每个方向 (3 x 72) + 1 个采样，将需要 217 x 217 x 217 = 10,218,313 个索引位置，大得不便使用。

但当今 GPU 能对尺寸适中的体积做快速三线性插值，这一点可以换一种方式利用。例如，8x8x8 的体积按同样方式采样，每个方向需要 (3 x 8) + 1 个采样，只有 25x25x25 = 15,625 个索引位置。我的做法是通过多次引用这样尺寸适中的存储体积来定义噪声。

那么怎样从 83 的立方体得到 723 的立方体？诀窍分两步：

  1. 用可环形平铺的 83 采样的副本填满空间。换句话说，构造这个采样，使它形成无限重复的连续图案，上边缘与下边缘无缝相接，左与右、后与前亦然。当这些采样像砖块一样在空间中堆叠时，就产生出一张连续但重复、铺满空间的纹理。
  2. 把这同一个采样图案放大九倍，用作低频图案，去扰动这套细尺度砖块平铺，使细尺度图案不再显得重复。

细节如下：不要把这个重复瓦片中的值定义为实数，而定义为复数值。注意这使表的存储开销翻倍（本例中为 31,250 个索引位置）。若表中每个数值标量用 16 位量表示，则存储该体积所需总内存为 31,250x2x2 字节 = 125,000 字节。

.03 * noise(x, y, z, 8); // 块状
.01 * stripes(x + 2 * turbulence(x, y, z, 1), 1.6);
// 大理石
- .10 * turbulence(x, y, z, 1);
// 皱褶

定义在下列函数之上：

// 条纹纹理（适合做大理石）
double stripes(double x, double f)
{
  double t = .5 + .5 * sin(f * 2 * PI * x);
  return t * t - .5;
}
// 湍流纹理
double turbulence(double x, double y, double z, double f)
{
  double t = -.5;
  for (; f < = W / 12; f *= 2) // W = 图像宽度（像素）
    t += abs(noise(x, y, z, f) / f);
  return t;
}

5.7 结论

用体积噪声做过程化贴图，在你想营造自然材质观感、又不愿制作显式纹理图像时极其有用。而且，你不必费心去想如何把纹理图像按参数映射到形体表面，基于噪声的纹理的体积特性让你只需在像素着色器里按（x、y、z）位置求值。这样一来，你实际上是从一块实心材料里凿出纹理，这往往比设法找出合理且不失真的参数化映射要直接得多。

基于噪声的纹理还让你能以分辨率无关的方式工作：靠近物体时纹理不会糊掉，只要你给纹理定义过程加入更高频率的噪声，它就能保持清晰和细节。

和过程化纹理的常规一样，应尽量不加入超过像素采样率的极高频率。这种超像素频率不会提升视觉质量，纹理动起来时还会产生不必要的颗粒感。

要在 GPU 上高效使用基于噪声的纹理，关键在于有一种真正用上 GPU 巨大算力的噪声实现。这里我们概述了这样一种实现，并给出了几个例子，说明如何在像素着色器中用它以过程化方式定义凹凸贴图。

这类基于体积噪声的过程化纹理长期以来是剧情长片的支柱，那里的着色器不要求实时性能，却要求高度还原自然材质的视觉外观。事实上，今天所有特效电影都大量使用基于噪声的过程化着色器。仅举两例：《完美风暴》中的海浪，以及《指环王》三部曲中大量的表面纹理与大气效果，其可信程度都高度依赖在以 Pixar 的 RenderMan 这类语言编写的像素着色器中对噪声函数的广泛使用。既然 GPU 上已经有了可用于实时的良好噪声函数实现，我期待看到剧情长片中一些激动人心的视觉创意被引入桌面与主机上的下一代互动娱乐。
