第 13 章　使用遮挡区间贴图生成软阴影

William Donnelly
University of Waterloo

Joe Demers
NVIDIA

本章我们介绍一种渲染软阴影的技术，我们称之为 遮挡区间贴图。遮挡区间贴图曾被用于 NVIDIA GeForce FX 5900 演示程序 「Last Chance Gas」 中生成软阴影。见图 13-1。我们之所以称之为遮挡区间贴图，是因为它用纹理贴图存储区间，表示光源何时可见、何时被遮挡。在满足算法要求的情形下，遮挡区间贴图让你能以高帧率获得令人印象深刻的视觉效果。

13.1 加油站

GeForce FX 5900 演示程序 「Last Chance Gas」 的目标之一，是做出一个具有准确室外光照的场景。我们想抓住的室外光照的一个重要方面，是太阳的软阴影。与阴影贴图或模板阴影体产生的硬阴影不同，软阴影有 半影 区域，在阴影区与非阴影区之间形成平滑过渡。正确的半影使阴影更真实，也让用户对空间关系有更好的感知，带来更真实、更有沉浸感的体验。

开始写这个演示时，我们找不到合适的实时软阴影算法，尽管针对这个问题的研究已经很多。由于软阴影问题如此之难，我们考虑如何简化问题，使其在实时条件下更可行。

考虑到加油站场景是静态的，我们考虑使用预计算可见性技术，例如 球谐光照（Sloan et al. 2002）。但对我们来说不幸的是，球谐光照假设光照频率极低，因此不适合太阳这样的小面积光源。我们开发了遮挡区间贴图，作为一种新的预计算可见性技术，可以实时得到太阳的软阴影。我们的方法把问题简化为沿固定轨迹的线光源，从而达成这个目标。

这个算法也与 地平线贴图（Max 1988）有相似之处。地平线贴图覆盖整个可见半球，而遮挡区间贴图只对沿可见半球上单一路径的光源有效。遮挡区间贴图还能处理任意几何体，而不只是高度场。

遮挡区间贴图并不打算作为软阴影问题的通用解法，但我们发现它对静态室外环境中的阴影很有用。与其他预计算可见性技术一样，遮挡区间贴图依赖离线过程存储所有可见性信息，因此对移动物体或任意光源不适用。

13.2 算法

假设我们有一个沿固定轨迹运动的光源，比如太阳，并且我们想为这个光源预计算硬阴影。我们可以把阴影表达为可见性函数：点在阴影中时值为 0，被照亮时值为 1。渲染时计算这个可见性函数，再把结果乘以一项着色计算，得到最终的颜色值。

可见性函数是三个变量的函数：两个空间维度对应物体表面，一个维度对应时间。我们可以把这个函数存成 3D 纹理，但显存需求会非常巨大。由于可见性函数的所有值非 0 即 1，我们可以改用类似游程编码的方法来存储。对每个点，我们在时间域上找出上升沿和下降沿。它们分别对应一天中太阳出现和消失的时刻。我们把所有上升沿构成的向量定义为「上升」向量，相应的「下降」向量由所有下降沿构成。见图 13-2。

现在硬阴影的预计算可见性所需的一切都已具备；给定上升向量、下降向量和一天中的时刻，我们就能计算可见性函数，判断该点是否在阴影中。

为了把它变成软阴影算法，我们沿轨迹把光源拉长。现在我们计算的不再是点光源的阴影，而是线光源的阴影。设想一个时间区间 。在这段时间里，光源会在空间中扫出一条曲线。如果我们对时间区间 内的光照取平均，就得到了线光源的正确阴影。这意味着，我们可以把渲染硬阴影图像所用的同一份信息用于渲染软阴影图像。见图 13-3。

13.3 创建贴图

为生成遮挡区间贴图，我们必须计算从光源轨迹上每一点到遮挡区间贴图中每个像素的可见性函数。做法是沿曲线取一系列等距点，从每个遮挡区间贴图像素向这些点各投一条射线，并检测每个可见性函数的上升沿和下降沿。我们用 8 位存储上升沿和下降沿的值；因此 256 条射线足以完整记录所有区间。为减少存储量，当某点的法线背向光源时，我们不存上升沿和下降沿。因为背面像素本来就是暗的，这个决定能省空间，且对渲染图像没有影响。

计算可见性函数可以由任何具备相应可编程能力的射线追踪器完成。我们用一个自定义着色器在 mental ray 软件包里计算了场景的全部数据。计算这些纹理会很耗时，因为遮挡区间贴图中的每个像素都要投 256 条射线。对于 "Last Chance Gas" 中的场景，计算整个场景的阴影花了几个小时。

我们把上升向量和下降向量存放在两组颜色纹理中，每张纹理四个通道。「上升」纹理在每个通道中存储一段光照区间的起点，对应的「下降」纹理存储光照区间的终点。等我们描述用遮挡区间贴图渲染的算法时，就会明白为什么这样拆分纹理。

为缓解存储遮挡区间贴图带来的额外显存需求，我们以颜色纹理一半的尺寸计算贴图，这使存储需求降低为四分之一。遮挡区间贴图的分辨率可以降低，因为阴影的柔和本身有模糊效果，可以弥补较低的分辨率。在某些情况下，我们发现即使把贴图分辨率降到颜色纹理尺寸的一半以下，也没有明显瑕疵。

对象参数化方面，我们使用物体自身的纹理坐标。由于遮挡区间贴图的像素存储的是与位置相关的信息，物体的纹理坐标不能重叠。对于使用平铺纹理的物体，这意味着要计算一套新的、唯一的纹理坐标。

示例 13-1. 用遮挡区间贴图计算软阴影的函数

half softshadow(sampler2D riseTexture, sampler2D fallTexture, float2 texCoord,
                half intervalStart, half intervalEnd, half intervalInverseWidth)
{
  half4 rise = h4tex2D(riseTexture, texCoord);
  half4 fall = h4tex2D(fallTexture, texCoord);
  half4 minTerm = min(fall, intervalEnd);
  half4 maxTerm = max(rise, intervalStart);
  return dot(intervalInverseWidth, saturate(minTerm - maxTerm));
}

注意这里用 saturate(x) 代替了 max(0, x)。这两个操作总是等价的，因为所考虑的量是可见光源区间的宽度，它总是小于 1。我们选择用 saturate(x) 而不是 max(0, x)，是因为它可以作为输出修饰符应用，省下一条指令。我们使用 16 位的 half 数据类型，发现它完全满足我们的需求，因为我们的计算超出了定点精度的范围，但不需要完整的 32 位浮点。

代码清单 13-1 最后一行的点积不是用于它通常的几何用途；我们用它同时完成除以光源宽度，以及把并行算出的各阴影值相加。我们以 intervalStart = t - 1/2dt、intervalEnd = t + 1/2dt 和 intervalInverseWidth = 1/dt 把这些值传给着色器。

这个着色器在 GeForce FX 上只编译成六条汇编指令：两次纹理查找、一个 min、一个 max、一次带 saturate 修饰符的减法，以及一个点积。该函数最多计算四个区间的阴影。如果有多个上升和下降纹理，我们只需多次调用该函数并把结果相加。

13.5 局限

如前所述，该技术只适用于静态场景，且只有单个光源沿固定轨迹运动。这意味着它不能用于角色和其他动态物体上的阴影，但很适合静态室外环境中的阴影。

由于遮挡区间贴图每个通道都需要完整 8 位精度，纹理压缩会导致视觉瑕疵。因此必须关闭纹理压缩，这会增加纹理占用。这一增加被遮挡区间贴图较低的分辨率抵消了。遮挡区间贴图中的不连续性意味着双线性滤波同样会产生瑕疵。于是，遮挡区间贴图上的任何纹理滤波都必须关闭。这使阴影看起来呈块状。同样，由于阴影本身的柔和，这种效果不像在细节丰富的颜色纹理上那样明显。

另一个视觉瑕疵来自用线光源近似太阳这一事实。如果你仔细看阴影边界，会发现阴影在平行于光源路径的方向上更平滑，在垂直方向上更硬。幸运的是，除非光源非常大，这种效果很微弱。在我们所用的宽度范围内，该效果并不明显。Heidrich 等（2000）也用线光源近似面光源，并指出线光源产生的阴影看起来非常像真实面光源的阴影。见图 13-4。

13.6 结论

实时渲染软阴影是一个极其困难的问题。图 13-5 和图 13-6 展示了其中微妙之处的两个例子。预计算可见性技术通过对场景和光源施加假设来产生软阴影。就遮挡区间贴图而言，我们以通用性换取性能，得到一个在静态场景上实时运行的软阴影算法。遮挡区间贴图可以替代静态光照贴图，实现动态效果，例如像 「Last Chance Gas」 中那样让光照从日出到日落变化。
