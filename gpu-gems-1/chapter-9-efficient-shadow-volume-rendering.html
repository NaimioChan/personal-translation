第 9 章　高效的阴影体渲染

Morgan McGuire
Brown University

9.1 引言

保安的影子先他一步进了金库——这提前的警示足够让窃贼躲到天花板上。异形掠食者贴在墙上，藏在旁边炮塔的阴影里，随时准备扑向松懈的星际战士。骑士的火把和德鲁伊的法杖照亮墓室中的雕像时，古老的大理石神祇投下的黄色与红色影子在四壁上摇曳。这些只是当今游戏中实时阴影用法的几个生动例子。

如今新的 3D 游戏都要求有实时阴影。玩家已经习惯了真实光照在感知、策略和电影感上带来的好处。与其他效果不同，阴影不是被渲染出来的物体，而是屏幕上因在光照计算中接收到的光较少而比别处更暗的区域。为渲染引擎加入阴影，难就难在实时找出这些区域。本章介绍如何用阴影体——id Software 的 Doom 3 等游戏所用的阴影方法——在模板缓冲中标记处于阴影中的像素。见图 9-1。一旦每个像素被判定为处于阴影中还是受光照，只要改动负责光照的像素程序，把受阴影像素的光照贡献置零即可。

9.1.1 何处使用阴影体

阴影体技术能由点光源、聚光灯和平行光产生锐利、逐像素精确的阴影。单个物体可以被多个光源照亮，光源可以有任意颜色和衰减。阴影从三角形网格投射到深度缓冲中的任何内容上。这意味着被投影的物体可以是网格、公告板、粒子系统，甚至是带有深度缓冲的预渲染场景。

与其他算法相比，阴影体能很好地处理许多难以投影的场景。图 9-2 就是这样一个棘手的场景。唯一的光源是南瓜灯内部的一个点光源。除了光从南瓜的孔洞中透出所照亮的几块三角形地面，整个场景都处于阴影中。这是个困难情形，原因有几个。它颠倒了我们通常的假设——场景大部分受光、阴影很小——很少有阴影把整个场景包住。受光面积相对于造成它们的南瓜孔洞来说非常大。虽然光只从前侧和底部透出，但光源是全向的，必须从各个角度考虑阴影。最后，投影者不只是靠近光源：它把光源包在里面了。

阴影体并不适合所有场景。该技术要构造一个 3D 体积，把物体投下的所有阴影都包住。这个体积由投影者的网格构造；然而有些投影者并没有能准确表示其形状的网格。例子包括公告板、粒子系统，以及用 alpha 遮罩贴图的网格（例如树叶）。这些投影者按其实际网格产生阴影，而实际网格与物体的真实外观并不一致。例如，一块公告板做的烟云会投下矩形阴影。

另一个有问题的物体是其网格中含有只有一个相邻面的边，通常称为裂缝。在现实世界里，往裂缝里看，你会看到物体的内部。当然，在渲染引擎里，你会穿过物体看到另一侧，因为内侧贴的是渲染时被剔除的背面多边形。这样的物体作为投影者毫无意义。从某些角度看，它投下实心阴影；从另一些角度看，光从孔洞透过去，从另一侧照出来。更糟的是，针对阴影体的某项优化在这些物体上会失效，在空处留下一条巨大的黑影，如图 9-3 所示。

这一做法的另一个潜在限制是：它要求场景中的所有东西都投射阴影。当角色的影子投到墙上时，它同时也投到了墙后的一切之上。观察者看不到墙那一侧的阴影，唯一的原因是墙自身投下的阴影与它重叠了。如果你让角色投射阴影而不让场景几何体投射阴影，阴影看上去就会穿过实心物体。

对阴影体性能最理想的场景是俯视视角，很多即时战略、体育和地面冒险游戏就是这种视角。这类场景由几个朝下的平行光照亮，相机在所有物体上方俯视地面。性能最差的情形是：场景中有多个点光源，处在一大堆投影物体中间——比如一大队举着火把的冒险者待在有柱子的地下房间里。

9.2 程序结构

阴影体技术分两部分：从轮廓边构造阴影体，以及把它们渲染到模板缓冲。这两部分要对每个光源重复执行，得到的图像相加成为最终的帧（这一过程称为多遍渲染）。基本算法容易理解和实现，但对大场景来说很慢。为此，一系列优化降低了所需的几何处理量和填充率。

我们先从程序结构的高层视角开始，接着详细讨论每一步，然后看几种优化。最后，我们通过考察几个关于阴影体的研究项目来展望未来。

9.2.1 多遍渲染

从数学上说，某一点的光照是若干项之和。单个光源的 Phong 光照公式就是如此：它是环境光、自发光（内部辉光）、漫反射和镜面反射分量之和。有多个光源的场景只有一个环境项和一个自发光项，但每个光源各有一个漫反射项和一个镜面反射项。在不做阴影渲染时，多个光源可以在单个渲染遍里全部完成。通常的做法是启用多个硬件光源，或者实现一个为每个光源写代码的像素着色器。

在有阴影渲染时，某个给定光源的贡献在某些点上为零，因为这些点处于阴影中。为此，每个光源的漫反射和镜面反射贡献放在单独的渲染遍里计算。最终图像是初始遍（计算环境光与自发光照明）与各个光照遍之和。由于初始遍把深度值写入了 z 缓冲，后续各遍的过度绘制为零，在填充率上可以便宜得多。在后续各遍中渲染的物体也很适合做遮挡剔除。

阴影体虽然无法产生面光源投下的软阴影，但可以利用多遍渲染来营造类似效果：在一个面光源的表面上分布多个较暗的聚光灯。可惜对于复杂场景，要让效果好看所需的光源数量太多，这种方法就慢得无法实用。（Assarsson 等人在 2003 年描述的一项新技术，提出了用阴影体渲染软阴影的更高效做法。）

各光照遍通过 alpha 混合合成。具体做法是：把环境光／自发光遍渲染到后备缓冲，启用深度写入，混合函数设为 glBlendFunc(GL_ONE, GL_ZERO)。这一步初始化深度缓冲，并生成基础照明。

然后对光照遍关闭深度写入，把混合函数改为 glBlendFunc(GL_ONE, GL_ONE)。这种混合模式把新渲染的像素加到已有的像素上。预先初始化的深度缓冲避免了过度绘制。另外一定要把深度测试设为 glDepthFunc(GL_LEQUAL)，以免后续各遍之间出现 z 冲突。

在这些设置下，为每个光源执行一遍。每一遍都清除模板缓冲，在其中标记阴影区域，然后计算非阴影区域的光照并累加到帧缓冲。

9.2.2 顶点缓冲结构

网格的阴影由其轮廓投出。为了快速找到轮廓边并把它们拉伸成阴影体，网格需要比传统只使用面三角形的渲染框架更多的信息。

在我们的系统中，网格的顶点缓冲为每个顶点保存两份拷贝。设有 n 个原始顶点。顶点缓冲的第 0 到第 n - 1 个元素是常规顶点，形式为 (x, y, z, 1)。第 n 到第 2n - 1 个元素是第一份的拷贝，但形式为 (x, y, z, 0)。第一份可用于常规渲染。两份都用于阴影判定，其中顶点着色器会把第二份变换到无穷远。

物体还必须有邻接信息和逐面法线。对每个面，我们需要知道三个逆时针方向的顶点索引和表面法线。对每条边，我们需要两个相邻面的索引和两个顶点的索引。如前所述，模型必须是封闭的，不能有裂缝。就邻接信息而言，这意味着每条边恰好有两个相邻面，这两个面含有相同的顶点但顺序相反。按约定，令边的第一个面索引为按正向遍历该边顶点的那个面，第二个索引为按反向遍历顶点的那个面。注意模型中可能存在不属于任何边或面的顶点。这是因为制作 3D 模型时，把纹理坐标不同的顶点放在同一位置是常见做法。对邻接信息，我们只关心原始几何体，忽略为渲染目的随模型存储的纹理坐标、法线、顶点颜色等。

9.2.3 在无穷远处工作

与你可能写过的其他 OpenGL 程序不同，阴影体大量使用无穷远处的坐标。阴影体本身既包含有限几何体，也包含无穷远处的几何体。算法是为点光源实现的，平行光则当作无穷远处的点光源处理。远裁剪面必须位于无穷远，这样才不会截掉无限的阴影体；透视投影也必须相应配置。

OpenGL 通过齐次坐标为在无穷远处工作提供完整支持。本节回顾齐次顶点（用于几何体和光源），并说明如何配置无限远透视矩阵。

有限的齐次点表示为 (x, y, z, 1)，即 w 分量等于 1。这隐含地表示 3D 位置为 (x/1, y/1, z/1) 的点。透视投影矩阵利用 w 分量除以一个非 1 的值，产生形如 (x, y, z, -z) 的顶点，经齐次除法后变成 (x/-z, y/-z, -1)。当 w 分量为零时会怎样？我们得到一个形如 (x/0, y/0, z/0) 的点。这个点「在无穷远处」。当然，如果真把每个分量除以 0 算出这个点，它会变成 (∞, ∞, ∞)，这丢掉了重要信息——该点趋向无穷远的方向。(x, y, z, 0) 这种表示用 w = 0 标记该点「在无穷远处」，同时保留了方向信息 (x, y, z)。

直观上，无论场景的物理尺度如何，无穷远处的点表现得就像在极远处。如同夜空中的星星，无穷远处的点随观察者位置变化而保持不动，但会随观察者朝向而旋转。OpenGL 能正确渲染 w = 0 的点。同样像星星，它们看上去像是渲染在以观察者为中心、「位于无穷远」的球面上。注意对无穷远处的点，只有方向 (x, y, z) 重要，各分量的大小并不重要。因此 OpenGL 用 w = 0 把平行光表示为位置是指向光源的向量的点光源，也就不奇怪了：平行光就是沿特定方向移到无穷远的点光源。

本章通篇用 w = 0 表示无穷远处的点。我们不仅使用无穷远处的点光源，还把阴影体拉伸到无穷远。上一节中我们把 w = 0 用作顶点缓冲后一半的记号。这是因为那些顶点会被移到无穷远（它们是阴影体的无限端）。不过在实际变换到无穷远之前，顶点着色器会先让它们相对于光源移动。

例 9-2　仿照 glFrustum 风格的无限远投影矩阵

void perspectiveProjectionMatrix(double left, double right, double bottom,
                                 double top, double nearval, double farval)
{
  double x, y, a, b, c, d;
  x = (2.0 * nearval) / (right - left);
  y = (2.0 * nearval) / (top - bottom);
  a = (right + left) / (right - left);
  b = (top + bottom) / (top - bottom);
  if ((float)farval > = (float)inf)
  {
    // 无限视锥体
    c = -1.0;
    d = -2.0 * nearval;
  }
  else
  {
    c = -(farval + nearval) / (farval - nearval);
    d = -(2.0 * farval * nearval) / (farval - nearval);
  }
  double m[] = {x, 0, 0, 0, 0, y, 0, 0, a, b, c, -1, 0, 0, d, 0};
  glLoadMatrixd(m);
}

9.3 详细讨论

markShadows 的目标是把模板缓冲中受光照的像素置零、处于阴影中的像素置为非零值。它的做法是构造阴影体——包住阴影区域的几何体——并把它渲染到模板缓冲。这里我们先简要看看其数学依据，然后详细讨论实现。

9.3.1 数学原理

图 9-5 显示一个简单场景：单个点光源（灯泡图标）、一个投影的盒子、一个接收阴影的地面，以及左侧的观察者。观察者前面的线代表图像平面，这对 9.5 节的讨论很重要。蓝色箭头代表从光源发出的光线（为清晰起见只画了几条）。最左和最右的光线打到地面处，地面是亮的。中间的光线打在投影者身上被挡住了。在这些光线被挡住的地方，投影者下方的地面是暗的（处于阴影中）。图中外侧光线与内侧光线之间某些位置是关键线，以虚线画出。这些线标出阴影的边界。注意它们穿过光源中心和投影者的边缘。图是 2D 的；在 3D 中它们不是线而是四边形。这些线就是阴影体的侧面。比投影者更远、且夹在这些面之间的所有点都在阴影中。其余点都受光照。

图 9-6 明确画出了阴影体。阴影体有三部分。

  • 侧面由投影者的边向外拉伸到无穷远形成四边形构成。投影者与光源之间的物体不应处于阴影中，所以必须在顶部把体积封闭。由于物体投下的阴影与其轮廓投下的阴影相同，我们只需拉伸轮廓边。所谓轮廓边，就是从光源角度看，其中一个相邻面是背面（N · L < 0）、另一个相邻面是正面（N · L > 0）的边。
  • 光盖是在靠近光源一侧封闭体积的几何体。它由投影者朝向光源的多边形（即从光源角度看是正面的多边形）构成。阴影向远离光源的方向无限延伸，但从数学上必须在后端把几何体封闭起来，才能构成体积。
  • 暗盖由投影者背向光源的多边形（即从光源角度看是背面的多边形）扩张到无穷远构成。在图 9-6 中它们被画成一条曲线，因为可以把无穷远处的多边形看作位于包围整个场景的极大球面上。

这些图虽然只是简单场景的 2D 示意，但要记住阴影体是 3D 的，如果投影者形状复杂，其几何体也会很复杂。作为对照，真实 3D 阴影体的几何形状见图 9-2、图 9-7 和图 9-10。如果有多个投影者（通常如此），阴影体会包含许多独立部分，这些部分甚至可能互相重叠。这些都不是问题；算法处理一个三角形和整个场景一样好，我们不需要为此做任何特别处理。

下面是用阴影体做阴影判定的数学思路。渲染时，每个像素对应 3D 空间中的一个点。如果该点在阴影体内，我们希望把该像素的模板缓冲设为非零值（处于阴影中）；否则设为零（受光照）。把这个待判定的点记为 P。考虑从 P 出发、沿负视线方向 -V 射向无穷远的射线与阴影体的交点。交点有两类。射线从阴影体外进入内部时是进入交点，设相交的阴影面的表面法线为 M，则进入交点处 M · V > 0。射线离开阴影体时是离开交点，此时 M · V < 0（忽略 M · V = 0 的掠射交点）。关键思路是统计两类交点出现的次数：

点 P 处于阴影中，当且仅当沿射向无穷远的射线，进入交点多于离开交点。

在透视投影下，沿负视线方向行进的射线恰好落在一个像素之内。我们利用这一点，借助模板缓冲在硬件上完成交点计数，从而让方法变得很快。

9.3.2 代码

下面说明如何在硬件上高效实现上述观察。把模板缓冲初始化为零，并启用回绕式递增和递减操作（如果显卡支持）。（若不支持回绕，就把所有模板值初始化为 128 或其他值以避免下溢。）关闭颜色渲染，把阴影体几何体渲染到模板缓冲。因为我们统计的是从每个可见点出发、远离观察者的射线上的交点，所以把硬件设置为在深度测试失败时改变模板值。每个通过不了深度测试的正面像素使模板值减一，每个通过不了深度测试的背面像素使模板值加一。

注意，我们在渲染阴影体之前刚关闭了颜色渲染，而深度写入则是在环境光照遍之后就关掉了。颜色写入和深度写入都已关闭，所以渲染阴影体只影响模板缓冲。必须关闭颜色写入，因为我们不想在最终图像中看到阴影体，只想看到阴影（它基于模板计数）。必须关闭深度写入，是因为我们假定 z 缓冲中的深度值代表可见表面的深度（而非阴影体的深度）。由于关闭了深度写入，各阴影面之间互不影响，因此渲染顺序无关紧要。

渲染之后，如果某像素处渲染的正面和背面数量相同，模板值为零；若数量不同则为非零。进入交点总由正面产生，离开交点总由背面产生。因此渲染后的模板计数就是进入交点数减去离开交点数——正是阴影判定所需要的结果。

9.3.3 markShadows 方法

Object 类上 markShadows 方法的代码见代码清单 9-4。

首先，我们把光向量从世界空间变换到物体空间。对点光源或聚光灯，该向量是位置 (x, y, z, 1)。对平行光，其形式为 (x, y, z, 0)，其中 (x, y, z) 是指向光源的向量。一般来说，w = 0 的齐次向量可以看作无穷远球面上的一个点。因此平行光等同于位于无穷远处的点光源。

例 9-4　markShadows 方法

// 面 f 背对光源时 isBackface[f] = true
// std::vector backface;
void Object::markShadows(const Vector4 &wsL)
{
  // （当视口未被该物体的阴影覆盖时，
  // 这一节会被“去盖”优化改写。）
  // 正面递减、背面递增
  // （即 z-fail 渲染）
  glActiveStencilFaceEXT(GL_FRONT);
  glStencilOp(GL_KEEP, GL_DECR_WRAP_EXT, GL_KEEP);
  glActiveStencilFaceEXT(GL_BACK);
  glStencilOp(GL_KEEP, GL_INCR_WRAP_EXT, GL_KEEP);
  glCullFace(GL_NONE);
  // （“Z 边界”优化会在这里设置深度边界。）
  // 把光源变换到物体空间，并计算光源的背面
  obj->findBackfaces(cframe.inv() * wsL);
  // 为顶点缓冲渲染做准备
  glVertexBuffer(vertexBuffer);
  renderShadowCaps();
  renderShadowSides();
  glVertexBuffer(NULL);
}

有了这个物体空间的光向量，我们计算朝向光源的面和背向光源的面。朝向信息只是临时需要，存在一个全局数组里。然后选用（双倍长度的）顶点缓冲，把阴影的光盖和暗盖作为三角形渲染。最后把阴影体的侧面作为四边形渲染。

9.3.4 findBackfaces 方法

findBackfaces 方法遍历每个面并计算 N · L，如代码清单 9-5 所示。

例 9-5　findBackfaces 方法

void Object::findBackfaces(const Vector4 &osL) // 物体空间中的
// 光照向量
{
  backface.resize(face.size());
  for (int f = 0; f < face.size(); ++f)
  {
    Vector3 L = L.xyz() - vertex[face[f].vertex[0]] * L.w;
    backface[f] = dot(face[f].normal, L) < 0;
  }
}

对有限的点光源，需要指向具体多边形的向量，所以我们用光源位置减去某个面顶点的位置。对平行光，直接使用光照方向不变。为了性能，这两种情形可以放在两个循环里分别处理；本例中把它们合在一起只是为了简短。注意这些向量都不需要是单位长度，因为我们只关心 N · L 的符号，不关心大小。

如果模型有动画，面法线必须每帧根据动画后的顶点重新计算。这就排除了在硬件中做矩阵蒙皮或顶点混合的可能，因为那样修改后的几何体在 CPU 上就取不到了。本章末尾我们会讨论一些把阴影体与硬件顶点位移结合起来的研究方案。

9.3.5 光盖与暗盖

有了背面数组，就能计算盖和阴影体侧面。每种情况都是先累积一个顶点索引列表，然后用 glDrawElements 从顶点缓冲渲染这些索引。索引临时存放在另一个名为 index 的全局数组中。

光盖和暗盖的代码见代码清单 9-6。

例 9-6　renderShadowCaps 方法

// 顶点缓冲的索引 std::vector
index;
void Object::renderShadowCaps()
{ // （“剔除”优化会修改这个
  // 方法，
  // 以便分别剔除亮盖与暗盖。）
  index.resize(0);
  for (int f = face.size() - 1; f > = 0; --f)
  {
    if (backface[f])
    {
      // 暗盖（顶点相同，但位于无穷远）
      for (int v = 0; v < 3; ++v)
      {
        index.pushBack(face[f].vertex[v] + n);
      }
    }
    else
    {
      // 亮盖
      for (int v = 0; v < 3; ++v)
      {
        index.pushBack(face[f].vertex[v]);
      }
    }
  }
  glDrawElements(GL_TRIANGLES, index.size(), GL_UNSIGNED_INT, index.begin());
}

光盖就是朝向光源的多边形。要生成暗盖，我们取背向光源的面，把它们送到远离光源的无穷远处。为此，我们从第二份顶点渲染，顶点着色器会替我们把它们送到无穷远。

图 9-7 显示一个动画的 Quake 3 角色站在白色地面上，由一个白色点光源照亮。角色的阴影体在图的右侧以黄色显示。注意暗盖的形状——即阴影体远离角色的那部分——与角色形状相同，只是被放大了。光盖看不见，因为它在角色内部。在光盖与暗盖之间延伸的多边形是侧面，它们由轮廓边构造。

9.3.6 侧面

阴影体的侧面是第一份与第二份顶点之间的四边形——也就是物体与无穷远之间的部分。我们遍历网格的边。回想一下，只有轮廓上的边需要拉伸成四边形；其他边不影响阴影体。

轮廓边出现在物体的一个背光面与一个朝光面相接处。做这种分类所需的信息我们都有。边里存了两个相邻面的索引，而背面数组告诉我们哪些面索引对应背光面。见代码清单 9-7。

为网格构造边信息时，必须保证边的朝向一致，这样得到的阴影面四边形绕序才正确。在阴影面上，顶点必须逆时针绕，使表面法线指向阴影体外。为保证这一点，我们采用这样的约定：从顶点 v0 = edge[e].vertex[0] 到顶点 v1 = edge[e].vertex[1] 的有向边，在索引为 edge[e].face[0] 的网格面中是逆时针的，在索引为 edge[e].face[1] 的网格面中是顺时针（反向）的。

阴影四边形的边方向必须与背面一致。因此，如果面 edge[e].face[0] 是背面，阴影面就包含从 v0 到 v1 的边；否则包含从 v1 到 v0 的边。图 9-8 显示了边从 v0 指向 v1 时，朝光面与阴影四边形的绕序方向。

例 9-7　renderShadowSides 方法

void Object::renderShadowSides()
{
  index.resize(0);
  for (int e = edges.size() - 1; e > = 0; --e)
  {
if (backface[edge[e].face[0]] != backface[edge[e].face[1])
{
  // 这是一条轮廓边
  int v0, v1;
if (backface[edge[e].face[0]))
  {
    // 与面 0 的绕序一致
    v0 = edge[e].vertex[0];
    v1 = edge[e].vertex[1];
  }
else
{
  // 与面 1 的绕序一致
  v1 = edge[e].vertex[0];
  v0 = edge[e].vertex[1];
}
// （“平行光”优化会修改这段代码。）
index.pushBack(v0);
index.pushBack(v1);
index.pushBack(v1 + n);
index.pushBack(v0 + n);
}
  }
  // （“平行光”优化会把它改成使用
  // GL_TRIANGLES 而不是 GL_QUADS。）
  glDrawElements(GL_QUADS, index.size(), GL_UNSIGNED_INT, index.begin());
}

至此我们走完了整套阴影渲染流程。我们建立的系统能在模板缓冲中把像素判定为处于阴影中或不受阴影，然后只给不受阴影的像素加光照。该系统能处理多种不同光源和复杂的投影者几何体，也能与投影阴影、阴影贴图等其他阴影算法配合使用。程序可以改成只给通过全部阴影测试的区域加光照。

利用阴影体算法在某些常见情形下可以简化的特点，我们能显著加快这一过程。本章余下部分介绍加快阴影体构造与渲染的方法。在实践中，下面这些方法能把基础算法的速度提高到四倍。

9.4 调试

要看自己生成的阴影体是否正确，可以临时启用颜色渲染，再用加性 alpha 混合绘制阴影体。打开面剔除，正面用一种颜色、背面用另一种颜色。这些形状除了调试还有别的用途：你可能想在游戏过程中渲染可见的阴影体来做出效果，比如穿过云层或树丛的光束。

记住，使用模板操作时，OpenGL 要求启用模板测试，即使它被设为 GL_ALWAYS_PASS。另外别忘了模板掩码：glStencilMask(~0)。这两项前提漏掉任何一个，你的写操作都会被忽略。

用断言检查每条边是否恰好有两个相邻面。如果模型有裂缝，就会在空中出现图 9-3 里那种阴影条带。3ds max 之类的软件建模工具能自动修复裂缝（称为顶点焊接）——用起来！

9.5 几何优化

为清晰和简单起见，本章前半部分以通用形式描述基础阴影体算法，把平行光、点光源和聚光灯一视同仁。我们在代码清单 9-5 中用了数学技巧 L.xyz() - V * L.w，代码清单 9-3 的顶点着色器里也用了类似技巧。这些代码用一个表达式就算出两类光源的光向量。我们可以把两类光源在顶点着色器中以及整个阴影体生成过程中分开处理，以此提升性能。平行光产生的阴影体比点光源的简单，所以这里能省下很多（代价是代码更复杂）。

我们还可以用保守包围体来剔除阴影几何体，从而改善几何处理性能。本节介绍这些优化。

9.5.1 平行光

对平行光，光向量就是 L.xyz。由于光向量在所有顶点处相同，暗盖的所有顶点都在同一个点，即 -L。这意味着不存在暗盖：阴影体的（平行）侧面在无穷远处汇聚成一点，因此不需要盖。

由于汇聚成一点，侧面是三角形而不是四边形。renderShadowSides（代码清单 9-7）中的 push 语句变成：

index.pushBack(v0);
index.pushBack(v1);
index.pushBack(n);

这些语句不仅索引更少，对顶点缓存也更友好。这是因为同一个顶点编号 n 被多次传入（我们也可以传索引大于等于 n 的任何一个顶点，因为它们都变换到同一个点）。另一种做法是完全去掉顶点着色器，在每个阴影遍之前额外加一个索引为 2n、设为负光向量的顶点。

9.5.2 点光源与聚光灯

点光源通常按距离衰减。超过一定距离后，点光源发出的光可以忽略不计（当它降到 1/255 以下时，在八位帧缓冲里根本看不出结果）。聚光灯按角度衰减，有时也按距离衰减。在聚光灯锥体之外，它们不提供任何光照。

如果物体在任一类光源的有效范围之外，它就不需要投射阴影，因为它后面的任何物体也在范围之外。检测这种情况，可用投影者的包围盒去测试距离衰减光源的包围球，或角度衰减光源的锥体。物体在范围之外时，不为它标记阴影。同样，光源范围之外的物体也不需要光照遍。

9.5.3 剔除阴影体

和常规几何体一样，剔除视图视锥之外的阴影几何体可以提高阴影体的顶点处理速度。注意投影者可能在视图视锥之外却仍在可见物体上投下阴影，所以剔除投影者和剔除阴影几何体是完全独立的两件事。

侧面和盖要分开剔除。对每一部分，用一个几何图元近似阴影几何体，再用视图视锥剔除该图元。光盖可以用与投影者几何体相同的包围体，因为盖在投影者内部。暗盖用的是同一套几何体，只是被送到远离光源的无穷远处。

例如，假设有投影者的包围盒。对包围盒的每个顶点 v，用公式 v' = MV * (v * L w - L xyz 把它变换到无穷远，其中 L 是物体空间的光向量，MV 是模型视图矩阵。然后用变换后的包围盒去测试视图视锥。如果盒子被剔除，暗盖也可以剔除。阴影体侧面最容易用平行光的圆柱体、点光源的截锥体来界定。

虽然任何剔除都有帮助，但剔除盖尤其能加快顶点处理，因为盖的顶点数比侧面多得多。对点光源，暗盖可能非常巨大；剔除它还能省下大量填充率。这就是卡通片里小猫站在手电筒前投出狮子般巨大阴影的效果。图 9-7 展示了这种放大效应：模型的暗盖比模型本身大好几倍。

9.5.4 无盖性能

即使在盖本来不会被剔除的情况下，还有另一种技术可以在视口不受阴影这一特殊情形下去掉盖。

在数学表述中，我们用的是从某点出发、远离观察者射向无穷远的射线。在实现中，这些射线是通过把多边形渲染到模板缓冲来模拟的。我们把远裁剪面移到无穷远，并让射线远离观察者，这样就不会因为裁剪而漏掉该点与无穷远之间的交点。

也可以朝反方向计数。要统计远离观察者方向的交点，在深度测试失败时递增或递减模板缓冲；要统计朝向观察者的交点，在深度测试通过时递增或递减。当视口不在阴影体内时，从不受阴影的点到图像平面的线段上的交点数为零。这是因为从不受阴影的点到不受阴影的视口，线段必然穿过相同数量的进入交点和离开交点。如果该点处于阴影中，交点数就非零。当然，只有在视口本身不在阴影中时才能朝这个方向计数；否则计数会偏差，差的是包围每个视口像素的阴影体数量。图 9-7 展示了可以用这一优化的情形，因为向场景深处延伸的阴影并没有把视口包住。图 9-2 则是不能用它的例子，因为视口处在南瓜投下的阴影中——实际上场景里所有东西都在阴影中，只有光从眼睛透出的那几块三角形地面例外。

朝观察者计数的好处是不需要渲染光盖和暗盖。光盖总是通不过深度测试，因为它在投影者内部，所以没理由渲染它。由于我们是从可见点朝观察者计数，位于无穷远的暗盖不可能产生交点，也就无从改变结果，因此不需要渲染它。

这一优化需要对代码做两处改动：

  1. 我们需要（保守地）检测视口是否在阴影体内。这个检测对每个投影者单独进行；我们可以为每个投影者独立选择计数方向，结果依然正确。
  2. 如果视口不在阴影体内，需要把模板操作中递增／递减的方向反过来（只对该投影者）。

图 9-9 显示了视口的遮挡金字塔。锥尖在光源处（如果是平行光则在无穷远），底面是视口。如果投影者的包围盒与这个金字塔相交，视口就可能处于阴影中，这一优化就不能用。这种情况下必须用常规的深度失败操作渲染，并在盖可见时把两个盖都画出来。如果包围盒不与金字塔相交，就可以改变模板操作。

遮挡金字塔可以位于视口的任一侧。如果投影者与绿色金字塔相交，就不能使用「无盖」优化。

对朝观察者计数，模板操作设置如下：

// 正面递增、背面递减
// （即 z-pass 渲染）
glActiveStencilFaceEXT(GL_FRONT);
glStencilOp(GL_KEEP, GL_KEEP, GL_INCR_WRAP_EXT);
glActiveStencilFaceEXT(GL_BACK);
glStencilOp(GL_KEEP, GL_KEEP, GL_DECR_WRAP_EXT);

因为这是「无盖」渲染，把渲染阴影体盖的代码从这一情形中完全去掉。

9.6 填充率优化

填充率是阴影体的软肋。阴影体覆盖大量像素，过度绘制很多。对点光源尤其麻烦，因为它产生的阴影离投影者越远就越大。所幸点光源也有很大的优化空间，因为它们的衰减造成一个范围，超出该范围光照实际上为零。我们已经讨论过不为范围之外的投影者标记阴影，也不对范围之外的物体渲染光照。现在我们来看三种降低范围之内投影者所需填充率的办法：有限体积、XY 剪裁与 z 边界。

9.6.1 有限体积

点光源的范围构成一个球。球外的物体接收不到光照，所以没必要在球外投射阴影。我们可以不把阴影体拉伸到无穷远，而是按球的半径延伸，从而省下渲染无限多边形的填充率。这对顶点着色器是个直接的改动，能收回可观的填充率。这一方法下暗盖更容易出现在屏幕上，因此因暗盖不易被剔除，几何处理量可能增加。

另一种做法仍然创建延伸到无穷远的多边形，但在 2D 中把它们剪裁到光源半径，如下一项优化所述。

9.6.2 XY 剪裁

范围球投影到屏幕上是一个椭圆。只有该椭圆内的像素才可能受光照，椭圆之外的阴影多边形或光照我们都不需要渲染。然而硬件支持的是矩形剪裁区域，不是椭圆。我们本可以求投影椭圆的包围盒，但更方便的是用包围光源范围的 3D 包围盒投影后的 2D 包围盒。固定功能管线只支持径向衰减，而美术可以在光源周围的一个立方体体积上指定任意衰减函数，从而得到更可控的效果，Doom 3 就是这么做的。衰减在盒内可以任意下降，所以我们就用这个盒子作为光源范围。把光源的盒子剪裁到视图视锥。如果它没有被完全剪掉，就把剩余多面体的所有顶点投影到视口上并求包围。最终的 2D 包围就是所用的矩形剪裁区域。用 glScissor 命令设置剪裁区域：

glScissor(left, top, width, height);
glEnable(GL_SCISSOR_TEST);

图 9-10 显示一个 Quake 3 角色站在建筑外面。这就是图 9-7 的场景，只是相机后移了。单个点光源由角色和建筑产生阴影体（以黄色显示），若不把它们剪裁到光源的有效边界，这些阴影体会铺满屏幕。剪裁区域在图的右半部分以白色方框显示。图左半部分是可见场景，这里剪裁的效果看不出来，因为光源照不到建筑远处的部分。对这个场景，只渲染剪裁区域内的阴影体像素能把填充率开销减半。

9.6.3 z 边界

如果某像素处的点落在光源范围之外——因为它比范围边界更近或更远——该点不可能受光照，因此不需要在这个像素上做阴影标记或光照遍。把这两类遍限制在特定深度范围，就意味着只为真正受光源影响的那些像素付出填充率，而这可能比光源 2D 边界内的像素更少。

glDepthBoundsEXT 函数让我们设置这一行为：

glEnable(GL_DEPTH_BOUNDS_TEST_EXT);
glDepthBoundsEXT(zMin, zMax);

这一设置会阻止渲染那些深度缓冲已经含有 [zMin, zMax] 范围之外值的像素——也就是说，该像素上可见的点（在环境光遍中渲染的）在范围之外。这与剪裁平面不同，剪裁平面阻止的是从超出边界的多边形渲染出新像素。

图 9-11 显示观察者看着一个被点光源照亮的物体。投影者的阴影向下投向崎岖的地面斜坡。地面上粗绿线的部分不可能被投影者遮蔽。深度边界测试省下了渲染阴影体橙色部分的填充率，因为它们后面的可见像素（粗绿线部分）在边界之外。注意阴影体本身在边界之内，但这无关紧要——深度边界作用于环境光遍中渲染的像素，而非阴影几何体。

注意深度边界比单纯的光源范围更严格。它是由视图视锥、光源范围和阴影体包围三者之交所定义的深度范围。OpenGL 函数的参数是投影后的相机空间值。如果交集的几何体由顶点存放在数组 std::vector<Vector4> boundVert 中的多面体定义，参数这样计算：

float zMin = 1.0f;
float zMax = 0.0f;
for (int v = boundVertex.size() - 1; v > = 0; --v)
{
  float z = 1.0f / (projectionMatrix * boundVert[v]).w;
  zMin = min(zMin, z);
  zMax = max(zMax, z);
}

9.7 阴影的未来

目前这种高度优化的阴影体方法是过去几十年产业界与学术界共同贡献的结果。基础方法由 Frank Crow 在 SIGGRAPH 1977 上提出，并逐步成熟为本章所述的方法。阴影体的历史以及若干研究者与开发者的个人贡献，总结在 NVIDIA 开发者网站上的技术报告中（Everitt and Kilgard 2002；McGuire et al. 2003）。McGuire et al. 2003 对本章所述方法给出了形式化描述与分析。

通过新的优化来提升阴影体生成的性能，至今仍是活跃的研究领域。轮廓判定一直在 CPU 上完成，这是一大限制。它排除了在顶点着色器里做矩阵蒙皮或其他形变的可能，并且使渲染在 CPU 操作上串行化。

已经有人提出若干方案，直接在可编程图形硬件上做轮廓判定。Michael McCool（2001）提出了一种从阴影贴图计算投影者轮廓的方法。Brabec 和 Seidel（2003）把编码为颜色的几何体送入像素处理器，在其中计算轮廓，然后读回帧缓冲，用作阴影渲染的顶点缓冲。John Hughes 和我最近描述了如何借助一张专门预计算的网格，完全在顶点着色器中找出轮廓并把它们拉伸成阴影体侧面（McGuire and Hughes 2003）。

用阴影体从面光源得到好看且高性能的软阴影，是另一个开放的研究课题。Ulf Assarsson 和 Tomas Akenine-Möller 在这个问题上研究了一段时间。他们与 Michael Dougherty、Michael Mounier 合作的最新论文（Assarsson et al. 2003）描述了如何为半影（软阴影区域）的内外边界构造显式几何体，并大量使用可编程硬件。

有几个人提出把各条轮廓边连接成连续的条带，这样就可以用四边形条带（对点光源）和三角扇（对平行光）来渲染阴影体侧面。Alex Vlachos 和 Drew Card（2002）在研究另一个简化思路：剔除和剪裁嵌套的阴影体，因为它们不会影响最终结果。

这些方法都还是实验性的，尚待在真实游戏引擎中打磨和验证。如果你想超越当前阴影体方法的能力，这些都是不错的起点。希望未来的研究与图形硬件能改进并加速这些方法。
