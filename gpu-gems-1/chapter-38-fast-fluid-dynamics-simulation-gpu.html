第 38 章　GPU 上的快速流体动力学仿真

Mark J. Harris
University of North Carolina at Chapel Hill

本章描述一种完全在 GPU 上运行的快速、稳定流体仿真方法。它介绍流体动力学及相关数学，并详细描述在 GPU 上执行仿真的技术。读完本章，你应当对流体动力学有基本认识，并知道如何用 GPU 模拟流体。本书附带的源代码演示了本章所述的技术。

38.1 引言

流体无处不在：在河岸间流过的水、从燃烧的香烟上袅袅升起的烟、从茶壶里冲出的蒸汽、凝结成云的水汽，以及罐中被搅动的颜料。它们底下都是流体的流动。这些都是我们希望在交互式图形应用中逼真描绘的现象。图 38-1 展示了用本书附带源代码模拟的流体的例子。

流体仿真是模拟各种自然现象的一个有用基石。由于图形硬件具有大量并行性，我们描述的仿真在 GPU 上运行明显快于在 CPU 上。使用 NVIDIA GeForce FX，我们比等效的 CPU 仿真快了最多六倍。

38.1.1 我们的目标

我们的目标是帮你学会一件强大的工具，而不只是教你一个新技巧。流体动力学是更复杂仿真中极为有用的组成部分，把它当作黑箱会是错误的。不理解流体基本的物理与数学，使用和扩展我们给出的算法会非常困难。因此这里在数学上并不吝惜篇幅。结果就是，本章包含许多看起来令人生畏的公式。凡是可能的地方，我们都给出清楚的解释，并把数学与它的实现联系起来。

38.1.2 我们的假设

读者应至少具备大学水平的微积分基础，包括对微分方程的基本掌握。了解向量微积分原理会有帮助，但不是必需的（需要的地方我们会复习）。此外，具备导数有限差分近似的经验也有用。如果你曾实现过任何形式的物理仿真，例如抛体运动或刚体动力学，我们用到的许多概念你都会感到熟悉。

38.1.3 我们的做法

我们描述的技术基于 Stam 1999 的「稳定流体」方法。不过 Stam 的仿真是用 CPU 实现的，我们选择在图形硬件上实现，因为 GPU 很适合流体仿真所需的那类计算。我们描述的仿真在单元网格上进行。可编程 GPU 针对像素运算做了优化，而我们可以把像素看作一个单元网格。GPU 通过并行达到高性能：它能同时处理多个顶点和像素。它还针对每周期执行多次纹理查找做了优化。由于我们的仿真网格存储在纹理中，这种速度和并行性正是我们需要的。

本章无法把流体动力学的一切都教给你。这里能覆盖的仿真概念范围必然是有限的。我们把自己限制在二维矩形区域上连续体积流体的仿真。此外，我们不模拟流体之间的自由表面边界，例如晃动的水与空气之间的界面。这些基本技术有许多扩展。我们在章末提到其中一些，并给出进一步阅读的指引。

全章使用统一的数学记号。公式中，斜体用于表示标量的变量，例如压力 p。粗体用于表示向量，例如速度 u。本章所有向量都假定为二维。

38.2 数学背景

要模拟流体的行为，我们必须有流体在任意时刻状态的数学表示。最重要的量是流体的速度，因为速度决定了流体自身以及其中物体的运动方式。流体的速度随时间和空间变化，因此我们把它表示为一个向量场。

向量场是把向量值函数映射到参数化空间（例如笛卡尔网格）上的结果。（也可以采用其他空间参数化，但本章中我们假定使用二维笛卡尔网格。）流体速度向量场的定义是：对每个位置 x = (x, y)，在时刻 t 都有一个关联的速度 u(x, t) = (u(x, t), v(x, t), w(x, t))，如图 38-2 所示。

流体仿真的关键是在时间上逐步推进，并在每个时间步正确确定当前速度场。做法是求解一组描述速度场在各种外力作用下随时间演化的方程。一旦有了速度场，我们就可以用它做有意思的事，例如用它移动物体、烟密度，以及其他可在应用中显示的量。

38.2.1 不可压缩流动的纳维–斯托克斯方程

在物理学中，为复杂现象建模时做简化假设很常见。流体仿真也不例外。我们假定流体是不可压缩、均匀的。

如果流体任何子区域的体积随时间保持不变，该流体就是不可压缩的。如果流体的密度 在空间上恒定，该流体就是均匀的。不可压缩与均匀这两条合起来，意味着密度在时间和空间上都恒定。这些假设在流体动力学中很常见，而且并不削弱所得数学对水、空气等真实流体仿真的适用性。

我们在规则笛卡尔网格上仿真流体动力学，空间坐标为 x = (x, y)，时间变量为 t。流体由前述速度场 u(x, t) 和标量压力场 p(x, t) 表示。这两个场都随时间和空间变化。若已知初始时刻 t = 0 的速度与压力，则流体随时间的状态可由不可压缩流动的纳维–斯托克斯方程描述：

38.2.2 纳维–斯托克斯方程中的各项

平流

流体的速度使流体带着物体、密度和其他量随流动一起运动。想象把染料喷进流动的流体中。染料被带着走，或者说被平流，沿着流体的速度场运动。事实上，流体的速度不仅带着染料走，也带着它自己走。公式 1 右侧的第一项表示速度场的这种自平流，称为平流项。

压力

由于流体的分子可以互相错动，它们容易「被挤压」和「晃荡」。当力作用在流体上时，它不会立刻传遍整个体积。相反，靠近施力处的分子推挤较远处的分子，压力逐渐积累。由于压力是单位面积上的力，流体中任何压力都会自然导致加速度。（想想牛顿第二定律 F = m a。）第二项称为压力项，表示这一加速度。

扩散

根据对真实流体的经验，你知道有些流体比另一些更「稠」。例如糖浆和枫糖浆流得慢，而外用酒精流得快。我们说稠的流体黏度高。黏度衡量流体对流动的阻力。这种阻力导致动量（因而速度）的扩散，所以我们把第三项称为扩散项。

外力

第四项概括了作用在流体上的外力所引起的加速度。这些力可以是局部力，也可以是体力。局部力作用在流体的特定区域，例如风扇吹风产生的力。体力（例如重力）均匀作用于整个流体。

在简要复习向量微积分之后，我们会回到纳维–斯托克斯方程。详细的推导和更多细节，推荐参阅 Chorin and Marsden 1993 以及 Griebel et al. 1998。

38.2.4 求解纳维–斯托克斯方程

纳维–斯托克斯方程只在少数简单的物理构型下才有解析解。不过可以用数值积分技术逐步求解。由于我们关心的是观察流动随时间的演化，逐步的数值解正合我们的需要。

与任何算法一样，我们必须把纳维–斯托克斯方程的求解拆成简单的步骤。我们所用的方法基于 Stam 1999 描述的稳定流体技术。本节描述各步骤的数学，38.3 节描述它们在 GPU 上用 Cg 语言的实现。

首先需要把方程变换成更适合数值求解的形式。回忆一下，纳维–斯托克斯方程是三个方程，我们可以求解 u、v 和 p 这三个量。但如何求解并不显然。下面一节描述一种变换，它能导向一个直接的算法。

亥姆霍兹–霍奇分解

基本的向量微积分告诉我们，任何向量 v 都可以分解为一组基向量分量，其和为 v。例如，我们通常把笛卡尔网格上的向量表示为沿网格轴的两个距离：v = (x, y)。同一个向量可以写成 v = x î + y ĵ，其中 î 和 ĵ 是与网格轴对齐的单位基向量。

这种做法有两个问题：第一，用显式方法做平流的仿真在大时间步下不稳定，若 u(t)t 的幅值大于单个网格单元的尺寸，它就会「炸开」。第二个问题与 GPU 实现有关。我们把仿真实现在片元程序中，而片元程序无法改变它正在写入的片元的位置。这种前向积分方法需要「移动」粒子的能力，因此无法在当前 GPU 上实现。

泊松方程的求解

我们需要求解两个泊松方程：泊松-压力方程和黏性扩散方程。泊松方程在物理学中很常见，也已被充分理解。我们采用迭代求解技术，从一个近似解出发，每次迭代都加以改进。

泊松方程是形如 Ax = b 的矩阵方程，其中 x 是待求解的值向量（在我们的情形是 p 或 u），b 是常数向量，A 是矩阵。在我们的情形，A 隐含在拉普拉斯算子 ∇2 中，不必显式存成矩阵。我们用的迭代求解技术从解的初始「猜测」x (0) 出发，第 k 步产生改进解 x (k)。上标表示迭代次数。最简单的迭代技术叫 Jacobi 迭代。一般矩阵方程的 Jacobi 迭代推导见 Golub and Van Loan 1996。

共轭梯度和多重网格等更精细的方法收敛更快，但我们选用 Jacobi 迭代，因为它简单、易于实现。更复杂求解器的细节与示例见 Bolz et al. 2003、Goodnight et al. 2003 和 Krüger and Westermann 2003。

初始条件与边界条件

定义在有限区域上的任何微分方程问题都需要边界条件才能适定。边界条件决定了我们如何计算仿真区域边缘处的值。此外，要计算流动随时间的演化，我们必须知道它如何开始——也就是它的初始条件。对流体仿真，我们假设流体初始处处速度为零、压力为零。边界条件还需要稍多讨论。

在每个时间步，我们求解两个量的方程——速度和压力——两者都需要边界条件。由于流体是在矩形网格上仿真的，我们假设它是盒子里的流体，不能穿过盒子的侧壁。对速度，我们采用无滑移条件，即速度在边界处为零。要正确求解泊松-压力方程，需要纯 Neumann 边界条件：∂p/∂ n = 0。这意味着在边界处，压力沿边界法向的变化率为零。我们在 38.3 节末尾再讨论边界条件。

38.3 实现

现在我们已经理解了问题和求解的基本思路，可以进入实现。一个好的起点是为算法写出伪代码。算法在每个时间步都相同，所以这段伪代码表示单个时间步。变量 u 和 p 保存速度场和压力场数据。

// 依次应用前 3 个算子，见公式 12。
u = advect(u);
u = diffuse(u);
u = addForces(u); // 现在对结果施加投影算子。
p = computePressure(u);
u = subtractPressureGradient(u, p);

实际实现中需要临时存储，因为这些运算大多无法原地完成。例如，伪代码中的平流一步更准确的写法是：

uTemp = advect(u);
swap(u, uTemp);

这段伪代码不包含任何与实现相关的细节。事实上，同一段伪代码对 CPU 和 GPU 实现同样适用。我们的目标是把所有步骤都放到 GPU 上执行。在 GPU 上做这类计算对部分读者可能陌生，因此我们会在典型 CPU 流体仿真中的运算与 GPU 上的对应运算之间作一些类比。

38.3.1 CPU 与 GPU 的类比

内存模型与处理模型是任何计算机的基础，因此任何应用都必须考虑数据表示与计算。下面我们从这两方面谈谈 CPU 与 GPU 的差异。

纹理即数组

我们的仿真在二维网格上表示数据。在 CPU 上，这个网格的自然表示是数组。数组在 GPU 上的对应物是纹理。纹理虽然不如数组灵活，但随着图形硬件的发展，其灵活性在不断提高。当前 GPU 上的纹理支持实现流体仿真所需的全部基本操作。由于纹理通常有三或四个颜色通道，它们为二到四元的分量向量数据提供了自然的数据结构。另一种做法是把多个标量场存进单个纹理。最基本的操作是数组（或内存）读取，它通过纹理查找完成。因此，数组偏移在 GPU 上的对应物是纹理坐标。我们至少需要两个纹理来表示流体的状态：一个存速度，一个存压力。为了把流动可视化，我们另外维护一个纹理，存放流体携带的某个量。可以把它想成「墨水」。图 38-4 展示了这些纹理，以及 38.5.1 节描述的另一张用于涡量的纹理。

循环体即片元程序

CPU 实现通过循环执行算法中的各步，用一对嵌套循环遍历网格中的每个单元，在每个单元上执行相同的计算。GPU 无法对纹理中的每个纹素执行这种内层循环。不过，片元管线本来就是为在每个片元上执行相同计算而设计的。在程序员看来，就好像每个片元都有一个处理器，所有片元同时被更新。按并行编程的说法，这种模型称为单指令多数据（SIMD）计算。因此，对数组做嵌套循环内部的计算，在 GPU 上的对应物就是以 SIMD 方式作用于每个片元的片元程序。

反馈即纹理更新

在 38.2.4 节我们描述了如何用 Jacobi 迭代求解泊松方程。这类迭代方法以上一次迭代的结果作为下一次迭代的输入。这种反馈在数值方法中很常见。在 CPU 实现中，人们通常根本不考虑反馈，因为用可读可写的变量和数组实现它轻而易举。而在 GPU 上，片元处理器的输出总是写入帧缓冲。可以把帧缓冲想成无法直接读取的二维数组。要把帧缓冲的内容变成可读取的纹理，有两种方法：

  • 复制到纹理（CTT）从帧缓冲复制到纹理。
  • 渲染到纹理（RTT）把纹理用作帧缓冲，GPU 可以直接写入其中。

CTT 和 RTT 效果相同，但在性能上有取舍。为通用起见，我们不假定使用其中任何一种，而把写入纹理的过程统称为纹理更新。

前面提到，实际实现中算法的五个步骤各自更新一块临时网格，然后做一次交换。RTT 需要两个纹理来实现反馈，因为一边渲染到某纹理、一边又把它绑定为读取源，结果是未定义的。这种情况下所谓交换不过是交换纹理 ID，因此 RTT 的性能开销是常数。而 CTT 只需要一个纹理。帧缓冲充当临时网格，交换是把数据从帧缓冲复制到纹理。这项复制的性能开销与纹理尺寸成正比。

38.3.2 板层操作

我们把仿真的各个步骤拆成所谓的板层操作（简称 slabop）。[2] 每个 slabop 包含对帧缓冲中一个或多个（常常是全部）片元的处理——通常是在片元程序激活状态下——随后做一次纹理更新。片元处理由绘制几何图元驱动。对这个应用来说，我们绘制的几何很简单：只有四边形和线图元。

任何板层操作中都有两类片元要处理：内部片元和边界片元。我们的二维网格留出一圈单格宽的外围，用来存放和计算边界条件。通常内部与边界的计算不同。为更新内部片元，我们绘制一个四边形，覆盖帧缓冲除最外一圈一像素宽边框以外的全部区域。为更新边界单元，我们绘制四个线图元。内部片元和边界片元分别使用不同的片元程序。见图 38-5。

示例 38-1. 平流片元程序

void advect(float2 coords
            : WPOS,
              // 网格坐标
              out float4 xNew
            : COLOR,
              // 被平流的量
              uniform float timestep, uniform float rdx,
              // 1 / 网格尺度
              uniform samplerRECT u,
              // 输入速度
              uniform samplerRECT x)
// 待平流的量
{
  // 沿速度场 “回溯时间”
  float2 pos = coords - timestep * rdx * f2texRECT(u, coords);
  // 插值后写入输出片元
  xNew = f4texRECTbilerp(x, pos);
}

这段代码中，参数 u 是速度场纹理，x 是待平流的场。它可以是速度，也可以是其他量，例如染料浓度。函数 f4texRECTbilerp() 是一个工具函数，对传给它的纹理坐标最近的四个纹素做双线性插值。由于当前 GPU 不支持在浮点纹理上自动做双线性插值，我们只能用这类代码自行实现。

黏性扩散

有了 38.2.4 节给出的 Jacobi 迭代技术说明，写一个 Jacobi 迭代片元程序就很简单了，如代码清单 38-2 所示。

示例 38-2. 用于求解泊松方程的 Jacobi 迭代片元程序

void jacobi(half2 coords
            : WPOS,
              // 网格坐标
              out half4 xNew
            : COLOR,
              // 结果
              uniform half alpha, uniform half rBeta,
              // beta 的倒数
              uniform samplerRECT x,
              // x 向量（Ax = b）
              uniform samplerRECT b)
// b 向量（Ax = b）
{
  // 左、右、下、上的 x 采样
  half4 xL = h4texRECT(x, coords - half2(1, 0));
  half4 xR = h4texRECT(x, coords + half2(1, 0));
  half4 xB = h4texRECT(x, coords - half2(0, 1));
  half4 xT = h4texRECT(x, coords + half2(0, 1));
  // 从中心取到的 b 采样
  half4 bC = h4texRECT(b, coords);
  // 执行 Jacobi 迭代
  xNew = (xL + xR + xB + xT + alpha * bC) * rBeta;
}

注意 rBeta 参数是公式 16 中 的倒数。要求解扩散方程，我们把 alpha 设为 (x)2/t，rBeta 设为 1/(4 + (x)2/t)，并把 x 与 b 参数都设为速度纹理。然后跑若干次迭代（通常 20 到 50 次，也可以用更多来减小误差）。

投影

本节开头我们了解到，投影这一步分为两个操作：求解关于 p 的泊松-压力方程，以及从中转速度场中减去 p 的梯度。这需要三个片元程序：前面提到的 Jacobi 迭代程序、计算中转速度场散度的程序，以及从中转速度场中减去 p 梯度的程序。

代码清单 38-3 所示的散度程序把中转速度场作为参数 w，把网格尺度倒数的一半作为参数 halfrdx，并按第 643 页表 38-1 给出的有限差分公式计算散度。

散度写入一块临时纹理，再作为 Jacobi 迭代程序的 b 参数输入。Jacobi 程序的 x 参数设为压力纹理，该纹理先被清为全零（也就是说，我们用零作为压力场的初始猜测）。alpha 与 rBeta 参数分别设为 -(x)2 和 ¼。

为了获得良好的收敛效果，我们通常做 40 到 80 次 Jacobi 迭代。改变 Jacobi 迭代次数会影响仿真的精度。不宜少于 20 次，因为误差会很明显。更多迭代能得到更细致的涡旋和更高的整体精度，但需要更多计算时间。Jacobi 迭代结束后，我们把压力场纹理绑定到下面程序的参数 p，该程序按表 38-1 的定义计算 p 的梯度，并从参数 w 里的中转速度场纹理中减去它。见代码清单 38-4。

示例 38-3. 散度片元程序

void divergence(half2 coords
                : WPOS,
                  // 网格坐标
                  out half4 div
                : COLOR,
                  // 散度
                  uniform half halfrdx,
                  // 0.5 / gridscale
                  uniform samplerRECT w)
// 向量场
{
  half4 wL = h4texRECT(w, coords - half2(1, 0));
  half4 wR = h4texRECT(w, coords + half2(1, 0));
  half4 wB = h4texRECT(w, coords - half2(0, 1));
  half4 wT = h4texRECT(w, coords + half2(0, 1));
  div = halfrdx * ((wR.x - wL.x) + (wT.y - wB.y));
}

示例 38-4. 梯度相减片元程序

void gradient(half2 coords
              : WPOS,
                // 网格坐标
                out half4 uNew
              : COLOR,
                // 新速度
                uniform half halfrdx,
                // 0.5 / gridscale
                uniform samplerRECT p,
                // 压力
                uniform samplerRECT w)
// 速度
{
  half pL = h1texRECT(p, coords - half2(1, 0));
  half pR = h1texRECT(p, coords + half2(1, 0));
  half pB = h1texRECT(p, coords - half2(0, 1));
  half pT = h1texRECT(p, coords + half2(0, 1));
  uNew = h4texRECT(w, coords);
  uNew.xy -= halfrdx * half2(pR - pL, pT - pB);
}

在 38.2.4 节我们确定，我们的「盒中流体」需要无滑移（零）速度边界条件和纯 Neumann 压力边界条件。在 38.3.2 节我们了解到，可以通过在网格四周留出一像素宽的外围来存放边界值，从而实现边界条件。我们用适当设置数值的片元程序在边界上绘制线图元，以此更新这些值。

38.5.2 三维

本章介绍的所有仿真都是二维的。没有什么能阻止我们把它们扩展到三维。方程基本不变，但必须扩展以纳入三维速度 u = (u, v, w)。片元程序必须相应重写；二维时对四个邻居的采样，在三维时变成对六个邻居的采样。

最大的变化在于向量场与标量场的表示方式。一种选择是用三维纹理。在不支持三维浮点纹理的硬件上这就有问题。这种情况下，我们可以把三维纹理的各板层平铺到存于二维纹理中的网格里（例如 32x32x32 的网格可平铺到 256x128 的二维纹理上，一个方向八块、另一个方向四块）。这种技术称为扁平三维纹理，Harris et al. 2003 有详细论述。

38.5.3 交错网格

我们的仿真把速度、压力和其他量都表示在单元中心。这只是在表示流体的连续区域上做离散化的一种方式。这种方式称为同位或单元中心离散化。另一种方式是使用交错网格。在交错网格中，标量（如压力）表示在单元中心，向量（如速度）表示在单元之间的边界上。具体来说，在二维网格上，我们把水平速度 u 表示在每个单元的右边缘，把竖直速度 v 表示在每个单元的上边缘。交错网格离散化能提高许多计算的精度。它还能减少在单元中心网格上施加浮力等力时可能出现的数值振荡。在交错网格上实现流体仿真的细节见 Griebel et al. 1998。

38.5.4 任意边界

到目前为止我们假设流体处于四面平直、坚固的矩形盒子中。如果任意形状和位置的边界很重要，就需要扩展仿真。

纳入任意边界要求在任意位置施加边界条件（38.3.3 节讨论过）。这意味着在每个单元上都必须判断边界位于哪个方向，才能算出正确的边界值。这种仿真在每个单元上要做更多判断，因此更慢、更复杂。不过，这样可以做出许多有趣的效果，例如烟绕障碍物流过。甚至可以把运动边界纳入进来，如 Fedkiw et al. 2001 所做。实现细节请参阅该论文以及 Griebel et al. 1998。

38.5.5 自由表面流

我们做的另一个假设是流体连续——我们只表示盒子的固体边界。因此我们无法模拟海面这类水与空气之间存在界面的情形。这类界面称为自由表面。把仿真扩展到包含自由表面，需要跟踪表面在各单元间移动时的位置。实现自由表面流的方法见 Griebel et al. 1998。

38.6 结论

GPU 现在提供的算力与可编程能力，使得快速仿真各种各样的现象成为可能。这些现象中许多的底层都是流体运动的动力学。

读完本章，你应当对在 GPU 上实现基本流体仿真所需的数学与技术有了根本的理解。从这些初步想法出发，你可以试验自己的仿真构想，把流体仿真引入图形应用。我们希望这些技术成为你工具箱中强大的新工具。
