第 21 章　实时辉光

Greg James
NVIDIA

John O'Rorke
Monolith Productions

辉光与光晕在世界上随处可见，它们为亮度和氛围提供了有力的视觉线索。在观看计算机图形、电影和印刷品时，到达眼睛的光强是有限的，因此要分辨强光源，唯一的方式就是靠其周围的辉光与光晕（Nakamae et al. 1990）。这些辉光重现了强光的视觉效果，让观察者误以为光源非常明亮。哪怕物体周围只有淡淡的辉光，也会让人觉得它比没有辉光的物体更亮。在日常生活中，这些辉光与光晕由光在大气中或在我们眼内的散射造成（Spencer 1995）。借助现代图形硬件，只需几次简单的渲染操作就能重现这些效果。这让我们能用明亮、有趣的物体填满实时渲染的场景，使它们看起来更真实或更奇幻；这也是克服实时图形长期以来动态范围低、画面平淡这一观感的一种优雅手段。

现在已有若干游戏用各种技术生成辉光与光晕，其中包括 Splinter Cell、Project Gotham Racing、Wreckless（Kawase 2003）和 Halo 2。另一个值得注意且广泛应用的辉光例子见于 Pixar 的影片 Finding Nemo，其中的辉光表现了海水的浑浊，并帮助为多个场景定下情绪基调。本章聚焦于为近期发行的 Tron 2.0 开发的一种特定技术，该游戏由 Buena Vista Interactive 出品、Monolith Productions 开发。这项技术旨在生成覆盖整个屏幕的大面积辉光，便于为大量游戏资源制作与控制，并且快到足以支撑一款帧率超过 60 帧每秒的第一人称射击游戏。结果见图 21-1 与 21-2。在这里，这个效果传达了 Tron 2.0 计算机世界的活力与电子能量，不过该技术也可用于制作其他效果，包括景深、光散射、边缘检测和图像处理。

21.1 技术概览

在场景中生成辉光有几种做法。对小的点状物体，可以把一张平滑的「发光」纹理贴到跟随物体在屏幕上移动的公告板几何上。在 Tron 2.0 中，这种做法用于 Bit 角色。对大面积的光源或复杂的发光形状，最好对场景的二维渲染做后处理来生成辉光。本章聚焦后处理做法，其步骤概述于图 21-3。

首先，必须用某种方式标出场景或模型中发光的部分，使它们能被单独分离出来，与不发光的部分分开处理。场景按常规渲染，就像没有辉光一样，但同时也用辉光源信息再渲染一遍，生成一张纹理贴图，除辉光源可见之处外处处为黑。图 21-3b 给出了这样一张渲染出的纹理贴图的例子。这张渲染出的纹理贴图可以在后续渲染中当作普通纹理使用。它被贴到简单几何上，使其在每个像素处被多次采样，做两步图像卷积，从而把辉光源点扩散成柔和、大面积的辉光图案。最后，用加法 alpha 混合把这层柔和辉光叠加到常规渲染之上。这样，借助硬件渲染与纹理映射，辉光源就被扩散成令人信服的光晕。

这些步骤中的每一步都能在广泛的图形硬件上高效、快速地完成。该技术最适合支持 Microsoft Direct3D 8 顶点着色器与像素着色器 1.1 或更高版本的硬件，但对只支持固定功能 Direct3D 7 渲染的硬件也有方便的退路。对于 Direct3D 7 时代的较老硬件——其填充率和纹理性能较低——可以降低渲染目标纹理的分辨率来提升性能，而在图像质量上损失不大。由于模糊后的辉光纹理通常只含低频特征，降低其分辨率几乎不会损失质量。事实上，正如后文所述，降低纹理渲染目标的分辨率是在不增加性能开销的前提下生成更大辉光的好办法。

21.2 逐步渲染辉光

21.2.1 指定并渲染辉光源

渲染辉光的第一步是指定哪些物体或物体上的哪些部分是辉光源。这些辉光源的颜色与亮度会直接转化为最终辉光的颜色与亮度，因此我们可以通过调整辉光源的亮度轻松控制辉光的外观。这些光源可以是按某种物体属性或标志指定的整块几何，也可以用纹理数据限定在物体的一小部分上。在后一种情况下，纹理数据会把物体上不发光的部分遮掉，使其在辉光源渲染中变黑。余下的辉光源区域可以具有任意所需的颜色与亮度。使用纹理数据既方便又对美术友好，是我们首选的做法。

辉光源遮罩可以放在单独的纹理里，但用普通漫反射颜色纹理的 alpha 通道来存遮罩值更方便。这种情况下，纹理的 RGB 颜色用于正常渲染物体而不做 alpha 混合。渲染辉光源时，RGB 颜色乘以纹理的 alpha 通道。alpha 值为零处没有辉光源；随着 alpha 升到满值，辉光源的强度增加。图 21-4 展示了为一个 UFO 指定辉光源所用的纹理 RGB 与 alpha 通道。此外，还可以把逐顶点或逐物体的值乘进辉光源（RGB×alpha）值，让辉光随时间变化。

辉光源指定好之后，需要把它们写入一张离屏渲染目标纹理，我们再处理这张纹理以生成柔和辉光。这是一张用 Direct3D 9 的 D3DUSAGE_RENDERTARGET 标志创建的纹理。把辉光源送进纹理渲染目标有两种做法：（1）把整个场景渲染到该纹理，用一种方法把辉光源渲染成彩色、把所有不发光物体渲染成黑色；或（2）用 IDirect3DDevice9::StretchRect(..) 函数把场景从普通后台缓冲拷贝到该纹理。对复杂场景，再次渲染整个三维场景到纹理可能代价很高，而且还需要一个专属于该纹理渲染目标的额外深度缓冲，因此更推荐 StretchRect(..) 的二维图像拷贝方式。StretchRect(..) 还允许我们在拷贝到纹理的过程中对后台缓冲图像做缩放和滤波。这可以用来降低分辨率，从而在处理纹理生成辉光时获得性能收益。

采用 StretchRect(..) 做法时，可以先把充当辉光源遮罩的 alpha 值渲染到普通后台缓冲的目标 alpha 值中。这不会影响普通场景，但在 StretchRect(..) 操作中它会被拷贝到纹理的 alpha 通道。随后可以把该 alpha 通道与 RGB 颜色相乘，遮掉场景物体，只留下辉光源。

完成这一步后，对辉光源纹理做模糊，以形成柔和的辉光观感。模糊操作会平滑源纹理中的高频或点状特征，结果只保留宽阔的低频特征。正因如此，辉光和辉光源可以用低分辨率渲染，而不会降低质量。辉光可以在每个轴上以全屏分辨率的三分之一或四分之一生成，这会大幅提升渲染该效果的速度。

以低分辨率渲染辉光源确实会影响最终辉光的走样。辉光源纹理的分辨率越低，其走样越严重，源纹素在场景中物体移动时也越容易闪烁。全分辨率图像中的一个像素可能对应辉光源的一个纹素，而这一个辉光源纹素会被扩散成一大片辉光图案。这加剧了走样的影响，使辉光在物体移动时闪烁、晃动。分辨率能降到多低，取决于最终图像中能接受多少闪烁。降低分辨率时提高所用滤波的质量，可以减轻这种闪烁。例如，在对高分辨率辉光源图像降采样时使用硬件加速的双线性纹理滤波，就能显著减弱闪烁。

21.2.2 模糊辉光源

模糊辉光源会把它们扩散成平滑、自然的辉光图案。模糊借助二维图像处理滤波器在硬件中完成。生成辉光效果的速度很大程度上取决于模糊执行得有多高效。模糊所需时间取决于所用滤波器以纹素计的尺寸。当模糊滤波器增大以覆盖更多纹素时，我们要读写的纹素数量与二维模糊的面积成正比。面积与模糊直径的平方成正比，即 d 2。把辉光直径加倍需要处理四倍的纹素。对于覆盖 50x50 纹素的模糊形状，我们每生成一个辉光像素就要读 2,500 个纹素！这会让大面积辉光非常不实用，不过幸运的是，通过一种称为可分离卷积的两步操作，可以避开这个讨厌的直径平方代价。可分离卷积把代价从 d 2 降到 2d，因此生成 50x50 的辉光在每个像素处只需 100 次纹素读取。这个计算在现代图形硬件上可以很快完成。

21.2.3 变通使用可分离卷积

可分离卷积这一技术是为在某些特殊情况下节省计算而设计的，即卷积核可以分解为各轴独立的各项之积时。这种情况下，nxm 个元素的二维卷积可以缩减为分别含 n 与 m 个元素的两次独立一维卷积。这大幅降低了卷积的计算代价。卷积不再是每点计算并累加 nxm 个采样，而变成只需 n + m 个采样的两步过程。首先，沿一个轴采样并累加 n 个元素，为结果中的每个点生成一张中间结果图像。然后沿另一个轴对中间结果取 m 个元素的邻域，生成最终结果中的每个点。n 或 m 个采样各自的权重系数就是卷积沿各轴的剖面。就我们关心而言，关键概念是：这个两步做法可以用于任意一组一维卷积剖面。即使某个二维模糊形状在数学上不可分离，我们也可以用两个一维剖面来近似该形状。只做两次一维模糊的工作量，就能造出各种各样的二维模糊形状。

关于可分离卷积的深入资料可以在 OpenGL.org 上找到。就我们的目的而言，数学推导似乎会限制模糊的形状。这是因为推导通常只基于一两个可分离函数，例如二维高斯。我们不必站在推导的角度把二维剖面拆成两个一维剖面，而可以直接指定任意一对一维剖面。每个剖面的形状无关紧要，只要它们产生某种有趣的二维模糊结果。本文所示图像用的是两条高斯曲线相加：一条提供平滑宽阔的基底，另一条在中心产生明亮的尖峰。我们的 Direct3D「Glow」演示（NVIDIA 2002）使用了其他各种剖面，其中包括一种周期性锯齿剖面，能产生有趣的、类似衍射的多重影像效果。该演示及完整源代码收录在本书附带的 CD 和网站上。

21.2.4 GPU 上的卷积

要在一个轴上模糊、再把这次模糊的结果在另一个轴上模糊，我们使用 GPU 上的渲染到纹理操作。渲染时为每个被渲染像素取周围一小片纹素邻域，并对邻域采样施加卷积核权重。如果 GPU 能在一遍中读完所有邻居，卷积可以在单遍渲染中完成；否则可以用加法混合在若干遍渲染中逐次累加几个邻居采样，逐步构建结果。

渲染由一块简单的屏幕对齐几何驱动。这块几何通常是一个覆盖整个渲染目标的矩形，由两个三角形构成。每个三角形顶点的纹理坐标决定了从源纹理采样纹素的位置。这些坐标也可以在顶点着色器或像素着色器中计算。如果坐标在整个渲染目标上设为 0.0 到 1.0，那么渲染就把源纹理拷贝到目标。每个被渲染的像素从源纹理中自己所在的位置读一个纹素，结果是一份精确的拷贝。反之，各纹理采样器的纹理坐标可以彼此偏移一个或多个纹素。这样每个被渲染像素就会从源纹理中采样一小片邻域。每个被渲染像素周围采样的邻居图案相同。该方法示于图 21-6，它提供了在 GPU 上做卷积的便捷途径。关于 GPU 上邻域采样与图像处理技术的更多资料，见 James 2001，以及网站上 developer.nvidia.com 和 gpgpu.org 上的内容。

要在图形处理器上执行模糊卷积，把辉光源纹理绑定到一个或多个纹理采样器单元，并计算纹理坐标以给出所需的邻居采样图案。把渲染目标设为一张将保存沿第一轴模糊结果的渲染目标纹理。称这张纹理为水平模糊纹理。渲染每个像素时，若干次纹理采样（邻居采样）被送到像素片元处理硬件，在那里乘以第一个一维卷积核的权重系数。用一遍或多遍渲染到纹理完成水平模糊后，把渲染目标切换到另一张将保存最终模糊结果的纹理渲染目标。把水平模糊纹理绑定到输入纹理采样器，并施加第二个一维卷积核（垂直模糊）的纹理坐标与像素着色器权重。

最后一次模糊操作之后，辉光就可以混合进场景了。把渲染目标切回普通后台缓冲，用一个简单矩形以加法 alpha 混合渲染，把辉光纹理加到场景上。

21.3 针对具体硬件的实现

21.3.1 Direct3D 9

在支持 Direct3D 9 ps.2.0 的硬件上，所有邻居采样都可以在一个复杂的像素着色器遍中读取并卷积。邻居采样的纹理坐标偏移可以在顶点着色器程序中计算，但 vs.2.0 与 ps.2.0 模型只支持八个迭代纹理坐标。额外的纹理坐标可以在像素着色器里计算，但这与多遍做法相比未必更快——多遍做法在每一遍中只使用八个由硬件迭代的坐标。示例 vs.2.0 与 ps.2.0 着色器见代码清单 21-1 与 21-2。顶点着色器设计为接受简单的全屏覆盖几何，其顶点坐标位于齐次裁剪空间（屏幕空间），坐标范围为 (x, y) = ([-1, 1], [-1, 1]) 以覆盖整个屏幕。这些着色器同时用于水平与垂直模糊步骤，两步之间只有输入的常量值变化。常量指定邻居采样的位置和卷积核权重。

示例 21-1. 为采样八个邻居设置纹理坐标的 Direct3D 顶点着色器

vs .2.0 dcl_position v0 dcl_normal v1 dcl_color v2 dcl_texcoord v3 mov oPos,
    v0 // 输出顶点位置到屏幕空间
        // 通过把单个输入纹理坐标按若干常量偏移，
        // 构造出邻域采样的纹理坐标。add
        // oT0,
        v3,
    c0 add oT1, v3, c1 add oT2, v3, c2 add oT3, v3, c3 add oT4, v3, c4 add oT5,
    v3, c5 add oT6, v3, c6 add oT7, v3, c7

示例 21-2. 累加八次加权纹理采样的 Direct3D 像素着色器


ps .2.0
    // 取 8 个相邻采样，对它们施加 8 个卷积核权重 dcl t0.xyzw
    // 声明纹理坐标 dcl t1.xyzw dcl t2.xyzw dcl t3.xyzw dcl t4.xyzw
    // dcl t5.xyzw dcl t6.xyzw dcl t7.xyzw dcl_2d s0 声明纹理采样器
    // 常量 c0..c7 是对应各个相邻采样的卷积核权重
    // 再求和输出。texld r0, t0, s0 texld r1, t1, s0 mul
    r0,
    r0, c0 mad r0, r1, c1, r0 texld r1, t2, s0 texld r2, t3, s0 mad r0, r1, c2,
    r0 mad r0, r2, c3, r0 texld r1, t4, s0 texld r2, t5, s0 mad r0, r1, c4,
    r0 mad r0, r2, c5, r0 texld r1, t6, s0 texld r2, t7, s0 mad r0, r1, c6,
    r0 mad r0, r2, c7, r0 mov oC0, r0

注意，为了在精确的纹素中心采样纹理，必须在纹理坐标上加上半个纹素大小的偏移。这在 Direct3D 中必须做，在 OpenGL 中则不需要，因为 Direct3D 的约定是坐标从纹素角点起算，而 OpenGL 的约定是从纹素中心起算。实践中这是个简单的调整。对代码清单 21-1 的顶点着色器，就是给常量 c0 到 c7 每一个都加上半纹素偏移。这应当在 CPU 上完成。

21.3.2 Direct3D 8

对最多只支持 Direct3D 8 顶点与像素着色器的硬件，我们每一遍只能取四个邻居采样。虽然这一限制意味着要构建任意给定尺寸的卷积需要更多渲染遍，但每一遍都可以执行得很快：对含几十万纹素的渲染目标纹理（尺寸从 256x256 到 512x512），通常能达到每秒几百遍的速率。示例 vs.1.1 与 ps.1.3 着色器见代码清单 21-3 与 21-4。

示例 21-3. 建立邻居采样的 Direct3D 顶点着色器程序

vs .1.1 dcl_position v0 dcl_texcoord v3 mov oPos,
    v0 // 输出顶点位置到屏幕空间
        // 通过把单个输入纹理坐标按若干常量偏移，
        // 构造出邻域采样的纹理坐标。add
        // oT0,
        v3,
    c0 add oT1, v3, c1 add oT2, v3, c2 add oT3, v3, c3

示例 21-4. 累加四次加权纹理采样的 Direct3D 像素着色器程序

ps .1.3 tex t0
    // 采样 4 个相邻纹素 tex t1 tex t2 tex t3，
    // 再逐个乘以卷积核权重并输出它们的和
    mul r0,
    t0, c0 mad r0, t1, c1, r0 mad r0, t2, c2, r0 mad r0, t3, c3, r0

21.3.3 Direct3D 7

Direct3D 7 级别的硬件缺少现代图形硬件便利的顶点与像素着色能力。它通常每遍也只能做两次纹理采样，填充率也低得多。不过模糊卷积仍可用若干重叠的全屏覆盖三角形来完成。每一对三角形组成一个全屏四边形，顶点位置相同但顶点纹理坐标不同。对双纹理多重采样硬件，每个四边形携带两个纹理坐标，每个坐标被设为采样不同的邻居。每个四边形的顶点颜色属性被设为对应邻居采样位置的卷积核权重，再通过固定功能的 SetTextureStageState(..) API 调用把这个顶点颜色乘以纹理采样值。这样一堆四边形可以在一次 DrawPrimitive(..) 调用中以加法混合渲染，逐步构建出卷积结果。

21.4 模糊的其他用途

除了目前讨论的用途——模拟对高动态范围强度值的感知——这种卷积与模糊方法还可用于多种其他效果。它可以用来为景深效果计算不同程度的对焦，其中可以用场景深度信息控制模糊程度。它可以用来柔化投影纹理阴影的边缘，或为深度阴影贴图的百分比邻近滤波（percentage-closer filtering）累积结果。大面积卷积可以施加到环境贴图上，生成近似辐照度贴图，以获得更真实的场景光照（Ramamoorthi and Hanrahan 2001）。许多非真实感渲染技术和其他特效都可以用大面积卷积实现，其中包括磨砂玻璃效果、模拟衍射的镜头光晕，以及为渲染皮肤而做的次表面散射近似。

21.5 把效果加入游戏引擎

接下来我们聚焦这些视觉效果如何用于 Buena Vista Interactive 的游戏 Tron 2.0，在其中它们对游戏独特的视觉风格起了重要作用。实现这些效果出乎意料地直接。不过在效果足够稳健、能用于游戏中各种各样的情况之前，有些重要问题必须解决。此外，开发过程中还发现了一些有趣的效果和辉光的另类用法。

21.5.1 渲染上下文

我们解决的第一个问题是如何渲染那张将被模糊以生成最终屏幕辉光的源图像。在 Tron 2.0 中有两条渲染管线：一条渲染世界几何，一条渲染模型。两条管线都需要扩展以支持渲染上下文的概念，它允许场景按不同目的以不同方式渲染。Tron 2.0 需要两种渲染上下文。一种是常规渲染，用于处理场景的初始渲染，不带任何屏幕辉光。第二种渲染上下文是辉光渲染，用于渲染辉光的源图像。

渲染上下文的实现在各应用之间差异很大，但为了说明，我们描述一下 Tron 2.0 中模型渲染管线是怎么做的。模型渲染基于一个网格和一组指示模型应如何渲染的渲染状态。这些渲染状态作为一种称为渲染样式的外部资源存储。为支持上下文的概念，该系统做了扩展，允许美术设置一张表，在渲染辉光时把任意渲染样式映射到相应的渲染样式。通过这一机制，常规渲染场景时使用原来的渲染样式，也就是按关闭辉光时所见的样子渲染模型。而在渲染辉光的源图像时，改用美术设置好的映射表中找到的渲染样式，从而渲染模型发光的部分。美术觉得这套系统非常灵活、易于使用，因为它让他们能控制哪些物体该发光、每个物体该如何发光。图 21-7 展示了未加特效的角色模型、美术制作的辉光纹理信息，以及施加到模型上的辉光效果。

21.5.2 走样问题

当我们把辉光效果从简单的测试用例扩展到完整的游戏场景时，走样问题立刻出现了。Tron 世界的特征是场景中一条条颜色鲜艳的几何，几乎像角色及其周围环境上的霓虹镶边。此外，多数环境都很广阔，因此这些发光几何条从离摄像机很近一直延伸到很远。为 Tron 2.0 我们用了 256x256 的辉光纹理，以便用最少的遍数实现相当大的模糊。但这种做法的缺点是，在渲染源图像时会造成严重的走样问题，而且随着玩家移动或环视，走样变得非常明显。

为解决这个问题，我们加入了对美术控制雾的支持，仅在渲染屏幕辉光的源图像时使用。雾会在大关卡中启用并设为黑色。由于屏幕辉光是加法混合，源图像中的黑雾会使远处物体对最终屏幕辉光只有微弱贡献，甚至没有贡献。于是远处的走样就变得不那么明显了。

这不是完美的解决方案——例如远处场景的部分区域不会发光——但视觉上通常比走样瑕疵更容易接受。除了避开走样，雾还在整个游戏的若干地方以意想不到的方式使用，用来营造额外的氛围，如图 21-8 所示。

21.5.3 DirectX 7 的精度问题

为了把混合权重放进一个颜色分量，最初的 DirectX 7 实现把它从 [0, 1] 的初始范围缩放到 0 到 255 之间的整数。但这些权重大多非常小，因而并未很好地分布在整个范围上。结果，转换成整数时产生的误差导致 DirectX 7 与 8 的实现之间出现明显的视觉差异。即使做了舍入，辉光看起来仍显著不同。

怎么解决？做舍入，但先确定舍入后的值与实际值差多少，再把这个差值加到下一个计算的权重上。例如权重 0.13 乘以 255 得 33.15，舍入后为整数 33。因此用于颜色的权重是 33，而剩下的部分（0.15）会加到下一个要渲染的权重上。结果，DirectX 7 与 8 的实现在视觉上几乎完全一致。

21.5.4 残影效果

有一个效果没能进入 Tron 2.0，因为发现得太晚。事实证明，可以把上一帧的源纹理加到当前帧的源纹理上，从而在玩家移动或环视时产生非常漂亮的辉光拖尾。这项技术实现起来非常简单。它需要一张额外的纹理表面，以便把源图像保留到下一帧，还需要一次加法混合，把上一帧的源图像加到当前帧的源图像上。做法是在施加模糊之前立即保存图像，然后再模糊。保存的图像被加到下一帧的源图像上，但会被略微调暗。随着这个过程在若干帧上重复，物体就会从辉光中淡出，而不是瞬间消失，这不仅让效果更有说服力，也有助于掩盖源图像的走样。

在把上一帧加到当前帧的辉光源之前，对其施加的调暗程度可以动态改变，从而得到范围很广的外观。例如，把上一帧调得很暗，残影就会很少，在用户看来只是视网膜上短暂的光灼痕，给人一种光更亮得多的印象。把上一帧调得暗一些再加进去，模糊和拖尾就会明显得多，给玩家的感觉像是醉了或濒死。

还有一种替代做法不需要额外缓冲。我们可以用模糊之后上一帧的最终屏幕辉光纹理，这样省内存，因为不必保留源图像。然而这个方案确实有某些问题。如果上一帧的辉光纹理太亮，递归相加时它会失控地溢出，每帧不断向外模糊，最终导致整屏辉光全白。为避免这种情况，设置混合权重和确定上一帧调暗多少时必须小心。

21.5.5 可变渐变效果

屏幕辉光必须用某一组参数——比如混合权重和雾——来生成单帧的最终模糊。但这并不意味着参数不能逐帧改变。事实上，改变其中任何参数都能得到各种有趣的效果。例如，在 Tron 2.0 的一个关卡里，玩家身处一台发出病态绿光的被感染的服务器内部。为传达不稳定的感觉，模糊的混合权重被从低到高渐变，形成屏幕辉光的沉闷脉动。见图 21-9。

虽然游戏中没有用到，其他效果也可以同样轻易地实现。例如，让屏幕辉光的雾淡入淡出，或改变雾的颜色，就能轻松高效地让一个关卡的氛围像是不断在变。

21.6 结论

大面积模糊与卷积可以在广泛的图形硬件上实时高效地计算。处理并生成这些效果的代码很容易封装成几个 C++ 类或一个小型库。这些类和示例代码可以在 NVIDIA 的开发者网站 developer.nvidia.com 上获取。该效果需要额外数据来指定辉光源的亮度，这些数据可以并入现有的纹理资源，即纹理的 alpha 通道。该效果为辉光的亮度和形状提供了直观的控制。能把大面积卷积施加到全屏渲染上，对多种效果都有用。它是表现场景中明亮物体的关键，能大幅提升实时渲染的外观与质量。

屏幕辉光属于少见的既足够稳健、能轻易扩展到几乎任何情况，又足够灵活、能借它派生众多附加效果的效果之一。最终效果细微但有力，值得在任何游戏中做原型验证。
