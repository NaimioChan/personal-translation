typedef unsigned long PaSampleFormat

用于指定一种或多种采样格式的类型。每个值表示传给流回调、Pa_ReadStream() 和 Pa_WriteStream() 或由它们返回的音频数据可能采用的一种格式。

PaStreamCallback

typedef int PaStreamCallback(const void *input, void *output, unsigned long frameCount, const PaStreamCallbackTimeInfo *timeInfo, PaStreamCallbackFlags statusFlags, void *userData)

PaStreamCallback 类型的函数由 PortAudio 客户端实现。它们响应活动 PortAudio 流的请求来消费、处理或生成音频。

流运行时，PortAudio 会周期性地调用流回调。回调函数负责处理经由 input 和 output 参数传入的音频采样缓冲区。

PortAudio 流回调以极高优先级或实时优先级运行。它必须始终满足其时限要求。请勿在流回调中分配内存、访问文件系统、调用库函数，也不要调用可能阻塞或耗时不可预测的其他函数。

为使流保持无故障运行，回调消费和返回音频数据的速度必须快于录制和/或播放的速度。PortAudio 预计每次回调调用的执行时长可能接近流采样率下 frameCount 个音频帧的时长。可以合理预期在 PortAudio 回调中使用 70% 或更多的可用 CPU 时间。不过，由于缓冲区大小自适应等因素，在任意固定的回调缓冲区大小下，并非所有宿主 API 都能在 CPU 负载较重时保证音频稳定。需要较高的回调 CPU 占用率时，把 paFramesPerBufferUnspecified 用作 Pa_OpenStream() 的 framesPerBuffer 参数可获得最稳健的行为。

参数
参数说明
input和
output要么是交错采样的数组；要么（如果使用 paNonInterleaved 采样格式标志请求了非交错采样）是缓冲区指针的数组，每个声道一个非交错缓冲区。

缓冲区所用的格式、打包方式和声道数由传给 Pa_OpenStream() 的参数决定。

参数
参数说明

返回值
流回调应返回 PaStreamCallbackResult 枚举中的某个值。为确保回调继续被调用，它应返回 paContinue (0)。可以返回 paComplete 或 paAbort 来结束流处理，返回其中任一值后，回调不会再被调用。如果返回 paAbort，流将尽快结束。如果返回 paComplete，流会继续运行，直到回调生成的所有缓冲区都播放完毕。这在诸如声音文件播放器这类需要特定输出时长的应用中可能有用。不过，并不一定要利用此机制，因为也可以用 Pa_StopStream()、Pa_AbortStream() 或 Pa_CloseStream() 停止流。无论返回值为何，回调都必须填满整个输出缓冲区。

PaStreamFinishedCallback

typedef void PaStreamFinishedCallback(void *userData)

PaStreamFinishedCallback 类型的函数由 PortAudio 客户端实现。它们可以用 Pa_SetStreamFinishedCallback() 函数注册到某个流。注册之后，它们会在流变为非活动状态时被调用（即此时调用 Pa_StopStream() 不会阻塞）。流会在流回调返回非零值之后，或在调用 Pa_StopStream() 或 Pa_AbortStream() 时变为非活动状态。对于提供音频输出的流，如果流回调返回 paComplete，或调用了 Pa_StopStream()，则流结束回调要等到生成的所有采样数据都播放完毕后才被调用。

用此回调通知你的应用流已结束。例如向 UI 事件循环投递一条通知。

Pa_OpenStream()

PaError Pa_OpenStream ( PaStream ** stream, const PaStreamParameters * inputParameters, const PaStreamParameters * outputParameters, double sampleRate, unsigned long framesPerBuffer, PaStreamFlags streamFlags, PaStreamCallback * streamCallback, void * userData )

打开用于输入、输出或两者的流。

参数
参数说明
stream一个 PaStream 指针的地址，它将接收指向新打开流的指针。
inputParameters描述已打开流所用输入参数的结构体。这些参数的说明见 PaStreamParameters。对于仅输出流，inputParameters 必须为 NULL。
outputParameters描述已打开流所用输出参数的结构体。这些参数的说明见 PaStreamParameters。对于仅输入流，outputParameters 必须为 NULL。
sampleRate期望的 sampleRate。对于全双工流，它是输入和输出共用的采样率。注意，由于硬件限制，实际的 sampleRate 可能与期望值有极小的差异。确切速率可用 Pa_GetStreamInfo() 查询。如果没有接近期望 sampleRate 的值可用，则打开操作会失败并返回错误。
framesPerBuffer传给流回调函数的帧数，或阻塞式读/写流的首选块粒度。特殊值 paFramesPerBufferUnspecified (0) 可用于请求流回调根据宿主需求和所要求的延迟设置接收最优的（且可能变化的）帧数。注意：对于某些宿主 API，回调流使用非零的 framesPerBuffer 可能引入额外的缓冲层，从而带来额外延迟。PortAudio 保证额外延迟保持在理论最小值，但仍强烈建议仅在你的算法要求每次流回调有固定帧数时才使用非零的 framesPerBuffer 值。
streamFlags修改流处理行为的标志。此参数可以包含按位或组合的多个标志。某些标志可能只与特定的缓冲区格式相关。
streamCallback指向客户端提供的函数的指针，该函数负责处理和填充输入与输出缓冲区。如果此参数为 NULL，流将以「阻塞式读/写」模式打开。在阻塞模式下，客户端可以用 Pa_ReadStream() 接收采样数据，用 Pa_WriteStream() 写入采样数据；无需阻塞即可读取或写入的采样数分别由 Pa_GetStreamReadAvailable() 和 Pa_GetStreamWriteAvailable() 返回。
userData客户端提供的指针，会传给流回调函数。例如，它可以包含处理音频缓冲区所需的实例数据指针。如果 streamCallback 为 NULL，则忽略此参数。
返回值
成功时 Pa_OpenStream() 返回 paNoError，并在 stream 参数中放入指向有效 PaStream 的指针。该流处于非活动（停止）状态。如果调用 Pa_OpenStream() 失败，则返回非零错误码（可能的错误码见 PaError），且 stream 的值无效。
另见
PaStreamParameters, PaStreamCallback, Pa_ReadStream, Pa_WriteStream, Pa_GetStreamReadAvailable, Pa_GetStreamWriteAvailable

Pa_ReadStream()

PaError Pa_ReadStream ( PaStream * stream, void * buffer, unsigned long frames )

从输入流读取采样。函数直到整个缓冲区被填满才返回，这可能涉及等待操作系统提供数据。

目前不支持从已停止的流读取。特别是，调用 Pa_StopStream() 之后无法通过调用 Pa_ReadStream 排空读取缓冲区。

参数
参数说明
stream指向此前用 Pa_OpenStream() 创建的已打开流的指针。
buffer指向采样帧缓冲区的指针。缓冲区中的采样采用打开流时所用的 inputParameters->sampleFormat 字段指定的格式，声道数由 inputParameters->numChannels 指定。如果使用 paNonInterleaved 采样格式标志请求了非交错采样，则 buffer 是指向缓冲区指针数组第一个元素的指针，每个声道一个非交错缓冲区。
frames要读入 buffer 的帧数。此参数不受特定范围限制，但高性能应用会希望让此参数与打开流时使用的 framesPerBuffer 参数一致。
返回值
成功时返回 PaNoError；如果输入数据在上一次调用之后、本次调用之前被 PortAudio 丢弃，则返回 PaInputOverflowed。

Pa_Terminate()

PaError Pa_Terminate ( void )

库终止函数 - 使用完 PortAudio 后调用它。此函数释放自通过调用 Pa_Initialize() 初始化以来 PortAudio 分配的所有资源。如果 Pa_Initialize() 已被多次调用，则每次调用都必须与相应的 Pa_Terminate() 调用配对。最后一次配对的 Pa_Terminate() 调用会自动关闭所有仍处于打开状态的 PortAudio 流。

使用 PortAudio 的程序退出前必须调用 Pa_Terminate()。否则可能导致严重的资源泄漏，例如音频设备在下次重启之前一直不可用。

Pa_WriteStream()

PaError Pa_WriteStream ( PaStream * stream, const void * buffer, unsigned long frames )
