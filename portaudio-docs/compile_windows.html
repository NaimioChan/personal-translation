在 Windows 上用 Visual Studio 构建 PortAudio

注意：本页介绍使用 msvc// 目录中旧版 MSVC 工程文件构建 PortAudio 的方法。你也可以使用 CMake 构建系统。

下面列出把 PortAudio 构建成 dll 和 lib 文件的步骤。生成的 dll 文件可能包含当前全部五种 win32 PortAudio API：MME、DirectSound、WASAPI、WDM/KS 和 ASIO，具体取决于下面第 9 步设置的预处理器定义。

可以使用 Microsoft 免费提供的 Visual C++ Express Edition 编译 PortAudio。如果你还没有 C++ 开发环境，直接下载并安装即可。这些说明在 Visual Studio 2010 上也验证可用。

1) 构建带 DirectSound 支持的 PortAudio 需要 dsound.h 和 dsconf.h 文件。从 http://www.microsoft.com/downloads/details.aspx?displaylang=en&FamilyID=3021d52b-514e-41d3-ad02-438a3ba730ba 下载并安装 DirectX SDK 即可获得这两个文件。如果已安装 DirectX SDK，Visual Studio/Visual C++ 应能自动找到 DirectSound 的库和头文件。如果出现提示 dsound.h 或 dsconf.h 缺失的错误，就需要在 Visual Studio 工程文件中增加一个包含路径，指向 DirectX 的 includes 目录。

2) 若要构建不带 ASIO（或其他宿主 API）支持的版本，请参阅下面的“不带 ASIO 支持的构建”一节。若要构建带 ASIO 支持的版本，请从 Steinberg 的 http://www.steinberg.net/en/company/developer.html 下载 ASIO SDK。该 SDK 免费，但你需要注册 Steinberg 开发者账号。要使用下面提到的 Visual Studio 工程，请把整个 ASIOSDK2 文件夹复制到 src\hostapi\asio\ 中，再把文件夹名从 ASIOSDK2 改为 ASIOSDK。注意：Windows 上某些版本的 ASIO SDK 存在数组删除缺陷。要绕过这个问题，需要给 ASIO SDK 打补丁。修复方法参见 src/host/asio/ASIO-README.txt。

3) 如果你使用 Visual Studio 6.0、7.0(VC.NET/2001) 或 7.1(VC.2003)，请打开 portaudio.dsp，必要时进行转换。

4) 如果你使用 Visual Studio 2005、Visual C++ 2008 Express Edition 或 Visual Studio 2010，请打开位于 msvc\ 中的 portaudio.sln 文件。打开后会启动 Visual Studio 或 Visual C++。如果出现转换向导，点击“Finish”。sln 文件包含四种配置：Win32 和 Win64，且各有 Release 和 Debug 两种变体。

适用于 Visual Studio 2005、Visual C++ 2008 Express Edition 或 Visual Studio 2010

下面的步骤介绍较新版本 Visual Studio 的设置。早期版本的 Visual Studio 也可以做类似的设置。

5) 打开 Project -> portaudio Properties，在树状视图中选择“Configuration Properties”。

6) 在上方的“Configurations”组合框中选择“all configurations”。在“Platforms”组合框中选择“All Platforms”。

7) 下面设置几个选项：

必需：

C/C++ -> Code Generation -> Runtime library = /MT

可选：

可选：C/C++ -> Optimization -> Omit frame pointers = Yes

可选：C/C++ -> Code Generation -> Floating point model = fast

注意：在 C/C++ 中使用 PortAudio 时，通常不必显式设置结构体成员对齐，默认值即可正常工作。但有些语言要求例如 4 字节对齐。如果遇到 portaudio.h 结构体成员读取或写入不正确的问题，可能需要显式设置该值：依次进入 C/C++ -> Code Generation -> Struct member alignment，将其设为合适的值（4 是常见取值）。如果你的编译器可配置，应确保它使用与构建 PortAudio 时相同的结构体成员对齐值。

设置完这些参数后点击“Ok”。

预处理器定义

由于各配置和平台的预处理器定义不同，你需要使用“Configurations”和“Platforms”组合框，为每个想要修改的配置/平台组合分别编辑。

8) 若要禁止 PortAudio 在调试控制台输出运行时信息，请依次进入 Project -> Properties -> Configuration Properties -> C/C++ -> Preprocessor。在“Preprocessor Definitions”字段中找到 PA_ENABLE_DEBUG_OUTPUT 并删除它。控制台将不再输出调试信息。

9) 同样在预处理器定义中，你还需要显式定义希望使用的本机音频 API。在 Windows 上可用的 API 定义有：

PA_USE_ASIO
PA_USE_DS (DirectSound)
PA_USE_WMME (MME)
PA_USE_WASAPI
PA_USE_WDMKS
PA_USE_SKELETON

其中值为 0 表示不包含对该 API 的支持，值为 1 表示包含对该 API 的支持。（PA_USE_SKELETON 通常不使用，它是供想要支持新 API 的开发者参考的代码示例）。

构建

与设置预处理器定义时一样，构建也是按配置、按平台分别进行的。请对每个你关注的配置/平台组合执行以下步骤。

10) 在 Build 菜单中点击 Build -> Build solution。32 位编译生成的文件为 portaudio_x86.dll，位于 msvc\Win32\Release 目录。64 位编译生成的文件名为 portaudio_x64.dll，位于 msvc\x64\Release 目录。

11) 现在，任何需要 portaudio 的工程都可以链接 portaudio_x86.lib（或 _x64）并包含相关头文件（portaudio.h 和/或 pa_asio.h、pa_x86_plain_converters.h）。你可能需要添加或删除一些 DLL 入口点。撰写本文时，以下 6 个入口点不属于 portaudio.h 中定义的官方 PortAudio API：

（摘自 portaudio.def）

...
PaAsio_GetAvailableLatencyValues    @50
PaAsio_ShowControlPanel             @51
PaUtil_InitializeX86PlainConverters @52
PaAsio_GetInputChannelName          @53
PaAsio_GetOutputChannelName         @54
PaUtil_SetLogPrintFunction          @55

不带 ASIO 支持的构建

要构建不带 ASIO 支持的 PortAudio，需要：

1) 确保你的工程不会尝试构建任何 ASIO SDK 文件。如果你使用随附的工程之一，请从工程中移除与 ASIO 相关的文件。在随附工程中，它们位于工程树的 portaudio > Source Files > hostapi > ASIO > ASIOSDK 下

2) 确保你的工程不会尝试构建 PortAudio 的 ASIO 实现文件：

src\\hostapi\\pa_asio.cpp
src\\hostapi\\iasiothiscallresolver.cpp

如果你使用随附的工程之一，请把它们从工程中移除。在随附工程中，它们位于工程树的 portaudio > Source Files > hostapi > ASIO 下

3) 按上面第 9 步所述，在工程属性中定义预处理器符号。在 VS2005 中，可以依次选择 Project Properties -> Configuration Properties -> C/C++ -> Preprocessor -> Preprocessor Definitions 来完成。省略 PA_USE_ASIO 或将其设为 0，可以阻止 src\os\win\pa_win_hostapis.c 尝试初始化 PortAudio 的 ASIO 实现。

4) 从 portaudio.def 中移除 PaAsio_* 入口点

Windows 音频 API 列表

WASAPI：Microsoft 推荐。自 Windows Vista 起支持（包括 7/8/10+）。

ASIO：面向专业音频用户的低延迟 API；需要用户安装 ASIO 驱动。

WMME、DirectSound：旧版 API，提供更好的向后兼容性

WDM/KS：直接访问驱动的底层 API。
