在 Windows 上用 MinGW-w64 构建 PortAudio

用 MinGW-w64 构建 Windows 版 PortAudio

MinGW-w64 是把 Linux 工具链（gcc、clang）移植到 Windows 的产物，按首选配置随 Msys2 一起打包提供。Msys2 提供 Linux 环境和包管理器 pacman。从 https://www.msys2.org/ 安装 MinGW-w64，并按照该页面上的说明操作。

题外话：Msys2 中有许多工具链变体，编译所有项目时必须使用同一套工具链。本教程使用 msvcrt-gcc 工具链，原因只是它在所有 Windows 版本上都已存在。读者以后可能会为了 Windows 10 及更高版本的构建而改用 ucrt-gcc 工具链，不过这样做几乎没有什么好处。可用工具链的列表见 https://www.msys2.org/docs/environments/。

此外，你还可以选择 Windows 音频 API；列表见 在 Windows 上用 Visual Studio 构建 PortAudio 的末尾。

你可以使用 msys2 预编译的 PortAudio，也可以自行编译 PortAudio。安装 msys2 预编译的 PortAudio 请见下一节。自行编译 PortAudio 请跳到下下节。

预编译包

打开 msys2 shell 并运行 "pacman -S mingw-w64-x86_64-portaudio"。这会给你一个默认构建的 PortAudio。据我所知，它包含 DirectSound、WASAPI、WD/MKS、WD/MKS_DEVICE_INFO 和 WMME。注意包名中间的 "-x86_64"。安装 msys2 包时，你在名字中间指定工具链名称，"-x86_64" 即选择 msvcrt-gcc 工具链。

从零开始编译

作为示例，这里只用 WASAPI 构建，不启用任何回退 API。在 msys2 shell 中进入你的 PortAudio 文件夹，运行：

pacman -S mingw-w64-x86_64-cmake mingw-w64-x86_64-ninja
mkdir build
cd build
cmake -G Ninja .. -DCMAKE_BUILD_TYPE=Release -DPA_USE_DS=0 -DPA_USE_WDMKS=0 -DPA_USE_WDMKS_DEVICE_INFO=0 -DPA_USE_WMME=0
cmake --build .

要测试是否可用，可以运行锯齿波示例（警告，声音非常大！）：

gcc ../examples/paex_saw.c -I../src/common -lportaudio
./a.exe

你可以通过删除 cmake 命令中 "-DPA_USE_WMME=0" 这类项来重新启用所需的回退 API。向公众发布你的应用程序时，务必把 libportaudio.dll（位于 build 文件夹中）复制到你自己的应用程序文件夹。（你还需要随程序附带 MinGW-w64 各种共享库的副本；可以用 Microsoft 的 Process Explorer 查看哪些 dll 是从你的 msys64 文件夹访问的。）

或者，采用静态编译，免除复制 dll 的麻烦。
