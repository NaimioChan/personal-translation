在 Mac OS X 上构建 PortAudio

要求

OS X 10.6 或更高版本。PortAudio v19.7 目前只能在 OS X 10.6 及更高版本上编译和运行。

在默认位置安装的 Apple Xcode 及其相关工具。PortAudio 没有提供 Xcode 工程。

Mac 10.6 SDK。在系统中查找 "/Developer/SDKs/MacOSX10.6.sdk" 文件夹，它可能随 XCode 一起安装。如果没有，可以从 Apple Developer Connection 下载。http://connect.apple.com/

构建

要构建 PortAudio，直接使用 Unix 风格的 "./configure && make"：

./configure && make

你不需要执行 "make install"，我们也不推荐这样做；不过，你使用的软件可能要求你这么做，此时应遵循该软件的说明。（Phil 的备注：执行上述命令之后我不得不运行 "sudo make install"，否则 XCode 在编译示例时会报错说找不到 "/usr/local/lib/libportaudio.dylib"。）

这些步骤的结果是在目录 "usr/local/lib/" 中生成名为 "libportaudio.dylib" 的文件。

默认情况下，这会生成通用二进制文件，因此需要 Apple 的 Universal SDK，它随 XCode 2.1 及更高版本提供。

其他构建选项

构建 PortAudio 还有许多其他选项。上面描述的默认方式获得的支持和测试最充分，因此推荐使用；不过你的需求可能不同，需要采用下面描述的其他选项。

默认情况下，PortAudio 构建为通用二进制文件。如果在 10.6（Snow Leopard）上编译，其中会包含 64 位版本。如果你想要 "thin"（即单一架构）库，有两种选择：

使用 configure 选项构建非通用库。对你计划使用的库的相应部分使用 lipo(1)。

注意，第一种选择可能需要相当新的 PortAudio 版本（至少是 2008 年 2 月 5 日的版本）。

要为宿主架构构建非通用库，只需在 configure 时使用 –disable-mac-universal 选项。

./configure --disable-mac-universal && make

–disable-mac-universal 选项还可以与环境变量配合使用，让你更好地控制通用二进制文件的构建过程。例如，要用 10.6 sdk 为 i386 和 ppc 架构构建通用二进制文件，可以这样指定 configure 命令行：

CFLAGS="-O2 -g -Wall -arch i386 -arch ppc -isysroot /Developer/SDKs/MacOSX10.6.sdk -mmacosx-version-min=10.6" \
  LDFLAGS="-arch i386 -arch ppc -isysroot /Developer/SDKs/MacOSX10.6.sdk -mmacosx-version-min=10.6" \
  ./configure --disable-mac-universal --disable-dependency-tracking

更多信息请参阅 Apple 的相关文档：

http://developer.apple.com/technotes/tn2005/tn2137.html http://developer.apple.com/documentation/Porting/Conceptual/PortingUnix/intro/chapter_1_section_1.html

第二种选择是正常构建，然后用 lipo (1) 提取你需要的架构。例如，如果你只想要 "thin" 的 i386 库：

lipo lib/.libs/libportaudio.a -thin i386 -output libportaudio.a

或者，如果你想提取单一架构的 fat 文件：

lipo lib/.libs/libportaudio.a -extract i386 -output libportaudio.a

默认情况下，Mac 上的 PortAudio 构建时不启用任何调试选项。这是因为断言通常不适合生产环境，而且人们怀疑（但未证实）调试信息会给某些接口带来问题。如果希望带调试信息编译，必须用相应的标志运行 configure。例如：

./configure --enable-mac-debug && make

这会启用 -g 并禁用 -DNDEBUG，从而实际启用断言。

在 XCode 工程中使用该库

如果你打算继续学习本教程的其余部分，有几种工程类型都可以用。你可以在 "Command Line Utility" 下创建 "Standard Tool"。如果你不继续学习本教程的其余部分，任何类型的工程都能与 PortAudio 配合使用，但这些说明可能不完全适用。

编译好 PortAudio 之后，在你的 XCode 工程中使用 PortAudio 最简单也最受推荐的方式，是把 "<portaudio>/include/portaudio.h" 和 "<portaudio>/lib/.libs/libportaudio.a" 加入工程。由于 "<portaudio>/lib/.libs/" 是隐藏目录，你无法通过点击文件和文件夹用 Finder 或 Mac OS 标准文件对话框导航到它。你可以在 Finder 中使用 command-shift-G 指定确切路径，或者在 shell 中，如果你位于 portaudio 目录，可以输入以下命令：

open lib/.libs

然后把 "libportaudio.a" 文件拖入你的 XCode 工程；如果工程类型中有 "External Frameworks and Libraries" 分组，就把它放在该分组中，如果没有，直接把它加到工程的顶层文件夹即可。

你需要向 XCode 工程中添加以下 framework：

  • CoreAudio.framework
  • AudioToolbox.framework
  • AudioUnit.framework
  • CoreServices.framework
  • CoreFoundation.framework

在其他项目中使用该库

对于 gcc/Make 风格的工程，包含 "include/portaudio.h" 并链接 "libportaudio.a"，同时使用上一节列出的那些 framework。具体做法取决于你的构建方式。

使用 PortAudio 的 Mac 专用扩展

如果需要 PortAudio 接口额外的 Mac 专用扩展，你可能还想获取 "include/pa_mac_core.h"。该文件包含一些 Mac 专用的特殊功能，涉及采样率转换、声道映射、性能以及设备独占。有关这些功能的更多细节参见 "src/hostapi/coreaudio/notes.txt"。

Makefile.darwin 怎么了？

注意，以前有一个专为 darwin 准备的 makefile。现在已不再支持它，因为可以通过标准的 configure 流程构建通用二进制文件。如果在你的目录结构中发现了这个文件，说明你使用的 PortAudio 版本已过时。

make -f Makefile.darwin
