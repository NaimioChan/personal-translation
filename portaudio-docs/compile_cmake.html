用 CMake 构建 PortAudio

作为 autotools 的替代方案，PortAudio 也提供了通过 CMake 构建的方式。CMake 的工作方式是生成供其他构建系统使用的文件，包括 Visual Studio 解决方案、Makefile 以及许多其他构建系统。

如果你熟悉 CMake 项目的构建，PortAudio 遵循构建 CMake 项目的标准步骤。如果不熟悉，请继续往下阅读。

通用步骤

CMake 项目的构建过程在所有平台上大体相同。为了让你尽快上手，我们先给出通用说明，介绍如何在所有平台上构建 PortAudio。如果你需要更多帮助，后面的小节会说明如何针对特定平台构建。（Windows 请见 Windows，macOS、Linux 及其他系统请见 Linux、OS X 及其他系统）。

前置条件

在做任何事之前，你需要先安装好相应的软件。本说明假定你已经安装了以下软件：

  • 已安装 C 编译器，例如 GCC、Clang 或 MSVC。
  • Git
  • CMake

Git 和 CMake 通常随开发者工具一起提供。例如在 Windows 上安装 Visual Studio 时，可以让 Visual Studio 安装程序顺带安装 CMake。否则，你需要分别从各自的网站下载它们。在 Linux 及类似系统上，用系统的包管理器安装即可。如果你还不知道具体怎么做，请查阅你所使用发行版的文档，或用你常用的搜索引擎查找更多信息。

在 Windows 和 macOS 上，PortAudio 不需要任何额外依赖。在其他系统（包括 Linux）上，你需要为计划在 PortAudio 中启用的音频后端安装相应的开发包。具体做法见 音频后端开发包 小节。

构建 PortAudio 需要经过三个步骤：

  • 第 1 步：获取 PortAudio 源代码
  • 第 2 步：配置构建
  • 第 3 步：构建 PortAudio

然后，可选的一步：

可选：安装 PortAudio

第 1 步：获取 PortAudio 源代码

在开始构建 PortAudio 之前，必须确保你已经拿到 PortAudio 的源代码。如果已经有源代码，可以跳到下一节。

获取 PortAudio 源代码有两种方式：克隆 PortAudio 的 GitHub 仓库 https://github.com/portaudio/portaudio，或者用你惯用的下载工具（例如 wget）下载 https://files.portaudio.com/download.html 上列出的源码压缩包。如果选择后一种方式获取源代码，别忘了先安装 tar 和 gzip 来解压。不过本教程使用 Git，因为这样不需要先解压。

要使用 Git 克隆 PortAudio 的 GitHub 仓库，先打开终端、命令提示符窗口，甚至 PowerShell 窗口，切换到一个合适的目录（例如你的文档文件夹）。然后在这个新打开的窗口中运行以下命令：

git clone https://github.com/portaudio/portaudio

现在可以开始构建 PortAudio 了。

第 2 步：配置构建

在第 1 步打开的同一个窗口中，运行以下命令来准备构建：

mkdir build
cd build
cmake ../portaudio

使用最后一条命令时，默认情况下构建系统会被配置为构建共享库（即 .dll、.dylib 或 .so）。如果你想要静态库（即 .a、.lib），需要在上面最后一条命令中加上 -DPA_BUILD_SHARED_LIBS=OFF，如下所示：

cmake -DPA_BUILD_SHARED_LIBS=OFF ../portaudio

（注意：PortAudio 也支持 CMake 标准的 BUILD_SHARED_LIBS 机制。）

在 Unix 系统上，或者在 Windows 上使用 Makefile 时，这还会让 CMake 默认构建 PortAudio 的调试版本。如果你希望默认构建发布版本，在上面三条命令中的最后一条上加上 -DCMAKE_BUILD_TYPE=Release：

cmake -DCMAKE_BUILD_TYPE=Release ../portaudio

如果需要，你也可以把 -DCMAKE_BUILD_TYPE=Release 和 -DPA_BUILD_SHARED_LIBS 这样组合起来使用：

cmake -DPA_BUILD_SHARED_LIBS=ON -DCMAKE_BUILD_TYPE=Release ../portaudio

此时 PortAudio 的构建文件已经生成，并放入 build 目录中。

在 Windows 上使用 Visual Studio 构建，或在 Unix 上使用 "Ninja Multi-Config" 生成器时，库文件会放在以你所选配置命名的文件夹中（例如 Debug/、Release/、RelWithDebInfo/ 等）。否则，它们就直接放在构建目录的根下。现在可以开始真正的构建了。

构建测试与示例

测试和示例分别由 PortAudio 的 -DPA_BUILD_TESTS 和 -DPA_BUILD_EXAMPLES 选项控制。把它们中的一个或两个加到上面那系列命令的（cmake）命令中即可。是否已经运行过该命令都没有关系。

所有测试都会放在构建目录下的 test 文件夹中，所有示例则放在同样位于构建文件夹中的 examples 目录下。

要在常规的 PortAudio 构建之外只构建测试，运行以下命令：

cmake -DPA_BUILD_TESTS=ON ../portaudio

要在常规的 PortAudio 构建之外只构建示例，运行以下命令：

cmake -DPA_BUILD_EXAMPLES=ON ../portaudio

要在常规的 PortAudio 构建之外同时构建示例和测试，运行以下命令：

cmake -DPA_BUILD_TESTS=ON -DPA_BUILD_EXAMPLES=ON ../portaudio

之后构建测试时，它们会位于构建文件夹下的 test/ 目录中。示例则位于 examples/。在 Windows 上，测试和示例各自所在的目录下还会多出一个以你所构建的配置命名的文件夹。默认是 Debug，如果你构建的是 Release 配置，也可能位于 Release/ 下。

PortAudio 的构建选项在 构建选项 中有进一步说明。关于运行 PortAudio 测试和示例的更多内容，见 运行测试与示例。

配置安装目录

如果你打算稍后安装构建好的 PortAudio，可能需要调整默认的安装目录。在 Linux 上默认是 /usr/local。要修改它，在 cmake 命令后面加上 -DCMAKE_INSTALL_PREFIX=/path/to/new/install/location。例如，如果你想让构建出的 PortAudio 安装到 /opt/portaudio，运行以下命令配置 CMake：

cmake -DCMAKE_INSTALL_PREFIX=/opt/portaudio ../portaudio

第 3 步：构建 PortAudio

构建系统已经配置好了，要构建 PortAudio，再运行最后一条命令，同样是在第 1 步打开的窗口中：

cmake --build .

你也可以直接调用 CMake 为其生成构建文件的构建工具。例如，如果 CMake 生成的是 Makefile（在 macOS、Linux 及类似系统上通常是默认情况），那么直接运行 make 即可。如果 CMake 生成的是 Visual Studio 工程（.sln、.vcproj）（在 Windows 上通常是默认情况），你可以打开生成的 Visual Studio 工程，在 Visual Studio 里构建 PortAudio（或者，如果你更习惯，也可以运行 msbuild）。

如果你使用的是 多配置生成器，例如 Visual Studio 或 "Ninja Multi-Config"，可以用 --config 选项控制构建哪种配置（Debug、Release 等）：

cmake –build . –config Debug

总结一下上面的所有步骤：

  1. 开始之前，先用 Git 从 GitHub 克隆 PortAudio 的源代码。没有源代码，其他什么都做不了。
  2. 然后，作为起步，创建一个新的构建文件夹。通常它与 PortAudio 源码树并列（这是推荐的位置），但技术上放在任何地方都可以。
  3. 接下来，cd 进入构建目录，以便在该文件夹内操作。
  4. 之后，调用 CMake 配置 PortAudio。换句话说，我们调用 CMake 生成 PortAudio 的构建文件。完成这件事的命令称为配置命令。
  5. 最后，再次调用 CMake，真正构建 PortAudio。

可选：安装 PortAudio

如果你想把刚构建好的 PortAudio 安装到系统中，可以运行以下命令：

cmake --build . -t install

和之前一样，你也可以直接调用 CMake 为其生成构建文件的构建工具。请务必构建 install 目标。注意这会把 PortAudio 安装到系统目录中，请谨慎操作。

运行测试与示例

如前所述，测试和示例分别位于 test 和 examples 文件夹中。同样地，Windows 上有个例外：测试和示例各自所在的目录下还会有一个以当前配置命名的子目录。（在其他平台上使用多配置生成器时也会如此。）在本例中，我们假定你构建这些测试时使用的是默认的 Debug 配置。如果你的配置不同，请相应地调整示例。所有可能的构建配置列表见 通用 CMake 选项。

要列出测试，在之前使用的同一个终端或命令提示符窗口中运行以下命令（在 Windows 命令提示符下把 ls 换成 dir）：

ls test/

在 Windows 上使用 Visual Studio 时，test/ 应该是这样：

dir test\Debug

要实际运行某个测试，运行以下命令：

test/patest_sometest

在 Windows 上使用 Visual Studio 时：

test/Debug/patest_sometest.exe

把 patest_sometest 换成你想运行的测试名。同时把 Debug 换成你当前使用的构建配置。

以上做法同样适用于示例：

ls examples/ # List all known examples
examples/paex_sine # Execute an example

最后，Windows 上对应的写法：

dir examples\Debug
examples\Debug\paex_sine.exe

构建选项

PortAudio 的 CMake 构建系统还提供若干配置选项。选项列表见 CMake 构建选项。把它们按 -DOPTION_NAME=VALUE 的格式追加到配置命令中，其中 VALUE 通常是 ON 或 OFF。例如 cmake /path/to/portaudio -DPA_BUILD_TESTS=ON。注意每次修改配置选项后通常不需要清空构建目录重新开始，但如果遇到问题，应该用一个全新的构建目录再试一次。

如果你想使用别的构建文件生成器，在最初的配置 cmake 命令中加上 -G "Generator Name"，其中 "Generator Name" 是你要使用的生成器名称，例如 "Ninja"。这里只介绍默认生成器（Visual Studio 工程和 Unix Makefile），如果你对其他生成器有经验，也可以随意使用。cmake --help 命令会列出所有可用的构建文件生成器。

以下几节给出针对各平台的示例。注意这些示例假定你在源码树之外创建了一个名为 pabuild 的构建目录。

Windows

在 Windows 上，CMake 默认会生成 Visual Studio 工程，因此你需要先安装 Visual Studio。安装 Visual Studio 时，请确保选中 使用 C++ 的桌面开发 工作负载。然后，要构建 64 位版本，打开一个命令提示符窗口（这种情况下不需要是开发者命令提示符）。也可以改用 PowerShell，下面的命令在 PowerShell 中同样有效。

开始之前，在你的命令提示符或 PowerShell 窗口中运行以下命令：

C:\> mkdir pabuild
C:\> cd pabuild

然后运行以下命令配置构建：

C:\pabuild> cmake C:\path\to\portaudio

配置成功后，就可以运行以下命令开始构建：

C:\pabuild> cmake --build .

这会构建 PortAudio 的调试配置。如果你需要 PortAudio 的发布配置，按下面的方式在上面的命令中加上 --config Release：

C:\pabuild> cmake --build . --config Release

（注意 --config Release 必须放在 --build . 之后 才能生效）

或者，你可以在 Visual Studio 中打开生成的 portaudio.sln 文件，用这种方式构建 PortAudio。

实际的 PortAudio 库会输出到以你刚构建的配置命名的目录中。例如，如果你构建的是 Debug 配置，文件会位于构建文件夹的 Debug/ 下。如果你构建的是 Release 配置，文件会位于构建文件夹的 Release/ 下。这是因为 CMake 的 Visual Studio 生成器属于多配置生成器（也就是说你可以在不重新生成构建系统的情况下构建多种配置）。在 Unix 上使用 Ninja Multi-Config 生成器时，你会看到类似的行为。

更多 CMake 选项见 通用 CMake 选项。

带 ASIO 支持编译

如果你想构建带 ASIO 支持的 PortAudio，必须先到 https://www.steinberg.net/developers 下载 ASIO SDK，并按 在 Windows 上用 MSVC 构建带 ASIO 支持的 PortAudio 中的说明放置它。CMake 会自动查找 ASIO SDK，并默认在 PortAudio 中启用 ASIO 支持。

另外，如果你使用的是 CMake 3.18 或更高版本，在配置命令中加上 -DPA_USE_ASIO=ON 后，CMake 会自动为你下载并解压 ASIO SDK。

重要警告：ASIO SDK 仅在专有许可下提供。该许可证提出了许多要求，包括对你构建的二进制文件的分发条件与限制。请务必阅读 Steinberg 的这个页面：https://www.steinberg.net/developers。另外请注意，启用 ASIO 可能影响初始化性能和可靠性，启用该后端时请谨慎。更多信息见 https://github.com/PortAudio/portaudio/issues/696。

Linux、OS X 及其他系统

Linux 与 Mac OS X 的配置过程相同，因此这两个平台放在同一节中。实际上本节的说明适用于大多数类 Unix 平台，例如 FreeBSD 用户也可以照此操作。

在阅读本节之前，如果你在 Linux 或类似系统上，请先安装 音频后端开发包 中列出的相应音频后端开发包。然后回到本节，继续下面的其余步骤。

首先，创建构建文件夹并进入其中：

$ mkdir build && cd build

然后运行 cmake 命令，把构建配置为 静态库：

$ cmake /path/to/portaudio/source

如果你想要 共享库 配置，加上 -DPA_BUILD_SHARED_LIBS=ON：

$ cmake -DPA_BUILD_SHARED_LIBS=ON /path/to/portaudio/source

默认情况下这会创建 Unix Makefile。如果你安装了 Ninja 并想改用它，可以在配置命令中加上 -G Ninja。要使用前面提到的 "Ninja Multi-Config" 生成器，可以加上 -G "Ninja Multi-Config"

配置完成后，运行以下命令构建 PortAudio：

$ cmake --build .

你可以加上 -j <num> 来加快构建速度（<num> 是分配给构建的作业数，通常取决于你电脑的 CPU 线程数）。

与 Windows 不同，实际的库文件无论在哪种配置下都位于构建目录的根下。

换个角度看，如果你熟悉 autotools，会发现 CMake 的作用与 ./configure 脚本类似。两者都会为你当前构建的项目生成 makefile。因此，下面这组命令的 CMake 等价写法是：

$ /path/to/portaudio/source/configure --prefix=/install_location # Assume we're in the build directory 'pabuild'
$ make
$ make install

则是：

$ cmake -DCMAKE_INSTALL_PREFIX=/install_location /path/to/portaudio/source # Assume we're in the build directory 'pabuild'
$ cmake --build .
$ cmake --build . --target install

音频后端开发包

注意在 Linux 上需要安装额外的音频开发包，否则 CMake 会报告没有可用的后端。在 Debian、Ubuntu 及其衍生发行版上，可以用 apt 安装下面一个或多个开发包，以获得可用的音频后端：

  • libasound2-dev，用于 ALSA
  • libjack-dev，用于 JACK

待办：补充 PulseAudio 开发包。

注意这里没有列出 OSS。在大多数现代 Linux 发行版上，音频设备不会出现在 OSS 下，这会让最终用户困惑。

如果你读到此处时已经编译过 PortAudio，请删除构建文件夹，安装好开发包后重新按照 PortAudio 的构建说明操作。

构建示例

注意
这些说明适用于所有平台。

要构建示例，只需在配置命令中加上 -DPA_BUILD_EXAMPLES=ON，然后按需重新构建 PortAudio。关于构建选项的更多信息见 通用步骤。示例会位于构建文件夹的 examples/ 目录中。

构建测试

注意
  • 这些说明适用于所有平台。
  • PortAudio 不支持 CTest。欢迎贡献代码为其添加支持。

用 CMake 构建 PortAudio 时不会自动构建测试。要构建测试，只需在配置命令中加上 -DPA_BUILD_TESTS=ON，然后按需重新构建 PortAudio。关于构建选项的更多信息见 通用步骤。测试会位于构建文件夹的 test/ 目录中。

CMake 构建选项

本节包含用于配置构建的选项。有些选项是 PortAudio 特有的，另一些是通用的 CMake 选项。无论它们是否专属于 PortAudio，这些选项在配置构建系统时都会被应用。

通用 CMake 选项

  • -DCMAKE_BUILD_TYPE=<buildtype>：改变构建系统要构建的配置。可用的配置有：Release 用于发布构建，Debug 用于调试构建，RelWithDebInfo 用于可调试的发布构建，MinSizeRel 用于尽可能小的构建，None 表示不做配置。
  • -DCMAKE_INSTALL_PREFIX=/install_prefix：运行 make install 或类似命令时，安装到 /install_prefix，而不是 CMake 默认的 /usr。

PortAudio 特有选项

后端选项

注意
这里的所有选项在可用时都默认为 ON，但 OSS、ASIO 和 skeleton 后端除外。
  • -DPA_USE_ALSA=ON|OFF：（仅限 Linux/类 Unix 等）。使用 ALSA 宿主 API。需要 ALSA。
    • -DPA_ALSA_DYNAMIC=ON|OFF：使用 PaAlsa_SetLibraryPathName 通过 dlopen 动态加载 libasound。默认关闭[3]。
  • -DPA_USE_ASIO=ON|OFF：（仅限 Windows）。使用 ASIO 宿主 API。需要 ASIO SDK[1]。
  • -DPA_USE_AUDIOIO=ON|OFF：（仅限 Solaris）。使用 audioio 宿主 API。
  • -DPA_USE_DS=ON|OFF：（仅限 Windows）。使用 DirectSound 宿主 API。
  • -DPA_USE_JACK=ON|OFF：使用 JACK 宿主 API。需要 JACK。
  • -DPA_USE_OSS=ON|OFF：（仅限 Linux/类 Unix 等）。使用 OSS 宿主 API[2]。需要 OSS。
  • -DPA_USE_PULSEAUDIO=ON|OFF：（仅限 Linux/类 Unix 等）。使用 PulseAudio 宿主 API。需要已安装 PulseAudio。
  • -DPA_USE_SKELETON=ON|OFF：使用 skeleton 宿主 API（无音频输出）。
  • -DPA_USE_SNDIO=ON|OFF：（仅限 Linux/类 Unix 等）。使用 sndio 宿主 API。
  • -DPA_USE_WASAPI=ON|OFF：（仅限 Windows）。使用 WASAPI 宿主 API。
  • -DPA_USE_WDMKS=ON|OFF：（仅限 Windows）。使用 WDMKS 宿主 API。
    • -DPA_USE_WDMKS_DEVICE_INFO=ON|OFF：使用 WDMKS API 获取设备信息。
  • -DPA_USE_WMME=ON|OFF：（仅限 Windows）。使用 MME 宿主 API。

[1] 在用 ASIO 编译 PortAudio 之前，请阅读上文 带 ASIO 支持编译 中的重要警告。

[2] 为避免让最终用户困惑，OSS 后端默认是关闭的，因为现代 Linux 系统上没有 OSS 设备。

[3] 与本节其他选项不同，PA_ALSA_DYNAMIC 默认为 OFF。

其他构建选项

  • -DPA_BUILD_SHARED_LIBS=ON|OFF：把 PortAudio 构建为共享库而不是静态库。默认值：OFF
  • -DPA_BUILD_TESTS=ON|OFF：构建所有测试。默认值：OFF
  • -DPA_BUILD_EXAMPLES=ON|OFF：构建所有示例。默认值：OFF
  • -DPA_DLL_LINK_WITH_STATIC_RUNTIME：（仅限 Windows）。让 PortAudio 链接静态运行时依赖。
  • -DPA_ENABLE_DEBUG_OUTPUT=ON|OFF：启用调试输出。默认值：OFF
  • -DPA_WARNINGS_ARE_ERRORS=ON|OFF：把所有警告视为错误。主要供开发者使用。默认值：OFF

在你自己的 CMake 项目中使用 PortAudio

PortAudio 定义了两个 CMake 目标：PortAudio::portaudio 用于动态库，PortAudio::portaudio_static 用于静态库，可以把它们添加到你自己项目目标的 target_link_libraries 中。

使用这些目标有两种方式：find_package() 或 add_subdirectory()。

使用 find_package() CMake 命令

使用上述目标最简单的方式，是通过包管理器（你的发行版包管理器、vcpkg 等）安装 PortAudio，然后使用 find_package() CMake 命令。命令用法如下：

find_package(portaudio)

可以在 portaudio 后面加上 REQUIRED，把它设为必需依赖：

find_package(portaudio REQUIRED)

遗憾的是，目前并非所有发行版软件包都会安装所需的 .cmake 文件，导致这种方式无法正常工作，另一种选择见下文 使用 pkg-config。

如果你按上文 第 3 步：构建 PortAudio 所述安装了 PortAudio，且所使用的安装前缀（由 CMAKE_INSTALL_PREFIX 指定）满足以下条件，这种方式同样可行：

  • 也是你项目的 CMAKE_INSTALL_PATH
  • 位于 CMake 变量或环境变量 CMAKE_PREFIX_PATH 中
  • 是你系统 PATH 中某个目录的前缀（例如，如果你把 PortAudio 安装在 /opt/portaudio，而你的 PATH 包含 /opt/portaudio/bin）

如果这些方式都不可行，你在配置项目时也可以设置 PortAudio_DIR，指向包含这些文件的安装目录。例如，如果你把 PortAudio 安装在 /home/me/portaudio19：

cmake -S . -B build -DPortAudio_DIR=/home/me/portaudio19/lib/cmake/portaudio

使用 add_subdirectory() CMake 命令

如果你不想把 PortAudio 安装到系统中，也可以把 PortAudio 放进你项目的源码树里（例如作为 Git 子模块）或类似的做法。这种情况下，按下面的方式使用 add_subdirectory() CMake 命令：

add_subdirectory(relative/path/to/portaudio)

这种情况下，在你项目中使用 portaudio 或 portaudio_static 目标时，还必须去掉 PortAudio:: 命名空间，并确保这些目标名不与已有的目标名冲突。这是 CMake 的一个长期存在的问题。

你也可以从源码树之外的目录引入 PortAudio，这种情况下必须再加上第二个参数，指定 PortAudio 二进制文件将构建到构建目录中的哪个子目录。

add_subdirectory(/absolute/path/to/portaudio portaudio)

请确保它不会与你项目中已有的目录冲突！

可选地，你可以加上 EXCLUDE_FROM_ALL。若加上 EXCLUDE_FROM_ALL，则会把 PortAudio 排除在默认构建之外。

使用 pkg-config

截至本文写作时，并非所有 GNU/Linux 发行版的 PortAudio 软件包都会安装所需的 .cmake 文件，让 find_package() 正常工作。如果是这种情况，你也可以用 pkg-config 获取把程序链接到 PortAudio 所需的编译选项。例如，如果你的程序目标名为 patest：

 find_package(PkgConfig)
 if(PKG_CONFIG_FOUND)
   pkg_check_modules(PORTAUDIO portaudio-2.0)
   if(PORTAUDIO_FOUND)
     target_link_libraries(patest ${PORTAUDIO_LIBRARIES})
     target_include_directories(patest PUBLIC ${PORTAUDIO_INCLUDE_DIRS})
   endif()
 endif()
