启动、停止与中止流

在你启动流之前，PortAudio 不会开始播放音频。调用 Pa_StartStream() 之后，PortAudio 将开始调用你的回调函数来执行音频处理。

err = Pa_StartStream( stream );
if( err != paNoError ) goto error;

你可以通过打开调用时传入的数据结构、全局变量或其他进程间通信技术与回调例程通信，但要注意，你的回调函数可能在前台进程最意想不到的中断时刻被调用。因此要避免共享像双向链表这样容易被破坏的复杂数据结构，也要避免使用互斥锁这类锁，因为这可能导致回调函数阻塞，从而丢失音频。这类技术在某些平台上甚至会导致死锁。

PortAudio 会继续调用你的回调并处理音频，直到你停止流。停止流有几种方式，但在我们这样做之前，先让流睡眠几秒钟，看看音频被处理的效果。用 Pa_Sleep() 很容易做到这一点，patests/ 目录中的许多示例正是为此使用它。注意，由于种种原因，你不能依靠此函数进行精确的定时，因此你的流运行的时间可能与你预期的不完全相同，但对我们的示例来说已经足够。

/* Sleep for several seconds. */
Pa_Sleep(NUM_SECONDS*1000);

现在我们需要停止播放。有几种方法可以做到，其中最简单的是调用 Pa_StopStream()：

err = Pa_StopStream( stream );
if( err != paNoError ) goto error;

Pa_StopStream() 的设计目标是确保你在回调中处理过的缓冲区都被播放完，这可能会带来一些延迟。另一种做法是调用 Pa_AbortStream()。在某些平台上，中止流要快得多，但可能导致回调处理过的一些数据不被播放。

停止流的另一种方法是从回调中返回 paComplete 或 paAbort。paComplete 确保最后一个缓冲区被播放，而 paAbort 会尽快停止流。如果用这种方式停止流，要再次启动流之前需要先调用 Pa_StopStream()。
