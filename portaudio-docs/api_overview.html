PortAudio API 概览

本页自顶向下概览整个 PortAudio API。它说明了所有 PortAudio 数据类型与函数如何相互配合，并给出每个函数和数据类型的文档链接。每个 API 函数和数据类型的完整详细文档都在 portaudio.h 页面中。

简介

PortAudio 在所有受支持的平台上提供统一的应用程序编程接口（API）。你可以把 PortAudio 库看作一层包装，它把对 PortAudio API 的调用转换成对平台特定原生音频 API 的调用。操作系统常常提供不止一个原生音频 API，某些 API（如 JACK）可能出现在多个目标操作系统上。PortAudio 支持每个受支持平台上的所有主流原生音频 API。下图展示了你的应用程序、PortAudio 与受支持的原生音频 API 之间的关系：

PortAudio 为原生音频 API 提供统一接口。不过它并不总能提供完全统一的功能。有些情况下 PortAudio 会受底层原生音频 API 能力的限制。例如，如果你请求的采样率不被原生音频 API 支持，PortAudio 不提供采样率转换。另一个例子是 ASIO SDK 同一时刻只允许打开一个设备，因此 PortAudio/ASIO 目前不支持同时打开多个 ASIO 设备。

核心抽象：宿主 API、设备与流

PortAudio 的处理模型包含三个主要抽象：宿主 API、音频设备与音频流。

宿主 API 代表平台特定的原生音频 API。宿主 API 的例子包括 Mac OS 上的 Core Audio、Windows 上的 WMME 与 DirectSound，以及 Linux 上的 OSS 与 ALSA。上一节的图展示了众多受支持的原生 API。有时了解自己在使用哪些宿主 API 会很有用，但完全不与宿主 API 抽象直接打交道也能轻松使用 PortAudio。

设备代表主机平台上的单个硬件音频接口或音频端口。设备有名称和某些能力，例如支持的采样率以及支持的输入和输出声道数。PortAudio 提供函数来枚举可用设备并查询设备能力。

流管理设备之间正在进行的音频输入与输出。流可以是半双工（输入或输出）或全双工（同时输入和输出）。流以特定采样率运行，并具有特定的采样格式、缓冲区大小和内部缓冲延迟。打开流时你需要指定这些参数。音频数据通过用户提供的异步回调函数，或通过调用同步读写函数，在流与你的应用程序之间传递。

PortAudio 支持多种采样格式的音频输入和输出：8、16、24 和 32 位整数格式以及 32 位浮点，与原生音频 API 支持的格式无关。PortAudio 还支持交错和非交错（每声道独立缓冲区）两种格式的多声道缓冲区，并在必要时自动执行转换。如有要求，PortAudio 可以对超出范围的采样进行钳制，和/或抖动到原生格式。

PortAudio API 提供以下功能：

  • 初始化与终止库
  • 枚举可用的宿主 API
  • 全局或在每个宿主 API 内枚举可用设备
  • 发现默认或推荐的设备与设备设置
  • 发现设备能力，例如支持的音频数据格式和采样率
  • 创建并控制音频流，从设备获取音频并向设备输出音频
  • 提供流时间信息，以支持将音频与应用程序的其他部分同步
  • 获取版本与错误信息。

下文更详细地介绍这些函数。

初始化、终止与实用函数

使用 PortAudio 库之前必须先初始化，使用完毕后终止以做清理。调用 Pa_Initialize() 初始化 PortAudio，调用 Pa_Terminate() 清理。

你可以用 Pa_GetVersion() 查询 PortAudio 的版本信息以获取数值型版本号，用 Pa_GetVersionText() 获取字符串。

由 PaSampleFormat 枚举表示的各种采样格式的字节大小可以用 Pa_GetSampleSize() 获取。

Pa_Sleep() 休眠指定的毫秒数。它并非面向生产系统使用，仅作为一种简单的可移植方式，用于在测试和示例中让主线程休眠，同时由异步回调函数采集或播放音频。

宿主 API

宿主 API 是单个原生平台音频 API 所提供的全部设备的顶层分组。每个宿主 API 都有唯一的类型标识符、名称、零个或多个设备，以及指定的默认输入和输出设备。

宿主 API 通常通过索引引用：一个 PaHostApiIndex 类型的整数，取值范围从零到 Pa_GetHostApiCount() - 1。遍历这个范围即可枚举所有可用的宿主 API。

调用 Pa_GetDefaultHostApi() 可以获取默认宿主 API 的索引。

宿主 API 的信息，例如它的名称和默认设备，存储在 PaHostApiInfo 结构体中。以宿主 API 的索引为参数调用 Pa_GetHostApiInfo()，可以获取指向某个宿主 API 的 PaHostApiInfo 结构体的指针。

大多数 PortAudio 函数通过 PaHostApiIndex 索引引用宿主 API。每个宿主 API 还有一个定义在 PaHostApiTypeId 枚举中的唯一类型标识符。你可以调用 Pa_HostApiTypeIdToHostApiIndex()，为某个 PaHostApiTypeId 获取当前的 PaHostApiIndex。

设备

设备代表某个原生音频 API 提供的音频端点。它通常对应硬件音频接口上的某个输入或输出端口，或者对应整个接口。每个宿主 API 独立运作，因此同一个物理音频端口可能通过不同宿主 API 暴露的不同设备来寻址。

设备有名称，关联到某个宿主 API，并具有受支持的最大输入和输出声道数。PortAudio 为每个设备提供推荐的默认延迟值和默认采样率。要获取更详细的设备能力信息，你可以调用 Pa_IsFormatSupported()，查询是否可以用特定设备、参数和采样率打开流。

尽管每个设备在概念上属于某个宿主 API，大多数 PortAudio 函数和数据结构都用全局的、与宿主 API 无关的 PaDeviceIndex 类型索引来引用设备 – 一个取值范围从零到 Pa_GetDeviceCount() - 1 的整数。这部分有历史原因，但这同样让应用程序可以忽略宿主 API 抽象，只与设备和流打交道。

如果要枚举属于某个宿主 API 的设备，可以在 0 到 PaHostApiInfo::deviceCount - 1 之间计数。你可以调用 Pa_HostApiDeviceIndexToDeviceIndex()，把这个宿主 API 专属的索引值转换成全局的 PaDeviceIndex 值。

设备的信息存储在 PaDeviceInfo 结构体中。以设备的索引为参数调用 Pa_GetDeviceInfo()，可以获取指向某个设备的 PaDeviceInfo 结构体的指针。

你可以用 Pa_GetDefaultInputDevice() 和 Pa_GetDefaultOutputDevice() 获取全局默认输入和输出设备的索引。每个宿主 API 的默认设备存储在该宿主 API 的 PaHostApiInfo 结构体中。

关于枚举设备并打印其能力信息的示例，参见 PortAudio 发行包 test 目录下的 pa_devs.c 程序。

流

流代表音频数据在你的应用程序与一个或多个音频设备之间的活动传输。流以特定采样率、特定采样格式和缓冲区大小运行。

I/O 方法：回调与读写

PortAudio 提供两种在已打开的流与应用程序之间传递音频数据的方法：(1) 异步回调接口，当有新的音频数据可用或需要音频数据时，PortAudio 会调用用户定义的回调函数；(2) 同步读写函数，可以以阻塞或非阻塞方式使用。打开流时你需要在两种方法之间选择。下文更详细地讨论这两种方法。

打开与关闭流

调用 Pa_OpenStream() 打开流，指定要使用的设备、输入和输出声道数、采样格式、建议的延迟值以及控制抖动、钳制和溢出处理的标志。其中许多参数需要在两个 PaStreamParameters 结构体中指定，一个用于输入，一个用于输出。如果使用回调 I/O 方法，你还要传入回调缓冲区大小、回调函数指针和用户数据指针。

设备可能是全双工（支持同时输入和输出）或半双工（支持输入或输出）– 这通常反映了底层原生音频 API 的结构。打开流时，你可以指定一个全双工设备同时用于输入和输出，或者为输入和输出指定两个不同的设备。有些宿主 API 只在配合全双工设备时才支持全双工运行（例如 ASIO），但大多数都能把两个半双工设备聚合成一个全双工流。PortAudio 要求一次 Pa_OpenStream() 调用中指定的所有设备都属于同一个宿主 API。

成功调用 Pa_OpenStream() 会创建一个指向 PaStream 的指针 – 一个代表已打开流的不透明句柄。所有作用于已打开流的 PortAudio API 函数都把指向 PaStream 的指针作为第一个参数。

PortAudio 还提供 Pa_OpenDefaultStream() – 它是 Pa_OpenStream() 的简化替代方案，当你希望用默认延迟参数打开默认音频设备时可以使用。

使用完流后，调用 Pa_CloseStream() 关闭流。

启动与停止流

新打开的流初始处于停止状态。调用 Pa_StartStream() 启动流。你可以用 Pa_StopStream() 或 Pa_AbortStream() 停止正在运行的流（Stop 函数会播放完所有内部排队的音频数据，而 Abort 则尽可能快地停止）。已打开的流可以多次启动和停止。你可以调用 Pa_IsStreamStopped() 查询流是运行中还是已停止。

调用 Pa_SetStreamFinishedCallback() 可以注册一个特殊的 PaStreamFinishedCallback，它会在流播放完所有内部排队的缓冲区后被调用。这可以与 paComplete 流回调返回值（见下文）配合使用，以避免在排队音频数据仍在播放时阻塞在对 Pa_StopStream() 的调用上。

回调 I/O 方法

所谓「回调流」通过定期调用你提供给 Pa_OpenStream() 的回调函数来运作。回调函数必须实现 PaStreamCallback 签名。每当 PortAudio 需要你的应用程序消费或产生音频数据时，PortAudio 就会调用它。回调会收到指向包含待处理音频的缓冲区的指针。这些缓冲区的格式（交错方式、采样数据类型）和大小由打开流时传给 Pa_OpenStream() 的参数决定。

流回调通常返回 paContinue，表示 PortAudio 应保持流继续运行。通过从流回调返回 paComplete 或 paAbort，可以让流变为非活动状态。这种情况下，流会在最后一个缓冲区播放完毕后（paComplete）或尽快（paAbort）进入非活动状态。你可以通过调用 Pa_IsStreamActive() 或使用 Pa_SetStreamFinishedCallback() 订阅流结束通知来检测非活动状态。注意，即使流回调返回 paComplete，仍然需要调用 Pa_StopStream() 或 Pa_AbortStream() 才能进入停止状态。

PortAudio 发行包 /tests 目录中的许多测试都实现了 PortAudio 流回调。例如参见：patest_sine.c（音频输出）、patest_record.c（音频输入）、patest_wire.c（音频直通）和 pa_fuzz.c（简单的音频效果处理）。

重要： 流回调函数经常需要以极高或实时优先级运行。因此，能够在流回调中执行的代码类型有严格限制。总体而言，这意味着要避免任何可能阻塞的代码，包括：获取锁、调用 OS API 函数（包括分配内存）。除 Pa_GetStreamCpuLoad() 之外，你不得在流回调内调用 PortAudio API 函数。

读写 I/O 方法

作为回调 I/O 方法的替代方案，PortAudio 提供同步读写接口来采集和播放音频。对于不需要尽可能最低延迟，或者不愿承担与异步回调函数同步所带来的额外复杂性的应用程序，这会很有用。从本身不支持异步回调的编程语言调用 PortAudio 时，这种 I/O 方法也很有用。

要以读写模式打开流，向 Pa_OpenStream() 传入一个 NULL 流回调函数指针。

要向流写入音频数据，调用 Pa_WriteStream()；要读取数据，调用 Pa_ReadStream()。如果内部缓冲区已满，这些函数会阻塞，因此可以安全地在紧凑循环中调用。如果想避免阻塞，你可以用 Pa_GetStreamReadAvailable() 或 Pa_GetStreamWriteAvailable() 查询可用的读或写空间量，并用返回的值限制读取或写入的数据量。

关于读写 I/O 方法的示例，参见 PortAudio 发行包 /tests 目录中的下列示例：patest_read_record.c（音频输入）、patest_write_sine.c（音频输出）、patest_read_write_wire.c（音频直通）。

获取流信息

调用 Pa_GetStreamInfo() 可以获取已打开流的信息。它返回一个 PaStreamInfo 结构体，其中包含流实际的输入和输出延迟以及采样率。这些值可能与传给 Pa_OpenStream() 的建议值不同。

使用回调流时，你可以调用 Pa_GetStreamCpuLoad() 获取回调函数占用 CPU 时间的粗略估计。

流时间信息

使用回调 I/O 方法时，流回调函数会通过一个指向 PaStreamCallbackTimeInfo 结构体的指针收到时间信息。该结构体包含当前时间，以及输入和输出缓冲区第一个采样的硬件采集与播放时间估计值。所有时间都以秒为单位，相对于某个流专属时钟。当前流时钟时间可以用 Pa_GetStreamTime() 获取。

你可以把流回调 PaStreamCallbackTimeInfo 中的时间与 Pa_GetStreamTime() 返回的时间戳结合使用，实现各种时间同步方案，例如让 GUI 显示与渲染出的音频在时间上对齐，或者在 MIDI 与音频播放之间保持同步。

错误处理

大多数 PortAudio 函数用 PaError 枚举中的值返回错误码。所有错误码都是负值。有些函数对正常结果返回大于或等于零的值，出错时返回负的错误码。

调用 Pa_GetErrorText() 可以把 PaError 错误码转换成人类可读的文本。

PortAudio 通常尝试把错误情况转换成可移植的 PaError 错误码。不过如果遇到意外错误，可能返回 paUnanticipatedHostError 错误码。这种情况下提供了进一步的机制来查询宿主 API 专属的错误信息。如果 PortAudio 返回 paUnanticipatedHostError，你可以调用 Pa_GetLastHostErrorInfo() 获取指向 PaHostErrorInfo 结构体的指针，其中提供更多信息，包括遇到错误的宿主 API、原生 API 错误码和错误文本。

宿主 API 与平台专属扩展

公开的 PortAudio API 只暴露能够在所有目标平台上提供的功能。某些情况下，各个原生音频 API 提供独特功能。部分 PortAudio 宿主 API 通过宿主 API 专属扩展暴露这些功能。例子包括访问底层缓冲和优先级参数、只使用设备的一部分声道打开流，或者访问声道名称之类的声道元数据。

宿主 API 专属扩展以额外函数和数据结构的形式提供，定义在 /include 目录下宿主 API 专属的头文件中。

传给 Pa_IsFormatSupported() 和 Pa_OpenStream() 的 PaStreamParameters 结构体有一个名为 PaStreamParameters::hostApiSpecificStreamInfo 的字段，有时用于在打开流时传递底层信息。

关于这些头文件所暴露扩展功能的细节，参见各个宿主 API 专属头文件的文档：
