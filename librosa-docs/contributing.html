参与贡献

为 librosa 做贡献的首选方式是在 GitHub 上 fork 主仓库：

  1. Fork 项目仓库： 点击页面顶部附近的 ‘Fork’ 按钮。这会在 GitHub 服务器上你的账户下创建一份代码副本。

  2. 把这份副本克隆到本地磁盘：

    git clone git@github.com:YourLogin/librosa.git

  3. 把 upstream 远程仓库设为 Librosa 的仓库：

    git remote add upstream git@github.com:librosa/librosa.git

  4. 创建一个新的 conda 环境以安装依赖：

    conda create -n librosa-dev python=3.13
conda env update -n librosa-dev --file .github/environment-ci.yml
conda activate librosa-dev
python -m pip install -e '.[tests]'

  5. 创建一个分支来存放你的修改：

    git switch -c <NAME-NEW-BRANCH>

    然后开始修改。绝不要在 main 分支上工作！

  6. 在计算机上使用 Git 做版本控制来处理这份副本。可以用下面的命令查看已修改的文件：

    git status

  7. 编辑完成后，执行：

    git add <PATH-TO-MODIFIED-FILES>
git commit -m "<COMMIT-MESSAGE>"

    把修改记录到 Git 中，然后用下面的命令推送到 GitHub：

    git push --set-upstream origin <NAME-NEW-BRANCH>

  8. 打开你所 fork 的 librosa 仓库网页， 点击 ‘Pull request’ 审阅你的修改，并添加一段说明描述你做了什么。

最后，点击 ‘Create pull request’ 把你的修改发给维护者审阅。这会向提交者发送一封邮件。

（若以上任何步骤对你来说像是魔法，请查阅网上的 Git 文档。）

提交 pull request 之前，建议检查你的贡献是否符合以下规则：

  • 所有函数都应有内容详实的 docstring，并给出示例用法。

也可以用以下工具检查常见的编程错误：

  • 代码要有良好的测试覆盖率，用下面的命令检查：

    pytest

  • 风格符合规范，用下面的命令检查：

conda install ruff
ruff check librosa

  • 确保 docstring 格式正确，用下面的命令检查：

    conda install numpydoc
numpydoc lint librosa/**.py

  • 确保任何新功能都有合法的类型标注，用下面的命令检查：

    python -m pip install mypy
python -m mypy librosa

tests/test_display.py 中的部分测试使用基准图像做输出比对。 若需要更新已有图像或添加新图像：

  1. 确保测试环境已正确配置（带插件的 pytest）

  2. 运行：

    pytest --mpl-generate-path=tmp tests/test_display.py [-k ANY_TESTS_THAT_CHANGED]

  3. 检查 tmp/ 下的新基准图像

  4. 若第（3）步的结果没问题，把它们复制到 tests/baseline_images/test_display/ 并加入 PR。

此外，有些函数需要网络访问才能正确测试。 若你新增的测试需要网络访问，请用 @pytest.mark.network 标记它们。

报告缺陷

我们用 Github issue 跟踪所有缺陷与功能请求；若你发现缺陷或希望某个功能被实现，欢迎开一个 issue。

提交之前，建议检查你的 issue 是否符合以下规则：

  • 确认你的问题目前没有被其他 issue 或 pull request 处理。

  • 请确保所有代码片段与错误信息都放在合适的代码块中。 参见 创建并高亮代码块。

  • 请附上你的操作系统类型和版本号，以及 Python、librosa、numpy 与 scipy 的版本。运行下面的代码片段即可获得这些信息：

    import platform; print(platform.platform())
import sys; print("Python", sys.version)
import numpy; print("NumPy", numpy.__version__)
import scipy; print("SciPy", scipy.__version__)
import librosa; print("librosa", librosa.__version__)

文档

你可以用任意文本编辑器编辑文档，然后在 docs/ 目录下输入 make html 生成 HTML 输出。生成的 HTML 文件会放在 _build/html/ 中，可在网页浏览器里查看。

构建文档还需要一些附加依赖。 执行下面的命令即可安装：

python -m pip install -e '.[docs]'

关于使用 AI 辅助（Copilot、Gemini、ChatGPT 等）的规定

我们不会对你的开发环境事无巨细地管理，也不要求你记录头脑风暴时用过的每个提示词或模型版本。如果你把生成式 AI 当作高级搜索引擎、结对程序员、调试棘手数学问题时对着说话的橡皮鸭，或用来编写样板工具脚本的帮手，完全可以。

我们看重的在于原则，而非行政式追踪，请在开发贡献时遵循以下几点：

1. 责任与可解释性标准

你的 Pull Request 的作者是你，而不是 AI。 若维护者问你的代码为何这样写，回答「AI 就是这么生成的」是不可接受的。你必须完全理解、能够解释，并在技术上为你提交的每一行代码负责。

2. 验证的必要性

若使用 AI 助手生成代码块、数据解析器、正则表达式或核心信号处理逻辑，请确保该方案属于能够有把握且高效地验证其正确性的类别。

3. 仓库对话中不出现 AI 生成内容

AI 在你的私人代码生成流程中受欢迎，但在我们的社区对话空间中不受欢迎。

我们（维护者）保留在生成 issue、pull request 或评论时使用自己的自动化与 AI 工具的权利。 但我们不欢迎外部以此种形式提交的 AI 贡献，因为这会给我们维护者带来大量额外处理工作。
