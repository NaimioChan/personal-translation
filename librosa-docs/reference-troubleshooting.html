故障排查

如果对如何使用 librosa 有疑问，请查看讨论论坛。 如需报告缺陷及其他更偏技术性的问题，请查看 github issues。

以下是用户最常遇到的一些问题。

no attribute ‘display’

如果你在运行某些示例代码时遇到下面的错误信息：

AttributeError: module 'librosa' has no attribute 'display'

这是因为在 0.10 之前的 librosa 版本中，需要显式导入 librosa.display 子模块。 这是因为 matplotlib 是 librosa 的可选依赖，所以我们不假定所有用户都安装了它，也不假定所有用户都需要绘图功能。

要解决这个问题，把这一行

import librosa.display

加到程序开头。

注意：自 librosa 0.10 起这已不再是问题，但写上显式的导入语句也无妨。

import librosa 长时间无响应

如果你在脚本或交互式环境中执行 import librosa，它「卡住」或无法完成，问题很可能出在 numba 正尝试为更高效的执行而编译 librosa 函数，却无法把编译后的函数写入磁盘供以后使用。 （详见 numba 缓存文档。） 如果 librosa 由管理员或超级用户安装，而普通用户（也就是你）可能没有权限在同一文件夹中写文件，就可能出现这种情况。

有两种办法解决这个问题：

  1. 以将要执行代码的同一用户身份安装 librosa，例如安装在虚拟环境中。

  2. 把 NUMBA_CACHE_DIR 环境变量改为用户确有写权限的文件夹。详见 numba 环境变量。

注意，在 librosa 0.10 及更高版本中，导入库时可能不会遇到这个问题，但执行函数时可能会遇到。 上述解决方案在两种情况下都适用。

在隔离环境中测试

Librosa 提供了一些需要联网来收集外部托管数据的函数。 这些函数的使用是可选的，但在限制网络访问的环境中运行测试套件时，它们会带来麻烦，这在打包工作流中最常见。 要在这种受限环境中运行测试套件，可以在 pytest 的命令行中指定 --librosa-isolation 参数

pytest --librosa-isolation

这会跳过已知需要联网的测试函数。测试覆盖率必然会降低，但其余测试应当仍能顺利通过。
