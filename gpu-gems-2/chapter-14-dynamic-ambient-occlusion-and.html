第 14 章　动态环境光遮蔽与间接光照

Michael Bunnell
NVIDIA Corporation

本章介绍一种计算漫反射光传输的新技术，并说明如何用它为动画场景计算全局光照。该技术在较快的 GPU 上实现后效率足够高，可以针对每个渲染帧即时计算环境光遮蔽与间接光照数据。它没有预计算辐亮度传输（PRT）或预计算环境光遮蔽技术的那些局限——后者只适用于彼此之间不发生相对运动的刚体（Sloan 2002）。图 14-1 展示了环境光遮蔽与间接光照如何增强环境光照。

我们的技术把多边形网格看作一组表面元素，它们能发射、传输或反射光，并能相互遮挡。这种方法效率高的原因在于它不计算元素之间的可见性。它改用一种基于近似遮蔽的简单得多、也快得多的技术来体现遮挡（阻挡）几何体。

14.1 表面元素

算法的第一步是把多边形数据转换成表面元素，以便容易地计算表面上一部分对另一部分的遮蔽或照明有多少。图 14-2 说明了基本概念。我们把表面元素定义为一个有朝向的圆盘，具有位置、法线和面积。元素有正面和背面。光从正面发射和反射。光从背面透射，阴影也从背面投射。我们为网格的每个顶点创建一个元素。假定顶点已经定义了位置和法线，我们只需计算每个元素的面积。顶点处的面积按共享该顶点的三角形面积的三分之一求和（四边形则取四分之一）。三边长分别为 a、b、c 的三角形面积，其海伦公式为：

我们把元素数据（位置、法线和面积）存储在纹理图中，因为我们将用片元程序（即像素着色器）完成全部环境光遮蔽计算。假定顶点位置与法线每帧都会变化，我们需要能快速改变纹理图中的值。一种选择是从一开始就把顶点数据保存在纹理图中，并用片元程序而非顶点程序完成所有动画以及从物体空间到眼睛（或世界）空间的变换。我们可以用渲染到顶点数组来生成要送入常规管线的顶点数组，然后使用一个简单的直通顶点着色器。另一种效率较低的选择是在 CPU 上做动画与变换，每帧把顶点数据加载到一张纹理里。

14.2 环境光遮蔽

环境光遮蔽是为受环境光照明的漫反射物体添加阴影的实用技术。没有阴影时，被多个方向照亮的漫反射物体看起来平淡、不真实。环境光遮蔽通过压暗对环境只有部分可见的表面来提供软阴影。它要计算可及度值，即每个表面点上方半球中未被几何体遮挡的比例（Landis 2002）。除可及度之外，计算遮蔽最少的方向也很有用，通常称为弯曲法线。给表面着色时用弯曲法线代替常规法线，可以得到更准确的环境光照。

我们可以把每个元素的可及度值计算为 1 减去其他所有元素对该元素的遮蔽量。我们把被遮蔽的元素称为接收者，把投射阴影的元素称为发射者。我们用基于有朝向圆盘立体角的近似来计算发射者元素对接收者元素的遮蔽量。设 A 为发射者的面积，则遮蔽量可近似为：

如图 14-3 所示，E 是发射者法线与从发射者指向接收者的向量之间的夹角。R 是接收者元素对应的夹角。圆盘立体角公式中加入 max(1, 4 x cos R ) 项，以忽略不位于接收者上方半球内的发射者，同时不对位于地平线附近的元素造成渲染瑕疵。

下面是近似计算元素间遮蔽的片元程序函数：

float ElementShadow(float3 v, float rSquared, float3 receiverNormal,
                    float3 emitterNormal, float emitterArea)
{
  // 我们假设 emitterArea 已经除以 PI
  return (1 - rsqrt(emitterArea / rSquared + 1)) *
         saturate(dot(emitterNormal, v)) * saturate(4 * dot(receiverNormal, v));
}

14.2.1 多遍遮蔽算法

我们分两遍计算可及度值。第一遍中，我们把其他每个元素所张开的半球份额相加，再从 1 中减去，以此近似每个元素的可及度。第一遍之后，有些元素通常会太暗，因为处于阴影中的其他元素本身也在投射阴影。于是我们用第二遍做同样的计算，但这次把每个形状因子乘以发射者元素在上一遍中的可及度。效果是处于阴影中的元素对其他元素的遮蔽变少，如图 14-4 所示。第二遍之后，我们消除了任何重复遮蔽。不过被三重以上遮蔽的表面会变得太亮。我们可以用更多遍得到更好的近似，也可以用第一遍与第二遍合并结果的加权平均来近似同样的答案。图 14-5 给出每一遍之后的结果，以及与光线追踪解法的对比。弯曲法线在第二遍中计算。我们先求元素之间归一化向量与形状因子的乘积，再从原元素法线中减去该结果，得到弯曲法线。

我们通过渲染单个四边形（或两个三角形）来计算遮蔽结果，使每个表面元素对应渲染一个像素。着色器计算每个元素接收到的遮蔽量，并把它写成像素颜色的 alpha 分量。结果渲染到一张纹理图，这样第二遍可以用另一次渲染完成。这一遍中计算弯曲法线，并把它写成颜色的 RGB 值，同时把新的阴影值写入 alpha 分量。

14.2.2 提升性能

即使元素间的遮蔽计算非常快（一块 GeForce 6800 每秒能做 1.5 亿次这样的计算），我们仍需改进算法，才能在实时下处理数千个以上的元素。我们可以对远处表面使用简化几何体来减少工作量。这对漫反射光照环境很有效，因为阴影非常软，远处几何体细节投射的阴影看不见。幸运的是，由于我们的技术并不使用多边形本身，我们可以创建表示简化几何体的表面元素，而不需要另做多边形模型。我们只需把原网格中顶点相邻的元素分组，用一个更大的元素表示它们。对更大的元素也可以这样做，形成元素更少、尺寸更大的层级结构。这样，我们渲染每个像素时不再遍历每一个元素，而是遍历元素的层级结构。如果接收者元素离发射者足够远——比如达到发射者半径的四倍——我们就用它来计算。只有当接收者靠近某个发射者时，才需要遍历它的子节点（如果有）。见图 14-6。以这种方式遍历层级结构，实践中可以把算法性能从 O(n 2) 提升到 O(n log n)。图 14-7 的图表表明，随着层级结构中顶点数增加，每个顶点的性能保持稳定。

我们用在层级结构中直接位于其下的子元素来计算父元素的数据。父元素的位置与法线由其子元素的位置与法线取平均得到。面积则取子元素面积之和。我们可以用一个着色器完成这些计算：对层级结构的每一层执行一遍该着色器，把值从叶节点向上传播。也可以用同样的技术对后续遍所需的遮蔽遍结果取平均，或者干脆把父节点与子节点同样对待，省去取平均这一步。值得注意的是，多数动画元素的面积变化很小、甚至不变，即使是非刚体对象也是如此；因此面积不必每帧重新计算。

环境光遮蔽片元着色器见代码清单 14-1。

示例 14-1. 环境光遮蔽着色器

float4 AmbientOcclusion(float4 position
                        : WPOS, float4 normOffset
                        : TEX1, uniform samplerRECT lastResultMap
                        : TEXUNIT0, uniform samplerRECT positionMap
                        : TEXUNIT1, uniform samplerRECT elementNormalMap
                        : TEXUNIT2, uniform samplerRECT indexMap
                        : TEXUNIT3)
    : COL
{
  float eArea;
  // 发光体面积
  float4 ePosition; // 发光体位置
  float4 eNormal;
  // 发光体法线
  float3 rPosition = texRECT(positionMap, position.xy).xyz;
  float3 rNormal = texRECT(elementNormalMap, position.xy).xyz;
  float3 v;
  // 从接收点到发光体的向量
  float total = 0;
  // 用来计算可达性
  float4 eIndex = float2(0.5, 0.5); // 当前发光体的索引
  float3 bentNormal = rNormal;
  // 用接收点法线初始化
  float value;
  float d2;
  // 接收点到发光体距离的平方
  while (emitterIndex.x != 0)
  { // 遍历尚未结束时循环
    ePosition = texRECT(positionMap, emitterIndex.xy);
    eNormal = texRECT(elementNormalMap, emitterIndex.xy);
    eArea = emitterNormal.w;
    eIndex = texRECT(indexMap, emitterIndex.xy); // 取下一个索引
    v = ePosition.xyz - rPosition;
    // 指向发光体的向量
    d2 = dot(v, v) + 1e - 16;
    // 计算距离平方，避免为 0
    // 接收点是否靠近父元素？
    if (d2 < -4 * emitterArea)
    {
      // （父元素面积为负）
      eIndex.xy = eIndex.zw;
      // 沿层次向下
      emitterArea = 0;
      // 忽略此元素
    }
    v *= rsqrt(d2);
    // 对 v 归一化
    value = SolidAngle(v, d2, rNormal, eNormal.xyz, abs(eArea)) *
            texRECT(resultMap, position.xy).w; // 以上一次的结果调制
    bentNormal -= value * v;
    // 更新弯曲法线
    total += value;
  }
  if (!lastPass)
    // 只有最后一趟才需要弯曲法线
    return saturate(1 - total); // 只返回可达性
  else
    return float4(normalize(bentNormal), 1 Ð total);
}

14.3 间接光照与面光源

通过加入由漫反射表面反射光所形成的间接光照，我们可以给渲染图像再加一层真实感（Tabellion 2004）。用环境光遮蔽着色器的一处小改动，就能加入单次反弹的间接光。我们把立体角函数换成圆盘对圆盘的辐亮度传输函数。我们用着色器的一遍来传输反射光或发射光，用两遍来对光做阴影。

对于间接光照，首先要计算每个表面元素正面反射的光量。如果反射光来自环境光照，我们先计算环境光遮蔽数据，再用它计算到达每个顶点的环境光。如果使用点光源或平行光的直接光照，我们就按给表面着色的方式计算每个元素处的光，包括阴影贴图。也可以同时做环境光照与直接光照，把两个结果相加。然后把光值乘以表面元素的颜色，使红色表面反射红光、黄色表面反射黄光，依此类推。面光源的处理与反射光的漫反射表面相同，只是它们被初始化为一个要发射的光值。

下面是计算元素间辐亮度传输的片元程序函数：

float FormFactor(float3 v, float d2, float3 receiverNormal,
                 float3 emitterNormal, float emitterArea)
{
  // 假定 emitterArea 已除以 PI
  return emitterArea * saturate(dot(emitterNormal, v)) *
         saturate(dot(receiverNormal, v)) / (d2 + emitterArea);
}

公式 14-2 圆盘对圆盘形状因子近似

我们用公式 14-2 给出的圆盘对圆盘形状因子的几何项来计算从一个表面元素传输到另一个表面元素的光量。我们略去可见性因子，该因子考虑遮挡（阻挡）几何体。取而代之的是像计算环境光遮蔽时那样的遮蔽技术——只不过这次用的是传输光时所用的同一个形状因子。此外，我们把遮蔽元素的形状因子乘以三分量的光值，而不是单分量的可及度值。

现在我们运行一遍辐亮度传输着色器，计算出能到达任一元素的最大反射光或发射光量。然后运行一遍阴影遍，根据到达遮蔽元素的光量，从每个元素的总光量中减去相应部分。与环境光遮蔽一样，我们可以再运行一遍，通过消除重复遮蔽来改善光照。图 14-8 展示一个同时受直接光照以及一次、两次间接光反弹照明的场景。

14.4 结论

环境光遮蔽与间接光照这类全局光照技术能极大提升漫反射表面的渲染质量。我们提出了一种用 GPU 计算漫反射表面光传输的新技术。该技术适用于在带可变形几何体的动态场景中实现各种全局光照效果。
