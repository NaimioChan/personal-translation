第 24 章　用查找表加速颜色变换

Jeremy Selan
Sony Pictures Imageworks

在电影视觉特效制作中，让高质量色彩操作保持交互式反馈，对美术极为有益。在消费端，让视频与渲染图像流实现实时色彩校正，正成为塑造媒介主题「外观」日益有用的工具。然而把多个复杂色彩变换直接施加到高分辨率影像上，超出了现代图形硬件的实时能力。

本章提出一种利用三维查找表对高分辨率影像做实时色彩处理的算法。我们的做法性能特点很好，既不受所施加色彩算子数量的影响，也不受底层色彩变换复杂度的影响。本章介绍的技术及其变体已在众多电影的制作中成功使用，应当视为「可用于生产」。

24.1 查找表基础

查找表（LUT）是一种极佳的技术，用于优化那些计算昂贵、缓存便宜的函数求值。把函数在常见输入域上的求值预先算好，昂贵的运行时操作就能用廉价的查表替代。如果查表比从头计算更快（或者函数会被反复以同一输入查询），使用查找表就能带来显著的性能提升。[1] 对落在表样本之间的数据请求，插值算法可以对邻近样本取平均，给出合理的近似。

24.1.1 一维 LUT

查找表的特征在于其维数，即索引一个输出值所需的索引个数。最简单的 LUT 由单个变量索引，因而称为一维（或 1D）LUT。

恒等查找表定义为在给定域上把输入索引映射回自身的变换，如图 24-1 所示。

一维 LUT 在图像处理中早已被使用，最常见的形式是显示器的伽马表。这类表通常用三个 LUT——每个颜色通道一个——在图像到达显示器之前以计算高效的方式修改像素强度。

考虑一个施加在 8 位灰度图像上的解析色彩算子 f(x)。朴素实现是遍历图像，对每个像素求该函数值。不过可以注意到，无论函数多复杂，它的结果只能是 255 个输出值之一（对应每个唯一输入）。因此另一种实现是把函数对每个可能输入值的结果列成表，运行时每个像素通过查已存的解来变换。假设整数查表是高效的（确实如此），且光栅化后的图像总像素数超过 255（很可能如此），那么用 LUT 会带来显著加速。

所有能参数化为单个输入变量的色彩算子都能用一维 LUT 加速，包括亮度、伽马和对比度算子。见图 24-2。给每个颜色通道各分配一个一维 LUT，我们就能实现更复杂的操作，例如色彩平衡。熟悉 Photoshop 图像处理软件的人会知道，所有「曲线」与「色阶」操作都能用一维 LUT 加速。

一维 LUT 的局限

可惜许多有用的色彩算子无法参数化为单个变量，因而无法用一维 LUT 实现。例如把彩色像素转换为灰度等价的「亮度算子」。由于每个输出值都是三个输入通道的加权平均，很难用一维 LUT 表达这样的算子。其他依赖这种通道「串扰」的算子同样无法表达。

24.1.2 三维 LUT

三维查找表为一维 LUT 的固有局限提供了显而易见的解法，允许用三个独立参数索引表数据，如图 24-3 所示。

一维 LUT 每轴采样 4 个位置只需 4 个元素，对应的三维 LUT 则需要 43 = 64 个元素。要当心这种维数增加；三维 LUT 的规模随其线性采样率增长得非常快。[2] 由于 LUT 尺寸更小，高质量插值对三维 LUT 比对一维领域更重要——在一维领域里简单的插值器往往就够用。

复杂色彩算子可以用三维 LUT 表达，因为它允许完全任意的输入输出映射。正因如此，三维 LUT 早已被色度学界采用，是色域映射中的首选工具之一（Kang 1997）。事实上，ICC 色彩配置文件中就用三维 LUT 来建模精确复现彩色图像所需的复杂设备行为（ICC 2004）。

大多数色彩算子都能用三维 LUT 表达。简单算子（如伽马、亮度、对比度）编码起来很轻松。色相与饱和度修改这类更复杂的变换同样可行。最重要的是，专业调色系统典型的色彩操作也能表达（例如对用户指定的一段色域做独立扭曲）。见图 24-4。

三维 LUT 的局限

可惜在现实场景中，并非所有色彩变换都能定义为直接的输入输出映射。一般情况下，三维 LUT 只能表达符合以下特征的变换：

  • 像素的计算必须与它在图像中的空间位置无关。受邻近值影响的色彩算子，例如贝叶斯抠像（Chuang et al. 2001）或垃圾遮罩（Brinkman 1999），无法以查找表形式表达。
  • 色彩变换必须相当连续，因为稀疏采样的数据集不适合表示不连续的变换。如果在采样得到的变换网格上做平滑插值会得到不可接受的结果，那么查找表就不是合适的加速技术。
  • 输入色彩空间必须落在定义良好的域内。一个「解析」定义的亮度算子可以在整个实数域上产生有效结果。然而把同一算子烘焙进查找表后，它只在有限域内有效（例如可能只在 [0,1] 范围内）。24.2.4 节讨论缓解这一问题的办法。

24.1.3 插值

插值算法让查找表在被查询样本点之间的值时也能给出结果。最简单的方法是最近邻插值，即找到并返回最近的表项。这个方法虽快（只需一次查表），但结果通常不连续，因而在图像处理中很少使用。

更进一步的插值算法是在两个相邻样本之间计算加权平均（一维 LUT 的情形），权重取决于样本到邻居的相对距离。这称为线性插值，结果比最近邻方案平滑得多。

线性插值通过沿三个轴依次施加一维线性插值来适配三维数据集（因而称为三线性插值）。这一算法依据包围立方体八个角的加权平均生成中间结果，通常足以用于色彩处理，并在图形硬件中普遍实现。更高阶的插值函数在重建函数中使用越来越多的样本，代价是计算量显著增加。（直接的三次插值需要 33 = 27 次纹理查找，但参见本书第 20 章「快速三阶纹理滤波」，其中有一种把查找次数减到 8 次的技术。）

24.2 实现

我们的做法基于这样一个假设：对三维纹理做三线性插值的代价很低。这在软件实现中显然不成立，但我们可以借助现代 GPU 的三维纹理能力，把它当作色彩校正引擎。

24.2.1 把 LUT 映射到 GPU 的策略

大多数现代 GPU 都提供硬件加速的三线性三维纹理查找（这个插值单元最初是为带 mipmap 的二维纹理查找而必需的）；因此我们的算法实现起来相当简单。

首先，把高分辨率图像载入一张标准二维纹理。接着，把我们的三维色彩校正映射作为三维纹理载入，注意要启用三线性滤波（在 OpenGL 中这需要把纹理放大滤波设为 GL_LINEAR）。

运行时，我们以常规方式采样颜色来变换输入图像，然后对三维纹理做一次相关纹理查找（把二维纹理查找的结果作为三维纹理的输入索引）。三维纹理的输出就是经色彩变换的最终结果。

24.2.2 Cg 着色器

代码清单 24-1 中的片元着色器代码几乎和你预期的一样简单。这一做法的效率一眼可见：整个色彩校正过程被缩减为一次（三维）纹理查找。

示例 24-1. 执行三维纹理查找的片元着色器

void main(in float2 sUV
          : TEXCOORD0, out half4 cOut
          : COLOR0, const uniform samplerRECT imagePlane,
            const uniform sampler3D lut, const uniform float3 lutSize)
{
  // 取图像颜色
  half3 rawColor = texRECT(imagePlane, sUV).rgb;
  // 计算 3D LUT 查找的缩放/偏移因子
  half3 scale = (lutSize - 1.0) / lutSize;
  half3 offset = 1.0 / (2.0 * lutSize);
  // ****** 应用 3D LUT 颜色变换！**************
  // 这就是我们的相关纹理读取；3D 纹理的
  // 查找坐标依赖于
  // 上一次纹理读取的结果
  cOut.rgb = tex3D(lut, scale * rawColor + offset);
}

着色器分析

最常见的问题大概是「为什么需要缩放和偏移因子？」答案与纹理映射硬件从我们的 LUT 采样时所用的坐标系有关。具体来说，硬件纹理采样算法默认从数据集的一端采样到另一端。这对图像数据贴图完全合理，但对数值数据集的采样并不合适，因为它会在纹理边缘附近引入非线性，如图 24-5 所示。因此，要正确插值我们的「数据」图像，只能查询外侧样本中心之间的区域，按下式：

调整后的采样坐标 = (lutSize - 1.0)/lutSize x oldCoord + 1.0/(2.0 x lutSize)

可以注意到，LUT 尺寸增大时校正因子变得可以忽略。例如 4,096 项的查找表（常见的一维 LUT 尺寸），缩放因子可以放心忽略，因为误差小于 half 像素格式的精度。然而对三维 LUT 常见的小网格尺寸，这一影响在视觉上很显著，不能忽略；在 32x32x32 的 LUT 上，未校正的 8 位缩放误差相当于把所有 [4..251] 之外的数据都钳制掉！

着色器优化

这段代码有明显的加速空间。首先，缩放与偏移因子在整幅图像上恒定，可以只算一次并以常量传入。（更好的做法是直接编译进片元着色器。）其次，使用满足需求的最小 LUT（但不要再小）是好习惯。对「一次调色」类色彩校正——只修改原色（RGB）与间色（CMY）的颜色——2x2x2 的表就够用！最后，对消费级应用，整数纹理格式可能就够（当然仍要启用三线性插值）。但要注意 8 位不足以防止 LUT 色彩变换中出现条带（Blinn 1998）。

24.2.3 系统集成

到目前为止我们还没讲如何生成三维 LUT——这是有理由的。把三维恒等查找表当作最终校正的二维代理图像来处理，就完全不需要专用软件！只需把这张三维 LUT「图像」走一遍任意色彩校正流程，最后一步用在得到的 LUT 数据集在 GPU 上扭曲高分辨率影像。见图 24-6。事实上，可以接连施加任意多个色彩算子（只要它们满足 24.1.2 节列出的要求）。还有一个值得注意的地方：由于我们的三维 LUT「图像」通常很小（32x32x32 的 LUT 相当于 256x128 像素），你可以求值复杂的色彩变换，而仍能期待交互级性能。

我们把三维 LUT 加速框架总结如下：

  1. 把三维网格生成（并缓存）为二维图像，最好采用与第 3 步中 GPU 所期望相同的字节序。
  2. 对这张网格图像施加任意色彩校正（用标准的色彩校正管线），把三维网格图像当作你最终想要施加的色彩校正的代理。
  3. 把高分辨率图像和三维纹理都载入 GPU。
  4. 用代码清单 24-1 的片元着色器绘制源影像。

这一优化的潜在提速非常可观。在我们的经验中，常常可以用仅仅 32x32x32（256x128 像素）的网格替代完整的图像处理（2048x1556 像素）。假设施加 LUT 的开销很低（在现代硬件上确实如此），这相当于约 100 倍的提速！此外在视频播放应用中，LUT 变换不必重新计算，可以几乎零成本地施加到后续每一帧。

24.2.4 扩展三维 LUT 以用于高动态范围影像

高动态范围（HDR）数据打破了我们使用查找表的一个主要假设，即输入域有限。

钳制

如果不先定义表的边界，我们就无法把色彩变换做成表格形式。因此必须为查找表选择要表示的最小值和最大值。微妙之处在于：如果最大值定得太低，就会不必要地钳制数据；而如果最大值定得太高，又会不必要地浪费表的精度。（也就是说，我们的 LUT 采样将不足以重现除最平滑者以外的任何色彩变换。）

把色彩空间的最小值定义为小于零偶尔是有用的，特别是当色彩渲染可能产生色域外颜色，或者施加了带负波瓣的滤波器时。不过对大多数用户来说，变换下限可以放心地钉在零。

选色彩空间的上限不太难，因为 HDR 空间很少完全没有约束。[3] 多数情况下，即便是定义为「高动态」（像素值大于一）的色彩空间，也往往因其他原因而有可执行的上限。例如在直接由 Cineon（对数）负片规范导出的线性色彩空间中（Kennel and Snider 1993），定义的最大值约为 13.5。[4] 即便在并不直接与胶片密度挂钩的色彩空间中，允许完全不受约束的高光也会严重破坏滤波器核尺寸。多数实际合成场景中确实存在合理的最大值——了解你的数据集，做出最好的判断。

非均匀采样的网格

为要采样的范围选定上下限之后，还有样本分布的问题。假设上限设为像素值 100.0。对 32x32x32 的 LUT 把这个范围等分成采样区域，单元大小约为 3。假设采用合理的曝光变换，几乎所有在感知上重要的结果都会被压缩进最低的几个单元，浪费掉大部分数据集。

因此我们希望把样本放在视觉上最重要的位置，这些位置通常更靠近色域的暗端。做法是用一对匹配的一维「整形」LUT 包裹我们的三维查找表变换，如图 24-7 所示。理想的整形 LUT 把输入 HDR 色彩空间映射到归一化的、感知均匀的色彩空间。[5] 然后照常施加三维 LUT（不过在计算它时必须把这一维变换考虑进去）。最后，图像经原始一维 LUT 的逆映射，「解开」像素数据回到它们原本的动态范围。

24.3 结论

我们给出了一个可直接用于制作的算法，能对高分辨率影像做实时颜色处理，在常见应用中加速 100 倍以上。该技术与所施加的颜色算子数量无关，也与底层颜色变换的复杂程度无关。我们希望这些思路能让实时而精细的颜色校正变得更常见，无论是在视觉特效行业还是在消费类应用中。
