第 23 章　Nalu 演示中的头发动画与渲染

Hubert Nguyen
NVIDIA Corporation

William Donnelly
NVIDIA Corporation

为 GeForce 6800 发布制作 Nalu 演示时，我们面对的最大技术挑战是实时渲染逼真的头发。此前 NVIDIA 演示角色 Dawn 和 Dusk 也有头发，但短、暗且静止。对 Nalu，我们定下的目标是在水下渲染长而金黄、飘逸的头发。本章介绍我们为实时达成这一目标所用的技术，包括模拟头发运动的系统、计算头发自遮挡的阴影算法，以及模拟光线穿过单根发丝散射的反射率模型。这些要素结合起来，实时产生了极其逼真的头发图像。图 23-1 是一个例子。

Nalu 头发着色的幕后，有一个系统负责生成头发几何体，并在每帧控制动力学与碰撞。它基本上分成两部分：几何体生成，以及动力学／碰撞计算。

头发由 4,095 根独立发丝组成，用线图元渲染。仅头发渲染我们就用了 123,000 个顶点。把所有这些顶点都送进动力学与碰撞检测会慢得无法接受，所以我们用控制发丝：Nalu 的发型可以由几百根发丝这一小得多的集合来描述和控制，尽管渲染需要数千根。所有昂贵的动力学计算只施加在这些控制发丝上。

我们既没有时间也没有工具去手工为控制发丝结构做动画。即便有工具，手工为这么多控制发丝做动画也非常困难。要让头发看起来可信，需要大量细微的次级运动。见图 23-2。基于物理的动画帮了大忙。

当然，引入过程化动画后，对头发运动的控制会失去一部分（在我们的情形中意味着失去 90% 的控制）。碰撞检测与响应可能引入不希望的头发行为，妨碍创作性的动画。我们的动画师很好地理解了动力学的内部运作，想出了一些变通办法。工程侧又加了几个工具，把剩下的 10% 人工控制权拿回来。

23.1 头发几何体

23.1.1 布局与生长

控制发丝结构用来粗略描述发型。我们在 Maya 中建了一个专用几何体表示「头皮」（渲染时不可见），从它上面「种出」控制发丝。每根控制发丝从头皮的一个顶点沿法线长出，如图 23-3 所示。生长过程 100% 是过程化的。

23.1.2 控制头发

有了控制发丝集合之后，我们对它们施加物理、动力学与碰撞计算，以过程化方式为头发做动画。在这个演示中，运动几乎完全依赖动力学。这样的系统看似有吸引力，但有人工可控的系统要好得多。当我们想把动画做得更有戏剧性时，需要能够「伪造」或「修正」头发的行为。此外，我们的头发动力学不够逼真，在某些情形下无法像真发那样运动。有更好的人工控制就能让运动更令人信服。

23.1.3 数据流

由于头发完全动态、每帧都在变化，我们需要每帧重建最终用于渲染的头发集合。图 23-4 展示了数据在流程中如何流动。做动画的控制发丝被转换成 Bezier 曲线并剖分，得到平滑的线条。随后对平滑后的线条做插值，以提高头发密度。插值得到的头发集合送入引擎，用于最终帧渲染。我们用动态顶点缓冲存放顶点数据。

23.1.4 剖分

头发剖分过程就是通过增加顶点把每根控制发丝变平滑。我们把顶点数增加五倍以上，从 7 个增加到 36 个。见图 23-5 与 23-6。

为计算新顶点的位置，我们把控制发丝转换成 Bezier 曲线：计算它们的切线（每帧都算），再用切线算出 Bezier 控制点。由 Bezier 曲线计算为平滑控制发丝而引入的额外顶点的位置。

平滑后的控制发丝会通过插值复制，生成一整套密集的头发，准备好用于最终渲染。

23.1.5 插值

插值头发利用头皮网格的拓扑来生成。见图 23-7。每个三角形的三个顶点处各有一根平滑后的控制发丝（以绿色显示）。我们想用头发填满三角形表面内部，于是对三根控制发丝的坐标做插值，生成新的平滑头发（以灰色显示）。平滑控制发丝与平滑插值发丝的顶点数相同。

为了用头发填满每个三角形，我们用重心坐标生成新的插值头发。例如图 23-7 中的插值头发 Y 由三个重心系数（b A , bB , bC ）计算，其中 bA + b B + b C = 1：

即 Y = A x bA + B x bB + C x bC 。

在 [0..1] 内生成两个随机值，若两者之和大于 1 就取 1 减去其中较大者，再把第三个设为 1 减去前两者，使三者之和为 1，这样就能确定长出所需头发密度的位置。

23.2 动力学与碰撞

Nalu 的头发动力学基于粒子系统，如图 23-3b 所示。每个未插值的控制发丝顶点都作为一个粒子做动画。粒子沿一根发丝并非均匀分布。控制发丝中的分段随离头骨越远而越长。这样可以在不增加太多顶点的前提下让头发更长。

本项目我们选用 Verlet 积分计算粒子运动，因为它往往比欧拉积分更稳定，又比 Runge-Kutta 积分简单得多。原理超出本章范围，若想进一步了解在游戏中使用 Verlet 积分的各种方式，见 Jakobsen 2003。

23.2.1 约束

粒子运动过程中，控制发丝的长度必须保持不变，以免被拉伸。为此我们在同一根控制发丝内的粒子之间使用约束。约束使靠得过近的粒子相互排斥，使离得过远的粒子收缩分段。当然，拉动一个粒子会让相邻分段的长度失效，所以这些修改需要迭代施加。经过若干次迭代，系统收敛到所需结果。见图 23-8。

23.2.2 碰撞

我们尝试了许多碰撞检测技术。需要让过程既简单又快。对这个演示，一套球体组成的骨架（rig）效果不错，而且最容易实现。见图 23-9。

起初这个方案没有按计划奏效，因为有些发丝分段比碰撞球体还大。由于我们做的是「点对球」的碰撞，没有什么能阻止发丝的两个端点穿进球体。

为防止这种情况，我们在控制发丝的碰撞数据中引入了「珍珠配置」，如图 23-10 所示。每个球体不再与一个点碰撞，而是与定位在粒子上的另一个球体碰撞。

我们也尝试过检测分段与球体之间的碰撞。这不太难，但不如用「珍珠」快。我们的边碰撞检测效果尚可，但存在稳定性问题，可能是碰撞响应代码所致。不管怎样，我们有了一个对本项目足够好用的方案。

23.2.3 鳍

美人鱼最初的构想里包含又长又软的鳍，我们认为这是角色的关键特征。我们建了实体鳍并蒙皮到骨架上。然而在 Maya 中做动画时，鳍只是跟着身体动，看起来相当僵硬。图 23-11 可以看到我们的意思。

幸运的是，我们的头发动力学代码也能用来做布料仿真。于是在实时引擎中，我们计算一次布料仿真，把布料结果混合到蒙皮几何体上。我们绘制了一张权重图来定义混入多少物理效果。物理效果用得越多，鳍看起来越软。反过来，混合更多蒙皮会得到更刚硬的动作。我们希望鳍的根部比尖端更刚硬，而权重图正好能做到这一点，因为我们可以为每个布料顶点精确绘制想要的物理与蒙皮比例。见图 23-12。最终这一组合让我们做出了柔软逼真的鳍，如图 23-13 所示。

23.3 头发着色

头发着色问题可以分成两部分：头发的局部反射率模型，以及计算发丝间自遮挡的方法。

23.3.1 头发的实时反射率模型

局部反射率模型我们选了 Marschner 等人 2003 提出的模型。选它是因为它对头发反射率的描述全面且基于物理。

Marschner 反射率模型可以表述为一个四维双向散射函数：

S( i , i ; o , o ),

其中 i ∊ [– /2, /2] 与 i ∊ [0, 2] 是输入方向的极坐标， o ∊ [– /2, /2] 与 o ∊ [0, 2] 是光线方向的极坐标。[1] 函数 S 完整描述了发丝如何散射和反射光线；只要能对这个函数求值，我们就能算出任意光源位置下表面的着色。

由于 S 求值昂贵，我们希望避免逐像素计算它。一个可行方案是把 S 存进查找表，运行时读表。这张查找表可以编码进纹理，从而能由像素着色器访问。

可惜函数 S 有四个参数，而 GPU 原生不支持四维纹理。这意味着我们需要某种方案，把四维函数编码到二维纹理中。幸运的是，只要查表方式得当，我们只用少量二维贴图就能编码完整的四维函数。

Marschner 反射率模型

Marschner 模型把每根发丝当作半透明圆柱，考虑光线穿过头发可能走的路径。它考虑三类路径，在路径记号中各有不同标注。路径记号把每条光路表示为一串字符，每个字符代表光线与表面之间的一种交互。R 路径表示从发丝表面反射向观察者的光。TT 路径表示折射进头发再折射出去、射向观察者的光。TRT 路径表示折射进发丝、在内表面反射、再折射出去射向观察者的光。每种情形中，「R」代表光反射，「T」代表光线透射（或折射）穿过表面。

Marschner 等人（2003）指出，这些路径各自贡献了头发反射率中独特且在视觉上重要的方面，使真实感达到此前头发反射率模型无法企及的程度。图 23-14 画出对头发外观贡献最大的三条反射路径。

于是可以把反射率模型写成：

S = SR + STT + STRT .

每一项 SP 可以进一步分解为两个函数的乘积。函数 MP 描述 角对反射率的影响。另一个函数 NP 刻画 方向上的反射。若假设发丝是完美圆形，我们就可以用更少的角把 M 和 N 都写出来。定义次级角 d = ½( i – o ) 与 d = i – o 之后，上式每一项可以写成：

Sp = Mp ( i , o ) x Np ( d , d )，对 P = R, TT, TRT。

从这种形式可以看出，M 与 N 都只是两个参数的函数。这意味着我们可以为每个函数算一张查找表，编码进二维纹理。二维纹理很理想，因为 GPU 针对二维纹理做了优化。我们还可以利用 GPU 的插值与 mipmap 功能来消除着色器走样。[2]

虽然我们要存六个函数，但其中许多是单通道的，可以放在同一张纹理里。M R、MTT 与 MTRT 各自只有一个通道，因此打包进第一张查找纹理。NR 是单通道，而 NTT 与 NTRT 各有三个通道。我们把 NTT 与 NR 一起存进第二张查找纹理。为提高性能、减少演示中的纹理占用，我们做了一个简化假设：M TT ( i , o ) = M TRT ( i , o )。这让我们能把 NTT 与 NTRT 存进同一张纹理，并把纹理数从三张减到两张。见图 23-15 与 23-16。

虽然模型以角度表述，但由向量计算这些角度需要反三角函数。这类函数昂贵，我们希望能避开。于是不把 i 与 o 传进第一次查表，我们改为计算正弦：

sin i = (light · Tangent),

sin o = (eye · Tangent).

然后就可以把 M 表示为 sin i 与 sin o 的函数，在着色器里省掉一些运算。

再多做一点工作，我们也能算出 cos d 。先把观察向量与光线向量投影到垂直于头发的平面上，如下：

lightPerp = light – (light · tangent) x tangent,

eyePerp = eye – (eye · tangent) x tangent.

然后由公式

(lightPerp · eyePerp) = ||lightPerp|| x ||eyePerp|| x cos d ,

可以如下计算 cos d ：

cos d

=

(eyePerp · lightPerp) x

((eyePerp · eyePerp) x (lightPerp · lightPerp))-0.5。

剩下要算的角只有 d 。为此注意到 d 是 i 与 o 的函数。由于我们已经在用以 i 与 o 索引的查找表，可以给查找表再加一个通道来存 d 。

代码清单 23-1 用伪代码简要总结了我们的着色器。

在我们的实现中，查找表在 CPU 上计算。我们用了每分量 8 位格式的 128 x 128 纹理。8 位格式要求把数值缩放到 [0..1] 范围。结果我们不得不在着色器里再加一个缩放因子，以平衡各项的相对强度。若需要更高精度，可以跳过这一步，改用 16 位浮点纹理存放查找表。我们发现对本项目的用途没必要。

要真正算出这些查找表中的一张，我们得写程序对函数 M 与 N 求值。这两个函数太复杂，无法在此列出；Marschner 等人 2003 给出了完整描述与推导。

实体几何体

虽然我们把这个头发反射率模型用于渲染以线条带表示的头发，它也能扩展到以实体几何体表示的头发。不用线条带的切线，我们可以用表面的某个主切线。最后还必须考虑表面的自遮蔽。做法是再乘一项 (wrap + dot(N, L)) / (1 + wrap)，其中 dot(N, L) 是法线与光线向量的点积，wrap 是 0 到 1 之间的值，控制光照被允许绕模型「包裹」多远。这是一个用于模拟光透过头发渗出的简单近似（Green 2004）。

23.3.2 头发中的实时光照体积阴影

实时应用中的阴影通常用两种方法之一计算：模板阴影体或阴影贴图。可惜这两种技术用于计算头发上的阴影都不理想。头发所用几何体的绝对数量会让模板阴影体难以处理，而阴影贴图在头发这类高度细节化的几何体上会出现严重走样。

我们改用了一种专为渲染头发阴影设计的阴影渲染方法。不透明度阴影贴图把阴影贴图扩展到能处理体积对象并支持抗锯齿（Kim and Neumann 2001）。不透明度阴影贴图最初在 GeForce 2 级硬件上实现，那时可编程性的灵活程度远不如现在的 GPU。最初的实现在大数据集上达不到实时性能，而且算法的很大一部分要在 CPU 上运行。GeForce 6 系列硬件的可编程性足以让我们在 GPU 上执行算法的大部分。这样即使头发数据集很大，我们也能达到实时性能。

一个更新后的实现

朴素的做法是把 (x, y, z i ) 存进 16 张纹理。这将需要渲染 16 次才能生成完整的不透明度阴影贴图。第一个观察是：存 只需要 1 个通道，所以我们可以把最多 4 个 sigma 值打包进一张 4 通道纹理，并一次同时渲染到它们。用这个方案，我们可以把渲染趟数从 16 减到 4。

不过如果使用多渲染目标（MRT），我们能做得比 4 趟更好。MRT 是一项允许同时渲染到最多 4 张不同纹理的功能。用 MRT，我们可以同时渲染到 4 张各自 4 通道的纹理，从而只用一趟渲染就写到全部 16 个通道。

现在，如果我们对所有通道都简单地做加法混合，每根发丝都会贡献到每一层。我们真正想要的是每一层 i 只受 z hair < z i 的那部分头发影响。用着色器，我们只需在 zhair > z i 时输出 0 即可。

density += dot(h4tex2D(OSM3, v2f.shadowCoord.xy), v2f.OSM3weight);

最后，我们由光学密度算出透射率，得到一个 0 到 1 之间的值，表示从光源到达点（x, y, z）的光线比例。把这个值乘以着色值，就得到头发的最终颜色。

half shadow = exp(-5.5 * density);

23.4 结论与未来工作

我们已经说明，现在可以实时模拟头发渲染的各个方面：从动画与动力学到渲染与着色。希望我们的系统能为游戏等交互应用中的头发实时渲染提供基础。

虽然这里的想法被用于头发的动画与渲染，但它们并不是只能用于此。Marschner 反射率模型有一种自然的分解形式，我们用它把模型分解成纹理查找。通过近似分解，这一做法可以扩展到任何反射率模型（McCool et al. 2001）。这类数值分解具备解析分解的所有优点，只多了一点误差。

不透明度阴影贴图除了对渲染头发极其有用，还能用于深度图失效的场合。例如，它们可以用于云和烟这类体积表示，或用于茂密植被这类高度细节化的对象。

随着 GPU 越来越灵活，值得寻找把更多工作转交给它们的办法。这不只包括剖分、插值这类显然并行的任务，还包括传统上交由 CPU 处理的领域，例如碰撞检测与物理。

性能并非我们唯一的关注点；我们也在设法让头发更容易由开发人员控制，使造型和动画变得简单。前路还有许多挑战，但我们希望在下一代应用中看到更逼真的头发。
