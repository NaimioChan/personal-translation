第 40 章　GPU 上的计算机视觉

James Fung
多伦多大学

计算机视觉任务计算密集且重复性强，常常超出 CPU 的实时处理能力，留给高层任务的时间很少。不过，许多计算机视觉操作能高效地映射到现代 GPU 上，其可编程性使得种类繁多的计算机视觉算法得以实现。本章介绍如何把计算机视觉中常见的数学操作高效地映射到现代计算机图形架构上。

40.1 引言

在某种意义上，计算机图形与计算机视觉互为对立。计算机图形取场景的数值描述并渲染成图像，而计算机视觉分析图像，以建立场景的数值表示。因此，在图形硬件上执行计算机视觉任务，是以「逆向」方式使用图形硬件。

GPU 提供流式的数据并行算术架构。这类架构对一组图像数据执行同一套计算。GPU 的单指令多数据（SIMD）能力使其适合运行计算机视觉任务，这类任务往往涉及对整幅图像执行相似的计算。

专用计算机视觉硬件在典型的量产个人计算机中很少见。人们通常改用 CPU 执行计算机视觉任务。为 CPU 优化的计算机视觉库往往要消耗大量 CPU 周期才能达到实时性能，留给其他非视觉任务的时间很少。

另一方面，GPU 出现在大多数个人计算机上，而且往往超出 CPU 的能力。因此我们可以用 GPU 加速计算机视觉计算，把 CPU 解放出来做其他任务。此外，同一台机器上可以使用多块 GPU，构成能并行运行多种计算机视觉算法的架构。

40.2 实现框架

许多计算机视觉操作可以看作一系列滤波操作的序列，每一个后续的滤波阶段都作用于前一滤波阶段的输出。在 GPU 上，这些滤波操作由片元程序执行。要把这些片元程序作用于输入图像，需先把输入图像初始化为纹理，再映射到四边形上。在尺寸合适的窗口中显示这些四边形，就能保证图像像素与输出片元一一对应。

带纹理的四边形显示时，片元程序随即运行，对图像的每个像素执行相同的操作。片元程序类似于常见 for 循环语句的循环体，但循环体的每次迭代可以看作并行执行。输出的结果不是原图像，而是滤波后的图像。现代 GPU 允许输入与结果都采用完整的 32 位 IEEE 浮点精度，为许多算法提供了足够的精度。

实现这些滤波操作的序列，就能构成完整的计算机视觉算法。纹理经片元程序滤波后，结果图像被放入纹理内存，可以用渲染到纹理扩展，也可以把帧缓冲拷贝进纹理内存。这样，输出图像就成为下一个片元程序的输入纹理。由此形成一条运行整个计算机视觉算法的管线。

不过，完整的视觉算法常常需要滤波之外的操作。例如求和就是常见的操作，我们会给出如何实现和使用它的例子。此外，诸如特征跟踪这类更一般化的计算，也能有效地映射到图形硬件上。

这些方法实现在 OpenVIDIA GPU 计算机视觉库中，可以用它编写实时计算机视觉程序（http://openvidia.sourceforge.net）。

代码清单 40-1 所示的片元程序利用当前纹理坐标计算一个偏移量，以此施加这种校正。程序再把这个偏移量加到当前像素的坐标上，用结果在校正后的坐标处查找纹理值。这个纹理值随后被输出，图像的径向畸变因而得到校正。

示例 40-1. 径向去畸变

float4 CorrectBarrelDistortion(float2 fptexCoord
                               : TEXCOORD0, float4 wpos
                               : WPOS, uniform samplerRECT FPE1)
    : COLOR
{
  // 特定镜头与传感器的已知常量
  float f = 368.28488;
  // 焦距
  float ox = 147.54834; // 主点，x 轴
  float oy = 126.01673; // 主点，y 轴
  float k1 = 0.4142;
  // 径向畸变校正用的常量
  float k2 = 0.40348;
  float2 xy = (fptexCoord - float2(ox, oy)) / float2(f, f);
  r = sqrt(dot(xy, xy));
  float r2 = r * r;
  float r4 = r2 * r2;
  float coeff = (k1 * r2 + k2 * r4);
  // 把算出的偏移加到当前纹理坐标上
  xy = ((xy + xy * coeff.xx) * f.xx) + float2(ox, oy);
  // 在校正后的坐标处采样纹理
  // 并输出颜色
  return texRECT(FPE1, xy);
}

示例 40-2. 使用非极大值抑制的 Canny 边缘检测器

本程序查找当前像素处梯度的方向，然后取沿梯度前向与后向的像素。若当前像素值大于沿梯度方向的两个值，程序返回 1；否则抑制（置零）输出。一个阈值参数使边缘检测器的灵敏度可以实时调节，以适应视觉装置与环境。

float4 CannySearch(uniform float4 thresh, float2 fptexCoord
                   : TEXCOORD0, uniform samplerRECT FPE1)
    : COLOR
{
  // magdir 存放 { dx, dy, mag, direct }
  float4 magdir = texRECT(FPE1, fptexCoord);
  float alpha = 0.5 / sin(3.14159 / 8); // 网格上的八个方向
  float2 offset = round(alpha.xx * magdir.xy / magdir.zz);
  float4 fwdneighbour, backneighbour;
  fwdneighbour = texRECT(FPE1, fptexCoord + offset);
  backneighbour = texRECT(FPE1, fptexCoord + offset);
  float4 colorO;
  if (fwdneighbour.z > magdir.z || backneighbour.z > magdir.z)
    colorO = float4(0.0, 0.0, 0.0, 0.0); // 不是边缘点
  else
    colorO = float4(1.0, 1.0, 1.0, 1.0); // 是边缘点
  if (magdir.z < thresh.x)
    colorO = float4(0.0, 0.0, 0.0, 0.0); // 阈值化
  return colorO;
}

40.3.2 求和操作

许多常见的视觉操作涉及对图像缓冲求和。需要用到求和的方法包括矩计算以及线性方程组的求解。

Buck 与 Purcell（2004）讨论了一种利用局部邻域高效求缓冲之和的通用方法。然而在不支持渲染到纹理的系统上，这种技术所需的渲染遍数可能成为限制，因为涉及大量图形上下文切换。我们发现，在这类系统上分两遍完成计算更高效。在我们的做法中，先创建一个片元程序对每一行像素求和，得到一列保存各行和的值。然后在第二遍中绘制一个像素，执行一个沿该列向下求和的程序。结果是一个像素，其「颜色」就是整个缓冲的总和。以此方式求和的 Cg 代码见本书 CD 上本章的附录。

我们在两个不同但常用的算法中使用求和操作，它们都需要对缓冲求和：一个手部跟踪算法，以及一个通过确定如何拼接图像来生成全景图的算法。

跟踪手部

跟踪用户的手或脸是构建交互系统的有用视觉工具，可以通过图像滤波与矩计算的组合在 GPU 上实现。跟踪用户手部的常见做法是用颜色分割找出肤色区域，然后在图像中持续跟踪这些区域的位置。此外，跟踪肤色的平均颜色也很有用，因为它会逐帧变化，通常是由光照变化引起的。

通常把分割放在 HSV 色彩空间中进行，因为各种色调的肤色在 HSV 色彩空间中趋于聚集。HSV 色彩空间用色调（颜色的种类，例如红、绿、蓝）、饱和度（该颜色的鲜艳程度）和明度（颜色的亮度）来描述颜色。相机通常产生 RGB 图像，因此可以用一个片元程序作为滤波操作完成快速的颜色空间转换。

假定我们对肤色的 HSV 值有某种初始猜测，还可以用片元程序对像素做阈值判断。给定某个像素的 HSV 值，我们可以求出它与平均肤色 HSV 的差，若差过大则输出 0，否则输出该 HSV 值。例如，这个比较可以简单地写成：

if (distance(hsv, meanhsv) < thresh)
{
  colorO = hsv;
}
else
  colorO = float4(0.0, 0.0, 0.0, 0.0);

40.3.3 用于生成全景图的方程组

VideoOrbits

VideoOrbits 是一种图像配准算法，用来计算成对图像之间的坐标变换，这些图像由可自由平移、俯仰、绕光轴旋转和变焦的相机拍摄。该技术解决两种情况下的问题：(1) 从同一位置拍摄任意三维场景的图像；(2) 从任意位置拍摄平面场景的图像。图 40-4 展示了由若干帧视频合成的图像全景。同样地，Mann 与 Fung（2002）展示了同一算法如何用计算机生成的内容替换场景中的平面，例如图 40-1 那样。

40.3.4 特征向量计算

在检测到的特征点处计算特征向量是计算机视觉中的常见操作。图像中的特征是一个点周围的局部区域，其「独特性」高于平均水平。这使该点更容易在后续视频帧中被识别。点的独特性通过为每个特征点计算特征向量来刻画。特征向量可用于在不同图像中识别同一个点，并可推广到更一般的物体识别技术。图 40-5 展示了相机移动时特征在帧间的运动。

在 GPU 上计算特征向量需要以不同于前文所介绍操作的方式处理图像数据。由于图像中只有少数点是特征点，这项计算不需要在图像的每个点处进行。此外，对单个特征点通常要计算一个较大的特征向量（100 个元素或更多）。因此，每个单点产生的结果数量较多，而非我们此前讨论的一对一或多对一映射。

这类计算仍然可以在 GPU 上完成。我们以一个特征向量为例，它由某个已定位特征点周围局部区域内经过滤的梯度幅值组成。

特征检测可以用类似 Canny 边缘检测器的方法实现，只是寻找角点而非线条。如果特征点是用滤波序列检测的（这很常见），我们可以在 GPU 上完成滤波，并把一个标记哪些像素是特征点的缓冲读回 CPU。CPU 随后可以快速扫描该缓冲，定位每个特征点，生成一个图像位置列表，我们将在 GPU 上为这些位置计算特征向量。

生成特征向量以跟踪特征点有许多做法。我们给出其中一种作为例子。对每个检测到的特征点，我们考察一个 16x16 的梯度幅值与方向邻域（如 Canny 边缘示例中所计算）。这个邻域被划分为 4x4 像素的区域，得到 16 个各含 16 个像素的区域。在每个区域中，我们建立梯度幅值的 8 元直方图。每个像素的梯度幅值按其量化后的梯度方向加入直方图对应的箱。每个区域的结果便是一个 8 元直方图。特征向量是这 16 个 8 元直方图的拼接，因此特征向量长度为 16 x 8 = 128 个元素。不同图像中的特征可以通过计算特征向量两两之间的欧氏距离来匹配，距离最小者即最佳匹配。

为产生 128 元的特征向量结果，我们绘制若干行顶点，每个特征一行，使行中绘制的每个点对应该特征向量的一个元素。逐点关联纹理值，能在为计算特征向量而映射纹理坐标时提供最大的灵活性。图 40-6 展示了顶点的布局以及图像纹理坐标的绑定。每个点都映射了不同的纹理坐标，使单个片元程序能够访问计算直方图所需的局部区域中相应的梯度。

通过为每个点顶点关联正确的纹理坐标，代码清单 40-4 所示的单个片元程序即可计算特征向量。为了每个区域产生 8 个元素，我们把结果打包进 16 位半精度浮点值；另一种做法是用 MRT 输出多个 32 位值。完成后，我们把帧缓冲读回 CPU，其中每行保存一个特征向量。

示例 40-4. 计算特征向量的片元程序

float4 FeatureVector(float2 fptexCoord
                     : TEXCOORD0, float2 tapsCoord
                     : TEXCOORD1, float4 colorZero
                     : COLOR0, float4 wpos
                     : WPOS, uniform samplerRECT FPE1, uniform samplerRECT FPE2)
    : COLOR
{
  const float4x4 lclGauss = {0.3536, 0.3536, 0.3536, 0.3536, 0.3536, 0.7071,
                             0.7071, 0.3536, 0.3536, 0.7071, 0.7071, 0.3536,
                             0.3536, 0.3536, 0.3536, 0.3536};
  const float eps = 0.001;
  float4 input;
  int xoffset = 1, yoffset = 1;
  float4 bins_0 = float4(0.0, 0.0, 0.0, 0.0);
  float4 bins_1 = float4(0.0, 0.0, 0.0, 0.0);
  for (xoffset = 0; xoffset < 4; xoffset++)
  {
    for (yoffset = 0; yoffset < 4; yoffset++)
    {
      input = texRECT(FPE1, fptexCoord + float2(xoffset, yoffset));
      float dir = input.y;
      input *= lclGauss[xoffset, yoffset].xxxx *
               texRECT(FPE2, tapsCoord + float2(xoffset, yoffset)).xxxx;
      if (dir < = (1.0 + eps) / 8.0)
        bins_0.x += input.z;
      /* . . . for each bin . . . */
      else if (dir < = (7.0 + eps) / 8.0)
        bins_1.z += input.z;
      else
        bins_1.w += input.z;
    }
  }
  return float4(pack_2half(bins_0.xy), pack_2half(bins_0.zw),
                pack_2half(bins_1.xy), pack_2half(bins_1.zw))
}

40.4 并行计算机视觉处理

当应用需要多种计算机视觉算法时，可以把多块显卡插入主板的 PCI 总线插槽，实现 GPU 并行处理。图 40-7 展示了一台为探索多显卡并行计算收益而搭建的机器。让每个计算机视觉程序在不同的 GPU 上运行，各卡便能并行处理；程序之间可以用常规的共享内存交互。

由于 PCI 总线即将过时，用 PCI 显卡搭建多 GPU 系统很快就会变得不可行；不过 PCI Express 的出现使新的多 GPU 方案成为可能。其中一种是 NVIDIA 的 SLI，它在多块 GPU 之间自动分配工作，使多 GPU 的存在对开发者透明。

40.5 结论

本章介绍了把计算机视觉算法映射到现代 GPU 上的技术。我们希望本章能让读者理解如何编写在 GPU 上快速处理的计算机视觉算法。虽然也可以使用其他专用硬件系统为计算机视觉算法提供硬件加速，但 GPU 的低成本与广泛可得会使硬件加速的计算机视觉算法更容易普及。
