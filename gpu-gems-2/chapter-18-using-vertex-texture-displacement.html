第 18 章　用顶点纹理位移渲染逼真水面

Yuri Kryachko
1C:Maddox Games

水面在计算机图形中很常见，在游戏中尤其如此。它们是能显著提升场景真实感的关键元素。但要逼真地描绘水面很难，因为水面运动带来的视觉复杂度很高，光与水相互作用的方式也很复杂。本章介绍为游戏 Pacific Fighters 渲染逼真海面所开发的技术。

现代图形硬件通过 DirectX 着色器模型 3.0 提供了许多有用的特性，可用于辅助渲染水面。本章讨论其中一个特性——顶点纹理——如何用于提高所渲染水面的真实感。图 18-1 给出了一些示例结果。此外我们还使用分支来提升顶点程序的性能。

18.1 水面模型

水面动画与渲染方面已经发展出许多方法。其中最出色、看起来最逼真的是基于流体动力学和快速傅里叶变换（FFT）的方法（如 Tessendorf 2001）。这些方法给出非常逼真的结果，但不幸的是计算量很大，不适合交互式应用。

在另一个极端，目前大多数游戏使用非常简单的水面模型，其中多数用做法线贴图来制造视觉细节。可惜这些做法无法提供足够的真实感，也不能忠实再现水面上的波浪。

我们要找的技术，既要有简单法线贴图水面渲染方法的速度，又要有类 FFT 方法的视觉质量。

18.2 实现

我们的实现建立在用做法线贴图做光照计算的渲染算法之上。由于法线贴图能忠实再现高频波浪的细节，我们用它们做光照计算。不过在此之外，我们还用振幅较大的低频波浪对水面网格做几何扰动。

18.2.1 水面模型

我们的水面模型基于若干高度图的叠加，这些高度图在空间和时间上都做了平铺。每张纹理代表频谱的一个「谐波」或「倍频程」，纹理按傅里叶合成的方式相加。这些纹理之所以称为高度图，是因为每个值代表对应点高于水平面的高度。

高度图对美术很友好：创建它就像画一张灰度图一样简单。见图 18-2。有了高度图，美术只要画出波形，就能轻易控制水面动画的参数，细到单个波浪。高度图也很适合做顶点纹理：用它们沿垂直方向位移顶点位置非常直接。

把若干具有不同空间尺度和时间尺度的高度图组合起来，我们就能得到复杂且视觉上精细的动画：

系数 A 与 B 以及求和项数都是凭经验选定的，以在尽量减轻重复图案瑕疵的同时取得最好看的结果。在 Pacific Fighters 中，我们用四张高度图求和做光照计算，其中尺度最大的两张用于置换贴图。这足以模拟从 10 cm 到 40 km 尺度上运动的洋面。

18.2.2 实现细节

我们需要做的全部计算可以分成两类：几何位移计算和光照计算。由于水面剖分得很细，在片元程序层面做光照计算是合理的，把置换贴图交给顶点阶段。另外，在顶点阶段做光照计算会产生视觉瑕疵，在远处尤其明显。

撰写本书时，唯一能做顶点纹理的硬件是 GeForce 6 系列 GPU 和最新的 NVIDIA Quadro FX GPU。这些硬件上的顶点纹理实现有一些限制；特别是顶点纹理必须是每分量 32 位、浮点的纹理，而且不能用最近邻之外的任何滤波模式。尽管如此，它们对本章所述的技术非常有用。

18.2.3 采样高度图

我们的实现逐顶点采样高度图，并在顶点程序中算出位移值。采样时我们使用以相机位置为中心的径向网格。这个网格的剖分方式使它离观察者越近细节越多，如图 18-3 所示。

下面的公式给出径向网格顶点位置的计算方式。

半径 r = a 0 + a 1 i 4

xi,j = r cos (2j/M)

yi,j = r sin (2j/M)，

其中 i = [0..N - 1]，j = [0..M - 1]。我们选择 a 0、a 1 使得

r 0 = a 0 = 10 cm

半径 r N-1 = a 0 + a 1 (N-1)4 = 40 km。

用这种方法，我们自然得到基于距离的剖分，也就是一个简单的细节层次（LOD）方案。这里本可以用其他做法，例如 ROAM 或 SOAR 地形渲染算法，但它们需要在 CPU 侧做大量工作，会抵消使用顶点纹理的全部好处。另见本书第 2 章「使用基于 GPU 的几何 Clipmap 渲染地形」，其中给出另一种在 GPU 上以自适应剖分渲染高度场的方法。

代码清单 18-1 给出用径向网格从单张高度图采样的简单顶点着色器。

示例 18-1. 用径向网格几何从高度图采样的顶点着色器

float4 main(float4 position
            : POSITION, uniform sampler2D tex0, uniform float4x4 ModelViewProj,
              uniform float4 DMParameters, // 置换贴图参数
              uniform float4 VOfs)
    : POSITION
{
  // 读取打包为 (cos(), sin(), j) 的顶点
  float4 INP = position;
  // 变换为径向网格顶点
  INP.xy = INP.xy * (pow(INP.z, 4) * VOfs.z);
  // 求置换贴图的纹理坐标
  // VOfs.xy、DMParameters.x — 高度纹理的偏移与缩放
  float2 t = (INP.xy + VOfs.xy) * DMParameters.x;
  // 从纹理中取置换值（lod 0）
  float vDisp = tex2D(tex0, t).x;
  // 把取到的值从 0..1 缩放到：
  // DMParameters.y — 水面高度
  // DMParameters.z — 波浪振幅
  INP.z = DMParameters.y + (vDisp - 0.5) * DMParameters.z;
  // 用水面高度置换当前位置
  // 并将其投影
  return mul(ModelViewProj, INP);
}

18.2.4 质量改进与优化

为双线性滤波打包高度值

顶点纹理取数可能相当昂贵。在 GeForce 6 系列硬件上，一次顶点纹理取数就能在顶点程序中引入明显的延迟。所以我们想尽量减少顶点程序里的纹理取数次数。另一方面，对纹理值做某种滤波又非常必要，否则视觉质量会明显下降。

传统上熟知的滤波方法是双线性与三线性滤波。双线性滤波计算离纹理取数坐标最近的四个纹素的加权平均。三线性滤波则对相邻 mip 层中的双线性查询结果取平均，每层按其对应的 LOD 小数部分加权。

由于当前这一代图形硬件不支持对顶点纹理值做任何形式的滤波，我们只能在着色器中用显式的数学指令模拟滤波。照直实现的话，即使最简单的双线性滤波也要四次纹理取数才能算出一个滤波值。三线性滤波则需要两倍的纹理取数。

为减少滤波所需的纹理取数次数，我们以特殊方式构建纹理，使每个纹素都包含单次双线性纹理查询所需的全部数据。这之所以可行，是因为我们的高度图本质上都是单分量纹理，我们可以把四个高度值打包进一张四分量纹理的单个纹素：

代码清单 18-2 实现了按前述方式打包的、对顶点纹理的双线性纹理查询。

示例 18-2. 顶点着色器中的高效双线性纹理插值

float tex2D_bilinear4x(uniform sampler2D tex, float4 t, float2 Scales)
{
  float size = Scales.x;
  float scale = Scales.y;
  float4 tAB0 = tex2Dbias(tex, t);
  float2 f = frac(t.xy * size);
  float2 tAB = lerp(tAB0.xz, tAB0.yw, f.x);
  return lerp(tAB.x, tAB.y, f.y);
}

我们可以把这一做法推广到三线性滤波。由于三线性滤波需要小数的 LOD 值，我们可以用离相机的距离作为 LOD 的良好近似。代码清单 18-3 中的代码实现了对打包顶点纹理的三线性纹理查询。

示例 18-3. 把双线性滤波技术扩展到三线性滤波

float tex2D_trilinear(uniform sampler2D tex, float4 t, float2 Scales)
{
  float fr = frac(t.z);
  t.z -= fr;
  // floor(t.zw);
  float Res;
  if (fr < 0.30)
    Res = tex2D_bilinear4x(tex, t.xyzz, Scales);
  else if (fr > 0.70)
    Res = tex2D_bilinear4x(tex, t.xyzz + float4(0, 0, 1, 1),
                           Scales * float2(0.5, 2));
  else
  {
    Res = tex2D_bilinear4x(tex, t.xyzz, Scales);
    float Res1 = tex2D_bilinear4x(tex, t.xyzz + float4(0, 0, 1, 1),
                                  Scales * float2(0.5, 2));
    fr = saturate((fr - 0.30) * (1 / (0.70 - 0.30)));
    Res = Res1 * fr + Res * (1 - fr);
  }
  return Res;
}

注意，我们进一步优化了三线性纹理取数：只在两层 mip 的影响都显著的区域内做两次纹理取数。在其他区域，我们把 LOD 值「吸附」到最近的 mip 层，从而省下纹理带宽。

用分支避免不必要的计算

即使做了纹理滤波优化，水面渲染时的纹理取数次数仍可能很高，显著影响性能。我们可以减少渲染的顶点总数，但那会降低整体视觉细节并加重走样。

由于我们用大批几何体渲染水面，有些三角形最终完全在屏幕之外。注意即便对这类三角形，顶点程序仍会执行，白白浪费宝贵的计算资源。如果能跳过落在相机视锥之外的三角形的计算，我们就能省下大量逐顶点工作。

顶点程序一次只处理一个顶点，拿不到拓扑信息，所以我们只能在逐顶点层面而不能在逐三角形层面做判断。如果某个三角形内有些顶点跳过了顶点纹理、有些没跳过，就会产生瑕疵。实践表明我们的三角形和顶点纹理位移都足够小，这个瑕疵看不出来。

下面的伪代码说明了这个思路：

float4 ClipPos = mul(ModelViewProj, INP);
float3 b0 = abs(ClipPos.xyz) < (ClipPos.www * C0 + C1);
if (all(b0))
{
  // 顶点属于可见三角形，
  // 进行纹理采样并相应地置换顶点
}

在上面的代码中，我们用裁剪空间的顶点位置判断当前顶点是否在视锥内，只在需要时才做昂贵的计算。

C0 与 C1 是特殊的「凑数」常量，控制三角形要多超出相机视锥多少才触发裁剪。这样我们避免了因跳过对视锥外但仍可见三角形上的顶点做纹理化而产生的瑕疵。实际上我们把「裁剪」视锥略微加宽了，在屏幕边缘留出一定量的「保护带」空间。由于水面细剖分得足够细、顶点纹理位移也合理，这个简单方法在实践中效果很好。

渲染到纹理

我们还可以先用单独一遍把各张高度图纹理合并成一张浮点纹理，以提升速度。这样就不必在顶点着色器里做多次昂贵的滤波操作。此外，我们现在可以用更紧凑的纹理格式——16 位浮点——来存储原始高度图。我们还可以把一系列动画高度图存为三维纹理的切片，让动画更平滑。

有了这个优化，我们的渲染循环变成两遍：

  1. 用一个特殊的像素着色器渲染单个四边形到 fp32 纹理，把各张高度图合并起来。这张纹理中的纹素对应径向网格的顶点。
  2. 把生成的高度图作为顶点纹理，按前述方式位移径向网格的顶点。

波浪的背面

由于我们的光照计算是在像素着色器中、假定水面平坦的前提下进行的，这个近似在某些情况下会造成视觉瑕疵。

在图 18-4 所示的情形中，我们看到的是波浪的背面，尽管由于几何位移它朝外对着观察者、现实里本不该可见。这导致浪尖出现令人不适的亮区。

为尽量减轻这些瑕疵，我们把用于光照计算的法线朝观察者方向「倾斜」一点，使它们更接近波浪的正面。这一技术的源码见随书光盘。图 18-5 显示用本章所述方法生成的场景。

18.2.5 渲染局部扰动

有时需要渲染由浮力物体或落入水中的物体引起的局部碎浪。这对游戏尤其重要，因为游戏里需要产生爆炸、船只尾迹之类的东西。由于很难把物理上正确的方法融入我们基于高度图的水面模型，我们讨论几种基于经验的更简单方法。

动态置换贴图

另一种做法是把所有局部生成的位移直接渲染进顶点纹理，本质上就是采用 GPU 通用计算（GPGPU）式的思路。这样我们在第一遍生成顶点纹理，在随后的一遍里用它做真正的水面渲染。额外的好处是，我们可以把过滤基础高度图和求和「倍频程」的工作放到像素着色器里，减轻顶点着色器的负担。

计算位移时，我们可以采用上述解析模型，也可以尝试元胞自动机式的方法，让局部位移逐帧演化。风的影响也可以通过沿适当方向模糊纹理来考虑。

不过，要以 50 cm 的分辨率覆盖 1 km 的水面，需要一张约 2048x2048 的纹理，这会给纹理内存和着色器执行速度带来额外压力。而且视点快速切换也会成问题。

尽管如此，我们仍鼓励读者尝试这些做法。

18.3 结论

把顶点纹理取数的灵活性与动态分支的省性能特性结合起来，我们得以开发出一种在交互速度下渲染逼真水面的实用方法。这里所述的做法已成功应用于 Pacific Fighters，让我们能在从 10 cm 到 40 km 的相当大距离范围内生成逼真的水面。这对现代飞行模拟器来说是可以接受的。我们得以消除整个可见水面区域上的平铺瑕疵。

未来的硬件很可能让这一技术有更稳健的实现，尤其是消除手工对纹理值做滤波的需要，并提供更高的顶点着色器性能。

采用视差贴图之类的高级着色技术，还能进一步提高我们方法的质量，为水面提供细粒度的细节与凹凸。这类做法之一见第 8 章「用距离函数做逐像素置换贴图」。

最后，光照计算可以从高动态范围技术中大大受益，因为高反射的水面会出现极大的亮度变化。
