第 45 章　GPU 上的期权定价

Craig Kolb
NVIDIA Corporation

Matt Pharr
NVIDIA Corporation

过去三十年间，期权及其他衍生品已成为越来越重要的金融工具。期权常用于对冲投资证券的风险，也用于通过套利利用市场上的定价异常。

使用期权的关键前提是算出它们的公允价值。三十多年来，寻找高效求解这一期权定价问题的方法一直是活跃的研究领域，如今仍是现代金融工程的重点。随着越来越多的计算被用于金融相关问题，在现代架构上高效实现这些算法也变得越来越重要。

本章介绍如何用 GPU 高效地为期权定价。我们用两种不同的定价模型进行评估：Black-Scholes 模型和格点模型。这两种方法都能很好地映射到 GPU，且在 GPU 上都比在现代 CPU 上快得多。虽然两者到 GPU 的映射都很直接，但格点模型由于计算之间存在依赖关系，实现起来需要额外的工作。

45.1 什么是期权？

期权属于被称为衍生品的一类投资工具。传统投资工具，如房地产或股票，具有内在价值。而期权则从另一种投资工具派生出其价值，后者称为标的资产。标的资产通常是股票或其他形式的证券。

期权有若干种类。看涨期权合约赋予买方（或称持有者）在未来某个日期以某个事先约定的价格买入标的资产的权利，但并非义务。事先约定的价格称为行权价，那个未来日期称为到期日。类似地，看跌期权赋予持有者在到期日以约定价格卖出标的资产的权利。

举例来说，考虑一份以 XYZ 公司股票为标的的看涨期权。设想该合约保证你可以在六个月后以 100 美元的价格买入 100 股 XYZ 股票。如果到期日该股票的交易价格低于 100 美元，行权就没有什么意义——毕竟你可以在公开市场上用更少的钱买到。这种情况下你干脆让期权到期作废。反过来，如果到期日 XYZ 每股价格是 120 美元，你就会行权，以每股 100 美元买入。若随即卖出，每股可赚 20 美元，再减去你为这份期权付出的成本。

如上例所示，行权价 X 与标的资产在到期日的价格都强烈影响期权的未来价值，从而决定你今天应该为它付多少钱。在某些简化假设下，我们可以用资产的当前价格 S 及其波动率 v（描述价格随时间变化的幅度）来统计建模资产未来的价格波动。

还有一些因素会影响你愿意为期权支付的价格：

  • 距到期日的时间 T。期限越长，意味着到期日标的资产可能取值的范围越宽，因而期权到期时价值的不确定性越大。
  • 无风险收益率 r。即使期权在六个月后给你带来 P 美元的收益，这 P 美元今天对你的价值也低于 P。如果债券或其他「无风险」投资以连续复利年利率 r 付息，你只需今天把 P x e -r(6/12) 美元投入该债券，就能保证六个月后得到同样的 P 美元。因此，未来某时刻 0 < t ≤T 的资产价值必须折现，即乘以 e -rt，才能确定它今天的实际价值。
  • 行权限制。到目前为止，我们只讨论了所谓的欧式期权，它只能在期权到期日当天行权。也存在行权限制不同的其他类型期权。特别是，美式期权可以在到期日之前（含到期日）的任何时候行权。这种额外的灵活性意味着美式期权的定价至少与相应的欧式期权一样高。

其他因素，例如股息派发，也可能牵涉进来。不过本章我们只限于上述考虑。

本章余下部分介绍两种标准的期权定价方法，以及它们传统上如何在 CPU 上实现。我们展示这些方法如何能在 GPU 上以更高的吞吐量实现，吞吐量以每秒定价的期权数量衡量。

下文的讨论中我们省略了大部分数学细节。背景材料可参见 Hull 2002，其中包括这些定价模型所用到的支撑理论、推导和假设。

45.2 Black-Scholes 模型

1973 年，Fischer Black 与 Myron Scholes 出色地推导出计算欧式期权价格的分析方法（Black and Scholes 1973）。Scholes 因这项工作获得 1997 年诺贝尔经济学奖。（Black 在获奖前已经去世。）

Black-Scholes 方程是一个微分方程，它描述在一组特定假设下，期权价值如何随标的资产价格变化而变化。更准确地说，它是一个随机微分方程；除确定性项之外，还包含一个随机游走项——用以建模标的资产价格随时间的随机波动。这个随机项使得我们必须使用与通常求解微分方程略有不同的数学工具；细节见参考文献。

Black-Scholes 方程表明，欧式看涨期权的价值 V 可按下式计算：

V = S x CND(d1 ) - Xe-rT x CND(d2 ),

其中

（看跌期权的公式类似。）累积正态分布函数 CND(x) 给出一个服从正态分布的随机变量取值小于 x 的概率。该函数没有闭式表达，因此必须数值求解。通常用多项式函数近似，我们这里也是这样做的。

我们用本书第 31 章「把计算概念映射到 GPU」中描述的 GPGPU 框架，结合代码清单 45-1 中的 Cg 代码，在 GPU 上并行地为期权定价。首先我们用每个期权对应的行权价、资产价格、距到期时间和资产波动率初始化四个二维数据数组，某个期权的输入数据存放在各数组中的同一位置。之后只要在每个像素上运行片元程序，就能并行地为所有期权定价。在测试中，我们假定所有期权的无风险收益率都是常数，因此可以通过 uniform 参数传给 Cg 程序。对某些应用来说，改变这个值也可能有用，这对程序只是一处直接的改动。累积正态分布函数 CND() 的实现见后面的代码清单 45-2。

示例 45-1. 用 Cg 实现 Black-Scholes 模型

float BlackScholesCall(float S, float X, float T, float r, float v)
{
  float d1 = (log(S / X) + (r + v * v * .5f) * T) / (v * sqrt(T));
  float d2 = d1 - v * sqrt(T);
  return S * CND(d1) - X * exp(-r * T) * CND(d2);
}

因此，用这种方法为一个给定期权定价依赖五个输入参数，需要相当多的浮点计算，并产生一个浮点值。结果是一项算术强度很高的计算，非常适合在 GPU 上运行，见图 45-1。

代码清单 45-2 表明，与其直接求值多项式——例如用霍纳法则——在 GPU 上更高效的做法是利用它的四路向量硬件，预计算 K 的各次幂，并用 dot() 函数与适当的常数快速求内积。

有趣的是，PCI Express 总线有可能成为该模型 GPU 实现的瓶颈：假定 PCI Express 达到 4 GB/秒带宽的理想性能，每秒可向 GPU 传入并传出 10 亿个 4 字节浮点值。在我们的测试程序中，有 4 个输入参数在变化，这意味着每秒可以向 GPU 送入足够的数据完成约 2.5 亿次 Black-Scholes 计算（4 GB/秒 除以 4 个值，再乘以每个浮点值的 4 字节）。这里的 Black-Scholes 实现编译后约 50 次浮点运算。因此，任何算术计算能力超过 10 Gflops 的 GPU 都会受限于数据送入 GPU 的速率（回想一下，当前的 GPU 具备数百 Gflops 的计算能力）。

示例 45-2. 实现累积正态分布函数

float CND(float X)
{
  float L = abs(X);
  // 构造 float4，使 K.x = K、K.y = K^2、K.z = K^3、K.w = K^4
  float4 K;
  K.x = 1.0 / (1.0 + 0.2316419 * L);
  K.y = K.x * K.x;
  K.zw = K.xy * K.yy;
  // 计算 K、K^2、K^3、K^4 各项，并重排以获得高效的
  // 向量化。上面我们预先算好了 K 的各次幂；
  // 这里则把每一项乘上对应的缩放系数，再用 dot()
  // 例程把这些项高效地求和。
  //
  // dot(float4(a, b, c, d), float4(e, f, g, h)) 会高效地
  // 计算内积 a*e + b*f + c*g + d*h，
  // 相比直白的实现，它能更好地利用
  // 4 路向量浮点硬件。
  float w =
      dot(float4(0.31938153f, -0.356563782f, 1.781477937f, -1.821255978f), K);
  // 再把 K^5 这一项单独加上
  w += 1.330274429f * K.w * K.x;
  w *= rsqrt(2.f * PI) * exp(-L * L * .5f); // rsqrt() == 1/sqrt()
  if (X > 0)
    w = 1.0 - w;
  return w;
}

尽管存在这一潜在瓶颈，在 GPU 仍比 CPU 快得多：它实际上能以其峰值计算速率运行，只是受 PCI Express 的限制。对于需要计算期权价格的完整应用，很可能还要在 GPU 上用 Black-Scholes 的结果做额外计算，这也会减轻 PCI Express 带宽的影响。（一般来说，GPU 上做的计算越多、与 CPU 的通信越少，GPU 表现越好。PCI Express 带宽限制只是一种表现，说明当计算与带宽之比提高时 GPU 尤为出色，参见本书第 29 章「流式架构与技术趋势」。）

45.3 格点模型

Black-Scholes 方程为计算欧式期权价格提供了方便的分析方法。但它不适用于美式期权，后者可在到期日之前的任何时候行权。事实上，在 Black-Scholes 方程所用的同一组假设下，目前还没有已知的闭式表达能给出美式期权的公平价格。

另一类期权定价模型是格点模型。这类模型用动态规划的方法，从时刻 T（即到期日）出发，在 N 个离散时间步中逐步「倒推」到 t = 0，从而求出期权在时刻 0（即现在）的价值。这种方法通用且实现简单，但由于其迭代性质，计算开销可能很大。本节讨论二项格点模型在 GPU 上的实现，以及如何用它计算欧式与美式期权的价格。

45.3.1 二项模型

最常用的格点模型是二项模型。二项模型之所以得名，是因为它假设标的资产在某个时间步的价格为 Sk（k 即该时间步）时，其在第 k + 1 步的价格只能取两个值：uSk 和 dS k，分别对应股票价格的「上涨」或「下跌」。通常 u 的计算方式是假设在一段很短的时长 dt 内，资产价值的变化服从正态分布，标准差等于 S k v 。

如果选取 d 使 u x d = 1，则期权存续期内可能的资产价格构成一棵树，如图 45-2 所示。从树的根节点到某个叶节点的每条路径，对应标的资产价格随时间的一次「游走」。距根节点深度为 k 的那组节点，代表时刻 t = k x dt 时可能的资产价格范围，其中 dt = T/N。深度为 k = N 的叶节点，代表期权到期时资产可能具有的价格范围。

要用二项树为期权定价，我们还要计算资产价格在任意时刻「上涨」的伪概率 Pu。下跌的伪概率就是 1 - Pu 。为计算 Pu 的值，我们假设一个风险中性世界，这意味着标的资产的期望收益率等于 r：

45.3.2 为欧式期权定价

给定一棵随时间变化的资产价值树，如图 45-2 所示，我们可以计算树上每个节点的期权价值。深度为 k 的节点所算出的价值，是在假定标的资产未来取该节点子节点对应的一组价格的前提下，期权在时刻 t = k x dt 的期望价值。于是我们的问题是算出树根处的期权价值。做法是从叶节点出发，向根节点倒推。

计算每个叶节点 i 处的期权价值很简单。首先我们算出每个叶节点对应的资产价格 Si：直接把 u 取相应的幂次（回想 d = u -1）再乘以 S。接着计算每个叶节点处相应的期权价值 V i 。在到期日，若 Si > X，看涨期权一文不值；否则其价值为 X - Si 。看跌期权的计算类似。用这些初值，我们就可以算出上一层时间步各节点的期权价值：用价格「上涨」的「概率」 Pu 与「上」「下」两个方向节点对应的期权价值 Vi,up 和 Vi,down 求出期权的期望未来价值，再用 e-r dt 对这个期望未来价值折现，得到该节点对应的期权价值：

示例 45-3. 用二项方法为欧式看跌期权定价的伪代码

 dt = T/N
u = exp(v * sqrt(dt))
d = 1/u
disc = exp(r * dt)
Pu = (disc - d) / (u - d)
// 用到期日的价值初始化期权价值数组
for i = 0 to N
Si = S * pow(u, 2 * i - N)
V[i] = max(0, X - Si)
// 对每个时间步
for j = N-1 to 0
// 对当前时间步的每个节点
for i = 0 to j
// 计算期权的贴现期望价值
V[i] = ((1 - Pu) * V[i] + Pu * V[i + 1])/disc

要让二项模型在 GPU 上运行，我们需要处理一个事实：与 Black-Scholes 不同，这项计算是迭代的，需要使用中间计算值——即 V[i] 的各个值。为 GPU 并行化这项任务的一种做法是一次只处理二项树的一个时间步（一列）：为一列中的每个节点启动一个线程，由它计算该节点的期权价值。从最右边一列开始，先算出到期时的期权价值。随后对每个更早时间步对应的列，按前面描述的方式用两个子节点已算出的值计算期权价值。这一策略如图 45-3 所示。每个线程算出结果后，这些值会作为输入传给新启动的一组线程，用于计算左边下一列的值。（这一过程的总体思路与 GPU 上归约的计算方式有关，参见本书第 31 章。）

为提高 GPU 可用的并行度，我们的实现同时对一千个左右的独立期权运行该算法进行定价。因此在任一时刻，GPU 上运行的线程总数等于正在定价的期权数乘以当前处理的那一列中的树节点数。这种额外的并行很容易加入，并且比每次只并行化单个期权定价计算能获得更好的 GPU 性能。

我们用两个片元程序为这批期权定价。第一个程序算出最初的 N + 1 个叶节点期权价值（V[0] . . . V[N]），对应代码清单 45-3 中的第一个 for 循环。第二个程序运行多次，迭代计算内部节点的 V[i]。应用调用该程序 N 次，每个时间步一次（对应代码清单 45-3 中的第二个 for 循环），每次迭代都用先前算出的 V[i] 计算当前时间步的值。每次调用该程序对应代码清单 45-3 最内层的 for 循环；如清单所示，每次迭代计算出的节点数减一，最后只剩一个结果值，对应 V[0]。

运行第二个程序需要把一次迭代的输出作为下一次迭代的输入。为高效做到这一点，我们使用双缓冲的 pbuffer，避免上下文切换和纹理拷贝的开销。这些程序的 Cg 代码见代码清单 45-4，驱动它们的伪代码见代码清单 45-5。

示例 45-4. 计算格点模型的期权定价

void init(Stream stockPrice, Stream strikePrice, Stream yearsToMaturity,
          Stream volatility, uniform float riskFreeRate, uniform float numSteps,
          float2 offset
          : DOMAIN0, out float4 result
          : RANGE0)
{
  float deltaT = yearsToMaturity.value(offset.x) / numSteps;
  float u = exp(volatility.value(offset.x) * sqrt(deltaT));
  float price =
      stockPrice.value(offset.x) * pow(u, 2 * (offset.y - 0.5) - numSteps);
  float value = max(strikePrice.value(offset.x) - price, 0);
  result = value;
}
void iterate(Stream Pu, Stream Pd, Stream optval, float2 offset
             : DOMAIN0, float2 offsetplus1
             : DOMAIN1, out float4 result
             : RANGE0)
{
  float val = (Pu.value(offset.x) * optval.value(offsetplus1) +
               Pd.value(offset.x) * optval.value(offset));
  result = val;
}

示例 45-5. 格点模型应用的伪代码

 domain = [0, nproblems, 0, N + 1]
Varray[N % 2] = init(Range, S, X, T, v, r, N, domain)
for j = N - 1 to 0
offset = [0, nproblems, 0, j + 1]
offsetplus1 = [0, nproblems, 1, j + 2]
Varray[(j % 2)] = iterate(Pu, Pd, Varray[((j + 1) % 2)], offset,
offsetplus1)

随着时间步数 N 增加，用二项方法算出的值收敛到 Black-Scholes 方法算出的值。二项方法的计算开销远大于 Black-Scholes 方法；例如其渐近时间复杂度为 O(N 2)，而 Black-Scholes 是 O(1)。不过这份计算开销也带来一个好处：与 Black-Scholes 不同，格点方法可以改造成适用于多种期权定价问题。

例如，我们可以修改前面的算法来为美式期权定价。在计算每个节点持有期权的期望价值时，我们也可以同时计算立即行权的价值。若行权比继续持有更值钱，就把该节点处的期权价值设为行权价值，而不是持有的期望价值。对看涨期权而言，行权价值是 X - Si ，其中 Si 是节点 i 处算出的资产价格。完整实现见本书附赠光盘。

45.4 结论

期权定价的 Black-Scholes 模型和格点模型都是计算金融的基本构件。本章展示了如何用 GPU 借助这些模型为期权定价，效率远高于 CPU。随着 GPU 持续比 CPU 更快地提升速度，这项应用中两者的差距很可能会继续拉大。

另一种广泛使用的期权定价做法是实现基于蒙特卡罗或准蒙特卡罗仿真的算法。这类算法也很适合 GPU，因为它们依赖运行大量独立试验，再基于所有试验一起算出总体估计。独立试验天然可以并行，而得出最终估计只是做归约。美式期权附带提前行权权利，这使得用蒙特卡罗方法计算其公平价格颇具挑战。寻找高效做到这一点的方法是一个活跃的研究领域。

使这类算法稍难映射到 GPU 的一个细节是缺少原生整数指令，而整数指令是蒙特卡罗所需的伪随机数生成器以及准蒙特卡罗所用的低差异序列的基础。在当前 GPU 上可以绕开这一限制：在 CPU 上生成这些数，再下载到 GPU。只要每个随机或准随机样本都伴随相当数量的计算，这一步就不会成为瓶颈。
