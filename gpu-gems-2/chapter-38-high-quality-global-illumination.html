第 38 章　用光栅化实现高质量全局光照渲染

Toshiya Hachisuka
东京大学

当前 GPU 能交互渲染的图像在视觉丰富度上持续快速提升，但仍有许多重要的光照效果用现有技术不易处理。GPU 难以处理的一个重要光照效果是高质量全局光照，即图像中包含来自场景中非发光物体反射的光。把这种间接光照纳入渲染图像，能极大提升画质；图 38-1 展示了一个带间接光照和大型面光源的室内场景。与本章所有图像一样，它是用一个基于 GPU 的全局光照算法渲染的，该算法借助光栅化硬件高效地做光线投射。

纳入这些效果的技术通常需要光线追踪才能获得高质量结果。在每个像素处执行一次「最终聚集」计算，在该点周围的半球上投射大量光线，以采样来自许多不同方向的光。本章介绍一种利用 GPU 光栅化硬件为高质量离线渲染做快速光线投射以完成最终聚集的方法。与以往的 GPU 光线追踪技术（例如 Purcell 等 2002 和 Carr 等 2002）不同，该方法基于以创新方式使用光栅化硬件来执行光线-物体相交，而不是把经典光线追踪算法映射到 GPU 的可编程片元处理单元上。虽然我们的目标是最高质量的图像而不是交互帧率的图像，但 GPU 上可用的巨大计算能力与带宽使其值得用于离线渲染。

38.1 通过光栅化实现全局光照

我们不是把各种基于 CPU 的全局光照方法移植到 GPU 上，而是主张推导一种使用光栅化的新全局光照算法更自然、更高效，因为图形硬件本身就是基于光栅化渲染的。尽管以往许多技术用 GPU 做带有部分全局光照特性的实时渲染——例如预计算辐射传输（Sloan 等 2002）——用 GPU 加速高质量离线渲染同样有吸引力。以这种方式使用光栅化的一个重要优势是，我们不需要在 GPU 上维护光线追踪加速结构（例如均匀网格）。这是一个显著优势，因为以往的基于 GPU 的光线追踪器依赖 CPU 构建这些结构，因而既受 CPU 处理速度的限制，也受 GPU 上可用于存储完整场景描述的内存量限制。我们的技术基本上不受这两个问题困扰。

我们把使用本章技术的全局光照渲染器「Parthenon」发布在 http://www.bee-www.com/parthenon/。该应用也可在本书附带的 CD 上找到。图 38-2 展示了 Parthenon 渲染的其他图像。

38.2 最终聚集概述

38.2.1 两遍方法

从概念上说，求解全局光照最简单的方法是路径追踪，但这种方法需要极多光线才能得到无噪声的图像。因此，如今大多数全局光照渲染器实现更高效的两遍方法。两遍方法在第一遍计算场景全局光照的粗略近似，然后在第二遍利用第一遍的结果高效渲染最终图像。许多渲染器用辐射度或光子映射做第一遍。虽然第一遍的结果可以直接用于最终图像，但要达到足够质量，这样做往往比用两遍方法需要更多计算时间（也就是说，如果用光子映射，需要大量光子才能得到足够准确的图像）。图 38-3 展示了康奈尔盒的全局光照渲染：一种直接可视化光子映射，另一种用两遍方法。这两张图像所花计算时间几乎相同。

虽然把同一场景处理两遍听起来冗余，但第一遍的计算开销通常并不很大，因为它只计算近似结果。因此第一遍只占总渲染时间的一小部分。这种方法已成为近年全局光照渲染器的事实标准，因为它通常能比路径追踪更快地产生质量足够的最终图像。

38.2.2 最终聚集

第一遍解法的用法多种多样，但最流行的做法是在第二遍通过光线投射求半球积分时，把它作为间接光照的来源。在每个可见点，我们希望确定有多少光从场景中其他物体到达该点。为此，我们在该点的半球上投射大量光线，确定沿每个方向能看到场景中的哪个物体，以及从它到达多少光，如图 38-4 所示。这个过程称为最终聚集。每个可见点的出射辐亮度（亮度）可由下面的积分计算：

38.3 通过光栅化实现最终聚集

我们基于 GPU 的最终聚集方法在所有可见点计算半球积分，因此不再需要插值——你只需要调整采样总数！此外，由于该方法同时处理所有可见点，我们可以渐进地观察渲染过程，并在所得图像达到足够质量时终止计算。我们的方法利用了 GPU 光栅化硬件的能力，因此通常比那种在 CPU 上对稀疏点集做最终聚集再用插值的做法更快。

38.3.1 最终聚集光线的聚类

对每个可见点，最终聚集步骤在以该点法向量为中心的半球上生成 N 条均匀分布的光线，如图 38-5a 所示。我们不像大多数基于 CPU 的实现那样在每个点选择不同的方向（我们称之为半球聚类），而是从一组预先确定的 N 个固定方向中为每条生成的光线选择方向（我们称之为平行聚类）。这组方向可以看作对单位球面上所有方向的离散化。现在考虑为所有可见点生成的全部光线。如果把具有相同预定方向的光线归入 N 个子集，每个子集将由起点不同但方向相同的光线组成（图 38-5b）。

我们的方法直接利用光线的平行聚类：不是分别追踪与每个可见点相关的光线，而是一次选取 N 个预定方向之一，并用光栅化同时有效地追踪该方向上的所有光线。这个光栅化通过沿当前方向对场景做平行投影来完成。当前选定的方向称为全局光线方向。全局光线方向这个概念本身此前已由 Szirmay-Kalos 与 Purgathofer（1998）提出。虽然我们可以把 hemicube 方法（Cohen 等 1993）与光线的半球聚类结合使用，但这非常耗时，因为需要把场景光栅化的次数达到像素数量级。注意我们的方法只需要把光栅化的次数达到全局光线方向的数量级（也就是最终聚集采样的数量）。通常像素数量比最终聚集采样数量大几个数量级，因此所提出的方法非常高效。

38.3.2 把光线投射视为多次平行投影

把最终聚集视为多次平行投影，关键在于深度层这一概念。深度层是场景几何体的子集，依据从场景外部开始沿某个方向的相交次数划分，如图 38-6 所示。例如，沿全局光线方向反向射出的光线在穿过第一个深度层之后，抵达第二个深度层。因此选定某个全局光线方向之后，我们要做的就是从某个特定位置出发，沿全局光线方向用深度层取得最近点。由于从可见点出发的最近点存在于最近的深度层上，如果我们能根据可见点平行投影的位置取到最近的深度层（见图 38-7），这个过程就等价于光线投射。

为了用 GPU 取得每个深度层，我们使用称为深度剥离的多遍渲染方法（Everitt 2001）。虽然这种方法当初是为了给几何体排序以做正确的 alpha 混合而发明的，但它本质上基于深度层的概念。用深度剥离时，先按常规渲染场景。下一次渲染遍忽略与第一遍所渲染深度相同的片元，于是深度值比第一深度层更大的片元被存入帧缓冲。结果，重复这一过程就能按顺序提取所有深度层。

38.4 实现细节

现在我们已经有了用光栅化在 GPU 上做最终聚集的工具，下面说明我们算法实现的细节。以下步骤概述了该方法。

  1. 把每个可见点的位置与法线存入可见点缓冲 A。
  2. 把「深度」缓冲 B 与缓冲 C 初始化为最大距离。
  3. 把采样的深度层缓冲 D 清零。
  4. 用均匀采样抽取一个全局光线方向。
  5. 在缓冲 A 中可见点平行投影的位置读取缓冲 D，如果该点沿所选全局光线方向位于可见点前方，就把结果存入缓冲 E。
  6. 用所选全局光线方向的平行投影，以反转深度测试（即渲染网格最远的点）把场景几何体（包括第一遍的数据）渲染到缓冲 B（存深度值）与缓冲 D（存颜色）。如果该点的片元深度值大于缓冲 C，则被剔除。
  7. 把缓冲 B 拷贝到缓冲 C。
  8. 返回第 5 步，直到第 6 步渲染的片元数量变为 0。
  9. 把缓冲 E 累加到间接光照缓冲。
  10. 返回第 2 步，直到采样数量足够。

38.4.1 初始化

首先，我们需要把可见点的数据存入浮点纹理，以启动最终聚集过程。最简单的做法是把顶点的位置与法线作为纹理坐标存储并渲染出来。稍后我们描述为全局光照渲染生成这些数据的细节。注意这些可见点是任意的（也就是说，每个可见点的数据与其他点无关）。因此我们不仅可以处理从相机可见的点，还可以处理任何数据集，例如光照图的纹素、顶点烘焙颜色等。除可见点数据之外，我们还需要采样全局光线方向，并把这个向量存入像素着色器常量。对于后续的深度剥离过程，我们把两个「深度」缓冲 B 和 C（这些缓冲不是深度模板缓冲！）填为最大距离。

38.4.2 深度剥离

由于深度剥离需要两个深度缓冲，我们用两张纹理作为深度缓冲。我们沿全局光线方向从最远到最近提取深度层。因此起初每个可见点采样到的是最远的交点，而我们需要的是最近的交点。我们依次提取深度层，如果采样点沿所选方向位于可见点前方，就采样该深度层。反复这一过程，每个可见点最终都得到它最近的交点，如图 38-8 所示。

为提取每个深度层，我们用反转深度测试（即渲染最远的片元）把场景深度值渲染到「深度」缓冲 B，如果所得片元的距离比「深度」缓冲 C 中对应值更远，就把它剔除。该片元的数据被存入缓冲 D，供采样深度层使用。然后把缓冲 B 拷贝到缓冲 C，进入下一次迭代。这一迭代把每个深度层提取到缓冲 D。

38.4.3 采样

如前所述，我们可以通过深度剥离采样最近的交点。每次迭代中，我们对可见点做平行投影，如果该点位于投影后的可见点前方，就读取缓冲 D。所得采样点存入缓冲 E。注意如果采样点比缓冲 E 中已存的点更近，缓冲 E 就会被覆盖。最终，缓冲 E 存储从可见点位置沿全局光线方向的最近交点。

如果在第 3 步把缓冲 D 清为环境贴图中对应的颜色，我们就可以同时采样基于图像的光照的直接光照。（不过这种采样方法仅限于均匀采样，因为每一点的间接光照分布都不同。因此我们通常另用一个直接光照步骤，采用更精细的采样方法，稍后描述。）注意在我们算法第 8 步的条件分支中，片元数量不必完全为零。如果你愿意容忍一些渲染误差，用作结束条件的片元数量可以取某个非零值（例如片元总数的 2%）；把该值设得大于零可以减少迭代次数，提升性能。

38.4.4 性能

由于所提出的算法与 CPU 上光线追踪的最终聚集完全不同，两者难以比较。不过目前的性能已接近 CPU 上的插值方法（例如辐照度梯度）。注意我们的方法在所有像素上做最终聚集。与在 CPU 上对所有像素做最终聚集相比，我们这种基于 GPU 光栅化的方法快得多。其性能通常接近每秒数百万条光线。这可以匹敌甚至超过高度优化的 CPU 光线追踪的最佳性能（Wald 等 2003）。注意 CPU 的这一高性能依赖所有光线具有相干性，而使用最终聚集时并不满足这一条件。

38.5 GPU 上的全局光照渲染器

既然能用 GPU 快速完成最终聚集，下面我们讨论用该技术在 GPU 上实际实现一个全局光照渲染器。任何全局光照渲染器的实际实现都相当复杂，因此为简化这里的说明，我们把讨论限定在朗伯材质，以及软阴影、互反射、抗锯齿、景深效果和基于图像的光照这类渲染器特性上。

38.5.1 第一遍

如前所述，第一遍执行粗略的全局光照计算。这里我们在 CPU 上使用网格光子映射，因为这种方法比普通光子映射略快。网格光子映射把光子累积到网格数据结构中，以精度为代价换取常数时间的最近邻查询（即对网格的查询）。构建好光子图的这种网格表示之后，我们在剖分得很细的网格中计算辐照度值作为顶点颜色。注意你也可以用任何数据结构存储辐照度，例如光照图或体纹理（例如 Greger 等 1998）。这里我们不解释实现细节，因为你可以在 CPU 或 GPU 上使用任何一种全局光照技术。重要的是快速生成辐照度分布，并且所得数据应能被后续 GPU 最终聚集步骤中的 GPU 光栅化轻松、即时地访问。因此，例如在 GPU 上用光子映射（Purcell 等 2003）可能并不高效，因为这种做法迄今的实现都是在运行中即时估计辐照度。注意，正如 38.2 节所述，用带辐照度数据的这个网格渲染，就能得到粗略的全局光照结果。

38.5.2 生成可见点数据

在开始光照过程之前，我们必须准备好可见点的位置、法向量和颜色。为此，我们只需从相机渲染场景，并用片元着色器把这些数据写出到浮点缓冲。如果支持多重渲染目标，用这项功能完成这个过程会很方便。

这些缓冲可以在光照过程中直接使用，也可以用累积缓冲技术提升最终图像的质量。例如，生成可见点集时可以在亚像素级别上抖动视锥体的近平面来做抗锯齿（Haeberli 与 Akeley 1990）。抖动最好使用拟蒙特卡洛方法或分层采样。在光栅化渲染中，我们可以用大量采样做抗锯齿，因为这只须改变透视投影矩阵即可完成。

类似地，要实现景深效果，也可以抖动相机位置。此时抖动的幅度随光圈/镜头形状或焦平面位置而变化。由于这种技术得到的图像等价于光线追踪的景深效果，我们不会遇到基于图像的景深所伴随的种种问题，例如边缘渗色。如果想把这一效果与抗锯齿结合，只需同时抖动相机位置和近平面。

38.5.3 第二遍

由于所提出的最终聚集只计算间接光照，我们必须独立计算直接光照，之后再把这些结果相加。计算直接光照时，我们使用典型的实时光照技术，例如阴影贴图和模板阴影。在我们的系统中，面光源通过使用多个点光源采样并对这些贡献取平均来模拟。

为执行基于图像的光照，我们把每个环境光视为一组平行光源。注意在几乎所有基于图像的光照中，均匀采样都没有帮助，因为高动态范围通常会造成光照的极大变化。因此应当使用基于重要性的采样方法，例如 Agarwal 等 2003 中提出的方法。

两种情况下都要注意，用图形硬件计算直接光照比基于 CPU 的光线追踪快得多。因此与使用光线追踪阴影相比，我们能以多得多的采样非常快地得到图像。

对于间接光照，我们如前所述在 GPU 上执行最终聚集方法，把第一遍的结果用作顶点颜色。我们用位置、法向量和颜色缓冲作为可见点集，用顶点处带辐照度值的网格数据作为渲染网格。为得到最终图像，我们把间接光照加到直接光照上。

38.5.4 补充方案

下面我们讨论一些额外的实现问题，并给出解决它们的示例。

走样

由于最终聚集方法基于用平行投影光栅化到有限分辨率的缓冲，存在与阴影贴图类似的走样问题。这种走样常常导致间接光照的泄漏。走样的一个例子如图 38-9 所示。这个问题与阴影贴图的问题完全相同；因此，如同在阴影贴图中那样，我们可以用透视阴影贴图（Stamminger 与 Dretakkis 2002）或其他精细方法来在一定程度上缓解走样。这里我们不深入实现细节，因为那超出本章的范围。

闪烁与跳变

虽然用光子映射做第一遍是一种高效的全局光照方法，但在有运动物体的场景中，由于光子发射的随机性可能出现闪烁。为解决这个问题，我们也可以使用本章描述的最终聚集方法。注意最终聚集方法在给定反射 N - 1 次的辐亮度分布的情况下，生成反射 N 次的辐亮度分布。这一观察意味着，你可以用下面的算法求解全局光照问题本身，该算法如图 38-10 所示。

首先，用拟蒙特卡洛采样对光源采样，并用直接光照技术把所得的光照数据（反射零次的辐照度分布，仅由直接光照构成）记录到顶点数据缓冲中。接着，我们用拟蒙特卡洛方法和这份光照数据，在三角形顶点处沿全局光线方向执行最终聚集，并把结果累加到另一个顶点数据缓冲中。结果，我们用基于 GPU 的最终聚集方法得到了反射「0 + 1」次的全局光照数据（即直接光照与反射一次后的间接光照数据）。要计算全部间接光照，我们只需迭代这一过程，依次生成反射 n + 1 次的光照数据，再把这些数据累加到缓冲中。注意每一步都不像最终渲染那样需要大量采样。使用这种预计算方法可以抑制闪烁与跳变，因为使用拟蒙特卡洛方法时采样方向（即全局光线方向）不随时间变化。

38.6 结论

本章演示了如何用 GPU 上的光栅化完成全局光照渲染。所得算法能高效渲染高质量图像。此外，由于所提出的最终聚集方法在所有点上执行，任何点集（例如光照图的纹素或顶点烘焙颜色）都能方便地处理。最终聚集步骤本身只是通过光线投射求半球积分，因此你也可以用所提出的方法完成任何需要该积分值的计算（例如形状因子计算或辐射传输预计算）。我们的方法目前在普通 GPU 上还达不到交互帧率，但与等价算法的 CPU 实现相比，它大幅加速了离线渲染。
