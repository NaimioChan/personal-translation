第 43 章　用于蛋白质结构预测的 GPU 计算

Paulius Micikevicius
Armstrong Atlantic State University

43.1 引言

确定蛋白质的三维结构是计算生物学中最大的挑战之一。核磁共振（NMR）波谱法是（继 X 射线晶体学之后）第二常用的结构预测方法。给定一个分子，NMR 实验能提供原子间距离的上界与下界。如果所有距离都精确已知，每个原子的笛卡尔坐标便可轻易算出。然而 NMR 实验只能得到全部距离界限中的一小部分（常常不到 10%；未知的上界与下界分别设为分子的直径与氢原子的直径）。因此实践中会使用若干启发式方法，从 NMR 数据生成三维结构。由于所算结构的质量与所需时间都取决于界限的紧致程度，必须使用高效的界限平滑过程（即提高下界或降低上界）。最广泛使用的过程基于三角形不等式，并被收录进流行的分子动力学软件包，例如 X-PLOR 与 DYANA。本章描述三角形不等式距离界限平滑过程的 GPU 实现。图 43-1 给出了一个所得结果的例子。

一个 n 原子分子用 n 个结点上的完全图 K n 建模，结点代表原子。每条边 (i, j) 被赋予两个标记——上界与下界，记为 uij 与 lij，分别表示第 i 个与第 j 个原子之间距离的界。设 i、j、k 是三维欧氏空间中的任意点。点之间的距离 dij、dik 与 dkj 必须满足三角形不等式；例如 dij ≤ d ik + d kj。三角形不等式也可以用距离的上界与下界来表述。dij 的上界必须满足不等式 uij ≤ uik + ukj，而下界必须满足 lij ≥ max {l ik - u kj, lkj - u ik }。必须先收紧上界，因为上界的值变小会带来更大的下界。Dress 与 Havel（1988）已证明，借助求解全对最短路径问题的 Floyd-Warshall 型算法，可以在 O(n 3) 时间内消除对三角形不等式的违反。

43.2 Floyd-Warshall 算法与距离界限平滑

给定一个 n 结点带权图，全对最短路径问题要求找出每一对结点之间的最短距离。这个问题是计算机科学与图论中的基础问题。除界限平滑之外，它还有其他实际应用，例如网络分析以及求解差分约束系统（Cormen 等 2001）。求解全对最短路径问题已有若干串行方法（简要讨论见 Bertsekas 1993），但对稠密图而言，Floyd-Warshall 算法因其简单与高效的内存访问模式而通常更受青睐。顺序执行的 Floyd-Warshall 算法见算法 43-1（我们假定结点用整数 1, 2, . . ., n 编号）。我们假定图存储为二维距离矩阵 D，其中 D[i, j] 保存结点 i 与 j 之间的距离。Floyd-Warshall 算法需要 O(n 3) 时间与 O(n2) 存储。把算法 43-1 的第 4 行替换为 uij ← min {uij , uik + ukj }，就得到上界平滑算法。类似地，把第 4 行替换为 lij ← max {lij , lik - u kj, lkj - uik }，就得到收紧下界的算法。

示例 43-1. 顺序执行的 Floyd-Warshall 算法

1. 对 k ← 1 到 n 执行
2. 对 i ← 1 到 (n - 1) 执行
3. 对 j ← (i + 1) 到 n 执行
4. dij ← min {dij , dik + dkj }

针对 O(n 2) 个处理器的一种经典并行化见算法 43-2，其中 Pij 指负责更新距离 dij 的处理器。

示例 43-2. 针对 n 2 个处理器的 Floyd-Warshall 算法并行化

1. 对 k ← 1 到 n 执行
2. 对 每个 Pij ，其中 1 ≤ i, j ≤ n 并行执行
3. dij ← min {dij , dik + dkj }

算法 43-2 的并行化适合 GPU 实现，因为每个处理器都从多个位置读取，但只写入一个预先确定的位置。

43.3 GPU 实现

要在 GPU 上求解，距离界限平滑问题被表述为可编程片元单元的一项渲染任务。上界与下界分别存为两张独立的二维纹理。虽然这种存储选择浪费内存（纹素 (i, j) 与 (j, i) 保存相同的值），但在向量化实现中它能减少纹理取数，因而带来更高性能，详见后文 43.3.4 节。为表述简单，我们先描述算法的标量版本，把向量化留到本节最后。

43.3.1 动态更新

由于 Floyd-Warshall 算法具有动态性质，第 k 次迭代的输出是第 (k + 1) 次迭代的输入。虽然为 CPU 编程时这不需要特殊考虑，但当前的 GPU 架构不允许同一块内存同时充当渲染目标与纹理。我们用乒乓缓冲克服这一限制：在前后缓冲之间交替渲染。例如，当后缓冲被绑定为纹理时，我们渲染到前缓冲。下一次迭代中缓冲的角色对调，过程重复。由于没有内存拷贝，我们经实验确认乒乓缓冲比拷贝到纹理的做法快一倍。

43.3.2 数据纹理的索引

对 n 结点图的全对最短路径解，通过分 n 遍渲染一个 nxn 像素的方形区域来计算，每一遍对应算法 43-2 中第 1 行 for 循环的一次迭代。位置 (i, j) 处的像素对应距离 d ij。因此，片元着色器执行对应算法 43-2 中第 3 行的计算。在朴素实现中，给定距离 dij，着色器生成两组纹理坐标，用于索引距离 dik 与 dkj 的存储，然后执行代数运算。把纹理坐标的生成从着色器移到光栅化器可以提升性能：在第 k 次迭代中，矩形的四个顶点各自被赋予三个纹理坐标，如图 43-2a 所示。这样经过插值后，每个片元 (i, j) 都能得到所需的三个纹理坐标。把纹理坐标生成从着色器移到光栅化器使性能提升了约 10%。

43.3.3 三角形做法

距离的上界与下界可以分别存放在一张纹理的上三角与下三角中。在这一假设下，需要确保用于平滑上界的着色器只取上三角的纹素。当纹理坐标 (u, v) 满足 u < v 时即可做到这一点：在第 k 次迭代中，上三角按 i、j、k 之间的关系被划分为三个区域，如图 43-2b 所示。因此我们渲染三个几何图元，其纹理坐标按区域调整。例如，下方三角形的纹理坐标见图 43-2c。如果不像上述那样渲染三个图元而只渲染一个，GPU 就必须为每个片元执行额外指令来判断该片元属于哪个区域。类似的做法可用于平滑下界。

43.3.4 向量化

由于 GPU 的每条管线都作用于四分量向量，我们可以通过向量化算法来提升性能。做法是把四条连续边的距离打包进单个纹素的 RGBA 分量。如图 43-3 所示，纹素 T[i, j] 包含距离矩阵的下列元素：D[i, 4j]、D[i, 4j + 1]、D[i, 4j + 2]、D[i, 4j + 3]。因此只需渲染一个 nxn/4 的矩形。注意在第 k 次迭代中渲染第 i 行的像素需要取距离值 D[i, k]，所以我们需要修改上界平滑的计算，

D[i, j] ← min{D[i, j], D[i, k] + D[k, j]},

以适用于向量运算：

T[i, j] ← min{T[i, j],+T[k, j]},

其中 是一个向量，由复制 T[i, [k/4]] 的 R、G、B 或 A 分量值得到，取决于是 k ≡ 0、1、2 还是 3（模 4）。平滑下界的代码也作类似修改。在 GPU 上生成 向量可能代价很高，因为在某些情况下分支或整数运算在当前片元单元中效率不高。我们可以运行四个独立的着色器程序来克服这一限制，每个程序针对不同的 k mod 4 取值硬编码，从而避免分支与整数运算（把标量值复制到 上不会带来额外开销 [Mark 等 2003]）。OpenGL 应用必须在 n 次迭代的每一次中显式绑定相应的着色器程序，其开销可以忽略。

虽然距离的上界与下界可以分别存放在同一张二维纹理的上三角与下三角中，但这会导致更多纹理取数。例如，要更新纹素 T[i, j] 中的上界，我们需要确保取 T[k, j] 时返回距离 D[k, 4j]、D[k, 4j + 1]、D[k, 4j + 2] 与 D[k, 4j + 3] 的上界。然而若 k > j，纹素 T[k, j] 位于下三角，保存的是下界。结果我们就需要取 4 个纹素（T[4j, k]、T[4j+ 1, k]、T[4j + 2, k]、T[4j + 3, k]）而非 1 个。这种做法对每个下界需要 11 次纹理取数，对每个上界需要 3 次（当 i, j < k 时）或 6 次（当 i、j 或两者都大于 k 时）纹理取数。因此，我们采用存储 2 张纹理、渲染理论所需两倍片元的做法取得更好的性能，因为平滑上界与下界分别只需要 3 次与 5 次纹理取数。

43.4 实验结果

实验在一台基于 2.4 GHz Intel Xeon 的 PC 上进行，配有 512 MB 内存与一块 NVIDIA GeForce 6800 Ultra GPU。GeForce 6800 Ultra 有 16 条片元管线，每条以 425 MHz 处理四元素向量。应用用 ANSI C++ 编写，图形操作使用 OpenGL、GLUT 与 Cg（Mark 等 2003）。pbuffer、纹理与着色器程序全部采用 32 位 IEEE 标准浮点类型，因为精度对距离界限平滑至关重要。可执行文件用 Intel C++ 8.1 编译器编译，启用了 SSE2 优化。此外，CPU 实现经过手工优化，以尽量减少缓存缺失。

问题规模 128 到 4096 的计时结果见表 43-1。我们给出了总时间，以及分别平滑下界与上界的时间。最大规模受图形系统限制，因为无法分配大于 4096x4096 的 pbuffer。所有结果以毫秒为单位，取连续执行 1000 次（对 n = 128、256）、100 次（对 n = 512）、10 次（对 n = 1024、2048）或 1 次（对 n = 4096）的平均值。平滑下界与上界所编译出的着色器分别包含九条与五条汇编指令。

43.5 结论与进一步工作

距离界限平滑过程的 GPU 实现与纯 CPU 实现相比取得八倍以上的加速。这归功于图形硬件的并行性质与高内存带宽。进一步工作可以在两个方向展开：(1) 设计算法以适应 GPU 内存限制，从而增大可求解的问题规模（4096 个原子对蛋白质分子来说并不算大）；(2) 让 CPU 与 GPU 之间的计算重叠。

为突破 4096x4096 的 pbuffer 尺寸限制，算法应设计成能一次更新邻接矩阵的一个片段（条带或块）。这样邻接矩阵就分布在若干像素缓冲中。还应开发一种针对具体应用的方法，在 GPU 内存中显式缓存数据，以突破 GPU 内存的物理限制。另一种做法是采用类似 Park 等 2002 中的递归方法，由 GPU 执行基本情况。

在 CPU 与 GPU 之间分担计算负载，对 n 结点的图需要在 GPU 与 CPU 内存之间传输数据 n 次。不过这一开销也许可以接受，因为在 n 次迭代的每一次中，只需传输一行与一列。因此通信代价是 O (n 2)，而计算复杂度是 O(n 3)。
