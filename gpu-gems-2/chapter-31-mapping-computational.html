第 31 章　把计算概念映射到 GPU

Mark Harris
NVIDIA Corporation

近年来，图形处理器已成为强大的计算平台。许多令人鼓舞的结果——主要来自用 GPU 加速科学计算与可视化应用的研究者——表明把 GPU 用于数据并行的计算问题可以取得显著加速。不过，要实现这些加速，需要了解 GPU 编程与架构。

前面几章介绍了现代 GPU 的架构，以及支配其性能与设计走向的趋势。承接那些章节提出的概念，本章给出把标准计算概念直观映射到 GPU 专用特性的方式。讲完基础之后，我们介绍一个简单的 GPU 编程框架，并用一段简短示例程序演示该框架的用法。

31.1 数据并行的重要性

与任何计算机一样，要从 GPU 获得最高性能，就要对其架构有所了解。前两章很好地概述了 GPU 架构及其演进的趋势。正如那些章节所示，GPU 是为计算机图形设计的，而计算机图形具有高度并行的计算风格：从由顶点和纹素构成的独立数据元素输入流，计算出彩色像素的输出流。为此，现代 GPU 配备许多可编程处理器，并行地对流元素施加内核计算。

为 GPU 编程时——无论用于图形还是通用计算——都必须记住 GPU 的设计。本章把第 29 章「流式架构与技术趋势」中介绍的流处理概念应用到 GPU 通用计算（GPGPU）上。把 GPU 用于一般计算问题的最大困难在于它的设计非常专用。因此，GPU 编程深深嵌在计算机图形 API 与编程语言之中。我们的目标是通过在计算机图形概念与一般计算概念之间建立类比，从这些 API 中抽象出来。这样做，我们希望能让你进入数据并行的思维状态，这是充分利用 GPU 并行架构所必需的。

31.1.1 哪类计算适合映射到 GPU？

在开始之前，先了解 GPU 真正擅长什么。显然它擅长计算机图形。计算机图形计算有两个关键属性：数据并行与独立性——不仅相同或相似的计算被施加到许多顶点和片元构成的流上，而且对每个元素的计算几乎不依赖或不依赖其他元素。

算术强度

这两个属性可以合并为一个概念，称为算术强度，即计算与带宽之比，更正式地写作：

算术强度 = 运算次数 / 传输的字数。

如第 29 章所述，微处理器上计算成本的下降速度快于通信成本。对 GPU 这类并行处理器尤其如此，因为随着技术进步带来更多可用晶体管，更多晶体管被用于提升计算吞吐量的功能单元（如算术逻辑单元），而不是用于降低存储延迟的存储层次（缓存）。因此，GPU 要达到峰值性能就需要高算术强度。

因此，最能从 GPU 处理中获益的计算具有高算术强度。线性方程组求解就是一个好例子。第 44 章「求解线性方程组的 GPU 框架」讨论了向量与矩阵的高效表示，以及如何用这种表示快速求解线性偏微分方程。这些计算在 GPU 上表现良好，因为它们高度数据并行：由大量数据元素构成的流（以矩阵和向量的形式），对其施加相同的计算内核。计算每个输出元素所需的数据通信量小且连贯。结果是，从主存传输的数据字数保持较低，算术强度较高。

在 GPU 上表现良好的其他计算例子还包括：如第 47 章「带复杂边界的流动仿真」所述的格点上的基于物理的仿真，以及如第 43 章「用于蛋白质结构预测的 GPU 计算」所述的全对最短路径算法。

31.1.2 示例：网格上的仿真

本章余下部分使用一个简单却有效的例子：在网格上仿真自然现象。图 31-1 所示的笛卡尔网格是我们所仿真现象演化的二维空间域的离散表示。本例是一个基于物理的云仿真。除了说明一些基本 GPGPU 概念之外，我们不会深入该仿真的物理与数学细节。关于云仿真的更多信息，见 Harris et al. 2003。

网格上的计算在 GPGPU 中很常见，因为网格在 GPU 上有天然的表示方式：纹理。此外，GPU 含有针对二维数据局部性优化的小型纹理缓存，这与 CPU 所用的一维数据缓存不同。许多计算天然映射到网格，包括矩阵代数；图像与体数据处理；基于物理的仿真；以及光线追踪、光子映射和辐射度这类全局光照算法（见第 39 章「使用渐进精化辐射度的全局光照」）。不天然在网格上进行的计算，也可以通过把一维地址转换为二维地址来映射为网格计算。

云仿真算法由若干步骤组成，如图 31-1 所示。算法步骤的重要细节在于：每一步都会更新整个网格，且每一步必须完成后才能进行下一步。用流处理的话说，网格单元中存储的数据构成我们的流，算法步骤就是我们的计算内核。每个内核施加到每个流元素上，生成新的流，成为下一步的输入。

31.1.3 流通信：聚集读与分散写

高算术强度要求把流元素之间的通信降到最低，但对许多计算而言，通信是必要之恶。例如在云仿真中，某些内核必须从当前正在处理的单元之外的单元获取信息。讨论 GPU 上的数据通信时，考虑两种主要类型会有帮助：聚集读（gather）与分散写（scatter）。聚集读发生在处理某个流元素的内核从流中其他元素请求信息时：它从存储器的其他部分「聚集」信息。分散写则发生在处理某个流元素的内核把信息分发给其他流元素时：它把信息「分散」到存储器的其他部分。用传统存储器概念来说，聚集读只需要随机访问读取能力，分散写只需要随机访问写入能力。后文我们会说明为什么聚集读通常优于分散写。

31.2 GPU 计算资源清点

要把一般计算映射到 GPU 的专用硬件上，首先应清点 GPU 提供的计算资源。我们从计算的主力——处理器——开始。

31.2.1 可编程并行处理器

GPU 有两类可编程处理器：顶点处理器与片元处理器。顶点处理器处理顶点流（顶点由位置、颜色、法线向量和其他属性构成），顶点是构成多边形几何模型的元素。计算机图形通常用三角形网格表示三维物体。顶点处理器对每个顶点施加顶点程序（有时称为顶点着色器），依据顶点相对于摄像机的位置做变换，然后每三个顶点用来计算一个三角形，由这些三角形生成片元流。片元可以看作「原始像素」。它包含在最终图像中生成一个着色像素所需的全部信息，包括颜色、深度以及在帧缓冲中的目标位置。片元处理器对片元流中的每个片元施加片元程序（有时称为像素着色器），计算出每个像素的最终颜色。

顶点处理器

现代 GPU 有多个顶点处理器（NVIDIA GeForce 6800 Ultra 与 ATI Radeon X800 XT 都各有六个）。这些处理器完全可编程，以 SIMD 或 MIMD 并行方式作用于输入顶点（关于这些术语的更多信息见第 34 章）。三维计算机图形的基本图元是投影空间中的三维顶点，用（x, y, z, w）向量表示，以及以（红、绿、蓝、alpha）向量（常缩写为 RGBA）存储的四分量颜色，其中 alpha 通常表示不透明度的百分比。因此，顶点处理器具备处理四分量向量的硬件。这使它们能以更少的周期产出变换后的顶点位置。

顶点处理器能够改变输入顶点的位置。想一想就会明白，这些顶点的位置最终决定了像素绘制在图像的何处。图像不过是一个存储数组；因此，既然顶点处理器能控制数据写入存储器的位置，它们也就具备分散写的能力。不过，当前多数顶点处理器无法直接读取输入流中除当前正在处理的那个顶点元素之外的信息。因此它们不具备聚集读能力。NVIDIA GeForce 6 系列 GPU 有一项新特性叫顶点纹理取数（VTF）。这意味着 GeForce 6 顶点处理器能随机访问存储器读取。于是我们可以把部分或全部输入流数据存到顶点纹理中，用 VTF 实现聚集读操作。

片元处理器

现代 GPU 也有多个片元处理器（NVIDIA GeForce 6800 Ultra 与 ATI X800 XT 都各有 16 个）。与顶点处理器一样，它们完全可编程。片元处理器以 SIMD 并行方式作用于输入元素，并行处理四元素向量。片元处理器能从纹理取数据，因此具备聚集读能力。不过，片元的输出地址总是在片元处理之前就已确定：处理器无法改变像素的输出位置。因此片元处理器本身不具备分散写能力。关于绕过这一限制的进一步讨论与技术，见 31.3 节。

对 GPGPU 应用而言，片元处理器的使用通常比顶点处理器更重。这有两个主要原因。第一，在典型的可编程 GPU 上，片元处理器比顶点处理器多。第二，片元处理器的输出或多或少直接进入存储器，可以径直作为新的纹理数据流回喂进来。而顶点处理器的输出必须先经过光栅化器和片元处理器才能到达存储器。这使顶点处理器的直接输出不那么方便。

光栅化器

如前所述，顶点处理器变换顶点之后，每三个顶点用来计算一个三角形（以边方程的形式），再由这个三角形生成片元流。生成片元的这项工作由光栅化器完成。我们可以把光栅化器看成一个地址插值器。后文会说明存储器地址如何表示为纹理坐标。光栅化器根据片元位置对这些地址以及其他逐顶点值插值。由于它从少量输入元素生成大量数据元素，也可以把它看成一个数据放大器。光栅化器的这些功能高度专用于渲染三角形，不是用户可编程的。

纹理单元

片元处理器（以及最新 GPU 上的顶点处理器）能以纹理的形式访问存储器。我们可以把纹理单元看成只读的存储器接口。

渲染到纹理

GPU 生成图像时，可以把它写入可显示的帧缓冲存储器，也可以写入纹理存储器。这种渲染到纹理（render-to-texture）功能对 GPGPU 至关重要，因为它是当前唯一无需回到主机处理器、就能把 GPU 输出直接反馈为输入的机制。（间接反馈也可通过复制到纹理（copy-to-texture）实现，它需要把数据从 GPU 存储器的一处复制到另一处。）我们可以把渲染到纹理看成只写的存储器接口。

你可能会问，为什么不把纹理单元和渲染到纹理合起来看成读写存储器接口。原因是片元处理器可以在内核内部任意多次读取存储器，但只能在核程序结束时写数据（这就是流输出）。因此 GPU 上的存储器读写从根本上是分开的，把它们分开来看会更有帮助。

数据类型

给 CPU 编程时，我们习惯处理多种数据类型，例如整数、浮点数和布尔值。当前的 GPU 在这方面限制更多。虽然 GPU 使用的一些高级着色语言暴露了整数与布尔数据类型，但当前 GPU 只处理定点或浮点形式的实数。此外，当前 GPU 支持多种浮点格式。例如 NVIDIA GeForce FX 与 GeForce 6 系列 GPU 同时支持 16 位（1 个符号位、10 个尾数位、5 个指数位）与 32 位（1 个符号位、23 个尾数位、8 个指数位，与 IEEE-754 标准相同）浮点格式。ATI 的所有当前产品，包括 Radeon 9800 与 X800，都支持 24 位浮点格式，含 1 个符号位、16 个尾数位和 7 个指数位。GPU 缺少整数数据类型是当前的局限。通常可以用浮点数绕过，但举例来说，并非所有 32 位整数都能用 32 位浮点格式表示（因为尾数只有 23 位）。必须小心，因为浮点数无法精确表示与其同尺寸整数类型相同范围的所有整数。表 31-1 给出各浮点格式的位字段，以及它们所能表示的值的说明。

31.3 CPU 与 GPU 的类比

即使对资深的 CPU 程序员来说，若不具备一些图形编程知识，起步 GPU 编程也可能颇为棘手。本节通过把传统 CPU 计算概念与其 GPU 对应物做几种很简单的类比，帮助你理解。我们从流与内核的概念开始。

31.3.1 流：GPU 纹理 = CPU 数组

这一条很简单。GPU 上的基础数组数据结构是纹理与顶点数组。如前所述，对 GPGPU 而言片元处理器往往比顶点处理器更有用。因此，凡是在 CPU 上会用数据数组的地方，在 GPU 上就可以用纹理。

31.3.2 内核：GPU 片元程序 = CPU 的「内层循环」

GPU 的大量并行处理器是它的计算主力——它们对数据流执行内核计算。在 CPU 上，我们会用一个循环遍历流（存在数组中）的元素，逐个顺序处理。在 CPU 的情形中，循环内部的指令就是内核。在 GPU 上，我们把类似的指令写在片元程序里，它们被施加到流的所有元素上。这次计算的并行量取决于我们所用的 GPU 处理器数量，也取决于我们对 GPU 运算的四分量结构所启用的指令级并行利用得有多好。注意，顶点程序也可以看作作用于顶点流的内核。

31.3.3 渲染到纹理 = 反馈

如前所述，多数计算都被拆成若干步骤。每一步都依赖前几步的输出。就流而言，由于流元素之间存在依赖，通常一个内核必须先处理完整个流，下一个内核才能继续。此外，在基于物理的仿真中，仿真的每个时间步都依赖上一时间步的结果。

在 CPU 上，这些反馈实现起来很轻松，因为 CPU 采用统一存储模型，程序中任何位置都可以读写存储器。而在 GPU 上就没那么容易了，正如前面所讨论的。要实现反馈，我们必须用渲染到纹理把片元程序的结果写入存储器，以便之后作为后续程序的输入。

31.3.4 几何光栅化 = 计算调用

现在我们对数据表示、计算和反馈都有了类比。不过要运行程序，还需要知道如何调用计算。我们的内核是片元程序，所以只需知道如何生成片元流。这一点从上一节应该已经清楚：要调用计算，我们只要绘制几何体。顶点处理器会变换几何体，光栅化器会确定它覆盖了输出缓冲中的哪些像素，并为每个像素生成一个片元。

在 GPGPU 中，我们通常要处理代表网格的矩形片元流中的每个元素。因此，GPGPU 编程中最常见的调用就是一个四边形。

31.3.5 纹理坐标 = 计算域

在 GPU 上执行的每个内核（片元程序）都以若干流为输入，通常产生一个输出流。支持多个渲染目标的较新 GPU 可以产生多个输出流（目前限于四个 RGBA 流）。任何计算都有输入域和输出范围。许多情况下，GPU 上某次计算的域可能与输入流的维度不同。

GPU 以纹理坐标的形式提供了一种简单办法来处理这一点。这些坐标存储在顶点上，光栅化器对每个顶点处的坐标做线性插值，为每个片元生成一组坐标。插值后的坐标作为输入传给片元处理器。在计算机图形中，这些坐标用作纹理取数的索引。对 GPGPU 而言，我们可以把它们看成数组索引，并可用它们来控制计算的域。域与范围的大小可以相同，也可以域小于范围（数据放大/放大率），或者域大于范围（数据缩小）。对上述每种情形，光栅化器都能让输入流按正确的间隔被正确采样。

31.3.6 顶点坐标 = 计算范围

如前所述，片元由光栅化器从输入几何体生成，经过片元处理后成为输出像素。由于片元处理器不能直接做分散写，输入顶点与顶点程序决定了生成哪些像素。通常我们在输出像素坐标中指定一个四边形的四个顶点，并施加一个只是把顶点原样传过去的顶点程序。于是顶点坐标直接控制计算的输出范围。

31.3.7 归约

到此为止讨论的一切都假设纯并行计算：每个元素的计算在很大程度上独立于流的其余部分。然而有时我们需要把一个大向量归约为较小的向量，甚至归约为单个值。例如，我们可能需要计算数组中所有值的和或最大值。这类计算称为并行归约。

在 GPU 上，归约可以通过轮流对一对缓冲进行渲染和读取来完成。每一遍都把输出（计算范围）的尺寸缩小一定比例。为产生输出的每个元素，片元程序读取两个或更多值，并用归约算子（例如加法或最大值）算出一个新值。这些遍持续进行，直到输出变成单元素缓冲，此时我们就得到了归约结果。一般而言，这一过程需要 O(log n) 遍，其中 n 是要归约的元素数。例如对二维归约，片元程序可能从输入缓冲的四个象限各读一个元素，使输出尺寸在每一步的两个维度上都减半。图 31-2 演示了对二维缓冲做最大值归约。

31.4 从类比到实现

至此你已对当前 GPU 上多数 GPGPU 程序如何运作有了高层次的理解。上一节的类比给了我们一个总体实现方案。现在，为了让你能开始把 GPU 用起来，我们深入讲解实践中需要的具体实现细节。

31.4.1 综合起来：一个基本的 GPGPU 框架

为方便起见，我们用 C++ 写了一个非常基础的框架，你可以用它编写 GPGPU 程序。框架在本书附带的 CD 上。这个框架名为 pug，它把上一节的所有类比都纳入进来，以更接近资深 CPU 程序员习惯的方式抽象 GPGPU 编程。

初始化与结束 GPGPU 应用

GPGPU 应用的第一步是初始化 GPU。在框架中这很简单：只要调用 pugInit()。应用用完 GPU 后，可以调用 pugCleanup() 清理图形 API 所用的存储器。

指定内核

框架中的内核用 Cg 语言编写。虽然 Cg 是为图形设计的，但它基于 C 语言，因此很容易学。更多信息我们推荐 The Cg Tutorial（Fernando and Kilgard 2003）以及 Cg 发行版附带的文档（NVIDIA 2004）。Cg 中图形专用的关键字很少。我们提供一个 Cg 文件 pug.cg，可以把它包含到内核文件中。该文件定义了一个名为 Stream 的结构，用来抽象最以图形为中心的概念：纹理取数。Stream 是 Cg 纹理采样器类型的包装。调用 Stream 结构的某个 value() 函数即可得到某个流元素的值。

要从文件加载并初始化内核程序，使用 pugLoadProgram() 函数。该函数返回指向 PUGProgram 结构的指针，你需要保存它，并传给其他框架函数，以便把常量与流绑定到内核并运行内核。

流管理

框架中的数据数组称为缓冲。pugAllocateBuffer() 函数创建一个新缓冲。缓冲可以是只读、只写或读写，可用该函数的 mode 参数指定。该函数返回指向 PUGBuffer 结构的指针，可以传给框架中的许多函数，包括下面两个。

要把初始数据装入缓冲，把数据传给 pugInitBuffer() 函数。

要把内核的某个输入流绑定到缓冲，调用 pugBindStream()，其参数为：要绑定到的 PUGProgram 指针、PUGBuffer 指针，以及一个字符串，内容是该 PUGBuffer 应绑定到的 Cg 内核程序中 Stream 参数的名称。

指定计算域与计算范围

要指定计算的域与范围，定义一个 PUGRect 结构，给出矩形四角的坐标，该矩形用作域或范围。可以指定多个域。它们会生成额外的纹理坐标，供内核程序按需使用。

要绑定一个域，调用 pugBindDomain()，传入 PUGProgram、内核 Cg 程序中为该域定义的字符串参数名，以及该域的 PUGRect。

一个内核只能有一个范围，因为片元程序无法做分散写。要指定范围，只要把一个 PUGRect 传给 pugRunProgram() 函数的 range 参数。

指定常量参数

单分量、双分量、三分量或四分量的浮点常量参数可以用 pugBindFloat() 指定，其参数为：PUGProgram 指针、字符串参数名，以及最多四个浮点值。

调用内核

完成上述步骤后，执行计算很简单：只要调用函数 pugRunProgram()。传入 PUGProgram 指针、输出 PUGBuffer（必须可写），以及一个可选的 PUGRect 来指定范围。若不指定范围，则写入整个缓冲。

注意，如果某个缓冲当前正被用作内核的输出，就不能把流绑定到该缓冲。对于在 pugRunProgram() 中被指定为输出缓冲的任何缓冲，框架会自动释放绑定到它的所有流。

把数据取回 CPU

要把 GPU 上的结果取回 CPU，调用 pugGetBufferData() 函数，传入 PUGBuffer 指针。该函数返回指向 float 类型 C 数组的指针。从 GPU 读回数据可能导致 GPU 管线冲刷，因此要少用这个函数，以免损害应用性能。

并行归约

框架支持三种简单的并行归约。缓冲可以按行归约（归约为单个列向量）、按列归约（归约为单个行向量），或两者都做（归约为单个值）。这些操作的框架函数是 pugReduce1D() 与 pugReduce2D()。

31.5 一个简单示例

作为一个基础但不平凡的 GPGPU 例子，我们仿真一种称为化学反应的扩散现象。反应–扩散是描述溶液中两种或更多反应物的浓度在经历化学反应与扩散过程时如何在空间和时间中演化的模型。我们所用的反应–扩散模型称为 Grey-Scott 模型（Pearson 1993），只涉及两种化学反应物。这个现象学模型并不代表某个真实的化学反应；它只是研究一般反应–扩散现象的简单模型。图 31-3 展示了 Grey-Scott 模型多次迭代的结果。

示例 31-1. 反应–扩散内核程序

float4 rd(float2 coords
          : DOMAIN, uniform stream concentration, uniform float2 DuDv,
            uniform float F, uniform float k)
    : RANGE
{
  float2 center = concentration.value2(coords).xy;
  float2 diffusion = concentration.value2(coords + half2(1, 0));
  diffusion += concentration.value2(coords + half2(-1, 0));
  diffusion += concentration.value2(coords + half2(0, 1));
  diffusion += concentration.value2(coords + half2(0, -1));
  // 取平均并按扩散系数缩放
  diffusion *= 0.25f * DuDv;
  float2 reaction = center.xx * center.yy * center.yy;
  reaction.x = -1;
  reaction.x += (1 - DuDv.x) * center.x + F * (1 - center.x);
  reaction.y += (-F - k + (1 - DuDv.y)) * center.y;
  // 现在把扩散加到反应上，得到结果。
  return float4(diffusion + reaction, 0, 0);
}

{ // 每次迭代都要调用
  pugBindStream(rdProgram, "concentration", rdBuffer, currentSource);
