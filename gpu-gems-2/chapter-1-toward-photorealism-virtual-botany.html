非茗的翻译文档库

第 1 章　迈向虚拟植物的照片级真实

David Whatley
Simutronics Corporation

实时渲染自然场景，同时为游戏引擎的其他需求留出足够的 CPU 与 GPU 资源，是个难题。植物的图像要有说服力，需要很强的视觉纵深与细节。本章讲述如何以对实时游戏引擎友好的方式渲染更具照片级真实感的自然场景。这里的方法协同工作，营造出遍生草木的草地质感，同时不让 CPU 或 GPU 不堪重负。这些技术用于 Simutronics 的 Hero's Journey，如图 1-1 所示。

我们首先讲述在大型户外环境中管理场景数据的基础。接着说明如何最大化 GPU 吞吐量，以达到所需的草叶视觉密度。然后把这些技术扩展用于地面杂物和树木等更大尺度的植物。最后用阴影和环境效果把画面统一起来。

1.1 场景管理

游戏引擎必须管理其渲染技术，使之与它想要可视化的环境规模相匹配。以自然场景为特色的游戏关卡由成千上万棵树与灌木、或许数百万片草叶组成，会带来重大的数据管理问题，必须解决才能以交互帧率渲染。

有说服力地渲染虚拟自然场景既是艺术挑战，也是技术挑战。我们可以像画家那样对待自然场景的渲染：把元素拆成图层，各自独立处理，最终合成一个整体。例如一层草、一层地面杂物、一层树，等等。这些图层共享一些共性，我们可以借此压缩数据表示。

我们的目标是让游戏相机在长距离的逼真户外场景中行进，而不必为此投入过多的内存资源。借助受引导的确定性随机数生成，我们有一个算法能以合理的方式「种下」自然界的全部元素，并且每次回到地图上同一处都得到相同的视觉结果。在网络游戏中，每个人看到的东西都一样，细到一片草叶的位置，而这个位置并不需要永久存储在内存里。

1.1.1 种植网格

我们在相机周围建立一个世界空间的固定网格，用来管理每一层植物和其他自然物体的种植数据。每个网格单元保存渲染其图层在其所占物理空间内所需的全部数据。具体说来，单元数据结构保存对应的顶点缓冲和索引缓冲，以及表示所绘制内容的材质信息。

对每一层植物，我们确定该层要生成画面所需距相机的距离，由此决定虚拟网格的大小。相机移动时，虚拟网格随之移动。某个网格单元不再属于虚拟网格时，就丢弃它，并在需要处补入新单元，以维持完整的网格结构。每加入一个单元，就用种植算法为该层填入合适的渲染数据。见图 1-2。

1.1.2 种植策略

对每个填入自然物体的单元，都要在地面上挑选合适的位置放置这些物体。选取位置的启发式规则取决于所放置物体的类型。一般做法是按某个期望密度随机取点，再看地面上对应的点是否适合种植。在我们的实现中，地面多边形的材质决定哪些图层适用。

最直白的做法是在单元体积内向地面随机垂直投射射线。每次命中多边形，就检查它是否合适（这里能种草吗？坡度是不是太陡？）。若通过，就得到一个种植点。如此反复，直到达到所需密度。

这种做法效果不错，但有明显问题。其一，在适合种植的位置很少的网格单元中（例如只有一块标记为草地的多边形顶部），为了靠随机取点达到密度要求可能耗费大量 CPU 时间。因此最坏情况下，必须在尝试次数达到某个上限时放弃搜索。其二，这种做法无法处理地形自重叠的情况（例如陆桥）。

更好的做法是收集与该单元相交的所有多边形，剔除所有不适合种植的多边形，再对它们做扫描转换以找出合适的种植位置。这类似渲染时对多边形做光栅化，只不过遍历中的每个「像素」都是一个世界空间中可能的种植点。要注意让扫描转换的步长与密度相称，同时不越出三角形的边界。此外，在每个选定的种植点上，还要沿多边形平面偏移一个合适的随机距离，以消除重复图案。这些值都是可调系数，应在设计阶段确定。在我们的实现中，设计师可以交互地调整这些值，为该图层调出理想效果。

最后，扫描转换时还必须注意在多边形边缘处剪裁（做偏移时），以及剪裁到单元边界，因为多边形可能延伸到单元之外（那里由另一个单元负责种植）。

这种种植既可以实时进行，也可以作为离线关卡预处理的一部分。后一种情况下，草的种植位置应以高度压缩的形式存储；运行时随着移动的相机把每个单元加入可能可见的单元集合，再把这些数据解压。

1.1.3 实时优化

若这种种植实时进行，必须保证种植操作足够快。借助 AABB 树或类似的数据结构，可以快速收集网格单元内的多边形。由于相机持续移动，可能突然需要种植许多单元，因此把这项任务排队也很有效，这样每帧在种植上只花相对固定的 CPU 时间。通过扩大网格尺寸，我们可以相当有把握地保证：在单元内容进入视野之前，相应的种植都已完成。

1.2 草图层

要在一望无际的草地上获得交互帧率，需要仔细平衡 GPU 技术与算法。关键挑战在于以相对较低的计算与渲染开销，做出表观视觉复杂度很高的画面，从而形成有说服力的草地体积感。这里介绍一种与 Pelzer（2004）在「Rendering Countless Blades of Waving Grass」中提出的技术类似的做法。我们的技术以更低的 GPU 与 CPU 负担取得质量更高、更稳健的结果。图 1-3 显示了用我们的技术渲染的场景。

显然逐片绘制草叶不可行。但我们可以用草簇来营造这种错觉，草簇最好用朝向相机的四边形配上合适的草纹理来表示。这类公告板以极小的代价造出体积感。不过大片草地仍可能需要过多的绘制调用，所以必须仔细组织 GPU 的用法，以达到足够的体积与密度。

GPU 在一次性提交大批次绘制时表现最好。因此我们的目标是设法用较少的 API 绘制调用来绘制成片草地。朴素做法是一次画一个公告板，而我们想要的是在一次绘制调用里尽可能多地绘制。

为此我们采用这样的技术：创建一个顶点缓冲和一个索引缓冲，填入大量草公告板，然后用一次调用把所有这些公告板画出来。这个算法类似通过循环展开来加速 CPU 循环。

对我们的用途而言，每一层草——即使用同一纹理和其他参数的所有草——在每个网格单元中由一对顶点缓冲和索引缓冲表示，如图 1-4 所示。每栽下一簇草（或一个公告板），就把其位置写入顶点缓冲，并相应更新索引缓冲。每个公告板需要四个顶点和六个索引。每个顶点的位置都设为该草簇的种植点。这意味着一个公告板的四个顶点位置完全相同，我们在顶点着色器中偏移这个位置，做出正确的朝向相机的四边形形状。另一种做法是，若草纹理能装进三角形，每个可省下一个顶点的处理；更好的是，此时索引变得不必要，可以完全省略而不损失性能——渲染这类三角形堆时，没有任何顶点能复用变换与光照之后的缓存。

顶点缓冲创建好并送入显存后，就能用一次绘制调用画出每个网格单元范围内的植物。在 GPU 上，我们用顶点着色器偏移各个顶点，使它们构成与屏幕对齐的四边形。由于每个顶点偏移的方向不同，必须区分哪个顶点构成四边形的哪个角。为此我们在顶点数据中增加两个浮点数，取值为 -1、0 或 1：第一个对应屏幕的 x 方向，第二个对应 y 方向。把这个因子乘以 x 和 y 方向的缩放值，即可按需偏移。此外，可以把所有的 -1 和 1 随机改成略有不同的值（例如 0.98 或 -1.2），让每簇草的大小有所差异。

虽然我们打算在屏幕空间移动顶点，但所有计算都在世界空间完成，这样透视效果是自然得到的。为此我们给顶点着色器提供一个指向相机右方的向量，以及一个指向相机上方的向量。简单的运算就能把顶点移到正确位置：

// 对每个顶点，我们为 x、y 传入 -1、0、1 值，它决定
// 该顶点如何被相机的 right 与 up 向量移动。这个值
// 我们作为纹理坐标（inTexCoord2）传入。
Out.Pos = Input.inPos + (Input.inTexCoord2.x * RightVector) +
          (Input.inTexCoord2.y * UpVector);

我们的做法与 Pelzer 不同：我们用朝向相机的公告板，而不是每簇三个四边形且不做屏幕对齐。朝向屏幕的公告板在任何视角下（即便俯视）都呈现恒定的纵深，而三四边形草簇的做法在相机越接近垂直俯视草地时越会失效。第三人称相机视角在许多类型的游戏和仿真中很常见，并非罕见的相机角度。

1.2.1 用溶解模拟 alpha 透明

渲染草时我们想用透明来改善视觉融合，并在虚拟网格边界附近随距离渐隐。然而基于 alpha 的透明远非理想，因为它需要排序，而排序很慢。虽然有些技术利用草的杂乱特性减少了一部分排序（Pelzer 2004），我们其实可以完全省掉排序。

做法是用溶解效果（也称筛网效果）代替 alpha 混合来模拟半透明。我们用一张噪声纹理调制草纹理的 alpha 通道，再用 alpha 测试剔除像素不参与渲染。把 alpha 测试的阈值从 0 滑到 1，纹理看上去就逐渐溶解。过程如图 1-5 所示。SpeedTreeRT 这个用于实时植被制作的商业软件包最早采用这种技术，在启用 alpha 测试的前提下做细节层次之间的过渡。Simutronics 为 Hero's Journey 授权使用了 IDV 的 SpeedTreeRT，本章中取自或改编自这套商业植被工具包的技术都会注明。

这种技术的好处在于 alpha 测试很快且与顺序无关。我们不再需要排序，草却能在远处渐隐。虽然在通常情况下溶解远不如真正的 alpha 半透明好看，但我们可以利用自然界的自相似特性，把筛网技术的视觉瑕疵完全遮住。实验发现，若用 Perlin 噪声纹理（Perlin 2002）而非随机噪声纹理，溶解效果与环境的契合度足以接近 alpha 半透明。

不过有一个问题：所选的 alpha 测试阈值需要依据每个公告板到相机的距离。然而每批（每个网格单元）只能用一个 alpha 测试值，即使这一批里的草簇距离各不相同——因为整个网格单元是在一次绘制调用中渲染的。既然希望每个草公告板按各自到相机的距离精确渐隐，我们就选定一个固定的 alpha 测试值，改为在着色器中调整 alpha 通道，按到相机的距离以及草开始可见的最大范围，把它们线性插值到完全不透明。具体做法是调整顶点着色器输出颜色的 alpha 分量，由它在像素着色器中衰减纹素的 alpha（这也可以用固定功能管线完成）。

还可以对最靠近相机的网格单元再加一遍，用 alpha 混合绘制，把草叶边缘羽化融入场景，消除近处草叶的硬边。这能以多一遍为代价换来略好的合成效果。但由于仍然使用 alpha 测试，写入后台缓冲的像素相对很少（至多只是草叶边缘）。alpha 混合与 alpha 测试配合良好；通常值得两者都试一试，以获得最佳的纵深与体积错觉。

1.2.2 变化

为了提高草的真实感，我们想在不影响帧率的前提下尽量增加变化。一种做法是用多种草图像，但批处理方式限制我们每次绘制调用只能用一张纹理。好在我们可以用一张更大的纹理，上面排布不同的草的变体。构建顶点时，可以调整 UV 坐标来选取纹理的不同子区域（也就是构建纹理图集；这项技术的更多内容见 NVIDIA 2004）。例如在一张纹理上放四种不同的草簇变体是很容易的。此外，在把草四边形展开写入顶点缓冲时，可以随机翻转 U 坐标来镜像图像。注意在图像之间留出空隙，以免 mipmap 引入纹素渗色的瑕疵。

每个公告板还可以携带颜色信息。若在种植时也为每一丛设定颜色，这对给灰度纹理上色或在顶点着色器中做细微的色彩偏移非常有用。我们发现 Perlin 噪声在这里同样管用。例如很容易把草从健康的绿色染向枯黄的褐色，形成大范围的色彩变化，打破草的重复感。见图 1-6。

1.2.3 光照

光照对草的外观影响很大。对公告板草，我们要确保草被照亮的方式与它下面的地面一致。地面天然起伏，因而接收到不同角度的阳光，我们希望用衰减草的亮度来模拟这一点。为此需要知道草所在地面的角度。一个简单的办法是把这一信息作为另一个向量放进顶点定义里。种植时我们求出种草处多边形的法线，把它随草公告板的定义一起带上。这样顶点着色器就能做与草下方多边形相同的光照计算，并衰减草的颜色与之匹配。在起伏的地形上，这会让草也带上地面那种细微的受光角度暗示。

可惜这种做法会让草呈现面片化的着色，尽管地面多边形很可能是光滑着色的（例如 Gouraud 着色）。为消除这一差异，随顶点着色器传入的法线本身必须在种植过程中做光滑插值。

若太阳角度是动态的，可以简化处理：假定地面法线大致竖直向上，再据此法线和光线角度做光照。这样就不必在顶点定义中计算或携带地面多边形的法线。这里存在质量上的权衡，但对我们的应用来说已经够用。

1.2.4 风

风一吹，草就有了生气。每帧偏移草四边形的上面两个顶点，就能让四边形随风摆动。我们用正弦求和近似来计算这个偏移，类似计算水面起伏（Finch 2004）。诀窍是在顶点定义中带一个混合权重：草四边形上面两个顶点设为 1，下面两个设为 0。然后把风的缩放因子乘以这个值，使底部顶点牢牢固定在地里。为了增加变化，还可以在种植时对上面两个顶点的权重做一定随机化，模拟有的草更硬、有的更软。

草叶随风摆动时常常改变朝向光线的角度，因而忽明忽暗。我们可以用风的相关项增强光照来模拟这一效果。这能显著改善风的视觉效果，即使对距离远到物理摆动形变已不足一个像素的草簇也有效。

但要注意，不应让风因子把草四边形变形得太多。变形过大会显得滑稽而不真实。分寸是关键。

1.3 地面杂物层

地被不只是起伏的草地。枯枝、小植物、石块和其他碎屑共同补全了自然复杂性的错觉。其中一些可以像草那样用公告板表示，但掺入各种几何物体能增强环境的丰富度。

与处理草公告板一样，我们把三维网格数据展开写入每个网格单元的顶点缓冲和索引缓冲，然后用一次调用绘制。必须把地面杂物按所用纹理和着色器分组成层。挑选种植点时可以施加随机变换来改变其大小和朝向，但变换必须依网格的性质而定：倒过来的石块无妨，倒过来的灌木就不行。为增加变化，还可以像处理草多边形那样传入 RGB 信息给物体上色。

用于处理顺序无关透明效果的溶解技术，对三维网格与对公告板完全一样。我们用 Perlin 噪声纹理调制纹理的 alpha 通道，并按到相机的距离衰减，然后 alpha 测试就像对草公告板那样把三维网格溶解掉。

每个顶点可以带一个权重值，这样就能把与公告板相同的风计算套用到三维物体上。石块、枯枝这类物体当然要保持刚性，而多叶植物可以带美术设定的权重以达到理想效果。图 1-7 显示了带地面杂物的场景示例。

1.4 乔木与灌木层

树干和主枝应当用三维网格建模。次级枝条可以用公告板模拟，以增加视觉复杂度。对多叶的树，可以用与草类似的技术，用朝向相机的公告板做出叶簇。

下面渲染乔木与灌木的做法基于 SpeedTreeRT，它为树木资产提供全部实时渲染信息，并包含用于参数化生成树木的 SpeedTreeCAD（IDV 2004）。树木的实际渲染仍由游戏引擎负责，这让开发者在实现上有很大的灵活性。

树木在远处仍要保持基本的体积感，而精细渲染代价很高，因此必须采用细节层次（LOD）策略。树离得越远，就可以用越大、数量越少的叶簇公告板。对较大的公告板，我们改用另一张纹理，上面叶子更多但每片更小。

为效率起见，与一棵树相关的所有纹理应合并到一张纹理中，如图 1-8 所示。实际上更好的做法是把多棵树的纹理打进一张纹理，这样一次调用就能画更多树。

到某个合适的距离，我们最终想用一个朝向相机的公告板来表示一棵树。当树的轮廓不对称时这会比较困难。解决办法是按不同角度生成树的公告板图像，再依据树与相机的角度在它们之间混合。

若树木是手工摆放的，我们发现最好让关卡设计师对每个实例的 LOD 过渡点做精细控制。在树木密集的区域，LOD 过渡可以离相机相当近；而在视线很长但树较少的其他地方，保持高细节、避免视觉瑕疵更容易。

灌木和大型叶状植物可以用许多相同的技术当作另一类树来处理。例如多叶的灌木就是树干很小或没有树干的树。此外还可以把一棵树倒过来、关掉叶子，得到一个精细的裸露根系，与正常的树拼接。

树木可以在标准建模软件包中制作，但美术需要某种机制来指定叶点和枝条公告板的位置，这会让导出变复杂。树木的实际渲染仍由游戏引擎负责，这让开发者在实现上有很大的灵活性。

1.5 阴影

由于我们为草和地面杂物传入 RGB 色调，可以为处在阴影中的区域选一个较暗的色调。这要求我们知道每个种植项是否在阴影中。要在自然环境中奏效，这类阴影只需粗略近似正确的阴影即可。见图 1-9。

一种做法是在种植时判定阴影。只需从种植位置朝主光源（太阳）投射一条阴影探测射线，看是否有交点。若有，就把 RGB 值朝场景的环境色调整。记住，阴影探测射线只关心是否有任何交点（不只最近的交点），因此比标准的碰撞射线投射高效得多。

软阴影（在此语境下技术上称为抗锯齿阴影）可以通过投射不止一条阴影探测射线来实现。图 1-10 显示了其中的原理。把每条射线的起点稍微错开，就能从给定位置投射三到五条射线，用命中的比例在漫反射阳光照明与场景环境光之间衰减光照。加大偏移量会增加阴影的柔和程度。

这类阴影不是动态的，但对移动缓慢的光源（例如行进的太阳）可以按一定间隔较快地重算。总体而言，它们提供的视觉暗示足以让景物显得更真实。

可以用专门的近似技术，让射线穿过树的整体体积时判定为命中阴影。不必去求与单片叶子的交点，只需与树冠部分的球形体积或树干的圆柱体求交。对树冠部分，可用随机函数按叶片密度判定射线是否相交。这种阴影技术虽然粗糙，但与精确解在视觉上分辨不出来。

若种植是作为离线流程预先算好的，阴影的保真度可以大幅提高。除阴影探测射线之外，还有一种办法是查看光照贴图的纹素来判定阴影。如果光照贴图不在系统内存中，这在实时条件下会比较困难。

1.6 后处理

自然环境对阳光的反应很难实时模拟。与多数交互式技术一样，目标是找到能给出合理（即便不精确）结果的方法。借助后处理效果，我们可以把画面统一起来，营造出更出色的环境。

全场景后处理泛光在游戏中常用于魔法和高科技效果，把这一简单技术扩展用于自然效果也被证明有效。实时泛光技术既能模拟光晕，也能产生自然的柔化效果（由高斯模糊带来）（James and O'Rorke 2004）。不过泛光是加法效果，制作纹理时必须注意这一点，很容易一时兴起把场景弄得过亮。与所有效果一样，少量有效并不意味着越多越好。

1.6.1 天空穹顶泛光

带纹理的天空穹顶为利用泛光提供了很好的机会。我们可以把穹顶的 alpha 通道留给美术，用来标出更明亮的区域，让美术对太阳与云的相互关系有很大的控制权。渲染天空穹顶时，只需把这一 alpha 层加到泛光通道上。图 1-11 是一个示例。

泛光量充足的天空穹顶会在树叶与枝条的纤细结构周围泛出光晕，带来一种几乎立刻就能察觉的逼真感，如图 1-12 所示。由于天空泛光由美术控制，这种技术格外有效、调节精细，而且没有额外开销。

1.6.2 全场景泛光

自然环境的摄影常常借助在相机镜头前加一层柔光纱（薄棉布）的技术来增色。如果已经用了后处理泛光，只需把泛光通道清成一个可调的非零值，就能得到全场景泛光。由于泛光基于高斯模糊模拟，这会让整个画面显得朦胧；明亮区域也会轻微泛出光晕，而不必动用更昂贵的 HDR 效果。对自然户外场景，这种做法能极大缓解多边形那种生硬的计算机生成感，且不增加 GPU 开销（因为全场景泛光处理本来就在进行）。见图 1-13。
