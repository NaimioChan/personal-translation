第四部分：GPU 通用计算入门

本书这一部分想为图形处理器上的通用计算（即如今常说的「GPGPU」）世界提供一个平易的入门。正文的写法既面向没有图形经验的程序员，也面向写了多年图形程序、但对其他应用的并行计算了解不多的人。

自 GPU Gems 出版以来，GPGPU 已从某种奇趣之物成长为图形与系统研究中一个受人重视、活跃的新领域。

你为什么会不嫌麻烦地把自己的计算问题改到 GPU 上运行？原因有两个：价格与性能。经济因素加上电子游戏成为大众娱乐，把价格压到了这样的程度：如今你只花几百美元，就能买到一块每秒可做数千亿次浮点运算的图形处理器。

GPU 并不适合所有类型的问题，但有很多应用借助图形硬件实现了显著的加速。性能最好的应用通常是那些「算术强度」高的——也就是数学运算与内存访问之比很大的。这类应用从音频处理和物理仿真，一直到生物信息学和计算金融。

凡是接触过现代计算的人，都不可能不注意到我们这个行业技术变革的迅猛步伐。本部分的第一章是加州大学戴维斯分校 John Owens 写的第 29 章「流式架构与技术趋势」，它通过描述推动 CPU 与 GPU 两者演进的半导体设计与制造趋势，为后面的章节搭好舞台。推动这些变化的重要因素之一是内存「鸿沟」——计算速度的提升远快于内存访问速度。这一章还引入了「流式」计算模型，它与现代 GPU 硬件的特性相当契合。采用这种编程风格，应用开发者就能利用 GPU 庞大的计算与内存带宽资源，所得程序相对等效的 CPU 实现能取得很大的性能提升。

NVIDIA 的 Emmett Kilgariff 和 Randima Fernando 合写的第 30 章「GeForce 6 系列 GPU 架构」详细描述了一款当前最先进的图形处理器 GeForce 6800 的设计。这一章由该芯片的首席架构师之一参与撰写，包含许多别处找不到的硬件底层细节。对任何编写高性能 GPU 应用的人来说，这些信息都极有价值。

本书本部分余下的内容接着是几章教程式的文字，讲解如何用 GPU 解决通用问题的细节。

NVIDIA 的 Mark Harris 写的第 31 章「把计算概念映射到 GPU」，讨论把计算问题转换为在 GPU 并行硬件上高效运行所涉及的问题。GPU 实际上由若干个可编程处理器加上一批固定功能硬件组成，这一章说明如何最好地利用这些资源。

斯坦福大学的 Ian Buck 写的第 32 章「投身 GPU 计算」，更详细地说明了 CPU 与 GPU 在内存带宽、浮点数表示和内存访问模型方面的差异。正如 Ian 在引言中所说，GPU 当初并不是为通用计算设计的，要让它高效运转需要一些用心。

GPU 编程最困难的领域之一是通用数据结构。CPU 程序员习以为常的链表、树这类数据结构，在 GPU 上实现并不简单。GPU 不允许任意内存访问，主要处理为表示位置和颜色而设计的四分量向量。尤其困难的是稀疏数据结构——它们在内存中没有规则的布局，而且结构的大小可能逐元素不同。

加州大学戴维斯分校的 Aaron Lefohn、犹他大学的 Joe Kniss 与 John Owens 合写的第 33 章「在 GPU 上实现高效的并行数据结构」，概述了流编程模型，接着讲解在 GPU 上实现多维数组和稀疏数据结构等数据结构的细节。

传统上，GPU 并不擅长执行带分支的代码。由于它们是并行机器，只有在同一操作能施加到每个数据元素上时性能才最好。Mark Harris 与 Ian Buck 合写的第 34 章「GPU 流控制惯用法」，说明在 GPU 上高效实现循环、if 语句等流控制结构的各种办法。其中包括利用现代 GPU 的深度测试与 z 剔除能力，以及最新版像素着色器硬件中可用的分支指令。

弗吉尼亚大学的 Cliff Woolley 花了大量时间编写 GPGPU 应用，（和我们许多其他作者一样）已基于自己的研究发表过多篇论文。在第 35 章「GPU 程序优化」中，他传授了优化 GPU 代码的最佳做法，以及如何避免 GPU 编程新手常犯的错误。人们常说过早优化是万恶之源，但总得在某个时候做。

在 CPU 上，写出每个输入数据元素对应输出量可变的程序很容易。不幸的是，在 GPU 这样的并行机器上要困难得多。斯坦福大学的 Daniel Horn 写的第 36 章「GPGPU 应用中的流归约操作」，展示了用 GPU 编程实现过滤操作的几种方式，这些操作从数据流中移除元素，以产生数量可变的输出。他演示了如何用这项技术高效实现碰撞检测和细分曲面。

CPU、GPU 以及 PC 生态中其他处理器之间最终如何分工，只有时间能告诉我们。有一点是确定的：半导体设计的现实与内存鸿沟意味着数据并行编程会一直存在。今天就学会用这种风格表述你的问题，你就能确保自己的代码在未来所有硬件上继续以可能的最快速度执行。

Simon Green, NVIDIA Corporation
