细节丰富的三维几何体若用硬件的原生多重采样渲染，会出现明显的走样瑕疵，因为多重采样目前只限于一像素的盒式滤波和较低的采样率。本章介绍一种分块超采样技术，可以用任意宽度的用户自定义滤波器和很高的采样率渲染任意分辨率的图像。这里的代码用在 Gelato 影视渲染器中，借助 GPU 生成质量毫不妥协的图像。图 21-1 是一个例子。

我们说明如何把图像切成瓦片，把每块以高分辨率渲染，然后用即时生成的片元程序做两趟可分离降采样，把每块降采样（即缩小）到最终分辨率。我们给出瓦片与滤波器正确重叠与填充的细节，并在随书 CD 上提供代码，可以不加多少修改就并入现有的渲染系统。代码还包含若干处理 GPU 与可分离滤波器的实用库。

21.1 概述

为了支持很高的超采样倍数和很大的最终图像，我们先把最终图像切成固定大小的矩形瓦片（有时称为桶），如图 21-2 所示。GPU 上可用的帧缓冲内存往往不足以放下一个足够大、能在降采样之前渲染高度超采样图像的单帧缓冲。此外，你可能还想用这份有限的资源存放渲染所需的其他数据：纹理、顶点缓冲对象等等。要渲染一张大到塞不进窗口的海报尺寸图像，把图像切成瓦片也很方便。同一技术还可以用来按瓦片对几何体「分桶」（Apodaca and Gritz 1999），以减小渲染时的工作集，不过本章不直接讨论这个题目。由于我们的技术不限制渲染瓦片所用的算法，它可以很容易地与运动模糊、景深、透明或其他效果的多趟算法结合。

我们在 GPU 上对每块高分辨率瓦片做降采样。用的是常见的可分离卷积（James and O'Rorke 2004），第一趟滤波行、第二趟滤波列，额外多一层复杂性：输出图像比输入图像小。每趟的片元程序都把滤波值作为常量编入其中（Bjorke 2004）。这些片元程序由我们根据所选滤波器形状、滤波宽度和超采样倍数即时生成。

因此整体算法如下。对最终图像的每一块：

  1. 把该瓦片渲染到一个大的离屏缓冲中，调整投影矩阵，让你现有的渲染代码以超采样分辨率渲染三维几何体。
  2. 用可分离的滤波器核把高分辨率瓦片降采样到最终分辨率的瓦片，做法是用即时生成的自定义片元程序渲染两个全屏四边形。
  3. 把低分辨率瓦片累积到最终图像中：或者把瓦片数据读回 CPU，或者再用一个片元程序把该瓦片的贡献加进一块累积最终结果的缓冲。

现在我们由内向外讲这个算法，先讲核心的降采样滤波算法，再扩展到外层的脚手架。讲解用一个示例程序来说明，它把几何体文件（.obj）渲染到离屏缓冲，再把结果存成图像文件（.ppm）。算法参数的汇总见代码清单 21-1，后面讨论中会用到。

21.2 降采样

考虑某块瓦片的某一条扫描线。这块超采样瓦片包含（ssx * tx）个输入像素（或称「样本」），要降采样成 tx 个输出像素。每个输出像素是附近若干输入样本的加权平均。权重由所选滤波器形状决定，样本数由所选滤波宽度和超采样倍数决定。（这仍然只是卷积，只不过输入输出分辨率不同。）图 21-3 展示了给定输出像素时滤波器如何覆盖在输入样本之上。注意滤波器中心在源像素与目标像素上的位置。

21.2.1 与现有硬件和软件方法的比较

在当前的硬件多重采样中，每个最终像素是它所覆盖样本的简单平均。这等价于宽度为 1 的盒式（即常量）滤波器。对许多应用来说这已经够用，但更平滑、更宽的滤波器能得到更好的抗锯齿效果。这类滤波器能更好地去掉最终分辨率无法表示的空间频率。2x2 高斯滤波器是个不错的默认选择，但看一看当前的影视渲染器就会发现，它们支持各种各样的滤波器（sinc、高斯、Catmull-Rom、Lanczos、Mitchell 等等），默认滤波半径在 2 到 5 像素之间。自己试出喜欢的设置吧。

提高超采样倍数也能改进抗锯齿，对很小的亚像素三维几何体、或存在亚像素变化的着色器尤其如此。我们的算法也无法完全避开硬件限制。完整的超采样瓦片分辨率 (tx * ssx) 必须小于硬件支持的最大渲染表面。

此外，如果样本位置具有良好的分层随机分布（Dippé and Wold 1985），用更少的样本就能得到质量更好的图像，如图 21-4 所示。我们的算法使用规则样本，往往需要比类似的随机技术更高的采样率。这个问题在某种程度上被缓解了，因为超采样倍数提高时渲染的物体更大，而硬件渲染较大物体时往往表现更好。我们的技术与硬件多重采样并不冲突。事实上，新一代硬件支持旋转的样本网格，效果优于标准的规则多重采样。

21.2.2 在 GPU 上降采样

为了在 GPU 上降采样，我们把输入样本放在纹理的一行里，把输出像素作为离屏缓冲的一行渲染出来。回忆一下，绘制一个覆盖这些输出像素的矩形，会让当前片元程序对每个输出像素各执行一次（矩形就像 x 和 y 上的 for 循环）。我们提供一个片元程序，它计算若干纹素的加权和，权重来自滤波器，纹素索引取决于当前输出像素的 x 位置。

我们的做法是由滤波参数自动生成片元程序。生成的片元程序是直线代码，把所有滤波权重和像素偏移都作为数值常量写进去。这就避免了逐像素求值、乃至逐像素纹理查找滤波值，也避免了循环开销。虽然当前世代的片元程序语言支持循环，但我们发现这种情况下展开循环、把常量内联进去性能更好。

在深入细节公式之前，需要先讨论填充。

21.3 填充

考虑离瓦片边缘一个滤波半径以内的某个输出像素。这个像素的一部分贡献样本位于相邻瓦片里。要得到正确结果，最终像素必须合并两块瓦片（在角上区域是四块瓦片）的样本。为此我们对降采样输出缓冲的尺寸做填充：输出瓦片不只覆盖那些覆盖输入样本的像素，而是覆盖输入样本有贡献的所有像素。这把瓦片在每个方向上都扩大一个滤波半径。（注：把滤波半径想成一个样本为参与某个输出像素所能「走」的最大距离，会有帮助。）accumulate_tile() 函数负责把重叠区域的像素相加，得到最终图像。

考虑到滤波半径可能是分数，且部分样本落在像素边缘附近，实际的填充量如下（注意加上 0.5，以计入滤波器从像素边缘起可能覆盖的最大距离）：

int txpad = ceil(filterx / 2.0 + 0.5);
int typad = ceil(filtery / 2.0 + 0.5);

降采样后的瓦片总大小为 (tx + 2 * txpad) 乘 (ty + 2 * typad)。

降采样任意一块瓦片时，「缺失」的输入样本（即来自瓦片之外的输入样本）按黑色处理，因为这些样本会由相邻瓦片计入。纹理查找模式设为越界查找返回黑色。这样片元程序就能对每个像素执行同样的计算，包括靠近边缘的像素。

还有一个填充问题。最终图像边缘附近的像素需要来自最终图像之外的输入样本。因此在把图像切分成瓦片之前，我们也要对最终图像的尺寸做填充。再次考虑分数半径，并注意到角落像素本身已经覆盖了 0.5 的滤波半径，这里的填充量如下（注意减去 0.5，以计入滤波器以每个像素为中心这一事实）：

int resxpad = ceil(filterx / 2.0 - 0.5);
int resypad = ceil(filtery / 2.0 - 0.5);

例如，一幅 200x200 的最终图像，若以宽度 2（半径 1）的滤波器渲染，需要渲染 (ssx * 202) 乘 (ssy * 202) 个样本。见图 21-5。

21.4 滤波器细节

生成滤波片元程序有许多细节要处理正确。最重要的细节是：偶数与奇数超采样倍数有微妙差别。偶数采样倍数下，目标像素中心落在超采样图像的像素边界上；奇数倍数下，像素中心落在某个源像素的中心。图 21-3 展示了这一点，同时也画出了输出瓦片的填充（至少左侧部分）。只要滤波器与样本所代表区间的任何部分重叠，该样本就必须纳入（ceil() 函数在这里很有用）。代码清单 21-2 给出运行时生成 ARBFP1 片元程序的伪代码。Cg 和 HLSL 都提供程序字面化功能，因此不必像这里这样直接生成汇编语言。

示例 21-2. 生成降采样着色器

这个片元程序对最终分辨率瓦片某一行的每个像素各执行一次，从存为纹理的原始图像中取像素，生成该行滤波并缩小后的版本。注意样本数是超采样倍数与滤波器直径（以最终图像像素计）的乘积。

21.5 两趟可分离滤波

把一些 x 和 y 对调，同一算法就能生成用于对列降采样的片元程序。我们用这两个片元程序实现常见的两趟可分离卷积：先滤波行，再把结果作为新输入滤波列。（可分离滤波器是一般卷积滤波器的特例，可以表示为 x 与 y 两个一维滤波器的乘积。）

我们从尺寸为 (ssx * tx) 乘 (ssy * ty) 的超采样瓦片开始。先运行行降采样片元程序，得到分辨率为 (tx + 2 * pad) 乘 (ssy * ty) 的中间纹理。然后在该纹理上运行列降采样片元程序，得到最终分辨率的输出瓦片，尺寸为 (tx + 2 * pad) 乘 (ty + 2 * pad)。

21.6 分块与累积

图 21-5 展示了瓦片相对于最终图像的位置。回忆一下，瓦片向最终图像之外延伸了一个滤波半径。（渲染出来的瓦片彼此不重叠——绝不要渲染同一个像素两次。重叠只在降采样之后才出现。）最后一行或最后一列中的瓦片可能大部分是空的。

每一块瓦片依次以超采样分辨率渲染。如果投影矩阵被设为按最终分辨率 resx 乘 resy 绘制整个场景，我们可以追加一些缩放和平移，用来绘制特定的瓦片。对原点为（x, y）的瓦片，最终图像区域 [x, x+tx] x [y, y+ty] 被映射到窗口 [0, ssx*tx] x [0, ssy*ty]：

// 假定 cam2ras 即普通渲染所用的投影矩阵，
// 也就是从相机空间到最终图像光栅的变换。
Matrix4 ras2tile = Matrix4::TranslationMatrix(Vector3(-x, -y, 0)) *
                   Matrix4::ScaleMatrix(ssx, ssy, 1);
Matrix4 cam2tile = cam2ras * ras2tile;

我们用这个二维瓦片变换更新投影矩阵，然后对每块瓦片把场景渲染一次。

渲染完一块超采样瓦片后，我们用前面介绍的两趟滤波方法把它降采样到最终分辨率。随后降采样后的瓦片在正确位置被合并（累积）进最终图像；与先前瓦片的重叠区域相加。最终图像可以是另一个 OpenGL 窗口或离屏缓冲，这种情况下累积在 GPU 上完成；也可以在主存中，这种情况下累积在 CPU 上完成（例如缓冲太大、GPU 放不下时）。

21.7 代码

如代码清单 21-3 所示，程序先创建一个用于绘制的离屏缓冲。然后用输入参数构造观察矩阵、图像缓冲和滤波函数。

示例 21-3. 为超采样渲染做设置

// 创建绘制表面，用于渲染单个超采样瓦片
GpuPBuffer pbuffer(resx *ssx, resy *ssy);
GpuCanvas canvas(pbuffer);
// GpuCanvas 相当于 OpenGL 上下文
// 创建绘制模式，用来保存 GPU 状态向量
GpuDrawmode drawmode;
float fov = 90;
float hither = 0.1;
float yon = 10000;
Matrix4 cam2ras = compute_cam2ras(fov, hither, yon, resx, resy);
// 分配 4 通道、fp32、RGBA 的最终输出图像缓冲
size_t nbytes = 4 * resx * resy * sizeof(float);
float *image = (float *)malloc(nbytes);
memset(image, 0, nbytes);
// 创建我们需要的滤波器
Filter2D *filter = Filter2D::MakeFilter("gaussian", filterx, filtery);
// 分配 4 通道、fp32、RGBA 的瓦片回读缓冲
int tilew = downsample.padded_tile_width(tx, *filter);
int tileh = downsample.padded_tile_height(ty, *filter);
float *tile = (float *)malloc(4 * sizeof(float) * tilew * tileh);

程序的主循环按行优先顺序逐块遍历输出图像，更新观察矩阵并调用渲染函数渲染一块高分辨率瓦片。随后瓦片被降采样、从 GPU 读回，交给累积函数。另一种做法是把瓦片移入纹理，在 GPU 上完成累积。

21.7.1 渲染循环

我们的代码全程使用 fp32 精度，以获得尽可能高的图像质量。它没有用渲染到纹理，只是因为最初开发时 Linux 上还没有这个功能。代码清单 21-4 是渲染循环。

示例 21-4. 渲染所有瓦片

// 把最终分辨率按滤波半径外扩，以生成
// 正确滤波最终图像边缘所需的像素
int fx = int(ceil(filter.width() / 2.0 - 0.5));
int fy = int(ceil(filter.height() / 2.0 - 0.5));
// 渲染所有瓦片
for (int y = -fy; y < resy + fy; y += ty)
{
  for (int x = fx; x < resx + fx; x += tx)
  {
    // 计算把该瓦片全屏渲染的矩阵
    Matrix4 cam2tile =
        compute_cam2tile(cam2ras, resx, resy, false, x, y, tx, ty);
    drawmode.view(cam2tile, tx * ssx, ty * ssy);
    // 绘制整个场景
    render(drawmode, canvas);
    // 由当前帧缓冲创建纹理
    GpuTexture fbtex("downsamplefb");
    fbtex.load(canvas, 0, 0, tx * ssx, ty * ssy, GL_FLOAT_RGBA_NV, true, 0,
               true);
    // 对渲染出的纹理降采样，存入一张新纹理
    downsample.run(fbtex, tx, ty, ssx, ssy, *filter);
    downsample.readback_padded_tile(tx, ty, *filter, tile);
    // 把结果纹理累加到最终图像中
    accumulate_tile(tile, downsample.padded_tile_xorigin(x, *filter),
                    downsample.padded_tile_yorigin(y, *filter), resx, resy,
                    tilew, tileh, image);
  }
}

21.7.2 降采样类

GpuDownsample 类通过创建离屏绘制表面、并根据超采样倍数与滤波器尺寸和类型生成自定义片元程序，实现两趟可分离降采样。该类提供函数来保证瓦片缓冲所需的填充。降采样后的瓦片留在 GPU 上，另提供两个函数把数据读回 CPU 缓冲，或把绘制表面转换成纹理（又一处我们本可以用渲染到纹理的地方）。

主要的降采样函数见代码清单 21-5。

21.7.3 实现细节

我们的代码用了若干实用库，都包含在随书 CD 的示例代码中。GPU 库是 OpenGL 的高层接口，提供构造窗口、离屏缓冲、纹理以及顶点与片元程序的例程。它还提供经过优化的顶点缓冲对象（VBO）图元绘制例程，在 Windows 和 Linux 下都能工作。它的 drawmode 对象封装 OpenGL 状态，减少状态切换，让调试容易得多。该库完全线程安全，并支持向多个缓冲绘制。

CD 中的代码还包含底层的向量与矩阵函数（在 CPU 上），以及一个平台无关的线程管理库。Filter 库提供一组常用采样滤波器。

21.8 结论

电影、视频和印刷往往需要比当前硬件原生提供的更好的抗锯齿。这里介绍的基于 GPU 的技术能达到与软件渲染器相同的图像质量，而对所用的基本场景渲染方法几乎不加限制。随附的示例代码很容易接到你现有的渲染程序上（我们希望如此），让你渲染出抗锯齿漂亮的画面。

这一技术用片元程序绕开了滤波质量限制，用分块绕开了缓冲尺寸限制。滤波这一步相当有效地利用了 GPU 的并行浮点算力。
