第 22 章　快速预滤波直线

Eric Chan
Massachusetts Institute of Technology

Frédo Durand
Massachusetts Institute of Technology

本章介绍一种针对直线的抗锯齿技术。走样的直线边缘呈锯齿状，直线运动起来时这种「锯齿感」尤其明显。虽然图形硬件支持直线抗锯齿，但其质量受许多因素限制，包括每像素样本数少、滤波器支撑窄、只用简单的盒式滤波器。此外不同硬件厂商使用不同算法，抗锯齿结果会因 GPU 而异。

本章提出的预滤波方法最初由 McNamara、McCormack 和 Jouppi（2000）开发，有几个优点。第一，它以固定的运行时开销支持任意对称滤波器。第二，常见硬件抗锯齿方案只考虑落在像素内的样本，而该方法支持更大的滤波器。结果与硬件无关，因此在不同 GPU 上直线抗锯齿表现一致。最后，算法快且易于实现。

22.1 锐利直线为什么难看

从数学上说，线段由其两个端点定义，但没有粗细、没有面积。可要在显示器上看到一条直线，我们就得给它一定粗细。所以在我们的语境里，一条直线由两个端点加一个宽度参数定义。在计算机图形学中，这个宽度通常以屏幕像素为单位给出。细线可能一像素宽，粗线可能三像素宽。

在尝试对直线做抗锯齿之前，必须先弄清我们究竟为什么会看到难看的走样瑕疵。假设我们在白底上画一条一像素宽的黑线。从信号处理的角度看，可以把这条直线看成一个信号，值 1 对应最大强度，0 对应最小强度。由于帧缓冲和显示器只有有限个像素，我们需要对该信号采样。采样定理告诉我们，要无走样地重建信号，采样率不得低于信号最高频率的两倍。

问题就在这里。边缘完全锐利的直线，对应的是频率无限高的信号！可以把一维直线的边缘看成一个阶跃函数，如图 22-1a 所示；离散样本在图 22-1b 中以蓝色竖线表示。直观上可以看到，无论采样多密，我们都无法足够准确地表示这个阶跃不连续。图 22-2 的三幅图展示了提高像素分辨率时直线外观的变化。结果如我们所料：走样随分辨率提高而减弱，但从不完全消失。

我们学到了什么？要重建边缘完全锐利的直线，唯一的办法是用无限分辨率的帧缓冲——这意味着要花无限的时间、内存和金钱。显然这不是什么实用的方案！

22.2 对信号限带

更实用的方案——也是本章介绍的方案——是对信号限带。换句话说，既然无法靠提高屏幕分辨率来表示原始信号，我们可以改为去掉那些无法再现的高频。这一操作的视觉结果是直线不再显得有锐利边缘，其边缘会显得模糊。这正是我们听到「抗锯齿」一词时通常想到的：多边形或直线边缘柔和平滑、看不到锯齿。

把信号与低通滤波器做卷积，就能去掉原始信号中的高频。图 22-3 用二维信号说明这一过程。图 22-3a 显示直线的锐利边缘。x、y 轴是二维图像坐标，竖直的 z 轴是强度值。左半边（z = 1）对应直线内部，右半边（z = 0）位于直线之外。注意 z = 0 与 z = 1 的边界处有锐利的不连续。图 22-3b 是一个以某像素为中心的低通滤波器，已归一化为单位体积。要计算图 22-3a 的信号与图 22-3b 的滤波器在某像素处的卷积，我们把滤波器放到该像素上，计算滤波器与信号相交部分的体积。图 22-3c 是这样一个体积的例子。对每个图像像素重复这一过程，就得到图 22-3d 中平滑的边缘。

把信号与低通滤波器卷积的想法虽然直白，但计算要在每个图像像素上做一遍。这让整个方法相当昂贵！幸运的是，正如下一节所见，所有昂贵的计算都可以放到预处理里完成。

22.2.1 预滤波

McNamara 等人（2000）提出了一种高效的预滤波方法，最初是为 Neon 图形加速器设计的。我们在此介绍他们的方法，并说明如何用现代可编程 GPU 上的像素着色器实现。

关键的观察是：如果假设我们的二维低通滤波器是对称的，那么卷积只取决于滤波器到直线的距离。这意味着我们可以在预处理中，把滤波器放在离直线若干不同距离处计算卷积，把结果存进一张查找表。运行时，我们求出每个像素到直线的距离，做一次查表就得到正确的强度值。Gupta 与 Sproull（1981）、Turkowski（1982）等许多其他直线抗锯齿技术都用了这一策略。

这一做法有几个很好的性质：

  • 我们可以用任何喜欢的对称滤波器，比如盒式、高斯或三次滤波器。
  • 滤波器求值昂贵或复杂都没关系，因为所有卷积都在离线完成。
  • 滤波器直径可以大于一个像素。事实上按照采样定理，它应当大于一个像素才能正确抗锯齿。另一方面，滤波器尺寸太大，直线就会过分模糊。

总结一下：这一做法以固定的运行时开销，支持用任意对称滤波器做预滤波的直线抗锯齿。既然已经看过预滤波方法的概貌，接下来从预处理开始深入一些细节。

22.3 预处理

关于这个阶段有许多问题要回答，例如表里需要多少项、用哪种滤波器、滤波器多大。我们边讲边看这些问题的答案。

先从对一组通用滤波器和直线参数如何计算这张表讲起。图 22-4 画出一条宽度为 w 的直线和一个半径为 R 的滤波器。我们区分数学意义上的直线 L（无限细、厚度为零）与边缘距 L 为 w/2 的宽直线。暂时先忽略直线的端点，假设直线无限长。

把滤波器与宽直线卷积，得到一个强度值。看看把滤波器放在离 L 不同距离处会得到什么值。当滤波器正落在 L 上时强度最大，如图 22-5a 所示，因为此时滤波器与宽直线的重叠最大。类似地，滤波器放在离直线 w/2 + R 处时强度最小，如图 22-5b 所示；这是滤波器与宽直线不再有任何重叠的最小距离。因此，滤波器从距 L 为 0 移到距 w/2 + R 处时，强度应当平滑下降。

这一观察结果正好提供了一种方便的表索引方式。索引表时不用以像素计的实际距离，而用归一化参数 d：滤波器正落在 L 上时其值为 1，位于距离 w/2 + R 处时其值为 0。用这种参数化的原因，是它让我们能一致地处理不同的 R 与 w 取值。

回到前面关于直线预滤波提出的几个问题。比如，该用哪种滤波器，它该多大？信号处理理论告诉我们，要消除重建信号中的走样，应当用 sinc 滤波器。可惜这个滤波器不实用，因为它的支撑是无限的，也就是说 R 会无界。好消息是用紧支撑的更简单滤波器也能取得不错的结果。实践中，对粗线（即 w 较大），我们倾向于用半径为两个像素、方差为 2 = 1.0 的高斯滤波器。但对更细的线，结果会偏软偏模糊，所以这些情况下我们用半径一像素的盒式滤波器。Blinn 1998 更详细地讨论了这些问题。记住，这一阶段算出的所有内容都属于预处理，运行时性能与滤波器选择无关。因此不妨为不同滤波器各预计算一张表，挑一个你喜欢的结果。

关于预计算还有一个问题：表需要多大？换句话说，应当在离 L 的多少个距离上做卷积？我们发现 32 项的表就绰绰有余。运行时把这表喂给 GPU 最自然的方式是用一维亮度纹理。一维的 32 项亮度纹理非常小，所以万一你发现 32 项不够，升到 64 项纹理，内存占用仍然很合理。

在进入算法的运行时部分之前还有一个问题：直线的端点怎么办？前面讨论与图 22-4 中我们完全忽略了端点，把 L 当作无限长。答案是：为方便起见，预处理阶段可以忽略端点，全部放到运行时处理。

22.4 运行时

上一节讲了预处理，它可以一次性全部在主机处理器上完成。现在说说算法的另一半。运行时我们做两类计算。第一，计算与直线相关的参数并传给 GPU。第二，在 GPU 上把每条直线保守地当作「宽」直线绘制，对硬件光栅器产生的每个片元，用 GPU 的像素着色器通过查表做抗锯齿。下面深入细节。

对给定直线，光栅器产生的每个片元对应一个样本位置。我们需要弄清如何用这个样本位置去索引预计算的查找表，从而得到该片元正确的强度值。记住，我们的表以参数 d 索引：样本正落在直线上时其值为 1，样本距直线 w/2 + R 像素时其值为 0。换句话说，我们要把样本位置映射到相应的 d 值。这可以用下面的直线设置算法高效完成。

如果四个结果中有任何一个小于零，就说明（x, y）距直线超过 w/2 + R 像素，该片元应当丢弃。

四个边缘函数的结果怎么用？我们需要一种既对宽直线的两侧、又对端点做抗锯齿的方法。McNamara 等人（2000）提出如下算法：

intensity = lookup(min(d0, d2)) * lookup(min(d1, d3))

看看这个方法如何工作。它取 d 0 与 d 2 的最小值，这两个函数对应两条侧边 E 0 与 E 2。类似地，它取 d 1 与 d 3 的最小值，这两个函数对应两条端边 E 1 与 E 3（见图 22-6）。然后用这两个最小值做两次查表。与 min(d 0, d 2) 对应的查表返回一个沿垂直于 L 方向变化的强度值；如所预期，靠近 L 的像素强度高，靠近 E 0 或 E 2 的像素强度接近零。如果 L 无限长，这就是唯一需要的一次查表。

不过由于需要处理 L 的端点，该方法还要做第二次查表（用 min(d 1, d 3)），它返回一个沿平行于 L 方向变化的强度值；靠近 L 端点的像素强度最大，而靠近 E 1 与 E 3 的像素强度接近零。把两次查表的结果相乘，就非常接近滤波器与有限长宽线段之间真实卷积的结果。这样得到的直线边缘和端点都平滑。

注意每个像素只需执行少量廉价操作。这让直线抗锯齿非常高效。

Cg 像素着色器源码见代码清单 22-1。手工优化的汇编版本只需要约十条指令。

示例 22-1. 用于直线抗锯齿的 Cg 像素着色器源码

void main(out float4 color
          : COLOR, float4 position
          : WPOS, uniform float3 edge0, uniform float3 edge1,
            uniform float3 edge2, uniform float3 edge3, uniform sampler1D table)
{
  float3 pos = float3(position.x, position.y, 1);
  float4 d = float4(dot(edge0, pos), dot(edge1, pos), dot(edge2, pos),
                    dot(edge3, pos));
  if (any(d < 0))
    discard;
  // ……计算颜色……
  color.w = tex1D(table, min(d.x, d.z)).x * tex1D(table, min(d.y, d.w)).x;
}

22.5 实现中的问题

22.5.1 绘制粗线

要让代码清单 22-1 的像素着色器工作，必须保证硬件光栅器产生与宽直线相关的所有片元。毕竟没有任何片元，我们的像素着色器也做不了什么有用的事！因此必须做保守光栅化，确保落在 w/2 + R 距离以内的所有片元都被生成。在 OpenGL 中，可以用足够大的值调用 glLineWidth 来做到：

glLineWidth(ceil((2.0f * R + w) * sqrt(2.0f)));

例如 R = 1、w = 2 时，应当以参数 6 调用 glLineWidth。我们还必须在每个方向上把直线延长 w/2 + R，使它足够长。

22.5.2 合成多条直线

到目前为止我们只考虑了绘制单条直线。有多条（可能重叠的）直线时会怎样？我们需要正确地合成这些直线。

完成这件事的一种办法是用帧缓冲混合，例如 alpha 混合。在像素着色器中，我们把求得的强度值写进 RGBA 输出的 alpha 分量，如代码清单 22-1 所示。在直线颜色全都相同的特例中，alpha 混合是可交换运算，所以绘制顺序无关紧要。但在直线颜色各不相同的更一般情形下，alpha 混合不可交换。这意味着必须对直线排序，并按逐像素的由后向前顺序绘制。这一要求用标准 z 缓冲无法总是正确做到，因此我们可以用启发式方法在物体空间近似一个由后向前的排序。一种启发式是按直线中点排序。虽然这种启发式偶尔会因排序错误而引入瑕疵，但这些瑕疵只影响有限数量的像素，实践中并不特别显眼。

22.6 示例

既然已经看过如何在 GPU 上实现预滤波直线，来看几个例子。图 22-7 把硬件渲染（开启与关闭 GPU 抗锯齿）与本章方法做了比较。第一行在空的白色背景上画一条宽度 1 的黑线；第二行是这条线的特写。第三行画一条宽度 3 的较粗黑线；第四行是粗线的特写。第三列与第四列分别是先用 R = 1 的盒式滤波器、以及 R = 2、 2 = 1.0 的高斯滤波器对直线做预滤波的结果。预滤波方法相对硬件抗锯齿在图像质量上的优势，在接近水平和接近垂直的直线上尤其明显。

直线抗锯齿的一个有趣应用是多边形边缘的平滑。虽然图形硬件对多边形抗锯齿提供内建支持，但用 Sander 等人（2001）提出的一个简单而有效的方法能得到更好的质量。思路是先按常规方式绘制多边形。然后把不连续边（例如轮廓线和材质边界）作为抗锯齿直线重绘一遍。例如图 22-8a 画的是一个未做抗锯齿的三角形。图 22-8b 把它的边缘画成预滤波的抗锯齿直线。把这些直线画在原始几何体之上，就得到图 22-8c 的结果。

图 22-9 给出三角形接近水平那条边的特写对比。图 22-10 给出三角形接近垂直那条边的特写。

不过这种多边形抗锯齿做法有一些局限。一个缺点是必须显式找出多边形模型的不连续边，对大型模型来说代价可能很高。另一个缺点是前面提到的由后向前合成问题。标准硬件多边形抗锯齿避免了这些问题，代价是图像质量。

22.7 结论

本章介绍了一种简单高效的直线抗锯齿方法。做法是把一条边缘与放在距边缘若干不同距离处的滤波器做卷积，把结果存进一张小表，以此实现直线的预滤波。这一做法以固定的运行时开销支持任意对称滤波器。此外算法只需少量的 CPU 与 GPU 算术、带宽和存储。这些特点使该算法适用于许多实时渲染应用，例如在游戏中渲染栅栏、电线和其他细结构。
