用 libfaust 嵌入 Faust 编译器

动态编译链

Faust 编译器使用一种中间表示 FIR（Faust Imperative Representation），它可被翻译成多种输出语言。FIR 语言以通用的方式描述对样本所做的计算。它包含读写变量和数组的基元、算术运算，以及定义必要控制结构（for 与 while 循环、if 结构等）的基元。

为生成多种输出语言，已为 C、C++、解释器、Java、LLVM IR、WebAssembly 等开发了多个后端。其中解释器、LLVM IR 与 WebAssembly 后端尤其值得关注，因为它们能把 DSP 程序直接编译成内存中的可执行代码，无需外部编译器。

配合 LLVM 后端使用 libfaust

带 LLVM 后端的 libfaust API

完整链路从 Faust DSP 源代码出发，用 LLVM 后端编译成 LLVM IR，最终用 LLVM JIT 生成可执行代码。所有步骤都在内存中完成，摆脱了传统的基于文件的做法。可以从生成的 LLVM 模块中取得可执行函数的指针，并用相应参数直接调用代码。

创建 API

libfaust 库导出以下 API：

  • 给定 Faust 源代码（字符串或文件），调用 createDSPFactoryFromString 或 createDSPFactoryFromFile 函数即可运行编译链（Faust + LLVM JIT），并生成该类的原型，即一个 llvm_dsp_factory 指针。该工厂实际上包含给定 DSP 编译后的 LLVM IR
  • 也可以用 createCPPDSPFactoryFromBoxes，从用 box API 构建的 box 表达式创建工厂
  • 也可以用 createDSPFactoryFromSignals，从用 signal API 构建的输出信号列表创建工厂
  • 库对所有已分配的工厂维护内部缓存，因此编译相同的 DSP 代码——即相同的源代码和相同的规范化（按规范顺序排序）编译选项集合——会返回同一个（带引用计数的）工厂指针
  • 接下来，createDSPInstance 函数（相当于 C++ 的 new className）实例化一个 llvm_dsp 指针，通过其接口使用，并连接到音频链和控制器接口。用完后可用 delete 销毁 DSP 实例，也可以使用智能指针。注意实例在整个生命周期内都需要访问其关联的工厂
  • 由于 llvm_dsp 是 dsp 基类的子类，该类型的对象可用于所有可用的 audio 与 UI 类。本质上，这相当于复用所有为静态 C++ 类编译方案开发的架构文件，如 OSCUI、httpdUI 接口等。
  • 不再需要工厂时——即所有关联的 DSP 实例都已正确销毁后——必须显式调用 deleteDSPFactory 以正确递减引用计数
  • 可以用工厂的 getSHAKey 方法取得其唯一的 SHA1 键

保存与恢复工厂

DSP 工厂编译完成后，运行它的应用或插件可能需要保存并稍后恢复它。要取得工厂内部的编译代码，有如下函数可用：

  • writeDSPFactoryToIR：以字符串形式获取 DSP 工厂的 LLVM IR（文本格式）
  • writeDSPFactoryToIRFile：获取 DSP 工厂的 LLVM IR（文本格式）并写入文件
  • writeDSPFactoryToBitcode：以字符串形式获取 DSP 工厂的 LLVM IR（二进制格式）
  • writeDSPFactoryToBitcodeFile：把 DSP 工厂的 LLVM IR（二进制格式）保存到文件
  • writeDSPFactoryToMachine：以字符串形式获取 DSP 工厂的可执行机器码
  • writeDSPFactoryToMachineFile：把 DSP 工厂的可执行机器码保存到文件

要从先前保存的代码重新创建 DSP 工厂，有如下函数可用：

  • readDSPFactoryFromIR：从包含 LLVM IR（文本格式）的字符串创建 DSP 工厂
  • readDSPFactoryFromIRFile：从包含 LLVM IR（文本格式）的文件创建 DSP 工厂
  • readDSPFactoryFromBitcode：从包含 LLVM IR（二进制格式）的字符串创建 DSP 工厂
  • readDSPFactoryFromBitcodeFile：从包含 LLVM IR（二进制格式）的文件创建 DSP 工厂
  • readDSPFactoryFromMachine：从包含可执行机器码的字符串创建 DSP 工厂
  • readDSPFactoryFromMachineFile：从包含可执行机器码的文件创建 DSP 工厂。

典型代码示例

更一般地说，在 C++ 中使用 libfaust 的典型方式大致如下：

// 要编译的 Faust 代码，以字符串给出（也可以放在文件中）
string theCode = "import(\"stdfaust.lib\"); process = no.noise;";

// 在内存中编译（也可以改用 createDSPFactoryFromFile）
llvm_dsp_factory* m_factory = createDSPFactoryFromString( 
  "faust", theCode, argc, argv, "", m_errorString, optimize);
// 创建 DSP 实例以便对接
dsp* m_dsp = m_factory->createDSPInstance();

// 创建一个通用 UI 与 DSP 交互
my_ui* m_ui = new MyUI();
// 把接口连接到 DSP 实例
m_dsp->buildUserInterface(m_ui);

// 用采样率初始化 DSP 实例
m_dsp->init(44100);

// 假想的音频回调，假定 m_input/m_output 已预先分配
while (...) {
  m_dsp->compute(128, m_input, m_output);
}

// 清理
// 手动删除 DSP
delete m_dsp;
delete m_ui;
// 工厂实际上会跟踪所有已分配的 DSP（在 createDSPInstance 中完成）。
// 因此若不手动删除，所有剩余的 DSP 都会在这里被回收。
deleteDSPFactory(m_factory);

第一步是从 DSP 文件（用 createDSPFactoryFromFile）或字符串（用 createDSPFactoryFromString）创建 DSP 工厂，并传入交给编译器的附加参数。假定编译成功，会返回一个工厂，再用工厂的 createDSPInstance 方法创建 DSP 实例。

注意，得到的 llvm_dsp* 指针类型（见 faust/dsp/llvm-dsp.h 头文件）是基础类 dsp 的子类（见 faust/dsp/dsp.h 头文件）。因此它可以与任何 UI 类型配合，在 DSP 对象上接入 GUI、MIDI 或 OSC 控制器，就像对编译成 C++ 类的 DSP 程序所做的那样（生成的 mydsp 类也是基础类 dsp 的子类）。my_ui* m_ui = new MyUI(); 与 m_dsp->buildUserInterface(m_ui); 两行演示了这一点，其中 buildUserInterface 方法用于连接控制器。

然后必须把 DSP 对象连接到音频驱动才能渲染（见 m_dsp->compute(128, m_input, m_output); 代码块）。更完整的 C++ 示例可在此找到。使用纯 C API 的示例可在此找到。

配合解释器后端使用 libfaust

编译时嵌入解释器后端的 libfaust 也可以生成 Faust 字节码（FBC）格式，并用其内置虚拟机在内存中解释执行。

带解释器后端的 libfaust API

解释器后端（在这篇论文中描述）最初是为了在 iOS 上实现动态编译而写的——Apple 不允许在 iOS 上部署基于 LLVM 的 JIT 编译——但也可用于开发测试工具。它被定义为一套带类型的字节码以及执行它的虚拟机。

FIR 语言足够简单，很容易翻译成解释器用的带类型字节码，这由一趟 FIR 到字节码的编译过程生成。虚拟机随后在基于栈的机器上执行字节码。

创建 API

解释器后端的 API 与 LLVM 后端 API 类似：

  • 给定 Faust 源代码（字符串或文件），调用 createInterpreterDSPFactoryFromString 或 createInterpreterDSPFactoryFromFile 函数即可运行编译链（Faust + 解释器后端），并生成该类的原型，即一个 interpreter_dsp_factory 指针。该工厂实际上包含给定 DSP 编译后的字节码
  • 也可以用 createInterpreterDSPFactoryFromBoxes，从用 box API 构建的 box 表达式创建工厂
  • 也可以用 createInterpreterDSPFactoryFromSignals，从用 signal API 构建的输出信号列表创建工厂
  • 库对所有已分配的工厂维护内部缓存，因此编译相同的 DSP 代码——即相同的源代码和相同的规范化（按规范顺序排序）编译选项集合——会返回同一个（带引用计数的）工厂指针
  • 接下来，工厂类的 createDSPInstance 方法（相当于 C++ 的 new className）实例化一个 interpreter_dsp 指针，可像任何常规的 Faust 编译 DSP 对象那样使用，通过其接口运行和控制。该实例包含加载了编译后字节码的解释器虚拟机，每个方法执行时都会运行它。用完后可用 delete 销毁 DSP 实例，也可以使用智能指针。注意实例在整个生命周期内都需要访问其关联的工厂
  • 由于 interpreter_dsp 是 dsp 基类的子类，该类型的对象可用于所有可用的 audio 与 UI 类。本质上，这相当于复用所有为静态 C++ 类编译方案开发的架构文件，如 OSCUI、httpdUI 接口等。
  • 不再需要工厂时——即所有关联的 DSP 实例都已正确销毁后——必须显式调用 deleteInterpreterDSPFactory 以正确递减引用计数。
  • 可以用工厂的 getSHAKey 方法取得其唯一的 SHA1 键

保存与恢复工厂

DSP 工厂编译完成后，应用或插件可能想保存/恢复它，以便下次使用时省去 Faust 到解释器字节码的编译。要取得并保存工厂内部的字节码，有两个函数可用：

  • writeInterpreterDSPFactoryToBitcode 可以以字符串形式取得解释器字节码
  • writeInterpreterDSPFactoryToBitcodeFile 可以把解释器字节码保存到文件

要从先前保存的代码重新创建 DSP 工厂，有两个函数可用：

  • readInterpreterDSPFactoryFromBitcode 可以从包含解释器字节码的字符串创建 DSP 工厂
  • readInterpreterDSPFactoryFromBitcodeFile 可以从包含解释器字节码的文件创建 DSP 工厂

完整 API 在安装的 faust/dsp/interpreter-dsp.h 头文件中有提供和文档说明。注意只支持标量编译模式。更完整的 C++ 示例可在此找到。

性能

生成的代码显然比 LLVM 生成的本地代码慢得多。已对多种 DSP 示例做过测量，代码比 LLVM 本地代码慢 3 倍到 10 倍以上。

配合 WebAssembly 后端使用 libfaust

libfaust C++ 库可以用 Emscripten 编译成 WebAssembly，在 Web 或 NodeJS 平台上使用。有专门页面讨论这个主题。

另一种做法是使用 wasmtime JIT 编译器，在 Web 环境之外使用 WebAssembly 格式。libfaust 库配合其 WebAssembly 后端产出一个 wasm 模块，再用 wasmtime 即时编译并执行。

创建 API

Wasm 后端 API 与 LLVM/解释器后端 API 类似：

  • 给定 Faust 源代码（字符串或文件），调用 createWasmDSPFactoryFromString 或 createWasmDSPFactoryFromFile 函数即可运行编译链（Faust + wasm 后端），并生成该类的原型，即一个 wasm_dsp_factory 指针。该工厂实际上包含给定 DSP 编译后的 wasm
  • 也可以用 createWasmDSPFactoryFromBoxes，从用 box API 构建的 box 表达式创建工厂
  • 也可以用 createWasmDSPFactoryFromSignals，从用 signal API 构建的输出信号列表创建工厂
  • 库对所有已分配的工厂维护内部缓存，因此编译相同的 DSP 代码——即相同的源代码和相同的规范化（按规范顺序排序）编译选项集合——会返回同一个（带引用计数的）工厂指针
  • 接下来，工厂类的 createDSPInstance 方法（相当于 C++ 的 new className）实例化一个 wasm_dsp 指针，可像任何常规的 Faust 编译 DSP 对象那样使用，通过其接口运行和控制。该实例包含加载了编译后字节码的解释器虚拟机，每个方法执行时都会运行它。用完后可用 delete 销毁 DSP 实例，也可以使用智能指针。注意实例在整个生命周期内都需要访问其关联的工厂。
  • 由于 wasm_dsp 是 dsp 基类的子类，该类型的对象可用于所有可用的 audio 与 UI 类。本质上，这相当于复用所有为静态 C++ 类编译方案开发的架构文件，如 OSCUI、httpdUI 接口等。
  • 不再需要工厂时——即所有关联的 DSP 实例都已正确销毁后——必须显式调用 deleteWasmDSPFactory 以正确递减引用计数。
  • 可以用工厂的 getSHAKey 方法取得其唯一的 SHA1 键

保存与恢复工厂

DSP 工厂编译完成后，应用或插件可能想保存/恢复它，以便下次使用时省去 Faust 到 wasm 字节码的编译。要取得并保存工厂内部的字节码，有两个函数可用：

  • writeWasmDSPFactoryToBitcode 可以以字符串形式取得 wasm 二进制代码
  • writeWasmDSPFactoryToBitcodeFile 可以把 wasm 二进制代码保存到文件

要从先前保存的代码重新创建 DSP 工厂，有两个函数可用：

  • readWasmDSPFactoryFromBitcode 可以从包含 wasm 二进制代码的字符串创建 DSP 工厂
  • readWasmDSPFactoryFromBitcodeFile 可以从包含 wasm 二进制代码的文件创建 DSP 工厂

完整 API 在安装的 faust/dsp/wasm-dsp.h 头文件中有提供和文档说明。注意只支持标量编译模式。更完整的 C++ 示例可在此找到，它用于开发 faustwasmtime 程序。

附加函数

libfaust API 中还提供一些附加函数：

  • 展开 DSP 代码。expandDSPFromString/expandDSPFromFile 函数可用于生成自包含的 DSP 源字符串，其中已包含所有需要的库。所有编译选项都被规范化，并作为注释写入展开后的字符串。这是创建自包含 DSP 程序版本的一种方式。

  • 使用其他后端或生成辅助文件。接收 DSP 源字符串或文件的 generateAuxFilesFromString 与 generateAuxFilesFromFile 函数可用于：

    • 激活并使用其他后端（取决于 libfaust 编译进了哪些）来生成 C、C++ 或 Cmajor 代码等。argv 参数需模拟命令行，例如 -lang cpp -vec -lv 1 以向量模式生成 C++ 文件。
    • 生成辅助文件，可以是 SVG、XML、ps 等文本文件。argv 参数需模拟命令行，例如 -json 生成 JSON 文件。

样本大小适配

用 -double 选项编译时，生成的代码内部使用 double 格式处理样本，同时期望输入/输出缓冲区填入 double 类型的样本。faust/dsp/dsp-adapter.h 中定义的 dsp_sample_adapter 装饰器类可用于适配缓冲区。

部署

使用 libfaust 的应用或插件可以把库作为静态链接组件嵌入（得到自包含的二进制文件），也可以把库作为独立组件在运行时动态加载。Faust 库本身通常需要单独打包，可以在运行时通过 createDSPFactoryFromString/createDSPFactoryFromFile 函数中的编译器 -I /path/to/libraries 选项访问。

用例

动态编译链已在多个项目中使用：

  • FaustLive：一个 Faust 集成开发环境，提供即时编译与执行功能

  • Faustgen：一个通用的 Faust Max/MSP 可编程外部对象

  • Faustgen：一个通用的 Faust PureData 可编程外部对象

  • faustgen2~ 对象是 Pd（即 Pure Data，Miller Puckette 的交互式多媒体编程环境）的 Faust 外部对象

  • Faust for Csound：一个在内部运行 Faust 编译器的 Csound opcode

  • LibAudioStream：一个通过流的概念操作音频资源的框架

  • Faust for JUCE：Oliver Larkin 开发的把 Faust 编译器集成到 JUCE 的工具，作为 pMix2 项目的一部分提供

  • Faust 在 Antescofo 中的实验性集成

  • FaucK：ChucK 编程语言与 Faust 的结合

  • libossia 是一个现代的 C++、跨环境分布式对象模型，用于创意编程。它用于 Ossia score 项目

  • Radium 是一款采用新型界面的音乐编辑器，其中包含 Faust 音频 DSP 开发环境，使用带 LLVM 与解释器后端的 libfaust

  • Mephisto LV2 是一个嵌入 LV2 插件的即时 Faust 编译器，使用 C API。

  • gwion-plug 是 Gwion 编程语言的 Faust 插件。

  • FaustGen 允许在 SuperCollider 中现场编写 Faust 代码。它使用 libfaust LLVM C++ API。

  • FAUSTPy 是 Faust DSP 语言的 Python 封装器。它用 CFFI 实现，因此在运行时动态创建封装器。该项目的更新版本可在此分支获取。

  • Faust.jl 是 Faust 编译器的 Julia 封装器。它使用 libfaust LLVM C API。

  • fl-tui 是 Faust 编译器的 Rust 封装器。它使用 libfaust LLVM C API。

  • faustlive-jack-rs 是 Faust 编译器的另一个 Rust 封装器，使用 JACK 服务器处理音频。它使用 libfaust LLVM C API。

  • DawDreamer 是一个音频处理 Python 框架，支持 DAW 的核心功能。它使用 libfaust LLVM C API。

  • metaSurface64 是一个实时连续声音变换控制面板，自带最多 64 个声部的循环发生器，以及一个多重效果 FX 引擎。它使用 libfaust LLVM C++ API。

  • metaFx 是一个实时连续声音变换控制面板，与 metaSurface64 类似。与 metaSurface64 一样，它自带循环发生器和多重效果 FX 引擎，但工作方式不同，尤其是在插件链和 pad 的管理上。

  • HISE 是一个用于构建基于采样的虚拟乐器的开源框架，集成了高性能磁盘流引擎、灵活的 DSP 音频模块系统和便捷的界面设计器。

  • AMATI 是一个用 Faust 编程语言现场编写效果代码的 VST 插件。

  • cyfaust 是 Faust 解释器和 RtAudio 跨平台音频驱动的 cython 封装器，源自 faustlab 项目。目标是得到一个最小、模块化、自包含的跨平台 python3 扩展。

  • nih-faust-jit 是用 Rust 写的插件，用于加载 Faust dsp 文件并用 LLVM 对其 JIT 编译。它提供简单的 GUI 来选择加载哪个脚本，以及到哪里查找该脚本可能导入的 Faust 库。选中的 DSP 脚本会作为插件状态的一部分保存，因此会随你的 DAW 工程一起保存。

  • QLFAUST 是一个用于 Faust 编程语言的插件，使用 FaustSwiftUI 项目——一个基于 SwiftUI 的 Faust DSP JSON 元数据动态 UI 渲染器。它解析 Faust UI JSON 结构，并显示相应的 SwiftUI 控件，如滑块、开关、按钮、条形图等。
