OSC 支持

概览

大多数 Faust 架构都提供 Open Sound Control（OSC）支持（内部实现基于 Ross Bencina 的 oscpack 库）。有了它，任何支持 OSC 的应用、编程语言或硬件设备都能远程控制该应用。

只要在标准 option 元数据中加上 [osc:on]，就能为任何 Faust 程序添加 OSC 支持（前提是目标架构支持，见下表）。

declare options "[osc:on]";

下表列出提供 OSC 支持的 Faust 架构。

简单示例

为说明 OSC 支持如何工作，我们先定义一个带电平控制的简单噪声发生器（命名为 noise.dsp）：

import("stdfaust.lib");
process = no.noise*hslider("level",0,0,1,0.01);

只要运行下面的命令，就能把这个示例编译成带 OSC 支持的独立 Jack Qt 应用：

faust2jaqt -osc noise.dsp

从命令行启动生成的应用时：

./noise

程序会向标准输出打印若干信息，其中包括：

Faust OSC version 0.93 application 'noise' is running on UDP ports 5510, 5511, 5512

因此 OSC 模块用到三个不同的 UDP 端口：

  • 5510 是监听端口：控制消息应发往该端口。
  • 5511 是输出端口：应用发出的控制消息以及对查询消息的回答都发往该端口。
  • 5512 是错误端口：用于异步错误通知。

注意，如果 DSP 程序中有 declare name "Foo"; 一行，Foo 会用作 OSC 根名；否则使用 DSP 文件名。

这些 OSC 参数可在命令行用下列选项修改：

  • -port number 设置应用接收消息所用的端口号。
  • -outport number 设置应用发送消息所用的端口号。
  • -errport number 设置应用发送错误消息所用的端口号。
  • -desthost host 设置应用发送消息的目标主机。注意，目标地址可被收到的第一条消息改变：来自另一主机的第一个数据包会把目标地址设为该主机。
  • -xmit 0|1|2 把发送设为关闭、ALL 或 ALIAS（默认关闭）。发送关闭时，输入控件可用其地址或别名（若有）控制。发送为 ALL 时，输入控件可用其地址或别名（若有）控制，用户操作和输出控件（即 bargraph 等）也作为 OSC 消息发送，别名（若有）同样发送。发送为 ALIAS 时，输入控件只能用别名控制，用户操作和输出控件只以别名发送。
  • -xmitfilter path 用于过滤输出消息。注意 path 可以是正则表达式（如 /freeverb/Reverb1/*）。

例如：

./noise -xmit 1 -desthost 192.168.1.104 -outport 6000

会以开启的发送模式运行 noise，目标为 192.168.1.104 的 6000 端口。

自动分配端口

为了能单独寻址每个应用，同一时刻只有一个应用能监听同一端口。因此，当默认接收端口 5510 已被另一个应用打开时，新应用会自动尝试递增的端口号，直到找到可用端口。假设我们在同一台机器上启动 noise 和 mixer（两个带 OSC 支持的 Faust 生成应用），会得到如下结果：

$ ./noise &
...
Faust OSC version 0.93 application 'noise' is running on UDP ports 5510, 5511, 5512
$ ./mixer
...
Faust OSC version 0.93 application 'mixer' is running on UDP ports 5513, 5511, 5512

mixer 应用打不开默认接收端口 5510，因为它已被 noise 占用。于是它从 5513 开始寻找可用端口并打开。请注意，两个发送端口 5511 和 5512 由所有运行中的应用共享。

发现 OSC 应用

liblo 包中的 oscsend 和 oscdump 命令提供了便捷手段，可用来试验 OSC 控制，也可用于调试带 OSC 支持的应用。

`oscsend [hostname] [port] [address] [types] [values]`: sends OSC messages 
via UDP. `[types]` is a string, the letters indicates the type of the following 
values: `i=integer`, `f=float`, `s=string`, etc.

`oscdump [port]`: receives OSC messages via UDP and dump to standard output

注意，OSC 消息可以从任何兼容 OSC 的应用（如 PureData、Max/MSP 等）发出。

下面的示例使用两个独立的终端窗口。第一个用 oscsend 向 noise 应用发送 OSC 消息。第二个用 oscdump 监视应用发出的消息。在终端 1 执行的命令前加 T1$。在终端 2 收到的消息前加 T2:。要在终端 T2 上监视 UDP 端口 5511 收到的 OSC 消息，使用 oscdump：

T2$ oscdump 5511

设置好之后，即可用 hello 消息扫描 UDP 端口，查找 Faust 应用。例如：

T1$ oscsend localhost 5510 "/* " s hello

它会给出 noise 应用的根消息地址、所用网络和 UDP 端口：

T2: /noise siii "192.168.1.102" 5510 5511 5512

发现应用的 OSC 接口

向根地址发送 get 消息，即可发现应用的 OSC 接口（即可以用来控制它的那组 OSC 消息）：

T1$ oscsend localhost 5510 /noise s get

作为对该 OSC 消息的回答，终端 T2 会打印完整描述：

T2: /noise sF "xmit" #F
T2: /noise ss "desthost" "127.0.0.1"
T2: /noise si "outport" 5511
T2: /noise si "errport" 5512
T2: /noise/level fff 0.000000 0.000000 1.000000

OSC 接口的根是 /noise。发送为关闭，xmit 为 false。发送消息的目标主机是 127.0.0.1，输出端口是 5511，错误端口是 5512。该应用只有一个界面控件：/noise/level，当前值 0.0，最小值 0.0，最大值 1.0。

控件的 OSC 地址

应用中的每个控件都有一个唯一的 OSC 地址，由它所属各分组的标签与自身标签拼接而成。

控件标签与 OSC 地址空间之间可能存在冲突。OSC 符号名是一个 ASCII 字符串，由一组受限的可打印字符组成。因此为保证兼容性，空格被替换为下划线，另有若干字符（星号、逗号、正斜杠、问号、左方括号、右方括号、左花括号、右花括号）被替换为连字符。

下面是一个极简的单声道音频混音器示例，四路输入、一路输出。每路输入有一个静音按钮和一个电平滑块：

input(v) = vgroup("input %v", *(1-checkbox("mute")) : *(vslider("level", 0, 0, 1, 0.01)));
process = hgroup("mixer", par(i, 4, input(i)) :> _);

如果查询这个应用：

T1$ oscsend localhost 5510 "/* " s get

我们会在终端 T2 上得到其 OSC 接口的完整描述：

T2: /mixer sF "xmit" #F
T2: /mixer ss "desthost" "127.0.0.1"
T2: /mixer si "outport" 5511
T2: /mixer si "errport" 5512
T2: /mixer/input_0/level fff 0.0000 0.0000 1.0000
T2: /mixer/input_0/mute  fff 0.0000 0.0000 1.0000
T2: /mixer/input_1/level fff 0.0000 0.0000 1.0000
T2: /mixer/input_1/mute  fff 0.0000 0.0000 1.0000
T2: /mixer/input_2/level fff 0.0000 0.0000 1.0000
T2: /mixer/input_2/mute  fff 0.0000 0.0000 1.0000
T2: /mixer/input_3/level fff 0.0000 0.0000 1.0000
T2: /mixer/input_3/mute  fff 0.0000 0.0000 1.0000

可以看到，每个控件的唯一 OSC 地址由顶层分组标签「mixer,」、分组「input」的标签和控件标签拼接而成（参见标签作为路径名一节）。请注意，空格被替换为下划线，元数据在此过程中被移除。

所有地址必须有共同的根。我们的示例就是如此，因为有一个包含全部控件的水平分组 mixer。如果缺少共同根，如下面的代码：

input(v) = vgroup("input %v", *(1-checkbox("mute")) : *(vslider("level", 0, 0, 1, 0.01)));
process = par(i, 4, input(i)) :> _;

那么 Faust 编译器会自动创建一个默认的垂直分组，以文件名 mix4 作为标签：

T2: /mix4 sF "xmit" #F
T2: /mix4 ss "desthost" "127.0.0.1"
T2: /mix4 si "outport" 5511
T2: /mix4 si "errport" 5512
T2: /mix4/input_0/level fff 0.0000 0.0000 1.0000
T2: /mix4/input_0/mute  fff 0.0000 0.0000 1.0000
T2: /mix4/input_1/level fff 0.0000 0.0000 1.0000
T2: /mix4/input_1/mute  fff 0.0000 0.0000 1.0000
T2: /mix4/input_2/level fff 0.0000 0.0000 1.0000
T2: /mix4/input_2/mute  fff 0.0000 0.0000 1.0000
T2: /mix4/input_3/level fff 0.0000 0.0000 1.0000
T2: /mix4/input_3/mute  fff 0.0000 0.0000 1.0000

通过 OSC 控制应用

发送前面发现的任一消息/地址，即可控制应用的任何界面控件。例如，要把应用的噪声电平设为 0.2，可发送以下消息：

T1$ oscsend localhost 5510 /noise/level f 0.2

此时再查询 /noise/level，如预期得到值 0.2：

T1$ oscsend localhost 5510 /noise/level s get
T2: /noise/level fff 0.2000 0.0000 1.0000

打开发送

根层的 xmit 消息用于控制是否实时发送对应用户操作界面的 OSC 消息。例如：

T1$ oscsend localhost 5510 /noise si xmit 1

把发送切到 ALL 模式。此时移动电平滑块，会收到一连串消息：

T2: /noise/level f 0.024000
T2: /noise/level f 0.032000
T2: /noise/level f 0.105000
T2: /noise/level f 0.250000
T2: /noise/level f 0.258000
T2: /noise/level f 0.185000
T2: /noise/level f 0.145000
T2: /noise/level f 0.121000
T2: /noise/level f 0.105000
T2: /noise/level f 0.008000
T2: /noise/level f 0.000000

该功能典型用于自动化：录制并回放界面上的操作，或从一个应用远程控制另一个应用。随时可用下面的消息关闭：

T1$ oscsend localhost 5510 /noise si xmit 0

如果需要限制对程序的访问，可用 ALIAS（xmit = 2）模式：使用 ALIAS 模式时，只有输入控件（滑块、按钮……）的别名能用来控制它们，输出控件（bargraph）也只在别名上发出消息。

过滤 OSC 消息

发送打开时，所有界面控件都通过 OSC 连接发出。

T2: /harpe/level f 0.024000
T2: /harpe/hand f 0.1
T2: /harpe/level f 0.024000
T2: /harpe/hand f 0.25
T2: /harpe/level f 0.024000
T2: /harpe/hand f 0.44
T2: /noise/level f 0.145000
T2: /harpe/hand f 0.78
T2: /noise/level f 0.145000
T2: /harpe/hand f 0.99

我们可以选择过滤掉不需要的参数（或参数组）。例如：

T1$ oscsend localhost 5510 /harpe si xmit 1 xmitfilter /harpe/level

结果是会收到：

T2: /harpe/hand f 0.1
T2: /harpe/hand f 0.25
T2: /harpe/hand f 0.44
T2: /harpe/hand f 0.78

要重置过滤器，发送：

T1$ oscsend localhost 5510 /harpe si xmit 1 xmitfilter

使用 OSC 别名

别名是一种便捷机制，可用一套现成的 OSC 消息来控制 Faust 应用。

假设我们要用 Android 上的 TouchOSC 控制前面的 noise 示例。第一步是把 TouchOSC 的主机设为 192.168.1.102（运行 noise 应用的主机），发送端口设为 5510。

然后可以用 oscdump 5510（先退出 noise 应用以释放端口 5510）查看 TouchOSC 发出的 OSC 消息。这里使用「simple layout」的左滑块。得到的是：

T2: /1/fader1 f 0.000000
T2: /1/fader1 f 0.004975
T2: /1/fader1 f 0.004975
T2: /1/fader1 f 0.008125
T2: /1/fader1 f 0.017473
T2: /1/fader1 f 0.032499
T2: /1/fader1 f 0.051032
T2: ...
T2: /1/fader1 f 0.993289
T2: /1/fader1 f 1.000000

把元数据 [osc:/1/fader1 0 1] 插入滑块标签，就能把这条 OSC 消息关联到噪声电平滑块：

可以在单个标签里插入多个 osc 别名，让同一个控件被多条 OSC 消息控制

import("stdfaust.lib");
process = no.noise*hslider("level[osc:/1/fader1 0 1]",0,0,1,0.01);

由于 /1/fader1 的范围是 0 到 1（与电平滑块相同），可以去掉范围映射信息，直接写成：

import("stdfaust.lib");
process = no.noise*hslider("level[osc:/1/fader1]",0,0,1,0.01);

TouchOSC 也能发送加速度计数据，需启用 Settings/Options/Accelerometer。再次用 oscdump 5510，即可查看 TouchOSC 发出的消息：

T2: ...
T2: /accxyz fff -0.147842 0.019752 9.694721
T2: /accxyz fff -0.157419 0.016161 9.686341
T2: /accxyz fff -0.167594 0.012570 9.683948
T2: ...

可以看到，TouchOSC 把 x、y、z 三个加速度计放在一条消息里，以三元组形式发送，取值范围约为 -9.81 到 9.81。要选取相应的加速度计，需要在 /accxyz 后拼接后缀 /0、/1 或 /2。例如 /accxyz/0 对应 x，/accxyz/1 对应 y，依此类推。由于范围不同，还需要定义映射：

import("stdfaust.lib");
process = no.noise * hslider("level[osc:/accxyz/0 0 9.81]",0,0,1,0.01);

默认端口

端口说明
5510默认监听端口
5511默认发送端口
5512默认错误端口

命令行选项

选项说明
-port n设置应用接收消息所用的端口号
-outport n设置应用发送消息所用的端口号
-errport n设置应用发送错误消息所用的端口号
-desthost h设置应用发送消息的目标主机
-xmit 0|1|2把发送设为关闭、ALL 或 ALIAS（默认关闭）
-xmitfilter s在发送时过滤 Faust 路径

发现消息

消息说明
oscsend host port "/*" s hello检测是否有 OSC 应用在监听 port 端口

oscsend host port "/*" s json查询监听 port 端口应用的 JSON 描述

控制消息

消息说明

oscsend host port widget f v设置控件的值

别名

别名说明
"...[osc: address lo hi ]..."带 lo \rightarrow min、hi \rightarrow max 映射的别名
"...[osc:' address]..."带 min、max 截断的别名

带复音支持的 DSP

DSP 代码以复音模式编译时，生成的程序会创建更复杂的层次结构，以便访问和控制各个声部。

下面的 OSC 消息对应同一段 DSP 代码分别按普通方式和复音模式编译的结果（此处只显示部分 OSC 层次）：

// 单声模式

/Organ/vol f -10.0
/Organ/pan f 0.0

// 复音模式

/Polyphonic/Voices/Organ/pan f 0.0
/Polyphonic/Voices/Organ/vol f -10.0
...
/Polyphonic/Voice1/Organ/vol f -10.0
/Polyphonic/Voice1/Organ/pan f 0.0
...
/Polyphonic/Voice2/Organ/vol f -10.0
/Polyphonic/Voice2/Organ/pan f 0.0
