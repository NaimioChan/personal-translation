常见问题

何时该用 int 或 float 强制转换？

信号处理器语义一节说明了 Faust 程序描述的内容。特别地，Faust 考虑两类信号：整数信号与浮点信号。数学运算依其类型发生在整数域或浮点域，参见此处。可能需要显式使用 int 强制转换或 float 强制转换，以强制某个计算在正确的数域中完成。

某些语言基元（如 par、seq、route、soundfile 等）假定其参数是整数类型的常量数值表达式。此时编译器会自动做类型提升，无需用 int 强制转换让参数成为整数类型（注意多余的强制转换会被直接忽略，不会在生成的代码中增加无用的计算）。

用户界面项产生浮点信号。取决于它们在后续计算表达式中的用法，也可能需要显式 int 强制转换，以强制某个计算在正确的数值域中完成。

select2 的行为像标准 C/C++ 的 if 吗？

简短回答是不像，select2 的行为不像传统编程语言的 if-then-else，标准库的 ba.if 也不是。要理解原因，可以把 select2 想成收音机的调谐器：它选择你听什么，但并不阻止各个电台继续广播。实际上，select2 可以很容易地在 Faust 中重新定义为：

select2(i, x, y) = (1-i) * x + i * y;

严格语义与惰性语义

用计算机术语说，select2(i,x,y) 具有所谓的严格语义。这意味着它的三个参数 i、x、y 总是在 select2 本身执行之前求值，即使 x 或 y 未被选中。标准 C/C++ 的 if-then-else 具有惰性语义。条件总是执行，但依条件的值，只执行 then 或 else 分支。

select2 的严格语义意味着不能用它来避免表达式中的除零，或对负数开平方等。例如下面的代码不能避免除零错误：

select2(x == 0, 1/x, 10000);

也不能用 ba.if，因为它是用 select2 实现的，语义同样严格。因此下面的代码不能避免除零错误：

ba.if(x == 0, 10000, 1/x);

但事情要稍微复杂一些……

关于 Faust 编译器如何编译 select2，严格语义始终得到保持。特别地，类型系统会标记有问题的表达式，有状态的部分总是放在 if 之外。例如 DSP 代码：

process = button("choose"), (*(3) : +~_), (*(7):+~_) : select2;

被编译成如下 C++ 代码，其中 fRec0[0] 与 fRec1[0] 包含各分支的计算：

for (int i = 0; (i < count); i = (i + 1)) {
    fRec0[0] = (fRec0[1] + (3.0f * float(input0[i])));
    fRec1[0] = (fRec1[1] + (7.0f * float(input1[i])));
    output0[i] = FAUSTFLOAT((iSlow0 ? fRec1[0] : fRec0[0]));
    fRec0[1] = fRec0[0];
    fRec1[1] = fRec1[0];
}

出于代码优化策略，生成的代码对 select2 并不完全严格。当 Faust 生成 C++ 代码时，C++ 编译器可以决定跳过未被选中（且其他地方也不需要）的无状态信号部分的执行。这不改变输出信号的语义，但如果在无状态部分本会执行除零，就改变了代码的严格性。使用无状态表达式时，默认用非严格条件表达式生成。

例如下面的 DSP 代码：

process = select2((+(1)~_)%10, sin:cos:sin:cos, cos:sin:cos:sin);

被编译成 C/C++：

for (int i0 = 0; i0 < count; i0 = i0 + 1) {
    iRec0[0] = iRec0[1] + 1;
    output0[i0] = FAUSTFLOAT(((iRec0[0] % 10) 
        ? std::sin(std::cos(std::sin(std::cos(float(input1[i0]))))) 
        : std::cos(std::sin(std::cos(std::sin(float(input0[i0])))))));
    iRec0[1] = iRec0[0];
}

其中只有 then 或 else 分支之一会被实际计算，从而节省 CPU。

如果确实希望两个分支都被计算，可以用 -sts (--strict-select) 选项，把它们放进局部变量以强制计算，如下面同一 DSP 代码用 -sts 生成的版本所示：

for (int i0 = 0; i0 < count; i0 = i0 + 1) {
    iRec0[0] = iRec0[1] + 1;
    float fThen0 = std::cos(std::sin(std::cos(std::sin(float(input0[i0])))));
    float fElse0 = std::sin(std::cos(std::sin(std::cos(float(input1[i0])))));
    output0[i0] = FAUSTFLOAT(((iRec0[0] % 10) ? fElse0 : fThen0));
    iRec0[1] = iRec0[0];
}

从而保持严格语义，即使产生 select2 表达式结果时用的是非严格的 (cond) ? then : else 形式。

这对调试有帮助，例如测试是否存在除 0，或产生 INF 或 NaN 值。interp-tracer 加上 -sts 选项即可用于此目的。

所以再次提醒，select2 不能用来避免计算某些东西。对于需要避开某些值或区间的计算（例如 val/0 会返回 INF，负值的 log 会返回 NaN），解决办法是用 min 和 max 把参数强制到正确的取值域。例如要避免除 0，可以写 1/max(ma.EPSILON, x)。

注意 select2 也常用于计算 rdtable/rwtable 的访问索引。此时计算越界的数组索引没有问题，只要之后不使用它。

Faust 编译器与生成的代码有哪些性质？[WIP]

编译器

编译器本身是图灵完备的，因为它包含模式匹配元编程模型。因此 Faust DSP 程序可以在编译期循环。例如下面这段：

foo = foo;
process = foo;

会一直循环，并希望以这样的消息结束：ERROR : after 400 evaluation steps, the compiler has detected an endless evaluation cycle of 2 steps，因为编译器包含死循环检测启发式。

生成的代码

生成的代码以有限次操作计算样本，因此无法写出会无限循环的 DSP 程序。这意味着生成的代码不是图灵完备的。这当然是限制，因为某些类别的算法无法表达（待办：二极管 VA 模型中使用的牛顿近似）。但反过来，它给出了 CPU 开销上界的强保证，在实时音频场景中部署程序时相当有价值。

内存占用

DSP 的内存占用在编译期完全可知，因此生成的代码总是消耗有限的内存。此外标准部署模型是在加载时分配 DSP、用给定采样率初始化，然后执行 DSP 代码，反复调用 compute 函数处理音频缓冲区。

CPU 占用

由于生成的代码以有限次操作计算样本，CPU 使用有上界，这在实时音频场景中部署程序时是有用的性质。关于 select2 基元的一些微妙问题，请阅读「select2 的行为像标准 C/C++ 的 if 吗？」。

模式匹配与列表

严格来说，Faust 中没有列表。例如 Lisp 中表示空列表的 () 或 NIL，在 Faust 中并不存在。同样，Lisp 中数字 3 与只含一个元素的列表 (3) 之间的区别，在 Faust 中也不存在。

不过，列表操作可以（部分地）用并行二元组合算子 , 和模式匹配来模拟。并行组合算子是右结合的。这意味着表达式 (1,2,3,4) 只是完全加括号表达式 (1,(2,(3,4))) 的简化形式。(1,2,(3,4)) 也一样，它也是同一个完全加括号表达式 (1,(2,(3,4))) 的简化形式。

可以把模式匹配理解为总是在完全加括号的表达式上进行。因此任何 Faust 函数都无法区分 (1,2,3,4) 与 (1,2,(3,4))，因为它们表示同一个完全加括号表达式 (1,(2,(3,4)))。

这就是为什么 ba.count( ((1,2), (3,4), (5,6)) ) 不是 3 而是 4，也是为什么 ba.count( ((1,2), ((3,4),5,6)) ) 不是 2 而是 4。

解释：两种情况下完全加括号的表达式都是 ( (1,2),((3,4),(5,6)) )。ba.count 的定义是：

count((x,y)) = 1 + count(y); // 规则 R1
count(x)     = 1; // 规则 R2

于是有：

ba.count( ((1,2),((3,4),(5,6))) ) 
-R1->   1 + ba.count( ((3,4),(5,6)) ) 
-R1->   1 + 1 +  ba.count( (5,6) ) 
-R1->   1 + 1 + 1 + ba.count( 6 )
-R2->   1 + 1 + 1 + 1

请注意，模式匹配并不限于并行组合，其他组合算子 (<: : :> ~) 也可以使用。

Faust 编译器的许可证与生成的代码是什么关系？

问题：Faust 编译器的许可证（LGPL）在某种程度上也适用于它产生的导出代码吗？还是导出代码的许可证可以自由选择，从而可以用 Faust 开发专有软件（例如 VST 插件）？

回答：你可以自由地用 Faust 开发专有软件。编译器的 LGPL 许可证不适用于编译器生成的代码。

Faust 编译器生成的代码的许可证只取决于输入文件的许可证。因此你应检查所用 Faust 库和架构文件的许可证。总的来说，未经修改使用时，Faust 库与架构文件与专有的、非开源的使用方式兼容。

GUI 项中的路径名

编译以下代码：

import("stdfaust.lib");
nBands = 8;
filterBank(N) = hgroup("Filter Bank",seq(i,N,oneBand(i)))
with {
    oneBand(j) = vgroup("Band",fi.peak_eq(l,f,b))
    with {
        a = j+1; // 只是为了让频段编号不从 0 开始
        l = vslider("[2]Level[unit:db]",0,-70,12,0.01) : si.smoo;
        f = nentry("[1]Freq",(80+(1000*8/N*(j+1)-80)),20,20000,0.01) : si.smoo;
        b = f/hslider("[0]Q[style:knob]",1,1,50,0.01) : si.smoo;
    };
};
process = filterBank(nBands);

会给出 ERROR : path '/Filter_Bank/Band/Q' is already used 消息。这是因为我们通常希望区分路径名，以便例如由 OSC 消息控制。因此合适的做法是把代码改写为：

import("stdfaust.lib");
nBands = 8;
filterBank(N) = hgroup("Filter Bank",seq(i,N,oneBand(i)))
with {
    oneBand(j) = vgroup("Band %a",fi.peak_eq(l,f,b))
    with {
        a = j+1; // 只是为了让频段编号不从 0 开始
        l = vslider("[2]Level[unit:db]",0,-70,12,0.01) : si.smoo;
        f = nentry("[1]Freq",(80+(1000*8/N*(j+1)-80)),20,20000,0.01) : si.smoo;
        b = f/hslider("[0]Q[style:knob]",1,1,50,0.01) : si.smoo;
    };
};
process = filterBank(nBands);

不同的 GUI 项应具有不同的路径名

规则如下：

  • 两个输入控件不能共享同一路径（ERROR）
  • 输入控件与条形图不能具有同一路径（ERROR）
  • 两个条形图可以具有同一路径（WARNING）

vgroup/hgroup 对控件与参数工作方式的意外影响

像 button、vslider/hslider、vbargraph/hbargraph 这样的用户界面控件基元，允许在 Faust 代码中抽象地描述用户界面。它们可以用 vgroup/hgroup/tgroup 基元以层次方式分组。每个控件随后都有一个关联的路径名，由包裹它的所有分组的标签与它自己的标签拼接而成。

在层次结构中具有相同路径的控件将对应同一个控制器，并在 GUI 中只出现一次。例如下面的 DSP 代码不含任何显式分组机制：

import("stdfaust.lib");

freq1 = hslider("Freq1", 500, 200, 2000, 0.01);
freq2 = hslider("Freq2", 500, 200, 2000, 0.01);

process = os.osc(freq1) + os.square(freq2), os.osc(freq1) + os.triangle(freq2);

共享的 freq1 与 freq2 控制器

因此即使 freq1 与 freq2 控制器在四个不同位置用作参数，os.osc(freq1) 与 os.square(freq1) 中使用的 freq1 也会具有相同路径（如 /foo/Freq1），关联到同一个控制器，最终在 GUI 中只出现一次。freq2 同理。

如果使用某种分组机制来更好地控制 UI 渲染，如下面的 DSP 代码：

import("stdfaust.lib");

freq1 = hslider("Freq1", 500, 200, 2000, 0.01);
freq2 = hslider("Freq2", 500, 200, 2000, 0.01);

process = hgroup("Voice1", os.osc(freq1) + os.square(freq2)), hgroup("Voice2", os.osc(freq1) + os.triangle(freq2));

freq1 与 freq2 控制器现在在各分组中路径不同（例如第一组中的 /foo/Voice1/Freq1 与 /foo/Voice1/Freq2，第二组中的 /foo/Voice2/Freq1 与 /foo/Voice2/Freq2），因此最终创建四个独立的控制器与 UI 项。

四个 freq1 与 freq2 控制器

使用标签作为路径名中说明的相对路径名，可以把 freq1 在层次结构中上移一级，从而再次得到唯一路径（如 /foo/Freq1）和唯一控制器：

import("stdfaust.lib");

freq1 = hslider("../Freq1", 500, 200, 2000, 0.01);
freq2 = hslider("Freq2", 500, 200, 2000, 0.01);

process = hgroup("Voice1", os.osc(freq1) + os.square(freq2)), hgroup("Voice2", os.osc(freq1) + os.triangle(freq2));

freq1 在层次结构中上移一级

注意给定 hgroup、vgroup 或 tgroup 的名称可以多次使用，它们会被合并。当你想为不同的控件信号定义不同名称、但仍想把它们分组时，这很有用。例如这种模式可用于把合成器的 UI 设计与合成器 DSP 的实现分开：

import("stdfaust.lib");

synth(foo, bar, baz) = os.osc(foo+bar+baz);

synth_ui = synth(foo, bar, baz)
with {
    ui(x) = hgroup("Synth", x);
    leftcol(x) = ui(vgroup("[0]foobar", x));
    foo = leftcol(hslider("[0]foo", 100, 20, 1000, 1));
    bar = leftcol(hslider("[1]bar", 100, 20, 1000, 1));
    baz = ui(vslider("[1]baz", 100, 20, 1000, 1));
};

process = synth_ui;

命名与分组

部分应用的规则是什么？

假定 F 不是抽象且具有 n+m 个输入，A 有 n 个输出，那么有重写规则 F(A) ==> A,bus(m):F (with bus(1) = _ and bus(n+1) = _,bus(n))

当 F 是 +,-,/,* 这样的二元运算时有个例外。此时重写规则为 /(3) ==> _,3:/。换言之，只应用一个参数时，它是第二个参数。

控制率与音频率

问题：我有个关于采样率/控制率的问题。我有一段 Faust 代码，把键盘的通道触后消息作为输入（因此是控制率），并输出采样率的表达式信号。代码的第一部分可以按控制率运行，但我想强制它按采样率运行（否则会出现不想要的行为）。有没有简单办法把压力信号强制到采样率（而不施加平滑，平滑也可能导致不想要的行为）？

回答：可以用 ba.kr2ar 函数达到这一目的。

回答：标签可以包含可变部分，用 % 符号后跟变量名表示。关于如何使用该功能的详细说明，参见完整文档。

条形图的语义

问题：控制率输出（如 hbargraph/vbargraph）什么时候每个样本都计算？

回答：这取决于进入条形图的信号的性质。如果它是控制率信号，如 process = vslider("foo", 0, 0, 1, 0.01) : vbargraph("bar", 0, 1);，那么按控制率更新：

virtual void compute(int count, FAUSTFLOAT** inputs, FAUSTFLOAT** outputs)
{
    FAUSTFLOAT* output0 = outputs[0];
    fVbargraph0 = FAUSTFLOAT(float(fVslider0));
    float fSlow0 = fVbargraph0;
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        output0[i0] = FAUSTFLOAT(fSlow0);
    }
}

但如果信号是采样率，如 process = vslider("foo", 0, 0, 1, 0.01) : si.smooth(0.9) : vbargraph("bar", 0, 1);，则计算必须在采样率进行才正确（即每个样本正确更新信号状态），即使并非所有值都被显示：

virtual void compute(int count, FAUSTFLOAT** inputs, FAUSTFLOAT** outputs) 
{
    FAUSTFLOAT* output0 = outputs[0];
    float fSlow0 = fConst0 * float(fVslider0);
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        fRec0[0] = fSlow0 + fConst1 * fRec0[1];
        fVbargraph0 = FAUSTFLOAT(fRec0[0]);
        output0[i0] = FAUSTFLOAT(fVbargraph0);
        fRec0[1] = fRec0[0];
    }
}
