HTTP 支持

与 OSC 类似，若干 Faust 架构也提供 HTTP 支持。这让 Faust 应用能被任何 Web 浏览器用特定 URL 远程控制。此外，OSC 与 HTTP 可以自由组合。

构建 Faust 时 OSC 支持默认就会安装，HTTP 则不然。因为它依赖 GNU 的 libmicrohttpd 库，而该系统上通常不会默认安装该库。因此编译安装 Faust 时还需要额外执行 make httpd 一步：

make httpd
make
sudo make install

注意，如果系统上没有 libmicrohttpd，make httpd 会失败。

只要在标准 option 元数据中加上 [http:on]，就能为任何 Faust 程序添加 HTTP 支持（前提是目标架构支持，见下表）：

declare options "[http:on]";

简单示例

为说明 HTTP 支持如何工作，我们沿用前面的示例：一个简单的单声道音频混音器，四路输入、一路输出。每路输入有一个静音按钮和一个电平滑块：

input(v) = vgroup("input %v", *(1-checkbox("mute")) : *(vslider("level", 0, 0, 1, 0.01)));
process  = hgroup("mixer", par(i, 4, input(i)) :> _);

该示例可以用下面的命令编译成带 HTTP 支持的独立 Jack QT 应用：

faust2jaqt -httpd mix4.dsp

-httpd 选项会把一个小型 Web 服务器嵌入生成的应用。它的用途是提供一个实现应用界面的 HTML 页面。该页面使用 JavaScript 和 SVG，与原生 QT 界面相当接近。

从命令行启动应用时：

./mix4

程序会在标准输出上打印若干信息，其中包括：

Faust httpd server version 0.73 is running on TCP port 5510

可以看到，嵌入的 Web 服务器默认运行在 TCP 端口 5510。入口是 http://localhost:5510。用任何较新的浏览器都能打开，得到的页面如下图所示：

用户界面的 JSON 描述

应用与 Web 浏览器之间的通信基于若干底层 URL。第一个是 http://localhost:5510/JSON，它返回应用用户界面的 JSON 描述。JavaScript 代码内部用这份 JSON 描述构建图形用户界面。下面是 mix4 返回的（部分）JSON：

{
  "name": "mix4",
  "address": "YannAir.local",
  "port": "5511",
  "ui": [
    {
      "type": "hgroup",
      "label": "mixer",
      "items": [
        {
          "type": "vgroup",
          "label": "input_0",
          "items": [
            {
              "type": "vslider",
              "label": "level",
              "address": "/mixer/input_0/level",
              "init": "0", "min": "0", "max": "1", 
              "step": "0.01"
            },
            {
              "type": "checkbox",
              "label": "mute",
              "address": "/mixer/input_0/mute",
              "init": "0", "min": "0", "max": "0", 
              "step": "0"
            }
          ]
        },

        ...

      ]
    }
  ]
}

查询应用的状态

每个控件都有一个唯一的 "address" 字段，可用于查询其值。我们的示例中，输入 0 的电平地址是 /mixer/input_0/level。用这个地址可以构造获取该控件值的 URL：http://localhost:5510/mixer/input_0/level，结果为：

/mixer/input_0/level 0.00000

使用层次中较高层的地址可以一次查询多个控件。例如要获取输入 0 的电平和静音状态，使用 http://localhost:5510/mixer/input_0，结果为：

/mixer/input_0/level 0.00000 
/mixer/input_0/mute  0.00000

要一次获取全部值，只需使用 http://localhost:5510/mixer，结果为：

/mixer/input_0/level 0.00000 
/mixer/input_0/mute  0.00000 
/mixer/input_1/level 0.00000 
/mixer/input_1/mute  0.00000 
/mixer/input_2/level 0.00000 
/mixer/input_2/mute  0.00000 
/mixer/input_3/level 0.00000 
/mixer/input_3/mute  0.00000

修改控件的值

假设我们要把混音器的输入 1 静音。为此可以使用 URL http://localhost:5510/mixer/input_1/mute?value=1，它由控件 URL 末尾追加 ?value=1 得到。

所有控件都可以用类似方式控制。例如 http://localhost:5510/mixer/input_3/level?value=0.7 会把输入 3 的电平设为 0.7。

对 Web 服务器的代理控制访问

控制应用可能想通过运行中的 DSP 的 Web 服务器访问并控制它，但不在浏览器里使用提供的 HTML 页面。由于可以取回完整的 JSON，控制应用可以纯用 C/C++ 开发。这样就能构建用户界面的代理版本，用 HTTP 请求设置和查询参数。

该模式可用 -server URL 参数动态启动。假设某个带 HTTP 支持的应用正运行在给定 URL 上，控制应用会取回它的 JSON 描述，据此动态构建用户界面，并允许访问远程参数。

端口说明

5511...备用 TCP 端口

命令行选项

选项说明
-port n设置应用 Web 服务器使用的 TCP 端口号
-server URL启动代理控制应用，访问运行在给定 URL 上的远程应用

URL 一览

URL说明
http://host:port代理控制访问模式下使用的基础 URL
http://host:port/JSON获取用户界面的 json 描述
http://host:port/address获取某个控件或某组控件的值
http://host:port/address?value=v把控件的值设为 v

JSON

顶层

JSON 描述应用的名字、主机和端口，以及用户界面项的层次结构：

{
  "name": <name>,
  "address": <host>,
  "port": <port>,
  "ui": [ <item> ]
}

一个 <item> 要么是一个（项的）分组，要么是一个控件。

分组

分组本质上是一个带特定布局的项列表：

{
    "type": <type>,
    "label": <label>,
    "items": [ <item>, <item>,...]
}

<type> 定义布局，可以是 "vgroup"、"hgroup" 或 "tgroup"

控件

{
    "type": <type>,
    "label": <label>,
    "address": <address>,
    "meta": [ { "key": "value"},... ],
    "init": <num>,
    "min": <num>,
    "max": <num>,
    "step": <num>
},

控件是用户界面的基本项。它们的 <type> 可以不同："button"、"checkbox"、"nentry"、"vslider"、"hslider"、"vbargraph" 或 "hbargraph"。
