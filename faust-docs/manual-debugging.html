使用 FIR 后端

FIR（Faust Imperative Representation）后端可用于查看中间命令式语言的文本形式。使用 make developer 目标编译 FIR 后端，然后用 faust -lang fir foo.dsp 把指定的 foo.dsp 文件编译为 FIR 文本输出。

import("stdfaust.lib");

vol = hslider("volume [unit:dB]", 0, -96, 0, 0.1) : ba.db2linear : si.smoo;
freq1 = hslider("freq1 [unit:Hz]", 1000, 20, 3000, 1);
freq2 = hslider("freq2 [unit:Hz]", 200, 20, 3000, 1);

process = vgroup("Oscillator", os.osc(freq1) * vol, os.osc(freq2) * vol);

调试 DSP 代码

在计算机上，进行数学上无定义的运算（如 val/0 或 log(-1)），在浮点运算中无法表示，会产生 NaN 值，它有特殊的内部表示。同样，有些运算会超出浮点运算能表示的范围，会用一个特殊的 INFINITY 值表示，其具体值取决于所选类型（如 float、double 或 long double）。

这些值产生之后，实际上会污染后续的计算流（例如 Nan + any value = NaN），甚至在使用数组访问时产生错误的索引，导致内存访问崩溃。

代码在语法或语义上不正确时，Faust 编译器会报错。它的区间分析系统设计用于在编译期检测可能不安全的信号运算，并拒绝相应的 DSP 代码。然而，区间分析尚不完善。在它无法保证安全的情况下，必须在生成的代码中插入特殊的保护，以确保运行时的正确行为。

人们开发了若干策略，帮助程序员在编译期和运行时更好地理解自己写的 DSP 代码，并对其进行分析。

在编译期调试

-ct 选项

使用 -ct 编译选项可以检查表的索引范围，并生成安全的表访问代码。它会验证信号范围与表大小是否相容，需要时把读、写索引约束在给定的 [0.. size-1] 范围内，从而生成安全的索引访问代码。

注意，由于信号区间计算并不完善，你可能会看到误报，从而生成不必要的范围约束代码，尤其是在使用递归信号时——区间计算系统通常会产生 [-inf, inf] 范围，这不足以准确描述真实的信号范围。

-me 选项

从 2.37.0 版开始，定义域有限的数学函数（如对非负值有定义的 sqrt，或对 [-1..1] 范围有定义的 asin）在编译期确实要计算值时会被检查，如果程序试图计算超出定义域的值，就会报错。若这些函数出现在生成的代码中，也可以（用区间计算系统）检查其使用域，-me 选项在使用域不正确时会显示警告。再次提醒，由于区间计算系统并不完善，可能出现误报，应予核实。

警告消息

警告消息不会中断编译过程，但能提供关于潜在问题代码的有用信息。使用 -wall 编译选项可打印这些消息。只有同时使用 -wall 和 -me 选项时，才会显示数学上的超出定义域错误警告消息。

在运行时调试

interp-tracer 工具

interp-tracer 工具使用解释器后端运行并插桩已编译的程序。运行期间和/或关闭应用时，会收集并显示代码的各种统计信息，典型的有 FP_SUBNORMAL、FP_INFINITE 和 FP_NAN 值，INTEGER_OVERFLOW、CAST_INT_OVERFLOW 和 DIV_BY_ZERO 运算，以及 LOAD/STORE 错误。

参见完整文档与用 interp-tracer 进阶调试教程。

faust2caqt 工具

在 macOS 上，faust2caqt 脚本有一个 -me 选项，可在运行时捕获数学计算异常（浮点异常、整数除零或溢出等）。开发者可以用 dsp_me_checker 类，为指定的 DSP 对象套上数学计算异常处理的代码。

修正错误

之后必须通过仔细检查信号范围来修正这些错误，例如核对 vslider/hslider/nentry 界面控件中的最小/最大值。

其他资源

注意 Faust 的数学库中包含 isnan 和 isinf 函数的实现，开发时可能有用。

正确处理无穷大与非数（NaN）仍是一个棘手的问题，当前版本的编译器尚未完全解决。Dario Sanfilippo 的博客文章非常有助于了解现状，其中给出了大量实用方案，可用来编写更安全的 DSP 代码。
