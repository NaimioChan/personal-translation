在 RNBO 的 Codebox~ 中使用 Faust

本教程介绍如何把 Faust 与 RNBO 配合使用，RNBO 是一套库与工具链，可以把类似 Max 的 patch 导出为可移植代码，并直接编译到 VST、Max External 或 Raspberry Pi 等目标。DSP 程序可以编译为内部的 codebox~ 样本级脚本语言。把 Faust DSP 编译成 codebox~ 代码，可以利用 Faust 库中实现的数百个 DSP 构建模块、开箱即用的示例、Powered By Faust 页面上 200 多个项目中开发的任何 DSP 程序，或网上找到的 Faust DSP 程序。

本教程面向谁？

第一节假定机器上已安装可用的 Faust 编译器，因此更适合常规的 Faust 用户。第二节更适合想了解 Faust 的 RNBO 用户。

使用命令行工具

生成 codebox~ 代码

假定你已经安装了 faust 编译器，从下面这个 DSP 程序 osc.dsp 出发：

import("stdfaust.lib");

vol = hslider("volume [unit:dB]", 0, -96, 0, 0.1) : ba.db2linear : si.smoo;
freq1 = hslider("freq1 [unit:Hz]", 1000, 20, 3000, 1);
freq2 = hslider("freq2 [unit:Hz]", 200, 20, 3000, 1);

process = vgroup("Oscillator", os.osc(freq1) * vol, os.osc(freq2) * vol);

可以用下面这一行生成 codebox~ 代码（注意使用了 -double 选项，这是 RNBO/codebox~ 中默认的样本格式）：

faust -lang codebox -double osc.dsp -o osc.codebox

这会生成一系列用于初始化、更新参数和计算音频帧的函数。

查看生成的代码

生成的代码包含一串参数定义，带有各自的最小值、最大值、步长和默认值：

// 参数
@param({min: 2e+01, max: 3e+03, step: 0.1}) freq1 = 1e+03;
@param({min: 2e+01, max: 3e+03, step: 0.1}) freq2 = 2e+02;
@param({min: -96.0, max: 0.0, step: 0.1}) volume = 0.0;

接着用 @state 装饰器声明 DSP 结构，创建一个在 codebox 对象整个生命周期内持续存在的状态。会创建具有正确类型的标量与数组字段：

// 字段
@state fSampleRate_cb : Int = 0;
@state fConst1_cb : number = 0;
@state fHslider0_cb : number = 0;
@state fConst2_cb : number = 0;
@state iVec0_cb = new FixedIntArray(2);
@state fRec0_cb = new FixedDoubleArray(2);
@state fConst3_cb : number = 0;
@state fHslider1_cb : number = 0;
@state fRec2_cb = new FixedDoubleArray(2);
@state fHslider2_cb : number = 0;
@state fRec3_cb = new FixedDoubleArray(2);
@state iVec1_cb = new FixedIntArray(2);
@state iRec1_cb = new FixedIntArray(2);
@state ftbl0mydspSIG0_cb = new FixedDoubleArray(65536);
@state fUpdated : Int = 0;
@state fControl_cb = new FixedDoubleArray(3);

随后，DSP 初始化代码被放进 dspsetup，它只在 codebox~ 中可用，每次在 Max 中开启音频时都会调用（基本上就是每次切换音频状态，或改变采样率、向量大小时）。这里用 RNBO 当前的采样率初始化 DSP 状态：

// 初始化
function dspsetup() {
    fUpdated = true;
    for (let l2_re0_cb : Int = 0; (l2_re0_cb < 2); l2_re0_cb = (l2_re0_cb + 1)) {
        iVec1_cb[l2_re0_cb] = 0;
    }
    for (let l3_re0_cb : Int = 0; (l3_re0_cb < 2); l3_re0_cb = (l3_re0_cb + 1)) {
        iRec1_cb[l3_re0_cb] = 0;
    }
    for (let i1_re0_cb : Int = 0; (i1_re0_cb < 65536); i1_re0_cb = (i1_re0_cb + 1)) {
        iVec1_cb[0] = 1;
        iRec1_cb[0] = ((iVec1_cb[1] + iRec1_cb[1]) % 65536);
        ftbl0mydspSIG0_cb[i1_re0_cb] = sin((9.587379924285257e-05 * iRec1_cb[0]));
        iVec1_cb[1] = iVec1_cb[0];
        iRec1_cb[1] = iRec1_cb[0];
    }
    fHslider0_cb = 0.0;
    fHslider1_cb = 1e+03;
    fHslider2_cb = 2e+02;
    ...
    ...   
    fSampleRate_cb = samplerate();
    let fConst0_cb : number = min(1.92e+05, max(1.0, fSampleRate_cb));
    fConst1_cb = (44.1 / fConst0_cb);
    fConst2_cb = (1.0 - fConst1_cb);
    fConst3_cb = (1.0 / fConst0_cb);
}

参数处理拆分为两个函数：每次参数变化时调用 control：

// 控制
function control() {
    fControl_cb[0] = (fConst1_cb * pow(1e+01, (0.05 * fHslider0_cb)));
    fControl_cb[1] = (fConst3_cb * fHslider1_cb);
    fControl_cb[2] = (fConst3_cb * fHslider2_cb);
}

只有在至少一个参数发生变化时才真正触发更改，这由全局变量 fUpdated 的状态控制：

// 更新参数
function update(freq1,freq2,volume) {
    fUpdated = int(fUpdated) | (freq1 != fHslider1_cb); fHslider1_cb = freq1;
    fUpdated = int(fUpdated) | (freq2 != fHslider2_cb); fHslider2_cb = freq2;
    fUpdated = int(fUpdated) | (volume != fHslider0_cb); fHslider0_cb = volume;
    if (fUpdated) { fUpdated = false; control(); }
}

最后，compute 处理音频输入并产生音频输出：

// 更新参数
/ Compute one frame
function compute() {
    iVec0_cb[0] = 1;
    fRec0_cb[0] = (fControl_cb[0] + (fConst2_cb * fRec0_cb[1]));
    let iTemp0_cb : Int = (1 - iVec0_cb[1]);
    let fTemp1_cb : number = ((iTemp0_cb) ? 0.0 : (fControl_cb[1] + fRec2_cb[1]));
    fRec2_cb[0] = (fTemp1_cb - floor(fTemp1_cb));
    output0_cb = (fRec0_cb[0] * ftbl0mydspSIG0_cb[max(0, min(int((65536.0 * fRec2_cb[0])), 65535))]);
    let fTemp2_cb : number = ((iTemp0_cb) ? 0.0 : (fControl_cb[2] + fRec3_cb[1]));
    fRec3_cb[0] = (fTemp2_cb - floor(fTemp2_cb));
    output1_cb = (fRec0_cb[0] * ftbl0mydspSIG0_cb[max(0, min(int((65536.0 * fRec3_cb[0])), 65535))]);
    iVec0_cb[1] = iVec0_cb[0];
    fRec0_cb[1] = fRec0_cb[0];
    fRec2_cb[1] = fRec2_cb[0];
    fRec3_cb[1] = fRec3_cb[0];
    return [output0_cb,output1_cb];
}

有了这些代码，每个样本都会执行下面这一串操作：

// 更新参数
update(freq1,freq2,volume);
// 计算一帧
outputs = compute();
// 写出输出
out1 = outputs[0];
out2 = outputs[1];

注意生成的代码使用所谓的标量代码生成模型（默认模型），其中编译好的样本生成代码在 compute 中完成。

测试生成的 codebox~ 代码

要测试的话，生成的代码必须粘贴到外层 RNBO patch 的 codebox~ 组件中，还需要额外的连线来添加所需的音频输入/输出与控制参数。因此更集成、更简单的做法是使用 faust2rnbo 工具。

使用 faust2rnbo 工具

faust2rnbo 工具把 Faust DSP 程序转换为一个 RNBO patch，其中包含 rnbo~ 对象，并把 codebox 代码（由 codebox 后端生成）作为子 patch 包含进去。所需的音频输入/输出与参数（带有正确的名字、默认值、最小值和最大值）会自动加入 patch。另有选项可以生成测试基础设施中使用的特殊版本 RNBO patch。代码用 Python 编写，使用非常强大的 py2max 库生成 maxpat JSON 格式。

faust2rnbo -h
Usage: faust2rnbo [options] [Faust options] <file.dsp>
Compiles Faust programs to RNBO patches
Options:
   -midi : activates MIDI control
   -nvoices <num> : produces a polyphonic DSP with <num> voices, ready to be used with MIDI events
   -effect <effect.dsp> : generates a polyphonic DSP connected to a global output effect, ready to be used with MIDI or OSC
   -effect auto : generates a polyphonic DSP connected to a global output effect defined as 'effect' in <file.dsp>, ready to be used with MIDI or OSC
   -compile : to trigger C++ compilation at load time
   -test : to generate special 'RB_XX' prefix for parameters (for testing)
   -sp : to generate codebox subpatcher as a file.rnbopat file (and possibly file_effect.rnbopat)
   -cpp_path <path> : to set C++ export folder
   -cpp_filename <filename> : to set C++ export filename
   Faust options : any option (e.g. -vec -vs 8...). See the Faust compiler documentation.

生成的 patch 包含：

  • 一个音频 adc~ 输入，自动连接到 rnbo~ 对象（当 DSP 有音频输入时）
  • 一个音频 dac~ 输出，自动与 rnbo~ 对象相连。

所以下面的命令：

faust2rnbo osc.dsp

会直接编译 osc.dsp 文件并生成 osc.maxpat 文件，可以在 Max/MSP 中打开，界面如下：

bargraph 的处理

在 Faust 中，bargraph 通常用于分析音频信号，计算出的值按控制率发送。这在 RNBO 模型中无法直接做到，因为 codebox~ 代码只能发送音频信号。因此会为 bargraph 创建额外的音频输出，采样后（使用 snapshot~ 与 change）作为输入控制器接到 param 对象上。

所以例如下面这个示例：

import("stdfaust.lib");

process = vmeter,hmeter
with {
    vmeter(x) = attach(x, envelop(x) : vbargraph("vmeter dB [midi:ctrl 1]", -96, 10));
    hmeter(x) = attach(x, envelop(x) : hbargraph("hmeter dB [midi:ctrl 2]", -96, 10));

    envelop = abs : max(ba.db2linear(-96)) : ba.linear2db : min(10) : max ~ -(96.0/ma.SR);
};

用 faust2rnbo 编译后，会创建一个含 2 个音频输入和 4 个音频输出（2 个真实的，2 个用于 bargraph）的子 patch，以及如下用户界面：

以及显示 bargraph 值的主 patch：

MIDI 控制

可以用 -midi 选项，或在 DSP 代码中使用 declare options "[midi:on]"; 语法，来启用参数的 MIDI 控制。这样 patch 会在全局层面包含 midiin/midiout 对象，并在 codebox 子 patch 中包含专门的 ctlin/notein etc. 对象，配合适当的 scale 对象把 MIDI 消息范围映射到目标参数范围。

所以例如这个加入 MIDI 的示例：

import("stdfaust.lib");

declare options "[midi:on]";

vol = hslider("volume [unit:dB][midi: ctrl 7]", 0, -96, 0, 0.1) : ba.db2linear : si.smoo;
freq1 = hslider("freq1 [unit:Hz][midi: ctrl 1]", 1000, 20, 3000, 0.1);
freq2 = hslider("freq2 [unit:Hz][midi: ctrl 2]", 200, 20, 3000, 0.1);

process = vgroup("Oscillator", os.osc(freq1) * vol, os.osc(freq2) * vol);

现在可以用 MIDI 音量（ctrl 7）以及 ctrl 1 和 ctrl 2 分别控制每个声道的频率。在 GUI 中对参数所做的修改会作为 MIDI 输出消息发送出去。

而下面的命令：

faust2rnbo -midi osc.dsp

会编译出一个包含额外 midiin/midiout 对象的 osc.maxpat 文件，界面如下：

生成的带 MIDI 控制的 RNBO patch

复音乐器

当 DSP 遵循支持复音乐器的约定时，就可以在 MIDI 可控的复音模式下启用。所以下面这个 DSP 程序：

declare options "[midi:on][nvoices:8]";
import("stdfaust.lib");

process = vgroup("Organ", voice(freq) * gain * en.adsr(0.1, 0.1, 0.8, 0.3, button("gate"))) * master <: (_,_)
with {
    master = hslider("master [midi:ctrl 7]", 0.5, 0, 1, 0.01);
    gain = hslider("gain", 0.5, 0, 1, 0.01);
    freq = hslider("freq", 500, 200, 3000, 0.1);
    voice(freq) = os.osc(freq) + os.osc(freq*2)*0.5 + os.osc(freq*3)*0.25;
};

用下面的命令编译：

faust2rnbo -midi -nvoices 12 organ.dsp

会创建一个含 12 个声部的 rnbo~ 对象的 patch，在子 patch 中加入 notein 对象并正确连接到能感知 freq/gain/gate 的相应参数。根据描述音高（freq 或 key）或增益（gain 或 velocity）所用的约定，还会在需要时加入额外的映射，最终界面如下：

生成的带 MIDI 控制的复音 RNBO patch

在 DSP 中，注意总滑块可以用 Ctrl 7（= 音量）MIDI 消息控制。

注意这里同样可以用 -sp 选项生成 rnbo~ 对象的子 patch，并可能用于其他场景。

带效果的复音乐器

下面这个集成了效果的支持复音乐器的 DSP 可以转换为复音 MIDI 就绪的 patch：

declare options "[midi:on][nvoices:8]";
import("stdfaust.lib");

process = vgroup("Organ", voice(freq) * gain * en.adsr(0.1, 0.1, 0.8, 0.3, button("gate"))) * master <: (_,_)
with {
    master = hslider("master [midi:ctrl 7]", 0.5, 0, 1, 0.01);
    gain = hslider("gain", 0.5, 0, 1, 0.01);
    freq = hslider("freq", 500, 200, 3000, 0.1);
    voice(freq) = os.osc(freq) + os.osc(freq*2)*0.5 + os.osc(freq*3)*0.25;
};

effect = dm.freeverb_demo;

用下面的命令编译：

faust2rnbo -midi -nvoices 16 -effect auto organ2.dsp

生成的用户界面与复音 DSP rnbo~ 对象使用 p 抽象模型来加载并激活复音乐器（作为 organ2.rnbopat 文件），并连接到全局效果（作为 organ2_effect.rnbopat 文件）。要让导出的项目正确生成，必须只有一个 rnbo~ 对象并内嵌这两个子 patch：

使用 Faust 网页版 IDE

Faust DSP 程序可以在 Faust 网页版 IDE 中编写、测试，并生成为 RNBO patch。

生成 RNBO patch

可以直接用 Platform = rnbo 与 Architecture = rnbo 导出选项生成 RNBO patch。得到的 foo 文件夹是自包含的，包含可用 Max/MSP 打开的 foo.maxpat 文件。

导出代码

以复音模式生成 RNBO patch

遵循复音freq/gate/gain 约定的 DSP 程序可以用 Platform = rnbo 与 Architecture = rnbo-poly 导出选项生成。得到的 foo 文件夹是自包含的，包含可用 Max/MSP 打开的 foo.maxpat 文件。

以复音模式并带全局效果生成 RNBO patch

遵循复音freq/gate/gain 约定、并带集成效果的 DSP 程序可以用 Platform = rnbo 与 Architecture = rnbo-poly-effect 导出选项生成。得到的 foo 文件夹是自包含的，包含 foo.maxpat、foo.rnbopat 与 foo_effect.rnbopat 文件（使用 p 抽象模型）；用 Max/MSP 打开 foo.maxpat 即可。

从网上找到的 Faust DSP 程序生成 RNBO patch

网上找到的 Faust DSP 程序也可以转换：

  • 例如 Powered By Faust 页面上列出的 fverb。用 https://faustide.grame.fr/?code=URL 语法配合下面这个 URL 即可加载它的 DSP 内容：https://faustide.grame.fr/?code=https://raw.githubusercontent.com/jpcima/fverb/master/fverb.dsp，在 Faust 网页版 IDE 中测试后，再按上述方法转换为 RNBO patch。

  • faustplayground 平台的示例可以在此找到并转换。
