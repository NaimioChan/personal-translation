居家篇：为你的 JUCE 插件添加 Faust DSP 支持

JUCE 是一个知名框架，用于为大量平台创建音频插件（即 VST、AU、AAX 等）和应用。可以用 Faust 配合 faust2juce 生成开箱即用的 JUCE 应用和插件，它们实现 Faust 代码中描述的标准用户界面（UI）。不过在 JUCE 中从零做出专业外观的 UI 非常容易，所以你可能更愿意用 Faust 实现插件的 DSP 部分，并自己构建 UI。

本教程演示如何用 Faust 编译器生成 C++ DSP 对象，以及如何把它与你的 JUCE 插件/UI 对接。我们涵盖基础示例（单音合成器、复音合成器、音频效果器）以及涉及复音等更高级的应用。

本节演示如何用 Faust 合成器在 JUCE 中从零构建带自定义 UI 的插件。

生成 DSP 引擎

首先，用 Faust 实现一个基于滤波锯齿波的基础减法合成器（FaustSynth.dsp）：

import("stdfaust.lib");
freq = nentry("freq",200,50,1000,0.01);
gain = nentry("gain",0.5,0,1,0.01) : si.smoo;
gate = button("gate") : si.smoo;
cutoff = nentry("cutoff",10000,50,10000,0.01) : si.smoo;
process = os.sawtooth(freq)*gain*gate : fi.lowpass(3,cutoff) <: _,_;

不妨在网页版 IDE 中运行它，听听效果！

低通的输出被分成 2 路信号，以创建立体声对象。

注意所有参数都做了平滑处理以防咔嗒声（我们希望插件干净！）。连 gate 也做了平滑，这样在发送触发信号时会施加一个平缓的指数包络，等等。

由于这里 Faust 不会构建自己的 UI，代码中使用哪种界面控件并不重要。它们只是作为控制即将生成的音频引擎参数的入口。所以 nentry 可以换成 hslider 或 vslider，没有任何区别。不过我们建议你始终写出「自洽」的界面，以防某天有人想「原样」使用你的 Faust 代码。

为了把这个 Faust 程序变成可在 JUCE 中使用的 C++ DSP 对象，必须使用一个 Faust 架构文件来包装 Faust 编译器生成的 C++ 代码（后者实际上只包含一个音频回调函数）。faustMinimal.h（包含在本教程开头下载的包中）就是做这件事的。实际上，打开它你会看到：

#include <cmath>
#include <cstring>

#include "faust/gui/MapUI.h"
#include "faust/gui/meta.h"
#include "faust/dsp/dsp.h"

// BEGIN-FAUSTDSP

<<includeIntrinsic>>

<<includeclass>>

// END-FAUSTDSP

如果系统安装了 Faust，faust/... 下的文件应该已经存在。如果没有，可以使用架构文件的内联版本（faustMinimalInlined.h），它同样可以在本教程开头下载的包中找到。

MapUI.h 让我们可以用 Faust 代码中声明的名称轻松控制 Faust 对象的参数。其他 include 在多数情况下都是必需的，它们只是 Faust 编译器生成的 DSP 类的父类。<<includeclass>> 是 Faust 编译器生成的代码被粘贴的位置。

只需运行以下命令，就可以把该架构文件用于 Faust 编译器：

faust -i -a faustMinimal.h FaustSynth.dsp -o FaustSynth.h

其中 FaustSynth.h 是生成文件的名称，本教程稍后会在 JUCE 项目中导入它。-i 选项会把包含的 C++ 文件内联进生成的文件。

另外，如果系统没有安装 Faust，可以用 Faust 在线 IDE 完成同样的工作，在导出（卡车）功能中选择 source/cplusplus。然后把下载的 C++ 文件内容复制粘贴到 BEGIN-FAUSTDSP 与 END-FAUSTDSP 标签之间。

现在可以创建新的 JUCE 插件项目了！

把 Faust DSP 对象集成到 JUCE 项目

现在把 Faust 生成的 DSP 对象集成到 PluginProcessor 中。在 PluginProcessor.h 的 MonoSynthAudioProcessor 类的 private 区声明以下成员：

private:
    MapUI* fUI;
    dsp* fDSP;
    float** outputs;
    //==============================================================================
    JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR (MonoSynthAudioProcessor)

fUI 用于控制 Faust DSP 的参数，fDSP 将包含音频 DSP/回调本身（基本上就是 Faust 编译器生成的对象）。为了在不知道 MapUI 和 dsp 定义的情况下声明这些对象，你还必须在文件开头声明空的类定义：

class dsp;
class MapUI;

class MonoSynthAudioProcessor : public AudioProcessor

在 PluginProcessor.cpp 中，在文件开头的 include 区加入 FaustSynth.h：

#include "PluginProcessor.h"
#include "PluginEditor.h"
#include "FaustSynth.h"

在 prepareToPlay 方法中写入以下内容：

void MonoSynthAudioProcessor::prepareToPlay(double sampleRate, int samplesPerBlock)
{
    fDSP = new mydsp();
    fDSP->init(sampleRate);
    fUI = new MapUI();
    fDSP->buildUserInterface(fUI);
    outputs = new float*[2];
    for (int channel = 0; channel < 2; ++channel) {
        outputs[channel] = new float[samplesPerBlock];
    }
}

这里首先实例化 fDSP，即 Faust DSP 对象。然后实例化 fUI，用于控制 DSP 的参数。这两个对象通过 fDSP 的 buildUserInterface 方法绑定在一起。最后为 Faust 对象的立体声输出分配内存。注意 outputs 是一个二维数组（一维表示声道，一维表示音频样本/缓冲区）。

相应地，在 MonoSynthAudioProcessor 的 releaseResources 方法中写入以下内容：

void MonoSynthAudioProcessor::releaseResources()
{
    delete fDSP;
    delete fUI;
    for (int channel = 0; channel < 2; ++channel) {
        delete[] outputs[channel];
    }
    delete [] outputs;
}

这里只是在资源释放时释放前面步骤分配的内存。

现在进入正题：通过 MonoSynthAudioProcessor 的 processBlock 方法实现的音频回调：

void MonoSynthAudioProcessor::processBlock (AudioBuffer<float>& buffer, MidiBuffer& midiMessages)
{
    ScopedNoDenormals noDenormals;
    auto totalNumInputChannels = getTotalNumInputChannels();
    auto totalNumOutputChannels = getTotalNumOutputChannels();

    fDSP->compute(buffer.getNumSamples(),NULL,outputs);

    for (int channel = 0; channel < totalNumOutputChannels; ++channel) {
        for (int i = 0; i < buffer.getNumSamples(); i++) {
            *buffer.getWritePointer(channel,i) = outputs[channel][i];
        }
    }
}

这里我们基本上计算一个大小为 buffer.getNumSamples() 的完整音频块，存入 outputs，然后把 outputs 链接到 processBlock 的实际音频输出（*buffer.getWritePointer(channel,i)）。

此时你的插件应该能发声了！在 prepareToPlay 方法中临时加入以下一行，把 gate 参数设为 1：

fUI->setParamValue("gate",1);

注意这里如何用 fUI 的 setParamValue 方法配置 Faust DSP 的参数，该方法有两个参数：参数在 Faust 代码中的路径/名称，以及它的值。

为目标平台（例如 VST、AU 等）编译插件。在我们的例子中，为方便起见只生成独立插件。运行插件时，你现在应该能听到声音！

生成 DSP 引擎

用 Faust 生成音频效果器 C++ DSP 对象的步骤与合成器完全相同（见上一节），也可以使用 faustMinimal.h 架构文件。

本示例中我们使用一个立体声回声：

import("stdfaust.lib");
echo(d,f) = +~de.delay(48000,del)*f

  del = d*ma.SR;
};
delay = nentry("delay",0.25,0,1,0.01) : si.smoo;

创建复音合成器 DSP 对象的流程与简单单音合成器（如本教程开头介绍的那个）略有不同。这里我们使用与单音合成器示例相同的 Faust 程序。要启用复音，只需配置 nvoices 元数据，它用于指定将要生成的 DSP 对象的最大复音声部数：

faust-poly-engine.h 包含 FaustPolyEngine 类，可用于把 Faust C++ DSP 对象变成复音合成器。为了让这个类工作，必须提供一个「音频驱动」，dummy-audio.h 中提供的 dummyaudio 类正是为此。它还允许我们把采样率和缓冲区大小传给 FaustPolyEngine。

用这个架构文件编译之前的 Faust 程序，可以使用 Faust 命令行编译器或网页版 IDE：

}

当然，别忘了在 PluginProcessor.h 中声明这些方法。

keyOn 会分配一个新的声部，把它的 pitch 参数转换为频率并自动发送给 Faust 的 freq 参数，velocity 被转换为电平并发送给 gain 参数，gate 参数被设为 1。反过来说，keyOff 把 gate 设为 0，并等待到达 t60 后再释放当前声部。

keyOn 返回一个类型为 unsigned long 的声部 ID。这个 ID 随后可用于改变特定声部的参数。本教程的示例中没有使用这个功能，但它的用法如下：

unsigned long voiceID = dspFaust.keyOn(60,110);
dspFaust.setVoiceParamValue("/synth/cutoff",voiceID,378);

注意，也可以不用 keyOn 和 keyOff，而是用 newVoice 和 deleteVoice 方法直接分配声部：

unsigned long voiceID = dspFaust.newVoice();
dspFaust.setVoiceParamValue("/synth/gate",voiceID,1);
// 做一些事情……
dspFaust.deleteVoice(voiceID);

像当前示例这样使用 setParamValue，可以为 DSP 引擎的所有声部设置某个参数的值。

以下实现极其简陋，只处理来自 UI 键盘的消息：我们这样做只是为了示例。如果你从未在 JUCE 中处理过键盘和 MIDI，我们强烈建议阅读这个教程。

在 PluginEditor.h 中，先给 PolySynthAudioProcessorEditor 类加上以下继承：

class PolySynthAudioProcessorEditor : 
  public AudioProcessorEditor, 
  private MidiInputCallback, 
  private MidiKeyboardStateListener
{

这是实现 MIDI 回调和键盘（UI）监听器所必需的。该继承要求我们在 PluginEditor.h 的 private 区实现以下方法。我们还会加入一个 UI 键盘实例及其关联状态，以及一个滑块及其标签，用于控制低通的截止频率：

private:
  void handleNoteOn(MidiKeyboardState*, int midiChannel, int midiNoteNumber, float velocity) override;
  void handleNoteOff(MidiKeyboardState*, int midiChannel, int midiNoteNumber, float /* 力度 */) override;
  void handleIncomingMidiMessage(MidiInput* source, const MidiMessage& message) override;

  MidiKeyboardState keyboardState;   
  MidiKeyboardComponent keyboardComponent; 

  Slider cutoffSlider;
  Label cutoffLabel;

在 PluginEditor.cpp 中，可以把键盘和滑块加入构造函数：

PolySynthAudioProcessorEditor::PolySynthAudioProcessorEditor (PolySynthAudioProcessor& p)
    : AudioProcessorEditor(&p), processor(p), keyboardComponent (keyboardState, MidiKeyboardComponent::horizontalKeyboard)
{
    setSize (800, 150);

    addAndMakeVisible(keyboardComponent);
    keyboardState.addListener(this);

    addAndMakeVisible(cutoffSlider);
    cutoffSlider.setRange(50.0, 10000.0);
    cutoffSlider.setValue(5000.0);
    cutoffSlider.onValueChange = [this] { 
        processor.setCutoff(cutoffSlider.getValue()); 
    };

    addAndMakeVisible(cutoffLabel);
    cutoffLabel.setText("Cutoff", dontSendNotification);
    cutoffLabel.attachToComponent(&cutoffSlider, true);
}

并且必须在析构函数中释放键盘状态监听器：

PolySynthAudioProcessorEditor::~PolySynthAudioProcessorEditor()
{
    keyboardState.removeListener(this);
}

setCutoff 方法的实现在本教程后面详述，与上一节介绍的非常相似。

我们还需要定义界面中各元素的尺寸（像之前那样）：

void PolySynthAudioProcessorEditor::resized()
{
    const int sliderLeft = 80;
    keyboardComponent.setBounds (10,10,getWidth()-30,100);
    cutoffSlider.setBounds(sliderLeft, 120, getWidth() - sliderLeft - 20, 20);
}

只需实现以下继承方法，就可以从键盘获取 MIDI 消息：

void PolySynthAudioProcessorEditor::handleIncomingMidiMessage (MidiInput* source, const MidiMessage& message) {}

void PolySynthAudioProcessorEditor::handleNoteOn(MidiKeyboardState*, int midiChannel, int midiNoteNumber, float velocity)
{
    processor.keyOn(midiNoteNumber,int(127*velocity));
}

void PolySynthAudioProcessorEditor::handleNoteOff(MidiKeyboardState*, int midiChannel, int midiNoteNumber, float /* 力度 */)
{
    processor.keyOff(midiNoteNumber);
}
