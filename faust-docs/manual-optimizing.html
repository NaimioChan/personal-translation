优化代码

优化 DSP 代码

Faust 是一门领域特定语言，帮程序员写出非常高层、简洁的 DSP 代码，而把生成该规格最佳、最高效实现的繁重工作交给编译器。处理 DSP 源码时，编译器的类型系统能发现所描述的计算实际上分为四大类：

  • 在编译/特化期完成的计算：这里适合以构成该语言的 lambda 演算及其模式匹配能力为基础的算法化信号处理器定义
  • 在初始化期完成的计算：例如所有依赖实际采样率的代码，或填充内部表的代码（用 rdtable 或 rwtable 语言基元编写）
  • 在控制率完成的计算：典型的是读取控制器（按钮、滑块、数值输入框）当前值、并更新依赖它们的 DSP 内部状态的所有代码
  • 在采样率完成的计算：其余所有处理和生产样本的代码

可以把这四类看作不同的计算率。程序员可以拆分 DSP 算法，把所需计算分配到最合适的域（较慢的率域通常优于较快的率域），也可以把 DSP 算法的某些部分从某个域改写到更慢的率域，以获得最高效的代码。

特化 DSP 代码

Faust 编译器在编译期可以完成许多优化。例如，DSP 代码可以按固定采样率编译，从而在编译期完成所有依赖采样率的计算。由于 Faust 编译器从本地目录开始搜索库，一种简单的做法是把 libraries/platform.lib 文件（其中包含 SR 定义）复制到本地，并把它改成固定值，例如 48,000 Hz。然后必须重新编译 DSP 代码，特化才会生效。注意 libraries/platform.lib 还包含 tablesize 常量的定义，它在多处用于为振荡器分配表。因此减小该值可以节省内存，例如为嵌入式设备编译时。某些 Faust 服务脚本就采用这一技术：它们在 Faust 命令行上添加 -I /usr/local/share/faust/embedded/ 参数，以使用特殊版本的 platform.lib 文件。

在初始化期完成的计算

如果没有在编译期用常量值特化，那么所有使用采样率的计算（在 DSP 源码中用 ma.SR 访问，在 DSP 的 init 函数中作为参数提供）都在初始化期完成，而且每当同一个 DSP 以另一个采样率初始化时可能再执行一次。

在控制率完成的计算

参数平滑

控制参数每块采样一次，其值在块内视为常量，依赖它们的内部状态在 compute 方法开头、采样率 DSP 循环之前更新。

在下面的 DSP 代码中，vol 滑块的值直接作用于输入音频信号：

import("stdfaust.lib");
vol = hslider("Volume", 0.5, 0, 1, 0.01);
process = *(vol);

为 compute 生成的 C++ 代码中，vol 滑块的值在实际 DSP 循环之前采样，方式是读取保存在局部变量 fSlow0 中的 fHslider0 字段：

virtual void compute(int count, FAUSTFLOAT** inputs, FAUSTFLOAT** outputs) {
    FAUSTFLOAT* input0 = inputs[0];
    FAUSTFLOAT* output0 = outputs[0];
    float fSlow0 = float(fHslider0);
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        output0[i0] = FAUSTFLOAT(fSlow0 * float(input0[i0]));
    }
}

如果控制参数需要用 control : si.smoo 这类代码平滑（例如避免咔嗒声或突变），计算率就从控制率移到采样率。若把前面的 DSP 代码改成：

import("stdfaust.lib");
vol = hslider("Volume", 0.5, 0, 1, 0.01) : si.smoo;
process = *(vol);

vol 滑块在实际 DSP 循环之前采样，乘以初始化期算出的滤波器常量 fConst0，最后在 DSP 循环中用于平滑滤波器：

virtual void compute(int count, FAUSTFLOAT** inputs, FAUSTFLOAT** outputs) {
    FAUSTFLOAT* input0 = inputs[0];
    FAUSTFLOAT* output0 = outputs[0];
    float fSlow0 = fConst0 * float(fHslider0);
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        fRec0[0] = fSlow0 + fConst1 * fRec0[1];
        output0[i0] = FAUSTFLOAT(float(input0[i0]) * fRec0[0]);
        fRec0[1] = fRec0[0];
    }
}

因此 CPU 占用显然更高，是否需要参数平滑应仔细权衡。

另一点要考虑的是平滑控制时的计算顺序。在下面的 DSP 代码中，dB 滑块的值先转换为线性值，再平滑：

import("stdfaust.lib");
smoother_vol = hslider("Volume", -6.0, -120.0, .0, 0.01) : ba.db2linear : si.smoo;
process = *(smoother_vol);

为 compute 生成的 C++ 代码中，ba.db2linear 里开销较大的 pow 数学函数在控制率求值，即 DSP 循环之前只算一次：

virtual void compute(int count, FAUSTFLOAT** inputs, FAUSTFLOAT** outputs) {
    FAUSTFLOAT* input0 = inputs[0];
    FAUSTFLOAT* output0 = outputs[0];
    float fSlow0 = fConst0 * std::pow(1e+01f, 0.05f * float(fHslider0));
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        fRec0[0] = fSlow0 + fConst1 * fRec0[1];
        output0[i0] = FAUSTFLOAT(float(input0[i0]) * fRec0[0]);
        fRec0[1] = fRec0[0];
    }
}

但如果把 ba.db2linear 与 si.smoo 的顺序反过来，如以下代码所示：

import("stdfaust.lib");
smoother_vol = hslider("Volume", -6.0, -120.0, .0, 0.01) : si.smoo : ba.db2linear;
process = *(smoother_vol);

为 compute 生成的 C++ 代码中，ba.db2linear 里用的 pow 数学函数现在在 DSP 循环中按采样率求值，开销显然大得多：

virtual void compute(int count, FAUSTFLOAT** inputs, FAUSTFLOAT** outputs) {
    FAUSTFLOAT* input0 = inputs[0];
    FAUSTFLOAT* output0 = outputs[0];
    float fSlow0 = fConst0 * float(fHslider0);
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        fRec0[0] = fSlow0 + fConst1 * fRec0[1];
        output0[i0] = FAUSTFLOAT(float(input0[i0]) * std::pow(1e+01f, 0.05f * fRec0[0]));
        fRec0[1] = fRec0[0];
    }
}

要让生成的代码性能最佳，所有开销大的计算都应尽量作用在控制值上（尽可能如此——这并不总是可取），并把 si.smoo（或任何把计算从控制率移到采样率的函数）作为最后一步操作。

在采样率完成的计算

可以用 -ct 选项关闭表的范围检查

-ct 选项默认开启（自 Faust 2.53.4 版起），但可以去掉（用 -ct 0）以加速代码。完整说明见调试 rdtable 与 rwtable 基元。

使用函数制表

在初始化期完成 rdtable 风格的编译，可以用 ba.tabulate 或 ba.tabulate_chebychev 函数简化：它们在给定区间上把给定的一元函数 fun 制表。系统创建一张表并填入预先算好的值，用于以更高效的方式计算 fun(x)（代价是表需要额外的静态内存）。

使用快速数学函数

当开销大的数学函数仍出现在采样率代码中时，可以用 -fm 编译选项把底层操作系统提供的标准版本（例如 C++ 中的 std::cos、std::tan 等）替换为用户自定义版本（希望更快，但可能精度较低）。

延迟线的实现与 DSP 内存占用

Faust 编译器自动为延迟线分配缓冲区。每次样本计算时，延迟信号写入某个位置（写位置），并从另一个位置（读位置）读出，读写索引之间的样本距离就是延迟本身。

实现延迟线有两种策略：要么读写索引保持不变、每次样本计算后移动延迟线内存，要么读写索引沿延迟线自行移动（有两种回绕索引方式）。这些方法可在内存消耗与使用延迟线的 CPU 开销之间取舍。

两个编译器选项 -mcd <n>（-max-copy-delay）和 -dlt <n>（--delay-line-threshold）可让你调整这两种策略，甚至组合使用。

对于最多两个样本的极短延迟线，第一种策略通过手动搬移缓冲区实现。随后，对 2 个到 -mcd <n> 个样本的延迟会生成搬移循环。

对于大于 -mcd <n> 个样本的延迟值，第二种策略通过以下方式实现：

  • 当延迟小于 -dlt <n> 值时，使用大小为 2 的幂的数组，并以基于掩码的索引计算访问。
  • 或者使用基于 if 的方式移动回绕索引：递增的索引与延迟线大小比较，达到时回绕到零。该方法用于大于 -dlt <n> 的延迟值。

在这一策略中，第一种方法更快但消耗更多内存（给定大小的延迟线会扩展到下一个 2 的幂大小），第二种方法更慢但占用内存更少。

注意默认使用 -mcd 16 和 -dlt <INT_MAX> 值。下图说明了该机制：

[ shift buffer |-mcd <N1>| wrapping power-of-two buffer |-dlt <N2>| if based wrapping buffer ]

在这个代码示例中，可以通过 fVec0_ridx_tmp0 和 fVec0_widx_tmp0 这类变量认出基于 if 方式移动的回绕索引。

在嵌入式设备场景中，选择占用内存更少的值可能尤为重要。试验 -mcd 与 -dlt 选项的不同组合有助于优化 CPU 利用率，总结如下：

  • 为 -mcd n 选较大的 n 值会消耗更少内存，但延迟值较大时搬移循环会开始耗时。如果 C++ 或 LLVM 编译器能正确自动向量化代码并生成更高效的 SIMD 代码，这种模型有时可能更合适。
  • 选 -mcd 0 会让 DSP 代码中所有延迟线都使用回绕索引的第二种策略，然后用 -dlt <n> 在更快但占用更多内存与更慢但占用更少内存两种方法之间取舍。
  • 当 DSP 代码中使用大量不同大小的延迟线时，选择 -mcd n1 与 -dlt <n2> 的组合可能更合适。

使用基准测试工具 faustbench 与 faustbench-llvm 可以细化编译选项的选择。

递归信号

在生成的 C++ 代码中，延迟线表现为 fVecXX 数组。DSP 中使用递归时，递归路径上会自动加入一个样本的延迟，并分配一条极短的延迟线（在生成的代码中表现为 fRecX 数组）。下面是递归定义的积分器代码：

process = 1 : + ~ _;

以及带 iRec0 缓冲区的生成 C++ 代码：

...
// DSP 的内存布局
int iRec0[2];
...
virtual void compute(int count, 
    FAUSTFLOAT** RESTRICT inputs, 
    FAUSTFLOAT** RESTRICT outputs) 
{
    FAUSTFLOAT* output0 = outputs[0];
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        iRec0[0] = iRec0[1] + 1;
        output0[i0] = FAUSTFLOAT(iRec0[0]);
        iRec0[1] = iRec0[0];
    }
}
...

递归信号中的延迟线

下面是一个 Faust 程序示例，十个并联的递归块，每个使用一条长度递增的延迟线：

process = par(i, 10, + ~ @(i+1)) :> _;

由于递归信号在其环路中使用一个样本的延迟，会分配一个缓冲区来处理该延迟。当递归信号之外还用了延迟时，会分配单个缓冲区来合并这两个延迟来源。例如用 faust -mcd 0 生成的代码现在是：

...

float fRec8[16];

    FAUSTFLOAT* input1 = inputs[1];

        fRec0[IOTA0 & 3] = float(input0[i0]) + fRec0[(IOTA0 - 2) & 3];
        fRec1[IOTA0 & 3] = float(input1[i0]) + fRec1[(IOTA0 - 3) & 3];
        fRec2[IOTA0 & 7] = float(input2[i0]) + fRec2[(IOTA0 - 4) & 7];
        fRec3[IOTA0 & 7] = float(input3[i0]) + fRec3[(IOTA0 - 5) & 7];

        fRec6[IOTA0 & 15] = float(input6[i0]) + fRec6[(IOTA0 - 8) & 15];
        fRec7[IOTA0 & 15] = float(input7[i0]) + fRec7[(IOTA0 - 9) & 15];
        fRec8[IOTA0 & 15] = float(input8[i0]) + fRec8[(IOTA0 - 10) & 15];
        fRec9[IOTA0 & 15] = float(input9[i0]) + fRec9[(IOTA0 - 11) & 15];

        IOTA0 = IOTA0 + 1;
    }

缓冲区命名为 fRecX 而非上一示例中的 fVecX。-mcd <n> 与 -dlt <n> 选项也可用于同样的目的。

管理 DSP 内存布局

在内存被分成若干块（如 SRAM、SDRAM……）、访问时间各不相同的音频板上，就需要细化 DSP 内存模型，使 DSP 结构不被分配在单一块内存上，而可能分布到所有可用块上。思路是把 DSP 中经常访问的部分分配到快速内存，其余分配到慢速内存。这可以用 -mem 编译选项和相应的架构文件来控制。

优化 C++ 或 LLVM 代码

对于给定的 DSP 程序，Faust 编译器会尽力生成最高效的实现。优化可以在编写 DSP 时进行，也可以在之后生成目标语言（如 C++ 或 LLVM IR）时进行。生成的代码依编译选项不同会有不同的形态，运行速度可快可慢。有多种程序和工具可帮 Faust 程序员测试程序是否有数值或精度问题、找出给定 DSP 代码的最佳选项集合，最后把它们编译成面向目标 CPU 的本地代码。

默认情况下 Faust 编译器在生成的 mydsp::compute 方法中产生一个大的标量循环。编译选项可让你生成其他形态的代码，例如在所谓的向量化模式下（用 -vec 选项获得）生成用缓冲区相连的若干更简单的独立循环。其假设是现代编译器中的自动向量化过程能为它们生成更高效的 SIMD 代码。在这个 vec 选项中，内部缓冲区的大小可以用 -vs value 选项更改。此外计算图可以用 -dfs 按深度优先顺序组织。

延迟线的实现可以用 -mcd size 与 -dlt size 选项控制，例如在大小为 2 的幂、基于掩码的回绕（更快但占用更多内存）与基于 if 的回绕（更慢但占用更少内存）之间选择。

还有许多其他编译选择完全可以通过选项控制。注意 C/C++ 与 LLVM 后端提供的编译选项最多。以下只是其中几个：

  • -clang 选项：用 clang/clang++ 编译时，为自动向量化添加特定的 #pragma。
  • -nvi 选项：用 C++ 后端编译时，不添加 'virtual' 关键字。该选项在嵌入式设备场景中特别有用
  • -mapp 选项：'floor/ceil/fmod/remainder' 函数的更简单、更快的版本（实验性）

逐个手动测试它们及其组合是不现实的。因此开发了若干工具来自动化这一过程，帮助搜索配置空间以找出最佳编译选项集合（务必在 Faust 顶层目录运行 make benchmark && sudo make devinstall 来安装基准测试工具）：

faustbench

faustbench 工具使用 C++ 后端，生成一组用不同 Faust 编译器选项产生的 C++ 文件。然后所有文件被编译进一个二进制文件，用于测量编译后各个 DSP 版本的 CPU 占用。该工具本应在终端中启动，但也可用于生成 iOS 工程，准备好在 Xcode 中启动和测试。更完整的文档见此页面。

faustbench-llvm

faustbench-llvm 工具使用 libfaust 库及其 LLVM 后端，动态编译用不同 Faust 编译器选项产生的 DSP 对象，然后测量它们的 DSP CPU 占用。除工具会自动探索的选项外，还可以给出附加的 Faust 编译器选项。更完整的文档见此页面。

faust2bench

faust2bench 工具可对给定 DSP 程序做基准测试：

faust2bench -h
Usage: faust2bench [Faust options] <file.dsp>
Compiles Faust programs to a benchmark executable

因此类似 faust2bench -vec -lv 0 -vs 4 foo.dsp 的命令用于生成一个可执行文件，然后启动 ./foo 会给出：

./foo
./foo : 303.599 Mframes/sec (DSP CPU % : 0.224807 at 44100 Hz)

-inj 选项可以注入并基准测试一个外部 C++ 类，使其适配为 dsp 类的行为，如下面 adapted.cpp 示例所示。继承的 compute 方法被重写为调用外部 C++ 的 limiterStereo.SetPreGain 等代码来更新控制器，以及调用计算 DSP 的 limiterStereo.Process 方法：

#include "faust/dsp/dsp.h"
#include "Limiter.hpp"

struct mydsp : public dsp {

    Limiter<float> limiterStereo;

    void init(int sample_rate)
    {
        limiterStereo.SetSR(sample_rate);
    }

    int getNumInputs() { return 2; }
    int getNumOutputs() { return 2; }

    int getSampleRate() { return 44100; }

    void instanceInit(int sample_rate)
    {}

    void instanceConstants(int sample_rate)
    {}
    void instanceResetUserInterface()
    {}
    void instanceClear()
    {}

    void buildUserInterface(UI* ui_interface)
    {}

    dsp* clone()
    {
        return new mydsp();
    }
    void metadata(Meta* m)
    {}

    void compute(int count, FAUSTFLOAT** inputs, FAUSTFLOAT** outputs)
    {
        limiterStereo.SetPreGain(0.5);
        limiterStereo.SetAttTime(0.5);
        limiterStereo.SetHoldTime(0.5);
        limiterStereo.SetRelTime(0.5);
        limiterStereo.SetThreshold(0.5);

        limiterStereo.Process(inputs, outputs, count);
    }

};

用 faust2bench -inj adapted.cpp dummy.dsp 会创建可执行文件，用 ./dummy 测试（记住 dummy.dsp 是一个在 -inj 模式下实际未使用的程序）。

faustcompilerbenchtool

faustcompilerbenchtool 是一套用于分析和测量 Faust 编译器生成的 C++ 代码性能的工具。这些工具在开发新的编译策略时特别有用，因为它们能确保正确性并评估性能影响。更完整的文档见此页面。

dynamic-faust

dynamic-faust 工具使用动态编译链（基于 LLVM 后端），把 Faust DSP 源码编译成 LLVM IR（.ll）、位码（.bc）、机器码（.mc）或目标码（.o）输出文件。这是 C++ 编译链的替代方案，因为 DSP 代码可以编译成目标码（.o），然后在常规 C++ 项目中使用并链接。更完整的文档见此页面。

用任意 faust2xx 工具优化

所有 faust2xx 工具默认以标量模式编译，但可以接受任意组合的最优选项（例如 -vec -fun -vs 32 -dfs -mcd 32），这些选项正是前面所述工具会自动找出的。因此串接使用 faustbench 或 faustbench-llvm 找出给定 DSP 的最佳编译选项，再在所需的 faust2xx 工具中使用，就能得到 CPU 优化的独立程序或插件。

注意某些 faust2xx 工具如 faust2max6 或 faust2caqt 可以在内部调用 faustbench-llvm 工具，找出并在之后使用尽可能好的编译选项。

为多种 CPU 编译

在现代 CPU 上，编译面向目标处理器的本地代码对获得最佳性能至关重要。涉及 SIMD 指令时尤其重要，因为向量单元宽度必须在编译期已知。使用 C++ 后端时，可以用 gcc 或 clang 配合相应的 -march=cpu 选项，为每种可能的目标 CPU 编译同一个 C++ 文件。使用 LLVM 后端时，可以用 dynamic-faust 工具把同一份 LLVM IR 代码编译成特定 CPU 的机器码。这一步通常会用 faustbench 或 faustbench-llvm 工具自动找出的最佳编译选项来完成。还开发了专门的工具来组合所有可能的选项。

faust2object

faust2object 工具使用标准 C++ 编译器或 LLVM 动态编译链（dynamic-faust 工具）把 Faust DSP 编译成面向不同 CPU 的目标码文件（.o）以及封装用 C++ 头文件。DSP 名称用于生成的 C++ 与目标码文件，因此可以生成不同版本的代码，最终链接到同一个二进制文件中。更完整的文档见此页面。
