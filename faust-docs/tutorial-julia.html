在 Julia 中使用 Faust

本教程介绍如何在 Julia 中使用 Faust。Julia 是一门高层次、高性能的动态编程语言。虽然它是通用语言，可用于编写任何应用，但它的许多特性非常适合数值分析与计算科学。

把 libfaust 编译器的集成引入 Julia 的工作最早由 Cora Johnson-Roberson 完成，将在本教程最后一节介绍。之后又在 Faust 编译器中加入了 Julia 后端，它可以从任意 Faust DSP 程序生成可直接使用的 Julia 代码。

本教程面向谁？

第一节假定机器上已安装可用的 Faust 编译器，因此更适合常规的 Faust 用户。第二节与第三节更适合想了解 Faust 的 Julia 用户。

安装所需的包

请确认 julia 命令已在 PATH 中可用，方法见此。全新安装 Julia 后，所有需要的包都在 packages.jl 文件中列出：

  • 如果你已经安装了某个 Faust 版本，可以在 Faust 仓库的 architecture/julia 目录中运行 julia packages.jl 命令来安装
  • 或者直接下载后用 julia packages.jl 命令执行

生成 Julia 代码

假定你已经从 master-dev 分支编译并安装了 faust 编译器，从下面这个 DSP 程序 osc.dsp 出发：

import("stdfaust.lib");

vol = hslider("volume [unit:dB]", 0, -96, 0, 0.1) : ba.db2linear : si.smoo;
freq1 = hslider("freq1 [unit:Hz]", 1000, 20, 3000, 1);
freq2 = hslider("freq2 [unit:Hz]", 200, 20, 3000, 1);

process = vgroup("Oscillator", os.osc(freq1) * vol, os.osc(freq2) * vol);

可以用下面的命令生成 Julia 代码：

faust -lang julia osc.dsp -o osc.jl

这会生成一个 mydsp{T} 数据结构，作为 abstract type dsp 的子类型，并附带一组操作它的方法。生成的 API 完全遵循为基类型 dsp 定义的那套接口。这个 API 基本上仿照为 C++ 后端定义的那套接口。

生成的文件不是自包含的，因此不能直接用 julia 程序编译：

julia osc.jl
ERROR: LoadError: UndefVarError: dsp not defined
...

像 FAUSTFLOAT、dsp、Meta、UI 这样的额外类型必须在所谓的架构文件中定义。Julia 专用的架构文件在这里说明。可以用一个名为 minimal.jl 的简单架构文件配合以下命令完成这件事：

faust -lang julia osc.dsp -a julia/minimal.jl -o osc.jl

现在生成的 foo.jl 文件是自包含的，可以用下面的命令执行：

julia -i osc.jl (here -i to stay in interactive mode)

这会编译并执行 Julia 代码，输出：

Application name: osc

getNumInputs: 0
getNumOutputs: 2

Path/UIZone dictionary: Dict{String, UIZone}("/Oscillator/volume" => UIZone(:fHslider0, 0.0f0, -96.0f0, 0.0f0, 0.1f0), "/Oscillator/freq2" => UIZone(:fHslider2, 1000.0f0, 20.0f0, 3000.0f0, 1.0f0), "/Oscillator/freq1" => UIZone(:fHslider1, 1000.0f0, 20.0f0, 3000.0f0, 1.0f0))

其中包含应用名称、输入/输出声道数、各控制器路径及其范围，以及所计算输出的前几个样本的图形显示（使用强大的 Plots.jl 包），这里显示的是信号开头处 si.smoo 的效果：

查看生成的代码

生成一个 mydsp{T} 数据结构，作为 abstract type dsp 的子类型，其中包含带类型的字段定义，以及一个初始化这些字段的构造函数：

mutable struct mydsp{T} <: dsp
    fSampleRate::Int32 
    fConst1::T 
    fHslider0::FAUSTFLOAT 
    fConst2::T 
    fRec0::Vector{T} 
    fConst3::T 
    fHslider1::FAUSTFLOAT 
    fRec2::Vector{T} 
    fHslider2::FAUSTFLOAT 
    fRec3::Vector{T} 
    iVec0::Vector{Int32} 
    iRec1::Vector{Int32} 
    ftbl0mydspSIG0::Vector{T} 
    mydsp{T}() where {T} = begin
        dsp = new{T}()
        dsp.fRec0 = zeros(T, 2)
        dsp.fRec2 = zeros(T, 2)
        dsp.fRec3 = zeros(T, 2)
        dsp.iVec0 = zeros(Int32, 2)
        dsp.iRec1 = zeros(Int32, 2)
        dsp.ftbl0mydspSIG0 = zeros(T, 65536)
        dsp
    end
end

注意该结构用 {T} 类型参数化，该类型在初始化时给出。生成的 const REAL = Float32 或 const REAL = Float64 一行取决于编译时给出的 -single（默认）或 -double 选项，可用于此。

生成的还有若干访问方法：

function getNumInputs(dsp::mydsp{T}) where {T}
    return Int32(0) 
end
function getNumOutputs(dsp::mydsp{T}) where {T}
    return Int32(2) 
end

还会生成 init!、instanceInit!、instanceResetUserInterface! 等若干初始化方法；下面是其中之一：

function instanceResetUserInterface!(dsp::mydsp{T}) where {T}
    dsp.fHslider0 = FAUSTFLOAT(0.0f0) 
    dsp.fHslider1 = FAUSTFLOAT(1000.0f0) 
    dsp.fHslider2 = FAUSTFLOAT(200.0f0) 
end

buildUserInterface! 方法使用 UI 子类型来构建控制器，可以是图形用户界面（例如使用 GTK），也可以是 OSC 控制器：

function buildUserInterface!(dsp::mydsp{T}, ui_interface::UI) where {T}
    openVerticalBox!(ui_interface, "Oscillator") 
    declare!(ui_interface, :fHslider1, "unit", "Hz") 
    addHorizontalSlider!(ui_interface, "freq1", :fHslider1, FAUSTFLOAT(1000.0f0), FAUSTFLOAT(20.0f0), FAUSTFLOAT(3000.0f0), FAUSTFLOAT(1.0f0)) 
    declare!(ui_interface, :fHslider2, "unit", "Hz") 
    addHorizontalSlider!(ui_interface, "freq2", :fHslider2, FAUSTFLOAT(500.0f0), FAUSTFLOAT(20.0f0), FAUSTFLOAT(3000.0f0), FAUSTFLOAT(1.0f0)) 
    declare!(ui_interface, :fHslider0, "unit", "dB") 
    addHorizontalSlider!(ui_interface, "volume", :fHslider0, FAUSTFLOAT(0.0f0), FAUSTFLOAT(-96.0f0), FAUSTFLOAT(0.0f0), FAUSTFLOAT(0.1f0)) 
    closeBox!(ui_interface)
end

要访问的 DSP 结构字段只需用名字描述（在 Julia 术语中实际上是 Symbol），之后就可以用标准的 setproperty! 与 getproperty 访问方法，就像 MapUI 架构中编写的 setParamValue! 与 getParamValue 方法那样。

最后，compute! 方法处理含 count 帧的输入缓冲区，产生一个输出缓冲区：

@inbounds function compute!(dsp::mydsp, count::Int32, inputs, outputs)
    output0 = @inbounds @view outputs[:, 1]
    output1 = @inbounds @view outputs[:, 2]
    fSlow0::Float32 = (dsp.fConst1 * pow(10.0f0, (0.0500000007f0 * Float32(dsp.fHslider0)))) 
    fSlow1::Float32 = (dsp.fConst3 * Float32(dsp.fHslider1)) 
    fSlow2::Float32 = (dsp.fConst3 * Float32(dsp.fHslider2)) 
    @inbounds for i0 in 0:count-1
        dsp.fRec0[1] = (fSlow0 + (dsp.fConst2 * dsp.fRec0[2])) 
        dsp.fRec2[1] = (fSlow1 + (dsp.fRec2[2] - floor((fSlow1 + dsp.fRec2[2])))) 
        output0[i0+1] = FAUSTFLOAT((dsp.fRec0[1] 
        * dsp.ftbl0mydspSIG0[trunc(Int32, (65536.0f0 * dsp.fRec2[1]))+1])) 
        dsp.fRec3[1] = (fSlow2 + (dsp.fRec3[2] - floor((fSlow2 + dsp.fRec3[2])))) 
        output1[i0+1] = FAUSTFLOAT((dsp.fRec0[1] 
        * dsp.ftbl0mydspSIG0[trunc(Int32, (65536.0f0 * dsp.fRec3[1]))+1])) 
        dsp.fRec0[2] = dsp.fRec0[1] 
        dsp.fRec2[2] = dsp.fRec2[1] 
        dsp.fRec3[2] = dsp.fRec3[1] 
    end
end

注意，这个简短介绍并未展示所有生成的方法。请查看生成的 osc.jl 文件以了解全部内容。

使用生成的代码

需要定义若干全局变量：

# Testing
samplerate = Int32(44100)
block_size = Int32(16)

必须创建并初始化 DSP 对象，这里使用生成的 REAL 类型别名：

# Init DSP
my_dsp = mydsp{REAL}()
init!(my_dsp, samplerate)

可以用下面的代码从 DSP 元数据中提取它的名字：

# Retrieve the application name
mutable struct NameMeta <: Meta
    name::String
end

function declare!(m::NameMeta, key::String, value::String)
    if (key == "name") 
        m.name = value;
    end
end)

m = NameMeta("")
metadata!(my_dsp, m)
println("Application name: ", m.name, "\n")

可以打印输入/输出的数量：

println("getNumInputs: ", getNumInputs(my_dsp))
println("getNumOutputs: ", getNumOutputs(my_dsp), "\n")

可以用 MapUI 类型获取所有控制器的信息：

# Create a MapUI controller
map_ui = MapUI(my_dsp)
buildUserInterface!(my_dsp, map_ui)

# Print all zones
println("Path/UIZone dictionary: ", getZoneMap(map_ui), "\n")

最后，可以用下面的代码处理一个缓冲区，这里把 FAUSTFLOAT 作为外部样本的实际类型：

inputs = zeros(FAUSTFLOAT, block_size, getNumInputs(my_dsp))
outputs = zeros(FAUSTFLOAT, block_size, getNumOutputs(my_dsp)) 
compute!(my_dsp, block_size, inputs, outputs)
println("One computed output buffer: ", outputs)

现在 osc.jl 可能可以直接集成到更大的项目中，或者用适配的新架构文件加以定制。

faust2portaudiojulia 工具

可以用更完善的 faust2portaudiojulia 工具编译并运行 Faust DSP 程序，它使用 PortAudio.jl 包访问音频驱动、使用 OpenSoundControl.jl 包做 OSC 控制、使用 GTK.jl 包做图形用户界面。

faust2portaudiojulia 工具使用这个 portaudio_gtk.jl 架构文件。按如下方式使用时：

faust2portaudiojulia osc.dsp

它会创建一个 osc.jl 文件，直接用下面的命令即可执行：

julia osc.jl

于是这个默认生成 1000 Hz 与 200 Hz 正弦波的立体声程序就开始播放了，没有任何可供控制它的界面。

现在改用下面的命令：

faust2portaudiojulia -play 2 osc.dsp

会创建 osc.jl 文件，直接用 Julia 执行，音频由 PortAudio 渲染，界面为 GTK GUI（需要 2 个线程分别用于 GTK 和音频）。注意，这个 GUI 还相当简单：

基于 GTK 的控制器

下面的命令：

faust2portaudiojulia -play 2 -osc osc.dsp

会创建 osc.jl 文件，直接用 Julia 执行，音频由 PortAudio 渲染，采用 OSC 控制（需要 2 个线程分别用于 OSC 和音频）。现在应用启动时会带一个运行在 5000 与 5001 端口上的 OSC 控制器：

getNumInputs: 0
getNumOutputs: 2

Dict{String, UIZone}("/Oscillator/volume" => UIZone(:fHslider0, 0.0f0, -96.0f0, 0.0f0, 0.1f0), "/Oscillator/freq2" => UIZone(:fHslider2, 500.0f0, 20.0f0, 3000.0f0, 1.0f0), "/Oscillator/freq1" => UIZone(:fHslider1, 1000.0f0, 20.0f0, 3000.0f0, 1.0f0))

Faust OSC application 'Oscillator' is running on UDP ports 5000, 5001

可以直接发送 OSC 命令，方法见此。例如同时改变两个声道的频率：

 oscsend localhost 5000 /Oscillator/freq1 f 400
 oscsend localhost 5000 /Oscillator/freq2 f 960

你还可以用 faust-osc-controller 工具远程控制这个 Julia 程序，命令如下：

faust-osc-controller /Oscillator -port 5001 -outport 5000 -xmit 1

faust-osc-controller OSC 控制器

最后，用 faust2portaudiojulia -play 2 -oscc osc.dsp 命令，可以让 faust-osc-controller 工具随 OSC 接收端一起自动启动。

使用 Faust 网页版 IDE

Faust DSP 程序可以在 Faust 网页版 IDE 中编写、测试，并生成为可嵌入的 Julia 代码，或者生成为可用的音频应用。

生成纯 Julia 输出

可以直接用 Platform = source 与 Architecture = julia 导出选项生成 Julia 后端的输出。如前所述，生成的文件不是自包含的，但它展示了需要用适配的 Julia 架构文件包装的代码。

导出代码

生成最小的可运行 Julia 文件

Platform = julia 与 Architecture = julia 导出选项可以借助 minimal.jl 架构生成自包含的文件，用下面的命令启动：

julia -i foo.jl (here -i to stay in interactive mode)

生成可用 GTK 或 OSC 界面控制的音频应用

Platform = julia 与 Architecture = portaudiojulia 导出选项可以借助 portaudio_gtk.jl 架构生成自包含的文件。下面的命令以 GTK 控制界面启动程序：

julia -t 2 foo.jl -gtk

下面的命令以 OSC 控制界面启动程序，随时可以接收 OSC 命令，或如前所述用 faust-osc-controller 工具控制：

julia -t 2 foo.jl -osc

最后，用下面的命令可以让 faust-osc-controller 工具随 OSC 接收端一起自动启动：

julia -t 2 foo.jl -oscc

使用 Faust.jl Julia 包

Julia 生态中有 4000 多个包注册在 General 注册表中。最初由 Cora Johnson-Roberson 开发的 Faust.jl 包已在此分支并扩展。它可以使用 libfaust 库与 Julia Faust 后端。

Visual Studio Code 应用可以配合 Julia 扩展使用。这是编辑、编译和测试 Julia + Faust 代码的非常方便的方式。

安装分支版的 Faust.jl 包

在 VS Code 中可以进入包管理模式。Pkg 自带一个 REPL。在 Julia REPL 中按 ] 进入 Pkg REPL，然后用下面的命令安装 Faust 包：

pkg> add https: // github.com/sletz/Faust.jl

要回到 Julia REPL，按退格键或 ^C，然后用下面的命令加载 Faust 包：

 julia> using Faust

假定已经搭好可用的 Julia 环境，就可以使用下面的命令。

使用 libfaust 编译器


 # Create a DSP factory.
 dsp = compile("""
 import("stdfaust.lib");

 freq = hslider("freq", 440, 20, 20000, 1);
 gain = hslider("gain", 0.25, 0, 1, 0.001);
 process = os.oscs(freq) * gain;
 """)

 # Initialize DSP instance and controls.
 init!(dsp; block_size=1024, samplerate=48000)

 # Compute one block of audio.
 compute!(dsp)

默认情况下程序按单精度编译；可以这样给编译器传入 -double 或其他参数：

 compile("process = _;"; name="passthrough", argv=["-double", "-vec"])

每次调用 compute! 都会计算 block_size 个样本，并把输出作为 (block_size, n_channels) 的矩阵返回。如果程序有输入，请在调用 compute! 之前把 dsp.inputs 设为 (block_size, n_channels) 的矩阵：

 passthrough = init!(compile("process = _,_;"))
 x = rand(Float32, 256, 2)
 passthrough.inputs = x
 @test compute!(passthrough) == x

调用 init! 之后，代码中声明的所有界面控件的路径名与范围都可以通过 dsp.ui.ranges 获得。

 julia> dsp.ui.ranges
 Dict{String, Faust.UIRange} with 2 entries:
 "/score/gain" => UIRange(0.25, 0.0, 1.0, 0.001)
 "/score/freq" => UIRange(440.0, 20.0, 20000.0, 1.0)

 julia> ctrl = dsp.ui.ranges["/score/freq"]; (ctrl.min, ctrl.max)
 (20.0f0, 20000.0f0)

然后就可以这样设置这些参数的值：

 setparams!(dsp, Dict("/score/freq" => 220.0f0))
