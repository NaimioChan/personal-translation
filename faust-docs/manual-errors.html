错误信息

错误信息通常以编译器错误的形式显示。它们出现在代码无法成功编译时，一般表示语法错误或语义错误之类的问题。它们可能在编译过程的不同阶段产生，并可能包含出错的文件与行号（当这些信息能取到时），以及问题的简要说明。

编译器分为若干阶段：

  • 从 DSP 源代码出发，解析器为源程序建立内部的内存表示（通常称为抽象语法树），在这里由框图语言的基元构成。第一类错误信息称为语法错误，例如缺少行末的 ; 字符等。
  • 下一步是求值 process 这个程序入口点的定义。这一步基本上是一个采用严格求值的 λ 演算解释器。结果是一张「扁平」的框图，其中一切都已展开。得到的框图会被标注类型，以确定它的输入数和输出数。
  • 随后「扁平」框图被翻译成信号语言，在信号语言中，信号在概念上是样本或控制值的无限流。框图语言实际上实现了 Faust 的框图代数，不遵守连接规则就会触发第二类错误信息，即框图连接错误。这一阶段还可能产生其他错误，例如某些基元的参数类型不正确。
  • 模式匹配元语言让我们能以算法方式创建和操作框图表达式。因此在这一层可能出现第三类错误，即模式匹配编码错误。
  • 信号表达式会被优化并标注类型（为每个信号关联整数或实数类型，并确定信号何时必须计算：初始化时、控制速率还是采样率），从而产生所谓的范式。在这一层可能出现第四类错误，即参数范围错误或类型错误，例如使用长度无界的延迟。
  • 随后信号表达式被转换为 FIR（Faust Imperative Representation），这是一种面向基于状态的计算的表示（内存访问、算术运算、控制流等），之后再转换为最终的目标语言（如 C/C++、LLVM IR、Rust、WebAssembly 等）。在这一层可能出现第五类错误，即后端错误，例如某个后端不支持的编译选项。

注意，当前的错误信息系统仍远非完善，尤其是无法正确追溯 DSP 源码中错误来源时。这种情况下不会显示出错的文件与行号，而是打印表达式的内部描述（作为框图或信号）。

语法错误

这些错误在语言语法未被遵守时发生。下面是一些例子。

以下程序：

box1 = 1
box2 = 2;
process = box1,box2;

将产生以下错误信息：

error.dsp:2 : ERROR : syntax error, unexpected IDENT

它的意思是，在文件 test.dsp 的第 2 行发现了一个意料之外的标识符。通常这个错误是因为上一行末尾缺少分号 ;。

以下程序：

t1 = _~(+(1);
2 process = t1 / 2147483647;

将产生以下错误信息：

errors.dsp:1 : ERROR : syntax error, unexpected ENDDEF

解析器在寻找右括号时遇到了定义的结尾（;）。

以下程序：

process = ffunction;

将产生以下错误信息：

errors.dsp:1 : ERROR : syntax error, unexpected ENDDEF, expecting LPAR

解析器期待一个左括号，却识别出一个需要参数的语言关键字。

以下程序：

process = +)1);

将产生以下错误信息：

errors.dsp:1 : ERROR : syntax error, unexpected RPAR

使用了不正确的括号。

以下程序：

process = <:+;

将产生以下错误信息：

errors.dsp:1 : ERROR : syntax error, unexpected SPLIT

<: 拆分算子使用不正确，应该写成 process = _<:+;。

以下程序：

process = foo;

将产生以下错误信息：

errors.dsp:1 : ERROR : undefined symbol : foo

这发生在使用了未定义的名字时。

框图连接错误

框图表达式表达的是如何把框图表达式组合成新的表达式。每种组合的连接规则都有精确定义，程序要正确就必须遵守。写较复杂的表达式时，请记住算子优先级。

五条连接规则

第二类错误信息在框图表达式连接不正确时返回。

并行连接

把两个框图 A 和 B 并行组合永远不会产生框图连接错误，因为两个框图是上下叠放的，之间没有连接。所得框图的输入是 A 和 B 的输入，所得框图的输出是 A 和 B 的输出。

顺序连接错误

把两个框图 A 和 B 顺序组合时，如果 outputs(A) != inputs(B)，就会产生框图连接错误。例如以下程序：

A = _,_;
B = _,_,_;
process = A : B;

将产生以下错误信息：

ERROR : sequential composition A:B
The number of outputs [2] of A must be equal to the number of inputs [3] of B

Here  A = _,_;
has 2 outputs

while B = _,_,_;
has 3 inputs

拆分连接错误

用拆分组合把两个框图 A 和 B 组合时，如果 B 的输入数不是 A 的输出数的整数倍，就会产生框图连接错误。例如以下程序：

A = _,_;
B = _,_,_;
process = A <: B;

将产生以下错误信息：

ERROR : split composition A<:B
The number of outputs [2] of A must be a divisor of the number of inputs [3] of B

Here  A = _,_;
has 2 outputs

while B = _,_,_;
has 3 inputs

合并连接错误

用合并组合把两个框图 A 和 B 组合时，如果 A 的输出数不是 B 的输入数的整数倍，就会产生框图连接错误。例如以下程序：

A = _,_;
B = _,_,_;
process = A :> B;

将产生以下错误信息：

ERROR : merge composition A:>B
The number of outputs [2] of A must be a multiple of the number of inputs [3] of B

Here  A = _,_;
has 2 outputs

while B = _,_,_;
has 3 inputs

递归连接错误

用递归组合把两个框图 A 和 B 组合时，如果 A 的输出数小于 B 的输入数，或者 B 的输出数大于 A 的输入数（即必须遵守以下连接规则：\mathrm{outputs}(A) \geq \mathrm{inputs}(B)\ \text{and}\ \mathrm{inputs}(A) \geq \mathrm{outputs}(B)），就会产生框图连接错误。例如以下程序：

A = _,_;
B = _,_,_;
process = A ~ B;

将产生以下错误信息：

ERROR : recursive composition A~B
The number of outputs [2] of A must be at least the number of inputs [3] of B. The number of inputs [2] of A must be at least the number of outputs [3] of B. 

Here  A = _,_;
has 2 inputs and 2 outputs

while B = _,_,_;
has 3 inputs and 3 outputs

route 连接错误

框图之间更复杂的路由也可以用 route 基元来描述。编码不正确时可能产生两种不同的错误：

process = route(+,8.7,(0,0),(0,1));

将产生以下错误信息：

ERROR : invalid route expression, first two parameters should be blocks producing a value, third parameter a list of input/output pairs : route(+,8.7f,0,0,0,1)

第二种出现在参数实际上不是数字时：

process = route(9,8.7f,0,0,0,button("foo"));

将产生以下错误信息：

ERROR : invalid route expression, parameters should be numbers : route(9,8.7f,0,0,0,button("foo"))

迭代构造

迭代类似于其他语言中的 for(...) 循环，提供了一种便捷的方式来把复杂的框图构造自动化。所有 par、seq、sum 和 prod 表达式的形式相同：第一个参数是一个标识符，第二个参数是作为整数常量数值表达式的迭代次数，第三个参数是任意的框图。

示例代码：

process = par(+, 2, 8);

将产生以下语法错误，因为第一个参数不是标识符：

filename.dsp : xx : ERROR : syntax error, unexpected ADD, expecting IDENT

示例代码：

process = par(i, +, 8);

将产生以下错误：

filename.dsp : 1 : ERROR : not a constant expression of type : (0->1) : +

模式匹配错误

模式匹配机制让我们能以算法方式创建和操作框图表达式。在这一层可能出现模式匹配编码错误。

符号重复定义错误

这个错误在同一个 DSP 文件中多次定义某个符号时发生：

ERROR : [file foo.dsp : N] : multiple definitions of symbol 'foo'

由于计算在编译期完成，而模式匹配语言是图灵完备的，编译期甚至可能产生死循环，编译器应当能检测出来。

循环检测错误

以下（有些极端的）代码：

foo(x) = foo(x);
process = foo;

将产生以下错误：

ERROR : stack overflow in eval

更复杂的代码也可能产生同类死循环错误。

信号相关错误

信号表达式由框图表达式产生，会被标注类型，最后归约为范式。有些基元要求其参数满足某些约束，例如位于特定范围内或有界。数学函数的定义域会被检查，不允许的运算会被标记出来。

自动类型提升

有些基元（如 route、rdtable、rwtable 等）要求参数为整数类型，整数类型会被自动提升。也就是说，内部会自动加上等同于 int(exp) 的处理，源码中无需显式写出。

参数范围错误

soundfile 用法错误

soundfile 基元要求 part 编号保持在 [0..255] 区间内，因此例如以下代码：

process = _,0 : soundfile("foo.wav", 2);

将产生以下错误：

ERROR : out of range soundfile part number (interval(-1,1,-24) instead of interval(0,255)) in expression : length(soundfile("foo.wav"),IN[0])

延迟基元错误

延迟 @ 基元要求延迟信号的值有界，因此以下表达式：

import("stdfaust.lib");
process = @(ba.time);

将产生以下错误：

ERROR : can't compute the min and max values of : proj0(letrec(W0 = (proj0(W0)'+1)))@0+-1
        used in delay expression : IN[0]@(proj0(letrec(W0 = (proj0(W0)'+1)))@0+-1)
        (probably a recursive signal)

[待补充]

表的构造错误

rdtable 基元可用于通过一张只读表（在初始化时预定义）读取数据。rwtable 基元可用于实现可读写的表。两者的尺寸都在编译期计算。

rdtable 基元要求表的内容由一个 0 输入、1 输出且在编译期已知的处理器产生。因此以下表达式：

process = rdtable(9, +, 4);

将产生以下错误，因为 + 的类型不正确：

ERROR : checkInit failed for type RSEVN interval(-2,2,-24)

在 rwtable 基元中读写索引定义不正确时，也会发生同类错误。

路径名重复错误

不同 GUI 元件的路径名必须不同。编译以下代码：

import("stdfaust.lib");
nBands = 8;
filterBank(N) = hgroup("Filter Bank",seq(i,N,oneBand(i)))
with {
    oneBand(j) = vgroup("[%j]Band",fi.peak_eq(l,f,b))
    with {
        a = j+1; // 这样频段编号就不会从 0 开始
        l = vslider("[2]Level[unit:db]",0,-70,12,0.01) : si.smoo;
        f = nentry("[1]Freq",(80+(1000*8/N*(j+1)-80)),20,20000,0.01) : si.smoo;
        b = f/hslider("[0]Q[style:knob]",1,1,50,0.01) : si.smoo;
    };
};
process = filterBank(nBands);

会给出 ERROR : path '/Filter_Bank/Band/Q' is already used 消息。这是因为我们通常希望区分路径名，以便例如由 OSC 消息来控制。所以正确的做法是把代码改写为：

import("stdfaust.lib");
nBands = 8;
filterBank(N) = hgroup("Filter Bank",seq(i,N,oneBand(i)))
with {
    oneBand(j) = vgroup("[%j]Band %a",fi.peak_eq(l,f,b))
    with {
        a = j+1; // 这样频段编号就不会从 0 开始
        l = vslider("[2]Level[unit:db]",0,-70,12,0.01) : si.smoo;
        f = nentry("[1]Freq",(80+(1000*8/N*(j+1)-80)),20,20000,0.01) : si.smoo;
        b = f/hslider("[0]Q[style:knob]",1,1,50,0.01) : si.smoo;
    };
};
process = filterBank(nBands);

数学函数超出定义域错误

当数学函数在其定义域之外使用，且问题计算在编译期完成时，会产生错误信息。若超出定义域的计算可能在运行时发生，则可用 -me 选项产生警告（见警告消息一节）。

取模基元错误

取模 % 要求分母不为 0，因此以下代码：

process = _%0;

将产生以下错误：

ERROR : % by 0 in IN[0] % 0

acos、asin、fmod、log10、log、remainder 和 sqrt 函数会产生同类错误。

FIR 与后端相关错误

语言中的某些基元在某些后端中不可用。

示例代码：

fun = ffunction(float fun(float), <fun.h>, "");
process = fun;

用 faust -lang wast errors.dsp 以 wast/wasm 后端编译，将产生以下错误：

ERROR : calling foreign function 'fun' is not allowed in this compilation mode

外部变量或常量也会产生同类错误。

编译器选项错误

并非所有编译器选项都能用于所有后端。此外，有些编译器选项不能组合使用。这些情况通常会在编译真正开始之前触发错误。

警告消息

警告消息不会中断编译过程，但会提供关于潜在问题代码的有用信息。使用 -wall 编译选项可打印这些消息。只有同时使用 -wall 和 -me 选项时，才会显示数学上的超出定义域错误警告消息。
