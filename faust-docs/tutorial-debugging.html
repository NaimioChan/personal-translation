用 interp-tracer 进阶调试

关于如何调试 Faust DSP 代码，这里有一些通用说明。本教程讲解如何用 interp-tracer 工具在运行时调试代码。
interp-tracer 工具使用解释器后端运行并插桩已编译的程序。运行期间和/或关闭应用时会收集并显示代码的各种统计信息，典型的有 FP_SUBNORMAL、FP_INFINITE 与 FP_NAN 值，INTEGER_OVERFLOW、CAST_INT_OVERFLOW、NEGATIVE_BITSHIFT 与 DIV_BY_ZERO 操作，以及 LOAD/STORE 错误。

调试域外计算

使用 -trace 4 选项可以在遇到第一个错误时退出，并把 FBC（Faust 字节码）追踪写成 DumpCode-foo.txt 文件，把程序内存布局写成 DumpMem-fooXXX.txt 文件。

下面的 debug.dsp 程序：

process = hslider("foo", 0.5, -1, 1, 0.01) : log;

一旦滑块值等于 0 或更低，就会产生域外值，并在控制台写出如下追踪：

调试 rdtable 与 rwtable 基元

rdtable 基元使用一个读索引，rwtable 基元使用一个读索引和一个写索引。表的大小在编译期已知，读写索引必须留在表内，以免运行时发生内存访问崩溃。

-ct 选项可用于检查表的索引范围，并生成安全的表访问代码。

对于下面的 table.dsp 程序：

process = rwtable(SIZE, 0.0, rdx, _, wdx)
with {
    SIZE = 16;
    integrator = +(1) ~ _;
    rdx = integrator%(SIZE*2);
    wdx = integrator%(SIZE*2);
};

用 -ct 0 选项生成的代码会产生：

virtual void compute(int count, FAUSTFLOAT** RESTRICT inputs, FAUSTFLOAT** RESTRICT outputs) {
    FAUSTFLOAT* input0 = inputs[0];
    FAUSTFLOAT* output0 = outputs[0];
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        iRec0[0] = iRec0[1] + 1;
        int iTemp0 = iRec0[0] % 32;
        ftbl0[iTemp0] = float(input0[i0]);
        output0[i0] = FAUSTFLOAT(ftbl0[iTemp0]);
        iRec0[1] = iRec0[0];
    }
}

其中 compute 方法里的表访问代码不正确，iTemp0 的读写索引可能超出 16 的表大小。执行 interp-tracer -trace 4 -ct 0 table.dsp 会在控制台生成如下追踪，显示内存读写访问错误：

Stack [Int: 16] [REAL: 0,000000]
opcode 3 kLoadInt int 0 real 0 offset1 7 offset2 0 name iTemp0
Stack [Int: 15] [REAL: 0,000000]
opcode 24 kLoadInput int 0 real 0 offset1 0 offset2 0
Stack [Int: 16] [REAL: 0,000000]
opcode 3 kLoadInt int 0 real 0 offset1 6 offset2 0 name i0
Stack [Int: 16] [REAL: 0,000000]
opcode 7 kStoreInt int 0 real 0 offset1 7 offset2 0 name iTemp0
Stack [Int: 16] [REAL: 0,000000]
opcode 41 kRemInt int 0 real 0 offset1 -1 offset2 -1
Stack [Int: 0] [REAL: 0,000000]

Stack [Int: 0] [REAL: 0,000000]

使用 -ct 1 选项，生成的代码现在是：

virtual void compute(int count, FAUSTFLOAT** RESTRICT inputs, FAUSTFLOAT** RESTRICT outputs) {
    FAUSTFLOAT* input0 = inputs[0];
    FAUSTFLOAT* output0 = outputs[0];
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        iRec0[0] = iRec0[1] + 1;
        int iTemp0 = std::max<int>(0, std::min<int>(iRec0[0] % 32, 15));
        ftbl0[iTemp0] = float(input0[i0]);
        output0[i0] = FAUSTFLOAT(ftbl0[iTemp0]);
        iRec0[1] = iRec0[0];
    }
}

此时 iTemp0 的读写索引被限制在 [0..15] 范围内，代码在运行时不再崩溃。

这个 DSP 程序确实有错，索引在 32 个样本的边界处回绕。可以改写为：

process = rwtable(SIZE, 0.0, rdx, _, wdx)
with {
    SIZE = 16;
    index = (+(1) : %(SIZE)) ~ _;
    rdx = index;
    wdx = index;
};

用 -ct 1 选项（并加上 -wall 选项在控制台打印警告信息）生成的 C++ 代码现在是：

virtual void compute(int count, FAUSTFLOAT** RESTRICT inputs, FAUSTFLOAT** RESTRICT outputs) {
    FAUSTFLOAT* input0 = inputs[0];
    FAUSTFLOAT* output0 = outputs[0];
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        iRec0[0] = (iRec0[1] + 1) % 16;
        int iTemp0 = std::max<int>(0, std::min<int>(iRec0[0], 15));
        ftbl0[iTemp0] = float(input0[i0]);
        output0[i0] = FAUSTFLOAT(ftbl0[iTemp0]);
        iRec0[1] = iRec0[0];
    }
}

警告信息为：

WARNING : RDTbl read index [0:inf] is outside of table size (16) in read(write(TABLE(16,0.0f),proj0(letrec(W0 = ((proj0(W0)'+1)%16)))@0,IN[0]),proj0(letrec(W0 = ((proj0(W0)'+1)%16)))@0)
WARNING : WRTbl write index [0:inf] is outside of table size (16) in write(TABLE(16,0.0f),proj0(letrec(W0 = ((proj0(W0)'+1)%16)))@0,IN[0])

范围检查代码会判断读或写索引的区间是否落在 [0..size-1] 范围内，只在需要时生成约束代码。但由于目前的信号区间计算并不完美，可能生成多余的区间约束代码！ 生成的代码里正是这种情况，可以用 interp-tracer -trace 4 -ct 0 table.dsp 测试，它不生成约束代码，也没有显示任何问题。

如果完全确定满足留在范围内这一性质，可以用 -ct 0 关闭约束代码的生成，生成的代码会更快。 我们希望改进信号区间计算模型，从而不再需要索引约束代码。

注意，DSP 程序也可以这样改写：

process = rwtable(SIZE, 0.0, rdx, _, wdx)
with {
    SIZE = 16;
    index = (+(1) ~ _) : %(SIZE);
    rdx = index;
    wdx = index;
};

这种情况下信号区间是正确的，生成的 C++ 代码现在是：

virtual void compute(int count, FAUSTFLOAT** RESTRICT inputs, FAUSTFLOAT** RESTRICT outputs) {
    FAUSTFLOAT* input0 = inputs[0];
    FAUSTFLOAT* output0 = outputs[0];
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        iRec0[0] = iRec0[1] + 1;
        int iTemp0 = iRec0[0] % 16;
        ftbl0[iTemp0] = float(input0[i0]);
        output0[i0] = FAUSTFLOAT(ftbl0[iTemp0]);
        iRec0[1] = iRec0[0];
    }
}

没有加入任何范围约束代码。

注意 -ct 1 选项是默认值，因此总会生成安全的代码。

调试 select2 基元

select2 基元有严格的语义，但为了优化代码，生成的代码并不完全严格。

对于下面的 DSP 程序：

process = select2(button("gate"), branch1, branch2)
with {
    branch1 = (hslider("foo", 0.5, 0, 1, 0.01):log);
    branch2 = (hslider("bar", 0.5, -1, 1, 0.01):sqrt);
};

生成的 C++ 使用 ((cond) ? then : else) 形式，实际上只根据 button("gate") 条件计算 then 或 else 两个分支中的一个：

virtual void compute(int count, FAUSTFLOAT** RESTRICT inputs, FAUSTFLOAT** RESTRICT outputs) 
{
    FAUSTFLOAT* output0 = outputs[0];
    float fSlow0 = ((int(float(fButton0))) ? std::sqrt(float(fHslider1)) : std::log(float(fHslider0)));
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        output0[i0] = FAUSTFLOAT(fSlow0);
    }
}

因此用 interp-tracer -trace 4 debug.dsp 执行它时，在条件处于某个状态时只能检测到一个分支。要强制计算两个分支，可以使用 -sts (--strict-select) 选项。生成的 C++ 现在是：

virtual void compute(int count, FAUSTFLOAT** RESTRICT inputs, FAUSTFLOAT** RESTRICT outputs) 
{
    FAUSTFLOAT* output0 = outputs[0];
    float fThen0 = std::log(float(fHslider0));
    float fElse0 = std::sqrt(float(fHslider1));
    float fSlow0 = ((int(float(fButton0))) ? fElse0 : fThen0);
    for (int i0 = 0; i0 < count; i0 = i0 + 1) {
        output0[i0] = FAUSTFLOAT(fSlow0);
    }
}

其中创建的中间变量 fThen0 与 fElse0 强制实际计算两个分支。然后用 interp-tracer -trace 4 -sts debug.dsp 执行，就会在条件的两种状态下揭示两个分支上的越界计算。

用测试信号调试

效果类 DSP 程序通常需要输入标准化的测试信号，才可能触发异常行为。interp-tracer 工具有一个 -input 选项，可以先把一个 impulse 程序（用 process = 1-1'; 定义）接到被测 DSP 的所有输入上，然后接一个 noise 程序（用 import("stdfaust.lib"); process = no.noise; 定义）。因此需要使用类似 interp-tracer -trace 4 -input debug.dsp 的命令。

也可以直接修改 debug.dsp 代码来使用更专门的测试输入信号，然后正常运行 DSP 代码（即不再使用 -input 选项）。比如写成：process = test_signal <: effect;，把给定的单声道 test_signal 接到 effect 程序的所有输入上。

修正程序

interp-tracer 工具能帮助找出编程错误。但显然，检测到的错误之后必须修正：

  • 仔细检查信号范围，比如核验 vslider/hslider/nentry 界面控件里的最小/最大值
  • 检查数学函数的定义域
  • 使用 rdtable/rwtable 基元时检查索引
  • ...
