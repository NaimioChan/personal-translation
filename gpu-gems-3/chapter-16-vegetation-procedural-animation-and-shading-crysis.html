第 16 章　Crysis 中的植被过程化动画与着色

Tiago Sousa
Crytek

在 Crytek，我们对 Crysis 的主要目标之一，是为电脑游戏图形确立新标准。为这款最新的游戏，我们开发了若干新技术，共同构成 CryENGINE 2。在 Crysis 的这些技术中，一项关键特性是植被渲染，它由几个部分组成，包括过程化折断与物理交互、着色、过程化动画，以及远景 sprite 生成等。

游戏中的植被历来基本是静态的，只靠某种简单的弯曲来制造风的错觉。我们的游戏场景中可以有成千上万种不同的植被，但我们仍进一步推进：让植被对全局与局部风源作出反应，而且不只弯曲植被本身，还细致地弯曲叶片，所有计算都在 GPU 上以过程化方式高效完成。

本章介绍我们如何以高效而真实的方式处理着色与过程化植被动画。

16.1 过程化动画

在我们的方法中，动画分两部分：（1）主弯曲，让整株植被沿风向摆动；（2）细节弯曲，让叶片动起来。风力向量按实例在世界空间中计算，把影响该实例的各风力相加。风区可以是有向风源，也可以是无向风源。在我们的实现中，求和方式与影响单个点的光源非常相似，都考虑方向与衰减。此外，每个实例有自己的刚度，当实例不再受任何风源影响时，风力强度会随时间衰减。图 16-1 是一个示例。

设计者可以把风源放在特定位置、挂到某个实体上（例如直升机），也可以挂到粒子系统上。用这种方法，理论上我们能承受大量风源，而每顶点开销保持不变，只是每个实例会多出一些线性的 CPU 开销。

我们用风力向量的 xy 分量生成主弯曲，它给出风向与风力强度，并以植被网格的高度作为尺度施加有向的顶点形变。注意必须小心限制形变量，否则结果看起来不可信。

叶片的细节弯曲做法类似，但这里只考虑风力强度。美术在常用的三维建模软件中为每个顶点绘制一个 RGB 颜色。这个颜色为我们提供了关于细节弯曲的额外信息。如图 16-2 所示，红色通道用于叶片边缘的刚度，绿色通道用于每片叶子的相位变化，蓝色通道用于叶片的整体刚度。alpha 通道用于预计算的环境光遮蔽。关于这套着色的更多细节，见 16.2 节。

16.1.1 实现细节

我们的主要目标之一是做出直观的系统，尽可能简单，方便美术或设计者使用。因此，设计者的主要输入是风向与风速。如果某些情况下有需要，美术仍可以覆盖默认设置，调整叶片的风速（频率）、边缘以及每片叶子的振幅，让植被动画在视觉上更悦目。

近似正弦波

过程化顶点动画的传统做法依赖正弦波。我们可以用一种更省的方式近似得到类似结果，即使用三角波。[1] 更具体地说，在细节弯曲的情形下，我们一共用四个向量化的三角波：两个用于叶片边缘，两个用于叶片弯曲。算出这些波之后，我们用三次插值对其平滑（Bourke 1999），如代码清单 16-1 所示。图 16-3 说明了这一过程。

示例 16-1. 用于生成波的函数


float4 SmoothCurve(float4 x) { return x * x * (3.0 - 2.0 * x); }
float4 TriangleWave(float4 x) { return abs(frac(x + 0.5) * 2.0 - 1.0); }
float4 SmoothTriangleWave(float4 x) { return SmoothCurve(TriangleWave(x)); }

细节弯曲

如前所述，叶片弯曲通过形变边缘完成，用顶点颜色的红色通道控制边缘刚度。这一形变沿世界空间的顶点法线 xy 方向进行。

最后是每片叶子的弯曲，我们只是沿 z 轴上下形变，用蓝色通道控制叶片刚度。

顶点颜色的绿色通道存放每片叶子的相位变化，我们用它给每片叶子各自的相位，使每片叶子的运动都不相同。代码清单 16-2 给出了细节弯曲方法的代码。

叶片的形状与顶点数量会因植被类型而异。例如，棕榈树的整片叶子我们完整建模，这样可以很好地、高度可控地为它做动画。不过对更大的树，我们把叶子建模为若干平面；我们接受无法完全控制，因为一片多边形数量相对较低的平面上以纹理形式放下了好几片叶子。即便如此，我们对所有不同情形都使用同一套做法，效果不错。

主弯曲

我们通过沿风向偏移顶点的 xy 位置来完成植被的主弯曲，并用归一化高度缩放形变量。只做简单位移还不够，因为需要限制顶点移动以减少形变瑕疵。我们的做法是计算顶点到网格中心的距离，并用这个距离重新缩放位移后的新归一化位置。

这个过程得到球面限定的移动，对植被这种情形已经够用，因为每株植被是单个对象。弯曲形变量也需要仔细调整：弯曲过多会毁掉错觉。代码清单 16-3 是我们的实现。图 16-4 展示了用这种主弯曲技术生成的一些示例。

16.2 植被着色

Crysis 中有成千上万个不同的植被对象，常常覆盖整个屏幕。因此我们必须时刻顾及质量与效率之比。

为此，我们把逐像素着色与顶点着色结合起来，草的情形也是同样的处理方式。唯一的区别是，由于草对填充率要求很高，我们对草全部采用逐顶点着色。

树干着色使用标准的兰伯特与 Phong 着色模型。

叶簇则另有一套做法。我们把它渲染为双面，叶片使用 alpha 测试，草使用 alpha 混合。项目开始时我们试过不同方案，比如两遍的 alpha 测试/混合，但在我们的情形中，质量与效率之比不划算。

现实中，叶簇可以有不同的厚度（对我们的叶簇，我们总是这样假设），并让不同数量的光从不同区域透过。因此我们需要一个次表面散射近似。

我们用一张美术制作的次表面纹理贴图来近似这一项，如图 16-5 所示，它用常见的图像编辑软件制作。这张贴图可以包含叶片内部深处的细节，例如叶脉与内部枝条，分辨率可以相对较低（例如 128 x 128），具体取决于所需细节。16.2.4 节的代码清单 16-4 给出实现细节。

由于植被的性能与质量都至关重要，这个情形下我们决定采用一种开销低、对美术友好的次表面散射近似，按顶点计算：简单地用 - N · L 乘以光源位置可见性，再乘以 E · L（视线向量与光照向量的点积），两者都再乘以次表面纹理以获得厚度变化。图 16-6 给出了一些示例。

还值得一提的是，CryENGINE 2 中所有着色都在世界空间中进行，在我们的具体方案中，这有助于绕开基于属性的实例化情形下的硬件限制，并在某些特定情形下减少着色不连续。

16.2.1 环境光照

传统的常数环境色看起来非常单调，已经过时。开发初期我们有两套不同的植被着色器。一套成为本章所描述的实现；另一套更复杂，用球谐函数做间接光照，主要用于大树。为了减少着色器排列组合的数量，也由于球谐函数的复杂性，我们遗憾地不得不放弃后一种做法，改用统一且更省的外景环境光照方案。

我们引擎中的环境光照现有三种变体：室外、室内，以及一个面向低配硬件的简单方案。室外与室内环境光照的处理相当复杂，要解释清楚还得再写两章，因此超出了本章范围。

这三种变体都试图让未受光照的表面显得有趣。本章我们假定使用低配硬件方案，它用半球光照（Taylor 2001）实现，以打破阴影区域的平板感。

最后，我们还使用一项预计算的环境光遮蔽，存放在顶点的 alpha 通道中，由美术绘制或用标准三维建模软件计算。

16.2.2 边缘平滑

使用 alpha 测试时的一大问题是边缘生硬。我们开发植被主着色的时候，还没有任何硬件支持 alpha-to-coverage（现在我们已支持）。于是我们想出一个特别的办法，通过后处理把边缘平滑掉。

在 CryENGINE 2 中，我们采用延迟渲染方案，先渲染一个 z 遍，把深度写入浮点纹理。

这项技术使许多需要深度信息的特效成为可能（Wenzel 2007）。边缘平滑就是其中之一：它用深度纹理做边缘检测，再用旋转的三角采样做依赖纹理读取，并利用双线性滤波。不过边缘平滑只对不透明几何体有效，因为非不透明几何体不会把深度写入 z 目标。图 16-7 展示了边缘平滑能带来多大改善。

16.2.4 实现细节

在展示着色器实现之前，我们要指出 CryENGINE 2 开发了一套统一的着色器库方案，它不仅简化了着色器，还让它们更易读、更易维护。它还有个额外好处：强制命名约定，并尽量减少代码重复。

思路很简单：尽可能多地共享，并尽量减少用户与着色内核的交互。结果是，所有光源管理、环境光计算以及其他重要计算（如视差遮蔽贴图或贴花）都对写着色器的人隐藏起来。

用户可以使用四个自定义函数，分别用于初始化自定义数据、做逐光源计算、环境光照以及着色最终合成。其余一切都被当作黑箱处理，黑箱通过一个统一的数据结构把每个函数所需的重要数据交给用户。这个数据结构包含重要的可共享数据，如视线向量、法线向量、漫反射贴图颜色、凹凸贴图颜色、alpha 等等。

代码清单 16-4 与 16-5 给出了最终的着色器实现。代码清单 16-5 中的函数是用户自定义函数，我们在其中做逐光源的着色计算，并应用光源的漫反射色、镜面反射色等属性。环境光函数里我们做半球光照近似。清单末尾的着色最终合成，则是应用漫反射纹理、漫反射色、镜面反射色等材质属性的地方。

示例 16-4. 用于着色叶片背面与正面的函数


half3 LeafShadingBack(half3 vEye, half3 vLight, half3 vNormal, half3 cDiffBackK,
                      half fBackViewDep)
{
  half fEdotL = saturate(dot(vEye.xyz, -vLight.xyz));
  half fPowEdotL = fEdotL * fEdotL;
  fPowEdotL *= fPowEdotL;
  // 背面漫反射着色，并稍作环绕
  half fLdotNBack = saturate(dot(-vNormal.xyz, vLight.xyz) * 0.6 + 0.4);
  // 允许美术调整视角相关项。
  half3 vBackShading = lerp(fPowEdotL, fLdotNBack, fBackViewDep);
  // 应用材质的背面漫反射颜色。
  return vBackShading * cDiffBackK.xyz;
}
void LeafShadingFront(half3 vEye, half3 vLight, half3 vNormal, half3 cDifK,
                      half4 cSpecK, out half3 outDif, out half3 outSpec)
{
  half fLdotN = saturate(dot(vNormal.xyz, vLight.xyz));
  outDif = fLdotN * cDifK.xyz;
  outSpec = Phong(vEye, vLight, cSpecK.w) * cSpecK.xyz;
}

16.3 结论

本章给出了撰写本章时 Crysis 中植被着色与过程化动画做法的一个快照。CryENGINE 2 演进得如此之快，在 Crysis 完成之前可能还会加入改进。

所介绍的过程化动画技术是以通用方式实现的，因此甚至可以对布料、毛发这类非植被对象施加风力；唯一的区别是这些情形不使用主弯曲。

我们可以让直升机、手榴弹爆炸乃至武器射击影响植被、布料与毛发，而且方式极其高效。

尽管我们在植被渲染上推进了不少，但随着硬件变快，仍有很大改进空间。例如着色可以改进——多数情况下叶片的镜面光照并非各向同性；我们也可以改用按像素计算的更准确的次表面散射近似。最后，用更多的波来做弯曲会扩大动画变化的范围。
