第 29 章　GPU 上的实时刚体仿真

Takahiro Harada
University of Tokyo

用基于物理的仿真，我们可以轻松算出真实的物体运动，产出高质量的计算机动画。例如手工做一段棋子下落的动画并不难。但要给几千枚下落的棋子做动画就很难了，如图 图 29-1 所示。

在 图 29-1 这种情况下，仿真才是唯一可行的方案。不过仿真在计算上仍然昂贵，所以任何能加速它的技术——例如本章提出的技术——都值得欢迎。对游戏这类用户会与场景中物体交互的实时应用而言，除仿真之外别无选择，因为用户交互不可预测。而且实时应用的要求高得多，因为仿真帧率至少要达到渲染帧率。

本章介绍我们如何利用 GPU 提供的强大计算能力加速刚体仿真。我们的技术完全在 GPU 上实时仿真大量刚体。29.1 节概述我们的做法，29.2 节详细描述其在 GPU 上的实现。

已有若干研究用 GPU 加速基于物理的仿真，例如元胞自动机（Owens 等 2005）、欧拉流体动力学（Harris 2004）和布料仿真（Zeller 2005）。这些已有研究的一个共同特点是，被仿真元素（粒子或网格单元）之间的连通关系在仿真过程中不变。而我们的技术在元素间连通关系随时间变化时也能工作。我们在 29.3 节简要讨论如何把它应用于其他类型的基于物理的仿真，例如颗粒材料、流体和耦合，以此说明这一点。

29.1.3 形状表示

现在我们知道如何计算刚体运动，下一步是计算碰撞以处理刚体之间的相互作用。计算碰撞有若干种做法。本小节介绍一种很适合 GPU 与实时仿真的方法。

在我们的方法里，碰撞检测不基于表示刚体的多边形，而是基于粒子，这与 Bell 等（2005）和 Tanaka 等（2006）的做法相同。一个刚体由一组大小相同的球形粒子表示，如图 29-3 所示。要生成刚体内部的粒子，我们对刚体周围的空间做离散化：定义一个包住刚体的三维网格，为刚体内部的每个体素分配一个粒子。假定刚体表示为封闭网格，那么可以沿平行于某个轴（通常取网格某条边）的方向投射射线，再求射线与网格的交点。沿一条射线从网格外逐个体素前进时，我们记录射线与网格相交的次数。若该次数为奇数，就把相应体素标记为刚体「内部」。

GPU 能加速这一计算——从网格生成粒子——所用的技术叫深度剥离。深度剥离按深度顺序从三维物体中提取深度图像（Everitt 2001）。当物体沿该轴方向做正交投影时，深度剥离提取的第一张深度图像包含每条射线与网格第一个交点的深度（射线从这些点进入网格）。第二张深度图像包含每条射线与网格第二个交点的深度（射线从这些点离开网格），依此类推。换句话说，奇数编号的深度图像包含进入点的深度，偶数编号的深度图像包含离开点的深度。

提取完成后，最后一个渲染遍判断每个体素是否位于刚体内部。渲染目标是一张扁平化三维纹理（29.2.2 节会详细说明）。片元着色器（FS）以体素为输入，查询所有深度图像，判断该体素的深度是否按顺序落在某张奇数编号图像的深度与紧接其后的偶数编号图像的深度之间。若成立，该体素就在物体内部。图 29-4 说明了这一过程。

29.1.4 碰撞检测

由于我们把刚体表示为一组粒子，形状复杂的刚体之间的碰撞检测就简化成粒子之间的碰撞检测。两个粒子的距离小于其直径时即发生碰撞。这种粒子表示的一个好处是仿真速度与精度可控。提高粒子分辨率会增加计算开销，但我们能得到更准确的形状表示，仿真精度也随之提高。因此我们可以按用途调整分辨率。例如对计算速度重要的实时应用，可以降低分辨率。

29.2 在 GPU 上进行刚体仿真

29.2.1 概述

到此我们描述了刚体仿真的基本算法。本节说明如何在 GPU 上实现这一仿真。

一次迭代由以下五个阶段组成，流程见图 29-5。

  1. 计算粒子数值
  2. 生成网格
  3. 碰撞检测与响应
  4. 计算动量
  5. 计算位置与四元数

我们不介绍基本的 GPGPU 技术；不熟悉这些技术的读者可参阅 Harris 2004、Harris 2005 等文献。

29.2.2 数据结构

要在 GPU 上仿真刚体运动，我们必须把每个刚体的所有物理量存成纹理。这些物理量可以存在一维纹理里，但通常用二维纹理，因为当今 GPU 对一维纹理的尺寸有限制。

每个刚体分配一个索引。要把每个刚体的物理量存进二维纹理，先把这个索引转换成二维索引，再由二维索引算出纹理坐标。图 29-6 说明了这一过程。刚体的每个量都存在该纹理坐标处的纹素里。对刚体，我们准备了线动量、角动量、位置与姿态四元数的纹理。每个量都准备两张纹理，因为更新时要从一张读取、再写入另一张。

我们还需要存粒子位置、速度以及相对质心位置的纹理。若一个刚体由四个粒子组成，就需要一张比刚体纹理大四倍的纹理。纹理尺寸按属于一个刚体的粒子数调整。属于某个刚体的粒子索引由刚体索引算出。与刚体索引一样，粒子索引也被转换成二维纹理坐标（如图 29-6 所示）。由于这些粒子数值是由刚体的物理量动态导出的，每个只需一张纹理就够。

除存储物理量之外，我们还要在 GPU 上为均匀网格分配内存，这个数据结构用来搜索邻近粒子。我们采用一种叫扁平化三维纹理的数据布局，把三维网格划分成一组二维网格，排布在一张大二维纹理里（Harris 等 2003）。之所以这样安排，是因为实现时 GPU 还不支持写入三维纹理的切片。NVIDIA GeForce 8 系列已支持，但用二维纹理仍有性能上的好处。

要在网格中读写一个值，我们需要把三维网格坐标转换成二维纹理坐标。设三维网格尺寸为 Lx x Ly x Lz，二维纹理中二维网格的个数为 Dx x Dy，如图 29-7 所示。二维纹理坐标 (u, v) 由三维网格坐标 (gx , gy , gz ) 按下式算出：

29.2.4 步骤 2：生成网格

这一步生成均匀网格数据结构。对每个粒子，我们把粒子索引写到它所属体素对应的像素上。这个操作不能在片元着色器里做，因为它属于分散写（Buck 2005）。我们改用顶点着色器(VS)，它把顶点当作尺寸为 1 的点图元渲染，从而能向任意位置写入值。

我们为每个粒子准备并指定一个顶点。在 VS 中，从粒子位置纹理读出粒子位置，用公式 9 算出体素索引。然后由体素索引算出网格纹理中的坐标（如 29.2.2 节所述），把顶点位置设为该网格坐标，把颜色设为粒子索引。然而用这种简单做法时，网格通常生成不正确，因为每个像素只能存一个值。于是当一个体素里有多个粒子时，这个过程就失效了。

为解决这个问题，我们采用下一段所述的方法，它允许每个体素最多存四个粒子。若体素边长小于粒子直径，且粒子不互相穿透，那么每个体素四个粒子就够——这正是我们的情形，因为粒子之间存在排斥力。我们把体素边长设为粒子直径；我们发现溢出很少发生。

我们用的方法类似 Purcell 等（2003）的模板路由技术，但我们的方法不必在每次迭代时准备复杂的模板图案。我们预先准备好顶点，并按粒子索引升序排好。然后假设有四个粒子最终落进同一个体素，其索引为 p 0、p 1、p 2 和 p 3，按升序排列并按此顺序渲染。我们的目标是把这些值分别存入一个像素的 RGBA 通道，如图 29-8 所示，我们用四个渲染遍来实现。每个遍中，我们用前面说的 VS 渲染所有顶点，然后由 FS 把粒子索引同时输出到颜色和片元深度。借助深度测试、模板测试和颜色掩码，我们选择要写入哪个索引、哪些通道。

第一个遍我们要把 p 0 写入 R 通道。对应 p 0 的顶点在四个顶点中深度最小，所以把深度缓冲清为最大值，并把深度测试设为通过更小的值。第二个遍我们要把 p 1 写入 G 通道。做法是先设置颜色掩码，使这个遍不覆写 R 通道；然后沿用第一个遍的深度缓冲而不清除，把深度测试设为通过更大的值。这样 p 0 会通不过深度测试，而 p 1、p 2、p 3 能通过。为了只写入 p 1，我们让 p 2 和 p 3 通不过模板测试：渲染前把模板缓冲清为零，把模板函数设为在深度测试通过时递增，并把模板测试设为在模板值大于一时失败。这个做法之所以有效，是因为 p 1 在 p 2 和 p 3 之前渲染。第三个与第四个遍的设置与第二个遍相同，只有颜色掩码不同。最后两个遍分别掩掉 RGA 与 RGB 通道。同样沿用同一深度缓冲且从不清除，每个遍前使用并清零模板缓冲。网格生成的伪代码见代码清单 29-1。

把这一方法扩展到每个体素存四个以上粒子，可以通过渲染到多渲染目标（MRT）实现。

29.2.5 步骤 3：碰撞检测与响应

能与其它粒子相撞的粒子，仅限于索引存放在 (a) 该粒子所属均匀网格体素 与 (b) 相邻体素中的粒子，合计 3 x 3 x 3 = 27 个体素。要检测粒子 i 的碰撞，先由粒子 i 的位置导出其网格坐标。然后从网格纹理查这 27 个体素里存的索引。我们通过计算粒子 i 到这些粒子的距离来检测碰撞。

在这种碰撞检测技术中，我们不需要把碰撞检测分成粗筛阶段与精筛阶段。要做的只是计算简单的粒子间距离。检测到碰撞后，用公式 10、11、12 计算粒子间的响应力。算出的碰撞力写入粒子受力纹理。碰撞检测与响应可以在一个着色器里完成。伪代码见代码清单 29-2。

29.2.6 步骤 4：计算动量

算出粒子受力之后，我们用公式 1 和公式 4 计算动量。计算刚体的线动量变化，需要把作用在该刚体所有粒子上的力累加。这个操作在一个片元着色器里完成，每个刚体调用一次。FS 从粒子受力纹理读取受力，把算出的值写入线动量纹理。若每个刚体的粒子数很多，把这个求和实现为多遍的并行归约可能更高效。

同样，计算角动量变化需要粒子相对质心的位置，但这些位置已在前一步算出并存进纹理。方便的做法是在同一个着色器里完成这两项计算，并用多渲染目标输出结果，如代码清单 29-3 所示。

29.2.9 性能

我们在 NVIDIA GeForce 8800 GTX 上实现了本方法，并测试了若干场景。在图 29-1 中，16,384 个棋子与 10,922 个圆环被抛下。两个仿真都用了 65,536 个粒子，运行速度分别为每秒 168 次迭代（ips）与 152 ips。若每次都渲染场景，帧率分别降到每秒 44 帧（fps）与 68 fps。

图 29-9 给出形状复杂得多的刚体结果：963 只兔子与 329 个茶壶。兔子由 68 个粒子组成，茶壶由 199 个粒子组成。这些场景中刚体粒子的总数约为 65,000。两个仿真分别运行在 112 ips 与 101 ips。这些仿真所用的粒子表示是实心的（即模型内部填满粒子）。若只把粒子放在表面，仿真可以加速，效果仍然不错。兔子表面有 55 个粒子，茶壶表面有 131 个粒子。刚体数量相同而刚体粒子数更少时，两个仿真分别运行在 133 ips 与 148 ips。在所有这些刚体仿真中，均匀网格的尺寸都是 1283。

要注意，对很大的计算域，均匀网格并不是存储刚体粒子索引的最佳选择。刚体在计算域中并非均匀分布，因此许多体素里没有粒子索引，显存被浪费。这种情况下我们需要更高效的数据结构——而且是动态的，因为物体的分布在仿真过程中会变化。

29.3 应用

如前所述，我们的技术即使元素之间的连接关系随时间变化也能工作。本章讲解的刚体仿真就是连接关系动态变化的一例。本节简要讨论它如何应用到其它类型的基于物理的仿真，例如颗粒材料、流体以及耦合。

29.3.1 颗粒材料

本章给出的刚体仿真器可以很容易改成颗粒材料仿真器，因为计算碰撞响应力的方法基于离散元方法，而后者正是为仿真颗粒材料发展起来的（Mishra 2003）。我们不用粒子受力去更新刚体的动量，而是用粒子受力直接更新粒子的位置。图 29-10（左）是仿真的一个结果。16,384 个粒子的仿真运行在约 285 ips。

我们采用基于粒子的方法，把流体离散成一组粒子，通过计算粒子间相互作用力来求解方程。光滑粒子流体动力学（SPH）是计算机图形学中常用的基于粒子的方法（细节见 Müller 等 2003）。粒子位置处的物理量，由邻近粒子各值的加权和算出。因此我们必须搜索邻近粒子。在 GPU 上实现 SPH 的难点在于，粒子间的邻域关系在仿真过程中动态变化（换句话说，粒子之间的连接关系不固定）。

既然我们知道了在 GPU 上生成均匀网格的办法，就能动态搜索邻近粒子。在刚体仿真中我们每次迭代搜索一次邻域，而在 SPH 仿真中必须搜索两次。首先我们要搜索邻近粒子以计算密度。然后由邻近粒子的密度导出压力。因此计算开销高于刚体仿真。不过用 GeForce 8800 GTX 我们能获得前所未有的性能，如图 29-10（右）所示。这里粒子位置被输出到文件，再用 marching cubes 由这些位置构造流体表面，由离线渲染器渲染（Lorensen 与 Cline 1987）。该仿真使用 1,048,576 个流体粒子，均匀网格尺寸为 2563，速度约为 1.2 ips。这个速度对实时应用还不够快，但几万个流体粒子的仿真可以跑到约每秒 60 帧。除了用于实时应用，我们还能用它加速高质量动画制作等场合的离线仿真。最后，GPU 内存的大小限制了我们能用的粒子数。768 MB 显存下，我们最多能用约 4,000,000 个流体粒子。

29.3.3 耦合

GPU 不仅能加速单一仿真，也能加速多个仿真相互作用的场合。本章所述的刚体粒子表示，使它很容易与基于粒子的流体仿真耦合。图 29-11（上）是一个与刚体仿真耦合的流体仿真。计算相互作用力时，把属于刚体的粒子当作流体粒子处理，再用这些力更新刚体的动量。杯子被叠起来，流体从上方倒入。之后另一个杯子被扔进这堆杯子。这个仿真使用 49,153 个流体粒子，运行在约 18 ips。

这些技术并不限于基于粒子的仿真。在图 29-11（下）中，我们给出基于粒子的流体仿真与布料仿真耦合的结果。可以看到，基于网格的仿真同样能与基于粒子的流体仿真整合。布料与流体仿真都在 GPU 上执行，相互作用也在 GPU 上计算。65,536 个流体粒子下仿真运行在约 12 ips，每块布料由 8,192 个多边形组成。两个仿真的视频见本书附带 DVD。

29.4 结论

本章我们讲述了在 GPU 上完整实现刚体仿真的技术。借助 GPU 的算力，我们仿真了大量刚体，这在过去很难实时完成。我们说明了本技术不仅适用于刚体仿真，也适用于流体等其它若干类型的仿真。

刚体仿真的精度还有提升余地。例如，我们可以把本文基于粒子的碰撞检测技术用作粗筛阶段，再为精筛阶段实现更精确的方法。

我们确信应用一节所展示的只是可能做法的一小部分，也希望其他人通过扩展本技术来探索 GPU 物理的可能。
