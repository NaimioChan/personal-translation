第 1 章　用 GPU 生成复杂的过程化地形

Ryan Geiss
NVIDIA 公司

1.1 引言

过程化地形传统上局限于由 CPU 生成、由 GPU 渲染的高度场。然而 CPU 的串行处理特性并不适合生成极其复杂的地形——那是一项高度并行的任务。而且，CPU 能处理的简单高度场也提供不了有趣的地形特征（如洞穴或悬垂）。

为了以交互帧率生成高复杂度级别的过程化地形，我们把目光投向 GPU。利用几何着色器（GS）、流输出和渲染到三维纹理等几项新的 DirectX 10 能力，我们可以用 GPU 快速生成大块的复杂过程化地形。这些块合在一起，构成一个大型、细致的多边形网格，表示当前视锥内的地形。图 1-1 给出一个例子。

1.2 Marching Cubes 与密度函数

在概念上，地形表面可以完全由一个函数描述，称为密度函数。对三维空间中的任意点 (x, y, z)，该函数产生一个浮点值。这些值在空间中变化——有时为正，有时为负。若值为正，则该空间点位于实心地形内部。

若值为负，则该点位于空的空间（如空气或水）中。正值与负值之间的边界——即密度值为零处——就是地形的表面。我们正是要沿这个表面构建多边形网格。

我们用 GPU 一次生成一块地形的多边形，但会进一步把这块地形细分为 32x32x32 个更小的单元，即体素。图 1-2 说明了坐标系。我们将在这些体素内构建表示地形表面的多边形（三角形）。marching cubes 算法让我们能在单个体素内生成正确的多边形，输入是该体素八个角上的密度值。输出则会产生 0 到 5 个多边形。若一个单元八个角上的密度符号全都相同，则该单元完全位于地形内部或外部，因此不输出任何多边形。在其他所有情形下，该单元位于岩石与空气的边界上，会生成一到五个多边形。

1.2.1 在单元内生成多边形

单元内多边形的生成过程如下：如图 1-3 所示，我们取八个角上的密度值，判断每个值是正还是负。由每个值得到一位。若密度为负，该位设为零；若密度为正，该位设为一。

随后我们把这八位按逻辑拼接（用按位或运算）成一个字节——也称为情形（case）——取值范围 0–255。若情形为 0 或 255，则该单元完全位于地形内部或外部，如前所述，不会生成多边形。但若情形在 [1..254] 范围内，则会生成一定数量的多边形。

若情形不是 0 或 255，就用它索引各种查找表（在 GPU 上使用常量缓冲），以确定该情形要输出多少个多边形，以及如何构建它们。每个多边形由连接三个点（顶点）而成，这些点位于单元的 12 条棱上某处。图 1-4 说明了应用 marching cubes 算法得到的基本情形。

顶点在棱上的确切位置由插值确定。顶点应放在密度值约为零处。例如，若棱的 A 端密度为 0.1，B 端为 -0.3，则顶点放在从 A 到 B 的 25% 处。

图 1-5 说明了一种情形。在用情形索引查找表之后，蓝点指示哪些棱上必须放置顶点。灰色区域显示这些顶点将如何连接成三角形。注意蓝点在棱上的实际位置取决于棱两端的密度值。

我们的输出是三角形列表，因此每输出三个顶点就构成一个三角形，下一个输出的顶点开始一个新三角形。若某个情形需要生成 N 个多边形，我们就需要生成 3xN 次顶点（位于该单元某条棱上）。

1.2.2 查找表

这里有两大主查找表。第一个以情形编号为索引，告诉我们该情形要创建多少个多边形：


int case_to_numpolys[256];

第二个查找表要大得多。它接收情形编号后，提供在该单元内构建最多五个三角形所需的信息。五个三角形各由一个 int3 值（三个整数）描述；这三个值是为了构建该三角形而必须连接的立方体棱编号 [0..11]。图 1-6 显示了棱的编号方案。

int3 edge_connect_list[256][5];

例如，若情形编号为 193，查 case_to_numpolys[193] 就会告诉我们需生成多少个多边形，答案是 3。接着查 edge_connect_list[193][] 会返回以下值：


int3 edge_connect_list[193][0] : 11 5 10
int3 edge_connect_list[193][1] : 11 7 5
int3 edge_connect_list[193][2] : 8 3 0
int3 edge_connect_list[193][3] : -1 -1 -1
int3 edge_connect_list[193][4] : -1 -1 -1

为在该单元内构建三角形，几何着色器会生成并流输出九个顶点（位于所列棱上的适当位置）——组成三个三角形——到顶点缓冲中存储。注意最后两个 int3 值都是 -1；不过这些值根本不会被采样，因为我们已经知道该情形只有三个三角形。之后 GPU 会转向下一个单元。

我们建议你从本书附带 DVD 的演示中复制这些查找表，因为从零开始生成这些表相当费时。这些表可在文件 models\tables.nma 中找到。

1.3 地形生成系统概述

如前所述，我们把世界划分为无限多个等大的立方块。在世界空间坐标系中，每块大小为 1x1x1。但每块内部还有 323 个体素，其中可能含有多边形。大约 300 个顶点缓冲组成的池会动态分配给当前位于视锥内可见的块，距离最近的块优先。当新的块进入视锥（用户四处移动时），最远的或新近可被视锥剔除的顶点缓冲会被逐出，改用于新需要的块。

并非所有块都含有多边形。是否有取决于复杂的计算，所以通常在我们尝试生成块之前并不知道它是否含有多边形。每生成一个块，一次流输出查询会询问 GPU 是否真的创建了任何多边形。不产生多边形的块——这很常见——会被标记为「空」并放入一个列表，以免它们被无用地重新生成。这一处理也避免这些空块无谓地占用一个顶点缓冲。

每一帧我们都把所有顶点缓冲（它们的包围盒是已知的）从前到后排序。然后生成所有需要的新块，每当需要一个空闲顶点缓冲时就逐出最远的块。最后，我们从前到后渲染排好序的块，这样 GPU 不会浪费时间着色那些可能被地形其他部分遮挡的像素。

1.3.1 生成一块地形内的多边形

在概念上，生成一块地形涉及两个主要步骤。这里先概述这些步骤，然后在后续小节中详述。

  1. 首先，我们用 GPU 的像素着色器（PS）单元在该块内每个单元角点处求值复杂的密度函数，并把结果存入一个大型三维纹理。块是一次生成一个，因此一个三维纹理就可以通用共享。不过，由于纹理存放的是单元角点处的密度值，其大小为 33x33x33，而非 32x32x32（块内单元的数量）。
  2. 接着，我们访问每个体素，必要时在其中生成实际的多边形。多边形被流输出到顶点缓冲，在那里保留并反复渲染到屏幕，直到不再可见。

1.3.2 生成密度值

渲染到三维纹理是一个稍新的想法，值得在此做些解释。在 GPU 上，三维纹理以二维纹理数组的形式实现。要运行一个向切片中每个像素写入的 PS，我们画两个三角形，二者合起来覆盖渲染门户。要覆盖所有切片，我们使用实例化。在 DirectX 中，这不过是调用 ID3D10Device::DrawInstanced()（而非普通的 Draw() 函数），并把 numInstances 参数设为 33。这个过程实际上把这对三角形画了 33 次。

顶点着色器（VS）通过用 SV_InstanceID 语义声明一个输入属性，得知当前正在绘制哪个实例；这些值将从 0 到 32，取决于正在绘制哪个实例。VS 随后可把这个值传给几何着色器，几何着色器用 SV_RenderTarget - ArrayIndex 语义把它写到属性中。该语义决定三角形实际光栅化到三维纹理的哪个切片（渲染目标数组）。这样，PS 就在整个三维纹理的每个像素上运行。书中 DVD 上的 shaders\1b_build_density_vol.vsh 与 .gsh 可供参考。

在概念上，为这些三角形着色的 PS 以世界空间坐标为输入，输出单个浮点密度值。把输入转换为输出的数学，就是我们的密度函数。

1.3.3 构造有趣的密度函数

密度函数唯一的输入是这个：


float3 ws;

这个值是世界空间坐标。幸运的是，着色器提供了大量有用的工具，可把这个值变成有趣的密度值。可供使用的工具包括以下几项：

  • 从源纹理采样，如一维、二维、三维纹理和立方体贴图
  • 常量缓冲，如查找表
  • 数学函数，如 cos()、sin()、pow()、exp()、frac()、floor() 以及算术运算

例如，一个不错的起点是在 y = 0 处放一个地平面：


float density = -ws.y;

这会把世界分为正值——位于 y = 0 平面以下的部分（我们称之为大地），和负值——位于平面以上的部分（我们称之为空气）。好的开始！图 1-7 显示结果。

接下来，我们加入一点随机性让地面更有趣，如图 1-8 所示。我们简单地用世界空间坐标（ws）去采样一个小型（163）的可重复三维纹理，其中充满 [-1..1] 范围内的随机（「噪声」）值，如下：

density += noiseVol.Sample(TrilinearRepeat, ws).x;

图 1-8 显示加入单个噪声倍频后地平面如何扭曲。

注意，我们可以在纹理查找之前缩放 ws 来改变频率（噪声在空间中变化的快慢）。也可以在把查找结果加进密度值之前缩放它；缩放改变噪声的幅度，即强度。为生成图 1-9 中的图像，下面这行着色器代码使用的噪声「函数」频率是上例的两倍、幅度是上例的一半：

density += noiseVol.Sample(TrilinearRepeat, ws * 2).x * 0.5;

一个噪声倍频（采样）并不那么有趣；用三个倍频就有所改善，如图 1-10 所示。为达到最佳效果，每个倍频的幅度应为上一个倍频的一半，频率应大致为上一个倍频的两倍。不过重要的是不要把频率设为正好两倍。两个重叠、可重复且频率略有差异的信号发生干涉在这里是有益的，因为它有助于打散重复感。注意我们还用了三个不同的噪声体。

density += noiseVol1.Sample(TrilinearRepeat, ws * 4.03).x * 0.25;
density += noiseVol2.Sample(TrilinearRepeat, ws * 1.96).x * 0.50;
density += noiseVol3.Sample(TrilinearRepeat, ws * 1.01).x * 1.00;

如果以逐步降低的频率（并逐步提高的幅度）加入更多噪声倍频，更大的地形结构就开始显现，如大山和沟壑。实践中，我们需要约九个噪声倍频，才能造出既有丰富的低频特征（如山脉和峡谷）、又保留有趣高频特征（近处可见的随机细节）的世界。见图 1-11。

采样技巧

关于采样各倍频，有几点细节值得一说。首先，世界空间坐标可以不加修改地用于采样最高频的七八个倍频。但对最低的一两个倍频，应先把世界空间坐标稍作旋转（用 3x3 旋转矩阵），以减少地形最显著特征的重复感。还明智的做法是在九个倍频中复用三四个噪声纹理，以提高缓存一致性；在尺度差异显著的场合，这种复用不会被察觉。

最后，采样极低频的噪声倍频时，精度可能开始崩溃。误差会表现为（不想要的）高频噪声。为绕开这一点，我们在采样最低的一两个倍频时，用完整的浮点精度手动实现三线性插值。关于具体做法，见 shaders\density.h. 中的注释与代码。

使用多个噪声倍频产生的细节是各向同性的（各方向相同），有时看起来会有点过于规整。打散这种均质感的一个办法是：在用坐标做九次噪声查找之前，先用另一次（低频）噪声查找来扭曲世界空间坐标。在中等频率和温和幅度下，这种扭曲会造出超现实的、绳索状、有机感的地形，如图 1-12 所示。在更低频率和更高幅度下，扭曲可以增加洞穴、隧道和拱门的出现。当然，把两个倍频相加，就能轻松把这些效果组合起来。


// 在用 'ws' 采样九个八度之前先做这一步！
float3 warp = noiseVol2.Sample( TrilinearRepeat, ws*0.004 ).xyz;
ws += warp * 8;

我们还可以通过在某个 y 坐标以下非常突然地提升密度值，为场景引入一个硬「地板」。这在一定程度上模拟了自然界的沉积作用——被侵蚀的沉积物会流向较低处并填满它们。在视觉上，这让场景不那么像水下，而更像陆地，如图 1-13 所示。

float hard_floor_y = -13;
density += saturate((hard_floor_y - ws_orig.y) * 3) * 40;

只根据世界空间的 y 坐标调整密度值，还能实现许多其他有趣效果。调整时可以用扭曲前的或扭曲后的世界空间坐标。若用扭曲后的坐标，那么在它的影响下，任何看起来像岩架或台地的效果都会随地形其他部分一起显得融化、下垂。图 1-14 和 1-15 给出两个例子。

这些都是非常基础的技术。当然可以实现无数效果，只要修改 shaders\density.h. 就能轻松做出原型。

1.3.4 定制地形

到目前为止讨论的所有技术都有助于产出好看、有有机感的地形。不过，要实用，我们必须能驯服地形的形状。做法有很多。

使用手绘二维纹理

把一张手绘二维纹理拉伸到很大区域上（大到在你的演示或游戏里「走过」它需要比如 10 分钟）。密度函数可以用 ws.xz 采样这张二维纹理，并用结果驱动八次噪声查找。纹理的红色通道可以影响 ws.y 在用于查找之前的缩放，使噪声在某些区域显得竖向压扁、在另一些区域显得拉伸。绿色通道可以调制高频噪声倍频的幅度，让地形有些地方看起来多岩、有些地方更平滑。蓝色通道甚至可以调制前面讨论的扭曲效果，使某些区域比其他区域更「异星」。

加入手动控制的影响

也可以给密度场加入手动控制的影响。所以，如果你的关卡需要一块平坦地面让飞船降落，如图 1-16 所示，你可以通过常量缓冲把描述它的数据传给像素着色器。着色器代码可能如下所示：


float distance_from_flat_spot = length(ws.xz – flat_spot_xz_coord);
float flatten_amount = saturate(outer_radius – distance_from_flat_spot)/
        (outer_radius – inner_radius) ) * 0.9;
density = lerp(density, ws.y – flat_spot_height, flatten_amount);

在这里，在距其中心 inner_radius 个世界空间单位以内，密度函数将有 90% 被「平地」函数替代；但到 outer_radius 的距离时，影响降到零（saturate() 把值钳制到 0..1 范围）。此外，你可以在整个地形上使用许多块平地——高度、权重和影响半径各不相同。只要它们之间距离足够，使单块地形一次至多只受一块平地影响，这些平地就能以一块平地的代价获得。（当然，如果你需要每块地形有多于一块平地，也可以用动态循环。）每当要生成一个块时，由应用负责用相关信息更新常量缓冲。

加入其他效果

把前面所有技术组合起来，还能实现其他效果——从洞穴到悬崖，再到手绘的河流图。只要你能想到，大概就能编出来。想要一个球形行星，如图 1-17？不要用 y 平面作地面，试试这个（再加上噪声）：

float rad = 80;
float density = rad - length(ws – float3(0, -rad, 0));

或者，想要一个无尽的三维洞穴网络，试试这个（再加上噪声）：

// 这个正的起始偏置让我们得到比开阔空间稍多的岩石。
float density = 12;

演示中所用的密度函数可以通过编辑 shaders\density.h 修改，该文件被演示中的其他几个着色器包含。如果你想实时做出改动，这样做：以窗口模式运行演示（见 bin\args.txt），按你的喜好编辑密度函数，然后按 F9（重新加载着色器），再按「Z」（重新生成地形）。

1.4 生成一块地形内的多边形

把在 GPU 上生成一块地形的任务拆开，有很多种方式。最简单的做法是：用一个渲染通道在整个三维纹理中生成密度值（代表块内所有体素的角点）。然后运行第二个渲染通道，访问密度体中的每个体素，用 GS 在每个体素中生成 0 到 15 个顶点（并流输出到顶点缓冲）。这些顶点会被解释为三角形列表，因此每 3 个顶点构成一个三角形。

现在先集中看生成单个顶点需要做什么。对每个顶点，我们希望知道并存储几项数据：

  • 世界空间坐标
  • 世界空间法线向量（用于光照）
  • 一个「环境光遮蔽」光照值

这些数据可以用下面布局中的七个浮点数轻松表示。注意环境光遮蔽光照值被打包进第一个 float4 的 .w 通道。

struct rock_vertex
{
  float4 wsCoordAmbo;
  float3 wsNormal;
};

法线很容易算：取密度函数的梯度（在 x、y、z 方向上的偏导数，即各自独立的变化率），再把得到的向量归一化。这只需对密度体采样六次即可完成。为求 x 方向的变化率，我们在 +x 方向的下一个纹素处采样密度体，再在 -x 方向的下一个纹素处采样，取差值；这就是 x 方向的变化率。在 y 和 z 方向重复这一计算，共六次采样。三个结果合成一个 float3 再归一化，得到一个质量很高的表面法线，之后可用于光照。代码清单 1-1 给出着色器代码。

示例 1-1　通过梯度计算法线

float d = 1.0 / (float)voxels_per_block;
float3 grad;
grad.x = density_vol.Sample(TrilinearClamp, uvw + float3(d, 0, 0)) -
         density_vol.Sample(TrilinearClamp, uvw + float3(-d, 0, 0));
grad.y = density_vol.Sample(TrilinearClamp, uvw + float3(0, d, 0)) -
         density_vol.Sample(TrilinearClamp, uvw + float3(0, -d, 0));
grad.z = density_vol.Sample(TrilinearClamp, uvw + float3(0, 0, d)) -
         density_vol.Sample(TrilinearClamp, uvw + float3(0, 0, -d));
output.wsNormal = -normalize(grad);

环境光遮蔽光照值表示根据周围几何，总体上有多少光可能到达该顶点。这个值负责把位于角落、缝隙和沟壑深处、光较难透入的顶点压暗。在概念上，我们可以这样生成这个值：先放置一个照向该顶点的大型均匀环境光球，然后向内追踪光线，看有多大比例的顶点能在不撞上地形其他部分的情况下到达该顶点；或者也可以把它想象成从顶点向外投射大量光线，统计能到达一定距离而未穿透地形的光线比例。后一种做法是我们的地形演示所采用的。

为计算空间中某点的环境光遮蔽值，我们投射 32 条光线。球面上恒定的泊松分布点很适合这一用途。我们把这些点存放在一个常量缓冲中。对于每个需要环境光遮蔽的顶点，我们可以——也应该——反复复用同一组光线。（注意：你可以直接用我们的泊松分布，不必自己生成；搜索「g_ray_dirs_32」，见书中 DVD 的 models\tables.nma。）对每条投射的光线，我们沿其取 16 次密度值采样——同样只是采样密度体。若其中任一采样得到正值，该光线就命中了地形，我们认为它被完全遮挡。32 条光线全部投射完后，被遮挡光线的比例——通常在 0.5 到 1 之间——就成为环境光遮蔽值。（很少有顶点的环境光遮蔽值小于 0.5，因为朝地形方向半球内传播的大多数光线会很快被遮挡。）

之后，绘制岩石时照常计算光照，但最终光量（漫反射与镜面反射）会先按这个值调制，再作用到表面颜色上。我们建议把光照乘以 saturate(1 – 2*ambient_occlusion)，这样遮蔽值 0.5 对应光照乘数 1，遮蔽值 1 对应光照乘数 0。这个乘数也可以过一遍 pow() 函数，以便在美术上影响衰减速率。

1.4.1 边缘数据

此时你可能注意到，有些遮挡测试光线跑到了已知密度值的当前块之外，得到错误的信息。这种情况会在两块相接处造成光照瑕疵。不过，这很容易解决：把密度体稍微放大，用多出来的空间在块边界之外一点生成密度值。块可能被划分为 323 个体素用于剖分，但我们可能为比如 443 的密度体生成密度值，其中多出的「边缘」体素代表实际位于我们 323 块之外的密度值。这样我们就能让遮挡光线在密度体中走得更远一些，得到更准确的结果。结果可能仍不完美，但实践中这个比例（32 体素对每条边 6 个体素的边缘数据）能产生不错的效果，没有明显的光照瑕疵。请记住，这些尺寸表示块内体素的数量；密度体（对应体素角点）在每个维度上会多一个元素。

遗憾的是，投射这么短的光线无法顾及大型低频地形特征，例如在大峡谷或大洞内部本应出现的变暗。为顾及这些低频特征，我们还沿每条光线对真实密度函数取几次采样，但范围更远——有意超出当前块。采样真实密度函数的计算代价高得多，但幸运的是，每条光线只需做大约四次采样就能得到好结果。为减轻一些处理负担，我们还可以使用密度函数的「轻量」版本。该版本忽略高频噪声倍频，因为在大范围内它们不太重要。实践中，在八个噪声倍频的情况下，可以安全地忽略频率最高的三个倍频。

代码清单 1-2 所示的伪代码说明了如何为一个顶点生成环境光遮蔽。

注意其中用了 saturate(d * 9999)，让任何正值采样——哪怕极小——都能完全遮挡光线。不过，地形深处的值往往密度逐渐更高，而离地形表面越远的值确实往往逐渐更负。尽管密度函数严格来说并不是有符号距离函数，它常常与之相似，我们在这里就利用了这一点。

{
  float3 dir = ray_dir[ray];
  // 来自常量缓冲

struct triangle_marker_point

方法 2 更快，并引入了「增加新渲染通道以把繁重的 GS 工作迁移到 VS」这一有用概念。不过，方法 2 有一个重大缺陷：它为使用该顶点的每个三角形各生成一次最终顶点。一个顶点平均大约被五个三角形共享，所以我们做了五倍于所需的工作。

1.4.4 生成一块地形：方法 3

这个方法每个顶点只生成一次，而非像前两个方法那样平均五次。尽管渲染通道更多，方法 3 仍比方法 2 快约 80%。方法 3 不生成由众多（大量冗余的）顶点构成的简单非索引三角形列表，而是创建一个顶点池和一个独立的索引列表。列表中的索引现在是对顶点池中顶点的引用，每三个索引表示一个三角形。

为使每个顶点只生成一次，我们把单元内的顶点生成限制在棱 3、0 和 8 上。位于其他任何棱上的顶点将由另一个单元生成——在那个单元里，该顶点恰好（很方便地）落在棱 3、0 或 8 上。这样就成功地把所有需要的顶点各生成了一次。

在一个单元内，判断某条棱（3、0 或 8）上是否需要顶点，只需检查该棱连接的两个角点的情形编号位是否不同。做法示例见 shaders\4_list_vertices_to_generate.vsh，但注意这也可以轻松用查找表完成。

你可能注意到，我们常常每个体素要泼洒最多三个顶点，却只写入一个单通道纹理！因此，若单个单元在棱 3 和棱 8 上都有顶点，VertexIDVol 只能存放其中一个的索引。简单的解决办法是把顶点 ID 体积的宽度扩大三倍（使其大小为 3NxNxN）。泼洒时，把块空间的整数 x 坐标乘以 3，再根据你为其泼洒顶点 ID 的棱（分别为 3、0、8）加上 0、1 或 2。（见 shaders\5b_splat_vertex_IDs.vsh。）在最后的通道中采样结果时，同样根据你要的是该体素内棱 3、0 还是 8 上的顶点 ID，对 x 坐标作相应调整。（见 shaders\7_gen_indices.gsh.）

还要注意，在方法 3 中，list_nonempty_cells 通道在 x、y、z 轴的远端各包含额外一层单元。有时需要的顶点会落在最后一行单元中棱 3、0、8 之外的其他棱上，这样就能确保这些顶点全都被创建——即使它们确实映射到棱 3、0 或 8 上的那个单元恰好位于相邻块中。在处理 nonempty_cell_list 的 gen_indices 通道中，对于实际超出当前块的单元，会跳过索引生成。（示例见 shaders\7_gen_indices.gsh。）

方法 3 让我们能共享顶点，因而生成的顶点数约为原来的五分之一。考虑到每个顶点要对复杂密度函数采样 128 次（32 条光线 x 每条光线 4 次长距遮挡采样），这是相当可观的节省。

使用本章演示自带的密度函数与设置，一块 NVIDIA GeForce 8800 GPU 用方法 1 每秒可生成约 6.6 个区块，用方法 2 约 144 个区块，用方法 3 约 260 个区块。

1.5 纹理与着色

对地形（或任意拓扑的形状）做过程化生成时，一个难点是纹理——具体来说，是生成纹理坐标，通常称为 UV。怎样才能以最小的畸变把纹理无缝映射到这些多边形上？像图 1-21 所示那样，对一张无缝且可重复的二维纹理做单一平面投影，从某个角度看不错，从其他角度看就不行，因为拉伸得很厉害（另见图 1-23）。

简单的解决办法是使用三平面纹理，即沿三个主轴（x、y、z）各做一次平面投影。在任意一点，我们采用在该点畸变（拉伸）最小的那个投影，并在过渡区域让若干投影混合，如图 1-22 所示。例如，法线大致指向 +x 或 -x 方向的表面点会使用 yz 平面投影。混合范围取 10 到 20 度左右通常效果不错；混合范围有多宽，见图 1-23 的示意。

把凹凸贴图与三平面纹理一起使用时，需要确保切线基是针对每个投影、分别由法线生成的。例如对 x 投影，一个非常粗糙的世界空间切线基可以直接取向量 <0, 1, 0> 与 <0, 0, 1>。不过我们能做得比这好得多。幸运的是，由法线生成真正的切线基非常容易。这里，向量的 90 度旋转不过是重排其中两个分量、再把其中一个变号。例如对 x 投影，你可以用向量 <normal.z, normal.y, -normal.x> 与 <normal.y, -normal.x, normal.z>。但要注意，负号的位置取决于数据在凹凸贴图中的存储方式。

三平面纹理可以在单个渲染遍中完成，如代码清单 1-3 的像素着色器代码示例所示。该示例取三次平面投影各自的颜色值与凹凸向量，再根据法线把它们混合起来。最后，把混合后的凹凸向量作用到由顶点插值得到的法线上，得到凹凸后的法线。

给地形加纹理的另一种便捷做法，是把特定的高度值映射到特定颜色，形成条带。在图形硬件上，这对应一次使用世界空间 y 坐标的一维纹理查找——或者更好的做法，是使用二维纹理查找。在纹理中，让配色方案沿 u 轴变化，让 v 轴表示海拔。查找时，用一个极低频噪声的单个倍频程驱动 u 坐标，这样配色方案会随观察者的移动而变化。

  float4 col1 = colorTex1.Sample(coord1);
  float4 col2 = colorTex2.Sample(coord2);
  float4 col3 = colorTex3.Sample(coord3);
  // 同时采样凹凸贴图，生成凹凸向量。
  // （注意：这里用的是过度简化的切线基。）
  float2 bumpFetch1 = bumpTex1.Sample(coord1).xy - 0.5;
  float2 bumpFetch2 = bumpTex2.Sample(coord2).xy - 0.5;
  float2 bumpFetch3 = bumpTex3.Sample(coord3).xy - 0.5;
  float3 bump1 = float3(0, bumpFetch1.x, bumpFetch1.y);
  float3 bump2 = float3(bumpFetch2.y, 0, bumpFetch2.x);
  float3 bump3 = float3(bumpFetch3.x, bumpFetch3.y, 0);
  // 最后，混合 3 个平面投影的结果。
  blended_color = col1.xyzw * blend_weights.xxxx +
                  col2.xyzw * blend_weights.yyyy +
                  col3.xyzw * blend_weights.zzzz;
  blended_bump_vec = bump1.xyz * blend_weights.xxx +
                     bump2.xyz * blend_weights.yyy +
                     bump3.xyz * blend_weights.zzz;
}
// 把凹凸向量施加到顶点插值得到的法线向量上。
float3 N_for_lighting = normalize(N_orig + blended_bump);

想更有意思，可以让低频噪声在 x 与 z 上缓慢变化、在 y 上快速变化——这样配色方案也会随海拔变化。另一个有趣的做法，是把法线向量 y 分量的一小部分加到用于查找的 u 坐标上；这有助于打破条带那种水平排布的感觉。图 1-24 与 1-25 展示了这些技巧。

平面二维投影与基于海拔的查找，对把精细的高分辨率二维纹理投影到地形上非常有用。不过纹理也可以过程化生成。例如，用基于世界空间坐标的几个倍频程噪声扰动法线向量，就能增加几层可感知的细节，如代码清单 1-4 与图 1-26 所示。

示例 1-4. 法线向量扰动

// 再用几个八度的过程化噪声进一步扰动法线向量。
        float3 v = 0;
        v += noiseVol1.Sample(ws* 3.97)*1.00;
        v += noiseVol2.Sample(ws* 8.06)*0.50;
        v += noiseVol3.Sample(ws*15.96)*0.25;
        N = normalize(N + v);

基础表面颜色也可以用过程化方法生成或修改。例如，用几个低频噪声倍频程扭曲世界空间坐标，再取 sin(ws.y)，就能生成简单的大理石纹理，如代码清单 1-5 与图 1-27 所示。

纹理投影与过程化纹理是很强大的工具，可以很容易地结合使用，做出各种各样的效果。单独使用过程化纹理，往往缺少纹理（例如照片或手绘贴图）能提供的高分辨率细节。另一方面，单独使用纹理投影，在很大的空间上会显得重复。把两种工具做简单而有创意的组合，就能解决这些问题，做出细节丰富、变化多样的美丽地景。

示例 1-5. 大理石纹理的生成

// 用扭曲后的世界空间坐标生成大理石纹理。
float3 v = 0;
v += noiseVol2.Sample(ws * 0.47) * 1.00;
v += noiseVol3.Sample(ws * 1.06) * 0.50;
v += noiseVol1.Sample(ws * 1.96) * 0.25;
float3 ws_warped = ws + v;
float is_marble = pow(saturate(sin(ws_warped.y) * 1.1), 3.0);
float3 marble_color = 1;
blended_color = lerp(blended_color, marble_color, is_marble);

1.6 实际应用中的考量

1.6.1 细节层次

在理想的三维场景中，所有多边形在屏幕上看起来都差不多大。但实际很少如此。到目前为止介绍的地形技术所生成的剖分在世界空间中大致均匀，但在屏幕空间中绝不均匀。结果，远处的多边形显得极小（只有一个像素甚至更小），既浪费又引入走样瑕疵。为缓解这个问题，我们希望把区块分成三组：近、中、远。近处的区块多边形保持常规大小，中距离的区块多边形更大（在世界空间中）。最后，远处的区块多边形最大。实现这一做法可以选用两种基本方案：一种让细节层次（LOD）较低的区块含更少的多边形，另一种让低 LOD 区块代表更大的空间。

在「更少多边形」方案中，所有区块在世界空间中仍是 1x1x1，但远处区块的内部网格尺寸更小（163 或 83 而不是 323）。可惜这个方案会让区块数量迅速膨胀，性能急剧下降——渲染如此，区块生成尤其如此。

「更大区块」方案是更好的做法。这里所有区块的内部网格尺寸恒为 323，但区块所代表的地形在世界空间中的大小随其与观察者的距离而变。近处的区块占据世界空间中 1x1x1 的立方体，而更大的区块（代表更远处的地形）在世界空间中覆盖 2x2x2 的立方体，更远处还有一些更大的立方体（4x4x4）。绘制时，我们先画大区块（远处），再画中等区块，最后在上面画精细区块（1x1x1）。由于区块数量始终可控，这是首选方案。

然而，与许多 LOD 方案一样，把一块地形从一个 LOD 切换到另一个，会产生突然的视觉跳变瑕疵。处理这个问题最简单的办法，是在过渡期间同时绘制两个 LOD。先画低 LOD，再在短时间内把高 LOD 区块缓慢地 alpha 淡入或淡出。不过这只有在高 LOD 区块每个像素的 z 缓冲（深度）值始终更近时才有效；否则高 LOD 区块无法在低 LOD 区块之上做 alpha 混合。

因此，绘制高 LOD 区块时，应在顶点着色器中给 z（深度）值加一点负偏移。更好的做法，是在密度函数中用一个小的负偏移来生成低 LOD 区块。这种做法会各向同性地「侵蚀」区块，类似于沿表面法线收缩表面（而且更好，因为它不会产生任何收缩成尖点的位置）。结果，高 LOD 块通常会包住低 LOD 块，在它们之上做 alpha 混合时不会出现 z 冲突问题。

1.6.2 外来物体的碰撞与光照

碰撞

在交互环境或游戏环境中，许多可移动物体——例如昆虫、鸟、角色的脚等等——都必须能检测并响应与地形的碰撞。「有智能」的飞行生物可能需要提前发射射线（就像「Cascades」演示中的蜻蜓那样），以避开地形特征。而在地表爬行的物体——例如生长的藤蔓（「Cascades」演示中的一个隐藏特性）、蜘蛛或流动的水——在移动时必须贴附在地形表面上。被抛出或发射的物体也需要知道自己何时击中地形，以便停止移动（例如长矛插进地面）、反弹（例如足球）或触发某种事件。

如果物体的运动主要由 GPU 在着色器内驱动，这些物体与地形的交互很容易计算。用几何着色器做最方便：每帧把一个缓冲区送进几何着色器，其中每个移动物体只占一个元素（顶点）。为了让几何着色器了解地形，密度函数必须放在一个单独的文件中，供其他着色器通过 #include 包含。几何着色器随后可以包含该文件并调用这个函数，在需要时查询空间中的某一点是在地形内部还是外部。

例如，如果一个足球正朝地形飞去，几何着色器可以在上一帧的位置和新一帧的位置上分别求密度函数的值。如果球此前在空中，而新位置会落在地形内部，那么可以用密度值插值找出它等于零的位置，从而确定球首次击中表面的确切位置。或者也可以用迭代细化方法，例如区间折半。一旦找到确切的碰撞点，就可以在该点计算梯度（再采样六次）。最后，知道球的速度与地形的法线，就能算出反弹方向，进而输出球正确的新位置与速度。

光照

如果上例中的足球落进洞穴，观察者会期望它看起来更暗，因为洞穴内部整体遮挡了环境光（假设这不是一个会发光的魔法足球）。幸运的是，这很容易做到：每帧（如果物体在移动）从物体中心向外发射环境光遮蔽射线，就像我们生成单个地形顶点时做射线投射一样。

唯一的区别是，这里必须用密度函数而不是密度体，因为这个区块的密度体数据很可能早已被丢弃。用密度函数要慢得多，但如果每帧只对几十个可见的移动物体发射这些遮蔽射线，影响并不明显。

1.7 结论

我们给出了一种用 GPU 以交互帧率生成引人入胜、无边界三维地形的方法。我们还展示了如何为显示而对地形做纹理与过程化着色、为地形建立细节层次方案、让外来物体与地形交互，以及为这些物体打光使其与地形匹配。

我们鼓励你尝试这些技术并在其基础上继续拓展。本章介绍的技术，只是可能成为一种全新范式的 GPU 地形生成的基础。如今完全可行的做法大多尚未被探索，而未来几代芯片所能做到的更值得期待。
