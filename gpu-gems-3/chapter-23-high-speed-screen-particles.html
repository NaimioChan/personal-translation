第 23 章　高速离屏粒子

Iain Cantlay
NVIDIA Corporation

粒子效果在游戏中无处不在。烟雾、火焰、爆炸、尘土与雾常用大型粒子系统。但这些效果铺满屏幕时，过度绘制几乎无上限，帧率问题很常见，即便在技术上很成熟的三 A 级作品里也一样。

我们的方案把开销大的粒子渲染到一张离屏渲染目标上，其尺寸只是帧缓冲尺寸的一小部分。这能在过度绘制上省下大量开销，代价是一些图像处理上的额外成本。

23.1 动机

粒子系统常常消耗大量过度绘制与填充率，导致性能问题。有几种常见情形以及相应的隐患。

粒子系统可以用来模拟具有复杂动态行为的系统——例如蘑菇云或爆炸。这类效果可能需要很多多边形，也许几百或几千个。

粒子常用来模拟体积现象，例如雾团或尘云。单个半透明多边形不是体积效果的好模型。人们常用好几层粒子来提供视觉上的深度复杂度。

许多游戏引擎的粒子系统高度可配置。加入大量粒子可能轻而易举，从而与性能约束发生冲突。

更糟的是，相机视角常以最有意思、最强烈的效果为中心。在第一人称与第三人称游戏里，武器与爆炸效果通常是朝玩家角色发出的。这类效果往往铺满屏幕，甚至单个粒子多边形也很容易消耗掉一整屏的过度绘制。

幸运的是，用粒子模拟的许多效果都是朦胧而柔和的。说得更技术一点，烟雾与雾的图像只有低频成分，没有锐利边缘。它们可以用少量样本表示而不损失视觉质量。所以低分辨率帧缓冲就够用了。

反过来，我们的技术不太适合图像频率高的粒子，例如飞溅的碎石。

23.2 离屏渲染

粒子被渲染到一张离屏渲染目标上，其尺寸是主帧缓冲尺寸的一小部分。我们不要求特定的尺寸比例。应用可以按所需的速度与质量权衡自行选择。我们的示例程序提供 1、2、4、8 倍缩放。缩放倍数不限于 2 的幂。

23.2.1 离屏深度测试

要让粒子正确地被场景中其他物体遮挡，需要深度测试，也需要一个尺寸与离屏渲染目标相匹配的深度缓冲。我们通过对主 z 缓冲降采样得到它。基本算法如下：

  1. 照常渲染场景中所有实体物体，并写深度。
  2. 对得到的深度缓冲降采样。
  3. 把粒子渲染到离屏渲染目标，与小尺寸深度缓冲做测试。
  4. 把粒子渲染目标升采样合成回主帧缓冲。

图 23-1 展示了第一、第三与第四阶段。（要展示深度缓冲的有意义表示并不容易。）橙色箭头显示深度测试如何在离屏渲染目标中形成实体物体的轮廓。

23.2.2 获取深度

从概念上说，上述算法很直接。难的是细节。

在 DirectX 9 中获取深度

在 DirectX 9 下无法直接访问主 z 缓冲。必须用三种方法之一显式创建深度。

可以用多渲染目标（MRT）：颜色信息写入第一个目标，深度写入第二个。这种做法有几个缺点。所有目标必须具有相同的位深。后备缓冲会是 32 位（或更多），而深度用得更少可能就够。更严重的是，在 DirectX 9 中 MRT 与多重采样抗锯齿（MSAA）不兼容。

另一种做法是在单独一遍中写入某个渲染目标来生成深度。这有一个明显的缺点：需要对场景的大部分几何体多做一遍，至少是与粒子效果相交的那部分。好处是深度可以直接按所需的离屏分辨率写入，无需降采样。

如果 alpha 尚未使用，深度也可以写入 RGBA 目标的 alpha 通道。A8R8G8B8 可能精度不够。它的限制相当大，但如果应用的深度范围很小，或许能用。A16B16G16R16F 几乎理想，内存开销与 MRT 方案相同。但同样，GeForce 6 与 GeForce 7 系列卡上不支持 MSAA。

这些选项都不理想。取决于目标应用，其中的问题可能过于受限。对把 MSAA 当作应有特性的游戏来说，缺少 MSAA 是主要的绊脚石。

考虑到显卡的深度缓冲里本来就有需要的深度信息，这一切颇令人沮丧。在主机平台上，你直接取深度数据就行。在关于 DirectX 的各种演讲上，总有人问：「什么时候才能访问 z 缓冲？」

DirectX 10 终于提供了这一特性——算是提供了。

在 DirectX 10 中获取深度

DirectX 10 允许直接访问深度缓冲中的值。具体来说，你可以为深度表面绑定一个着色器资源视图（SRV）。不出所料，你必须先把它作为渲染目标解绑。除此之外都相当直接。

还有一个坎：无法为多重采样的深度缓冲绑定 SRV。原因相当深。MSAA 解析操作该怎么作用到深度值上？与解析颜色值不同，取平均是错的，点采样也是错的。实际上没有正确答案。对我们的粒子应用来说，点采样也许可以接受。后面会谈到，我们更想要一个高度针对具体应用的函数。而这正是关键：它需要针对具体应用，而这在 DirectX 10 中不受支持。不过，DirectX 10.1 计划支持（Boyd 2007）。

幸运的是，DirectX 9 各方案所受的大部分限制在 DirectX 10 中都已取消。MRT 可以与 MSAA 一起用，MRT 各目标可以有不同的位深。对浮点表面格式使用 MSAA 也没有限制。

我们的示例代码在 DirectX 10 中演示两种方案：没有 MSAA 时，把深度缓冲绑定为 SRV；使用 MSAA 时，改用 MRT 方法。

23.3 深度降采样

无论我们如何获取深度值，深度表面都需要降采样到离屏渲染目标更小的尺寸。（其实，只在单独一遍中渲染深度不属于这种情况。不过那种方法等同于点采样的缩小。）正如前面关于 MSAA 解析所讨论的，深度降采样没有普遍正确的做法。

23.3.1 点采样深度

简单地对深度做点采样会产生明显瑕疵。在 图 23-2 中，绿色三角形是一个前景物体，靠近视点，深度值小。白色背景区域的深度为最大值。虚线标出的 16 个像素降采样为 1 个离屏像素。A 点是我们取深度样本的位置。它不能代表这 16 个输入像素中的大多数；只有像素 B 的深度与它相近。

如果绿色三角形是前景物体，后面还有一个粒子，那么深度测试会在这一个低分辨率像素上、以及在全部 16 个高分辨率像素上把粒子遮挡掉。结果可能在前景物体周围形成光晕。图 23-3 中间那幅图显示了这种光晕。（图 23-3 的参数被特意选得把误差极度放大。缩放非常极端：8x8 的帧缓冲像素降采样为 1x1 的离屏像素。颜色也选了最大对比度：黄色背景、红色粒子。并且关闭了线性放大滤波，以显示各个低分辨率像素。）

某些情况下光晕可以接受。例如对爆炸这类移动极快的效果，你可能注意不到细节。图 23-4 给出了一个更贴近实际的例子：颜色更自然，2x2 降采样为 1x1，并开启线性滤波。

23.3.2 深度样本取最大值

多做几次点采样而不只采一次，可以改善光晕。图 23-3 与 图 23-4 右边的图展示了降采样时应用取最大值函数的结果。我们从全分辨率深度数据中分散取四个深度值并取其中最大者。这会让粒子离屏图像中物体的轮廓收缩。粒子于是侵入实体物体。这没有任何物理或理论依据。它只是看起来比光晕好一些。这是一种权宜的取巧办法。这就是为什么深度降采样函数必须由应用来定义。

这里只取了四个样本。这完全消除了 图 23-4 中的光晕，因为四个样本完整代表了高分辨率数据。但在 图 23-3 中，四个深度样本并不能完整代表被降采样的 8x8 高分辨率像素。所以仍有轻微的光晕瑕疵。它们足够小，当低分辨率粒子图像加回主帧缓冲时，基本被线性混合掩盖了。

23.4 深度测试与软粒子

深度测试通过像素着色器中的一次比较来实现。降采样后的深度缓冲被绑定为纹理（在 DirectX 10 中是 SRV）。所渲染粒子的深度在顶点着色器中计算，并传给像素着色器。代码清单 23-1 展示了像素被遮挡时如何丢弃。

示例 23-1. 在像素着色器中实现的深度测试


float4 particlePS(VS_OUT vIn) : COLOR
{
  float myDepth = vIn.depth;
  float sceneDepth = tex2D(depthSampler, vIn.screenUV).x;
  if (myDepth > sceneDepth)
    discard;
  // 计算颜色等。
  ...
}

既然我们在像素着色器中能访问粒子与场景深度，额外实现软粒子就轻而易举。软粒子效果在粒子接近与实体场景物体相交处时淡化其 alpha。这样就避免了生硬锐利的相交。视觉上的好处很明显。代码清单 23-2 给出了所需的像素着色器代码。注意 zFade 值取代了比较与丢弃；粒子被完全遮挡处 zFade 为零。

示例 23-2. 软粒子优于二值深度测试


float4 particlePS(VS_OUT vIn) : COLOR
{
  float myDepth = vIn.depth;
  float sceneDepth = tex2D(depthSampler, vIn.screenUV).x;
  float zFade = saturate(scale * (myDepth - sceneDepth));
  // 计算 (r,g,b,a) 等。
  ... return float4(r, g, b, a * zFade);
}

这里我们不再进一步讨论软粒子。它只是一个不错的附赠效果，并非主要关注点。该技术在 NVIDIA 的 DirectX 10 SDK 中有详尽探讨（Lorach 2007）。

23.5 alpha 混合

部分透明的粒子效果通常混合进帧缓冲。设置 alpha 混合渲染状态以形成混合方程：

p 1 = d(1 - 1) + s 11，

其中 p 1 是最终颜色，d 是帧缓冲中已有的目标颜色，s 1 与 1 是像素着色器输出的入射源颜色与 alpha。如果随后有更多粒子混合到 p 1 之上，结果变成

p 2 = (p 1)(1 - 2) + s 22 = (d(1 - 1) + s 11)(1 - 2) + s 22，

p 3 = (p 2)(1 - 3) + s 33 = ((d(1 - 1) + s 11)(1 - 2) + s 22(1 - 3) + s 33，

更后面的混合项依此类推。把 p 3 的方程重新整理，把 d 项与 s 项分别归组，得到

p 3 = d(1 - 1)(1 - 2)(1 - 3) + s 11(1 - 2)(1 - 3) + s 22(1 - 3) + s 33。

除了帧缓冲中的 d 项，其余所有内容都必须存到我们的离屏渲染目标里。最后的合成操作需要产生 p 3，更一般地说是 p n 。

先看 d 项——这比较简单。它被乘以每一个参与混合的 alpha 值的倒数。所以我们把它们乘性地累积到渲染目标的 alpha 通道里。

接着看 s 项，它们对 p 3 有贡献。注意它们的形式与 p 2、p 3 等的常规 alpha 混合方程相同，只要目标初始化为零：

0(1 - 1) + s 11

0(1 - 1)(1 - 2) + s 11 (1 - 2) + s 22

0(1 - 1)(1 - 2)(1 - 3) + s 11 (1 - 2)(1 - 3) + s 22 (1 - 3)+ s 33

所以我们用常规 alpha 混合把 s 项累积到 RGB 通道中。颜色通道与 alpha 通道的混合方程不同。需要 SeparateAlphaBlendEnable 标志。代码清单 23-3 给出了所需的 DirectX 9 混合状态。此外，渲染任何粒子之前必须把渲染目标清成黑色。

示例 23-3. 用于渲染离屏粒子的 alpha 混合状态

AlphaBlendEnable = true;
SrcBlend = SrcAlpha;
DestBlend = InvSrcAlpha;
SeparateAlphaBlendEnable = true;
SrcBlendAlpha = Zero;
DestBlendAlpha = InvSrcAlpha;

把粒子以加法混入帧缓冲，对火焰这类自发光效果也很常见。处理这种情况比前面的 alpha 混合情形简单得多。数值以加法累积到离屏目标里，然后加到帧缓冲上。

在游戏里同时使用混合粒子与加法粒子很常见。我们没有试过，但我们认为无法把两者合并到同一个离屏缓冲中。要同时支持两者，可能各自需要一个单独的离屏遍。

23.6 混合分辨率渲染

用深度最大值做深度降采样能减少光晕。不过离屏粒子图像仍可能块状明显到无法接受。图 23-5 给出了一个例子。图像动起来时，这些瑕疵会闪烁、跳变。在快速移动的动画里这可能不明显。但我们的示例移动缓慢而连续，以尽量模拟最坏情况。

23.6.1 边缘检测

检查渲染目标中的离屏颜色与 alpha 通道，如 图 23-6 所示。（alpha 图像是反相的。回想一下，我们存放的是粒子 alpha 倒数的乘积。）图 23-5 最终图像中的块状问题区域，源于小尺寸离屏缓冲里的锐利边缘。

强烈的边缘说明，只要先提取边缘，瑕疵就能修好。用标准的 Sobel 滤波器就能轻松完成边缘检测。结果存到另一张离屏渲染目标中。

23.6.2 结合模板的合成

边缘检测滤波器只选出少数呈块状的像素。（在 图 23-5 与 图 23-6 中，图像大部分被裁掉了；左右两侧未显示的地方有大片全黑、没有边缘的区域。但这两幅图的这些区域中仍然有粒子。）只要在出现边缘的位置按全帧缓冲分辨率渲染粒子，像素化的区域就能修正。

模板缓冲用于高效地遮罩帧缓冲的某些区域。把低分辨率离屏粒子合成回主帧缓冲时，我们同时写入模板缓冲。像素着色器无法显式设置模板值。但可以为所有像素启用模板写入，然后让像素着色器调用 discard 关键字中止后续输出。这样就阻止了该像素的模板写入，像素着色器实际上控制了模板值，从而形成遮罩。见代码清单 23-4。

到这个阶段，低分辨率粒子已合成进帧缓冲，看起来像 图 23-7 左边那幅图。

然后粒子再渲染一次。模板状态设为只在上一遍合成未触及的区域写入像素，即 图 23-7 中的品红区域。结果显示在下一节 图 23-8 的右图中。作为对比，图 23-8 左边的图展示了完全按全分辨率渲染的粒子系统。

示例 23-4. 用 discard 关键字避免模板写入，形成遮罩


float4 composePS(VS_OUT2 vIn) : COLOR
{
  float4 edge = tex2D(edgesSampler, vIn.UV0.xy);
  if (edge.r == 0.0)
  {
    float4 col = tex2D(particlesRTSampler, vIn.UV1.xy);
    return rgba;
  }
  else
  {
    // 在边缘处中止，以免写入模板。
    discard;
  }
}

23.7 结果

23.7.1 图像质量

图 23-8 把全分辨率粒子与离屏表面按 4x4 缩放的混合分辨率结果作比较。混合分辨率结果非常接近高分辨率版本。有几处轻微瑕疵。在图像左侧角色的斧头上，有几个米色的小点。这是因为线性滤波把像素化的区域从边缘检测遮罩中「漏」了出来。

在高分辨率图像最右侧边缘有一处细节尖刺，被粒子遮住了。注意边缘滤波器在 图 23-7 中漏掉了这一细节。这纯粹是欠采样的问题：低分辨率表面没能充分表示这一细节。

最后，低分辨率图像中不可避免地损失了一些高频信息。注意图像最右侧边缘的灰色粒子。还有角色头顶上那一团粒子。两者在混合分辨率图像中都略模糊一些。

我们原以为必须改动高分辨率那一遍，以匹配低分辨率图像中高频的损失。一两级的 mipmap 细节层次偏移能降低高频。而实际上，最终图像中两种分辨率交接处没有明显的断裂。

23.8 小结

结果表明，我们的低分辨率离屏渲染能带来显著的性能提升。它有助于让粒子的开销更具可伸缩性，使帧率在过度绘制最坏的情形——粒子系统铺满屏幕——下不会骤降。在实际游戏中，这会转化为更稳定的帧率体验。

从视觉上看，结果永远无法完全无瑕疵，因为深度值没有完美的降采样方式。所以总会有一些欠采样问题。不过游戏中爆炸这类粒子往往移动很快，小瑕疵也许可以接受。我们的混合分辨率技术常能修正不少瑕疵。
