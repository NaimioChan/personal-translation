34.1 引言

本章讨论计算有符号距离场的实际问题。我们提出一种用图形硬件加速计算的方法。该方法实现简单，并在性能与质量之间提供权衡。

34.1.1 有符号距离场概述

有符号距离场表示为到物体表面（该物体用多边形模型表示）最近距离的网格采样，通常采用物体内部为负值、外部为正值的约定。有符号距离场在计算机图形学及相关领域非常有吸引力。它们常用于布料动画（Bridson 等 2003）、多体动力学（Guendelman 等 2003）、可变形物体（Fisher 和 Lin 2001）、网格生成（Molino 等 2003）、运动规划（Hoff 等 1999）与雕刻（Bærentzen 2001）中的碰撞检测。

然而，快速而稳健的有符号距离场计算，往往要么因场分辨率高而成为性能瓶颈，要么因输入网格存在退化而几乎无法完成。因此计算可能既繁琐又耗时。例如，在高分辨率网格（2563 或更高）上，CPU 上的朴素实现可能花上数小时甚至数天。

在图形硬件上计算距离场的方法分为两种：距离网格化与包围体的扫描转换。34.7 节对这两种及其他方法做了简短综述。

34.1.2 我们的方法概述

我们的做法是一种新的扫描转换方法。除由 GPU 加速之外，我们的方法还修复了棱柱扫描（Sigg 等 2003）与特征扫描转换（CSC）（Mauch 2003）方法有时产生的漏光瑕疵，因此能处理「不一致网格」（Bischoff 等 2005）——即带孔洞、面片翻转、面重叠甚至更糟情况的多边形模型。实践中，这类多边形模型常出现在由动画师建模、或经扫描与分割得到的物体表面上。

更准确地说，我们的方法不需要任何扫描线，而是把棱柱扫描中新的片元程序与伪法线方法（Aanæs 和 Bærentzen 2003）结合起来。因此它是单趟的，并避免了其他扫描转换算法的符号错误。注意片元程序中正确的符号计算依赖顶点与边的角度加权伪法线；如果这些伪法线无法正确算出，就无法保证该方法给出距离场的正确符号。

在棱柱扫描与 CSC 方法中，有符号距离在沿物体表面的窄带壳层内计算。壳层尺寸由用户指定。我们的方法同样受窄带尺寸限制。以往方法常把窄带尺寸设为 3 到 5 个体素。这样小的窄带尺寸会掩盖较远处的计算错误，因此我们采用 30 到 50 个体素量级的窄带尺寸。

34.2 扫描方法中的漏光瑕疵

特征扫描转换使用受 Voronoi 区域启发的空间细分。更准确地说，为多边形模型的每个要素（即顶点、边和面）创建一个包围体，即特征多面体，使其包住那些到该要素比到其他要素更近的体素集合。所有这些可能互相重叠的包围体之并定义了窄带壳层。

为避免离散化造成的走样瑕疵，我们略微放大包围体。然后对每个要素的包围体做扫描转换，对位于该包围体内的每个体素，计算它到该要素的有符号距离。对窄带壳层内的任何体素，再从中选出到物体的有符号距离：在此前为该体素算出的所有到各要素的有符号距离中，取绝对值最小的那个。

棱柱扫描的做法类似，只是不为边与顶点创建包围体，而是对每个面只创建一种包围体——塔形棱柱。

两种方法有时都会产生漏光瑕疵，即某些体素算出的距离符号错误。这些瑕疵有三个来源。

34.2.1 平面测试

两种扫描方法——距离网格化与包围体扫描转换——都用平面测试来确定距离函数的符号，见图 34-1。如图所示，这种用法可能导致符号计算错误。

该图显示一个多边形模型的剖面，聚焦于面 A 与面 B。图中给出 A、B 以及 A 周围的包围体，有符号距离就在其中计算。在红色虚线区域内，点离 A 最近，因此符号变正。这显然是错的：红色虚线区域内的点位于物体内部，符号应当为负。绿色虚线区域内符号是对的。如果只用平面来确定距离，那么红色虚线与绿色虚线两个区域的距离都会出错。

在特征扫描转换方法中，这个问题更严重，因为特征多面体为避走样而被放大，于是对一个面来说，位于该面 Voronoi 区域之外的体素也会相对该面所在平面计算距离。这意味着图 34-1 中的虚线会在相邻面的 Voronoi 区域内产生距离接近零的体素。棱柱扫描对放大区域内的体素做了情形分析，因此只会出现符号计算错误。

图 34-2 给出这些问题的实际例子。与本章所有同类例子一样，为便于观察，我们用平面剖切等值面，使内部与外部区域分别以蓝色和红色显示。下一节的图 34-5 展示了使用我们方法的结果。

34.2.2 包围体是如何构造的

漏光瑕疵的第二个来源在于包围体的构造方式，见图 34-3。在薄区域的两侧，窄带壳层的宽度不同，使一侧的内部区域越过了对侧的外部区域。对图中所示的构形，上面那个面的包围区域向下伸到了下面那个面的包围区域之下，于是在图中形成一小块灰色区域，那里距离变为负值。图 34-4 给出一个实际例子。

34.2.3 多边形模型中的折叠

漏光瑕疵的最后一个来源是多边形模型中存在的折叠。两种扫描方法都要求模型表面是完美的二维流形，但这个条件并不足以避免符号问题。事实上，如果表面含折叠，三角形面的朝向就可能翻转。

折叠通常与网格中其他三角形重叠，其内侧与那些三角形的外侧朝向相同。如果折叠三角形的外侧到某个体素的绝对距离小于到被重叠三角形的绝对距离，算出的距离值与符号就会出错。当折叠三角形与被重叠三角形的绝对距离相同时，会出现一种特殊情况：此时选中哪个符号取决于扫描顺序，而这个顺序可能造成看起来奇怪的错误，距离正确但符号错误，形成怪异的漏光效果。图 34-6 说明折叠的网格拓扑，图 34-7 给出一个实际例子。

折叠无法用单趟算法处理。我们的方法可以增加第二趟来处理折叠引起的符号问题，就像 Houston 等 2006 所做的那样。

34.3 我们的四面体 GPU 扫描方法

给定以三角形集合表示的物体表面，我们在用户指定的窄带壳层内计算有符号距离。

我们的做法——四面体（T4）GPU 扫描方法——使用由四面体构成的壳层：也就是只考虑四面体体积。34.3.1 节说明如何在 CPU 上由网格三角形算出这个壳层。每个三角形生成若干四面体，每个四面体界定一块包含部分网格体素的空间区域。对这些体素中的每一个，在 GPU 上计算它到该三角形的有符号最近距离。

为确保完全覆盖，我们保证生成的四面体在指定窄带距离内覆盖网格的 Voronoi 区域。因此，由一个三角形生成的四面体必须覆盖该三角形 Voronoi 区域的所有体素；由一个顶点的一环邻域生成的四面体之并，同样必须覆盖该顶点的 Voronoi 区域；此外，由一条边的两个相邻三角形生成的四面体之并必须覆盖该边的 Voronoi 区域。我们的四面体生成法会特意让顶点与边的 Voronoi 区域出现大幅重叠。

使用四面体使我们能采用快速的四面体切片器，计算壳层与网格体素的交。四面体切片技术在体可视化中广为人知，效率极高，因此比对更复杂的棱柱、锥体或楔体做三维扫描转换更便宜。

为确定位于每个四面体内的体素，我们沿正 z 轴方向移动一个 z 平面。在规则网格的每个 z 切片处停下该 z 平面，求出四面体与该 z 平面的截面，见 34.3.2 节。一个状态集保存任意给定步骤中与该 z 切片相交的所有四面体。我们采用简单的扫描线算法（de Berg 等 1997）快速找出与该 z 平面相交的所有四面体；该算法要求四面体按 z 值递增排序。另一种选择是用 Sud 等 2004 的遮挡查询方法。

求出截面后，我们渲染它们，并用 GPU 片元程序计算有符号距离，见 34.3.3 节。片元程序把有符号距离输出到颜色缓冲，把有符号距离的绝对值输出到深度缓冲；深度测试的设置使颜色缓冲中的最终结果是绝对值最小的有符号距离，正是我们想要的。在移到规则网格的下一个 z 切片之前，我们从帧缓冲读回算出的距离值，存入内部数据结构。代码清单 34-1 展示 T4 GPU 扫描方法的整体步骤。

示例 34-1. 我们的 T4 GPU 扫描转换方法的伪代码

algorithm T4-GPU-scan()
 for z = min z plane to max z plane
  foreach tetrahedra t that intersects the z plane
   find cross-section with z
   render cross section
  next t
  read back distance values
 next z
end algorithm

注意，本可以在扫描转换过程中创建壳层以尽量减少存储占用。不过在我们的实现中，为获得更好的模块化，我们选择把壳层创建保留为独立阶段。

我们的壳层创建方法在三角形面数 n 上具有线性时间复杂度 O(n)，因为它只遍历一遍三角形面，并为每个三角形面生成固定数量的四面体。扫描线的初始化（四面体的 z 排序）具有 O(n log n) 的时间复杂度，不过实际的扫描转换可以预期在生成的四面体数量上具有线性复杂度。

可以看到，我们对每个 z 增量做一趟渲染，并且对每个截面做一次渲染调用。目前截面几何用 OpenGL 的立即模式传送到 GPU。我们可以用顶点数组与几何着色器来生成截面，从而大幅优化这一步。这将是后续工作的主题。

34.3.1 计算壳层

壳层的计算方式是遍历网格三角形，每个三角形生成五个四面体。

用最长边 e 与正交的高向量 h，可以在三角形所在平面内放置一个紧贴的矩形。此后把这个矩形按用户指定的窄带尺寸 放大。最后，把矩形的四个顶点沿面法线向内、向外各挤出 的距离，方向为 n,，得到包围三角形面的有向包围盒（OBB）。图 34-8 展示了这些步骤。

随后把这个 OBB 直接分解成五个四面体。这一步实现简单，几乎不可能出错。它确保窄带被完全覆盖，尽管会有相当大的部分伸在外面或互相重叠。于是，简洁性带来了性能下降。

壳层创建方法不对网格做任何假设，可用于带各种退化的非结构网格。注意任何类型的四面体壳层生成方法都能用于我们的扫描转换方法，例如自适应薄四面体壳层网格（Erleben 等 2005），它允许在创建简便性与扫描转换效率之间做权衡。

34.3.2 计算四面体的截面

要用 z 平面计算四面体的截面，我们按 z 值递增排序四面体的四个点。这使算法可以非常简单，就能确定交点个数并生成供片元程序处理的多边形。

考虑图 34-9。如果所考虑的 z 平面低于四面体中的最低点，就没有交点；同样，如果 z 平面高于四面体中的最高点，也没有交点，见图 34-9。

z 平面实际切割四面体的拓扑方式只有三种互不相同的可能：

  1. z 平面位于 p 1 之下。此时平面切割直线 p 0 p 3、p 0 p 1 和 p 0 p 2（图中情形 A）。
  2. z 平面位于 p 1 与 p 2 之间。此时平面切割直线 p 0 p 3、p 1 p 3、p 1 p 2 和 p 0 p 2（图中情形 B）。
  3. z 平面位于 p 2 之上。此时平面切割直线 p 0 p 3、p 1 p 3 和 p 2 p 3（图中情形 C）。

情形 B 中，多边形始终是凸的，只要把四面体所有可能的配置画出来，并考虑平面切割四条直线的顺序，就能看出这一点。只切到一个点、或者沿一条线切开的四面体没有面积，不应考虑。我们描述的切割算法保证了这种情况不会发生。多边形的顶点可能是顺时针也可能是逆时针，因此可能需要后处理来保证朝向正确。不过，T4 GPU 扫描方法不需要这一性质。

34.3.3 用角度加权伪法线计算有符号距离

Sigg 等 2003 引入了一个新颖的片元程序，用来计算到三角形的距离。这里我们描述确定距离所用的情形分析，以及我们的扩展——通过角度加权伪法线算出正确的符号。

用这个三角形建立一个局部三角形标架，由向量 r、s 和 t 构成，如图 34-10 所示。

t 向量取为面法线 n。接着找出三角形最长的边，并相对于面法线逆时针给顶点编号。按惯例，最长的边总是从顶点 0 到顶点 1，如图 34-11 所示。三角形标架的原点由顶点 2 投影到三角形最长边得到。然后 r 取为从原点到顶点 1 的单位向量，s 取为从原点到顶点 2 的单位向量。

四面体横截面的坐标被转换到局部三角形标架，并作为纹理坐标 p = (r, s, t) 送入 GPU，其中 r、s 和 t 分别是相对于 r、s 和 t 向量的局部三角形坐标。

对三角形进行分析，得到三个长度，如图 34-11 所示：高 h；长度 a，从三角形标架原点到顶点 v 1；以及长度 b，从原点到顶点 v 0。

此外还要计算顶点（n v0、n v1 和 n v2）与边（n e0 , n e1 , 和 n e2 ,）上的六个角度加权伪法线，并用由单位列向量构造的旋转矩阵把它们变换到局部三角形标架，如下：

其中 n' 是 n 变换后的法线。这些伪法线与三个长度作为纹理坐标送入 GPU。

GPU 上做的第一件事是把问题归约到半平面 r ≥ 0。也就是说，若 r 为负，我们翻转数据，使 r = -r、a = b、n v1 = n v0、n e1 = n e2。这大大减少了后续分析。

情形分析使用一个带撇的坐标系，坐标为 r' 和 s'。带撇坐标系的原点是顶点 2，r' 轴是从顶点 2 到顶点 1 的向量。s' 轴就是 r' 轴的单位向量。注意带撇坐标系没有单位轴向量。由 r 和 s 导出 r' 与 s'，再按图 34-12 所示的区域进行情形分析。

通过情形分析，我们可以算出到最近特征的距离，并确定对应的伪法线。符号可以用最近特征的伪法线 n(c) 和该特征上的一点 c 求出，即取下式的符号：

d = n(c)·(p - c)，

如 Bærentzen 和 Aanæs 2005 所述。

有符号距离场计算的完整 Cg 程序见代码清单 34-2。

示例 34-2. 用情形分析和伪法线正确计算符号的 Cg 程序


void main(
  in float3 local     : TEXCOORD0,
  in float3 triangle  : TEXCOORD1,
  in float3 nv0       : TEXCOORD2,
  in float3 nv1       : TEXCOORD3,
  in float3 nv2       : TEXCOORD4,
  in float3 ne0       : TEXCOORD5,
  in float3 ne1       : TEXCOORD6,
  in float3 ne2       : TEXCOORD7,
  out float4 dist     : COLOR0,
  out float  absDist  : DEPTH,
  const uniform float narrowbandSize)
{
  // 复制到临时变量。
   float   a = triangle.x;
  float   b = triangle.y;
  float   h = triangle.z;
  float   r = local.x;
  float   s = local.y;
  float   t = local.z;
  float3 nv = nv1;
  float3 ne = ne1;
  // 归一化到半空间 r >= 0。
   if (r < 0) {
    r = -r;
    a =  b;
    nv = nv0;
    ne = ne2;
}
// 变换到带撇的坐标系。
   float lensqr = (a * a + h * h);
float rprime = (a * r + h * h - h * s) / lensqr;
float sprime = (a * s + h * r - h * a) / lensqr;
// 情况分析
   // 默认为区域 I
   float3 c = float3(0, 0, 0);
float3 n = float3(0, 0, 1);
if (s < 0) {
  // 区域 III 或 II
  c.x = a;
  n = (r > a) ? nv : ne0;
}
else if (sprime > 0) {
  if (rprime < 0) {
    // 区域 VI
    c.y = h;
    n = nv2;
  }
  else {
    // 区域 IV 或 V
    c.x = a;
    n = (rprime > 1) ? nv : ne;
  }
}
// IV, V, VI
rprime = max(max(- rprime,0), rprime - 1);
// I, V
sprime = max(sprime,0);
// II, III
r      = max(r-a,0);
// 计算距离。
   float tmp = (s < 0) ? (r * r + s * s)
                    : ((rprime * rprime + sprime * sprime) * lensqr);
absDist = sqrt(tmp + t * t);
// 计算符号。
   float sign_tst = sign(dot(n, local - c));
dist = float4(sign_tst * absDist, local);
// 深度缓冲被钳制在 0..1，因此要重新放缩。
absDist /= narrowbandSize;
}

34.4 结果

图 34-13 和 34-14 中的所有测量都在一台 2.4 GHz Pentium 4、4 GB 内存的机器上完成，运行 Gentoo Linux，显卡是带 256 MB 显存的 NVIDIA GeForce 6800 GT。我们使用的窄带尺寸相当于网格最大范围的 10%，大致是 30 到 50 个体素的量级。所有计时以秒为单位，绘于图 34-13 和 34-14 中。如预期，所有图都显示复杂度随网格规模线性增长。

图 34-13 显示了 CPU 时间开销。显然，对我们四面体网格数据结构的查找操作是实现中的瓶颈。为什么？因为我们所有网格数据结构都是为了便于拓扑操作而设计的，不是为快速取回信息而设计的。第二昂贵的操作是局部三角形初始化、切割、对顶点坐标与法线的表面网格查找，以及法线变换。除了网格顶点和法线查找之外，这些操作都可以借助顶点着色器和几何着色器下放到 GPU。图 34-14 绘制的是 GPU 时间开销，它表明片元程序在计算上是最昂贵的部分，网格较大时会超过帧缓冲回读的耗时。

图 34-15 中我们展示了几例有符号距离场结果。左列是符号计算，中列是有符号距离场，右列叠加了网格。可以看到没有出现渗漏，有符号距离场在各处都显得平滑。

图 34-16 比较了我们方法的 CPU 实现与 GPU 实现的运行时间。不同规模的多种网格以约 20 像素的窄带尺寸（相当于网格范围的 10%）扫描转换到 2563 网格中。这些测试在一台 Dell Precision M90 上完成，配置 Intel Core Duo 2.33 GHz、2 GB 内存，运行 Windows XP，显卡是带 512 MB 显存的 NVIDIA Quadro FX 2500。平均而言，GPU 版本给出 6 倍的加速比。CPU 版本利用对内存的随机访问，因此不需要使用扫描线；四面体切片被直接渲染进 CPU 内存中的三维网格。

34.5 结论

我们提出了一种有符号距离场的扫描转换方法，它具有以下特点：

  • 它基于一种简单的几何体：四面体。
  • 它使用伪法线来处理正确的符号计算。
  • 它的一部分天然适合 GPU 实现，平均带来 6 倍的加速比。

我们还提出了一种壳生成方法，易于理解、便于实现。合在一起，我们的工作构成了一个灵活、简单而高效的有符号距离场计算系统。

34.6 未来工作

未来工作包括改进算法本身以及它的 GPU 实现。

34.6.1 算法改进

可以采用生成更贴合四面体壳网格的快速方法来提升性能。OBB 创建方法确实给出了很好的质量。不过，由于大 OBB 远远超出窄带尺寸并且重叠严重，扫描转换过程中会做冗余且不必要的计算。

其次，尽管我们提出的壳生成方法并不依赖伪法线，片元程序实际上仍然需要伪法线。对一些退化网格来说这可能是缺点——这类网格含冗余顶点，形成相接但在拓扑上并未连通的开边界。因此未来工作可以聚焦于对伪法线的依赖，例如找出一种能为退化网格计算有意义伪法线的算法。除此之外，该方法能够处理开边界，甚至重叠的面。

34.6.2 实现的改进

我们的 GPU 实现还有很大改进余地，可以获得更高的加速比。

第一，我们可以用顶点缓冲对象替代 OpenGL 的立即模式，以获得更好的三角形批处理。第二，扫描线方法可以移到 GPU 上，用遮挡查询快速确定与当前 z 平面相交的四面体集合。第三，每个 z 切片都要发生的多次回读可以减少为一次，做法是创建一张扁平化的三维纹理（即一张包含有符号距离场所有 z 切片、并用 uniform 指示每次渲染遍在扁平纹理中偏移量的二维纹理）。这三项改进仍能让实现向后兼容所有支持可编程 GPU 的显卡。

此外，在较新的 GPU 上我们可以使用顶点纹理取数，在顶点程序中完成实际的四面体切割，并在几何着色器中生成四面体几何。

34.7 延伸阅读

计算距离场的暴力做法可以这样描述：「对每个体素，计算到多边形模型中各面的最近距离。」已有各种加速技术，例如只让体素对包围体层次做查询，或者反转迭代，改为遍历面周围的包围体。

朴素做法也可以直接并行化，即反转迭代顺序：对每个面，计算到所有体素的距离，Hoff 等 1999 就是这样做的。作者把顶点、边或面的距离函数网格化，并直接渲染到深度缓冲。对体数据，这一步按切片逐层进行，距离场再从深度缓冲读回。可以使用任何距离度量，但不处理符号。这种方法的简单性很有吸引力，尽管它需要在三维中对椭圆锥和双曲面片做剖分。显然，剖分会在距离计算中引入离散化误差，但误差可以控制。这种方法称为距离网格化。

使用 GPU 的扫描转换算法已经相当流行。这类方法把各种外部区域做扫描转换，这些区域界定了一组点，它们比任何其他几何特征更靠近某个几何特征。这些方法需要构造有界体积，再用为三维体数据扩展的 CPU 扫描线方法逐切片扫描转换。早先的 CPU 方法用两遍策略解决符号问题。Aanæs 和 Bærentzen 2003 用角度加权伪法线确定正确的符号，从而只需一遍。

Mauch 2003 提出了特征扫描转换算法，使用三种特征多面体：棱柱（对应面）、锥（对应顶点）和楔形（对应边）。这个算法概念上容易理解，但锥和楔形的曲面应当如何剖分并不清楚。为避免走样，必须放大这些多面体；然而作者没有描述体素落到曲面错误一侧所导致的计算误差。这一瑕疵在 34.2 节中有详细描述。

Sigg 等 2003 提出了 CSC 的优化 GPU 版本，以及一种更激进的扫描转换方法，名为棱柱扫描。棱柱只对平面构造，从而减少了需要扫描转换的有界体积数量。此外他们还提出了一个新颖的片元程序，用来计算光栅化体素的有符号距离。棱柱扫描存在与 CSC 相同的符号问题，因为只用面平面来确定符号，34.2 节有详细解释。这些符号错误看起来无关紧要，因为在小尺寸窄带和平滑曲面物体上很少发生。然而，如果增大窄带尺寸并对带尖脊和凹谷的物体做扫描转换，符号错误会立刻放大成大片不连续区域，曲面错误的一侧渗漏到另一侧。

棱柱扫描和 CSC 都受用户指定窄带尺寸的限制。

这两种方法都要求输入表面网格是完美的二维流形。处理真实模型时我们常常发现并非如此，因此往往必须求助于网格重建（Nooruddin 和 Turk 2003）。

Sud 等 2004 提出了在图形硬件上计算距离场的若干性能改进。两项主要贡献是：基于遮挡查询的剔除方法，以及基于距离场空间连贯性的保守钳制计算。

总结一下，图形硬件上计算距离场的方法分为两类：距离网格化，以及有界体积的扫描转换。Hsieh 和 Tai 2005 针对二维情形提出了这两类方法的混合。

其他做法包括用两阶段快速行进法之类的办法求解程函方程（Sethian 1999a）。我们刚才描述的扫描转换方法计算的是精确的有符号距离场，快速行进法则通常有 O(1) 量级的离散化误差，不过也存在高阶精度的版本（Sethian 1999b）。还有些方法也处理距离场的计算，例如 Danielsson 的距离场算法（Danielsson 1980）。Danielsson 用四遍扫描方法在规则二维网格上传播距离信息。这种方法可以扩展到三维，在某种程度上类似快速行进法。

Frisken 等（2000）走了另一条路，引入自适应距离场。
