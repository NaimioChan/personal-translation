本章介绍一种在当代图形处理器上以交互帧率渲染元球的技术。我们的方法不用 marching cubes 算法生成多边形列表，而是通过把自由运动的粒子约束到元球的隐式曲面上，对该曲面进行采样。我们的目标是渲染成千上万个粒子来把元球可视化为光滑曲面，每个粒子只覆盖极小的曲面面积。要在 GPU 上成功应用这种基于点的技术，我们解决三个基本问题。第一，我们需要为每个被渲染的粒子求值元球的隐式函数及其梯度，以便把粒子约束到曲面上。为此我们设计了一种新的数据结构，可在片元着色器中快速求值隐式函数。第二，我们需要把粒子均匀分布到曲面上。我们提出一种在 GPU 上分两遍渲染完成、对每个粒子做最近邻搜索的快速方法。该方法用于按光滑粒子流体动力学的方法计算排斥力。第三，为进一步加速粒子分散，我们提出一种把粒子从高密度区域转移到曲面上低密度区域的方法。

7.1 元球、光滑粒子流体动力学与曲面粒子

可变形隐式曲面的可视化是一个有趣的课题，因为它旨在表现从软体到水与气体现象的各种非刚体。元球是 Blinn 在 1980 年代初发明的一种广泛使用的隐式曲面（Blinn 1982），常用于获得类似流体的外观。

元球的概念与光滑粒子流体动力学（SPH）（Müller et al. 2003）密切相关，后者是一种把流体仿真为粒子云的方法。两个概念都采用把空间点映射为质量密度的光滑标量函数。这些标量函数称为光滑核，基本表示在小体积空间内被摊平的点质量，类似于二维图像处理中的高斯模糊。此外，用 SPH 仿真的流体可以很自然地可视化为元球。本章不关注元球本身的动力学。我们只关心元球云的可视化，以生成流体曲面。不过所提出的元球可视化技术严重依赖 SPH 方法。我们假定元球（也称为流体原子）在 CPU 上以自由形态动画技术或基于物理的仿真来驱动动画。我们还假定流体原子的动力学是交互式确定的，因此像 Vrolijk et al. 2004 那样对流体动画序列做预处理，在我们的情况下不可行。

SPH 中的流体原子基本上是一组粒子，通过其空间构型定义隐式元球曲面。为可视化该曲面，我们使用另一组称为曲面粒子的粒子，它们以始终留在流体原子所定义隐式曲面上的方式运动。这些粒子随后可以渲染为公告板或定向四边形，作为流体曲面的近似。

7.1.1 方法比较

使用曲面粒子并不是可视化隐式曲面的最常规做法。更常见的方法有应用 marching cubes 算法（Lorenson and Cline 1987）或采用光线追踪（Parker et al. 1998）。marching cubes 把三维体数据离散为网格单元，并根据各单元角点的隐式函数值，为每个单元计算一组图元。这些图元对隐式曲面与网格单元的交线做插值。光线追踪从视点向曲面发射光线，确定每个像素处曲面的深度与颜色。图 7-1比较了这三种方法。

基于点的方法（Witkin and Heckbert 1994）在隐式曲面可视化中用得少得多。最可能的原因是处理大量粒子做可视化的计算代价很高。其他技术如光线追踪的计算代价也很高，但通常更容易在传统基于 CPU 的硬件上实现，因此对离线渲染是更自然的选择。

随着 GPU 处理能力的大幅增长，隐式曲面可视化看来很适合交给图形硬件。此外，当代 GPU 的并行特性使其处理能力的提升速度远快于以往，未来基于 GPU 的方法会比基于 CPU 的方法更有优势。然而并非每种隐式曲面可视化技术都能轻易改成在并行环境中工作。例如 marching cubes 算法的复杂度与元球对象的整个体积同阶，必须访问所有网格单元才能确定曲面（Pascucci 2004）。沿曲面行进、只访问相邻网格单元的迭代优化不适合并行化。因此它的复杂度比基于点的方法更差——后者只需更新所有曲面粒子的位置，而粒子数与流体曲面面积成线性关系。

粒子系统就其本质而言非常适合利用时间相干性。一旦曲面粒子在某一时刻的流体曲面上的位置确定下来，只需移动很小的量就能表示稍后一小段时间的流体曲面。marching cubes 与光线追踪无法利用这一特性。这些技术每次都要从头确定流体曲面。

7.1.2 GPU 上基于点的曲面可视化

我们提出一种使用曲面粒子的元球可视化方法。首要目标是在尽可能短的时间内用曲面粒子覆盖尽可能多的流体曲面。我们不关注粒子本身的渲染；只会简要讨论粒子混合与着色器效果，用来让曲面更可信。

我们的方法几乎完全在 GPU 上运行。这样我们省去大量 CPU 工作，让 CPU 空闲去做别的事。我们仍需要 CPU 以能被片元着色器高效处理的形式存放流体原子的位置与速度。其他所有可视化任务都交给 GPU。图 7-2给出了整个流程的概览。

我们的做法基于 Witkin 和 Heckbert（1994）的已有方法。在该方法中，通过把粒子约束到曲面上并让它们均匀分布，对隐式曲面进行采样。要在具备至少 Shader Model 3.0 功能的 GPU 上成功实现这一概念，我们需要解决三个问题：

第一，我们需要高效地求值隐式函数及其梯度，以便把粒子约束在流体曲面上。为解决这个问题，我们选择一种能在片元着色器中快速求值隐式函数的数据结构。这种数据结构在受 GPU 限制的场景中还能有选择地减轻 GPU 负载。我们在 7.2 节介绍该方案。

第二，我们需要计算粒子之间的排斥力，以获得曲面粒子的均匀分布。粒子的均匀分布至关重要：一方面，应尽量减少粒子之间的重叠以提高渲染速度；另一方面，为达到高视觉质量，粒子应覆盖整个曲面，不应出现空洞或裂缝。我们按 SPH 方法计算作用在曲面粒子上的排斥力来解决这个问题。执行 SPH 的难点在于对粒子集合做最近邻查询。我们给出一种在片元着色器中确定某粒子最近邻的新算法。7.3 节介绍排斥力的计算。

最后，由于仅靠排斥力的分布过程相当慢，而且无法把粒子分布到断开的区域，我们再加一种分布算法。这种全局分散算法加速分布过程，7.4 节会加以说明。

本质上，粒子的行为可以定义为粒子在隐式曲面上运动的流体仿真。GPU 已被成功用于类似的大量粒子基于物理的仿真（Latta 2004）。但据我们所知，粒子之间相互影响的基于 GPU 的粒子系统尚未有公开文献。

既然我们已经用公式 2 对粒子建立了速度约束，接下来讨论如何在 GPU 上高效计算该方程。首先注意，该函数只用流体原子位置与流体原子速度就能重建——前者用于 F i、、 与 各项；后者用于 与 。因此只需把原子位置与速度从 CPU 上的 SPH 仿真送到 GPU。其次，我们不去为计算公式 1 及其导数而求值每个流体原子的位置或速度——那在 GPU 上意味着昂贵的纹理查找——而是利用一个事实：原子在其影响半径 h a 之外对密度场没有贡献。

为找出所有相邻原子，我们选用 Teschner et al. 2003 描述的空间哈希数据结构。相比基于树的空间数据结构，空间哈希的优点在于查询时访问时间恒定。树的遍历需要访问在显存中可能并不相邻的节点，这会让过程不必要地昂贵。

7.2.5 构造与查询哈希

在说明哈希方法的第二处不同之前，先概览一下哈希的构造与查询。我们用空间哈希同时携带流体原子的位置与速度，这些数据必须从 CPU 上的流体仿真送到 GPU 上的流体可视化。因此我们在 CPU 上构造它，而在 GPU 上查询。

空间哈希的实现由两部分组成：哈希索引表与原子属性池。大小为 hs 的哈希索引表索引存放流体原子位置与速度的原子属性池。哈希索引表中的每个条目 e 对应哈希桶 e，表中信息指向该桶在原子属性池中的第一个属性元素，以及该桶中现有的元素个数。由于空间哈希用于把原子位置与速度从 CPU 送到 GPU，我们在 CPU 上构造，在 GPU 上查询。图 7-4演示了在 GPU 上查询该数据结构的过程。

现在说明与 Teschner et al. 2003 相比的第二处不同，即哈希构造的方法。构造空间哈希的传统做法是把每个流体原子加入哈希表一次，即加入其位置映射到的哈希桶。用所得结构查找邻居时，传统做法要对每个流体原子做多次查询：对与其位置周围、半径为流体原子半径的球相交的每个网格单元各查一次。这样得到所有影响该位置处密度场的流体原子。而我们采用一种反向哈希做法：流体原子被加入哈希多次，对其影响区域相交的每个网格单元各加一次。这样 GPU 只需查询一个哈希桶，就能找出与该网格单元相交或将其包含的所有原子。两种方法如图 7-5所示。代码清单 7-2 包含伪代码。

在性能上，反向哈希方法的好处是 GPU 上只需一次查询，与所选网格单元尺寸无关。减小哈希单元尺寸时，就能让网格单元相对其中影响位置的流体原子获得更好的近似。这两方面结合，使 GPU 在纹理内存中必须执行的数据查找次数最小。不过网格单元越小，CPU 上的构造时间越长，因为与流体原子影响半径相交的网格单元越多，单个原子加入哈希的次数就越多。传统哈希方法正好相反：网格单元越小，GPU 的查询次数越多，而 CPU 始终只把原子加入哈希一次。因此受 GPU 制约的硬件配置应选反向哈希方法，受 CPU 制约的配置应选传统哈希方法。

7.3 局部粒子排斥

除了把粒子约束在流体曲面上，我们还要求它们覆盖整个曲面面积。为获得粒子在流体曲面上的均匀分布，我们采用 Witkin 和 Heckbert 1994 提出的排斥力概念。该文按距离定义作用于空间两点的排斥力；距离越大，排斥力越小。流体曲面上的粒子必须对这些排斥力作出反应。因此它们不再能自由移动到曲面上的任意位置。

7.3.3 GPU 上的最近邻

既然已用公式 6 定义了作用在曲面粒子上的排斥力，我们又一次面临在 GPU 上高效计算它们的难题。如同处理影响密度场的流体原子那样，我们将利用一个事实：粒子只在其周围很小的邻域内影响密度场。全局数据结构在这种情形下不是可行的方案；构造必须在 GPU 上进行，而不能在 CPU 上。这类结构的构造会依赖排序或类似的相互依赖的输出，对可视化的执行时间不利。例如，构造 7.2.3 节那种空间哈希的数据结构，在 GPU 上需要不止一遍，因为它要求长度可变的哈希桶。

为绕开必须构造数据结构的限制，我们改用显卡上的渲染目标。我们用它在其中存放浮点数据元素，由变换管线完成构造。通过用着色器程序把某些图元渲染到特定位置，就可以在计算排斥力时查询并使用渲染目标中的信息。

算法分两步工作：

第一遍

  1. 建立表示正交投影的变换矩阵 M，其视口涵盖所有曲面粒子，并准备一个 float4 渲染目标。
  2. 把曲面粒子渲染到其中心所映射到的那个像素。
  3. 把它们的世界空间坐标存入帧缓冲中该像素处。
  4. 把渲染目标保存为纹理「Image 1」，如 图 7-7a 所示。

第二遍

  1. 启用加法混合，并保留 float4 渲染目标。 [1]
  2. 围绕每个曲面粒子渲染一个四边形，包住其影响区域在图像空间中的投影，如图 7-7b所示。
  3. 执行片元程序：把存在四边形中心处的粒子世界空间位置，与图像 1 中处理中的片元所在像素处可能存在的邻居粒子的世界空间位置作比较，然后输出一个排斥力。见图 7-7c。排斥力按公式 6 计算。
  4. 把渲染目标保存为纹理「图像 2」，如图 7-7d所示。

第一步中若两个粒子重叠，则保存最前面的粒子，丢弃另一个。选取足够的视口分辨率，可以把这种信息损失降到最低。不过丢失粒子位置并不会损害可视化效果；因为上面的粒子会因排斥力离开拥挤区域，下面的粒子就会重新浮现。

第二步之所以有效，是因为粒子的影响区域是一个球。该球投影为圆盘，其包围盒可以用一个四边形表示。这个四边形随后包含球内所有投影后的粒子位置，我们正是把它画出来，以便对第一步中存放的数据做最近邻搜索。

查询生成的排斥力图，使用与执行两遍排斥算法时相同的变换矩阵 M。要查询某个粒子所需的排斥力，用该变换矩阵变换其世界空间位置得到一个像素位置，再在所得像素处读取包含排斥力的图像。

这个算法会得到一张排斥力图，我们把它放在粒子仿真循环之外单独执行，如代码清单 7-3 所示。其结果在确定粒子速度之前被查询。

示例 7-3. 最近邻算法第 2 遍的片元着色器

void pass2main(
        in float4 screenpos : WPOS,
        in float4 particle_pos,
        out float4 color : COLOR0,
        const uniform float rep_radius,
        const uniform samplerRECT neighbour_texture: TEXUNIT0
        )
{
  // 读取片元位置。
  float4 neighbour_pos = texRECT(neighbour_texture, screenpos.xy);
  // 计算斥力。
  float3 posdiff = neighbour_pos.xyz IN.particle_pos.xyz;
  float2 distsq_repsq = float2(dot(posdiff, posdiff), rep_radius * rep_radius);
  if (distsq_repsq.x < 1.0e-3 || distsq_repsq.x > distsq_repsq.y)
    discard;
  float dist = sqrt(distsq_repsq.x);
  float e1 = rep_radius - dist;
  float resultdens = e1 * e1 / distsq_repsq.y;
  float3 resultforce = 5.0 * resultdens * posdiff / dist;
  // 输出斥力。
  color = float4(resultforce, resultdens);
}

7.4 全局粒子分散

为加速 7.3 节所述的粒子分布过程，我们引入一种粒子分散方法。该方法直接作用于 GPU 所仿真的曲面粒子的位置。我们按粒子密度（由公式 5 定义）改变粒子位置，密度可以用计算排斥力的同一套最近邻算法算出。高密度区域的粒子被移除，放到低密度区域的位置上。为此，我们把基准粒子与比较粒子的密度与某个阈值 T 作比较。当比较粒子的密度最低且密度差超过阈值时，基准粒子的位置会改变，以在比较位置处提高密度、在基准位置处降低密度。基准粒子将被移到比较粒子影响区域边缘的随机位置，如图 7-8所示，以尽量减少比较粒子位置处密度的波动。这种波动会引发更多粒子迁移，可能让流体曲面不得安宁。

在曲面粒子仿真的每次迭代中，让每个粒子都去搜索整个曲面粒子池以寻找流体曲面上的低密度位置是不可行的。因此，对每个粒子，GPU 每隔 t 秒利用一张在 CPU 上生成的随机值纹理，从池中随机选出一个比较粒子。t 的取值可以任意。算法如下：

对每个曲面粒子：

  1. 判断该粒子是否到了换位置的时间。
  2. 若是，则选出比较位置，并比较两个位置处的密度。
  3. 若该粒子处的密度高于比较粒子处的密度，且差值大于阈值 T，则把位置改为比较粒子影响边界上的一个随机位置。

7.5 性能

最终应用的性能受许多不同因素影响。图 7-2给出了可能在 GPU 上形成瓶颈的三个阶段：粒子排斥阶段、受约束粒子速度计算，以及粒子分散算法。我们取用图 7-11中一杯水的场景来分析这三部分的性能。

我们发现应用的大部分计算时间花在两处。第一个瓶颈是受约束粒子速度的计算。为约束粒子速度，每个粒子都要遍历流体原子位置构成的哈希结构，每次迭代都做多次纹理查找与距离计算。为最大化性能，我们通过增加哈希桶数量把哈希碰撞次数降到最少。我们还选了较小的网格单元尺寸，以减少曲面粒子访问到的冗余邻居；网格单元尺寸为流体原子直径的三分之一到五分之一。

第二个瓶颈是排斥力的计算。算法性能主要取决于曲面粒子周围的查询尺寸。尺寸越小，过度绘制越少，性能越快。不过查询尺寸选得太小，粒子排斥可能减弱过多。因此理想尺寸取决于应用的需求。为大致说明我们的算法能达到的实际每秒帧数，我们在 GeForce 6800 上多次运行应用，对 16,384 个曲面粒子选用不同的查询尺寸。查询尺寸用四边形可视化，如图 7-10所示。

7.6 渲染

为展示我们的可视化方法能达到的真实感水平，图 7-11给出了带光照、混合、曲面法线曲率以及反射与折射的流体曲面渲染示例。为渲染光滑透明的曲面，我们采用一种只保留最前面粒子、丢弃其他粒子之后粒子的混合方法。难点在于区分两种情况：位于曲面另一部分、应当丢弃的粒子，与位于曲面同一部分、因重叠而应当保留以参与混合的粒子。

为解决确定最前面粒子的问题，我们做一次深度渲染，把粒子渲染为定向四边形，并为每个生成的片元计算该四边形的投影空间位置。我们把每个像素处深度最小的片元存入深度纹理。把流体曲面渲染为定向四边形时，我们只在粒子位置即四边形中心处查询深度缓冲。用等于流体原子半径的偏移量，判断某个粒子能否被视为最前面。我们渲染通过该测试的粒子。这样，同一个像素上就可以渲染多个重叠的四边形。

我们这样进行混合：先按到四边形中心的距离，为四边形上的每个位置指定一个 alpha 值。在实际渲染之前，我们在一次 alpha 遍中累加这些 alpha 值。渲染时，我们根据片元的 alpha 值与 alpha 遍中累加得到的 alpha 值，确定某个四边形对最终像素颜色的贡献。

最后，我们用一种法线扰动技术来增加细节、改善流体曲面的混合。把曲面渲染为定向四边形时，我们对每个片元的法线作轻微扰动。扰动依据是用于渲染该四边形的粒子位置处流体密度场的曲率。密度场的曲率可以在速度约束遍中计算梯度与密度场时算出。利用梯度，我们可以得到一个与渲染四边形同样大小、与流体曲面相切的向量。该向量乘以曲率（一个 3x3 矩阵），得到法线沿该切向量的变化量。我们只用点积把法线变化投影到切向量上，得到一个标量。这是对粒子位置处散度的近似（实际上它只构成散度的一部分）。这个标量被存下来，在曲面渲染时与重建的切向量一起用来构造四边形法线的扰动向量。

7.7 结论

我们给出了一套方案，能在 GPU 上高效、有效地实现 Witkin 和 Heckbert 1994 的基于点隐式曲面可视化方法，以交互帧率渲染元球。我们的方案由三部分组成：计算约束速度、排斥力，以及为获得接近均匀的粒子分布而计算粒子密度。后两部分涉及一种新的 GPU 粒子系统算法，其中粒子之间相互影响。方案的最后一个部分还改进了原方法：加速粒子在流体曲面上的分布，并让粒子能分布到断开的曲面之间以防止出现空隙。与 marching cubes 和光线追踪方法相比，我们的方案有明显性能优势，因为其复杂度取决于流体曲面面积，而另外两种方法的复杂度取决于流体体积。

不过，所提出的方法并未解决所有问题。今后对算法的改造可以引入自适应粒子大小，以便更快填补流体曲面上临时出现的空隙。此外，新产生的断开曲面片并不总是其表面上有粒子，这意味着只要它们保持断开，就不太可能获得粒子。最大的问题则在于处理相距很远的小块流体。由于排斥算法需要一个包住所有粒子的裁剪空间，视口分辨率有限就很可能使多个粒子映射到同一像素，从而造成数据丢失。最后一个研究方向是把曲面粒子用于渲染以实现各种视觉效果，图 7-11就是一个例子。
