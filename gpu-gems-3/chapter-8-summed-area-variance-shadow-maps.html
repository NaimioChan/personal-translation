第 8 章　求和面积方差阴影贴图

Andrew Lauritzen
University of Waterloo

本章讨论阴影贴图滤波与软阴影。我们回顾方差阴影贴图算法，说明它如何帮助解决许多常见的阴影贴图问题。我们还给出一种简单而有效的技术，用于显著减轻与方差阴影贴图（VSM）相关的漏光瑕疵。

最后，我们介绍一种基于 VSM 与求和面积表（SAT）的实时阴影算法。我们对任意矩形滤波区域都能高效地计算阴影贡献，这使求和面积方差阴影贴图（SAVSM）成为生成无走样软阴影的理想算法。

8.1 引言

阴影贴图（Williams 1978）是一种流行的阴影算法，相比阴影体（Crow 1977）有几个重要优势。特别是阴影贴图可以在任意位置查询，并且对几何复杂度不那么敏感。遗憾的是，标准阴影贴图也受几种众所周知的纹理映射瑕疵困扰。

当投影后的阴影贴图纹素在屏幕空间中覆盖很大面积时，会出现放大瑕疵。相反，当多个阴影贴图纹素映射到同一个屏幕空间像素时，会出现缩小瑕疵。

解决这些问题需要对阴影贴图正确滤波，这也是本章的重点。图 8-1 就是用本章所述技术得到的高效软边阴影的一个好例子。

8.2 相关工作

减少阴影贴图走样的一种方法是改变阴影贴图投影，以减少放大与缩小极端的区域。这个方向已有大量研究，尤其是透视阴影贴图（Stamminger and Drettakis 2002）、光空间透视阴影贴图（Wimmer et al. 2004）和梯形阴影贴图（Martin and Tan 2004）。不过，除非场景中只有一个平面阴影接收者，否则用统一的仿射投影无法实现完美的纹素到像素一对一映射。

因此，要正确处理缩小情形，我们需要纹理滤波。遗憾的是，三线性与各向异性滤波这类硬件纹理滤波对标准阴影贴图并不适用。硬件会对阴影贴图中的深度值求平均，而滤波后的深度仍要接受一次二值深度比较。百分比邻近滤波（PCF）（Reeves et al. 1987）解决了这个问题，它滤波的是多次深度比较的结果，而不是深度值本身，从而得到正确结果。

另一种解法是使用方差阴影贴图（Donnelly and Lauritzen 2006）。把每个阴影贴图纹素视为深度的分布而不是单个深度，就可以用可线性滤波的方式表示阴影贴图。于是 mipmap、各向异性滤波和求和面积表这类技术都可以用上。

注意，阴影贴图滤波通常与投影扭曲正交。特别是滤波对放大瑕疵几乎无能为力，而放大瑕疵正是投影扭曲算法的主要关注点。因此，在稳健的阴影贴图实现中，这两类技术应当结合使用。

本章我们简要讨论百分比邻近滤波，然后重点讲方差阴影贴图，因为它在性能与质量两方面都有若干有利特性。

8.3 百分比邻近滤波

百分比邻近滤波的工作方式是：把当前屏幕空间像素的范围投影到阴影贴图上并采样相应区域，这个过程类似于标准纹理滤波。然后把每个采样与参考深度比较，得到二值结果。接着，把这些深度比较结果合并，算出滤波区域内比参考深度更近的纹素所占百分比。这个百分比用来衰减光照。

Reeves et al. 1987 指出，增大滤波区域的尺寸会使阴影边缘变软，如 图 8-2 所示。通过钳制最小滤波尺寸，我们可以得到任意软的边缘，同时仍避免缩小走样。不过，大的滤波尺寸需要高分辨率阴影贴图才能保持细节。

该算法的一个常见变体是采样固定区域的邻近阴影贴图纹素。这易于实现；但它只是软化了阴影边缘，并没有解决我们提到的走样瑕疵。

8.3.1 百分比邻近滤波的问题

PCF 的质量可以非常好，但要达到这样的高质量需要大量采样。与标准纹理滤波一样，浅角度的表面需要极大的各向异性滤波区域。就百分比邻近滤波而言，由于要逐采样做深度比较，无法用预滤波的 mipmap 来加速。因此，在最坏情况下，为了给一个帧缓冲像素计算光衰减，我们必须采样并比较阴影贴图中的每一个纹素！如预期的那样，这个过程可能很慢。

当我们用 PCF 来实现边缘软化时，情况更糟，因为这种做法等价于给滤波区域的尺寸设了下界，也就给像素的着色代价设了下界。

百分比邻近滤波的另一个问题是它继承并加剧了阴影贴图的经典毛病：「阴影痤疮」与偏移（biasing）。最难解决的偏移问题由覆盖大范围深度的阴影贴图纹素造成。这种情况常源于几乎平行于光源方向的多边形，如 图 8-3 所示。

为防止不恰当的自阴影，我们需要选择一个常数深度偏移，它与阴影贴图中任何纹素所覆盖的最大深度范围成正比。当然，这个范围可以任意大，而按此设置偏移会使阴影脱离其投影者（即所谓的彼得潘现象）。按 Kilgard 2001 的建议，选择与遮挡多边形斜率成正比的逐纹素深度偏移会有帮助，但并不能消除问题。

为 PCF 采样邻近纹素会使情况更糟，因为这实际上要求偏移与整个滤波区域上的深度范围成正比。由于这个区域是在着色遍中动态算出的，不可能选出一个适用于所有滤波尺寸的好的逐纹素偏移。

8.4 方差阴影贴图

阴影贴图滤波问题的另一个优雅解法是使用方差阴影贴图。主要思想是以可线性滤波的方式表示深度数据，这样就能使用处理颜色和其他线性数据的算法与硬件。

这个不等式给出任意滤波区域上百分比邻近滤波结果的上界。上界的好处是可以避免本应完全照亮的区域出现自阴影。更重要的是，Donnelly and Lauritzen 2006 表明，对单个平面遮挡体和单个平面接收者，这个不等式是精确的，而对许多真实场景来说这是合理的近似。特别是对单个遮挡体和单个接收者，总存在一个小邻域使它们局部为平面，因此在该区域上算出的 p max 能很好地近似真实概率。

8.4.1 对方差阴影贴图滤波

既然阴影贴图已可线性滤波，大量技术与算法就都能为我们所用。最值得注意的是，我们可以直接启用 mipmap、三线性与各向异性滤波，甚至多重采样抗锯齿（在渲染阴影贴图时）。仅此一项就能比使用标准阴影贴图与固定滤波尺寸的百分比邻近滤波显著提升质量，如 图 8-4 所示。

示例 8-1. 在场景着色期间计算 p max


float ChebyshevUpperBound(float2 Moments, float t)
{
  // 单尾不等式，在 t > Moments.x 时成立
  float p = (t < = Moments.x);
  // 计算方差。
  float Variance = Moments.y – (Moments.x * Moments.x);
  Variance = max(Variance, g_MinVariance);
  // 计算概率上界。
  float d = t – Moments.x;
  float p_max = Variance / (Variance + d * d);
  return max(p, p_max);
}
float ShadowContribution(float2 LightTexCoord, float DistanceToLight)
{
  // 从方差阴影贴图中读取矩。
  float2 Moments = texShadow.Sample(ShadowSampler, LightTexCoord).xy;
  // 计算切比雪夫上界。
  return ChebyshevUpperBound(Moments, DistanceToLight);
}

不过我们还能做更多。特别是 Donnelly and Lauritzen 2006 建议在着色之前对方差阴影贴图做模糊（一个简单的盒式滤波就够了）。这种做法等价于邻域采样的百分比邻近滤波，但由于使用了可分离的模糊卷积，代价低得多。如前所述，这样实际上等于钳制了最小滤波宽度，会软化阴影边缘，有助于掩盖放大瑕疵。

使用硬件滤波之外的另一种选择是求和面积表，它同样要求数据可线性滤波。我们在 8.5 节更详细地讨论这一选项。

8.4.2 偏移

除了提供廉价的高质量滤波，方差阴影贴图还为阴影偏移问题提供了一种优雅的解法。

示例 8-2. 在方差阴影贴图渲染期间计算矩


float2 ComputeMoments(float Depth)
{
  float2 Moments;
  // 一阶矩就是深度本身。
  Moments.x = Depth;
  // 计算深度的偏导数。
  float dx = ddx(Depth);
  float dy = ddy(Depth);
  // 在像素覆盖范围上计算二阶矩。
  Moments.y = Depth * Depth + 0.25 * (dx * dx + dy * dy);
  return Moments;
}

最后，通常把 M 2 中偏导数那一部分钳制住是有益的，以免遮挡体几乎平行于光源方向时方差过大。在这些情况下，硬件生成的偏导数会变得不太稳定，而不稳定的方差会在本应完全处于阴影中的区域产生随机闪烁的亮点。

许多场景完全不用偏导数偏移就能避免这种不稳定。如果阴影分辨率足够高，仅仅钳制最小方差就足以消除表面痤疮。

8.4.3 漏光

方差阴影贴图已知的一个问题是可能出现漏光（本应完全处于阴影中的区域出现了光）。这个瑕疵通常出现在这样的情形：阴影的软边在第一个接收者上可见（这是应该的），同时在第二个接收者上也有较轻程度的可见（而它本应被第一个接收者完全遮挡），如 图 8-6 所示。在 图 8-7 中，最令人不适的漏光出现在 a 与 b 之比较大时。

坏消息是，不增加采样（那会退化成暴力百分比邻近滤波）就无法完全解决这个问题。对任何算法都是如此，因为遮挡体的分布、以及滤波区域上的可见性，都是阶跃函数。

当然，我们常常可以加速常见的滤波情形（方差阴影贴图就很好地做到了），但总能构造出病态情形：在一个有 N 个项的滤波区域内有 N 个不同的遮挡体。任何不采样全部 N 个值的算法都无法正确重建可见性函数，因为理想函数是含 N 个唯一片段的分段阶跃函数。因此，一个能在任意滤波区域上算出精确解的高效阴影贴图采样算法必须是自适应的。

这个要求当然不方便，但也不算致命：方差阴影贴图实际上既是精确阴影算法、也是近似阴影算法的良好构件。我们主要关心保持高性能，并愿意接受偶尔的物理不准确，所以近似算法大概是最有前途的方向。

为此，对 p max 做一个简单的修改就能大幅减少漏光，代价是半影区域会稍微变暗。

近似算法（减少漏光）

一个重要的观察是：如果深度为 t 的表面在平均深度为 的某个滤波区域上被完全遮挡，那么 t > 。因此 (t- )2 > 0，由切比雪夫不等式得 p max < 1。简单说，完全被遮挡表面上不正确的半影永远不会达到全强度。

我们可以修改 p max 来去掉这些区域：把低于某个最小强度的值都映射为 0，其余值重新缩放，使其从 0（在最小强度处）映射到 1。

这个函数可以在 HLSL 中轻松实现，如代码清单 8-3 所示。

示例 8-3. 应用漏光削减函数


float linstep(float min, float max, float v)
{
  return clamp((v – min) / (max – min), 0, 1);
}
float ReduceLightBleeding(float p_max, float Amount)
{
  // 去掉 [0, Amount] 这一段，把 (Amount, 1] 线性重映射。
  return linstep(Amount, 1, p_max);
}

注意，linstep() 可以替换为 [0, 1] 上任意单调递增的连续函数。例如 smoothstep() 产生一个不错的三次衰减函数，可能正是我们想要的。

Amount 参数可由美术编辑，实际上设定了漏光削减的力度。它与场景尺度无关，但漏光更多的场景通常需要更高的值。最佳设置与场景中遮挡体和接收者的深度比有关。这个参数要谨慎处理，设得太高会减少阴影细节。因此应当把它设到刚好足以消除最令人不适的漏光，同时尽量保持细节。

在实践中这个解法基本上是免费的，对许多场景都有效，图 8-8 中可以看得很清楚。因此对游戏和其他性能敏感的应用来说，漏光削减比精确的自适应算法有吸引力得多。

8.4.4 数值稳定性

另一个潜在问题是数值稳定性。特别是众所周知，方差的算子在数值上不稳定，因为要用两个接近相等的大值相减。所幸解决这个问题很容易：使用 32 位浮点纹理与滤波，GeForce 8 系列显卡支持这一功能。

我们还强烈建议使用线性深度度量，而不是投影后的 z 值。后者随到光源距离增大而严重损失精度。对百分比邻近滤波这类基于比较的阴影贴图，这种损失也许不是大问题，但精度损失会很快使方差计算变得不稳定。精度更均匀的线性度量，例如到光源的距离，更合适也更稳定。

8.4.5 实现说明

到这一步，方差阴影贴图已经相当可用，它提供高效滤波、廉价的边缘软化，并解决了标准阴影贴图的偏移问题。确实，目前的实现已适合用于游戏和其他实时应用。

总结一下，我们可以按如下方式实现硬件方差阴影贴图：

  • 用线性深度度量（代码清单 8-4）渲染到方差阴影贴图，输出深度与深度的平方（代码清单 8-2）。若硬件支持，对阴影贴图使用多重采样抗锯齿（MSAA）。
  • 可选地，用可分离的盒式滤波器对方差阴影贴图做模糊。
  • 为方差阴影贴图生成 mipmap。
  • 渲染场景，像通常那样把当前片元投影进光源空间，但对方差阴影贴图只做一次经过滤波的（各向异性与三线性）纹理查询，取回两个矩。
  • 用切比雪夫不等式计算 p max（代码清单 8-1）。
  • 可选地，对 p max 施加漏光抑制（代码清单 8-3）。
  • 用 p max 衰减阴影造成的那部分光照贡献。

因此，使用方差阴影贴图与使用普通阴影贴图相似，只是可以利用模糊、多重采样与硬件滤波。不过要注意，某些配合标准阴影贴图使用的技术（例如下面这些）并不适用于方差阴影贴图：

  • 把「第二深度」或「中点」渲染进方差阴影贴图不会正常工作，因为恢复出来的深度分布应当表示光源空间中最靠近光源的那些投影体的深度。不过这并不成问题，第二深度渲染本来是用来回避偏移问题的，而方差阴影贴图可以更直接地解决偏移问题（见 8.4.2 节）。
  • 只把投影体（不含接收体）渲染进方差阴影贴图是错误的！要让插值正常工作，接收表面必须出现在深度分布中。否则阴影半影的尺寸会不正确，也无法从亮到暗平滑过渡。

不过，投影扭曲与视锥分割这两种技术与 VSM 完全兼容。事实上两者相辅相成。方差阴影贴图能掩盖扭曲或分割视锥带来的许多瑕疵，例如分割点之间的不连续，以及相机移动时阴影边缘的游移。

8.4.6 方差阴影贴图与软阴影

接下来我们处理使用硬件滤波时的几个问题。首先，高精度的硬件滤波可能无法获得。更重要的是，我们希望逐像素控制滤波区域。

如前所述，钳制最小滤波宽度可以让阴影边缘变软。近期几种软阴影算法利用了这一能力，依据对「遮挡体深度」的估计动态选择滤波宽度。这种做法能产生令人信服的阴影半影，半影随遮挡体与接收体之间的距离增大而变大。

遗憾的是，这种情况下我们无法用模糊来钳制最小滤波宽度，因为该宽度逐像素变化，取决于遮挡体搜索的结果。我们当然可以钳制硬件使用的 mipmap 层级，但用 mipmap 这样去做模糊会产生极其难看的块状瑕疵，如图 8-9 所示。改用高阶滤波手工生成 mipmap 层级，有望取得更好的结果，这是未来工作的一个值得期待的方向。

在最理想的情况下，我们会有一套滤波方案，能逐像素动态选择滤波尺寸，最好还保持恒定开销、不需要动态分支。求和面积表恰好提供了这种能力。

8.5.1 生成求和面积表

我们希望在 GPU 上生成求和面积表，以获得更好的性能并避免过多数据搬运。有两种算法可能适用：逐行与递归倍增。

逐行做法基本上就是一次一维的累加和，一次处理一个维度。在 GPU 上，可以一次处理一行，把当前行加到之前的和上。这种方法的缺点是需要（width+ height）遍。

在 GPU 上生成求和面积表的另一种做法是递归倍增，由 Hensley 等 2005 提出。算法的完整描述见该文献。本书附带的示例代码中也有一份实现。

8.5.2 再谈数值稳定性

求和面积表消耗精度的速度相当快：log(width x height) 位。因此一张 512x512 的 SAT 在最坏情况下要吃掉 18 位精度，23 位尾数里只剩 5 位留给数据本身！平均情况没有这么惨，但使用求和面积表会显著降低底层数据的有效精度。

幸运的是，有几个技巧可以把精度提升到可接受的水平。Hensley 等 2005 针对浮点求和面积表给出了若干提高精度的建议。其中一条是生成 SAT 之前给每个元素减去 0.5 的偏置，在区域平均之后再还原。这种做法相当于从符号位多榨出一位精度。对于数据分布高度不均匀的图像（我们的情形是阴影贴图），以数据均值为偏置可以获得更大的收益。此外，作者建议使用「原点居中」的 SAT 再省下两位，代价是复杂度上升。这对聚光灯尤其是一个有用的优化，因为它把低精度区域推到阴影投影的四个角落，这样任何瑕疵都会在很大程度上被圆形的聚光灯衰减锥遮住。

Donnelly 与 Lauritzen 2006 提出的一个技巧在这里也有用：把精度分散到多个分量中。我们不再存储双分量的方差阴影贴图，而是存四个分量，把前两个矩各自分散到两个分量里。这种精度拆分不能随意进行；要与线性滤波正确配合，它必须是线性操作。不过代码清单 8-5 给出了一个在实践中效果相当不错的示例实现。

示例 8-5　分散浮点精度


// 数值在哪里拆分。8 位在多数情况下够用。
float g_DistributeFactor = 256;
float4 DistributePrecision(float2 Moments)
{
  float FactorInv = 1 / g_DistributeFactor;
  // 拆分精度
  float2 IntPart;
  float2 FracPart = modf(Value * g_DistributeFactor, IntPart);
  // 把各输出组合起来，让重建更省。
  return float4(IntPart * FactorInv, FracPart);
}
float2 RecombinePrecision(float4 Value)
{
  float FactorInv = 1 / g_DistributeFactor;
  return (Value.zw * FactorInv + Value.xy);
}

这一步当然使求和面积方差阴影贴图的存储与带宽需求翻倍，但得到的实现仍在许多情况下胜过暴力百分比邻近过滤，如 8.5.3 节所示。

GeForce 8 系列硬件提供的另一个选择，是用 32 位整数存储阴影贴图。这样存储可以省下原本浪费在浮点指数部分（我们根本不用）上的好几位精度。

使用整数时，溢出是潜在问题。要完全避免溢出，我们必须为累加保留 log(width x height) 位。幸运的是，Direct3D 10 中的溢出行为（回绕）反而对我们有利。具体来说，如果我们知道会用到的最大滤波尺寸是 M x x M y，那么只需保留 log(M x x M y ) 位。由于滤波尺寸通常能给出相当保守的上界，留给数据的位数就很充裕。实践中，这个方案即使对大型阴影贴图也工作得极好，而且不需要分散精度之类的技巧。

最后一个选择要等硬件支持就绪后才能用：用双精度浮点数存储矩。双精度带来的巨大精度提升（52 位对 23 位）可以消除数值稳定性造成的任何问题。

8.5.3 结果

图 8-11 展示了一张用 512x512 求和面积方差阴影贴图渲染的图像。注意其中看不到任何走样。图 8-12 展示了仅仅改变最小滤波宽度就得到的硬阴影与软阴影。该技术的性能与滤波宽度无关，因此可以在不影响帧率的情况下得到任意柔和的阴影。

该技术在现代硬件上也很快。图 8-13 比较了 PCF（带硬件加速）、模糊后的 VSM（带与不带阴影多重采样）以及 SAVSM 的性能。我们选了一个简单测试场景来评估相对性能，因为这些技术都在图像空间工作，因此基本上与几何复杂度无关。

显然，标准模糊方差阴影贴图是恒定滤波宽度下的最佳方案。即使启用多重采样，VSM 也快过竞争者。注意模糊方差阴影贴图的开销理论上随滤波宽度线性增长，但现代硬件执行这类可分离模糊极快，除非滤波核特别大，否则看不出性能下降。

对于动态滤波宽度，求和面积方差阴影贴图的初始化开销高于百分比邻近过滤（生成 SAT）。不过这一开销很快被 PCF 更高的采样开销抵消，特别是在最小滤波尺寸较大（即阴影较软）时。根据我们的经验，要消除阴影贴图最刺眼的走样瑕疵，最小滤波宽度至少需要 4，因此 SAVSM 是明显的赢家。我们预期更激进的优化还能带来进一步的性能提升。

8.6 百分比邻近软阴影

现在我们有了能在恒定开销下滤波任意区域的算法，可以用来让 SAVSM 生成可信的软阴影了。任何在阴影贴图上做 PCF 式采样的算法都是潜在的集成对象。

Fernando 2005 提出的一个这类算法是百分比邻近软阴影（PCSS），它因为简单而格外有吸引力。PCSS 分三步工作：（1）遮挡体搜索，（2）半影尺寸估计，（3）阴影滤波。

8.6.1 遮挡体搜索

遮挡体搜索在当前阴影纹素周围采样一个搜索区域，求出该区域内所有遮挡体的平均深度。搜索区域的大小与光源尺寸和到光源的距离都成比例。若某个采样比当前片元更靠近光源（用标准深度测试判断），就认为它是遮挡体。

这一步的一个不幸后果是，由于要做深度测试，PCF 的偏移问题会被重新引入我们的软阴影算法。此外，在好不容易实现恒定时间滤波之后，还要在阴影贴图的某个区域上取大量采样，实在令人失望。

8.7 结论

我们详细讨论了阴影贴图滤波这一主题，并为许多相关问题提供了解决方案，例如缩小走样、偏移与软阴影。

我们展示了方差阴影贴图相当有用，是未来研究的一个值得期待的方向。话虽如此，标准模糊方差阴影贴图配合漏光抑制函数，速度极快、稳健，质量也很好。对于大多数不需要逐像素控制滤波宽度的应用，我们强烈推荐用这套实现来做阴影滤波。

对于可信的软阴影，方差阴影贴图也被证明有用。配合求和面积表，它们能对任意矩形区域做恒定时间滤波。

总之，我们希望本章提供了有用的方案，也希望它能激发今后对方差阴影贴图乃至一般实时阴影滤波算法的研究。
