蒙特卡洛方法为那些难以或无法精确求解的问题提供近似数值解。蒙特卡洛仿真的决定性特征在于使用多次独立试验，每次试验由某种随机过程驱动。随后把各次独立试验的结果组合起来，提取平均答案，依据的是大数定律：随着合并的试验增多，平均答案会收敛到真实答案。独立试验天然可并行，而且通常由密集的数值运算构成，因此 GPU 为蒙特卡洛仿真提供了近乎理想的平台。

然而蒙特卡洛仿真中的一个关键组件是随机数生成器（RNG），它为每次试验提供独立的随机输入。这些生成器必须满足彼此冲突的目标：既要极快，又要给出与真正随机源无法区分的随机数流。关于 CPU 上的随机数生成已有大量文献，但其中最有效的那些对处理器架构和性能作了基本假设，往往不适合在 GPU 上使用。此前的工作如 Sussman 等 2006 研究过较老几代 GPU 上的随机数生成，而最新一代完全可编程的 GPU 特性不同，需要新的方法。

本章我们讨论用 CUDA 生成随机数的方法，特别关注高斯随机数的生成，这是许多金融仿真的关键组件。我们描述两种生成高斯随机数的方法：一种用 Box-Muller 方法变换均匀分布的数，另一种用 Wallace 方法直接生成高斯分布的随机数。然后我们用两个 CUDA 期权定价的例子，演示这些随机数生成器如何用于真实仿真。总体来看，一块 GeForce 8 GPU 生成高斯随机数的速度是四路 Opteron 2.2 GHz CPU 的 26 倍，两个金融例子中相应的加速比分别为 59 倍和 23 倍。

37.1 蒙特卡洛仿真

蒙特卡洛方法由 Ulam 和 von Neumann 在 20 世纪 40 年代提出，目的是模拟核反应（Metropolis 1987）。用一个简单例子说明蒙特卡洛解法：计算 。取一个正方形，在其中内切一个与正方形各边相切的圆。我们知道若圆半径为 r，则圆面积为 r 2，正方形面积为 4r 2。如果能算出圆面积与正方形面积之比 p，就能算出 ：

我们可以用蒙特卡洛方法计算比值 p：在正方形内均匀生成 n 个独立随机点。其中有 k 比例的点落在圆内，于是 p ≈ k/n，从而 p ≈ 4k/n。图 37-1 显示在圆内放置的随机点，n = 20、200 和 2,000 分别以蓝色圆点、红色叉号和绿色点表示，给出的 估计为 3.4、3.18 和 3.158。点数增加时精度提高，n = 2 x 104 时估计为 3.1492，n = 2 x 105 时为 3.1435。

显然这不是计算 的高效方法：精度提升的速率很低（精度通常与试验次数的平方根成正比），比标准的迭代方法低效得多。不过它确实说明了蒙特卡洛方法如此流行的三个原因：

  1. 很容易理解方法如何工作，而对应的精确解法（假设存在）往往并非如此。
  2. 很容易实现，主要障碍是随机数的生成。
  3. 蒙特卡洛方法天然可并行。

最后一点是重大优势，让蒙特卡洛解法可以轻松扩展到网络集群中的多个节点，或 CPU、GPU 内的多个处理器。

更贴近实际的蒙特卡洛方法例子在金融领域。这里的做法是抓住一部分市场变量——例如某只股票在时刻 0 的价格 S 0——再选一个人为的随机模型，让它看起来能较好地刻画以往的股价路径。最常用的模型是几何布朗运动，其中股票在时刻 t 的最终价格建模为 St = S 0 e µ+ N ，其中 N 是从高斯分布中抽取的随机样本（Wilmott 2006）。

蒙特卡洛方法可以轻松地在多个处理器上并行，常被称为令人尴尬的并行。其中有五个主要步骤：

  1. 给每个处理单元分配一个随机序列。每个处理单元必须使用不同的随机数序列，且应与所有其他处理器使用的序列不相关。
  2. 把仿真参数（例如 S 0）传播到所有处理单元，并告诉它们要执行多少次仿真运行。
  3. 为每个处理单元生成要使用的随机数流。
  4. 在处理单元上并行执行仿真内核。
  5. 收集各处理单元的仿真输出，合并起来得到近似结果。

在许多传统架构上，困难的是第 4 步：写出仿真内核的高效实现，因为更快的内核能在给定时间内执行更多仿真试验，从而给出更准确的答案。不过在 GPU 上，数学负担很重的仿真内核往往相对容易实现。真正的挑战是管理不同随机数流到处理器的分配，并高效地生成这些随机数流。图 37-2 从高层展示了处理器之间的工作划分。

37.2 随机数生成器

37.2.1 引言

按「随机性」的来源，随机数生成器可以分为三类：

  • 真随机数生成器（TRNG）。这类生成器用物理随机源提供真正不可预测的数。TRNG 主要用于密码学，因为对仿真而言它们太慢。
  • 准随机数生成器（QRNG）。这类生成器试图用点均匀填充 n 维空间，不让点聚集或成组。QRNG 虽用于蒙特卡洛仿真，但本章不予考虑。
  • 伪随机数生成器（PRNG）。PRNG 是最常见的随机数生成器类型，设计目标是看起来和 TRNG 一样随机，却可以用确定性软件实现，因为其状态和转移函数完全可以预测。本章只考虑这一类生成器。

随机数生成器还有一种正交分类，按所产生的数的分布来组织。常见的库函数，例如 C 的 rand()，从均匀分布中采样，也就是在某个数值范围内每个值出现的可能性相同。

然而许多蒙特卡洛仿真实际需要不同的分布；常见的例子有正态分布、对数正态分布和指数分布。从非均匀分布产生样本的主要方法是先生成均匀随机数，再施加一个变换，把均匀数转换成所需非均匀分布的样本。

举例来说，标准指数变量 E 的累积分布函数（CDF）为 FE (x) = P[x < E ] = 1 - e -x 。CDF 把来自指数分布的样本 x 映射回小于 x 的值出现的概率，该概率是 0 到 1 之间的值。因此若 E 服从指数分布，则 P[x < E ] 服从均匀分布。这就引出反演法：既然我们知道 FE (x) 把指数分布转换为均匀分布，那么从逻辑上讲 就会把均匀分布转换为指数分布。于是若随机变量 U 服从均匀分布，则 将服从指数分布。

尽管反演 CDF 在概念上简单，但计算代价往往太高，难以使用。在上面的指数例子中，每个随机数都要调用一次 log()。这或许可以接受，但在许多情况下逆函数可能复杂得多，某些情况下甚至没有闭式解。高斯分布就是如此，而它是最重要的分布之一，因此人们投入了大量精力研究变换均匀分布的其他方法。这些方法不用直接的逆 CDF 变换，而用数学恒等式和统计技巧从均匀分布转换，例如使用成对的均匀随机数。

于是我们看到希望 PRNG 满足的两项主要通用要求：

  • 长周期。每个确定性生成器最终必然循环，目标是让循环周期尽可能长。有一个有力的论点：若一次仿真中所有节点总共使用 n 个随机样本，则生成器的周期至少应为 n 2。
  • 良好的统计质量。生成器的输出在实用意义上应与所需分布的 TRNG 无法区分，且不应表现出任何相关性或图案。生成器质量差会毁掉蒙特卡洛应用的结果，因此生成器必须能通过现有的理论与实践质量测试。可用的统计检验非常多，可用来验证这一要求（Knuth 1969，Marsaglia 1995，L'Ecuyer 2006）。

本章我们考虑两种生成高斯随机数的方法，它们特别适合新一代 GPU。第一种采用传统技术：先生成均匀随机数，再施加变换产生高斯分布。第二种用较新的技术直接生成随机数，无需均匀随机源。随后我们看这些生成器在两个奇异期权估值的蒙特卡洛仿真中的用法。

37.2.2 均匀到高斯的转换生成器

产生高斯随机数的传统方法需要两个组件：一个均匀 PRNG 和一个到高斯分布的变换。两者都有很多选择，因此这里简要讨论各自的要求，并对主要选择做简要分析。然后我们根据 GPU 架构的独特要求选出两个组件。

除了要满足 37.2.1 节讨论的均匀 PRNG 通用要求之外，GPU 的并行特性还提出两项额外要求：

  • 能在并行节点上生成不同的子流。每个节点必须分到随机流中不同且不重叠的部分。
  • 不同节点上的子流之间不能有相关性。这些子流必须看起来是完全独立的随机数流。

可用的均匀 PRNG

线性同余生成器

经典的生成器是线性同余生成器（LCG）（Knuth 1969），其转移函数形如 xn + 1 = (axn +c) mod m。生成器的最大周期为 m（假设三元组 (a, c, m) 具备某些性质），但这意味着在 32 位整数中周期至多为 232，实在太低。LCG 还有已知的统计缺陷，不适合现代仿真。

多重递归生成器

LCG 的一个衍生是多重递归生成器（MRG），它以加法方式组合两个或多个生成器。若组合 n 个周期为 m 1、m 2、. . .、mn 的生成器，则合成周期为 LCM(m 1, m 2, . . ., mn )，因此周期至多为 m 1 x, m 2 x, . . ., mnx。这类生成器既有良好的统计质量，又有长周期，但互素的模数需要使用 32 位乘除法的复杂算法，因此不适合当前的 GPU（NVIDIA 2007，6.1.1.1 节）。

滞后斐波那契生成器

分布式蒙特卡洛仿真中常用的一种生成器是滞后斐波那契生成器（Knuth 1969）。它与 LCG 相似，但引入了延迟反馈，转移函数为 xn +1 = (xn ⊗xn - k ) modm，其中 ⊗ 通常是加法或乘法。然而要取得好的质量，常数 k 必须很大。因此需要 k 个字的内存来保存状态。通常 k 必须大于 1000，而且每个线程都需要自己的状态，所以必须存在全局内存中。因此我们放弃滞后斐波那契方法，但指出由于它简单且所需寄存器少，在某些基于 GPU 的应用中可能有用。

梅森旋转

软件中最受推崇的随机数生成方法之一是梅森旋转（Matsumoto 和 Nishimura 1998），周期为 219,937，统计质量极佳。然而它有与滞后斐波那契类似的问题：状态很大，而且必须串行更新。于是每个线程都必须在全局 RAM 中有一份独立状态，且每生成一个数就要多次访问。再加上每生成一个数所需的计算量相对较大，这个生成器太慢，除非需要极致的质量。

组合 Tausworthe 生成器

在内部，梅森旋转用一个二元矩阵把一个比特向量变换成新的比特向量，所用的是极大的稀疏矩阵和大的向量。不过有一批相关生成器使用小得多的向量，量级为两到四个字，并相应地使用更稠密的矩阵。这类生成器的一个例子是组合 Tausworthe 生成器，它用异或把两个或多个由二元矩阵导出的独立流组合起来，得到周期更长、质量好得多的流。每个独立流用代码清单 37-2 所示的 TausStep 以六条按位指令生成。例如 L'Ecuyer 1999 的四分量 LFSR113 生成器需要 6 x 4 + 3 = 27 条指令，产生的流周期约为 2113。

示例 37-2. 组合 Tausworthe 生成器的单步


// S1、S2、S3 和 M 都是常量，z 属于
// 每个线程私有的生成器状态。
unsigned TausStep(unsigned &z, int S1, int S2, int S3, unsigned M)
{
  unsigned b = (((z << S1) ^ z) >> S2);
  return z = (((z & M) << S3) ^ b);
}

然而我们的统计检验显示，即便是四分量 LFSR113，在相对较小的样本量下也会在 5 元组和 6 元组上产生显著相关性。

混合生成器

我们提出的做法是把简单的组合 Tausworthe 与另一种生成器结合起来；若所有分量的周期互素，则合成生成器的周期将是所有分量周期的乘积，而且一种生成器的统计缺陷应当能掩盖另一种的缺陷。

我们已经提到过基于 LCG 的生成器，但因创建 MRG 需要素模数而放弃了它们。不过若使用单个模数为 232 的生成器，我们可获得两项重要性质：(1) 由于 32 位算术的截断，模运算在代码清单 37-3 所示的 LCGStep 中是免费的。(2) 得到的 232 周期与组合 Tausworthe 的所有分量周期互素，因此两者可以组合出周期长得多的生成器。

示例 37-3. 一个简单的线性同余生成器


// A 和 C 是常量
unsigned LCGStep(unsigned &z, unsigned A, unsigned C)
{
  return z = (A * z + C);
}

我们选定的具体组合是 L'Ecuyer 1996 的三分量组合 Tausworthe「taus88」与 Press 等 1992 的 32 位「Quick and Dirty」LCG，如代码清单 37-4 所示。两者在各自的生成器家族中统计质量都相对较好，组合起来则消除了我们在各单独生成器中观察到的全部统计缺陷。该生成器的状态由四个 32 位值组成，总体周期约为 2121。对初始状态的唯一限制是三个 Tausworthe 状态分量应大于 128；除此之外，四个状态分量可初始化为任意随机值。每个线程应收到一组不同的四个状态值，这些值应互不相关，为方便起见可用 CPU 侧的随机数生成器提供。若将使用整个随机流的相当一部分（例如超过 264），可以用跳流来推进四个状态分量，保证随机流相互独立；不过这种情形超出本章范围。

示例 37-4. 把 LCG 与 Tausworthe 组合成改进的生成器


unsigned z1, z2, z3, z4;
float HybridTaus()
{
  // 合成周期为 lcm(p1,p2,p3,p4) ~ 2^121
   return 2.3283064365387e-10 * (              // 周期
    TausStep(z1, 13, 19, 12, 4294967294UL) ^  // p1=2^31-1
    TausStep(z2, 2, 25, 4, 4294967288UL) ^    // p2=2^30-1
    TausStep(z3, 3, 11, 17, 4294967280UL) ^   // p3=2^28-1
    LCGStep(z4, 1664525, 1013904223UL)        // p4=2^32
   );
}

KISS

另一个广受推崇的混合生成器是 Marsaglia 的 KISS 家族（L'Ecuyer 2006）。它们组合三类不同的生成器：一个 LCG、一个类似 Tausworthe 的移位型生成器，以及一对带进位乘法生成器。这个生成器虽然统计质量也好，但需要大量 32 位乘法，在当代硬件上损害性能（NVIDIA 2007，6.1.1.1 节），只有 Tausworthe 八成左右的性能。

37.2.3 高斯变换的类型

现在我们转向从均匀分布到高斯分布的变换。同样，由于高斯分布如此重要，可选的技术很多。

Ziggurat 方法

软件中最快的方法是ziggurat 方法（Marsaglia 2000）。这个过程用一套复杂的办法把高斯概率密度函数切成轴对齐的矩形，设计目标是让生成一个样本的平均代价最小。但这也意味着对 2% 的生成数必须走更复杂的路径，使用更多均匀样本和函数调用。在软件中这可以接受，但在 GPU 上，慢路径的性能会影响一个 warp 中的所有线程，哪怕只有一个线程走这条路。若 warp 大小为 32、走慢路径的概率为 2%，则任一 warp 走慢路径的概率是 (1 - 0.02)32，即 47%！因此由于线程成批执行，ziggurat 设计中所作的假设被破坏，性能优势也随之消失。

极坐标方法

许多其他方法同样依赖类似 Ziggurat 的循环行为，因此在硬件上也不可用。极坐标方法（Press 等 1992）简单且效率相对高，但每个线程需要循环的概率为 14%。这导致每个生成样本的期望迭代次数从 1.6 次变成计入 warp 影响后的 3.1 次。

Box-Muller 变换

由于 GPU 对循环和分支如此敏感，结果高斯变换的最佳选择其实是古老的 Box-Muller 变换，其代码见代码清单 37-5。它取两个均匀样本 u0 和 u1，用下列关系把它们变换成两个高斯分布样本 n0 和 n1：

示例 37-5. Box-Muller 变换


float2 BoxMuller()
{
  float u0 = HybridTaus(), u1 = HybridTaus();
  float r = sqrt(-2 log(u0));
  float theta = 2 * PI * u1;
  return make_float2(r * sin(theta), r * cos(theta));
}

Box-Muller 做法在软件中基本被弃用，尤其是因为它对产生的每个样本都要计算正弦和余弦。不过对线程成批执行的 GPU 实现，它有几项重要优势，最明显的是没有分支也没有循环：只有一条代码路径。它也不需要任何查表，或某些方法中那样大量的常量。它的计算负载仍然相当高，但幸运的是这正是 GPU 擅长的：直线代码，塞满数学运算。此外，我们的结果表明 GPU 上的高速正弦和余弦函数能给出令人满意的结果，在很大程度上抵消了 Box-Muller 做法的性能劣势。

37.2.4 Wallace 高斯生成器

Wallace 高斯生成器（Wallace 1996，Brent 2003）是一种新颖的方法，能直接生成高斯样本，无需先使用均匀生成器。核心思想是取一个由 k 个已服从高斯分布的随机数构成的池，对池施加一个变换，产生另一个同样服从高斯的池。每次变换之后就可以输出该池来提供随机数。关键要求是让变换的输出尽可能与输入不相关，同时仍保持分布性质。

理想情况下，每个新池都通过对前一个池施加不同的 kxk 正交矩阵得到。正交矩阵是保持池中平方和不变的矩阵；换句话说，若把输入池看作一个 k 维向量，正交矩阵会保持该向量的欧氏长度。正交矩阵的常见例子有单位矩阵，以及反射、旋转这类保持尺寸的仿射变换。

不过这里有个计算问题：生成一个随机 kxk 正交矩阵非常昂贵——比用传统技术只生成 k 个高斯分布的数要贵几个数量级。因此采用的做法是用许多小得多的正交变换来构造正交变换，例如使用 2x2 正交矩阵，即二维旋转。施加 k/2 次二维旋转会保持整个 k 向量的长度，但实现起来便宜得多。缺点是各遍之间的混合程度低得多：用完整的 kxk 矩阵时，新池中的每个值都可受旧池中每个值影响；而若用 2x2 矩阵，新池中的每个值至多依赖旧池中的两个值。

有两种技术可以缓解混合不足。第一种是在施加分块变换之前对池做随机置换，这样经过足够多遍之后，新池的每个元素都会依赖于前一个池的所有元素。第二种只是在使用池输出数之前对池做多次变换。两种方法都有缺点，因为建立完整的随机置换很昂贵，而执行多遍显然更费时间。实践中常把两者结合：执行少量遍数，并在每一遍对池做某种程度随机的置换。

置换池

把 Wallace 算法映射到 GPU 上有若干挑战。最重要的要求是随机置换必须足够随机。测试中我们发现置换的质量是产生高质量随机数的关键因素：使用简单的非随机置换产生的随机数无法通过统计检验。基于这些测试，我们认定产生随机置换远比减少 bank 冲突重要，因此设计算法时可以忽略冲突。

对置换唯一的关键要求是它必须确实是置换。一遍之内任何池值都不能被读取两次（因而从逻辑上讲，任何池值也不能被忽略）。在读取阶段，每个线程必须从 k 个样本的池中读取 d 个样本。于是我们可以把问题定义为建立从 1..k→ 1..dx 1..k/d 的随机映射。前面我们提到过 LCG，它提供了在 [0,m) 范围内指定最大周期生成器的方法。若取 m =k/d，就可以用它作为高质量随机置换的基础。

我们已经有一个每线程唯一的值：线程 id，其取值在 [0,m) 内。现在若把线程 id 送入一个模 m 的 LCG，每个线程仍然有唯一标识符，但顺序已被伪随机地改变。注意这个 LCG 提供的统计质量低；不过我们发现，在这个上下文中质量低并不是问题。再施加一次 LCG 会得到新的映射，但每个线程在 [0, m) 范围内仍有唯一标识符。地址置换与分块正交变换的结合构成了变换过程的基础。当我们把单个 Wallace 变换步与一个循环结合起来，在整体可见的变换中执行反复的内部变换时，就得到代码清单 37-6 的代码，其中 TransformBlock 对数据执行矩阵运算，此处用的是 Walsh-Hadamard 矩阵（Wallace 1996）。

__device__ void TransformBlock(float *b)
{
  float t=(b[0]+b[1]+b[2]+b[3])/2;
  b[0]=b[0]-t;
  b[1]=b[1]-t;
  b[2]=t-b[2];
  b[3]=t-b[3];
}

初始化池

随机数池的初始化必然是与 Wallace 生成器本身分离的过程，因此需要独立的随机数生成器。这个初始化可以在 CPU 上完成：例如把 ziggurat 方法与梅森旋转配合使用。尽管这个生成器不如基于 GPU 的 Wallace 生成器快，但它只需为 Wallace 池提供种子值；线程一旦开始执行，就不再需要新的种子值。事实上软件可以利用这一点，在 GPU 线程使用上一组种子值工作时生成下一组种子值。

Wallace 的随机数生成思路相比其他做法有两大优势：

  1. 直接生成正态分布的值
  2. 状态池可以完全并行地操作，从而充分利用处理器本地的共享内存资源

把 Wallace 与仿真集成时，我们开始看到局限。若仿真需要大量共享内存，Wallace 方法可能不适合集成，因为它同样有共享内存需求。当然，它仍可以输出到全局内存，让仿真读取这些数据，如前所述，但性能很可能更低。我们还会看到可用寄存器数量的限制，因为把 Wallace 变换与仿真循环结合后计算复杂度更大，寄存器需求随之增加。减少同时运行的线程数是这个问题的一种解法；由于计算中算术占比很高，集成 Wallace 生成器后线程数较低，未必构成严重的性能限制——集成带来的好处超过线程数低的弊端。

37.3 应用示例

为评估上一节的想法，我们现在看两个不同的蒙特卡洛仿真内核。两者都用于期权定价，但计算特性以及（尤其是）存储特性不同。两个算法的目标都是给期权定一个价格，期权简单说就是一方可以选择行使（也可以不行使）的合约。例如合约可以这样写：「两个月后，甲方有期权以 50.00 美元从乙方买入 1 股 S 股票。」这里我们把 50.00 美元称为期权的行权价，股票 S 是标的，因为期权以它为基础。

这份合约对甲方显然有非负的货币价值：若两个月后股票 S 的交易价高于 50.00 美元，甲就可以行使期权，以更便宜的价格从乙买入股票，再立刻在公开市场上卖出。若交易价低于 50.00 美元，甲选择不行使期权，于是既无盈利也无亏损。乙方的问题是在现在、即把期权卖给甲方时，考虑合约所有可能的结果，为合约定价。

最常用的股票模型是对数正态随机游走，它假设股票价格的百分比变化服从高斯分布。这保持了股票的两项最重要特征：价格永不为负，且股价波动的幅度与股价的幅度成正比。在这个模型下，乙方可以估计股票 S 价格的概率分布，并尝试估计自己在期权上的期望损失。这个期望损失随后决定了乙应向甲出售期权的价格。

这类简单期权可以用多种方式定价：闭式 Black-Scholes 定价公式、有限差分方法、二叉树，或蒙特卡洛仿真。在蒙特卡洛定价仿真中，期望损失通过为 S 在两个月后生成成千上万个可能价格来估计，所用的是从对数正态分布中抽取的随机样本。所有这些可能股价上的平均损失就作为期权的价格。更技术性的细节与基础理论见 Wilmott 2006；期权定价的 GPU 实现见 Colb 和 Pharr 2005。

不过也存在比简单看涨（买入期权）和看跌（卖出期权）复杂得多的期权，通常称为奇异期权。它们可以针对多个标的指定复杂的收益函数，由甲方为对冲某组特定市场情形而构造，再由乙方作为一次性合约卖出。这类期权的价格往往无法找到任何闭式解，而合约的多资产性质又使二叉树和有限差分方法不实用。于是对许多奇异期权定价来说，蒙特卡洛仿真成了唯一可行的选择。

37.3.1 亚式期权

第一个应用是一份基于两个标的最大值的亚式期权（Wilmott 2006）。亚式期权用标的的平均价格来确定最终行权价，因此价格既取决于标的最终走到哪里，也取决于它走过的路径。这里我们考虑一份基于两个标的之最大值的期权，标的价格服从对数正态随机游走，且相关性结构已知。注意我们忽略折现等一些细节，只关注计算。

__device__ float AsianBasket(unsigned T, float A_0, float B_0, float MU_A,
                             float SIG_AA, float MU_B, float SIG_AB,
                             float SIG_BB)
{
  float a = A_0, b = B_0, s = 0, sum = 0;
  for (unsigned t = 0; t < T; t++)
  {
    float ra = RNORM();
    float rb = RNORM();
    a *= exp(MU_A + ra * SIG_AA);
    b *= exp(MU_B + ra * SIG_AB + rb * SIG_BB);
    s = max(a, b);
    sum += s;
  }
  return max(sum / T - s, 0);
}

// (MAX_T%WARP_SIZE)==0
const unsigned MAX_T;
__device__ float LookbackDiff(unsigned T, float VOL_0, float EPS_0, float A_0,
                              float A_1, float A_2 float MU)
{
  __shared__ float path[NUM_THREADS * MAX_T];
  float vol = VOL_0, eps = EPS_0;
  float s = S0;
  int base = __mul24(tid, MAX_T) - NUM_THREADS;
  // 随机选择一条资产路径。
  for (unsigned t = 0; t < T; t++)
  {
    // 保存当前资产价格。
    base = base + NUM_THREADS;
    path[base] = s;
    // 计算下一次资产价格。
    vol = sqrt(A_0 + A_1 * vol * vol + A_2 * eps * eps);
    eps = RNORM() * vol;
    s = s * exp(MU + eps);
  }
  // 回看路径以求出收益。
  float sum = 0;
  for (unsigned t = 0; t < T; t++)
  {
    base = base - NUM_THREADS;
    sum += max(path[base] - s, 0);
  }
  return sum;
}

在亚式期权的情形中，我们看到 Wallace 发生器相对 Tausworthe/Box-Muller 发生器只带来 1.06 倍的有限提升。这种相对变慢看起来源于 Wallace 代码与仿真内核代码之间的相互作用，可能是寄存器分配冲突造成的。即便如此，其性能仍是软件实现的 59 倍。

在回望期权的情形中不能用 Wallace，因为共享内存要留给仿真内核，性能也远低于亚式期权。有意思的是，软件实现表现出相反的性能：回望期权明显比亚式期权快。不过，用 GPU 而不是基于 CPU 的方案能获得 23 倍的速度提升。

37.4 结论

现代 GPU 硬件完全有能力用于金融仿真。本章讨论了为这类仿真生成随机数的方法。统计分析表明，Wallace 方法在保持高质量随机数的同时提供了不错的性能。由于资源限制，权衡是必要的，因此 Wallace 方法并不适合所有情形。这些权衡在多数情形下应当是可管理的，而用 CUDA 与 GPU 硬件做金融仿真在未来应是一个可行的选项。
