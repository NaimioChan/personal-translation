第 33 章　基于 CUDA 的碰撞检测 LCP 算法

Peter Kipfer
Havok

物理行为正确的环境是电脑游戏沉浸体验的核心。有些游戏甚至要求玩家以某种方式与场景中的物体交互，而这正是通关的关键。因此物理仿真已成为游戏开发者不可或缺的软件组件。开发游戏物理的主要挑战是把仿真占用的处理器资源降到最低，因为可用资源早已被游戏 AI、资源管理、动画和图形预处理大量占用。更麻烦的是，这些组件都依赖物理世界的一致表示，并严重依赖能从中查询信息。

本章我们用 CUDA 加速凸体碰撞检测，并研究 Lemke 算法（也称互补枢轴算法）（Lemke 1965）求解线性互补问题（LCP）的并行实现。LCP 的重要应用包括线性与二次规划、两人博弈、边值问题，以及求平面内点集的凸包。该算法的并行版本最早由 Thompson（1987）提出，在处理器数量较少时接近线性加速。

33.1 并行处理

加速特定仿真所需计算的自然做法，是把工作分给多个处理器。现代计算机系统有多个可编程单元。如今的主 CPU 具备多个执行核心，而图形硬件上的专用并行算法已成为高响应性仿真的重要构件。

并行计算的文献浩如烟海。CUDA 提供的环境具备多 CPU 计算机上常用的许多并行化特性。因此值得考察现有并行算法能否在当前这一代 GPU 上高效运行。这将使我们有可能在处理单元之间动态转移负载——上一代 GPU 因功能受限，这件事还很麻烦。NVIDIA 当前这一代 GPU 已从相当僵硬的四分量向量处理器，转变为带多个 SIMD 多处理器的标量架构。GPU 在访存模式上仍然很有特殊性。并行 CPU 线程通常通过主存通信，而当前这一代 GPU 把共享内存块挪到更靠近 ALU 的位置。这影响了高效算法所需的通信与同步粒度。因此现有并行算法必须针对这一变化做调整。

本章在物理仿真的语境下，考察新的 CUDA 编程环境为高级求解器技术带来的机会。所涉及的数值计算在上一代 GPU 上并不是主要问题，但访存寻址缺乏灵活性与输出带宽受限，使许多算法无法在 GPU 上高效运行。CUDA 环境解决了这些问题，并提供对并发处理至关重要的额外特性：线程同步，以及线程共享与线程私有的存储。这些增强使我们能把一类此前无法实现的算法搬到 GPU 上：多线程协作式并行程序。

33.2 物理管线

刚体物理的处理管线通常分为三大块：粗筛阶段、精筛阶段和求解阶段。每个阶段各有要解决的具体任务，且需要对参与仿真的物体有不同的视角。

粗筛阶段做粗略而快速的检查，判断哪些物体可能发生碰撞，输出潜在碰撞对列表。为便于快速比较，使用非常简单的数据结构，如包围球或轴对齐包围盒，见图 33-1a。此外，一般的认识是：多数情况下物体每个仿真时间步的位移相对于其包围盒尺寸很小。能利用这种连贯性的算法已有很多（例如 sweep-and-prune）。

精筛阶段拿到碰撞对列表，对每一对用其实际几何判断两个物体是否相碰。这个阶段可以任意复杂，因此在实时物理仿真的语境下，参与碰撞的形状通常限于凸体。对非凸形状，只用其凸包做碰撞检测。多数情况下这已足够——例如凹处很小，或者凹处位于本来就不希望游戏角色进入的部件，如飞船的排气管或其他无关位置。为提高碰撞质量与性能，可以把大的或凹的物体分解为若干凸块。因此一个游戏物体可能持有一套与显示几何不同的简化碰撞几何。本章研究一种确定两个凸体之间距离的精筛阶段算法。对图 33-1b 中的两个物体，检测到标有黄色星号的接触点，其位置被算出并与碰撞对一起存储。

最后，求解阶段根据精筛阶段的结果计算力，在每个接触点把互相穿透的物体推开。由于一个物体可能与多个物体相碰，必须妥善处理多重接触。

得到的接触力与速度（在图 33-1c 中以绿色箭头表示）连同物体属性（如惯量）一起代入刚体运动公式，对物体做时间积分。

33.3 确定接触点

关于确定接触点的问题，文献数量极大。算法可分为两大类。第一类把从时刻 t 0 到 t 1 寻找接触点看作时间的单一连续函数，基本问题是确定首次接触的时刻。第二类则离散地看待这个问题，考察一系列时间增量 t 0 < t 0 + 1 < t 0 + 2 < . . . < t 0 + n < t 1。此时给定各物体在时刻 t 0 + i 的位置，就要检验物体是否互相穿透。图 33-2 比较了这两种做法。下面的连续做法可以解析地考虑物体从 t 0 到 t 1 的扫掠体与场景中其他物体的相交，从而解出首次接触时刻 ∂0。而离散做法在这种情况下只检查三个位置上的重叠。

33.3.1 连续方法

第一类做法假定物体在一段时间内的运动是给定的。文献中已描述过用（低阶）多项式的根来确定角速度恒定的刚体多面体首次碰撞的算法。但对刚体凸多面体任意轨迹的一般情形，首次接触时刻不存在闭式解，只能用迭代数值方法确定。

由于连续方法假定物体随时间的运动路径是给定的，它们无法全局地解决接触点问题，因为这样的路径恰恰是仿真器想要算出来的。不过在适当短的时间区间内使用，它们能保证不遗漏物体间的碰撞——而图 33-2 中的离散方法就会漏掉。这些连续方法，尤其是基于区间分析的那些，实现复杂，目前不如离散方法快。

33.3.2 离散方法（基于连贯性）

第二类做法是对某一时刻的物体做几何分析，目标是以最优的渐近时间复杂度求解该问题的单个静态实例。这里最著名的算法是 Gilbert-Johnson-Keerthi 距离算法，它计算含 n 个顶点的凸多面体之间的最小距离。该算法的复杂度在 O(n) 与 O(n log n) 之间，取决于其中是否含稳定性优化。至于判断两个含 n 个顶点的凸多面体是否不相交（不考虑二者的距离），有一个基于线性规划的更简单的 O(n) 算法。

遗憾的是，小的渐近时间复杂度是以大的运行时常数为代价的。不过这些算法很适合并行处理。本章我们用 CUDA 开发这样一套并行解法。

33.3.3 求解接触点

确定物体何时何地相互接触之后，我们需要施加非穿透约束。对无摩擦的接触物体，防止互相穿透有两种基本做法。第一种也叫惩罚方法，它在每个接触点上、两个接触物体之间放置一个带阻尼的弹簧来建模接触。接触点处允许物体互相穿透，但随着穿透量增加，物体之间会产生排斥性的恢复力（惩罚力），把它们推开。惩罚方法是很有吸引力的模型，因为实现极简单、数值上也简单。尤其是，在上一代硬件上利用并行性做 GPU 实现相当直接。

第二种做法计算约束力，使这些力恰好抵消任何会导致穿透的外加加速度。该方法需要求解非线性方程组。本章开发的 CUDA 求解器可用于计算这类力。它使仿真中的互相穿透被完全消除（在数值容差范围内）。

33.4 数学优化

33.4.1 线性规划

来看一个简单的优化问题。我们想知道两个二维多边形是否相交。考虑图 33-3 中取自 Ericson 2005 的两个三角形。每个三角形的内部都可描述为其各边所定义半空间的交集。

三角形 A 由以下三个半空间方程描述：

-u + v ≤ -1，-u - 4v ≤ -1，4u + v ≤ 19

三角形 B 则给出如下：

- 4u + v ≤ 0，u - 4v ≤ 0，u + v ≤ 5。

用矩阵记号，这给出不等式约束 Ax ≤ b 和待最大化的目标函数 c T x，其中 c 是常量向量。由于同时属于两个三角形的任何点都是它们碰撞的见证，目标函数可以任选，例如 c = (1, 0, . . ., 0)。要用单纯形算法求解该系统以最大化 x，我们引入松弛变量 s 把不等式变成等式——也就是说，对分量 i 与向量 x 上的不等式 Ai xi ≤ bi ，我们写成 Aixi + si = bi 。于是松弛变量 s 取差值使等式成立。对这个简单情形，直接解法甚至穷举测试半空间可能更快，但这里给出的思路足够通用，可支持任意凸多面体。这对物理引擎很重要，以便在仿真中对任意物体之间做查询。

给定的线性规划问题回答的是两个物体是否重叠。因此一旦检测到重叠，物理仿真实际上处在刚体互相穿透的非法状态。这必须避免，所以我们希望能对分离的物体做距离查询。然而用当前的做法无法回答这个问题。

33.4.2 线性互补问题

线性规划中一个重要观察是：每个最大化问题都有一个对偶最小化问题。强对偶原理指出，优化原问题或对偶问题都能得到相同的值。其推论是原问题与对偶问题的松弛变量相互关联（互补松弛性）。原问题的松弛变量向量是 s = b - Ax ≥ 0；对偶问题的向量是 u = A T y - c。由此可得出结论：只有当 xj = 0 或 uj = 0，或者 yi = 0 或 si = 0 时，我们才算找到了最优解。现在的思路是把原问题与对偶问题合并成所谓的互补问题。

33.6 用 CUDA 并行求解 LCP

从公式 3 的例子与 Lemke 算法的并行化可以立即看出，我们能对矩阵的枢轴运算做并行化。特别是，只要枢轴列可用，我们就能并发更新矩阵的各列。沿用 Thompson 1987 的做法，我们按行把矩阵 M 分给 CUDA 线程；也就是说，每个线程负责矩阵 M 的某一行。右端向量 q 对所有线程可见，并维护一份当前基本变量与非基本变量的列表。

每次迭代开始时，由互补枢轴规则确定枢轴列。每个线程独立地用最小比值检验算出枢轴行，并更新自己负责的那部分矩阵。这可以并行完成，因为每个线程都有右端向量 q 的更新副本，并能算出当前的枢轴列。为优化起见，枢轴列在多处理器的线程共享内存中计算。

33.6.1 求解器的实现

CUDA LCP 求解器有三项主要任务：

  1. 选择枢轴元素
  2. 求解选定的方程变量
  3. 检查是否终止

每个碰撞对都要算一个解，各解之间相互独立。因此我们把碰撞对列表映射到 CUDA 的计算网格上。每块的线程数等于 LCP 中的方程数。由于线程之间可以交流部分结果，LCP 方程可以由这些线程协作求解。图 33-4 给出处理流程概览。

为凸体距离计算建立特定 LCP 问题所需的方程数，取决于定义域的维数与半空间数量。两个点的距离每个维度一个方程，每条参与的半空间约束一个方程。对二维中两个三角形之间距离的计算，这相当于 2 x 2 + 3 + 3 = 10 个方程（见公式 3）。若参与的是任意多边形，约束数显然会变。不过要把整个碰撞对列表作为一个 CUDA 网格运行，各块的线程数必须相同。我们的处理方式是保存每块的方程数，让多余的线程空转。这比为每个块单独调用内核更高效，而且编程很容易，因为每个线程都知道自己的基数。注意这在上一代 GPU 架构上会非常难以解决。这种做法所需的线程数很快会达到相当大的规模，这在过去的多处理器机器实现中一直是个问题。对 CUDA 而言，这种做法却很理想，因为 GPU 就是为处理大量线程而优化的。要求解两个各含 60 个面的凸体之间的三维距离，需要 129 个线程，这对 CUDA 内核是个合理的线程数。处理凹物体的凸分解时，物体描述很容易变得更复杂。

因此整个网格可以由同一个内核覆盖。这是非常强大的特性，我们利用它把前面三个步骤的控制循环也实现在内核里。于是不需要读回任何中间状态。内核返回时，每个块要么已算出解，要么已把自己标记为不可解。第二步的实现负责生成连续的结果列表（见图 33-5 与 33-6），使我们能一次批量高效下载。

选择枢轴元素

下一个枢轴元素的选择由单纯形算法的最小比值检验决定。该检验指出，从基本集合中移除多项式的常数项与变量系数之比最小的那个变量，目标函数获得的改善最大。由于每个变量由矩阵的一行表示，这相当于检查所有行的比值并选出最小的一个。由于这里求解的是 LCP，我们还要根据方程的基/非基状态小心选取正确的互补变量。还需要处理人工变量 z 0 不是基本变量的特殊情况，这是求解器要做的第一步。实现时只需选取最小的（负）常数项。初始时至少有一个常数项为负，否则一开始就已经有解。若所有负常数项互不相同，就取常数项与 z 0 系数之比最小（负得最多）的那个方程。若有多个方程含最小的负常数项，则取系数最大的那个，因为它是多项式最高次幂的系数（这就是最小下标规则 [Bland 1977]）。

比值的处理提供了若干并行工作机会。图 33-5 展示了 CUDA 算法的处理路径。上一节所述的线程布局保证每个方程——也就是矩阵的每一行——都有一个线程可用。因此图 33-5 中的控制流在所有线程上并行执行。线程在三个主要代码块处同步。第一块确定 z 0 是否为基本变量，这决定随后的搜索。第二块并行地为每个变量构建有效系数列表。再次同步之后，所有线程都能访问关于方程组状态的相同信息，因为 z 0 的基本标志与有效候选都放在共享内存中。第三块则确定常数与变量系数之比最小的方程。然后，找到的枢轴变量被写回设备内存。由于这些信息在共享内存中算出，块内所有线程对 LCP 当前状态有一致的视角。

求解选定的方程变量

用 CUDA 并行求解选定变量很直接。同样，每个方程有一个线程可用。每个线程把枢轴列的一个元素带入快速的共享内存，同时读取自己的系数。这有效地利用了可用带宽。由于共享内存有限，这部分要对 z、w 和常数系数依次重复，见图 33-6。注意我们这样做并不是为了在线程间共享方程系数，而是因为对系数的修改涉及若干算术运算，而共享内存访问比在设备内存里操作快得多。这是相对此前 GPU 架构的巨大优势。

每个线程还生成替换方程（也就是要解出的那个变量），然后用正确的互补变量对自己的方程做枢轴运算。不过其中一个线程将充当枢轴行，它只需用算出的替换方程替换该行。

最后一步是检查是否已得到解。所有线程检查自己是否把 z 0 表示为基本变量。这些标志收集到共享内存中，经过一个同步点后，块内所有线程都知道这个 LCP 是否已解出。若是，则相应更新一个状态变量，向主机程序报告完成。注意我们的应用并不需要整个 z 向量，只关心构成解的点 P 0 与 P 1，因此把它们写入一个紧凑的解数组。对公式 3 中那个小的二维 LCP 问题，前四个条目就是两个二维解点（参见矩阵 M 的构造）。

33.7 结果

所提出的 LCP 方法对离散（基于连贯性）的接触点方法非常通用。它既能用于确定凸多面体的接触点，也能用于计算带约束的接触力。其矩阵本性特别适合高度并行的系统，可以高效映射到 GeForce 8800 架构上。

为考察 CUDA LCP 求解器的性能，我们使用 CUDA 的性能分析工具。表 33-1 给出在 GeForce 8800 GTX 上对若干凸物体类型测得的典型耗时分解。该 GPU 有 16 个多处理器，处理单元运行在 1350 MHz。每个仿真时间步都必须构建 LCP 矩阵 M，因为要算距离就需要物体的世界空间位置。物体在移动，所以平面不等式必须重算。接着，枢轴迭代在求解某个方程与确定下一个待解方程之间交替。理论上，这最多需要对每个方程做一次枢轴运算。由于数值精度，这个过程可能多迭代几次。不过实践中迭代次数大多远低于 M 的维数。
