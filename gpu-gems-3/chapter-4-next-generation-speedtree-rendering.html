4.1 引言

SpeedTree 是 IDV Inc. 出品的一个用于实时树木渲染的中间件包。使用 SpeedTree 的游戏在如何渲染 SpeedTree 上有很大的灵活性。我们讨论 GeForce 8800 的若干特性，它们使 SpeedTree 得以实现高质量、面向下一代的扩展。首先，轮廓修剪为枝条与树干的轮廓增添细节。其次，阴影贴图带来单叶级别的真实自阴影。此外，我们进一步用双面叶片光照模型与高动态范围（HDR）渲染改进光照。最后，多重采样抗锯齿配合alpha 转覆盖率提供很高的视觉质量，没有走样瑕疵。

4.2 轮廓修剪

树枝与树干是有机的、不规则的、复杂的。图 4-1 展示了一个真实案例：树枝大致呈圆柱形，但细节轮廓粗糙、不规则。中面数或低面数的树干网格，比如 1,000 个多边形，无法表现这种细节。结果就是笔直的多边形边缘，这是一个细微却重要的线索，让人看出眼前是计算机生成的图像。

有很多算法可以帮助表现图 4-1 中树枝所见的大量细节。其中最早、实现最广的是凹凸贴图。凹凸贴图能相当好地表现树枝的内部区域，例如图 4-1 中绿色方框内的区域。然而它完全无法处理蓝色方框标出的轮廓细节。它也无法表现观察者本应从树皮起伏深度中看到的视差。在凹凸贴图之上改进的是一对相关技术：浮雕贴图（Oliveira and Policarpo 2005）与视差遮蔽贴图（POM）（Tatarchuk 2006）。两种技术都沿物体表面做浅层射线追踪，可以加入视差与自遮蔽。（我们用浮雕贴图作为涵盖两者的统称。）用视差遮蔽贴图，效果仍局限于物体内部，轮廓不变。浮雕贴图提供若干扩展，其中一种支持轮廓，但需要额外的预处理才能启用。最后，也可以用模型剖分加置换贴图，但它们会带来可观的几何处理开销，在渲染整片森林的树时可能不值得。

我们的做法是在树干上使用浮雕贴图处理内部细节，再用额外一遍提供轮廓细节。这些都不受 SpeedTree 参考着色器支持，但由于其工具、文件格式与 API 允许额外的自定义功能（包括额外的纹理贴图），很容易加上。

对轮廓，我们采用一种称为轮廓修剪的技术。虽然它与 Sander 等 2000 描述的原始方法差别很大，但最终效果非常相似。我们的技术从物体轮廓沿垂直于视线向量的方向挤出鳍片。这些轮廓随后对高度图做类似浮雕贴图的射线追踪，以确定哪些像素实际上应被轮廓遮挡。与用在树枝多边形上的浮雕贴图一样，这项技术不需要额外的预处理工作。

4.2.1 轮廓鳍片挤出

渲染轮廓的第一步是挤出鳍片。我们用平滑的逐顶点法线来确定三角形内的轮廓边。如果顶点法线与视线向量的点积在某个三角形边上变号，我们就在该边上找到一个新的顶点，位置是插值后的视线向量与插值后的法线点积等于零之处。图 4-2 示意了该过程。

寻找轮廓与挤出鳍片可以直接在 DirectX 10 硬件上完成。我们在顶点着色器中计算顶点法线与视线向量的点积。随后，几何着色器比较这些点积的符号，并在点积等于零处构建两个三角形，如图 4-2c 与 图 4-2d 所示。由于这两个三角形以条带方式生成，几何着色器输出的顶点数最多为四个。如果点积在三角形内不变号，几何着色器就不输出任何东西。如果某个顶点法线恰好与视线向量正交，我们的计算会产生退化三角形。自然，我们不想浪费时间处理这类三角形，因此会检查这种情况，一旦发现三角形的两个位置相同，就不从几何着色器发出这个三角形。图 4-3 给出了中间输出的一个例子。

为保证轮廓沿线连续，算法需要平滑的逐顶点几何法线。这一要求与 SpeedTree 可选的「光缝削减」技术冲突——该技术把枝条法线从几何法线偏转开，以避免光照不连续。要同时支持两者，必须往顶点属性里加两套不同的法线。

4.2.2 高度追踪

鳍片挤出之后，我们用一张高度图来呈现细致的物体轮廓。这张高度图与主干网格三角形做浮雕贴图时用的是同一张，但轮廓鳍片需要更精细的高度图追踪算法。我们从顶点 V 0 与 V 1 挤出额外的几何，如图 4-4 所示。对这个鳍片，我们需要以下内容：

  • 切线基，用于计算漫反射光照
  • 顶点位置，用于正确地为鳍片投影阴影
  • 纹理坐标
  • 视线向量，用于高度追踪

顶点 V 2 与 V 3 的切线基与纹理坐标不必计算新值。V 2 的属性等于 V 1 的属性，而 V 3 的属性等于 V 0 的属性，尽管这在理论上并不正确。

图 4-5 演示了这如何工作。它显示出我们为每个顶点计算了不同的视线向量。在像素着色器中，我们先把鳍片上的纹理坐标（A 点）沿视线向量方向退一步加以修改（经过几何着色器后，视线向量位于切线空间）。我们把沿视线向量的距离钳制在实验得出的一个值以内，到达 B 点。B 点在不同片元上可能不同。之后，我们执行通常的浮雕贴图高度追踪搜索。如果找到交点，就为该片元计算漫反射光照与阴影。否则，该片元做抗锯齿处理（见 4.6.3 节）或被丢弃。

对轮廓鳍片，在高度图中的搜索会在纹理空间中走过更长的足迹，因为按定义，视线向量在轮廓处与网格以锐角相交。因此鳍片比主干多边形上的浮雕贴图需要更多线性搜索步。幸运的是，鳍片在屏幕着色像素数上总是很小，因此逐像素代价并不显著。我们还会把纹理空间中的搜索长度钳制在一个最大值以内，以进一步限制代价。图 4-6 展示了一个带有鳍片的圆柱。它说明鳍片是如何从简单几何挤出的。图 4-7 是同一个圆柱加上纹理后的样子。浮雕贴图结合轮廓，呈现出真实、令人信服的视觉效果。

虽然这里给出的算法效果极好，但它在很多方面只是冰山一角。我们的浮雕贴图依赖简单的线性高度图追踪。可以用 Policarpo 2004 那样线性与二分搜索的组合来改进，或用额外的预计算数据加速追踪算法（Dummer 2006，Donnelly 2005）。此外，还可以通过追踪额外的射线来计算自阴影。

4.2.3 轮廓的细节层次

即使有这些优化，也要注意大多数树并不需要轮廓。在远处，轮廓的视觉影响微不足道。由于它们确实消耗大量像素与几何周期，我们把远处树木的轮廓去掉。对每种树，都有一个过渡区间，在此期间轮廓的宽度（按世界坐标）随距离逐渐减到零，如图 4-8 所示。这样它们被去掉时不会跳变。实际上，在 4.7 节所示那样的典型场景中，可见轮廓的数量不超过十个。

4.3 阴影

树轮廓改进之后，我们接着提升阴影的质量。由于通用的阴影技术因游戏引擎而异，SpeedTree 开箱即用的阴影是离线预计算的、静态的——这是一种折中方案，好让 SpeedTree 能配合许多不同的引擎。这种做法有若干缺点：

  • 当树模型因风效而运动时，阴影动画仅限于纹理坐标的变换：拉伸、旋转等等。
  • 预计算的阴影不如动态阴影真实，尤其是投在树干上的阴影。
  • 叶片没有自阴影。

4.3.1 叶片自阴影

我们的第二个主要目标，是让叶片在叶卡内部看起来各自受阴影影响。（SpeedTree 同时使用平面叶卡与三维叶片网格；本节详述叶卡的自阴影。）叶片自阴影并不简单，因为叶卡是复杂三维几何的简化二维表示。叶卡总是转向朝向相机，因此它们都平行于视平面。图 4-9 展示了一棵带叶卡的树。在这个方法中，我们使用阴影贴图。（阴影贴图技术的介绍见 King 2004。）为了让阴影在视觉上更好看，我们改动了生成阴影贴图的过程与投影阴影贴图的技术。

我们为叶片生成阴影贴图的做法大体遵循标准渲染。叶卡转向朝向视点。渲染到阴影贴图时，它们转向朝向光源，因此是很好的阴影投射者。然而如图 4-10 所示，它们绕自身中心点旋转，这就带来一个问题。图中浅蓝色的叶卡转向观察者；绿色的叶卡是同一张叶卡，但此时转向光源。在图 4-10a 中可以看到，投影时绿色叶卡只会遮住蓝色叶卡的下半部分。为避免这种瑕疵，我们只需把绿色叶卡朝光源平移，如图 4-10b 所示。平移量是可调的任意值，约等于叶卡高度的一半。

叶卡的平面几何在应用阴影贴图时带来更严重的问题。把阴影贴图应用到平面叶卡上，阴影会沿二维叶卡拉成细长的条纹（见图 4-12）。只有光源接近视点时效果才好。

为了在叶卡上投射更真实、不出条纹的阴影，在应用阴影的那一遍里，我们沿视线方向平移用于阴影计算的位置。（注意我们并没有改动几何上被光栅化的位置——叶卡仍是二维矩形。我们只平移用于阴影计算的位置。）偏移系数存在一张纹理中，在同一张叶卡内部对每片叶子是均匀的。图 4-11 展示了生成的纹理。用这个新的叶片位置，我们把受阴影的像素投影到光照空间并采样阴影贴图。由于这一操作会独立地改动叶卡内不同的叶子，必须在像素着色器中完成。用于执行这些操作的函数详见代码清单 4-1。

示例 4-1. 应用带偏移的阴影贴图的像素着色器代码


float PSShadowMapFetch(Input In)
{
  // 设 In.VP 与 In.VV 为 float3；
  // In.VP - VS 输出的插值后顶点位置
  // In.VV - VS 输出的观察向量
  // OCT - 偏移系数纹理
  // SMPP - 阴影贴图像素位置
  // SMMatrix - 变换到阴影贴图空间
  float3 SMPP = In.VP + In.VV * tex2D(OCT, In.TexCoord).x;
  float3 SMCoord = mul(SMMatrix, float4(SMPP, 1));
  float SM = tex2D(SMTexture, SMCoord);
  return SM;
}

图 4-12 展示了两种偏移的结果。（除阴影项外，其他光照与颜色都已去掉，以突出阴影。）在图 4-12a 中可以看到两类瑕疵：一是阴影贴图沿二维叶卡垂直向下投影造成的竖直条纹；二是渲染阴影贴图时叶卡位置上的斜线。在图 4-12b 中，这些瑕疵被消除了。结果是细节丰富、自然的枝叶。在我们的实时演示中，单叶的自阴影会随树在风中摆动而变化。

4.3.2 级联阴影贴图

改进了树叶的阴影表现，可惜并没有让场景免于其他阴影贴图瑕疵。对广袤的室外场景，单张阴影贴图通常不够。级联阴影贴图（CSM）是一种常见技术，它把视锥分割成若干区域，为每个区域渲染一张单独的阴影贴图到不同纹理中来解决这个问题。（CSM 的描述见 Zhang et al. 2006。另见本书第 10 章「可编程 GPU 上的平行分割阴影贴图」，其中有更多关于阴影贴图的内容以及一项与 CSM 相关的技术。）

为降低 CPU 开销，不同级联以不同频率更新：

  • 最近的级联每帧更新。所有物体都渲染进去。
  • 第二级联每两帧更新。叶枝不渲染进阴影贴图。
  • 第三级联每四帧更新。只有叶片渲染进阴影贴图。

阴影贴图渲染完成后，我们有很多方式真正为三维世界投影阴影：

  1. 按阴影贴图渲染时的相同顺序渲染物体，并使用合适的级联。
  2. 从每个级联取像素并混合。
  3. 使用纹理数组，在像素着色器中选择合适的级联。
  4. 用视口把一个渲染目标分割成多张阴影贴图。

每种做法各有优劣。在 SpeedTree 中，我们选择了第二种。

4.4 叶片光照

光照在观察者的感知中起重要作用。最新版本的 SpeedTree 提供了在叶卡上做逐像素动态光照所需的全部数据，包括切线与法线贴图。另一种选择是，SpeedTree 中的叶卡可以使用只含漫反射光照的预计算纹理。细致的光照与阴影被预先烘焙进漫反射纹理。我们选择了第一种方案，因为它支持完全动态的光照环境。

4.4.1 双面光照

除了镜面反射光照的差异，我们还观察到叶子会随视点相对于光源的位置而呈现不同外观。图 4-13 展示了两张同一批叶子的照片，相隔几秒拍摄，光照条件相同，曝光等相机设置也相同。（仔细看病斑的褐色斑点，就能在两张照片中比对同一片叶子。其中一片叶子用红点标出。）当叶子被从背后照亮时，主要贡献不是反射光；照明的主要贡献来自透射光。光线穿过叶片时，其色调会略微偏向黄色或红色。

基于这一观察，我们实现了以下方案来模拟照明的双面特性：

  • 黄色叶色在像素着色器中生成，是一个分量为（Diffuse.g * 0.9, Diffuse.g * 1.0, Diffuse.g * 0.2）的 float3 向量。
  • 根据 µ - angle 的取值（即光线方向与视线向量之间的夹角），如 图 4-14 所示，我们在原色与偏黄的版本之间做线性插值。当 µ 接近 时就会发生插值，这意味着我们正对着太阳看；若树挡在眼前，树叶会显得略黄一些。

根据 µ 减小镜面反射分量，因为背面不应出现光反射。这种做法也许显得幼稚，但它让画面更好看。见图 4-15。

4.4.2 镜面反射光照

除了双面光照的调整，我们还修改镜面反射照明以增强真实感。首先，用常规镜面反射光照时远处的树容易闪烁，因此我们按距离衰减镜面反射光照。其次，我们观察真实树叶以获得更多线索。图 4-16 展示了一些典型的亮泽叶片，从中我们观察到三点。镜面反射主要被叶片沿其轴向分成两个平面的强烈分割所主导。相对于这两个平面的效果，叶脉等精细细节相当不重要。反射的镜面反射强度低：反射并不锐利，不像玻璃质材料那样。由于我们关心的是整棵树的尺度而非叶脉的建模，我们用这些观察来简化叶片镜面反射模型。为模拟轴向分隔，我们用一张较粗糙的 V 形法线贴图把叶片分成两半。最后，由于镜面反射贡献中细节过多常常导致闪烁，我们把纹理取数偏置到法线贴图较低的 mipmap 层级。最终结果是更平滑、更柔和的镜面反射光照，不会引入严重的光照相关走样。

4.5 高动态范围与抗锯齿

我们的 SpeedTree 演示实现了高动态范围与多重采样抗锯齿（MSAA）的结合。我们使用 GL_RGBA16F_ARB 格式的帧缓冲，并配合 GL_ARB_multisample 扩展。

高范围帧缓冲数值来自天空盒（一张 HDR 图像）与树的渲染。SpeedTree 支持过亮渲染。我们的演示对此做了调整，使其输出的值略微超出 [0, 1] 范围。

一个后处理滤波器用径向模糊给帧缓冲中的亮点加上「体积光」。除此之外，我们对 HDR 的用法并无新意。

4.6 Alpha 转覆盖率

alpha 转覆盖率把像素着色器输出的 alpha 值转换成覆盖率掩码，按 MSAA 渲染目标的子像素分辨率应用。做 MSAA 解析时，结果就是一个透明像素。对原本是 1 位透明度镂空的区域，alpha 转覆盖率能很好地做抗锯齿。

4.6.1 把 alpha 转覆盖率用于 SpeedTree

这种 1 位镂空在植被渲染中很常见，SpeedTree 对叶枝与叶片就使用透明纹理。我们对这些纹理应用 alpha 转覆盖率，图 4-17 展示了用在叶枝上的效果。应用 alpha 转覆盖率后，左图中的像素化和硬边大大减少。植被做动画时收益更大（SpeedTree 支持真实的风效），因为透明镂空的硬边容易闪烁。alpha 转覆盖率基本消除了这些闪烁瑕疵。与 alpha 混合不同，alpha 转覆盖率与顺序无关，因此叶片与叶枝不需要按深度排序就能得到正确的图像。

4.6.2 细节层次交叉淡化

不过有个问题。SpeedTree 参考渲染器把 alpha 镂空用于另一个目的：fizzle 细节层次（LOD）。一个位于 alpha 通道的噪声纹理配以变化的 alpha 测试参考值来应用。随着参考值变化，噪声纹理中通过 alpha 测试的部分多少不同。（更多细节见 Whatley 2005。）

为在 LOD 之间交叉淡化，会同时绘制两个 LOD 模型，使用不同的 alpha 测试参考值。fizzle 用 alpha 测试在像素级别产生交叉淡化。把 alpha 转覆盖率简单地和 fizzle LOD 一起使用时，各种问题都出现了（最明显的是树干变成半透明）。

幸运的是，alpha 转覆盖率也可以改造用来实现交叉淡化。alpha 转覆盖率并不能直接替代 alpha 混合：大面积半透明区域并不总是效果良好。特别地，alpha 转覆盖率不会像混合 alpha 那样累加。如果两个物体一前一后都以 50% 的 alpha 转覆盖率绘制，它们用的是同一个覆盖率掩码。得到的结果是通过深度测试的那个物体以 50% 透明度绘制。

我们通过错开两个 LOD 的 alpha 淡化曲线来解决这个问题。结果并不完美：在过渡过程中的某些时刻，整棵树仍比我们希望的要透明。但这个缺陷在实际中很少被察觉。图 4-18 展示了一棵正处于交叉淡化中途的树，使用 alpha 转覆盖率。

4.6.3 轮廓边抗锯齿

在我们的轮廓修剪算法中，高度追踪在像素着色器中执行。这意味着轮廓外形只按像素确定，而不是按采样点确定。由于可见边缘不再是几何边缘，标准的多重采样无法对可见边缘做抗锯齿。

可以用 alpha 转覆盖率来对轮廓边缘做抗锯齿。做法是在轮廓边缘生成一条窄窄的边界区域，让轮廓的不透明度在其中从实心渐变到全透明。

我们在几何着色器中把 1 或 0 存进视线向量的 W 分量。顶点 V 0 与 V 1 存 0，V 2 与 V 3 存 1，如图 4-19 所示。这个值会在鳍片上插值，代表平滑的高度变化。

在高度追踪过程中，我们记下相对于高度图的最小未命中量，并据此改变像素不透明度。我们对视线向量 W 分量取 ddx() 与 ddy() 来确定每像素的高度变化。之后，我们把最小未命中量（视线向量到高度图的追踪结果）与足迹比较，以线性函数确定像素 alpha。如果视线向量与树干高度图相交，alpha 值为 1.0。如果未命中，且最小未命中量在屏幕空间单位下小于约 1.5 个像素，就让 alpha 淡到 0。否则，alpha 设为 0。

图 4-20 展示了未做抗锯齿的轮廓，以及同一个轮廓应用我们的 alpha 转覆盖率边界后的效果。

4.7 结论

最后一节的图展示了用我们的技术得到的一些典型结果。它们把我们在 GeForce 8800 上用到的 SpeedTree 技术汇聚到一个高质量演示中。图 4-21 展示了我们的双面叶片光照模型与高动态范围效果相互作用。细致的树干轮廓也清晰可见。仔细看图 4-21 底部中央附近的树干，可以看到树干网格与轮廓之间有一些不连续的瑕疵。不过我们认为这些瑕疵很小，可以接受。

图 4-22 展示了轮廓修剪应用在一种很不一样的树干上：又高又细的树。注意轮廓的起伏与作用在树干网格上的浮雕贴图起伏配合得很好。轮廓在最细的树干上也有细微效果，例如图像最右边缘处。效果很微妙，但它打破了本来笔直的多边形边缘。光照与 HDR 效果也可见，所有树都表现出细致的自阴影。

图 4-23 展示了我们阴影的更近视图。前景的树在下方岩石上和自己的树干上投下准确的阴影，包括轮廓鳍片。随着树在 SpeedTree 风效下摇摆，这些阴影真实地移动。图像最右上角和中央的叶片表现出自阴影。这种表现在严格意义上并不准确，但很真实。光源几乎就在正上方。注意叶片阴影如何反映这一点：图像中央的叶簇顶部受光、底部在阴影中，中间有真实的斑驳光影。

还要注意级联阴影贴图的效果。图 4-23 的前景中可见极其细致的阴影。然而就在中央偏右，远处的树也投下阴影，一直到可视距离的极限。所有可见阴影都是动态生成的，随树的动画而移动。

这些图像表明，SpeedTree 的着色器可以很容易地大幅定制，远超标准参考实现。它们也表明，NVIDIA GeForce 8800 能够渲染质量极高、真实感很强的植被。
