第 5 章　通用的自适应网格细化

Tamy Boubekeur
LaBRI–INRIA, University of Bordeaux

Christophe Schlick
LaBRI–INRIA, University of Bordeaux

本章给出一个单遍的通用顶点程序，用于对任意拓扑的网格做自适应、即时的细化。从一个静态或动画的粗糙网格出发，该顶点程序把每个三角形替换为一个细化后的三角面片：它依据所需的局部几何细化程度，从存放在 GPU 内存中的一组预剖分模式中选出这个面片。由于这些模式以参数空间编码，这种一对多、即时的三角形替换就化为对顶点位移函数的简单重心插值，该位移函数由用户提供，或由已有数据算出。除了顶点位移，同一过程还能在细化过程中插值任何其他逐顶点属性。这个方法完全通用，对网格拓扑、位移函数与细化级别都不作任何限制。

这里给出若干示例应用，包括完全在 GPU 上实现：（1）用高阶 Bézier 面片做网格平滑，（2）用过程化位移函数合成高频几何，（3）动画自由变形，（4）保证着色与轮廓一致的标准置换贴图，（5）多级地形渲染，仅举几例。但这项技术几乎适用于任何依靠细化来可预测地生成几何的问题。

5.1 引言

网格细化是表现复杂形状三维物体的有力技术。与其枚举出为准确离散近似这样一个复杂形状所需的海量多边形，网格细化技术把表面表示拆成一个粗糙多边形网格加一个连续位移函数。随后在渲染时，对粗糙网格基本执行两个相继的操作：

  • 剖分，用于在所需细节层次上生成细化的网格拓扑
  • 位移，用于把每个新插入的顶点移到最终位置，位置由采样连续位移函数得到

更准确地说，剖分这一步的作用是把粗糙网格的每个多边形分成（可能极多的）一小组小三角形，但不做实际的几何形变。位移这一步的作用是沿位移函数给出的向量移动这些三角形的顶点，以加入小尺度几何细节。视这个函数而定，每个顶点的位移可以约束在其法线方向上，也可以沿任意向量进行。前一种方案更紧凑，在动画物体上也更易应用；后一种则能为给定的粗糙网格造出复杂得多的形状。常见的位移方法包括位图纹理（例如灰度高度场）与过程化三维纹理（例如 Perlin 噪声）。

许多已有的计算机图形技术都可以用这个范式表达，例如基于样条或小波的表面表示、细分曲面、层次高度场等等。不过用当前设备对整个两阶段过程做完整的 GPU 实现仍有困难。虽然传统顶点着色器能高效计算位移阶段，但 GPU 上缺少几何创建能力，使剖分阶段相当棘手。近来有几何着色器（Blythe 2006）被设计用于几何放大，但它有一个严重限制：最多输出 1,024 个浮点数，这意味着每个三角形上只能应用两三级细化。如果需要更深的细化，就必须采用多遍几何着色，这显然会降低整体性能。

相反，本章提出的顶点程序即使在落后三代的 GPU 上也能做到很深的、自适应的单遍网格细化。它基本上依靠重心坐标来做到一致、无裂缝的自适应剖分。这种即时网格细化实现的一大优势，是在 CPU 层面只需处理低分辨率网格，让 GPU 自适应地生成高分辨率的位移后网格。用我们的方法，目标网格从不在 CPU 上生成，从不在图形总线上传输，甚至从不存储在 GPU 上；唯一剩下的瓶颈是 GPU 的顶点处理能力。

5.2 概览

本章提出的通用自适应网格细化（GAMeR）技术具有以下特性：

  • 常见渲染 API 使用的标准几何表示（多边形汤或索引三角形集）可以原样使用，无需任何预处理（例如全局或局部参数化），也不需要细化技术常要求的那些额外数据结构（例如半边结构）。
  • 只有粗糙网格从 CPU 传到 GPU。GAMeR 唯一需要的额外数据是一个逐顶点的标量属性，称为深度标记，用来指示每个顶点附近所需的细节层次。注意这种深度标记既可以自动生成，也可以在用户监督下生成。
  • 由于网格细化是即时的、按帧/按三角形进行的，即使对动画网格也能得到任意的细节层次。
  • 整个两阶段的自适应网格细化（剖分与位移）由单个单遍顶点程序在 GPU 上完成，这完全把片元着色器解放出来，可用于加入额外的视觉增强。

GAMeR 使用的工作流架构见图 5-1。关键思路是：针对各种逐顶点深度标记，预计算单个三角形所有可能的细化配置，并用重心坐标编码。每种可能的配置称为一个自适应细化模式（ARP），一次性存放在 GPU 上，作为一个顶点缓冲对象。随后在渲染时，把粗糙网格每个多边形的属性以及位移函数的属性上传到 GPU（例如使用 uniform 变量），并根据深度标记选用合适的 ARP。最后，顶点程序利用 ARP 每个节点上存放的重心坐标，同时插值当前粗糙多边形的顶点与位移函数。第一次插值产生节点在多边形上的位置（剖分），第二次插值把节点移到最终位置（位移）。

5.3 自适应细化模式

在 GAMeR 的初始化步骤中，所有可能的 ARP 一次性算好，存进一个三维矩阵，称为 ARP 池，如图 5-2a 所示。该矩阵的一个元素 {i, j, k} 就是这样一个 ARP：三角形在其第一条边上细化到深度 i、第二条边深度 j、最后一条边深度 k。由于深度值按顶点存储，边的枚举顺序无关紧要。矩阵的对应对角线情形是均匀细化（所有边以相同深度细化）。其余情形都要处理自适应细化，因为每条边可能要求不同的深度。

为非均匀深度标记配置生成 ARP 的一种简单（但非最优）做法，是先把初始三角形均匀细化，直到达到三条边中最小的那个深度。然后在剩下那些边的邻域内，简单地分割边界三角形，使每条边达到正确的细化深度。图 5-2b 中上方那个模式，就是把这一简单算法用在 {3, 4, 5} 深度标记配置上得到的。要得到更接近等边的三角形，可以扩大自适应细化的支撑范围。图 5-2b 中下方那个模式给出了同一 {3, 4, 5} 配置的另一种拓扑。

5.3.1 实现

如前所述，ARP 的每个节点都用其重心坐标编码。这种做法极有价值的好处是：对给定的深度配置，只需一个模式，无论它在细化这一步将替换的粗糙三角形位置、朝向与形状如何。因此要注意，在顶点程序中，细化后顶点的重心坐标将取代通常的位置（gl_Vertex）。于是粗糙三角形的几何属性必须通过其他方式传递。对足够深的细化或较新的图形设备，从性能上看可以放心使用 uniform 变量。

ARP 是我们系统的核心结构。为在光栅化时获得最大性能，ARP 被编码为退化三角带的索引顶点缓冲，直接放在 GPU 内存中。此外，因为我们采用二进细化，每个细化级别实际上是前一级的超集，所以我们可以把几何与拓扑分开，进一步减小全局内存占用。一个顶点缓冲用来编码所有几何，即属于最深规则 ARP 的节点的重心坐标集合。然后，任一给定 ARP 的拓扑用索引缓冲编码，作为这个最大配置上的索引条带。于是渲染时唯一要做的操作，就是绑定所选 ARP 的索引缓冲，而顶点缓冲始终保持不变。

在受限条件下——例如 16 位精度的 PDA——这种编码允许每个粗糙三角形最高 256x256 的细化级别。在另一个极端，用现代 GPU，在过程化高频几何合成的场景中，我们已实测到每个粗糙三角形 1024x1024 细化时的实时性能。如果需要，还能轻松得到更高分辨率，因为我们的内核完全在物体空间中运行，不依赖屏幕分辨率。

5.4 渲染流程

5.4.1 深度标记

深度标记过程为控制输入粗糙网格的自适应细化程度提供了一种高效而灵活的方案。在 CPU 层面，应用提供一个逐顶点标量属性（在我们的实现中是正整数），指示每个顶点附近所需的细节层次。实际上，计算深度标记的常见选择包括相机到顶点的距离、局部曲率、物体的语义重要性、显著性，或这些值的任意组合。图 5-3 展示了 GAMeR 在同一粗糙网格上生成的两种不同网格细化：一种用基于距离的标记，一种用基于曲率的标记。

注意在某些特定情况下，深度标记也可以在 GPU 层面完成，用一次借助渲染到顶点缓冲功能的预备渲染遍。不过我们认为这通常不是好选择，主要有两个原因：

  • 深度标记是在粗糙网格上计算的，在 CPU 层面的开销很小。
  • 深度标记可能依赖多种准则，其中大多数在 GPU 层面不易获得。

深度标记完成后，把每个粗糙多边形的属性作为 uniform 变量上传，并用深度标记配置选取合适的 ARP 索引缓冲。注意在大多数实时三维引擎中，边并没有显式表示。因此我们按顶点计算深度标记，再简单地用两个相邻顶点的均值把它转成按边的深度标记。这确保了相邻三角形之间无裂缝的过渡。

5.4.2 CPU 层面的渲染循环

在 CPU 层面，应用只需维护逐顶点深度标记、从 ARP 池中绑定合适的索引缓冲并绘制它，如代码清单 5-1 所示。

5.4.3 GPU 层面的细化过程

顶点程序包含三个阶段：（1）剖分阶段，简单地插值粗糙三角形的顶点；（2）位移阶段，采样并插值连续的位移函数；（3）传统的着色阶段。在代码清单 5-2 中，我们对两个阶段都使用简单的线性插值，但也可以使用更高阶的插值，各属性的阶数还可以不同（例如顶点位置用线性插值，法线向量用二次插值）。

示例 5-2. GPU 上细化顶点程序的伪代码

const uniform vec3 p0, p1, p2, n0, n1, n2;
// 用户自定义的置换函数 float dispFunc(vec3 v) {. . .}
void main(void)
{
  // 用重心插值做剖分
  float u = gl_Vertex.y, v = gl_Vertex.z, w = gl_Vertex.x; // w=1-u-v

5.5 结果

本节给出若干用 GAMeR 制作的示例。它们大多使用简单的基于曲率与基于距离的深度标记。细化深度从 4 到 10（即从 16x16 到 1024x1024 个细化三角形）。在图 5-4 中，用三角 Bézier 面片做网格平滑，使用曲面 PN 三角形（Vlachos et al. 2001）或标量标记 PN 三角形（Boubekeur et al. 2005）来加入额外的锐利特征。此时在图形总线上传输的位移属性被减少到每个粗糙三角形几个 Bézier 参数。

图 5-5 展示了我们通用细化方法的另一个有趣特性：由于不需要对粗糙输入网格做任何转换或预处理，它可以实时做动画，同时始终保持一致地细化。

如图 5-6 所示，这种灵活性也保证了对任意拓扑表面的一致自适应细化。

我们细化内核的另一个应用是过程化细化。此时，复杂形状可以表示为配备了过程化函数的极简网格。这些函数可能包含非常高的频率，需要很深的剖分才能准确采样。示例见图 5-7。

借助顶点纹理，置换贴图也可以与我们的内核一起使用。图 5-8a 展示了一个地形渲染系统，用我们的内核以依赖视角的方式细化粗糙地面，同时用高度图对它做位移。图 5-8b 与 5-8c 展示了对一张扫描人脸做的位移细化。

一般来说，细化后尺寸与粗糙尺寸之比越高，整体性能越好。细化可以比等效的 CPU 实现快约三个数量级。用近来的 GPU 统一架构，顶点纹理取数可以非常高效地执行，这使得实时应用能够使用越来越多的置换贴图。于是我们的通用细化技术很适合节省 CPU 工作量、图形总线带宽与板上显存。表 5-1 展示了我们的实现在一块 NVIDIA GeForce 8800 GTX 上、对前面介绍的各个模型所得到的帧率。

总体而言，如果细化深度低而输入的 CPU 网格大，系统就受限于粗糙多边形属性的上传。在另一个极端，如果输入的 CPU 网格粗糙而细化很深，系统就只受 GPU 算力限制。例如，目标网格为一百万三角形时，输入 CPU 网格 65,000 个三角形得到的平均 GPU 细化深度为 2，渲染达到 38 帧/秒。CPU 网格为 4,000 个三角形时，平均 GPU 细化深度为 4，渲染达到 279 帧/秒。这使该系统对需要极深细化的应用特别有吸引力，例如 CAD 或科学可视化。

5.6 结论与改进

我们给出了一种高效的单遍顶点着色技术，用于实时自适应网格细化。当输入网格粗糙而细化很深时，这项技术尤其有意思。这项技术可以与几何着色器结合：用几何着色器处理浅细化（例如深度 1 或 2），然后切换到我们的内核做更深的细化。标记体系让我们的方法保持通用，只需加一个逐顶点属性就能把它集成进三维引擎。我们方法的杀手级应用显然是这样一个场景：粗糙的动态网格（例如动画的角色面部或软体）配上位移函数，CPU 上的应用只需维护粗糙网格，屏幕上就能有分辨率极高的物体。

这项技术可能的改进之中，可以提到使用分布不同的替代细化模式，以及实现真正的细分曲面——其中位移函数基于其参数形式而非递归定义。
