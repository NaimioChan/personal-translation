第 27 章　作为后处理效果的运动模糊

Gilberto Rosado
Rainbow Studios

27.1 引言

在电子游戏里模拟速度感，最好的办法之一是用运动模糊。运动模糊可以是游戏中最值得加入的效果之一，尤其是赛车游戏，因为它增强真实感和速度感。运动模糊还能让游戏画面更平滑，对以每秒 30 帧或更低帧率渲染的游戏尤其如此。不过，为已有引擎加入运动模糊支持可能很有挑战，因为多数运动模糊技术都需要把场景单独渲染一遍，以生成逐像素的速度缓冲。这种多遍做法有局限：许多应用无法承受把场景再送过整个图形管线一遍，同时还要达到目标帧率。

生成逐像素速度图的其他办法包括使用多渲染目标，把速度信息输出到其中一个渲染目标。这个策略的一大缺点是需要改动场景的所有着色器，加上计算速度并把它输出到第二个渲染目标的代码。另一个缺点是，在某些平台上渲染到多个渲染目标可能降低性能。此外，一些平台渲染内存有限，在 1280x720 或更大的帧缓冲上使用多渲染目标需要瓦片机制。

本章介绍一种技术：把深度缓冲作为纹理输入送入像素着色器程序，以生成场景的速度图。像素着色器程序利用深度缓冲中存储的深度值，结合当前帧的视图投影矩阵，算出每个像素的世界空间位置。确定该像素处的世界空间位置之后，我们可以用上一帧的视图投影矩阵对它做变换，再计算当前帧与上一帧在视口位置上的差，从而得到逐像素的速度值。然后以该速度向量为方向，在帧缓冲上多次采样，一路求平均，就能得到运动模糊效果。

我们这个技术的优点是可以作为后处理步骤执行。因此它很容易集成到已有引擎中，只要硬件支持把深度缓冲当作纹理采样。

27.2 从深度缓冲提取物体位置

渲染物体并把深度值写入深度缓冲时，三角形三个顶点经世界-视图-投影矩阵变换后，深度缓冲中存储的值是三角形插值后的 z 坐标除以插值后的 w 坐标。把深度缓冲当作纹理，用当前视图投影矩阵的逆变换该像素处的视口位置，再把结果乘以 w 分量，就能提取出已渲染到深度缓冲的物体的世界空间位置。我们把视口位置定义为像素在视口空间中的位置，即 x、y 分量在 -1 到 1 范围内，原点 (0, 0) 位于屏幕中心；该像素在深度缓冲中存储的深度成为 z 分量，w 分量置为 1。

把给定像素处的视口空间位置记为 H，就可以说明这一做法如何实现。设 M 为世界-视图-投影矩阵，W 为该像素处的世界空间位置。

代码清单 27-1 中的 HLSL/Cg 代码在全屏后处理像素着色器中使用前面的公式，借助深度缓冲和当前视图投影矩阵的逆，计算给定像素处已渲染物体的世界空间位置。

示例 27-1. 提取已渲染到深度缓冲的物体逐像素世界空间位置的着色器代码


// 取此像素处的深度缓冲值。
float zOverW = tex2D(
    depthTexture,
    texCoord); // H 是该像素处的视口位置，范围 -1 到 1。
float4 H = float4(texCoord.x * 2 - 1, (1 - texCoord.y) * 2 - 1, zOverW,
                  1); // 用视图投影矩阵的逆进行变换。
float4 D = mul(
    H, g_ViewProjectionInverseMatrix); // 除以 w 得到世界位置。
float4 worldPos = D / D.w;

确定世界空间位置后，我们可以用上一帧的视图投影矩阵对它做变换，求屏幕位置的差，从而计算像素速度，如代码清单 27-2 所示。

示例 27-2. 计算决定图像模糊方向的逐像素速度向量的着色器代码


// 当前视口位置
float4 currentPos =
    H; // 用世界位置，并以上一帧的视图投影
// 矩阵进行变换。
float4 previousPos =
    mul(worldPos,
        g_previousViewProjectionMatrix); // 转换为非齐次点
// [-1,1]：除以 w。previousPos
// /= previousPos.w; 用当前帧
// 的位置和上一帧的位置
// 来计算像素
// 速度。
float2 velocity = (currentPos - previousPos) / 2.f;

获取深度缓冲作为纹理使用的方法因平台而异，也取决于所用的图形 API。Gilham 2006 讨论了一些把深度缓冲作为纹理访问的细节。如果目标硬件不支持把深度缓冲当纹理采样，可以用多渲染目标生成深度纹理，把深度输出到单独的渲染目标，或把深度值输出到颜色缓冲的 alpha 通道。

27.3 执行运动模糊

拿到像素速度之后，我们就可以沿该方向在颜色缓冲中采样，累积颜色值得到运动模糊后的值，如代码清单 27-3 所示。

示例 27-3. 用当前像素的速度向量多次采样颜色缓冲以实现运动模糊效果的着色器代码


// 取此像素处的初始颜色。
float4 color = tex2D(sceneSampler, texCoord);
texCoord += velocity;
for (int i = 1; i < g_numSamples; ++i, texCoord += velocity)
{
  // 沿速度向量对颜色缓冲采样。
  float4 currentColor = tex2D(sceneSampler, texCoord);
  // 把当前颜色累加到颜色和中。
  color += currentColor;
} // 对所有采样取平均，得到最终的模糊颜色。
float4 finalColor = color / numSamples;

该技术的实际效果见 图 27-3。注意靠近观察者的地形比远处的地形模糊得多。

27.4 处理动态物体

该技术对静态物体效果完美，因为它只考虑相机的移动。不过，如果需要更准确地记录场景中动态物体的速度，我们可以另外生成一张速度纹理。

要为刚体动态物体生成速度纹理，用当前帧和上一帧的视图投影矩阵分别对物体做变换，再像后处理那一遍那样计算视口位置的差。这个速度应当逐像素计算：把两个变换后的位置都传入像素着色器，在那里求速度。DirectX 9 SDK 的运动模糊示例描述了该技术（Microsoft 2006）。

27.5 遮掉物体

视应用而定，你可能想遮掉场景的某些部分，使它们不接收运动模糊。例如在赛车游戏中，你可能希望所有赛车都保持清晰细致而不是模糊。一个简便做法是把掩码渲染到单独的纹理或颜色缓冲的 alpha 通道，再用该掩码决定哪些像素应当模糊。

27.6 后续工作

这种基于场景深度缓冲计算场景中物体世界空间位置的技术非常有用。我们可以用它实现其他图形效果：景深就是一个很适合该技术效果，Gilham 2006 中有描述；场景雾也可以借助深度缓冲作为后处理步骤实现。

27.7 结论

本章讨论了利用深度缓冲中存储的深度值获取物体世界空间位置的方法，并展示了如何以该信息为基础在游戏引擎中实现运动模糊。把运动模糊主要实现为后处理效果，使它容易集成到已有的渲染引擎中，同时性能优于传统的多遍方案。
