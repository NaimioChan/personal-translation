第 6 章　GPU 生成的过程化树木风动动画

Renaldas Zioma
Electronic Arts/Digital Illusions CE

本章介绍一种过程化方法，为受风场影响的树木合成可信的运动。该方法的主要目标是能对包含大量植被的大范围开阔环境进行仿真与可视化。把过程化的动画计算放进顶点着色器之后，这种方法与实例化配合良好，并能发挥 GPU 的威力。

6.1 引言

风是营造可信、悦目植被效果的重要元素。在风场中模拟树木运动是一个复杂的科学课题。多数科学做法使用基于运动方程的物理仿真技术，把风力作用到各条树枝上。这类仿真对受时间限制的应用往往不可行，而且由于底层问题本身固有的复杂性，结果还可能显得不自然。

正如 Harker 2002 所指出的，树木在风场中的实际运动取决于多种因素，包括树枝的刚度与长度、叶冠的大小与形状、风场的状态，以及树冠内部的湍流。

考虑到风对树木作用力的复杂性，以及对自然条件下树木的实际观察，我们可以看出树木的运动是随机的。因此，许多方法放弃物理正确的仿真，转而把树木运动建模为随机过程。

6.2 GPU 上的过程化动画

可视化自然环境需要大量植物，因此我们需要一种既能高效仿真、又能高效渲染植被的方法。而按图形硬件当前的演进速度，终端用户已经期待被仿真的植被越来越复杂。我们方法的目标是：（1）把树木的运动仿真从 CPU 转移到 GPU；（2）利用硬件实例化减少渲染调用次数；（3）能与基于 GPU 的流体仿真无缝集成，得到不断变化的风场（Harris 2004）。

6.3 现象学方法

对树木运动做物理正确的仿真非常复杂，计算代价对实时应用来说也太高。我们改为聚焦仿真的视觉层面。正如 Stam（1997）所观察到的，树木在风场中的运动本质上是混沌的。因此，我们可以用噪声或一组周期函数来近似复杂的底层动力学。这一观察构成了我们方法的基础。为提高已有做法的真实感，我们挑出若干可辨识的视觉现象，把它们归纳为一组简单规则。树木最终的动力学由噪声函数按这些规则组合而成。

6.3.1 风场

为简化计算，我们把风定义为地形上的二维力场。Wejchert 1991 中提出的、基于空气动力学在流体中仿真物体的方法，给出了力场的表示方式。这类场定义了流体的方向与速度。这类场另一个常用的名称是向量场。

向量场可以存为稀疏数据结构。全局风向与风速可以与稀疏放置的风图元一同存储，如 Di Giacomo 2001 所做，也可以用小块的向量网格为风场添加细节——例如表现爆炸或低空飞行的直升机旋翼造成的现象。风图元定义为解析函数：

v = G(x, t),

其中 x 是表示风图元内部位置的二维向量，v 是给定位置处的风向量。时间 t 表示风随时间的演化。风图元让我们能计算场内每个给定点处的风向与风速，例如排斥力或涡量。

6.3.2 树的概念结构

从概念上说，一棵树由主干、树枝和树叶构成。这样的结构可以表示为相互连接的刚性段组成的简化层级，以主干为层级的根。每条树枝表示为一个刚性段，可以绕与父枝相连的关节旋转。真实树木的树枝并非刚性，可以弯曲，但我们不像其他一些方法（如 Kanda 2003）那样用若干段来表示树枝。我们把这部分留给渲染，作为纯粹的视觉效果来处理。

两到三层节点的浅层级通常就足以表示视觉上可信的树木运动。表示带枝树木的层级示例见图 6-1。本章后面会给出一个框架，通过在层级各关节处建模角运动来生成动画。

出于性能考虑，我们忽略树叶与小枝对整棵树运动的直接影响。不过这些影响可以隐式地并入随机仿真中。

我们假定树初始处于平衡状态。树的内力或约束力（例如树枝的弹性力）由重力抵消。离线工具或建模软件包可以给出这些约束的解。

6.3.3 仿真的两个分类

动画中的仿真细节层次（SLOD）类似于几何细节层次。远处的复杂仿真可以用简化版本替代，视觉误差极小。远距离时，树干的运动是最重要的视觉线索；距离很近时，树枝的自然运动则变得更重要。我们把树干与树枝区分为两个重要的仿真类别。两个类别都受益于同一套随机仿真方法，但各有自己的实现细节。

不同 SLOD 之间的切换会出现视觉跳变；不过由于小枝运动的混沌特性和叶冠本身形状的不定，这类副作用被部分掩盖了。

树干的动画

树干运动主要来自作用在树枝上的阻力。本章按空气动力学的含义使用阻力一词：作用于固体、方向与流动方向一致的外力之和。要模拟树干的动态运动，我们需要模拟每条有贡献的树枝所受的阻力，再沿层级逐级向下传递到树干。

然而这种做法很难并行化，因为它要求所有树枝的仿真都完成后才能处理树干。因此这种做法不适合在 GPU 上实现。于是我们选择相反的做法。我们观察到，从各条树枝传递到树干的所有力之和会导致树干运动呈混沌状态。因此我们忽略树枝的直接物理效应，而把它们隐式地包含进噪声函数中，以更高频的噪声表示树干的运动。

除主要的阻力外，还有若干重要现象影响树干运动的外观。第一，树木质量带来的惯性与树干的刚度会影响运动的振幅与形态。第二，由于树枝分布不均匀，树干运动会表现出一些垂直于风向的位移，以及少量绕树干轴的旋转。最后，风场中的湍流非常重要，可避免树丛中出现不自然的同步运动。

出于性能考虑，我们希望把所有这些力合在一起，作为单个随机过程来仿真。所幸外力、木材的物理属性与由此产生的树枝运动之间有很强的关系（Ota 2003）：

m a(t) + c v(t) + k x(t) = f(t),

其中 m 是质量，c 与 k 分别是阻尼系数与刚度系数。力 f 表示风带来的外部载荷。向量 a、v、x 分别表示树枝的线性加速度、线速度与位置。

这种强关系让我们可以直接近似底层动力学并合成运动。我们不显式求解动力学方程，而通过精心挑选并叠加频段，直接组合出运动的结果函数。由一系列波叠加而成的噪声函数示例如图 6-2。

在图 6-2中，A 段表示树在强风下向外倾斜。B 段表示湍流的合成效应：风阻力暂时减小，树干因内部弹性（弹簧）力而产生强烈响应。换句话说，树弹回并「过冲」其平衡位置。更高频的噪声添加混沌细节，模拟小枝的效果。

降低函数的振幅并减小频率，就可以模拟质量更大、弹性更低的树。图 6-3给出了这样一个函数的示例。

树干最终的动画由两个噪声函数组合而成，分别表示平行与垂直于风向的运动。可以用第三个噪声函数模拟绕树干轴的轻微旋转。如前所述，垂直运动与旋转的振幅远小于平行运动，因此可以用简单得多的噪声函数来模拟这些运动，而保持同样的视觉质量。

树枝的动画

许多树木运动仿真方法把风对树枝的作用建模为纯阻力。然而这种做法并不完全适用于叶宽而平、叶柄坚硬的树种，也不适用于针叶粗厚的常绿树。我们观察到这类树的树枝表现出更强的空气动力学特性，建议把它们当作风场中的机翼来分析。这样的树枝在风场作用下会产生升力。升力按空气动力学的定义，是作用于物体、方向垂直于流动方向的外力之和。

同样，我们不显式计算树枝的阻力与升力，而用一组简单规则来近似树枝的行为，同时考虑阻力与升力会如何作用于只有单点约束的翼状物体（例如与树干或另一条树枝相连的树枝）。

可以区分树枝与主干之间空间关系的三种情形：

  • 树枝位于树的迎风侧。
  • 树枝位于树的另一侧。
  • 树枝垂直于风向。

若树枝迎风，如图 6-4所示，升力与阻力的合力会把它压向树干，因此这条树枝的自由摆动较少。对位于树后侧的树枝，树内湍流与升力对其运动起主导作用，如图 6-5所示。这样的树枝会表现出大幅度运动，例如随机摇摆或扑动。最后，对垂直于风向的树枝，强阻力与大的攻角会使它绕父枝的轴弯曲。升力还会使它绕自身主轴略微扭转，如图 6-6所示。

即使是简单的周期函数，按上述规则组合后也能得到视觉上悦目的树枝行为。树枝的实际运动仿真将是各情形仿真的加权和。由于所有情形都用周期函数表示，无需显式求解树枝的压制、弯曲与扭转约束。这些约束被建模为周期函数的振幅修正项。

由于结果是所述各情形的加权和，某些树枝上可能出现剪切。不过这种副作用在视觉上并不难看，可以忽略。

树枝动画的改进

至此，单调的风场总体上应当能产生可信的树木运动。但树枝可能以不自然的同步方式运动。我们引入相位偏移来为表示树枝运动的前述函数添加变化。相位偏移值作为预处理步骤为每条树枝随机指定。相位偏移值之间的相关性越低，树枝行为就越混沌，反之亦然。

惯性是树枝运动另一个重要的视觉属性。我们提出利用树干仿真步骤的信息来修改前述压制与弯曲约束（更确切地说，是相应的振幅），以此模拟惯性效应。期望的视觉效果如图：当树朝风的反方向摆动时，被压向树干的树枝得以释放。这种效果营造出惯性的感觉。

6.4 仿真步骤

所提出的树木随机动画方法可以完全在 GPU 上完成。我们方法的优点在于仿真不需要上一次迭代的信息，因此所有树枝可以同时处理，与它们在层级中的位置无关。每一步仿真只需要风场状态、骨骼层级和树木参数作为输入。所需的参数函数可以直接在 GPU 上对一系列简单周期函数（如余弦与正弦）求和得到，也可以在 CPU 上预先算好，以采样数组的形式传给 GPU。

风场可以在顶点着色器中从二维纹理采样，也可以从额外的顶点缓冲中以表示风向与风速的向量形式取出，作为每个树实例特有的数据（DirectX 9 中用 D3DSTREAMSOURCE_INDEXEDDATA）。当风场同样完全在 GPU 上仿真时，第一种做法最合适。其他所需输入数据，例如骨骼层级、与噪声相关的数据以及各种树木参数，都可以作为顶点着色器常量上传到 GPU。

与每条树枝关联、并以顶点常量数组形式上传到 GPU 的数据如下：

  • 树枝的原点：即树枝绕其旋转的定义点
  • 树枝的主轴
  • 同时垂直于本条树枝主轴与其父枝主轴的切线
  • 树枝的刚度系数
  • 指定父枝的索引；若为树干，则为终止索引

除常规几何信息外，每个顶点还存储以下内容：

  • 影响该顶点的树枝索引列表（从该顶点直接所属的树枝开始，逐一列出其所有父枝，直到层级的根）
  • 影响该顶点的树枝权重列表

仿真步骤对每个顶点执行，并作为自定义顶点着色器的一部分实现。

每次仿真步骤都会遍历影响给定顶点的树枝列表。该列表为每个顶点指定，从该顶点直接所属的树枝开始，逐一列出其所有父枝，直到层级的根。有影响的树枝事先确定，并以索引数组的形式存在顶点属性中，如图 6-7所示。

对影响给定顶点的每条树枝，按本章前面的情形描述组合周期函数，算出绕其轴的旋转角。树枝的旋转角转换为四元数表示，如图 6-8所示。最终的旋转由该顶点所遍历各树枝的旋转四元数依次连接得到。

我们的方法与传统矩阵调色板蒙皮（NVIDIA 2004）有两点重要不同：（1）我们直接在顶点着色器中合成变换矩阵；（2）我们用连接操作而非线性插值来得到最终变换。代码清单 6-1 包含实现本方法部分内容的示例代码。

6.4.1 HLSL 中的四元数库

我们选择四元数来实现仿真步骤，因为处理角度旋转时它们方便、紧凑且快速。不过在实践中，用旋转矩阵旋转向量要快得多。因此我们的实现在合成角运动时只用四元数，随后把结果转换为旋转矩阵。

为配合仿真步骤，在 HLSL 中实现了以下四元数相关函数：

  1. 角度–轴到四元数的旋转转换
  2. 四元数连接
  3. 四元数到旋转矩阵的转换（Watt and Watt 1992）

示例 6-1. 模拟弯曲树枝的 HLSL 函数

float4 bendBranch(float3 pos, float3 branchOrigin, float3 branchUp,
                  float branchNoise, float3 windDir, float windPower)
{
  float3 posInBranchSpace = pos - branchOrigin.xyz;
  float towardsX =
      dot(normalize(float3(posInBranchSpace.x, 0, posInBranchSpace.z)),
          float3(1, 0, 0));
  float facingWind = dot(
      normalize(float3(posInBranchSpace.x, 0, posInBranchSpace.z)), windDir);
  float a =
      branchSwayPowerA * cos(time + branchNoise * branchMovementRandomization);
  float b = branchSwayPowerB *
            cos(timeWithDelay + branchNoise * branchMovementRandomization);
  float oldA = a;
  a = -0.5 * a + branchSuppressPower * branchSwayPowerA;
  b *= windPower;
  a = lerp(oldA * windPower, a * windPower,
           delayedWindPower * saturate(1 - facingWind));
  float3 windTangent = float3(-windDir.z, windDir.y, windDir.x);
  float4 rotation1 = quatAxisAngle(windTangent, a);
  float4 rotation2 = quatAroundY(b);
  return lerp(rotation1, rotation2, 1 - abs(facingWind));
}

6.5 渲染树

运动合成步骤用刚性段表示树枝。渲染时我们在两根骨骼之间做混合，以掩盖由此产生的、不自然的僵硬感。因此树的每个顶点受两个变换影响：

  • 顶点所属树枝的位置与旋转
  • 层级中高一级的树枝的位置与旋转

若该树枝是树干，则因它是层级的根，第二个变换用单位变换。

对每个顶点，对其位置与法线施加加权后的变换。顶点的切线与副法线（如果存在）也应同样变换。局部树枝与父枝之间的影响比例可以离线确定并存入顶点数据，也可以在运行时按顶点位置与树枝原点之间的距离计算，并按树枝刚度参数作调整。

为获得最佳渲染性能，几何细节层次应与前面讨论的仿真细节层次结合使用。

6.5.1 DirectX 10

本文所述方法在 DirectX 9 下实现会有不必要的开销，如图 6-9所示：树枝变换必须为每个顶点重新计算。DirectX 10 的流输出功能让我们能保存仿真步骤的中间结果，并在渲染步骤中复用，如图 6-10所示，从而省去每个顶点的若干运算。

DirectX 10 的实现把仿真与蒙皮步骤分到两个独立的顶点着色器中。首先，树枝与层级的信息存放在顶点缓冲里，而不再像 DirectX 9 实现那样必须放在着色器常量中。存放树枝信息的顶点缓冲作为负责仿真步骤的顶点着色器的输入。对每条树枝运行仿真时，顶点着色器把每条树枝当作一个独立顶点处理。得到的树枝变换借助 DirectX 10 的流输出功能存入另一个临时顶点缓冲。

6.6 分析与比较

我们对风场中树木过程化运动生成的方法有以下优点与缺点。

6.6.1 优点

  • 我们的方法在顶点着色器中合成动画，从而发挥 GPU 的算力。它还使基于 GPU 的风场流体仿真能更好地集成进来，完全绕开本来必须的把风场信息回读到主机内存的操作。
  • 这种方法与 GPU 实例化完全兼容——在渲染大量树木时这是一大优势。
  • 用这种技术可以模拟各种视觉上重要的现象，产生可信的树木运动。此外，我们的方法能轻松处理爆炸等局部效果。
  • 仿真步骤高度可并行，且不要求保留上一帧的信息。因此它可以方便地适配不同的多处理器环境。

6.6.2 缺点

  • DirectX 9 的实现有额外的逐顶点开销，因为仿真结果本可被同一条树枝上的多个顶点共享，现在却必须重复执行。不过 DirectX 10 提供了显著降低该方法逐顶点代价的途径。
  • 仿真并非严格物理正确，因为该方法的主要目标只满足那些能接受「看起来像」受风场影响的树木的应用。

6.7 小结

本章介绍了一种在风力等外力作用下合成树木运动的方法。它基于把树木运动建模为随机过程的已有方法，并通过添加简单规则、仿真树枝行为中的空气动力学特性对其加以扩展。我们提供了把基于 GPU 的流体仿真与本方法结合的手段，以改善用户对风的整体感觉。我们还详细讲解了 GPU 上的运动合成，以及基于 DirectX 9 与 DirectX 10 的实现。
