30.1 引言

烟、水、火等流体的基于物理的动画，是计算机图形学中最惊艳的视觉效果之一，但由于计算开销巨大，它历来属于高质量离线渲染的领域。本章我们不仅说明如何实时仿真并渲染这些效果（如图 30-1 所示），还说明如何把它们无缝整合进实时应用。基于物理的效果已经改变了交互式环境的设计方式。而流体打开的设计可能性世界还要大得多。

过去，美术在实时应用里依靠粒子系统来模拟三维流体效果。粒子系统虽然能做出好看的结果，但无法达到流体仿真的真实外观与行为。实时流体至今仍是难题，不仅因为仿真开销更大，还因为仿真产生的体积数据不容易套进标准的基于光栅化的渲染范式。

本章详细讲述 NVIDIA GeForce 8 系列发布演示「Smoke in a Box」中实时流体效果所用的技术，并讨论它如何整合进即将推出的游戏 Hellgate: London。

本章分两部分：

  • 30.2 节讲仿真，包括烟、水、火以及与实心障碍物的交互，还有性能与内存方面的考量。
  • 30.3 节讨论如何渲染流体现象，以及如何把流体渲染无缝整合进现有的基于光栅化的框架。

30.2 仿真

30.2.1 背景

本节全篇假定读者具备通用 GPU（GPGPU）方法的基本知识，即把 GPU 用于常规光栅图形之外的问题。特别推荐读者看 Harris 在 GPU Gems 中关于二维流体仿真的那一章（Harris 2004）。正如那一章所说，实现并调试三维流体求解器绝非易事（即使在传统编程环境里也是如此），扎实理解背后的数学与物理会大有帮助。Bridson 等 2006 在这方面是极好的参考资料。

30.2.3 求解速度

流行的「稳定流体」速度计算方法由 Stam 1999 提出，Harris 2004 给出了该方法在二维流体上的 GPU 实现。本节简要说明如何求解速度，细节请读者参阅所引文献。

为了数值求解动量方程，我们必须把计算域（即流体流经的空间区域）离散化为计算单元。我们选择欧拉离散，即计算单元在仿真过程中固定在空间中——只有存储在这些单元上的值在变化。具体来说，我们把一个长方体体积细分为立方体单元的规则网格。每个网格单元同时存放标量（如压力、温度等）和矢量（如速度）。这种方案让 GPU 上的实现变得简单，因为网格单元与三维纹理中的体素之间存在直接的映射。拉格朗日方案（即计算单元不固定在空间中的方案），例如光滑粒子流体动力学（Müller 等 2003），在流体动画中也很流行，但其不规则结构使其难以在 GPU 上高效实现。

由于我们对空间做了离散，方程中的导数也必须离散：有限差分通过对网格上定义的值做线性组合来数值近似导数。与 Harris 2004 一样，为教学上的简洁，我们把所有量都存在单元中心，不过交错排列的 MAC 式网格能得到更稳健的有限差分，也更容易定义边界条件。（细节见 Harlow 与 Welch 1965。）

在 GPU 实现中，单元属性（速度、压力等）存在若干张三维纹理里。每个仿真步，我们通过在网格上运行计算内核来更新这些值。内核实现为一个像素着色器，在网格的每个单元上执行，把结果写入输出纹理。然而，由于 GPU 是设计来渲染到二维缓冲的，我们必须对三维体积的每一层切片各运行一次内核。

要在某个网格切片上执行内核，我们光栅化一个尺寸等于该体积宽与高的四边形。在 Direct3D 10 中，我们可以把三维纹理的某个切片指定为渲染目标，从而直接渲染进三维纹理。把切片索引放入绑定到 SV_RenderTargetArrayIndex 语义的变量，就指定了几何着色器输出的图元被光栅化到哪个切片。（细节见 Blythe 2006。）通过遍历切片索引，我们就能在整个网格上执行内核。

我们不是一次性求解动量方程，而是把它拆成一组可以依次计算的更简单操作：平流、施加外力、压力投影。相应内核的实现细节见 Harris 2004，代码清单 30-1 给出了我们 Direct3D 10 框架中的几个例子。特别值得注意的是例程 PS_ADVECT_VEL：这个内核实现半拉格朗日平流，下一节把它作为更精确平流的基础构件。

示例 30-1. 仿真内核


struct GS_OUTPUT_FLUIDSIM
{
  // 当前网格单元的索引（i,j,k，范围 [0,gridSize]）
   float3 cellIndex : TEXCOORD0;
  // 当前网格单元及其紧邻单元的
   // 纹理坐标（x,y,z，范围 [0,1]）
   float3 CENTERCELL : TEXCOORD1;
  float3 LEFTCELL   : TEXCOORD2;
  float3 RIGHTCELL  : TEXCOORD3;
  float3 BOTTOMCELL : TEXCOORD4;
  float3 TOPCELL    : TEXCOORD5;
  float3 DOWNCELL   : TEXCOORD6;
  float3 UPCELL     : TEXCOORD7;
  float4 pos        : SV_Position; // 齐次裁剪空间中的
   // 2D 切片顶点
   uint RTIndex    : SV_RenderTargetArrayIndex;  // 指定
   // 目标切片
};
float3 cellIndex2TexCoord(float3 index)
{
  // 把 [0,gridSize] 范围内的值转换为 [0,1] 范围内的值。
   return float3(index.x / textureWidth,
                index.y / textureHeight,
                (index.z+0.5) / textureDepth);
}
float4 PS_ADVECT_VEL(GS_OUTPUT_FLUIDSIM in,
                     Texture3D velocity) : SV_Target
{
  float3 pos = in.cellIndex;
  float3 cellVelocity = velocity.Sample(samPointClamp,
                                        in.CENTERCELL).xyz;
  pos -= timeStep * cellVelocity;
  pos = cellIndex2TexCoord(pos);
  return velocity.Sample(samLinear, pos);
}
float PS_DIVERGENCE(GS_OUTPUT_FLUIDSIM in,
                    Texture3D velocity) : SV_Target
{
  // 从相邻单元取速度值。
   float4 fieldL = velocity.Sample(samPointClamp, in.LEFTCELL);
  float4 fieldR = velocity.Sample(samPointClamp, in.RIGHTCELL);
  float4 fieldB = velocity.Sample(samPointClamp, in.BOTTOMCELL);
  float4 fieldT = velocity.Sample(samPointClamp, in.TOPCELL);
  float4 fieldD = velocity.Sample(samPointClamp, in.DOWNCELL);
  float4 fieldU = velocity.Sample(samPointClamp, in.UPCELL);
  // 用中心差分计算速度的散度。
   float divergence =  0.5 * ((fieldR.x - fieldL.x)+
                             (fieldT.y - fieldB.y)+
                             (fieldU.z - fieldD.z));
  return divergence;
}
float PS_JACOBI(GS_OUTPUT_FLUIDSIM in,
                Texture3D pressure,
                Texture3D divergence) : SV_Target
{
  // 取当前单元处的散度。
   float dC = divergence.Sample(samPointClamp, in.CENTERCELL);
  // 从相邻单元取压力值。
   float pL = pressure.Sample(samPointClamp, in.LEFTCELL);
  float pR = pressure.Sample(samPointClamp, in.RIGHTCELL);
  float pB = pressure.Sample(samPointClamp, in.BOTTOMCELL);
  float pT = pressure.Sample(samPointClamp, in.TOPCELL);
  float pD = pressure.Sample(samPointClamp, in.DOWNCELL);
  float pU = pressure.Sample(samPointClamp, in.UPCELL);
  // 计算中心单元的新压力值。
   return(pL + pR + pB + pT + pU + pD - dC) / 6.0;
}
float4 PS_PROJECT(GS_OUTPUT_FLUIDSIM in,
                  Texture3D pressure,
                  Texture3D velocity): SV_Target
{
  // 通过取相邻压力值的中心差分，
   // 计算当前单元处的压力梯度。
   float pL = pressure.Sample(samPointClamp, in.LEFTCELL);
  float pR = pressure.Sample(samPointClamp, in.RIGHTCELL);
  float pB = pressure.Sample(samPointClamp, in.BOTTOMCELL);
  float pT = pressure.Sample(samPointClamp, in.TOPCELL);
  float pD = pressure.Sample(samPointClamp, in.DOWNCELL);
  float pU = pressure.Sample(samPointClamp, in.UPCELL);
  float3 gradP = 0.5*float3(pR - pL, pT - pB, pU - pD);
  // 减去压力梯度，把速度投影到
   // 其无散度分量上。
   float3 vOld = velocity.Sample(samPointClamp, in.texcoords);
  float3 vNew = vOld - gradP;
  return float4(vNew, 0);
}

30.2.4 固体-流体交互

使用实时仿真（而非预计算动画）的好处之一是流体能与环境交互。图 30-4 给出这样一个场景的例子。本节讨论两种让环境作用于流体的简单做法。

影响速度场的一种基本方式是施加外力。要得到障碍物推开流体的大致效果，我们可以用盒子或球之类的基本形状来近似障碍物，把障碍物的平均速度加到速度场的相应区域。这类简单形状可以用形如 f (x, y, z) ≤ 0 的隐式方程描述，像素着色器可以在每个网格单元上轻松求值。

虽然我们可以显式加一个速度来近似简单运动，但有些场合需要更多细节。例如在 Hellgate: London 中，我们希望烟从地面裂缝中渗出。按裂缝形状加上一个向上的速度和烟密度，得到的效果很无趣。于是我们改用图 30-5 内插图所示的裂缝形状来定义实心障碍物，让烟与它碰撞交互。同样，我们希望烟与动画石像鬼之间有更精细的交互，如图 30-4 所示。为此我们需要能用动态障碍物影响流体运动（细节见本节后文），而这要求障碍物内部以及其边界处的速度有体积表示（本节后文也会说明）。

动态障碍物

到此我们假定流体占据仿真网格所定义的整个长方体区域。然而在多数应用里，流体域（即网格中实际被流体占据的区域）要更有意思得多。在 GPU 上处理静态边界的多种方法见 Harris 等 2003、Liu 等 2004、Wu 等 2004 与 Li 等 2005。

流体域可能随时间变化，以适应环境中的动态障碍物；对水这类液体，随着液体晃荡，域也在不断变化（30.2.7 节会多讲）。本节描述 Hellgate: London 中处理动态障碍物所用的方案。关于动态障碍物的进一步讨论，见 Bridson 等 2006 与 Foster 和 Fedkiw 2001。

要处理复杂的域，我们必须考虑流体在域边界处的行为。在离散化的流体中，域边界由含流体的单元与不含流体的单元之间的面构成——也就是说，流体单元与固体单元之间的那个面属于边界，而固体单元本身不属于。域边界的一个简单例子是在仿真网格四周放一圈静态屏障，防止流体「逃逸」（没有它，流体看起来就像直接流进了太空）。

要支持因动态障碍物存在而变化的域边界，我们需要修改部分仿真步骤。在我们的实现里，障碍物用内外体素化表示。此外，我们在与域边界相邻的固体单元里保存障碍物速度的体素化表示。这些信息存在一对三维纹理中，障碍物移动或变形时更新（本节后文会讲到）。

在固体-流体边界处，我们要施加自由滑移边界条件，即流体与固体在垂直于边界的方向上速度相同：

u · n = u solid · n.

换句话说，流体不能流进或流出固体，但可以沿其表面自由流动。

对速度值也可以用类似的技巧：每次采样相邻单元时（例如计算速度散度时），我们先检查它是否含固体。若含，就从体素化结果里查障碍物的速度，用它代替流体速度场中存的值。

由于我们无法总把压力-泊松系统解到收敛，我们在压力投影之后立刻显式施加自由滑移边界条件。我们还必须修正域边界旁流体单元的压力投影结果。做法是计算障碍物速度在垂直于边界方向上的分量。这个值替换中心单元处流体速度的相应分量，如图 30-7 所示。由于固体-流体边界与体素面对齐，把速度投影到表面法线上只需选取相应的分量。

若一个流体单元相对的两个面都是固体-流体边界，我们可以对两侧的速度值取平均。不过只选其中一个面通常也能得到可接受的结果。

最后，有一点很重要：时间步很大时，量可能在平流过程中「泄漏」穿过边界。为此我们给平流步加了一条额外约束，确保绝不把任何量平流到障碍物内部，从而保证被平流的量（例如烟密度）在实心障碍物内部始终为零（见代码清单 30-3 中的 PS_ADVECT_OBSTACLE 例程）。代码清单 30-3 给出为考虑边界条件而修改过的仿真内核。

  // 取当前单元处的散度和压力。
   float dC = divergence.Sample(samPointClamp, in.CENTERCELL);
  float pC = pressure.Sample(samPointClamp, in.CENTERCELL);
  // 从相邻单元取压力值。
   float pL = pressure.Sample(samPointClamp, in.LEFTCELL);
  float pR = pressure.Sample(samPointClamp, in.RIGHTCELL);
  float pB = pressure.Sample(samPointClamp, in.BOTTOMCELL);
  float pT = pressure.Sample(samPointClamp, in.TOPCELL);
  float pD = pressure.Sample(samPointClamp, in.DOWNCELL);
  float pU = pressure.Sample(samPointClamp, in.UPCELL);
  // 确保实体单元中的压力被有效忽略。
   if(IsSolidCell(in.LEFTCELL)) pL = pC;
  if(IsSolidCell(in.RIGHTCELL)) pR = pC;
  if(IsSolidCell(in.BOTTOMCELL)) pB = pC;
  if(IsSolidCell(in.TOPCELL)) pT = pC;
  if(IsSolidCell(in.DOWNCELL)) pD = pC;
  if(IsSolidCell(in.UPCELL)) pU = pC;
  // 计算新的压力值。
   return(pL + pR + pB + pT + pU + pD - dC) /6.0;
}
float4 GetObstacleVelocity(float3 cellTexCoords)
{
  return obstaclevelocity.Sample(samPointClamp, cellTexCoords);
}
float PS_DIVERGENCE_OBSTACLE(GS_OUTPUT_FLUIDSIM in,
                             Texture3D velocity) : SV_Target
{
  // 从相邻单元取速度值。
   float4 fieldL = velocity.Sample(samPointClamp, in.LEFTCELL);
  float4 fieldR = velocity.Sample(samPointClamp, in.RIGHTCELL);
  float4 fieldB = velocity.Sample(samPointClamp, in.BOTTOMCELL);
  float4 fieldT = velocity.Sample(samPointClamp, in.TOPCELL);
  float4 fieldD = velocity.Sample(samPointClamp, in.DOWNCELL);
  float4 fieldU = velocity.Sample(samPointClamp, in.UPCELL);
  // 对任何实体单元使用障碍物速度。
   if(IsBoundaryCell(in.LEFTCELL))
    fieldL = GetObstacleVelocity(in.LEFTCELL);
  if(IsBoundaryCell(in.RIGHTCELL))
    fieldR = GetObstacleVelocity(in.RIGHTCELL);
  if(IsBoundaryCell(in.BOTTOMCELL))
   fieldB = GetObstacleVelocity(in.BOTTOMCELL);
  if(IsBoundaryCell(in.TOPCELL))
   fieldT = GetObstacleVelocity(in.TOPCELL);
  if(IsBoundaryCell(in.DOWNCELL))
   fieldD = GetObstacleVelocity(in.DOWNCELL);
  if(IsBoundaryCell(in.UPCELL))
   fieldU = GetObstacleVelocity(in.UPCELL);
  // 用中心差分计算速度的散度。
   float divergence =  0.5 * ((fieldR.x - fieldL.x) +
                             (fieldT.y - fieldB.y) +
                             (fieldU.z - fieldD.z));
  return divergence;
}
float4 PS_PROJECT_OBSTACLE(GS_OUTPUT_FLUIDSIM in,
                           Texture3D pressure,
                           Texture3D velocity): SV_Target
{
  // 若该单元是实体单元，就直接使用
   // 对应的障碍物速度。
   if(IsBoundaryCell(in.CENTERCELL))
  {
    return GetObstacleVelocity(in.CENTERCELL);
  }
  // 取当前单元及其相邻单元的压力值。
   float pC = pressure.Sample(samPointClamp, in.CENTERCELL);
  float pL = pressure.Sample(samPointClamp, in.LEFTCELL);
  float pR = pressure.Sample(samPointClamp, in.RIGHTCELL);
  float pB = pressure.Sample(samPointClamp, in.BOTTOMCELL);
  float pT = pressure.Sample(samPointClamp, in.TOPCELL);
  float pD = pressure.Sample(samPointClamp, in.DOWNCELL);
  float pU = pressure.Sample(samPointClamp, in.UPCELL);
  // 取相邻实体单元中的障碍物速度。
   // （注意：若邻居不是实体单元，
   // 这些值没有意义。）
   float3 vL = GetObstacleVelocity(in.LEFTCELL);
  float3 vR = GetObstacleVelocity(in.RIGHTCELL);
  float3 vB = GetObstacleVelocity(in.BOTTOMCELL);
  float3 vT = GetObstacleVelocity(in.TOPCELL);
  float3 vD = GetObstacleVelocity(in.DOWNCELL);
  float3 vU = GetObstacleVelocity(in.UPCELL);
  float3 obstV = float3(0,0,0);
  float3 vMask = float3(1,1,1);
  // 若相邻单元是实体单元，就忽略其压力
   // 而使用其速度。
   if(IsBoundaryCell(in.LEFTCELL)) {
    pL = pC; obstV.x = vL.x; vMask.x = 0; }
  if(IsBoundaryCell(in.RIGHTCELL)) {
    pR = pC; obstV.x = vR.x; vMask.x = 0; }
  if(IsBoundaryCell(in.BOTTOMCELL)) {
    pB = pC; obstV.y = vB.y; vMask.y = 0; }
  if(IsBoundaryCell(in.TOPCELL)) {
    pT = pC; obstV.y = vT.y; vMask.y = 0; }
  if(IsBoundaryCell(in.DOWNCELL)) {
    pD = pC; obstV.z = vD.z; vMask.z = 0; }
  if(IsBoundaryCell(in.UPCELL)) {
    pU = pC; obstV.z = vU.z; vMask.z = 0; }
  // 通过取相邻压力值的中心差分，
   // 计算当前单元处的压力梯度。
   float gradP = 0.5*float3(pR - pL, pT - pB, pU - pD);
  // 减去压力梯度，把速度投影到
   // 其无散度分量上。
   float3 vOld = velocity.Sample(samPointClamp, in.texcoords);
  float3 vNew = vOld - gradP;
  // 通过把新速度的相应分量替换为
   // 障碍物速度，来显式施加自由滑移
   // 边界条件。
  vNew = (vMask * vNew) + obstV;
  return vNew;
}

体素化

要处理动态固体的边界条件，我们需要一种快速判断给定单元是否含实心障碍物的方法。我们还需要知道障碍物边界旁单元的固体速度。为此我们用两个不同的体素化例程，把实心障碍物体素化成一张「内外」纹理与一张「障碍物速度」纹理，如图 30-8 所示。

内外体素化

我们获得内外体素化的思路受模板阴影体算法启发。想法很简单：用正交投影把输入的三角网格依次渲染进目标三维纹理的每个切片。远裁剪面设在无穷远，近平面与当前切片的深度一致，如图 30-9 所示。绘制几何体时，我们使用一个（与切片尺寸相同的）模板缓冲，初始化为零。把模板操作设为背面递增、正面递减（两者都回绕）。结果就是网格内部的任何体素都会得到非零的模板值。最后我们做一个遍，把模板值拷进障碍物纹理。[1]

由此我们得以区分三类单元：内部（模板值非零）、外部（模板值为零）、以及内部但紧邻边界（这些单元由接下来描述的速度体素化算法标记）。注意，由于这个方法依赖每一个正面都有一个对应的背面，它最适合水密的封闭网格。

速度体素化

第二个体素化算法为每个含有障碍物边界部分的网格单元计算障碍物速度。不过首先我们需要知道障碍物在每个顶点处的速度。计算逐顶点速度的一个简单做法，是把上一帧与当前帧的顶点位置 p n-1 与 p n 分别存进顶点缓冲。瞬时速度 v i（顶点 i 的速度）可用前向差分近似

接下来，我们必须为任何含有表面网格片段的网格单元计算插值后的障碍物速度。与内外体素化一样，网格对网格的每个切片各渲染一次。不过这一次我们必须确定每个三角形与当前切片的交。

切片与三角形的交可以是一条线段、一个三角形、一个点，或为空。若交是线段，我们用四边形把该线段的「加粗」版本画进切片。这个四边形由原线段的两个端点，以及由这两个端点偏移得到的两个额外点构成，如图 30-10 所示。偏移距离 w 等于三维纹理某个切片中一个纹素的对角线长度，偏移方向是三角形法线在切片上的投影。用线性插值，我们求出每个端点处的速度值，并把它们赋给四边形相应的顶点。绘制四边形时，这些值会按需要跨网格单元插值。

这些四边形可以用一个作用于网格三角形的几何着色器生成：若交是线段则输出四个顶点，否则输出零个顶点。由于几何着色器不能输出四边形，我们必须改用两个三角形的三角带。要计算三角形与切片的交，我们把三角形的每条边与切片求交。若恰好找到两个边-切片交点，就把相应的交点作为线段的端点。这些点处的速度值通过在相应三角形边上做插值算出。代码清单 30-4 中的几何着色器 GS_GEN_BOUNDARY_VELOCITY 给出了该算法的一个实现。图 30-12 给出对图 30-11 中的模型做体素化后，体素体积的几个切片。

   // GS_GEN_BOUNDARY_VELOCITY:
   // 输入：
   //  - 一个三角形（3 个顶点），
   //  - sliceIdx，
   //  - sliceZ；
   // 输出：
   //  - 2 个三角形（若输入三角形与切片的交集
   //    是一条线段）
   //  - 否则 0 个三角形
   // 这 2 个三角形沿线段构成宽度为 1 个
   // 体素的四边形。
[maxvertexcount (4)]
void GS_GEN_BOUNDARY_VELOCITY(
  triangle VsGenVelOutput input[3],
  inout TriangleStream triStream)
{
  GsGenVelOutput output;
  output.RTIndex = sliceIdx;
  float minZ = min(min(input[0].Pos.z, input[1].Pos.z), input[2].Pos.z);
  float maxZ = max(max(input[0].Pos.z, input[1].Pos.z), input[2].Pos.z);
  if((sliceZ < minZ) || (sliceZ > maxZ))
    // 该三角形不与切片相交。
   return;
  GsGenVelIntVtx intersections[2];
  for(int i=0; i<2; i++)
  {
    intersections[i].Pos = 0;
    intersections[i].Velocity = 0;
  }
  int idx = 0;
  if(idx < 2)
    GetEdgePlaneIntersection(input[0], input[1], sliceZ,
                             intersections, idx);
  if(idx < 2)
    GetEdgePlaneIntersection(input[1], input[2], sliceZ,
                             intersections, idx);
  if(idx < 2)
    GetEdgePlaneIntersection(input[2], input[0], sliceZ,
                             intersections, idx);
  if(idx < 2)
    return;
  float sqrtOf2 = 1.414; // 一个像素的对角线
   float2 normal = sqrtOf2 * normalize(
    cross((input[1].Pos - input[0].Pos),
          (input[2].Pos - input[0].Pos)).xy);
  for(int i=0; i<2; i++)
  {
    output.Pos = float4(intersections[i].Pos, 0, 1);
    output.Velocity = intersections[i].Velocity;
    triStream.Append(output);
    output.Pos = float4((intersections[i].Pos +
                        (normal*projSpacePixDim)), 0, 1);
    output.Velocity = intersections[i].Velocity;
    triStream.Append(output);
  }
  triStream.RestartStrip();
}
void GetEdgePlaneIntersection(
  VsGenVelOutput vA,
  VsGenVelOutput vB,
  float sliceZ,
  inout GsGenVelIntVtx intersections[2],
  inout int idx)
{
  float t = (sliceZ - vA.Pos.z) / (vB.Pos.z - vA.Pos.z);
  if((t < 0) || (t > 1))
    // 线-面交点不在这条边的两个端点
   // （A 和 B）之内
   return;
    intersections[idx].Pos = lerp(vA.Pos, vB.Pos, t).xy;
    intersections[idx].Velocity = lerp(vA.Velocity, vB.Velocity, t);
    idx++;
}

30.2.7 水

水的建模方式与前面讨论的流体现象不同。对火或烟，我们关心的是可视化贯穿整个体积的密度；而对水，视觉上有趣的部分是空气与液体之间的界面。

因此我们需要某种方式来表示这个界面，并跟踪它被流体速度推着走时如何变形。

水平集方法（Sethian 1999）是液面的一种流行表示，也特别适合 GPU 实现，因为它只需要每个网格单元上的一个标量值。在水平集中，每个单元记录从单元中心到水面的最短有符号距离 。网格中的单元按 的值分类：若 < 0，该单元含水；否则含空气。 等于零的地方正是水与空气交界处（零集）。由于平流不会保持水平集的距离场性质，常见做法是周期性地重初始化水平集。重初始化确保每个单元确实存的是到零集的最短距离。不过要单纯定义表面并不需要这个性质，对实时动画来说，不做重初始化也能得到不错的结果。本章开头的图 30-1 展示了结果质量。

与颜色、温度等属性一样，水平集被流体平流，但它也影响仿真的动力学。事实上，水平集定义了流体域：在水与空气的简单模型中，我们假定空气对液体的影响可忽略，并 ≥ 0 的地方都不做仿真。实践中这意味着在求解压力之前把液体外部压力设为零，只在液体单元中修改压力。这也意味着我们不在液体外部施加重力等外力。为确保只处理流体单元，我们在相关着色器中检查水平集纹理的值，若 f 的值高于某个阈值就屏蔽该单元的计算。两个可能更高效的替代方案是：用 z 剔除来排除单元（若 GPU 不支持动态流控制）（Sander 等 2004），以及使用稀疏数据结构（Lefohn 等 2004）。

30.2.8 性能考量

编写高效求解器的一大因素是带宽。每一帧动画里，求解器要运行大量算术上很简单的内核，内核之间数据必须与纹理内存来回传输。虽然这些内核大多表现出良好的局部性，带宽仍是主要问题：用 32 位浮点纹理存量，性能大约只有 16 位纹理的一半。意外的是，用 16 位存储几乎看不出视觉上的退化，如图 30-13 所示。注意算术运算仍以 32 位浮点执行，这意味着结果写入目标纹理时会被周期性截断。

有些情况下，为减少内存占用或图方便，人们会想把多个单元属性打包进一张纹理，但从内存带宽角度看这并不总是最优。例如假设我们把障碍物的内外信息与速度信息打包进一张 RGBA 纹理。迭代求解压力-泊松方程时，每帧都要多次加载内外值，而与此同时障碍物速度完全用不上。由于把这两张纹理打包在一起，会需要从内存传输四倍的字节数，也需要四倍的缓存空间，因此把障碍物的内外信息单独放在自己的标量纹理里可能更明智。

30.2.10 数值问题

由于实时应用要求极高，我们选择了仍能给出可接受视觉结果的最简单数值格式。但要注意，对高质量动画，更精确的替代方案更可取。

仿真中最昂贵的部分之一是求解压力-泊松系统 ∇2 p = ∇ · u*。我们用 Jacobi 方法求解该系统，因为它容易在 GPU 上高效实现。不过还有几种合适的求解器已在 GPU 上实现，包括共轭梯度法（Bolz 等 2003）与多重网格法（Goodnight 等 2003）。循环归约是特别有意思的一个选项，因为它是直接法，且能利用带状系统（Kass 等 2006）。选择迭代求解器时，值得考虑的不只是总体收敛速度，还有残差中不同空间频率的收敛速度（Briggs 等 2000）。由于实时应用里可能没有足够时间达到收敛，频率的分布会对解的观感产生一定影响。

理想情况下我们希望精确求解压力-泊松系统，以满足不可压缩约束并保持流体体积。不过对烟和火这类流体，体积变化并不总会产生令人反感的视觉瑕疵。因此我们可以按可用资源调整求解该系统时的迭代次数。图 30-14 比较了用不同 Jacobi 迭代次数时火焰的观感。动态观看时，只用少量迭代会让旋转的涡稍微更「摊平」一些，但整体观感非常相似。

关于 GPGPU 性能问题更详尽的讨论，见 Pharr 2005。

另一方面，对液体来说体积变化会立刻显现：流体看起来要么凭空涌出，要么整个消失！即便只是水箱里静置的水，若用于求解压力的迭代次数太少也可能出问题：因为信息无法从箱底传到水面，箱底的压力就无法抵消重力。结果水会缓慢地穿过箱底沉下去，如图 30-15 所示。

30.3 渲染

30.3.1 体绘制

仿真的结果是存在三维纹理里的一组值。然而 Direct3D 或 OpenGL 都没有直接显示这张纹理的机制。因此我们用光线步进像素着色器来渲染流体。我们的做法与 Scharsach 2005 所述非常接近。

流体在场景中的位置由六个四边形确定，它们表示仿真体积的各个面。这些四边形被画进延迟着色缓冲，以确定射线应从何处、以何种方式投射。然后我们让射线穿过体积步进，从三维纹理累积密度来渲染流体，如图 30-17 所示。

体光线投射

要投射一条射线，我们需要知道它从何处进入体积、朝哪个方向行进、以及取多少个采样。获得这些值的一种方法是在光线步进着色器里做若干次射线-平面求交。不过预先算出这些值并存入纹理，更容易做正确的合成与裁剪（本节后文会详述），这也是我们这里采用的做法。作为一个预遍，我们生成一张屏幕尺寸的纹理，称为 RayData 纹理，它为每个要渲染的像素编码射线在纹理空间中的进入点，以及射线穿过体积的深度。为得到穿过体积的深度，我们先用一个着色器绘制体积的背面，把从眼到片元位置的距离（在视图空间中）输出到 alpha 通道。然后我们在正面上运行类似的着色器，但用公式 1 启用减性混合。此外，为得到射线的进入点，我们还在 RGB 通道中输出正面所生成的每个片元的纹理空间坐标。

此前我们用体积背面的距离来决定光线步进应在何处终止。要处理与体积相交的障碍物，我们改用背面距离与场景距离（即眼到场景中最近障碍物的距离）中的较小者。场景距离可以通过读取场景深度并反投影回视图空间，求出眼到场景的距离。若在像素着色器中无法把深度缓冲作为纹理读取（Direct3D 10 使用多重采样抗锯齿时就是如此），可以在主场景渲染遍中用多渲染目标算出这个距离；我们采用的就是这种做法。

要处理场景几何体完全遮挡体积一部分的情形，我们把正面片元的距离与场景距离作比较。若正面距离大于场景距离（即该片元被遮挡），我们在红通道输出一个很大的负值。这样，为 RayData 纹理中相应纹素算出的最终纹理空间位置就会落在体积之外，于是沿相应射线不会取任何采样。

在正面被裁掉的区域，我们不知道射线从何处进入体积，而且体积深度的值也是错的。

要处理这些区域，我们标记出那些渲染了体积背面、却没渲染正面的像素。做法是在把流体体积背面渲染到 RayData 纹理时，往绿通道写入一个负的颜色值。注意在渲染正面或背面之前，RayData 纹理都被清为零。由于我们用 alpha 混合渲染正面时（公式 1）不使用目标颜色的 RGB 值，渲染正面之后绿通道含负颜色的像素，就是那些渲染了流体体积背面却没渲染正面（因裁剪）的像素。在光线投射着色器中，我们把这些被标记像素的位置显式初始化为近平面上相应点的纹理空间位置。我们还修正从 RayData 纹理读到的深度值，减去从眼到近平面上相应点的距离。

不过条带通常仍会在某种程度上存在，而且当体积密度或密度到颜色的映射（称为传输函数）出现高频变化时，条带会变得更明显。这个众所周知的问题在 Hadwiger 2004 以及 Sigg 和 Hadwiger 2005 中有讨论。常见解法包括提高采样频率、沿射线方向抖动采样位置，或在采样体积时使用更高阶的滤波器。通常最好把其中几种技术结合起来，以找到性能与质量之间的良好权衡。在 Hellgate: London 中，我们使用了频率为每体素两次的三线性抖动采样。

离屏光线步进

若仿真网格的分辨率相对屏幕分辨率偏低，以高分辨率做光线投射几乎没有视觉收益。我们改为把流体画进较小的离屏渲染目标，再把结果合成进最终图像。除图像中场景几何体存在尖锐深度不连续的区域（如图 30-22 所示）以及相机裁掉流体体积的地方之外，这种做法的效果都不错。

这个问题在本书第 23 章 Iain Cantlay 的「高速离屏粒子」中有深入讨论。在 Hellgate: London 中，我们采用与该章类似的做法：大部分烟以低分辨率绘制，但问题区域的像素以屏幕分辨率渲染。我们通过对本节前面算出的 RayData 纹理运行边缘检测滤波来找这些区域。具体来说，我们对该纹理的 alpha 通道（找与体积相交的障碍物边缘）、红通道（找遮挡体积的障碍物边缘）与绿通道（找相机近平面裁切体积处的边缘）分别运行 Sobel 边缘检测滤波。

火

渲染火与渲染烟类似，只是步进时不混合各值，而是累积由反应坐标 Y（而非烟密度）决定的值（见 30.2.6 节）。具体来说，我们使用一张由美术定义的、把反应坐标映射到颜色的一维纹理，从而得到火的外观。关于火渲染更基于物理的讨论，见 Nguyen 等 2002。

如有需要，火体积也可以用作光源。最简单的做法是在若干位置对体积采样，把每个采样当作一个点光源。反应坐标与一维颜色纹理可用来确定光的强度与颜色。不过若点采样数不足，这种做法会导致严重闪烁，而且可能抓不住光的整体行为。另一种做法是把反应坐标纹理降采样到极低分辨率，然后把每个体素都当作光源。后一种做法不易闪烁，但抓不住任何高频光照效果（例如火花引起的局部光照）。

30.3.2 渲染液体

要渲染液面，我们同样步进穿过一个体积，但这次查看的是水平集 的值。我们不在步进时积分各值，而是寻找射线上第一个 = 0 的位置。找到该点后，我们像着色任何其它表面片元那样给它着色，用该点处的 ∇f 近似着色法线。对水而言，尤其重要的是不能看到网格分辨率的痕迹，所以我们用三三次插值来滤波这些值。本章开头的图 30-1 展示了渲染结果。关于如何在 GPU 上快速求交并滤波水平集这类体积等值面数据，细节见 Sigg 和 Hadwiger 2005 以及 Hadwiger 等 2005。

折射

对水这类流体，有几种方式可让表面看起来像在折射其后的物体。光线追踪是一种可能，但投射射线开销大，而且可能无法求到与其它场景几何体的交点。我们改用一种近似，能给人折射的印象，实现起来又快又简单。

首先，我们把流体体积后面的物体渲染进一张背景纹理。

接着，我们通过步进穿过体积，为每个像素求出与水面的最近射线交点。这产生一对纹理，分别存放命中位置与着色法线；存放命中位置的纹理中，若某像素没有射线-表面交点，其 alpha 值设为零，否则设为一。然后我们用一张使用背景纹理的折射着色器给这些命中点着色。最后加入前景物体，形成最终图像。

30.4 结论

本章我们希望已说明，基于物理的流体动画是创建交互式环境的有价值工具，并提供了开始开发实用实现所需的一些基本构件。然而这绝非终点：我们略去了流体动画大量可能方向的讨论，包括融化（Carlson 等 2002）、粘弹性流体（Goktekin 等 2004）与多相流（Lossasso 等 2006）。我们也略去了若干有趣数据结构与算法的讨论，例如稀疏水平集（Lefohn 等 2004），它可能显著提升仿真性能；以及基于网格的表面提取（Ziegler 等 2006），它可能让液体渲染更高效。
