[declare]

设置加载 patch 的环境

描述

编译好的外部库要么以单个二进制包的形式（“classic”库格式）提供，要么以一组分离的二进制和/或抽象对象提供。单个二进制包就是我们所说的 'library'，需要预加载——而有分离的二进制/抽象对象的外部库，只需把它的目录添加到搜索路径就能加载。如果你想要加载其中的音频和文本文件之类的东西，也需要把目录添加到路径中。

一个 declare 对象向 Pd 的搜索路径添加一个或多个目录，和/或预加载一个或多个库（“externals”），为从文件打开 patch 做准备。用法为 "declare [-flag value] [-flag value] ..."（对其中任意项，你可以用完整路径名，例如 "/tmp/dir"，或者在 Windows 上用 "C:/garbage"，来代替相对路径）。

例如，如果你把抽象对象和/或其他支持文件放在子目录 "more" 中，你可以放一个对象 "declare -path more" 来确保 Pd 在加载 patch 时能看到它们。或者，如果你的文件安装在目录 extra/stillmore（在 Pd 安装目录中），你可以用 "declare -stdpath stillmore" 取到它。

用 '-path' 声明的路径具有最高搜索优先级。其次是相对路径，然后是用户添加的搜索路径（在 "Preferences => Path" 中设置），最后是标准路径（也叫 'extra' 文件夹）。从 0.49 版本起，如果到 patch 的相对路径不存在，"declare -path" 和 "declare -lib" 会退回到其他搜索路径。要避免继续检查，可以使用显式的相对路径，在路径或库名前加上 "./" 或 "../"。

由于 'extra' 文件夹在搜索优先级中排最后，其他路径会先被搜索。你可以用 [declare -stdpath ./] 来确保 'extra' 具有搜索优先级。注意你指定 '-path' 选项的顺序也指定了搜索优先级。

当前的最佳做法是直接使用 [declare]，而不是把路径永久加入用户搜索路径或把库加入启动项。用 [declare] 你可以更好地管理并避免不同库中同名外部对象的冲突，用它调用你想要的那个库。

但是要注意，当你加载一个库时（用 'declare -lib' 或通过启动项），它的所有对象都会被预加载并优先，所以使用 'declare -path' 无法强制加载优先级。因此，你可能需要采用斜杠声明，如 [library/objectname]。另外注意，'-path' 只会为拥有该 [declare] 对象的 patch 添加搜索路径，而一旦库被加载，它就留在 Pd 中，无需 [declare] 就能在其他 patch 中加载。关于这一点以及 Pd 中外部对象加载如何工作的更多细节，请参考 Pd 手册的第 4 章。

警告：从 0.47 版本起，抽象对象内部的 "declare -path" 和 "declare -stdpath" 只在那些抽象对象内部生效。如果 Pd 的兼容版本设为 0.46 或更早，旧的（有 bug 的）行为会生效。

BUG：名字 "-stdpath" 令人困惑，因为它与 pd 命令行上的 "-stdpath" 效果相当不同。

选项

选项说明
-path <symbol>添加到搜索路径，相对于 patch 或用户路径
-stdpath <symbol>添加到搜索路径，相对于 Pd（'extra' 文件夹）
-lib <symbol>加载库，相对于 patch 或用户路径
-stdlib <symbol>加载库，相对于 Pd（'extra' 文件夹）
