非茗的翻译文档库

Max

mtr

记录消息并进行序列回放

描述

记录消息，并提供按序列回放。

讨论

mtr 充当可记录任何类型消息的多轨录音机。mtr 的最左入口是所有轨道的控制入口。你也可以把同样的消息发送给单条轨道。每条轨道记录从其入口送入的内容，并直接通过该入口正下方的出口回放出来。

mtr 中的时间有两种度量方式，取决于 sync 特性是启用还是禁用。当 sync 关闭时，时间单位是毫秒。当 sync 打开时，时间单位是 ticks。本文档余下部分所说的 "时间"，其时间单位类型都取决于 sync 的设置。

参数

tracks [int] 可选

指定 mtr 中轨道的数量。轨道数量决定了除最左入口和出口之外还要有多少个入口和出口。最多可以有 128 条轨道。若没有参数，则只有一条轨道。

特性

autostart [int]

设置传输启动时 mtr 是否播放所有轨道。默认值为 0（关闭）。该特性只能全局设置，不适用于单条轨道。

autostarttime [Time Value] : 0 ticks

设置 mtr 的 autostarttime。若启用了 autostart 特性，mtr 会在该特性指定的时间自动播放所有轨道。autostarttime 只能全局设置，不适用于单条轨道。

bindto [atom]

用 pattr 脚本名把单个界面对象绑定到轨道，无需连线。若你给某个界面对象指定了脚本名，就可以用同一个名称来设置到 mtr 的绑定。@bindto 键入的参数应当是轨道编号，后面跟所需对象的脚本名。

embed [int]

当 embed 设为 1 时，任何已记录的数据都会随补丁一起保存。注意，录音、修改或清除数据都不会使补丁变 dirty。该特性只能全局设置，不适用于单条轨道。

length [float]

以时间单位计设置所有轨道的长度。这定义了轨道何时停止或循环。若长度比最初记录的长度短，指定时间之后的事件不会播放，但仍保留在轨道中。该特性可以通过 Inspector、attrui、键入的参数或发给左入口的消息来设置。这样设置时，length 被视为全局特性，会覆盖此前设置的任何轨道专属长度取值。

若作为消息发给任何非左入口，它会以时间单位计设置与该入口相对应的轨道的长度。若随后全局设置了长度取值（见上文），所有轨道专属取值都会被覆盖。

loop [int]

为所有轨道关闭/打开循环。该特性可以通过 Inspector、attrui、键入的参数或发给左入口的消息来设置。这样设置时，loop 被视为全局特性，会覆盖此前设置的任何轨道专属循环取值。

若作为消息发给任何非左入口，它会设置与该入口相对应的轨道的循环状态。若随后全局设置了 loop 取值（见上文），所有轨道专属取值都会被覆盖。

mode [int]

启用自动化回放模式；在该模式下，启动或重启某条轨道时会播放 selection 之前的最后一个事件（前提是选区起点非零）。默认值为 0（关闭）。该特性可以通过 Inspector、attrui、键入的参数或发给左入口的消息来设置。这样设置时，mode 被视为全局特性，会覆盖此前指定的任何轨道专属设置。

若作为消息发给任何非左入口，它会为该入口相对应的轨道启用/禁用自动化回放模式。若随后全局设置了 mode 特性（见上文），所有轨道专属设置都会被覆盖。

nextmode [int]

设置 next 消息的行为方式。当 nextmode 设为 0 时，最后一个事件之后的 next 消息会产生一个 delta 时间为 -1 的事件。当 nextmode 设为 1（循环模式）时，最后一个事件之后的 next 消息会立即回到第一个事件继续循环。该特性只能全局设置，不适用于单条轨道。
可选值：

0 = 'end'
1 = 'loop'

quantize [Time Value] : 0 ticks

设置回放量化。这不会改变轨道中的实际事件，只改变它们的播放方式。该特性只能全局设置，不适用于单条轨道。

selection [2 floats]

设置所有轨道的回放选区。选区以基于轨道长度的归一化单位表示，轨道长度由 length 特性定义；若 length 为 0，则使用记录的总时长。例如，"selection 0.25 0.75" 会播放一条轨道的中间部分。给某条轨道发送 play 消息时，它会从选区点开始，而不是从头开始。回放会（细微地）受到 mode 特性的影响。

该特性可以通过 Inspector、attrui、键入的参数或发给左入口的消息来设置。这样设置时，selection 被视为全局特性，会覆盖此前设置的任何轨道专属选区取值。

若作为消息发给任何非左入口，它会设置与该入口相对应的轨道的回放选区。若随后全局设置了 selection 特性（见上文），所有轨道专属取值都会被覆盖。

speed [float]

设置要施加到所有轨道速度上的全局倍率，其中 1.0 是原始速度。这让你可以让各条轨道以不同的 trackspeed 运行，然后再施加一次全局速度变化。该特性只能全局设置，不适用于单条轨道。

sync [int]

启用 sync 时，mtr 会同步到一个具名的传输（“internal” 为默认值）。当 sync 关闭时，时间单位是毫秒。当 sync 打开时，时间单位是 ticks。该特性只能全局设置，不适用于单条轨道。

trackspeed [float]

设置所有轨道的速度，其中 1.0 是最初录制的速度。实际轨道速度是 mtr 的 speed 特性、trackspeed 和 timescale 三者共同作用的结果。该特性可以通过 Inspector、attrui、键入的参数或发给左入口的消息来设置。这样设置时，trackspeed 被视为全局特性，会覆盖此前设置的任何轨道专属 trackspeed 取值。

若作为消息发给任何非左入口，它会设置与该入口相对应的轨道的速度。若随后全局设置了 trackspeed 取值（见上文），所有轨道专属取值都会被覆盖。

transport [symbol] : internal

设置传输名称。默认设置是 "internal"，即全局传输。该特性只能全局设置，不适用于单条轨道。

消息

bang

与 info 消息一样，把 bang 发给 mtr 的左入口，会从左出口送出一个字典，其中包含该对象当前状态的信息。字典中既包含全局信息，也包含轨道专属信息。以 "global_" 开头的条目是指定特性的全局设置。若同一特性还有轨道专属设置，该取值会列在该轨道的信息之下。

int

除左入口以外的任意入口：若该轨道当前正在录音，该轨道入口收到的数字会与一个 delta 时间（自上一个事件以来经过的时间）合并后存入 mtr。

参数：

  • input [int]

float

除左入口以外的任意入口：若该轨道当前正在录音，该轨道入口收到的数字会与一个 delta 时间（自上一个事件以来经过的时间）合并后存入 mtr。

参数：

  • input [float]

list

除左入口以外的任意入口：若该轨道当前正在录音，该轨道入口收到的列表会存入 mtr，并在前面加上 delta 时间（自上一个事件以来经过的时间）。列表允许的最大长度为 4096 项。

参数：

  • input [list]

anything

除左入口以外的任意入口：若该轨道当前正在录音，该轨道入口收到的符号会存入 mtr，并在前面加上 delta 时间（自上一个事件以来经过的时间）。

尽管 mtr 可以记录从 midiin 收到的 MIDI 消息的单个字节，但它为每个字节分别存储一个 delta 时间，而且不会像 seq 那样把 MIDI 消息格式化。若要记录完整的 MIDI 消息并在之后编辑它们，seq 更适合这项工作。另一方面，mtr 非常适合记录来自 Max 中几乎任何对象的数字、列表或符号序列：诸如 notein 或 pgmin 这样的专用 MIDI 对象，诸如 number box、slider 和 dial 这样的用户界面对象，或者其他任何对象。

一个文件要被读入 mtr 以进行回放，它必须采用正确的格式。一条 mtr 多轨序列甚至可以直接在文本文件中键入，只要它遵循该格式即可。不同轨道的内容在 mtr 文件中按顺序列出，每条轨道的格式如下。注意每行以分号（;）结束。

第 1 行：track <track number>;（存放后续数据的轨道）
第 2 行等：<delta time> <message>;
最后一行：end;（该轨道数据的结束）

参数：

  • input [list]

addevent

单词 addevent 后面跟一个列表（绝对时间和数据），会在特定时间向某条轨道添加一个事件。例如，消息 "addevent 1000 1" 会在时间 1000 处添加事件 1。该消息可以在轨道正在录音、播放或停止时发送。该消息只在轨道专用入口中有效，不能发给左入口。

参数：

  • absolute time-data [list]

clear

左入口：清除 mtr 的内容。单词 clear 后面跟一个或多个轨道编号，会清除这些轨道。

其他入口：清除与该入口对应的轨道。

参数：

  • tracks [list]

cleareventat

单词 cleareventat 后面跟一个列表（绝对时间和匹配条件），会清除在特定时间与条件完全匹配的所有事件。与 deleteeventat 不同，cleareventat 不会删除该事件所占用的时间。例如，若事件位于时间 1000、2000 和 3000，而位于 2000 的事件被清除，下一个事件仍留在时间 3000。该消息可以在轨道正在录音、播放或停止时发送。该消息只在轨道专用入口中有效，不能发给左入口。

参数：

  • absolute time-matching criteria [list]

definelengthandstop

左入口：停止录音，并把轨道的长度设为当前的录音时间。相比之下，stop 消息不会设置轨道的长度；总录音长度（可在 info 字典中获取）由这两个消息共同定义，它由录音开始到收到 stop 或 definelengthandstop 之前所记录的最后一个事件之间的时间构成。单词 definelengthandstop 后面跟一条或多条轨道，会停止并设置这些轨道的长度。

其他入口：停止并设置与该入口对应的轨道的长度。

参数：

  • tracks [list]

delay

左入口：单词 delay 后面跟一个数字，会把每条轨道的第一个 delta 时间值设为该数字，使所有轨道在收到 play 消息后经过这段时间才开始回放。

其他入口：设置与该入口对应的轨道的初始 delta 时间。

参数：

  • delay-time [int]

deleteeventat

单词 deleteeventat 后面跟一个列表（绝对时间和匹配条件），会删除在特定时间与条件完全匹配的所有事件。该事件所占用的时间也会被删除。"deleteeventat 1000" 会删除该轨道中绝对时间 1000 处的所有事件。消息 "deleteeventat 1000 3" 会删除绝对时间 1000 处包含 3 的事件。事件 "3 4 5" 不会被删除，因为它不是完全匹配。该消息可以在轨道正在录音、播放或停止时发送。该消息只在轨道专用入口中有效，不能发给左入口。

参数：

  • absolute time-matching criteria [list]

dictionary

消息 dictionary 后面跟一个名称，会把该特定字典载入 mtr，其中包括每条轨道序列中的所有事件。

参数：

  • dictionary name [symbol]

dump

消息 dump 发给 mtr 的任意入口时，会从 mtr 的左出口送出一个字典。与 info 或 bang 消息送出的字典不同，这个字典包含每条轨道序列中的各个事件。

first

左入口：单词 first 后面跟一个数字，会使 mtr 在收到 play 消息后等待这段时间才开始回放。与 delay 不同，first 不会改变轨道中第一个事件的 delta 时间值，它只是在从头回放之前等待一段时间（在第一个 delta 时间之外额外等待）。

参数：

  • wait-time [int]

info

与 bang 一样，把 info 消息发给 mtr 的左入口，会从左出口送出一个字典，其中包含该对象当前状态的信息。字典中既包含全局信息，也包含轨道专属信息。以 "global_" 开头的条目是指定特性的全局设置。若同一特性还有轨道专属设置，该取值会列在该轨道的信息之下。

mute

左入口：使 mtr 停止产生输出，但仍继续 "play"（仍在序列中向前推进）。单词 mute 后面跟一条或多条轨道，会使这些轨道静音。

其他入口：使与该入口对应的轨道静音。

参数：

  • tracks [list]

next

左入口：使每条轨道只输出其已记录序列中的下一条消息。收到 next 消息时，正在输出的每条消息的轨道编号、delta 时间和绝对时间会作为一个列表从最左出口送出。单词 next 后面跟一个或多个轨道编号，会输出这些轨道中存储的下一条消息。

其他入口：输出与该入口对应的轨道上存储的下一条消息。

参数：

  • tracks [list]

play

左入口：回放之前记录的所有消息，把它们按照录制时相同的节奏和相同的速度从对应的出口送出。单词 play 后面跟一个或多个轨道编号，会开始播放这些轨道。

其他入口：回放与该入口对应的轨道上的所有消息。当 play 消息发给特定的轨道入口时，可以给它两个可选参数：迭代次数和时间刻度。100 是原始的时间刻度。消息 "play 3 200" 会把该轨道播放三次，速度加倍。

参数：

  • tracks [list]

playat

左入口：从某个特定位置开始回放所有消息，该位置以 0-1 的归一化范围指定，其中 0 是开头，1 是结尾。消息会按照录制时相同的节奏和相同的速度从对应的出口送出。

其他入口：从某个特定位置开始回放与该入口对应的轨道上的所有消息。回放从某个特定位置开始，该位置以 0-1 的归一化范围指定。

参数：

  • position [float]

playatms

左入口：从某个特定位置开始回放所有消息，该位置以毫秒指定。消息会按照录制时相同的节奏和相同的速度从对应的出口送出。

其他入口：从某个特定位置开始回放与该入口对应的轨道上的所有消息。回放从某个特定位置开始，该位置以毫秒指定。

参数：

  • milliseconds [float]

read

左入口：调出标准的 Open Document 对话框，以便把之前保存的文件读入 mtr。只能载入 .txt、.pat 和 .json 文件。

其他入口：打开一个只包含与该入口对应的轨道的文件。

参数：

  • filename [symbol]

record

左入口：开始记录从其他入口收到的所有消息。单词 record 后面跟一个或多个轨道编号，会开始记录这些轨道。

其他入口：开始记录与该入口对应的轨道上的消息。

参数：

  • tracks [list]

rewind

左入口：把 mtr 重置到其已记录序列的开头。当用 next 逐条步进消息时，该命令用于返回到序列的开头。要在播放或录音过程中返回到序列的开头，只需重复 play 或 record 消息即可。当 mtr 正在播放或录音时，stop 消息应放在 rewind 消息之前。单词 rewind 后面跟一个或多个轨道编号，会返回到这些轨道的开头。

其他入口：把指针返回到与该入口对应的轨道的开头。

参数：

  • tracks [list]

stop

左入口：当 mtr 正在录音或播放时把它停止。单词 stop 后面跟一个或多个轨道编号，会停止这些轨道。

其他入口：停止与该入口对应的轨道。

参数：

  • tracks [list]

timescale

左入口：设置所有轨道的时间刻度。100 是原始的时间刻度，而 200 会使速度快一倍。该消息可以在轨道正在播放时设置。请注意，当轨道再次播放时，时间刻度会重置为 100。因此，强烈建议改用不会重置的 trackspeed 特性，而不要使用该消息。

其他入口：设置与该入口对应的轨道的时间刻度。

参数：

  • timescale [float]

touch

为与该入口对应的轨道打开/关闭触摸自动化录音。在轨道正在播放时把消息 "touch 1" 发给某个特定入口，会用该轨道入口收到的新数据覆盖已有的录音。时序不受影响。把消息 "touch 0" 发给某个特定入口会结束触摸自动化录音，此后该轨道中的任何事件都照常播放。touch 消息只在轨道已经在播放时才有效。

该消息用于单条轨道入口。要一次在多条轨道上启用/禁用触摸自动化录音，请使用 touchenable 和 touchdisable 消息，它们发给 mtr 的左入口。

参数：

  • off/on [int]

touchdisable

左入口：为指定的轨道关闭触摸自动化录音。发送消息 "touchdisable 2 3" 会结束轨道 2 和 3 上的触摸自动化录音。此后这些轨道中的任何事件都照常播放。该消息与 touchenable 消息配合使用。时序不受影响。touchdisable 消息只在轨道已经在播放时才有效。

参数：

  • tracks [list]

touchenable

左入口：为指定的轨道打开触摸自动化录音。在轨道正在播放时发送消息 "touchenable 2 3"，会用这些轨道入口收到的新数据覆盖轨道 2 和 3 已有的录音。使用消息 touchdisable 来停止触摸自动化录音。时序不受影响。touchenable 消息只在轨道已经在播放时才有效。

参数：

  • tracks [list]

unmute

左入口：撤销之前收到的任何 mute 消息。单词 unmute 后面跟一个或多个轨道编号，会取消这些轨道的静音。

其他入口：取消与该入口对应的轨道的静音。

参数：

  • tracks [list]

write

左入口：调出标准的 Save As 对话框，使 mtr 的内容可以保存为单独的文件。若指定的文件名（作为参数给出）以 .json 结尾，则保存一个 JSON 格式的文件。

其他入口：写入一个只包含与该入口对应的轨道的文件。

参数：

  • filename [symbol]

writejson

左入口：调出标准的 Save As 对话框，使 mtr 的内容可以保存为单独的 JSON 格式文件。与 write 消息不同，writejson 把时间写成 float，从而精确保留事件的时序。

其他入口：写入一个 JSON 格式的文件，其中只包含与该入口对应的轨道。

参数：

  • filename [symbol]

输出

anything

所有轨道出口：当最左入口收到 play 消息时，每条轨道中存储的消息会按照录制时相同的节奏和相同的速度从该轨道的出口送出。在单条轨道的入口收到 play 消息会播放该特定轨道。

当最左入口收到 next 消息时，每条轨道中的下一条消息会从它对应的出口送出。单词 next 在单条轨道的入口收到时，会送出该轨道中的下一条消息。

list

左出口：每当响应 next 消息送出一个值时，该值的轨道编号、delta 时间和绝对时间会作为一个三项列表从左出口送出。
