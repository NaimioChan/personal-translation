MSP

poly~

管理补丁的复音 / DSP

描述

用 poly~ 把补丁封装在对象框内，把补丁文件名和想要加载的实例数指定为 poly~ 对象的参数，并控制已加载补丁实例中的对象处理与路由。

讨论

poly~ 对象把其入口收到的信号和事件（消息）送往补丁实例内部的 in 和 in~ 对象，并处理来自 poly~ 对象各实例的信号或事件输出，用的是 out 和 out~ 对象。

参数

patcher-name [symbol] 可选

第一个参数必须指定要加载的补丁名称，该补丁必须已经存在且位于 Max 搜索路径中。为 poly~ 对象提供了补丁参数时，不会自动打开子补丁窗口供编辑。

number-of-instances [int] 可选

补丁实例的数量对应于可用「声部」的数量。该数字可以是 1 与 1023 之间的任意数字，并且可以用 voices 消息动态更改。

'up' and up-sampling-factor [symbol] 可选

使用 up 参数后跟一个为 2 的幂的数字，对当前加载的补丁进行升采样本地 DSP 处理（例如，up 2 在 44100 Hz 的采样率下指定 88200 Hz）。升采样可以用 up 消息动态更改。

'down' and down-sampling factor [symbol] 可选

使用 down 参数后跟一个为 2 的幂的数字，对当前加载的补丁进行降采样本地 DSP 处理（例如，down 2 在 44100 Hz 的采样率下指定 22050 Hz）。降采样可以用 down 消息动态更改。

'args' and list-of-argument-values [symbol] 可选

使用参数 args 并在其后跟一个参数值，可以初始化所加载补丁中的任何井号参数（例如 args #1）。若使用该参数，args 必须是最后一个使用的参数词；出现在单词 args 之后的一切都会被当作参数值。

特性

args [20 atoms]

用消息为 poly~ 对象所加载的补丁指定参数时，必须通过设置 patchername 特性重新加载该补丁，新参数才会在初次加载之后生效。

filterparams [int] : 0 >= 9.0.0

启用后，通过经典参数对象（例如 live.dial 或 number，后者打开了 parameter_enable）定义的参数不会出现在顶层补丁的参数列表中。通过 param 对象定义的参数则始终会发布到顶层。

被过滤的参数会出现在 poly~ 局部的参数列表中，类似于参数出现在 amxd~ 对象内部的方式。
可选值：

0 = 'Off'
1 = 'Filter non-'param' Parameters' ( 过滤非 param 参数 )
只有由 param 对象定义的参数才会出现在顶层补丁的 Parameter Window 中。

legacynotemode [int] : 0 >= 8.0.0

设为 1 时，legacynotemode 允许 note 和 midinote 消息使用旧版（Max 8 之前）的声部分配算法，它会持续播放声部 1。设为 0 时，note 和 midinote 消息会循环使用最近最少使用的声部。

midimode [int] : 0 >= 7.2.0

当 midimode 设为 '1' 时，所有送往 poly~ 的 MIDI 消息都会被送往所有声部。注意这不适用于 mpeevent 消息。若要把所有 mpeevent 消息送往所有声部，请把声部参数设为 '-1'，例如：'mpeevent 1 1 2 210 117'（一条发往所有声部的触后消息）。

mpemode [int] : 0 >= 7.2.0

当此特性设为 '1' 时，poly~ 会基于 mpeevent 消息的声部参数执行直接声部分配。

parallel [int]

当此特性被设为启用并行处理时，poly~ 对象会启用多线程，为所有补丁实例运行音频处理。若禁用，poly~ 会在音频处理线程中运行所有补丁实例。只要改动了 parallel 特性，就必须重启 DSP 链。当 Max 由 Live 应用程序托管时，此特性会被禁用。

注意：目前你还不能把单个子补丁指定到另一个核心上。启用后，此特性会把声部数分配到可用的处理器数量上。它主要面向同一个 poly~ 对象的多个声部中占用大量 CPU 的补丁，而多线程开销主要对较大的信号向量大小（至少 32 或更大）才有用。其他情形不会获益。使用默认的 threadcount（等于物理核心数）最佳。

patchername [32 symbols]

别名：patchernames

设置加载到 poly~ 对象中的一个或多个补丁文件的文件名。poly~ 对象可以在不同的声部上加载不同的补丁，具体做法是把它指定为 patchername/patchernames 特性的参数。若 poly~ 没有 voices 参数，则键入的 patchername 特性所指定的补丁总数就是声部数；若有 voices 参数，则各补丁会循环重复，直到达到声部号为止。你不能通过给 poly~ 的 patchername 特性提供多于声部数的文件名来增加声部数。不过，你可以在设置 patchername 的取值之前，先用 voices 特性增加声部数。

replicate [int] : 1 >= 8.0.0

复制输入

resampling [int]

切换是否使用高质量重采样滤波器。这些滤波器默认启用。

steal [int]

启用声部抢占会让 poly~ 对象把 note 或 midinote 消息中的数据送往仍被标记为 "busy" 的实例；这可能会产生咔哒声，取决于这些实例如何处理打断。声部抢占默认禁用。

target [int]

后续消息（除 poly~ 对象自身专门使用的消息之外）到达 poly~ 对象入口时，将由这个 poly~ 实例接收 —— 例如，消息 target 2 会把消息路由到第二个实例。若 target 消息指定的取值大于所加载补丁当前的实例（副本）数量，消息会被送往编号最大的实例（例如，把消息 target 2 发往只包含单个实例的 poly~ 对象时，后续消息会被送往第一个实例）。消息 target 0 会把输入送往所有实例，而用任何负数作为 target 消息的取值都会禁用送往所有实例的输入。

voices [int]

声部数

vs [int]

指定 poly~ 对象所加载补丁的信号向量大小。信号向量大小会在下一次编译 DSP 链时被设置。vs 消息不会强制重新编译 DSP 链。vs 0 表示不指定固定向量大小。默认值是当前的信号向量大小。

zone [int] : 0 >= 7.2.0

用此特性设置 poly~ 要监听的 MPE 'zone'。默认值是 '0'（忽略区域）。

消息

bang

向加载到 poly 对象中的补丁发送一个 bang。该消息的结果由所加载的补丁决定。

int

执行专属于用户自行设计的 poly~ 补丁本身的功能。

参数：

  • input [int]

float

执行专属于用户自行设计的 poly~ 补丁本身的功能。

参数：

  • input [float]

list

若要向 poly~ 实例发送一条以用于控制 poly~ 对象本身的某个词开头的消息，请以 list 一词开始这条消息。例如，把消息 list target 2 发往 poly~ 的左入口，会把 target 2 从所有 in 1 对象的出口送出，而不是把当前目标实例改为第二个补丁。

参数：

  • message [list]

anything

poly~ 的入口与出口数量由所加载的补丁决定。由 poly~ 对象加载的补丁，其入口同时接受信号连接与事件连接。

信号在已加载的补丁内部通过 in~ 对象（用于信号）或 in 对象（用于事件）进行路由。poly~ 对象的入口总数由已加载补丁中 in~ 或 in 对象的最高编号决定（例如，若有一个参数为 3 的 in~ 和一个参数为 4 的 in，则 poly~ 对象会有四个入口。即使并非每个入口都有对应的 in~ 对象，所有入口也都接受信号连接。

信号输入会送入所有实例。

参数：

  • message [list]

(drag)

把补丁从 Max File Browser 拖到 poly~ 对象时加载文件。

allnotesoff

通过向每个正在播放音符的实例发送一条消息，停用所有正在播放的音符；该消息由最近通过 note 或 midinote 消息收到的 MIDI 音高后跟零力度（note off 消息）组成。

assignpatcher

用 assignpatcher 把一个具名补丁加载到某个编号的声部位置，其他声部上已分配的补丁保持不变。assignpatcher 消息不能用来增加声部数——它的第一个声部号参数必须介于 1 与当前声部总数之间。此外，assignpatcher 只有在补丁已经通过参数加载到 poly~ 的第一个实例，或者已通过 patchername 特性加载之后才会生效。
使用 assignpatcher 消息之后，patchername 特性的内容会被修改，使其为当前的每一个声部都包含对应的具名补丁。

参数：

  • instance-index [int]
  • oatcher-name [symbol]

busymap

报告由参数指定编号的声部的忙碌状态，从 poly~ 对象的指定消息出口送出。

参数：

  • message-outlet-number [int]

bypass

让传入的信号直接通过。第一个参数指定声部，第二个参数指定状态。若要旁通所有声部，请发送消息 'bypass 0 1'。

参数：

  • voice [int]
  • on/off [int]

(mouse)

双击 poly~ 会打开一个显示窗口，可在其中查看已加载补丁的内容。

down

使用 down 消息后跟一个为 2 的幂的数字，对当前加载的补丁进行降采样本地 DSP 处理（例如，down 2 在 44100 Hz 的采样率下指定 22050 Hz）。降采样不是动态的。必须重启 DSP，改动才能生效。虽然 up 和 down 都是允许发往 poly~ 对象的消息，但 down 消息优先于 up。

参数：

  • sampling-factor [int]

exclude

发送单词 exclude，后跟一个声部号和一个 1，会阻止某个 poly~ 实例在 poly~ 收到 note 或 midinote 消息时通过音符分配收到消息。默认情况下，所有声部都启用了音符分配。单词 exclude 后跟一个声部号和一个 0，会重新让该实例能够在 poly~ 收到 note 或 midinote 消息时接收消息。

参数：

  • voice-number [int]
  • status [int]

midievent

单词 midievent 后跟两到四个数字，会向 poly~ 发送一条 MIDI 事件。前三个数字参数是 MIDI 消息的字节。第四个参数是可选的，它是一个用于 MIDI 音符消息的失谐参数。midievent 消息旨在与 polymidiin 对象配合使用。

参数：

  • MIDI-message (2 to 4 numbers) [list]

midinote

midinote 消息后跟两个或更多取值。音符取值通常是指定 MIDI 音符号和力度值的两个数字，但对于工作方式与标准 MIDI 模型不同的补丁，可以使用任意数字。

若第二个音符取值不为 0，poly~ 对象会把音高力度路由到第一个可用的实例。若力度为 0（即 MIDI note-off 消息），音高力度会被送往生成该音符的 poly~ 实例。要确定 midinote 消息会被送往已加载补丁的哪个实例，请发送 0（非忙碌）或 1（忙碌）消息给位于该已加载补丁中的 thispoly~ 对象。

参数：

  • voice [int]
  • note-values [list]

mpeevent

MPE 事件消息是一个列表，由符号 mpeevent 后跟 6 个整数构成，这 6 个整数分别指定 Zone First Channel、Zone Index、Voice Number、Channel Number、MIDI Message Number 和 Data。可以把该消息发送给封装在 poly~ 对象中的补丁，做法是使用 polymidiin 对象。

参数：

  • message [list]

mute

针对由 poly~ 对象加载的补丁的指定实例关闭信号处理，并把一条 bang 消息送往该指定实例的 thispoly~ 对象。把 0 作为第二个参数发送会打开该补丁实例。消息 mute 0 1 会静音所有实例，而 mute 0 0 会打开补丁所有实例的信号处理。若用 mute 0 1 消息静音了所有实例，则在用 mute 0 0 消息解除所有静音之前，无法单独解除某个实例的静音。

参数：

  • instance [int]
  • on/off-flag [int]

mutemap

从指定的 poly~ 消息出口报告声部静音情况

参数：

  • outlet-number [int]

note

单词 note 后跟一条消息，会把数据送往补丁的第一个实例中的第一个 in 对象，该实例尚未通过把 1 发送给补丁实例内部的 thispoly~ 对象而把自己标记为 "busy"。

参数：

  • voice-allocated-data [list]

notemessage

notemessage 消息用于向每个活动声部（即由 poly~ 对象加载的子补丁的单个实例）发送消息。该消息直接发送到 poly~ 对象，发送方式是借助 in 对象（在寻址 poly~ 对象时，子补丁中的第一个 in 对象专用于 midinote 消息）。顺序上，notemessage 消息跟随在 note 消息之后——该消息的第一个参数被当作音高，用作后续 notemessage 消息的 ID。notemessage 消息的长度可以任意，并可以在子补丁内部解包和路由。在某些情形下，note-off 消息在完成之前会涉及一段时间（例如使用 adsr~ 对象时），notemessage 消息会持续被接收处理，直到该声部被关闭。

注意：使用 notemessage 时，要正确关闭一个声部的唯一办法是向 thispoly~ 对象送入信号，该对象位于 poly~ 对象所加载的子补丁中（若没有信号连接到 thispoly~ 对象，MIDI note-off 消息会立即关闭声部分配）。

参数：

  • message [list]

open

单词 open 后跟一个数字，会打开补丁的指定实例。你可以查看补丁任意实例的活动，最多到声部数（由 voices 消息或 poly~ 对象的参数设置）。不带参数时，open 消息会打开当前作为目标的实例（参见 target 消息）。

参数：

  • instance-index [int]

setvalue

单词 setvalue 后跟一个实例索引（从 1 开始）以及任意消息，会把该消息送给 MC 包装中的单个声部。setvalue 0 后跟一条消息，会把该消息送给所有声部。setvalue 消息可以用在任何入口中。setvalue 指定的实例索引会覆盖 target 特性的当前取值，但在消息送出之后不会改变它。

参数：

  • instance-index [int]
  • message [symbol]
  • message arguments [list]

threadcount

单词 threadcount 后跟一个数字，设置用于划分 poly~ 实例音频处理的线程数。默认值是你电脑上可用的处理器核心数。通常，为获得最佳性能，线程数应设为电脑的处理器核心数。这也可以通过发送消息 threadcount 0 来实现。若 poly~ 对象有十六个实例且 threadcount 为 4，则四个线程中每个线程都会处理四个 poly~ 实例的音频。

参数：

  • number of threads [int]

up

使用 up 消息后跟一个为 2 的幂的数字，对当前加载的补丁进行升采样本地 DSP 处理（例如，up 2 在 44100 Hz 的采样率下指定 88200 Hz）。升采样不是动态的。必须重启 DSP，改动才能生效。虽然 up 和 down 都是允许发往 poly~ 对象的消息，但 down 消息优先于 up。

参数：

  • sampling-factor [int]

wclose

关闭参数所指定编号实例的窗口。若没有使用数字参数，wclose 会关闭编号最大的那个补丁窗口。

参数：

  • instance-index [int]

输出

anything

poly~ 对象的出口数量由已加载补丁中 out 和 out~ 对象的最高参数编号之和决定。例如，若有一个 out 3 对象和一个 out~ 2 对象，则 poly~ 对象将有六个出口。与 out~ 对象对应的信号输出位于 poly~ 对象中的最左侧，其后是与 out 对象对应的事件出口，再后面是一个声部号出口。

若补丁实例不止一个，送入每个补丁实例中各 out~ 对象入口的信号会被混合，并出现在 poly~ 对象相应的出口上。
