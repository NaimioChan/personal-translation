Max

follow

把现场演奏与录制的演奏进行比较

描述

follow 会记录音高，也可以给它一个 MIDI 文件，这时它会查看该文件的 note-on 并忽略其他事件。当它处于「跟随」状态时，会输出最后匹配到的音符的索引。

参数

filename [symbol] 可选

该参数是一个包含先前录制序列的文件名，补丁载入时会自动读入 follow。

消息

bang

开始播放存储在 follow 中的序列。

int

当 follow 正在录音时，其入口收到的数字会被记录为一段序列。这些数字可以是 MIDI 消息的字节（来自 midiformat 或 midiin），与 seq 对象完全相同。不过，follow 与 seq 的不同之处在于它能记录单个整数；用 follow 可以把音符记录成单个音高值。无论演奏是被记录为完整的 MIDI 消息还是仅记录为 note-on 音高，follow 之后都能在跟随演奏时有效地逐条走过这些 note-on 音高数字。

参数：

  • input [int]

(inlet1)

当 follow 处于跟随状态时，其入口收到的数字会与序列中记录的数字进行比较。当收到的数字与序列中的数字匹配时，follow 会送出该数字的索引。

参数：

  • input [int]

float

转换为 int。

参数：

  • input [float]

append

在已存储序列的末尾开始录制，不清除现有序列。

delay

delay 一词后面跟一个数字，以毫秒为单位设置所记录序列中第一个事件的起始时间。

参数：

  • onset-time (milliseconds) [int]

dump

调出标准的 Open Document 对话框，以便把先前录制的序列或标准 MIDI 文件作为文本打开，并显示在新的 Untitled 文本窗口中。这实际上对 follow 对象没有直接影响，但可以让你查看或编辑序列，把改动保存到文件中，之后再用 follow 对象配合 read 消息载入新文件。

follow

follow 消息是把 follow 与 seq 区分开来的主要特性。实际上，follow 就像一个读谱器，把现场演奏与先前存储的演奏进行比较。

follow 一词加一个数字，会让 follow 从指定的索引（即其自身存储序列中指定的事件）开始，把收到的数字与自身存储的数字进行比较。当 follow 处于跟随状态，且收到的数字与 follow 中记录的数字匹配时，它会送出该数字的索引。

follow 对象是一个宽容的读谱器，即使收到的数字与所记录的序列不完全匹配，它也会尽量跟随。如果到来的数字与序列中的下一个数字、或再往后的两个数字中的任何一个都不匹配，follow 什么也不做。如果到来的数字与序列中最多提前两个音符的数字匹配，follow 会认为演奏者只是漏掉了一两个音符，并跳到匹配到的那个数字。

参数：

  • index [int]

next

让 follow 送出它当前正试图匹配的索引和存储的数字，并前进到下一个数字。

print

在 Max Console 中打印所记录序列的最初几个事件。

read

read 一词不带参数时会弹出标准的 Open Document 对话框，用于选择要载入 follow 的序列文件。若 read 后面跟一个 symbol 文件名参数，则会找到指定的文件并载入 follow。

参数：

  • filename [list]

record

开始记录入口收到的整数。

start

start 一词单独使用与 bang 效果相同。start 一词后面跟一个数字，会以该数字决定的速度播放存储的序列。消息 start 1024 表示正常速度。若数字为 512，follow 会以原始录制速度的一半播放该序列，start 2048 则以原始速度的两倍播放，依此类推。

参数：

  • tempo [int]

stop

让 follow 停止录音、播放或跟随。从录音直接切换到播放、从跟随切换到录音等时，不必先收到 stop 消息。

write

打开标准的 Save As 对话框，把 follow 序列保存为文件。

参数：

  • filename [list]

输出

int

左出口：当 follow 处于跟随状态，且入口收到的数字与存储序列中的下一个数字（或再往后的两个数字之一）匹配时，会送出匹配到的数字的索引。收到 next 消息时，也会送出下一个数字的索引。

右出口：当 follow 收到 bang 或 start 消息时，会播放所记录的数字。当 follow 处于跟随状态并收到 next 消息时，会送出所记录序列中的下一个数字。
