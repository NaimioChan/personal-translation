mcs.tapout~

延时线输出（多通道 I/O）

描述

必须把 tapin~ 对象的出口连接到 tapout~ 的左入口，延迟线才能工作。

tapout~ 对象有一个或多个入口以及一个或多个出口。某个入口收到的延迟时间信号或数字会影响该入口正下方出口所送出的输出信号。

在入口收到延迟时间信号时，tapout~ 对象是亚采样点精确的。当入口收到的是延迟时间数字时，它不是亚采样点精确的。

参数

initial-delay [number] ms 可选

一个或多个初始延迟时间，单位为毫秒，每个所需的延迟「抽头」入口-出口对对应其中一个。例如参数 50 100 300 会创建一个带三个独立「抽头」的 tapout~ 对象，它们对应三个入口和三个出口。若某个入口连接了 signal，则该入口-出口对所对应的初始延迟时间会被忽略。可用的最小延迟时间由当前信号向量大小决定（Options->Audio Status）。若 Signal Vector Size 设为 64，则任何小于 64 个采样点的延迟都会被限制为最少 64 个采样点。

特性

unique [int] >= 8.1.2

启用 unique 特性后，所连接的 mc.tapin~ 对象的各个相继通道会依次分配给 tapout~ 的各个信号出口。若源 mc.tapin~ 的通道数少于 tapout~ 的信号出口数，则分配给 tapout~ 额外通道时会从 mc.tapin~ 的第一个通道重新开始。该特性对 mc.tapout~ 对象是禁用的，因为它本来就提供一个多通道信号出口，其中包含 mc.tapin~ 中存在的所有通道。

消息

int

若 signal 没有连接到 tapout~ 的某个入口，则使用固定延迟算法，该入口收到的 float 或 int 会设定相应出口所送出信号的延迟时间。当延迟时间被改动时，这可能会让输出中出现咔嗒声。不过，固定延迟适合诸如混响之类延迟时间不动态变化的许多应用，而且它的计算开销比连续延迟算法小。

参数：

  • delay-time [int]

float

若 signal 没有连接到 tapout~ 的某个入口，则使用固定延迟算法，该入口收到的 float 或 int 会设定相应出口所送出信号的延迟时间。当延迟时间被改动时，这可能会让输出中出现咔嗒声。不过，固定延迟适合诸如混响之类延迟时间不动态变化的许多应用，而且它的计算开销比连续延迟算法小。

参数：

  • delay-time [float]

list

左入口：允许同时改变多个固定延迟时间。列表中的第一个数字设置第一个出口的延迟时间，依此类推。若与 list 中各取值对应的入口中有任何一个连接了 signals，这些取值会被跳过。

参数：

  • delay-times-corresponding-to-outlets [list]

signal

若 signal 连接到了 tapout~ 的某个入口，则其下方出口送出的信号会使用连续延迟算法。传入的信号取值表示延迟时间，单位为毫秒。若信号上升得足够缓慢，输出的音高会下降；反之，若信号下降得足够缓慢，输出的音高会上升。连续延迟算法的计算开销比未把信号连接到 tapout~ 入口时所用的固定延迟算法更大。

tapconnect

tapconnect 一词会把一个 tapout~ 对象远程连接到一个可用的 tapin~ 对象。

输出

signal

tapout~ 的每个出口对应由 tapin~ 对象写入的延迟线中一个可单独控制的「抽头」。从某个 tapout~ 出口送出的输出信号，是 tapin~ 的输入被延迟相应毫秒数之后的结果，该毫秒数由该出口正上方入口收到的数字控制或信号控制来指定。
