Node for Max

node.script

在 Max 中控制本地的 Node.js 进程

描述

在 Max 中控制本地的 Node.js 进程。以 script 开头的消息控制 Node 脚本的生命周期（start 启动、stop 停止）。其他消息会直接发送给该进程。

讨论

Node 是用于编写应用程序的 JavaScript 框架。要详细了解 Node，请访问他们的 网站。

有些 Max 补丁想做的事情很难在 Max 里做到。例如，可能希望从某个网址拉取一些数据，然后解析并分析这些数据以生成合成参数。又或者，可能想监视本地文件夹中的文件，在文件夹内容发生变化时触发 Max 内部的某些操作。对于这类长时间运行的任务，它们可能需要某种复杂且持久的状态，此时 Node 可以是非常有用的工具。

使用 Node 的另一个原因，是利用 Node Package Manager（NPM）中注册的大量开源模块。这些包中包含 JavaScript 代码库，可以做从解析日期、训练神经网络、运行 Web 服务器到编写和弦进行等各种事情，远不止这些。Node for Max 帮助把这些资源提供给 Max 程序员使用。

为了与 Max 通信，Node 脚本使用 "max-api" Node 模块。这组函数简化了在 Node 应用程序与 Max 之间发送数据的过程。该 API 可以为 Max 消息挂接处理函数；把 Max 字典解析为 JSON 对象；并读取、更新和设置 Max 内的具名字典。关于如何使用该 API 的示例，参见 Node for Max 包随附的代码示例，以及 https://docs.cycling74.com/apiref/nodeformax 处的 API 文档。

node.script 对象引用一个 JavaScript 源文件，因此它与 js 对象有一些重叠之处。不过，两者之间也有一些重要差别。与 js 不同，node.script 运行在单独的进程中。这在并行化方面有一些好处，因为 Max 与 Node 脚本可以运行在不同的核心上。Node 脚本是一个完整的应用程序，这意味着一旦启动，它就有自己的运行循环，并且在何时运行什么代码上拥有完全的自由。它像其他任何应用程序一样响应事件，甚至可以有自己的图形用户界面（GUI）。发送给 Node 脚本的消息会异步执行，因为 Node 与 Max 运行在各自独立的进程中。最后，用 node.script 运行的脚本可以访问完整的 Node 库，用于网络通信、文件 I/O 等。

参数

script [symbol] 可选

Node 应用程序的入口点。向 node.script 发送 start 消息即可开始运行该脚本。

特性

args [16 atoms]

启动时传递给 Node 脚本的参数。注意，该特性只有与 autostart 特性一起使用时才有意义。否则，node.script 会使用随 start 消息提供的参数。

autostart [int]

自动启动 Node 脚本，无需 script start

defer [int]

为 false（默认值）时，来自 Node 的消息会在调度器线程上以与其他 Max 消息相同的优先级处理。启用 defer 会把处理移到低优先级队列的末尾，与 metro 上的 defer 特性相同

log_path [symbol]

仅调试用：指定写入调试日志的路径，例如 ~/Documents/debug.txt

node_bin_path [symbol]

覆盖内置的 Node 可执行文件。可选。仅当你希望使用与 Max for Node 附带的 Node 可执行文件不同的 Node 可执行文件时才使用该特性（可能是出于兼容性原因想使用较旧的版本）。

npm_bin_path [symbol]

覆盖内置的 NPM 可执行文件。可选。仅当你希望使用与 Max for Node 附带的 NPM 可执行文件不同的 NPM 可执行文件时才使用该特性（可能是出于兼容性原因想使用较旧的版本）。

pm_path [symbol]

仅调试用：指定进程管理器脚本的路径

restart [int] : 1

启用 restart（默认）后，node.script 会在处理函数回调中的 node 代码崩溃后自动重启。若禁用 restart，则不会自动重启。

running [int] 只读

只读：若有正在运行的 Node 进程则为 1，否则为 0

watch [int]

若为 true，node.script 应在源文件发生变化时自动重新启动 Node 脚本

消息

bang

向正在运行的 Node 脚本发送 bang 消息

anything

向正在运行的 Node 脚本发送任意长度的消息。也可以用来发送字典，字典会被自动转换为 JSON。

参数：

  • anything [list]

api

打开 JS 文档

(mouse)

双击以显示 Node 脚本

reveal

在 Finder 或 Explorer 中显示 Node 脚本

script

以符号 script 开头的消息用于启动、停止和查询 Node 进程。script 之后的符号决定该消息将如何处理。若适用，后续参数会传递给相应的处理函数。

npm - 与 Node Package Manager（npm）交互。若 node 脚本位于某个 node 包中，则可以用该消息（例如）把 package.json 中列出的模块依赖安装到 node_modules 中。npm 消息假定 package.json 与作为 node.script 第一个参数指定的脚本位于同一个文件夹中。跟在 npm 之后的符号会作为参数发送给 npm（例如 script npm install 会运行 `npm install`）。

processStatus - 获取一个描述正在运行的 Node 进程（若有）状态的字典

reboot - 很少使用。若 Node 进程管理器已崩溃，则重启它。

running - 若有正在运行的 node 进程则返回 1，否则返回 0

status - 返回一个字典，其中包含所安装 Node 版本的信息

start - 用给定（可选）的参数开始运行 Node 脚本。跟在 start 之后的参数会作为命令行参数提供给 Node 脚本。

stop - 停止运行 Node 脚本

参数：

  • arguments [list]

stdin

把字符流直接发送到 stdin。向 node.script 发送的、跟在 stdin 之后的内容会直接送到正在运行的 node 脚本的标准输入。注意，Max 会在所发送消息的末尾添加一个换行字符。

参数：

  • stream [list]
