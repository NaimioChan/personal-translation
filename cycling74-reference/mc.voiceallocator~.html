MC

mc.voiceallocator~

管理事件的声部号

描述

mc.voiceallocator~ 对象为传入消息分配声部号，并用一个可选的多通道信号判定声部的忙碌状态。它还维护一张声部 busy map，供其他 MC 对象使用，以避免对未在响应事件而主动产生音频的通道做不必要的处理。

参数

voice count [int] 可选

可选参数可以设置 mc.voiceallocator~ 对象会使用的最大声部号数量。若未提供参数，默认声部数为 0，这意味着 mc.voiceallocator~ 会按所连接多通道输入的通道数来设置其最大声部数。若没有连接多通道输入，默认声部数为 16。

特性

initialbusystate [int] : 1

设置初始的忙碌状态。默认值为 1。在音频开启后发送事件之前，把它设为零可避免高 CPU 占用。

name [symbol]

name 特性为该对象的 busy map 指定一个全局名。默认情况下，mc.voiceallocator~ 的 busy map 没有名称，只对同一补丁内的 MC 对象可用。具名 busy map 对所有用 busymapname 特性引用它的 MC 对象（任何补丁中）都可访问。

steal [int]

steal 特性设为 1 时，消息可以穿过 mc.voiceallocator~，并且在所有声部都已分配的情况下仍会被分配声部号。设为 0 时，若所有声部都已分配，消息不会被放行，也不会被分配声部号。

voices [int]

voices 特性设置 mc.voiceallocator~ 会分配并输出的最大声部号。voices 为 0（默认值）时，活动声部数由所连接多通道信号的通道数决定。若没有连接信号，mc.voiceallocator~ 默认使用 16 个声部。

消息

bang

bang 消息会被重复送往左出口，并在前面加上从右出口送出的一个新声部号。

int

数字会被重复送往左出口，并在前面加上从右出口送出的一个新声部号。

float

数字会被重复送往左出口，并在前面加上从右出口送出的一个新声部号。

list

列表会被重复送往左出口，并在前面加上从右出口送出的一个新声部号。

anything

消息会被重复送往左出口，并在前面加上从右出口送出的一个新声部号。

endevent

endevent 一词后面跟一个由 event 消息定义的事件名时，会释放与该事件关联的声部。整条 endevent 消息会被重复送往左出口。

参数：

  • event name [list]

event

event 一词后面跟一个事件名和一条消息时，会把整条 event 消息从左出口送出，并在前面加上一个新分配的声部号。该名称之后可以和 endevent 消息一起使用，用来释放与该事件关联的声部。

参数：

  • event-name [list]

holdevent

holdevent 一词后面跟一个事件名和一条消息时，会把整条 holdevent 消息从左出口送出，并在前面加上一个新分配的声部号。该名称之后可以和 endevent 消息一起使用，用来释放与该事件关联的声部。与 event 消息不同，holdevent 会显式保持该具名事件，直到所连接的音频归零。

参数：

  • event-name [list]

printbusymap

把 mc.voiceallocator~ busy map 的当前状态以列表形式打印到 Max Console。

release

release 一词后面跟一个声部号时，会释放该声部号（置为非忙碌状态）。不带参数时，release 会把所有声部置为非忙碌状态。

参数：

  • voice number [list]

releaseevent

releaseevent 一词后面跟一个由 event 消息定义的事件名时，会释放与该具名事件关联的声部号，但与 endevent 不同，它不会产生送往左出口的消息。

参数：

  • event-name [list]

signal

连接一个可选的多通道信号，可避免 mc.voiceallocator~ 在相应通道的信号电平降为零之前重新分配声部。
