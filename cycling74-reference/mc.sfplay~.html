mc.sfplay~

从磁盘播放音频文件（多通道）

描述

用 mc.sfplay~ 对象从磁盘播放音频文件。支持的格式包括 AIFF、WAVE、MP3、OGG、FLAC、M4A、CAF、WF64、WAVE64 和 Raw Data。

讨论

若要播放文件，你要向 mc.sfplay~ 发送 open 消息，然后发给它 1 开始、0 停止。open 接受一个参数，用来指定搜索路径中的文件名。你还可以用 preload 消息创建额外的 cue。这些 cue 可以引用其他文件，它们全都可以同时访问。open 消息设置 "current" 文件：也就是收到 1 时从头播放的那个文件，并被用作 preload 消息的默认对象。mc.sfplay~ 也可以连接到 sflist~ 对象中定义的 cue。由于多个 mc.sfplay~ 对象可以引用同一个 sflist~，这让你可以存储一份全局的 cue 列表。

参数

sflist-object-name [symbol] 可选

若第一个参数是 symbol，它指定一个 sflist~，mc.sfplay~ 对象将用它来播放 cue。若没有给出 symbol 参数，mc.sfplay~ 会播放它内部定义的 cue。

number-of-output-channels [int] 可选

设置作为一个多通道信号输出的通道数。最大通道数为 64，默认值为 1。若所播放的音频文件的输出通道数多于 mc.sfplay~ 对象，编号更高的通道不会被播放。若音频文件的通道数少于 mc.sfplay~ 对象，那些未被使用的通道会被置零。

buffer-size [int] 可选

还可以用一个额外的可选参数以采样点数指定磁盘缓冲区大小。一般而言，除非你在播放期间遇到丢音，否则我们建议使用默认的缓冲区大小。

对于通道数不超过 8 的实例，默认磁盘缓冲区大小为 483840；对于通道数超过 8 的实例，则为 80640 乘以通道数。

磁盘缓冲区大小会被舍入到最接近的 20160 的倍数。若该参数取值为 0，则使用默认的磁盘缓冲区大小。

position-outlet-flag [int] 可选

还可以用一个额外的可选参数为 mc.sfplay~ 对象创建用于显示定位信息的出口。把最后一个参数指定为 1，会在最右侧的 "bang on finish or halt" 出口左边创建一个出口，它输出一个与当前播放位置（单位：毫秒）对应的信号取值。

与所有 MSP 音频信号一样，这个播放位置是 32 位单精度浮点信号。若需要更高的精度，把最后一个参数指定为 2 会创建第二个出口，它输出第二个 32 位单精度浮点信号，其中包含单精度舍入误差。这两个信号合起来可提供接近双精度的浮点精度。（注意：经过几分钟后，单精度浮点取值就不再是采样点精确的了）把这两个信号与 hr.+~ 之类不受支持的 Max/MSP 高精度信号处理对象配合使用，就可以基于文件位置做采样点精确的计算

object-reference-name [symbol] 可选

若最后一个参数是一个 symbol，它指定一个名称，其他对象可用该名称引用 mc.sfplay~ 对象来访问其内容。

特性

audiofile [symbol] >= 7.0.0

指定由 mc.sfplay~ 对象载入的音频文件的名称/路径名。

basictuning [int] : 440 >= 7.0.0

为音高校正操作设置以 A 的频率为基准的调律标准（440 = 默认，范围为 400 - 500）

formantcorrection [int] : 0 >= 7.0.0

loop [int]

打开或关闭循环。

mode [symbol] >= 7.0.0

设置要使用的 timestretching 模式。每种模式都针对处理不同类型的音频素材做过优化。所有模式都是零延迟。

可选值：

'basic'（默认工作模式）
这是默认的工作模式。

'monophonic'（单声部音源（人声、长笛））
该模式最适合单声部乐器（例如独唱人声、长笛等）

'rhythmic'（针对瞬态保留做过优化）
该模式用于经过时间拉伸的打击乐。它能提供最佳的瞬态保留效果。

'general'（在频谱完整性与瞬态保留之间取得平衡）
该模式在一般情形下兼顾频谱完整性与瞬态保留。

'extremestretch'（用于拉伸比大于 2.0 的情形）
该模式用于拉伸比大于 2.0 的情形，追求更具艺术性的效果。

'efficient'（良好的 CPU 性能）
该模式追求良好的 CPU 性能与质量之间的折衷。

name [symbol]

名称

originallength [Time Value] : 0 ticks >= 7.0.0

音频文件以拍为单位的原始长度。followglobaltempo 用它来相对于全局走带速度计算速度。设置 originallength 会计算出 originaltempo。

音频文件的原始速度。followglobaltempo 用它来相对于全局走带速度计算速度。设置 originaltempo 会计算出 originallength。

单词 pitchcorrection 后跟 0 或 1，启用/禁用带共振峰校正的半音音准校正。若需要更全面的实时音准校正，请使用 mc.retune~ 对象。

pitchshift [float] : 1. >= 7.0.0

把音高移动指定为原始音高的倍数（即 2.0 = 音高加倍，.5 = 原始音高减半，等等）。

pitchshiftcent [int] : 0 >= 7.0.0

以正的或负的音分值来指定 pitchshift（即 100 = 升高一个半音，-1200 = 降低一个八度）。音分值可以用 int 或 float 指定。

quality [symbol] >= 7.0.0

选择 timestretching 输出的质量。
可选值：

'basic'（基础质量（默认））
'good'（良好质量）
'better'（更好的质量）
'best'（最高质量）

slurtime [float] : 0. >= 7.0.0

设置校正达到完全校正量所需的时间。通常，音符在起始处会有些不稳定，因为声音的起音阶段噪声较多，也因为歌手在音符起音之后会逐渐调整自己的音准。滑音时间使音高校正听起来自然，因为它模拟了这种效果。取值越大，适应时间越慢，校正要产生校正后的音高所需的时间也越长。不过，较长的滑音时间也能更好地保留颤音。

speed [float]

timestretch [int] : 0 >= 7.0.0

单词 timestretch 后跟 0 或 1，禁用/启用 timestretching。

在独立应用程序中启用 timestretch 时，mc.sfplay~ 的输出被限制为 2 个通道。

消息

int

左入口：若已用 open 消息打开了一个文件，1 会开始播放（最近打开的那个文件），0 则停止播放。大于 1 的数字会触发用 preload 消息定义过的提示，或根据 mc.sfplay~ 对象的保存状态定义过的提示。文件播放时，文件中的音频数据会按该对象拥有的通道数从信号出口送出。当一个提示播放完毕，或 mc.sfplay~ 被 0 停止时，会从右出口送出一个 bang。若该对象当前被指派给一个 sflist~ 对象（用 set 消息或键入型参数指派），int 会触发存储在 sflist~ 对象中的提示，而不是 mc.sfplay~ 内部的提示。若要让 mc.sfplay~ 重新使用自己的提示，给它发送不带参数的 set 消息。

参数：

  • start/stop-playback-of-cue-number [int]

float

右入口：定义音频文件的播放速率。取值为 1.0 时以正常速度播放音频文件。播放速率为 -1 时以正常速度倒放音频文件。播放速率为 2 时以两倍正常速度播放音频文件。播放速率为 .5 时以正常速度的一半播放音频文件。播放关闭时无法改变播放速率。

若要以负速度从某个提示开始播放，必须使用双向提示。

参数：

  • playback-rate [float]

list

左入口：给 mc.sfplay~ 一组依次播放的提示。一个列表中最多可以有 128 个提示。提示编号（用 preload 消息设置）可以是任意大于或等于 2 的整数。若列表中的某个提示编号尚未定义，它会被跳过，转而尝试下一个提示（若有）。若该对象当前被指派给一个 sflist~ 对象，列表会使用存储在 sflist~ 对象中的提示。否则使用存储在 mc.sfplay~ 对象内部的提示。

参数：

  • cues [list]

anything

左入口：若把 sflist~ 对象的名称发给 mc.sfplay~，后面再跟一个数字，则会播放 sflist~ 中该编号的提示（若存在）。

参数：

  • sflist-object-name [symbol]
  • cue-number [int]

(drag)

把一个音频文件从 Max File Browser 拖到 mc.sfplay~ 对象上时，该文件会被载入。

modout

左入口：modout 一词后面跟 1，会打开取模输出。若音频文件中的通道数少于 mc.sfplay~ 对象的通道数，启用取模输出后 mc.sfplay~ 对象会把音频文件的各个通道重复铺到 mc.sfplay~ 的所有通道上（而不是输出零）。例如，把一个单声道音频文件载入有两个通道的 mc.sfplay~ 对象，启用取模输出后它会在两个通道中都被播放。类似地，一个立体声音频文件在带四个出口的 mc.sfplay~ 对象上播放时，左声道会在通道 1 和 3 上播放，右声道则会在通道 2 和 4 上播放。消息 modout 0 会禁用该功能。

参数：

  • modulo-output-flag [int]

offset

左入口：offset 一词后面跟一个数字，以字节为单位指定采样的起始偏移量。默认值为 0。该取值在把采样点对齐、避免播放头部信息时很有用。

参数：

  • sample-start-offset (bytes) [int]

open

左入口：后面跟一个 AIFF、WAVE、MP3、OGG、FLAC、M4A、CAF、WF64、WAVE64 或 Raw 格式的音频文件或 CD 音频轨道的名称，会打开该文件供播放，并把它设为当前文件。open 一词后面跟一个文件名时，若该文件存在于 Max 的搜索路径中就会打开它。若不带文件名，open 会调出标准的打开文件对话框，让你选择一个文件。文件被打开时，它的开头会被读入内存，并且在打开另一个文件之前，只要给 mc.sfplay~ 发送消息 1，就可以从开头播放该文件。收到 open 消息时，此前的当前文件（若有）仍然保持打开，并且可以在用 preload 消息定义提示时按名称引用它。若已定义过使用此前当前文件的提示，即使该文件不再是当前文件，这些提示依然有效。

参数：

  • filename [symbol]

openraw

左入口：openraw 消息的功能与 open 完全相同，但允许你打开任意类型的文件用于播放，并把它设为当前文件。openraw 消息假定所打开的文件是采样率为 44100 Hz 的 16 位立体声文件，并假定没有需要忽略的头部信息（即偏移量为 0）。可以用 samptype、offset、srate 和 srchans 消息显式指定文件类型。

参数：

  • filename [symbol]

pause

左入口：pause 消息会让音频文件的播放暂停在当前播放位置。可以用 resume 消息重新开始播放。

preload

左入口：定义一个提示——一个大于或等于 2 的整数——用来指向文件的某个特定区域。之后收到该提示编号时，mc.sfplay~ 会播放该文件的这个区域。提示编号 1 始终是当前文件（最近用 open 消息打开的文件）的开头，且不能用 preload 消息修改。

preload 消息有多种形式。preload 一词后面跟一个必需的提示编号，取值在 2 到 32767 之间。若提示编号后面跟的是 Max 搜索路径中某个文件的文件名，或一个完整的文件路径名，该提示编号将播放指定的文件。注意，文件不必已用 open 消息显式打开才能用在提示里。若没有指定文件名，则使用当前已打开的文件。

在可选的文件名之后，可以指定一个可选的起始时间，单位为毫秒。若没有指定起始时间，则使用文件开头作为提示的起始点。在起始时间之后，可以指定一个结束时间，单位为毫秒。若没有指定结束时间，或结束时间为 0，提示会一直播放到文件末尾。若结束时间小于起始时间，提示仍会被定义，但不会播放。将来或许可以定义倒放的提示。

在起始时间和/或结束时间参数之后，有一个可选的方向缓冲区标志，用于对已存储的提示启用倒放。把该标志设为 1 会启用提示的倒放。默认设置为 0（关闭双向缓冲）。

最后一个可选参数用于设置播放速度。浮点取值会相对于该对象的全局播放速度来设置 mc.sfplay~ 对象的播放速度——全局播放速度由 speed 消息或 mc.sfplay~ 对象的右入口设定。默认值是 1。

在默认缓冲区大小（40320）且关闭双向缓冲的情况下，每个已定义的提示大约需要为每个 mc.sfplay~ 通道占用 40K 内存。打开双向缓冲后，每个提示占用的内存量会翻倍。

preload 消息总是被推迟到低优先级执行。pause、resume 和 int 消息则不是。若你在 overdrive 模式下遇到这些消息在你期望之前到达的问题（也就是说，在你预载完最近的提示之前就到达），可以使用 defer 对象。

print

左入口：打印对象的状态信息，以及所有当前已定义提示的列表。

resume

左入口：若播放此前被暂停，则从文件中暂停的位置继续播放。

samptype

左入口：samptype 一词后面跟一个符号，指定解读音频文件采样数据时使用的采样类型（从而覆盖音频文件实际的采样类型）。这有时被称为 “header munging”。在响应 openraw 消息读取文件时，假定的采样类型是 16 位整数。用 samptype 所做的修改不会更改磁盘上的文件。

支持以下类型的采样数据：

int8：8 位整数
int16：16 位整数
int24：24 位整数
int32：32 位整数
float32：32 位浮点数
float64：64 位浮点数
mulaw：8 位 “mu”-law 编码
alaw：8 位 a-law 编码

参数：

  • sample-type [symbol]
  • bit-depth [int]

seek

左入口：seek 一词后面跟一个以毫秒为单位的起始时间，会移到当前文件中的指定位置并开始播放。在起始时间之后，还可以指定一个可选的结束时间，它会设定播放停止的位置。seek 消息用于让你预览并调整某个提示的起始点与结束点。

注意：seek 消息总是被推迟到低优先级执行。若你在 overdrive 模式下遇到这些消息在你期望之前到达的问题（也就是说，在你已完成向新位置的定位之前就到达），那么请使用 defer 对象。

参数：

  • start-time [number]
  • end-time [number]

set

左入口：消息 set 后面跟一个 sflist~ 对象的名称时，会使 mc.sfplay~ 播放存储在 sflist~ 中的提示，只要它收到 int 或 list。不带参数的 set 消息会把 mc.sfplay~ 重置为在收到 int 或 list 时使用它自己内部定义的提示。

参数：

  • sflist-object-name [symbol]

signal

左入口：输入信号可用于以采样点精确的方式触发预先存储的提示。当左入口收到信号取值时，会监测该信号取值的整数部分。当输入信号的整数部分变为等于某个预先存储的提示的索引时，该提示就会被触发。负值会被忽略。

srate

左入口：srate 一词后面跟一个数字，指定解读音频文件采样数据时使用的采样率（赫兹）（从而覆盖音频文件实际的采样率）。这有时被称为 “header munging”。在响应 openraw 消息读取文件时，假定的采样率是 44,100 Hz。用 srate 所做的修改不会更改磁盘上的文件。

参数：

  • sample-rate [float]

srcchans

左入口：srcchans 一词后面跟一个数字，指定以多少个通道来解读音频文件的采样数据（从而覆盖音频文件实际的通道数）。这有时被称为 “header munging”。在响应 openraw 消息读取文件时，假定的通道数是 2。用 srcchans 所做的修改不会更改磁盘上的文件。

参数：

  • number-of-channels [int]

输出

bang

右出口：文件播放完毕时，或用 0 消息停止播放时，会送出一个 bang。

multi-channel signal

mc.sfplay~ 有一个信号出口，它输出一个多通道信号。输出的通道数由 mc.sfplay~ 对象的参数指定。

若指定了可选的输出位置参数，多通道输出之后会有一或两个信号输出，它们的信号输出显示定位信息。若该参数为 1，最右侧 "bang on finish or halt" 出口的左边会有一个出口，它输出一个信号，其中包含以毫秒为单位的当前播放位置。若把最后一个参数指定为 2，则会再创建第二个出口，它输出一个信号，其中包含播放位置单精度舍入误差的毫秒值（关于 mc.sfplay~ 对象位置出口的更详细说明见「参数」）。
