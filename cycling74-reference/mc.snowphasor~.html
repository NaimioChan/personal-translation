MC

mc.snowphasor~

控制一个相位器群体

描述

mc.snowphasor~ 对象根据平均速率一类的全局控制，在多个音频通道中生成相位器斜坡。该对象也可以从多通道音频信号触发斜坡。

参数

无。

特性

busymapname [symbol]

别名：bzname

若设置了 Use Busy Map（usebusymap）特性，busymapname 会指定一个具名 busy map，而非默认的全局 busy map。

chans [int]

设置输出通道数。若 chans 的值为 0，输出数量会自动适配连接到对象入口的多通道信号中的通道数。若 chans 的值为非零，则多通道输出中的通道数固定，不会自动适配输入。

interval [float]

当 mode 特性设为 Utilization（0）时，interval 设置单位时间内输出相位器群体密度的更新间隔。新的相位器只会在其中某次更新期间启动。
当 mode 特性设为 Rate（1）时，interval 设置单位时间内相位器平均速率的更新间隔。新的相位器只会在其中某次更新期间启动。即使 rate 实际上快于 interval，相位器在时间上的生成间隔也不会比 interval 指定的更近。当 rate 会在一个 interval 的时间内生成多个相位器时，它们会同时启动。当 mode 特性设为 Audio（3）时，interval 会被忽略。当 mode 特性设为 Interval（2）时，interval 设置相位器触发之间的时间，而 rate 会被忽略。

intervalcycle [int]

设置平均间隔时间（由 interval 特性指定）在多少个间隔之后被恢复。mc.snowphasor~ 所用的时间间隔不一定是 interval 特性的取值，只要 intervaldev 特性被设为非零值并在算出的各个间隔中造成变化，就是如此。举个例子，假设 interval 设为 100 ms，但上一个间隔（由于 intervaldev 非零）为 90。若 intervalcycle 特性设为 2，则下一个使用的间隔会是 110，以便在两个间隔的跨度内把均值维持在 100。若 intervalcycle 特性设为 10，则会先生成九个间隔，然后才调整第十个间隔以维持平均间隔时间。在极少数情况下，若在本周期的最后一个间隔被算出之前，此前的各个间隔已经超过平均间隔时间，则得出的修正间隔会是 1 ms。一般来说，间隔周期越大，在 intervaldev 取值较大时间隔的变化范围就可以越「宽」。

intervaldev [float]

设置 interval 特性当前取值中允许随机变化（高于或低于该值）的比例。intervaldev 取值为 0 时，间隔不会产生任何随机变化。

mode [int]

决定新的相位器斜坡以哪种方式被触发
可选值：

0 = 'utilization' (利用率模式)
按 prob 特性所设定，在全部可用的时间与空间（通道）中维持一定比例的相位器斜坡处于激活状态。interval 特性设定利用率更新与触发新相位器之间的时间。当 interval 变大时，为维持利用率水平，相位器会被同时触发（更像节拍器）。当间隔很小时，相位器的触发会更分散，相位器被同时触发的可能性更低。

1 = 'rate' (速率模式)
尝试按 rate 特性所设定，为每个通道维持单位时间内新相位器触发（诞生）的速率。不过，若 interval 特性被设为一个比 rate 更慢的时间值，就可能出现相隔更远但更同步的触发。
举例来说，若 interval 为 50 ms、rate 为 4，则大约每 250 ms 会启动一个相位器，因为 mc.snowphasor~ 每 50 ms 就会检查一次是否该启动相位器。然而，若 interval 为 2000 ms，你会听到每 2000 ms 有多达 20 个相位器同时启动，因为 mc.snowphasor~ 每 2000 ms 才检查一次是否要启动新相位器。任一时刻相位器启动的有效速率还会进一步受 ratedev、prob、probdev 和 intervaldev 特性影响。

2 = 'interval' (间隔模式)
按 interval 与 intervaldev 特性所设定，在各次相位器触发之间维持恒定的间隔。prob 特性决定在任何一个特定间隔上触发相位器的概率。此模式下 rate 特性不起作用。

3 = 'audio' (音频模式)
当各音频通道的采样点取值超过信号输入阈值（由 threshold 特性设定）时触发新相位器。此模式下 rate 与 interval 特性不起作用。

perchantriggers [int]

当 perchantriggers 被设定时，输入音频通道上的零到非零跳变只会触发对应的输出通道。当 perchantriggers 为 0 时，触发会作用于任意可用的输出通道。perchantriggers 仅当 mode 设为 Audio (3) 时才适用。

prob [float]

当 mode 特性设为 Utilization (0) 时，prob 特性设定的是全部音频输出通道中由相位器斜坡占用的时间百分比。随着 decaytime 特性取值增大，单位时间内新斜坡（诞生）的平均数量会降低。
当 mode 特性设为 Rate (1) 时，prob 的取值会降低平均 rate（实际速率将是 rate 的取值乘以 prob）。例如若 prob 为 0.5，按 rate 该启动新相位器时，只有一半的时候会真的启动，具体由一次随机判定决定。
当 mode 特性设为 Interval (2) 时，prob 决定在指定间隔上是否真的生成相位器。若 prob 的取值为 1.0，相位器总会生成。若 prob 的取值为 0.5，相位器只有一半的时候会生成，具体由一次随机判定决定。
当 mode 特性设为 Audio (3) 时，prob 不起作用。

probdev [float]

设置 prob 特性当前取值中允许随机变化（高于或低于该值）的比例。probdev 取值为 0 时，利用率概率不会产生任何随机变化。

rampdev [float]

别名：decaydev

设置 ramptime 特性当前取值中允许随机变化（高于或低于该值）的比例。rampdev 取值为 0 时，斜坡时间不会产生任何随机变化。

ramptime [float]

别名：decaytime

设置由 mc.snowphasor~ 产生的相位器斜坡的时长，单位为毫秒。

rate [float]

当 mode 特性设为 Rate (1) 时，rate 特性设定每秒相位器斜坡触发（诞生）的速率。当 mode 特性设为其他取值时，rate 特性不起作用。

ratedev [float]

设置 rate 特性当前取值中允许随机变化（高于或低于该值）的比例。rate 取值为 0 时，斜坡诞生速率不会产生任何随机变化。

threshold [float]

设置音频模式下斜坡触发的采样点最小值。

usebusymap [int]

别名：bz

当 usebusymap 特性被设定时，mc.snowphasor~ 会把 busy map 纳入其声部分配算法，并在触发斜坡时把 busy map 中的通道设为忙碌。

消息

signal

左入口：当 mode 特性（即 mc.snowphasor~ 的触发模式）设为 Audio (3) 时，会启动一个新的相位器斜坡。若 perchantriggers 特性被设定，则斜坡只会出现在非忙碌的输出通道上，该通道与任一采样点超过当前信号输入阈值的通道相对应。若输入音频通道多于输出通道 —— 输出通道数由 chans 特性设定 —— 多出的输入通道会被忽略。若 perchantriggers 为 0，则使用下一个可用（非忙碌）的输出通道。
右入口：连接到右入口的信号会设定斜坡时长，并覆盖 decaytime 特性的取值。若连接的是多通道信号，则使用与输出斜坡所在通道相对应的输入通道来设定时长。
