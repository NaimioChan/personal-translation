MC

mc.r~

无需连线即可从任意已加载的补丁接收信号

描述

用 receive~ 对象来抓取 send~ 对象送出的信号，并从其信号出口输出。receive~ 对象只需在对象框中键入简写字母 "r~" 即可实例化。

讨论

你可以在所有当前的 receive~ 对象之间切换，方法是使用 set 消息。要关闭来自某个 receive~ 的音频，请用 set 加一个当前不存在的 send~ 的名称。

注意：使用 receive~ 对象可能引入长度不一的延迟。该延迟取决于许多因素，包括但不限于：涉及多少个 send~ 与 receive~ 对象、是否检测到反馈回路，以及在启用多处理时使用不同的顶层补丁。

参数

object-name [symbol] 可选

设置 receive~ 对象的名称。

特性

chans [int]

chans 特性在 receive~ 对象中被禁用。它在 mc.receive~ 中可用。

name [symbol]

为 receive~ 对象命名。若没有参数，receive~ 只有一个入口，必须先通过 set 消息提供一个名称，才能接收任何内容。所有共享同一名称的 receive~ 对象都会从共享其名称的任意 send~ 对象接收数据。

如果你想让你在 Max for Live 设备中具名的 send~ / receive~ 对象对该设备唯一，请用三个短横线（---）开头来命名你的 send~ / receive~ 目标（例如 s ---filtercutoff）。

补丁初始化时，会把这三个短横线替换为一个对 Live 唯一的编号（例如 s 024filtercutoff）；

消息

(mouse)

双击 receive~ 对象会查找并打开一个已加载的补丁窗口，其中含有同名的 send~ 对象。反复双击该 receive~ 对象会查找并打开更多这样的窗口。

set

单词 set 后跟一个 symbol，会更改 receive~ 的名称，使它连接到不同的 send~ 对象，这些对象以该 symbol 为名称。若不存在具有该名称的 send~ 对象，receive~ 的输出为 0。

参数：

  • object-name [symbol]

signal

receive~ 对象接收所有与它同名的 send~ 对象发来的信号。它把这些信号相加，并把总和从出口送出。若没有任何 send~ 对象与当前名称同名，receive~ 的输出为 0。这些 send~ 对象不必与对应的 receive~ 位于同一个补丁中。

输出

signal

所有送入 send~ 对象（其名称与 receive~ 相同）的信号之组合。
