mc.dac~

音频输出与开关

描述

dac~（“数模转换器”）对象把它的信号输入送到音频硬件。双击 dac~ 会打开 Audio Status 窗口，以便配置音频设置与硬件。

参数

outputs [int/symbol] 可选

你可以创建带一个或多个逻辑通道号的 dac~ 对象，逻辑通道号介于 1 和 1024 之间。逻辑通道通过 Audio Status 窗口、它的 I/O Mappings 子窗口，或者 adstatus 对象（配合关键字 output）分配给音频设备通道。如果使用计算机的内置音频硬件，会有两个可用输出通道。其他音频驱动程序或设备可能有超过两个通道。若不键入任何参数，dac~ 会有两个入口，分别对应输入通道 1 和 2。

若把符号作为第一个参数提供给 dac~ 对象，它的输出会被送到 Max 混音器。补丁层级中的多个 dac~ 实例若共享同一个名称，它们会使用同一个混音器输出。

消息

int

非零的数字会打开所有已加载补丁中的音频处理。0 会关闭所有已加载补丁中的音频处理。

参数：

  • on/off-flag [int]

list

由整数组成的 list 按从左到右的顺序为每个信号入口设置逻辑输出通道。

参数：

  • output-channel-designations [list]

(mouse)

双击 dac~ 会打开 Audio Status 窗口。

open

打开 Audio Status 窗口。

set

任意入口：单词 set 后跟一个数字，为收到该 set 消息的那个信号入口设置逻辑输出通道。例如，发送 set 3 到 dac~ 的左入口，会使从左入口进来的信号输出到逻辑输出通道 3。

注意，如果音频处于打开状态，而你用 set 消息把某个 dac~ 改成使用当前未使用的逻辑通道，那么在这些通道上不会听到声音，直到把音频关掉再打开。例如，你有一个参数为 1 2 3 4 的 dac~ 对象，而信号只连接到了最左边的两个入口（对应通道 1 和 2），那么消息 set 1 3 不会立即把最左边的音频信号路由到逻辑通道 3，因为该通道当前未在使用。绕开这个问题的一个方法是，把 sig~ 0 连接到一个 dac~ 的每个通道——如果你打算给它发送 set 消息的话。既然如此，你还不如用 matrix~ 或 selector~ 对象，在音频信号到达 dac~ 之前做类似的事情。

参数：

  • output-channel-designation [int]

signal

进入 dac~ 某个入口的信号会被送到与该入口对应的音频输出通道。为避免削波，信号必须介于 -1 和 1 之间。

start

打开所有已加载补丁的音频处理。

startwindow

只在包含此 dac~ 的补丁及其子补丁中打开音频处理。关闭所有其他补丁中的音频处理。

stop

关闭所有已加载补丁的音频处理。

wclose

若 Audio Status 窗口已打开，则关闭它。

输出

Audio

dac~ 在应用程序内部不产生输出。其入口收到的信号会被送到分配给它的逻辑音频输出通道。你可以在 Audio Status 窗口的 I/O Mappings 子窗口中把逻辑通道分配给设备输出通道。
