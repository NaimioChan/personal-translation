max-mxj

mxj~

MSP 中的 Java

描述

mxj~ 对象（及其 Max 对应物 mxj）会实例化专门编写的 Java 类，并充当 Max 层面的对等对象，把源自 Max 的数据传给 Java 对象，反之亦然。

讨论

mxj~ 对象所采取的形式——入口、出口的数量以及它能理解的消息——由它实例化的 Java 类决定。与 Max 的 mxj 对象不同，mxj~ 对象能够对 MSP 处理链中的信号向量执行运算。使用 mxj~ 要求主机安装了较新版本的 Java 虚拟机（JVM）。Macintosh 用户可以通过 System Preferences 中的 Software Update 来确保自己拥有最新版本的 JVM。

默认情况下，Mac M1 机器和 Windows XP 都没有安装 JVM。在撰写本文档时，最新版本的 JVM 可从此链接下载。

Max 包含一个名为 "java-doc" 的目录，在 Windows 机器上位于

C:\Program Files\Common Files\Cycling '74\java-doc

在 Macintosh 机器上位于

/Applications/Max*/java-doc

java-doc 目录中有以下重要的子目录：

"classes" - 包含 Max 附带的示例 Java 类的源代码和类文件。

"help" - 包含与示例 Java 类关联的帮助文件。浏览这些补丁是了解 mxj~ 已经并将会如何扩展 Max 世界的一个快速好办法。

"doc/tutorial" - 包含一个分步教程，带你从创建你的第一个 Java 类一直到应用高级 mxj~ 编程技巧。该教程为 HTML 格式。

"doc/api" - 包含说明 mxj~ 的应用程序编程接口（API）的 html 文件。你在编写自己的 Java 类时，这些页面将是无价的资源。

"doc/ide" - 包含一些集成开发环境（IDE）的示例项目，我们认为你可能想用它们来创建 Java 类。

"doc/mxj~ examples" - 包含用于信号处理的示例类

"lib" - 包含 mxj~ 对象用来沟通 Max 与 Java 两个世界的代码库。

此外，java 目录中还有一个名为 "max.java.config.txt" 的文件。该文件让你指定哪些目录应位于 Java 的 classpath 中——这个概念大致类似于 Max 的搜索路径。

参数

Java-class [symbol] 可选

mxj~ 对象的第一个参数必须是有效 Java 类的名称。该 Java 类文件必须存在于 classpath 中的某处，而且必须是为配合 mxj~ 对象使用而设计的类（该类必须继承 com.cycling74.max.MaxObject）。mxj~ 实例创建的入口数量以及它会响应的消息，由对等 Java 类中做出的声明决定。

attributes [list] 可选

mxj~ 对象支持在对等类的 Java 代码中定义特性。这些特性可以在实例化时通过 @ 范式设置。例如，若某个类 Foo 定义了一个名为 intBar 的整数特性，那么只要在对象框中键入 mxj~ Foo @intBar 74，就能创建该类的实例，并把该特性设为取值 74。

benchmark

单词 benchmark 后面跟一个 0 或 1，再跟一个指定输出间隔的数字（perform 方法的执行次数），会禁用对 mxj~ 对象 perform 方法的基准测试，并把结果输出到 Max Console。默认值为 0（禁用）

参数：

  • benchmark-flag [int]
  • post-interval [int]

(mouse)

用鼠标双击 mxj~ 对象，会以文本形式在一个编辑窗口中显示其内容，用户可以在该窗口中修改。

exceptioncheck

单词 exceptioncheck 后面跟一个 0 或 1，会禁用/启用 mxj~ 对象 perform 方法中的 Java 异常检查。默认值为 0（禁用）。

参数：

  • exception-flag [int]

get

单词 get 后面跟一个特性名，会把该特性的取值输出到 Max 窗口中。

参数：

  • attribute-name [list]

viewsource

viewsource 消息会打开一个文本编辑器窗口，并加载对等 Java 对象的源代码。若源代码与对等类的 .java 文件不在同一个目录中，则会尝试对该类文件进行反编译，并显示反编译得到的源代码。在编辑器窗口中，可以编辑源代码、保存文件并重新编译该类。

zap

当把 zap 消息发送给一个 Java 对等类为 Foo 的 mxj~ 对象后，下一个用同一个 Java 对等类 Foo 实例化出来的 mxj~ 对象（即在对象框中键入 "mxj Foo"）会让该类从磁盘上重新加载自己。这在编程语境中最有用：如果修改了 Foo.java 并重新编译出新的 Foo.class，zap 消息让你无需退出并重启 Max 环境就能创建新类的实例。若不发送 zap 消息，Max 只会使用在做出这些修改之前实例化 Foo 对象时所加载的该类的缓存定义。

输出

various

mxj~ 的实例所创建的出口数量由对等 Java 类的构造函数中所做的声明决定。最右侧的出口可能是、也可能不是一个信息出口，信息出口的唯一职责是在被查询时报告关于各特性的信息。
