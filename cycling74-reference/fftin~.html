MSP

fftin~

供 pfft~ 加载的补丁使用的输入

描述

fftin~ 对象为由 pfft~ 对象加载的补丁提供一个信号输入。

讨论

pfft~ 对象负责管理输入信号的加窗与重叠，而 fftin~ 则施加加窗函数（包络）并执行快速傅里叶变换。

参数

inlet-assignment [int] 可选

决定哪个 pfft~ 入口将被路由到 fftin~ 对象。入口编号从 1 开始，对应 pfft~ 中最左侧的入口。多个 fftin~ 对象通常会有不同的入口编号。

window-envelope-function [symbol] 可选

指定 fftin~ 对象将对输入信号上重叠的 FFT 施加的窗包络函数。可选项有 square（即无窗包络）、hanning（默认）、triangle、hamming 和 blackman（注意：Blackman 窗应配合 4 或更大的重叠量使用）。如果使用符号 nofft，那么 fftin~ 对象将不使用加窗包络，也不执行快速傅里叶变换——它会把它输入采样窗的前一半回送到实部输出，把输入采样窗的后一半回送到虚部输出。这样你就能通过 pfft~ 对象中的入口，从父补丁外部输入原始控制信号，前提是它的重叠量设为 2。其他重叠值可能不会产生有用的结果。

特性

nofft [int]

设置 nofft 后，fftin~ 允许音频在不执行 fft 的情况下从 pfft~ 的入口传入子补丁。pfft~ 在默认的半频谱帧模式和 pfft~ 在全频谱模式下有一些特有的行为，出于遗留原因它们就是这样表现的。

当 pfft 处于默认的半频谱模式时，fftin~ 会忽略加窗函数，从外层 MSP 补丁送来的帧的前一半读入并写入该前一半。

当 pfft 处于全频谱模式时，与半频谱模式不同，fftin~ 的 nofft 会对实部输出/输入施加加窗函数（默认 hanning）。

处于全频谱模式的 fftin~ 会把未加窗的值从虚部输出送出。要让实部输出具有类似的行为，把窗设为 square。

userwindow [symbol] :

当 window 特性设为 user 时，userwindow 特性设置用哪个缓冲区作为窗函数。

window [symbol] : hanning

把窗函数设为内置窗函数之一，或设为用户指定的缓冲区。
可选值：

'square'
'triangle'
'hanning'
'hamming'
'blackman'
'user'

消息

signal

占位入口。fftin~ 对象的信号输入是该对象所在 pfft~ 子补丁中的一个入口。

updatewindow

根据当前特性或用户窗缓冲区重新构建窗，并在下一个 FFT 帧边界处发布完整的窗。音频线程不会被阻塞。在 DSP 初始化之前，或者当另一个窗更新尚未完成时，该消息不起作用。

输出

signal

左出口：该输出包含对 pfft~ 相应入口执行快速傅里叶变换所得到的实数值。该输出帧只有父 pfft~ 对象 FFT 大小的一半，因为实输入信号的频谱是对称的，因此其中一半是冗余的。一个频谱的实部与虚部对称为一个频谱帧。

中间出口：该输出包含对 pfft~ 相应入口执行快速傅里叶变换所得到的虚数值。该输出帧只有父 pfft~ 对象 FFT 大小的一半，因为实输入信号的频谱是对称的，因此其中一半是冗余的。一个频谱的实部与虚部对称为一个频谱帧。

右出口：一串采样点，对应当前频率槽的索引，该槽的数据正从前面两个出口送出。这是一个从 0 到（帧大小 - 1）的数。在 pfft~ 对象的子补丁中，频谱帧大小等于 FFT 窗大小的一半。
