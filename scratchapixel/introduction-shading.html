着色

阅读时间：17 分钟。

现实世界中的一切虽然都源于光与物质的相互作用，但有些相互作用复杂到无法用光传输的方法来模拟。这时着色就变得不可或缺。

如前一章所述，要模拟物体的外观，就需要计算物体表面每一点的颜色与明暗。颜色和明暗关系密切。必须区分两种明暗：一种由落在物体表面上的光量造成，另一种是物体颜色本身的明暗（有时称为颜色的亮度）。颜色的明暗连同色相和饱和度，是颜色自身的属性。如果你在完全相同的光照条件下观察两个物体，它们看起来颜色相同（相同的 色度），但一个比另一个暗，这说明它们的明暗并非单纯由接收到的光决定。相反，它更多取决于每个物体向环境中反射出去的光量。本质上，这两个物体颜色（色度）相同，但反射（或吸收）的光量不同。因此，它们颜色的明暗（或亮度）不同。在计算机图形学中，物体的这种特征色称为反照率。物体的反照率可以精确测量。

要注意，物体不可能反射比它接收到的更多的光（除非它像光源那样发光）。物体的颜色，尤其是漫反射表面，一般可以按反射光量与入射（白）光量之比来计算。既然物体反射的光不会多于它接收的光，这个比值总小于 1。因此，物体的颜色在 RGB 系统中定义为 0 到 1 之间的值（浮点编码），若用字节表示则是 0 到 255。把这个比值写成百分比更实用。例如，若该比值——也叫颜色或反照率（这两个词可以互换）——为 0.18，就表示物体把入射光的 18% 反射回环境中。更多内容见颜色这门课。

如前所述，把物体的颜色定义为反射光量与入射到表面上的光量之比，意味着颜色不能大于 1。但这并不意味着入射到物体表面的光量以及从表面反射的光量不能大于 1；只是两者之比不能大于 1。我们眼睛感知到的，是入射到表面上的光量与物体颜色之积。例如，若打到表面上的光能量为 1000，物体颜色为 0.5，则表面反射到眼睛的光量为 500。从物理角度看，这种简化在技术上并不正确，但它有助于说明概念。在讲着色与光传输的课程中，我们会深入说明 1000、500 这些数值在物理单位下意味着什么，并理解这种相互作用远比把光子数乘以 0.5 或乘以物体反照率复杂。

因此，假设已知物体的颜色（反照率），要计算该物体表面上一点 \(P\) 在特定光照条件下的实际明暗（指表面实际反射到眼睛的光能量，而不是物体反照率的明暗或亮度），需要考虑两个因素：

  • 有多少光落在物体的这一点上？

  • 有多少光从这一点沿观察方向反射出去？

要记住，对镜面表面而言，反射的光量取决于观察角度。比如绕着镜子走动，镜中映出的画面会变；朝你反射的光量随视点而变。

已知物体的颜色（反照率），我们还必须确定有多少光到达点 \(P\)，以及有多少光沿观察方向从 \(P\) 反射到眼睛。

  • 第一件事是在表面上方的点 \(P\) 处「聚集」光，这更多是光传输的问题。如前一章所述，做法可以是直接向光源投射光线来计算直接光照，并从 \(P\) 发出次级光线来计算间接光照（其他表面对 \(P\) 处照明的贡献）。这看起来像是纯粹的光传输问题，但后续关于着色与光传输的课程会表明：表面的类型（漫反射还是镜面）决定了这些光线的方向，而着色器在选择方向上起关键作用。此外，计算直接光照与间接光照也可以采用光线追踪之外的方法。

  • 第二件事（确定有多少光沿给定方向反射出去）要复杂得多，我们会更详细地探讨。

首先必须理解：表面向环境反射的光，源于光线（或光子，如果你熟悉这个词）与构成物体的材质之间复杂的相互作用。有三点很关键：

  • 这些相互作用通常复杂到无法直接模拟。

  • 反射的光量取决于观察方向。一般而言，表面不会把入射光等量地向各个方向反射。对完美漫反射表面来说不是这样，它们从任何观察角度看亮度都一样；但对所有镜面表面都成立。现实世界中的大多数物体都兼有漫反射与镜面反射，因此光不被等量反射才是常态。

  • 沿观察方向重新定向的光量还取决于入射光的方向。要计算有多少光沿方向 \(\omega_v\) 反射出去（「v」代表 view，\(\omega\) 是希腊字母 omega），我们还需要考虑入射光的方向 \(\omega_i\)（「i」代表 incident 或 incoming）。这个概念在图 3 中示出。想一想当反射光线的表面是一面镜子时会发生什么。根据反射定律，光线入射方向 \(\omega_i\) 与入射点处法线之间的夹角，和反射方向（镜面方向）\(\omega_r\) 与法线之间的夹角相同。当观察方向 \(\omega_v\) 与反射方向 \(\omega_r\) 相同时（图 3 上），反射光线进入眼睛。而当 \(\omega_v\) 与 \(\omega_r\) 不同时（图 3 下），反射光线不会射向眼睛，因此看不见。所以，反射到眼睛的光量同时取决于入射光方向 \(\omega_i\) 与观察方向 \(\omega_v\)。

我们来总结一下已知的内容：

  • 模拟光与物质的相互作用（发生在微观与原子尺度）过于复杂，必须另寻出路。

  • 从一点反射出去的光量随观察方向 \(\omega_v\) 变化。

  • 对给定的观察方向 \(\omega_v\)，反射的光量取决于入射光方向 \(\omega_i\)。

着色负责计算从表面反射到眼睛（或场景中其他表面）的光量，它至少取决于两个变量：入射光方向 \(\omega_i\) 与出射或观察方向 \(\omega_v\)。光的来源与表面无关，但沿给定方向反射的光量随表面类型（漫反射或镜面）而变。如前所述，在入射点聚集光更多是光传输的问题。无论用什么技术在点 P 处聚集光，关键在于确定光的来源，也就是它来自哪个方向。着色器以入射光方向与观察方向作为输入变量，返回表面沿这两个方向反射的光的比例。

$$\text{ratio of reflected light} = \text{shader}(\omega_i, \omega_o)$$

模拟光与物质的相互作用以得到结果很复杂，但这无数次相互作用的结果是可预测、一致的，因此可以用数学函数来近似或建模。我们会在专门讲着色的课程里探究这些函数的来历、性质与发现过程。现在先凭直觉理解它为什么成立、如何成立。

前一章介绍的反射定律可以写成：

$$\omega_r = \omega_i - 2(N \cdot \omega_i) N$$

用平实的话说，这个公式的意思是：反射方向 \(\omega_r\) 等于 \(\omega_i\) 减去两倍的 N（入射点处的表面法线）与 \(\omega_i\) 的点积再乘以 N。这个公式更多是关于计算方向，而不是关于反射的光量。不过，如果对任意给定的入射方向（\(\omega_i\)），\(\omega_r\) 与 \(\omega_v\)（观察方向）重合，那么这一特定情形下反射光的比例就是 1（图 3 上）。若 \(\omega_r\) 与 \(\omega_v\) 不同，反射的光量就是 0。要把这个概念形式化，可以写成：

$$\text{ratio of reflected light} = \begin{cases} 1 & \text{if } \omega_r = \omega_o \\ 0 & \text{otherwise} \end{cases}$$

这只是一个例子。对完美的镜面表面，我们从不会这样做。这里的要点是：如果我们能用公式描述光的行为，就能对任意一组入射与出射方向算出反射的光量，而不必运行复杂耗时的模拟。这正是着色器所做的事：用数学模型替代复杂的光与物质相互作用，这种模型计算起来很快。如我们很快会看到的，这些模型并不总是很准确，也不一定符合物理，但它们是近似这些相互作用结果的最实用方式。着色领域的研究主要是开发新的数学模型，尽可能贴近材质反射光的真实方式。可以想象，这是件困难的事：它本身就难，更重要的是，材质表现出非常不同的行为，因此一般不可能用单一模型准确模拟所有材质。往往需要为不同材质分别开发模型，比如一个模型用来模拟棉布的外观，另一个用来模拟丝绸的外观，等等。

那么模拟漫反射表面的外观呢？对漫反射表面，我们知道光向各个方向等量反射。因此反射到眼睛的光量，等于到达表面（给定点处）的总光量乘以表面颜色（表面反射回环境的光占入射光总量的比例），再除以一个出于数学与物理准确性考虑所必需的归一化因子。这些会在专门讲着色的课程里详细说明。注意，对漫反射而言，入射光方向与出射光方向都不影响反射的光量。不过这是个例外。对大多数材质，反射的光量取决于 \(\omega_i\) 与 \(\omega_v\)。

光泽表面的行为最难用公式复现。人们提出过许多方案，其中最简单（也最容易在代码中实现）的是你可能听说过的 Phong 镜面反射模型。

Phong 模型用反射定律的公式计算完美镜面方向，该公式依赖表面法线与入射光方向。然后它取实际观察方向与镜面方向之间的偏离（或差异）的某个幂次（对这两个向量取点积），并假定入射点处表面的亮度与这一差异成反比。差异越小，表面越亮。指数参数用来控制镜面反射的扩散范围（更多关于 Phong 模型的说明见着色部分的相关课程）。

不过，好的模型遵守一些 Phong 模型所缺少的已知性质。比如其中一条是模型能量守恒。向所有方向反射的光量不应大于入射光总量。如果模型不具备这一性质（Phong 模型就缺这条），它就违反了物理定律。它可能给出视觉上讨喜的结果，但不是物理上可信的结果。

你听说过物理可信渲染这个词吗？它指的是这样一种渲染系统：所有着色器与光传输模型都遵循物理定律。计算机图形学早期，速度和内存比准确性更重要，一个模型只要跑得快、占内存少（牺牲准确性）就常被认为不错。但在我们追求照片级真实的过程中，也因为今天的计算机比设计最初那些着色模型时快得多，我们不再用准确性换速度，而是尽可能使用基于物理的模型（即使它们比非物理模型慢）。能量守恒是基于物理的模型最重要的性质之一。现有的基于物理的渲染引擎能产生极其真实的图像。

用一段伪代码把这些想法串起来：


Vec3f myShader(Vec3f Wi, Vec3f Wo) 
{ 
    // 定义物体的颜色、粗糙度等
    ... 
    // 做一些数学计算，求出表面沿这对方向（入射与出射）
    // 反射出去的光所占的比例。
    ... 
    return ratio; 
} 
 
Vec3f shadeP(Vec3f ViewDirection, Vec3f Point, Vec3f SurfaceNormal) 
{ 
    Vec3f totalAmountReflected = 0; 
    for (all light sources above P [direct|indirect]) { 
        totalAmountReflected += 
            lightEnergy * 
            shaderDiffuse(LightDirection, ViewDirection) *
            dotProduct(SurfaceNormal, LightDirection); 
    } 
 
    return totalAmountReflected; 
}

注意这段代码分成两大部分：一个例程（第 11 行）聚集来自点 P 上方各个方向的所有光；另一个例程（第 1 行）也就是着色器，计算表面对任意一对入射与观察方向反射的光的比例。这个循环常被称为光源循环，它把场景中所有可能光源对 P 处照明的贡献累加起来。每个光源具有一定的能量，并来自特定方向（由 P 与光源在空间中的位置之间的连线确定）。所需做的只是把这些信息连同观察方向一起交给着色器。着色器随后算出该特定方向上反射到眼睛的光的比例，这个结果再与光源产生的光量相乘。对场景中所有可能的光源把这些结果相加，就得到从 P 反射到眼睛的光总量，也就是我们想要的结果。

注意在这个求和（第 18 行）里有第三项：法线与光线方向的点积。这一项在着色中很关键，与余弦定律有关。它会在讲光传输与着色的章节里展开。现在需要理解的是：它描述了当表面与光源之间的夹角变化时，光能量在物体表面上的分布。

结论

光传输与着色之间只有一线之隔。等我们进入光传输一节就会清楚，光传输算法往往依赖着色器来决定朝哪个方向发出次级光线，以计算间接光照。

本章有两个要点，分别是着色与着色器的定义：

  • 着色是渲染过程中负责计算沿任意给定观察方向反射的光量的部分。正是在这一阶段，图像中的物体从某个特定视点获得了最终外观，包括外观感受、颜色、纹理和明暗等方面。模拟物体的外观，归根到底就是回答一个问题：物体相对于它接收到的光总量，反射了多少光（以及向哪些方向反射）？

  • 着色器就是为回答这个问题而设计的。把着色器想成一个黑箱，你向它提出这样的问题：「已知这个物体由木头制成，具有特定颜色与粗糙度，若有某量的光从方向 \(\omega_i\) 打到这个物体上，物体会向环境中的方向 \(\omega_v\) 反射多少光？」着色器对这个问题作出回应。说它是黑箱，并不是因为它的内部机理神秘，而是因为它在渲染系统中作为一个独立实体运作。它只有一个目的——回答上面提出的问题，而且在回答时除了表面属性（如粗糙度和颜色）以及入射与出射方向之外，不需要知道系统的任何其他东西。

    这个「黑箱」内部发生的事一点也不神秘。物体各自独特的外观，是光的粒子（光子）与构成物体的原子之间复杂相互作用的结果。虽然直接模拟这些相互作用并不现实，但我们观察到它们的结果是可预测、一致的。因此可以用数学来「建模」或表示真实世界的运作方式。数学模型永远不是现实的精确复制，但它是紧凑表达复杂问题的便利手段，可以在只占直接模拟一小部分的时间里算出复杂问题的解（或近似解）。着色这门科学，就是开发这类模型，用微观与原子尺度上的光相互作用来描述物体的外观。这些模型的复杂度取决于我们想复现的表面外观类型。对完美的漫反射表面和镜面表面有简单的模型，但为光泽表面与半透明表面设计好模型要困难得多。

    这些模型会在本节专门讲着色的课程里考察。

历史上，实时渲染 3D 场景的技术很大程度上由 API 预先规定，用户几乎没有修改的余地。实时技术已经超越了这一范式，提供更可编程的管线，渲染过程的每一步都由称为「着色器」的独立「程序」控制。当前的 OpenGL API 支持四种着色器：顶点着色器、几何着色器、细分着色器和片元着色器。负责计算图像中某一点颜色的是片元着色器，其他着色器在定义物体外观上只起次要作用。要注意，「着色器」这个词因此被用得越来越宽泛。
