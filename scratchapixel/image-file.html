创建、保存与读取数字图像

阅读时间：28 分钟。

什么是数字图像？

在学习如何把二维数字图像的结果存到文件之前，我们先看看什么是数字图像。有时数字图像是黑白的（B&W），但大多数时候是彩色的。上一课我们学到，要表示一种颜色，计算机需要三个值（当然黑白图像只需要一个值），在加色系统中它们就是三种原色红、绿、蓝。对于计算机生成的图像，我们通常还会存第四个值，称为 alpha 通道或图像的遮罩。这个遮罩或 alpha 通道用来表示渲染场景中物体的不透明度。对不透明的物体，这个值应为 1；对完全透明的物体（或者那里根本没有物体），这个值应为 0。如果值介于两者之间，那么面对的是一个半不透明的物体。下图给出了这类图像及其对应 alpha 通道或遮罩的一个例子。本章后面我们会说明它有什么用。

你可能需要区分不透明度与透明度这两个概念。如果你用透明度的概念，完全透明物体的值应设为 100% 即 1，完全不透明的设为 0% 即 0。如果你用不透明度的概念，那么完全透明物体的不透明度应设为 0% 即 0，完全不透明物体的不透明度应设为 100% 即 1。

总结一下，我们知道处理计算机生成的图像时，需要一个三个值来表示颜色，可能还需要额外一个值来存物体的不透明度（也就是渲染 3D 场景的时候）。既然已经了解了颜色，现在来看看数字图像本身。数字图像（有时也叫 光栅图形 或 位图）最简单的形式就是一个 二维像素数组（pixel 是 picture element 的缩写）。它的尺寸由沿图像宽度的像素数（列数）和沿高度的像素数（行数）定义。像素可以看成一个被赋了颜色的方块，如图 2 和图 3 所示（不过像素并不是一个小方块。更正式地说，它代表一个采样。本章末尾你会找到关于这点的更多信息）。当我们很近地看屏幕上的数字图像时，能看到构成它的一个个像素。但从远处看，图像由离散的单个像素构成这一事实对人眼来说是无法分辨的。

要创建一张数字图像，我们需要创建一个二维像素数组，每个像素存三个值（计算机生成的图像是四个值），如上所述，用来编码该像素的颜色。通常我们用缩写 RGB（红、绿、蓝）来指称这三个值，如果图像还存了 alpha 通道，就用 RGBA（红、绿、蓝、alpha）。

注意，我们也可以把所有红光的数值存进一个二维数组，对绿光和蓝光照此办理，如图 4 和图 5。每个二维数组称为一个 通道。在大多数查看程序里（例如 Photoshop），图像通道可以彼此独立地查看。它们通常被显示成黑白图像，因为每个通道编码的是图像中每个像素所含红光、绿光或蓝光的量。

上一课我们学到，屏幕上的每个像素由一盏小的红、绿、蓝灯构成。把这三盏灯同时开到最大强度，屏幕上就会出现一个白点。最后，图像中的每个像素将对应屏幕上的一个像素，而照亮屏幕上该像素的红、绿、蓝灯各自的亮度或强度，由图像文件中为该像素存的红、绿、蓝值决定（如图 5 所示）。

在渲染器中，RGB 像素值应以浮点精度存储。这样我们就能在渲染管线中尽可能保留数值精度来存储、表示和处理颜色，直到把最终图像存到磁盘（在那个阶段我们可能会把值转换成另一种类型。注意我们说的是「可能」，并非一定。如果你用 8 bpc 的文件格式，bpc 意为「每通道位数」，比如 JPG、TGA 或 PNG，那你就需要把这些浮点值转换成 byte，换句话说，转换成 [0:255] 范围内的整数）。Photoshop 使用的另一种表示方式，是用 0 到 255 的整数（取整的数）编码像素值，0 表示某种颜色没有光，255 表示最大强度。从编程的角度看，你可以用不同方式声明一种颜色。为简单起见，我们决定用浮点数保存像素数据（见下面关于高动态范围图像的一节）。


class Image
{
public:
    Image(const int &w, const int &h) : width(w), height(h) { imageData = new float [w * h * 3]; }
    ~Image() { delete [] imageData; }
    void setPixel(const float *pixelValues, const int &x, const int &y)
    {
        imageData[(y * width + x) * 3] = pixelValues[0];
        imageData[(y * width + x) * 3 + 1] = pixelValues[1];
        imageData[(y * width + x) * 3 + 2] = pixelValues[2];
    }
    void saveToPpm(const char *filename) { ... }
    void readPpm(const char *filename) { ... } 
    float *imageData;
    int width, height;
};

这个类相当简单。构造函数接收我们想创建的图像的宽度和高度作为参数；然后我们分配存储图像数据所需的内存（第 6 行）（图像宽度乘以高度再乘以 3，即 RGB 颜色的分量数）。为方便起见，我们写了一个 setPixel 方法（第 12 至 17 行），可以用它设置某个特定像素的颜色（其坐标 x 和 y 作为参数传入）。save() 和 read() 方法的代码在后面给出。这两个方法用来把 PPM 图像保存到磁盘或从磁盘读取。PPM 文件格式本章后面也会介绍。

像素值既可以按 RGB 打包，也可以存成三个通道（三个二维数组）。在我们的代码里，一个像素颜色的各个分量按顺序存在计算机内存中（即某个像素的 B 值跟在 G 值之后，G 值又跟在 R 值之后）。你也可能决定先把所有像素的红色分量存完，再存绿色和蓝色值：


void setPixel(const float *pixelValues, const int &x, const int &y)
{
	unsigned pos = y * width + x;
	imageData[pos                     ] = pixelValues[0];
	imageData[width * height + pos    ] = pixelValues[1];
	imageData[width * height * 2 + pos] = pixelValues[2];
}

这个选择主要取决于你之后想在应用里以何种方式访问和处理像素数据。

计算机数值格式：哪种适合图像？

从计算的角度看，存储像素信息非常简单。对帧中的每个像素，我们需要存三个数，即这种颜色所含原色的量。而我们需要存的像素数就是帧中的像素数，这可以由图像宽度和高度算出来。更难的一个选择是：这些数该用什么数值精度来存？你可能知道，编程语言（我们这里是 C++）提供不同的计算机数值格式或类型来编码数字。最简单的元素是 byte，它含 8 位，我们可以用它编码字母表里的字符，也能表示 0 到 255 的数。每个通道（红、绿、蓝）只有 256 个级别可用来编码图像每个像素的每个通道，这并不算多，尽管红、绿、蓝三个通道合起来代表超过 160 万种可能的颜色选择。用这套系统能为任一 RGB 分量编码的最小差值就是 1/255，这是个相当大的步长。这会带来问题；我们可能无法以足够的精度表示颜色之间的变化，尤其是在人特别敏感的图像的暗部（这个问题我们上一章已经描述过）。

为了解决这个问题，我们可以对像素值人为施加 1/2.2 的伽马编码，从而在图像强度值较低的区间腾出更多空间（这个过程上一章已详细描述）。这个办法的问题在于，它改变了原始的像素值，一旦施加了伽马编码并把伽马编码后的图像数据存到磁盘，原始值就丢失了。用 byte 作为编码像素值的数值格式还有一个问题：这些值常常需要从浮点精度的数转换过来，这个问题称为 量化，我们会在本章后面讨论。尽管有这些毛病，8 位 RGB 图像仍然非常流行。这包括 JPG 或 PNG 这类文件格式，它们很常见，在浏览器里显示图像时是事实标准。它们成功的理由主要是文件大小。用 8 位而不是浮点精度所需的 32 位，意味着保存或加载图像数据时占用的磁盘存储和内存只有四分之一（对一张 RGB 图像，用字节时总位数是 3*8 = 24 位。用 C++ 的 float 类型则需要 3*32 = 96 位，96/24 = 4）。这些 8 位 RGB 图像在互联网上传输时，占用的带宽远小于 32 位浮点图像。你付的带宽费用更少，图像在屏幕上出现得也更快，这两个优势相当有吸引力。

总之可以说，8 位 RGB 图像是存储像素值最常见的方式。对于大多数与图像有关的消费电子设备（数码相机、电视屏幕、计算机等）所生成、处理、保存或读取的图像，这一点尤其成立。

不过随着网络与磁盘技术改进、成本下降，在互联网上使用 8 位 RGB 图像变得不再那么必要。需要制作高质量图像的行业如今一般更青睐使用浮点精度的图像格式。1990 年代开发过一些过渡格式，比如使用 12 位的 Kodak Cineon 文件格式。今天你可以用 OpenEXR 文件格式，它几乎是电影行业的事实标准。用 OpenEXR 你可以把图像存成 16 位（称为半浮点）或 32 位。另一个支持浮点精度的流行格式是 TIFF 格式，它最初开发于 1980 年代中期（但对浮点编码的支持是后来才加的）。这类格式常常依靠压缩技术来缩小图像文件体积。别忘了数码相机用来把 CCD 传来的数据存出去的 RAW 格式，以及在视觉特效行业很流行的 DPX 格式（Digital Picture Exchange）（关于这些格式的更多信息将在 2D 部分中提供）。

乍看之下，把图像数据写成特定文件格式的过程似乎很神秘。它往往确实如此，因为在大多数情况下，作为用户你要做的只是把数据以正确的形式交给该图像格式的 API，而 API 就像一个黑箱替你干活。要把图像数据写成特定格式，你需要下载并在计算机上安装该图像格式的 API，并在用这个 API 的库编译程序时做一些复杂的链接或配置。另一种做法是，如果你了解某个格式的规范，也可以直接读写该格式的图像。本课我们会演示如何读写 PPM（以及 PFM）文件，它是你能想象到的最简单的文件格式。尽管如此，Photoshop 或（Mac 上的）Preview 这类应用都支持它，这让它在开发图形应用、需要快速读写图像时非常方便。我们还会演示如何用自己的程序读取并显示 PPM 图像。

用来编码一个像素的位数称为 色彩深度 或 位深度 或 每像素位数（bpp）。位数越多，能创造的颜色越多。注意只有 1 位时我们只能编码黑或白。如今大多数图像每像素用 24 位（每个分量 8 位即 1 字节，一个像素有 3 个分量 R、G、B），这个标准也称为真彩色。大多数图像格式按 R-G-B 的顺序存像素分量，但有些格式按相反的顺序（B-G-R）存。

图像量化

过去，渲染器通常用浮点精度表示颜色，但在存盘之前必须把这些颜色转换成低得多的位深度。即使在今天，大多数图形文件格式也只支持 24 bpp（用更多位会增加文件在磁盘上的大小）。记住 24 bpp 意味着图像的每个通道，也就是 RGB 像素的每个分量，用 8 位，而我们只能用这 8 位表示 0 到 255 的整数。从 float 到 byte 的朴素转换做法是：把原始浮点值钳制到 0 与 1 之间，乘以 255，把结果赋给相应类型的变量（byte，或 C++ 中的 unsigned char，这涉及一次类型转换）。


unsigned char r = (unsigned char)(std::max(0.f, std::min(1.f, pixel[0])) * 255);
unsigned char g = (unsigned char)(std::max(0.f, std::min(1.f, pixel[1])) * 255);
unsigned char b = (unsigned char)(std::max(0.f, std::min(1.f, pixel[2])) * 255);

如你所见，这个过程降低了我们表示像素值的精度。例如原先落在 100 到 101（不含 101）范围内的所有像素值，在钳制并乘以 255 之后，都被归并成数值 100。换句话说，我们把这个范围内的所有颜色或像素值都归并成一个单一的颜色或数值。这个过程称为 图像量化。

通常，这会降低图像质量，因为我们丢失了关于图像本身的信息（原始图像数据中的色调或颜色层次被归并成更少的数值，因而更少的颜色）。这也可以看作一种图像压缩。图像量化会在图像中引入误差（等值线），可以用 半色调 和 抖动 之类的技术来减轻。为了让本课保持合理篇幅，这些技术将在单独一课中说明。此外，图像量化本身意义不大，因为专业图像格式（TIFF、OpenEXR）支持浮点图像（每通道 32 位，即 96 bpp）。不过由于本课会介绍一种把浮点值转换成 32 bpp 图像的简单存图格式，这里只提一句：上面给出的基本转换技术可以改进。注意例如 100 到 101 范围内的所有值都映射到取整值 100（如图 8 所示）。然而大于 100.5 的浮点值离 101 比离 100 更近。因此更好的做法是把 99.5 到 100.5 的所有值都映射到 100，把 100.5 到 101.5 的所有值都映射到 101。这只需对我们上面给出的代码做一点改动。当一个值乘以 255 之后，我们在结果上加 0.5 的偏移，再截断到最近的整数。如果浮点值是 100.3，加 0.5 得 100.8，会被转换成 100。如果值是 100.6，加 0.5 得 101.1，会被转换成 101。


unsigned char r = (unsigned char)(std::max(0.f, std::min(1.f, pixel[0])) * 255 + 0.5);
unsigned char g = (unsigned char)(std::max(0.f, std::min(1.f, pixel[1])) * 255 + 0.5);
unsigned char b = (unsigned char)(std::max(0.f, std::min(1.f, pixel[2])) * 255 + 0.5);

编码伽马

如果你把图像存成 32 bpp 的文件格式，给图像加一个伽马编码可能是有用的（我们已在上一章解释过使用伽马编码的好处）。这可以很容易地在像素值从 32 位转成 8 位之前完成。下面的代码做的事情与 sRGB 色彩空间类似，但并不完全相同。它只是对像素值施加 1/2.2 的伽马编码（把线性像素值转换成 sRGB 涉及的过程要稍复杂一些）：


unsigned char r = (unsigned char)(std::max(0.f, std::min(255.f, powf(pixel[0], 1/2.2) * 255 + 0.5f)));
unsigned char g = (unsigned char)(std::max(0.f, std::min(255.f, powf(pixel[1], 1/2.2) * 255 + 0.5f)));
unsigned char b = (unsigned char)(std::max(0.f, std::min(255.f, powf(pixel[2], 1/2.2) * 255 + 0.5f)));

简单例子：PPM 文件格式

最后我们给出一个非常简单的图像格式的例子，它能被 Photoshop 或（Mac 上的）Preview 这类应用读取。由于简单，这个格式在调试图形应用时很有用。这个格式叫 PPM（是 Portable Pixmap 的缩写），据其创造者说，它是最低公共标准的图像文件格式。我们不建议把它当作专业格式，但作为起点它很完美。在下面的例子里，我们会创建一张浮点图像，在这个图像的像素中存一些值，再用 PPM 格式把结果存到磁盘：


void saveToPpm(const char *filename)
{
    std::ofstream ofs;
    // 在 Windows 上必须使用二进制标志
    ofs.open(filename, std::ios_base::out | std::ios_base::binary);
    ofs << "P6\n" << width << " " << height << "\n255\n";
    float *pixel = imageData;
    for (int j = 0; j < height; ++j) {
        for (int i = 0; i < width; ++i) {
            unsigned char r = (unsigned char)(std::max(0.f, std::min(255.f, powf(pixel[0], 1/2.2) * 255 + 0.5f)));
            unsigned char g = (unsigned char)(std::max(0.f, std::min(255.f, powf(pixel[1], 1/2.2) * 255 + 0.5f)));
            unsigned char b = (unsigned char)(std::max(0.f, std::min(255.f, powf(pixel[2], 1/2.2) * 255 + 0.5f)));
            ofs << r << g << b;
            pixel += 3;
        }
    }
    ofs.close();
}

这段代码是上面给出的 Image 类的一部分。首先我们需要打开一个用于输出的文件（第 6 至 7 行）。我们写入一些关于图像的信息（通常称为文件头）。P6 定义 PPM 图像的类型（彩色 8 bap），然后是图像的宽度和高度。第三个值指定文件中编码的最大值（255）。最后我们遍历图像的所有像素，对原始像素值施加伽马编码（如果需要的话），把结果乘以 255，加上偏移（0.5），把结果截断到 [0:255] 范围，并转换成字节（unsigned char）。转换后像素颜色的三个分量被写入磁盘（第 15 行），然后我们移到下一个像素（在图像数据的 float 数组里偏移 3 个 float。第 16 行）。

高动态范围图像

用来定义屏幕上什么算白色的惯例，理论上完全是任意的。不过在实践当中，大多数计算机系统把数值 1（R = 1, G = 1, B = 1，如果你处理的是 float 或 96 bpp 图像；处理 32 bpp 图像时是 255）定义为白色，或定义为屏幕上能显示的最亮颜色。然而（假设你用浮点图像）存大于 1 的值是可能的。回想第一章：颜色其实就是光，我们应当把颜色的色相与它的强度区分开。在真实世界的场景中，场景最亮的区域（例如暴露在阳光下的区域）与最暗的区域（处于阴影中的区域）之间可能存在极大的差异。在一个典型的晴天，这些区域之间的比值可以极端到 1 比 100000。如果你用 8 位编码颜色三个值中的一个（红、绿或蓝分量），你能定义的最大数是 255。那样的话，图像的动态范围只有 1:255。每像素每通道用 12、14（RAW 格式）、16（半浮点）或 32 位的文件能保存更大的亮度范围，称为 高动态范围图像（或 HDRI）。大于 1 的颜色无法在屏幕上显示，它们会被裁剪到 1。为了显示超出屏幕自身动态范围的颜色，我们需要把大于 1 的值重映射到一个能在屏幕上可视化的范围。这个过程称为 色调映射。最简单的做法是把颜色乘以一个小于 1 的值，但存在更聪明的色调映射算法（我们将来会写一课讲这个话题）。

压缩

如前所述，图像数据可能在磁盘上占很大空间。缩小图像文件体积的一种办法是降低位深度（例如你可以每通道用 8 位而不是 32 位来存像素值，这会把文件大小减少到四分之一）。不过正如我们在图像量化那一部分解释的，这种技术有减少颜色数量的缺点。另一种技术是压缩图像数据。例如设想你图像的第一行是完全黑色的，这张图宽 640 像素。与其往文件里写 640 次每像素 3 个字节，你完全可以只往磁盘上写一个数表示同一个像素值应横向重复多少次，再写另一个值编码该像素值是多少。在这个例子里，就是 640 次 3 作为第一个值，第二个值是 0。

这样描述这一行时，你只需存 4 个数（1 个表示行内重复次数，3 个表示要重复的颜色），而不是往磁盘上存 1920 个数（640*3），这是相当可观的缩减。这种压缩方法称为 RLE（游程编码），极其简单，但还存在多得多的技术，其中一些会用到小波这样相当复杂的数学工具（关于这个话题的更多信息可以在 2D 部分找到）。压缩通常由图像文件格式的 API 替你管理，你不太可能需要自己写这方面的代码。在这个阶段你真正需要了解的关于压缩的唯一一点是：有些压缩方法会丢弃原始图像中的信息，以换取好得多的压缩比。换句话说，如果压缩后的图像看起来和原始数据大致相同，那它永远不会看起来完全一样。这类方法被称为 有损 的，因为原始图像数据中有一部分确实丢失了（JPG 格式用的就是有损压缩方法）。相比之下，确实保留原始图像数据的方法被称为 无损 的（但它们通常不如有损压缩方法高效）。

使用 alpha 通道

alpha 通道（也叫 不透明度通道、遮罩 或 遮片，后者源自传统的光学视觉特效术语）是第四个通道，有时与图像基本的 RGB 通道关联在一起。它表示所渲染物体的不透明度，可用于按照下面的公式把这些物体合成到一张背景图像之上：

$$I_{final} = I_{B} \cdot (1 - I_{F \: alpha}) + I_{F} \cdot I_{F \: alpha}$$

换句话说，你可以把一张计算机生成的图像合成到另一张图像（一张照片或另一张计算机生成的图像）之上：把背景图像 \(I_{B}\) 乘以一减去前景图像的 alpha 通道（我们把它取反），再把这个结果与前景图像 \(I_{F}\) 乘以它自己的 alpha 通道 \(I_{B \: alpha}\) 相加。这种方法称为 alpha 合成。你可能也会看到 alpha 混合 这个说法，如果你用过 OpenGL 也许对它不陌生，不过它的公式和使用场景与 alpha 合成略有不同。下面是 alpha 合成过程以图示形式呈现的样子：

Rgb pixelComp;
const Rgb& pixelBG = ImageA.getPixel(x, y);
const Rgba& pixelFG = ImageB.getPixel(x, y);
pixelComp = pixelBG * (1 - pixelFG.alpha) + pixelFG * pixelFG.Alpha;

我们很少在渲染器里做合成，而是把这项任务交给专门的 2D 应用（比如静态图像用 Photoshop，专业视觉特效工作用 Nuke）。alpha 通道的概念发展于 1970 年代末，由 Thomas Porter 和 Tom Duff（当时在 Lucasfilm 工作）于 1984 年在一篇题为「Compositing Digital Images」的开创性论文中完整提出。关于图像 数字合成 的更多信息可以在 2D 部分找到。

正式的定义：像素是采样，不是小方块

像素到底是什么？大多数时候，为了简化，很少有必要去解释像素不过是一个小方块，就像砖之于墙。我们周围的世界由表面连续的物体构成。然而当我们拍一张数字照片时，我们把这些连续的表面变成一组离散的采样，其颜色代表物体在每个像素投影面积上的平均颜色。这个过程如下图所示：

结论

本章我们回顾了关于数字图像文件最重要的概念。数字图像是一个二维的 RGB 或 RGBA 像素数组，其尺寸由数组沿宽度（列数）和沿高度（行数）的像素数定义。数字图像也可以（例如在 Photoshop 中）被看成三个二维的数值数组（每种原色一个，即红、绿、蓝），称为通道。图像还可能有第四个通道（当它们是计算机生成的时候），即 alpha 通道，表示 3D 场景中物体的不透明度。alpha 通道可用于把计算机生成的元素合成到照片（在视觉特效行业称为 plate）或其他计算机生成的图像（背景）之上。文件格式定义了 RGB 图像数据如何保存到文件。理论上这些数据可以以任何形式保存，只要图像内容能被正确读回并显示在屏幕上。不过文件格式通常是为特定目标设计的，比如压缩图像数据以使文件尽可能小（例如 JPG 格式）、以浮点精度而非字节存储图像数据（RAW、OpenEXR），或者设计得易于实现（PPM）。如果图像文件使用的位长（每像素位数）与计算机生成图像所定义的位长不同，我们就需要在存盘前把像素值转换成另一种数值表示，这个过程称为量化。最后要记住，与其把像素看作方块，不如把它们看作代表被摄场景中物体的采样（这对真实世界的照片和计算机生成的图像都成立）。
