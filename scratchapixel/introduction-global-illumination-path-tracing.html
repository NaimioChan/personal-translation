前言

这门课程想对路径追踪这个概念做一次轻量介绍：它描述的是一类通用方法，用来求解光与不同材质（玻璃、混凝土、皮肤等）物体相互作用的种种情形。我们不直接一头扎进路径追踪本身，也不去啃它背后的数学和催生它的那些研究论文——那些主题要好几门课才讲得完——而是先在现阶段聚焦于路径追踪所处理的那类光照问题的一个简单、直观的实现，也就是所谓的间接漫反射光照。它指的是纯漫反射表面对光线的反射。

总的来说，这门课会带你接触一些基本概念——要完全理解它们还需要继续学习——同时配上一份篇幅相当短、可实际运行的间接光照现象实现。这不仅能让你对问题有一个初步把握，也能帮你建立信心和动力。带着扎实的实践基础去面对后面更有挑战的课程，要比直接扎进复杂的数学概念容易得多，后者容易让人不知所措、望而却步。这也是本课在顺序上被安排在这里的原因：让你在遇到更抽象的材料之前，有机会以更容易接受的方式先和这些概念打交道。

到底什么是全局光照？

什么是全局光照？你知道，我们能看见东西，是因为太阳这类光源发出的光在物体表面反弹。当光线从物体表面只反射一次就到达眼睛时，我们称之为直接光照。但光源发出的光线，往往要在物体表面之间多次反弹才到达眼睛（当然，这取决于场景的构成）。为了与直接光照区分，这种情况我们称为间接光照：光线沿着复杂的路径，从一个物体弹到另一个物体，最后才进入我们的眼睛。下面的图里能看到这个效果。

有些表面并没有直接暴露在光源（通常是太阳）下，却也不是全黑的。这是因为光在表面之间来回反弹时，它们仍然接收到了光。

很难量化间接光照对场景亮度的贡献有多少。如前所述，这取决于场景的构成，因此变化很大。不过，间接光照多半都占据了场景整体光照中相当关键的一部分。所以，如果我们的目标是产出接近现实所见的图像，模拟这个效果就是头等重要的。

能模拟全局光照是每个渲染系统都该具备的功能，那为什么还要大做文章？因为它在某些情况下虽然简单，但一般情况下求解起来很复杂，而且计算代价高昂。这就解释了为什么大多数实时渲染系统并不提供全局光照效果的模拟（至少不是尽可能准确地模拟）。简言之，全局光照在理论上模拟起来是简单的（数学提供了所需的理论工具，它们本身并不难）。但在实践上，要高效地模拟这个效果，即便有超快的计算机也是个难题，因为模拟这一过程本身的算法计算量极大。

图 1：正向追踪的一个例子。一条光线在到达眼睛之前可能反弹多次。

以下是这件事本身就难的几个原因：

  • 很难设计出一个能解决所有光路的通用方案：光线在到达你的眼睛之前，可能与许多不同的材质发生作用。举例来说，光源发出的一条光线可能先被漫反射表面反射，然后穿过一杯水（在那里被折射，也就是方向稍微改变），接着打到金属表面，再到另一个漫反射表面，最后到达眼睛。可能的组合有无限多种。光线从光源到眼睛所走的路径叫作光路。在现实世界里，光是从光源传播到眼睛的。从数学角度看，我们知道规定光线如何被各种材质表面反射的规则。比如，我们了解反射定律和折射定律。用计算机模拟一条光线与不同材质作用时的路径，是我们轻松就能做到的。但问题在于，图形学里的正向追踪并不是一种高效的成像方式。模拟光线从光源到眼睛的路径是低效的（如果你需要复习这个题目，见课程 光线追踪入门：创建 3D 图像的简单方法）。我们更倾向于反向追踪，也就是沿光线从眼睛回溯到它出发的光源。问题在于，反向追踪虽然计算直接光照很高效，但模拟间接光照时并不总是高效。本课会说明原因。

  • 直接光照主要是从着色点向场景中各个光源投射阴影光线。计算直接光照能有多快，取决于场景里光源的数量。然而，计算间接光照通常比计算直接光照慢得多，因为它需要模拟大量额外的、在场景中四处反弹的光线的路径。这些光路的模拟一般用光线来完成，而众所周知，光线追踪的代价相当高。随着本课展开，为什么模拟全局光照代价高昂，原因会越来越清楚。现在只需说明一点：模拟间接光照效果所需的光线数量，比只考虑直接光照时要多出几个数量级。既然由于光线与三角形求交方法计算量大，用光线追踪算直接光照本就慢，那么向场景投射多出几个数量级的光线，只会把这个问题线性放大。

回想本课前面那部分：物体接收光有两种方式，直接从光源接收，或间接地从其他物体接收。物体也可以充当光源——不是因为它们自己发光，而是因为它们反射来自光源的光，或反射来自其他物体的光，而那些物体又是从光源或其他物体那里得到光的，如此类推。因此，在计算一个着色点接收到的光量时，我们需要把这些物体考虑进来。（当然，一个物体要能反射光，它首先得被照亮，无论是直接还是间接。）

这个问题之所以复杂，是因为物体 A 朝物体 B 反射的光，可能又被 B 反射回 A，A 再把这部分光中的一些反射给 B，如此往复。B 的受照取决于 A，而 A 的受照也取决于 B（见图 3）。这个过程涉及表面之间的能量交换，理论上可以无限持续下去。用数学语言把它表达出来是可行的，但在计算机上模拟这个效果，与其说复杂，不如说慢，而且可能需要在与真实世界的贴合程度上做出妥协。

模拟间接光照，要追踪光线从被光源发出那一刻到抵达观看者眼睛所走的路径。因此，我们常把这个过程称为光传输，它描述的是光在空间中从一个表面弹到另一个表面时如何传播。光传输算法就是求解这个光传输问题的算法（反向追踪就是一个例子，我们会在本章后面讨论）。正如本课将要说明的，模拟光传输是个复杂的问题，要设计出单独一个能高效处理现实世界中所有类型光路的算法，非常困难。确实，光线与玻璃球作用时遵循的光学规则，和它与完全漫反射表面、或与皮肤这类半透明表面作用时并不相同。

如何用反向追踪模拟间接光照？

要理解用反向追踪模拟全局光照难在哪里，首先必须弄清我们怎么模拟间接光照。人们做过许多尝试，想把这个过程形式化——把它纳入一个数学框架。（有兴趣、偏数学的读者，可以在本课末尾的参考资料部分找到更多信息。）不过我们先从简单的讲法入手。

从之前的课程我们知道，照亮物体表面某一点 \(P\) 的光，可以来自围绕 \(P\) 处表面法线 \(N\) 的半球内所有可能的方向。面对直接光源时，确定光的来源很直接。我们只要遍历场景中所有光源，或者取它们的方向（对平行光），或者从光源向 \(P\) 连一条线（对球形光源或点光源）。

然而，处理间接光照要复杂得多，因为 \(P\) 上方的每一块表面都可能把光重新导向它。从直接光源求光线的方向相对简单，可当一个表面自身发光时，我们又怎么确定方向呢？这时不再有单一的光源位置可以用来计算光照方向。面对一个发光表面，可供选择用来确定光照方向的点有无限多个。

那么，既然那个物体表面上的每一点都可能把光反射向 \(P\)，凭什么选这个方向而不选那个？而如果要把所有点都考虑进来，我们会得到一个无限的集合，这显然不现实。

这个问题的答案既简单又棘手。在某些情形下，问题可以解析求解，存在闭式解。也就是说，可以用一个方程把它解出来。当场景中物体的形状简单（例如球体、四边形、矩形）、物体彼此不投射阴影、并且表面上的光照均匀时，这样的解才是可能的。可以看到，条件相当多。

例如，计算两个矩形面片之间、或一个矩形与一个球体之间的光能交换是相对直接的，只要它们不被其他物体遮挡，并且颜色保持一致。然而，一旦我们在面片和球体之间插入第三个物体，或者开始对这些物体做着色，那些简单的解析解就不成立了。（关于这个主题，你可以查一下辐射度方法，它是 90 年代在光线追踪兴起之前流行的一种技术。今天，用光线追踪求解这个问题已经成为标准做法。）

因此，我们必须为这个问题找一个更稳健的解——一个不管物体形状如何都成立、也不依赖可见性的解。在这些约束下求解是相当有挑战性的。我们可以用一个简单的方法，叫作 Monte Carlo 积分。Monte Carlo 积分背后的理论在计算机图形学的数学部分的两门课里有详细讲解。为什么要积分？因为从本质上说，我们要做的是把来自围绕 \(P\) 处法线的半球内所有可能方向的光「收集」起来。用数学语言说，这个收集过程可以用一个「积分」算子表示：

$$\text{gather light} = \int_\Omega L_i.$$

这里 \(\Omega\)（希腊大写字母 omega）表示围绕 \(P\) 处法线取向的方向半球。它定义了做积分的空间区域。

做积分时，我们通常是针对某个函数。那么在我们的情形里，这个函数是什么？图 3 把场景中其他物体对 \(P\) 的照明表示为一个函数。凡场景中的物体投影到半圆盘上的地方，这个函数都非零（前提是物体本身不是黑的）。这个函数可以用不同方式参数化：它可以是立体角的函数（用希腊字母 omega，即 \(\omega\) 表示），也可以用球坐标 \(\theta\) 和 \(\phi\)（希腊字母 theta 和 phi）来表示。这只是参数化半球的两种不同但同样有效的办法。在二维情形下（图 3），这个函数可以直接定义为角度 \(\theta\) 的函数。

在这套讲着色的课程里，为了让入门内容更好懂，我们刻意避开了辐射度量学的专业术语。不过此时引入辐射亮度这个概念或许有帮助，你读其他关于全局光照的资料时很可能会遇到这个词。辐射亮度才是描述场景中物体反射向 \(P\) 的光的恰当术语，通常用字母 \(L\) 表示。

如果你不熟悉积分这个概念，我们建议先读计算机图形学的数学与物理部分的课程。不过你可以把这里的积分符号理解为：「把积分号右边的值（在这里是 \(L_i\)）在空间区域 \(\Omega\) 上收集起来。」在这里，\(\Omega\) 表示围绕 \(N\)（着色点 \(P\) 处的法线）取向的半球（二维情形下则是半圆盘）。举个例子，想象这个半球的表面上撒满了「米粒」。积分的意思就是「把撒在这个半球表面上的米粒收集起来、数一数有多少粒」。不过要注意，「米粒」是离散的单元，数起来很简单。而在我们的情形里，我们想度量的是从 \(P\) 处直接可见的那些表面反射来的光量，这就复杂得多，因为这些表面是连续的，无法像米粒那样拆成离散单元。但原理是一样的。

要理解我们怎么处理「该选物体表面上的哪一点，来计算这个物体对我的着色点 \(P\) 的照明贡献」这个问题，可以这样想：既然我们用积分把来自所有方向的光收集起来，那我们需要的就不是物体表面上的某一个点，而是构成它表面的所有「点」。然而，用点铺满一个物体的表面既不实际也不可行。为什么？因为点是奇点——没有面积。所以我们无法用无限多个没有物理尺寸的点来表示一个表面。

为解决这个问题，一种可行的做法是把物体表面划分成大量很小的面片，并计算每个面片对 \(P\) 的照明贡献。在计算机图形学里，这种做法在技术上可行，称为辐射度方法。确实有方法可以求解小面片与 \(P\) 之间的光传输问题，但辐射度方法有局限——它对漫反射表面效果好，对光泽或镜面表面就不行。关于辐射度方法的更多细节可以在后面几节找到。

另一种做法是把物体表面划分成小面片，并把这些面片当作小的点光源，来模拟它们对 \(P\) 的照明贡献。这种做法在理论上是可行的，一种称为 VPL（虚拟点光源）的高级渲染技术就基于这个原理。不过说到底，Monte Carlo 光线追踪更简单、也更通用。

Monte Carlo 是应对这个问题的另一种办法。它本质上是一种统计方法，基本想法是：从 \(P\) 向表面上方随机方向投射光线，并求出这些光线所命中的物体的颜色（如果它们确实与几何体相交），就可以近似或估计场景中其他物体重定向向 \(P\) 的光量。把每条光线的贡献累加，再除以光线数量。用伪数学的方式写出来就是：

$$\text{Gather Light} \approx \dfrac{1}{N} \sum_{n=0}^N \text{ castRay(P, randomDirectionAboveP) }.$$

如果你已经熟悉 Monte Carlo 积分，大概已经知道用 Monte Carlo 积分近似一个积分的公式可以写成：

$$\langle F^N \rangle = \dfrac{1}{N} \sum_{i=0}^{N-1} \dfrac{f(X_i)}{pdf(X_i)}.$$

如果你不熟悉 Monte Carlo 方法，可以在计算机图形学的数学部分的两门课里找到讲解。在上面的公式里，你会注意到有一个 PDF 项，为简单起见我们先不管它（供你参考，PDF 代表「概率密度函数」）。到这一步，我们只希望你能理解 Monte Carlo 积分的原理，所以不必太纠结技术细节——那些我们会在下一章讲到。

如果你以前没接触过 Monte Carlo 积分，理解它最简单的办法是拿民意调查来类比。假设你想知道一个国家全部成年人口的平均身高。你可以去量每个人的身高，把所有测量值加起来，再除以人数。可是人口太多了，这种做法要花的时间长到做不完。我们说这个问题是不易处理的。换个办法，你可以只量这个人群里一个小样本的身高，把这些身高加起来，再除以样本量（把这个数记为 \(N\)）。

这个办法成立的前提是样本里的人是以相等概率随机选出的（即人群中的每个个体被纳入样本的机会相同）。这就是我们说的民意调查。结果大概不是精确的平均身高，但一般是个「不错」的估计。增大 \(N\)，你（从概率意义上）提高了估计的准确度。

在近似或估计场景中其他物体反射向 \(P\) 的光量时，原理类似。这个问题同样不易处理，因为我们无法把半球内的所有方向都算一遍（如前所述，表面是连续的，因而有无穷多个点和方向，问题因此不易处理）。于是我们随机选几个方向，取它们贡献的平均值。

用伪代码写出来就是：


int N = 16; // 随机方向的数量
Vec3f indirectLightingApprox = 0;
for (int n = 0; n < N; ++n) {
    // 在 P 上方、围绕 P 处表面法线 N 取向的半球内，沿一个随机方向投射一条光线
    indirectLightingApprox += castRay(P, randomDirectionAboveP); // 累加结果
}
// 除以所取方向的总数
indirectLightingApprox /= N;

在计算机图形学里，我们把这些随机方向称为采样。在 Monte Carlo 采样中，我们在积分的定义域上取采样，也就是积分 \(\int_\Omega L_i\) 所施行的空间区域——在这个例子里是半球。

不必操心怎么在半球上选这些随机方向，或者该用多少个采样（N）。这些我们很快就讲。现在只要记住：Monte Carlo 积分方法给出的只是真实解的一个估计（或近似），真实解是积分 \(\int_\Omega L_i\) 的结果。这个近似「质量」如何，主要取决于所用采样数量 \(N\)。\(N\) 越高，你越可能得到接近真实积分的结果。这个话题我们下一章再回过头讲。

我们说的采样是什么意思？既然光可以来自 \(P\) 上方的任何方向，在 Monte Carlo 积分里，我们改为在围绕 \(P\) 取向的半球内挑几个随机方向，沿这些方向向场景中投射光线。如果这些光线与场景中的几何体相交，我们就计算被交物体在该点的颜色。这个颜色代表被交物体沿光线所定方向反射向 \(P\) 的光量：


Vec3f indirectLight = 0;
int someNumberOfRays = 32;
for (int i = 0; i < someNumberOfRays; ++i) {
    Vec3f randomDirection = getRandomDirectionHemisphere(N);
    indirectLight += castRay(P, randomDirection);
}
indirectLight /= someNumberOfRays;

记住，我们的目标是把场景中物体反射向 \(P\) 的全部光收集起来，这可以用积分 \(\int_\Omega L_i\) 表示。这里 \(\Omega\) 表示围绕 \(P\) 处法线取向的方向半球。这就是我们要解的公式；要用 Monte Carlo 积分近似这个积分，我们需要对积分号右边的函数（即 \(\int\) 符号所代表的内容）做「采样」，具体来说是对其中 \(L_i\) 这一项。

采样指的是：从我们要求解的积分的定义域中选取随机方向，并在这些随机方向上求积分号右边函数的值。对间接光照来说，积分的定义域，也就是积分所施行的空间区域，是方向半球 \(\Omega\)。

现在看一个例子，看看它是怎么运作的。为简单起见，我们先从二维例子开始，本课后面会给出在三维中应用这个技术的代码。

想象我们要计算间接到达 \(P\) 的光量。首先在 \(P\) 上方画一个理想的半圆盘，沿着色点处的表面法线对齐。这个半圆盘是一个可视化的表示，代表我们需要在其上收集场景中各表面反射向 \(P\) 的光的那组方向。接着我们计算 \(N\) 个随机方向，你可以把它们想成落在半圆盘外缘上的 \(N\) 个点，位置是随机选的。在二维情形下，可以用下面的代码完成：

  • 第 1 步：首先，我们为单位圆的半圆盘选一个随机位置，做法是在 \([0, \pi]\) 范围内的任意位置为角度 \(\theta\) 取一个随机值。计算随机角度可以用 C++ 的随机函数（例如 drand48()），它返回 \([0,1]\) 范围内的一个随机浮点数。这个值随后需要映射到 \([0, \pi]\) 范围。

  • 第 2 步：「采样」得到的方向躺在一个尚未与着色点法线对齐的半圆盘上。给它定向的最好办法是用着色点的法线构造一个 2x2 矩阵，这里利用了二维向量的一个有趣性质：用 \((V_x, V_y)\) 和 \((V_y, -V_x)\) 就能建立一个二维笛卡尔坐标系。这两个向量定义了笛卡尔坐标系的上轴和右轴，它们永远互相垂直。矩阵就位之后，我们就可以旋转采样方向了。

  • 第 3 步：接下来，我们沿采样方向追踪一条光线。这一步检查采样光线是否与场景中的物体相交。如果相交，我们就计算交点处的颜色，并假定它代表被交物体沿光线方向反射向 \(P\) 的光量。

  • 第 4 步：现在我们知道场景中某个物体沿采样方向反射向 \(P\) 的光有多少了，于是把这个求交结果当作一个光源。在这个例子里，我们假定 \(P\) 处的物体是漫反射的，所以把光线交点处物体的颜色乘以表面法线 \(N\) 与光照方向（在这里就是采样方向）之间夹角的余弦。这遵循 Lambert 余弦定律：漫反射的强度正比于光照方向与表面法线之间夹角的余弦。我们还假定场景中其他物体也都是漫反射的（因为我们递归调用了 castRay() 函数，而在这个例子里它只计算漫反射表面的外观）。

  • 第 5 步：累加每个采样的贡献。

  • 第 6 步：按照 Monte Carlo 积分的公式，把各采样贡献之和除以采样数量 \(N\)。

  • 第 7 步：最后，把 \(P\) 处物体来自直接光照与间接光照的漫反射颜色累加起来，再把这个和乘以物体的反照率（记得把漫反射反照率除以 \(\pi\) 作为归一化因子，着色入门里解释过）。


vec3f castRay(Vec2f P, Vec2f N, uint32_t depth) {
    if (depth > scene-&gtoptions.maxDepth) return 0;
    Vec2f N = ..., P = ...; // 着色点的法线与位置
    Vec3f directLightContrib = 0, indirectLightContrib = 0;
    // 计算直接光照
    for (uint32_t i = 0; i < scene-&gtnlights ++i) {
        Vec2f L = scene-&gtlights[i].getLightDirection(P);
        Vec3f L_i = scene-&gtlights[i]-&gtintensity * scene-&gtlights[i]-&gtcolor
        // 假定 P 处的表面是漫反射的
        directLightContrib += shadowRay(P, -L) * std::max(0.f, N.dotProduct(L)) * L_i;
    }
    // 计算间接光照
    float rotMat[2][2] = {{N.y, -N.x}, {N.x, N.y}}; // 计算旋转矩阵
    uint32_t N = 16;
    for (uint32_t n = 0; n < N; ++n) {
        // 第 1 步：在半圆盘内抽取一个随机采样
        float theta = drand48() * M_PI;
        float cosTheta = cos(theta);
        float sinTheta = sin(theta);
        // 第 2 步：旋转采样方向
        float sx = cosTheta  * rotMat[0][0] + sinTheta  * rotMat[0][1];
        float sy = cosTheta  * rotMat[1][0] + sinTheta  * rotMat[1][1];
        // 第 3 步：把光线投射进场景
        Vec3f sampleColor = castRay(P, Vec2f(sx, sy), depth + 1); // 从 P 沿随机方向追踪一条光线
        // 第 4、5 步：把返回的颜色当作光来处理（假定被着色的表面是漫反射的）
        indirectLightContrib += sampleColor * cosTheta; // 漫反射着色 = L_i * cos(N.L)
    }
    // 第 6 步：把 indirectLightContrib 的结果除以采样数量 N（Monte Carlo 积分）
    indirectLightContrib /= N;

    // 最终结果是来自直接与间接光照的漫反射，乘以 P 处物体的颜色
    return (indirectLightContrib + directLightContrib) * objectAlbedo / M_PI;
}

如果你是 Monte Carlo 方法的专家，可能已经注意到我们跳过了把采样贡献除以随机变量 PDF 这一步。这是有意为之，免得让不熟悉 PDF 概念的读者困惑。完整的实现请参考下一章。

瞧，这就完成了。现在你大概能看出这个技术为什么计算代价高了。要计算间接光照（这里指的是间接漫反射，因为我们模拟的是漫反射表面如何互相照亮），你需要投射多条光线（上面的例子里是 16 条）。每当其中一条光线与漫反射表面相交，同样的过程就会重复一遍：这个过程是递归的。经过 3 次反弹，这就意味着向场景投射 16 * 16 * 16 = 4096 条光线（假定所有光线都与几何体相交）。光线数量随每次反弹指数增长。因此，与镜面反射类似，我们在指定的反弹次数（例如 3 次）之后就不再投射光线，在上面的代码里这由 maxDepth 变量控制。

注意，每多一次反弹，光的贡献都会减弱。这是因为每次从表面投射新光线，其贡献都会按余弦定律打折扣。举例来说，在有 2 次反弹的情况下，射入场景的一条光线可能在点 \(P_1\) 处与物体相交（第 1 次反弹）。这个交点 \(C_1\) 处的颜色会按着色法线与光线方向的点积 \(D_1\) 打折扣。然后从 \(P_1\) 再射出一条光线，在点 \(P_2\) 处与物体相交，这条光线的贡献 \(R_2\) 又要按 \(P_2\) 处着色法线与光线方向 \(R_2\) 之间夹角的余弦进一步打折扣。第二条光线的贡献，还要再按 \(P_1\) 处着色法线与第一个采样方向 \(D_1\) 之间夹角的余弦打折扣。于是，第二次反弹的贡献被衰减了两次，第三次反弹会被衰减三次，依此类推。到某个程度，再模拟更多反弹对最终图像几乎没有影响（对漫反射表面来说，通常 4 到 5 次反弹之后就是如此，不过这也取决于场景的构成）。

从技术上讲，你现在已经知道如何模拟间接光照与直接光照，足以生成真实感图像了。但这个挑战比看上去要复杂。在这个例子里，我们只讨论了用漫反射表面模拟间接光照。完全漫反射的表面在自然界里很少见，大多数场景都同时含有漫反射与镜面材质。此外，我们还没处理其他类型的材质，比如半透明材质，它们的行为并不像真正的漫反射材质。你可能会问：「为什么不用 Monte Carlo 积分模拟所有类型的材质？」这么做确实可行，但当场景中同时含有镜面、透明和漫反射表面时，方法就变得低效了。我们看几个例子来更好地理解这一点。

用间接漫反射的采样方法计算间接镜面反射是低效的

材质本质上分两类：镜面反射和漫反射。如上一课所述，漫反射物体表面某一点上方的所有光源（无论直接还是间接）都对该点的亮度有贡献。每个光源（同样是无论直接还是间接）的贡献都按光照方向与表面法线之间夹角的余弦衰减，不过这个细节我们先不管。记住漫反射与视角无关：无论从哪个角度看，漫反射表面的亮度总是一样的。镜面反射表面则不同：它们与视角有关。只有当视角与物体反射光所沿的镜面反射方向大致对齐时，你才能看到物体的反射。这意味着，光泽表面反射的光线是围绕反射方向的一个方向锥内反射出去的，上一章解释过。在计算一个物体对漫反射物体照明的贡献时，我们说的是间接漫反射。类似地，计算一个物体对光泽物体照明的贡献时，我们说的是间接镜面反射。另外还要记住两件事：

  • 对光泽表面来说，一束具有给定入射方向的光会在一个方向锥（镜面反射瓣）内被反射。这个锥的宽度取决于表面粗糙度；表面越粗糙，锥越宽。

  • 表面反射是一个互易过程：如果把视线方向与入射方向互换，表面反射光的方式保持不变

对漫反射表面来说，它上方的任何光源都对 \(P\) 处的照明有贡献。但对镜面反射表面而言，只有当视线方向 \(V\) 与入射光方向的镜面方向 \(R\) 大致对齐时，光源才可见。\(V\) 与 \(R\) 要对齐到什么程度，取决于表面粗糙度。如果表面非常粗糙，即使 \(V\) 与镜面方向 \(R\) 并不怎么对齐，光也可能仍被反射向视线方向，如图 7（上）所示。可是，一旦 \(V\) 完全落在镜面反射表面反射光线的那个方向锥之外，就完全不该有光被反射回来（图 7 上）。我们可以利用这个观察来计算光泽表面上物体的光泽反射。如果已知视线方向 \(V\)，那么只有入射方向特定的光线才会沿 \(V\) 被反射向眼睛。现在想象计算向量 \(V\) 的镜面方向，如图 7（下）所示。这样得到向量 \(R_V\)。接着，想象一个以 \(R_V\) 为中心、光线在其中被反射的方向锥。这告诉我们什么？任何入射方向落在这个锥内的光线，都会至少在某种程度上沿 \(V\) 被反射。

这是互易规则的直接推论：所有沿 \(V\) 被反射的光，其入射方向都必须落在以 \(R_V\) 为中心的那个方向锥内。

这就是我们用来计算间接漫反射的那个技术，为什么用在间接镜面反射上效果不好的原因。如前所述，只有以 \(R_V\) 为中心的方向锥内的光线，才对沿 \(V\) 反射的光有贡献。因此我们只应关心那个锥内的方向（如图 7 所示）。此前所用的技术——对整个半球采样——问题在于，生成的方向有很多落在锥外。换个说法：由于采样方向是随机选的，无法保证有任何一条光线落在镜面反射瓣的方向锥内（图 8 中）。即使只有少数光线落在锥内，锥外的光线也全是浪费，因为我们知道，即便它们命中了物体，贡献也是零。所以这个技术是低效的，因为在我们对半球采样时，大量光线被浪费了。

这是对问题的一个简化看法。如果你熟悉 Monte Carlo 积分，就会明白：理想情况下，你希望所有采样在某种程度上都覆盖到你要积分的函数取非零值的区域。不这么做就会增大我们所说的方差，它在视觉上表现为噪声。在图 8 中，你能看到绿色方块在光泽表面上的反射在渲染上的差别。左边是噪声很高的图像示例，相比之下右边那幅几乎无噪声。两幅图用相同数量的采样 \(N\) 渲染。左图方差高，右图方差低。下一部分的完整课程会讲解降低方差（方差缩减）的技术，例如重要性采样。你也会找到更多关于噪声的信息，以及它与采样数量 \(N\)、图像中噪声量之间的关系。

你的直觉应该会告诉你，解决这个问题的办法是让投射的光线全部落在镜面反射瓣的方向锥内（图 9）。按照 Monte Carlo 积分方法的要求，它们的方向仍应是随机的，但要落在有用的方向上。做法有好几种，我们会在下一部分关于高级全局光照的课程里学习。

焦散：反向追踪的噩梦

在光传输入门里，我们讨论过模拟焦散的困难。当光线被镜面反射表面、或由于折射而聚焦到空间中某些特定的点或区域时，就产生了焦散（例如光穿过一杯水或一杯酒，在离开玻璃时聚焦到一点，如图 10 和图 11 所示）。

焦散的问题与前面把采样分布到半球上来模拟间接镜面反射的问题类似。如图 11 所示，许多光线没有与球体相交，而这个球体是把光线汇聚向着色点 \(P\) 的。有一条光线与球体相交了，但交点离光线离开球体时汇聚的位置很远。尽管由于许多光线在那里汇聚，\(P\) 处很可能非常亮，我们的 Monte Carlo 方法却没能探到照亮 \(P\) 的那些具体光源。结果，\(P\) 在渲染中会显得很暗，而它本该是亮的。模拟焦散会生成噪声极大的图像，如图 12 所示。

焦散与间接镜面反射不同，因为至少在间接反射的情况下，我们对该往哪些方向投射光线有一些先验知识。前面说过，这些方向应当落在镜面反射瓣的方向锥内。但就焦散而言，我们不知道场景中焦散形成在哪里。我们不知道场景的哪些区域会把光线汇聚并重定向向 \(P\)。当然，我们可以提高采样数量 \(N\)，但要想显著降低方差，大概需要非常大的数量，而这会大幅拉长渲染时间。这不是一个有效的解。有效的解应当在把渲染时间压低的同时大幅降低方差。

只靠反向追踪，没有合理的办法模拟焦散，这也是研究者们发展出其他做法的原因。一种常见的解决方案是在预处理阶段用正向追踪模拟光在强镜面、透明物体中的传播。光线与光泽或折射材质作用之后打到漫反射表面，它们在这些点上的贡献被存入一个空间数据结构。在渲染时（预处理之后、计算最终图像时），如果主光线打到一个漫反射表面，我们就查询这个空间数据结构，看预处理阶段是否有能量由镜面或透明物体沉积在那里。这就是光子映射技术的基础，我们希望将来在还没写的一课里深入讲它。

一般来说，把反向追踪与正向追踪结合起来求解复杂的光传输，效果比单独用其中任何一种都好。例如在光子映射里，我们在预处理阶段用正向追踪跟踪光线与光泽、折射物体作用的光路，而可见性和直接光照则用反向追踪。这种做法被用在许多光传输算法里，比如我们已经提到的光子映射，以及双向路径追踪——后者我们会在将来的课程里讲。当然，这些光传输算法（也）有它们的局限。
