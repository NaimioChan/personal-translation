生成随机数

阅读时间：12 分钟。

随机数生成器这个题目也与噪声生成的概念有关。不过本课我们不谈噪声（指街头那种噪声，不是蒙特卡罗方法在你的图像里产生的噪声）。关于作为过程式生成图案的噪声，见《值噪声与过程式图案》和《Perlin 噪声》两门课。

在计算机上生成（伪）随机数

本章会比较短。至少在本课的这个版本里，我们不打算详细讨论随机数生成器这个题目。不过，因为蒙特卡罗方法主要依赖能生成随机数（往往还要符合给定的 PDF），所以很值得一提的是：拥有一个好的随机数生成器，对于保证蒙特卡罗方法输出的质量很重要。稍后我们会说明什么是好的随机数生成器，并简要解释这些生成器是怎么工作的。

生成随机数是计算机程序里使用任何蒙特卡罗方法的前提。那么你怎么生成随机数？真正的随机数（「真」是指不可预测）是可以用计算机生成的！比如想象一个装置，它测量某个本身就随机的自然现象（比如你 CPU 的温度，或者你在过去 10 秒里敲字母「a」的次数），把这个测量值转换成一个计算机可以当随机数用的数字。这些自然现象随机归随机，但这样的装置为什么对给程序提供随机数是理想的，并不难理解。除了对计算机来说太慢，这类系统的主要问题是：我们从监测这些「真实世界」随机变量得到的随机值，不一定能恰当地映射到计算机程序所需的那类随机变量。正如俄罗斯数学家 Ilya M. Sobol 所说：

一个能够令人满意地描述某类现象中某个物理量的随机变量，用来描述其他现象中的同一物理量时，可能就不那么令人满意了。

此外，这种装置产生的数的质量很难检查。最后，也许最重要的是，「锁定」生成的随机数序列可能是有利的，这样每次运行程序时，产生的都是同样的数、同样的顺序。你也许会想，那就不叫随机了。它们是确定性的，听起来正好是随机的反面。确实如此，这也正是我们把这类系统称为伪随机而不是随机的原因。它们产生的数具有随机分布的性质，但它们的取值以及产生的顺序总是相同的。在渲染中，这个性质至关重要。如果你用蒙特卡罗方法生成图像，一个「可重复」的随机数生成器（那它就是伪随机的）让你能锁定画面里的噪声图案。在生产环境中，结果的「可重复性」是必需的（至少对 Pixar 这样的工作室来说是必需的）。因此，任何依赖物理装置的随机数生成器（确实存在这种装置，本章后面会谈到），无论可能多么「真正随机」，都不总是理想的。总结一下，我们真正追求的，一般是「可控且可重复的随机性」。

一般来说，在程序里获取随机数可以用三种途径。你可以用存在表里的预生成随机数序列（一种古老但非常容易实现的方法，万一哪天你需要快速写点自己的东西），也可以用一个（真）随机数生成器或一个伪随机数生成器。

随机数表

原理很直接，和彩票号码的产生方式类似。如果你把 0 到 99（比如说）每个数写在一张卡片上，把卡片都放进帽子里，摇一摇，再一张一张地从帽子里抽出来，最后你就得到一列 100 个随机数。要在程序里使用这些数，你可以把它们存进内存（按抽出时的顺序），再创建一个全局变量，用来记录表中下一个可用的随机数。这当然简单，但这种做法有两个难处。第一，这列数必须真正随机（你帽子摇得不好，很多数最后就是递增顺序的）。而且很难保证用来产生这些数的物理装置能生成符合所需概率分布的序列（你可以用统计检验来检查你的随机数序列是否具备某些期望的性质，比如这些数是否真正独立同分布，即 i.i.d.）。此外，随机数序列的大小是有限的。


short rand[100] = {16, 55, 30, 12, 3, 92, ... };
int counter = 0;
int N = 32;
for (int i = 0; i < N; ++i) {
    short randNumber = rand[counter++];
    ...
}

1955 年，Rand 公司发布了一列一百万个随机数字。这是有史以来出版过的最长的随机数序列（可以在 Rand 公司网站上查找「A MILLION Random Digits WITH 100,000 Normal Deviates」）。

摘要：1946 年 RAND 开始研究后不久，就产生了对随机数的需求，用来求解各类实验性概率程序的问题。这些应用被称为蒙特卡罗方法，它们需要大量高质量的随机数字与正态偏差，这里给出的表格正是为满足这些需求而制作的。这本书是 RAND 在计算领域开创性工作的产物，也是 RAND 早期研究者耐心与坚持的见证。本书中的随机数表已成为工程与计量经济学教材的标准参考。此外，它们还被广泛用于采用蒙特卡罗试验的游戏与模拟中。作为迄今仍是最广泛的已出版随机数字与正态偏差来源，这本书被统计学家、物理学家、民意调查者、市场分析师、彩票管理者以及质量控制工程师常规使用。

（真）随机数生成器

顾名思义，随机数生成器产生真正的随机数（也就是说「你永远不知道会得到什么」，或者用更正式的表述，结果是不可预测的）。这些一般由物理装置产生，也叫噪声发生器，它们与计算机相连。在计算领域，从物理过程产生随机数的装置叫作硬件随机数生成器，或 TRNG（true random number generator 的缩写）。

如前所述，如果需要「真正的」随机性，这些生成器是合适的，但它们有一些难处。首先，正如提到的，噪声是由物理装置（比如真空二极管）产生的，得到的模拟信号需要以某种方式转换成数字序列（一串 0 和 1，再解释为数字）。这是一项有挑战的工作。另外，这些生成器不一定能按程序所需的速度产生随机数（换句话说，很难让程序对随机数生成器的调用与硬件噪声发生器的输出同步）。它们还可能遭遇硬件故障，而且它们产生的序列质量很难检查（它们可能带有偏置，也就是统计上产生的 0 比 1 更多）。

（伪）随机数生成器

任何考虑用算术方法产生随机数字的人，都处于一种罪孽状态。John von Neumann。

只要系统产生的随机数能通过某些检验，证明它们具有与真正随机变量相同的「统计」性质（比如均匀分布），那么这些数是用什么手段产生的就无所谓。计算机是确定性的，所以如前所述，用计算机产生真正的随机数很有挑战，这也是我们在需要「真正」随机性时一般求助于噪声发生器（前面谈过）的原因。不过，我们在计算机上能做的是，开发某种算法，生成一列近似随机数性质的数字。当数字由某个模拟随机变量 X 取值的算法或公式产生时，它们就叫伪随机数。而这个算法叫作伪随机数生成器（或 PRNG）。这里「模拟」这个词很关键：它只是说，这个算法能生成一些数字序列，其统计性质与我们要模拟的随机变量相似（而且这可以被检验）。比如，如果我们需要模拟一个概率分布为 D 的随机变量 X，那就需要检验我们的 PRNG 产生的数字序列是否具有相同的分布。

在变得太抽象之前，我们给一个这种生成器的实际例子。最早的 PRNG 算法之一就是 John von Neumann 本人提出的。它叫作平方取中法。这个方法只是个示例；别在生产里用它。想法很基本。我们从一个四位数开始，比如 \(n_0 = 0.4872\)。把这个数平方，得到八位数 0.69799713。现在取出这个数中间的四位，我们得到 \(n_1 = 0.7997\)。把这个数平方，得到 0.89425947。再一次取出中间四位，得到序列中的下一个数：\(n_2 = 0.4259\)。如果一遍又一遍地重复这个过程，我们得到下面这列数：\(n_0\) = 0.4872，\(n_1\) = 0.7997，\(n_2\) = 0.4259，\(n_3\) = 0.2610，\(n_4\) = 0.0881，\(n_5\) = 0.6816，等等。下面这个小程序是这个算法的快速实现（它只计算序列的前 10 个「随机数」）。


int main(int argc, char **argv)
{
    float seed = 0.4872, rand = seed;
    int seqlength = 10;
    while (seqlength--) {
        printf("%0.4f\n", rand);
        rand = sqrtf(rand);
        rand = ((int)((rand * 100 - (int)(rand * 100)) * 10000)) / 10000.f;
    }
    return 0;
}

再说一次，这个算法太受限，没什么用处。例如，种子为 0 时程序就不工作了。存在更好的算法，我们稍后会简要谈到。不过现在，先讨论一下 PRNG 的优缺点。在计算领域，写蒙特卡罗程序的开发者一般更青睐伪随机生成器。首先，软件方案通常比硬件方案更好，因为它更可靠，也更容易集成到其他程序里。因为可以编程，它们能以可预测的方式生成随机数序列（这些伪随机数的统计性质也是可预测的。只需要检验一次，而噪声发生器产生的数就不是这样）。换句话说，它们是确定性的，而如前所述，这在「锁定」基于随机数生成器的过程的输出时很有帮助（蒙特卡罗光线追踪就是这种情况）。PRNG 算法很快，几行代码就能写下。注意，所有这些算法都可以设种子。换句话说，你可以用一个数初始化它们，而得到的数字序列取决于这个种子。

主要的缺点是这类算法产生的序列是周期的。为什么？因为每个数都依赖于序列中前一个数。我们可以写成：

$$x_n = F(x_{n - 1}).$$

计算机内存中任何数的精度，都受存储这个数所用字节数的限制。如果字节数固定，能生成的「数」就只有有限个。因此可以预期，迟早会有一个生成的数（我们把它叫作 \(x_L\)）与序列中已经生成过的某个数（我们把它叫作 \(x_N\)）重合。于是序列的周期就是 L - N（周期是指序列自我重复之前有多少个值）。我们要在意这个吗？比如 C 库函数 drand48() 的周期是 \(2^{48}\ = 281474976710656\)。这是个非常大的数，而且一些更新的生成器周期更长，所以除非你的程序产生的随机数个数超过这个周期（这不太可能发生），你就不必在意。

最流行的两种 PRNG 算法是线性同余生成器（C 库函数 drand48 就基于它）和 Mersenne Twister 算法（在 C++11 的「random」库中实现——见下文）。这些算法怎么工作，我们会在本课未来的一个修订版里解释（等基础部分的所有课程都完成之后）。

C++11 随机库

知道自己可以用 C/C++ 库里的哪个函数来生成伪随机数，相当有用也很重要。你本可以用 drand48() 这类函数。它在 [0,1] 区间内产生（几乎）均匀分布的随机数。如果你想生成其他任何分布的随机数，就得自己写！

幸运的是，最新的 C++ 标准（C++11）现在带了一个 random 库。它提供的伪随机生成器由两部分组成。第一部分叫作生成器引擎。它生成数字（生成这些数字可以在三种不同的算法中选择），第二部分控制结果的分布（均匀、泊松、正态等等）。


#include &ltrandom> 
#include &ltfunctional> 
 
std::uniform_int_distribution&ltint> distribution(0, 99); 
std::mt19937 engine;  //Mersenne twister MT19937
auto generator = std::bind(distribution, engine); 
int random = generator();  //产生 0 到 99 之间均匀分布的整数变量
int random2 = distribution(engine);  //直接用分布对象与引擎对象再产生一个样本。
