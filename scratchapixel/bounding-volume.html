包围体

阅读时间：8 分钟。

包围盒

最简单的加速光线追踪的方法未必能算作一种加速结构，但这无疑是缩短渲染时间最简单的办法。茶壶的每个网格都可能有一百多个三角形：分成 8 份时，一个网格含 128 个三角形，于是投射到场景中的每条光线都要做差不多这么多次求交测试。我们换一种做法：对一个包住该网格所有顶点的盒子做光线追踪。这样的盒子叫作包围体：它是能包住该网格的最紧的体（这里是盒子，但也可以是球体）。图 1 展示了构成本模型茶壶的 32 块 Bézier 曲面片各自的包围盒。

我们可以先测试光线是否与这个盒子相交，如果不相交，我们就确定它不可能与这个包围体所包的几何体相交（图 2）。如果这个包围盒里的三角形可以跳过，我们就省下了 128 次光线与三角形求交测试。考虑到场景里许多包围盒很可能都通不过这个测试，总体算下来能省下大量对光线与三角形求交例程的调用。但如果光线与包围盒相交，盒内的所有三角形就都得与这条光线做求交测试。图 2 中可以看到一条光线与构成茶壶模型的各块 Bézier 曲面片的包围盒相交。只有带颜色的盒子被光线击中，也只有这些盒子里装的网格才会与光线做求交测试。未被击中的盒子所装的曲面片可以安全剔除。

为一个物体计算包围盒非常简单。我们可以遍历构成网格的所有顶点，找出点各坐标（xyz 位置）的最小值和最大值。这些值构成我们所说的物体最小与最大范围，定义出包围盒的两个角（见图 3）。物体的包围盒通常在物体构建时算好（比如在多边形网格类的构造函数里），并存在物体类的成员变量中（每种图元类型可能需要不同的方法来计算这个包围盒，比如二次球体的包围体可以由它的半径算出）。下面这段光线追踪器的代码展示了我们如何计算一个多边形物体的包围盒（第 13 行）。bbox 变量是基类 Object 的成员变量（代码在本课程最后一章）。

和光线与三角形求交方法一样，我们统计光线与盒子求交方法被调用的次数。box.cpp 文件里声明了一个全局变量 numRayBoxTests，每次调用盒子求交方法就用原子加法把它加一。最终值在渲染结束时随其他统计信息一起打印。

我们还建了一个 AccelerationStructure 基类，行为与物体非常相似。它有一个 intersect 方法，遍历场景中所有物体（第 5 行）。我们先测试光线与当前物体包围盒的交（第 7 行）。若测试成功，再让光线与盒内所装的物体求交（第 9 行）。其余代码与第 11 课里 trace 函数的实现非常相似。每命中一个三角形，我们都要更新到交点的最近距离（第 10–11 行），并保存被击中物体的指针（第 12 行）：


const Object* AccelerationStructure::intersect(const Ray&ltfloat>& ray, IsectData& isectData) const 
{
    float tClosest = ray.tmax;
    Object *hitObject = NULL;
    for (size_t i = 0; i < rc-&gtobjects.size(); ++i) {
        Ray&ltfloat> r(ray);
        if (rc-&gtobjects[i]-&gtbbox.intersect(r)) {
            IsectData isectDataCurrent;
            if (rc-&gtobjects[i]-&gtintersect(ray, isectDataCurrent)) {
                if (isectDataCurrent.t < tClosest && isectDataCurrent.t > ray.tmin) { 
                    isectData = isectDataCurrent; 
                    hitObject = rc-&gtobjects[i];
                    tClosest = isectDataCurrent.t;
                }
            }
        }
    }
 
    return (tClosest < ray.tmax) ? hitObject : NULL;
}

最后要更新 trace 函数。不再遍历场景中所有物体，我们只需调用 AccelerationStructure 类的 intersect 方法。如果该方法返回一个指向场景中某物体的有效指针，说明发生了相交，我们就可以用被击中物体的颜色设置该像素的颜色：


template&lttypename T>
void trace(const Ray&ltT> ray, const RenderContext *rc, Spectrum &s)
{
    IsectData isectData;
    const Object *hitObject = NULL;
    if ((hitObject = rc-&gtaccelStruct-&gtintersect(ray, isectData)) != NULL)
        s.xyz = hitObject-&gtcolor
    else
        s.xyz = rc-&gtbackgroundColor
}

本章介绍的技术在茶壶这个例子上效果很好，因为模型包含许多分辨率（按多边形数量算）相当低的网格。而 Ape 模型非常复杂，由单独一整块构成。如果渲染这个物体，我们只有在主光线没击中它的包围盒时才能省时间（典型一帧中，这类像素大概不到总像素数的三分之一）。对剩下的光线，我们仍然要对构成模型的那十万个三角形做求交测试。在那个特定例子里，包围盒方法相比暴力做法只能带来很小的收益。它实现简单又快，但显然并不适用于所有情况，因此算不上一种很好的加速方法。

用包围体加速光线追踪的想法相当古老。要确切找出是谁、在何时提出这个想法很难。1980 年一篇题为《A 3-Dimensional Representation for Fast Rendering of Complex Scenes》的论文中，作者 Ruben 和 Whitted 已经谈到可以用这类包围体的层次结构来做「快速」渲染（见本课程末尾的参考文献小节）。
