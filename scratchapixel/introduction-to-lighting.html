前言

欢迎来到《光照简介》这门课。作为一个一直对电影制作怀有感情的人，计算机图形学里的光照这个话题对我格外亲近。与我在其他课程里的做法不同，本课程除了严格意义上的编码与数学，还加入了与影片用光相关的视频和作品的参考。我强烈建议读者去看看摄影指导 Roger Deakins 这类人的作品，从中寻找更多灵感（如果你有其他好的参考资料想分享，请通过 Discord 发给我）。

在《着色简介》那门课里，我们简要讨论过光源，以及如何在渲染程序中实现它们。不过这些内容嵌在更宽泛的着色主题里，读者可能不容易找到。为了让有兴趣的读者能找到一门专门讲渲染中光照实现的课程，我们写了这一门。

你将在这里看到什么？我们为 CGI 编程新手准备的这个部分已接近尾声，本课程延续前几门课的精神。我们会给出一个程序，演示如何实现不同类型的（基础的、以及不那么基础的）光源类型，但产出的图像仍然相当简单，远不如那些为炫技而精心制作的 demo。不过，随着你继续往前走，你会发现下一个部分会深入光照更细节的层面。我们将在那里继续研究，最终做出可与顶级视效与动画公司作品比肩的图像。

在那之前，如果你已经消化了本课程提供的知识，那你离掌握它应该已经不远了。

本课程我们将学到什么？

本课程中，我们会介绍三维渲染里常见的各种基础光源类型，主要是：

  • 平行光

  • 点光源与聚光灯

  • 三角形、四边形、圆盘与球形面光源

我们要学习如何实现并模拟这每一种光源类型，并弄清什么时候该用它们。换句话说，我们会探讨每种光源类型有什么用处、能模拟出什么样的光照效果。在这个过程中，我们会了解这些光源所具备的属性，既从工程／物理的角度，也从审美的角度。内容虽有技术性，但对 CG 美术师可能相当有用——他们日常工作中用到的某些光源为什么会有那样的属性和控制参数，这里能给出答案。

尽管我们会在光线追踪的渲染框架里探讨并实现这些光源类型，但要注意：不以光线追踪为基础的渲染框架——它们在电子游戏图形中占主导（用的是光栅化算法）——用的是同样的光源类型。本课程会讲如何为这些不同的光源类型模拟阴影：从场景中的点向光源投射阴影光线。相比之下，基于光栅化的渲染引擎用的是阴影贴图，那自有一套难题，包括 bias 之类的问题，以及因阴影贴图受固定分辨率限制而从根本上缺少分辨率。此外，用阴影贴图准确模拟软阴影——比如面光源投下的那种——也相当困难。

尤其是通过学习和实现面光源，我们会接触到渲染方程，以及在渲染中最常用来模拟面光源的一项特定技术：蒙特卡洛方法。本课程并非专门讲这两个主题（它们本身就需要很长、很细致的解释），但你仍会在这里学到它们，因为实现这类光源需要用到。我们尽力以最简洁、最直观的方式来介绍，让你既不会被技术细节淹没，又能对它们有足够的理解，使它们在我们将用来实现这些光源的光线追踪框架里讲得通。我们强烈建议你参考专门讲本课程提到的各个主题的课程，继续深化这些内容，把涉及的全部技术及其相互依赖关系拼成一幅完整的图景。具体来说，是这几门：

  • 蒙特卡洛方法

  • 采样策略（尚未发布）

  • 渲染方程（尚未发布）

  • 路径追踪（尚未发布）

  • BRDF（尚未发布）

最后，我们会了解光照循环，也就是我们如何在场景中存在多个光源时把它们都算进来。

本课程不会讲的是用环境贴图照亮场景的技术（远场光照）。这个方法有专门的课程：基于图像的光照与高动态范围图像简介（尚未发布）。

术语

本课程提到的许多技术首次发表于 90 年代。此后，技术论文里对各种概念命名的术语发生了变化。比如在 90 年代，人们常把光源不叫 light，而叫 luminaire，这个说法如今不那么常见了。随着课程推进，我们会尽力把这类情况标出来，并定期更新这一节，把需要特别解释、或因少见、或因属历史用法而值得一说的名称收进来，帮你过渡到已经演变了的术语体系。

引言

在深入每种光源类型的具体实现之前，我们先回顾一下光在生成三维场景图像中所扮演的根本角色。正如我们在本部分的许多课程里提到的，「没有任何光，你就什么也看不见。」光是我们感知世界的基础。这一点确认之后，我们来看看在计算机模拟中光大致是如何工作的。

要用计算机模拟光与物质的相互作用，需要考虑三点：

  • 我们想知道其亮度的那个点，是否处于阴影中？也就是说，从光源的位置看，这个点可见吗？是或否？

  • 如果这个点不在阴影中，那么该光源对这个点照明的贡献是多少？这取决于光源类型本身，以及所关注点处表面的属性，尤其是它的朝向。

我们逐点来看：

判断该点是否处于阴影中

在自然界中，光从光源出发，经物体表面反弹，其中一部分反射光最终行进到我们的眼睛，打在眼球后部对光敏感的区域上。因为我们沿着光的自然路径追踪，所以称之为正向追踪。不过，在光传播的途中，光源发出的某些光子可能被沿途的物体挡住。这些被挡住的光子轨迹正后方的物体收不到任何光，因而看起来处于阴影中。

在计算机图形学中，我们倾向于反向追踪光子的路径，从眼睛追到光源，原因在本部分最初的几门课里已经讲过。所以，一旦一条相机光线打到三维场景中某个物体的表面，我们就想知道这个点接收到了多少光。为此（暂时假定光源很简单），我们从该点再投射一条光线到光源，这条光线叫作阴影光线。如果这条光线在到达光源的途中与某些几何体相交，那么这个点就处于阴影中；如果没有，它就受到该光源的照明。

在光线追踪中，这类光线被称为二次光线。从编码角度看，它们比相机光线简单，因为相机光线需要收集交点处的表面信息（比如法线），还要找出离相机最近的交点，而阴影光线不需要。只要一次相交测试返回真，我们就可以返回，因为我们知道（而且只关心这一点）这个点处于阴影中。这个交点是不是从被着色点看去最近的物体，无关紧要，因为我们关心的只是光是否被挡住。所以从根本上说，这类光线投射起来通常更便宜，不需要像主光线那样做那么多优化、处理那么多边界情况。

总结一下：

  • 我们从相机投射一条主光线。

  • 如果这条相机光线打到场景中某个三维物体的表面，我们就从 \(P\) 向光源位置（暂时是这样）投射一条二次光线，也就是阴影光线。

  • 如果这条阴影光线被某些几何体挡住，\(P\) 就处于阴影中。

  • 如果这条阴影光线没有被挡住，我们就进入第 2 步：计算该光源对我们这个点的贡献。

上图说明了这个原理。我们从相机（眼睛）位置向场景中投射两条主光线（白色）。它们分别与场景中的平面相交于 P1 和 P2。从 P1 向光源投射阴影光线时，我们看到这个点被光源照到了。而对 P2，阴影光线与茶壶在两处相交。阴影光线与几何体相交多少次并不重要；我们首要关心的是它到底有没有与任何几何体相交。一旦发现相交（假定物体不透明——见下文），我们就返回。因此 P2 处于阴影中，这在最终渲染里清晰可见。

如果挡住光的物体是部分透明的呢？那总该有些光能穿过去吧？是的，确实就是这样。当阴影光线与一个被判定为不完全不透明的物体相交时，我们必须求出该物体的不透明度（通常通过运行该物体的表面着色器）。这时，这条光线要返回的不再是 0（在阴影中）或 1（不在阴影中），而是 1 乘以（1 减去该物体的不透明度）。在这种情形下，我们还需要继续测试场景中剩下所有物体，直到抵达光源。如果沿途又发现不完全不透明的物体，就重复这个过程。如果遇到一个完全不透明的物体，我们就把这条光线的不透明度设为 0 并返回。透明阴影就是这样模拟出来的。

原理相当简单，可以写成如下伪代码：


for (each pixel in the image) {
    Hit hit;
    Ray ray{orig, dir};
    // 向场景中投射一条主光线
    Intersect(ray, hit, prims);
    // 如果光线与物体相交，计算该物体在
	// 此点（交点）处的亮度／颜色。
    pixel_color = 0;
    if (hit) {
        for (each light in the scene) {
            Ray light_ray(hit_point, p_to_light_pos_norm);
            bool in_shadow = Occluded(light_ray, prims);
            if (in_shadow)
                continue;
            pixel_color += light_color * light_ray.dir.Dot(hit_normal);
        }
    }
}

这确实是一段很粗略的伪代码，其中涉及的某些细节稍后会解释。不过现在要注意的是，正如光线追踪的典型做法，我们先遍历图像中的每个像素并为它构造一条主光线。这个流程我们已经讲过很多次（例如见《用光线追踪生成相机光线》）。接着，我们检查这条光线是否与场景中任何几何体相交。如果相交，就继续遍历场景中的每个光源，向当前光源投射一条阴影光线。如果交点处于该光源的阴影中，这个光源就不为点的颜色做贡献；反之，如果该点能看到这个光源，就加上它的贡献。不必太在意计算光源贡献所用的数学，那部分接下来会讲。在下一章处理点光源的情形时，我们会给出实际的代码。

这段代码值得注意的一点是，我们用了两个不同的函数来计算光线与几何体的相交：一个用于主光线（Intersect），一个用于阴影光线（Occluded）。这种做法在大多数渲染器里极为常见，原因正如上面所提示的：对阴影光线来说，我们不需要找离光线原点最近的交点，只需要知道光线有没有与任何（不透明的）几何体相交。这一步对阴影光线的工作量比主光线小。因此，如果两者用同一段代码（完全可行），我们很可能就错过了优化程序的机会。为处理这一点，我们为阴影光线写一个针对阴影情形优化的专用函数：

  • 我们省略交点处任何与几何体相关的计算。

  • 一旦找到命中，就可以从函数返回 true，同时结束对场景中所有物体以及构成每个物体的所有三角形的遍历。

如果这个原理还不够清楚，我们用下面这张图来说明。当一条阴影光线与场景中的四个三角形逐一测试时，由于场景的构造方式，我们事先并不知道三角形的测试顺序。在这个例子里，我们先测三角形 1，没有相交。接着测三角形 2，检测到相交。尽管三角形 3 比三角形 2 的交点离光线原点更近，我们仍可以立刻以 true 返回并忽略之后的所有三角形。在这个语境下，我们首要关心的是阴影光线是否被某块几何体挡住，而不是找出是哪块几何体挡住的。存在遮挡这一事实本身就足够了。

计算光源对点 P 的贡献

回到光的话题。如果这个点不在光源的阴影中，我们就需要计算该光源对交点颜色的贡献。这里用「颜色」这个词并不理想，但请记住，在真实世界里我们处理的是能量。光由光子构成。光源的颜色取决于光子的波长，光子越多，能量越大。这些后面再细说。就本课程而言，我们只考虑纯漫反射的表面，换句话说，哑光表面。更进阶的着色模型见第 2 部分的系列课程。漫反射表面有一个很好的性质：表面反射的光量，正比于照明点处表面法线与光线方向夹角的余弦。这一点我们已经提过多次，尤其是在《着色简介》那门课里。这就是所谓的朗伯余弦定律。

这条定律可以写成如下公式：

$$I = I_0 \cos(\theta)$$

其中 \(\theta\) 就是 \(N \cdot L\)，\(N\) 是表面法线，\(L\) 是从点 \(P\) 指向光源的方向（见图 2）。

这套记号可能有点让人迷惑，因为 \(L\) 也用来表示辐射亮度，这个概念我们在讲着色的课程里见过。辐射亮度指的是穿过某个区域、或由该区域发出，并落在指定方向给定立体角内的光量。如果这些术语（立体角、辐射亮度等）你是第一次遇到，不必太在意。本课程后面我们会回过头来讲它们。所以，我们用字母 \(L\) 来表示表面上的点反射向眼睛的光量，并用 \(wo\) 和 \(wi\) 分别表示出射光方向与入射光方向。出射光就是从该点传向眼睛的光，入射光则是从光源打到我们这个点上的光，如图 2 所示。

$$L_o(\mathbf{w}_o) = L_e(\mathbf{w}_i) \cdot (\mathbf{n} \cdot \mathbf{w}_i) \cdot \text{V} \cdot \text{R}$$

其中每一项的含义如下：

  • \(L_o(\mathbf{w}_o)\)：沿出射方向 \(\mathbf{w}_o\)（朝向观察者或相机）观察到的辐射亮度。

  • \(L_e(\mathbf{w}_i)\)：光源沿入射方向 \(\mathbf{w}_i\)（从表面上的点指向光源）发出的辐射亮度。

  • \(\mathbf{n} \cdot \mathbf{w}_i\)：表面法线 \(\mathbf{n}\) 与入射光方向 \(\mathbf{w}_i\) 的点积，体现入射角的影响。

  • \(\text{V}\)：一个考虑阴影的因子（此处 \(V\) 表示可见性）。

  • \(\text{R}\)：材质的反射属性，决定入射光中有多少被反射到出射方向上。对完美漫反射表面，它是常数。后面再细说。

这个公式之所以重要，是因为它体现出对点 P 处接收或反射的能量、以及入射或出射方向的依赖。有意思的是，完美漫反射表面反射的光量并不依赖于观察方向 \(\mathbf{w}_o\)。它是常数，这也是我们为了方便从漫反射表面入手的原因。这个常数是 \(1/\pi\)。如果你好奇其中的原因，欢迎阅读《BRDF、线性与曝光的一次创意探索》那门课。这个公式如果显得抽象，不必担心；下一章我们会深入一个具体的实现。

注意我们在公式里加入了一项 \(\text{V}\)，用来表示前面讨论过的阴影或遮挡。在本课程中，它只会取 0 或 1，表示一个点处于阴影中还是阴影外（对光源可见或不可见）。

还要注意图 2 中的箭头可能有点误导。光由光源发出，其中一部分会照到点 \(P\) 处的表面上。所以黄色箭头从 \(P\) 指向光源，只是为了在图中的情形下表示未归一化的 \(\omega_i\) 向量的方向。向量 \(\omega_o\) 和 \(\omega_i\) 通常都确实是背离 \(P\) 指向的。

有了这些信息，我们要做的就是在代码里应用这个公式，模拟光源对交点 \(P\) 的贡献。如果从点 \(P\) 能看到该光源——我们在第 1 步检查过——就计算表面法线与光线方向 \(\omega_i\) 夹角的余弦，乘以光强（如果你愿意，它就是颜色，一个 Vec3），再把整体乘以材质反射率；如前所述，对漫反射表面它是 \(1/\pi\)。真的很简单。

注意场景中可能有不止一个光源。本课程最后一章会更详细地讨论这一点，但光源对 \(P\) 处照明的贡献是线性的。所以你只需要遍历场景中的所有光源，用我们上面刚介绍的同一套逻辑累加它们的贡献（计算夹角余弦、乘以光源颜色，等等）。

可以想见，光源有不同的类型，各自都有其特点。下面我们先简要介绍它们，再看如何逐一实现——那将是随后几章的主题。

光源类型：delta 光源与面光源

光源可以分成两大类：delta 光源与面光源。在真实世界里，所有光源都是有质量、大小和形状的实体。不过，等我们讲到面光源类型时就会看到，在计算机图形学中模拟具有物理大小和形状的光源并不是一个简单直接的问题。在 CG 发展的早期，尤其是计算机只有几十兆内存、CPU 算力有限的年代，研究者更愿意用物理光源的「理想」表示。他们想模拟自然界最常见的几种光源：球形灯、投影灯和太阳。结果他们为这些光源建立的模型，把它们表示成理想光源——奇特的是，这些理想光源根本没有大小。点光源不过是空间中的一个点，假定它向所有方向发光。而由于点在物理世界里没有对应物、纯粹是数学构造，我们就用 delta 光源这个名字来称呼它们。这是因为数学中的 delta 函数被数学家用来定义一个在物理世界中并不存在的形状。delta 函数除了在零点之外处处为 0，而它的积分等于 1。我们的光源也是如此，所以它们被称为 delta 光源。

在一些教材里，你可能会看到这类光源被用数学方式定义成：

$$Li(\omega) = L\delta(\omega - \omega_{\text{light}})$$

其中 \(\omega\) 表示以被着色点为中心的半球上方的任意方向，\(\omega_{\text{light}}\) 实际上就是光线方向。这里的 \(\delta\) 是希腊字母 delta，用来表示 delta 函数。这个定义说明，该函数只在 \(\omega\) 与 \(\omega_{\text{light}}\) 相同时才返回 1，其他所有情况下都返回 0。

你需要记住的是：这些光源之所以叫 delta 光源，是因为它们与 delta 函数一样，在渲染计算中被视为点状、或没有可辨别的大小。做这种简化是为了更高效地处理渲染中某些计算层面的问题，特别是阴影和反射的计算，这些我们会在随后几章探讨。

delta 光源虽然带点历史色彩，但在今天的制作中仍被大量使用，尽管只要可能，大家更愿意用面光源。不过，出于本简介范围之外的原因，它们给 CG 美术师带来了不少头疼的问题。delta 光源的问题在于它们没有大小。确切地说，这意味着我们没法让这些光源像真实光源那样投出阴影、或在物体上形成反射。想一想：如果光只是空间中的一个点，你怎么表示它的反射？连达·芬奇都想不出这个问题。所以是的，它们比什么都没有强，几十年来在让我们做出能唬住观众的 CGI 这件事上起了关键作用，但代价是牺牲了物理正确性。

面光源，顾名思义，有物理大小，因此不受这个问题困扰。不过它们最初普及得很慢，因为模拟它们需要多得多的算力。而如今，多亏了 GPU 和 CPU 里的数十亿个晶体管，使用面光源不再意味着面对卡死的电脑。这也意味着我们可以得到准确的阴影和反射，做出所谓物理正确的图像。

delta 光源与面光源的区分确立之后，我们就可以接着研究每种光源类型的具体特点，探讨如何实现它们。本课程中，我们将研究以下四种不同的光源类型：

  • 点光源：模仿完美球形光源的行为。

  • 平行光（也叫方向光）：模仿太阳的行为。

  • 聚光灯：像投影灯一样工作，带有锥角和衰减。

  • 面光源（四边形与球形）：通常是矩形或球形。

前三种光源属于 delta 光源这一类，而面光源自然归入面光源这一类。下图展示了每种光源类型渲染出的场景。

为完整起见，再提三种本课程不会研究的光源类型：

  • 环境光源（含天空穹顶光源）：这类特殊光源模拟天空或我们周围的环境。如果你听说过用 HDRI 贴图来做照明，那些图像就是派这个用场的。它是环境对场景照明的贡献。专门讲环境光源实现的课程在第 2 部分（HDRI 图像由 Hdri-Haven 提供）。

  • 几何光源：CG 里常用的面光源具有矩形、管状、球形这类「简单」形状。这很方便，因为这些形状可以用数学表示，从而简化阴影和反射的计算。几何光源是会发光的（多数情况下是多边形）网格。因为它们可以有任意形状和拓扑，处理起来比四边形光源或球形光源难得多。

  • 体积：体积同样可以发光，比如烛焰或爆炸。

在继续之前，还想介绍两个术语，因为你可能会在各种工具和 API 文档里遇到它们。

  • 点状光源：这个词用来把聚光灯和点光源与平行光区分开。区别在于——等我们逐一实现时会看到——点光源和聚光灯在空间中有位置，而模仿太阳行为的平行光没有（我们只考虑光线方向）。

  • 光度学光源：这类光源一般是点状光源（点光源或聚光灯），使用我们所说的 IES 或 EULUMDAT 光照剖面。这些剖面是从真实光源测量得来的，按方向给出光源发出的能量。这项技术——本课程后面还会简要提到——非常适合给点光源和聚光灯增加复杂度，因为这两类光源的外观本质上非常简单，无法模拟真实光源的样子，也无法模拟它们对照亮周围场景所产生的效果。

光的线性

仔细读这一节。

光有一个很重要的性质，正如着色简介中所讨论的：每个光源对场景的贡献是线性的。意思是，如果场景里有两个光源，你先用它们分别照亮同一场景渲染出两张图像，再把两张图像相加，结果与同时打开两个光源渲染该场景完全相同。每个光源的贡献直接在循环里累加即可。因此，只要你知道如何计算单个光源的贡献——这个概念我们会在随后几章展开——渲染含多个光源的场景就只是遍历每个光源、对每一个套用同样的逻辑，把它们的贡献加到被着色的点上。


std::vector&ltLight> lights;
Vec3&ltfloat> L = 0;
for (const auto& light : lights) { // 把 'light' 改正为 'lights'
    L += light_dir.Dot(hit_normal) * Vis(hit_point, light_pos) * material_reflectance;
}
// 把该点的「颜色」保存进图像
buff[(y * image_width + x)] = L;

辐射亮度与辐照度

现在我们已经引入了观察辐射亮度 \(L_o\) 这个概念（其中 \(o\) 也可以表示出射）。你虽然已经接触过辐射亮度这个概念，但可能还会遇到辐照度这个词。记住，辐射亮度（见《着色简介》与《着色的数学》两门课）是一个辐射度量学量，衡量的是单位面积、单位立体角上的辐射通量（功率）密度。辐照度只衡量单位面积上的辐射通量密度。总结一下：

  • 辐照度：衡量从各个方向入射到某一点的光量。

  • 辐射亮度：衡量从单一方向入射到某一点的光量。

首先，表面上某一点的辐照度是单位面积上的辐射通量（功率）密度，而表面上某一点在某个特定方向上的辐射亮度，是单位面积且单位立体角上的辐射通量密度。简单说，辐照度是（可能来自所有方向）到达某一点的光量，而辐射亮度是从单一方向到达某一点的光量。

现在，通过方向 \(\omega_i\) 周围一个很小的锥体 \(d\omega_i\)（立体角大小记为 \(d\sigma(\omega_i)\)）入射到点 \(x\) 的光量，称为辐射亮度 \(L_i(\omega_i)\)。这束细小的入射光在 \(x\) 处的表面上产生了一定的辐照度。也就是说，表面以入射到其上的光为交换，现在能够向外发光（光被反射回它所处的环境）。这个「部分」辐照度记为 \(dE(\omega_i)\)。我们用「部分」是想说明：这里只是辐照度（表面向各个方向反射的光）中、作为对来自某个又小又窄的光方向的入射光的贡献而被反射出去的那一份。入射光一部分被吸收，一部分向各个方向散射（反射）。\(L_i(\omega_i)\)、\(dE(\omega_i)\) 中朝方向 \(\omega_o\) 出射的辐射亮度的外散射贡献，记为 \(dL_o(\omega_o)\)。通过实验可以验证，出射辐射亮度 \(dL_o(\omega_o)\) 的量与入射辐照度 \(dE(\omega_i)\) 成线性正比，而 BRDF（双向反射分布函数）刻画的正是这个比值：

\[f_r(\omega_i \rightarrow \omega_o) = \frac{dL_o(\omega_o)}{dE(\omega_i)}\]

其中 \(f_r\) 是渲染方程里表示我们所说的 BRDF（双向反射分布函数）的常见写法。注意 \(f_r\) 本质上就是我们前面提到的材质反射率。（BRDF 的快速介绍可见《BRDF、线性与曝光的一次创意探索》那门课）。

这个关系是渲染中的核心概念之一，与渲染方程本身并列；渲染方程会在进阶部分的一门专门课程里探讨。

光强、光色与动态范围图像

区分光强与光色很重要。在大多数三维软件里，这两个属性作为独立参数呈现给用户，但这主要是为了便利或艺术控制。实际上它们是交织在一起的。光本身是以不同波长振动的光子的混合。每个光子所贡献的波长混合决定了光的颜色。正如本部分上一门课提到的，光可以描述为连续的波长光谱，而相似的谱在振幅上可以不同，取决于一束光里包含多少光粒子。光子越多，能量越大。

如你所知，在计算机图形学中我们倾向于用三种主要颜色来表示颜色：红、绿、蓝。我们不用光谱，原因有三：1）计算代价高得多（想象一下要处理 16 个采样而不是 3 个）；2）对大量常见材质，我们往往并没有现成的光谱数据；3）靠调光谱来调整颜色，比在色轮上移动一个点（在加色系统里，色轮由三种原色组合而成）难得多。考虑到光的强度可能远大于用来表示颜色的范围（多数消费级屏幕每通道限于 256 个值），我们倾向于把颜色与光强分开（在大多数三维应用里标为 intensity，一般就是一个 float）。

总结一下：

  • 光的颜色一般定义为一组三个值，可以是 float（在 0–1 范围内），也可以是单个字节（可表示 256 个值）。

  • 光强用一个 float 表示。

要计算最终的光照贡献，我们把光色乘以光强。在真实世界里，这个组合会内含在光谱中：构成光的波长分布决定它的颜色，光谱的振幅代表它的能量。

记住，除非我们使用高动态范围图像格式（HDR、EXR、TIFF 等）或高动态范围屏幕（不过屏幕能显示的范围要有限得多，因为人眼视觉系统本身能适应的光范围也有限——而图像没有这个限制，它可以存储任意大范围内的值），否则我们都得把构成图像的最终像素值存进每通道单字节的范围（RGB）。所以即使我们用 float 表示颜色，在渲染流程末尾、把值写入文件之前（这里同样假定用的是 PNG、JPG、PPM 这类低动态范围格式），也需要把基于 float 的颜色转换成无符号字节。

另外，澄清一个可能让人困惑的地方：并不是说我们初始的光色乘以光强远超 1，表面反射的光量就必然大于 1——虽然那也完全可能。原因我们会在下一章解释：光强随光源与被照点之间距离的平方而衰减。因此，即使发射处的光量很高，等它到达表面时可能已经衰减了不少。还要记住，我们需要把这个数乘以表面法线与光线方向夹角的余弦，再乘以材质反射率，而这两个值都小于 1。所以总的来说，即使最初到达表面的光可能大于 1，表面反射出去的光仍可以小于 1（这里假定用的是浮点值）。

光色温

在真实世界里，光由被加热的物体发出。比如白炽灯，是电流通过细灯丝，灯丝被加热到很高温度而发光。荧光灯的原理类似，只不过这里是靠电流电离灯泡内的气体，从而使气体发光。如你所知，太阳表面非常热。有意思的是，物体被加热的温度与它发出光的「颜色」之间存在关系。温度较低时，光偏橙色调。温度升高，光变得「更冷」，向蓝色调移动。这个效应以及如何按物体温度计算颜色，已在《黑体辐射》那门课里详细解释过，你可以在那里找到关于这个现象是什么、以及如何根据物体温度计算颜色的深入说明。

这就是所谓的光色温。摄影指导对它有充分认识，必须非常仔细地考虑光的这个属性，因为它对图像整体的色调影响很大（如图 4。来源：LensProToGo）。确实，被加热到低温的人造光源发出橙色调的光，会给图像带来整体的橙色，我们把它与更温暖、更舒适的情绪联系在一起。处于高得多的温度下的光源则发出蓝光，从创作角度看会被感受为营造冷色调的情绪。所以在用于建筑模拟或在影片中营造特定情绪时，必须了解并考虑光的这个属性。

在实际操作中，CG 美术师很少用色温参数来指定光的颜色。大多数先进的渲染软件，比如今天三维动画工具和游戏引擎里的那些（Arnold、Pixar 的 PRMan、Unreal Engine 等），允许你指定色温而不必指定 RGB 颜色。软件内部会根据给定的色温算出对应的 RGB 颜色。实践中，至少在我们的制作经验里，CG 美术师一般更愿意用标准 RGB 颜色面板来指定光的颜色。

由此可以推出：除了物理光源能发出的那一段色温范围之外，影片里的其他光色一般（至少）是靠给光源加上某种彩色涂层做出来的。这种效果你通过调整 RGB 颜色设置更容易复现。

我们的 CG 光照与真实世界的物理光源是什么关系？

在我们进入下一章、探讨点光源的实现之前，你可能会想：如何用计算机图形学模拟某个特定的光源，比如你家里书桌上的那盏？换句话说，你怎样把真实世界的物理单位——功率、光温、形状——转换成一种虚拟表示，使其对这些合成对象的效果被准确模仿，从而有效地重建整个场景？

前面我们已经讲过多个要素，比如光温、表面反照率（反射光与入射光之比）、光源的物理形状，以及亮度与能量的关系。前三个因素我们已经讲透了，也理解了形状可以被完整建模，做出所谓的「几何光源」，那么现在剩下要处理的就是亮度与能量的那些微妙之处。这一方面之所以棘手，主要有两个重要原因：

  • 人眼视觉系统是非线性的，也就是说我们对亮度的感知带有主观成分。

  • 光源消耗的能量与它产生的光量并不直接相关。比如一只 LED 灯耗电可能比老式灯泡少，亮度却可以一样高。

此外，正如《BRDF、线性与曝光的一次创意探索》那门课所讨论的，渲染要在光度学与辐射度量学这两套既有区别又相互交织的模型之间周旋。辐射度量学是计算机图形学的基石，量化包括光在内的电磁辐射。相比之下，光度学专注于测量人眼感知到的光，使用坎德拉、流明、勒克斯这类在五金店灯具设备上常见的单位。难点在于，试图把这些基于感知的光度学单位换算成辐射度量学的线性可测单位——辐射亮度、辐照度、光强——时会遇到问题，因为人类对亮度的主观体验与辐射度量学客观的线性度量之间，本身就存在差距。

渲染中的这些微妙之处与摄影中的如出一辙，尤其是传感器感光度或相机曝光时间对光的影响。曝光时间越长，图像必然越亮；而镜头光圈与 ISO 设置又会进一步调节图像中物体或光源的亮度。这些因素给渲染过程增添了一层又一层复杂度，并与光度学测量和辐射度量学测量之间的根本差异交织在一起，使得在计算机生成图像中准确模拟真实世界的光照条件成为一个多层面的难题。

如你所见，要想用包装盒上提供的光度学数据，在 CG 里准确模拟一盏五金店的 LED 灯，并不简单。不过，如果我们知道场景中物体的反照率，那就只剩光行为的两个具体方面：

  • 它的亮度（它辐射出的能量大小）

  • 它发射能量的方向性。光源并不会向所有方向均匀发射能量。大多数光源都有一条独特的剖面，描述按方向发射多少能量。这些剖面称为 IES 剖面，对建筑师这类专业人士至关重要——他们要准确渲染由特定灯具照亮的建筑或街道，因为这让他们能用这些 IES/EULUMDAT 剖面来做模拟。知道物体的反照率和光源的 IES 剖面，我们就能调整光强，直到渲染结果看起来与真实观察合理相符。了解这些细节，可以确保我们即使面对光度学单位到辐射度量学单位换算的复杂性，也能准确地近似所需的能量水平调整。

这种做法并不意味着我们应该跳过把光度学测量换算成辐射度量学单位这一步。它只是承认这种换算很复杂，并把它放到一门专门课程里集中讨论。你可以在「计算机图形学珍宝」部分找到一门专门讲 IES/EULUMDAT 剖面使用的课程。

值得注意的是，在计算机图形学（CG）中，光源通常被假定向所有方向均匀发光。通用型聚光灯和点光源就是这种情况，结果得到的剖面相当平淡、不真实。不过正如前面提到的，它们的优点是容易估算。要做出与 IES 剖面所能达到的效果相同的光源完全可行，而且常被设计汽车前灯的车企采用。他们需要在建造之前预览这些设计的输出，这就要求对玻璃、反射镜以及灯具的每一个部件建模，做物理准确、考虑反射与折射的光照模拟。这类模拟单单为一盏灯就可能要跑上几小时，对制作渲染来说不现实。这就是为什么用 IES 剖面这类「技巧」可以给由简单点光源或聚光灯照亮的场景增加复杂度，同时又保留这类简化模型在快速渲染上的好处。

「CG 动画／视效里用的都是简单光源类型」这个说法已经不完全正确了。自 2010 年代以来，得益于算力的提升，如今已足以在可接受的时间内渲染带面光源的场景，面光源在生产中的使用变得相当普遍。不过，虽然面光源可能更受青睐，即使用面光源，复现复杂的光照剖面仍然很有挑战。因此，IES 剖面在这里提供了最好的办法。几乎每个渲染系统和游戏引擎（Arnold/Maya、Redshift、Unreal Engine、Godot Engine、Pixar 的 PRMan 等）都支持使用 IES/EULUMDAT 剖面的光度学光源，原因正在于此。所以如果你在用这些应用之一，那你很可能具备配置光度学光源的能力。

作为示例，旁边这张图是 Maya 中一盏 Arnold 光度学光源的截图。你可以看到用来指定希望该光源使用的 IES 剖面的参数。它还有一个选项，可以为光源使用色温（并即时计算这个值），而不必用一组 RGB 值来设置颜色。

小结

到目前为止我们学到了什么：

  • 我们了解到，把光源整合进渲染流程是一个两步的过程：

    • 遮挡：从被着色点看，该光源可见吗？

    • 照明本身：该光源对被着色点的贡献是多少？我们了解到，这取决于光线方向、光源距离（这个概念我们还没细讲）、光色、光强、表面法线以及材质反射率（更不用说前面讲过的可见性／遮挡因子）。

  • 我们了解到各光源的贡献可以线性相加。这简化了代码，只需要遍历场景中的所有光源并累加它们的贡献。

  • 我们了解了不同的光源类型以及它们所属的类别：delta 光源（聚光、点、平行）与面光源；并且我们在 delta 光源这一类里区分了点状光源（聚光、点）与平行光（太阳）。

  • 我们了解了 IES/EULUMDAT 剖面。

  • 我们还了解了光色温。虽然不常用，但有些三维软件让你可以访问它，作为用标准的一组 RGB 值设置光色的替代方案。

如果这一章只能记住一件事，那就是我们为 BRDF 给出的定义：从给定方向 \(dL(\omega_i)\) 入射到某一点 \(x\) 的光量，与因这束入射光而被表面反射出去的光（记为 \(dL(\omega_o)\)）之间存在关系，并且有一个叫 BRDF 的函数用数学方式描述两者之比。注意对漫反射表面，漫反射（哑光）表面的 BRDF 是 \(\frac{1}{\pi}\)（详见《BRDF、线性与曝光的一次创意探索》那门课）。
