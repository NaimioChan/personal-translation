模拟天空的颜色

阅读时间：42 分钟。

本章我们学习大气散射。建议先读体积渲染与次表面散射那门课程，它们与本主题共享几乎相同的概念。大气散射可以看作体积渲染的延伸。

引言

几个世纪以来，天空一直是许多艺术家着迷的主题，他们尽力精确地描绘它的颜色。19—20 世纪之前的许多代物理学家和数学家，大概也曾执迷于弄清究竟是什么让天空在日出日落时呈现橙色、在白天呈现蓝色。历史上，大气散射的发现被归功于 Rayleigh（又名 John Strutt），这位英国物理学家拿过诺贝尔奖，主要成果产生于 19 世纪后期（Rayleigh 在剑桥大学接替的是以电磁学研究闻名的 Maxwell。计算机图形学研究的很大一部分都与 Maxwell 的工作有关。Rayleigh 还曾与 Max Planck 一起研究黑体）。大气散射也会影响物体的外观。这种效应称为空气透视，最早由达·芬奇在绘画中观察、研究并再现（事实上，在达·芬奇之前的画作里就能找到这种手法）。随着物体与观察者的距离增加，物体的颜色会被大气的颜色取代（白天天空通常是蓝色，日出日落时是红橙色）。这是一条重要的视觉线索：我们人类习惯通过比较景物中各物体显得有多蓝，来估判它们之间的距离。在（数字）绘画中，空气透视能极大地帮助图像增加纵深感（大脑更容易判断出一个物体比另一个更远），如下面这幅达·芬奇画作（《岩间圣母》）的复制品所示。

在更近的历史里，也就是计算机图形学的历史中，Nishita 在 1993 年写了一篇开创性论文，题为「Display of the Earth Taking into Account Atmospheric Scattering」，其中描述了一种模拟天空颜色的算法。有趣的是，他这篇论文以及 1996 年就同一主题写的下一篇（「Display Method of the Sky Color Taking into Account Multiple Scattering」）并不完全关于大气模拟，而更多关于从外太空看到的地球的逼真渲染（包括海面、云层与大陆的渲染）。

这提醒我们，那些年里推动计算机图形技术发展的是制造业——为了准确模拟自家产品，或提供 3D 虚拟培训环境——而不是娱乐产业（电影与游戏）。Nishita 描述的天空模拟技术自他那之后就没什么大变化。这一领域的大部分研究集中在把他的算法实现在 GPU 上，而没有带来模拟质量的明显提升（重点更多在速度与实时模拟）。不过还存在另一个天空模型，由 Preetham 等在 1999 年发表于 Siggraph 的论文（「A Practical Analytic Model for Daylight」）中描述。正如标题所示，这是一个解析模型，能准确模拟天空颜色；但它比 Nishita 提出的技术限制更多（例如，该模型只适用于位于地面的观察者）。值得一提的是 Jensen 等2011 年在 Siggraph 发表的关于夜空模拟的论文（「A Physically-Based Nightsky Model」）。本章将给出 Nishita 模型的一种实现。后续各章我们研究其他算法。

下一段里，我们会描述各种现象——它们叠加起来造就了天空的颜色。然后展示 Nishita 的算法如何模拟这些现象。等模型在 C++ 程序中实现之后，我们会说明这套技术可以轻易扩展来模拟空气透视，而且通过改变模型参数，还能造出异星天空。

大气模型

大气是环绕行星的一层气体。这层大气靠行星的引力维持在原位。定义这层大气的主要是它的厚度与成分（构成它的不同元素）。地球大气的厚度约 100 km（以卡门线为界），由氧、氮、氩（Rayleigh 发现的气体）、二氧化碳与水蒸气构成。不过模拟中我们采用 60km 的厚度（我们只考虑地球大气前两层，即对流层与平流层中的散射）。如果你读过体积渲染那门课程（还没读的话，我们建议现在就先去读再来继续），你会知道光子与粒子碰撞时会被散射。当光沿特定方向穿过一个体积（大气）时，光子与粒子碰撞会偏转到其他方向。这一现象称为散射。粒子散射光的频繁程度取决于粒子的属性（主要其大小）以及它们在体积中的密度（单位体积内有多少粒子/分子）。我们现在知道地球大气由何种大小的分子构成，以及它们的浓度/密度。我们将把这些科学测量值用于大气散射模拟。环绕行星的大气还有一个关键点：这些粒子的密度随高度递减。换句话说，海平面处每单位立方米的空气中，分子数远多于海平面以上 2 km 处。这是一个重要事实，因为如前所述，散射的多少取决于分子的密度。当光在大气中从上层射向地面时，我们需要沿光线以固定间隔采样大气密度，并据这些采样位置的大气密度计算散射量（我们做一次数值积分，细节在下文详述）。多数论文（包括 Nishita 的）都假设大气密度随高度指数递减。换句话说，它可以用如下形式的简单公式来建模：

$$density(h)=density(0) e^{-\frac{h}{H}}.$$

其中 density(0) 是海平面处的空气密度，\(h\) 是当前高度（海拔），我们在此处测量大气密度。\(H\) 是大气密度若均匀时的厚度（在科学论文中，\(H\) 称为标高，与大气密度衰减为 \(e\) 分之一所对应的高度有关。\(H\) 取决于温度）。有些论文认为这个模型是很好的近似。但另一些论文认为它不正确，宁愿把天空密度建模为一组同心层，每层由其厚度与密度决定（XX please quote paper here XX）。

把天空密度建模为一组层（在 Nishita 的论文中称为球壳）在计算上也有好处。因为我们要沿光射向观察者的路径做数值积分，在大气密度高处取的样本比密度低处的样本更关键。沿光线做「等步长」积分会导致收敛很差。今天的计算机足够快，可以靠取固定步长暴力算完，但在 Nishita 的年代，优化算法是必需的。他提出一个模型，把大气表示为一组球壳，低空处间隔小、高空处间隔大。不过，论文里发表的示意图中，各层厚度其实呈很强的指数变化。这不奇怪，因为在他的模型中，每个壳的半径正是由空气分子的密度分布决定的（而他用来算这个密度的公式与我们上面写的那个非常相似）。

大气由微小的粒子（空气分子）构成，它们在低空与被称为气溶胶的较大粒子混合。这些粒子可能是风卷起的灰尘或沙粒，也可能因空气污染而存在。它们对大气外观的影响相当显著，因为它们散射光的方式与空气分子不同。空气分子对光的散射称为 Rayleigh 散射，气溶胶对光的散射称为 Mie 散射。简言之，Rayleigh 散射（空气分子对光的散射）造就了天空的蓝色（以及日出日落时的红橙色）。而 Mie 散射（气溶胶对光的散射）通常造成你在受污染城市上空常看到的那种灰白雾霾（雾霾使天空的清澈度下降，见图 2）。

模型若不提这一点就不完整：它需要用户指定行星半径与天空（半径）。这些数字用来计算沿视线光线与光照光线所取采样位置的高度。对地球，我们用 Re = 6360 km（e 代表 Earth）与 Ra = 6420 km（a 代表 atmosphere）。我们模型中所有与距离有关的距离和参数，都应使用同一单位制表达（km、m 等任选其一）。

对大气模型来说这有些棘手，因为行星的尺度可能很大。这种尺度下，公里通常是更合适的选择。然而散射系数非常小，更容易用米或毫米表达（光波长甚至用纳米）。选择好的单位也受浮点精度限制的驱动（也就是说，数字太大或太小，计算机对这些数字的浮点表示可能变得不精确，从而导致计算错误）。模型的输入参数可以用不同单位表达，由程序内部换算。

最后，我们以这一点结束模型的描述：太阳是我们天空的主要照明光源。太阳离地球如此之远，我们可以假定到达大气的所有光线都平行。后面我们还会说明这一观察如何简化模型的实现。

Rayleigh 散射

Rayleigh 在 19 世纪后期发现了空气分子对光的散射。他特别指出，这一现象有很强的波长依赖性，空气分子散射蓝光多于绿光和红光。这种散射形式，以及他为计算由分子构成的体积（比如大气中的那种）的散射系数而提出的公式，只适用于尺寸远小于可见光波长的粒子（粒子至少应比被散射的波长小十分之一）。可见光的波长范围从 380 到 780 nm；440、550、680 分别是蓝、绿、红光的峰值。本课余下部分我们将使用这些值。Rayleigh 散射公式给出的是在已知分子密度的体积中的散射系数。在大气散射的文献中，散射系数用希腊字母 β（beta）表示。

$$\beta_R^s (h, \lambda) = \frac{8\pi^3(n^2-1)^2}{3N\lambda^4} e^{-\frac{h}{H_R}}$$

上标 S 代表散射，下标 \(R\) 代表 Rayleigh（以区别于 Mie 散射系数）。式中 \(h\) 是高度，\(\lambda\)（lambda）是波长，\(N\) 是海平面处的分子密度，n 是空气的折射率，\(H_R\) 是标高。我们的模拟中取 \(H_R\) = 8km（需要更精确的测量值可以上网查 scale height）。从这个公式可以看出，短波长的光（如蓝光）会给出更大的 \(\beta\) 值；而长波长的光（红光）则较小，这就解释了天空白天为何呈蓝色。阳光穿过大气时，散射到观察者方向的蓝光比绿光和红光更多。那么日出日落时天空为何呈红橙色？在这种特定构型下，阳光要经过比太阳位于你头顶（天顶）时长得多的那部分大气，才能到达观察者的位置。这段距离要长得多，大部分蓝光在到达观察者所在位置之前就被散射掉了，而散射频率低于蓝光的红光则保留下来。于是日出日落时天空呈红橙色（有时也会呈紫色或略带绿色）。

我们本可以用 \(N\)、\(n\) 等的某些测量值来算出 \(\beta\)，但我们将使用对应海平面处天空散射系数的预计算值（波长 440、550、680 分别对应 \(33.1 \mathrm{e^{-6}} \mathrm{m^{-1}}\)、\(13.5 \mathrm{e^{-6}} \mathrm{m^{-1}}\) 和 \(5.8 \mathrm{e^{-6}} \mathrm{m^{-1}}\)。注意蓝光的散射系数大于绿光和红光）。套用公式中的指数部分（右边的项），我们就可以针对任意给定高度 \(h\) 调整这些系数。

Nishita 的论文以及本课提到的其他论文，一个主要问题是它们都没有给出生成论文中那些图像所用的 N、n 等数值。用到测量值时，论文作者通常也不标注来源。海平面分子密度的科学数据并不容易找到，如果你在这个主题上有任何有用的链接或信息可以提供给我们，我们很乐意听。本课使用的海平面散射系数可在两篇论文中找到：Riley 等人的Efficient Rendering of Atmospheric Phenomena，以及 Bruneton 等人的Precomputed Atmospheric Scattering。

我们不会详细讨论空气密度，但网上能找到有趣的信息。本课只需要在海平面处适用的平均散射系数，足以用来重建天空颜色；不过学习如何计算这些系数，对任何希望对大气模型有更多掌控的好奇读者来说都是有意思的。

读一读体积渲染那门课程。你会知道，用来渲染参与介质的物理模型包括散射系数、吸收系数与相位函数，后者描述光与粒子碰撞时被散射多少、散射到哪些方向。本课我们只给出（并解释如何计算）地球大气的散射系数。对大气散射，通常认为吸收可以忽略。换句话说，我们假定大气不吸收光。回忆体积渲染课程：渲染参与介质所用物理模型中需要的消光系数是吸收系数与散射系数之和；因此（既然吸收系数为零），消光系数可以写成：

$$\beta_R^e = \beta_R^s$$

Rayleigh 相位函数长这样：

$$P_R(\mu)=\frac{3}{16\pi}(1+\mu^2).$$

其中 \(\mu\) 是光照方向与视线方向夹角的余弦（见图 8）。

Mie 散射

Mie 散射与 Rayleigh 公式相似，但适用于尺寸大于被散射波长的粒子。地球大气低空的气溶胶就属于这种情况。若把 Rayleigh 公式套用到气溶胶上，得不到令人信服的图像。用于渲染散射系数的 Mie 公式长这样：

$$\beta_M^s(h,\lambda)=\beta_M^s(0,\lambda) e^{-\frac{h}{H_M}}$$

其中下标 \(M\) 代表 Mie。注意 Mie 散射有一个专门的标高值 \(H_M\)，通常设为 1.2 km。与 Rayleigh 散射不同，我们不需要公式来计算 Mie 散射系数，而是使用在海平面处测得的数值。Mie 散射我们取 \(\beta_S = 210 \mathrm{e^{-5}} \mathrm{m^{-1}}\)。气溶胶的密度同样随高度指数递减。与 Rayleigh 散射一样，我们通过在公式右侧加入指数项来模拟这一效应（由标高因子 \(H_M\) 调制）。Mie 消光系数约为其散射系数的 1.1 倍。而 Mie 相位函数公式是：

$$P_M(\mu)=\frac{3}{8\pi}\frac{(1-g^2)(1+\mu^2)}{(2+g^2)(1+g^2-2g\mu)^{\frac{3}{2}}}$$

Mie 相位函数包含一个 \(g\) 项（Rayleigh 相位函数没有），它控制介质的方向异性。气溶胶表现出很强的前向指向性。有些论文取 \(g\)=0.76（我们也将把它用作默认值）。

光学深度的概念

在看 C++ 中的实际实现之前，我们先把拼图的所有碎片拼起来。首先，天空不过是一个包围着实心球体的球形体积。既然它不过是个体积，渲染天空就可以用光线步进算法，这是渲染参与介质最常用的技术。我们在体积渲染课程中详细研究过该算法。渲染体积时，观察者（或相机）既可能在体积内部，也可能在外部。

相机在内部时，我们必须找出视线光线离开体积的位置。在外部时，需要找出视线光线进入和离开体积的点。由于天空是一个球，我们用光线与球求交的程序来解析地计算这些点。我们在基础部分（光线与二次曲面求交）介绍过几种计算光线与球交点的技术。我们以地面为参考测试相机的高度，从而知道相机在大气内部还是外部。若该高度大于大气厚度，相机就在大气外，视线光线可能与大气在两处相交。

现在我们先假定相机在地面上（或离地一米），但算法对任意相机位置都适用（本课最后我们会渲染一张从外太空看天空的图像）。假定我们有一条视线光线（对应帧中的一个像素），并已知这条光线在何处与大气上边界相交。此时要解决的问题是：沿这条光线、朝观察者方向行进的光有多少。如下图所示，我们的相机或观察者不太可能直视太阳（那对眼睛有害）。

按逻辑讲，如果你朝天空的方向看，本应什么都看不到，因为你看到的是外太空，那里是空的（天体之间的空间）。但事实是你看到了蓝色。这是因为来自太阳的光进入大气后，被空气分子偏转到视线方向上。换句话说，沿视线方向并没有来自太阳的直接光（除非视线方向正对着太阳），但由于来自太阳的光被大气散射，其中一部分最终沿你眼睛的方向传播。这一现象称为单次散射（在体积渲染课程中解释过）。

到目前为止我们知道什么？我们知道，要渲染帧中一个像素的天空颜色，先要从点 \(Pc\)（相机位置）沿关注方向投射一条视线光线（\(V\)）。我们会算出这条光线与大气的交点 \(Pa\)。最后，需要计算因单次散射而沿这条光线行进的光量。这个值可用体积渲染公式算出，我们在体积渲染课程中研究过：

$$L(P_c, P_a)=\int_{P_c}^{P_a} T(P_c,X)L_{sun} (X)ds$$

其中 \(T\) 是点 \(Pc\) 与 \(X\)（沿视线方向的采样位置）之间的透射率，\(L\) 是体积中 \(X\) 处的光量。它说的只是：到达 \(Pc\) 处观察者的总光量，等于沿视线方向 \(V\) 被散射的所有阳光之和。这个量可以通过把 \(V\) 上不同位置（\(X\)）的光叠加起来得到。这种技术称为数值积分。沿光线取的样本越多，结果越好，但计算耗时越长。公式中的透射率项（\(T\)）考虑到一个事实：每个采样位置（\(X\)）上沿 \(V\) 朝观察者方向散射的光，在从 \(X\) 传播到 \(Pc\) 的过程中也会被衰减。

回忆体积渲染课程：光在体积中从一点传播到另一点时，因吸收与外散射而衰减。我们把 \(Pb\) 处的光量称为 \(Lb\)，把从 \(Pb\) 到达 \(Pa\) 的光量称为 \(La\)。存在参与介质时，\(La\)（从 \(Pb\) 接收到的光）将小于 \(Lb\)。透射率表示 \(La\) 与 \(Lb\) 之比，因此 \(T\) 的取值范围是零到一。写成公式，透射率是这样的：

$$T(P_a,P_b)=\frac{L_a}{L_b}=exp(-\sum_{P_a}^{P_b} \beta_e(h)ds)$$

用平白的话说，这个公式的意思是：我们需要沿路径光线 Pa-Pb 在各个采样位置测量大气的消光系数 \(\beta_e\)，把这些值加起来，乘以线段长度 \(ds\)（即 Pa-Pb 的距离除以所用样本数），再取该值的负数并送进指数函数。

回到我们讲过的 Rayleigh 散射，你会记得 \(\beta_s\)（我们将由此算出 \(\beta_e\)）可以用海平面处的散射系数乘以高度 \(h\) 对标高（\(H\)）之比的指数来算。

$$\beta_s(h) = \beta_s(0)exp(-\frac {h}{H})$$

对 Rayleigh 散射，吸收可以忽略，于是可以写成：

$$\beta_e(h)=\beta_s(h)+\beta_a(h)=\beta_s(h)+0=\beta_s(h)$$

你可以把 \(\beta_e(0)\) 移到积分号外（因为它是常数），然后把透射率公式改写为：

$$T(P_a, P_b)=exp(-\beta_e(0) \sum_{P_a}^{P_b} exp(-\frac{h}{H})ds)$$

指数函数里的这个和，可以看作 \(Pa\) 与 \(Pb\) 之间的平均密度值。这个公式本身在文献中通常被称为大气在 Pa-Pb 两点之间的光学深度。

把阳光加进去

最后，我们用上一段给出的渲染公式计算天空颜色。再写一遍：

$$L(P_c,P_a)=\int_{P_c}^{P_a} T(P_c, X)L_{sun}(X)ds$$

我们已经解释了如何渲染透射率。现在来看 Lsun(X) 这一项，解释如何求它。Lsun(X) 对应沿视线方向在采样位置 \(X\) 处被散射的阳光量。要求它，首先必须算出到达 \(X\) 的光。直接取阳光强度是不够的。确实，如果光在 \(Ps\) 处进入大气，它在传播到 \(X\) 的过程中也会衰减。因此我们需要用一个类似的公式来计算这个衰减，就像我们一直用来计算光沿视线光线从 \(Pa\) 传播到 \(Pc\) 的衰减的那个公式（公式 1）：

$$L_{sun}(X)=Sun \: Intensity * T(X,P_s)$$

公式 1

技术上，对视线光线上的每个采样位置 \(X\)，我们都需要朝阳光方向（\(L\)）投射一条光线，并找出这条光线与大气的交点（\(Ps\)）。然后我们用与视线光线相同的数值积分技术来估算公式 1 中的透射率（或光学深度）项。光射线会被切分成段，并对每个光段中心处的大气密度求值。

构建天空颜色算法的最后几个环节之一，是根据光照方向与视线方向，计入散射到视线方向的光量。这就是相位函数的作用。Rayleigh 散射与 Mie 散射各有自己的相位函数，我们前面已给出。如果需要复习相位函数，请读体积渲染课程。简言之，相位函数描述从方向 \(L\) 射来的光有多少被散射到方向 \(V\)。Mie 相位函数多含一个 \(g\) 项，称为平均余弦（还有许多其他叫法），它决定光主要沿前向（\(L\)）还是后向（\(-L\)）散射。前向散射时 \(g\) 在 [0:1] 区间，后向散射时 \(g\) 在 [-1:0] 区间。当 \(g\) 等于零时，光向各方向均匀散射，我们说这种散射是各向同性的。Mie 散射我们取 \(g\) 为 0.76。

$$L_{sun}(X)=Sun \: Intensity*T(X,P_s)*P(V,L)$$

最后，我们必须考虑到：对 Rayleigh 散射，主要是蓝光被散射到视线方向。为体现这一点，我们把上式的计算结果乘以散射系数（\(\beta_s\)），就得到整个公式中光的那一部分的完整表达式。不过要记得，\(\beta_s\) 随高度变化（其值是高度的函数），其中 \(h\) 是 \(X\) 相对地面（更准确说是海平面）的高度：

$$ \begin{array}{l} L_{sun}(X)=Sun \: Intensity*T(X,P_s)*P(V,L)*\beta_S(h)\\ L(X)=\int_{4\pi} Light \: Intensity * T(X, P_s)*P(V,L)*\beta_S(h) \end{array} $$

对地球大气，太阳是天空中唯一的光源；不过要写出上式的通用形式，我们应该考虑光可能来自许多方向。在科学论文中，你通常会看到这个公式写成对 \(4\pi\) 的积分，后者描述一个入向方向的球面。这个更通用的公式还会计入地面反射的阳光（多次散射），本章我们将其忽略。

计算天空颜色

把所有要素合在一起，我们得到（公式 2）：

$$ \begin{array}{l} Sky \: Color(P_c, P_a)=\int_{P_c}^{P_a}T(P_c,X)L_{sun}(X)ds \end{array} $$

公式 2

其中（公式 3）：

$$L_{sun}(X)=Sun \: Intensity * T(X,P_s)*P(V,L)*\beta_S(h)$$

公式 3

把 3 代入 2，得到：

$$ \begin{array}{l} Sky \: Color(P_c, P_a) = \\ \int_{P_c}^{P_a} T(P_c, X) * Sun \: Intensity * P(V,L) * T(X,P_s)*\beta_s(h)ds \end{array} $$

相位函数的结果是常数，阳光强度也是常数。因此我们可以把这两项移到积分号外（公式 4）：

$$ \begin{array}{l} Sky \: Color(P_c, P_a) = \\ Sun \: Intensity * P(V,L)\int_{P_c}^{P_a} T(P_c, X) * T(X,P_s)*\beta_s(h)ds \end{array} $$

公式 4

这就是针对特定视线与光照方向渲染天空颜色的最终公式。如此看来它并不太复杂。它计算量更大，因为要算一个积分，并且（通过透射率项）多次调用指数函数。另外记住，天空颜色是 Rayleigh 与 Mie 散射共同的结果。因此对每种散射我们都要算一遍这个公式：

$$ \begin{array}{l} Sky \: Color(P_c, P_a) = \\ Sky \: Color_{Rayleigh}(P_c,P_a) +Sky \: Color_{Mie}(P_c,P_a) \end{array} $$

回忆微积分：两个指数函数相乘等于一个指数函数，其指数为前两个函数指数之和：

$$e^ae^b=e^{a+b}$$

我们可以利用这一性质（只算一个指数而不是两个），把公式 4 中两个透射率项的乘积改写为：

$$ \begin{array}{l} T(P_c,X)=e^{ -\beta_{e0} } \\ T(X,P_s)=e^{ -\beta_{e1} } \\ T(P_c,X)*T(X,P_s)=e^{ -\beta_{e0} }*e^{ -\beta_{e1} }=e^{ -(\beta_{e0} + \beta_{e1}) } \end{array} $$

公式 5

现在我们来看看大气模型在 C++ 程序中的实现。

实现（C++）

现在要素齐备，可以在 C++ 程序中实现一版 Nishita 算法了。照例，程序会写得让算法易于理解。本段末尾会给出一些优化建议，让程序跑得更快。不过实时并非这里的目标；用这个程序仍能在几秒之内生成天空图像。

首先我们创建一个 Atmosphere 类，用来指定系统的所有参数：行星半径与大气半径（Re、Ra）、海平面处的 Rayleigh 与 Mie 散射系数、Rayleigh 与 Mie 的标高（Hr 与 Hm）、太阳方向、太阳强度以及平均余弦。所有距离都以米为单位（散射系数亦然）。


class Atmosphere 
{ 
public: 
    Atmosphere( 
        Vec3f sd = Vec3f(0, 1, 0), 
        float er = 6360e3, float ar = 6420e3, 
        float hr = 7994, float hm = 1200) : 
        sunDirection(sd), 
        earthRadius(er), 
        atmosphereRadius(ar), 
        Hr(hr), 
        Hm(hm) 
    {} 
 
    Vec3f computeIncidentLight(const Vec3f& orig, const Vec3f& dir, float tmin, float tmax) const; 
 
    Vec3f sunDirection;      //太阳方向（已归一化） 
    float earthRadius;       //论文中这通常是 Rg 或 Re（地面半径，eart） 
    float atmosphereRadius;  //论文中这通常是 R 或 Ra（大气半径） 
    float Hr;                //大气密度若均匀时的厚度（Hr） 
    float Hm;                //同上，但用于 Mie 散射（Hm） 
 
    static const Vec3f betaR; 
    static const Vec3f betaM; 
}; 
 
const Vec3f Atmosphere::betaR(3.8e-6f, 13.5e-6f, 33.1e-6f); 
const Vec3f Atmosphere::betaM(21e-6f);

最后，这里是用来计算公式 4（特定相机光线对应的天空颜色）的函数。我们做的第一件事是求相机光线与大气的交点（第 4 行）。然后计算 Rayleigh 与 Mie 相位函数的值（用太阳方向与相机光线方向。第 14 行和第 16 行）。第一个循环（第 17 行）沿相机光线生成采样。注意采样位置（公式中的 X）是线段中点（第 19 行）。由此可以算出采样点（X）的高度（第 19 行）。我们为 Rayleigh 与 Mie 散射计算 exp(-h/H) 乘以 ds（用 Hr 和 Hm）。这些值被累加（第 23、24 行），用来计算 X 处的光学深度。后面我们还会用它们来缩放公式 4 中的散射系数 \(\beta_s(h)\)（第 42、43 行）。接着我们计算 X 处来自太阳的光（第 31 到 38 行）。我们朝太阳方向投射一条光线（光线是平行的），求出与大气的交点。这条光线被切分成段，我们在段的中点处对密度求值（第 35、36 行）。把这些值累加就得到光射线的光学深度。注意我们会检验每个光照采样点在地面之上还是之下。若在地面之下，说明这条光射线处于地球的阴影中，这时我们可以放心丢弃这条光线的贡献（第 34、39 行）。注意 Mie 消光系数约为 Mie 散射系数的 1.1 倍（第 40 行）。最后，借助公式 5 的技巧，我们可以把光照与相机光线的光学深度累加进一次指数调用，从而算出累积的透射率（第 40、41 行）。函数末尾我们返回这条光线对应的天空最终颜色，即 Rayleigh 与 Mie 散射的透射率分别乘以其相位函数与散射系数之和。这个和还要乘以太阳强度（第 48 行）。

到这里，太阳强度只是一个魔法数（我们用了 20 这个值）。但在本课的后续修订中，我们会学习如何使用真实的物理数据）。


Vec3f Atmosphere::computeIncidentLight(const Vec3f& orig, const Vec3f& dir, float tmin, float tmax) const 
{ 
    float t0, t1; 
    if (!raySphereIntersect(orig, dir, atmosphereRadius, t0, t1) || t1 < 0) return 0; 
    if (t0 > tmin && t0 > 0) tmin = t0; 
    if (t1 < tmax) tmax = t1; 
    uint32_t numSamples = 16; 
    uint32_t numSamplesLight = 8; 
    float segmentLength = (tmax - tmin) / numSamples; 
    float tCurrent = tmin; 
    Vec3f sumR(0), sumM(0);  //mie 与 rayleigh 的贡献 
    float opticalDepthR = 0, opticalDepthM = 0; 
    float mu = dot(dir, sunDirection);  //论文中的 mu，即太阳方向与光线方向夹角的余弦 
    float phaseR = 3.f / (16.f * M_PI) * (1 + mu * mu); 
    float g = 0.76f; 
    float phaseM = 3.f / (8.f * M_PI) * ((1.f - g * g) * (1.f + mu * mu)) / ((2.f + g * g) * pow(1.f + g * g - 2.f * g * mu, 1.5f)); 
    for (uint32_t i = 0; i < numSamples; ++i) { 
        Vec3f samplePosition = orig + (tCurrent + segmentLength * 0.5f) * dir; 
        float height = samplePosition.length() - earthRadius; 
        // 计算光的光学深度
        float hr = exp(-height / Hr) * segmentLength; 
        float hm = exp(-height / Hm) * segmentLength; 
        opticalDepthR += hr; 
        opticalDepthM += hm; 
        // 光的光学深度
        float t0Light, t1Light; 
        raySphereIntersect(samplePosition, sunDirection, atmosphereRadius, t0Light, t1Light); 
        float segmentLengthLight = t1Light / numSamplesLight, tCurrentLight = 0; 
        float opticalDepthLightR = 0, opticalDepthLightM = 0; 
        uint32_t j; 
        for (j = 0; j < numSamplesLight; ++j) { 
            Vec3f samplePositionLight = samplePosition + (tCurrentLight + segmentLengthLight * 0.5f) * sunDirection; 
            float heightLight = samplePositionLight.length() - earthRadius; 
            if (heightLight < 0) break; 
            opticalDepthLightR += exp(-heightLight / Hr) * segmentLengthLight; 
            opticalDepthLightM += exp(-heightLight / Hm) * segmentLengthLight; 
            tCurrentLight += segmentLengthLight; 
        } 
        if (j == numSamplesLight) { 
            Vec3f tau = betaR * (opticalDepthR + opticalDepthLightR) + betaM * 1.1f * (opticalDepthM + opticalDepthLightM); 
            Vec3f attenuation(exp(-tau.x), exp(-tau.y), exp(-tau.z)); 
            sumR += attenuation * hr; 
            sumM += attenuation * hm; 
        } 
        tCurrent += segmentLength; 
    } 
 
    // 这里我们给太阳强度用一个魔法数（20）。在本课/代码的后续修订中，
    // 我们会让它更符合物理
    return (sumR * betaR * phaseR + sumM * betaM * phaseM) * 20; 
}

在 2.5GHz 处理器上每帧只需几秒就能算完（耗时取决于你用的视线采样与光照采样数量）。这个程序可以加上几项功能。有些论文在保存结果图像前会对它做色调映射。这有助于减小太阳周围天空亮度（非常亮、发白）与天空其余部分之间的反差。另外，你可以把结果图像保存为浮点图像格式（HDR、EXR），因为视你的太阳强度而定，数值很容易大于一（把数值重新映射并裁剪掉并不是好选择）。这个功能可以轻易加到任何现有渲染器中（详见空气透视那一段）。这些图像中，太阳位于地平线上方或略低于地平线时，天空颜色转为红橙色。你也可以把 Mie 散射的贡献注释掉，单独观察 Rayleigh 散射的贡献（反之亦然）。不过，只消看看生成的图像，再回想你学过的这两个散射模型，就能轻易猜出：Mie 散射造就了太阳周围那一大圈白色光晕，以及地平线处天空的变亮/去饱和。而 Rayleigh 散射则造就了天空的蓝/红/橙。

一个有意思的项目可以是：把日期和时间传给程序，据此算出太阳位置，用这个太阳方向渲染一帧，再把结果与同一天同一时刻拍摄的真实天空照片作比较。它们能有多接近？太阳的位置与其赤纬和太阳时角有关（换句话说，与一天中的时刻有关）。

优化：Nishita 注意到天空关于「太阳位置与地心所定义的轴」是对称的。基于这一观察，论文提出一种技术，把光学深度烘焙进一张 2D 表，可以用 \(\mu\)（视线与光照方向夹角的余弦）和 h（采样点高度）来查表。你最好为每种散射模型（Rayleigh 与 Mie）各建一张表。这些表可以预先算好、存进文件，每次运行程序时复用。用预计算的光学深度值代替即时计算（那需要几次昂贵的指数调用），会大幅加快渲染。如果速度对你的应用很关键，这就是你该实现的第一个优化（细节见 Nishita 的论文）。

光束

大气效应有时能造出壮观的视觉效果。光束通常让这些效果更具戏剧性。如果光在体积中自由穿行，体积看起来会亮度均匀。但若我们在场景中放入一些物体，体积中被这些物体遮住的区域就会比未被遮挡的区域更暗。光束就是与光源（太阳）照亮的那部分体积对应的光柱。但它们之所以可见，只是因为该体积中有区域被场景里的物体遮住（对地球大气而言，主要是山和云）。

模拟空气透视

计算空气透视不需要对代码做多少改动。如下图所示，山的颜色受蓝色大气存在的影响。因为从眼睛到地面的距离在光线 A 上比在光线 B 上短，大气对光线 A 颜色的贡献不如对光线 B 那么明显。

首先，你应该渲染该光线对应的几何体（地形）颜色。然后你最好渲染透射率（也就是不透明度）以及大气的颜色（用眼睛位置与该光线和几何体的交点作为 Pc 与 Pa），再用下面的 alpha 混合公式把两种颜色合成起来：


Ray Color = Object Color * (1 - Transmittance) + Atmosphere Color

不过本课为了让代码简单，我们不渲染地面的颜色，它将默认为黑色。如果你想详细了解这种合成操作怎么做，请查看体积渲染课程。下面是太阳在两个不同位置时我们得到的两张结果。相机非常远，因此画幅下半部分能看到地球。我们先判断主光线是否与地球相交。若相交，再计算从眼睛位置到该交点之间的大气颜色。

                    // 击中地球的位置）。当然，如果视线光线没有击中地球，
                    // 那么光线的范围就是 [0:INF]。随后在 computeIncidentLight() 中，
                    // 我们计算这条主光线与大气的交点，并把光线的最大 t 范围 
                    // 限制在它离开大气的那个点。
                    float t0, t1, tMax = kInfinity; 
                    if (raySphereIntersect(orig, dir, atmosphere.earthRadius, t0, t1) && t1 > 0) 
                        tMax = std::max(0.f, t0); 
                    // 视线光线（或称相机光线）被限制在 [0:tMax] 范围内
                    *p += atmosphere.computeIncidentLight(orig, dir, 0, tMax); 
                } 
            } 
            *p *= 1.f / (numPixelSamples * numPixelSamples); 
        } 
        fprintf(stderr, "\b\b\b\b%3d%c", (int)(100 * y / (width - 1)), '%'); 
    } 
#endif 
    ... 
}

异星天空

改变 Atmosphere 模型的参数，很容易造出与我们地球天空外观迥异的天空。例如可以设想重建火星的大气，或创造一个想象中的天空。散射系数与大气厚度是改变外观最显而易见的可调参数。增加 Mie 散射的贡献会很快把大气变成一个雾蒙蒙的天空，再配上光束，可以造出富有表现力/有气氛的图像。

那多次散射呢？

天空的颜色是光在大气中向观察者方向被散射一次或多次的结果。不过在文献中，人们强调单次散射占主导。因此忽略多次散射来渲染天空图像仍能得到非常可信的结果。文献中的多数模型忽略多次散射，或没有提供计入它的技术。Bruneton 认为地面反射的光量足够大，会影响天空颜色。他提出一个模型，其中考虑了地面散射的光（该模型中假定地球是完全的球形）。

结论

本章你需要记住的头几个要点是：天空可以当作一个巨大的球形体积来渲染（它包围着另一个更大的球，代表地球）。吸收系数、散射系数与相位函数可以定义任何体积（如体积渲染课程所学）。天空的外观是 Rayleigh 与 Mie 散射叠加的结果。Rayleigh 散射造就了天空的蓝色（以及日出日落时的红橙色），它由尺寸远小于光波长的空气分子散射光所致。空气分子散射蓝光多于绿光和蓝光。Mie 散射造就了大气灰白的朦胧外观。它由尺寸大于光波长的分子散射阳光所致。这类分子称为气溶胶。气溶胶对各波长的光散射相同。

改进思路/练习

如果你想改进/扩展代码，这里有一串想法：

  • 用过程式纹理或 mipmap 渲染地球表面（陆地与海洋）。

  • 给天空模型加上云。

  • 预计算太阳与光线上任意一点之间的光学深度（用这种技术加速程序——方法细节见 Nishita 的论文）。

  • 加入多次散射。

  • 把这个模型与其他天空模型作比较（看论文「A Framework for the Experimental Comparison of Solar and Skydive Illumination」）。
