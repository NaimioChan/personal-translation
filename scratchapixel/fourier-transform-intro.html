傅里叶变换简介

阅读时间：20 分钟。

傅里叶变换快速入门

傅里叶变换的思想是：由真实数据构成的信号可以分解成一系列频率。我们先从一维函数（比如声波）入手，后面再说明如何把方法扩展到二维函数（比如图像）。在那之前，先凭直觉体会一下「把信号分解成频率」到底是什么意思。有意思的是，看图像比看声波更容易对这个概念产生直觉。例如下图里有三种石滩纹理。

左图里，卵石的大小非常规整，而且大体均匀地铺满整幅图像。把它换算成频率，这些石头通常具有相同的频率；又因为图像里除了卵石什么都看不到，卵石的振幅应当是最大的。而中间的图里，这次卵石的尺寸各不相同。换到频率世界，这意味着这幅图很可能由多个频率组成，每种卵石尺寸对应一个频率，比如大、中、小各一个。

最后右边的图里也有卵石或石头，尺寸都一样，但这次数量很少。它们的频率应当仍是一致的，但振幅要比第一个例子低得多，因为它们出现得没那么频繁。

傅里叶变换会用「构成图像的元素都有哪些频率」和「这些频率的振幅有多大」来描述图像，而振幅在某种程度上代表某一频率的元素在图像中出现的频繁程度。

  • 第一幅图：单一频率，振幅很大。

  • 第二幅图：多个频率，振幅相近。

  • 第三幅图：唯一的频率（就石头而言），振幅很低。

你可以把傅里叶变换看作按频率与振幅对信号的一次分解。

现在看一个具体的例子。首先，你需要知道关于傅里叶变换的几件事。本课里我们处理的是「离散值」（也就是采样）。就声波而言，这些值就是每个时间步上的信号值（采样）。以图像的一行为例（它是一维信号），这些值就是构成这一行的每个像素的亮度值。我们拿选好的这组图像来验证一下自己的直觉，做法如下。每幅图宽 128 像素。先用左边的图和中间那一行取一些离散数据（用红色通道）。图像以 PPM 格式存储，你可以读取它（我们在 Scratchapixel 上已经讲过很多次怎么读）。动手做一遍，把得到的值打印出来。

现在手上有了数据，来对它做离散傅里叶变换（既然作用于离散数据，就是构成我们信号的那 128 个像素值），把它从空域（信号中每个值对应图像某一行中一个确定的像素位置，因此它确实是空间的函数）变换到频域。

到了这里就要开始算点数学了。离散傅里叶变换的公式长这样：

$$f(k) = \sum_{n=0}^{N-1} f(n) e^{-\dfrac{i 2\pi k n}{N}}$$

左边算出来的变量 \(f(k)\) 是傅里叶分解的系数。在我们这个例子里，信号含 128 个值，因此会有 128 个这样的傅里叶系数。注意这并非强制。我们可以用比输入信号值个数更少的系数来「分解」输入信号。不过系数用得少了，之后就没法把信号完美还原成与输入完全一致的样子。公式说的是：对每一个这样的系数，都要把输入函数的所有值乘以一个含指数函数的项，再求和。奇妙之处就在这个指数函数里，在欧拉数 \(e\) 的指数上。指数里出现了字母 \(i\)，也就是说，可以说我们面对的不再是普通数字，而是所谓的虚数。现在先别急着弄明白这些奇怪的数字是什么。你只要知道这些数由两部分组成：实部与虚部就够了。数学上恰好有这样一个结果：指数里含复数的指数函数，可以写成另一种形式：

$$e^{-ix} =\color{green}{ \cos(x) } - \color{blue}{ i \sin(x) }$$

其中 \(ix\) 是一个复数。顺便注意指数项前面的负号。这就是欧拉公式，数学里一个极其重要的公式。别去过度琢磨它意味着什么。这样看：它给出一个复数，实部（绿色）和虚部（蓝色）都是三角函数。为简单起见，（从编程角度）我们可以把数的实部（\(\color{green}{ \cos(x) }\) 项）存进一个变量，把虚部（\(\color{blue}{ i \sin(x) }\) 项）存进另一个变量。这样就得到。


float real = ( cos(x)); float imag = (-sin(x));

公式里的 \(k\) 项是什么？前面说过，输入信号傅里叶分解的系数个数可以少于信号的长度（记为 \(N\)）。这个 \(k\) 项就与这件事有关：它是我们想用于信号分解（或变换）的系数个数。在我们这个例子里 \(N=128\)，所以 \(k\) 取什么值都行，比如 \(0 \lt k \le N = 128\)。但正如已经说过的，虽然可以用比输入数据采样数更少的系数，可如果你之后想通过逆离散傅里叶变换从系数还原出原信号，系数个数就必须与信号采样数相同。因此我们这里用 \(k = N\) 个系数。

C++ 自带复数类型，但为了清楚起见，我们用自己的结构体来存复数。下面是前向离散傅里叶变换（把一行像素从空域转到频域）的一个伪代码式、朴素实现：


typedef struct
{
    float real;
    float imag;
} complex;

void DFT1D(const int N, const unsigned char *in, complex *out)
{
    for (int k = 0; k < N; ++k) {
        out[k].real = out[k].imag = 0; // 初始化
        for (int n = 0; n < N; ++n) {
            out[k].real += (int)in[n] * ( cos(2 * M_PI * n * k / N));
            out[k].imag += (int)in[n] * (-sin(2 * M_PI * n * k / N));
        }
    }
}

complex *coeffs = new complex[N];
DFT1D(N, imageData, coeffs);

结果（输出）是一行复数。虚数的数学可能和设想一个空间维度超过 3 的世界一样让人头晕。但正如你所见，实际实现相当简单。万岁！注意这个函数包含两个长度为 \(N\) 的内层循环，因此该算法的复杂度是 \(O(N^2)\)。换个说法，随着 \(N\) 增大，算法会很快变慢。你可能听说过快速傅里叶变换（FFT），它是对这个算法的优化。本课选择简单优先于速度，因此不用它。

另外，你也可以从中窥见这个公式在做什么。\(\cos\) 和 \(sin\) 函数里的项有时被称为公式的角频率项。这是因为傅里叶变换所做的，就是把输入函数的采样表示成一系列有限个（复）正弦波，每个正弦波有各不相同（但固定）的频率（即 \(2 \pi k n / N\) 项）。

那现在怎么算逆变换？要理解这部分，从一个稍复杂的问题入手再往回走会更容易。设想我们要先对图像的采样做傅里叶变换，再做它的反变换。此时面对的是二维离散傅里叶变换（像素是离散值）。这个问题之所以能简单解决，是因为傅里叶变换是一个被称为可分离的滤波器。若滤波器可分离，你就可以先把它作用于图像的每一行，把问题简化成我们已经会解的一维情形。这样得到的、经过变换的像素行，行数与图像的行数一样多。第二步，再对变换得到的这些行做一次一维变换，不过这次是沿垂直方向。下图说明了这个思路，为简单起见，例子用的是 4x4 像素的图像。

xx image xx

事件顺序与对应的结果如下：

步骤 1：从真实数据出发，也就是图像的像素，它是一个二维数组。把这个数组叫做 A。

步骤 2：逐行（水平方向）处理，得到的「复数」行数与图像的行数一样多。我们可以把这些行装进一个复数数组，叫做 B。写成伪代码就是：


unsigned char A = new unsigned char[N * N * 3];
readPPM(A, "pebble-A.ppm");
complex *B = new complex[N * N];

for (j = 0; j < N; ++j) {
    DFT1D(N, A + N * 3 * j, B + N * j);
}

DFT1D 函数长这样：


void DFT1D(const int N, const unsigned char *real, complex *coeffs)
{
    ...
}

可以看到，我们的前向一维傅里叶变换以真实数据为输入，输出由实部和虚部构成的复数。

步骤 3：最后处理 B 里的数据，不过这次用列而不是行，得到另一个二维数组 C。伪代码看起来是这样：


// 处理 B 数组的所有列（复数）
complex *column = new complex[N];
complex *C = new complex[N * N]
for (i = 0; I < N; ++i) {
    // 提取数据
    for (j = 0; j < N; ++j) {
        column[j] = B[j * N + i];
    }
    // 处理下标为 i 的列
    DFT1D(N, column, C + N * i);
}
// 不再需要这些临时数组
delete [] column;
delete [] B;

从编程角度看，你能看出这段代码的问题吗？问题在于 DFT1D 函数第二个参数的类型是 unsigned char，而上面代码里传进去的变量类型是 complex。因此它跑不起来（编译不过）。

问题出在哪？其实在数学上，离散傅里叶变换既处理实数也处理复数。步骤 1 和 2 里我们只处理由图像像素值构成的真实数据。这些是现实世界的数据，因此没有虚部。这样的数完全可以写成这样：


complex c;
c.real = pixel_value;
c.imag = 0;

换句话说，我们仍然从复数出发，但由于填入的是真实数据，它们的虚部会空着（置为 0）。这样做之后，我们可以搭出一条流水线：前向傅里叶变换始终以复数为输入，无论这个输入代表的是真实数据（比如像素值），还是系数行——如前面所示，当我们利用 DFT 的可分离性把二维真实数据（图像）从空域变换到频域时，就会出现后一种情况。于是我们的代码现在应当是这样。


unsigned char imageData = new unsigned char[N * N * 3];
readPPM(imageData, "pebble-A.ppm");
complex *A = new Complex[N * N];

// 把真实数据存入复数数组 A
for (j = 0; j < N; ++j) {
    for (i = 0; i < N; ++i) {
        A[N * j + i].real = imageData[N * j + i];
        A[N * j + i].imag = 0;
    }
}

// 用来存对图像各行做 DFT 的结果
complex *B = new complex[N * N];

for (j = 0; j < N; ++j) {
    DFT1D(N, A + N * j, B + N * j);
}

并把 DFT1D 函数改成：


void DFT1D(const int N, const complex *in, complex *out)
{
	...
}

现在它就能顺利编译了。但我们绕这么大一圈并不只是为了一个编译问题。数学部分也要改。再把离散傅里叶公式看一遍。它说的是：

$$f(k) = \sum_{n=0}^{N-1} f(n) e^{-\dfrac{i 2\pi k n}{N}}$$

如你所知，\(f(k)\) 项是一个系数，因此是复数；而到目前为止，我们一直把 \(f(n)\) 当作实数。但现在既然把 DFT1D 改成了既能处理复数、不只处理实数，在这个版本的函数里 \(f(n)\) 也变成了复数。于是我们有公式中由 \(f(n)\) 项表示的复数，乘以右边的欧拉数 \(e\)——我们也知道它是复数，因为它的指数里有字母 \(i\)。于是我们有两个复数相乘，可以写成这种形式：

$$z \cdot w = (\color{green}{a} + \color{blue}{ib}) \cdot (\color{green}{c} + \color{blue}{id})$$

其中 \(a\) 和 \(c\) 是两个虚数 \(z\) 和 \(w\) 的实部，而 \(b\) 和 \(d\) 是它们各自的虚部。展开并整理各项，得到：

$$z \cdot w = \color{green}{ (ac - bd) } + \color{blue}{ i(ad + bc) }$$

如何得到这个公式最终结果的完整推导，可以在 wikipedia 上找到。在我们的例子里，\(z\) 将换成 \(f(n)\)，\(w\) 将换成那个指数项：

$$f(n) \cdot e^{-\dfrac{2\pi I k n}{N}}$$

用欧拉公式，我们可以写成：

$$(\color{green}{f(n).real} + \color{blue}{f(n).imag}) \dot (\color{green}{cos(\theta)} + \color{blue}{-\sin(\theta)})$$

其中 \(\theta = \dfrac{2\pi i k n}{N}\)。

代入复数乘法的结果，就得到：

$$\color{green}{(f(n).real \cdot \cos(\theta) - f(n).imag \cdot -\sin(\theta))} + \color{blue}{i(f(n).real \cdot -\sin(\theta) + f(n).imag \cdot \cos(\theta))}$$

这一项定义数的实部：

$$\color{green}{ (f(n).real \cdot \cos(\theta) - f(n).imag \cdot -\sin(\theta))},$$

而虚部由这一项定义：

$$\color{blue}{ (f(n).real \cdot -\sin(\theta) + f(n).imag \cdot \cos(\theta)) }.$$

写成代码就是这样：


void DFT1D(const int N, const complex *in, complex *out)
{
    for (int k = 0; k < N; ++k) {
        out[k].real = out[k].imag = 0; // 初始化
        for (int n = 0; n < N; ++n) {
            out[k].real += in[n].real * ( cos(2 * M_PI * n * k / N))
                         + in[n].imag * ( sin(2 * M_PI * n * k / N));
            out[k].imag += in[n].real * (-sin(2 * M_PI * n * k / N)) 
                         + in[n].imag * ( cos(2 * M_PI * n * k / N));
        }
    }
}

这一版前向离散傅里叶变换就算完整了。那逆 DFT 怎么算？首先要知道，计算逆 DFT 的公式与前向 DFT 略有不同。它长这样：

$$f(n) = \dfrac{1}{N} \sum_{k=0}^{N-1} f(k) e^{\dfrac{i 2\pi k n}{N}}$$

它与第一个公式相似，但注意这次我们是对 DFT 的系数循环，算出空域（或时域）中的一个值。还要注意，这个求和的结果总要以某种方式除以系数的总数（这里是 \(N\)）。同样注意，这里算出来的是 \(f(n)\)，而前向 DFT 里算的是 \(f(k)\)，即系数。另外注意这次欧拉数的指数（\e\）是正的。欧拉公式在这个特定情形下变成：

$$e^{ix} =\color{green}{ \cos(x) } + \color{blue}{ i \sin(x) }$$

我们把正弦函数前面的减号换成了加号。用这个欧拉公式，这两个复数的相乘可以写成：

$$(\color{green}{f(n).real} + \color{blue}{f(n).imag}) \dot (\color{green}{cos(\theta)} + \color{blue}{\sin(\theta)})$$

套用两个复数相乘的公式（见上文），得到：

$$\color{green}{(f(k).real \cdot \cos(\theta) - f(k).imag \cdot \sin(\theta))} + \color{blue}{i(f(k).real \cdot \sin(\theta) + f(k).imag \cdot \cos(\theta))}$$

下面是这个公式的一份 C++ 实现：


oid iDFT1D(const int N, const Complex *in, Complex *out)
{
    for (int n = 0; n < N; ++n) {
        out[n].real = 0, out[n].imag = 0;
        // 遍历所有系数
        for (int k = 0; k < N; ++k) {
            out[n].real += in[n].real() * (cos(2 * M_PI * n * k / N))
                         - in[n].imag() * (sin(2 * M_PI * n * k / N));
            out[n].imag += in[n].real() * (sin(2 * M_PI * n * k / N))
                         + in[n].imag() * (cos(2 * M_PI * n * k / N));
        }
        out[n].real /= N;
        out[n].imag /= N;
    }
}

如前面所说，二维 DFT（或它的逆）可以通过执行两次一维 DFT 完成，一次沿图像的行，一次沿图像的列，下面这个函数做的就是这件事：


template &lttypename OP>
void DFT2D(const int N, const Complex *in, Complex *out, OP op)
{
    // 处理行
    for (int i = 0; i < N; i++) {
        op(N, in + i * N, out + i * N);
    }

    // 处理列
    Complex ca[N], cb[N];
    for (int i = 0; i < N; i++) {
        for (int j = 0; j < N; j++) {
            ca[j].real = out.real[j * N + i];
            ca[j].imag = out.imag[j * N + i]; // 提取下标为 j 的列
        }
        op(N, ca, cb); // 对这一列做一维 DFT
        for (int j = 0; j < N; j++) {
            out[j * N + I].real = cb[j].imag;
            out[j * N + I].imag = cb[j].imag; // 把结果存回数组
        }
    }
}

注意在这个实现里，函数是一个模板，模板参数是我们想对数据执行的函数类型。这个函数既可以是前向一维 DFT，也可以是逆一维 DFT。这种手法让我们只写一个函数，就能把图像从空域转到频域（前向），或从频域转回空域（逆变换）。换成别的方式，我们就得写两个（每种变换一个）。把图像变换到频域再变回空域的代码长这样：


int main()
{
    // 读取输入图像
    ...

    complex *in = new complex[N * N];
    for (int j = 0; j < N; ++j) {
        for (int i = 0; i < N; ++i) {
            in[j * N + i] = complex(img[(j * N + i) * 3], 0);
        }
    }
    complex *out = new complex[N * N];

    DFT2D(N, in, out, DFT1D); // 前向变换
    DFT2D(N, out, in, iDFT1D); // 逆变换

    // 输出图像
    ...

    return 0;
}

这里不贴结果，自己跑一遍可能更有意思。如果代码正确，输入与输出的图像看起来应当一样。但从这个例子你能看出，只要讲得清楚、写得明白，DFT 其实很简单（就是直白的实现，不用任何奇怪的心思绕弯）。这个朴素实现唯一潜在的问题是速度，但另一方面，这一版也紧凑、好写、好懂。如果你想在不依赖复杂晦涩的库的前提下试做基于 DFT 的技术原型，它是一个理想的实现。

关于复数还需要知道的几件事

实现 Tessendorf 的论文会用到复数的基本运算，比如加法和乘法。这些我们已经看过了。例如我们知道，做加法时要把参与相加的复数的实部与虚部分别相加。

$$w + z = (a + ib) + (c + id) = (a + c) + i(b + d)$$

我们也知道乘法的公式：

$$w * z = (a + ib) * (c + id) = (ac - bc) + i(ad + bc)$$

做 Tessendorf 的论文，你还需要知道复数的共轭。复数 \(w\) 的共轭记作 \(\overline w\)（在上面加一横）。而复数 \(w = a + ib\) 的共轭是：

$$\overline w = a - ib$$

很简单，把它的虚部变号。

符合 C++11 的 DFT 函数

较新版本的 C++ 以 std::complex 类型（定义在 #include 中）的形式提供了复数概念的实现。这个实现非常方便：它负责复数的加法、乘法、求共轭等运算。因此我们可以用这个标准 C++ 库写出更简单的代码。例如会得到类似这样的东西：


void DFT1D(const int N, const complex *in, complex *out)
{
    for (int k = 0; k < N; ++k) {
        out[k] = 0;
        for (int n = 0; n < N; ++n) {
           double w = 2 * M_PI * n * k / N;
           out[k] += in[n] * complex(cos(w), -sin(w));
        }
    }
}

void iDFT1D(const int N, const complex *in, complex *out)
{
    for (int n = 0; n < N; ++n) {
        out[n] = 0;
        for (int k = 0; k < N; ++k) {
            double w = 2 * M_PI * n * k / N;
            out[n] += in[k] * complex(cos(w), sin(w));
        }
        out[n] /= N;
    }
}

备注

想挑战一下的读者可以注意：离散傅里叶变换的代码很容易「并行化」。如果你了解 C++ 的多线程，把这些函数并行化会是个有意思的练习。
