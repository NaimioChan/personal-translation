用 4x4 矩阵在三维中变换物体

阅读时间：12 分钟。

本课我们学习用 4x4 变换矩阵改变 3D 物体的位置、旋转和缩放。到目前为止，我们都假设渲染的几何体一直待在模型最初创建时的位置。我们学过如何对任意中心位置求光线与球的交点。而多边形网格在场景中的位置是由构成它的顶点位置确定的，多数情况下这并非我们想要物体在最终场景里所处的位置。因此需要变换它。比如你建了一棵树的模型，却想渲染一片森林的图像。要造出这片森林，你会用做好的树的模型，复制很多份，再对这些副本施加随机变换，让每棵树的缩放、位置和旋转都各不相同。这样一来，你多少能让模型看起来像是独有的，制造出森林由许多不同树的模型组成的错觉。更一般地说，变换可以把任何模型放到渲染场景中它最终的位置（这里的「位置」是广义的，包含位置、旋转和缩放的概念）。在 CG 里，艺术家把这一步叫作布局（layout）或场景陈设（set dressing）（布局也可能包括在场景中摆放相机，相机本身也要被变换）。它做的事就是拿物体建模时的样子（往往会取同一模型的多个副本），把它们到处移动、旋转、缩放。

3D 模型在 Maya 或 Blender 这类建模软件中创建时，通常以世界原点为中心。更多情况下模型的底部还落在 xz 平面上（Maya 中如此，3DSMax 中是 xy 平面）。处于这个位置时，我们说模型是在物体空间中定义的。如果我们用 4x4 变换矩阵改变这个物体的尺寸、旋转和位置，我们就说物体是在世界空间中定义的，而把这个物体从物体空间变换到世界空间的矩阵，自然就叫物体到世界矩阵（在 OpenGL 以及更普遍的实时图形 API 中，这个矩阵也被称为模型矩阵）。

变换顶点

从编程角度看，把物体从物体空间变换到世界空间很直接。我们要做的只是遍历网格的所有顶点，用物体到世界矩阵变换它们：


for (uint32_t i = 0; i < numVertices; ++i) { 
    const Vec3f & vertObjectSpace = vertices[i]; 
    Vec3f vertWorldSpace; 
    objectToWorld.multVecMatrix(vertObjectSpace, vertWorldSpace); 
    vertices[i] = vertWorldSpace; 
}

上面的代码是为了清楚而写的，还可以更快。物体到世界矩阵在 3D 应用里往往可以方便地查出来。比如在 Maya 里你可以选中物体，用 Mel 命令 xform -q -ws -m 或 getAttr .worldMatrix。

物体到世界矩阵是场景中任何物体都具有的属性，因此我们可以把它定义成程序中 Object 类的成员变量。该矩阵会传给类的构造函数（第 4 行）。


class Object 
{ 
 public: 
    Object(const Matrix44f &o2w) : objectToWorld(o2w) {} 
    virtual ~Object() {} 
    virtual bool intersect(const Vec3f &, const Vec3f &, float &, uint32_t &, Vec2f &) const = 0; 
    virtual void getSurfaceProperties(const Vec3f &, const Vec3f &, const uint32_t &, const Vec2f &, Vec3f &, Vec2f &) const = 0; 
    Matrix44f objectToWorld; 
};

所有物体都能访问这个矩阵，因为它们都派生自这个基类（二次曲面、多边形网格等）。以 TriangleMesh 类为例，它的工作方式如下。物体到世界矩阵传给 TriangleMesh 类的构造函数（第 6 行），后者再把它传给 Object 类的构造函数（第 13 行）。最后，在三角网格类的构造函数里，我们遍历构成网格的所有顶点，把网格顶点设为输入顶点经物体到世界矩阵变换后的结果（第 19-22 行）：


class TriangleMesh : public Object 
{ 
public: 
    // 由面索引数组和顶点索引数组构建三角网格
    TriangleMesh( 
        const Matrix44f &o2w, 
        const uint32_t nfaces, 
        const std::unique_ptr&ltuint32_t []> &faceIndex, 
        const std::unique_ptr&ltuint32_t []> &vertsIndex, 
        const std::unique_ptr&ltVec3f []> &verts, 
        std::unique_ptr&ltVec3f []> &normals, 
        std::unique_ptr&ltVec2f []> &st) : 
        Object(o2w), 
        numTris(0) 
    { 
        ... 
        // 为存储网格顶点位置分配内存
        P = std::unique_ptr&ltVec3f []>(new Vec3f[maxVertIndex]); 
        for (uint32_t i = 0; i < maxVertIndex; ++i) { 
            // 把物体空间顶点变换到世界空间位置
            objectToWorld.multVecMatrix(verts[i], P[i]); 
        } 
        ... 
    } 
};

关于变换流水线。

现在我们对变换流水线有了完整的图景。物体首先从物体空间变换到世界空间。如果使用光栅化，物体随后从世界空间变换到相机空间。接着顶点被投影到屏幕上（用透视投影矩阵）进入屏幕空间，然后重映射到 NDC（这一步是透视投影矩阵的一部分）。最后，NDC 坐标下图像平面上的点被转换成最终的栅格或像素坐标。在光线追踪中，我们只关心物体到世界变换矩阵。光线在世界空间中定义，光线与几何体的求交也在世界空间中进行（也可以像本课后面所述在物体空间中进行，不过这通常更算特例）。

变换法线

还记得几何那门课里讲过，当我们用 4x4 矩阵变换点和向量时，法线必须用该物体到相机矩阵的逆的转置来变换。因此，除了在 Object 类构造函数里设置物体到世界矩阵，我们还会计算世界到物体矩阵（第 4 行），变换法线时要用到它：


class Object 
{ 
 public: 
    Object(const Matrix44f &o2w) : objectToWorld(o2w), worldToObject(o2w.inverse()) {} 
    virtual ~Object() {} 
    virtual bool intersect(const Vec3f &, const Vec3f &, float &, uint32_t &, Vec2f &) const = 0; 
    virtual void getSurfaceProperties(const Vec3f &, const Vec3f &, const uint32_t &, const Vec2f &, Vec3f &, Vec2f &) const = 0; 
    Matrix44f objectToWorld, worldToObject; 
};

在 TriangleMesh 的构造函数里，我们现在需要用世界到物体矩阵的转置来变换法线。我们先算出转置矩阵（第 27 行），再用它变换所有法线（第 33 行）：


TriangleMesh( 
    const Matrix44f &o2w, 
    const uint32_t nfaces, 
    const std::unique_ptr&ltuint32_t []> &faceIndex, 
    const std::unique_ptr&ltuint32_t []> &vertsIndex, 
    const std::unique_ptr&ltVec3f []> &verts, 
    std::unique_ptr&ltVec3f []> &normals, 
    std::unique_ptr&ltVec2f []> &st) : 
    Object(o2w), 
    numTris(0) 
{ 
    uint32_t k = 0, maxVertIndex = 0; 
    // 算出这个网格需要创建多少个三角形
    for (uint32_t i = 0; i < nfaces; ++i) { 
        numTris += faceIndex[i] - 2; 
        for (uint32_t j = 0; j < faceIndex[i]; ++j) 
            if (vertsIndex[k + j] > maxVertIndex) 
                maxVertIndex = vertsIndex[k + j]; 
        k += faceIndex[i]; 
    } 
    maxVertIndex += 1; 
 
    // 为存储网格顶点位置分配内存
    P = std::unique_ptr&ltVec3f []>(new Vec3f[maxVertIndex]); 
    N = std::unique_ptr&ltVec3f []>(new Vec3f[maxVertIndex]); 
    texCoordinates = std::unique_ptr&ltVec2f []>(new Vec2f[maxVertIndex]); 
    Matrix44f transformNormals = worldToObject.transpose(); 
    for (uint32_t i = 0; i < maxVertIndex; ++i) { 
        // 变换顶点
        objectToWorld.multVecMatrix(verts[i], P[i]); 
 
        // 变换法线
        transformNormals.multDirMatrix(normals[i], N[i]); 
        N[i].normalize(); 
 
        texCoordinates[i] = st[i]; 
    } 
 
    // 为存储三角形索引分配内存
    trisIndex = std::unique_ptr&ltuint32_t []>(new uint32_t [numTris * 3]); 
    uint32_t l = 0; 
    // 生成三角形索引数组并设置法线与 st 坐标
    for (uint32_t i = 0, k = 0; i < nfaces; ++i) {  //对每个面
        for (uint32_t j = 0; j < faceIndex[i] - 2; ++j) {  //对该面中的每个三角形
            trisIndex[l] = vertsIndex[k]; 
            trisIndex[l + 1] = vertsIndex[k + j + 1]; 
            trisIndex[l + 2] = vertsIndex[k + j + 2]; 
            l += 3; 
        } 
        k += faceIndex[i]; 
    } 
}

注意纹理坐标不需要变换。它们活在自己的二维空间里，不受物体变换的影响。当然也可以变换纹理坐标，但那种情况下一个 3x3 矩阵就够了（足以处理二维空间中的缩放、旋转和平移）。不过实践中很少这么做。纹理坐标一般在 3D 应用里调整好，变换直接烘进坐标本身。

世界到物体矩阵在光线追踪中的一种特殊用法

本课这一部分介绍世界到物体矩阵在光线追踪中一种有趣的用法。在 极简光线追踪器：渲染简单形状（球、立方体、圆盘、平面等） 那门课里，我们学过两种计算光线-球求交的技术：几何法和参数法。两种方法都可以指定所渲染球的球心和半径，但设想一种情况：我们只知道当球半径为 1、球心位于世界坐标系原点时如何做光线-球追踪。那还怎么改变球的大小、旋转和位置？这个问题的解法很简单。如果球的新缩放、位置和旋转由 4x4 变换矩阵定义，那么与其用这个矩阵变换球，我们改为把光线变换到球的物体空间，也就是用球的世界到物体矩阵（球物体到世界矩阵的逆）变换光线的位置和方向。我们不变换球，而是用球的矩阵逆转变换光线。想象你把球沿 Y 平移 2 个单位。那么我们就不去计算光线与平移后球的交点，而是让球留在原点，把光线的位置沿 Y 移动 -2（如图 2 所示）。这种技术在光线追踪里相当常见。有时把形状留在它的物体空间里计算交点更方便。于是与其用物体到世界矩阵变换形状、再用世界空间中的光线测试光线与形状的交点，我们改为把光线变换到形状的物体空间，在物体空间里做光线与几何体的测试。


bool intersect(const Vec3f &orig, const Vec3f &dir, float &t) const 
{ 
    Vec3f origObject, dirObject; 
    worldToObject.multVecMatrix(orig, origObject); 
    worldToObject.multDirMatrix(dir, dirObject); 
    float t0, t1;  //如果光线相交，t 的解 
    // 解析解
    float a = dirObject.dotProduct(dirObject); 
    float b = 2 * dirObject.dotProduct(origObject); 
    float c = origObject.dotProduct(origObject) - 1;  //半径 = 1，半径^2 = 1 
    if (!solveQuadratic(a, b, c, t0, t1)) return false; 
    if (t0 > t1) std::swap(t0, t1); 
 
    if (t0 < 0) { 
        t0 = t1;  //如果 t0 为负，改用 t1 
        if (t0 < 0) return false;  //t0 和 t1 都为负 
    } 
 
    t = t0; 
 
    return true; 
}

这种技术的问题在于，\(t\) 交点距离已经不在世界空间中，而在物体空间中。用这种方法算出的值无法与比如 TriangleMesh 类 intersect() 方法返回的值相比较。要解决这个问题，需要先在物体空间中算出交点，把交点变换到世界空间，再用光线原点与交点的距离在世界空间中算出 \(t\)。如果光线与几何体的求交在物体空间中比在世界空间中高效得多，这些麻烦就都值得。我们的程序里不会实现这种方法。提一下就够了，不过你可以作为练习改写上面的代码试一试。
