计算机图形学编程轻松入门

你有兴趣了解计算机图形学（CG）吗？先问一句：你知道它是什么吗？在下一课里，你会看到计算机图形学的定义，并了解它大致如何运作。你也许听过建模、几何、动画、3D、2D、数字图像、3D 视口、实时渲染、合成这些词。本节的主要目标是把它们的含义讲清楚，更重要的是演示它们之间如何相互关联。这样你就能对制作计算机生成图像（CGI）所涉及的工具与流程有一个整体理解。

我们的世界是三维的。至少我们的感官是这样体验它的；换句话说，你周围的一切都有长、宽、高。显微镜可以把一粒沙子放大，观察它的高度、宽度和深度。有些人还喜欢再加上时间这一维。时间在 CGI 里作用关键，这点我们后面再谈。所以现实世界中的物体是三维的。这是我们都同意、无需证明的事实（好奇的读者可以去看看 Donald Hoffman 的《The Case Against Reality》，那本书挑战了我们对时空与实在的设想）。有意思的是，视觉——我们体验这个三维世界的感官之一——本质上却是一个二维过程。我们也许会说，脑中形成的图像是没有维度的（图像究竟如何在我们大脑中「显现」，我们还没完全搞清楚），但一说到图像，通常指的是一个平坦表面，物体的维度在这个表面上从三维降到了二维（画布或屏幕的表面）。画布上的图像之所以在我们大脑看来是准确的，唯一的原因是物体离你站的地方越远就显得越小，这个效应叫透视缩短。把图像想成一面镜子的反射就好。镜面完全是平的，可我们却分不出「看镜中反射的场景」和「直接看那个场景」有什么不同。

正因为我们有两只眼睛，才能看到立体的东西，这叫作立体视觉。每只眼睛从略微不同的角度看同一个场景，大脑用这两幅图像去估算三维空间中各物体相对彼此的距离与位置。不过立体视觉相当有限，我们无法很准确地测出到物体的距离或物体的大小（计算机可以）。人的视觉很精巧，是演化上了不起的成果，但它是一套很容易被骗的把戏（很多魔术就是靠这个）。在某种意义上，计算机图形学就是一种手段：我们用它造出人造世界的图像，并通过视觉这一媒介把它们当作真实的体验呈现给大脑（我们把这叫作照片级真实），原理和镜面反射完全一样。这个主题在科幻作品里很常见，而技术已经快要让它成真了。

虽然我们看上去更关注生成这些图像的过程——这个过程我们叫作渲染——但计算机图形学不只是做图像，还包括模拟流体运动、软体与刚体运动，以及想办法给物体和虚拟角色做动画，让它们的运动及由此产生的每一个效果都被准确模拟（比如你走路时肌肉形状会变化，你身体的整体外形就是这些肌肉形变的结果）。这些技术你也会在 Scratchapixel 学到。

到目前为止我们学到了什么？世界是三维的，我们观看它的方式是二维的，而只要能复现物体的形状与外观，大脑就分不出「直接看这些物体」和「看这些物体的图像」。计算机图形学并不局限于制作照片级真实的图像。不过，虽然做非真实感图像比做完全照片级真实的图像容易，图形学的目标仍是真实感（既包括事物如何运动，也包括它们看起来如何）。

现在我们要做的，就是学会制作这样一张照片级真实图像的规则，而这正是你在 Scratchapixel 这里要学的。

描述填充虚拟世界的物体

画家描绘一个真实场景（除非画的对象来自他的想象）与我们用计算机造一张图像之间的差别在于：我们必须先把要渲染的场景中那些物体的形状（与外观）描述出来。

我们在学校里学到的最简单也最重要的概念之一，是空间的概念——点可以在其中被定义。点的位置通常由一个原点确定，就像尺子上标着数字零的那一点。用两把互相垂直的尺子，我们就能在二维中定义点的位置。再加第三把与前两把都垂直的尺子，我们就能在三维中确定点的位置。表示点相对于三把尺子中某一把的位置的那些具体数字，叫作这个点的坐标。我们对用坐标来标记自己相对于某个参考点或参考线的位置（比如格林尼治子午线）这件事都很熟悉。现在，我们可以在三维中定义点了。想象你刚买了一台电脑，多半装在一个有八个角的箱子里（恕我直言这么显然的事）。描述这个箱子的一种办法，是量出这 8 个角相对于其中一个角的距离，那个角就充当我们的坐标系原点。这个参考角相对于它自己的距离在每一维上都是 0，而它到另外七个角的距离都不为 0。假设我们的箱子尺寸如下：


corner 1: ( 0, 0,  0)
corner 2: (12, 0,  0)
corner 3: (12, 8,  0)
corner 4: ( 0, 8,  0)
corner 5: ( 0, 0, 10)
corner 6: (12, 0, 10)
corner 7: (12, 8, 10)
corner 8: ( 0, 8, 10)

要用程序定义这个箱子，你可以写一个这样的 C/C++ 程序：


typedef float Point[3];
int main()
{
    Point corners[8] = {
        { 0, 0,  0},
        {12, 0,  0},
        {12, 8,  0},
        { 0, 8,  0},
        { 0, 0, 10},
        {12, 0, 10},
        {12, 8, 10},
        { 0, 8, 10},
    };

    return 0;
}

这个程序演示了在 C/C++ 中定义「点」这个概念的一种方式（第 1 行），以及如何把箱子的各个角存进内存（作为一个含八个点的数组）。

你已经写下了自己的第一个 3D 程序。它还不能生成图像，但你已经能把一个三维物体的描述存进内存了。在计算机图形学中，这些物体的集合叫作场景。场景还包括相机、光源这类概念，这些我们另找时间再谈。如前面所暗示的，要完成整个流程并让它变得有意思，还缺两个关键要素。第一，为了在计算机内存里表示这个箱子，我们最好还需要一套系统，来定义这八个点如何连接、构成箱子的各个面。在 CG 里，这叫作物体的拓扑（也叫模型）。我们会在几何那门课，以及「3D 渲染入门」部分（讲三角形与多边形网格渲染的那一课）里讨论它。拓扑指的是点——我们叫顶点——如何连接成面（也就是平面），面也叫多边形。这个箱子会由六个面或多边形组成，构成我们所说的多边形网格。我们还需要的第二样东西，是一套为这个箱子生成图像的系统，它要把箱子的各个角投影到一块想象中的画布上，这个过程叫作透视投影。

为这个虚拟世界生成图像

把一个 3D 点投影到画布表面上，要用到一个特定的矩阵，叫透视矩阵（不知道矩阵是什么也不必担心）。用这个矩阵来投影点是可选的，但它能大大简化过程。不过，你不必懂数学和矩阵也能明白它是怎么工作的。你可以把一幅图像或一块画布想成放在眼睛前方的一块平面。从眼睛出发，向画布的四个角各画一条线，共四条，再把这些线向世界深处延长（一直延到你能看见的地方）。你就得到一个金字塔，我们把它叫作视锥体。视锥体在 3D 空间中定义了一个体积，画布则是垂直视线切下这个体积的一个平面。把你的箱子放到画布前面。接着，从箱子的每个角向眼睛画一条线，在线与画布相交的地方点一个点。找出画布上对应于箱子十二条棱的各个点，再在这些点之间连线。你看到了什么？箱子的图像。

用来量取箱子各角坐标的那三把尺子，构成了我们所说的坐标系。它是一套可以在其中量度点的系统。所有点的坐标都相对于这个坐标系。注意坐标可以是正、负或零，取决于它位于尺子原点（数值 0）的右侧还是左侧。在 CG 中，这个坐标系常被称为世界坐标系，而点 (0,0,0) 就是原点。

我们把视锥体的顶点移到原点，并让视线（观察方向）沿 z 轴负方向（图 1）。许多图形应用都把这种配置当作默认的「观察系统」。记住，金字塔的顶点就是我们看场景的那一点。我们再把画布移到离原点一个单位远的地方。最后，把箱子移到离原点一段距离处，使它完全落在视锥体的体积内。因为箱子换了位置（是我们移动了它），它八个角的坐标也变了，需要重新量。注意，因为箱子位于量取物体深度所用尺子原点的左侧，所有深度坐标（也叫 z 坐标）都会是负的。有四个角在量取物体高度所用参考点之下，它们的高度即 y 坐标是负的。最后，有四个角在量取物体宽度所用尺子原点的左侧，它们的宽度即 x 坐标也会是负的。箱子各角的新坐标是：


corner 1: ( 1, -1, -5)
corner 2: ( 1, -1, -3)
corner 3: ( 1,  1, -5)
corner 4: ( 1,  1, -3)
corner 5: (-1, -1, -5)
corner 6: (-1, -1, -3)
corner 7: (-1,  1, -5)
corner 8: (-1,  1, -3)

我们从侧面看这套设置，从其中一个角向原点（视点）画一条线。我们可以定义两个三角形：ABC 与 AB'C'。如你所见，这两个三角形共享同一个原点（A）。在某种意义上它们也是彼此的副本：边 AB 与 AC 形成的角，和边 AB' 与 AC' 形成的角相同。这样的三角形在数学中称为相似三角形。相似三角形有一条有趣的性质：它们的邻边与对边之比相同。换句话说：

$$ \frac{BC}{AB} = \frac{B'C'}{AB'}. $$

因为画布位于离原点 1 个单位处，我们知道 AB' 等于 1。我们也知道 B 与 C 的位置，它们分别是该角的 z 坐标（深度）与 y 坐标（高度）。把这些值代入上面的公式，得到：

$$ \frac{P.y}{P.z} = \frac{P'.y}{1}. $$

其中 P'.y 是从该角到视点的那条线与画布交点的 y 坐标，也就是前面说过的、可以据此在画布上画出箱子图像的那个点。因此：

$$ P'.y = \frac{P.y}{P.z}. $$

可以看到，该角的 y 坐标在画布上的投影，就是这个角的 y 坐标除以它的深度（z 坐标）。这个关系是计算机图形学中最基本的几个关系之一，叫作 z 除法或透视除法。同样的原理也适用于 x 坐标。投影点的 x 坐标（x'）就是该角的 x 坐标除以它的 z 坐标。

不过，在我们的例子里 P 的 z 坐标是负的（为什么总是如此，我们会在「3D 渲染基础」部分专门讲透视投影矩阵的那一课里解释），所以当 x 坐标为正时，投影点的 x 坐标会变成负的（同样，如果 P.x 为负，P'.x 就会变正。y 坐标也是同样的情形）。结果是三维物体的图像在垂直和水平两个方向都被镜像了，这不是我们想要的效果。为了绕开这个问题，我们改成用 -P.z 去除 P.x 和 P.y，从而保持 x 与 y 坐标的符号。最终得到：

$$ \begin{array}{l} P'.x = \frac{P.x}{-P.z} \\ P'.y = \frac{P.y}{-P.z}. \end{array} $$

现在我们有了一个方法，可以算出各角在画布表面上实际出现的位置，也就是投影到画布上的那些点的二维坐标。我们来更新基础程序，把这些坐标算出来：


typedef float Point[3];
int main()
{
    Point corners[8] = {
         { 1, -1, -5},
         { 1, -1, -3},
         { 1,  1, -5},
         { 1,  1, -3},
         {-1, -1, -5},
         {-1, -1, -3},
         {-1,  1, -5},
         {-1,  1, -3}
    };

    for (int i = 0; i < 8; ++i) {
        // 把 x 与 y 坐标除以 z 坐标，
        // 以此把点投影到画布上
        float x_proj = corners[i][0] / -corners[i][2];
        float y_proj = corners[i][1] / -corners[i][2];
        printf("Projected corner %d: x:%f, y:%f\n", i, x_proj, y_proj);
    }

    return 0;
}

画布本身的尺寸也是任意的。它可以是正方形，也可以是长方形。在我们的例子里，两个方向都做成了 2 个单位宽，这意味着落在画布上的任何点的 x 与 y 坐标都落在 -1 到 1 的范围内（图 6）。

问题：如果某个投影点的坐标不在这个范围内，比如说 x' 等于 -1.1，会怎样？

这个点不可见；它落在画布的边界之外。

到这里，我们说投影点的坐标位于屏幕空间（屏幕的空间，在这个语境下屏幕与画布是同义的）。但它们不方便直接操作，因为它们可正可负，而且我们还需要弄清它们是相对于什么——比如相对于你电脑屏幕的尺寸（如果我们要把这些点显示在屏幕上的话）。因此，我们先对它们做归一化，也就是把它们从原来的取值范围转换到 [0,1]。在我们的例子里，要把 -1 到 1 的坐标映射到 0 到 1，可以写成：


float x_proj_remap = (1 + x_proj) / 2;
float y_proj_remap = (1 + y_proj) / 2;

投影点的坐标现在落在 0 到 1 的范围内。这样的坐标被认为定义在 NDC 空间，NDC 是归一化设备坐标的缩写。这很方便，因为不管画布（或屏幕）原来的尺寸是多少——它会随你用的设置变化——我们现在所有的点坐标都定义在一个共同的空间里。归一化这个词到处都在用，它指的是把数值从原来任意的取值范围重新映射到 [0,1]。最后，我们通常用最终图像的尺寸来定义点坐标，而众所周知，图像尺寸是用像素表示的。数字图像不过是一个二维的像素数组（你的电脑屏幕也是）。

一张 512x512 的图像，是一个有 512 行、每行 512 个像素的数字图像；或者如果你愿意，也可以说是 512 列、每列 512 个垂直排列的像素。既然我们的坐标已经归一化，要用像素表示它们，只需把这些 NDC 坐标乘以图像尺寸（512）。这里我们的画布是正方形，所以也用正方形图像：


#include &ltcstdlib> 
#include &ltcstdio> 

typedef float Point[3];

int main()
{
    Point corners[8] = {
         { 1, -1, -5},
         { 1, -1, -3},
         { 1,  1, -5},
         { 1,  1, -3},
         {-1, -1, -5},
         {-1, -1, -3},
         {-1,  1, -5},
         {-1,  1, -3}
    };

    const unsigned int image_width = 512, image_height = 512;

    for (int i = 0; i < 8; ++i) {
        // 把 x 与 y 坐标除以 z 坐标，
        // 以此把点投影到画布上
        float x_proj = corners[i][0] / -corners[i][2];
        float y_proj = corners[i][1] / -corners[i][2];
        float x_proj_remap = (1 + x_proj) / 2;
        float y_proj_remap = (1 + y_proj) / 2;
        float x_proj_pix = x_proj_remap * image_width;
        float y_proj_pix = y_proj_remap * image_height;
        printf("Corner: %d x:%f y:%f\n", i, x_proj_pix, y_proj_pix);
    }

    return 0;
}

得到的坐标被认为位于光栅空间。「光栅」指的就是我们熟知的那张图像本身——一个 2D 像素网格。这个网格可以看成一个坐标系，原点位于图像左上角，坐标为 (0,0)。反过来说，图像右下角的坐标是 (width, height)，度量单位是像素。我们的程序仍然有限，因为它还没有真正生成箱子的图像；但如果你用下面这些命令编译并运行它（把代码复制粘贴到一个文件里，存为 box.cpp）：


c++ box.cpp -o box
./box

你会得到：


Corner: 0 x:307.200012 y:204.800003
Corner: 1 x:341.333344 y:170.666656
Corner: 2 x:307.200012 y:307.200012
Corner: 3 x:341.333344 y:341.333344
Corner: 4 x:204.800003 y:204.800003
Corner: 5 x:170.666656 y:170.666656
Corner: 6 x:204.800003 y:307.200012
Corner: 7 x:170.666656 y:341.333344

你可以用画图软件新建一张图像（尺寸设为 512x512），在程序算出的那些像素坐标上点出点来。然后把这些点连起来，构成箱子的棱，你就得到一张真正的箱子图像（如下面的视频所示）。像素坐标是整数，所以你需要把程序给出的数字取整。

如果你在想图像不是正方形时会怎样，你其实稍稍跑到前面去了，这是我们在后面几课才要介绍的内容。这门课真正想让你看到的是：能在一个平面（这里是正方形图像）表面上复现一个物体（这里是立方体）的形状，其实相当简单。专业应用并不用这么简陋的做法，但它们底层的数学是一样的。毕竟在数学里，达成某个结果并没有一百种办法。一般来说我们会用所谓的投影矩阵，这个后面再讲；投影矩阵确实会把图像的宽高比——也就是图像宽与高之比——考虑进去。如果这个比值不是 1（图像不是正方形），矩阵会妥善处理，使结果符合预期。

不过我们明白，若不在这里至少简短地回答你的问题，你的好奇心是放不下的。其实让这个程序支持非正方形图像相当简单。有两种做法。第一种，先像前面说的那样算出图像的宽高比：宽除以高（这里假定宽大于高），然后把投影点的 x 坐标除以这个宽高比，或者把投影后的 y 坐标乘以这个宽高比。这两种做法得到的图像并不相同。虽然两种情况下立方体都会被正确投影到图像表面上，但第二种做法里立方体会显得更大，如下图所示。图中白色区域代表原来的正方形图像，灰色区域代表非正方形图像。如左图所示，正方形图像的上下边缘贴住非正方形图像的上下边缘。右图这第二种情况里，正方形图像的左右边缘分别贴住非正方形图像的左右边缘，于是里面的立方体看起来更大。

原因在针孔相机模型：针孔相机如何工作（第 2 部分）这一课里有详细解释。简言之，你可以把原来的正方形图像在非正方形图像里按水平方向贴合（选项 1：正方形图像的上下贴住非正方形图像的上下），也可以按垂直方向贴合（选项 2：正方形图像的左右贴住非正方形图像的左右）。

下面是选项 2 的代码：


// clang++ projpoints.cc
#include &ltcstdlib>
#include &ltcstdio>
#include &ltcstdint>

typedef float Point[3];

int main()
{
    Point corners[8] = {
         { 1, -1, -5},
         { 1, -1, -3},
         { 1,  1, -5},
         { 1,  1, -3},
         {-1, -1, -5},
         {-1, -1, -3},
         {-1,  1, -5},
         {-1,  1, -3}
    };

    uint32_t image_width = 640;
    uint32_t image_height = 480;
    float aspect_ratio = image_width / static_cast&ltfloat>(image_height);

    for (int i = 0; i < 8; ++i) {
        // 把 x 与 y 坐标除以 z 坐标
        // 以此把点投影到画布上
        float x_proj = corners[i][0] / -corners[i][2]; // 选项 1：除以 aspect_ratio
        float y_proj = corners[i][1] / -corners[i][2] * aspect_ratio; // 选项 2
        float x_proj_remap = (1 + x_proj) / 2;
        float y_proj_remap = (1 + y_proj) / 2;
        float x_proj_pix = x_proj_remap * image_width;
        float y_proj_pix = y_proj_remap * image_height;
        printf("Corner: %d x:%f y:%f\n", i, x_proj_pix, y_proj_pix);
    }

    return 0;
}

我们学到了什么？

  • 在能生成 3D 场景（场景是物体的集合）的图像之前，我们首先得用顶点和拓扑（关于这些顶点如何连接成多边形或面的信息）这类要素来描述三维物体。

  • 渲染是生成 3D 场景图像的过程。不管你用什么技术来做 3D 模型（这样的技术相当多），渲染都是「看见」任何 3D 虚拟世界所必需的一步。

  • 从这个简单的练习可以明显看出，要用计算机生成图像，数学（比编程更是）至关重要。计算机只是加快运算的工具，而生成这张图像所用的原理根植于纯数学。几何在这个过程中扮演核心角色，尤其是在处理物体变换（缩放、旋转、平移）以及为诸如计算两条线之间的夹角、求一条线与其他简单形状（平面、球体等）的交点这类问题提供解法时。

  • 总之，计算机图形学主要是把数学应用到一个计算机程序里，让这个程序尽可能快地（并以计算机能达到的精度）生成一张图像（无论是否照片级真实）。

  • 建模涵盖创建 3D 模型所用的全部技术。建模技术会在「几何/建模」部分讨论。

  • 静态模型对某些应用来说够用了，但也完全可以随时间给它们做动画。这意味着每个时间步都需要渲染一张该模型的图像（你可以在相邻两张图像之间，通过给各角坐标做动画或给模型施加变换矩阵，把箱子稍微平移、旋转或缩放）。更高级的动画技术能模拟骨骼与肌肉造成的皮肤形变。不过所有这些技术都有一个共同点：几何（构成模型的面）随时间被形变。所以如引言所说，时间在 CGI 里也是一个关键因素。想了解更多，去看「动画」部分。

  • 有一个特别的领域同时横跨动画与建模。它涵盖以真实方式模拟物体运动的所有技术。计算机图形学中很大一片领域专门用来模拟流体（水、火、烟）、布料、头发等的运动。物理定律被施加到 3D 模型上，让它们像在现实世界里那样运动、变形或破碎。物理模拟一般计算量很大，但也可以实时运行（取决于你模拟的场景复杂度）。

  • 渲染同样是一项计算密集的任务。复杂度取决于场景中几何量的多少，以及你想让最终图像有多照片级真实。在渲染中，我们区分两种模式：离线与实时渲染。实时渲染用在电子游戏里（而且是必须的），3D 场景的内容至少要跑到每秒 30 帧（每秒 60 帧一般被视为标准）。GPU 就是专门为尽快渲染 3D 场景而设计的处理器。离线渲染常用于电影 CGI 制作，那里不需要实时（图像先算好并存起来，再以 24、30 或 60 fps 播放）。一张图像算完可能要几秒到几小时。但它能处理多得多的几何量，产出的图像质量也高于实时渲染。不过，实时与离线渲染之间的界线正越来越模糊：电子游戏不断推高它们能处理的几何量和质量，离线渲染器也在努力利用 CPU 技术的最新进展来大幅提升性能。

确实，我们/你学到了不少！

我该从哪里开始？

希望这个简单的箱子例子已经勾起了你的兴趣，但这段引言的主要目的，是凸显几何在计算机图形学中的重要性。确实，事情并不只是几何，但这个领域里大量问题都能用几何原理有效解决。多数计算机图形学教材都以一章几何开篇，这多少有点让人望而生畏，因为在能用代码真正做出东西之前，得先学很多。尽管如此，我们强烈建议你先读几何那一课。在那里我们会讨论并学习点、向量和法线。我们会探索坐标系，更关键的是矩阵。矩阵对于管理旋转、缩放和/或平移至关重要；本质上，就是处理变换。这些概念在所有图形学文献里反复出现，所以尽早掌握它们十分必要。

很多图形学教材对几何的引入都写得乏善可陈，要么假定读者已有基础，要么指望读者去看更专门的教材。我们的几何课不同：它对几何概念给出全面、深入且直观的解释。它不仅说明这些概念如何起作用，还深入讲清它们为什么能起作用。我们这一课与众不同之处，在于它直接贴合你日常的图形学编程工作。

现在花时间把这些基础概念掌握牢，你会发现我们这一课比许多书讲得更全面。我们的做法正好补上了我们自己读早期 CG 教材时遇到的空缺。这份基础理解，会随着你往后学而变得极其宝贵。这些概念你会反复遇到，从一开始就扎实掌握，会让你的学习过程顺畅许多。说到底，这份先见之明会让你日后更容易吸收更进阶的内容。
