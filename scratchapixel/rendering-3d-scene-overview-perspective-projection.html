透视投影

阅读时间：9 分钟。

上一章我们说过，渲染过程可以看作两步：

  • 把三维形状投影到画布表面上，并确定这些表面中哪些部分从给定视点可见。

  • 模拟光在空间中传播的方式；再结合对光如何与构成物体的材质相互作用的描述，就决定了这些物体最终的外观（颜色、亮度、纹理等等）。

本章我们只专注于第一步，更详细地解释这两个问题（把物体的形状投影到画布表面上、以及可见性问题）各自通常是怎么解决的。解法可能有很多，我们只探讨最常见的那几种。这里只是一个概览。每种方法都会在单独的课程里研究，并给出这些算法的实现（放在一个自包含的 C++ 程序里）。

从 3D 到 2D：投影矩阵

图像本质上就是三维场景在一个平面上的表示：画布或屏幕的表面。如上一章所述，要生成一幅在我们大脑看来真实的图像，就需要模拟世界的图像在我们的眼睛中是如何形成的。原理相当直接。我们只需从物体的各个角向眼睛延长直线，找出这些线与一个垂直于视线的平面的交点。把这些点连起来画出物体的棱，就得到场景的线框表示。

值得注意的是，这种构建图像的方法，某种意义上完全是一种把三维世界压平到二维表面上的任意做法。刚才描述的技术在绘画中称为单点透视投影，这也是 CG 中普遍采用的做法，因为它模仿了眼睛与相机的运作方式（相机本就是为生成与眼睛所成图像相似的画面而设计的）。不过在艺术世界里，创造力没有限制。例如，你可以创作多点透视（两点、三点、四点等）的图像。

这类投影的一个关键视觉特征是：物体离眼睛越远，看起来就越小（盒子的后侧棱比前侧棱显得小）。这种效果称为透视缩短。

关于这类投影，有两点值得注意。第一，眼睛位于画布的中心，也就是说视线总是穿过图像的中部（图 2）。同样关键的是要理解我们可以改变画布的大小。借助视锥体来说明，这个变化就更好理解了（图 3）。视锥体是从画布每个角向眼睛画线、并把这些线继续延伸进场景所构成的棱锥。它也叫观察视锥体或观察体。显然，只有处在这个棱锥体积内的物体才对相机可见。调整画布大小可以扩大或减小这个体积。体积越大，我们捕捉到的场景就越多。这一效果类似于改变摄影镜头的焦距。换个说法：改变画布大小就是改变视场角。

当画布缩小到无限小时会出现一个有趣的现象：构成视锥体的各条线变得平行（垂直于画布）。这在物理上不可能，但在计算的虚拟世界里是可行的。在这种情况下，得到的就是所谓的正交投影。值得注意的是，正交投影是透视投影的一种，只是画布大小实际上为零。这有效地消除了透视缩短效应，使物体各条棱投影到屏幕上时尺寸保持不变。

从几何上看，确定这些线与屏幕的交点非常直接。观察旁边的图（其中 P 是要投影到画布上的点，P' 是它的投影点），显然角 \\(\\angle ABC\\) 与 \\(\\angle AB'C'\\) 相等。这里 A 代表眼睛，AB 是到点 P 的沿 z 轴距离（P 的 z 坐标），BC 是到点 P 的沿 y 轴距离（P 的 y 坐标）。B'C' 表示 P' 的 y 坐标，AB' 表示 P' 的 z 坐标（也就是眼睛到画布的距离）。两个三角形若共有一个角，就称为相似。相似三角形有一个有趣的性质：对应边长度之比保持不变。应用这条原理，可以写出：

$${ BC \over AB } = { B'C' \over AB' }$$

假定画布位于离眼睛一个单位处（为简单起见，AB' 等于 1），并把 AB、BC、AB'、B'C' 换成各自的坐标，就得到：

$${ BC \over AB } = { B'C' \over 1 } \rightarrow P'.y = { P.y \over P.z }.$$

本质上，要确定投影点的 y 坐标，只需把该点的 y 坐标除以它的 z 坐标。同理，要确定 P' 的 x 坐标：

$$P'.x = { P.x \over P.z }.$$

这个关系称为透视除法或 z 除法，是计算机图形学的基础。如果你被困在荒岛上，只准记住一条计算机图形学原理，那大概就是这条公式。

在计算机图形学中，这个运算通常用一个所谓的透视投影矩阵来完成。这个矩阵作用在点上时，会把它们投影到屏幕上。下一课我们会深入这个矩阵的运作方式，解释它的机制以及如何构造和使用它。

不过，是否需要透视投影，取决于解决可见性问题所用的技术。正如我们会在本章第二部分看到的，处理可见性问题的算法分为两大类：

  • 光栅化

  • 光线追踪

第一类算法依靠把 \(P\) 投影到屏幕上来算出 \(P'\)。因此这类算法需要透视投影矩阵。在光线追踪中，我们不把几何体投影到屏幕上，而是追踪一条穿过 \(P'\) 的光线，去寻找 \(P\)。用这种办法不必投影 \(P\)，因为 \(P'\) 已知；所以严格说来，光线追踪并不需要透视投影（因此也从不用它）。

这两种算法我们会在接下来的章节和课程里详细研究。但现在就理解它们的区别以及各自如何工作是重要的。如前所述，要把几何体投影到画布表面，就是让 \(P\) 沿一条「隐式」直线（说隐式，是因为像在光线追踪里那样，我们其实从不需要真正构造这条线）投影，这条线连接 \(P\) 与眼睛。你可以把这个过程想象成让一个点沿那条线从 \(P\) 移向眼睛，直到它落在画布上。这个点就是 \(P'\)。在这种做法里，你知道 \(P\)，而 \(P'\) 未知，它由投影方法算出来。反过来，你也可以从另一个角度看这个问题。对画布上的任意一点（比如 \(P'\)——默认我们会假定它位于像素中心），几何体表面上可能存在一个点 \(P\) 投影到 \(P'\) 上。这个问题的解法是显式地从眼睛向 \(P'\) 构造一条光线，把这条光线延伸或投影进场景，再判断它是否与任何三维几何体相交。若发生相交，交点就是 \(P\)。这番解释应该有助于弄清光栅化（已知 \(P\)，算出 \(P'\)）与光线追踪（已知 \(P'\)，寻找 \(P\)）之间的区别。

光栅化相对于光线追踪的优势主要在于速度。计算光线与几何体的交点是计算量很大的操作。这个求交时间还会随场景中几何体数量线性增长，我们会在后续一课中讨论。反过来，投影过程极其直接，只基于基本数学运算（乘法、除法等），可以大幅优化（尤其在 GPU 这类专用硬件上）。显卡主要使用基于光栅化思路的算法（这也是它们能如此快速地以交互帧率渲染三维场景的原因之一）。使用 OpenGL 或 DirectX 这类实时渲染 API 时，就必须处理投影矩阵。即便你只对光线追踪感兴趣，理解投影矩阵也是有价值的，出于历史原因：它是渲染中的一项关键技术，也是生成实时三维计算机图形最常见的方法。此外，你很可能要与 GPU 和实时渲染 API 打交道，而它们不会替你算这个矩阵，所以你得自己算。

光栅化的概念在渲染中至关重要。正如本章所学，把 \(P\) 投影到屏幕上，就是把该点的 \(x\) 和 \(y\) 坐标除以它的 \(z\) 坐标。一开始所有坐标都是实数——比如浮点数——也就是说 \(P'\) 坐标也是实数。但像素坐标必须是整数。因此，要把 \(P'\) 的颜色存进图像，就得把它的坐标转换成像素坐标——从浮点数变成整数。这个过程叫作把点的坐标从屏幕空间转换到光栅空间。关于这一过程的更多信息，会在讲光线与相机的课程里给出。
