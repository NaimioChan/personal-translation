色彩空间

阅读时间：30 分钟。

请记住，本课程只是颜色主题的入门。它提供的信息足以让读者理解计算机图形学中用来表示与操作颜色的主要概念和技术（至少足够渲染图像）。本课程的目标并不是罗列一份穷尽所有色彩空间的清单。

在本课程的第一章里，我们介绍了与光和颜色有关的最重要的概念。一个物体的颜色或一盏灯的颜色，可以看作可见光谱中许多不同光色混合在一起的结果。某一束光由哪些光色构成，用它的 光谱功率分布 来描述。这种表示方式的问题在于，人眼无法直接感知 SPD。上一章我们还讲过，眼睛基于三色视觉系统，也讲过我们在正常照明环境下和在昏暗照明条件下感知颜色的方式并不相同。因此，要表示颜色，我们需要把 SPD 转换成另一种更适合三色视觉的表示。这类表示我们称为 色模型 或 色彩空间（读完本章你会明白为什么）。色模型有很多，但本课程只介绍 CIE XYZ 色模型——它是所有色模型的基础——以及 RGB 模型——计算机图形学中广受欢迎的模型。简短地说，你可以把色模型看作一种把 SPD 的数值映射到三个数值（三刺激值）的技术，这三个数值能更直接地对应我们眼睛感知颜色的方式。

阅读本章时要牢记一个区分：颜色的概念与颜色的明度或亮度并不是一回事。一种颜色「是什么颜色」（姑且这么说）称为色相。它有时也被称为 色度，用来在与明度无关的前提下定义一种颜色的品质。

什么是色彩空间？

色彩空间是一种模型，用来表示我们的视觉系统所能感知的尽可能多的颜色（不过大多数情况下，它们只能表示其中的一个子集）。我们说「颜色」时，通常指的是人类视觉系统能感知的颜色（这正是 XYZ 色模型的主要优势：它力求贴合人类视觉系统对颜色的响应），以及可见光谱中所有光色的各种可能组合所能得到的颜色（记住人类视觉系统是感知性的）。某一特定系统所能表示的可能颜色的范围称为 色域。色彩空间在最简单的形式上，可以看作加色系统中三种原色（红、绿、蓝）的组合。把这些颜色彼此相加，能产生范围很广的颜色（这是 RGB 色模型的基础）。例如 CIE xyY 色彩空间 的色域呈马蹄形，如图 1 所示（颜色是在 CIE xyY 色彩空间中绘制的，其中 xy 表示颜色的色度。这个模型后面会详述）。这个形状随所用的色彩空间而不同。注意色域上某处有一块特定区域，颜色在那里汇聚成白色的印象。这称为色域的 白点。自然，我们真正关心的是人眼能感知的颜色。任何无法表示我们所能看到的全部颜色的色彩空间，都比能表示所有可感知颜色的系统更受限、更狭窄。事实上，现存的大多数色彩空间模型在覆盖完整色域的能力上都是有限的。可是什么才算完整色域？那是一种能表示人眼所能感知的全部颜色的色域。技术上，这个色域称为 人类视觉的色域，而 XYZ 色彩空间模型正是抱着这个特定目标设计的。你可能还想问，它为什么叫「空间」。表示颜色至少需要三个变量（XYZ、RGB、HSV 等），就像表示 3D 点一样，而这些变量在其定义范围内所能取的全部值可以画在 3D 空间里，构成一个体积或空间（等我们讲到 RGB 色模型时，这会更容易理解）。

CIE XYZ 与 xyY 色模型

尽管并不准确，我们可以先假设：眼睛里负责色觉的三种主要视锥细胞，分别对蓝光（S（短）视锥）、绿光（M（中）视锥）和红光（L（长）视锥）敏感（说不准确，是因为近期的测量表明 L 视锥的敏感峰值更偏向黄色而非红色。S 和 M 视锥本身也并不完美地落在蓝色和绿色上，如图 2 所示。同样要记住，视锥的分布因而这些曲线因人而异。不过正是这个简化，促使 CIE 在 1930 年代初做了一个实验，其出发点是这样的想法：任何颜色（在加色模型中）都可以用眼睛中各类视锥所敏感的红色、绿色和蓝色光的组合来表示。实验的做法是请大量的人，用不同分量的纯红、纯绿、纯蓝光，重新调出展示在他们面前的屏幕上的颜色。由于视锥细胞主要集中在视网膜中央，他们的视野被限制在 2 度的角度内，以免对颜色的感知受到视杆细胞的干扰——如上一章所述，视杆细胞帮助我们在低照度条件下看清东西，但没有色感。

做这个实验时他们还发现，有些颜色可以用红、绿、蓝原光的不同组合得到。这称为 同色异谱。

根据实验结果，他们绘出了表示可见光谱中每一种颜色所需的红、绿、蓝原光的分量。实验结果给出三条曲线，称为 CIE 标准观察者色匹配函数（文献中也称 CIE 1931 2° 标准观察者）：

有一点值得注意：绿色那条曲线奇怪地与光度函数相吻合，如上一章所述，光度函数代表人眼对亮度的敏感度。我们从一条明知看不见的光谱出发，现在又多了三条曲线。这怎么可能让事情变简单？有了这些曲线，我们现在就能用下面的公式把光谱转换成三个值，称为 X、Y、Z：

$$\begin{array}{l} X={\dfrac{1}{\int Y(\lambda)d \lambda}} \int_\lambda S_e(\lambda) \bar{X}(\lambda) d \lambda \\ Y={\dfrac{1}{\int Y(\lambda)d \lambda}} \int_\lambda S_e(\lambda) \bar{Y}(\lambda) d \lambda \\ Z={\dfrac{1}{\int Y(\lambda)d \lambda}} \int_\lambda S_e(\lambda) \bar{Z}(\lambda) d \lambda \\ \end{array}$$

其中 \(S_e(\lambda)\) 表示发射光谱（来自光源或来自材质），在辐射度量学中称为 光谱强度。

符号 \(\int\) 表示数学中的积分。如果你不知道积分是什么，请看「计算机图形学的数学与物理」部分中的 「着色数学」 一章。

通常光谱和色匹配函数都是离散的（由一串采样定义）；它们并不表示成定义连续曲线的函数，而是一系列离散的采样或点，我们可以把这些点「连」起来构成曲线。如果色匹配函数数据和光谱数据覆盖相同的波长范围（例如 380 到 780），并且点数相同（从 380 nm 起每 5 nm 一个采样，到 780 nm 结束，共 81 个采样），那么我们就能用下面的代码计算 XYZ（本章后面会解释这段代码）：


void SpectrumToXYZ(int colorIndex, float XYZ[]) 
{ 
    float Ysum = 0; 
    for (int i = 0; i < 81; ++i) { 
        XYZ[0] += colorMatchingFunc[i][0] * spectralData[colorIndex][i]; 
        XYZ[1] += colorMatchingFunc[i][1] * spectralData[colorIndex][i]; 
        XYZ[2] += colorMatchingFunc[i][2] * spectralData[colorIndex][i]; 
        Ysum += colorMatchingFunc[i][1]; 
    } 
    XYZ[0] *= 1 / Ysum; 
    XYZ[1] *= 1 / Ysum; 
    XYZ[2] *= 1 / Ysum; 
}

在这个例子中，光谱数据从 350 到 750 nm，每 5 nm 采样一次，不过你也可以用更精确的数据（每 1 nm 一个采样）或更粗的数据（每 10 nm 一个采样），并把范围也缩小（例如 400 到 750）。材质或光源的光谱数据很难找，所以这个选择更多是在让代码去适应手头有什么数据。用更少的数据意味着算 XYZ 更快，用更多的数据意味着结果更精确（但计算时间也更长）。现在你更能理解为什么光谱渲染器通常比使用更基础的 RGB 色彩系统的渲染器慢。

可是这三个值凭什么比光谱本身更有意义？就其本身而言，它们确实没什么用，因为 XYZ 颜色无法直接在计算机屏幕上显示。要显示 XYZ 颜色，必须先把它转换成 RGB 颜色，用的就是马上要讲的技术。XYZ 色彩空间的主要优势在于，在表示我们所能看到的全部颜色这件事上，它是现存所有系统里最好的。在所有现存的色彩空间中，它是最能完整表示人类视觉可感知的全部颜色的模型（换句话说，其他色彩空间的色域通常更小，或被包含在 XYZ 色彩空间的色域之内）。因此它大概是存储颜色信息的最佳系统，至今仍被视为黄金标准。在学习如何把 XYZ 颜色转换成 RGB 颜色之前，我们先介绍 RGB 色彩空间。不过在结束本课程这一部分之前，先说说 X、Y、Z 这三个值本身的意义。事实上，正如我们已提到的，Y 色匹配函数与光度函数非常接近。因此有些人喜欢把 XYZ 三元组中的 Y 值看作表示一种颜色的亮度。XYZ 颜色的各个值并不能真的直接当作 RGB 值使用，但它们当然也能指示一种颜色里红、绿、蓝各占多少。

要对一个光源的光谱数据做积分（对材质也是一样的做法），我们需要把光谱中的全部数据相加，再乘以两个相邻采样之间的距离。得到的数值定义了光源的功率（可以用焦耳或瓦特表示）。这个概念很重要，因为很多渲染器并不直接处理光谱数据，而是依赖用户指定光源的功率或强度。能计算这个功率，有助于我们用有物理意义的数据来设定光源（注意，从这个光谱我们也能算出一个 XYZ 值，再把它转换成 RGB）。数学上，这个积分写成下面的形式：$Power = \Phi_e = \int_{\lambda_0}^{\lambda_1} S_e(\lambda) d\lambda$ 其中 \(S_e(\lambda)\) 是光源的发射光谱，在辐射度量学中也称为光的 光谱强度。

xyY 色彩空间

xyY 色彩空间由 XYZ 派生而来，我们只简要提一下，因为它被用来绘制色彩空间色域的图像，如图 1。前面说过，把色度的概念（定义一种颜色有多鲜艳）与颜色亮度的概念区分开很重要。一个典型的例子是白色：它的色度与某种灰色相同，但亮度与白色并不相同。xyY 色彩空间正是为了能把这两个属性分开而提出的：只用两个分量（x 和 y）编码颜色的色度，并保留 XYZ 三刺激值中的 Y 值来编码颜色的亮度或明度。思路很简单，就是把 XYZ 颜色的三个分量用这三个分量之和归一化：

$$ \begin{array}{l} x = {\dfrac{X}{X + Y + Z}}\\ y = {\dfrac{Y}{X + Y + Z}}\\ z = {\dfrac{Z}{X + Y + Z}}\\ \end{array} $$

归一化之后，得到的 x、y、z 三个分量的值之和为 1。因此，只要知道其中两个分量的值，就能求出第三个。例如对 z 可以写：\(z = 1 - x - y\)。这实际上意味着只用两个分量就能定义一种颜色的色度。在 xyY 色彩空间中，这两个分量就是上面刚算出的归一化值 x 和 y（我们丢弃 z 值，必要时可以用 x 和 y 按刚才所示的方法重算）。最后，因为跟踪原颜色的亮度很重要，我们会把 XYZ 颜色中原有的 Y 值与 x、y 值存在一起。如前所述，在 XYZ 色彩空间中 Y 代表颜色的亮度。在 xyY 色彩空间中，xy 值可以看作颜色色度的表示，而 Y 值可以看作颜色强度或亮度值的表示。由于现在只用两个坐标来定义，色域中的颜色就能画在二维坐标系里，如图 1 所示。其他色彩空间，比如接下来要讲的 RGB 色彩空间，其原色（红、绿、蓝）以及白点都是相对那个 xy「色度」坐标系定义的。

问题：马蹄形是怎么画出来的？可见光谱 380 到 700 范围内的每一种颜色，都用色匹配函数转换成 XYZ 颜色。这些颜色可以画在三维笛卡尔坐标系中，如上面的图（左）所示。然后我们可以画一个三角形，其顶点经过 z=(0,1,0)、x=(1,0,0) 和 y=(0,0,1)。接下来的思路是把 XYZ 颜色投影到这个三角形所定义的平面上（这正是我们把一个 XYZ 颜色转换到 xyY 色彩空间时所做的），再改变观察角度，让三角形从侧面看过去（在这个视角下，三角形可以看作一个二维笛卡尔坐标系，y 轴朝上，x 轴朝右）。

RGB 色彩空间

RGB 色彩空间的思路就是紧贴人类视觉的原理，把颜色表示成三种原色（红、绿、蓝）任意份量（0 到 1）的简单相加。因此它可以表示成一个简简单单的立方体（图 4），其中三个顶点代表三种原色。沿这个立方体的顶点方向移动，就是把两种原色混合在一起；当我们到达与这两种原色相对的那个立方体顶点时，得到的就是次生色（青、品红或黄之一）。立方体有两个顶点很特殊，分别对应白色（三种原色以全量混合）和黑色（三种原色全都没有）。这两个顶点连成一条对角线，这条线上的颜色全是灰色（灰阶）。这里要注意，我们谈颜色时指的是它们的色度，而不是它们可能的亮度或明度。

RGB 色彩空间是现存最基本的色彩空间之一，这大概也是它流行的原因之一。它也易于理解和可视化（就像立方体的例子）。但它的色域比 XYZ 色彩空间的色域小得多，如图 5 所示。它可以表示成一个包含在 XYZ 色域马蹄形内的三角形，三角形的每个顶点代表一种原色，这些原色是相对 XYZ 色彩空间表达的（更准确地说，这些坐标是在我们前面用来绘制马蹄形 XYZ 色域的那个 xyY 色彩空间中表达的）。RGB 三色红、绿、蓝相对 xyY 色彩空间的坐标汇总在右表中。注意白点的坐标也给了定义（某个色彩空间的白点可能因其设计时所针对的观看条件而不同）。在 CIE RGB 的情形中，白点定义为照明体 E，它和上一章讲到的 D65 照明体一样，是 CIE 预定义的一种照明体，其特性是在整个可见光谱上 SPD 恒定（一种对所有波长都给出相同权重的照明体）。我们可以把这些坐标画到现有的马蹄形上，再连线把各点连起来。你会看到它定义出一个三角形。落在这个三角形边界之内的所有颜色，就是用 RGB 色彩空间能表示的颜色。你也能看到，用这个模型能表示的颜色比用 XYZ 色彩空间能定义的颜色要有限得多（见图 5）。

大多数计算机屏幕的技术都基于与 RGB 色模型类似的系统。屏幕上的每个像素由三盏小灯——一红、一绿、一蓝——构成，三盏同时点亮时，它们的贡献合成为白色（凑近看屏幕你能分辨出这三种颜色，但从远处看它们就混成白色）。不过下一章我们会说明，计算机屏幕还会以我们并不总是很意识到的方式操纵颜色。

最后提一句，RGB 色模型并不是现存的唯一一种 RGB 类色彩空间。还有若干基于与 RGB 色彩空间相同原理的模型被提出，用来改进原模型，或试图解决某些特定问题。例如 sRGB 色模型对原始 RGB 值施加伽马校正（下一章会解释），以更好地表示人类视觉对亮度变化的响应（这种响应是非线性的）。这类模型被称为非线性的，因为它们把原本是线性的 RGB 或 XYZ 三刺激值改成了非线性值。下一章会完整解释。不过本章我们只讨论 线性色彩空间，如 XYZ 和 RGB。

用 3D 渲染器渲染图像的经验法则是：所有输入和输出的颜色都应当以线性色彩空间（如 XYZ 或 RGB）来表达。以非线性色彩空间（如 sRGB）表达的颜色，应由渲染器使用前先转换回 RGB。要了解更多关于伽马校正和非线性色彩空间的内容，请读下一章。

从 XYZ 转换到 RGB

你可以先读几何那一课，更好地理解矩阵如何工作，然后如果愿意，再稍后回到本课程这一部分。在渲染器中使用 XYZ 或光谱数据是进阶话题，我们不会在渲染器的基本版本里用这项技术。在这篇颜色入门里，我们不会花太多篇幅解释把 XYZ 转换成 RGB 颜色的那些数字从哪来，不过你会在进阶 2D 部分找到专门讲这件事的一课。

从 XYZ 到 RGB 的转换可以用一个 [3x3] 矩阵完成。回想本章开头：在某个色彩空间里定义的颜色通常由三个坐标定义（至少 RGB 和 XYZ 色彩空间是这样），这些坐标可以画在 3D 空间里。而当某个色彩空间所能表示的色域中的全部颜色都画在 3D 空间里时，它们就定义出一个体积（例如 RGB 模型就是立方体，如图 4 所示）。把一个色彩空间中定义的颜色转换到另一个色彩空间，可以简单地看作把一个点在 3D 空间中从一处移到另一处。而这类线性变换一般最适合用矩阵处理。要记住，这个变换并不改变颜色本身，它只是把同一种颜色用不同的色彩空间表达出来。并非所有色彩空间之间的变换都能用 [3x3] 矩阵处理，有些可能需要更复杂的数学公式，例如从 RGB 到 HSV（色相-饱和度-明度）色彩空间的变换（关于色彩空间的更多信息见 2D 部分）。

矩阵乘法可以看作一种 线性变换（关于线性算子或用矩阵做变换的更多信息，见几何那一课）。换句话说（在色彩空间这一领域里），矩阵只能用来在线性色彩空间之间做变换。如果你还不知道线性空间与非线性空间（例如 sRGB）的区别，这个细节听起来可能很抽象，下一章我们会讲到。但了解这个区别的读者应当记住：[3x3] 矩阵不能用来在非线性色彩空间和线性色彩空间之间做转换（反之亦然）。任何非线性色彩空间都必须先转换成线性色彩空间，才能施加这样的变换。

下面的代码展示了用 [3x3] 矩阵把 XYZ 中定义的颜色转换到 RGB 色彩空间的一种做法（不必太在意这些数字从哪来。一般来说，在网上找到这些矩阵并直接在程序里用就足够了）：


void SpectrumToXYZ(int colorIndex, float XYZ[])
{
    float Ysum = 0;
    for (int i = 0; i < 81; ++i) {
        XYZ[0] += colorMatchingFunc[i][0] * spectralData[colorIndex][i];
        XYZ[1] += colorMatchingFunc[i][1] * spectralData[colorIndex][i];
        XYZ[2] += colorMatchingFunc[i][2] * spectralData[colorIndex][i];
        Ysum += colorMatchingFunc[i][1];
    }
    XYZ[0] *= 1 / Ysum;
    XYZ[1] *= 1 / Ysum;
    XYZ[2] *= 1 / Ysum;
}

float XYZ2RGB[3][3] =
{
    { 2.3706743, -0.9000405, -0.4706338},
    {-0.5138850,  1.4253036,  0.0885814},
    { 0.0052982, -0.0146949,  1.0093968}
};

void convertXYZtoRGB(float XYZ[], float rgb[], const float XYZ2RGB[3][3])
{
    rgb[0] = XYZ2RGB[0][0] * XYZ[0] + XYZ2RGB[0][1] * XYZ[1] + XYZ2RGB[0][2] * XYZ[2];
    rgb[1] = XYZ2RGB[1][0] * XYZ[0] + XYZ2RGB[1][1] * XYZ[1] + XYZ2RGB[1][2] * XYZ[2];
    rgb[2] = XYZ2RGB[2][0] * XYZ[0] + XYZ2RGB[2][1] * XYZ[1] + XYZ2RGB[2][2] * XYZ[2];
}

练习：Macbeth 色卡

什么是 Macbeth 色卡？Macbeth 色卡是一块平整的硬纸板，上面有二十四个彩色色块（六列四行）。这些颜色总是相同的，对应常被拍摄的典型材质的平均反射率，比如人的皮肤、天空和植被。无论 Macbeth 色卡在哪里生产，这些颜色都应当一致，因为色卡被用作参照，据此调整相机的曝光和颜色设置。由于这二十四个色块的颜色总是一样，并且在受控条件下生产，我们可以用分光光度计测量每一块的光谱功率分布（SPD）（在恒定、受控的照明条件下）。你可以在图 9 中看到 Macbeth 色卡上两种颜色（浅肤色和蓝天）的光谱曲线。Macbeth 色卡的光谱数据在网上很容易找到，形式是一张有 24 个条目的表格，每个条目对应色卡上的一种颜色。视测量的精度而定，颜色的 SPD 可以按 1、2、5 或 10 纳米采样，采样范围的边界可以变化，但必须落在可见光谱之内（一般是 380 到 780 nm）。

我们练习中要用的数据是从 380 到 780 nm 每 5 nm 采样。我们还需要 CIE 色匹配函数，你可以直接从 CIE 网站下载。我们会用这些数据和上面给出的代码，为 Macbeth 色卡的每个色块计算一个 XYZ 值。对 XYZ 三元组的每个分量，我们需要把某个色块的光谱数据与对应色匹配函数的相应采样相乘（计算 X 时用 \(\bar X\)，计算 Y 或 Z 时分别用 \(\bar Y\) 或 \(\bar Z\)），再把得到的数相加。然后，我们用上面讨论的技术把 XYZ 颜色转换成 RGB。

不过对这个练习来说，我们用的是光谱反射率曲线。它们定义某个物体反射（或吸收）特定波长光的特性。然而我们之所以看得见物体，是因为它们被具有各自光谱发射曲线（或各自色温）的光照亮。比如一个物体在阳光下的颜色，看起来可能和在人工光源（路灯）照明下观察时不同。因此，理想情况下，要把 Macbeth 色卡的光谱反射率曲线可视化为颜色，我们还需要模拟我们想在什么照明条件下看这些颜色。为此，我们需要把每种颜色的反射率数据，乘以我们想在其下观察这些颜色的光的光谱分布，再在转换成 XYZ 值时乘以 CIE 色匹配函数。还记得上一章讲过，光的光谱分布就是我们所说的 照明体。

标准照明体是一种理论上的可见光源，其分布（它的光谱功率分布）是公开发布的。

我们可以把计算 XYZ 的公式改写成下面这样：

$$ \begin{array}{l} X={\dfrac{1} {\int Y(\lambda)d \lambda}} \int_\lambda S_e(\lambda) \bar{X}(\lambda) I(\lambda) d \lambda \\ Y={\dfrac{1}{\int Y(\lambda)d \lambda}} \int_\lambda S_e(\lambda) \bar{Y}(\lambda) I(\lambda) d \lambda \\ Z={\dfrac{1}{\int Y(\lambda)d \lambda}} \int_\lambda S_e(\lambda) \bar{Z}(\lambda) I(\lambda) d \lambda \\ \end{array} $$

其中 \(I\) 是照明体的归一化光谱功率分布。本次练习我们会用 D65 照明体的数据，如上一章所述，它对应太阳的光谱功率。

D65 大致对应西欧／北欧正午的太阳，因此它也被称为日光照明体。

最后，为了把结果可视化，我们会把这些颜色保存到一个图像文件里（要了解如何把图像文件存到磁盘，请看 数字图像：从文件到屏幕 这一课）。这个练习的完整代码在「源代码」一章中可以找到。程序的结果如图 8 所示。把这个结果与真实 Macbeth 色卡的照片（图 7）比较一下。在这篇颜色入门里，我们只是想给一个简单的例子，帮助读者更好地理解把光谱数据（无法在屏幕上显示）转换成 RGB 值（可以在屏幕上显示）这个基本（而简单的）过程。

void convertXYZtoRGB(float XYZ[], float rgb[], const float XYZ2RGB[3][3])
{
    rgb[0] = XYZ2RGB[0][0] * XYZ[0] + XYZ2RGB[0][1] * XYZ[1] + XYZ2RGB[0][2] * XYZ[2];
    rgb[1] = XYZ2RGB[1][0] * XYZ[0] + XYZ2RGB[1][1] * XYZ[1] + XYZ2RGB[1][2] * XYZ[2];
    rgb[2] = XYZ2RGB[2][0] * XYZ[0] + XYZ2RGB[2][1] * XYZ[1] + XYZ2RGB[2][2] * XYZ[2];
}

void SpectrumToXYZ(int colorIndex, float XYZ[])
{
    float Ysum = 0;
    for (int i = 0; i < numBins; ++i) {
        XYZ[0] += macbethChartData[colorIndex][i] * D65[i] * colorMatchingFunc[i][1];
        XYZ[1] += macbethChartData[colorIndex][i] * D65[i] * colorMatchingFunc[i][2];
        XYZ[2] += macbethChartData[colorIndex][i] * D65[i] * colorMatchingFunc[i][3];
        Ysum += D65[i] * colorMatchingFunc[i][2];
    }
    XYZ[0] /= Ysum; XYZ[1] /= Ysum; XYZ[2] /= Ysum;
}

关于 ACES 色彩空间的简要说明

ACES 色彩空间是最近（2011 年）由美国电影艺术与科学学院技术委员会开发的，正被大多数需要处理数字图像创建或操作的行业逐步采用。ACES 代表 Acedemy Color Encoding Specification。它的设计目标是覆盖完整色域，这使它成为色彩空间的理想选择。以 ACES 色彩空间保存的图像无法直接显示在屏幕上，它们需要额外一步转换（对图像施加参考渲染变换（RRT），再施加输出设备变换（ODT）），这一步取决于用来显示图像的设备（计算机显示器、数字投影仪等）。这种格式及相关颜色管线的目标，是确保同样的图像无论用哪台相机创建、在哪台设备上显示，看起来都一样。关于这个色彩空间的更多信息可以在网上以及本站的 2D 部分找到。如果你有兴趣为专业用途制作数字图像，我们强烈建议你使用 ACES 色彩空间，它正在成为事实标准。

小结

本章我们学到了什么？我们介绍了色彩空间的概念，并展示了两种最常见、最重要的色彩空间：XYZ 与 RGB 色彩空间。XYZ 覆盖人类视觉的色域，可以由物体或光源的光谱功率分布与色匹配函数的乘积算出。在这个色彩空间中，Y 分量代表颜色的亮度。XYZ 颜色也可以转换到 xyY 色彩空间，其中 xy 分量编码颜色的色度，而 Y 和 XYZ 色彩空间中一样，代表颜色的亮度。这样我们就能把一种颜色最重要的两个属性——它的亮度或明度，以及它的色度（一种颜色的鲜艳程度）——分开。XYZ 颜色不能直接显示在屏幕上，它们首先要被转换成现有的某个 RGB 色彩空间。CIE RGB 色彩空间是一种线性色彩空间，它把颜色表示为三种原色（在加色系统中）——红、绿、蓝——的简单组合。
