光线与球体求交

阅读时间：18 分钟。

求一条光线与球体的交点，是光线与几何体求交测试中最简单的一种形式，这也是很多光线追踪器爱用球体图像来展示的原因。简单也带来了速度。不过，要保证它可靠工作，总有几处重要的细节需要注意。

这项测试可以用两种方法实现。第一种方法用几何来解题。第二种方法——常常是更受青睐的方案（因为它可以复用到更广泛的一类曲面，即二次曲面上）——使用解析解（或称代数解，即可以用闭式表达式求解）。

几何解法

光线与球体求交测试的几何解法依赖简单的数学，主要是几何、三角学以及勾股定理。看图 1 你会明白，要找出点 P 与 P' 的位置——它们就是光线与球体相交的位置——我们需要求出 \(t_0\) 和 \(t_1\) 的值。

记住，一条光线可以用下面的参数形式表示：

$$O + tD$$

其中 \(O\) 表示光线的原点，\(D\) 是光线方向（通常已归一化）。改变 \(t\) 的值可以定义光线上任意位置。当 \(t\) 大于 0 时，该点位于光线原点的前方（沿光线方向看过去）；当 \(t\) 等于 0 时，该点与光线原点（O）重合；当 \(t\) 为负时，该点位于原点后方。看图 1 可以看出，\(t_0\) 可以用 \(t_{ca}\) 减去 \(t_{hc}\) 得到，\(t_1\) 可以用 \(t_{hc}\) 加上 \(t_{ca}\) 得到。我们要做的，只是找出计算这两个值（\(t_{hc}\) 和 \(t_{ca}\)）的方法，据此推出 \(t_0\)、\(t_1\)，再用光线参数方程得到 P 和 P'：

$$ \begin{array}{lcl} P & = & O + t_{0}D\\ P' & = & O + t_{1}D \end{array} $$

我们先注意到，由边 \(L\)、\(t_{ca}\) 和 \(d\) 构成的三角形是直角三角形。于是我们可以轻松算出 \(L\)，它就是 \(O\)（光线的原点）与 \(C\)（球心）之间的向量。\(t_{ca}\) 还有待确定，但我们可以用三角学来解决这个问题。

我们知道 \(L\)，也知道 \(D\)，即光线的方向。我们还知道向量 \(\vec{b}\) 与 \(\vec{a}\) 的点积（或标量积）对应于把 \(\vec{b}\) 投影到由向量 \(\vec{a}\) 定义的直线上，投影的结果就是图 2 中线段 AB 的长度（关于点积性质的更多内容，见 几何 课程）：

$$\vec{a} \cdot \vec{b} = |a||b|\cos\theta.$$

换句话说，\(L\) 与 \(D\) 的点积给出了 \(t_{ca}\)。注意，只有当 \(t_{ca}\) 为正时，光线与球体之间才可能有交点（若为负，说明向量 \(L\) 与向量 \(D\) 方向相反。即使存在交点，交点也可能落在光线原点后方，而原点后方发生的一切对我们毫无用处）。现在我们有了 \(t_{ca}\) 和 \(L\)。

$$ \begin{array}{l} L = C - O\\ t_{ca} = L \cdot D\\ if \; (t_{ca} < 0) \; return \; false \end{array} $$

这个构造中还有第二个直角三角形，由 \(d\)、\(t_{hc}\) 以及球体半径构成。我们已经知道球体的半径，要找的是 \(t_{hc}\)，以便得到 \(t_0\) 和 \(t_1\)。为此，先得算出 \(d\)。记住，\(d\) 同时也是由 \(d\)、\(t_{ca}\) 和 \(L\) 构成的直角三角形的对边。勾股定理说的是：

$$\text{opposite side}^2 + \text{adjacent side}^2 = \text{hypotenuse}^2$$

把对边、邻边和斜边分别替换为 \(d\)、\(t_{ca}\) 和 \(L\)，得到：

$$ \begin{array}{l} d^2 + t_{ca}^2 = L^2\\ d = \sqrt{L^2 - t_{ca}^2} = \sqrt{L \cdot L - t_{ca} \cdot t_{ca}}\\ if \; (d < 0) \; return \; false \end{array} $$

注意，如果 \(d\) 大于球体半径，光线就错过了球体，表示没有交点（光线从球体旁边掠过）。现在我们有了计算 \(t_{hc}\) 所需的全部项。再次使用勾股定理：

$$ \begin{array}{l} d^2 + t_{hc}^2 = \text{radius}^2\\ t_{hc} = \sqrt{\text{radius}^2 - d^2}\\ t_{0} = t_{ca} - t_{hc}\\ t_{1} = t_{ca} + t_{hc} \end{array} $$

在本节的最后一段，我们会演示如何用 C++ 实现这个算法，并讨论几处能加速过程的优化。

解析解法

回顾一下，光线可以用函数 \(O + tD\)（公式 1）表示，其中 \(O\) 是光线原点对应的点，\(D\) 是表示光线方向的向量，\(t\) 是函数的参数。改变 \(t\)（可正可负）可以算出由光线原点与方向所定义直线上的任意点位置。当 \(t\) 大于 0 时，光线上的点位于原点「前方」；\(t\) 为负时，点位于原点后方；\(t\) 恰为 0 时，点与光线原点重合。

求解光线与球体求交测试的思路在于：球体也可以用代数形式定义。球体的方程是：

$$ x^2 + y^2 + z^2 = R^2 $$

其中 \(x\)、\(y\) 和 \(z\) 是某个笛卡尔点的坐标，\(R\) 是以原点为球心的球体半径（后面我们会看到如何修改方程，使它适用于球心不在原点的球体）。这意味着存在一组点使上述方程成立。这组点定义了以原点为球心、半径为 \(R\) 的球面。或者更简单地说，如果把 \(x\)、\(y\) 和 \(z\) 视为点 \(P\) 的坐标，我们可以把它写成（公式 2）：

$$ P^2 - R^2 = 0 $$

这个方程具有数学与计算机图形学中所谓隐式函数的特征。用这种形式表示的球体也称为隐式形状或隐式曲面。隐式形状不是用彼此相连的多边形定义的（如果你在 Maya 或 Blender 这类 3D 软件里建过模型，会对多边形比较熟悉），而是直接用方程定义。许多形状（往往相当简单）都可以用函数定义（立方体、圆锥、球体等）。尽管简单，这些形状可以组合出更复杂的形式。这就是用 blob 做几何建模背后的思路（blobby 曲面也叫 metaball）。不过在跑题太远之前，让我们回到光线与球体求交测试（隐式建模的课程见进阶章节）。

现在只需把公式 1 代入公式 2，也就是把公式 2 中的 \(P\) 替换成光线方程（记住 \(O + tD\) 定义了光线上的所有点）：

$$ (O + tD)^2 - R^2 = 0 $$

展开这个方程，得到（公式 3）：

$$ O^2 + (Dt)^2 + 2ODt - R^2 = O^2 + D^2t^2 + 2ODt - R^2 = 0 $$

这本质上是一个形如（公式 4）的方程：

$$ ax^2 + bx + c $$

其中 \(a = D^2\)、\(b = 2OD\) 和 \(c = O^2 - R^2\)（注意公式 4 中的 \(x\) 对应公式 3 中的 \(t\)，也就是未知量）。把公式 3 改写成公式 4 很关键，因为公式 4 是一个二次方程。它是一个函数，其根（即 \(x\) 取到使 \(f(x) = 0\) 的值时）可以用下面的公式求出（公式 5）：

  • 当 \(\Delta > 0\) 时，有两个根，可用下式计算：$$ \dfrac{-b + \sqrt{\Delta}}{2a} \quad \text{and} \quad \dfrac{-b - \sqrt{\Delta}}{2a} $$ 此时光线与球体交于两点（\(t_0\) 和 \(t_1\)）。

  • 当 \(\Delta = 0\) 时，只有一个根，可用下式计算：$$ -\dfrac{b}{2a} $$ 光线只与球体交于一点（\(t_0 = t_1\)）。

  • 当 \(\Delta < 0\) 时，没有实数解，表示光线不与球体相交。

既然我们有了 \(a\)、\(b\) 和 \(c\)，就能轻松解出这些方程，求出 \(t\) 的值，它们对应光线与球体的两个交点（图 1 中的 \(t_0\) 和 \(t_1\)）。注意根的值可以为负，表示光线与球体相交但交点在原点后方。也可能一个根为负、另一个为正，表示光线的原点在球体内部。二次方程也可能无解，表示光线与球体之间没有交点。

在探讨如何用 C++ 实现这个算法之前，先看看球心不在原点时如何求解同一个问题。这时公式 2 可以改写为：

$$ |P-C|^2-R^2=0 $$

其中 \(C\) 是球体在三维空间中的球心。公式 4 现在可以改写为：

$$|O+tD-C|^2-R^2=0.$$

由此得到：

$$ \begin{array}{l} a = D^2 = 1\\ b = 2D \cdot (O-C)\\ c = |O-C|^2 - R^2 \end{array} $$

更直观地说，这意味着我们可以把光线平移 \(-C\)，再把这条变换后的光线拿去与一个位于原点的球体求交。

「为什么是 \(a=1\)？」因为 \(D\)，也就是光线的方向，通常是一个归一化的向量。向量平方的结果等于该向量与自身做点积。我们知道归一化向量与自身的点积为 1，因此 \(a=1\)。不过代码里必须非常小心，因为拿去与球体求交的光线，其方向向量并不总是归一化的，所以你得自己算出 \(a\) 的值（见下面的代码）。这是代码中经常引发 bug 的一个陷阱。

计算交点

一旦求出 \(t_0\) 的值，计算交点位置（即命中点）就很直接了。直接套用光线参数方程：

$$P_{hit} = O + t_0 D.$$


Vec3f Phit = ray.orig + ray.dir * t_0;

计算交点处的法线

计算隐式形状表面上某点法线的方法有多种。不过，正如本课程第一章提到的，其中一种方法涉及微分几何，数学上相当复杂。因此我们选一个简单得多的做法。例如球面上某点的法线，可以用该点的位置减去球心算出（记得把结果向量归一化）：

$$N = \frac{P - C}{||P - C||}.$$


Vec3f Nhit = normalize(Phit - sphere.center);

计算交点处的纹理坐标

有意思的是，纹理坐标本质上就是球面上该点的球坐标，重映射到 [0, 1] 区间。回顾上一章和几何课程，一个点的笛卡尔坐标可以由它的球坐标这样得到：

$$ \begin{array}{l} P.x = \cos(\theta)\sin(\phi),\\ P.y = \sin(\theta),\\ P.z = \cos(\theta)\sin(\phi).\\ \end{array} $$

如果采用不同的约定，这些方程可能有所不同。球坐标 \(\theta\) 和 \(\phi\) 也可以由该点的笛卡尔坐标用下面这些方程推出：

$$ \begin{array}{l} \phi = \text{atan2}(z, x),\\ \theta = \text{acos}\left(\dfrac{P.y}{R}\right). \end{array} $$

其中 \(R\) 是球体的半径。这些方程在 几何 课程中有进一步解释。球坐标对纹理映射或过程式纹理很有用。本课程的程序会演示如何用它们在球体表面生成图案。

用 C++ 实现光线与球体求交测试

来看看如何用解析解实现光线与球体求交测试。直接套用公式 5 是可行的（而且能工作）来算根。然而，由于计算机表示实数的精度有限，这个公式可能遭遇有效数字丢失。当 \(b\) 与判别式的平方根数值接近但符号相反时，这个问题就会出现。鉴于计算机上浮点数的精度有限，这会导致灾难性抵消或不可接受的舍入误差。关于这个问题的细节，网上有大量资料。不过公式 5 可以换成一个稍作修改的方程，它在计算机实现中被证明更为稳定：

$$ \begin{array}{l} q = -\dfrac{1}{2} \left( b + \text{sign}(b) \sqrt{b^2 - 4ac} \right) \\ x_{1} = \dfrac{q}{a}, \quad x_{2} = \dfrac{c}{q} \end{array} $$

其中当 \(b\) 小于 0 时 \(\text{sign}\) 为 -1，否则为 1。这一改动确保用来计算 \(q\) 的各个量符号相同，从而避免灾难性抵消。下面是该例程在 C++ 中的实现：


bool solveQuadratic(const float &a, const float &b, const float &c, 
					float &x0, float &x1) {
    float discr = b * b - 4 * a * c;
    if (discr < 0) return false;
    else if (discr == 0) x0 = x1 = -0.5 * b / a;
    else {
        float q = (b > 0) ?
            -0.5 * (b + sqrt(discr)) :
            -0.5 * (b - sqrt(discr));
        x0 = q / a;
        x1 = c / q;
    }
    if (x0 > x1) std::swap(x0, x1);
    
    return true;
}

现在给出光线与球体求交测试的完整代码。在几何解法里，我们注意到如果 \(d\) 大于球体半径，就可以提前剔除这条光线。但那需要计算 \(d^2\) 的平方根，是有计算代价的。而且代码里从不使用 \(d\) 本身，只用 \(d^2\)。所以我们不计算 \(d\)，而是测试 \(d^2\) 是否大于 \(radius^2\)（这也是 Sphere 类的构造函数里会算出 \(radius^2\) 的原因），条件成立就剔除光线。这个做法能有效地加速过程。


bool intersect(const Ray &ray) const
{
        float t0, t1; // 若光线与球体相交，t 的解
#if 0
        // 几何解法
        Vec3f L = center - ray.orig;
        float tca = L.dotProduct(ray.dir);
        // if (tca < 0) return false;
        float d2 = L.dotProduct(L) - tca * tca;
        if (d2 > radius * radius) return false;
        float thc = sqrt(radius * radius - d2);
        t0 = tca - thc;
        t1 = tca + thc;
#else
        // 解析解法
        Vec3f L = ray.orig - center;
        float a = ray.dir.dotProduct(ray.dir);
        float b = 2 * ray.dir.dotProduct(L);
        float c = L.dotProduct(L) - radius * radius;
        if (!solveQuadratic(a, b, c, t0, t1)) return false;
#endif
        if (t0 > t1) std::swap(t0, t1);

        if (t0 < 0) {
            t0 = t1; // 若 t0 为负，改用 t1。
            if (t0 < 0) return false; // t0 和 t1 都为负。
        }

        t = t0;

        return true;
}

注意：如果场景中有多个球体，它们会按加入场景的顺序被测试，而不一定按相对相机位置的深度排序。正确的做法是记录交点距离最近的那个球体，也就是 \(t\) 最小的那个。下图展示的场景渲染中，左边显示的是物体列表里最后一个被光线击中的球体，即使它并不是最近的；右边的渲染则记录离相机最近的物体，得到正确结果。这项技术的实现在下一章给出。

现在来看看如何用解析解实现光线与球体求交测试。我们可以直接用公式 5（你可以实现它，它能工作）来计算根。但在计算机上，我们表示实数的精度能力有限，无法尽可能准确地算出这些根。于是这个公式会受有效数字丢失的影响。当 b 与判别式的根符号不同、但数值非常接近时，这种情况就会发生。由于计算机表示浮点数所用的位数有限，在这种特定情况下，这些数要么在本不该抵消的时候抵消掉（这叫灾难性抵消），要么舍入到不可接受的误差（你很容易在网上找到关于这个话题的更多资料）。不过公式 5 很容易被替换成一个略有不同的方程，它在计算机上实现时被证明更稳定。我们改用：

$$ \begin{array}{l} q=-\dfrac{1}{2}(b+sign(b)\sqrt{b^2-4ac})\\ x_{1}=\dfrac{q}{a}\\ x_{2}=\dfrac{c}{q} \end{array} $$

其中当 b 小于 0 时符号取 -1，否则取 1。这个公式确保为 q 相加的各项符号相同，避免灾难性抵消。下面是该例程在 C++ 中的样子：


bool solveQuadratic(const float &a, const float &b, const float &c, float &x0, float &x1)
{
    float discr = b * b - 4 * a * c;
    if (discr < 0) return false;
    else if (discr == 0) x0 = x1 = - 0.5 * b / a;
    else {
        float q = (b > 0) ?
            -0.5 * (b + sqrt(discr)) :
            -0.5 * (b - sqrt(discr));
        x0 = q / a;
        x1 = c / q;
    }
    if (x0 > x1) std::swap(x0, x1);
    
    return true;
}

最后给出光线与球体求交测试的完整代码。对于几何解法，我们提到过如果 \(d\) 大于球体半径，就可以提前剔除光线。但那需要计算 \(d^2\) 的平方根，是有代价的。此外，代码里从不使用 \(d\)，只用 \(d^2\)。所以我们不计算 \(d\)，而是测试 \(d^2\) 是否大于 \(radius^2\)（这就是我们在 Sphere 类的构造函数里计算 \(radius^2\) 的原因），条件成立就剔除光线。这是加速的一个简单办法。

{
        float t0, t1; // 若光线相交，t 的解
#if 0

        Vec3f L = center - ray.orig;
        float tca = L.dotProduct(ray.dir);
        // if (tca < 0) return false;
        float d2 = L.dotProduct(L) - tca * tca;
        if (d2 > radius * radius) return false;
        float thc = sqrt(radius * radius - d2);

        t1 = tca + thc;
#else
        // 解析解法
        Vec3f L = ray.orig - center;
        float a = ray.dir.dotProduct(ray.dir);
        float b = 2 * ray.dir.dotProduct(L);
        float c = L.dotProduct(L) - radius * radius;
        if (!solveQuadratic(a, b, c, t0, t1)) return false;

注意，如果场景中有不止一个球体，对任意一条光线，球体都是按加入场景的顺序被测试的。因此这些球体不太可能按深度（相对相机位置）排序。这个问题的解决办法是记录交点距离最近的那个球体，也就是 \(t\) 最小的那个。在下图中，左边是场景的一次渲染，显示的是光线击中的物体列表里最后一个球体（即使它不是最近的物体）；右边则记录离相机距离最近的物体，并且只在最终图像里显示它，从而得到正确结果。这项技术的一种实现在下一章给出。
