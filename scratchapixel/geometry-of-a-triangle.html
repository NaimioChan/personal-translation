三角形的几何

阅读时间：9 分钟。

基础数学工具

在探讨求解光线与三角形求交测试的技术之前，有必要先熟悉一些基础数学工具。如前所述，三角形的顶点定义一个平面。每个平面都由一条法线刻画，法线是垂直于该平面的向量。已知三角形顶点 \(A\)、\(B\) 和 \(C\) 的坐标，我们可以算出向量 \(AB\) 和 \(AC\)，它们分别表示从 \(A\) 到 \(B\) 的边、以及从 \(A\) 到 \(C\) 的边。做法是用 \(A\) 减去 \(B\)、用 \(A\) 减去 \(C\)。

这里要注意：记住 Scratchapixel 的所有课程都使用右手坐标系（上方向为 y 轴）。因此，当你从正面看一个三角形时，三角形的顶点会按 \(v0\)、\(v1\)、\(v2\) 的逆时针顺序标注。

同样，把第一个顶点定为 \(A\) 或 v0——后续的 \(AB\) 或 \(AC\) 之类的向量都从它算起——是合乎逻辑的。不过，选 \(A\) 而不是 \(B\) 或 \(C\) 纯属任意。如果你决定从顶点 \(B\) 或 \(C\) 开始（如下图所示），我们接下来给出的全部数学推导照样成立，尽管这看起来不像是你通常会做的事。

等到讲重心坐标那一课时你会看到，把起点选在 \(A\) 以外的点可能更方便。如果这么做，唯一的要求是保证沿逆时针方向「绕」三角形走一圈。例如你选 \(C\) 作起点，那么下一个顶点应当是 \(A\)，再下一个是 \(B\)。

目前，为本章及下一章的需要，我们假定 \(A\) 或 v0 是第一个顶点，后续向量都从它定义。但要记住，这并不是数学成立的必要条件。

上图中，我们把计算法向量的三种可能方式都画了出来，每次都把洋红色向量作为叉积的第一个向量，自然把青色向量作为第二个。这说明并不一定总要把顶点 \( A \)（或 \( v_0 \)）当作第一个顶点来计算后续所有变量。你可以选 \( B \) 或 \( C \) 作起点，只要始终按逆时针方向考虑顶点即可（数学上可能的说法叫循环置换）。

要确定平面的法线——它同时也是三角形的法线，因为三角形就在这个平面内——我们计算向量 \(AB\) 与 \(AC\) 的叉积。由于这两个向量位于同一平面内（它们连接三角形的顶点），叉积得到的向量 \(N\) 就是我们要找的法线（见图 1）。这些运算可概括为下面的伪代码：


Vec3f v0(-1, -1, 0), v1(1, -1, 0), v2(0, 1, 0);
Vec3f e0 = v1 - v0; // 边 0
Vec3f e1 = v2 - v0; // 边 1
Vec3f N = cross(e0, e1); // 三角形的法线
normalize(N);

这些运算的数学表示如下：

$$ \begin{array}{l} AB = B - A = (1 - (-1), -1 - (-1), 0 - 0) = (2, 0, 0) \\ AC = C - A = (0 - (-1), 1 - (-1), 0 - 0) = (1, 2, 0) \\ N = AB \times AC \\ N_x = AB_y \cdot AC_z - AB_z \cdot AC_y = 0 \cdot 0 - 0 \cdot 2 = 0 \\ N_y = AB_z \cdot AC_x - AB_x \cdot AC_z = 0 \cdot 1 - 2 \cdot 0 = 0 \\ N_z = AB_x \cdot AC_y - AB_y \cdot AC_x = 2 \cdot 2 - 0 \cdot 1 = 4 \\ \end{array} $$

把 \(N\) 归一化后，我们得到向量 \((0, 0, 1)\)，它与 \(z\) 轴的正方向平行。这个结果是意料之中的，因为顶点 \(A/v0\)、\(B/v1\) 和 \(C/v2\) 都位于 \(XY\) 平面内。

坐标系的手性

三角形顶点的定义顺序会显著影响表面法线的朝向。按逆时针（CCW）顺序定义顶点 \(v_0\)、\(v_1\) 和 \(v_2\)，得到的法线记作 \(N\)。反之，如果顶点按顺时针（CW）顺序定义，两条边（\(v0v1 = v_1 - v_0\) 与 \(v0v2 = v_2 - v_0\)）叉积得到的法线就指向相反方向，得到 \(-N\)。同样，如果你算的是 \(v0v2 \times v0v1\) 而不是 \(v0v1 \times v0v2\)，也会得到 \(-N\)。因此，处理逆时针排列的顶点时务必使用 \(v0v1 \times v0v2\)，这也是右手坐标系下的预期做法。

在 Maya 里创建三角形时（它使用右手坐标系），按逆时针（CCW）顺序生成三角形顶点意味着：如果你在 XY 平面上创建一个三角形，并把由 \(v0v1\) 与 \(v0v2\) 定义的向量做叉积，得到的向量（三角形的法线）会与世界坐标系的正 z 轴同向（图 2）。但如果顶点按顺时针顺序创建，\(N\) 就会沿负 z 轴方向。按顺时针顺序创建顶点并由叉积 \(v0v1 \times v0v2\) 算出 \(N\)，等价于在顶点按逆时针顺序创建时计算叉积 \(v0v2 \times v0v1\)。（我知道上面刚说过这一点，但我还是保留这次重复，以防这次的解释比上一次更容易理解。）

设想在左手坐标系里创建这个三角形（不同于上面那些例子以及 Scratchapixel 所有课程所假定的右手坐标系），顶点坐标与右手坐标系例子里的完全相同（\(v_0 = (0,0,0)\)、\(v_1=(1,0,0)\) 和 \(v_2=(0,1,0)\)）。按同样的步骤，我们创建向量 \(v0v1\)（\(v_1-v_0\)）与 \(v0v2\)（\(v_2-v_0\)），并算出 \(N\)（由 \(v0v1 \times v0v2\) 得到）。结果是 \((0,0,1)\)，与右手坐标系例子完全相同，因为顶点坐标一样。因此向量 \(v0v1\) 与 \(v0v2\)、以及叉积 \(v0v1 \times v0v2\) 都保持不变。按约定，左手坐标系里的 z 轴指向屏幕外（此时 x 轴指向右，y 轴指向上），这与我们对坐标系手性的说明一致。叉积是反交换运算，这在我们讲几何的课程里讨论过。

下一步是从一个朝向负 z 轴的相机去渲染这些三角形。结果如图 4 所示：尽管两个三角形的顶点坐标相同，两张图看起来却不一样。这个差异是个问题，因为改变坐标系的手性不该改变三角形在相机里的样子。理想情况下，无论用哪种手性，三角形看起来都应当相同。虽然这个问题与光线与三角形求交测试没有直接关系，但仍然值得注意。我们可以通过沿负 z 轴翻转相机（包括它的位置与方向）来修正，如图 4 所示。

不过这一调整会改变相机与三角形法线相对其镜像前原始朝向的方向。在图 3 中，相机与三角形法线方向相反。调整之后，它们方向相同。这两个向量——三角形的法线与相机方向——对着色很重要，所以它们的相对朝向应当保持不变。

所以，翻转三角形问题的解决办法是把相机镜像、并把三角形的法线反向。但这要求我们跟踪哪些几何体是在与渲染程序手性不同的坐标系中建模的，也就是说，需要在着色阶段为那些几何体反转法线。这个做法并不理想。

举例来说，如果一个三角形的顶点在左手坐标系中定义为 \(v_0\)、\(v_1\) 和 \(v_2\)，那么转换到右手坐标系时，应当把 x 坐标取负，并把顺序反转为 \(v_2\)、\(v_1\) 和 \(v_0\)。

只有在一种坐标系中创建几何体、却在另一种坐标系中渲染时（比如在 Maya 中创建几何体——它使用右手系——然后在 RenderMan 中渲染——它使用左手系），这种调整才是必要的。做过这些改动之后，就无需再修改相机设置，也无需在着色时把法线取负。模型在视觉上会保持一致，法线如预期那样朝外，无论渲染应用使用哪种手性的坐标系。

顶点定义的具体顺序与方向称为绕序。

有了这些工具，我们完全可以用简单的几何来解决光线与三角形求交测试了。
