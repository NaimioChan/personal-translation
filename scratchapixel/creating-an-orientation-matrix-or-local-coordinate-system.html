创建朝向矩阵或局部坐标系

阅读时间：7 分钟。

由一个法线向量构造局部坐标系

本章我们会把对坐标系的理解用起来，围绕一个向量——它常常是一条法线——构建一个局部坐标系（或称标架）。这种方法在渲染过程中经常被用来把点与向量从一个坐标系转到另一个坐标系，做法是把给定点处的法线作为这个局部标架的一个轴。这个轴通常与向上向量对齐，而该点处的切线与副切线构成其余的正交轴。

要准确地构成这样的局部标架，应当使用表面在点 P 处的法线、切线与副切线。这些向量位于表面在 P 处的切平面内，并且必须正交且已归一化。在讲光线与几何体求交的课程里，讨论会延伸到计算交点处的导数——即 dPdu 与 dPdv。这些导数提供了在 P 处定义切线与副切线的技术手段。P 处的法线通常由 dPdu 与 dPdv 的叉积得出。必须留意这些向量的朝向，确保叉积得出的是从表面朝外伸出的向量，而不是朝内的。知道了这些向量的方向朝向，就可以用右手定则确定叉积的正确顺序，保证法线背离表面（详见第 3 章 点与向量上的数学运算）。

把法线 N 指定为向上向量、切线指定为向右向量、副切线指定为向前向量，这些向量就可以按下面的方式排成 [4x4] 矩阵的各行：

$$ \begin{bmatrix} T_x&T_y&T_z&0\\ N_x&N_y&N_z&0\\ B_x&B_y&B_z&0\\ 0&0&0&1 \end{bmatrix} $$

在代码里使用这个矩阵时，务必留心它所在的具体语境。例如代码的某些部分，尤其是与着色相关的部分，可能采用另一种约定，把 z 轴当作向上向量。这种做法在关于球坐标的讨论中常常讲到，于是需要按下面的方式重新组织矩阵各行，以符合这种以着色为中心的约定：

$$ \begin{bmatrix} T_x&T_y&T_z&0\\ B_x&B_y&B_z&0\\ N_x&N_y&N_z&0\\ 0&0&0&1 \end{bmatrix} $$

这个调整把法线向量的坐标放到矩阵的第三行，遵循以着色为中心、把表面法线与 z 轴对齐的约定。这种对齐也许不能一眼就看懂，但它在着色领域是被广泛接受的标准，为了一致性我们也不得不采用它。如图 4 所示，这一约定与世界坐标系形成对照：世界坐标系里通常 y 向量代表向上向量，而在局部坐标系中这里把 z 向量指定为向上向量。

要注意，如果你的工作采用列主序约定——与 Scratchapixel 的行主序相反——那么这些向量必须表示成列而非行。这意味着对于充当向上向量的 z 向量，T 的坐标填第一列，B 的坐标填第二列，N 的坐标填第三列。

这个矩阵有什么用？把它作用于一个向量——例如位于世界空间的 \(v\)——这个矩阵就把 \(v\) 转到 \(v_M\)，其坐标此时是相对于由 \(N\)、\(T\) 与 \(B\) 锚定的局部构造坐标系定义的。这个矩阵第四行没有平移分量，正说明它属于朝向矩阵，只用于向量的操控。这一特性在着色应用中极为宝贵——那里向量相对于表面法线（按约定通常与 y 轴或 z 轴对齐）的朝向，会极大地影响在光线交点处决定物体颜色的计算过程，如图 4 所示。这种着色方法会在即将推出的着色一课中全面探讨。

仿射空间：某些渲染平台，比如 Intel 的 Embree，更偏好用仿射空间来表示矩阵与变换。这种做法用一个特定的空间位置（记作 O）加上三个方向轴（Vx、Vy、Vz）来界定一个笛卡尔坐标系。

代码

下面是这些概念的一个实现。假定向量 v1 代表右手坐标系中的 z 轴（以及／或者着色法线 \( N \)），代码如以下片段所示：


void CoordinateSystem(const Vec3f& v1, Vec3f& v2, Vec3f& v3) {
	if (std::fabs(v1.x) > std::fabs(v1.y)) {
        float inv_len = 1 / std::sqrt(v1.x * v1.x + v1.z * v1.z);
        v2 = Vec3f(v1.z * inv_len, 0, -v1.x * inv_len);
    }
    else {
        float inv_len = 1 / std::sqrt(v1.y * v1.y + v1.z * v1.z);
        v2 = Vec3f(0, -v1.z * inv_len, v1.y * inv_len); 
    }
    v3 = v1.Cross(v2);
}

  • 对于 \( N = \text{z-axis} \)，即 \( (0, 0, 1) \)：

    • 条件 \( \vert N.x \vert > \vert N.y \vert \) 为假（因为 \( N.x = 0 \) 且 \( N.y = 0 \)），所以走 else 分支。

    • 因此 \( Nt = \text{Vec3f}(0, -N.z, N.y) / \sqrt{N.y^2 + N.z^2} \)。

    • 代入 \( N = (0, 0, 1) \)：

      • \( Nt = \text{Vec3f}(0, -1, 0) \)。

    • 然后计算 \( Nb = N \times Nt \)：

      • \( Nb = (0, 0, 1) \times (0, -1, 0) = (1, 0, 0) \)。

因此，如果 \( N \) 代表右手坐标系中的 z 轴，那么执行 CoordinateSystem(v1, v2, v3) 之后，你应该会看到：

  • v2 即 \( Nt \)（新体系中的切线方向或 y 轴方向）与负 y 轴方向对齐：\( (0, -1, 0) \)。

  • v3 即 \( Nb \)（新体系中的副切线方向或 x 轴方向）与 x 轴方向对齐：\( (1, 0, 0) \)。

这次变换旋转了坐标系，使原体系的 z 轴与 \( N \) 对齐，而 \( Nt \) 与 \( Nb \) 则以 \( N \) 为法线向量，构成一组标准正交基。

如果你用的是左手坐标系，请改用下面的代码：


void CoordinateSystem(const Vec3f& v1, Vec3f& v2, Vec3f& v3) {
	if (std::fabs(v1.x) > std::fabs(v1.y)) {
        float inv_len = 1 / std::sqrt(v1.x * v1.x + v1.z * v1.z);
        v2 = Vec3f(-v1.z * inv_len, 0, v1.x * inv_len);
    }
    else {
        float inv_len = 1 / std::sqrt(v1.y * v1.y + v1.z * v1.z);
        v2 = Vec3f(0, v1.z * inv_len, -v1.y * inv_len); 
    }
    v3 = v1.Cross(v2);
}
