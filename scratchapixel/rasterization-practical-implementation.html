改进光栅化算法

走样与抗锯齿

前面几章介绍的技术构成了光栅化算法的基础。不过我们是以非常基础的方式实现这些技术的。GPU 渲染管线以及其他基于光栅化的生产级渲染器用的是同样的概念，只是算法的版本经过高度优化。把加速算法的各种技巧都讲清楚，超出了这篇入门文章的范围。下面我们简单过一遍其中一些，并打算将来专门用一门课来讲这个话题。

先来看 3D 渲染的一个根本问题。如果你把上一章渲染出的三角形图像放大，会发现三角形的边缘是不规则的（这种不规则也影响方块边缘处的棋盘格图案）。图 1 中可见的那些台阶叫作锯齿。这些锯齿状、阶梯状的边缘并非瑕疵，它们是三角形被拆解为像素所致。用光栅化，我们把一个连续表面（三角形）拆成离散的元素（像素），这个过程在渲染入门中已经提过。这个难题好比用乐高积木去表现一条连续曲线或一个连续曲面，不看出积木是不可能的（图 2）。

渲染中的解法叫作抗锯齿（AA）。我们不再对每个像素只做一个采样，而是把像素细分为子像素，对每个子像素做覆盖测试（图 3）。虽然每个子像素仍然只是另一块「积木」，但这种方法能稍微更精确地捕捉物体的边缘。像素通常被划分为 N×N 的子像素网格，N 一般是 2 的幂（2、4、8 等），技术上也可以是任何大于等于 1 的值（1、2、3、4、5 等）。处理走样问题有各种方法，这里描述的技术属于基于采样的抗锯齿方法。

最终像素颜色按所有子像素颜色之和除以子像素总数来计算。举例来说，设想三角形是白色的。如果只有 2 个或 4 个采样与三角形重叠，最终像素颜色就等于 (0+0+1+1)/4=0.5。这个像素不会是完全的白或黑，而是有一段渐变，从而减轻阶梯状的像素瑕疵。这种技术就叫抗锯齿。要彻底理解抗锯齿，需要深入信号处理理论，那是一个庞大而复杂的题目。

把 N 取为 2 的幂是有好处的，因为如今的处理器大多能并行执行若干条指令，而并行指令数一般是 2 的幂。你可以在网上找到关于 CPU 专用的 SSE 指令集之类的资料，GPU 用的是类似的概念。SSE 是大多数现代 CPU 上具备的特性，通常能同时做 4 个或 8 个浮点运算（在一个周期内）。这意味着，花一次浮点运算的代价，你实际上白得了 3 次或 7 次额外的运算。理论上这能让渲染时间加快 4 倍或 8 倍（不过由于设置这些指令有少量开销，这样的性能很难达到）。例如，SSE 指令能在计算一个像素的代价下渲染 2x2 个子像素，几乎不增加开销就让边缘更平滑。

按像素块渲染

另一种加速光栅化的技术是按像素块渲染。我们不去逐一测试块内的每个像素，而是先检查块角上的像素。GPU 的算法可能用 8x8 像素的块。这个方法是涉及 tile（瓦片）的复杂概念的一部分，这里不展开。如果 8x8 网格的四个角都覆盖了三角形，那么该块内剩余的像素很可能也覆盖这个三角形，如图 7 所示。

这种情况下，再测试其余像素就没必要了，能省下不少时间。这些像素可以直接填上三角形的颜色。若需要在像素块范围内做插值顶点属性，这个过程同样被简化：既然已在块的四个角上算出了这些属性，只需沿两个方向（水平和垂直）做线性插值即可。这种优化对屏幕上显得很大的三角形最为有效。小三角形从中获益没那么多。

优化边函数

边函数也可以优化。回顾一下它的实现：


int orient2d(const Point2D& a, const Point2D& b, const Point2D& c)
{
    return (b.x - a.x) * (c.y - a.y) - (b.y - a.y) * (c.x - a.x);
}

记住，这个函数里的 a 和 b 代表三角形的顶点，c 表示像素坐标（在光栅空间中）。一个有意思的观察是：这个函数对三角形包围盒内的每个像素都要调用一次。遍历多个像素时，只有 c 在变；a 和 b 保持不变。假设我们算一次这个式子，得到一个结果 w0：


w0 = (b.x - a.x) * (c.y - a.y) - (b.y - a.y) * (c.x - a.x);

如果 c.x 增加一个步长 s（即每像素的增量），w0 的新值就是：


w0_new = (b.x - a.x) * (c.y - a.y) - (b.y - a.y) * (c.x + s - a.x);

用新式子减去原式子，可得：


w0_new - w0 = -(b.y - a.y) * s;

由于 -(b.y - a.y) * s 对某个特定三角形是常量（因为 s 是固定的增量，a 与 b 也是常量），我们可以只算一次，把它存为 w0_step。于是计算就简化为：


w0_new = w0 + w0_step;

这一调整同样可以用于 w1 与 w2，也适用于 c.y 方向的步长。

原本边函数需要 2 次乘法与 5 次减法，经过这个优化，可以简化为一次加法，只是要先算出初始值。这个技巧在网上讨论得很多。本课程中我们不会用它，但打算将来专门讲高级光栅化技术的那门课里进一步探讨并实现它。

定点坐标

结束本节之前，简单说说在进入光栅化阶段前把顶点坐标从浮点格式转成定点格式这项技术。「定点」本质上就是整数表示的术语说法。顶点坐标从 NDC 转到光栅空间时，同时也从浮点数被转成定点数。为什么要这么做？答案并不直白，但本质上，GPU 使用定点算术是因为通过逻辑位运算处理整数，在计算上比处理 float 或 double 更容易、更快。这个解释相当笼统；从浮点坐标到整数坐标的转换，以及用整数坐标实现光栅化，涵盖的内容广泛而复杂，网上却几乎找不到文档，考虑到它在现代 GPU 功能中的核心地位，这挺令人意外的。

这个转换要把顶点坐标四舍五入到最近的整数。不过只做这一步，顶点坐标可能会过于贴近像素的角点，对静帧来说这是个小问题，但在动画中会造成视觉瑕疵（顶点可能逐帧对齐到不同的像素）。解决方案是把数转成最小的整数值，同时留出一些位来表示顶点的子像素位置（即顶点位置的小数部分）。通常 GPU 会分配 4 位给子像素精度。对一个 32 位整数来说，可能 1 位用于符号，27 位用于顶点的整数位置，4 位用于顶点在像素内的小数位置。这种安排意味着顶点位置被「对齐」到 16x16 子像素网格最近的角点上，如图 8 所示。虽然顶点仍被吸附到网格上，但这个方法比起对齐到像素坐标问题要小。这个过程还带来其他挑战，其中包括整数溢出——因为整数能表示的范围比浮点数窄，就可能发生溢出。此外，整合抗锯齿又增加了复杂性。要把这个话题讲透，得另开一门课。

定点坐标能加快光栅化过程与边函数的计算。这种效率正是把顶点坐标转成整数的一个关键原因，这门技术我们会在即将推出的一门课里进一步讨论。

float t, b, l, r; 

computeScreenCoordinates( 
    filmApertureWidth, filmApertureHeight,

    nearClippingPlane,

  • convertToRaster 函数把三角形顶点坐标从相机空间转到光栅空间，相当于前一门课里的 computePixelCoordinates 函数。记住，我们学过一种把屏幕空间坐标转到 NDC 空间（在 GPU 领域坐标范围是 [-1,1]）的方法。这里用的是同样的重映射方法。与前面几门课的一个重要区别是：投影后的点现在必须是三维点，其 x、y 坐标表示该点在屏幕空间中的投影位置，z 坐标则反映顶点在相机空间中的 z 坐标。这个 z 坐标对解决可见性问题至关重要，详见第四章。

    
convertToRaster(v0, worldToCamera, l, r, t, b, nearClippingPlane, imageWidth, imageHeight, v0Raster); 
convertToRaster(v1, worldToCamera, l, r, t, b, nearClippingPlane, imageWidth, imageHeight, v1Raster); 
convertToRaster(v2, worldToCamera, l, r, t, b, nearClippingPlane, imageWidth, imageHeight, v2Raster);

  • 记住，与三角形顶点相关的所有顶点属性，也需要用顶点的 z 坐标做「预除」，以实现透视正确插值。这通常在渲染三角形之前（紧接像素遍历循环之前）进行。不过在代码里，顶点的 z 坐标被设成了它的倒数（以便用乘法而非除法来加速深度计算）。

    
// 预先算好顶点 z 坐标的倒数
v0Raster.z = 1 / v0Raster.z, 
v1Raster.z = 1 / v1Raster.z, 
v2Raster.z = 1 / v2Raster.z; 

Vec2f st0 = st[stindices[i * 3]]; 
Vec2f st1 = st[stindices[i * 3 + 1]]; 
Vec2f st2 = st[stindices[i * 3 + 2]]; 

// 透视正确插值所需
st0 *= v0Raster.z, st1 *= v1Raster.z, st2 *= v2Raster.z;

  • 这个函数包含两个循环：外层循环遍历场景中所有三角形，内层循环遍历包围盒内与当前三角形重叠的所有像素。值得注意的是，内层循环里有些变量是常量，因此可以预先算好，包括三角形顶点 z 坐标的倒数（对覆盖该三角形的每个像素做线性插值），以及需要除以各自 z 坐标的顶点属性。

    
// 外层循环：遍历三角形
for (uint32_t i = 0; i < ntris; ++i) {
    ...
    // 内层循环：遍历像素
    for (uint32_t y = y0; y <= y1; ++y) { 
        for (uint32_t x = x0; x <= x1; ++x) {
            ...
        }
    }
}

  • 每个像素都用边函数技术做一次覆盖测试。若某个像素覆盖了三角形，我们就计算它的重心坐标，再确定采样点的深度。通过深度缓冲测试后，就可以用新的深度值更新深度缓冲，并用三角形的颜色更新帧缓冲。

    
Vec3f pixelSample(x + 0.5, y + 0.5, 0); 
float w0 = edgeFunction(v1Raster, v2Raster, pixelSample); 
float w1 = edgeFunction(v2Raster, v0Raster, pixelSample); 
float w2 = edgeFunction(v0Raster, v1Raster, pixelSample); 
if (w0 >= 0 && w1 >= 0 && w2 >= 0) { 
    w0 /= area; 
    w1 /= area; 
    w2 /= area; 
    // 线性插值采样点深度
    float oneOverZ = v0Raster.z * w0 + v1Raster.z * w1 + v2Raster.z * w2; 
    float z = 1 / oneOverZ; 
    // 通过深度缓冲测试了吗？
    if (z < depthBuffer[y * imageWidth + x]) { 
        depthBuffer[y * imageWidth + x] = z;
        // 更新帧缓冲
        ...
    }
}

  • 着色技术：为了让画面更有看头，我们用了好几种着色方法。模型有一个顶点属性：st，也就是纹理坐标。这些坐标可以生成棋盘格图案，再配合一种叫朝向比的简单着色技术。朝向比是三角形法线（由两条三角形边叉积算出）与视线方向的点积。视线方向是从三角形上正在着色的点 P 指向相机位置 E 的向量。在相机空间中——现在所有点都在这个空间里定义——相机位置就是 E=(0,0,0)，于是视线方向就是 -P，然后要做归一化。由于点积可能为负，我们把它夹到只取正值。

    
Vec3f n = (v1Cam - v0Cam).crossProduct(v2Cam - v0Cam); 
n.normalize(); 
Vec3f viewDirection = -pt; 
viewDirection.normalize(); 
// 朝向比 
float nDotView =  std::max(0.f, n.dotProduct(viewDirection));

    这项技术需要算出 P（即像素所重叠的三角形上那一点）的坐标，做法跟其他任何顶点属性一样。我们取相机空间中的顶点，除以它们的 z 坐标，用重心坐标插值，再把结果乘以采样点的深度（顺便说一句，这也正是 P 的 z 坐标）：

    
// 取得相机空间中的三角形顶点。
Vec3f v0Cam, v1Cam, v2Cam; 
worldToCamera.multVecMatrix(v0, v0Cam); 
worldToCamera.multVecMatrix(v1, v1Cam); 
worldToCamera.multVecMatrix(v2, v2Cam); 

// 与任何其他顶点属性一样除以各自的 z 坐标，
// 再用重心坐标做插值。
float px = (v0Cam.x/-v0Cam.z) * w0 + (v1Cam.x/-v1Cam.z) * w1 + (v2Cam.x/-v2Cam.z) * w2; 
float py = (v0Cam.y/-v0Cam.z) * w0 + (v1Cam.y/-v1Cam.z) * w1 + (v2Cam.y/-v2Cam.z) * w2; 
 
// P in camera space
Vec3f pt(px * z, py * z, -z);

  • 帧缓冲输出：最后，帧缓冲的内容被保存成 PPM 文件，展示渲染结果。

再补一个有意思的点：我们把图像每个像素所重叠的三角形上那一点的世界空间位置导了出来，在 3D 查看器里显示所有这些点。毫不意外，点只出现在相机直接可见的物体部位上，这印证了深度缓冲技术的有效性。第二张图是同一组点的特写（右侧）。

结论

光栅化的主要优点是简单和快，尽管它主要只用来解决可见性问题。记住，渲染包含两步：可见性与着色。这个算法不提供任何着色方案。

练习

  • 实现抗锯齿：把像素细分为 4 个子像素，在每个子像素中心生成一个采样，对每个采样做覆盖测试，把各采样的颜色求和，除以 4，再把结果设为像素颜色。这项技术的一个实现可以在讲纹理映射的课程里找到。

  • 实现背面剔除：若三角形的法线与视线方向的点积低于某个阈值，就不渲染该三角形。这利用的原理是：方向相反的向量点积为负。两个向量的点积等于它们夹角的余弦。把阈值表示为以度为单位的夹角。

  • 把 z 缓冲的内容输出到 PPM 文件，将深度缓冲的值重映射到 [0,255] 范围。
