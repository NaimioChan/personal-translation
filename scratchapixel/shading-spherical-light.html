球形光源

阅读时间：11 分钟。

如上一章所述，这里只是对光照与阴影的一个高层次入门。想进一步研究这个题目的读者，可以去读 深入 BRDF、线性与曝光 和 光照简介 这两门课。它们虽然同属入门部分，但对光的实现讲得更深。之后你可以接着读进阶部分的课程。

本章结构

本章我们将学习如何模拟球形（或点）光源，以及如何用球形光源投射阴影。

球形光源

我们已经介绍过平行光源的概念，它可以用来模拟太阳这类遥远的光源。平行光源是距离场景如此之远、以至于其发出的光线可以视为彼此平行的光源。换句话说，一个遥远的光源只沿一个方向发出光线。

球形光源则不同。它们不像平行光源那样遥远，而是局部的。球形光源可以表示为 3D 空间中的一个光点，光从该点沿径向向外发射。因此，它们也常被称为点光源。点光源可以用来模拟烛焰或灯泡之类的东西。不过，正如讲平行光源的那一章所提到的，球形光源或点光源也被认为是没有大小的光源。换句话说，我们把它们建模为空间中的一个理想点，光从该点沿径向发出，但这样的物体在自然界中并不存在。烛焰或灯泡确实可能沿径向发光，但它们是有大小的。眼下这不成问题，但要记住：到目前为止，我们的光源在尺寸上都被视为无穷小。这类光源常被称为delta 光源，详见讲 光源 的入门章节。当球形光源向所有方向等量发光时，我们说它是各向同性的。

那怎么模拟点光源呢？首先，要考虑光的发射方式：沿径向。从编码角度看，只需从正在着色的点（\(P\)）向球形光源的位置连一条线，就能模拟这一点。这条线就给出了点光源射向 \(P\) 的光线方向，如图 1 所示。

从编码角度看，定义一个点光源只需在 Light 基类里加一个成员变量来记录它在空间中的位置。我们假定点光源创建于世界坐标系的原点。要修改它在 3D 空间中的位置，我们使用 light-to-world 变换矩阵（就像修改平行光源的方向时那样）：


class PointLight : public Light 
{ 
public: 
    Vec3f pos;  // 光源在世界空间中的位置              
    PointLight(const Matrix44f &l2w, const Vec3f &c = 1, const float &i = 1) : Light(l2w, c, i) 
    { l2w.multVecMatrix(Vec3f(0), pos); } 
};

由于光线方向取决于 \(P\) 的位置和光源在 3D 空间中的位置，我们给 Light 基类加一个 getDirection() 函数。这个函数接收点 \(P\) 作为参数，返回归一化后的光线方向。对平行光源，这个方向是恒定的；对球形光源，必须显式算出：


class PointLight : public Light 
{ 
public: 
    Vec3f pos; // 光源的位置           
    PointLight(const Matrix44f &l2w, the Vec3f &c = 1, the float &i = 1) : Light(l2w, c, i) 
    { l2w.multVecMatrix(Vec3f(0), pos); } 
    // P：着色点             
    Vec3f getDirection(const Vec3f &P) const { return (pos - P).normalize(); } 
};

球形光源与平行光源还有一个方面不同。先看点光源。如本章前面所述，球形光源从空间中的一个点发光。从该点发出的光能分布在一个球面上，如图 2 所示。这里不深究细节（那需要更透彻地理解辐射度量学），暂且只说明：点光源的全部光能或功率被重新分布到这个球面上。与漫反射表面类似，到达一小块微分面积 \(dA\) 上的光的量，大致正比于半径为 \(r_1\) 的球面上、面积约等于 \(dA\) 的一小块中所含的光的量，如下图所示。不过，正如同一张插图所示，随着球面扩大，与微分面积 \(dA\) 面积相匹配的那块微分立体角 \(d\omega\) 的面积也变大了。换句话说，原本集中在 \(d\omega\) 上的能量，现在散布在更大的面积上。因此，\(P_2\) 接收到的光比 \(P_1\) 少，换个说法，\(P_2\) 看起来会比 \(P_1\) 暗（\(P_2\) 接收到的光量正比于绿色立体角除以红色立体角）。

用任何真实的点光源（比如灯泡）都很容易观察到这个效果。离光源越近的物体越亮。光源的贡献似乎随着物体到光源距离的增大而减小。现在的问题是要确定这种衰减由什么决定。

从点光源到达场景中某一点的光能量，取决于那个「球面」的面积，而面积本身又取决于球的半径。注意这个球面实际上并不存在，我们只是用这个图像帮你想象这个过程。说到球面时，我们实际指的是一种虚拟球面，它以光源所在点为中心，半径等于从光源到 \(P\)（我们想着色的场景中一点）的距离。我们要确定的是从那个光源点有多少光到达 \(P\)。如前面所说，点光源的贡献取决于半径为 \(r\) 的球面面积：

$$A = 4\pi r^2.$$

到达 \(P\) 的光强与球面面积成反比。也就是说：

$$L_i = \dfrac{\text{light intensity * light color}}{4 \pi r^2}.$$

更正式的说明请参阅讲辐射度量学的课程。

其中 \(r\) 等于光源位置与 \(P\) 之间的距离。这种衰减在 CG 中叫作平方衰减。注意，当球的半径翻倍时（也就是点光源到 \(P\) 的距离翻倍时），球面面积变为 4 倍，于是光的贡献变为四分之一。更一般地，这类光衰减遵循我们所说的平方反比定律。这种衰减的曲线见下图。

从这张图可以看到，点光源的贡献随距离衰减得非常快。

为实现这种平方衰减，我们对 getDirection 方法做一点小改动，并把它改名为 getDirectionAndIntensity。你可能已经猜到，计算给定 \(P\) 处的光强也在这里做。之所以放在一起，是因为我们在这个方法里本来就要计算连接光源与 \(P\) 的向量，以得到光线方向。我们可以用这个向量长度的平方，按平方反比定律衰减光强（第 13 行）：


class PointLight : public Light 
{ 
    Vec3f pos; // 光源的位置           
public: 
    PointLight(const Matrix44f &l2w, const Vec3f &c = 1, const float &i = 1) : Light(l2w, c, i) 
    { l2w.multVecMatrix(Vec3f(0),

 pos); } 
    // P：着色点             
    void getDirectionAndIntensity(const Vec3f &P, Vec3f &lightDir, Vec3f &lightIntensity) const 
    { 
        lightDir = pos - P;  // 计算光线方向            
        float r2 = lightDir.norm(); 
        lightDir.normalize(); 
        lightIntensity = intensity * color / (4 * M_PI * r2); 
    } 
};

球形光源与阴影

用球形光源计算阴影相当直接，可以用与平行光源类似的办法。我们只需算出光线方向，再沿反方向投一条光线。光线方向很容易算：从光源向着色点 \(P\) 连一条线，把得到的向量归一化，就得到了光线方向：


class PointLight : public Light 
{ 
    Vec3f pos; 
public: 
    PointLight(const Matrix44f &l2w, const Vec3f &c = 1, const float &i = 1) : Light(l2w, c, i) 
    { l2w.multVecMatrix(Vec3f(0), pos); } 
    // P：着色点             
    void getDirectionAndIntensity(const Vec3f &P, Vec3f &lightDir, Vec3f &lightIntensity) const 
    { 
        lightDir = pos - P; 
        float r2 = lightDir.norm(); 
        lightDir.normalize(); 
        lightIntensity = intensity * color / (4 * M_PI * r2); 
    } 
};

不过有一个需要注意的地方。按定义，平行光极其遥远——被视为位于无穷远。球形光源则不然。如果我们沿光的方向投出阴影光线，这条光线完全可能越过点光源，与比光源更远的物体相交。这就会错误地表明该点处在阴影中，而实际上 \(P\) 与光源彼此可见（如图 3 所示）。解决办法是把光线的最大长度即 \(tNear\) 设为 \(P\) 到光源位置的距离（也就是我们记作 \(r\) 的那个距离）。这样 trace() 函数就永远不会接受距离大于 \(r\) 的交点。换句话说，如果找到了交点，但交点距离比 \(P\) 到光源的距离更远，那么这个交点就会被忽略。既然我们已经在 getDirectionAndIntensity() 函数里算过该距离的平方，只需给这个方法加一个变量，让它存放 \(P\) 到光源的距离：


class PointLight : public Light 
{ 
    Vec3f pos; 
public: 
    PointLight(const Matrix44f &l2w, const Vec3f &c = 1, const float &i = 1) : Light(l2w, c, i) 
    { l2w.multVecMatrix(Vec3f(0), pos); } 
    // P：着色点             
    void getShadingInfo(const Vec3f &P, Vec3f &lightDir, Vec3f &lightIntensity, float &dist) const 
    { 
        lightDir = pos - P; 
        // 计算距离的平方             
        float r2 = lightDir.norm(); 
        dist = sqrtf(r2); 
        // 归一化入射光线方向                        
        lightDir.x /= dist, lightDir.y /= dist, lightDir.z /= dist; 
        // 应用平方衰减        
        lightIntensity = intensity * color / (4 * M_PI * r2); 
    } 
};

然后把阴影光线的 \(tNear\) 变量设为 dist 的结果。如果我们把 isectShad.tNear 变量直接传给光源的 getShadingInfo() 方法，这可以直接做到（顺便可以把方法名改得更通用一些）。


IsectInfo isectShad; 
light-&gtgetShadingInfo(hitPoint, lightDir, lightIntensity, isectShad.tNear); 
bool vis = !trace(hitPoint + hitNormal * options.bias, -lightDir, objects, isectShad, kShadowRay);
