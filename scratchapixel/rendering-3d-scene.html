接下来是一个 3D 场景

在深入渲染之前，先弄清楚我们在渲染什么、在观察什么，这很关键。没有可看的东西，本质上也就没有可渲染的东西。

现实世界由形状、外观、结构千差万别的物体组成。想想烟、一把椅子、海水这三者的区别。在计算机图形学中，物体通常被分成实体与非实体两类。但在现实世界里，区分这两种状态的，是构成物体的物质的密度。烟由松散相连的分子组成，分子之间隔着一大片空隙；而椅子里的木材，分子密集地塞在尽可能小的体积里。不过在计算机图形学里，我们通常只需要定义物体的外部形状（非实体物体的渲染会在本系列后面讲到）。我们是怎么做到的？

在上一课*我该从哪里开始？计算机图形学编程轻松入门*里，我们介绍了在计算机内存中定义形状的概念，从 3D 空间中「点」这个最基本的概念讲起。一般来说，一个点在计算机内存里表示为三个 float，分别对应笛卡尔坐标系的三个轴：x、y、z。由此，我们可以在空间中定义多个点，把它们连接起来勾勒出一个表面（一个多边形）。要注意，多边形应当总是共面的，也就是说构成一个面或多边形的所有点都应位于同一个平面上。用三个点，你可以做出最简单的形状：三角形。三角形无处不在，在光线追踪里尤其如此，因为人们已经发展出多种技术，可以高效地计算一条直线与一个三角形的交点。当一个面或多边形多于三个点（也叫顶点）时，通常会把这样的面转换成三角形，这个过程叫作三角化。

为什么把几何转成三角形有好处，我们后面再解释；其要点是：三角形代表你能创建的最简单的表面或物体。单独一个三角形也许没什么用，但把多个三角形拼起来，就能造出更复杂的形状。在很多方面，这个过程就像用砖块砌出更精巧的形状与表面。

必须承认：世界本身并不是多边形的；这只是为了数字化表示与渲染而做的简化。

很多刚接触计算机图形学的人常常会问：既然三角形本身是平的、带尖角的，怎么能用三角形构造出曲面？首先必须明白，我们在图形学里用三角形或多边形定义物体表面的方式，本身就是对现实的一种简化表示。在我们眼中看似平坦的表面，比如一面墙，在微观层面上却极其复杂。物体的微观结构会显著影响它们的外观，但不一定影响它们的整体形状——这是个值得记住的有趣之处。

回到主要问题：用三角形或多边形确实不是表示曲面的最优方法。这种做法会让物体带上棱面感，有点像切割过的钻石。这种棱面外观可以用一种叫平滑着色的技术稍微缓解，但平滑着色只是一种视觉上的把戏。着色技术我们会在后面几课深入讲。如果你画一条光滑曲线，可以沿曲线放几个点，再用直线段把这些点连起来，从而逼近这条曲线。要改进这种逼近，只需把线段变短，也就是沿曲线造出更多点。沿光滑表面放置点或顶点的这个动作叫作采样，而把光滑表面转成三角网格则叫作曲面细分。本章后面我们会探讨光滑表面如何定义。同样，在 3D 形状中，造出更多、更小的三角形，就能更好地逼近曲面。但增加几何量（或三角形数）必然拉长渲染时间。所以渲染这门手艺，常常要在「用多少几何细节去逼近物体曲度」与「渲染这个 3D 模型要花多久」之间取得平衡。一个 3D 模型所包含的几何细节还取决于它在图像中的远近。物体越近，需要的细节越多。管理模型复杂度是图形学中一个庞大的研究领域，其中大量工作致力于寻找自动或自适应的方法，根据物体到相机的距离或物体曲度来调整它的三角形数量。

本质上，用多边形或三角形渲染一个完美的圆或球是不可能的。但要记住：计算机和显示器都以离散结构运作。如果形状最终要显示在光栅屏幕上，渲染器就没有必要把它渲染得完美。一个由来已久的解法是使用比像素还小的三角形，让观察者分辨不出图元的三角形性质。这条原理已被广泛应用于高质量渲染软件，比如 Pixar 的 RenderMan，近来也通过曲面细分过程进入了实时应用。

多边形网格因其简单而流行（多数 CG 剧情片或电子游戏里的物体都是用这种方式定义的），但在为曲面或有机表面建模时效果较差。随着汽车这类工业产品的计算机辅助设计（CAD）出现，这就成了一个大问题。NURBS 与细分曲面正是为克服这一局限而发展出来的。这些技术基于这样一个观念：点只是定义一个控制网格，从这个网格可以用数学算出一个完美的曲面。曲面本身是某个公式的结果，无法直接渲染；控制网格也不行，它只是算法的输入。它需要采样，类似前面提到的曲线采样过程（构成基础网格或输入网格的点通常叫作控制点）。这些技术的优点之一是：控制一个完美光滑的曲面所需的点更少，而这个曲面随后又能转成比原始输入控制网格更平滑的三角网格。虽然用多边形也能做出曲面，但与用 NURBS 和细分曲面那样只用几个点定义相似形状相比，编辑多边形更费时、也更不精确。既然这些技术更优越，为什么没有被普遍采用？它们其实几乎无处不在，只是渲染成本比多边形网格略高，因为需要多一步，从控制网格生成多边形网格。因此在电子游戏里用得较少（不过很多游戏引擎都实现了它们，比如 Unity、Unreal Engine、Cry Engine），但在电影里被广泛使用。NURBS 比多边形网格更难操作一些，所以美术师更偏爱细分曲面，不过 NURBS 因其精度在设计领域与 CAD 中依然有价值。NURBS 与细分曲面都会在几何部分探讨。后面的一课里，我们还会考察 Bezier 曲线与曲面，它们与 NURBS 有相似之处，用来渲染标志性的 Utah Teapot。

需要澄清的是：NURBS 与细分曲面是两种不同的东西。NURBS 由数学公式定义，属于参数曲面这一族。而细分曲面则是把某个过程施加到输入网格上、通过递归细分使其表面变平滑所得的结果。这两种技术在几何部分都有详述。

多数情况下，3D 模型是手工制作的，也就是由某个人在 3D 空间中创建顶点，再把它们连起来构成物体的面。但模拟软件也可以用来生成几何。这种做法通常用于生成水、烟或火这类元素。专门的程序会模拟流体的运动，再根据模拟结果生成多边形网格。对于烟或火，程序不生成表面，而是创建一个三维网格（一块被划分成等距单元的长方体或立方体空间，这些单元也叫体素）。每个网格单元代表一小块空间体积，它可能是空的，也可能被烟占据，主要由其密度来定义。密度用一个 float 表示，考虑一个 3D 网格，512x512x512 的网格大约占 512Mb 内存。这个尺寸增长得很快，因为还可能要存温度或颜色之类的附加数据，而且网格分辨率每翻一倍，内存需求就增加为原来的八倍（比如 1024x1024x1024 的网格需要 4Gb 存储）。流体模拟计算量大，生成的文件也大，而且体积渲染一般比渲染实体物体更费时，因为它需要一种专门的算法，叫作光线步进，后面的章节会介绍。上图（图 6）展示了在 Maya 里创建的一个 3D 网格的截图。

使用光线追踪时，并不一定需要把物体转换成多边形表示才能渲染。光线追踪计算的是光线（本质上就是直线）与场景几何的交点。判断一条光线是否与某个几何形状相交，有时可以用数学方法做到，途径有两种：

  • 一种几何解法，或者，

  • 光线与物体求交测试的一种代数解法。当物体的形状可以用一个公式在数学上定义时，这就是可行的，这个公式通常表示空间中的一个曲面（比如球体的表面）。这类曲面叫作隐式曲面（或代数曲面），因为它们是由一个函数隐式定义的。看下面这个线性方程组的例子：

    $$ \begin{array}{l} y = 2x + 2\\ y = -2x\\ \end{array} $$

    旁边的图把这两个公式画了出来。要判断这两个公式所定义的直线是否交于一点，它们必须共享同一个 x 值、并由此得到相同的 y 值，写成：

    $$ 2x + 2 = -2x $$

    解出 x 得：

    $$ \begin{array}{l} 4x + 2 = 0\\ 4x = -2\\ x = -\dfrac{1}{2}\\ \end{array} $$

    既然光线也可以用公式定义，那么光线与物体形状的两个公式就可以像任何线性方程组一样求解。若有解，光线就与该物体相交。

球体就是一个典型例子：它与光线的交点既可用几何方法、也可用代数方法求出，详见渲染简单形状那一课。

参数曲面与隐式曲面的区别是什么

前面我们提到，NURBS 与细分曲面也是用数学定义的。但 NURBS 与隐式曲面之间有一个关键区别（细分曲面是另一种情况，它是对基础网格做处理，得到更平滑、分辨率更高的网格）。NURBS 由参数方程定义，是一个或几个参数的函数。在 3D 中，这个公式一般写成：

$$ f(u,v) = (x(u,v), y(u,v), z(u,v)) $$

其中参数 u 与 v 的取值范围通常是 0 到 1。而隐式曲面则由一个关于三个变量 x、y、z 的多项式定义：

$$ p(x, y, z) = 0 $$

举例来说，一个以原点为中心、半径为 R 的球体，可以参数化地定义为：

$$ f(\theta, \phi) = (\sin(\theta)\cos(\phi), \sin(\theta)\sin(\phi), \cos(\theta)) $$

其中用 \(\theta\) 与 \(\phi\) 分别替代 u 与 v，且 \(0 \leq \theta \leq \pi\) 与 \(0 \leq \phi \leq 2\pi\)。同一个球体用隐式方式定义则是：

$$ x^2 + y^2 + z^2 - R^2 = 0 $$

隐式曲面在建模中非常有用，但已不像从前那么常见了。用隐式曲面可以造出更复杂的形状（把球体、立方体、圆锥等隐式图元通过布尔运算组合起来），这门技术叫作构造实体几何（或 CSG）。由 Jim Blinn 在 1980 年代早期发明的 Metaball，是另一种用来创建有机形状的隐式几何。

隐式曲面的麻烦在于它们不好渲染。虽然常常可以直接对它们做光线追踪（用前面说的代数方法计算光线与隐式曲面的交点），但它们必须先转换成网格。这个转换过程不像 NURBS 或细分曲面那样直接，需要专门的算法，比如 Lorensen 与 Cline 在 1987 年提出的移动立方体算法。这个转换可能产生很重的网格。

这些题目的更多细节，见几何部分。

以三角形作为渲染图元

在本系列课程中，我们会通过光线与球体求交来研究一个隐式曲面的例子。我们也会考察一个参数曲面——使用 Bezier 曲面的 Utah Teapot。但多数渲染 API 一般会把不同的几何类型都转换成三角网格，再渲染这个网格。这种做法有几个好处。要支持多边形网格、隐式曲面、参数曲面等多种几何类型，就得为每种支持的表面类型写一套光线与物体求交的例程。这需要更多代码（缺点显而易见），也让这些例程很难整合进一个通用框架，往往还会拖低渲染引擎的性能。

记住，渲染不只是渲染 3D 物体，它还要支持运动模糊、置换等功能。要支持多种几何表面，就意味着每一种表面都得与整套受支持的功能配合工作，这比把所有表面都转换成同一种渲染图元、让所有功能只跟这一种图元打交道要难得多。

一般来说，把代码限制为只渲染一种图元能获得更好的性能，因为这样可以把全部精力集中在高效渲染这一种图元上。三角形一直是光线追踪的首选。人们做了大量研究，想找出计算光线与三角形交点的最佳算法，追求最快执行、最少内存占用和最稳定。其他渲染 API 也只渲染三角形，比如 OpenGL，尽管它并不使用光线追踪算法。现代 GPU 一般就是围绕基于三角形的单一渲染方式设计与优化的。有人幽默地说：

因为现在的 GPU 是为处理三角形而设计的，所以人们用三角形，于是 GPU 只需要处理三角形，于是它们的设计就只盯着三角形。

限制为一种图元，就可以把常用操作直接做进硬件，让硬件在执行这些操作时极为高效。三角形有诸多好处，包括共面、易于细分、不可再分，以及在三角形上插值纹理坐标很简便。不过这并不意味着 GPU 不能被设计成高效渲染其他类型图元（比如四边形）。

我可以用四边形代替三角形吗？

三角形并不是渲染中唯一使用的图元，四边形也可以用。生成细分曲面的建模或曲面算法以四边形为工作单位，所以四边形在 3D 模型里很常见。如果四边形能像三角形那样高效渲染，那就没必要做三角化了。即便在光线追踪里，四边形有时也比三角形更可取，况且还能避免对本来就由四边形构成的模型做多余的三角化。四边形光线追踪会在光线追踪的进阶部分讲到。

3D 场景不只是几何

不过，一个 3D 场景不只是几何。几何是关键要素，但看场景还得有相机。所以场景描述通常包含一台相机。而且，没有光的场景看起来是黑的，因此还得加入光源。在渲染中，所有这些信息（几何、相机、光源）都被装在一个叫作场景文件里。3D 场景的内容也可以载入 Maya 或 Blender 这类 3D 软件的内存里。这种情形下，当用户发起渲染时，一个专门的程序或插件会处理场景中的每个物体和每盏灯，并把所有内容（包括相机）直接导给渲染器。此外，渲染器还需要一些额外信息，比如最终图像的分辨率，通常称为全局渲染设置或选项。

小结

本章你该记住的是：在生成一张 3D 场景的图像之前，先弄清场景由哪些部分组成很必要。一个场景需要包含三样东西：几何（一个或多个 3D 物体）、光源（没有光场景就是黑的），以及相机，用来定义观察的透视关系。虽然描述几何可以用各种技术（多边形网格、NURBS、细分曲面、隐式曲面等），而且每一种都能用相应的算法直接渲染，但只支持一种渲染图元更简单也更高效。在光线追踪中和现代 GPU 上，三角形是首选的渲染图元。因此，几何一般在渲染前会被转成三角网格。
