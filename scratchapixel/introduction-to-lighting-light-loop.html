直接光照：光源循环

阅读时间：15 分钟。

直接光照：光源循环

正如本课开头提到的，我们迄今对光源所做的，都是计算它们对场景中某一点照明的直接贡献。这一部分称为直接光照，与之相对的是间接光照，后者处理的是着色点从场景中其他表面接收到的光有多少。间接光照的产生，是因为光不仅来自光源，还会在表面之间来回弹射。你可以把整个现象想象成网球或台球：球要么直接砸到你（那可能很疼），要么在撞过地板、球场围网边、或周围任何硬表面弹了几次之后才砸到你。直接命中类比于直接光照，而弹了几次之后被砸到则算作间接光照。再说一次，本课一直只关注直接光照，也就是那些能「看见」光源、并且直接暴露在射向它们的光之下的点。当然，可能有别的物体挡在这些点前面，那样它们就处在该光源的阴影里了。

这就是我们迄今研究的内容。我们只孤立地研究了单一种类光源的效果，而且主要关注的还是场景中只有一盏灯时的情况。然而，大多数典型的生产场景都有多种光源类型和多盏灯。那要怎么处理？这就是我们在这最后一章要看的。回想起来，我觉得有点奇怪，我竟决定用这个话题来收尾本课，因为从头就讲它可能更好。不过其中必有我还没看清的理由。

光能量总体上、特别是物体反射多少能量这一点，遵循线性规律。换个说法：无论物体接收到多少光（或光能量），它反射的都是所接收光的某个百分比。物体反射的光量往往还是观察方向的函数；换句话说，物体并非向各个方向均等地反射光。这一点只对纯漫反射物体成立，而这正是本课迄今的假设。不过，等我们后面讨论着色器和 BRDF 时你会看到，现实中的大多数物体都不是完美的漫反射表面。它们通常在把更多光重定向到某些方向上有所「偏好」。这些偏好方向一般源于物体材质的宏观结构，但我们会在讲 BRDF 与着色器的课程里详述。

现在先假定是完美漫反射表面，也就是光在着色点法线所定的半球内各个方向上都均等地反射。

那么，如果在该半球内某个给定方向（或某个极小的方向锥）上，物体在该点每接收 100 单位能量就反射 1 单位能量，那么当物体在同一点接收的光能量翻倍（即 200 单位）时，它在该方向上就反射 2 单位能量。如果接收三倍（300 单位），就反射三倍（3 单位），以此类推。这个效果是纯线性的。

这就简化了计入多盏光源贡献的过程，因为我们只需以纯线性的方式累加每盏灯的贡献，这在数学上就等于用一个加号。我们会把着色点反射回场景的光量——即第一章提到过的出射辐射亮度——初始化为 0。

在代码里，这件事是通过我们在渲染中称为光源循环的循环完成的。这个循环遍历场景中所有光源，计算它们各自的贡献，并把这个贡献累加到出射辐射亮度上（我们一开始把它设为 0）。它定义在我们 Integrator 类的 Li 方法里。


Vec3f Li(const Ray& ray, const std::unique_ptr&ltScene>& scene) {
	...
	Vec3f L = 0; // 初始化为 0
    ...
	size_t num_samples = 512;
	for (size_t i = 0; i < scene-&gtlights_.size(); ++i) { // 光源循环
		Vec3f L_light = 0;
		for (size_t n = 0; n < num_samples; ++n) { // 遍历所有样本
			LightSample ls;
			ls.L = scene-&gtlights_[i]-&gtSample(dg, ls.wi, ls.tmax, Vec2f(rand() / (float)RAND_MAX, rand() / (float)RAND_MAX));
			if (ls.L == 0 || ls.wi.pdf == 0 || dg.Ng.Dot(Vec3f(ls.wi)) <= 0.f) continue;
			bool in_shadow = [&]() -> bool {
				for (size_t i = 0; i < scene-&gtnum_triangles_; ++i) {
					if (Occluded(Ray(dg.P, ls.wi, dg.error * espsilon_, ls.tmax - dg.error * espsilon_), tris[i], vertices))
						return true;
				}
				return false;
			}();
			if (in_shadow) continue;
			L_light += 1 / M_PI * ls.L * dg.Ng.Dot(Vec3f(ls.wi)) / ls.wi.pdf;
		}
		L += L_light / num_samples;
	}

	return L;
}

换个角度看这件事，可以设想你要渲染一个有三级光源的场景会怎么做。你可以每盏灯渲染一张图，然后在合成软件里把这些图相加（见下图）。这与直接渲染三灯场景、在光源循环里把它们的贡献相加，效果相同。

这里的要点是：图像中物体的亮度会随场景中光能量的多少线性地增减。因此这些公式必须保持这种线性性质（不能通过任何非线性处理影响最终的像素颜色），这很重要。顺便说一句，输出未经处理的图形图像被归类为原始（raw）图像。有些软件可以给这种图像施加伽马曲线，好让它能在本身会施加反向伽马曲线的屏幕上线性显示（或接近线性）。这个话题在数字图像：从文件到屏幕那门课里讨论。

你可能会问，Integrator 是什么，以及这个函数为什么叫 Li，而不是比如 CalculateOutgoingRadiance。两个问题都问得有理。

积分器这个词指的是这样一类算法：它负责用 Monte Carlo 积分方法，结合着色点处的表面属性（比如点的位置和法线），求光与构成物体的材质之间的相互作用（积分器这个叫法正来源于此）。换句话说，我们想用 Monte Carlo 积分来解决渲染问题中的着色部分；如果你还记得 Scratchapixel 前几课，这个部分大体可分为两个问题：可见性与着色。着色问题涉及确定有多少光从 \(\mathbf{x}\)（着色点）处法线所定半球的各个方向到达该点，以及这些光中有多少被重定向到观察者方向。在光线追踪这一特定情形下，常见的做法是用 Monte Carlo 积分方法，本课已让你窥见一斑。再总结一次，Monte Carlo 积分的思路是：我们可以在积分域（本例中是半球上或面光源表面上的点）中随机取点，对这些点上函数值取平均，从而算出任何函数的积分（本例中是渲染方程）。不必为此太担心，因为在专讲渲染方程、BRDF、着色器，以及各种旨在最好地估计光在场景中传播路径的算法的课程里，我们会研究这些细节（如我们将看到的，这是个复杂问题——至少当你不是自然本身、无法以光速做模拟的时候）。

至于 Li，我自己也觉得有点莫名其妙，但它在业界成了标准。我猜这个名字来自这样的事实：在这个特定情形下（就直接光照而言），入射辐射亮度正是通过光源循环在这个方法里被「收集」的。对间接光照，后面我们会看到需要扩展这个方法，先提一句，它涉及递归调用 Li。换句话说，你如果愿意，完全可以把这个方法叫 CalculateOutgoingRadiance，同样正确；但 Li 之所以留下来，大概是因为 PBRT、Embree 这类开源渲染项目采用这套约定，影响了别的开发者。如果你对这段历史了解更多，请告诉我们。由于类似项目常常反复使用同一个名字，我也决定沿用，以确保你能建立联系、明白它是什么。

不要把光源循环与光源样本循环搞混。在本课中，为了简单，我们一直是每盏灯生成多个光源采样方向来计算阴影，本例中任一特定面光源的光源样本数是硬编码的（上面代码里是 512）。在大多数现代生产级渲染器里，这并不是最常被选用的做法。常见的做法是每盏灯只投射一条光源采样光线，但每个像素多次调用 Li 方法。这意味着我们是每像素多个样本，而不是每盏灯多个光源样本。通过在大量像素样本上对贡献取平均，我们得到的结果与单次调用 Li 时投射许多光源样本相同。不过前一种做法（每像素多次调用 Li）还有别的好处，我们会在后续讲渲染方程和采样策略的课程里说明。

所以，还是那句话，在引入像素样本这个概念之前，我们暂时就满足于：为面光源投射若干个光源样本并对它们的贡献取平均，以此计算阴影。

多光源优化：向重要性采样问好

最后，我们想提一个本课不研究其实现的方法，因为那会离这个仍然是入门性质的话题太远。此外，虽然本课已经引入了与 Monte Carlo 积分方法相关的一些概念，但下面这项技术在某种程度上虽也依赖与 Monte Carlo 积分相同的原理，却建立在我们尚未讲过的知识之上。所以我们在这里只提一句它存在，至于详细研究，就看我们决定走哪条路：放到本课将来的修订版，还是放进第二部分。

如前所述，使用面光源的问题在于：即便计算机已经快到足以做光线追踪，它依然昂贵。如果靠做图形图像谋生的人——比如在 Pixar 这类工作室工作的那些人——不需要渲染动辄几千盏这种灯的场景，这倒也不算大问题。Pixar 的《寻梦环游记》里有一个场景大约有 29,000 盏灯。

要调整我们的代码去复现这个，相对容易，但我连浪费时间去走那条路的胆子都没有。没意义。要点是：场景可能包含很多（很多）光源，所以我们需要进一步优化。考虑到这 29,000 盏灯里可能只有少数几盏对某个像素的亮度有显著贡献，这一点就更重要了。那些非常亮但超远的，那些非常大但不太亮的，以及那些集齐了所有能想到的弱点——又小又远——的，计算起来都是浪费，因为它们对某一点的亮度实际上贡献很小。不过，从统计或数学的角度看，并不是因为贡献小就该彻底忽略它们。事实上，若那样做，你就引入了我们所说的偏差。总之，它们单个可能贡献很小，但如果你有几千盏灯、每盏给场景添一点点光，合起来就可能构成场景全局光照中相当大的一部分。没错。

那我们该怎么办？再说一次，这里不深入细节，总体思路是借助 Monte Carlo 方法的统计特性：你对光源采样，并把求值每盏灯的结果除以选中该灯相对于选中其他灯的概率。把这个「求值光源贡献的结果除以选中该光源的概率（PDF）」的思路，与我们在用 Monte Carlo 采样选择光源采样方向时把光源贡献除以采样光源形状所对应的 PDF，是类似的。这样做是为了确保赋予所选采样方向或所选光源的权重，能够补偿所有你未选到的其他方向或光源，从统计上使结果收敛到与采样所有方向或所有光源时相同的值。

这样想：如果你决定优先采样场景中功率大的那些灯，那么采样这类灯的 PDF 就会更大。也就是说（因为这就是你的目标），你会更可能采样到功率大的灯，而不是功率值被认为很小的灯。设想采样这类灯的 PDF 是 0.8，你求值其中一盏灯，并把它的贡献除以 0.8。再设想采样低功率灯的 PDF 是 0.2（采样这类灯的概率低于采样大功率灯的概率）。你有时（但不如采样亮灯那样频繁）会采到一盏暗灯。但这没关系，因为你会把它的贡献除以 0.2，实际上就是把它乘以 5，这就补偿了那些因你选定的 PDF 而较少被代表、因而未被采到的其他暗灯。一切抵消之后（要么采样所有灯，要么采样部分灯但把它们的贡献除以采样到它们的概率），最终你得到的结果与采样了所有灯相同（但你快得多）。当然，和所有 Monte Carlo 积分方法一样，这会给结果引入方差，在图像中表现为噪声（叠加在采样面光源形状所得的噪声之上）。但这就是权衡：你缩短了渲染时间，同时至少从统计上忠实于「若有无限算力本会得到的结果」，代价是图像中引入了噪声。我们都知道，世上没有完美的东西。

选择能满足多光源采样要求的 PDF，存在不同策略。最基本的一种是把每盏灯都视为同等，取 PDF 等于 \(1 / Nl\)，其中 \(Nl\) 表示场景中的光源数。虽然未必最好（这种方法会产生高方差），但如你所猜，它仍然有效，已经能帮你减少所使用的光源数量，同时仍给出一个（在多次运行后）会收敛到真实结果的结果。更聪明的策略是按光源的贡献来采样（即与贡献成正比），这项技术称为重要性采样（你给贡献最大的光源以重要性，同时至少从统计上仍考虑那些贡献较小的，通过把它们的贡献乘以更大的权重来补偿其较低的采样概率）。

这项技术在着色中很常见，在涉及材质、着色器和 BRDF 时也会用到，我们会在后续课程中讨论。
