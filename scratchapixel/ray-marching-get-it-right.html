光线步进：把它做对！

阅读时间：28 分钟。

内散射与外散射。

前面几章里，我们只计入了光束与构成介质的粒子之间两类相互作用：吸收与内散射。但要得到准确结果，我们应该考虑四类。可以把它们分成两组：一类让光束在穿过介质到达眼睛的过程中损失能量，另一类让它们的能量增加。

  • 光束穿过介质飞向眼睛时会因以下原因损失能量：

    • 吸收：一部分光能被构成介质的粒子吸收。如果你是那个粒子，你可以说：「有些光正朝你——也就是观看者——飞去，但抱歉，我决定吃掉一部分，所以你收到的会少一些。」

    • 外散射：如上一章所说，光会被粒子散射。这使得原本不朝眼睛飞的光多少被改向朝眼睛来。这就是我们在上一章描述的内散射效应。但朝眼睛飞的光在途中也可能被散射出去。这意味着光也会因这个效应损失能量。这自然就叫外散射。如果你是那个粒子，你可以说：「有些光正朝你——也就是观看者——飞去，但我决定把其中一部分散射到一些随机方向上，所以你收到的会少一些。」

  • 光束穿过介质飞向眼睛时会因以下原因获得能量：

    • 发射：第一章里我们提过这个效应，但也说了暂时忽略它。比如火焰就能发出白炽光。

    • 内散射：这个效应我们已经熟悉了。一些原不朝眼睛飞的光因散射被改向朝眼睛来。这个效应叫内散射。如果你是那个粒子，可以这样理解这个效应：「我把从各个方向来的光收集起来，再朝你——也就是观看者——的方向吐出一些，于是你会收到一些本来不是给你的光」。你可以把内散射看成外散射的结果：光被散射到各个方向（大致如此，等后面引入相位函数时会看到）。只不巧其中有一个方向就是视线方向（眼睛或相机光线）。

在计算光穿过介质飞向眼睛时我们损失了多少光时，必须同时计入吸收与外散射。外散射与内散射都由同一类光与粒子的相互作用引起：散射，上一章我们用变量 \(\sigma_s\)（希腊字母 sigma）来表示它。那么既然散射（\(\sigma_s\)）也决定了光穿过介质飞向眼睛时的损失量，我们就得把它和吸收系数 \(\sigma_a\) 一起写进 Beer 定律的公式里。记住，这个公式既用来计算 Li(x) 项，也用来计算采样点透射值。于是我们的代码现在变成（改动用红色标出）：

密度项

我们会在下一章详细讲这一项。

到目前为止，我们一直假定用来控制体积有多「不透明」的散射系数与吸收系数（记住这两个系数越大，体积越不透明）在整个体积内是均匀的。科学文献里常称之为均匀参与介质。现实世界中的「体积」一般不是这样。想想云或烟羽。它们的不透明度随空间变化。这时我们称之为非均匀参与介质。

密度随空间变化的体积物体怎么模拟，我们到下一章才看，现在只需说：我们需要某种变量来整体缩放散射系数与吸收系数。就把这个变量叫 density。我们用如下方式缩放 \(\sigma_a\) 与 \(\sigma_s\)（改动用红色标出）：


...
float sigma_a = 0.5; // 吸收系数
float sigma_s = 0.5; // 散射系数
&ltspan style="color: red; font-weight: bold; background-color: rgba(255,0,0,0.1);"&gtfloat density = 1;</span>
// 计算采样点透射率
float sample_attenuation = exp(-step_size * &ltspan style="color: red; font-weight: bold; background-color: rgba(255,0,0,0.1);"&gtdensity</span> * (sigma_a + sigma_s)); 
transparency *= sample_attenuation; 
 
// 内散射。求光穿过体积球体到达采样点的距离。
// 然后用 Beer 定律衰减内散射带来的光贡献。

    float light_attenuation = exp(-density * isect_vol.t1 * (sigma_a + sigma_s)); 
    result += transparency * light_color * light_attenuation * sigma_s * &ltspan style="color: red; font-weight: bold; background-color: rgba(255,0,0,0.1);"&gtdensity</span> * step_size; 
}
...

记住 \(\sigma_s\) 在代码里用在两处。密度随空间变化的概念怎么实现，我们会在下一章解释。

现在注意一件有意思的事。当密度为 0 时，result 变量什么也不会加。换句话说，在没有体积的地方（空无一物，或 density = 0），不应该有任何累积的光。这对下面这一行很重要：


// 与背景色组合后返回
return background_color* transparency + result;

如果没体积时 result 不为 0（比如我们在内散射计算里忘了把散射乘以密度值），那么我们就会在该什么也看不到的时候看到东西（result > 0），而实际上那时它应当是 0。这就是上一章我们说 result 已经「预先乘过」的原因。它已经乘过它自己的「不透明遮罩」。密度/不透明度大于 0 的地方它大于 0，其他情况为 0。

相位函数。

内散射贡献应当用下面的公式计算：

$$Li(x, \omega) = \sigma_s \int_{S^2} p(x, \omega, \omega')L(x,\omega')d\omega'$$

$Li$ 是内散射（辐射亮度）贡献，$x$ 是采样位置，$\omega$ 是视线方向（我们的相机光线方向）。通常 $\omega$ 总是指向辐射亮度传播的方向，也就是从物体指向眼睛。\(\omega'\) 项表示光照方向（\(\omega'\) 应从物体指向光源）。这里的 \(L(x, \omega')\) 项不过是 L(x) 项，即光的贡献或入射辐射亮度——我们代码里迄今一直在算它的值。就是这一段：


...
// 内散射。求光穿过体积球体到达采样点的距离。
// 然后用 Beer 定律衰减内散射带来的光贡献。
if (hit_object-&gtintersect(sample_pos, light_dir, isect_vol) && isect_vol.inside) { 
    float light_attenuation = exp(-density * isect_vol.t1 * (sigma_a + sigma_s)); 
    result += transparency * light_color * light_attenuation * sigma_s * density * step_size;
...

它计入的是从某个特定光照方向 $\omega'$（代码中的变量 light_dir）来、在采样点 x（代码中的 sample_pos）处、在体积中走了一定距离（代码中的 isect_vol.t1）之后的光量。

但我们还没引入积分号后面紧跟着的那一项：\(p(x, \omega, \omega')\)。它叫相位函数，接下来我们解释它是什么。不过在此之前，先用文字说说这个公式在讲什么。带 $S^2$ 符号的积分（文献里你最终也会看到它写成 \(\Omega_{4\pi}\)）意思是：内散射贡献可以通过计入来自整个方向球 $S^2$ 上所有方向的光来计算。

为了计算实体物体的外观，我们用的是叫 BRDF 的函数，它们改在方向半球上收集光。对实体物体来说，我们不关心从表面「下面」来的光——透光材质是例外，不过那又是另一个长故事了。如果你对这个话题感兴趣，请看著色相关的课程，比如全局光照与路径追踪或着色的数学）。现在我们回到相位函数。

光子与粒子相互作用时，可能被散射到该粒子周围任意一个可能方向上，其中每个方向被选中的概率都相同。这种情形下，我们称之为各向同性散射体积。但各向同性散射并不是常态。大多数体积倾向于把光散射在一个受限的方向范围内。这时我们称之为各向异性散射介质或体积。相位函数就是一个数学公式，它告诉你对某一组方向——视线方向 \(\omega\) 与入射光方向 $\omega'$——有多少光被散射。该函数返回 0 到 1 范围内的值。用数学语言说，相位函数刻画了被散射的光（或辐射亮度）的角度分布。

相位函数有几个性质。第一，它在自己的定义域（方向球 \(S^2\)）上的积分必然为 1。确实，构成体积的粒子会被来自可能各个方向的光束打到，而这组可能的方向可以看成以粒子为中心的一个球。那么，若考虑光能到达该粒子周围的所有方向，从这个粒子周围散射出去的光不可能大于全部入射光之和。这就是相位函数需要在方向球上归一化的原因：

$$\int_{S^2} f_p(x, \omega, \omega')d\omega' = 1$$

如果相位函数没有归一化，它就会凭空「增加」或「减少」光。相位函数的另一个性质是互易性。如果把公式里的 \(\omega\) 与 \(\omega'\) 两项对调，相位函数返回的结果不变。

$$f_p(x, \omega, \omega') = f_p(x, \omega', \omega)$$

相位函数只取决于视线方向与入射光方向之间的夹角。这就是它一般用夹角 $\theta$（希腊字母 theta）来定义（即两向量之间的夹角，而不是用 \(\omega\) 和 \(\omega'\) 定义）的原因。如果对方向 $\omega$（视线方向）与 \(\omega'\)（入射光方向）取点积，\(\cos(\theta\) 的范围是 [-1, 1]，因此 \(\theta\) 本身的范围是 [0, $\pi$]，如下图所示。

总之，相位函数告诉你，对任意一个特定的入射光方向（\(\omega'\)），有多少光可能被散射向观看者（\(\omega\)）。

聊够了。这些相位函数长什么样？

最简单的是各向同性体积的相位函数。因为来自方向球内各方向的光同样均匀地被散射到球上所有方向，所以相位函数（记住它在球域上的积分需归一化为 1）就是：

$$f_p(x, \theta) = { 1 \over {4\pi}}$$

注意这个函数与视线方向、入射光方向都无关。$\theta$ 角出现在函数的定义里，却没有用在公式本身中（等号右边）。这在意料之中，因为被外散射的光子其方向与入射光方向无关（两者之间没有依赖关系，所以它没理由出现在公式里），而所有外散射方向被选中的概率都相同（所以公式是个常数）。这个公式并不难理解。球面的面积是 $4\pi$ 球面度，如果你用微分立体角来想这些方向，那基本上就是所有入射方向覆盖的表面，因此相位函数应当是 1 除以 \(4\pi\)，以满足归一化性质：所有入射方向覆盖的表面除以 \(4\pi\) 等于 1。顺带说一下，相位函数的单位是 1/sr（这里的 sr 指球面度）。

各向同性体积的相位函数相当简单。我们再看另一个，叫 Henyey-Greenstein 相位函数。它长这样：

$$f_p(x, g, \cos\theta) = {1 \over {4\pi}}{{1-g^2}\over{(1 + g^2 - 2g\cos\theta)^{3/2}}}$$

它确实稍微复杂一点。如你所见它还有一个变量 \(g\)，叫非对称因子，其中 \(-1 \leq g \leq 1\)。这个参数让你控制光是向前散射还是向后散射。当 \(g \gt 0\)，光主要向前外散射。当 \(g \lt 0\)，向后散射。而当 \(g = 0\) 时，函数等于 \(1/{4\pi}\)，即各向同性体积的相位函数。图 3 展示了 \(g\) 取不同值时的函数形状。

如果你想要这个函数在方向球上已归一化的证明，就在下面。首先别忘了我们要在方向球上（在 \(4\pi\) 球面度上）对函数积分，因为我们这里的方向 \(d\omega\) 是用微分立体角定义的。如着色入门那门课所解释的，微分立体角 \(d\omega\) 可以用 \(\phi\)（经度）与 \(\theta\)（纬度）表示。于是得到：

$$\int^{2\pi} \Big\{ \int_0^\pi p(\theta) \sin \theta d \theta \Big\} d\phi.$$

对 \(2\pi\) 积分 \(d\phi\) 直接得到 \(2\pi\)。于是剩下：

$$2\pi\int_0^{\pi} p(\theta) \sin \theta d \theta.$$

我们可以把它写成 \(\mu = \cos \theta\) 的函数，在 -1 到 1 上积分：

$$2\pi\int_{\mu=-1}^{1} {\color{red}{1 \over {4\pi}}}{{1-g^2}\over{(1 + g^2 - 2g\mu)^{3/2}}} d \mu.$$

可以把积分里的常数（标红部分）移到左边，于是有：

$${1\over 2}\int_{\mu=-1}^{1} {{1-g^2}\over{(1 + g^2 - 2g\mu)^{3/2}}} d \mu.$$

做这个积分，我们要用微积分第二基本定理：

$$\int_a^b f(x) dx = F(b) - F(a).$$

其中 \(F\) 是函数 \(f\) 的原函数。所以我们需要求下面这个式子的原函数：

$${{1-g^2}\over{(1 + g^2 - 2g\mu)^{3/2}}}.$$

还存在其他相位函数，比如 Schlick、Rayleigh、Lorenz-Mie 散射相位函数。它们是为贴合不同类型粒子的行为而设计的。例如，渲染由微小粒子（比光波长还小）构成的体积时，用 Rayleigh 函数更合适；而 Mie 函数更适合较大的粒子（灰尘、水滴等）。Henyey-Greenstein 常用于生产渲染，也就是我们为电影做的那种渲染，因为它算起来快（其他的可能没这么快），也便于采样（例如参见蒙特卡洛模拟那门课）。

抖动采样位置

到目前为止，我们一直把采样点放在线段的中点。使用规则间隔的采样，就像把体积切成一片片，而这些切片会导致不好看的条带瑕疵，如上图所示（该效果被刻意夸大了）。要「修掉」这个问题，我们可以改为在每个线段上取随机位置。换句话说，采样点可以落在线段边界内的任何地方（当然是沿相机光线）。为此，我们把这几行：


float t = isect.t0 + step_size * (n + 0.5); 
vec3 sample_pos = ray_orig + t * ray_dir;

换成：


float t = isect.t0 + step_size * (n + rand()); 
vec3 sample_pos = ray_orig + t * ray_dir;

其中 rand() 是一个返回 [0,1] 范围内均匀分布数的函数。我们把这种方法叫随机采样。

随机采样是一种蒙特卡洛技术：不在规则间隔的位置上、而在适当的非均匀间隔位置上对函数采样。

我们不能说这样就更好（所以「修掉」加了引号），因为现在我们把条带换成了噪声，而噪声本身也是问题。不过结果在视觉上比条带舒服。你可以用更讲究的「随机」数序列生成方法来减轻这种噪声（例如准蒙特卡洛方法）。但在这个版本的课程里我们跳过这个话题；这方面可以写一整本书（目前你可以在蒙特卡洛实践那门课里找到一些信息）。

不透明时跳出光线步进循环（优化）

确实，如果穿过 t0 到 t1 之间一半距离后体积的透明度已经低于比如 1e-3，你可能会认为剩下那一半的采样点不必再算（如旁边那幅图所示）。做法就是一旦检测到透明度变量低于这个最低阈值，就跳出光线步进循环（见下面的伪代码）。考虑到光线步进是一种相当慢的计算方法，我们应该用这个优化；它能省下大量时间，尤其是体积物体相当稠密的时候（越稠密，透明度下降得越快）。上一章我们提过，这也是我们可能宁愿用正向而不愿用反向积分方法的原因之一。


...
float transparency = 1;
// 沿光线步进
for (int n = 0; n < ns; ++ns) {
    ...
    if (transparency < 1e-3)
        break;
}

现在你可以在通过透明度检查后就停止步进、别的什么都不做，然而这在「统计上」是错的。这会以某种方式给渲染图像引入偏差。看看图 xx 就更容易明白。如你所见，红线标出了我们停止光线步进的阈值。若这么做，我们等于去掉了曲线下方（沿 x 轴方向）那部分体积的贡献。当然，这个量在某种意义上「可以忽略」，这也是我们一开始决定采用这种截断方案的原因；但如果你是试图模拟中子在板中如何运动的核工程师，这就是不可接受的。那么，怎样才能既利用这个优化、又满足核工程师的期望？

我们要用的方法叫俄罗斯轮盘赌，在专门讲蒙特卡洛方法的那门课里已经谈过。思路是：当透明度值低于某个阈值（比如 1e-3）时应用俄罗斯轮盘赌技术。然后我们取一个 [0, 1] 范围内（均匀分布的）随机数，检验它是否大于 1/d，其中 d 是某个大于 1 的正实数（整数，但不必是整数；也可以等于 1，不过那样检验就没意义了）。若是，我们就跳出循环；否则继续，但把当前透明度值乘以 d。这里的 d 表示我们通过检验的可能性。例如 d = 5 时，光线步进循环被终止的「概率」是五分之四。

这（但愿）说得通。如果随机数小于 1/d，你就把这个光子杀掉。它没了，你再也不能拿它做任何事。但作为杀掉它的交换，我们给通过检验活下来的那些更多权重（在我们的情形里是增大透明度值），与光子被杀的可能性成反比。思路写成代码就是这样：


...
float transparency = 1;
// 沿光线步进
int d = 2; // 值越大，我们越常跳出步进循环
for (int n = 0; n < ns; ++ns) {
    ...
    if (transparency < 1e-3) {
        if (rand() > 1.f / d) // 在此停止
            break;
        else
            transparency *= d; // 继续，但做补偿
   }
}

这是对俄罗斯轮盘赌技术的一个简短说明；如前所述，它在蒙特卡洛模拟与积分里都会用到。需要更详细的解释请参看那几门课。

读懂别人的代码！

本课程前三章涵盖了开始渲染体积所需的内容。到了这一步，如果你要面对别人的代码，应该已经能看懂里面在干什么了。我们一起来做这个练习。我们要用到一个叫 PBRT 的开源项目，看它的体积渲染实现。那里面应该再没有对你是秘密的东西了。

PBRT 是一个研究/教学项目，走的路子和 Scratchapixel 差不多：用示例来教渲染。不过 PBRT 是一个完全集成的渲染器，而 Scratchapixel 里每种技术都实现在一个自包含的示例程序中。此外，PBRT 是为硕士/博士生设计的，设想他们能用 PBRT 实现自己的研究。PBRT 书中的大多数公式给出时都没多少解释。这本书假定你具备读懂它们所需的背景。而 Scratchapixel 想把计算机图形学教给所有人。我们确实认为PBRT 的书现在已在线、任何人都可以免费阅读。该渲染器的源代码可在 GitHub 上获取。

除了比 Scratchapixel 稍复杂一些，它也是这一领域学生与工程师的参考书。它仍由第一版（2004 年出版，Scratchapixel 大约 2007 年起步）的作者们维护，即 Math Pharr、Greg Humphreys 与 Pat Hanrahan（后续几版还有更多人参与），他们不断用最新的技术更新书与代码。

如果你仍觉得这段代码难以消化，别担心。我们可能花了好几年才熟悉这些概念。不过我们希望，有了本课程给出的解释，你能跟得上这段代码的大致结构，能理解它在做什么，并迎来一句「现在我终于懂了」的时刻）。


Spectrum SingleScatteringIntegrator::Li(const Scene *scene, 
    const Renderer *renderer, const RayDifferential &ray, 
    const Sample *sample, RNG &rng, Spectrum *T, 
    MemoryArena &arena) const {

// [comment]
// 求与体积物体的相交边界 (t0, t1)。若光线不与
// 体积物体相交，则把透射率置为 1，并返回颜色 0。
// [/comment]

    VolumeRegion *vr = scene-&gtvolumeRegion
    float t0, t1;
    if (!vr || !vr-&gtIntersectP(ray, &t0, &t1) || (t1-t0) == 0.f) {
        *T = 1.f;
        return 0.f;
    }

// [comment]
// 若已相交。把整体透射（透明）值置为 1，并把用于
// 存最终颜色（此处名为 Lv）的变量置为 0。计算采样点数，
// 并相应调整步长。
// [/comment]

    // 在 _vr_ 中做单次散射的体积积分
    Spectrum Lv(0.);

    // 为体积积分的步进做准备
    int nSamples = Ceil2Int((t1-t0) / stepSize);
    float step = (t1 - t0) / nSamples;
    Spectrum Tr(1.f);
    Point p = ray(t0), pPrev;
    Vector w = -ray.d;
    t0 += sample-&gtoneD[scatterSampleOffset][0] * step;

    // 计算单次散射采样点的采样图案
    float *lightNum = arena.Alloc<float>(nSamples);
    LDShuffleScrambled1D(1, nSamples, lightNum, rng);
    float *lightComp = arena.Alloc<float>(nSamples);
    LDShuffleScrambled1D(1, nSamples, lightComp, rng);
    float *lightPos = arena.Alloc<float>(2*nSamples);
    LDShuffleScrambled2D(1, nSamples, lightPos, rng);
    uint32_t sampOffset = 0;

// [comment]
// 光线步进（正向）。这是主循环，我们遍历各线段，并
// 计算每个采样点各自的不透明度与内散射对最终体积
// 透明度 (Tr) 与颜色 (Lv) 的贡献。
// [/comment]

    for (int i = 0; i < nSamples; ++i, t0 += step) {
        // 前进到 _t0_ 处的采样点，并更新 _T_

// [comment]
// 更新采样位置。然后求该点在体积中的密度。
// 这部分我们还没讲。这是接下来两章的主题。目前
// 把变量 stepTau 当作我们代码里的密度变量即可。
// 采样位置经过抖动。然后用 Beer 定律以当前采样点
// 的不透明度衰减我们的整体透射变量 (Tr)。
// [/comment]

        pPrev = p;
        p = ray(t0);
        Ray tauRay(pPrev, p - pPrev, 0.f, 1.f, ray.time, ray.depth);
        Spectrum stepTau = vr-&gttau(tauRay,
            .5f * stepSize, rng.RandomFloat());
        Tr *= Exp(-stepTau);

// [comment]
// 应用俄罗斯轮盘赌技术。
// [/comment]

        // 若透射率很小，可考虑终止光线步进
        if (Tr.y() < 1e-3) {
            const float continueProb = .5f;
            if (rng.RandomFloat() > continueProb) {
                Tr = 0.f;
                break;
            }
            Tr /= continueProb;
        }

// [comment]
// 我们活下来了。来算该采样点的内散射贡献。通常
// 可以计算场景中每个光源的贡献。不过这段代码
// 用了另一种技术。它随机选一个光源，只计算那一个
// 光源的贡献。这是蒙特卡洛积分的又一个例子。
// 这条现在不必太在意。我们会在以后的课程里研究它。
// [/comment]

        // 计算 _p_ 处的单次散射源项
        Lv += Tr * vr-&gtLve(p, w, ray.time);
        Spectrum ss = vr-&gtsigma_s(p, w, ray.time);
        if (!ss.IsBlack() && scene-&gtlights.size() > 0) {
            int nLights = scene-&gtlights.size();
            int ln = min(Floor2Int(lightNum[sampOffset] * nLights),
                nLights-1);
            Light *light = scene-&gtlights[ln];
            // 加上 _light_ 因 _p_ 处散射而产生的贡献
            float pdf;
            VisibilityTester vis;
            Vector wo;
            LightSample ls(lightComp[sampOffset], lightPos[2*sampOffset],
                lightPos[2*sampOffset+1]);

// [comment]
// 计算光的颜色（颜色 * 强度等）
// [/comment]

            Spectrum L = light-&gtSample_L(p, 0.f, ls, ray.time, 
                &wo, &pdf, &vis);
            
            if (!L.IsBlack() && pdf > 0.f && vis.Unoccluded(scene)) {

// [comment]
// 把光的颜色乘以光的透射值（即光穿体积到采样点
// 之后还剩多少）。Beer 定律在 Transmittance
// 函数中应用（此处未展示该代码，你可以去看
// PBRT 的源代码）。
// [/comment]

                Spectrum Ld = L * vis.Transmittance(scene, 
                    renderer, NULL, rng, arena);

// [comment]
// 然后把内散射贡献加到最终颜色上。注意这里我们
// 乘上了所有该乘的项：Tr（体积当前透明度值）、
// ss（散射项）、vr-&gtp（相位函数）、Ld（光的贡献，
// 即 Li(x) 项）。其他项先不管，它们与前面谈到的
// 蒙特卡洛积分方法有关。注意：这里不乘步长，
// 因为那要在最末尾、光线步进循环之外做。
// [/comment]

                Lv += Tr * ss * vr-&gtp(p, w, -wo, ray.time) * Ld * 
                    float(nLights) / pdf;
            }
        }
        ++sampOffset;
    }
    *T = Tr;

// [comment]
// 最后把最终颜色乘以步长。在我们的代码里，为了清楚
// 是在光线步进循环里做的。但为了优化，你可能想在
// 最末尾做，他们在这里就是这么选择的。
// [/comment]

    return Lv * step;
}
