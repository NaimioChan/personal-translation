光线追踪多边形网格（第 2 部分）

阅读时间：9 分钟。

现在我们来看看，怎么把光栅化课程里渲染出的那张图重现出来。我们已经知道如何载入一个圆盘几何体文件，并用光线追踪渲染这个物体。把这两项技术放进同一个程序里。理论上，如果一切正常（数学从不说谎），我们应该得到两张完全相同的图像。不过，如果前面关于光线追踪学到和说到的都成立，光线追踪应该比光栅化更耗时。我们来验证这些假设。

首先，我们把 多边形网格 课程里讲过的几何体文件读取函数整合进程序代码。从文件中读出的所有数据（面数、面索引数组与顶点索引数组、点坐标数组、法线数组与 st 坐标数组）都传给 TriangleMesh 的构造函数（第 5 行）。

TriangleMesh* loadPolyMeshFromFile(const char *file) 
{ 
    std::ifstream ifs; 
    try { 
        ifs.open(file); 
        if (ifs.fail()) throw; 
        std::stringstream ss; 
        ss << ifs.rdbuf(); 
        uint32_t numFaces; 
        ss >> numFaces; 
        std::unique_ptr&ltuint32_t []> faceIndex(new uint32_t[numFaces]); 
        uint32_t vertsIndexArraySize = 0; 
        // 读取面索引数组
        for (uint32_t i = 0; i < numFaces; ++i) { 
            ss >> faceIndex[i]; 
            vertsIndexArraySize += faceIndex[i]; 
        } 
        std::unique_ptr&ltuint32_t []> vertsIndex(new uint32_t[vertsIndexArraySize]); 
        uint32_t vertsArraySize = 0; 
        // 读取顶点索引数组
        for (uint32_t i = 0; i < vertsIndexArraySize; ++i) { 
            ss >> vertsIndex[i]; 
            if (vertsIndex[i] > vertsArraySize) vertsArraySize = vertsIndex[i]; 
        } 
        vertsArraySize += 1; 
        // 读取顶点
        std::unique_ptr&ltVec3f []> verts(new Vec3f[vertsArraySize]); 
        for (uint32_t i = 0; i < vertsArraySize; ++i) { 
            ss >> verts[i].x >> verts[i].y >> verts[i].z; 
        } 
        // 读取法线
        std::unique_ptr&ltVec3f []> normals(new Vec3f[vertsIndexArraySize]); 
        for (uint32_t i = 0; i < vertsIndexArraySize; ++i) { 
            ss >> normals[i].x >> normals[i].y >> normals[i].z; 
        } 
        // 读取 st 坐标
        std::unique_ptr&ltVec2f []> st(new Vec2f[vertsIndexArraySize]); 
        for (uint32_t i = 0; i < vertsIndexArraySize; ++i) { 
            ss >> st[i].x >> st[i].y; 
        } 
 
        return new TriangleMesh(numFaces, faceIndex, vertsIndex, verts, normals, st); 
    } 
    catch (...) { 
        ifs.close(); 
    } 
    ifs.close(); 
 
    return nullptr; 
}

程序其余部分就是光线追踪器的常规写法。我们遍历图像中的每个像素，生成一条主光线（其方向与原点由相机到世界空间的 4x4 变换矩阵变换），并检测这条主光线是否与场景中的任何物体相交。在 castRay() 里，我们调用 trace() 函数，在其中遍历 objects 列表中的所有物体。


bool trace( 
    const Vec3f &orig, const Vec3f &dir, 
    const std::vector&ltstd::unique_ptr&ltObject>> &objects, 
    float &tNear, uint32_t &index, Vec2f &uv, Object **hitObject) 
{ 
    *hitObject = nullptr; 
    for (uint32_t k = 0; k < objects.size(); ++k) { 
        float tNearTriangle = kInfinity; 
        uint32_t indexTriangle; 
        Vec2f uvTriangle; 
        if (objects[k]-&gtintersect(orig, dir, tNearTriangle, indexTriangle, uvTriangle) && tNearTriangle < tNear) { 
            *hitObject = objects[k].get(); 
            tNear = tNearTriangle; 
            index = indexTriangle; 
            uv = uvTriangle; 
        } 
    } 
 
    return (*hitObject != nullptr); 
} 
 
Vec3f castRay( 
    const Vec3f &orig, const Vec3f &dir, 
    const std::vector&ltstd::unique_ptr&ltObject>> &objects, 
    const Options &options) 
{ 
    Vec3f hitColor = options.backgroundColor; 
    float tnear = kInfinity; 
    Vec2f uv; 
    uint32_t index = 0; 
    Object *hitObject = nullptr; 
    if (trace(orig, dir, objects, tnear, index, uv, &hitObject)) { 
        Vec3f hitPoint = orig + dir * tnear; 
        Vec3f hitNormal; 
        Vec2f hitTexCoordinates; 
        hitObject-&gtgetSurfaceProperties(hitPoint, dir, index, uv, hitNormal, hitTexCoordinates); 
        float NdotView = std::max(0.f, hitNormal.dotProduct(-dir)); 
        const int M = 10; 
        float checker = (fmod(hitTexCoordinates.x * M, 1.0) > 0.5) ^ (fmod(hitTexCoordinates.y * M, 1.0) < 0.5); 
        float c = 0.3 * (1 - checker) + 0.7 * checker; 
 
        hitColor = c * NdotView; 
    } 
 
    return hitColor; 
}

最后调用三角网格的 intersect() 方法。为检测光线是否与网格相交，我们对每个三角形调用光线-三角形求交测试函数。如上一章所述，在这个过程中我们还会记录最近的交点距离，以防光线与不止一个三角形相交（我们还需要记录相交三角形的索引以及交点的重心坐标，着色时会用到这些信息）。


bool intersect(const Vec3f &orig, const Vec3f &dir, float &tNear, uint32_t &triIndex, Vec2f &uv) const 
{ 
    uint32_t j = 0; 
    bool isect = false; 
    for (uint32_t i = 0; i < numTris; ++i) { 
        const Vec3f &v0 = P[trisIndex[j]]; 
        const Vec3f &v1 = P[trisIndex[j + 1]]; 
        const Vec3f &v2 = P[trisIndex[j + 2]]; 
        float t = kInfinity, u, v; 
        if (rayTriangleIntersect(orig, dir, v0, v1, v2, t, u, v) && t < tNear) { 
            tNear = t; 
            uv.x = u; 
            uv.y = v; 
            triIndex = i; 
            isect = true; 
        } 
        j += 3; 
    } 
 
    return isect; 
}

最后，如果光线与网格相交，我们在 castRay() 函数里执行着色（第 47-56 行）。先调用相交网格的 getGeometryData() 方法，计算交点处的法线与纹理坐标。然后用这些信息生成棋盘格图案并计算朝向比，两者混合后构成最终的像素颜色（第 56 行）。

关于着色补一句：如果理解着色相关代码时需要帮助，不必太担心。着色简介里会讲。注意这段代码和光栅化课程里用过的很相似。首先，我们用交点的重心坐标插值出物体实际的 st 或纹理坐标。交点最终的纹理坐标随后用来计算棋盘格图案。至于法线，我们有两个选择。面法线——光栅化课程里讲过——可以通过对三角形的两条边取叉积算得。我们也可以用交点的重心坐标插值顶点法线（从几何体文件读入），方式和插值纹理坐标一样。如前所述，这段代码很快就会讲到（见着色简介课程）。

结果

先看视觉结果。如你所见，光线追踪器生成的图像与光栅化器生成的图像完全相同（背景色除外）。正如本课开头所说，数学从不说谎。只要做对了，两种渲染技术应该给出完全一样的结果。至少我们证明了情况确实如此，这也是验证程序做对了的一种方式。万岁！

现在比较渲染时间。光线追踪：15.22 秒。光栅化器：0.00628 秒（两个程序在同一台机器上运行）。正如预期，在朴素实现下，光线追踪慢了 2421 倍。这是相当大的差距。好在如上一章所说，可以用加速结构来改善。本节不会讲加速结构，但你可以在「高级光线追踪」部分找到相关课程。尽管慢，接下来的课程里我们仍会继续用光线追踪来学习着色。如前所述，光线追踪是更适合着色的技术。着色涉及计算空间中各点之间的可见性，而光线追踪正擅长于此。它提供了一个统一的框架，既能解决可见性问题，也能完成着色。

结论

恭喜。走到学习旅程的这一步，你已经知道光线追踪与光栅化的区别，知道如何实现这两种算法，并能生成从给定视点观察某个 3D 模型的图像，而且无论用哪种技术渲染，这张图都一致。你也已经能够判断两种方法在性能上的差异。下一课我们会学习变换物体。之后就准备好开始第一堂讲着色的课程了。
