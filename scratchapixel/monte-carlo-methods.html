蒙特卡罗方法

阅读时间：15 分钟。

本课程与上一课（第 16 课）互补。蒙特卡罗方法的数学基础那门课更多讲的是蒙特卡罗方法所依托的概念。在这门课里，我们讲方法本身，并给出一些实际例子。

蒙特卡罗方法：我感觉自己（不）走运！

在渲染领域，蒙特卡罗（常缩写为 MC）这个词经常被使用、被读到、被听到。但它到底是什么意思？你现在已经花了不少时间复习统计与概率的概念，会发现（对某些人来说也许是个失望）它指的其实是一个简单得难以置信的想法。然而简单归简单，它很有力，还有一些有趣的特性，使它非常适合用来求解各种问题。简而言之，蒙特卡罗方法指一系列统计方法，主要用来为这样一些东西找解：计算函数的期望值，或者对无法解析求解的函数做积分，比如它们没有闭式解（另见着色的数学那门课）。我们说「统计方法」，意思是它们使用与我们前几章详细研究过的相同的采样技术来计算这些解。为什么叫蒙特卡罗方法？原因很简单：同一套原理可以用来求解不同的问题，而每一个这样的问题都对应一种不同的技术或算法。所有这些算法的共同点是都使用随机（或随机性）采样。正如俄罗斯数学家 Sobol 所描述的：

蒙特卡罗方法是一种通过随机采样（或对随机变量做模拟）来求解数学问题的数值方法。

蒙特卡罗（MC）方法的共同概念，都是用随机抽取的样本去计算某个给定问题的解。这些问题一般分为两大类：

  • 模拟：用蒙特卡罗或随机采样来跑一次模拟。如果你想算从 A 点到 B 点要花多少时间，给定一些条件，比如路上会下雨或下雪的概率、堵车的概率、中途得停下来加油的概率等等，你可以在模拟开始时设定这些条件，然后把模拟跑上 1,000 次，得到一个估计时间。一如既往，跑的次数（这里是 1,000）越多，估计就越好。

  • 积分：这是一门对数学家有用的技术。在着色的数学里，我们学过如何用黎曼和的技术计算简单积分。这办法虽然简单，但随着积分维度的增加，计算代价会变得相当高。而 MC 积分虽然收敛到真实解的速度不算最快，却能让我们以更「便宜」的计算代价得到一个相当接近的结果。

但让我们换个说法，强调一下这个方法一个非常重要的地方（其实这正是它真正令人兴奋、真正美妙之处）。如果说样本用得越多、MC 方法就越接近真实解，这话不假；但因为我们用的是随机样本，一个 MC 方法也完全可能「只是」纯靠运气随机落到了精确值上。换句话说，有时候跑一次 MC 模拟或积分，结果恰好就是对的。不过大多数时候不会，然而把这些结果平均起来，终究还是会收敛到精确解（这一点以及大数定律我们已在蒙特卡罗方法的数学基础里学过）。

举个例子，给定天气、星期几、一天中的时刻等条件，你从 A 到 B，我们的第一次模拟给出 1 小时 32 分钟。现在假设在同样条件下我们跑的其他 1,000,000,000,000 次模拟，没有一次给出这个数字，但把结果平均之后，我们得到 1 小时 32 分钟。换句话说，你的第一次模拟给出的似乎就是你这个问题真正的解（而这本来也是你对一万亿次模拟的平均值所期待的、相当接近的那个数）。当然，只跑一次你并不知道自己拿到了正确答案，但这正是这个方法的一大特点：样本很少的时候，有时你也能拿到精确解（或非常接近它的值）。

然而 MC 方法的长处所在，也正是它的主要弱点所在。如果说有时候你凭运气只用很少的样本就得到了正确或接近正确的结果，那么另一些时候你也可能运气很差，需要非常大量的样本才能接近正确答案。一般来说，MC 方法的收敛速度（即随着样本数增加，MC 方法收敛到正确结果的速率）相当低（甚至可以说很差）。这一点我们在本章后面还会再讲。这是 MC 方法另一个需要记住的重要特点。

命中或未命中蒙特卡罗方法

我们会逐一详述每种技术（蒙特卡罗模拟与蒙特卡罗积分），并给出一个例子，说明 MC 方法在计算机图形学中、尤其是在渲染领域实际是怎么用的。不过在讲这些之前，先用一个简单的例子把这个概念引出来，既方便又容易。设想我们想估计一个任意形状的面积，比如图 1 里画的那个。我们唯一知道的是包含这个形状、由边界 ac 与 ab 所确定的矩形的面积。因为这些边界定义的是一个简单矩形，我们知道这个矩形的面积是 \(A = ab \times ac\)。要估计形状本身的面积，我们可以用一门叫作命中或未命中（有时也叫拒绝法）的技术。思路是把一定数量的随机点均匀地「抛」进矩形里，数出落在形状上的点（命中）有多少，并把其余的拒绝掉。因为点是随机分布在矩形面积 \(ab \times ab\) 上的，所以有理由假定形状的面积与命中数占总抛点数的比例成正比（换句话说，命中数占总样本数的比值，是形状面积与其外接矩形面积之比的一个近似）。假定总样本数（抛出的点数）保持不变：形状越大，命中数越多；反过来，形状越小，命中数越少。我们可以写出：

$$A_{shape} \approx {N_{hits} \over N_{total} } \times A \text{ where } A = ab \times ac.$$

这是一个非常基础、非常简单的例子，说明随机采样如何用来求解一个给定的问题（这个装置最初是冯·诺依曼本人想出来的，你可以在本章末尾的照片里看到他）。有几点需要注意。当然，样本用得越多，估计越好。同样重要的是，样本在矩形面积上的分布必须是均匀的。如果因为某种原因，更多的点落进了矩形的某个区域（就像图 2 那样，越靠近图形中心样本密度越高），结果就会有偏（也就是说，结果会与真实解相差某个偏移量）。在下一门讲重要性采样的课程里我们会看到，均匀采样并不是使用 MC 方法的绝对条件。当我们知道用的是非均匀分布时，可以用别的办法补偿它通常引入的偏差。那么我们为什么会对使用非均匀采样感兴趣？因为正如下一门讲重要性采样的课程会说的，这可以当作一种方差缩减技术来用。方差，正如上一门课《蒙特卡罗方法的数学基础》所解释的，是衡量我们的估计与真实解之间误差的一个量。在 MC 方法里，降低方差唯一暴力、也最明显的办法是增大 \(N\)，即总样本数。不过，另一些涉及随机样本生成方式的方法（见本课末尾讲准随机数与伪随机数的章节）以及重要性采样（其中使用非均匀的采样分布）也可以用来降低方差。然而（在我们研究这些更进阶的方法之前），请记住：基础或朴素的蒙特卡罗方法要求样本均匀分布。记住，一个随机数如果它所有可能的结果出现的概率都相同（这一性质称为等概率），它就具有均匀分布。

作为一个实际例子，假设我们要用命中或未命中蒙特卡罗方法估计单位圆的面积。我们知道单位圆的半径是 1，因此该单位圆内接于一个边长为 2 的正方形。我们可以在这个正方形内生成样本，数出落在圆内的点数。要判断该点在圆内（命中）还是圆外（未命中），只需量出样本点到原点（单位圆的圆心）的距离，检查这个距离是否小于（或等于）圆的半径（对单位圆来说等于 1）。注意，因为我们可以把圆分成四个相等的部分（或象限），每个都内接于一个单位正方形（图 3），所以我们可以把这个测试限制在单位正方形内，再把得到的数目乘以四。要计算单位圆四分之一的面积，我们只需把总命中数（图 3 中的绿点）除以总样本数，再把这个比值乘以单位正方形的面积（等于 1）。下面的 C++ 代码实现了这个算法：


#include &ltcstdlib> 
#include &ltcstdio> 
#include &ltrandom> 
 
int main(int argc, char **argv) 
{ 
    std::default_random_engine gen; 
    std::uniform_real_distribution&ltfloat> distr; 
    int N = (argc == 2) ? atoi(argv[1]) : 1024, hits = 0; 
    for (int i = 0; i < N; i++) { 
        float x = distr(gen); 
        float y = distr(gen); 
        float l = sqrt(x * x + y * y); 
        if (l <= 1) hits++; 
    } 
    fprintf(stderr, "Area of unit disk: %f (%d)\n", float(hits) / N * 4, hits); 
 
    return 0; 
}

这段代码使用 C++11 random 库里的函数，用一个给定的随机数生成器（关于在计算机上生成随机数的更多信息，见本课后面的某一章）和一个给定的概率分布（这里是均匀分布）来生成随机数。查看文档可以了解更多关于这些 C++11 库的信息（到 2013 年为止，C++11 是 C++ 编程语言标准的最新版本）。如果你编译并运行这个程序，应该会得到：


clang++ -o pi -O3 -std=c++11 -stdlib=libc++ pi.cpp
./pi 1000000
Area of unit disk: 3.141864 (785466)

你可以用最新的 C++ 版本更新这个例子，到 2022 年，那就是 C++20。

可以看到，我们得到的结果相当接近精确解（即 \(\pi\)，因为单位圆的面积是 \(A = \pi r^2\)，其中 \(r = 1\)），而且随着样本数的增加（你可以把它作为参数传给程序），估计值会不断逼近这个数（正如预期）。如果你以前用过 3D 应用，你很可能已经用过随机采样，只是自己不知道。不过有了这个程序（以及后面那些），你现在可以真地说：你不仅知道 MC 方法是什么，还亲手实现了一个实际例子来说明这种方法。

我们为什么用蒙特卡罗方法？

如果你跑那段计算单位圆面积的代码，会发现要把数 \(\pi\) 逼近到小数点后第四位（3.1415），大约需要一亿个样本。这是估计数 \(\pi\) 的高效办法吗？答案是否定的。那么，既然它们看起来并不高效，我们为什么还需要蒙特卡罗方法？正如前面几门课里已经提到的，我们说一个方程有闭式解，是指这个解可以被表达出来、从而解析地算出来。可是许多方程并没有这样的闭式解，即便有，有时其复杂度也使得只有在无限时间内才可能求解。这类问题或方程被称为不可解的。对一个问题可能的结果有一些预测，通常总比完全没有预测要好。而蒙特卡罗方法有时就是唯一可行的办法，能对这些方程或问题做出估计。正如 Metropolis 与 Ulam 在他们那篇关于蒙特卡罗方法的开创性论文中所说（见参考文献部分）：

要计算一局接龙纸牌获胜的概率，是一件完全不可解的任务。[……] 实际的做法是大量地产生任一给定牌局的实例，然后考察获胜的相对比例。[……] 我们立刻就能看出，这个估计永远不会确定地落在给定界限之内，而只是——在试验次数很大时——以很大的概率落在其中。

正如后面几章会看到的，这类问题中有许多（比如定积分）可以用某些数值方法高效求解，这些方法一般比 MC 方法收敛得更快（换句话说，是更好的方法）。然而随着积分维度的增加，这些方法往往变得计算代价高昂，而蒙特卡罗方法在固定的计算代价下（由计算估计值所花掉的样本数决定）仍能给出相当好的估计。因此，对于复杂的积分，MC 方法一般是更好的选择（尽管它们的收敛速度相当糟糕）。

最后，蒙特卡罗方法一般实现起来简单得难以置信，而且非常通用。它们可以用来求解极其广泛的问题，几乎涉及一切你能想象到的领域。在 Metropolis 与 Ulam 的论文里，我们可以读到：

正如引言里已经暗示的，蒙特卡罗方法的流行与发展，与 1940 年代计算技术的出现有很大关系，而冯·诺依曼（见上图）正是其中的先驱。在洛斯阿拉莫斯科学实验室 1957 年发表的一份关于蒙特卡罗方法的报告里，我们已经可以读到：

高速数字计算机目前的发展水平，使得使用规模足够大的样本成为可能，从而在大多数实际问题中保证令人满意的精度。

理解这一点很重要，因为 MC 本身虽然是个相当简单的想法，但在没有计算机帮忙的情况下使用它，是一件相当繁琐、甚至可以说不可用的解题方式。计算机可以替我们完成所有计算，这也是为什么尽管收敛速度很差，蒙特卡罗或随机采样还是变得如此流行。我们只是让计算机替我们干那些繁琐的活。

最后，让我们这样结束本章：蒙特卡罗方法与随机数的生成同样有很大关系（本课前几章一直在研究随机变量）。要跑一个 MC 算法，我们首先得能生成随机数（一般还要符合给定的概率分布）。因此，生成这类「随机」数的算法（它们看起来是随机的，但一般并不是「真正」随机的，这也是这些算法被称为伪随机数生成器的原因）的开发，一直是计算技术中一个重要的研究领域。这个话题会在后面某一章进一步展开。
