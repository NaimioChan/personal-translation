小结与关于渲染的其他考量

阅读时间：5 分钟。

小结

前面几章已经讨论过的内容不再重复。这里只把本课程最要紧的术语和概念做个小结：

  • 计算机处理的是离散结构，而要表现图像所需的连续形状，就成了一个难题。

  • 在解决可见性问题时，三角形对光线追踪和光栅化两种方法都是有效的渲染图元。

  • 与光线追踪相比，光栅化处理可见性更快，是 GPU 的首选方法。不过光线追踪擅长模拟全局光照效果，能同时处理可见性与着色问题。用光栅化做全局光照则要借助额外的算法或方法。

  • 尽管有优势，光线追踪也面临困难，比如光线与几何体求交的代价高昂，渲染时间还会随场景复杂度线性增长。加速结构能缩短渲染时间，但为所有场景配置找到一种最优结构很难。光线追踪还会引入噪声，这是一种很难消除的视觉瑕疵。

  • 光线追踪要有效地计算着色并模拟全局光照效果，就必须模拟光线从光源到观察者所走的各条路径，而这些路径受表面类型（漫反射、镜面、透明等）影响。准确模拟这些路径，对于复现漫反射与镜面反射的相互反射、焦散、软阴影、半透明等光照效果至关重要。高效的光传输算法会模拟所有可能的光线路径。

  • 在微观与原子尺度上模拟光与物质的相互作用并不可行，但这些相互作用的结果可预测且一致。因此人们用数学函数来模拟这些相互作用。着色器借助数学模型近似表面反射光的方式，定义物体的视觉特征，并能模拟各种材质的外观以生成照片级真实的图像。着色器在这一过程中起关键作用。

  • 着色器与光传输算法之间的区别很细微。为产生间接光照效果而发出次级光线，取决于材质类型（漫反射、镜面等），这正体现了着色器与光传输之间的互动。接下来关于光传输的一节会进一步探讨着色器如何参与生成这些次级光线。

前面几章没有讨论的一个方面，是在 CPU 上渲染与在 GPU 上渲染的差别。切不可把 GPU 等同于实时渲染，也不可把 CPU 等同于离线渲染。实时渲染与离线渲染各有确切含义，与 CPU 或 GPU 无关。当一个场景以每秒 24 到 120 帧（fps）的速率渲染时，我们称之为实时渲染，其中 24 到 30 fps 是产生运动错觉的最低要求。典型的电子游戏运行在约 60 fps。低于 24 fps 且高于 1 fps 的速率算作交互式渲染。当渲染一帧需要几秒到几分钟甚至几小时时，就属于离线渲染。在 CPU 上达到交互式甚至实时帧率完全可行。渲染时间主要取决于场景的复杂度。即使在 GPU 上，极为复杂的场景也可能需要几秒以上才能渲染完。我们要说明的是，把 GPU 与实时渲染、CPU 与离线渲染对应起来是一种误解。在本节的课程里，我们会研究用 OpenGL 在 GPU 上渲染图像，并在 CPU 上实现光栅化与光线追踪两种算法。有一门专门的课程会讲 GPU 渲染与 CPU 渲染各自的优缺点。

本节不会涉及的另一个话题，是渲染与信号处理的关系。理解这层关系很关键，但需要扎实的信号处理基础，包括傅里叶分析。我们打算在完成基础部分之后，推出一系列相关课程。若没有对底层理论的透彻理解，讨论渲染的这一方面可能只会带来混乱，而不是清晰。

回顾完这些概念，你现在对专门讲渲染的几节内容——尤其是光传输、光线追踪和着色——已经有了一个预览。光传输一节会讨论如何模拟全局光照效果。光线追踪一节会深入具体技术，比如加速结构和光线微分（现在不熟悉这些术语也没关系）。在着色一节，我们会研究着色器以及为模拟各种材质外观而开发的数学模型。

我们还会涉及一些工程话题，比如多线程、多进程，以及利用硬件加速渲染。

最重要的是，对刚接触渲染的读者，我们建议从本节接下来的课程开始，掌握那些基础而关键的渲染技术：

  • 理解透视投影与正交投影，包括用透视投影矩阵把点投影到一块「虚拟画布」上，从而生成 3D 物体的图像。

  • 光线追踪的工作原理，以及如何从相机发出光线来生成图像。

  • 计算光线与三角形的交点。

  • 渲染三角形之外的复杂形状，包括球体、圆盘、平面等。

  • 模拟运动模糊以及景深这类光学效果。

  • 学习光栅化算法。

  • 研究着色器、Monte Carlo 光线追踪与纹理映射。纹理映射是给物体表面添加细节，可以用基于图像的纹理，也可以用过程式生成。
