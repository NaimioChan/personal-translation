生成相机光线

首先回顾一下：渲染器的目的是给画面的每个像素指定一种颜色。结果必须准确表现从某个 3D 视点所看到的场景几何体。我们还从上一章知道，视场角这类参数会改变我们能看到场景的多大一部分。第 1 课和本课也都解释过，光线追踪图像是通过为画面中每个像素生成一条光线来创建的。当光线与场景中的某个物体相交时，我们用交点处物体的颜色来设置该像素的颜色。这个过程我们在第 1 课已经讲过，后面几课还会再详细展开，它叫作反向追踪或眼睛追踪（因为我们沿光线路径从相机追到物体、再从物体追到光源，而不是从光源追到物体、再从物体追到相机）。

自然，生成图像的过程要从构造这些光线开始，我们称之为主光线或相机光线（之所以叫主，是因为这是第一批投射进场景的光线。次级光线例如阴影光线，我们稍后再说）。关于这些光线，我们知道哪些有助于构造它们的信息？我们知道它们从相机原点出发。在几乎所有 3D 应用里，相机创建时的默认位置都是世界原点，即坐标为 (0, 0, 0) 的那个点。回想3D 观察：针孔相机模型那一课，相机原点可以看作针孔相机的孔径（也就是投影中心）。真实针孔相机的胶片位于孔径后方，由几何构造导致光线在胶片上形成场景的倒像。不过，如果胶片平面与场景位于同一侧（在孔径前方而不是后方），这种倒置就可以避免。按惯例，在光线追踪中它常被放在恰好距相机原点 1 个单位处（这个距离永远不会变，原因我们后面再解释）。按惯例，我们还会把相机朝向定为负 z 轴方向（相机默认朝向由开发者自行选择，不过一般沿正 z 轴或负 z 轴。RenderMan、Maya、PBRT 与 OpenGL 都把相机沿负 z 轴对齐，我们建议开发者遵循同一惯例）。最后，为了让演示在一开始更简单，我们假设渲染出的图像是正方形的（图像宽度与高度的像素数相同）。

我们的任务是为画面上每个像素创建一条主光线。做法很简单：从相机原点出发，画一条穿过每个像素中心的线（图 1）。我们可以把这条线表示成一条光线，其原点是相机原点，方向是从相机原点指向像素中心的向量。要算出像素中心处某点的位置，我们需要把原本以光栅空间表示的像素坐标（点坐标以像素为单位，坐标 (0,0) 是画面的左上角）转换到世界空间。

为什么是世界空间？世界空间是场景中所有物体、几何体、光源与相机的坐标所表达的那个空间。例如，如果一个圆盘位于沿负 z 轴距世界原点 5 个单位处，那么这个圆盘的世界空间坐标就是 (0, 0, -5)。如果我们要让计算光线与该圆盘交点的数学成立，光线的原点与方向也必须定义在同一个空间里。例如，若一条光线的原点是 (0, 0, 0)、方向是 (0, 0, -1)，而这些数字代表世界空间坐标系下的坐标，那么这条光线将在 (0, 0, -5) 处与圆盘相交。如图 3 所示。

关于各种空间的更多信息，见计算 3D 点的像素坐标课程。

看这个问题的另一种方式是从相机出发。我们知道图像平面恰好位于距世界原点 1 个单位处，并沿负 z 轴对齐。我们也知道图像是正方形的，因此图像平面用来投影的那块区域也必然是正方形的。原因我们很快会解释，这块投影区域的尺寸是 2 乘 2 个单位（图 2）。我们还知道光栅图像由像素构成。我们需要的是找到这些像素在光栅空间中的坐标，与同一批像素在世界空间中的坐标之间的关系。这个过程需要几步，如图 5 所示。

首先，我们需要用画面的尺寸把这个像素位置归一化。像素的新归一化坐标据说定义在 NDC 空间中（NDC 即 Normalized Device Coordinates，归一化设备坐标）：

$$ \begin{array}{l} PixelNDC_x = \dfrac{(Pixel_x + 0.5)}{ImageWidth},\\ PixelNDC_y = \dfrac{(Pixel_y + 0.5)}{ImageHeight}. \end{array} $$

注意我们给像素位置加了一个小的偏移（0.5），因为我们希望最终的相机光线穿过像素中心。以 NDC 空间表示的像素坐标在 [0,1] 范围内（是的，光线追踪里的 NDC 空间与光栅化世界里的 NDC 空间不同，后者一般映射到 [-1,1] 范围）。不过如图 2 所示，胶片或图像平面是以世界原点为中心的。换句话说，位于图像左侧的像素应当有负的 x 坐标，而右侧的像素应当有正的 x 坐标。y 轴也是同样的道理。位于 x 轴所定义的直线之上的像素应当有正的 y 坐标，之下的应有负的 y 坐标。我们可以把当前处于 [0:1] 范围的归一化像素坐标重映射到 [-1:1] 范围来修正这一点：

$$ \begin{array}{l} PixelScreen_x = 2 * {PixelNDC_x} - 1,\\ PixelScreen_y = 2 * {PixelNDC_y} - 1. \end{array} $$

不过要注意，用这个公式，位于 x 轴上方的像素其 \({Pixel \; Remapped_y}\) 为负，下方的为正（而实际情况应当相反）。下面的公式可以修正这个问题：

$$ PixelScreen_y = 1 - 2 * {PixelNDC_y}.$$

现在当 \({Pixel_y}\) 从 0 变到 \({ImageWidth}\) 时，该值从 1 变到 -1。以此方式表示的坐标据说定义在屏幕空间中。

不过到目前为止我们都假设图像是正方形的。考虑宽高比其实很简单。现在看一个图像尺寸为 7 乘 5 像素的情形（图像虽小，但终究是图像）。用图像宽度除以高度得到值 1.4。当像素坐标定义在屏幕空间中时，它们在 [-1, 1] 范围内。然而沿 x 轴的像素（7 个）比沿 y 轴的像素（5 个）多，因此像素被压扁、沿竖直轴被拉长（见图 6）。要让它们重新变成正方形（像素本该如此），需要把像素的 x 坐标乘以图像宽高比，这里就是 1.4（再见图 6）。注意这个操作不改变 y 像素坐标（在屏幕空间中），它们仍在 [-1,1] 范围内，但 x 像素坐标现在处于 [-1.4, 1.4] 范围（更一般地说是 [-宽高比, 宽高比]）。

$$ \begin{array}{l} ImageAspectRatio = \dfrac{ImageWidth}{ImageHeight},\\ PixelCamera_x = (2 * {PixelScreen_x} - 1) * {ImageAspectRatio},\\ PixelCamera_y = (1 - 2 * {PixelScreen_y}). \end{array} $$

最后，我们需要考虑视场角。注意到目前为止，屏幕空间中任何点的 y 坐标都在 [-1, 1] 范围内。我们还知道图像平面距相机原点 1 个单位。如果从侧视图看这个相机设置，把相机原点连到胶片平面的上下边缘，就得到一个三角形。因为知道相机原点到胶片平面的距离（1 个单位）和胶片平面的高度（2 个单位，因为它从 y=1 到 y=-1），我们可以用简单的三角学求出直角三角形 ABC 的角，它是竖直角 \(\alpha\)（alpha）的一半，而后者正是我们关心的角：

$${\alpha \over 2} = atan (\dfrac{OppositeSide}{AdjacentSide }) = atan(\dfrac{1}{1}) = \dfrac{\pi}{4}.$$

换句话说，这个特定情形下的视场角，也就是角 \(\alpha\)，是 90 度。现在注意，要算出线段 BC 的长度，我们只需计算角 \(\alpha\) 的正切再除以 2：

$$\||BC|| = tan(\dfrac{\alpha}{2}).$$

回想几何课上的记号 ||V|| 表示向量 V 的长度。我们还能观察到，当 \(\alpha\) 大于 90 度时 ||BC|| 大于 1，小于 90 度时 ||BC|| 小于 1。例如 \(\alpha\)=60 时 tan(60/2)=0.57，\(\alpha\)=110 时 tan(110/2)=1.43。因此我们可以把屏幕像素坐标（目前位于 [-1, 1] 范围内）乘以这个数，把它们放大或缩小。你大概已经猜到了，这个操作会改变我们能看到场景的多大一部分，等价于拉近（视场角变小时看到的场景更少）与拉远（视场角变大时看到的场景更多）。总之，我们可以用角 \(\alpha\) 来定义相机的视场角，并把屏幕像素坐标乘以这个角的正切除以二的结果（如果这个角以度为单位，别忘了换算成弧度）：

$$ \begin{array}{l} PixelCamera_x = (2 * {PixelScreen_x } - 1) * ImageAspectRatio * tan(\dfrac{\alpha}{2}),\\ PixelCamera_y = (1 - 2 * {PixelScreen_y }) * tan(\dfrac{\alpha}{2}). \end{array} $$

到这里，原始像素坐标已经是相对相机的图像平面来表示的了。它们被归一化、重映射到 [-1:1] 之间、乘以图像宽高比，再乘以视场角 \( \alpha\) 的正切除以 2。这个点据说位于相机空间，因为它的坐标是相对相机的坐标系表示的。当相机处于默认位置时，相机的坐标系与世界坐标系是对齐的。这个点位于图像平面上，该平面距相机原点 1 个单位，但记住相机也是沿负 z 轴对齐的。因此我们可以把像素在图像平面上的最终坐标写成：

$$ P_{cameraSpace} = (PixelCamera_x, PixelCamera_y, -1)$$

这样我们就得到了图像中某个像素在相机图像平面上的位置 P（\( P_{cameraSpace}\)）。据此，我们可以为这个像素计算一条光线：把光线的原点定义为相机原点（我们称这个点为 O），把光线的方向定义为归一化的向量 OP（图 8）。向量 OP 就是该点在图像平面上的位置减去相机原点。当相机处于默认位置时，相机原点与世界笛卡尔坐标系是同一个，因此点 O 就是 (0, 0, 0)。

写成伪代码就是（真正的 C++ 实现见本课末尾）：


float imageAspectRatio = imageWidth / (float)imageHeight; // 假设宽度大于高度
float Px = (2 * ((x + 0.5) / imageWidth) - 1) * tan(fov / 2 * M_PI / 180) * imageAspectRatio;
float Py = (1 - 2 * ((y + 0.5) / imageHeight) * tan(fov / 2 * M_PI / 180);
Vec3f rayOrigin(0);
Vec3f rayDirection = Vec3f(Px, Py, -1) - rayOrigin; // 注意这其实就等于 Vec3f(Px, Py, -1);
rayDirection = normalize(rayDirection); // 这是方向向量，别忘了归一化

最后，我们希望能从任意特定视点渲染场景的图像。把相机从初始位置（位于世界坐标系原点、沿负 z 轴对齐）移开之后，你可以用一个 4x4 矩阵来表达相机的平移与旋转值。通常这个矩阵叫作相机到世界矩阵（它的逆叫作世界到相机矩阵）。如果我们把这个相机到世界矩阵应用到点 O 与 P 上，那么向量 ||O'P'||（其中 O' 是点 O、P' 是点 P 经相机到世界矩阵变换后的结果）就表示光线在世界空间中的归一化方向（图 8）。把相机到世界变换应用到 O 与 P 上，就是把这两个点从相机空间变换到世界空间。另一种做法是趁相机还在默认位置时先算出光线方向（向量 OP），再把这个矩阵应用到该向量上。

注意相机的坐标系是随相机一起移动的。我们的伪代码可以很容易地修改成考虑相机变换（旋转与平移；缩放相机并不特别推荐）：


float imageAspectRatio = imageWidth / imageHeight; // 假设宽度大于高度
float Px = (2 * ((x + 0.5) / imageWidth) - 1) * tan(fov / 2 * M_PI / 180) * imageAspectRatio;
float Py = (1 - 2 * ((y + 0.5) / imageHeight) * tan(fov / 2 * M_PI / 180);
Vec3f rayOrigin = Point3(0, 0, 0);
Matrix44f cameraToWorld;
cameraToWorld.set(...); // 设置矩阵
Vec3f rayOriginWorld, rayPWorld;
cameraToWorld.multVectMatrix(rayOrigin, rayOriginWorld);
cameraToWorld.multVectMatrix(Vec3f(Px, Py, -1), rayPWorld);
Vec3f rayDirection = rayPWorld - rayOriginWorld;
rayDirection.normalize(); // 这是方向向量，别忘了归一化

要计算最终图像，我们需要用刚才描述的方法为画面中的每个像素创建一条光线，并测试这些光线中是否有任何一条与场景中的几何体相交。遗憾的是，在这套课程里我们还没走到能计算光线与物体交点的那一步，不过这将是接下来两课的主题。

源代码

本课的源代码只是一个简单示例，演示如何为图像中的每个像素生成光线。代码遍历图像的所有像素（第 13-14 行），并为当前像素计算一条光线。我们把本章描述的所有重映射步骤合并到了一行代码里。原始的 x 像素坐标除以图像宽度，把初始坐标重映射到 [0,1] 范围。得到的值再重映射到 [-1,1] 范围，乘以 scale 变量（第 9 行）和图像宽高比（第 10 行）。像素的 y 坐标也做类似变换，不过记住 y 的归一化坐标需要翻转（第 16 行）。这个过程结束后，我们可以用变换后的点 x、y 坐标创建一个向量。这个向量的 z 坐标设为负一（第 18 行）：默认情况下相机沿负 z 轴看向前方。得到的向量最后由相机到世界矩阵变换并归一化。相机的原点也会被相机到世界矩阵变换（第 12 行）。最后我们可以把变换到世界空间的光线方向与原点传给 rayCast 函数。


void render(
    const Options &options,
    const std::vector&ltstd::unique_ptr&ltObject>> &objects,
    const std::vector&ltstd::unique_ptr&ltLight>> &lights)
{
    Matrix44f cameraToWorld;
    Vec3f *framebuffer = new Vec3f[options.width * options.height];
    Vec3f *pix = framebuffer;
    float scale = tan(deg2rad(options.fov * 0.5));
    float imageAspectRatio = options.width / (float)options.height;
    Vec3f orig;
    cameraToWorld.multVecMatrix(Vec3f(0), orig);
    for (uint32_t j = 0; j < options.height; ++j) {
        for (uint32_t i = 0; i < options.width; ++i) {
            float x = (2 * (i + 0.5) / (float)options.width - 1) * imageAspectRatio * scale;
            float y = (1 - 2 * (j + 0.5) / (float)options.height) * scale;
            Vec3f dir;
            cameraToWorld.multDirMatrix(Vec3f(x, y, -1), dir);
            dir.normalize();
            *(pix++) = castRay(orig, dir, objects, lights, options, 0);
        }
    }

    // 把结果保存为 PPM 图像（在 Windows 下编译请保留这些标志）
    std::ofstream ofs("./out.ppm", std::ios::out | std::ios::binary);
    ofs << "P6\n" << options.width << " " << options.height << "\n255\n";
    for (uint32_t i = 0; i < options.height * options.width; ++i) {
        char r = (char)(255 * clamp(0, 1, framebuffer[i].x));
        char g = (char)(255 * clamp(0, 1, framebuffer[i].y));
        char b = (char)(255 * clamp(0, 1, framebuffer[i].z));
        ofs << r << g << b;
    }

    ofs.close();

    delete [] framebuffer;
}

接下来几课我们会演示如何把主光线投射进场景：调用 rayCast 函数，它接收光线原点与方向作为参数（还接收物体列表、光源等其他东西），返回一种颜色。如果光线什么都没命中，函数返回背景颜色；否则返回交点处物体的颜色。注意，在遍历图像所有像素计算颜色之前，我们先创建了一个帧缓冲，用来存放 rayCast 函数的结果（第 7 行）。等图像中所有像素的光线都追踪完毕，我们就可以把这张图像的结果存到磁盘上。遗憾的是，在进入下一课之前我们还没法实现 rayCast 函数。在此期间，我们先把光线方向转换成颜色，并为当前像素存下这个颜色（下面第 8-9 行）。最终图像以 ppm rabbits 格式保存到磁盘（上面第 25-34 行）。


Vec3f castRay(

    const std::vector&ltstd::unique_ptr&ltObject>> &objects,
    const std::vector&ltstd::unique_ptr&ltLight>> &lights,
    const Options &options,
    uint32_t depth)
{
    Vec3f hitColor = (dir + Vec3f(1)) * 0.5;

在计算机图形学中，用不同做法得到同一结果的方式往往有好几种。如果你去看其他渲染引擎的源代码，很可能会发现把光线从图像空间变换到世界空间这个问题有很多种解法。当然，无论采用哪种做法，结果都应当相同。

例如，我们可以这样看这个问题：像素坐标不必归一化（也就是说，不必从像素坐标转到 NDC 再转到屏幕空间）。我们可以用下面的公式计算光线方向：

$$ \begin{array}{l} d_x &=& x - width / 2 \\ d_y & = & height / 2 - y\\ d_z & = &-(height / 2) / tan(fov * 0.5). \end{array} $$

其中 x 与 y 是像素的坐标，fov 是竖直视场角。记住 \(d_z\) 为负，因为相机默认沿负 z 轴朝向。然后如果我们把这个向量归一化，得到的结果与走一遍光栅到 NDC、NDC 到屏幕变换是相同的。如果我们把这个光线方向变换到世界空间（用相机到世界矩阵乘以向量 d），就得到：

$$ \begin{array}{l} d_x &=& (x - width / 2) u_x + (height / 2 - y) v_x - ((height / 2 ) / tan(fov * 0.5)) w_x \\ d_y &=& (x - width / 2) u_y + (height / 2 - y) v_y - ((height . 2)/tan(fov * 0.5)) w_y \\ d_z & =  & (x -width /2) u_z + (height / 2 - y) v_z - ((height / 2)/tan(fov * 0.5)) w_z \end{array} $$

展开并重新归并各项，得到：

$$ \begin{array}{l} d_x & = & x u_x - width / 2 u_x + height / 2 v_x - y v_x - (height /2 )/tan(fov * 0.5) w_x \\ & = & x u_x + y (-v_x) + (width / 2 u_x + height / 2 v_x - (height / 2) /tan(fov * 0.5) w_x) \\ d_y & = & x u_y - width / 2 u_y + height / 2 v_y - y v_y - (height /2 )/tan(fov * 0.5) w_y \\ & = & x u_y + y (-v_y) + (width / 2 u_y + height / 2 v_y - (height / 2) /tan(fov * 0.5) w_y) \\ d_z & = & x u_z - width / 2 u_z + height / 2 v_z - y v_z - (height /2 )/tan(fov * 0.5) w_z \\ & = & x u_z + y (-v_z) + (width / 2 u_z + height / 2 v_z - (height / 2) /tan(fov * 0.5) w_z) \end{array} $$

可以改写成（公式 1）：

$$d = x u + y (-v) + w'.$$

其中 \( w' = (-width / 2) u + (height / 2) v - ((height / 2) / tan(fov * 0.5)) w.\)

换句话说，如果知道相机到世界矩阵，我们可以预先算出 w' 向量，用公式 1 在世界空间中算出光线方向，再对得到的向量归一化。伪代码如下：


Vec3f w_p = (-width / 2 ) * u + (height / 2) * v - ((height / 2) / tan(fov_rad * 0.5); 
Vec3f ray_dir = normalize(x * u + y * (-v) + w_p);

向量 w' 只需计算一次，之后每次需要计算新的光线方向时重复使用即可。向量 u、v 与 w 就是相机到世界矩阵的第一、第二和第三个向量（如果你用行主序矩阵，就是前三行）。
