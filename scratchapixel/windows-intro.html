窗口系统的通用问题

阅读时间：8 分钟。

没有窗口的世界？

在屏幕上显示图像是件根本性的重要事情。这种重要性来自一个事实：自 1980 年代以来，人们已经清楚地看到，通过图形用户界面（GUI）与程序打交道，通常比用命令行界面更高效。能生成图像却看不到它，那种挫败感相当大。你们中很多人属于千禧一代和 Z 世代，可能没直接经历过这种事，但计算机生成图像（CGI）的先驱们往往只能在无法实时在屏幕上与图像交互的情况下做图。早期很多图像处理软件都是靠命令行操作的，完全没有图形界面。懂得如何把图像显示到屏幕上，在做图像相关工作时非常有帮助。随着我们在 CGI 技术里越走越深，能看到并与程序生成的东西交互，价值会越来越大。不过有几点要说明：

  • 这个过程看起来可能吓人，但它比想象中容易上手。

  • 尽管这件事很重要，但找相关资料却可能很难，因为它常被忽视，虽然也有一些优质的教程和入门材料，尤其是在讲 DirectX 这类实时图形 API 的资料里。

这个主题的教学资源之所以稀缺，可以归结为几个因素，而这些因素常被教育者忽略或不去讨论：

  • 它有时被学界看成一项没有内在价值的技能，学生自己学学就行——这是一种误解。

  • 它依赖于操作系统。显示内容、尤其是显示图像的方法，在 Windows、MacOS、Linux 以及其他系统之间差别很大。即便在 Linux 这样一个系统内，也有多种做法，虽然底层概念大体相同。

  • 它被认为很复杂。这往往涉及理解操作系统的原生机制、使用相对底层的库，而人们觉得这需要多年经验。这话部分（不）对。

这种局面有几个后果：

1. 为了满足所有人的需要，我们得分别讲如何在 Windows、Mac、Linux 等系统上创建并显示图像，工作量是使用统一 API 的三倍。由于我们的资源有限，会先聚焦 Windows，你们中绝大多数人都在这个平台上工作。不过请放心，Mac 与 Linux 的基础知识我们后面也会涉及。

2. 很多人会建议（往往是那些看起来不希望你成功的专业人士）使用 Qt 这类现成的库。Qt 本身倒没什么天生的毛病，但它确实有明显缺点。它是个庞大的库，还有不少古怪之处，比如有一个特殊的预编译步骤，把你代码里独特的语法转换成编译器能用的 C++ 代码，以及它极度依赖的「slot」概念等等。学 Qt 当然也是一条路，但我们这里不会讲。用 Qt 这类库的主要优势是跨操作系统兼容，而我们会演示如何不靠它也能做到——是的，这完全可行。

3. Qt 的替代品，比如 GLFW，为跨操作系统的窗口问题提供了更简单的解决方案。尽管 GLFW 很流行、也容易集成，但它有自身的局限，最终可能还是把你推回原生窗口系统。因此从一开始就学原生做法是有好处的。你会发现，理解和编译窗口相关的代码并不像看上去那么可怕，尤其是它很短。

4. 要演示如何用窗口搭建 3D 应用，实时图形 API 似乎是个合适的选择。然而，看当前 3D 图形 API 的形势——OpenGL 正走向过时，而 DirectX、Vulkan（用于 Windows——Mac 上则是 Metal）这类替代品又很复杂——要把这些塞进一个简短的形式里很难。所以我们的课程会从在窗口里显示一个光线追踪的三角形开始，从而避开对实时图形 API 的需求。这种不常规的做法可以绕过大量图形 API 前置课程带来的复杂度。

我是不是说过这挺好玩。嗯，对极客来说确实好玩。

话不多说，开始吧。

不同操作系统下窗口系统的通用问题

在深入实践之前，必须明白所有窗口系统都基于相似的原理运作。除了窗口的外观之外，我们这里讨论的是你的程序与它的用户之间的交互机制。这不仅包括窗口本身，还包括鼠标、键盘这类输入设备。

下面是它如何运作的简化说明：

  • 首先，你初始化一个窗口，设置大小、标题这类基本属性。

  • 接着，让窗口可见。

  • 然后，一个有意思的过程开始了。你的程序开始响应输入。最常见的输入来自鼠标和键盘。你的窗口应用进入一个无限的事件循环，监听事件，而事件可以是来自鼠标或键盘的某个动作。当你移动鼠标或按键时，操作系统检测到这个动作，把它转发给你应用的事件循环，等于在说：「这是用户触发的一个事件。」你的程序通过操作系统 API 提供的函数收到事件数据（例如新的鼠标位置、按下的键），并据此作出反应。你与计算机的交流就是这样进行的。

用伪代码表示，这个交互过程大致如下：


void MyWindowProcFunc(WindowHandle handle, Message msg, SomeParams params) {
    switch (msg) {
        case MOUSEMOVE:
            int x = ConvertParamsToInt(params[0]);
            int y = ConvertParamsToInt(params[1]);
            // 处理鼠标移动
            break;
        case LEFTBUTTON:
            // 处理鼠标左键按下/松开
            break;
        ...
    }
}

WindowHandle CreateWindow(...) {
	WindowsProperties prop;
	prop.title = "This is My First Window";
	prop.size.width = 640;
	prop.size.height = 480;
	// 还有颜色等其他属性
	...
	prop.identifier = MY_WINDOW_ID;
	prop.proc = MyWindowProcFunc;

	WindowHandle handle = CreateWindow(∝);

	ShowWindow(handle);

	return handle;
}

void DoSomeWork() {
	Render();
	ForceRedraw();
}

int main() {
	CreateWindow(...);
	Message msg;
	while (1) {
		while (MessagesInQueue()) {
			msg = GetMessage(POP_FROM_QUEUE);
			if (msg.value == QUIT)
				break;
			DispatchMessage(msg);
		}
		// 附加任务，比如渲染一张图像……
		DoSomeWork();
	}

	CleanWindow(handle);
    ...
}

上面这段伪代码深受 Windows 操作系统处理窗口事件的方式启发，但底层概念在各类系统上都广泛适用。有一点必须理解：应用在其 main() 部分的无限循环中一直运行。这个循环的每一轮，应用都会检查是否有新到的消息。操作系统通常把这些消息排成队列，这意味着你的应用可能需要在同一个循环周期内依次处理多条消息。

如果遇到一条表示应用应当退出的消息，就跳出循环，程序接着清理与窗口相关的资源。还有一点值得注意：收到消息后，它们会被分派出去，从而调用另一个在创建窗口时指定的函数 MyWindowProcFunc。你在这个函数里定义如何响应各种可能的消息，比如鼠标移动或点击，以及大量其他事件，例如操作系统为窗口重绘而发起的绘制消息、键盘动作等。

在我们的例子里，我们只关注鼠标移动和鼠标左键的按下/松开。不过还能处理许多其他消息，包括窗口被别的窗口遮住之后的重绘、键盘输入的处理等等。这种结构使应用能够及时响应、具备交互性，可以处理各种各样的用户输入与系统通知。

这里没有提到 MY_WINDOW_ID，但下一节会更详细地讨论它。这个标识符在我们应用中对窗口资源的管理与交互起着关键作用。

注意，处理完事件之后，我们在回到事件处理之前还有机会做别的事。这个循环会一直持续下去，直到你决定退出应用。在我们的代码里，这些任务封装在 DoSomeWork() 函数中。渲染 3D 场景图像、做图像处理这类活动都在这里进行。同时也要向窗口发出信号，表明我们希望用更新后的图像刷新其内容。这种做法是制作动画的基础。通过按固定间隔生成新帧，并请求窗口 API 刷新显示，我们就能让内容动起来。下一章会给出这一过程的实际演示。
