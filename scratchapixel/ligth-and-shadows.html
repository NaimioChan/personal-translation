光照与阴影

阅读时间：9 分钟。

如上一章所述，这里只是对光照与阴影的一个高层次入门。想进一步研究这个题目的读者，可以去读 深入 BRDF、线性与曝光 和 光照简介 这两门课。它们虽然同属入门部分，但对光的实现讲得更深。之后你可以接着读进阶部分的课程。

本章结构

本章我们将学习如何给图像加入阴影。

光与阴影

在旁边这张图里，我们看到一个漫反射球体和一个漫反射平面，被一盏平行光源照亮。要让这张图更真实，现在还缺的是球体在平面上的阴影。好在在计算机图形学（CG）中，模拟物体在场景中其他物体上投下阴影这件事相当直接。不过，这取决于你用哪种算法来求解可见性问题。

  • 如果用的是光栅化，给场景加阴影没法轻松地在一趟里做完。它需要先从光源的视点预先计算物体的可见性，存放在一种特殊的图像里，叫作阴影贴图。场景中每盏灯都要算一张阴影贴图，而且这个过程必须在你渲染最终图像之前完成。我们打算以后写一门讲这个技术的课程。

  • 如果用的是光线追踪，阴影可以在渲染主图像的过程中顺带算出来（不需要预先计算阴影贴图那样的特殊图像）。我们要做的，就是从通过某个像素可见的物体出发，自交点向光源投一条光线。如果这条光线——我们称之为阴影光线——在射向光源的途中与其他物体相交，那么正在着色的这个点就处在该物体的阴影中。

前面已经多次提到，现实世界中光是自光源传向眼睛的。阴影是一些物体挡在光路上、使光无法到达更远处另一个表面所造成的结果。不过你现在也知道，在 CG 中，从眼睛向光源追踪光路效率更高。因此我们先追踪一条相机光线即主光线，找到交点（也就是投出这条主光线的像素所看到的表面），再从该交点向光源投一条阴影光线。自然界的实际过程与 CG 中计算阴影的方式之间的差别见图 2。

在光线追踪器里加阴影很简单。如果主光线与某个物体相交，我们算出交点，再沿光的方向（更准确地说，是光的反方向）多投一条光线。这很简单，因为计算光线与构成场景的物体求交所需的代码我们都已经有了。眼下我们只学如何加入平行光源投下的阴影。本章后面会讲怎么对球形光源做同样的事。代码如下：


Vec3f castRay( 
    const Vec3f &orig, const Vec3f &dir, 
    const std::vector&ltstd::unique_ptr&ltObject>> &objects, 
    const std::unique_ptr&ltDistantLight> &light, 
    const Options &options) 
{ 
    Vec3f hitColor = options.backgroundColor; 
    IsectInfo isect; 
    if (trace(orig, dir, objects, isect)) { 
        Vec3f hitPoint = orig + dir * isect.tNear; 
        Vec3f hitNormal; 
        Vec2f hitTexCoordinates; 
        isect.hitObject-&gtgetSurfaceProperties(hitPoint, dir, isect.index, isect.uv, hitNormal, hitTexCoordinates); 
        Vec3f L = -light-&gtdir 
        IsectInfo isectShad; 
        bool vis = !trace(hitPoint + hitNormal * options.bias, L, objects, isectShad, kShadowRay); 
        hitColor = vis * isect.hitObject-&gtalbedo * light-&gtintensity * light-&gtcolor * std::max(0.f, hitNormal.dotProduct(L)); 
    } 
 
    return hitColor; 
}

可以看到，我们只是再次调用了 trace 函数（第 16 行），并在 trace 返回 true 时把变量 vis 设为 false（交点处在阴影中，因此该点未被平行光源照亮），否则设为 true（交点不在阴影中，因此该点被光源照亮）。剩下的只是把交点的颜色乘以这个变量的值。如果该点在阴影中，它就是黑的。如果 vis 为 true，该点的颜色保持不变（第 17 行）。

优化

注意，在判断一个点是否处在某物体的阴影中时，阴影光线与物体相交的先后顺序并不重要。阴影光线相交的物体是不是离光线起点最近的那个，也无关紧要。对阴影光线来说，我们只关心它到底有没有与任何物体相交；若相交，投出这条阴影光线的点就在阴影中。实际含义是：对阴影光线，我们完全可以在与场景中第一个物体相交时就立即从 trace 函数返回。这有可能省下一些计算时间。

不过，这个优化只有在场景中所有物体都完全不透明时才可行。如果有些物体是透明的，那么光在穿过这些半透明物体时可能被衰减，这类光线应当继续穿过物体，直到在射向光源的途中遇到不透明物体，或者一直到达光源本身为止（只有在球形光源的情形下才有「到达光源」，平行光被假定位于无穷远，不存在这种情况）。本节不会讲如何处理阴影光线的半透明物体问题。如果你打算以后支持半透明物体，现在就去为阴影光线做代码优化并不划算；但若你有兴趣探究，可以作为练习。

阴影痤疮：避免自相交

用光线追踪计算阴影时一个常见问题叫作阴影痤疮，在旁边这张图（上图）里能看到。这种视觉瑕疵表现为物体表面的小黑点。由于我们的 3D 引擎中数值精度有限而引入的一些微小误差，交点有时并不正好位于表面之上，而是略微偏下。此时若沿光方向投出阴影光线，它既不会完全不相交，也不会与物体表面上方的其他物体相交，而是与投出它的那个表面相交。换句话说，出现了自相交。物体确实可以给自己投下阴影，但在这个具体情形里，这是个错误：它之所以发生，只是因为交点位于表面之下而不是正好在表面上。这种情况如图 4（中图）所示。主光线与某个表面相交，但由光线起点与方向以及相交距离 \(t\) 算出的交点，恰好略低于表面，而不是正好在表面之上。从这个位置投出阴影光线，阴影光线就会与这个点本应所在的表面相交，从而把该点标记为处于阴影中。

有几种方法可以缓解这个问题。一种办法是改用双精度而非单精度浮点数，也就是用 double 代替 float。这并不能消除问题，但能降低它发生的可能性。更简单也更稳健的办法，是系统性地把阴影光线的起点沿表面法线方向挪动，使其位于表面之上（图 4 下图）。沿法线方向挪动多少由使用者决定，可以逐个场景调整。在光线追踪器里，这个值常被称为阴影偏移。

阴影偏移这个说法在阴影贴图里也会用到。参见讲阴影贴图的课程。

写成代码就是这样：


struct Options 
{ 
    ... 
    float bias = 1e-4; 
}; 
 
Vec3f castRay(...) 
{ 
    ... 
    bool vis = !trace(hitPoint + hitNormal * options.bias, L, objects, isectShad, kShadowRay); 
    ...
}

可以看到，偏移一般是一个很小的值。所需偏移量取决于多种因素，如场景尺度、物体的曲率、物体到相机的距离等。如前所述，调偏移是消除阴影痤疮最省事的办法，但它首先得逐个场景调整。更重要的是，改变阴影光线起点的实际位置后，得到的结果会与我们从表面上「真实」的那一点投出光线所得到的结果略有差异。偏移越大，应当得到的阴影与图像中出现的阴影之间差别就越大（如图 5 所示）。因此调节偏移值是一种平衡：既要足够大，使最终画面中不出现痤疮，又要尽可能小，以减小阴影偏移带来的影响（这种把光线推到表面下方或上方的技巧，在投射反射光线和折射/透射光线时也会用到，详见模拟 反射与折射 的那一章）。
