坐标系

阅读时间：25 分钟。

探索坐标系

坐标系是图形管线中的一个基础环节，概念简单却很关键。它往往在早期的几何教育里就已出现，理解坐标是更透彻地掌握矩阵的垫脚石。

在前面的讨论中我们指出，在计算机图形学（CG）里，点与向量由三个实数定义。这些数表示从直线的原点到该直线上某点的带符号距离。想象画一条直线，把它的中心标为原点。这个标记就是我们的参照点，是度量到其他点距离的基准。位于原点右侧的点被赋予正的带符号距离，表示它大于零；反之，左侧的点为负值。

我们假定这条直线从原点向两侧无限延伸。这意味着直线上任意两点之间的距离可以无限大。不过在计算中，数的表示受用于编码的位数限制，这给我们能处理的数值设了一个实际的上下限。幸运的是，这个限制通常足以构建 CG 中打算渲染的 3D 场景，所以目前计算上的约束不是大问题。

有了直线和原点，我们在原点两侧引入等距的刻度（单位长度），把直线变成一把可度量的尺。这把尺让我们能确定某点相对于原点的坐标，「坐标」指的就是从原点到该点的带符号距离。在计算机图形学与数学中，这把尺称为轴（axis）。

设想某点并不正好落在轴上。我们仍然可以用一条竖直线把它投影到轴上（假定轴是水平的），通常用一条垂直于轴的线，从而确定它的坐标。这条竖直线与轴相交的位置，就给出该点相对于这根轴的坐标——这就是沿一根轴确定点坐标的方法。

探索维度与笛卡尔坐标系

在坐标系概念的基础上，我们来看看维度是如何加入的，先从前面所说的 x 轴——我们的水平尺——开始。在 x 轴的原点处再放一把与它成直角的尺，就得到 y 轴。这样一来，向每根轴作垂线并量出到原点的距离，就能同时确定任意点的 x 坐标与 y 坐标，方法与前面所述相同。于是我们可以给任意点赋予两个坐标：一个表示它沿 x 轴的位置，另一个表示它在 y 轴上的位置。通过这一机制，两根轴的交汇定义了一个二维空间，也就是一个平面。

想象在一张纸上标出若干个点，这个动作发生在二维空间里。当我们在这张纸上画两根轴——每个维度一根——并用它们测量每个点的位置时，我们实际上就建立了一个坐标系。如果这两把尺以直角相交，它们就构成所谓的笛卡尔坐标系。

要表示一个点在这个系统中的坐标，我们使用有序对，即两个用逗号分隔的数。在笛卡尔坐标系中，惯例是先写 x 坐标（水平），再写 y 坐标（竖直）。例如 x 坐标为 2.5、y 坐标为 2.25 的点写作 (2.5, 2.25)，如图 2 所示。这种记法让人一眼看出该点位于原点右侧 2.5 个单位、上方 2.25 个单位处。后面讨论中我们都用这种方式描述点的坐标。

掌握这些之后，我们就知道了如何建立二维笛卡尔坐标系，以及如何定义其中二维点的坐标。必须认识到：在给定的坐标系内，点的坐标是唯一的，也就是说同一个点不可能同时拥有不同的坐标。

虽然在一个平面内可以定义任意多个坐标系，为简单起见，我们只考虑画在同一张纸上的两个笛卡尔坐标系。纸上同一点被赋予的坐标会随所用坐标系而不同。例如在图 3 中，点 P 在坐标系 A 中的坐标是 (-1, 3)，在坐标系 B 中是 (2, 4)，说明尽管坐标不同，该点的物理位置并未改变。

要把点的坐标从一个系统换算到另一个系统——比如从 A 到 B，这是计算机图形学（CG）与数学中的一项基本操作——我们只需把 (3, 1) 加到该点在系统 A 中的坐标上，就得到它在系统 B 中的坐标。反过来，从系统 B 的坐标中减去这些值，就回到系统 A 中的值。这个过程体现了加法逆元的概念，以及它们在坐标系之间换算时的作用。

此外，像平移（在同一坐标系内把点移到新位置）和缩放（通过乘法改变点的坐标）这样的操作，演示了线性算子作用于点坐标的方式。比如缩放会让点沿着穿过该点与原点的直线移动，凸显了点与向量之间的变换关系。这些概念的进一步探讨会在后续课程中继续。

扩展到三维

从二维坐标系过渡到三维坐标系是很自然的延伸，它引入第三根轴——称为 z 轴——与 x 轴和 y 轴都正交（垂直），从而为原本扁平的表示增添了深度。在这种安排下，x 轴向右延伸，y 轴向上伸展，z 轴向后投射，当 x 轴指向右方来观察时，它看起来像是从屏幕里伸出来。这种安排并非唯一可能，但在 Scratchapixel 的讨论中我们会一直采用。这个三维框架所定义的，更正式的名称是欧几里得空间，它是几何学中的基石概念。

要进一步深入，尤其是对坐标系的形式化层面感兴趣的读者，我们转向线性代数原理。这里基（basis）的概念变得不可或缺。在坐标系的语境中——无论是一维的单轴、二维的双轴，还是刚介绍的三维——各根轴构成了该系统的基。基是一组线性无关的向量，通过线性组合可以表示某个特定向量空间（即该坐标系本身）内的任意向量（或点）。若一个集合中的向量无法用同集合中其他向量的线性组合表示，则这些向量被认为是线性无关的。基变换——也就是更换坐标系——这一操作在数学与图形管线中都举足轻重，它让同一空间内不同视角与维度之间的转换成为可能。

理解左手坐标系与右手坐标系

坐标系手性的概念因为惯例不一而多了一层复杂性。看 z 轴相对于 x 轴（右向量）与 y 轴（上向量）的朝向，最能说明这层复杂。把屏幕看作 XY 平面，y 轴朝上、x 轴向右延伸时，z 轴（也叫前向量或下向量）既可以指向屏幕里，也可以指向你，这就表明了深度的方向。

为区分这两种朝向，我们把前一种安排称为左手坐标系，后一种称为右手坐标系。物理学家 John Ambrose Fleming 提出的左手定则与右手定则，使这两类系统的区别变得清晰。

左手系与右手系的区分很直接：x 轴向右、y 轴向上时，若 z 轴背离你，就是左手坐标系；反之，若 z 轴朝向你，就是右手坐标系。

要轻松记住每种坐标系的朝向，可以用手作助记。把拇指、食指和中指分别指派为 x、y、z 轴——这个顺序正好与我们伸手指的方式一致。左右手各做一次，让拇指朝右、食指朝上，此时中指所指的方向就是 z 轴的方向：

  • 用左手时，z 轴背离你。

  • 用右手时，z 轴朝向你。

这个方法可能需要一点手上功夫，但确实能帮你稳定地记住这些坐标系里 z 轴的朝向。因此，「左手」「右手」坐标系这些说法，或者说一个系统的「手性」，就源自这一身体上的表示。

手性大概是计算机图形学里争论最多的话题之一（至少据我观察如此），因为它一直是困惑的来源，对正在学图形学的人尤其如此。这也因为，我从未见过、也不知道有哪个资料在这个题目上堪称权威，能把问题讲得清楚、不含糊，并且配有插图。

困惑来自几个方面：

  • 一方面，我本人在职业生涯中就用过好几种不同的配置来解释这个概念。这一点我后面还会回头说。

  • 困惑还源于这样一个说法：Y 轴与 Z 轴会因你是数学家还是物理学家而互换。不对，这是错的，但我故意把这句留在那里，看你是不是在认真读。X 轴与 Y 轴并不会互换。真正的惯例问题在于：指向上方（朝向你的天花板或天空）的那个上向量，到底取 Z 还是取 Y。这不是标签的互换，而是你如何定向坐标系的选择。不过关键在于，一旦你用自己偏好的惯例定好了坐标系——用 Z 轴还是 Y 轴作上向量——你就可以再判断它是左手系还是右手系。

解释这一点最好的办法是举例。就拿 Unreal Engine 使用的坐标系来说。如果你认为当 X 轴指向右方时，Unreal Engine 的坐标系就是右手系——因为把右手拇指朝右、食指朝上、中指朝向自己应该能对上——那你就错了。别担心，每个人这辈子至少会在这上面迷路一次。

事实上，如果你看 Unreal Engine 界面里显示的坐标系，会注意到朝上的那根轴是蓝色：那是 Z 轴。朝向你的那根轴是绿色：那是 Y 轴。而如果你读 Unreal Engine 的文档，它会告诉你这个坐标系是左手坐标系。什么？为什么？

因为实际上，用手指时——不管是你左手还是右手的手指——你要做的只是把 X 轴对应拇指、Y 轴对应食指、Z 轴对应中指，仅此而已。拇指：红色，X。食指：绿色，Y。中指：蓝色，Z。问题在于，如果你用右手去对 Unreal Engine 的坐标系，会发现无论怎么扭手腕、手臂或手指，都对不上那张图。事实上，如果你把右手拇指指向右、食指朝向自己，你的中指（代表 Z 轴）就会朝下。所以，它确实是个左手坐标系。

用左手做这个动作，需要手与前臂弯成 90 度，相当困难。但如果你做到了，手指最终能与 Unreal Engine 界面中显示的坐标轴对齐。

秘诀——一旦有人讲给你听就很简单——就是只用我刚给你的方法。按顺序张开手指：拇指、食指、中指，并对每根手指大声念出：X、Y、Z。就这样。然后把手指定向到与你所用软件的坐标系一致，就能看出这个软件用的是左手系还是右手系。顺便说，如果屏幕上没显示 X、Y、Z 这些字母，就看颜色。通常，除非有人疯狂到把问题搞得更乱，大家都应该用红、绿、蓝分别表示 X、Y、Z 轴。

现在你已经是这方面的行家，可以拿这套东西去惊到朋友了，那我们来看看你是不是真的理解了。我们再看 Maya 和 Blender 这类软件用的是哪种坐标系。

为什么选择左手系还是右手系很重要？严格说起来并不关键，但这个选择确实有后果，比如在沿构成多边形的各顶点遍历计算法线时，法线的朝向会受影响。看下面这个例子：一个三角形由三个顶点 \(v_0 = (0, 0, 0)\)、\(v_1 = (0, 0, 1)\) 和 \(v_2 = (1, 0, 0)\) 定义。下图给出了在左手系与右手系中分别绘制的这个三角形。

现在，我们来计算两个三角形的法线。给定顶点（两个系统相同）：

  • \(V_0 = (0, 0, 0)\)

  • \(V_1 = (0, 0, 1)\)

  • \(V_2 = (1, 0, 0)\)

我们计算三角形的边：

1. \(\mathbf{v1} = V_1 - V_0 = (0, 0, 1)\)

2. \(\mathbf{v2} = V_2 - V_0 = (1, 0, 0)\)

然后求叉积：

$$\mathbf{N} = \mathbf{v1} \times \mathbf{v2} = (0, 0, 1) \times (1, 0, 0) = (0, 1, 0)$$

写到这里我才意识到，向量的点积与叉积要到后面几章才讲。如果你对这些概念不熟，别慌。继续往下读几页，等弄明白叉积是什么，再回头来看这一节就行。

无论用哪个坐标系，我们都得到 \((0, 1, 0)\)。所以乍看之下，坐标系的手性并不影响三角形的法线。可再看图 9——你会发现两个三角形的图像并不相同。也就是说，三角形的数据一样，视觉结果却不同。这不是我们想要的。一般来说，生成一个三维物体的图像时，我们希望无论内部用哪种惯例，画面看起来都一样。至少这是人们能指望的。

要让左手坐标系中的三角形与右手坐标系中的一致，我们需要把它绕 Z 轴旋转 180 度。注意，是把左手系画出的三角形旋转去匹配右手系的三角形，还是反过来，都无所谓。实践中我们不做旋转，而是把顶点的 X 坐标取负（或视配置取 Z 坐标），以此从一个系统切换到另一个。所以，在左手坐标系中视觉上相近的三角形（假定我们要让它与右手系中画出的三角形外观一致）会有如下坐标：

  • \(V_0 = (0, 0, 0)\)

  • \(V_1 = (0, 0, 1)\)

  • \(V_2 = (-1, 0, 0)\)

我们计算三角形的边：

1. \(\mathbf{v1} = V_1 - V_0 = (0, 0, 1)\)

2. \(\mathbf{v2} = V_2 - V_0 = (-1, 0, 0)\)

然后求叉积：

$$\mathbf{N} = \mathbf{v1} \times \mathbf{v2} = (0, 0, 1) \times (-1, 0, 0) = (0, -1, 0)$$

法线反了。由此可以得出：要得到相同的视觉结果，法线是反向的。所以，如果你的初始数据是相对左手坐标系定义的，当它在右手坐标系中绘制时（假定物体视觉上看起来一样），该物体的法线会被反转（反之亦然）。因此，坐标系的选择有一个直接后果：它决定了三角形法线的朝向。

如果你把右手手指按下图那样卷起来，手指所指的方向就是右手坐标系中正角旋转的方向。例如把三角形旋转 30 度，它会如图 10 那样转动；若旋转角为 -30 度，则反向转动。用右手时你能看到手指指示的是逆时针旋转（与钟表指针方向相反的旋转）。这也意味着，假设三角形顶点的排列方向与你的手指一致，法线就会指向拇指的方向。举例来说，假定你计算 (v1 - v0) 和 (v2 - v0)，且顶点 v0、v1、v2 按逆时针方式定义，那么三角形的法线就沿拇指所指的方向。

同样的原理也适用于左手。在左手坐标系中，卷起手指后，它们所指的方向表明旋转角为正时三角形绕某轴（比如上向量）旋转的方向（对 x 轴和 z 轴同样可以这么做）。当顶点按顺时针排序时（按你卷起手指给出的朝向），拇指就表明三角形法线的方向。

下图用一个顶点为 \(V_0 = (0,0,0)\)、\(V_1 = (0,0,1)\) 和 \(V_2 = (2,0,0)\) 的三角形说明这个概念。在左手坐标系中，如果我们从 \(v0\) 沿顶点走到 \(v2\)，是在按顺时针方向走。在右手坐标系中，如果我们从 \(v0\) 经 \(v1\) 走到 \(v2\)，则是绕上向量逆时针走。两种情况下，拇指都表明法线朝上。这在数学上是自洽的，因为如前所述，顶点坐标相同，所以 \(e1 = v1 - v0\) 与 \(e2 = v2 - v0\) 相同，因而叉积 \(n = e1 \times e2\) 也相同。

然而，正如前面指出的，两个三角形的样子会不同。如果我们在左手坐标系中把所有顶点的 x 坐标取负，使两个三角形看起来完全一致，那么请注意，此时从 \(v0\) 沿顶点走到 \(v2\) 变成逆时针旋转——与你手指卷起的方向相反。这意味着三角形的法线会指向与左手拇指相反的方向；换句话说，在这种配置下它会朝下。

如果你还没反应过来，原因在于：顺时针旋转之后，顶点现在会以这样的顺序出现：\(v0, v2, v1\)。因此 \(e1 = v2 - v0\) 与 \(e2 = v1 - v0\)，这两个向量的叉积给出法线 (0, -1, 0)。

这个例子表明，选择左手系还是右手系主要影响两件事：

  • 旋转方向：即知道角度为正或为负时物体是顺时针还是逆时针旋转，这可以用卷起左手或右手手指的方法来判断。

  • 法线方向：同样用卷手指的方法，拇指表明法线指向的方向，前提是顶点按手指的朝向排序。在左手坐标系中，顶点按顺时针排序时法线朝上；在右手坐标系中，顶点按逆时针排序时法线朝上。

这些细节大多在现代图形 API（如 Metal、Vulkan 或 DirectX）中是可配置的。你可以指定引擎期望顶点以何种顺序提供。这些参数在你创建所谓图形管线时定义。下面是这些控制在 Vulkan API 中如何设置的一个例子：


VkPipelineRasterizationStateCreateInfo info = {
	...
	.polygonMode = VK_POLYGON_MODE_FILL,
	.cullMode = VK_CULL_MODE_BACK_BIT,
	.frontFace = VK_FRONT_FACE_COUNTER_CLOCKWISE,
	...
};

这并不影响这些 API 如何计算法线，因为事实上图形 API 不会替你算法线；你需要在顶点着色器或片元着色器里自己算。不过，你在这些着色器里算出的法线朝向，既取决于三角形顶点定义的顺序，也取决于你指示引擎期望的顺序，因为这影响着传进着色器用于计算法线的数据以何种方式给出。

这一点很重要，因为图形引擎会执行一个叫剔除的过程。剔除是去掉那些法线不朝向相机的三角形，它们被视为背面三角形，你可能不想渲染。不过现代图形 API 也允许你剔除正面三角形、同时剔除正反面，或者完全关闭剔除。但重点不在这里。重点是：如果你选择剔除正面或背面三角形，那么三角形算正面还是背面，既取决于顶点排序，也取决于你设置的这些控制参数。

对 Scratchapixel 以及为演示课程概念而写的代码，我们一律使用右手坐标系。在这个系统中，Y 轴朝上，Z 轴（由你的中指代表）朝向你，X 轴指向右方。

结束这个话题前要指出：你所选择、或在数字内容创作工具（如 Blender、Maya、Unreal Engine）中被要求使用的坐标系手性，通常不是什么大问题——直到你在工作流中同时使用其中几个工具。比如你可能用 Houdini 做特效、Maya 做建模与动画、Blender 做渲染，或者用 Unreal Engine 做游戏开发。具体组合因人而异。

真正的问题出现在这些工具之间导出、导入资产（尤其是几何体）的时候。如果它们使用的坐标系手性惯例不同，你就得在过程中——通常是导入时——处理数据。举例说，假设你在 Maya 里工作，那里 Y 轴是上向量。如果你把这套几何体直接导入 Blender，而 Blender 里 Y 轴表示深度而不是上向量，你的几何体可能会躺着出现而不是立着（像一座雕像）。这种情形下，你需要交换物体顶点的 Y 与 Z 坐标来纠正朝向。

软件之间的手性差异是生产管线中主要的问题来源之一，也可能格外令人沮丧。选这套还是那套，往往出于历史原因，而不是常识，也不是为了让美术和用户的日子好过些。如果你有选择惯例的余地，我建议坚持用 Y 轴为上向量的右手坐标系。这个选择会在后面替所有人省掉大量麻烦。

认识世界坐标系

在三维应用的旅程中，我们已经看到点与向量的位置和方向如何锚定在一个笛卡尔坐标系的原点上，而这个坐标系由三个互相垂直的单位向量构成的基所建立。这番探索揭示了可以构造出无数个坐标系，每个都让点在自身范围内获得一组唯一坐标。然而，支撑大多数三维环境结构的，是世界坐标系。这个主坐标系搭好舞台，提供基础的 x、y、z 轴，其他所有坐标系都从它那里取得朝向。在渲染管线所用的坐标系群（包括专门用于物体、局部环境（尤其在着色语境下）、相机和屏幕的那些）里，它是基石。这些系统的细节将逐步揭开。

需要记住的核心概念

基础几何的要点或许很多读者已经熟悉，但这场讨论的要点更偏向让你熟悉图形学（CG）文献中随处可见的术语。本讲的重点术语是坐标、轴与笛卡尔坐标系。词汇表还因引入缩放、平移这类线性算子而更加丰富，它们在操作点与向量时起着关键作用。要带走的不仅是几何原理本身，还包括这样一个认识：点总是与某个坐标系绑定，而坐标系可以造出无穷多个，每个都给同一个点不同的坐标。

同样关键的是，要能辨认你所用坐标系的手性——无论是在自己的编程中，还是在用于图像渲染的 API 里。这种辨识能力有助于厘清坐标系手性与轴朝向惯例之间的细微差别，让这些概念在各类图形学应用中顺利衔接。
