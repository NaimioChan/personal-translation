光源

阅读时间：10 分钟。

本课写于 2010 年代初的某个时候。它的定位是着色中一些最基本概念的轻量入门。这一章的内容今天依然成立，也可以当作光源的入门读物，适合不打算在这个题目上深入的人。若想读者对图形学中的光源有深入得多的了解，推荐阅读以下课程：深入 BRDF、线性与曝光的一次创造性探索 和 光照简介，后者于 2024 年首次发布。

光源

在开始生成我们第一张着色图像之前，先要介绍光的概念。如前几课所述，一个场景由相机、物体和光源组成。光源是特殊的「实体」，其唯一作用是指示场景中光从何处发出。如前所述，我们之所以能看见物体，唯一原因是光源发出的光从物体表面弹射出来。如果场景中没有创建光源，场景应该渲染成黑色。

现实世界中，每个光源都有实体。光源是具有发光属性的物体。不过，光源也无非是一个标准物体：它有形状，有大小。但它有一项别的物体没有的属性：它发光。因为光源本身也是物体，它们也可以被眼睛直接看到。不过一般来说，千万不要用裸眼直视光源，那可能有害。直视太阳确实会灼伤眼睛。但其他光源我们可以安全地凝视，比如营火的火焰或手电筒的灯泡。如果你正在读这几行字，你此刻就正看着一个：你手机或电脑的屏幕。问题在于，在 CG 中以物理准确的方式模拟光，也就是把它们表示为有形状和大小之物，计算代价很高。这类光源称为面光源，或者更一般地说，几何面光源。因此，CG 中的光源很长一段时间里都只被表示为理想化对象，即没有物理大小的实体。与面光源相对，这类光源有时也叫delta 光源（源自 delta 函数一词，它是数学中的一种特殊函数，可以说就是为了定义一个自然界中不可能存在、但在抽象的数学世界里确实存在的函数而造的。尽管抽象，它在解决各种有趣的实际问题上极其有用）。我们大致可以区分两类 delta 光源：平行光或称远距光源，以及球形光源或称点光源。前者一般是后者的一个子集，这一点我们稍后解释。

你需要知道：delta 光源在计算机图形学的早期被使用，是出于实际原因——很长一段时间里模拟面光源代价太高。随着 2000 年代后期计算机变快，切换到面光源也慢慢变得实际可行。使用 delta 光源，尤其是在今天，应该尽可能避免。为什么？因为不把光表示为面光源会带来很多问题。例如，我们知道物体会反射其他物体，而光源本身也是物体，那么它们当然也应该被光泽表面或镜子反射。但一个物体被光泽表面反射出的像的大小，取决于被反射物体的大小以及它与光泽表面的距离（这两个概念——物体的大小，以及被反射物体到反射表面的距离——可以合并为立体角的概念，本课不会多谈。想了解更多，请看高级部分的课程）。

当光源没有大小时，就根本无法决定它在光泽表面上反射出的像应该有多大！这在渲染领域造成了很多年的麻烦。人们不得不用各种花招来控制这些反射像的大小：调整反射表面的粗糙度，同时在光源本身上人为控制一个「粗糙度」参数。这样做可以逐光源地欺骗光源的大小，但显然永远无法产生物理准确的图像。好在如今这类做法几乎完全消失了，主要因为如前所述，模拟面光源现在负担得起了（尽管模拟面光源在计算上仍然昂贵，需要细致的优化）。

使用面光源是基于物理的渲染（PBR）的前提条件，这个词你可能已经熟悉。这个话题在高级部分的课程中有非常详细的讲述。你也可以在本节最后一课找到更多相关信息。

远距光源

远距光源被认为极其遥远，以至于它发出的光到达我们时是平行光线。对于这类光源，唯一相关的因素就是这些光线的方向。太阳就是远距光源的一个例子。虽然太阳是个球体，可能被当作球形光源，但在太阳系的尺度乃至更大尺度上，是的，它表现得像个球形光源。不过如下图所示，地球相对于太阳很小，离这颗恒星也相当远，因此到达地球表面的太阳光被包含在一个极窄的方向锥内。

这个锥的立体角，对熟悉该概念的读者来说，只有大约 0.0000687 球面度。在 CG 中，当我们渲染只覆盖地球表面一小块区域的场景时，可以放心假设照亮该场景的太阳光线全都平行。可能存在可以忽略的变化，但它小到我们可以完全不考虑。我们大概永远不会有足够的数值精度来准确表示这种变化。简单说：我们不在乎。打到地球表面的太阳光线是平行的。因此，这种情况下我们只关心光线的方向，这就是平行光一词的由来。光源相对于所渲染场景的位置无关紧要，因为光线之所以平行，唯一原因就是光源离场景极远，于是光线被包含在一个极小的方向锥内，这也带来了「远距光源」这个叫法。本质上，在 CG 中模拟太阳或任何其他远距光源，我们只需要一个方向，别的什么都不需要。

注意，太阳非常遥远，但它在天空中有着可见的大小。事实上，说来也许令人惊讶，太阳在天空中看起来比月亮更大。

本课我们会先渲染漫反射物体，并学习如何用远距光源投射阴影。然后学习如何模拟球形光源。

球形光源

球形光源是自然界中最常见的一类光源。在某种程度上，即使不是球形的光源也可以近似为一组球形光源。与远距光源不同，球形光源的位置至关重要。事实上，对球形光源来说，位置就是唯一重要的事。我们需要知道它们在空间中的位置。如果 \(P\) 是物体表面上我们想要着色的某一点，那么找出球形光源朝 \(P\) 发出的光线的方向就很简单：它无非是 \(P\) 减去球形光源的位置（我们称之为 \(L_P\)），如图 2 所示。

$$\text{Light Direction} = P - L_P.$$

后续各章中我们会说明，\(P\) 与光源之间的距离也很重要（对球形光源是如此，对远距光源则不是：照亮物体的光量取决于光源与物体之间的距离）。我们会用到这个距离，然后用它把光方向向量归一化。本课后面会解释这一点。

光的强度（与颜色）

除了光源的位置（如果它是球形或点光源）或光的方向（如果它是远距或平行光源），我们还需要什么来定义一个光源？在计算机图形学中，光源发光，我们可以把光表示为颜色与强度的组合。通常最好把光的颜色定义为 [0,1] 区间内的值，把光的强度定义为 0 到无穷大（或到计算机代码中浮点数能表示的最大值）。最终发出的光量由光的颜色乘以强度算出：

$$\text{light amount} = \text{light color} \times \text{light intensity}.$$

实现

在代码中，我们通过创建一个特殊的 Light 类把光源与几何体区分开。这个基类包含以下成员变量：

  • lightToWorld：光源同样可以被 4x4 矩阵变换。这个矩阵用来计算球形光源的位置和平行光的方向。

  • color：光源的 RGB 颜色（取值范围 [0,1]）。

  • intensity：光的强度。

代码如下：


class Light {
public:
    Light(const Matrix44f &l2w) : lightToWorld(l2w) {}
    virtual ~Light() {}
    Matrix44f lightToWorld;
    Vec3f color;
    float intensity;
};

默认情况下，我们假设光源点在世界的原点处创建。我们用光源到世界矩阵把光源变换到它在世界空间中的位置。注意光源不受缩放变化影响。点光源也不受旋转影响（平行光则会受影响），而平行光不受平移影响。下面是点光源的一种可能实现：


class PointLight {
public:
    PointLight(const Matrix44f &l2w, const Vec3f &c = Vec3f(1), const float &i = 1) : Light(l2w) {
        this-&gtcolor = c;
        this-&gtintensity = i;
        l2w.multVecMatrix(Vec3f(0), pos);
    }
    Vec3f pos;
};

类似地，对于远距光源，我们默认假设光方向沿 z 轴负方向（与 Maya 中的默认朝向类似）。换句话说，默认的光方向是 (0,0,-1)。

要修改或控制光的方向，我们调整光源到世界变换矩阵：


class DistantLight {
public:
    DistantLight(const Matrix44f &l2w, const Vec3f &c = Vec3f(1), const float &i = 1) : Light(l2w) {
        this-&gtcolor = c;
        this-&gtintensity = i;
        l2w.multDirMatrix(Vec3f(0, 0, -1), dir);
        dir.normalize();
    }
    Vec3f dir;
};
