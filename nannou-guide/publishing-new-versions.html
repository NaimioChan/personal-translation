发布新版本

nannou 仓库允许社区成员提交 PR 来发布 nannou 各 crate 的新版本。这让维护者发布新发布变得容易得多——我们所要做的就是接受你的 PR！

发布由 release-plz 自动完成。一旦版本号提升的 PR 合并到 master，CI 就会按正确的依赖顺序发布每个版本尚未出现在 crates.io 上的 nannou crate，然后创建 vX.Y.Z git 标签和带有自动生成说明的 GitHub Release。你永远不需要手动运行 cargo publish。

维护者请注意：发布通过 Trusted Publishing 向 crates.io 认证（不存储 API 令牌）。一次性配置请参见下文的Trusted Publishing 设置。

如果你希望看到一个新版本被发布，请遵循以下步骤。

选择版本

使用的版本取决于所做的变更。nannou 的 crate 遵循 Rust 的约定，你可以在这里了解相关内容。

小贴士！crate 版本中的每个数字都有自己的名称：

例如在版本 0.15.3 中，0 是「主」（major）版本，15 是「次」（minor）版本，3 是「修订」（patch）或「小」（tiny）版本。在阅读 Rust 中有关版本控制的内容时，请留意这些名称。

按照约定，发布的 nannou crate 共享同一个版本（工作区版本）并一起提升版本号，这样用户一眼就能判断出兼容的版本。这只是约定而非硬性要求——下文的 set_version 会为你一起提升它们的版本号，但当一次发布有需要时，没有什么能阻止你以不同的方式选择版本。未发布的 crate——示例和各种支持性 crate——保留各自的版本号，不做改动。

提升版本号

版本号只存在于一个地方——根 Cargo.toml 中的 [workspace.package].version——发布的 crate 通过 version.workspace = true 继承它。内部 nannou_* 依赖对应的版本要求则位于根 [workspace.dependencies] 表中。

要一次性提升这两处，请使用 scripts/set_version 中的小程序：

cargo run --bin set_version -- "0.42.0"

这会把 [workspace.package].version 以及 [workspace.dependencies] 中每个内部 nannou* 条目的 version 设置为新版本。

更新指南

指南中有两处需要更新：

  1. guide/src/changelog.md 中的 Changelog。这是手写的散文，与自动生成的 GitHub Release 说明分开维护——我们在其中描述一次发布的亮点和任何迁移说明。在 Unreleased 标题下添加一个日期和发布标题（可参考最近的版本作为示例）。
  2. guide/src/getting_started/create_a_project.md 第 3 步中的 nannou 版本号（即代码片段的 [dependencies] 部分）。

除此之外，我们在指南中避免提及具体版本，以便于更新。如果你熟悉 grep，可以用它来复查是否还有更多需要更新的地方：

grep -nr "= \"0.14\"" guide/

其中 0.14 是 nannou 上一个版本的开头。这会列出前一个版本仍然出现、很可能需要更新的文件和行号。

提交 PR

现在你应该准备好提交 PR 了！请务必遵循 PR 检查清单。

提示：撰写 Conventional Commit 风格的提交信息（feat:、fix:、破坏性变更为 feat!: 等）可以让自动生成的 GitHub Release 说明保持整洁，因为 release-plz 会按类型对它们分组。

一旦你的 PR 通过评审并合并，CI 就会发布新版本、为发布打标签并自动创建一个 GitHub Release。

恭喜，你刚刚为 nannou 社区在 crates.io 上发布了一些好东西！

Trusted Publishing 设置

本节面向维护者——这是一次性设置，不是上述每次发布流程的一部分。

CI 通过 GitHub OIDC 使用 Trusted Publishing 向 crates.io 认证，因此没有作为密钥存储的长期 crates.io API 令牌。发布任务会在发布时通过 rust-lang/crates-io-auth-action 铸造一个短期令牌（这就是该任务拥有 id-token: write 权限的原因）。

要让这奏效，每个发布的 crate 都需要在 crates.io 上配置一个受信任的发布者。在该 crate 的 crates.io 页面上，进入 Settings -> Trusted Publishing -> Add a new trusted publisher 并填写：

  • Repository owner（仓库所有者）：nannou-org
  • Repository name（仓库名）：nannou
  • Workflow filename（工作流文件名）：ci.yml
  • Environment（环境）：留空（或者，如果你还为发布任务添加了匹配的 environment: 以获得额外保护，也可以设置一个 GitHub Actions 环境名）

crates.io 只允许你为已经存在的 crate 添加受信任的发布者。因此，任何从未发布过的 crate 都必须先用令牌发布一次（例如用个人 API 令牌执行一次性的 cargo publish），然后才能配置其受信任的发布者。从那以后，每次发布都经由 CI 完成，无需存储任何密钥。
