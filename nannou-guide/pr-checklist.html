PR 检查清单

创建 PR 时，有几件事你可以做，以帮助你的变更顺利落地：

  • 代码格式化 - 最容易被遗忘的一步是运行 cargo fmt --all（我总是忘记）！这一步确保 nannou 代码库拥有一致的风格。
  • 错误 - 所有变更都必须构建成功，且所有测试都必须通过，我们才能合并各个 PR。请记住，在本地运行测试可能会花上很~~~长的时间，所以有时更简单的做法是先打开你的 PR，让仓库机器人代你检查。
  • 警告 - 在你最后一次提交之前，务必处理掉遗留的代码警告。请记住，由于编译器的 linter 在版本之间发生变化，有时警告是本来就存在的。至少请确保你的变更没有带来任何新的警告 :)
  • 检查示例 - 通过运行 cargo run --bin run_all_examples 确保示例仍然可用。这会执行一个脚本，构建并运行项目中的所有示例。你需要手动检查示例是否运行成功（例如检查是否有 wgpu 验证错误）。
  • 文档 - 如果你所做的任何变更可以从更新某些代码文档中受益，请务必这样做！试着站在第一次阅读你代码的人的角度想一想。
  • Changelog - changelog 作为仓库的人类友好历史，在社区成员于 nannou 的不同版本之间更新时尤其有用。请务必把你的变更添加到 guide/src/changelog.md 中。
  • PR 评论 - 请务必在你的 PR 中添加以下内容，以便评审者更容易理解和落地你的代码：
    • 变更的动机。是什么启发了这个 PR？请链接到任何相关议题。
    • 变更的摘要。任何有助于评审者理解你的变更做了什么的内容都会大有帮助！

如果你在提交 PR 之前忘记了其中某一步，别慌！nannou 仓库有一个 CI（持续集成）机器人，它会检查其中一些步骤，并在发现任何不妥之处时通知你。一旦机器人检查通过，社区成员会评审其余部分。
