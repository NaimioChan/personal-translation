为什么选择 Nannou？

nannou 是一组代码，旨在让艺术家能够用简单、快速、可靠、可移植的代码表达自我。无论是做一个 12 个月的装置作品，还是一个 5 分钟的草图，这个框架的目标都是让艺术家轻松获得他们需要的工具。

这个项目源于一个愿望：打造一个受 Processing、OpenFrameworks 和 Cinder 启发、但面向 Rust 的创意编程框架。名字取自这个。

如今，nannou 构建在 Bevy 游戏引擎之上。nannou 的各个 crate 以一组 Bevy 插件的形式暴露，这意味着你既能使用 nannou 友好的 sketch/app API 和 Draw 接口，也能在需要时随时接入更广泛的 Bevy 生态（它的 ECS、渲染器、资产系统和插件）。

目标

Nannou 旨在为艺术家提供对所需事物的轻松、跨平台访问：

  • [x] 窗口与事件，通过 Bevy（其底层使用 winit）。
  • [x] 音频，通过 CPAL。支持输入和输出流。尚不支持双工。
  • [x] 视频播放，通过 nannou_video crate；摄像头输入，通过 nannou_webcam。
  • [x] GUI，通过 egui。未来可能切换为 nannou 自有的方案（见 future）。
  • 几何，提供用于生成顶点和索引的函数与迭代器：
    • [x] 一维 - Scalar、Range。
    • [x] 二维 - Path、Polyline、Polygon、Rect、Line、Ellipse、Quad、Tri。
    • [x] 三维 - Cuboid。
    • [ ] 三维待办 - Ellipsoid、Cube、棱柱、金字塔、Hedrons、Camera 等。
    • [x] 顶点与索引迭代器。
    • [x] Graph，用于组合几何。
  • 图形，通过 Bevy 的渲染器（构建于 wgpu 之上）：
    • [x] Draw API。例如 draw.ellipse().w_h(20.0, 20.0).color(RED)。
    • [x] Mesh API。
    • [x] Image API。
    • [x] Texture API。
    • [x] WGPU API。
    • [x] Text API。
    • [ ] 着色器热加载。参见 hotglsl 和 nannou_isf WIP。
  • 协议：
    • [x] OSC - Open Sound Control。
    • [x] ISF - Interactive Shader Format。
    • [x] CITP - Controller Interface Transport Protocol（网络实现正在进行中）。
    • [x] Ether-Dream 激光器 DAC 协议与网络实现。
    • [x] DMX via sACN - 常用于灯光与特效。
    • [x] Serial - 常用于连接 LED 及其他硬件。
    • [x] MIDI - 通过 nannou_midi crate 实现的跨平台 MIDI 输入/输出（构建于 midir 之上）。
    • [x] UDP，通过 std。
    • [x] TCP 流与监听器，通过 std。
  • 设备与 I/O 流 API：
    • [x] 窗口。
    • [x] 应用事件。
    • [x] Audio。
    • [x] Video 与 Webcam。
    • [x] Lasers。
    • [ ] 灯光。目前，我们推荐通过 sacn crate 使用 DMX。
    • [ ] LED。目前，我们推荐通过 sacn crate 使用 DMX。
  • [ ] 图形化节点图，通过 gantz。
  • [ ] GUI 编辑器。

Nannou 的目标是只使用纯 Rust 库。作为新用户，你只需 cargo build 就能上手。只有在尚无开发中的 Rust 替代方案时，才会把回退到 C 绑定视为临时方案。相比依赖对 C 代码的绑定，我们更愿意推动那些尚不成熟的 Rust 替代方案向前发展。这样应该能让 nannou 的用户更容易成为 nannou 的贡献者，因为他们不必为了向上游贡献而学习第二门语言。

Nannou 不会包含 unsafe 代码，只有在必要时绑定操作系统或硬件 API 的情况除外。

Nannou 希望消除在众多提供相同硬件访问的不同后端之间做选择的需要。相反，我们想专注于一组特定的后端，并确保它们运转良好。

为什么选 Rust？

Rust 是一门既高度富于表达力、又快如闪电的语言。以下是我们选择它的一些原因：

  • 速度超快，达到 C 与 C++ 级别的快。
  • 标准包管理器，让处理依赖和在几秒内分享你自己的项目变得非常容易。
  • 高度可移植。轻松为 MacOS、Linux、Windows、Android、iOS 以及众多其他平台构建。
  • 没有头文件，也没有奇怪的链接错误。
  • 和类型与模式匹配，且没有 NULL。
  • 局部类型推断。只在要紧处写类型，不必重复自己。
  • 一种更现代的、函数式且富有表达力的风格。
  • 内存安全且无数据竞争！尽情记录你的想法，不必担心造出指针意大利面或陷入段错误的时间黑洞。
  • 默认不可变。一眼就能区分哪些变量可以改变、哪些不可以。
  • 模块系统，带来非常干净简洁的命名空间。
  • 我们遇到过的最友善的互联网社区之一。如果你刚入门、需要指点，请访问 mozilla 的 #rust 或 /r/rust。

为什么采用 Apache/MIT 双许可？

在很大程度上，nannou 试图在许可方面保持与 Rust 本身相同的最大灵活性与兼容性，Rust 本身也是双许可的。

Apache 2.0 与 MIT 许可非常相似，但有一些关键区别。以 Apache 2.0 许可接受贡献会触发 Apache 2.0 的专利授权。这项授权旨在防止利用专利法体系绕过（部分）许可条款。如果贡献以 Apache 2.0 许可提供，贡献者即保证他们不会主张（自己的）专利被侵犯。如果有人基于 Apache 2.0 许可的代码创作了作品，他们反过来也承诺不起诉他们的用户（侵犯专利）。

MIT 许可则与许多其他 FLOSS 许可具有兼容性。
