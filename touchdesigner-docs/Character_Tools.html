角色工具

骨骼组件

Bone Component 是所有 Character Tools 的基础。它是一个组件，具备 Geometry Component 的大部分属性。它还有一些额外特性，例如长度、两种几何、首尾相连以及运动学参数。

骨骼几何 - 默认情况下，Bone Component 包含两种几何：link geometry 和 capture geometry。两者都在 Bone Component 的 SOP 网络中定义，因此可以自定义。大多数情况下默认设置就够用。

link geometry 是一个细长的菱形，其中一个角位于 Bone Component 的原点，对角沿 Bone Component 的负 z 轴延伸，长度与 Bone Component 的 length 参数值一致。这种链接几何只是用来直观显示 Bone Component 的位置和大小。

capture geometry 定义一个捕获区域，可用于把骨骼变形应用到其他几何。它由两个椭圆组成，沿 Bone Component 的长度方向排列。Bone Component 中有多个参数可用于调整这两个椭圆的大小和位置。如果某个 Bone Component 是另一个 Bone Component 的直接子级，它的捕获几何还会包含用户指定数量的椭圆，把子级的第一个椭圆与父级的第二个椭圆连接起来。这些椭圆让你可以额外控制角色「关节」处的骨骼变形。

链接几何和捕获几何有各自独立的参数控制是否显示。通常，在给骨骼定位时显示链接几何，在定义用于骨骼变形的捕获区域时显示捕获区域。角色设置完成后，可以把两个显示参数都关掉。

Bone Component 的 SOP 网络中这两类几何的构建方式都相当简单，值得一看。

链接几何由两个底座相对放置的锥形网格组成，并用一个引用 Bone Component 的 length 参数的 Transform SOP 拉伸。结果再送入一个 Switch SOP，它会根据 Bone Component 的 Display Link 参数值，在链接几何与空之间切换。

捕获几何用两个 Circle SOPs 创建，它们引用 Bone Component 中相应的参数来决定大小和朝向。它们的大小同时取决于 Bone Component 的 Ellipse 1 & 2 Radius 和 Length 参数。这样默认捕获区域对常用骨骼来说大小会比较合理。只需修改各个圆 Radius 参数中的表达式，就能轻松去掉对 Length 的依赖。

捕获几何的关节部分用一个专为此任务创建的 Joint SOP 生成。它会在父 Bone Component 的最后一个椭圆（通过名为 parent_end 的 Object Merge SOP 导入）与当前 Bone Component 的第一个椭圆（circle1）之间创建中间椭圆。

注意：为了让 Joint SOP 正常工作，parent_end 的参数必须由用户手动设置，除非该骨骼是用骨骼创建状态创建的。

Joint SOP 的输出与 circle2 合并，构成 Bone Component 的捕获几何。该几何再送入另一个 Switch SOP，其显示控制方式与链接几何所用的 Switch SOP 类似。

有一个名为 point 的 Add SOP，它输出单个点。当链接几何和捕获几何不显示时，就用它来替代。由于它的 display 标记已设置，它也是 Bone Component 的可见几何。

首尾相连定位 - 默认情况下，Bone Component 的 Transform 参数中有一个表达式，会执行以下操作之一：

  • 如果骨骼没有父级，其原点锁定在世界原点。
  • 如果其父级是 Bone Component，则锁定在父骨骼的末端。
  • 如果父级是其他类型，则锁定在该父级的原点。

上面第二种情况称为骨骼的首尾相连定位，这是最常用的行为。

要覆盖此行为，可编辑骨骼 Transform 参数中的表达式，或直接删除包含表达式的通道（在参数上右键，然后选择 Delete Channels）。如果修改后想恢复表达式，可在参数对话框的 Presets 菜单中用 Load 命令加载文件 $HS/presets/bone/end_to_end.preset。

骨骼参数 - 骨骼参数在 Bone Component 中讨论。

需要注意，一些常见的变换参数（scale、pivot、transform order 和 rotate order）不出现在 Bone Component 的参数列表中，但它们确实存在，并可通过通道编辑器或键盘命令修改。只有这些值保持不变时，骨骼定位和运动学才能正常工作。以下是这些参数及其正确值：

Scale：1, 1, 1　Pivot：0, 0, 0　Transform Order：Scale Rot Trans　Rotate Order：Rz Ry Rx

创建骨骼 - 虽然可以逐个创建骨骼，但我们强烈建议使用 Bone Creation State（见 TouchDesigner Interface Guide 中的 Bone Creation State）。Bone Creation State 大大简化了创建骨骼的流程。它会在需要时在骨骼基部建立 Null Component，使运动学解算表现更好。

骨骼解算器

任何线性的 Bone Component 层级都可以组织成一个 Bone Chain。该层级中的第一根骨骼称为 Bone Chain 的 Driver，其中包含对链中最后一个 Bone Component 的引用。

定义好 Bone Chain 后，可以给它关联一个 Kinematic Solver，由它决定 Bone Chain 中每个 Bone Component 的朝向。例如，可以使用 Follow Curve Kinematic Solver，把 Bone Chain 中的骨骼沿给定曲线对齐。这个解算器和其他运动学解算器会在下面的 Kinematic Solvers 中讨论。

所有 Kinematic Solver 的输入都是 Bone Chain 中每个 Bone Component 的长度，以及它处于「at rest」时的朝向。每个 Kinematic Solver 还可能要求其他专属参数。例如 Follow Curve Solver 需要 Bone Chain 应对齐的那条曲线。各 Kinematic Solver 根据输入计算出骨骼链的合适朝向，并作为输出返回。

链的静止角通常用于指定链的初始朝向，解算由此推导。Bone Chain 中每根骨骼的静止角位于该骨骼参数的 Bone 页中。解算器的专属参数也在同一个 Bone 页中指定，但只在 Bone Chain 的 Driver 中。

每次 Driver 计算时，它都会收集 Bone Chain 中每根骨骼的所有静止角，连同解算器专属参数一起传给相应的 Kinematic Solver。然后它取解算器的输出，设置骨骼链中每根骨骼的旋转参数。

注意，由于 Driver 会设置每根骨骼的旋转参数，用户不应给旋转参数做动画，它们总会被 Kinematic Solver 给出的值覆盖。

运动学解算器

简介 - TouchDesigner 中有四种运动学解算器。Kinematic Solver 负责确定骨骼链的朝向。每个解算器会按其所用算法和给定参数来调整给定骨骼链的朝向。

  • 反向运动学
  • 沿曲线运动学
  • 显示静止位置
  • 显示捕获位置

前两个解算器用于在动画中控制骨骼链，后两个则作为「辅助」工具使用。

本节将逐一讨论这些解算器。此外还会介绍一种称为 Forward Kinematics 的骨骼链控制方法。

反向运动学 - 在反向运动学中，我们指定骨骼链末端的期望位置，解算器随后求出骨骼链中相应的一组关节角度。骨骼链的期望位置用某个组件的原点来指定。IK 解算器会尝试弯曲骨骼链，使其末端触及该组件的原点。这个组件称为链的 end-affector。骨骼链的起点（第一根骨骼起点的位置）称为链的 base。

TouchDesigner 的 IK 解算器产生唯一解。也就是说，对给定的 end-affector 位置，无论 end affector 的移动方向如何，总是得到相同的解。其次，IK 解的形状可以通过改变骨骼链的静止角来交互式调整。第三，TouchDesigner 的 IK 是可变长度的（prismatic），这意味着你可以给骨骼链中的骨骼长度做动画，IK 解算器仍会持续求解 end-affector 位置。最后，TouchDesigner 的 IK 既支持平面 IK 链（2D），也支持非平面 IK 链（3D）。

TouchDesigner 如何确定反向运动学的解？ - 设想如下情况：一条 IK 链完全伸直（所有骨骼在一条直线上），然后把 end affector 移近链的 base。链中的关节必须弯曲，才能让 end-affector 移进来。问题在于：「这种情况下 TouchDesigner 如何决定关节往哪个方向旋转？」答案是：你通过骨骼的 Rest Angles 来指定偏好的旋转方向。

静止角 - 简单来说，IK 链中的每个关节都会朝 Rest Angle 旋转。因此在下图中，如果一条链的静止角如虚线所示（Rest），那么从完全伸直状态被压缩时，链会趋向粗线所示的构型（I.K. Solution）。

调整静止角提供了一种交互式方法，让你在能满足给定 end affector 位置的多种关节朝向中做选择。此外，静止角还规定了 end affector 移动时每根骨骼旋转的相对量。从这个意义上说，静止角可以看作每个局部关节旋转的「相对权重」。

也就是说，在下图中，由于静止角 Qrest 比静止角 Frest 更锐，end-affector 移动时对应关节会旋转得更多。但要注意，IK 解算器只在某一点之前偏好更锐的角度，超过之后它就不得不去旋转更浅的角度。

平面 IK 与非平面 IK - 在平面 IK 中，所有关节都相当于铰链。只在 X 或只在 Y 上放置非零静止角，就得到平面 IK 链。如果静止角涉及多个维度，或不同骨骼绕不同维度，得到的链就是非平面的。此时每个关节相当于球关节而不是铰链。

平面 IK 比非平面 IK 更快，通常也更好管理。非平面的肢体常常可以拆成若干组平面 IK 链。在 TouchDesigner 的 IK 中，每条 IK 链的起点天然就是一个球关节。因此，通常用两条或更多平面 IK 链就能实现非平面 IK 链的效果，只需把第二条 IK 链的起点放在角色中球关节应出现的位置。

IK 的附加控制

骨骼长度 - 此参数控制骨骼段的长度，可做动画。随着骨骼长度变化，IK 解算器会调整内部关节角度，使链的末端始终贴在 end-affector 上。但要注意，如果你为骨骼长度设置了通道并改变了骨骼长度，IK 解算器要等到设置关键帧或时间标记后才会计算（红色关键帧指示器由红变绿）。

Twist - 此参数指定绕一条轴的旋转，该轴从骨骼链的 base 延伸到 end-affector。它非常适合控制链顶端球关节的扭转。

沿曲线运动学 - TouchDesigner 的 Follow Curve 运动学提供了一种控制多段骨骼链的方法，例如脊椎或尾巴。

Follow Curve 运动学需要一段可供跟随的曲线几何（Curve Object 参数）。该曲线可以是任意类型（NURBS、Bezier 或多边形）。Follow Curve 会调整链内的关节角度，使骨骼链顺着曲线的形状。如果曲线离骨骼太远（即骨骼在物理上够不到曲线），会调整该骨骼的关节角度，使骨骼末端与曲线之间的距离最小。

一条跟随曲线的链，曲线远离链的前两根骨骼

显示静止位置 - 此运动学解算器会读取每根骨骼 Rest Position 参数中的骨骼角度，并用这些角度旋转各骨骼。如果你想查看骨骼处于静止位置时的朝向，这个解算器很有用。

显示捕获位置 - 此运动学解算器与 Show Rest Position 类似，区别在于它使用 Capture Angles 参数中的角度来确定各骨骼的朝向。

Bone Component 的捕获角保存了该骨骼最后一次在 Skeleton SOP 中用于捕获点时的朝向。可以用 Show Capture Position 解算器把骨骼链摆回捕获时的状态，以便调整捕获区域。

正向运动学控制 - 在正向运动学中，我们指定每根骨骼的旋转，从而把骨架末端带到空间中的某个位置。从这个意义上说，正向运动学并不是真正的运动学解算器。

在 TouchDesigner 中有两种方式控制正向运动学。第一种是创建骨骼链层级，直接改变每个 Bone Component 的 Transform 标签页中的角度。请记住，Bone Component 仍然是 TouchDesigner 组件，因此可以像几何、摄像机和灯光那样设置父级和变换。

第二种控制正向运动学的方法是创建由单骨骼反向运动学链组成的层级。之后就可以用每条单骨骼 IK 链的 end-affector 在视口中直接操纵关节旋转。

带 affector 和层级的正向运动学链。

使用骨骼状态创建正向运动学链时，会自动建立这种带 affector 的正向运动学。更多内容见 TouchDesigner Interface Guide 中的 Bone Creation State。

骨骼创建状态

Bone Creation 状态是 TouchDesigner 的 Character Tools 之一。它让你可以在视口中绘制，以交互方式创建骨骼链。Bone Creation 状态的一些特殊功能包括：

  • 自动创建捕获区域、Bone Component 和 end affector。
  • 轻松把新的骨骼链设为其他几何的子级。
  • 控制新几何的命名。
  • 用自定义几何替换标准骨骼几何。
  • 以数值精确指定骨骼位置。
  • 尽可能避免非平面 IK 链。

Bone Creation 状态的完整说明见 TouchDesigner Interface Guide 中的 Bone Creation State。

用骨骼使几何变形

TouchDesigner 有三个 SOP 用于定义骨骼使几何变形的方式。这解决了分配点变形权重的问题（其他一些软件称之为「weighting」）。它提供了最程序化、最直观也最灵活的方式来为角色加权并使其变形。

Capture Region SOP - Capture Region SOP 定义一个体积（两端各带半球的管）。位于该 Capture Region 内的点会随 Capture Region 移动而变形。

Capture SOP - Capture SOP 为几何分配点捕获权重。点捕获权重作为点属性与几何一起存储。Capture SOP 不改变几何的外观，只是为 Deform SOP 的变形做好准备。

Deform SOP - Deform SOP 根据几何中的点捕获属性真正使几何变形（顾名思义）。把几何的加权与变形拆成两个 SOP，是为了让你在这两步之间能灵活地以程序化方式修改几何和/或权重。
