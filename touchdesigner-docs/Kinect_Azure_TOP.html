Kinect Azure TOP

摘要

注意

OS: 此操作符仅在 Microsoft Windows 10 April 2018 or newer 操作系统下受支持。

Kinect Azure TOP 可用于配置 Microsoft Kinect Azure 摄像头或 Kinect 兼容的 Orbbec 摄像头（Femto Mega、Femto Bolt 等）并从中采集数据。

该 TOP 可用于配置摄像头设置（分辨率、帧率、同步等），也可从彩色或深度摄像头获取采集的图像。来自一台摄像头的图像数据可以重新映射（对齐）到另一台摄像头，以匹配彩色与深度信息。每台 Kinect 摄像头只能连接一个 Kinect Azure TOP。要从同一摄像头获取更多图像，请使用 Kinect Azure Select TOP。

Kinect Azure 还可以利用深度摄像头图像提取身体跟踪信息与骨骼位置。要访问这些数据，请使用 Kinect Azure CHOP，并将其 Kinect TOP 参数设置为连接到该设备的主 Kinect Azure TOP。注意： Microsoft 与 Orbbec 硬件可以用于同一个项目，但任一时刻只能有一种硬件类型启用身体跟踪。Player Index 图像或获取骨骼数据需要身体跟踪。如果不需要 Orbbec 的身体跟踪，建议改用原生的 Orbbec TOP。

注意： Orbbec Femto Mega 不会自动支持通过 Kinect Azure TOP 或 CHOP 的以太网连接。不过，可以使用放在 toe 文件旁边的外部配置文件启用以太网设备检测。以太网连接仅支持深度与 IR 图像，彩色视频仅支持通过 USB 传输。有关该文件的更多信息，请参阅 Orbbec documentaion。

警告： 使用 Orbbec 硬件时，在同一项目中使用 Kinect Azure 与 Orbbec 节点可能导致不稳定。建议根据项目需求，全部使用 Kinect Azure 节点或全部使用 Orbbec 节点。

提示： 参见 Elburz 关于使用 KinectAzure 点云及一批 Azure 通用技巧的视频。在 Interactive and Immersive HQ 上的 Kinect Azure Point Cloud in TouchDesigner Tutorial。

另请参阅 Kinect Azure CHOP、Kinect Azure Select TOP、Palette:pointRender、Palette:kinectCalibration、Palette:kinectRecorder、Palette:kinectPointcloud。

参数 - Kinect Azure 页

Active active - 启用或禁用摄像头。注意 禁用此 TOP 也会禁用任何依赖它的其他操作符（Kinect Azure Select TOP 或 Kinect Azure CHOP）。
Hardware Type library - 选择使用 Microsoft Kinect Azure 硬件还是 Kinect 兼容的 Orbbec 摄像头（Femto Mega、Femto Bolt 等）。两种摄像头可在同一项目中一起使用，但任一时刻只能有一种硬件类型启用身体跟踪。
  • Microsoft Kinect Azure microsoft - 如果使用原版 Microsoft Kinect Azure 摄像头，请选择此选项。
  • Orrbec Compatible (Femto Mega, Femto Bolt, ...) orbbec - 为 Kinect 兼容的 Orbbec 摄像头（例如 Femto Mega、Femto Bolt 等）选择此选项。并非所有 Orbbec 摄像头都与 Kinect Azure 兼容。一般的 Orbbec 支持请使用 Orbbec TOP。
Sensor sensor - 已连接 Kinect Azure 摄像头的序列号。TOP 会自动将所有可用摄像头填入列表。注意：每台摄像头只应连接一个 Kinect Azure TOP。
Camera FPS fps - 控制彩色与深度摄像头的帧率。某些较高分辨率在 30FPS 下不受支持。较低的帧率可在低光条件下生成更亮的彩色图像。
  • 5 FPS fps5 -
  • 15 FPS fps15 -
  • 30 FPS fps30 -
Color Resolution colorres - 彩色摄像头采集图像的分辨率。不同分辨率的宽高比可能不同。注意：4096 x 3072 在 30 FPS 下不受支持。
  • 1280 x 720 (16:9) 1280x720 -
  • 1920 x 1080 (16:9) 1920x1080 -
  • 2560 x 1440 (16:9) 2560x1440 -
  • 2048 x 1536 (4:3) 2048x1536 -
  • 3840 x 2160 (16x9) 3840x2160 -
  • 4096 x 3072 (4x3) 4096x3072 - 注意：30FPS 下不支持此分辨率。请将帧率降至 15 或 5 FPS 以使用此设置。
Depth Mode depthmode - 深度模式控制使用 Kinect 两个深度摄像头中的哪一个（Wide 或 Narrow FOV）生成深度图像，以及是否使用「binning」处理数据。在「binned」模式下，2x2 像素块会被合并，生成经过滤波的低分辨率图像。注意：Passive IR 深度模式不支持身体跟踪。
  • Narrow FOV - Unbinned (640x576) narrowunbinned -
  • Wide FOV - 2x2 Binned (512x512) widebinned -
  • Narrow FOV - 2x2 Binned (320x288) narrowbinned - 注意：不建议将此模式用于身体跟踪。
  • Wide FOV - Unbinned (1024x1024) wideunbinned - 注意：30FPS 下不支持此模式，也不建议用于身体跟踪。
  • Passive IR (1024x1024) passiveir - 注意：此模式不支持身体跟踪。
Body Tracking Model modelpath - 执行身体跟踪功能的 ONNX 模型文件路径。TouchDesigner 包含 Kinect Azure SDK 中的常规模型与精简模型。
Body Tracking Processing Mode proccessingmode - 决定身体跟踪模型的处理方式。默认模式主要在 GPU 上运行（支持 Nvidia、AMD 和 Intel），在没有兼容 GPU 时也可以切换到 CPU 模式。
  • GPU Default gpudefault - 默认处理模式。在 Windows 上运行时等同于 DirectML。
  • CPU cpu - AI 模型将运行在 CPU 而非显卡上。速度明显更慢，不建议用于正式发布。
  • DirectML directml - 在 Windows 上运行时等同于默认模式。AI 模型将运行在 GPU 上。兼容 Nvidia、AMD 和 Intel GPU。
Body Tracking GPU Device gpu - 系统中有多块 GPU 时，要使用的 GPU 设备编号。排序方式可能取决于 GPU 制造商。
Sensor Orientation orientation - 用于指示摄像头安装时未处于竖直位置。这有助于改善身体跟踪结果。
  • Default default -
  • Clockwise 90 Degrees cw90 -
  • Counterclockwise 90 Degrees ccw90 -
  • Flipped 180 Degrees flipped -
Image image - 可从设备采集并在此 TOP 中显示的可用图像类型列表。所有图像类型都有第二个版本，会映射（对齐）到另一台摄像头的图像空间，以便匹配彩色与深度图像数据。图像分辨率由 Color Resolution 或 Depth Mode 参数控制，取决于所选的图像类型。使用 Kinect Azure Select TOP 可从同一摄像头访问更多图像类型。
  • Color color - 来自彩色摄像头的 8 位 RGBA 图像。
  • Color aligned to Depth colorremap - 重新映射以与当前深度摄像头图像对齐的彩色摄像头图像。分辨率由 Depth Mode 决定。
  • Depth depth - 单通道 32 位浮点深度图像，像素值表示距摄像头的距离（单位：米）。分辨率与视场由 Depth Mode 参数决定。
  • Depth aligned to Color depthremap - 重新映射以与当前彩色摄像头图像对齐的深度图像。分辨率由 Color Resolution 参数决定。
  • IR ir - 由深度摄像头采集的 16 位整数红外图像。分辨率与视场由 Depth Mode 决定。
  • IR aligned to Color irremap - 重新映射以与当前彩色摄像头图像对齐的红外图像。分辨率由 Color Resolution 参数决定。
  • Player Index playerindex - 8 位单通道图像，将像素映射到身体跟踪系统识别出的玩家。像素值表示身体 ID 乘以 25，以提高对比度。注意：玩家索引图可能有额外的硬件要求（支持 CUDA 的显卡），并且根据当前设置可能不会与彩色或深度图像同步。分辨率由当前 Depth Mode 决定。
  • Player Index aligned to Color playerindexremap - 重新映射以与当前彩色图像对齐的玩家索引图。分辨率由 Color Resolution 参数决定。
  • Point Cloud pointcloud - 32 位浮点 RGBA 图像，其中深度信息已转换为存储在 RGB 通道中的 XYZ 位置。位置数据以米为单位，分辨率与视场由 Depth Mode 决定。激活该 TOP 并在右键菜单中选择「View as Points」，或将该 TOP 用作 Geometry COMP 中的实例源，即可在 3D 中查看点云图像。
  • Point Cloud aligned to Color pointcloudremap - 重新映射以与当前彩色图像对齐的点云图像。注意：在 3D 中查看点时，重新映射可能造成缝隙与伪影。
Align Image to Other Camera remapimage - 启用后，当前图像将重新映射以与另一台摄像头的图像对齐。例如，用此功能创建与深度摄像头像素对应的彩色摄像头图像。

将使用当前深度模式与彩色分辨率进行重新映射。 注意：由于重新映射算法存在缝隙，重新映射点云图像可能会在点的分布中产生伪影。

Sync Image to Body Tracking bodyimage - 启用后，生成的图像将被延迟，以对应身体跟踪系统的最新数据。延迟量可能随执行身体跟踪的处理器性能与场景复杂度而波动。可以同时使用 Kinect Azure Select TOP 获取实时图像流。
Mirror Image mirrorimage - 沿水平轴翻转图像。
CPU Body Tracking cpu - 启用后，身体跟踪计算将在 CPU 而非显卡上完成。此方法慢得多，但不需要高性能显卡即可运行。

参数 - Color 页

使用 Color 页上的控件调整彩色摄像头的输出。

Reset Color Controls resetcolors - 将所有颜色控件重置为摄像头的默认值。这些值因摄像头而异，可能与参数默认值不同。
Enable Color Controls enablecolors - 开启后可启用彩色摄像头的调节控件。禁用时，之前的颜色设置将保持不变。使用 Reset Color Controls 按钮可将摄像头恢复为默认设置。
Manual Exposure manualexposure - 启用以允许手动设置曝光时间。禁用时，摄像头将根据光照水平和帧率自动选择曝光。

注意：由于当前 Kinect SDK 的问题，此功能可能无法正常工作。

Exposure Time exposure - 调整彩色图像的曝光时间，单位为微秒。时间必须小于一帧。

注意：由于当前 Kinect SDK 的问题，此功能可能无法正常工作。

Manual White Balance manualwhitebalance - 启用以允许手动设置摄像头白平衡。
White Balance whitebalance - 选择用于设置图像白平衡的色温，单位为开尔文。该值会四舍五入到最接近的 10 度。
Brightness brightness - 用于调整图像亮度，范围 0 到 255。默认值为 128。
Contrast contrast - 控制彩色图像的对比度。
Saturation saturation - 控制彩色图像的饱和度。
Sharpness sharpness - 调整彩色图像的锐度。
Gain gain - 彩色图像的增益。
Backlight Compensation backlight - 启用对场景中强烈逆光的补偿。
Powerline Frequency powerfreq - 选择供电频率，用于摄像头的降噪系统。
  • 50Hz 50hz -
  • 60Hz 60hz -

  • Use Input useinput - 使用输入的分辨率
  • Eighth eighth - 将输入的分辨率乘以该数值。
  • Quarter quarter - 将输入的分辨率乘以该数值。
  • Half half - 将输入的分辨率乘以该数值。
  • 2X 2x - 将输入的分辨率乘以该数值。
  • 4X 4x - 将输入的分辨率乘以该数值。

Resolution resolution - - 仅当 Resolution 参数设为 Custom Resolution 时启用。某些生成器（如 Constant 和 Ramp）不使用输入，仅使用此字段确定其大小。右侧的下拉菜单提供一些常用分辨率。

Use Global Res Multiplier resmult - 使用 Edit>Preferences>TOPs 中的 Global Resolution Multiplier。这会将所有 TOP 的分辨率乘以设定的数值。在硬件规格不同的计算机上工作时这很方便。如果项目是在显存充足的工作站上设计的，而使用仅有 64MB VRAM 的笔记本电脑的用户可以将 Global Resolution Multiplier 设为一半或四分之一，以便以可接受的速度运行。勾选此复选框后，此 TOP 会受全局乘数影响。
Output Aspect outputaspect - - 设置图像宽高比，使任何纹理都能以任何尺寸查看。在合成宽高比不同的 TOP 时要注意意外结果。（可以使用 xres、yres、aspectx、aspecty 定义非方形像素的图像，其中 xres/yres != aspectx/aspecty。）
  • Use Input useinput - 使用输入的宽高比。
  • Resolution resolution - 使用图像所定义分辨率的宽高比（即 512x256 为 2:1），此时每个像素为方形。
  • Custom Aspect custom - 允许你在下面的 Aspect 参数中显式定义自定义宽高比。
Aspect aspect - - 在 Output Aspect 参数设为 Custom Aspect 时使用。
  • Aspect1 aspect1 -
  • Aspect2 aspect2 -
Aspect Menu armenu - 包含一些常用宽高比的下拉菜单。
Input Smoothness inputfiltertype - - 控制对 TOP 输入图像的像素过滤。
  • Nearest Pixel nearest - 使用最近像素或精确图像表示。在任何非 Native Resolution 的缩放级别查看时，图像会显得有锯齿。
  • Interpolate Pixels linear - 在像素之间使用线性过滤。这就是让查看器中的 TOP 图像在各种缩放级别下都好看的方式，在使用除 Native Resolution 以外的任何 Fill Viewer 设置时尤其有用。
  • Mipmap Pixels mipmap - 缩放图像时使用 mipmap 过滤。这可用于减少细节丰富的运动/缩放图像中的伪影和闪烁。
Fill Viewer fillmode - - 决定 TOP 图像在查看器中的显示方式。

注意： 要理解 TOP 如何处理图像，在刚开始放置 TOP 时，你会希望将此设为 Native Resolution。这样你可以看到实际发生的情况，而没有任何查看器自动缩放。

  • Use Input useinput - 使用与其输入相同的 Fill Viewer 设置。
  • Fill fill - 拉伸图像以适应查看器边缘。
  • Fit Horizontal width - 拉伸图像以在水平方向适应查看器。
  • Fit Vertical height - 拉伸图像以在垂直方向适应查看器。
  • Fit Best best - 拉伸或压扁图像，使图像的任何部分都不被裁剪。
  • Fit Outside outside - 拉伸或压扁图像，使图像在保持其比例的同时填满查看器。这通常会导致图像的一部分被查看器裁剪。
  • Native Resolution nativeres - 在查看器中以图像的原始分辨率显示。
Viewer Smoothness filtertype - - 控制查看器中的像素过滤。
  • Nearest Pixel nearest - 使用最近像素或精确图像表示。在任何非 Native Resolution 的缩放级别查看时，图像会显得有锯齿。
  • Interpolate Pixels linear - 在像素之间使用线性过滤。用于让查看器中的 TOP 图像在各种缩放级别下都好看，在使用除 Native Resolution 以外的任何 Fill Viewer 设置时尤其有用。
  • Mipmap Pixels mipmap - 缩放图像时使用 mipmap 过滤。这可减少细节丰富的图像在移动/缩放时的伪影和闪烁。当输入为 32 位浮点格式时，只使用 nearest 过滤（无论选择什么）。
Passes npasses - 将 TOP 的操作重复指定次数。第一次之后的每一遍都会取上一遍的结果，并用上一遍的结果替换该节点的第一个输入。例外情况是使用 compute shaders 时的 GLSL TOP，此时输入始终是所连接 TOP 的图像。
Channel Mask chanmask - 允许你选择 TOP 将作用于哪些通道（R、G、B 或 A）。默认选中所有通道。
Pixel Format format - - 用于存储图像中每个通道数据的格式（即 R、G、B 和 A）。更多信息请参阅 Pixel Formats。
  • Use Input useinput - 使用输入的像素格式。
  • 8-bit fixed (RGBA) rgba8fixed - 每个通道使用 8 位整数值。
  • sRGB 8-bit fixed (RGBA) srgba8fixed - 每个通道使用 8 位整数值，并以 sRGB 色彩空间存储颜色。注意这not对像素值应用 sRGB 曲线，而只是用 sRGB 曲线存储它们。这意味着较暗的值使用更多数据，较亮的值使用更少。下游读取这些值时会转换回线性。更多信息请参阅 sRGB。
  • 16-bit float (RGBA) rgba16float - 每个颜色通道使用 16 位，每像素 64 位。
  • 32-bit float (RGBA) rgba32float - 每个颜色通道使用 32 位，每像素 128 位。
  • 10-bit RGB, 2-bit Alpha, fixed (RGBA) rgb10a2fixed - 每个颜色通道使用 10 位，alpha 使用 2 位，每像素共 32 位。
  • 16-bit fixed (RGBA) rgba16fixed - 每个颜色通道使用 16 位，每像素共 64 位。
  • 11-bit float (RGB), Positive Values Only rgba11float - 一种 RGB 浮点格式，Red 和 Green 通道有 11 位，Blue 通道有 10 位，每像素共 32 位（因此内存占用与 8 位 RGBA 相同）。此格式中的 Alpha 通道始终为 1。值可以大于 1，但不能为负。即范围为 [0, infinite)。
  • 16-bit float (RGB) rgb16float -

  • 16-bit fixed (Mono) mono16fixed - 单通道，RGB 都具有相同的值，Alpha 为 1.0。每像素 16 位。
  • 16-bit float (Mono) mono16float - 单通道，RGB 都具有相同的值，Alpha 为 1.0。每像素 16 位。

Info CHOP 通道

可通过 Info CHOP 访问 Kinect Azure TOP 的额外信息。

Kinect Azure TOP 专属信息通道

  • image_frame - 摄像头已处理的图像帧数。
  • bodytracking_frame - 摄像头已处理的身体跟踪帧数。
  • color_timestamp - 彩色摄像头最新一帧的摄像头时间戳，单位为微秒。
  • depth_timestamp - 深度摄像头最新一帧的摄像头时间戳，单位为微秒。
  • bodytracking_timestamp - 用于计算身体跟踪数据的帧的时间戳，单位为微秒。
  • image_errors - 图像系统产生的错误总数。
  • bodytracking_errors - 身体跟踪系统产生的错误总数。

TOP 通用信息通道

  • resx - TOP 的水平分辨率，以像素为单位。
  • resy - TOP 的垂直分辨率，以像素为单位。
  • aspectx - TOP 的水平宽高比。
  • aspecty - TOP 的垂直宽高比。
  • depth - 如果此 TOP 包含 2D 或 3D 纹理数组，则为该 2D 或 3D 数组的深度。
  • gpu_memory_used - 此 TOP 使用的纹理内存总量。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
