Video Stream Out TOP

摘要

注意

Hardware: 此 TOP 使用 Nvidia 硬件编码器创建流，因此需要 Nvidia GPU 和 Windows 才能运行。

Video Stream Out TOP 可作为 RTMP 或 SRT 发送端，可创建 RTSP 服务器，通过网络发送压缩的视频和音频。它使用 Nvidia 的硬件编码器。对于 RTSP，它可以同时处理多个客户端连接。多个使用同一端口的 Video Stream Out TOP 将由同一个底层 RTSP 服务器处理。Video Stream Out TOP 还可用于通过 WebRTC 视频/音频轨道发送视频流。

可输出的视频编解码器为 H.264、H.265（HEVC）和 AV1。（AV1 仅受较新的 NVIDIA GPU 支持。）。并非每种流协议和/或服务都支持每个编解码器选项。

可输出的音频编解码器为 MP3、AAC 和 Opus。

RTMP

也支持 Enhanced RTMP。

要获得用于推流的 RTMP URL，你可能需要根据所在位置和所用服务搜索正确的 URL。其格式应为：

{service url}/{stream key}.

例如对于 Twitch，URL 大致如下

rtmp://live-yto.twitch.tv/app/live_1234567_sduhy3xJ1KJ34Eg6CjksdJLubFS7gtUY

有关不同服务的更多信息，请参阅 RTMP。

SRT

SRT 可使用 H.264 或 H.265 视频编解码器。当在 Per-Frame Metadata 参数中指定 CHOP 或 DAT 时，它还可以发送逐帧元数据。

SRT 服务器的设置由 URL 选项控制。例如，要以监听模式创建 Video Stream Out，需指定 URL：

srt://0.0.0.0:9494?mode=listener

要在 Video Stream In TOP 中连接到监听端，可这样做：

srt://127.0.0.1:9494?mode=caller

连接的任一端都可以作为监听端或呼叫端，哪一端发视频、哪一端收视频都无关紧要。接收端应把模式设为与发送端相反。

所有可用选项列于 here。多个选项可用 & 作为分隔符设置。例如

srt://127.0.0.1:9494?mode=caller&send_buffer_size=100000

从 Video Stream Out TOP 发送的 SRT 可包含逐帧元数据，便于与视频同步收发 CHOP/DAT 数据。可用 Video Stream In TOP 读取。

RTSP

可通过 Info DAT 或中键单击该节点，获取用于连接 Video Steam Out TOP 的 RTSP 服务器的 URL。其格式为：

rtsp://<ipaddress>:<port>/<streamName>

e.g.

rtsp://192.168.0.1:554/tdvidstream

限制

RTSP 流不支持通过 RTP 直接发送到另一个 RTSP 服务器。

NVIDIA Geforce 级别的卡每系统最多只有 8 个编码会话。降低分辨率并不能避开编码会话限制。Quadros/RTX Pro 卡没有会话限制。无论哪种情况，可编码的像素总量都取决于底层硬件，较新/较强的卡能编码更多像素。更多信息请参阅 Nvidia Video GPU Support Matrix。

在 M6000 上使用默认 TouchDesigner 启动文件进行的一次测试中，可以运行 13 个 1080p@30hz 的 Video Stream Out TOP。

另请参阅 Video Stream In TOP、RTMP、RTSP 以及 Video Streaming User Guide、Movie File Out TOP。

有关 IP 上的其他协议，请参阅 NDI (Network Data Interface) 以及 Touch Out TOP / Touch In TOP。

NOTE for Windows OS - If experiencing connection issues make sure Windows Firewall is disabled.
