TDPyEnvManagerHelper

用于管理 TouchDesigner 的 Python 和 Conda 环境安装与设置的类。

此类不需要 TouchDesigner 运行，可作为独立的 Python 脚本使用。

它在 TouchDesigner 中作为模块、在 TDPyEnvManager 的上下文中被导入，用作 TDPyEnvManager 内的辅助类。

它提供下载和安装 Miniconda、创建 Conda 环境以及管理 Python 虚拟环境的方法。还包括日志记录、下载文件、创建 .gitignore 文件、创建 .condarc 文件、验证安装等方法以及其他工具和实用程序。

该文件位于你的 TouchDesigner 安装文件夹中，%TD_INSTALL_PATH%\\bin\\Lib\\tdutils\\TDPyEnvManagerHelper.py，其中 %TD_INSTALL_PATH% 是 TouchDesigner 根安装文件夹的路径。（在 MacOS 上为 $YOUR_TOUCHDESIGNER_INSTALL_PATH/Contents/Frameworks/Python.framework/Versions/$TD_PYENVMANAGER_PYTHONVERSION/lib/python$TD_PYENVMANAGER_PYTHONVERSION/site-packages/tdutils/TDPyEnvManagerHelper.py，其中 $YOUR_TOUCHDESIGNER_INSTALL_PATH 是 TouchDesigner.app 的路径，$TD_PYENVMANAGER_PYTHONVERSION 是当前 TouchDesigner 版本的 Python 版本，例如 3.11。）

TDPyEnvManagerHelper 在 TouchDesigner 启动时初始化。如果找到 TDPyEnvManagerContext.yaml 文件，且 context 文件中注册的环境有效，那么该环境会在任何 TouchDesigner COMP 计算和自定义扩展初始化之前被加入 Python 搜索路径。旧版 TDPyEnvManagerContext.json 文件会自动转换为 YAML，除非 pyproject.toml 已包含 [tool.touchdesigner.TDPyEnvManagerContext]。自 TouchDesigner 版本 2025.32280 起，context 数据也可以存储在该 pyproject.toml 段中，之后它将成为读写时首选的 context 存储位置。

它作为 TDPyEnvManager 的 Helper 属性暴露，或暴露在 app.pyEnvHelper 上。

调试时，使用环境变量 TOUCH_APP_LOG_LEVEL 并把日志级别设置为低于 WARNING 会很有用（INFO、DEBUG...）。（log level table for reference）

把 TDPyEnvManagerHelper 作为 CLI 使用

TDPyEnvManagerHelper 可作为独立的 CLI 工具使用。下面是使用指南，包括可传入的参数、示例值及其作用。

从命令行运行脚本： python TDPyEnvManagerHelper.py [OPTIONS]

其中 python 是指向 TouchDesigner 自带 Python 的别名：

  • 在 Windows 上为 YOUR_TOUCHDESIGNER_INSTALL_PATH\bin\python.exe
  • 在 MacOS 上为 YOUR_TOUCHDESIGNER_INSTALL_PATH/Contents/Frameworks/Python.framework/bin/python3.11
说明文字
Argument Description Example Value Default Value
--mode Specifies the mode of environment setup. Can be Conda Env or Python vEnv. --mode "Conda Env" Python vEnv
--installPath The path where Miniconda or Python virtual environment should be created. --installPath "C:\Envs" Current working directory
--envName The name of the Conda or Python virtual environment to be created. --envName "MyEnv" TDPyEnv
--pythonVersion The version of Python to be installed in the environment. --pythonVersion "3.11" Current Python version
--useReqs Python vEnv mode only. Install requirements after creating or validating the vEnv. --useReqs False
--requirementsFiles Python vEnv mode only. Optional list of requirements files to use with --useReqs. --requirementsFiles base.txt dev.txt requirements.txt
--useEnvYml Conda mode only. Create the environment from environment.yml when present. --useEnvYml False
--clean Cleans the install directory before installing. --clean False
--keepInstaller Keeps the installer after installation or if installation fails. --keepInstaller False

参数详情

--mode

描述：决定创建 Conda 环境（Conda Env）还是 Python 虚拟环境（Python vEnv）。

示例：python TDPyEnvManagerHelper.py --mode "Conda Env"

默认：Python vEnv

--installPath

描述：指定安装环境的目录。

示例：python TDPyEnvManagerHelper.py --installPath "C:\MyEnvironments"

默认：当前工作目录。

--envName

描述：要创建的环境的名称。

示例：python TDPyEnvManagerHelper.py --envName "MyCustomEnv"

默认：TDPyEnv

--pythonVersion

描述：指定要安装到环境中的 Python 版本。它应始终与 TouchDesigner 自带的 Python 版本一致。

示例：python TDPyEnvManagerHelper.py --pythonVersion "3.11"

默认：系统的当前 Python 版本。

--useReqs

描述：在 Python vEnv 模式下，在 vEnv 创建之后或复用已有 vEnv 时显式安装 requirements。

示例：python TDPyEnvManagerHelper.py --mode "Python vEnv" --useReqs

默认：False

--requirementsFiles

描述：在 Python vEnv 模式下，传入 --useReqs 时提供要安装的一个或多个自定义 requirements 文件。如果省略，辅助程序会回退到当前工作目录中的 requirements.txt。

示例：python TDPyEnvManagerHelper.py --mode "Python vEnv" --useReqs --requirementsFiles requirements/base.txt requirements/dev.txt

默认：requirements.txt

--useEnvYml

描述：在 Conda 模式下，从 environment.yml 创建环境，而不是先创建空环境再手动添加包。

示例：python TDPyEnvManagerHelper.py --mode "Conda Env" --useEnvYml

默认：False

--clean

描述：如果指定，安装前会先清理安装目录。 示例：python TDPyEnvManagerHelper.py --clean 默认：False

--keepInstaller

描述：如果指定，安装后不会删除安装程序。

示例：python TDPyEnvManagerHelper.py --keepInstaller

默认：False

示例

1. 创建 Python 虚拟环境

python TDPyEnvManagerHelper.py --mode "Python vEnv" --installPath "C:\Envs" --envName "MyPythonEnv" --pythonVersion "3.11"

在 C:\Envs 目录下创建一个名为 MyPythonEnv 的 Python 虚拟环境，Python 版本为 3.11。

2. 创建 Conda 环境

python TDPyEnvManagerHelper.py --mode "Conda Env" --installPath "C:\Conda" --envName "MyCondaEnv" --pythonVersion "3.11" --clean

在 C:\Conda 目录下创建一个名为 MyCondaEnv 的 Conda 环境，Python 版本为 3.11。安装前会清理 C:\Conda 目录。

3. 安装后保留安装程序

python TDPyEnvManagerHelper.py --mode "Conda Env" --keepInstaller

创建一个 Conda 环境，并在安装后保留安装程序文件。

4. 创建或复用 Python vEnv 并安装多个 requirements 文件

python TDPyEnvManagerHelper.py --mode "Python vEnv" --installPath "C:\Envs" --envName "MyPythonEnv" --useReqs --requirementsFiles requirements\base.txt requirements\gpu.txt

按需创建 vEnv，然后按顺序安装所列 requirements 文件中的包。

5. 从 environment.yml 创建 Conda 环境

python TDPyEnvManagerHelper.py --mode "Conda Env" --installPath "C:\Conda" --useEnvYml

使用当前文件夹的 environment.yml 创建 Conda 环境。

说明

  • 脚本不再提示确认 clean 或 keepInstaller。这些行为通过 CLI 标记显式控制。
  • 确保 installPath 目录可写，并有足够空间进行安装。
  • 对于 Conda 环境，如果尚未安装 Miniconda，脚本会自动下载并安装它。
  • 在 Python vEnv 模式下，如果解析出的 Python 可执行文件实际上不在有效的 vEnv 内，requirements 安装会被拒绝。这可防止误装到 TouchDesigner 或系统解释器中。
  • 本指南应能帮助你开始把 TDPyEnvManagerHelper 作为 CLI 工具使用。

CLI 用法示例见 Samples/TDPyEnvManager 文件夹。你会找到脚本以及 .sh 和 .bat 文件，可用参数运行脚本以创建 Conda 或 Python 虚拟环境。

成员

mode → str or None :

用于安装环境的模式。可以是 `Conda Env` 或 `Python vEnv`。默认为 None。

envName → str or None :

为 Python vEnv 或 Conda Env 创建的环境名称。默认为 None。

installPath → pathlib.Path or None :

Miniconda 安装或 Python 虚拟环境的路径。默认为 None。

pythonVersion → str :

要安装的 Python 版本。仅对 Miniconda 环境有用。Python vEnv 使用 TouchDesigner 自带的 Python 解释器创建，版本与之匹配。

logger → logging.Logger or None :

辅助程序使用的 Python logger 实例。

taskQueue → queue.Queue :

用于在工作线程中运行任务的队列。

errorQueue → queue.Queue :

存储工作线程错误的队列。

onError → callable or None :

工作线程任务失败时调用的可选回调。

runningProcess → subprocess.Popen or None :

辅助程序中当前正在执行工作的子进程（如果有）。

envPath → pathlib.Path or None :

Conda 或 Python 虚拟环境的路径。

executablePath → pathlib.Path or None :

环境中 Python 可执行文件的路径。

osPath → list[str] :

由辅助程序管理的 PATH 条目列表。

sysPath → list[str] :

由辅助程序管理的 sys.path 条目列表。

extraPaths → list[str] :

在环境链接之后要添加到 sys.path 的额外路径。

loadedFromContext → bool :

表示是否已加载 context 文件的标记。

initLoadedFromContext → bool :

跟踪「首次从 context 加载」状态的标记。

Ready → bool :

表示环境已可使用状态的标记。

autoSetup → bool :

为 True 时，环境设置会根据 context 数据自动完成。

autoSetupReqs → list[str] :

自动设置期间要安装的 requirements 文件列表。

autoSetupSyncReqs → bool :

为 True 时，即使目标环境已存在，自动设置也会安装 requirements。

contextVersion → int :

写入 YAML 或 pyproject.toml context 数据的序列化 context 架构版本。

contextCreatedByVersion → str :

表示上一次写入 context 的 TDPyEnvManager 版本元数据。

thread → threading.Thread :

执行排队任务的工作线程。
