Point File In TOP

摘要

Point File In TOP 从单个文件或文件序列把 3D 点数据载入 TOP。点由一个或多个浮点值组成，例如 XYZ 位置、RGB 颜色值、3D 法线、扫描仪强度等。Point File In TOP 会载入所有可用的点数据，但输出图像中只能放入四个通道。默认情况下，前四个点数据通道分别放入红、绿、蓝和 alpha 通道；不过你可以在 Point Data 页上用参数把任意点通道指定给某个颜色通道。挂接一个 Point File Select TOP，就能从同一源文件创建额外的输出图像。

Point File In TOP 会从各种网格和浮点数据文件中读取点数据，包括：.obj、.ply、.fits（天文格式）和 .exr。它也能载入 ASCII 点文件（.xyz、.pts、.csv、.txt 等），每行一个点，字段以逗号或空格分隔。ASCII 点文件的第一行可以是点数、点字段名，或文件中的第一个点。

完整列表见 File Types。通常最好使用 OpenEXR 文件格式：它是二进制的，可以在多帧文件序列中读取并使用 TouchDesigner 的影片文件预读与缓冲，而且可以由 TouchDesigner 的 Movie File Out TOP 写出，通道数不限。

挂接一个 Info CHOP，即可检查 Point File In TOP 的状态。它会显示点数、每点字段数和帧数等信息，也会显示文件打开状态、当前帧、预读帧数和队列大小、丢帧数、CPU 解码时间和 GPU 上传时间等动态信息。

Headers：如果文件包含任何额外的头部数据，可以通过挂接 Info DAT 查看。头部数据以键值对存储，键在第一列，对应的数据在第二列，用 Python 很容易解析。

所有 ASCII 点列表格式的载入方式都相同，无论扩展名是 txt、csv、xyz 等。解析器会寻找第一个分隔字符（逗号、空格或制表符），并用它来分隔文件其余部分。单引号或双引号内的分隔符会被忽略。根据分隔符风格还有几条特殊规则，例如连续多个空格会合并为一个，但行尾的逗号表示后面有一个空字段。分隔符确定后，第一行可以是点数，但会被忽略。如果下一行是字符串，就被当作一行表头（通道名）。之后每行被视为一个点。

另请参阅 OpenEXR。

参数 - Point Data 页

控制点的字段数据如何放入输出图像。

custom 开关控制是否使用自定义字段名，来选择哪个字段放入对应的颜色通道。若为 false，则按顺序选取字段，例如第一个字段进红色，第二个进绿色，依此类推。

设为 custom 时，你可以从下拉菜单选择字段，或直接输入。如果输出图像格式没有该颜色通道（见 Pixel Format 参数），此参数会被禁用。

File file - 要载入的点文件的路径和名称。点文件格式见 File Types。你可以用 http:// 指定互联网上的文件……

要把一个文件夹里的文件当作动画，请指定该文件夹而不是文件名。所有文件的分辨率必须相同。文件夹中每个文件会被当作动画中的一帧。文件顺序按字母数字排序。默认第一个文件索引为 0，第二个为 1，以此类推，与文件名无关。在 Trim 参数页上覆盖采样率，就能以任意帧率播放该动画。

在包含一系列文件的目录中放一个 info.xml 文件，就可以指定每秒帧数。示例 xml 文件： 

<?xml version="1.0" encoding="ISO-8859-1" standalone="yes" ?>
  <Settings>
      <attributes fps="30.0" />
  </Settings>

可以用 URL 来获取文件。文件会下载到用户的 Derivative 临时目录，然后被读入 Point File In TOP。

参数 - Play 页

Play Mode playmode - - 指定播放动画所用的方式，共有 3 个选项。
  • Locked to Timeline locked - 此模式把动画锁定到时间轴。在时间轴上拖动或跳转，会相应改变动画位置。此模式下 Play、Reset、Speed 和 Index 参数被禁用，因为位置直接由时间轴决定。
  • Specify Index specify - 此模式允许用户用下面的 Index 参数指定动画中的特定位置。需要随机访问影片中任意位置时使用此模式。
  • Sequential sequential - 此模式持续播放，与时间轴位置无关（Index 参数被禁用）。下方的 Reset 和 Speed 参数被启用，可提供一定控制。
Play play - 为 1 时播放动画，为 0 时停止。
Speed speed - 这是一个速度倍率，仅在 Play Mode 为 Sequential 时生效。值为 1 是默认播放速度。值为 2 是双倍速，0.5 是半速，以此类推。负值会使动画倒放。
Cue cue - 设为 1 时跳转到 Cue Point。仅在 Play Mode 为 Sequential 时可用。
Cue Pulse cuepulse - 立即跳转到影片中的 Cue Point 位置。
Cue Point cuepoint - 将动画中的任意索引设为要跳转到的点。
Cue Point Unit cuepointunit - - 从此参数的单位中选择 Index、Frames、Seconds 和 Fraction（百分比）。
  • I indices -
  • F frames -
  • S seconds -

Cue Behavior cuebehavior - - 自定义 Cue 参数的行为。
  • On Release, Repeat Cued Frame repeat - 释放 Cue 参数时，立即播放下一帧。
  • On Release, Play Next Frame play - 释放 Cue 参数时，先播放被 cue 的那一帧，再继续播放下一帧。
Index index - 当 Play Mode 设为 Specify Index 时，此参数显式设置文件序列的位置。右侧的单位菜单让你用以下单位指定索引：Index、Frames、Seconds 和 Fraction（百分比）。例如，假设一个序列内部是 25 fps，而时间轴是 60 fps。若把 Units 设为 Index、参数值设为 25，你得到的是序列中第 1 秒的图像。若把 Units 设为 Frames、值设为 60，你得到的也是影片中第 1 秒处的同一幅图像。

参数 - Tune 页

Pre-Read Frames prereadframes - 设置 TouchDesigner 预读并保存在内存中的动画帧数。Point File In TOP 会在使用之前读取动画帧并解码到 CPU 内存，这能消除因某些帧解码过久、其他资源访问硬盘或循环造成的播放爆音与卡顿。读取文件序列时，Pre-Read Frames 越多，就能同时解码多个文件。这样只要机器有足够的 CPU 核心，就能实时播放 .exr 这类重型文件格式。
Frame Read Timeout frametimeout - TouchDesigner 从硬盘等待一帧的时间（毫秒），超时则放弃。达到 Disk Read Timeout 时间后，该帧会被直接跳过。这也适用于通过 http:// 下载的网络文件。
Frame Timeout Strategy frametimeoutstrat - - 开启时，如果达到 Disk Read Timeout，TouchDesigner 会用最新的可用帧代替被跳过的帧。
  • Keep Frame keep - 持续显示当前正在输出的同一帧。
  • Best for Playback playback - 尝试挑选最适合播放的帧。这可能比当前显示的帧更新，但不完全是所请求的那一帧。
  • Best for Seeking seeking - 尝试显示任意一帧，无论是目标帧之前还是之后。适合在 UI 中通过 shuttle 控件拖动影片时使用。
Always Load Initial Frame alwaysloadinitial - 如果开启此参数，则对第一个加载的帧会忽略 Frame Read Timeout，始终等待第一帧，以确保节点总是以有效图像启动。
File Open Timeout opentimeout - TouchDesigner 等待文件打开的时间（毫秒）。如果达到 Disk Open Timout，Point File In TOP 会停止等待，把图像变为全黑，并在右下角显示一个灰色方块。如果下次该 TOP 计算时文件仍未打开，它会再等一次，同样处理。如此反复，直到文件打开或打开失败。
Async Upload to GPU asyncupload - 启用后，会使用 OpenGL 功能把影片图像异步上传到 GPU。这会大幅降低 Movie File In TOP 的计算时间（在 performance monitor 中，「Uploading Image to GPU」那些行会降到几乎为零）。不过使用此功能要付出 GPU 内存代价：它额外占用 (Width * Height * 4 * Read Ahead Size) 字节的 GPU 内存。如果此功能效果不佳，请确保你的显卡驱动是最新的。
Update Image updateimage - 设为 0 时图像不更新。动画索引会继续前进，但输出图像不会更新。
Max Decode CPUs maxdecodecpus - 限制用于解码某些支持多 CPU 解码的文件编解码器的最大 CPU 数量。
High Performance Read highperfread - 播放需要很高 SSD 读取速度的文件时应使用此选项。在这些情况下它能大幅提升读取性能。低分辨率或低数据率的文件不应使用它。
High Performance Read Factor highperfreadfactor - 进行高性能读取时，此参数控制磁盘上读取操作的大小。无论编解码器请求的最大操作是多少，都会乘以 read factor，之后所有读取都会读取这么多数据。根据硬盘不同，这可以提高吞吐量。例如某次请求读取 1MB，而系数设为 3，那么实际操作会从磁盘读取 3MB，多读的 2MB 会为下一帧做好准备，很可能接下来 2 帧已经存在于 CPU 内存中。
Hardware Decode hwdecode - 控制此节点是否通过 Nvidia 硬件解码芯片使用硬件解码。你可以用 Info CHOP 的 'hardware_decode' 通道检查是否正在使用硬件解码。此参数对 Hap 和 NotchLC 编解码器无效，它们始终使用硬件解码。

TOP 通用信息通道

  • resx - TOP 的水平分辨率，以像素为单位。
  • resy - TOP 的垂直分辨率，以像素为单位。
  • aspectx - TOP 的水平宽高比。
  • aspecty - TOP 的垂直宽高比。
  • depth - 如果此 TOP 包含 2D 或 3D 纹理数组，则为该 2D 或 3D 数组的深度。
  • gpu_memory_used - 此 TOP 使用的纹理内存总量。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
