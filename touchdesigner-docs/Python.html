TouchDesigner 中可用的 Python 类与模块

TouchDesigner 包含 standard Python installation 中的所有模块，另外还包括以下内容：

td：TouchDesigner 的主 Python 模块

All td module members and methods are available in scripts, expressions, and the textport. 无需显式导入该模块或其成员。这在表达式中尤为重要，因为表达式不允许 import 语句。

在 td 模块中可以找到以下内容：

  • Main TouchDesigner utilities - 与 TouchDesigner 交互最基础的起点，例如 me 和 op()。
  • TouchDesigner Python helper classes - 重要的辅助对象，用于组织与 TouchDesigner 特定部分相关的函数和信息。
  • Operator related classes - TouchDesigner 中的每个 Operator 在 td 模块中都有一个关联的 Python 类。点击其 parameter dialog 中的 Python Help 按钮即可访问它们的 wiki 页面。此外还有许多相关的 Python 对象，在处理操作符时会用到。
  • Useful standard Python modules - td 模块还会自动导入若干有用的标准模块（例如 math），使它们可以在表达式中通过其命名空间访问。

安装自定义 Python 包

Python 的强大之处部分在于可以访问无数已创建的模块。如果你想使用上述内容之外的模块，请按以下步骤操作：

注意：当你为 TouchDesigner 已自带的某个包添加自己的版本时，可能会遇到意外行为。 我们的许多内部工具和调色板组件依赖 NumPy 和/或 OpenCV。Loading different versions of Numpy and/or OpenCV is at your own risk. 另一个可能的问题如下：假设包 A 依赖包 B，如果更新 sys.path 导致 B 的另一个版本先被加载，可能会给包 A 带来问题。

Windows

  1. 在硬盘上安装一份相同 Python 版本的并行副本。TouchDesigner 当前自带的 Python 版本为 3.11。可以在 here 找到它。请使用 3.11 的最新子版本。
    1. 或者，你可以使用 Python 包与环境管理器 such as Anaconda。
  2. 按照其常规安装流程，将该包安装到并行的 python 安装中。
  3. 启动 Python 并手动导入该模块，以确保在 TouchDesigner 环境之外没有错误。

模块安装成功后，即可按以下步骤在 TouchDesigner 中导入它：

在 Edit → Preferences 菜单下，勾选「Add External Python to Search Path」。你可以通过修改名为「Python 32/64 bit Module Path」的偏好设置来添加搜索路径。多个路径用分号分隔（;）。

最后，你可以直接修改搜索路径：修改系统环境变量 PYTHONPATH，或用下面的代码片段修改 firing an Execute DAT onStart()。 

import sys
mypath = "C:/Python311/Lib/site-packages" # 请使用安装的正确路径，有时位于用户文件夹中
if mypath not in sys.path:
	sys.path = [mypath] + sys.path

此脚本会把自定义 Python 安装的 site-packages 文件夹前置到你的 PATH 中。前置可确保在导入自定义包时，它will have priority over any other package with a matching package name found 在路径中。如果在自定义路径中找不到该包，但在 TouchDesigner Python 的 site-packages 文件夹中找到了同名包，则it will fall back on this package。

用户也可以从并非使用官方 Python 安装程序、而是使用替代 Python 包与环境管理器 such as Anaconda 安装的 Python 环境中导入包。

MacOS

在 MacOS 上，请使用 Homebrew 管理你的 Python 安装。按照 Homebrew 网站上的说明开始。

安装 Homebrew 后，可以使用命令 brew install python@3.11 在系统上安装 Python。python 之后的 @3.11 用于设置版本，该版本必须与 TouchDesigner 的版本相同。

Intel Mac

在 Intel Mac 上，默认的 Homebrew 路径应为 /usr/local/bin/brew

ARM Mac

在 ARM Mac 上，Homebrew 路径应为 /opt/homebrew/bin/brew、for the native ARM homebrew。也就是说，使用默认的 Homebrew 安装命令时。

注意： 某些情况下，你可能需要运行 Homebrew Rosetta。如果你使用的是非原生 / Intel 版 TouchDesigner，并且需要 MacOS 上不提供 ARM 安装程序的 Python 版本，则必须这样做。

要安装 Homebrew Rosetta，请使用以下命令：arch -x86_64 /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/master/install.sh)"。 你的 Homebrew Rosetta 路径应为 /usr/local/bin/brew。

如果系统上安装了两个 Homebrew 版本，建议为 Homebrew Rosetta 安装添加一个别名。 在终端中使用以下命令 alias ibrew="arch -x86_64 /usr/local/bin/brew"，其中 ibrew 代表 Intel Brew。 你可以将此别名添加到终端配置文件中，使其持久生效。

现在你可以分别使用 brew install YOUR_APP_NAME 或 ibrew install YOUR_APP_NAME 来安装 ARM 或 Intel 的 formula 或 cask。

继续你的 python 安装，使其与 TouchDesigner 的 Python 匹配，如本 MacOS 节顶部所述。记住，如果你按前面的步骤操作：使用 ARM 原生版 TouchDesigner 时用 brew，若是通过 Rosetta 运行的 Intel 版，则用 ibrew。

添加额外的别名也很有用，当它们与 Intel / Rosetta 相关时，可以在前面加上 i，用于 Python 本身和 pip： 

alias iPY311=/usr/local/opt/python@3.11/bin/python3
alias iPIP311=/usr/local/opt/python@3.11/bin/pip3

现在你只需使用 iPIP311 install YOUR_PACKAGE_NAME 安装自定义的（Intel）Python 3.11 包即可。

模块安装成功后，即可按以下步骤在 TouchDesigner 中导入它：

在 Edit → Preferences 菜单下，勾选「Add External Python to Search Path」。你可以通过修改名为「Python 32/64 bit Module Path」的偏好设置来添加搜索路径。多个路径用分号分隔（;）。你可以输入 Python 包所在的路径（通常为 <python install>/Lib/site-packages）

如果偏好设置方法对你无效，还有其他几种方法：你可以直接修改 Python 搜索路径，即修改 system environment variable PYTHONPATH，或用下面的代码片段修改 setting up an Execute DAT onStart()。 

import sys
mypath = "/usr/local/lib/python3.11/site-packages" # 提示：用 Homebrew 安装该 Python 版本时，此路径会打印在终端中
if mypath not in sys.path:
	sys.path = [mypath] + sys.path

此脚本会把自定义 Python 安装的 site-packages 文件夹前置到你的 PATH 中。前置可确保在导入自定义包时，它will have priority over any other package with a matching package name found 在路径中。如果在自定义路径中找不到该包，但在 TouchDesigner Python 的 site-packages 文件夹中找到了同名包，则it will fall back on this package。

Python 陷阱

标准 Python 中有一些地方在 TouchDesigner 里可能会让你栽跟头。如果你发现了此处未包含的内容，请在论坛发帖！

  • 某些 TouchDesigner 对象（尤其是参数和 CHOP 通道）会尝试表现得像其上下文所需的数据类型。例如，Float 参数对象（myOp.par.Float1）会像浮点数一样运作 in most cases，但它仍然是参数对象。例如 round(myOp.par.Float1) 将无法工作。要获取参数或通道的实际值，请使用其 .eval() 方法。如果你认为自己可能遇到此问题，可以用 repr 函数来区分。例如 repr(myOp.par.Float1) 会显示这是一个参数而不是数字。
  • 操作符参数类型也是如此。如果参数是指向 CHOP 的路径，n.par.Chop 通常可行，但为了稳妥，n.par.Chop.eval() 总是可行。
  • subprocess.Popen 不能用于类文件对象。详情请参阅 this forum post。
  • Python 线程无法访问 TouchDesigner 对象。在论坛中搜索「threading」可找到一些变通方法。自 TouchDesigner 2023.31500+ 起，请参阅 Python threading in TouchDesigner 和 Thread Manager。
