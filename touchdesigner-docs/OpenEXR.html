OpenEXR

OpenEXR 是一种高动态范围光栅文件格式，作为开放标准发布，并附带一套由 Industrial Light & Magic（ILM）创建的软件工具，采用类似 BSD 许可证的自由软件许可证。

该格式的完整技术介绍可在 openexr.org 上找到。当前支持的版本是 OpenEXR 2.3。

EXR 格式的优势在于支持高达 32 位浮点数据（参见 TOP 的 Common 参数页上的 Pixel Format 参数），以及能够存储任意数量的通道。

EXR 文件可以通过 Movie File In TOP 载入 TouchDesigner，它把前 4 个通道读取为 RGBA；也可以通过 Point File In TOP 载入，它可读取具有任意数量通道的 EXR 文件，并提供自定义通道映射选项。

EXR 图像可以从 TouchDesigner 中保存出来，方式有：(1) TOP 上的 Save Image... 菜单，(2) TOP 上的 .save() Python 方法，以及 (3) Type 为 "Image" 或 "Image Sequence" 的 Movie File Out TOP。

改善 EXR 序列的播放

EXR 序列对 SSD 读取速度和 CPU 解码时间的要求都很高。要流畅播放高分辨率 EXR 图像，你既需要快速的 SSD（最好是 NVMe M.2），也需要足够的 CPU 核心来同时解码多个 EXR。 多帧通过 'Pre-Read Frames' 参数同时解码。默认值 3 表示最多同时解码 3 帧。EXR 帧的解码可能耗时很长，因此你需要确保 Pre-Read Frames 足够大，让播放跟得上；此外还要确保在开始播放之前已预先读取了初始的一批帧。这可以通过 Movie File In TOP 中的 isFullyPreRead 成员来检查。

举例来说，每帧解码需要 200ms，而你要以 60FPS 播放该序列。由于新帧在开始解码 200ms 后才可用，因此至少需要有 200ms 的帧处于「预读」状态，这样当读取到最后一帧时，新的一帧已经就绪。这意味着此处 'Pre-Read Frames' 至少应为 6，并且你需要有 6 个 CPU 核心专门用于解码。不过留一些余量是好的，所以 7 或 8 可能是更好的选择。
