TDI 库

TDI 库仅在 2025.30000 及更高版本的 build 中可用

TouchDesigner 接口库

TDI Library 包含 TouchDesigner 弹出帮助和在 Microsoft Visual Studio Code (VS Code) 中代码补全所需的全部信息。它包含所有内置 TouchDesigner 对象、类和函数的 wiki 帮助与 Python 描述。除了帮助和自动补全，使用 TDI 库还能消除在 VS Code 中编辑 TouchDesigner Python 时出现的错误和警告提示。

注意，该库不包含 TouchDesigner 对象的实际代码，只包含足以提供编辑器帮助的 stub 信息。

未来的迭代会让 TDI 库支持其他编辑器。

设置 TDI

TDI 的设置很简单，使用随编辑器自动打包的 VS Code 扩展。

安装 VS Code

你需要安装 Microsoft Visual Studio Code。不需要其他特别的东西。

设置 TouchDesigner 以使用 VS Code

要把 TouchDesigner 设置为以 VS Code 作为标准文本编辑器：

  1. 从菜单中选择 Edit>Preferences。
  2. 转到 DATs 选项卡。
  3. 在 Text Editor 条目中，浏览并选择 VS Code。

在 VS Code 中启用 Python 扩展

如果以下扩展尚未启用，请在 VS Code 中启用它们：

  • Python
  • Pylance

TDI 设计为与这些标准 Python 扩展配合使用，它们已包含在标准 VS Code 安装中。有关在 VS Code 中安装/启用扩展的更多信息，请参阅 https://code.visualstudio.com/docs/editor/extension-marketplace。

把 VS Code 的 Python 解释器切换到 TouchDesigner

要启用 TDI，你只需告诉 VS Code 使用 TouchDesigner 安装目录中的 Python 可执行文件。为此，请按以下步骤操作：

  1. 打开 VS Code 命令面板（Win：ctrl-shift-P / macOS：cmd-shift-P）
  2. 输入或选择 "Python: Select Interpreter"
  3. 从菜单中选择 "Enter interpreter path..."
  4. 浏览到或直接输入 TouchDesigner 的 Python 可执行文件路径。
  • 在 PC 上通常是 <your TD install folder>/bin/Python.exe。
  • 在 Mac 上通常是类似 /Applications/TouchDesigner.app/Contents/Frameworks/Python.framework/Versions/Current/bin/python3.11 这样的路径
  • 不确定时，可以在 TouchDesigner 的 textport 中输入 app.pythonExecutable。它会返回可粘贴到 VS Code 的路径。

注意： 每次安装新的 TouchDesigner 版本时，你可能都需要重复此步骤。

测试 TDI 安装

至此安装完成。编辑器可能需要一分钟来加载所有 TouchDesigner 信息。要测试是否正常：

  1. 在 TouchDesigner 网络中拖入一个 Parameter Execute DAT。
  2. 在该 DAT 上选择 RMB>Edit Contents...。文件将在 VS Code 中打开。
  3. VS Code 顶部可能会有一条关于在受信任环境中工作的 Restricted Mode warning message。如果有，点击 "Manage" 然后点击 "Trust"。你也可以通过编辑器左下角的 "Resticted" 字样判断自己处于受限模式，点击它同样可以更改设置。处于受限模式时，TDI 库将无法正常工作。

使用 TDI

在使用以下功能前，请务必先通过上面的安装测试确认 TDI 库正常工作。

弹出帮助与自动补全

TDI 提供许多自动功能来帮助你工作。例如，在 VS Code 的 Python 文件中输入 containerC。你会看到 containerCOMP 的自动补全菜单弹出。如果你没有设置显示更多附加信息，可以把鼠标悬停在高亮的右端并按 > 箭头以显示额外的帮助信息。

输入 containerCOMP. 时，你会看到 Container Comp 所有可用成员的菜单。在开启额外帮助信息的情况下用方向键滚动，就能逐个浏览它们的帮助。

同样，输入 containerCOMP.par. 会显示 containerCOMP 所有内置参数的列表以及每个参数的帮助。

提供类型提示

虽然弹出帮助和自动补全会自动作用于 TouchDesigner 专有项（例如 me 或 debug()），但在很多情况下你仍需给编辑器提供更多信息。为此你会使用 Python type annotations，即 type hints。

基本思路是，你可以用 variable : type = 语法告诉 VS Code 该 TouchDesigner 对象是什么类型。之后在代码中使用该对象时，VS Code 就能提供相应的帮助。

例如，如果你有一个名为 "movie1" 的 Movie File In TOP，可以这样写： 

movie : moviefileinTOP = op('movie1')
movie.par.play = False

由于 VS Code 不知道 op('movie1') 返回的是什么类型的操作符，你必须在代码中加入类型提示，才能让编辑器的代码分析生效。这样当你把鼠标悬停在 movie、par 或 play 这些词上时，VS Code 就会弹出每个元素的信息。

类型提示的另一个常见用法是在 Python Extensions 中。如果你在为 Container Component 编写扩展，你很可能会在扩展的 __init__ 方法中使用它： 

self.ownerComp : containerCOMP = ownerComp

加上这一行后，每当你在扩展中访问 self.ownerComp，VS Code 都会知道它是 containerCOMP，并相应地提供自动补全和弹出帮助。

再举几个例子： 

# 带参数与返回值类型标注的函数定义
def exampleFunction(arg1 : clockCHOP, arg2 : Par) -> DAT
    # 这个没用的函数以 clockCHOP 和参数为参数，返回一个 DAT
    print(arg1, arg2)
    return me

# 由于 VS Code 不知道 "me" 是什么 OP 类型，你可以这样写：
me : parameterexecuteDAT = me

想快速学习 Python 注解，请参阅 here。

确定类型

如上述示例所示，要充分发挥 TDI 的作用，了解脚本中使用的是什么类型的 Python 对象很重要。对于操作符，要查看其 Python 类名，可以点击参数对话框顶部的 Python Help... 图标。这些就是使用 TDI 时最常需要的类名。对于其他 Python 对象，如果需要知道其类名，可以用 debug(<object>) 返回包含类名的字符串。

转到定义

VS Code 中有时很有用的另一个功能是 RMB>Go to Definition。在编辑器中对 TD Python 对象使用此功能时，会跳转到包含该对象全部信息的 TDI 库 stub 文件。在那里你可以看到该对象的所有成员和帮助字符串。如果你对此感兴趣，还能看到 TDI 库的一些内部实现。

当然，你可能想沿着定义一路深入下去，随时可以对刚打开的文件中的对象再次「转到定义」。

编辑器中的高级类型检查

以下技巧用于在编辑器中启用更严格的类型检查，例如 PyLance 的类型检查模式。由于 Python 并非严格类型检查，只有当你把编辑器设置为在类型不匹配时发出警告，这些功能才重要：

上图显示 PyLance 报错，因为 op() 返回的是 OP 类型的对象，它不一定能转换为 constantTOP 类型的对象。要解决这个问题，可以使用 OP.asType() 函数。 

a = op('constant1')
a = a.asType(constantTOP)

在上面的解决方案中，变量 a 会显示 constantTOP 的代码提示，PyLance 也不会报错。不能一行搞定的原因是：op() 可能返回 None，而 PyLance 会报 None 没有 asType 函数。若要用一行解决，请使用 opex，它在找不到操作符时会抛出异常而不是返回 None： 

a = opex('constant1').asType(constantTOP)

如果你希望 TouchDesigner 在你对相关操作符使用无效类型的 asType 时抛出异常，可以使用 checkType 参数： 

a = opex('someOperator').asType(constantTOP, checkType=True)

自定义组件与参数

目前 TDI 尚未设置为自定义组件和参数提供帮助。未来版本会包含此功能。

使用多个 TouchDesigner 版本

如果你使用多个 TouchDesigner 版本，并希望针对不同项目把 VS Code 的 Python 解释器指向不同版本，就需要设置 VS Code 工作区。有关操作方法，请参阅 https://code.visualstudio.com/docs/editor/workspaces。进入工作区后，VS Code 会记住你为该工作区设置的 Python 解释器。为该 TouchDesigner 项目编辑 Python 代码时，请务必先打开 VS Code 工作区。如果不先打开工作区，VS Code 只会使用你上次在非工作区状态下选择的 Python 解释器。

疑难解答

如果你在安装或其他方面遇到问题，尤其是以下任何问题，请在 forum 中发帖或发邮件至 support@derivative.ca。

缺少帮助

如果你发现某些 TouchDesigner 对象的帮助/自动补全不正确或不存在，请发送整个脚本文件以及问题对象列表。

其他编辑器

目前 TDI 库专为配合 VS Code 使用而设计。不过代码相当标准，全部位于 TouchDesigner 安装目录的 Lib/tdi 文件夹中。如果你使用其他编辑器并希望参与让 TDI 支持该编辑器，请发邮件！
