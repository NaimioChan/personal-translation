Bullet Solver COMP

摘要

在 Bullet Dynamics 系统中，Bullet Solver COMP 相当于 actor/body（即 Actor COMPs）所处的世界/模拟。Bullet Solver COMP 可包含任意数量的 actor/body（Actor COMP）或力（Force COMP/Impulse Force COMP），正如其名，它还会使用 Bullet Physics API 来逐步推进模拟。

Bullet Solver COMP 根据一些模拟参数（如 linear multiplier 或 angular multiplier）运行 Bullet 模拟，并在模拟推进时更新其中所含 Actor COMP 的变换。可以使用 COMP 上的参数暂停、减速、加速或重新开始模拟。

Bullet Solver COMP 的模拟在真空中运行，因此模拟中的任何 actor 都不会受到空气阻力。模拟以给定的采样率步进，并相应更新 Actor COMP 的变换。这些变换与 Bullet Solver CHOP 中显示的结果相同。

Bullet Solver COMP 所引用的 Actor COMP 不必位于其网络内部。它们可以位于任何位置，只要尚未被另一个 Bullet Solver COMP 引用。

另请参阅：Bullet Dynamics、Actor COMP、Force COMP、Impulse Force COMP、Constraint COMP、Bullet Solver CHOP。

参数 - Solver 页

Actors actors - 要包含在模拟中的 Actor COMP。这些 actor 不能已经是另一个 Bullet Solver COMP 的一部分。
Global Forces forces - 要包含在模拟中的 Force COMP。这些力是全局力，会作用于模拟中所有非静态 actor。
Gravitational Acceleration gravity - - 作用于模拟中所有 actor 的重力，单位为 m/s^2。重力作用于 actor 时与其质量无关。
  • X gravityx -
  • Y gravityy -
  • Z gravityz -
Dimension dimension - - 模拟的维度。此菜单中的选项也可以用 linear/angular multiplier 参数重建。
  • 1D 1d - Actor 仅被约束为沿 X 轴的线速度，没有角速度（linmult 1,0,0，angmult 0,0,0）
  • 2D 2d - Actor 仅被约束为 XY 平面上的线速度，角速度仅绕 Z 轴（linmult 1,1,0，angmult 0,0,1）
  • 3D 3d - Actor 不受约束，可沿 X、Y 或 Z 任意方向移动。同样，Actor 也可以绕 X、Y 或 Z 任意方向旋转（linmult 1,1,1，angmult 1,1,1）
Linear Multiplier linmult - - 模拟中 actor 线速度的乘数。例如，如果 linmult 为 (0, 1, 1)，则 actor 可以在 Y 和 Z 轴上以正常速度线性移动，但不能沿 X 方向移动。这些值会在内部与 dimension 的值相乘。例如，如果 dimension 为 2D 且 linmult 为 (0, 1, 1)，则 actor 唯一能移动的方向是 Y 轴，因为 2D 在 Z 上施加约束，而此参数在 Y 上施加约束。
  • X linmultx -
  • Y linmulty -
  • Z linmultz -
Angular Multiplier angmult - - 模拟中 actor 角速度的乘数。例如，如果 angmult 为 (1, 0, 0)，则 actor 只能绕 X 轴旋转。这些值会在内部与 dimension 的值相乘。因此，如果 dimension 为 2D 且 angmult 为 (1, 0, 0)，则 actor 将无法向任何方向旋转，因为 2D 只允许绕 Z 轴旋转，而此参数又只允许绕 X 轴旋转。
  • X angmultx -
  • Y angmulty -
  • Z angmultz -
Initialize Sim and Collision Shapes initall - 将所有 body 重置为初始状态（即位置、朝向、速度），并重建它们的碰撞形状。此参数等同于对每个 Actor COMP 的「Initialize Actor」执行脉冲。某些情况下创建碰撞形状可能很耗时，因此如果不需要，应改用 Initialize Sim。如果用于创建碰撞形状的任何 SOP 发生变化，或实例化 OP 发生变化，则需要重建碰撞形状。
Initialize Sim init - 将所有 body 重置为初始状态（即位置、朝向、速度）。这不会开始逐步推进模拟，只会进行初始化。注意： 这不会重置任何 Actor COMP 的碰撞形状，应使用上面的「Initialize Sim and Collision Shapes」或 Actor COMP 上的「Initialize Actor」。
Start Sim start - 初始化模拟并运行（开始步进）。
Play play - 播放模拟。开启时会逐步推进模拟，关闭时不会（即暂停）。
Sample Rate rate - 模拟的采样率。采样率影响时间步，时间步为 1/rate
Simulation Speed simspeed - 模拟的速度。它是时间步大小的乘数，用于减慢或加快模拟。
Feedback CHOP feedback - （另请参阅：Bullet Solver CHOP）要回送的 CHOP 引用。Bullet Solver COMP 会取用该 CHOP 中的 transform/velocity 通道，并在下一个模拟步开始时覆盖相应 actor 的变换或速度。

如果回送的 Bullet Solver CHOP 中通道值没有任何变化，模拟会照常运行，因为没有任何内容被覆盖。这让你可以做出下面示例中的效果。 例如，要取反模拟中每个 actor 的速度，可以使用一个 Bullet Solver CHOP，将其接入 Switch CHOP，第二个输入为同一个 CHOP，只是速度通道取了反。然后将按钮脉冲导出到 switch index，并把 Switch CHOP 放入 Feedback CHOP 参数。这样，当按钮被按下单帧（脉冲）时，速度就会被覆盖并取反。 唯一必需回送的通道是 actor_id 和 body_id 通道，其他所有通道都是可选的。通道名称应与 Bullet Solver CHOP 中的完全相同。除 Bullet Solver CHOP 输出的通道外，还可以使用 force 和 torque。通道名称为 force[xyz] 和 torque[xyz]。注意： scale 不能用于回送。

Perform Contact Test contacttest - 为模拟中所有 body 启用接触测试。接触测试用于 Bullet Solver CHOP 上的 colliding 和 total_collisions 通道。未启用此参数时，这些通道的值不会更新。注意： 当 body 很多时，接触测试可能很慢。
Always Simulate alwayssim - 启用后，Bullet Solver COMP 每帧都会进行模拟（即计算）。
Callbacks DAT callbacks - 对带有 python 回调的 DAT 的引用。可用的回调有：onCollision(solverComp, collisions)、onFrameStart(solverComp)、onFrameEnd(solverComp)、onInit(solverComp)、onStart(solverComp)。创建 Bullet Solver COMP 时会自动创建并引用一个带有这些回调的 DAT。onCollision(solverComp, collisions) 传递所有发生的碰撞的列表，并要求启用 Perform Contact test。collisions 是命名元组列表（bodyA 和 bodyB）。bodyA 和 bodyB 是参与碰撞的两个 body。bodyA 和 bodyB 是 Python Body 对象（见 Body Class）。

参数 - Xform 页

Xform 参数页控制对象组件在世界空间中的变换。

  • sRGB srgb - sRGB 色彩空间，使用 sRGB 传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • sRGB - Linear srgblinear - sRGB 色彩空间，使用线性传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.601 (NTSC) rec601ntsc - Rec.601，NTSC 原色色彩空间，使用 Rec.601 传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.709 rec709 - Rec.709 色彩空间，使用 Rec.709（与 Rec.2020 相同）传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.2020 rec2020 - Rec.2020 色彩空间，使用 Rec.2020（与 Rec.709 相同）传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • DCI-P3 dcip3 - DCI-P3 色彩空间，D65 白点，2.6 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • DCI-P3 (D60) dcip3d60 - DCI-P3 "D60 sim" 色彩空间，D60 白点，2.6 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Display-P3 (D65) displayp3d65 - Display-P3 色彩空间，D65 白点，sRGB gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • ACES2065-1 aces2065-1 - ACES 2065-1（也称为 ACES AP0）色彩空间，线性 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • ACEScg acescg - ACEScg（也称为 ACES AP1）色彩空间，线性 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Passthrough passthrough - 选中后，颜色值将按原样用于运算，不作任何修改，也不尝试将其转换到 Working Color Space。
Parameter Reference White parmreferencewhite - - 在将参数颜色值转换为 Working Color Space 时，此项控制相对于 Reference White 应如何处理。如果 Working Color Space 的 Reference White 相同，则不做调整。如果不同，则此颜色的 Reference White 级别（亮度）将被调整到 Working Color Space 所期望的范围。例如，如果项目将 SDR Reference White 设为 120 nits，而 HDR Reference White 为 80 nits，那么 (1, 1, 1) 的颜色在 SDR 色彩空间中为 120 nits，将被转换为 (1.5, 1.5, 1.5)，在 HDR Working Color Space 中仍为 120 nits。
  • Default For Color Space default - 将根据所选的色彩空间使用 SDR 或 HDR Reference White。
  • Use Parent Panel useparent - 将使用父级面板所选的 Reference White。如果顶层面板也选择了「Use Parent」，则将使用「UI Reference White」。
  • Standard (SDR) sdr - 会将 Parameter Color Space 的 Reference White 值按 SDR 处理。
  • High (HDR) hdr - 会将 Parameter Color Space 的 Reference White 值按 HDR 处理。
  • UI ui - 会将 Parameter Color Space 的 Reference White 值按 UI 处理。其亮度使用「UI Reference White Nits」的值。
