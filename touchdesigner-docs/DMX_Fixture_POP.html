DMX Fixture POP

摘要

DMX Fixture POP 从 POP 输入构建 DMX universe，并与 DMX Out POP 配合使用，把 DMX 发送到设备。

在 POP 输入中，每个图元相当于一个灯具。系统会遍历每个灯具，并用 Channels 页上定义的 DMX 配置文件为每个灯具构建 DMX universe。图元/灯具按它们在 POP 中定义的顺序遍历。

以下图元属性（无符号整数）可用于指定 net、subnet、universe、channel 和 netaddress，从而无需使用 Routing Table 就能对每个灯具单独定制：

  • DMXFixtureNet
  • DMXFixtureSubnet
  • DMXFixtureUniverse
  • DMXFixtureChannel
  • DMXFixtureNetAddress

除此之外，还可以用一个无符号整数属性 DMXFixtureGap 来逐个图元覆盖 DMX Fixture POP 中的 Channel Gap 参数。

可以用 DMX Map DAT 检查创建出的 DMX universe。

创建 DMX 配置文件

DMX 配置文件由 DMX Profile 页上的 Channel 序列定义。

DMX 通道在 universe 输出中的排列顺序与它们在 DMX Profile 页上定义的顺序相同。

对于任何给定的 Channel 序列，所有属性分量都会交错在一起。例如，「P」会交错为「Px Py Pz」。如果 DMX 配置文件要求它们不交错，就需要把它们分到各自的 Channel 序列块中。

多个属性可以一起指定：例如，「P Color」会把 P 和 Color 交错成「Px Py Pz Colorr Colorg Colorb Colora」。如果交错的分量分辨率不同，就需要把它们分到各自的 Channel 序列块中，但通过启用 Merge with Above Block，它们仍可以交错在一起。

对于 Point 值类型，会先遍历完所有点，再进入下一个 Channel Sequence。

也可以指定单个属性分量。例如，「P(0) P(1)」只使用位置的 x 和 y。

除非为该属性组启用了 Interleave Bytes，否则属性分量按值交错。 例如：分辨率为 16 位的 Position 属性 P，在 Interleave Bytes 开关关闭时会交错为 Px[0] Px[1] Py[0] Py[1] Pz[0] Pz[1] ...，开启时会交错为 Px[0] Py[0] Pz[0] Px[1] Py[1] Pz[1] ...。

自动布局模式

当 Auto Layout 开关开启时，DMX Fixture POP 处于自动布局模式；或者在开关关闭、未引用路由表，或路由表没有行时，也默认为该模式。

自动布局模式会从定义的起点（使用 net、subnet、universe 和 channel 参数）自动递增 channel 和 universe 值。图元按图元顺序遍历（例如 prim 0 最先），每个图元的点按点顺序遍历（例如 point 0 最先）。

DMX Profile 页定义每个图元的通道布局。它对每个图元执行一次，然后在各图元的通道布局之间添加一个通道间隙（由参数指定）。

如果 Quantize Universe 设为 off，下一个图元会紧接在通道间隙之后开始。但如果 Quantize Universe 设为 By Fixture，则会先检查下一个图元（即灯具）能否放入该 universe 剩余的通道中，若不能，就跳到下一个 universe 的 channel=1 处。同样，如果 Quantize Universe 设为 By Components，而 DMX Profile 页上某个多分量 DMX Channel 条目无法把全部分量放入该 universe 剩余的通道中（例如 P 有 3 个分量 x y z，8 位分辨率时需要 3 个剩余通道），则会跳到下一个 universe 的 channel=1 处。

设置 DMXFixtureNetAddress 属性后，每个具体的 net 地址值都会各自独立递增 channel 值。例如，如果有 8 个图元、每个正好 512 个通道，其中 4 个的值为 DMXFixtureNetAddress=192.168.0.1、4 个的值为 DMXFixtureNetAddress=192.168.0.2，那么得到的通道布局将是 4 个 universe [0-3]，带 netaddress=192.168.0.1，以及 4 个 universe [0-3]，带 netaddress=192.168.0.2。

设置 DMXFixtureUniverse 属性后，该 universe 的 channel 值会设为 1，除非同时设置了 DMXFixtureChannel。如果 DMXFixtureUniverse 大于 15，则即便设置了 DMXFixtureNet 和 DMXFixtureSubnet 属性值也不会被使用。

参数 - Fixture 页

Active active - 启用后会主动更新灯具和 universe 数据，如果在 DMX Out POP 中使用，还会发送到设备。禁用时，DMX Out POP 不会合并该 POP 构建的 DMX universe 用于发送。
Auto Layout autolayout - 启用后，universe 会从参数中指定的 net、subnet、universe 和 channel 开始按顺序构建。例如，若起点为 net=0、subnet=0、universe=1、channel=0，则 DMX Fixture POP 会按配置文件遍历全部 512 个通道，然后转到 universe 2。禁用时，必须改用 Routing Table，并把 universe 手动分配给 primindex。
Routing Table routingtable - 使用 Routing Table 为灯具/图元分配特定的 net、subnet、universe 值。此外，还可以选择指定 netaddress 来覆盖 DMX Out POP 上的对应项。路由表会覆盖参数的使用，以及任何保留属性：DMXFixtureNet、DMXFixtureSubnet、DMXFixtureUniverse、DMXFixtureChannel 和 DMXFixtureNetAddress。
Net (0-127) net - 使用自动布局时，指定起始 net 值。
Subnet (0-15) subnet - 使用自动布局时，指定起始 subnet 值。
Universe universe - 使用自动布局时，指定起始 universe 值。
Channel channel - 使用自动布局时，指定起始 channel 值。
Channel Gap changap - 使用自动布局时，指定灯具之间的通道数量。例如，如果灯具 1 在第 200 个通道结束，而通道间隙为 10，则灯具 2 将从第 211 个通道开始。
Quantize Universe quantizeuni - - 指定在 universe 内执行的量化级别。可以设为 By Fixture 或 By Component。
  • Off off - 设为 Off 时不做量化，通道和灯具都可以跨越 universe。
  • By Fixture fixture - 设为 By Fixture 时，灯具不能跨越 universe（即通道范围不能始于一个 universe 而止于另一个），意味着最多只能是 512 个通道。此外，如果某个灯具无法放入某个 universe 的剩余通道，它会被移到下一个 universe。
  • By Component component - 设为 By Component 时，多分量 DMX Channel 条目（例如 P 有 3 个分量 x y z，8 位分辨率时需要 3 个通道）不能跨越 universe。如果无法放入某个 universe 的剩余通道，它会被移到下一个 universe。

参数 - DMX Profile 页

DMX Channel dmxchan - 用于定义 DMX 配置文件的顺序参数块的开始
Name dmxchan0name - 指定唯一的 DMX Channel 标识符。
Value Type dmxchan0valuetype - - 指定通道值如何遍历，以及属性如何获取。
  • Point point - 使用 Point 值类型时，会为该通道块遍历每个点并交错它们的值，然后再进入下一个通道。
  • Primitive primitive - 使用 Primitive 值类型时，通道值只会在每个图元/灯具上从值来源交错一次，然后再进入下一个通道。
Value Source dmxchan0valuesource - - 对于 DMX 通道值，从属性或参数中获取。
  • Constant constant - 用常量设置通道值。注意：如果 Value Type 为 Point，仍会遍历每个点一次并把它们的值设为该常量。换句话说，无论使用常量还是属性作为值来源，用掉的通道数都一样。
  • Attribute attribute - 用属性设置值。可以同时指定多个属性，它们会全部交错。
Group dmxchan0group - 可选地选择一个点组。只有组内的点会用于 universe 创建，而不是全部点。

Value is Normalized dmxchan0normalized - 启用时，期望的取值为 0-1，它们会被缩放到该分辨率对应的范围（例如 8 位为 0-255）。禁用时，值按原样输出。两种情况下都会做限幅。
Merge with Above Block dmxchan0merge - 启用时，会把通道值与上方块交错。这些块必须具有相同的值类型和值来源。当需要交错不同分辨率的值时，这个特性很有用。
Interleave Bytes dmxchan0interleavebytes - 启用时，属性分量值将按字节顺序交错，而不是按值顺序。例如：分辨率为 16 位的 Position 属性 P，在开关关闭时会交错为 Px[0] Px[1] Py[0] Py[1] Pz[0] Pz[1] ...，在 Interleave Bytes 开关开启时会交错为 Px[0] Py[0] Pz[0] Px[1] Py[1] Pz[1] ...。这也意味着，如果分量是 8 位值分辨率，该开关将不起作用。当多个 DMX Channel 块通过 Merge Above Block 合并在一起时，Interleave Bytes 只能在根（即最顶层）DMX Channel 上启用。

参数 - Common 页

Bypass bypass - 把第一个输入原样传递到输出。
Free Extra GPU Memory freeextragpumem - 释放输出内存增减时累积占用的内存。
Delete Input Attributes delinputattrs - 只输出你在该 POP 中指定的属性——有助于把属性隔离到单独的分支。
Parameter Color Space parmcolorspace - - 控制如何解释此节点上的所有颜色参数。仅在项目启用了 Working Color Space 时可用。颜色值被视为处于所选色彩空间中，并在作为节点运算的一部分使用之前转换为 Working Color Space。注意这不会改变节点自身的色彩空间，因为它始终处于 Working Color Space。
  • sRGB srgb - sRGB 色彩空间，使用 sRGB 传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • sRGB - Linear srgblinear - sRGB 色彩空间，使用线性传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.601 (NTSC) rec601ntsc - Rec.601，NTSC 原色色彩空间，使用 Rec.601 传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.709 rec709 - Rec.709 色彩空间，使用 Rec.709（与 Rec.2020 相同）传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.2020 rec2020 - Rec.2020 色彩空间，使用 Rec.2020（与 Rec.709 相同）传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • DCI-P3 dcip3 - DCI-P3 色彩空间，D65 白点，2.6 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • DCI-P3 (D60) dcip3d60 - DCI-P3 "D60 sim" 色彩空间，D60 白点，2.6 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Display-P3 (D65) displayp3d65 - Display-P3 色彩空间，D65 白点，sRGB gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • ACES2065-1 aces2065-1 - ACES 2065-1（也称为 ACES AP0）色彩空间，线性 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • ACEScg acescg - ACEScg（也称为 ACES AP1）色彩空间，线性 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Passthrough passthrough - 选中后，颜色值将按原样用于运算，不作任何修改，也不尝试将其转换到 Working Color Space。
Parameter Reference White parmreferencewhite - - 在将参数颜色值转换为 Working Color Space 时，此项控制相对于 Reference White 应如何处理。如果 Working Color Space 的 Reference White 相同，则不做调整。如果不同，则此颜色的 Reference White 级别（亮度）将被调整到 Working Color Space 所期望的范围。例如，如果项目将 SDR Reference White 设为 120 nits，而 HDR Reference White 为 80 nits，那么 (1, 1, 1) 的颜色在 SDR 色彩空间中为 120 nits，将被转换为 (1.5, 1.5, 1.5)，在 HDR Working Color Space 中仍为 120 nits。
  • Default For Color Space default - 将根据所选的色彩空间使用 SDR 或 HDR Reference White。
  • Use Parent Panel useparent - 将使用父级面板所选的 Reference White。如果顶层面板也选择了「Use Parent」，则将使用「UI Reference White」。
  • Standard (SDR) sdr - 会将 Parameter Color Space 的 Reference White 值按 SDR 处理。
  • High (HDR) hdr - 会将 Parameter Color Space 的 Reference White 值按 HDR 处理。
  • UI ui - 会将 Parameter Color Space 的 Reference White 值按 UI 处理。其亮度使用「UI Reference White Nits」的值。
