Blend SOP

摘要

Blend SOP 在拓扑结构相同的形状之间提供 3D 变形。它可以使用每个输入各自通道的平均权重，在最多十六个输入 SOP 之间混合。它还会在形状之间插值点颜色和／或纹理坐标。

为了获得最佳效果，每个 SOP 几何中的点数／CV 数（以及面数）应当相同。点的顺序应当相近；如果一个源中的第 17 个点在左侧，而另一个源中的第 17 个点在右侧，它就会在混合过程中横穿物体移动，可能产生扭曲变形的形状。为确保不发生这种情况，可以让所有待混合的部件都通过编辑同一个基础形状的点位置来制作。每个要变形的部件都必须位于不同的 SOP 中。

例如，在 Model Editor 中编辑形状时，可以将每个特定的几何保存后再读入，也可以将 Model SOP 直接输入 Blend SOP。这样，基础模型几何会先进入 Blend SOP 的第一个 Blend 输入，然后最多 15 个 Model SOP 从包含基础模型几何的 SOP 获取输入，再输入 Blend SOP。请记住，Model SOP 无法解锁，因此是不使用 File In SOP 也能安全存储数据的方式。

Blend SOP 现在只计算权重非零的输入。

另请参见 Sequence Blend SOP。

参数 - Blend 页

Group group - 指定第一个输入中的点组或图元组。例如，如果指定的组包含第一个和第三个点，那么每个输入的第一个和第三个点都会被混合，而第二个、第四个、第五个等点则会被设为与第一个输入源一致。接受模式匹配，详见：Pattern Matching。
Differencing diff - 在对象之间生成夸张的混合，大于 1 或小于 0 的值会产生过度缩放后的混合。

勾选此选项后，上述通道值不会求和并缩放到 1。第一个输入被视为参考；Blend 会为每个点计算第一个输入与其他输入之间的差异；大于 1 和小于 0 的值会使第 2 个及之后的输入形状产生夸张效果。但第一个输入无法通过其混合通道 /blend1 被夸张，它被视为「基础」。使用 Differencing 时，/blend1 通道不起作用。如果必须变形第一个输入中的几何，请将其接入另一个输入，在那里混合通道才会生效。

Blend Position dopos - 勾选后，将根据混合通道的权重混合输入的点位置。未勾选时，输入几何不会改变，仅允许在选中时混合 Colors、Normals 和 Textures。
Blend Colors doclr - 勾选后，将根据混合通道的权重混合输入几何的点颜色。
Blend Normals donml - 勾选后，将根据混合通道的权重混合输入几何的点法线。
Blend Texture douvw - 勾选后，将根据混合通道的权重混合输入几何的点纹理坐标。
Blend Up doup - 勾选后，将根据混合通道的权重混合输入几何的 Up Vector。

参数 - Weights 页

控制各输入几何对输出几何贡献的通道。根据已连接的输入数量，在下方按需添加参数。

Input input - 输入权重序列。
Weight input0weight - 该输入的权重或贡献。0 表示无贡献，1 表示全部贡献。

用法

此 SOP 可用作一种几何变形方式。为几何建模，例如角色头部的嘴部。它将作为你的第一个输入。

每个输入对最终形状的贡献量由各输入的混合通道控制。编辑混合通道的值，每个输入就会按比例决定最终形状。

例如，如果 /blend3 通道的值为 1，其余通道都设为 0，最终形状就是第三个输入 SOP 中的几何。现在将 /blend5 通道的值改为 1，最终形状将是输入 SOP 三和五中几何各占 50% 的混合。将两个通道都设为 0.3 会得到完全相同的结果；只要两个通道的数值相同，无论取什么数，对形状的贡献都相等。

Info CHOP 通道

Blend SOP 的额外信息可通过 Info CHOP 访问。

SOP 通用信息通道

  • num_points - 此 SOP 中的点数。
  • num_prims - 此 SOP 中的图元数。
  • num_particles - 此 SOP 中的粒子数。
  • last_vbo_update_time - 在另一个线程中根据 SOP 的 CPU 数据更新 GPU 上的几何数据所花的时间。由于它属于另一个线程，此时间不计入通常的帧时间。
  • last_meta_vbo_update_time - 在另一个线程中根据 SOP 的 CPU 数据更新 GPU 上的元表面几何数据（如 metaball 或 nurbs）所花的时间。由于它属于另一个线程，此时间不计入通常的帧时间。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
