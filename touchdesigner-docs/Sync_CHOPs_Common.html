Sync CHOP 通用参数

Sync In CHOP 和 Sync Out CHOP 用于让两个或更多 TouchDesigner 进程中的时间轴保持在彼此一帧之内。一个进程包含 Sync Out CHOP，一个或多个其他进程包含 Sync In CHOPs。带 Sync In CHOPs 的进程应设置其 Realtime flag checked off，因为它们的帧率将由 Sync Out CHOP 决定。另请注意，所有显示器（包括所有客户端和服务器）都应设置为 same rate。注意拔掉或重新接入显示器有时会改变先前配置的设置。

这些 CHOP 通过暂停自己的时间轴直到所有 Sync In/Out CHOP 完成计算来实现同步。Sync Out CHOP 会领先于 Sync In CHOPs。如果有任何 CHOP 通信失败，其他 CHOP 会超时，导致所有进程运行缓慢。

客户端机器可以在任何时候上线，也可以按需关闭，因为 Sync Out CHOP 会相应调整，按指定对个别客户端临时或永久封禁。

此外，通过 Sync Out CHOP 发送的任何额外 CHOP 通道都会被 Sync In CHOPs 接收。

NOTE for Windows OS - If experiencing connection issues make sure Windows Firewall is disabled.

一个指向 Sync Out CHOP 的 Info DAT 可提供所有客户端的详细列表：

各列含义为：

  • pid：客户端的进程 id
  • address：ip 和端口号
  • machine_name：客户端机器名
  • filename：客户端所在的 .toe 文件名
  • op_path：到客户端的完整操作符路径
  • include：为 1 时，Sync Out CHOP 等待回复；为 0 时忽略。
  • timeout_total：Sync Out CHOP 等待该客户端而停顿的总次数
  • timeout_consecutive：Sync Out CHOP 等待该客户端而停顿的当前计数。
  • steady_total：Sync Out CHOP 按时收到回复的总次数。
  • steady_consecutive：Sync Out CHOP 按时收到回复的当前计数：
  • reply：客户端最后一次回复，所有客户端应具有相同的递增数值。


类似地，一个 Info CHOP 会揭示更多信息：Info CHOP Channels

间歇性连接

每当客户端回复，Sync Out CHOP 就会立即认为它可靠，并在之后的每一帧等待它。 然而，当客户端连续超时若干次后，Sync Out CHOP 会持续忽略它，直到它再次按时回复。 这也适用于已完全停止通信的客户端。 连续超时次数由 Client Timeouts (consecutive) 参数控制，并反映在 timeout_consecutive Info DAT 列中。

修复客户端掉帧

如果某台客户端在掉帧，可用 info DAT 检查服务器端的 Sync Out CHOP。查看 timeout_consecutive 列。同时留意 Sync In CHOP 名为 sync_incompletes 的 info chop 通道。如果这两个属性中有一个或两个在增长，试着调整 sync CHOP 的 TimeOut 参数。已知增大该值可以解决此问题。

封禁

如果某客户端的通信不可靠，时而稳定、时而超时，可以通过启用 Ban Clients 并相应设置 Total Timeouts 来永久忽略它。一旦客户端超时达到一定次数，其 Info DAT 的 include 列会报告 banned，之后它将被始终忽略，即使它又开始按时响应。

重置

Sync Out CHOP 每次初次启动时，所有客户端都会被接受，没有任何封禁。在 Sync Out CHOP 中按下 Clear Stats 也会回到此状态，清除所有封禁列表和总计，即使在远程客户端的 Info CHOPs 中。

另见 Syncing Multiple Computers 和 Hardware Frame Lock。
