克隆

Clones 是 TouchDesigner 用来确保多个组件与主克隆的结构和行为保持一致的机制。当主组件被编辑时，它的所有克隆会自动改变以保持一致。

克隆是指 Clone Master 参数被设为另一个组件路径的组件，那个组件就是它的「克隆主控」。如果 Clone Master 参数为空，或指向不存在的组件，或其 Clone Enable 参数关闭，或克隆主控的 Clone Enable 关闭，则该组件不是克隆。

Common among all Clones：克隆与其主控的共同点：

  • 克隆主控上的所有顶层自定义参数和页面都会在克隆上重新创建。参数定义相同，但值不会镜像——克隆的所有顶层参数的值都与主控独立。（在主控的某个参数上右键 → Copy to all Clones，可手动把改动后的值传播到所有克隆。）
  • 在克隆内部，所有克隆都会被强制包含组件内相同的子操作符（节点）。这包括节点之间的连线、节点的布局、参数值，以及节点的标记，例如 bypass、lock 和 viewer state。

Unique to each Clone：可以让克隆以不同方式计算和输出：

  • component inputs - 通过输入进入克隆的 CHOP、SOP、TOP 和 DAT 可能带有不同的数据。因此克隆内节点输出的数据通常不同，克隆自身输出的数据也会不同。
  • 如上所述的 top-level component parameter values。
  • expressions - 克隆上或克隆内节点上使用 parent().name（操作符父级的名称）和 parent().digits（操作符父级名称中的数字）的表达式，可用来区分不同的克隆。例如，克隆名称中的数字可用于在外部表格中查找值（op('table1')[parent().digits, 'columnname']）。因此参数可能具有相同的表达式，但表达式可能计算出不同的值。
  • immune nodes - 位于克隆内部并设为「免疫」（节点上的标记）的节点不可触碰且唯一。设置了免疫标记的节点不会被强制与克隆的主控一致。例如，你可以在克隆内放一个免疫的 Table DAT，使它唯一、封装且便于移植。

让所有克隆的某个参数具有相同的值

在任意作为若干克隆主控的参数上右键，选择「Copy to all Clones」。这会找到所有克隆并让它们的值全部相同。

克隆免疫与 Immune 标记

免疫允许：（1）克隆内的节点不从克隆主控更新；（2）克隆中存在一个在克隆主控中不存在的节点。

如果你打开克隆内某个节点的 Immunity 标记，然后在克隆主控中更改该节点，克隆中的节点会保持不变。一个典型的例子是用 Clone Immune 在克隆内保留个性化的 DAT 表格：这些表格可以在每个克隆中包含不同的数据。

你可以在克隆中添加任意数量的新节点并打开它们的 Immunity 标记。这些节点不会被克隆删除或更改。

在克隆主控组件中，如果你打开任意节点的 Immune 标记，那么该 Immune 标记会在所有克隆中被打开。如果你在克隆主控中关闭某个节点的 Immune 标记，TouchDesigner 会询问你是否要在所有克隆中关闭该标记。

如果你在主克隆中 paster 一个 Clone Immune 节点，那么该免疫节点会在每个克隆中被创建。如果你在克隆主控中删除一个免疫节点，它也会在克隆中被删除，除非你进入克隆并手动设置了克隆免疫标记。

更多行为参见 Immunity。
