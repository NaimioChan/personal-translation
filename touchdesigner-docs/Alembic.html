Alembic

"Alembic 是一个开放的计算机图形交换框架。Alembic 将复杂的动画场景提炼为一组非程序化、与应用程序无关的烘焙几何结果。这种将场景「提炼」为烘焙几何的方式，完全类似于将灯光和渲染场景提炼为渲染图像数据。

Alembic 专注于高效存储复杂程序化几何构建的计算结果。它非常明确地不负责存储用于生成这些计算结果的程序化工具的复杂依赖图。例如，Alembic 会高效存储由任意复杂的动画与模拟流程（可能涉及包络、校正形状、体积保持模拟、布料与肌肉模拟等）所产生的动画顶点位置和动画变换。Alembic 不会尝试存储生成最终动画顶点位置与动画变换所需的计算网络（基本上就是 rig）的表示。" [1]

Alembic 导入

Alembic 文件可以通过 Alembic In POP 和 Alembic SOP）导入 TouchDesigner。 几何支持的 Alembic 图元有 polymesh、curves 和 points。此外，也支持 Alembic 变换。

Polymesh 图元在面为 3 个或 4 个顶点时分别作为三角形或四边形导入，面超过 4 个顶点时作为闭合线带导入。

一个 Alembic 归档可能包含一个或多个几何的一个或多个对象路径。可以一次查看所有这些对象，也可以使用「Object Path」参数菜单分别选择它们。如果分别选中的对象包含重复的属性（即名称相同）但关联到不同的属性类（例如 vertex 与 point），则重复的属性将被转换为顶点属性。

Alembic 文件 schema 中的每个对象都可能拥有标准或自定义属性。标准属性有法线（N）、速度（V）和纹理坐标（Tex）。 一个 Alembic schema 中可能存在多个自定义属性，其名称和类型更灵活。大多数 Alembic 属性都受支持，但并非都能一对一转换为 POP 格式：

  • 16 位 int 属性（例如 Int16、V2s、P3s 等）会转换为 32 位 int。
  • 64 位属性（例如 Uint64、Int64、V2d 等）会转换为 double，这是 POP 目前唯一支持的 64 位属性。
  • 分量数大于 4 的属性（例如 Box3f、M33f、M44f 等）会打包为 vec4 数组。如果存在这类属性的数组，它们会首尾相接地打包在一起。例如 M44f 有 16 个分量，将作为 float4[4] 导入，而 M44f[2] 将作为 float4[8] 导入，M44f[0] 在前，M44f[1] 在后。

unsupported 属性列表：

  • String/WString
  • 8 位和 16 位浮点颜色
  • Bool
  • UChar/Char

Alembic 导出

Alembic 文件可以使用 , 导出，并通过 Alembic Out POP 输出为 Alembic 文件。

目前仅支持单对象 Alembic 文件。当导出的 POP 只包含 Point 图元时，将导出为单个 Points Alembic 对象。所有其他面图元（三角形和四边形）将导出到一个 PolyMesh 对象中。File Out POP 尚不支持导出线带或曲线。

属性

File Out POP 支持写入多种不同的属性类型。其中有内置和自定义两种。

内置属性包括 Color、N 和 Texture Coordinates（默认 Tex，但可以通过 Tex Coord Attribute 参数指定）。如果这些属性存在，将自动写入。

自定义属性可以在 Alembic Out POP 的 Inputs 页上指定，并支持以下类型

  • int, uint, float, double
  • int2, float2, double2
  • int3, float3, double3
  • 上述类型的数组属性，例如 float3[15]

此外，具有两个或更多分量的属性可以写为 Point 或 Vector 属性。

对于只有点图元的 POP，只能写入点属性。对于有面图元的 POP，可以导出点、顶点和图元属性。

对于动画点云，可以指定两个附加属性：Ids Attribute 和 Velocity Attribute。 对于使用 Particle POP 创建的 POP，它们分别是 PartId 和 PartVel。
