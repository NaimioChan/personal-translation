优化

所有实时系统都需要在优化阶段投入大量精力和制作时间。对 TouchDesigner 网络进行性能优化，往往可以带来 2 到 20 倍的速度提升。这会影响你的计算机硬件能运行什么，也会影响观众的体验。

优化工具：

  • 在每个节点上中键单击弹出的信息窗口（macOS 上为 alt+右键单击）
  • Dialogs 下的 Performance Monitor Dialog（alt+y），用于辅助优化。
  • Palette 中的 Probe，可以图形化地观察 CPU 和 GPU 上的时间与内存如何被动态消耗，并捕捉性能的瞬时下降。
  • Dialogs → Errors 以及 Error DAT，用于捕捉可能拖慢速度的错误。
  • Textport
  • Perform CHOP 后接 Trail CHOP，并打开 Frame Time 和 Cook 通道，以查看性能的时间历史。
  • 你的 Python 脚本中的 print() 或 debug() 语句

每秒帧数（或每帧毫秒数）取决于每帧的计算负载，尤其是所选用的程序化操作符、几何数量、CPU 与显卡速度，而最重要的是用户在搭建项目时所采用的优化。

TouchDesigner 大量使用 CPU 和 GPU。减轻这两个处理器的负载需要两种不同的策略，如下所述。

Quick Tip：首先要确定 GPU 是否为瓶颈。试着把渲染分辨率降到 64x64，看看速度是否提升。如果提升了，就说明与 GPU 有关。不过你的问题也很可能不是 GPU 瓶颈，除非你只是在运行 GLSL 着色器，系统中几乎没有其它负载。查看 Performance Monitor，了解哪些部分占用了大部分时间。

参见 Cook、Dependency、Event、Troubleshooting in TouchDesigner

确定瓶颈

CPU 与 GPU 之间的交互高度流水线化。流水线是计算中的一种特性，类似工厂里的装配线。流水线可以带来高得多的速度，但在尝试优化其中一环时，你必须非常注意瓶颈。

以汽车工厂为例。假设该工厂的装配线有 3 个阶段：一个制造底盘，一个把发动机装到底盘上，一个把车轮装到底盘上。假设底盘部门每小时能造 10 个底盘，发动机安装工每小时能装 7 台发动机，车轮安装工每小时能装 15 套车轮。由于除非所有零件都装好，汽车就没有用，所以工厂每小时只能产出 7 辆车。如果管理层出去买了一台机器，让车轮安装工每小时能装 25 套车轮，工厂每小时仍然只能产出 7 辆车。发动机安装工就是流水线中的瓶颈。工厂提高产量的唯一办法，是先提高发动机安装工效率，使他们每小时能装 10 台或更多发动机。假设他们能提高到每小时 13 台。现在工厂每小时能造 10 辆车，因为底盘部门此时成了瓶颈，在底盘部门变得更高效之前，对发动机部门的任何进一步改进都是无用的。

以上所有内容对 TouchDesigner 同样成立，其中不同的「部门」就是 CPU 和 GPU（它们还可以进一步分为子部门，但那另作讨论）。因此，如果你的系统存在 CPU 瓶颈，减轻 GPU 负载不会带来帧率的任何变化。

CPU 瓶颈

你可以使用 Hog CHOP 来查看是否存在 CPU 瓶颈。如果放置一个 Hog CHOP 后帧率下降，说明存在 CPU 瓶颈。如果帧率没有变化，说明瓶颈在 GPU。

反之，如果你把图像的渲染或合成（TOPs）降到非常小的分辨率（如 32x32），而帧率没有变化，说明存在 CPU 瓶颈。

GPU 瓶颈

GPU 自身的流水线也有若干阶段，其中包括顶点着色、像素着色、混合。对于 TOP 而言，95% 的情况下 GPU 瓶颈来自像素着色器。当它着色的像素过多，和/或每个像素需要执行的操作过于昂贵时就会如此。

要判断是否存在像素着色器瓶颈，试着降低每帧都在计算的 TOP 的分辨率。如果帧率上升，说明存在像素着色器瓶颈。

如果你把 X 和 Y 方向的分辨率都减半（Common 页），总像素数就降到四分之一，此时该 TOP 的 GPU 时间也应降到四分之一。（在节点上中键单击可查看该节点的 GPU 时间。）

优化 CPU 使用

性能监视器

使用 Performance Monitor Dialog 找出耗时的计算或不必要地计算的节点。通过性能监视器，你可以看到一帧的计算顺序，以及所有阶段的计算时间。你也可以在超过某阈值的帧上触发转储。使用 Probe 动态观察 CPU 使用率的变化。

OP 计算时间、OP 信息弹窗

每个 OP 信息弹窗（在 OP 上中键单击）都会显示它已计算的次数，以及上一次计算花费的时间（毫秒）。

  • cook time：该操作符处理（或「cook」）所需的时间。
  • number of cooks：通常重要的是它每帧都计算、只计算一次，还是仅在其输入数据变化时才计算。

理解节点为何计算

参见 Cook 一文。

查找不必要的计算

  • Re-ordering：不会变化的 OP 应移到计算链的靠前位置，以免不必要地计算。
  • Combining output length of multi-input CHOPs：当两个或更多 CHOP 合并时（在 Math CHOP 中连接），要确保结果 CHOP 的长度不会因为一个 CHOP 在第 1 帧、另一个在当前帧而不必要地变长。

更快的计算

一般来说，DAT、SOP、CHOP 在后续计算时，如果不必增删输出中的单元格/点/通道，而只是调整上次计算的输出值，计算会更快。因此，尽可能让每次计算生成的输出量保持一致。

确保你的几何处于最佳格式

虽然实际渲染几何的是 GPU，但把渲染该几何所需的全部信息告知 GPU 可能带来很大的开销。更多信息请参阅 Optimize Geometry for Rendering 一文和 Render TOP。

在对象层级而非 SOP 中变换几何

尽可能在 object 层级进行变换。通常，如果对象的 SOP 中有一个 Transform SOP，其平移、旋转或缩放的效果与在对象层级应用相同变换参数相同。也就是说，使用 Transform SOP 与在对象变换上使用相同数值效果相同。但它们的计算时间差别很大。作为 SOP 时，CPU 需要对每个点应用变换；而如果变换在对象上，则由图形硬件完成，速度快得多，并且是对整个对象应用。

分析 DAT 中的 Python 脚本

Python 脚本可能非常昂贵。如果性能监视器显示它们占用了大量时间，就值得看看能否优化。可以使用通用的 Python 和编码优化技巧。你可以使用 time 模块中的 time.perf_counter() 方法来分析脚本中哪些部分耗时。

在许多情况下，一段段 Python 代码可以替换为由少数 TouchDesigner CHOP 或 DAT 组成的小网络，速度可能快一个数量级。你越熟悉 CHOP 和 DAT，就越能节省自己的时间和 CPU 的时间。

如果可能，避免每帧运行的脚本。性能监视器会显示脚本的计算时间。优化 Python 的方法有很多，包括预先计算那些会被多次使用的量和引用。

通过在表达式中使用 Python 减少计算

参数表达式中的 Python 现在已相当优化（通常会预编译成更可执行的代码）。查看带表达式的参数上的悬停弹窗帮助，会显示 (Optimized) 或 (Un-optimized)。最耗时的是扩展和模块中的长 Python 函数。

减少 CHOP 中的计算

Selective 模式下的 Null CHOP 可用于在 Null CHOP 的输入不变时减少 CHOP 链下游的计算。不过在此模式下，Null CHOP 本身在数据变化时总是计算，因此请谨慎使用。

其它进程运行并打断 TouchDesigner

  • 运行 TouchDesigner 时关闭所有病毒检查和间谍软件服务。这些服务常常占用大量 CPU 周期，并频繁访问硬盘。
  • 关闭所有不必要的 Windows 服务。

多 CPU 使用

  • 你可以在同一台计算机上运行多个 TouchDesigner 实例。然后使用各种 Touch In/Out 在进程之间传递数据，从而把部分工作分担到其它处理器上。
  • 请注意，使用 Touch In TOP 和 Touch Out TOP 以及大尺寸图像这样做可能得不到你想要的性能提升，因为 TOP 大量使用显卡，而你只有一块。不过你完全可以在另一台物理计算机上这样做，并使用快速的千兆网络。

优化 GPU 使用

减少 Render TOP 中的像素数量

与其它 TOP 一样，如果你把 Render TOP 的 X 和 Y 分辨率都减半（Common 页），总像素数就降到四分之一，GPU 渲染时间也应降到四分之一。（在节点上中键单击可查看时间。）

减少 Render TOP 中的过度绘制

参见关于 Early Depth-Test 的文章。

另一个有助于减少过度绘制的功能是 Back-Face Culling。

减少 Render TOP 中的顶点数

如果顶点或粒子数量非常高，顶点着色器引擎会影响 GPU 负载，尤其是在你使用带顶点着色器代码的 GLSL 着色器时。此时试着减少顶点或粒子数量，看看渲染时间是否下降。

减少 Render TOP 中的 GPU 负载

真正大幅影响速度的是灯光数量、灯光类型，以及 MATs 中使用的功能。例如，锥形灯比点光源或距离点光源更昂贵（参见 Light COMP）。在 Phong MAT 中启用 Rim Lighting 等功能也会增加像素着色器的开销（要查看开销，关闭 rim lighting 看速度提升多少）。

Render TOP 参数

Render TOPs 的 Advanced 页上有一些参数可以用来加速渲染。例如，如果你只是在计算阴影贴图，可以打开 Draw Depth Only 功能。如果你不需要该 Render TOP 的颜色输出，可以关闭 Color Output Needed，这样就能避免把离屏抗锯齿缓冲解析到一张可供其它 TOP 用作输入的纹理中。

减少其它 TOP 的负载

如上所述，其它 TOP 的开销通常与其分辨率直接相关，降低分辨率会使 GPU 负载获得 1:1 的加速。有些 TOP 的开销取决于其参数，Blur TOP 的滤镜尺寸就是一个例子。

优化内存使用

使用 Probe 查看 CPU 和 GPU 内存在哪里被消耗。

Audio Play CHOP

Audio Play CHOP 目前会把整个声音文件加载到 RAM 中。如果你的声音文件较长，应考虑使用 Audio File In CHOP。
