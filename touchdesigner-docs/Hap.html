Hap

Movie File In TOP 支持 Hap、Hap Q 和 Hap R 编解码器，Movie File Out TOP 也能编码它们。Hap 和 Hap Q 还用于 over-IP 视频操作符 Touch Out TOP 和 Touch In TOP。

Hap 是一种使用计算机图形硬件进行解压的视频编解码器，能大幅降低播放视频所需的 CPU 占用。它允许播放比我们所知任何其他编解码器更高分辨率和/或更高帧率的视频。它还允许播放比其它编解码器多得多的低分辨率视频流，前提是你的驱动器速度跟得上。

Hap 有许多不同的编解码器：

  • Hap - 数据率最低，图像质量也较低。8 位色深。
  • Hap Alpha - 图像质量与 Hap 相同，并支持 Alpha 通道。Hap Alpha 的文件大小是 Hap 文件的两倍。8 位色深。
  • Hap Q - 图像质量大为改善，但没有 alpha 通道。Hap Q 的文件大小约为 Hap 文件的两倍。8 位色深。
  • Hap Q Alpha - 图像质量与 Hap Q 相同，但也包含 Alpha 通道。8 位色深。
  • Hap R - 图像质量高于 Hap 和 Hap Q，并且可以包含 alpha。8 位色深。使用 BC7 Texture Compression。*** WARNING - GPU Driver Timeout on long GPU activities *** 在高分辨率下编码这种格式可能是缓慢且占用 GPU 的操作。因此它通常会超过 Windows 给 GPU 驱动完成一次操作的默认 2 秒时间。如果你看到提示说 Windows 重置了 GPU 驱动，那就是遇到了这个问题。要解决此问题，请创建以下注册表值：

HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\GraphicsDrivers\TdrDelay
该值的类型应为 REG_DWORD。此值是操作系统重置 GPU 驱动前一次操作可以持续的秒数。根据你打算编码的分辨率，把它设得更大一些，比如 20-40（秒）。必须重启机器此设置才会生效。如果仍然出现驱动重置，就再设大一些。

  • Hap HDR - 具有 16 位浮点数据。由于数值可以超出 0-1 范围，它旨在用于 HDR 内容。它 not 适合编码点云位置等原始数据。使用基于 BC6 Texture Compression。

Hap Q 的图像质量很高，是播放超高分辨率视频项目的绝佳选择。由于文件数据率高，你经常遇到的主要瓶颈是 SSD 读取速度。

压缩比与数据率

Hap 编解码器采用两级压缩。第一级是纹理压缩，为固定压缩比。第二级是 CPU 压缩，压缩比随内容变化。对于噪点多/繁忙的内容，CPU 这一级可能完全没有压缩。第一级是有损压缩，可能引入伪影或色带。第二级是无损的，不会引入任何额外的图像伪影。

Hap 视频的数据率几乎不会差于这些比例，它们是每种格式固定的纹理压缩比。

  • Hap = 每像素 0.5 字节/每像素 4 位。相比未压缩的 RGB 视频为 6:1 压缩。也称为 Hap1。
  • Hap Alpha = 每像素 1 字节/每像素 8 位。相比未压缩的 RGBA 视频为 4:1 压缩。也称为 Hap5。
  • Hap Q = 每像素 1 字节/每像素 8 位。相比未压缩的 RGB 视频为 3:1 压缩。也称为 HapY。
  • Hap Q Alpha 每像素 1.5 字节/每像素 12 位。相比未压缩的 RGBA 视频为 2.6:1 压缩。也称为 HapM。

因此对于 4096x2160@60hz 的视频，即每秒 530,841,600 像素。最坏情况下的数据率为：

  • Hap = 265,420,800 字节/秒
  • Hap Alpha = 530,841,600 字节/秒
  • Hap Q = 530,841,600 字节/秒
  • Hap Q Alpha = 796,262,400 字节/秒。

纹理压缩之后，得到的帧会使用一个名为 Snappy 的快速、非激进的压缩器进行压缩，通常可获得 2:1 的压缩比。这一级压缩是无损的，不会引入任何伪影。

TouchDesigner 支持该编解码器所有形式的编码和解码。

它的规范和示例代码可以在 github 上找到：Hap video codec

外部工具

VLC Media Player 可以播放 Hap 和 Hap Q 文件，但不能播放 Hap Q Alpha 或 Hap R（截至 VLC 3.0.4）。

Hap Exporter for Adobe CC 2018 是一个允许进行 Hap 编码的插件，包括使用分块。

Jokyo Hap Encoder 一个适用于多种 Adobe 工具的高质量商业 Hap 编码器插件。

TouchDesigner 支持 HAP 并不需要 The QuickTime plugin，但它在 macOS 上测试时可能有用。

处理高分辨率或高帧率视频

当需要超高分辨率或高帧率视频时，Hap Q 是最佳的编解码器选择。不过视频必须正确编码，才能支持多线程 CPU 解码。这在 Hap 标准中称为「Chunked」编码。Movie File Out TOP 总是使用分块编码进行编码。使用最新版本的 FFmpeg 也可以进行分块编码，使用 -chunks 选项即可。例如：

 ffmpeg -i source.mov -c:v hap -format hap_q -chunks 12 dest.mov

每个分块都可以使用不同的 CPU 解码，因此分块数等于或大于系统 CPU 核心数（不含超线程核心）最好。分块数超过 CPU 核心数不应影响性能，但理想情况下分块数应保持在合理范围内。 TouchDesigner 编码时使用 12 个分块。

注意：QuickTime 插件不使用分块编码进行编码。

极端情况

对于极端分辨率的情况，启用任何 CPU 压缩都可能过重。可以在 TouchDesigner 中 Movie File Out TOP 的「Advanced」页上，在「Hap Secondary Compression」选项下关闭它。这样只会使用固定压缩比的纹理压缩写入帧。这避免了任何 CPU 解压，并且在 Movie File In TOP 上启用「High Performance Read」时还可以减少内存带宽占用。
