TouchDesigner 简介

Introduction

欢迎使用 TouchDesigner。安装好许可证、更新显卡驱动并首次打开程序后，你应该会看到类似这样的界面：


Interface Topography

我们首先来认识新工作区中的所有不同控制区域。先从整体的大项开始，慢慢深入到界面的较小元素。在默认工作区中，有八个需要了解的不同区域：

  • Menu Bar | 菜单栏包含程序中的所有常规菜单操作：保存和打开对话框、编辑元素、帮助等。这里也是切换 Cooking 开关以及 Realtime 处理开关的地方。
  • Pane Layout | 在 TouchDesigner 中，窗格相当于工作区布局。每个窗格都有多个视图和功能，让你可以同时查看网络的各个部分。这类似于许多 3D 渲染环境，让你在任何给定时间都能看到场景的多个视图。Layout 栏让你可以在不同布局之间快速切换（例如水平分割和垂直分割），也可以创建自己的自定义视图配置。
  • Pane Bar | Layout 栏帮助你确定窗口的配置，而各个窗格栏则让你为工作区做具体配置。
  • Palette Browser | Palette 浏览器在 TouchDesigner 中承担多种功能。首先，在这里可以找到多种工具和不同问题解决方案的示例。这里也是存放你在自己工作中开发的常用模块的地方。
  • Parameters Window | 操作符几乎所有的控制都可以在参数窗口中访问。这个窗口是你在工作中会不断使用的，稍后我们会讨论这个窗口的组织方式。
  • Network Editor | 在 TouchDesigner 中，你的程序和算法被组织成操作符网络。因此 Network Editor 是你进行大部分搭建工作的地方。我们可以把这个空间想象成一个类似桌面或画布的二维空间。
  • Time Attributes | 使用 time attributes 框，我们可以控制网络中时间运作方式的多个元素。这里可以设置以每秒帧数（FPS）表示的全局采样率，以及合成的长度（以帧为单位）。在某些场景中，时间对播放和编程非常重要；而在其他非线性应用中，你不太会去改动 Time Attributes 对话框。
  • Time Line | 除了在网络中设置一些时间属性外，我们还可以使用时间轴来控制线性序列行进的多个方面。这里你会看到播放和暂停按钮、由 + 和 - 号表示的逐帧前进和后退按钮，以及用于指定在时间轴中行进方向的箭头。


Operators - All in the Family

TouchDesigner 中信息的组织方式有很多，最直观的区别之一是操作符的类型。在 TouchDesigner 中，不同种类的操作按所属族分类。其核心实际上在于给定操作符中嵌入的数据种类。例如，想想盒式磁带和光盘的区别，显然不能用磁带播放器播放 CD。这部分是由于介质的性质，但也与用于存储信息的编码方式有关。磁带和光盘在处理信息的方式上根本不同 - 尽管两者都包含「声音」。


在 TouchDesigner 中，我们可以认为不同的族对其各自的数据有不同的组织系统。只要记住这一点，就很容易理解为什么不能直接把不同族连接在一起。为了在视觉上帮助我们，还可以看到不同族有各自关联的颜色：

COMPs | Components | Gray

  • Computed on both the GPU and CPU - depends on the COMP
  • 组件是高层操作符，常用于「容纳」其他网络。除了拥有自己的一组参数外，COMP 还可以包含完整的操作符网络。随着我们构建更复杂的项目，我们会很快依赖这些操作符，既为了组织清晰，也为了构建模块化、可复用的操作符网络。


TOPs | Texture Operators | Purple

  • Computed on the GPU
  • 纹理操作符处理像素信息。对你的显卡来说，纹理就是应用到一块 3D 几何上的东西。TouchDesigner 尽可能使用 GPU 来处理信息，正因如此，图像被视为供显卡渲染的场景。这就是为什么我们把照片和视频视为纹理 - 因为对我们的 GPU 来说，它们就是应用到几何上的纹理。

CHOPs | Channel Operators | Green

  • Computed on the CPU
  • 通道操作符是浮点数或整数的线性序列。它们通常表现为动画、信号、输入、曲线、波形或图形。音频作为浮点数的线性流，也被归入通道操作符族。CHOP 是你网络的神经系统。它们在项目中传递控制和逻辑信息，是驱动程序的关键部分。

SOPs | Surface Operators | Blue

  • Computed on the CPU
  • 表面操作符是 3D 几何片段。当我们想在 3D 空间中处理某些东西，或渲染物体时，通常会使用表面操作符。虽然我们可以做大量程序化表面建模，但必须注意我们的 SOP 是由 CPU 计算的。因此，如果你突然雄心勃勃地大量使用 SOP，很容易让系统慢如蜗牛。

MATs | Materials | Yellow

  • Computed on the GPU
  • 材质被应用到 3D 几何上。材质通过指定对象的颜色与纹理，以及灯光与它如何相互作用，来决定 3D 表面在渲染时的外观。

DATs | Data Operators | Pink

  • Computed on the CPU
  • 有些操作需要对文本、表格或其他类型的数据进行处理，为此我们有 DAT。我们也可以用 DAT 来编写操作序列的脚本，以及用于一些更高级的编程方法。


Connections

除了工作区本身，还有一些其他视觉线索，帮助我们一眼看出网络里正在发生什么。把网络连接在一起的关系有两类——连线和链接。它们以两种不同的视觉样式呈现，便于我们区分。


Links 链接在网络中以带移动箭头的虚线表示。链接在参数之间、以及网络中的不同操作符族之间建立连接。链接可以建立在同一操作符族的操作符之间，也可以建立在不同操作符族的操作符之间——不同操作符族之间的链接也称为引用或导出参数。



Wires 连线连接同一操作符族的操作符——TOP 到 TOP、CHOP 到 CHOP，等等。这类连接在操作符之间传递信息，从而形成程序化网络——一个算法运算的结果沿网络传给下一个操作符。连线有两种不同的视觉样式：移动与静止。这一差别很细微，但在网络中识别出它，能帮你更快、更高效地读懂程序。

移动的连线告诉你，信息正在从一个操作符主动传递给下一个。TouchDesigner 是基于拉取（pull）的编程环境。这意味着操作符只有在被网络中的另一个操作符请求时才会计算（处理信息）。移动的连线让我们一眼就能看出有东西正在计算。



如果移动的连线帮我们看出操作符正在沿网络拉取数据，那么静止的连线则帮我们看出信息何时没有在网络中主动流动。静止的连线外观是实心的。


Anatomy of an Operator

操作符是网络的积木，关于它们有很多东西要了解。我们先从操作符自身的构成看起，这样就能一眼看出它在告诉我们什么。之后我们会细看参数窗口，更好地理解我们能控制什么、以及如何操控这些积木。


Operator Name 在 TouchDesigner 中，每个操作符都可以有名字，而且在任何给定网络中，所有操作符的名字都应当唯一。这是什么意思，你为什么要在意？因为我们建立的关系既可以存在于同一操作符族的操作符之间，也可以存在于不同操作符族的操作符之间，所以需要唯一的名字才能构成特定的引用。如果你参与过的项目里有不止一个 Bob 或 Jennifer，你就知道起一个明确的名字有多重要——无论是在冗长的邮件往来中，还是在项目会议进行到一半时，你都能确切知道自己在跟谁说话。

另一个值得注意的重要特性是操作符名字的迭代编号。在下例中可以看到，操作符名字是「moviein2」——为什么是 2？这说明它是我添加到网络中的第二个 Movie In TOP。如果我再添加一个 Movie In TOP，它的默认名字会是「moviein3」。当我们开始搭建大型复杂网络时，这一点尤其有用。同样重要的是，我们可以获取操作符的名字，也可以只获取它末尾的数字。在下例中，操作符的名字是「moviein2」，它的数字是 2。后面我们会看到为什么这如此有用和重要，现在先把这个概念收进脑海的某个角落。



Operator Viewer 在 TouchDesigner 中你会遇到的最强大的元素之一就是操作符查看器。每个操作符都有查看器，你可以用它查看操作符的内容并与之交互。在我们这里的例子中，我们看的是一个香蕉的 png（嘿，Andy！）。在其他可视化编程环境里，我们可能只能看到一个文件路径，或一串字母，告诉你有一个可用的图像文件。在 TouchDesigner 里，我们实际上能看到文件的缩略图。当我们开始用不同的操作符处理图像时，也能立刻看到这些操作产生了什么效果。这意味着我们始终能实时看到网络中整条算法运算链的情况。这体现为可视化调试网络的能力。你可能会担心这会给最终程序带来多少计算负担，你想得没错，这种便利是有代价的。确实，渲染所有这些预览是有代价的——不过，代价只在你查看网络时产生。一旦你离开某个网络空间，或进入执行模式，TouchDesigner 就会停止渲染各个节点的预览。这意味着你有时可以两者兼得——既能获得看到程序每一步在发生什么的好处，又在你不再渲染编程环境时不必付出性能代价。



Connector Outputs 连接器的输入与输出，是你在同一操作符族内把信息从一个操作符传到另一个操作符的方式。在 TouchDesigner 中，输入和输出分别位于操作符的左侧和右侧。这与其他一些可视化编程环境不同，也意味着网络通常按从左到右的顺序读取其运算。有些操作符有多个输入并带有专门的功能——volume、reset 等等；另一些则允许大量输入堆叠（Merge CHOP 或 Composite TOP 就是很好的例子）。



Flags

在 TouchDesigner 中，标记用来指示操作符的状态。我们不仅可以用标记查看操作符的各种状态，还可以用它们来控制操作符。这听起来不错，但它到底意味着什么？在深入标记的作用之前，重要的是先了解标记有两种：通用标记与族专用标记。


Universal

通用标记存在于所有操作符上——而且在所有操作符上的位置都一样。这些标记既可以在可视化编程环境中访问，也可以用脚本命令访问。位于操作符左上角的通用标记有：

  • Viewer | 查看器标记用于开关查看器窗口。你可能某时会发现，不需要看到网络中算法链的每一个环节。你也可能想省回渲染预览所消耗的资源。这个标记就是帮你做到这一点的。
  • Clone Immune | 克隆构建是制作轻量、可复用网络组件的重要部分。克隆的核心是把 Base 或 Container 组件的内容复制到另一个组件中。不过，你有时可能希望复制每一个单独的操作符，但不复制该操作符的参数。克隆免疫标记就是用来解决这个问题的。
  • Bypass | 你肯定会在某个时刻问自己：「这个操作符到底在干什么？！」这种情况下，bypass 标记能帮上大忙。bypass 标记相当于一个直通开关。也就是说，当 bypass 开启时，选中的操作符对处理流没有影响——就像你在算法链中关掉了这个元素。当你关闭 bypass 时，选中的节点又重新对网络产生影响。
  • Lock | lock 标记是最不显眼却最强大的标记之一。lock 标记切换到开启位置时，会把该操作符的内容保存在项目文件中。这意味着该节点不再计算，其输入变化时也不会更新。起初这看起来没什么用，但它意味着你可以把原本难以获取的信息保存在程序化网络里。



Viewer Active 查看器激活标记也存在于每个操作符上，但它的位置不在左上角，而是在右下角。这个小小的加号形标记用于开关直接与操作符内容交互的能力。它让你能快速访问操作符中的多种信息、切换视图类型，在某些情况下还能改变观察角度（这对 Surface 操作符尤其重要）。



Family Specific 如我们所见，不同操作符族处理不同类型的信息，这也意味着我们有时需要为不同族提供不同的信息显示选项。族专用标记就是为此而设。在右下角查看器激活标记旁，你会找到各操作符族专用的标记。它们显示为小圆圈，按功能进行颜色编码。不妨去看一下 wiki 的 Flags 页面上所有标记类型。


Parameters

Anatomy of the Parameters Window

参数窗口是我们访问给定操作符所有控制功能的地方。在这里你可以改变网络中某个元素的工作方式、在操作符之间建立关系等等。不过，为了充分利用操作符的功能，参数窗口有几个重要特性我们需要了解。


Names

操作符的名字总是位于窗口最上方。你会注意到我说的是「名字」（复数），不是「名字」（单数）。这是怎么回事？任何操作符都有两个与之关联的名字——操作符的类型名，以及你（程序员）给该操作符起的名字。在下例中可以看到这是一个 Movie In TOP（我从它的紫色知道它是 TOP）。我还能看到这个操作符名叫「moviein2」——它显示在操作符类型名旁边。你为什么要在意这个？原因很多。网络越大，用便于建立引用的方式给操作符命名就越重要。例如，你可能在某个网络中使用一系列 Composite TOP。当你终于准备把视频输出到显示器时，如果你依赖 TouchDesigner 的默认命名，你就得突然回忆起你要用的是「composite4」、「composite8」，甚至可能是「composite11」。相反，如果你直接把它命名为「finalComp」，就更容易记住自己引用的是哪个操作符。假设你给所有操作符都起了描述性的名字，当你把网络交给另一个程序员（或者三个月后回来看自己的作品），如果你想看清网络里用了哪些操作符，描述性名字可能帮不上忙。这就是为什么在参数窗口顶行同时显示操作符类型名和它的描述性名字如此有用。



Help and Info

参数窗口的下一行有许多有用的东西。从左到右依次是：

  • Help | 第一个帮助按钮会带你到为该操作符建立的 wiki 页面。在那里你可以找到该操作符功能的简短说明，以及该操作符所有参数控制内容的说明。
  • Python Help | Python 3 是 TouchDesigner 选用的脚本语言，Python Help 按钮会带你到该操作符对应的 Class 页面。在那里你可以找到关于该操作符脚本编写和引用的信息。你使用 TouchDesigner 越多，就越会发现有理由用脚本解决问题。刚开始学的时候，你不需要懂任何 Python 就能上手工作，但当你准备做更复杂的操作时，Python Help 按钮就变得非常宝贵。
  • Info | Info 按钮会显示操作符的各种有用信息——包括它的计算时间（处理需要多久）、内存占用（如果它是 TOP，还会告诉你它的 GPU 内存占用），以及更多更多。
  • Comment | 给 TouchDesigner 网络添加注释有很多方式，操作符的 comment 功能就是其中之一。在这里你可以留下关于某个操作符在做什么的简短注释。这里留下的注释会显示在 Info 窗口中。
  • Copied Values | 复制值按钮会显示操作符之间的连接。我们可以设想这样一种情形：我们希望一个 TOP 的分辨率改变时，自动改变另一个 TOP 的分辨率，而不是全部手动完成。在操作符之间复制参数时，这个按钮能帮我们快速看出这些连接存在于哪里（哪个操作符、哪个参数）。
  • Scripting Language | TouchDesigner 有两种脚本语言——Python 和 TScript。虽然 Python 现在是默认脚本语言，但仍有大量用户使用 TScript，也有很多用 TScript 解决问题的好方法。如果你需要更改某个节点的脚本方式，这个按钮就是在两种语言之间切换的地方。
  • Expand / Collapse Parameters | TouchDesigner 中的每个参数都可脚本化。这意味着你能用滑块或参数字段控制的任何东西，都能用脚本或另一个操作符来控制。这也是 TouchDesigner 如此强大灵活的原因之一。既然如此，你有时会想展开所有参数的脚本区域。全部展开按钮就是做这个的。同样，它也会折叠所有参数，让你的编程空间更整洁一些。
  • Non-Default Parameters | 非默认参数开关是你新的好朋友。当你看别人的作品，甚至看自己的作品时，很容易搞不清哪些是默认设置、哪些是程序员改过的。这个开关只显示已更改 / 非默认的参数。如果你不确定某个操作符里改了什么，这个开关能让你一眼看清情况。



Pages

任何操作符可能只有少量参数，也可能多到一屏放不下。正因如此，它们常被划分到与其功能相关的页中。你可能会看到某份文档、wiki 的某部分或论坛讨论提到某个参数页。当你看到这样的说法时，就应该到这里来找。



Parameters

最后我们来到参数窗口中做所有精彩工作的部分。这里你能找到某个操作符的全部控制元素。使用这些值时，有一个重要的考虑：它们有多种不同的类型——有些可以更改，有些不能。例如，在下面的 Movie In TOP 中可以看到，Cue Point 参数被设为视频的 %。这个归一化值的运作前提是，你愿意用 0-100% 来考虑影片的时长。话虽如此，你可以把这个特定参数改为 Index、Frames、Seconds 或 Fraction。使用参数是使用 TouchDesigner 的基本功，所以不要害怕花些时间试验某个参数，弄清楚它在为你做什么。
