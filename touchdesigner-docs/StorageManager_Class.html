StorageManager 类

StorageManager 是一个 Python 工具类，旨在让 Storage 在 Python Extensions 中易于使用。它还为创建 Python 属性和可靠集合提供了许多有用的功能。尽管 StorageManager 会执行一些复杂的 Python 任务，但在扩展中使用它很简单，本文会让你掌握它的实际用法。全文假设读者具备中级 Python 水平。

提示： 如果你想使用 StorageManager 的属性和可靠性功能，但不需要把值保留在 Storage 中（在保存之间、扩展初始化之间），可以考虑使用 TDFunctions 中的 createProperty 函数。

For technical class details see TDStoreTools

把 StorageManager 加入扩展

StorageManager 用于 Python extensions。把它加入扩展的常用方式如下：

from TDStoreTools import StorageManager

class ExampleExt:
	def __init__(self, ownerComp):
		# 此扩展所附加到的组件
		self.ownerComp = ownerComp

		storedItems = [
			# 已存储项列表放在这里
		]
		self.stored = StorageManager(self, ownerComp, storedItems)

注意顶部的 import 语句导入了 StorageManager。然后在 __init__ 方法中创建了一个 storedItems 列表。该列表包含关于每个待存储条目的信息字典。接着我们把扩展（self）、其 storage 将被使用的组件（ownerComp）以及 storedItems 列表传给 StorageManager 类构造函数。

存储条目列表

使用 StorageManager 时，你最重要的工作是设置 stored items list。列表中的每一项都包含一个 item dictionary，带有关于待存储条目的信息。每个条目的字典中可定义五个键：

  • name - 待存储条目的名称。这是唯一必需的键。如果为小写，该存储值的 property 将不是 promoted。
  • default - 待存储条目的默认值。如果未提供，将使用 None。
  • property - 如果为 True，会创建一个关联属性来访问该值。详见下文。默认为 True。
  • readOnly - 如果为 True，创建的属性将是只读值。若 property 键为 false 则无效。默认为 False。
  • dependable - 如果为 True，当值为容器时将是 deeply dependable。非容器值始终是 dependable，此项对其无效。默认为 False。

此列表中定义的条目会在组件的 Storage 字典中创建，因此保存 .toe 时会保存到磁盘。扩展重新初始化时，它们的值也会保留。在详细介绍每个字典属性之前，先看几个示例条目字典：

{'name': 'Value0'}
# 一个名为 "Value0" 的存储值。其他字典键将使用默认值，
# 因此它完全等价于：
{'name': 'Value0', 'default': None, 'property': True, 'readOnly': False, 'dependable': False}

{'name': 'value0', 'default': 23}
# 一个与上面的 "Value0" 类似的存储值，但它不会被提升，
# 其初始值为 23。

{'name': 'ValueList', 'default': [1, 8, 42], 'dependable': True}
# 一个存储的、可深度依赖的列表，初始内容为 [1, 8, 42]

{'name': 'ID', 'readOnly': True}
# 一个名为 "ID" 的存储值，其被提升的属性为只读。

{'name': 'Internal', 'property': False}
# 一个名为 "Internal" 的存储值，无法通过属性访问，
# 只能通过 Component 存储或 StorageManager 对象访问。

访问已存储的条目

访问 StorageManager 存储的条目有多种方式，取决于条目在存储条目列表中的设置方式。以下示例假设你的扩展设置如下：

from TDStoreTools import StorageManager

class ExampleExt:
	def __init__(self, ownerComp):
		# 此扩展所附加到的组件
		self.ownerComp = ownerComp

		storedItems = [
			{'name': 'value0'},
			{'name': 'Value1', 'default':0},
			{'name': 'ID', 'readOnly': True},
			{'name': 'Internal', 'property': False}
		]
		self.stored = StorageManager(self, ownerComp, storedItems)

通过 StorageManager 对象访问

所有已存储条目都可以通过 StorageManager 对象本身访问，它的行为类似以条目名称为键的字典。例如，下面这个函数可以在 ExampleExt 中运行，打印并递增 Value1：

	def changeValue(self):
		print(self.stored['Value1'])
		self.stored['Value1'] += 1

无论条目是否定义为只读，或是否有关联属性，都可以用这种方式读写。

通过属性访问

如果某个存储条目有关联属性，可以更直接地访问。存储条目的属性与条目同名，所以沿用上面的示例，Value1 也可以这样访问：

	def changeValue(self):
		print(self.Value1)
		self.Value1 += 1

如果存储条目设置为 read only，则无法通过其属性修改。回看上面的扩展定义，注意 ID 存储值设为只读。这意味着你可以这样做

print(self.ID)

但

self.ID = 5

会导致错误。如果要修改 ID，应这样做：

self.stored['ID'] = 5

如果你的扩展是 promoted，任何以大写字母开头的成员或方法都可以通过其所附着的组件直接访问。属性也是如此，所以如果 ExampleExt 在 root 中名为「exampleComp」的组件上被 promoted，你可以这样做：

op('/exampleComp').Value1 = 12

注意： 在我们的示例扩展中，这种访问方式对 value0 无效，因为它是小写；对 ID 无效，因为它是只读；对 Internal 无效，因为它没有关联属性。

StorageManager 的限制

只有 Python 能保存的对象才能用 StorageManager 存储。这包括大多数内置 Python 对象，但不包括许多 TouchDesigner 对象，尤其是 Operator。如果想存储 Operator，最简单的方法是改存其 path。尝试存储不允许的对象会报错。
