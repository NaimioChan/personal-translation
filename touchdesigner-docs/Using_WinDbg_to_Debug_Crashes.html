用 WinDbg 调试崩溃

概述

如果 TouchDesigner 在系统上无法启动，但没有创建 .dmp 文件或提供其他信息，或者运行一段时间后崩溃且没有 .dmp 文件，可能需要更深入的分析来找到解决方案。这可以使用 Microsoft 提供的 'WinDbg Preview' 工具完成。

请参阅 Troubleshooting in TouchDesigner。

下载 WinDbg

可以按照 this link 从 Microsoft App 商店下载 WinDbg。

调试启动崩溃

启动 WinDbg Preview。在 'File' 菜单中选择 'Launch Executable'，然后选择 TouchDesigner.exe。它通常位于 C:/Program Files/Derivative/TouchDesigner/bin/TouchDesigner.exe。这会使 TouchDesigner 启动。启动很可能很快在断点处停下，Command 窗口中会显示类似 'Break instruction exception - code 80000003 (first chance) ntdll!LdrpDoDebuggerBreak+0x30:' 的内容。按左上角的 'Go' 按钮（播放符号）继续执行。你可能需要按几次 Go 来跳过一些断点。最终你会到达 TouchDesigner 启动失败的位置。出现这种情况时，你可以将 'Logs' 和 'Command' 窗口中的文本发布给你的支持团队联系人。

调试不产生 .dmp 文件的崩溃

如果你的项目随机崩溃，但崩溃时不会创建 .dmp 文件（例如只是消失），你可以使用 Windbg 为这些情况创建 .dmp 文件。打开你的项目，然后打开 windbg。在 Windbg 的 File 菜单中，选择 'Attach to a Process' 并选择 TouchDesigner.exe。然后让项目运行直到崩溃发生，并在崩溃时保存 .dmp 文件。

保存 .dmp 文件

如果日志提供的信息不够，那么保存 .dmp 文件会提供更多信息来帮助我们诊断问题。在 'Command' 窗口中可以使用命令 

 .dump /mf C:/SomeFolder/Output.dmp

来创建 .dmp 文件。你需要创建输出文件夹。此文件会相当大，所以请将其打包成 .zip 并发送链接给我们。务必包含创建 .dmp 所用的 TouchDesigner 版本号，因为我们需要将其与我们的备份完全匹配才能诊断 .dmp。
