Video Device In TOP

摘要

Video Device In TOP 可用于从连接到系统的外部摄像机、采集卡、采集加密狗、IP 摄像机或视频解码器采集视频。通过使用多个 Device In TOP，多个设备可以同时将视频流式传输到 TouchDesigner。HD-SDI 视频可以通过采集卡（例如来自 Blackmagic Design、AJA 和 Deltacast 的采集卡）流式传输到 TouchDesigner。

如果设备似乎没有提供视频流，但在 Cameras 参数菜单中可见，请确保当前没有其他应用正在使用该设备。

提示：创建一个 Info DAT 并将其指向 Video Device In TOP，以查看当前连接的设备。Info CHOP 提供用于分析 Video Device In 和 Out TOP 性能的数据。此外，Info CHOP 可用于获取某些设备源信号中嵌入的时间码，如下表所示。

目前支持的主要采集设备厂商：

  • Blackmagic Design - 支持 Timecode。Windows 和 macOS。
  • AJA - 支持 Timecode。仅 Windows 与 macOS。
  • Deltacast - 支持 Timecode。仅 Windows。
  • Bluefish444 - 支持 Timecode。仅 Windows。

此外，Datapath SDI、Allied Vision、Imaging Development Systems (IDS)、FLIR/Point Grey 和 Ximea 的一些型号也通过原生驱动得到支持。

AJA 和 Blackmagic Design 设备支持 12 位输入和输出格式，包括 AJA 能够以完整的 12 位 RGB 4:4:4 进行采集。

关于 Magewell HDMI 转 USB3 采集（强烈推荐，无需驱动，即插即用），请参阅 Magewell。

IP Cameras and USB3 包括以下型号：

  • Allied Vision - 仅 PvAPI SDK 型号，不支持 Vimba SDK。Prosilica 系列和 Manta 摄像机。仅 Windows。
  • Point Grey FLIR Flycapture2 and Spinnaker - 仅 Windows。
  • Imaging Development Systems (IDS) - TouchDesigner 实现了 uEye IDS Software Suite 和 'Peak' 两种 SDK。目前不支持 GigE Vision 摄像机。
  • Ximea - 仅 Windows。

每个厂商只有一小部分摄像机在内部测试过，不过预期受支持厂商的任何现代摄像机都应可用。如果遇到任何问题，请联系 support@derivative.ca。

另请参阅 Video Device Out TOP。

Deinterlace deinterlace - 设置要显示哪些场。
  • Off off - 将整个帧作为一张图像显示，不做任何去隔行处理。
  • Even even - 仅显示偶数场。第 1 行是帧的顶行。这将显示第 2、4、6、8 等行，从顶行下方第二行开始，到最底行结束。
  • Odd odd - 仅显示奇数场。第 1 行是帧的顶行，因此这将显示第 1、3、5、7 等行，从最顶行开始。
  • Bob (Split) bob - 交替显示偶数场和奇数场，从而实现两倍的帧率并消除隔行伪影。先显示哪个场由 'Field Precedence' 参数控制。
Field Precedence precedence - 使用 Bob (Split) 去隔行时，此参数选择每帧先显示哪个场。
  • Even even - 先显示偶数行，再显示奇数行。第 1 行是帧的顶行。这将先显示第 2、4、6、8 等行，下一次计算时显示第 1、3、5、7 等行。
  • Odd odd - 先显示奇数行，再显示偶数行。第 1 行是帧的顶行。这将先显示第 1、3、5、7 等行，下一次计算时显示第 2、4、6、8 等行。

Signal Format signalformat - 采集输入的信号格式。这包括分辨率和帧率，以及帧是逐行还是隔行。请注意，使用隔行格式时，速率指的是每秒场数。
Quad Link quadlink - 用于支持四链路格式的卡。四链路本质上是接收 4 个输入并从中创建一个更大的单一输入，例如 4 个 1080p 输入变成单个 4K 输入。

Input Color Space inputcolorspace - - 控制输入数据将被视为哪种色彩空间。上传到 GPU 时，它会被转换为工作 Color Space。
  • Automatic automatic - 根据输入可用的色彩空间元数据，自动尝试确定输入的色彩空间（如果有）。如果无法确定色彩空间，则假定为 sRGB。
  • sRGB srgb - sRGB 色彩空间，使用 sRGB 传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • sRGB - Linear srgblinear - sRGB 色彩空间，使用线性传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.601 (NTSC) rec601ntsc - Rec.601，NTSC 原色色彩空间，使用 Rec.601 传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.709 rec709 - Rec.709 色彩空间，使用 Rec.709（与 Rec.2020 相同）传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.2020 rec2020 - Rec.2020 色彩空间，使用 Rec.2020（与 Rec.709 相同）传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Rec.2020 ST2084PQ rec2020st2084pq - Rec.2020 色彩空间，使用 Perceptual Quantizer 传递函数。相对于 Reference White 被视为 HDR 色彩空间。
  • Rec.2020 HLG rec2020hlg - Rec.2020 色彩空间，使用 Hybrid Log Gamma 传递函数。相对于 Reference White 被视为 HDR 色彩空间。
  • DCI-P3 dcip3 - DCI-P3 色彩空间，D65 白点，2.6 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • DCI-P3 (D60) dcip3d60 - DCI-P3 "D60 sim" 色彩空间，D60 白点，2.6 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Display-P3 (D65) displayp3d65 - Display-P3 色彩空间，D65 白点，sRGB gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Display-P3 (D65) - Linear displayp3d65linear - Display-P3 色彩空间，具有 D65 白点和线性传递函数。相对于 Reference White 被视为 HDR 色彩空间。
  • ACES2065-1 aces2065-1 - ACES 2065-1（也称为 ACES AP0）色彩空间，线性 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • ACEScg acescg - ACEScg（也称为 ACES AP1）色彩空间，线性 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • ACESproxy acesproxy - ACESproxy 色彩空间，具有对数传递函数。相对于 Reference White 被视为 HDR 色彩空间。
  • Passthrough passthrough - 选中后，颜色值将按原样用于运算，不作任何修改，也不尝试将其转换到 Working Color Space。
Input Reference White inputreferencewhite - - 在把输入颜色值转换到工作色彩空间时，控制相对于 Reference White 应如何处理它们。如果工作色彩空间是相同的 Reference White，则不做调整。如果不同，颜色的 Reference White 水平（亮度）会被调整到工作色彩空间期望的范围。例如，如果项目设置的 SDR Reference White 为 120 nits，而 HDR Reference White 为 80 nits，那么 SDR 色彩空间中的颜色 (1, 1, 1)（即 120 nits）将被转换为 (1.5, 1.5, 1.5)，在 HDR 工作色彩空间中仍为 120 nits。
  • Default For Color Space default - 根据检测到/选择的色彩空间，使用 SDR 或 HDR Reference White。
  • Standard (SDR) sdr - 将其参考白值按 SDR 处理输入色彩空间。
  • High (HDR) hdr - 将其参考白值按 HDR 处理输入色彩空间。
Transfer Mode transfermode - 控制帧如何从输入设备传输到 CPU 内存，以及如何从 CPU 内存传输到 GPU。
  • Automatic automatic - 为计算机上安装的组件选择最佳传输模式。通常为 'Pre-Upload'。
  • Pre-Upload preupload - 帧到达后即上传到 GPU。这确保 GPU 想要处理时数据已在 GPU 内存中。
  • On-Demand ondemand - 仅当 TOP 在该次计算中要显示帧时才上传到 GPU。在 TOP 显示的帧数少于输入设备采集的帧数时，这可减少 GPU 与 CPU 内存之间的 PCIe 带宽。但这意味着 GPU 可能会因等待该帧上传而停顿。
  • On-Demand, Sync to Frame Input ondemandsync - 此模式目前仅适用于 AJA 设备。这会使整个 TouchDesigner 进程停顿，直到该输入上有一帧到达之后。然后进程将开始执行，并将该输入帧用于此节点的计算。这消除了采集输入的任何延迟，但可能导致性能变差。应关闭 UI 顶部 TouchDesigner 进程的 Real-time，且单个进程中只应有一个节点设为该模式。
Memory Mode memorymode - 控制用于在采集卡和 GPU 之间传输数据的内存类型。
  • Automatic automatic - 为传输选择最佳内存模式。对于支持它的采集卡为 'Pinned'，否则为 'Regular'。
  • Pinned pinned - 固定（Pinned）内存允许数据以 2 次复制而非 3 次传输。采集→固定 CPU 内存，固定 CPU 内存→GPU 内存。
  • Regular regular - 常规内存模式意味着需要 3 次复制。采集→采集可写内存，采集可写内存→GPU 可读内存，GPU 可读内存→GPU 内存。
Sync Inputs syncinputs - 启用多个 Video Device In TOP 的同步。同步使单个系统上使用多个输入和采集卡的多个节点能够确保输出帧同步。不启用时，每个节点将自由运行，由于内部排队，可能输出到达时间不同的帧。输入源必须进行 GenLock 锁定，以确保所有数据同时到达所有输入，否则同步将不起作用。此功能目前支持 Blackmagic、DataPath、Deltacast 和 BlueFish 设备。
Sync Group Index syncgroupindex - 一个 .toe 文件中可以有多个活动的同步组。节点只会与属于同一同步组的其他节点同步。
Max Sync Offset (ms) maxsyncoffset - 以毫秒为单位指定。两张图像到达时间的最大差异，在此范围内视为同步。到达时间差异大于此偏移的图像将被视为属于不同的「帧」。
Sync Timeout (ms) synctimeout - 在放弃同步尝试之前，等待同步组中所有帧变为可用的时间。以毫秒表示。如果在等待同步组中一个或多个源的帧时超时，同步组中的所有节点将保留当前图像而不输出新图像，即使某些输入上已有新图像到达。
Reset Stats resetstats - 一个脉冲，用于重置所附加 Info CHOP 中的统计数据。

  • 16-bit float (A) a16float - 仅 Alpha 的格式，每通道 16 位，每像素 16 位。
  • 32-bit float (A) a32float - 仅 Alpha 的格式，每通道 32 位，每像素 32 位。
  • 8-bit fixed (Mono+Alpha) monoalpha8fixed - 2 通道格式，一个值用于 RGB，一个值用于 Alpha。每通道 8 位，每像素 16 位。
  • 16-bit fixed (Mono+Alpha) monoalpha16fixed - 2 通道格式，一个值用于 RGB，一个值用于 Alpha。每通道 16 位，每像素 32 位。
  • 16-bit float (Mono+Alpha) monoalpha16float - 2 通道格式，一个值用于 RGB，一个值用于 Alpha。每通道 16 位，每像素 32 位。
  • 32-bit float (Mono+Alpha) monoalpha32float - 2 通道格式，一个值用于 RGB，一个值用于 Alpha。每通道 32 位，每像素 64 位。
Parameter Color Space parmcolorspace - - 控制如何解释此节点上的所有颜色参数。仅在项目启用了 Working Color Space 时可用。颜色值被视为处于所选色彩空间中，并在作为节点运算的一部分使用之前转换为 Working Color Space。注意这不会改变节点自身的色彩空间，因为它始终处于 Working Color Space。
  • sRGB srgb - sRGB 色彩空间，使用 sRGB 传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • sRGB - Linear srgblinear - sRGB 色彩空间，使用线性传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.601 (NTSC) rec601ntsc - Rec.601，NTSC 原色色彩空间，使用 Rec.601 传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.709 rec709 - Rec.709 色彩空间，使用 Rec.709（与 Rec.2020 相同）传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.2020 rec2020 - Rec.2020 色彩空间，使用 Rec.2020（与 Rec.709 相同）传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • DCI-P3 dcip3 - DCI-P3 色彩空间，D65 白点，2.6 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • DCI-P3 (D60) dcip3d60 - DCI-P3 "D60 sim" 色彩空间，D60 白点，2.6 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Display-P3 (D65) displayp3d65 - Display-P3 色彩空间，D65 白点，sRGB gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • ACES2065-1 aces2065-1 - ACES 2065-1（也称为 ACES AP0）色彩空间，线性 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • ACEScg acescg - ACEScg（也称为 ACES AP1）色彩空间，线性 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Passthrough passthrough - 选中后，颜色值将按原样用于运算，不作任何修改，也不尝试将其转换到 Working Color Space。
Parameter Reference White parmreferencewhite - - 在将参数颜色值转换为 Working Color Space 时，此项控制相对于 Reference White 应如何处理。如果 Working Color Space 的 Reference White 相同，则不做调整。如果不同，则此颜色的 Reference White 级别（亮度）将被调整到 Working Color Space 所期望的范围。例如，如果项目将 SDR Reference White 设为 120 nits，而 HDR Reference White 为 80 nits，那么 (1, 1, 1) 的颜色在 SDR 色彩空间中为 120 nits，将被转换为 (1.5, 1.5, 1.5)，在 HDR Working Color Space 中仍为 120 nits。
  • Default For Color Space default - 将根据所选的色彩空间使用 SDR 或 HDR Reference White。
  • Use Parent Panel useparent - 将使用父级面板所选的 Reference White。如果顶层面板也选择了「Use Parent」，则将使用「UI Reference White」。
  • Standard (SDR) sdr - 会将 Parameter Color Space 的 Reference White 值按 SDR 处理。
  • High (HDR) hdr - 会将 Parameter Color Space 的 Reference White 值按 HDR 处理。
  • UI ui - 会将 Parameter Color Space 的 Reference White 值按 UI 处理。其亮度使用「UI Reference White Nits」的值。

Info CHOP 通道

Video Device In TOP 的额外信息可以通过 Info CHOP 访问。

Video Device In TOP 特定的 Info 通道

  • connected - 若节点成功连接到设备则为 1，否则为 0。这并不一定意味着设备有有效的输入。
  • sync_timeouts - 使用 'Sync Group' 功能时，统计该组在超时时间内有多少次未能全部提供时间戳足够接近的帧。
  • last_sync_wait - 从节点准备好接收新帧，到所有输入都提供可用于同步输出的有效帧，节点等待了多长时间。
  • odd_field - 对隔行输入进行去隔行时，显示奇场期间该值为 1，显示偶场期间为 0。
  • capture_fps - 设备正在采集的帧率计算值。它 not 直接对应信号格式帧率。例如它不会显示 59.97。这只是统计最近 1000ms 内采集了多少帧。
  • capture_total - 自本次采集开始以来采集的帧总数。
  • frames_repeated - 节点重复显示同一帧的次数。目前它不会修正那些本就预期的重复，例如采集 30hz 信号而 TouchDesigner 以 60fps 运行的情况。此时该通道会持续增长，因为每个采集到的帧都会被显示两次。
  • frames_dropped - 统计采集卡采到、但从未被 TouchDesigner 的读取线程消费的帧数。当采集速度快于 TouchDesigner 消费帧的速度时会出现这种情况。
  • frames_skipped - 统计已被 TouchDesigner 的读取线程消费、但从未被节点本身消费的帧数。当 TouchDesigner 未以完整帧率运行时可能出现这种情况。
  • connection_changes - 统计连接变化次数，并非所有设备都支持。
  • temperature - 在支持的设备上，输出设备的温度（摄氏度）。对于不支持此功能的设备，将是一个很大的负数。
  • signal_fps - 输入信号的实际信号格式 FPS。未知时为 0。
  • rgb_input - 若检测到输入为 RGB（例如 RGB 4:4:4）格式则为 1。若为基于 YUV/YCbCr 的格式则为 0。-1 表示未知或该库不支持。
  • frame_queue_length - 在 TouchDesigner 内部排队的已接收帧数。
  • frame_hw_queue_length - 设备上仍在排队、TouchDesigner 尚未读取的帧数。
  • last_dma_copy_time - 把上一帧从设备复制到 CPU 所花的时间，单位为毫秒。-1 表示未测量此项。
  • frame_timestamp - 最后显示帧的时间（秒）。如果设备为该帧提供了带标记的帧时间，则为该值。否则将是根据任意时钟（例如设备的内部时钟，或设备使用的 PTP）采集图像的时间。-1 表示设备未提供此信息。

TOP 通用信息通道

  • resx - TOP 的水平分辨率，以像素为单位。
  • resy - TOP 的垂直分辨率，以像素为单位。
  • aspectx - TOP 的水平宽高比。
  • aspecty - TOP 的垂直宽高比。
  • depth - 如果此 TOP 包含 2D 或 3D 纹理数组，则为该 2D 或 3D 数组的深度。
  • gpu_memory_used - 此 TOP 使用的纹理内存总量。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
