Write a GLSL TOP

概述

官方 GLSL 文档可在 this address. 找到

TouchDesigner 主要支持的 GLSL 版本为 4.60。由于切换到 Vulkan，对 GLSL 3.30 及更早版本的支持已被移除。不过，为 3.30 编写的着色器在面向更新的 GLSL 时应该能正常工作。

为 GLSL TOP 编写的着色器通常是一种基于图像的操作。它基本不做任何基于几何的工作。对于熟悉编写 3D GLSL 着色器的用户来说，GLSL TOP 就是应用在单个四边形上的着色器，该四边形被绘制以覆盖整个视口（也称为全屏对齐四边形）。 为简化主题，本指南会避开 3D 渲染带来的额外复杂性，仅在 2D 世界中介绍编写 GLSL 着色器这一主题，只处理像素。

GLSL TOP 中的着色器代码会针对每个要输出的像素运行一次。着色器编写者的工作是：

  • 对输入的像素进行采样（如果有的话）。
  • 执行所需的数学运算来生成像素颜色。
  • 输出像素颜色。

概念

Output Swizzle

为确保 Windows 与 macOS 之间的跨平台支持，写入纹理的任何颜色都应先经过 vec4 TDOutputSwizzle(vec4)。该函数会根据目标纹理格式，确保正确的通道进入正确的输出通道。例如，纯 alpha 纹理实际上并不存在，而是以纯红色纹理存储。采样时会对输出自动应用 swizzle（0, 0, 0, R）。这种情况下，vec4 TDOutputSwizzle() 会把 alpha 值放入输出的红色通道。当该纹理在其他地方使用时，借助前面提到的 swizzle，该值会正确出现在「alpha」通道中。

输出颜色

像素着色器

通常，你只需要一个像素着色器就能创建可用的 GLSL TOP。

一个简单的入门着色器就是把每个像素都设为红色。 

layout(location = 0) out vec4 fragColor;
void main()
{
   vec4 color = vec4(1.0, 0.0, 0.0, 1.0);
   fragColor = TDOutputSwizzle(color);
}

只需将此代码放入 DAT，并将 GLSL TOP 的 Pixel Shader 参数设为该 DAT。

注意，fragColor 由着色器编写者定义为输出颜色的位置。这与 GLSL 1.20 中不同，那里使用的是内置变量 gl_FragColor。

计算着色器

对于计算着色器，输出纹理会为你定义好，不要在你的着色器代码中定义它。

你应使用这些函数读写纹理。uvec3 版本是为了方便而提供，其行为与 ivec3 版本相同。如果输出纹理的维度不需要 3 个坐标，则多余的坐标会被忽略。这与 2025.30000 系列版本之前的工作流程不同，那时使用 sTDComputeOutputs。之所以改变，是因为读写 sRGB 编码的纹理需要配合 imageStore()/imageLoad() 进行特殊处理，而这些函数会为你自动处理。 在使用这些函数之前，你也 ***不需要*** 对颜色应用 TDOutputSwizzle()，它会在内部自动为你应用。 这些函数还会为你做范围检查，确保超出范围的坐标被送入 imageStore/imageLoad。 尽管 GLSL 声明这些函数对越界访问是安全的，但 Vulkan 并非如此，因此需要做范围检查以保证安全。 

void TDImageStoreOutput(uint index, ivec3 coord, vec4 color);
void TDImageStoreOutput(uint index, uvec3 coord, vec4 color);
vec4 TDImageLoadOutput(uint index, ivec3 coord);
vec4 TDImageLoadOutput(uint index, uvec3 coord);

要写入输出，请使用 GLSL 函数 TDImageStoreOutput() 

void main()
{
   vec4 color = vec4(1, 0, 0, 1);
   TDImageStoreOutput(0, ivec3(gl_GlobalInvocationID.xy, 0), color);
}

采样输入

接下来你可能想做的是采样输入 TOP 的像素。下面这行使用 texture() 函数采样一个输入 TOP： 

vec4 inputColor = texture(sTD2DInputs[0], vUV.st);

像素着色器

默认情况下，像素着色器中会为你声明并设置输入变量 vUV，其中包含该像素的纹理坐标。只有在你没有提供顶点着色器时才会给出该变量。如果你提供了自己的顶点着色器，那么把纹理坐标传递到像素着色器就由你负责。这些值会在整个 2D 图像上平滑插值，因此当你绘制中间像素时，vUV.st 的值为（0.5, 0.5）。输入采样器变量会以数组形式为你声明。采样器按其维度（2D、3D、2DArray、Cube）划分。指向包含第一个 2D 纹理的 TOP 的采样器为 sTD2DInputs[0]。类似地，第二个 2D 输入称为 sTD2DInputs[1]，依此类推，适用于任意数量的 2D 输入（GLSL Multi TOP 的输入数量不限，但你的显卡在着色器中可使用的纹理数量是有限的）。

代码行 texture(sTD2DInputs[0], vUV.st) 在纹理坐标 vUV.st 处采样纹理 sTD2DInputs[0]。由于 vUV.st 对每个像素都会变化，因此每次都会从输入中采样不同的像素。

要可视化 vUV.st 的值，可以尝试将此着色器放入 GLSL TOP。 

layout(location = 0) out vec4 fragColor;
void main()
{
   fragColor = vec4(vUV.s, vUV.t, 0.0, 1.0);
}

计算着色器

计算着色器可以像像素着色器一样，使用相同的 texture() 函数采样输入。但它没有可用的 vUV 坐标，因此需要利用 gl_GlobalInvocationID 和输入纹理分辨率（可在其 TDTexInfo 结构中获取）手动计算坐标。也可以使用 texelFetch，它访问范围为 [0, width - 1] 和 [0, height - 1] 的整数纹理坐标。

采样器

采样器是 GLSL 中对纹理的称呼。采样器以数组形式提供给 GLSL 程序，按纹理的维度（2D、3D、2DArray、Cube 等）划分。你可以使用以下常量了解每种类型有多少个连接到了该 TOP： 

TD_NUM_2D_INPUTS
TD_NUM_3D_INPUTS
TD_NUM_2D_ARRAY_INPUTS
TD_NUM_CUBE_INPUTS

如果你改变了连接到 GLSL TOP 的输入数量或类型，着色器会重新编译，上面的 define 和下面的数组都会使用新值。无论 TOP 连接到哪个输入，它都会按维度归并到相应的采样器数组中。数组定义如下（你无需在着色器中声明它们）： 

uniform sampler2D sTD2DInputs[TD_NUM_2D_INPUTS];
uniform sampler3D sTD3DInputs[TD_NUM_3D_INPUTS];
uniform sampler2DArray sTD2DArrayInputs[TD_NUM_2D_ARRAY_INPUTS];
uniform samplerCube sTDCubeInputs[TD_NUM_CUBE_INPUTS];

例如，假设你的 GLSL TOP 按此顺序连接了 5 个输入：2D TOP、3D TOP、2D TOP、Cube TOP、2D Array TOP。那么 

TD_NUM_2D_INPUTS = 2
TD_NUM_3D_INPUTS = 1
TD_NUM_2D_ARRAY_INPUTS = 1
TD_NUM_CUBE_INPUTS = 1

你可以像这样引用你的输入： 

texture(sTD2DInputs[0], vUV.st); // 第一个 2D 输入
texture(sTD2DInputs[1], vUV.st); // 第二个 2D 输入，但不是连接到该 TOP 的第二个输入
texture(sTD3DInputs[0], vUV.stp); // 第一个 3D 输入
texture(sTDCubeInputs[0], vUV.stp); // 第一个立方体输入
texture(sTD2DArrayInputs[0], vUV.stp); // 第一个 2D 数组输入

非动态 uniform 的采样器访问

默认情况下，访问采样器数组（或图像输出）必须使用所谓的 dynamically uniform expression。这基本上意味着数组索引应为编译期常量、编译器在编译时可化简为常量的值，或前文链接文章中列出的其他少数着色器输入。例如，始终从 0 到 5 的 for 循环是编译器在编译时就能知道的，因此是动态 uniform 的。类似地，传入着色器的 uniform 整数值也是动态 uniform 的。对于 GLSL MAT，你的 Instance ID（TDInstanceID()）not 动态 uniform 的。 如果你想用在着色器执行期间才决定的值来查找输入，例如根据当前 UV 值选择不同的输入，就需要用 nonuniformEXT() 包裹索引，告诉编译器该索引是非 uniform 的。 例如 

int inputIndex;
if (vUV.s > 0.5)
   inputIndex = 0;
else
   inputIndex = 1;
vec4 col = sTD2DInputs[nonuniformEXT(inputIndex)], vUV);

Uniform

Uniform 是每个绘制的像素都保持相同的值。它们通过 GLSL TOP 中的 Vectors 1 和 Vectors 2 页设置。要在着色器中使用 uniform，请声明一个与你在 GLSL TOP 的 Vectors 页上设置的参数同名同尺寸的 uniform。 例如，假设我们要做一个生成纯色图像的着色器，但你不想把它硬编码在着色器中（如同第一个示例那样）。 

layout(location = 0) out vec4 fragColor;
uniform vec4 uColor;
void main()
{
   fragColor = uColor;
}

现在你可以根据需要为 Uniform Name uColor 设置 GLSL TOP 上的 Value 参数（例如导出到这些参数、使用表达式或手动设置）。GLSL TOP 会自动更新，并根据变化的值生成新图像。

内置 Uniform 变量

GLSL TOP 有内置 uniform，根据你所编写的着色器可能会派上用场。你无需声明这些 uniform，它们会为你声明。

有许多该结构的数组，提供关于输入/输出纹理的信息，例如其分辨率。该结构定义如下： 

struct TDTexInfo
{
   // 包含 (1.0 / width, 1.0 / height, width, height)
   vec4 res;  
   // 包含 (1.0 / depth, depth, depthOffset, undefined)
   // depthOffset 对 3D 纹理位于 [0,1]，对 2D 纹理数组位于 [0, depth - 1]。
   vec4 depth;
};

对于每个输入采样器数组（2D、3D、2DArray 等），都有一个上述结构的并行数组，包含关于每个采样器的信息。纹理的输出信息由 uTDOutputINfo 提供。你可以使用该 uniform 获取 TOP 将要输出的分辨率，无需通过自定义 uniform 手动传入。不过 depthOffset 值始终为 0。 

uniform TDTexInfo uTD2DInfos[TD_NUM_2D_INPUTS];
uniform TDTexInfo uTD3DInfos[TD_NUM_3D_INPUTS];
uniform TDTexInfo uTD2DArrayInfos[TD_NUM_2D_ARRAY_INPUTS];
uniform TDTexInfo uTDCubeInfos[TD_NUM_CUBE_INPUTS];
  
// 有关 TOP 输出的信息，例如它的分辨率。
uniform TDTexInfo uTDOutputInfo;

例如，要获取第一个 2D 输入的宽度，你可以这样写： 

float width = uTD2DInfos[0].res.z;

当输入是有深度的纹理（3D 或 2D Array）时，depth 变量会包含深度，以及 depthOffset。depthOffset 是从纹理前端处的纹理坐标到最近更新的输入切片的纹理坐标的偏移。因此，如果你想要一个始终输出 3D 纹理最新切片的 TOP，可以使用这个着色器 

layout(location = 0) out vec4 fragColor;
void main()
{
   // 第一个切片的中心并不位于 0，而是位于 0（第一个切片的起点）
   // 与 1.0 / depth（第一个切片的终点）之间
   float firstSlice = uTD3DInfos[0].depth.x * 0.5;

   // 现在加上偏移
   firstSlice += uTD3DInfos[0].depth.z;
 
   // 现在采样纹理
   fragColor = texture(sTD3DInputs[0], vec3(vUV.st, firstSlice));
}

对于 3D 纹理，depthOffset 始终在 0 到 1 之间。对于 2D Array，偏移在 0 到（depth - 1）之间，且始终为整数。

当输出 3D 或 2D Array 纹理时，该 uniform 保存你当前正在渲染到的切片索引。 

// 参见 [[#3D Textures and 2D Texture Arrays |3D Textures and 2D Texture Arrays]]
uniform int uTDCurrentDepth;

使用 GLSL TOP 的 Common 页上的「Num Passes」参数时，通常需要在着色器中知道当前正在渲染哪一个 pass。你可以通过查看该 uniform 来实现 

// GLSL TOP 中当前的渲染通道，从 0 开始递增。
uniform int uTDPass;

原子计数器

原子计数器是全局无符号整数，可对其执行原子操作，即自增和自减。它们可以在管线的任何阶段（vertex、fragment/pixel、compute）的着色器中使用，可用于追踪各种信息，例如顶点数量、红色像素数量等。所有着色器执行都会使用同一个变量，从而可以在彼此之间共享信息。

下面是一个简单的像素着色器示例：每次（即每个像素一次）递增原子计数器，将其转换为 float，然后写入红色通道。从视觉上看，先渲染的像素会比后渲染的像素呈现更深的红色。 

uniform atomic_uint ac;
out vec4 fragColor;
void main()
{
   uint c = atomicCounterIncrement(ac);
   float r = (c/255)/255.f;
   fragColor = vec4(r,0,0,1);
}

它们也可以通过如下方式声明为数组并初始化： 

uniform atomic_uint ac[10];

注意，尽管许多在线示例会在声明前加上绑定点，如 layout (binding = 0)，但省略它并让我们的编译器自动分配绑定会更高效。

特化常量

Specialization Constants 是 Vulkan 的新特性，它允许基于整数常量值对代码重新优化，而无需完全重新编译着色器代码。它们适用于为很少变化的值设值，例如着色器中的「模式」，或通过 switch() 或 if() 语句选择的特定代码路径。过去这可能通过 #define 语句或 uniform 来实现。 着色器的特化版本会被缓存并重复使用，但会占用 GPU 资源。因此不应用于不断变化的值，而应用于仅偶尔变化、且取值范围有限的值。

要定义特化常量，需声明一个带额外 layout() 限定符的常量。

layout(constant_id = 0) const int SomeMode = 0;

然后你可以像使用其他变量一样使用 SomeMode。如果不希望它为 = 0，可以在 GLSL TOP、GLSL MAT 等的「Constants」页上赋予不同的值。 你可以声明多个特化常量，只需为每个赋予自己唯一的 constant_id 值（0、1、2 等）。

采样多个像素

在某些着色器中，你可能想从输入 TOP 采样多个像素（例如创建模糊着色器时）。这只需多次调用 texture()，同时偏移 vUV 的值（或你自己的纹理坐标）。

就纹理坐标而言，一个像素与其右侧相邻像素的值差为（1.0 / width）。类似地，一个像素与其下方相邻像素的值差为 -（1.0 / height）。 以下函数有助于计算相邻像素的正确纹理坐标： 

// 此函数未替你提供，你需要自行声明它。
vec2 input2DOffset(int texIndex, int xOffset, int yOffset)
{
   return vec2(vUV.s + (float(xOffset) * uTD2DInfos[texIndex].res.s),
               vUV.t + (float(yOffset) * uTD2DInfos[texIndex].res.t));
}

不过 GLSL 中有一个新函数 textureOffset() 会为你完成这项工作。但它从起始坐标可采样的范围有限，因此不能用于从某个坐标获取任意偏移的采样。

下面是一个非常简单的模糊着色器，它会在每个像素周围采样 3x3 网格，并输出全部 9 个像素的平均值。它手动计算偏移，而没有使用 textureOffset，不过在本例中 textureOffset 也可以正常工作，因为偏移只有 1 个像素。 

vec2 input2DOffset(int texIndex, int xOffset, int yOffset)
{
   return vec2(vUV.s + (float(xOffset) * uTD2DInfos[texIndex].res.s),
               vUV.t + (float(yOffset) * uTD2DInfos[texIndex].res.t));
}

layout(location = 0) out vec4 fragColor;
void main()
{
   vec4 colorSum = vec4(0.0);
   colorSum += texture(sTD2DInputs[0], input2DOffset(0, 0, 0));
   colorSum += texture(sTD2DInputs[0], input2DOffset(0, -1, -1));
   colorSum += texture(sTD2DInputs[0], input2DOffset(0, 0, -1));
   colorSum += texture(sTD2DInputs[0], input2DOffset(0, 1, -1));
   colorSum += texture(sTD2DInputs[0], input2DOffset(0, 1, 0));
   colorSum += texture(sTD2DInputs[0], input2DOffset(0, 1, 1));
   colorSum += texture(sTD2DInputs[0], input2DOffset(0, 0, 1));
   colorSum += texture(sTD2DInputs[0], input2DOffset(0, -1, 1));
   colorSum += texture(sTD2DInputs[0], input2DOffset(0, -1, 0));<br>
   fragColor = colorSum / 9.0;
}

3D 纹理与 2D 纹理数组

像素着色器

创建 3D Texture 或 2D Texture Array 时，你的着色器会针对生成的每个深度切片渲染一次。这就像渲染一批 2D 纹理。

除了会获得不同的输入采样器外，你还可以使用一些 uniform 来帮助决定每个切片要创建什么。 

uniform int uTDCurrentDepth; // 当前正在创建的切片的从 0 开始的索引。

计算着色器

使用计算着色器创建 3D Texture 或 2D Texture Array 时，着色器仍然只运行一次。整个输出纹理都可以通过 TDImageStoreOutput 写入，应按需填充，Z 调度尺寸可能等于纹理的深度。

输出到多个颜色缓冲区

在同一个像素着色器中，你可以同时输出到多个尺寸/格式相同的缓冲区。为此，首先在 GLSL TOP 中把「# of Color Buffers」参数调到你需要的输出数量。

GLSL TOP 的输出连接器始终输出第一个颜色缓冲区的颜色。要获取其他颜色缓冲区，请使用 Render Select TOP 并将其指向 GLSL TOP，然后选择你需要的颜色缓冲区索引。

像素着色器

在你的着色器中声明其他输出位置。例如，如果你打算输出到 3 个不同的缓冲区，可以这样声明： 

layout(location = 0) out vec4 fragColor;
layout(location = 1) out vec4 otherColor;
layout(location = 2) out vec4 extraInfo;

现在你可以写入 fragColor、otherColor 和 extraInfo，从而写入你正在输出的 3 个颜色缓冲区。如果你并非在所有情况下都写入全部输出，则得到的像素值未定义。不要为了避免写入而试图让缓冲区保留上一帧的值。

计算着色器

sTDComputeOutputs[] uniform 的尺寸会等于正在输出的颜色缓冲区数量。

顶点着色器

大多数情况下，你不需要为 GLSL TOP 提供顶点着色器。如果你决定提供顶点着色器，其最基本的形式如下： 

out vec3 texCoord;
void main()
{
   texCoord = uv[0];
   gl_Position = TDSOPToProj(vec4(P, 1.0));
}

非常重要的一点是不要操纵顶点位置，因为这会导致四边形与 TOP 输出不对齐。另外请注意我们在这里为纹理坐标声明了自己的输出变量。如果我们提供了顶点着色器，vUV 在像素着色器中就不会自动可用，因此我们改用这个变量； 

layout (location = 0) out vec4 fragColor;
in vec3 texCoord;
void main()
{
   fragColor = texture(sTD2DInputs[0], texCoord.st);
}

其他说明

#version 语句

TouchDesigner 在编译着色器时会自动在开头加上 #version 语句，因此你应确保自己的着色器没有 #version 语句。如果有，就会报错。
