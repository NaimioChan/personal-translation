创建自定义 TDAbleton 组件

TDAbleton 系统包含一个框架，可用于构建自己的自定义组件以连接 Ableton Live。这要用 Python 扩展实现，需要对编程有中等程度的了解。

另请参阅：TDAbleton、TDAbleton System Components、TDAbletonCompBaseExt Extension

开发工具

创建自定义 TDAbleton 组件时，tdAbleton master component 提供了一些有用的工具。在其 TDAbleton 自定义参数页中，底部区域包含对此任务有用的参数。Ableton Log File、Log TDA Messages 和 Open Log File 是与 Ableton log file 配合使用的辅助工具。另请参阅：tdAbleton master component。

Ableton 控制台

Open Console 会打开一个进入 TouchDesigner Remote Script 的 Python 控制台，让你可以直接与 Live Object Model 交互。这对于理解 Ableton Python Live Object Model 的结构非常有用。控制台提供了一些特殊的快捷名称，便于在 Remote Script 中浏览：

  1. SONG：当前的 Live Object Model（LOM）song 对象。也称为「Live Set」。
  2. APP：当前的 LOM application 对象。
  3. TDA：TouchDesigner Remote Script 对象。
  4. CLIENT：此 TouchDesigner 进程的 TDA client 对象。
  5. OSC：用于通信的 OSC Python 模块

例如，如果打开控制台并输入 SONG.tracks[0].name，你会看到返回的第一条轨道的名称。

Ableton 的 Live Object Model

TDAbleton 系统大量使用 Ableton 的 Live Object Model（简称 LOM），它让 Python 几乎可以访问 Ableton Live 的方方面面。深入探讨细节超出了本 wiki 的范围，但以下是一些非常有帮助的文档链接：

  1. https://docs.cycling74.com/max7/vignettes/live_object_model
  2. https://julienbayle.studio/PythonLiveAPI_documentation/Live9.6.xml

TDAbleton 组件的构成

TDAbleton 中提供的 abletonComp 自定义组件是构建自定义 TDAbleton 组件的起点。它本身不做任何事，但包含所有必需的操作符以及 TDAbleton 系统使用的所有 Custom Parameters。属于 TDAbleton 基础系统的组件内部操作符显示为橙色。

abletonBase 组件

所有 TDAbleton 组件内部都有一个 abletonBase Component，其中包含 TDAbleton 系统的核心内容。它克隆自 tdAbleton 主组件中的 abletonBase，因此当你在网络中放入更新后的 tdAbleton 主组件时，它会自动更新。它有一个输出，即包含 TDAbleton listeners 所报告值的 CHOP（见下文）。通常连接到 out1 Out CHOP，用于报告从 Ableton Live 接收的数据。当然，可以用各种 CHOP 技巧为此输出添加自定义通道。

自定义 Ableton 扩展

每个自定义 TDAbleton 组件都需要自己的自定义 Extension。要使用 abletonBase 中的内置功能，扩展应派生自 TDAbletonCompBaseExt Extension，它位于 abletonBase 组件中。

TDAbleton 自定义参数

TDAbletonCompBaseExt 和 abletonBase 使用的所有自定义参数都包含在 Ableton Comp custom parameter page 上。它们并非每个自定义 TDAbleton 组件都必需，但作为方便的起点提供。不需要的可以删除。

abletonComp 上还有一个 TDAbleton custom parameter page，其中包含 TDAbleton 系统使用的参数，不应修改。

设置新的自定义 TDAbleton 组件

在 abletonComp 上有一些地方需要修改，以便创建自定义 TDAbleton 组件。首先复制一份 abletonComp 作为起点，然后按下面的说明开始自定义。

更改名称

TDAbleton 官方组件都以「ableton」开头。你可以采用这一规范，也可以不采用，但给操作符起有意义的名字总是好事。不要保留 abletonComp 这个名称，那肯定会造成混淆。

更改颜色

大多数 TDAbleton 组件是深橙色，便于在网络中辨认。浅橙色（如 abletonComp 及各种内部操作符）用于表示更偏基础构件的部分。

重新指定克隆源

TDAbleton 的 Update system 会使用克隆源。它应指向你存放该自定义组件母版的位置。

更改扩展名

虽然并非绝对必要，但最好把扩展名改成与自定义组件名称一致。在 Extension Object 1 参数中，把两处 AbletonCompExt 都改为适合你的扩展的名称。Ext 后缀同样不是必需的，但属于最佳实践。修改扩展参数后，进入组件内部，修改扩展 DAT 的名称以及其中扩展类的名称。

设置你的 TDAbleton 自定义参数

如上所述，abletonComp 一开始就包含 TDAbleton 系统使用的所有参数。使用 Component Editor 打开你的自定义组件。把 Ableton Comp 页的名称改成符合组件名称的名称。如果你知道自己需要哪些参数，可以现在就删除不需要的；如果不确定，也可以留到以后再处理。

重要： Live Object Model（LOM）参数（Track、Device、Chains、Chain Devices 和 Parameter）用于按层级浏览 Ableton 的 Live Object Model。它们之间以特定方式相互依赖。只有以下组合是有效的：

  • No LOM parameters：无需 LOM 导航
  • Track only：组件用于作用于某条 Ableton 轨道。
  • Track and Device：组件用于作用于某个 Ableton 设备。
  • Track, Device, Parameter：组件用于作用于顶层 Device 上的某个 Ableton 参数。
  • Track, Device, Chain (+ optional Chain Devices and Chains ending on a Chain)：组件用于作用于某条 Track 或 Device Chain。
  • Track, Device, Chain, Chain Device, (+ optional Chains and Chain Devices ending on a Chain Device)：组件用于作用于顶层或子链中的 Device。
  • Track, Device, Chain, Chain Device, (+ optional Chains and Chain Devices ending on a Chain Device), Parameter：组件用于作用于顶层或子链 Device 上的某个 Ableton 参数。

自定义 TDAbleton 组件

学习使用 TDAbleton 系统的最好方式，是研究 TDAbleton System Components，尤其是与你目标最接近的那些。很多情况下，你只需要自定义自己的扩展。连接 Live 的功能通过让扩展派生自 TDAbletonCompBaseExt Extension 来提供。

示例：AbletonParameterExt

abletonParameter 组件提供对某个 Ableton 设备参数的访问。这一功能由一个小型自定义扩展脚本实现，我们在此探讨一下。 如果你不熟悉 Python 中的继承，网上有很多教程，例如 this one。基本上，你的扩展类会从其父类 TDAbletonCompBaseExt Extension「继承」方法和成员。

派生自 TDAbletonCompBaseExt

TDAbletonCompBaseExt = mod('abletonBase/TDAbletonCompBaseExt').TDAbletonCompBaseExt

class AbletonParameterExt(TDAbletonCompBaseExt):
	"""
	AbletonParameterExt sets up a basic 2 way connection with an Ableton parameter.
	"""
	def __init__(self, ownerComp):
		# 此扩展所附加到的组件
		TDAbletonCompBaseExt.__init__(self, ownerComp)

AbletonParameterExt 脚本的开头部分把扩展设为 TDAbletonCompBaseExt Extension 的子类。第一行从 abletonBase 中的 DAT 模块取得该类。类定义使用 TDAbletonCompBaseExt 作为父类，并在 AbletonParameterExt.__init__ 期间调用其 __init__ 函数。

设置监听器

	def setupListeners(self):
		TDAbletonCompBaseExt.setupListeners(self)

		# 确保我们有有效的 Ableton 参数
		aParInfo = self.LomParInfo('Parameter')
		if not aParInfo:
			return

		# 设置监听器参数
		# lomExpression：指向 TDA 中 live 对象的 Python 表达式
		lomExpression = aParInfo['lomExpression']

		# returnAddress：TDA 将更新发送到的 OSC 地址。
		# 注意，这必须是有效的 CHOP 通道名
		returnAddress = aParInfo['returnAddress'] + '/value'

		# id：请求监听器的对象的唯一 id
		ownerId = self.ownerComp.id

		# property：要监听的 live 对象属性名
		property = 'value'

		# 此元组即为监听器键（listener key）的形式
		listener = (lomExpression, property, returnAddress, ownerId)

		# addListener(listener, outgoing 参数,
		# autoSync 用于保持 par 同步更新, parMin, parMax)
		self.addListener(listener, self.ownerComp.par.Valuesend,
					aParInfo['lomInfo']['min'], aParInfo['lomInfo']['max'])

这里是扩展真正的核心所在。当组件准备好在 Ableton Live 中创建监听器时，setupListeners 函数会由 TDAbletonCompBaseExt Extension 调用。监听器是 LOM 中在值变化时接收信息的一种方式。TDAbleton 从 Ableton Live 接收信息的主要途径就是监听器。提示： 想要试验数值监听器，abletonValueListener 组件是个很好的选择。

通读代码时，注释解释了各行内容，但整体思路是：TDAbletonCompBaseExt Extension 提供了在 Ableton Live 中设置监听器的便捷接口。下面这行定义了实际的监听器： 

		# 此元组即为监听器键（listener key）的形式
		listener = (lomExpression, property, returnAddress, ownerId)
监听器元素

一个监听器由四部分信息组成：

  1. lomExpression：一个指向 Ableton Live Object Model 中对象的 Python 表达式。如果你查看代码上方，会看到这可以通过 LOM 自定义参数轻松提供，由下面这行：aParInfo = self.LomParInfo('Parameter') 以及再下面这行：aParInfo['lomExpression']。每个参数都知道如何为所引用的对象创建 LOM 表达式。它是一段简单的 Python 代码字符串，也可以通过引用 [Live Object Model documentation] 并试验 TDAbleton Console 来创建。
  2. property：lomExpression 所引用 LOM 对象的某个属性。
  3. returnAddress：属性变化时要发送到的 OSC 地址
  4. ownerId：请求监听器的对象的唯一 ID。
  5. extra：extra 元素是一个带有特殊指令的可选字符串。如果为 'noinit'，则跳过初值发送。在监听大量通道时，这有助于避免 CHOP 变得杂乱。
添加监听器

监听器由下面这行添加： 

		self.addListener(listener, self.ownerComp.par.Valuesend,
					aParInfo['lomInfo']['min'], aParInfo['lomInfo']['max'])

除了监听器本身，addListener 还接受可选参数，用于指定一个为该监听器 setting 发送数据的 Touch 参数。这些数据包括该参数以及最小值和最大值。

onParPulse 与 doMap 函数

AbletonParameterExt 扩展的末尾还有几个用于该组件映射功能的函数。它们比本教程的范围更进阶，但有经验的用户能从中学习到重要技巧，包括：

  1. 响应 Pulse 参数（需要自己的 Parameter Execute DAT）
  2. 向 Live 请求远程数据并响应
  3. 打开 PopDialog Custom COMP
  4. 通过遍历 song info 层级设置 LOM 参数
