Engine COMP

摘要

Engine COMP 会在单独的进程中运行一个 .tox file（组件）。它使用 TouchEngine 来管理这些进程，并在加载的组件与主项目之间传递数据。

Engine COMP 还允许在其中加载的组件打开 Window COMP（并进入 Perform Mode）。为此必须将 Clock Mode 设为 Independent（在 Tune 页上）——这是为 UI 事件提供服务所必需的。

Inputs and Outputs

所选组件的顶层 Inputs 和 Outputs 会作为 Engine COMP 的输入和输出暴露出来。仅支持 TOP、CHOP 和 DAT 输入和输出。

Custom Parameters

顶层组件上的任何 custom parameters 都会添加到 Engine COMP 的参数中。引用网络中其他节点的自定义参数（例如 TOP、CHOP 和 DAT 参数）不受支持——应改用输入来连接这些节点。

请注意，参数只在一个方向上起作用——你无法从加载的 .tox 内部设置参数。

External File Paths

默认情况下，OP 上或脚本中位于 inside 所加载组件内的相对路径，是相对于 .tox 文件的位置。这可以通过 'Asset Paths' 参数更改。作为文件或文件夹自定义参数位于 of 组件上的相对路径——即显示在 Engine COMP 上的那些——始终相对于主项目。

Monitoring Engine Status

监视 Engine COMP 的状态和性能很有用。默认情况下，一个 Info DAT 会停靠到 Engine COMP，其中包含文件路径和进程 ID。一个停靠的 Info CHOP 包含三组监视通道：Info Type 菜单默认设为 TouchEngine Status，给出 Engine 进程的加载/运行/错误状态。将菜单改为 TouchEngine Perform 可得到引擎的性能统计，将菜单改为 Initialize/Start 可得到专门针对所加载组件的就绪/运行状态信息，因为它可以被暂停、计时和重新初始化。

Controlling Engine State

Engine 进程会由 TouchDesigner 进程启动，并自动运行你的 .tox 组件。但你可以使用当前加载的 .tox 文件的 Unload、Reload 脉冲参数，对多个组件的时间/内存管理进行更多控制。在 Advanced 页上，Launch 和 Quit Engine Process 参数让你可以终止/重启整个 Engine 进程。

Component Lifetime

在 TouchEngine 下，组件被加载到已在运行的实例中。因此，Execute DAT 的 onStart() 和 onExit() 方法在 TouchEngine 下永远不会执行。onCreate() 方法会在组件加载时执行，是执行你通常在 onStart() 中所做设置的合适位置。

Time in TouchEngine

当 Engine COMP 启动组件时（如果 'Start when Initialized' 为 On，则在组件加载之后），TouchEngine 中的组件时间为 0。之后它会与 Engine COMP 同步递增，或按 TouchEngine 的内部时钟递增，取决于 Tune 参数页上 'Clock' 参数的设置。

使用输入缓冲区和输出缓冲区来容纳 Engine COMP 与 TouchEngine 之间的计算速率差异。通常你可能需要调整 Tune 页上的参数以适合你的具体配置。必要时，Engine COMP 会先计算若干帧以填满其输入缓冲区，然后开始在 TouchEngine 中计算组件；随后在 TouchEngine 中计算若干帧以填满其输出缓冲区，再从 Engine COMP 输出。Auto 设置会尝试保持足以避免丢帧的小缓冲区，但你可能希望设置固定的缓冲区大小以适合你的配置，尤其是在处理音频时。

TouchEngine Versions

TouchEngine 作为 TouchDesigner 的一部分安装，当前运行的版本将用于加载给定的 .tox。如果你想使用其他版本的 TouchEngine，可以：将 environment variable TOUCHENGINE_APP_PATH 设为 TouchDesigner 安装的路径（Windows 上的安装目录，或 macOS 上的 TouchDesigner 应用）or 将 TouchDesigner 安装到与 .tox 并列的名为 TouchEngine 的文件夹中（在 macOS 上，将应用从 TouchDesigner 重命名为 TouchEngine）or 在与 .tox 并列的位置创建一个名为 TouchEngine 的链接，指向某个安装目录或 TouchDesigner 应用。

参数 - Engine 页

Tox File file - 指定要用 TouchEngine 加载的 .tox 文件。
Unload unload - 卸载当前加载的组件。
Reload reload - 重新加载当前加载的组件。
Reload on Crash reloadoncrash - 如果 TouchEngine 实例因任何原因退出，则重新启动它。
Asset Paths assetpaths - 指定组件内的相对路径如何解析。
  • Relative to Project File (.toe) project - 组件内的相对路径相对于运行 TouchEngine 的项目文件。
  • Relative to COMP File (.tox) comp - 组件内的相对路径相对于该组件（.tox 文件）。
Callbacks DAT callbacks - Callbacks DAT 将针对与 TouchEngine 实例相关的事件执行。

参数 - Tune 页

Clock clock - 指定与 TouchEngine 实例的时间连接。
  • Synchronized synced - 时间在 Engine COMP 与 TouchEngine 实例之间严格同步。
  • Independent independent - TouchEngine 实例按其自身的内部时钟运行。
Match Local Component Rate matchrate - 打开时，组件在 TouchEngine 中将按与 Engine COMP 相同的速率计算。
Frames per Second fps - 在 TouchEngine 中计算组件的帧率。
Wait for Render wait - 启用后，如果某帧在 TouchEngine 中计算耗时较长，Engine COMP 会在计算期间等待，而不是丢弃该迟到帧。

此行为受输出缓冲区大小影响：例如，如果 Out Buffer Frames 为 4，Engine COMP 将等待第 4 个最新帧完成。

Render Timeout timeout - 等待帧时，TouchEngine 会在这么多毫秒后放弃等待。
In Buffer Auto inauto - 自动管理排队的输入帧数量。
In Buffer Frames inframes - 在传给 TouchEngine 实例之前排队的输入帧数量。

为了适应 TouchEngine 实例中时间切片可能的波动，CHOP 输入必须提前发送若干帧。

Out Buffer Auto outauto - 自动管理排队的输出帧数量。
Out Buffer Frames outframes - 从 TouchEngine 实例接收后排队的输出帧数量。

为了适应 Engine COMP 中时间切片可能的波动，CHOP 输出必须提前发送若干帧。

参数 - InitStart 页

Pre-Roll preroll - 初始化时，先运行这么长时间再进入就绪状态。
Pre-Roll Units prerollunits - 测量 Pre-Roll 所用的单位。
  • F frames - Pre-Roll 以帧为单位测量。
  • S seconds - Pre-Roll 以秒为单位测量。
Ready when readywhen - 指定 Engine COMP 何时进入就绪状态。
  • Component Loaded loaded - 当 TouchEngine 已加载组件时，Engine COMP 进入就绪状态。
  • Output Buffered buffered - 当 TouchEngine 已加载组件且已计算足够帧填满输入和输出缓冲区时，Engine COMP 进入就绪状态。
  • Component Running running - 当 TouchEngine 已加载组件、已计算足够帧填满输入和输出缓冲区且组件正在运行时，Engine COMP 进入就绪状态。
Start when Initialized startoninit - 启用后，组件一旦初始化完成并处于就绪状态，播放就会开始。
Initialize initialize - 重新加载 .tox 文件，重启 TouchEngine 实例。
Start start - 开始播放 TouchEngine 实例中的组件。
Play play - 打开或关闭 TouchEngine 实例中的计算。
Go to Done gotodone - 使 Engine COMP 进入 done 状态。
On Done ondone - 决定 Engine COMP 进入 done 状态时采取的操作（如果有）。
  • Do Nothing donothing - 除状态变化外不执行任何操作，TouchEngine 继续运行该组件。
  • Pause pause - 已加载组件的播放暂停。
  • Unload unload - 已加载的组件被卸载。
  • Re-Initialize reinit - 已加载的组件被卸载，然后进行初始化。
  • Re-Start restart - 组件保持加载状态，并重新开始播放。
  • Quit Engine Process quit - TouchEngine 被完全关闭。

参数 - Advanced 页

On Engine COMP Create oncompcreate - 指定创建 Engine COMP 时（例如加载项目时）会发生什么。
  • Do Nothing nothing - 创建 Engine COMP 时不执行任何操作。
  • Launch Engine launch - 创建 Engine COMP 时启动 TouchEngine。不加载任何指定的组件。
  • Load and Initialize initialize - 启动 TouchEngine，加载任何指定的组件，并初始化 Engine COMP 使其进入就绪状态。
Launch Engine Process launch - 如果 TouchEngine 进程未运行，则启动它。
Quit Engine Process quit - 如果 TouchEngine 进程正在运行，则停止它。
Allow UI allowui - 要使用此功能，'Clock' 参数必须设为 'Independant'。当 'Allow UI' 为 On 时，在 TouchEngine 中加载的组件可以打开 Window COMP 或进入 perform mode。可通过顶层组件上的参数或脚本来实现。

参数 - Extensions 页

Extensions 参数页设置组件的 Python 扩展。更多信息请参阅 extensions。

Re-Init Extensions reinitextensions - 重新编译所有扩展对象。通常只有在扩展对象被引用且其定义已更改时，扩展对象才会被编译。
Init Extensions On Start initextonstart - 在 TouchDesigner 启动时自动执行 Re-Init
Extension ext - 用于在此组件上创建扩展的信息序列
Object ext0object - 可附加到组件的类实例数量。
Name ext0name - 可选，用于搜索的名称，代替实例类名。
Promote ext0promote - 控制扩展是直接在组件层级可见，还是必须通过 .ext 成员访问。示例：n.Somefunction 与 n.ext.Somefunction

参数 - Common 页

Common 参数页设置组件的 node viewer 和 clone 关系。

Parent Shortcut parentshortcut - 指定一个名称，可在组件内任意位置用作该组件的路径。参见 Parent Shortcut。
Global OP Shortcut opshortcut - 指定一个名称，可在任何位置用作该组件的路径。参见 Global OP Shortcut。
Internal OP iop - 内部操作符的序列标题。
Shortcut iop0shortcut - 指定一个名称，可在组件内任意位置用作下方「Internal OP」的路径。参见 Internal Operators。
OP iop0op - 此组件内 Internal OP 的路径。参见 Internal Operators。
Operator Viewer opviewer - 当上方的 Node View 参数设为 Operator Viewer 时，选择使用哪个操作符的节点查看器。
Enable Cloning enablecloning - 控制该 OP 是否应持续克隆。关闭此项会使此节点停止克隆其「Clone Master」。
Enable Cloning Pulse enablecloningpulse - 立即克隆内容。
Clone Master clone - 用作 Master Clone 的组件路径。
Load on Demand loadondemand - 仅在需要时将组件加载到内存。适用于项目中并非总是使用的组件。
Enable External .tox enableexternaltox - 开启时（默认），.toe 启动时会加载外部 .tox 文件，COMP 的内容将与该外部 .tox 一致。如有需要，可以关闭此项，以避免启动时从引用的外部 .tox 加载（COMP 的内容改为从 .toe 文件加载）。如果你希望某个 COMP 引用外部 .tox，但不总是从它加载，除非你特意按下 Re-Init Network 参数按钮，这会很有用。
Enable External .tox Pulse enableexternaltoxpulse - 此按钮会从外部 .tox 文件重新加载（若存在）。
External .tox Path externaltox - 磁盘上 .tox 文件的路径，该文件会在 .toe 启动时作为组件内容的来源。这让组件可以包含能独立更新的网络。若找不到 .tox 文件，则会加载 .toe 文件保存时的内容。
Reload Custom Parameters reloadcustom - 启用此复选框后，重新加载 .tox 时会重新加载组件 Custom Parameters 的值。这仅影响组件上的顶层参数；组件内节点上的所有参数始终随 .tox 重新加载。
Reload Built-In Parameters reloadbuiltin - 启用此复选框后，重新加载 .tox 时会重新加载组件内置参数的值。这仅影响组件上的顶层参数；组件内节点上的所有参数始终随 .tox 重新加载。
Save Backup of External savebackup - 启用此复选框后，由 External .tox 参数指定的组件的备份副本会保存在 .toe 文件中。若找不到 External .tox，将使用此备份副本。出现这种情况可能是因为 .tox 被重命名、删除，或 .toe 文件在另一台缺少组件媒体的电脑上运行。
Sub-Component to Load subcompname - 从外部 .tox 文件加载时，此选项允许你深入 .tox 取出一个 COMP，并将其作为顶层 COMP，忽略文件中的其他所有内容（该 COMP 的内容除外）。例如，若名为 project1.tox 的 .tox 文件包含 project1/geo1，将 geo1 设为 Sub-Component to Load，就会加载 geo1 来替代当前 COMP。若此参数为空，则按常规使用文件中的顶层 COMP 加载 .tox 文件。
Relative File Path Behavior relpath - - 设置此 COMP 内的子文件路径是相对于 .toe 本身还是 .tox，或从父级继承。
  • Use Parent's Behavior inherit - 从父级继承设置。
  • Relative to Project File (.toe) project - 当指定为相对路径时，该路径将相对于 .toe 文件。
  • Relative to External COMP File (.tox) externaltox - 当指定为相对路径时，该路径将相对于 .tox 文件。未指定外部 COMP 文件，或 Enable External .tox 未开启时，此项没有影响。

Info CHOP 通道

可以通过 Info CHOP 查看 Engine COMP 的额外信息。

Engine COMP 专用 Info 通道

  • input_buffer_frames - 输入缓冲区中的帧数。这受 Tune 参数页上的参数影响。
  • output_buffer_frames - 输出缓冲区中的帧数。这受 Tune 参数页上的参数影响。
  • output_cook_abs_frame - 计算当前输出时的 cook_abs_frame 值。这受输出缓冲区中的帧数影响。
  • output_did_wait - Engine COMP 等待输出计算时为 1。仅在 Wait for Render 为 On 时为 1，并受 TouchEngine 中完成一帧所需时间以及输入和输出缓冲区数量的影响。详情请参阅 Tune 参数页。
  • initializing - Engine COMP 处于 initializing 状态时为 1。
  • initialize_fail - 初始化期间发生错误时为 1。这通常表示在 TouchEngine 中加载组件时出错。
  • ready - 初始化完成后、启动之前为 1。
  • running - 从启动后到 Engine COMP 进入 done 状态或被重新初始化之前为 1。
  • done - Engine COMP 处于 done 状态时为 1。
  • timer_seconds - 在 Engine COMP 中，这与 playing_seconds 一致。
  • playing_seconds - 自启动以来经过的秒数，已计入播放状态。
  • running_seconds - 自启动以来经过的秒数。
  • engine_launching - TouchEngine 正在启动、尚未加载任何组件时为 1。
  • engine_running - TouchEngine 已启动并正在运行时为 1。
  • engine_none - TouchEngine 未运行时为 1。
  • engine_error - TouchEngine 遇到与组件无关的错误时为 1。
  • component_loading - TouchEngine 正在加载组件时为 1。
  • component_loaded - TouchEngine 成功加载组件时为 1。
  • component_unloading - TouchEngine 正在卸载组件时为 1。
  • component_none - TouchEngine 没有已加载的组件时为 1。
  • component_error - TouchEngine 在加载或运行组件时遇到错误时为 1。
  • crash_reload_count - 当 Reload on Crash 为 On 时，因错误而重新加载组件的次数。
  • engine_absolute_frame - TouchEngine 中以帧表示的绝对时间值。
  • engine_absolute_seconds - TouchEngine 中以秒表示的绝对时间值。
  • engine_fps - TouchEngine 中最后一秒内渲染的帧数。
  • engine_frame_msec - TouchEngine 中每帧计算所花费的时间（毫秒）。
  • engine_cook - 在 TouchEngine 中，帧被计算时等于 1，帧被跳过时等于 0。
  • engine_dropped_frames - TouchEngine 中上一帧与当前帧之间丢弃的帧数。
  • engine_read_ahead_misses - 在 TouchEngine 中，影片预读未能维持指定的 Read Ahead 帧数的次数。
  • engine_gpu_mem_used - TouchEngine 中使用的 GPU 内存量（兆字节）。
  • engine_total_gpu_mem - 系统上可用的 GPU 内存总量（兆字节）。
  • engine_active_ops - TouchEngine 中当前正在计算的操作符数量。
  • engine_deactivated_ops - 在 TouchEngine 中对关闭了 Cooking Flag 的组件调用计算的次数。
  • engine_total_ops - TouchEngine 中的操作符总数。
  • engine_cpu_mem_used - TouchEngine 中使用的 CPU 内存量（兆字节）。
  • engine_cookstate - 监视 TouchEngine 中实际计算了哪些帧。
  • engine_cookrealtime - 监视 realtime 标记的状态，判断 TouchEngine 是否以实时模式运行。
  • engine_cookrate - TouchEngine 的全局目标计算速率（每秒帧数）。这是根组件的每秒帧数 root.time.rate，通常为 60，但由于帧计算耗时过长，实际每秒帧数可能更低。
  • engine_timeslice_step - TouchEngine 在本次计算中前进的帧数。它是时间切片以帧表示的长度。当系统完成一帧耗时不超过 1000/root.time.rate 毫秒（速率为 60 时为 16.666 毫秒）时，该值等于 1。
  • engine_timeslice_msec - 当前时间切片的长度（毫秒）。
  • engine_active_expressions - 在 TouchEngine 中找到的活动 python 表达式数量。
  • engine_active_expressions - 在 TouchEngine 中已优化的 python 表达式数量。
  • engine_cached_expressions - 在 TouchEngine 中已缓存的 python 表达式数量。

COMP 通用信息通道

  • num_children - 此组件中的子级数量。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
