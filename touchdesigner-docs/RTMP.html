RTMP

RTMP 是一种通过互联网传输音频/视频流的协议。标准 RTMP 仅支持 H.264 编码的内容。一个名为 Enhanced RTMP 的较新标准支持 H.265 和 AV1 等其他编解码器。通常，流从编码源发送到摄取服务器，进行转码并广播到手机、平板电脑、智能电视或电脑等客户端播放设备。点击此链接查看关于 Real-Time Messaging Protocol 的维基百科条目。RTMP 是将音频和视频流式传输到 Facebook、Twitch 和 YouTube 等流媒体服务最广泛采用的协议。

另请参阅 Video Streaming User Guide、Video Stream Out TOP 和 Video Stream In TOP。

有关其他 IP 视频传输技术，见 NDI In TOP、NDI Out TOP 和 NDI DAT、SRT、Touch In TOP、Touch Out TOP。

服务器流摄取

Video Stream Out TOP 支持作为 RTMP 发送方运行。在此模式下，会提供一个 RTMP Destination URL，用于使用指定的流名称连接到指定端口上的 RTMP 摄取服务器。其形式为：

rtmp://<ipaddress>:<port>/<streamName>

e.g.

rtmp://192.168.0.1:554/tdvidstream

编码选项

Twitch 和 Youtube 等流媒体服务对 Video Stream Out TOP 会有类似的最佳设置。搜索「twitch optimal streaming settings」之类的关键词通常就能得到最新答案。有关一些通用对比，请参考 Video Streaming User Guide。

客户端流播放

RTMP 流被 RTMP 服务器摄取后，该流可被转码为多分辨率包，以适配不同网络带宽，然后提供到流媒体端点，供客户端请求播放。客户端请求通常是基于 HTTP 的，例如 Apple 的 HLS 和 Android 的 MPEG-DASH。

TouchDesigner 最终也将支持一系列基于 HTTP 的协议来接收流。有关它当前支持的流类型，见 Video Stream In TOP。

HLS 播放流

HLS 是 Apple 开发的协议。它已成为客户端播放音视频流的行业标准协议。如果你在任何 Apple 平台上推流，很可能通过 HLS 协议推流，视频流也在 HLS 视频播放器中播放。如果你使用 Android 操作系统推流，你可能在用 HLS，但同样也可能在用 MPEG-DASH。

取决于 RTMP 服务器服务提供商，会提供一个 URL，可在任何兼容的 HLS 播放器中播放。HLS URL 通常以该扩展名结尾：m3u8。

例如 https://stream.mux.com/a24aDSqw45425345nF1A1oZmrd7ABW51.m3u8 << 此链接无效。

HLS 流可以在此类基于互联网的播放器中快速测试。

https://players.akamai.com/players/hlsjs

延迟

一个 RTMP 流离开 Video Stream Out TOP 再返回（例如通过使用 Video Stream In TOP 的 HLS 协议）的往返延迟，会因所用服务及其服务位置而有很大差异。Twitch 等服务已将其服务器调优为低延迟，在北美标准高带宽互联网连接下约为 1 至 5 秒。Mux.com 等其他服务则为了播放质量等其他因素，将服务器和网络调优为长达 30 秒的延迟。
