编写 C++ 插件

CPlusPlus 操作符（CPlusPlus CHOP、CPlusPlus TOP、CPlusPlus POP、CPlusPlus SOP 和 CPlusPlus DAT）允许你加载自己编译成插件的 C++ 代码。你可以使用此节点创建自定义滤镜、输出到某种自定义文件格式或设备，或从某种自定义设备或文件格式引入数据。取决于操作符类型，输入和输出、行为和函数名会有所不同，但总体思路相同。虽然这些操作符并不等同于完整的 SDK，但它们提供了许多相同的功能。

用于为 CPlusPlus 节点创建插件的同一份代码，也可以用来创建 Custom Operator。

示例集合位于 following Github repository。安装文件夹中的 Samples/CPlusPlus 文件夹中还有更基础的示例。

接口摘要

TouchDesigner 定义了一个基础 C++ 类，你创建自己的类时需继承它。有些纯虚函数是必须重写的，而其他一些如果你不提供重写方法则会执行默认行为。数据通过其他持有信息的简单类传入和传出函数。

要初始化插件并创建类的实例，你必须指定 3 个 C 函数。第一个会告诉 TouchDesigner 你运行的是哪个 API 版本（通过返回一个头文件中可见的常量）。另外两个会在 TouchDesigner 请求时创建（使用 new）和销毁（使用 delete）类的实例。每个使用该插件的操作符都会创建一个类实例。

示例代码

你可以在 Samples/CPlusPlus/ 文件夹中找到开始制作插件的代码，从 TouchDesigner 的 Help 菜单中选择 "Browse Samples"。该文件夹中每种 CPlusPlus 操作符（CHOP 和 TOP）都有一个子文件夹，包含所有源代码以及 Visual Studio Solution 和 Project 文件，以及一个 Xcode 项目。

头文件中会定义一个基类（例如 TOP_CPlusPlusBase.h），不应编辑它。你要创建此基类的子类。示例目录中已提供了一个示例子类。编程插件所需的大量信息都在这些文件以及基类头文件的注释中。

查看完示例代码并准备制作自己的插件后，将示例代码用作你自己项目的模板。

一般工作流程

一般来说，CPlusPlus 操作符计算时会调用你的类中的一些函数来询问一些问题（例如节点是否应每帧计算）。然后它会调用 execute() 函数，你的类应在此执行实际工作。

在 Windows 上开发插件

编译

Windows 上的插件构建为 DLL。示例是使用 Visual Studio 2015 创建和编译的。

构建产物放在项目旁边。

调试

你可以在 TouchDesigner 运行时将 Visual Studio 调试器附加到它。插件代码中的断点会正常工作。这也是探索 TouchDesigner 传入和传出函数的所有数据结构的好方法。

要在 Visual Studio 中以已附加调试器的方式启动项目，打开项目属性，在调试部分将 TouchDesigner.exe 的完整路径填入 'Command' 部分。如果你已设置 .toe 文件，将其填入 'Command Arguments' 部分。现在你可以按 F5，项目将在附加调试器的情况下在 TouchDesigner 中加载。你会收到一个错误说没有 TouchDesigher.exe 的调试信息，这是预期之中的。当进程执行你的代码时，你会有 .dll 的调试信息。

查看控制台输出

要查看 print 语句输出，使用 std::cout 并设置 Windows 环境变量 TOUCH_TEXT_CONSOLE=1，你会得到一个黑色控制台窗口，显示你的 print 语句（以及 TouchDesigner 的一些一般调试语句）。注意：向控制台窗口打印文本行对性能有很大影响。在进行性能测试或发布最终插件时，务必禁用所有打印。

在 macOS 上开发插件

编译

macOS 上的插件构建为以 .plugin 扩展名命名的 bundle。示例可用 macOS 上最新版本的 Xcode 打开并构建。

与 Visual Studio 不同，Xcode 不会将构建产物与项目源代码放在一起。

  • 要创建用于分发的成品插件，使用 Product > Archive 创建 Archive 构建，然后 Export... 并 Save Built Products。
  • 要在开发和测试期间使用调试构建，在 Xcode 中使用 Product > Build，然后 Product > Show Build Folder in Finder，你的插件将在 Products/Debug 中。现在切换到 TouchDesigner，放置一个 CPlusPlus CHOP 或 TOP 并点击 Plugin Path 参数旁的 + 按钮，再切回 Finder，将插件从 TouchDesigner 屏幕上的选择文件对话框拖入。你可以保存 .toe 用于调试，这样无需重复此操作（见下一节）。

调试

你可以在 TouchDesigner 运行时将 Xcode 调试器附加到它。插件代码中的断点会正常工作。这也是探索 TouchDesigner 传入和传出函数的所有数据结构的好方法。

要以已附加调试器的方式启动项目，编辑项目的 scheme（Product > Scheme > Edit Scheme...），使其 Run 目标在 'Info' 部分以 TouchDesigner 为可执行文件。如果你已设置 .toe 文件，将该文件的路径填入 'Arguments' 部分。调试将正常工作。

查看控制台输出

发送到 std::cout 的消息会出现在 Xcode 的 Debug 区域的控制台中。注意：向控制台打印文本行会影响性能。在进行性能测试或发布最终插件时，务必禁用所有打印。

Python

你的插件可以通过提供暴露方法和成员供用户访问的自定义 Python 类，以及调用 Callback DAT Python 回调，与 Python 交互。参见 CHOPWithPythonClass 示例项目了解如何做到这一点。Note: Python only works when the Plugin is installed as a Custom Operator. It does not work when used within a CPlusPlus node.

Info CHOP 和 Info DAT

所有 CPlusPlus 操作符都支持通过 Info CHOP 和 Info DAT 输出数据。有些函数可指定要输出多少数据，另一些则指定实际要输出的数据。

如何使用自定义参数

CPlusPlus CHOP 和 CPlusPlus TOP 都支持 Custom Parameters。与 Custom Parameters 的创建和管理相关有两个主要函数。第一个是 setupParameters() 函数，第二个是 pulsePressed() 函数。

setupParameters() 函数是所有 Custom Parameters 应定义的地方。下例展示如何创建一个 RGB 自定义参数：

{
	OP_NumericParameter	np;

	np.name = "Color1";
	np.label = "Color 1";
	np.defaultValues[0] = 1.0f;
	np.defaultValues[1] = 0.0f;
	np.defaultValues[2] = 0.0f;

	for (int i=0; i<3; i++)
	{ 
		np.minValues[i] = 0.0f;
		np.maxValues[i] = 1.0f;
		np.minSliders[i] = 0.0f;
		np.maxSliders[i] = 1.0f;
		np.clampMins[i] = true;
		np.clampMaxes[i] = true;
	}
	
	manager->appendRGB(np);

	OP_NumericParameter	npDir;

	npDir.name = "Dir";
	npDir.label = "Direction";
	npDir.defaultValues[0] = 1.0f;
	npDir.defaultValues[1] = 0.0f;
	npDir.defaultValues[2] = 0.0f;

	manager->appendXYZ(npDir);
}

下面的代码片段演示如何获取上述 Custom Parameters 'Dir' 的值。

double dirx = (float)inputs->getParDouble("Dir", 0);
couble diry = (float)inputs->getParDouble("Dir", 1);
double dirz = (float)inputs->getParDouble("Dir", 2);

类似地，这可以在一次调用中完成：

double dirx, diry, dirz;
inputs->getParDouble3("Dir", dirx, diry, dirz);

RGB 和 RGBA 属性应使用 getParRGB(), getParRGBA() 求值，以便在进行 Color Space Workflows 时对值做色彩空间转换。

double r, g, b;
inputs->getParRGB("Color", r, g, b);


如上所述将 Custom Parameters 添加到 manager 类，可从 inputs 类中获取 Custom Parameters 值。

第二个重要的函数是 pulsePressed() 函数。此函数允许你获取自定义脉冲参数的名称和值。下面是从 OpenGLTOP.cpp 源码中 setupParameters() 函数里脉冲参数的定义：

// pulse
{
	OP_NumericParameter	np;

	np.name = "Reset";
	np.label = "Reset";
	
	manager->appendPulse(np);
}

要基于 'Reset' 脉冲参数运行代码，我们可以检查传给 pulsePressed() 函数的 name 参数，如下例所示（来自 OpenGLTOP.cpp 源码中的 pulsePressed() 函数）：

if (!strcmp(name, "Reset"))
{
	myRotation = 0;
}

自定义参数类定义

由于自定义参数扩展现有类，这些类的定义可在 CPlusPlus_Common.h 源文件中找到，随所有 CPlusPlus 示例一同提供。类定义包括：

OP_ParameterManager - 包含添加自定义参数函数的管理器类。

OP_NumericParameter - 用于定义脉冲按钮、开关、浮点参数、整数参数等数值字段的类。

OP_StringParameter - 用于定义基于字符串的字段的类，例如字符串输入、文件或文件夹引用、操作符引用、菜单项等。
