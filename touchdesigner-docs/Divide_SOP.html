Divide SOP

摘要

Divide SOP 用于细分输入的多边形几何。它可以平滑输入的多边形、分割多边形，也可以使用 Bricker 选项对输入多边形进行细分。Bricker 还可用于边数超过四的多边形面，将其切分为四边形和三角形，从而在使用变形工具时获得正确的着色。

divideSOP_Class

参数 - 页

Group group - 如果存在输入组，在此字段中指定组名将使该 SOP 仅作用于指定的组。接受模式匹配，说明见 Pattern Matching。
Convex Polygons convex - 勾选后，此选项会将所有输入多边形凸化到下方字段指定的最大边数。这对于减少凹多边形且着色不正确的多边形的边数很有用。例如，要从所有输入几何生成三角形，勾选此选项并将下方的 Maximum Edges 字段改为 3。你会看到所有多边形都被减少到最多三条边（三角形）。
Maximum Edges numsides - 输入值决定所有输入多边形在超过该数值时会被减少到的最大边数。设置凸化后多边形的最大边数。至少必须有三条边。使用 3-6 范围内的小数值效果最好；生成的多边形不会那么细长。如果输入多边形的边数少于指定值，则这些多边形不会发生任何变化。
Triangulate Non-Planar planar - 对任何非平面多边形进行三角化。
Smooth Polygons smooth - 勾选后，此功能会细分彼此相邻且不平坦的多边形，例如盒子的角。平滑阈值和添加的多边形细分数由下方字段控制。

所有输入几何必须共享点，Smooth Polygons 才能生效。你可能需要让几何经过 Facet SOP ＞ Consolidate Points 来实现这一点。例如，要从盒子创建骰子，先添加 Box SOP，再经过 Facet SOP＞ Consolidate Points，然后用启用 Smooth Polygons 的 Divide SOP 处理；将 Weight 字段设为：4,0.5，Divisions 设为：2。

Weight weight - 决定添加的多边形的局部化效果。你可以将细分限制在几何中存在边缘的位置，大于 1 的值会通过平滑角度过渡来强化边缘。小于 1 的值倾向于把细分放在源几何较平坦的区域，并通过向内收拢边缘显著改变几何的形状。
  • weight1 -
  • weight2 -
Divisions divs - 确定 Smooth Polygons 选项的细分级别。值为 1 时，角部的多边形数量加倍；值为 2 时会再加一倍的细分。值为 3 及更大时可能会增加大量多边形，应谨慎使用——复杂度会呈指数级增长。
Bricker Polygons brick - 选择此选项会将输入的多边形几何分割成网格状的正方形，不过输出并不是 mesh。Brickering 会创建新的多边形。它可用于分割曲面，使其在使用 Creep SOP 包裹到另一个曲面或使用 Lattice SOP 扭曲时变形更自然。

它还可用于将平面表面分割成更小的块，以便使用 Point SOP 施加点颜色。Brickering 创建的正方形细分的大小和位置由以下三个选项决定。

Size size - 设置 bricker 网格细分在三个轴向上的大小。

  • Y sizey -
  • Z sizez -
Offset offset - 设置网格细分相对于 Source 几何的 XYZ 偏移（移动的是 Brickering Grid）。
  • X offsetx -
  • Y offsety -
  • Z offsetz -
Angle angle - 确定创建 Bricker 多边形时相对于 XYZ 轴的角度。
  • X anglex -
  • Y angley -
  • Z anglez -
Remove Shared Edges removesh - 消除任何公共边。
Compute Dual dual - 将多面体转换为其点/面二重体。将多面体转换为其点/面二重体。

Info CHOP 通道

可以通过 Info CHOP 查看 Divide SOP 的额外信息。

SOP 通用信息通道

  • num_points - 此 SOP 中的点数。
  • num_prims - 此 SOP 中的图元数。
  • num_particles - 此 SOP 中的粒子数。
  • last_vbo_update_time - 在另一个线程中根据 SOP 的 CPU 数据更新 GPU 上的几何数据所花的时间。由于它属于另一个线程，此时间不计入通常的帧时间。
  • last_meta_vbo_update_time - 在另一个线程中根据 SOP 的 CPU 数据更新 GPU 上的元表面几何数据（如 metaball 或 nurbs）所花的时间。由于它属于另一个线程，此时间不计入通常的帧时间。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
