TouchDesigner CUDA API 参考

概述

TouchDesigner 与你编写的 .dll 对接所用的 API 是一种调用—应答机制。也就是说，TouchDesigner 会调用你 .dll 中的某些函数，你应在这些函数中填入必要代码，把 TouchDesigner 所需的信息返回给它。大量信息和注释放在 TCUDA_Types.h 文件中而非本文，以确保信息始终与 API 的变更保持同步。

枚举类型

API 定义了许多枚举类型，便于了解结构中某一项的有效取值。例如若结构有一个 TCUDA_DataFormat 类型的成员，从 TCUDA_Types.h 可以看出其有效值为 TCUDA_DATA_FORMAT_UNSIGNED_BYTE 和 TCUDA_DATA_FORMAT_FLOAT。
这里不讨论各种枚举类型，请查看 TCUDA_Types.h 获取相关信息。

结构

API 用结构来向 .dll 发送信息并从 .dll 取回信息。

这里不讨论各种结构，请查看 TCUDA_Types.h 获取相关信息。

填写结构的规则

你会注意到结构是这样声明的（真实结构可能不同）：

 typedef struct
 {
   int reserved[9];
   union
   {
       struct
       {
           int         reserved[9];
       } param;
       struct
       {
           int         reserved[9];
       } chop;
       struct
       {
           TCUDA_DataFormat    dataFormat;
           int                 reserved[9];
       } top;
       struct
       {
           bool        interestedInTransforms;
           bool        interestedInParameters;
           union {
               struct {
                   int projWidth;
                   int projHeight;
               } cam;
           };
           int         reserved[6];
       } obj;
   } ;
 } TCUDA_ParamRequestResult;

首先要注意声明了许多 reserved* 成员。它们用来占位，以便日后向这些结构添加更多功能而不破坏旧的 CUDA .dll。绝不要写入这些 reserved* 成员。其次，结构里有一个 union。根据你写入的参数类型，只应写入这个 union 的一个部分。若不知道 C++ 中的 union 是什么，请参考 this page

例如，若你在回复一个摄像机对象的请求，而结构声明为

 TCUDA_ParamRequestResult *result;

你会像这样写入该结构的各个成员

 result->obj.interestedInParameters = true
 result->obj.cam.projWidth = 512;
 result->obj.cam.projHeight = 512;

重要的是不要写入与该参数数据类型不匹配的结构。因此你不会为对象写入 result->chop 结构。同样，若对象的 subType 不是摄像机，你就不会写入 result->obj.cam。

函数

每个函数向 .dll 提供和/或索取特定信息。有些函数必须定义 .dll 才能工作，有些则不必。你的函数声明必须与 API 期望的完全一致，否则会发生意外（比如崩溃）。声明为 const 的参数是提供给你的信息，帮助你决定怎么做，绝不能修改这些结构中的数据。未声明为 const 的参数，则是你填入信息、告诉 TouchDesigner 它想知道的内容的地方。

必需函数

 int tCudaGetAPIVersion()

此函数必须始终返回 TCUDA_API_VERSION。这让 TouchDesigner 知道该 .dll 是针对哪个 API 版本编写的，从而实现向后兼容。

Parameters：无

Return Value：必须返回 TCUDA_API_VERSION，它在 TCUDA_Types.h 中定义。

 bool tCudaGetParamInfo(const TCUDA_NodeInfo *info, const TCUDA_ParamRequest *request, TCUDA_ParamRequestResult *reqResult)

此函数对每个潜在参数调用一次。它在 request 中提供该参数的信息，你想返回的任何信息都填入 reqResult 参数。返回 true 告诉 TouchDesigner 你对此参数感兴趣，返回 false 表示不感兴趣。

Parameters:

info - 指向 TCUDA_NodeInfo 结构的指针，提供当前正在计算的节点的信息。
request - 指向 TCUDA_ParamRequest 结构的指针，提供此特定参数的信息。 reqResult - 此结构将包含选项，让你规定该参数如何使用。

Return Value：若将使用该参数返回 true，否则返回 false。

 bool tCudaExecuteKernel(const TCUDA_NodeInfo *info, const int nparams, const TCUDA_ParamInfo **params, const TCUDA_ParamInfo *output)

TouchDesigner 调用此函数时，是要求你用给定参数执行你的 CUDA 内核，并把结果写入 output 结构给出的数据指针。

Parameters:

info - 指向 TCUDA_NodeInfo 结构的指针，提供当前正在计算的节点的信息。
nparams - params> 数组中的条目数。
params - 一个指针数组，指向可用作 CUDA 内核输入的参数。该数组中列出哪些参数，取决于你从 tCudaGetParamInfo 返回的内容。
output - 指向一个结构的指针，该结构包含内核应把输出写到哪里这类信息。根据你的输出设置（数据格式、分辨率、通道数等），该结构的 data 成员将是已分配的、足以存放输出的 CUDA 设备内存。

Return Value：若已执行内核、OP 应从输出更新其数据则返回 true；若什么都没做（因此 OP 不必从输出更新数据）则返回 false。

可选函数

你可以选择不定义这些函数。对于可以返回信息的函数，TouchDesigner 会对未定义的函数采用某些默认值。

 void tCudaNodeAttached (const TCUDA_NodeInfo *info)

此函数在节点首次连接到该 .dll 时调用。

Parameters:

info - 指向 TCUDA_NodeInfo 结构的指针，提供正在连接到此 .dll 的节点的信息。

Return Value：无

  void tCudaNodeDetached(const TCUDA_NodeInfo *info)

此函数在节点从 .dll 断开时调用。发生在节点被删除或加载另一个 .dll 时。

Parameters:

info - 指向 TCUDA_NodeInfo 结构的指针，提供正在连接到此 .dll 的节点的信息。

Return Value：无

  void tCudaGetGeneralInfo(const TCUDA_NodeInfo *info, TCUDA_GeneralInfo *ginfo)

此函数向 .dll 索取一些它可以自行填写的一般信息。ginfo 将包含默认值，你可以根据希望 OP 如何表现来修改它们。

Parameters:

info - 指向 TCUDA_NodeInfo 结构的指针，提供当前正在计算的节点的信息。
ginfo - 指向 TCUDA_GeneralInfo 结构的指针，你可以在其中填入信息。

Return Value：无

  bool tCudaGetTOPOutputInfo(const TCUDA_NodeInfo *info, TCUDA_TOPOutputInfo *oinfo)

Only called if the OP is a TOP. 此函数让你在代码中指定 TOP 的输出，而不必在 Common 页中设置，也不必依赖输入 TOP 的设置。

Parameters:

info - 指向 TCUDA_NodeInfo 结构的指针，提供当前正在计算的节点的信息。
oinfo - 在此参数中填入 TOP 期望输出的信息，如分辨率和像素格式。

Return Value：若希望 TouchDesigner 使用这些设置则返回 true；若希望它用 Common 页决定输出设置则返回 false。返回 false 与完全不定义此函数相同。

 void tCudaGetTOPKernelOutputInfo(const TCUDA_NodeInfo *info, TCUDA_TOPKernelOutputInfo *oinfo)

Only called if the OP is a TOP. 此函数让你指定内核数据如何输出的选项，如通道顺序或数据格式。若未定义此函数，将使用默认设置（BGRA、8 位无符号字节等）

Parameters:

info - 指向 TCUDA_NodeInfo 结构的指针，提供当前正在计算的节点的信息。
oinfo - 在此参数中填入内核期望输出的信息，如通道顺序和数据格式。

Return Value：无

其他重要概念

主机内存与设备内存

CUDA 文档定义了主机内存和设备内存。简而言之，主机内存是 CPU 能访问的内存，你可以在任何 C++ 函数中读写它。传给 tCuda* 函数以及从这些函数返回的所有结构都在主机内存中。设备内存是 CUDA 能访问的内存，只能在 CUDA 内核内部读写。在 CUDA 内核之外的任何地方尝试读写设备内存指针都会导致崩溃。同样，在 CUDA 内核中尝试读写主机内存指针会导致内核无法正确运行。

TouchDesigner 给你内存指针时，它们会声明为 void*。除指针外，结构还会有一个 dataLocation 成员，告诉你该指针指向主机内存还是设备内存。你需要把这些指针转换为正确的类型并正确使用。例如在 tCudaExecuteKernel 中，output 结构包含一个名为 data 的成员。该指针总是指向设备内存中 CUDA 内核应写入结果的位置。调用内核时你应把这个指针传进去。

当你拿到主机内存指针时，首先需要把它转换为正确的类型。例如若类型为 TCUDA_DATA_TYPE_FLOAT，你会这样转换第一个参数中的数据指针

 float *flts = (float*)(params[0]->data);

然后就可以这样访问这些值

 float addition = flts[0] + flts[1]; // 把第一个值和第二个值相加。

把这些值传给 CUDA 内核时，需要逐个传值。不能直接传 flts，因为那是指针，CUDA 会认为它是指向设备内存的指针。

RGBA 与 BGRA

在 TOP 中工作时你会注意到像素格式写成 TCUDA_PIXEL_FORMAT_RGBA8 这样，但另外还有所谓的通道顺序，通常是 TCUDA_CHAN_BGRA。RGBA8 只是说有 R、G、B 和 A 通道，并不表示它们的顺序。通道顺序说明实际的通道顺序。我们只允许以 BGRA（而非 RGBA）通道顺序处理，因为这是 GPU 原生存储数据的通道顺序，性能更好。
