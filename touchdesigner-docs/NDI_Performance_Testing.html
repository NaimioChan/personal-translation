NDI 性能测试

NDI 是一种网络协议，迅速在视频分发和播放领域获得关注。本文介绍 2019 年 10 月在墨西哥 Cocolabs 与 Derivative 合作进行的一次 NDI 性能测试。测试目标是尝试找出各种计算机和网络技术的最大吞吐量，并解决与 Dante 音频协议等其他网络技术相关的问题。

关于在同一网络基础设施上使用 NDI 和 Dante，请参见 Dante 页上的 Using Dante with NDI。

重要的交换机与网卡配置

  • 确保发送和接收端的硬盘持续读写速度都高于 1.3 GB/s。
  • 确保网卡为 10Gbe，如果是扩展卡，要确保安装在正确的 PCI 插槽中。
  • 通常这要求插槽支持 x4。
  • 确保计算机芯片组和网卡驱动为最新版本。最新驱动通常不在「品牌」或「制造商」网站上。例如要查找 ASUS XG-C100C 驱动，必须前往芯片厂商网站 https://driverdownloads.aquantia.com/，搜索部件号 AQC107 / 选择操作系统等。

10Gbe 网络交换机测试

在开始使用 NDI 测试网络带宽之前，首先要确定单个 10 Gbe 交换机能被视频数据饱和到什么程度。使用标准基准测试时，交换机的最大可能负载是多少？随后进行了以下实际测试。

合成测试（Crystal Mark）

对于测试平台中的所有网卡和交换机，都可以完全或非常接近地饱和完整的 10 Gb/s（1.25GB/s）。为此，发送端和接收端都需要支持超过 1.3 GB/s 的硬盘。

测试网络带宽

以下简单测试已被证明可靠且易于执行。它提供了清晰的统计数据，在判断交换机设置和功能性能时结果一致。因此我们建议使用默认设置的 CrystalDiskMark，来对比你自己对网络和计算机硬件性能的分析。

https://crystalmark.info/en/software/crystaldiskmark/

Crystal Disk Mark 可通过在共享网络位置上执行标准驱动器测试来测试网络带宽，该位置所在的驱动器需支持高于 1300 MB/s 的持续读写速度。

以下小节说明如何获得该基准测试结果。需要两台计算机。一台是配有高速硬盘的系统。第二台能够通过 Windows 网络以挂载驱动器或共享位置的方式访问该高速硬盘。

在 Derivative 的测试中，配有最快硬盘的计算机是名为 Galactus 的视频服务器测试平台。为准备运行测试，在服务器和辅助网络计算机（在我们的例子中名为 Jupiter）上都安装了 CrystalDiskMark。高速硬盘在网络中共享。两台计算机上的所有其他网卡均已禁用。

在 Galactus 本地运行 Crystal Mark 可显示 D 视频驱动器的性能（7 块磁盘的 SATA Raid 0 阵列，运行在 12Gb/s SAS PCI 扩展卡上）。可以看到第一行测试的读/写性能为 3633/3217 MB/s，远高于 10 Gb/s 或 1250 MB/s 的交换机最大带宽。

接下来在同一驱动器上执行相同测试，但在同一 10G 网络上的另一台计算机上运行。使用 Select Folder 下拉菜单访问有效的网络位置。

可以看到，基于网络的基准测试在所有测试中得分都低得多，第一行测试的读/写速度为 1185/1025。

最初的目标之一是确保网络交换机和网卡以其最大能力运行。可能导致交换机性能不理想的因素有很多。借助这套易于使用的基于网络的基准测试设置，测试网络网卡和交换机设置可以变得很直接。接下来几节将介绍搭建音视频网络时需要注意的一些重要功能。

MTU 大小 - 巨型帧 / 巨型数据包

MTU 代表最大传输单元，即在单次网络层事务中可以传输的最大协议数据单元（PDU）大小。

https://en.wikipedia.org/wiki/Maximum_transmission_unit

大多数受管交换机和质量较高的网卡都支持一项设置，可以增大 MTU，从而用更少的单个数据包发送更多数据。该设置通常称为 Jumbo Frames 或 Jumbo Packets。

要配置网卡，请使用网卡属性对话框并点击「Configure…」按钮。 （Control Panel → Network & Internet → Ethernet → Change Adapter Options → Ethernet Adaptor → Properties → Configure → Advanced）

在配置对话框中，使用 Advanced 页访问可自定义的设置。每个网卡适配器的 Advanced 页配置都会略有不同。通常网卡的 Jumbo Packets 是禁用的。

如果要使用 Jumbo Packets 提升网络性能，重要的是同一网络上的所有网卡都能使用指定的数据包大小。同时，最大大小必须受交换机支持。

在 BS-MP2008 的交换机手册中快速搜索「Jumbo」得到以下内容。

因此可以看到网卡最高支持 16348 字节，而交换机最高仅支持 9216 字节。（交换机手册确实写的是 9216 frames，但那是翻译错误。）

因此网卡的最大设置应为 9014 Bytes，而 Jumbo Frames 必须使用交换机配置工具启用。每台交换机都不同，因此你必须查阅交换机文档，了解可用的配置选项。

Buffalo BS-MP2008 交换机有一个简单的配置面板，可以通过网页浏览器访问。

测试网络功能的最后说明

这是我们找到的最便捷的方法，用于对照实际测试来测试、重测和复核系统/网络性能。我们鼓励其他人也尝试同样的方法，并将结果与我们的进行对比。

NDI 测试

迄今为止我们进行了 NDI 3.8 和 NDI 4.1 测试。测试相当全面，有时令人困惑，过程中我们发现了各种问题，有些已解决，有些仍未解决。

性能评估

讨论性能时，我们主要关注播放「看起来」如何。我们仍然没有数字指标来衡量收到了多少帧、丢了多少帧或漏了多少帧等。唯一的测试方法是用肉眼观察发送端和接收端的信号，并通过「白线测试」观察丢帧来判断播放速率。

什么是白线测试？

「白线测试」是一种用肉眼评估播放质量的方法。用一条垂直线从左到右线性往返扫描，眼睛很容易捕捉到哪怕单帧丢失，或任何其他伪影，例如扫描线不同步导致的水平撕裂。

NDI 测试结果与分析

阅读以下图表，我们可以查看每新增一路流时的 CPU、GPU 和网络负载。第 0 行是发送端运行一个 TouchDesigner 文件，从磁盘流式播放单个 HAPQ 影片并经过「白线测试」组件。此时没有活动的 NDI 流，因此这建立了基线负载。

使用 Windows 任务管理器测量约 1 分钟内的最大 CPU / GPU / 网络负载值。做法是观察任务管理器的图表，同时留意白线播放。

丢帧值是根据测试人员观察丢帧视频的经验做出的最佳估计。每 2 秒丢 1-2 帧以上在许多情况下会被认为不可接受，当然在其他情况下完全可以接受。为清楚起见，我们将任何频繁丢帧都视为失败，并与正确配置的 Displayport 或 SDI 视频信号对比，因为本测试的目标是实现无瑕播放。

所有测试都使用同一个名为 Flares.mov 的视频文件。该文件是从 Cocolab 设计团队生成的 6 个视频中选出的，用以代表他们在实际用例中会生成的内容类型。之所以从这 6 个中选它，是因为它的内容最「嘈杂」，因此可能对 NDI 压缩引擎最具挑战性。这里值得一提的是，很容易彻底搞坏 NDI 压缩器，因此阅读「Breaking NDI Compression」一节很重要。

每一行是再增加一路流，随着流数量增加，我们可以看到发送和接收计算机的 CPU、GPU 和网络带宽负载如何上升。最后的红色行是 TouchDesigner 自身开始丢帧的位置，因为负载超出了 TouchDesigner 的处理能力。

这里可以看到，一旦超过单路流，NDI 3.8 通常就会丢一两帧。超过 3 路流后，丢帧会达到不可接受的程度。随着流数量增加，发送端计算机的负载相当小。这对于希望集中渲染能力并将信号流式传输到专用于显示/投影的服务器的人来说是好消息。

在撰写本文的过程中，NDI 4.0 发布，其播放效果非常差，即使只有单路流也每秒丢很多帧。NDI 4.1 在播放质量上明显改善。我们很高兴看到这个最新版本大幅解决了该问题。

从这些统计中也清楚地看到，CPU 和 GPU 负载大幅增加。NDI 3.8 接收端负载为 CPU 25%、GPU 33%，而 NDI 4.1 为 CPU 30%、GPU 66%。同时网络负载从 653 略降至 523 Mb/s。

压缩画质从 3.8 到 4.1 也有很大提升。详情请参见压缩质量一节。

增加更多接收方

NDI 只在建立连接时才开始发送数据。 再增加一个连接到同一 NDI TOP Out 的接收方 NDI TOP In，对带宽的影响与将接收方连接到另一个 NDI Out 相同。带宽基本上会翻倍。 增加更多接收方会给发送端计算机增加少量负载，同时使发送端出站网络再增加一整路流的带宽。

压缩质量

NDI 基本上无需设置。不过它会随分辨率提高而增加压缩。分辨率越高的图像压缩越强。分辨率较低的图像看起来更好。下图中，同一视频的二次裁剪画面合成在 3840x2160 主信号之上。NDI 4.1 的裁剪画面为 330x198。裁剪版本的压缩质量要干净得多。

HAPQ 通常看起来比 NDI 好得多，但占用带宽也大得多。在压缩测试案例中，单路 3840x2160 @60Hz 的流使用 NDI 占用 260 Mb/s 带宽，而 HAPQ 大约需要 6 倍，即 1.8 Gb/s。

延迟 / 时延

在我们的测试平台上，NDI 似乎天然比 TouchIn/Out 落后约 10 帧。因此 NDI 的延迟比 TouchIn 和 TouchOut 更大

NDI 对某些内容效果不佳

与任何压缩编码一样，要注意在 TouchDesigner 中很容易创建难以压缩的内容。粒子、像素着色器以及大量噪声的内容，与实拍等内容相比往往压缩效果不佳。测试过程聚焦于单个内容——即 Flares.mov 文件。NDI 性能会因输入内容类型的不同而剧烈变化。AV 测试套件中包含一系列可能或至少曾经导致 NDI 失败的信号——结果表现为丢帧增加或出现纯绿输出等伪影。你应熟悉这些情况，并警惕可能将 NDI 推入这些性能瓶颈的内容。

巨型帧对 NDI 有影响吗？

在我们的可视播放分析中，没有发现开启或关闭巨型帧有任何区别。因此我们两种做法都不推荐。

NDI 故障排查

  • 更改网络拓扑后，重启所有计算机（尤其是发送端）可能会有帮助。mDNS 似乎会卡住，以为自己有连接，而实际上看的是旧 IP 地址，因此发现机制似乎不会发生。我们见过 NDI 变得非常混乱，检查防火墙设置后唯一能做的就是重启。
  • NDI 经常进入一种状态：接收 TOP 的信息报告已连接，但收不到视频。使用 NDI Monitor App 会得到黑图，图像顶部有绿色和红色条。处于此状态时，即使从其 Test Pattern 应用发送测试图案，NDI Monitor 也只收到黑色。它能在菜单中看到信号，但没有任何数据通过。处于此状态时，即使发送端的 NDI 流已不再活动，接收端仍能检测到它们。我们发现的唯一修复方法是重启发送端计算机。重启客户端无济于事。这通常发生在修改网络设置时。
  • 要让单路 4K 流流畅播放，唯一可靠的方法是让它成为唯一的流。第二路流往往会导致两路输入都丢帧。
