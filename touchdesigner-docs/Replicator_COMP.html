Replicator COMP

摘要

Replicator COMP 会创建组件的副本，为表格中的每一行创建一个，或通过 Number of Replicants 参数指定数量——它是操作符的「for 循环」。与 Clone 不同，它会自动创建主组件的副本。

它创建复制节点（「replicants」），并在表格变化或复制数量变化时删除它们。复制母版可以是完整的组件及其内容，也可以是单个节点。

它取 Master Node 参数指定的节点，为 Template Table 中的每一行（或 Number of Replicant 参数指定的数量）创建一份母版副本。

创建的节点可以通过两种方式命名。副本可以使用 Node Prefix 参数指定的前缀按顺序命名/编号：item1、item2…… 或者，副本可以根据表格某一列中的字符串命名，该列由 Name from Table 参数指定。

如果你想为表格的第一行创建节点，请取消设置 Ignore First Row 参数。

复制节点会在网络中按网格排列，具体由 Layout 和 Layout Origin 参数决定。

Replicator 不假定也不要求母版和复制节点是组件——如果你愿意，它们可以全都是 Movie File In TOP。它也不假定也不要求复制节点是 Clones。不过，Master Node 可以是一个组件，其 Clone 参数设为自身，这样创建的所有节点都是母版的克隆。

对于每个复制节点，你可以在 callback DAT 中运行脚本，其中有一些可参照修改的典型用例示例。以下还有一些其他示例：

  • 更改 parameter 的表达式：c.par.display.expr = "op('thing')[op.digits, 'display']"
  • 更改参数表达式模式：c.par.display.mode = ParMode.EXPRESSION 模式为以下之一：ParMode.CONSTANT、ParMode.EXPRESSION 或 ParMode.EXPORT。

如果表格只有一行发生变化，其他现有复制节点不会被更改或重新创建。在 callback DAT 中，删除 onRemoveReplicant() 会让复制节点保留下来，待表格再次增长时重新使用。

这是一种极其强大的节点类型。例如：(1) 为表格的每一行创建一个按钮控件；一个几何组件在 3D 粒子系统的每个点处复制，各自独立行为。(2) 你可以将 Multi Touch In DAT 的表格直接输入 Replicator，在每个指尖处创建内容。

参数 - Replicator 页

Replication Method method - - 选择使用 Template DAT Table（每一行创建一个复制节点），或使用下方的 Number of Replicants 参数设定复制数量。
  • By Number bynum -
  • By Table bytable -
Number of Replicants numreplicants - 当上方的 Replication Method = By Number 时，设置复制数量。
Template DAT Table template - 驱动复制过程的表格 DAT 的路径。
Name from Table namefromtable - - 节点名称的生成方式。
  • Row Index rowindex - 使用 Node Prefix 参数后接行号。默认创建名为 item1、item2、item3 …… 的节点。（第一行为 0）。
  • Column by Index colbyindex - 节点名称位于由列号指定的列中。
  • Column by Name colbyname - 节点名称位于由第一行中的列名指定的列中。
Ignore First Row ignorefirstrow - 不为第一行创建节点。
Column Name colname - 列顶部的名称。
Column Index colindex - 列号，从 0 开始。
Operator Prefix opprefix - 将此前缀添加到所有节点。
Master Operator master - 要复制哪个节点或组件。
Destination destination - 复制节点的放置位置。如果位置为 ..，则把节点放在父级内，实际上与 Replicator 组件同级。如果填 .，则放在自身内部，即 Replicator 组件内部。如果留空，将会报错。
Maximum Operators domaxops - 启用下方参数以设置允许的最大复制数量。
Maximum Operators maxops - 复制的最大节点数。
Script tscript - 仅 Tscript（在 Python 中使用 callback DAT）：对于每个复制节点，你可以运行脚本来相对于母版自定义它，例如设置 Display 或 Clone 参数，或 Render 标记。Replicator 运行该脚本命令，以逐个自定义每个复制节点相对于母版的设置。此处可以使用 me.curItem 来访问当前项并对其进行修改。从右侧下拉菜单中选择 3 个条目之一可查看一些示例。

如果使用 Tscript，会定义一些局部变量：

  • $ITEM 当前正在复制的节点名称。
  • $MASTER 母版节点名称。
  • $LOCATION 位置组件名称。

最常见需求是母版不显示、复制节点显示。对于 Panel 组件，最常见的是「opparm $ITEM paneldisplay ( 1 )」；对于 Geometry 组件，最常见的是「opset -d on $ITEM」。使用弹出菜单获取一些常用脚本。

Script Names scriptmenu - 从此菜单中选择一些常用脚本（Tscript）。
Callbacks DAT callbacks - 包含所收到每个事件回调的 DAT 路径。用法见 replicatorCOMP_Class。
Layout layout - - 新节点的布局方式——全部放在一处（Off）、水平、垂直或网格。
  • Off off -
  • Horizontal horizontal -
  • Vertical vertical -
  • Grid grid -
Layout Origin layoutorigin - - 新节点的布局位置，给出左上角节点左下角的 XY 位置。
  • layoutorigin1 -
  • layoutorigin2 -
Incremental Update doincremental - 启用下方参数以增量创建复制节点。
Incremental Update increment - 错开操作符的复制过程，以避免创建复制节点时出现大幅掉帧。如果 Incremental Update 开启，每帧最多创建指定数量的复制节点，默认每帧 1 个。
Recreate All Operators recreateall - 删除它创建的所有节点，然后使用模板及其当前参数重新创建它们。
Recreate Missing Operators recreatemissing - 根据模板表格重新创建缺失的操作符，但不会删除并重新创建已存在的复制节点。

参数 - Extensions 页

Extensions 参数页设置组件的 Python 扩展。更多信息请参阅 extensions。

Re-Init Extensions reinitextensions - 重新编译所有扩展对象。通常只有在扩展对象被引用且其定义已更改时，扩展对象才会被编译。
Init Extensions On Start initextonstart - 在 TouchDesigner 启动时自动执行 Re-Init
Extension ext - 用于在此组件上创建扩展的信息序列
Object ext0object - 可附加到组件的类实例数量。
Name ext0name - 可选，用于搜索的名称，代替实例类名。
Promote ext0promote - 控制扩展是直接在组件层级可见，还是必须通过 .ext 成员访问。示例：n.Somefunction 与 n.ext.Somefunction

参数 - Common 页

Common 参数页设置组件的 node viewer 和 clone 关系。

Parent Shortcut parentshortcut - 指定一个名称，可在组件内任意位置用作该组件的路径。参见 Parent Shortcut。
Global OP Shortcut opshortcut - 指定一个名称，可在任何位置用作该组件的路径。参见 Global OP Shortcut。
Internal OP iop - 内部操作符的序列标题。
Shortcut iop0shortcut - 指定一个名称，可在组件内任意位置用作下方「Internal OP」的路径。参见 Internal Operators。
OP iop0op - 此组件内 Internal OP 的路径。参见 Internal Operators。
Operator Viewer opviewer - 当上方的 Node View 参数设为 Operator Viewer 时，选择使用哪个操作符的节点查看器。
Enable Cloning enablecloning - 控制该 OP 是否应持续克隆。关闭此项会使此节点停止克隆其「Clone Master」。
Enable Cloning Pulse enablecloningpulse - 立即克隆内容。
Clone Master clone - 用作 Master Clone 的组件路径。
Load on Demand loadondemand - 仅在需要时将组件加载到内存。适用于项目中并非总是使用的组件。
Enable External .tox enableexternaltox - 开启时（默认），.toe 启动时会加载外部 .tox 文件，COMP 的内容将与该外部 .tox 一致。如有需要，可以关闭此项，以避免启动时从引用的外部 .tox 加载（COMP 的内容改为从 .toe 文件加载）。如果你希望某个 COMP 引用外部 .tox，但不总是从它加载，除非你特意按下 Re-Init Network 参数按钮，这会很有用。
Enable External .tox Pulse enableexternaltoxpulse - 此按钮会从外部 .tox 文件重新加载（若存在）。
External .tox Path externaltox - 磁盘上 .tox 文件的路径，该文件会在 .toe 启动时作为组件内容的来源。这让组件可以包含能独立更新的网络。若找不到 .tox 文件，则会加载 .toe 文件保存时的内容。
Reload Custom Parameters reloadcustom - 启用此复选框后，重新加载 .tox 时会重新加载组件 Custom Parameters 的值。这仅影响组件上的顶层参数；组件内节点上的所有参数始终随 .tox 重新加载。
Reload Built-In Parameters reloadbuiltin - 启用此复选框后，重新加载 .tox 时会重新加载组件内置参数的值。这仅影响组件上的顶层参数；组件内节点上的所有参数始终随 .tox 重新加载。
Save Backup of External savebackup - 启用此复选框后，由 External .tox 参数指定的组件的备份副本会保存在 .toe 文件中。若找不到 External .tox，将使用此备份副本。出现这种情况可能是因为 .tox 被重命名、删除，或 .toe 文件在另一台缺少组件媒体的电脑上运行。
Sub-Component to Load subcompname - 从外部 .tox 文件加载时，此选项允许你深入 .tox 取出一个 COMP，并将其作为顶层 COMP，忽略文件中的其他所有内容（该 COMP 的内容除外）。例如，若名为 project1.tox 的 .tox 文件包含 project1/geo1，将 geo1 设为 Sub-Component to Load，就会加载 geo1 来替代当前 COMP。若此参数为空，则按常规使用文件中的顶层 COMP 加载 .tox 文件。
Relative File Path Behavior relpath - - 设置此 COMP 内的子文件路径是相对于 .toe 本身还是 .tox，或从父级继承。
  • Use Parent's Behavior inherit - 从父级继承设置。
  • Relative to Project File (.toe) project - 当指定为相对路径时，该路径将相对于 .toe 文件。
  • Relative to External COMP File (.tox) externaltox - 当指定为相对路径时，该路径将相对于 .tox 文件。未指定外部 COMP 文件，或 Enable External .tox 未开启时，此项没有影响。

Info CHOP 通道

可通过 Info CHOP 访问 Replicator COMP 的额外信息。

COMP 通用信息通道

  • num_children - 此组件中的子级数量。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
