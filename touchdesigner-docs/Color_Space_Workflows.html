色彩空间工作流

概述

首先，请确保你已读过 Color Space 文章，以了解色彩空间概念的高层概述。

默认情况下，TouchDesigner 不具备色彩空间意识，运行在我们现在称为 Pass-Through 的模式下。这意味着所有颜色都从文件中原样载入、原样组合/合成，并原样输出到显示器和文件。不加任何其他干预时，这个工作流实际上是不正确的，因为引入的内容很可能带有非线性传递函数（例如 sRGB），而光照/合成只应使用线性传递函数完成。不过图像和影片在输出时通常看起来是正确的，因为它们载入时仍带着那个传递被应用，然后显示时也带着该传递，而它通常与显示器的传递相匹配（至少在处理 sRGB 内容时如此）。2025.30000 系列之前的所有版本都存在这一缺陷。

为避免破坏已有文件，新的色彩正确工作流需要按项目逐一选择启用。

工作色彩空间

工作色彩空间定义了项目中存储的所有颜色值如何保存。这包括 SOP 和 POP 属性的颜色，以及 TOP 中保存的颜色。无论源颜色定义在哪个色彩空间（例如大多数图像会是 sRGB），载入时它们都会被转换到工作色彩空间。项目只有单一的工作色彩空间，以避免把某个色彩空间中的 TOP 与另一个不同色彩空间中的 TOP 组合时可能出现的混淆和错误。

RGB 颜色参数

所有颜色参数在被求值并由节点使用时，都会自动转换到工作色彩空间。用于控制把值视为哪个色彩空间的参数位于带颜色参数的节点的 Common 页上。这称为 Parameter Color Space。

TOP 纹理数据

引入外部数据的 TOP（Movie File In TOP、Video Device In TOP）会尝试检测源内容的色彩空间，并在引入数据时把它转换到工作色彩空间。如果检测不到，则假定为 sRGB，但有一个参数可以显式指定把输入视为哪个色彩空间。

把 TOP 输出到 Movie File Out TOP、Video Device Out TOP 等时，你需要指定输出前希望把内容转换到哪个色彩空间。如果可能，这些节点还会把内容标记为该色彩空间（当输出协议支持时）。某些协议（如 SDI）在其元数据中只支持非常有限的色彩空间。

GLSL 节点现在有一个新的「Colors」标签页，它把这些 uniform 与常规的 Vector uniform 区分开

POP 颜色属性限定符

POP 属性在创建时可以赋予 Color 限定符，这会使用来填充其默认值的参数从 Parameter Color Space 转换为 Working Color Space。由参数创建的 POP 颜色属性会被转换到工作色彩空间。通过外部几何格式导入的颜色也会被转换到工作色彩空间。

启用色彩空间工作流

色彩空间正确的工作流是一个按项目选择启用的功能。这样做是为了避免改变已有项目和组件的行为。但请注意，依赖 Pass-Through 行为的 .tox 文件在色彩空间正确的项目中使用时，表现可能不同。

You will need to save your .toe and restart it for color space changes to take effect.

注意： 你可以使用 Preferences Dialog 的「Color」标签页，或在 Python 中通过 Project Class 直接控制这些设置。

工作色彩空间

工作色彩空间是所有图像/影片和颜色值在用于处理之前都会被转换到的色彩空间。所有 TOP 都把数据存储在这个色彩空间中。输出时，内容会按输出目标的要求转换到正确的色彩空间。

要选择项目的工作色彩空间，请使用 

 project.workingColorSpace

它接受以下值 

 WorkingColorSpace.PASS_THROUGH
 WorkingColorSpace.SRGB_LINEAR
 WorkingColorSpace.ACES_CG
 WorkingColorSpace.DCIP3_LINEAR
 WorkingColorSpace.REC_2020_LINEAR

PASS_THROUGH 是所有项目的默认状态，与 2025.30000 系列之前发布的所有版本行为一致。 ACES_CG 强制所有 TOP 为 16 位浮点，所有颜色都将处于 ACEScg 色彩空间并使用线性传递。 SRGB_LINEAR 表示所有颜色都将处于 sRGB 色彩空间，并使用线性传递函数处理。但是，任何 8 位 RGBA 纹理都会使用 sRGB 传递函数来 store 其数据。这样做是为了给较暗的颜色提供更多细节。这并不意味着你会看到颜色变化如同对图像应用了 gamma。它只意味着较亮的颜色值会被舍入到 8 位所能容纳的 256 个色阶中更粗的台阶。

编辑器窗口像素格式

用于向操作系统输出内容的像素格式同时决定内容的位深，以及内容是否支持 HDR。对于 Perform 窗口，这是在 Window COMP 中选择的。不过主编辑器窗口可以用以下方式选择

 project.editorWindowPixelFormat

它接受以下值： 

 WindowPixelFormat.SDR8_FIXED
 WindowPixelFormat.SDR10_FIXED
 WindowPixelFormat.HDR10_FIXED
 WindowPixelFormat.HDR16_FLOAT

如果你的编辑器窗口设为 HDR 格式，但显示器未处于 HDR 模式，那么你可能会遇到模式切换，因为操作系统会自动把它切换到 HDR 模式。建议在使用 HDR 窗口像素格式时，先让显示器处于 HDR 模式。

请注意，这并不直接控制你的显示器运行在哪个色彩空间，也不控制通过线缆发送给显示器的内容。它只控制 TouchDesigner 发送给操作系统的内容。TouchDesigner 和操作系统会就每种像素格式使用哪个色彩空间达成一致，然后操作系统可能再做一次从该色彩空间到显示器所需色彩空间的转换。 使用 16 位浮点（你的 GPU/操作系统很可能支持）并不意味着会把 16 位浮点数据发送给显示器。

发送给显示器的数据位深通常在你的 GPU 驱动设置中控制。
