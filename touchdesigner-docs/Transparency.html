透明

简答

有两种方法可以渲染正确的透明效果：
1. 以由远及近的顺序渲染物体并开启混合（设置起来很费工夫）。关于对实例、单个多边形和其他图元进行排序和渲染，请参见下文“排序与混合”一节。
2. 使用 Render TOP 中的 “Order-Independent Transparency” 功能（简单，但会占用更多图形处理器资源）。

如果情况需要，你可以组合使用这两种方法（放在两个独立的 Render TOP 和 Render Pass TOP 中）。

对几何物体排序

要渲染多个带有一定透明度的 Geometry 物体：

  • 在要设为透明的物体的 MAT 的 'Common' 页中开启 'Blending'。
  • 调整透明物体的绘制顺序，确保它们按由远及近的顺序绘制。这通常在 Geometry COMP 的 'Render' 页上通过调整 'Draw Priority' 参数完成。数值越低表示越晚绘制，因此较近的物体应比较远的物体取值更低。

在一个 Render TOP（或 Render Pass TOP）中先绘制所有不透明几何。如果追求最高速度，尽量确保这些不透明物体按由近及远的顺序绘制。然后在另一个 Render Pass TOP 中，按由远及近的顺序绘制所有透明物体，并在它们所有 MAT 的 Common 页中开启 Alpha Blending（这一点很重要！）。如果你的几何全部是透明的，可以忽略第一次渲染，直接在第一个 Render TOP 中按由远及近的顺序渲染所有几何。你可以使用 Geometry COMP 中的 “Draw Priority” 参数控制几何的绘制顺序。

这种技术非常快，但设置起来很费工夫。简单的情况是摄像机和几何的位置都静止不动，但一旦摄像机或几何移动，就需要动态设置 Draw Priority 参数。以下文件展示了若干场景

顺序无关透明度

此功能在 Render TOP 的参数页中启用。启用后，几何的绘制顺序不再重要。同时你*不应*在 MATs 中开启 Alpha Blending。透明度通道数控制结果的质量（几何越复杂，需要越多通道才能在视觉上正确），但通道越多渲染速度越慢。 此过程是多通道的。对于每个像素，最近的表面在第一通道渲染，第二近的表面在第二通道渲染，直到下方 Transparency Passes 参数指定的通道数。开启此选项会禁用 Render TOP 中的一些高级功能以及抗锯齿。你可以改用 Anti Alias TOP 在之后对场景进行抗锯齿处理。

它使用一种称为 Depth Peeling 的技术。首先渲染正常的一帧。在下一次渲染时，剥离第一帧中看到的所有像素，露出它们下面的像素。下一帧再做同样的事，剥离第 2 次渲染中能看到的像素。依此类推。所有渲染完成后，从最远的层开始，逐层将每层 Over 合成到其他层上。

以球体为例，你需要 2 个通道，第一个通道渲染球体的正面，第二个通道渲染球体的内部。

如果你有 10 个球体，一个在另一个后面。你需要 19-20 个通道才能得到正确的图像。

如果你有 10 个球体，在屏幕上彼此并排，则只需要 2 个通道。

不过实际上，你只需要 3-5 个通道就能得到可接受的图像。它可能不是 100% 正确，但看起来会非常接近正确。 每个通道都是一次完整渲染，因此每个通道都会带来显著开销。

Alpha 到覆盖率

Alpha-to-coverage 是一种在非常繁复的场景中伪造透明效果的取巧方法。启用后，渲染像素的 alpha 值将控制抗锯齿缓冲区中有多少子采样用于生成该像素的最终颜色。例如，使用 8x 抗锯齿时，每个像素有 8 个可能的子采样用于构建其最终颜色。使用 alpha to coverage 时，如果几何覆盖了全部 8 个子采样，输出 alpha 为 0.5 意味着只会用到其中的 4 个。这种透明模式只在特定情况下有效，通常只适用于非常繁复的粒子系统。

完整解答

关于 OpenGL 的一个常见误解是：它只需将 alpha 应用到几何上就能支持透明。这是不正确的，OpenGL 中没有任何功能会隐式实现透明。

OpenGL 中的透明度是通过一种称为 Alpha-Blending 的功能实现的。它本质上是用渲染几何的 alpha 作为混合系数，与场景中的其他几何混合。透明就是将较远物体的颜色与较近物体的颜色混合。要正确地做到这一点，较远的物体必须已经绘制完成，这样较近的物体才有可混合的颜色。如果处理正确，这会使物体看起来透明（或按需要呈现半透明）。

让 OpenGL 中的透明度变得棘手的是 Depth-Test。Depth-Test 是 OpenGL 让靠近摄像机的几何遮挡远离摄像机的几何的机制，与几何的绘制先后无关。如果一个靠近摄像机的物体已经绘制，然后绘制一个较远（且位于已绘制物体之后）的物体，Depth-Test 将不会绘制第 2 个物体中被第 1 个物体遮挡的像素。

这对透明意味着你需要先绘制最远的几何。按由远及近的顺序绘制，可以确保每个像素都被绘制，这样当绘制较近的几何时，它就有来自较远几何的颜色信息可供混合。你可以把透明看作一系列 Over 合成操作。

一个几何未按正确顺序绘制时混合会发生什么的例子： 假设你先绘制较近的几何，其 alpha 为 0.0。该几何会被渲染并与当前已绘制的内容混合。

假设背景是红色的，那么结果将是 100% 红色。接下来你绘制较远的几何。由于较近的几何已经绘制，其深度值已在深度缓冲区中。较远的几何不会被渲染，因为 GPU 会判定它被较近的几何遮挡。

设置 Alpha 值

控制 Alpha

几何的 alpha 值是 Cd 属性的第 4 个分量。（这与 Houdini 不同，后者使用名为 'Alpha' 的独立属性表示 alpha。从 Houdini 导入的带 Alpha 属性的几何会自动转换为 TouchDesigner 的 alpha 格式。）

你可以在许多地方控制几何的 alpha。

  • Primitive SOP - 图元属性 SOP，可逐个图元设置 alpha。
  • Point SOP - 点属性 SOP，可逐点设置 alpha。
  • Vertex SOP - 顶点属性 SOP，可逐顶点设置 alpha。

除了几何 alpha 之外，还可以通过以下方式应用 alpha：

  • 材质中的各种贴图。
  • 材质中的 Alpha 参数（例如 Phong MAT 中的 Alpha 页）

材质操作符列表请参见 MATs。

各种 alpha 来源都会相乘，得到几何的最终 alpha（渲染时逐像素进行）。

排序与混合

OpenGL 渲染与 Alpha

SOP 内图元的排序以及 Component 绘制顺序的排序，对控制 alpha 混合至关重要。当 SOP 的几何需要与自身正确混合时，图元排序很重要。例如一个透明的立方体或球体，你想同时看到近侧和远侧。有些图元可能无法正确排序。例如，一条长而弯曲的网格是单个图元，如果它弯回自身，可能无法正确进行混合渲染。 当一个 SOP 需要与另一个 SOP 混合时，Component 的排序很重要。这是更常见的情况。

绘制顺序

几何按以下顺序传入 OpenGL 渲染管线。首先，根据 SOP 所在的 Component（以及这些 Component 的 Draw Priority），一次渲染一个 SOP 的几何。在该 SOP 内部，图元按其图元编号顺序渲染，编号较小的图元先渲染。

在 Geometry 物体中排序 SOP（Draw Priority）

在 TouchDesigner 中，Component 的 “Draw Priority” 参数可让你设置绘制顺序。Draw Priority 值较高的物体会先绘制。

可以通过导出 Object CHOP 的 TZ 通道来自动设置优先级，其中摄像机是 Reference Object，透明物体是 Target Objects。由于在 TouchDesigner 中 Component 可以嵌套 Component，绘制优先级按层级方式工作。这意味着从顶层开始，对 Render TOP 的 Geometry 参数中列出的每个 Component，会将其绘制优先级与 Geometry 参数中列出的其他 Component 比较，并按顺序处理。

如果每个 Component 内还有其他 Component，会比较它们的绘制优先级，并依次处理。重要：本质上，Draw Priority 控制的是一个 Component 相对于其同级 Component 的渲染方式。它不控制该 Component 相对于位于其他组件中的场景内其他 Component 的渲染方式。

举例来说，如果你有两棵要渲染的物体树，一棵位于 /character1/geo，另一棵位于 /character2/geo，并且你在 Render TOP 中将它们列为 '/character1/geo /character2/geo'，则会发生以下情况：

假设 /character1/geo 的绘制优先级为 1，/character2/geo 的绘制优先级为 0。 在这种情况下，/character1/geo 内的所有内容会先渲染，随后是 /character2/geo 内的所有内容。

这两个 'geo' 组件内部的 Component 也有绘制优先级，但无论其值如何，/character2/geo/ 内的内容都不可能先于 /character1/geo/ 绘制，因为 /character1/geo 内的*所有*内容都会先绘制，它的绘制优先级高于 /character2/geo。

在 SOP 中排序图元

SOP 内部的排序由图元编号控制，编号较小的图元先渲染。Sort SOP 是控制图元渲染顺序的关键。Sort SOP 可以按相对于可选摄像机的深度等选项对图元排序。这种技术同样很慢，因此不建议让该节点每帧都计算。

如前所述，图元排序对网格、NURBS、Beziers 或其他面片效果不佳，这会给旋转球面片（如 NURBs 球体）带来问题。

通常 SOP 内的透明度并不必要，因此启用混合并渲染 SOP 所造成的渲染瑕疵，可以通过开启 Back-Face Culling 来解决

在 Geometry 物体中排序实例

一组实例会在一次绘制调用中全部渲染，因此它们会全部在文件中的其他 SOP 之前或之后渲染。要按彼此关系对实例排序，请在指定实例数据的 CHOP 或 DAT 上使用 Sort CHOP 或 Sort DAT。如果你的摄像机朝 -Z 方向看，可以按 tz 坐标排序，并按值递增排序（最小值在前）。

由于所有实例都在一次调用中渲染，位于某些实例之前但在其他实例之后的其他几何，无法为透明正确排序。

因此如果实例已排序，该物体就不需要做顺序无关透明度。

性能考量

虽然按由远及近的顺序绘制几何对透明是必要的，但这是最慢的绘制方式。按由近及远的顺序绘制几何可以获得巨大的性能提升。这归功于现代图形硬件上的一项功能，称为 Early Depth-Test。因此必须注意，只在必要时才使用由远及近的渲染。

顺序无关透明度

使用顺序无关透明度时，结果只能在 Render TOP 中看到，在 Geometry Viewer/Geometry Viewport 中不可见。

使用此功能时，对几何/图元排序没有帮助，因此可以省去这些工作。

Alpha 混合函数详解

这些设置在所有 MAT's common page 上都可用。

这些设置不太容易理解，但如果你有耐心阅读每个因子的说明和示例，就会完全掌握如何使用它们。本文档为你提供实验的基础，示例则展示了一些可用的结果。

借助 OpenGL 混合函数，像素可以使用一个函数来绘制，该函数将传入（源）的 RGBA 值与帧缓冲区中已有的 RGBA 值（目标值）混合。因此，了解 TouchDesigner 如何决定多边形通过渲染管线的顺序，以及已渲染的像素信息如何与传入的几何、材质属性和纹理贴图结合以生成最终像素颜色，就很重要了。

OpenGL 混合函数提供了多种将渲染颜色与缓冲区中已有颜色结合的方式。不同的因子可以决定最终的源颜色和目标颜色。然后，修改后的源值和目标值相加，形成新颜色。要理解如何使用这些因子，重要的是理解此函数的各个组成部分。它们如下。

  • (Rs, Gs, Bs, As) Source Color - 来自材质参数设置和纹理贴图颜色。
  • (Rd, Gd, Bd, Ad) Destination Color - 是缓冲区中当前的颜色，最终会被结合并替换为该像素的最终颜色。
  • (Sr,Sg,Sb,Sa) Source Factor - 由 Source Blend 菜单决定。
  • (Dr,Dg,Db,Da) Destination Factor - 由 Dest Blend 菜单决定。

混合函数的组合方式如下。 

R = (Rs * Sr) + (Rd * Dr)
G = (Gs * Sg) + (Gd * Dg)
B = (Bs * Sb) + (Bd * Db)
A = (As * Sa) + (Ad * Da)

或更简单地说 

(Source Color * Source Factor) + (Current Destination Color * Destination Factor) = Final Destination Color

源混合因子

无论选择哪个选项，所有源混合因子都会乘以源颜色的 RGBA。例如，如果选择 Dest Alpha，颜色的 RGB 和 A 都会乘以 Dest Alpha。

One -（默认）

源混合因子设为 1。

来自材质和纹理贴图的源颜色乘以 1。

标准透明最好使用此混合函数，并将图元按由远及近的顺序排序。 这是默认设置，因为我们的 MAT 默认会在着色器末尾将源颜色后乘其自身的 alpha。如果你在 MAT 中关闭了此功能（例如 Phong MAT 的 Alpha 页），或使用的着色器不这样做，则应使用 Source Alpha 作为 Source Factor。

Zero

源混合因子设为 0。

源颜色 (Rs,Gs,Bs,As) 乘以 (0,0,0,0)。 这实际上从 alpha 混合函数中移除了任何源颜色，只留下目标颜色和目标因子来生成最终像素颜色。

Dest Color

源混合因子设为目标颜色值。

源颜色 (Rs,Gs,Bs,As) 乘以 (Rd,Gd,Bd,Ad)。

One Minus Dest Color

源混合因子设为 1 减去目标 alpha 值。

源颜色 (Rs,Gs,Bs,As) 乘以 (1 - Rd, 1 - Gd, 1 - Bd, 1 - Ad)。

Src Alpha

源混合因子设为源颜色的 alpha。

源颜色 (Rs,Gs,Bs,As) 乘以 (As,As,As,As)

One Minus Src Alpha

源混合因子设为源颜色的 alpha，然后用 1 减去它。

源颜色 (Rs,Gs,Bs,As) 乘以 (1 - As, 1 - As, 1 - As, 1 - As)

Dest Alpha

源混合因子设为目标 alpha 值。

源颜色 (Rs,Gs,Bs,As) 乘以 (Ad,Ad,Ad,Ad)

One Minus Dest Alpha

源混合因子设为 1 减去目标 alpha 值。

源颜色 (Rs,Gs,Bs,As) 乘以 (1 - Ad, 1 - Ad, 1 - Ad, 1 - Ad)

目标混合因子

One

目标混合因子设为 1。

目标颜色 (Rd,Gd,Bd,Ad) 乘以 (1,1,1,1)。

Src Color

目标混合因子设为源颜色。

目标颜色 (Rd,Gd,Bd,Ad) 乘以 (Rs,Gs,Bs,As)。

One Minus Src Color

目标混合因子设为 1 减去源颜色。

目标颜色 (Rd,Gd,Bd,Ad) 乘以 (1 - Rs, 1 - Gs, 1 - Bs, 1 - As)。

Src Alpha

目标混合因子设为源 alpha。

目标颜色 (Rd,Gd,Bd,Ad) 乘以 (As,As,As,As)。

One Minus Src Alpha -（默认）

目标混合因子设为 1 减去源 alpha。

目标颜色 (Rd,Gd,Bd,Ad) 乘以 (1 - As, 1 - As, 1 - As, 1 - As)。

标准透明最好使用此混合函数，并将图元按由远及近的顺序排序。

Dest Alpha

目标混合因子设为目标 alpha 值。

目标颜色 (Rd,Gd,Bd,Ad) 乘以 (Ad,Ad,Ad,Ad)。

One Minus Dest Alpha

目标混合因子设为 1 减去目标 alpha 值。

目标颜色 (Rd,Gd,Bd,Ad) 乘以 (1 - Ad, 1 - Ad, 1 - Ad, 1 - Ad)。

Zero

目标混合因子设为 0。

目标颜色 (Rd,Gd,Bd,Ad) 乘以 (0,0,0,0)。

这实际上会用黑色替换当前缓冲区中的所有像素值。
