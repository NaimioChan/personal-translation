拖放

TouchDesigner 支持拖放功能，作为复杂导入/导出和复制/粘贴功能的快捷方式。拖放功能允许你：

  • 导入 TouchDesigner-readable files。
  • 将 TouchDesigner 节点的数据导出到外部应用程序。
  • 将节点从一个 TouchDesigner 网络复制和/或移动到另一个网络。
  • 将 TouchDesigner 可读的文件、Panel 组件或 TouchDesigner 节点添加到已打开的控制面板中。

Panel Components 在其参数的 Drag/Drop 页上有拖放选项。这些参数可用于继承面板父级的拖放设置，或强制打开/关闭拖放。提示： Text COMP 在 Text 页上还有一个 Drag Drop Behavior 参数，允许使用一些预定义的放置操作，但也可以设置为使用此处定义的通用 Panel 系统。

拖放回调

要为 UI 创建自定义拖放系统，可以对所有 Panel Components 使用 Python 拖放回调。相关参数都在 Drag/Drop parameter page 上。在 When Dragging This 或 On Dropping Into 参数中将面板设为 Use Drag/Drop Callbacks 后，可以按 Drag/Drop Callbacks 参数中的 Add 按钮创建一个默认的 callbacks DAT。编辑该 DAT 即可设置自定义拖放行为。这些回调在用户拖放于组件显示的面板上时被调用，not 组件的网络节点，因此要在网络中测试，节点查看器必须处于活动状态。

要为面板网络创建单个拖放 callbacks DAT，需要注意的是，Use Parent's Drag/Drop Settings 菜单选项会让面板使用其在层级中上方找到的第一个拖放回调。由于接收拖放操作的源面板组件始终作为参数传入，因此可以为不同面板设置不同的行为。

设置可拖动面板

要使用回调系统创建可拖动面板，首先确保组件上的 When Dragging This 参数设为 Use Drag/Drop Callbacks。接下来，使用 onDragStartGetItems 回调告诉系统：当用户单击并拖动面板时将拖动哪个或哪些项目。拖动完成后，你会收到 onDragEnd 回调，可在其中编写后续要执行的操作。

onDragStartGetItems(comp, info) → list of items to drag

在需要拖动项的信息时调用。
  • comp - 被点击的面板
  • info - 包含拖动全部信息的字典
You must return a list of items from the callback to start a drag operation. 项就是你希望 TouchDesigner 拖动的任何东西。通常是某个 OP、参数或 CHOP 通道，但你可以把任意 Python 对象放进项列表。
Example onDragStartGetItems callback code
return [comp] 拖动面板操作符本身
return [comp.parent()] 拖动面板的父级
return [op('custom1'}, op('custom2')] 拖动两个操作符
return [comp.par.x] 拖动面板的 x 参数
return [op('myCHOP')['speed']] 拖动 CHOP 的 speed 通道。

onDragEnd(comp, info)

在拖动操作结束时调用。
  • comp - 被点击的面板
  • info - 包含拖动全部信息的字典，其中包括：
accepted：如果拖动被接受则为 True
dropResults：放置结果的字典。即 onDropGetResults 的返回值
dragItems：正被拖到 comp 上方的对象列表
如果你需要在放置发生后执行特殊操作，可以使用此回调。

将面板设置为放置目标

要使用回调系统设置向面板放置，首先确保组件上的 On Dropping Into 参数设为 Use Drag/Drop Callbacks。接收放置的第一步是使用 onHoverStartGetAccept 回调判断面板能否接受悬停在其上的项目（即 hovering）。如果有可接受的项目被放到面板上，随后可以使用 onDropGetResults 回调来响应放置。onHoverEnd 回调可用于编写项目被拖入 and then back out of 面板区域时要执行的操作。这通常用于关闭任何视觉悬停指示。

提示： Text COMP 默认使用由 Text 页上的 Drag Drop Behavior 参数设置的自身预定义放置操作。将该参数设为 'Use Panel System' 即可使用此处定义的示例。

在回调中测试 dragItems 的示例

	# 通过测试长度（len）来判断拖动项的数量
	if len(info['dragItems']) == 1:
		debug('Received one dragged item only')

	# 用 isinstance 判断第一个拖动项是否为操作符
	if isinstance(info['dragItems'][0], OP):
		debug('First dragged item is an operator')
	# 可用于测试的类：
	# OP：操作符
	# COMP, TOP, CHOP, SOP, MAT, DAT：操作符族
	# panelexecDAT, containerCOMP 等：具体的操作符类型
	# Channel：CHOP 通道
	# Par：参数
	# tdu.FileInfo：文件

	# 用 all、列表推导和 isinstance 判断所有拖动项的类型是否都是 DAT
	if all([isinstance(item, DAT) for item in info['dragItems']]):
		debug('All dragged items are DATs')

onHoverStartGetAccept(comp, info) → True if drag items are acceptable

在 comp 需要知道 dragItems 是否可作为放置对象时调用。如果希望接受 dragItems 放置，必须返回 True。
  • comp - 被放置到的面板
  • info - 包含悬停全部信息的字典，其中包括：
dragItems：正被拖到 comp 上方的对象列表
要最容易地看到实际效果，可以在此回调中使用以下代码，并在把各种项拖到面板上时观察 textport：
debug('\nonHoverStartGetAccept', comp.path, '\n\t', info)

onHoverEnd(comp, info)

在 dragItems 离开 comp 的悬停区域时调用。
  • comp - 被放置到的面板
  • info - 包含悬停全部信息的字典，其中包括：
dragItems：正被拖到 comp 上方的对象列表

onDropGetResults(comp, info) → dict of results

在 comp 接收到 dragItems 的放置时调用。只有当 onHoverStartGetAccept 对这些 dragItems 返回 True 时才会调用。
  • comp - 被放置到的面板
  • info - 包含放置全部信息的字典，其中包括：
dragItems：正被放到 comp 上的对象列表
从此函数返回项字典是可选的，但它允许你在拖动源与放置目标之间建立相互通信。字典的结果应使用有描述性的键。以下键/值对是标准用法，应尽可能使用：
  • 'createdOPs':[<list of created ops in order of corresponding drag item>]

获取放置的面板位置（u/v）

如果想了解某个东西被放置在面板中的确切位置，可以在回调中访问 comp.panel.dragrollu 和 comp.panel.dragrollv。也可以使用 Panel CHOP 持续跟踪这些值。

dragDropExt 订阅者

在 TouchDesigner 网络中发生文件放置事件时，TouchDesigner 可以通过 /sys/dragDropExt 将被放置文件的信息转发给外部订阅者 COMP。这使得扩展现有的内置文件放置行为，或为内置加载器不处理的新文件类型添加支持成为可能。

此订阅者系统适用于网络编辑器中的文件放置。它不会取代上文所述的面板拖放回调系统。

实践中，订阅者在两种情况下很有用：

  • 响应 TouchDesigner 已支持拖入网络的文件
  • 为内置拖放加载器不支持的文件类型添加处理程序

订阅文件类型

外部组件可以通过以下方式为一个或多个文件类型注册自己： 

op('/sys/dragDropExt').ext.DragDrop.Subscribe(externalComp, ['csv', 'json'])

参数为：

  • externalComp - 发起订阅的 COMP
  • fileTypes - 一个文件类型，或文件类型的列表/元组

Subscribe() 返回：

  • 如果组件被添加为新订阅者，则返回 True
  • 如果组件已订阅且其文件类型已被更新，则返回 False

说明：

  • 文件类型会规范化为小写。
  • 重复的文件类型会被移除。
  • 重新订阅同一组件会替换其先前的文件类型列表。
  • 文件类型不应带前导点。

示例：

  • ['csv', 'json']
  • ['whl', 'tar.gz', 'tgz']

回调名称

当被放置的文件匹配到订阅者时，/sys/dragDropExt 会按以下顺序在订阅组件上查找回调：

  1. OnDropReceived<FileType>(dropDict, newOp)
  2. OnDropReceived(dropDict, newOp)

示例：

  • csv 变为 OnDropReceivedCsv
  • whl 变为 OnDropReceivedWhl
  • tar.gz 变为 OnDropReceivedTarGz

放置路由

当文件被拖入 TouchDesigner 网络时：

  1. TouchDesigner 检查该文件类型是否有内置加载器。
  2. 拖放扩展会检查是否有任何外部订阅者与该文件匹配。

如果 TouchDesigner 有内置加载器：

  • 先运行内置加载器
  • 然后通知匹配的订阅者
  • 订阅者通过 newOp 接收所创建的操作符

这允许订阅者扩展已支持的网络文件放置行为。

如果 TouchDesigner 没有内置加载器，但有订阅者匹配：

  • 不会创建任何内置操作符
  • 订阅者仍会收到该放置
  • newOp 将为 None

这允许订阅者添加对 TouchDesigner 未内置的新网络文件放置类型的支持。

如果 TouchDesigner 和订阅者都无法处理该文件，则此次放置被视为不受支持。

dropDict 数据负载

订阅者回调会收到一个规范化后的 dropDict，其中包含：

  • dropName - 被放置文件的完整路径
  • xPos - 放置的 x 位置
  • yPos - 放置的 y 位置
  • index - 被放置项的索引
  • totalDragged - 被放置项的总数
  • dropExt - 规范化后的文件扩展名
  • baseName - 父目录名称的合法名称版本
  • destPath - 目标网络操作符
  • dropFileType - 匹配到的订阅者文件类型

dropFileType 对复合扩展名特别有用。例如，名为 package.tar.gz 的文件可能具有：

  • dropExt = 'gz'
  • dropFileType = 'tar.gz'

返回值

订阅者回调可以返回值。/sys/dragDropExt 会转发匹配订阅者返回的第一个非 None 返回值。

这主要在 TouchDesigner 自身未创建操作符时有用。此时，订阅者可以为放置结果创建并返回一个操作符。

示例

class MyDropHandlerExt:
    def __init__(self, ownerComp):
        self.ownerComp = ownerComp

    def SubscribeToDrops(self):
        op('/sys/dragDropExt').ext.DragDrop.Subscribe(
            self.ownerComp,
            ['whl', 'tar.gz', 'tgz']
        )

    def OnDropReceivedTarGz(self, dropDict, newOp):
        return self.HandleArchiveDrop(dropDict)

    def OnDropReceivedWhl(self, dropDict, newOp):
        return self.HandleArchiveDrop(dropDict)

旧版拖放系统

组件拖放的工作原理

  • 拖入启用了 Allows Drop 的网络中的任何内容都会由该网络的 Drop Script 处理，无论你是放置到节点查看器、控制面板视图，还是列表视图或节点视图中的网络编辑器上。不会弹出菜单。
  • 默认情况下，组件 Do Not Allow Drop。
  • 如果组件不允许放置（Does Not Allow Drop），你只能通过网络编辑器列表或节点视图向其放置内容。可能会弹出菜单提供选项列表。
  • 如果要放置的节点具有 Dropped Component 或 Drop Destination Script，则 Move 选项不可用。
  • 具有 Dropped Component 或 Drop Destination Script 的节点，如果放置到参数或 Text DATs 上，仍会以自身形式放置。如果放置到 Windows 桌面或文件夹上，也会保存为自身的 *.tox。

Drop Script - 文本

当你将另一个组件或外部文件拖入某个组件时，该组件的 Drop Script 就会运行。

每个组件网络都可以设置为允许拖放。在组件的参数对话框中有一个 Drag 页，可以在其中修改设置。你可以将组件设置为使用其父级设置，或使用自定义脚本。默认情况下，根文件夹的拖动设置为 Do Not Allow Drag，放置设置为 Do Not Allow Drop，默认 Drop Script 在 /sys/drop 中指定。

要设置自己的 Drop Script，请将组件的 Drop 参数设为 Allow Drop，并在 Drop Script 参数中填入指定 Drop Script 的 DAT 路径。每当有内容被放置到此组件上时，该 DAT 就会执行。以 Python 形式传给 Drop Script 的参数为：

  • args[0] - 被放置的节点名称、CHOP 通道或文件名，取决于所放置的内容
  • args[1] - 鼠标释放时在网络坐标中的 x 位置
  • args[2] - 鼠标释放时在网络坐标中的 y 位置
  • args[3] - 正在放置的项的编号
  • args[4] - 正在放置的项的总数
  • args[5] - 操作符类型或文件扩展名
  • args[6] - 节点或通道被拖出所在的网络或节点的完整路径，或父目录
  • args[7] - 接收此次放置的网络

Drop Script - 表格

如果想处理各个节点类型或文件类型，可以使用放置表（drop table）。在 drop script 字段中指定一个 Table DAT。TouchDesigner 会自动在表中查找 2 列。第一列应指示数据类型，第二列应指示保存处理该数据类型的脚本的 Text DAT。TouchDesigner 会针对每个数据调用脚本，并传入上述参数。下面是一个放置表示例： 

 chop      chop_script        handle CHOP nodes
 sop       sop_script         handle SOP nodes
 channel   channel_script     handle channel data
 cmd       cmd_script         runs a .cmd file
 tox       tox_script         loads a .tox file

列数不限于两列，但只有前两列会用于处理放置。

Drag Script

你可以指定组件是否允许被拖动。root 的默认设置为 Do Not Allow Drag。这意味着你不能单击组件的控制面板视图并将其拖到可放置的网络中。不过，你仍然可以拖动该组件的 Node View 并将其放置。

以 Python 形式传给 Drag Script 的参数为：

  • args[0] - 被拖动的操作符名称
  • args[1] - 被拖动操作符的索引
  • args[2] - 正在拖动的操作符总数
  • args[3] - 操作符类型
  • args[4] - 被拖动操作符的父级路径

有几种方法可以修改拖动组件时放置哪个操作符。Dropped Component 参数是指定替代放置操作符的最简单方式。注意该替代操作符必须存在，否则将放置组件本身。替代项仅在放置到网络或控制面板时使用。通过拖放粘贴的文本，或通过放置到桌面保存的文件，仍会使用原始内容。

Drop Destination Script

更灵活地指定替代放置内容的方式是使用 Drop Destination Script。 如果指定了 Drop Destination Script，则会创建一个临时网络，并将该组件（或 Dropped Component 中指定的替代操作符）复制到此网络。你可以在此网络中添加或修改操作符。

然后 echo 一个路径列表。TouchDesigner 会查看该脚本输出的路径列表，并将它们复制到放置目标网络。 节点路径在脚本退出时相对于当前组件指定。如果某个字符串找不到对应节点，TouchDesigner 会将其视为文件，并把该字符串作为文件放入目标网络。

Destination Drop Script 的参数为：

  • arg[0] - 脚本的完整路径
  • arg[1] - 组件副本（或 Dropped Component 参数中指定的替代操作符）
  • arg[2] - 临时网络的完整路径（位于 /sys 中）
  • arg[3] - 组件名称（或 Dropped Component 参数中指定的替代操作符）
  • arg[4] - 组件父级的完整路径（拖动来源处）（或替代操作符的父级）
  • arg[5] - 副本的操作符类型

放置类型

默认情况下，拖动组件放置的是操作符或文件路径。如果指定了 drop destination script，还可以添加一个 DAT 表格，列出该 drop destination script 将提供的返回类型。返回类型可以是操作符类型之一（COMP、TOP、CHOP、SOP、MAT、DAT）、channel，或受支持的 filetypes。例如，仅包含以下内容的 DAT 表格 

 jpg
 tiff
 top

只会让被放置到的组件知道它将仅提供这 3 种类型。如果被放置到的组件有一个类型及对应脚本的表格，那么只有存在匹配类型时才能放置。也就是说，如果 drop script 表格如下所示： 

 top      top_script

那么该组件只接受 drop destination script 提供的 tops。
