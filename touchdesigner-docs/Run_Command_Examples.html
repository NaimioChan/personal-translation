Run 命令示例

本页也作为教程连同附带的示例文件发布在 Derivative 网站上 here。

以下示例应粘贴到 textDAT 中。然后可以运行它们（RMB→Run Script，或选中后按 ctrl-R），并在 textport 中查看结果。

Run 命令

run command 允许你将字符串作为 Python 语句运行。它有许多关于如何运行该命令的选项。这些选项中最强大的功能是允许将执行延迟一定数量的帧或毫秒。下面是 run 的完整 wiki 文档。本教程将逐一介绍所有选项。

run(scriptOrCallable, *args, endFrame=False, fromOP=None, asParameter=False, group=None, delayFrames=0, delayMilliSeconds=0, wallTime=False, delayRef=None)→ Run:

Run 该脚本，返回一个 Run 对象，可用于选择性地修改其执行。这最常用于按 delayFrames 或 delayMilliSeconds 参数指定的延迟运行脚本。更多信息请参阅 Run Command Examples。

  • scriptOrCallable - 要执行的脚本代码字符串，或可调用的 Python 对象，例如函数或 lambda。
  • args - （可选）执行时传入 scriptOrCallable 的一个或多个参数。在脚本中可以通过名为 args 的元组访问它们。如果 scriptOrCallable 是可调用对象，它们会自动作为参数传入。
  • endFrame - （关键字，可选）如果为 True，执行将延迟到当前帧结束时。
  • fromOP -（关键字，可选）指定一个可选的 operator，执行将相对于它运行。
  • asParameter -（关键字，可选）使用 fromOP 时，相对于 fromOP 的某个参数运行。
  • group - （关键字，可选）可用于为此 Run 对象所属的组指定字符串标签。之后可以将此标签与 td.runs 对象配合使用，以修改其执行。
  • delayFrames - （关键字，可选）执行脚本前等待的帧数。
  • delayMilliSeconds - （关键字，可选）执行脚本前等待的毫秒数。此值会四舍五入到最近的帧。
  • wallTime -（关键字，可选）将其设为 True 后，延迟选项将基于实际经过的时间，而不是经过的帧数。
  • delayRef - （关键字，可选）指定可选的 operator，延迟时间从中推导。你可以使用自己的 independent time component 或 op.TDResources（内置的独立时间组件）。如果未提供 delayRef，则使用 root

运行一个简单脚本

最基本地，run 允许你将字符串作为 Python 脚本执行。下面的写法与直接执行 script 参数（不用 run 命令包裹）完全相同。

run("print('hello, world')")

上面是 run 在 TouchDesigner 中长期以来的形式，你会在许多示例中看到它。在较新版本的 TouchDesigner 中，你还可以将函数作为 run 的第一个参数传入，并在其后跟上该函数的参数。下一个示例用这种较新的格式完成与上面相同的事：

run(print, "hello, world")

运行带延迟的脚本

为脚本添加延迟只需增加 delayFrames 或 delayMilliSeconds 参数。

run("print('hello, world')", delayFrames=60)
run("print('hello, moon')", delayMilliSeconds=2000)

使用 wallTime 参数可让延迟基于已流逝的时间而非已流逝的帧。当掉帧且 Real-time 模式关闭时，这很有用，可确保在 fps 下降时延迟量仍然准确。

run("print('hello, world')", delayFrames=60, wallTime=True)
run("print('hello, moon')", delayMilliSeconds=2000, wallTime=True)

在 Run 命令中包含 Python 对象/参数

你可以包含任意数量的 args，它们会在命令执行时插入命令中。这对于插入变量和运行其他函数很有用。

location = 'world'

# 第一个参数是字符串，接下来是一个变量
run('print(args[0] + ", " + args[1])', 'hello', location, delayFrames=60)

# 使用 args 运行另一个函数
def otherFunc(thing):
    print('yo,', thing)

run('args[0]("moon")', otherFunc, delayMilliSeconds=2000)

如上所述，你也可以将 Python 函数（或其他可调用对象，如 lambda）作为 run 命令的第一个参数，像这样：

location = 'world'
 
# 第一个参数是字符串，接下来是一个变量
run(print, 'hello,', location, delayFrames=60)
 
# 使用 args 运行另一个函数
def otherFunc(thing):
	print('yo,', thing)

run(otherFunc, 'moon', delayMilliSeconds=2000)

可以看到，在处理函数参数时，这种新格式用起来明显更好，也更易读。

参数与脚本的求值时机

传给 run 命令的参数在 run 命令被 started 时求值。脚本本身中的所有内容在 run 命令被 executed 时求值。

# 注意，前两个延迟项使用 args 来打印帧号。它们是在启动延迟时计算的。后两个在 run 语句中
# 对帧求值，因此在 run
# 命令真正执行时才计算。

print('Current Frame:', absTime.frame)
run("print('hello, world. Frame:', args[0])", absTime.frame, delayFrames=60)
run("print('hello, moon. Frame:', args[0])", absTime.frame, delayMilliSeconds=2000)
run("print('hello, Venus. Frame:', absTime.frame)", delayFrames=180)
run("print('hello, Mars. Frame:', absTime.frame)", delayMilliSeconds=4000)

使用 endFrame

endFrame 参数使脚本在当前帧结束时运行。在下面的示例中，两条语句都在同一帧中运行，但 run 命令在第二位执行，因为它被推迟到帧结束，而 print 命令立即执行。

run("print('hello, world. Frame:', absTime.frame)", endFrame=True)
print("hello, moon. Frame:", absTime.frame)

delayRef 参数

使用 delayRef 参数，你可以提供一个组件，其时间轴将用于延迟，而不是主 TouchDesigner 时间轴。这可以是你自己的 independent time component，但更常见的是使用拥有独立时间的 op.TDResources。一般来说，这用于即使 TouchDesigner 时间轴暂停也仍会发生的延迟运行。如果不使用此参数，除非时间轴正在播放，否则 TD 不会认为时间在流逝！

# 在尝试之前先暂停时间轴
run("print('hello, world')", delayFrames=60)
run("print('hello, moon')", delayMilliSeconds=2000, delayRef=op.TDResources)
# 几秒后再恢复时间轴

使用 fromOP 更改上下文

fromOP 参数允许你像从另一个操作符运行一样来运行脚本。一般来说，这只会影响对 TouchDesigner 网络上下文敏感的 Python，例如 me 和 op。

run('debug(me)')
run('debug(me)', fromOP=root)

使用 asParameter 改变上下文

asParameter 参数影响一种旧有的 run 行为：当指定 fromOP 时，op 会在该操作符内部搜索。也就是说，如果 torus1 位于 geo1 内，run("print(op("torus1"))', fromOP=op('geo1')) 会找到 geo1 的子级，而不是像人们可能预期的那样搜索同级。将此参数设为 True（默认为 False）会改为搜索同级。此参数仅在 fromOP 设为 COMP 时相关，且只影响 op 对象的操作。

run("print(op('torus1'))", fromOP=op('geo1'))
run("print(op('torus1'))", fromOP=op('geo1'), asParameter=True)

高级 run 命令功能

上面已介绍 run 的基本用法。本节将详述一些更高级的 run 功能，包括 Run object 和 runs collection。

终止 Run 对象

run 命令返回一个 Run object，可以存储在变量中。这最常用于通过对象的 kill 方法取消已计划的命令。

worldRun = run("print('hello, world')", delayFrames=60)
moonRun = run("print('hello, moon')", delayMilliSeconds=2000)

print(worldRun)
worldRun.kill()

runs 集合

项目中所有活动的 Run 对象都可以通过 runs collection 访问。

run("print('hello, world')", delayFrames=60)
run("print('hello, moon')", delayMilliSeconds=2000)

print('total runs:', len(runs))
for i,r in enumerate(runs):
	print(i, r.remainingFrames)

终止所有 Run 对象

结合上面的技巧，终止所有活动的 Runs 相当简单……

run("print('hello, world')", delayFrames=60)
run("print('hello, moon')", delayMilliSeconds=2000)

for r in runs:
	r.kill()    

run("print('goodbye, world')", delayFrames=60)

GOTCHA: TouchDesigner 的许多内部和用户构建功能都使用 run 来处理计时。终止所有活动的 run 可能导致意外和隐藏的问题。只终止选定的 run 对象要安全得多……

终止选定的 Run 对象

只终止选定的 run 对象可能更复杂。为此，你可以在创建 Run 时指定一个 group 字符串，以区分各个对象。group 可作为 Run 的成员使用。

run("print('hello, world')", group='world', delayFrames=60)
run("print('hello, moon')", group='moon', delayMilliSeconds=1000)
run("print('hello, Luna')", group='moon', delayMilliSeconds=1000)
run("print('hello, Earth')", group='world', delayMilliSeconds=1000)

for r in runs:
	if r.group == 'world':
		r.kill()

或者，你可以查看 run 对象的 source 成员，以决定是否要终止它。此功能允许你测试实际将运行的代码字符串。在下面的示例中，带有「Earth」一词的 run 被终止。

run("print('hello, world')", group='world', delayFrames=60)
run("print('hello, moon')", group='moon', delayMilliSeconds=1000)
run("print('hello, Luna')", group='moon', delayMilliSeconds=1000)
run("print('hello, Earth')", group='world', delayMilliSeconds=1000)

for r in runs:
	if 'Earth' in r.source:
		r.kill()

测试 Run 对象状态

访问已经执行过的 Run 对象会引发异常。如果你想测试存储在变量中的对象是否仍在待执行状态，这会带来一些麻烦。要绕开这个问题，可以使用 try/except 子句检查 tdError。

worldRun = run("print('hello, world')", delayFrames=60)
moonRun = run("print('hello, moon')")

try:
	if worldRun.active:
		print('world active')
except tdError:
	print('world inactive')

try:
	if moonRun.active:
		print('moon active')
except tdError:
	print('moon inactive')

print("\nThis one is okay because it's active ---")
print(worldRun.active)
print("\nThis one errors because it's not ---")
print(moonRun.active)

单次更新设计模式示例

run 的一个非常有用的设计模式是：当你需要执行某种可由许多不同事件触发的更新操作，但只想每帧实际更新一次。下面的示例设置成：任何事件都可以在一帧内多次调用 scheduleUpdate 函数，而实际的 update 函数只在该帧结束时运行一次。

# 在任何需要帧末（end of frame）的地方运行 "update" 函数
# update。update 只会运行一次！

scheduledUpdateRun = None

def update():
	# 实际的 update 函数
	print('Run updater!')
	global scheduledUpdateRun
	scheduledUpdateRun = None

def scheduleUpdate():
	# 被调用以表示需要一次更新
	global scheduledUpdateRun

	print('Called schedule update!')
	if scheduledUpdateRun is None:
		scheduledUpdateRun = run('args[0]()', update, endFrame=True)

scheduleUpdate()
scheduleUpdate()
scheduleUpdate()
