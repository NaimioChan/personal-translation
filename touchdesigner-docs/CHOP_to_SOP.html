CHOP to SOP

摘要

CHOP to SOP 接收 CHOP 通道并在 SOP 中生成 3D 多边形。它从 CHOP 读取采样数据，并将其转换为点位置和点属性。这使它成为 SOP to CHOP 的补充。由 SOP to CHOP 创建的通道可以被修改，然后通过 CHOP to SOP 重新插回 SOP 网络。

默认情况下，SOP 是一条从 (-1 0 0) 到 (1 0 0) 的线，CHOP 中每个采样对应一个点。

它尽可能将输入通道匹配到 Channel Scope（tx ty tz）。如果 tx 或 ty 或 tz 没有匹配到任何内容，它就直接使用默认线的值，并且只显示一条警告。

最简单的做法是给它一个名为 ty 的通道，这会生成一条看起来像 CHOP 曲线的 3D 曲线。

这能完成带 op('wave1')['chan1'].eval(0) 功能的 Point SOP 所做的事，但快得多。

通过使用传入 SOP 的点组，可以只将通道插入该组的点中。

CHOP to SOP 也支持自定义属性。如果用户将通道映射到未找到的属性，该属性会被添加到点上。目前所有自定义属性都是浮点型，大小为 1。

在默认状态下，它会尝试用名为 tx ty 和 tz 的通道替换点位置（P(0) P(1) P(2)）。

通道范围和属性范围首先展开为单个名称，并按 1 对 1 匹配。如果填充的是 P，指定 t[xyz] 还是 tx ty tz 都无所谓，两者都会替换 P(0) P(1) P(2)，而后者可以缩写为 P。

例如：用 CHOP to SOP 将自定义属性「Scale」、「Twist」或「Roll」添加到 backbone 的点上。

如果将 SOP 连接到其输入，它会使用该 SOP 作为起始几何，而不是默认的线。

参数 - 页

Group group - 只修改此点组内的点。若留空，则修改所有点。接受模式，如 Pattern Matching 中所述。
CHOP chop - 指定哪个 CHOP Network / CHOP 包含要获取的采样数据。
Start Position startpos - - 设置未由通道定义的位置的边界，即通道未设为某个 P 属性时。
  • X startposx -
  • Y startposy -
  • Z startposz -
End Position endpos - - 设置未由通道定义的位置的边界，即通道未设为某个 P 属性时。
  • X endposx -
  • Y endposy -
  • Z endposz -
Channel Scope chanscope - 用于修改属性的名称。
Attribute Scope attscope - 要在 SOP 中修改的属性的字符串列表。常用属性列表：
  • P - 点位置（X、Y、Z）- 3 个值
  • Pw - 点权重 - 1 个值
  • Cd - 点颜色（red、green、blue、alpha）- 4 个值
  • N - 点法线（X、Y、Z）- 3 个值
  • uv - 点纹理坐标（U、V、W）- 3 个值

属性完整列表请参见 Attributes。

Organize by Attribute organize - 不使用点索引，而使用此属性的值作为在 CHOP 中查找时使用的索引。
Mapping mapping - - 决定 CHOP 采样如何映射到几何的点。
  • One Sample to Each Point onetoone - 采样按 1 对 1 简单映射，每个采样按顺序映射到下一个点。
  • Resample CHOP to Fit SOP scale - 如果 CHOP 采样数与几何点数不一致（多或少），则对 CHOP 通道重采样，为所有几何点插值出数值。
Compute Normals compnml - 在几何上创建法线。
Compute Tangents comptang - 在几何上创建切线。

操作符输入

  • Input 0: -

Info CHOP 通道

CHOP to SOP 的额外信息可通过 Info CHOP 访问。

SOP 通用信息通道

  • num_points - 此 SOP 中的点数。
  • num_prims - 此 SOP 中的图元数。
  • num_particles - 此 SOP 中的粒子数。
  • last_vbo_update_time - 在另一个线程中根据 SOP 的 CPU 数据更新 GPU 上的几何数据所花的时间。由于它属于另一个线程，此时间不计入通常的帧时间。
  • last_meta_vbo_update_time - 在另一个线程中根据 SOP 的 CPU 数据更新 GPU 上的元表面几何数据（如 metaball 或 nurbs）所花的时间。由于它属于另一个线程，此时间不计入通常的帧时间。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
