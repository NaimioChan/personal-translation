Cook

Cooking 是 TouchDesigner 中用来表示计算或算出网络中各操作符的术语。在节点上中键单击，可以看到它上次计算用了多久，以及自启动 TouchDesigner 以来它计算了多少次。

TouchDesigner 只会在需要时计算节点——它不会每帧计算所有节点。

每一帧，TouchDesigner 都会考虑计算以下节点：

  • 查看器在 Network 中可见的节点。
  • 参与在面板或 Window COMP 中显示面板的节点。
  • 参与网络操作符向 TouchDesigner 外部发送数据的节点，例如 Touch Out CHOP、OSC Out CHOP。
  • 参与通过 NDI Out TOP、Video Device Out TOP、Audio Device Out CHOP 等节点发送视频/音频输出的节点。

当你看到节点之间的 Wires 在动画（虚线在动）时，表示上游节点正在计算。下游节点可能在计算，也可能没有。Middle mouse-click 任意节点，在信息弹窗中查看计算次数是否在增加。

Dialogs → Performance Monitor 会显示一帧内计算了哪些内容。要让你的合成以 30 或 60 fps 运行，关键在于尽量减少参与计算的节点数量。

调色板 Tools 中的 Probe 组件可以让你实时观察正在计算的内容。

参见 Optimize、Dependency 和 Event。

计算机制

什么会导致计算

节点要计算，需要满足两个条件：(1) 节点需要有计算请求（有东西要求它计算），(2) 它需要有计算的理由。

会产生计算请求的情况：

  • 连接到该节点输出的节点想要计算。
  • 通过参数引用该节点的节点想要计算。
  • 有查看器正在查看该节点的数据。
  • CHOP 或 DAT 正在导出到的那个节点想要计算。
  • 在 OP 上调用 cook() 方法。

会赋予节点计算理由的情况。

  • 该节点的某个输入已计算。
  • 它通过参数指向的节点已计算。
  • 该节点的某个参数发生变化。
  • 在该节点上运行了特定的脚本命令。
  • 表达式的结果可能已改变。
  • 该节点引用的变量值发生变化。
  • 其某个参数的表达式中指向的节点已计算。
  • 该节点与时间相关，也就是说它每帧都可能输出不同的数据，即使其输入或参数都没有变化（例如 Time Slice CHOP，或 Video Device In TOP）。
  • 用户与它交互，但仅当它是 Panel Component 时。

当节点收到计算请求时，它会请求其所有输入计算，这可能会也可能不会让它们计算。如果其中任何一个计算了，它就有了计算的理由，于是它会计算。如果都没有计算，它就会检查其他可能的计算理由。如果这些都不存在，它就不会计算（你也不会在 Performance Monitor 中看到它）。

例如，如果你正在查看默认 Constant CHOP 的查看器（一个没有表达式的通道），该节点会不断收到计算请求（例如每次 UI 重绘时），但它从不计算，因为它没有计算的理由。

计算顺序

TouchDesigner 是一个「拉取系统」。关于 TouchDesigner 中的计算，一个常见误解是计算从上游开始、向下游推进。例如，如果你有一个 Constant CHOP 连接到 Math CHOP，大多数人会认为在 Constant CHOP 中改动一个值，就会强制 Math CHOP 计算。这是不对的。几乎所有操作符只有在有东西需要它的数据时才会计算。在我们的例子中，这意味着虽然在 Constant CHOP 中修改参数会让它变「脏」，但在有人请求它的数据之前它不会计算。所以 Constant CHOP 要等到 Math CHOP 请求它的数据时才会计算。Constant CHOP 也可能因其他原因计算，比如它的查看器开着（即用户要求查看它的数据）。

什么在拉取？所有每帧都需要图像的显示设备，都会拉取所有参与生成一帧图像的 TOP 和其他 OP。音频输出设备同理，它们每帧都需要把采样送入音频硬件。

事件驱动的计算

参见 Event。所有「Execute」DAT 都会响应收到的事件，并通过其 python 回调函数改变其他操作符的参数，或让其他操作符计算。「Execute」DAT 这一组包括 Panel Execute DAT、CHOP Execute DAT、Parameter Execute DAT、DAT Execute DAT、Render Pick DAT。其他操作符如 Monitors DAT、OP Find DAT、Folder DAT 也有在条件变化时被调用的回调，同样可以改变参数并让节点计算。参数被改变时，目标节点只会按照上述拉取系统的计算规则计算。而当任何节点通过调用 OP.cook() 被强制计算时，它的数据会向下游传递，同样遵循上述计算规则。

强制计算

有些节点，特别是 Movie File Out TOP、Touch Out OP 及其他 *Out OP 之类的节点，会每帧计算，无论其输入或参数是否变化。这种行为确保其输出的接收方（影片、网络管道等）能获得持续的数据流。

其他节点在被要求计算时，即使输入或参数都没有变化也会计算。这些主要是特殊节点，如 Render TOP 以及 *In OP（例如 Touch In 和 Pipe In CHOP，但不包括 In CHOP 和 In SOP）。这些节点有太多可能的输入变化需要监视（对 Render TOP 来说：材质、几何位置、几何渲染标记等），因此与其试图判断它们是否 should 计算，不如直接计算。对这些节点来说，始终计算在 99% 的情况下都能节省计算周期，因为渲染场景中大多数时候 something 都在变化。
