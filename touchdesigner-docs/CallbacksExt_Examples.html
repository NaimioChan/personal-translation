CallbacksExt 示例

本页包含如何为组件搭建 CallbackExt Python 回调系统的示例。这些示例假定你具备 TouchDesigner 和 Component Editor Dialog 的基础知识，并具备中等程度的 Python 知识。

CallbackExt 扩展的完整文档请参见：CallbacksExt Extension。

入门

本页所有示例都使用同一个自定义组件，并层层递进。首先，在网络中创建一个 Base COMP 并将其命名为「userComp」。然后，按照 CallbackExt Extension: Adding CallbackExt to a Component 中关于向组件添加 CallbackExt 的说明操作。并按该节所述提升该扩展。

现在为 userComp 创建一些 Custom Parameters。首先，使用 Component Editor Dialog 创建一个名为「UserComp」的自定义页。然后，按上文链接的章节所述，添加「Callbackdat」和「Printcallbacks」参数。提示： 使用「Callback DAT」和「Print Callbacks」作为标签，让参数看起来更美观。这两个参数由 CallbackExt 自动使用。接着创建几个供示例使用的参数：名为「Toggle」的 Toggle 参数、名为「String」的 Str 参数，以及名为「Pulse」的 Pulse 参数。完成后，你的自定义页应如下所示：

最后，我们需要一个用于试验的回调 DAT，因此在任意位置创建一个 Text DAT，并将其拖到 userComp 的 Callback DAT 参数上。提示： 由于下面的所有示例都使用 Python，你大概会想打开一个 Textport，或者更好是打开一个专用的 Textport 编辑窗格（在任意编辑窗格左上角的 Pane Type 箭头中选择「Textport and DATs」）。

示例 1 - 使用 Callback DAT 的参数回调

在本例中，我们让 userComp 在其任一参数改变时调用其 Callback DAT 中的回调。

设置 Parameter Execute DAT

要设置对参数变化的响应，进入 userComp 并创建一个 Parameter Execute DAT。将其 OP 参数改为 ..（parent），Parameter 参数改为 *（all），并将 Built-In 参数关闭。这样当任何自定义参数改变时，参数执行 DAT 就会调用 valueChange 回调。

现在定义该 valueChange 回调。在 DAT 中编辑 valueChange 函数，使其如下所示： 

def valueChange(par, val, prev):
	infoDict = {'parameter': par, 'value': val, 'previousValue': prev}
	parent().DoCallback("onParChange", infoDict)

使用 CallbackExt 回调系统只需要这两行代码。第一行定义要发送给用户回调的相关信息字典。下一行执行回调本身，即用回调名（onParChange）和上面定义的 infoDict 调用 DoCallback 方法。

即使还没有定义任何用户回调，也可以用 Print Callbacks 功能测试。只要开启 Print Callbacks 自定义参数，就会在 Textport 中立即看到 CallbacksExt 尝试回调的报告：

onParChange NOT FOUND - callbackInfo: {'value': 'on', 'parameter': type:Par name:Printcallbacks owner:/callbackExtExamples/userComp1, 'ownerComp': type:baseCOMP path:/callbackExtExamples/userComp1, 'previousValue': 'off', 'callbackName': 'onParChange'}

这表明 CallbackExt 尝试调用 onParChange 回调，但没有找到。字典显示了本应发送给回调的所有数据。注意索引中的 parameter 键保存的是 Printcallbacks 参数，说明该回调是通过切换该参数触发的。还要注意 ownerComp 和 callbackName 是由 CallbacksExt 自动提供的。

改变它们的值，你会看到其他任一参数改变时也会尝试类似回调，例外是 Pulse 参数，它的行为与带值的参数不同。我们会在后面的示例中使用它。

创建用户回调

为 CallbacksExt 系统创建用户回调非常简单。编辑你在 Getting Started 一节中创建的回调 DAT，加入以下文本： 

def onParChange(info):
	debug("PAR CHANGE:", info['parameter'].name, info['value'])

CallbacksExt 回调就是一个名称正确、只有一个参数的函数。该参数会被填入你在 Textport 消息中看到的信息字典。本例回调的实质内容，只是用信息字典中的 parameter 和 value 元素打印一条调试消息。

要测试新建的回调，请关闭 Print Callbacks 参数，以免消息过多。然后改变 Toggle 和 String 参数。你会在 Textport 中看到回调的调试消息。

示例 2 - 使用指定回调的 Pulse 回调

上一个示例中，我们使用了 Callback DAT 中定义的回调。Assigned Callbacks 与之非常相似，但它不在 Callback DAT 中，而是由用户指定一个 python 函数来接收回调。

本例中，我们为 Pulse 参数使用回调。回到你的 Parameter Execute DAT，开启 On Pulse 参数。然后进入其中，编辑 onPulse 函数，使其如下所示： 

def onPulse(par):
	infoDict = {'parameter': par}
	parent().DoCallback("onPulse", infoDict)

与第一个示例中的 valueChange 回调非常相似，只是 infoDict 中的信息少一些，回调名称也不同。现在可以用 Print Callbacks 参数并按下 userComp 的 Pulse 参数，测试此回调是否触发。

此时，你可以像 onParChange 回调那样，把 onPulse 回调写进 Callbacks DAT。不过我们改为直接给回调指定一个函数。做法是在 userComp 旁边的网络中创建一个 Text DAT，并在该 DAT 中输入以下文本： 

def printPulse(info):
	print("PAR PULSE:", info['parameter'].name)

op('userComp').SetAssignedCallback('onPulse', printPulse)

这段代码做两件事：定义作为回调的 printPulse 函数，并把该函数指定为 userComp 的「onPulse」回调。在网络中右键点击该 Text DAT 并选择「Run Script」。回调就指定好了。此后点击 userComp 的 Pulse 参数就会运行这个新回调。

关于指定回调，有几点值得注意：

  • CallbackExt 扩展重新初始化时，所有指定的回调都会被清除。
  • 要移除已指定的回调，只需以 None 作为回调调用 SetAssignedCallback。

示例 3 - 带返回值的回调

本例展示如何从回调返回值并接收该值。

接收回调的返回值

CallbackExt 可以接收回调的返回值。每次调用 DoCallback 都会返回所提供的信息字典，其中 "returnValue" 键包含返回的值。当然，如果回调没有返回任何内容，该值就是 None。如果没找到回调，DoCallback 会返回 None，因此通常先判断这一点。作为示例，将你的 Parameter Execute DAT 中的 valueChange 函数改为： 

def valueChange(par, val, prev):
	infoDict = {'parameter': par, 'value': val, 'previousValue': prev}
	if parent().DoCallback("onParChange", infoDict):
		debug('onParChange callback returned', infoDict['returnValue'])

现在，当参数值改变时，if 分支会判断 DoCallback 是否返回了内容。如果为 False，说明没找到回调，因此显然没有返回值，也不应打印任何内容。如果为 True，我们会打印返回的信息。记住返回值实际包含 infoDict，由于它永不为空，因此判断为 True。我们已经有了 infoDict 的引用，无需再次保存。Notice that this means infoDict will be changed when passed to DoCallback!

在 userComp 上改变参数试一试，你会看到目前所有回调都返回 None。如果把 Callback DAT 中的 onParChange 回调注释掉，你会看到不再产生调试消息，因为找不到回调。

从回调返回值

从回调返回值与从其他任何函数返回值一样。将 CallbackDAT 中的 onParChange 函数改为： 

def valueChange(par, val, prev):
def onParChange(info):
	debug("PAR CHANGE:", info['parameter'].name, info['value'])
	if info['parameter'].name == 'String':
		return 'String changed!'

现在当 String 参数改变时会发送返回值。试一试就知道了。

返回值说明

重要的是让使用者知道何时会期望回调返回值，以及返回值应为何种格式。在 CallbackExt 中，标准做法是在回调的信息字典的「about」键中写明说明。这由程序员决定，因为 CallbackExt 无法知道任一回调的意图或用途。
