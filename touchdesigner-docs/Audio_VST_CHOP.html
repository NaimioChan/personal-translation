Audio VST CHOP

摘要

Audio VST CHOP 加载 VST3 插件文件，这些插件可生成（乐器）或处理（滤波器）音频。参见 VST 概述。

插件的参数可以通过对应的 TouchDesigner 参数或插件的 GUI 控件暴露并双向驱动。为充分发挥插件参数双向特性的优势，建议在 TouchDesigner 中驱动参数时使用 Binding 或 Bind CHOP，而不是表达式或 CHOP 引用。

Python 调用可让你 send MIDI messages 到该插件。若插件生成 MIDI，你可以在 docked 回调 DAT 中获取并处理这些消息。

取决于插件，Audio VST CHOP 最多接受 4 个多通道输入。

关于哪些 VST 插件与 TouchDesigner 配合良好的讨论，参见 VST Plugin Testing。此外，这里有一批免费 VST 以及一组实用且价格合理的升级版本：https://hy-plugins.com。

TouchDesigner 附带 2 个免费的 HY-Plugins，可通过 Help → Browse Samples 菜单找到。这会打开一个文件浏览器，定位到 TouchDesigner 应用程序的 Samples 文件夹，其中包含一个 VST3 文件夹，内有适用于 Windows 和 MacOS 的一个合成器和一个滤波器插件。Windows 的 VST3 插件文件可通过其中包含的 "64 Bit" 字符串来区分。

在 Windows 上，已安装的 VST 插件位于 C:Program Files/Common Files/VST，在 macOS 上位于 /Library/Audio/Plug-Ins/VST3。

提示：通过将 Info DAT 附加到该 CHOP，可以获得 VST 插件的详细信息。

VST 是 Steinberg Media Technologies GmbH 的商标，在欧洲及其他国家注册。

参数 - VST 页

File file - VST3 插件的路径。VST3 插件的默认安装位置在 Windows 上为 C:/Program Files/Common Files/VST3，在 macOS 上为 /Library/Audio/Plug-Ins/VST3。
Reload reloadpulse - 重新加载 VST3 插件。脉冲触发会清除所有已学习的参数并重置 GUI，以及任何暂存的插件数据。基本上就是将插件重置为默认状态。
Load Plugin State on Start loadpluginstate - 插件状态（包括预设值和其他 UI 元素）会保存到 toe 文件中，若启用，则在 TouchDesigner 启动时恢复。此开关用于为那些在设置插件状态时表现不佳（例如崩溃）的插件提供变通办法；在这些情况下应禁用该开关。
Sample Rate rate - 设置 VST3 插件的采样率。
Plugin GUI Always on Top alwaysontop - 启用后，插件窗口将始终位于其他窗口之上。
Display Plugin GUI displaygui - 脉冲触发时，会在单独的窗口中打开插件 GUI。在学习开关启用时更改插件 GUI 中的参数，会在 Audio VST CHOP 一侧创建该参数。
Learn Parameters learnparms - 启用后，在 VST 插件窗口中操作过的参数会被创建为 Plugin 页上的参数，即会被学习。
Regular Parameters regularparms - 启用后，每个插件参数都会在 Plugin 页上创建。
Read-Only Parameters readonlyparms - 启用后，所有只读插件参数都会在 Plugin 页上创建。若 Regular Parameters 也已开启，则此开关不起作用。
Clear Learned Parameters clearlearnedparms - 脉冲触发时，会清除所有已学习的参数。若 Regular 和 Read-only 参数都未开启，则这些参数会被销毁。
Callbacks DAT callbacks - 对包含 Audio VST CHOP 所支持回调的 DAT 的引用。

参数 - Bus Layout 页

Custom Bus Layout custombuslayout - 启用自定义总线布局。禁用时，总线布局为插件的默认布局。
Output Bus Layout outputbuslayout - 选择输出总线的布局（即通道数）。这会直接影响 Audio VST CHOP 具有的通道数。
Main Input Bus Layout maininputlayout - 选择主输入总线布局（即通道数）。主输入总线始终是该 CHOP 的第一个输入，此选择决定它从中接受多少个通道。
Aux Input aux - 此序列描述 VST 插件的辅助输入。
Enable aux0enable - 启用辅助总线。
Bus Layout aux0layout - 选择辅助输入的辅助总线布局（即通道数）。辅助输入是主输入之后的每个输入。并非所有插件都支持辅助总线，若不支持，该参数会被禁用。若无法再添加后续辅助总线（即参数序列中的 +/- 消失），则说明已达到辅助总线上限。

参数 - Playhead 页

Custom Playhead customplayhead - 启用自定义播放头。禁用时，插件始终按时间顺序向前步进。并非所有插件都支持自定义播放头。
Timecode Object/CHOP/DAT timecodeop - 指定插件的播放头时间。可以是带有 'hour'、'second'、'minute'、'frame' 通道的 CHOP 的引用、第一个单元格含时间码字符串的 DAT，或 Timecode Class 对象。
Tempo (bpm) tempo - 播放头的速度。并非所有插件都支持通过播放头更改速度。
Signature signature - - 播放头的拍号。并非所有插件都支持通过播放头更改拍号。

参数 - Common 页

Time Slice timeslice - 开启后强制通道为「Time Sliced」。Time Slice 是上一个计算帧与当前计算帧之间的时间。
Scope scope - 为了确定哪些通道受影响，一些 CHOP 会使用 Common 页上的 Scope 字符串。见 Pattern Matching。
Sample Rate Match srselect - - 处理多个输入 CHOP 采样率不同的情况。发生重采样时，曲线按 Interpolation Method 选项进行插值；若没有可用的 Interpolate 选项，则按「Linear」插值。
  • Resample At First Input's Rate first - 使用第一个输入的速率重采样其他输入。
  • Resample At Maximum Rate max - 重采样到最高采样率。
  • Resample At Minimum Rate min - 重采样到最低采样率。
  • Error If Rates Differ err - 不接受互相冲突的采样率。
Export Method exportmethod - - 这决定如何把 CHOP 通道连接到参数。更多信息请参阅 Export 文章。
  • DAT Table by Index datindex - 使用停靠的 DAT 表格，并通过通道在该 CHOP 中的索引来引用通道。
  • DAT Table by Name datname - 使用停靠的 DAT 表格，并通过通道的名称来引用通道。
  • Channel Name is Path:Parameter autoname - 通道即完整的导出目标位置，例如 geo1/transform1:tx。
Export Root autoexportroot - 该路径指向根节点，通过 Channel Name is Path:Parameter 导出的所有路径都相对于它。
Export Table exporttable - 使用 DAT Table Export Methods 时用来存放导出信息的 DAT（见上文）。
Rename from commonrenamefrom - 要重命名的通道模式。见 Pattern Matching。
Rename to commonrenameto - 名称的替换模式。默认参数不会重命名通道。见 Pattern Replacement。

Example:

通道名称：c[1-10:2] ambient
重命名自：c* ambient
重命名至：b[1-5] amb

此示例获取通道 c1 c3 c5 c7 c9 和 ambient。

然后它们被重命名为 b1 b2 b3 b4 b5 和 amb。

重命名模式的进一步说明见 Rename CHOP。

Info CHOP 通道

Audio VST CHOP 的额外信息可通过 Info CHOP 访问。

通用 CHOP Info 通道

  • start - CHOP 区间的起始，以采样计。
  • length - CHOP 中的采样数。
  • sample_rate - 通道的采样率，单位为帧每秒。
  • num_channels - CHOP 中的通道数。
  • time_slice - 如果 CHOP 启用了 Time Slice 则为 1，否则为 0。
  • export_sernum - 导出连接被更新的次数。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
