GLSL 版本

TouchDesigner 使用 GLSL 3.30 及更高版本作为其语言。许多在线示例以及 WebGL 着色器都是针对 GLSL 1.20 编写的。GLSL 1.20 与 GLSL 3.30+ 之间存在一些重要的语言差异。有关其中一些差异的信息，请参阅 Changes from GLSL 1.20

GLSL 着色器的概念

GLSL Shader 是在几何渲染时应用于几何的程序。GLSL 着色器分为两个主要部分：顶点着色器和像素着色器。

Vertex Shader - 顶点着色器是应用于材质所作用几何的每个顶点的程序。

Pixel Shader - 像素着色器是应用于每个绘制像素的程序。它也常被称为 Fragment Shader。

还有一个 Geometry Shader，它是顶点阶段和像素阶段之间的阶段，但不常使用。关于几何着色器的更多信息，请查看 here。

TouchDesigner GLSL 约定

TouchDesigner 作为 GLSL 语言扩展提供的所有函数和 uniform 都遵循这些约定。

  • 函数名始终以字母 TD 开头。例如 TDLighting()。
  • Uniform 以字母 uTD 开头。
  • Sampler 以字母 sTD 开头。
  • Image 以字母 mTD 开头。
  • 顶点输入属性的命名与 TouchDesigner SOP 接口中相同（P、N、uv）。

TouchDesigner 提供的大多数 uniform 都包含在 Uniform Block 中。这意味着不再通过 uTDMatrixName 访问单个矩阵，而是将矩阵存储在包含许多矩阵的单个块中，例如 uTDMats，其成员如 uTDMats[0].worldCam 和 uTDMats[0].projInverse。

着色器阶段

顶点着色器

在顶点着色器内部，你只能访问一个顶点，不知道其他顶点的位置，也不知道其他顶点的顶点着色器输出会是什么。

顶点着色器的输入是关于程序正在处理的特定顶点的所有数据。可以获取顶点在 SOP 空间中的位置、纹理坐标、颜色、法线等数据。这些值称为 attribute。attribute 在顶点着色器中使用 in 关键字声明。

顶点着色器可以输出许多内容。主要输出的是顶点位置（经世界、摄像机和投影矩阵变换后）、颜色和纹理坐标。它也可以使用通过 out 声明的输出变量输出任何其他值。顶点着色器的输出会在该顶点所属图元的表面上线性插值。例如，如果你在线段的第 1 个顶点输出值 0.2、第 2 个顶点输出值 0.4，则在这两点之间中点绘制的像素将获得值 0.3。

像素着色器

像素着色器的输入是顶点着色器的所有输出以及已定义的任何 uniform。顶点着色器的输出已在顶点所构成的多边形上线性插值。像素着色器主要将颜色输出到 Color Buffer。颜色通过声明为 layout(location = 0) out vec4 oFragColor 的变量输出。如果要输出到多个颜色缓冲区，可以声明更多颜色输出，将 location 值设为 1、2、3 等，而不是 0。你也可以将输出声明为数组，例如 layout(location = 0) out vec4 oFragColor[3]。

几何着色器

几何着色器接收单个点图元（点、线或三角形），并输出一组点、线带或三角形带。目前在 TouchDesigner 中，你必须使用的输入图元类型之一要与我们所渲染的内容相匹配：

 layout(points) in;
 layout(lines_adjacency) in;
 layout(triangles) in;

目前不支持 lines 或 triangles_adjacency 等其他输入类型。

注意 - 在 2018.20000 系列版本中支持 lines，不支持 lines_adjacency，因此 2019.10000 将支持对象切换为 lines_adjacency 的变化不幸地破坏了现有的几何着色器。

一个基础着色器

顶点着色器

此顶点着色器只是正确地变换每个顶点，完全交由像素着色器为像素着色：

void main()
{
	// P 是当前顶点的位置
	// TDDeform() 会返回变形后的 P 位置，位于世界空间。
	// 把它从世界空间变换到投影空间，以便进行光栅化
	gl_Position = TDWorldToProj(TDDeform(TDPos()));
}

像素着色器

此像素着色器只是将每个像素设为红色：

// 我们需要声明输出片元颜色的名称（这与 GLSL 1.2 不同，那里会自动声明为 gl_FragColor）
out vec4 fragColor;
void main()
{
	fragColor = vec4(1, 0, 0, 1);
}

使用几何属性

以下顶点着色器属性（输入）始终会自动为你声明，可在顶点着色器中使用。你无需自行声明它们。

vec3 TDPos(); // 顶点位置
vec3 TDNormal(); // 法线
vec3 TDTexCoord(uint coordLayer); // 纹理坐标层

Other Attributes

你想使用的所有其他属性都需在着色器代码中声明。它们作为自定义属性传入。为将来与 POP 兼容，这些属性应使用 GLSL MAT 上的 'Attributes' 页声明。声明的属性可通过调用 TDAttrib_AttribName() 访问。例如，如果你声明一个名为 'life' 的自定义属性，你将在着色器中用 TDAttrib_life() 访问它。

为方便起见，TDTexAttrib_AttribName(uint textureLayer) 对 POP 返回 TDAttrib_AttribName()，对 SOP 返回 uv[textureLayer]，这样着色器代码可以更容易在 POP 和 SOP 之间共享

对 POP 而言，可通过指定顶点索引参数来访问任意顶点的属性值。

attribType TDAttrib_AttribName(uint arrayIndex, uint vertIndex) // 访问输入几何体属性（必须在 Attributes 页面上声明）
TDAttrib_AttribName(uint arrayIndex) = TDAttrib_AttribName(arrayIndex, gl_VertexID); // vertIndex 是可选的，默认为 gl_VertexID
TDAttrib_AttribName() = TDAttrib_AttribName(0, gl_VertexID);
// 对于点和图元属性，查找是基于顶点进行的；

const uint cTDAttribArraySize_AttribName // 用于数组属性的、带数组大小的常量

Other POP Attributes

要按元素索引访问任意 POP 属性，可以使用 Buffers 页：

attribType TDBuffer_AttribName(uint elementIndex, uint arrayIndex); // 访问在 Buffer 页上声明的 POP 属性缓冲区
TDBuffer_AttribName(uint elementIndex) = TDBuffer_AttribName(elementIndex, 0); // arrayIndex 可选，默认为 0

const uint TDBufferLength_AttribName(); // 缓冲区长度
const uint cTDBufferArraySize_AttribName; // 用于数组属性的、带数组大小的常量

TouchDesigner 特有的 define

TouchDesigner 中的着色器会根据若干因素动态重新编译，例如场景中的灯光数量和类型，或此渲染通道中使用的摄像机数量（在 Multi-Camera Rendering 的情况下）。这样做是为了优化，因为迭代次数已知的循环在 GLSL 中要快得多。还提供了一些 define，使最终用户编写的代码能在不同灯光/摄像机数量下正确重新编译。

// This define will be defined at compile time, and your shader will be recompiled for each combination
// of lights in use (if it's is used in multiple light configurations). You can use it for things like a loop
// counter to loop over all lights in the scene, as you will see if you output example code from the Phong MAT.
// Environment COMPs are counted separately from regular Light COMPs.
#define TD_NUM_LIGHTS <defined at compile time>
#define TD_NUM_ENV_LIGHTS <defined at compile time>

// On newer hardware multiple cameras can be rendered at the same time. This define will be set to the
// number of cameras done on this render pass. This may be 1 or more, depending on many factors.
// Code should be written in a way that should work regardless of what this value is.
#define TD_NUM_CAMERAS <defined at compiler time>

// One of these defines will be set depending on which shader stage is being compiled.
// This allows shaders to use #ifdef <stageName> and #ifndef <stageName> to either include or
// omit code based on the current shader stage being included. This also allows for single
// large DATs to contain all the code for all stages, with each portion #ifdef-ed in for
// each stage.
#define TD_VERTEX_SHADER
#define TD_GEOMETRY_SHADER
#define TD_PIXEL_SHADER
#define TD_COMPUTE_SHADER

{
	mat4 world;			// 世界变换矩阵，是包含该 SOP 的 Object COMP 层级组合。
						// 从 SOP 空间到世界空间的变换
	mat4 worldInverse;	// 世界矩阵的逆
	mat4 worldCam;		// 世界矩阵与相机矩阵的乘积。（Cam * World）
	mat4 worldCamInverse;
	mat4 cam;			// 相机变换矩阵，取自用于渲染的 Camera COMP
	mat4 camInverse;
	mat4 camProj;		// 相机的变换矩阵与相机 COMP 的投影矩阵，（Proj * Cam）
	mat4 camProjInverse;
	mat4 proj;			// 来自 Camera COMP 的投影矩阵。Z 范围为 [0,1]，Vulkan 风格。
	mat4 projInverse;
	mat4 worldCamProj;	// 世界、相机和投影矩阵的乘积。（Proj * Cam * World）
						// 取 SOP 空间中的顶点并放入投影空间
	mat4 worldCamProjInverse;
	mat3 worldForNormals;	// 世界矩阵的逆转置，用它把法线
							// 从 SOP 空间变换到世界空间
	mat3 camForNormals;		// 相机矩阵的逆转置，用它把法线
							// 从世界空间变换到相机空间
	mat3 worldCamForNormals;	// worldCam 矩阵的逆转置，用它把法线
								// 从 SOP 空间变换到相机空间 inverse(transpose(Cam * World))
	   
};

struct TDLight
{
	vec4 position;		// 光源在世界空间中的位置
	vec3 direction;		// 光源在世界空间中的方向
	vec3 diffuse;		// 光源的漫反射颜色
	vec4 nearFar;		// 光源 View 页面中的近、远设置
						// 包含 (near, far, far - near, 1.0 / (far - near)
	vec4 lightSize;		// 光源 Light Size 参数的值
						// 容器 (light width, light height, light width / light projection width, light height / light projection height)
	vec4 misc;			// 杂项参数值，目前包含
						// (Max shadow softness, 0, 0, 0)
	vec4 coneLookupScaleBias;	// 应用于锥形光的贡献，以创建聚光照明区域
								// 包含 (coneLookupScale, coneLookupBias, 1.0, 0.0)。
                                // 如果光源不是锥形光，则包含 (0.0, 0.0, 0.0, 0.0)。
	vec4 attenScaleBiasRoll;	// 应用于光到点的距离，以得到衰减值
								// 包含 (attenuation scale, attenuation bias, attenuation rolloff, 0)
	mat4 shadowMapMatrix;		// 把世界空间中的点变换到阴影贴图光源的投影空间
								// 同时把投影空间从 [-1, 1] 重新缩放到 [0, 1]，使该值可用于
								// 在阴影贴图中查找
	mat4 shadowMapCamMatrix;	// 把世界空间中的点变换到阴影贴图光源的相机空间
	vec4 shadowMapRes;			// 与此光源关联的阴影贴图分辨率
								// 包含 (1.0 / width, 1.0 / height, width, height)
								// 如果光源未使用阴影贴图，则填充 0
	mat4 projMapMatrix;			// 把世界空间中的点变换到光源的投影贴图空间
								// 在使用 textureProj() 函数进行投影映射时使用
}

使用灯光

为使着色器尽可能快，大量计算灯光的逻辑根据启用的特性和灯光类型硬编码在着色器中。为 GLSL MAT 编写的着色器会根据场景中灯光的数量和类型，以不同实现的 TDLightingPBR()、TDLighting() 等重新编译。这使得同一个 GLSL MAT 可用于多个不同场景，而无需根据场景中的灯光数量进行修改。这些编译会被缓存，因此每次运行 TD 时，每种光照设置组合只会触发一次编译。

提示： 几何查看器内置灯光，与场景中的灯光对象相互独立。有关如何复现该灯光的信息，参见 Geometry Viewer 文章。

自定义灯光处理

如果决定做自定义灯光处理，本节介绍我们的着色器中大量灯光值的使用方式。

了解哪些变量对应哪些 Light COMP

变量会按索引区分不同灯光，从 0 开始。Light 0 是 Render TOP 中列出的第一盏灯，Light 1 是列出的第二盏，依此类推。如果使用 light* 之类的通配符选择灯光，则从该通配符收集到的灯光将按字母数字顺序排序。

例如，假设 Render TOP 的 Light 参数中列出 "/light3 /container1/light* /alight1"，且 /container1/ 有两个 light COMP，名为 light1 和 light2。此时灯光对应的索引如下：
/light3 为索引 0
/container1/light1 为索引 1
/container1/light2 为索引 2
/alight1 为索引 3

锥形光照技术

TouchDesigner 内置着色器使用一种自定义的锥形光照技术，你可以在自己的着色器中模仿。锥形光的强度预先计算到 1D 纹理（查找表）中，以减少着色器的工作量。1D 纹理的起始处（纹理坐标 0.0）是锥角边缘处的光强（第一个像素始终为 0）。1D 纹理的末尾（纹理坐标 1.0）是锥形中心处的光强。该查找表通过以下方式访问：

float TDConeLookup(int lightIndex, float coord);

还向着色器提供了第二个辅助 uniform，使在 1D 纹理中查找更容易：

uTDLights[i].coneLookupScaleBias;

要正确查询此查找表，应使用以下算法：

// 'spot' 是聚光向量
// 'lightV' 是从光源位置出发、指向
// 我们要着色的几何体上的点的向量。
// 这些向量处于哪个空间（相机空间、物体空间）并不重要，
// 只要它们处于同一空间即可。
// 求两向量夹角的余弦值，范围在 [-1, 1]
float spotEffect = dot(spot, lightV);
// 现在使用特殊的辅助 uniform 重新缩放该值，使其位于 [0,1]
// 值为 0 表示两向量夹角等于光源的整个
// 锥角 + 锥角增量
spotEffect = (spotEffect * uTDLights[i].coneLookupScaleBias.x) + uTDLights[i].coneLookupScaleBias.y;
// 最后在查找表中查找
float dimmer = TDConeLookup(i, spotEffect);
// 现在可以把光照强度乘以 'dimmer'，以根据该像素位于锥形光影响范围内

衰减

衰减在 TDLighting() 函数中已为你处理，但如果你想自己添加，本节说明如何做。

要确定灯光到空间中某点的衰减，使用此函数。lightDist 是从顶点到灯光的距离。

// 如果没有衰减则返回 1，如果光完全衰减则返回 0，处于衰减过渡区域则返回两者之间的值。
float TDAttenuateLight(int lightIndex, float lightDist);

TDAttenutateLight 背后的数学如下：

TouchDesigner 内置着色器使用自定义的衰减技术。与锥形光照类似，会预先为你计算好缩放和偏移，让你能获得正确的衰减光强。该 uniform 为：

uTDLights[i].attenScaleBiasRoll // 包含 (1 / -(attenEnd - attenStart), attenEnd / (attenEnd - attenStart), attenRolloff)

TDAttenutateLight 定义为：

float TDAttenuateLight(int lightIndex, float lightDist)
{
    float lightAtten = lightDist * uTDLights[lightIndex].attenScaleBiasRoll.x;
    lightAtten += uTDLights[lightIndex].attenScaleBiasRoll.y;
    lightAtten = clamp(lightAtten, 0.0, 1.0) * 1.57073963
    lightAtten = sin(lightAtten);
    lightAtten = pow(lightAtten, uTDLights[lightIndex].attenScaleBiasRoll.z);
    return lightAtten;
}

投影与阴影贴图

投影映射和阴影贴图在 TDLighting() 函数中已为你处理，但如果你想，也可以用下面的信息自己实现。

投影和阴影贴图是非常相似的操作。唯一的区别是，投影贴图用于给表面着色，而阴影贴图用于决定该表面是否接收某盏灯的光照。

投影映射

使用 TDProjMap() 函数，它会返回投影贴图颜色，并处理不同的投影类型。

阴影贴图

使用 TDHardShadow() 或 TDSoftShadow() 手动获取阴影值。

多渲染目标

使用 Render TOP 中的 '# Of Color Buffers' 参数配合 Render Select TOP，你可以编写为每个像素输出多个颜色值的 GLSL 着色器。这通过声明并写入如下所示的像素着色器输出实现：

layout(location = 0) vec4 fragColor[TD_NUM_COLOR_BUFFERS];

常量 TD_NUM_COLOR_BUFFERS 会根据渲染设置自动为你设置。确保不要写出所提供缓冲区数量之外，否则可能发生损坏或 GPU 崩溃。

多摄像机渲染

多摄像机渲染是在一次渲染通道中渲染多台摄像机，它们都看向同一场景。这意味着场景图只遍历一次，从而避免大量图形驱动调用。对于整组要渲染的摄像机，灯光、纹理、材质和绘制调用只需执行一次。此功能受 Nvidia Pascal（Geforce 1000、Quadro P-Series）或 AMD Polaris（Radeon R9、Radeon Pro WX）及更新 GPU 支持。该功能对 VR 渲染很重要，对一次渲染立方体贴图（而不是每面一次）等也很有用。

如果各摄像机的灯光遮罩不同，多摄像机渲染将无法工作。这种情况下，摄像机会逐通道渲染。

当 'Cameras' 参数中列出多台摄像机时，Render TOP 会使用此功能。'Multi-Camera Hint' 参数可帮助控制该特定 Render TOP 如何使用此功能。每台摄像机的渲染结果可以通过 Render Select TOP 获取。

Nvidia 将此功能称为 'Simultaneous Multi-Projection'。

这些 GPU 上的多摄像机功能并非通用，需要一些技巧才能正常工作。因此，你的所有着色器都应使用 TD* 函数，例如 TDWorldToProj()、TDInstanceID()，而不是手动做这些事并使用内置 GLSL 功能。TDFog() 等函数还需要传入摄像机索引，以便为正确的摄像机应用雾效。

图像输出

在 Render TOP 中，你可以分配额外的图像输出，在渲染期间访问。这些任意尺寸的图像可在任意位置写入和读取（类似 GLSL TOP 的 Compute 着色器工作流），使用 TDImageStore_Name() 和 TDImageLoad_Name()，其中 'Name' 会替换为你为图像输出起的名字。图像会在着色器内自动为你声明，你不应自行声明（像其他 uniform 那样）。这是因为图像 uniform 需要大量额外的装饰。目前在 GLSL MAT 本身中编译时，你的代码会报错，因为那里没有这些图像。你可以在使用 TDImage* 函数的代码周围使用以下方式避免这些编译错误

#ifdef TD_RENDER_TOP
// Render TOP only code
#endif

当把 MAT 应用到几何并通过 Render TOP 渲染时，会编译一个新版本的着色器，其中已声明图像。

应使用这些函数写入和读取图像。'Name' 部分应替换为 Render TOP 中定义的图像输出名称。这些函数取代了 2025.30000 之前直接使用 imageStore()/imageLoad() 的工作流。这一变化是因为读写 sRGB 编码纹理需要 imageStore()/imageLoad() 的特殊处理，因此由这些函数自动为你处理。你也不not需要在使用这些函数前对颜色应用 TDOutputSwizzle()，它会在内部自动为你应用。ivec3 与 uvec3 版本做同样的事，只是为了方便而重复提供。如果图像维度需要少于 3 个坐标，多余的坐标会被忽略。

如果图像声明时 Array Size 为 0（不是数组），则 arrayIndex 应设为 0。

void TDImageStore_Name(uint arrayIndex, ivec3 coord, vec4 color);
void TDImageStore_Name(uint arrayIndex, uvec3 coord, vec4 color);
vec4 TDImageLoad_Name(uint arrayIndex, ivec3 coord);
vec4 TDImageLoad_Name(uint arrayIndex, uvec3 coord);

例如，如果 Image Output 命名为 'test'，则函数将调用 TDImageStore_test()

输出 gl_Position

虽然一般来说你可以随意使用内置的 model/view 和投影矩阵变换点/向量，但在输出到 gl_Position 时应使用内置函数。这些函数允许 TouchDesigner 根据渲染设置对值做最终输出处理。例如，为实现优化的 Multi-Camera Rendering，位置需要乘以本次顶点着色器执行所对应的正确摄像机。为给 TouchDesigner 机会做此处理，你应调用内置函数来变换顶点位置：

vec4 TDWorldToProj(vec4 v);
vec4 TDWorldToProj(vec3 v);

因此，例如在着色器末尾你会这样做：

gl_Position = TDWorldToProj(worldSpacePosition);

特化常量

Specialization Constants 是 Vulkan 的新特性，它允许基于整数常量值对代码重新优化，而无需完全重新编译着色器代码。它们适用于为很少变化的值设值，例如着色器中的「模式」，或通过 switch() 或 if() 语句选择的特定代码路径。过去这可能通过 #define 语句或 uniform 来实现。 着色器的特化版本会被缓存并重复使用，但会占用 GPU 资源。因此不应用于不断变化的值，而应用于仅偶尔变化、且取值范围有限的值。

要定义特化常量，需声明一个带额外 layout() 限定符的常量。

layout(constant_id = 0) const int SomeMode = 0;

然后你可以像使用其他变量一样使用 SomeMode。如果不希望它为 = 0，可以在 GLSL TOP、GLSL MAT 等的「Constants」页上赋予不同的值。 你可以声明多个特化常量，只需为每个赋予自己唯一的 constant_id 值（0、1、2 等）。

使用变形

目前可应用于几何的变形有两种： skinned deforms 和实例化变换。

TouchDesigner 在 GLSL 函数中自动封装了这两种变形的所有工作。变形向量时使用 *Vec 版本。
These functions always return the point/vector in World space, not model/SOP.

vec4 TDDeform(vec4 p);
vec3 TDDeform(vec3 p);
vec3 TDDeformVec(vec3 v);
vec3 TDDeformNorm(vec3 v);


作为着色器作者，操作位置和法线等顶点属性是你的工作（因为编写着色器的是你，TouchDesigner 无处插手），因此需要你调用 TDDeform() 函数。一般来说你只需这样简单调用：

vec4 worldSpaceVert = TDDeform(vec4(TDPos(), 1.0)); 
vec3 worldSpaceNorm = TDDeformNorm(TDNormal()));

不过你也可以直接使用下面声明的函数。

蒙皮变形（骨骼变形）

当你在 GLSL MAT 中启用 Deform 功能时，TouchDesigner 会自动声明一些 attribute、varying、uniform 和函数，供你以与其他 MAT 相同的方式变形几何。使用变形时，重要的是不要重复使用这些保留字，以免编译着色器时发生名称冲突。不过即使不使用变形，下面列出的函数也会被声明，因此着色器代码在变形开启和关闭时都能正确运行。变形关闭时这些函数不做任何事（且对着色器速度无开销）。变形的骨骼矩阵通过 pCaptPath 和 pCaptData 细节属性，结合该帧骨架中骨骼的当前位置来构建。在 SOP 中，'pCapt' 属性为影响该顶点的每根骨骼保存索引/权重对。在 POP 中，这些改为加载到两个名为 'BoneIndices' 和 'BoneWeights' 的属性中。关于蒙皮变形工作原理的更多信息可在此找到： Deforming Geometry (Skinning)

函数

一般来说你无需直接调用这些，它们由 TDDeform() 函数调用。

在顶点着色器中：

vec4 TDSkinnedDeform(vec4 pos);
vec3 TDSkinnedDeformVec(vec3 vec);

你可以用此函数获取给定矩阵索引的骨骼矩阵：

mat4 TDBoneMat(int boneIndex);

实例化

当你在 Geometry COMP 的 Instance 页启用实例化时，TDDeform() 函数会根据 XForm CHOP 参数中给定的通道，自动调用正确的底层函数来变换实例。如果不指定 CHOP，则所有实例都会绘制在同一位置，除非你自己变换它们。

实例索引/ID

要计算实例 ID，使用提供的 TDInstanceID() 函数。不要直接使用 gl_InstanceID，因为由于 Multi-Camera Rendering，实际渲染的实例数可能大于请求的数量。

int TDInstanceID();

由于此函数仅在顶点着色器中可用，如果像素着色器需要它，你需要通过 out/in 传递过去。

// 在顶点着色器中声明类似这样的内容，并在 main() 中赋值 vInstanceID = TDInstanceID()
flat out int vInstanceID;
void main()
{
	vInstanceID = TDInstanceID();
	// 其他顶点主函数内容
	// ....
}

而在像素着色器中，如果这样声明，你就可以读取该值：

// 像素着色器
flat in int vInstanceID;

这里声明为 flat，因为 int 变量类型无法在图元上插值。

变形函数

一般来说你无需直接调用其中任何一个，它们由 TDDeform() 函数调用。这些函数仅在顶点着色器中可用。

在顶点着色器中：

vec4 TDInstanceDeform(vec4 pos);
vec3 TDInstanceDeformVec(vec3 vec);

对于变换，使用以下函数访问这些矩阵：

mat4 TDInstanceMat(int instanceIndex);
mat4 TDInstanceMat();

这些矩阵包含完整变换，包括 TX、TY、TZ、SX、SY、SZ 以及 Rotate To。

属性函数

修改纹理坐标时，这些函数按实例执行纹理坐标修改。t 是要修改的纹理坐标。不带 instanceIndex 的版本会自动使用当前 gl_InstanceID 的值。

vec3 TDInstanceTexCoord(int instanceIndex, vec3 t);
vec3 TDInstanceTexCoord(vec3 t);

要修改漫反射颜色，这些函数会在原始漫反射颜色上替换、加上或减去。一般来说你会想把 TDPointColor() 的结果传入这些函数，让它们修改它。如果未使用实例颜色，此函数只会原样返回传入的颜色。

vec4 TDInstanceColor(vec4 curColor);
vec4 TDInstanceColor(int instanceIndex, vec4 curColor);

自定义实例属性可使用这些函数获取：

vec4 TDInstanceCustomAttrib0();
vec4 TDInstanceCustomAttrib0(int instanceIndex);
vec4 TDInstanceCustomAttrib1();
vec4 TDInstanceCustomAttrib1(int instanceIndex);
vec4 TDInstanceCustomAttrib2();
vec4 TDInstanceCustomAttrib2(int instanceIndex);
vec4 TDInstanceCustomAttrib3();
vec4 TDInstanceCustomAttrib3(int instanceIndex);

实例纹理化

实例纹理允许将更多单独纹理映射到实例上。单次渲染中可用的纹理数量因 GPU 而异。每个纹理的分辨率/像素格式可以不同。它避免了使用 2D Texture Array 将多个图像映射到实例上。一次只支持一种纹理维度（2D、Cube 等）。访问纹理分两步。首先你需要获取当前正在输出的实例的纹理索引。这通过 TDInstanceTextureIndex() 实现。然后你可以在 TDInstanceTexture() 调用中使用该纹理索引，以在传入坐标处获得采样纹理颜色。这些函数有几个变体。在顶点着色器中有可隐式获知当前实例索引并使用它的版本。在顶点和像素着色器中还有可通过参数手动指定实例索引的版本。通常你会在像素着色器中采样纹理，此时你要在顶点着色器中获取纹理索引，然后通过 flat uint in/out 变量传入像素着色器。

// 仅在顶点着色器中可用
// 隐式使用当前实例。返回此实例的纹理索引。
uint TDInstanceTextureIndex();
// 返回给定 'uv' 处的纹理颜色，隐式使用当前实例索引来决定采样哪个纹理。
// 你通常不会用到这些版本的 TDInstanceTexture()，因为它们仅在顶点着色器中可用。
vec4 TDInstanceTexture(vec2 uv);
vec4 TDInstanceTexture(vec3 uv);

如果你需要对使用哪个实例纹理有更多自定义控制，可以改用这些函数：

// 在所有着色器阶段均可用
// 给出给定 instanceIndex 对应的 textureIndex。
uint TDInstanceTextureIndex(int instanceIndex);
// 在给定 'uv' 处采样纹理 'texIndex'。
vec4 TDInstanceTexture(uint texIndex, vec3 uv);
vec4 TDInstanceTexture(uint texIndex, vec2 uv);

查看这些代码实际用法的最佳方式，是从正在执行实例纹理的 Phong MAT 输出着色器。

点精灵

点精灵现在必须使用 vec2 TDPointCoord() 而不是 gl_PointCoord 来获取精灵的纹理坐标。使用 gl_PointCoord 在某些情况下会导致纹理坐标垂直翻转。

渲染点精灵图元时，你必须写入顶点着色器输出 gl_PointSize。该输出变量决定点精灵渲染时的大小（以像素计）。如果不写入该输出，点的大小将是不确定的。

每个点精灵会渲染为 gl_PointSize 像素宽的正方形像素块。该像素块在像素着色器中会获得覆盖整个正方形的 0-1 纹理坐标，通过 TDPointCoord() 获取。

顺序无关透明度

只需在像素着色器 main() 函数开头添加这一行，即可让着色器支持顺序无关透明度。如果 Render TOP 中未启用顺序无关透明度，此函数将不做任何事。

TDCheckOrderIndTrans();

抖动

如果在 Render TOP 中启用了抖动，你可以通过简单调用以下函数将抖动应用到颜色：

finalColor = TDDither(finalColor);

通常你会希望在着色器末尾、即将把值写入输出颜色之前执行。如果 Render TOP 中禁用了抖动，此函数仍然可用（以避免编译错误），但会保持颜色不变。

拾取

Render Pick DAT 和 CHOP 通过渲染操作完成工作，因此它们需要与着色器交互才能工作。如果你导出 Phong MAT 的着色器，会看到以下行

#ifndef TD_PICKING_ACTIVE
	// All the typical shader code
#else
	TDWritePickingValues();
#endif

这里发生的关键是：拾取发生时，会设置 define TD_PICKING_ACTIVE，只执行 #else 块内的代码。该函数：

void TDWritePickingValues();

会写入供拾取使用的默认值，Render Pick DAT/CHOP 会读取它们。如果你有以非标准方式改变顶点位置的自定义着色器，或想输出不同类型的信息（如 TDPointColor() 之外的颜色），可以在此函数之后替换已写入的值。可供你使用的值有：

TDPickVertex {
	vec3 sopSpacePosition;
	vec3 worldSpacePosition;
	vec3 camSpacePosition;
	vec3 sopSpaceNormal;
	vec3 worldSpaceNormal;
	vec3 camSpaceNormal;
	vec3 uv[1];
	flat int instanceId;
	vec4 color;
} vTDPickVert;

因此，例如如果你以不同于标准 TDDeform() 的方式修改顶点位置，可以这样写入新计算的值： Be sure to do this AFTER the call to TDWritePickingValues(), otherwise that call will overwrite your values 。

TDWritePickingValues();
vTDPickVert.sopSpacePosition = newPosition;
vTDPickVert.worldSpacePosition = uTDMats[TDCameraIndex()].world * vec4(newPosition, 1.0);
vTDPickVert.camSpacePosition = uTDMats[TDCameraIndex()].worldCam * vec4(newPosition, 1.0);

你不必写入此结构中的所有条目，但为完整起见可以这样做。只有 Render Pick CHOP/DAT 会读取的值（在其参数中选择的）必须填写。

对于你在 Render Pick CHOP 或 Render Pick DAT 中为拾取设置的自定义属性，这些属性在 vTDCustomPickVert 中可用，名称和大小与 Render Pick 节点中定义的一致。

Shadertoy

VR 着色器

来自 Shadertoy 且支持 VR 渲染的着色器会定义一个 mainVR 函数。在 TD 内重建该函数使用的 fragRayOri 和 fragRayDir 变量很简单。在顶点着色器中：

vec4 worldSpaceVert = TDDeform(TDPos());
vec4 worldSpaceCamPos = uTDMat.camInverse[3]; // 相机变换矩阵的最后一列即是它的位置

vec3 fragRayOri = worldSpaceCamPos.xyz;
vec3 fragRayDir = worldSpaceVert.xyz - worldSpaceCamPos.xyz;
// 使用你自行命名的 'out' 变量把这些变量传给像素着色器

而在像素着色器中，你只需将 fragRayDir 传入的任何变量归一化。来自 fragRayOri 的变量可以原样使用。

要支持这些着色器（通常是光线步进着色器），你需要渲染覆盖整个视口的几何，例如在摄像机周围放置一个球体。

相对 GLSL 1.20 的变化

为 1.20 编写的着色器无法作为 3.30 着色器编译。该语言经过了大幅重构，更改了许多关键函数的名称并替换了大量功能。所有变化都可在前面链接的官方 GLSL 文档中查看。其中一些较重要的变化是：

  • 移除了 texture1D(sampler1D, float), texture2D(sampler2D, vec2), etc.。所有纹理采样都使用相同的函数名，无论纹理的维度如何。例如 texture(sampler1D, float), or texture(sampler2D, vec2)。
  • 移除了关键字 varying。改用 in 和 out（取决于值是从着色器输出，还是从上一着色器阶段输入）。示例见本文后续部分。
  • 移除了关键字 attribute。在顶点着色器中直接使用 in 即可。
  • 移除了内置 varying gl_TexCoord[]。你始终需要自己声明在着色器阶段之间输出和输入的变量。
  • 移除了 gl_FragColor 和 gl_FragData[]。改为使用语法 layout(location = 0) vec4 oFragColor[TD_NUM_COLOR_BUFFERS] 命名你自己的颜色输出。
  • 移除了 gl_Vertex, gl_MultiTexCoord0, gl_Normal 等所有内置 attribute。在 TouchDesigner 中，这些属性可通过自动声明的属性访问，如 in vec3 TDPos(); in vec3 TDTexCoord(uint coordLayer); in vec3 TDNormal(); vec4 TDPointColor()。更多细节见 later。
  • 移除了几乎所有内置 uniform，例如矩阵（gl_ModelViewMatrix, gl_ProjectionMatrix）、灯光信息（gl_LightSource[]）、雾信息（gl_Fog）。所有这些数据都将通过 TouchDesigner 提供的新方式获得，详见 later。
  • 现在支持 sampler 数组，并在 TouchDesigner 中适当地广泛使用。不过这些 sampler 的索引方式有限制，详见你所使用特定版本的 GLSL 规范（例如 3.30 与 4.10 的规则不同）。

自 TouchDesigner088 以来的重大变化

099 中 TouchDesigner 的 GLSL API 有大量变化。其中大部分变化是为了更好地支持 Multi-Camera Rendering。这些变化的摘要如下：

  • 光照和其他工作现在在世界空间而非摄像机空间中完成。这使代码更清晰，因为多摄像机时着色器需要在多个不同的摄像机空间中工作。旧版 GLSL 着色器可通过 GLSL TOPs 的 'Lighting Space' 参数支持，该参数对旧着色器会设为 Camera Space。
  • 应使用 TDInstanceID() 而不是 gl_InstanceID/uTDInstanceIDOffset。
  • 在世界空间中进行光照时已移除 uTDMat，改用数组 uTDMats[]。
  • uTDGeneral 结构中的一些值已移到 uTDCamInfos[]，因为那些信息是特定于摄像机的。
  • 某些函数（如 TDFog()）需要摄像机索引的概念（在顶点着色器中用 TDCameraIndex() 获取）。
  • 必须调用 TDAlphaTest(float) 来应用 alpha 测试。在 MAT 上禁用 alpha 测试时也可以安全调用，此时它不做任何事。
  • 在向输出颜色缓冲区写入任何颜色之前，应先让它经过 vec4 TDOutputSwizzle(vec4)。这确保根据通道在输出纹理中的存储方式，通道处于正确位置。例如仅有 Alpha 的纹理在内部可能存储在「仅红色」纹理中，因此输出前需要将 alpha 值 swizzle 到红色通道。
