Sync In CHOP

摘要

注意

License: 仅在 TouchDesigner Pro 中可用。

Sync In CHOP 和 Sync Out CHOP 用于让两个或更多 TouchDesigner 进程中的时间轴保持在彼此一帧之内。一个进程包含 Sync Out CHOP，一个或多个其他进程包含 Sync In CHOPs。带 Sync In CHOPs 的进程应设置其 Realtime flag checked off，因为它们的帧率将由 Sync Out CHOP 决定。另请注意，所有显示器（包括所有客户端和服务器）都应设置为 same rate。注意拔掉或重新接入显示器有时会改变先前配置的设置。

这些 CHOP 通过暂停自己的时间轴直到所有 Sync In/Out CHOP 完成计算来实现同步。Sync Out CHOP 会领先于 Sync In CHOPs。如果有任何 CHOP 通信失败，其他 CHOP 会超时，导致所有进程运行缓慢。

客户端机器可以在任何时候上线，也可以按需关闭，因为 Sync Out CHOP 会相应调整，按指定对个别客户端临时或永久封禁。

此外，通过 Sync Out CHOP 发送的任何额外 CHOP 通道都会被 Sync In CHOPs 接收。

NOTE for Windows OS - If experiencing connection issues make sure Windows Firewall is disabled.

一个指向 Sync Out CHOP 的 Info DAT 可提供所有客户端的详细列表：

各列含义为：

  • pid：客户端的进程 id
  • address：ip 和端口号
  • machine_name：客户端机器名
  • filename：客户端所在的 .toe 文件名
  • op_path：到客户端的完整操作符路径
  • include：为 1 时，Sync Out CHOP 等待回复；为 0 时忽略。
  • timeout_total：Sync Out CHOP 等待该客户端而停顿的总次数
  • timeout_consecutive：Sync Out CHOP 等待该客户端而停顿的当前计数。
  • steady_total：Sync Out CHOP 按时收到回复的总次数。
  • steady_consecutive：Sync Out CHOP 按时收到回复的当前计数：
  • reply：客户端最后一次回复，所有客户端应具有相同的递增数值。


类似地，一个 Info CHOP 会揭示更多信息：Info CHOP Channels

间歇性连接

每当客户端回复，Sync Out CHOP 就会立即认为它可靠，并在之后的每一帧等待它。 然而，当客户端连续超时若干次后，Sync Out CHOP 会持续忽略它，直到它再次按时回复。 这也适用于已完全停止通信的客户端。 连续超时次数由 Client Timeouts (consecutive) 参数控制，并反映在 timeout_consecutive Info DAT 列中。

修复客户端掉帧

如果某台客户端在掉帧，可用 info DAT 检查服务器端的 Sync Out CHOP。查看 timeout_consecutive 列。同时留意 Sync In CHOP 名为 sync_incompletes 的 info chop 通道。如果这两个属性中有一个或两个在增长，试着调整 sync CHOP 的 TimeOut 参数。已知增大该值可以解决此问题。

封禁

如果某客户端的通信不可靠，时而稳定、时而超时，可以通过启用 Ban Clients 并相应设置 Total Timeouts 来永久忽略它。一旦客户端超时达到一定次数，其 Info DAT 的 include 列会报告 banned，之后它将被始终忽略，即使它又开始按时响应。

重置

Sync Out CHOP 每次初次启动时，所有客户端都会被接受，没有任何封禁。在 Sync Out CHOP 中按下 Clear Stats 也会回到此状态，清除所有封禁列表和总计，即使在远程客户端的 Info CHOPs 中。

另见 Syncing Multiple Computers 和 Hardware Frame Lock。

参数 - Sync In 页

Active active - CHOP 当前是否尝试将自己同步到 Sync Out CHOP。
Multicast Address multicastaddress - 用于通信的 IP 地址（224.0.0.1）。
Network Port port - 与该地址关联的网络端口。
Timeout (msec) timeout - CHOP 等待其他 Sync CHOP 同步信号的最长时间。该值以毫秒表示。

参数 - Common 页

Time Slice timeslice - 开启后强制通道为「Time Sliced」。Time Slice 是上一个计算帧与当前计算帧之间的时间。
Scope scope - 为了确定哪些通道受到影响，一些 CHOP 在 Common 页上使用 Scope 字符串。
Sample Rate Match srselect - - 处理多个输入 CHOP 采样率不同的情况。发生重采样时，曲线按 Interpolation Method 选项进行插值；若没有可用的 Interpolate 选项，则按「Linear」插值。
  • Resample At First Input's Rate first - 使用第一个输入的速率重采样其他输入。
  • Resample At Maximum Rate max - 重采样到最高采样率。
  • Resample At Minimum Rate min - 重采样到最低采样率。
  • Error If Rates Differ err - 不接受互相冲突的采样率。
Export Method exportmethod - - 这决定如何把 CHOP 通道连接到参数。更多信息请参阅 Export 文章。
  • DAT Table by Index datindex - 使用停靠的 DAT 表格，并通过通道在该 CHOP 中的索引来引用通道。
  • DAT Table by Name datname - 使用停靠的 DAT 表格，并通过通道的名称来引用通道。
  • Channel Name is Path:Parameter autoname - 通道即完整的导出目标位置，例如 geo1/transform1:tx。
Export Root autoexportroot - 该路径指向根节点，通过 Channel Name is Path:Parameter 导出的所有路径都相对于它。
Export Table exporttable - 使用 DAT Table Export Methods 时用来存放导出信息的 DAT（见上文）。

Info CHOP 通道

Sync In CHOP 的额外信息可通过 Info CHOP 获取。

Sync In CHOP 特定的 Info 通道

  • sync_incompletes - 系统同步时该数值保持不变；每当响应的客户端数与预期数不符，该数值就会增加。When all is steady, the number does not change。
  • sync_totaldelay - 等待 Sync Out CHOP 的总时长（毫秒）。
  • sync_lastdelay - 最后一条消息等待 Sync Out CHOP 的时长（毫秒）。
  • sync_serial - 从 Sync Out CHOP 发来的最后一个序列索引。每发送一条消息递增。

通用 CHOP Info 通道

  • start - CHOP 区间的起始，以采样计。
  • length - CHOP 中的采样数。
  • sample_rate - 通道的采样率，单位为帧每秒。
  • num_channels - CHOP 中的通道数。
  • time_slice - 如果 CHOP 启用了 Time Slice 则为 1，否则为 0。
  • export_sernum - 导出连接被更新的次数。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
