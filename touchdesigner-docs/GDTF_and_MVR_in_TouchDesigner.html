TouchDesigner 中的 GDTF 与 MVR

常规信息

GDTF（General Device Type Format）和 MVR（My Virtual Rig）是描述娱乐行业设备、其功能、放置与配接的开放标准。这两种文件格式的目的都是让建筑软件、预可视化、控制硬件和软件之间的设备与设置信息交换更容易。 两种格式其实都是 .zip 压缩包，内含基于 xml 的描述以及相邻的媒体文件，如 3d 模型、图标和纹理。

GDTF 文件包含单个设备的描述，而 MVR 在 GDTF 之上构建，封装设备可能被使用的完整场景，包括桁架、舞台和其他场景元素。MVR 允许通过单个文件导入整套舞台设置，包括所有设备寻址信息。

在 TouchDesigner 中使用 GDTF 和 MVR 的目的，是让对灯具（或任何可通过 DMX 及相关协议控制的对象）的支持成为一个相当简单直接的过程。GDTF 的实现建立在 DMX Fixture POP 和通用 POP 属性工作流程之上。借助属性和 DMX Fixture POP，传输颜色信息的 DMX 通道可以直接由 POP 颜色属性驱动，而不必重排通道和采样来构造灯具的 DMX 通道布局。在处理较高分辨率的数据通道（如 16 位颜色或移动头灯中的变换通道）时，这尤其有优势。这些仍然可以表示为简单属性，并在 DMX Fixture POP 中指定为 16 位 DMX 通道，由 POP 负责构造通道映射。

GDTF 灯具文件

GDTF 灯具文件通常由设备制造商分发。另一个不错的通用资源是 "GDTF Share"，制造商和娱乐行业专业人士都在那里上传大量灯具的 GDTF 文件。有些灯光控台有自己的灯具库，与控台配合工作时，向控台操作员索要 GDTF 文件可能更合理，以确保所有人使用相同的定义。

MVR 文件

关于 MVR 文件的一个有趣之处是，虽然它们本应包含所有必需的 GDTF 文件，但往往只包含 GDTF 存根。因此需要手动获取相关 GDTF 文件，才能得到可用的 rig。

TouchDesigner 软件包

TDGdtf

TDGdtf 是一个组件，用于解析 GDTF 文件、创建必要的 POP 几何和属性、填充 DMX Fixture POP 的 DMX Channel 页，并把所有 DMX Channel Function 作为参数暴露出来。该组件能够通过其输入创建带寻址的灯具副本，这意味着所有同类型且运行相同 Mode 的灯具都可以由单个 TDGdtf COMP 控制。一个可循环回该 COMP 第二个输入的 POP 输出可用于查找属性，从而能高效控制灯具的任何方面，例如灯具的灯光颜色或 pan/tilt 值。 除了把所有 DMX Channel 功能作为参数暴露之外，该组件还会为 gdtf 定义中标记为 master 通道的所有通道创建一个 Master 参数，通常涉及调光通道，以便快速访问……

目前尚未实现的有虚拟通道、灯具的几何表示，以及考虑 gdtf 文件灯光测量数据的预可视化。

设置

最好把 TDGdtf 软件包安装到 TouchDesigner 使用的 virtual environment 中。可以直接从 github 安装：

pip install git+https://github.com/TouchDesigner/TDGdtf.git

用法

安装后，你可以在项目中放置一个 Base COMP，并把 External .tox Path 参数设为表达式 mod.TDGdtf.toxPath('TDGdtfFixture') 最后按 Reload 加载所引用的 .tox 文件。

在 TDGdtf Fixture COMP 的「Fixture」参数页上，选择要加载的 GDTF。按 Parse 并在 Mode 参数下选择灯具所设的 mode。

解析器会在组件中创建一个 POP 网络，复制其结构控制架构（而不是实际物理几何），并带上控制该灯具所需的全部属性。创建的属性用于填充 DMX Fixture POP 的 DMX Channel Page。属性本身由「Channel Functions」页上创建的参数控制。

寻址灯具是通过 TDGdtf Fixture COMP 的第一个输入完成的。这里，输入 POP 中的点数表示该类型和模式的灯具数量。连接到该 COMP 的 POP 可以指定点属性，以便高效地寻址每个灯具。这些属性是：

  • DMXFixtureNet (uint)
  • DMXFixtureSubnet (uint)
  • DMXFixtureUniverse (uint)
  • DMXFixtureChannel (uint)
  • DMXFixtureNetAddress (uint4)

并非所有属性都必须指定。只指定 universe 就能控制灯具落在哪个 universe 上，而无需同时设置 dmx 起始通道。如果需要，这仍可以留给 DMX Fixture POP 自动控制。

TDGdtf COMP 内的 DMX Fixture POP 名为“fixture”，应通过网络中的 DMX Out POP 引用它。

查找

TDGdtf Fixture COMP 的输出可以通过 Lookups 等方式，在 POP 中直接控制属性。例如要控制一个简单灯具的颜色，可以连接一个 Lookup Texture POP，引用包含颜色的 TOP，并确保把 Lookup Texture POP 的 Output Attribute Scope 参数设为保存该灯具颜色信息的属性名称。然后把该 POP 的输出插入 TDGdtf COMP 的第二个输入。

尽管这感觉有点像反馈回路，但它实际上只是一个内部桥接，用来从外部修改属性，而不必改动 COMP 的内部。这样即使通过例如载入新的灯具固件来更换灯具定义，作品中的生成 / 创意部分也能保持完整。

TDMvr

TDMvr 建立在 TDGdtf 之上，是一个组件，用于解析 MVR 文件、提取所有灯具数据、把其中包含的 GDTF 文件放入本地文件夹，并创建 TDGdtf 组件及其各自的灯具寻址内容。MVR 文件中包含的其他舞台几何目前会被忽略。

设置

TDMvr 包最好安装到 TouchDesigner 使用的 virtual environment 中。它可以直接从 github 安装： 

pip install git+https://github.com/TouchDesigner/TDMvr.git

由于 TDMvr 依赖 TDGdtf，后者会一并安装。

用法

安装完成后，可以在项目中放置一个 Base COMP，并把 External .tox Path 设为表达式 mod.TDMvr.toxPath('TDMvr')。最后点击 Reload 载入所引用的 .tox 文件。

在“Scene”参数页上，选择要载入的 MVR 文件并点击 Load。该组件会在内部创建所需的 TDGdtf 组件，并提取所有其他相关数据。

如前所述，MVR 文件中包含的 GDTF 文件往往只是存根，除了要使用的灯具名称和模式之外并没有任何有意义的信息。你需要前往制造商页面或从 Share 获取 GDTF 文件，替换已创建的 TDGdtf 组件中的引用，然后重新解析。

有关这两个包的更多信息，可在它们各自 github 页面上的 README 中找到。
