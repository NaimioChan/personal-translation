Curveclay SOP

摘要

Curveclay SOP 与 Clay SOP 类似，都是直接操纵曲面来使样条曲面变形，而不是修改 CV。不过，它使用的不是曲面上的一个点，而是一个或多个面来使该曲面变形。此外，CurveClay 目前还不支持多边形网格。

输入的组合将决定变换模式。对于任意输入组合，下列参数会修改该 SOP 的以下行为。

curveclaySOP_Class

参数 - Curve Clay 页

Face Group facegroup - 要投影的面（NURBS、Bézier、多边形）子集，或要变形的轮廓子集，取决于连接了多少个输入。

例如：0.5 1.2-3.9 5.*

当第 2 个输入不存在时，这个组甚至可以接受曲面（可能与轮廓曲线混在一起），表示必须使用该曲面的所有轮廓。
那么上面的示例就变成：0.5 1.2-3.9 5

Surface Group surfgroup - 当三个 SOP 输入全部连接时，要变形的样条曲面子集。
Divisions on Face divs - 在轮廓或面上求值的点数。该 SOP 通过用直线近似给定曲线来使曲面变形。因此，分段越多越慢，但结果看起来更好。在变形轮廓时，以及当静止面与变形面具有相同数量的断点时，需要指定的细分可以更少。
Sharpness sharp - 指定面周围要变形的区域。Sharpness 越大，它们周围的变形区域越小（从而对曲面的拉扯更尖锐）。
Refinement refine - 通常，CurveClay 会自动细化曲面。不过，你也可以指定一定程度的细化控制。一般来说，曲面细化得越多，结果越平滑。更好的细化会得到更密集的曲面。你应该在 -1 到 1 之间的取值上做试验。当值为负时，该 SOP 会先把曲面细化到细化值为 0 时的相同细节级别，然后再对其进行反细化。值越低，反细化程度越高。

参数 - Projection 页

控制曲线投影。仅当 3 个输入都存在时启用。

Projection Axis projop - - 可选择几种投影轴：
  • X xaxis - 笛卡尔轴 - X、Y 或 Z。
  • Y yaxis - 笛卡尔轴 - X、Y 或 Z。
  • Z zaxis - 笛卡尔轴 - X、Y 或 Z。
  • Minimum Distance mindist - 将曲线点投影到曲面上离它们最近的位置。
  • User Defined: other - 在下方字段中输入 Vector。
projdir - - 指定投影的方向向量。

参数 - Displacement 页

如何使曲面变形。仅当只有 1 个输入时启用。

Displacement Axis deformop - - 可选择几种投影轴：
  • Surface Normal snormal - 轮廓将沿曲面法线变形。
  • X xaxis - 笛卡尔轴 - X、Y 或 Z。
  • Y yaxis - 笛卡尔轴 - X、Y 或 Z。
  • Z zaxis - 笛卡尔轴 - X、Y 或 Z。
  • User Defined: other - 在下方字段中输入向量。
deformdir - - 指定位移的方向向量。

Distance deformlen - 沿向量变形的距离。
Deform Inside of Loop deforminside - 选择是否应变形闭合环的内部。
Consider Profiles Individually individual - 选择是否让多条曲线构成闭合环。

说明

在环绕曲面上使用 CurveClay 时，有几点需要记住：

  • 你可能需要使用更多的分段，因为跨越环绕曲面接缝时，直线近似会被关闭，可能需要更多采样点。
  • 如果没有跨越接缝，曲面的细化就只是局部的。但当曲面的变形区域接近接缝时，细化会在整个曲面上进行。如果整个曲面都被细化了，不必惊慌。

Info CHOP 通道

Curveclay SOP 的额外信息可通过 Info CHOP 查看。

SOP 通用信息通道

  • num_points - 此 SOP 中的点数。
  • num_prims - 此 SOP 中的图元数。
  • num_particles - 此 SOP 中的粒子数。
  • last_vbo_update_time - 在另一个线程中根据 SOP 的 CPU 数据更新 GPU 上的几何数据所花的时间。由于它属于另一个线程，此时间不计入通常的帧时间。
  • last_meta_vbo_update_time - 在另一个线程中根据 SOP 的 CPU 数据更新 GPU 上的元表面几何数据（如 metaball 或 nurbs）所花的时间。由于它属于另一个线程，此时间不计入通常的帧时间。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
