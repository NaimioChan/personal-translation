Skin Deform POP

摘要

（needs to be updated）一种常见的基于变换或完整骨架使几何变形的做法称为 Skinning（蒙皮）。蒙皮让每个点受到若干变换的影响，每个变换有不同的权重。

属性说明

Detail 属性 pCaptPath

pCaptPath 细节属性是一个索引属性，包含用作骨骼的 COMP 的路径列表。第一个路径对应索引 0，下一个对应索引 1，依此类推。可以使用 SOP to DAT 查看此属性的值。

Detail 属性 pCaptData

此属性的条目数与 pCaptPath 相同。每个条目包含 20 个浮点数。前 16 个构成该关节绑定/静止姿势的矩阵。其余 4 个在 TouchDesigner 中未使用，是来自 Houdini 的遗留值。

点或顶点属性 pCapt[]

该属性包含成对的信息。每对中第一个值是影响该点的变换的索引编号，第二个数值是该特定变换的权重。变形时，TouchDesigner 使用此属性中的索引，通过 pCaptPath 找到正确的 COMP。给定点的所有权重之和应为 1。索引为 -1 表示该条目没有要应用的变换。该属性有一个大小，表示它包含的条目数（例如 pCapt[8]）。该大小同时包含索引和权重，因此如果 pCapt 的大小为 8，意味着每个点最多应用 4 个变换（4 个变换和 4 个权重）。pCapt 的大小将足以容纳受最多变换影响的点。几何中可能（甚至很可能）只有一两个点受到的变换远多于其他点，你可以使用 Bone Group SOP 裁掉这些点，使 pCapt 更小。

不支持的 Houdini 属性

pCaptSkelRoot - 此属性是 Houdini 中骨架根部的路径。由于 Houdini 中的路径不太可能与 TouchDesigner 中的路径匹配，我们不支持此属性。取而代之的是 Deform SOP 和 MAT 的 Deform 页中的 Skeleton Root Path 参数。

pCaptAlpha - 不支持此属性。

pCaptFrame - 不支持此属性。

在 CPU 上变形

要在 CPU 上变形，只需使用 Deform SOP。Deform SOP 使用 Point Capture 属性而非 Vertex Capture 属性。你需要在 Skeleton Root Path 参数中指定骨架的路径。

例如，要在 FBX 中于 CPU 上变形：可以将带捕获属性的 Import Select SOP 用作 Deform SOP 的输入。Deform SOP 的骨架根路径将是 FBX COMP。

在 GPU 上变形

在 GPU 上变形非常快（几乎无成本），但设置需要多做一些工作。第一个问题是大多数 GPU 单次只能处理约 50 到 200 根骨骼所需的数据。这意味着几何需要拆分为若干子部分，每个子部分受骨架中不同子集的骨骼影响。这些称为 Bone Groups。Bone Group SOP 会将带捕捉属性的几何拆分为不同的骨骼组。细节属性 pCaptData 和 pCaptPath 会被拆分为带后缀的细节属性，后缀从 0 开始。例如，如果几何被拆分为两个骨骼组，就会有细节属性 pCaptData0、pCaptPath0、pCaptData1 和 pCaptPath1。原始的 pCaptData 和 pCaptPath 将被删除。点/顶点属性 pCapt 将变为名为 pCapt 的顶点属性。此外还会有名为 boneGroup0、boneGroup1 的图元组，包含每个骨骼组中的所有图元。

你应使用 Delete SOP 将每个图元骨骼组分离出来。接着放入一个支持形变的 MAT（例如 Phong MAT）。你需要向该 MAT 提供一些信息：

  • 包含你希望此 MAT 使用的形变信息的 SOP 路径。这通常是 Delete SOP，或其后某个节点。
  • pCaptData 和 pCaptPath 属性的名称。例如，如果你用此 MAT 渲染骨骼组 0，就应指定 pCaptData0 和 pCaptPath0。
  • 骨架根部的路径。

使用 GLSL MAT 变形

GLSL MAT 支持自动变形代码，你只需像 Phong MAT 一样在 deform 页设置选项，并对顶点位置和法线调用 [code]TDDeform()[/code] 来进行变形。正确的变形代码会自动生成，并在发送到 GPU 时前置到你的着色器代码中。

编写自己的变形代码

你可以在 GLSL 着色器中自行编写任何变形代码。以下是自动生成的变形代码的样子，如果你想以此为起点可以使用。在此示例中，pCapt 属性有 12 个条目（信息弹出窗口中为 pCapt[12]），这意味着它可以引用 6 根骨骼。由于它们被合并为 vec4 作为着色器输入，因此着色器中的 pCapt 声明为 in vec4 pCapt[3]，因为总共是 12 个条目。注意，如果 SOP 中 pCapt 的大小不能被 4 整除，则需小心。在这种情况下，GLSL 着色器中最后一个 pCapt 条目的最后一对值将是未定义的。例如，如果 SOP 中 pCapt 是 pCapt[10]，那么着色器中的 pCapt 仍会声明为 in vec4 pCapt[3]。但 pCapt[2].z 和 pCapt[2].w 的值是未定义的，不应使用。索引不一定等于 -1，因此无法据此检查。

TDBoneMat() 返回的矩阵由该骨骼在该帧的世界变换和绑定姿势组成。绑定姿势不会改变，包含在 pCaptData 属性中。世界变换每帧根据骨骼的 COMP 计算。它们像这样相乘： WorldTransform*BindPose

vec4 TDSkinnedDeform(vec4 pos)
{
  vec4 newp = vec4(0.0, 0.0, 0.0, 1.0);
  int index;
  if (pCapt[0].x >= 0.0)
  {
      index = int(pCapt[0].x);
      newp += (TDBoneMat(index) * pos) * pCapt[0].y;
  }
  else
  {
      return pos;
  }
  if (pCapt[0].z >= 0.0)
  {
      index = int(pCapt[0].z);
      newp += (TDBoneMat(index) * pos) * pCapt[0].w;
  }
  if (pCapt[1].x >= 0.0)
  {
      index = int(pCapt[1].x);
      newp += (TDBoneMat(index) * pos) * pCapt[1].y;
  }
  if (pCapt[1].z >= 0.0)
  {
      index = int(pCapt[1].z);
      newp += (TDBoneMat(index) * pos) * pCapt[1].w;
  }
  if (pCapt[2].x >= 0.0)
  {
      index = int(pCapt[2].x);
      newp += (TDBoneMat(index) * pos) * pCapt[2].y;
  }
  if (pCapt[2].z >= 0.0)
  {
      index = int(pCapt[2].z);
      newp += (TDBoneMat(index) * pos) * pCapt[2].w;
  }
  newp.w = 1.0;
  return newp;
}

  • total_cooks - 自进程启动以来该操作符的计算次数。

  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
