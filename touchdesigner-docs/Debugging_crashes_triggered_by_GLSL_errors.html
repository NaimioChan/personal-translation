调试 GLSL 错误引发的崩溃

随着 TouchDesigner 运行的 API 转向 Vulkan，在某些非法操作发生时，GLSL 代码更容易导致整个应用崩溃。尤其是采样器数组或 uniform 数组中的越界数组访问这类错误，可能引发崩溃。

如果你在编写自定义 GLSL MAT 或 TOP 代码，并遇到提示 GLSL 可能是元凶的整个应用崩溃，有几件事可以立刻检查。

  1. 在 GLSL TOP 中，确保对 sTD*Inputs[] 数组的访问在范围内。如果是通过变量（而不是常量）动态选择要采样的输入，请使用 TD_NUM_*_INPUTS 定义在代码中添加 if 语句。
  3. 如果使用 Uniform 数组（不是纹理缓冲区），请确保为 GLSL 代码可能访问的任何数组条目提供足够的数据。
  4. 确保没有 for 循环或 while 循环之类的无限循环。
  5. 如果你的着色器非常复杂，某些 GPU 可能无法在操作系统判定应用崩溃之前完成工作。你可能需要针对低端 GPU 优化代码。

Robust Buffer Access

某些 GPU 能够启用名为 Robust Buffer Access 的功能。它有助于防止由 GLSL 数组访问问题引起的崩溃。不过 not 不应把它当作避免错误的手段，而只能用来获得提示：崩溃是否由越界数组访问引起。要启用此功能，请设置系统环境变量 TOUCH_ROBUST_BUFFER_ACCESS=1 并启动 TD。如果设置后崩溃不再发生，就说明崩溃很可能源于 GLSL 代码的越界数组访问。如果你的 GPU 不支持该功能，会弹出消息框提示不支持。

Nvidia Aftermath

在 Nvidia GPU 上，如果遇到无法确定原因的崩溃，可以通过设置 Windows 系统环境变量来生成特殊的 GPU 专用崩溃文件 

 TOUCH_ENABLE_NV_AFTERMATH=1

将生成的文件发送到 support@derivative.ca，我们可以进一步查看。
