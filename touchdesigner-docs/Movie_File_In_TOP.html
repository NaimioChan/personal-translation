Movie File In TOP

摘要

Movie File In TOP 把影片、静态图像或一系列静态图像加载到 TOP 中。它可以读取 .jpg、.gif、.tif 或 .bmp 格式的图像。它可以读取 QuickTime 的 .mov 格式、.mp4、.mpg、.mpeg、.avi、.wmv、.dpx、Cineform 和 Hap Q 格式（包括带 Alpha 的 Hap Q）的影片。

它还支持 NotchLC 编解码器、EXR 文件（.exr）以及一些 .swf 和 .flv Flash 文件，还有 DXT1/3/5 和 RG 压缩的 .dds 文件。也可以用 http:// 指定 URL，从网上获取图像和影片。

在 Nvidia GPU 上，通过「Tune」页上的 Hardware Decode 参数访问硬件解码器。在支持的硬件上，这支持 10 位和 12 位的 H264/H265 以及 YUV 444 文件，并转换为 16 位像素通道。它还能解码的其他编解码器包括 VP8、VP9、JPEG、AV1、VC1。 更多信息 here.

读取支持更高位深的文件格式（如 10 位/16 位/32 位）时，只要 Common 页上的「Pixel Format」菜单保持为「Use Input」，就会自动使用合适的像素格式。也就是说，16 位文件会自动让每个像素的每个颜色通道为 16 位。

完整列表参见 File Types。

通过给 Movie File In TOP 附加一个 Info CHOP（参见下面关于 Info CHOP 的说明）来检查其状态。它会显示影片长度、分辨率、每秒图像数（sample_rate 通道）以及文件中是否有音频等信息。它还会显示动态信息，例如影片打开状态、当前帧、预读帧和队列大小、丢帧数、CPU 解码时间和 GPU 上传时间。

注意影片的「每秒图像数」（sample_rate）可能与时间轴的每秒帧数不同。提到影片的「index」时，指的是影片文件中图像的序列，与全局项目帧率无关。

另请参阅 Movie File In TOP 优化页面 Movie Playback，以及 Hap、Movie File Out TOP、Cineform 和 Video Stream In TOP。

参数 - Play 页

File file - 要加载的图像或影片文件的路径与名称。图像和影片格式即 File Types 中列出的那些。可以用 http:// 指定互联网上的文件……

要把一个图像文件夹当作一部影片来处理，请指定包含这些图像的文件夹而不是文件名。所有文件必须分辨率相同。它会把该文件夹中的所有静态图像/影片当作一部影片中的各帧。图像的顺序按字母数字排列。默认第一张图像的索引为 0，第二张为 1，依此类推，与文件名无关。覆盖 Trim 参数页上的采样率即可按任意帧率回放该图像序列。

在包含图像序列的目录中使用 info.xml 文件，可以指定每秒帧数以及与图像序列配合使用的音频文件。示例 xml 文件： 

<?xml version="1.0" encoding="ISO-8859-1" standalone="yes" ?>
  <Settings>
      <attributes fps="30.0" />
      <audio filename="audio.wav" />
  </Settings>

可以用 URL 获取图像和影片。图像或影片会下载到用户的 Derivative 临时目录，并读入 Movie File In TOP。

Play Mode playmode - - 指定播放影片的方法，共有 3 个选项。
  • Locked to Timeline locked - 此模式把影片位置锁定到时间轴。在时间轴上拖动或跳转会相应地改变影片位置。此模式下 Play、Reset、Speed 和 Index 参数被禁用，因为时间轴直接与影片位置绑定。
  • Specify Index specify - 此模式允许用户使用下面的 Index 参数指定影片中的特定位置。需要随机访问影片中任意位置时使用此模式。
  • Sequential sequential - 此模式持续播放，与时间轴位置无关（Index 参数被禁用）。下方的 Reset 和 Speed 参数被启用，可提供一定控制。
  • Timecode Object/CHOP/DAT timecodeop - 此模式允许用户通过引用时间码来设置影片索引，时间码可以是 CHOP、DAT 或 Timecode Class 对象。

参数 - Image 页

Interpolate Frames interp - 根据精确时间在帧之间插值。例如索引（以帧计）为 1.5 时，第 1 帧和第 2 帧会各占 50% 混合。如果索引为 1.7，则第 1 帧的 30% 与第 2 帧的 70% 混合，依此类推。
Deinterlace deinterlace - - 适用于以场存储的影片，其中每幅图像由两幅交织在一起的图像组成。每秒 30 帧的影片每秒会包含 60 个场。对每幅图像，第一个场的偶数扫描行与第二个场的奇数扫描行交织。Movie File In TOP 有几种处理方式：
  • Off off - 原样输出影片图像。
  • Even even - 只取文件图像的偶数扫描行，并通过在偶数扫描行之间插值来生成奇数扫描行。（出于历史原因，反交错时扫描行 0 位于图像顶部。）
  • Odd odd -
  • Bob (Split) bob -
Field Precedence precedence - - 在逐场提取的情况下，默认先提取 Even 场，否则先提取奇数场。视频行业对此并没有统一标准。
  • Even even - 用于磁盘文件碎片化的情况。Movie File In TOP 会在使用之前先把影片的帧读入内存，这可以消除因文件碎片化、其他资源访问硬盘或影片循环而产生的播放爆音或卡顿。
  • Odd odd -

Decode Pixel Format decodepixelformat - - 尽管视频/图像可能以某个位深（8、10、12 位等）编码，但并不总是需要按编码位深来使用这些数据。如果你的输出是 8 位显示器，并且不对数据做大量处理，那么直接解码到 8 位缓冲区也许是合理的。这样既节省用于处理的 GPU 周期，也节省 GPU 内存。此菜单让你指定是优先获得解码出的最快像素格式，还是最佳/最高质量。如果格式本身以 8 位编码，那么两种情况下都会是 8 位。

参数 - Tune 页

Pre-Read Frames prereadframes - 设置 TouchDesigner 预读多少视频帧并存入内存。Movie File In TOP 会在使用之前先把影片的帧读取并解码到 CPU 内存中，这可以消除因某些帧解码过久、其他资源访问硬盘或影片循环而产生的播放爆音或卡顿。读取图像序列时，预读帧越多，就能同时解码更多图像。只要机器有足够的 CPU 核心，就能实时播放 .exr 这类重型文件格式。
Frame Read Timeout frametimeout - TouchDesigner 从硬盘等待一帧的时间（毫秒），超时则放弃。达到 Disk Read Timeout 时间后，该帧会被直接跳过。这也适用于通过 http:// 下载的网络文件。
Frame Timeout Strategy frametimeoutstrat - - 开启时，如果达到 Disk Read Timeout，TouchDesigner 会用最新的可用帧代替被跳过的帧。
  • Keep Frame keep - 持续显示当前正在输出的同一帧。
  • Best for Playback playback - 尝试挑选最适合播放的帧。这可能比当前显示的帧更新，但不完全是所请求的那一帧。
  • Best for Seeking seeking - 尝试显示任意一帧，无论是目标帧之前还是之后。适合在 UI 中通过 shuttle 控件拖动影片时使用。
Always Load Initial Frame alwaysloadinitial - 如果开启此参数，则对第一个加载的帧会忽略 Frame Read Timeout，始终等待第一帧，以确保节点总是以有效图像启动。
File Open Timeout opentimeout - TouchDesigner 等待影片打开的时间（毫秒）。达到 Disk Open Timout 后，Movie File In TOP 会停止等待，图像全黑，右下角显示一个灰色方块。如果下次该 TOP 计算时文件仍未打开，它会再次等待，并重复同样的过程，直到文件打开或打开失败。
Pre-Download HTTP Addresses predownloadhttp - 开启时，文件会完全下载后才播放。关闭时，文件会从其 URL 流式播放。
Update Image updateimage - 设为 0 时图像不会更新。影片索引会继续前进，但输出图像不会更新。当你用 Movie Audio CHOP 从影片中取音频而并不关心视频时，这很有用。
Max Decode CPUs maxdecodecpus - 限制用于解码某些支持多 CPU 解码的视频编解码器（如 H264/H265 和 Cineform）的最大 CPU 数。注意，这不影响图像序列播放的多线程解码，后者通过增大 Pre-Read Frame 参数来控制。
High Performance Read highperfread - 播放需要极高 SSD 读取速度的文件（例如高分辨率（4K+）HAP Q 文件）时应使用此选项。在这些情况下它能大幅提升读取性能。不应把它用于低分辨率或低数据率的文件，例如 1080p H264 文件。
High Performance Read Factor highperfreadfactor - 进行高性能读取时，此参数控制磁盘上读取操作的大小。无论编解码器请求的最大操作是多少，都会乘以 read factor，之后所有读取都会读取这么多数据。根据硬盘不同，这可以提高吞吐量。例如某次请求读取 1MB，而系数设为 3，那么实际操作会从磁盘读取 3MB，多读的 2MB 会为下一帧做好准备，很可能接下来 2 帧已经存在于 CPU 内存中。
Hardware Decode hwdecode - 控制此节点是否通过 Nvidia 硬件解码芯片使用硬件解码。你可以用 Info CHOP 的 'hardware_decode' 通道检查是否正在使用硬件解码。此参数对 Hap 和 NotchLC 编解码器无效，它们始终使用硬件解码。

  • 4X 4x - 将输入的分辨率乘以该数值。

  • Limit Resolution limit - 限制输入分辨率不超过此分辨率，同时保持宽高比不变。
  • Custom Resolution custom - 直接控制宽度和高度。

  • Use Input useinput - 使用输入的宽高比。
  • Resolution resolution - 使用图像所定义分辨率的宽高比（即 512x256 为 2:1），此时每个像素为方形。

Input Smoothness inputfiltertype - - 控制对 TOP 输入图像的像素过滤。
  • Nearest Pixel nearest - 使用最近像素或精确图像表示。在任何非 Native Resolution 的缩放级别查看时，图像会显得有锯齿。
  • Interpolate Pixels linear - 在像素之间使用线性过滤。这就是让查看器中的 TOP 图像在各种缩放级别下都好看的方式，在使用除 Native Resolution 以外的任何 Fill Viewer 设置时尤其有用。
  • Mipmap Pixels mipmap - 缩放图像时使用 mipmap 过滤。这可用于减少细节丰富的运动/缩放图像中的伪影和闪烁。
Fill Viewer fillmode - - 决定 TOP 图像在查看器中的显示方式。

注意： 要理解 TOP 如何处理图像，在刚开始放置 TOP 时，你会希望将此设为 Native Resolution。这样你可以看到实际发生的情况，而没有任何查看器自动缩放。

  • Use Input useinput - 使用与其输入相同的 Fill Viewer 设置。
  • Fill fill - 拉伸图像以适应查看器边缘。
  • Fit Horizontal width - 拉伸图像以在水平方向适应查看器。
  • Fit Vertical height - 拉伸图像以在垂直方向适应查看器。
  • Fit Best best - 拉伸或压扁图像，使图像的任何部分都不被裁剪。
  • Fit Outside outside - 拉伸或压扁图像，使图像在保持其比例的同时填满查看器。这通常会导致图像的一部分被查看器裁剪。
  • Native Resolution nativeres - 在查看器中以图像的原始分辨率显示。
Viewer Smoothness filtertype - - 控制查看器中的像素过滤。
  • Nearest Pixel nearest - 使用最近像素或精确图像表示。在任何非 Native Resolution 的缩放级别查看时，图像会显得有锯齿。
  • Interpolate Pixels linear - 在像素之间使用线性过滤。用于让查看器中的 TOP 图像在各种缩放级别下都好看，在使用除 Native Resolution 以外的任何 Fill Viewer 设置时尤其有用。
  • Mipmap Pixels mipmap - 缩放图像时使用 mipmap 过滤。这可减少细节丰富的图像在移动/缩放时的伪影和闪烁。当输入为 32 位浮点格式时，只使用 nearest 过滤（无论选择什么）。
Passes npasses - 将 TOP 的操作重复指定次数。第一次之后的每一遍都会取上一遍的结果，并用上一遍的结果替换该节点的第一个输入。例外情况是使用 compute shaders 时的 GLSL TOP，此时输入始终是所连接 TOP 的图像。
Channel Mask chanmask - 允许你选择 TOP 将作用于哪些通道（R、G、B 或 A）。默认选中所有通道。
Pixel Format format - - 用于存储图像中每个通道数据的格式（即 R、G、B 和 A）。更多信息请参阅 Pixel Formats。
  • Use Input useinput - 使用输入的像素格式。
  • 8-bit fixed (RGBA) rgba8fixed - 每个通道使用 8 位整数值。
  • sRGB 8-bit fixed (RGBA) srgba8fixed - 每个通道使用 8 位整数值，并以 sRGB 色彩空间存储颜色。注意这not对像素值应用 sRGB 曲线，而只是用 sRGB 曲线存储它们。这意味着较暗的值使用更多数据，较亮的值使用更少。下游读取这些值时会转换回线性。更多信息请参阅 sRGB。

  • 16-bit fixed (Mono) mono16fixed - 单通道，RGB 都具有相同的值，Alpha 为 1.0。每像素 16 位。

Info CHOP 通道

Movie File In TOP 的额外信息可以通过 Info CHOP 访问。

Movie File In TOP 的专用信息通道

  • index - 当前显示的帧索引。这使用影片文件的 FPS，而不是时间轴帧。
  • true_index - 当影片应用了 Trim 时，这里显示实际显示的影片内帧索引。
  • index_fraction - 从影片开头到结尾由 0 到 1 的归一化索引值。
  • file_resx - 影片的宽度，单位为像素。
  • file_resy - 影片的高度，单位为像素。
  • start - 目前未使用。
  • length - 影片的长度，以影片帧计。
  • sample_rate - 影片的 FPS。
  • last_index_uploaded - 最后上传到 GPU 的影片帧。
  • mv_has_audio - 影片有音轨时为 1，没有为 0。
  • preloading - 影片当前正通过 preload() Python 方法预加载时为 1。
  • odd_field - 使用 Bob（split）反交错时，1 表示正在显示奇数场，0 表示正在显示偶数场。
  • last_frame - 当前正在显示影片最后一帧时为 1，否则为 0。注意如果影片在循环，丢帧时最后一帧可能永远不会被显示。
  • loop_frame - 影片刚刚循环过时为 1。
  • pre_read_misses - 统计节点想要显示某帧、但该帧尚未在 Pre-Read Cache 中准备好的次数。
  • last_pre_read_miss_wait - 节点上次等待 pre_read_misses 帧被读取所花的时间，单位为毫秒。
  • hard_drive_timeouts - 节点因读取速度不够而放弃读取某帧的次数。等待时间由 'Frame Read Timeout' 参数控制。
  • num_pre_read_frames - 已预读、已解码并准备好显示的帧数。
  • first_index_to_read - Pre-Read 缓存中第一个索引的帧索引。
  • last_frame_hd_read_time - 从硬盘读取最后一帧所花的时间，单位为毫秒。
  • last_frame_decode_time - 在 CPU 上解码/解压缩最后一帧所花的时间，单位为毫秒。这不包括 NotchLC 或硬件解码等编解码器在 GPU 上解码的时间。
  • open - 影片文件已打开时为 1。
  • opening - 影片文件正在打开但尚未打开时为 1。
  • open_failed - 打开影片失败时为 1。
  • fully_pre_read - 影片的 Pre-Read Cache 已填满解码好的帧时为 1。
  • true_length - 影片的真实长度，忽略任何修剪。
  • hardware_yuv_to_rgb - 影片编码所用的 YUV 格式正在 GPU 上转换为 RGB 时为 1。
  • has_non_av_track - 影片文件含有非视频或音频的轨道（例如字幕轨）时为 1。
  • pre_read_fails - 预读某帧失败的次数。
  • disk_read_mbit_rate - 每秒从硬盘读取的数据量，单位为兆比特。
  • has_decode_errors - 文件出现解码错误时为 1。
  • num_decode_chunks - 对于 Hap 编解码器，文件被编码为多少个块。
  • hardrware_decode - 如果 Hardware Decode 参数开启，当 GPU 能够硬件解码影片的编解码器时，此项为 1。

TOP 通用信息通道

  • resx - TOP 的水平分辨率，以像素为单位。
  • resy - TOP 的垂直分辨率，以像素为单位。
  • aspectx - TOP 的水平宽高比。
  • aspecty - TOP 的垂直宽高比。
  • depth - 如果此 TOP 包含 2D 或 3D 纹理数组，则为该 2D 或 3D 数组的深度。
  • gpu_memory_used - 此 TOP 使用的纹理内存总量。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
