模式匹配


注意: With TouchDesigner 2025 we have transitioned to a new pattern matching that is consistent throughout the product. Some uses of it are obsolete but we have legacy modes that allow older patterns and files to continue to work as-is. With POPs being a new operator family, only the new pattern matching works. See Legacy Features below. Please report any difficulties you may be having.

TouchDesigner 中有些参数用于指定多个操作符、多个通道、多个点等。例如，Render TOP 允许使用多个灯光、Geometry COMP 和摄像机。Join CHOP 和 Composite TOP 分别接受多个 CHOP 和 TOP。

作为「模式」的参数允许你指定多个名称和/或指定「通配符」，以匹配操作符、通道、点索引等名称的全部或部分。模式也用于某些 Python 方法，例如 ops() 允许你用单个字符串指定多个 OP。

有关 TouchDesigner 中存在模式匹配的各处及其特定规则，请参阅 Pattern Matching Support。

基本模式

基本模式匹配也常用于匹配通道名称。它使用以下类型的模式来选择输入 CHOP 中的现有通道，用于 Select CHOP 和 Math CHOP 的 Scope 参数等 CHOP 中，此时你只想影响某些通道而让其余保持不变。

  • pattern - 精确匹配字符串
  • * - 匹配任意字符序列的「通配符」
  • ? - 匹配任意单个字符的「通配符」
  • ^ - 不匹配
  • [alphaset] - 匹配方括号内任意一个字母字符。在 TouchDesigner 中，目前不支持 [a-g] 格式，字符必须列为 [abcdefg]
  • [int1-int2] 或 [int1-int2:increment] - 匹配数字范围内任意整数，可选增量
  • [int1,int2,int3] - 匹配给定的特定整数
  • "pattern" - 忽略空白作为分隔符的模式匹配

注意： 范围内不应有空格，即应写 [1,3,0-10:2] 而不是 [1, 3, 0-10:2]

示例

chan2 Matches a single channel name
chan3 tx ty tz Matches four channel names, each name is separated by spaces
chan* Matches each channel that starts with "chan" and ends with anything
*foot* Matches each channel that has "foot" in it, with anything or nothing before or after
t? The ? matches a single character. t? matches two-character channels starting with t, like the translate channels tx, ty and tz
r[xyz] Matches channels rx, ry and rz. that is, "r" followed by any character between the [ ]
blend[3-5] Matches number range giving blend3, blend4, and blend5.
blend[3-7:2] Matches number ranges giving blend3, blend5, and blend7. (3 to 7 in steps of 2)
blend[2-3,5,13] Matches channels blend2, blend3, blend5, blend13
t[uvwxyz] [uvwxyz] matches characters between u and z, giving channels tu, tv, tw, tx, ty and tz
"Instance 3" Matches the string "Instance 3" exactly, NOT matching Instance and 3.
"run -exec test[0-5]" Matches the string "run -exec test0" to "run -exec test5" exactly. Useful for matching Page names in Parameter DAT or entries in a Table DAT

某些节点参数还支持在匹配前展开组件组名称。

  • @groupname - 展开组中的所有项目。由于每个组都属于某个网络，可以在 @groupname 标识符前指定路径。

示例

container1/@lights1 Matches members of the lights1 group defined inside container1.

操作符模式

有些参数接受节点路径，例如 Render TOPs Geometry 或 Lights 参数。此时模式匹配可以让选择多个节点变得快速简便。

  • pattern - 搜索当前网络，匹配任何符合基本模式 pattern 的节点。
  • /subpattern1/subpattern2/subpattern3/pattern - 根据其子模式搜索每个子路径，匹配任何符合基本模式 pattern 的节点

示例

geo* Matches all nodes whose names start with "geo" in the current network
/project1/geo* Matches all nodes in /project1 whose names start with "geo"
/project[1-3]/geo* Matches all nodes in /project1, /project2, and /project3 whose names start with "geo"

索引模式

有些参数只对索引进行匹配，通常是 CHOP 和 POP（SOP 见下文），因此语法稍有不同。总是存在一个隐含的、模式将要在其上匹配的点范围，例如通道数、点数等。

  • number - 精确匹配该数字的任意索引
  • * - 匹配所有数字
  • ^ - 不匹配
  • [int1-int2] 或 [int1-int2:increment] - 匹配数字范围内任意整数，可选增量
  • [int1-int2:take:increment] - 在数字范围内，每隔 increment 匹配前 take 个数字。见下方示例。
  • [*:increment] 或 [*:take:increment] - 同上，只是范围为从 0 到最大值的所有数字。
  • [int1,int2,int3] - 匹配给定的特定整数

示例

^20 All indices except 20 are included
[3-15] All indices from 3 to 15 are included
^[100-200] Every index <100 and >200 is included
[0-15:2] Every second point from 0 to 15 is included
[0-15:2:5] Take the first 2 numbers, every increment of 5, from 0 to 15, this selects 0,1,5,6,10,11,15
[*:3] From 0 to the maximum index, every multiple of three is included. For example with 10 points, this selects 0,3,6,9

有序索引模式

某些节点（例如 Primitive POP）允许在索引选择中使用排序，规则如下

  • * 作为从 0-max 开始的范围
  • 范围内的条目按其在范围中出现的顺序被选择
  • 否定范围中的条目，是从 0-max 中减去该范围指定的索引后被选择的
[9-0] This selects 9,8,7,6,5,4,3,2,1,0 in that order
[9-0:2] This selects 9,7,5,3,1 in that order
[0-10:4,3,7] This selects 0,4,8,3,7 in that order
[15-0:2:5] This selects 15,14,10,9,5,4,0 in that order
^[*:3] With a maximum value of 10, this selects 1,2,4,5,7,8,10 in that order

注意： 有序索引模式不支持集合运算符表示法

集合运算符表示法

某些模式匹配规则（见 Pattern Matching Support）可以与集合运算符表示法配合使用，以实现更具表现力的选择。基本、操作符和索引模式（即 /project/geo1、t?、chan*、blend[2-6:2]）会创建集合，而 |、&、~ 可以在它们之间应用以下集合运算。模式将匹配最终结果集合中的任何元素。

  • | 表示两个集合的 Union
  • & 表示两个集合的 Intersection
  • ~ 表示两个集合的 Set Difference
  • ( ) 对集合运算分组，并将结果视为一个集合

这些运算的优先级依次为 ()，然后是模式中从左到右的集合运算。注意： |、&、~ 运算符优先级相同。这意味着例如

  • A | B & C IS 等于 B & C | A

示例

* ~ chan[1,5,6] Matches everything except chan1, chan5, and chan6
(* ~ geo*) | geo3 Matches everything except things that starts with "geo" and ends with anything unless its geo3
./mygeos/geo* ~ ./mygeos/geo[3-5] Matches every node in ./mygeos that starts with "geo" and ends with anything except geo3, geo4, and geo5
blend* ~ blend[0-9]* Matches everything that starts with blend except anything with a digit after blend, for example it would not match blend0_light, blend2_dark but would match blend_light and blend_dark.

旧版功能

  • Prefer using | set operator notation instead
    • 示例：使用 tx | nx 代替 tx nx
    • 以前对大多数节点而言，空格和逗号分隔的模式意味着这些模式会以 OR 方式组合。为向后兼容，不含新集合运算符的模式仍遵循此逻辑。集合运算符使其更明确
  • Prefer using the updated index pattern syntax that is consistent with basic pattern matching
    • 示例：使用 [100-120:2] ~ [0-9] 代替 100-120:2 !0-9
    • CHOP 的旧索引匹配表示法将成为一个旧版开关，对于新放置的节点现在默认关闭。开启时无法使用新的集合运算符表示法。建议改用与现有模式匹配更一致的新语法
  • Prefer using /path/to/node instead of op:/path/to/node
    • 示例：使用 /project1/geo 代替 op:/project1/geo
    • 旧路径名称的常用写法

旧索引表示法

SOP 仍使用旧式索引表示法，不支持新的集合运算符语法。示例和粗略文档请参阅 Group SOP 或 Add SOP 的参数文档
