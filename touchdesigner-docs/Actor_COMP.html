Actor COMP

摘要

Actor COMP 类似于物理系统中的一个（或多个）刚体。Actor COMP 必须与物理求解器配合使用：Bullet Solver COMP 或 Nvidia Flex Solver COMP，它们相当于这些 actor／刚体所在的世界／模拟。Actor COMP 可以是 static，表示它不受模拟中任何力的影响且无法移动（即具有无限质量）；也可以是 dynamic，表示它由力推动移动，并与世界中的其他刚体（static 或 dynamic）发生碰撞。

另请参阅：Flex、Bullet Dynamics、Bullet Solver COMP、Force COMP、Constraint COMP、Bullet Solver CHOP、Nvidia Flex Solver COMP、Nvidia Flex TOP。

用法

Bullet 中的 Actor

静态刚体可以是凹形或凸形，但动态刚体必须是凸形。不过，动态碰撞形状可以是复合的，即由其他碰撞形状组成的碰撞形状。因此，动态情况下可以用一组凸形状拼出凹形碰撞形状。这可以通过多个 SOP 实现。每个 SOP 必须是凸的，但它们的组合不必是凸的。若选择 Automatic 模式，则会由这些 SOP 创建复合碰撞形状。

Actor COMP 中的所有刚体都有对应的碰撞形状。碰撞形状决定了物体彼此如何碰撞，需要注意的是，在 viewer／render 中看到的内容不一定与碰撞形状直接一致。

碰撞形状使用 SOP 创建，既可以通过「Collision SOPs」参数，也可以把 SOP 放在 Actor COMP 内部。「Collision SOPs」参数填有内容时，Actor COMP 会将给定路径上的所有 SOP 合并创建一个刚体（若路径是一个 COMP，则会递归抓取该 COMP 内的所有 SOP）。若「Collision SOPs」参数为空，Actor COMP 会转而递归搜索自身内部所有同时打开 display 和 render 标记的 SOP。Actor COMP 会由这些 SOP 创建一个刚体及对应的碰撞形状。

由 SOP 创建碰撞形状时有几种选项，可在「Collision Shape」参数中选择。例如「Oriented Bounding Box」选项会在所选 SOP 周围创建最小体积的包围盒。

要创建多个刚体，可使用 Actor COMP 的「Instance」页上的实例化功能。这样会创建任意数量的相同刚体，每个刚体都有自己的相同碰撞形状。目前无法在单个 Actor COMP 中创建多个不相同的刚体。

刚体通过「Initialize Actor」参数初始化，因此若创建刚体的 SOP 有任何更改，必须重新初始化 Actor COMP。若 Kinematic State、Shape 或 Center of Mass 发生变化，刚体会自动重新初始化。

可以使用 Xform 和 Pre-Xform 页对 Actor COMP 应用变换，就像在 Geometry COMP 或 Camera COMP 上一样。Xform 和 Pre-Xform 页上的变换会创建 actor 在模拟中的初始变换，但也可以在模拟过程中修改 actor 的变换。在任一页上更改 scale 都需要重新初始化 actor，因为它会改变碰撞形状本身。实例化时修改任何变换都会自动重新初始化 actor。

Actor COMP 不能相互嵌套；但 Actor COMP 可以嵌套在 Geometry COMP 内，反之亦然。包含嵌套 Actor COMP 的 Geometry COMP 不能有任何 scale 变换；而嵌套在 Actor COMP 内的 Geometry COMP 可以有 scale。嵌套在 Geometry COMP 内的 Actor COMP 只在其初始化时使用这些 Geometry COMP 的变换。因此，这些 Geometry COMP 的变换有任何更改，都需要重新初始化该 Actor COMP。

Flex 中的 Actor

Flex actor 可以是流体粒子、流体粒子发射器或静态形状。

Flex 中的静态形状构建方式与 Bullet 中的凹形（即静态）形状相同。静态形状需要一个 triangle mesh SOP 来构建其碰撞形状。不过，也可以使用 box／sphere 碰撞形状选项来为碰撞形状 SOP 创建包围盒／包围球。

流体粒子的行为与 Bullet actor 上的实例化非常相似。流体粒子的数量等于由 instance OP 创建的实例数量。instance 参数用于给粒子一个初始变换，但一旦模拟开始运行，变换就由模拟结果更新。

流体粒子 Actor COMP 的一个关键区别是：不需要任何 SOP 来创建流体粒子，因为其大小／行为由 Nvidia Flex Solver COMP 上的模拟参数定义。Actor COMP 中的 SOP 可用于渲染／显示粒子的位置。或者，也可以使用 Nvidia Flex TOP 获取粒子位置。

流体发射器在发射点（即 Actor COMP 的变换位置）向场景添加粒子。粒子会持续添加直到达到最大发射量，此后发射的粒子将从已有粒子中回收。

使用 Actor COMP

创建 Actor COMP 时，有几个重要问题需要考虑：

  • Will this Actor be in a Bullet or Flex simulation? Bullet actor 与 Flex actor 有许多共同点，但功能上确实不同，这意味着并非所有参数都通用。Bullet 专用参数请参见 Actor COMP 的 Bullet 页，Flex 专用参数请参见 Actor COMP 的 Flex 页。
  • Will the bodies move? 运动刚体的 Kinematic State 必须为 dynamic。静态刚体可以通过覆盖其位置来「移动」，但不建议这样做，因为很容易发生穿插，且碰撞会不正确（因为刚体没有动量）。
  • What SOPs will be used to create the collision shape? 每个 Actor COMP 都有由 SOP 创建的对应碰撞形状。SOP 可以通过 Collision SOPs 参数设置；若该参数未设置，则通过 Actor COMP 内 SOP 的 display／render 标记来确定。
  • What collision shape will be used? 上一步收集的 SOP 用于创建碰撞形状。每种碰撞形状各有优缺点，详见 Bullet Dynamics 页。碰撞形状决定了刚体将如何与其他刚体交互（即碰撞）。碰撞形状不一定与显示／渲染的内容一致。可以使用 Display Collision Shape 开关显示碰撞形状。
  • Will the collision shape be concave? 若碰撞形状是凹形且为静态，只需从下拉菜单中选择 Concave。若要凹形且为动态，则多一步：凸分解。碰撞形状必须是 Compound 碰撞形状（即一组凸碰撞形状），其中复合形状的每一部分都是凸的，但组合在一起形成凹形。复合形状的每个部分用一个 SOP 表示。以字母「T」为例。「T」是凹的，因此需要拆分为两个独立的凸部分：上面一横和下面一竖。需要为碰撞形状创建 2 个 SOP（每条线一个），组合起来构成完整的凹形「T」。但若「T」是静态的，则可以保持为 1 个 SOP。

为什么我的刚体不碰撞？

要理解两个刚体为何可能不碰撞，重要的是理解 Bullet 是离散模拟的。速度、位置、约束、碰撞都是逐帧计算的，而不是连续计算。就 Bullet 而言，碰撞在每帧的开头和结尾计算。这意味着，如果一个刚体每帧移动的距离很大，就可能穿过其他刚体，因为在计算碰撞的帧首或帧尾时它并没有与对方相碰。同理，如果物体非常薄，其他刚体就比面对更有厚度的物体更容易穿过它，因为在单帧内无需移动太远就能完全跳过它。

连续碰撞检测（见参数）通过在运动矢量上（帧首到帧尾之间）执行碰撞检测来帮助解决这个问题，从而能捕捉到发生在帧首／帧尾之间的碰撞。这对高线速度刚体帮助很大，但对高角速度刚体帮助不大。

要解决刚体「漏出」问题，还可以考虑调整以下几项：

  1. 手动限制刚体的速度，或降低所施加的力的大小。
  2. 为非常薄的碰撞面增加厚度。如果你用 Grid SOP 作为碰撞面，考虑改用 Box SOP。或者，如果你用 Box SOP 作为容纳其他刚体的碰撞形状，考虑将碰撞形状改为由 6 个独立的 Box SOP（盒子的每一面一个）组合而成。

参数 - General 页

Initialize Actor initialize - 重新创建 Actor COMP 中所有刚体的碰撞形状。同时将所有速度和位置重置为默认状态。当用于创建碰撞形状的 SOP 发生任何更改，或 instancing OP 发生任何更改时，应脉冲 Initialize Actor。
Update Collision Shape updatecs - 启用后，Actor COMP 会自动更新碰撞形状。当「Collision SOPs」或「Collision Shape」参数发生变化，或用于创建碰撞形状的底层 SOP 发生变化（即其计算次数增加）时，就会执行更新。
Update Collision Shape updatecspulse - 点击后会立即更新碰撞形状。
Active active - 开启／关闭该 actor。若 actor 处于活动状态，它会随模拟推进而更新。若处于非活动状态，则会从模拟中移除，不再与其他任何 actor／刚体碰撞。因此，它的变换也不再更新。
Kinematic State kinstate - 运动学状态定义 Actor COMP 受外力移动的能力。若物体为 dynamic，则在模拟中可移动；若为 static，则不可移动。
  • Static (Infinite Mass) static - 此 COMP 中的刚体无法在模拟中移动。
  • Dynamic (Finite Mass) dynamic - 此 COMP 中的刚体可以移动。
Collision SOPs sops - 指定用于碰撞形状的 SOP 或 COMP。若引用的是 SOP，则仅使用该 SOP 作为碰撞形状。若选择的是 COMP，则该 COMP 内的所有 SOP（递归）都会用于碰撞形状。若此参数留空，则所选 SOP 为 Actor COMP 内所有打开 display 和 render 标记的 SOP。
Collision Shape shape - 由所选 SOP 生成的碰撞形状类型。可以在 Actor COMP 的查看器中通过辅助线查看碰撞形状
  • Concave (Static only) concave - 由所有 SOP 创建凹形碰撞形状。只应用于静态 Actor COMP。用于创建凹形碰撞形状的 SOP 应只包含 3 或 4 个顶点的多边形。若为动态 Actor COMP 选择此模式，则会改为创建复合形状。
  • Convex Hull convex - 由所有 SOP 创建凸包。凸包是一组点，它包围所有其他点（此处即 SOP 的点），由这些点构成的形状是凸的。凸包的点将是原始点集（即来自 SOP 的点）中的点
  • Oriented Bounding Box obb - 在 SOP 周围创建一个经过定向以最小化体积的包围盒。
  • Axis-Aligned Bounding Box aabb - 在 SOP 周围创建一个轴与 XYZ 对齐（即不旋转）的包围盒。
  • Bounding Ellipsoid bellipsoid - 在 SOP 周围创建最小体积的包围椭球。
  • Bounding Sphere bsphere - 在 SOP 周围创建最小体积的包围球。它与包围椭球的不同之处在于所有半径相同（XYZ）。
  • Compound compound - 复合碰撞形状是由其他碰撞形状组成的碰撞形状。若 Actor COMP 为静态，则结果与凹形相同。若 Actor COMP 为动态，则每个 SOP 都会创建为各自的凸包，随后再全部合并为一个复合碰撞形状。此模式允许你用多个凸 SOP 为动态刚体创建凹形碰撞形状。
Ellipsoid Tolerance elltol - 最小体积包围椭球的容差。换言之，即它与最优解的接近程度。
Infinite Mass infinitemass - 赋予 actor 无限质量。若物体为 dynamic，这会使其无法移动，变为 static。与更改 Kinematic State 参数不同，开关 infinite mass 不需要重建碰撞形状。
Mass mass - actor 的质量，单位为千克。
Cue Velocity cuevel - 保持 linvel 和 angvel 所给定的线速度与角速度值。物体仍会与模拟中的其他刚体碰撞。
Cue Pulse cuevelpulse - 脉冲，将线速度和角速度设为 linvel 和 angvel 给定的值。这会在下一帧开始时将速度设为给定值。
Linear Velocity linvel - actor 的初始线速度，单位为 m/s。此参数也可用于在模拟过程中修改 actor 的线速度。此外，它与「Cue Velocity」和「Cue Velocity Pulse」参数配合使用。

Angular Velocity angvel - actor 的初始角速度，单位为度每秒，m/s。此参数也可用于在模拟过程中修改 actor 的角速度。此外，它与「Cue Velocity」和「Cue Velocity Pulse」参数配合使用。

Continuous Collision Detection ccd - 为该 actor 开启／关闭连续碰撞检测。通常碰撞检测是离散进行的，即在帧首／帧尾验证碰撞。但若刚体运动太快，在单帧内移动过远，就会穿过任何表面（即检测不到碰撞）。连续碰撞检测通过在刚体帧内的初始位置与最终位置之间按间隔执行碰撞检测来改善这一点。连续碰撞检测会影响性能，因此即使该参数已开启，也不会一直使用。它只用于速度超过阈值的刚体。
Display Guide dispguide - 开启在 COMP 查看器中显示碰撞形状。

实例纹理化

此功能允许将任意纹理应用到实例。这些纹理不需要具有相同的分辨率，也不需要合并为 3D Texture 或 2D Texture array 之类的分组格式。可以使用「Instance Textures」参数指定多个 TOP，而每个实例所应用的纹理由「Texture Index」参数中选择的通道指定。这与 3D Texture 或 2D Texture Array 不同，后者会使用 W 纹理坐标在单个纹理内选择纹理。默认情况下，此纹理会用作 PBR MAT 的「Base Color Map」纹理，以及所有其他材质（如 Phong MAT）的 Color Map。对于支持多个贴图的材质，可以在此材质的参数中选择本功能所替换的贴图。目前在 Windows 上最多可同时使用 16384 个纹理，在 macOS 上最多可同时使用 128 个纹理。这些数量还会因渲染所用的其他纹理（如其他贴图、cone light 查找贴图等）而减少。

Enable External .tox enableexternaltox - 开启时（默认），.toe 启动时会加载外部 .tox 文件，COMP 的内容将与该外部 .tox 一致。如有需要，可以关闭此项，以避免启动时从引用的外部 .tox 加载（COMP 的内容改为从 .toe 文件加载）。如果你希望某个 COMP 引用外部 .tox，但不总是从它加载，除非你特意按下 Re-Init Network 参数按钮，这会很有用。
Enable External .tox Pulse enableexternaltoxpulse - 此按钮会从外部 .tox 文件重新加载（若存在）。
External .tox Path externaltox - 磁盘上 .tox 文件的路径，该文件会在 .toe 启动时作为组件内容的来源。这让组件可以包含能独立更新的网络。若找不到 .tox 文件，则会加载 .toe 文件保存时的内容。
Reload Custom Parameters reloadcustom - 启用此复选框后，重新加载 .tox 时会重新加载组件 Custom Parameters 的值。这仅影响组件上的顶层参数；组件内节点上的所有参数始终随 .tox 重新加载。
Reload Built-In Parameters reloadbuiltin - 启用此复选框后，重新加载 .tox 时会重新加载组件内置参数的值。这仅影响组件上的顶层参数；组件内节点上的所有参数始终随 .tox 重新加载。
Save Backup of External savebackup - 启用此复选框后，由 External .tox 参数指定的组件的备份副本会保存在 .toe 文件中。若找不到 External .tox，将使用此备份副本。出现这种情况可能是因为 .tox 被重命名、删除，或 .toe 文件在另一台缺少组件媒体的电脑上运行。
Sub-Component to Load subcompname - 从外部 .tox 文件加载时，此选项允许你深入 .tox 取出一个 COMP，并将其作为顶层 COMP，忽略文件中的其他所有内容（该 COMP 的内容除外）。例如，若名为 project1.tox 的 .tox 文件包含 project1/geo1，将 geo1 设为 Sub-Component to Load，就会加载 geo1 来替代当前 COMP。若此参数为空，则按常规使用文件中的顶层 COMP 加载 .tox 文件。
Relative File Path Behavior relpath - - 设置此 COMP 内的子文件路径是相对于 .toe 本身还是 .tox，或从父级继承。
  • Use Parent's Behavior inherit - 从父级继承设置。
  • Relative to Project File (.toe) project - 当指定为相对路径时，该路径将相对于 .toe 文件。
  • Relative to External COMP File (.tox) externaltox - 当指定为相对路径时，该路径将相对于 .tox 文件。未指定外部 COMP 文件，或 Enable External .tox 未开启时，此项没有影响。
Parameter Color Space parmcolorspace - - 控制如何解释此节点上的所有颜色参数。仅在项目启用了 Working Color Space 时可用。颜色值被视为处于所选色彩空间中，并在作为节点运算的一部分使用之前转换为 Working Color Space。注意这不会改变节点自身的色彩空间，因为它始终处于 Working Color Space。
  • sRGB srgb - sRGB 色彩空间，使用 sRGB 传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • sRGB - Linear srgblinear - sRGB 色彩空间，使用线性传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.601 (NTSC) rec601ntsc - Rec.601，NTSC 原色色彩空间，使用 Rec.601 传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.709 rec709 - Rec.709 色彩空间，使用 Rec.709（与 Rec.2020 相同）传递函数。相对于 Reference White 而言视为 SDR 色彩空间。
  • Rec.2020 rec2020 - Rec.2020 色彩空间，使用 Rec.2020（与 Rec.709 相同）传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • DCI-P3 dcip3 - DCI-P3 色彩空间，D65 白点，2.6 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • DCI-P3 (D60) dcip3d60 - DCI-P3 "D60 sim" 色彩空间，D60 白点，2.6 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Display-P3 (D65) displayp3d65 - Display-P3 色彩空间，D65 白点，sRGB gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • ACES2065-1 aces2065-1 - ACES 2065-1（也称为 ACES AP0）色彩空间，线性 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • ACEScg acescg - ACEScg（也称为 ACES AP1）色彩空间，线性 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Passthrough passthrough - 选中后，颜色值将按原样用于运算，不作任何修改，也不尝试将其转换到 Working Color Space。
Parameter Reference White parmreferencewhite - - 在将参数颜色值转换为 Working Color Space 时，此项控制相对于 Reference White 应如何处理。如果 Working Color Space 的 Reference White 相同，则不做调整。如果不同，则此颜色的 Reference White 级别（亮度）将被调整到 Working Color Space 所期望的范围。例如，如果项目将 SDR Reference White 设为 120 nits，而 HDR Reference White 为 80 nits，那么 (1, 1, 1) 的颜色在 SDR 色彩空间中为 120 nits，将被转换为 (1.5, 1.5, 1.5)，在 HDR Working Color Space 中仍为 120 nits。
  • Default For Color Space default - 将根据所选的色彩空间使用 SDR 或 HDR Reference White。
  • Use Parent Panel useparent - 将使用父级面板所选的 Reference White。如果顶层面板也选择了「Use Parent」，则将使用「UI Reference White」。
  • Standard (SDR) sdr - 会将 Parameter Color Space 的 Reference White 值按 SDR 处理。
  • High (HDR) hdr - 会将 Parameter Color Space 的 Reference White 值按 HDR 处理。
  • UI ui - 会将 Parameter Color Space 的 Reference White 值按 UI 处理。其亮度使用「UI Reference White Nits」的值。

Info CHOP 通道

Actor COMP 的额外信息可通过 Info CHOP 访问。

Actor COMP 专用信息通道

  • num_bodies -
  • num_active_bodies -

COMP 通用信息通道

  • num_children - 此组件中的子级数量。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
