WebRTC

什么是 WebRTC

WebRTC（Web 实时通信）是 Web 上点对点通信的开放标准。它支持在对等端之间发送低延迟的视频、音频和通用数据。WebRTC 得到所有现代浏览器的支持，因此提供了一种从 TouchDesigner 向网页浏览器流式传输视频/音频/数据的机制。

延伸阅读：MDN docs。

TouchDesigner 中的 WebRTC

TouchDesigner 中的 WebRTC 通过WebRTC DAT提供支持。WebRTC DAT 代表任意数量的 WebRTC 点对点连接一端的对等端。WebRTC DAT 的方法以 Python 为主，遵循WebRTC JavaScript library以回调为中心的特性。方法/回调名尽可能贴近其 JavaScript 对应名。

WebRTC 的视频和音频输入/输出通过Video Stream In TOP、Video Stream Out TOP、Audio Stream In CHOP和Audio Stream Out CHOP完成，并引用WebRTC DAT。

参见WebrtcDAT_Class。

对于希望测试、审阅或演示该技术的用户，TouchDesigner 2022.21000+ 在Palette的 WebRTC 文件夹中提供了Palette:signalingServer、Palette:signalingClient和Palette:webRTC COMP。

要快速跑起来，请启动两个 TouchDesigner 进程。在一个进程中添加 signalingServer、signalingClient 和 webRTC COMP。在另一个进程中添加 signalingClient 和 webRTC COMP。访问各自链接的帮助文章，了解需要填写或调整哪些参数。

建议进阶用户访问 signalingServer、signalingClient 和 webRTC COMP 的扩展页面。

调色板中包含Palette:webRTCPanel和Palette:webRTCPanelRcv。这些组件可让你通过 WebRTC 会话快速共享远程面板。快速搭建的细节见Palette:webRTCPanel页面。

webRTCPanelRcv 组件还有in the following repository提供的网页版，以及一个按this link的在线演示。

信令

要通过 WebRTC 建立点对点连接，必须通过双方商定的信令服务器完成协商过程。没有信令服务器就无法建立 WebRTC 连接。

信令服务器必须在正在连接的对等端之间转发消息（即 offer、answer、candidate），以便它们完成协商过程。信令服务器的协议与设计不在 WebRTC 的规定之内，完全开放。

例如，TouchDesigner 的示例信令服务器（Palette:signalingServer）使用 WebSockets。可以使用Palette:signalingClient配合Palette:webRTC COMP 连接到该信令服务器。

SDP

SDP（会话描述协议）是 WebRTC 中用于描述点对点连接一端的协议。它包含对等端在连接中能支持的各种信息，包括：音频信息、视频信息、数据通道信息、编解码器、源地址、候选地址等。

SDP 通过信令服务器交换。

在 TouchDesigner 中，本地 SDP 会在分别调用createOffer和createAnswer之后，通过onOffer和onAnswer回调传出。必须使用setLocalDescription在WebRTC DAT上本地设置它，然后传给信令服务器。收到对应的远端 SDP 后，应使用setRemoteDescription设置。

延伸阅读：Anatomy of a WebRTC SDP。

ICE

ICE（交互式连接建立）是用于在网络中连接两个对等端的协议。网络连接过程中的一个重要部分是ICE candidates，它们本质上是远端对等端可以到达本地对等端的连接点。它们通常与某个媒体流（音频或视频）相关联。

ICE 候选地址的收集过程通常在创建 offer 或 answer 之后执行。候选地址会传给WebRTC DAT上的 onIceCandidate 回调，随后应发送到信令服务器。从信令服务器收到远端 ICE 候选地址时，可用addIceCandidate方法添加。

ICE 候选地址可以是本地生成的、STUN（NAT 会话穿越工具）或 TURN（使用中继穿越 NAT）。

STUN：STUN servers会为对等端生成 ICE 候选地址。有许多免费的公共 STUN 服务器，默认情况下WebRTC DAT使用 stun:stun.l.google.com:19302。在某些配置下，用 STUN 服务器生成的候选地址可能无法完成 NAT 穿越（例如因为防火墙），连接会失败。这种情况下就需要 TURN 服务器。

TURN：TURN servers在对等端之间充当中继，当对等端无法直接用 STUN 连接时会很有用（例如 NAT 穿越失败，或可能因为网络歧义）。免费 TURN 服务器不太可能存在，因为它们还必须在对等端之间中继媒体流量。可在WebRTC DAT的 ICE 页指定自定义 TURN 服务器 URL。

用于测试本机 ICE 候选地址收集的示例：https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/
