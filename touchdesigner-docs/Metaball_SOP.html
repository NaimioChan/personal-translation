Metaball SOP

摘要

Metaball SOP 创建元球和超二次曲面。元球可以看作球形的力场，其表面是一个隐函数，定义在力场密度等于某个阈值的任意点上。由于其他元球力场的靠近会提高力场密度，元球具有独特性质：会改变自身形状，与周围的元球适应并融合。这使它们非常适合为有机表面建模。例如，下面是一个元球。只要元球场密度达到某个阈值，元球的表面就存在：

当两个或更多元球力场组合时（如下图），力场的合成密度会相加，表面会延伸到这些力场相交并产生密度值为 1 的区域。有关元球的更多信息，请参阅 Metaballs。

元球显示的细节级别

可以通过调整 Display Option Dialog > Viewport 页 > Level of Detail 选项中的 Level of Detail 参数，改变元球和 NURBS 显示的细节级别。要打开 Display Options Dialog，请在 SOP 视口中按「p」。

改善元球着色的提示

转换为多边形时如果存在 normal 属性，就会计算出准确的元球法线。因此，为了改善多边形化元球的着色，最好在转换元球之前添加 normal 属性（即使用 Facet SOP）。

什么是指数？

在元球的情形中，指数决定向「方形」膨胀或向「星形」收缩，如下所述：

  • 值 > 1 - 使元球看起来更像「星形」。
  • 值 < 1 - 使元球看起来更「方」。
  • 值 = 1 - 使元球呈球形。

Info CHOP 通道

Metaball SOP 的额外信息可以通过 Info CHOP 访问。

SOP 通用信息通道

  • num_points - 此 SOP 中的点数。
  • num_prims - 此 SOP 中的图元数。
  • num_particles - 此 SOP 中的粒子数。
  • last_vbo_update_time - 在另一个线程中根据 SOP 的 CPU 数据更新 GPU 上的几何数据所花的时间。由于它属于另一个线程，此时间不计入通常的帧时间。
  • last_meta_vbo_update_time - 在另一个线程中根据 SOP 的 CPU 数据更新 GPU 上的元表面几何数据（如 metaball 或 nurbs）所花的时间。由于它属于另一个线程，此时间不计入通常的帧时间。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
