使用多显卡

概述

在某些情况下，根据你的具体情况，在计算机中安装多块显卡可能带来好处。最常见的情况是增加对更多显示器的支持，不过你需要在系统中进行非常特定的设置才能获得最佳性能。

另请参阅 Multiple Monitors、Sync In CHOP

多 GPU Mosaic 与 EyeFinity

Multi-GPU Mosaic（Nvidia Quadro 显卡）和 EyeFinity（AMD 显卡）将多个 GPU 绑定在一起，以驱动大量输出。使用这种方式，你可以输出到更多显示器，而在 Windows 看来，这些显示器就像是连接在单个虚拟 GPU 上的单个大显示器。这通过桥接电缆完成，例如 SLI、NVLink 或 Crossfire 电缆，将 GPU 桥接在一起。在 Nvidia 上，此模式以前称为 'SLI Mosaic'，现在称为 'Premium Mosaic'。

虽然此模式下使用了多个 GPU，但额外的 GPU 并不会提升系统性能。事实上，使用此模式的实际性能会比在单个 GPU 上使用相同尺寸的输出画布更差。这是因为每个 GPU 都在重复相同的工作，只是显示其输出所需的那部分最终画面。同步这些重复工作的开销是单 GPU 配置所没有的额外成本。不过在某些情况下它很有用：当你需要的像素多于单个 GPU 所能输出的像素，但又不想处理多 GPU/多进程同步问题时。

如果你想输出的像素数量可以用单个 GPU 的 4-6 个输出来完成，那么可以使用 DataPath 分离器之类的分离设备配合单个 GPU，而不是多个 GPU。这样性能会优于使用多个 GPU。

Nvidia 相关细节

虽然 Multi-GPU Mosaic 使用与 SLI 相同的桥接电缆，但它是 GPU 的不同模式。常规 SLI 是连接多块显卡以获得更好的渲染性能，但它在额外的 GPU 上显示输出。Multi-GPU Mosaic 旨在将多块显卡的所有输出组合成单个虚拟桌面，由单个虚拟 GPU 驱动。

考虑使用「Nvidia Mosaic Utility」（在其网站上搜索最新版本），以更轻松地设置 Mosaic 输出。

请注意，SLI 连接器（也称为 Quadro Link）在最新的 GPU 中已被移除，通信仅通过 PCIe 总线进行。

GPU 亲和性

从 TouchDesigner 2022.20000 系列开始，所有 GPU 型号都支持 GPU Affinity。

GPU 亲和性将单个 TouchDesigner 实例（一个进程）绑定到单个 GPU。系统中有多块 GPU 时，你可以运行多个 TouchDesigner 实例，每个绑定到唯一的 GPU。这避免了任何 GPU 之间的通信，并让多块 GPU 投入工作。一个进程可以使用其 2 个输出向投影仪发送数据，同时第二个 GPU 连接到你用于运行第二个 TouchDesigner 进程的显示器，该进程控制演出（通过各种网络 OP 向第一个实例发送命令和数据流）。

使用 GPU 亲和性时，请确保绑定到特定 GPU 的 TouchDesigner 进程的窗口不会重叠到其他 GPU 的桌面空间上。如果窗口显示在错误的 GPU 上，会导致数据在 GPU 之间复制，而这正是我们使用 GPU 亲和性想要避免的。在创建和编辑文件时这可以接受，但在演出播放期间，你应只将窗口放在与该进程绑定的 GPU 所连接的显示器上。

亲和性用法

GPU 亲和性的用法是将单个 TouchDesigner 实例绑定到单个 GPU。启动 TouchDesigner 时，需要在命令行中指定要使用的 GPU。这可以通过 -gpuformonitor <monitorIndex> 或 -gpubusid <domain:bus:device:function> 完成。

-gpuformonitor 选项将进程绑定到连接到指定显示器的 GPU。显示器的索引方式与 Monitors DAT 中相同，即从左到右、从下到上。这与操作系统可能赋予你显示器的索引不一致。你可以指定连接到想绑定的特定 GPU 的任何显示器。例如，如果你只想运行两个 TouchDesigner 实例，分别在第一块和第二块显卡上运行，且每块 GPU 只连接了 1 个显示器，你会用这样的 .bat 文件启动它们： 

 set APPPATH=C:\Program Files\Derivative\TouchDesigner\bin
 start "%APPPATH%" "%APPPATH%\TouchDesigner" -gpuformonitor 0 C:/Projects/Playback.toe
 start "%APPPATH%" "%APPPATH%\TouchDesigner" -gpuformonitor 1 C:/Projects/Control.toe

或者，可以使用 -gpubusid 选项直接引用 GPU。Bus ID 的值也在 Monitors DAT 中提供，位于 gpu_bus_id 列，这是表格中最后几列之一。此选项在机器之间可移植性较差，因为 Bus ID 的值在不同机器之间可能不同。示例如下： 

 set APPPATH=C:\Program Files\Derivative\TouchDesigner\bin
 start "%APPPATH%" "%APPPATH%\TouchDesigner" -gpubusid 0:1:0:0 C:/Projects/Playback.toe
 start "%APPPATH%" "%APPPATH%\TouchDesigner" -gpubusid 0:1:1:0 C:/Projects/Control.toe

要查看绑定是否按预期工作，使用 Monitors DAT 并查看 'affinity' 列。

SLI 与 Crossfire

SLI（Nvidia）和 Crossfire（AMD）是一项将两块显卡连接在一起成为一块虚拟显卡的功能。此时只有一块显卡可以连接到显示器，另一块显卡仅用于提供额外的处理能力。其思路是将工作分摊到两块显卡之间。

使用此功能要求驱动程序能很好地预判每一帧将发生什么，以便它知道如何调度工作。这对视频游戏效果不错，因为它们每帧执行相同的渲染通道（例如 shader、main、post-process）。因此每个游戏都在驱动中有针对其特定使用模式的内置配置文件。这对 TouchDesigner 效果不佳，因为每个 .toe 都有不同的使用模式。因此，驱动中并没有为 TouchDesigner 提供 SLI/Crossfire 配置文件。我们尚未做大量测试来判断使用 SLI 配置对 TouchDesigner 是否有任何好处。如果你想尝试，我们建议使用 SLI 的 Alternate Frame Rendering 方法，而不是 Split Frame Rendering 方法。要看到任何速度提升，你首先需要确保你的项目是 GPU 瓶颈。有关确定瓶颈的更多信息，请参阅 Optimize 文章。

多 GPU 直接使用

在没有 GPU 亲和性/SLI Mosaic 的情况下，进程的所有工作都会发送到系统向 TouchDesigner 列出的第一块 GPU，只有最终图像会被传输到其他 GPU 上显示。如果系统同时有独立显卡和集成显卡，则会选择独立显卡而不是集成显卡，即使集成显卡列在前面。这类似于 Multi-GPU Mosaic/EyeFinity，但驱动的设置模式不够理想。这种工作方式会对项目产生很大的性能影响，不推荐使用，但在某些情况下可能合适（如果性能满足要求）。
