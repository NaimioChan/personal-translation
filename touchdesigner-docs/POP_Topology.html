POP 拓扑

POP 拓扑（Topology）是构成 POP 的各几何实体之间的关系，涉及 POP 的 Primitives、每个图元的 Vertex / Vertices，以及顶点所引用的 Points 列表。

对于某些 POP 操作：

  • 结果点数只有在 GPU 上才知道。结果 POP 的信息弹窗中会显示「Point Count Info on GPU」而不是「Point Count Info on CPU」（例如 Facet POP：Cusp 和 Consolidate 操作……）
  • 结果顶点数和图元数（Topology Info）只有在 GPU 上才知道。结果 POP 的信息弹窗中会显示「Topology Info on GPU」而不是「Topology Info on CPU」（例如 Convert POP：打开或关闭线段条）
  • 点数和拓扑信息都只有在 GPU 上才知道。这种情况下，结果 POP 的信息弹窗中会显示「Point Count Info on GPU」和「Topology Info on GPU」（例如 Delete POP）


对于这些 POP 的点或拓扑，分配的内存是该 POP 可能使用的最大内存。从 GPU 下载这些 POP 的实际点数与拓扑信息（图元数和顶点数）会导致停顿。

对于下游 POP 的计算着色器，点数信息和拓扑信息通过缓冲传递，以避免停顿和不必要的工作：这称为计算着色器的间接调度。这些调度需要填充额外的命令缓冲，因此比常规调度开销稍大。


中键点击的信息弹窗会执行下载，并显示实际使用量与分配量。


某些 OP（POP to DAT、POP to SOP、POP to CHOP）以及 Python 函数支持「下一帧」异步下载，可避免停顿，但会引入 1 帧延迟。某些 POP 上的「Copy topology back to CPU」参数会把 POP 变回常规 POP，只在下游重新分配所需内存。Convert POP 上也有此模式。

Topology POP 可让你为信息在 GPU 上的 POP 手动分配内存，从而无停顿地回收部分未用内存；或者在已知点数与拓扑信息时，手动在 CPU 上设置它们，使 POP 无停顿地变回「常规」POP。

Feedback POP 有一个开关，可把分配内存限制为输入内存的倍数，以防止在反馈循环内创建几何体时内存使用量暴增。这也可通过功能更多、控制更精细的 Topology POP 实现。
