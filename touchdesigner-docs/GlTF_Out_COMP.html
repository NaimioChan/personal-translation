GlTF Out COMP

摘要

glTF Out COMP 把网格、动画、Blend Shape、纹理和场景导出为 glTF 2.0 文件（.gltf 或 .glb）。不支持 glTF 1.0 文件。

glTF 主要有两种文件扩展名：

  • .gltf'：ASCII 格式的 JSON 结构，通常带有存放在磁盘上的外部纹理文件，以及用于缓冲数据的外部 .bin 文件。
  • .glb：将 JSON 场景结构、纹理和缓冲数据自包含在一个轻量的压缩文件中的二进制格式。

glTF (Graphics Library Transmission Format) 是由 Khronos Group 创建的开放标准 3D 文件格式。它旨在高效加载 3D 模型，有时被称为 3D 文件格式中的 JPEG。glTF 使用 JSON 格式描述场景及其结构，并通过访问器指向包含实际场景数据（如位置、属性等）的缓冲，其格式便于实现无缝的 GPU 拷贝。缓冲数据既可以内部存储（如 .glb 文件的情况），也可以外部存储在一个单独的 .bin 文件中。由于底层数据与场景结构分离，场景结构的 JSON 格式可以保持相当高的可读性。

导出

glTF Out COMP 可以导出其内部网络，也可以导出由其 Component Path 参数引用的网络。两种网络遍历模式 Automatic 和 Manual 决定了网络中哪些操作符会被导出到 glTF 文件。

在 Automatic 模式下，glTF COMP 会遍历网络，并导出所有启用了 render 标记的有效操作符。有效操作符包括：

  • 表示 glTF 节点的 Geometry COMP
  • 表示 glTF 摄像机的 Camera COMP
  • 表示蒙皮中关节所对应 glTF 节点的 Null COMP
  • 表示网格和网格图元的 POP（其中 Blend POP、Skin Deform POP 和 Null POP 作为特殊情况处理）
▸动画导出步骤演示

glTF Out COMP 支持从 glTF In COMP 以及一般网络导出动画（前提是它们的格式正确）。下面演示如何从加载了 samples 文件夹中提供的 Fox.gltf 示例文件的 glTF In COMP 导出多个动画。

设置 Component Reference

设置 Component Reference，右侧显示 glTF Out COMP 的参数。

把 glTF Out COMP 上的「Export Method」参数改为 Component Reference，并在 Component Path 中引用 gltfin1。

  • 当「Export Method」设为「Internal Network」时，glTF Out COMP 也可以导出内部节点。
  • 顶层组件不会被读取，只导出所引用组件内部的节点。

设置默认变换

设置默认变换：先把动画设为 None:animation，然后在 glTF Out COMP 的 Default Transforms CHOP 参数中引用该 Import Select CHOP。

把「Animation」参数改为 None:animation。任何带动画的 glTF 文件内部总是有包含节点默认变换的 None:animation。

  • 其中可以包含 Geometry 节点的 translate（tx ty tz）、rotate（rx ry rz）、scale（sx sy sz）以及 quaternion（qx qy qz qw）的默认值。

设置动画通道 CHOP

在 gltfin1 内部设置动画 CHOP

在 gltfin1 内部创建三份 Import Select CHOP animation 的副本。对这三个新 CHOP，关闭「Use Parent Animation」，把「Play Mode」设为 Output Full Range，然后各自选择一段动画，此处为 Survey、Walk 和 Run。 在 glTF Out COMP 的 Animation CHOP 参数中引用这些新 CHOP（名为 animation1、animation2、animation3）及其名称。

  • glTF Out COMP 可以一次导出多个动画，这就是需要创建三个单独 CHOP 的原因。
  • 由于 glTF Out COMP 进行无损导出，因此需要使用非 time-sliced 的 CHOP。
  • 动画可以有 keyframes 通道（用 glTF Out COMP 导入的会有），它决定哪些采样会被导出。如果没有 keyframes 通道，则所有采样都被视为关键帧。

设置 Geometry COMP / POP

为新建的动画 CHOP 在 Animation CHOP 参数中指定与之对应的名称。

导出 glTF In COMP 时，可以把 Mesh Parse Mode 设为 Automatic。它会自动遍历网络并确定要导出哪些节点/POP。它遵循以下规则：

  • 启用了 render 标记的 Geometry 节点会作为 glTF 节点导出。
  • 导出的 Geometry 节点可以带材质，且必须是 PBR MAT。
  • Geometry 节点内任何启用了 render 标记的 POP 都会导出为一个单独的网格，其图元类型作为单独的网格图元添加。
    • Skin Deform POP 会作为 Skeleton 导出。
    • Blend POP 会作为变形目标导出。
  • 任何启用了 render 标记的 Null POP 都会导出最左侧的非 Null POP（即一连串 Null 会导出该链起点之前的那个 POP）。

另请参阅：glTF、glTF In COMP

  • DCI-P3 dcip3 - DCI-P3 色彩空间，D65 白点，2.6 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • DCI-P3 (D60) dcip3d60 - DCI-P3 "D60 sim" 色彩空间，D60 白点，2.6 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Display-P3 (D65) displayp3d65 - Display-P3 色彩空间，D65 白点，sRGB gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • ACES2065-1 aces2065-1 - ACES 2065-1（也称为 ACES AP0）色彩空间，线性 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • ACEScg acescg - ACEScg（也称为 ACES AP1）色彩空间，线性 gamma 传递函数。相对于 Reference White 而言视为 HDR 色彩空间。
  • Passthrough passthrough - 选中后，颜色值将按原样用于运算，不作任何修改，也不尝试将其转换到 Working Color Space。
Parameter Reference White parmreferencewhite - - 在将参数颜色值转换为 Working Color Space 时，此项控制相对于 Reference White 应如何处理。如果 Working Color Space 的 Reference White 相同，则不做调整。如果不同，则此颜色的 Reference White 级别（亮度）将被调整到 Working Color Space 所期望的范围。例如，如果项目将 SDR Reference White 设为 120 nits，而 HDR Reference White 为 80 nits，那么 (1, 1, 1) 的颜色在 SDR 色彩空间中为 120 nits，将被转换为 (1.5, 1.5, 1.5)，在 HDR Working Color Space 中仍为 120 nits。
  • Default For Color Space default - 将根据所选的色彩空间使用 SDR 或 HDR Reference White。
  • Use Parent Panel useparent - 将使用父级面板所选的 Reference White。如果顶层面板也选择了「Use Parent」，则将使用「UI Reference White」。
  • Standard (SDR) sdr - 会将 Parameter Color Space 的 Reference White 值按 SDR 处理。
  • High (HDR) hdr - 会将 Parameter Color Space 的 Reference White 值按 HDR 处理。
  • UI ui - 会将 Parameter Color Space 的 Reference White 值按 UI 处理。其亮度使用「UI Reference White Nits」的值。
