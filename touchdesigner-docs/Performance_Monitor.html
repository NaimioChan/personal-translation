性能监视器

说明

Performance Monitor 对话框（Dialogs -> Performance Monitor）让你监视并诊断哪些操作符占用处理时间最多、各项操作以什么顺序执行，从而优化你的网络。可以通过以下几种方式做到：

  • Performance Dialog - 计算时间、计算次数、视口显示时间、用户界面计算时间等都可以记录在 Performance Monitor 对话框中。点击 Analyze 按钮可获取合成中当前状况的快照。
  • Each OP's Info Pop-up - 每个操作符的计算时间和计算次数可显示在该操作符的 Info 弹窗中。用鼠标中键点击任一操作符的图标（没有中键时用 Alt 加右键）。
  • 对 CPU 与 CPU 时间及内存使用情况更图形化的多帧分析，是 Palette 中的 probe。

另请参阅 Optimize。

绿色叠加条形图

每一行输出上的绿色条形图，直观表示处理该操作所花的时间。深灰色的剩余时间，是该行等待其他操作的时间（例如节点等待其输入节点计算）。条形在 X 方向的位置表示处理的先后顺序。例如在上图中可以看到，Lookup TOP 在能够计算之前，一直在等待一批其他 TOP 计算完成。

在 Performance Monitor 输出窗口中点击鼠标左键，可让统计图适配性能窗口。按住鼠标中键拖动可缩放统计图。

按住鼠标右键拖动可平移统计图。

使用 Performance Monitor 对话框

要打开 Performance Monitor，选择 Dialogs --> Performance Monitor...，或使用快捷键 Alt-y。

点击 Analyze 按钮来分析你的合成。事件信息上会叠有一个可视条形图，帮助识别每个事件的处理时间。要让图在窗口内归位，在输出窗口任意处点击左键。

设置与选项

Analyze

按 Analyze 按钮，会抓取若干帧的快照并输出事件时间。连续两帧之间的消息先被捕获到内存中，然后再报告，这样可以准确分析属于完整一帧动画的所有事件。用 Enable Output 持续输出流通常会拖慢你的合成，并影响所报时间的准确性。使用 Analyze 方法生成性能日志时会暂停输出，因此对 TouchDesigner 整体性能的干扰要小得多。

Frame Trigger (ms)

用 Frame Trigger 捕获在一段设定时间内发生的事件。它的一个有用用法是：如果你发现只有某些特定的帧似乎计算很久（TouchDesigner 在某些帧上像是卡住了），可以用 Frame Trigger 只列出处理时间长于 Frame Trigger 设定值的那些帧的计算时间。例如，在 TouchDesigner 正向播放时，在 Frame Trigger 中输入 100 然后点 Analyze。下一次某帧计算超过 100 毫秒时，performance monitor 就会报告一份被监视项的列表。最好按 Adjusted Length 排序，这样计算最久的一项会出现在列表底部。

Filter

filter 字段让你限定 performance monitor 输出中的特定项目。例如，Filter *CHOP* 会把输出限制为所有 CHOP。

Home

计算时间被记录后按此按钮。它会把计算时间条形图的可视化缩放到 Performance Monitor 窗口的大小。你也可以在输出窗口任意处点击左键让图归位。

Clear

清除显示窗口。

注意：如果不想丢失信息，请先保存。

Save...

把当前性能日志保存为文本（.txt）文件。点击 Save 会弹出 File Save 对话框，保存 Scrolling Text Field 的内容。

Close

关闭 Performance 对话框。只要 Enable 按钮仍处于勾选状态，性能监视就会继续进行。

性能日志信息

监视项

Monitor 窗口让你选择要监视哪些类型的性能事件，从而决定记录哪些信息。如果你想看到全部内容，就勾选所有复选框。以下选项让你控制记录的范围，必要时可缩小搜索范围：

  • OP Cook Time - 某个特定操作计算所花的时间。
  • OP Export Time - 导出一个通道所花的时间。
  • Long CHOPs - 报告长度超过 100 个采样的 CHOP。
  • Object Draw Time - 绘制一个对象所花的时间。
  • Custom Panel Time - 绘制控制面板所花的时间。
  • Port Draw Time - 绘制 3D 视口所花的时间。
  • Movie Library Time - 绘制 QuickTime Image/Movie 面板所花的时间。
  • Draw Channels Time - 绘制 CHOP 通道查看器所花的时间。
  • Midi Handling - 发送和接收 MIDI 所花的时间。
  • Graphics Driver Time - 花在对图形驱动发起调用（或等待图形驱动完成某些工作）上的时间。
  • Frame Time - 报告帧之间的时间和/或播放速率。
  • Errors - 记录来自操作符的错误消息。

列出/记录的信息

用这些信息来追踪哪些操作符占用的处理时间最多，并了解性能瓶颈在哪里。

  • Order - 操作符被计算的顺序。
  • OP Cook Time - 每项操作的计算时间，以及它调用的所有操作符的计算时间。
  • OP Cook Count - 每个操作符各有一个计数器，即该操作符被计算的次数。
  • Viewport Display Time - 次数（视口中每个 Object/SOP 各自的显示时间）。
  • Frame Length / Frequency - 计算整帧所花的时间。
  • Gadget Drawing - 绘制 gadget 面板所花的时间。
  • draw - 绘制一个对象所花的时间。
  • cook - 操作符计算所花的时间。
  • port - 视口或图表绘制所花的时间。
  • drawlist - 在显示列表中重新排序对象所花的时间。
  • custom - 绘制控制面板所花的时间。
  • midi - 检查 MIDI 事件所花的时间。
  • export - CHOP 通道导出到参数所花的时间。
  • tessellate - 几何细分为多边形所花的时间。

TIP: Watching networks cook is useful for understanding how to design networks in ways to minimize cooks. Always place animating operators (operators whose output wires are animating) near the leaves (ends) of the network to avoid unnecessary cooking by operators that are not changing. If an operator is changing every frame, the entire network after may also be cooking every frame.

理解结果

查看 SOP、DAT、CHOP 这类节点的计算时间时，所见即所得。你在 performance monitor 上看到的时间，就是它们执行所花的时间。减少它们的工作量（更少的点或更少的通道）会带来更小的计算时间。

COMP 的计算时间通常非常小，所以除了彻底避免计算之外，没有办法加快它们的计算。

TOP 的情况就比较棘手。大多数 TOP 的实际工作是在 GPU 上执行的，不会显示在 Performance Monitor 中。例外的是会从 GPU 上传或下载图像的 TOP，例如 Touch In、Movie File In、Touch Out、Movie Out 等。对大多数 TOP 而言，它们的计算时间只是 TOP 告诉 GPU 它想让它做什么工作所花的时间（例如告诉 GPU 对输入图像 X 和输入图像 Y 执行 Displace 操作）。TOP 早在 GPU 完成任务之前就结束计算了。这称为异步执行。目前无法确切得知 GPU 执行一项操作需要多少时间。因此 Performance Monitor 目前对优化 GPU 使用帮助不大。要优化 GPU 使用，请参阅 Optimize 一文。

读完 Cook 一文后，你可以进一步弄清某个节点「为什么」在计算：观察图表，注意哪些操作符的条形出现在其他操作符的条形之内。在一批条形相互嵌套的节点中，位于列表中较上面的节点是在请求较下面的节点计算。位于较下面的节点，就是它上方那个节点计算的原因。

理解结果不一致

在负载很重的系统上使用 Performance Monitor 时，可能会得到一些令人困惑的结果。本不该有昂贵计算的节点（例如 Null、In 和 Out 操作符）可能出现非常大的计算耗时。其他本不该有昂贵计算的节点是 TOP（上述会从 GPU 上传/下载数据的那些除外）。你还可能遇到某个节点在一帧里计算耗时很大，再分析一次却得到完全不同的数值，那次大耗时可能转移到了另一个毫不相关的节点上。

出现这种情况，通常意味着你的 CPU 超负荷了。可能发生的是：TouchDesigner 开始计算某个节点，但 CPU 转去执行了另一个完全不同的应用的代码。当 TouchDesigner 重新获得 CPU 并完成该节点的计算时，它无从知道自己（举例来说）在这 2 毫秒里实际只用了 0.1 毫秒来计算该节点。这常常就是本不该耗那么久的节点出现随机大耗时的原因。检查一下你的 CPU 使用率是否达到 100%（在 Windows 任务管理器中查看）。

TOP 计算时间长、或 Draw All TouchDesigner Windows 条目很长的另一个原因，是 GPU 超负荷。图形驱动可能会让 TouchDesigner 停顿，等待 GPU 赶上并完成交给它的所有工作。

Draw All TouchDesigner Windows

一个常见问题是「Draw All TouchDesigner Windows」条目是什么。该条目是 TouchDesigner 绘制 UI（面板和网络，不含几何等）所用的 CPU 时间。如上所述，如果 GPU 超负荷，这个条目可能会变得很长。
