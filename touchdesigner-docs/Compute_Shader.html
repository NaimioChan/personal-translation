计算着色器

概述

GPU 可以看作是拥有成千上万个非常轻量线程的处理器。这些线程通常用于处理顶点或像素。但 Compute Shader 让 GLSL 开发者能以更通用的方式利用这些线程，脱离把多边形渲染和光栅化为像素的概念。

典型的 GLSL 顶点/像素着色器程序会变换顶点（顶点着色器）、把它们光栅化为像素，并用像素着色器为这些像素着色。写入的像素数量由多边形覆盖的像素数决定。结果总是写入颜色缓冲和深度缓冲。像素着色器在每个渲染通道中只能写入输出颜色缓冲一次，无法读回相邻输出像素的结果并据此改变自己的值。它们也无法控制自己的结果被写入颜色缓冲的哪个位置。写入的输出像素位置是硬性固定的，取决于像素被渲染的位置。

Compute shader 不同，它们没有预定义的输入和输出集合来限制其作用范围。它们只是按指定的线程配置被运行，具体做什么完全取决于 GLSL 代码。每个线程都可以从纹理读取值、执行计算，并在任意位置写出值。在同一个着色器中，它们随后还可以读取其他线程写入的值，并对这些值做更多计算。

正确编写 compute shader 相对复杂。性能方面有许多注意事项，而这些注意事项非常依赖于硬件。关于如何编写 compute shader 的学习资料，请参考互联网上提供的众多教程。

注意：Compute Shader 需要 GLSL 4.30 或更高版本。

参见 GLSL TOP，其中有一个停靠的 compute shader 以及一个普通的 GLSL 着色器。把 Mode 改为 Compute Shader。
