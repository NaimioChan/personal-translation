Windows PowerShell 与 TouchDesigner

什么是 PowerShell

对于需要部署计算机集群（从私有网络到云端系统）的 TouchDesigner 工程师来说，PowerShell 是很有用的工具。本文介绍如何设置 PowerShell 和 Windows 安全策略，以简化对网络中运行的 TouchDesigner 应用的管理。

PowerShell 是一种跨平台的、基于任务的命令行 shell 和脚本语言，设计重点在于系统管理。它是直接内建于 Windows 的最现代的命令 shell，可以替代 Windows CMD shell，也可替代移植的 linux / unix 变体，如随 GIT 等提供的 MINGW64。该 shell 支持 Windows 命令和许多熟悉的 Unix 命令。它能很好地消除 Unix 与 Windows 在路径和字符串操作上的那些恼人差异。它与 Python 配合良好，并与 Python 有大量相似之处。它可轻松访问 WMI 和 .NET，并良好集成到 Windows 的 WSMAN 架构中，可直接访问驱动和其他系统检测接口，以及管理 Windows 安全的工具。这些因素以及其他因素使 PowerShell 成为部署 TouchDesigner 的有效工具。有关 PowerShell 的更多一般信息，从这里开始……

https://docs.microsoft.com/en-us/windows-server/administration/windows-commands/powershell

安全警告！！

本文不涉及如何使你的计算机免受来自 Internet 或其他恶意网络的入侵。Windows 和 Internet 安全是你组织的责任，本文的建议必须结合你自己网络环境的风险、策略和情况来评估。特别是，本文侧重于使用 CredSSP 和 RDP 作为远程控制运行 TouchDesigner 图形应用的 Windows 客户端的解决方案。某些网络管理员和网络环境不允许这些技术运行，因为它们提供了更多攻击途径，尤其是在云和与 Internet 相邻的网络中。这些危险是可以预见的，因为我们讨论的是在一组计算机集群上对 TouchDesigner 的全面控制。能力越大，责任越大。

用户账户设置检查清单

  • 所有计算机都应分配一个通用用户，在各系统上名称和密码一致。
  • 该用户账户必须具有管理员权限。

以管理员模式打开 PowerShell

点击 Windows 开始菜单并直接键入 "PowerShell" 搜索，即可打开 PowerShell。PowerShell 图标会出现在开始菜单中。你必须以管理员模式启动 PowerShell。为此，右键点击该图标，在弹出的菜单中选择 "Run as Administrator"。或者右键点击开始菜单并选择 "Windows Powershell (Admin)"。以管理员模式启动 PowerShell 时，可能会弹出 Windows 对话框通知，点击 Yes 即可。打开后，PowerShell 应用窗口的标题会显示 "Administrator: Windows PowerShell"。

激活 Windows 远程管理服务（WinRM）

你必须确保 Windows 远程管理（WinRM）服务正在运行，并且在重启 Windows 后会自动启动。PowerShell 提供了一条简单命令来完成此过程。

  • 验证你的用户名和计算机名，确保你在 shell 中以正确的用户身份、在正确的计算机上操作。这里返回的用户名就是你在 PowerShell 中应使用的用户名。它可能与 Windows 登录界面显示的用户名不同，后者例如可能是电子邮件地址。
$env:UserName
$env:ComputerName
  • 运行 WinRM 快速配置命令，以设置远程服务和常规远程配置……

winrm quickconfig

  • 如果一切已正确设置，你会看到这个……
WinRM service is already running on this machine.
WinRM is already set up for remote management on this computer.
  • 如果尚未设置，你会依次经过这些问题……
WinRM is not set up to receive requests on this machine.
The following changes must be made:
Start the WinRM service.
Set the WinRM service type to delayed auto start.
  • 对此项以及后续每一项要求都输入 "y"。它会设置一些权限规则和一个防火墙例外。
  • 运行以下 PowerShell 命令设置防火墙，以便主机之间顺畅通信。
netsh advfirewall firewall add rule name="Enable Echo Ping Request" protocol="icmpv4:8,any" dir=in action=allow
netsh advfirewall firewall set rule group="File and Printer Sharing" new enable=Yes
  • 设置受信任主机，信任所有计算机名。# Trust all hosts
Set-Item WSMan:localhost\client\trustedhosts -value *
  • 验证受信任主机配置
Get-Item WSMan:\localhost\Client\TrustedHosts
  • 对网络中每台要远程控制的计算机重复这些步骤。
  • 再次检查每台计算机上的权限。从每个系统出发，你应能打开 PowerShell 并 ping 通其他所有系统。

测试 PowerShell

如果配置正确，你应能执行以下操作。

  • 使用以下命令登录任意其他已配置的主机。
Enter-PSSession -ComputerName <COMPUTERNAME> -Credential <USERNAME>
  • 会出现一个输入 PowerShell 凭据的 Windows 对话框。在此输入密码。登录后，你会注意到命令提示符通过在命令行开头用方括号打印计算机名 [COMPUTERNAME] 来表示你已登录到另一台主机。例如，普通管理员提示符看起来是这样……
PS C:\Windows\System32>
  • 而登录到远程主机时，提示符看起来大致是这样。
[ComputerName]: PS C:\Users\UserName\Documents>
  • 当通过远程 shell 登录另一台主机后，你可以使用 Invoke-Command 运行任何命令。
[ComputerName]: PS C:\Users\UserName\Documents> Invoke-Command -scriptblock {$env:ComputerName}
  • 或者在本地的 shell 提示符下，使用带凭据的 Invoke-Command 远程运行任何命令。
PS C:\Windows\System32> Invoke-Command -ComputerName COMPUTERNAME -Credential USERNAME -scriptblock {$env:ComputerName}

理解 Windows 会话与 Powershell

Windows 会话由代表单个用户登录的所有进程和其他系统对象组成。Windows 启动时会启动一个包含主要服务和驱动的会话。随着它继续加载到图形桌面，又会加载另一个会话。

Windows PowerShell ISE

Windows PowerShell ISE 是一个有用的交互式工具，可用于试验 PowerShell 脚本。你可以轻松勾画想法并执行，快速保存和回顾你的工作。

使用 PowerShell 和 PSTools 远程运行 TouchDesigner

  • 使用 Invoke-Command cmdlet 可以在本地计算机上执行任何应用。例如，要启动 Notepad，可打开新的 PowerShell 并使用以下命令：
Invoke-Command -scriptblock {notepad}
  • 然而，从远程 PSSession 运行同样的命令会启动应用，但用户界面永远不会出现。检查 Windows 任务管理器会发现 Notepad 已启动，但 Windows 安全机制不允许从远程会话打开图形应用。有两种已知方法可绕过此问题。第一种是安装 PSTools，第二种是使用 Windows 任务计划程序。

安装 PSTools

  • PSTools 是一组 shell 可执行命令，有助于自动化计算机行为 —— 尤其是启动和停止应用以及 Windows 服务等功能。这些是 Microsoft 提供的工具。它们无需安装程序，只需解压到 Windows 应用路径中的某个位置。一个会自动位于 Windows 应用路径中的推荐位置是 C:\Users\<MYUSERFOLDER>\AppData\Local\Microsoft\WindowsApps 。
  • 在此处下载 PsTools 套件……
https://docs.microsoft.com/en-us/sysinternals/downloads/pstools

$s = New-PSSession -ComputerName HOSTNAME -Credential USERNAME

Copy-Item -ToSession $s C:\PowerShellZipFolder\ps*.exe -Destination C:\Users\USERNAME\AppData\Local\Microsoft\WindowsApps\ -PassThru
