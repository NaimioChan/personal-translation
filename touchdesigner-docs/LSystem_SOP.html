LSystem SOP

摘要

Lsystem SOP 实现 L-system（Lindenmayer-system，以 Aristid Lindenmayer（1925-1989）命名），可通过迭代定义复杂形状。它们使用一种数学语言，其中初始字符串会被反复求值，结果用于生成几何。每次求值的结果成为下一次几何迭代的基础，从而产生生长的错觉。

构建 L-system 时，先定义一系列规则，求值后产生新的字符串。新字符串的每个字符代表一条命令，作用于一个假想的笔尖，即「turtle」。重复此过程将使几何生长。

可以用 L-system 创建诸如：

  • 随时间生成树木、植物、花朵等有机对象。
  • 创建闪电、雪花等动画分叉对象。

该文件可从磁盘或网络读取。指定 URL 时使用 http:// 。

规则替换

使用 L-system 语法创建高度结构化的有机与分叉对象。L-system 是一个过程：对初始字符串应用一系列规则以生成新字符串。要构建几何，最终字符串的每个字符代表一条命令，作用于一个假想的笔尖，即「turtle」。

此过程先检查 premise 字符串的第一个字符。依次搜索全部十六条规则，直到找到适用的规则。当前字符随后被替换为该规则定义的一个或多个字符。premise 字符串中剩余的字符以类似方式替换。每一代重复一次整个过程。

规则的限制

  • 多边形 {} 和分支 [] 操作符最多可嵌套 30 层
  • 规则长度可达 256 个字符
  • 变量最多可有 5 个参数
  • 最多可定义 25 条规则

生成式规则语法

Touch 的 L-system 规则写作：

[lc<] pred [>rc] [:cond]=succ [:prob]

其中：

  • lc - 可选的左侧上下文
  • pred - 要被替换的前驱符号
  • rc - 可选的右侧上下文
  • cond - 条件表达式（可选）
  • succ - 替换字符串
  • prob - 规则执行概率（可选）

上下文相关性

最基本类型的规则是：

pred = succ

在这种情况下，当且仅当字符与 pred 匹配时，它才被替换为 succ 的字符。

例如：

Premise：ABC
Rule 1：B=DOG

将得到 ADOGC

pred 只能指定一个字母，但可以指定左右上下文符号。一般语法为 [lc<] pred [>rc] = succ。

For example:

Premise：ABC
Rule 1：A<B=DOG

同样得到 ADOGC，因为 B 前面是 A。如果规则是 Z<B=DOG 或 B>A=DOG，规则就不会应用。

参数符号

每个符号最多可关联五个用户定义的变量，可在表达式中引用或赋值。前驱中的变量被实例化，后继中的变量被赋值。

例如：

规则 A(i, j) = A(i+1, j-1) 会将每个 A 替换为一个新的 A，其中第一个参数已加一，第二个参数已减一。

注意，前驱中的变量也可以被规则的条件部分或概率部分引用。

例如：

规则 A(i):i<5 = A(i+1) A(i+1) 会将每个 A 加倍，最多五次（假设 Premise 为 A(0)）。

赋给几何符号（例如 F、+ 或 !）的参数会按几何意义解释。

例如：

规则 F(i, j) = F(0.5*i, 2*j) 同样会将每个 F 替换为包含已修改参数的新 F。此外，新的 F 现在会以一半长度和两倍宽度绘制。

操作符覆盖

通常 turtle 符号使用当前长度/角度/粗细等来决定其效果。通过为 turtle 操作符提供显式参数，会覆盖该操作符通常使用的值。

F、f、G、h、H 的覆盖参数形式为：

F(i,j,k,l,m)

  • i - 覆盖长度。
  • j - 覆盖粗细。
  • k - 覆盖 # 管段数。
  • l - 覆盖 # 管行数。
  • m - 用户参数。

k 和 l 覆盖参数允许动态解析管段。

示例

F - 按当前长度向前移动并创建几何。

H - 按当前长度的一半向前移动并创建几何。

F(i, j) - 向前移动距离 i,，创建粗细为 j 的几何。

H(i, j) - 向前移动 i 距离的一半，创建粗细为 j 一半的几何。

+ - 按当前角度转向。
~ - 按随机角度旋转。

+(i) - 转 i 度。
~(i) - 用 i 的值覆盖随机角度。

$(x0,y0,z0) - 将 turtle 指向位置 (x0,y0,z0)。

基于上述，Premise：

F(1) +(90) F(1) +(90) F(1) +(90) F(1)

无论默认的 Step Size 或 Angle 设置如何，都会生成一个单位立方体。

边重写

在《植物的算法之美》中，许多示例使用了一种称为边重写（Edge Rewriting）的技术，涉及左下标和右下标。一个典型的例子可能像这样：

Generations 10
Angle 90
Premise F(l)
Rules
F(l) = F(l)+F(r)+
F(r) = -F(l)-F(r)

不过 Touch 并不知道 F(l) 和 F(r) 是什么。这种情况下，我们可以修改规则以使用参数传递。对于 F turtle 符号，前四个参数分别是 length、width、tubesides 和 tubesegs，最后一个参数留作用户定义。我们可以定义这个最后的参数，使 0 为左、1 为右：

Generations 10
Angle 90
Premise F(1,1,3,3,0)
Rules

经过两代后会产生：Fl+Fr+-Fl-Fr。这个最终字符串与 F+F+-F-F. 之间应当没有区别

另一种方法是使用两个新变量，并在最后一步用条件语句将它们转换为 F：

Variable b ch("generations")
Premise l
Rules
l:t<b=l+r+
r:t<b=-l-r
l=F
r=F
Output l
F
F+F+
F+F++-F-F+

表达式

在前面的示例中，使用了表达式 0.5*i 和 2*j。事实上，表达式可用于任何需要数值的地方。目前表达式中可以使用以下符号：

( ) - 用于嵌套优先级的括号

^ + - * / % - 算术运算符

min() max() sin() cos() asin() acos() pic() in() - 支持的函数

== != = < <= > >= - 逻辑运算符

& | ! - 逻辑运算符：and、or、not

b c d - 展开后的 SOP b、c、d 参数

x y z - 当前 turtle 位置

g - 符号的年龄

t - L-system 的时间（代数）

a - SOP 角度参数

T - SOP 向性（重力）参数

上述预定义变量不应在前驱的参数中使用。

For example: A(a,b) = B(a*2,b*2) 是错的（a 是 SOP Angle 参数）。a<b (A,B) = b(A+1,B) 才对。

最后一条语句是正确的，因为 a 和 b 被用作符号而不是变量名。A 和 B 是正确的，因为变量名区分大小写。

    0

  • in(q, r, s) - 给定包含 metaball 几何的 MetaTest 输入源，如果点 (q, r, s) 位于 metaball 内，此函数返回 1，否则返回 0。使用 in(x, y, z)（字母 x、y 和 z 是特殊的，包含 turtle 的 X、Y、Z 位置）来测试 turtle 当前是否在 metaball 内，从而生成修剪后的输出。

条件

每条规则可以指定一个可选条件。语法为：

[lc<] pred [>rc]:cond = succ

For example:

Rule1 A:y>2=J 包含所有位于 2 高度以上的 A 处的源 J。

概率

每条规则可以指定其被使用的概率（前提是其它方面适用）。语法为：

[lc<] pred [>rc]:cond=succ=prob

For example:

Rule1 A=B:0.5
Rule2 A=C:0.5

会以相同概率将 A 替换为 B 或 C。

用 L-system 创建组

有一个组操作符 'g'，它会将当前正在构建的所有几何归入组 g。

For example: g[F] 将 F 生成的几何归入名为 lsys0 的组。可以从 Funcs page 设置 lsys 前缀。

可选的组参数

g 也可接受一个可选参数。

For example: g(1)[F] 将 f 生成的几何归入名为 lsys1 的组。如果没有给定参数，默认索引会相应递增。

当前组容器会随 turtle 状态一起压入/弹出，因此可以这样做：

gF [ gFF] F - 第一个和最后一个 F 被放入组 0，中间的 FF 被放入组 1。

gF [ FF] F - 四个 F 的几何都被放入组 0（压入 turtle 时会沿用父级的组）。

要将中间的 FF 从父级的组类型中排除：gF [ g(-1)FF ] F

随时间控制长度

要创建一个每次迭代前进距离减少 X% 的 L-system，需要用某个值开始你的 Premise，然后在规则中将该值乘以希望保留的百分比：

Premise A(1)
Rule A(i) = F(i)A(i*0.5)

这样「i」会在再次求值 A 之前被缩放。关键部分是 Premise。你必须以一个值开始，才能缩放该值。

示例

Step 1) 放置一个 Circle SOP，并将 Number of Divisions 设为 : param("lsys", 3）

随后会显示一个三角形（3 是默认值）。

Step 2) 将其接入 L-System SOP 的 J 输入。如果 L-system 的 Premise 为：

J A
J(,,4) A
J(,,5) A

这样，你可以在每片叶子被复制之前自定义它。

Step 3) 将 Premise 和 Rule 改为：

PremiseA(0)
Rule1A(i)=FJ(,,i+3)A(i+1)

这会创建一行阶数递增的多边形。

Step 4) 最后，我们要创建 20 片叶子，并将它们全部放入一个 Switch SOP。为此，在 Switch SOP 的 Select Input 中输入以下表达式：param("lsys",0)
Step 5) 然后在 L-system 中，J(,,0) 得到第一个 SOP，J(,,1) 得到第二个，依此类推。这解决了仅用 JKM 时叶子数量受限的问题。

另外注意，这些示例只用了第一个印记参数，你最多可以使用三个参数：例如 J(,,1,2,3)

J、K、M 的前两个参数用于覆盖长度和宽度，与符号 F 类似。

Info CHOP 通道

可通过 Info CHOP 访问 LSystem SOP 的额外信息。

SOP 通用信息通道

  • num_points - 此 SOP 中的点数。
  • num_prims - 此 SOP 中的图元数。
  • num_particles - 此 SOP 中的粒子数。
  • last_vbo_update_time - 在另一个线程中根据 SOP 的 CPU 数据更新 GPU 上的几何数据所花的时间。由于它属于另一个线程，此时间不计入通常的帧时间。
  • last_meta_vbo_update_time - 在另一个线程中根据 SOP 的 CPU 数据更新 GPU 上的元表面几何数据（如 metaball 或 nurbs）所花的时间。由于它属于另一个线程，此时间不计入通常的帧时间。

通用操作符 Info 通道

  • total_cooks - 自进程启动以来该操作符的计算次数。
  • cook_time - 上一次计算的耗时，单位为毫秒。
  • cook_frame - 该操作符上一次计算时的帧号，相对于组件时间轴。
  • cook_abs_frame - 该操作符上一次计算时的帧号，相对于绝对时间。
  • cook_start_time - 该操作符在其计算的那一帧中开始计算的时刻，单位为毫秒。
  • cook_end_time - 该操作符在其计算的那一帧中结束计算的时刻，单位为毫秒。
  • cooked_this_frame - 如果操作符在本帧进行了计算则为 1。
  • warnings - 该操作符的警告数量（如果有）。
  • errors - 该操作符的错误数量（如果有）。
