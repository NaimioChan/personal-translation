分支操作指南

开篇来自 Jonas Bülow 的评论：

我关于分支的原则（很多人也这么做）可以概括为：

  • 在分支点上打一个普通的标签，命名为 branched-vX-Y-Z

  • 在分支标签上创建分支，命名为 branch-vX-Y-Z

现在，当你想查看分支上发生了什么时，可以从分支点 diff 到分支头，做法是

  • cvs diff -r branched-vX-Y-Z -r branch-vX-Y-Z

很多人忘记在创建分支的地方打标签，这使得分支之间很难同步。

vX-Y 是表示版本前缀的符号，即 v0-39。v0-39-1 则是分支上的一个标签。

主要开发在主干上进行。也就是说，按上面的例子，在标签 branched-v0-39 之后，主干上就没有以 v0-39 开头的标签了。第一个标签应该是一个递增的版本号，例如 v0-40 或更高。

CVS 在分支之间做合并时不太友好。分支之间的第一次合并很简单，直接用 branched-vX-Y 标签就行。把分支 branch-vX-Y 上的工作合并到 HEAD（MAIN 主干最新部分的符号名），做法是在 HEAD 里执行 cvs update -j branched-v0-39 -j v0-39-1。

如果你从一个分支向另一个分支做增量合并，就需要手动记录合并点。一个好习惯是在目标上把这些点标记为 MERGED_FROM_xxx，在源上标记为 MERGED_TO_xxx。下次做合并时，你就用其中一个标签来指明应该从哪里开始合并。
