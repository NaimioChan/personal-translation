使用 Pd-extended 源代码

要实现完整的开发周期，就需要知道如何把 Pd 的许多不同源代码仓库组合起来，这些仓库列在 GettingPdSource 中。本文提供一些对开发者友好的建议，介绍如何下载相关的源代码，以及如何把它们组合起来。

为开发下载 Pd Extended

带版本控制的相关源代码包括以下几项：

* Pd extended 的核心，位于 Git 中。我们把这个代码库称为 pd-extended.git。

 git clone git://git.code.sf.net/p/pure-data/pd-extended

* Pd extended 的完整社区仓库，包含大部分外部对象。它位于 Subversion 中，我们称之为 pd-svn。

 svn co svn://svn.code.sf.net/p/pure-data/svn/trunk pd-svn

 # 为了统一，我们建议不用上面的命令，改用 Git 接口，如下所示：
 git svn clone https://svn.code.sf.net/p/pure-data/svn/trunk/ pd-svn
（关于 git+svn 的开发流程，见 https://sourceforge.net/apps/trac/vxl/wiki/GitSvn）

* Gem 有自己独立的 Git 仓库。

 git clone git://git.code.sf.net/p/pd-gem/gem gem.git

把各部分组合起来

把这些源代码组合成开发者的构建版本有两种方式。

完整方式

这种方式以 pd-svn 为中心，并链接到最新的 pd-extended.git 和 Gem。如果你需要用到许多库、并希望把整体一起开发和测试，这可能是最好的方式，因为它几乎能构建 Pd 所有可用的库。

按上面的方法下载 pd-svn、pd-extended.git 和 Gem。然后用指向 pd-extended.git 的符号链接替换 pd-svn 的 'pd' 子目录。

 cd pd-svn/
 mv pd pd-original
 ln -s ../pd-extended.git pd
把 Gem 符号链接到 pd-svn/Gem 和 pd-svn/externals/Gem 
 ln -s ../gem.git Gem
 cd externals
 ln -s ../../gem.git Gem

在 Linux 下，按 BuildingPdExtended 中所述的 linux-make 方式编译。

选择方式

这种方式以 pd-extended.git 为中心，在 pd-extended.git/extra 内用符号链接指向你当前想开发的库。如果你需要把各部分隔离开来单独开发，这可能是最好的选择。

按上面的方法下载 pd-extended.git、pd-svn 和 Gem。在 pd-extended.git/extra 内，链接到你需要的库，例如来自 pd-svn 或 Gem 的库。例如：

 libdir -> ../../pure-data/trunk/externals/loaders/libdir
 cyclone -> /Applications/Pd-extended.app/Contents/Resources/extra/cyclone/
 extra -> ../../pure-data/trunk/externals/extra
 vanilla -> ../../pure-data/trunk/externals/vanilla/
 pddp -> ../../pure-data/trunk/externals/pddp
 pdlua -> ../../pure-data/trunk/externals/loaders/pdlua/src/

在 pd-extended.git 内构建全部内容，这样就能快速测试核心部分的改动，并直接从那里运行 Pd：

 cd ~/code/pd-extended.git
 ./autogen.sh
 ./configure
 make
 ./src/pd
