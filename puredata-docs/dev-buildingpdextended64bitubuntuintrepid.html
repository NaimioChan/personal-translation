在 64 位 Ubuntu Intrepid 上构建 pd-extended

===== 在 64 位 Ubuntu Intrepid 上构建 pd-extended =====

这是一份快速指南，讲如何为 64 位 Ubuntu 8.10 Intrepid Ibex 构建 amd64 的 pd-extended 包，因为目前还没有可用的 64 位 .deb 包。它基于 BuildingPdExtended、GettingPdSource 和 64BitLinux 中为 Ubuntu 8.04 Hardy Heron 制作包的说明。

这个包不是 *真正* 的 pd-extended 构建，而是 Pd-Vanilla 0.42.4 加上全部 pd-extended 外部对象，所以 [import] 不可用（抱歉），详见下文……

2009 年 3 月 1 日 Dan Wilcox

http://danomatika.com | http://robotcowboy.com

它在 **ubuntu 9.10**（karmic koala）上也几乎毫无问题地工作：只需去掉 deb 的 control 文件里的 ttf-bitstream-vera 依赖（现在叫 ttf-dejavu，bitstream vera 反正随 gem 一起提供），然后重新打包：

  • mkdir -p unpack/DEBIAN build && dpkg -x Pd-0.40.3-extended_amd64.deb unpack/ && dpkg -e Pd-0.40.3-extended_amd64.deb unpack/DEBIAN/

  • {你的编辑器} unpack/DEBIAN/control

  • dpkg -b unpack/ build/

由于这样或那样的原因，pix_image 在打包好的 GEM 里无法工作。为了让它能用，我把 Gem.pd_linux 换成了 karmic 源里的那个——这是个非常丑陋的解决办法，但看起来有效。

谢谢，t.

1 获取源代码

首先我们要下载用于构建这个包的源代码文件。打开终端，建一个工作目录并 cd 进去。我在桌面上建了一个：

  • mkdir ~/Desktop/pd-build && cd ~/Desktop/pd-build

**pd-extended**

下载 0.40.3 的 pd-extended 代码：

  • wget http://downloads.sourceforge.net/pure-data/Pd-0.40.3-extended.tar.bz2 tar xvf Pd-0.40.3-extended.tar.bz2

这会花一些时间……

**pd**

下载 Pd-Vanilla 0.42.4 的源码包，解压它，用它替换 Pd-0.40.3-extended 文件夹里的 Pd 核心源码。我这么做是因为 0.41 的 pd-extended 核心（当时）还没有解决 64 位的 table bug（table 只能读到一半）。希望在不久的将来这一步就不需要了。

::

  • wget http://downloads.sourceforge.net/pure-data/pd-0.42-4.src.tar.gz tar xvf pd-0.42-4.src.tar.gz yes | rm -R Pd-0.40.3-extended/pd/* cp -R pd-0.42-4/* Pd-0.40.3-extended/pd

**Gem**

pd-extended 的源码 tarball 里不带 Gem，所以你可以用 rsync 从 pd-extended 的自动构建里取来，放进 Pd-0.40.3-extended 文件夹：

  • rsync -av --delete rsync://128.238.56.50/distros/pd-extended/Gem Pd-0.40.3-extended/

2 准备

下面是为了让所有外部对象都能在 Intrepid 上正确编译，需要做的源码文件修改清单。

**pdp**

pd-extended 源码包里包含的这个版本的 pdp 会调用 open 函数来创建新文件，却没有指定这个文件的权限，而 Intrepid 里的 libc 要求指定。你需要在具体那个 file:: 的函数参数里加上它。

  • gedit Pd-0.40.3-extended/externals/pdp/modules/generic/pdp_rawout.c

跳到第 141 行，在 "O_CREAT" 后面加上 ", 0666"，于是

if (-1 == (pipefd = open(x->x_pipe->s_name, O_WRONLY|O_CREAT))){

变成

if (-1 == (pipefd = open(x->x_pipe->s_name, O_WRONLY|O_CREAT, 0666))){

另外，这个外部对象缺少一个在 64 位下链接所需的编译标志。你需要加上这个标志：

  • gedit Pd-0.40.3-extended/externals/pdp/opengl/Makefile.config

跳到第 9 行，在 CFLAGS 那一行加上 "-fPIC"，于是

CFLAGS = -DPD -O2 -funroll-loops -fomit-frame-pointer -ffast-math \

变成

CFLAGS = -DPD -fPIC -O2 -funroll-loops -fomit-frame-pointer -ffast-math \

**gem2pdp**

gem2pdp 这个外部对象缺少一个在 64 位下链接所需的编译标志。你需要加上这个标志：

  • gedit Pd-0.40.3-extended/externals/gem2pdp/Makefile.in

跳到第 16 行，在 CFLAGS 那一行加上 "-fPIC"，于是

CFLAGS = -DPD -O2 -funroll-loops -fomit-frame-pointer -ffast-math \

变成

CFLAGS = -DPD -fPIC -O2 -funroll-loops -fomit-frame-pointer -ffast-math \

**cyclone**

cyclone 这个外部对象缺少一个在 64 位下链接所需的编译标志。你需要加上这个标志：

  • gedit Pd-0.40.3-extended/externals/miXed/Makefile.common

跳到第 44 行，在 DEFINES 那一行加上 "-fPIC"，于是

DEFINES = -DUNIX

变成

DEFINES = -fPIC -DUNIX

**pdip**

pdip 这个外部对象缺少一个在 64 位下链接所需的编译标志。你需要加上这个标志：

  • gedit Pd-0.40.3-extended/externals/pidip/Makefile.in

跳到第 18 行，在 PDP_PIDIP_CFLAGS 那一行加上 "-fPIC"，于是

PDP_PIDIP_CFLAGS = $(MPEG4IP_CFLAGS) $(IMLIB_CFLAGS) \

变成

PDP_PIDIP_CFLAGS = -fPIC $(MPEG4IP_CFLAGS) $(IMLIB_CFLAGS) \

3 构建

**开发库与软件**

在你能够构建这个包之前，需要先安装一些开发库和软件：

  • sudo apt-get install build-essential dpkg-dev swig ttf-bitstream-vera x-ttcidfont-conf \ libvorbis-dev libspeex-dev fakeroot libgsl0-dev dssi-dev liblo0-dev freeglut3-dev libimlib2-dev \ libbz2-dev libtheora-dev libmagick9-dev libfftw3-dev libasound2-dev libjack-dev libmp3lame-dev \ libmpeg3-dev libogg-dev libquicktime-dev libsdl1.2-dev libvorbis-dev tcl8.4-dev tk8.4-dev libdv4-dev

因为我在尝试制作 pd-extended 包之前就已经装上了其中一些库，所以这份清单是我根据构建包时生成的 Debian control 文件整理的。可能有些错误，如果你发现请更新这里。

**构建**

好，现在我们可以进入 linux 包构建文件夹，用自带的 Makefile 试着构建：

::

  • cd ~/Desktop/pd-build/Pd-0.40.3-extended/packages/linux_make make install

这会在 Pd-0.40.3-extended/packages/linux_make/build 文件夹里构建出一个包结构。

如果（在第 1 步里）你选择使用 Pd-vanilla 核心，那么安装很可能会出点岔子，把所有 pd 核心文件装到了 build/home/.. 文件夹而不是 build/usr/lib/pd 文件夹。我遇到了这种情况，于是我把那些文件都移到了正确的位置：

::

  • cp -R build/home/YOUR_USERNAME/Desktop/pd-build/Pd-0.40.3-extended/packages/linux_make/build/usr/lib/pd/* build/usr/lib/pd/ rm -R build/home

**制作 .deb 包**

构建结构创建好之后，就可以构建 debian 包了：

  • make package

**打包构建出错？**

如果你像我一样遇到类似这样的错误：

dpkg-deb: parse error, in file /home/dano/Desktop/pd-build/Pd-0.40.3-extended/packages/linux_make/build//DEBIAN/control near line 8 \package pd-extended: Depends field, syntax error after reference to package zlib1g make: *** deb Error 2

那么就是某个依赖项后面漏了一个逗号。打开 Debian control 文件，翻到第 8 行的依赖列表，在报错提到的那两个包后面补上漏掉的逗号，这里是 "zlib1g"：

  • gedit build/DEBIAN/control

然后重新运行下面这条构建命令（在这里你还可以指定 .deb 的名字）：

  • fakeroot dpkg-deb --build build/ Pd-0.40.3-extended.deb

**安装与使用**

如果打包成功了，你现在应该在 ~/Desktop/pd-build/Pd-0.40.3-extended/packages/linux_make/ 里有一个 .deb 包。不要担心 .deb 文件上的版本名不是 0.40.3，包的控制信息里内部带着这个版本号以及 "pd-extended" 这个包名。

我最后得到的是 "Pd-0.40.3-extended_amd64.deb"，它并不是 *真正* 的 pd-extended，因为它没有 pd-extended 核心，而是 Pd Vanilla 0.42.4。所以它基本上就是最新的 Vanilla 加上全部外部对象，也就是说我至少又能干活了！
