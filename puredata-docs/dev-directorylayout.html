目录结构

在做软件包的构建系统时，所有这些目录里的东西都需要被引用到。有些开发者把东西放在不同的位置，导致很难有一套统一的构建系统。所以这份文档的目的是让大家对 Pd 目录的布局方式达成一致。

一个很好的例子是：需要引用 pd 的源码目录或 bin 二进制文件（即 -bundle_loader ../../../pd/bin/pd），或者 packages/darwin_app/Makefile 在各个不同目录里调用 make 并从这些目录复制文件。

源代码的所有不同部分都应该检出在同一个目录、同一层级下。用一个名为 "pd" 的软链接，可以方便地在你要使用的各个 Pd 核心版本（MAIN、devel、impd，或来自 .tar.gz 的版本）之间切换。

pure-data-\
          |\_abstractions
          |
          |\_doc
          |
          |\_externals
          |
          |\_packages
          |
          |\_pd 
          |
          \_scripts

由于 pd 这一部分有多个分支，还有打过标签的发布版和发布分支，你很可能会同时拥有好几个不同版本的 pd 目录，这时 pd 就是一个指向你当时所用版本的软链接。另外， pure-data Vanilla 和 Pd-extended 的核心开发都在 git 里。

          |\_pd -> pd-0.39-test4
          |
          |\_pd-0.38-4
          |
          |\_pd-0.38-0test4
          |
          |\_pd-devel_0_37
          |
          \_pd-impd_0_37

在 doc 目录里，为核心文档的各部分加上符号链接，这样存放在 doc 源码树里的帮助文件就能使用并链接到它们。

          |\_doc
          | \
          | |\_2.control.examples -> ../../pd/doc/2.control.examples
          | |
          | |\_3.audio.examples -> ../../pd/doc/3.audio.examples
          | |
          | |\_4.fft.examples -> ../../pd/doc/4.fft.examples
          | |
          | |\_7.stuff -> ../../pd/doc/7.stuff
          | |
          | |\_sound -> ../../pd/doc/sound
          | |
