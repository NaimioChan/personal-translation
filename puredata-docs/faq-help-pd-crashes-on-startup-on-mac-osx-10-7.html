救命！Pd 在 Mac OSX 10.7+ 上启动时崩溃

你在用 Mac OSX 10.7 或更高版本（Lion、Mountain Lion、Mavericks 等），Pd 启动时崩溃了吗？这可能是由于较新版本的 OSX 会在应用被关闭时保存窗口状态，并为你重新打开它们。如果过快或同时打开多个 patch 时在资源（套接字等）上发生冲突，这对 Pd 可能很糟糕。

好在有办法手动告诉操作系统不要保存窗口状态，可以设置一个 defaults 选项，或者直接锁定存放这些信息的文件夹。这样 Pd 每次都会以空状态打开。

清除旧状态

首先，务必删除已有的状态，否则它会一直按上次保存的那些窗口打开。退出 Pd 时可以按住 Option（也就是 Cmd+Opt+Q）来绕过 OSX 的状态保存机制，并删除当前的状态。

另一种办法是用终端：

rm -rf ~/Library/Saved\ Application\ State/org.puredata.*

如果你遇到启动崩溃，这至少能让 Pd 回来，但它并没有关闭状态保存……

方案 1：设置 defaults 选项

关闭 Pd 状态保存机制最简单的办法，是设置一个用户 defaults 选项，告诉 OS X 在退出时默认 *不要* 保存 Pd 的窗口状态：

defaults write org.puredata NSQuitAlwaysKeepsWindows -bool false

现在重启 Pd。退出时，Pd 不会删除任何已经设置好的窗口状态。另外，如果你 *确实* 想保存窗口状态，在通过 File 菜单或 Cmd+Q 快捷键退出时按住 Option/Alt 键。

方案 2：锁定状态文件夹

你可以用「显示简介」对话框（CMD+I）锁定 Pd-Extended 的状态文件夹，从而关闭 Pd 的状态保存机制：

~/Library/Saved\ Application\ State/org.puredata.*

"~/" 是你的用户主目录。

可能有不止一个名为 "org.puredata..." 的文件夹，因为（在撰写本文时）Pd-vanilla 和 Pd-extended 使用的标识符略有不同。不管怎样，如果你清掉了一个，多半也应该把两个都清掉。

和前面一样，你也可以用终端：

chflags -v uchange ~/Library/Saved\ Application\ State/org.puredata.*

"uchange" 标志会锁定该文件夹。
