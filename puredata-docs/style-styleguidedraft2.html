Send/Receive 命名约定

使用 $0+ 与空格与层级

打 patch 时，建立名字的层级通常很有用。最常见的例子是创建局部 send/receive 时使用 $0：写成 [send $0-frequency]，其中 "$0" 是「父」，"frequency" 是「子」。我们用 "-" 分隔层级。例如，局部命名空间里某个滤波器的 "cutoff" 参数可以写成 [receive $0-filter-cutoff]。如果用的是 $0 之外的参数也同样适用，比如把 "foobar" 传给 $1：可以写成 [receive $1-baz]，得到完整的名字 "foobar-baz"。

有时一个参数由不止一个词组成。为了清晰，用 "_" 分隔词，例如 [receive $0-resonance_peak]。

全局变量

由于全局变量被广泛使用可能带来令人困惑的 bug，它们写成全大写，例如 [send SSSAD_ADMIN]。像上面那样用 "_" 分隔词。

参数传递

如果把父抽象对象的参数传给子抽象对象，在可能的情况下，应让它们处在与父级相同的 $# 位置上。例如，如果父级调用为 [parent a b c]，而 [child] 还需要 "a b c" 加上 "x y z"，就把 [child] 设计并调用为 [child a b c x y z]。

通道命名

对于 [send~/receive~] 或 [throw~/catch~] 配对的多个并行通道这一特殊情况，用数字而不是 "left"、"right" 来命名你的通道。例如 [throw~ $0-wavetable_osc-ch1] 和 [throw~ $0-wavetable_osc-ch2]。这样以后把 patch 扩展到多于 2 声道的音频会更容易。
