安装 pdj

pdj 让你可以用 Java 编写与操作系统无关的 pd 外部对象。它是 Max/MSP 的 mxj 对象的克隆，所以你为 pdj 编写的 Java 代码应该（！）也能在 mxj 里正常运行。

我个人发现，要在我的 Dell Latitude E6400 上、在 Linux Ubuntu 12.04 配合 pd-extended 0.43.1 beta 的环境里安装当前的 pdj 版本（0.8.7）很困难。

以下是我遵循的步骤：

  • 假定已经安装了 ant 和 Sun Java(TM) Development Kit (JDK) 7（两者都通过 synaptic 或类似的包管理器安装）

  • 为你的操作系统下载 pdj。解压，例如解压到 ~/Download 目录下一个单独的文件夹里

  • 下载 puredata 0.43.1 的源代码 tarball。解压，然后只把 src 文件夹复制到你已有的 pd-extended 文件夹里。大概像这样：

sudo cp -r src /usr/lib/pd-extended/

  • 在 pdj-0.8.7/ 里通过你喜欢的文本编辑器按这种方式配置 Linux-build.properties（如果你用的是 amd64 之类的机器，请做相应修改）：

# Linux 的属性文件，现在带有默认的 ubuntu 软件包

# 填入 jdk（java sdk）安装的路径
jdk.home=/usr/lib/jvm/java-7-sun

# 填入 pd 安装的路径
pd.home=/usr/lib/pd-extended

# 常见的 linux 属性
isLinux=true
compiler=gcc
linker.type=shared
platform=linux

# 64 位系统？取消下面一行的注释
#jdk.libs=${jdk.home}/jre/lib/amd64

jdk.libs=${jdk.home}/jre/lib/i386
pdj.outfile=${dist.dir}/pdj

  • 在 pdj-0.8.7/ 里构建：

sudo ant package
（我注意到有几条警告）

  • 把 dist 文件夹复制到 puredata 的额外外部对象文件夹里，并把它重命名为 pdj。在我的机器上：

sudo cp -r dist /usr/local/lib/pd-externals/
sudo mv /usr/local/lib/pd-externals/dist /usr/local/lib/pd-externals/pdj

  • 把需要的类（pdj-0.8.7/work/com 文件夹）加进这个新文件夹里。在我的机器上：

cd /usr/local/lib/pd-externals/pdj/classes
sudo cp - r ~/Downloads/temp/pdj-0.8.7/work/classes/com .

  • 让 puredata 能看到新的额外外部对象（Edit -> Preferences -> New... -> /usr/local/lib/pd-externals/pdj）

  • 用（最简单的）方式配置 pdj.properties，让 puredata 能运行测试类：

# 这是要设置的 pdj classpath（动态）：
pdj.classpath=

# 这会打印出在编译/加载用户类之前加载的所有 .jar
pdj.verbose-classloader=true

# 与 pdj classloader 一起使用的编译器类型。只能使用 'javac'
# 或 'jikes'。不要填编译器的完整路径
#
# 要禁用自动编译，只需使用
# pdj.compiler=null
#
pdj.compiler=javac

# pdj 编译器/classloader 目录。如果没有定义这个属性，默认使用
# ${pdj.home}/classes 目录。编译之前，pdj 会检查你的 .java
# 是否需要编译。
#
#pdj.classes-dir=

# 这会把 java 的 out/err 流重定向到 pd 控制台。如果你需要把 pdj
# 的错误和异常记录到 stderr 和 stdout，把它设为 false。
#
pdj.redirect-pdio=true
# 要使用的 jvm。如果找不到它而且系统是 Windows，
# 将使用注册表里安装的 jvm。在 OS X 上不使用
#
pdj.JAVA_HOME=/usr/lib/jvm/java-7-sun

# 在 OS X 上使用的 JVM 版本；与 OS X 上的 Java Framework 关联
#
#pdj.osx.JVM_JAVA_VERSION=1.5.0

# 注意：pdj.home 会根据 pdj.pd_linux 或 pdj.dll 安装的位置自动设置
# （在 OS X 上你需要把它放进你的 pd 路径里）

# =========================================================================
# VM 参数
#
# 要用 1.5（jconsole）监控内存和线程的使用情况，使用
#   -Dcom.sun.management.jmxremote
# 要在 8000 端口上进行远程调试
#   -Xdebug -Xrunjdwp:transport=dt_socket,server=y,suspend=n,address=8000
# 要检查 jni 调用
#   -Xcheck:jni -verbose:jni
#
# 所有参数写在同一行，就像 $ java -X... -X... myclass
#
pdj.vm_args=-Xincgc -Xms32m -Xmx256m

# 告诉 pdj 它必须使用哪种类型的 jvm：client 或 server。在 OS X
# 上不使用。client 的启动时间更短，占用的内存也可以更少。server
# 启动更慢、占用更多内存，但代码一旦执行起来，会比 client 模式更快。
#
pdj.vm_type=server

此时测试 patch 应该能正常工作了。

下面这条由 Hans 留下的说明，也许能解决 puredata 在第一次打开 pdj~ 模块运行时遇到的可见性问题。

  • 为 pdj.pd_linux（GNU/Linux）或 pdj.pd_darwin（Mac OS X）建立一个符号链接，并把它命名为 pdj~.pd_linux（GNU/Linux）或 pdj~.pd_darwin（Mac OS X），像这样：

(GNU/Linux)

cd ~/pd-externals
ln -s pdj.pd_linux pdj~.pd_linux

(Mac OS X)

cd ~/Library/Pd
ln -s pdj.pd_darwin pdj~.pd_darwin
