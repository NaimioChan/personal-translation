开发者文档

  • Getting Pd Source - 如何获取构建所有内容所需的全部源代码

  • Directory Layout - 这是 Pd 开发者使用的标准布局，这样所有 Makefile 之类的东西都能在正确的位置查找。

  • Repository Layout - 代码仓库被划分为若干部分，这里是对各部分的说明。

  • Code Guidelines - 使用 Pd Subversion 仓库和 Pd-extended 构建时的一些准则。

  • SVN Commit Access - pure-Data Sourceforge 项目是为了给所有 Pd 开发者提供一个贡献作品的场所而建立的。

  • Merging Howto - 在 SVN 中如何把一个分支的改动合并到另一个分支。

自动构建系统

  • Pd-Extended Build System - Pd-extended 构建系统是一套统一的跨平台构建系统，目标是把 Subversion 仓库中的内容尽可能多地组装成易于安装的包，并覆盖尽可能多的平台。

  • PdLab Build Farm - nightly 构建在一组服务器组成的构建农场上运行，Pd 开发者也可以用这些机器来构建和测试自己的代码。

  • Auto-Build Process - 运行 auto-builds 的流程分步概要

  • Auto Build Scripts - 用于运行 nightly 自动构建的脚本的简要草图。

打包 Pd

  • Debian Debs - Pd 里大部分代码都有 debian 包。这里是具体做法。

  • Windows Installer - 这里讲如何从源代码构建你自己的 Windows 安装程序。

Pd 内部

  • PdAPI - 用于记录 Pd API 的 wiki。

  • Pd Source Notes - 关于 Pd 源代码结构和形式的笔记。

  • Pd File Format - Miller Puckette 关于 Pd 文件格式的论文，以前在 http://student-kmt.hku.nl/%7Etjeerd/pd/pd_fileformat.html

  • Libdir - 我写了一些关于为 Pd patch 库提议的 libdir 格式的文档。随着 Thomas 的 loader patch 的出现，这种格式对用其他语言写的对象也同样适用：

  • AtomTypes - Pd-atom 的用法与滥用（它们是什么、做什么、与哪个 type-ID 关联……）

  • ParsingPatchesInVariousLanguages - 如何用各种编程语言把 Pd patch 读成一行行 atom。

Pd 外部对象

  • Pd Externals Howto - 这份 HOWTO 教会了许多现在还在写 Pd 的开发者如何编写 Pd 对象。用 C 编写自己的 Pd 对象时，从这里开始。

  • Pd externals in Xcode - 关于如何在 Xcode 中构建 “Hello World” 外部对象的简短教程

  • flext - 一个用于跨平台开发 Pd 与 Max/MSP 对象的 C++ 层。还有一份 introduction into flext in PDF format

  • Inlet Proxy Object - 这是一个示例，展示如何创建一个入口代理对象，用来处理冷入口上的任意选择器。

  • DebuggingPdExternals - gdb 对于追查代码里的各种 bug 非常方便
