合并指南

声明：本文可能已经过时，因为当前的工作流程基于 Git

你常常会想把在一个分支上所做的改动（比如某个 Pd-extended 发布分支）合并回主干，或者反过来。

SVN 分支实质上就是某个修订版本下某个目录的副本，其历史一直共享到复制那一刻。你可以用 svn log --stop-on-copy 找出分支产生的确切修订版本，在这个例子里就是：

svn log --stop-on-copy https://pure-data.svn.sourceforge.net/svnroot/pure-data/branches/pd-extended/v0-40/abstractions/senderfruit

它告诉我，我的目录是在修订版本 9819 被复制过来的。

所以，既然我知道了起点在哪里，就取出我要合并到的那个分支的一份副本（合并是在本地进行的，以防出现冲突）：

svn co https://pure-data.svn.sourceforge.net/svnroot/pure-data/branches/pd-extended/v0-40/abstractions/senderfruit

cd senderfruit

然后把从 9819 到当前的所有内容（来自主干）合并过来：

svn merge -r 9819:HEAD https://pure-data.svn.sourceforge.net/svnroot/pure-data/trunk/abstractions/senderfruit

而且最重要的是，我会在日志里留一条记录说明我合并了什么，这样如果以后还要合并，我就知道上次停在哪里。

svn ci -m "merged r 9819:9852 from trunk/abstractions/senderfruit"

你会注意到，这些修订版本的记账工作烦人得很。

据说 SVN 1.5 会修好这个问题，届时你只需写 svn merge [URL] [WorkingCopy]，剩下的它会自己算出来。
