Deken

Deken 是一个用于创建、上传和分发 Pd-vanilla 外部对象库的框架。它由两部分组成：

  • 一个用于获取、构建并上传已打包外部对象的脚本
  • 一个用于搜索和安装外部对象的插件。
  • 一个用于在线搜索外部对象的网站 https://deken.puredata.info


项目网站位于 https://github.com/pure-data/deken

下面列出了把一个对象包转换为 deken 格式所要做的任务。这些任务用于转换 pd-extended 的包，但也适用于其他编译型代码包。

修正一些错误和/或改进帮助文件（helppatch）；
这里不是写修复 pd 外部对象手册的地方，但下面有一些链接：
  • https://github.com/pure-data/externals-howto
  • https://puredata.info/dev/CodeSnippets/
以及大量阅读代码，Pd 的或其他项目的代码
在开发系统上构建、安装并测试；
提交到代码仓库；github、sourceforge……；
如果你确信一切正常，可以给仓库打一个反映你版本的标签。但移植过程中可能会发现平台特有的问题。最好等所有平台都测试过之后再打标签。
从 github 下载当前源代码的 .zip 包；
这样做是为了确保构建包与仓库里的版本一致，并且不包含 .o 或可执行文件之类的构建产物。
把它重新打包成 *-(Sources).tgz（这是用于各平台移植的源码）；
现阶段文件名格式是自由的，但将来某个时候，远程构建工具可能会要求特定格式。要确保文件名和版本里都没有连字符 -，否则会让 Deken 插件困惑
上传到移植机器；
构建、安装并运行加载测试；
做一个包含所有对象的 patch 就能快速测试。如果它能无错误地打开，说明所有对象都成功加载和实例化了。这虽然不是正规测试的替代品，但可以快速发现编译、安装和打包问题
把 *-(Sources).tgz 复制到安装目录，并按库名、版本和平台生成名称正确的 .tgz 或 .zip 文件）；
在你的库目录所在的目录里运行打包工具（tar, zip），确保 tar.gz 或 zip 里包含了库目录本身。正确的文件名是 libraryName-version-(platform)(Sources).tar.gz（或 .zip）
把打包文件复制到开发系统；
这里假定开发系统就是安装了 deken 工具和用于签名的密钥环的那台机器。
运行 deken upload ... 进行签名并上传到 puredata.info；
上传需要一个 https://puredata.info 的账号。签名过程把上传者的邮箱地址与上传的包绑定在一起。包的哈希和证书会随包一起上传。将来某个时候，可能会有工具让下载者在下载前验证包的来源。
把 *-objects.txt 上传到 puredata.info 上对应的目录；
objects 文件由 puredata.info 服务器用来按对象名查找库包。它是一个文本文件，由维护者/上传者创建，包含库包里所含对象的名称，每行一个。可以在每行里加一段简短的对象描述，用一到多个空格与对象名分隔，但目前还没有用到。上传的包会被 deken 工具放在 Members/userName/software/packageName/version，objects 文件也应该放在这里。

deken 插件目前识别的平台名称有：

  • Linux Intel 32 位：Linux-i386-32
  • Linux Intel 64 位：Linux-amd64-32
  • MacOSX 32 位：Darwin-i386-32
  • MacOSX 64 位：Darwin-amd64-32
  • macOS/M1：Darwin-arm64-32
  • Windows 32 位：Windows-i386-32
  • Windows 64 位：Windows-amd64-32
  • Linux ARM 32 位：Linux-armv7-32
  • Linux ARM 64 位：Linux-arm64-32

对于 MacOSX 构建系统，习惯上同时为 Intel 64 位和 Apple Silicon 构建。文件名于是变成
packageName-version-(Darwin-amd64-32)(Darwin-arm64-32)(Sources).tar.gz

关于 deken 工具的更多信息见：https://github.com/pure-data/deken/tree/master/developer
