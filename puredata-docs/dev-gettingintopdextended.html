加入 Pd-extended

本页概述了把一个库整合进 Pd-extended 所需的信息。思路是尽可能让 Pd-extended 的开发去中心化，使每个开发者都有尽可能大的灵活性，同时不拖慢发布周期（反正它已经够慢了……）。

要求

库

要被纳入 Pd-extended，一个库必须：

  • 采用 Libdir 格式，并有正确的元文件

  • 已经作为独立的 Libdir 发布过

  • 不依赖任何未包含在 Pd-extended 中的东西

  • 列在 puredata.info downloads 页面中（你可以自己添加： Adding Your Project To Downloads）

  • 包含在 Debian/testing 中

  • 基于 Library Template

维护者

你可以在这里看到库及其维护者的列表： Libraries In Pd-extended

  • 每个库都必须有明确的维护者

  • 维护者必须关注 bug tracker

  • 维护者必须订阅 pd-dev

  • 维护者必须确保任何提交在所有构建服务器上都能正常工作

Pd-extended 发布分支

Pd-extended 是从 SVN 上的一个分支构建并发布的。每个发布周期都有一个分支，即 0.43、0.42、0.41 等。每个发布分支都从上一个发布分支的副本开始，然后需要把更新并入其中。每个库都必须手动复制或合并到发布分支里。在 Pd-extended 分支中更新一个库的推荐做法是：先在 Pd-extended 之外做一个正式且经过测试的发布。等你觉得它稳定、可以最终发布时，在 SVN 里给它打标签，把 tarball 发到 http://puredata.info/downloads，再把它复制进 Pd-extended 发布分支：

  • Pd-extended 发布分支

  • 从 trunk 合并改动的例子

svn co https://pure-data.svn.sourceforge.net/svnroot/pure-data/branches/pd-extended/0.42
cd 0.42/externals/ekext
svn log --stop-on-copy    # 找到这个库最后一次从 trunk 复制过来时的提交号
svn merge -r13589:13962 https://pure-data.svn.sourceforge.net/svnroot/pure-data/trunk/externals/ekext
svn ci -m "merged in changes from trunk"

Pd-extended 各次发布之间的构建

在两次 Pd-extended 发布之间，Pd-extended 的大部分内容会直接从 pure-data SVN 的 trunk 构建。这是获得测试和反馈的好机会，因为提交到 trunk 的内容每晚都会进入 nightly 构建。这并不意味着整个 trunk 都会被纳入下一个 Pd-extended 发布分支，那要由每个维护者自己决定。
