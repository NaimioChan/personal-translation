方法 2：在 64 位系统上使用 32 位库安装 32 位的 Pd-extended

以下步骤用于让 32 位的 Pd-extended 二进制文件在 64 位 ubuntu Hardy 机器上运行起来。任何基于 Debian 的系统上的说明应该类似，也许可以在发现之后补充到这个 wiki 页面里

注意：按这些说明安装出来的结果只能部分工作，并不能完全工作。例如，没有任何视频文件能正确载入。/usr/lib32/libquicktime1.so.1 会发生段错误。

  • 安装核心 32 位库：sudo apt-get install ia32-libs

  • 安装 getlibs： http://ubuntuforums.org/showthread.php?t=474790

  • 下载 Pd-extended： http://puredata.info/downloads

  • 安装 Pd-extended：sudo dpkg -i --force-architecture pd-extended-0.XX.deb

  • 安装 Pd-extended 所需的 32 位库： 

    sudo getlibs -l libtcl8.4.so.0 libdv.so.4 libmpeg.so.1 libmpeg3.so.1 libaviplay-0.7.so.0 \
libquicktime.so.1 libMagick++.so.10 libWand.so.10 liba52-0.7.4.so libtheora.so.0 \
libgslcblas.so.0 libtheora.so.0 libgslcblas.so.0 libvorbis.so.0 libvorbis.so.0 \
libvorbisenc.so.2 libmp3lame.so.0 libImlib2.so.1

    • 注意：这份库和版本的清单只适用于 ubuntu Hardy。对于其他基于 Debian 的发行版，只要运行 Pd，记下它抱怨缺少哪个库，然后用 getlibs -l <library name> 把该库加上。每个库你都得这样一个一个地做。

Fedora 12 x86_64 上的 pd ——sl, Tue, 20 Apr 2010 00:14:00 +0200

用最新的 pd-0.42-5.src.tar.gz，我成功地构建出了带 64 位库的 rpm。最简单的方法似乎是对 src 目录里的 configure.in 使用 autoconf。pd-gui 可以通过在控制台里输入 pd 启动。我用 jack2（1.9.4）测试了音频连接，用 alsamidi 测试了 MIDI——看起来都能工作，不过我注意到 pd 连接 jack 时用的是已废弃的 api。

在 Fedora release 13（Goddard）64 位上构建 Pd-extended

我在 F13 x86_64 上成功构建了 pd-extended。效果很不错。以下是我迄今为止所做的：

安装 rpmfusion 仓库

$ sudo rpm -Uvh http://download1.rpmfusion.org/free/fedora/rpmfusion-free-release-stable.noarch.rpm
$ sudo rpm -Uvh http://download1.rpmfusion.org/nonfree/fedora/rpmfusion-nonfree-release-stable.noarch.rpm
$ sudo yum clean all && sudo yum update

我从 ccrma 重新构建了 avifile 包。如果你已经装了 ccrma 仓库并且安装了 avifile，也许可以跳过这一步。我这里没法测试直接从 ccrma 安装是否能行。（你试一下，然后告诉我结果。）

你的主目录里需要有一个可用的构建目录树。如果已经建好，你可以用下面的命令构建自己的 avifile： 

$ cd ~/rpmbuild/SRPMS
$ wget http://mirrors.ircam.fr/pub/planetccrma/mirror/fedora/linux/planetccrma/13/SRPMS/avifile-0.7.45-3.fc13.ccrma.src.rpm
$ rpm -i avifile-0.7.45-3.fc13.ccrma.src.rpm
$ sudo yum install esound-devel libmad-devel faad2-devel qt3-devel
$ rpmbuild -bb ~/rpmbuild/SPECS/avifile.spec
$ sudo yum localinstall --nogpgcheck ~/rpmbuild/RPMS/x86_64/avifile-0.7.45-3.fc13.x86_64.rpm ~/rpmbuild/RPMS/x86_64/avifile-devel-0.7.45-3.fc13.x86_64.rpm

获取 pd-extended 源代码

你可以在这里获取我这次用到的源代码： 

$ mkdir ~/source/puredata
$ cd  ~/source/puredata
$ rsync -av --delete rsync://128.238.56.50/distros/pd-extended/ pd-extended/
$ cd pd-extended

对源代码做一些修改

在「~/source/puredata/pd-extended/Gem/src/Pixes/videoV4L2.h」的开头插入下面这一行 

#include <sys/stat.h>

修正 libquicktime 的路径

如果还没安装，请先安装「findutils」。 

$ sudo yum install findutils

如果 findutils 安装成功，运行： 

$ find ~/source/puredata/pd-extended/externals/pdp externals/pidip -type f -exec perl -p -i -e "s|<quicktime/|<lqt/|g" {} \;

现在可以构建 pd-extended 了

切换到 Linux 的 Build 目录并运行「make install」 

cd ~/source/puredata/pd-extended/packages/linux_make
make install

现在你应该在「build」目录下有一个可用的 pd-extended。它下面的目录应该复制到「/usr/local/」，或者加入你的 $PATH。

运行 pd-extended

如果你想在 pd-extended 的同时使用其他音频输出，pulseaudio 可能会挡路。

在我的情况下，把「padsp」和「pd-extended」一起跑就是我的「变通办法」。不优雅，但能用。更好的办法可能是让 jackd 与 pulseaudio 一起运行，再通过 jack 连接 pd-extended，可惜 Fedora 的「pulseaudio-module-jack」目前似乎是坏的。

反正，这样在我这儿是可行的： 

$ padsp pdextended -oss -audiobuf 70
