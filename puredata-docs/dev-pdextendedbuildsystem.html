Pd-extended 构建系统

本文档概述面向外部对象的 Pd-extended 构建系统。你可以在 externals/Makefile 里找到许多可用的示例。相关主题的更多信息见：Directory Layout、RepositoryLayout、GettingPdSource 等。

基本布局

在整个源代码树的每个主要部分（abstractions、doc、externals、packages）的根目录下，都有一个 Makefile。每个 Makefile 负责该部分的总体构建，而 packages/Makefile.buildlayout 指定所有位置、公共变量等。可以在运行 make 时设置 BUILDLAYOUT_DIR 变量来覆盖 Makefile.buildlayout。

packages/Makefile 的工作方式是调用其他 SVN 部分里的所有 Makefile。

对于每种包类型，例如 Mac OS X Pd.app，都有一个单独的子目录 packages/darwin_app，其中包含该平台和该包特有的 Makefile 和文件。

例外

由于各种原因，上述规则有一些例外：flext、gem 和 pd。这些都可以通过 packages/Makefile 中的 target 引入。

如何添加你的库

一旦你决定让库走完 Getting Into Pd extended 的流程，最好的起步方式就是用 Library Template 来构建你的库。这个模板为所有受支持的 Pd 平台（非常之多）提供了现成可用的构建系统，并且便于打包成 Debian .deb、Fedora .rpm 等。

Makefile target

要把你的对象加入这个构建系统，先创建你自己的 target，并把它加到 all: 和 install: target 中。例如：对于 RRADical 对象，有一个名为 rradical_install: 的 target，它完成安装 RRADical 对象所需的一切工作，包括安装帮助文件（helppatch）和其他文档。rradical_install: 会调用 rradical: 来构建安装前需要构建的东西。每个库还有一个 clean target，例如 rradical_clean。

mylibrary

构建你的库所需的所有步骤都放在这个 target 里。这个 target 完成后，一切就都可以安装了。

mylibrary_install

所有文件的安装都在这个 target 里完成。

mylibrary_clean

这个 target 应删除 mylibrary_install 安装的每一个文件，以及任何构建产物，比如 .o 文件等。

术语解释

MYLIBRARY_NAME = mylibrary

在每个库于 Makefile 中的区段开头，你会看到一个变量 MYLIBRARY_NAME。这个变量是安装抽象对象时使用的名字。它应当全部小写，因为它在 Pd 内部加载对象时会用到（例如 [mylibrary/myobject]）。

$(objectsdir)

如果你的项目由一些打算在其他 patch 中复用、而不是当作应用来使用的对象组成，那么它们应该放到这个目录里。它们应该放在一个名字独特的目录中。这个名字就是你对象库的名字，可以把它加到路径里，也可以直接调用（例如 [mylibrary/myobject]）。

子目录名（例如 mylibrary）应始终全部小写。

$(helpdir)

所有帮助文件（helppatch）都应放到这个目录中，放在与你的对象子目录同名的子目录里。例如上面的 [mylibrary/myobject]，其帮助文件应为 mylibrary/myobject-help.pd。

子目录名（例如 mylibrary）应始终全部小写。

$(manualsdir)

如果你还有其他类型的文档，比如文本或 HTML 手册，或者基于 Pd 的教程，那么它应该放到这个目录中，同样放在与库名或应用名相同的子目录里。再用前面的例子，<i>mylibrary</i> 手册应为 mylibrary/mylibrary.html。

子目录名（例如 mylibrary）应始终全部小写。

$(examplesdir)

如果你的项目有一些打算直接运行的示例 patch 或应用，那么它们应该放到这个目录中，各自放在自己的子目录里。这个目录是一个可浏览的应用集合。如果你的应用关联很多文件，就放一个主 patch，把其余文件放在子目录里。

rradical/usecases/showcase 就是一个很好的例子。

$(manualsdir)

如果你的项目有手册，那么它应该安装到 $(manualsdir) 中，放在以 $(MYLIBRARY_NAME) 里设置的名字命名的文件夹里。

$(readmesdir)

如果你的项目只有 README，那么它应该安装到 $(readmesdir)，而不是 $(manualsdir)。如果同时还有手册，那么 README 应放到 $(manualsdir)。README 应直接放到 $(readmesdir) 中，文件名为 $(MYLIBRARY_NAME).txt。

        install -p $(externals_src)/mylibrary/README \
                $(readmesdir)/$(MYLIBRARY_NAME).txt

添加不在 SVN 中维护的文件

有时你无法编译某些东西，但手头有一个想直接放进去的二进制文件。target noncvs_install 会安装放在 <i>noncvs</i> 树中的文件。这一部分里只有平台特定的目录，因为二进制文件总是平台特定的。<i>noncvs</i> 树模仿标准的 Pd 布局。例如在 Mac OS X 上，目前有 packages/noncvs/darwin/bin、packages/noncvs/darwin/extra 和 packages/noncvs/darwin/doc/5.reference 可以作为放置文件的位置。

noncvs_install 会在你在 packages 中执行 make install 时自动使用。

Makefile 链

Pd-extended 的构建从 packages 中平台特定的目录开始，主要有三个：packages/darwin_app、packages/linux_make 和 packages/win32_inno。下面给出各个 Makefile 如何互相调用：

packages/_______/Makefile
                    |
                    \_packages/Makefile
                                     |
                                     |_pd/src/configure
                                     |_Gem/src/configure
                                     |_abstractions/Makefile
                                     |_doc/Makefile
                                     \_externals/Makefile
                                              |
                                              \_externals/&mdash;/Makefile
