开发仓库与构建系统

Pd 的核心基本上由 Miller Puckette 编写，他会接收来自 Pd 社区的补丁，而 Pd 开发者的大部分活动发生在核心之外，形式包括抽象对象、外部对象、GUI 增强、API 等。这正是 Pd 如此强大的关键：围绕一个稳固的核心，由社区提供的大量代码。

因此，为了把这一切汇集起来并创建包罗万象的软件包，建立了 Subversion 仓库。所有为 Pd 编写代码或用 Pd 写代码的开发者都被鼓励把代码贡献到该仓库并在那里维护，这样任何人都可以通过从仓库下载代码、用自己平台的构建系统编译，得到最新版本的 Pd 安装。

为了确保你的代码随 Pd 安装包一起分发，你需要把你的文件加入构建系统。

abstractions
目前，如果你想让自己的文件包含在 Pd-extended 中，需要把它们加入 abstractions/Makefile
documentation
任何额外的文档都放在这个目录里。doc/pddp 是 PDDP 文件的根目录。各种教程、手册等都可以放在这里。
extensions
这一部分用于 Pd 本身的扩展，比如替换 Pd GUI 的 xgui 或 gripd。
externals
主要的外部对象构建系统位于 externals/Makefile。你可以复制并粘贴该文件中 template 部分来创建自己的构建系统。
packages
如果你想为另一个平台创建安装程序的构建系统，那么相关的所有文件都应该放在 packages 的一个子目录里。该目录目前有 darwin_app、linux_make 和 win32_inno。debian 和 planetccrma_rpm 正在开发中。子目录名的格式是 OSname_packagetype。MacOS X 选用 Darwin， 因为那是底层 BSD/UNIX 操作系统的名称。对于 GNU/Linux，则使用发行版名称。
scripts
任何与 Pd 相关的脚本都放在这一部分。这里有一些 UNIX 风格的脚本，比如 SysV 启动脚本、bash 补全脚本等，还有一些参与 Pd-extended 构建的脚本
