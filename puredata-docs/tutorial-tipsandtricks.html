在大量 Pd patch 中替换大量对象

使用 Perl

安装 Perl，然后就可以用这个小小的单行命令：

$ perl -pi.bak -e 's/^(#X obj \d+ \d+) OLD_NAME([ ;])/$1 NEW_NAME$2/' *.pd

"OLD_NAME" 是要替换掉的对象的名称，"NEW_NAME" 是替换成的名称。下面是一个例子：

$ perl -pi.bak -e 's/^(#X obj \d+ \d+) line~([ ;])/$1 vline~$2/' test.pd
$ diff test.pd test.pd.bak
7c7
< #X obj 176 364 vline~;
---
> #X obj 176 364 line~;

这把所有 [line~] 对象替换成了 [vline~] 对象，原 patch 保留在 test.pd.bak 里。用 diff 检查是否一切正常。

另外，要把外部对象替换成带完整路径的形式（例如把 [ead~] 换成 [creb/ead~]），必须用 \\ 转义 / 字符。例如：

$ perl -pi.bak -e 's/^(#X obj \d+ \d+) OBJECT([ ;])/$1 LIBRARY\/OBJECT$2/' *.pd

使用 SED

'sed'（流编辑器）是一个小巧的标准工具，所有 unix 系统上都应该装了。 要做到与上面的 Perl 例子几乎相同的事，你可以在 GNU-sed 上用下面的命令：

$ sed -i -e 's/^\(#X obj [0-9]\+ [0-9]\+\) OLDNAME\([ ;]\)/\1 NEWNAME\2/' *.pd

注意这只在 GNU-sed 上有效，因为它用了 '-i' 参数做原地替换。换用其他版本的 sed，你必须为每个要遍历的 patch 使用一个临时（备份）文件（当然这在 GNU-sed 上也能用）。例如：

for f in *.pd
do
 cp ${f} ${f}.bak
 sed -e 's/^\(#X obj [0-9]\+ [0-9]\+\) line~\([ ;]\)/\1 vline~\2/'  ${f}.bak > $f
done

这会把目录里所有 patch 中出现的 [line~] 都替换成 [vline~]。原 patch 会留下备份（例如原来的 "test.pd" 现在叫 "test.pd.bak"）

求一个数的倒数

方法

「在数学中，数 x 的倒数（乘法逆元）是这样一个数：它与 x 相乘得到 1。」Max 用户用 [inv] 做这件事，但 Pd 没有 [inv]。那你能做什么？办法有很多。打开 ASCII 模式：

number
|
[1 $1(
|
[/ ]

num
|
[expr 1/$f1]

num
|
[pow -1]

number
|
[swap 1]
|    /
[/ ]

示例：BPM 和 [metro]

用倒数在 BPM（每分钟节拍数）表示的速度与 [metro] 可用的周期之间换算就变得容易了。BPM 是一个频率（每时间单位多少次），周期是它的倒数，是一个时间跨度。但 [metro] 要求时间以毫秒为单位，而 BPM 是按分钟计数的。所以我们需要先把分钟换算成毫秒。以下是一些事实：

  • 1 分钟 == 60 秒 == 60000 毫秒
  • 每分钟 1 拍 == 每 60000 毫秒 1 拍
  • 1 BPM 时 1 拍的时长 == 1 分钟或 60000 毫秒。
  • 每分钟 2 拍 == 每 60000 毫秒 2 拍
  • 2 BPM 时 1 拍的时长 == 1 分钟 / 2 拍 == 0.5 分钟或 60000 毫秒 / 2 拍
  • 如果每拍用 30000 毫秒，一分钟内的拍数：2 拍 == 60000 毫秒 / 30000 毫秒

所以通用公式是这样的：1 beat at x BPM = x / 60000，反过来：BPM, if 1 beat comes every x msec == x / 60000。在 Pd 里这意味着：

bpm or period  
|
[expr 60000 / $f1]
|
period or bpm

所以要显示一个 BPM 输入来控制 metro，可以这样写：

      [120\ 用于 bpm 的数字框
      |
      [expr 60000 / $f1]
      |
[metro]  <= 这里现在以 500 运行。

PI

有时你需要用到数 PI 的值：3.14159... 如果你不想记住它，可以用这个表达式对象即时算出来：

expr 4*atan(1)

给它一个 bang，就得到 PI。

旁注：尝试创建对象 [f 3.141592657] 不是个好主意，因为 pd 把 patch 保存到磁盘时会截断数字；下次打开时，你的 PI 已经变得明显不同了（差别大小取决于你原来的精度）。

把 $0 放进消息

我再说一遍：消息框里没有 $0！

消息框只认识 $1、$2、$3…… 之类。如果你必须在消息框里用 $0 呢？比如用分号消息给一个 $0 接收者发送东西。那就改用 [pack] 和 $1、$2、$3、…… 像这样：

[440\
|
[pack 0 $0]
|
[; $2-frequency $1(

[r $0-frequency]
|
[440\

但如果你想给一个 $0 子 patch 发送消息呢？比如要清空一个叫 [pd $0-sub] 的子 patch。这个子 patch 的接收者是 pd-$0-name，但（目前）你不能在 symbol 内部使用 $ 变量（只能在开头），而且根本不能在消息里用 $0。解决办法是 [makefilename]：

[f $0]
|
[makefilename pd-%d-sub]
|
[; $1 clear(

或者也可以用这个：

[symbol $0-sub]
|
[makefilename pd-%s]
|
[; $1 clear(

在较新版本的 Pd（0.40 及以上）里，你也可以用这个：

[clear(
|
[s pd-$0-subpatch]

让 patch 保持整洁

这听起来可能有点无聊，但养成整洁的连线风格出于很多原因都很重要。我不在这里全部列出，最重要的是可读性更好。下面是一些让 patch 更整洁的建议：

  1. 尽量避免连线跨过对象以及互相交叉
  2. 重新排列对象，并在可能时用 [trigger] 让连线走竖直的直线。
  3. 在无法重新排列的地方，用 send 和 receive 代替连线。
  4. 用子 patch 按功能给对象分组
  5. 对使用不止一次的功能使用抽象对象。

下面两张图展示了上面第 1 点和第 2 点的效果。第一张图是没有清理过的 patch。连线互相穿插，相当混乱。通过重新排列对象和使用 [trigger] 稍微清理了一下。我没有用任何 send 或 receive 对象，但用了它们 patch 会更整洁。

在 Path 和 Library 对话框中添加更多条目

问题：我想往 Path/Library 设置对话框里再加一个路径/库，但文本框已经用完了，全都被占满了？

回答：每个文本框里都可以放不止一个条目，用冒号（":"）分隔即可，像这样：

Path: 
/usr/lib/pd/extra:/home/me/pd/abstractions:/home/me/pd/externals

Libs:
Gem:msd:zexy:my_library

然后照常点 "Save" 和 "Save all settings" 就行。

如何避免音频中断

有些情况下会出现音频中断。如果你知道某类中断为什么会发生，多半就能找到办法绕过问题。

  • fileIO：所有从磁盘读文件的对象都会阻塞音频，直到它们执行完毕。所以要事先把所有文件都加载好。在演出当中需要把声音文件加载进表时，不要用 [soundfiler]。miller 曾建议在一个带升采样的子 patch 里用 [readsf~]，这样加载采样会比实时读取更快，而且在加载期间不会阻塞 dsp。似乎有些人只把演出中要用到的每个文件最开头的一小段加载进表，其余部分从磁盘读取。
  • 重新编译 dsp-graph。加载 patch 或动态创建对象都可能造成音频中断。演出场合要事先打开所有会用到的 patch，并用 [switch~] 把不需要的部分全部关掉，而且不要用动态 patch。
  • 一个 tick 里做太多运算。不要用 [100000(-[until] 这类东西。因为 pd 想在 0 逻辑时间里处理完，多半会造成中断。
  • 向 [netsend]/[netclient]/[netserver]/[tcpsend] 等发送太多数据。这些对象类有固定大小的内部缓冲（我记得是 4kB）。缓冲满了以后，这些对象会阻塞 pd 的处理，直到缓冲被清空。尽量不要一次发送太大的数据块，而是用类似滴流机制的办法人为限制带宽。

获取表/数组的大小

获取表或数组大小的一种办法是用名为 arraysize 的外部对象。另一种是用 vanilla Pd 自带的 expr 外部对象。可以像下面这样用它获取数组大小。

下面 array1 是一个示例数组的名字：

[bang(
|
[expr size("array1")]
|
[print arraysize]

或者：

[symbol array1(
|
[expr size("$s1")]
|
[print arraysize]
